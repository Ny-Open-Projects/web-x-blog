## 思路与架构
```text
答题架构：先抛判定公式"嵌入类型 = 类型名 T 或 *T(T 非接口非指针)"，再分三类落子：
1. 可嵌：具名类型(基类型/结构体/接口/map) + 其匿名指针
2. 不可嵌-指针类：具名指针类型(type P *T)、接口指针(*I)
3. 不可嵌-未命名类：切片/映射/数组/函数/通道裸字面量(需 type 起名)
记忆锚：编译器报错信息"embedded type cannot be a pointer"/"must be a named type"就是两条红线
```

## 方案取舍
```text
面试取舍：被问"哪些能嵌"不要逐个数类型，直接给判定公式 + 三分类，比罗列更显体系。
若面试官只问"struct 能嵌 struct 吗"→ 答能(具名)，顺带补"但 *struct 匿名也可、type P *struct 不可"。
避免陷阱：切片/映射是高频误判点，必补"裸复合类型需 type 起名"。
```

## 答题技巧
```text
技巧1：用一句 spec 规则封口——"嵌入字段类型必须是有名字的 T 或指向非接口 T 的 *T，T 不能是指针"。
技巧2：举 *sync.Mutex 匿名嵌入的实战例子，显熟悉度(外层直接 Lock)。
技巧3：区分"匿名指针字面量"与"具名指针类型"是加分项，多数人混为一谈。
技巧4：收尾点"方法提升是另一回事"(引 615)，避免把资格题答成继承题。
```
