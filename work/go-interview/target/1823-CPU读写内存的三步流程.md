# 1823 CPU 读写内存的三步流程

> 分类：操作系统 / 内存 | 难度：L1~L2 | 题型：机制题 | 频率：中 | 关键词：**寄存器**/**读写流程**/**取指**/**数据布局**/**缓存局部性**

> 原文锚点：第 1~24 段「读=定地址→内存返回→入寄存器…写=寄存器→定地址→写入内存…两种读内存时机」

## 一句话总述
CPU 与内存打交道的流程固定三步：**读** = 定地址 → 总线发地址、内存回数据 → 数据放入寄存器；**写** = 数据放入寄存器 → 定地址 → 寄存器数据写入内存指定位置。触发读写只有两种场景：**访问数据**与**取下一条指令**。寄存器是 CPU 内部的临时存放点，一切读写都经它中转。

## 面试官视角
- 意图：计算机基础的底线题——分不清寄存器/内存/缓存角色的人，后面性能题都白搭。
- 分档：P5 说清读写三步与寄存器角色；P6 知道取指也是读内存（两类访存场景）；P7 能把流程接到数据布局优化与缓存局部性实测。
- 红旗答案：以为 CPU 直接操作硬盘数据；说不出写路径也要先过寄存器。
- 惊艳点：当场报一组行/列遍历实测倍数——同数据量布局不同差 2 倍多，把流程题答成性能题 [经验]。

## 主问答
**Q（面试官原话）：** CPU 是如何读写内存的？

**A：**
1. **读三步**：指令确定目标地址（变量/数据结构持有）→ CPU 通过总线把地址发给内存，内存返回该地址存的数据 → 数据放入寄存器供后续运算。寄存器 = CPU 内部小容量临时存放点。
2. **写三步**：数据先放入寄存器 → 指令确定写入地址 → 寄存器内容写入内存指定位置。注意写也经寄存器中转，不是「直接改内存」。
3. **两种访存时机**：① 程序执行中读写数据（load/store）；② 取下一条要执行的机器指令（取指）——指令也躺在内存里，这也是取指优化（icache）存在的理由。
4. **速度差与启示**：CPU 远快于内存（缓存层级 why 见 811），所以高效代码的核心是**少访存、访得连续**——利用缓存把热数据留在离 CPU 近的地方，避免频繁落盘/走内存。

## 关键代码
```go
package main

import "time"

const N = 8192

func rowMajor(m *[N][N]int64) int64 { // 行优先：顺缓存行连续访存
	var s int64
	for i := 0; i < N; i++ {
		for j := 0; j < N; j++ {
			s += m[i][j]
		}
	}
	return s
}

func colMajor(m *[N][N]int64) int64 { // 列优先：每步跳 64KB
	var s int64
	for j := 0; j < N; j++ {
		for i := 0; i < N; i++ {
			s += m[i][j]
		}
	}
	return s
}

func main() {
	m := &[N][N]int64{}
	t0 := time.Now()
	rowMajor(m)
	println("row:", time.Since(t0).String())
	t0 = time.Now()
	colMajor(m)
	println("col:", time.Since(t0).String())
}
```

[实测] 两轮稳定：row 376.7ms/353.7ms，col 967.9ms/928.3ms——同数据量、同运算次数，仅访问顺序不同差 **2.5 倍**，即「数据布局利用缓存」的量化证据。

1. 术语核校： [经验] 原文将「数据」音转为多个崩坏串（速据/方据变体），本卡统一为规范术语，不列举原词。
