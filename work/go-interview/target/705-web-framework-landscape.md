# 705 Go Web 框架生态与面试回答策略

> 分类：Go Web 生态 | 难度：L2 | 题型：认知题 | 频率：中 | 关键词：**框架依赖度低** / **面试三方向** / **Gin 首选** / **net/http 够用**
> 原文锚点：第 1~11 段「Go 对外部框架依赖度不高…面试回答优先讲自己用过的/企业在用的/至少掌握 GIN」

## 一句话总述
Go 标准库 net/http 已足够撑起多数服务，框架依赖度天然偏低；但选成熟框架能提效、约束模块组织。面试题"你用过哪些框架"的回答策略是：**自己用过 > 应聘企业在用 > 至少掌握 Gin**（当前最受欢迎、命中率最高）。

## 面试官视角
- 考察意图：是否真用过框架、有没有选型意识、是否做过目标企业技术调研
- P5 能列 2~3 个框架名；P6 能讲清"为什么掌握 Gin"；P7 能结合业务做框架选型对比（见 705-framework-comparison-3dimensions）
- 红旗：说"Go 不需要框架"（net/http 够用≠不选型）；背框架名却不熟任何一个
- 惊艳点：开口先说"按熟悉度作战 + 提前调研企业技术栈"，体现面试策略 [经验]

## 主问答
**Q（面试官原话）：** 你用过哪些 Web 框架，都有什么特点？
**A：**
1. **先亮回答策略**：优先讲**自己真正用过**的框架（熟悉度作战），其次讲**应聘企业正在用**的（提前调研岗位 JD/内推人技术栈），两者都没有就至少掌握 **Gin**——Go 生态最流行、面试命中率最高 [经验]。
2. **点出 Go 框架依赖度低**：Go 标准库 `net/http` 已能起服务，很多项目自组合开源库而非重度框架；选框架主要为了**提效 + 约束代码组织 + 提升可维护性**，不是必需 [边界]。
3. **落到对比维度**：框架差异集中体现在「轻量 vs 全功能 / API 风格 / 性能」三维度，展开见 705-framework-comparison-3dimensions；选型原则见 705-framework-selection-principles [边界]。

## 关键代码
```go
// 即便用框架，底层仍是 net/http：Gin 用 httprouter 接管路由，Fiber 用 fasthttp
// 最简 net/http 服务（框架依赖度低的佐证，仅示意）
http.HandleFunc("/ping", func(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("pong"))
})
http.ListenAndServe(":8080", nil) // 无框架也能起服务
```
