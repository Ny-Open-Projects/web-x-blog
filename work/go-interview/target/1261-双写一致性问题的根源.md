# 1261 双写一致性问题的根源：并发来自业务层，不是 Redis

> 分类：缓存 / Redis | 难度：L4 | 题型：原理题 | 频率：高 | 关键词：**双写一致性、并发更新、网络抖动、乱序、Redis 单线程**

> 原文锚点：第 1~22 段「使用缓存最大的挑战是如何保证 Redis 与数据库的双写一致性问题…我们是先更新数据库，还是先更新缓存呢…如果先更新缓存再更新数据库，缓存更新成功但数据库更新失败，就会导致数据库与缓存不一致…并发问题并不是 Redis 内部执行机制导致的，而是业务层发起了并发请求导致的」

## 一句话总述
只要更新数据时**既要改库又要改缓存**，无论先后顺序如何，都会因**并发请求乱序**产生不一致；关键认知是这个并发问题**源于业务层的并发请求与网络抖动，而非 Redis 内部执行机制**。

## 面试官视角
P6 会说「先更新数据库再更新缓存」；P7 必须指出**两种顺序都会出问题**，并能画出并发乱序的时序：两个请求在数据库上有先后，但到达缓存的顺序可能因网络拥堵而颠倒，导致缓存停留在一个已被覆盖的旧值上。

## 主问答
**Q（面试官原话）：** Redis 和数据库双写，先更新哪个？

1. **问题背景**：高并发且一致性要求高的场景，引入缓存后**更新数据时既要更新数据库，又要更新缓存**，于是产生先后顺序问题 `[源码]`。
2. **先更新缓存再更新数据库**：若缓存更新成功而**数据库更新失败**，则二者不一致 `[源码]`。
3. **先更新数据库再更新缓存**：表面无问题，但**同一份数据并发更新**时存在并发安全问题 `[源码]`。
4. **Redis 单线程不等于无并发**：Redis 执行虽是单线程，但**并发问题来自业务层发起的并发请求** `[源码]`。
5. **乱序时序**：两个请求在数据库上有先后，但发送到缓存的时间相近；一旦先发的请求**遇到网络拥堵**，后发的请求可能**先到达缓存** `[源码]`。
6. **产生脏值**：例如数据库最终为 18，而缓存先被写成 18、又被先发请求写成 17，最终缓存为 **17**，与数据库不一致 `[源码]`。
7. **结论**：**先更新缓存或先更新数据库，都会出现并发问题** `[源码]`。
8. **这是常态**：这种并发场景在业务中属于常态，不能靠「应该不会并发」回避 `[源码]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Redis 全版本 | 命令单线程执行 | 单线程不消除业务层并发 |
| 所有版本 | 网络不可靠 | 到达顺序不保证与发送一致 |
| 所有版本 | 强一致场景 | 需引入分布式锁或串行化 |
| 长期有效 | 通用解法 | 改为删除缓存而非更新缓存 |

## 关键代码
```go
// 错误示范：先更新 DB 再更新缓存 —— 并发下会因到达顺序颠倒而留下旧值
func updateAgeWrong(id int64, age int) error {
	if err := db.Exec("UPDATE user SET age=? WHERE id=?", age, id).Error; err != nil {
		return err
	}
	// 两个并发请求在此处的到达顺序可能与 DB 提交顺序相反
	// 结果：DB=18，缓存却被后到的请求写成 17
	return rdb.Set(ctx, cacheKey(id), age, 0).Err()
}

// 时序示意（DB 有序，缓存乱序）：
//   请求1: DB age=17  ->  网络拥堵 -> 缓存 age=17（后到）
//   请求2: DB age=18  ->  正常到达 -> 缓存 age=18（先到）
//   最终：DB=18，缓存=17  -> 不一致
```

## 总结与追问预判
**题眼是「并发来自业务层，不是 Redis 单线程能解决的」**——很多人在这里答错。既然更新缓存无法避免并发问题，下一步应换思路：不更新缓存而是**删除缓存**（见同批 1261-delete-vs-update）。

## ⚠️ 原文纠错
1. 事实核校：双写需同时更新两处、先更新缓存则库失败不一致、先更新库则并发下有安全问题、并发源于业务层而非 Redis 内部、网络拥堵导致乱序——分析正确 `[经验]`。
2. 补充：示例中的不一致窗口源于「写缓存」这一动作保留了过期值；根本解法是**用删除代替更新**，让下一次读取重新从数据库加载，从而把并发乱序的影响限制在缓存缺失期间 `[经验]`。
3. 崩坏词归一：源码将 Redis、数据库、缓存、并发等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
