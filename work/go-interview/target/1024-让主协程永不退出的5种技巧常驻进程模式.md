# 1024 让主协程永不退出的 5 种技巧（常驻进程模式）

> 分类：Go 并发 / 常驻进程 | 难度：中 | 题型：技巧题 | 频率：中 | 关键词：**主协程不退出、死循环、channel 阻塞、空 select、signal.Notify**

> 原文锚点：第 1~46 段「常驻进程需主协程不退；5 法：for死循环/无缓冲channel阻塞/nil channel/空select{}/signal.Notify；需注意 panic 用 recover 恢复」

## 一句话总述
常驻进程要让 `main` 永不退出，常见 5 招：① `for {}` 死循环；② 从无缓冲 channel 读/写造成阻塞；③ 向 nil channel 读写（永久阻塞）；④ `select {}` 空语句阻塞；⑤ `signal.Notify` 监听退出信号（最推荐）。前四者靠"阻塞/空转"卡住 main，第五者还能优雅捕获退出方式。一句话背法：**「卡 main 五法：死循环/无缓冲阻塞/nil channel/空select 四类是堵，signal.Notify 是优雅堵」**。

## 面试官视角

## 主问答
**Q（面试官原话）：** 怎么让 Go 的主协程一直不退出？

**先铺垫（由浅入深第 1 层）**：main 函数 return 进程就结束，所有子协程跟着被强杀。常驻进程（daemon/长连接）必须让 main 一直"卡"着。卡住的本质只有两类——要么空转（一直跑）、要么阻塞（等一个永远不会来的事）。5 招就是这两类的不同写法。

1. **for{} 死循环（第 2 层·空转）**：最简单但空转持续占 CPU，且需配合抢占调度才不饿死其他协程（版本边界见 1024 for死循环）。
2. **无缓冲 channel 阻塞（第 3 层·阻塞）**：主协程从无缓冲 channel 读（或写）而无对方就绪 → 阻塞；若没有任何持续运行的 goroutine 提供数据，会触发死锁。
3. **nil channel 读写（第 4 层·阻塞）**：对 nil channel 读写永久阻塞，等价于"卡住 main"，机制同无缓冲阻塞。
4. **select{} 空语句（第 5 层·阻塞）**：无 case 的 `select{}` 永久阻塞 main；同样要求已有 goroutine 在跑，否则死锁。
5. **signal.Notify（第 6 层·推荐）**：监听 OS 信号阻塞 main，还能读取具体退出方式（interrupt/terminate/kill），生产最常用（见 1024 signal.Notify）。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| for{} | 全版本空转占 CPU；单核饿死边界见 1024 for死循环（Go 1.14 前） |
| 无缓冲/nil/空select | 全版本阻塞；无并发 goroutine 时 runtime 报 `deadlock` |
| signal.Notify | 标准库 `os/signal`，全版本；可读退出方式 |
| 推荐做法 | 生产用 signal.Notify + recover，而非纯阻塞/空转 |
| Go 版本 | 与 Go 版本无关，本项目实测 Go 1.26.5 |

## 关键代码
```go
package main

import (
	"fmt"
	"os"
	"os/signal"
	"syscall"
)

func main() {
	// 法1：死循环（空转，不推荐）
	// for {}

	// 法2/3：channel 阻塞
	// ch := make(chan int); <-ch   // 无缓冲且无发送方 → 阻塞
	// var nch chan int; <-nch       // nil channel 永久阻塞

	// 法4：空 select 阻塞（要求已有 goroutine 在跑，否则 deadlock）
	// select {}

	// 法5：信号阻塞（推荐）：既能常驻又能拿到退出原因
	sig := make(chan os.Signal, 1)
	signal.Notify(sig, syscall.SIGINT, syscall.SIGTERM)
	s := <-sig
	fmt.Println("exit by:", s)
}
```

## 总结与追问预判
**背这三句就够**：① **卡 main 五法分两类：死循环（空转）与无缓冲/nil/空select（阻塞）**；② **纯阻塞法要求已有 goroutine 在跑，否则 runtime 报 deadlock**；③ **生产最推荐 signal.Notify（能拿退出原因），并配 recover 防 panic 退出**。
**预判追问**：
- 「空 select 为啥会死锁？」→ 无任何 case 且 main 无其它 goroutine 在跑，runtime 判定所有协程休眠即 deadlock（见 909）。
- 「信号法好在哪？」→ 阻塞同时能读到具体 os.Signal，可接优雅关停（见 1024 signal.Notify）。
- 「nil channel 和空 select 区别？」→ 都永久阻塞，nil channel 是读写未初始化 chan，空 select 是无 case（见 610/909）。
