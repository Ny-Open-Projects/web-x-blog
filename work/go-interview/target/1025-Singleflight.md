# 1025 Singleflight：请求合并与防缓存击穿

> 分类：Go 并发 | 难度：中 | 题型：原理+场景 | 频率：高 | 关键词：**singleflight、请求合并、缓存击穿、并发原语、Group**

> 原文锚点：第 1~11 段「singleflight 使用场景、缓存穿透、合并并发请求只穿透一次」

## 一句话总述
singleflight 是 Go 官方扩展并发原语，用于把「同一时刻、同一 key 的多个并发请求」合并成「只让一个真正执行」，其余请求直接复用其结果。典型场景：本地缓存未命中时，海量并发请求同时打到数据库（缓存击穿/穿透），用它能让 DB 只被访问一次。

## 面试官视角
singleflight 是 Go 并发高频题。考官看你能不能讲清「它解决什么（缓存击穿）」「怎么用（Group.Do + 同一 key）」「底层靠什么（map 合并 + WaitGroup 等待）」。能对比「它不等同于限流/批处理，只合并相同 key 的并发」说明理解到位。

## 主问答
**Q（面试官原话）：** singleflight 是什么？解决什么问题？

1. **定位**：官方扩展库提供的请求合并原语，属于并发控制，不是限流也不是批处理。
2. **解决的问题**：缓存失效瞬间大量并发同时回源（DB/下游），造成穿透或雪崩；singleflight 让同 key 并发只回源一次。
3. **核心语义**：对「同一 key」的一组并发调用，只有一个 goroutine 真正执行 fn，其余阻塞等待并拿到同一份返回值。
4. **边界**：只合并「同时刻」的并发；若第一个请求已结束、第二个稍后才来，则各自执行（除非显式 Forget 重置）。
