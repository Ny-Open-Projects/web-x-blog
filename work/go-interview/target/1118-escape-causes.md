# 1118 常见逃逸原因

> 分类：内存与 GC | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**返回局部地址** / **闭包捕获** / **interface 装箱**
> 原文锚点：第 55~109 段「返回后存活、闭包、全局变量、channel 等情况发生逃逸」

## 一句话总述
变量在编译期无法确认生命周期或作用域超出函数时逃逸到堆：返回局部变量地址、被闭包捕获、对象过大、赋值给 interface（装箱）、发送 channel、经 reflect 等会逃逸。

## 面试官视角
- 意图：能否枚举真实逃逸触发点，而非只背定义。
- P5 知返回地址/闭包 / P6 知 interface 装箱与大对象 / P7 知 channel 与 reflect 细节及误判。
- 红旗：以为所有全局变量都逃逸；以为 channel 发送一定逃逸。
- 惊艳点：返回 `&local` 与闭包捕获都因"地址被外部持有"而逃逸；interface{} 赋值触发装箱分配 —— 验证 `go build -gcflags="-m" main.go` `[实测]`。

## 主问答
**Q（面试官原话）：** 哪些情况会让对象逃逸到堆上？
**A：**
1. **结论**：取局部变量地址并在函数返回后被持有（返回指针、存全局）、被闭包捕获、尺寸超栈阈值、赋值 interface、发 channel、走 reflect。
2. **机制**：编译器保守判断——只要变量的指针可能逃出当前栈帧，就分配到堆；interface 装箱因动态类型擦除需堆分配。
3. **边界**：channel 发送按值拷贝，未必逃逸；真正让 goroutine 内变量逃逸的是闭包捕获（生命周期超出函数），非 channel 本身是否同步。
**加分层：** 不在闭包里修改变量、减少 interface 装箱，可显著压低堆分配。

## ⚠️ 原文纠错
原文第 72~88 段称「channel 本质是同步的所以发送到 channel 的变量没逃逸」，因果不当：变量是否逃逸取决于地址是否被外部持有，与 channel 是否同步无关；真正让 goroutine 内变量逃逸的是闭包捕获（生命周期超出函数）。channel 发送值通常按值拷贝，故未必逃逸。机翻解码：利用→nil、勾浪→Go、首时→守时、得体。
