# 22 七特性的考察映射与协同关系深挖

> 覆盖源 2-2 的备考延伸：七特性在面试中的考察深度地图、特性间的协同矩阵、每特性的高频追问与卡库锚点、「特点题」的差异化答法。主卡已给七特性主线，本附录做映射与协同深挖。

## 思路与架构

```text
七特性 -> 考察深度地图 (各特性考到哪一层)
├─ goroutine 并发: 考最深 (到 GMP/泄漏/池化)
│   └─ 卡库锚点: 912 系列 / 101 系列
├─ channel:        考深 (语义族/死锁/hchan)
│   └─ 610/611/612/615/911 系列
├─ defer:          考机制 (LIFO/求值时机/循环坑)
│   └─ 606 系列
├─ error:          考实践 (wrap/哨兵/ errs.Is)
│   └─ 513 系列
├─ 多返回值:        考搭配 (末位 error 约定)
├─ 网络库:          考工程 (server 模型/netpoll)
│   └─ 1833/1840 系列
└─ 规范内建:        考认知 (gofmt/vet/编译即门禁)
└─ 协同矩阵 (答出彩的关键)
    多返回值<->error / channel<->goroutine
    defer<->panic / 网络库<->goroutine 并发
```

## 方案取舍
- **「特点题」的差异化打法**：七条人人会背，差异在**第二句**——每条报完立刻接「所以在我们工程里它改变了什么」：goroutine→「每个连接一个 goroutine 成为可能」、error→「错误路径是代码评审的一等公民」、gofmt→「全团队零风格争论」。特点→工程影响的映射，是把认知题答成经验题的杠杆 [经验]。
- **协同矩阵是 P7 信号**：特性不是孤岛——**多返回值与 error** 是一体的（没有多返回值，error 要么占参数位要么用异常）；**channel 与 goroutine** 是一体的（单说 channel 是数据结构，配上 goroutine 才是并发模型）；**defer 与 panic/recover** 是一体的（defer 是 recover 的唯一挂载点）。答出两三组协同关系，考官会自动把你归入「懂设计」档 [经验]。
- **每特性的高频追问提前列装**：goroutine→「怎么控制数量」（池/信号量/errgroup 并发上限）；channel→「nil/closed 的行为」（收发规则表）；defer→「循环里 defer 文件句柄会怎样」（积压到函数尾，句柄耗尽——见 606.md` 的四步演进）；error→「wrap 之后怎么判断」（errors.Is/As）。四个追问的答案在卡库里都有专卡，面试前把「特性→专卡」的映射过一遍即可 [经验]。
- **与 201 的边界分工**：`201-go-success-factors` 答「**Go 为什么成功**」（设计目标/团队/历史），本卡答「**Go 长什么样**」（特性清单/协同/工程影响）——两题常被连问，答法上注意承接：「这些特性正是它成功的手段」自然过渡，不重复论据 [边界]。

## 答题技巧
- 报七条时**按「并发主线→错误处理主线→工程主线」分组**：goroutine+channel 一组、error+多返回值+defer 一组、网络库+规范一组——结构化输出本身就是示范 [经验]。
- 每条带一个「注意什么」：goroutine→数量控制、channel→nil/closed、defer→循环积压——只报优点会被当营销 [经验]。
- 主动画协同矩阵：三组特性对的出现顺序就是你的讲解顺序——「先讲清单体，再讲清连接」[经验]。
- 被问「Go 不支持 X（继承/异常/重载）」→ 报设计取舍视角（组合/显式 error/命名分化），与 `614-no-overload-override`/`615-go-oop` 呼应 [经验]。
- 主动边界到 `22-go-features-overview`（特性主线）、`201-go-success-factors`/`201-go-selection`（成功因素与选型）、`201-go-tradeoffs`（设计取舍）、`102-go-concurrency-overview`（并发总览），构成「Go 语言认知」专题 [边界]。
