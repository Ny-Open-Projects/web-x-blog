# 1261 为什么删除缓存优于更新缓存：懒加载与 Cache Aside

> 分类：缓存 / Redis | 难度：L4 | 题型：方案题 | 频率：高 | 关键词：**删除缓存、懒加载、Cache Aside、查询缓存、高频查询**

> 原文锚点：第 23~38 段「除了解决问题本身，我们还可以避免问题的产生…真的有必要去更新缓存吗…当数据库的数据被更新之后，我们可以删除缓存数据…MySQL 8.0 中被废弃的查询缓存就是这么实现的…Redis 本质上取代了 MySQL 的查询缓存…我希望它缓存的都是高频查询的数据，所以更新频繁的数据本身不适合缓存…使用 lazy loading 也就是懒加载的方式去被动填充这些缓存数据…这个策略就是 Cache Aside 的策略，也叫做旁路缓存策略」

## 一句话总述
与其更新缓存，不如**直接删除缓存**：更新路径更短、避免无效计算、天然规避并发乱序；配合读取时未命中再回写的**懒加载**，即标准的 **Cache Aside（旁路缓存）策略**。

## 面试官视角
P6 知道有 Cache Aside 这个词；P7 要讲清**为什么删除优于更新的四条理由**——操作路径更短、避免无意义的查询与写入、与 MySQL 查询缓存同构、更新频繁的数据本就不该缓存——并说明它的适用边界。

## 主问答
**Q（面试官原话）：** 数据更新了，你是更新缓存还是删除缓存？为什么？

1. **换个思路**：既然更新缓存无法避免并发问题，不如**避免问题产生** `[源码]`。
2. **核心质疑**：更新数据库后还要更新缓存，**操作路径变长**；真的有必要更新缓存吗 `[源码]`。
3. **改为删除**：数据库数据更新后，直接**删除缓存数据**，很多缓存方案都是这么做的 `[源码]`。
4. **与查询缓存同构**：MySQL 8.0 中被废弃的**查询缓存**正是这么实现的——表数据更新时，涉及该表的缓存全部失效 `[源码]`。
5. **Redis 的定位**：Redis 本质上**取代了 MySQL 的查询缓存**，作用相同——减轻数据库压力、提升响应速度 `[源码]`。
6. **只缓存高频数据**：缓存应当保存**高频查询的数据**；**更新频繁的数据本身不适合缓存** `[源码]`。
7. **避免无效开销**：更新数据库后再更新缓存**还需再次查询数据库**，带来额外压力；若频繁更新却长时间不查询，更新缓存毫无意义 `[源码]`。
8. **懒加载更优**：用 **lazy loading（懒加载）** 被动填充缓存，在计算资源与整体性能上都是更优方案 `[源码]`。
9. **最终策略**：更新时删除缓存，读取时未命中则从数据库读取并回写——这就是 **Cache Aside（旁路缓存）策略** `[源码]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| MySQL 8.0 | 查询缓存被废弃 | 该职责上移到 Redis |
| 8.0 之前 | 查询缓存表级失效 | 更新即失效整表缓存 |
| 所有版本 | 高频读低频写 | Cache Aside 收益最大 |
| 所有版本 | 写多读少 | 不适合缓存 |

## 关键代码
```go
// Cache Aside：更新时删除缓存，读取未命中再回写（懒加载）
func updateAge(id int64, age int) error {
	if err := db.Exec("UPDATE user SET age=? WHERE id=?", age, id).Error; err != nil {
		return err
	}
	// 删除而非更新：路径更短，且避免并发乱序写入旧值
	return rdb.Del(ctx, cacheKey(id)).Err()
}

func getAge(id int64) (int, error) {
	// 1) 先读缓存
	if v, err := rdb.Get(ctx, cacheKey(id)).Int(); err == nil {
		return v, nil
	}
	// 2) 未命中 -> 查数据库
	var age int
	if err := db.QueryRow("SELECT age FROM user WHERE id=?", id).Scan(&age); err != nil {
		return 0, err
	}
	// 3) 回写缓存（懒加载），并设置过期时间作为兜底
	_ = rdb.Set(ctx, cacheKey(id), age, 5*time.Minute).Err()
	return age, nil
}
```

## 总结与追问预判
**删除优于更新的核心理由是「避免无效工作 + 规避并发乱序」**。追问常是「那顺序呢，先删缓存还是先更新库」——两者各有不一致窗口，详见同批 1261-cache-aside-order。
