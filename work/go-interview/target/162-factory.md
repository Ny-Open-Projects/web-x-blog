# 162 工厂方法与抽象工厂：把对象创建收口

> 分类：设计模式/创建型 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**工厂方法** / **抽象工厂** / **开闭原则**
> 原文锚点：第 11~22 段「工厂方法定义创建接口由子类决定实例化哪个类；抽象工厂创建相关对象族」

## 一句话总述
工厂方法把"该建哪个具体类型"推迟到具体工厂决定，消除 switch 分支；抽象工厂进一步一次性产出一组相互依赖的对象，客户端不依赖具体类。

## 面试官视角
- 意图：区分简单工厂、工厂方法、抽象工厂三者的演进与适用面。
- P5 知用函数返回接口 / P6 说清工厂方法 vs 抽象工厂差异 / P7 知 Go 里用 `func() Product` 即可，不必硬套类继承。
- 红旗：把简单工厂（if-else 分发）当成工厂方法；以为 Go 必须有抽象类才能用工厂。
- 惊艳点：Go 无继承，工厂方法常退化成 `type Factory func() Product` 这种函数类型，比 Java 的继承层级更轻 —— 验证：函数类型即一等公民，go1.26.5 `[源码]`。

## 主问答
**Q（面试官原话）：** 工厂模式有几种？Go 里怎么写工厂方法？
**A：**
1. **结论**：简单工厂（集中 if-else）、工厂方法（每产品一工厂）、抽象工厂（一工厂产一族产品）三者递进。
2. **机制**：工厂方法定义 `Product` 接口与 `Create() Product`，具体工厂返回不同实现，新增产品只加工厂不改动旧代码，符合开闭原则 `[源码]`。
3. **边界**：抽象工厂解决"产品族"一致性（如 Win/Mac 的按钮+文本框成套），单产品维度变化用工厂方法即可，别为单一维度上抽象工厂。
**加分层：** Go 里工厂方法常写成 `func NewX() Product`，用函数而非子类收口创建逻辑，更贴合语言习惯。
