# 701 Go 库与框架选型 深挖

> 覆盖源 7-1 全文：标准库重点包 + 外部框架(轻量组合哲学) + 微服务框架(kratos/go-zero/go-micro) + 三方库(go-orm/gRPC/protobuf)。主卡已给生态综述，本附录做"标准库vs框架取舍"与微服务框架选型对比。

## 思路与架构

```text
Go 生态选型
├─ 标准库优先: io/fmt/time/os/net-http/sync/database-sql 覆盖 80% 场景
├─ Web 框架: Gin(主)/beego/echo — 仅补路由/中间件便利
└─ 微服务框架: kratos(通用) / go-zero(工程化) / go-micro(gRPC系) 按规模选型
```

## 方案取舍
- **标准库 vs 框架**：能用 net-http 起服务就先别引框架；框架价值在路由分组/中间件/校验等工程便利，而非能力缺口 [经验]。
- **微服务框架选型**：kratos 通用组合式（服务发现/负载/容错全）；go-zero 工程化+代码生成+内置超时并发容错，中小团队友好；go-micro 基于 gRPC、插件丰富、多传输协议 [经验]。
- **三方库必要性**：go-orm 降 SQL 样板、gRPC+protobuf 跨语言高性能 RPC——属真实需求，非"为用而用"。

## 答题技巧
- 面试被问"掌握哪些库"先分层答：标准库→Web 框架→微服务框架→三方库，显结构 [经验]。
- 主动边界到 `702`(net-http 体系)、`615`(OO/接口)，构成生态+机制全栈 [边界]。
