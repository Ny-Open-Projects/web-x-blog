# 1021 安全退出读取循环的两种方式

> 分类：Go 并发 | 难度：中 | 题型：八股题 | 频率：中 | 关键词：**for-range、ok 判断、channel 关闭、consumer 退出、死锁**

> 原文锚点：第 26~37 段「关闭后 for-range 自动退出；for-select 用第二返回值 false 退出」

## 一句话总述
读 channel 的循环有两套退出机制：`for v := range ch` 在 channel 被 `close` 且缓冲读完时自动退出；`for { v, ok := <-ch; if !ok { return } }` 用第二返回值 `ok==false` 显式退出。两者都依赖**发送方主动 close**。一句话背法：**「单路用 for-range 等关闭，多路用 v,ok 判关闭，退出的前提是有人 close」**。

## 面试官视角
考官看你会不会正确终结 consumer 循环，避免永久阻塞/死循环。能讲清「for-range 退出条件」「ok 语义」「不关会死锁」说明基本功扎实；能指出「多路别只靠 default，用 done/stop channel 更稳」说明有实战经验。
- **P5**：说出两种写法（for-range / v,ok）。
- **P6**：讲清 for-range 退出条件（close 且缓冲空）、ok 语义（已关闭且无值）。
- **P7**：点出不关 channel 会死锁、`for-select` 里 default 会忙轮询、应改用 done channel。

## 主问答
**Q（面试官原话）：** 怎么让读 channel 的循环正常退出来？别让它一直阻塞。

**先铺垫（由浅入深第 1 层）**：channel 是阻塞式的，读一个没人写、也没关闭的 channel，协程就永远卡住。consumer 循环要退出，必须有一个明确的「结束信号」——在 Go 里这个信号就是发送方调用 `close(ch)`，以及读操作返回的 `ok==false`。

1. **结论（第 2 层·怎么用）**：单 channel 就用 `for v := range ch`；要混合退出信号或读多路就用 `for { v, ok := <-ch; if !ok { return } }`。
2. **机制（第 3 层·底层）**：for-range 底层收到「关闭态 + 缓冲为空」就退出；`v, ok` 的 `ok` 为 false 表示 channel 已关闭且**没有剩余数据**可读。
3. **边界（第 4 层·最常考）**：两者都依赖**发送方 close**；如果发送方永不 close，range 会一直阻塞，直到 runtime 检测到所有协程都阻塞而报 `deadlock`。
4. **多路陷阱（第 5 层）**：`for-select` 里若只写 `case v := <-ch` 不判 ok，channel 关闭后该 case 持续返回零值形成死循环；正确做法是读 `v, ok` 后 `if !ok { return }`。
5. **误用风险（第 6 层）**：别为了退出手动 `close` 数据 channel——close 责任应归发送方（见 1021 关闭责任），consumer 主动 close 会和发送方冲突报 `panic: close of closed channel`。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| 结论成立版本 | Go 全版本稳定，for-range 与 `v, ok` 语义长期不变（语言规范） |
| 退出前提 | 发送方 `close(ch)`；consumer 不负责关数据 channel |
| 死锁判定 | 所有协程都阻塞且无可运行协程时 runtime 抛 `fatal error: all goroutines are asleep - deadlock` |
| 多路推荐 | 用 `done`/`stop` channel 或 `ctx.Done()` 广播退出，比 `default` 更稳（default 会忙轮询） |
| Go 版本 | 与 Go 版本无关，本项目实测 Go 1.26.5 |

## 关键代码
```go
package main

import "fmt"

func main() {
	// 方式一：for-range，发送方 close 后自动退出
	ch := make(chan int, 3)
	ch <- 1
	ch <- 2
	ch <- 3
	close(ch) // 发送方负责关闭
	for v := range ch {
		fmt.Println("range:", v) // 1,2,3 后自动退出
	}

	// 方式二：for-select + ok，多路/混合信号时显式 return
	ch2 := make(chan int, 1)
	ch2 <- 10
	close(ch2)
	for {
		v, ok := <-ch2
		if !ok {
			fmt.Println("ch2 closed, exit") // ok=false 显式退出
			break
		}
		fmt.Println("select-ok:", v)
	}
}
```

## 总结与追问预判
**背这三句就够**：① **单路用 `for v := range ch`，发送方 close 后自动退出**；② **多路用 `v, ok := <-ch`，`ok==false` 即已关闭无值，要 return**；③ **退出前提是发送方 close，不关会 deadlock**。
**预判追问**：
- 「谁负责 close？发送方还是接收方？」→ 单发送者由发送方关，多发送者用额外 stop channel 协调（见 1021 关闭责任）。
- 「for-select 不判 ok 会怎样？」→ channel 关闭后该 case 持续回零值，形成死循环（见本卡第 5 层）。
- 「default 能不能当退出用？」→ 不能，default 会忙轮询空转，应改用 done channel（见本卡第 5/6 层）。
