# 1712 一致性哈希环基础（2^32 取模）

> 分类：分布式/一致性哈希 | 难度：L3 | 题型：八股题 | 频率：中 | 关键词：**哈希环**/**2^32取模**/**顺时针**/**只迁移相邻**/**扩容**

> 原文锚点：第 13~28 段「那一致性哈希算法呢也用了取模运算…其他的这些数据呢是不会影响到的」（对 2^32 取模构成环 → 节点与数据两步哈希映射 → 顺时针找第一个节点 → 新增节点只迁移相邻区间 → 只影响后驱节点）

## 一句话总述
哈希环的本质是**把「节点数取模」换成「对固定 2^32 空间取模」**，再用「节点和数据都落在环上、数据顺时针找最近节点」的两条映射规则，让扩容只搬运环上一段相邻数据。

## 面试官视角
这题考算法落地的细节：① 两次哈希分别映射什么（节点 IP + 数据 key）；② 顺时针查找怎么实现（有序数组 + 二分）；③ 增删节点的迁移边界到底在哪。能画出「环 + 节点 + 数据顺时针箭头」并说清迁移区间，才算过关。

## 主问答
**Q（面试官原话）：** 一致性哈希的「哈希环」具体是怎么工作的？数据怎么知道该放哪个节点？

**A：**
1. **第一步：节点映射上环**。对每个真实节点（通常用 IP 或唯一标识）做哈希，得到环上的一个位置；这一步与数据无关，只是把「机器」摆到环上。
2. **第二步：数据映射上环 + 顺时针寻址**。对要存的数据 key 做哈希，落在环上某点后，**沿顺时针方向找到第一个节点**，该节点即负责此 key。等价于 `node = 顺时针第一个 hash ≥ hash(key) 的节点`（越过环尾则回到环首）。
3. **增节点只迁移「相邻区间」**：新增节点 N4 后，原本落在「N3 → N4 顺时针区间」内的数据会从 N3 迁到 N4；**其余所有区间的数据完全不动**，因此迁移量被限制在环上一段，而非全量。
4. **删除/故障同理**：某节点下线，它负责的那段区间顺时针交给下一个节点接管，影响范围依旧只是相邻一段，不会波及全环。

## 版本与兼容性
- 顺时针查找的工程实现依赖「虚拟节点 hash 有序数组 + 二分查找（`sort.Search`）」，**时间复杂度 O(log V)**，V 为虚拟节点总数；经典无虚拟节点时 V≈节点数，引入虚拟节点后 V≈节点数×副本数。
- 该实现与语言无关；Go 中用 `sort.Search`、Java 用 `TreeMap.tailMap / ceilingEntry`、C++ 用 `std::map::lower_bound` 都能 O(log N) 完成顺时针寻址。

## 关键代码

```go
// 顺时针寻址核心（含环回）：给定 key，返回应落点的真实节点
func (c *ConsistentHash) Get(key string) string {
	if len(c.sorted) == 0 {
		return ""
	}
	h := c.hash([]byte(key))
	// sort.Search 找到第一个 >= h 的下标
	idx := sort.Search(len(c.sorted), func(i int) bool { return c.sorted[i] >= h })
	if idx == len(c.sorted) {
		idx = 0 // 越过环尾 → 回到环首（wrap-around）
	}
	return c.ring[c.sorted[idx]]
}

// 迁移边界演示：新增节点后，仅 [oldMaxHash, newHash) 区间的数据需搬迁
func affectedRangeBeforeAdd(c *ConsistentHash, newNode string) (uint32, uint32) {
	vh := c.hash([]byte(fmt.Sprintf("%s#0", newNode)))
	// 顺时针前一个虚拟节点即为迁移区间起点
	idx := sort.Search(len(c.sorted), func(i int) bool { return c.sorted[i] >= vh })
	start := c.sorted[(idx-1+len(c.sorted))%len(c.sorted)]
	return start, vh
}
```

## 总结与追问预判
收口：**环 = 固定哈希空间；数据落点 = 顺时针首个节点；扩容代价 = 相邻一段（1/N）**。预判追问：① 节点在环上分布不均怎么办 → 虚拟节点（`1712-virtual-node.md`）；② 真实代码怎么写 → 见 1712.md` 的 Go 实现与深卡。回答时强调「环回（wrap-around）」这一边界 case，体现工程严谨。

## ⚠️ 原文纠错
源视频机器转写将 hash ring / 顺时针 / 后驱节点 / node 等音译为崩坏词（如「希环」「后聚节点」「lode 与 node 混写」），本卡已还原为规范术语（哈希环 / 顺时针 / 后驱节点 / 节点 node）。交付卡禁止保留任何原词崩坏写法。

> **[经验]** 顺时针查找必须处理「环回」：当 key 的 hash 大于环上最大虚拟节点 hash 时，要回到 `sorted[0]`（最小虚拟节点），否则尾部区间的数据会找不到节点。这是手写实现最常见的 off-by-one 漏点，面试写出来是加分项。
