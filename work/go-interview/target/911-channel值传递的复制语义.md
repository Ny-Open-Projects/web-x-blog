# 911 channel 值传递的复制语义

> 分类：Go 并发 | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**复制**/**至少一次**/**两次**/**直接值部**/**hchan buf**/**与传参同机制**

> 原文锚点：第 12~13、43~45 段「channel 传递发生数据复制 / 至少复制一次、经缓冲则两次」

## 一句话总述
通过 channel 传递值时，值会被**复制**——发送方和接收方各自持有自己的副本，从而保证并发安全。**直接值部**被复制（指针只复制地址、不复制指向内容）；值若**不经过缓冲**只复制一次，若**在缓冲中停留过**则复制两次（发送协程→buf 一次、buf→接收协程一次），机制与赋值/函数传参完全一致。

## 面试官视角
这是 channel 里最容易被忽略的细节。很多人知道「channel 传值是复制」，但答不出「为什么是两次」「只复制直接值部意味着什么」。能讲清复制次数与缓冲的关系，并点出「大结构体传 channel 有复制成本」的，明显超出背 API 的水平。

## 主问答
**Q（面试官原话）：** channel 传值的时候会发生什么？

1. **值一定被复制**：发送方把值放入 channel、接收方从中取出，双方各持一份独立副本，互不影响——这是 channel 并发安全的基础（不共享同一块内存）。
2. **复制次数是 1 还是 2 取决于缓冲**：值**不经缓冲**（无缓冲 handoff，或接收方已等在 recvq 直接交接）只复制**一次**；值**在 hchan.buf 中停留过**（先入缓冲、后被取走）则复制**两次**。
3. **两次分别发生在哪**：第一次是发送协程把值拷入 `buf[sendx]`；第二次是接收协程从 `buf[recvx]` 拷出。两次都走和「赋值 / 函数传参」相同的复制语义。
4. **只复制直接值部**：若元素是切片 / 指针 / map，复制的是「直接值部」（底层数组指针、地址），**不**递归复制指向的底层数据；所以通过 channel 传大 struct 会付复制成本，传指针则只复制地址。
5. **工程含义**：高频传递大结构体时用指针可降复制开销，但要自行保证「发送后不再改」避免并发写同一底层数据；这也呼应 `1112-value-size` 的参数复制成本。

## 版本与兼容性
| 情形 | 复制次数 | 说明 |
|------|----------|------|
| 无缓冲 handoff | 1 | 发送方直接拷给接收方 sudog |
| 有缓冲未满 | 2 | 入 buf + 出 buf |
| 缓冲空、接收方等 | 1 | 直接交接给 recvq 队首 |
| 元素含指针 | 只拷地址 | 不递归拷底层 |

## 关键代码
```go
type Big struct{ Buf [1 << 20]byte } // 1MB 结构体

// 传值：每次 send/recv 都复制整个 1MB（经 buf 则复制两次）
ch := make(chan Big, 1)
ch <- Big{} // 拷贝 1MB 入 buf
v := <-ch   // 再拷贝 1MB 出 buf

// 传指针：只复制 8 字节地址，不拷底层 1MB
chp := make(chan *Big, 1)
chp <- &Big{} // 仅拷地址
p := <-chp    // 仅拷地址；注意发送后勿再改 *p，否则并发写同一底层
```

## 总结与追问预判
核心：**channel 传值必复制；经 buf 停留则两次；只复制直接值部**。追问拐向「hchan 结构」——备好「环形 buf + recvq/sendq + lock」（见 609.md`）；或拐向「参数复制成本」（见 1112.md`）。
