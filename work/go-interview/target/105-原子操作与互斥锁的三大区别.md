# 105 原子操作与互斥锁的三大区别

> 分类：并发模型 | 难度：L2 | 题型：对比题 | 频率：高 | 关键词：**原子操作** / **互斥锁** / **实现方式**
> 原文锚点：第 3~15 段「原子操作由底层 CPU 指令实现…锁在软件层…保护范围与性能差异」

## 一句话总述
原子操作与互斥锁核心三点差异——实现（CPU 指令 vs 软件）、保护范围（单个变量 vs 代码块）、性能（小范围原子更快，但前提明确）。

## 面试官视角
- **考察意图**：能否讲清两者本质区别而非背结论。
- **P5** 知原子保护变量、锁保护代码块 / **P6** 能说 CPU 指令 vs 软件实现及性能前提 / **P7** 知何时该用锁、原子并非总是更快。
- **红旗**："原子一定比锁快"无前提；以为锁只能保护单个变量。
- **惊艳点**：原子保护范围是一个变量，锁保护的是临界区；多变量一致性必须靠锁 —— 验证：`go doc sync/atomic`，go1.26.5 `[源码]`。

## 主问答
**Q（面试官原话）：** 原子操作和锁有什么区别？
**A：**
1. **结论**：实现上原子靠 CPU 原子指令（硬件），锁在软件层（mutex 用原子+调度）；保护范围原子是单个变量，锁是临界区代码块。
2. **机制**：原子指令执行期间不可被其他核中断观察，无需上下文切换；锁在竞争时要挂起/唤醒 goroutine。
3. **边界**：原子只在"单变量读写/计数"场景占优，涉及多变量一致或复合操作必须上锁。
**加分层：** 原子不是"永远更快"，竞争激烈的复合临界区里锁反而结构更清晰。

## 关键代码
```go
// 示意，未验证：单变量计数用原子，复合逻辑用锁
var c int64
atomic.AddInt64(&c, 1) // 原子：单变量

var mu sync.Mutex
mu.Lock(); /* 多步临界区 */; mu.Unlock() // 锁：代码块
```

## 总结与追问预判
- 原子=硬件指令/单变量/小范围快；锁=软件/临界区/竞争时挂起。
- 预判：底层原理 → 见 105；选型 → 见 105。

## ⚠️ 原文纠错
原文第 3 段称原子操作"要么全部执行成功，要么全部不执行"。这是事务回滚（all-or-nothing）语义；原子操作的准确含义是不可分性（indivisibility）——执行期间其他 goroutine 不会观察到中间状态，单个原子读/写/CAS 不存在"回滚"。应表述为"不可被中断地整体生效"。
