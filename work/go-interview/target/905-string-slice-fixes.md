# 905 切断引用的三种写法：强转会拷贝，地址改变才是真独立

> 分类：Go 基础 / string | 难度：L3 | 题型：修复题 | 频率：高 | 关键词：**强转拷贝、[]byte、strings.Builder、strings.Clone、追加拷贝、地址改变**

> 原文锚点：第 50~75 段「我们先对这个字符串进行切片，切片后把它转成 byte 类型，然后我们再把它转成 string 类型，这时它的地址就发生了改变，意味着这种强转就会发生数据的拷贝，它会将原来的字符串复制一份，然后拷贝到一个新的内存空间里面去…我们因为 si 追字符串之后呢，我们把这个空的字符串给它截取掉，因为这里面对字符串进行追加的过程中，这个字符串是会发生拷贝的，一旦这个操作发生了拷贝之后，它就会指向了一个新的内存空间…我们可以通过 strings.Builder 来进行字符串的截取，由于 strings.Builder 是新申请的一块内存空间，所以追加进去之后这个字符串和我们外面这个字符串 s 肯定是指向不同的内存空间的」

## 一句话总述
要切断子串对大字符串的引用，**判据只有一个：地址必须改变**——而**地址改变 ⇔ 发生了数据拷贝**。三种可靠写法：**① 截取后先转 `[]byte` 再转回 `string`**（强转必经拷贝）；**② 截取后先拼一个新字符串（如前拼空串）再把这一段截掉**（追加过程会发生拷贝）；**③ 用 `strings.Builder` 预分配空间后写入**（它是新申请的内存空间，最安全）。这样生成的是新字符串，**原始大字符串若无引用就会被回收**。

## 面试官视角
- 考察意图：不仅问"会不会泄漏"，更要问"**怎么修**"——能给出三种写法并说清原理才算过关。
- 分档：P5 知道要"想办法拷贝一份"；P6 能写出 `[]byte` 中转；P7 能给出三种写法，并指出 **`strings.Clone` 是 Go 1.18+ 的官方答案**，以及 **`strings.Builder` 方案可读性最好**。
- 红旗答案：以为 `string(b)` 这种转换是"零成本"的——**`string` 与 `[]byte` 互转都会发生拷贝**，这正是它能用来切断引用的原因。
- 惊艳点：**这一节所有的修复手法，本质都是在"骗"编译器做一次拷贝**——连"前面拼个空串再截掉"这种看似无意义的操作，也是靠追加时的拷贝来换一个新地址 `[源码]`。

## 主问答
**Q（面试官原话）：** 怎么截取字符串才不会拖着原来的大内存？

1. **结论**：**让截取结果指向新的内存空间**——即**发生一次数据拷贝**。三种写法：**先转 `[]byte` 再转回 `string`**、**先拼一个新字符串再截掉**、**用 `strings.Builder` 重新构造** `[源码]`。
2. **原理 · 强转必拷贝**：**字符串与 `[]byte` 之间如果发生了强转，就会发生地址改变；地址改变意味着这种强转会发生数据的拷贝**，**它会将原来的字符串复制一份，然后拷贝到一个新的内存空间里面去** `[源码]`。
3. **原理 · 切片转字符串也拷贝**：**字节切片到 `string` 的强转同样会发生内存拷贝**——打印可见**切片转字符串之后，地址再次发生了改变** `[源码]`。
4. **写法一 · `[]byte` 中转**：**先把字符串切片，切片后转成 `[]byte` 类型，再转成 `string` 类型**；实测地址发生改变，即已脱离原始大内存 `[源码]`。
5. **写法二 · 前拼新串再截掉**：**先对字符串进行截取，截取之后再追加一个空的字符串，然后再把这个空的字符串截取掉**；**这样这个字符串的地址就会发生改变**——**因为对字符串进行追加的过程中，这个字符串是会发生拷贝的**，**一旦发生拷贝就会指向一个新的内存空间**；**把前面那个空串截掉后，拿到的就是原始字符串的前二十个字节** `[源码]`。
6. **写法三 · `strings.Builder`**：**通过 `strings.Builder` 来进行字符串的截取**——**首先预分配我们需要截取的空间**，**然后把截取后的字符串写入 Builder 里面**；**由于 Builder 是新申请的一块内存空间**，**追加进去之后，这个字符串与外层的字符串 `s` 肯定是指向不同的内存空间的**；**这种截取方式是最安全的** `[源码]`。
7. **最终效果**：**这三种方式截取之后都会生成一个新的字符串**，**这样如果原始的这个大字符串没有对象引用它，它就会被垃圾回收** `[源码]`。

**加分层：** **Go 1.18 起标准库提供 `strings.Clone`**，语义就是"返回一个内容相同但底层独立的副本"，是这三种手写法的官方替代，可读性最好，优先推荐。

## 关键代码
```go
package main

import (
	"fmt"
	"strings"
	"unsafe"
)

func addr(s string) uintptr { return uintptr(unsafe.Pointer(unsafe.StringData(s))) }

func main() {
	big := strings.Repeat("X", 1<<20)

	// 写法一：[]byte 中转 —— string 与 []byte 互转会拷贝，地址必然改变
	a := string([]byte(big[:20]))
	fmt.Println("写法一 是否仍共享:", addr(a) == addr(big)) // false

	// 写法二：前拼一个新串再截掉 —— 追加过程触发拷贝
	prefix := "@"
	b0 := prefix + big[:20]
	b := b0[len(prefix):]
	fmt.Println("写法二 是否仍共享:", addr(b) == addr(big)) // false

	// 写法三：strings.Builder 预分配 + 写入 —— 新申请的内存，最安全
	var sb strings.Builder
	sb.Grow(20)
	sb.WriteString(big[:20])
	c := sb.String()
	fmt.Println("写法三 是否仍共享:", addr(c) == addr(big)) // false

	// 官方写法（Go 1.18+）：语义清晰，优先推荐
	d := strings.Clone(big[:20])
	fmt.Println("strings.Clone 是否仍共享:", addr(d) == addr(big)) // false
}
```

## 总结与追问预判
**最爱追问的是"这些方法有性能代价吗"**——**有**：三种写法都要做一次分配与拷贝，所以**不要在热路径上对每条消息都做**；正确姿势是**只在"子串需要长期存活"时才切断**，短期用完即弃的截取保持原样即可。追问常接"`strings.Clone` 内部怎么实现"——就是 `string([]byte(s))` 加一层边界处理，语义更清晰。

## ⚠️ 原文纠错
1. 事实核校：`string` 与 `[]byte` 互转会发生拷贝且地址改变、切片转字符串同样发生内存拷贝、三种写法（[]byte 中转 / 前拼新串再截掉 / strings.Builder）均能生成新字符串从而使原大串可被回收、前拼之所以有效是因为追加过程触发拷贝、Builder 因是新申请内存故最安全——均与 Go 语义一致 `[经验]`。
2. 补充：**Go 1.18 起应优先使用标准库提供的 `strings.Clone`**，它是本节三种手写法的官方替代；另外**编译器在少数场景会对 `string([]byte(s))` 做优化**，但语义上仍必须按"会发生拷贝"来理解 `[经验]`。
3. 崩坏词归一：源码将字符串、字节切片、强转、strings.Builder、追加、垃圾回收等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
