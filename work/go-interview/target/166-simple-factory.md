# 166 简单工厂：集中分发的静态工厂

> 分类：设计模式/创建型 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**简单工厂** / **静态工厂方法** / **if-else 分发** / **不在 GoF 23 种**
> 原文锚点：第 1~22 段「简单工厂又叫静态工厂方法，一个工厂类按类型 if-else 创建不同产品，不在 GoF 23 种，适合产品种类少」

## 一句话总述
简单工厂是"一个工厂类 + 一个 switch/if-else 按类型分发"的创建型写法，把对象创建收口到一处；它不在 GoF 23 种之内，适合产品种类少、扩展不频繁的场景。

## 面试官视角
- 意图：确认候选人分得清简单工厂与工厂方法（红旗：把 if-else 分发当成工厂方法）。
- P5 能写出 if-else 分发；P6 能说清"不在 23 种、适合少产品"的边界；P7 能指出它违反开闭原则（加产品要改工厂）。
- 红旗：以为简单工厂也是 GoF 模式；以为它和工厂方法只是命名不同。
- 惊艳点：点出 Go 里简单工厂常退化成 `func NewX(t Type) Product`，比 Java 的工厂类更轻。

## 主问答
**Q（面试官原话）：** 什么是简单工厂？Go 里怎么写？
**A：**
1. **结论**：简单工厂用一个具体工厂类，按入参类型 if-else 返回不同产品实例；它不在 GoF 23 种设计模式内，属于工厂方法的特例/变体。
2. **机制**：客户端只传类型、不关心创建逻辑；工厂内 `switch t { case A: return &A{}; case B: return &B{} }`，所有创建集中在 `CreateProduct` 一处 `[源码]`。
3. **边界**：产品种类少、几乎不新增时最合适；一旦要加新产品就得改工厂的 switch，违反开闭原则，此时应升级为工厂方法 `[经验]`。

## 关键代码
```go
// 示意，未验证：简单工厂
type Product interface{ Use() }

type SimpleFactory struct{}

func (f SimpleFactory) CreateProduct(t string) Product {
    switch t {
    case "A":
        return &A{}
    case "B":
        return &B{}
    default:
        return nil
    }
}
```

## 总结与追问预判
- 简单工厂=集中 if-else 分发，不在 GoF 23 种，适合少产品、低扩展。
- 预判：加产品违开闭 → 见 166-factory-comparison（升级工厂方法）；产品族 → 见 166-abstract-factory。
