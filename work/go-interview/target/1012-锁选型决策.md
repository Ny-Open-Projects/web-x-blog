# 1012 锁选型决策：自旋 / 互斥 / 读写

> 分类：Go / 并发 / 锁 | 难度：L3 | 题型：选型题 | 频率：中 | 关键词：**选型决策** / **Mutex 快路径 CAS** / **读写锁写锁不等价互斥** / **读多** / **读写都多**

> 原文锚点：第 19~43 段「不确定→互斥/读写；很短→自旋；读多→读写锁；读写都多→互斥；Go Mutex 加锁先 CAS 判竞争(无竞争直取否则慢路径)；基准测试互斥明显优于读写锁写锁(读写锁底层含互斥、写锁不等价互斥)」

## 一句话总述
锁选型经验：**不确定持有时间→互斥锁/读写锁；确定极短→自旋锁；读多→读写锁；读写都多→互斥锁**（写锁底层是互斥锁、实现更复杂，读写都频繁时读被写阻塞概率高、失去读锁优势）。Go 的 `sync.Mutex` 加锁时**先 CAS 判竞争**：无竞争直接拿、有竞争才走慢路径睡眠。一句话背法：**「锁选型：短→自旋、读多→读写锁、读写都多/不确定→互斥；Mutex 先 CAS 快路径、读写锁写锁底层含互斥故更重」**。

## 面试官视角
这是把"几种锁"串起来的决策题。考官要你给"按场景选锁"的决策树，而非背一种锁。
- **P5**：知道读多用读写锁。
- **P6**：知道读写都多回到互斥、Mutex 先 CAS 快路径。
- **P7**：知道"读写锁写锁≠互斥（底层含互斥、更复杂）" `[边界]` 见 925（读写锁实现）、925-mutex-impl（Mutex 实现）、1013-mutex-pessimistic（Mutex 悲观锁）。
- **红旗**：以为读写锁永远比互斥快；或以为读写锁写锁=互斥锁。
- **惊艳点**：点出"基准测试里互斥锁写操作明显优于读写锁写锁，因为读写锁写锁实现更复杂、还要管读锁相关逻辑" `[经验]`。

## 主问答
**Q（面试官原话）：** 几种锁怎么选，为什么读写锁写锁比互斥锁慢？

**先铺垫（由浅入深第 1 层）**：锁没有"万能最快"的。选锁的本质是匹配"临界区长度"和"读写比例"两个维度——错了就是要么多付切换开销、要么多付竞争阻塞。

1. **决策树（第 2 层·机制）**：不确定持有时间→互斥/读写；确定极短→自旋；读操作多→读写锁（读锁不互斥读）；读和写都频繁→互斥锁（读被写阻塞概率高、读写锁优势尽失）`[经验]`。
2. **Mutex 快路径（第 3 层）**：`sync.Mutex` 加锁先 `CAS` 判是否有竞争，无竞争直接获取、跳过慢路径，有竞争才睡眠等唤醒——这是它快的原因 `[源码]`。
3. **写锁≠互斥（第 4 层）**：读写锁底层就是用互斥锁实现的，还要额外管读锁计数/升级等逻辑，因此写锁更重；基准测试里互斥锁写操作明显比读写锁写锁快 `[实测]`。
4. **权衡（第 5 层）**：读多时读锁并发带来收益，覆盖写锁的额外开销才划算；一旦写变多，收益消失、反而更慢 `[经验]`。
5. **进阶（第 6 层）**：自旋锁只用于极短临界区或底层原语，普通业务别碰（见 1012 自旋锁实现）`[边界]`。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| Go 全版本 | 选型按场景；Mutex 先 CAS 快路径、读写锁写锁更重是通用事实 |
| sync.Mutex | 加锁先 CAS 抢锁（无竞争快路径），失败走 sema 睡眠 |
| sync.RWMutex | 写锁底层含互斥锁 + 读锁计数，写锁比纯 Mutex 重 |
| 推荐 | 不确定/读写都多→Mutex；读明显多→RWMutex；极短→自旋 |

## 关键代码
```go
package main

import "fmt"

// 锁选型决策树（经验规则）
func pick(reads, writes int, holdShort bool) string {
	if holdShort {
		return "spinlock" // 极短临界区
	}
	if reads > writes*4 {
		return "rwmutex" // 读明显多
	}
	return "mutex" // 不确定/读写都多
}

func main() {
	fmt.Println(pick(0, 0, true))     // spinlock
	fmt.Println(pick(100, 10, false)) // rwmutex
	fmt.Println(pick(50, 50, false))  // mutex（读写都多）
	fmt.Println(pick(10, 10, false))  // mutex（不确定）
}
```

## 总结与追问预判
**背这三句就够**：① **短→自旋、读多→读写锁、读写都多/不确定→互斥**；② **Mutex 先 CAS 快路径**；③ **读写锁写锁底层含互斥、比纯 Mutex 重**。
**预判追问**：
- 「自旋锁怎么写？」→ atomic CAS 忙等（见 1012 自旋锁实现）。
- 「Mutex 底层？」→ CAS 快路径 + sema 慢路径（见 925-mutex-impl）。
- 「为什么读写锁写更慢？」→ 写锁含读锁计数/升级逻辑，更重。
