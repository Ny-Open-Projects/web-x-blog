# 1112 复制代价与指针取舍

> 分类：Go/性能 | 难度：L3 | 题型：设计题 | 频率：中 | 关键词：**值复制成本** / **大 struct 用指针** / **GC 压力** / **间接值部**
> 原文锚点：第 16~39 段「赋值传参复制直接值部；避免大 struct/array 作参数/通道元素(用指针)；slice/map/chan/func/string/interface 不用指针(只复制header十几字节)；指针增GC压力；直接值部 vs 间接值部(切片底层共享)」

## 一句话总述
降值复制成本的核心取舍：**大 struct/array 作参数或通道元素时用指针**（避免复制整个直接值部），但指针增多会加大 GC 压力；而 **slice/map/chan/func/string/interface 本身只复制十几字节的 header（间接值部在底层共享），通常不用指针**——二者复制代价本来就很小。

## 面试官视角
- 意图：考察"用指针省复制"与"指针增 GC 压力"的权衡，而非无脑传指针。
- P5 知道大 struct 用指针；P6 能说清 slice/map 等只复制 header；P7 能讲清"间接值部共享"与"指针增 GC 压力"的取舍。
- 红旗：对所有类型都传指针（无视 GC 压力）；以为 slice 传参复制底层数据。
- 惊艳点：点出 slice 直接值部只 3 机器字、底层间接值部共享，故切片传参复制代价极小；指针是"用 GC 压力换复制成本"。

## 主问答
**Q（面试官原话）：** 为了减少复制，是不是都该用指针传参？
**A：**
1. **结论**：**大 struct / 大 array** 作函数参数或通道元素时，用指针避免复制整个直接值部（复制成本 = 值尺寸 × 频率）；但**指针本身增 GC 压力**，不能滥用。
2. **机制（省复制）**：slice/map/chan/func/string/interface 的"直接值部"只是 header（slice=3 机器字、string=2、interface=2、map/chan/func=1），复制只拷这十几个字节，**间接值部（底层数组/数据）在赋值时共享**，所以这些类型复制代价极小，通常**不用指针**。
3. **边界（代价权衡）**：指针让 GC 多追踪一个可达对象、增扫描与回收压力；高频创建指针对象会抵消"省复制"收益。经验法则：大值类型用指针、header 类类型不用指针 `[经验]`。

## 关键代码
```go
// 大 struct 传值 vs 传指针：传值复制整个直接值部（含 padding），传指针只复制 1 机器字
type Big struct{ a [1024]int64 } // 直接值部 = 8KB

func byValue(b Big)    {} // 每次调用复制 8KB
func byPointer(b *Big) {} // 每次调用复制 8B（指针），但 b 对 GC 可见

// slice 赋值是"直接值部(header)复制 + 间接值部(底层数组)共享"
s1 := make([]int, 3)
s2 := s1           // s2 与 s1 共享底层数组，仅 header(3机器字)被复制
s2[0] = 9          // s1[0] 也变成 9 —— 间接值部共享
_ = s2
```

## 总结与追问预判
- 大 struct/array 用指针省复制（但增 GC 压力）；slice/map 等只复制 header，不用指针。
- 预判：值尺寸体系 → 见 1112-value-size；for-range 复制陷阱 → 见 1112-forrange-copy-trap；传值机制见 923-slice-pass-by-value / 923-map-pass-by-value。
