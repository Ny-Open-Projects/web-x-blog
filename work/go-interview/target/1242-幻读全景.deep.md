# 1242 幻读全景：从定义到 RR 下复现（深卡）

> 分类：MySQL 事务 | 难度：L4 | 题型：体系题 | 频率：高 | 关键词：**幻读体系**/**发生场景**/**快照/当前读**/**RR 复现**/**间隙锁兜底**

> 原文锚点：第 1~57 段「幻读全节」

## 思路与架构
幻读这条线应按「**定义 → 发生场景 → RR 的两类读 → RR 下复现 → 锁兜底**」五层串起来：
- 定义层：结果集条数因别事务提交而变化（区别于不可重复读的「值变化」）。
- 场景层：RC/RU 下插入 / 删除 / 更新出范围三类必触发。
- 读模型层：RR 快照读靠 ReadView 隔离、当前读读最新。
- 复现层：RR 下「UPDATE 拉入新行」「FOR UPDATE 当前读」两口子仍幻读。
- 兜底层：间隙锁 / Next-Key 锁锁住间隙，从根上拦插入。

## 方案取舍
- **讲定义用对比法**：与不可重复读同框讲（值 vs 行数），记忆成本最低，对应 `1230-nonrepeatable-vs-phantom.md`。
- **讲机制用读模型**：快照读 / 当前读二分，是连接 MVCC 与锁的枢纽，对应 `1231-mvcc.deep.md` 与锁专题。
- **讲复现用两个具体 demo**：比空讲「很大程度避免」更有说服力，本深卡配套的 `1242-rr-phantom-recurrence.md` 承担此角色。
- **不重复锁内部**：间隙锁/Next-Key 锁的加锁细节交给 `1235-next-key-lock.md` / `1236-gap-lock-mechanics.md`，本卡只点「锁住间隙拦插入」一句。

## 答题技巧
1. 开场先给判据：**幻读看行数、不可重复读看值**——一句话立住。
2. 接着分档答：RC/RU 必发生（插/删/改出范围）→ RR 靠快照读大部分避免 → RR 下两口子仍幻读 → 串行化彻底避免但慢。
3. 收尾补锁语法版本差异（FOR SHARE vs FOR SHARE MODE）当加分项。
4. 若被追问「为什么 RR 还幻读」，直接上「脱离快照读 → 当前读」两个 demo，不要绕。
5. 边界话术：**「很大程度上避免，而非完全避免」**——这句是区分背定义与真懂的关键。

## 细节与核心 API

```sql
-- 幻读：同一事务两次“范围查询”得到不同行集（中途别的事务插入/删除了符合条件的行）
-- RR 隔离级别下，InnoDB 用 临键锁(next-key lock = 记录锁+间隙锁) 防止幻读
BEGIN;
SELECT * FROM orders WHERE amount > 100 FOR UPDATE;  -- 锁范围内所有间隙，阻止插入新行
-- 其他事务 INSERT 一条 amount=200 会被阻塞 -> 避免幻读
COMMIT;
-- 快照读（普通 SELECT）靠 MVCC 一致性视图天然不幻读；当前读（FOR UPDATE/UPDATE）靠 next-key lock
-- 对比：RC 隔离级别只有记录锁无间隙锁 -> 会幻读；RU 连脏读都有
-- 验证：SHOW ENGINE INNODB STATUS 看锁等待；information_schema.INNODB_LOCKS
-- 要点：RR 下“当前读”防幻读靠间隙锁，间隙锁会降低并发插入（热点区间慎锁）
```
