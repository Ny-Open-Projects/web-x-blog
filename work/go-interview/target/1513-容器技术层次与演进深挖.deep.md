# 1513 容器技术层次与演进 深挖

> 覆盖源 15-13 全文：LXC 定义 + 容器 vs 虚拟机 + Docker 与 LXC 五点差异。主卡已给对比结论，本附录做"隔离机制""分层存储""技术演进"三层深挖。

## 思路与架构

```text
容器技术层次
├─ 隔离机制: namespace(视图隔离) + cgroups(资源限额) —— 内核特性, LXC/Docker 共用
├─ 存储: LXC 模板建根fs(不分层) → Docker UnionFS(只读层共享 + 容器可写层)
└─ 演进: Docker 0.9.0 前依赖 LXC → 之后 libcontainer → runc/OCI 标准化, 上层接 K8s
```

## 方案取舍
- **容器 vs 虚拟机（互补）**：虚拟机让不同 OS 同跑一份硬件（各自内核、隔离强、开销大）；容器共享宿主机内核（启动快、密度高），代价是**必须与底层系统兼容**——不能让 x86 Linux 跑 arm Linux 容器 [经验]。
- **分层存储的收益**：UnionFS 让多个容器共享同一份只读镜像层，磁盘与拉取时间都省；容器自己的改动只写最上面的可写层，删除容器即丢弃改动 [经验]。
- **为什么要做 libcontainer**：把底层容器创建与管理从"依赖外部 LXC 工具"收归自研，才能统一行为、摆脱对特定工具链与外部进程的依赖，也为后续 OCI/runc 标准化铺路 [经验]。

## 答题技巧
- 被问"Docker 和 LXC 区别"先定位层次（应用交付 vs OS 虚拟化），再按生命周期/抽象/管理/分层/生态五点展开 [经验]。
- 别把容器和虚拟机对立——明确说"互补"，并补"共享内核所以需与底层兼容" [经验]。
- 主动边界到 `1515-k8s-architecture`(编排层)，构成"容器→编排"全栈 [边界]。
