# 409 init 的三个注意点：只执行一次、单 goroutine、禁止循环导入

> 分类：Go 基础 | 难度：L3 | 题型：陷阱题 | 频率：高 | 关键词：**只初始化一次**/**同一 goroutine**/**串行**/**循环导入**/**import cycle**

> 原文锚点：第 79~99 段「重复导入 / 单 goroutine / 循环导入」

## 一句话总述
三个必须记住的注意点：**①** 一个包被多次导入，**初始化只执行一次**；**②** 所有 init 都在**同一个 goroutine** 中按顺序串行执行；**③** 包之间**禁止循环导入**，a 导入 b 而 b 又导入 a 会直接编译失败。

## 面试官视角
这题考的是「你踩过坑没有」。第三条几乎人人知道，前两条才是区分度——尤其「所有 init 在同一 goroutine 串行」，能顺带推出「某个 init 阻塞会卡死整个启动」，就是工程视角。

## 主问答
**Q（面试官原话）：** 使用 init 有什么需要注意的？

1. **重复导入只初始化一次**：a 包导入 b 包、c 包也导入 b 包时，b 被引用多次，但它的初始化**只执行一次**，不会重复触发。
2. **执行时机取首次到达点**：按深度优先顺序，b 的 init 发生在遍历首次到达它的时候，而不是每次被导入都执行。
3. **都在同一个 goroutine**：所有 init 函数都在同一个 goroutine 里执行，且是**串行**的，不存在并发初始化。
4. **阻塞会拖垮启动**：正因为串行且处于启动阶段，任何一个 init 阻塞或 panic，整个程序都无法继续启动。
5. **禁止循环导入**：a 导入 b、b 又导入 a 形成死循环，这种情况不被允许，**编译期就会失败**。

| 注意点 | 表现 |
|--------|------|

| 执行载体 | 同一 goroutine 串行 |

## 关键代码
```go
// main2.go：pkg2 与 pkg3 都被导入，且 pkg2 也依赖 pkg3
package main

import (
	"fmt"
	"example.com/demo/pkg2" // pkg2 依赖 pkg3
	"example.com/demo/pkg3" // 再次导入，但 pkg3 的 init 只跑一次
)

func main() { fmt.Println(pkg2.V, pkg3.V) }
// 输出顺序：pkg3 的 init（随 pkg2 首次到达）→ pkg2 的 init → main
```

## 总结与追问预判
核心：**只一次、串行、禁循环**。追问常拐向「init 里起 goroutine 会怎样」，备好「goroutine 是并发的，但 init 本身不等待它，main 可能在它完成前就开始执行」这句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称循环导入「在编辑器里没有出现任何错误」但执行时报错——循环导入是**编译期**错误（典型信息为 import cycle not allowed），编辑器未实时诊断不代表代码合法。
2. 事实核校： [经验] 原文称「所有的 init 函数都会在同一个 goroutine 里面执行」——正确；本卡补充推论：正因为串行且处于启动阶段，任一 init 阻塞或 panic 都会让整个程序无法启动。
3. 崩坏词归一：源码将 init / 循环导入 / goroutine / 包 等音译为多组崩坏词，本卡统一为规范术语。
