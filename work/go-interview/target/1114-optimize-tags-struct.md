# 1114 优化 JSON 标签与结构

> 分类：Go 性能 / 序列化 | 难度：L3 | 题型：工程题 | 频率：中 | 关键词：**json 标签** / **嵌套** / **简单类型** / **存储占用** / **最后手段**
> 原文锚点：第 59~64 段「简短 json 标签减存储；简单类型少嵌套；前两点无空间再做」

## 一句话总述
前两招（换库、避 map）无优化空间后，再做**结构层优化**：用**简短 json 标签**（键值名参与存储与计算）、**简单数据类型**、**减少嵌套**——属于边际优化，优先级最低。

## 面试官视角
- 意图：是否知道还有结构层微调手段，且明白其优先级。
- 分档：P5 知标签可简写；P6 知标签名参与存储；P7 能讲清"这是最后手段、收益小"。
- 红旗：舍本逐末——先搞标签缩写却不去换库/避 map。
- 惊艳点：点出 json 标签的 key 名本身参与序列化后的存储与计算，缩短 key 直接减体积。

## 主问答
**Q（面试官原话）：** 标签和结构还能优化吗？
**A：**
1. **简短 json 标签**：标签定义的 key 名会写进序列化结果、参与存储与后续计算，用更短 key 直接减小体积（如 `json:"u"` 而非 `json:"user_name"`）。
2. **简单类型 + 少嵌套**：优先用基础类型，减少多层嵌套结构，降低编解码与遍历开销。
3. **优先级最低**：换库、避 map 是数量级优化；标签/结构是边际优化，仅当前两者已无空间时再做。
