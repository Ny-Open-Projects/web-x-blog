> 原文锚点：第 29~50 段「但是呢一致性哈希算法呢，它并不保证节点能够在哈希环上分布均匀…它还适合节点规模发生变化的场景」（节点分布不均 → 请求集中 → 雪崩连锁 → 虚拟节点两层映射 → 160 虚拟节点/真实节点 → 稳定性与权重）

## 一句话总述
一致性哈希的固有缺陷是**节点少时数据在环上分布不均、热点集中**；解法是引入**虚拟节点（virtual node）**——一个真实节点映射成多个环上随机散布的虚拟节点，从而把负载打散、提升均衡度与容灾稳定性，并支持按硬件权重分配虚拟节点数。

## 面试官视角
这是一致性哈希的「进阶考点」，区分背过定义的人和真正调过生产的人。考点：① 为什么需要虚拟节点（数据倾斜的本质）；② 虚拟节点怎么映射（两层映射）；③ 数量怎么定（工程值如 100~200/节点，Redis 为 160）；④ 虚拟节点如何顺带解决「权重」和「稳定性」。

## 主问答
**Q（面试官原话）：** 一致性哈希不是能保证均匀分布吗？为什么还要引入虚拟节点？

**A：**
1. **节点少必然倾斜**：一致性哈希只保证「寻址规则」，不保证节点在环上均匀。真实节点只有 3 个时，它们落在环上的位置随机，某节点顺时针管辖的区间可能远大于其他节点，**大量 key 集中到少数节点 → 热点 → 该节点宕机引发雪崩式连锁**。
2. **虚拟节点打散分布**：给每个真实节点生成多个（如 3 个、160 个）虚拟节点，随机散布到环上；虚拟节点数量变多后，环上分布趋近均匀，**单节点热点被分摊到多个真实节点的虚拟节点上**。
3. **两层映射**：真实节点不再直接落环，而是「真实节点 → 多个虚拟节点（如 node1 → node1-1/node1-2/node1-3）→ 环」，查数据时先命中虚拟节点，再反查其归属的真实节点。
4. **额外收益：权重 + 稳定性**。配置更高的机器可分配**更多**虚拟节点（权重），自然扛更多流量；节点变化时，它的多个虚拟节点被移除，其负载由**不同**真实节点的虚拟节点分别接管，比单节点变化更平滑、更稳。

## 版本与兼容性
- 虚拟节点数属**工程调参**：Guava/Cassandra 常用 100~200 个/真实节点；**Redis（一致性哈希变体）每个真实节点约 160 个虚拟节点**；Kafka 分区副本调度也借鉴此思想。
- 查找复杂度仍为 **O(log V)**（V = 虚拟节点总数），虚拟节点增多只增大常数，不退化成线性；这是「用空间换均衡」的可接受trade-off。

## 总结与追问预判
收口：**虚拟节点 = 用「真实节点→多个环上虚拟节点」的两层映射，把倾斜打散成均匀，并顺带支持权重与平滑容灾**。预判追问：① 虚拟节点数怎么选（经验值 + 压测）；② 和 Redis 槽位对比（见 `1712-consistent-hashing-overview.md` 版本兼容节）。回答时把「均衡度 / 权重 / 稳定性」三点一次说全，是高阶答案标志。

> **[经验]** 虚拟节点数不是越多越好：过多会增大 `ring` 内存与排序开销，过少则均衡不足。生产经验区间是 **100~200 虚拟节点/真实节点**（Redis 取 160）。面试给出具体数字 + 说明「O(log V) 不退化」比空谈「多加几个」更可信。

```go
// 虚拟节点：一个真实节点复制成 replicas 个环上位置
func (c *ConsistentHash) Add(node string) {
	for i := 0; i < c.replicas; i++ { // replicas 即虚拟节点数，如 160
		vh := c.hash([]byte(fmt.Sprintf("%s#%d", node, i)))
		c.ring[vh] = node        // 虚拟节点 hash -> 真实节点（两层映射第二层）
		c.sorted = append(c.sorted, vh)
	}
	sort.Slice(c.sorted, func(i, j int) bool { return c.sorted[i] < c.sorted[j] })
	c.nodes[node] = struct{}{}
}

// 按权重加节点：高配机给更多虚拟节点
func (c *ConsistentHash) AddWithWeight(node string, weight int) {
	// weight 倍 replicas，相当于权重越高的机器在环上占据越多弧段
	for i := 0; i < c.replicas*weight; i++ {
		vh := c.hash([]byte(fmt.Sprintf("%s#%d", node, i)))
		c.ring[vh] = node
		c.sorted = append(c.sorted, vh)
	}
	sort.Slice(c.sorted, func(i, j int) bool { return c.sorted[i] < c.sorted[j] })
}
```
