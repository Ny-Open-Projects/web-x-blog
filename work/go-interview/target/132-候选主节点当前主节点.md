# 132 候选主节点 ≠ 当前主节点

> 分类：Elasticsearch | 难度：L3 | 题型：陷阱题 | 频率：中高 | 关键词：**master-eligible、投票、cat nodes、选举**

> 原文锚点：第 15~16 段「配置里指定只能成为候选主节点…需要经过投票才能决定」

## 一句话总述
配置里把节点设为主节点角色，得到的只是**候选资格**；谁是真正的主节点，要等集群启动后由投票决定，看监控时也不能把角色列当成当选标志。

## 面试官视角
P6 会答"配了就是主节点"；P7 要立刻区分三层：配置给资格、投票定结果、集群中**有且只有一个**主节点 `[经验]`。加分点是排查手势——`_cat/nodes` 的角色列里那个字母只代表候选，要看**主节点列**是否为星号才知当前谁在主位 `[源码]`。

## 主问答
**Q（面试官原话）：** 怎么确认集群里哪个节点是主节点？

1. **配置只给资格**：在配置里打开主节点角色，节点成为候选主节点，能否真正当选要经投票 `[经验]`。
2. **集群只有一个主节点**：它负责索引创建删除、分片分配、配置变更等管理与协调工作 `[源码]`。
3. **角色字母不代表当选**：列表里那个字母只表示"有资格"，别把它当现任标志 `[经验]`。
4. **看主节点列**：带星号的那个才是当前主节点；另外一个字母表示仅参与投票不参选 `[实测]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ES 6.x | node.master 布尔配置 | 开启即候选 |
| ES 7.x 起 | node.roles 列表 | 含主节点角色即候选 |
| ES 7.x 起 | 引入仅投票节点 | 参与选举但不参选 |

## 关键代码
```bash
GET _cat/nodes?v          # role 列含 m = 候选；master 列 * = 当前主节点
GET _cat/nodes?h=ip,node.role,master
```
```go
// 客户端不必感知主节点，连接协调节点即可
resp, _ := http.Get("http://coord:9200/_cat/nodes?h=node.role,master&v")
```
> 验证：三节点集群中三者 role 均含候选字母，而 master 列只有一行是 `*` `[实测]`。

## 总结与追问预判
**资格 ≠ 结果，角色列 ≠ 主节点列**。这两句话能挡掉大半误判。
