# 101 并发与并行的区别及单核多线程机制

> 分类：并发基础 | 难度：L3 | 题型：概念题 | 频率：高 | 关键词：**并发**/**并行**/**时间片**/**单核多线程**/**上下文切换**
> 原文锚点：第 13~30 段「为什么必须掌握并发编程 + 并发与并行 + 单核多线程」

## 一句话总述
**并发**是「同一时间段内多个任务交替执行、都未结束」，强调交替；**并行**是「单位时间内多个任务真正同时执行」。单核 CPU 靠时间片轮转实现多线程并发，任意时刻只有一个线程的指令在核上运行。

## 面试官视角
- 考察意图：是否真正分清并发（concurrency）与并行（parallelism）这对高频混淆概念，以及是否理解单核也能跑多线程的底层机制。
- 分档：P5 知并发≠并行；P6 知并发=交替、并行=同时；P7 知单核靠时间片切换、并发程序「可能并行也可能不」。
- 红旗答案：把并发和并行混为一谈；或认为单核不能跑多线程。
- 惊艳点：点出「并发涉及上下文切换、并行不一定」「多核时代并发才容易变成并行」。

## 主问答
**Q（面试官原话）：** 并发和并行有什么区别？单核处理器能支持多线程吗？
**A：**
1. **并发（concurrency）**：同一时间段内多个任务都在推进但未结束，任务间交替执行；某一时刻（单位时间）只有一个任务在运行，因此并发必然伴随上下文切换。
2. **并行（parallelism）**：单位时间内多个任务真正同时执行，需要多核/多 CPU 支撑；并发程序若跑在多核上「可能」是并行的，单核上则只是并发。
3. **单核多线程机制**：CPU 用时间片分配算法循环执行任务，给每个线程分配一段 CPU 时间（通常几十毫秒），时间片用完就让出 CPU 给下一线程，靠快速切换制造「同时运行」的错觉。
4. **比喻**：多核好比多个饮水机，单位时间内每个饮水机只服务一人，但多台可同时给多人接水；单核则是一台饮水机排队接水。

## 关键代码
```go
// 并发：单核上两个 goroutine 交替执行（Go 调度器时间片轮转）
func concurrentDemo() {
	go func() { // goroutine A
		for i := 0; i < 3; i++ {
			fmt.Println("A", i) // 与 B 交替输出
		}
	}()
	go func() { // goroutine B
		for i := 0; i < 3; i++ {
			fmt.Println("B", i)
		}
	}()
	time.Sleep(time.Millisecond) // 等两个 goroutine 跑完
}
// 并行：runtime.GOMAXPROCS(多核) 时 A、B 可真正同时在不同核上运行
```

## 总结与追问预判
并发强调「交替推进」、并行强调「同时执行」，单核靠时间片轮转伪造并发。并发必然带来上下文切换——下一张讲切换的代价。
