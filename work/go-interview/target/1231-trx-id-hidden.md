# 1231 事务 ID 生成与三个隐藏列

> 分类：MySQL 事务 | 难度：中高 | 题型：原理 | 频率：中 | 关键词：**事务ID、Max Trx ID、隐藏列、DB_TRX_ID、DB_ROLL_PTR、DB_ROW_ID**

> 原文锚点：第 36~49 段、第 73~78 段「全局变量自增、256 倍数刷盘、重启+256、二级索引页头存最大事务ID」

## 一句话总述
事务 ID 由内存中的全局变量自增分配；**每当变量值是 256 的倍数**时刷到系统表空间页号 5 的 Max Trx ID 属性（8 字节）；重启时把该值载入内存并**加 256** 再赋给全局变量（因上次关机时全局变量可能大于未刷盘的值，加 256 保证仍是最大）。聚簇索引行有三个隐藏列：DB_TRX_ID(6B)、DB_ROLL_PTR(7B)，无主键时追加 DB_ROW_ID(6B)。二级索引不存行级事务 ID，改由**页头 PAGE_MAX_TRX_ID(8B)** 记录。

## 面试官视角
这题考细节深度。考官期待你讲清 256 这个魔数的来由（刷盘粒度 + 重启安全余量），以及二级索引为何不能逐行存事务 ID——答：那样每次更新要维护所有索引的事务 ID，代价太大，故退化为「页级粗粒度判断 + 必要时回聚簇索引」。

## 主问答
**Q（面试官原话）：** 事务 ID 是怎么生成的？二级索引怎么判断可见性？

1. **分配策略**：内存维护全局自增变量，需要时把当前值作为事务 ID 分给事务并自增；生成策略与隐藏主键列 DB_ROW_ID 大致相同。
2. **持久化**：变量值为 **256 的倍数**时刷入系统表空间页 5 的 Max Trx ID 属性（8 字节）；重启时载入该值并 **+256** 赋回全局变量，保证事务 ID 仍是当前最大。
3. **隐藏列**：聚簇索引行含 DB_TRX_ID(6B，最近修改事务 ID)、DB_ROLL_PTR(7B，回滚指针指向 undo log)；无自定义主键/唯一键时再补 DB_ROW_ID(6B)。
4. **二级索引方案**：叶子只存主键值+索引列值，**不存行级事务 ID**；改在数据页页头(56 字节)用 **PAGE_MAX_TRX_ID(8B)** 记录本页最大事务 ID——若它小于最小活跃事务 ID，则整页记录对本事务都可见，否则需回聚簇索引逐行判断。

## 版本与兼容性
| 隐藏列 | 大小 | 作用 |
|--------|------|------|
| DB_TRX_ID | 6B | 最近修改事务ID |
| DB_ROLL_PTR | 7B | 指向 undo log |
| DB_ROW_ID | 6B | 无主键时的隐藏主键 |

## 关键代码
```text
页头 PAGE_MAX_TRX_ID(8B) < 最小活跃事务ID → 该二级索引页所有记录可见
否则 → 回聚簇索引逐行判断
```

## 总结与追问预判
核心：**事务 ID 全局自增、256 倍数刷盘、重启 +256；三隐藏列；二级索引靠页头 PAGE_MAX_TRX_ID 粗判**。追问可回「可见性算法」（见 1231-visibility）。
