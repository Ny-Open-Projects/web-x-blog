# 1828 管道（匿名/命名）与消息队列

> 分类：内存与 OS | 难度：L2 | 题型：机制题 | 频率：中 | 关键词：**匿名管道** / **命名管道** / **亲缘关系** / **mkfifo** / **消息队列长度限制**
> 原文锚点：第 4~20 段「管道半双工…匿名仅父子/命名任意…pipe创建/mkfifo…消息队列内核列表/类型传递/长度限制/拷贝开销」

## 一句话总述
管道是半双工、先进先出的流式通道：匿名管道靠 pipe 创建、仅用于有亲缘关系的进程、随进程销毁；命名管道靠 mkfifo 在文件系统留名、可用于任意进程、生命周期独立于进程。消息队列是内核中的消息链表，按类型传递、可靠但消息体有长度上限且需用户态↔内核态拷贝。

## 面试官视角
- 意图：能否区分匿名/命名管道的差异，并说清消息队列的利弊。
- P5 知管道半双工、匿名仅父子；P6 说清命名管道跨进程/持久、消息队列长度限制；P7 知消息队列的拷贝开销与适用边界。
- 红旗：以为命名管道也是随进程销毁；忽略消息队列的体长度上限。
- 惊艳点：匿名管道生命周期绑定进程（所有 fd 关闭即销毁），命名管道是文件系统对象、需显式删除——这是二者最易被问到的差别 `[经验]`。

## 主问答
**Q（面试官原话）：** 匿名管道和命名管道有什么区别？消息队列有什么优缺点？
**A：**
1. **匿名管道**：pipe 创建、无名字、仅用于父子等亲缘进程、生命周期随创建进程（引用全关即销毁）`[源码]`。
2. **命名管道**：mkfifo 创建、文件系统有名、任意进程凭路径访问、生命周期独立于进程（需显式删除）。
3. **消息队列**：内核维护消息链表、按类型传递、可靠性高；但有消息体最大长度限制，且收发存在用户态↔内核态数据拷贝开销。
4. **取舍**：简单流式父子通信选匿名管道；跨进程持久通道选命名管道；需结构化按类型投递选消息队列（忍拷贝开销）。

## 关键代码
```go
// 示意，未验证：Go 用 os.Pipe 建匿名管道；命名管道可用 syscall.Mkfifo 创建
package main
import ("fmt"; "os")
func main() {
    r, w, _ := os.Pipe() // 匿名管道：仅本进程派生出的亲缘进程可用
    go func() { w.Write([]byte("anon pipe")) }()
    buf := make([]byte, 32)
    n, _ := r.Read(buf)
    fmt.Println("匿名管道:", string(buf[:n]))
    // 命名管道：syscall.Mkfifo("/tmp/np", 0600) 后在文件系统中可见，任意进程可 open 读写
}
```
