# 173 数组栈 vs 链表栈：怎么选

> 分类：数据结构 / Go | 难度：L3 | 题型：选型题 | 频率：中 | 关键词：**数组栈**/**链表栈**/**随机访问**/**顺序访问**/**读多写少**/**写多读少**

> 原文锚点：第 50~54 段「数组栈与链表栈的优劣对比」

## 一句话总述
两者都 O(1) 出入栈，差异在**内存布局与访问模式**：数组栈底层连续、支持随机访问、查询快但增删要搬移；链表栈不连续、只顺序访问、查询慢但增删只改指针。**读多写少用数组栈，写多读少用链表栈**。

## 面试官视角
选型题考的是「场景匹配」而非「背结论」。能说出「数组靠连续内存换随机访问、链表靠指针换增删自由」，再落到「读多写少 / 写多读少」的取舍，就是合格回答；补一句「切片扩容偶发 O(n) 摊销仍 O(1)」更稳。

## 主问答
**Q（面试官原话）：** 数组栈和链表栈该怎么选？

1. **内存布局不同**：数组栈底层是连续内存块，下标即地址，操作系统寻址 O(1)；链表栈节点散落、靠指针串，不连续。
2. **访问模式不同**：数组栈支持随机访问，按索引直接取元素；链表栈只顺序访问，取非栈顶需遍历。
3. **增删成本不同**：数组栈 push 可能触发扩容搬移（均摊 O(1)），pop 若重建切片也有复制；链表栈 push/pop 仅改指针，无搬移。
4. **选型口诀**：**读多写少 → 数组栈**（利用随机访问快）；**写多读少 → 链表栈**（利用增删只改指针）。
5. **注意点**：数组栈要防「截取式 pop 内存泄漏」（见 `173-array-stack.md`）；链表栈每个节点有指针额外开销、缓存局部性差。

## 版本与兼容性
| 维度 | 数组栈（切片） | 链表栈 |
|------|----------------|--------|
| 内存 | 连续、缓存友好 | 散落、缓存差 |
| 访问 | 随机 O(1) | 顺序 O(n) |
| 增删 | 可能搬移（均摊 O(1)） | 仅改指针 O(1) |
| 适用 | 读多写少 | 写多读少 |

## 总结与追问预判
核心：**数组栈赢在随机访问、链表栈赢在增删自由；按读写比重选型**。追问常拐向「Go 运行时栈是哪种」——注意那是 goroutine 调用栈（连续内存 + 可增长），属 runtime 概念，与本卡用户态数据结构栈不同（见 `173-stack-overview.deep.md` 边界声明）。
