# 409 init 顺序（二）：跨包与依赖链

> 分类：Go 基础 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**深度优先**/**最后被依赖最先初始化**/**import 顺序**/**依赖图**/**main 最后**

> 原文锚点：第 11~14 段「包的依赖顺序」、第 48~74 段「pkg1/pkg2/pkg3 依赖示例」

## 一句话总述
跨包时先看**依赖**：**最后被依赖的包最先初始化**。无相互依赖的包按 main 包中 import 的先后顺序执行；一旦某包有依赖，就先把它依赖的包全部初始化完，再执行它自己的 init。

## 面试官视角
考官会给一个依赖图让你排顺序。正确模型是**对导入图做深度优先后序遍历**：一个包的 init 永远在它所有依赖的 init 之后。能用「pkg1 → pkg3 → pkg2 → main」这个例子讲清楚，比背「最后被依赖最先」这句话可信得多。

## 主问答
**Q（面试官原话）：** 多个包都有 init，main 依赖它们，执行顺序是什么？

1. **无依赖则按 import 序**：不同包之间若互不依赖，按照 main 包中 import 的先后顺序调用各自的 init。
2. **有依赖则倒过来**：若包之间存在依赖，**最后被依赖的包最先被初始化**；依赖链最深的一端最先执行。
3. **递归展开**：main 依赖 a、a 依赖 b、b 依赖 c 时，顺序为 c → b → a → main 的 init。
4. **示例推演**：main 导入 pkg1 与 pkg2，pkg2 又依赖 pkg3；则先执行 pkg1，执行 pkg2 时发现其依赖 pkg3，于是先执行 pkg3，最后才是 pkg2。
5. **main 永远最后**：所有包的 init 全部执行完成后，才轮到 main 包的 init 与 main 函数。

## 版本与兼容性
| 情形 | 顺序 |
|------|------|
| 无依赖 | 按 import 先后 |
| 有依赖 | 被依赖者先 |
| 依赖链 c←b←a | c → b → a |
| 收尾 | 所有 init 后执行 main |

## 关键代码
```go
package main

import (
	_ "example.com/demo/pkg1" // 无外部依赖，最先初始化
	_ "example.com/demo/pkg2" // 依赖 pkg3，故 pkg3 先于它
)

func init() { println("main init") } // 最后执行

func main() { println("main") }
// 输出：pkg1 → pkg3 → pkg2 → main init → main
```

## 总结与追问预判
核心：**依赖优先 + import 序兜底 + main 最后**。追问常拐向「被多个包同时导入的包什么时候初始化」，备好「只初始化一次，且发生在深度优先首次到达时」这句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文表述为「按 import 顺序执行，遇到依赖则先执行被依赖的包」——结论正确，但更准确的模型是**对包导入图做深度优先后序遍历**：一个包的 init 只在其全部依赖都初始化完成后才执行。
2. 事实核校： [经验] 原文推断「pkg3 的 init 是在导入 pkg2 时触发的，而非 main 导入 pkg3 时」——推断正确，正是深度优先后序遍历的自然结果，本卡保留并给出规范解释。
3. 崩坏词归一：源码将 init / import / 依赖 / main 等音译为多组崩坏词，本卡统一为规范术语。
