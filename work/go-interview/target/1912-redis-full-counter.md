## 一句话总述
Redis 全量存储是把所有计数器直接放 Redis：靠**哈希分片集群**提写性能、靠**主从复制+读写分离**提读性能、靠**持久化**保数据安全，是中大型场景的理想方案。但 Redis 是内存存储，单计数值有效利用率仅约 18.5%，千亿级数据 + 一主三从 + 多数据中心轻松突破 100T、需上千台大内存服务器，**成本极高**。

## 面试官视角
面试官想看你懂 Redis 集群的伸缩手段，也懂它的**成本/内存效率**边界——这正是引出 Pika 等磁盘型方案的铺垫。

## 主问答
**Q（面试官原话）：** 直接用 Redis 全量存计数器行不行？有什么代价？

**A：**

1. **集群化提写**：用哈希分片把计数打散到多分片，Redis Cluster 写性能随分片数近线性提升，能扛高并发写。
2. **主从提读**：主节点后挂多个从节点做读写分离，读流量分摊，显著提升整体读写吞吐；AOF/RDB 持久化保证重启不丢数据。
3. **内存效率极低**：一个 `key=长整型ID + value=4字节计数`，Redis 自身元数据至少占 ~65 字节，而实际有效数据只需 12 字节，**有效利用率 ≈ 12/65 ≈ 18.5%**；若 ID 要存 4 类 4 字节计数，利用率更低。
4. **成本爆炸**：千亿级历史记录，单副本即超物理内存；一主三从 + 多数据中心部署轻松 >100T，按单机 100G 内存算需上千台大内存服务器，存储成本难以接受。结论：Redis 全量**性能理想但成本不可承受**。
