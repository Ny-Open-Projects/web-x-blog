# 516 for range 遍历指针数组：nil 元素解引用 panic 与 `_` 安全遍历

> 分类：Go 陷阱 / for range | 难度：L3 | 题型：陷阱题 | 频率：中 | 关键词：**指针数组** / **nil 元素** / **解引用 panic** / **忽略值** / **下划线**
> 原文锚点：第 37~46 段「指针类型数组遍历:value为nil时解引用panic(控制帧异常);安全遍历用下划线忽略值只取下标或先判空」

## 一句话总述
遍历**指针数组/切片**时，若元素可能为 `nil`，在循环里直接解引用 `v` 会 **panic（无效内存地址/控制帧异常）**。安全做法：用**下划线 `_` 忽略值、只取下标** `for i := range arr` 再访问 `arr[i]`（并先判空），避免对 nil 元素解引用。

## 面试官视角
- 意图：考察对"指针元素可能为 nil"的防御性遍历，以及对 range 变量取值时机（遍历中即解引用）的敏感。
- P5 知指针数组 nil 会 panic；P6 知用 `_` 忽略值、取下标并判空；P7 知"遍历中解引用"与"延后访问"的时序差异、panic 类型含义。
- 红旗：在 range 里直接 `*v` 而不判空；或不知 `_` 忽略值能规避。
- 惊艳点：点出"控制帧异常"本质是 nil 指针解引用的运行时崩溃，与"先判空再访问"的防御范式 `[边界]` 见 414-nil-pointer-array（nil 指针数组）、415-nil-slice-vs-array（nil 语义）、516-range-address-trap（取地址陷阱同源）。

## 主问答
**Q（面试官原话）：** 遍历指针数组为什么会 panic？怎么安全遍历？
**A：**
1. **nil 解引用 panic**：指针数组元素可能为 `nil`；`for _, p := range arr` 中 `p` 是 nil 时直接 `*p` 解引用，触发无效内存地址运行时崩溃（控制帧异常）。
2. **用 `_` 忽略值**：`for i := range arr` 只取下标、忽略值，再访问 `arr[i]` 并先判 `arr[i] != nil`，安全遍历不 panic。
3. **先判空再访问**：无论是否用 `_`，凡涉及指针元素解引用都应先判空，是防御性编程基线。
4. **与副本陷阱同源**：这里 `p` 也是副本语义，但问题不在副本而在"nil 解引用"，与 516-range-address-trap 同属 range 变量使用陷阱族。

## 关键代码
```go
package main

import "fmt"

func main() {
	arr := []*int{nil, nil, nil} // 指针数组，元素可能为 nil

	// 陷阱：value 为 nil 时解引用 → panic（无效内存地址）
	for _, p := range arr {
		fmt.Println(*p) // panic
	}

	// 安全：忽略值，只取下标，先判空再访问
	for i := range arr {
		if arr[i] != nil {
			fmt.Println(*arr[i])
		}
	}
}
```

## 总结与追问预判
- 指针数组遍历：nil 解引用 panic；用 `_` 忽略值 + 下标 + 判空安全遍历。
- 预判：nil 指针数组 → 见 414-nil-pointer-array；nil slice/array 语义 → 见 415-nil-slice-vs-array；取地址陷阱同源 → 见 516-range-address-trap；副本语义 → 见 516-range-value-copy。
