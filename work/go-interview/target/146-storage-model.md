# 146 Kafka 存储模型：topic→分区→日志段

> 分类：消息中间件 / Kafka | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**topic、分区、日志段、物理文件夹、索引文件、顺序写**

> 原文锚点：第 1~10 段「消息以 topic 归类，每 topic 分多个分区；不分副本时一分区对应一日志文件…引入 log segment 切分…物理上以文件夹存储，每 log segment 对应一个日志文件与两个索引文件」

## 一句话总述
Kafka 存储分层：topic → 多个分区 → 每分区一个日志（log）→ 切分为多个日志段（log segment）。物理上分区是文件夹（如 test-0），每段含 1 个日志文件 + 2 个索引文件（.index 偏移量、.timeindex 时间戳），消息顺序追加写。

## 面试官视角
P6 能说出 topic/分区/日志段三层；P7 要讲清「只有最后一个活跃段可写、其余只读」，以及段对应「1 日志 + 2 索引」的物理文件结构。

## 主问答
**Q（面试官原话）：** Kafka 的数据是怎么存的？

1. **三层模型**：topic 逻辑独立，下设多个分区；不考虑副本时一分区对应一个日志 `[源码]`。
2. **日志段**：为防止单文件过大，日志切分为多个 log segment，便于维护与清理 `[源码]`。
3. **物理结构**：分区是文件夹，段对应磁盘上「1 日志文件 + 2 索引文件（.index/.timeindex）」`[源码]`。
4. **顺序写**：消息顺序追加，只有最后一个活跃段可写，之前段只读 `[源码]`。
5. **目录示例**：topic=test 两分区即 test-0、test-1 两目录，各含日志与索引文件 `[经验]`。
