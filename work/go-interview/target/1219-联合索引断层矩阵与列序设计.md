# 1219 联合索引断层矩阵与列序设计

> 分类：MySQL 索引 | 难度：L3 | 题型：设计题 | 频率：高 | 关键词：**联合索引** / **最左列** / **断层** / **列序设计** / **高区分度**
> 原文锚点：第 27~32 段「联合索引(ABC)：查 ABC/AB/A 可用；查 AC 仅 a 可用(b断层)；查 BC/B/C 不可用；索引从 a 开始」

## 一句话总述
联合索引 `(a,b,c)` 必须从**最左列**起连续匹配：查 `a`/`ab`/`abc` 都能用索引；一旦中间列断层（如只查 `a`+`c`，跳过 `b`），断层之后的列（c）就**用不上索引**；完全不从 `a` 起（查 `b`/`c`/`bc`）则整棵索引失效。列序设计上，把**高区分度、最常用作过滤**的列放最左。

## 面试官视角
- 意图：能否给出"哪些组合能命中索引"的精确矩阵，并据此设计列序。
- P5 知联合索引要从最左列；P6 知断层后列失效（AC 仅 a 用）；P7 知"列序按区分度+查询频率排，范围列放最后"。
- 红旗：以为 `(a,b,c)` 查 `a`+`c` 也能用 c 的索引；或列序随手排。
- 惊艳点：点出"断层失效是因为 B+树按 (a,b,c) 字典序排，跳 b 后 c 在全局无序" `[边界]` 见 1222（例外汇总）、1221-index-design-principles（设计原则）。

## 主问答
**Q（面试官原话）：** 联合索引 (a,b,c) 哪些查询能用上索引？
**A：**
1. **连续前缀可用**：`WHERE a=?` / `a=? AND b=?` / `a=? AND b=? AND c=?` 都从最左列起连续匹配，全用索引。
2. **断层后失效**：`a=? AND c=?` 跳过 `b`，`c` 在 (a,b,c) 字典序中全局无序，故 **c 用不上索引**（只有 a 用）。
3. **不从最左起全失效**：`b=?` / `c=?` / `b=? AND c=?` 没从 a 起，整棵联合索引无法定位，失效。
4. **列序设计**：把区分度高、最常作等值过滤的列放最左；**范围列（>、<、BETWEEN）放最后**，否则其后续列全失效（见 1219）。

## 关键代码
```sql
-- 联合索引 (a,b,c)
CREATE INDEX idx_abc ON t(a,b,c);
EXPLAIN SELECT * FROM t WHERE a=1 AND b=2 AND c=3; -- 三列都用 (ref/range)
EXPLAIN SELECT * FROM t WHERE a=1 AND c=3;          -- 仅 a 用，c 断层失效
EXPLAIN SELECT * FROM t WHERE b=2 AND c=3;          -- 全失效 (type 差)
```

## 总结与追问预判
- 联合索引最左连续匹配；断层后列失效；列序按区分度+频率，范围列放最后。
- 预判：断层例外(覆盖) → 见 1222；范围断层 → 见 1219；索引设计原则 → 见 1221。
