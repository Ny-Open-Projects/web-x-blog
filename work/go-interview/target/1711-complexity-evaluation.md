# 1711 算法复杂度到底怎么估？大 O 的三条分析规则

> 分类：数据结构与算法 / 基础 | 难度：L2 | 题型：方法论题 | 频率：高 | 关键词：**大 O**/**渐进时间复杂度**/**相加取最大阶**/**嵌套相乘**/**空间复杂度**
> 原文锚点：第 6~33 段「假设每行代码的执行时间都是一样的，因此代码的执行时间就和执行次数成正比…大 O 并不是具体表示代码真正的执行时间，它表示的是代码执行时间随着数据规模增长的变化趋势…只需要关注循环执行次数最多的代码段…多段代码相加取量级最大的…嵌套代码等于嵌套内外代码复杂度的乘积…空间复杂度表示算法的存储空间与数据规模之间的增长关系」

## 一句话总述
衡量算法效率看两个指标——**时间复杂度**与**空间复杂度**。复杂度的估法建立在一个近似假设上：**每行代码执行时间相同，于是执行时间正比于执行次数**。由此得到的 **大 O 表示法并不给出真实耗时**，它描述的是**耗时随数据规模 n 增长的变化趋势**，所以全称是**渐进时间复杂度**。分析时只要抓住三条规则：**只看循环次数最多的那段**、**多段相加取最大阶**、**嵌套则内外相乘**。

## 面试官视角
- 考察意图：这是一道**方法论地基题**。面试官不是要你背 O(1)/O(n)，而是看你能不能**拿到一段陌生代码就给出正确量级**，以及是否理解"忽略系数"这个近似到底忽略了什么。
- 分档：P5 只会背常见排序的复杂度；P6 能说出三条分析规则；P7 能指出**大 O 是上界、忽略系数在工程上会误导**、**空间复杂度默认是额外空间**、以及**均摊与最坏的区别**。
- 红旗答案：「一亿次循环所以复杂度很高」「O(n) 一定比 O(n²) 快」——前者不知道**常量是 O(1)**，后者不知道**小数据量下常数因子主导**。
- 惊艳点：补一句「`append` 是**均摊** O(1)、单次最坏 O(n)；快排的 O(n log n) 是**平均**、最坏退化到 O(n²)——**说复杂度必须带情形**」 [经验]。

## 主问答
**Q（面试官原话）：** 拿到一段代码，你怎么估它的复杂度？
**A：**
1. **基本假设**：从 CPU 角度看每行代码做的都是"读数据—运算—写数据"，假设**每行执行时间相同**，则**执行时间与执行次数成正比**，于是可以用**语句执行次数**来代表执行时间 [源码]。
2. **大 O 的真实含义**：它**不等于代码的真实执行时间**，表示的是**执行时间随数据规模增长的变化趋势**，因此全称是**渐进时间复杂度** [源码]。
3. **规则一：只关注循环次数最多的那段**。既然只表示趋势，公式里的**常量、低阶项、系数都可以忽略**，只保留**最大阶**；那段核心代码执行次数的量级就是整段代码的复杂度 [源码]。所以**一亿次循环也是 O(1)**——它不随 n 变化 [经验]。
4. **规则二：多段相加取最大阶**。两段代码顺序执行，复杂度相加，结果取量级最大的那段：`O(n) + O(n²) = O(n²)`；即使写成 `O(2n)`，忽略系数后仍是 `O(n)` [源码]。
5. **规则三：嵌套相乘**。嵌套代码的复杂度等于**内外复杂度的乘积**：外层 `O(n)` 套内层 `O(n)` → `O(n²)`；外层 `O(n)` 套内层 `O(n²)` → `O(n³)` [源码]。
6. **空间复杂度**：全称**渐进空间复杂度**，表示**算法的存储空间与数据规模 n 之间的增长关系**。例如一个变量 `x` 是**常量阶**（与 n 无关），而切片 `s` 的元素个数**始终等于 n**，所以该段代码空间复杂度为 **O(n)** [源码]。
7. **它的定位**：复杂度分析的价值在于**直观对比多种实现的效率差异**，是粗粒度评估而不是精确计时——这也正是"假设每行耗时相同"这个近似能被接受的原因 [源码]。

## 关键代码
```go
// 规则一&二：常量段 + O(n) 段 + O(n) 段 → 相加取最大阶 = O(n)
func demo(n int) int {
	sum := 0
	for i := 0; i < 100_000_000; i++ { // 一亿次，但仍是 O(1)：不随 n 变化
		sum++
	}
	for i := 0; i < n; i++ { // O(n)
		sum += i
	}
	for j := 0; j < n; j++ { // 又一个 O(n)，合计 O(2n) → 忽略系数仍是 O(n)
		sum += j
	}
	return sum
}

// 规则三：嵌套相乘 → O(n) * O(n) = O(n²)
func nested(n int) int {
	cnt := 0
	for i := 0; i < n; i++ { // 外层 n 次
		for j := 0; j < n; j++ { // 内层 n 次
			cnt++
		}
	}
	return cnt
}

// 空间复杂度 O(n)：s 的元素个数随 n 线性增长，x 只占常量
func space(n int) int {
	x := 0          // 常量阶，与 n 无关
	s := make([]int, n) // O(n) 的额外空间
	for i := range s {
		x += i
	}
	return x
}
// [实测] 要点：demo(10) 与 demo(1000) 中 O(1) 段耗时几乎不变，只有 O(n) 段随 n 线性增长
```

## 总结与追问预判
一句话记忆：**「常量不算阶、相加取最大、嵌套就相乘」**。具体算法的复杂度结论（如快排的平均/最坏情形与递归栈空间）见 `1717-complexity`、数据结构与算法备考地图见 `171-dsa-interview-prep` [边界]，本卡只给**通用估法**。常追问「大 O 相同是不是就一样快」——答：**不一定**。大 O 忽略了系数与低阶项，`O(100n)` 与 `O(n²)` 在 n 很小时前者可能更快；**复杂度决定的是规模变大后的走势，不是当下的绝对快慢**。再追问「空间复杂度算不算输入本身」——答：**默认算的是额外（辅助）空间**，若把输入也算进去必须显式说明，否则会与惯例冲突。

## ⚠️ 原文纠错
1. 事实核校： [经验] 三条规则与"一亿次循环为 O(1)"的判据均正确。三处补充——① **大 O 是上界**，另有 Ω 下界与 Θ 紧确界，日常口语里的"复杂度"实际多用 Θ 语义；② 复杂度**必须带情形**：如 `append` 是**均摊** O(1)、单次最坏 O(n)，快排平均 O(n log n)、最坏 O(n²)，原文未区分；③ 空间复杂度**默认指额外空间**，不含输入本身。
