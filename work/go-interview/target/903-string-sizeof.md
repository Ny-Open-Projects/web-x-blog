# 903 unsafe.Sizeof("hello") 是多少：string 是 16 字节的结构体

> 分类：Go 基础 / string | 难度：L3 | 题型：代码题 | 频率：高 | 关键词：**unsafe.Sizeof、string 结构体、uintptr、len、16 字节**

> 原文锚点：第 50~56、84 段「为什么字符串 ABC 和字符串中文，它的 sizeof 值都是十六呢？这是因为 unsafe.Sizeof 返回的是数据类型的大小，而 string 在 Go 语言里面其实是一个结构体类型…它包含两个字段，一个是 data 字段，它是 uintptr 类型，表示指向实际存储字符串字节的数组的指针，第二个字段是 len，它是 int 类型，指的是字符串的长度…在六十四位操作系统上，uintptr 和 int 都是八字节，所以字符串整个结构的大小就是十六字节」

## 一句话总述
`string` 在 Go 中是一个**结构体**：`data uintptr`（指向底层字节数组的指针）+ `len int`（字节长度）；**64 位系统上两者各 8 字节，故 `unsafe.Sizeof` 恒为 16 字节**，与字符串内容长短无关。

## 面试官视角
P6 会猜 8 或按字符数答；P7 要讲清 **string 是描述符而非数据本体**——`unsafe.Sizeof` 量的是这个描述符的大小（固定 16），不是底层字节数组的大小；并指出它与 `len()` 的区别。

## 主问答
**Q（面试官原话）：** `unsafe.Sizeof("hello")` 结果是多少？为什么？

1. **常见问法**：面试官往往不直接问底层结构，而是问 `unsafe.Sizeof` 的结果并要求解释 `[源码]`。
2. **函数语义**：`unsafe.Sizeof` **返回的是数据类型的大小**，不是字符串内容的字节数 `[源码]`。
3. **string 是结构体**：在 Go 中 `string` **本质是一个结构体类型**，不是裸字节数组 `[源码]`。
4. **字段一 · data**：类型为 **uintptr**，是**指向实际存储字符串字节的数组（字节切片）的指针** `[源码]`。
5. **字段二 · len**：类型为 **int**，表示**字符串的长度（字节数）** `[源码]`。
6. **64 位上的计算**：**uintptr 与 int 各占 8 字节**，故整个结构为 **16 字节** `[源码]`。
7. **与内容无关**：`"ABC"` 与 `"中文"` 的 `unsafe.Sizeof` **都是 16**，尽管内容字节数不同 `[源码]`。
8. **32 位系统差异**：在 32 位系统上两者各 4 字节，结构体大小为 **8 字节** `[经验]`。

## 关键代码
```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	s1 := "ABC"
	s2 := "中文"

	fmt.Println(len(s1), unsafe.Sizeof(s1)) // 3 16
	fmt.Println(len(s2), unsafe.Sizeof(s2)) // 6 16

	// string 是描述符：data 指针(8) + len(8) = 16 字节
	// 注意：Sizeof 只量描述符本身，不含底层字节数组

	var s string
	fmt.Println(unsafe.Sizeof(s)) // 16：空串同样是 16
}
```

## 总结与追问预判
**`unsafe.Sizeof(string)=16` 是固定的，量的是描述符不是数据**。面试官常追问「那 slice 呢」——slice 多一个 cap 字段，64 位下为 **24 字节**。len 与字符数的区别见同批 903-len-is-bytes。

## ⚠️ 原文纠错
1. 事实核校：Sizeof 返回类型大小、string 为结构体、data 为 uintptr、len 为 int、64 位各 8 字节故共 16 字节、与内容长度无关——均与 Go 规范一致 `[经验]`。
2. 补充：原文在示例输出处先称结果为「八」，后文又说明「sizeof 值都是十六」并给出 8+8 的推导——**正确值是 16**，前面「八」应为口误或转写错误，本卡以 16 为准 `[经验]`。
3. 崩坏词归一：源码将结构体、指针、字节、长度等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
