# 1231 MVCC 是什么：多版本并发控制

> 分类：MySQL 事务 | 难度：中高 | 题型：原理 | 频率：高 | 关键词：**MVCC、多版本并发控制、undo log、版本链、读写不阻塞**

> 原文锚点：第 8~25 段「MVCC 定义、提高并发、避免读加锁、复用 undo log 历史版本」

## 一句话总述
MVCC（Multi-Version Concurrency Control，多版本并发控制）为每条记录保存多份历史版本，使读操作读旧版本、写操作写新版本，从而**读写互不阻塞**。InnoDB 复用 undo log 中已记录的历史版本数据来满足 MVCC 需求；记录上的隐藏列 DB_TRX_ID 记录最近修改它的事务 ID，更新时生成新版本并写入，其他事务可继续访问旧版本——这就是「快照读」。

## 面试官视角
MVCC 是 MySQL 事务最高频考点。考官看你能不能讲清三点：① MVCC 解决什么（读写冲突、避免读加锁）；② 版本存在哪（undo log 版本链 + 记录隐藏列 DB_TRX_ID、DB_ROLL_PTR）；③ 怎么判断是否可见（ReadView，见 1231-readview）。几乎主流数据库都用它。

## 主问答
**Q（面试官原话）：** 什么是 MVCC？它解决了什么问题？

1. **定义**：Multi-Version Concurrency Control，为每条记录保存多份历史数据供事务访问，新写入只添加新版本、无需等待。
2. **解决什么**：避免只读事务与写事务互相冲突、避免写操作等待读操作，从而提升并发度；几乎所有主流数据库都采用。
3. **版本从哪来**：InnoDB **复用 undo log** 里的历史版本数据，通过回滚指针 DB_ROLL_PTR 串成版本链；记录隐藏列 DB_TRX_ID 记最近修改的事务 ID。
4. **可见规则**：事务只能访问事务 ID 小于「当前活跃事务中最小事务 ID」的版本（即已提交版本），更新则创建新版本并刷新 DB_TRX_ID。

## 总结与追问预判
核心：**MVCC 用多版本让读写互不阻塞，版本来自 undo log 版本链，靠 DB_TRX_ID 判可见**。追问必接「ReadView 与 RC/RR 差异」（见 1231-readview）。
