# 506 指针作 map key 比的是地址而非值

> 分类：Go 语法/map | 难度：L3 | 题型：八股题 | 频率：低 | 关键词：**指针key**/**地址比较**/**值相等**/**不同key**/**精确可比**

> 原文锚点：第 49~57 段「使用指针类型作为 map 的 k 时…虽然指针指向的值相同，但指针地址不同，也会被认为是不同的 k…p1/p2 都 new 了新的地址，指向地址不一样…它们的值相等但地址不相等，所以不是同一个元素」（指针作 key 按地址比较）

## 一句话总述
指针类型**可比较、能作 map key**，但比较的是**指针地址**而非指向的值——两个指向相同内容的指针，只要地址不同就是**两个不同的 key**。选 key 类型时应优先用**值类型（int/string 等精确可比）**，避免指针地址带来的反直觉行为。

## 面试官视角
这题是 map key 约束的「收口细节」。考点：① 指针 key 比的是地址不是值；② 由此带来的「同值不同 key」陷阱；③ key 类型的正确选择。能把它和「值类型 vs 指针」的语义连起来，是高阶信号。

## 主问答
**Q（面试官原话）：** 指针类型作 map key 会有什么坑？

**A：**
1. **指针 key 比地址不比值**：map 用 `==` 判 key，对指针而言 `==` 比较的是**地址**（两个指针是否指向同一块内存），而非它们指向的**内容**。所以 `p1`、`p2` 即使 `*p1 == *p2`，只要 `p1 != p2`（不同地址），就是**两个不同 key**。
2. **同值不同 key 的陷阱**：`p1, p2 := new(int), new(int); *p1, *p2 = 1, 1` 后，`map[*int]int{p1:1, p2:2}` 长度为 **2**——即便两个指针指向的整型值都是 1。若业务期望「值相同即同一 key」，用指针 key 会**静默产生重复条目**。
3. **正确选择 key 类型**：优先用**值类型**——`int`/`int64`/`string` 等精确、稳定、可预期的比较语义；需要「按内容去重」时绝不用指针 key。指针 key 仅在「确实想以对象身份（地址）区分」时才用（极少）。
4. **边界**：`nil` 指针可作 key（与 nil 比较合法），但两个 `nil` 指针是同一 key——这与「非 nil 指针按地址」一致，都是地址语义。

## 版本与兼容性
- 指针比较语义（`503-pointer-compare.md`）恒定；作 map key 时即「地址相等才同 key」，自 Go 1.0 不变。
- 与 `506-map-key-comparable.md`（key 必须 comparable）衔接：指针是 comparable，故可作 key，但比较维度是地址——这是「合法但反直觉」的又一例（同 float key）。
- 与「可比较 ≠ 可排序」（`509-comparable-types.md`）一致：指针只可相等比较，不可排序。

## 关键代码

```go
package main

import "fmt"

func main() {
	p1, p2 := new(int), new(int)
	*p1, *p2 = 1, 1 // 指向的值相等
	m := map[*int]int{p1: 1, p2: 2}
	fmt.Println(len(m))        // 2 —— 即便 *p1==*p2，地址不同→两个 key
	fmt.Println(p1 == p2)      // false —— 指针 == 比地址

	// ✅ 用值类型 key：内容相等即同一 key（k 为变量，运行期重复允许、后写覆盖）
	k := 1
	v := map[int]int{k: 1, k: 2}
	fmt.Println(len(v)) // 1
}
```

## 总结与追问预判
收口：**指针 key 比地址不比值 → 同值不同址产生双 key；优先值类型 key**。预判追问：① key 合法性（见 506.md`）；② float/NaN key（见 506.md`）；③ 指针比较基础（见 503.md`）。回答时把「`map[*int]` 同值存两条」这句抛出，最显你把比较语义吃透了。
