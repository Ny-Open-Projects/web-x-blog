# 163 责任链模式：请求沿链传递直到被处理

> 分类：设计模式/行为型 | 难度：L2 | 题型：工程题 | 频率：中 | 关键词：**链式传递** / **middleware** / **动态编排**
> 原文锚点：第 33~39 段「责任链把请求沿节点链传递，直到某节点处理为止」

## 一句话总述
责任链把多个处理器串成链，请求从首节点流入，逐节点传递直到被某节点处理；Go 里就是 middleware 切片/链式调用，常用于鉴权、日志、限流。

## 面试官视角
- 意图：能否区分责任链（处理请求）与装饰器（增强对象）、与观察者（广播）。
- P5 知用切片串联 handler / P6 说清"是否必须被处理""链路中断 vs 继续" / P7 知动态编排、短路与性能。
- 红旗：把所有逻辑塞进一条链；以为链上每个节点都必须处理。
- 惊艳点：Go 责任链常写成 `[]func(next) handler` 或每个节点持 next 指针；某节点可"截断"不再向下传，类似 HTTP middleware 短路 —— 验证：`net/http` 中间件即此结构，go1.26.5 `[源码]`。

## 主问答
**Q（面试官原话）：** 多个处理器都有可能处理一个请求怎么组织？
**A：**
1. **结论**：定义统一 Handler 接口（含 next 或返回是否处理），节点按序串联，请求逐节点传递。
2. **机制**：节点处理不了就转交 next；能处理则执行并可选择是否继续向下，实现动态编排 `[源码]`。
3. **边界**：链过长增加调用栈与延迟；需明确"无人处理"的兜底，别让请求静默丢失。
**加分层：** 与装饰器不同：责任链重在"请求分发与短路"，装饰器重在"对象能力叠加"。

```go
// 示意，未验证：责任链节点
type Node func(req string) bool // 返回 true 表示已处理并截断

func Chain(nodes ...Node) Node {
	return func(req string) bool {
		for _, n := range nodes {
			if n(req) { return true } // 被处理则短路
		}
		return false // 无人处理
	}
}
```
