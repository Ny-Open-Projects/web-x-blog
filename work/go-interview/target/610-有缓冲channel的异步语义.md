# 610 有缓冲 channel 的异步语义

> 分类：Go 并发 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**有缓冲**/**异步**/**条件非阻塞**
> 原文锚点：第 71~97 段「有缓冲 channel 也叫异步…缓冲满继续写会死锁」

## 一句话总述
有缓冲 channel 在**缓冲区未满（发送）/非空（接收）时非阻塞**，可暂存数据、允许同协程先写后读；但缓冲满时发送、空时接收照样阻塞。

## 面试官视角
- 考察意图：能否讲清"异步/非阻塞"是**有条件的**，而非无脑非阻塞。
- 分档：P5 知有缓冲能暂存；P6 懂满/空时仍阻塞；P7 能解释 hchan 环形缓冲与等待队列。
- 红旗答案："有缓冲永远非阻塞"；"缓冲越大越好"。
- 惊艳点：**非阻塞是容量相关的**——发送只在 `len < cap` 时立即返回，满了就挂 `sendq`；这正是和无缓冲的本质差异 `[源码]`。

## 主问答
**Q（面试官原话）：** 有缓冲 channel 为什么叫异步 channel？
**A：**
1. **结论**：有缓冲 channel 在**缓冲区未满时发送非阻塞、非空时接收非阻塞**，数据可暂存，故称"异步"。
2. **机制**：发送时若环形缓冲 `buf` 未满，元素入队立即返回；只有 `len==cap` 才把 goroutine 挂 `sendq` 等待。接收对称——`len>0` 直接取，空了才挂 `recvq` `[源码]`。
3. **边界**：**非阻塞是有条件的**——缓冲满再写、缓冲空再读都会阻塞甚至死锁；原文标题式"异步非阻塞"需加这个容量前提，否则误导成"永远不阻塞"。

**加分层：** 缓冲大小是 trade-off：大缓冲解耦生产者消费者、抗突发，但占用内存且延迟回收；按实际吞吐选，而非越大越好。

## 关键代码
```go
ch := make(chan int, 1) // 容量 1
ch <- 1                // 缓冲未满，立即返回（非阻塞）
fmt.Println(<-ch)       // 同协程先写后读，正常
// ch <- 1; ch <- 2  // 容量1再写第二个 → 阻塞，若无接收方则 deadlock
```

## 总结与追问预判
有缓冲=条件非阻塞+可暂存，但满/空仍会阻塞；缓冲大小是工程权衡。追问接"各类死锁场景"。

## ⚠️ 原文纠错
1. 原文称有缓冲 channel"发送和接收操作都是**非阻塞**的"——准确说**仅当缓冲区未满（发送）/非空（接收）时非阻塞**；缓冲区满时发送同样阻塞、空时接收阻塞。标题式"异步非阻塞"是有条件的，缺容量前提会误导 `[源码]`。
