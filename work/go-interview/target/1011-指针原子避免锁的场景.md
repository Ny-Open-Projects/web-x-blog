# 1011 指针原子避免锁的场景

> 分类：并发模型 | 难度：L4 | 题型：对比题 | 频率：中 | 关键词：**无锁结构** / **CAS 自旋** / **指针交换**

> 原文锚点：第 89~126 段「无锁链表队列用 CS 操作指针实现入队出队；锁队列用头尾两把锁」

## 一句话总述
当共享状态可被"一次指针替换"表达（无锁队列头/尾、配置热切换、单值标志）时，用 `atomic.Pointer[T]` 的 Store/Swap/CAS 免锁；但高竞争下自旋 CAS 未必比锁快，需实测。一句话背法：**「单指针状态(队列头尾/配置热切换/标志位)可用 atomic.Pointer[T] 的 Store/Swap/CAS 免锁；复合一致或高写竞争须回锁，性能靠压测」**。

## 面试官视角
这是考察"指针原子取代锁的适用边界"的题，而非无脑去锁。
- **P5**：知道可换指针免锁。
- **P6**：说清 CAS 自旋 + 无锁队列。
- **P7**：知道高竞争下自旋反而更慢、需压测。
- **红旗**："原子一定比锁快"无前提；以为任何临界区都能用指针原子替。
- **惊艳点**：无锁链表队列靠 CAS 改 `head`/`tail` 指针推进；竞争激烈时自旋重试开销可能超过锁的休眠唤醒 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么场景用指针原子代替锁？

**先铺垫（由浅入深第 1 层）**："去锁"不是把 `Mutex` 换成 `atomic` 就完事。原子操作只能保护"一个字"的替换——指针正好是一个字。所以当状态能建模成"单个指针的原子替换"时，指针原子才比锁轻。

1. **结论（第 2 层·机制）**：状态能用"单个指针的原子替换"建模时（队列头尾、配置对象、标志位）用 `atomic.Pointer[T]` `[源码]`。
2. **机制（第 3 层）**：CAS 自旋重试推进指针，避免互斥锁的休眠/唤醒；读端 Load 无竞争开销极低 `[源码]`。
3. **边界（第 4 层）**：多字段复合更新、需要"全有或全无"的一致性时，指针原子不够，必须回锁；高写竞争下自旋 CPU 浪费可能更慢 `[经验]`。
4. **选型（第 5 层）**：单指针状态免锁用 Pointer；复合/高竞争回锁，性能靠压测，没有"永远更快"的原子 `[经验]`。
5. **进阶（第 6 层）**：无锁链表队列靠 CAS 改 `head`/`tail` 推进；无锁 ≠ 无代价，竞争强度决定谁快 `[边界]` 见 105（原子 vs 锁）。

## 关键代码
```go
package main

import (
	"fmt"
	"sync/atomic"
)

// 配置对象热切换：免锁
type Conf struct{ Timeout int }

func main() {
	var cur atomic.Pointer[Conf]
	cur.Store(&Conf{Timeout: 3})
	// 读端无锁
	c := cur.Load()
	fmt.Println("current timeout:", c.Timeout)

	// 热切换：Swap 原子替换整个对象，返回旧对象
	old := cur.Swap(&Conf{Timeout: 5})
	fmt.Println("swapped old timeout:", old.Timeout, "new:", cur.Load().Timeout)
}
```

## 总结与追问预判
**背这三句就够**：① **单指针状态可用 `atomic.Pointer[T]` 免锁**；② **复合一致 / 高写竞争须回锁**；③ **性能靠压测，无"原子永远更快"**。

- 「泛型 Pointer 几方法？」→ Load/Store/Swap/CompareAndSwap（见 1011 泛型 API）。
