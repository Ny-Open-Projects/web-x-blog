# 1011 指针原子避免锁的场景

> 分类：并发模型 | 难度：L4 | 题型：对比题 | 频率：中 | 关键词：**无锁结构** / **CAS 自旋** / **指针交换**
> 原文锚点：第 89~126 段「无锁链表队列用 CS 操作指针实现入队出队；锁队列用头尾两把锁」

## 一句话总述
当共享状态可被"一次指针替换"表达（无锁队列头/尾、配置热切换、单值标志）时，用 `atomic.Pointer[T]` 的 Store/Swap/CAS 免锁；但高竞争下自旋 CAS 未必比锁快，需实测。

## 面试官视角
- 意图：是否理解"指针原子取代锁"的适用边界，而非无脑去锁。
- P5 知可换指针免锁 / P6 说清 CAS 自旋 + 无锁队列 / P7 知高竞争下自旋反而更慢、需压测。
- 红旗："原子一定比锁快"无前提；以为任何临界区都能用指针原子替。
- 惊艳点：无锁链表队列靠 CAS 改 `head`/`tail` 指针推进；竞争激烈时自旋重试开销可能超过锁的休眠唤醒 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么场景用指针原子代替锁？
**A：**
1. **结论**：状态能用"单个指针的原子替换"建模时（队列头尾、配置对象、标志位）用 `atomic.Pointer[T]`。
2. **机制**：CAS 自旋重试推进指针，避免互斥锁的休眠/唤醒；读端 Load 无竞争开销极低。
3. **边界**：多字段复合更新、需要"全有或全无"的一致性时，指针原子不够，必须回锁；高写竞争下自旋 CPU 浪费可能更慢。
**加分层：** 选型靠压测，没有"永远更快"的原子。

```go
// 示意，未验证：用 Swap 原子热切换配置对象，免锁

cur.Store(&Conf{Timeout: 3})
// 读端无锁：c := cur.Load()
```

## 总结与追问预判
- 单指针状态免锁用 Pointer；复合/高竞争回锁，性能靠压测。
- 预判：CAS 比对对象 → 见 1011；对比 105。
