# 134 ES 倒排索引的四部分组成：term、词典、单词索引、倒排列表

> 分类：Elasticsearch 存储 | 难度：L4 | 题型：原理题 | 频率：高 | 关键词：**term、term dictionary、term index、posting list、posting、词频、偏移量、二分查找**

> 原文锚点：第 35~52 段「在 ES 中倒排索引是由四部分组成的。首先是单词 term，term 是字段原文经过分词器处理之后分成的一个个的单词…第二部分是 term dictionary，也就是单词字典，单词词典是经过排序后的全部 term 的集合，因为它是有序的，所以能很方便地对 term 进行二分查找…第三部分是 term index，它是单词词典的一个索引…是一种树形结构，存储的是 term 的前缀与单词词典的 block 块之间的映射关系…第四部分是 posting list，它记录了出现过某个 term 的所有文档 ID 的集合」

## 一句话总述
ES 的倒排索引由**四部分**组成：**① term**（原文经分词器切出的单词）；**② term dictionary**（**排序后**的全部 term 集合，有序故可二分查找）；**③ term index**（词典的索引，**树形结构**，存 **term 前缀 → 词典 block** 的映射，可压缩后放内存，用来**减少磁盘随机读**）；**④ posting list**（出现过该 term 的**所有文档 ID 集合**，每条记录称为一个 **posting**，含**文档 ID、词频、位置/偏移量**三类信息）。

## 面试官视角
- 考察意图：能否把倒排索引从"词 → 文档列表"这一层，细化到**磁盘与内存如何协作**这一层。
- 分档：P5 知道倒排索引是"词 → 文档 ID 列表"；P6 能说出 term / 词典 / 倒排列表三部分；P7 能补上 **term index 这层"索引的索引"**并解释它存在的理由（**词典太大放不进内存**）。
- 红旗答案：以为 ES 会把全部 term 放内存；漏掉 **term index** 这一层。
- 惊艳点：**term index 存在的唯一理由就是"词典放不进内存"**——ES 的做法是**给词典再建一层索引**，把前缀到 block 的映射压缩后缓存到内存，从而**大幅减少磁盘随机读次数** `[源码]`。

## 主问答
**Q（面试官原话）：** ES 的倒排索引内部到底有哪几部分？

1. **结论**：四部分——**term、term dictionary（单词词典）、term index（单词索引）、posting list（倒排列表）** `[源码]`。
2. **term（单词）**：**term 是字段原文经过分词器处理之后分成的一个个的单词**；例如用 **IK 分词器**对"测试文本"分词，会拆成"**测试**"和"**文本**"两个 term `[源码]`。
3. **term dictionary（单词词典）**：是**经过排序后的全部 term 的集合**；**因为它是有序的，所以能很方便地对 term 进行二分查找** `[源码]`。
4. **term index（单词索引）**：**是单词词典的一个索引**，**目的是加速 term 的查找**。ES 存储的文档越来越多后，**把全部 term 放到内存中显然不太现实**；**但每次都去磁盘查找，寻道次数过多也会严重影响查询效率**。于是 ES **给单词词典建一个索引**——**功能就像字典中的索引页** `[源码]`。
5. **term index 的结构与作用**：**它是一种树形结构，存储的是 term 的前缀与单词词典的 block 块之间的映射关系**；**结合压缩技术可以使 term index 缓存到内存中**；**通过 term index 快速定位到单词词典的 offset**，再从这个位置去磁盘上查找 term，**大大减少了磁盘随机读的次数** `[源码]`。
6. **posting list（倒排列表）**：**记录了出现过某个 term 的所有文档 ID 的集合**，据此可以知道哪些文档包含某个单词；**除文档 ID 外还包括文档频率（term 出现的次数）以及 term 在原文中的位置信息（偏移量）**；**包含这三个信息的每一条记录称为一个倒排项，即 posting** `[源码]`。
7. **串联关系**：**通过 term index 找到 term 在单词词典中的位置，进而找到 posting list**；**有了倒排列表，还可以根据文档 ID 找到文档存储的原文**（前提是存储了原文） `[源码]`。

**加分层：** 用词典类比最好记——**term 相当于词典里的每一个词，term dictionary 相当于词典本身，term index 相当于词典的目录页索引**。

## 关键代码
```go
// ES 倒排索引四部分：用 mapping 控制 posting list 存多少信息
package main

import (
	"context"
	"fmt"

	"github.com/olivere/elastic/v7"
)

const mapping = `{
  "mappings": {
    "properties": {
      "title": {
        "type": "text",
        "analyzer": "ik_max_word",      // 决定 term 如何切分
        "index_options": "positions"    // 控制 posting list 记录的信息量（默认 positions）
      }
    }
  }
}`

func main() {
	ctx := context.Background()
	client, _ := elastic.NewClient(elastic.SetURL("http://127.0.0.1:9200"), elastic.SetSniff(false))

	// 建索引：term 由分词器产出，term dictionary/index/posting list 由 Lucene 维护
	client.CreateIndex("article").BodyString(mapping).Do(ctx)

	// 检索：先按查询词查 term index -> term dictionary -> posting list
	res, _ := client.Search().Index("article").
		Query(elastic.NewMatchQuery("title", "测试文本")).
		Size(10).Do(ctx)
	fmt.Println("命中文档数:", res.TotalHits())
	for _, h := range res.Hits.Hits {
		fmt.Printf("docID=%s 原文=%s\n", h.Id, string(h.Source))
	}
}
```

## 总结与追问预判
**最爱追问的是"term index 和 term dictionary 到底差在哪"**——**词典是"所有词的完整有序集合"（太大，放磁盘），单词索引是"词典的稀疏前缀索引"（小，放内存）**，查询路径是**内存里的 term index 定位 offset → 磁盘上的词典精确查词 → 取 posting list**。追问常接"posting 里为什么要存位置"——为了**短语查询与临近查询**；再往下就是 `index_options` 的四个档位（见 134）。

## ⚠️ 原文纠错
1. 事实核校：term 由分词器产出、词典为排序后的 term 集合且可二分、term index 为词典的索引且存前缀到 block 的映射并可压缩入内存、posting list 记录文档 ID 集合且 posting 含文档 ID + 词频 + 位置信息、查询路径为 term index → 词典 → posting list——均与 Lucene/ES 实现一致 `[经验]`。
2. 补充：原文称 posting list 除文档 ID 外还包括"文档频率，也就是 term 出现的次数"——**术语上"文档频率（document frequency）"通常指"包含该 term 的文档数"，而"term 在某文档内出现的次数"应称"词频（term frequency）"**；面试中这两个概念要分开表述 `[经验]`。
3. 崩坏词归一：源码将 term、单词词典、单词索引、倒排列表、posting、分词器等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
