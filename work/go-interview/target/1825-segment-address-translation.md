# 1825 分段地址转换：段表、基址与限长

> 分类：内存与 OS | 难度：L3 | 题型：机制题 | 频率：中 | 关键词：**段表** / **段基址** / **段长度** / **越界保护** / **地址转换**
> 原文锚点：第 28~35 段「分段管理内存划分为变长段…段基址和段长度…段表…段号查基址+偏移得物理地址」

## 一句话总述
分段地址转换=段号查段表得段基址与段长度，先校验段内偏移≤段长度（越界即中断），物理地址=段基址+段内偏移；段表每项还带权限位，是分段保护的基础。

## 面试官视角
- 意图：是否真懂段表结构与"基址+偏移"的换算，以及越界保护怎么落地。
- P5 知段表存基址/限长；P6 说清转换四步与越界校验；P7 知权限位如何实现按段保护。
- 红旗：以为分段也像分页那样"页号×页大小"；忽略越界检查。
- 惊艳点：分段保护粒度是"段"——代码段可设只读可执行、数据段可读写，这是分页早期做不到的（x86 段保护先于页保护）`[经验]`。

## 主问答
**Q（面试官原话）：** 分段机制怎么做地址转换？段表起什么作用？
**A：**
1. **段表结构**：每段在段表中一项，含段基址（物理起始）、段长度（限长）、访问权限；段号即段表索引 `[源码]`。
2. **转换步骤**：取段号→查段表得基址；取段内偏移→先校验 `偏移 ≤ 段长度`，否则触发越界中断；物理地址 = 段基址 + 段内偏移。
3. **保护落地**：权限位按段控制（只读/读写/执行），代码段设只读可执行可防被篡改，越权访问由硬件在转换时拦截。
4. **与页表区别**：段表按逻辑段、变长、基址+限长；页表按固定页、页号+页内偏移，二者地址结构不同。

## 关键代码
```go
// 示意，未验证：用 Go 还原"段基址 + 段内偏移 + 越界校验"的地址换算逻辑
package main
import "fmt"
type Segment struct {
    Base  uint64 // 段基址
    Limit uint64 // 段长度
}
func translate(seg Segment, offset uint64) (uint64, bool) {
    if offset > seg.Limit { // 越界保护：段内偏移不得超段长度
        return 0, false
    }
    return seg.Base + offset, true // 物理地址 = 基址 + 偏移
}
func main() {
    code := Segment{Base: 0x400000, Limit: 0x1000}
    if pa, ok := translate(code, 0x20); ok {
        fmt.Printf("物理地址=0x%x\n", pa) // 0x400020
    }
}
```
