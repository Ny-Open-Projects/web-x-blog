# 197 企业级网盘搜索架构：端到端流程

> 分类：架构/搜索 | 难度：L3 | 题型：设计题 | 频率：高 | 关键词：**事件驱动**/**分布式存储**/**元数据入库**/**ES文件名索引**/**内容索引**
> 原文锚点：第 1~14 段「上传→分布式文件系统(HDFS/Ceph/对象存储)→元数据入库→事件推送服务→搜索服务订阅写ES文件名索引(文件名字段查询/类型时间过滤)」

## 一句话总述
网盘搜索是典型**事件驱动**架构：文件上传到分布式存储（HDFS/Ceph/对象存储）→ 元数据（名/类型/大小/时间/上传者/对象地址）入库 → 文件服务发变更事件 → 搜索服务订阅后把元数据写入 **ES 文件名索引**（文件名字段用于检索、类型/时间用于过滤）。内容搜索（会员权益）则解析文档后写**独立的内容索引**。

## 面试官视角
- 考察意图：能否画出「上传→存储→元数据→事件→索引」全链路，并说清 ES 在其中的角色。
- 分档：P5 知用 ES 做搜索；P6 能画事件驱动链路；P7 知文件名/内容索引分离、元数据与索引异构存储。
- 红旗答案：把搜索当成「直接查数据库 LIKE」；忽略事件解耦与异步索引。
- 惊艳点：点出「用事件推送解耦文件服务与搜索服务、索引异步构建不阻塞上传」，以及「文件名检索字段与过滤字段（类型/时间）分开设计」 [经验]。

## 主问答
**Q（面试官原话）：** 网盘搜索怎么从文件上传到能被搜到？
**A：**
1. **存储 + 元数据**：文件存分布式文件系统，元数据（名/类型/大小/时间/上传者/对象地址）入数据库 [经验]。
2. **事件驱动索引**：文件服务发变更事件，搜索服务订阅后把元数据写 **ES 文件名索引**（文件名字段检索、类型/时间过滤） [经验]。
3. **内容索引独立**：文档类文件经解析服务抽取内容，写**独立的内容索引**（会员权益），与文件名索引分开 [经验]。

## 关键代码

```go
// 事件驱动：消费文件变更事件 → 写 ES 文件名索引（与文件服务解耦）
func onFileEvent(evt FileEvent) error {
    doc := EsFileDoc{
        FileID:    evt.FileID,
        Name:      evt.Name,     // 检索字段
        Type:      evt.Type,     // 过滤字段
        Size:      evt.Size,
        UploadedAt: evt.UploadedAt,
        Uploader:  evt.Uploader,
        ObjAddr:   evt.ObjAddr,
    }
    return es.Index("netdisk_filename", doc) // 异步建索引，不阻塞上传
}
// 内容索引：文档类走独立索引（会员权益），本卡只引、mapping 见 198
```

## 总结与追问预判
网盘搜索的核心是「写路径异步建索引、读路径走 ES」。事件驱动让上传与索引解耦，是搜索类系统的通用范式。
