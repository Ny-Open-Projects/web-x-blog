# 1253 Redis 持久化（四）：混合持久化

> 分类：Redis | 难度：中 | 题型：原理 | 频率：中 | 关键词：**混合持久化、RDB 全量+AOF 增量、aof-use-rdb-preamble、4.0+**

> 原文锚点：第 83~95 段「混合持久化结合 RDB+AOF、前半 RDB 后半 AOF、4.0+、配置项」

## 一句话总述
混合持久化（Redis 4.0+）结合 RDB 与 AOF 优点：AOF 重写时，子进程先把内存全量数据以 RDB 格式写入 AOF 文件前半段，再把重写期间的增量写命令以 AOF 格式追加到后半段。恢复时先快速加载 RDB 全量，再重放 AOF 增量，兼顾「恢复快」与「丢数据少」。开启需 appendonly yes 且 aof-use-rdb-preamble yes。

## 面试官视角
混合持久化是进阶题，常问「为什么需要它」。考官期待你对比：RDB 恢复快但丢间隔数据、AOF 丢得少但恢复慢；混合则「前半 RDB 快恢复 + 后半 AOF 少丢数据」两全。能报出「4.0 引入、aof-use-rdb-preamble 控制、默认 yes」是细节加分。

## 主问答
**Q（面试官原话）：** 混合持久化是什么？为什么用？

1. **结构**：开启后 AOF 文件 = 前半段 RDB 格式全量数据 + 后半段 AOF 格式增量命令。
2. **写入过程**：重写时子进程先以 RDB 方式 dump 内存全量到 AOF 文件头；主线程后续新写命令进重写缓冲，再以 AOF 格式追加到文件尾。
3. **恢复优势**：重启先加载 RDB 全量（快），再重放尾部 AOF 增量（少丢），比纯 AOF 恢复快、比纯 RDB 丢得少。
4. **配置与版本**：Redis 4.0 引入；需 `appendonly yes` + `aof-use-rdb-preamble yes`（默认 yes）。
