# 1023 无缓冲 channel 同步 vs 信号量：等待退出与限并发的边界

> 分类：Go 并发 | 难度：中 | 题型：技巧题 | 频率：中 | 关键词：**无缓冲 channel 同步、semaphore、P/V 操作、限并发、资源池**

> 原文锚点：第 25~47 段「无缓冲channel同步(子末行写主读全部);信号量(semaphore包,P/V)此场景不推荐,本职限并发数;本质是资源池防过度使用」

## 一句话总述
除 WaitGroup 外，也可用**无缓冲 channel** 同步主协程（子协程末行写、主依次读全部值），但多协程必须读满全部值；**信号量**（`semaphore` 包，P 获取/V 释放）也能"等全释放"，只是它的本职是**限制并发数、保护资源池**，并非"等待退出"的合适原语，此场景不推荐。一句话背法：**「等待退出用 WG/channel，限并发才用信号量，别拿资源池当完成计数器」**。

## 面试官视角
考官看你能不能厘清"等待退出"与"限并发"两类不同诉求对应的原语，避免误用信号量。能讲清 channel 同步的"读满全部"陷阱、信号量的"资源池"本质与 WaitGroup 职责边界，说明选型成熟；用信号量去"等 N 个协程退出"（语义错位）、或 channel 同步只读了一次导致漏等，是红旗。

- **P6**：知道多协程 channel 需读满、信号量限并发。
- **P7**：知道信号量是资源池语义、与 WaitGroup 职责边界。

## 主问答
**Q（面试官原话）：** 除了 WaitGroup，channel 和信号量怎么用来等协程？

**先铺垫（由浅入深第 1 层）**：等协程退出和限制并发数，是两件事。WaitGroup 管"等做完"，信号量管"同时只允许做几个"。把信号量拿去等退出，就像用秤去当秒表——能凑合但语义是错的。

1. **无缓冲 channel 同步（第 2 层·机制）**：子协程把"写 channel"放最后一行，主协程依次读出全部值即代表全完成；多协程必须读满 N 个，否则漏等。
2. **信号量 P/V（第 3 层·机制）**：启动前 `Acquire`（P 减），完成后 `Release`（V 增），主协程获取全部即表示全释放——但这是"资源池"语义。
3. **信号量本职限并发（第 4 层·本质）**：它的设计目标是限制同时执行的协程数、确保资源池不被过度使用，并非"等待退出"的原语，本场景应优先 WaitGroup。
4. **对比结论（第 5 层·选型）**：等待退出用 WaitGroup/无缓冲 channel；限制并发用信号量——二者诉求不同，选错即语义错位。
5. **误用风险（第 6 层）**：信号量"等全释放"看似能等退出，但它不关心"谁做完"，只关心"额度够不够"，一旦中间有协程复用额度就会错判，故只适合限并发。

## 关键代码
```go
package main

import (
	"context"
	"fmt"
	"sync"

	"golang.org/x/sync/semaphore"
)

// ① 无缓冲 channel 同步：主读全部值即全完成（必须读满 N 个）
func withChannel(n int) {
	done := make(chan struct{})
	var wg sync.WaitGroup
	for i := 0; i < n; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			done <- struct{}{} // 末行写，主读全部即表示完成
		}()
	}
	go func() { wg.Wait(); close(done) }()
	for range done { // 读满全部，否则漏等
	}
	fmt.Println("channel 同步：全部完成")
}

// ② 信号量：本职是限并发数，不是等待退出
func withSem(n int) {
	sem := semaphore.NewWeighted(int64(n))
	ctx := context.Background()
	var wg sync.WaitGroup
	for i := 0; i < n; i++ {
		_ = sem.Acquire(ctx, 1) // P：占额度
		wg.Add(1)
		go func() {
			defer wg.Done()
			defer sem.Release(1) // V：还额度
		}()
	}
	wg.Wait()
	fmt.Println("信号量：限并发执行完毕")
}

func main() {
	withChannel(3)
	withSem(3)
}
```

## 总结与追问预判
**背这三句就够**：① **无缓冲 channel 同步：子末行写、主读满全部值（否则漏等）**；② **信号量 P/V 本职是限并发、保护资源池，不是等待退出原语**；③ **等待退出优先 WaitGroup，限并发才用信号量**。
**预判追问**：
- 「channel 同步有什么坑？」→ 多协程必须读满全部值，只读一次会漏等（见本卡第 2/4 层）。
- 「信号量和 WaitGroup 怎么选？」→ 等退出用 WG，限并发用信号量，语义别错位（见本卡第 3/5 层）。
- 「信号量限并发怎么实现？」→ 见 1015 channel 信号量；无缓冲阻塞机制见 609。
