# 711 信道控制协程池并发度

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**缓冲信道** / **空结构体** / **信号量**
> 原文锚点：第 3~8 段「用缓冲 channel 控制携程数量，写不进即满」

## 一句话总述
用带缓冲的 `chan struct{}` 当计数信号量：任务开始前写入、结束后读出，写满即阻塞，从而把并发 goroutine 数卡在容量内。

## 面试官视角
- 意图：是否掌握"channel 即信号量"这个最朴素的并发限制手法。
- 分档：P5 知能限流 / P6 说清写入读出配对 / P7 知空结构体零开销与释放时机。
- 红旗：只说加锁计数；忘记配对释放导致永久阻塞。
- 惊艳点：`struct{}` 占 0 字节，仅用 channel 做信号不读值 `[源码]` 标准库。

## 主问答
**Q（面试官原话）：** 不用第三方库，怎么限制同时跑的 goroutine 数量？
**A：**
1. **结论**：用容量为 N 的 `chan struct{}` 做信号量，进任务前写入、出任务后读出。
2. **机制**：缓冲满时写操作阻塞，超容量的任务就地等待；任务结束读出空结构体，腾出一个槽位给下一个。
3. **边界**：必须"写/读"严格配对，否则槽位只减不增会死锁；空结构体 `struct{}` 零内存，最适合只计数不传值。
**加分层：** 这是 ants 等池的容量控制内核，理解它就读懂了池的"限流"本质。

## 关键代码
```go
// 示意，未验证：用 chan struct{} 限制并发为 5
sem := make(chan struct{}, 5)
for i := 0; i < 100; i++ {
    sem <- struct{}{} // 满则阻塞
    go func() {
        defer func() { <-sem }()
        work()
    }()
}
```

- 缓冲 channel 即信号量，写入读出配对卡并发。
