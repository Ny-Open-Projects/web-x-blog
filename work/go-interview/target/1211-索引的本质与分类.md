# 1211 索引的本质与分类

> 分类：MySQL 索引 | 难度：L3 | 题型：概念题 | 频率：高 | 关键词：**索引本质**/**B+树索引**/**聚簇/二级索引**/**哈希/全文/R树**/**空间换时间**
> 原文锚点：第 1~37 段「索引本质、四维修分类与优缺点」

## 一句话总述
索引本质是「空间换时间」的数据结构，类比新华字典目录帮存储引擎快速定位数据；按四个维度分类——数据结构（B+树/哈希/全文/R树）、物理存储（聚簇/二级）、字段特性（主键/唯一/普通/前缀）、字段个数（单列/联合）；优点提检索效率降 IO，缺点耗维护时间、降写入速度、占额外磁盘。

## 面试官视角
- 考察意图：是否建立「索引是多维度分类体系」的认知，而非只背 B+树。
- 分档：P5 知索引是目录、B+树最常见；P6 知聚簇/二级、哈希/全文支持引擎；P7 知 R树空间索引、前缀索引、优缺点的代价权衡。
- 红旗答案：以为哈希索引 InnoDB 支持；或说不清聚簇与二级区别。
- 惊艳点：点出「全文索引 InnoDB 5.6+ 才支持、建在 char/varchar/text 上解决 like 性能」「哈希索引仅 memory/NDB 支持」。

## 主问答
**Q（面试官原话）：** 索引是什么？怎么分类？有什么优缺点？
**A：**
1. **本质**：帮存储引擎快速获取数据的数据结构，类比字典目录，靠空间换时间存字段位置信息。
2. **按数据结构**：B+树索引（最常见，MyISAM/InnoDB/memory 支持）、哈希索引（仅 memory/NDB）、全文索引（MyISAM 特殊，InnoDB 5.6+ 在 char/varchar/text 上，解决 like 性能）、R树（空间索引，MyISAM 特殊，地理空间）。
3. **按物理存储**：聚簇索引（主键，clustered）、二级索引（非聚簇/辅助/非主键）。
4. **按字段特性**：主键/唯一/普通/前缀索引；按字段个数：单列/联合索引。
5. **优缺点**：优=提检索效率降 IO、减分组排序时间、唯一索引保唯一、外键保一致；缺=创建维护耗时随数据量增、降写入速度、占额外磁盘（索引文件可能比数据大）。

## 关键代码
```sql
-- 联合索引 + 前缀索引示例
CREATE TABLE t (
  id INT PRIMARY KEY,
  name VARCHAR(100),
  KEY idx_name (name(20))          -- 前缀索引
);
CREATE INDEX idx_cover ON t(id, name); -- 联合索引
```

## 总结与追问预判
索引分类是「四维坐标」，核心是 B+树与聚簇/二级。下一步常问 InnoDB 的物理文件布局与表空间——那是索引落盘的地方。
