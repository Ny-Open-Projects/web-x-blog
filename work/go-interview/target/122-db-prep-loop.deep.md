# 122 数据库备考的时间配比与自检闭环 深挖

> 覆盖源 12-2 全文：九大分域的优先级排序逻辑、折叠复述为什么有效（提取练习原理）、场景案例的积累管道、复杂 SQL 的刻意练习路径、八股文的「锚点价值」。主卡已给地图与三步法，本附录做时间分配、自检闭环设计与案例沉淀机制四层深挖。

## 思路与架构

```text
数据库备考的三线并行 + 一条闭环
├─ 线 1: 地图 (知识面) —— 九大分域, 亲手重写
│   └─ 优先级: 索引 > 事务/锁 > 日志/主从 > 优化 > 引擎/备份
├─ 线 2: 场景案例 (实战面) —— 表设计/分库分表/CPU飙升/慢查询
│   └─ 每个案例 = 现象 -> 排查链 -> 根因 -> 方案 -> 复盘
├─ 线 3: 手写 SQL (技能面) —— 分组/排序/子查询/连接/窗口函数
└─ 闭环: 折叠复述 -> 标记卡壳点 -> 回填地图 -> 再复述
    └─ 迭代到「全图无卡壳」才算准备完成
```

## 方案取舍
- **优先级为什么这么排**：索引考察最多（几乎必考且可深挖到 B+ 树页结构与优化器行为）；事务与锁紧随（一致性是数据库的存在理由）；日志与主从是**架构题入口**（数据可靠性、延迟治理）；优化题偏综合排查；存储引擎与备份安全出镜率低但有地图位。**时间配比大致按考察频率走，但每域至少过一遍**——考得少的域答「我知道边界在哪」也比空白强 [经验]。
- **折叠复述有效的原理**：看答案产生「熟悉感」，大脑把「见过」误判为「会」；**提取练习**（不看材料主动回忆）强制重建检索路径，卡壳处即真实的记忆缺口。操作上：只看问题清单 → 口头完整作答 → 录音回放或写要点 → 对照标准答案找差异。**复述两遍仍卡壳的条目单独成「补漏清单」**，这是最高效的复习材料 [经验]。
- **场景案例的积累管道**：场景题（表结构设计、分库分表、CPU 飙升、慢查询优化）考的是**排查链与权衡叙述**，无法临时背。管道是：平时遇到就记「现象 → 定位手段（processlist / 慢日志 / explain）→ 根因 → 方案 → 效果数字」五段；没有真实案例时，把开源项目 issue、同事复盘当素材复述推演。**面试叙述时带数字**（QPS、慢查询数、优化前后耗时）真实感立现 [经验]。
- **复杂 SQL 的刻意练习路径**：日常 CRUD 用不上复杂 SQL，退化是必然——必须**专项手写**：由易到难练「分组聚合 → 多表连接 → 相关子查询 → 窗口函数」，每题先手写再跑验证。窗口函数（`ROW_NUMBER/RANK/DENSE_RANK` 三兄弟的区别）见 `1252-sql-window-functions`、`1252-sql-pivot.deep` [边界]，与源提到的「分组排序子查询连接」正好构成完整技能树 [经验]。
- **八股文的锚点价值**：八股不是终点而是**检索锚点**——「MySQL 为什么用 B+ 树不用 B 树」这一条八股，向外牵出磁盘 IO 模型与页结构、向内牵出聚簇/二级索引、根节点常驻内存等实现细节。把每条八股当成「知识子树的入口」逐条长出枝叶，体系自然成形；把八股当孤立答案背，才是「没用」的根源 [经验]。

## 答题技巧
- 被问「怎么准备」先给三线结构（地图 / 案例 / SQL）再给自检闭环——方法论题答的是系统不是清单 [经验]。
- 主动报优先级：索引最多、备份安全最少，证明地图不是均匀涂抹的 [经验]。
- 被问「怎么知道背会了」→ 答提取练习原理 + 卡壳清单机制，把直觉升级成方法 [经验]。
- 场景题叙述带五段结构与真实数字，这是 P6 到 P7 的分水岭 [经验]。
- 主动边界到 `402-tech-interview-prep`（通用面试五大范围）、`171-dsa-interview-prep`（算法备考六法）、`125-bufferpool-lru-young-old`（buffer pool 实现层）、`1252-sql-window-functions`（窗口函数），构成备考与数据库双链 [边界]。
