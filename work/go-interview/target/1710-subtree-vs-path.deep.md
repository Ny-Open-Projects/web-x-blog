# 1710 子树和 vs 路径和：双通道递归与变体深挖

> 覆盖源 17-10 的对比延伸：「返回值通道 vs 答案通道」的双通道递归范式、子树和与最大路径和（LeetCode 124）的语义鸿沟与改法、全负树/空树边界的工程化处理、深树递归的栈风险与迭代化。主卡已给后序主线，本附录做变体与范式深挖。

## 思路与架构

```text
双通道递归范式 (一棵树同时收集两种信息)
├─ 返回值通道 (向上)
│   └─ 给父节点用的局部量: 子树和 / 最长链 / 深度
├─ 答案通道 (旁路)
│   ├─ 全局变量 / 指针参数 / 闭包捕获
│   └─ 每个节点算完局部量后顺手更新
├─ 最大子树和 (本题)
│   ├─ 返回: 左子树和+右子树和+Val (整棵计入)
│   └─ 答案: max 全部 S(x) [实测: 源树=12]
└─ 最大路径和 (LC124, 关键差异)
    ├─ 返回: max(0, 左链)+max(0, 右链)+Val (负链剪掉)
    ├─ 答案: 在每个节点尝试"左链+右链+Val"拐弯组合
    └─ 实测辨析: 树4(-10,6) 子树和=6, 路径和=10
```

## 方案取舍
- **双通道是树形 DP 的通用骨架**：「返回值给父亲、答案走旁路」分离了「父辈需要的量」与「全局要求的量」。最大深度、直径、平衡二叉树判定、最大 BST 子树全部同构——都是后序 + 返回局部量 + 旁路更新全局答案。把这个范式讲清楚，一道题带一片 [经验]。
- **子树和 vs 路径和的语义鸿沟**：子树的定义是「节点 + 全部后代」，**不可拆**——负孩子也必须背，所以树 4(-10,6) 的答案是 6；路径的定义是「任意链」，可以拐弯也可以剪——LC124 在每个节点允许「左右链都取且可拐弯」，返回值却只能带单链向上（父节点不能同时接两条链）。**「能否剪负」是两个变体的分水岭**，答题先问清面试官要哪个，再动手 [实测]。
- **全负树的边界哲学**：子树和变体答案=最大单节点（[实测] -5,-2,-9 → -2）；路径和变体如果照抄 `max(0,链)` 剪负会得到 0（空路径）——与「至少选一个节点」的题意冲突，要改成 `max(单侧链, 拐弯组合)` 且允许全负结果。**同一棵全负树，两个变体答案不同、修法也不同**——边界题的分档就在这里 [经验]。
- **递归深度的工程边界**：O(h) 栈空间在退化链（10 万节点单链）会打爆 goroutine 栈吗——Go 栈可增长（初始 2KB，最大默认 1GB），通常扛得住；但仍可用显式栈模拟后序（双栈法或「最后访问指针」法）转 O(1) 递归深度。面试答「Go 栈可增长但显式栈更稳」两全 [经验]。

## 答题技巧
- 先复述定义再动手：「最大子树和=每个节点为根的整棵子树求和取最大」——一句话把「子树不可拆」钉住，避免面试官默想路径和时的误会 [经验]。
- 用「返回值 vs 答案」的通道语言描述递归，展示范式级理解，而不是背代码 [经验]。
- 主动抛边界：全负树答单节点、空树判空、和溢出用平台自适应 MinInt——三连报直接拉开档次 [实测]。
- 被问「改成路径和」→ 先答剪负规则差异，再报树 4 的 6 vs 10 实测对账 [实测]。
- 主动边界到 `1711-complexity-evaluation`（遍历复杂度方法）、`177-go-set-implementation`（map 聚合的另一类「求和」）、`1715-selection-sort`/`1714-bubble-vs-selection`（同为 O(n²) 级的实测对账方法论），构成「树与算法对账」专题 [边界]。
