# 122 数据库面试备考地图：九大考点与三步自检法

> 分类：数据库 / 备考方法 | 难度：L2 | 题型：方法论 | 频率：中 | 关键词：**考点地图**/**折叠复述自检**/**场景案例**/**复杂 SQL**/**八股文价值**
> 原文锚点：第 1~35 段「首先我们需要去梳理数据库相关的考点…整个数据库知识体系里面分为了几大类，一类是常识类…一类是根据场景写 SQL…一类是原理类…索引相关的在面试中考察的是最多…注意这个思维导图一定要自己亲自动手去整理一遍…面试前把这些答案折叠起来，根据问题自己复述答案」

## 一句话总述
数据库面试准备 = **一张地图 + 三步自检 + 两类实战**：先按「常识 / 场景写 SQL / 原理 / 内存管理 / 存储引擎 / 索引 / 事务 / 锁 / 查询优化 / 日志 / 主从复制 / 备份安全」把考点系统化成自己的思维导图（必须亲手重写一遍）；再用「折叠答案→复述」做自检；最后备好**场景案例**（表结构设计、分库分表、CPU 飙升排查、慢查询优化）并**动手练复杂 SQL**——八股文出现频率最高，是横向拓展的抓手，眼高手低最吃亏。

## 面试官视角
- 考察意图：本题考「会不会备考」本身——数据库知识点多而散，没有地图的候选人复习即随机游走；面试官从你答题的系统性就能反推你的准备方式。
- 分档：P5 能列出索引/事务/锁三大高频；P6 能给出完整考点分域并说清「复述自检」的原理；P7 能把八股文、场景案例、手写 SQL 三条线的**时间配比**讲出策略。
- 红旗答案：「数据库就看 MySQL 索引和事务」——地图残缺；「八股文没用」——直接暴露实战数据源匮乏。
- 惊艳点：把「折叠复述」说成**提取练习（retrieval practice）**——能复述的知识才是可提取的，看懂 ≠ 会答 [经验]。

## 主问答
**Q（面试官原话）：** 数据库面试题又多又散，你是怎么系统准备的？
**A：**
1. **第一步：亲手重写考点地图**。九大分域——①常识类；②**场景写 SQL**；③原理类；④内存管理（重点 **buffer pool**）；⑤存储引擎；⑥**索引**（面试考察最多）；⑦事务；⑧锁；⑨查询与库优化、日志（**binlog / redo log / undo log**）、主从复制（为什么复制 + 怎么解决同步延迟）、备份与安全（考得少但要有地图位）。**必须按自己的理解重写一遍再对照补充**——抄来的地图是别人的，写过的地图才是自己的 [源码]。
2. **第二步：折叠复述自检**。面试前把地图上的答案折叠起来，只看问题**口头复述**，这是检验准备效果的最佳方式——能独立复述的才算是掌握了，卡壳的地方就是复习盲区 [源码]。
3. **第三步：备好场景案例**。高频场景题：**表结构如何设计、怎么分库分表、数据库 CPU 突然飙升怎么排查处理、怎么优化性能与慢查询**。这类题没有标准答案，靠的是平时攒的真实案例与排查链路 [源码]。
4. **第四步：动手练复杂 SQL**。按需求写 SQL 是独立题型：**分组、排序、子查询、多表连接**的复合语句；日常工作 SQL 偏简单，不专门练就写不出——手过一遍才算数 [源码]。
5. **八股文的正确定位**：实际面试**出现频率最高的就是八股文**，答不上会被贴「基础不牢」的标签；且八股是**横向拓展、纵向深挖**的抓手——由一条八股牵出原理、源码与实战，正是构建知识体系的路径 [源码]。

## 关键代码
```sql
-- 复杂 SQL 练习样板：分组 + 聚合 + 子查询 + 连接（手写练熟的目标形态）
-- 需求：查每个部门工资最高的员工（并列第一都要），输出部门名、姓名、工资
SELECT d.dept_name,
       e.emp_name,
       e.salary
FROM   employee e
JOIN   department d ON d.id = e.dept_id
WHERE  e.salary = (
    SELECT MAX(e2.salary)
    FROM   employee e2
    WHERE  e2.dept_id = e.dept_id   -- 相关子查询: 逐部门取最高薪
)
ORDER BY d.dept_name, e.salary DESC;
-- [经验] 考点覆盖：JOIN 连接、相关子查询、聚合函数、排序；
-- 进阶写法可用窗口函数 MAX(salary) OVER (PARTITION BY dept_id) 对比优劣
```

## 总结与追问预判
一句话记忆：**「地图亲手画、答案折起来复述、案例靠平时攒、复杂 SQL 手过一遍」**。通用技术面试的备考框架（五大范围、检索式学习）见 402；DS&A 备考六法见 171；buffer pool 的 young/old 分区实现见 125 [边界]。常追问「索引/事务高频题有哪些」——答索引的 B+ 树结构与失效场景、事务的隔离级别与 MVCC，本卡只管地图不展开；再追问「CPU 飙升怎么查」——答排查链：show processlist 定位活跃连接 → 慢查询日志 → explain 分析执行计划，作为场景案例的骨架。
