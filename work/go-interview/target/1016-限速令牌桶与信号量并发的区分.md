# 1016 限速（令牌桶）与信号量（并发）的区分

> 分类：Go/并发 | 难度：L2 | 题型：概念题 | 频率：中 | 关键词：**令牌桶限速率**/**信号量限并发**/**channel妙用**/**漏桶**
> 原文锚点：第 1~3 段「回顾令牌桶限流器 + channel 对请求限速，本节再回顾」

## 一句话总述
同样用 channel，两种经典限流语义易混：**令牌桶 = 限速率**（按固定速率放令牌，控制「每周期最多 N 请求」），**信号量 = 限并发**（channel 容量 = N，控制「最多 N 个同时在飞」）。前者管「多快」、后者管「多少」；还有漏桶（恒速流出、突发被缓冲）与分布式令牌桶（Redis）等不同形态。

## 面试官视角
- 考察意图：能否区分「速率限制」与「并发限制」两种语义，并据此选型。
- 分档：P5 知 channel 能限流；P6 能说清令牌桶 vs 信号量；P7 知漏桶/滑动窗口/分布式形态与选型。
- 红旗答案：把限速率和限并发混为一谈；认为信号量也能平滑突发速率。
- 惊艳点：点出「令牌桶允许短时突发（桶内有积存令牌）、信号量只卡在飞数」，以及「单机 channel 限流无法跨实例、分布式须 Redis」 [经验]。

## 主问答
**Q（面试官原话）：** 用 channel 既能限速又能限并发，两者啥区别？
**A：**
1. **令牌桶 = 限速率**：按固定速率生成令牌、取走才放行，控制「每周期最多 N 请求」，允许桶内积存令牌短时突发（见 1016） [经验]。
2. **信号量 = 限并发**：channel 容量 = N 表示最多 N 个 goroutine 同时在飞，控制「并发数」而非「速率」（见 1015） [经验]。
3. **其他形态**：漏桶恒速流出、突发被缓冲排队；滑动窗口/分布式场景用 Redis+令牌桶或滑动窗口计数（见 108） [经验]。

## 关键代码

```go
// 令牌桶（限速率）vs 信号量（限并发）——同一 channel 两种语义
// 令牌桶：定时写令牌，读即消费，控制每周期请求数（允许积存突发）
quota := make(chan struct{}, rateLimit)
go func() { for range time.Tick(period / rateLimit) { quota <- struct{}{} } }()

// 信号量：容量=N，获取才放行，控制同时在飞 goroutine 数（不限速率）
sem := make(chan struct{}, maxConcurrency)
for _, job := range jobs {
    sem <- struct{}{} // 占一个并发位
    go func(j Job) {
        defer func() { <-sem }() // 释放并发位
        process(j)
    }(job)
}
// 令牌桶管「多快」、信号量管「多少」——不要混用
```

## 总结与追问预判
选型口诀：要「平滑 QPS」用令牌桶/漏桶，要「保护下游并发」用信号量。单机 channel 无法跨实例一致，多副本须集中式限流（Redis/网关）。
