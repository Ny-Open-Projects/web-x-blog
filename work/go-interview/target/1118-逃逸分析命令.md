# 1118 逃逸分析命令：go build -gcflags="-m"

> 分类：内存与 GC | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**-gcflags="-m"** / **-m -m** / **-l 禁内联**
> 原文锚点：第 43~54 段「执行 go build 参数 gcflags 双引号至少给一个 -m」

## 一句话总述
逃逸分析是编译期静态分析，用 `go build -gcflags="-m"` 查看哪些变量逃逸到堆；`-m -m`（或 `-m=2`）更详细，最多 4 级；`-l` 禁止内联便于观察。

## 面试官视角
- 意图：是否会真用工具定位逃逸，而非背概念。
- P5 会跑 -m / P6 懂 -m -m 层级与 moved to heap / P7 用 -m 佐证性能优化。
- 红旗：以为逃逸是运行时行为；以为只能看不能关内联。
- 惊艳点：`-gcflags="-m -m"` 会打印 "moved to heap" 及流分析；`-l` 关内联使逃逸更直观 —— 验证 `go build -gcflags="-m" main.go` `[实测]`。

## 主问答
**Q（面试官原话）：** 怎么看一个变量有没有逃逸到堆上？
**A：**
1. **结论**：用 `go build -gcflags="-m" main.go`（或 `go run -gcflags="-m" main.go`）打印逃逸信息，是编译期分析。
2. **机制**：`-m` 级数越多越详细（最多 4 个），`-m -m` 或 `-m=2` 等价给出流图；`-l` 禁止内联，避免内联掩盖逃逸。
3. **边界**：输出 "moved to heap" 表示变量从栈迁堆，"func literal escapes to heap" 表示闭包直接堆分配；这是编译期，非运行期观测。
**加分层：** 想稳定对比时加 `-l` 关内联，否则内联可能让变量"看似没逃逸"。
