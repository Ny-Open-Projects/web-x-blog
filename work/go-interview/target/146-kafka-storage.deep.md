# 146 Kafka 数据存储 · 深挖

## 思路与架构
Kafka 存储是「逻辑 topic → 物理分区目录 → 日志段文件」三层。每分区是一个仅尾段可写的顺序日志，段由「1 日志 + 2 索引（.index 偏移→物理、.timeindex 时间戳→偏移）」组成，以 baseOffset 命名。写入是顺序追加（高吞吐根基）；读取靠稀疏索引 + 二分快速定位物理位置。段在四条件（大小 1GB / 时间 7 天 / 索引 10MB / 相对偏移超 int）任一满足时切分，便于清理与维护。消息格式 v2 用变长 + ZIGZAG 压缩，端到端压缩（batch 级）省网络与磁盘。

## 方案取舍
- **顺序写 vs 随机写**：Kafka 只尾段写、顺序追加，换来极高吞吐；代价是不能为单消息随机改。
- **稀疏索引 vs 稠密索引**：稀疏（4KB 间隔）省空间内存，查找多一次二分但可控；稠密占资源。
- **offset 存 zk vs 内部 topic**：zk 写频繁低效且拖集群；__consumer_offsets 借 Kafka 自身能力，稳且易扩展。
- **副本 vs 单日志**：副本提供高可用与读分担，但多一份存储与同步开销；leader 对外读写。

## 答题技巧
答存储题先给三层模型（topic→分区→段），再点「段=1 日志+2 索引、仅尾段写、顺序追加」。必提四分段条件与默认阈值（1GB/7 天/10MB/int 边界）、稀疏索引 + 二分定位、baseOffset 20 位命名。消费侧点 pull 模式、offset 在 __consumer_offsets（非 zk）、端到端压缩。追问架构时用「顺序写 + 稀疏索引 + 段切分 + 副本」收尾。
