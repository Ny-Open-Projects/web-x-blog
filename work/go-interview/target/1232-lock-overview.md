# 1232 为什么需要数据库锁：并发三关系与异常

> 分类：数据库 / MySQL 锁 | 难度：L3 | 题型：原理题 | 频率：极高 | 关键词：**并发控制、脏读、不可重复读、幻读、脏写、事务关系**

> 原文锚点：第 3~22 段「多事务同时改同一行需并发控制…事务间三种关系（读读/读写/写写）…读写导致脏读不可重复读幻读…任何隔离级别都不允许脏写」

## 一句话总述
多事务并发改同一行数据需并发控制。事务间三类关系：读读无冲突不加锁；读写会引脏读/不可重复读/幻读；写写会引脏写——**任何隔离级别都不允许脏写**，靠锁让写操作排队。

## 面试官视角
P6 能说出三类异常；P7 要讲清脏读（读未提交）、不可重复读（同条被改）、幻读（范围插新行）的区别，以及脏写为何在所有级别都被禁止。

## 主问答
**Q（面试官原话）：** 为什么需要锁？不加锁会怎样？

1. **读读无锁**：多事务只读同一行，无并发问题，无需加锁 `[源码]`。
2. **读写引三类异常**：读未提交致脏读、同条被改致不可重复读、范围插新行致幻读 `[源码]`。
3. **写写引脏写**：两未提交事务改同一行，后提交的覆盖先提交的，破坏回滚语义 `[源码]`。
4. **脏写必禁**：任何隔离级别都不允许脏写，靠锁让修改同一行的写操作排队执行 `[经验]`。
5. **锁即结构**：锁本质是内存结构，事务开始改数据时才与记录绑定，而非事务开启就有 `[源码]`。
