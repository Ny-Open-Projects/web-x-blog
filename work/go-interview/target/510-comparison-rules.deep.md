# 510 结构体比较规则与零尺寸技巧 深挖

> 覆盖源 5-10 全文：如何使结构体不可比较 + 优雅的零尺寸非导出字段 + 结构体相等三前提 + 命名 vs 匿名结构体。主卡已给手法与结论，本附录做"相等三前提""零尺寸字段原理""何时需要禁用比较"深挖。

## 思路与架构

```text
结构体比较与禁用
├─ 禁用手法: 加不可比较字段 → 优雅版 `_ [0]func()`(不可比较+零尺寸+非导出)
├─ 相等三前提: 字段可比较 + 类型可隐式转换 + 按声明顺序逐字段全等
└─ 命名 vs 匿名: 命名类型不可互转(哪怕字段一致) / 匿名结构体可互转可比较
```

## 方案取舍
- **用什么字段禁用比较**：`map`/`slice` 字段虽能禁用比较，但自身占 8/24 字节且让结构体语义变重；`func` 字段占 8 字节；**`[0]func()` 是零尺寸**，既不占内存又不可比较，是唯一"零成本"方案 [经验]。
- **为什么必须非导出**：导出字段外部可直接构造，零尺寸数组虽无值但仍是字段；非导出配合零尺寸，外部连赋值都无从下手，语义最封闭 [经验]。
- **命名 vs 匿名**：Go 的类型同一性看类型名——两个独立命名的结构体类型即使底层结构完全一致也是不同类型，不能隐式转换、不能用 `==` 比较；匿名结构体（字面量类型）底层一致即可转换与比较 [经验]。
- **字段顺序是契约的一部分**：结构体按声明顺序逐字段比较，字段顺序不同即视为不同类型，既不能隐式转换也不能比较 [经验]。

## 答题技巧
- 被问"怎么让结构体不能被比较"直接给 `_ [0]func()`，并补一句"零尺寸所以不占内存"[经验]。
- 追问"为什么不直接加 slice"→ 答"能禁用但有内存开销且语义变重，零尺寸方案更干净" [经验]。
- 主动边界到 `509-comparable-types`(可比较清单)、`506-map-key-comparable`(map key)、`910`(零尺寸原理)，构成比较全栈 [边界]。
