# 113 Go 基准测试的写法与命名规则

> 分类：Go 测试 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**Benchmark**/**_test.go**/**testing.B**/**b.N**/**原生支持**

> 原文锚点：第 1~5 段「基准测试目的与原生支持」、第 18~27 段「文件与函数命名规则」、第 82~89 段「用法总结」

## 一句话总述
基准测试是为被测对象**建立性能基准**的方式，目的一是为性能优化提供支撑数据，二是评估代码变更对性能的影响。Go 原生支持，靠标准库 `testing` 实现：文件必须以 `_test.go` 结尾，函数必须以 `Benchmark` 打头且首字母大写，唯一参数是 `*testing.B`。

## 面试官视角
这题基础但细节多。考官会盯着三件事：文件名后缀、函数名大小写、参数类型。答出「单元测试传 `*testing.T`、基准测试传 `*testing.B`」的对比，说明你真的写过而不是看过。

## 主问答
**Q（面试官原话）：** Go 里怎么做基准测试？有什么命名要求？

1. **文件后缀**：与单元测试一样，基准测试文件必须以 `_test.go` 结尾，否则不会被识别。
2. **函数前缀**：被测函数必须以 `Benchmark` 打头，且紧随其后的首字母必须大写；写成小写就识别不了。
3. **参数类型**：单元测试传 `*testing.T` 的指针，基准测试必须传 `*testing.B` 的指针，作为唯一参数。
4. **无返回值**：基准函数没有返回值，结果通过框架输出的指标呈现。
5. **循环不可少**：被测代码必须放进 `for i := 0; i < b.N; i++` 循环里，靠多次执行取平均值来评估性能。

## 关键代码
```go
package demo

import (
	"testing"
	"time"
)

func F1() { time.Sleep(10 * time.Millisecond) }

// BenchmarkF1 必须是 Benchmark 前缀 + 大写首字母，参数为 *testing.B
func BenchmarkF1(b *testing.B) {
	for i := 0; i < b.N; i++ { // b.N 由框架自动校准
		F1()
	}
}
```

## 总结与追问预判
核心：**`_test.go` + `Benchmark` 大写前缀 + `*testing.B` + for 循环**。追问常拐向「b.N 能不能自己指定」「怎么排除初始化耗时」，备好「不要改 b.N」与「用计时器控制」两句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称命名要求大写是因为「它是可以导出的」——理由不准。真实原因是 **go test 的识别规则**：基准函数名须为 `Benchmark` 后接**首字母非小写**的名字；写成小写不会被识别，这是框架匹配约定，与标识符是否导出无关。
2. 事实核校： [经验] 原文强调「被测代码必须放到 for 循环里」——正确；补充原因：单次执行的耗时太短、误差大，必须靠 b.N 次重复后取平均值才有统计意义。
3. 崩坏词归一：源码将 Benchmark / testing / _test.go 等音译为多组崩坏词，本卡统一为规范术语。
