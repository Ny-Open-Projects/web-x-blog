# 419 Go 浮点上溢与移位限制

> 分类：Go 数值类型 | 难度：L3 | 题型：陷阱题 | 频率：中 | 关键词：**float64**/**上溢 +Inf**/**移位不支持**/**IEEE754**
> 原文锚点：第 21~26 段「浮点上溢与浮点不支持移位」

## 一句话总述
Go 浮点遵循 IEEE754：**超过最大可表示值会溢出为 `+Inf`（正无穷）**，并非"保持最大值"；且**浮点类型不支持移位运算符**，编译期即报错。

## 面试官视角
- 考察意图：浮点溢出的真实结果是 +Inf，以及"浮点不能移位"这个编译期限制。
- 分档：P5 知浮点溢出；P6 知结果是 +Inf；P7 知浮点不支持移位（编译错）。
- 红旗答案：以为浮点溢出后"等于最大值"或以为浮点也能移位。
- 惊艳点：点出 IEEE754 上溢→+Inf，且 `+Inf == +Inf` 为真（源码"两数相等"其实因都是 +Inf）。

## 主问答
**Q（面试官原话）：** 浮点数加着加着溢出了会变成什么？
**A：**
1. **上溢→+Inf**：`math.MaxFloat64 + 1000` 超过最大可表示值，结果是 **`+Inf`**（`+Inf == +Inf` 为真，所以源码"两数相等"其实是两个 +Inf 相等，并非"保持最大值"）。
2. **补正源码**：原文称"加完仍等于最大值"是错的——IEEE754 浮点上溢得到正无穷，不是饱和到最大值；饱和（clamp）是定点/整数做法，浮点不是。
3. **浮点不支持移位**：对 `float` 做 `<<` / `>>` 编译期直接报错（"float 类型不支持移位运算符"）；移位只适用于整数类型。
4. **下溢→0（次正规）**：极小正数下溢会趋向 0（或次正规数），与溢出对称但方向相反。

## 关键代码
```go
package main
import ("fmt"; "math")
func main() {
    fmt.Println(math.MaxFloat64 + 1000) // +Inf
    // var x float64 = 1.23 << 32   // 编译错误：float 不支持移位

```

## 总结与追问预判
Go 浮点溢出得到 +Inf（非饱和最大值），这是 IEEE754 标准行为；浮点类型不支持移位（编译期错）。源码"加完等于最大值"需纠正为"得到 +Inf"。

## ⚠️ 原文纠错
1. 事实核校： [经验] 浮点不支持移位（编译错）、IEEE754 上溢为 +Inf，正确。
2. **补正**：原文"浮点加超最大值仍等于最大值"不准确——应为 **+Inf（正无穷）**；源码演示的"两数相等"实为两个 +Inf 相等。饱和到最大值是整数/定点做法，浮点不适用。
3. 崩坏词归一：浮点形移出→浮点上溢。
