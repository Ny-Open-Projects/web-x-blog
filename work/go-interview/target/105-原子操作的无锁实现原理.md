# 105 原子操作的无锁实现原理

> 分类：并发模型 | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**CPU 原子指令** / **LOCK 前缀** / **CAS**
> 原文锚点：第 10~12 段「原子操作通过底层 CPU 指令实现…芯片级支持」

## 一句话总述
原子操作由 CPU 提供的原子指令（如 x86 的 LOCK 前缀、CAS 指令）保证，执行期间该内存操作对其他核不可中断，因此无需加锁即保证一致性。

## 面试官视角
- **考察意图**：是否理解"无锁"的底层来源。
- **P5** 知原子靠硬件指令 / **P6** 能说 LOCK 前缀与缓存一致性(MESI) / **P7** 知 CAS 的 ABA 与循环重试代价。
- **红旗**：以为"无锁"是完全没有同步；以为原子比任何锁都快。
- **惊艳点**：x86 下 `atomic.AddInt64` 编译为带 `LOCK` 前缀的指令（如 `LOCK XADD`）—— 验证：`go build -gcflags=-S`，go1.26.5 `[实测]`。

## 主问答
**Q（面试官原话）：** 原子操作底层怎么做到不加锁也安全？
**A：**
1. **结论**：靠 CPU 原子指令，在指令级保证读-改-写整体不可被其他核打断。
2. **机制**：x86 用 LOCK 前缀锁总线/缓存行，配合 MESI 缓存一致性协议让修改全局可见；CAS 类操作循环重试直到成功。
3. **边界**：原子只保证"单个操作"不被打断，复合逻辑（如先读后写带条件）仍需 CAS 循环或锁。
**加分层：** 原子指令本身有开销（锁 cache line），高竞争下反复重试可能比一把锁更慢。
