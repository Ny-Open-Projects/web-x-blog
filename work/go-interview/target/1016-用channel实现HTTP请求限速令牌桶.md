# 1016 用 channel 实现 HTTP 请求限速（令牌桶）

> 分类：Go/并发 | 难度：L3 | 题型：方案题 | 频率：高 | 关键词：**channel限速**/**令牌桶**/**定时器写令牌**/**goroutine发起**/**协程池**

> 原文锚点：第 1~20 段「两常量(周期/峰值) + handleRequest 声明容量=rateLimit 的 channel + goroutine+timer 按速率写空 struct 令牌 + 处理前读 channel 放行」

## 一句话总述
用 channel 实现**令牌桶限流器**：声明一个容量等于「单位时间峰值」的 channel 当令牌桶，另开 goroutine 用定时器按 `周期/个数` 的速率向里写空 struct 令牌；处理请求前先从 channel 读令牌，有才放行、无则阻塞到定时器写入——天然等价于恒定速率限流。请求用 goroutine 发起、高并发配协程池防端口耗尽。一句话背法：**「channel 令牌桶限流：容量=峰值的 channel 当桶，goroutine+timer 按速率写空struct令牌，处理前读令牌放行；请求用 goroutine 发起+协程池防端口耗尽」**。

## 面试官视角
这是考察"能否把限速映射成固定容量 channel + 定时写令牌"的方案题。
- **P5**：知道 channel 当令牌桶、定时写。
- **P6**：能写读令牌放行的处理循环。
- **P7**：知道 goroutine 发起避免耗时拖累速率、协程池防端口耗尽。
- **红旗**：把速率限制说成"sleep 每秒"而非恒定令牌流；忽略请求耗时会拖慢实际速率。
- **惊艳点**：点出"定时器按 周期/请求数 写令牌、读即消费，等价于令牌桶算法"，以及"请求耗时 > 间隔时必须 goroutine 发起否则速率被拉长" `[经验]`。

## 主问答
**Q（面试官原话）：** 怎么用 channel 对 HTTP 请求做限速？

**先铺垫（由浅入深第 1 层）**：限流的本质是"控制单位时间放行的请求数"。channel 的"容量 + 阻塞读"天然就是个令牌桶——桶里有令牌才能过，没令牌就等。要做的只是定时往桶里补令牌。

1. **容量即令牌桶（第 2 层·机制）**：声明容量为 rateLimit（单位时间峰值）的 channel 当桶；另开 goroutine 用 timer，按 `周期/请求个数` 的速率向 channel 写空 struct 令牌 `[经验]`。
2. **读即放行（第 3 层）**：处理请求前从 channel 读令牌，有令牌才放行，无令牌阻塞至 timer 写入——恒定速率限流 `[经验]`。
3. **goroutine 发起（第 4 层）**：用 goroutine 发真实请求，避免单请求耗 1 秒把"1 秒 100 请求"拖成 1 秒 1 请求——耗时 > 间隔时必须异步 `[经验]`。
4. **协程池（第 5 层）**：高并发需协程池限制 goroutine 数，否则拥堵致本地端口耗尽（见 711-ants）`[经验]`。
5. **扩展（第 6 层）**：单机令牌桶；分布式多实例要用 Redis 令牌桶/滑动窗口（见 108），突发流量可借桶容量允许短期积压 `[边界]`。

## 关键代码
```go
package main

import (
	"fmt"
	"time"
)

// channel 令牌桶限流：容量=峰值，goroutine 按速率写空 struct 令牌
const (
	rateLimitPeriod = time.Second
	rateLimit       = 2 // 1 秒内最多 2 个请求
)

func main() {
	quota := make(chan struct{}, rateLimit) // 容量=单位时间峰值，当令牌桶
	go func() {
		tick := time.NewTicker(rateLimitPeriod / rateLimit) // 按速率生成令牌
		for range tick.C {
			quota <- struct{}{} // 恒定速率写入令牌
		}
	}()

	// 模拟 6 个请求，观察被限流到 ~2/秒
	for i := 0; i < 6; i++ {
		<-quota // 无令牌则阻塞，直到 timer 写入才放行
		go func(id int) {
			// doHTTP：真实请求（生产应限协程池数量）
			time.Sleep(50 * time.Millisecond)
			fmt.Println("handled request", id, time.Now().Format("15:04:05.000"))
		}(i)
	}
	time.Sleep(time.Second)
}
```

## 总结与追问预判
**背这三句就够**：① **容量=峰值的 channel 当令牌桶，定时写令牌**；② **读令牌才放行，无则阻塞到写入**；③ **请求 goroutine 发起 + 协程池防端口耗尽**。
**预判追问**：
- 「分布式多实例怎么一致？」→ Redis 令牌桶/滑动窗口（见 108）。
- 「突发流量怎么缓冲？」→ 漏桶/桶容量允许短期积压。
- 「和信号量限并发区别？」→ 令牌桶控速率、信号量控并发数（见 1016 区分）。
