# 906 字符串与字节切片转换选型 深挖

> 覆盖源 9-6 全文：常规强转拷贝 + 零拷贝（unsafe.Pointer / reflect header）+ unsafe 不安全的提示 + 大文本高并发才值得。主卡已给写法全景与版本演进，本附录做"选型决策清单"与"面试答法分层"。

## 思路与架构

```text
string ↔ []byte 转换决策
├─ 默认: 标准强转(拷贝, 安全, 易读) —— 绝大多数场景
├─ 热点: 零拷贝 —— 大文本/高并发且只读才值得
└─ 写法代际: reflect header(旧,GC风险) → Go1.20 unsafe.String/StringData/Slice(推荐)
```

## 方案取舍
- **正确性 vs 性能**：标准强转换来不可变语义与 GC 安全，代价是一次分配+拷贝；零拷贝省掉拷贝，代价是把不可变性风险交给人来保证——**默认站在正确性这边** [经验]。
- **何时零拷贝才划算**：仅在确认这块内存生命周期可控、且 conversions 数量极大（大文本解析、协议编解码热点）时才值得；小字符串上零拷贝的收益远低于引入的风险 [经验]。
- **新旧 API**：手写 reflect header 依赖 `Data` 为 `uintptr`，GC 不把它当指针根，对象可能被回收后悬垂；Go 1.20+ 官方 API 用 unsafe.Pointer 语义表达，规避该问题，应优先 [经验]。

## 答题技巧
- 先给结论（会拷贝），再说原因（保护不可变），再给现代写法（Go 1.20 官方 API），最后补代价（三大坑）——四步答满分 [经验]。
- 被问到旧写法要不要提：可作为"演进背景"提一句，但明确说**现在不应再用** [经验]。
- 主动边界到 `1113-*`(原理与陷阱)、`903-*`(底层结构)，构成转换全栈 [边界]。
