# 516 for range 取地址陷阱：value 是副本、每次复用同地址（map 值全为最后）

> 分类：Go 陷阱 / for range | 难度：L3 | 题型：陷阱题 | 频率：高 | 关键词：**for range 取地址** / **value 副本** / **同一地址** / **map 值全相同** / **先拷贝再取址**
> 原文锚点：第 3~23 段「for range创建元素副本非引用;value每次迭代指向同一地址;循环内&value存map所有key同址值全为最后(全3);正确写法先拷贝value再取址」

## 一句话总述
`for range` 的循环变量 `v` 是**元素的副本**，且**每次迭代复用同一个变量、地址不变**。若在循环内取 `&v` 存入 map，所有 key 都指向这同一个地址，最终读到的全是最后一次迭代的值（经典"map 值全为 3"）。正确写法：先 `vv := v` 拷贝一份再取 `&vv`，每次地址不同。

## 面试官视角
- 意图：这是 for range 最高频面试题，考察对"副本 + 同址复用"本质的理解，而非背结论。
- P5 知循环内取地址有坑；P6 知 v 是副本、地址复用、全得最后值；P7 知正确写法（拷贝后再取址）及为何能修、与 goroutine 闭包捕获的异同。
- 红旗：以为 `v` 每次迭代是新变量；或把"副本"理解成"每次分配新地址"。
- 惊艳点：点出"for range 本质是语法糖，底层 for 循环 + 复用同一 value 变量" `[边界]` 见 1112（大元素复制性能）、1017-closure-loop-var（goroutine 闭包捕获同款陷阱）、1017-goroutine-solutions（用传参破捕获）。

## 主问答
**Q（面试官原话）：** 下面的 for range 为什么 map 里所有值都一样？
**A：**
1. **v 是副本**：`for _, v := range s` 中 v 是元素的拷贝，不是原元素的引用。
2. **地址复用**：每次迭代复用同一个 v 变量，地址不变；循环内 `&v` 拿到的是同一个地址。
3. **全得最后值**：所有 map key 都存了同一个 `&v`，遍历结束后 v 停在最后一个元素，故读出来全是最后值（如全 3）。
4. **正确写法**：在循环内先 `vv := v` 拷贝一份（每次 vv 地址不同），再 `m[k] = &vv`，各 key 指向各自副本，值正确。

## 关键代码
```go
package main

import "fmt"

func main() {
	s := []int{0, 1, 2, 3}
	m := make(map[int]*int)

	// 陷阱：v 是副本且地址复用，&v 全指向同址 → 值全为 3
	for _, v := range s {
		m[v] = &v
	}
	for k, p := range m {
		fmt.Println(k, *p) // 全部输出 3
	}

	// 正确：先拷贝 value 再取地址，每次地址不同
	m2 := make(map[int]*int)
	for _, v := range s {
		vv := v
		m2[vv] = &vv
	}
}
```
