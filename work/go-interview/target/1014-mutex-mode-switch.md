# 1014 Mutex 模式切换：正常↔饥饿的动态平衡

> 分类：Go / 并发 / 锁 | 难度：L3 | 题型：原理题 | 频率：中高 | 关键词：**模式切换** / **1ms 阈值** / **吞吐** / **公平** / **Go 1.9**

> 原文锚点：第 36~41 段「切换条件：①队列只剩一个等待者 ②某等待者等待>1ms…任一触发进饥饿模式…正常模式吞吐最好/饥饿模式解决公平但性能降…本质性能vs公平平衡」

## 一句话总述
sync.Mutex 在正常/饥饿模式间**自动切换**，触发条件是二者任一：① 等待队列**只剩 1 个**等待者；② 某等待者**等待锁超过 1ms**。本质是在**吞吐（正常模式）与公平（饥饿模式）之间动态平衡**——默认正常模式求性能，检测到长等就切饥饿模式保公平。一句话背法：**「Mutex 正常/饥饿自动切换：等>1ms 或 队剩1人→饥饿；本质吞吐↔公平动态平衡；Go 1.9 起」**。

## 面试官视角
这是两模式题的收口。面试官想看你能否说清"何时切、为何切"，尤其是两个触发条件（队列空 / 1ms 阈值）和"性能 vs 公平"的底层动机。
- **P5**：知道有切换、阈值约 1ms。
- **P6**：说清两个触发条件（队剩1人 / 等>1ms）。
- **P7**：点出"单一模式无法兼顾吞吐与公平，故动态切换"，并知 Go 1.9 引入饥饿模式。
- **红旗**：以为只能手动切模式；以为 1ms 是可调参数。
- **惊艳点**：点出 1ms 是运行时常量 `starvationThresholdNs`，非用户可调。

## 主问答
**Q（面试官原话）：** 正常模式和饥饿模式怎么切换？为什么需要两种？

**先铺垫（由浅入深第 1 层）**：Mutex 不会让你选模式——它自己根据"等待时长"和"队列长度"在两种行为间跳。理解切换条件，就理解了"为什么既快又不会饿死"。

1. **两个触发条件（第 2 层·机制）**：(a) 等待队列里**只剩 1 个**等待者（快没人等了，没必要 handoff）；(b) 某个等待者**等锁超过 1ms**（出现长尾，需保公平）。任一触发即切饥饿模式；反之当队首等待者拿到锁且不再满足条件、或队列清空，会切回正常模式 `[源码]`。
2. **为何要两种（第 3 层）**：正常模式**吞吐最高**（新请求占优、可连续获取），但极端竞争下队尾会饥饿；饥饿模式**公平**（handoff 队首）却吞吐下降。单一模式无法兼顾，故运行时按等待时长/队列长度动态切换 `[实测]`。
3. **版本（第 4 层）**：饥饿模式是 Go 1.9 才加的公平性修复；此前只有正常模式，写者可能饿死 `[源码]`。
4. **常量（第 5 层）**：1ms 阈值即 `starvationThresholdNs = 1e6`，是运行时常量，非可调参数 `[源码]`。
5. **关联（第 6 层）**：切换由解锁路径的状态位逻辑驱动，细节见 925（Mutex 实现）`[边界]`。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
	"time"
)

// 模式切换阈值（取自 src/sync/mutex.go，示意）
const starvationThresholdNs = 1e6 // 1ms：等待超过即可能标记饥饿

func main() {
	var mu sync.Mutex
	// 高并发长跑场景下，runtime 按"等待>1ms 或 队剩1人"自动在
	// 正常模式(吞吐优先)与饥饿模式(公平优先)间切换
	var wg sync.WaitGroup
	for i := 0; i < 50; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			mu.Lock()
			_ = id
			mu.Unlock()
		}(i)
	}
	wg.Wait()
	fmt.Println("starvationThresholdNs =", time.Duration(starvationThresholdNs))
}
```

## 总结与追问预判
**背这三句就够**：① **切饥饿=等>1ms 或 队剩1人**；② **正常模式吞吐优先、饥饿模式公平优先**；③ **本质吞吐↔公平动态平衡，Go 1.9 起**。
**预判追问**：
- 「饥饿模式怎么给锁？」→ handoff 直交队首（见 1014 饥饿模式）。
- 「正常模式特点？」→ FIFO 排队但唤醒者竞争、新请求占优（见 1014 正常模式）。
- 「能手动选模式吗？」→ 不能，runtime 自动切换；1ms 不可调。
