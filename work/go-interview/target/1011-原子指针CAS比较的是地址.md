# 1011 原子指针 CAS 比较的是地址

> 分类：并发模型 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**CompareAndSwap** / **地址** / **指针值**

> 原文锚点：第 48~69 段「CS 比较的是指向的地址，不是地址指向的值；值相等地址不等不替换」

## 一句话总述
`atomic.Pointer[T].CompareAndSwap(old, new *T)` 比较的是**指针值（地址）本身**是否相等，而不是两个指针指向的结构体内容；地址不同即使字段值相同也会返回 false。一句话背法：**「atomic.Pointer[T].CAS 比较的是指针值(地址)本身非内容；同值不同地址必失败，换得动需传入当前实存地址」**。

## 面试官视角
这是考察"有没有踩过值相等但 CAS 失败的坑"的题，核心是理解 CAS 的比对对象。
- **P5**：知道 CAS 比较指针。
- **P6**：说清比的是地址非内容。
- **P7**：知道由此推导"用同一实例地址才换得动"。
- **红旗**：以为 CAS 会比较结构体字段；拿两个字段相同的不同对象去 CAS。
- **惊艳点**：同值不同地址的两个 `*T`，`CompareAndSwap` 必失败——验证：打印两地址不等即知 `[实测]` `fmt.Printf("%p")`。

## 主问答
**Q（面试官原话）：** 指针的 CAS 比较的是值还是地址？

**先铺垫（由浅入深第 1 层）**：很多人写指针 CAS 时直觉以为"两个对象字段一样就该换成功"。但 CAS 是机器级的"比较并交换一个字"，它只会比那个指针字（地址），根本不去看指向的内容。

1. **结论（第 2 层·机制）**：比较**地址（指针值）**，不是指针指向的内容 `[源码]`。
2. **机制（第 3 层）**：CAS 原子地比对当前存储的指针是否等于 old；相等才换成 new 并返回 true，否则 false `[源码]`。
3. **边界（第 4 层）**：两个字段完全相同的不同对象地址不同，CAS 永远失败；要换得动必须传入"当前确实存着的那个地址" `[实测]`。
4. **验证（第 5 层）**：用 `fmt.Printf("%p", &a)` 打印两地址，不等即知 CAS 必败 `[实测]`。
5. **进阶（第 6 层）**：想要"按内容换"得自己保证同一份实例，或改用值比较的自定义逻辑（如先比对内容再换）`[经验]`。

## 关键代码
```go
package main

import (
	"fmt"
	"sync/atomic"
)

func main() {
	var p atomic.Pointer[int]
	a, b := 1, 1
	p.Store(&a)
	// CAS 比较的是"指针值(地址)"，不是指向的内容
	// &b 与 &a 是不同地址，即使值都为 1，CAS 也失败
	ok := p.CompareAndSwap(&b, &a)
	fmt.Printf("CAS(&b,&a)=%v （地址不等，必失败）\n", ok) // false

	// 传入当前实存地址 &a 才换得动
	ok2 := p.CompareAndSwap(&a, &b)
	fmt.Printf("CAS(&a,&b)=%v （地址相等，成功）\n", ok2) // true

	fmt.Printf("a addr=%p b addr=%p\n", &a, &b) // 两地址不同
}
```

## 总结与追问预判
**背这三句就够**：① **指针 CAS 比的是地址（指针值）非内容**；② **同值不同地址必失败**；③ **换得动需传入当前实存地址**。
**预判追问**：
- 「想按内容换怎么办？」→ 保证同一实例，或先比对内容再换（见 1011 指针原子避免锁）。
- 「怎么验证地址不等？」→ `fmt.Printf("%p", ptr)`。
- 「泛型 Pointer 几方法？」→ Load/Store/Swap/CompareAndSwap（见 1011 泛型 API）。
