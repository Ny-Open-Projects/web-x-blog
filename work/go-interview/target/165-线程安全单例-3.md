# 165 线程安全单例：sync.Once 方案

> 分类：Go/并发 | 难度：L2 | 题型：方案题 | 频率：中 | 关键词：**sync.Once** / **once.Do** / **只执行一次** / **官方推荐**
> 原文锚点：第 24~33 段「用 once.Do 包住实例化，Once 保证只执行一次；测试 100 并发只建一次」

## 一句话总述
Go 里实现线程安全单例的**官方推荐**是 `sync.Once`：把实例化逻辑包进 `once.Do(f)`，无论多少 goroutine 并发调用，`f` 只执行一次，后续直接返回已建实例。语义清晰、无竞态、无需手写锁与双重检查——比 Mutex/DCL 更省心。

## 面试官视角
- 意图：考察"是否知道 Go 原语级的正确单例写法"。
- P5 知道加锁；P6 能写出 Once 版；P7 能讲"Once 内部就是 atomic + Mutex 双重检查，与我们手写的原子方案同源"并联系 1021-safe-close-once。
- 红旗：手写 DCL 而不知 Once；以为 Once 很神秘。
- 惊艳点：点出"Once 内部实现 = atomic 标志 + Mutex 双重检查，正是原子方案的由来"。

## 主问答
**Q：** Go 里单例最稳的写法？
**A：**
1. **写法**：声明 `var once sync.Once` 与 `var inst *T`；`GetInstance` 里先判断 `inst` 是否已建，未建则 `once.Do(func(){ inst = &T{} })`——`Do` 保证 `f` 只跑一次。
2. **为什么稳**：`Once` 内部用原子操作判"是否已执行"、拿锁后二次检查再执行，天然规避了手写 DCL 的内存可见性 race，且语义直白。
3. **边界**：`Once` 只保证"一次"，若需重置/重建实例则不适用，得换其他机制。

## 关键代码
```go
// sync.Once：Go 官方推荐的线程安全单例写法
var (
    inst *Singleton
    once sync.Once
)

func GetInstance() *Singleton {
    if inst == nil { // 快速路径：已建好直接返回，无锁
        once.Do(func() {
            inst = &Singleton{} // 只执行一次，内部已处理可见性
        })
    }
    return inst
}
// 100 并发调用也只创建一次；与 1021-safe-close-once 共用 Once 原语
```
