# 1222 覆盖索引如何让非前缀 LIKE 也能走索引

> 分类：MySQL 索引 | 难度：中高 | 题型：原理 | 频率：高 | 关键词：**覆盖索引、二级索引全扫、type=index、回表、LIKE 例外**

> 原文锚点：第 29~49 段「非前缀 LIKE 只查 name 也能用索引、二级索引树含全部值、覆盖则走二级索引」

## 一句话总述
当查询「只取索引列」满足覆盖索引时，非前缀 LIKE（如 `'%x%'`）虽然无法利用有序性定位，但优化器会选择「全表扫描二级索引树」（type=index）而非聚簇索引树——因为二级索引树叶子只存「索引列+主键」，数据量小、IO 成本低，且无需回表即可拿到所需字段，于是「不遵循最左前缀也能用上索引」。

## 面试官视角
这是 LIKE 题的「进阶破例点」，区分普通候选与高手。考官期待你说清：① 全表扫描也有「扫主键树」和「扫二级索引树」两种方式；② 覆盖索引下二级索引树已含所需全部值，扫描它更便宜；③ type=index 表示「遍历整棵二级索引」，与 type=range（利用有序性快速定位）效率不同。

## 主问答
**Q（面试官原话）：** 为什么只查 name 字段时，'%x%' 也能用上索引？

1. **全表扫的两种路径**：非前缀 LIKE 必全扫，但可扫「聚簇（主键）索引树」或「二级索引树」二选一。
2. **二级索引树更小**：其叶子只存索引列值与主键值，不含其他列与隐藏列，体积远小于聚簇索引树。
3. **覆盖即免回表**：若只查索引列（如 name），遍历二级索引树就能拿到全部结果，无需回表，IO 成本最低。
4. **优化器选型**：覆盖条件下，优化器认为「遍历二级索引树」比「遍历聚簇索引树」便宜，故选 type=index（用二级索引）。

## 版本与兼容性
| 条件 | type | 扫描对象 |
|------|------|----------|
| 非前缀 LIKE + 覆盖 | index | 二级索引树 |
| 前缀 LIKE | range | 索引范围 |
| 非前缀 + 需回表 | ALL | 聚簇索引树 |

## 关键代码
```sql
-- name 是二级索引，只查 name 满足覆盖
SELECT name FROM user WHERE name LIKE '%张%';  -- type=index，走二级索引
```

## 总结与追问预判
核心：**覆盖索引下，非前缀 LIKE 走 type=index 全扫二级索引树（免回表、IO 便宜），破最左前缀限制**。追问常接「为何二级索引树更便宜」（见 1222）。
