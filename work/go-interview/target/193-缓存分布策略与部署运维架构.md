# 193 缓存分布策略与部署运维架构

> 分类：架构/缓存 | 难度：L2 | 题型：设计题 | 频率：中 | 关键词：**一致性哈希** / **取模** / **分池分层** / **异构**
> 原文锚点：第 9~16 段「分布式算法(取模/一致性哈希)；client 直连 vs proxy 路由；动态拆分迁移；分池/分层/分IDC/异构/服务化」

## 一句话总述
选好组件和结构后，要规划**分布策略**和**部署运维**：分布算法在取模（简单但扩缩容数据漂移大）与一致性哈希（节点变更仅影响邻近槽、可负载均衡）间权衡；访问方式在 client 直连（性能最优、需感知分布）与 proxy 路由（对业务友好、略损性能）间权衡；部署上对核心数据分池隔离、海量数据分层（本地+远程）、跨机房分 IDC，并视情况异构与服务化。

## 面试官视角
- 意图：考察"会不会把单点缓存扩成可水平扩展的分布式缓存"。
- P5 知道分片；P6 能讲取模 vs 一致性哈希的差异、client vs proxy 取舍；P7 能讲分池/分层/分IDC/异构/服务化的实战理由（隔离故障、分摊热点、就近接入）。

- 惊艳点：点出"动态拆分迁移避免命中率骤降"和"异构=组合多种组件发挥各自优势"。

## 主问答
**Q：** 缓存怎么分布、怎么部署才稳？
**A：**
1. **分布算法**：**取模**简单但节点数变化会大面积重映射；**一致性哈希**把 key 映射到环，节点变更只影响相邻区间，迁移量小、可负载均衡——是秒杀这类弹性扩缩容场景的首选。
2. **访问方式**：**client 直连**按 hash 定位节点，性能最优但业务要感知分布逻辑；**proxy** 代理路由对开发友好，代价是额外一跳延迟。
3. **部署运维**：核心高并发数据**分池**独立、互不拖累；海量数据**分层**（本地+远程）分摊访问；跨地域**分 IDC** 就近；极端场景**异构**组合多种组件；并将缓存**服务化**做统一管控监控。

## 关键代码
```go
// 一致性哈希：节点变更仅影响相邻区间，迁移量远小于取模
type ConsistentHash struct {
    ring         map[uint32]string
    sortedHashes []uint32
}

func (c *ConsistentHash) Get(key string) string {
    h := hashKey(key)
    // 在 sortedHashes 中顺时针找首个 >= h 的节点
    idx := sort.Search(len(c.sortedHashes), func(i int) bool {
        return c.sortedHashes[i] >= h
    })
    if idx == len(c.sortedHashes) { idx = 0 } // 环回
    return c.ring[c.sortedHashes[idx]]
}
// 对比取模 rdb[hash(key)%N]：N 变化会导致几乎所有 key 重映射
```
