# 414 数组与切片的相同点：连续内存与 O(1) 访问

> 分类：Go 基础 / 数组与切片 | 难度：L3 | 题型：记忆题 | 频率：高 | 关键词：**数组、切片、连续内存、O(1)、map 对比**

> 原文锚点：第 6~16 段「数组和切片都要求全部元素的类型都必须相同…所有的元素都是紧挨着存放在一个连续的内存当中…映射元素访问的速度要比数组和切片慢上几倍…对 int 切片的第一千个元素赋值，前面九百九十九个元素的零值也会被分配一样的内存空间」

## 一句话总述
数组与切片都要求元素同类型、在连续内存中紧挨存放、按下标访问 O(1)；map 访问同为 O(1) 但常数慢几倍，优势是 key 可为任意可比较类型、稀疏场景省内存。

## 面试官视角
P6 答出「同类型 + 连续内存 + O(1)」；P7 要补上**与 map 的对比**：为何同样 O(1) 却慢几倍（哈希 + 桶探测），以及**切片长度确定即要为全部零值分配空间**的内存代价。

## 主问答
**Q（面试官原话）：** 数组和切片有什么相同点？和 map 比呢？

1. **元素同类型**：二者都要求全部元素类型一致，编译期即确定 `[源码]`。
2. **连续内存紧挨存放**：所有元素在一块连续内存中相邻排列，是下标 O(1) 寻址的前提 `[源码]`。
3. **访问都是 O(1)**：数组、切片、map 按位访问均为 O(1)，但 map 通常**慢上几倍** `[源码]`。
4. **map 慢的原因**：要先算哈希、定位桶、桶内比对 key，常数远大于直接地址偏移 `[经验]`。
5. **map 优势一**：key 可为**任何可比较类型**，而数组/切片下标只能是整数 `[源码]`。
6. **map 优势二**：多数元素为零值时省内存——切片长度一旦确定就要为**全部**零值分配空间，map 只存真实存在的键 `[源码]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |

## 关键代码
```go
package main

import "fmt"

func main() {
	// 稀疏场景：切片长度确定后，前 999 个零值也要真实占用内存
	s := make([]int, 1000)
	s[999] = 1 // 只关心 1 个元素，却分配了 1000 * 8 字节

	// map 只存真实存在的键，无零值浪费
	m := make(map[int]int)
	m[999] = 1

	fmt.Println(s[999], m[999])
}
```

## 总结与追问预判
**相同点三句（同类型、连续、O(1)），差异靠 map 两优势拉开**。常追问「何时必须用切片」——下标连续、需顺序遍历、追求极速；稀疏或键非整数则选 map。nil 语义见同批 414-slice-nil-vs-map。

## ⚠️ 原文纠错
1. 事实核校：元素同类型、连续内存、O(1) 访问、map 慢几倍、map key 可比较、稀疏省内存——均与 Go 规范一致 `[经验]`。
