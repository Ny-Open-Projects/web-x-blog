# 1231 可见性判断：事务 ID 三区间算法

> 分类：MySQL 事务 | 难度：高 | 题型：原理 | 频率：高 | 关键词：**可见性、活跃事务列表、min_trx_id、max_trx_id、undo log 回溯**

> 原文锚点：第 50~72 段「事务ID分三区间、小于最小则可见、区间内查活跃列表、大于最大则回溯」

## 一句话总述
拿到 ReadView 后，把数据版本的 DB_TRX_ID 与「活跃事务列表」的最小/最大事务 ID 比较，分三区间判断可见性：**① 小于最小活跃 ID → 已提交，可见**；**② 介于最小与最大之间 → 若在活跃列表中则不可见（事务未提交），否则可见；若等于本事务自身 ID 则可见**；**③ 大于最大活跃 ID → 是 ReadView 之后才生成的版本，不可见**。②③ 不可见时沿 undo log 回溯上一版本重新判断。

## 面试官视角
三区间算法是 MVCC 的硬核，能完整讲出来就是高分。考官还会追问「为什么 RR 下会读到大于最大活跃 ID 的版本」——答：RR 的 ReadView 只在启动时生成，之后新事务的 ID 不在该视图的活跃列表里，所以判断依据始终是启动时那份快照。

## 主问答
**Q（面试官原话）：** MVCC 怎么判断一个版本对当前事务是否可见？

1. **区间①（trx_id < 最小活跃 ID）**：生成该版本的事务在 ReadView 生成前就已提交 → **可见**。
2. **区间②（介于最小与最大活跃 ID 之间）**：查该 ID 是否在活跃事务列表中——**在**说明创建 ReadView 时该事务仍活跃，版本**不可见**，需沿 undo log 找上一版本重判；**不在**则已提交，**可见**。特例：若该 ID **等于当前事务自身 ID**，说明是本事务自己改的，**可见**。
3. **区间③（trx_id > 最大活跃 ID）**：该版本是 ReadView 生成之后才产生的 → **不可见**，同样沿 undo log 回溯上一版本重判。
4. **回溯**：不可见时通过 DB_ROLL_PTR 找到 undo log 中的上一版本，取其 DB_TRX_ID 重新走一遍判断。
