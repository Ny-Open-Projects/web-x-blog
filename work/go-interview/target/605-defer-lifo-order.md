# 605 defer 执行顺序：LIFO 与链表栈实现

> 分类：Go 错误处理 / defer | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**defer 顺序** / **LIFO** / **链表栈** / **后进先出** / **goroutine 结构**
> 原文锚点：第 1~47 段「defer是链表栈,最后声明插链表头,执行从头部取→后进先出;多个defer实例单链表挂在goroutine结构;函数退出从头部取执行」

## 一句话总述
多个 `defer` 按**后进先出（LIFO）**执行：每个 defer 语句生成一个 defer 实例，以**指针串成单链表**挂在 goroutine 的数据结构上；**最后声明的插到链表头**，函数退出时从**链表头**依次取出执行，于是"最后声明最先执行"。（与 607 互补：607 讲 defer 在 return 求值之后执行的时机，本卡讲 LIFO 的链表栈结构。）

## 面试官视角
- 意图：不仅背"LIFO"，还要讲清底层是链表栈、为何最后声明先执行。
- P5 知多个 defer 倒序执行；P6 知链表栈、最后声明插头部、退出从头部取；P7 知 defer 实例挂在 goroutine 结构、与 return 时机的先后关系（见 607）。
- 红旗：以为按顺序执行；或讲不清"为什么倒序"。
- 惊艳点：点出"defer 实例是单链表、挂在 goroutine 上，函数退出统一弹出" `[边界]` 见 607-defer-exec-order（return 求值后执行时机）、607-defer-loop-var（defer+循环变量坑）、607-defer-named-return（命名返回值被改）。

## 主问答
**Q（面试官原话）：** 多个 defer 什么顺序执行？为什么？
**A：**
1. **结论 LIFO**：多个 defer 后进先出，最后声明的先执行（如 3-2-1）。
2. **链表栈实现**：每个 defer 生成一个实例，用指针串成**单链表**挂在 goroutine 数据结构；最后声明的插到**链表头**。
3. **执行时机**：函数执行完毕（return 之后）从**链表头**依次取出执行，故头部的最先跑 → 倒序。
4. **与 return 时机互补**：607 指出 defer 在 return 表达式求值之后、真正返回之前执行；本卡补"倒序"的链表结构根因。

## 关键代码
```go
package main

import "fmt"

func main() {
	defer fmt.Println(1)
	defer fmt.Println(2)
	defer fmt.Println(3)
	// 输出：3 2 1（LIFO，最后声明最先执行）
}
```
