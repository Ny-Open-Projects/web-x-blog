# 607 defer 变量估值时刻

> 分类：错误处理 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**声明时估值** / **闭包执行时** / **值/实参/闭包**
> 原文锚点：第 14~39 段「非闭包 s 在声明时估值，闭包取最新值」

## 一句话总述
defer 后跟普通语句或值参数时，变量在 defer 声明那一刻估值定格；只有闭包会在执行时才读最新值。

## 面试官视角
- 意图：是否分清"声明时拷贝"与"执行时读取"两种捕获语义。
- 分档：P5 知有差异 / P6 说清三态 / P7 知方法值接收者也同理。
- 红旗：以为 defer 永远读最新值；以为闭包和值参数一样。
- 惊艳点：s 在 defer 声明时为 0，非闭包打印 0、闭包打印 1 `[源码]` 语言规范。

## 主问答
**Q（面试官原话）：** defer 里打印的变量，是声明时的值还是执行时的值？
**A：**
1. **结论**：普通语句/值参数在 defer 声明时估值；闭包在 defer 执行时才读变量当前值。
2. **机制**：非闭包 `defer fmt.Println(s)` 把 s 当时值压栈；`defer f(s)` 把实参定格；闭包 `defer func(){print(s)}()` 捕获变量，执行时 s 已变。
3. **边界**：区分"值/实参"与"闭包"是同一道题的两种答案，漏掉一种就是半对。
**加分层：** 想延迟读最新值就用闭包；想定格快照就直接传值或普通语句。

## 关键代码
```go
// 示意，未验证：值参数定格 vs 闭包读最新
func g() {
    s := 0
    defer fmt.Println(s)                // 打印 0（声明时定格）
    defer func() { fmt.Println(s) }()   // 打印 1（执行时读）
    s = 1
}
```

## 总结与追问预判
- 值/实参在声明时定格，闭包在执行时读最新。
