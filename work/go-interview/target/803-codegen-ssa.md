# 803 中间代码、SSA 与机器码生成

> 分类：Go 编译 | 难度：L4 | 题型：八股题 | 频率：低 | 关键词：**SSA**/**代码优化**/**机器码**
> 原文锚点：第 35~38、44~49 段「生成中间代码→代码优化→生成 SSA→生成机器码→链接」

## 一句话总述
编译后端把 AST 转成与机器无关的中间表示（IR），再降级为 SSA 做一系列优化（死代码消除、寄存器分配等），最终 lowering 成特定架构的机器码，由汇编器产出 `.o` 目标文件，交给链接器合成可执行文件。

## 面试官视角
- 考察意图：是否理解"与机器无关→与机器相关"的降级过程，以及优化的落脚点。
- 分档：P5 知有"代码生成"；P6 懂 SSA 是优化载体；P7 能讲清 IR→SSA→机器码→目标文件→链接的完整链路。
- 红旗答案：以为 SSA 已经是机器码；分不清汇编器（`.o`）与链接器（合成二进制）的分工。
- 惊艳点：**Go 的 SSA 在 `cmd/compile/internal/ssa`，优化（内联/逃逸的结论在此落地、死代码、寄存器分配）与架构后端（amd64/arm64）都挂在 SSA 框架上；`cmd/internal/obj` 负责把 SSA 产物变成 `.o`** `[源码]`。

## 主问答
**Q（面试官原话）：** 编译后端经历了哪些步骤？
**A：**
1. **结论**：AST→带类型 IR→SSA（与机器无关）→多轮优化→lowering 成架构相关指令→机器码→`.o` 目标文件→链接器合成二进制。
2. **机制**：SSA 是"静态单赋值"形式，便于做常量传播、死代码消除、逃逸后的堆分配决策；优化后 lowering 到目标架构（如 amd64），由 `cmd/internal/obj` 汇编成可重定位 `.o` `[源码]`。
3. **边界**：每个 `.o` 只含本包代码与对外符号；跨包/跨库的拼接与地址重定位由链接器（`cmd/link`）完成。

**加分层：** 现代 Go 链接器默认把 runtime、标准库一起静态链接进单文件二进制，所以 `go build` 产物不依赖外部动态库（CGO 除外）。

## 关键代码
```bash
# 窥探 SSA 与汇编产物
go build -gcflags='-S' ./...        # 打印汇编（机器码）输出
go build -gcflags='-d=ssa/...' ...  # 导出各阶段 SSA 中间表示
```

## 总结与追问预判
后端=IR→SSA 优化→机器码→`.o`→链接；SSA 是优化与架构解耦的关键。追问接"链接器如何把多个 .o 合成一个二进制"。
