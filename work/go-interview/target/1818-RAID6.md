# 1818 RAID 6：双奇偶校验与分布约束

> 分类：存储/硬件 | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**双校验**/**P+Q**/**Reed-Solomon**/**(N-2)/N**/**重建窗口**

> 原文锚点：第 31~40 段「RAID 6 结构与校验分布规则」、第 50~51 段「容忍两块盘故障」

## 一句话总述
RAID 6 在 RAID 5 基础上再加一份独立校验（P + Q），至少 4 块盘、可用容量 (N-2)/N，可容忍两块盘同时故障；核心布局约束是**数据与其校验位必须落在不同磁盘上**，否则单盘故障会同时丢数据与校验而无法恢复。

## 面试官视角
考官常问「为什么大容量盘不推荐 RAID 5」。标准答案就是 RAID 6：盘越大重建越久，重建期间再坏一块就全丢，多一份校验换的是**重建窗口的安全边际**。能提到重建时间与 URE 风险，说明你真碰过生产。

## 主问答
**Q（面试官原话）：** RAID 6 和 RAID 5 有什么本质区别？为什么需要它？

1. **双份校验**：除数据外还保存两组独立校验块，分别存放在不同磁盘上，因此可承受两块盘同时故障。
2. **不是简单复制**：两份校验由不同算法生成（如 P 用异或、Q 用 Reed-Solomon 类运算），才能解出两个未知数，单纯复制一份校验无法恢复两盘数据。
3. **分布约束**：数据与其校验位必须分布在不同磁盘——若同盘既存数据又存其校验，整盘故障时会同时丢失，数据便无法恢复。
4. **容量代价**：可用容量为 (N-2)×单盘，最少 4 块盘，比 RAID 5 再多牺牲一块盘的容量。
5. **写入代价**：每次写入都要计算并写出两份校验，写性能受影响，故更适合读多写少与大容量近线存储。

## 版本与兼容性
| 级别 | 最少盘 | 可用容量 | 容错 | 写性能 |
|------|--------|----------|------|--------|
| RAID 5 | 3 | (N-1)×单盘 | 1 块 | 较差 |
| RAID 6 | 4 | (N-2)×单盘 | 2 块 | 更差 |

## 关键代码
```go
// Go 侧视角：容量规划器，迁移与扩容前先算清可用空间
package main

import "fmt"

func usable(level int, disks, sizeGB int) int {
	switch level {
	case 5:
		return (disks - 1) * sizeGB
	case 6:
		return (disks - 2) * sizeGB
	default:
		return disks * sizeGB
	}
}

func main() {
	fmt.Println("6 盘 4TB 做 RAID6 可用:", usable(6, 6, 4000), "GB")
}
```

## 总结与追问预判
核心：**多一份校验 = 多一块盘的容量 + 更长的重建安全窗口**。追问常拐向「重建期间业务影响」「要不要配热备盘」，备好「重建 IO 打满、需限流并配热备」这条工程经验。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称 RAID 6「相当于把校验位冗余了一份」——并非复制同一份校验，而是用两套独立算法生成两个不同校验块，才能从两个未知数中解出数据。
2. 事实核校： [经验] 原文关于「数据与其校验位必须分布在不同磁盘」的表述正确，这是 RAID 5/6 布局的核心约束，本卡保留并强调。
3. 崩坏词归一：源码将 RAID / 奇偶校验 等音译为多组崩坏词，本卡统一为规范术语。
