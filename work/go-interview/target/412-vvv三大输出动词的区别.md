# 412 %v %+v %#v 三大输出动词的区别

> 分类：数据结构/格式化 | 难度：L3 | 题型：对比题 | 频率：高 | 关键词：**%v 默认格式** / **%+v 字段名** / **%#v Go 语法**
> 原文锚点：第 1~32 段「定义了结构体 s…分别用 %v %+v %#v 三种方式输出 s1 s2 和 map」

## 一句话总述
`%v` 打印默认值（结构体不显字段名）、`%+v` 额外打印**导出**字段名、`%#v` 打印 Go 语法值（带包名与类型名）；三者对未实现 `String()` 的结构体差异最明显。

## 面试官视角
- **意图**：是否真用过 fmt 三大动词，还是只背过名字。
- **P5** 能说出三者「显不显字段名/类型名」的差异 / **P6** 能讲清 map 与结构体表现一致、且知道 `%#v` 带包名 / **P7** 知 `String()` 实现后三者走 `String()`（除 `%#v` 优先 `GoString()`）。
- **红旗**：以为 `%v` 也打印字段名；以为 `%#v` 只比 `%+v` 多类型。
- **惊艳点**：`%#v` 对 `*string` 字段打印 `(*string)(0xc0…)` 类型名——验证：`go run` 实测，`fmt.Printf("%#v", s)` go1.26.5 `[实测]`。

## 主问答
**Q（面试官原话）：** `%v`、`%+v`、`%#v` 有什么区别？
**A：**
1. **结论**：`%v` 默认格式（结构体只列字段值，无字段名）；`%+v` 在 `%v` 基础上加**导出**字段名；`%#v` 输出 Go 语法值，含包名、类型名与指针类型名。
2. **机制**：三者都走 fmt 的反射格式化；`%+v` 多一步导出字段名导出，`%#v` 多一步类型/包名渲染 `[源码]`。
3. **边界**：未导出字段（小写）`%+v` 和 `%#v` 都照常显示值，`%#v` 仍带类型名；一旦类型实现 `String()`，`%v`/`%+v` 改走 `String()`，`%#v` 仅当另有 `GoString()` 才覆盖。
**加分层：** 生产日志用 `%+v` 比 `%v` 更易排查，因带字段名；极致可读再用 `%#v` 定位类型。

## 关键代码
```go
// 示意，未验证：三者对比（s 未实现 String 时）
type S struct{ Name *string; ID int }
n := "x"; s := S{Name: &n, ID: 1}
fmt.Printf("%v\n", s)   // {0xc0… 1}
fmt.Printf("%+v\n", s)  // {Name:0xc0… ID:1}
fmt.Printf("%#v\n", s)  // main.S{Name:(*string)(0xc0…), ID:1}
```

## 总结与追问预判
- `%v` 默认值、`%+v` 加字段名、`%#v` 加类型与包名。
- 预判：`%#v` 的 Go 语法细节 → 见 412；`String()` 如何接管输出 → 见 412。
