# 1022 协程泄露全景（深卡）

> 分类：Go 运行时 · 并发缺陷 | 难度：L3 | 题型：综合题 | 频率：高 | 关键词：**泄露本质**/**场景枚举**/**预防体系**/**监控定位**
> 原文锚点：第 1~66 段「协程泄露定义、三类易发场景(defer/nil/空select/无退出)、预防(context/超时/池化/分治)、监控」

## 思路与架构
把"协程泄露"从本质到落地串成一条线：

1. **本质**：协程被创建却永不退出（阻塞在 channel / 死循环 / 等永不发生的事件），其栈与引用对象一直可达，GC 不敢回收；持续创建 → 堆积 → 内存/端口/句柄耗尽 → OOM 或服务崩溃。
2. **场景枚举（两组互补）**：
   - **本卡组**（1022-leak-trigger-scenarios）：defer 误用（文件句柄堆积）、nil channel 读写、空 `select{}`、channel 收发不匹配的延伸。
   - **1019 组**：for-select 不判 ok 空转、发送超缓冲永久阻塞、ticker 不 Stop。
3. **预防体系**（1022-leak-prevention）：context 取消 + 超时 + 协程池/信号量控并发 + 大文件分治/文件流 + 监控。
4. **监控定位**：`runtime.NumGoroutine()` 看趋势、pprof goroutine profile 抓现场。

## 方案取舍
| 治理手段 | 防什么 | 代价/注意 |
| --- | --- | --- |
| context 取消 | 无退出机制的协程 | 每个协程都要接 Done |
| 超时 | 长任务/下游故障堆积 | 需业务可接受中断 |
| 协程池/信号量 | 无界并发创建 | 需估并发上限 |
| 大文件分治 | 单协程吃光内存 | 代码稍复杂 |
| NumGoroutine/pprof | 发现泄露 | 线上常态化观测 |

**取舍总纲**：泄露的"发现"靠监控、"根治"靠给每个协程确定性退出路径 + 并发上限；不能依赖"函数返回协程就自动没" `[经验]`。

## 细节与核心 API

**① 三类典型泄露场景（可直接背的代码现场）**

```go
// 坑 1：nil channel 读写 —— 永久阻塞
func leakNilChannel() {
	var ch chan int          // nil channel
	go func() { ch <- 1 }()  // 收发都永久阻塞，协程永不退出
}

// 坑 2：空 select{} —— 永久阻塞（常用于"故意挂住"，误用即泄露）
func leakEmptySelect() {
	go func() { select {} }() // 没有任何 case，永远等下去
}

// 坑 3：channel 只发不收 / 只收不发
func leakNoReceiver() {
	ch := make(chan int)      // 无缓冲
	go func() { ch <- 1 }()   // 没人接收 → 发送方永久阻塞
}

// 坑 4：defer 写在死循环里 —— 资源永不释放
func leakDeferInLoop(path string) {
	for {
		f, _ := os.Open(path)
		defer f.Close() // defer 只在函数返回时执行，循环里永不返回 → 句柄堆积
	}
}
```

**② 根治：给每个协程一条确定性退出路径（context）**

```go
func worker(ctx context.Context, jobs <-chan int) {
	for {
		select {
		case <-ctx.Done():   // 退出信号
			return           // 确定性退出，栈与引用随之不可达，可被 GC
		case j, ok := <-jobs:
			if !ok {
				return      // channel 关闭也要退出，否则会空转收零值
			}
			process(j)
		}
	}
}
// 调用方：ctx, cancel := context.WithCancel(ctx); cancel() 即可让 worker 退出
```

**③ 兜底：超时 + 并发上限，双保险**

```go
// 超时兜底：即使忘了 cancel，到点也会退出
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

// 并发上限：用带缓冲 channel 当信号量，杜绝无界创建
sem := make(chan struct{}, 100) // 最多 100 个并发
for _, task := range tasks {
	sem <- struct{}{}            // 占一个位（满了就阻塞在这里，而不是无脑起协程）
	go func(t Task) {
		defer func() { <-sem }() // 归还
		worker(ctx, t)
	}(task)
}
```

**④ 监控：发现泄露的两把尺子**

```go
// ① 看趋势：协程数只涨不跌 = 大概率泄露
go func() {
	t := time.NewTicker(10 * time.Second)
	defer t.Stop()
	for range t.C {
		log.Printf("goroutines=%d", runtime.NumGoroutine())
	}
}()

// ② 抓现场：pprof goroutine profile
//   curl http://localhost:6060/debug/pprof/goroutine?debug=2
//   go tool pprof http://localhost:6060/debug/pprof/goroutine
// 看哪个函数下的协程数最多，就是泄露点
```

> API 速记：`context.WithCancel/WithTimeout`（退出路径）/ 带缓冲 channel 当信号量（并发上限）/ `runtime.NumGoroutine()`（趋势）/ `pprof/goroutine`（现场）。
