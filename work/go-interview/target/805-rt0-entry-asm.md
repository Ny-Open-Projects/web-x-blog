# 805 程序入口 _rt0_amd64 与 rt0_go

> 分类：运行时 | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**_rt0_amd64** / **rt0_go** / **OS_ARCH 相关**
> 原文锚点：第 41~48 段「入口点函数 RT零AMD六十四…不同操作系统/CPU 架构执行的函数不同」

## 一句话总述
Go 可执行文件加载后，真正的起点是平台相关的汇编入口（如 amd64 Linux 的 `_rt0_amd64`），它做完最小环境准备后跳进 `runtime.rt0_go`，再转入 Go 写的运行时初始化——入口因 OS/ARCH 而异。

## 面试官视角
- 意图：是否知道 Go 程序并非从 `main` 起，入口是汇编且平台相关。
- P5 知入口不是 main / P6 能说 `_rt0_amd64`→`rt0_go` 链路 / P7 知为何用汇编（要直接读 argc/argv、设栈）。
- 红旗：以为 `main` 是第一个执行的函数；以为入口与平台无关。
- 惊艳点：同一份 Go 代码，amd64/arm64、linux/darwin 的入口汇编各不相同 —— 验证 `runtime` 包 `asm_amd64.s` `[源码]`。

## 主问答
**Q（面试官原话）：** Go 程序跑起来，第一个执行的是 `main` 吗？入口在哪？
**A：**
1. **结论**：不是 `main`。先是 OS 加载镜像，再由平台相关汇编入口（`_rt0_amd64` 等）接管，跳进 `runtime.rt0_go`。
2. **机制**：入口汇编负责把 argc/argv 从栈上取出、设置好初始栈与寄存器，再调用 Go 实现的 `rt0_go` 进入运行时。
3. **边界**：入口函数名随 OS/ARCH 变化（如 `_rt0_amd64_linux`），不能用一份汇编覆盖所有平台。
**加分层：** 用汇编是因为此时还没有 Go 运行时，连栈和参数约定都要手动摆好。

## 总结与追问预判
- 入口是平台汇编 `_rt0_amd64`→`rt0_go`，不是 main；跨 OS/ARCH 不同。
