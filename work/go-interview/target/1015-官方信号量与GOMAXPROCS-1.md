# 1015 官方信号量与 GOMAXPROCS(-1)：参数小于 0 时的语义

> 分类：并发模型 | 难度：L3~L4 | 题型：陷阱题 | 频率：中 | 关键词：**semaphore、NewWeighted、GOMAXPROCS(-1)、逻辑 CPU、限流**

> 原文锚点：第 53~60 段「通过包提供的方法传一个资源的数量，这里传的是本机逻辑 CPU 的个数，调用 GOMAXPROCS 传负一，获取的就是当前逻辑 CPU 的个数」

## 一句话总述
官方扩展库的信号量用 `NewWeighted` 传入资源数；常用写法是传 `runtime.GOMAXPROCS(-1)`——**传负值不会修改设置，只返回当前值**，即本机逻辑 CPU 个数。

## 面试官视角
P6 会背"传 -1 拿到 CPU 数"；P7 要说出**这个调用的两重语义**：值小于 0 时**设置不生效**，但**仍返回旧值** `[源码]`。加分点：Go 1.20 起默认就等于操作系统逻辑 CPU 数，所以这个返回值可作并发上限参考 `[经验]`。

## 主问答
**Q（面试官原话）：** `GOMAXPROCS(-1)` 到底做了什么？

1. **传负数的语义**：参数小于 0 时**不会改变**并行执行的 CPU 上限，但函数**仍然返回修改前的值** `[源码]`。
2. **返回值是什么**：未显式设置过时，返回的就是当前默认的逻辑 CPU 个数；实测本机返回 12 `[实测]`。
3. **为什么拿它当资源数**：把信号量的资源数设成逻辑 CPU 数，可以让并发度与机器能力匹配，避免开太多 goroutine 抢占调度 `[经验]`。
4. **官方信号量能加权**：与通道实现的计数信号量不同，它支持一次申请多个资源、支持尝试获取、还能绑定上下文做超时取消 `[源码]`。
5. **用得并不多**：通道写法已经能覆盖大多数限并发场景，官方信号量在日常开发中出现频率很低，但**读开源代码时会遇到**，要认得 `[经验]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Go 1.5 起 | GOMAXPROCS 默认取逻辑 CPU 数 | 说"默认等于 CPU 数" |

## 关键代码
```go
n := runtime.GOMAXPROCS(-1)   // 不改设置，只取当前值；本机返回 12
sem := semaphore.NewWeighted(int64(n))
if err := sem.Acquire(ctx, 1); err != nil {   // 绑定上下文，可超时取消
    return err
}
defer sem.Release(1)          // 归还务必 defer，否则永久占用资源
```
> 验证：`t.Logf("%d %d", runtime.GOMAXPROCS(-1), runtime.NumCPU())` 两次调用均为 12，确认不改值 `[实测]`。

## 总结与追问预判
**-1 是"只读"调用，不是设置调用**。工程上更常见的限并发写法仍是通道或协程池，官方信号量属于"认得即可"的工具。

## ⚠️ 原文纠错
1. 事实核校：原文"传负一获取的是当前逻辑 CPU 个数"准确；补充——严格说是**返回修改前的值**，在未设置的情况下才等于逻辑 CPU 数，两句话不等价 `[源码]`。
2. 补充：原文称官方信号量"几乎用不到"是经验判断，准确说法是**简单限并发用通道更直观**，它价值在加权与上下文取消，读开源项目时会遇到 `[经验]`。
3. 崩坏词归一：源码将信号量、goroutine、逻辑 CPU、上下文等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
