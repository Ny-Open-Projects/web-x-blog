# 187 Linux 进程状态机：运行/就绪/睡眠三子态

> 分类：操作系统 / Linux | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**运行态**/**就绪态**/**睡眠态**/**可中断/不可中断**/**停止态**/**僵尸态**/**单核单进程**

> 原文锚点：第 3~21 段「进程状态分类与转换」

## 一句话总述
Linux 进程状态机核心三态：**运行态**（在 CPU 上执行）、**就绪态**（已准备好等 CPU）、**睡眠态**（等事件暂停、释放 CPU）。睡眠态再细分：**可中断**（可被信号唤醒）、**不可中断**（等 IO/硬件、不被信号打断，保操作原子性）、**停止态**（暂停于内存不被调度）。子进程退出但父未 `wait` 即**僵尸态**。任一 CPU 核同一时刻只跑一个进程/线程。

## 面试官视角
进程状态机是 OS 面试基本功。能画出三态转换、讲清「不可中断态为何不被信号打断」「僵尸怎么产生」的，过关；只背「运行/阻塞」两态的，少了一半细节。

## 主问答
**Q（面试官原话）：** Linux 进程有哪些状态？怎么转换？

1. **运行态**：进程/线程正在 CPU 上执行指令、占用 CPU；任一核同时只跑一个。
2. **就绪态**：已具备运行条件但未分到 CPU，在就绪队列等调度；被选中即转运行态。
3. **睡眠态（等待事件）**：暂时停、释放 CPU，事件（IO 完成/信号/定时器）到来被唤醒转就绪态；含三子态——**可中断**（可被外部信号如 SIGTERM 中断）、**不可中断**（内核关键操作或等硬件如磁盘 IO，不能被信号打断，保数据一致性）、**停止态**（暂停于内存、不被调度，除非手动继续）。
4. **僵尸态**：子进程退出、父进程未调用 `wait`/`waitpid` 回收，残留 task_struct 占资源；父退出后由 `init`（PID 1）收养并回收。
5. **转换主线**：就绪→运行（被调度）、运行→睡眠（等事件）、睡眠→就绪（事件到）、运行→僵尸（退出且父未 wait）。

## 版本与兼容性
| 状态 | 触发 | 是否占 CPU | 信号可中断？ |
|------|------|------------|--------------|
| 运行态 | 被调度上 CPU | 是 | — |
| 就绪态 | 等 CPU | 否 | — |
| 可中断睡眠 | 等事件 | 否 | 是 |
| 不可中断睡眠 | 等 IO/硬件 | 否 | 否 |
| 停止态 | 被暂停 | 否 | 手动继续 |
| 僵尸态 | 退出未回收 | 否 | — |

## 关键代码
```go
// Go 视角：用 os/exec 起一个子进程，观察其生命周期与回收
cmd := exec.Command("sleep", "30")
_ = cmd.Start() // 子进程进入运行态
// 若此处不调用 cmd.Wait()，子进程 30s 后退出会成为僵尸，直到本 Go 进程退出
_ = cmd.Wait()  // 父进程回收子进程，避免僵尸（对应"父未 wait → 僵尸"）
fmt.Println("child reaped")
```

核心：**三态 + 睡眠三子态 + 僵尸；不可中断态保原子、僵尸因父未 wait**。追问拐向「僵尸 vs 孤儿」——备好「孤儿被 init 收养、不浪费资源」（见 `187-zombie-orphan.md`）。
