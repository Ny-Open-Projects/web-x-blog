# 807 Go GC 发展历程（按 STW 时长）

> 分类：Go/运行时 | 难度：L3 | 题型：演进题 | 频率：高 | 关键词：**GC 演进** / **STW** / **混合写屏障** / **里程碑版本**
> 原文锚点：第 2~38 段「STW 定义与延迟影响；1.0 秒级→1.3 分离→1.4 准确式→1.5 三色标记→1.6 状态机→1.7 bitmap→1.8 混合写屏障；里程碑 1.5/1.8」

## 一句话总述
衡量 Go GC 的核心指标是 **STW（Stop The World）时长**。Go GC 从 1.0 的秒级 STW 标记清除，演进到 1.3 标记/清除分离、1.5 并发三色标记（10~40ms）、1.8 混合写屏障（<1ms）——**1.5 解决性能问题、1.8 进入高性能时代**是两个里程碑。

## 面试官视角
- 意图：考察对 Go GC 演进脉络的掌握，常以"Go 的 GC 经历过哪些版本优化"切入。
- P5 能说清 STW 是什么；P6 能列出 1.3/1.5/1.8 三个关键版本及优化点；P7 能讲清每版 STW 下降的原因与写屏障/并发标记的因果。
- 红旗：以为 Go 一直用分代 GC（Go 长期是非分代）；把 1.5 与 1.8 的贡献混为一谈。
- 惊艳点：点出 1.5 是"解决性能问题使 GC 不再成为问题"、1.8 是"毫秒级以内进入高性能时代"的定性差异。

## 主问答
**Q（面试官原话）：** Go 的 GC 是怎么演进的？关键版本有哪些？
**A：**
1. **结论**：Go GC 演进以压低 STW 为主线——1.0/1.1 秒级 STW 标记清除 → 1.3 标记/清除分离（清除并发，降 50~70%）→ 1.4 runtime 用 Go 重写、准确式 GC、写屏障雏形 → **1.5 并发非分代非移动三色标记清除（10~40ms）** → 1.6 状态机协调（5~20ms） → 1.7 并发栈收缩+span bitmap（1~3ms） → **1.8 混合写屏障消除重新扫描（<1ms）**。
2. **机制**：每次优化都围绕"缩短必须暂停用户代码的时间"——把串行扫描改并发、把整堆 STW 改局部 STW、用写屏障保护并发标记的正确性。
3. **边界**：两个里程碑——**1.5 基本解决 GC 性能问题**（生产不再被 GC 卡顿困扰）、**1.8 STW 进入毫秒级以内**（高性能时代）；Go 长期是**非分代、非移动**的三色标记清除 `[经验]`。
