# 1115 API 接口性能优化总览（定位优先 + 8 大方向实战清单）

> 分类：性能优化 / API | 难度：L3 | 题型：方法论题 | 频率：中 | 关键词：**瓶颈优先** / **1090 法则** / **阿姆达尔定律** / **缓存** / **并行** / **异步**
> 原文锚点：第 1~46 段「先定位关键路径再优化(1090法则/阿姆达尔/监控+链路追踪)；8 方向：数据库/缓存/串行改并行/异步化/减少锁粒度/批量获取/服务扩展」

## 一句话总述
API 性能优化**第一步是定位瓶颈再动手**：靠 1090 法则（抓关键 10% 撬动 90% 收益）、阿姆达尔定律（优化关键路径占比大的部分）与监控/链路追踪定位耗时大头；随后从**数据库、缓存、串行改并行、异步化、减少锁粒度、批量获取、服务扩展**等方向下手。

## 面试官视角
- 意图：考察是否懂"先测量后优化"的工程纪律，以及能否系统枚举常见优化杠杆。
- P5 知"先定位再优化"原则与常见方向；P6 知 1090 法则/阿姆达尔、缓存命中率反直觉、并行省时=最慢一次；P7 知各方向的取舍与边界（哪些数据不适合缓存、锁粒度如何细化）。
- 红旗：上来就背"加缓存加索引"却不谈测量；或把"优化清单"讲成零散技巧缺主线。
- 惊艳点：点出"缓存无权限用户反而命中率高"的反直觉案例、以及"定位优先于优化"是全局红线 `[边界]` 见 112-bottleneck-first（瓶颈优先方法论）、1506-observe-tracing（链路追踪定位）、193/1254（缓存模式）、1828（MQ 异步）、925（锁）、136（批量）。

## 主问答
**Q（面试官原话）：** 怎么优化 API 接口的性能？
**A：**
1. **先定位再优化**：用监控指标 + 链路追踪（traceID）找出链路中耗时占比大的关键路径；遵循 1090 法则与阿姆达尔定律，把精力压在瓶颈处，避免无谓优化。
2. **数据库与缓存**：数据库常是瓶颈，先做慢查询治理；缓存缓解 DB 压力，但要算命中率——热点数据放本地缓存减远程调用，强一致或频繁修改的数据不适合缓存。
3. **并行与异步**：无强依赖的多任务（多个 RPC 调用）改并行，总耗时取决于最慢一次；非核心逻辑（发邮件）异步化进消息队列，缩短主请求时长。
4. **锁粒度与批量与扩展**：只锁必要代码、用分段/读写分离细化锁；合并远程调用（IN 语句/mget）减网络往返；资源不足时水平扩展或垂直扩容。

## 关键代码
```go
package main

import (
	"golang.org/x/sync/errgroup"
)

// 串行改并行：多 RPC 无强依赖时并行，总耗时=最慢一次而非总和
func fetchAggregated() error {
	g := new(errgroup.Group)
	var profile, order string
	g.Go(func() error { profile = rpcGetProfile(); return nil })
	g.Go(func() error { order = rpcGetOrder(); return nil })
	return g.Wait() // 任一失败即返回，否则聚合完成
}
```
