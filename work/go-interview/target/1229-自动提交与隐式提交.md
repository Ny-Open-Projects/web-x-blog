# 1229 自动提交与隐式提交

> 分类：MySQL 事务 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**autocommit** / **隐式提交** / **DDL** / **COMMIT**
> 原文锚点：第 16~48 段「自动提交默认开启每句独立事务；DDL/改系统表/再开事务/改 autocommit/锁表/load data/复制语句等会隐式提交；遇错自动回滚」

## 一句话总述
MySQL 默认 `autocommit=ON`，每条语句是一个独立事务；一旦显式开事务或关掉 autocommit，语句不再自动提交，但**很多特殊语句会"悄悄"把当前事务提交了**——这就是隐式提交，面试高频。

## 面试官视角
- 意图：考察候选人对"哪些语句会隐式提交"的实战经验（红旗：以为只有 COMMIT 才提交）。
- P5 知道 autocommit 默认 ON；P6 能列 3~4 类隐式提交；P7 能讲全 7 类并说清 DDL 必提交的原理。
- 红旗：以为 BEGIN 之后只有显式 COMMIT 才提交；在事务里混 DDL 导致前面改动被提前提交。
- 惊艳点：指出"在事务中执行 DDL 会先隐式提交前面所有改动"，是线上事故高发点。

## 主问答
**Q（面试官原话）：** 除了 COMMIT，还有哪些情况会提交事务？
**A：**
1. **结论**：自动提交（`autocommit=ON`，MySQL 8.0 默认，每条语句独立事务）+ 隐式提交（特殊语句悄悄提交）+ 手动 `COMMIT` 三种；隐式提交主要有 DDL、改 mysql 系统库表、事务控制语句再开事务、autocommit OFF→ON、锁表、LOAD DATA、复制语句等。
2. **机制**：`autocommit=OFF` 后多条语句属同一事务，直到 COMMIT/ROLLBACK；但执行 `CREATE/ALTER/DROP` 等 DDL、或 `ALTER USER/CREATE USER/GRANT`、或再次 `START TRANSACTION`、或 `LOCK TABLES`、或 `LOAD DATA` 时，MySQL 会先把当前事务提交掉 `[源码]`。
3. **边界**：原文称"遇到错误事务自动回滚"——更精确的是 InnoDB 对**单条语句**错误做语句级回滚（savepoint），仅死锁/锁等待超时等才回滚整个事务，应用仍须显式 `ROLLBACK` `[经验]`。

## 关键代码
```sql
-- 事务里穿插 DDL，会先隐式提交前面的 UPDATE
BEGIN;
UPDATE accounts SET balance=balance-100 WHERE id=1;  -- 尚未提交
CREATE TABLE audit_log(id INT);   -- 触发隐式提交：上面的 UPDATE 已落库
-- 此时 ROLLBACK 只能回滚 CREATE 之后的改动，前面的 UPDATE 无法撤销
```
