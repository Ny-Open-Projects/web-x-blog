# 1118 闭包捕获与 goroutine 的逃逸细节

> 分类：内存与 GC | 难度：L3 | 题型：工程题 | 频率：中 | 关键词：**闭包捕获** / **变量按引用** / **goroutine 逃逸**
> 原文锚点：第 55~109 段「goroutine 里使用的变量发生逃逸、变量捕获 assign=true」

## 一句话总述
闭包（尤其传给 goroutine）捕获的变量按引用持有，生命周期超出定义函数，故必然逃逸到堆；`-m -m` 会标出 captured 与 assign=true，提醒注意闭包内外共享同一地址。

## 面试官视角
- 意图：是否理解闭包捕获的逃逸机理及并发下的坑。
- P5 知 goroutine 内变量逃逸 / P6 懂按引用捕获 / P7 知 assign=true 与并发读写陷阱。
- 红旗：以为闭包里改的是局部副本；以为所有局部变量都逃逸。
- 惊艳点：`-m -m` 输出 assign=true 表示变量按地址被闭包捕获，goroutine 调度到时读到的是外部最新值 —— 验证 `go build -gcflags="-m -m" main.go` `[实测]`。

## 主问答
**Q（面试官原话）：** 为什么 goroutine 里的变量会逃逸？闭包捕获要注意什么？
**A：**
1. **结论**：goroutine 异步执行，闭包捕获的变量生命周期超出原函数，编译器只能把它放堆。
2. **机制**：被捕获变量按地址共享（assign=true），闭包内外读写同一块内存；`-m -m` 可看到 captured 标记。
3. **边界**：仅闭包内部声明、作用域未超出的局部变量不逃逸；真正逃逸的是"被捕获且存活超出函数"的变量。
**加分层：** 闭包共享变量易出 data race，必要时用局部副本或显式传参，避免 goroutine 读到意外值。
