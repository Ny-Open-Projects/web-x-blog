# 1519 Pod 健康检查：三探针三方式

> 分类：K8s / Pod 进阶 | 难度：L1~L2 | 题型：机制题 | 频率：高 | 关键词：**liveness**/**readiness**/**startup**/**HTTP 探针**/**自愈**

> 原文锚点：第 1~17 段「存活/就绪/启动三种探测…HTTP/TCP/执行三种方式…状态码 200~399 健康…失败重启或摘除」

## 一句话总述
三探针各管一件事：**liveness 管生死**（失败 → 重启容器，故障自愈）；**readiness 管流量**（失败 → 从 Service 负载均衡摘除，恢复后自动加回，不重启）；**startup 管启动保护**（成功前屏蔽前两者，护住慢启动应用）。三方式共用：**httpGet**（状态码 200~399 为健康）、**tcpSocket**（端口能连即健康）、**exec**（命令退出码 0 为健康）。

## 面试官视角
- 意图：Pod 自愈机制是 K8s「声明式+控制循环」的核心体现——考是否真配过、真排过_probe 误杀_。
- 分档：P5 报全三探针三方式；P6 说清 liveness 与 readiness 的动作差异（重启 vs 摘流量）；P7 能讲 startup 保护的必要性、探针参数调优与误杀排查。
- 红旗答案：说「readiness 失败会重启容器」；不知道 404 也算失败（只认 2xx~3xx）。
- 惊艳点：点破 exec 探针的坑——命令不存在报 **unknown 不计失败**，与「返回非零=失败」是两条路径；liveness 配错路径会造成重启风暴 [经验]。

## 主问答
**Q（面试官原话）：** 简述 K8s 中 Pod 的健康检查方式？

**A：**
1. **liveness 存活探针**：定期 HTTP GET / TCP 连 / 执行命令；失败到阈值（默认连续 3 次）→ **kubelet 重启容器**——死锁、死循环等「活着但不干活」的自愈手段 [实测]。
2. **readiness 就绪探针**：方式相同；失败 → 容器**从 Service endpoints 摘除**，流量不进来，恢复后自动加回——**不重启**，用于「还在初始化/临时过载」场景。
3. **startup 启动探针**：仅在启动阶段执行；成功前，liveness/readiness 都不生效——护住启动慢的应用（如 JVM 预热），避免被 liveness 误杀。
4. **三方式判定**：httpGet 状态码 200~399 健康（404/500 即失败）；tcpSocket 端口连通即健康（不验内容）；exec 退出码 0 健康。
5. **配置要点**：initialDelaySeconds（启动缓冲）、periodSeconds（周期）、failureThreshold（失败阈值）；每个容器可独立定义。

## 关键代码
[实测] k3d 集群（nginx:alpine）：`probe-ok` 探 `/`（200）与 `probe-bad` 探 `/notfound`（404），均 `initialDelay=3s, period=3s`——35 秒后 probe-ok `Running 0 restarts`，probe-bad **`Running 2 (11s ago) restarts`**：404 计入失败，连续 3 次失败即重启容器，自愈实证。

```python
# 探针配置速查：三探针 × 三方式 的 YAML 骨架生成器
def probe(kind, method, **kw):
    """kind: liveness|readiness|startup; method: http|tcp|exec"""
    base = {"initialDelaySeconds": kw.get("delay", 3),
            "periodSeconds": kw.get("period", 3)}
    if method == "http":
        base["httpGet"] = {"path": kw["path"], "port": kw.get("port", 80)}
    elif method == "tcp":
        base["tcpSocket"] = {"port": kw["port"]}
    else:
        base["exec"] = {"command": kw["cmd"]}
    return {kind + "Probe": base}

print(probe("liveness", "http", path="/healthz"))
# → {'livenessProbe': {'initialDelaySeconds': 3, 'periodSeconds': 3,
#     'httpGet': {'path': '/healthz', 'port': 80}}}
```

[实测] 生成骨架可直接嵌入 container spec；健康判定：http 2xx~3xx、tcp 连通、exec 退出码 0。

## ⚠️ 原文纠错
1. 术语核校： [经验] 原文「pok八s」「它八s」等音转混用指 K8s/kubelet，本卡统一为规范术语，不列举原词。
2. 事实核校： [经验] 原文「存活探针失败会重启这个 pod」不准确——动作对象是**容器**（kubelet 按重启策略在原节点重启容器），Pod 对象不重建；readiness 同理是摘 endpoints 而非重启。
3. 补充核校： [经验] exec 方式「命令返回非零=失败」要补一句：命令**不存在**时探针报 unknown（错误路径），不计入失败阈值 [实测]——最小镜像（如 pause）里无常用命令，探针会一直 unknown 而不触发重启。
