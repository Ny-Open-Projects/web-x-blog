# 1313 ES 部署 OS 配置（三）：网络、安全与 JVM 堆

> 分类：搜索 / Elasticsearch | 难度：L3 | 题型：运维题 | 频率：中 | 关键词：**somaxconn**/**tcp_keepalive**/**JVM堆**/**压缩指针**/**Xms/Xmx**
> 原文锚点：第 40~57 段「TCP keepalive + 最大连接 + 安全 + JVM 堆内存」

## 一句话总述
剩余四项：① 调小 `net.ipv4.tcp_keepalive_time` 更快探测死连接；② 调大 `net.core.somaxconn` 提升并发连接；③ 安全（防火墙限访问、启用基础认证与通信加密）；④ JVM 堆设 `Xms=Xmx`、约为总内存 50% 且 ≤32G（≤31G 开启压缩指针），留足 OS 内存做文件系统缓存以加速搜索。

## 面试官视角
- 考察意图：是否覆盖网络、安全与最关键的 JVM 堆配置（堆过大反而因压缩指针失效而变慢）。
- 分档：P5 知 JVM 堆要设；P6 知 Xms=Xmx、50% 总内存；P7 知 ≤31G 压缩指针、留 OS 缓存、somaxconn/tcp_keepalive 调法。
- 红旗答案：把堆设到总内存 80% 甚至超过 32G（压缩指针失效、GC 更重）；或不留 OS 缓存。
- 惊艳点：点出「标准配置：64G 总内存 → 32G 堆，剩余给 OS 文件系统缓存缓存段文件，搜索性能更好」。

## 主问答
**Q（面试官原话）：** ES 部署还要调哪些网络、安全和 JVM 配置？
**A：**
1. **TCP keepalive**：`net.ipv4.tcp_keepalive_time` 控制空闲连接多久后才发探测包；长连接应用可调小，更快发现对端已断，避免挂死连接。
2. **最大连接（somaxconn）**：`net.core.somaxconn` 控制内核允许的 TCP 全连接队列上限；协调节点/数据节点处理大量并发连接时应调大，提升并发吞吐。
3. **安全配置**：用防火墙限制访问来源；启用 ES 安全功能（基础认证、TLS 加密通信）防止未授权访问与嗅探。
4. **JVM 堆（最关键）**：编辑 jvm.options 设 `Xms=Xmx`（避免运行时伸缩）；推荐总内存 50% 且 ≤32G；**≤31G 才开启压缩指针**（堆利用率更高），故多数场景设 31G；必须给 OS 留内存做文件系统缓存（缓存 Lucene 段文件），否则搜索变慢。标准：64G 总内存→32G 堆。
