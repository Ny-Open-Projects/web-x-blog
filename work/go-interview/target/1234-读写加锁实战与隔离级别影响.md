# 1234 读写加锁实战与隔离级别影响

> 分类：MySQL 锁 | 难度：高 | 题型：综合 | 频率：高 | 关键词：**读锁汇总、写锁汇总、RR/RC、实操建议、死锁**

> 原文锚点：第 1~104 段「MySQL 加锁语句全景」

## 一句话总述
加锁可汇总为：读——普通 SELECT 走一致性读无锁，FOR UPDATE 加 X、FOR SHARE/LOCK IN SHARE MODE 加 S；写——UPDATE/DELETE/ 显式加锁均加 X。行锁在引擎层、S 兼容 S、X 不兼容任何；RR 下还有间隙锁与 next-key 锁防幻读，RC 无间隙。合理选隔离级别与索引是降低锁冲突的关键。

## 面试官视角
这是加锁体系的收口题。考官期待你一张表讲清「什么语句加什么锁」，并指出隔离级别如何改变锁粒度。能结合「走索引才能精准锁行、否则锁全表」的人，是实战派。

## 主问答
**Q（面试官原话）：** 把 MySQL 各种读写操作的加锁情况总结一下。

1. **读操作**：普通 SELECT = 一致性读、无锁（RC/RR 均走 MVCC）；`FOR UPDATE` = X 锁；`FOR SHARE`/`LOCK IN SHARE MODE` = S 锁。
2. **写操作**：UPDATE / DELETE 自动对涉及行加 X 锁（定位后加记录锁，RR 下可能带间隙/next-key）；INSERT 加插入意向锁 + 表级自增锁（若有自增列）。
3. **隔离级别影响**：RR 下默认 next-key 锁（含间隙锁）防幻读；RC 退化为记录锁、无间隙锁；这直接决定并发插入是否会被阻塞。
4. **实操建议**：尽量走索引（否则行锁退化为表级锁范围）、短事务、避免长事务持锁；高并发写入评估 RC 以减少间隙争用。

## 总结与追问预判
核心：**读看一致性/锁定二分、写全加 X；RR 有间隙、RC 无；走索引才能精准锁行**。追问常要排查死锁，备好「next-key 间隙重叠 + 加锁顺序相反」成因。
