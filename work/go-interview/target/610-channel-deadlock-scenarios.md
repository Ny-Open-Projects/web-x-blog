# 610 channel 死锁场景全解

> 分类：Go 并发 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**deadlock**/**永久挂起**/**select**
> 原文锚点：第 27~97 段「只写不读/只读不写/同协程收发/双向互等/永久阻塞协程」

## 一句话总述
channel 死锁本质是"所有相关 goroutine 都在等对方、无人推进"；典型有只写不读、只读不写、同协程自锁、双向互等；有"永久阻塞协程"时不会触发 deadlock panic 但程序永久挂起。

## 面试官视角
- 考察意图：能否把死锁归因为"等待环 + 无推进者"，并区分真死锁与永久挂起。
- 分档：P5 知同协程收发会死锁；P6 懂只写/只读/互等；P7 能区分 fatal deadlock 与 hang。
- 红旗答案："有缓冲就不会死锁"；分不清 deadlock panic 与 hang。
- 惊艳点：**deadlock 检测器只在"所有 goroutine 都阻塞"时 fatal**；若有一个 goroutine 在空转/永久阻塞于别处，其余卡在 channel 上是**永久挂起(hang)**而非 panic `[源码]`。

## 主问答
**Q（面试官原话）：** 什么情况下 channel 会死锁？
**A：**
1. **结论**：死锁 = 参与通信的 goroutine 全部阻塞在 channel 上、无人能推进；常见四类：只写不读、只读不写、同一协程先收后发（自锁）、两 channel 互相先读后写（互等）。
2. **机制**：无缓冲需双方同时就绪，任一方缺位就永久阻塞；有缓冲若"先读无数据/满后继续写"同样阻塞。**有缓冲不能消除互等读导致的死锁**——f14 两个有缓冲 channel 都先读，仍死锁 `[源码]`。
3. **边界**：若存在一个"永久阻塞协程"（如 `for{}` 不在 channel 上），运行时不报 deadlock panic，但程序**永久挂起(hang)**，需靠其他 goroutine 退出才结束——原文"不会发生死锁"应精确为"不触发 panic，但实际 hang"。

**加分层：** 用 `context`/超时/`select + default` 可主动打破阻塞，避免不可逆死锁。

## 关键代码
```go
// 互等死锁：两有缓冲 channel 都先读
go func() { <-chA; chB <- 1 }()
<-chB; chA <- 1 // 双方都在等读，无人先写 → deadlock
// 破法：任一侧用 select{ case <-ch: default: } 或加超时
```

## 总结与追问预判
死锁=等待环无推进；有缓冲不豁免互等读；区分 deadlock panic 与 hang。追问接"channel 底层 hchan 结构"。
