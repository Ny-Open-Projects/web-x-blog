## 思路与架构
```text
Go 调度器负载均衡的两层结构：
- 本地 runq（每 P 一个，无锁，容量 256）：M 优先消费自己 P 的本地 G。
- 全局 runq（有锁）：本地空时取一批；溢出（>256）或 netpoll/GC/sleep 唤醒的 G 直接入全局。
- 窃取路径：本地空 -> 取全局一批 -> 全局空 -> 偷其他 P 本地约一半。
- 对照范式：工作共享（繁忙方推）vs 工作窃取（空闲方拉），Go 选窃取因低频低耗。
```

## 方案取舍
```text
- 为何本地队列无锁：M 独占本 P runq，避免每 G 全局锁（Go 1.1 前旧模型的瓶颈）。
- 为何偷一半而非全部：再平衡同时不过度抽空受害者，减少后续再偷次数。
- 为何选窃取不选共享：高并发 CPU 高负载下"繁忙方让出"更频繁，若每次都主动迁移判断开销大；窃取仅在空闲触发，加锁窗口小。
- 全局队列定位：兜底（溢出+特殊 G），不是主消费路径，降低锁竞争频率。
```

## 答题技巧
```text
- 被问"工作窃取"：先画"本地->全局->偷其他P一半"三级链，再点 runq 容量 256。
- 被问"窃取 vs 共享"：对仗"推(被动)/拉(主动)"，补 Go 选窃取的低频低耗理由。
- 必点观测：GODEBUG=schedtrace=1000 看每 P runq 长度再平衡。
- 收尾落细节：netpoll/GC/sleep 的 G 直接进全局，解释"本地未满全局却多"。
```
