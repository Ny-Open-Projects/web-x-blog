# 1831 磁盘调度算法：七族全景

> 分类：操作系统 / 存储 | 难度：L2 | 题型：原理题 | 频率：中 | 关键词：**FCFS**/**SSTF**/**SCAN 电梯**/**C-SCAN**/**LOOK/C-LOOK**/**饥饿**

> 原文锚点：第 2~13 段「FCFS → SSTF → SCAN → C-SCAN → N-Step → LOOK/C-LOOK」

## 一句话总述
磁盘调度算法决定磁头响应读写请求的顺序，目标是**缩短寻道时间**：**FCFS**（公平但寻道最长）→ **SSTF**（贪心找最近，快但有饥饿）→ **SCAN/电梯**（单向扫到边界再回头，无饥饿）→ **C-SCAN**（到边界立即跳回另一端，等待更均匀）→ **N-Step/C-N-Step**（请求分批防新请求插队）→ **LOOK/C-LOOK**（SCAN 的改良，到最近请求即折返不走到边界）。[实测] 经典队列：FCFS 640、SSTF 236、SCAN 331。

## 面试官视角
这题考的是**算法族的演进逻辑**：每代算法修上一代的一个病——FCFS 慢、SSTF 饿死远处请求、SCAN 走到边界浪费、C-SCAN 回程不服务。能把「病→药」的链讲清比背八种名字强；[实测] 数字（640 vs 236 vs 331）一出口，说明真算过。SSD 语境是现代追问：机械盘调度算法在 SSD 上基本失效（无寻道），答出这一点是时代意识的信号。

## 主问答
**Q（面试官原话）：** 磁盘调度算法有哪些？

1. **FCFS（先来先服务）**：按请求到达顺序服务——公平、实现最简，但磁头来回乱跳，寻道最长。[实测] 经典队列（磁头 53，请求 98/183/37/122/14/124/65/67）：总寻道 **640** 磁道。
2. **SSTF（最短寻道优先）**：每次选离当前磁头最近的请求——平均寻道最短；**远端请求可能饥饿**。[实测] 同队列总寻道 **236**，比 FCFS 省 404 磁道，序列 65→67→37→14→98→122→124→183。
3. **SCAN（电梯算法）**：磁头单向扫，服务沿途所有请求，**到磁盘边界**才反向——像电梯，无饥饿。[实测] 向大端扫描总寻道 **331**。
4. **C-SCAN（循环扫描）**：到边界后**立即跳回**另一端再扫——回程不服务，各磁道等待时间更均匀（把「刚扫过」与「快扫到」的等待差拉平）。
5. **N-Step-SCAN / C-N-Step**：请求队列切成长度 N 的子队列，按 FCFS 轮次处理子队列、队内用 SCAN——**新请求只能进新队列**，防大量新请求插队饿死老请求（解决 SSTF/SCAN 对中部磁道的偏置）。
6. **LOOK / C-LOOK**：SCAN/C-SCAN 的改良——**移到该方向最后一个请求处即折返**，不真走到磁盘边界，省掉无请求区的空跑。
7. **选型逻辑**：响应优先 → SSTF（小队列）；公平无饥饿 → SCAN/C-SCAN；防插队 → N-Step；工程默认 → LOOK 族。**SSD 时代**：无机械寻道，这些算法在块层基本退化为简单合并——「调度算法是机械盘的遗产」是必答的现代边界。

## 关键代码
```go
// SSTF: 每次选离磁头最近的请求 ([实测] 640->236)
func sstf(head int, q []int) (int, []int) {
	remaining := append([]int(nil), q...)
	total, seq := 0, []int{}
	for len(remaining) > 0 {
		best, bi := 1<<30, -1
		for i, t := range remaining {
			if d := abs(head - t); d < best {
				best, bi = d, i
			}
		}
		total += best
		head = remaining[bi]
		seq = append(seq, head)
		remaining = append(remaining[:bi], remaining[bi+1:]...)
	}
	return total, seq
}
```

[实测] 磁头 53、队列 98/183/37/122/14/124/65/67：FCFS=640、SSTF=236（序列 65→67→37→14→98→122→124→183）、SCAN 向大端=331。

## 总结与追问预判
核心：**FCFS 基线 → SSTF 贪心但饥饿 → SCAN 电梯无饥饿 → C-SCAN 均匀等待 → N-Step 防插队 → LOOK 省空跑；[实测] 640/236/331**。追问常拐向「SSD 还需要吗」与「Linux 实际用什么」——Linux 块层调度器（cfq/bfq/kyber/none）是同一思想的现代演化；电梯思想与 IO 排查的衔接见 1811.md`、存储硬件底座见 1818.md`，N-Step/C-LOOK 细节见 1831.md`。

## ⚠️ 原文纠错
1. 术语核校： [经验] 原文「loke/clock/c 磁干算法」=LOOK/C-LOOK/C-SCAN（音转）；「层盘调度」=磁盘调度；已归一。
2. 事实核校： [经验] 原文说 C-SCAN「可以提高更均匀的等待时间」正确，但未讲**为什么**——回程不服务使「刚被扫过的磁道」与「即将被扫的磁道」等待差距收敛到一轮扫描周期，均匀性来自「单向服务」；补上因果才算答透。
