# 1817·深 提权模型的两条轴：认证归属与环境归属

> 分类：操作系统 / Linux | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**提权**/**认证归属**/**登录 shell**/**sudoers**/**最小权限**/**审计**/**visudo**
> 原文锚点：第 5~31 段「su 切换用户的时候，它会保留当前用户的环境变量，也就是只切换用户的身份，而不会去切换用户的登录环境…sudo -i 还需要输入当前用户的密码，注意它是我们当前这个登录的用户的密码…它有一个前提，就是我们当前这个用户在 /etc/sudoers 这个文件里面有进行配置…sudo -i 它可以记录我们使用 sudo 执行的所有命令，以便在需要的时候进行审计」
> [边界] 本文是 `1817-su-sudo-variants` 的深挖，主卡已讲的四命令对照此处不重述；文件描述符与重定向见 `1813-fd-stdin-out-err`，进程与后台执行见 `187-process-states`。

## 思路与架构

把四个命令抽象掉，剩下的其实是**两个正交的判断题**：

```text
轴一：认证归属 —— 你要证明"你是谁"？
────────────────────────────────────────
su / su -       → 证明你是【目标用户】 → 需要目标用户（通常是 root）的密码
                  代价：root 密码必须在多人之间散播，泄露即全盘失守

sudo -i / -s    → 证明你是【你自己】   → 输入当前用户自己的密码
                  授权判定在服务端：查 /etc/sudoers 或用户所属组
                  收益：**root 密码无需散播**；撤销单人权限不影响他人

轴二：环境归属 —— 切过去之后，环境变量是谁的？
────────────────────────────────────────
不带横杠（su / sudo -s） → 保留【原用户】环境
                          只有 euid 变了，PATH/HOME/JAVA_HOME 全是旧的

带横杠（su - / sudo -i） → 加载【目标用户】登录环境
                          底层是启动 login shell，读取 /etc/profile 与 ~/.profile
```

关键的三个推论：

1. **为什么"只切身份不切环境"会出问题**：`PATH` 还是原用户的，于是**新装的运维工具找不到**、**`JAVA_HOME` 指向错误版本**、甚至**执行到原用户可写的同名恶意程序**。这就是"横杠不是可选项"的原因。
2. **为什么 `sudo` 的模型更安全**：认证对象从"共享密钥（root 密码）"变成"**个人凭证 + 集中授权表**"。撤销权限只需动 sudoers 一行，**不需要改 root 密码**——后者意味着通知所有人并重新分发。
3. **为什么审计能力是决定性的**：`su` 之后 shell 里发生什么，日志里只有"某人 su 成了 root"；而 **`sudo` 会把每条执行的命令记下来**。出事后能不能复盘到"谁在什么时候跑了 `rm -rf`"，全靠这条。

## 方案取舍

```text
该用哪个？决策树
────────────────────────────────
需要完整 root 工作环境（跑一堆运维命令）
    └─ sudo -i     （加载环境 + 可审计）

只需临时跑一两条特权命令
    └─ sudo <cmd>  （连 shell 都不开，最小权限）

系统锁了 root 密码（Ubuntu / Debian 默认）
    └─ 只能 sudo，su 直接失败

要切到【非 root】的某个服务账号（如 nginx、postgres）
    └─ sudo -u nginx -i   （-u 指定目标用户）

调试时怀疑环境不对
    └─ 先 echo $PATH / $HOME 确认，再决定要不要补横杠
```

- **`su` 的取舍**：换来**直白**，付出**root 密码散播**与**零审计**。生产环境基本已被 `sudo` 取代。
- **`sudo -s` 的取舍**：换来**轻量**（不开登录 shell、快），付出**环境是旧的**——适合"我就想用 root 权限跑一条我自己 PATH 里的命令"，不适合"我要进 root 的完整环境干活"。
- **`sudo -i` 的取舍**：换来**环境正确 + 可审计**，付出**多加载一轮 profile（略慢）**。生产环境**默认推荐**。
- **授权配置的取舍**：`/etc/sudoers` 是**0440 root 只读**，直接 `vim` 改会破坏权限、且语法错误会**让你永久失去 sudo**（必须进救援模式）。**一律用 `visudo`**——它会在保存前做语法校验。

## 答题技巧

- **开口就给两条轴**：「认证归属 + 环境归属」。先立框架再填四个命令，结构立刻比背命令清晰一个量级。
- **把"横杠 = 换环境"说成口号**：这句最好记，也最容易在紧张时救场。
- **用实测反证**：`sh -c` 读不到 `.profile`、`sh -lc` 能读到（实测 `MYENV=[]` vs `MYENV=[from-profile]`）——**这就是横杠的底层机制**，说出来就是在讲原理而不是背命令。
- **主动补安全视角**：`sudo` 的真正价值不是"少打一个字"，而是**"个人凭证 + 集中授权 + 可审计"**三件套，这个角度能直接拉到 P7。
- **别踩的坑**：① 别说"sudo 要输 root 密码"；② 别以为 `su` 和 `sudo` 能随便互换——**root 密码被锁的系统上 `su` 直接失败**；③ 别忘了提 `visudo`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Linux 全发行版 | 两轴语义一致 | 通用答案 |
| Ubuntu / Debian | **默认锁 root 密码** | 只能用 `sudo` |
| RHEL / CentOS 系 | root 密码可用，授权组常为 `wheel` | 两者皆可 |
| 实测 macOS | 授权组名为 **`admin`** | 组名随平台而异 [实测] |
| 实测 `/etc/sudoers` | 权限 **0440**（`-r--r-----`） | 必须 `visudo` [实测] |
| sudo 1.9.x | 日志与审计能力完备 | `sudo -i` 便于复盘 [实测] |
