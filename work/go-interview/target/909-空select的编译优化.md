# 909 空 select 的编译优化：永久挂起协程

> 分类：Go/并发 | 难度：L2 | 题型：原理题 | 频率：中 | 关键词：**空select**/**block调用**/**挂起协程**/**让出CPU**/**永久阻塞**
> 原文锚点：第 24~26 段「空 select 被编译成 block 函数调用、直接挂起当前协程让出 CPU、永久阻塞用空 select 而非死循环」

## 一句话总述
想让当前协程**永久阻塞 / 让出 CPU**，应写**空 `select{}`** 而非 `for {}` 死循环——编译器会把空 select 优化成 `block` 运行时调用，直接挂起当前协程、不占 CPU；而 `for {}` 空转会持续消耗 CPU。

## 面试官视角
- 考察意图：能否说出空 select 的编译优化及其与死循环的本质区别。
- 分档：P5 知空 select 会阻塞；P6 能说编译成 block、让出 CPU；P7 知与 `for{}` 的 CPU 占用差异、main 协程用空 select 等。
- 红旗答案：用 `for {}` 做永久阻塞（空转耗 CPU）；不知道空 select 被特殊优化。
- 惊艳点：点出「空 select 编译期转 `block` 调用、挂起让出 CPU，是 Go 惯用的永久等待写法」 [经验]。

## 主问答
**Q（面试官原话）：** 怎么让协程永久阻塞又不占 CPU？
**A：**
1. **空 select 优化**：编译器把空 `select{}` 转成运行时 `block` 调用，直接挂起当前协程 [经验]。
2. **让出 CPU**：挂起后协程不占用 CPU，等待被唤醒（如其他协程结束/通道事件）——区别于忙等 [经验]。
3. **别用死循环**：`for {}` 空转会持续占满一个 CPU 核，永久等待应写 `select{}` 而非 `for {}` [经验]。

## 关键代码

```go
// 永久阻塞当前协程且不占 CPU：用空 select（编译期转 block 调用）
func main() {
    go worker()
    select {} // 永久等待；编译优化为挂起，不空转
}
// 反例：for {} 空转会持续占满一个 CPU 核，绝不用于永久等待
// func main() { for {} } // 错误写法

// 也常用于「等一个永远不发生的信号」来挂起 goroutine
func parkForever() {
    select {} // 挂起让出 CPU，直到进程退出
}
```

## 总结与追问预判
空 `select{}` 是 Go 里「永久等待」的惯用法（如 `main` 协程等子协程）。核心考点是「编译优化 + 不空转」，区别于忙等。
