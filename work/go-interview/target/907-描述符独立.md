# 907 描述符独立：共享底层，各记各的长度

> 分类：Go 语言 | 难度：L3 | 题型：原理题 | 频率：中高 | 关键词：**描述符、len、cap、共享底层数组、互不影响**

> 原文锚点：第 76~80 段「slice2 的长度或容量改变并不会影响 slice1 的直接部分」

## 一句话总述
两个切片共享同一块底层数组，但它们各自的**描述符是独立的**：一方长度或容量的变化不会影响另一方描述符里的记录。

## 面试官视角
P6 会混淆"共享底层数组"与"共享描述符"；P7 要划清这条线：赋值拷贝的是描述符，从此两份描述符各自演进，只有它们指向的那块内存是共用的 `[经验]`。加分点：这也解释了为什么 append 到不同容量表现不同——容量够就在共用内存上写（会互相看见），容量不够就换一块新内存（从此分道扬镳）`[源码]`。

## 主问答
**Q（面试官原话）：** 一个切片的长度变了，另一个会跟着变吗？

1. **描述符是副本**：赋值把描述符整体拷了一份，两份从此独立 `[源码]`。
2. **指针相同**：副本里的指针指向同一块底层数组，所以元素改动互相可见 `[经验]`。
3. **长度容量各记各的**：改一方的长度或容量不会影响另一方的描述符 `[实测]`。
4. **分道扬镳的时机**：一旦某方扩容换了底层数组，指针也就不一样了，此后彻底独立 `[源码]`。

## 关键代码
```go
s1 := []int{1, 2, 3}
s2 := s1            // 拷贝描述符，指针相同
s2 = s2[:1]         // 只改 s2 的描述符
fmt.Println(len(s1), len(s2)) // 3 1，互不影响
s2 = append(s2, 9)  // 容量够，写进共用内存，s1[1] 被改成 9
```
> 验证：len 分别为 3 与 1；append 后 s1 的第 2 个元素变为 9 `[实测]`。

## 总结与追问预判
**共用的是内存，独立的是记录**。这条分界是切片所有"改了/没改"类问题的统一解法。
