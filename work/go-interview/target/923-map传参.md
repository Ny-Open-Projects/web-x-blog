# 923 map 传参：直接部分拷贝

> 分类：Go 语言基础 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**map 传参**/**hmap 共享**/**重新赋值**
> 原文锚点：第 75~92 段「map 的传参…重新赋值后修改不影响外层」

## 一句话总述
map 传参同样拷贝 **map header（直接部分）**，底层 hmap（间接部分）被共享；因此**函数内改键值会反映到外层**，但**函数内对参数重新赋值**只改变函数内 header 指向，不影响外层 map。

## 面试官视角
- 考察意图：能否把"map 传参"和"切片传参"归到同一个"直接部分/间接部分"模型下，而非当成两种规则。
- 分档：P5 知 map 传参能改内容；P6 知重新赋值不影响外层；P7 能讲清 header 拷贝 + hmap 共享。
- 红旗答案：说"map 是引用传递所以一定能改"——掩盖了"重新赋值不影响外层"的边界。
- 惊艳点：点出 **map 和切片共享同一套传参模型**，差异只在"map 没有扩容换地址"（见 923）`[经验]`。

## 主问答
**Q（面试官原话）：** map 当参数传进去，函数里改了外面看得见吗？
**A：**
1. **结论**：看得见——前提"通过 key 改/增键值"；若是"对参数重新赋值一个新 map"，则只影响函数内自己。
2. **机制**：map 本质是 `*hmap` 指针的 header，传参拷贝 header，双方指向同一个 hmap。下标赋值 `m[k]=v` 改的是共享 hmap，外层自然变；`m = make(map...)` 是把函数内 header 换成新 hmap，外层不受影响。
3. **边界**：与切片完全一致的逻辑——"改间接部分内容共享、改直接部分本身不共享"，只是 map 没有 append 那种"扩容换地址"的例外。

**加分层：** 验证同样可打印参数与外层 map 的底层地址（如 `fmt.Printf("%p", m)` 在不同 Go 版本行为不同，更稳的是观察键值变更是否互见）。

## 关键代码
```go
func modify(m map[int]int) {
    m[1] = 5        // 改共享 hmap → 外层能看到
    m = map[int]int{9: 9} // 只改函数内 header 指向 → 外层不变
}
func main() {
    a := map[int]int{1: 1}
    modify(a)
    fmt.Println(a) // map[1:5]：改键值生效，重赋值不生效
}
```

## 总结与追问预判
map 传参与切片同一模型：改内容共享、改参数不共享。差异仅在 map 无扩容换地址。追问接"map 新增键值为何必反映"与"直接/间接部分模型"。

## ⚠️ 原文纠错
1. 机翻崩坏词归一：`mam`/`m`→**map**；`me`→**main**；`poygram`/`pilram`/`patram`→**parameter（参数）**；`构`→**Go**；`普mam`→**map m**。事实演示正确，仅术语崩坏，本卡已归一 `[经验]`。
2. 原文"map 的传参和切片一样，也是直接部分的拷贝"——准确，本卡据此将切片与 map 归一到同一传参模型。
