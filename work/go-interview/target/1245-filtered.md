# 1245 EXPLAIN 的 filtered 列：过滤性怎么读

> 分类：MySQL 调优 | 难度：中高 | 题型：原理 | 频率：中 | 关键词：**filtered、过滤百分比、预估、驱动表、被驱动表查询次数**

> 原文锚点：第 32~44 段「filtered 定义、越大过滤性越好、99630×10%≈9963 次、覆盖索引下 100%」

## 一句话总述
`filtered` 表示「经查询条件过滤后剩余的记录数」占「通过 type 方式扫描到的记录数」的**百分比**（预估值）。**值越大说明索引过滤性越好**；值很小说明扫描了大量无效行。连接查询中还可用来估算被驱动表的访问次数：驱动表 rows × filtered ≈ 被驱动表被查询的次数（如 99630 × 10% ≈ 9963 次）。

## 面试官视角
filtered 是进阶列。考官看你能不能讲清两点：① 它是「百分比、预估」，越大越好；② 驱动表 rows×filtered 可估算被驱动表访问次数，这是判断 join 成本的关键。能补「filtered 不是核心指标，重点仍看 type/key/rows」体现主次分明。

## 主问答
**Q（面试官原话）：** EXPLAIN 的 filtered 是什么意思？高低说明什么？

1. **定义**：filtered = 经条件过滤后剩余记录行数 / 通过 type 扫描的记录行数，是**预估值**。
2. **高低含义**：值**越大**表示索引过滤性越好（扫描即命中）；值**越小**说明过滤性差、存在大量无效扫描，往往提示需要为字段增加合适的索引。
3. **join 估算**：驱动表 rows × filtered ≈ 被驱动表被执行的查询次数（例：99630 × 10% ≈ 9963 次）。
4. **主次**：filtered 不是性能核心指标，判断查询好坏应优先看 **type、key、rows**，filtered 作辅助。
