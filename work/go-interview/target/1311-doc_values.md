# 1311 doc_values：排序与聚合的入场券

> 分类：Elasticsearch | 难度：L3 | 题型：原理题 | 频率：中高 | 关键词：**doc_values、fielddata、列式存储、堆内存、压缩指针**

> 原文锚点：第 77~86 段「ID 的 doc_values 是 false…不能排序…存在磁盘上」

## 一句话总述
排序与聚合要按**文档到值**的方向取值，依赖建索引时就落盘的列式结构 doc_values；字段没开它、又走了禁用态的堆内结构，排序会直接报错。

## 面试官视角
P6 说"加个排序就行了"；P7 要区分两条路径：doc_values 是**列式、落磁盘、建索引时生成**，靠操作系统缓存加速；fielddata 是**运行时在堆里反向构建**，`text` 类型默认关闭，一开就吃堆 `[经验]`。再补一句量化约束：堆一般不超过 30 多 GB，否则对象指针压缩失效、可用内存反而下降 `[源码]`。

## 主问答
**Q（面试官原话）：** 按某个字段排序报字段数据被禁用，根因是什么？

1. **方向反了**：倒排索引是"值到文档"，排序聚合要"文档到值"，必须另有一份列式结构，即 doc_values `[经验]`。
2. **落盘而非进堆**：它在建索引时随段写入磁盘，常驻操作系统缓存，不占堆；这是它能默认开启的前提 `[源码]`。
3. **禁用态的替补**：`text` 字段默认没有列式结构，只能运行时在堆里反转倒排表构建，成本高所以默认关，一碰就报错 `[实测]`。
4. **解法是改映射**：重建索引、把字段设为带列式结构的类型（如 keyword / 数值），或显式开启该属性 `[经验]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ES 1.x 起 | doc_values 引入 | 排序聚合的标准依赖 |

## 关键代码
```json
PUT /user
{ "mappings": { "properties": { "id": { "type": "keyword" } } } }
```
```go
// 排序字段必须可列式读取：用 keyword / 数值，别用 text
mapping := map[string]any{
	"mappings": map[string]any{
		"properties": map[string]any{
			"id": map[string]any{"type": "keyword"}, // 默认开列式结构
		},
	},
}
```
> 验证：原文把该字段列式属性设为 true 后重建索引，同样的排序语句即可正常返回 `[实测]`。
