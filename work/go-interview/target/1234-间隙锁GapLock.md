# 1234 间隙锁（Gap Lock）

> 分类：MySQL 锁 | 难度：高 | 题型：原理 | 频率：高 | 关键词：**间隙锁、幻读、RR、索引区间、互斥、unsafe_for_binlog**

> 原文锚点：第 84~97 段「间隙锁机制与配置」

## 一句话总述
间隙锁锁定索引记录的「间隙」（区间），专为解决可重复读（RR）下的幻读——它只阻塞其他事务在间隙内插入，不阻塞已有记录的读取与修改。间隙锁之间互不互斥（都只为防插入），且仅在 RR 隔离级别生效；`innodb_locks_unsafe_for_binlog` 曾控制是否禁用间隙锁，5.6.3 起已移除、默认开启间隙锁。

## 面试官视角
间隙锁是「RR 为何不幻读」的最后一环。考官想听你讲清「间隙锁只防插入、不防读写」以及「间隙锁间不互斥」这两个反直觉点。能点出「仅 RR 生效 + 5.6.3 移除配置」即满分。

## 主问答
**Q（面试官原话）：** 什么是间隙锁？它解决什么问题？

1. **解决幻读**：行锁只能锁住已存在的行，但插入新记录操作的是「行之间的间隙」。RR 下为防止当前读出现幻影记录，InnoDB 引入间隙锁锁住索引区间。
2. **只阻塞插入**：间隙锁锁的是索引区间，目的是阻止间隙内插入新记录，因此**只阻塞 INSERT，不阻塞已有记录的读取与修改**。
3. **间隙锁互不互斥**：相同记录上的间隙锁之间不互斥（都只为防插入），其他事务仍可继续加间隙锁——这是它与 S/X 锁的重要区别。
4. **仅 RR 生效 + 配置变迁**：间隙锁只在可重复读下生效；`innodb_locks_unsafe_for_binlog`（0=加间隙锁/1=禁用）从 5.6.3 起被移除，后续版本默认开启间隙锁。

## 关键代码
```sql
-- RR 下范围当前读，锁住间隙防插入
SELECT * FROM t WHERE id BETWEEN 5 AND 10 FOR UPDATE;
```

## 总结与追问预判
核心：**间隙锁锁区间、只防插入不防读写、间隙锁间不互斥、仅 RR 生效、5.6.3 起默认开**。追问常回到 next-key 锁（见 1235）或自增锁（见 1234）。
