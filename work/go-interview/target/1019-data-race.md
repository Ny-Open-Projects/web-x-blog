# 1019 忽视数据竞争

> 分类：并发模型 | 难度：L2 | 题型：事故题 | 频率：高 | 关键词：**data race** / **-race** / **共享内存**
> 原文锚点：第 3~32 段「多个 goroutine 访问同一内存且至少一个写，即数据竞争；可用 go run -race 检测」

## 一句话总述
当≥2 个 goroutine 访问同一块内存（全局变量、闭包捕获变量）且至少一个写时，就产生数据竞争，结果不可预期；用 `go run -race` 能在同进程内抓出调用栈。

## 面试官视角
- 意图：是否真懂 data race 的判定条件，以及 -race 的能力边界。
- P5 知多写共享变量会乱 / P6 说清判定条件 + 会用 -race / P7 知 -race 抓不到跨进程/跨请求冲突。
- 红旗：以为加锁就一定对；以为 -race 能查出所有并发问题。
- 惊艳点：`-race` 只检测**同进程内** goroutine 的内存竞争，检测不到需靠锁/事务解决的跨请求写冲突 `[源码]` race detector。

## 主问答
**Q（面试官原话）：** 你写的并发代码怎么确认没有数据竞争？
**A：**
1. **结论**：多个 goroutine 同时访问同一变量且至少一方写，就存在竞争；用 `-race` 跑一遍定位调用栈。
2. **机制**：-race 在编译插桩，记录每处内存访问的 happens-before，冲突即报调用栈（main→increase→add→plus）。
3. **边界**：除 `atomic` 与 `sync.Map` 外，内置类型都非并发安全；**跨进程/跨 HTTP 请求的写冲突不是 data race**，-race 查不到，要事务或锁 `[源码]`。
**加分层：** -race 有运行时开销，只用于测试不上生产；它会漏报依赖外部时序的竞态。

## 关键代码
```go
// 示意，未验证：触发 data race 被 -race 抓出（go run -race main.go）
package main

import "sync"

func main() {
	var cnt int
	var wg sync.WaitGroup
	for i := 0; i < 100; i++ {
		wg.Add(1)
		go func() { defer wg.Done(); cnt++ }() // 无同步，竞争
	}
	wg.Wait()
}
```

## 总结与追问预判
- 竞争=共享内存+并发写；-race 抓同进程竞态，跨请求写冲突要锁/事务。
- 预判：忘了等 goroutine → 见 1019-goroutine-not-wait。

## ⚠️ 原文纠错
原文把"多个 HTTP 请求并发修改同一行数据"也称作数据竞争。纠正：跨请求/跨进程的写冲突属于资源争用，**不是** Go 内存模型层面的 data race，`go run -race` 也检测不到，需靠数据库事务、行锁或分布式锁解决；data race 专指同进程内 goroutine 对共享内存的无同步并发访问。
