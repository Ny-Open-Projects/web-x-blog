# 809 三色标记的工程要点与权衡

> 分类：Go/运行时 | 难度：L3 | 题型：综合题 | 频率：中 | 关键词：**防环辅助结构** / **并发减少停顿** / **浮动垃圾** / **仍需短STW**
> 原文锚点：第 53~70 段「三色通用算法(白灰黑/根遍历/灰转黑/白即垃圾)；需辅助结构防环；优点并发减少停顿；需写屏障保正确；强/弱三色不变式」

## 一句话总述
三色标记是高效可靠的 GC 算法：基于白/灰/黑三色从根遍历对象图（灰集合中对象取其下游入灰、自身转黑，灰空则白即垃圾），可**与程序并发执行、减少/避免停顿**。但工程上有三点要记：① 标记需辅助数据结构（如 worklist/位图）防环死循环；② 并发正确性必须靠写屏障；③ 仍有代价——浮动垃圾、且标记启动/终止仍需**短暂 STW**；其正确性由强/弱三色不变式约束。

## 主问答
**Q：** 三色标记法工程上要注意什么？
**A：**
1. **防环**：遍历对象图时若有环会死循环，需辅助结构（灰色 worklist/已标位图）记录"待处理"与"已处理"，避免重复扫描与无限循环。
2. **并发正确**：标记与用户代码并发，用户改引用会破坏颜色，必须配写屏障（Go 1.8 混合屏障）保证不变式——否则黑引白漏标、白被误回收。
3. **代价与边界**：① 并发标记产生**浮动垃圾**（本应回收但拖到下一轮）；② 标记**启动/终止仍需短暂 STW**（不只是纯并发）；③ 强三色不变式（黑不引白）由插入屏障保，弱三色不变式（黑引白时白上游须有灰）由删除屏障保。

## 关键代码
```go
// 三色推进 + 防环：用 worklist(灰集合) 而非递归，避免环导致的栈溢出/死循环
var (
    worklist = []*obj{} // 灰色集合（待处理）
    black    = map[*obj]bool{}
)
func markRoots(roots []*obj) {
    for _, r := range roots {
        worklist = append(worklist, r) // 根入灰
    }
}
func markStep() {
    for len(worklist) > 0 {
        o := worklist[len(worklist)-1]
        worklist = worklist[:len(worklist)-1]
        for _, c := range o.refs { // 下游入灰
            if !black[c] {
                worklist = append(worklist, c)
            }
        }
        black[o] = true // 自身转黑
    }
    // 灰空后：不在 black 中的对象即不可达（白），待清扫
}
```
