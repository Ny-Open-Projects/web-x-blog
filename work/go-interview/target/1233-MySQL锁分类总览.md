# 1233 MySQL 锁分类总览

> 分类：MySQL 锁 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**S锁/X锁**/**表锁/行锁**/**乐观锁/悲观锁**/**意向锁**
> 原文锚点：第 1~22 段「并发控制与锁的分类」

## 一句话总述
MySQL 锁按**粒度**（全局/表/页/行）与**性能思想**（乐观/悲观）划分，底层以**共享锁 S（读）**与**排他锁 X（写）**为基元。

## 面试官视角
- 考察意图：必考总纲——"MySQL 有哪些锁、怎么分类、S 和 X 什么关系"。
- 分档：P5 知 S/X；P6 知粒度排序；P7 知意向锁/MDL/auto-inc 属表级。
- 红旗答案：把乐观锁说成"MySQL 内置的一把锁"。
- 惊艳点：点出"乐观/悲观是思想，DB 各类锁归悲观阵营"。

## 主问答
**Q（面试官原话）：** MySQL 里的锁是怎么分类的？
**A：**
1. **S/X 基元**：读锁（共享 S）之间不互斥可并发读；写锁（排他 X）既阻塞读也阻塞其他写——保证同一时刻仅一个写者、写时不让他人读到半成品。
2. **按粒度**：库级锁（全局锁，粒度最大、冲突最高、并发最低）→ 表级锁 → 页锁（BDB 引擎，已废弃）→ 行级锁（粒度最小、冲突最低、并发最高）。
3. **表级锁组成**：除 S/X 表锁外，还有加行锁前自动上的**意向锁（IS/IX）**、server 层 **MDL**、**auto-inc 锁**。
4. **按性能思想**：乐观锁（提交时检测版本冲突，适合读多写少）、悲观锁（修改前先加锁，S/X 即其实现）。

| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
| --- | --- | --- | --- | --- |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
| --- | --- | --- |
| MySQL 5.5+ | 无 | S/X、意向锁、MDL、auto-inc 各版通用；行锁为 InnoDB 特性（MyISAM 仅表锁） |

## 关键代码
```sql
SELECT * FROM t WHERE id=1 LOCK IN SHARE MODE;   -- S 锁（8.0 推荐 FOR SHARE）
SELECT * FROM t WHERE id=1 FOR UPDATE;           -- X 锁
```

## 总结与追问预判
锁以 S/X 为基元，按粒度分库/表/页/行、按思想分乐观/悲观；InnoDB 行锁+意向锁+MDL 协同，MyISAM 只有表锁。

## ⚠️ 原文纠错
1. 事实核校： [经验]S/X 互斥矩阵、粒度排序、意向锁/MDL/auto-inc 属表级、乐观(版本冲突检测)vs 悲观(先加锁) 划分，均正确。
2. 崩坏词归一：解锁→写锁(X)、库机锁→库级锁、表级组→表级锁、原数据组/MATDAAA→元数据锁(MDL)、航机锁/行情锁→行级锁、零件锁→临键锁(next-key)、漏关锁→乐观锁、被关锁→悲观锁、度indb/英LDB→InnoDB、排排锁→排他锁、协作→写锁。
