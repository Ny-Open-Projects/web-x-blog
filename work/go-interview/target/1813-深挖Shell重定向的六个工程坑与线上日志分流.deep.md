# 1813 深挖：Shell 重定向的六个工程坑与线上日志分流

> 分类：操作系统 / Linux | 难度：L4 | 题型：实操题 | 频率：中 | 关键词：**日志分流**/**管道**/**缓冲**/**/dev/null**/**追加与截断**/**子进程捕获**
> 原文锚点：第 1~36 段「重定向就是把原本应该输出到屏幕上的内容，转移到其他的地方去…默认键盘输入送到标准输入，标准输出和标准错误则显示在屏幕上」
> [边界] 本文只讲**重定向语义与工程坑**：fd 上限（`nofile` / `limits.conf`）见 1313，守护化手段（nohup / exec / screen）见 187，均不重述。

## 思路与架构

把「重定向」从一条命令上升为**一张 I/O 流向图**，按三个维度拆：

```text
维度一：方向（写到哪）
  屏幕(tty) ──┐
  文件       ─┼── 由 fd 1 / fd 2 各自指向决定
  /dev/null  ─┘      ↑
                     └── 重定向改的就是这里

维度二：时机（顺序）
  shell 从左到右逐条执行
  > f 2>&1   : fd1→f，再 fd2 := fd1  ⇒ 都进 f
  2>&1 > f   : fd2 := fd1(tty)，再 fd1→f ⇒ stderr 留屏幕

维度三：模式（写的方式）
  >   截断写（O_TRUNC）
  >>  追加写（O_APPEND，多进程安全追加靠它）
  2>&1 复制目标；| 只接 stdout（stderr 不进管道，除非 2>&1 或 |&）
```

**关键心智模型**：程序永远只认 0/1/2 三个编号，**它不知道自己在跟谁说话**。所有"输出去哪"的决策都在**启动它的那一层**（shell / systemd / 父进程）完成。这个模型一旦建立，下面六个坑都能自己推出来。

## 方案取舍

```text
方案 A：> app.log 2>&1            （合并到同一文件）
  + 排障时时序完整，stdout/stderr 交错顺序即真实发生顺序
  - 正常日志与错误日志混在一起，做告警采集要多写一条正则
  适用：短任务、一次性脚本、CI 步骤

方案 B：> app.log 2> app.err      （分流到两个文件）
  + 错误单独一份，可直接挂告警；正常日志可独立轮转
  - 两份文件的时间线要靠时间戳自己对齐，跨文件追因果很痛
  适用：长期运行的服务

方案 C：> app.log 2>&1 | tee ...  （合并后进管道）
  + 既落盘又能在终端看
  - 管道只吃 stdout，必须先把 2>&1 写在管道左侧才生效
  适用：交互式排障

方案 D：> /dev/null 2>&1          （彻底丢弃）
  + 干净，不产生磁盘垃圾
  - 出错时无痕迹，等于主动放弃排障线索
  适用：cron 里确定不需要输出的命令

方案 E：程序内分流（Go: cmd.Stdout / cmd.Stderr 分别赋值）
  + 不依赖 shell，跨平台，可分别加前缀、分级落库
  - 需要自己处理并发写与缓冲
  适用：用 Go 管子进程、做任务编排
```

**取舍的三条判据**：① **排障优先还是采集优先**——排障选 A，采集选 B；② **是否容器化**——容器里 stdout/stderr 被日志驱动接管，程序内再落文件会造成**双写**，此时应直接打标准输出；③ **是否多进程同写一个文件**——必须用 `>>` 追加，用 `>` 会互相截断。

## 答题技巧

```text
1. 开口先给模型，不给命令
   「程序只认 0/1/2，输出去哪由启动它的那一层决定。」
   这句话一出口，面试官就知道你不是背答案的。

2. 主动抛顺序陷阱当加分项
   「> f 2>&1 和 2>&1 > f 不一样，后者错误会留在屏幕。」
   这是区分 P6 与 P7 的分水岭，多数人答不上。

3. 顺手补三个高频追问
   - 追加用什么？        >> 与 2>>（> 会截断，日志场景是事故）
   - 管道吃不吃 stderr？ 不吃，只有 stdout；要吃就先 2>&1 或写 |&
   - 想丢掉输出？        > /dev/null 2>&1（只写前半截的话错误还会刷屏）

4. 踩过的坑要能举出一个真实例子
   例：「cron 任务没重定向，stderr 被邮件塞满 / 服务双写日志导致磁盘翻倍」。

5. 收尾拔高一句
   「重定向解决的是'流向'，fd 上限解决的是'够不够用'，
     两者不是一回事——前者不消耗 fd 配额，管道才消耗。」
```

**避坑清单（写成 check list 更容易记）**：

```text
[ ] 日志场景一律用 >>，永远不要用 > 覆盖已有日志
[ ] 长期服务用分流（方案 B），别合并
[ ] 容器里别再往文件写，交给日志驱动
[ ] 管道前确认 stderr 是否需要一起进（2>&1 放在管道左边）
[ ] 代码里用 os.Stdout 而不是硬编码 1
[ ] 起子进程时显式指定 Stderr，别让它继承父进程的流向
```
