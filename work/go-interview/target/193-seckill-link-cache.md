# 193 秒杀链路中的各类缓存

> 分类：架构/缓存 | 难度：L2 | 题型：设计题 | 频率：中 | 关键词：**静态资源CDN** / **本地缓存预热** / **库存缓存** / **MQ同步DB**
> 原文锚点：第 52~70 段「静态资源CDN；本地缓存(商品预热进内存)；用户+访问记录缓存(防刷)；库存缓存+MQ 异步同步DB」

## 一句话总述
秒杀链路不是单一缓存，而是**多层缓存协同**：静态资源走 CDN 就近回源、商品信息预热进本地缓存（内存直读不查库）、用户与访问记录缓存识别并拦截恶意刷单、库存缓存承接扣减并经由**消息队列异步批量同步 DB**，把峰值写压力从数据库侧卸到缓存+MQ。

## 面试官视角
- 意图：考察"能否把缓存落到秒杀具体链路"，而不是泛谈概念。
- P5 知道 CDN；P6 能讲清本地缓存预热、库存缓存+MQ 削峰；P7 能讲"前端按钮置灰防重复请求 + 访问记录缓存封 IP/限刷"的组合防刷体系。
- 红旗：以为库存直接在 DB 扣减；不知道本地缓存预热的意义。
- 惊艳点：点出"缓存层先初步处理成交，再用 MQ 记录事件、分批落库避免打爆 DB"。

## 主问答
**Q：** 秒杀链路里缓存都用在哪？
**A：**
1. **静态资源缓存**：商品详情页的描述/图片/CSS/JS 预置 CDN，用户就近取，极大减轻回源；前端在活动前/抢购后置灰按钮，避免无效重复请求。
2. **本地缓存**：秒杀商品数量有限，活动前把全部商品信息预热进秒杀服务进程内存，请求直读内存不查 DB。
3. **用户与访问记录缓存**：存用户身份/历史行为、访问 IP/时间，异常访问即时封 IP/限刷，提前识别脚本僵尸号。
4. **库存缓存**：为商品建独立库存缓存，扣减先在缓存完成，成交事件写入 MQ 后分批同步 DB，避免高并发直写打爆数据库。

```go
// 库存扣减先在缓存完成，成交事件发 MQ 异步落库（削峰）
func deductStock(rdb *redis.Client, mq chan int64, skuID int64) error {
    // DECR 库存缓存，返回值即剩余；<=0 表示已售罄
    left, err := rdb.Decr(ctx, "seckill:stock:"+strconv.FormatInt(skuID, 10)).Result()
    if err != nil || left < 0 {
        rdb.Incr(ctx, "seckill:stock:"+strconv.FormatInt(skuID, 10)) // 回补
        return errors.New("sold out")
    }
    mq <- skuID // 成交事件入队，由消费者分批写 DB
    return nil
}
```
