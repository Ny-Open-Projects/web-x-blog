# 104 原子操作的本质与 Go 底层实现

> 分类：Go 并发 | 难度：中 | 题型：原理题 | 频率：中 | 关键词：**不可中断、变量级互斥锁、LOCK 前缀、sync/atomic、跨架构封装**

> 原文锚点：第 57~66 段「原子=不可中断(要么完成要么不执行)；变量级互斥锁，同刻一协程读写；Go 通过 LOCK 前缀 CPU 指令实现(锁内存总线/防其他CPU访问同地址)；封装到 sync/atomic；支持 int32/64/uint32/64/uintptr/unsafe.Pointer」

## 一句话总述
原子操作的本质是**不可中断的操作**——要么完整执行、要么不执行，无中间态；可理解为"**变量级的互斥锁**"，同一时刻只允许一个线程/协程对该变量读或写，因此天然具互斥性。Go 在底层调用带 **LOCK 前缀的 CPU 指令**实现：执行期间不被其他操作打断、并锁定内存总线防止其他 CPU 访问同一地址，保证原子性；不同架构指令不同，Go 将其统一封装进标准库 `sync/atomic`。一句话背法：**「原子=不可中断的变量级互斥；Go 靠 LOCK 前缀指令锁总线，封进 sync/atomic」**。

## 主问答
**Q（面试官原话）：** 原子操作到底是什么？Go 怎么实现的？

**先铺垫（由浅入深第 1 层）**："原子"这个词借自物理——不可再分。在并发里它的意思就是"这一读-改-写动作，要么全发生、要么不发生，中间不会被别的协程插进来看到半成品"。它是并发原语里唯一在硬件层就保证原子性的。

1. **本质（第 2 层）**：原子操作不可中断、无中间态，等价于"变量级互斥锁"——同一时刻一个协程对该地址读写，保证互斥。它是并发原语中**唯一**在硬件层保证原子性的。
2. **Go 底层（第 3 层）**：`sync/atomic` 的函数（如 `AddInt64`）编译为带 **LOCK 前缀**的 CPU 指令（如 `LOCK XADD`），执行期间锁定内存总线/缓存行，阻止其他 CPU 核访问同一地址，读-改-写整体不可被中断。
3. **跨架构封装（第 4 层）**：x86 用 LOCK 前缀、ARM 用 `LDAXR/STLXR` 或 LSE 等，指令各异；Go 把这些差异封进 `sync/atomic`，对外给统一 API，支持 int32/int64/uint32/uint64/uintptr 与 unsafe.Pointer。
4. **局限（第 5 层）**：原子只保证**单个变量**的读-改-写不可分割；多个变量组合的一致性（如"转账 A-1 且 B+1"）原子做不到，必须用 Mutex 或 CAS 循环。
5. **误用风险（第 6 层）**：别以为原子"免费"——LOCK 指令锁 cache line 有开销；更别拿它保护一段临界区逻辑（超出单变量就失效）。

## 关键代码
```go
package main

import (
	"fmt"
	"sync/atomic"
)

func main() {
	var c int64
	// atomic.AddInt64 编译为带 LOCK 前缀的指令，读-改-写 整体不可被其他核打断
	atomic.AddInt64(&c, 1)
	atomic.AddInt64(&c, 1)
	fmt.Println("c =", atomic.LoadInt64(&c)) // 2

	// 类型化 API（Go 1.19+）：不必手写指针，更安全
	var n atomic.Int64
	n.Add(1)
	n.Add(1)
	fmt.Println("n =", n.Load()) // 2

	// 支持类型：int32/int64/uint32/uint64/uintptr + unsafe.Pointer
	// 多变量组合一致性 → 原子做不到，必须 sync.Mutex（见 105）
}
```

## 总结与追问预判
**背这三句就够**：① **原子=不可中断的变量级互斥，并发原语里唯一硬件层保原子**；② **Go 靠 LOCK 前缀指令锁 cache line/总线，封进 sync/atomic 统一 API**；③ **原子只保单变量，复合逻辑/多变量要 CAS 循环或 Mutex**。
**预判追问**：
- 「atomic 和锁性能差多少？」→ 单变量原子更轻（无调度阻塞），但高竞争下 CAS 自旋可能反超锁（见 104 陷阱 / 105 何时用原子）。
- 「多变量怎么保一致？」→ 上 Mutex，或把多字段聚合成一个值塞 atomic.Value（见 104 陷阱 / 105）。
- 「类型化 API 有啥好？」→ Go 1.19+ atomic.Int64 免手写指针、编译期防类型错（见 105 原子适用类型）。
