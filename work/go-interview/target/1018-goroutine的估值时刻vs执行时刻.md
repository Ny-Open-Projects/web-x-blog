# 1018 goroutine 的「估值时刻 vs 执行时刻」

> 分类：并发模型 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**go 语句估值** / **调度时机** / **GOMAXPROCS** / **非确定性**

> 原文锚点：第 16~29 段「go 声明时变量即估值、调度执行时机不定；sleep(1s) 恰能看到正确值；GOMAXPROCS=1 只是巧合非保证」

## 一句话总述
`go f(args)` 在**声明那一刻**就对参数求值，而 goroutine 的**执行**是异步调度、时机不定——这是 for 循环里 goroutine 读到"奇怪值"的根因：你以为读的是当时的值，实际读的是调度到时才看到的值。一句话背法：**「go f(args) 声明即估值、执行才调度；for 里主协程继续改变量→goroutine 读到新值；正解传值/重赋值造独立存储，sleep/GOMAXPROCS=1 只是巧合」**。

## 面试官视角
这是把"循环变量捕获"等坑串起来的元认知题。考官想看你有没有"声明求值 / 执行调度"两阶段心智模型，而非只背"传参能修"。
- **P5**：知道 goroutine 异步、读到的值不确定。
- **P6**：能说清"声明即估值、执行才调度"。
- **P7**：能指出 GOMAXPROCS=1 或 sleep 只是巧合、非语义保证。
- **红旗**：以为 sleep(1s) 能"保证"读到正确值；以为 GOMAXPROCS=1 就安全。
- **惊艳点**：用"估值时刻 vs 执行时刻"一句话解释所有 for+goroutine 坑，而非逐例记。

## 主问答
**Q（面试官原话）：** 为什么 for 里 go 打印变量，有时 sleep 一下又对了？

**先铺垫（由浅入深第 1 层）**：很多人以为 `go func(){...}()` 是"立刻并行执行"，其实它是"**此刻**把这段闭包+实参登记给调度器，**稍后某个不确定的时刻**才真正跑"。两个时刻的差异，正是所有坑的来源。

1. **结论（第 2 层·机制）**：`go` 语句在声明处就对实参求值，但函数体在调度到时才跑；for 循环里主协程还在继续改循环变量，goroutine 执行时读到的已是新值 `[源码]`。
2. **机制（第 3 层）**：`go f(v)` 中 `v` 在 go 语句那一行就已定格（值或地址），但 `f` 的体要等调度；sleep(1s) 只是给主协程足够时间把循环跑完、goroutine 得以调度，是"调度巧合"不是保证 `[源码]`。
3. **边界（第 4 层）**：GOMAXPROCS=1 同样非保证——单核下主协程不主动让出时子 goroutine 仍可能迟迟不调度；真正的解法是传值/重赋值制造独立存储 `[经验]`。
4. **模型（第 5 层）**：所有 "for+goroutine 读变量" 坑，本质都是"估值/执行错位"——统一用"两阶段"模型解释，而非逐例记 `[经验]`。
5. **版本（第 6 层）**：Go 1.22 起循环变量 per-iteration 独立，原写法自愈，但仍推荐传参更清晰 `[源码]` release notes。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	const n = 3
	var wg sync.WaitGroup

	// 反例：直接捕获共享 i，执行时读到终值（≤1.21 全 n；1.22+ 0..n-1 但仍乱序）
	for i := 0; i < n; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println("shared:", i)
		}()
	}
	wg.Wait()

	// 正解：声明处用 v := i 制造独立存储（估值定格为本轮值）
	for i := 0; i < n; i++ {
		v := i // 声明即估值，v 定格为本轮值
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println("captured:", v) // 读到定格值
		}()
	}
	wg.Wait()
}
```

## 总结与追问预判
**背这三句就够**：① **go 声明即估值、执行才调度（两阶段模型）**；② **for 里主协程继续改变量→goroutine 读到新值**；③ **正解传值/重赋值造独立存储，sleep/GOMAXPROCS=1 只是巧合**。
**预判追问**：
- 「为什么 sleep 一下有时对？」→ 只是给主协程跑完的窗口，调度巧合非保证。
- 「1.22 改了啥？」→ 循环变量每轮独立，该坑自愈（见 1017）。
- 「怎么验证有没有竞争？」→ go run -race（见 1018 用 -race 揪出）。
