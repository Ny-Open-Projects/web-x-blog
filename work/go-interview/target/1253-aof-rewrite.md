# 1253 Redis 持久化（三）：AOF 重写

> 分类：Redis | 难度：中 | 题型：原理 | 频率：中 | 关键词：**AOF 重写、后台子进程、新文件替换、命令合并、缩小体积**

> 原文锚点：第 63~82 段「AOF 过大问题、重写机制、后台进程、新文件替换、命令合并」

## 一句话总述
AOF 文件会随写命令累积而膨胀，拖慢恢复。AOF 重写（BGREWRITEAOF）在后台子进程扫描当前数据库所有键值对，为每条数据生成「最小命令集」写入新 AOF 文件（如同一 key 多次 set 只留最后一次），完成后用新文件替换旧文件，从而大幅缩小体积。重写失败不影响旧文件。

## 面试官视角
重写是 AOF 的必考题。考官看你能不能讲清「为什么不直接改旧文件而写新文件」（答：重写失败会污染旧文件、导致无可用恢复数据，故先写新文件、成功再替换）。能点出「命令合并（多次 set 留最后一次）」和「后台子进程不阻塞主线程」说明理解到位。

## 主问答
**Q（面试官原话）：** AOF 重写是什么？为什么先写新文件再替换？

1. **动机**：AOF 持续追加命令会越来越大，恢复变慢、占磁盘；重写可压缩体积。
2. **机制**：后台子进程读取当前所有键值对，为每条生成「恢复所需的最小命令集」写入新 AOF 文件。
3. **命令合并**：同一 key 的多次写只保留最终状态对应的一条命令，避免冗余历史。
4. **先新后替**：重写先写新文件、成功后再原子替换旧文件——若重写中途失败，旧 AOF 不受影响，仍有可用恢复数据；若直接改旧文件，失败会污染它。
