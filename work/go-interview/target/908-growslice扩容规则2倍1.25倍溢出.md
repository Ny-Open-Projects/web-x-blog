# 908 growslice 扩容规则（2 倍 / 1.25 倍 / 溢出）

> 分类：Go / 切片 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**growslice** / **2 倍扩容** / **1.25 倍过渡** / **int 溢出 panic** / **零大小字段**
> 原文锚点：第 13~27 段「网传超1024变1.25倍不准；growslice：旧cap<256→2倍；≥256→过渡到1.25倍；int溢出panic；零大小字段返零值指针；新cap溢出设长度最大值」

## 一句话总述
`append` 触发扩容时由 runtime 的 `growslice` 决定新容量：旧 cap **< 256 直接翻倍**；**≥ 256** 时扩容因子从 2 倍**逐步过渡到约 1.25 倍**（不是一跨过 256 就变 1.25）。另含保护：新长度 int 溢出直接 panic；元素含零大小字段（如空结构体）直接返零值指针；新 cap 溢出 int 最大值则设为长度最大值。

## 面试官视角
- 意图：能否纠正"超过 1024 才变 1.25 倍"的误传，说清真实阈值与过渡逻辑。
- P5 知 cap 不够才扩容；P6 知 <256 翻倍、≥256 过渡到 1.25；P7 知"1.25 是渐进过渡非硬切换、int 溢出 panic、零大小字段特例"。
- 红旗：背"cap>1024 变 1.25 倍"；或以为扩容只翻倍。
- 惊艳点：点出"1.25 倍是逐步逼近的过渡因子，旧 cap 越大越接近 1.25，并非过了某阈值立刻切换" `[边界]` 见 923（扩容换地址陷阱）、907-slice-desc-independent（底层结构）。

## 主问答
**Q（面试官原话）：** slice 的扩容规则到底是什么，网传 1.25 倍对吗？
**A：**
1. **基础规则**：旧 cap < 256 时新 cap **翻倍**；旧 cap ≥ 256 时扩容因子从 2 倍**渐进过渡到约 1.25 倍**（随 cap 增大越接近 1.25，不是硬切）。
2. **阈值纠正**：网上"超过 1024 才变 1.25"不准确——过渡从 256 就开始，1.25 是渐近上限。
3. **溢出保护**：若新长度计算 int 溢出 → 直接 panic；若新 cap 溢出 int 最大值 → 把新 cap 设为切片长度最大值。
4. **零大小字段**：元素含零大小字段（空结构体等），growslice 直接返回零值指针，不做常规扩容计算。

## 关键代码
```go
// 示意：growslice 容量决策直觉（非源码，未验证）
// 旧 cap < 256 → 翻倍；≥256 → 向 1.25 倍渐进过渡（非硬切）
func newCap(old, need int) int {
    if old < 256 {
        return old * 2
    }
    // 渐进：因子从 2 向 1.25 靠拢
    c := old
    for c < need {
        c += (c + 3*256) / 4 // 约 1.25 倍逼近
    }
    return c
}
```
