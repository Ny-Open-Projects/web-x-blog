# 1853 从输入 URL 到页面：TCP 连接建立与协议栈封装

> 分类：网络/TCP | 难度：L3 | 题型：流程题 | 频率：高 | 关键词：**TCP封装**/**三次握手**/**SYN/SYNACK/ACK**/**HTTPS/TLS**/**协议栈**
> 原文锚点：第 27~49 段「应用层→TCP段→IP包→链路帧→物理层封装 + 三次握手 + HTTPS 建 TLS」

## 一句话总述
拿到 IP+端口后，数据要**逐层封装**下送：应用数据→TCP 段（加端口/seq/ACK/窗口/标志位）→IP 包（加源目 IP/TTL）→链路帧（加 MAC）→物理信号；连接用 **TCP 三次握手**（SYN→SYN+ACK→ACK）建立可靠通道；若是 HTTPS，还要在 TCP 之上再建 **TLS/SSL** 加密通道。

## 面试官视角
- 考察意图：能否讲清「协议栈封装方向」与「三次握手报文序列」，并区分 TCP 与 TLS 的层次。
- 分档：P5 知三次握手 SYN/ACK；P6 能列封装各层加了什么；P7 知 HTTPS=TCP+TLS、TLS 在传输层之上。
- 红旗答案：把 TLS 说成 TCP 的一部分；封装方向说反（物理层在上）。
- 惊艳点：点出「TCP 头部含 seq/ACK/窗口实现可靠+流控+拥塞控制，信息用于端到端传输」 [经验]。

## 主问答
**Q（面试官原话）：** 拿到 IP 后怎么建立连接？数据怎么打包？
**A：**
1. **协议栈封装**：应用数据向下逐层封装——TCP 段加端口号/序列号/确认号/窗口/标志位；IP 包加源目 IP/TTL；链路帧加 MAC 与校验，最终物理层转电信号/光信号 [经验]。
2. **三次握手**：客户端发 SYN → 服务端回 SYN+ACK → 客户端回 ACK，双方确认收发能力后连接建立 [经验]。
3. **HTTPS 额外 TLS**：HTTP 走 TCP 即可；HTTPS 在 TCP 之上再握手建立 TLS/SSL 加密通道，保证传输机密性与完整性 [经验]。

## 总结与追问预判
连接建立的代价主要在握手：TCP 三次 + TLS 1.3 一至两次往返。面试常追问「TLS 握手优化（0-RTT/会话复用）」「队头阻塞」——均建立在本卡分层事实之上。

2. 崩坏词归一：源码将若干术语音译为崩坏词，本卡统一为规范术语（协议栈、TCP 段、IP 包、链路帧、三次握手、TLS 等）。

```go
// TCP 三次握手 + HTTPS 额外 TLS（建立连接）
func dial(host string, https bool) (net.Conn, error) {
    addr := net.JoinHostPort(host, "443")
    if https {
        // TCP 之上再建 TLS 加密通道（三次握手由底层 TCP 完成）
        return tls.Dial("tcp", addr, &tls.Config{MinVersion: tls.VersionTLS12})
    }
    // 普通 HTTP：TCP 三次握手 SYN→SYN+ACK→ACK 后即 ESTABLISHED
    return net.Dial("tcp", addr)
}
// 注：TCP 段含 seq/ACK/窗口实现可靠传输与流控；本卡只引握手，头部细节见 1840 系列
```
