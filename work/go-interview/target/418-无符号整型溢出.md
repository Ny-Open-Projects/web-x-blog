# 418 无符号整型溢出：回绕为零与预算校验

> 分类：Go 数值类型 | 难度：L3 | 题型：陷阱题 | 频率：高 | 关键词：**uint64 回绕**/**模运算**/**预算校验**/**MaxUint64**/**确定性**

> 原文锚点：第 43~52 段「无符号整型溢出后的值与事前校验」

## 一句话总述
无符号整型溢出后**回绕为零**：`uint64` 最大值加 1 的二进制会一路进位直到最高位溢出，结果整体变成 0。Go 把它定义为**模 2^n 的确定性回绕**（不像 C 是未定义行为），但业务上必须在运算**之前**做范围校验并拦截。

## 面试官视角
考官关心两件事：你知道结果是 0，以及你知道**该怎么防**。多数人只答前者。能把校验式写成 `math.MaxUint64-x < y` 而不是 `x+y > math.MaxUint64`（后者本身就会溢出），说明你真处理过边界。

## 主问答
**Q（面试官原话）：** uint64 最大值加 1 会怎样？怎么防？

1. **结果是零**：`math.MaxUint64 + 1` 的二进制为全 1 加 1，逐位进位一直推进到最高位后溢出，整体结果变为 0。
2. **不是未定义行为**：Go 规范把无符号整型运算定义为**模 2^n 的回绕**，结果确定、可复现，与 C/C++ 的未定义行为不同。
3. **校验要前置**：不能在算完再判断，因为溢出已经发生，判断本身失去意义。
4. **正确判据**：用减法改写，判断 `math.MaxUint64 - x < y`，若成立则说明相加必然溢出，直接报错返回。
5. **不满足才运算**：只有确认不会溢出时才执行加法，否则提前返回错误，避免错误值流入后续逻辑。

## 关键代码
```go
package main

import (
	"errors"
	"fmt"
	"math"
)

func addUint64(x, y uint64) (uint64, error) {
	if math.MaxUint64-x < y { // 用减法避免"先溢出再判断"
		return 0, errors.New("uint64 overflow")
	}
	return x + y, nil
}

func main() {
	v, err := addUint64(math.MaxUint64, 1)
	fmt.Println(v, err) // 0 uint64 overflow

	x := uint64(math.MaxUint64)
	fmt.Println(x + 1) // [实测] 输出：0 —— 不校验时静默回绕
}
```

## 总结与追问预判
核心：**回绕确定但危险，校验必须前置且用减法写**。追问常拐向「乘法怎么判」「无符号减法下溢」，备好除法判据与 `x < y` 拦截两条。
