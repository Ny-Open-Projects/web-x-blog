# 912 Goroutine 与进程、线程的区别

> 分类：Go 并发 / 执行模型 | 难度：L3 | 题型：对比题 | 频率：高 | 关键词：**进程**/**线程**/**goroutine**/**上下文切换**/**TLB失效**/**用户态调度**

> 原文锚点：第 1~43 段「进程(资源分配最小单位/独立虚拟地址空间)...线程(调度最小单位/共享内存需加锁)...上下文切换开销(硬件/内核栈/寄存器/TLB失效)...协程=用户态轻量单元(初始栈2KB/仅寄存器切换/并发优)...Go 用 goroutine+channel 优雅并发」

## 一句话总述
**进程**是资源分配最小单位（独立虚拟地址空间，32 位下 4G），**线程**是调度执行最小单位（轻量进程，共享堆/全局区、访问需加锁）。**goroutine（协程）**是用户态轻量执行单元：初始栈仅 2KB、按需增长收缩，切换只在用户态保存/加载 CPU 寄存器，把线程的内核态切换搬到用户态，开销远低于线程，并发性能更优。Go 用 goroutine + channel 实现优雅并发模型。

## 面试官视角
- 考察意图：是否真懂三者定位差异，尤其是 goroutine 的"用户态调度 + 小栈"为何轻量，以及上下文切换的真实开销来源（TLB 失效）。
- 分档：P5 知进程/线程区别；P6 能讲上下文切换四部分开销（含 TLB 失效）；P7 能讲 goroutine 用户态调度 + 2KB 栈 + 并发优势。
- 红旗答案：把 goroutine 当线程（忽视用户态调度）；不知上下文切换为何慢（只说"有开销"不提 TLB）。
- 惊艳点：点出「线程切换涉及用户↔内核态、开销高；goroutine 仅用户态存寄存器」「切换导致 TLB 失效→地址转换变慢」 [经验]。

## 主问答
**Q（面试官原话）：** Goroutine 和进程、线程有什么区别？
**A：**
1. **进程=资源分配最小单位**：独立虚拟地址空间，OS 以进程为单位分配 CPU 时间片/内存；是 OS 级概念，需显式创建管理 [经验]。
2. **线程=调度执行最小单位**：轻量进程，寄生在进程上，除各自栈外共享堆/全局区，通信简单但访问需加锁同步；OS 不区分进程/线程，皆分配时间片 [经验]。
3. **上下文切换四部分开销**：硬件上下文 + 内核栈切换 + 保存执行流状态到寄存器 + **TLB 失效**（页表切换→虚拟地址转物理变慢→程序变慢）[经验]。
4. **goroutine=用户态协程**：初始栈 2KB（线程通常数 MB），栈按需增长收缩；切换仅保存/加载 CPU 寄存器，全在用户态，极大减少内核↔用户态切换 [经验]。
5. **并发优势**：轻量 + 小资源 + 低切换成本 → 更好并发性能；单 goroutine 由运行时自动调度到多个线程，无需显式管线程 [经验]。

- 减少上下文切换的优化手段（减锁/CAS/减线程/协程/M:N）见 `101-reduce-context-switch` [边界]；本卡讲三者概念对比，不重述优化。

## 总结与追问预判
核心区分：进程管资源、线程管调度、goroutine 是用户态轻量单元。面试常追问「goroutine 为什么比线程轻」→ 答「2KB 栈 + 仅用户态存寄存器 + 不触发 TLB 失效」；再追问调度则引 GMP。

## ⚠️ 原文纠错
1. 事实核校： [经验] 进程/线程定位、上下文切换四部分开销与 TLB 失效、goroutine 2KB 栈与用户态调度、Go 1.19+ 栈自适应——均正确，符合 OS 与 Go 运行时事实。

```go
// goroutine 是用户态轻量执行单元：go 关键字即可启，初始栈仅 2KB，由运行时调度
func main() {
    ch := make(chan int, 3)
    for i := 0; i < 3; i++ {
        go func(id int) { ch <- id * id }(i) // 仅一个 go 关键字，开销远低于线程
    }
    for i := 0; i < 3; i++ {
        fmt.Println(<-ch) // 通过 channel 通信，而非共享内存加锁
    }
}
```
