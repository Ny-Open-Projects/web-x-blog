# 1219 最左前缀原则深挖

> 分类：MySQL 索引 | 难度：L3 | 题型：深挖 | 频率：高 | 关键词：**最左前缀** / **B+树有序性** / **断层** / **范围** / **逆序**
> 原文锚点：第 1~42 段「B+树排序→最左前缀；字符串逐字符比较；前缀/范围可用、中间后缀不可用；逆序后缀匹配；联合索引断层；索引长度限制」

## 思路与架构
最左前缀不是孤立规则，而是"B+树有序性 → 前缀/范围可定位"这一底层事实在两类场景的统一体现：① 联合索引（列序即字典序）；② LIKE（字符串前缀有序）。两类的"失效"都源于"跳过了有序前缀段"。

## 方案取舍
```text
最左前缀两大场景对照：
──────────────────────────────────────────────────────────
场景              能用的写法              失效写法              根因
联合索引(a,b,c)    a / a,b / a,b,c          b / c / b,c         不从最左起
联合索引断层        a,c（仅 a）             a,c 中 c 失效         中间 b 断层
范围截断            a=1 AND b=2             a=1 AND b>2 后 c 失效  范围锁区间、后续无序
LIKE               'x%'（前缀）            '%x%'/'%x'（非前缀）  后缀无序
逆序变通           name_rev LIKE 'NOL%'     name LIKE '%LON'        后缀转前缀

设计法则：
- 列序：高区分度/最常用等值列放最左，范围列放最后
- 长字段：用前缀索引 name(20)，受 767/3072 字节限制（见 1228）
- 后缀搜索：逆序存储 + 查询串逆序
```

## 答题技巧
```text
面试话术（先原理，再两类场景，后设计）：
1. 原理：B+树按列值有序，字符串逐字符比，前缀有序可定位、后缀无序不可
2. 联合索引：最左连续匹配；断层后列失效；范围列右侧失效
3. LIKE：'x%' 走 range；'%x%' 常规全扫（覆盖索引例外见 1222）
4. 设计：高区分度列放左、范围列放右；长字段前缀索引；后缀搜逆序存储
5. 收尾：最左前缀是 B+树有序性的必然，不是人为规定
```

> 边界：LIKE 规则与覆盖例外见 1222；联合索引非前缀 LIKE 例外见 1222；例外汇总见 1222；索引设计原则见 1221；索引长度/字符集见 1228；B+树结构见 1217。本卡只深挖"最左前缀原则"不重述各规则卡。

## 细节与核心 API

**联合索引 (a,b,c)：最左连续匹配才生效，断层/范围右侧失效**：

```sql
CREATE TABLE t (a INT, b INT, c INT, KEY idx(a,b,c));
SELECT * FROM t WHERE a=1 AND b=2 AND c=3;  -- 全用 idx
SELECT * FROM t WHERE b=2 AND c=3;          -- 失效（不从最左起）→ 全表扫
SELECT * FROM t WHERE a=1 AND c=3;          -- 仅 a 用，c 断层失效
SELECT * FROM t WHERE a=1 AND b>2 AND c=3;  -- a,b 用；范围锁区间，c 失效
```

**LIKE：前缀有序可走 range，后缀/中间无序全扫（覆盖索引例外见 1222）**：

```sql
SELECT * FROM t WHERE name LIKE 'x%';   -- 走索引（range）
SELECT * FROM t WHERE name LIKE '%x%';  -- 全扫

-- 后缀搜索变通：逆序存储 + 查询串逆序
SELECT * FROM t WHERE name_rev LIKE 'NOL%';  -- 等价于 name LIKE '%LON'
```

**列序设计**：高区分度 / 等值列放最左，范围列放右；长字段用前缀索引 `name(20)`（受 767/3072 字节限制，见 1228）。

> 边界：索引设计原则见 1221；索引长度/字符集见 1228；联合索引结构见 1217。本卡只深挖最左前缀原则。
