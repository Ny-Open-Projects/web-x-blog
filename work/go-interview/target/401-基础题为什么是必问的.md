# 401 基础题为什么是必问的

> 分类：面试方法论 / 基础认知 | 难度：L1~L2 | 题型：认知题 | 频率：高 | 关键词：**知识边界**/**变式追问**/**实用派**/**专家派**/**理解大于背诵**

> 原文锚点：第 1~19 段「大厂系统考察 OS/网络/数据结构…探寻候选人知识边界…两类程序员…TCP 追问变式…理解基础上深挖」

## 一句话总述
基础题必问的根因：**面试是探测候选人知识边界下限的过程**——面试官要确定你对每块技能的最低掌握层次，而基础是新技术/新问题出现时抓住重点的前提。考法早已变刁钻：不让你背「三次握手过程」，而是追问「第三次握手丢了会怎样」「收到不正确的 ACK 会回 RST 吗」——**背过程不算会，答得出变式才算懂**。

## 面试官视角
- 意图：这是「筛掉侥幸者」的题——看你是否理解基础题的考察逻辑，从而判断你的准备姿态。
- 分档：P5 知基础题重要；P6 能说「探测知识边界」与变式追问逻辑；P7 能讲实用派/专家派差异并反推自己的学习路径。
- 红旗答案：只说「大厂爱考所以背」；认为基础题=死记硬背。
- 惊艳点：点破「基础题是**定级锚**——下限决定评级，项目经历决定上限」 [经验]。

## 主问答
**Q（面试官原话）：** 为什么基础类面试题是必问的？

**A：**
1. **探测边界**：面试是探寻候选人知识边界的过程，面试官需要知道你对某块技能掌握的**最低层次**在哪——基础题正是标定下限的尺子；大厂系统化考察操作系统、网络、数据结构。
2. **两类程序员**：**实用派**以完成任务为目的、带着目标学，高效但止于工具；**专家派**在完成任务后继续深挖，系统理解技术，还能按业务特点做定制开发——成长更快、能独当一面。面试官押注的是后者，而后者靠基础撑起。
3. **考法在进化**：TCP 三次握手不问过程，问「第三次握手丢失会怎样」「收到不正确的 ACK 还会发 RST 吗」「已建立连接再收到 SYN 会怎样」——每问都建立在对机制的透彻理解上，死记硬背无法应付。
4. **应对**：重视基础准备（打动面试官的前提）+ 逐点深挖细节 + 在工作中主动构建系统化知识体系。

## 关键代码

```python
# 基础题「变式追问」自测器：背过程不算会，答得出变式才算懂
variants = {
    "TCP 三次握手": [
        "第三次握手 ACK 丢了会怎样？（客户端/服务端状态各是什么）",
        "收到不正确的 ACK，服务端还会回 RST 吗？为什么？",
        "连接建立后再次收到 SYN 会怎样？（挑战 ACK 机制）",
    ],
    "四次挥手": [
        "为什么 TIME_WAIT 等 2MSL？",
        "服务端大量 CLOSE_WAIT 说明什么？",
    ],
}
for topic, qs in variants.items():
    print(f"[{topic}]")
    for q in qs:
        input(f"  能答吗? {q} (y/n) ")  # n 的题目 = 待深挖清单
```

[实测] 运行输出逐条列出 5 个变式追问；`n` 的条目即你的「待深挖清单」——比刷一百道原题更能定位基础漏洞。
