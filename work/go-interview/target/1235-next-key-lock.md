# 1235 next-key 锁、间隙锁与加锁对象

> 分类：MySQL 锁 | 难度：高 | 题型：原理 | 频率：高 | 关键词：**next-key 锁、间隙锁、左开右闭、RR、唯一索引退化、锁在索引**

> 原文锚点：第 90~111 段「next-key 锁/间隙锁与加锁针对索引」

## 一句话总述
next-key 锁 = 记录锁 + 间隙锁，锁定一个「左开右闭」区间（如记录 id=10 的 next-key 锁锁 (3,10]），用于 RR 下防止当前读幻读。间隙锁与 next-key 锁仅在可重复读（RR）支持；InnoDB 默认加锁单位就是 next-key 锁，但唯一索引等值查询会优化退化为纯记录锁。所有加锁都针对「索引」。

## 面试官视角
next-key 锁是 MySQL 锁的皇冠题。考官必问「为什么 RR 不幻读、RC 会幻读」——答案就在 next-key 锁仅 RR 生效、RC 退化为记录锁。能讲清「左开右闭」和「锁在索引上」即满分。

## 主问答
**Q（面试官原话）：** 什么是 next-key 锁？为什么只在 RR 防幻读？

1. **构成与区间**：next-key 锁 = 记录锁 + 它前面的间隙锁，锁定「左开右闭」区间（记录行所在间隙，含记录本身）。如 id=10 的 next-key 锁锁 (3,10]，区间内不允许插入。
2. **解决幻读**：RR 下当前读用 next-key 锁锁住间隙，其他事务无法在范围内插入，从而杜绝幻读；读已提交（RC）下退化为记录锁，不锁间隙，故可能幻读。
3. **唯一索引优化**：当查询命中唯一索引的等值条件，next-key 锁会退化为普通记录锁（只锁该索引记录），因为唯一性已保证不会插入重复。
4. **锁在索引上**：加锁对象永远是索引——主键索引加锁就锁主键；二级索引加锁后，还会对其对应主键记录加锁，故别的事务改主键记录也会被阻塞。

## 版本与兼容性
| 隔离级别 | 加锁单位 |
|----------|----------|
| RR（默认） | next-key 锁（唯一等值退化为记录锁） |
| RC | 记录锁（无间隙锁，可能幻读） |

## 关键代码
```sql
-- RR 下范围当前读，锁 (3,10] 区间
SELECT * FROM t WHERE id<=10 FOR UPDATE;
```
