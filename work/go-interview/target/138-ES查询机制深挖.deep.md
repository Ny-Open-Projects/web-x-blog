# 138 ES 查询机制深挖

> 原文锚点：第 1~102 段「term/match/match_phrase 与分词器体系」

## 一句话总述
从倒排索引与 analyzer 的视角，统一解释 term/match/match_phrase 的召回差异，并给出字段类型与查询类型的选型矩阵。

## 主问答
**Q（面试官原话）：** 能不能把 ES 查询讲深一点？
**A：**
1. **倒排索引视角**：所有查询最终都变成"拿 term 去倒排里比"；term 直接拿整串比，match/match_phrase 先经 search_analyzer 变 term 再比。
2. **位置信息（positions）**：mapping 的 `index_options=positions` 让倒排存 term 位置，match_phrase 才能校验"相邻同序"；没有位置信息则短语约束无从谈起。
3. **召回 vs 精度三角**：term(精确高精低召回) → match(全文低精高召回) → match_phrase(短语中精中召回)；`operator=and` 与 `slop` 是两个可调旋钮。
4. **GET by ID**：`_get` 按 `_id` 直接取文档，走的是 doc id 路由而非倒排，不属于 query 类型，别混进三者对比。

## 思路与架构
- 三层结构：字段类型(text/keyword) → analyzer(索引/搜索分词器) → 查询类型(term/match/match_phrase)。任一层错配都会让"查不到"或"召回太脏"。
- keyword 字段的倒排存的是整值 term，所以 term 精确命中；text 字段倒排存分词 term，所以 term 整串查空、必须 match。

## 方案取舍
- 等值过滤（状态/枚举/ID）→ term 查 keyword，最快最准。
- 用户输入的自由文本搜索 → match（默认 OR 高召回），必要时 and。
- 短语/姓名/地址连续匹配 → match_phrase + 合理 slop。
- 单文档按 ID 取 → 直接用 GET，别走 query。

## 答题技巧
1. 开场先点"三者差别在分不分词 + 要不要位置"，一句话定调。
2. 必带 text 字段坑：term 查 text 必空，正确姿势是 `.keyword` 或 match。
3. 提 analyzer 分离（max_word 建 / smart 搜）展示工程经验。
4. 收尾用"召回—精度三角 + operator/slop 旋钮"体现深度。

## 总结与追问预判
term/match/match_phrase 本质是"倒排 term 比对"的三种封装；分词器与字段类型决定 term 形状。选型按精度需求：等值→term、全文→match、短语→match_phrase。
