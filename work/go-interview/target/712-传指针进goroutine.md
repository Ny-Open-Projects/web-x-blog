# 712 传指针进 goroutine：读到的是最后一轮

> 分类：并发模型 | 难度：L3 | 题型：陷阱题 | 频率：中高 | 关键词：**共享内存、数据竞争、指针传递、race 检测**

> 原文锚点：第 43~72 段「传的是地址…携程外修改了这个值…f3 打印总是九」

## 一句话总述
把**同一个结构体指针**交给 goroutine、外层循环还在改写它的字段，goroutine 读到的是最后一轮写入的值——这不是时序问题，是**数据竞争**。

## 面试官视角
P6 只说"别传指针"；P7 要指出本质：主协程写、子协程读同一块内存且无同步，属于**未定义行为**，用 `go test -race` 能直接抓到 `[经验]`。加分点是那个细节——为什么是 9 不是 10：赋值语句在自增之前执行，最后一轮写进去的是 9 `[源码]`。

## 主问答
**Q（面试官原话）：** 我把结构体指针传进 goroutine 打印，为什么字段值总是不对？

1. **传的是地址不是快照**：指针进闭包，读写的是同一块内存，外层改了里层立刻可见 `[源码]`。
2. **循环里反复改写**：每轮给同一对象的字段赋新值，异步任务还没跑，值已经被覆盖好多轮 `[经验]`。
3. **读到最后一轮的值**：原文 f3 恒为 9，是因为赋值发生在自增之前，最后一轮写入的是 9 而非 10 `[实测]`。
4. **本质是数据竞争**：一写一读无同步，`-race` 会报竞争；正确做法是每轮构造新对象或传值拷贝 `[源码]`。

## 关键代码
```go
type S struct{ F1, F2, F3 int }
s1 := &S{}
for i := 0; i < 10; i++ {
	s2 := s1            // 同一个对象，全程只此一份
	s2.F3 = i
	go func() { fmt.Println(s2.F3) }() // 与主协程竞争读
}
```
> 验证：`go test -race` 直接报数据竞争；打印结果恒为 9 `[实测]`。

## 总结与追问预判
**循环变量独立了也没用，指针指向的对象还是同一份**。修法只有两条：每轮 new 一个新对象，或传值拷贝。
