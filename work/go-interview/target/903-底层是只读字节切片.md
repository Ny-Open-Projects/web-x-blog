# 903 底层是只读字节切片：data 指针指向哪里，为什么改不了

> 分类：Go 基础 / string | 难度：L4 | 题型：原理题 | 频率：高 | 关键词：**只读字节切片、data 指针、底层数组、不可变、下标赋值报错**

> 原文锚点：第 57~76 段「在 Go 语言里面，字符串的底层存储结构其实是一个只读的字节切片，它使用的是 UTF-8 编码来表示的 Unicode 字符串…它会有两个字段，一个字段是指向底层的字节切片的指针，另一个字段是它指向的底层的字节切片的长度…字符串的底层的这个数组元素，其实是不可变的，我们可以对字符串进行重新赋值，但是不能直接修改字符串中某个字符…我们将字符串里面的第二个字符改成 d，它提示有错误，所以我们不能直接对这个字符串进行修改」

## 一句话总述
`string` 的底层是**只读的字节切片**（UTF-8 编码），其结构体只有**指向底层字节数组的指针**与**长度**两个字段；底层数组元素不可变，因此**可以整体重新赋值，但不能通过下标修改单个字符**。

## 面试官视角
P6 知道「字符串不能改」；P7 要讲清**物理布局**——string 描述符指向一个底层字节数组、该数组自带长度/容量/数据指针，以及**下标赋值为何编译报错**，并能用反射或 `unsafe` 说明 data 指针的实际指向。

## 主问答
**Q（面试官原话）：** 字符串的底层到底是什么？为什么 `s[1] = 'd'` 不行？

1. **底层形态**：Go 字符串的底层存储结构**是一个只读的字节切片**，用 **UTF-8 编码**表示 Unicode 字符串 `[源码]`。
2. **描述符两个字段**：一个**指向底层字节切片的指针**，另一个是该**字节切片的长度** `[源码]`。
3. **实际存储的是码点值**：例如 "ABC" 的 Unicode 码点是 **97、98、99**，底层存储的就是这几个值；因都 ≤127，每个字母占 1 字节，总长度 3 `[源码]`。
4. **指针的最终指向**：字符串指针指向底层字节切片，而字节切片自身还有**长度、容量与底层数据指针** `[源码]`。
5. **底层数组不可变**：字符串**底层的数组元素是不可变的** `[源码]`。
6. **可整体重新赋值**：可以对字符串**重新赋值**，但**不能直接修改其中某个字符** `[源码]`。
7. **下标赋值报错**：试图把第二个字符改成 'd' 时**直接编译报错** `[源码]`。
8. **观察手段**：可通过反射取到字符串结构，打印 **data 指向的地址**，再将其强转为字节数组即可看到底层码点值 `[源码]`。
9. **重新赋值的代价**：重新赋值会**重新开辟内存**存储新字符串，即发生一次拷贝 `[源码]`。

## 关键代码
```go
package main

import (
	"fmt"
	"reflect"
	"unsafe"
)

func main() {
	s := "ABC"

	// 用反射取到字符串头部，观察 data 指针与长度
	h := (*reflect.StringHeader)(unsafe.Pointer(&s))
	fmt.Printf("dataPtr=%#x len=%d\n", h.Data, h.Len)

	// 把 data 指向的数据强转为字节数组，即可看到底层码点值
	bytes := unsafe.Slice((*byte)(unsafe.Pointer(h.Data)), h.Len)
	fmt.Println(bytes) // [65 66 67] 即 A B C

	// ❌ 编译错误：不能直接修改字符串中的字符
	// s[1] = 'd' // cannot assign to s[1]

	// ✅ 正确做法：先转 []byte 或 []rune，修改后再赋回（产生一次拷贝）
	b := []byte(s)
	b[1] = 'd'
	s = string(b)
	fmt.Println(s) // AdC
}
```

## 总结与追问预判
**「只读字节切片 + 指针/长度两字段」是底层全貌**。面试官常追问「真要改怎么办」——答案是转 `[]byte`（ASCII 场景）或 `[]rune`（含中文场景）修改后赋回，代价是一次内存分配与拷贝。不可变性的收益与代价见同批 903-string-storage.deep。

## ⚠️ 原文纠错
