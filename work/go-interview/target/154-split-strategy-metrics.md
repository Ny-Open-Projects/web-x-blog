# 154 微服务拆分策略与合理性衡量

> 分类：架构设计 / 微服务 | 难度：L3 | 题型：设计题 | 频率：高 | 关键词：**六拆分策略** / **绞杀者模式** / **内部复杂度** / **外部复杂度** / **交付周期**
> 原文锚点：第 24~60 段「六策略；衡量：内部复杂度(人数)/外部复杂度(子系统数)/交付周期/跨团队成本」

## 一句话总述
拆分**六策略**：独立新业务 / 通用服务 / 边界明显服务 / 核心服务 / 独立属性服务优先，遗留系统用**绞杀者模式**；合理性用四维度衡量：**内部复杂度**（参与人数，三个火枪手）、**外部复杂度**（一次请求涉及子系统数，约 5 合理、20 过高）、**交付周期**（天级正常，数周=粒度过大）、**跨团队沟通成本**（多数功能能否单服务内完成）。

## 面试官视角
- 意图：是否掌握可落地的拆分顺序与量化衡量手段。
- 分档：P5 知优先抽核心/通用；P6 能列 2~3 策略；P7 能讲绞杀者模式 + 四维度量化衡量。
- 红旗：只会"按业务拆"，无优先级与衡量标准。
- 惊艳点：点出绞杀者模式——在遗留系统外围逐步用新服务绞杀老系统，保障不中断迁移。

## 主问答
**Q（面试官原话）：** 从单体怎么落地拆分？怎么判断拆得合不合理？
**A：**
1. **六策略（优先级）**：①独立新业务先行（影响老系统最小）②优先抽象通用服务（边界明、耦合低）③优先边界明显的服务（基于原有清晰 package）④优先核心服务（边缘运营系统可不拆）⑤优先独立属性服务（按变更频率/资源/技术栈）⑥遗留系统用绞杀者模式逐步绞杀。
2. **康威定律对齐**：服务边界应与团队/沟通边界一致——拆分粒度最终由组织沟通结构决定，三个火枪手（3 人/服务）正是其落地表现；拆得过细会放大跨团队成本（见衡量维度四）。
3. **衡量四维度**：
   - 内部复杂度：单服务参与开发人数（三个火枪手为准）。
   - 外部复杂度：一次请求涉及子系统数，约 5 合理、20 过高。
   - 交付周期：小功能修改应以天为单位；数周~月=粒度过大、合并冲突多。
   - 跨团队成本：多数功能应能在单一服务内完成；频繁跨团队联合开发=划分有问题。
