# 1820 用户空间与内核空间：系统调用陷入

> 分类：Linux 内核 | 难度：L3 | 题型：机制题 | 频率：中 | 关键词：**用户空间**/**内核空间**/**用户态**/**内核态**/**系统调用**/**中断**
> 原文锚点：第 26~34 段「内核工作方式：用户空间/内核空间 + 系统调用」

## 一句话总述
内核把内存划分为**内核空间**（仅内核可访问、权限高、可访问全部内存）与**用户空间**（给应用、只能访问局部内存）。应用要进内核空间必须**系统调用**：触发中断→CPU 跳中断处理程序执行内核代码→内核完成再触发中断把权限交回用户态。

## 面试官视角
- 考察意图：是否理解特权级隔离（用户态/内核态）与系统调用的「陷入-返回」机制，以及它对性能的含义。
- 分档：P5 知用户态/内核态之分；P6 知系统调用触发中断陷入内核；P7 知用户↔内核切换有开销、Go GMP 正是为减少此类切换。
- 红旗答案：以为应用能直接读写内核空间；或不知系统调用靠中断实现。
- 惊艳点：点出「每次系统调用都要用户态↔内核态切换，频繁切换拉低 CPU 利用率（Go GMP 针对性优化）」。

## 主问答
**Q（面试官原话）：** 用户空间和内核空间有什么区别？系统调用是怎么发生的？
**A：**
1. **空间隔离**：内核把内存分成两块——内核空间仅内核程序可访问、权限高可控制 CPU/内存/硬盘等全部资源；用户空间给应用，其代码只能访问局部内存。
2. **态的叫法**：用用户空间时称「用户态执行」，用内核空间时称「内核态执行」；内核态权限远高于用户态。
3. **系统调用陷入**：应用要进内核空间须通过系统调用；调用时产生中断，CPU 中断当前用户程序、跳转到中断处理程序（开始执行内核代码）。
4. **返回用户态**：内核处理完主动触发中断，把 CPU 执行权限交回用户程序，回到用户态。每次陷入/返回都是一次特权级切换，有开销。

// 系统调用陷入示意：Syscall 进入内核态，返回时回到用户态
func syscallDemo() {
	// 例如文件写入：用户态发起 write 系统调用 → 中断陷入内核 → 内核写设备 → 返回
	n, _ := syscall.Write(1, []byte("via syscall\n")) // 1=stdout，由内核完成
	_ = n
}
