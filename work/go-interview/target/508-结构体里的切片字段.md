# 508 结构体里的切片字段：改元素怎么就影响了外面

> 分类：Go 语言基础 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**切片字段、间接部分、共享底层数组、指针地址、浅拷贝**

> 原文锚点：第 74~80 段「字段是有间接部分的值，修改间接部分指向的值就会改变…打印出的 names 地址与原始相同」

## 一句话总述
结构体按值传，但它的**切片字段只是个头部**；头部被拷进副本后，两边头部里的指针仍指向**同一块底层数组**，所以副本改 `names[i]`，调用方也看得到。

## 面试官视角
这是"值传递"最容易翻车的地方，面试官用它验证你是否真懂。P6 能说"共享底层数组"就够了；P7 会补**证据**：打印调用方 `p.Names` 与函数内 `ps.Names` 的**首元素地址 `&names[0]` 完全相同**，并给出工程结论——传值得到的是**浅拷贝**，敏感场景要显式 `slices.Clone` 隔离 `[经验]`。

## 主问答
**Q（面试官原话）：** 结构体是值传递，为什么函数里改了它的切片字段，外面也变了？

1. **结论**：值传递拷的是结构体的**直接部分**（含切片字段的头部 ptr/len/cap）；拷贝之后两个头部的 ptr **值相同**，于是共享同一份间接部分。
2. **机制**：`ps.Names[2] = "d"` 不是给字段赋值，而是**通过副本头部里的指针写底层数组**，这条路径与调用方共用一块内存。
3. **证据**：原文实测在调用前后分别打印两处 `Names` 字段的地址，两者相同；原本是 `[a b c]`，调用后变成 `[a b d]` `[实测]`。
4. **边界**：共享只在"改元素"这条路径上成立；若要连同切片头部一起替换，结果完全相反（见 508）。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Go 1.0+ | 无 | 拷贝头部、共享底层；改元素可见，整体替换不可见 |

## 关键代码
```go
type Team struct {
    Names []string
}

func changeStruct2(t Team) {
    t.Names[2] = "d"  // 写底层数组：调用方可见
}

func main() {
    t := Team{Names: []string{"a", "b", "c"}}
    fmt.Printf("%p\n", &t.Names[0])  // 与函数内打印值相同
    changeStruct2(t)
    fmt.Println(t.Names)             // [a b d]，原文实测值
}
```

## 总结与追问预判
记住这条链路：**拷头部 → 共享底层 → 下标写入才跨函数可见**。想隔离就先 `slices.Clone`；想让函数一定改到外面就传 `*Team` 或用返回值。
