# 1012 自旋锁 vs 互斥锁：忙等还是睡眠

> 分类：Go / 并发 / 锁 | 难度：L3 | 题型：对比题 | 频率：中 | 关键词：**忙等待** / **线程切换开销** / **CPU 浪费** / **短临界区** / **高竞争**

> 原文锚点：第 1~5 段「自旋锁等待时不睡眠、循环尝试；锁持有短则优于其他锁(免切换开销)，锁长或竞争频则浪费 CPU；适合极短持有场景」

## 一句话总述
自旋锁与互斥锁的核心区别在**等待方式**：自旋锁拿不到锁时**忙等**（循环重试、不睡眠、占 CPU），互斥锁拿不到则**睡眠**（让出 CPU、被唤醒）。因此**临界区极短**时自旋锁免去线程切换开销、性能更优；**临界区长或竞争激烈**时自旋空转浪费 CPU，反不如互斥锁。一句话背法：**「自旋锁拿不到忙等(占CPU、省切换、短临界区优)；互斥锁拿不到睡眠(让CPU、长/高竞争稳)；本质用CPU换延迟」**。

## 面试官视角
这是锁选型的第一道题。考官要你在"等待成本"维度讲清取舍，而非只会调 Lock。
- **P5**：知道自旋不睡眠、互斥会睡眠。
- **P6**：知道短临界区自旋优、长临界区自旋浪费。
- **P7**：知道"自旋本质是用 CPU 换延迟、竞争高时崩"。
- **红旗**：以为自旋锁永远更快；或以为自旋锁不会占 CPU。
- **惊艳点**：点出"Go runtime 的 M 也是自旋找 G，与用户自旋锁同源——都是用短促忙等换低延迟" `[边界]` 见 815（runtime M 自旋）、925-mutex-impl（Mutex 休眠实现）。

## 主问答
**Q（面试官原话）：** 自旋锁和互斥锁有什么区别，怎么选？

**先铺垫（由浅入深第 1 层）**：两把锁保护的都是临界区，差别只在"拿不到锁时在干嘛"。一个在 CPU 上死等（自旋），一个把线程挂起去睡觉（互斥）。这个差异决定了它们各自的甜区。

1. **等待方式（第 2 层·机制）**：自旋锁拿不到锁→循环忙等（不睡眠、占 CPU）；互斥锁拿不到→睡眠让出 CPU，被唤醒再抢 `[源码]`。
2. **性能拐点（第 3 层）**：临界区**极短**时，自旋省去线程切换/调度开销，优于互斥锁；临界区**长**或**竞争频繁**时，自旋线程一直空转占 CPU，反而浪费、不如互斥锁 `[实测]`。
3. **适用（第 4 层）**：自旋锁只适合"锁持有时间非常短"的场景；不确定持有时间一律用互斥锁/读写锁更稳 `[经验]`。
4. **本质（第 5 层）**：自旋是用 CPU 周期换低延迟，竞争高时 CPU 被空转吃满、吞吐崩；互斥是用调度延迟换 CPU 利用率 `[经验]`。
5. **进阶（第 6 层）**：runtime 的 M 找 G 也用短自旋，与用户自旋锁同源——都是"短暂忙等换低延迟" `[边界]` 见 815。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

// SpinLock 用 atomic CAS 实现忙等自旋锁
type SpinLock struct{ flag int32 }

func (s *SpinLock) Lock() {
	for !atomic.CompareAndSwapInt32(&s.flag, 0, 1) {
		// 拿不到锁：循环重试（忙等），占 CPU 但不睡眠
	}
}
func (s *SpinLock) Unlock() { atomic.StoreInt32(&s.flag, 0) }

func main() {
	var sl SpinLock
	var cnt int32
	var wg sync.WaitGroup
	for i := 0; i < 100; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			sl.Lock()
			cnt++ // 极短临界区，自旋锁省切换
			sl.Unlock()
		}()
	}
	wg.Wait()
	fmt.Println("spinlock cnt =", cnt) // 100

	// 对照：互斥锁（拿不到睡眠，不确定持有时间时更稳）
	var mu sync.Mutex
	var cnt2 int32
	for i := 0; i < 100; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			mu.Lock()
			cnt2++
			mu.Unlock()
		}()
	}
	wg.Wait()
	fmt.Println("mutex cnt =", cnt2) // 100
}
```

## 总结与追问预判
**背这三句就够**：① **自旋锁忙等、互斥锁睡眠**；② **短临界区自旋优、长/高竞争自旋废 CPU**；③ **自旋本质是用 CPU 换延迟**。
**预判追问**：
- 「自旋锁怎么实现？」→ atomic CAS 忙等（见 1012 自旋锁实现）。
- 「Mutex 底层怎么休眠？」→ sema 信号量挂起（见 925-mutex-impl）。
- 「runtime 也有自旋？」→ M 自旋找 G，同源（见 815）。
