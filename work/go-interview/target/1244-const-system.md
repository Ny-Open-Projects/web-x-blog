# 1244 system 与 const：常量级访问

> 分类：MySQL 调优 | 难度：中 | 题型：原理 | 频率：高 | 关键词：**system、const、主键等值、唯一索引、统计精确**

> 原文锚点：第 7~20 段「system 单表一行、const 主键/唯一二级索引等值常量」

## 一句话总述
system 是 type 最快一档：表只有一行且存储引擎统计精确（如 MyISAM、Memory），访问等同于读常量。const 出现在「用主键或唯一属性的二级索引，与常数做等值匹配」时，优化器把查询结果当常量——整条查询最多只读一行。

## 面试官视角
const 是面试高频点。考官想听清「触发条件 = 主键或唯一索引 + 等值 + 常量」，并能举例（如 `WHERE id = 1` 主键、`WHERE unique_col = 'x'`）。分不清 system 与 const 的区别（单行表 vs 等值命中唯一键）是常见失分点。

## 主问答
**Q（面试官原话）：** 什么情况下 EXPLAIN 的 type 会显示 const？system 又是什么？

1. **system**：表中仅一行，且引擎的统计信息精确（MyISAM、Memory 这类），访问代价等价于常量，比 const 还快一档。
2. **const 触发条件**：查询条件是「主键」或「唯一属性的二级索引」，且这个值与「常数」做等值匹配。
3. **本质**：优化器在优化阶段就能确定结果唯一且固定，于是把该表访问降级为读一个常量，整个查询最多扫一行。
4. **失效信号**：若唯一索引列用了函数、范围、或比较对象不是常量（是另一列），则掉到 ref/range/ALL。

## 版本与兼容性
| 条件 | type |
|------|------|
| 主键 = 常量 | const |
| 唯一二级索引 = 常量 | const |
| 表仅 1 行 + 精确统计 | system |

## 关键代码
```sql
EXPLAIN SELECT * FROM t WHERE id = 1;          -- 主键等值 → const
EXPLAIN SELECT * FROM t WHERE k2 = 'a';        -- 唯一索引等值 → const
```

## 总结与追问预判
核心：**const = 主键/唯一索引 + 等值 + 常量，最多读一行；system 是单行精确统计表的特例**。追问常接「唯一索引等值为什么是 const 不是 eq_ref」（见 1244-eqref-ref）。
