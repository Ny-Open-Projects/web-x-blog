# 1814 磁盘存储与 inode 基础

> 分类：Linux 文件系统 | 难度：中 | 题型：概念 | 频率：高 | 关键词：**扇区、块、inode、元信息、stat**

> 原文锚点：第 1~21 段「磁盘存储单位与 inode 定义/内容」

## 一句话总述
文件在磁盘上以「扇区(512B)→块(4KB=8扇区)」组织；inode（索引节点）是文件元信息的载体，记录字节数/权限/UID/GID/时间戳/链接数/数据块位置，系统靠 inode 编号而非文件名识别文件。

## 面试官视角
inode 是 Linux 文件系统的基石题。考官看你能不能讲清「文件名与 inode 分离」这一核心抽象，以及 stat 能看到什么。能顺带说出「小文件多可能耗尽 inode」的人更扎实。

## 主问答
**Q（面试官原话）：** 什么是 inode？它存了什么？

1. **存储层级**：磁盘最小单位扇区 512B；OS 一次读多个扇区组成一个块（常见 4KB=8 扇区），文件数据存在块里。
2. **inode 是什么**：每个文件对应一个 inode，存放元信息——字节数、拥有者 UID/GID、权限、四个时间戳、硬链接数、数据块位置。
3. **系统如何找文件**：用户用文件名 → 系统查文件名对应的 inode 编号 → 用编号定位 inode → 读数据块。`ls -i` 看编号，`stat` 看全部元信息。
4. **inode 与文件名分离**：系统内部只用 inode 编号识别文件，文件名只是给用户用的「指针」。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| inode 大小 | 固定 128/256B（因 FS 而异） |
| 编号 | 分区内唯一，系统靠它识别文件 |
| 文件名 | 仅用户层指针，与 inode 解耦 |

## 关键代码
```bash
# 查看 inode 编号与元信息
ls -i test.log
stat test.log   # 含 size/blocks/ino/uid/gid/时间戳
```

## 总结与追问预判
核心：**inode = 文件元信息 + 编号，文件名只是壳**。追问常拐向「inode 耗尽」（见 1814）或「硬链接为什么共享 inode」（见 1814）。
