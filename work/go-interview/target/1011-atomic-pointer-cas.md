# 1011 原子指针 CAS 比较的是地址

> 分类：并发模型 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**CompareAndSwap** / **地址** / **指针值**
> 原文锚点：第 48~69 段「CS 比较的是指向的地址，不是地址指向的值；值相等地址不等不替换」

## 一句话总述
`atomic.Pointer[T].CompareAndSwap(old, new *T)` 比较的是**指针值（地址）本身**是否相等，而不是两个指针指向的结构体内容；地址不同即使字段值相同也会返回 false。

## 面试官视角
- 意图：有没有踩过"值相等但 CAS 失败"的坑，理解 CAS 的比对对象。
- P5 知 CAS 比较指针 / P6 说清比的是地址非内容 / P7 知由此推导"用同一实例地址才换得动"。
- 红旗：以为 CAS 会比较结构体字段；拿两个字段相同的不同对象去 CAS。
- 惊艳点：同值不同地址的两个 `*T`，`CompareAndSwap` 必失败——验证：打印两地址不等即知 `[实测]` `fmt.Printf("%p")`。

## 主问答
**Q（面试官原话）：** 指针的 CAS 比较的是值还是地址？
**A：**
1. **结论**：比较**地址（指针值）**，不是指针指向的内容。
2. **机制**：CAS 原子地比对当前存储的指针是否等于 old；相等才换成 new 并返回 true，否则 false。
3. **边界**：两个字段完全相同的不同对象地址不同，CAS 永远失败；要换得动必须传入"当前确实存着的那个地址"。
**加分层：** 想要"按内容换"得自己保证同一份实例，或改用值比较的自定义逻辑。

## 关键代码
```go
// 示意，未验证：CAS 比地址，值同地址异则失败
var p atomic.Pointer[int]
a, b := 1, 1
p.Store(&a)
ok := p.CompareAndSwap(&b, &a) // false：&b != 当前&a 的地址
```

## 总结与追问预判
- 指针 CAS 比对地址而非内容；换得动需传入当前实存地址。
- 预判：指针原子 vs 锁场景 → 见 1011-atomic-pointer-vs-lock。
