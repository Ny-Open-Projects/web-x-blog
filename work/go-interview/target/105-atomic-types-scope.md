# 105 原子操作适用类型与保护范围

> 分类：并发模型 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**int32/64** / **unsafe.Pointer** / **atomic.Value** / **单变量**
> 原文锚点：第 5~14 段「原子操作保护单个变量…常用于计数器、状态变量」

## 一句话总述
原子操作只作用于"单个变量"，标准库支持 int32/int64/uint32/uint64/uintptr/unsafe.Pointer 及 atomic.Value；多变量组合一致性必须上锁。

## 面试官视角
- **考察意图**：是否知道原子能保护哪些类型、边界在哪。
- **P5** 知计数器用原子 / **P6** 能列支持类型与 atomic.Value / **P7** 知多字段需锁或聚合到单个 atomic.Value。
- **红旗**：对 struct 直接 atomic.Load；以为原子能保护一段逻辑。
- **惊艳点**：`atomic.Value` 可存任意类型但要求"存入类型一致"，否则 panic —— 验证：`go doc atomic.Value`，go1.26.5 `[源码]`。

## 主问答
**Q（面试官原话）：** 哪些类型能用原子操作？原子能保护一段代码吗？
**A：**
1. **结论**：原子仅保护单个变量，支持 int32/64、uint32/64、uintptr、unsafe.Pointer，以及承载任意值的 atomic.Value。
2. **机制**：每个原子函数操作一个地址；atomic.Value 内部用指针原子交换实现类型安全的整体替换。
3. **边界**：原子不能保护"多个变量 + 条件"的复合临界区，那样会出现竞态，必须 mutex。
**加分层：** Go1.19+ 推荐 `atomic.Int64` / `atomic.Bool` 等类型化原子变量，比手写地址更不易出错。

## 总结与追问预判
- 原子只护单变量；atomic.Value 存任意类型但类型须一致；多字段上锁。
