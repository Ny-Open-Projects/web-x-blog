# 419 Go 数值类型边界深挖

> 原文锚点：第 1~106 段「移位溢出、浮点上溢、精度、除法、iota」

## 一句话总述
从"类型即宽度"的视角统一解释 Go 数值陷阱：运算/移位结果类型由操作数决定、浮点走 IEEE754、常量与变量求值时机不同、iota 是 const 行计数器。

## 主问答
**Q（面试官原话）：** Go 数值类型有哪些必踩的坑？
**A：**
1. **整数溢出是回绕不是报错**：Go 不对整数溢出 panic，而是模 2^N 回绕（uint16 下 65536→0）；靠自己选够宽的型或用 math/bits 检查。
2. **浮点溢出是 +Inf**：IEEE754 上溢得正无穷，不是饱和；下溢趋向 0/次正规。
3. **精度是表示问题**：0.1+0.2≠0.3、不满足结合律、float32 仅 ~6-7 位——金额用整数分或 decimal 库。
4. **iota 按行不按次**：const 块重置、前导常量占行号。

## 关键代码
```go
import "math/bits"
// 检查加法是否溢出
func addUint16(a, b uint16) (uint16, bool) {
    s := a + b
    return s, !(s >= a) // 回绕检测
}
```

## 思路与架构
- 一条主线：**Go 的类型是宽度即语义**——任何运算结果类型由操作数类型决定，不会自动拓宽；溢出/精度问题都源于"类型定宽度，宽度定边界"。
- 两个域：整数域（模 2^N 回绕，无 NaN/Inf）与浮点域（IEEE754，有 +Inf/-Inf/NaN、精度损失）。二者行为不能类比。

## 方案取舍
- 计数/索引用有符号 int（可判负）；位标志/协议字段用无符号 uint，但要手动防回绕。
- 金额/比率：优先整数分（int64 分）或 `shopspring/decimal` 等十进制库，绝不直接用 float 比较或累加。
- 存储单位/枚举：用 `1<<(10*iota)` 与 iota 枚举，清晰且零分配。

## 答题技巧
1. 开场定调："Go 类型定宽度，运算不自动拓宽"，一句话收掉大半陷阱。
2. 整数溢出必答"回绕不 panic"——这是和 Java/C++ 最大差异点，面试官爱考。
3. 浮点必带 0.1+0.2 与 +Inf 两个例子，展示你区分整数/浮点两域。
4. iota 强调"按行不计次"，顺手用 KB/MB 例子证明掌握。

## 总结与追问预判
Go 数值陷阱的统一根因是"类型即宽度"：整数回绕、浮点 IEEE754、常量编译期求值、iota 按行。答题时先讲清域（整数/浮点）再给对应规则即可稳。
