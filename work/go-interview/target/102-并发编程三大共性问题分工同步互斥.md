# 102 并发编程三大共性问题（分工 / 同步 / 互斥）

> 分类：Go 并发模型 | 难度：中 | 题型：概念题 | 频率：高 | 关键词：**分工、同步、互斥、并发安全、并发原语**

> 原文锚点：第 1~15 段「并发三类共性问题：分工/同步/互斥；Go 对应原语」

## 一句话总述
并发编程有三类共性问题：**分工**（任务分解分配，提效）、**同步**（线程/协程间协作通知）、**互斥**（共享资源访问控制，保证并发安全）；Go 用 channel+条件变量做同步，用锁+原子做互斥。一句话背法：**「并发三问题：分工提效、同步协作、互斥保正确；分工同步讲性能，互斥讲正确性」**。

## 面试官视角

## 主问答
**Q（面试官原话）：** 并发编程要解决的共性问题有哪些？

**先铺垫（由浅入深第 1 层）**：很多人一提并发就想到"加锁"。但锁只是其中一类问题的解法。并发真正要解决的是三件事——怎么把活拆开（分工）、怎么让大家配合（同步）、怎么别同时改同一份数据（互斥）。看清这三类，原语选型才有章法。

1. **分工（第 2 层）**：把任务拆成子任务分给不同线程/协程，目标是提高执行效率与资源利用率（如 DB 服务分线程管读写/监控）。
2. **同步（第 3 层）**：线程/协程间依赖时的协作通知（如线程二等线程一的数据），Go 用 **channel** 或**条件变量**实现。
3. **互斥（第 4 层）**：多执行体访问同一共享资源时，任一时刻最多一个占用，防并发修改致数据不一致——即并发安全，Go 用 **读写锁/互斥锁/原子操作**实现。
4. **目标差异（第 5 层）**：分工与同步强调性能（让活干得快、配合得好），互斥强调数据正确性与一致性——二者目标不同，不能互相替代。
5. **误用风险（第 6 层）**：只上锁不分工，并发度起不来；只分工不同步，结果错乱；只同步不互斥，数据竞争——三者要配套设计。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

// 三大共性问题对应原语：分工（goroutine）+ 同步（channel）+ 互斥（Mutex）
func main() {
	done := make(chan struct{}) // 同步：通知"活干完了"
	var mu sync.Mutex
	var shared int64

	// 分工：起一个 goroutine 干活
	go func() {
		mu.Lock()
		shared++ // 互斥：锁护住共享
		mu.Unlock()
		done <- struct{}{} // 同步：通知主协程
	}()

	<-done // 同步：等通知
	fmt.Println("shared =", shared)
}
```

## 总结与追问预判
**背这三句就够**：① **分工=拆任务提效，同步=协程间协作通知，互斥=共享访问互斥保正确**；② **Go 同步用 channel/条件变量，互斥用锁/原子**；③ **分工/同步讲性能，互斥讲正确性，三者目标不同要配套**。
**预判追问**：
- 「同步和互斥区别？」→ 同步是"等我告诉你再走"（协作），互斥是"同一刻只能一人动"（安全）（见本卡）。
- 「channel 和锁怎么选？」→ 编排用 channel、保护用锁（见 102 选型大方向）。
- 「条件变量怎么用？」→ 见 105 Cond/semaphore。
