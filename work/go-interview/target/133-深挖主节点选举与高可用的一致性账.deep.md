# 133 深挖：主节点选举与高可用的一致性账

> 分类：Elasticsearch | 难度：L4 | 题型：架构题 | 频率：高 | 关键词：**选举、投票规则、法定数量、脑裂、角色分离、副本恢复**

> 原文锚点：第 1~58 段「什么情况下会丢失副本分片…master 节点的角色与职责…master 选举的具体过程…脑裂与法定数量」

## 思路与架构

这一节可以拆成**一个核心问题的三层答案**：集群如何在节点随时可能失联的前提下，始终维持"**有且只有一个主节点**"这个不变量。

**第一层：故障时数据先怎么扛。** 节点离线时，它上面的主分片由其他节点上的副本接管并升级为主分片；升级之后副本数量减少，等于副本缺失，集群进入 yellow。副本不会立刻重建，要等 `index.unassigned.node_left.delayed_timeout`（默认 1 分钟）超时才开始——这个等待窗口是刻意的：给节点重启留出时间，否则一次短暂重启就要付出整片跨节点拷贝的磁盘与网络代价。恢复之所以昂贵，是因为副本要靠**拷贝主分片数据**来对齐，分片越大越痛。真正的危险窗口在升级后、恢复前：此时若承载主分片的节点再宕机，主分片丢失，集群转 red。

**第二层：主节点凭什么被信任。** 主节点不碰文档读写，只做集群级管理：维护并广播含映射、分片配置与分配的集群状态；维护活跃节点列表并感知上下线；决定分片分配与再平衡；处理索引的创建删除、映射更新、集群设置变更；承接集群级 API。因为它只管元数据，资源占用小，**与数据节点分离部署**是大型集群的标准做法。

**第三层：主节点怎么产生。** 主节点不可用时触发选举：候选先初始化并连接配置中的初始主机列表；超时仍拿不到集群状态即判定旧主不可用；随后每个候选发布含**节点 ID、选举轮次、集群状态版本**的自我声明；收到声明的节点按四条规则投票——同轮只投一次、优先投状态版本更高者、版本相同投节点 ID 更小者、不投给自己；得票超过候选总数一半者当选并广播结果，无人过半则等超时重开一轮。选举期间没有主节点，取不到集群状态，健康状态可能短暂变黄甚至变红，选出新主后即恢复。

把三层串起来就是完整叙事：**副本保数据、主节点管元数据、选举保唯一性**。

## 方案取舍

| 决策 | 选项 | 取舍 |
|---|---|---|
| 副本恢复延迟 | 默认 1m / 调大 | 调大少做无用拷贝，代价是副本缺口窗口变长 |
| 主节点部署 | 混部 / 分离 | 分离更稳，代价是多几台机器 |
| 候选主节点数 | 偶数 / 奇数 | 奇数让过半判定更省节点 |
| 法定数量 | 手配 / 自维护 | 手配可控但扩缩容易漏改；自维护省心但需理解机制 |
| 选举失败 | 立即重选 / 等待超时 | 等待避免选举风暴，代价是短暂无主 |
| 副本数 | 1 / 2 及以上 | 多副本更抗二次故障，代价是存储与同步开销 |

取舍要点：

- **延迟恢复与副本数是同一道保险的两半。** 副本只有一份时，升级后到恢复前是真正的裸奔窗口，这两项必须一起评估。
- **过半约束不能被绕过。** 它是唯一性保证，任何"为了可用性降低门槛"的想法都会直接引入脑裂风险。
- **版本优先的投票排序是为了少丢变更。** 让掌握最新集群状态的候选胜出，比随机或按 ID 优先更符合一致性目标。
- **别把"无主"说成"不可用"。** 无主期间取不到集群状态，但数据节点上的既有读写路径并不整体停摆，措辞要准确 `[经验]`。

## 答题技巧

1. **用"副本 → 主节点 → 选举"三层开场**，先讲数据怎么扛，再讲元数据谁管，最后讲怎么选出来，骨架清晰。
2. **三色判据要精确**：yellow 是副本未分配，red 是主分片未分配，说反了直接掉档 `[源码]`。
3. **报出具体默认值**：副本恢复延迟 1 分钟、法定数量 N/2+1，这些数字是可信度信号 `[源码]`。
4. **版本栅栏必须带**：ES 7 起不再手工配置法定数量，改由集群自动维护投票配置；角色配置也从布尔开关演进到角色列表 `[源码]`。
5. **每个调优都补代价。** 延迟调大换来缺口变长、副本加倍换来同步开销——肯说代价才像做过生产决策 `[经验]`。

## 细节与核心 API

**副本恢复延迟与法定数量（约束仍在 N/2+1，ES 7+ 改由集群自维护）：**

```json
// 副本升级后延迟恢复（默认 1m，给重启留窗口，避免短暂重启就跨节点拷贝）
PUT /_all/_settings { "index.unassigned.node_left.delayed_timeout": "1m" }
// ES 7+ 法定数量不再手配，集群自动维护 voting config；版本栅栏必带
GET _cluster/health
```

**选举投票四规则（落地为代码式判据）：**

```text
收到自我声明后按序投票：
① 同轮只投一次
② 优先投 集群状态版本更高者
③ 版本相同投 节点 ID 更小者
④ 不投给自己
得票 > 候选总数/2 → 当选广播；无人过半 → 等超时重开一轮
```

**三色判据（精确，说反即掉档）：**

```bash
GET _cat/nodes?v&h=name,node.role,master   # 主节点列看星号
# green：主副全分配   yellow：副本未分配（主分片在）   red：主分片未分配
```
