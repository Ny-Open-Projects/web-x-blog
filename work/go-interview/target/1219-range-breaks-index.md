# 1219 范围查询导致的索引断层

> 分类：MySQL 索引 | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**范围查询** / **索引断层** / **范围列放最后** / **type 退化** / **等值 vs 范围**
> 原文锚点：第 23~26 段「B+树数据按列序排；范围查找只有最左列能用到索引树；联合索引范围查询后续列失效」

## 一句话总述
联合索引上，**等值条件**后续列仍能继续走索引，但**范围条件**（`>`、`<`、`BETWEEN`、`LIKE 'x%'`）一旦出现在某列，其**右侧所有列都无法再用索引**——因为范围锁定了一段区间，区间内后续列已无序。列序设计必须把**范围列放最后**。

## 面试官视角
- 意图：是否分得清"等值断层"与"范围断层"的差异，并据此排序列序。
- P5 知联合索引最左匹配；P6 知范围列右侧失效；P7 知"范围 vs 等值对后续列的影响不同，范围列必须靠右"。
- 红旗：以为 `(a,b,c)` 上 `a=1 AND b>2 AND c=3` 三列都用；实际 b 是范围，c 失效。
- 惊艳点：点出"范围锁定区间后后续列无序，所以失效；等值不破坏后续列有序性" `[边界]` 见 1222-like-basics（范围=前缀定位）、1244-range-index-all（EXPLAIN type 退化链）。

## 主问答
**Q（面试官原话）：** 联合索引上范围查询为什么会让后续列失效？
**A：**
1. **等值的传递性**：`a=? AND b=?` 等值逐层缩小，b 在 a 确定的子区间内仍有序，c 可继续用——等值不破坏后续列有序。
2. **范围的截断**：`a=? AND b>?` 中 b 是范围，锁定的是一段区间；该区间内 c 的分布不再按 (a,b,c) 全局有序，故 **c 无法用索引**（type 退化）。
3. **设计法则**：联合索引把**范围列放最右**；无法避免时，范围列之后的列就别指望走索引，考虑用覆盖索引或拆索引。

## 关键代码
```sql
-- 联合索引 (a,b,c)
CREATE INDEX idx_abc ON t(a,b,c);
EXPLAIN SELECT * FROM t WHERE a=1 AND b=2 AND c=3; -- 三列都用 (ref)
EXPLAIN SELECT * FROM t WHERE a=1 AND b>2 AND c=3; -- b 是范围，c 失效
-- 设计：范围列 b 放最后 → (a,c,b) 让等值 c 先走、范围 b 收尾
```

## 总结与追问预判
- 范围列截断后续索引；等值不截断。列序：范围列放最右。
- 预判：断层矩阵 → 见 1219-composite-gap；LIKE 范围定位 → 见 1222-like-basics；EXPLAIN type 链 → 见 1244-range-index-all；索引长度（字符集） → 见 1228-index-length-limit。
