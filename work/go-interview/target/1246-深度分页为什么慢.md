# 1246 深度分页为什么慢：扫描百万行加百万次回表

> 分类：数据库 / MySQL 索引 | 难度：L4 | 题型：原理题 | 频率：高 | 关键词：**LIMIT offset、回表、二级索引、聚簇索引、深度分页**

> 原文锚点：第 8~19 段「查询条件 name LIKE 以 name 开头的字符串，取 0 到 10，执行了一百多毫秒…起始偏移量是一百万，也是取十条，耗时一秒零六百五十毫秒…需要从二级索引树上扫描符合条件的记录…由于需要获取全部字段，每次二级索引树上获取到符合条件的数据后都需要到主键索引上进行回表…回表操作执行了一百万多次」

## 一句话总述
深度分页慢在两件事：**先扫描并丢弃 offset 之前的百万行**，且**每扫描一行就要回表一次**取完整字段；`LIMIT 1000000,10` 实测比 `LIMIT 0,10` 慢一个数量级。

## 面试官视角
P6 会说「offset 越大越慢」；P7 要能拆出**两段代价**（扫描 + 回表）并给出量化解释：为什么取 10 行却要付出百万行的代价，以及「丢弃前 100 万条」这个动作本身不产生结果却是必需成本。

## 主问答
**Q（面试官原话）：** 同样取十条数据，为什么 LIMIT 1000000,10 比 LIMIT 0,10 慢这么多？

1. **实测对比**：`LIMIT 0,10` 耗时**一百多毫秒**，而 `LIMIT 1000000,10` 耗时**一秒六百五十毫秒** `[源码]`。
2. **扫描路径**：name 是普通索引，查询会**从二级索引树扫描符合条件的记录** `[源码]`。
3. **命中量大**：示例表中记录都以 name 开头，因此**扫描到的前一百万条都是符合条件的** `[源码]`。
4. **回表代价**：查询需要全部字段（`SELECT *`），所以**每在二级索引树取到一条符合条件的数据，就要到主键索引树回表一次** `[源码]`。
5. **回表次数**：因此需要**一百万零一百次回表**，之后才丢弃前一百万条并返回 `[源码]`。
6. **耗时两块**：一是**扫描一百万多条数据**，二是**对这一百一十多万条数据执行回表** `[源码]`。
7. **本质结论**：offset 并不「跳过」数据，而是**先取出再丢弃**，代价随 offset 线性增长 `[经验]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| MySQL 5.x / 8.0 | 执行机制一致 | offset 大即慢，与版本无关 |
| InnoDB | 二级索引叶子存主键值 | 取非索引列必然回表 |
| 所有版本 | 优化器行为 | 大 offset 可能放弃索引走全表 |
| 所有版本 | 业务侧 | 应限制最大翻页深度 |

## 关键代码
```sql
-- 建表：id 主键，name 普通索引，age 普通列
CREATE TABLE userbig (
  id   BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(64),
  age  BIGINT,
  KEY idx_name (name)
);

-- 浅分页：只扫描少量记录，约 100+ ms
SELECT * FROM userbig WHERE name LIKE 'name%' LIMIT 0, 10;

-- 深度分页：扫描并回表百万行后丢弃前 1000000 条，约 1650 ms
SELECT * FROM userbig WHERE name LIKE 'name%' LIMIT 1000000, 10;

-- 观察执行计划：确认是否走 idx_name、是否出现大量回表
EXPLAIN SELECT * FROM userbig WHERE name LIKE 'name%' LIMIT 1000000, 10;
```

## 总结与追问预判
**题眼是「offset 不跳过，只是取出后丢弃」**。追问常是「那怎么办」——两条主线：用覆盖索引消掉回表（见 1246），或用 id 游标直接跳过已读区间（见 1246）。

## ⚠️ 原文纠错
1. 事实核校：普通索引从二级索引树扫描、需要全部字段必须回表、回表百万次、耗时分扫描与回表两块、offset 为取出后丢弃——均与 InnoDB 索引机制一致 `[经验]`。
2. 补充：原文说「一百万零一百次回表」是基于示例数据（前百万条全部命中过滤条件）的推算；实际回表次数取决于**满足 WHERE 条件的行数**，若过滤性强则远小于该值 `[经验]`。
3. 崩坏词归一：源码将索引、主键、回表、偏移量等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
