> 原文锚点：第 13~32 段「映射及其指针可作内嵌类型…无名非指针类型(切片·映射)不能作为内嵌字段…未命名类型需type起名才能嵌」

## 一句话总述
"未命名类型（unnamed composite type）"——切片 `[]T`、映射 `map[K]V`、数组 `[N]T`、函数 `func(...)`、通道 `chan T` 等——**不能直接作内嵌字段**，因为嵌入字段要求"类型名 T"，而未命名类型没有名字；**用 `type` 给它们起名变成具名类型后即可嵌入**。map 本身（具名后）及其指针可嵌，但裸 `map[...]...` 字面量不行。

## 面试官视角
考察你是否理解"具名 vs 未命名"这一底层区分。面试官常拿 `[]int` 当陷阱：你说"切片能嵌吗"，答"先 type 起名就能"才显功力。

## 主问答
**Q（面试官原话）：** 切片、映射这种类型能直接内嵌吗？

**A：**

1. **未命名类型不能直接嵌**：嵌入字段必须是"类型名 T"，而 `[]int`、`map[string]int`、`[3]int`、`func()`、`chan int` 都是**未命名复合类型**，没有类型名，直接写进结构体字段会编译报错。
2. **type 起名后即可嵌**：`type Ints []int`、`type Dict map[string]int`，再嵌入 `Ints`/`Dict` 就合法——此时它们已是具名类型。
3. **map 的特殊性**：`map` 具名化后可嵌（含其指针）；但裸 `map[K]V` 字面量不行；接口/结构体是具名的所以原生可嵌，无需额外起名。

## 版本与兼容性
- 具名/未命名区分自 Go 1.0 起稳定；`type` 定义的新类型即使底层是复合类型也会获得独立类型名，可嵌入。

## 关键代码
```go
// 裸未命名类型：编译报错（embedded type must be a named type）
// type Bad struct { []int }
// type Bad2 struct { map[string]int }

// 起名后合法
type Ints []int
type Dict map[string]int
type Handler func(int) error
type A struct {
    Ints     // 具名切片 ✓
    Dict     // 具名映射 ✓
    Handler  // 具名函数类型 ✓
}
```

## 总结与追问预判
- 口诀：**裸复合类型无名字→不能嵌；type 起名→就能嵌**。
- 预判追问："那为什么结构体不用 type 也能嵌？"→ 结构体字面量 `struct{...}` 虽未命名，但写成 `type T struct{...}` 已是具名；裸 `struct{...}` 同样不能嵌。
