# 1110 切片截取共享底层数组

> 分类：Go 语言基础 | 难度：L2 | 题型：原理题 | 频率：高 | 关键词：**切片截取**/**底层数组共享**/**互相影响**
> 原文锚点：第 1~15 段「切片截取共享底层数组…修改一个影响另一个」

## 一句话总述
切片截取（`s2 := s1[a:b]`）与原切片**共享同一块底层数组**；任一方改元素，另一方**同步可见**——这是"克隆切片"必须先理解的前提，也是最常见的切片 bug 来源。

## 面试官视角
- 考察意图：是否理解切片截取只是"换了个 header 指向同一底层数组"，而非复制数据。
- 分档：P5 知截取后改一个会影响另一个；P6 能讲清"共享底层数组、header 各自独立"；P7 能讲扩容换地址脱钩。
- 红旗答案：以为 `s2 := s1[0:4]` 会得到独立副本。
- 惊艳点：点出 **header(len/cap) 各自独立、但底层数组 ptr 共享**——这是 slice 语义的核心 `[经验]`。

## 主问答
**Q（面试官原话）：** 切片截取之后，改一个切片另一个会变吗？
**A：**
1. **结论**：会——截取后的切片和原切片共享底层数组，改元素互相影响。
2. **机制**：`s2 := s1[0:4]` 让 s2 的 ptr 指向 s1 的底层数组；`s1[0]=1` 之后 `s2[0]` 也变成 1，反之亦然。
3. **边界**：只有"底层数组"共享，**header 的 len/cap 是各自独立**的。一旦某一方 append 触发**扩容换地址**，两者就脱钩（见 1110 / 1110-append-clone）。

**加分层：** 正因为共享，很多"以为拿到独立子切片"的代码会意外污染原切片——克隆时务必切断底层共享。

## 关键代码
```go
s1 := []int{0, 0, 0, 100}
s2 := s1[0:4]   // 共享底层数组
s1[0] = 1
fmt.Println(s2[0]) // 1 —— 改 s1 影响 s2
```

## 总结与追问预判
切片截取只换 header、不复制数据，所以共享底层、互相影响。追问接"append 覆盖原切片"与"如何用 copy/append 真正克隆"。
