> 原文锚点：第 42~45 段「删除文件空间没回收的另一种情况：硬链接…文件有硬链接指向它，删原文件只要还有硬链接指向，磁盘空间就不释放…删完所有硬链接才释放」

## 一句话总述
`rm` 后空间不释放的又一类原因：**文件还有硬链接**。硬链接与原文件共享同一 inode，删除任意一个只是把 inode 的硬链接计数减 1；**只有最后一个硬链接被删（计数归零），数据块才释放**——删"原文件"但留着硬链接，空间照旧占着。

## 面试官视角
考察 inode 引用计数本质。面试官想看你是否分得清硬链接（同 inode）与软链接（独立 inode），以及能否说出"删到 link count=0 才释放"。

## 主问答
**Q（面试官原话）：** 删了文件磁盘还是没回收，会不会跟硬链接有关？

**A：**

1. **机制：硬链接共享 inode**：硬链接是同一 inode 的另一个目录项，删除文件（`unlink`）只是把对应目录项移除并把 inode 的硬链接计数 −1；只要计数 >0，inode 与数据块就保留，空间不释放。
2. **定位：看硬链接数**：`ls -l` 第 2 列（link count）>1 说明还有别的硬链接；`find / -samefile file` 或 `find / -inum <ino>` 可找出所有指向该 inode 的硬链接路径。
3. **回收：删光所有硬链接**：把其余硬链接也 `rm` 掉，计数归零后数据块才释放；若只删"原文件"留着硬链接，空间一直占着。软链接则不影响（它是指向路径的独立 inode）。

## 版本与兼容性
- 硬链接计数即 inode `i_nlink`；POSIX 规定 `unlink` 后 `i_nlink` 归零且无进程打开才释放数据块（进程占用见 1815）。
- 软链接（`ln -s`）有独立 inode，删除软链接不影响目标文件占用；跨文件系统只能用软链接。

## 关键代码
```go
// 演示硬链接：删除硬链接需计数归零才释放（用 Go 创建并验证）
func hardlinkDemo(orig, link string) error {
    if err := os.Link(orig, link); err != nil { // 创建硬链接，i_nlink++
        return err
    }
    // 删除其中一个：i_nlink--，只要还有硬链接指向，数据块不释放
    if err := os.Remove(orig); err != nil {
        return err
    }
    // 必须再删 link，i_nlink 归零且无进程打开，空间才真正回收
    return os.Remove(link)
}
```

## 总结与追问预判
- 口诀：**硬链接同 inode，删一不减块；链尽计数零，空间才回头**。
- 预判追问："硬链接和软链接对释放的影响差在哪？"→ 硬链共享 inode 需删光，软链独立 inode 删除即脱钩（见 1814）。
