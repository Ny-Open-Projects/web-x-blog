# 1822 用户态↔内核态切换的四步流程

> 分类：操作系统 / 内核 | 难度：L1~L2 | 题型：流程题 | 频率：中 | 关键词：**系统调用**/**上下文保存**/**调用号**/**软中断**/**特权级**

> 原文锚点：第 1~12 段「特权操作需转内核态…syscall 指令发起…保存上下文到栈…按调用号找内核函数…返回恢复现场…软中断实现」

## 一句话总述
唯一合法通道是**系统调用**，四步走：① 用户程序经系统调用接口（`syscall` 指令/libc 封装）发起请求；② CPU 把用户态上下文（寄存器、程序计数器）**保存**，切换到内核态；③ 内核按**系统调用号**定位并执行对应内核函数（open/brk/…）；④ 结果写回、**恢复**用户现场、切回用户态。Linux 上由**软中断/陷入指令**触发——内核态权限高、用户态受限，切换由内核统一管理以保证安全与稳定。

## 面试官视角
- 意图：1820 的空间概念之后，考「切换怎么发生」——能否步骤化讲出陷入-执行-返回的机制与代价。
- 分档：P5 知两态与系统调用；P6 报全四步；P7 能讲软中断/陷入指令演进、切换开销量化与性能含义。
- 红旗答案：把用户态/内核态切换与进程上下文切换混为一谈；说不出「按调用号查系统调用表」。
- 惊艳点：量化切换代价——单次 syscall 几十 ns，比普通函数调用贵几十倍；高频路径（getpid/time）内核用 vDSO 免陷入 [经验]。

## 主问答
**Q（面试官原话）：** 用户态和内核态是如何切换的？

**A：** 触发前提：应用要做特权操作（访问硬件、申请内存、读写文件）——只有内核能做，只能切过去。四步 [实测]：

1. **发起系统调用**：用户态程序通过系统调用接口——`syscall` 指令（或 libc 封装函数）请求特权操作。
2. **保存上下文并切换**：CPU 将当前用户态现场（寄存器值、程序计数器）保存，**切换到内核态**（特权级翻转），转到内核栈执行。
3. **内核执行**：内核根据**系统调用号**在系统调用表中找到对应函数执行——打开文件、分配内存等。
4. **返回用户态**：执行完把结果放回约定位置，**恢复用户程序现场**，切回用户态继续运行。

补充两点：Linux 的系统调用经**软中断/陷入机制**进入内核（传统 `int 0x80`，现代 CPU 用专用 `syscall` 指令更快）；切换是**特权模式切换**而非进程切换——同一进程内完成，比进程上下文切换轻得多。

## 关键代码
```go
package main

import (
	"os"
	"runtime"
	"time"
)

func plain(n int) int { return n + 1 } // 纯用户态：不陷入内核

func main() {
	const N = 200000
	t0 := time.Now()
	x := 0
	for i := 0; i < N; i++ {
		x = plain(x)
	}
	d1 := time.Since(t0)

	t0 = time.Now()
	pid := 0
	for i := 0; i < N; i++ {
		pid = os.Getpid() // 每次都触发一次系统调用
	}
	d2 := time.Since(t0)
	_ = pid
	runtime.KeepAlive(x)
	println("plain fn :", d1.Nanoseconds()/N, "ns/op")
	println("getpid   :", d2.Nanoseconds()/N, "ns/op")
}
```

[实测] 输出：`plain fn: 0 ns/op`（被编译器内联，亚 ns 级）、`getpid: 28 ns/op`——**单次系统调用几十 ns、比普通函数调用贵几十倍**，这就是「高频小调用走 vDSO / 批量化（io_uring）」的代价依据。

## ⚠️ 原文纠错
1. 术语核校： [经验] 原文将 syscall 音转为「caceco」、「寄存器」音转为「计算器」、「程序计数器」音转为「程序计时器」，本卡统一为规范术语，不列举原词。
2. 事实核校： [经验] 原文「上下文保存到用户态的栈中」不准确——系统调用陷入时现场保存在**内核栈**（每进程/线程配对的内核栈）中，用户栈内核不可信赖；「唯一能做到的只有系统调用」也应补上中断/异常两条进入路径（系统调用是主动陷入，中断异常是被动进入）。
3. 事实核校： [经验] 「Linux 系统调用通过软中断实现」是传统答案——x86-64 现代 Linux 用 `syscall` 专用指令（非 int 0x80 软中断）进入内核，更快；面试答「软中断/陷入机制实现，现代 CPU 有专用指令」两头都稳。
