# 1234 行锁基础：共享锁与排他锁

> 分类：MySQL 锁 | 难度：中 | 题型：原理 | 频率：高 | 关键词：**行锁、S 锁、X 锁、存储引擎、UPDATE/DELETE 自动加锁**

> 原文锚点：第 1~20 段「行锁的实现与 S/X 锁语义」

## 一句话总述
行锁在存储引擎层（非服务器层）实现，主要有共享锁（S，读锁）与排他锁（X，写锁）：S 与 S 兼容，X 与任何锁都不兼容。UPDATE/DELETE 会自动对涉及行加 X 锁，也可显式用 `FOR UPDATE` 加锁；行锁只在事务内有效，不同资源的行锁互不冲突，但易引发死锁。

## 面试官视角
行锁是 MySQL 并发的基石题。考官看你能不能讲清「S 兼容 S、X 不兼容任何」这条互斥矩阵，以及「行锁在引擎层、UPDATE/DELETE 自动加 X」。能点出「行锁只在事务内有效」的人更稳。

## 主问答
**Q（面试官原话）：** 什么是行锁？共享锁和排他锁有什么区别？

1. **实现位置**：行锁由存储引擎（如 InnoDB）实现，服务器层不感知细节；不同引擎可实现不同行锁语义。
2. **S 与 X 语义**：共享锁（S，读锁）允许多事务同时持有，用于保护读；排他锁（X，写锁）只允许一个事务持有，用于保护写。
3. **互斥矩阵**：S 与 S 兼容；X 与 S、X 都不兼容（一事务持 X，其他事务既拿不到 S 也拿不到 X，全部阻塞）。
4. **自动加锁**：执行 UPDATE/DELETE 时引擎自动对行加 X 锁；也可显式 `SELECT ... FOR UPDATE` 加 X 锁。行锁仅对「同一事务」内的操作生效，不同资源的行锁不冲突。

## 版本与兼容性
| 锁 | 兼容 S | 兼容 X |
|----|--------|--------|
| S 锁 | 是 | 否 |
| X 锁 | 否 | 否 |

## 关键代码
```sql
BEGIN;
UPDATE t SET a=1 WHERE id=1;   -- 自动对 id=1 加 X 锁
SELECT * FROM t WHERE id=1 FOR UPDATE;  -- 显式 X 锁
```

## 总结与追问预判
核心：**行锁在引擎层，S 兼容 S、X 不兼容任何，UPDATE/DELETE 自动 X 锁、仅事务内有效**。追问常拐向「读要不要加锁」（见 1234）或「自增怎么保证不冲突」（见 1234）。
