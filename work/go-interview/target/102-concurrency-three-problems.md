# 102 并发编程三大共性问题（分工 / 同步 / 互斥）

> 分类：Go 并发模型 | 难度：L3 | 题型：概念题 | 频率：高 | 关键词：**分工** / **同步** / **互斥** / **并发安全** / **并发原语**
> 原文锚点：第 1~15 段「并发三类共性问题：分工/同步/互斥；Go 对应原语」

## 一句话总述
并发编程有三类共性问题：**分工**（任务分解分配，提效）、**同步**（线程/协程间协作通知）、**互斥**（共享资源访问控制，保证并发安全）；Go 用 channel+条件变量做同步，用锁+原子做互斥。

## 面试官视角
- 意图：考察对"并发到底在解决什么"的结构化认知，而非只会背 API。
- 分档：P5 知锁防并发安全；P6 能分述三问题；P7 能映射到 Go 原语并讲清各自目标。
- 红旗：把并发等同于"加锁"，遗漏分工与同步。
- 惊艳点：点出"分工/同步讲性能，互斥讲正确性"——二者目标不同，不能互相替代。

## 主问答
**Q（面试官原话）：** 并发编程要解决的共性问题有哪些？
**A：**
1. **分工**：把任务拆成子任务分给不同线程/协程，目标是提高执行效率与资源利用率（如 DB 服务分线程管读写/监控）。
2. **同步**：线程/协程间依赖时的协作通知（如线程二等线程一的数据），Go 用 **channel** 或**条件变量**实现。
3. **互斥**：多执行体访问同一共享资源时，任一时刻最多一个占用，防并发修改致数据不一致——即并发安全，Go 用 **读写锁/互斥锁/原子操作**实现。
4. **目标差异**：分工与同步强调性能，互斥强调数据正确性与一致性。
