# 1711 复杂度分析法与大 O 的近似边界 深挖

> 覆盖源 17-11 全文：衡量执行效率的两个指标、大 O 表示法的推导假设（每行耗时相同 → 耗时正比于执行次数）、大 O 描述的是增长趋势而非真实耗时、三条分析规则（只关注最大阶 / 相加取最大 / 嵌套相乘）、空间复杂度即渐进空间复杂度并以"变量常量阶 + 切片 O(n)"为例。主卡已给结论与可运行示例，本附录做「这个近似假设牺牲了什么」「三条规则的推导」「大 O 会骗人的四个场景」「复杂度 vs 实测怎么配合」「答题分层」五层深挖。

## 思路与架构

```text
推导链
CPU 视角(读-算-写) → 假设每行耗时相同 → 耗时 ∝ 执行次数
        → 用"执行次数"代换"执行时间" → 只保留最大阶 → 大 O

三条规则
├─ 只关注循环次数最多的那段(常量/低阶/系数全忽略)
├─ 顺序多段: 相加取最大阶  O(n)+O(n²) = O(n²)
└─ 嵌套: 内外相乘          O(n) × O(n)  = O(n²)
```

## 方案取舍
- **这个假设牺牲了什么**：真实 CPU 上，一次除法、一次 cache miss、一次分支预测失败的代价天差地别，绝不可能"每行耗时相同"。但这个近似之所以成立，是因为它的用途是**横向对比不同算法的量级**，而不是预测绝对耗时——**只要 n 足够大，量级的差异会碾压所有常数因子**。所以正确的用法是：**用大 O 排除掉量级上不合适的方案，再用实测在剩下的候选里挑**。反过来拿大 O 去预测毫秒数，就是用错了工具 [经验]。
- **三条规则是从"忽略低阶"这一条推出来的**：相加取最大阶，是因为 `n² + n` 在 n 变大时 `n` 的贡献趋近于 0；嵌套相乘，是因为内层每被执行一次就要完整跑一遍，外层跑 n 次就是 n 遍内层。**理解了"忽略低阶"是根，三条规则就不用死记** [经验]。
- **大 O 会骗人的四个场景**：① **小数据量**——`O(100n)` 在 n=10 时比 `O(n²)` 慢很多，很多库在小切片上专门用插入排序就是这个道理；② **常数因子巨大**——同样是 O(n)，一次内存顺序扫描与一次随机访问在 cache 命中率上能差一个数量级；③ **不区分情形**——`append` 说 O(1) 是**均摊**结论，触发扩容那一次是 O(n)；快排说 O(n log n) 是**平均**，基准选得差就退化成 O(n²)；④ **只看时间不看空间**——很多"快"的算法是靠预分配大块内存换来的，在内存受限环境反而不合适 [经验]。
- **复杂度与实测是配合关系不是替代关系**：工程上的正确顺序是——先用复杂度**筛掉量级不合适的实现**（比如把 O(n²) 换成 O(n log n)），再用 benchmark 在同量级的候选里做常数级优化。**跳过第一步直接 micro-optimize，是在错误的量级上做无用功**；反过来只用复杂度不用实测，又会在常数因子上吃亏 [经验]。
- **空间复杂度的口径要提前说清**：业界默认是**额外（辅助）空间**，不含输入本身。若不提前声明，讨论"这个算法是 O(1) 空间"时就会出现一方算输入、一方不算输入的鸡同鸭讲。递归算法还容易漏掉**调用栈**——快排虽是原地排序、数据空间 O(1)，但递归栈在 O(log n)~O(n) 之间 [经验]。

## 答题技巧
- 开口先讲**推导链**（CPU 读算写 → 假设每行同耗时 → 耗时正比次数 → 只留最大阶 → 大 O），比直接背定义更显功底 [经验]。
- 一定要强调**「大 O 不是真实耗时，是增长趋势」**——这是本题的地基句 [经验]。
- 被问"一亿次循环是什么复杂度"→ 立刻答 **O(1)**，并补一句"它不随 n 变化，但它本身很慢" [经验]。
- 主动补**情形限定**：均摊 / 平均 / 最坏，说复杂度不带情形是常见的减分项 [经验]。
- 收尾给方法论：**先用复杂度筛量级，再用实测挑常数**，一句话把"理论与工程怎么配合"讲清楚 [经验]。
- 主动边界到 `1717-complexity`（快排的平均/最坏复杂度与递归栈空间的具体结论）、`171-dsa-interview-prep`（数据结构与算法备考地图），本卡只给**通用估法** [边界]。

## 细节与核心 API

```go
// 归并排序：T(n)=2T(n/2)+O(n) -> O(n log n)
func mergeSort(a []int) []int {
    if len(a) <= 1 { return a }
    mid := len(a) / 2
    l, r := mergeSort(a[:mid]), mergeSort(a[mid:])
    out := make([]int, 0, len(a))
    for len(l) > 0 || len(r) > 0 {
        if len(r) == 0 || (len(l) > 0 && l[0] <= r[0]) { out = append(out, l[0]); l = l[1:] } else { out = append(out, r[0]); r = r[1:] }
    }
    return out
}
// 大 O：描述增长上界（忽略常数与低阶）；Ω 下界；Θ 紧界
// 近似边界：同规模下 O(n log n) 远优于 O(n^2)；但常数大的 O(n log n) 在小 n 可能慢于优化后的 O(n^2)
// 工程取舍：n<~16 时插入排序常数更小；多数标准库排序用 introsort（快排+堆排+插入）
// 递归复杂度：主定理 T(n)=aT(n/b)+f(n)；平摊分析（如动态数组 append 均摊 O(1)）
```
