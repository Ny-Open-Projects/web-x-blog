# 806 追踪式 GC 的六种细分实现

> 分类：Go/运行时 | 难度：L3 | 题型：综述题 | 频率：高 | 关键词：**标记清除** / **标记整理** / **复制** / **分代** / **增量** / **并发**
> 原文锚点：第 28~40 段「追踪式细分：标记清除（两步/碎片）、标记整理（搬连续区清碎片）、复制（两半区/废一半内存）、分代（按存活时间/年轻代复制老年代标记）、增量（拆小步交替降停顿增总开销）、并发（并行降 STW 增同步复杂度）」

## 一句话总述
追踪式 GC 按"**怎么标记、标记后怎么处理、要不要分代、要不要并发**"可细分为六种：标记清除、标记整理、复制、分代、增量、并发。前三种解决"碎片 vs 内存利用率"，后三种解决"停顿时间（STW）"。**Go 实际采用的是"并发 + 非分代 + 非移动"的三色标记清除**——从六者中取了交集的一角。

## 面试官视角
- 意图：考察能否把追踪式 GC 的演进脉络**串成一张谱系图**，而不是只会背某一个算法。
- P5 能说出其中 2~3 个；P6 能讲清标记清除/标记整理/复制三者的碎片取舍；P7 能点出"增量与并发都是为降 STW、但代价不同（增总开销 vs 增同步复杂度）"。
- 红旗：以为六种是互斥的（实际可组合，如"分代+并发"）；把 Go 说成用了复制或分代。
- 惊艳点：点出"Go 非分代非移动、只取并发三色标记清除"，并说明为什么（见 806-go-why-no-generational）。

## 主问答
**Q（面试官原话）：** 追踪式 GC 有哪些细分实现？各有什么特点？
**A：**
1. **结论**：追踪式按实现策略分为六种——①标记清除 ②标记整理 ③复制 ④分代 ⑤增量 ⑥并发。
2. **机制（前三种：碎片 vs 内存）**：
   - **标记清除**：只做标记+清除两步，最简单，但回收产生**内存碎片**（见 807-gc-mark-sweep）。
   - **标记整理**：标记后把存活对象搬到连续内存区，再清掉剩余空间，**消除碎片**，但搬移成本高。
   - **复制**：堆分两等半区，只用一半，存活对象复制到另一半再清空原半区，**无碎片但浪费一半内存**。
3. **机制（后三种：停顿时间）**：
   - **分代**：按存活时间分代（年轻/老年/永久），年轻代用复制、老年代用标记清除/整理，针对"多数对象短命"假设优化。
   - **增量**：把标记清除拆成多个小步，与用户代码**交替**执行，**降停顿但增总开销**。
   - **并发**：GC 与用户代码**并行**执行，**进一步降 STW 但需处理同步问题、增实现复杂度**。
4. **边界（Go 的选择）**：Go 取"**并发 + 非分代 + 非移动（不整理）**"的三色标记清除（见 806-go-why-no-generational / 807-gc-tricolor），而非六者全用 `[经验]`。

## 总结与追问预判
- 六种：标记清除/标记整理/复制（碎片取舍）+ 分代/增量/并发（停顿取舍）；Go 取并发+非分代+非移动。
- 预判：标记清除单点 → 见 807-gc-mark-sweep；三色标记 → 见 807-gc-tricolor；Go 不用分代 → 见 806-go-why-no-generational。
