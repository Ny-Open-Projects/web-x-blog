# 712 ants 池：把 goroutine 数量关进笼子

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**ants、协程池、worker 复用、Submit、Release**

> 原文锚点：第 73~88 段「实例化一个协程池，size 是五…往池里丢任务…释放掉」

## 一句话总述
ants 是高性能 goroutine 池：用 `NewPool(size)` 限定并发上限，`Submit` 投递任务，复用 worker 避免反复创建销毁，从而把 goroutine 数量压到可控范围。

## 面试官视角
P6 会用 `Submit` 就够；P7 要讲清三件事：**为什么需要池**（批量文件处理这类任务不控制数量会耗尽句柄与内存）、**释放时机**（线上通常进程退出时才 Release，不是函数结束）、**池满行为**（默认阻塞排队，可配非阻塞与最大排队数）`[经验]`。

## 主问答
**Q（面试官原话）：** goroutine 很轻量，为什么还要用池？

1. **轻量不等于无限**：原文场景——批量读文件处理，单文件耗时较长，全部丢进 goroutine 会耗尽句柄与内存 `[经验]`。
2. **池做两件事**：限制同时运行的任务数量、复用已创建的 worker，省掉反复的创建与调度开销 `[源码]`。
3. **API 就三步**：`NewPool(size)` 建池、`Submit(func())` 投递、`Release()` 释放；`defer Release()` 是演示写法 `[实测]`。
4. **释放时机看业务**：线上常驻场景一般到程序退出才释放，短任务才在函数结束即释放 `[经验]`。

## 关键代码
```go
p, _ := ants.NewPool(5) // 最多 5 个 worker 同时跑
defer p.Release()
for i := 0; i < 100; i++ {
	i := i
	_ = p.Submit(func() {
		time.Sleep(100 * time.Millisecond)
		atomic.AddInt32(&counter, 1)
		fmt.Println("task", i)
	})
}
```
> 验证：日志中始终"每次五个一批"推进，结束后 counter 为 100；goroutine 数从峰值回落 `[实测]`。

## 总结与追问预判
**池的价值是削峰与复用，不是提速**。下一步会问怎么知道任务跑完了、goroutine 数怎么监控。
