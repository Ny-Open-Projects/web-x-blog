# 1015 用 channel 实现互斥锁：容量必须是 1

> 分类：并发模型 | 难度：L3 | 题型：编码题 | 频率：中高 | 关键词：**channel 锁、容量 1、空结构体、加锁即写入、解锁即读出**

> 原文锚点：第 1~17 段「我们定义了一个 channel，它的缓冲大小为一，这里缓冲容量大小必须是一…写入的动作是加锁，读取的动作是解锁」

## 一句话总述
用**容量为 1 的缓冲 channel** 当锁：往里写一个空结构体等于加锁，从中读出等于解锁；容量被占时其他写入方阻塞，互斥就此成立。

## 面试官视角
P6 知道"channel 能当锁"；P7 要说出**容量必须是 1 的原因**——容量大于 1 时多个 goroutine 都能写入，互斥失效 `[源码]`。加分点：用 `struct{}{}` 而非 bool，因为**空结构体不占内存**，传的是信号不是数据 `[经验]`。

## 主问答
**Q（面试官原话）：** 怎么用 channel 写一个互斥锁？为什么缓冲要设成 1？

1. **定义容量 1 的 channel**：声明一个缓冲容量为 1 的通道，元素类型用 `struct{}{}`，避免承载无意义的数据 `[源码]`。
2. **写入即加锁**：访问共享变量前先向 channel 写入一个元素；此时通道容量被占，其他 goroutine 再写入就会阻塞在写这一行 `[实测]`。
3. **读出即解锁**：操作完成后从 channel 读出该元素，容量释放，被阻塞的下一个写入方才被唤醒并成功写入 `[源码]`。
4. **容量为什么是 1**：容量为 1 时同时只有一方能写入；若容量大于 1，多个 goroutine 都能写进去，**互斥直接失效** `[经验]`。
5. **正确性可验证**：1000 个 goroutine 各自自增，配合等待组同步，最终计数恰好是 1000 `[实测]`。

## 关键代码
```go
type ChanMutex struct{ ch chan struct{} }

func NewChanMutex() *ChanMutex { return &ChanMutex{ch: make(chan struct{}, 1)} }
func (m *ChanMutex) Lock()     { m.ch <- struct{}{} }   // 容量被占则阻塞
func (m *ChanMutex) Unlock()   { <-m.ch }               // 释放后唤醒下一个写入方
```
> 验证：1000 个 goroutine 各做一次自增，最终 `counter=1000`；把容量改成 2 后结果随即乱掉 `[实测]`。

## ⚠️ 原文纠错
1. 事实核校：原文"写入是加锁、读出是解锁"准确；补充——**容量必须为 1**，这是互斥成立的前提，原文虽提到但容易被当成可选细节 `[源码]`。
2. 补充：原文示例未处理异常路径，工程上应把解锁放进 `defer`，否则临界区 panic 会造成**永久阻塞** `[经验]`。
3. 崩坏词归一：源码将 channel、goroutine、互斥锁、等待组等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
