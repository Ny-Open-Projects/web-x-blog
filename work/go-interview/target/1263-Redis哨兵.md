# 1263 Redis 哨兵：两轮投票选主与 quorum 配置

> 分类：Redis/高可用 | 难度：L3 | 题型：方案题 | 频率：高 | 关键词：**两轮投票**/**哨兵leader**/**quorum**/**半数以上**/**误判脑裂**
> 原文锚点：第 15~33 段「第一轮判断主下线(主观→客观) + 第二轮选哨兵leader(半数+≥quorum) + quorum建议n/2+1避免误判脑裂」

## 一句话总述
哨兵选主分**两轮投票**：第一轮由哨兵发起命令、其他按网络状况投票，赞成达 **quorum** 即把主标为客观下线；第二轮从哨兵中选 **leader** 执行故障转移，leader 需「半数以上赞成票 **且** ≥ quorum」。quorum 建议设为 `n/2+1`（n 为哨兵数），避免设 1（过敏误判）或过大（反应迟钝），在灵敏度与误判/脑裂间权衡。

## 面试官视角
- 考察意图：能否讲清两轮投票的票数规则，以及 quorum 配置的权衡。
- 分档：P5 知要投票选 leader；P6 能说 quorum 规则；P7 知 `n/2+1` 建议、quorum=1 风险、挂 1 哨兵仍可用的最小部署。
- 红旗答案：认为 quorum=1 安全（单哨兵网络抖动即误转移）；忽略 leader 需「半数+quorum」双条件。
- 惊艳点：点出「quorum=2 至少布 3 哨兵、挂 1 个剩 2 个仍能拿 2 票；只布 2 个挂 1 个永远凑不齐」 [经验]。

## 主问答
**Q（面试官原话）：** 哨兵怎么选主？quorum 怎么设？
**A：**
1. **第一轮（定下线）**：哨兵判断主观下线后向其他发起命令，其他按网络状况赞成/拒绝，赞成票达 **quorum** → 客观下线 [经验]。
2. **第二轮（选 leader）**：想当 leader 的哨兵需「**半数以上赞成票** 且 **票数 ≥ quorum**」两条件同时满足才当选，由其执行故障转移 [经验]。
3. **quorum 配置**：避免设 1（过敏误判触发不必要转移）；建议 `n/2+1`（超半数共识才动），权衡灵敏度与误判/脑裂；quorum=2 至少布 3 哨兵 [经验]。

## 总结与追问预判
quorum 是哨兵「灵敏度 vs 稳定性」的总开关。`n/2+1` 保证只有超半数哨兵共识才转移，是抗脑裂的推荐基线。

```go
// quorum 与 leader 当选判定（哨兵选举逻辑抽象）
func isLeaderElected(votes, totalSentinels, quorum int) bool {
    majority := totalSentinels/2 + 1       // 半数以上
    return votes >= majority && votes >= quorum // 双条件：半数 + 达到 quorum
}
// 推荐配置：quorum = n/2 + 1；例 n=3 → quorum=2，挂 1 个剩 2 仍能凑 2 票
// 反例：只布 2 哨兵 quorum=2，挂 1 个剩 1 个永远凑不齐 → 无法转移
// quorum=1 风险：单哨兵网络抖动即误判主观下线→客观下线→不必要转移
```
