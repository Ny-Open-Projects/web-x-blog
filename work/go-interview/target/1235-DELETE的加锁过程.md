# 1235 DELETE 的加锁过程

> 分类：MySQL 锁 | 难度：中 | 题型：原理 | 频率：中 | 关键词：**DELETE、X 锁、delete mark、REC_NOT_GAP、表 IS**

> 原文锚点：第 78~89 段「删除记录的加锁过程」

## 一句话总述
DELETE 先在 B+ 树定位目标记录，对其加 X 锁（记录锁 REC_NOT_GAP，只锁本行），再执行 delete mark 标记删除；定位阶段还会在表级加 IS 锁。REC_NOT_GAP 标记说明这是「普通记录锁」而非 next-key 锁。

## 面试官视角
DELETE 加锁是「更新/删除类」题的代表。考官看你能不能讲清「先定位加 X 锁、再标记删除」的两阶段，以及 REC_NOT_GAP 的含义。能区分「标记删除 vs 物理删除」更稳。

## 主问答
**Q（面试官原话）：** 执行一条 DELETE，MySQL 加了哪些锁？

1. **定位 + X 锁**：引擎从 B+ 树找到记录后，先对该记录加 X 锁（排他锁），保证删除期间别人不能改。
2. **delete mark**：加锁后执行「标记删除」（在记录头打删除标志），真正的物理回收由 purge 线程后续异步完成——所以删除后空间未必立即释放。
3. **表级 IS 锁**：定位阶段事务需在表上加意向共享锁（IS），表示即将在行上加锁。
4. **REC_NOT_GAP 含义**：该 X 锁类型是普通记录锁（只锁这一行），并非 next-key 锁——`REC_NOT_GAP` 即「不含间隙」的标记。

## 版本与兼容性
| 阶段 | 加锁 |
|------|------|
| 定位 | 表 IS + 行 X（REC_NOT_GAP） |
| 删除 | delete mark（purge 异步回收） |

## 关键代码
```sql
BEGIN; DELETE FROM t WHERE id=1;   -- 行 X 锁 + 表 IS
SELECT * FROM performance_schema.data_locks;  -- 看 REC_NOT_GAP
```

## 总结与追问预判
核心：**DELETE = 定位加 X(记录锁) + 标记删除 + 表 IS；物理回收靠 purge**。追问常拐向 next-key 锁与间隙锁（见 1235），或被问「为什么大表 DELETE 慢」。

## ⚠️ 原文纠错
1. 事实核校/补正： [经验] DELETE 先定位加 X 锁、再 delete mark、purge 异步回收、表级 IS、REC_NOT_GAP 为普通记录锁——均正确。但**源稿口播「删除操作需获取表中记录的 s 锁」为口误，实际对记录加的是 X 锁**（与后续「加一个 x」自洽），本卡以 X 锁为准。
2. 崩坏词归一：源码将 InnoDB / 行锁 / 事务 / 聚簇索引 等音译为崩坏词；本卡统一为规范术语。
