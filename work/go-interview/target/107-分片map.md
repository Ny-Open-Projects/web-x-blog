# 107 分片 map：用 FNV 哈希取模把一把大锁打散成 32 把

> 分类：Go 并发 | 难度：中高 | 题型：实现题 | 频率：中 | 关键词：**分片、sharding、FNV 哈希、取模、锁粒度、两层遍历、return 前解锁**

> 原文锚点：第 24~51 段「为了分散锁的力度，我们可以对 map 的元素进行分片存储…切片大小设置为三十二个…分片下标通过 key 对分片数量取模计算…FNV 哈希算法简单快速、特别适合对字符串哈希计算」

## 一句话总述
分片 map 把**一个 map 拆成 32 个分片**（用**切片**存放 32 个 map），**每个分片配一把独立的读写锁**，于是**锁的粒度从"整个 map"降到"分片级"**；分片号由 **key 经 FNV 哈希映射成整数后对分片数量取余**得到，**相同 key 必落同一分片、不同 key 被打散到不同分片**，从而获得更高并发性能。遍历则要**两层循环**（先遍历分片、再遍历分片内键值），且**锁必须加在循环内部**。一句话背法：**「分片 map：32 分片各配读写锁，FNV 哈希取模定位，锁粒度降到分片级」**。

## 主问答
**Q（面试官原话）：** 一把大锁太粗，怎么把锁粒度降下来？

**先铺垫（由浅入深第 1 层）**：大锁的痛点是"所有人抢同一把锁"。降粒度的思路是"把数据切成几堆，每堆自己一把锁"——这样只有访问同一堆的人才会互斥，访问不同堆的人并行无阻。关键是怎么切，才能让访问尽量分散、又不丢数据归属。

1. **结论（第 2 层）**：对 map 元素分片存储，用切片存放多个 map，对每个切片加锁，锁粒度从整个 map 降到分片级。
2. **分片数量（第 3 层）**：切片大小设为 32，即分成 32 个分片；初始化时先建长度 32 的切片，再循环把 32 个 map 声明好。
3. **定位分片·FNV 哈希（第 4 层）**：分片下标由 key 对分片数取模计算；key 是字符串需先映射成整数，用 **FNV 哈希**——简单快速、特别适合字符串。
4. **定位分片·取余（第 5 层）**：key 经 FNV 成整数后对分片数取余，余数即分片编号；相同 key 哈希值相同→同分片，不同 key 打散到不同分片。
5. **读写锁位置（第 6 层）**：读加读锁、写加写锁，锁在分片级。加分层：分片数取 2 的幂（如 32），取余可用位运算 `hash & (n-1)` 替代 `%`。
6. **遍历陷阱（第 7 层）**：遍历需两层循环（先分片、再分片内键值），锁放循环内部、每片操作完即释放；`break` 只跳出当前分片，`return` 才终止全部——但 `return` 前必须再解锁一次防泄漏。

## 关键代码
```go
package main

import (
	"fmt"
	"hash/fnv"
	"sync"
)

const shardCount = 32 // 分片数取 2 的幂，可用位运算替代取余

type shard struct {
	mu sync.RWMutex
	m  map[string]any
}

type ShardedMap []*shard

func NewShardedMap() ShardedMap {
	s := make(ShardedMap, shardCount)
	for i := range s {
		s[i] = &shard{m: make(map[string]any)}
	}
	return s
}

// getShard：FNV 把字符串映射成整数，再对分片数取余得到分片编号
func (s ShardedMap) getShard(key string) *shard {
	h := fnv.New32a()
	h.Write([]byte(key))
	return s[uint(h.Sum32())%shardCount]
}

func (s ShardedMap) Set(k string, v any) { // 写 -> 分片级写锁
	sh := s.getShard(k)
	sh.mu.Lock()
	defer sh.mu.Unlock()
	sh.m[k] = v
}

func (s ShardedMap) Get(k string) any { // 读 -> 分片级读锁
	sh := s.getShard(k)
	sh.mu.RLock()
	defer sh.mu.RUnlock()
	return sh.m[k]
}

// Range：两层遍历；锁必须在循环内部，每个分片操作完即释放
func (s ShardedMap) Range(f func(k string, v any) bool) {
	for _, sh := range s {
		sh.mu.RLock()
		stopped := false
		for k, v := range sh.m {
			if !f(k, v) {
				stopped = true
				break // 只跳出当前分片
			}
		}
		sh.mu.RUnlock()
		if stopped {
			return // 终止全部迭代（锁已在上面释放，安全）
		}
	}
}

func main() {
	sm := NewShardedMap()
	sm.Set("a", 1)
	fmt.Println("get a =", sm.Get("a")) // 1
}
```

## 总结与追问预判
**背这三句就够**：① **分片 map：32 个分片各配读写锁，锁粒度从整 map 降到分片级**；② **FNV 哈希把 key 映射成整数再取模定位分片，同 key 同分片、异 key 打散**；③ **遍历两层循环、锁在循环内部，return 前需再解锁；分片数取 2 的幂可用位运算**。
**预判追问**：
- 「分片数选多少？」→ 无固定答案，常见 32/64/128；太少仍竞争，太多内存+遍历开销升（见本卡加分层）。
- 「和 sync.Map 比？」→ sync.Map 读多写少最优且内部用类似分片；分片 map 胜在类型安全+可预测写性能（见 107 读写锁 map / 922）。
- 「channel 串行化呢？」→ 并发度恒 1，通常不如分片（见 107 用 channel 串行化）。
