# 1829 进程调度算法全景（深挖）

> 分类：OS 进程调度 | 难度：L4 | 题型：体系题 | 频率：高 | 关键词：**六算法**/**抢占原则**/**FCFS**/**SJF**/**RR**/**多级反馈队列**
> 原文锚点：第 1~59 段「进程调度算法」全景

## 思路与架构
本卡把 OS 进程调度按「**基础层 → 批处理层 → 分时层**」串起 `1829-scheduling-foundation`（定义/抢占vs非抢占/三原则）、`1829-batch-algorithms`（FCFS/SJF/HRRN）、`1829-modern-algorithms`（RR/最高优先级/多级反馈队列）三张主卡，并显式划边界。

- **基础层**：调度=选就绪进程给 CPU；非抢占(完成/阻塞让出) vs 抢占(可打断)；三原则=时间片/优先权/短作业优先；调度只影响等待时间。
- **批处理层**：FCFS 非抢占长作业饥饿；SJF 短者先不利长作业；HRRN 响应比=(等待+服务)/服务 兼顾长短。
- **分时层**：RR 时间片 20~50ms；最高优先级 静态/动态+抢占/非抢占+饥饿；多级反馈队列 结合 RR+优先级、未完成降级、兼顾长短。

## 方案取舍
| 算法 | 抢占 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| FCFS | 否 | 简单 | 长作业饥饿 | CPU 繁忙型 |
| SJF | 否/可 | 平均等待低 | 长作业饥饿、难预估 | 批处理 |
| HRRN | 否 | 兼顾长短 | 需算响应比 | 批处理 |
| RR | 是 | 公平、响应好 | 切换开销 | 分时 |
| 最高优先级 | 可选 | 重要任务优先 | 低优饥饿 | 多用户 |
| 多级反馈 | 是 | 兼长短作业 | 实现复杂 | 通用 |

- 选型主线：批处理重吞吐用 SJF/HRRN；交互分时重响应用 RR；通用系统用多级反馈队列。
- 与「饥饿」的权衡：优先权/最短作业都会饿死长作业，靠动态优先级(老化)或 HRRN 响应比自然回升化解。

## 答题技巧
- **必背六算法**：FCFS→SJF→HRRN→RR→最高优先级→多级反馈队列，顺序即由简到繁。
- **时间片数字**：RR 20~50ms 是高频送分点，且「太短切换多、太长响应差」必讲。
- **HRRN 公式**：(等待+要求服务)/要求服务，长作业等久响应比升——这是化解饥饿的关键。
- **显式边界**：Go runtime 的用户态调度（GMP，解决频繁用户态↔内核态切换的 CPU 利用率问题）见 805/`813-g`/`815-p`/`816-gmp`；本卡只讲 OS 进程调度理论，不重画 Go 调度器。

## 细节与核心 API

```bash
# 普通进程：CFS（完全公平调度器），按虚拟运行时间 vruntime 红黑树选最小
# 实时进程：SCHED_FIFO（抢占式，同优先级先到先跑，不时间片）/ SCHED_RR（轮转）
ps -eo pid,ni,cls,comm     # cls 看调度类（ts=CFS, ff=FIFO, rr=RR）
top -p <PID>               # 看优先级/调度
nice -n 10 cmd             # 调低普通优先级（nin -20~19，越小越优先）
renice -n 5 -p <PID>
chrt -p <PID>              # 看实时策略
chrt -f 50 cmd             # 设 SCHED_FIFO 优先级50（需 CAP_SYS_NICE）
# 演进：O(1) -> CFS（按公平而非固定时间片）；实时类独立于 CFS 保证确定性延迟
# 要点：CPU 密集型调 nice 降权；硬实时才用 FIFO/RR 且优先级谨防饿死普通进程
```
