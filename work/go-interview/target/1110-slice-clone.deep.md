# 1110 切片克隆深浅与性能深挖

## 思路与架构
克隆的本质是"得到一份**不共享底层数组**的新切片"。四条路径：
- **① 截取 `s[a:b]`**：共享底层（**不是克隆**，是陷阱，见 1110-slice-shared-backing）。
- **② `copy(dst, src)`**：覆盖式，dst 须 `make` 出长度，返回复制个数（见 1110-copy-clone）。
- **③ `append(dst, src...)`**：展开式，dst 须 `make(0, cap)` 只给容量，从 0 开始填（见 1110-append-clone）。
- **④ 三元表达式 `s[:0:0]`+append**：保留原切片 nil 语义的克隆（同上）。

关键机制：**是否共享底层数组，决定了改一个会不会影响另一个**；而 append 是否串扰原切片，取决于 cap 是否触发扩容（见 1110-append-overwrite / 1110-three-index-expr）。

## 方案取舍
- 要"独立副本"必走 ② 或 ③（或 ④）。② copy 语义清晰（覆盖、不追加），适合"已有目标切片、按位置覆盖"；③ append 适合"从空开始构建新切片"。
- **性能**：Go 1.15 之前 `append` 通常更快（少了覆盖判断）；**Go 1.15 起 `copy` 经 `memmove` 优化，通常更快**。但 32 位 vs 64 位、具体规模下差异很小（同量级），不必过度优化——**可读性优先**。
- **陷阱优先级**：最高频的两个坑是"截取后误当独立副本"和"给 make 了长度导致 append 接在默认值后"——面试最爱挖。

## 答题技巧
1. **先讲根因**：开口即"切片截取共享底层数组，克隆必须切断共享"。
2. **区分 copy（覆盖）vs append（追加）** 的语义差异，别混。
3. **三元表达式锁定 cap** 是隔离 append 串扰、安全截断的通用技巧，必提。
4. **反直觉点**：① append 原切片会覆盖原数据（共享+cap 够）；② `make([]T, len)` 给长度会让 append 接在默认值后；③ 原切片 nil 时普通 make 得空数组而非 nil，用 `s[:0:0]` 保语义。
5. **版本锚点**：Go 1.15 起 copy 经优化通常快于 append；Go 1.2 引入三元切片表达式。
