# 402 技术面试怎么准备才能事半功倍（总纲）

> 分类：面试方法论 | 难度：L2 | 题型：总纲题 | 频率：高 | 关键词：**五大范围**/**针对性准备**/**信息vs知识**/**主动检索**/**80-20法则**
> 原文锚点：第 1~43 段「技术面试五大范围(数据库与缓存/数据结构与算法/操作系统与网络/编程语言特性/项目经历)...针对性准备薄弱点与重点...信息≠知识需自己编码成记忆...主动检索...面试后复盘扩展到整个知识域...80%时间花在20%高频重点」

## 一句话总述
技术面试按**五大范围**准备：① 数据库与缓存（MySQL/Redis 必考，兼 MongoDB/ES、分布式与 CAP）② 数据结构与算法（大厂必备项、能否通过的分水岭）③ 操作系统与网络（Linux/IO 模型、TCP/HTTP）④ 编程语言特性（Go 的 GMP、GC、map 与 slice 扩容、堆栈内存分配、设计模式、并发与锁）⑤ 项目经历（高频考察点，STAR 提问法深挖）。核心方法是**针对薄弱点 + 针对重点考点**两手抓，用「思维导图折叠后自述、主动检索」把**信息编码成自己的知识**，面试后围绕漏题扩展复盘，把 80% 时间投到 20% 高频重点。

## 面试官视角
- 考察意图：看你准备是否有章法、能否分清主次，而不是盲目堆时间。
- 分档：P5 能列五大范围；P6 能说针对性准备方法与薄弱点发现手段；P7 能讲「信息≠知识」的认知误区 + 80/20 投入 + 漏题扩展复盘法。
- 红旗答案：只说「多刷题多背八股」而无范围意识；认为看过=掌握、拿到资料=掌握。
- 惊艳点：点出「看了只是信息，必须自己检索出来才算知识」「围绕一道漏题扩展到整个知识域（redo log → MySQL 日志全家族 + 事务）」 [经验]。

## 主问答
**Q（面试官原话）：** 技术面试该怎么准备才能事半功倍？
**A：**
1. **先划五大范围**：数据库与缓存（MySQL/Redis 基本每场必考，兼 Nosql 与搜索引擎、分布式与 CAP）、数据结构与算法（大厂必备项、通过与否的分水岭）、操作系统与网络（Linux 构成/命令/内核/CPU 与内存调度/IO 模型，网络重点 TCP 与 HTTP）、编程语言特性（Go 的 GMP、GC、map 与 slice 扩容、堆栈内存分配、设计模式、并发与锁）、项目经历（高频考察点，按 STAR 提问法深挖）[经验]。
2. **针对性准备两手抓**：既针对自己的**薄弱点**，也针对**重点考点**；忌平均用力 [经验]。
3. **发现薄弱点靠主动检索**：把考点整理成「知识点 → 可能被问的问题 → 自己的答案」的思维导图，折叠答案后自述；讲得清才算掌握，讲不清就是还没理解 [经验]。
4. **警惕把信息当知识**：看一遍、拿到资料都不等于掌握——信息必须经过自己编码产生记忆后才成为知识；让大脑**主动检索**，检索得到的才是自己的 [经验]。
5. **重点考点三个来源 + 80/20**：大部分公司都会问的（MySQL/Redis/算法）、岗位 JD 明确要求的技能、简历上自己写下的技能点；把 80% 时间投入这 20% 的高频重点 [经验]。
6. **面试后复盘要扩展**：没答上的问题记下来，并扩展到该知识点相关的**全部**问题——如被问 redo log 没答上，就要补 MySQL 日志全家族（redo/undo/binlog）以及事务特性与隔离实现，而不是只补这一道题 [经验]。

## 总结与追问预判
准备的关键是「范围清晰 + 主次分明 + 真检索」。面试常追问「某某八股你看过吧」→ 别只答看过，答「我用自己的话讲得清 X，讲不清的我会回头补」（呼应检索式学习）；再追问项目则引 STAR 结构化讲述。
