# 172 链表四变体的结构与实战选型深挖

> 覆盖源 17-2 的变体延伸：四变体的结构图与不变量、循环链表的「任意节点遍历全表」特性、双向链表删除 O(1) 的前提、标准库 container/list 与手写的取舍。主卡已给单链表主线，本附录做变体与选型深挖。

## 思路与架构

```text
链表家族结构图 (指针数 x 是否成环)
├─ 单链表: data + next
│   └─ 单向; 删除需知道前驱 (找前驱 O(n))
├─ 双向链表: data + next + prev
│   ├─ 可进可退; 持节点引用即 O(1) 删除
│   └─ 代价: 每节点多 8B 指针 (64位), 维护双指针
├─ 循环单链表: 尾.next = 头
│   └─ 从任意节点出发可遍历全表 (轮询调度基础)
└─ 循环双向链表: next/prev 均成环
    └─ 头尾操作均 O(1); container/list 即此类
```

## 方案取舍
- **双向链表的 O(1) 删除有前提**：删除 O(1) 的条件是**手里已有节点引用**（如 LRU 的 map 直接命中节点）；只有值查找仍是 O(n)。「双向链表删除快」必须带前提说，否则是半截话。LRU=哈希表(O(1)定位)+双向链表(O(1)移位)的合体，正是这一前提的标准应用 [经验]。
- **循环链表的真正价值是「无头尾之分」**：任一节点出发都能走完全表——轮转调度（Round-Robin）、约瑟夫问题、多玩家轮流行动都用它；配合哨兵头节点可把「空表/单节点」边界归一。代价是终止条件从 `cur != nil` 变为 `cur != 起点`，**忘记判起点就是死循环**——循环链表的 bug 九成在此 [经验]。
- **手写 vs `container/list`**：手写是面试考基本功、定制节点字段（如带权重）的场景；生产优先 `container/list`（双向循环链表，Element 抽象成熟、久经考验）。注意 `container/list` 存的是 `interface{}`（泛型后仍可包一层），高频小对象场景每元素有额外开销——性能敏感的环形缓冲需求（如 channel 底层）走数组环形结构而非链表 [经验]。
- **四变体的不变量检查法**：手写变体的测试要点——单链表：尾 next==nil；双向：`p.next.prev == p` 双向一致性；循环：从任意节点走 len 步回到自身。**不变量测试比功能测试更容易抓住成环/断链 bug**，手写链表的面试追问常落在「怎么验证你的实现没断链」[经验]。

## 答题技巧
- 四变体报结构图（指针数×成环）而非背名字，每个补一句「典型应用」：双向→LRU、循环单→轮询、循环双→container/list [经验]。
- 被问「删除复杂度」→ 主动带前提「持引用 O(1)、按值查找仍 O(n)」——精确表述是加分点 [经验]。
- 被问「循环链表怎么防死循环」→ 报「记录起点、走到起点停」+ 不变量测试 `走 len 步回起点` [经验]。
- 被问「生产用不用手写」→ container/list 优先，性能敏感环形结构走数组环形缓冲（channel 底层即此）[经验]。
- 主动边界到 `172-linkedlist-basics`（单链表主线与尾指针）、`173-linkedlist-stack`（链表实现栈）、`176-linkedlist-queue.deep`（尾指针 O(1) 实测 1055 倍）、`908-slice-grow.deep`（数组侧对照），构成「线性结构家族」专题 [边界]。
