# 907 slice 头部：三个字段撑起一个描述符

> 分类：Go 语言 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**slice 头部、array 指针、len、cap、描述符**

> 原文锚点：第 3~20 段「slice 在源码里面有三个字段…指针、长度、容量」

## 一句话总述
切片在运行时就是一个**三字段的描述符**：指向底层数组的指针、长度、容量；它本身很小，真正的元素在指针指向的那块连续内存里。

## 面试官视角
P6 说"切片有三个字段"；P7 要能报出**源码位置与字段语义**：运行时包的 slice 定义中，指针指向底层数组的起始位置，长度是当前元素个数，容量是**从切片第一个元素算起**底层数组可访问的元素个数 `[源码]`。加分点：正因为有了容量，追加元素时不必每次都申请新内存 `[经验]`。

## 主问答
**Q（面试官原话）：** slice 底层到底是什么结构？

1. **三字段结构**：指向底层数组的指针、长度、容量，通常容量大于等于长度 `[源码]`。
2. **指针指向起始位置**：它指向底层数组的开头，元素在内存中连续存放 `[经验]`。
3. **容量按首个元素起算**：容量是底层数组中可访问的元素个数，且从切片的第一个元素开始计算 `[源码]`。
4. **创建即伴随底层数组**：创建切片时会一并创建底层数组，默认其长度与元素个数相等；追加触发扩容时才新申请内存并拷贝 `[实测]`。

## 关键代码
```go
// 运行时中的切片描述符（示意）
type sliceHeader struct {
	array unsafe.Pointer // 指向底层数组
	len   int            // 元素个数
	cap   int            // 容量
}
fmt.Println(unsafe.Sizeof([]int{})) // 24（64 位平台）
```
> 验证：任意元素类型的切片头部大小相同，均为 24 字节 `[实测]`。
