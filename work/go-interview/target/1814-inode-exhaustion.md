# 1814 inode 耗尽与「目录也是文件」

> 分类：Linux 文件系统 | 难度：中 | 题型：故障/原理 | 频率：中 | 关键词：**inode 区、inode 耗尽、ls -i、目录项、执行权限**

> 原文锚点：第 40~54 段「inode 占用/耗尽与目录本质」

## 一句话总述
硬盘分区时 OS 把空间分成「数据区」和「inode 区」，inode 大小固定（128/256B）且数量有限——小文件过多会出现「磁盘没满但 inode 已耗尽、无法建新文件」。目录本质也是文件，其目录项 = 文件名 + inode 编号，读目录只需读权限、读 inode 信息需执行权限。

## 面试官视角
inode 耗尽是经典线上故障。考官想听你能否定位 `df -i` 而非 `df -h`，以及理解「为什么删了大文件空间不释放」（仍有进程持 inode）。能讲清目录的执行权限语义是加分项。

## 主问答
**Q（面试官原话）：** 什么是 inode 耗尽？目录为什么需要执行权限？

1. **inode 有限**：每个分区 inode 数量固定，小文件（如海量日志）会先把 inode 用光，此时磁盘有空间却建不了文件——用 `df -i` 查看。
2. **inode 像身份证**：系统用 inode 编号识别文件；文件名仅用于查编号。删文件=链接数减到 0 才真正回收 inode。
3. **目录是特殊文件**：目录项仅含「文件名 + inode 号」。读权限只能列文件名；要读 inode 元信息（如 stat）需目录的执行(x)权限——这是目录 x 权限的真实含义。

## 关键代码
```bash
df -i /data      # 看 inode 使用率
ls -i file       # 看单个文件 inode 号
```

## 总结与追问预判
核心：**inode 是有限资源，耗尽比空间满更隐蔽；目录 x 权限=可访问 inode**。追问常拐向「删文件空间不释放」（进程仍持 inode 句柄），备好 `lsof | grep deleted`。
