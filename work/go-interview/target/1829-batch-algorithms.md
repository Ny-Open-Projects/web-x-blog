# 1829 经典调度算法（FCFS / SJF / HRRN）

> 分类：OS 进程调度 | 难度：L3 | 题型：算法题 | 频率：高 | 关键词：**先来先服务**/**最短作业优先**/**高响应比优先**/**饥饿**/**周转时间**
> 原文锚点：第 21~35 段「先来先服务 / 最短作业优先 / 高响应比优先」

## 一句话总述
三类早期/批处理调度算法：**FCFS（先来先服务）**非抢占、简单但长作业饥饿、适合 CPU 繁忙型；**SJF（最短作业优先）**不利长作业；**HRRN（高响应比优先）**用「响应比=(等待+要求服务)/要求服务」兼顾长短作业，长作业等久了响应比自然升高。

## 面试官视角
- 考察意图：能否讲清三个算法的排队逻辑、优缺点，尤其 HRRN 如何化解 FCFS/SJF 的饥饿。
- 分档：P5 知 FCFS 按顺序；P6 知 SJF 短者先、SJF 不利长作业；P7 知 HRRN 公式与兼顾长短作业的机理。
- 红旗答案：把 SJF 说成「先来先服务」；或答不出 HRRN 公式。
- 惊艳点：点出「HRRN 响应比随等待时间单调升，长作业等足够久必被选中」。

## 主问答
**Q（面试官原话）：** 先来先服务、最短作业优先、高响应比优先分别是什么？
**A：**
1. **FCFS（先来先服务）**：按到达顺序分配 CPU，非抢占；一旦运行就占满直到退出/阻塞。简单但长作业先到会让后面短作业等长等待（饥饿），适合 CPU 繁忙型、不适合 IO 频繁型。
2. **SJF（最短作业优先）**：优先选估计运行时间最短的进程；降低平均等待与响应，但不利长作业——就绪队列若满是短作业，长作业被不断后推、周转时间拉长乃至长期不被运行。
3. **HRRN（高响应比优先）**：每次调度先算响应比=(等待时间+要求服务时间)/要求服务时间，选最高者；两进程要求服务时间相同时等待越久响应比越高，长作业等待足够久后响应比升高终获运行，兼顾长短作业。
4. **组合使用**：SJF/短作业优先难精确预测运行时间，常与优先权原则结合成「短作业优先+动态优先级」综合算法。

## 关键代码
```go
// HRRN：每次从就绪进程里选响应比最高的
type proc struct{ wait, service int; done bool }
func hrrnPick(procs []proc) int {
	best, bestR := -1, -1.0
	for i, p := range procs {
		if p.done {
			continue
		}
		r := float64(p.wait+p.service) / float64(p.service) // 响应比
		if r > bestR {
			best, bestR = i, r
		}
	}
	return best // 响应比最高者优先运行
}
```
