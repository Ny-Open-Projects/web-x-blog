# 1003 并发编程类面试题怎么回答（方法论）

> 分类：面试方法论 / 并发 | 难度：L2 | 题型：方法论 | 频率：高 | 关键词：**并发考点**/**费曼学习法**/**项目案例**/**多方案优劣**/**级别匹配**

> 原文锚点：第 1~45 段「考察范围(基本原语+扩展原语/原子/channel+哲学/分布式并发/项目并发问题)...答题技巧(充分准备+模拟面试费曼/基础用自己的话/项目真实案例按级别/多方案优劣对比)...程序员六级别」

## 一句话总述
并发面试题按**五大考点**准备：① 基本/扩展并发原语（mutex/rwmutex/waitgroup/cond/信号量/singleflight）② 原子操作（atomic）③ channel 使用与原理（Go 哲学"不要通过共享内存通信，通过通信共享内存"）④ 分布式并发（etcd/redis）⑤ 项目真实并发问题（排查解决过程）。**答题四技巧**：按考点准备+模拟面试（费曼）、基础概念用自己的话、准备真实项目案例（按初/中/高级别匹配、清晰讲排查与解决）、多给方案并说清优劣。

## 面试官视角
- 考察意图：不只考知识点，更考"能否把并发讲清楚 + 是否有真实排障经验 + 能否多方案权衡"。
- 分档：P5 知五大考点；P6 能用自己话讲基础（并发vs并行、waitgroup 实现）；P7 能拿真实案例 + 多方案优劣对比。
- 红旗答案：只背概念不自己阐述；无项目案例或案例讲不清排查过程；一个问题只给一种解法。
- 惊艳点：点出「用费曼学习法模拟面试」「按级别选案例」「一个并发问题常有多原语解甚至可规避，给方案+优劣」 [经验]。

## 主问答
**Q（面试官原话）：** 并发编程类的问题应该怎么回答？
**A：**
1. **明确五大考点**：基本/扩展原语、原子操作、channel 原理与 Go 通信哲学、分布式并发（etcd/redis）、项目真实并发问题 [经验]。
2. **充分准备+模拟面试**：按考点准备，用费曼学习法把知识点讲出来（基础概念如并发vs并行、waitgroup 实现用自己的话，不背拗口定义）[经验]。
3. **项目案例真实可复述**：选自己参与解决过的真实并发问题，能清晰讲背景/发现/定位/解决；按级别匹配——初中级可用经典案例如原子性坑，高级用自己的真实案例 [经验]。
4. **多给方案+优劣**：一个并发问题常能用多种原语解，甚至可规避；从多角度给方案并说清优劣，比只答一种更显功底 [经验]。
5. **日常积累**：养成写博客/笔记复盘习惯，把遇到的问题记清背景/发现/定位/解决，成为面试素材 [经验]。

## 总结与追问预判
并发题 = "知识点 + 表达 + 经验 + 权衡"。面试常追问「你遇到过什么并发问题」→ 拿真实案例按背景/发现/定位/解决四要素讲；再追问「还有别的治法吗」→ 给多原语方案并比优劣。

## ⚠️ 原文纠错
1. 事实核校： [经验] 五大考点、Go 通信哲学、费曼模拟面试、按级别选案例、多方案优劣——均正确，符合并发面试实战。
2. 崩坏词归一：源码将 Go 及相关概念音译为若干崩坏串（如将标准库、Go 原子性、Go 运行时、singleflight 等音译为非规范串），本卡统一为规范术语；涉及 Go 本身的崩坏串不列举任何原词崩坏词。

```go
// Go 哲学：不要通过共享内存来通信，而是通过通信来共享内存
// 共享内存加锁（传统写法）
var mu sync.Mutex
var cnt int
func incLock() { mu.Lock(); cnt++; mu.Unlock() }

// 通过通信共享（Go 推荐）：多 goroutine 向 chan 发送，主 goroutine 接收累加，无需显式锁
func incChan(ch chan<- int) { ch <- 1 }
```
