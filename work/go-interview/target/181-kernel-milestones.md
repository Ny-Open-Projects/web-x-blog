# 181 Linux 内核版本里程碑（0.01 → 6.0）

> 分类：Linux 基础 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**内核版本**/**SMP**/**livepatch**/**WSL**/**NTFS3**

> 原文锚点：第 20~40 段「Linux 发展史各阶段与版本特性」

## 一句话总述
内核版本从 1991 年的 0.01 走到 2022 年的 6.0，每代都有标志性能力：1.0 支持 TCP/IP 协议栈与 X Window；2.0 引入多处理器（SMP）与负载均衡；2.4 补齐大容量存储、USB 与嵌入式；2.6 全面重写文件系统与安全机制；4.0 引入不重启的实时补丁。

## 面试官视角
考官不指望你背全版本号，但会挑两个节点问「这个版本解决了什么问题」。能把 2.0 的 SMP、4.0 的 livepatch、5.15 的 NTFS3 讲成「为什么需要它」，比背时间线值钱得多。

## 主问答
**Q（面试官原话）：** 说几个 Linux 内核大版本的标志性变化？

1. **1.0（1994）**：首个正式版，支持 TCP/IP 协议栈、X Window 系统与多种硬件平台，具备实用价值。
2. **2.0（1996）**：引入多处理器、多线程与负载均衡，性能与稳定性上台阶，商业公司开始入场。
3. **2.4（2001）**：增强大容量存储、USB 与嵌入式支持，把 Linux 推向更多设备形态。
4. **2.6（2003）**：对硬件平台、文件系统与安全机制做全面支持，是企业级普及的技术底座。
5. **3.0 与 4.0（2011/2015）**：3.0 取消奇偶版本号规则改为按时间节奏发布；4.0 引入实时补丁，可不重启修内核。

## 关键代码
```go
// Go 侧视角：灰度发布前批量核对机器内核版本，判断是否具备某特性
package main

import (
	"fmt"
	"os/exec"
	"strings"
)

func main() {
	out, _ := exec.Command("uname", "-r").Output()
	rel := strings.TrimSpace(string(out))
	fmt.Println("kernel:", rel)
	// 4.0+ 支持 livepatch；5.15+ 才有新的 NTFS3 驱动
	fmt.Println("支持 livepatch:", kernelAtLeast(rel, 4, 0))
}

func kernelAtLeast(rel string, major, minor int) bool {
	var a, b int
	fmt.Sscanf(rel, "%d.%d", &a, &b)
	return a > major || (a == major && b >= minor)
}
```

## 总结与追问预判
核心：**每个大版本对应一类能力补齐**，回答时讲「解决了什么问题」。追问常拐向「大版本号变化不等于 ABI 兼容」「怎么查线上机器内核版本」，备好 `uname -r` 与灰度核对脚本。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称 6.0 于 2022 年 12 月发布——实际 Linux 6.0 发布于 2022 年 10 月 2 日，12 月发布的是 6.1。
2. 事实核校： [经验] 原文称 3.0「采用时间戳作为版本号的一部分」——实际是取消 2.6 时代奇偶版本号（偶稳定、奇开发）规则，改为按时间节奏递增发布，版本号本身不含时间戳。
3. 事实核校： [经验] 原文对 1.0 所支持的网络协议栈与图形系统用了音译写法，实为 TCP/IP 协议栈与 X Window 系统。
4. 崩坏词归一：源码将 Linux / GPL / Shell / TCP/IP 等音译为多组崩坏词，本卡统一为规范术语。
