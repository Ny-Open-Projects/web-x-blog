# 168 指挥者的存废、校验时机与创建型三模式选型 深挖

> 覆盖源 16-8 全文：Director 在 Go 语境下的存废论证、校验时机从构造瞬间到 Build 收口的设计意义、分步构建的中间态合法性、建造者/工厂/原型/Options 四种创建方式的选型矩阵。主卡已给四角色与实测，本附录做设计权衡四层深挖。

## 思路与架构

```text
创建型需求的选型决策树
├─ 对象简单, 无多步骤? -> 直接构造 / new
├─ 需要「按类型选择实现」? -> 工厂 (管 what)
├─ 多配置项 + 有默认值 + 少校验? -> 函数式 Options (见 162)
├─ 多步骤组装 + 依赖约束 + 强不变量校验? -> Builder (管 how)
│   ├─ 链式 API: 方法返回 *Builder
│   ├─ 中间态: 允许暂时非法 (只设了 port 没设 host)
│   └─ Build(): 收口校验不变量 -> (T, error)
└─ 构建成本高需克隆? -> 原型模式 (Go 用拷贝语义)
指挥者的位置: 把「步骤顺序」从调用方抽走 -> 流程固化
```

## 方案取舍
- **Director 在 Go 里为什么常常消失**：GoF 的 Director 存在意义是**复用构建流程**——同一流程配不同 ConcreteBuilder 产出不同表示（如同一「渲染流程」建 ASCII 文档或 HTML 文档）。这依赖接口多态体系；Go 语境下「流程固化」更常用**一个普通函数**承担（`func NewDefaultServer() (Server, error) { return NewBuilder().Host(..).TLS().Build() }`）——流程即函数，无需抽象层。只有当「多种表示 + 同一流程」真实存在时才值得恢复 Director 角色，Go 标准库里几乎没有这种形态 [经验]。
- **校验时机是 Builder 最有信息量的设计点**：构造函数校验意味着「一参不合法全盘报错」，且无法表达「字段间依赖」（port 未定时 maxConn 的合法区间未知）；Builder 把校验推迟到 **Build() 收口**——分步过程中间态允许「暂时非法」（只设了 port、host 还是零值），收口时基于**完整终态**校验跨字段不变量（如 `tls && port==80 时拒绝`）。这本质是把「对象不变量的守护点」从构造期挪到「构建完成」这个语义时刻，与「两阶段初始化」的争论正交——**只要 Build 之前对象不流出构造作用域，不变量就安全** [经验]。
- **链式 API 的代价清单**：① 每次调用返回 `*Builder` 指针自身（零分配），但闭包式 Options 每项一次闭包分配——超高频路径 Builder 更省；② 链式 API 的**方法集合暴露在类型上**，接口面大；③ **必填项无法编译期强制**——漏设只能靠 Build 校验兜底，这是 Builder 与 Options 共同的短板，真正必须的参数应作为 `NewBuilder(required1, required2)` 的位置参数 [经验]。
- **工厂 vs 建造者的一句话分界**：工厂回答「**造哪一个**」（类型选择，调用方不知道具体类型）；建造者回答「**怎么组装**」（类型已知、过程复杂）。混淆的典型是「工厂返回Builder」——这是合法组合（抽象工厂生产具体 Builder），但面试表述要分层说清。Go 标准库参照系：`strings.Builder`（分步写入 + 收口 `String()`，行为同构但为性能而生，见 904 [边界]）、`http.Server`（字段直构 + ListenAndServe，说明「简单配置不用 Builder 也行」） [经验]。
- **不变量守护的工程纪律**：分步构建最大的风险是「半成品逃逸」——把 `*Builder` 或中间态 Server 传给别的协程使用。纪律有三：① Server 字段全小写（包外不可见）；② 只暴露 Build() 产出的**不可变值**（值类型或只读接口）；③ build 完成前 Builder 不跨协程共享。做到这三条，「收口校验」才有意义——否则不变量在逃逸处照样被破坏 [经验]。

## 答题技巧
- 报完四角色立刻补「Go 里 Director 常由普通函数替代」，避免死背 GoF 的嫌疑 [经验]。
- 用实测说话：合法构建返回完整 Server、`Port(70000)` 被 Build 拦截——「中间态自由、收口拦截」八个字总结 [实测]。
- 被问「和 Options 怎么选」→ 给出矩阵：配置量、是否有跨字段约束、是否高频创建（闭包分配）、是否需要必填强校验，四维一比就清楚 [经验]。
- 被问「工厂和建造者区别」→ 「what vs how」一句话分界 + 抽象工厂生产 Builder 的组合形态 [经验]。
- 主动边界到 `162-builder`（函数式 Options 全解）、`904-builder-vs-buffer`（strings.Builder 性能形态）、`161-*`（单例等其他创建型），构成创建型模式专题 [边界]。
