# 419 Go 整型除法陷阱

> 分类：Go 数值类型 | 难度：L2 | 题型：陷阱题 | 频率：高 | 关键词：**整型除法**/**int/int=0**/**float 转型**/**先转后算**
> 原文锚点：第 59~62 段「整型相除先转 float 否则得 0」

## 一句话总述
Go 中 **整数除以整数**结果是整数（向下截断），`1/3` 直接得 `0`；要做浮点除法必须**先把操作数转成 float** 再运算，不能"先算完再转"。

## 面试官视角
- 考察意图：最基础的入门陷阱——int/int 得 0，而非 0.333。
- 分档：P5 知 int/int 截断；P6 知要先转 float；P7 能讲清"先转操作数再运算"的顺序。
- 红旗答案：`float(1/3)`——先做了整数除法得 0，再转 float 还是 0。
- 惊艳点：点出"转型要作用在分子分母上，不是作用在结果上"。

## 主问答
**Q（面试官原话）：** 1 除以 3 转成浮点为什么是 0？
**A：**
1. **整数除法截断**：`int64(1) / int64(3)` 两操作数都是整数，结果按整数算，值 <1 直接截断为 **0**。
2. **错误写法**：`float32(1/3)` 先算 `1/3=0`（整数），再转 float → 仍是 `0.0`；转型发生在结果上，没用。
3. **正确写法**：先把操作数转 float——`float32(1) / float32(3)` 或 `1.0/3`，让除法在浮点域进行 → `0.333...`。
4. **通用规律**：参与运算的类型决定结果类型；想得浮点，操作数里至少一个得是浮点字面量或显式转型。

## 关键代码
```go
fmt.Println(float32(1) / float32(3)) // 0.333...
fmt.Println(float32(1 / 3))          // 0（错误）
```

## 总结与追问预判
Go 整数除法直接截断，1/3=0；要浮点结果须先转操作数为 float 再算，`float(1/3)` 顺序错必得 0。金额/比率计算优先用 float64 或整数分。

## ⚠️ 原文纠错
1. 事实核校： [经验] int/int 截断得 0、须先转操作数再除、float(1/3) 顺序错得 0，均正确。
2. 崩坏词归一：flot三十二银→float32、in的六十四→int64；源码将 Go 语言 音译为崩坏词，本卡统一为 Go 语言。
