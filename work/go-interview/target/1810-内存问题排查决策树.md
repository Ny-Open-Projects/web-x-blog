# 1810 内存问题排查决策树

> 分类：Linux/内存排查 | 难度：L3 | 题型：流程题 | 频率：中 | 关键词：**排查流程** / **决策树** / **内存不足信号** / **swap**
> 原文锚点：第 33~74 段「free 看系统→top 定位进程→vmstat 看趋势；分类三型(可用内存低→pmap/swap占用/buffer cache高→slabtop)；内存不足信号(free↓+swap↑+io↑+缺页中断↑+cs↑+b↑+wa↑)」

## 一句话总述
内存排查的固定打法：`free/top` 看系统整体 → `top` 按 RES 定位占用进程 → `vmstat` 看趋势分类问题 → 三型分流（可用内存低→`pmap` 下钻 / swap 被用→物理内存耗尽 / buffer cache 高→`slabtop` 找进程）。**内存不足**的硬信号是 free↓ + si/so↑ + bi/bo↑ + 缺页中断↑ + cs↑ + b↑ + wa↑ 同时出现。

## 面试官视角
- 意图：考察"有方法的排查"而非零散命令，看是否能把工具串成决策树。
- P5 能列 free/top/vmstat；P6 能说清三型分流；P7 能完整给出"内存不足信号集"并解释 wa/b 与 swap 的因果。
- 红旗：拿到机器就 pmap；说不清 swap 被用意味着什么；把 cache 高当内存不足。
- 惊艳点：点出 ES 实战"关闭 swap 避免性能问题"；缺页中断过多=内存不足/分配不当迹象。

## 主问答
**Q（面试官原话）：** 一台机器内存报警，你怎么一步步排查？
**A：**
1. **结论**：四步——① `free`/`top` 看系统整体（重点 `available`）；② `top` 按 RES 找出占用最大的进程；③ `vmstat 1` 看趋势；④ 按现象分流：**可用内存低**（排除 cache 后 `pmap <pid>` 下钻地址空间）、**swap 被大量使用**（物理内存大概率已耗尽，swap 慢拖累性能）、**buffer/cache 高**（`vmstat` 看 cache 趋势 + `slabtop` 找占用进程）。
2. **机制**：内存不足时多个信号同时亮——`free` 急剧减少（回收 cache 也无济）、`si/so` 换入换出频繁、`bi/bo` 磁盘 IO 增多、缺页中断增多、`cs` 上下文切换增多、`b`(等 IO 进程)增多、`wa`(IO 等待 CPU 占比)升高。
3. **边界**：`cache` 高未必是问题（可回收）；真不足看 `available` 持续低 + swap 启用。生产如 ES 常直接关 swap 避免性能劣化 `[经验]`。
