# 1506 微服务化影响评估深挖

> 分类：架构设计 / 微服务 | 难度：L3 | 题型：深挖 | 频率：中 | 关键词：**影响评估** / **一致性成本** / **延迟** / **关联查询** / **服务治理**
> 原文锚点：第 31~48 段「微服务化后影响…一致性成本/延时会变高/资源成本/关联查询复杂度/远程调用/服务治理/人员要求/工具依赖/运维复杂度」

## 思路与架构
微服务化是把"进程内复杂度"搬成"分布式复杂度"。落地前必须评估九类负面影响，逐项对照单体是否可承受：
- 一致性成本↑：单库事务变分布式事务（见 152 六大缺点）。
- 整体延迟↑：跨服务调用次数增多，响应时间累加、吞吐下降。
- 资源成本↑：吞吐下降需补更多资源，交付型/小规模部署尤其致命。
- 关联查询复杂度↑：每服务数据仅经自身 API 访问，旧 join 变跨服务集成。
- 远程调用↑：需额外考虑序列化/协议/压缩/负载均衡/容错。
- 服务治理：服务发现与依赖治理成为必答题。
- 人员要求↑：开发既要定接口又要管库，门槛更高。
- 工具依赖↑：服务多、工具收益大、依赖深。
- 运维复杂度↑：监控/健康检查要求更高。

```text
                            是 ↓

                            是 ↓
Q3: 基础设施就绪吗？        否 → 先建监控/自动化部署/灰度（见 154 前置）
                            是 ↓
Q4: 能承受九类负面影响吗？  逐项评估：一致性/延迟/资源/关联查询/远程/治理/人/工具/运维
                            能 → 微服务化，配可观测性(1506-observe-tracing)+安全(1506-microservice-security)
                            否 → 暂缓，或只拆核心域
```

## 答题技巧
```text
面试话术（先承认收益，再讲现实成本，显实战）：
1. 微服务解决单体"大泥球"，但把复杂度搬去分布式
2. 最痛三点是：数据一致性（分布式事务）、延迟累加、运维/治理成本
3. 落地前先问四问（Q1~Q4），边界不清/基础设施未就绪就先单体
4. 配套必须补：可观测性(链路追踪) + 安全(密钥/脱敏) + 自动化
5. 收尾点：二八定律，先聚焦核心域，不为微服务而微服务
```

## 细节与核心 API

**决策树四问（边界不清先单体）：**

```text
Q1 业务边界清晰? 否 → 先单体，演进式拆分
Q2 单体已过大/发布慢? 否 → 暂不需微服务（过度设计）
Q3 基础设施就绪(监控/自动化部署/灰度)? 否 → 先建前置
Q4 能承受九类负面影响? 能 → 微服务化，配可观测性+安全+自动化；否 → 暂缓或只拆核心域
```

**最痛三点（必点）：**

```text
① 数据一致性：单库事务 → 分布式事务/Saga（见 152）
② 延迟累加：跨服务调用次数增多，响应时间叠加、吞吐下降
③ 运维/治理成本：服务发现、依赖治理、监控/健康检查要求陡增
```
