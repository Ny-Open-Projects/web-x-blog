# 1223 唯一索引的数据就一定不会重复吗？

> 分类：MySQL/SQL | 难度：L3 | 题型：陷阱题 | 频率：高 | 关键词：**唯一索引**/**NULL例外**/**联合唯一**/**逻辑删除**/**大字段哈希**

> 原文锚点：第 1~43 段「唯一索引避免指定列重复、写相同值触发冲突...但 NULL 是例外,唯一索引列允许多个 NULL...规避设 NOT NULL...逻辑删除场景 email+status 联合唯一只能删一次,改用 deleteID 记录被删主键才可反复删...大字段直接建唯一索引受 3072 字节(utf8mb4 下 768 字符)限制且耗磁盘,应取 MD5 哈希做唯一列」

## 一句话总述
**不一定**。唯一索引能阻止重复值写入，但**列值为 NULL 时是例外**——多个 NULL 互不判为重复，所以唯一索引列仍可能出现一堆「重复」的 NULL；规避办法是把字段设为 NOT NULL。另有两类实战坑：逻辑删除场景下 `email+status` 联合唯一只能删一次，改用 `deleteID`（写入被删行主键）才能反复删；大字段直接建唯一索引受 **3072 字节**（utf8mb4 下 **768 字符**）限制且极耗磁盘，应取 MD5 等哈希值另存一列再加唯一索引。

## 面试官视角
- 考察意图：是否知道唯一索引的 NULL 例外，以及逻辑删除、大字段这两个真实设计坑。
- 分档：P5 知唯一索引防重复；P6 能答出 NULL 例外 + NOT NULL 规避；P7 能讲清逻辑删除 deleteID 方案与大字段哈希方案。
- 红旗答案：断言「有唯一索引就绝对不重复」（不知 NULL 例外）；给长字段直接建唯一索引撞长度上限。
- 惊艳点：点出「多个 NULL 互不冲突」「email+status 只能逻辑删除一次，要用 deleteID 记录主键」「3072 字节限制下 utf8mb4 只能索引 768 字符，改存 MD5」 [经验]。

## 主问答
**Q（面试官原话）：** 唯一索引的数据就一定不会重复吗？
**A：**
1. **NULL 是例外**：唯一索引列允许存在**多个 NULL**（NULL 之间不判为重复），所以「一定不重复」是错的；应把字段设为 NOT NULL 从根上规避 [经验]。
2. **与主键对比**：主键索引同样具备唯一性，但主键列**不允许为 NULL**，这是它与普通唯一索引的关键差别 [经验]。
3. **逻辑删除·方案一**：加 `status`（0 未删/1 已删）后对 `email+status` 建**联合唯一索引**——同一 email 只能被逻辑删除一次，再次删除相同 email 仍会冲突 [经验]。
4. **逻辑删除·方案二**：改用 `deleteID`（类型同主键，默认 0 表示未删，删除时写入被删行的主键 ID），`email+deleteID` 联合唯一——每次删除 deleteID 都不同（等于主键值），故同一 email 可反复删除而不冲突 [经验]。
5. **大字段坑与解法**：给长字段直接建唯一索引受 **3072 字节**索引长度限制，utf8mb4（4 字节/字符）下最多 **768 字符**，超出直接报错；且大字段索引消耗大量磁盘。**解法**：取 MD5 等哈希值另存为新字段，只对哈希列建唯一索引 [经验]。

## 总结与追问预判
记住三类「会重复 / 难保证唯一」的场景：NULL 例外、逻辑删除、大字段超长。面试常追问「逻辑删除怎么保证唯一」→ 答 `email+deleteID` 联合唯一；再追问「超长字符串怎么保证唯一」→ 答存 MD5 哈希列并对其建唯一索引。

## ⚠️ 原文纠错
1. 事实核校： [经验] NULL 例外、3072 字节限制与 utf8mb4 下 768 字符上限、联合唯一与 deleteID 方案、MD5 哈希列——均正确，符合 MySQL 实际行为。
2. 崩坏词归一：源码将若干术语音译为崩坏词（如 NOT NULL、NULL、status、deleteID、MD5 等），本卡统一为规范术语，无黑名单词。

```sql
-- NULL 例外：唯一索引列仍可存在多个 NULL
CREATE TABLE users (
  id    INT PRIMARY KEY,
  email VARCHAR(64) UNIQUE          -- 可插入多条 email 为 NULL 的记录
);
-- 规避：建表时设 NOT NULL
CREATE TABLE users2 (
  id    INT PRIMARY KEY,
  email VARCHAR(64) NOT NULL UNIQUE
);

-- 逻辑删除方案二：email + deleteID 联合唯一，同一 email 可反复删除
CREATE TABLE users3 (
  id       INT PRIMARY KEY,
  email    VARCHAR(64) NOT NULL,
  deleteID INT NOT NULL DEFAULT 0,  -- 0=未删除；删除时写入被删行的主键 id
  UNIQUE KEY uk_email_del (email, deleteID)
);

-- 大字段唯一性：存 MD5 哈希列并加唯一索引（绕开 3072 字节 / 768 字符限制）
ALTER TABLE users3 ADD COLUMN email_md5 CHAR(32) NOT NULL;
ALTER TABLE users3 ADD UNIQUE KEY uk_email_md5 (email_md5);
```
