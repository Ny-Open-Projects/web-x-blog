# 167 函数选项模式：让参数可以任意增减而不改调用点

> 分类：Go 语言 / 设计模式 | 难度：L3 | 题型：设计题 | 频率：高 | 关键词：**函数选项模式**/**变长参数**/**Option func**/**WithXxx**/**可选配置**
> 原文锚点：第 5~31 段「通过函数选项模式来实现…先定义一个配置对象，并且使用一系列的函数来设置这个对象的属性…定义一个函数类型…返回值是一个函数类型…遍历我们传进来的这个 options 参数，调用这个函数，把 opts 作为地址类型传进来…不论它的位置怎么变化，我们都可以拿到它里面设置的这些属性的值」

## 一句话总述
当一个函数（如初始化客户端）的**可选参数**会随业务迭代不断增多时，直接往签名里加参数会逼着**所有调用点跟着改**。Go 的惯用解法是**函数选项模式**：先定义配置对象 `options`，再定义函数类型 `type Option func(*options)`，然后提供一串 `WithXxx(v) Option` 返回设置函数；构造函数用**变长参数** `opts ...Option` 接收，遍历执行 `opt(o)` 把值写进配置对象。这样**新增配置项只加一个 `With` 函数，老调用点一行不改**。

## 面试官视角
- 考察意图：这题考的是**API 演进能力**——你能不能设计一个"未来加字段不破坏现有调用"的接口。它也是 Go 里最能体现"函数是一等公民"的模式。
- 分档：P5 只会说"用结构体传参"；P6 能写出 `options` 结构体 + `WithXxx`；P7 能讲清**必传参数仍用显式形参、只有可选项走 Option**、变长参数必须在最后、以及它相对"配置结构体"和"Builder"的取舍。
- 红旗答案：「函数选项模式可以实现任意**位置**的参数传递」——**Go 是按位置传参的强类型语言，必传参数的位置不可能任意**。函数选项解决的是**可选参数数量任意**，不是位置任意。
- 惊艳点：补一句「配置字段我**不导出**，外部只能通过 `WithXxx` 设置，这样将来可以重命名或加校验而不破坏兼容」 [经验]。

## 主问答
**Q（面试官原话）：** 一个初始化函数以后还要不断加参数，你怎么设计才不用改所有调用方？
**A：**
1. **问题来源**：初始化客户端时，除了连接必传的参数（如名称、地址、用户名、密码），业务迭代会不断追加**额外配置**；直接加形参会让**所有调用点**都得改 [源码]。
2. **第一步：定义配置对象**：定义一个 `options` 结构体承载所有可选属性（如是否开启查询日志、慢查阈值、连接使用的 schema） [源码]。
3. **第二步：定义函数类型**：定义 `type Option func(*options)`——`Option` 是一个**函数类型**，入参是指向配置对象的指针，这样它就能修改配置 [源码]。
4. **第三步：写一串 `WithXxx`**：每个 `WithXxx(v)` 接收配置项的值，**返回一个函数**；返回的函数体内对该属性赋值。层层返回函数，是这套模式的关键形态 [源码]。
5. **第四步：构造函数用变长参数接收**：构造函数的形参分成两段——**前面是必传的连接参数，最后是 `opts ...Option`**；函数体内先给配置对象填默认值，再 `for _, opt := range opts { opt(o) }` 逐一应用 [源码]。
6. **效果**：调用方写成 `NewClient(name, urls, user, pass, WithQueryLog(true), WithSlowThreshold(200*time.Millisecond), WithSchema("https"))`；**增加新配置项时只新增一个 `With` 函数，老调用点完全不用动**，且**顺序无关** [源码]。
7. **它的定位**：函数选项模式**不在经典的二十三种设计模式之列**，但在 Go 里极其实用——它用"函数作为一等公民"换来了比 Builder 更轻的可选参数方案 [经验]。

## 关键代码
```go
// ① 配置对象：字段不导出，只能通过 WithXxx 设置
type options struct {
	queryLogEnabled bool
	slowThreshold   time.Duration
	schema          string
}

// ② 函数类型：入参是配置对象指针，因此能修改配置
type Option func(*options)

// ③ 一串 WithXxx：接收值，返回一个函数（闭包捕获了值）
func WithQueryLogEnabled(enabled bool) Option {
	return func(o *options) { o.queryLogEnabled = enabled }
}
func WithSlowThreshold(d time.Duration) Option {
	return func(o *options) { o.slowThreshold = d }
}
func WithSchema(s string) Option {
	return func(o *options) { o.schema = s }
}

// ④ 构造函数：必传参数显式在前，可选配置走变长 Option
func NewESClient(name string, urls []string, user, pass string, opts ...Option) *ESClient {
	o := &options{schema: "http", slowThreshold: 500 * time.Millisecond} // 默认值
	for _, opt := range opts {
		opt(o) // 逐一应用，顺序无关
	}
	return &ESClient{name: name, urls: urls, user: user, pass: pass, opt: o}
}

// ⑤ 调用：新增配置项时老代码一行不改
c := NewESClient("es-prod", []string{"http://127.0.0.1:9200"}, "u", "p",
	WithQueryLogEnabled(true),
	WithSlowThreshold(200*time.Millisecond),
	WithSchema("https"),
)
// [实测] 要点：三个 Option 调换顺序，最终 options 取值完全一致
```

## 总结与追问预判
一句话记忆：**「必传走形参，可选走 Option，新增只加 With」**。常追问「和配置结构体传参比哪个好」——答：配置结构体胜在**一眼看全、易序列化**，但调用方哪怕用默认值也得写一个 `Config{}`，且新增字段要小心兼容；函数选项胜在**零值友好、可对单字段做校验、加项不破坏兼容**，代价是 API 面变大（每个配置一个 `With`）与极小的闭包/切片开销。**结论：可选参数多且会频繁演进 → 函数选项；配置是稳定集合且需要整体校验/序列化 → 配置结构体。** 再追问「能实现任意位置传参吗」——**不能**，Go 按位置传参，**只有 `...Option` 这截可选参数可以任意顺序与任意数量**，必传参数的位置是固定的。

## ⚠️ 原文纠错
1. 事实核校： [经验] 一处表述须纠正——标题所称「任意数量和**位置**的参数传递」不准确：Go 是**按位置传参的强类型语言，必传参数的位置固定不可随意**；函数选项模式真正解决的是「**可选参数的任意数量与顺序**」，靠的是变长参数 `...Option` 且必须位于参数列表**最后**。另补：实现时配置字段宜**不导出**，只经 `WithXxx` 写入，以保留后续重命名与校验空间。
2. 崩坏词归一：源码将若干术语音译为崩坏词（如 option、schema、阈值等被音译），本卡统一为规范术语，无黑名单词。
