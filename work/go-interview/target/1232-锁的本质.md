# 1232 锁的本质：内存结构与排队机制

> 分类：数据库 / MySQL 锁 | 难度：L4 | 题型：原理题 | 频率：中 | 关键词：**锁结构、事务ID、锁状态、排队、锁开销**

> 原文锚点：第 62~84 段「锁本质是内存结构…事务开始操作数据才生成锁结构与记录绑定…含事务 ID 与锁状态…未提交改同条记录需排队…锁开销与数据安全平衡」

## 一句话总述
锁本质是内存中的结构：事务**开始改数据**时才生成锁结构与记录绑定，含事务 ID 和锁状态。多个未提交事务改同一行时，后者进入「等待」状态排队，前者提交/回滚后释放锁才继续执行。

## 面试官视角
P6 知道锁是内存结构、改数据才加；P7 要讲清「排队靠锁状态实现」以及锁操作（获取/检查/释放）本身有开销，粒度越小越并发但管理成本越高。

## 主问答
**Q（面试官原话）：** 锁在 MySQL 里到底是什么？怎么保证不脏写？

1. **内存结构**：锁是内存里的结构，事务开启时**没有**锁，只有开始操作数据才生成并绑到记录 `[源码]`。
2. **基本属性**：锁结构含事务 ID 与当前锁状态（是否等待），源码中还含锁定记录、索引、类型等 `[源码]`。
3. **排队防脏写**：事务 A 改记录一占用锁，事务 B 改同条记录时锁状态变「等待」，被阻塞 `[源码]`。
4. **释放即续**：A 提交或回滚释放锁后，B 才从等待变执行，保证写写串行不脏写 `[源码]`。
5. **开销权衡**：获取/检查/释放锁都耗资源；锁粒度越小并发越高但管理越贵，是开销与安全的平衡 `[经验]`。

## 关键代码
```sql
-- 事务 A 占用行锁，事务 B 改同行进入 LOCK_WAIT
BEGIN; UPDATE t SET c=1 WHERE id=1; -- A 持有 X 锁
-- 另一会话：UPDATE t SET c=2 WHERE id=1; -- 阻塞，状态 LOCK_WAIT
COMMIT; -- A 释放后 B 才继续
```
