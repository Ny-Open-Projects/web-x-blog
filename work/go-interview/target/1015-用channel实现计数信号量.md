# 1015 用 channel 实现计数信号量：限住 goroutine 峰值

> 分类：并发模型 | 难度：L3 | 题型：编码题 | 频率：中高 | 关键词：**计数信号量、并发峰值、for range、close、容量即配额**

> 原文锚点：第 37~52 段「我们使用 channel 实现了一个计数信号量…active 表示当前活跃的 goroutine，我们允许最多有三个在执行」

## 一句话总述
计数信号量就是**容量为 N 的缓冲 channel**：进来先写入占一个配额，结束再读出归还；容量 N 就是同时运行的 goroutine 上限。一句话背法：**「信号量 = 容量 N 的 channel，写入即占配额、读出即还配额，峰值锁在 N」**。

## 面试官视角
- **P6**：会写"通道控制并发"，容量即配额。
- **P7**：要说出**容量即配额**、**写入即获取、读出即释放**，以及任务通道用 `for range` 配 `close` 才能干净退出。加分点：这东西是**限峰值**不是限总量——总量由任务数决定。

## 主问答
**Q（面试官原话）：** 怎么限制同时运行的 goroutine 数量？

**先铺垫（由浅入深第 1 层）**：并发数失控会把 CPU/下游打满，需要一个「同时在跑」的准入闸门；channel 的缓冲容量天然就是这种闸门。

1. **容量即配额（第 2 层）**：声明容量为 N 的通道，N 就是允许同时执行的 goroutine 数量，示例中容量为 3 即最多三个并行。
2. **占配额（第 3 层）**：goroutine 启动时先向该通道写入一个元素，写成功才继续执行；第 4 个到来时容量已满，阻塞在写入处。
3. **还配额（第 4 层）**：任务执行完从通道读出，容量释放，被阻塞的那个随即写入成功并继续，峰值始终不超过 N。
4. **任务通道要关闭（第 5 层）**：任务通道先写满再 `close`，消费侧用 `for range` 读取，**读完通道内所有元素后自动退出**，不需要额外结束信号。
5. **限的是峰值（第 6 层）**：它约束"同时在跑"的数量，不是任务总数；任务总数由投进任务通道的数量决定（总量大、峰值小，靠排队消化）。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func doJob(j int) {
	fmt.Printf("job %d start\n", j)
	time.Sleep(50 * time.Millisecond)
	fmt.Printf("job %d done\n", j)
}

func main() {
	active := make(chan struct{}, 3) // 信号量：最多 3 个并发
	jobs := make(chan int, 9)        // 9 个任务（总量）
	for j := 1; j <= 9; j++ {
		jobs <- j
	}
	close(jobs) // 必须关闭，否则 for range 不退出

	var wg sync.WaitGroup
	for job := range jobs { // 读完自动退出
		active <- struct{}{} // 占配额，满了就阻塞
		wg.Add(1)
		go func(j int) {
			defer wg.Done()
			defer func() { <-active }() // 还配额，务必 defer（否则 panic 会永久占住）
			doJob(j)
		}(job)
	}
	wg.Wait()
	fmt.Println("done: 峰值恒为 3，总量 9")
}
```

## 总结与追问预判
**背这三句就够**：① **信号量 = 容量 N 的 channel**；② **写入占配额、读出还配额**；③ **限的是峰值，不是总量**。
**预判追问**：
- 「官方信号量怎么用？」→ `semaphore.NewWeighted(n)` + `Acquire`/`Release`，支持加权与 context（见 1015 官方信号量）。
- 「和互斥锁什么关系？」→ 互斥锁是容量 1 的信号量特例（见 1015 channel 互斥锁）。
- 「忘了还配额呢？」→ 后续永久阻塞，故必须 `defer` 还。

## ⚠️ 原文纠错
1. 事实核校：原文"active 容量为 3 即最多三个执行"准确；补充——归还必须放在 `defer` 里，否则任务 panic 会**永久占住配额**，后续全部卡死。
2. 易混点：原文"jobs 的容量表示可容纳任务总数"应理解为**缓冲长度**，它与并发峰值无关；峰值只由信号量的容量决定。
3. 崩坏词归一：源码将 channel、goroutine、信号量、任务等术语音译为多组崩坏词，本卡统一为规范术语。
