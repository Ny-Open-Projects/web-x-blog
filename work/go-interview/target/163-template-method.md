# 163 模板方法：固定流程骨架留钩子

> 分类：设计模式/行为型 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**流程骨架** / **钩子方法** / **嵌入**
> 原文锚点：第 8~16 段「模板方法定义算法框架，把可变步骤延迟到子类」

## 一句话总述
模板方法把算法的固定骨架写死、把可变步骤留成钩子让子类填充；Go 没有继承重写，用"嵌入结构体 + 可覆盖的钩子字段/接口"实现同款效果。

## 面试官视角
- 意图：是否理解模板方法是"控制反转"——父类调子类，而非 Go 常见的组合。
- P5 知用嵌入+钩子 / P6 说清 Go 里用函数字段或接口让子类注入步骤 / P7 知 Go 更常用组合而非模拟继承的模板方法。
- 红旗：以为 Go 必须靠继承才能用模板方法；把钩子写成必填导致调用方必传。
- 惊艳点：Go 用"基础结构体持有 step 函数字段，零值即默认实现"来模拟模板方法，调用方只覆盖关心的步骤 —— 验证：`testing.T` 的清理钩子即用此思路，go1.26.5 `[经验]`。

## 主问答
**Q（面试官原话）：** 一套流程大部分固定、个别步骤要变怎么写？
**A：**
1. **结论**：把固定流程放进一个函数/方法，可变步骤抽成钩子（函数字段或接口方法），由调用方注入。
2. **机制**：基础结构先跑不变部分，到可变点调用钩子；钩子零值用默认行为，不强制覆盖 `[经验]`。
3. **边界**：Go 没有"父类调子类重写"的虚函数，靠组合注入而非继承；过度抽象会把简单流程写复杂。
**加分层：** 若步骤差异巨大，模板方法反而不如直接传整个策略/函数清晰，别硬套骨架。

type Cook struct{ boil func(); fry func() }
func (c Cook) Run() {
	if c.boil != nil { c.boil() } // 可变步骤，零值用默认
	if c.fry != nil { c.fry() }
}
