# 158 限流与隔离（含高可用四基）

> 分类：微服务/高可用 | 难度：L3 | 题型：设计题 | 频率：高 | 关键词：**限流** / **令牌桶** / **隔离** / **消除单点** / **服务分级**
> 原文锚点：第 12~20,39~59 段「消除单点/可回滚/可禁用/服务分级四基；限流令牌桶漏桶超载丢部分；隔离服务/线程池/进程级」

## 一句话总述
限流是"超载时只服务部分请求、其余快速丢弃"保整体；隔离是"把故障关进笼子"——服务/线程池/进程级隔离限制影响面（应急车道思想）。二者之上还有高可用四基：消除单点、可回滚、可禁用、服务分级。

## 面试官视角
- 意图：考察候选人对"流量管控"与"爆炸半径"两套思想的区分。
- P5 知道限流丢部分保整体、隔离限影响面；P6 能说清令牌桶/漏桶与隔离维度；P7 能讲服务分级（核心预留资源、核心调非核心要防被拖）。
- 红旗：以为限流=拒绝所有；以为隔离只是"不同机器"。
- 惊艳点：点出"服务分级"是前置设计——核心业务预留更多资源、核心调非核心失败时不能拖垮主流程（超时/熔断兜底）。

## 主问答
**Q（面试官原话）：** 限流和隔离怎么帮微服务抗故障？
**A：**
1. **结论**：限流用令牌桶/漏桶对访问限速，超载时丢弃部分请求保整体可用；隔离把不同服务/资源分池，故障只影响局部（应急车道类比）。
2. **机制**：令牌桶按速率发令牌、无令牌则拒/排队；漏桶以恒定速率出水、突发被平滑；隔离可做到服务级、进程级甚至线程池级，给不同服务独立资源 `[源码]`。
3. **边界**：高可用四基是前提——消除单点（多副本+负载均衡）、可回滚（升级留退路）、可禁用（功能开关快速关）、服务分级（核心多投资源）。限流/隔离是"故障中减损"，四基是"故障前预防" `[经验]`。

## 关键代码
```go
// 示意，未验证：令牌桶限流骨架
type TokenBucket struct {
    mu       sync.Mutex
    tokens   float64
    capacity float64
    rate     float64 // 每秒补充
    last     time.Time
}

func (b *TokenBucket) Allow() bool {
    b.mu.Lock(); defer b.mu.Unlock()
    now := time.Now()
    b.tokens += b.rate * now.Sub(b.last).Seconds()
    if b.tokens > b.capacity { b.tokens = b.capacity }
    b.last = now
    if b.tokens >= 1 {
        b.tokens--
        return true
    }
    return false // 无令牌：快速丢弃/排队
}
```
