# 1240 死锁检测与锁超时：两个开关一个阈值

> 分类：数据库 / MySQL 锁 | 难度：L4 | 题型：配置题 | 频率：中 | 关键词：**死锁检测、innodb_lock_wait_timeout、回滚、锁优先级、监控**

> 原文锚点：第 57~75 段「从 MySQL 5.7.15 开始新增的一个配置项，我们可以通过它来开启对死锁的检测，默认也是 on…在高并发的系统中使用死锁检测会引起性能问题，建议关闭…锁等待超时时间默认是 50 秒，一般我们建议 5 到 10 秒…锁超时之后会回滚整个事务」

## 一句话总述
死锁靠死锁检测开关（5.7.15 起，默认 ON，高并发建议关闭）主动发现，靠锁等待超时（默认 50 秒，建议 5~10 秒）被动兜底，二者配合锁监控构成完整防线。

## 面试官视角
P6 知道有锁等待超时；P7 要说出**版本 5.7.15**、**默认 ON**、**高并发为何要关**，以及**超时回滚范围由独立开关决定**这个细节。

## 主问答
**Q（面试官原话）：** 死锁怎么处理？锁等待超时设多少合适？

1. **检测开关**：自 **5.7.15** 起新增配置项用于开启死锁检测，**默认 ON** `[源码]`。
2. **高并发建议关闭**：官方指出高并发下死锁检测会引起性能问题 `[源码]`。
3. **关闭的代价**：死锁不再被主动检测，只能等超时兜底，故超时值须相应调小 `[经验]`。
4. **检测有深度上限**：默认 200；等待队列中行锁规模过大时也可能直接判定死锁，阈值以版本手册为准 `[源码]`。
5. **锁等待超时**：默认 **50 秒**，建议设 **5~10 秒**，避免阻塞长时间扩散 `[源码]`。
6. **超时回滚范围**：该开关默认 OFF，即只回滚超时那条语句；设为 ON 后**回滚整个事务** `[源码]`。
7. **锁优先级**：可为高优先级操作指定较高锁优先级，减少等待时间 `[源码]`。
8. **持续监控**：监控锁状态，及时发现死锁与持锁过久的事务 `[源码]`。

| 结论成立版本 | 翻转点 | 现在该怎么答 |

| 5.7.15 起 | 引入死锁检测开关 | 默认 ON |

## 关键代码
```sql
-- 查看死锁检测开关（5.7.15 起支持，默认 ON）
SHOW VARIABLES LIKE 'innodb_deadlock_detect';

-- 高并发场景关闭死锁检测（需配合更短的锁等待超时）
SET GLOBAL innodb_deadlock_detect = OFF;

-- 查看与设置锁等待超时（默认 50 秒，建议 5~10 秒）
SHOW VARIABLES LIKE 'innodb_lock_wait_timeout';
SET GLOBAL innodb_lock_wait_timeout = 5;

-- 锁超时后是否回滚整个事务（默认 OFF，即只回滚超时语句）
SHOW VARIABLES LIKE 'innodb_rollback_on_timeout';

-- 锁相关的运行状态概览
SHOW STATUS LIKE '%lock%';
```

## 总结与追问预判
**主动检测 + 被动超时双保险**。补一句「关闭检测后必须把超时从 50 秒调小，否则死锁要等 50 秒才解开」——这是体现工程判断的关键句。优化方向见同批 1240-lock-optimization。
