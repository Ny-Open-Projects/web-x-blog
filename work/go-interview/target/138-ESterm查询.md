# 138 ES term 查询

> 分类：Elasticsearch 查询 | 难度：L3 | 题型：概念题 | 频率：高 | 关键词：**term**/**精确匹配**/**keyword**/**不分词**
> 原文锚点：第 1~7 段「term 查询的精确匹配语义」

## 一句话总述
`term` 查询是 **ES 里的精确匹配查询**：对查询条件**不做分词**，直接用整串去倒排索引里找**完全相等**的 term；适用于 `keyword`、数值、日期等不分词字段。

## 面试官视角
- 考察意图：term 与 match 的根本区别——"分不分词"。
- 分档：P5 知 term 不分词、精确匹配；P6 知适用于 keyword/数值；P7 能讲"用 term 查 text 字段查不到"的坑。
- 红旗答案：以为 term 和 match 一样会对关键词分词。
- 惊艳点：点出"term 查 text 字段基本失效"——因为 text 被分词、倒排里是分词后的 term。

## 主问答
**Q（面试官原话）：** term 查询和 match 有什么区别？
**A：**
1. **不分词**：`term` 把查询值当作一个完整 term，不走 analyzer 分词；必须字段倒排里存在**一模一样**的 term 才命中。
2. **适用字段**：`keyword`、数值、日期、布尔等**本身不分词**的字段；对这些字段做精确过滤（如 `status=1`、`user_id=123`）最合适。
3. **对 text 失效**：text 字段写入时已被分词（如"测试文本"→`测试`、`文本`两个 term），用 `term` 查"测试文本"整串，倒排里没有这个 term → **查不到**。
4. **语法**：`{"term":{"field":{"value":50}}}`（注意是 `value`，不是 `query` 包裹关键词）。

## 关键代码
```json
{ "term": { "status": { "value": 1 } } }
```

## 总结与追问预判
term = 精确匹配、不分词，命中要求倒排存在完全相等的 term；用于 keyword/数值/日期的等值过滤，查 text 字段几乎必失效（应改用 `.keyword` 或 match）。
