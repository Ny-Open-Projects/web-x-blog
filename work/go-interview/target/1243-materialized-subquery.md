# 1243 物化子查询 vs 非物化（DEPENDENT SUBQUERY）

> 分类：MySQL 调优 | 难度：中高 | 题型：原理 | 频率：中高 | 关键词：**物化子查询、SUBQUERY、DEPENDENT SUBQUERY、临时表、空间换时间**

> 原文锚点：第 71~95 段「subquery 物化、dependentsubquery 非物化、5.6 特性、临时表哈希索引、空间换时间」

## 一句话总述
子查询的执行有两种形态：SUBQUERY 表示「物化子查询」——MySQL 把子查询结果物化成内存临时表（主键用哈希索引、去重、体积小），只执行一次，以空间换时间；DEPENDENT SUBQUERY 表示「非物化」，子查询依赖外层，可能对外层每行都执行一次。优化器按扫描范围与复杂度决定物化与否；结果过大超过 tmp_table_size 则临时表退化到磁盘。

## 面试官视角
物化子查询是 5.6+ 的重要优化，面试常考。考官看你能不能讲清：① SUBQUERY=物化（一次）、DEPENDENT SUBQUERY=非物化（多次）；② 物化本质空间换时间（临时表）；③ tmp_table_size 超限转磁盘临时表；④ 物化后外层仍可能全表/全索引扫描，并非万能。能点出「缩小子查询范围更易触发物化」是实战加分。

## 主问答
**Q（面试官原话）：** SUBQUERY 和 DEPENDENT SUBQUERY 有什么区别？

1. **SUBQUERY=物化**：优化器把子查询结果物化成临时表（哈希索引主键、去重、体积小），子查询只执行一次，外层拿临时表来匹配。
2. **DEPENDENT SUBQUERY=非物化**：子查询带外层依赖，无法提前物化，常对外层每一行都重执行一次，性能差。
3. **触发条件**：优化器根据子查询扫描范围与复杂度判断；子查询范围小（如加 WHERE id=1）更易被物化。
4. **代价与边界**：物化是空间换时间；若子查询结果超 tmp_table_size，临时表落到磁盘，且外层仍可能全表/全索引扫描。

## 关键代码
```sql
-- 子查询范围小 → 易被物化（select_type=SUBQUERY）
SELECT * FROM t1 WHERE id IN (SELECT id FROM t2 WHERE id = 1);
```

## 总结与追问预判
核心：**SUBQUERY=物化一次（空间换时间），DEPENDENT SUBQUERY=非物化每行一次；范围小易物化，超 tmp_table_size 落磁盘**。追问常接「union 中的 dependent」（见 1243-union-dependent）。
