# 1316 ES 性能优化全貌深挖

## 思路与架构
ES 性能优化分四层：**硬件/OS**（盘、swap、JVM buffer）→ **索引/写入**（index.sort、ID 选型、refresh、translog）→ **查询/路由**（term 缓存、routing 降扇出）→ **集群规划**（分片大小、副本、分配均匀）。每层都是"用一种资源换另一种"的权衡。

## 方案取舍
- **refresh_interval vs 近实时性**：调大省 IO/CPU 但可见延迟升高；日志场景（秒级延迟可接受）收益最大，交易检索不宜过大。
- **translog durability=async vs 可靠性**：异步换吞吐，崩溃丢最后窗口；仅日志/指标类可承受。
- **自定义 ID vs 自动 ID**：需增删改必自定义（避免查 ID 链路放大）；仅追加用自动 ID 更快。
- **分片数多因子 vs 拍脑袋**：多因子便于整除节点数、均摊负载；质数分片后期无法均摊。单分片 10~50GB 是经验上沿。
- **副本数 vs 成本**：副本提升读可用但等倍耗资源；日志可 0，核心业务按 SLA 设 1+。
- **定向 routing vs 简单写入**：降扇出、抗局部故障，但破坏默认负载均衡、GET 须带 routing。

## 答题技巧
1. **分层展开**：按"硬件→索引→查询→集群"四层答，显出体系而非零散参数。
2. **代价意识**：每个优化都点出"换了什么"——一致性/可靠性/存储/复杂度。
3. **量化记忆**：10~50GB 单分片、20 分片/GB 堆、refresh 调大对大文档显著、translog async 仅日志。
4. **反直觉点**：① 自动 ID 写入反而更快；② range(now) 永不命中缓存，要拆字段用 term；③ 分片数要"多因子"整除节点；④ routing 后 GET 必带 routing。
5. **收尾钩子**：自然过渡到"架构层冷热分离/读写分离/多集群"，体现端到端视角。
