# 806 GC 分类总览（深挖）

> 分类：Go/运行时 | 难度：L4 | 题型：体系化深挖 | 频率：中 | 关键词：**GC 谱系** / **选型决策** / **追踪式 vs 引用计数**

## 思路与架构
GC 的方法论架构是一棵两层树：
- **第一层（派别）**：追踪式 vs 引用计数式——区别在于"是否主动扫堆找存活"（追踪式是）还是"被动等计数归零"（引用计数式是）。
- **第二层（追踪式细分）**：六种实现围绕两个坐标轴展开——
  - **碎片轴**：标记清除（有碎片）→ 标记整理/复制（无碎片，代价不同）。
  - **停顿轴**：分代/增量/并发（都是为降 STW，机制与代价各异）。
- **语言落点**：Go = 追踪式 ∩ 并发 ∩ 非分代 ∩ 非移动；Java = 追踪式 ∩ 并发 ∩ 分代；Python = 引用计数 + 标记清除兜底。

## 方案取舍
| 维度 | 追踪式（Go/Java） | 引用计数式（Python/ObjC） |
|---|---|---|
| 回收及时性 | 批量回收，有延迟 | 对象死即收，及时 |
| 循环引用 | 能回收 | **不能回收**（需兜底） |
| 实现复杂度 | 高（需 STW/写屏障） | 低（计数器） |
| 额外开销 | 扫堆成本 | 计数维护成本 |
| 停顿 | 可并发压低 | 基本无 STW |

面试取舍要点：**没有"最好的 GC"，只有最适合语言特性的 GC**。Go 选追踪式是为循环引用兜底 + 并发低延迟；引用计数式为实现简单 + 回收及时。

## 答题技巧
1. **先画树再展开**：开口"GC 分两派，追踪式和引用计数式"，立刻建立框架感，避免被追问带偏。
2. **用坐标轴收口**：讲到六种细分时，用"碎片轴 / 停顿轴"两句话收，显出体系化。
3. **锚定 Go**：每讲到一种，点一句"Go 用/不用这个、为什么"，把广度题落回 Go 岗位语境。
4. **循环引用是钩子**：引用计数的死穴 → 自然解释"Go 为什么不选引用计数" → 引出追踪式六细分。
5. **版本边界**：Go 的"非分代"是主动设计，不是短板；对比 Java 时分代假设差异而非优劣。
