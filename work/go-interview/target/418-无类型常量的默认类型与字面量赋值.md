# 418 无类型常量的默认类型与字面量赋值

> 分类：Go 数值类型 | 难度：L3 | 题型：陷阱题 | 频率：高 | 关键词：**无类型常量**/**默认类型 float64**/**字变量**/**strconv.IntSize**/**rune**

> 原文锚点：第 5~20 段「字面量能否赋给整型 / 默认类型推断 / 字符字面量」

## 一句话总述
数值字面量只有在**不需要四舍五入**时就能表示整型的值，所以 `var a int = 1.00` 是合法的；而 `b := 1.0` 的默认类型恒为 `float64`，**与操作系统是 32 位还是 64 位无关**——架构只影响 `int`/`uint` 的位宽。

## 面试官视角
这题几乎必错一次。考官就等着你说「32 位系统上 1.0 是 float32」。记住规范原文：无类型浮点常量的默认类型是 `float64`，没有任何架构分支。能顺带讲清 `strconv.IntSize` 管的是什么，这题就满分。

## 主问答
**Q（面试官原话）：** `var a int = 1.00` 能编译过吗？`b := 1.0` 是什么类型？

1. **可以编译**：数值类型的字面量，只要不需要四舍五入就能表示某个整数类型的值，就可以赋给该整型。
2. **判断依据**：`1.00` 是变量 a 的字面量，它不需要四舍五入即可表示整数，因此可用来表示整型值。
3. **默认类型恒定**：不给类型直接用 `1.0` 声明变量时会自动推断类型，无类型浮点常量的默认类型**恒为 float64**，不受系统位数影响。
4. **架构只影响 int**：`strconv.IntSize` 反映当前系统是 32 位还是 64 位，它决定的是 `int`/`uint` 的位宽，**不改变**浮点常量的默认类型。
5. **字符字面量**：`var c int = 'x'` 输出 120 与 int 类型，因为字符字面量的值就是其码点，此处即字母 x 的十进制码点。

## 关键代码
```go
package main

import (
	"fmt"
	"reflect"
	"strconv"
)

func main() {
	var a int = 1.00 // 合法：字面量可精确表示
	b := 1.0
	var c int = 'x'
	// [实测] 输出：1 float64 120 / IntSize = 64
	fmt.Println(a, reflect.TypeOf(b), c)
	fmt.Println("IntSize =", strconv.IntSize) // 只反映 int/uint 位宽
}
```

## 总结与追问预判
核心：**「不需四舍五入即可表示」决定能否赋给整型；默认类型恒 float64**。追问常拐向「1.5 赋给 int 会怎样」「常量和变量的类型推断差别」，备好「不可表示则编译失败」与「常量精度任意、变量定宽」两句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称 `b := 1.0`「在 64 位系统是 float64、32 位系统是 float32」——**错误**。Go 规范规定无类型浮点常量的默认类型恒为 float64，与操作系统和架构无关。
2. 事实核校： [经验] 原文用 `strconv.IntSize` 推断浮点默认类型——该值只反映 `int`/`uint` 的位宽（32 或 64），与浮点默认类型无关，两者不可混用。
3. 崩坏词归一：源码将 Go / float64 / strconv / 码点 等音译为多组崩坏词，本卡统一为规范术语。
