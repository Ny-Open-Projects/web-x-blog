# 1021 多发送者的通道关闭方案

> 分类：并发模型 | 难度：L4 | 题型：工程题 | 频率：高 | 关键词：**stop channel** / **广播退出** / **WaitGroup 收口**

> 原文锚点：第 77~112 段「多发送者单接收者、或多对多：用额外 stop channel 通知停发，协调者收口后关数据 channel」

## 一句话总述
多发送者场景不能让任何一方直接关数据 channel。做法是引入一个 stop channel 广播"停止发送"信号：发送者收到后退出，协调者（WaitGroup 收齐或独立 goroutine）确认无发送者后再关数据 channel。一句话背法：**「多发送者禁止任一方关数据channel；用 stop channel 广播停发，协调者 WaitGroup 收齐后唯一关闭数据channel；先停发后关数据」**。

## 面试官视角
这是考察"能否在 N 个发送者下既防向已关写 panic 又防重复 close"的工程题。
- **P5**：知道 stop channel 思路。
- **P6**：说清"先停发再关数据"顺序。
- **P7**：知道 N:N 必须独立协调者关、关前确无写入。
- **红旗**：让接收方直接 close 数据 channel（其余发送方还在写 → panic）；多发送者各自 close。
- **惊艳点**：stop 关闭后所有发送者都能读到零值退出（广播），但数据 channel 只能在"零发送者"后由唯一协调者关 `[源码]`。

## 主问答
**Q（面试官原话）：** 多个 goroutine 往一个 channel 发，怎么安全关？

**先铺垫（由浅入深第 1 层）**：单发送者时"发完 close"很自然。但一旦有多个发送者，谁都没有资格去 close 数据 channel——因为只要你 close，别的发送方可能正要写，立刻 panic。解法是用一条"第三方信号"先让所有人停手，再关。

1. **结论（第 2 层·机制）**：数据 channel 谁都不能随意关；用独立 stop channel 通知所有发送者停发 `[源码]`。
2. **机制（第 3 层）**：接收（或协调者）close(stop) → 各发送者 `select` 收到零值退出；WaitGroup 等全部发送者结束后，由协调者 close 数据 channel `[源码]`。
3. **边界（第 4 层）**：N:N 时关闭既不在发送方也不在接收方，而在独立 goroutine/main；关前必须保证不再有发送者写入，否则 panic `[源码]`。
4. **铁律（第 5 层）**："先停发、后关数据"的顺序不能反——反了就是向已关 channel 写，panic `[经验]`。
5. **进阶（第 6 层）**：stop 关闭后所有发送者都能读到零值退出，这是无缓冲 channel close 的广播语义（见 1021 四条特性）`[边界]`。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	data := make(chan int)
	stop := make(chan struct{})
	var senders sync.WaitGroup

	// 5 个发送者：收到 stop 广播即停发退出
	for i := 0; i < 5; i++ {
		senders.Add(1)
		go func(id int) {
			defer senders.Done()
			for {
				select {
				case <-stop: // 收到广播，停发退出
					return
				case data <- id:
				}
			}
		}(i)
	}

	// 接收者（演示简单启动一个）
	go func() {
		for range data {
		}
	}()

	// 协调者收口：先广播停发，等所有发送者退出，再唯一关闭 data
	close(stop)   // 广播：停止发送
	senders.Wait() // 所有发送者已退出，不再有写入
	close(data)    // 此刻关闭数据 channel，安全（无发送者再写）
	fmt.Println("data channel closed safely, no panic")
}
```

## 总结与追问预判
**背这三句就够**：① **多发送者禁止任一方关数据 channel**；② **stop channel 广播停发，WaitGroup 收齐**；③ **协调者唯一关闭数据 channel（先停发后关数据）**。
**预判追问**：
- 「单发送者怎么办？」→ 发送方发完 close，接收方 range 退出（见 1021 单发送者）。
- 「重复关会怎样？」→ panic（见 1019 重复关闭）。
- 「泄漏怎么防？」→ 显式退出 + ctx 取消（见 1019 channel 泄漏）。
