# 1012 锁选型决策：自旋 / 互斥 / 读写

> 分类：Go / 并发 / 锁 | 难度：L3 | 题型：选型题 | 频率：中 | 关键词：**选型决策** / **Mutex 快路径 CAS** / **读写锁写锁不等价互斥** / **读多** / **读写都多**
> 原文锚点：第 19~43 段「不确定→互斥/读写；很短→自旋；读多→读写锁；读写都多→互斥；Go Mutex 加锁先 CAS 判竞争(无竞争直取否则慢路径)；基准测试互斥明显优于读写锁写锁(读写锁底层含互斥、写锁不等价互斥)」

## 一句话总述
锁选型经验：**不确定持有时间→互斥锁/读写锁；确定极短→自旋锁；读多→读写锁；读写都多→互斥锁**（写锁底层是互斥锁、实现更复杂，读写都频繁时读被写阻塞概率高、失去读锁优势）。Go 的 `sync.Mutex` 加锁时**先 CAS 判竞争**：无竞争直接拿、有竞争才走慢路径睡眠。

- P5 知读多用读写锁；P6 知读写都多回到互斥、Mutex 先 CAS 快路径；P7 知"读写锁写锁不等价互斥（底层含互斥、更复杂）" `[边界]` 见 925-rwmutex-impl（读写锁实现）、925-mutex-impl（Mutex 实现）、1013-mutex-pessimistic（Mutex 悲观锁）。

- 惊艳点：点出"基准测试里互斥锁写操作明显优于读写锁写锁，因为读写锁写锁实现更复杂、还要管读锁相关逻辑" `[经验]`。

## 主问答
**Q（面试官原话）：** 几种锁怎么选，为什么读写锁写锁比互斥锁慢？
**A：**
1. **决策树**：不确定持有时间→互斥/读写；确定极短→自旋；读操作多→读写锁（读锁不互斥读）；读和写都频繁→互斥锁（读被写阻塞概率高、读写锁优势尽失）。
2. **Mutex 快路径**：`sync.Mutex` 加锁先 `CAS` 判是否有竞争，无竞争直接获取、跳过慢路径，有竞争才睡眠等唤醒——这是它快的原因。
3. **读写锁写锁 ≠ 互斥锁**：读写锁底层就是用互斥锁实现的，还要额外管读锁计数/升级等逻辑，因此写锁更重；基准测试里互斥锁写操作明显比读写锁写锁快。

func pick(reads, writes int, holdShort bool) string {
    if holdShort      { return "spinlock" } // 极短临界区
    if reads > writes*4 { return "rwmutex" } // 读明显多
    return "mutex"                         // 不确定/读写都多
}

- 选型：短→自旋、读多→读写、读写都多/不确定→互斥；Mutex 先 CAS 快路径、读写锁写锁更重。
