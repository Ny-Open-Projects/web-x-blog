# 1021 单发送者多接收者的关闭责任

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**fan-out** / **发送方关闭** / **WaitGroup**
> 原文锚点：第 56~77 段「一个发送者多个接收者：由发送者关闭 channel 并退出发送」

## 一句话总述
一个发送者、多个接收者（fan-out）时，关闭责任归**唯一发送者**：它在发完数据后 close，五个接收者 for-range 检测到关闭态即全部退出，干净无 panic。

## 面试官视角
- 意图：是否掌握"关闭责任唯一"这一核心约定。
- P5 知发送方关 / P6 说清为何接收方不能关（会触发已关还写） / P7 知多发送者要升级方案。
- 红旗：让接收方去 close 数据 channel；多发送者也照搬此方案。
- 惊艳点：发送方唯一 → close 必然只一次，且 close 时机在发送结束后，杜绝"向已关写" `[源码]`。

## 主问答
**Q（面试官原话）：** 一个 goroutine 发、五个 goroutine 收，谁关 channel？
**A：**
1. **结论**：由**发送方**关闭；它在 for 循环发送完毕后再 close，接收方一律 for-range 读取。
2. **机制**：发送方唯一，close 只发生一次且位于发送之后；接收方读到关闭态自动退出，主协程用 WaitGroup 等齐。
3. **边界**：此方案前提是**发送者只有一个**；一旦多个发送者，接收方关数据 channel 会让别的发送方写已关 channel 而 panic。
**加分层：** 关闭前必须保证"不再发送"，顺序错就前功尽弃。

## 关键代码
```go
// 示意，未验证：单发送者 fan-out
ch := make(chan int)
var wg sync.WaitGroup
for i := 0; i < 5; i++ { wg.Add(1); go func() { defer wg.Done(); for range ch {} }() }
go func() { for i := 0; i < 10; i++ { ch <- i }; close(ch) }()
// 接收方退出后 wg.Wait()
```

## 总结与追问预判
- 唯一发送方关闭最稳妥；close 在发送之后，接收方 range 自动收尾。
- 预判：多发送者怎么办 → 见 1021。
