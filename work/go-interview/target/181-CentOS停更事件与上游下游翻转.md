# 181 CentOS 停更事件与上游 / 下游翻转

> 分类：Linux 发行版 | 难度：L3 | 题型：场景题 | 频率：中 | 关键词：**CentOS**/**RHEL**/**CentOS Stream**/**EOL**/**迁移**

> 原文锚点：第 41~63 段「CentOS 与 RHEL 关系 / 停更决策与影响」

## 一句话总述
CentOS Linux 原本是 RHEL 的**下游**免费重建版；2020 年 12 月红帽宣布 CentOS 8 提前至 2021 年底停止、CentOS 7 于 2024 年 6 月 30 日停止维护，重心转向 CentOS Stream——而 Stream 位于 RHEL 的**上游**，这次上下游翻转才是事件核心。

## 面试官视角
这题是典型的「行业事件 + 技术判断」。能说清上游/下游方向，说明你懂发行版生产流程；能说清对业务的具体影响（安全补丁断供、兼容性、迁移成本），说明你有工程视角，而不是只会背新闻。

## 主问答
**Q（面试官原话）：** CentOS 停更怎么回事？CentOS Stream 和原来的 CentOS 一样吗？

1. **原定位**：CentOS Linux 由 RHEL 源码重建而来，去掉商标与商业支持，免费且与 RHEL 二进制兼容，因此在服务器领域被广泛采用。
2. **停更时间线**：2020-12-08 宣布 CentOS 8 提前至 2021 年底 EOL，CentOS 7 维护至 2024-06-30，此后不再有免费的 RHEL 等价物。
3. **Stream 在上游**：Stream 位于 Fedora 与 RHEL 之间，比 RHEL 更早拿到变更，滚动更新、稳定性更低——它不再是「免费版 RHEL」。
4. **实际冲击**：安全补丁断供导致风险上升、兼容性问题频发、迁移成本高；同时倒逼团队重新评估 OS 选型。
5. **大背景**：云厂商定制系统普及、容器化降低对操作系统的依赖，使「换发行版」不再是伤筋动骨的事。

## 关键代码
```go
// Go 侧视角：迁移前先给机器做发行版指纹，避免脚本在跨系机器上跑错分支
package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
)

func main() {
	f, _ := os.Open("/etc/os-release")
	defer f.Close()
	sc := bufio.NewScanner(f)
	for sc.Scan() {
		line := sc.Text()
		if strings.HasPrefix(line, "ID=") || strings.HasPrefix(line, "VERSION_ID=") {
			fmt.Println(line)
		}
	}
}
```

## 总结与追问预判
核心：**CentOS 原是 RHEL 下游，Stream 却在上游**。追问常拐向「你们线上怎么迁的」「为什么选 Rocky/AlmaLinux」，备好「同系迁移保二进制兼容，跨系迁移要重做包与配置」这条判断链。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文把 CentOS Stream 仍描述为 RHEL 的「下游分支」——Stream 位于 RHEL **上游**（Fedora → Stream → RHEL），先于 RHEL 拿到变更、稳定性更低。
2. 事实核校： [经验] 原文称 CentOS 7「在生命周期结束后停止维护」，未给出具体日期；实际维护终止日为 2024 年 6 月 30 日。
3. 存疑标记： [存疑] 原文引用机构统计称该发行版在中国服务器市场份额近四分之一——份额数据有时效性，面试引用须标注统计年份。
4. 崩坏词归一：源码将 CentOS / Red Hat / RHEL 等音译为多组崩坏词，本卡统一为规范术语。
