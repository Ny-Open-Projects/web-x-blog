# 420 栈伸缩时内存块地址变化与逃逸隐式指针

> 分类：Go 语言基础 · 内存布局 | 难度：L3 | 题型：机制题 | 频率：中 | 关键词：**协程栈扩容缩容**/**内存块搬迁**/**地址刷新**/**逃逸隐式指针**/**栈快不需 GC**
> 原文锚点：第 21~50 段「协程栈初始 2KB 自适应、上限 1GB/250MB；栈上开辟快不需 GC、CPU 缓存友好；逃逸时栈留隐式指针指向堆；栈伸缩内存块地址改变」

## 一句话总述
Go 每个 goroutine 有**独立连续栈**，初始约 2KB、运行时按需扩容/缩容（Go 1.19 起自适应），上限 64 位 1GB / 32 位 250MB（可用 `runtime/debug.SetMaxStack` 改）。**栈扩容/缩容时，栈上已有内存块会被整体搬迁到新栈，地址随之改变、指向它们的指针也会被刷新**。发生逃逸时，本在栈上的值被移到堆，但栈上仍留一个**隐式指针**引用它——这正是"栈→堆"的引用关系。

## 面试官视角
- 考察意图：是否理解"栈上地址不是稳定的"，以及逃逸时栈与堆的引用链——很多"取地址两次不一样"的题根在这。
- 分档：P5 知栈快、堆需 GC；P6 知协程栈 2KB 自适应、上限 1GB；P7 能讲清"栈伸缩搬迁→地址变→指针刷新"和逃逸隐式指针。
- 红旗：以为局部变量地址恒定；或以为逃逸后栈上就什么都不剩了。
- 惊艳点：用源码示例（int 两次取地址不同）证明"栈地址随伸缩变化"，并指出根因是栈搬迁而非 GC 移动。

## 主问答
**Q（面试官原话）：** 为什么同一个局部变量，两次取地址结果不一样？
**A：**
1. **栈快、堆慢**：栈上开辟由编译器管理、**不需 GC**、对 CPU 缓存更友好；堆是虚拟概念、全局可达、需 GC、供协程间共享，要考虑并发安全 `[经验]`。
2. **栈伸缩搬迁地址变**：协程栈扩容/缩容时会换一块更大的栈，原栈上内存块**整体搬过去**，地址改变；凡是栈上指向这些块的指针（含隐式指针）**地址都会被刷新**。源码示例：函数内定义超大数组撑大栈后，同一 int 的地址前后不同（去掉防内联注释后又相同——说明是栈伸缩而非别的原因）。
3. **逃逸隐式指针**：局部变量逃逸到堆后，值本身在堆，但**栈上仍留一个指向它的指针（隐式指针）**引用着它；包级（全局）变量同理，被全局区的隐式指针引用。所以"逃逸"不是栈空了，而是栈→堆多了一条引用。

## 关键代码
```go
package main

import "fmt"

func f() {
    var big [1 << 20]int // 撑大栈，触发栈扩容搬迁
    x := 1
    fmt.Println(&x) // 栈扩容后地址已变
}

func main() {
    x := 1
    fmt.Println(&x) // 地址 A
    f()
    fmt.Println(&x) // 仍是地址 A（main 的栈未搬迁）
}
// 注：同一 goroutine 内、若中间发生栈伸缩，局部变量地址可能改变
```
