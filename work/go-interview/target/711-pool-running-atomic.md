# 711 原子维护运行计数

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：低 | 关键词：**atomic** / **int32** / **释放时机**
> 原文锚点：第 91~131 段「addRunning 用原子操作，减一误放函数首行致少五个」

## 一句话总述
用 `int32` + `atomic.AddInt32/LoadInt32` 维护当前运行任务数；释放（减一）必须放在任务真正结束后，否则计数失真。

## 面试官视角
- 意图：是否知道并发计数必须原子，且"释放时机"写错会静默少算。
- 分档：P5 知用原子 / P6 说清增删配对 / P7 知放首行为何丢计数。
- 红旗：用裸 int 计数；把减一写在函数开头。
- 惊艳点：减一误放首行，循环 100 任务只数到 95，移到末尾才得 100 `[经验]` 原文 demo。

## 主问答
**Q（面试官原话）：** 怎么统计池里正在跑的任务数？为什么我数少了？
**A：**
1. **结论**：字段用 `int32`，增删都走 `atomic.AddInt32`，读取走 `atomic.LoadInt32`，避免竞态。
2. **机制**：任务入队 `addRunning(+1)`，结束 `addRunning(-1)`；原文把减一写在函数第一行，任务还没跑完就减，叠加调度让计数提前归零，最终漏算。
3. **边界**：释放必须紧跟任务真正结束（用 `defer` 放末尾），放首行等于"未干完就销账"。
**加分层：** 计数只用于监控/等待结束，写错不影响功能但会误导运维判断。
