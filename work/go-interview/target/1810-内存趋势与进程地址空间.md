# 1810 内存趋势与进程地址空间：vmstat / slabtop / pmap

> 分类：Linux/内存排查 | 难度：L2 | 题型：工具题 | 频率：中 | 关键词：**vmstat** / **slabtop** / **pmap** / **si/so/wa**
> 原文锚点：第 32~54 段「vmstat 字段(PROCS r/b, swpd/free/buff/cache, si/so, bi/bo, in/cs, us/sy/id/wa)；slabtop 按 a/c 排序；pmap 分析进程地址空间」

## 一句话总述
定位到"系统内存有异"后，用 `vmstat`（看趋势与交换/IO/上下文切换）、`slabtop`（看哪类内核对象/cache 占用高）、`pmap <pid>`（看具体进程地址空间）三层深入。`vmstat` 里 **si/so**（换入换出）、**wa**（IO 等待）、**b**（等 IO 进程数）是内存不足的关键信号。

## 面试官视角
- 意图：考察工具链的"递进使用"——free 看静态、vmstat 看趋势、pmap/slabtop 看归属。
- P5 知道 vmstat 看内存；P6 能说清 si/so/wa/b 含义；P7 能讲清 slabtop 按对象数(a)/size(c) 排序、pmap 定位进程内库/函数占用。
- 红旗：只看 free 不追趋势；不知道 si/so 是 swap 活动、wa 高=在等 IO（常因内存不足）。
- 惊艳点：点出 vmstat 第一参数是间隔秒、第二是次数；slabtop 的 a/c 排序分别看"活跃对象数"和"slab 内存占用"。

## 主问答
**Q（面试官原话）：** free 看不出问题，怎么进一步看内存趋势和归属？
**A：**
1. **结论**：`vmstat 1` 周期性看趋势——**swpd/free/buff/cache** 内存概况，**si/so** 每秒换入/换出（>0 说明在用 swap，物理内存大概率用完），**bi/bo** 块读写（反映磁盘 IO），**in/cs** 中断/上下文切换，**wa** CPU 等 IO 占比，**b** 不可中断休眠（等 IO）进程数；`slabtop` 按 `a`(活跃对象数)/`c`(size) 排序看哪类内核对象占 cache；`pmap <pid>` 看某进程地址空间里库/函数的内存分布。
2. **机制**：vmstat 的 PROCS 行 `r`=等 CPU、`b`=等 IO；memory 行 `swpd`=已换出块；swap 行 `si/so`=换入/换出。内存不足时 free↓、si/so↑、bi/bo↑、cs↑、b↑、wa↑ 同时出现。
3. **边界**：先 `top` 按 RES 定位占用最大的进程，再 `pmap <pid>` 下钻其地址空间；cache 持续涨用 `slabtop` 找对应进程/对象 `[经验]`。

## 关键代码

```go
// Go 读取本进程常驻内存 RES（对应 top 的 RES 列、vmstat 的 free 之外进程级视角）
func readRSS() {
    b, _ := os.ReadFile("/proc/self/status")
    for _, line := range strings.Split(string(b), "\n") {
        if strings.HasPrefix(line, "VmRSS:") {
            fmt.Println(line) // VmRSS: 12345 kB —— 实际物理内存占用
        }
    }
}
```
