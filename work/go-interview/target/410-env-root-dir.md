# 410 环境变量定义全局根目录

> 分类：工程化与测试 | 难度：L2 | 题型：工程题 | 频率：中 | 关键词：**环境变量** / **GOPATH** / **路径拼接**
> 原文锚点：第 124~140 段「设 GOPATH/APP_PATH/HOME 作全局根目录，再与配置日志相对路径拼接」

## 一句话总述
把根目录写进环境变量（如 `APP_PATH`/`GOPATH`/`HOME`），代码里 `os.Getenv` 读出后与子路径拼接，得到与执行目录无关的**固定绝对路径**——适合部署期固化根目录。

## 面试官视角
- 意图：是否懂用环境变量解耦"代码位置"与"运行位置"，以及系统预设变量的用法。
- P5 知 Getenv 读变量 / P6 说清拼接固定路径 / P7 知 12-factor 配置外置、HOME 跨平台差异。
- 红旗：把根目录写死在代码里；不知道 Windows 下 HOME 是 Users\用户名。
- 惊艳点：Linux 的 `HOME` 指向当前用户主目录，Windows 下是 `Users\用户名`，跨平台需归一 `[经验]`。

## 主问答
**Q（面试官原话）：** 不想依赖代码位置，怎么让配置路径固定下来？
**A：**
1. **结论**：用环境变量（自定义 `APP_PATH` 或系统 `GOPATH`/`HOME`）承载根目录，`os.Getenv` 读出后拼接子路径。
2. **机制**：部署时把根目录注入环境变量，代码只拼相对子路径，与 cwd、exe 位置全部解耦。
3. **边界**：`HOME` 在 Linux/Windows 含义不同；变量缺失要兜底，别直接拼出空路径导致读错 `[经验]`。
**加分层：** 这是 12-factor 配置外置思路，比写死路径更利于多环境部署。

package main

import (
	"fmt"
	"os"
	"path/filepath"
)

func main() {
	root := os.Getenv("APP_PATH") // 部署注入，如 /srv/myapp
	cfg := filepath.Join(root, "config", "app.yaml")
	fmt.Println(cfg)
