# 1247 深度分页优化 深挖

> 覆盖源 12-47 全文：按主键排序的游标分页、按二级索引排序的覆盖索引两查询拆分。主卡已拆成游标分页、覆盖索引拆分、问题总览三张，本附录做横向串联与取舍。

## 方案取舍
- **游标分页 vs 覆盖拆分**：排序键为主键且有序唯一 → 游标最优（无 OFFSET、O(n) 顺序扫）；排序键为二级索引 → 只能覆盖拆分，第一查询仍带大 OFFSET 但只扫索引。
- **覆盖拆分的两查询代价**：第一查询代价在「扫 m 行索引」、第二在「k 行回查」，总优于原「扫 m+n 行 + m 次回表」；k 很大时 IN 列表受限需分批。
- **极端去 OFFSET**：二级索引场景可在第一查询上叠加「上一页末 (name,id) 复合游标」进一步消去 OFFSET，代价转纯顺序扫。

## 答题技巧
- 被问「深度分页」先答根因（跳过 m + 回表），再按排序键类型分流两种解法，比直接甩 SQL 显体系 [经验]。
- 主动边界到 `1246`（慢因量化）/ `1217`（回表 IO）/ `1247-keyset-cursor-paging`/`1247-covering-index-split`（实现），构成「根因→解法」全栈 [边界]。

## 细节与核心 API

**排序键为主键：游标分页 keyset，无 OFFSET，O(n) 顺序扫：**

```sql
SELECT * FROM t WHERE id > ? ORDER BY id LIMIT ?;
-- 每批最大 id 续作下界；结果集空 = 终止（删除致批 ≤ k）
```

**排序键为二级索引：覆盖索引两查询拆分（第一查询只扫索引，第二只 k 行回表）：**

```sql
-- ① 覆盖索引只取 id，不回表（仍带大 OFFSET，但只扫索引列）
SELECT id FROM t ORDER BY secondary_key, id LIMIT 1000000, ?;

-- ② IN 主键回查全字段，仅 k 行回表；k 很大时 IN 列表受限需分批
SELECT * FROM t WHERE id IN (?, ?, ?) ORDER BY FIELD(id, ?, ?, ?);
```

**二级索引场景叠加复合游标，进一步消去第二查询 OFFSET，转纯顺序扫：**

```sql
-- 上一页末 (secondary_key, id) 复合游标
SELECT id FROM t
WHERE (secondary_key, id) > (?, ?)
ORDER BY secondary_key, id
LIMIT ?;
```
