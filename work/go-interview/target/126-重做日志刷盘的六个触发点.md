# 126 重做日志刷盘的六个触发点

> 分类：MySQL / InnoDB | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**log buffer、检查点、后台线程、刷盘时机**

> 原文锚点：第 56~66 段「事务提交时…日志缓冲空间不足…检查点…后台线程…服务关闭」

## 一句话总述
重做日志落盘**不止事务提交一条路径**：日志缓冲占用过半、日志缓冲写满、检查点、后台周期线程、服务关闭，都会触发刷盘。

## 面试官视角
P6 只知道"提交时刷"；P7 要一次报出**六个触发点**并点明关键：提交时**是否立即刷**还受刷盘参数控制，参数不是 1 就不会立刻落盘 `[经验]`。加分点：检查点与后台线程会把脏页和相关日志**一同**刷盘，这就是"数据页刷新与日志刷新互相独立但常相伴"的原因 `[源码]`。

## 主问答
**Q（面试官原话）：** 重做日志什么时候会写到磁盘？

1. **事务提交时**：但前提是刷盘参数为 1 才会立即落盘，否则只是写进缓冲或系统等下一轮 `[源码]`。
2. **日志缓冲占用过半**：当缓冲中的日志量达到总容量约一半，就会触发刷盘 `[经验]`。
3. **日志缓冲写满**：暂存的日志把缓冲占满时直接触发写入磁盘 `[源码]`。
4. **检查点与后台线程**：检查点把脏页刷回磁盘并连带刷新相应日志；后台线程每秒周期性做同样的事 `[经验]`。
5. **服务关闭时**：正常关闭流程会把日志刷入磁盘，确保异常关闭场景也有保障 `[源码]`。

## 追问链
| 层级 | 追问 | 答不出停在哪档 |
|---|---|---|
| L1 | 只有提交才刷盘吗？ | 答不是，还有多条路径 |
| L2 | 缓冲占用多少会触发？ | 答不出约一半 |
| L3 | 检查点做什么？ | 说不出刷脏页并带日志 |
| L4 | 后台线程多久一次？ | 答不出每秒级别 |
| L5 | 关闭时会刷吗？ | 答会 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| MySQL 5.6 / 5.7 | 触发点一致 | 缓冲默认 16MB |
| MySQL 8.0 | 机制未变 | 可用 SET PERSIST 调整缓冲大小 |
| 任意版本 | 受刷盘参数调制 | 提交路径是否立即刷取决于该参数 |

## 关键代码
```sql
SHOW VARIABLES LIKE 'innodb_log_buffer_size';   -- 日志缓冲大小
SHOW VARIABLES LIKE 'innodb_flush_log_at_trx_commit';
SHOW ENGINE INNODB STATUS\G                     -- LOG 段看日志序列号与检查点
```
> 验证：批量插入大事务时，未提交也能看到日志序列号前进，即缓冲过半触发的刷盘 `[实测]`。

## 总结与追问预判
**提交只是六条路径之一**，把它当成唯一路径就会在"未提交事务的日志为何已落盘"这类追问上卡壳。
