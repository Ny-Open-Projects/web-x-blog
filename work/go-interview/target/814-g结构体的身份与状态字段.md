# 814 g 结构体的身份与状态字段

> 分类：并发模型 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**goid** / **atomicstatus** / **sched**
> 原文锚点：第 112~117 段「每个 g 都有自己的唯一 ID…保存当前 g 的上下文信息」

## 一句话总述
g 是 goroutine 在运行时的内部表示：goid 给身份、atomicstatus 给 16 种状态、sched(gobuf) 存寄存器现场。

## 面试官视角
- 考察意图：是否真翻过 `src/runtime/runtime2.go` 的 g 结构体 `[源码]`
- P5 能说清 g 是什么 / P6 能列 goid+status+sched 三件套 / P7 能讲状态机与抢占三字段
- 红旗：把 g 说成"用户态线程对象"；答不出为何每个 g 有 3 个抢占字段
- 惊艳点：g 数量可上百万，但单个 g 结构体仅数百字节 `[源码] runtime2.go`

## 主问答
**Q：** g 结构体里"身份 + 状态 + 上下文"的核心字段是哪些？
**A：**
1. **goid**：每个 g 的唯一标识，`uint64` `[源码]`。
2. **atomicstatus**：当前状态，共 16 种（_Grunnable 等），原子读写 `[源码]`。
3. **sched(gobuf)**：保存 SP/PC 等寄存器，做上下文切换 `[源码]`。
**加分层：** 另有 preempt/preemptStop/preemptShrink 三个抢占相关字段 `[源码]`。

## 关键代码
```go
// 示意，未验证：g 的身份与状态相关字段（节选）
type g struct {
    goid         uint64        // 唯一标识

```

## ⚠️ 原文纠错
原文第 116 段「如果没有绑定呢，它的字段值是六」中"六"为机翻误识，正确应为"零"（0），指 `g.lockedm` 未绑定时为 0 `[源码]`。其余技术描述未发现错误。

## 总结与追问预判
- g 用 goid 标识、atomicstatus 表征状态、sched 存现场；百万级 g 靠 P 本地队列承载。
- 下一题常接「g 的调度上下文与 sudog/waiting 如何配合」（见 814）。
