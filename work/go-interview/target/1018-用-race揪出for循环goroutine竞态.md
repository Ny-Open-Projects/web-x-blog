# 1018 用 -race 揪出 for 循环 goroutine 竞态

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：中 | 关键词：**-race** / **数据竞争** / **未定义行为** / **go test**
> 原文锚点：第 42~60 段「for 循环内 goroutine 读主循环正在修改的变量/字段，结果取决于调度时机」

## 一句话总述
for 循环里 goroutine 读共享/循环变量，绝大多数情况是**数据竞争**（未定义行为）。别靠"多跑几次看着对"判断，用 `go run -race` / `go test -race` 在竞态发生时直接报冲突位置，再按 1018 系列修法根治。

## 面试官视角
- 意图：考察候选人是否有"竞态要靠工具验证、不能靠肉眼/运气"的工程素养。
- P5 知道 -race 能检测；P6 能说清数据竞争是 UB、不加锁的"偶尔正确"不可信；P7 能讲 -race 的原理（影子内存/happens-before）与开销。
- 红旗：以为"我跑过好几次都对就没问题"；以为竞态一定会 panic。
- 惊艳点：指出 -race 有运行时开销（约 2~10x 内存/时间），只在测试与 CI 开，不在生产常驻。

## 主问答
**Q（面试官原话）：** 怎么确认 for 循环里的 goroutine 是不是有数据竞争？
**A：**
1. **结论**：用竞态检测器 `go run -race main.go` 或 `go test -race ./...`，它会报告每处"写-读无同步"的冲突调用栈；有冲突即存在数据竞争，必须修。
2. **机制**：-race 给每个内存访问维护影子状态、跟踪 happens-before，发现无同步的并发访问对就告警；直接定位到具体行，比肉眼分析调度可靠 `[源码]`。
3. **边界**：数据竞争是**未定义行为**——不报 panic、不崩溃都可能，运行期偶发错乱最难查；所以"看着对"不等于"对"，靠 -race 证明无竞争才算过关 `[经验]`。

## 关键代码
```go
// 示意，未验证：用 -race 跑测试，捕获 for 循环 goroutine 竞争
// go test -race ./...
func TestLoopGoroutine(t *testing.T) {
    var mu sync.Mutex
    var x int
    for i := 0; i < 10; i++ {
        go func() {
            mu.Lock(); x++; mu.Unlock() // 无锁版本会被 -race 报 WARNING: DATA RACE
        }()
    }
    time.Sleep(time.Millisecond)
}
```
