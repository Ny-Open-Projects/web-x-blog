# 1225 唯一索引冲突与显式指定 ID 造成断层

> 分类：MySQL 内核 | 难度：L3 | 题型：八股题 | 频率：中 | 关键词：**唯一索引**/**自增断层**/**显式 ID**
> 原文锚点：第 23~30、49~54 段「唯一索引冲突…指定主键值留洞」

## 一句话总述
唯一索引冲突与显式指定主键值都会留下自增洞：前者先分配自增值再做唯一性校验、校验失败不回退；后者让后续插入从"历史最大 ID"起跳，跳过中间的显式值。

## 面试官视角
- 考察意图：是否理解"先分配后校验"的顺序与显式 ID 对自增序列的影响。
- 分档：P5 知唯一冲突会留洞；P6 懂"先自增后校验"；P7 能区分唯一冲突 vs 主键冲突的不同结果。
- 红旗答案：以为唯一索引冲突会回退自增值；以为显式指定 ID 会"填补"已有洞。
- 惊艳点：**唯一索引冲突与主键冲突结果相反**——唯一冲突留洞（已分配不回退），主键冲突（显式值撞已占用）**不留洞**（语句在分配前就失败）`[经验]`。

## 主问答
**Q（面试官原话）：** 唯一索引冲突为什么会导致自增 ID 不连续？
**A：**
1. **结论**：插入时先维护当前自增值（分配新 ID），再做唯一性校验；校验失败仅回滚数据行，自增值不回退，于是留下洞。
2. **机制**：自增分配发生在存储引擎层、唯一校验在其后；为支持高并发，MySQL 不愿为回退去加锁查最大值，故选择"宁可留洞也不回收" `[经验]`。
3. **边界**：显式指定 ID（如 INSERT ... ID=11）若撞已占用值会直接报错且**不留洞**（因为没走自增分配）；但若指定的 ID 落在洞里（如 ID=7 之前被删）则能成功插入，不补齐序列。

**加分层：** 主键索引本质是特殊唯一索引，但"显式值冲突"路径与"自增分配冲突"路径不同，结果也不同——这是易混点。

## 关键代码
```sql
-- 唯一索引冲突留洞演示
CREATE TABLE t(id INT AUTO_INCREMENT PRIMARY KEY, u VARCHAR(10), UNIQUE KEY(u));
INSERT INTO t(u) VALUES('a'),('a');  -- 第二条报 1062，但自增已 +1，下条 id 跳号
```

## 总结与追问预判
唯一冲突=先分后验留洞；主键显式冲突=分配前失败不留洞。追问接"offset/increment 怎么制造规律断层"。

## ⚠️ 原文纠错
1. 原文对唯一索引冲突"先自增后校验不回退"与显式 ID 留洞的论述正确，仅术语崩坏：事物→**事务**、circle→**SQL**、内me→**name**（字段名 ASR 崩坏）。本卡已归一为规范术语与字段名 `[经验]`。
2. 原文第 41 段称"主键冲突不会导致断层"——准确（显式值撞占用在分配前失败），本卡沿用并补充了"唯一冲突 vs 主键冲突结果相反"的对比，属厘清而非纠错。
