# 809 写屏障场景推演：栈/堆对象的不同处理

> 分类：Go/运行时 | 难度：L3 | 题型：推演题 | 频率：高 | 关键词：**栈黑不触发** / **堆灰删白→删除屏障** / **堆黑增白→插入屏障** / **防漏标防错删**
> 原文锚点：第 12~50 段「栈黑对象改/删引用不触发屏障；堆灰色对象删白对象→删除屏障标灰；堆黑色对象增白对象→插入屏障标灰；最终白对象回收」

## 一句话总述
混合写屏障下，栈与堆对象待遇不同：**栈对象已黑，改/删引用不触发任何屏障**（靠"黑"保证安全）；**堆灰色对象删除对白色对象的引用**→触发**删除屏障**，白色对象标灰以保留其下游引用路径、防被误删；**堆黑色对象新增对白色对象的引用**→触发**插入屏障**，白色对象标灰以防漏标。两类屏障从不同方向堵住"黑引白"的漏标/错删。

## 面试官视角
- 意图：考察"能否在真实对象图改动上判断屏障何时触发、触发后做什么"，是原理的落地题。
- P5 知道有插入/删除屏障；P6 能按"栈黑不触发、堆删=删除屏障、堆增=插入屏障"正确推演；P7 能讲清"删除屏障保的是被删对象的下游、插入屏障保的是新引用对象"的语义差异。
- 红旗：以为栈对象改引用也触发屏障；分不清删除/插入屏障各自保护谁。
- 惊艳点：点出"删除屏障保留引用路径、插入屏障保护新生对象，二者合力满足强/弱三色不变式"。

## 主问答
**Q：** 并发标记中，对象图发生改动时屏障怎么动作？
**A：**
1. **栈对象（已黑）**：栈上对象在 GC 启动已全标黑，运行期改/删引用**不触发屏障**——因为黑色对象本身已确定存活，其下游即便临时变白也会在别处被保护，无需额外动作。
2. **堆灰删白**：灰色对象解除对白色对象的引用 → 触发**删除屏障**，把被删的白色对象**标灰**，保留它的引用路径，等下一轮 GC 再决定能否回收（防"错删"其下游）。
3. **堆黑增白**：黑色对象新增对白色对象的引用 → 触发**插入屏障**，把新引用的白色对象**标灰**，防止黑色直接引用白色导致漏标（满足强三色不变式）。

## 关键代码
```go
// 屏障触发的判定（语义示意）：栈对象不经过；堆指针写才进 heapWrite
func heapWrite(slot *unsafe.Pointer, newobj unsafe.Pointer) {
    if *slot != nil {
        shade(*slot)   // 堆"灰删白/黑删白"：删除侧，被覆盖旧值标灰
    }
    if newobj != nil {
        shade(newobj)  // 堆"黑增白/灰增白"：插入侧，新值标灰
    }
    *slot = newobj
}
// 栈对象：GC 启动已黑，改/删引用不调用本函数——这是"栈不触发屏障"的由来
```

## 总结与追问预判
- 栈黑不触发；堆删→删除屏障保下游；堆增→插入屏障保新生；合力防漏标防错删。
- 预判：规则①栈免重扫见 809-hybrid-barrier-stack-norescan；强弱不变式见 808-strong-weak-invariant；混合屏障动机见 808-hybrid-barrier（本卡只做场景推演，不重复原理）。
