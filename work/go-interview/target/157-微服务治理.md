# 157 微服务治理：容错策略总览与三层面串联

> 分类：微服务/治理 | 难度：L2 | 题型：概念题 | 频率：中 | 关键词：**服务容错**/**失败通知**/**失败自动切换**/**快速失败**/**失败缓存**/**熔断**/**限流**/**降级**/**非幂等不重试**
> 原文锚点：第 36~54 段「服务容错7策略 + 非幂等不无脑重试 + 框架默认集成」

## 一句话总述
治理第三层面是**服务容错**（保稳定可用）：七策略——失败通知/失败自动切换/快速失败/失败缓存/熔断/限流/降级；核心纪律是**非幂等操作不能无脑重试**，且这些手段通常由框架默认集成。

## 面试官视角
- 考察意图：能否系统列出容错策略并说清重试红线；是否知道治理三层面关系。
- 分档：P5 知有重试/熔断/降级；P6 能列七策略并说清非幂等不重试；P7 知框架默认集成、业务无需自实现。
- 红旗答案：对非幂等操作（如扣款）无脑重试；把容错与节点管理/负载均衡割裂讲。
- 惊艳点：点出「重试仅幂等安全，非幂等服务端可在响应头放可重试标识、客户端据标识判断」，以及「治理三手段框架默认集成」 [经验]。

## 主问答
**Q（面试官原话）：** 服务容错有哪些策略？注意什么？
**A：**
1. **七策略清单**：①失败通知（失败/超时后不重试、据详情定后续）；②失败自动切换（选下一可用节点重调）；③快速失败（立即返回不等待超时，省资源）；④失败缓存（缓存故障实例、定期更新，免再发请求）；⑤熔断（连续失败达阈值暂断、恢复试探）；⑥限流（控请求防过载崩溃）；⑦降级（关非核心功能保核心）[经验]。
2. **非幂等不能无脑重试**：重试仅适用于**幂等**操作；非幂等（如扣款）重试会重复生效。服务端可在响应头放「可重试」标识，客户端据此判断 [经验]。
3. **框架默认集成**：节点管理/负载均衡/容错通常由服务框架（开源 RPC 框架）默认集成，业务代码无需自实现；自实现可参考开源框架 [经验]。

## 关键代码

```go
// 失败自动切换：依次尝试可用节点直到成功（容错策略之一）
func callWithFailover(addrs []string, req Req) (Resp, error) {
    var lastErr error
    for _, a := range addrs { // 自动切换到下一个可用节点
        if r, err := Call(a, req); err == nil {
            return r, nil
        } else {
            lastErr = err
        }
    }
    return Resp{}, lastErr // 全失败
}
// 注：对非幂等请求（扣款等）勿在 failover 中无脑重试，需业务层幂等保护
```
