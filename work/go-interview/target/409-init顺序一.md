# 409 init 顺序（一）：同文件与同包内多文件

> 分类：Go 基础 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**按定义顺序**/**文件名字典序**/**ASCII**/**同包多文件**/**不可依赖该顺序**

> 原文锚点：第 10~11 段「顺序规则总述」、第 17~33 段「同文件与同包内多文件验证」

## 一句话总述
**同一个 .go 文件内**定义多个 init，按**代码编写顺序**依次执行；**同一个 package 下不同文件**中的 init，按**文件名的字典序**依次执行——例如 `a.go` 的 init 先于 `b.go` 的 init。

## 面试官视角
这题是「细节掌握度」的试金石。多数人只能答出同文件顺序，答不出同包多文件的规则。能说出「由编译器收到的文件顺序决定，而 go 工具链按字典序排」，并提醒**不要依赖这个顺序写耦合逻辑**，就是满分。

## 主问答
**Q（面试官原话）：** 同一个包里有很多 init，执行顺序是什么？

1. **同文件多 init**：同一个 go 文件里可以重复定义多个 init 方法，执行顺序就是**代码编写的顺序**，先定义的先执行。
2. **与普通函数不同**：自定义普通函数不能重名，而 init 是例外，这是它能多个共存的前提。
3. **同包不同文件**：同一个 package 下不同文件中的 init，按照**文件名的顺序**先后执行。
4. **判定依据**：文件名按字典序比较，本质是字符编码比较，因此 `a.go` 排在 `b.go` 之前。
5. **验证结果**：包内有 a.go、b.go、pkg.go 时，输出顺序为 a → b → pkg，与文件名序一致。

## 追问链

## 版本与兼容性
| 范围 | 顺序规则 |
|------|----------|
| 同一文件 | 按定义先后 |
| 同包不同文件 | 按文件名字典序 |
| 不同包 | 见跨包规则卡 |

## 关键代码
```go
// a.go —— 文件名靠前，其 init 先执行
package pkg

import "fmt"

func init() { fmt.Println("pkg-a") }
```

```go
// b.go —— 文件名靠后，其 init 后执行
package pkg

import "fmt"

func init() { fmt.Println("pkg-b") }
```

## 总结与追问预判
核心：**同文件按定义序，同包按文件名序**。追问常拐向「这个顺序能依赖吗」，备好「不要写有先后依赖的初始化逻辑，需要顺序就放在同一个 init 里显式调用」这句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称同包不同文件「按照文件名的顺序」「按 ASCII 码比较」——结论正确；更严谨的说法是：实际顺序由**构建时传给编译器的文件顺序**决定，而 go 工具链按文件名字典序排序，因此在正常构建下等价于字典序。
2. 事实核校： [经验] 原文未提醒风险——跨文件 init 存在隐式先后顺序，**不应编写依赖该顺序的初始化逻辑**；确实需要先后时，应在单个 init 内显式按序调用，避免换个构建方式就崩。
3. 崩坏词归一：源码将 init / 包 / go 文件 / ASCII 等音译为多组崩坏词，本卡统一为规范术语。
