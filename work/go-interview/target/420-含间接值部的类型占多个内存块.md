# 420 含间接值部的类型（占多个内存块）

> 分类：Go 语言基础 · 内存布局 | 难度：L2 | 题型：分类题 | 频率：中 | 关键词：**间接值部**/**slice/map/chan/func/interface/string**/**底层数组**/**hmap/hchan**
> 原文锚点：第 52~58 段「含间接值部的类型：切片/映射/通道/函数/接口/字符串；切片直接值部=头(ptr,len,cap)，指针指向底层数组即间接值部」

## 一句话总述
"占多个内存块"的类型就是**含间接值部的类型**：**切片、映射(map)、通道(chan)、函数、接口、字符串**。它们的"直接值部"只是个**header（含一个指向真正数据的指针）**，真正的元素数据存在**另一个内存块**（间接值部），被直接值部引用。

## 面试官视角
- 考察意图：能否逐一说清这 6 类类型"header 里指针对应哪块数据"，而不只是笼统说"它们有指针"。
- 分档：P5 知这 6 类占多块；P6 能说清 slice 指向底层数组；P7 能逐一拆解 map/chan/string/interface/func 各自的间接值部。
- 红旗：把这 6 类说成"引用类型"（Go 无引用类型，只有值传递 + header 含指针）；或说不清 interface 的 itab+data 两段。
- 惊艳点：点出"string 也占两块——header(指针+长度) 指向只读字节数组"，打破"string 是单块"的错觉。

## 主问答
**Q（面试官原话）：** 哪些 Go 类型会分布在多个内存块上？各自的"另一块"是什么？
**A：**
1. **切片 slice**：直接值部 = (ptr, len, cap) 头；间接值部 = ptr 指向的**底层数组**。复制切片只拷头，双方共享底层数组。
2. **映射 map**：直接值部 = 一个指向 `hmap` 的指针（1 机器字）；间接值部 = 堆上的 `hmap` 结构及桶数组。
3. **通道 chan**：直接值部 = 指向 `hchan` 的指针；间接值部 = 堆上的 `hchan`（环形队列 + 等待队列）。
4. **函数 func**：直接值部 = 指向函数代码/闭包环境的指针；间接值部 = 闭包捕获的变量（逃逸到堆）。
5. **接口 interface**：直接值部 = (itab, data) 两段（itab 含类型信息，data 是指针）；间接值部 = data 指向的堆上动态值。
6. **字符串 string**：直接值部 = (ptr, len) 头；间接值部 = ptr 指向的**只读字节数组**（不可修改）`[经验]`。

## 关键代码
```go
// 切片：header 单块，底层数组另块（共享）
s1 := []int{1, 2, 3}
s2 := s1          // 只拷 header；s1、s2 共享同一底层数组
s2[0] = 9         // s1[0] 也变成 9 —— 间接值部被共享

// 字符串：header + 只读字节数组（两块）
str := "hello"    // str 的 ptr 指向只读区字节数组，不可修改
```

## 总结与追问预判
含间接值部的 6 类类型，本质是"值 = header + 指针"，复制只拷 header、数据共享底层。这与 420-single-block-types（单块类型）对立互补；传参表现差异的统一解释见 923。
