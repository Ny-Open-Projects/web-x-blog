# 707 校验失败处理：ShouldBindJSON 与 ValidationErrors

> 分类：Web框架 | 难度：L2 | 题型：工程题 | 频率：中 | 关键词：**ShouldBindJSON** / **ValidationErrors** / **Field-Tag定位**
> 原文锚点：第 57~70 段「sude的森传进来是杰省参数…打印切割field响应错误…GT一标签校验不通过」

## 一句话总述
`ShouldBindJSON` 返回 error；校验失败时 error 可断言为 `validator.ValidationErrors`，逐条取出失败字段名（`Field()`）与未通过的规则标签（`Tag()`），据此返回精确错误。

## 面试官视角
- **考察意图**：是否会优雅处理校验错误、给出可读提示而非整段 dump。
- **P5**：知道 err != nil 就返回 400。**P6**：能断言 ValidationErrors 取 Field/Tag。**P7**：知道区分「校验失败」与「JSON 解析失败」两类 error、知道翻译器做中文提示。
- **红旗答案**：把 raw err 直接全量返回给前端；分不清解析错误与校验错误。
- **惊艳点**：`err.(validator.ValidationErrors)` 后 `e.Field()` 是结构体字段名、`e.Tag()` 是失败规则（如 `gte`）——错误提示可精确到字段+规则 [源码]

## 主问答
**Q（面试官原话）：** 校验没过，你怎么把哪个字段错了告诉调用方？
**A：**
1. **结论**：把 error 断言成 `validator.ValidationErrors`，遍历取 Field/Tag。
2. **机制**：`ShouldBindJSON` 在 JSON 合法但规则不满足时填充 ValidationErrors；每条含字段名与规则名。
3. **边界**：JSON 本身解析失败不是 ValidationErrors，需先判类型再分别处理。
**加分层：** 生产常用 `en/zh_translator` + `RegisterTranslation` 把 `gte` 翻成中文提示。

## 关键代码
```go
if err := c.ShouldBindJSON(&u); err != nil {
    if verrs, ok := err.(validator.ValidationErrors); ok {
        for _, e := range verrs {
            log.Printf("字段 %s 规则 %s 未通过", e.Field(), e.Tag()) // User.Age / gte
        }
    }
    c.JSON(400, gin.H{"error": err.Error()})
    return
}
```
