# 1506 微服务安全：传输、密钥与脱敏

> 分类：架构设计 / 微服务 | 难度：L3 | 题型：实战题 | 频率：中 | 关键词：**mTLS** / **API网关** / **配置中心** / **密钥不落盘** / **日志脱敏**
> 原文锚点：第 24~28 段「服务间通信安全…加密传输/API网关/权限控制…禁硬编码密钥…配置中心…日志脱敏」

## 一句话总述
微服务安全 = 传输加密 + 网关鉴权 + 密钥不落盘（启动时从配置中心注入内存）+ 日志脱敏；多服务暴露面广，任一处硬编码密钥或明文日志都是突破口。

## 面试官视角
- 意图：是否意识到微服务把"单体内部调用"变成"跨网络多跳"，暴露面与密钥管理难度陡增。
- P5 知传输加密/网关；P6 说清密钥不硬编码、配置中心注入；P7 知 mTLS、最小权限与脱敏合规。
- 红旗：以为内部服务不用加密；把密钥写进代码或配置文件提交仓库。
- 惊艳点：敏感配置"禁硬编码、禁落盘"，运行时从配置中心读入内存，且密钥与隐私禁止进日志——这是合规红线 `[经验]`。

## 主问答
**Q（面试官原话）：** 微服务架构下安全性要注意什么？
**A：**
1. **通信安全**：服务间加密传输（如 mTLS），统一经 API 网关做鉴权与权限控制，避免裸奔调用 `[源码]`。
2. **密钥不落盘**：敏感配置禁硬编码进代码、禁写入配置文件落盘，应用启动时从配置中心拉取并只在内存中使用。
3. **日志脱敏**：密钥与用户隐私数据禁止记录进日志文件，需做脱敏处理，避免二次泄露。
4. **最小权限**：服务按需授权、彼此隔离，避免横向越权；网关侧统一收敛入口。

```go
// 示意，未验证：密钥从环境变量/配置中心注入，不硬编码；日志对敏感字段脱敏
package main
import ("log"; "os"; "strings")
func loadSecret() string {
    // 运行时从配置中心/环境变量读取，而非写死在代码
    return os.Getenv("DB_TOKEN") // 不在源码中出现明文
}
func desensitize(id string) string {
    if len(id) <= 4 { return "***" }
    return strings.Repeat("*", len(id)-4) + id[len(id)-4:] // 138****1234
}
func main() {
    _ = loadSecret()
    log.Println("user=", desensitize("13800001234")) // 脱敏后输出
}
```
