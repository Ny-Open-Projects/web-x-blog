# 711 任务队列与 worker 消费

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：中 | 关键词：**任务信道** / **worker 模型** / **缓冲队列**
> 原文锚点：第 9~12 段「work 是 function 类型的 channel，作任务队列」

## 一句话总述
用一个 `chan func()` 当任务队列：submit 往里塞函数，预启动的若干 worker goroutine 持续读出并执行，实现生产-消费模型。

## 面试官视角
- 意图：是否理解"任务队列 + 固定 worker"这个池的核心骨架。
- 分档：P5 知有队列 / P6 说清产销配对 / P7 知缓冲大小即积压上限。
- 红旗：worker 数=任务数（失去池意义）；队列无缓冲致提交阻塞。
- 惊艳点：worker 只读一个 `chan func()` 即可复用，与并发度 channel 解耦 `[源码]` 标准库。

## 主问答
**Q（面试官原话）：** 协程池里任务怎么存、谁来执行？
**A：**
1. **结论**：任务队列是一个 `chan func()`，提交即入队，worker 循环 `<-queue` 取出执行。
2. **机制**：队列带缓冲，满了再提交就阻塞，天然限制积压；预启动 N 个 worker 各自 `for task := range queue` 消费。
3. **边界**：worker 数决定并行消费能力，与并发度信号量是两件事；worker 太多等于无池。
**加分层：** 队列缓冲大小 = 最大积压，过大会吃内存，过小会背压阻塞提交方。

## 关键代码
```go
// 示意，未验证：worker 循环消费任务队列
queue := make(chan func(), 5)
for w := 0; w < 4; w++ {
    go func() {
        for task := range queue {
            task()
        }
    }()
}
queue <- func() { println("do") }
```

## 总结与追问预判
- 任务队列 = chan func，worker 循环消费，缓冲即积压上限。
