# 811 虚拟内存与页表：为何需要及地址映射

> 分类：内存与 GC | 难度：L3 | 题型：八股题 | 频率：中 | 关键词：**虚拟地址** / **页表 PTE** / **4KB 页**
> 原文锚点：第 31~63 段「为什么使用虚拟内存…虚拟地址映射到物理地址…每页默认四KB…PTE」

## 一句话总述
虚拟内存给每个进程一套独立地址空间，由页表（PTE）把虚拟地址映射到物理地址；物理内存当缓存、磁盘当后备，既提利用率又隔离进程。

## 面试官视角
- 意图：是否真懂「为什么不直接用物理内存」以及映射机制。
- P5 知虚拟地址隔离 / P6 说清页表+PTE+4KB 页 / P7 知大页、64 位布局差异。
- 红旗：以为虚拟地址就是物理地址；以为每页大小固定不可配。
- 惊艳点：4KB 是折中值，过小置换频繁、过大浪费 —— 验证 `getconf PAGESIZE` `[经验]`。

## 主问答
**Q（面试官原话）：** 为什么需要虚拟内存？页表起什么作用？
**A：**
1. **结论**：虚拟内存隔离进程、提物理内存利用率，页表维护虚拟→物理的映射 `[源码]`。
2. **机制**：程序只用虚拟地址，MMU 查页表得物理地址；内存按 4KB 分页管理，PTE 含有效位与物理地址。
3. **边界**：页大小可配置（非永远 4KB），大页减少 TLB 压力；32 位与 64 位地址空间布局差异巨大。
**加分层：** 过度映射会触发 swap 与颠簸，性能服务常禁 swap。

## ⚠️ 原文纠错
原文第 102 段描述的「0~4G 虚拟地址、内核占最高 1G、用户占低 3G」是 32 位 x86 Linux 的 3:1 拆分，且原文十六进制边界被机翻崩坏（如「零SC零零零零」应为 0xC0000000）。该描述对 32 位成立，但现代 64 位（Go 主流部署）使用 48/57 位地址空间、用户与内核各占一半并经符号扩展规范地址，布局完全不同。回答时应说明原理并点明 32/64 位差异，避免把 3G/1G 当成普适结论。机翻解码：勾浪→Go、列表→页表、缺液→缺页。
