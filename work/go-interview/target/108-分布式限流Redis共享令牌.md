# 108 分布式限流（Redis 共享令牌）

> 分类：Go 并发 / 分布式 | 难度：中高 | 题型：设计题 | 频率：中 | 关键词：**分布式限流、Redis 令牌、副本流量不均、Lua 原子**

> 原文锚点：第 59~67 段「本地限流不精准（副本流量不均）；令牌放 Redis 跨副本共享」

## 一句话总述
本地限流器只对本副本生效，多副本部署且流量不均时整体限速会偏差；把令牌放到 **Redis** 等共享存储，让所有副本争用同一令牌源，才能实现全局精准限流。一句话背法：**「单机限流各副本独立、流量不均失真；令牌外置 Redis 跨副本共享才全局精准」**。

## 面试官视角
考官考察从单机限流上升到分布式一致性的思维。能讲清副本流量不均导致偏差、设计 Redis 共享令牌 + Lua 原子扣减、并考虑 Redis 可用性与降级，说明成熟；以为每副本各限 5 QPS = 全局 5 QPS、忽略 Redis 原子性与可用性，是红旗。
- **P5**：知道本地限流。
- **P6**：知道副本流量不均导致偏差。
- **P7**：能设计 Redis 共享令牌 + Lua 原子扣减。

## 主问答
**Q（面试官原话）：** 服务多副本部署，本地限流够吗？

**先铺垫（由浅入深第 1 层）**：单机限流假设的"一个进程"在微服务里不存在——同一服务往往起 N 个副本分担流量。每个副本各限 5 QPS，听起来全局 5，实则每个副本独立计数，流量一旦不均，全局就跑偏了。要"全局精准"，令牌必须有个所有副本都认的"总账本"。

1. **问题（第 2 层）**：本地限流器独立计数，副本流量不均时全局限速失真。例：限每副本 5 QPS，A 收 3、B 收 30，全局实际最多 8 QPS，而非 10。
2. **解法（第 3 层）**：令牌存 Redis，所有副本从同一令牌源获取；用 `INCR`/`DECR` + `EXPIRE` 或 **Lua 脚本**原子地"取令牌+续期"，保证跨副本互斥。
3. **代价（第 4 层）**：引入 Redis 依赖，需考虑 Redis 可用性（降级策略）与原子性（Lua 保证"判断+扣减"不被并发打断）。
4. **加分层（第 5 层）**：Lua 是必须的——"读当前令牌→判断够不够→扣减"三步若不用 Lua 原子执行，并发下会超发。
5. **误用风险（第 6 层）**：Redis 挂了要有降级（如退化为本地限流或放行）；Lua 脚本要保证"判断+扣减"整体原子，否则多副本并发会超发令牌。

## 关键代码
```go
package main

// Redis + Lua 原子取令牌：保证"判断+扣减"不被并发打断
const takeTokenScript = `
local key = KEYS[1]
local now = tonumber(ARGV[1])
local rate = tonumber(ARGV[2])   -- 每秒补充
local cap  = tonumber(ARGV[3])   -- 桶容量
local cur = tonumber(redis.call('GET', key) or cap)
if cur <= 0 then return 0 end     -- 无令牌，拒绝
redis.call('SET', key, cur - 1, 'EX', 1)
return 1                          -- 取到令牌
`
```

## 总结与追问预判
**背这三句就够**：① **本地限流各副本独立、流量不均→全局失真（例：各限5，实际最多8非10）**；② **令牌外置 Redis、所有副本争用同一源才全局精准**；③ **用 Lua 脚本原子"判断+扣减"防超发，Redis 挂要有降级**。
