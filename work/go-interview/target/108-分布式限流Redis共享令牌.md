# 108 分布式限流（Redis 共享令牌）

> 分类：Go 并发 / 分布式 | 难度：L3 | 题型：设计题 | 频率：中 | 关键词：**分布式限流** / **Redis 令牌** / **副本流量不均** / **Lua 原子**
> 原文锚点：第 59~67 段「本地限流不精准（副本流量不均）；令牌放 Redis 跨副本共享」

## 一句话总述
本地限流器只对本副本生效，多副本部署且流量不均时整体限速会偏差；把令牌放到 **Redis** 等共享存储，让所有副本争用同一令牌源，才能实现全局精准限流。

## 面试官视角
- 意图：考察从单机限流上升到分布式一致性的思维。
- 分档：P5 知本地限流；P6 知副本流量不均导致偏差；P7 能设计 Redis 共享令牌 + Lua 原子扣减。
- 红旗：以为每副本各限 5 QPS = 全局 5 QPS；忽略 Redis 可用性与原子性。
- 惊艳点：用实例点破——每副本限 5，副本 A 流量 3、副本 B 流量 30，全局实际最多 8 而非 10。

## 主问答
**Q（面试官原话）：** 服务多副本部署，本地限流够吗？
**A：**
1. **问题**：本地限流器独立计数，副本流量不均时全局限速失真。例：限每副本 5 QPS，A 收 3、B 收 30，全局实际最多 8 QPS，而非 10。
2. **解法**：令牌存 Redis，所有副本从同一令牌源获取；用 `INCR`/`DECR` + `EXPIRE` 或 Lua 脚本原子地"取令牌+续期"，保证跨副本互斥。
3. **代价**：引入 Redis 依赖，需考虑 Redis 可用性（降级策略）与原子性（Lua 保证"判断+扣减"不被并发打断）。
