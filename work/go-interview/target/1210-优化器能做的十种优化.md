# 1210 优化器能做的十种优化：从关联顺序到 IN 二分

> 分类：数据库 / MySQL 优化器 | 难度：L4 | 题型：记忆题 | 频率：高 | 关键词：**关联顺序、外转内、条件简化、常量折叠、覆盖索引、子查询、提前终止、等值传播**

> 原文锚点：第 14~30 段「它可以重新定义关联表的顺序…它可以将外连接转化成内连接…它会简化查询条件…它会优化 COUNT/MIN/MAX 这些函数…它会优先使用覆盖索引扫描…它可以进行子查询的优化，一般会转成 EXISTS 查询或者转成连接查询…它可以提前终止查询…它可以进行等值传播…IN 列表里面的值会优先排序，然后通过二分查找的方式来判断是否满足条件」

## 一句话总述
MySQL 优化器能做的十类优化：**重排关联顺序、外连接转内连接、简化恒等条件、优化 COUNT/MIN/MAX、表达式常量折叠、优先覆盖索引、子查询转 EXISTS/JOIN、LIMIT 提前终止、等值传播、IN 列表排序后二分**。

## 面试官视角
P6 能说出两三条；P7 要**成体系地列出主要优化项**，并能解释等值传播与 IN 二分这类「看起来不起眼但很能体现深度」的项，同时知道哪些写法会**阻碍**优化（如恒等条件、无法估算的函数）。

## 主问答
**Q（面试官原话）：** MySQL 优化器到底会对 SQL 做哪些改写？

1. **重排关联顺序**：如 `a LEFT JOIN b LEFT JOIN c`，执行顺序**不一定**是 a→b→c，优化后可能变为 **c→b→a** `[源码]`。
2. **外连接转内连接**：并非所有外连接都以外连接方式执行；优化器判定可转换时**会改写成内连接** `[源码]`。
3. **简化查询条件**：如 `1=1 AND 字段 > 10`，优化器会**去掉恒等式**，只保留有效条件 `[源码]`。
4. **优化 COUNT/MIN/MAX**：**MIN 可查索引树最左端，MAX 可查最右端**；对 **MyISAM**，因直接存储了总条数，**COUNT 可直接取值**而无需计算 `[源码]`。
5. **表达式常量折叠**：检测到表达式可转为常量时，**一直按常量处理**（如自定义变量不发生变化时） `[源码]`。
6. **优先覆盖索引扫描**：当索引**已包含查询所需列**时，**无需回表**即可取到数据 `[源码]`。
7. **子查询优化**：子查询性能通常较差，一般**转成 EXISTS 查询或连接查询** `[源码]`。
8. **提前终止查询**：发现已满足条件即**立即停止**，如使用 **LIMIT** 取够指定条数后查询自动结束 `[源码]`。
9. **等值传播**：两列以等式关联时，其中一列的条件会**传播到另一列**；如 `a.age = b.age AND a.age > 10` 可推出 **`b.age > 10`** `[源码]`。
10. **IN 列表优先比较**：MySQL 会**先将 IN 列表中的值排序**，再通过**二分查找**判断是否满足条件 `[源码]`。

## 关键代码
```sql
-- 1) 重排关联顺序：实际顺序可能与书写顺序不同，用 EXPLAIN 观察
EXPLAIN SELECT * FROM a LEFT JOIN b ON a.id=b.id LEFT JOIN c ON b.id=c.id;

-- 2) 恒等条件会被去掉
SELECT * FROM t WHERE 1=1 AND age > 10;      -- 优化为 WHERE age > 10

-- 3) 等值传播：a.age>10 会传播到 b.age
SELECT * FROM a JOIN b ON a.age = b.age WHERE a.age > 10;

-- 4) MIN/MAX 走索引端点，无需全表扫描
SELECT MIN(id), MAX(id) FROM t;

-- 5) 覆盖索引：所需列都在索引里，Extra 出现 Using index
EXPLAIN SELECT name FROM userbig WHERE name > 'name10';

-- 6) LIMIT 触发提前终止
SELECT * FROM t WHERE status = 1 LIMIT 10;
```

## 总结与追问预判
**十项里最爱考的是「等值传播」与「外连接转内连接」**，因为很多人不知道优化器会改写自己写的 SQL。追问常是「COUNT(*) 在 InnoDB 上快吗」——**不快**，因为 InnoDB 因 MVCC 无法直接取总行数（原因见同批 1210-optimizer-limits）。

1. 事实核校：关联顺序重排、外转内、恒等条件简化、MIN/MAX 走索引端点、MyISAM 的 COUNT 可直接取、常量折叠、覆盖索引优先、子查询转 EXISTS/JOIN、LIMIT 提前终止、等值传播、IN 排序二分——均与 MySQL 优化器能力一致 `[经验]`。
