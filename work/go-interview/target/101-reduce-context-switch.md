# 101 减少上下文切换的四类方法

> 分类：并发基础 | 难度：L3 | 题型：方案题 | 频率：高 | 关键词：**减少锁**/**CAS**/**减少线程**/**协程**/**M:N模型**
> 原文锚点：第 40~62 段「减少上下文切换的优化方式」

## 一句话总述
降低上下文切换有四类手段：**避免/减少锁**（数据分段）、**CAS 自旋**（免锁阻塞）、**减少线程数**（任务粒度重排）、**协程**（用户态 M:N 调度，单线程内多任务切换，免内核切换）。

## 面试官视角
- 考察意图：能否从「减少切换」反推并发调优手段，是否覆盖锁/CAS/线程数/协程四个层次。
- 分档：P5 知减锁/减线程；P6 知 CAS 自旋；P7 知协程 M:N、用户态切换。
- 红旗答案：只答「用多线程」——与减少切换背道而驰。
- 惊艳点：点出「协程本质是把调度从内核搬到用户空间，一个线程当多个线程用」。

## 主问答
**Q（面试官原话）：** 有哪些方法可以减少上下文切换、提高执行效率？
**A：**
1. **避免/减少锁**：多线程竞争锁会触发切换；可用 ID 哈希取模分段（不同线程处理不同数据段）、整体更新 map 避免并发写、借鉴 `sync.Map` 的读写分离分散锁粒度，从源头规避竞争。
2. **CAS 算法**：Compare-And-Swap 是原子操作，比较内存值与预期值，相等才替换，否则自旋重试；免锁保护共享资源，避免锁开销与线程阻塞。
3. **减少线程数**：线程切换本身有开销，合理拆分/合并任务粒度，用更少线程完成相同工作，直接降低切换总次数。
4. **使用协程**：协程（Go 的 goroutine）采用 M:N 模型，一个线程可绑多个协程，在用户空间完成上下文切换，避免用户态↔内核态切换；单线程内维持多任务调度，等效「一线程当多线程用」。

## 关键代码
```go
// 数据分段：用 worker 各自负责一段，规避锁竞争（减少切换）
func partitionDemo(ids []int, workers int) {
	chunks := make([][]int, workers)
	for _, id := range ids {
		chunks[id%workers] = append(chunks[id%workers], id) // 哈希取模分段
	}
	var wg sync.WaitGroup
	for w := 0; w < workers; w++ {
		wg.Add(1)
		go func(c []int) { // 每 worker 独占一段，无锁竞争
			_ = c
			wg.Done()
		}(chunks[w])
	}
	wg.Wait()
}
```

## 总结与追问预判
四类手段从「规避竞争 → 免锁 → 减线程 → 用户态调度」层层递进。CAS 与 sync.Map 的内部机制在专项卡展开，协程 M:N 在 Go 调度卡展开。
