# 2004 去大公司还是小公司

> 分类：求职与录用 / 职业选择 | 难度：L3 | 题型：方法论 | 频率：中 | 关键词：**决策矩阵**/**分阶段权重**/**业务线三分类**/**小公司≠创业公司**/**不可替代性**
> 原文锚点：第 1~30 段「没大厂背景优先考虑大公司（简历背书/人才密度/业务规模/稳定性）……大公司业务线像不同的小公司（夕阳/蓬勃/探索）……是不是螺丝钉跟公司规模关系不大……小公司不等于创业公司，核心看程序员是否不可替代」
> 版本口径：**[2026 年·中国大陆]**。方法论与权重都可改；决策矩阵脚本为本机真跑 [实测]。本卡只讲「在大小公司之间怎么选、按什么依据选」；录用条件见 2001，岗位内容与单源孤证见 2002，谈薪见 2003，试用期见 2005。

## 一句话总述
选大还是选小，不是「哪个好」，而是「**在哪个职业阶段、你的价值排序是什么**」——用**能按阶段改权重的决策矩阵**，别背「应届必须去大厂」这类结论。动作顺序：定阶段（应届/1-3 年/3-5 年）→ 定权重（应届调高「简历背书+技术成长」、3-5 年调高「现金+自主权+业务前景」，**说得出为什么这么配才是依据**）→ 逐维度打 1-5 分算加权得分 → 对结论最敏感的 1-2 个维度**去交叉验证**（方法见 2002 单源孤证），而不是把表算得更精确。两个必须破的误解：①「小公司=多面手，大公司=螺丝钉」错——**是不是螺丝钉跟规模关系不大**，看岗位能接触多少、自由度与技术挑战；②「小公司=创业公司」错——软件作坊/外包/外派靠人脉拉项目变现，真创业公司靠产品/核心技术放大程序员产出，**判据只有一条：程序员是不是价值链上不可替代的一环**。

## 面试官视角
- 考察意图：这类问题通常是「你为什么选我们」的变体——面试官在评估你选工作是「随便投投」还是「想清楚了」。
- 分档：P5 能说出大/小公司各自的好处；P6 能讲「阶段→权重→结论」的链条；P7 能报出「权重变、结论翻」的实测对照，并讲出业务线三分类与真假创业公司判据。
- 红旗答案：把「去大厂」当人人适用的结论；用「公司大小」这个错误维度做决策；把「稳定」绝对化（大公司同样会加班、会裁撤业务线）。
- 惊艳点：报得出实测数字——同一组 offer 打分、只因权重随阶段变，结论**完整翻转**：应届 A=4.10/B=3.20（差 −0.90，偏大公司）→ 1-3 年 3.80/3.80（平局）→ 3-5 年 3.60/4.00（差 +0.40，偏小公司）[实测]。

## 主问答
**Q（面试官原话）：** 你为什么来大公司 / 为什么选我们这家小公司？
**A：**
1. **先把权重说出来，再对上这家公司的具体点**（投大公司）：「我在这个阶段的权重是简历背书和技术成长最重要。贵公司在 XX 领域的技术积累、这条业务线的数据量与并发场景，正好压在我最看重的两项上。」（投小公司）：「我判断创业公司的标准是——程序员是不是价值链上不可替代的一环。你们做自研产品、有核心技术，产品成型后能放大我的产出。」[源码]
2. **被问「大公司是不是容易当螺丝钉」**：把「公司大小」这个错误维度替换成「岗位/业务线能接触什么」：「是不是螺丝钉跟公司规模关系不大，看岗位能接触多少、自由度多大、有没有技术挑战。我在大厂见过做核心系统的，也在小公司见过天天改外包皮的。」[源码]
3. **被问「小公司薪水更高你去吗」**：用「阶段 → 权重 → 结论」链条回答：「看我在什么阶段。应届更看重背书和基础训练；3-5 年、能力可举证时会认真看——只要它是真创业公司、能给自主权和赛道，薪水更高是加分不是决定项。」[源码]
4. **大公司内也要选业务线**：**夕阳业务**（维护为主、不再投入）/ **蓬勃业务**（投入最大、飞速扩张）/ **探索业务**（验证市场、少数成长为主营）——「进大厂」只是第一步，「进哪条业务线」同样决定成长 [源码]。
5. **被问「你会在一家公司待多久」**：别答死数字，答判断依据：「看我当初选它的那几个权重维度是否还成立——为技术成长来的，业务进入维护期就是重新评估的信号。」把「待多久」转成「什么时候该重新审视」[经验]。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| 决策矩阵 | 权重是个人价值排序，无标准答案 | 改权重可以，但必须说得出理由 |
| 「应届优先大公司」 | 是经验规律非定律 | 大厂背景利于简历筛选的口径随年份与招聘方变 |
| 大公司稳定性 | 相对优势非绝对保障 | 会加班、会战略调整、会裁撤业务线 |
| 业务线三分类 | 蓬勃业务收入占比可能不高 | 看投入力度与增速，不看当期收入 |
| 真假创业判据 | 程序员不可替代性 | 靠人脉拉项目变现的软件作坊不在此列 |

## 关键代码
```go
// decision_matrix.go —— 大公司 vs 小公司：按职业阶段选权重的决策矩阵
// 重点不是帮你选，而是：① 给出三档预设权重并说明理由；
// ② 所有数字可改，看结论在哪个维度最敏感——那时该去补信息，不是拍脑袋。
// 打分 1~5，权重和 = 100，加权得分 = Σ(权重 × 打分) / 100
package main

import (
	"fmt"
	"sort"
)

var dims = []string{"现金薪酬", "技术成长", "简历背书", "稳定性", "自主权/影响力", "业务前景", "工作生活平衡"}

// 三档预设权重（每档和 = 100）：
//   应届：最缺「好赛道+可流通背书+基础训练」，简历背书 25/技术成长 20 最高，自主权 5 最低
//   1-3年：已有背书，缺「能力跃迁+涨薪」，技术成长 25/现金 20 抬上来，背书降到 15
//   3-5年：要带事、拿决定权、押赛道，现金 25/自主权 20/业务前景 20 最高，背书 5 最低
var tiers = []struct {
	name    string
	weights []int
}{
	{"应届", []int{10, 20, 25, 15, 5, 15, 10}},
	{"1-3年", []int{20, 25, 15, 10, 10, 15, 5}},
	{"3-5年", []int{25, 15, 5, 10, 20, 20, 5}},
}

// 两个 offer 的打分（1~5，读者按自己情况改）：A 大公司稳、背书强、自主权低；
// B 小公司（真创业/核心技术岗）现金高、成长快、自主权大，稳与背书弱。
var scoreA = []int{4, 3, 5, 5, 2, 4, 4} // 大公司
var scoreB = []int{5, 5, 2, 2, 5, 3, 2} // 小公司

func dot(w, s []int) int {
	sum := 0
	for i := range w {
		sum += w[i] * s[i]
	}
	return sum
}

func main() {
	fmt.Println("=== 大公司 vs 小公司 · 决策矩阵 ===")
	fmt.Println("\n--- 各阶段加权得分 ---")
	for _, t := range tiers {
		a := float64(dot(t.weights, scoreA)) / 100
		b := float64(dot(t.weights, scoreB)) / 100
		win := "平局（需自行定夺）"
		switch {
		case a > b:
			win = "A 大公司"
		case b > a:
			win = "B 小公司"
		}
		fmt.Printf("%-8s A=%.2f  B=%.2f  差=%+.2f  → 倾向 %s\n", t.name, a, b, b-a, win)
	}

	// 敏感性：贡献 = 权重×(打分A-打分B)/100，正=偏 A，负=偏 B；绝对值越大结论越容易翻
	fmt.Println("\n--- 敏感性：各维度对「A−B」的贡献 Top3 ---")
	for _, t := range tiers {
		type contrib struct {
			dim string
			val float64
		}
		var cs []contrib
		for i, d := range dims {
			cs = append(cs, contrib{d, float64(t.weights[i]*(scoreA[i]-scoreB[i])) / 100})
		}
		sort.Slice(cs, func(i, j int) bool { return cs[i].val > cs[j].val })
		fmt.Printf("[%s]", t.name)
		for k := 0; k < 3; k++ {
			fmt.Printf(" %s(%+.2f)", cs[k].dim, cs[k].val)
		}
		fmt.Println()
	}
	fmt.Println("\n用法：把「结论最敏感的那一两个维度」去交叉验证（见 2002 的单源孤证），")
	fmt.Println("      而不是把整张表算得更精确 —— 精度不等于可信度。")
}
```

实测输出（go1.26.5 darwin/amd64）[实测]：

```text

1-3年    A=3.80  B=3.80  差=+0.00  → 倾向 平局（需自行定夺）
3-5年    A=3.60  B=4.00  差=+0.40  → 倾向 B 小公司
--- 敏感性 Top3 ---
[应届]   简历背书(+0.75) 稳定性(+0.45) 工作生活平衡(+0.20)
[1-3年]  简历背书(+0.45) 稳定性(+0.30) 业务前景(+0.15)
[3-5年]  稳定性(+0.30) 业务前景(+0.20) 简历背书(+0.15)
```

**同一份事实（打分没变），只因权重随阶段变，结论就相反**——「X 一定比 Y 好」都是偷偷固定了一套权重的伪命题。应届阶段该补信息的是「简历背书/稳定性」这两个敏感维度，而不是纠结 0.20 的平衡项。

## 总结与追问预判
一句话记忆：**「阶段定权重，权重定结论；真假创业看不可替代性」**。追问预判：「怎么判断创业公司靠不靠谱」——三问尽调：钱从哪来（自研产品 vs 人脉拉项目）/ 核心角色是谁（程序员 vs 拉项目的人）/ 成功后程序员能否分到回报（期权/股权/分成）；危险信号：收入靠一两个大客户定制、技术一两个人撑着、老板全是销售背景。「你的权重为什么这么配」——必须给出理由链，说不出理由就是拍脑袋。敏感维度的验证方法见 2002；薪资的年包口径见 2003 [边界]。

## ⚠️ 原文纠错
1. 大公司「不需要没日没夜加班、不用担心战略变动、不用担心工资发放」——绝对化。大公司同样会加班（业务线差异极大）、会战略调整、会裁员裁业务线；稳定性与背书是平均优势，不是保障。
2. 「小公司到大公司属于正向发展」——绝对化。小→大常被视为正向，但大→小或平移也可能是更优选择（更核心岗位、更大自主权、更好赛道）。
3. 「只要公司有一两个技术大拿，通常都能顺利完成项目」——绝对化且与源文自己的立场矛盾（它前文刚说软件作坊核心不是程序员）。
4. 「每个人都是一颗螺丝钉」——以偏概全，这是源文转述的误解引子，源文后文自我否定（跟规模关系不大），读者易只记住前半句。
5. 全篇只给建议没给方法：说了「应届优先大公司」，没给多 offer 比较的可操作框架——本卡的决策矩阵补这个缺口。
6. 「核心公员」「生成的概率」「不具备公司的特质」「零成本复制的图点」「公报」——转写崩坏，应为「核心人员」「生存」「创业公司的特质」「优点」「回报」。
