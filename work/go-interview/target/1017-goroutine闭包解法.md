# 1017 goroutine 闭包解法

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**传参值拷贝** / **循环内重赋值** / **传指针仍坏**
> 原文锚点：第 76~106 段「重赋值 i、传参、传指针仍坏、WaitGroup 同步」

## 一句话总述
修 goroutine+循环变量三招：① 循环内 `x := i` 造每轮新变量；② 传值参数 `go f(i)`（值拷贝）；③ **传指针 `&i` 仍坏**。同步用 WaitGroup，且 `Done` 必须在 goroutine 内调。

## 面试官视角
- 意图：能否给出可工作的修法并识破"传指针"伪解。
- P5 知传参能修 / P6 说清重赋值与值拷贝原理 / P7 知 WaitGroup 的 Done 调用位置陷阱。
- 红旗：以为传 `&i` 也行；在 go 语句外调 `wg.Done`。
- 惊艳点：传指针版参数地址不变，输出仍全最后值，与"不修"同效 `[经验]`。

## 主问答
**Q（面试官原话）：** 上面那个 for+goroutine 打印 i 的坑，有哪几种正确修法？
**A：**
1. **结论**：循环内重赋值 `x := i` 或传值参数 `go func(v int){}(i)` 都能修；传 `&i` 修不了。
2. **机制**：重赋值/传值让每轮有独立存储；传指针共享的还是那个 `i` 的地址，值仍被覆盖。
3. **边界**：`wg.Done` 必须写在 goroutine 体内，不能写在 `go` 语句之后（那边是异步的）。
**加分层：** Go 1.22+ 原写法已自愈，但显式传参可读性更好、向后兼容。

- 重赋值/传值可修，传指针无效；Done 在 goroutine 内。
