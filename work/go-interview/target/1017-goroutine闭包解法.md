# 1017 goroutine 闭包解法

> 分类：并发模型 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**传参值拷贝** / **循环内重赋值** / **传指针仍坏** / **WaitGroup 同步**

> 原文锚点：第 76~106 段「重赋值 i、传参、传指针仍坏、WaitGroup 同步」

## 一句话总述
修 `for + goroutine` 捕获循环变量的三招：① 循环内 `x := i` 造每轮新变量；② 传值参数 `go f(i)`（值拷贝）；③ **传指针 `&i` 仍坏**。同步用 WaitGroup，且 `Done` 必须写在 goroutine 体内。一句话背法：**「闭包捕获的是变量不是值，重赋值或传值切断共享，传指针切断不了」**。

## 面试官视角
- 意图：能否给出可工作的修法并识破"传指针"伪解。
- **P5**：知传参能修。
- **P6**：说清重赋值与值拷贝原理。
- **P7**：知 WaitGroup 的 Done 调用位置陷阱，并点出"传指针版地址不变、输出仍全最后值"。
- 红旗：以为传 `&i` 也行；在 `go` 语句外调 `wg.Done`。

## 主问答
**Q（面试官原话）：** 上面那个 for+goroutine 打印 i 的坑，有哪几种正确修法？

**先铺垫（由浅入深第 1 层）**：Go ≤1.21 循环变量 `i` 在每次迭代**共享同一个变量**，goroutine 异步启动后才读 `i`，读到的是循环结束后的终值——所以全打最后一个数。根因是"闭包捕获的是变量，不是那一刻的值"。

1. **结论（第 2 层）**：循环内重赋值 `x := i` 或传值参数 `go func(v int){}(i)` 都能修；传 `&i` 修不了。
2. **机制（第 3 层）**：重赋值/传值让每轮有独立存储；传指针共享的还是那个 `i` 的地址，值仍被覆盖。
3. **边界（第 4 层）**：`wg.Done` 必须写在 goroutine 体内，不能写在 `go` 语句之后（那边是异步的，Done 时机不可控）。
4. **演进（第 5 层）**：Go 1.22+ 循环变量每轮独立，原写法**自愈**；但显式传参可读性更好、向后兼容，仍推荐写。
5. **验证（第 6 层）**：用 `go test -race` 跑修复前后的版本，未修复版会报 `data race`，修复版干净。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	// ✅ 修法1：循环内重赋值，每轮独立变量
	var wg sync.WaitGroup
	for i := 0; i < 3; i++ {
		i := i // 每轮新变量
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println("fix1:", i) // 0 1 2
		}()
	}
	wg.Wait()

	// ✅ 修法2：传值参数，值拷贝切断共享
	for i := 0; i < 3; i++ {
		wg.Add(1)
		go func(v int) {
			defer wg.Done()
			fmt.Println("fix2:", v) // 0 1 2
		}(i)
	}
	wg.Wait()

	// ❌ 传指针 &i 仍坏：所有 goroutine 读的是同一个 i 的地址，输出仍全 2
	// for i := 0; i < 3; i++ {
	//     wg.Add(1)
	//     go func(p *int) { defer wg.Done(); fmt.Println("bad:", *p) }(i)
	// }
}
```

## 总结与追问预判
**背这三句就够**：① **闭包捕获变量不是值**；② **重赋值/传值切断共享，传指针切断不了**；③ **Done 写在 goroutine 内，1.22+ 自愈但建议传值**。
**预判追问**：
- 「1.22 改了什么？」→ 循环变量每轮独立，消除历史闭包坑（见 1017 循环变量语义）。
- 「和 Add 时机坑有关吗？」→ 无关，是独立坑（见 1020）。
- 「怎么确认修好了？」→ `go test -race` 无 data race 即通过。
