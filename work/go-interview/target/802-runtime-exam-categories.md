## 一句话总述
Go runtime 面试题可归为**三类**：①**基础概念类**（协程调度器/内存管理/GC/反射及其优缺点）；②**结构体类**（G/M/P/Mspan/mheap 等核心结构与字段、相互关系）；③**场景细节类**（协程泄漏/内存泄漏/GC 暂停/协程抢占/内存分配策略及排查）。辅以 **pprof/GDB** 等调试工具定位性能问题——本质是"概念→结构→场景"三层知识地图。

## 面试官视角
这道题考你能否把 runtime 庞杂知识**结构化**。面试官想看你是否有一张清晰的考点地图，而非零散记忆。

## 主问答
**Q（面试官原话）：** runtime 面试一般会问哪些方向？

**A：**

1. **基础概念类**：协程调度器、内存管理、垃圾回收、反射的原理与优缺点；典型如"什么是 goroutine / GMP 模型是什么 / GC 标记清除怎么实现"。
2. **结构体类**：G/M/P/Mspan/mheap 等核心结构体与关键字段、相互作用；典型如"G 结构体有哪些字段 / mheap 含义"。
3. **场景细节类**：协程泄漏、内存泄漏、GC 暂停、协程抢占、内存分配策略的分析与解决，以及最新特性（混合写屏障、基于信号抢占）；排查靠 pprof/GDB。
4. **调试工具**：用 pprof 做 CPU/堆分析、GDB 看运行时状态，把"背概念"连到"真排查"。
