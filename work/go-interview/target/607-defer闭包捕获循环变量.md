# 607 defer 闭包捕获循环变量

> 分类：并发模型 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**循环变量** / **闭包捕获** / **per-iteration**
> 原文锚点：第 62~80 段「闭包 defer 读 y 得三，输出三个三」

## 一句话总述
defer 闭包捕获的是循环变量本身；旧版 Go 变量全程一个地址，defer 执行时读到终值；Go 1.22 起每轮独立，坑被修复。

## 面试官视角
- 意图：是否知道 defer 闭包 + 循环变量的经典坑及版本翻转。
- 分档：P5 知输出全同 / P6 说清共享变量 / P7 知 1.22 翻转且旧代码仍兼容。
- 红旗：以为一定输出 0,1,2；以为 GOMAXPROCS=1 能避坑。
- 惊艳点：同段代码 go1.21 打印三个三、go1.22 打印 0,1,2 `[源码]` release notes。

## 主问答
**Q（面试官原话）：** for 里 defer 闭包打印 i，为什么全是同一个数？
**A：**
1. **结论**：旧版循环变量全程一个地址，闭包读的是终值；Go 1.22 起每轮变量独立，该坑自愈。
2. **机制**：defer 把闭包压栈，执行在函数返回前；此时循环已跑完，闭包读到的是循环结束后的 y 值（如 3）。
3. **边界**：非闭包 `defer print(i)` 在声明时定格各轮值，按 LIFO 输出；只有闭包才读终值。
**加分层：** 1.22+ 该写法已自愈，但仍推荐显式传参或 `i:=i` 更清晰。

## 关键代码
```go
// 示意，未验证：旧版典型坑（go1.21 输出三个三）
for i := 0; i < 3; i++ {
    defer func() { println(i) }() // 1.21 打印 3,3,3；1.22+ 打印 2,1,0
}
```

## 总结与追问预判
- 旧版共享循环变量，闭包读终值；1.22 每轮独立修复。
- 预判：正确修法 → 见 607。
