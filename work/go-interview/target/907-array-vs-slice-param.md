# 907 数组与切片传参：一组地址对比实验

> 分类：Go 语言 | 难度：L2 | 题型：陷阱题 | 频率：高 | 关键词：**值传递、数组拷贝、切片传参、取地址**

> 原文锚点：第 36~42 段「数组在 main 与函数内地址不一样…切片传进去地址一样」

## 一句话总述
数组传参会把**整个数组的值**拷进函数，所以函数内外地址不同；切片传参只拷那份很小的描述符，描述符里的指针没变，因此打印出的底层数组地址一致。

## 面试官视角
P6 说"切片是引用传递"；P7 要纠正——Go **只有值传递**，切片传的是描述符的副本，只是副本里的指针仍指向同一块底层数组 `[经验]`。加分点：打印数组地址要先取地址再用 `%p`，而切片本身就可以直接格式化，这个细节能暴露是否真动手写过 `[源码]`。

## 主问答
**Q（面试官原话）：** 数组和切片当参数传进去，地址为什么不一个变一个不变？

1. **Go 只有值传递**：赋值与传参都是把原始值的直接部分复制给目标值 `[源码]`。
2. **数组拷贝代价大**：数组没有间接部分，传参会复制整个数组的值，大数组开销显著 `[经验]`。
3. **切片只拷描述符**：描述符里的指针、长度、容量被复制一份，代价只有几十字节 `[实测]`。
4. **指针没变所以地址相同**：副本中的指针仍指向同一块底层数组，用 `%p` 打印自然得到同一个地址 `[源码]`。

## 关键代码
```go
func f1(a [3]int) { fmt.Printf("%p\n", &a) } // 与调用方不同
func f2(s []int)  { fmt.Printf("%p\n", s)  } // 与调用方相同
func main() {
	a := [3]int{1, 2, 3}; fmt.Printf("%p\n", &a); f1(a)
	s := []int{1, 2, 3};  fmt.Printf("%p\n", s);  f2(s)
}
```
> 验证：数组两处地址不同、切片两处地址相同 `[实测]`。

## 总结与追问预判
**变的不是传递方式，是被拷贝的东西大小不同**。把这句说清，"切片是不是引用传递"这类问题就稳了。
