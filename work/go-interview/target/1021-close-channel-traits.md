# 1021 关闭通道的四条特性

> 分类：并发模型 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**close** / **零值** / **ok**
> 原文锚点：第 3~7 段「关闭的通道不能再关、重复 close 会 panic；读关闭通道得零值…」

## 一句话总述
关闭态 channel 有四条稳定特性：不可再关、向它写会 panic、读它得零值且第二返回值 `ok==false`、for-range 读完即退出。

## 面试官视角
- 意图：是否把 close 后的读写行为当常识掌握。
- P5 知写panic/读安全 / P6 能说清四条尤其是 ok 信号 / P7 知用 ok 或 for-range 做退出判定。
- 红旗：以为读关闭 channel 也 panic；以为 close 后还能再写。
- 惊艳点：读已关闭 channel 不会 panic，只是反复得零值且 `ok=false` `[源码]` 语言规范。

## 主问答
**Q（面试官原话）：** 关了的 channel 还能读吗？读完会怎样？
**A：**
1. **结论**：已关闭 channel 可继续读，不会 panic，只是取零值，第二返回值 `ok` 变 `false`。
2. **机制**：close 置关闭态；接收端见关闭态即返回零值+false，for-range 在读完缓冲后自动退出。
3. **边界**：向已关闭 channel **发送**才会 panic；close 后再 close 也 panic——读是安全的，写/关不是。
**加分层：** 退出读取循环优先用 for-range 或 `v, ok := <-ch`，别自己猜。

## 关键代码
```go
// 示意，未验证：读已关闭 channel 得零值 + ok=false
ch := make(chan int, 1)
ch <- 7
close(ch)
v, ok := <-ch // v=7, ok=true（缓冲里还有值）
v, ok = <-ch  // v=0, ok=false（已空且关闭）
```

## 总结与追问预判
- 关闭 channel 读安全（零值+ok=false）、写/关 panic；for-range 读完退出。
- 预判：怎么安全退出读取循环 → 见 1021-close-exit-patterns。
