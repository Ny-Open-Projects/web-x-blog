# 181 Linux 发行版格局与迁移决策深挖

## 思路与架构
把整个事件拆成**三层因果链**，回答时自上而下讲，不会散：

1. **许可证层**：内核采用 GPL，任何人都能拿到源码重编译再分发——这正是「RHEL 源码 → 免费重建版」能合法存在的根因。
2. **发行版生产流程层**：`Fedora（前沿） → CentOS Stream（上游，滚动） → RHEL（商业稳定） → 社区重建版（下游）`。停更的本质是把社区重建版抽走，只留上游滚动版。
3. **工程决策层**：团队真正关心的是三件事——**有没有安全补丁**、**要不要改代码与包**、**迁移窗口有多长**。所有选型讨论都应回到这三点。

按这三层讲，既能接住「讲讲历史」的开放式提问，也能接住「你们怎么选」的落地追问。

## 方案取舍
- **同系迁移（Rocky / AlmaLinux） vs 跨系迁移（Debian / Ubuntu）**：前者保二进制兼容、迁移脚本成熟、成本最低，但生态仍绑定 rpm 系；后者包管理、路径、systemd 配置全要重做，收益是社区生态与新内核更快。
- **自建重建版 vs 用成熟社区版**：自建可控但长期维护成本高，除非有强合规要求，否则不划算。
- **原地升级 vs 重建镜像**：原地升级省事但状态脏、难回滚；重建镜像（Immutable 思路）前期投入大，却换来可复现与快速回滚，中大规模更划算。
- **静态编译 vs 动态链接**：`CGO_ENABLED=0` 的静态二进制不依赖 glibc，能跨发行版直接跑，代价是失去 cgo 依赖的系统库（如某些 DNS 解析行为与数据库驱动）。
- **容器化规避 vs 直面迁移**：容器把依赖打进镜像，弱化 OS 差异，但基础镜像本身仍是某个发行版，内核特性与系统调用仍受宿主机约束——**容器降低迁移成本，不等于消灭迁移**。

## 答题技巧
- **先给时间线再给影响**：2020-12 宣布 → 2021-12 CentOS 8 EOL → 2024-06 CentOS 7 EOL → Stream 上位。时间线是证据，影响才是观点。
- **被问「Stream 和 CentOS 区别」先画方向**：一句话「原来在下游，现在在上游」，比描述特性更快建立共识。
- **被问「你们选了什么」先反问约束**：是否需要 RHEL 二进制兼容？信创合规？运维工具链能否重建？——带着约束回答显得有落地经验。
- **主动补一个反常识点**：「RAID 不是备份」同理，「容器不是迁移豁免券」，这类补充能把你从背答案的人里拉出来。
- **收尾给可验证动作**：灰度批次、回滚镜像、补丁节奏、监控 agent 兼容性验证——有动作才像做过。
