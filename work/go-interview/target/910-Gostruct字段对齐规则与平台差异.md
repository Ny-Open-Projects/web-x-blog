# 910 Go struct 字段对齐规则与平台差异

> 分类：Go 语法/内存 | 难度：L2 | 题型：概念题 | 频率：中 | 关键词：**对齐值**/**min 规则**/**最大对齐**/**32位 vs 64位**/**填充**
> 原文锚点：第 35~60 段「对齐值=min(类型对齐,机器字节)；结构体对齐值=最大字段对齐；size=累加+填充；平台差异」

## 一句话总述
字段对齐值 = **min(类型自身对齐, 编译器默认机器字节)**（64 位多为 8B）；结构体对齐值 = **所有字段对齐值的最大值**；size = 字段累加后**按对齐值填充**，对齐值为 1 则无填充。32/64 位与平台均影响结果。

## 面试官视角
- 考察意图：能否从「对齐值」公式推出 size，而非靠猜。
- 分档：P5 知对齐值=min(类型,机器字节)；P6 知结构体对齐值=字段最大对齐、size 含填充；P7 知对齐值=1 无填充、不同平台/编译器规则可能不同。
- 红旗答案：把结构体对齐值说成「字段对齐值之和」或「公约数」（正确是最大值）；忽略填充。
- 惊艳点：点出「源文本想表达结构体对齐值=最大字段对齐（非字面公约数），按最大对齐才正确」 [经验]。

## 主问答
**Q（面试官原话）：** 对齐值和对齐规则具体怎么算？
**A：**
1. **字段对齐值 = min(类型对齐, 机器字节)**：如 64 位架构机器字节 8B，int8 对齐 1、int16 对齐 2、int64 对齐 8；字段按各自对齐值摆位 [经验]。
2. **结构体对齐值 = 字段对齐值的最大值**（源文误写「公约数」，正确为最大）：size = 各字段尺寸累加后**按该最大对齐值填充**补齐；若对齐值=1 则不做任何填充、按裸布局 [经验]。
3. **平台/编译器差异**：32 位机器字节 4B、64 位 8B，同一结构在两环境 size 可能不同（如 32 位 12/16、64 位 16/24）；不同硬件/编译器对齐规则也可能不同 [经验]。

## 版本与兼容性
- 不依赖 Go 版本，属编译期布局；unsafe.Sizeof/Alignof 可实测。struct padding 通用结论见 1112 [边界]。

## 总结与追问预判
规则会算后，空结构体作为字段（尤其末位）有个反直觉特例，下一张讲。

## ⚠️ 原文纠错
1. 事实核校： [经验] 字段对齐值=min(类型对齐,机器字节8)、结构体对齐值=最大字段对齐、size=累加+填充、对齐值=1 无填充、32/64 位差异——均正确；补正源文「公约数」为「最大值」之误。
2. 崩坏词归一：源码将若干术语音译为崩坏词，本卡统一为规范术语（对齐值、填充、机器字节、结构体布局等）。

```go
package main

import (
    "fmt"
    "unsafe"
)

type T struct {
    a int8   // 对齐1
    b int64  // 对齐8
    c int16  // 对齐2
}

func main() {
    fmt.Println(unsafe.Alignof(T{}))      // 8（最大字段对齐）
    fmt.Println(unsafe.Sizeof(T{}))       // 1+7(pad)+8+2+6(pad)=24
}
```
