# 421 指针内嵌：具名/匿名/接口判定

> 分类：Go 语法/结构体嵌入 | 难度：L3 | 题型：八股题 | 频率：中 | 关键词：**指针内嵌**/**匿名指针**/**具名指针**/**接口指针**/**判定**

> 原文锚点：第 8~30 段「内嵌类型不能是指针…具名指针类型(intPtr)不可嵌…匿名指针类型可嵌…接口类型本身的指针(*iperson)不可嵌…匿名结构体指针可嵌…基类型指针可嵌」

## 一句话总述
"指针能不能嵌"的判定关键是**指针是不是具名的、以及指向的是不是接口**：**匿名指针 `*T`（T 为具名非指针非接口类型）可以嵌**；**具名指针类型 `type P *T` 不可嵌**（因为 T 成了指针类型，违反"T 不能是指针"）；**接口类型的指针 `*I` 不可嵌**（接口可嵌 T 本身，但不可嵌 `*T`）。

## 面试官视角
这是上一题的纵深。面试官要看你区分"匿名指针字面量"与"具名指针类型"、以及"接口 vs 接口指针"的能力——多数人只会说"指针不能嵌"，漏掉匿名指针可嵌的例外。

## 主问答
**Q（面试官原话）：** 那指针类型到底能不能被内嵌？

**A：**

1. **匿名指针 `*T` 可以嵌**：直接写 `*int`、`*person` 这种匿名形式，只要 T 是具名、非接口、非指针类型，就满足"指向非接口类型名 T 的指针"，合法。
2. **具名指针类型不可嵌**：`type intPtr *int` 再嵌入 `intPtr`，此时内嵌字段类型 `intPtr` 的底层是**指针类型**，违反 spec"T 不能是指针类型"→ 编译报错。
3. **接口指针不可嵌**：接口 `iperson` 本身可以嵌；但 `*iperson`（指向接口的指针）不行——规则明确"若嵌入类型是指针，T 不能是接口类型"。

## 版本与兼容性
- 规则源自 Go 语言规范"Struct types"节，Go 1.0 起不变；匿名指针嵌入是常见惯用法（如嵌入 `*sync.Mutex` 让外层直接 `Lock()`）。

## 关键代码
```go
type person struct{ name string }

// 匿名指针嵌入：合法（*person 的 T=person 具名非指针非接口）
type Worker struct{ *person }

// 具名指针类型：非法（T 成了指针类型）
// type pPerson *person
// type Bad struct{ pPerson } // compile error: embedded type cannot be a pointer

// 接口指针：非法
// type I interface{ F() }
// type Bad2 struct{ *I } // compile error
```

## 总结与追问预判
- 口诀：**匿名指针可嵌，具名指针不可；接口可嵌，接口指针不可**。
- 预判追问："那嵌入 `*sync.Mutex` 算什么？"→ 正是匿名指针嵌入的典范，外层直接复用 `Lock`/`Unlock`。
