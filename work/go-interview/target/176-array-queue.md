# 176 用切片（数组）实现队列

> 分类：数据结构 / Go | 难度：L2 | 题型：实现题 | 频率：中 | 关键词：**队列**/**FIFO**/**切片**/**入队 append**/**出队 copy 前移**/**截取出队内存泄漏**

> 原文锚点：第 9~19 段「数组实现队列：队尾入队、队头出队」

## 一句话总述
队列是**先进先出（FIFO）**结构，从**队尾入队、队头出队**。用 Go 切片实现时，入队即 `append` 到末尾（O(1)），出队取 `items[0]` 后**用 `copy` 把后续元素整体前移一位再缩视图**——直接 `s[1:]` 截取虽省事，但弹出的元素仍留在底层数组前部，指针元素无法被 GC，会内存泄漏。

## 面试官视角
切片队列是手撕题常客，与切片栈（见 `173-array-stack.md`）成对出现。栈的坑在**尾部**槽位不释放，队列的坑在**头部**槽位不释放——考官用同一把刀切两遍，看你是不是真懂「切片只是视图」这层。能主动说出 `copy` 前移与 `s[1:]` 的区别，才算想过。

## 主问答
**Q（面试官原话）：** 用数组怎么实现一个队列？

1. **结构定义**：切片存元素 + `size` 计数；并发场景加 `sync.Mutex`。把**数组头部当队头**，尾部当队尾。
2. **入队 O(1)**：`append(items, x)` 追加到末尾，size+1，无需移动任何元素。
3. **出队的正确姿势**：取 `items[0]` 后执行 `copy(items, items[1:])` 把全体前移一位，再 `items = items[:size-1]` 缩视图，size-1。`copy` 是值前移覆盖，队头槽位被后继元素覆写，旧引用断开。
4. **为什么不能用 `s[1:]` 截取**：截取只是移动切片视图的起始指针，**底层数组前部槽位原样保留**——元素是值类型浪费的是内存，是指针类型则被 GC 扫描到、**弹出的对象永远无法回收**（[实测] go1.26.5：`s=s[1:]` 一次后，底层数组槽位 [0] 仍持有原 `*Big` 指针，`full[0] != nil` 为 true）。
5. **代价要心里有数**：`copy` 前移是 O(n)，出队总代价 O(n)——[实测] n=100000 次入队+出队，数组 copy 版 1.37s，而 O(1) 链表队列仅 8.5ms（160 倍）。大批量场景见深卡 `176-linkedlist-queue.deep.md`。

## 版本与兼容性
| 写法 | 出队复杂度 | 内存风险 |
|------|------------|----------|
| `s[1:]` 截取 | O(1) | 头部槽位引用滞留，指针元素泄漏 |
| `copy` 前移 | O(n) | 无泄漏，但高吞吐下 CPU 代价大 |
| 标准库 `container/list` | O(1) | 双向链表，每元素额外两个指针开销 |

## 关键代码
```go
type Queue struct {
    items []int
    size  int
    mu    sync.Mutex
}

func (q *Queue) Enqueue(x int) {
    q.mu.Lock()
    defer q.mu.Unlock()
    q.items = append(q.items, x)
    q.size++
}

// Dequeue: copy 前移覆盖队头，断开旧槽位引用；截取 s[1:] 会内存泄漏
func (q *Queue) Dequeue() (int, bool) {
    q.mu.Lock()
    defer q.mu.Unlock()
    if q.size == 0 {
        return 0, false
    }
    v := q.items[0]
    copy(q.items, q.items[1:])  // 整体前移一位
    q.items = q.items[:q.size-1]
    q.size--
    return v, true
}
```

## 总结与追问预判
核心：**切片队列入队 append O(1)；出队必须 copy 前移，`s[1:]` 截取会让队头元素滞留底层数组——指针元素直接泄漏**。追问常拐向「和链表队列怎么选」「高并发任务队列怎么设计」——备好 O(n) vs O(1) 账本（见 `176-linkedlist-queue.deep.md`），并发安全对比见 `109-safeslice-channel.md`（channel 天然队列语义）。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文出队演示沿用栈的思路说「使用新的切片替换原切片让旧切片地址被回收」——表述含混且不完整：仅 `s = s[1:]` 换视图并**不会**让队头元素脱离底层数组，元素仍被引用；正确做法是 `copy` 前移或头槽位置空。本卡以实测输出修正。
2. 术语归一：源文多次将「队列」音译为 queen、入队转写为「艾特」「首入」，本卡统一为规范术语。
