# 912 Goroutine 调度与栈演进 深挖

> 覆盖源 9-12 全文：进程/线程/协程三者对比 + 上下文切换开销(TLB) + goroutine 四大优势。主卡已给概念对比，本附录做"协程调度模型"与"Go 栈尺寸演进"深挖。

## 思路与架构

```text
goroutine 轻量根因
├─ 调度模型: M:N — 工作线程(M)服务多个协程(G), 协程仅用户态调度
├─ 切换成本: 只保存/加载 CPU 寄存器, 无内核态切换
└─ 栈演进: Go1.2(4KB→8KB) → Go1.4(8KB→2KB) → Go1.19+(自适应, 最小2KB)
```

## 方案取舍
- **协程 vs 线程切换**：线程切换是用户↔内核态，涉及内核栈/私有栈/寄存器，开销高；goroutine 切换仅 CPU 寄存器，全程用户态，开销低一个量级 [经验]。
- **栈尺寸策略**：早期固定栈（1.2: 4KB→8KB，1.4: 8KB→2KB）浪费或易溢出；1.19+ 改为按需增长收缩的自适应栈，最小 2KB，兼顾省内存与防溢出 [经验]。
- **TLB 视角**：进程/线程切换必换页表→TLB 失效→地址转换变慢；goroutine 切换不换页表，无此代价。

## 答题技巧
- 被问"goroutine 为什么轻"按三层答：小栈(2KB)→用户态调度(无内核切换)→不触发 TLB 失效 [经验]。
- 主动边界到 `101-reduce-context-switch`(减少切换)、`813-gmp`(调度模型)，构成执行模型全栈 [边界]。
