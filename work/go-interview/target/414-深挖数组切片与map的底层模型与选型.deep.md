# 414 深挖：数组、切片与 map 的底层模型与选型

> 分类：Go 基础 / 数组与切片 | 难度：L4 | 题型：综合题 | 频率：高 | 关键词：**值类型、引用语义、底层数组、哈希表、内存布局、选型**

> 原文锚点：第 6~89 段「数组和切片都要求全部元素类型相同…切片的零值是 nil…nil 切片 append 不报错…映射不能直接写入…映射对于大多数元素为零值的情况可以节省大量内存」

## 思路与架构

把三者的差异收敛到**一个模型**上理解，答题时逐层展开：

1. **第一层：类型身份**——数组是值类型且**长度属于类型的一部分**（`[3]int` 与 `[4]int` 是不同类型）；切片是描述符（指针 + 长度 + 容量）；map 是指向哈希表结构的指针。
2. **第二层：内存布局**——数组与切片的底层数组都是**连续内存**，故下标访问是纯地址偏移；map 是**分桶的哈希表**，键经哈希落入桶，故有额外常数开销。
3. **第三层：零值语义**——数组的零值是「全元素零值」且内存已分配；切片与 map 的零值都是 nil，但**二者的可用性不对称**：nil 切片可 append，nil map 只读不可写。
4. **第四层：可用性边界**——切片能否写入取决于「索引是否越界」，与其是否为 nil 无关；map 能否写入取决于「哈希表指针是否为空」，故 nil 必 panic。
5. **第五层：选型决策**——下标密集、需顺序遍历、追求访问速度 → 数组/切片；键非整数、数据稀疏、需按键查找 → map。

## 方案取舍

| 维度 | 数组 | 切片 | map |
|---|---|---|---|
| 长度 | 编译期固定 | 动态可变 | 动态可变 |
| 类型身份 | 长度参与类型 | 与长度无关 | 与长度无关 |
| 内存 | 连续，全量分配 | 连续，按需扩容 | 分桶，只存真实键 |
| 访问 | O(1) 地址偏移 | O(1) 地址偏移 | O(1) 哈希 + 探测 |
| 零值 | 全元素零值 | nil | nil |
| 零值可用 | 可直接读写 | 可 append，不可索引写 | 只读，写 panic |
| 稀疏数据 | 浪费 | 浪费 | 节省 |
| 顺序性 | 有序 | 有序 | 无序 |

取舍要点：
- **要顺序 + 要极速** → 切片。
- **要按键查 + 稀疏** → map。
- **长度固定且极小** → 数组（常见于哈希、固定缓冲区），但 Go 中绝大多数场景应优先切片，因为数组传参会整体拷贝。

## 答题技巧

1. **先给模型再给结论**：开口先说「数组是值类型、切片是描述符、map 是指针」，再展开差异，比罗列零值表更有说服力。
2. **主动点出反直觉点**：「数组零值不是 nil 而是全零元素」「nil 切片能 append 但 nil map 不能写」——这两句是加分项，多数候选人答不全。
3. **用内存账说话**：被问到「什么时候用 map」时，直接举「给第 1000 个元素赋值，切片要分配 1000 份零值，map 只存 1 份」，比抽象描述有力得多。
4. **把 panic 场景说全**：主动区分编译期错误（如 `[3]int` 赋给 `[4]int`）与运行期 panic（nil map 写入、nil 指针数组赋值），体现排错经验。
5. **止步档位**：能讲清三层（类型身份 / 内存布局 / 零值语义）即达 L4；能再讲可用性边界与选型决策并给出内存账，即达 L5。

## 细节与核心 API

数组是值类型，长度是类型的一部分；切片是描述符（reflect.SliceHeader：指针+len+cap），指向底层数组：

```go
type sliceHeader struct {
    Data uintptr
    Len  int
    Cap  int
}
arr := [3]int{1, 2, 3}   // 值类型，赋值整体拷贝
s   := []int{1, 2, 3}    // 描述符，拷贝描述符但仍共享底层数组
fmt.Println(unsafe.Sizeof(arr)) // 24（3*8）
fmt.Println(unsafe.Sizeof(s))   // 24（指针8+len8+cap8），与长度无关
```

map 底层是 `*hmap`，buckets 指向 `bmap` 数组（每个 bucket 8 个 key/value + tophash）。选型：小定长集合用数组/切片；需要 key→value 查找用 map（注意非并发安全）；需有序遍历用切片+sort。

## ⚠️ 原文纠错
1. 事实核校：数组长度参与类型、切片为描述符、map 为指针、连续内存与哈希桶差异、零值不对称——均与 Go 规范一致 `[经验]`。
2. 补充：原文称「映射中的所有元素也都存放在一块连续的内存块当中」表述不严谨——map 的桶数组本身连续，但键值对分散在各个桶中，整体并非连续存放，答题时应说「桶数组连续、元素分桶存放」 `[经验]`。
3. 崩坏词归一：源码将数组、切片、映射（map）、下标、零值、连续内存等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
