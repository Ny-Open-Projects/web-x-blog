# 172 用 Go 实现单链表

> 分类：数据结构 / Go | 难度：L2 | 题型：实现题 | 频率：高 | 关键词：**单链表**/**节点结构**/**追加遍历**/**链表家族**/**尾指针优化**

> 原文锚点：第 2~11 段「节点结构体 → 追加实现 → 四种链表变体」

## 一句话总述
链表是递归结构：**节点 = 数据 + 指向下一节点的引用**。Go 实现 = 一个含 `data` 与 `next *Node` 字段的结构体；追加需沿指针走到 `next == nil` 的尾部再挂接（O(n)）；链表家族按指针数与成环与否分四类——**单链表、双向链表（加 prev）、循环单链表、循环双向链表**。

## 面试官视角
手写链表是数据结构第一题，考官看三点：① 结构定义是否干净（指针语义清楚）；② 追加/遍历的边界（空表、找尾）；③ 能否横向讲清**四变体的结构与适用**——只写过单链表的人说到循环链表就开始含糊。加分项是主动指出「走尾追加 O(n)，加尾指针变 O(1)」——这一步优化意识直接区分段位。

## 主问答
**Q（面试官原话）：** Go 中如何实现链表？

1. **节点定义**：`Node{ data int; next *Node }`——`next` 指向下一节点，nil 表示链尾。链表本体即「要么为空、要么持有头节点指针」。
2. **追加（源码版）**：从头开始 `for cur.Next != nil { cur = cur.Next }` 走到尾，再 `cur.Next = &Node{data: v}`——[实测] 追加 1、2、3 后遍历输出 1→2→3 正确。
3. **代价要主动报**：走尾追加是 **O(n)**——n 次追加总代价 O(n²)。优化：结构体多存一个 `tail` 指针，追加直接挂尾，O(1) 封顶（同一教训在队列实现里 [实测] 快 1055 倍，见 176.md`，此处不重复展开）。
4. **四种变体**：**单链表**——只有 next，单向可走；**双向链表**——加 `prev *Node`，可进可退（`container/list` 即此类）；**循环单链表**——尾节点 next 指回头节点成环，从任意节点可遍历全表；**循环双向链表**——next+prev 都成环，向前向后均可达。
5. **变体选型直觉**：只要「下一个」→ 单链表；要「回退/任意删除」→ 双向；要「环形轮询」→ 循环（如调度轮转）。

| 操作 | 源码版 | 尾指针版 | 说明 |

## 关键代码
```go
type Node struct {
	data int
	next *Node
}

type LinkedList struct{ head *Node }

// Append 源码版: 走到尾再挂接 (O(n); 加 tail 指针可 O(1))
func (l *LinkedList) Append(v int) {
	n := &Node{data: v}
	if l.head == nil {
		l.head = n
		return
	}
	cur := l.head
	for cur.next != nil { // 一直走到 next 为 nil 的尾节点
		cur = cur.next
	}
	cur.next = n
}
```

[实测] 依次追加 1、2、3 后遍历输出 1→2→3。

## 总结与追问预判
核心：**节点=数据+next；追加走尾 O(n)（尾指针可 O(1)）；四变体=单/双/循环单/循环双**。追问常拐向「链表 vs 数组怎么选」「环怎么检测」——环检测（快慢指针）与栈/队列实现族见 173.md`/`173-linkedlist-stack.md`/`176-array-queue.md`，走尾 O(n) 的实测教训见 176.md`，四变体的结构图与选型矩阵见 172.md`。
