# 505 数值转换的溢出防护与平台边界推导 深挖

> 覆盖源 5-5 全文：上下界位运算公式的补码推导、`^uint(0)>>1` 惯用法的来历、uint 系只判上界的数学依据、ParseInt 的 bitSize 参数选择、泛型时代的收敛方案。主卡已给六分支转换函数与实测，本附录做「边界公式推导」「平台差异账本」「错误处理设计」「泛型收敛」四层深挖。

## 思路与架构

```text
ToInt(v interface{}) (int, error) 决策树
├─ switch 断言分派
│   ├─ int          -> 直接返回
│   ├─ int8/16/32   -> 范围是 int 子集, 直接转 (64 位平台)
│   ├─ int64        -> 64 位平台直转; 32 位平台判 minInt<=v<=maxInt
│   ├─ uint8/16     -> 子集, 直转
│   ├─ uint32/uint64-> 只判 v > maxInt (无负数, 无下界问题)
│   ├─ string       -> ParseInt(s,10,64) -> 按平台位宽再判
│   └─ 其他(float64/结构体...) -> 返回 error
└─ 边界只算一次: 包级 init 里按 strconv.IntSize 算好 maxInt/minInt
```

## 方案取舍
- **边界公式的补码来历**：n 位补码能表示 `-2^(n-1) ~ 2^(n-1)-1`，负数比正数多一个（0 归到非负侧）。所以 max = `1<<(n-1) - 1`、min = `-1<<(n-1)`——**min 不能写成正 max 取负**（会溢出自己）：`-maxInt` 得到的是 `-2^(n-1)+1`，比真 min 大 1。惯用法 `int(^uint(0) >> 1)` 先取全 1 的无符号数再算术右移，天然适配任意位宽 [源码]。
- **math.MaxInt 与手算的取舍**：Go 1.17+ 有 `math.MaxInt/MinInt` 常量（无类型常量，随目标平台实例化），新代码应优先用；但面试手写位运算版更能展示**为什么是这个数**，且兼容老代码库。两者在 64 位平台等价 [经验]。
- **uint 系只判上界的严格论证**：无符号 n 位范围是 `0 ~ 2^n-1`，最小值 0 永远 ≥ int 的 min，所以下界判断是死代码；上界 `2^n-1` 对 uint64 是 `1.8×10^19`，远超 int64 的 `9.2×10^18`，必须判。**经典事故**：`int(uint64(1<<63))` 不报错、结果是最小负数——强转是**位模式重解释**（截断 + 符号位重新解释），不是数值映射，这是 Go 与多数语言一致的静默陷阱 [实测]。
- **ParseInt 的 bitSize 参数怎么填**：`ParseInt(s, 10, 64)` 先按 64 位解析并报 range error，再按平台判溢出；也可以直接填 `strconv.IntSize` 让解析本身就按平台位宽报错——后者少一步判断，但错误信息粒度相同。选 64 的理由是统一行为（32/64 位平台报错口径一致），选 IntSize 的理由是语义直白，两者都对，说清理由即可 [经验]。
- **泛型时代的收敛**：Go 1.18+ 可用 `constraints.Integer` 写一个泛型 `safeToInt[T Integer](v T)`，把窄类型直转、宽类型判界统一成「按位宽比较」的单一逻辑；但 interface{} 入口（DB 驱动返回值、JSON decode）仍需 switch 分派，**泛型收敛内部、断言守住边界**才是完整答案 [经验]。

## 答题技巧
- 先报函数签名再讲分支，边界在 init 算一次的细节主动说，体现「写的是生产代码不是面试代码」 [经验]。
- 用实测数字压轴：`uint64(1<<63) → -9223372036854775808`，一句话讲清「位模式重解释」，比背十条规则都有力 [实测]。
- 被问「32 位平台哪一分支变化」→ 答该平台上 int 就是 int32，int64/uint64/大数字符串三个分支全部进入判界路径 [经验]。
- 被问「浮点怎么转」→ 先反问「要不要四舍五入」再答 `int(f)` 截断 + 大数精度丢失，把问题收敛清楚再动手 [经验]。
- 主动边界到 `906-string-bytes-conversion`（string/[]byte 转换三代写法）、`510-struct-not-comparable`（类型系统另一类边界），构成类型转换专题 [边界]。

## 细节与核心 API

```go
var big int64 = 1 << 40
small := int32(big)          // 截断！编译通过但值错误（1<<40 mod 2^32）
// 安全收窄：先判范围
func toInt32(v int64) (int32, bool) {
    if v < math.MinInt32 || v > math.MaxInt32 { return 0, false }
    return int32(v), true
}
// 平台相关：int 宽度随架构变化（32/64），跨平台协议/存储务必显式 int32/int64
// uint→int 负值会回绕：uint(-1) == 4294967295（uint32）
```
