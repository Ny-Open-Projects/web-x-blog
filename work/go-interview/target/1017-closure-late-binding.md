# 1017 闭包延迟绑定

> 分类：并发模型 | 难度：L2 | 题型：事故题 | 频率：高 | 关键词：**闭包** / **延迟绑定** / **执行时才取值**
> 原文锚点：第 35~54 段「闭包用外部 user 变量，循环外执行时 user 已指向最后元素」

## 一句话总述
闭包**执行时才读取**外部变量，不是在创建时"拍快照"；把闭包推迟到循环外执行，它读到的循环变量已是最后一轮的值——这就是延迟绑定（late binding）。

## 面试官视角
- 意图：是否理解"闭包捕获的是变量本身，而非当时的值"。
- P5 知输出全是最后值 / P6 说清执行时机 + 捕获变量 / P7 知 Go 1.22 每轮独立变量可缓解。
- 红旗：以为闭包"记住了创建时的值"；以为没取址就没事。
- 惊艳点：函数切片在循环内立即调用就正常，延迟调用才踩坑 `[经验]`。

## 主问答
**Q（面试官原话）：** 我把一堆闭包存进切片，循环外统一执行，为什么打出来都是最后一个元素？
**A：**
1. **结论**：闭包捕获的是循环变量 `user` 本身，循环外执行时它已变成最后元素。
2. **机制**：闭包体里的 `user` 是外部变量引用，读值的时机在**执行那一刻**，不是创建那一刻。
3. **边界**：循环内立即执行闭包则读的是当轮值；Go 1.22 起每轮变量独立，常规写法不再踩坑。
**加分层：** 想"快照"就传参或循环内 `u := user` 显式拷贝。

## 关键代码
```go
// 示意，未验证：延迟绑定
var fns []func()
for _, u := range users {
    fns = append(fns, func() { println(u.Name) }) // 捕获 u
}
for _, f := range fns { f() } // 全打最后元素(旧版)
```
