# 1017 for-range 取址陷阱

> 分类：并发模型 | 难度：L2 | 题型：事故题 | 频率：高 | 关键词：**循环变量复用** / **取址** / **同一地址**
> 原文锚点：第 11~34 段「for-range 元素进行取址，循环里元素始终指向同一个地址」

## 一句话总述
旧版 Go 的 for-range 循环变量在每次迭代**复用同一变量（同一地址）**；对其取址并把指针追加进切片，遍历结束后所有指针都指向最后一个元素。

## 面试官视角
- 意图：是否理解 for-range 循环变量的"单实例"老语义，以及指针追加的典型坑。
- P5 知道取址会出问题 / P6 说清复用同一地址 + 给出正确写法 / P7 知 Go 1.22 已翻转该语义。
- 红旗：以为"每次迭代 u 是新变量"；以为打印出来的地址各不相同。
- 惊艳点：复现只需打印 `&u` 三次，地址完全相同 `[经验]` go1.21。

## 主问答
**Q（面试官原话）：** 下面这段 for-range 取地址存进切片，为什么打印出来全是最后一个元素？
**A：**
1. **结论**：旧版 for-range 的循环变量 `u` 在循环外只创建一次，每次迭代覆盖它。
2. **机制**：`&u` 取的是同一个地址，三次追加的都是这一地址；遍历完该地址里是最后元素的值。
3. **边界**：若切片元素是引用类型（如 `[]*User`）且**不取址**直接 append，则各元素各自独立，结果正常。
**加分层：** 该坑本质是"循环变量单实例"，与闭包无关；Go 1.22 起每次迭代独立变量，顺带修复。

## 关键代码
```go
// 示意，未验证：旧版 Go 典型坑
users := []User{{1, "a"}, {2, "b"}, {3, "c"}}
var ps []*User
for _, u := range users {
    ps = append(ps, &u) // 三次都是同一个 &u
}
// ps[0..2] 全指向 users[2]
```

## 总结与追问预判
- for-range 旧版复用变量→取址即同地址→全最后元素；引用类型不取址则正常。
- 预判：goroutine 里复用同一循环变量 → 见 1017。
