# 908 切片扩容深挖

> 分类：Go / 切片 | 难度：L3 | 题型：深挖 | 频率：高 | 关键词：**growslice** / **扩容因子** / **size 权衡** / **memmove** / **预分配**
> 原文锚点：第 1~42 段「slice 扩容机制；growslice 规则(<256翻倍/≥256过渡1.25/溢出panic/零大小)；按 elemsize 优化权衡；memmove 拷贝；make 预分配」

## 思路与架构
切片扩容 = "底层数组不可变 → 超限则分配新数组 + 拷贝 + 预留" 这一事实的三层展开：规则层（growslice 算容量）、优化层（按 elemsize 权衡时间/空间）、实战层（预分配降拷贝）。与「扩容换地址陷阱」是同一机制的两面。

## 方案取舍
```text
切片扩容三层：
──────────────────────────────────────────────────────────
规则层(growslice)   旧cap<256翻倍 / ≥256向1.25渐进过渡 / int溢出panic / 零大小返零值
优化层(elemsize)   大切片低因子(防内存浪费) / 小切片高因子(降拷贝频率) / 位运算微调
实战层(工程)        make 预分配避免频繁扩容 / 大切片append小数据警惕retention

扩容代价：
底层数组固定 → append 超 cap → 分配新数组 + memmove 拷贝旧 len + 预留 buffer
amortized：单次 append 摊还后近似 O(1)
```

## 答题技巧
```text
面试话术（先现象，再规则，后优化与实战）：
1. 现象：cap 不够才扩容，扩容后底层数组换地址（见 923 换地址陷阱）
2. 规则：<256 翻倍、≥256 向 1.25 渐进过渡；网传 1024 切换不准；int 溢出 panic
3. 优化：按 elemsize 权衡——大切片不双倍防浪费、小切片翻倍降拷贝
4. 实战：已知容量 make 预分配；拷贝的是旧 len；amortized 近似 O(1)
5. 收尾：扩容与换地址是同一机制两面，预分配是核心优化
```
