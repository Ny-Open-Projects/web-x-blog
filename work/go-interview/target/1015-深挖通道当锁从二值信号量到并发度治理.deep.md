# 1015 深挖：通道当锁——从二值信号量到并发度治理

> 分类：并发模型 | 难度：L4 | 题型：架构题 | 频率：高 | 关键词：**二值信号量、计数信号量、限峰值、设计哲学、快速路径、实测基准**

> 原文锚点：第 1~60 段「使用 channel 实现互斥锁…基准测试对比…channel 还能实现信号量…官方信号量与 GOMAXPROCS」

## 思路与架构

这一节的知识可以拆成**同一枚硬币的两面**：带容量的通道天然就是信号量，容量取 1 是互斥锁，容量取 N 是并发度控制器。

**第一面：容量 1 即互斥锁。** 声明缓冲容量为 1 的通道，元素用空结构体——传的是信号不是数据，零内存开销。访问共享变量前写入一个元素，此时唯一容量被占；其余 goroutine 再写入就会阻塞在写这一行，这就是加锁。操作完成后读出，容量释放，被阻塞者被唤醒并写入成功，这就是解锁。**容量必须是 1**：容量大于 1 时多个 goroutine 都能写入，互斥直接失效。这个结构在并发理论里叫**二值信号量**，锁只是它的一个特例。

**第二面：容量 N 即计数信号量。** 把容量换成 N，同样的写入/读出动作就变成"占配额/还配额"，N 就是同时运行的 goroutine 上限。任务侧通常用另一条通道承载任务，投完之后 `close`，消费侧用 `for range` 读完自动退出，不需要额外的结束信号。这里最易混淆的一点：**任务通道的容量只影响能缓存多少任务，与并发峰值无关**——峰值只由信号量通道的容量决定。

**第三面：该不该这么用。** 推崇通道不是因为它快，而是因为它契合"**不要通过共享内存来通信，而要通过通信来共享内存**"。实测同一段自增临界区：标准库互斥锁约 19.48 ns/op，通道锁约 62.00 ns/op，差约 3.2 倍，且两者都是 0 B/op、0 allocs/op——差距纯粹来自执行路径。原因在于通道内部本身就要加锁并维护发送/接收等待队列，用它当锁等于在锁外面再套一层；而互斥锁有 CAS 快速路径，一次 CAS 成功即拿到锁，失败才进慢路径，并在正常模式与饥饿模式之间切换、限制自旋。

于是结论收敛成一条判断准则：**保护共享状态用互斥锁，表达所有权流转与并发度用通道**。

## 方案取舍

| 决策 | 选项 | 取舍 |
|---|---|---|
| 保护临界区 | 互斥锁 / 通道锁 | 通道锁慢约 3 倍，仅教学与特殊编排场景用 |
| 限并发 | 通道信号量 / 官方信号量 | 通道够直观；官方支持加权与上下文取消 |
| 资源数取值 | 固定值 / 逻辑 CPU 数 | 取 CPU 数贴合机器，但 IO 型任务应更大 |
| 任务通道 | 关闭 / 不关 | 必须关，否则 `for range` 永不退出 |
| 归还配额 | 显式 / defer | 必须 defer，panic 不还会永久占住配额 |
| 尝试加锁 | 互斥锁 TryLock / select 模拟 | 通道锁需自行用 select + default 模拟 |

取舍要点：

- **通道锁与互斥锁同样不可重入。** 同一 goroutine 二次加锁必永久阻塞，实测 200 毫秒仍未完成；这不是通道的缺陷，而是"锁"的共性。
- **限峰值不等于限总量。** 信号量约束"同时在跑"，任务数约束"总共要跑"，两者常常被混为一谈。
- **`GOMAXPROCS(-1)` 是只读调用。** 参数小于 0 时不改设置、只返回修改前的值；未显式设置过时它等于逻辑 CPU 数，所以能当资源数参考，但不能当成"设置成 CPU 数"的动作。
- **基准数字只能报数量级。** 24/76 与 19/62 是不同机器上的同一结论，答题时报"约 3 倍、互斥锁明显更快"比背死数字稳 `[经验]`。

## 答题技巧

1. **先给结构再给代码**：一句话点破"带容量的通道就是信号量，容量 1 退化成锁"，再写 Lock/Unlock，听感是理解而非背诵 `[经验]`。
2. **把"容量必须是 1"说成硬约束**，并补一句"容量 2 就互斥失效"，这是最直接的区分点 `[源码]`。
3. **性能题报实测与原因两层**：数字（约 3 倍）+ 机理（通道内部自带锁与等待队列、互斥锁有 CAS 快路径）`[实测]`。
4. **主动区分通道的两类用途**——保护共享状态 vs 表达所有权流转，把"官方推崇通道"解释成设计哲学而非性能主张 `[源码]`。
5. **工程细节别漏**：`defer` 归还配额、任务通道要 `close`、重入必死锁。这三点是面试官判断"写过生产代码"的信号 `[经验]`。

## ⚠️ 原文纠错

1. 事实核校：原文关于容量 1 实现互斥锁、限并发信号量、`GOMAXPROCS(-1)` 取逻辑 CPU 数的描述整体准确，本卡沿用并补结构 `[经验]`。
2. 补充：原文性能数字为 24/76 ns/op，本机实测 **19.48/62.00 ns/op**（12 逻辑 CPU、Go 1.26.5），同向同量级；答题应报**比值约 3 倍**而非固定数字 `[实测]`。
3. 补充：原文未提三类工程风险——**不可重入、无原生 TryLock、漏归还即永久阻塞**，这恰是通道锁在生产上的主要代价，本卡补齐 `[源码]`。
