# 1717 深挖：快速排序全流程与优化取舍

> 分类：排序算法 | 难度：高 | 题型：深挖 | 频率：高 | 关键词：**分治、partition、复杂度推导、优化矩阵、工程排序**
> 原文锚点：第 1~105 段「快排实现全链路」

## 思路与架构
把「一次快排」串成一条链：
1. **思想层**：分治——选基准、分区、递归，每轮让一个元素归位。
2. **实现层**：递归三参数 (数组/low/high) + 终止条件 low<high + partition 返回基准下标。
3. **核心层**：partition 双指针扫描、错序交换、基准归位，是整张卡的枢纽。
4. **分析层**：平均 O(n log n)（主定理）、最差 O(n²)（基准取极值）、空间 原地 O(1)+栈 O(log n)~O(n)、不稳定。
5. **优化层**：随机/三数取中防退化、小数组插排降常数、三向切分治重复、尾递归/显式栈控栈。
6. **工程层**：Go 标准库 sort 综合上述策略，是「理论→生产」的范例。

## 方案取舍
- **基准取法**：首元素最简但遇有序数组直接 O(n²)；随机化期望 O(n log n) 但多一次交换；三数取中确定性强、代价是额外比较——生产多用后者或 introsort。
- **partition 实现**：双指针(Hoare) 交换少更快但边界易错；Lomuto 好写但略多交换——面试优先选能讲清不变量的。
- **递归 vs 非递归**：递归代码短但受系统栈深限制；非递归用显式栈可控，适合超大数据。
- **何时切插入排序**：小数组（如 ≤10~20）插入排序常数更小，避免递归边际开销。

## 答题技巧
- 答「快排怎么写」用**四段法**：思想→递归骨架→partition→复杂度，逐段对应一个得分点。
- 必点「最差 O(n²) 的触发条件是基准取极值」，并顺势引出随机化——这是区分 P6/P7 的关键。
- 被追问稳定性时，直接说「分区交换跨距移动相等元素→不稳定」，并对比归并/插入稳定。
- 收尾补一句「Go 标准库 sort 用了三数取中等优化」，展示工程视野，避免被追问时只停在教科书。

## ⚠️ 原文纠错
1. 事实核校： [经验] 分治三步走、递归三参数、partition 双指针、平均 O(n log n)/最差 O(n²)、空间与不稳定、各项优化与标准库实践——均为架构性归纳，与算法事实一致。
2. 崩坏词归一：源码将 Go / 数组 / 主定理 / 尾递归 / O(1)/O(n)/O(log n) 音译为崩坏词；本卡统一为规范术语与记号。最差复杂度源稿误作「log 方」，本卡订正为 O(n²)。
