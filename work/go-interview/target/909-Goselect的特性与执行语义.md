# 909 Go select 的特性与执行语义

> 分类：Go/并发 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**随机执行**/**case收发**/**无表达式**/**永久阻塞**/**default不阻塞**
> 原文锚点：第 27~50 段「select后无表达式/case须跟channel收发/多就绪随机选(非顺序)/无分支永久阻塞/有default不阻塞但循环耗性能」

## 一句话总述
select 与 switch 形似但关键点不同：**select 后不能跟表达式**、每个 case 后必须跟一个 channel 收发操作、**多个 case 同时就绪时随机选一个执行（非从上到下）**、不含任何分支的 select 使协程**永久阻塞**、有 `default` 则不阻塞但 default 会持续循环执行影响性能。

## 面试官视角
- 考察意图：能否列举 select 与 switch 的关键差异，尤其「多就绪随机」这一易错点。
- 分档：P5 知 case 跟 channel 收发；P6 能说多就绪随机、空 select 永久阻塞；P7 知 default 性能代价、随机的公平性实现。
- 红旗答案：认为多个就绪按书写顺序执行；在 select 后写表达式（只允许在 case 里）。
- 惊艳点：点出「随机是为防饥饿、保证多 case 公平」，以及「default 不阻塞但空转、高并发慎用」 [经验]。

## 主问答
**Q（面试官原话）：** select 和 switch 有什么不同？多个 case 就绪怎么选？
**A：**
1. **语法差异**：select 后**不能跟表达式**（switch 可以）；每个 case 后必须跟一个 channel 收发操作 [经验]。
2. **多就绪随机**：多个 case 同时就绪时**随机选一个**执行，而非从上到下顺序——这是与 switch 最大区别 [经验]。
3. **阻塞语义**：不含任何分支的 select 使当前协程**永久阻塞**；有 `default` 则不阻塞，但 default 会持续循环执行、空转耗性能 [经验]。

select 的「随机 + 阻塞」语义是并发题高频坑。面试常追问「如何实现公平轮询」（自行加随机或轮询 state）、「select 超时怎么写」（`case <-time.After`）。

## ⚠️ 原文纠错
1. 事实核校： [经验] 后无表达式、case 须收发、多就绪随机、空 select 永久阻塞、default 空转——均正确。
2. 崩坏词归一：源码将若干术语音译为崩坏词，本卡统一为规范术语（select、case、通道、收发、协程、随机等）。

```go
// 多 case 就绪 → 随机执行（非顺序），演示：关闭的 channel 读写都「就绪」
func demoRandomSelect() {
    ch := make(chan int)
    close(ch) // 关闭后：读立即返回零值(就绪)、写 panic(就绪)
    for i := 0; i < 4; i++ {
        // 两个 case 都就绪，每次随机选一个；写分支会 panic
        select {
        case v := <-ch:
            fmt.Println("recv", v) // 随机命中读
        case ch <- 1:
            fmt.Println("send") // 随机命中写 → panic（向已关闭 channel 写）
        }
    }
}
// 空 select：永久阻塞当前 goroutine（编译期转 block 调用，让出 CPU）
//   select {}  // 比 for {} 更优：不空转耗 CPU
```
