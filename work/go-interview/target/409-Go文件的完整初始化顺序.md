# 409 Go 文件的完整初始化顺序

> 分类：Go 基础 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**常量与变量**/**包级变量**/**init**/**main**/**初始化链**

> 原文锚点：第 75~80 段「go 文件初始化顺序与说明」

## 一句话总述
单个包的初始化链路是：**先初始化它导入的包 → 再初始化本包的常量与包级变量 → 再执行本包的 init**；所有包的 init 全部执行完毕后，才轮到 main 包的 init 与 main 函数。

## 面试官视角
这题最容易答歪。很多人把「本包变量」排到「被导入包的 init」之前，正好说反。判据很简单：**被导入包必须先完整就绪，导入方才能用它来初始化自己的变量**——按这个因果推就不会错。

## 主问答
**Q（面试官原话）：** 一个 Go 文件从加载到运行，初始化顺序是什么？

1. **先处理导入包**：首先初始化当前文件导入的包，被导入包会**完整走完**「变量 → init」这一整套流程。
2. **再初始化本包变量**：被导入包就绪后，才初始化当前包的常量与包级变量；若变量初始化依赖了某个导入包的导出值，此时该值必然已就绪。
3. **再执行本包 init**：本包变量就绪后，按「同文件按定义序、跨文件按文件名序」执行本包的全部 init。
4. **main 包最后**：main 包也是普通包，同样遵循上述顺序，只是它排在依赖链的末端。
5. **全部完成后才 main**：所有 init 函数执行结束之后，才会执行 main 函数——这是 init 能做启动前置逻辑的原因。

## 关键代码
```go
package main

import "fmt"

const C = "const"          // 常量最先
var V = initVar()          // 其次：包级变量

func initVar() string { fmt.Println("变量初始化"); return "var" }

func init() { fmt.Println("init:", C, V) } // 再次：init

func main() { fmt.Println("main") }        // 最后：main
// 输出：变量初始化 → init: const var → main
```

## 总结与追问预判
核心：**导入包 → 本包常量变量 → 本包 init → main**。追问常拐向「包级变量初始化时能不能用导入包的值」，备好「可以，因为被导入包此时已完整初始化」这句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文描述为「先初始化引入的包 → 再初始化当前包的常量和变量 → 再初始化引入包里面的 init → 最后执行 main」——**顺序有误**。被导入包的 init 发生在**导入方变量初始化之前**，准确链路是「被导入包：常量/变量 → init；然后本包：常量/变量 → init；全部包完成后 → main」。
2. 事实核校： [经验] 原文强调「所有 init 执行结束之后才执行 main 函数」——正确，这正是 init 适合放启动前置逻辑的根本原因。
3. 崩坏词归一：源码将 init / 变量 / main / go 文件 等音译为多组崩坏词，本卡统一为规范术语。
