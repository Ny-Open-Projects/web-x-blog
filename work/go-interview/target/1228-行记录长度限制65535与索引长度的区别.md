# 1228 行记录长度限制（65535）与索引长度的区别

> 分类：MySQL 存储 / 限制 | 难度：L3 | 题型：概念题 | 频率：中 | 关键词：**65535 字节** / **排除 text/blob** / **行长度 vs 索引长度** / **字符集**
> 原文锚点：第 42~45 段「行记录总长限制 65535 字节（不含 text/blob，只算长度信息与 NULL 标志等元信息）；加索引前要注意版本/字符集/行格式对索引最大长度的影响」

## 一句话总述
MySQL 单行记录**所有字段数据总长 ≤ 65535 字节**，但 **TEXT/BLOB 不计入**——只算它们的长度信息与 NULL 标志等元信息。这是"行长度限制"，与"索引长度限制（767/3072）"是两回事：前者是整行上限、后者是单索引字节上限；加索引前必须同时考量 MySQL 版本、字符集、行格式，因为它们共同决定索引最大长度。

## 面试官视角
- 考察意图：能否区分"行长度 65535"与"索引长度 767/3072"两个独立限制
- P5 知行有 65535 限制；P6 能讲 TEXT/BLOB 不计入、只算元信息；P7 能讲清"行限制 vs 索引限制是两回事、加索引要额外看版本/字符集/行格式"
- 红旗：把 65535 行限制和 767 索引限制混为一谈；以为 TEXT/BLOB 占满行长度
- 惊艳点：点出"TEXT/BLOB 只记 9~12 字节元信息（长度+NULL标志+溢出指针），实体数据在溢出页，不占行内 65535 配额" [源码]

## 主问答
**Q（面试官原话）：** MySQL 一行最多能存多少？和索引长度限制什么关系？
**A：**
1. **行长度上限 65535**：所有字段数据字节总和 ≤ 65535；**TEXT/BLOB 不计入**——只记长度信息、NULL 标志、溢出页指针等元信息（约 9~12 字节），实体在溢出页 [源码]。
2. **两个限制独立**：行长度限制（整行 ≤65535）与索引长度限制（单索引 ≤767/3072）是**不同维度**——即便行没超 65535，单索引仍可能因字符集/行格式超 767/3072 而建不了 [源码]。
3. **加索引三看**：版本（5.6 易 767）、字符集（UTF8MB4 4 字节放大）、行格式（dynamic 才 3072）——三者共同决定单索引上限 [边界]。

## 关键代码
```sql
-- 行总长受 65535 限制（TEXT/BLOB 只记元信息，不占此配额）
CREATE TABLE t (a VARCHAR(10000), b VARCHAR(10000), c VARCHAR(10000)) CHARSET=utf8mb4;
-- 但单索引仍受 767/3072 限制，与行是否超 65535 无关
-- CREATE TABLE t2 (a VARCHAR(2000), KEY(a)) CHARSET=utf8mb4; -- 2000*4=8000>3072 ERROR
```

- 行限制 65535（TEXT/BLOB 只算元信息）≠ 索引限制 767/3072；加索引要看版本/字符集/行格式。
