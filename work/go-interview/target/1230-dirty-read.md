# 1230 脏读：读到从未真正存在过的数据

> 分类：MySQL 事务 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**脏读**/**未提交**/**回滚**/**读未提交**/**最严重**

> 原文锚点：第 1~17 段「脏读定义与并发问题」、第 37~61 段「读未提交下的脏读演示」

## 一句话总述
**脏读**指一个事务读到了另一个**尚未提交**的事务修改过的数据；若对方随后回滚，本事务就等于基于一个「从未真正存在过的值」继续操作。它是三类并发问题中最严重的一类，把隔离级别提到**读已提交**即可避免。

## 面试官视角
考官要的是「为什么脏读最严重」——因为脏数据可能根本没落库，在此基础上做的任何更新都是错的。能举出「读到的值回滚后变回去」的演示过程，并给出解法（读已提交），这题就完整了。

## 主问答
**Q（面试官原话）：** 什么是脏读？怎么解决？

1. **定义**：一个事务读到了另一个未提交事务修改过的数据，这些数据随时可能被回滚。
2. **演示过程**：事务 A 把字段从 1 改成 2 但未提交；事务 B 读到 2；A 回滚后字段回到 1，B 再查又变回 1——B 中间读到的 2 就是脏数据。
3. **连锁危害**：B 若在脏数据基础上做加一再更新，最终值取决于 A 何时回滚，结果不可预测。
4. **严重性最高**：三类并发问题中脏读最严重，其次是不可重复读，幻读相对影响最小。
5. **解法**：把隔离级别提升到**读已提交**及以上，未提交的修改对其它事务不可见。

## 关键代码
```sql
-- 终端 A：修改但不提交
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
START TRANSACTION;
UPDATE t SET a = a + 1 WHERE id = 1;   -- 未提交

-- 终端 B：此时能读到未提交的 2（脏读）
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
START TRANSACTION;
SELECT a FROM t WHERE id = 1;          -- 读到 2

-- 回到 A 执行 ROLLBACK，B 再查又变回 1
```

## 总结与追问预判
核心：**脏读 = 读到会消失的数据，读已提交即可解决**。追问常拐向「脏写/丢失修改」，备好「一个事务覆盖另一未提交事务的写入，任何隔离级别都不允许」这句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文演示中把锁等待超时从默认 50 秒调成 1 小时以便观察——`innodb_lock_wait_timeout` 默认确为 **50 秒**，数值正确；但生产不应调大，否则会长时间占用连接。
2. 事实核校： [经验] 原文用系统表查看运行中事务——准确表名为 `information_schema.INNODB_TRX`，本卡给出规范表名。
3. 事实核校： [经验] 原文在演示中提到「脏读之外还可能出现丢失修改」——补充准确名称：**脏写**（一个事务覆盖另一个未提交事务的写入），InnoDB 在任何隔离级别下都会通过行锁阻止。
4. 崩坏词归一：源码将事务 / 脏读 / 隔离级别 / 回滚 等音译为多组崩坏词，本卡统一为规范术语。
