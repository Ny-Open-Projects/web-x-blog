# 1012 自旋锁 vs 互斥锁：忙等还是睡眠

> 分类：Go / 并发 / 锁 | 难度：L3 | 题型：对比题 | 频率：中 | 关键词：**忙等待** / **线程切换开销** / **CPU 浪费** / **短临界区** / **高竞争**
> 原文锚点：第 1~5 段「自旋锁等待时不睡眠、循环尝试；锁持有短则优于其他锁(免切换开销)，锁长或竞争频则浪费 CPU；适合极短持有场景」

## 一句话总述
自旋锁与互斥锁的核心区别在**等待方式**：自旋锁拿不到锁时**忙等**（循环重试、不睡眠、占 CPU），互斥锁拿不到则**睡眠**（让出 CPU、被唤醒）。因此**临界区极短**时自旋锁免去线程切换开销、性能更优；**临界区长或竞争激烈**时自旋空转浪费 CPU，反不如互斥锁。

## 面试官视角
- 意图：能否在"等待成本"维度讲清两者取舍，而非只会调 Lock。
- P5 知自旋不睡眠、互斥会睡眠；P6 知短临界区自旋优、长临界区自旋浪费；P7 知"自旋本质是用 CPU 换延迟、竞争高时崩"。
- 红旗：以为自旋锁永远更快；或以为自旋锁不会占 CPU。
- 惊艳点：点出"Go runtime 的 M 也是自旋找 G，与用户自旋锁同源——都是用短促忙等换低延迟" `[边界]` 见 815-m-spin-locks-blocked（runtime M 自旋）、925-mutex-impl（Mutex 休眠实现）。

## 主问答
**Q（面试官原话）：** 自旋锁和互斥锁有什么区别，怎么选？
**A：**
1. **等待方式**：自旋锁拿不到锁→循环忙等（不睡眠、占 CPU）；互斥锁拿不到→睡眠让出 CPU，被唤醒再抢。
2. **性能拐点**：临界区**极短**时，自旋省去线程切换/调度开销，优于互斥锁；临界区**长**或**竞争频繁**时，自旋线程一直空转占 CPU，反而浪费、不如互斥锁。
3. **适用**：自旋锁只适合"锁持有时间非常短"的场景；不确定持有时间一律用互斥锁/读写锁更稳。

## 关键代码
```go
// 示意：自旋 vs 互斥的选择信号（未做端到端验证）
// 极短临界区：自旋锁（忙等，免切换）
func shortCritical(l *SpinLock, v *int32) {
    l.Lock(); *v++; l.Unlock()
}
// 不确定持有时间：互斥锁（拿不到睡眠，不空耗 CPU）
func uncertain(m *sync.Mutex, v *int) {
    m.Lock(); doWork(); m.Unlock()
}
```

## 总结与追问预判
- 自旋=忙等省切换（短临界区优），互斥=睡眠让 CPU（长/竞争稳）。
- 预判：自旋锁实现 → 见 1012-spinlock-impl；Mutex 实现 → 见 925-mutex-impl；runtime 自旋 → 见 815-m-spin-locks-blocked。
