# 808 删除写屏障：起点快照保命

> 分类：Go 运行时 | 难度：L3 | 题型：原理题 | 频率：中高 | 关键词：**删除屏障、起始快照、Yuasa、浮动垃圾、回收精度**

> 原文锚点：第 65~90 段「当白色或灰色对象的引用被移除时，该对象标记为灰色…回收精度比较低」

## 一句话总述
删除屏障在指针被删除或覆盖时，把**即将失去引用的原对象染灰**，保证 GC 开始那一刻存活的对象这一轮不会被回收，从而满足弱三色不变式，又称**起始快照**。

## 面试官视角
P6 能说"删引用就把被删的对象染灰"；P7 会补代价：这是**保守**做法——本轮确已无人引用的对象也要活到下一轮，形成**浮动垃圾**，回收精度下降；换来的是不必担心漏标，且只需一次极短 STW 记录快照 `[经验]`。

## 主问答
**Q（面试官原话）：** 删除屏障又是怎么保证不丢对象的？

1. **规则**：当白色或灰色对象的某个指针字段被移除或被覆盖时，把**原来指向的那个对象**标记为灰色 `[经验]`。
2. **语义**：它保护的是"灰色到下游的路径不会断"，等价于维持 GC 开始那一刻的引用快照，因此称起始快照，对应弱三色不变式。
3. **例子**：原文演示删除灰色对象到白色对象的引用时，白色的下游对象立刻被染灰，随后继续正常标记；若无这一步，它及其下游会被误回收 `[实测]`。
4. **代价**：被删引用的对象哪怕真的没人引用，本轮也一定存活，只能等下一轮回收，**浮动垃圾**变多、堆占用偏高 `[经验]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Go 1.5 起 | 理论引入 | 删除屏障保守、精度低但保证存活 |
| Go 1.8 起 | 混合写屏障 | 不再单独使用，其性质用于豁免栈重扫 |

## 关键代码
```go
// 语义示意：覆盖或清空前先保护旧值
func heapWrite(slot *unsafe.Pointer, newobj unsafe.Pointer) {
    old := *slot
    if old != nil {
        shade(old)      // 删除屏障：旧的下游对象先染灰
    }
    *slot = newobj
}
```

## 总结与追问预判
**保护旧值 = 保守但安全**，代价是浮动垃圾；插入屏障保护新值，代价是要重扫栈。两者互补，引出 Go 1.8 的混合写屏障（见 808-hybrid-barrier）。

## ⚠️ 原文纠错
1. 事实核校：原文"删除或上游替换引用时把该对象染灰、对应弱三色不变式"表述正确，但需明确被染灰的是**原来被引用的下游对象**，而非被删引用的父对象，本卡已澄清 `[经验]`。
2. 补充：原文"GC 开始时要 STW 记录快照"准确——这轮快照内的存活对象本轮都不会被回收，这正是浮动垃圾的来源 `[源码]`。
3. 崩坏词归一：源码将 Go、对象、引用等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
