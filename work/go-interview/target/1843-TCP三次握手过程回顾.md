# 1843 TCP 三次握手过程回顾

> 分类：网络/TCP | 难度：L3 | 题型：流程题 | 频率：高 | 关键词：**三次握手**/**SYN**/**SYN+ACK**/**ESTABLISHED**/**同步初始序号**
> 原文锚点：第 1~22 段「客户端SYN(初始序x,SYN_SENT)→服务端SYN+ACK(初始序y,确认x+1,SYN_RECV)→客户端ACK(确认y+1,ESTABLISHED)→服务端ESTABLISHED」

## 一句话总述
TCP 建立连接靠**三次握手**：① 客户端发 `SYN`（初始序号 x，状态 SYN_SENT）；② 服务端回 `SYN+ACK`（自身初始序号 y、确认号 x+1，状态 SYN_RECV）；③ 客户端回 `ACK`（确认号 y+1，状态 ESTABLISHED），服务端收到也进入 ESTABLISHED。三次握手让双方**同步初始序列号**、确认双向收发能力。

## 面试官视角
- 考察意图：能否完整说出三次握手的报文序列与状态迁移，并解释「为什么是三次」。
- 分档：P5 知 SYN/SYN+ACK/ACK；P6 能说状态与序号；P7 知同步序号意义、两次 SYN 各自目的。
- 红旗答案：把第二次握手说成只 ACK（漏了服务端的 SYN）；忽略确认号 = 对方序号 +1。
- 惊艳点：点出「第二次握手的 SYN+ACK 里 ACK 是对客户端 SYN 的确认、SYN 是服务端发起连接」，以及「序号同步防止旧报文干扰」 [经验]。

## 主问答
**Q（面试官原话）：** TCP 三次握手具体过程？
**A：**
1. **第一次（SYN）**：客户端发 SYN（初始序号 x），进入 SYN_SENT，表示希望建连并通告自己的 ISN [经验]。
2. **第二次（SYN+ACK）**：服务端回 SYN+ACK（自身 ISN=y、确认号=x+1），进入 SYN_RECV——ACK 确认客户端 SYN、SYN 发起服务端连接 [经验]。
3. **第三次（ACK）**：客户端回 ACK（确认号=y+1），进入 ESTABLISHED；服务端收到也 ESTABLISHED，双方同步序号、确认双向可达 [经验]。

## 关键代码

```go
// TCP 三次握手（状态迁移示意）
const (
    SYN_SENT = iota // 客户端发 SYN 后
    SYN_RECV        // 服务端回 SYN+ACK 后
    ESTABLISHED     // 双方收到 ACK 后
)
// 客户端: 发 SYN(ISN=x) → 收 SYN+ACK(确认 x+1) → 发 ACK(确认 y+1) → ESTABLISHED
// 服务端: 收 SYN → 发 SYN+ACK(ISN=y, 确认 x+1) → 收 ACK(确认 y+1) → ESTABLISHED
// 关键：第二次握手中的 ACK 确认客户端 SYN，SYN 是服务端发起自己的连接
// 序号同步（ISN）用于去重旧报文、保证字节流有序
```

## 总结与追问预判
三次握手的核心是「双方各发一次 SYN 并各收到一次 ACK」。面试常追问「两次行不行」（不行，服务端无法确认客户端能收）、「SYN Flood 攻击」（半连接队列耗尽）。
