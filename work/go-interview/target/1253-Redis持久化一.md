# 1253 Redis 持久化（一）：RDB 快照

> 分类：Redis | 难度：中 | 题型：原理 | 频率：高 | 关键词：**RDB、快照、BGSAVE、写时复制、全量备份**

> 原文锚点：第 4~30 段「RDB 快照原理、save 触发条件、BGSAVE 子进程、写时复制、优缺点」

## 一句话总述
RDB 是 Redis 将「某一时刻内存中的全量数据」以二进制压缩文件落盘的全量快照。触发条件由 save 配置（如 900 秒 1 次改 / 300 秒 10 次 / 60 秒 1 万次，满足其一即触发）；实际执行的是 BGSAVE——fork 子进程在后台做，不阻塞主线程。恢复时直接加载 RDB，速度快。

## 面试官视角
RDB 是 Redis 基础题。考官看你能说清：① RDB 是「全量快照」非增量；② 触发靠 save 配置、执行靠 BGSAVE（fork 子进程）；③ 父子进程靠「写时复制（COW）」共享内存、改时才复制页，故不会双倍占内存；④ 优点紧凑快恢复，缺点两次快照间数据可能丢失。

## 主问答
**Q（面试官原话）：** RDB 持久化是什么？怎么触发的？

1. **本质**：某时间点的内存全量数据快照，二进制压缩文件，适合备份/迁移/灾难恢复。
2. **触发**：save 配置满足条件即触发（默认 save 900 1 / 300 10 / 60 10000）；关闭则把 save 置空。注意执行的是 BGSAVE 而非同步的 SAVE。
3. **执行方式**：BGSAVE 调用 fork 创建子进程，由子进程写 RDB；主线程继续服务，几乎不阻塞。
4. **写时复制**：fork 后父子虚拟内存指向同一物理内存；父进程改数据时，内核以 4KB 内存页为单位复制该页（COW），避免整体复制，故不会内存翻倍。

```bash
save 900 1
save 300 10
save 60 10000
```
