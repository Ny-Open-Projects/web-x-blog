# 1112 降低值复制成本优化性能（深挖）

> 分类：Go/性能 | 难度：L3 | 题型：综合题 | 频率：中 | 关键词：**值复制优化** / **尺寸体系** / **指针取舍** / **for-range 陷阱**
> 原文锚点：第 1~63 段「值尺寸体系；直接值部复制；大 struct/array 用指针(slice等不用)；零尺寸值；for-range 双变量复制陷阱与基准」

## 一句话总述
降值复制成本是一条"先看尺寸、再定取舍、最后验证"的链路：用 `unsafe.Sizeof` 建立值尺寸认知 → 大 struct/array 用指针（权衡 GC 压力）、header 类用值传递 → for-range 大元素避双变量 → 全部用 benchmark 量化。与 923/508 互补（923 讲传值机制、508 讲字段拷贝，本卡讲尺寸体系与全局优化决策）。

## 思路与架构
- **认知层（值尺寸体系）**：各类型直接值部固定（基础类型）/动态（struct=字段和+padding、array=元素×长）；零尺寸值占 0。这是判断"复制贵不贵"的前提。
- **决策层（指针取舍）**：大值类型用指针省复制，但指针增 GC 压力；slice/map/chan/func/string/interface 只复制 header（间接值部共享），不用指针。
- **陷阱层（for-range）**：大元素双变量每次复制，单变量+s[i] 或 for 下标规避；小元素可忽略。
- **验证层**：用 `go test -bench` 量化，不凭直觉。

## 方案取舍
- **为何 header 类不用指针**：复制只十余字节、底层共享，加指针反而增 GC 扫描/回收压力，得不偿失。
- **为何大 struct 用指针**：直接值部可能 KB 级，每次传参/通道发送都全量复制，指针把复制降到 8B，代价是 GC 多追踪一个对象——高频小对象需权衡。
- **与既有卡边界**：923-slice-pass-by-value / 923-map-pass-by-value 讲"传值只复制 header"机制，508-struct-copy-field 讲结构体字段拷贝，本卡在二者之上补"尺寸体系 + 优化决策 + for-range 陷阱"，角度互补。

## 答题技巧
1. **先报尺寸**：开口用 unsafe.Sizeof 表建立"复制多少"的量化认知。
2. **给决策**：大 struct/array→指针（权衡 GC）；slice/map 等→值传递；零尺寸值→白嫖。
3. **点陷阱**：for-range 大元素避双变量，用 bench 验证。
4. **关联延展**：提 923（传值机制）、508（字段拷贝），显示体系化。
