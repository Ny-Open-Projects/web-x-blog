# 420 Go 值内存布局全景（深卡）

> 分类：Go 语言基础 · 内存布局 | 难度：L3 | 题型：综合题 | 频率：中 | 关键词：**直接值部/间接值部**/**单内存块分类**/**栈堆逃逸**/**地址随栈伸缩变化**
> 原文锚点：第 7~68 段「内存块概念、直接/间接值部分类、单块类型清单、栈堆分配与逃逸、地址随栈伸缩变化」

## 思路与架构
本卡把"Go 值在内存里怎么摆"串成一条主线：**值部 → 内存块 → 单块/多块分类 → 栈堆落点 → 地址稳定性**。

- **值部与内存块**：值部是类型值在某内存块上的部分；内存块是承载若干值部的连续内存片段。一个值可跨多个块。
- **两类值部**：直接值部（落在一个块）、间接值部（被直接值部引用、在另一块）。
- **分类**：单块类型 = 直接值部类型（bool/数值/指针/struct/array）；多块类型 = 含间接值部的 6 类（slice/map/chan/func/interface/string）。
- **落点**：编译器决定栈或堆——不能确定只被一个 goroutine 用时放堆（保守安全）；栈上快、不需 GC、缓存友好；逃逸时栈留隐式指针指向堆。
- **地址**：栈伸缩时内存块搬迁、地址变、指针刷新；堆地址相对稳。

## 方案取舍
| 维度 | 单块类型 | 多块类型 |
| --- | --- | --- |
| 复制代价 | 整体搬走，随尺寸变（struct/array 动态） | 只拷 header（固定小），共享底层 |
| 共享风险 | 无（整块独立） | 间接值部共享，改底层互相可见 |
| 判定法则 | 不含间接引用 | 含指针/header |

**取舍结论**：面试答"哪些类型单块"用 5 类清单 + "看是否含间接引用"法则；解释切片/map 传参表现差异统一归到"直接部分独立、间接部分共享"（见 923）。栈堆取舍：小且生命周期明确留栈省 GC，大/逃逸对象只能堆 `[经验]`。

## 答题技巧
- 被问"哪些类型只占一个内存块"：先给 5 类（bool/数值/指针/struct/array），立刻补判定法则"是否含间接引用"，再点"指针值单块但所指多块"防坑。
- 被问"为什么地址变了"：归因"栈伸缩搬迁 + 指针刷新"，不是 GC 移动；用源码 int 两次取地址不同的例子佐证。

  - 传参拷贝模型见 923、值尺寸/零尺寸值见 1112、栈堆分工与上限见 1118、逃逸分析命令见 1118。本卡仅做整合，不重复其内部论证。

## 细节与核心 API

```go
type Bad struct { a bool; b int64; c bool } // 24 字节（bool 各占 8 对齐）
type Good struct { b int64; a bool; c bool } // 16 字节（bool 紧邻）
fmt.Println(unsafe.Sizeof(Bad{}), unsafe.Sizeof(Good{}))  // 24 16
fmt.Println(unsafe.Offsetof(Good{}.b))                    // 0
// 对齐规则：字段偏移 = 上一个结束按自身对齐系数向上取整；整体大小按最大字段对齐
// 零尺寸类型（struct{}/[0]byte）在内存中有唯一地址（runtime 共享一块 zerobase）
```
