# 418 整型转换溢出与常量溢出的编译期报错

> 分类：Go 数值类型 | 难度：L3 | 题型：陷阱题 | 频率：中 | 关键词：**按位重解释**/**高位截断**/**符号位丢失**/**常量编译期**/**区间判断**

> 原文锚点：第 71~87 段「常量溢出 / 类型转换溢出 / 有符号转无符号」

## 一句话总述
Go 的整型转换是**按位重新解释**：不做值域检查、也不会失败，高位直接截断——`int32` 最大值转 `int16` 得 -1，最小 `int32` 转无符号得到 2147483648；而**常量**表达式的溢出是**编译期**错误，构建时就失败。

## 面试官视角
这题考「转换」和「常量」两条规则的分野。变量转换静默截断、常量溢出直接编译失败——能把这两件事分开说清楚，并且知道转换前要自己判区间，就是合格的边界意识。

## 主问答
**Q（面试官原话）：** int32 转 int16 会报错吗？结果是什么？

1. **不会报错**：Go 的整型转换不做值域检查，也不会「失败」，只是按目标位宽截断高位后重新解释。
2. **最大值截断**：`int32` 最大值 0x7FFFFFFF 取低 16 位为 0xFFFF，按有符号解释即 **-1**。
3. **符号位丢失**：有符号转无符号时符号位变成数值位，最小 `int32` 的补码 0x80000000 按无符号解释是 **2147483648**，不再是负数。
4. **常量在编译期报错**：常量表达式在编译阶段求值，一旦溢出直接编译失败，源码行号即时报出，不会等到运行。
5. **转换前须判区间**：变量转换前要判断是否落在目标类型的最小值与最大值之间，超出就走错误处理分支。

## 关键代码
```go
package main

import (
	"errors"
	"fmt"
	"math"
)

func toInt16(x int32) (int16, error) {
	if x < math.MinInt16 || x > math.MaxInt16 {
		return 0, errors.New("int16 overflow")
	}
	return int16(x), nil
}

func main() {
	v, err := toInt16(math.MaxInt32)
	fmt.Println(v, err) // 0 int16 overflow

	var i32 int32 = math.MaxInt32
	m32 := int32(math.MinInt32)
	// [实测] 输出：-1 与 2147483648（无符号不可能为负），转换不报错
	fmt.Println(int16(i32), uint32(m32))
}
```

核心：**变量转换静默截断，常量溢出编译期失败**。追问常拐向「位移操作要注意什么」，备好「位移位数须为非负数、超出位宽结果按规则补零或补符号位」这条（该源末段未尽，另见移位专题卡）。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称常量溢出「在运行时的阶段进行判断」——**错误**。Go 常量表达式在**编译期**求值，溢出直接导致编译失败；原文自己也指出报错出现在源码第 38 行，正是编译期行为。
2. 事实核校： [经验] 原文称 `int32` 最小值转无符号后「输出结果为负数」——无符号类型不可能为负；-2147483648 的补码为 0x80000000，按无符号解释是 **2147483648**。
3. 事实核校： [经验] 原文称「转换失败后是负一」——措辞不准：Go 的整型转换不会失败，只是高位截断后重新解释，结果为 -1 属于**预期行为**而非失败。
4. 崩坏词归一：源码将 int32 / int16 / uint32 / 溢出 等音译为多组崩坏词，本卡统一为规范术语。
