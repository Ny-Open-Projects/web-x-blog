## 思路与架构
```text
答题架构：先抛"Mutex 有两模式，本质吞吐vs公平"总纲，再分三块：
1. 正常模式行为：FIFO排队 + 唤醒者与新请求竞争(新请求占优) + 连续获取高吞吐
2. 饥饿模式行为：handoff直交队首 + 新来者入尾不抢 + 公平保先等者
3. 切换：等>1ms 或 队剩1人 → 饥饿；平衡回正常
底层实现(state位/CAS/sema)交给 925，本波只讲可观察行为
```

## 方案取舍
```text
面试取舍：被问"两种模式区别"直接上对照表(排队/竞争/吞吐/公平)，比背实现更利落。
必提两个切换触发条件(1ms/队空)——这是区分"懂行为"和"只会背实现"的分水岭。
避免：不要重写 state/sema 位布局(那是 925 的地盘)，聚焦行为对比。
```

## 答题技巧
```text
技巧1：用一句话封口——"正常求吞吐(新请求占优)、饥饿求公平(handoff队首)，按1ms/队空切换"。
技巧2：举"新请求在CPU上缓存热度高故抢赢"解释为何正常模式新请求占优，显深度。
技巧3：收尾点 go1.9 引入饥饿模式(修复写者饿死)，显版本意识(引 925)。
```
