# 807 Go GC 流程（一）全景（深挖）

> 分类：Go/运行时 | 难度：L3 | 题型：综合题 | 频率：高 | 关键词：**GC 流程全景** / **STW 演进** / **标记清除** / **三色标记**
> 原文锚点：第 2~78 段「STW 定义与延迟；1.0→1.8 演进；标记清除三步与三问题；三色标记含义与推进；并发需写屏障」

## 一句话总述
Go GC 流程（一）串起三条线：用 STW 时长衡量 GC → 标记清除是基础算法（有三问题）→ 三色标记让标记可并发（配写屏障保正确）。面试讲 GC 时按"指标→基础算法→并发演进"递进，就能覆盖绝大多数追问。

## 思路与架构
- **指标层**：STW 是 GC 的"用户体验"指标——暂停越久延迟越大；早期秒级 STW 对实时通信不可忍。
- **算法层**：标记清除（Mark-Sweep）两阶段，致命在"整堆 STW + 碎片"；三色标记（Tri-color）把"扫整堆"改为"渐进灰集推进"，使标记可并发。
- **演进层**：1.0 秒级 STW → 1.3 标记/清除分离 → 1.5 并发三色标记（10~40ms）→ 1.8 混合写屏障（<1ms）。架构上每次优化都"把必须暂停的时间越切越短"。
- **与 runtime 层的关系**：本卡聚焦**算法流程层**；runtime 结构体里的 GC 关联字段（g 的 gcscanvalid、P 的 gc timer、debug GC）属另一层，见 813/814/815，二者互补不重复。

## 方案取舍
- **为何从标记清除走向三色标记**：标记清除必须扫整堆且全程 STW，无法支撑高性能后端；三色标记只需维护三色集合、渐进推进，标记阶段可并发，STW 从"整堆扫描"降到"根扫描+启停"。
- **为何仍需写屏障**：并发标记期间用户改引用，黑色对象新引用白色对象会被误回收（漏标），写屏障在此刻拦截并保护，是并发正确性的代价。
- **非分代非移动的取舍**：Go 选择简单可并发的三色标记而非分代，换取实现简单与低延迟，代价是长尾对象回收不如分代高效——面试可点出这是 Go 的设计取舍。

## 答题技巧
1. **开口定调**：先说"GC 我按 STW 时长讲"，立住主线。
2. **先基础后演进**：标记清除三步 + 三问题 → 三色标记含义与推进 → 1.5/1.8 里程碑。
3. **踩硬知识点**：三色含义（白/灰/黑）、1.5 并发三色、1.8 混合写屏障、Go 非分代非移动——这四点答全即 P7。
4. **主动延展**：提一句"并发标记需写屏障防漏标""runtime 层 GC 字段见 813/814/815"，显示体系化与跨卡联动。
