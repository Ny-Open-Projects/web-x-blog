# 1245 EXPLAIN 的 key_len：索引长度怎么算

> 分类：MySQL 调优 | 难度：中高 | 题型：原理 | 频率：中高 | 关键词：**key_len、索引长度、utf8mb4、NULL 标志位、变长长度字节**

> 原文锚点：第 1~25 段「key_len 定义、固定/变长类型、NULL 标志位、联合索引 1146 计算实例」

## 一句话总述
`key_len` 表示优化器决定使用某索引时**该索引记录的最大长度**（字节）。构成：固定长度类型取其固定字节数；变长类型按「字符数 × 每字符字节数」算（如 `varchar(30)` + utf8mb4 = 30×4=120）；列**可为 NULL 则 +1 字节**存 NULL 标志位；变长字段再 **+2 字节**存长度信息。注意它按字段**定义的最大长度**计算，不是实际占用。

## 面试官视角
key_len 是判断「联合索引到底用到几列」的利器。考官期待你会算：给 `varchar(30)`/`varchar(255)` + utf8mb4 + 可空，能推出 123 / 1023 / 合计 1146。能补「key_len 显示最大长度而非实际长度」说明理解到位。

## 主问答
**Q（面试官原话）：** EXPLAIN 的 key_len 是怎么计算出来的？

1. **固定长度类型**：如 `int` 占 4 字节；若该列可为 NULL，再加 1 字节 NULL 标志位 → 共 5 字节。
2. **变长类型**：按「字符数 × 字符集每字符字节数」计算，如 `varchar(30)` 配 utf8mb4（每字符 4 字节）= 120；再加 2 字节存长度信息、1 字节 NULL 标志位 → 123。
3. **联合索引累加**：`varchar(30)` → 120+2+1 = 123；`varchar(255)` → 1020+2+1 = 1023；两者相加 = **1146**，即为用到了 a、b 两列。
4. **关键细节**：key_len 显示的是**可用到的最大索引长度**（按字段定义最大长度算），并非实际数据占用长度。

## 关键代码
```sql
-- a varchar(30)、b varchar(255)，utf8mb4，均可空
-- key_len = (30*4+2+1) + (255*4+2+1) = 123 + 1023 = 1146
```

## 总结与追问预判
核心：**key_len = 列字节数 +（变长 +2）+（可空 +1），按定义最大长度算，可反推联合索引用到几列**。追问常接「ref/rows 怎么看」（见 1245-ref-rows）。
