# 1246 优化二：id 游标法跳过已读区间（含不等价说明）

> 分类：数据库 / MySQL 索引 | 难度：L4 | 题型：优化题 | 频率：高 | 关键词：**游标法、书签、主键范围扫描、LIMIT offset 替代、ID 不连续**

> 原文锚点：第 24~31 段「我们可以通过 ID 去缩小它的查询范围…增加一个查询条件 id 大于一百万，再通过 ID 进行排序，然后再取前十条…这个查询语句跟下面这个查询语句是等价的…结果是一百万零一到一百万零一十，而下面是一百万零三到一百万零一十二，还是有一些区别…因为前面删除了两条数据，ID 发生了断层…如果需要查全表的数据或者分页去获取表里面所有的数据，上面这个优化的查询还是有很多使用场景的」

## 一句话总述
用上一页的最大 id 作为游标，改写成 `WHERE id > last_id ORDER BY id LIMIT n`，让查询**直接落在主键区间上**，不再扫描和丢弃前百万行；需注意它与原 `LIMIT offset` **并不完全等价**。

## 面试官视角
P6 会写 `LIMIT offset, n`；P7 要能提出**游标法（书签法）**并主动说明它的两个前提：**必须有稳定有序的唯一键**（通常主键）与**它与 offset 分页不等价**（数据有间隙时结果会错位），以及它最适合的场景是**顺序遍历全表**而非「任意跳页」。

## 主问答
**Q（面试官原话）：** 千万级表要分页遍历全量数据，你怎么写？

1. **缩小范围的做法**：增加一个条件 `id > 上一页最大 id`，再按 id 排序取前若干条 `[源码]`。
2. **为什么快**：条件直接命中**主键索引区间**，无需扫描并丢弃前 offset 行 `[经验]`。
3. **与 offset 的关系**：这种写法与 `LIMIT 1000000,10` **大体等价** `[源码]`。
4. **但结果有差异**：示例中原查询返回 **1000003~1000012**，游标法返回 **1000001~1000010** `[源码]`。
5. **差异根因**：表中**删除过数据导致 id 出现断层（不连续）**，offset 是按「行序」数，游标法是按「id 值」切 `[源码]`。
6. **因此不等价**：两者并不完全等价，使用时要接受这一语义差异 `[源码]`。
7. **适用场景**：需要**查询全量数据或分页遍历整张表**时，游标法有大量可用场景 `[源码]`。
8. **不适用**：需要**任意跳页**（直接翻到第 N 页）时，游标法无法直接定位 `[经验]`。

## 关键代码
```sql
-- 原写法：扫描并丢弃前 1000000 行（id 有断层时返回 1000003~1000012）
SELECT * FROM userbig WHERE name LIKE 'name%' ORDER BY id LIMIT 1000000, 10;

-- 游标法：直接落在主键区间（返回 1000001~1000010）
SELECT * FROM userbig WHERE id > 1000000 ORDER BY id LIMIT 10;

-- 遍历全表的典型写法：每页取上一页最大 id 作为下一页起点
-- 第 1 页
SELECT * FROM userbig ORDER BY id LIMIT 10;            -- 记下 last_id
-- 第 2 页起
SELECT * FROM userbig WHERE id > {last_id} ORDER BY id LIMIT 10;
```

## 总结与追问预判
**游标法是遍历全表的最优解，但换不来「任意跳页」**。答题时务必主动说「它与 offset 分页不等价，因为 id 可能有断层」——这句话体现你理解了两种分页的语义差别，而不是只会套优化套路。Go 侧遍历实现见同批 1246-go-count-total。

## ⚠️ 原文纠错
1. 事实核校：用 id 缩小范围、按 id 排序取前 N 条、与 offset 大体等价但结果有差异、差异源于删除造成的 id 断层、适合遍历全表——均与 MySQL 行为一致 `[经验]`。
2. 补充：原文称两者「等价」应修正为**在数据无删除、id 严格连续时才等价**；一旦存在删除或事务回滚造成的空洞，两者结果必然错位，这是使用游标法必须向业务方确认的语义前提 `[经验]`。
3. 崩坏词归一：源码将主键、分页、排序、断层等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
