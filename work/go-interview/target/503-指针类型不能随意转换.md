# 503 指针类型不能随意转换

> 分类：语法 | 难度：L2 | 题型：对比题 | 频率：中 | 关键词：**底层类型** / **具名类型** / **隐式转换**
> 原文锚点：第 76~108 段「第二个限制就是一个指针类型的值不能随意被转化为另一个…底层类型一致且至少一个无名类型」

## 一句话总述
Go 指针类型转换受规范约束：两指针底层类型一致、且至少有一个是"无名类型"才能隐式互转；否则必须走 `unsafe.Pointer`，不能随便把 `*int32` 当 `*MyInt` 用。

## 面试官视角
- 意图：是否真懂 Go 类型系统里的"具名/无名"与底层类型规则，而非凭感觉。
- P5 知不能随便转 / P6 能说清底层类型+无名类型条件 / P7 知为何这样设计（防误读内存）。
- 红旗：以为 `*int32` 能直接转 `*MyInt`；以为所有指针都能互转。
- 惊艳点：`*int32` 与 `*MyInt`（MyInt 底层 int32）底层类型不同，直接转换编译报错 —— 验证 `go build` `[源码]`。

## 主问答
**Q（面试官原话）：** 为什么 Go 里 `*int32` 不能直接赋值给 `*MyInt`？
**A：**
1. **结论**：转换只看"底层类型"与"是否具名"。两指针底层类型不一致时不允许直接转换。
2. **机制**：`MyInt` 是 `type MyInt int32`，它的指针 `*MyInt` 底层类型是与 `*int32` 不同的类型；只有底层一致且至少一个无名类型才可隐式转换。
3. **边界**：若两指针都无名且基类型底层一致（如 `*int32` 与它的别名）则可互转；真正跨底层类型只能经 `unsafe.Pointer`。
**加分层：** 限制是为类型安全，避免把一块内存按错误的类型语义读写。
