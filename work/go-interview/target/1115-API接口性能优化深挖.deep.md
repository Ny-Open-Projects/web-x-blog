# 1115 API 接口性能优化深挖

> 分类：性能优化 / API | 难度：L3 | 题型：深挖 | 频率：中 | 关键词：**定位优先** / **命中率反直觉** / **并行异步** / **锁粒度** / **批量扩展**
> 原文锚点：第 1~46 段「定位关键路径(1090/阿姆达尔/链路追踪)；8 方向：数据库/缓存/并行/异步/锁粒度/批量/扩展」

## 思路与架构
API 优化是"测量驱动"而非"技巧堆砌"：先用监控/链路追踪定位耗时大头（关键路径占比大者优先），再在八个杠杆上取舍。八个方向可分三层——**数据层**（数据库慢查询、缓存）、**并发层**（串行改并行、异步化解耦、锁粒度细化）、**规模层**（批量减调用、服务扩展）。回答时以"定位优先"为主线串起，避免零散罗列。

## 方案取舍
```text
八方向取舍矩阵：
──────────────────────────────────────────────────────────────
方向            杠杆层      收益点                风险/前提
数据库优化      数据层     解决最常见瓶颈        先治慢查询
缓存            数据层     减 DB 压力           算命中率；强一致/频繁改不宜
串行改并行      并发层     耗时=最慢一次        仅限无依赖调用
异步化          并发层     主请求变短           非核心逻辑；MQ 可靠性兜底
减少锁粒度      并发层     打散竞争             分段/读写分离
批量获取        规模层     减网络往返           控单次条数
服务扩展        规模层     突破单机资源        无状态；先定位瓶颈

设计法则：
- 主线：先测量定位，再按关键路径占比排优先级（1090/阿姆达尔）
- 缓存：命中率要算账，反直觉侧优先；本地缓存减远程
- 并行≠异步：并行是同请求内并发，异步是跨请求解耦
- 扩之前先确认自身 IO/计算已到瓶颈，否则白扩
```

## 答题技巧
```text
面试话术（先纪律后清单，再取舍）：
1. 纪律：先定位瓶颈（监控+链路追踪），1090 法则/阿姆达尔，不盲优化
2. 数据层：慢查询 + 缓存（算命中率、本地缓存、避强一致/频繁改）
3. 并发层：无依赖 RPC 并行(最慢一次) + 非核心异步化(MQ) + 锁粒度细化(分段/读写)
4. 规模层：批量合并(IN/mget) + 水平/垂直扩展(前提达瓶颈)
5. 收尾：八方向互补，定位优先是全局红线
```

## 细节与核心 API

**定位优先**：串行改并行（无依赖 RPC，耗时 = 最慢一次），区别于异步（跨请求解耦）：

```go
func fetchAll(ctx context.Context) (*A, *B, error) {
    var a A; var b B; var errA, errB error
    var wg sync.WaitGroup; wg.Add(2)
    go func() { defer wg.Done(); a, errA = svcA(ctx) }()
    go func() { defer wg.Done(); b, errB = svcB(ctx) }() // 同请求内并行
    wg.Wait()
    return &a, &b, errors.Join(errA, errB)
}
```

**批量减往返**（`IN`/`mget` 合并 N 次调用为 1 次）：

```go
rows, _ := db.Query("SELECT * FROM t WHERE id IN (?,?,?)", ids...)
```

**锁粒度细化**（分段锁打散竞争）：

```go
var shards [32]sync.Mutex
h := fnv32(key) % 32
shards[h].Lock(); defer shards[h].Unlock()
```

**缓存命中率要算账**：`hitRate = hit/(hit+miss)`；强一致 / 频繁改的场景不宜缓存。异步化只用于非核心逻辑（MQ 可靠性兜底），主请求变短。
