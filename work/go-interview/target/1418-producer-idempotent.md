# 1418 Kafka 幂等/事务生产者（producer 端机制）

> 分类：消息中间件 / Kafka | 难度：L3 | 题型：机制题 | 频率：中 | 关键词：**幂等生产者** / **PID 序列号** / **事务生产者** / **exactly-once** / **0.11/0.14**
> 原文锚点：第 28~35 段「producer 端幂等(0.11)/事务(0.14)；每条消息唯一标识去重；流计算支持精确一次」

## 一句话总述
Kafka producer 端内置两种去重：**幂等生产者**（0.11+，PID+序列号让 broker 单分区内去重）与**事务生产者**（0.14+，跨分区原子写+消费转换写回）；但二者只去重 producer 端，consumer 因 offset 问题仍可能重投——端到端精确一次需消费逻辑幂等配合。

## 面试官视角
- 意图：是否分清"producer 幂等"与"端到端幂等"的边界。
- 分档：P5 知幂等生产者去重；P6 知 0.11/0.14 版本；P7 能讲"仅去重发送端、消费端仍可能重复"。
- 红旗：以为幂等生产者=端到端精确一次。
- 惊艳点：点出幂等生产者只保证"同一条不重发到同一分区"，消费端 offset 滞后导致的重投它管不到。

## 主问答
**Q（面试官原话）：** Kafka 幂等生产者和事务生产者有什么区别？
**A：**
1. **幂等生产者（0.11+）**：开启后每条消息带 PID + 序列号，broker 按序列号对单分区内重复消息去重；仅解决 producer 重试导致的重发，不跨分区。
2. **事务生产者（0.14+）**：支持跨分区原子写入、以及"消费-转换-写回"的原子语义；配合流计算可实现精确一次。
3. **边界**：二者都只在 producer 端去重；consumer 因 offset 未及时提交导致的重投，producer 机制管不到——所以端到端精确一次 = producer 幂等/事务 + 消费逻辑幂等（见 1418-idempotent-consumption）。

- producer 幂等≠端到端精确一次；消费逻辑幂等才是最后一道网。
