# 1111 append 保序删除单元素

> 分类：数据结构 | 难度：L2 | 题型：代码题 | 频率：高 | 关键词：**append 拼接** / **保序** / **可读性优先**
> 原文锚点：第 52~56 段「通过 append 实现：截 [ :i] 再 append [i+1:]」；第 102~110 段基准测试 append 略快

## 一句话总述
保序删除单元素另一写法是 `a = append(a[:i], a[i+1:]...)`：保留前段、把后段追加回来；语义直观、可读性最好，底层多数复用数组，必要时才扩容 `[源码]`。

## 面试官视角
- 意图：是否懂 append 切片表达式的边界与可读性权衡。
- P5 会写 append 删除 / P6 说清切片表达式与扩容 / P7 知基准结论与选型。
- 红旗：`append(a[:i], a[i:]...)` 写成不删（漏 +1）；以为一定零分配。
- 惊艳点：原文基准（x86 平台）显示 append 删除略快于 copy、差距极小，可读性更好 —— 出自原文基准测试 `[经验]`。

## 主问答
**Q（面试官原话）：** 除了 copy，还有别的保序删除写法吗？
**A：**
1. **结论**：`a = append(a[:i], a[i+1:]...)` 把前段与后段拼接，跳过 `a[i]`，语义最直观。
2. **机制**：`a[:i]` 与 `a[i+1:]` 共享底层数组，`append` 多在原数组上写；仅当 cap 不足才新分配 `[源码]`。
3. **边界**：原文基准（x86）中 append 略快于 copy 但差距极小，二者都 O(n)；可读性优先选 append。
**加分层：** 不要为微优化牺牲可读性，除非 profiling 证明是瓶颈。

## 关键代码
```go
// 示意，未验证：保序删除 a[i]（append 拼接）
a := []int{1, 2, 3, 4, 5}
i := 1
a = append(a[:i], a[i+1:]...) // a = [1 3 4 5]
```

## 总结与追问预判
- append 拼接跳过 i，保序、可读最好；基准略快于 copy。
