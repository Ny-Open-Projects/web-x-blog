# 706 Gin 中间件的引入方式

> 分类：网络与 IO | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**路由组 group** / **Use 顺序敏感** / **单路由注册**
> 原文锚点：第 70~110 段「路由组 group + use 对其下所有子路由生效…单个路由 use 仅对该路由生效」

## 一句话总述
中间件有两种引入：路由组 `group(...).Use(...)` 对组内所有子路由生效；单路由 `r.GET(path, mw, h)` 仅对该路由生效。位置必须在 handler 之前，否则 Next 统计不到前面耗时。

## 面试官视角
- 考察意图：是否理解注册位置/作用域对中间件生效范围的影响
- P5 知"group.Use 全组生效" / P6 能讲顺序敏感 + 单路由局部生效 / P7 能讲全局/分组/路由三级粒度
- 红旗：把中间件写在 handler 之后以为还生效；说 group.Use 只对该路由生效
- 惊艳点：中间件写在 handler 之后，c.Next 只统计其之后的 handler，前面的 handler 不被它包裹 `[源码]`

## 主问答
**Q：** 中间件怎么挂、挂哪生效？
**A：**
1. **路由组全局**：`g := r.Group("/api"); g.Use(Mw)` 后，/api 下所有子路由都套上 Mw `[源码]`。
2. **单路由局部**：`r.GET("/x", Mw, h)` 仅 /x 生效，不影响其他路由 `[源码]`。
3. **顺序敏感**：Mw 必须写在 handler 之前；写在 handler 之后则 c.Next 统计不到前面 handler 的耗时 `[源码]`。
**加分层：** 典型三级粒度：全局（r.Use）、分组（g.Use）、单路由（写在 handler 前）。
