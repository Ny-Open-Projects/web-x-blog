# 129 MySQL 逻辑架构与连接管理

> 分类：MySQL 内核 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**四层架构**/**连接器**/**max_connections**/**wait_timeout**/**长连接**
> 原文锚点：第 57~83 段「一条查询语句执行过程…架构四层、连接管理」

## 一句话总述
MySQL 逻辑架构四层：**网络连接层**（连接器/连接池，`max_connections` 默认 151、普通用户 150+管理员 1，`wait_timeout` 默认 28800s=8h）、**服务层**（NoSQL/SQL 接口、解析器、优化器、缓存）、**存储引擎层**（InnoDB/MyISAM…）、**文件系统层**；长连接省建连但临时内存累积易涨（可定期断开或 `mysql_reset_connection` 重置），短连接频繁建连开销大。

## 面试官视角
- 考察意图：是否答得出 MySQL 整体架构与"一条 SQL 怎么走过各层"，以及连接管理的内存坑。
- 分档：P5 知四层架构；P6 知 max_connections/wait_timeout；P7 能讲长连接内存涨的原因与 reset_connection 解法。
- 红旗答案：把"连接池"说成服务端组件（连接池在客户端；服务端是连接器）。
- 惊艳点：点出 **长连接内存涨是因为临时内存挂在连接对象上、断开才释放**，并给出 `mysql_reset_connection` 兜底 `[经验]`。

## 主问答
**Q（面试官原话）：** MySQL 逻辑架构分几层？连接管理要注意什么？
**A：**
1. **结论**：四层（网络/服务/引擎/文件）；连接池在客户端、连接器在服务端。
2. **机制**：连接器负责握手、鉴权、维护连接；`max_connections` 默认 151（留 1 个给管理员防占满）；`wait_timeout` 默认 8h 无操作自动断。长连接省建连，但**执行中临时用的内存挂在连接对象上，只有断开才释放**→长期累积涨内存甚至 OOM。
3. **边界**：解法有二——① 定期断开重连；② **MySQL 5.7+ 用 `mysql_reset_connection`** 重置连接资源（不必重连、免权限校验）。服务层的优化器不存统计信息，需向引擎层取。

**加分层：** 短连接每次建连成本高，所以"尽量长连接"是默认，但要配合 reset 防内存涨。

## 关键代码
```sql
-- 8 小时无操作自动断开（默认）
SHOW VARIABLES LIKE 'wait_timeout';        -- 28800 秒
SHOW VARIABLES LIKE 'max_connections';     -- 151
-- 5.7+ 重置连接资源（不重连、免权限校验）
mysql_reset_connection();
```

## 总结与追问预判
四层架构 + 连接管理（连接池在客户端、长连接内存涨用 reset 兜底）。追问接"服务层优化器职责"与"存储引擎统计信息"。
