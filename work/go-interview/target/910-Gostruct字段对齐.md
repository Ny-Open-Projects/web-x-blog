# 910 Go struct 字段对齐：为什么对齐与字段顺序

> 分类：Go 语法/内存 | 难度：L2 | 题型：概念题 | 频率：中 | 关键词：**内存对齐**/**字段顺序**/**字长**/**padding**/**CPU 周期**
> 原文锚点：第 1~34 段「两结构体字段同序异→size不同；CPU 按字长读；对齐省空间省周期」

## 一句话总述
struct 尺寸受**字段顺序**影响：Go 编译器按字段类型做内存对齐，让 CPU 按字长读取更少次数；**把大字段/小字段顺序排好**可既省空间又减 CPU 读取周期。

## 面试官视角
- 考察意图：是否理解对齐的动机（CPU 按字长读、减访问字数），而非只会背「struct 有 padding」。
- 分档：P5 知字段顺序影响 size、有 padding；P6 知对齐为 CPU 按字长高效读、对齐后周期更少；P7 能给出具体 size 差异与排字段口诀。
- 红旗答案：以为 struct 尺寸=字段裸和、无 padding；或说不清为什么对齐。
- 惊艳点：点出「64 位字长 8 字节、32 位字长 4 字节，对齐把小字段合并减少读取字数」 [经验]。

## 主问答
**Q（面试官原话）：** 为什么 struct 字段顺序会影响大小？对齐有什么用？
**A：**
1. **对齐动机：CPU 按字长读**：64 位系统字长 8 字节、32 位字长 4 字节，CPU 按字长取数；字段不对齐会被拆成多次读取。**对齐是为减少访问内存的字数**，提升效率 [经验]。
2. **字段顺序直接影响 size**：同字段、异顺序两结构体，64 位下 size 分别为 **16B 与 24B**（小字段打散插在大字段前后导致更多 padding）；按「小→大」或合理排布可压实 [经验]。
3. **对齐后更省空间更省周期**：未对齐占用 24B、需 **3 个 CPU 周期**读完；对齐后仅占 16B、只需 **2 个周期**——存储与读取次数双优 [经验]。

## 关键代码

```go
package main

import (
    "fmt"
    "unsafe"
)

type S1 struct { a int8; b int16; c int64 } // 合理顺序：对齐后 16B
type S2 struct { a int8; c int64; b int16 } // 打散顺序：未优化 24B

func main() {
    fmt.Println(unsafe.Sizeof(S1{}), unsafe.Sizeof(S2{})) // 16 24
}
```
