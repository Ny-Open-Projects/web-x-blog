# 1814 硬链接的原理与边界

> 分类：Linux 文件系统 | 难度：中 | 题型：概念/对比 | 频率：高 | 关键词：**硬链接、同 inode、链接数、跨文件系统、不可链目录**

> 原文锚点：第 55~79 段「硬链接创建、链接数与特殊目录」

## 一句话总述
硬链接是多个文件名指向同一个 inode——它们本质是同一文件的多个名字，改内容互相同步、删其一不影响其他，只有链接数减到 0 才真正删除。硬链接不能跨文件系统、不能链接目录。

## 面试官视角
硬链接 vs 软链接是必考题。考官看你能不能点出「硬链接共享 inode、删除靠链接数」这个本质，以及「为什么不能链目录」（避免目录树环）。能举例 `.`/`..` 各自的 inode 更稳。

## 主问答
**Q（面试官原话）：** 硬链接是什么？为什么删原文件还能访问？

1. **共享 inode**：多个文件名指向同一 inode 编号，是同一文件的不同名字；`stat` 显示的硬链接数初始为 1（文件自身即一个链接）。
2. **删除语义**：删除任一名字只把链接数减 1，只要链接数 >0 文件数据仍可访问；减到 0 才真正回收 inode 与数据块。
3. **边界限制**：硬链接必须与原文件同文件系统（inode 编号只在分区内唯一）；且不能链接目录（防目录环）。`ls -i` 可见 `.`(当前目录) 与 `..`(上级) 也是基于 inode 的链接。

## 版本与兼容性
| 维度 | 硬链接 |
|------|--------|
| inode | 与原文件相同 |
| 跨文件系统 | 不支持 |
| 链目录 | 不支持 |
| 删除 | 减链接数，0 才删 |

## 关键代码
```bash
ln file.txt hard.txt     # 创建硬链接
stat file.txt            # Links 字段 +1
ls -i file.txt hard.txt # 两文件 inode 号相同
```

## 总结与追问预判
核心：**硬链接=同 inode 多名字，删靠链接数，不跨 FS、不链目录**。追问必拐向软链接对比（见 1814-soft-link）。回答时强调「inode 共享」是区分硬/软的根本。
