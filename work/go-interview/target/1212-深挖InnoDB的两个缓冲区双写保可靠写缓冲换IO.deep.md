# 1212 深挖：InnoDB 的两个缓冲区——双写保可靠、写缓冲换 IO

> 分类：数据库 / MySQL 存储 | 难度：L5 | 题型：综合题 | 频率：中 | 关键词：**doublewrite、change buffer、随机IO、顺序IO、部分写失效、唯一性检查、写多读少、buffer pool**

> 原文锚点：第 19~45、52~65 段「doublewrite 的做法就是先将脏页和 redo log 得到的最终数据先持久化到磁盘的另一个地方，然后再进行原地更新…脏页的落盘是随机IO，而 doublewrite buffer 的落盘是顺序IO…对于写多读少的场景，如何进一步去优化我们的磁盘IO呢？MySQL 就使用了写缓冲，也就是 change buffer…它不会立刻将磁盘上的数据加载到 buffer pool 里面，而仅仅是将数据修改记录到更改缓冲区当中，当后面这个数据被读取的时候再将数据合并进缓冲池」

## 思路与架构

本节的两个缓冲区，本质是**同一个思路的两种用法**：**把不可控的随机 IO 换成可控的顺序 IO（或干脆推迟）**。

1. **双写缓冲区（doublewrite）——解决"写一半"**：
   - **问题**：InnoDB 以页为单位写盘，**数据库页（16KB）大于文件系统页（4KB）**，**一个数据库页要写 4 个文件系统页**；写到一半宕机就产生**部分写失效 / 页断裂**，而 **redo log 不含完整页内容、修不了坏页**。
   - **做法**：**先把脏页与 redo log 得到的最终数据持久化到磁盘的另一个地方，然后再进行原地更新**；**一旦发生宕机，可以通过这份完整的数据来恢复被损坏的页**。
   - **落地**：内存 doublewrite buffer（2MB）→ **分两次顺序写共享表空间的 2MB 连续区（每次 1MB）** → 成功后再把脏页**随机写入各表空间** → 持久化后双写区**可覆盖**。
   - **三道保险**：**顺序 IO**（不易撕裂）+ **时序保证**（双写失败则数据页不动）+ **页尾校验值**（可判定完整性）。
2. **更改缓冲区（change buffer）——解决"改之前要先读"**：
   - **问题**：**修改的页不在 buffer pool 时，必须先从磁盘把页读进内存**，产生**一次随机读**；**写多读少的场景**下这笔开销很亏。
   - **做法**：对**非唯一普通索引页**，**不立即加载磁盘数据，只把修改记录进 change buffer**；**数据被读取时再合并进缓冲池**，从而**在很大程度上减少磁盘随机读**。
   - **边界**：**唯一索引必须做唯一性检查，而检查必须读盘**，所以这次随机读省不掉——**更新频繁的字段谨慎加唯一索引**。
3. **两者的共同点**：都位于**内存缓冲区 + 系统表空间持久化**这一结构里（双写区与 change buffer 的持久化数据都落在共享表空间），都由**后台机制驱动**（脏页刷新 / 定期刷盘与 merge），都服务于"**用可控代价换掉不可控代价**"。

## 方案取舍

| 关注点 | 双写缓冲区 | 更改缓冲区 |
|---|---|---|
| 解决什么 | 页断裂 / 部分写失效 | 修改前的随机读 |
| 手段 | 先顺序写副本，再随机写数据页 | 记账式延迟合并 |
| 换来的 | 落盘原子性 / 可恢复性 | 减少磁盘随机读 |
| 付出的 | 一次额外顺序写（写放大） | 读取时延后合并，读路径变长 |
| 适用 | 所有脏页（默认开启） | **仅非唯一二级索引页** |
| 不适用 | 底层保证 16KB 原子写时可关 | 主键、唯一索引 |
| 最适负载 | 无差别 | **写多读少** |

取舍要点：**双写是"买保险"**——多写一份换崩溃可恢复，代价是写放大；**写缓冲是"赊账"**——把读 IO 推迟到真正需要时才付，代价是读路径变长且仅对非唯一索引有效。前者**默认开、几乎不该关**；后者**默认开、但要按负载调 `innodb_change_buffer_max_size`**。

## 答题技巧

1. **开场先立一条纲**：**本节两个机制都在做"把不可控的随机 IO 变成可控的顺序 IO 或延迟 IO"**——这句话能让整节内容有主线。
2. **讲双写必须先讲根因**：**页大小不对等（16KB vs 4KB）→ 页断裂 → redo log 修不了坏页 → 需要页副本**。倒过来讲会很散。
3. **讲写缓冲必须先讲两条路径**：**页在缓冲池（内存操作 + 顺序写）vs 页不在（多一次随机读）**，change buffer 的价值才立得住。
4. **两个"只"字不能漏**：**双写默认开启**（`innodb_doublewrite`）；**写缓冲只对非唯一二级索引生效**（唯一索引要读盘做唯一性检查）。
5. **数字要报**：**16KB / 4KB**、**2MB 双写区 / 每次 1MB**、**redo block 512 字节**、**change buffer 默认 25%、上限 50%**——报数字是 P7 的硬证据。
6. **止步档位**：能讲清两个机制各自的作用即达 L4；能补上根因链、三个思考题、配置项数字与"写多读少"的适用判据，即达 L5。

## 细节与核心 API

**双写缓冲区（默认开，几乎不该关）——解决页断裂（16KB 数据库页 vs 4KB 文件系统页，部分写失效）**：

```ini
innodb_doublewrite = ON
# 内存 2MB → 顺序写共享表空间 2MB 连续区(每次1MB) → 成功后再随机写各表空间数据页
# 三道保险：顺序IO(不易撕裂) + 时序保证(双写失败则数据页不动) + 页尾校验值(判定完整性)
```

**更改缓冲区（默认开，仅非唯一二级索引页；唯一索引要读盘做唯一性检查 → 随机读省不掉）**：

```ini
innodb_change_buffering = all            # 默认 all
innodb_change_buffer_max_size = 25       # 占 buffer pool 比例，上限 50
# 写多读少：页不在 buffer pool 时只记账，读取时才 merge 进缓冲池，省一次随机读
# 更新频繁字段谨慎加唯一索引（唯一性检查必读盘，change buffer 失效）
```

**关键数字（P7 硬证据）**：16KB / 4KB、2MB 双写区（每次 1MB）、redo block 512 字节、change buffer 默认 25%（上限 50%）。

> 边界：buffer pool 与 AHI 见 1300；redo/undo 见 1209；本卡只讲 doublewrite 与 change buffer 两个缓冲区。
