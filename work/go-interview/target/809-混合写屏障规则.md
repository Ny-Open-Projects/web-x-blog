# 809 混合写屏障规则①：栈全黑免二次扫描

> 分类：Go/运行时 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**栈不装屏障** / **栈对象全标黑** / **GC 期间栈新增标黑** / **免 STW 重扫栈**
> 原文锚点：第 7~11 段「GC 开始扫描栈上对象全标黑(含 GC 期间栈新增对象标黑)；目的为避免 STW 二次扫描栈；对象删除触发删除屏障、新增触发插入屏障」

## 一句话总述
混合写屏障有三条规则，关键差异在**栈**：① GC 启动时把栈上可达对象**全部标黑**，且 GC 期间在栈上**新增的对象也直接标黑**——这样栈整个免装屏障、也**免 STW 二次扫描栈**；② 堆对象引用被删除时触发**删除屏障**（被删对象标灰，保留其下游引用路径）；③ 堆对象新增引用时触发**插入屏障**（新对象标灰）。规则①是 Go 1.8 把 STW 压到毫秒级的前提。

## 面试官视角
- 意图：考察"为什么栈可以不装屏障却仍正确"，这是混合写屏障最易被忽略的细节。
- P5 知道栈对象标黑；P6 能讲"栈全黑+期间新增标黑→免重扫、免 STW"；P7 能点出"若栈也装插入屏障则结束要 STW 重扫全部栈，停顿随栈数增长——混合屏障用规则①绕开它"。
- 红旗：以为栈对象也走插入/删除屏障；不知道"GC 期间栈新增对象标黑"是免重扫的关键。
- 惊艳点：点出"栈为性能不装屏障，靠启动全标黑+期间新增标黑补足保护，代价是栈上对象一律按存活处理（可能多标）"。

## 主问答
**Q：** 为什么 Go 1.8 的栈不用写屏障，却还能正确并发标记？
**A：**
1. **栈全黑**：GC 启动先扫描所有 goroutine 栈，把栈上可达对象标黑；栈空间小、对象少，扫描快。
2. **期间新增也黑**：GC 运行期间在栈上新分配的对象**直接标黑**——无论它有没有被引用，都不再参与后续标记。
3. **免重扫**：因为栈上对象从一开始就全黑且只增不减地黑，标记结束**不必再 STW 重扫栈**（若栈装了插入屏障就得结束时重扫，停顿随栈数线性增长）。栈上的引用改动（改/删）不触发屏障，靠"已是黑"保证安全。

## 关键代码
```go
// 混合写屏障语义（runtime 实际用汇编实现）；栈对象不经此函数
func heapWrite(slot *unsafe.Pointer, newobj unsafe.Pointer) {
    shade(*slot)   // 删除侧：被覆盖的旧值标灰（保留引用路径）
    shade(newobj)  // 插入侧：新写入的值标灰（防漏标）
    *slot = newobj
}
// 栈对象：GC 启动统一标黑 + 期间新分配直接标黑，根本不调用 heapWrite，
// 故无需结束时 STW 重扫栈（对比 Go 1.5 的插入屏障需重扫）
```

## 总结与追问预判
- 规则①：栈全黑+期间新增标黑→免重扫、免 STW；规则②③：堆删/增触发删除/插入屏障。
- 预判：混合屏障动机三连见 808；插入/删除屏障见 808/808-delete-barrier；三色含义见 807（本卡只补规则①与栈免重扫，不重复原理）。
