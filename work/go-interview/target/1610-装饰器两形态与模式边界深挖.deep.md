# 1610 装饰器两形态与模式边界深挖

> 覆盖源 16-10 的形态延伸：结构体四角色版 vs 闭包函数版（中间件）的取舍、与代理/适配器/责任链的边界、装饰顺序的语义影响、HTTP 中间件洋葱模型与结构体版的同构。主卡已给四角色主线，本附录做形态与边界深挖。

## 思路与架构

```text
装饰器在 Go 的两种形态
├─ 结构体四角色版 (16-10 源文形态)
│   ├─ 接口 + 抽象装饰器(嵌入 wrapped) + 具体装饰器
│   ├─ 适用: 多方法契约 / 装饰器带配置状态 / 教学骨架
│   └─ [实测] B(A(base)) -> "B(A(基础功能))" 洋葱叠加
├─ 闭包函数版 (162 号卡中间件形态)
│   ├─ type Middleware func(Component) Component
│   ├─ 适用: 单方法接口 / 运行时动态组合 (http 链)
│   └─ 优点: 组合零仪式; 代价: 闭包嵌套可读性
└─ 边界三兄弟
    ├─ 装饰器: 同接口, 加功能, 客户端知情权为零
    ├─ 代理:   同接口, 控制访问 (鉴权/缓存/远程), 意图是管控
    └─ 适配器: 不同接口, 转换契约, 意图是兼容
```

## 方案取舍
- **两形态的选择标准**：**方法数与状态**。契约 ≥2 个方法或装饰器本身有配置（重试次数、超时、日志级别）→ 结构体版，字段放配置、遮蔽式重写清晰；单方法接口 + 动态组合需求（如 net/http 的中间件链由路由器运行时拼装）→ 闭包版，`func(h Handler) Handler` 一个类型搞定。Go 生态里 HTTP 中间件几乎全是闭包版，因为 Handler 接口恰好单方法 [经验]。
- **装饰顺序是语义的一部分**：洋葱模型下 `日志(重试(业务))` 与 `重试(日志(业务))` 行为不同——前者每次重试都打日志，后者整个重试过程只打一条。用结构体版 [实测] 可见最外层先执行；闭包版同理（先包的在外层）。**「谁在外层」必须作为设计决策明确下来**，随手叠加会埋顺序 bug [经验]。
- **与代理的一线之隔**：结构上一模一样（都是同接口包一层），区别只在**意图**——装饰器透明加功能（日志/指标/压缩），代理控制访问（鉴权/懒加载/远程桩）。答模式题时报意图差异即可，不必纠结实现形态；而适配器是**换契约**（接口不同），一眼可分 [经验]。
- **与责任链的混淆点**：责任链（`163-chain-of-responsibility.md`）每节点**可以中断**传递（处理了就停），装饰器**必须逐层委托到底**（每一层都执行）——「可短路」是责任链的指纹。HTTP 中间件容易混：中间件链其实常混入责任链语义（如鉴权失败直接 return），说明**工程中的形态常是模式的混合体**，答题点到即止 [经验]。

## 答题技巧
- 手写四角色后主动补一句「单方法接口我会直接用闭包版，即中间件形态」——两形态自由切换是最强信号 [经验]。
- 用 [实测] 输出讲顺序：`B(A(基础功能))` 一眼看懂洋葱模型，比画图快 [实测]。
- 被问「和代理什么区别」→ 一句话「代理管访问、装饰管增强」，再各举一个例子 [经验]。
- 被问「顺序重要吗」→ 报 `日志(重试)` vs `重试(日志)` 的日志条数差异——顺序即语义 [经验]。
- 主动边界到 `1610-decorator-components`（四角色主线）、`162-decorator`（函数式形态立论）、`163-chain-of-responsibility`（责任链对照）、`169-strategy-context-tradeoffs`（行为型族）、`168-builder-pattern-roles`（创建型族），构成「Go 设计模式实战」专题 [边界]。

## 细节与核心 API

```go
// 形态1：函数装饰器（包装函数，附加日志/重试/鉴权）
type Handler func(ctx context.Context, req Req) (Resp, error)
func WithRetry(next Handler, n int) Handler {
    return func(ctx context.Context, req Req) (Resp, error) {
        var err error
        for i := 0; i < n; i++ {
            if r, e := next(ctx, req); e == nil { return r, nil } else { err = e }
        }
        return Resp{}, err
    }
}
// 形态2：中间件链（责任链，按序包裹，可短路）
func Chain(mws ...func(Handler) Handler) func(Handler) Handler {
    return func(h Handler) Handler {
        for i := len(mws) - 1; i >= 0; i-- { h = mws[i](h) }
        return h
    }
}
// 边界：装饰器适合“横切关注点”（日志/限流/追踪）；不要塞业务主流程，避免嵌套过深难测
// 与代理区别：装饰器在编译/构造期组合；代理常运行期动态替身（如 RPC 客户端代理）
```
