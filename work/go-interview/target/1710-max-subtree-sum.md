# 1710 求二叉树的最大子树和：后序遍历一遍搞定

> 分类：数据结构 / 算法 | 难度：L2 | 题型：算法题 | 频率：中 | 关键词：**最大子树和**/**后序遍历**/**递归返回值与全局最大**/**负数边界**

> 原文锚点：第 4~13 段「后序遍历 + 左右子树和累加 + 全局最大值更新」

## 一句话总述
最大子树和 = 所有「以某节点为根的子树」的节点和中最大的那个。用**后序遍历**一趟解决：递归函数返回「以当前节点为根的子树和」（左 + 右 + 自身），同时在返回途中用该和**更新全局最大值**——一次遍历同时拿到「每个子树的和」与「最大者」，O(n) 时间 O(h) 栈空间。

## 面试官视角
这题的考点不在写出递归，而在两个分水岭：① **「返回值」与「答案」分离**——递归函数的返回值是给父节点用的子树和，真正答案走全局变量/指针旁路收集，混为一谈必错；② **子树和 ≠ 路径和**——子树必须整棵计入，不能像最大路径和那样「负孩子剪掉只取单边」。能主动指出与「二叉树中的最大路径和」（LeetCode 124）的差异，直接升档。

## 主问答
**Q（面试官原话）：** 如何求一颗二叉树的最大子树和？

1. **问题定义**：节点值可正可负，对每个节点 x，「以 x 为根的子树」的全体节点之和记 S(x)，求 max S(x)。
2. **为什么是后序遍历**：要算 S(x) 必须先知道左右子树的和——**先左右后根**的信息依赖恰好就是后序。前序/中序在算根时子树和还没出来。
3. **递归骨架**：`sum(x) = sum(x.Left) + sum(x.Right) + x.Val`；每次算出 sum 就与全局 max 比较，大则更新。
4. **[实测] 源文树验证**（5(3(-4,1), -8(6,9))）：后序路径 -4→1→3→6→9→-8→5，各子树和：3 子树=0、-8 子树=7、根=12 → **最大 12**（即全树和）；过程实测输出逐点吻合。
5. **三个边界**（[实测]）：**全负树** (-5,-2,-9) 答案 -2——最大子树可以是单个节点，不能默认「包含根」；**负子树拖累**——树 4(-10,6) 答案是右子树 6 而非路径 4+6=10，因为左子树整棵必须计入；**空树**——递归基线返回 0，但全局 max 保持初值，调用方要判空。

## 关键代码
```go
type TreeNode struct {
	Val         int
	Left, Right *TreeNode
}

// MaxSubtreeSum 后序遍历：返回以 node 为根的子树和；全程维护全局最大值
func MaxSubtreeSum(node *TreeNode, maxSum *int) int {
	if node == nil {
		return 0
	}
	left := MaxSubtreeSum(node.Left, maxSum)
	right := MaxSubtreeSum(node.Right, maxSum)
	sum := left + right + node.Val // 以 node 为根的子树和
	if sum > *maxSum {
		*maxSum = sum // 答案走旁路, 不参与返回
	}
	return sum // 返回值只供父节点计算
}
```

[实测] 源文树输出 12；全负树 (-5,-2,-9) 输出 -2；树 4(-10,6) 输出 6。

## 总结与追问预判
核心：**后序一趟、返回值传子树和、答案走全局旁路；全负树取单节点、子树整棵计入不可剪枝**。追问常拐向「改成最大路径和怎么办」——路径和允许只取一侧子链，递归返回值要改成 `max(0, 左链)+max(0, 右链)+Val`（负贡献剪掉），返回与答案依旧分离；复杂度评估与遍历家族见 `1711-complexity-evaluation.md`，排序类后序应用见 `1714-bubble-sort.md`。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文把初始化最大值写成 64 位最小值后在「32 位系统」溢出，改用 32 位最小值修复——该说法含混：Go 的 int 位数随平台，现代环境均为 64 位；正确做法是 `math.MinInt`（1.17+ 随平台自适应）或直接用 int64，无需手写特定位数最小值。另原文递归函数签名描述「两个参数」实际是「节点 + 全局最大值指针」。
2. 术语归一：源文将「子树」音转为「子数」、最大值相关多处音转（大指数组合等），本卡统一为规范术语。
