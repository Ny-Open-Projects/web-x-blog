# 503 Go 指针为何不能做算术运算

> 分类：语法 | 难度：L1 | 题型：八股题 | 频率：高 | 关键词：**指针算术** / **解引用自增** / **atomic.AddInt64**
> 原文锚点：第 69~75 段「第一个限制就是 go 语言指针不支持直接进行算术运算…p 自增无效」

## 一句话总述
Go 指针是"受限指针"：不允许 `p++` 这类指针算术，要改指向的值必须先解引用（`*p++`）或用 `sync/atomic` 操作，从语言层杜绝 C 式的越界游走。

## 面试官视角
- 意图：是否理解 Go 指针与 C 指针的本质差异及设计取舍。
- P5 知 `p++` 报错需解引用 / P6 能说清为何禁止与替代写法 / P7 知这保障了内存安全、避免越界。
- 红旗：以为 `p++` 合法；以为 Go 指针能像 C 那样遍历数组。
- 惊艳点：指针算术被禁，数组遍历靠下标而非指针加减 —— 验证 `go vet` 报 invalid operation `[源码]`。

## 主问答
**Q（面试官原话）：** Go 的指针能不能像 C 一样做 `p++` 之类的运算？
**A：**
1. **结论**：不能。Go 禁止对指针做加减、自增等算术运算，编译期直接报 invalid operation。
2. **机制**：指针只存储地址，语言规范不提供指针偏移运算；想改值必须先 `*` 解引用得到所指变量再运算（`*p++`）。
3. **边界**：多变量批量遍历不能靠指针加减，仍用 slice 下标；若确需原子自增用 `atomic.AddInt64(&x, 1)`。
**加分层：** 禁算术是为内存安全，避免 C 式野指针越界游走，代价是失去底层指针遍历的灵活性。

- 指针算术被禁，改值需解引用或用 atomic；设计取舍是内存安全换灵活性。
