# 808 Go 1.8 混合写屏障：两种屏障合起来的理由

> 分类：Go 运行时 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**混合写屏障、Go 1.8、栈不重扫、毫秒级停顿**

> 原文锚点：第 91~97 段「为确保栈性能，栈上的对象不使用屏障机制…Go 1.8 引入混合写屏障，避免对栈的重新扫描」

## 一句话总述
混合写屏障在一次堆指针写里同时做两件事——**把新写入的对象染灰（插入侧）+ 把被覆盖的旧对象染灰（删除侧）**，两条性质叠加后**不再需要重新扫描栈**，STW 被压到毫秒级。

## 面试官视角
这是本讲的高潮题。P6 知道"Go 1.8 引入混合写屏障"；P7 能说清**动机三连**：① 栈为了性能不装屏障，只装插入屏障就得在结束时 STW 重扫栈，停顿随栈数量增长；② 只用删除屏障则精度太低、浮动垃圾多；③ 混合后既保住不丢对象，又免掉栈重扫 `[源码]`。

## 主问答
**Q（面试官原话）：** 为什么 Go 1.8 要搞混合写屏障？

1. **插入屏障的短板**：对栈不生效，若不提供额外保护，标记结束前必须 STW 重新扫描全部 goroutine 栈，栈越多停顿越长 `[经验]`。
2. **删除屏障的短板**：回收精度低，本该回收的对象要拖到下一轮（浮动垃圾），堆占用偏高。
3. **混合的做法**：在一次堆指针写操作里同时执行两种保护——染灰新写入的对象，也染灰被覆盖的旧对象。
4. **收益**：既保证不丢对象，又**免除栈的重新扫描**，STW 降到毫秒级，可用 `GODEBUG=gctrace=1` 观察各阶段停顿佐证 `[实测]`。

## 关键代码
```go
// 混合写屏障的语义示意，真实实现在 runtime 汇编
func heapWrite(slot *unsafe.Pointer, newobj unsafe.Pointer) {
    shade(*slot)    // 删除侧：保护被覆盖的旧值
    shade(newobj)   // 插入侧：保护新写入的值
    *slot = newobj
}
```
