# 143 五款主流消息中间件横向对比

> 分类：架构设计 | 难度：L3 | 题型：对比题 | 频率：高 | 关键词：**ActiveMQ、RabbitMQ、Kafka、RocketMQ、Pulsar**

> 原文锚点：第 24~74 段「单机吞吐在万级…十万级…十四万…各自特点」

## 一句话总述
主流产品按**吞吐与定位**拉开梯度：老牌万级、企业级万级、大数据级十万级、金融级十万级、云原生级更高，选型要看场景落在哪一档。

## 面试官视角
P6 只会说"Kafka 快"；P7 要按**语言/协议/吞吐/可靠性/生态**五维对照，并说清各自的定位：老牌产品社区已转冷、企业系统看重协议与可靠性、大数据领域几乎都优先支持流式产品 `[经验]`。加分点：吞吐数字要带量级——万级、十万级、开启压缩与异步批量后还能更高 `[源码]`。

## 主问答
**Q（面试官原话）：** 主流的消息队列各自有什么特点？

1. **老牌 ActiveMQ**：Java 开发，单机吞吐万级，比后起产品低一个数量级；基于主从实现高可用、功能完善，但社区活跃度低，新项目基本不再使用 `[经验]`。
2. **RabbitMQ**：Erlang 开发、基于 AMQP 协议，支持点对点与发布订阅，可靠性与安全性高；适合对一致性稳定性要求高的企业系统 `[源码]`。
3. **Kafka**：分布式、Scala 与 Java 编写，单机吞吐十万级，开启压缩与异步批量后更高；社区活跃、生态完善，几乎成了大数据领域的默认选择 `[实测]`。
4. **RocketMQ**：Java 重写，低延迟强一致，单机吞吐十万级，且主题数量达几百上千对吞吐影响不大 `[源码]`。
5. **Pulsar**：雅虎起源后捐给基金会，计算与存储分离，多租户与跨区域复制，吞吐可达十四万且不受主题数量影响 `[经验]`。

## 版本与兼容性
| 结论成立范围 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ActiveMQ | 社区活跃度下降 | 新项目不选 |
| RabbitMQ | 协议稳定 | 企业系统仍在用 |
| Kafka | 生态最成熟 | 大数据与日志流首选 |
| RocketMQ | 主要维护 4.0 以上 | 金融与电商场景常见 |
| Pulsar | 社区持续成长 | 别用多年前的活跃度结论 |

## ⚠️ 原文纠错
1. 事实核校：原文各产品量级与定位（万级 / 十万级 / 十四万）基本准确，本卡沿用 `[经验]`。
2. 补充：原文称 RabbitMQ"数据能保证百分之百不丢失"**过于绝对**——任何系统都有极限，准确说法是依托镜像队列、确认机制与持久化把丢失概率压到极低，本卡更正 `[源码]`。
3. 补充：原文"某流式产品的批量处理模型"表述为字母缩写，实为**客户端批量发送**：消息先在客户端攒批再整体发送，从而减少网络与磁盘开销，这是其高吞吐主因，本卡归一 `[源码]`。
4. 崩坏词归一：源码将各产品名、协议名、语言名与术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
