# 1111 O(1) 交换删除切片元素

> 分类：数据结构 | 难度：L2 | 题型：代码题 | 频率：高 | 关键词：**交换删除** / **O(1)** / **打乱顺序**
> 原文锚点：第 21~28 段「不关心顺序时最快：末元素移到 i，再截掉末位」「只需一次赋值一次截取」

## 一句话总述
不关心顺序时，删除 `a[i]` 的最快做法是 `a[i] = a[len(a)-1]; a = a[:len(a)-1]`，O(1)、零分配；代价是**会打乱元素顺序**，不能用于保序场景 `[源码]`。

## 面试官视角
- 意图：是否知道 O(1) 删除法及它的关键权衡（乱序）。
- P5 会写交换删除 / P6 说清 O(1) 与零分配 / P7 知何时禁用（需保序/去重场景）。
- 红旗：声称"删除必 O(n)"；用交换删除却要求顺序不变。
- 惊艳点：交换删除 0 分配、1 次赋值 —— 验证 `testing.AllocsPerRun` go1.26.5 `[源码]`。

## 主问答
**Q（面试官原话）：** 怎么从切片里删掉一个元素？有没有 O(1) 的？
**A：**
1. **结论**：不关心顺序时 `a[i] = a[len(a)-1]; a = a[:len-1]` 是 O(1) 删除，仅一次赋值一次切片。
2. **机制**：只改一个槽位并缩短 len，不搬移其余元素，不触发扩容/分配 `[源码]`。
3. **边界**：**会打乱顺序**——被删位置被末元素覆盖，其余元素相对位置变化；需保序或需稳定去重时不能用。
**加分层：** 顺序无关的"集合/栈"类数据用它，排序/有序列表别用。

## 关键代码
```go
// 示意，未验证：O(1) 交换删除（打乱顺序）
a := []int{1, 2, 3, 4, 5}
i := 1                      // 删除值 2
a[i] = a[len(a)-1]          // a = [1 5 3 4 5]
a = a[:len(a)-1]            // a = [1 5 3 4]
```

## 总结与追问预判
- 交换删除 O(1)、零分配，但打乱顺序；保序请用 copy/append 法。
- 预判：保序删除 → 见 1111-slice-delete-copy / 1111-slice-delete-append；底层数组 → 见 1111-slice-delete.deep。
