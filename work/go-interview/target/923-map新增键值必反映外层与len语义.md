# 923 map 新增键值必反映外层与 len 语义

> 分类：Go 语言基础 | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**map 无扩容**/**键值对个数**/**len 语义**
> 原文锚点：第 93~103 段「map 在函数中新增键值对…长度即底层键值对个数」

## 一句话总述
map **没有"扩容换地址"的概念**（hmap 哈希表动态增长但 header 始终指向同一 hmap），所以**函数内新增 key 必然反映到外层**；且 **map 的 len 就是底层键值对个数**，不像切片 len 存在"可见个数"的歧义。

## 面试官视角
- 考察意图：是否抓住切片与 map 传参的**唯一关键差异**——map 不会因"增长"而换底层地址。
- 分档：P5 知 map 新增键值外层看得见；P6 知 map 无扩容换地址；P7 能讲清"len=键值对个数"与切片 len 的本质区别。
- 红旗答案：把切片的"append 不可见"套到 map 上，以为 map 新增也可能看不见。
- 惊艳点：一句话——**切片 len 是"可见元素数"（可被直接部分独立坑掉），map len 是"底层实际键值对数"** `[经验]`。

## 主问答
**Q（面试官原话）：** 切片 append 有时外层看不到，map 新增键值为什么一定能看到？
**A：**
1. **结论**：因为 map 没有切片那种"扩容换地址"——hmap 增长时原地扩容/渐进搬迁，header 仍指向同一 hmap，函数内新增的键值外层立即可见。
2. **机制**：传参共享 hmap；`m[k]=v` 直接写入共享结构。即便触发 hmap 的桶扩容，也只是内部数据搬迁，外层持有的 header 指针不变，依然看到全部键值。
3. **边界**：**map 的 len 就是底层键值对的实际个数**，不存在切片"底层有 4 个但 len 写死 3 看不见"的情况；所以"新增是否可见"对 map 永远成立。

**加分层：** 切片与 map 的 len 语义差异，正是面试爱考的对比点——切片 len 是 header 独立字段（可被拷贝隔离），map len 由 hmap 的 count 实时决定。

## 关键代码
```go
func addIn(m map[int]int) {
    m[3] = 6 // hmap 可能内部扩容，但 header 指向不变
}
func main() {
    a := map[int]int{0: 1, 1: 2}
    addIn(a)
    fmt.Println(a)              // map[0:1 1:2 3:6]：新增立即可见
    fmt.Println(len(a))         // 3：len 即底层键值对个数
}
```

## 总结与追问预判
map 与切片的唯一关键差异：map 无扩容换地址→新增必反映，len 语义无歧义。追问接"切片 append 换地址"与"直接/间接部分统一模型"。

1. 机翻崩坏词归一：`建建对`→**键值对**；`层层空间`→**同一空间**；`底层速度`→**底层数组**；`普mam`→**map m**；`mam`→**map**。事实推理正确，仅术语崩坏，本卡已归一 `[经验]`。
2. 原文"map 的长度其实就是 map 中元素的个数，而不是可见的个数"——精准点出切片/map 的 len 语义差异，本卡据此展开对比，已补"切片 len 是 header 独立字段、map len 由 hmap count 实时决定"的底层解释。
3. 原文"追加的表现跟切片是不一样的"——准确，因 map 无扩容换地址，本卡已强化这一结论。
