# 507 切片展开实战 + 编译期求值（make/len/cap）与 nil 函数 panic

> 分类：Go 函数 | 难度：L3 | 题型：机制题 | 频率：中 | 关键词：**切片展开** / **编译期求值** / **len/cap 常量** / **nil 函数** / **运行期求值**
> 原文锚点：第 11~46 段「展开两个传法(打平多个参 vs 整体1参);编译期求值(make/len/cap及数组len/cap编译期可赋常量,普通函数返回值运行期);特殊函数(死循环无return合法/nil函数调用panic)」

## 一句话总述
变长参数的切片展开有两种调用姿态：**`s...` 打平**（逐元素多参）vs **直接传 `s`**（整体当一个参数，类型不符报错）。另注意函数求值时机：内置 `make`/`len`/`cap` 对**数组**调用的 `len`/`cap` 是**编译期常量**，可作常量初值；普通函数返回值则是**运行期**，不能赋常量。还有两个边界：死循环函数可"无 return"合法；**nil 函数调用会 panic**。

## 面试官视角
- 意图：把"变长参数"延伸到"求值时机"与"函数边界"，考察对编译期/运行期、nil 函数的敏感度。
- P5 知 `s...` 与直接传区别；P6 知数组 len/cap 编译期常量、普通函数返回值运行期；P7 知 nil 函数调用 panic、死循环函数无 return 为何合法。
- 红旗：以为 `len(切片)` 都能当编译期常量；或敢直接调用未赋值的函数变量。
- 惊艳点：点出"编译期求值意味着返回值可作 const 初值，运行期不行"的实操差异 `[边界]` 见 903（len 语义）、414（数组 len/cap）、923-direct-indirect-part（切片值部）。

## 主问答
**Q（面试官原话）：** 切片怎么展开传给变长参数？len/cap 为什么能赋常量？
**A：**
1. **展开两种姿态**：`f(s...)` 把切片元素逐个展开成多实参；`f(s)` 把整个切片当一个 `[]T` 参数，与 `...T` 期望不符，编译报错。
2. **编译期求值**：数组的 `len`/`cap` 在编译期已知，故 `const n = len([3]int{})` 合法；内置 `make` 同理部分场景编译期。
3. **运行期求值**：普通自定义函数返回值在运行期算出，不能赋给常量（`const m = f()` 非法）。
4. **函数边界**：死循环函数即使没写 return 也合法（函数体不会正常返回）；但声明未赋值的 nil 函数变量一旦调用就 panic。

## 关键代码
```go
package main

// 编译期求值：数组的 len/cap 是编译期常量，可作常量初值
const n = len([3]int{}) // 合法

// 普通函数返回值运行期求值，不能赋给常量
func f2() int { return 1 }

// const m = f2() // 非法：运行期求值

var nilFn func() // nil 函数

	_ = n
	// nilFn() // panic: invalid memory address / runtime error

}
```

- 展开用 `s...`；数组 len/cap 编译期常量、普通函数运行期；nil 函数调用 panic、死循环可无 return。
- 预判：len 语义 → 见 903；数组 len/cap → 见 414*；切片值部 → 见 923；函数选项模式 → 见 507。
