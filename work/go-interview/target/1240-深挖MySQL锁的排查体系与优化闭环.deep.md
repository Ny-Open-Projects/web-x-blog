# 1240 深挖：MySQL 锁的排查体系与优化闭环

> 分类：数据库 / MySQL 锁 | 难度：L4 | 题型：综合题 | 频率：高 | 关键词：**排查链路、锁视图、死锁检测、优化闭环、全局锁、MDL、意向锁**

> 原文锚点：第 1~81 段「show processlist 可以显示哪些线程正在运行…8.0 开始查 performance_schema 下的 data_locks…避免死锁可以开启死锁检测并设置合理的锁超时时间…本节详细介绍了全局锁、元数据锁、AUTO-INC 锁、表级共享锁与排他锁、意向锁，以及间隙锁、记录锁、插入意向锁」

## 思路与架构

把「锁」这件事故化成一条**可执行的排查闭环**，面试时按链路叙述：

1. **第一层：现象确认**——业务报慢或超时，先用 `SHOW PROCESSLIST` / `information_schema.PROCESSLIST` 看有没有 STATE 含锁关键字、TIME 异常偏大的会话。这是入口，不是终点。
2. **第二层：聚合定位**——把 processlist 当表聚合：按客户端 IP 分组找连接数最多的来源；过滤空闲连接后按时间倒序找长 SQL；设阈值并生成清理语句。
3. **第三层：锁定归属**——查 `information_schema.INNODB_TRX` 找活跃事务，查 `performance_schema.data_locks`（8.0）看加锁类型与被锁数据，查 `data_lock_waits` 看谁在等谁；表级问题看 `SHOW OPEN TABLES` 的占用与表名锁，DDL 阻塞看 `metadata_locks`。
4. **第四层：兜底机制**——死锁检测（`innodb_deadlock_detect`，5.7.15 起默认 ON，高并发建议关闭）负责主动发现；锁等待超时（默认 50 秒，建议 5~10 秒）负责被动兜底；`innodb_rollback_on_timeout` 决定回滚范围。
5. **第五层：优化闭环**——回到 SQL 与事务设计：选隔离级别、冲突少用乐观锁、加锁操作放事务最后、WHERE/JOIN 命中索引缩小锁范围、大查询分页、合并查询减少加锁次数，最后把锁状态纳入长期监控。

**锁谱系回顾**（本节收尾总结）：库级全局锁（用于备份）、表级元数据锁 MDL、AUTO-INC 锁、表级共享锁与排他锁、意向共享锁 IS 与意向排他锁 IX；行级包括间隙锁、记录锁、插入意向锁。实验基于 MySQL 8.0.35，不同版本表现可能有差异。

## 方案取舍

| 手段 | 解决的问题 | 代价 | 适用场景 |
|---|---|---|---|
| 降低隔离级别 | 锁竞争高、并发不足 | 引入脏读/不可重复读 | 读多写少、容忍读异常 |
| 乐观锁 | 显式加锁开销大 | 需应用层重试逻辑 | 冲突概率低 |
| 缩短持锁时间 | 阻塞扩散 | 需重构事务边界 | 通用，首选 |
| 命中索引缩范围 | 全表扫描加锁过多 | 需维护索引 | 通用，首选 |
| 分页处理 | 单次锁定数据量大 | 一致性快照难保证 | 批处理、导出 |
| 合并查询 | 加锁次数多 | SQL 复杂度上升 | 高频小查询 |
| 关闭死锁检测 | 检测本身的性能损耗 | 死锁只能靠超时兜底 | 高并发热点写 |
| 调小锁超时 | 死锁解开太慢 | 正常等待也可能被中断 | 配合关闭检测 |

取舍要点：**先做无副作用的（缩短持锁时间、加索引），再做有业务代价的（降隔离级别、关检测）**；任何关闭主动检测的改动，都必须同步调小锁等待超时，否则兜底失效。

## 答题技巧

1. **按链路答而非按点答**：从「现象 → 定位 → 归属 → 兜底 → 优化」五层展开，比背诵零散命令更有体系感。
2. **主动报版本号**：说出「8.0 起行锁视图迁到 performance_schema」「死锁检测开关自 5.7.15 引入」这类版本锚点，是 P7 的硬证据。
3. **成对记忆**：检测与超时成对（关一个必须调另一个）；data_locks 与 INNODB_LOCKS 成对（8.0 前后）；IS 与 IX 成对（意向锁）。
4. **给数字**：默认超时 50 秒、建议 5~10 秒、检测深度 200、Info 截断 100 字符——具体数字比形容词可信。
5. **止步档位**：能完整说出排查链路三层即达 L4；能再讲清版本差异、兜底开关的耦合关系并给出优化顺序，即达 L5。

## 细节与核心 API

**排查闭环五层（从现象到优化）**：

```sql
SHOW PROCESSLIST;                               -- ① 现象：STATE 含锁字、TIME 异常偏大
SELECT * FROM information_schema.INNODB_TRX;    -- ② 活跃事务 / 持锁时长
SELECT * FROM performance_schema.data_locks;    -- ③ 8.0 加锁类型与被锁数据
SELECT * FROM performance_schema.data_lock_waits;-- ③ 谁等谁（锁等待图）
SELECT * FROM performance_schema.metadata_locks;-- ③ DDL 阻塞（MDL，看 PENDING）
SHOW OPEN TABLES WHERE In_use > 0;              -- ③ 表级占用
```

**兜底机制（成对记忆：检测 ↔ 超时）**：

```ini
innodb_deadlock_detect = ON     # 5.7.15+ 默认 ON；高并发热点写可关闭
innodb_lock_wait_timeout = 5    # 默认 50s，建议 5~10s；关闭检测必须同步调小，否则兜底失效
innodb_rollback_on_timeout       # 决定超时回滚范围（整事务 or 仅当前语句）
```

**优化闭环（先做无副作用的）**：缩短持锁时间 → WHERE/JOIN 命中索引缩小锁范围 → 大查询分页 → 合并查询减少加锁次数 → 加锁操作放事务最后 → 冲突少可用乐观锁。

> 边界：行锁本质与排查四步见 1239；锁谱系（全局锁/MDL/AUTO-INC/IS-IX）见 1233；本卡只讲锁的排查体系与优化闭环。
