# 1826 页置换算法谱系与近似路线取舍 深挖

> 覆盖源 18-26 全文：六种页置换算法按「信息来源」重组为谱系、OPT 作为基准的不可实现性与不可替代性、FIFO 的 Belady 异常机理、精确 LRU 的软件代价与 Clock 的硬件协作、LFU 时间盲区、Random 的工程位置。主卡已给六算法原理与实测，本附录做「谱系视图」「Belady 异常为什么发生」「Clock 与 Redis 近似采样对比」「从缺页率到生产性能」四层深挖。

## 思路与架构

```text
按「用什么信息预测未来」分三条路线
├─ 向前看(不可能): OPT —— 缺页率理论下界, 只做基准
├─ 向后看(可观测的历史)
│   ├─ 时间维度: LRU —— 最久未访问的先淘汰
│   │   ├─ 精确实现: 链表 + 每次访存移动节点 -> 太贵
│   │   └─ 近似实现: Clock(1bit 使用位) / Redis 采样(时间戳)
│   └─ 频率维度: LFU —— 访问次数最少的先淘汰
│       └─ 硬伤: 只看频率不看时间 -> 冷页占坑 -> 需时间衰减
├─ 顺序维度: FIFO —— 只看进入年龄, 与使用无关 -> Belady 异常
└─ 无信息: Random —— 零状态, 性能方差大, 无硬件支持时的退路
```

## 方案取舍
- **OPT 不可实现，为什么还必须讲**：它把「最优」显式化——如果能预知未来，该淘汰哪页。两个不可替代的用途：① 任何算法缺页率的**下界标尺**，论文与调优报告都要报「相对 OPT 的差距」；② 反过来定义了所有实用算法的本质——**都在用可观测的过去预测不可观测的未来**，LRU 用「时间连续性」假设，LFU 用「频率持续性」假设。讲清这层，六个算法就从并列名词变成一棵有根的树 [经验]。
- **Belady 异常的机理**：FIFO 的淘汰决策与页的**使用历史完全无关**，页面的「驻留集合」随帧数变化时，进入顺序的相位会错位——某页在 3 帧时恰好「还没轮到」被换出，4 帧时反而因队列相位变化被换出，缺页数不降反升。经典串 `1,2,3,4,1,2,5,1,2,3,4,5` 实测 3 帧 9 次、4 帧 10 次 [实测]。**LRU/LFU/OPT 属栈式算法（驻留集是帧数的子集嵌套），数学上保证不会异常**——这正是「LRU 优于 FIFO」的严格版本，比「经验上更好」有力得多 [经验]。
- **精确 LRU 贵在哪，Clock 省在哪**：精确 LRU 每次访存要做「查链表 + 删节点 + 头插」三步软件操作，访存路径上插任何软件逻辑都是不可接受的。Clock 的关键洞察是**把维护工作外包给硬件**：MMU 在地址翻译时顺手把使用位置 1，零额外成本；软件只在缺页时才扫位。代价是信息从「精确的访问时序」退化成「自上次扫描后是否被访问过」的 1 bit，近似质量略降但完全够用。**Redis 的近似采样是另一条路**：它没有硬件帮忙，就把时间戳塞进对象头、淘汰时随机抽 5 个比时间——本质都是「用更少的信息换更低的维护成本」，只是 OS 靠硬件、Redis 靠概率，见 1259 [边界]。
- **LFU 的时间盲区与两种修法**：裸 LFU 的计数器单调增长，历史热页「吃老本」。OS 页面层一般不修这个（页面访问模式相对稳定）；应用层必须修——Redis LFU 的做法是**时间衰减**（按距上次访问时长衰减 + 概率性增长），InnoDB 的做法是 **young/old 分区**（新页先进 old 区观察，防一次性扫描污染），两者与「缓存污染」共同构成缓存设计三件套，见 125、`1259-cache-eviction-internals.deep` [边界]。
- **Random 不是笑话**：模拟结果显示局部性强时 Random 缺页率显著差于 LRU，但它的**零状态**意味着不需要任何硬件配合、不受策略被对抗利用（有恶意工作负载能专门构造让 LRU 命中率崩塌的访问序列，Random 无法被针对性攻击）。VAX/VMS 曾用 FIFO+扩展、某些无引用位平台用 Random，都是「按硬件条件选算法」的工程决策 [经验]。

## 答题技巧
- 先立框架再报名字：「六算法按信息来源分三条路线」，一句话把名词题变成理解题 [经验]。
- 用实测数字压轴：FIFO 3 帧 9 次 / 4 帧 10 次的 Belady 反例，报得出数字就是真做过 [实测]。
- 被问「Clock 和 Redis 近似 LRU 区别」→ 答「都是廉价近似，OS 靠 MMU 置使用位、Redis 靠对象内时间戳 + 随机采样」，跨层对比是 P7 惊艳点 [经验]。
- 被问「Linux 用哪个」→ 别答裸 LRU，答 **active/inactive 双链近似 LRU**（页面在两链间按活跃度迁移），体现读过实现 [经验]。
- 主动边界到 `1259-lru-vs-lfu`（应用层近似与缓存污染）、`125-bufferpool-lru-young-old`（分区 LRU）、`188-load-diagnosis.deep`（major fault 与 D 状态归因），构成内存管理全链 [边界]。

## 细节与核心 API

```bash
cat /proc/sys/vm/swappiness        # 0~100，倾向换出的程度（默认 60）
echo 10 > /proc/sys/vm/swappiness  # 降低换出倾向（数据库等常设这个减少延迟抖动）
# 算法演进：
#  OPT（理想，未来最远用）-> FIFO（Belady 异常）-> LRU（欠命中率但贵）
#  -> 近似 LRU（Clock/二次机会）：用引用位环形扫描，近似 LRU 且 O(1)
#  -> 老化算法（老化计数器模拟 LRU）
# Linux 实际：per-zone 的 LRU 双链表（active/inactive）+ 二次机会扫描
# 调优：swappiness 调低 + 加大脏页阈值（dirty_ratio）减少抖动；内存型服务可设 1~10
```
