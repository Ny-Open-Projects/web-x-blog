# 1253 Redis 持久化（五）：三种方式对比与选型

> 分类：Redis | 难度：中 | 题型：对比 | 频率：高 | 关键词：**RDB、AOF、混合持久化、选型、数据安全 vs 性能**

> 原文锚点：第 4~103 段（综合）「RDB/AOF/混合 三者优劣与按安全/性能需求选型」

## 一句话总述
Redis 三种持久化：RDB（全量快照，紧凑、恢复快，但两次快照间可能丢数据）、AOF（追加写命令，丢得少、可秒级，但文件大、恢复慢）、混合（RDB 全量 + AOF 增量，恢复快且丢得少，4.0+）。选型按需求：要高性能选 RDB，要高可靠选 AOF，要兼顾选混合，也可同时开启 RDB+AOF 平衡。

## 面试官视角
对比选型是收口题。考官看你能用一张表说清三者差异，并给出「数据安全优先→AOF/混合，性能优先→RDB，折中→混合」的选型逻辑。能点出「RDB 与 AOF 可同时开启互相兜底」说明你对生产配置有体感。

## 主问答
**Q（面试官原话）：** RDB、AOF、混合持久化怎么选？

1. **RDB**：优点是二进制紧凑、恢复最快、对主进程影响小；缺点是全量快照、频率不能太高，故障会丢两次快照间的数据。
2. **AOF**：优点是记录每次写、数据最安全（取决于刷盘策略）、可秒级；缺点是文件大、恢复需重放命令较慢、写放大。
3. **混合**：RDB 全量 + AOF 增量，恢复快且丢得少，是 4.0+ 的推荐默认；几乎集合两者优点。
4. **选型**：高性能→RDB；高可靠→AOF（everysec）；兼顾→混合；生产常同时开 RDB+AOF 互为兜底。
