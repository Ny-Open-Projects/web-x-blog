# 187 僵尸进程 vs 孤儿进程

> 分类：操作系统 / Linux | 难度：L3 | 题型：对比题 | 频率：中 | 关键词：**僵尸进程**/**孤儿进程**/**wait/waitpid**/**init(PID1) 收养**/**资源浪费**

> 原文锚点：第 21~26 段「僵尸进程与孤儿进程的区别」

## 一句话总述
**僵尸进程**：子进程退出、父进程未调用 `wait`/`waitpid` 回收，残留 task_struct 占用资源（尤其 PID），**会浪费资源**；父进程退出后由 `init`（PID 1）收养并回收。**孤儿进程**：父进程先退出、子进程仍在运行，被 `init`（PID 1）收养并由其收集状态，**不浪费资源**。两者最大区别：僵尸占资源、孤儿不占。

## 面试官视角
这是经典对比题，考「回收机制」而非只背定义。能说清「僵尸因父不 wait、孤儿因父先死、二者都被 init 接管但后果相反」，并点出「僵尸的 PID 泄漏风险」的，加分。

## 主问答
**Q（面试官原话）：** 僵尸进程和孤儿进程有什么区别？

1. **僵尸进程成因**：子进程结束，父进程未 `wait`/`waitpid`，内核保留其退出状态与 task_struct 直至父回收；此期间它已不运行，却仍占着进程表项/PID。
2. **僵尸的危害**：大量僵尸会耗尽 PID 与进程表项，导致无法创建新进程——**浪费资源**；父进程退出后由 `init`（PID 1）接管并回收。
3. **孤儿进程成因**：父进程先于子进程退出，子进程「失去父亲」；内核将其 `ppid` 置为 1，交由 `init`（PID 1）收养，由 init 负责 `wait` 回收。
4. **孤儿无害**：孤儿仍在正常运行、最终由 init 正常回收，**不浪费资源**；与僵尸的「占着不还」形成对照。
5. **排查与避免**：僵尸靠父进程及时 `wait`（或 `SIGCHLD` 信号处理）消除；写服务时 `exec` 起子进程务必 `Wait`，否则积累僵尸（Go 里 `exec.Command` 须 `Wait`）。

## 版本与兼容性
| 维度 | 僵尸进程 | 孤儿进程 |
|------|----------|----------|
| 成因 | 子退父未 wait | 父先退 |
| 收养者 | init(PID1) | init(PID1) |
| 资源 | 占用 PID/进程表 | 正常，不浪费 |
| 后果 | 可能耗尽 PID | 无害 |

## 关键代码
```go
// 孤儿：父退出后子被 init(PID1) 收养
if pid := os.Getpid(); pid == 1 {
    // 当前已是 init，负责收养孤儿
}
// 僵尸：Go 中起子进程却不 Wait，子退出即变僵尸
cmd := exec.Command("true")
_ = cmd.Start()
// 漏掉下面这行 → cmd 退出后残留僵尸直到本进程结束
// _ = cmd.Wait()
```

## 总结与追问预判
核心：**僵尸=父未 wait 占资源、孤儿=父先死被 init 收养无害；二者都归 init 但后果相反**。追问拐向「进程状态机」——备好「僵尸是终止态非睡眠子态」（见 `187-process-states.md`）。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文将僵尸表述为"睡眠态的一种"——严谨地，僵尸是独立终止态（已退出、仅留 task_struct 待回收），并非睡眠子态；本卡修正归类并强调其 PID 泄漏风险。
2. 崩坏词归一：源码将僵尸 / 孤儿 / 进程 / 终端 / init 等音译为多组崩坏词，本卡统一为规范术语。
