# 104 原子操作的使用陷阱与边界

> 分类：Go 并发 | 难度：中 | 题型：陷阱题 | 频率：中 | 关键词：**不对 struct 直接原子、原子不保复合逻辑、高竞争不如锁、atomic.Value 同类型**

> 原文锚点：第 57~66 段引申「原子=变量级互斥；Go 封装 sync/atomic 通用 API；支持类型有限」+ 标准实战陷阱归纳

## 一句话总述
原子操作虽轻，但有清晰边界：**① 不能对 struct 直接原子**（只支持基础标量/unsafe.Pointer，多字段要上锁或聚合进 atomic.Value）；**② 不保证复合逻辑**（"读—判断—写"仍要 CAS 循环或锁）；**③ 高竞争下原子反复重试可能不如一把锁**；**④ 单核也要原子**（编译重排 + 调度抢占仍会交错，不能靠 GOMAXPROCS=1 偷懒）；**⑤ atomic.Value 必须存同类型**否则 panic。一句话背法：**「原子五陷阱：struct 不直接原子、不保复合逻辑、高竞争不如锁、单核也要护、Value 须同类型」**。

## 主问答
**Q（面试官原话）：** 用原子操作有哪些常见陷阱？

**先铺垫（由浅入深第 1 层）**：原子轻量，所以容易被"用过头"——拿它去护不该护的东西。记住一条铁律：**原子只保证"一个变量的读-改-写"不可分割**，超出这个边界全是坑。下面五个就是高频踩点。

1. **类型限制（第 2 层）**：原子只支持 int32/64/uint32/64/uintptr/unsafe.Pointer 与 atomic.Value；对 struct 直接 `atomic.Load(&s)` 编译不过——多字段一致性要上锁，或把整个值塞进 `atomic.Value`（存入类型须一致）。
2. **不保复合逻辑（第 3 层）**：`if atomic.Load(&f)==0 { ... } atomic.Store(&f,1)` 这种"读—判—写"不是原子整体，仍竞态；要 `CompareAndSwap` 循环或上锁。
3. **高竞争代价（第 4 层）**：原子指令锁 cache line，极高竞争下 CAS 自旋重试的 CPU 开销可能超过一把锁——选型以实测为准。
4. **单核也需保护（第 5 层）**：单核下编译重排与调度抢占仍会让 load/add/store 交错，不能靠 GOMAXPROCS=1 省原子。
5. **atomic.Value 同类型（第 6 层）**：`Store` 后必须存同一动态类型，否则下次 `Store` 直接 panic。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| 支持类型 | 标量（int/uint 32/64、uintptr）+ unsafe.Pointer + atomic.Value |
| 复合逻辑 | 必须 CAS 循环或 Mutex，原子本身不保 |
| 高竞争 | CAS 自旋 CPU 开销可能超锁，实测为准 |
| atomic.Value | 同动态类型约束，否则 panic |
| Go 版本 | 陷阱通用于各版本；类型化 API 始于 Go 1.19，本项目实测 Go 1.26.5 |

## 关键代码
```go
package main

import (
	"fmt"
	"sync/atomic"
)

func main() {
	// 陷阱②：读-判-写不是原子整体，用 CAS 循环替代
	var flag int64
	for {
		old := atomic.LoadInt64(&flag)
		if old != 0 {
			break
		}
		if atomic.CompareAndSwapInt64(&flag, 0, 1) { // CAS：整体不可分
			fmt.Println("抢到锁")
			break
		}
	}

	// 陷阱⑤：atomic.Value 必须同类型，否则下次 Store panic
	var v atomic.Value
	v.Store("a")
	// v.Store(42) // panic：与首次存入类型不一致（int != string）

	// 陷阱①：struct 不能直接原子——多字段一致性要 Mutex 或聚合成一个值
	type S struct{ A, B int }
	_ = S{}
	// atomic.LoadInt64(&s.A) 合法，但对整个 S 原子非法
	fmt.Println("原子使用边界已演示")
}
```

## 总结与追问预判
**背这三句就够**：① **原子只保单变量，struct 不直接原子（多字段上锁/聚合进 Value）**；② **"读-判-写"复合逻辑仍竞态，要 CAS 循环或锁**；③ **高竞争下 CAS 自旋可能不如锁；单核也需原子；Value 须存同类型**。
**预判追问**：
- 「什么时候该用锁而不是原子？」→ 复合临界区/多变量一致性（见 105 何时用原子）。
- 「原子和锁到底怎么权衡？」→ 单变量无竞争用原子，高竞争/复合上锁（见 105 原子与锁三大区别）。
- 「CAS 一直失败？」→ 自旋重试烧 CPU，超竞争考虑退化为锁（见 1012 自旋锁）。
