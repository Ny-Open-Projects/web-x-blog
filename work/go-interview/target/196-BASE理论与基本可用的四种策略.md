# 196 BASE 理论与基本可用的四种策略

> 分类：架构设计 | 难度：L2 | 题型：架构题 | 频率：高 | 关键词：**BASE** / **基本可用** / **降级** / **过载保护**
> 原文锚点：第 93~145 段「base理论是CAP中AP延伸…流量消封延迟响应降级过载保护…超时失败故障限流降级」

## 一句话总述
BASE 是 CAP 中 AP 的延伸：基本可用 + 软状态 + 最终一致。实现「基本可用」靠四类策略——流量削峰、延迟响应、服务降级（手动/自动）、过载保护。

## 面试官视角
- **考察意图**：是否会用工程手段保核心链路，而非追求强一致。
- **P5**：能说出降级、限流、削峰几个词。**P6**：说清 BASE 三要素 + 自动降级的触发指标。**P7**：知道降级返回兜底/静态页、知道软状态是容忍短暂不一致的中间态、知道转账四步靠记录状态实现最终一致。
- **红旗答案**：为基本可用牺牲核心功能；把降级当成关全部服务。
- **惊艳点**：自动降级四大触发指标=超时/连续失败次数/突发故障/限流阈值；降级后返回默认值或缓存兜底，而非报错 [经验]

## 主问答
**Q（面试官原话）：** 做不到强一致，秒杀怎么保证基本可用？
**A：**
1. **结论**：走 BASE——基本可用+软状态+最终一致，用削峰/延迟/降级/过载保护保核心。
2. **机制**：削峰用 MQ 排队瞬时流量；延迟响应让请求排队；降级关非核心（广告/审计/风控）；过载保护超限直接拒绝。降级支持手动（配置中心开关）和自动（按负载/RT/QPS 指标）。
3. **边界**：降级只关非核心、保核心下单；软状态允许短暂不一致，最终收敛。
**加分层：** 自动降级靠监控恢复状态，服务恢复即撤降级；强一致可视为最终一致的特例（零延迟窗口）。
