# 173 栈实现全景：双实现 + 选型 + 边界（深卡）

> 分类：数据结构 / Go | 难度：L3 | 题型：体系题 | 频率：中 | 关键词：**栈体系**/**切片栈**/**链表栈**/**选型**/**与运行时栈边界**

> 原文锚点：第 1~54 段「栈的实现全节」

## 思路与架构
栈实现这条线按「**定义 → 双实现 → 选型 → 边界**」四层组织：
- 定义层：FILO，仅栈顶出入，push/pop/peek 三操作。
- 实现层：切片栈（连续内存、随机访问）与链表栈（指针串、增删自由）两种落地。
- 选型层：读多写少→数组栈、写多读少→链表栈，时间复杂度同为 O(1)。
- 边界层：本卡讲的是**用户态数据结构栈**，与 Go runtime 的 goroutine 调用栈（连续可增长内存、调度相关，对应 `420-*`/`1118-*` 等卡）是不同概念，面试别混。

## 方案取舍
- **手撕优先切片栈**：代码短、易写对，但必须点出「截取 pop 内存泄漏」——对应 `173-array-stack.md`。
- **强调指针操作用链表栈**：考 prev 指针衔接与空栈处理，对应 `173-linkedlist-stack.md`。
- **串起来用选型卡**：把两种实现的优劣收敛成「读写比重」一句话，对应 `173-stack-select.md`。
- **不碰 runtime 栈**：goroutine 栈增长、逃逸分析等交给 runtime 专题，本深卡只在边界声明点一句。

## 答题技巧
1. 开场给定义：**FILO、仅栈顶出入**——一句话立住。
2. 二选一先写切片栈（最稳），主动补「防内存泄漏」显深度。
3. 被要求「另一种实现」时切链表栈，重点讲 head 即栈顶、push 头插。
4. 收尾用选型口诀「读多写少数组、写多读少链表」做总结，并点明这是用户态数据结构栈、区别于 Go 运行时栈。
5. 加分项：提「sync.RWMutex 让 peek 走读锁、push/pop 走写锁」体现并发意识。

## 细节与核心 API

```go
// 切片实现栈（最常用，均摊 O(1)）
type Stack struct{ data []int }
func (s *Stack) Push(v int) { s.data = append(s.data, v) }
func (s *Stack) Pop() (int, bool) {
    if len(s.data) == 0 { return 0, false }
    v := s.data[len(s.data)-1]; s.data = s.data[:len(s.data)-1]; return v, true
}
func (s *Stack) Top() (int, bool) {
    if len(s.data) == 0 { return 0, false }
    return s.data[len(s.data)-1], true
}
// 数组+指针实现（固定容量，无扩容）
type FixedStack struct { a [100]int; n int }
func (s *FixedStack) Push(v int) bool { if s.n >= len(s.a) { return false }; s.a[s.n] = v; s.n++; return true }
// 注意 Pop 不缩容切片底层数组；长期持有大底层数组可 copy 缩容或手动置 nil 释放
```
