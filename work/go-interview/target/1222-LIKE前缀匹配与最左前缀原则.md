# 1222 LIKE 前缀匹配与最左前缀原则

> 分类：MySQL 索引 | 难度：中 | 题型：原理 | 频率：高 | 关键词：**LIKE、最左前缀、索引失效、范围查询、B+树有序性**

> 原文锚点：第 1~4 段「B+树 最左前缀原则、联合索引断层失效、LIKE 须前缀匹配」

## 一句话总述
B+ 树索引遵循「最左前缀原则」：联合索引必须从最左列开始匹配，中间断层则失效；对索引字段做 LIKE 模糊查询也必须「从前缀开始」（`'x%'`）才能用索引。若写成 `'%x%'` 或 `'%x'`（非前缀），常规情况下无法利用索引有序性，会走全表扫描。但「覆盖索引」存在例外（见后续卡）。

## 面试官视角
LIKE 与索引是经典题。考官看你能不能讲清：① 最左前缀原则在两个场景的体现（联合索引断层 / LIKE 非前缀）；② 为什么 `'x%'` 能用而 `'%x%'` 不能——本质是 B+ 树的有序性只能做「前缀/范围」定位，无法从中间或末尾反推；③ 能否抛出「覆盖索引例外」作为加分。

## 主问答
**Q（面试官原话）：** LIKE '%x%' 一定会导致索引失效吗？

1. **最左前缀（联合索引）**：联合索引 `(a,b,c)` 必须从 a 开始匹配，a 与 c 之间断了 b，则 c 用不上索引。
2. **最左前缀（LIKE）**：对索引列 LIKE 必须从前缀匹配，`'x%'` 可走索引（range），`'%x%'`/`'%x'` 违反前缀原则。
3. **常规失效**：非前缀 LIKE 无法利用 B+ 树有序性定位，优化器只能全表扫（type=ALL）。
4. **例外预告**：当查询满足「覆盖索引」时，即便非前缀 LIKE 也可能走二级索引（type=index），详见 1222。

## 版本与兼容性
| 写法 | type | 是否用索引 |
|------|------|------------|
| 'x%' | range | 是 |
| '%x%' | ALL/index | 通常否（覆盖时 index） |

## 关键代码
```sql
SELECT * FROM user WHERE name LIKE '张%';   -- 前缀，range
SELECT * FROM user WHERE name LIKE '%张%';  -- 非前缀，常规 ALL
```

## 总结与追问预判
核心：**LIKE 须前缀匹配（'x%'）才能用 B+ 树有序性；'%x%' 常规失效，但覆盖索引下可走二级索引全扫**。追问必接「为什么覆盖索引能破例」（见 1222）。
