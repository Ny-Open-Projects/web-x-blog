# 903 len(string) 是字节数，不是字符数

> 分类：Go 基础 / string | 难度：L3 | 题型：代码题 | 频率：高 | 关键词：**len、字节数、字符数、UTF-8、中文三字节**

> 原文锚点：第 5~15 段「s1 的值是 ABC，s2 的值是中文两个字，我们分别打印它的长度…得到的是三和六，也就是 s1 的长度是三，s2 的长度是六…对于中文这两个字，它长度是六，由此可见 Go 语言里面的 len 不能简单的理解为字符串的字符个数…字符串的 length 其实是指这个字符串中的字节的个数，而非是字符的个数…在 UTF-8 编码里面一个中文字符是三个字节，所以两个中文字符就是六个字节」

## 一句话总述
Go 中 `len(string)` 返回的是**字节数**而非字符数：`"ABC"` 为 3，`"中文"` 为 6——因为 UTF-8 下一个中文字符占 **3 个字节**。

## 面试官视角
P6 会以为 `len("中文")==2`；P7 要立即纠正**「len 是字节数」**并说明 UTF-8 变长编码的原因，且能给出**获取真实字符数的正确写法**（转 `[]rune`）。

## 主问答
**Q（面试官原话）：** `len("中文")` 等于多少？为什么不是 2？

1. **实测结果**：`"ABC"` 的 `len` 为 **3**，`"中文"` 的 `len` 为 **6** `[源码]`。
2. **len 的真实语义**：字符串的 `len` 指**字节的个数**，而**非字符的个数** `[源码]`。
3. **因此不能按字符理解**：Go 里 `len` **不能简单理解为字符个数** `[源码]`。
4. **中文为何是 3 字节**：在 **UTF-8 编码中，一个中文字符占三个字节**，故两个中文字符为 **6 字节** `[源码]`。
5. **英文为何是 1 字节**：ASCII 范围内的字符在 UTF-8 中只占 **1 字节**，故 `"ABC"` 为 3 `[源码]`。
6. **要字符数怎么办**：把字符串转成 **rune 切片**再取长度，即可得到真实字符数 `[经验]`。

## 关键代码
```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s1 := "ABC"
	s2 := "中文"

	fmt.Println(len(s1)) // 3：3 个 ASCII 字符，各 1 字节
	fmt.Println(len(s2)) // 6：2 个中文字符，各 3 字节

	// 获取真实字符数（Unicode 码点数）：两种方式
	fmt.Println(len([]rune(s2)))              // 2
	fmt.Println(utf8.RuneCountInString(s2))   // 2（更省内存，不分配切片）

	// 注意：按下标取到的是字节，不是字符
	fmt.Printf("%c %d\n", s2[0], s2[0])      // 取到的是第一个字节
}
```

## 总结与追问预判
**「len 是字节数」是 Go 字符串的第一道坎**。追问常是「那怎么遍历字符」——答案是用 `for range` 或转 `[]rune`，详见同批 903-rune-iteration。编码细节见 903。

## ⚠️ 原文纠错
1. 事实核校：len("ABC")=3、len("中文")=6、len 指字节数、UTF-8 中一个中文 3 字节——均与 Go 与 UTF-8 规范一致 `[经验]`。
2. 补充：获取字符数推荐用 `utf8.RuneCountInString`，它**不分配切片**；`len([]rune(s))` 会做一次转换并分配内存，在大字符串或高频路径上应避免 `[经验]`。
3. 崩坏词归一：源码将字节、字符、长度、中文等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
