# 1017 goroutine 循环变量

> 分类：并发模型 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**goroutine** / **循环变量** / **per-iteration scope**
> 原文锚点：第 55~75 段「go 启动闭包读 i，调度顺序不定，输出最后值或不定值」

## 一句话总述
`go` 启动的闭包异步执行，读到的循环变量 `i` 是**共享的那一个**；旧版 Go 每轮复用同一变量，调度顺序不定 → 输出全 10 或乱序——Go 1.22 起每轮变量独立，该坑被修复。

## 面试官视角
- 意图：是否掌握 goroutine + 循环变量的竞态本质，以及 Go 1.22 的语义翻转。
- P5 知输出不定 / P6 说清异步 + 共享变量 / P7 知 1.22 翻转且旧代码仍兼容。
- 红旗：以为 goroutine 一定按顺序读 i；以为设 GOMAXPROCS=1 就安全。
- 惊艳点：同段代码 go1.21 输出全 10、go1.22 输出 0..9（顺序不定）`[源码]` release notes。

## 主问答
**Q（面试官原话）：** for 里 go 打印 i，为什么打出来都是 10 或者乱的？
**A：**
1. **结论**：旧版循环变量 `i` 全程一个地址，闭包读的是"终值"；goroutine 异步调度，读到哪轮看运气。
2. **机制**：`i` 在循环外创建、每轮覆盖；闭包捕获该变量，执行晚于迭代，多半读到结束后的 10。
3. **边界**：Go 1.22+ 每轮 `i` 是独立变量，闭包各自捕获当轮值 → 输出 0..9（仍并发无序）。
**加分层：** GOMAXPROCS=1 只是让循环抢满 CPU 延迟调度，属巧合非保证，勿依赖。

## 关键代码
```go
// 示意，未验证：旧版典型坑
for i := 0; i < 10; i++ {
    go func() { println(i) }() // 旧版多打印 10；1.22+ 打印 0..9
}
```

## 总结与追问预判
- 异步 + 共享循环变量 → 读终值/乱序；1.22 每轮独立修复。
- 预判：正确修法 → 见 1017。

## ⚠️ 原文纠错
原文将"循环变量每轮复用同一变量"作为**普适事实**叙述，未提示版本边界。正确结论：**Go 1.22 起 for 与 range 的循环变量改为每轮独立（per-iteration scope）**，旧版（≤1.21）才是共享单变量。现在面试应主动区分两版本：旧代码踩坑，1.22+ 该写法已自愈，但仍推荐显式传参。
