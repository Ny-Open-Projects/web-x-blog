# 1310 ES 机架感知与同机规避

> 分类：架构/ES | 难度：L2 | 题型：方案题 | 频率：中 | 关键词：**机架感知** / **node.attr.zone** / **same_shard.host** / **多可用区**
> 原文锚点：第 22~50 段「单机多节点须禁止同分片主副同机(same_shard.host=false)；机架感知 zone 属性避开同机架/同机房；多可用区部署；master 至少 3 个且分属不同 AZ」

## 一句话总述
分片副本不共节点只是第一步，部署层还要防"同机/同机架/同机房"导致整片丢失：单机多节点要设 `cluster.routing.allocation.same_shard.host=false` 禁止同分片主副同主机；用**机架感知**（`node.attr.zone` + `cluster.routing.allocation.awareness.attributes=zone`）让副本避开同一 zone；跨多可用区时把 master 节点（至少 3 个）分布到不同 AZ，避免单 AZ 故障选不出主。

## 面试官视角
- 意图：考察"HA 是否落到部署拓扑"，这是运维实战题。
- P5 知道分片分布；P6 能讲 same_shard.host 与机架感知；P7 能讲"master 跨 AZ 部署 + 至少 3 master 防脑裂/选不出主"的全可用区容灾。
- 红旗：以为副本在不同节点就够了；不知道同机多实例仍可能共机。
- 惊艳点：点出"master 至少 3 个且分属不同 AZ，否则单 AZ 宕选不出主"。

## 主问答
**Q：** 怎么让 ES 副本真正高可用（部署层）？
**A：**
1. **同机规避**：一台机器跑多个 ES 实例时，默认可能把同分片主副放同机；设 `cluster.routing.allocation.same_shard.host=false` 禁止，否则单机宕整片全失。
2. **机架感知**：给每个节点配 `node.attr.zone=<机房/机架>`，集群设 `cluster.routing.allocation.awareness.attributes=zone`，ES 分配副本时自动避开同 zone 节点——同理规避同机架/同机房整片丢失。
3. **master 跨 AZ**：若设独立主节点，至少 **3 个**且分属不同可用区；单 AZ 不可用后仍剩 ≥2 master 可选出主，避免"选不出主"。

## 关键代码
```go
// 通过 ES REST API 开启机架感知（避免同 zone 放同分片主副）
func setRackAwareness(base, zone string) error {
    // 每个节点 yaml: node.attr.zone: <机房>; 集群级开启 awareness
    body := `{"persistent":{"cluster":{"routing":{"allocation":{
        "awareness":{"attributes":"zone"}}}}}}`
    req, _ := http.NewRequest(http.MethodPut,
        base+"/_cluster/settings", strings.NewReader(body))
    req.Header.Set("Content-Type", "application/json")
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return err
    }
    defer resp.Body.Close()
    // 另需 node.attr.zone + same_shard.host=false 才完整生效
    return nil
}
```
