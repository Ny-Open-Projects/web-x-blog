# 112 服务质量 QoS 四大指标：可用性/吞吐/延迟/丢失

> 分类：面试策略/架构 | 难度：L2 | 题型：概念题 | 频率：中 | 关键词：**可用性四个九**/**TPS/QPS/RPS**/**p99 延迟**/**丢失率**
> 原文锚点：第 32~54 段「QoS 四指标：可用性/吞吐量/延迟/丢失」

## 一句话总述
衡量服务质量的 QoS 看四类指标：**可用性**（停机越少越高）、**吞吐量**（单位时间处理量）、**延迟**（用 p99 等分位数描述尾部体验）、**丢失**（失败/丢包）。回答性能题时结果要落到这些可量化维度。

## 面试官视角
- 考察意图：是否用标准化指标描述性能，而非「快/慢」模糊词。
- 分档：P5 能背出四类指标名；P6 算得出四个九对应年停机、分得清 TPS/QPS/RPS、讲得清 p99 含义；P7 知 p99 比均值更抗异常值、知五个九代价陡增。
- 红旗答案：把 QPS 和 TPS 混为一谈且说不清区别；用平均值代替分位数掩盖长尾。
- 惊艳点：现场算 99.99% 年可用=8760h×0.01%≈52.6 分钟；强调 **p99 排除极端值、刻画绝大多数请求体验** [经验]。

## 主问答
**Q（面试官原话）：** 除了接口响应，还有哪些指标衡量服务质量？
**A：**
1. **可用性（Availability）**：以可用时间占比衡量，周期常取一年。**四个九=99.99%**，年不可用仅 8760h×0.0001≈**0.876h≈52.6 分钟**；**五个九=99.999%** 仅约 **5.26 分钟**。不可用时间越短可用性越高，五个九极难达成 [经验]。
2. **吞吐量（Throughput）**：单位时间处理请求数。**TPS**=每秒事务数（评数据库交易基准）；**QPS**=每秒查询数；**RPS**=每秒请求数（通常与 QPS 同义）。三者口径不同但都描述「处理能力」[经验]。
3. **延迟（Latency）**：常用 **p99 分位数**——99% 的观测延迟 ≤ 该值，仅 1% 更差；同理 p95/p90。p99=100ms 即正常情况 99% 请求百毫秒内返回。**p99 比平均值更稳**，因排除极端值、避免异常拉偏整体 [经验]。
4. **丢失（Loss）**：单位时间内请求处理失败个数或网络丢包个数，含存储丢失、数据处理异常中断导致的丢失等 [经验]。

## 关键代码

```go
// p99 分位数：排序后取 99% 位置，刻画尾部延迟（比均值抗异常）
func p99(samples []time.Duration) time.Duration {
    s := append([]time.Duration(nil), samples...)
    sort.Slice(s, func(i, j int) bool { return s[i] < s[j] })
    return s[int(float64(len(s))*0.99)]
}

// 四个九可用性 → 年停机分钟数
func downtimeMinutes(availability float64) float64 {
    yearHours := 365 * 24.0 // 8760h
    return yearHours * (1 - availability) * 60
}
// downtimeMinutes(0.9999) ≈ 52.6 分钟；downtimeMinutes(0.99999) ≈ 5.26 分钟
```
