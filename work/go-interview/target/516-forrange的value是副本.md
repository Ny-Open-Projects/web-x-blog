# 516 for range 的 value 是副本：改 v 不动原值，大元素用下标避复制

> 分类：Go 陷阱 / for range | 难度：L3 | 题型：陷阱题 | 频率：中 | 关键词：**value 副本** / **不改原值** / **大元素复制** / **单变量+下标** / **s[i]**
> 原文锚点：第 10~37 段「for range value是副本(与原元素两份);循环内v++不改原slice/array;大元素遍历用单变量+下标s[i]直接取原值地址避免复制」

## 一句话总述
`for range` 的 `v` 是**独立副本**，与原始元素是两份数据：循环内对 `v` 自增、改写都不影响原 slice/array。遍历**大元素类型**（大 struct/大数组）时，双变量每次复制元素代价高，应改用**单循环变量 + 下标 `s[i]`** 直接按索引访问原值，避免这次复制（性能角度，详见 1112）。

## 面试官视角
- 意图：区分"副本语义"的两层影响——① 改 v 不动原值（正确性）② 大元素复制开销（性能）。
- P5 知 v 是副本、改 v 不动原；P6 知大元素用单变量+下标避复制；P7 能讲清"副本"在这两种场景的不同后果与取舍。
- 红旗：以为循环内改 v 会改原切片；或在大 struct 数组上无脑双变量不测性能。
- 惊艳点：把"副本"串成两条线——正确性问题（取地址陷阱 516-range-address-trap）与性能问题（大元素复制 1112）`[边界]` 见 1112（基准/大元素复制性能）、516-range-address-trap（取地址陷阱）。

## 主问答
**Q（面试官原话）：** for range 里改 v、大元素遍历要注意什么？
**A：**
1. **v 是副本、两份数据**：`for _, v := range s` 的 v 与原元素是两份，循环内 `v++` 等改写**不影响**原 slice/array。
2. **大元素复制开销**：元素是大型 struct/数组时，每次迭代把元素复制给 v，代价 = 元素尺寸 × 次数；应改用单变量 `for i := range s` 后 `s[i]` 直接访问原值，避开复制。
3. **小元素可忽略**：元素是小 header 类型（slice/string/接口，十来字节）时复制代价可忽略，不必刻意规避。
4. **与取地址陷阱关联**：正因为 v 是副本且同址复用，才引出 516-range-address-trap 的"全得最后值"问题——两条线同源。

## 关键代码
```go
package main

import "fmt"

func main() {
	s := []int{0, 1, 2, 3}
	// v 是副本：循环内自增不改原切片
	for _, v := range s {
		v++
	}
	fmt.Println(s) // [0 1 2 3] 不变

	// 大元素遍历：单变量 + 下标取原值，避免复制
	big := [1024]int{}
	for i := range big {
		_ = big[i] // 直接按索引访问，不复制元素
	}
}
```

## 总结与追问预判
- v 是副本两条线：不改原值（正确性）、大元素复制（性能）；大元素用 s[i]。
- 预判：取地址陷阱 → 见 516；大元素复制基准 → 见 1112；指针数组 nil → 见 516。
