> 原文锚点：第 1~56 段「本节呢我们来看看 TCP 在哪些情况下会丢数据…那如果我们还想保证应用层的消息可靠性，那就需要应用层自己去实现逻辑做保证」（TCP 可靠机制概述 → 五大丢包场景 → 传输层可靠不等于应用层可靠）

## 一句话总述
TCP 虽然内置「错误检测 / 重传 / 流量控制 / 拥塞控制」保证**传输层**可靠，但在**建连队列溢出、网卡队列/驱动、收发缓冲区满（零窗口）、中间网络**四类环节仍会丢数据；且 TCP 只保证「A 的传输层 → B 的传输层」，**不保证抵达应用层**——应用层可靠性必须自己实现。

## 面试官视角
这题考「TCP 可靠」的边界认知，很多人背完「TCP 可靠」就以为不会丢。考点：① 能枚举 TCP 实际会丢数据的几类场景；② 每类能不能对应到排查命令（netstat -s / ifconfig / MTR）；③ 最关键——**传输层可靠 ≠ 应用层可靠**这条边界。能说出这条边界的人明显更高阶。

## 主问答
**Q（面试官原话）：** TCP 不是可靠传输吗？那它还会在哪些情况下丢数据？

**A：**
1. **建连阶段队列溢出丢包**：三次握手时服务端先建**半连接队列**（收到 SYN 后），完成握手转入**全连接队列**（等 `accept` 取走）。两个队列任一满，新包被丢弃；现象可在 `netstat -s` 看到 `ListenOverflows` / `ListenDrops`。
2. **网卡队列/流量控制丢包**：网卡处理能力有上限，突发流量在网卡队列（`txqueuelen`）排队，队满即丢；`ifconfig` 中某网卡 `drop` 计数 > 0 即证据，可调大 `txqueuelen`。
3. **网卡/驱动硬件丢包**：网线质量差、接触不良、网卡性能不足或驱动 bug，属于物理层丢包。
4. **接收缓冲区满（零窗口）丢包**：对端接收缓冲区满会通告**零窗口**让发送方停发；若发送方仍强行发数据，则被丢弃。内核 5.9+ 可在 `/proc/net/snmp` 的 `TCPBacklogDrop` 看到。
5. **中间网络丢包**：A、B 间链路长，经过路由器/交换机/光缆，任一节点都可能丢；用 `ping` 或 `mtr -u -r 目标` 看逐跳 `%loss`。

## 版本与兼容性
- **内核版本差异**：`/proc/net/snmp` 的 `TCPBacklogDrop`（接收队列满丢包计数）需 **Linux 5.9+** 才支持；老内核该字段不存在，需用 `netstat -s` 的 `TCPBacklogDrop`/丢包相关行替代。
- `netstat -s` / `ifconfig` / `mtr` 为通用诊断手段，跨发行版可用；`txqueuelen` 调整用 `ifconfig <if> txqueuelen 2000`。
- 该知识**与编程语言无关**，是内核/网络栈层面事实。

## 关键代码

```go
// 演示「TCP 只保证到对端传输层(内核 recv buffer)，不保证应用层读到」
// 服务端：accept 后若应用迟迟不 Read，数据只停在内核接收缓冲区
func server() {
	ln, _ := net.Listen("tcp", ":8080")
	for {
		c, _ := ln.Accept() // 全连接队列取出；队列满则客户端握手包被丢弃
		go func(c net.Conn) {
			buf := make([]byte, 4096)
			// 若此处不读，对端发的数据堆积在 recv buffer，
			// 缓冲满 → 零窗口 → 对端仍发则丢包
			_, _ = c.Read(buf)
		}(c)
	}
}

// 客户端：写满发送缓冲区且对端零窗口时，阻塞写会等、非阻塞写返回错误
func client() {
	c, _ := net.Dial("tcp", "server:8080")
	_, err := c.Write([]byte("payload"))
	if ne, ok := err.(net.Error); ok && ne.Timeout() {
		// 超时/窗口满，需应用层重传或降级
	}
}
```

## 总结与追问预判
收口：**TCP 可靠是「传输层」可靠，五类环节仍可能丢（队列溢出/网卡/缓冲区零窗口/中间网络），且它不保证数据到达对端应用层**。预判追问：① 每类场景的具体排查命令 → 1848.md`（队列/缓冲区）与 `1848-network-nic-loss.md`（网卡/中间网络）；② 应用层怎么自保（消息确认/重传/幂等）。把「传输层≠应用层」这句话抛出来，是这题的高阶收尾。

> **[经验]** 面试最容易被追问的一句话是「TCP 可靠到哪一层」——标准答：**只保证 A 机器传输层 → B 机器传输层的字节流可靠有序，不保证对端应用进程真正读到**。若业务要应用层不丢（如支付指令），必须在应用层做确认/重传/幂等，不能依赖 TCP。
