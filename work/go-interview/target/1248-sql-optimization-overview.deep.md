# 1248 SQL 优化经验全景（一）：设计层 → 查询层 → 版本细节 → 编写习惯

> 分类：MySQL · 优化全景 | 难度：L3 | 题型：深挖 | 关键词：**表设计** / **索引失效** / **版本差异** / **编写习惯**
> 原文锚点：第 1~67 段「表设计 + 索引失效 + 版本例外 + 编写习惯（长连接/TRUNCATE/深度分页）」

## 思路与架构
SQL 优化分四层，本波聚焦前三层未被覆盖的真 gap，编写习惯层与既有卡互补：
1. **设计层（本卡组 1248-主1）**：类型恰当 / NOT NULL / 默认值 / date→int。既有 1215 讲 compact 行格式 NULL 存储，本卡讲"设计建议 why"。
2. **查询层索引失效（1248-主2）**：隐式类型转换 + OR 规则。既有 1221/1222 汇总了函数/最左前缀/覆盖索引，本卡补"隐式转换"与"OR 两字段都索引"两个具体坑。
3. **版本细节（1248-主3）**：8.0 范围列后索引仍有效 + IS NULL/IS NOT NULL/NOT IN 规则。既有 1222 讲最左前缀基础，本卡补版本例外。
4. **编写习惯层（互补不重产）**：长连接（见 129-querycache）、TRUNCATE vs DELETE（见 1225）、深度分页改造（见 1246-deep-paging）。

## 答题技巧
- 答 SQL 优化按"设计→索引→版本→习惯"四层递进，先说设计前移最省力。
- 易混点：范围列后失效是**老版本**经验，8.0 以 EXPLAIN 为准；隐式转换本质是对列套函数。
- 口诀收尾：全值匹配我最爱，最左前缀要遵守；索引列上少计算，字符引号不能丢；不等空值还有 OR，索引失效要注意。
