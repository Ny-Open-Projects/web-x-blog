## 按分类背诵

### Python 语言/内置方法（1 张）

- **[L1/中] 395 list.reverse() 与 reversed()：一个原地、一个返回新序列** — `list.reverse()` 是**原地反转、返回 `None`**；`reversed(s)` 是**内置函数、返回一个反向迭代器、不改原对象**；想要新列表就写 `list(reversed(s))` 或切片 `s[::-1]`。

### Python 语言基础（2 张）

- **[L2/高] 301 Python 是动态强类型语言：两个正交的坐标** — **Python 是「动态 + 强类型」语言：类型在运行期确定（动态），且绝不偷偷做隐式类型转换（强类型）——这两个概念正交，混淆它们是高频送分题。
- **[L3/中] 303 Monkey Patch：运行期的属性替换** — **Monkey patch = 不改源码，在运行期把模块/对象的属性换成自己的实现——威力与代价同源：改的是全局可见的对象，影响所有调用方。

### Python/内存（4 张）

- **[L2/高] 465 Python 垃圾回收总览** — CPython 的垃圾回收以 **引用计数（reference counting）为主**，**标记清除（mark-sweep）+ 分代回收（generational）为辅**：引用计数处理绝大多数对象，标记清除解决它搞不定的**循环引用**，分代回收提升回收效率。
- **[L2/高] 466 引用计数机制详解** — CPython 给每个对象维护一个 **`refcount`**：被引用 +1、不再被引用 -1，**归零即回收**。`del` 只是**减计数**而非销毁；`sys.getrefcount` 可查看，但**小整数对象池**会让某些对象的计数"诡异"偏大。
- **[L3/高] 467 循环引用与标记清除** — **循环引用**（如 `a` 引用 `b`、`b` 引用 `a`）让双方的引用计数**永不归零**，引用计数无能为力，造成内存泄露；CPython 用**标记清除**从**根对象**出发遍历引用图，把**不可达**的孤立环标灰并回收。
- **[L3/中] 468 分代回收（Generational GC）** — CPython 把对象按"年龄"分**三代（第 0/1/2 代）**，各代用**双向链表**维护；新对象进第 0 代，**达到阈值**才触发对应代的标记回收，没被回收的晋升到更老代。阈值由 `gc.get_threshold()` 返回（默认 `(700, 10, 10)`）。

### Web 安全（2 张）

- **[L3/高] 524 SQL 注入与防范** — **SQL 注入 = 攻击者构造特殊输入拼进 SQL，使后端执行恶意语句**（如 `'--` 注释掉密码校验）；根因是**直接拼接 SQL 且不过滤**。修复用**参数化查询（占位符 + 元组传参）**，防范核心原则"永远不信任用户输入"。
- **[L3/高] 525 XSS 跨站脚本攻击（Cross-Site Scripting）** — **XSS = 攻击者把恶意 JS 注入页面，其他用户浏览时脚本在其浏览器执行**（如盗取 `document.cookie` 冒用账号）；分**存储型（持久，存库后他人浏览触发）**与**反射型（非持久，URL 参数 + 诱导点击）**。

### Web 架构（2 张）

- **[L2/中] 526 前后端分离** — **前后端分离 = 后端只提供数据接口（JSON），不再渲染模板；前端取数后自行渲染展示**。相比传统 MVC（后端渲染 HTML 返回浏览器），它让前后端解耦、接口可跨端复用，但单页应用对 SEO 不友好。
- **[L3/高] 527 RESTful API 设计** — **RESTful 是一种以"资源"为中心的 Web 软件架构风格**（Roy Fielding 提出）：把一切抽象为资源（用 URI 标识），用 **HTTP 动词（GET/POST/PUT/DELETE）对资源做增删改查**实现状态转移，接口无状态、返回 JSON。它**不是规范也不是强制约束**。

### Web 框架（4 张）

- **[L2/高] 520 WSGI 规范：Web 服务器与 Python 框架的桥梁** — **WSGI 是 Python Web 服务器与 Web 应用/框架之间的一套标准网关接口（PEP 3333）**：应用实现"接收 environ 字典 + start_response 回调、返回可迭代字节序列"的可调用对象，Server 据此调用它——于是任意框架能跑在任意 WSGI Server 上。
- **[L2/高] 521 Python Web 框架对比：Django vs Flask vs Tornado** — **三大主流 Python Web 框架**：Django 大而全（内置 ORM/Admin、插件丰富）；Flask 微框架（灵活、插件组合，但结构不统一）；Tornado 微框架 + 异步网络库（轮子少、需自己造）。
- **[L2/中] 522 Web 框架的 MVC 模式** — **MVC 是 Web 框架组织代码的经典范式**：Model（数据与 DB 交互）、View（展示/模板渲染）、Controller（收参、粘合 Model 与 View）；请求流是 URL 路由 → Controller → Model → View。前后端分离后 View 退化为只做序列化。
- **[L2/中] 523 ORM：对象关系映射** — **ORM（Object Relational Mapping）把数据库表/行映射成程序里的对象**，让"用业务模型操作数据"取代"手写 SQL"；Python 里 SQLAlchemy 已成事实标准，另有 Django 内置 ORM、轻量 Peewee。

### 工程/规范（1 张）

- **[L1/中] 320 Python 之禅与"优雅代码"的可执行标准** — `import this` 输出的是 Tim Peters 编写的 19 条设计哲学；它不是装饰，而是**拿不准时用来裁决编码取舍的默认规则**。

### 工程化/测试（3 张）

- **[L1/中] 345 什么是单元测试，为什么动态语言更该写** — 单元测试针对**最小单元**（函数/类）做正确性检验、自底向上保证质量；它的价值有三——**验证底层逻辑、回归防改坏、反过来逼你把设计写简单**。
- **[L2/中] 346 测试用例怎么设计：正常值 / 边界值 / 异常值** — 用例按**等价类划分**设计，必须覆盖**正常值、边界值、异常值**三类；`pytest 文件名` 会自动收集 `test_*.py` 中所有 `test_` 开头的函数并执行。
- **[L2/中] 347 用 mock 隔离外部依赖，用 coverage 看覆盖** — `unittest.mock` 把外部依赖（网络、数据库、时钟）**打桩替换**成可控返回值，让测试保持纯净、快速、可重复；`coverage` 度量覆盖情况，但**覆盖率不是目标**。

### 并发（6 张）

- **[L2/高] 454 线程安全与 i+=1 陷阱** — **线程安全**=多线程下正确访问共享数据并得正确结果；**`i += 1` 非线程安全**，因它编译成"读-加-写"多步字节码，中途可被切换导致更新丢失。
- **[L2/高] 455 线程同步之锁（互斥量）** — **锁（互斥量）**保证同一时刻只有一个线程进入**临界区**；Python 用 `threading.Lock`，`with lock` 持有期间其他线程阻塞，从而把 `i += 1` 这类非原子操作变安全。
- **[L2/中] 456 线程同步之信号量（Semaphore）** — **信号量（Semaphore）**用**计数器**控制同时进入临界区的线程数量（N 个）；与锁的区别是：锁只允许 **1** 个，信号量允许 **N** 个——常用于连接池、限流。
- **[L2/中] 457 线程同步之事件（Event）与三者对比** — **Event** 是线程间的**信号通知**机制：一个线程 `set()` 唤醒等待的线程，`wait()` 阻塞等待。它与**锁（互斥，1 个）**、**信号量（限流，N 个）** 共同构成 Python 线程同步三件套，定位不同。
- **[L2/高] 459 Python 多线程：threading 模块** — Python 多线程用 **`threading.Thread`** 创建，`start()` 启动、`join()` 等待结束；配合 **`threading.Lock`** 保护共享数据，适合 **IO 密集型** 任务。
- **[L2/高] 460 Python 多进程：multiprocessing 模块** — CPU 密集型任务用 **`multiprocessing.Process`** 启多进程，绕过 **GIL** 真正并行；其 **API 与 `threading` 几乎一致**，底层靠 `os.fork` 复制进程。Web 服务（gunicorn/uWSGI）即用 master-slave 多进程模型。

### 并发/GIL（3 张）

- **[L2/高] 333 什么是 GIL，CPython 为什么要有它** — GIL 是 CPython 解释器上的一把**互斥锁**，同一时刻只允许**一个线程执行字节码**；它的起因是用最省事的办法保护**非线程安全的引用计数内存管理**。
- **[L2/高] 334 为什么有 GIL 还能用 Python 写 Web 后端** — GIL 会在**阻塞 IO 期间被释放**并切换到其他线程，因此**IO 密集**的 Web 服务仍能靠多线程/协程拿到并发收益，而**CPU 密集**任务几乎吃不到多核。
- **[L3/中] 335 GIL 是怎么被让出来的：切换间隔** — 持锁线程在**切换间隔到期**或**进入阻塞调用**时放锁，其他线程再竞争获取——CPython 早期按"执行 N 条字节码"让出，**3.2 起改为按时间间隔**（默认 5ms）。

### 并发/协程（3 张）

- **[L3/中] 342 基于生成器的协程：send / throw / 预激** — PEP 342 给生成器加上 `send()` / `throw()` / `close()`，让 yield 从"单向产出"变成**双向通道**——这就是 Python 2 时代的**基于生成器的协程**，且必须**先预激**才能 send。
- **[L2/低] 343 @coroutine 装饰器只是帮你预激** — `@coroutine` 装饰器唯一的作用就是**自动预激**——包装后调用协程函数直接返回"已经跑到第一个 yield"的生成器，省掉每次手写 `next(c)`。
- **[L3/高] 344 生成器、生成器协程、原生协程，面试怎么区分** — 三代演进：**生成器**（yield 产出值）→ **基于生成器的协程**（PEP 342，yield + send 双向）→ **原生协程**（3.5+，`async def` / `await`，由事件循环调度）。今天说"协程"默认指最后一种。

### 并发/线程安全（2 张）

- **[L3/高] 336 有了 GIL，为什么 n += 1 还会算错** — GIL 只保证**单条字节码**不被打断，而 `n += 1` 是**读—改—写三步**，中间可能被切走导致**丢更新**——**GIL 不等于线程安全**。
- **[L3/中] 337 用 dis 判断一个操作是不是原子的** — `dis.dis()` 把函数反编译成字节码，**能一条条数出来你写的语句用了几条指令**——只有**单条指令**完成的才是原子的，多指令的都可能被切走。

### 并发/选型（1 张）

- **[L3/高] 338 想绕开 GIL，有哪些路线、怎么选** — 先分 **CPU 密集还是 IO 密集**：CPU 走**多进程/进程池**或把热点下沉到 **C 扩展/Cython**，IO 走**多线程或协程**；没有一条路线是免费的。

### 性能/排障（1 张）

- **[L2/中] 339 怎么定位 Python 程序的性能瓶颈** — **先测量再优化**：`cProfile` 找热点函数、`line_profiler` 下钻到行、线上用采样式 profiler 出火焰图；遵循**二八定律**，大部分耗时集中在少量代码上。

### 性能/架构（1 张）

- **[L3/高] 340 Python Web 后端有哪些通用的性能优化手段** — 按**算法与数据结构 → 数据库（索引/慢查询/批量/连接池）→ 缓存（Redis/Memcached）→ 异步与并发**四层推进，每上一层都要**先证明瓶颈确实在那里**。

### 操作系统（2 张）

- **[L2/高] 452 进程与线程的本质区别** — 进程是**资源分配与调度的基本单位**（拥有独立地址空间），线程是**进程内的子任务、CPU 调度的基本单位**（共享进程内存）；一个进程可含多个线程。
- **[L2/高] 458 进程间通信（IPC）全景** — **IPC（Inter-Process Communication，进程间通信）**解决"进程地址空间隔离、数据不共享"下的信息交换；常见六类：**管道、信号、消息队列、共享内存、信号量、socket**。

### 操作系统/Linux（7 张）

- **[L2/中] 445 为什么学 Linux 与查命令：man / --help / tldr** — 后端应用多部署在 **Linux 服务器**（容器技术也基于 Linux），面试常考基础命令；查命令用法首选 **`man`**，嫌手册晦涩可用带示例的 **`tldr`**（man 的现代替代品），以及命令自带的 **`--help`**。
- **[L3/高] 446 软链接 vs 硬链接：inode 不同，常考** — **软链接（符号链接）**是一个独立文件，里面存**原文件的路径**，其 **inode 与原文件不同**；**硬链接**与原文件**共享同一个 inode**，指向同一块磁盘数据——这是二者最常被考的区别。
- **[L2/中] 447 文件与权限命令：chmod / chown / chgrp / ls / cp / rm** — Linux 下管控文件靠三类命令：**`chown`** 改属主、**`chgrp`** 改属组、**`chmod`** 改权限位（rwx）；配合 `ls -l` 查看、`cp` 拷贝、`rm` 删除、`cd` 切换目录，是日常排障与部署的基础。
- **[L2/中] 448 查找与搜索：locate / find / grep** — 定位文件用 **`locate`**（基于索引、快但不实时）或 **`find`**（实时遍历）；**`grep -r`** 递归搜索文件内容——三者是"找文件/找内容"的利器，`find` 还能按类型/名/时间做条件筛选与批量操作。
- **[L2/高] 449 进程命令：ps / grep / kill（-9 与 -15）/ top / htop** — 查进程用 **`ps aux | grep 名`**；终止用 **`kill`**——`kill -15`（SIGTERM）是**优雅终止**（让进程清理后退出），`kill -9`（SIGKILL）是**强制杀**（不可捕获、不清理），生产上优先 -15、必要时才 -9。
- **[L2/高] 450 网络命令：查端口 / 远程 / 抓包（ss / netstat / ssh / scp / tcpdump）** — 查端口占用用 **`ss -tlnp`**（新）或 **`netstat -tlnp`**（旧）；远程登录 **`ssh`**、远程拷贝 **`scp`**；抓包 **`tcpdump`**（或 Wireshark 图形化）——"Web 应用占用了哪个端口"是高频实战题。
- **[L2/中] 451 内存查看 / 用户组 / 定时任务：free / useradd / crontab** — **`free -h`** 看系统内存（重点看可用 `available` 与缓存）；用户/组用 **`useradd`/`usermod`/`groupadd`/`groupdel`**；**`crontab -e`** 配置定时任务——这些偏运维，但内存排查与定时任务是后端常碰到的。

### 操作系统/内存（4 张）

- **[L2/中] 461 分页机制（Paging）** — **分页**把程序的**逻辑地址**按固定大小（通常 4KB，由 OS 定）切成**页（page）**，物理内存切成同样大小的**帧（frame）**，用**页表（page table）**做逻辑→物理映射；页可离散分配，从而减少外部碎片。
- **[L2/中] 462 分段机制（Segmentation）** — **分段**按**逻辑意义**把内存分成段（代码段/数据段/栈段/堆段），用**段表（segment table：段号+段长+起始地址）**映射；**段内连续、段间离散**，目的是**数据保护与隔离**，段大小由用户程序决定。
- **[L2/高] 463 虚拟内存与局部性原理** — **虚拟内存**让程序以为自己有比物理内存大得多的地址空间：暂不用的内存页换出到**硬盘（swap）**，需要时再换入。其理论基石是**局部性原理**（时间局部性 + 空间局部性）。
- **[L2/中] 464 内存抖动与页面置换策略** — **内存抖动（thrashing）**指页面频繁换入换出，进程不断产生**缺页中断**，性能急剧下降；根因常是页面置换策略不当或物理内存不足。常见策略：**LRU / LFU / FIFO**。

### 操作系统/并发（1 张）

- **[L2/高] 453 并发与并行：GIL 视角** — **并行**是多核真正同时执行；**并发**是单核时间片轮转、宏观同时微观交替。CPython 因 **GIL** 同一时刻仅一个线程跑字节码，故多线程 CPU 密集只能"并发"而非"真并行"。

### 数据库（18 张）

- **[L2/高] 489 数据库事务与 ACID 特性** — **事务**是数据库**并发控制的基本单位**，本质是一组 SQL 的"**要么全成功、要么全失败（回滚）**"；用 **ACID** 描述其保证——**A 原子性（全或无）、C 一致性（前后数据完整）、I 隔离性（并发互不干扰）、D 持久性（提交后落盘不丢）**。
- **[L2/高] 490 事务并发异常：脏读/不可重复读/幻读/丢失更新** — 多个事务并发读写同一数据时会产生四类异常：**脏读**（读到别的事务未提交的修改）、**不可重复读**（同一事务内两次读同一行得到不同结果）、**幻读**（同一事务内两次范围查询，第二次多出原本没有的行）、**丢失更新**（两个事务改同一行，后写覆盖前写）。
- **[L2/高] 491 事务隔离级别：RU/RC/RR/Serializable** — SQL 标准定义四级隔离：**Read Uncommitted（读未提交）**→**Read Committed（读已提交）**→**Repeatable Read（可重复读）**→**Serializable（串行化）**，级别越高并发异常越少但性能越差；**MySQL/InnoDB 默认是 Repeatable Read**。
- **[L2/高] 492 乐观锁与悲观锁** — **悲观锁**假设别人一定会改，操作前**先加锁再读写**（如 MySQL `SELECT ... FOR UPDATE`），冲突少但加锁有开销；**乐观锁**假设别人不会改，先改，**提交时比对版本号/时间戳**，变了就回滚重试，无锁开销但冲突高时要重试——**按冲突频率与重试代价选型**。
- **[L2/中] 493 高并发场景下的并发插入去重** — 高并发插入要去重，常用三招：**① 唯一索引**（重复时数据库抛异常，捕获忽略即可，最简单）、**② 消息队列异步串行写入**（削峰 + 串行化避免并发冲突）、**③ Redis 分布式锁**（插入前加锁、插完释放）——本质都是"**用约束或串行化换一致性**"。
- **[L2/中] 494 MySQL 常用数据类型与显示宽度误区** — MySQL 类型分三类：**字符串**（CHAR 定长 / VARCHAR 变长 / TEXT 长文本）、**数值**（TINYINT/SMALLINT/INT/BIGINT/FLOAT/DOUBLE）、**日期**（DATETIME 8 字节 / TIMESTAMP 4 字节）。**关键误区：`INT(10)` 的 10 是显示宽度，不是字节数也不是取值范围——INT 永远是 4 字节**。
- **[L2/中] 495 InnoDB 与 MyISAM 存储引擎对比** — 两大引擎核心差异：**InnoDB** 支持**事务、外键、行锁+表锁**（并发控制更细），是互联网默认；**MyISAM** 只支持**表锁、不支持事务与外键**，但早期支持全文索引。简单记：**需要事务/并发写选 InnoDB，只读全文检索且不要事务才考虑 MyISAM**。
- **[L2/高] 496 什么是索引与查找结构进化史** — **索引是数据表上一列或多列排序的数据结构**，目的是把"全表逐行扫描"变成"按结构快速定位"；MySQL 用 **B+ 树** 作索引。理解索引要先懂查找结构的**进化史**：线性查找（慢）→ 二分（需有序、插入 O(N)）→ 哈希（查询快但占空间）→ 二叉查找树 BST（logN 但退化成链表）→ 平衡树 AVL（解决退化，但二叉→节点多时树高仍高）→ 多路平衡查找树 **B 树**（一父多子降树高）→ **B+ 树**（MySQL 实际采用）。
- **[L3/高] 497 B 树与 B+ 树的区别（MySQL 为什么用 B+ 树）** — **B 树**是 m 阶**多路平衡查找树**，所有节点（含叶子）都存数据；**B+ 树**是 B 树的变形，两处关键改进——**① 非叶节点只存 key 和孩子指针（不存数据）→ 单页塞更多 key、树更矮**；**② 叶子节点用双向指针串联 → 天然支持范围查询**。MySQL/InnoDB 用 **B+ 树** 而非 B 树。
- **[L2/高] 498 MySQL 索引类型** — MySQL 常见索引类型：**普通索引**（纯加速）、**唯一索引**（值必须唯一，可判重）、**联合索引**（多列组合，B+ 树 key 由多列值拼成，引出最左前缀）、**主键索引**（一表一个，InnoDB 即聚集索引）、**全文索引**（倒排索引，适合搜索）。除全文索引外，其余底层都是 **B+ 树**。
- **[L3/高] 499 联合索引与最左前缀原则** — **联合索引**把多列拼成一个 B+ 树 key（如 `(a,b,c)` 按 a→b→c 排序）。**最左前缀原则**指：查询必须从索引的**最左列开始**才能命中——`(a)`、`(a,b)`、`(a,b,c)` 都能用索引，而 `(b,c)` 不能，因为 B+ 树 key 的比较**从第一列起逐列进行**，缺了最左基准就无法二分定位。
- **[L3/高] 500 创建索引的最佳实践** — **建索引不是越多越好，而是围绕查询需求在「非空、高区分度、短长度」三个维度上取舍**；三条原则都能由 B+树 key 比较的代价推导出来，理解底层就不必死记。
- **[L3/高] 501 索引失效三大场景与统一根因** — **索引失效的三种高频场景——LIKE 以 % 开头、隐式类型转换、违反最左前缀——根因只有一个：B+树的 key 无法被直接比较**，理解这一点就不用死记。
- **[L4/高] 502 聚集索引与非聚集索引（回表原理）** — **聚集 vs 非聚集的唯一区别：B+树的叶子节点存的是"数据记录"还是"指向数据的指针"**；InnoDB 主键索引=聚集（叶存整行），MyISAM 全是非聚集（索引、数据两文件分离）。
- **[L3/中] 503 慢查询排查的三板斧** — **慢查询排查三板斧：看慢查询日志定位问题 SQL → 用 EXPLAIN 分析索引使用 → 在业务代码层修类型匹配与分页**；多数慢查询根因仍是"缺索引或索引不合理"。
- **[L2/中] 504 SQL 语句编写重点与连接查询总览** — **面试 SQL 编写重点在连接查询（JOIN）**；由于复杂 SQL 在高并发下表现差，业界（阿里 Java 规范）倾向"数据库只做存取、join 不超过 3 张表、复杂逻辑下沉到代码层"。
- **[L2/高] 505 内连接 INNER JOIN** — **INNER JOIN 只返回两表都满足 ON 条件的匹配行**，语义上类似"两表的交集"；写法是 `SELECT 列 FROM a INNER JOIN b ON a.id = b.id`。
- **[L2/高] 506 外连接 LEFT/RIGHT JOIN 与全连接模拟** — **LEFT JOIN 返回左表全部记录、右表无匹配则填 NULL；RIGHT JOIN 反之**；"全连接"在 MySQL 没有原生 `FULL OUTER JOIN`，需用 `LEFT JOIN ... UNION RIGHT JOIN` 模拟。

### 数据库·缓存（12 张）

- **[L2/高] 507 为什么使用缓存与典型场景** — **缓存本质是"用内存换速度"**：把热点数据放内存，缓解后端关系库压力、降低响应延迟（内存读取 μs 级 vs 磁盘 ms 级）、提升单机吞吐（QPS）。
- **[L2/高] 508 Redis 与 Memcached 的核心区别** — **Redis 与 Memcached 的三大区别**：① Redis 数据类型丰富（string/list/hash/set/zset），Memcached 仅简单 KV；② Redis 单进程单线程 + IO 多路复用，Memcached 多线程；③ Redis 支持 RDB/AOF 持久化，Memcached 不支持。
- **[L2/高] 509 Redis 五种常用数据类型与使用场景** — **Redis 五大常用类型各司其职**：string（KV/计数器）、list（双向链表，关注列表/队列）、hash（关联对象）、set（去重集合）、zset（有序集合，排行榜）。
- **[L3/中] 510 Redis 底层数据结构实现** — **Redis 五种类型在底层有多种编码，按数据量自动切换**：string→SDS/整数；list→ziplist/双端链表；hash→ziplist/哈希表；set→intset/哈希表；zset→skiplist。
- **[L3/中] 511 跳跃表（Skip List）** — **跳跃表（skiplist）是 zset 的底层结构**：在有序链表上叠加多层索引，用"逐层向右、比较大小决定走向"的二分思想实现 O(logN) 查找；相比平衡树实现更简单。
- **[L3/高] 512 Redis 持久化：RDB 与 AOF** — **Redis 两种持久化**：RDB 定时快照（恢复快、丢间隔数据）、AOF 追加每条写命令（丢数据少、文件大恢复慢）；按业务对"恢复速度 vs 数据丢失量"的容忍度选择。
- **[L3/中] 513 Redis 事务与 ACID 特性** — **Redis 事务 = MULTI 入队 + EXEC 一次性按序执行**，靠 WATCH 实现乐观锁；但与 MySQL 事务不同——它**原子性不含回滚**、持久性不完全保证，隔离性靠单线程天然达成。
- **[L3/高] 514 Redis 分布式锁** — **Redis 分布式锁 = SETNX 加锁（key 不存在才设成功）+ EXPIRE 超时防死锁 + 释放时校验随机值再 DELETE**；解决多机多进程间的互斥。
- **[L3/高] 515 缓存使用模式：Cache Aside** — **最常用的是 Cache Aside（旁路缓存）**：读时先查缓存、未命中查 DB 再回填；写时**先更新 DB、再删缓存**（而非更新缓存），避免并发写导致缓存脏数据。
- **[L3/高] 516 缓存穿透** — **缓存穿透 = 查询根本不存在的数据，缓存与 DB 都没有，请求每次都打到 DB**。解法：缓存空值（NULL）并设短 TTL，或用布隆过滤器拦截。
- **[L3/高] 517 缓存击穿** — **缓存击穿 = 某个超热点 key 过期瞬间，海量请求同时穿透到 DB 把它打挂**。解法：分布式锁互斥重建，或后台异步定期刷新热点 key 使其不过期。
- **[L3/高] 518 缓存雪崩** — **缓存雪崩 = 大量缓存同时失效或缓存集群不可用，瞬间海量请求打到 DB 把它打挂**。解法：多级缓存、随机 TTL 错峰失效、提升可用性与监控。

### 数据库·设计（1 张）

- **[L3/中] 519 数据库主键设计与分布式 ID 生成** — **单库用自增 INT 主键最契合 B+树聚集索引（顺序追加、页分裂少）；UUID 主键随机无序→大量页分裂与碎片**。分布式下自增失效，改用**雪花算法 / 号段 / Redis 自增 / Leaf** 等方案。

### 算法与数据结构/二叉树（5 张）

- **[L2/高] 374 二叉树怎么表示，三种遍历怎么写** — 二叉树节点 = `data` + `left` + `right`（空表示无子树，两者皆空即叶子）；三种遍历**只差打印节点的位置**——前序**根左右**、中序**左根右**、后序**左右根**。
- **[L2/高] 381 反转二叉树（镜像）：递归三行是怎么来的** — 反转二叉树就是求**镜像**：对每个节点**交换左右孩子**，再**递归处理左右子树**；本质是**先序遍历**（先处理根、再递归左右），代码只有几行。
- **[L2/高] 382 层序遍历：两个列表滚动就能做 BFS** — 层序遍历 = **广度优先**，用 `current` / `next` **两个列表滚动**：遍历当前层时把下一层的非空孩子收进 `next`，本层走完就**整体切换到下一层**，每层的值成一个子列表。
- **[L3/中] 384 二叉树的左视图与右视图：层序遍历的变形** — 左视图 = 从左边看树能看到的节点（**每层第一个**），右视图 = 每层**最后一个**；只要在**层序遍历**基础上对每层取 `层[0]` 或 `层[-1]` 即可，无需新算法。
- **[L2/高] 385 二叉树遍历全景：DFS 四种与 BFS 怎么选** — 二叉树遍历分两大族：**DFS**（先序/中序/后序，递归或显式栈，一路走到底）与 **BFS**（层序，队列，一层一层）；**递归写法本质是栈**，选型取决于你要的是"路径信息"还是"层信息"。

- **[L2/高] 398 对撞指针（双端遍历）：一类题的通用套路** — **对撞指针**（双端遍历）是固定套路：两个指针一头一尾，**在相遇前**每轮做一次对称操作（交换/比较/累加），然后同时向中间收拢；适用于**有序数组两数之和、反转、回文判定**等"对称"问题。

### 算法与数据结构/哈希表（1 张）

- **[L3/高] 373 哈希冲突的两种解法：链地址法与开放寻址** — 哈希冲突（不同 key 落到同一槽位）有两大解法：**链地址法**——槽位挂链表/桶继续追加；**开放寻址（探查法）**——按探查序列（线性/二次）找下一个空槽。

### 算法与数据结构/堆（5 张）

- **[L2/高] 375 堆为什么是完全二叉树，大顶堆与小顶堆怎么分** — 堆是**完全二叉树**（因此可以用**数组**紧凑存储、无需指针）；**大顶堆**要求每个非叶节点 ≥ 其孩子（堆顶最大），**小顶堆**反之（堆顶最小）。
- **[L3/高] 376 一亿个数里取最大的 K 个，为什么用小顶堆** — 求最大的 K 个，维护一个**容量为 K 的小顶堆**：堆顶是"当前入选者里最小的"，新元素**比堆顶大就替换**，否则丢弃；扫完全部数据后堆内即 TopK，**时间 O(n log K)、空间 O(K)**。
- **[L3/高] 390 合并 K 个有序链表：最小堆三步法** — 合并 K 个有序链表用**最小堆**只需三步：**遍历所有链表把值收进列表 → `heapify` 原地建堆 → 反复 `heappop` 取出最小值串成新链表**；时间 `O(N log N)`（N 为总节点数）。
- **[L2/高] 391 heapq 三板斧：heappush、heapify、heappop** — `heapq` 是 Python 的**最小堆**实现，常用就三个动作：`heappush(h, x)` 入堆、`heapify(h)` **原地线性时间**把一个列表变成堆、`heappop(h)` 弹出最小；牢记它是**最小堆且不是排序后的列表**。
- **[L3/中] 392 两两归并还是堆？合并 K 有序链表的两种解法对比** — 合并 K 个有序链表有两条路：**顺序两两归并**实现简单但约 `O(kN)`；**堆（多路归并）**复杂度 `O(N log k)`（惰性写法）或 `O(N log N)`（一次性读值），k 越大堆的优势越明显。

### 算法与数据结构/字典结构（3 张）

- **[L2/中] 352 什么样的对象才能做字典的 key** — 能做 dict 键的对象必须**可哈希**：实现 `__hash__` 且生命周期内哈希值不变，并与 `__eq__` 保持一致；**可变容器（list / set / dict）一律不可哈希**。
- **[L3/高] 358 dict 底层为什么用哈希表，冲突怎么解决** — dict 底层是**哈希表**，用哈希函数把 key 映射到数组下标，从而把查找均摊压到 **O(1)**；冲突由**开放寻址（探测）**而非链地址法处理。
- **[L3/中] 359 哈希表什么时候扩容，扩容做了什么** — 哈希表的主体是一个**数组**；当**装载因子**（已用槽位 / 总槽位）超过阈值时触发**扩容**：申请更大数组并 **rehash 重排**全部元素。

### 算法与数据结构/字符串（2 张）

- **[L1/高] 394 原地反转字符串：双指针一次搞定** — 原地反转字符数组用**首尾双指针**：`begin` 从头、`end` 从尾，**交换两端**后各自向中间移动，直到**两指针相遇**即停；时间 `O(n)`、额外空间 `O(1)`。
- **[L1/高] 396 判断回文数：字符串双指针与两条边界** — 回文数 = 正着读反着读一样；用**字符串 + 首尾双指针**向中间比对，遇到不等即 False，指针相遇仍未不等则 True；两条必答边界是**负数一律 False**、**个位数一律 True**。

### 算法与数据结构/数学（1 张）

- **[L3/中] 397 回文数的数值解：只反转后一半，O(1) 空间** — 不转字符串的回文数解法：**只反转数字的后一半**，与前一半比较；用"**反转值 ≥ 剩余值**"作为到达中点的判据，时间 `O(log₁₀ n)`、**额外空间 `O(1)`**。

### 算法与数据结构/栈（3 张）

- **[L2/中] 370 用 deque 实现栈，和队列只差一个方法** — 栈是 **LIFO（后进先出）**：用 deque 时**入栈和出栈都在右端**——`append()` + `pop()`；与队列（右进左出）**只差出队用的是 `pop` 还是 `popleft`**。
- **[L3/高] 372 最小栈：怎么让 get_min 也是 O(1)** — 最小栈 = **主栈 + 辅助最小栈**：辅助栈**同步**压入"当前最小值"（重复值也要压），弹出时同步弹；这样 `min()` 直接取辅助栈栈顶，**全程 O(1)**。
- **[L2/中] 386 从零手写 Stack 类：四个接口与栈顶约定** — 用 `collections.deque` 封装栈只需**四个接口**：`push`（右端 `append`）、`pop`（右端 `pop`）、`top`（返回 `items[-1]`）、`empty`（`len(items) == 0`）；**约定栈顶在右端**是全部正确性的前提。

### 算法与数据结构/栈与队列（4 张）

- **[L3/高] 371 如何用两个栈实现一个队列** — 两个栈分别扮演**输入栈**与**输出栈**：入队只压输入栈，出队只从输出栈弹；**输出栈空时才把输入栈整体倒入**，因此每个元素最多被倒一次，**摊销 O(1)**。
- **[L2/中] 387 为什么一个栈做不出队列：LIFO 与 FIFO 的语义鸿沟** — 栈只能看到**栈顶**一个元素，而队列要求**先取最早进入的元素（在栈底）**；单个 LIFO 结构**无法在不违反规则的前提下触达栈底**，所以"单栈实现队列"无解，必须引入第二个栈做**一次顺序翻转**。
- **[L2/中] 388 peek 与 empty：实现队列时最容易漏的两个接口** — 实现"用栈模拟队列"时，除 `push`/`pop` 外常被要求补 `peek`（**只返回队头不弹出**）与 `empty`（**两个栈同时为空才为空**）；两者都应**复用同一段"倒栈"逻辑**，避免复制粘贴。
- **[L2/中] 389 栈与队列是底层：图遍历和高级结构都靠它们** — 栈和队列本身简单，却是**图遍历与众多高级结构的底层**：DFS 靠栈（一路走到底再回溯），BFS 靠队列（一层一层扩散）；Python 没有内置栈类型，用 `list`/`deque` 替代，二者常因 **LIFO/FIFO 易混**而放在一起考。

### 算法与数据结构/线性结构（1 张）

- **[L2/高] 351 tuple 的"不可变"到底指什么** — tuple 的不可变是**它保存的引用不可变**——**不能替换其中某个位置指向的对象**，但**若该对象本身可变（如 list），其内容照样能改**。

### 算法与数据结构/缓存（3 张）

- **[L2/高] 361 缓存满了按什么策略淘汰** — 内存有限时必须**挑一个 key 淘汰**：常见策略是 **LRU**（最久未用）、**LFU**（使用次数最少）、**FIFO**（先进先出）与**随机**；LRU 从**时间维度**衡量，LFU 从**频次维度**衡量。
- **[L3/高] 362 用 OrderedDict 手写一个 LRU 缓存** — 用 `OrderedDict` 同时承担**KV 存储**与**访问顺序**：`get` 命中后 `move_to_end` 标记为最新，`put` 超容量时 `popitem(last=False)` 淘汰最旧者，两个操作都是 **O(1)**。
- **[L2/中] 363 functools.lru_cache 装饰器怎么用才不踩坑** — `functools.lru_cache` 一行给函数加上 **LRU 缓存**，`maxsize` 控制容量（None 表示不限）；被装饰函数的参数必须**可哈希**，且应当是**幂等**的。

### 算法与数据结构/边界与测试（2 张）

- **[L1/高] 383 空树边界：一个 None 让提交挂掉的复盘** — 层序遍历漏判**空树**时，`[n.value for n in current]` 会对 `None` 取属性，抛 `AttributeError: 'NoneType' object has no attribute 'value'`；**先判空根返回 `[]`** 即可，代价一行。
- **[L2/中] 393 空输入三重坑：[]、[[]] 与空堆 heappop** — 合并 K 个有序链表时连续踩了三个坑：`heappop` 对**空堆**抛 `IndexError`；输入 `[]` 要判空；而 `[[]]`（**嵌套空列表**）在 Python 里是**真值**，`if not lists` 判不出来——最稳的做法是**判真正要用的堆/列表是否为空**。

### 算法与数据结构/链式结构（1 张）

- **[L2/高] 354 为什么用 deque 而不是 list 实现栈和队列** — Python 没有内置链表结构，但 `collections.deque` 作为**双端队列**在**两端增删都是 O(1)**，用它实现栈和队列既简单又不会退化。

### 算法与数据结构/链表（4 张）

- **[L2/高] 366 链表有哪几种，用 Python 怎么表示** — 链表按指针数分三种：**单链表**（value + next）、**双链表**（prev + value + next）、**循环双向链表**（首尾相连）；Python **没有内置链表**，用**类持有引用**即可表示。
- **[L3/高] 367 迭代法反转单链表怎么写才不出错** — 反转单链表用**迭代三指针**：维护 `prev` 与 `cur`，每轮先**存下 next**、再把 `cur.next` **反向指向 prev**、然后两个指针**同时前移**；循环结束返回 `prev`。
- **[L3/高] 377 只给你待删节点，怎么把它从链表里删掉** — 拿不到头节点就**无法找到前驱**，于是换个思路：**把后继节点的值复制过来，再跳过后继**——等价于"用后继顶替自己"，只需 **O(1)**。
- **[L3/高] 378 合并两个有序链表，哑节点怎么用** — 合并两个有序链表沿用**归并排序的合并步**：双指针比较取小者接上；引入**哑节点（dummy/root）**省掉"头节点特判"，最后把**剩余整段**直接接上即可。

### 算法与数据结构/队列（2 张）

- **[L2/中] 368 用 deque 封装一个队列类** — 队列是 **FIFO（先进先出）**：用 `deque` 时 **入队 = `append`（右端）**、**出队 = `popleft`（左端）**，再补一个 `empty()` 委托 `len(items) == 0` 即可。
- **[L2/中] 369 用 list 实现队列到底慢在哪** — list 尾部 `append` 是 O(1)，但**头部 `insert(0, x)` / `pop(0)` 需要整体搬移元素，是 O(n)**；所以拿 list 当队列，出队会随着长度增长线性变慢。

### 算法与数据结构/集合结构（1 张）

- **[L1/中] 360 set 与 frozenset 该怎么选** — `set` 是**可变**集合（可 add/discard），`frozenset` 是**不可变**集合（创建后不能改）；后者因此**可哈希**，能作为 dict 的键或放进另一个集合。

### 算法与数据结构/面试方法（2 张）

- **[L1/中] 379 白板编程怎么准备才有效** — 白板编程 = **脱离 IDE 手写/口述代码**；有效准备方式是**按数据结构分类刷**（链表/栈/二叉树/排序各刷一类）+ **剑指 Offer 类高频题亲手实现** + **面试前按公司面经定向补**。
- **[L2/中] 380 算法题现场没思路，怎么把损失降到最低** — 现场卡壳时，**不要沉默空转**：先**复述题意确认理解** → 讲出**暴力/次优解**并说明复杂度 → 与面试官**逐步对齐约束** → 在次优基础上**尝试优化**；能解决问题的方案远好于零产出。

### 算法与数据结构/面试范围（1 张）

- **[L1/高] 364 面试常考的排序与查找题有哪些** — 算法面试以**排序 + 查找**为主战场：排序常考冒泡、快排、归并、堆排；查找考线性与二分；**硬指标**是能**徒手写出代码**并**分析时间与空间复杂度**。

### 系统设计（5 张）

- **[L3/中] 528 系统设计概述与难点** — **系统设计 = 定义一个能"满足特定需求"的系统架构、模块、接口与数据的过程**。它难在既要求领域/架构经验（如 feed 流推拉模型），又要求熟悉后端组件（MQ/缓存/DB/Web 框架）并能画图编码；微服务拆分让"独立设计与实现一个服务"成为高频面试题。
- **[L3/高] 529 系统设计回答框架：三大要素与延伸** — **答系统设计题围绕"三大要素"展开**：① **场景与限制**（先问清场景、用户量、估算峰值/平均 QPS）；② **数据存储**（按需求做库选型、建表、索引、缓存）；③ **算法模块**（定义接口、选算法、做时空权衡）。延伸再看**扩展**（QPS/数据规模）与**容错**（单点/雪崩）。
- **[L4/高] 530 短网址系统设计（需求·场景·存储）** — **短网址系统 = 把长 URL 映射成 ≤7 位短码（62 字符集）并提供"长转短 / 短还原长"的服务**。设计上先量化场景（bitly 实测每秒新增数百、查询上千），存储只用 MySQL 即可：四字段（自增 ID / token / 原 URL / 创建时间）+ 给 token 加索引。
- **[L4/高] 531 短码生成算法：MD5 截断 vs 自增 ID base62** — **短码生成有两种路线**：① **MD5 摘要 + 截断前 7 位**——简单但有冲突概率，高并发插入要查库检测冲突，不友好；② **自增 ID → base62 编码**（字符集 62 个，62^7≈3.5 万亿足够），用 **Redis INCR** 生成全局自增 ID，再"不断取余 + 倒序输出"转 62 进制。**实战选②**，无冲突、无需查库。
- **[L4/高] 532 短网址服务编码实现（Flask + Redis + MySQL）** — **落地短网址服务用单文件 Flask**：`request.json` 取长 URL → **Redis `INCR` 拿全局自增 index** → `encode(index)` 得 62 进制 token → **MySQL 参数化 INSERT** → 提交并返回 `short.com/{token}`。面试时**图文并茂**：白纸分区（左上数据表 / 中间算法+接口 / 底部请求流程图），紧扣三要素。

### 编程范式/Python 类（6 张）

- **[L1/高] 400 Python 类的定义：__init__、属性与方法** — 用 `class` 定义类，`__init__` 在**实例创建后**给实例绑属性；类里定义的 `def` 叫**方法**（首参 `self`），类外定义的才叫**函数**。
- **[L2/高] 401 Python 没有 private：下划线约定与名称改写** — Python **没有真正的访问限定符**：单下划线 `_x` 是"请勿外部访问"的**约定**，类体内双下划线 `__x` 触发**名称改写**成 `_类名__x`（只是改名，仍可访问）；`__len__` 这类 dunder 是**魔术方法**，由内置函数与运算符间接调用。
- **[L2/高] 403 类变量 vs 实例变量：谁被所有实例共享** — **类变量**定义在类体里、**由该类所有实例共享**（如 `country = 'China'`）；**实例变量**在 `__init__` 里用 `self.x` 绑定、**每个实例各一份**、互不影响。
- **[L3/中] 404 可变类变量陷阱：全实例共享的那一个 list** — 类变量若是 `list`/`dict`/`set` 这类**可变对象**，它只有**一份**，任何实例做**原地修改**（`append` 等）都会让**所有实例**看到变化——这是类变量最经典的线上事故源。
- **[L2/高] 405 classmethod vs staticmethod：一个拿 cls，一个什么都不拿** — 两者都能用 `类名.方法()` 调用；**`@classmethod`** 首参是**类本身 `cls`**（可读写类变量、可作工厂），**`@staticmethod`** **不接收 `self`/`cls`**，只是把一个普通函数**放进类的命名空间**做代码组织。
- **[L2/高] 409 __new__ vs __init__：谁造对象，谁填属性** — **`__new__` 负责创建实例**（静态方法，首参是 `cls`，**必须返回实例**），`__init__` 负责**初始化**已创建的实例（首参 `self`，**不能返回非 None**）；调用顺序是先 `__new__` 后 `__init__`。

### 编程范式/元类（3 张）

- **[L3/中] 406 元类：创建类的类，以及 type 的三种用法** — **元类（metaclass）是创建类的类**：实例由类创建，类由元类创建；内置元类是 `type`，`class X: a = 1` 等价于 `type('X', (), {'a': 1})`——**类名、基类元组、属性字典**三参数。
- **[L3/中] 407 自定义元类：重写 __new__ 拦截类的创建** — 自定义元类 = **继承 `type` 并重写 `__new__(mcs, name, bases, attrs)`**，在类对象**生成前**改写 `attrs` 字典，最后 `return type.__new__(mcs, name, bases, new_attrs)`；使用时写 `class X(metaclass=...)`。
- **[L2/中] 408 元类用在哪：ORM 框架是它最常见的主场** — 元类允许**在类生成时拦截并改写类**，因此适合做"声明式 → 运行时结构"的转换；**ORM** 是最典型场景：用户只声明字段，元类自动收集字段、建立**类与表、属性与列**的映射。

### 编程范式/函数式（5 张）

- **[L2/中] 440 高阶函数 map：对每个元素应用函数，Python3 返回迭代器** — **`map(fn, iterable)`** 把 `fn` **依次作用**到可迭代对象的每个元素上；**Python 3 里它返回迭代器**（惰性），需 `list()` 落定——但日常更推荐用**列表推导**替代，可读性更好。
- **[L2/中] 441 高阶函数 filter：按谓词保留元素，同样推荐列表推导** — **`filter(pred, iterable)`** 用谓词 `pred` **逐元素判断**，只保留使 `pred` 为真的元素；和 `map` 一样 **Py3 返回迭代器**，且日常更推荐用**列表推导** `[x for x in it if pred(x)]` 替代。
- **[L2/中] 442 高阶函数 reduce：把序列规约为单一值，位于 functools** — **`reduce(fn, seq, init)`** 用二元函数 `fn` 把序列**从左往右规约**成单一值（`fn(前次结果, 当前元素)`）；**Python 3 中它从内置移到了 `functools.reduce`**。
- **[L3/高] 443 闭包：捕获外部自由变量的函数，变量随闭包存活** — **闭包**是一个**函数**，它**捕获并记住**了定义时所在**外部作用域的变量**（即**自由变量**）——即使外层函数已返回，只要内部函数还持有引用，那些变量就**不会**被销毁。
- **[L3/中] 444 实战：用闭包实现缓存装饰器（斐波那契记忆化）** — 源里的经典例子：写一个 `cache` **装饰器**——外层持有 `store` 字典，内层函数引用它来**缓存**已算过的斐波那契结果，从而避免指数级重复计算，这正是**闭包**的典型实战。

### 编程范式/编程范式（1 张）

- **[L2/中] 439 函数式编程：运算即函数，追求无副作用与引用透明** — **函数式编程**把计算看作**数学函数的求值**，强调**无副作用**与**引用透明**（相同输入永远得到相同输出），Python 是多范式语言，可在面向对象之外选用函数式风格。

### 编程范式/装饰器（7 张）

- **[L1/高] 410 装饰器的本质：接收函数、返回新函数** — Python 中**函数是一等公民**（可当参数传递），装饰器就是**接收一个函数、加功能后返回一个新函数**的高阶函数；`@deco` 只是 `f = deco(f)` 的**语法糖**，两种写法完全等价。
- **[L2/高] 411 手写耗时装饰器：*args/**kwargs 与返回值透传** — 耗时装饰器模板：外层 `def log_time(func)` 收函数，内层 `def _log(*args, **kwargs)` **收任意参数**，先记 `begin`、调原函数、**保存结果**、打印耗时，**最后把结果 return 出去**。
- **[L3/高] 412 被装饰后函数名变了：functools.wraps 必写** — 装饰器返回的是**内层 wrapper**，所以 `func.__name__` 会变成 `wrapper`、`__doc__` 变 `None`，依赖函数名的**日志、文档、框架路由、序列化**全受影响；用 `@functools.wraps(func)` 把元信息**拷贝**回 wrapper 即可。
- **[L2/中] 413 用类实现装饰器：__call__ 让实例可调用** — 类也能当装饰器：**`__init__` 接收被装饰函数**并保存在实例上，**`__call__` 里写包装逻辑**，因为带 `__call__` 的实例是**可调用对象**，能顶替原函数的位置。
- **[L3/中] 414 给装饰器本身加参数：三层闭包或类构造参数** — 想让装饰器**自己带参数**，就要多包一层：函数版是**三层闭包**（`参数 → 装饰器 → wrapper`），类版是**`__init__` 收参数、`__call__` 收函数**；用途是**控制装饰器自身的行为**（如耗时打印成 int 还是 float）。
- **[L2/中] 415 多个装饰器叠加：定义自下而上，执行由外而内** — 叠多个装饰器时，**等价展开是自下而上**：`@a` `@b` `def f` ≡ `f = a(b(f))`；因此**定义（包装）顺序自下而上，调用执行顺序由外而内**（先 `a` 的前置、`b` 的前置、原函数、`b` 的后置、`a` 的后置）。
- **[L1/高] 416 装饰器用在哪：不改动原函数就加功能（AOP）** — 装饰器对应设计模式的**装饰器模式**、思想上是**面向切面编程（AOP）**：把**日志、鉴权、限流、缓存、耗时统计、重试、事务**这类**横切关注点**从业务函数里剥出去，**不改原函数一行代码**就加上。

### 编程范式/设计模式（22 张）

- **[L1/中] 417 设计模式三大分类：为什么 Python 里讲得少** — GoF《设计模式》收录 **23 种**模式，按目的分 **创建型 / 结构型 / 行为型** 三类；Python 讲得少，是因为**语言本身已内置**了迭代器、装饰器等模式，且大量 Python 代码偏脚本/数据分析，规模没到必须用模式的程度。
- **[L2/高] 418 工厂方法：把"创建"从"使用"里剥出去** — **工厂方法**用一个函数（或类方法）**封装对象创建**：调用方只传**类型标识**，工厂返回对应实例，从而把"**创建**"与"**使用**"解耦；新增产品时只改工厂一处。
- **[L2/中] 419 抽象工厂：一族产品一起换，而不是一个一个换** — **抽象工厂**是"**工厂的工厂**"：一个工厂接口负责创建**一族相关产品**（如同一风格的按钮+输入框+滚动条），换工厂就**整族切换**，保证产品之间**风格/协议一致**。
- **[L2/中] 420 建造者模式：复杂对象分步装配** — **建造者（Builder）**把**创建过程与最终表示分离**：复杂对象（如电脑）不一次 new 出来，而是由 `ComputerBuilder` **逐步** `config_memory/config_ssd/config_gpu`，最后由 `Engineer`（导演）装配并 `build()` 返回成品。
- **[L2/低] 421 原型模式：用克隆代替昂贵构造** — **原型模式**通过**克隆（clone）已有原型**来创建新实例：当新对象与原对象**只有少数字段不同**，或**构造代价很高**（要读库、要 IO）时，复制一份再改比重新构造更划算。
- **[L3/高] 422 手写单例：__new__ 共享实例，以及它的三个坑** — **单例**保证一个类**只有一个实例**：在 `__new__` 里判断 `cls._instance` 是否为空，为空才 `super().__new__(cls)` 并存回类属性，之后每次都**返回同一个**；验证方式是 `a is b` 或 `id(a) == id(b)`。
- **[L2/中] 423 模块即单例：Python 里最省事的单例实现** — Python 的**模块天然是单例**：首次 import 后模块对象缓存在 `sys.modules`，**再次 import 只是取缓存**，不会重新执行模块体；因此模块里的**全局变量**就是天然的单例对象。
- **[L2/中] 424 惰性计算：@property 让昂贵属性用到才算** — **惰性计算**把昂贵计算**推迟到真正访问属性的那一刻**，并**缓存结果**：Python 里用 `@property`（每次都算）或 `functools.cached_property`（**只算一次**）实现，调用方始终写 `obj.x` 而非 `obj.get_x()`。
- **[L2/中] 425 对象池：预建一批实例，用完归还而不是销毁** — **对象池**预先创建**一批同类型实例**，使用时 `acquire` 取出、用完 `release` **归还**（而非销毁），从而**摊薄创建与销毁的开销**；数据库连接池、线程池、HTTP 连接池都是它的实例。
- **[L2/高] 426 代理模式：把操作委托给另一个对象，has-a 组合** — **代理模式**为一个对象提供一个**替代者（代理）**，把对原对象的操作**转接/委托**给另一个对象；它通常是**has-a 的组合关系**，而不是继承。
- **[L3/中] 427 代理模式实战：deque 实现栈队列 + 保护代理加校验** — **栈和队列用 `deque` 实现就是代理模式**：把 `push/pop` 等接口**委托**给内部 `deque` 成员；而**保护代理**则在委托前插入**校验/鉴权**间接层，是代理最常被考到的变体。
- **[L2/高] 428 适配器模式：把不同接口统一到同一接口** — **适配器模式**通过一个**间接层**，把**多个不兼容的接口**统一成**同一个接口**，使调用方可以用一致的方式使用它们（如万能充电头适配不同电器）。
- **[L3/中] 429 适配器实战：用 setattr 把狗叫猫叫统一成 make_noise** — 原文的经典例子：有 `Dog.bark()` 和 `Cat.meow()` 两个**不同名**方法，用**适配器**把它们统一成 `make_noise()`，调用方无需关心对象到底是狗还是猫——这正是适配器"接口转接"的核心价值。
- **[L2/中] 430 外观模式：用一个高层接口简化复杂子系统** — **外观模式**为一组**复杂子系统**提供一个**统一的高层接口**，让调用方**只跟外观打交道**，而不必了解内部一堆类和方法，从而降低耦合、减少使用门槛。
- **[L3/中] 431 享元模式：共享不可变的内在状态，减少重复对象** — **享元模式**通过**共享**大量细粒度对象的**内在状态（intrinsic，不可变、可复用）**，把外在状态（extrinsic，随场景变化）由调用方传入，从而大幅减少重复对象的内存占用。
- **[L2/高] 432 MVC 与 MTV：解耦展示逻辑与业务逻辑** — **MVC** 把应用拆成**模型（数据/业务）、视图（展示）、控制器（流转）**三层以解耦；**Django 的 MTV** 是它的变体——**M**odel、**T**emplate（展示）、**V**iew（负责控制器式的业务流转）。
- **[L2/高] 433 迭代器模式与可迭代对象：__iter__ vs __next__** — **迭代器模式**提供一种**顺序访问**聚合对象元素、又不暴露内部结构的方式；在 Python 里**可迭代对象**实现 `__iter__`（返回迭代器），**迭代器**额外实现 `__next__`（产生下一个元素），二者不是一个东西。
- **[L3/中] 434 实战：让自定义 Stack 可迭代（__iter__ 从栈顶遍历）** — 源里的经典例子：自定义 `Stack`（内部用 deque 存）**默认不可迭代**，给它加 `__iter__` 并**反转 deque**（因 deque 从左往右、push 在右端），即可实现"后入先出、从栈顶往下遍历"。
- **[L2/高] 435 观察者模式与发布订阅：一对多通知，解耦生产者与响应者** — **观察者模式**定义**一对多**依赖：一个**发布者**状态变化，所有**订阅者**自动收到通知并执行各自回调；**发布订阅（Pub/Sub）**是它的常用实现，典型用于**解耦**业务逻辑。
- **[L3/中] 436 实战：发布订阅（Publisher/Subscriber + setter 触发 notify）** — 源里的完整例子：发布者持有订阅者列表，提供 `add/remove/notify`；订阅者实现 `notify_by(publisher, data)`；当发布者的数据**被赋值（setter）**时自动调用 `notify`，逐个触发订阅者的回调——这就是发布订阅的落地。
- **[L2/中] 437 策略模式：不同输入走不同算法，对外暴露统一接口** — **策略模式**把**一组可互换的算法**封装成独立策略，对外只暴露**统一接口**，运行时按输入**选择**具体策略——从而消除长长的 `if/elif` 分支。
- **[L3/中] 438 实战：策略模式做订单折扣（按数量选折扣策略）** — 源里的例子：订单按**数量**选择折扣——100 个走 `ten_percent`（10% off）、1000 个走 `0.25`（25% off），对外只暴露一个统一入口，内部据数量挑策略，这就是策略模式的落地。

### 编程范式/面向对象（1 张）

- **[L1/高] 399 面向对象编程：三大特征与过程式编程的分野** — **OOP** 以**对象**（类的实例）为基本单元，类 = **属性（成员）+ 方法**；靠**封装、继承、多态**解决过程式编程"复用差、业务模型表达不清"的问题。

### 编程范式/面向对象设计（1 张）

- **[L2/高] 402 组合 vs 继承：has-a 与 is-a，为什么优先组合** — **组合**是"类里持有其他类的实例"= **has-a**（有一个），**继承**是"子类扩展父类" = **is-a**（是一个）；两者都能完成时**优先用组合**，因为继承会带来**类膨胀与强耦合**。

### 网络（11 张）

- **[L2/高] 469 浏览器输入 URL 到返回的全过程** — 输入 URL 后宏观链路：**查 DNS 拿 IP → socket 发起 TCP 三次握手 → 发 HTTP 请求 → Nginx 反向代理/负载均衡 → WSGI 适配层（uWSGI/gunicorn）→ Web 框架（Django/Flask/Tornado）处理（查库/发消息）→ 响应经 TCP 返回 → 四次挥手关闭**。
- **[L2/高] 470 TCP 三次握手** — TCP 建立连接需**三次握手**：客户端发 **SYN**（seq=j）→ 服务端回 **SYN+ACK**（ack=j+1, seq=k）→ 客户端回 **ACK**（ack=k+1）。状态上客户端经 `SYN_SENT`→`ESTABLISHED`，服务端经 `SYN_RCVD`→`ESTABLISHED`。
- **[L2/高] 471 TCP 四次挥手** — TCP 关闭连接需**四次挥手**：主动方发 **FIN**（seq=x）→ 被动方回 **ACK**（ack=x+1）→ 被动方发 **FIN**（seq=y）→ 主动方回 **ACK**（ack=y+1）。主动方在 **TIME_WAIT** 需等待 **2MSL** 才彻底关闭。
- **[L2/高] 472 TCP 与 UDP 的区别** — **TCP** 是**面向连接、可靠、基于字节流**的传输协议（三次握手、确认重传、有发送缓冲区可分段）；**UDP** 是**无连接、不可靠、面向报文**的协议（发完不管、无缓冲区、应用层给多少发多少）。
- **[L2/高] 482 阻塞 IO 与 IO 多路复用** — **IO 多路复用**是操作系统提供的"**一个线程同时监听多个 socket**"的机制；它能用**单进程/单线程**支撑成千上万并发连接，关键在于把"等待多个 fd 就绪"交给内核，**应用只在有 socket 可读/可写时才被唤醒处理**。
- **[L2/高] 483 select、poll、epoll 的区别与时间复杂度** — 三者都是 Linux 下**就绪事件通知**机制，**本质差异在"每次调用如何找到就绪 fd"**：`select`/`poll` **每次调用都要把全量 fd 拷进内核并线性扫描**，复杂度 **O(N)**；`epoll` 把监听注册到内核红黑树、**只返回就绪 fd**，调用开销与总监听数无关（**O(1) 每事件**），故 C10K+ 必用 epoll。
- **[L2/中] 484 Python selectors 模块与事件循环** — Python 标准库 **`selectors`** 是对 `select`/`poll`/`epoll` 的**高级跨平台封装**：`DefaultSelector` 按 OS 自动选底层实现（**Linux→epoll、macOS→kqueue**），用 **`register` 注册 fd + 事件类型（`EVENT_READ`/`EVENT_WRITE`）+ 回调**，**`select()` 阻塞到就绪后回调解派**——这就是"事件循环 + 回调"模型，回调地狱后来被**协程（asyncio）**解决。
- **[L2/中] 485 Python 三大并发网络库总览** — Python 生态三大并发网络库 **Tornado（FriendFeed 开源的 Web 微框架）**、**gevent（greenlet 绿色线程 + monkey patch）**、**asyncio（Python3 内置、协程 + 事件循环）**，**底层全部建立在 IO 多路复用之上**；差异在"回调 / 绿色线程 / 原生协程"三种并发范式，以及是否依赖 monkey patch 改写标准库。
- **[L2/中] 486 Tornado 框架** — **Tornado** 是 **FriendFeed** 开源的**并发框架 + Web 微框架**，靠**自身 IOLoop + 非阻塞 socket + 协程（回调/async）**实现高并发，适合轻量微服务与 RESTful 接口；**底层仍是 IO 多路复用**，并非另起炉灶。
- **[L2/中] 487 gevent 框架** — **gevent** 是基于 **greenlet（用户态绿色线程）** 的并发网络库：用 **`monkey.patch_all()` 把标准库阻塞调用（socket/threading 等）替换成非阻塞实现**，再由**事件循环（libev）**调度这些 greenlet，从而"看似同步写、实则并发跑"——常与 **gunicorn** 搭配作为 WSGI 服务器。
- **[L2/中] 488 asyncio 与 aiohttp** — **asyncio** 是 Python3 标准库里的**原生协程并发框架**（`async/await` + 事件循环，底层 IO 多路复用），由 Guido 主导的 Tulip 项目演化而来；**aiohttp** 是基于它实现的异步 HTTP 客户端/服务器库——两者现在已是 Python 异步生态的基石。

### 网络/HTTP（6 张）

- **[L2/高] 473 HTTP 请求与响应组成** — HTTP 报文分**请求**与**响应**两类，每类都由"**行 + 头 + 主体**"组成：**请求行**（方法+路径+版本）+ 请求头 + 消息主体；**状态行**（版本+状态码）+ 响应头 + 响应正文。GET 通常无 body，POST 把参数放 body。
- **[L2/高] 474 HTTP 状态码五大类** — HTTP 状态码分五类：**1xx** 继续、**2xx** 成功（200）、**3xx** 重定向（301 永久/302 临时/304 未修改）、**4xx** 客户端错误（400/401/403/404/405）、**5xx** 服务器错误（500）。面试重点记 301 vs 302 与常见 4xx/5xx。
- **[L2/高] 475 HTTP 方法与 RESTful 语义** — RESTful 下四个常用方法语义分明：**GET 获取 / POST 创建 / PUT 更新 / DELETE 删除**。GET 参数在 URL（明文、有长度限制、幂等），POST 参数在 body（相对隐蔽、非幂等）。
- **[L2/高] 476 HTTP 幂等性与安全性** — **幂等（idempotent）**=多次调用结果一致（如 `a=4` 幂等、`a+=4` 非幂等）；**安全（safe）**=不修改服务端数据。**GET/PUT/DELETE 幂等、POST 非幂等**；**GET/HEAD 安全，其余非安全**——两个概念要区分。
- **[L2/中] 477 HTTP 长连接（Keep-Alive）** — HTTP 基于 TCP，每次建连有三次握手/四次挥手开销。**HTTP/1.1 默认长连接（keep-alive）**复用同一 TCP 连接发多个请求；要区分"一次请求在哪结束"，靠 **Content-Length** 或 **Transfer-Encoding: chunked**（边生成边发、长度未知时）。
- **[L2/高] 478 Cookie 与 Session 的区别** — HTTP 是**无状态**的，需服务端给每个用户生成标识来识别。**Session** 指"识别用户会话"的机制（通常服务端存 sessionID→用户ID）；**Cookie** 是实现 session 的**一种方式**（把 sessionID 存在客户端、每次请求带回）。另一种方式是 **URL 重写**（sessionID 拼进 URL 参数）。

### 网络/Python（3 张）

- **[L2/中] 479 TCP 服务端 Socket 编程** — TCP 服务端流程：**`socket()`→`bind(端口)`→`listen()`→`accept()`（阻塞等新连接）→`recv/send`→`close()`**。`accept` 返回**新的连接 socket**（与客户端的通信通道）和客户端地址；原监听 socket 继续等下一个连接。
- **[L2/中] 480 TCP 客户端 Socket 与字节编解码** — TCP 客户端流程：**`socket()`→`connect(地址)`→`sendall(字节)`→`recv(字节)`→`close()`**。`connect` 触发三次握手；Python3 里 `send` 必须 **encode** 成字节、`recv` 返回的是 **bytes**，需用 `decode("utf-8")` 转回字符串。
- **[L2/中] 481 用原始 Socket 手工发送 HTTP 请求** — HTTP 跑在 TCP 之上：建好 TCP 连接后，**手工拼 HTTP 报文**（`请求行 GET / HTTP/1.1` + `Host:` 头 + 空行 `\r\n\r\n`）通过 `sendall` 发出，再 `recv` 读回响应。理解这一步，就明白 `requests`、爬虫、Web 框架的本质。

### 语言/选型（1 张）

- **[L2/高] 302 为什么用 Python 做 Web 后端** — Python 的核心优势是**生态广度 + 开发效率**，代价是**运行性能、大型项目维护性与 2/3 不兼容**——选型时要明确自己买的是什么、付的是什么。

### 语言基础/函数（6 张）

- **[L2/高] 321 Python 传参到底是传值还是传引用** — Python 只有一种参数传递方式——**共享传参（call by object reference）**：形参拿到的是实参引用的**副本**，两者指向同一对象，改不改得动只取决于**对象可变与否**。
- **[L2/高] 323 为什么不能用可变对象做默认参数** — 默认参数在 **def 执行（函数定义）时**求值一次并塞进 `func.__defaults__`，所有调用**共享同一个对象**——所以可变默认值会**跨调用累积**。
- **[L1/高] 324 *args 把多余位置参数打包成元组** — `*args` 用来接收**数量不确定的位置参数**，函数体内 `args` 是一个 **tuple**；名字可以随便起，起作用的是前面那颗星。
- **[L1/高] 325 **kwargs 把多余关键字参数打包成字典** — `**kwargs` 接收**数量不确定的关键字参数**，函数体内是一个 **dict**（CPython 3.7+ 保证保持调用时的插入顺序），不传时是**空 dict**。
- **[L2/高] 326 调用处的 * 与 ** 是解包，不是打包** — 同一个星号符号，在**定义处是打包**、在**调用处是解包**：`f(*seq)` 把序列拆成位置实参，`f(**mapping)` 把字典拆成关键字实参。
- **[L2/中] 327 函数形参的固定顺序：位置 → 默认 → *args → 仅限关键字 → **kwargs** — 形参声明顺序是**语法硬规则**：**普通位置参数 → 默认参数 → `*args` → 仅限关键字参数 → `**kwargs`**，写反要么 SyntaxError，要么语义悄悄变掉。

### 语言基础/工程实践（1 张）

- **[L3/中] 328 怎么避免函数把调用方的数据改脏** — 把入参当**只读**：确实要改就先拷贝（`list(x)` / `dict(x)` / `copy.deepcopy`），或者干脆**返回新对象**而不是原地改——这是消除共享传参副作用的两种标准姿势。

### 语言基础/异常（4 张）

- **[L1/高] 329 异常机制与错误码的本质差别** — 异常是**打破程序正常执行流程的错误事件**；Python/Java 走异常机制，C 走返回码——两者的本质差别在于**错误能否被静默忽略**。
- **[L2/高] 330 为什么自定义异常继承 Exception 而不是 BaseException** — 异常根类是 `BaseException`，`SystemExit` / `KeyboardInterrupt` / `GeneratorExit` 与 `Exception` **并列**挂在它下面；业务异常必须继承 `Exception`，否则 `except BaseException` 会把 **Ctrl-C 与 sys.exit() 一起吞掉**。
- **[L2/高] 331 try/except/else/finally 各段什么时候执行** — `try` 包风险代码，`except` 处理异常，`else` **只在没异常时**跑，`finally` **无论如何都跑**——但 `finally` 里写 `return` 会**吞掉异常并覆盖返回值**。
- **[L2/高] 332 怎么自定义业务异常** — 自定义异常 = **继承 `Exception`** + 在 `__init__` 里挂业务字段；抛出用 `raise BizError(...)`，捕获时靠**父类兜住子类**实现一处收口。

### 语言基础/数据模型（3 张）

- **[L1/高] 322 哪些内置类型可变，哪些不可变** — 不可变 = 创建后**内容不能原地改**（bool/int/float/str/bytes/tuple/frozenset）；可变 = 可原地改（list/set/dict/bytearray）；可变对象**一定不可哈希**，不能当字典键。
- **[L2/高] 348 赋值、浅拷贝、深拷贝到底差在哪** — 三个层次——**赋值**只是给同一对象多贴一个标签（**不产生拷贝**）；**浅拷贝**新建容器但**子对象仍共享**；**深拷贝**递归复制、完全独立。
- **[L2/高] 349 初始化二维数组的坑：别用 [[0]*n]*m** — `[[0] * n] * m` 的外层 `*` 只是**重复同一个引用**，m 行共享**同一个 list**，改一行会改全部行；正解是**列表推导式** `[[0] * n for _ in range(m)]`。

### 语言基础/生成器（1 张）

- **[L2/高] 341 yield 如何让一个函数变成生成器** — 函数体里出现 `yield` 就是**生成器函数**——**调用它并不执行函数体**，而是返回一个 generator 对象；每次 `next()` 推进到下一个 yield 处**产出值并原地挂起**。

### 语言特性（5 张）

- **[L2/高] 304 鸭子类型与 file-like object** — 鸭子类型 = **只看对象"能做什么"，不看它"是什么类"**；只要实现了 `read`/`write`，文件对象和内存缓冲区都能当"类文件对象"用。
- **[L2/高] 305 自省：type、isinstance 与 id** — 动态语言没有编译期类型，靠**运行期自省**补上：`type` 拿类型、`isinstance` 判归属、`id` 看身份、`inspect` 取更深的元信息。
- **[L2/高] 306 is 与 == 的区别，以及为什么判空用 is** — `==` 比**值是否相等**（走 `__eq__`），`is` 比**是否为同一个对象**（等价于比较 `id`）；判 `None` 必须用 `is`。
- **[L1/高] 307 列表推导与字典推导** — 推导式把**构造 + 过滤**压成一行，可读性优于 `map`/`filter` 嵌套；`zip` 配合字典推导是最常见的两表合成字典写法。
- **[L2/中] 314 限定关键字参数 keyword-only arguments** — 在参数列表里放一个**裸 `*`，其后的参数必须按名字传**，不能靠位置——用来消灭"一堆布尔/同类型参数靠顺序传"的经典事故。

### 语言特性/内存（1 张）

- **[L2/高] 308 生成器推导式：把方括号换成圆括号** — 列表推导**立即**算出全部元素并占内存，生成器表达式**惰性**逐个产出——只差一对括号，内存量级相差一个数据集大小。
