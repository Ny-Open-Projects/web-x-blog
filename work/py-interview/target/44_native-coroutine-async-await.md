# 44. 生成器、生成器协程、原生协程，面试怎么区分

> 分类：并发/协程 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**async/await** / **PEP 492** / **事件循环** / **并发非并行**
> 原文锚点：第 45~50 段「直到 Python 3.5 之后才开始引入原生协程…可以使用 async 和 await 来支持」

## 一句话总述
三代演进：**生成器**（yield 产出值）→ **基于生成器的协程**（PEP 342，yield + send 双向）→ **原生协程**（3.5+，`async def` / `await`，由事件循环调度）。今天说"协程"默认指最后一种。

## 面试官视角
- **考察意图**：能否把这三个常被混用的概念一次讲清，并说清并发与并行的差别。
- **P5** 会写 async/await / **P6** 能讲清三代演进 / **P7** 能点明"单线程并发、不等于并行"以及 async 的传染性。
- **红旗**：① 把生成器说成协程；② 说"async/await 是多线程"（它是单线程并发）；③ "用了 async 就并行执行了"。
- **惊艳点**：`asyncio.gather` 里两个 0.2 秒的任务总耗时约 **0.2 秒**，但打印出来的**线程名始终是同一个**——这直接证明是并发而非并行。验证：下方代码 `[实测]`

## 主问答
**Q：Python 的协程是怎么回事？生成器和协程是一回事吗？**
**A：**
1. **先给结论**：不是一回事，是三代产物——生成器 → 生成器协程（PEP 342）→ 原生协程（`async def`/`await`，PEP 492，3.5+）。
2. **再给机制**：原生协程由**事件循环**调度，执行到 `await`（IO 等待点）时挂起并让出控制权，别的协程趁机执行，等待时间被重叠掉。
3. **最后给边界**：这是**并发不是并行**，CPU 密集任务不会提速；而且 async 会"传染"整条调用链，链上混进一个阻塞调用就会卡住整个循环。
**加分层**：如今被问"协程"就按 `asyncio` 生态答；生成器协程只需说明是历史形态、用来读懂老代码即可。

## 关键代码
```python
import asyncio, threading, time
async def job(name, delay):
    await asyncio.sleep(delay)              # 等待点：让出控制权
    print(name, "线程:", threading.current_thread().name)
async def main():
    t0 = time.perf_counter()
    await asyncio.gather(job("a", 0.2), job("b", 0.2))
    print("总耗时:", round(time.perf_counter() - t0, 2))   # ≈0.2s
asyncio.run(main())
```

## ⚠️ 原文纠错
原文称"Python 异步编程的生态依然不是很成熟"，这是录制当时的状况，已过时：**3.7 之后 asyncio 已进入标准库成熟期**，是当前事实标准。答题应按成熟生态表述。原文中的音译术语已还原。
