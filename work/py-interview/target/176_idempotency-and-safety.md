# 176. HTTP 幂等性与安全性

> 分类：网络/HTTP | 难度：L2 | 题型：原理题 | 频率：高 | 关键词：**幂等** / **安全方法** / **GET** / **POST**
> 原文锚点：第 78~97 段「幂等=多次调用结果一致；GET/PUT/DELETE 幂等，POST 非幂等；safe=是否改服务端数据，GET/HEAD 安全，其余非安全」

## 一句话总述
**幂等（idempotent）**=多次调用结果一致（如 `a=4` 幂等、`a+=4` 非幂等）；**安全（safe）**=不修改服务端数据。**GET/PUT/DELETE 幂等、POST 非幂等**；**GET/HEAD 安全，其余非安全**——两个概念要区分。

## 面试官视角
- **考察意图**：是否分得清"幂等"与"安全"这两个常被混用的词，以及能否指导接口设计。
- **P5** 能说出哪些方法幂等/安全 / **P6** 能解释 PUT（赋值式全量更新）为何幂等、POST 为何不 / **P7** 能指出非幂等操作要"服务端做去重/校验"才能保证安全（如按邮箱判重）。
- **红旗**：把"幂等"和"安全"当成同义词；或认为"幂等=安全"。
- **惊艳点**：**幂等 ≠ 安全**——PUT 幂等但非 safe（它改数据）；正确区分后，重试策略就清晰：幂等方法客户端可安全重发，非幂等需服务端去重 —— 验证：支付/下单接口必须服务端做幂等键（如订单号）防重复扣款 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是幂等？HTTP 哪些方法是幂等的？安全和幂等是一回事吗？

**A · 标准答案骨架：**
1. **先给结论**：**幂等**=多次调用结果一致；**安全**=不修改服务端数据。两者**不是一回事**。
2. **再给机制**：**GET/PUT/DELETE 幂等**（GET 不改、PUT 赋值式全量更新、DELETE 删一次与删多次同效），**POST 非幂等**（每次创建新资源）；**GET/HEAD 是 safe**（不改数据），POST/PUT/DELETE 非 safe。
3. **最后给边界**：非幂等（如 POST 创建）想"安全"，只能在**服务端**做校验/去重（如邮箱判重、订单号幂等键），不是客户端能解决的。

**加分层**：面试答"幂等=可安全重试、安全=只读"——一句话把两词钉死，比罗列方法更显功力 `[经验]`。
