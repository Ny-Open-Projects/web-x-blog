# 46. 测试用例怎么设计：正常值 / 边界值 / 异常值

> 分类：工程化/测试 | 难度：L2 | 题型：工程题 | 频率：中 | 关键词：**等价类划分** / **边界值** / **pytest 发现规则**
> 原文锚点：第 31~37 段「使用正常值、边界值和异常值…等价类划分；pytest 会自动发现所有以 test 开头的函数」

## 一句话总述
用例按**等价类划分**设计，必须覆盖**正常值、边界值、异常值**三类；`pytest 文件名` 会自动收集 `test_*.py` 中所有 `test_` 开头的函数并执行。

## 面试官视角
- **考察意图**：是随手写两个 assert，还是有一套设计方法。
- **P5** 会写几个 assert / **P6** 能按三类设计用例 / **P7** 能说出用例的**独立性与可重复性**要求。
- **红旗**：① 只测 happy path；② 用例互相依赖、依赖执行顺序；③ 测试里发真实网络请求。
- **惊艳点**：断言失败时 pytest 会**回显期望值与实际值**，把人工 print 对比彻底自动化。验证：故意改错一个期望值观察输出 `[实测]`

## 主问答
**Q：拿到一个函数，你怎么设计它的测试用例？**
**A：**
1. **先给结论**：三类必覆盖——**正常值**（典型输入）、**边界值**（空、首/尾、极值）、**异常值**（不存在、非法类型）。
2. **再给机制**：等价类划分把输入空间切成若干等价区间，每区间取一个代表，用最少的用例覆盖最多的路径；pytest 靠命名约定（`test_*.py` / `test_*`）自动发现并执行。
3. **最后给边界**：用例必须**相互独立、可重复执行**——依赖真实网络、数据库或共享状态的测试会变成 flaky test，比不写更糟。
**加分层**：断言要写清**具体期望值**而不是"不报错"，失败信息才可直接定位问题。

## 关键代码
```python
# test_search.py
from search import binary_search
def test_normal():
    assert binary_search([1, 3, 5], 3) == 1
def test_boundary():
    assert binary_search([1, 3, 5], 1) == 0    # 首元素
    assert binary_search([1, 3, 5], 5) == 2    # 尾元素
    assert binary_search([], 1) == -1          # 空列表
def test_abnormal():
    assert binary_search([1, 3, 5], 6) == -1   # 不存在
    assert binary_search([1, 3, 5], -1) == -1  # 小于最小值
# 运行：pytest test_search.py -v
```
