# 137. 策略模式：不同输入走不同算法，对外暴露统一接口

> 分类：编程范式/设计模式 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**策略模式** / **算法族** / **统一接口** / **消除 if-else**
> 原文锚点：第 6 段「策略模式：针对不同输入使用不同策略；对外暴露统一接口，内部按输入选算法」

## 一句话总述
**策略模式**把**一组可互换的算法**封装成独立策略，对外只暴露**统一接口**，运行时按输入**选择**具体策略——从而消除长长的 `if/elif` 分支。

## 面试官视角
- **考察意图**：考你能否把它和**工厂模式**、**条件分支**区分开，以及说出它的真实价值（可扩展、可测试）。
- **P5** 能说出"不同输入用不同算法" / **P6** 能指出它**消除分支**、策略可独立测试，并能对比**工厂模式**（工厂选"创建什么"，策略选"怎么算"）/ **P7** 能指出策略过多的**类膨胀**问题，并给出用 **dict 映射 / functools.singledispatch** 的轻量替代 `[经验]`。
- **红旗**：① 把策略模式说成"就是一堆 if-else"（那是被它取代的反面）；② 和工厂模式混为一谈；③ 没说"策略之间可互换、实现同一接口"。
- **惊艳点**：策略模式的本质是**把"变化点"抽成对象**——新增策略不改调用方代码，只加一个策略类。验证：调用方只认 `context.execute(data)` 不感知具体策略 `[实测]`。

## 主问答
**Q：策略模式解决什么问题？和工厂模式有什么区别？**
**A：**
1. **结论**：当有多种**可互换算法**、且会随输入切换时，把每个算法封装成策略，对外统一接口，运行时选择。
2. **机制**：调用方只依赖"策略接口"，不写 `if/elif`；换算法 = 换一个策略对象，开闭原则友好；各策略可单独单测。
3. **边界**：策略解决"**怎么算**"，工厂解决"**造什么**"——一个选算法、一个选对象，别混。
**加分层**：策略过多会类膨胀；可用 `dict[str, Callable]` 或 `singledispatch` 做轻量映射，不必每个策略都建类。

## 关键代码
```python
def discount_10pct(o):  return o * 0.9
def discount_25pct(o):  return o * 0.75
STRATEGY = {"ten": discount_10pct, "twentyfive": discount_25pct}

def checkout(count, total):
    key = "twentyfive" if count >= 1000 else "ten"   # 选策略
    return STRATEGY[key](total)                       # 统一接口调用
```

## ⚠️ 原文纠错
原文"策略模式：针对不同输入使用不同策略；对外暴露统一接口，内部根据输入规模采取不同策略"——准确，并予以保留（原文以超市折扣为例：满 10 个八折、超 20 个七折，"tenpercent/零点二五"分别为 **10% / 25% 折扣策略**）。机翻"pasass"=**行为型**（"行为型设计模式"），"零点一的折扣/打了一折"表述有歧义，按常识修正为"10% off / 25% off"。原文未提"与工厂模式区别"及"类膨胀/dict 轻量替代"，已在机制与加分层补充 `[经验]`。无事实错误。
