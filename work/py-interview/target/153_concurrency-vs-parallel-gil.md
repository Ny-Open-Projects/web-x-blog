# 153. 并发与并行：GIL 视角

> 分类：操作系统/并发 | 难度：L2 | 题型：概念主问 | 频率：高 | 关键词：**并发** / **并行** / **GIL**
> 原文锚点：第 9~11 段「并行是真正多核 CPU 同时执行；Python 难以利用多 CPU，只能并发」

## 一句话总述
**并行**是多核真正同时执行；**并发**是单核时间片轮转、宏观同时微观交替。CPython 因 **GIL** 同一时刻仅一个线程跑字节码，故多线程 CPU 密集只能"并发"而非"真并行"。

## 面试官视角
- **考察意图**：是否混淆并发/并行，以及是否知道 Python 多线程的 GIL 天花板。
- **P5** 能区分两个词 / **P6** 能说出 GIL 让 CPython 多线程 CPU 密集无法线性加速 / **P7** 能指出 GIL 释放点（IO/长时间纯 C 调用）、多进程绕开方案、IO 密集仍可用多线程。
- **红旗**：说"Python 多线程能利用多核"；或把并发等同于并行。
- **惊艳点**：CPython 在**进入 IO 等待**和**纯 C 扩展长时间运行**时会释放 GIL，所以网络/磁盘 IO 多线程仍有收益 —— 验证：`threading` + `time.sleep` 两线程可重叠，而纯 `while` 计算不能 `[实测]`。

## 主问答
**Q（面试官原话）：** 你总说并发并行，这俩到底啥区别？Python 多线程能跑满多核吗？

**A · 标准答案骨架：**
1. **先给结论**：**并行=同时执行**（多核）；**并发=交替执行**（时间片），Python 多线程受 GIL 限制**不能真并行**跑 CPU 任务。
2. **再给机制**：GIL 是 CPython 的**全局解释器锁**，任一时刻只有一个线程持有它并执行字节码；多核下线程仍被串行化。
3. **最后给边界**：**IO 密集型**线程在等待时会释放 GIL，多线程仍有并发收益；**CPU 密集型**想用多核必须**多进程**（multiprocessing）。

**加分层**：GIL 不是 Python 语言特性，是 CPython 实现细节；Jython/PyPy 行为不同，但面试默认指 CPython `[经验]`。

## 关键代码
```python
import threading, time

def busy():
    s = 0
    for _ in range(10_000_000):   # CPU 密集：受 GIL 限制，两线程不会真正并行
        s += 1

t1 = threading.Thread(target=busy)
t2 = threading.Thread(target=busy)
# 测量 t1+t2 并行耗时 ≈ 单线程两倍，证明未并行 [实测]
```

## ⚠️ 原文纠错
原文第 9~11 段将 GIL 音译为「**GRL**」「**give**」，正确术语为 **GIL（Global Interpreter Lock，全局解释器锁）**；"生活利用多个CPU只能并发"应为"难以利用多 CPU、只能并发"。核对范围：第 9~14 段并发/并行与 GIL 论述。

## 总结与追问预判
- 并行=多核同时；并发=时间片交替；CPython GIL 让多线程 CPU 任务只能并发。
- 顺势会问：**线程安全（见 154 卡）**、**Python 多进程绕 GIL（见 160 卡）**。
