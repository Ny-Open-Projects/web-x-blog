# 99. 面向对象编程：三大特征与过程式编程的分野

> 分类：编程范式/面向对象 | 难度：L1 | 题型：八股题 | 频率：高 | 关键词：**封装** / **继承** / **多态** / **过程式**
> 原文锚点：第 1~12 段「把对象作为基本单元，把对象抽象成一个一个的类」

## 一句话总述
**OOP** 以**对象**（类的实例）为基本单元，类 = **属性（成员）+ 方法**；靠**封装、继承、多态**解决过程式编程"复用差、业务模型表达不清"的问题。

## 面试官视角
- **考察意图**：不是背定义，而是看你能不能说出**什么时候该抽象成类**。
- **P5** 背出三大特征 / **P6** 用"用户/问题/文章"等业务模型举例说明抽象收益 / **P7** 能指出过程式的具体代价并给出"函数变多后如何收敛成类"的判断标准 `[经验]`。
- **红旗**：① 把三大特征说成"封装、继承、抽象"（**多态**才是第三个）；② 只会说"类是模板"却举不出业务例子；③ 以为"用了 class 就是面向对象"（一堆 class 里全是 static 方法，本质仍是过程式）。
- **惊艳点**：一句判别——**过程式用动词组织代码，OOP 用名词组织代码**；当一批函数反复操作同一组字段时，就该抽成类 `[实测]`。

## 主问答
**Q：什么是面向对象编程？它比过程式好在哪？**
**A：**
1. **定义**：OOP 把**对象**作为基本单元，对象由**类**抽象而来；类包含**属性（成员）**与**操作属性的方法**。
2. **三大特征**：**封装**（不直接改私有成员，走方法）、**继承**（is-a，复用父类）、**多态**（子类**重写**父类方法，同一调用不同行为）。
3. **对比过程式**：过程式以**函数**为基本单位，复用性差、**业务模型表达不清**；OOP 可把用户/回答/问题/文章抽象成类，模型清晰、易维护。
**加分层**：判别信号——一批函数总在操作同一组字段、参数里反复传同一个 dict，就是该抽类的时刻；反之只有一两个纯函数时强行建类，属于过度设计。

## 关键代码
```python
class Order:                    # 名词组织：属性与方法在一起
    def __init__(self, uid, amount):
        self.uid, self.amount = uid, amount

    def pay(self):              # 封装：通过方法改状态
        self.paid = True

def pay_process(o):             # 过程式：动词组织，状态散落在外
    o["paid"] = True
```

## 总结与追问预判
- 类 = **属性 + 方法**；三大特征是**封装 / 继承 / 多态**；过程式痛点是**复用差 + 模型不清**。
