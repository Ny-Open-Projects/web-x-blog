# 59. 哈希表什么时候扩容，扩容做了什么

> 分类：算法与数据结构/字典结构 | 难度：L3 | 题型：八股题 | 频率：中 | 关键词：**扩容** / **装载因子** / **rehash** / **摊销**
> 原文锚点：第 87~88 段「哈希表其实就是一个数组…当这个数组不断的添加元素的时候，如何去触发这个扩容操作」

## 一句话总述
哈希表的主体是一个**数组**；当**装载因子**（已用槽位 / 总槽位）超过阈值时触发**扩容**：申请更大数组并 **rehash 重排**全部元素。

## 面试官视角
- **考察意图**：是否理解"空间换时间"以及扩容为何是一次昂贵操作。
- **P5** 知道会扩容 / **P6** 说清装载因子与 rehash / **P7** 能解释"摊销 O(1)"为何成立、以及缩容的缺失。
- **红旗**：① 以为扩容是"在原数组后面追加"；② 不知道要重新计算所有元素位置；③ 以为删除元素会自动缩容。
- **惊艳点**：单次扩容是 O(n)，但因为它发生得**足够稀疏**（按倍数增长），**摊销后插入仍是 O(1)**——这是必须与面试官点破的论证。测算方式：连续插入十万条并计时，只在少数点位出现跳变尖峰 `[实测]`。

## 主问答
**Q：哈希表是怎么扩容的？代价是什么？**
**A：**
1. **先给结论**：底层是数组，元素持续增加使**装载因子**超过阈值（常见约 2/3 量级）时，分配一个**更大的新数组**。
2. **再给机制**：新数组大小变化后，元素下标 `hash % size` 也随之改变，必须把**所有已有元素重新计算位置（rehash）**搬过去，单次成本 O(n)。
3. **最后给边界**：扩容只由**插入**触发，**删除不会缩容**（删多插少会长期占着大数组）；扩容期间是一次性峰值开销，会造成偶发延迟抖动。
**加分层**：摊销分析——按倍数扩容时，n 次插入的总搬迁量是 O(n)，故**均摊插入仍为 O(1)**；能预估规模时**预分配容量**可彻底避开抖动。

## 关键代码
```python
import sys
d = {}
sizes = []
for i in range(1, 20001):
    d[i] = i
    if i in (1, 100, 1000, 10000, 20000):
        sizes.append((i, sys.getsizeof(d)))
print(sizes)                       # 容量随规模阶梯式跳变 [实测]
# 删除不缩容
big = {i: i for i in range(100000)}
before = sys.getsizeof(big)
for i in range(90000): del big[i]
print(before, sys.getsizeof(big))  # 删除后占用不回落 [实测]
```

## ⚠️ 原文纠错
原文正确指出"表就是一个数组"并提示关注扩容触发，但未展开 rehash 与摊销分析，卡面已补齐；另需补正**删除不会触发缩容**。转写中的音译词已统一还原为标准术语。未发现原理性错误。

## 总结与追问预判
- 装载因子超阈值 → 新数组 + rehash；只增不缩，摊销 O(1)。
