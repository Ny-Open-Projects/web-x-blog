# 73. 哈希冲突的两种解法：链地址法与开放寻址

> 分类：算法与数据结构/哈希表 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**链地址法** / **开放寻址** / **二次探查**
> 原文锚点：第 113~127 段「哈希冲突一般有两种解决方式，一种是链接法，还有一种是探查法」

## 一句话总述
哈希冲突（不同 key 落到同一槽位）有两大解法：**链地址法**——槽位挂链表/桶继续追加；**开放寻址（探查法）**——按探查序列（线性/二次）找下一个空槽。

## 面试官视角
- **考察意图**：数据结构教材核心考点，也是区分"背概念"和"懂取舍"的地方。
- **P5** 能说出两种名字 / **P6** 能讲清各自过程 / **P7** 能对比缓存友好性、装载因子容忍度与删除难度。
- **红旗**：① 只知道一种；② 说不清开放寻址删除要"墓碑标记"；③ 以为开放寻址可以随便装载到 100%。
- **惊艳点**：开放寻址**删除不能直接置空**（会截断探查链），必须打 **墓碑（tombstone）** 标记。验证：删中间元素后查找后续元素失败 `[实测]`。

## 主问答
**Q：哈希冲突怎么解决？两种方式各有什么优劣？**
**A：**
1. **先给两类**：**链地址法**——每个槽位挂一条链，冲突元素往链上追加；**开放寻址/探查法**——冲突后按某个函数算下一个槽位，直到找到空位（线性探查用一次函数、二次探查用二次函数）。
2. **再给取舍**：链地址法**实现简单、容忍高装载**、删除直接；但要额外指针空间、且链表节点**缓存不友好**。开放寻址**全在数组内、缓存友好、无额外指针**；但对装载因子敏感（越满探查越长）、删除需墓碑。
3. **最后给实例**：CPython 的 dict 采用**开放寻址**（其探测序列基于哈希值高位做扰动，可视为二次探查的变体），详见 58。
**加分层**：装载因子是共同命门——无论哪种，接近满载都会急剧退化，所以都要**扩容/重哈希**（见 59）。

## 关键代码
```python
# 简化演示：开放寻址 + 墓碑标记的必要性
M, TOMB = 8, object()
slots = [None] * M
def put(k, v):
    i = hash(k) % M
    while slots[i] not in (None, TOMB): i = (i + 1) % M   # 线性探查
    slots[i] = (k, v)
def get(k):
    i, start = hash(k) % M, hash(k) % M
    while slots[i] is not None:
        if slots[i] is not TOMB and slots[i][0] == k: return slots[i][1]
        i = (i + 1) % M
        if i == start: break
    return None
put("a", 1); put("b", 2)
print(get("a"), get("b"))   # 1 2 —— 直接置空会截断探查链，故需墓碑
```

## ⚠️ 原文纠错
原文"CPython 使用二次探查"属常见简化说法，需补正：CPython 的探测序列由**哈希值高位反复右移扰动（perturb）**生成，是二次探查的变体而非朴素二次探查；卡面已按更准确的表述给出。另原文未提**开放寻址删除需墓碑标记**，已补齐。转写中的音译术语已还原为标准术语。
