# 138. 实战：策略模式做订单折扣（按数量选折扣策略）

> 分类：编程范式/设计模式 | 难度：L3 | 题型：代码题 | 频率：中 | 关键词：**折扣策略** / **订单数量** / **可互换** / **统一调用**
> 原文锚点：第 48~53 段「订单按数量选折扣策略：100 个用 ten_percent，1000 个用 0.25 折扣」

## 一句话总述
源里的例子：订单按**数量**选择折扣——100 个走 `ten_percent`（10% off）、1000 个走 `0.25`（25% off），对外只暴露一个统一入口，内部据数量挑策略，这就是策略模式的落地。

## 面试官视角
- **考察意图**：考你能否把"按条件选算法"从 `if/elif` 重构成**策略对象/映射**，并讲清扩展点。
- **P5** 能写出按数量返回不同折扣的函数 / **P6** 能把它重构成**策略映射（dict / 类）**，说明新增档位只加策略、不动调用方 / **P7** 能指出源里"硬编码数量阈值（100/1000）"应抽到配置，并指出**折扣策略应是纯函数**便于测试 `[经验]`。
- **红旗**：① 写成一长串 `if/elif` 还自称策略模式（那是被取代的反面）；② 策略里夹带副作用（改全局状态）；③ 阈值写死在逻辑里无法配置。
- **惊艳点**：用 `dict[threshold, strategy]` 或 `bisect` 做**区间分档**，数量阈值可配置、可排序，比散落的 `if` 更稳。验证：传入不同数量得到不同折扣且无分支嵌套 `[实测]`。

## 主问答
**Q：用策略模式实现"数量越多折扣越大"的订单计价？**
**A：**
1. **结论**：把每个折扣档位封装成**独立策略**（纯函数或类），再用一张"数量→策略"的映射来选。
2. **机制**：调用方只调 `checkout(count, total)`，内部按数量查映射得到策略并执行；新增档位只加一条映射。
3. **边界**：折扣策略应是**纯函数**（同输入输出一致、无副作用），方便单测；数量阈值抽到配置而非写死。
**加分层**：档位多时可用 `bisect` 在区间表里二分定位策略，避免线性判断。

## 关键代码
```python
def ten(o):      return o * 0.9
def twentyfive(o): return o * 0.75
def checkout(count, total):
    strategy = twentyfive if count >= 1000 else ten   # 选策略（应抽到配置）
    return strategy(total)

print(checkout(100, 100.0))    # 90.0
print(checkout(1000, 100.0))   # 75.0
```

## ⚠️ 原文纠错
原文示例逻辑正确（订单按数量选折扣：100 个用 `ten_percent` 即 10% off，1000 个用 `0.25` 即 25% off，"tenpercent"=**ten_percent**）。机翻"零点一的折扣/打了一折"表述歧义，已按"10% off / 25% off"修正。原文把阈值（100/1000）写死在示例逻辑里，卡面在 P7 与加分层指出应抽到配置、策略应为纯函数 `[经验]`。无事实性错误，仅折扣表述需澄清。
