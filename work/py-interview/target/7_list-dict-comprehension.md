# 7. 列表推导与字典推导

> 分类：语言特性 | 难度：L1 | 题型：代码题 | 频率：高 | 关键词：**comprehension** / **zip** / **替代 map/filter**
> 原文锚点：第 83~92 段「返回 0 到 9 之间所有偶数的数字…我们使用字典推导来简化这个操作」

## 一句话总述
推导式把**构造 + 过滤**压成一行，可读性优于 `map`/`filter` 嵌套；`zip` 配合字典推导是最常见的两表合成字典写法。

## 面试官视角
- **考察意图**：写出来的代码是不是"Pythonic"，以及是否知道推导式的适用边界。
- **P5** 会写 `[x for x in ... if ...]` / **P6** 会用 `zip` 做字典推导 / **P7** 知道**什么时候不该用推导式**。
- **红旗**：① 把带副作用的逻辑塞进推导式；② 多重嵌套推导式（可读性反噬）；③ 以为推导式一定更快。
- **惊艳点**：推导式相对 `append` 循环只是**省掉方法查找**的量级提升，**不是算法级加速**；数据量大时瓶颈在别处 `[经验]`。

## 主问答
**Q：给你两个列表 a 和 b，怎么快速生成 {a[i]: b[i]} 的字典？**
**A：**
1. **先给结论**：`{k: v for k, v in zip(a, b)}`，一行搞定，比先建空字典再循环赋值清晰得多。
2. **再给机制**：推导式把"遍历 + 过滤 + 构造"三步合并为表达式；`zip` 成对迭代两个序列，长度不一致时以**较短者**为准。
3. **最后给边界**：推导式适合**单一表达式**的构造；一旦逻辑需要多分支或副作用，就该退回普通 `for` 循环，否则可维护性反而下降。
**加分层**：`zip` 截断到最短序列是静默行为，长度必须严格对齐时应显式断言或改用 `strict=True`。

## 关键代码
```python
a, b = ["a", "b", "c"], [1, 2, 3]
d = {k: v for k, v in zip(a, b)}        # {'a': 1, 'b': 2, 'c': 3}
evens = [i for i in range(10) if i % 2 == 0]   # [0, 2, 4, 6, 8]
```
