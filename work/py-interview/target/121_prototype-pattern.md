# 121. 原型模式：用克隆代替昂贵构造

> 分类：编程范式/设计模式 | 难度：L2 | 题型：八股题 | 频率：低 | 关键词：**prototype** / **克隆** / **copy.deepcopy** / **构造开销**
> 原文锚点：第 43~47 段「原型模式通过克隆原来的原型来创建新的实例」

## 一句话总述
**原型模式**通过**克隆（clone）已有原型**来创建新实例：当新对象与原对象**只有少数字段不同**，或**构造代价很高**（要读库、要 IO）时，复制一份再改比重新构造更划算。

## 面试官视角
- **考察意图**：考你是否把它和**深浅拷贝**联系起来——这才是 Python 侧的真考点。
- **P5** 知道是"克隆创建对象" / **P6** 能说出 `copy.copy` / `copy.deepcopy` 的差别并选择 / **P7** 能指出**浅拷贝共享嵌套可变对象**的坑，并给出 `deepcopy` 与自定义 `__deepcopy__` 的取舍 `[源码]`。
- **红旗**：① 用浅拷贝克隆含嵌套 list/dict 的原型，改一个**两个都变**；② 认为 deepcopy 一定安全（它会**递归复制**、可能很慢且对文件句柄/连接等**不可复制对象**报错）；③ 说不出适用场景。
- **惊艳点**：判断标准——**原型里有没有嵌套可变对象**；没有就用 `copy.copy`（快），有就用 `deepcopy`（安全）。验证：浅拷贝后 `a.items is b.items` 为 `True` `[实测]`。

## 主问答
**Q：什么是原型模式？Python 里怎么实现？**
**A：**
1. **定义**：通过**克隆原型**创建新实例，而非走构造函数；适合**差异很小**或**创建开销大**（需查询数据库、加载大对象）的场景。
2. **实现**：Python 用 `copy` 模块——`copy.copy(obj)` 浅拷贝（只复制一层，**嵌套对象仍共享**），`copy.deepcopy(obj)` 深拷贝（**递归复制**全部层级）。
3. **注意**：深拷贝**更慢**且可能失败（遇到文件句柄、socket、锁等不可复制对象需自定义 `__deepcopy__`）；很多类还提供自己的 `.copy()`（如 `dict.copy()`、列表切片）。
**加分层**：与单例/工厂的关系——原型是**创建型**的第三选择：构造贵用原型、构造复杂用 Builder、构造多态用工厂。

## 关键代码
```python
import copy

class Proto:
    def __init__(self, name, items): self.name, self.items = name, items

p = Proto('base', [1, 2])
shallow = copy.copy(p)
deep = copy.deepcopy(p)

print(shallow.items is p.items)      # True  —— 浅拷贝共享嵌套 list
print(deep.items is p.items)         # False —— 深拷贝独立
shallow.items.append(3)
print(p.items)                       # [1, 2, 3] —— 原型被污染
```
