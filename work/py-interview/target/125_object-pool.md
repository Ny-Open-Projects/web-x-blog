# 125. 对象池：预建一批实例，用完归还而不是销毁

> 分类：编程范式/设计模式 | 难度：L2 | 题型：工程题 | 频率：中 | 关键词：**对象池** / **复用** / **连接池** / **acquire/release**
> 原文锚点：第 11 段「对象池的模式就是我们会分配一些同一类型的一组实例」

## 一句话总述
**对象池**预先创建**一批同类型实例**，使用时 `acquire` 取出、用完 `release` **归还**（而非销毁），从而**摊薄创建与销毁的开销**；数据库连接池、线程池、HTTP 连接池都是它的实例。

## 面试官视角
- **考察意图**：考你能否把它和**享元**区分开，并说出工程上真正的难点（归还、泄漏、失效检测）。
- **P5** 能说出"复用对象" / **P6** 能说明连接池的四个核心参数（最小/最大/超时/校验）/ **P7** 能指出**未归还导致池耗尽**、**归还脏状态**、**连接已断但仍在池里**三类事故及对策 `[经验]`。
- **红旗**：① 只说"复用"却讲不出 `acquire/release` 契约；② 忘了**归还时重置状态**（上次的事务、缓冲区残留）；③ 认为池越大越好（连接数过大反而拖垮数据库）。
- **惊艳点**：对象池 vs 享元——**池里的对象同一时刻只能被一个使用者占用（互斥）**，享元则是**被多方同时共享的不可变状态**。验证：池在 `acquire` 后计数减一，再次取空会阻塞 `[实测]`。

## 主问答
**Q：什么是对象池模式？用在哪些地方？**
**A：**
1. **定义**：预先创建**一组同类型实例**放入池中；需要时取出、用毕**归还**，避免频繁创建/销毁。
2. **典型**：**数据库连接池**（DBUtils、SQLAlchemy 的 pool）、线程池、HTTP 连接池——原文指出用 ORM 或数据库时都会用到连接池。
3. **收益**：**预先创建**好连接，每次从池里取，显著减少资源创建的时间与消耗。
**加分层**：工程三件事——① 必须有**上限**与**获取超时**，否则泄漏会拖垮服务；② 归还前**重置状态**（回滚未提交事务、清空缓冲）；③ 取用时做**有效性校验**（`ping`/`SELECT 1`），剔除已断开的连接。

## 关键代码
```python
import queue, threading

class Pool:
    def __init__(self, factory, size=3):
        self._q = queue.Queue(size)
        for _ in range(size):
            self._q.put(factory())          # 预先创建

    def acquire(self, timeout=1): return self._q.get(timeout=timeout)
    def release(self, obj):       self._q.put(obj)          # 归还而非销毁

pool = Pool(lambda: {'conn': object()})
o = pool.acquire()
pool.release(o)
print(pool.acquire() is not None)           # True —— 复用同一批
```

## ⚠️ 原文纠错
原文"对象池的模式就是我们会分配一些同一类型的一组实例"，概括正确，予以保留；原文在结构型一章补充"享元模式通过对象池的复用技术改善资源利用、数据库连接会预先创建很多连接，每次从池子里取一个，大大减少资源创建与消耗的时间"，与对象池机制一致。原文未涉及归还、泄漏与失效校验，卡面补充的工程三件事属扩展，已用 `[经验]` 标注。转写中的音译词已还原为标准术语。
