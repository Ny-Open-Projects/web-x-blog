# 101. Python 没有 private：下划线约定与名称改写

> 分类：编程范式/Python 类 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**下划线约定** / **名称改写** / **魔术方法** / **约定优于强制**
> 原文锚点：第 27~29 段「Python 里面并没有访问限定符，所有属性都可以访问」

## 一句话总述
Python **没有真正的访问限定符**：单下划线 `_x` 是"请勿外部访问"的**约定**，类体内双下划线 `__x` 触发**名称改写**成 `_类名__x`（只是改名，仍可访问）；`__len__` 这类 dunder 是**魔术方法**，由内置函数与运算符间接调用。

## 面试官视角
- **考察意图**：考"Python 的封装是约定而非强制"这条哲学，以及 `__` 的真实机制。
- **P5** 知道 `_x` 表示私有 / **P6** 说清 `__x` 是**改名**不是禁止、写得出 `_A__x` / **P7** 能指出改写**只发生在类体内**、`__x__` 前后都有下划线**不改写** `[源码]`。
- **红旗**：① 说"双下划线外部访问不了"（`obj._A__x` 照样取到）；② 把 `__x__` 也当成私有；③ 不知道 `len(obj)` 走的是 `__len__`。
- **惊艳点**：名称改写的真实目的**不是安全，而是避免子类意外覆盖父类属性**。验证：`class A: __x=1` 后 `A().__dict__` 的键是 `_A__x` `[实测]`。

## 主问答
**Q：Python 怎么表示私有属性？双下划线真的私有吗？**
**A：**
1. **无强制**：Python 没有访问限定符，**所有属性都能访问**，靠**约定**表达意图。
2. **单下划线**：`_x` 表示"不希望被外部访问"；`from module import *` 也不会导入它。
3. **双下划线**：类体内 `__x` 被改写为 `_类名__x`，**仍能访问**；前后都带双下划线的 `__x__` 是**魔术方法**，不改写。
**加分层**：`len(obj)` 实际调 `obj.__len__()`，`obj[i]` 调 `__getitem__`；自定义容器就是实现这些 dunder。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| Python 2/3 一致 | 改写规则未变 | 按 _类名__x 作答 |
| 仅类体内改写 | 函数内 __x 不改写 | 说明作用域差异 |
| dunder 不改写 | 前后双下划线 | 属公开协议 |

## 关键代码
```python
class A:
    def __init__(self):
        self.__x = 1        # 类体内 → 改名为 _A__x

a = A()
print(a.__dict__)           # {'_A__x': 1}
print(a._A__x)              # 1 —— 仍能访问
# print(a.__x)              # AttributeError
```

## ⚠️ 原文纠错
原文称"Python 里面并没有访问限定符，所有属性都可以访问"，属实，予以保留。原文把双下划线开头的都称为"魔术方法"，表述不够准确：只有**前后均带双下划线**的 `__len__` 等才是魔术方法，前面双下划线、后面没有的会触发**名称改写**，卡面已按此区分。转写中的音译词已还原为标准术语。

## 总结与追问预判
- `_x` 约定、`__x` 改名、`__x__` 魔术方法；封装靠**约定**而非强制。
