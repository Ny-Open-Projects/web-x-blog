# 130. 外观模式：用一个高层接口简化复杂子系统

> 分类：编程范式/设计模式 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**外观模式** / **简化访问** / **高层接口** / **解耦**
> 原文锚点：第 9 段「外观模式就是用来简化一些复杂对象的访问」

## 一句话总述
**外观模式**为一组**复杂子系统**提供一个**统一的高层接口**，让调用方**只跟外观打交道**，而不必了解内部一堆类和方法，从而降低耦合、减少使用门槛。

## 面试官视角
- **考察意图**：考你能否分清外观（简化一整组）与适配器（改单个接口形状）与代理（控访问）。
- **P5** 能说出"用一个接口包住复杂调用" / **P6** 能举出实例（如 Django 的 `manage.py`、ORM 的 `Session` 封装连接/事务/映射）/ **P7** 能指出外观**不隔离子系统**本身，仍可绕过外观直接调用，以及过度封装会**藏住必要细节** `[经验]`。
- **红旗**：① 把外观说成"只改一个接口"（那是适配器）；② 认为用了外观就**不能**直接调子系统（外观是可选项，非强制）；③ 和门面后的对象强耦合。
- **惊艳点**：外观是**结构化入口**而非新功能——它**聚合**已有调用，不替代子系统逻辑。验证：外观方法内部仍是依次调子系统的既有方法 `[实测]`。

## 主问答
**Q：外观模式是什么？和适配器有什么区别？**
**A：**
1. **结论**：外观提供一个**高层统一入口**，把多个子系统的调用**打包**成一步，调用方无需逐个了解。
2. **机制**：外观内部**持有并调用**子系统对象，本身**不实现业务逻辑**，只是编排；子系统仍可独立使用。
3. **边界**：外观**简化但不隔离**——需要精细控制时仍可绕过它直接调子系统；别把必要的细节也藏掉。
**加分层**：和适配器区分——适配器是"把 A 接口换成 B 接口"，外观是"把 N 个调用合成 1 个"。

## 关键代码
```python
class SubSystemA:
    def connect(self): return "连接"
class SubSystemB:
    def query(self):   return "查询"

class Facade:                         # 外观：打包两步为一
    def __init__(self):
        self._a, self._b = SubSystemA(), SubSystemB()
    def do(self):
        return f"{self._a.connect()} -> {self._b.query()}"   # 只暴露 do()
```
