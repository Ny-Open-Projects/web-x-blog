# 80. 算法题现场没思路，怎么把损失降到最低

> 分类：算法与数据结构/面试方法 | 难度：L2 | 题型：事故题 | 频率：中 | 关键词：**次优解** / **沟通** / **拆解约束** / **不空转**
> 原文锚点：第 50~62 段「如果我们想不到最优的算法，我们可以提供一个次优的，只要能解决这个问题也行」

## 一句话总述
现场卡壳时，**不要沉默空转**：先**复述题意确认理解** → 讲出**暴力/次优解**并说明复杂度 → 与面试官**逐步对齐约束** → 在次优基础上**尝试优化**；能解决问题的方案远好于零产出。

## 面试官视角
- **考察意图**：观察**压力下的沟通与拆解能力**，这本身就是评分项。
- **P5** 会直接说"不会" / **P6** 能给出次优解并分析复杂度 / **P7** 能通过提问缩小问题规模，甚至把面试官变成协作方。
- **红旗**：① 长时间沉默；② 直接放弃不说话；③ 硬编一个不成立的"最优解"被发现。
- **惊艳点**：主动问"这个场景的数据规模/内存限制是多少" —— 很多题**约束一变，解法就变**（如 TopK，内存够用排序、不够用堆，见 76）。验证：面试官通常乐意补充约束 `[经验]`。

## 主问答
**Q：面试时算法题完全没思路，你会怎么办？**
**A：**
1. **先给原则**：**先给能跑的次优解**。暴力解也是解，写出来并说明它的复杂度与瓶颈，比空着强得多——面试官要的是**能解决问题的人**。
2. **再给动作**：**复述题意**确认自己理解无误；**问清楚数据规模与约束**（内存、是否允许改原数据、是否有序），很多题在补充约束后答案会自然浮现；把问题**拆成小步骤**逐个攻克。
3. **最后给心态**：边写边**讲思路**，让面试官能随时纠正方向；如果最终确实做不出，坦诚说明薄弱环节——会是减分项，但**不影响后面的题**。
**加分层**：最忌讳的是被一题卡住后心态崩掉、影响后续发挥；正确的做法是**及时止损、把剩下的题答好**。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 不会时怎么办 | 心态 | 给次优解 | 换题 → 不及格 |
| L2 | 次优解有用吗 | 策略 | 有，先跑通 | 判 P5 |
| L3 | 要不要提问 | 沟通 | 要，问清约束 | 判 P6 |

| L5 | 失败后怎么调整 | 复盘 | 止损、保后续题 | 答上判 P7 |

## 关键代码
```python
# 演示"先给次优、再优化"的现场节奏：以 TopK 为例
def topk_brute(data, k):              # 次优：全排序，O(n log n)，但一定能过
    return sorted(data, reverse=True)[:k]

def topk_heap(data, k):               # 优化：小顶堆，O(n log k) / O(k)（见 76）
    import heapq
    h = []
    for v in data:
        if len(h) < k: heapq.heappush(h, v)
        elif v > h[0]: heapq.heapreplace(h, v)
    return h

data = [3, 1, 5, 9, 2, 6]
print(topk_brute(data, 3), sorted(topk_heap(data, 3), reverse=True))
```
