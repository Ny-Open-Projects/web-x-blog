# 193. 高并发场景下的并发插入去重

> 分类：数据库 | 难度：L2 | 题型：工程题 | 频率：中 | 关键词：**唯一索引** / **队列异步** / **分布式锁** / **INSERT IGNORE** / **幂等**
> 原文锚点：第 60~67 段「并发写入可能插入重复数据；三种解法：唯一索引（重复抛异常忽略）、队列异步串行写、Redis 分布式锁」

## 一句话总述
高并发插入要去重，常用三招：**① 唯一索引**（重复时数据库抛异常，捕获忽略即可，最简单）、**② 消息队列异步串行写入**（削峰 + 串行化避免并发冲突）、**③ Redis 分布式锁**（插入前加锁、插完释放）——本质都是"**用约束或串行化换一致性**"。

## 面试官视角
- **考察意图**：是否掌握"高并发去重"的工程套路，理解缓存/队列在并发中的普遍价值。
- **P5** 能说出唯一索引 / **P6** 能讲清三种方案各自适用场景与代价（唯一索引有上限、队列解耦削峰、分布式锁防多机并发） / **P7** 能指出分库分表后单库唯一索引失效，必须用**分布式唯一键（如雪花算法）或分布式锁/队列**兜底。
- **红旗**：认为"唯一索引万能"（分库分表后跨库不生效）；或把分布式锁当银弹（锁粒度/死锁/超时都要考虑）。
- **惊艳点**：大量高并发问题本质是"**竞态**"，通用解法是**缓存 + 队列 + 锁**三件套——去重只是其中一例，限流、削峰同理 `[经验]`。

## 主问答
**Q（面试官原话）：** 高并发下怎么防止重复插入？

**A · 标准答案骨架：**
1. **先给结论**：三招——**唯一索引、队列异步写、分布式锁**，按是否分库分表与并发规模选型。
2. **再给机制**：**唯一索引**最直接，重复插入数据库抛 `DuplicateKey` 异常，捕获忽略即可；**队列**把写入请求丢进 MQ，消费者**单线程/串行**处理，天然去重又削峰；**Redis 分布式锁**在插入前 `SET NX` 加锁、插完释放，跨进程互斥。
3. **最后给边界**：**分库分表后单库唯一索引管不住跨片重复**，必须上**分布式唯一键（雪花算法等）或全局分布式锁/队列**；且唯一索引对写入量有上限，超高并发优先队列削峰。

**加分层**：去重要兼顾**幂等**——即使请求重复到达，结果也一致；唯一索引/分布式锁/幂等表都是手段 `[经验]`。
