# 76. 一亿个数里取最大的 K 个，为什么用小顶堆

> 分类：算法与数据结构/堆 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**TopK** / **小顶堆** / **heapreplace** / **内存受限**
> 原文锚点：第 158~193 段「给了你一亿个数字，让你找出最大的十个，但是只给你很少的内存」

## 一句话总述
求最大的 K 个，维护一个**容量为 K 的小顶堆**：堆顶是"当前入选者里最小的"，新元素**比堆顶大就替换**，否则丢弃；扫完全部数据后堆内即 TopK，**时间 O(n log K)、空间 O(K)**。

## 面试官视角
- **考察意图**：把"内存受限"这个约束落到数据结构选型上，是区分度的经典题。
- **P5** 想到排序取前 K / **P6** 能给出小顶堆方案并算对复杂度 / **P7** 能说明为什么是**小**顶堆、以及 `heapreplace` 相比 `pop`+`push` 的优势。
- **红旗**：① 说"用大顶堆"（大顶堆保留的是最小的 K 个）；② 直接 `sorted(data)[-K:]`（内存爆掉）；③ 复杂度写成 O(n log n)。
- **惊艳点**：`heapq.heapreplace(h, x)` = **先弹后压**且只做一次下沉调整，比 `heappop`+`heappush` 少一次调整，且**堆大小恒定**。验证：百万级数据计时对比 `[实测]`。

## 主问答
**Q：海量数据里取最大的 K 个，内存有限，怎么做？**
**A：**
1. **先给结论**：维护**容量 K 的小顶堆**——因为要淘汰的是"当前最小的那个"，小顶堆能在 O(1) 看到它、O(log K) 换掉它。
2. **再给流程**：先取前 K 个建堆；之后逐个遍历剩余元素——`if x > heap[0]` 则 `heapreplace(heap, x)`，否则**直接跳过**。
3. **最后给复杂度**：时间 **O(n log K)**（每次最多一次 log K 调整）、空间 **O(K)**，与数据总量 n 解耦，因此可以**流式处理**上亿条数据。
**加分层**：对比全排序 `sorted(data)[-K:]` 需 O(n) 内存且 O(n log n) 时间，在"一亿个数、内存很少"的前提下直接出局；多路归并/分桶是 K 极大时的进阶方案。

## 关键代码
```python
import heapq, random

def topk(iterable, k):
    heap = []
    for v in iterable:
        if len(heap) < k:
            heapq.heappush(heap, v)        # 先填满 K 个
        elif v > heap[0]:
            heapq.heapreplace(heap, v)     # 比堆顶大才替换，堆大小恒定
    return heap                            # 堆内即最大的 K 个（无序）

data = list(range(1000)); random.shuffle(data)
print(sorted(topk(data, 10), reverse=True))   # [999, 998, ... 990] [实测]
print(heapq.nlargest(10, data))               # 静态数据可直接用内置
```

## ⚠️ 原文纠错
原文"用最小堆求最大 K 个"的思路与逐步图解均正确；两处补正：① 原文口语中"如果堆顶元素大于当前元素就替换"表述颠倒，正确条件是**当前元素大于堆顶**才替换，卡面已更正；② 原文未给出复杂度，已补 O(n log K) / O(K)。转写中的音译函数名已还原为 heapq / heapreplace / nlargest。
