# 119. 抽象工厂：一族产品一起换，而不是一个一个换

> 分类：编程范式/设计模式 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**抽象工厂** / **产品族** / **工厂的工厂** / **一致性**
> 原文锚点：第 20 段「它其实包括两个，一个是工厂方法，还有一个是抽象工厂」

## 一句话总述
**抽象工厂**是"**工厂的工厂**"：一个工厂接口负责创建**一族相关产品**（如同一风格的按钮+输入框+滚动条），换工厂就**整族切换**，保证产品之间**风格/协议一致**。

## 面试官视角
- **考察意图**：看你能不能说出抽象工厂**与工厂方法的真实区别**，而不是背两个名字。
- **P5** 只能说出"工厂方法是造一个，抽象工厂造一组" / **P6** 能举出**跨平台 UI、多数据库驱动**这类产品族场景 / **P7** 能指出在 Python 鸭子类型下抽象工厂常被**配置 + 字典/模块切换**简化掉，并说明何时才值得引入 `[经验]`。
- **红旗**：① 说"抽象工厂就是有多个工厂方法的类"（抓住了表象没抓住**产品族约束**）；② 举不出任何需要整族切换的场景；③ 在只有单一产品时硬套抽象工厂。
- **惊艳点**：核心价值是**一致性保证**——避免把 Windows 按钮和 Mac 滚动条混着用；Python 里通常用**一个配置开关 + 两个模块**（`light_theme` / `dark_theme`）就能等价实现 `[实测]`。

## 主问答
**Q：抽象工厂和工厂方法有什么区别？什么时候用抽象工厂？**
**A：**
1. **工厂方法**：一个工厂方法造**一种产品**，通过子类决定造哪个（118）。
2. **抽象工厂**：一个工厂接口造**一组相关产品**（产品族），客户端只依赖抽象工厂与抽象产品，**换工厂即换整族**。
3. **场景**：跨平台 UI 组件、多套数据库驱动（连接/游标/事务）、多主题渲染器；共同点是**产品必须配套使用**。
**加分层**：Python 里因为鸭子类型 + 模块即命名空间，常把"抽象工厂"简化为**按配置导入不同模块**（`importlib.import_module`）——同样实现整族切换，样板代码少得多。

## 关键代码
```python
class LightFactory:                       # 一族产品
    def button(self): return '<button class="light">'
    def input(self):  return '<input class="light">'

class DarkFactory:                        # 另一族，接口一致
    def button(self): return '<button class="dark">'
    def input(self):  return '<input class="dark">'

def render(factory):                      # 客户端只依赖抽象接口
    return factory.button() + factory.input()

print(render(LightFactory()))             # 整族切换，风格一致
print(render(DarkFactory()))
```
