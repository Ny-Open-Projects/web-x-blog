# 212. Redis 持久化：RDB 与 AOF

> 分类：数据库·缓存 | 难度：L3 | 题型：对比 | 频率：高 | 关键词：**RDB** / **AOF** / **快照** / **追加日志** / **持久化取舍**
> 原文锚点：第8章 8-4「持久化两种方式：RDB(定时快照,SAVE/BGSAVE,恢复快但丢间隔数据) / AOF(append only,每写命令追加,丢数据少但文件大恢复慢)；按业务特性选择」

## 一句话总述
**Redis 两种持久化**：RDB 定时快照（恢复快、丢间隔数据）、AOF 追加每条写命令（丢数据少、文件大恢复慢）；按业务对"恢复速度 vs 数据丢失量"的容忍度选择。

## 面试官视角
- **考察意图**：是否懂两种方式的优缺点与适用场景，而非只背名词。
- **P5** 能说出 RDB 快照、AOF 追加两种 / **P6** 能对比"RDB 恢复快但可能丢一整段、AOF 丢得少但文件大恢复慢" / **P7** 能补充"BGSAVE 后台 fork、AOF 重写、混合持久化（Redis 4+）"等生产细节。
- **红旗**：认为"开了持久化就绝对不丢数据"；分不清 SAVE（阻塞）与 BGSAVE（后台）。
- **惊艳点**：能点出"生产常 RDB + AOF 混合（aof-use-rdb-preamble），兼顾恢复速度与数据安全" `[经验]`。

## 主问答
**Q（面试官原话）：** Redis 的持久化有哪几种？各有什么优缺点？

**A · 标准答案骨架：**
1. **RDB（快照）**：每隔一段时间把数据库状态存成压缩的 RDB 文件（如 `SAVE` 阻塞、`BGSAVE` 后台 fork 执行）。**优点**：文件紧凑、恢复快、可恢复到某时间点快照；**缺点**：若宕机在两次快照之间，会丢失整个间隔的数据。
2. **AOF（Append Only File）**：把每条写命令追加到 AOF 文件。**优点**：宕机时丢失的数据远少于 RDB；**缺点**：文件可能很大、恢复速度不如 RDB。
3. **选择**：按业务特性——容忍少量丢失选 RDB，要求尽量少丢选 AOF，生产常二者结合。

**加分层**：`BGSAVE` 通过 fork 子进程做快照不阻塞主线程；AOF 有重写机制压缩历史命令；Redis 4.0+ 支持 RDB-AOF 混合持久化。
