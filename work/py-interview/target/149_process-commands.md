# 149. 进程命令：ps / grep / kill（-9 与 -15）/ top / htop

> 分类：操作系统/Linux | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**ps** / **kill** / **SIGKILL** / **SIGTERM** / **端口排查**
> 原文锚点：第 50~57 段「ps 与 grep 配合查进程；kill 发信号，kill -9 与 kill -15 区别；top/htop 监控」

## 一句话总述
查进程用 **`ps aux | grep 名`**；终止用 **`kill`**——`kill -15`（SIGTERM）是**优雅终止**（让进程清理后退出），`kill -9`（SIGKILL）是**强制杀**（不可捕获、不清理），生产上优先 -15、必要时才 -9。

## 面试官视角
- **考察意图**：考你是否懂 **信号** 语义，而非只会 `kill -9`。
- **P5** 能写出 `ps aux | grep xxx` 和 `kill PID` / **P6** 能讲清 **-15 SIGTERM（可捕获、优雅）vs -9 SIGKILL（强制、不清理、可能丢数据）**，以及 `ps`/`top` 看 CPU/内存 / **P7** 能指出 `kill -9` 会导致**未刷盘、锁未释放、子进程变孤儿**，以及卡死时先 -15 再 -9 的处置顺序 `[经验]`。
- **红旗**：① 一律 `kill -9` 且说不出后果；② 以为 `kill` 默认是 -9（默认是 -15）；③ 用 `kill` 当"重启"手段而不查根因。
- **惊艳点**：`kill -l` 列出全部信号；`kill PID` 默认发 SIGTERM(15)。验证：`kill -15 PID` 后进程可 `atexit` 清理，`kill -9` 则直接消失 `[实测]`。

## 主问答
**Q：怎么查进程、怎么杀？kill -9 和 -15 区别？**
**A：**
1. **结论**：`ps aux | grep 名` 定位进程；`kill PID` 默认发 **SIGTERM(-15)**，`kill -9` 发 **SIGKILL**，二者语义完全不同。
2. **机制**：**-15** 进程可捕获、先做清理（flush、释锁、关连接）再退出，是**优雅**做法；**-9** 内核直接终止、进程**无机会清理**，可能丢数据或留孤儿进程。
3. **边界**：先 -15、等几秒无效再 -9；`top`/`htop` 实时监控 CPU/内存，定位"卡死/吃资源"的进程。
**加分层**：`kill -9` 后应检查是否有残留子进程（变孤儿被 init 收养）与未释放的端口/文件锁。

## 关键代码
```bash
ps aux | grep nginx          # 查进程
kill 1234                   # 默认 SIGTERM(15)，优雅
kill -9 1234                # SIGKILL，强制（最后手段）
kill -l                     # 列出全部信号
top                         # 实时监控 CPU/内存
```

```python
import os, signal
os.kill(pid, signal.SIGTERM)       # 等价 kill -15 pid（优雅）
os.kill(pid, signal.SIGKILL)       # 等价 kill -9 pid（强制，最后手段）
```

## ⚠️ 原文纠错
原文"用 ps 配合 grep 查指定进程；kill 加参数发不同信号，kill -9 与 kill -15 区别是发送不同信号"——准确（机翻"q命令"=**kill**，"q杠九/q杠十五"=**kill -9 / kill -15**，"grab"=**grep**）。原文未强调"默认 kill 是 -15 而非 -9"及"-9 导致不清理/孤儿进程"，已在机制与 P7 补充 `[经验]`。无事实错误，仅术语音译需还原。
