# 22. 哪些内置类型可变，哪些不可变

> 分类：语言基础/数据模型 | 难度：L1 | 题型：八股题 | 频率：高 | 关键词：**可变对象** / **可哈希** / **tuple 陷阱**
> 原文锚点：第 59~64 段「布尔值、整数值、float、tuple、string 以及 frozenset 都是不可变对象…list、set、dict 可以修改」

## 一句话总述
不可变 = 创建后**内容不能原地改**（bool/int/float/str/bytes/tuple/frozenset）；可变 = 可原地改（list/set/dict/bytearray）；可变对象**一定不可哈希**，不能当字典键。

## 面试官视角
- **考察意图**：能否一眼预判函数副作用，能否解释"list 为什么不能做 key"。
- **P5** 背得出类型清单 / **P6** 能举出"tuple 里装 list 仍不可哈希"的反例 / **P7** 知道 `+=` 作用在 tuple 元素上的诡异表现。
- **红旗**：① 说"tuple 不可变所以绝对安全"；② 把"不可变"等同于"可哈希"；③ 说 frozenset 可变。
- **惊艳点**：`t = ([1],); t[0] += [2]` **抛 TypeError，但里面的 list 已经被改掉**——`+=` 是先原地改再赋值回容器。验证：CPython 直接运行 `[实测]`

## 主问答
**Q：Python 里哪些类型是可变的，哪些是不可变的？**
**A：**
1. **先给结论**：**不可变** = bool / int / float / str / bytes / tuple / frozenset；**可变** = list / set / dict / bytearray。
2. **再给机制**：可变类型提供原地修改方法（`append`/`add`/`__setitem__`），改完 `id()` 不变；不可变类型没有这些方法，"改"只能是**新建对象 + 重绑定名字**。
3. **最后给边界**：不可变 ≠ 无副作用。`([1], 2)` 这种 tuple 只是**自身元素换不掉**，里面装的可变对象照样能改，且它**不可哈希、不能做 dict 键**。
**加分层**：能否做 key 的硬判据是**可哈希（hashable）**，不是可变性；`hash(x)` 不抛异常才可哈希。

## 关键代码
```python
a = [1, 2]; i0 = id(a); a.append(3); print(id(a) == i0)   # True 原地改
s = "ab";   j0 = id(s); s += "c";     print(id(s) == j0)   # False 新对象
print(hash((1, 2)))                                        # 正常
try:
    hash(([1], 2))
except TypeError as e:
    print(e)                                               # unhashable type: 'list'
t = ([1],); t[0].append(2); print(t)                       # ([1, 2],) 嵌套元素照样改
```

- 可变性决定**能否原地改**，可哈希决定**能否做键**，两者相关但不等价。
