# 26. 调用处的 * 与 ** 是解包，不是打包

> 分类：语言基础/函数 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**解包** / **序列拆位置** / **字典拆关键字**
> 原文锚点：第 105~111 段「传一个列表进去，加一个星号…使用两个星，相当于把一个字典打包成关键字参数」

## 一句话总述
同一个星号符号，在**定义处是打包**、在**调用处是解包**：`f(*seq)` 把序列拆成位置实参，`f(**mapping)` 把字典拆成关键字实参。

## 面试官视角
- **考察意图**：能不能分清"同一个符号的两个方向"——这是函数类题目最容易混的点。
- **P5** 会用 `f(*lst)` / **P6** 知道个数不匹配会 TypeError、字典键要能对上形参名 / **P7** 知道 `f(*a, **k)` 是透传标准式。
- **红旗**：① 把定义处的打包和调用处的解包说成同一件事；② 以为 `*` 能解包任意迭代器就不受个数限制；③ 说 `**` 解包修改原字典。
- **惊艳点**：`f(*[1,2], **{"c":3})` 可以**混用**，两者合起来才能"原样转发任意签名"，这是装饰器能通用化的根因。验证：CPython 直接运行 `[实测]`

## 主问答
**Q：`f(*args)` 和 `f(**kwargs)` 写在调用括号里是什么意思？**
**A：**
1. **先给结论**：调用处的 `*` / `**` 是**解包**——分别把可迭代对象拆成位置实参、把字典拆成关键字实参。
2. **再给机制**：`*` 会先把可迭代对象**展开成一个元组**再逐个绑定，因此元素**个数必须与形参匹配**，多了少了都是 TypeError；`**` 要求键是字符串且与形参名对应。
3. **最后给边界**：`**` 解包时若字典含有形参表里**没有的键**，只有存在 `**kwargs` 兜底才不报错；函数内对 kwargs 的修改**不影响**调用方的原字典。
**加分层**：`wrapper(*args, **kwargs)` 是装饰器透传的标准写法，缺一个都会破坏被包装函数的签名兼容性。

## 关键代码
```python
def f(a, b, c):
    return a + b + c
print(f(*[1, 2, 3]))                  # 6
print(f(**{"a": 1, "b": 2, "c": 3}))  # 6
print(f(*[1, 2], **{"c": 3}))         # 6 混用
# f(*[1, 2])                          # TypeError: missing 1 required positional argument
print(f(*[1], *[2, 3]))               # 6 多解包，3.5+ 支持
```

## ⚠️ 原文纠错
原文把"调用处加星号传列表"描述为"打包"，方向说反了：调用处是**解包（unpacking）**，打包发生在**函数定义处**。其余表述与公认事实一致。

## 总结与追问预判
- 定义处打包、调用处解包；个数与键名是两道硬约束。
