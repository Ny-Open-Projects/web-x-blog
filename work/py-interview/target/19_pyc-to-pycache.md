# 19. 字节码缓存统一到 __pycache__

> 分类：版本差异/工程 | 难度：L1 | 题型：八股题 | 频率：低 | 关键词：**__pycache__** / **.pyc** / **字节码缓存**
> 原文锚点：第 105~107 段「Python 3 里面把 pyc 文件都统一放到 __pycache__ 里面」

## 一句话总述
Python 3 把散落在源码目录里的 `.pyc` 统一收进 **`__pycache__` 子目录**，并在文件名中带上**版本与解释器标识**。

## 面试官视角
- **考察意图**：这是一道"有没有注意过工程目录"的观察力题，顺带考多版本共存。
- **P5** 知道有 `__pycache__` / **P6** 知道文件名带版本标识 / **P7** 能说清它对多版本共存与部署的意义。
- **红旗**：① 把 `.pyc` 提交进版本库；② 以为删了它就"清了缓存"却不知道还有 `-B`；③ 不知道它会因源码 mtime 变化而失效。
- **惊艳点**：文件名形如 `mod.cpython-311.pyc`，**版本标识让多个 Python 版本可共用同一份源码目录**——这正是 2/3 混跑时的关键 `[经验]`。

## 主问答
**Q：Python 3 里 __pycache__ 目录是干什么的？**
**A：**
1. **先给结论**：存放模块编译后的**字节码缓存**，导入时若缓存有效则跳过重新编译，加快启动。
2. **再给机制**：缓存文件名含解释器名与版本号（如 `cpython-311`），因此同一目录可被多个 Python 版本共用而互不覆盖 `[经验]`。
3. **最后给边界**：缓存是否失效取决于源文件的 **mtime 与大小**；改动源码会触发重编。它属于**可再生成产物**，必须写进 `.gitignore`。
**加分层**：不想生成缓存可用 `python -B` 或设置 `PYTHONDONTWRITEBYTECODE=1`，容器里追求最小镜像时常用。

## 关键代码
```python
import py_compile, os
py_compile.compile("mod.py")            # 手动生成字节码缓存
print(os.listdir("__pycache__"))        # ['mod.cpython-313.pyc']
```

未发现技术错误。原文「2 里当前目录会生成一堆 pyc 很乱，3 统一到一个文件夹」准确；机翻中的目录名音译已还原为 `__pycache__`。

- 统一目录 + 版本标识 = 多版本共存；产物必须忽略。
