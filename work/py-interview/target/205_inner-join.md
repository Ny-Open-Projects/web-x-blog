# 205. 内连接 INNER JOIN

> 分类：数据库 | 难度：L2 | 题型：概念+手写 | 频率：高 | 关键词：**INNER JOIN** / **交集语义** / **on 条件** / **两表匹配**
> 原文锚点：第8章 8-3「内连接 inner join：两表都能关联起来的行才返回，类似求交集；语法 select 列 from a inner join b on a.id=b.id；用 a(ID,val)/b(ID,val) 表手算+终端验证」

## 一句话总述
**INNER JOIN 只返回两表都满足 ON 条件的匹配行**，语义上类似"两表的交集"；写法是 `SELECT 列 FROM a INNER JOIN b ON a.id = b.id`。

## 面试官视角
- **考察意图**：是否真懂内连接的"匹配才返回"语义，能否手算结果集。
- **P5** 能写出 INNER JOIN 语法并说出"两表都匹配才返回" / **P6** 能用"交集"类比并现场手算小表示例结果 / **P7** 能指出内连接结果行数 ≤ 两表行数、且 ON 与 WHERE 在外连接中的过滤时机差异。
- **红旗**：把内连接说成"返回左表全部"（那是左连接）；或认为 INNER JOIN 一定会去重。
- **惊艳点**：能指出"内连接结果集里 NULL 只可能来自表自身数据，不会因匹配缺失产生 NULL"，与 OUTER JOIN 形成对比 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是内连接（INNER JOIN）？怎么写、结果是什么？

**A · 标准答案骨架：**
1. **定义**：内连接把左表 a 与右表 b 能关联起来的数据连接后返回——**两表都存在匹配行时才返回该行**，类似求两表的交集（比喻不严谨但好理解）。
2. **语法**：`SELECT 列 FROM a INNER JOIN b ON a.id = b.id`（`INNER` 可省略，直接 `JOIN`）。
3. **手算示例**：源文件用 a(ID,val)={(1,'AB'),(2,'AC')}、b(ID,val)={(1,'AD'),(3,'BC')}，公共键只有 ID=1。INNER JOIN 后只保留 ID=1 那一行：结果为 `(AID=1, BID=1, a.val='AB', b.val='AD')`；终端执行验证与手算一致。

**加分层**：内连接在关联阶段就丢弃不匹配的行，所以结果里**不会因"另一表无匹配"而出现 NULL**——这是它和 OUTER JOIN 的本质差别。

## 版本与兼容性

|---|---|---|
| INNER JOIN 语义在各 SQL 引擎一致 | 无版本翻转 | `INNER` 关键字可省略；ON 与 WHERE 在内连接中等价，但在外连接中不等价 |

## 关键代码
```sql
-- 内连接：只返回 a、b 都匹配的行（公共键 ID=1）[实测, MySQL 8]
SELECT a.id AS AID, b.id AS BID, a.val AS aval, b.val AS bval
FROM a INNER JOIN b ON a.id = b.id;
-- 结果：AID=1, BID=1, aval='AB', bval='AD'
```

## ⚠️ 原文纠错
- 机翻还原：「innerjoy / innership」→ **INNER JOIN**；「sename」→ **SELECT**；「ainterjoind」→ **a INNER JOIN ...**；「nuve」→ **NULL**（内连接结果中不会出现，是外连接才填的）。
- 原文"类似求交集"是比喻，需补严谨边界：内连接是**基于 ON 条件的行配对**，结果行数取决于匹配数，不是数学集合去重意义上的"交集"。
- 原文手算示例里把 BID 误写成 DID（笔误），已统一为 BID。

## 总结与追问预判
内连接=两表匹配才返回，是 JOIN 的默认语义。面试官常紧接着问"那左连接/右连接呢"和"全连接怎么写"，可衔接：**外连接 LEFT/RIGHT JOIN（见 206 卡）**。
