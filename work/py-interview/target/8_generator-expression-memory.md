# 8. 生成器推导式：把方括号换成圆括号

> 分类：语言特性/内存 | 难度：L2 | 题型：代码题 | 频率：高 | 关键词：**generator** / **惰性求值** / **省内存**
> 原文锚点：第 93~96 段「只要把这个方括号改成圆括号，它就会返回生成器，从而大大节省内存」

## 一句话总述
列表推导**立即**算出全部元素并占内存，生成器表达式**惰性**逐个产出——只差一对括号，内存量级相差一个数据集大小。

## 面试官视角
- **考察意图**：是否理解"惰性求值"的收益与代价，而不是只会写 `yield`。
- **P5** 知道圆括号变生成器 / **P6** 能说清惰性求值与一次性消费 / **P7** 能指出它并不总是更快。
- **红旗**：① "生成器一定更快"；② 不知道生成器**只能遍历一次**；③ 把生成器当列表反复用。
- **惊艳点**：生成器省的是**内存峰值**（O(n) → O(1)），**不是** CPU 时间；单次遍历的总工作量反而略多 `[经验]`。

## 主问答
**Q：列表推导和生成器表达式该怎么选？**
**A：**
1. **先给结论**：数据量大、只需**遍历一次**（如求和、管道处理）用生成器；需要多次访问、下标取值或要持久化结果时用列表。
2. **再给机制**：生成器表达式 `(x for x in ...)` 返回 generator 对象，只在 `next()` 时计算一个元素，因此内存占用与数据规模无关。
3. **最后给边界**：生成器是**一次性**的，遍历完就耗尽；想重复使用必须 `list()` 固化，而那一步就把省下的内存又花回去了。
**加分层**：大文件逐行处理时，直接 `for line in f` 本身就是惰性迭代，再套 `list()` 是最常见的内存事故来源。

## 关键代码
```python
import sys
lst = [i for i in range(10**6)]
gen = (i for i in range(10**6))
print(sys.getsizeof(lst), sys.getsizeof(gen))   # 生成器体积与数据规模无关
print(next(gen), next(gen))                      # 惰性：要一个算一个
```

## ⚠️ 原文纠错
未发现技术错误。原文「改成圆括号返回生成器从而大大节省内存」准确；补充一点：节省的是内存而非时间，且生成器只能消费一次。机翻中的类型名音译已还原。
