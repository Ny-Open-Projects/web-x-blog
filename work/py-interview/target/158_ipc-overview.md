# 158. 进程间通信（IPC）全景

> 分类：操作系统 | 难度：L2 | 题型：原理题 | 频率：高 | 关键词：**IPC** / **管道** / **信号** / **socket**
> 原文锚点：第 49~63 段「进程间不共享数据，需要通信；六种方式；Control+C 发信号」

## 一句话总述
**IPC（Inter-Process Communication，进程间通信）**解决"进程地址空间隔离、数据不共享"下的信息交换；常见六类：**管道、信号、消息队列、共享内存、信号量、socket**。

## 面试官视角
- **考察意图**：是否知道进程为何不能像线程那样共享内存，以及能列举并区分 IPC 方式。
- **P5** 能说出管道、socket 等几种 / **P6** 能讲清六种各自特点与典型场景（如 socket 走网络、共享内存最快） / **P7** 能对比性能/复杂度，并指出业务里多用 socket（Web 服务）与消息队列（Kafka/RabbitMQ）。
- **红旗**：把 IPC 说成"用全局变量传数据"；或混淆 IPC 与 RPC。
- **惊艳点**：**共享内存**是六种里**最快**的（零拷贝、直接映射），但需配信号量防竞态；**socket** 跨机也能用 —— 验证：同一主机 unix domain socket 比 TCP 回环少一次协议栈拷贝 `[经验]`。

## 主问答
**Q（面试官原话）：** 不同进程之间怎么通信？你都知道哪些方式？

**A · 标准答案骨架：**
1. **先给结论**：进程**地址空间隔离**，不能像线程共享内存，必须靠 IPC；六类：**管道 / 信号 / 消息队列 / 共享内存 / 信号量 / socket**。
2. **再给机制**：**管道**（匿名/有名，父子或本机）；**信号**（如 Ctrl+C 发 `SIGINT` 终止进程）；**消息队列**（系统级或 Kafka/RabbitMQ）；**共享内存**（最快，需配锁）；**socket**（跨网络通用，Web 服务走它）。
3. **最后给边界**：业务代码里最常用的是 **socket（服务间调用）** 与 **消息队列（异步解耦）**；管道/信号多用于本机运维脚本。

**加分层**：IPC 是"本机或跨机传数据"的统称；RPC 是"像调本地函数一样调远程"的**编程模型**，建立在 socket 等传输之上——二者不同层 `[经验]`。

## ⚠️ 原文纠错
原文存在两处概念性错误，须纠正：
1. 第 52 段称"进程间通信经常用 **RPC** 简写"——**错误**。IPC = Inter-Process Communication（进程间通信），RPC = Remote Procedure Call（远程过程调用），二者不同；正确缩写是 **IPC**。
2. 第 55~56 段称 Ctrl+C 发送"**CN**"信号——**错误**。实际发送的是 **SIGINT（中断信号）**，进程默认行为为终止。
另：音译还原——「RMMQ」→ RabbitMQ；「sopping」→ socket；「部应文」→ Web 服务。
