# 18. 编写 2/3 兼容代码的三个工具

> 分类：版本差异/工程 | 难度：L2 | 题型：八股题 | 频率：低 | 关键词：**six** / **2to3** / **__future__** / **迁移**
> 原文锚点：第 110~116 段「six 模块提供语法兼容工具…2to3 工具批量转换…from __future__ import print_function」

## 一句话总述
三件套分工明确：**`__future__` 让 2 提前用 3 的特性**、**`six` 提供兼容层**、**`2to3` 做一次性批量改写**。

## 面试官视角
- **考察意图**：有没有真的做过迁移——没做过的人只会说"用 2to3 转一下"。
- **P5** 知道 `2to3` / **P6** 能说清三者的分工 / **P7** 能指出自动转换的局限与验证手段。
- **红旗**：① 以为 `2to3` 转完就能跑；② 把 `six` 当转码工具；③ 不知道 `__future__` 只对单文件生效且必须在开头。
- **惊艳点**：**`2to3` 只改语法不改语义**——除法、字典视图这类语义变化它不会替你判断，必须靠单测兜底 `[经验]`。

## 主问答
**Q：怎么让一份代码同时兼容 Python 2 和 3？**
**A：**
1. **先给结论**：`__future__` 导入 3 的行为、`six` 抹平库与类型差异、`2to3` 做批量语法改写，三者是**并存而非替代**关系。
2. **再给机制**：`from __future__ import print_function` 让 2 里的 `print` 变成函数；`six` 提供 `six.moves`、字符串类型常量等兼容封装；`2to3` 扫描源码做机械改写 `[经验]`。
3. **最后给边界**：`__future__` 导入必须位于文件**最开头**；`2to3` 无法处理语义差异（整除、字典视图返回值），转完必须跑测试。
**加分层**：现在新项目不应再做 2/3 双兼容——Python 2 已于 2020 年停止维护，这套知识的价值主要在**维护老系统**。
