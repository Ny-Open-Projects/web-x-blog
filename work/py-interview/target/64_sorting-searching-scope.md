# 64. 面试常考的排序与查找题有哪些

> 分类：算法与数据结构/面试范围 | 难度：L1 | 题型：八股题 | 频率：高 | 关键词：**快排** / **归并** / **二分** / **复杂度**
> 原文锚点：第 2~8 段「关于这个算法，它有哪些比较常考的一些问题…总的来说就是排序跟查找重中之重」

## 一句话总述
算法面试以**排序 + 查找**为主战场：排序常考冒泡、快排、归并、堆排；查找考线性与二分；**硬指标**是能**徒手写出代码**并**分析时间与空间复杂度**。

## 面试官视角
- **考察意图**：这一步是筛"背过"还是"能写"。
- **P5** 能说清各算法思路 / **P6** 能对复杂度对答如流 / **P7** 能在白板/纸上手撕快排与归并，并讲清稳定/原地等性质。
- **红旗**：① 只能描述不能写；② 复杂度靠猜；③ 说不清快排最坏 O(n²) 的触发条件。
- **惊艳点**：主动给出**性质矩阵**（是否稳定、是否原地、最坏复杂度），比单纯报数字更显体系。验证：现场手写 + 逐行讲复杂度（`[实测]` 建议自己计时十万级数据，感受 O(n log n) 与 O(n²) 的差距）。

## 主问答
**Q：算法面试一般考什么？怎么准备？**
**A：**
1. **先给范围**：核心是**排序**与**查找**。排序常考冒泡、快速、归并、堆排序；查找分线性查找与二分查找。
2. **再给要求**：不止会讲思路，要能**独立实现代码**，并能分析**时间与空间复杂度**；快排、归并建议练到**不看资料手写**。
3. **最后给方法**：很多公司是**白板/纸面**手写，务必脱离 IDE 与补全；练的时候同时记忆稳定性与最坏情况，避免只背平均复杂度。
**加分层**：答完主动说"我可以现场写一下快排"，把被动回答转成主动展示，是最省力的加分动作。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 常考哪些算法 | 范围 | 排序 + 查找 | 换题 → 不及格 |
| L2 | 手写快排 | 编码 | 分区 + 递归 | 判 P5 |
| L3 | 复杂度多少 | 分析 | 平均 O(n log n) | 判 P6 |
| L4 | 最坏什么情况 | 边界 | 有序输入退化为 O(n²) | 判 P6+ |
| L5 | 稳定吗 | 性质 | 快排不稳定、归并稳定 | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 通用（与语言无关） | 算法性质由定义决定 | 复杂度与稳定性按教材结论答 |
| Python 实践 | 内置 sort 用 Timsort | 工程排序优先用 `sorted`，手撕用于考察 |

## 关键代码
```python
def quicksort(xs: list) -> list:
    if len(xs) <= 1:
        return xs
    pivot, *rest = xs
    lo = [x for x in rest if x < pivot]
    hi = [x for x in rest if x >= pivot]
    return quicksort(lo) + [pivot] + quicksort(hi)

def binary_search(xs: list, target: int) -> int:
    lo, hi = 0, len(xs) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if xs[mid] < target: lo = mid + 1
        elif xs[mid] > target: hi = mid - 1
        else: return mid
    return -1

print(quicksort([3, 1, 4, 1, 5]), binary_search([1, 3, 5], 3))
```

## ⚠️ 原文纠错
原文对考试范围与能力要求的描述准确；需补充一点：上述简洁版快排需要 O(n) 额外空间，并非**原地分区**版本，面试时应说明自己写的是哪种。转写中的算法名音译已统一还原为快排 / 归并 / 二分查找。未发现原理性错误。
