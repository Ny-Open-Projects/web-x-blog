# 131. 享元模式：共享不可变的内在状态，减少重复对象

> 分类：编程范式/设计模式 | 难度：L3 | 题型：工程题 | 频率：中 | 关键词：**享元模式** / **内在状态** / **共享** / **对象池区别**
> 原文锚点：第 10~11 段「享元模式通过对象池的复用技术改善资源利用；数据库链接预先创建很多连接从池中取」

## 一句话总述
**享元模式**通过**共享**大量细粒度对象的**内在状态（intrinsic，不可变、可复用）**，把外在状态（extrinsic，随场景变化）由调用方传入，从而大幅减少重复对象的内存占用。

## 面试官视角
- **考察意图**：专考你能否把**享元**和**对象池**讲清——两者都"复用"，但语义相反。
- **P5** 能说出"共享对象减少内存" / **P6** 能区分**内在状态（共享、不可变）**与**外在状态（外部传入）**，并指出与对象池的差异 / **P7** 能举真实例子（如字符 glyph 缓存、整数小对象缓存）并说清享元要求状态**不可变** `[经验]`。
- **红旗**：① 把享元说成"池里借了要还"（那是对象池，享元**不归还、被多方同时共享**）；② 让共享状态可变导致串数据；③ 在外在状态频繁变化时硬用享元。
- **惊艳点**：享元对象**同一时刻被多方并发读**（只读），对象池对象**同一时刻只被一个占用（互斥）**。验证：享元工厂返回同一 id，池 `acquire` 后计数减一 `[实测]`（见 125）。

## 主问答
**Q：享元模式和对象池到底差在哪？**
**A：**
1. **结论**：享元**共享不可变的内在状态**，对象被**多方同时只读**使用，无需归还；对象池是**预建+借还**，同一时刻只给一个使用者。
2. **机制**：享元把"会变的部分"抽成**外在状态**由调用方传入，把"不变的部分"做成**工厂共享**的单例式对象；对象池则是 `acquire/release` 契约下的互斥复用。
3. **边界**：享元**只适用内在状态不可变**的场景；若状态要改，强行共享会串数据——那就该用对象池而非享元。
**加分层**：源里说的"连接池"严格说是对象池（125），不是享元；享元的典型是字体字形缓存、Python 的小整数缓存。

## 关键代码
```python
class Flyweight:
    _pool = {}                       # 共享不可变内在状态
    def __init__(self, intrinsic): self._k = intrinsic   # 不可变
    @classmethod
    def get(cls, k):
        return cls._pool.setdefault(k, cls(k))   # 同一 k 返回同一对象

a = Flyweight.get("red"); b = Flyweight.get("red")
print(a is b)                        # True —— 多方共享，不归还
```

原文"享元模式通过对象池的复用技术来改善资源利用，数据库链接会预先创建很多连接每次从池子取一个"——这里原文**把享元和对象池混用了**：连接池严格是**对象池**（互斥借还），不是享元（共享不可变）。卡面已在机制与加分层中明确区分，并指回对象池卡 425。机翻无额外音译词。原文用"对象池"举例在享元语境下不够严谨，予以纠正说明。
