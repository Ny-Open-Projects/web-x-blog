# 77. 只给你待删节点，怎么把它从链表里删掉

> 分类：算法与数据结构/链表 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**复制后继** / **无头节点** / **覆盖值**
> 原文锚点：第 25~50 段「它只给了我们一个要删除的节点，它并没有给我们这个头节点」

## 一句话总述
拿不到头节点就**无法找到前驱**，于是换个思路：**把后继节点的值复制过来，再跳过后继**——等价于"用后继顶替自己"，只需 **O(1)**。

## 面试官视角
- **考察意图**：考察**换角度建模**——约束（没有头节点）逼你放弃常规删除路径。
- **P5** 会想到"找前驱改指针" / **P6** 发现走不通后能给出复制后继法 / **P7** 能指出该解法的**不适用边界**。
- **红旗**：① 坚持找前驱（题目明确不给头节点）；② 只改值不改指针（链表长度没变）；③ 没意识到"删的不是这个对象"。
- **惊艳点**：这题的本质是——**删除节点对象的唯一方式是让前驱绕过它**；没前驱时就只能"借尸还魂"。验证：删除后链表长度减一但对象 id 仍在 `[实测]`。

## 主问答
**Q：单链表中只给出待删除节点（保证不是尾节点），如何删除它？**
**A：**
1. **先给难点**：常规删除需要**前驱节点**把 `next` 跨过待删节点；但函数只传入待删节点本身，**无法向前遍历**，所以常规路走不通。
2. **再给解法**：把**后继节点的值复制**到当前节点（`node.value = node.next.value`），再把 `node.next` 指向**后继的后继**（`node.next = node.next.next`）。效果上等价删除，且 **O(1)**。
3. **最后给边界**：题目保证**不是尾节点**——否则 `node.next` 为 None 无从复制；该方法**并未真正销毁该节点对象**，只是用后继值覆盖并跳过后继。
**加分层**：正因为"没有真正销毁对象"，若外部仍持有该节点引用、或节点值带有副作用/深比较语义，此解法会出问题；生产代码里正常删除仍应走"找前驱"。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 常规怎么删 | 机制 | 前驱跨过它 | 换题 → 不及格 |

## 关键代码
```python
class ListNode:
    def __init__(self, value, nxt=None): self.value, self.next = value, nxt

def delete_node(node):        # 题目保证 node 不是尾节点且合法
    node.value = node.next.value      # 1) 后继值覆盖自己
    node.next = node.next.next        # 2) 跳过后继

head = ListNode(4, ListNode(5, ListNode(1, ListNode(9))))
delete_node(head.next)                # 删除值为 5 的节点
out, cur = [], head
while cur: out.append(cur.value); cur = cur.next
print(out)                            # [4, 1, 9]
```

## ⚠️ 原文纠错
原文"用后继替换自己、再跳过后继"的思路与最终输出 `[4, 1, 9]` 均正确；需补正：原文口语中"把下一个节点值赋值成 node 的值"表述方向颠倒，正确为 **`node.value = node.next.value`**（后继值覆盖自身），卡面已更正。另原文未说明该解法**并未真正销毁节点对象**这一边界，已补齐。转写中的音译词已还原为标准术语。

## 总结与追问预判
- 没前驱就借后继：覆盖值 + 跳过后继；前提是"非尾节点"。
