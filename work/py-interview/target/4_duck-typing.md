# 4. 鸭子类型与 file-like object

> 分类：语言特性 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**duck typing** / **关注行为** / **file-like object**
> 原文锚点：第 24~36 段「当你看到一只鸟走起来像鸭子…更关注对象的行为，而不是它的类型」

## 一句话总述
鸭子类型 = **只看对象"能做什么"，不看它"是什么类"**；只要实现了 `read`/`write`，文件对象和内存缓冲区都能当"类文件对象"用。

## 面试官视角
- **考察意图**：是否理解动态语言的多态是靠**协议**而非继承实现。
- **P5** 能背出那句俗语 / **P6** 能举出 file-like / 迭代器协议实例 / **P7** 能指出它的风险与补救（EAFP、抽象基类、Protocol）。
- **红旗**：① 说"鸭子类型就是不检查类型"；② 举不出具体协议；③ 不知道运行期会怎么崩。
- **惊艳点**：**鸭子类型的代价是错误被推迟到运行期**——用 `hasattr` 或 `try/except AttributeError` 主动兜底才是稳的写法 `[经验]`。

## 主问答
**Q：什么是鸭子类型？举个你用过的例子。**
**A：**
1. **先给结论**：判断依据是**对象的行为（方法/接口）**，而不是它的类或继承关系。
2. **再给机制**：`io.StringIO`、真实文件对象、`socket.makefile` 都实现了 `read`/`write`，因此都能传给期望"类文件对象"的函数——这就是鸭子类型带来的解耦 `[经验]`。
3. **最后给边界**：它**不等于完全不检查类型**，需要时仍可用 `type()`、`isinstance()` 或自省判断；代价是类型错误只在运行到那一行才暴露。
**加分层**：`for x in obj` 也是鸭子类型——只要实现了迭代协议就能迭代，与具体类无关。

## 关键代码
```python
# 鸭子类型：不关心传入的是什么类，只要有 read 就能用
def head(obj, n=8):
    return obj.read(n)          # 文件、StringIO、BytesIO 都能传

import io
print(head(io.StringIO("hello duck typing")))   # hello du
```
