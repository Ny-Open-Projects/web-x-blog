# 127. 代理模式实战：deque 实现栈队列 + 保护代理加校验

> 分类：编程范式/设计模式 | 难度：L3 | 题型：代码题 | 频率：中 | 关键词：**deque** / **保护代理** / **校验间接层** / **委托**
> 原文锚点：第 19~22 段「栈的成员是 deck，push 代理到 deck 的 append 方法；代理层可做校验」

## 一句话总述
**栈和队列用 `deque` 实现就是代理模式**：把 `push/pop` 等接口**委托**给内部 `deque` 成员；而**保护代理**则在委托前插入**校验/鉴权**间接层，是代理最常被考到的变体。

## 面试官视角
- **考察意图**：考你能否**动手写出**一个代理（不止背定义），并讲清保护代理解决了什么。
- **P5** 能写出"成员是 deque、方法委托" / **P6** 能补出**保护代理**：在代理层加权限判断，拒绝非法调用 / **P7** 能说明代理链过深会导致**调试困难**、并指出用 `__getattr__` 做通用委托的隐患 `[经验]`。
- **红旗**：① 用 `list` 当栈却说成代理（list 本身就是实现，无委托关系）；② 保护代理只写"加校验"却给不出判断逻辑；③ 混淆 `deque.append`（右端）与 `appendleft`。
- **惊艳点**：`deque` 两端 O(1)，而 `list.pop(0)` 是 O(n)——用 list 当队列会退化。验证：`timeit` 对比 `deque.popleft` 与 `list.pop(0)` `[实测]`。

## 主问答
**Q：你刚说栈是代理模式，写一下？再加上一个"带权限的"版本。**
**A：**
1. **结论**：栈持有 `deque`，`push/pop` **委托**给 `deque.append/pop`，队列同理用 `append/popleft`，这就是功能代理。
2. **机制**：保护代理在委托前加**校验**——例如只有白名单调用方才能执行敏感操作，代理层拦截。
3. **边界**：代理层越厚，调用链越深；过度包装会让**栈帧与日志难以定位**，只在确实需要控制访问时才加。
**加分层**：动态代理可用 `__getattr__` 把未定义属性自动转发给被代理对象，但会**掩盖拼写错误**，需谨慎。

## 关键代码
```python
from collections import deque

class ProtectedStack:           # 功能代理 + 保护代理
    def __init__(self, allow=True):
        self._d = deque(); self._allow = allow
    def push(self, x):
        if not self._allow: raise PermissionError("无权限")  # 校验间接层
        self._d.append(x)
    def pop(self):
        if not self._allow: raise PermissionError("无权限")
        return self._d.pop()
```

## ⚠️ 原文纠错
原文"栈有一个成员是 deck，push 代理到 deck 的 append、pop 代理到 deck 的 pop"——描述准确（即 deque），机翻 `deck/deick` 已还原为 **deque**。原文还点出"代理模式也常用来实现安全相关的东西，在代理层做校验"，卡面据此给出 `ProtectedStack`。原文未给队列用 `popleft` 的明确说法，属常识补充，已在代码与版本节标注。无事实错误。
