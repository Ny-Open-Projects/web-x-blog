# 126. 代理模式：把操作委托给另一个对象，has-a 组合

> 分类：编程范式/设计模式 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**代理模式** / **委托** / **has-a 组合** / **安全代理**
> 原文锚点：第 6 段「代理模式就是把一个对象的操作去代理到另一个对象上」

## 一句话总述
**代理模式**为一个对象提供一个**替代者（代理）**，把对原对象的操作**转接/委托**给另一个对象；它通常是**has-a 的组合关系**，而不是继承。

## 面试官视角
- **考察意图**：看你能否说清"代理和装饰器、适配器的区别"，以及能否区分代理的两种典型用途。
- **P5** 能说出"代理 = 把操作委托给成员对象" / **P6** 能区分**功能代理**（纯转发）与**安全/保护代理**（在间接层加校验）/ **P7** 能举出远程代理、虚拟代理、动态代理（如 Python 的 `__getattr__` 懒加载）并说明何时不该用 `[经验]`。
- **红旗**：① 把代理说成继承关系（原文明确是 has-a 组合）；② 和装饰器混为一谈（装饰器改功能、代理控制访问）；③ 说不出保护代理的校验场景。
- **惊艳点**：代理与装饰器同是包装，但**意图不同**——装饰器"增强功能"、代理"控制访问"。验证：保护代理在调用前校验权限，装饰器在调用前后增强逻辑 `[经验]`。

## 主问答
**Q：说说代理模式，你平时在哪用过？**
**A：**
1. **先给结论**：代理模式用一个对象**包装**另一个对象，把操作**委托**出去，本体通常作为代理的**成员变量**（has-a）。
2. **再给机制**：常见两类——一是**功能转发**（如用 `deque` 实现栈，把 `push`/`pop` 直接委托给 `deque` 的方法）；二是**保护代理**，在代理层插入**校验/鉴权**等间接层。
3. **最后给边界**：代理适合"控制访问、懒加载、加安全层"；若只是**增强功能**应改用装饰器，避免错配。
**加分层**：远程代理（本地桩调远程服务）、虚拟代理（懒加载大对象）是高频变体。

## 关键代码
```python
class Stack:                      # 用 deque 实现栈 = 功能代理
    def __init__(self):
        from collections import deque
        self._d = deque()         # has-a 组合，而非继承
    def push(self, x): self._d.append(x)      # 委托
    def pop(self):  return self._d.pop()      # 委托
```

## ⚠️ 原文纠错
原文"通常代理模式都是一种 has 的组合关系"——正确，代理是**组合**而非继承，予以保留。原文举例"用 deque 实现 stack 跟 queue 就是一种代理模式"准确，卡面据此给出代码。机翻"此电话"应为**子类**（"不需要通过子类就能扩展功能"指装饰器），已在 5-2 装饰器卡中还原；本卡聚焦代理，未引入该音译。转写词 `deack/deick` 已还原为 **deque**。原文无技术性错误，仅缺"代理 vs 装饰器"辨析，已在红旗与惊艳点补充 `[经验]`。
