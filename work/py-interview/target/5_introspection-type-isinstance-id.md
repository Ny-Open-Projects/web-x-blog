# 5. 自省：type、isinstance 与 id

> 分类：语言特性 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**introspection** / **type** / **isinstance** / **id**
> 原文锚点：第 56~76 段「Python 提供 type、isinstance 这些函数来获取对象的类型信息」

## 一句话总述
动态语言没有编译期类型，靠**运行期自省**补上：`type` 拿类型、`isinstance` 判归属、`id` 看身份、`inspect` 取更深的元信息。

## 面试官视角
- **考察意图**：知不知道在"没有类型声明"的前提下怎么安全地写分支逻辑。
- **P5** 会用 `type` / **P6** 知道 `isinstance` 会**考虑继承**而 `type` 不会 / **P7** 能指出 `id` 在 CPython 的实现含义。
- **红旗**：① 用 `type(x) == int` 判断类型；② 说 `id` 返回"内存地址"却讲不清它是实现细节；③ 不知道 `inspect` 模块。
- **惊艳点**：**`type` 不做继承判断，`isinstance` 做**——子类实例上两者结论会分叉 `[源码]`（CPython `Objects/typeobject.c` 的 `type_is_subtype`）。

## 主问答
**Q：动态语言没有类型声明，运行时怎么判断一个变量是什么？**
**A：**
1. **先给结论**：四个层次——`type` 返回**精确类型**、`isinstance` 判断**是否为某类（含子类）**、`id` 返回对象**身份**、`inspect` 取签名/源码等深层信息。
2. **再给机制**：`isinstance` 沿继承链查找，因此子类实例也会被判定为父类；`type` 只比对最精确的那个类型对象，两者在多态场景下不可互换 `[经验]`。
3. **最后给边界**：`id` 返回的是 CPython 中对象的**身份标识**（实现上取地址），属于实现细节，别拿它做跨实现的逻辑判断 `[源码]`。
**加分层**：业务里更推荐"EAFP + 协议检测"而不是满屏 `isinstance` 分支，后者往往是设计该抽象的 signal。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| Python 3.x 全系 | 3.10 起 `isinstance` 支持 `X | Y` 联合类型写法 | 判多类型时答 `isinstance(x, (A, B))`，3.10+ 也可写 `A | B` |

## 关键代码
```python
class A: pass
class B(A): pass

print(type(B()) is A)        # False —— 不看继承
print(isinstance(B(), A))    # True  —— 沿继承链判断
```
