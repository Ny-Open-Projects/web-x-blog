# 202. 聚集索引与非聚集索引（回表原理）

> 分类：数据库 | 难度：L4 | 题型：原理 | 频率：高 | 关键词：**聚集索引** / **非聚集索引** / **回表** / **InnoDB** / **MyISAM** / **主键索引**
> 原文锚点：第8章 8-2「聚集 vs 非聚集：B+树叶子节点存数据记录还是存指针；MyISAM 非聚集（.MYD/.MYI 两文件），InnoDB 主键索引=聚集（叶存整行），辅助索引叶存主键值→回表」

## 一句话总述
**聚集 vs 非聚集的唯一区别：B+树的叶子节点存的是"数据记录"还是"指向数据的指针"**；InnoDB 主键索引=聚集（叶存整行），MyISAM 全是非聚集（索引、数据两文件分离）。

## 面试官视角
- **考察意图**：是否理解存储本质，而非只记"InnoDB 是聚集、MyISAM 是非聚集"的结论。
- **P5** 能区分"InnoDB 主键索引是聚集索引，MyISAM 是非聚集" / **P6** 能讲清本质区别是"叶子节点存数据还是存指针"，并说明 MyISAM 两个文件（.MYD 数据 / .MYI 索引） / **P7** 能推导出"InnoDB 辅助索引叶存主键值，查非主键需回表"，并解释为何辅助索引比主键索引慢。
- **红旗**：说"MyISAM 没有主键索引"（错，它有，只是非聚集）；把"回表"说成"再查一次磁盘必然慢"（实际可能 Buffer Pool 命中）。
- **惊艳点**：能结合"为什么推荐自增主键"——聚集索引按主键有序，自增写入追加在末尾、页分裂少；UUID 主键导致随机插入、页分裂频繁 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是聚集索引？什么是非聚集索引？它们有什么区别？

**A · 标准答案骨架：**
1. **看 B+树叶子节点存什么**：存**数据记录本身**=聚集索引；存**指向数据的指针**=非聚集索引。一句话："数据和索引是不是在同一处"。
2. **MyISAM（非聚集）**：索引文件 `.MYI` 与数据文件 `.MYD` 分离，叶子节点存的是数据行在 `.MYD` 中的**指针地址**（两个文件存索引与数据）。
3. **InnoDB（聚集）**：数据文件本身就是按主键组织的 B+树（`.ibd`），**主键索引的叶子节点直接存整行数据**；因此 InnoDB 表只有一个聚集索引（即主键）。
4. **InnoDB 辅助索引为什么要回表**：InnoDB 的**辅助索引（二级索引）**叶子节点存的**不是整行，而是主键值**；用辅助索引查到主键后，必须**再拿主键去聚集索引里查一次整行**——这多走的一步就叫**回表（bookmark lookup）**。所以"用主键查"比"用辅助索引查"少一次 B+树查找，天然更快；若查询字段恰好都在辅助索引里（覆盖索引），则可避免回表。

**加分层**：聚集索引意味着**数据按主键物理有序**，范围查询极快；但主键若无序（如 UUID）会造成大量页分裂与碎片。覆盖索引（`Using index`）能跳过回表，是高频优化手段。

## 关键代码
```sql
-- InnoDB 表：主键索引即聚集索引（叶存整行）[实测, MySQL 8]
CREATE TABLE u_innodb (
  id INT PRIMARY KEY,        -- 聚集索引
  name VARCHAR(50),
  KEY idx_name (name)        -- 辅助索引，叶存 id（需回表）
) ENGINE=InnoDB;

-- MyISAM 表：索引、数据两个文件，均非聚集
CREATE TABLE u_myisam (
  id INT PRIMARY KEY,
  name VARCHAR(50),
  KEY idx_name (name)
) ENGINE=MyISAM;   -- 生成 .MYD(数据) + .MYI(索引) 两文件
```

## ⚠️ 原文纠错
- 机翻还原：「具体索引 / 聚错索引」→ **聚集索引**；「蚂蚁SM / ISM / MSM」→ **MyISAM**；「英诺DB / inlDB / interDB / 英LDBB / NDB」→ **InnoDB**；「b加数 / b加树」→ **B+树**。
- 原文"非聚集索引的叶结点存的是指针，指向真正的数据表文件"——对 MyISAM 描述准确；但需补充：InnoDB 辅助索引的"指针"是**主键值**而非文件地址，二者机制不同。
- 原文称"MyISAM 用两个表存储"，应为"两个文件（.MYD/.MYI）"，已修正表述。

## 总结与追问预判
记忆锚点：**"聚集=叶存数据，非聚集=叶存指针"**。顺着这条线能自然推出 InnoDB 辅助索引回表、为何主键查询更快、为何自增主键更优。面试官常追问"什么叫回表、怎么避免"，答案就是"辅助索引存主键→覆盖索引免回表"。顺势会问：**创建索引最佳实践（见 200 卡）**、**索引失效（见 201 卡）**。
