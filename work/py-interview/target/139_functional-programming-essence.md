# 139. 函数式编程：运算即函数，追求无副作用与引用透明

> 分类：编程范式/编程范式 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**函数式编程** / **引用透明** / **无副作用** / **多范式**
> 原文锚点：第 2~7 段「Python 支持多种范式；函数式把运算视作数学函数；重要特性是无副作用、相同参数得同样结果」

## 一句话总述
**函数式编程**把计算看作**数学函数的求值**，强调**无副作用**与**引用透明**（相同输入永远得到相同输出），Python 是多范式语言，可在面向对象之外选用函数式风格。

## 面试官视角
- **考察意图**：考你是否真懂"无副作用/引用透明"的含义，而不只是"会用 map/filter"。
- **P5** 能说出"函数式把运算当函数、少用可变状态" / **P6** 能讲清**引用透明**（同样输入同样输出、不依赖也不修改外部状态）并对比命令式 / **P7** 能指出 Python 是"多范式"而非纯函数式，且**业务代码里过度函数式反而难维护**，以及纯函数便于并发 `[经验]`。
- **红旗**：① 把"函数式"等同"用了 lambda"；② 说函数式"快"（无前提）；③ 在函数里偷偷改了全局/可变参数还自称无副作用。
- **惊艳点**：引用透明 → 结果可**缓存/记忆化**且天然**线程安全**（不改共享状态）。验证：`lru_cache` 正是利用纯函数特性做缓存 `[实测]`（见 144）。

## 主问答
**Q：什么是函数式编程？Python 适合吗？**
**A：**
1. **结论**：函数式编程把程序看成**函数求值**，核心是**无副作用**与**引用透明**；Python 同时支持过程式、面向对象与函数式，可混用。
2. **机制**：纯函数不读/不改外部状态，同样输入必得同样输出；由此带来可缓存、可并行、易测试的好处；其理论基础是 lambda 演算。
3. **边界**：Python **不是纯函数式语言**——允许可变状态；业务代码里过度使用函数式风格（嵌套 map/filter）反而可读性差，常推荐列表推导替代。
**加分层**：引用透明是记忆化（`lru_cache`）与并行安全的根基，这是函数式最实在的工程价值。

## ⚠️ 原文纠错
原文"函数编程把运算视作数学上的函数计算，重要概念是 lambda 演算；重要特性是没有副作用，相同参数调用产生同样的结果"——准确，并予以保留（机翻"兰姆达演算"=**lambda 演算**，"日据"等杂音词已按语义还原为"同样"，"过程式"=**过程式编程**）。原文"业务代码里函数式用得不多"——符合工程实际，卡面在 P7 与加分层补充"过度函数式可读性差、推荐列表推导"的判断 `[经验]`。原文未提"引用透明"术语，已在机制节明确。无事实错误，仅部分机翻音译需还原。
