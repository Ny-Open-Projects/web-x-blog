# 13. super() 简化与星号解包

> 分类：版本差异 | 难度：L2 | 题型：代码题 | 频率：中 | 关键词：**super()** / **\*rest** / **PEP 3132** / **丢弃元素**
> 原文锚点：第 50~64 段「Python 3 里我们是用 super 加括号来方便调用父类函数…*c 解包剩下所有元素」

## 一句话总述
Python 3 的两个语法糖：`super()` 不再需要写类名和 `self`；`a, b, *rest = ...` 可把**剩余元素**整体收走，也能用 `*_` 直接丢弃。

## 面试官视角
- **考察意图**：是否真的用 Python 3 写过代码——这两处几乎只在 3 里出现。
- **P5** 会写无参 `super()` / **P6** 会用 `*rest` 收尾 / **P7** 能说清 `rest` 的类型与空列表边界。
- **红旗**：① 还在写 `super(Parent, self)`；② 以为 `*rest` 只在函数参数里能用；③ 不知道 `rest` 恒为 list。
- **惊艳点**：**`a, b, *rest = [1]` 会直接 ValueError**，而 `a, b, *_ = [1]` 同样报错——星号解包**不会**让必需变量变可选 `[经验]`。

## 主问答
**Q：Python 3 里 super 和解包相比 2 有哪些改进？**
**A：**
1. **先给结论**：`super()` 无需参数（编译器自动补全当前类与实例）；解包支持 `a, b, *rest = seq` 把剩余元素收进 list。
2. **再给机制**：无参 `super()` 依赖 `__class__` cell，由编译器注入，因此改名类时不必同步改多处；星号解包来自 PEP 3132，用于替代"切片取头部 + 手动切尾部"的笨写法 `[经验]`。
3. **最后给边界**：`*rest` 收集结果**恒为列表**（即使为空或原对象是元组），且只解决了"尾部收集"，**不能**让左侧必需变量少一个。
**加分层**：写 `a, b, *_ = seq` 是表达"我只要前两个"最清晰的方式，比 `seq[0], seq[1]` 更不容易写错下标。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 3.0 起（PEP 3132） | Python 2 无此解包语法，super 必须带参 | 按 3.x 答；维护 2 代码时用 `super(C, self)` 与切片 |

## 关键代码
```python
a, b, *rest = range(5)      # a=0, b=1, rest=[2,3,4]
first, *_ = range(100)      # 只要第一个，其余丢弃
print(type(rest))           # <class 'list'> 即使原对象是 tuple 也是 list
```
