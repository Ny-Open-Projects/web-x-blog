# 123. 模块即单例：Python 里最省事的单例实现

> 分类：编程范式/设计模式 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**模块单例** / **sys.modules** / **import 缓存** / **全局状态**
> 原文锚点：第 50~52 段「Python 模块本身就是单例，import 多次其实只 import 一次」

## 一句话总述
Python 的**模块天然是单例**：首次 import 后模块对象缓存在 `sys.modules`，**再次 import 只是取缓存**，不会重新执行模块体；因此模块里的**全局变量**就是天然的单例对象。

## 面试官视角
- **考察意图**：看你是不是"用 Python 的方式做 Python"，而不是照搬 Java 的私有构造 + 静态 getInstance。
- **P5** 知道模块只导入一次 / **P6** 能说出 `sys.modules` 缓存机制与 `importlib.reload` 的例外 / **P7** 能指出模块单例的**真实风险**（全局可变状态、测试互相污染）并给出依赖注入替代 `[经验]`。
- **红旗**：① 为了"单例"硬写 `__new__` 却不知模块就够；② 把可变全局状态（连接池、配置 dict）当常量用，测试间串数据；③ 以为改了模块变量后 `import` 会拿到新值（缓存里仍是旧对象）。
- **惊艳点**：单例的取舍标准——**无状态/只读用模块，有状态且需控制生命周期用显式对象 + 依赖注入**。验证：两处 `import config` 后 `config is sys.modules['config']` 为 True `[实测]`。

## 主问答
**Q：为什么说 Python 的模块本身就是单例？**
**A：**
1. **机制**：`import` 时 Python 先查 `sys.modules`；**已存在则直接返回缓存的模块对象**，模块体（含全局变量初始化）**只执行一次**。
2. **结论**：模块内的全局变量（配置对象、连接池、注册表）因此**全局唯一**，等价于单例。
3. **例外**：`importlib.reload(mod)` 会**重新执行**模块体，会造出新的对象、打破单例；仅开发调试用，生产禁用。
**加分层**：模块单例的**代价**是隐式全局状态——单元测试之间会互相污染、初始化顺序难以控制；更好的做法是模块里只放**工厂/获取函数**，由调用方显式注入依赖。

## 关键代码
```python
# config.py
_value = {'env': 'prod'}          # 模块级变量：全局唯一

import sys, config
print(config is sys.modules['config'])      # True —— 取的是缓存
config._value['env'] = 'test'
import config as c2
print(c2._value)                            # {'env': 'test'} —— 同一份
# importlib.reload(config)                  # 会重建，打破单例
```
