# 144. 实战：用闭包实现缓存装饰器（斐波那契记忆化）

> 分类：编程范式/函数式 | 难度：L3 | 题型：代码题 | 频率：中 | 关键词：**闭包** / **缓存装饰器** / **记忆化** / **斐波那契**
> 原文锚点：第 35~46 段「用 catch 外层函数 + 内层函数捕获外部 store 变量，实现斐波那契的缓存记忆化」

## 一句话总述
源里的经典例子：写一个 `cache` **装饰器**——外层持有 `store` 字典，内层函数引用它来**缓存**已算过的斐波那契结果，从而避免指数级重复计算，这正是**闭包**的典型实战。

## 面试官视角
- **考察意图**：考你能否**动手写出**一个基于闭包的缓存装饰器，并理解它为什么能"记住"结果。
- **P5** 能写出外层 + 内层、内层读/写 `store` / **P6** 能讲清 `store` 是**自由变量**、被闭包捕获所以跨调用存活，并指出这是**记忆化（memoization）** / **P7** 能指出手写版不如标准库 `functools.lru_cache`，以及 `store` 无限增长无淘汰、`functools` 加 `maxsize` 更稳 `[经验]`。
- **红旗**：① 把 `store` 定义在内层（那就不是闭包、无法跨调用共享）；② 缓存键没覆盖多参数（只按位置）；③ 不知道 `lru_cache` 已是现成方案还手写。
- **惊艳点**：手写的"闭包缓存"本质就是 `lru_cache` 的简化版——`store` 对应缓存表、`inner` 对应包装函数。验证：缓存后斐波那契从指数降到线性 `[实测]`。

## 主问答
**Q：用闭包写一个缓存装饰器，给斐波那契加速？**
**A：**
1. **结论**：外层函数定义 `store` 字典，内层函数先查 `store`、命中直接返回，否则计算并写入——`store` 因被内层引用而成**自由变量**，跨调用保留。
2. **机制**：这就是**记忆化**：已算的 `n` 不再重算，斐波那契从 O(2ⁿ) 降到 O(n)；每次调用外层都会新建独立 `store`。
3. **边界**：手写 `store` **无上限、无淘汰**，长期运行会涨内存；生产请直接用 `functools.lru_cache(maxsize=...)`。
**加分层**：多参数函数要当心缓存键——手写需把参数序列化成 key，`lru_cache` 已自动处理。

## 关键代码
```python
def cache(func):
    store = {}                       # 自由变量：被闭包捕获
    def wrapper(n):
        if n not in store:
            store[n] = func(n)       # 记忆化
        return store[n]
    return wrapper

@cache
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)
```
