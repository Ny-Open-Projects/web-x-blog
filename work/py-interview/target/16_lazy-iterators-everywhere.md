# 16. Python 3 的全面迭代器化

> 分类：版本差异/内存 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**range** / **map** / **dict.items** / **惰性**
> 原文锚点：第 71~92 段「Python 3 的一个非常大的改进，就是一切都是返回迭代器…可以大大的节省内存」

## 一句话总述
Python 3 把 `range`、`map`、`filter`、`dict.keys/values/items` 从**返回列表**改成**返回惰性可迭代对象**，`xrange` 因此退场。

## 面试官视角
- **考察意图**：是否知道这次改动的内存收益，以及它会带来哪些"旧代码静默变慢/报错"的副作用。
- **P5** 知道 `range` 不再生成列表 / **P6** 能列全改了哪些内置 / **P7** 能指出"迭代一次就耗尽"的新坑。
- **红旗**：① 说"`range` 就是生成器"（它是惰性序列，不是生成器）；② 还在找 `iteritems`；③ 以为改了就一定更快。
- **惊艳点**：`dict.items()` 返回的是**视图**，`for k, v in d.items()` 时删除/新增键会直接抛 `RuntimeError`——这是 2 时代没有的 `[经验]`。

## 主问答
**Q：Python 3 里 range、map、dict.items 有什么变化？**
**A：**
1. **先给结论**：它们都从"返回列表"变成**惰性可迭代对象/视图**，内存占用不再随数据规模线性增长。
2. **再给机制**：`range` 是惰性序列对象（只存起止与步长），`map`/`filter` 是迭代器，`dict` 的三件套返回**动态视图**；要真实列表需显式 `list()` 包一层 `[经验]`。
3. **最后给边界**：视图是**动态的**，遍历中改字典会报错；迭代器**一次性**，重复遍历要重新构造——这正是从 2 迁过来最常踩的两个坑。
**加分层**：`range` 不是生成器：它支持 `len()`、下标、切片和 `in` 判断，是"惰性序列"而非"一次性迭代器"。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| Python 3.x 全系 | 2 里 `range` 返回 list、`xrange` 是惰性版；3 移除 `xrange`、`iteritems` 等 | 统一答"惰性 + 视图"，迁移时用 `list()` 显式固化 |

## 关键代码
```python
r = range(10**9)
print(type(r), r[3], 5 in r)      # range 对象：支持下标与 in，不占内存
d = {"a": 1}
v = d.items()
d["b"] = 2
print(list(v))                     # 视图是动态的，已包含新键
```

## ⚠️ 原文纠错
原文称「一切都是返回迭代器」不够精确：`range` 是**惰性序列**而非迭代器，`dict` 三件套返回的是**视图**；三者都惰但语义不同。机翻中的函数名音译已还原。

## 总结与追问预判
- 惰性化换来内存收益，代价是"一次性"与"动态视图"两个新坑。
