# 51. tuple 的"不可变"到底指什么

> 分类：算法与数据结构/线性结构 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**引用不可变** / **tuple** / **可变元素**
> 原文锚点：第 89~101 段「准确的来说，应该是 tuple 是保存的引用不可变」

## 一句话总述
tuple 的不可变是**它保存的引用不可变**——**不能替换其中某个位置指向的对象**，但**若该对象本身可变（如 list），其内容照样能改**。

## 面试官视角
- **考察意图**：区分"容器不可变"与"元素不可变"，这是 Python 对象模型的基本功。
- **P5** 知道 tuple 不可改 / **P6** 能说清是引用不可变 / **P7** 能举出 tuple 套 list 的反例并延伸到可哈希性。
- **红旗**：① 断言"tuple 里所有东西都不能变"；② 不知道 `t[0].append()` 能成功；③ 把"不可变"和"值不可变"混为一谈。
- **惊艳点**：真正的不变量是 `t[0]` 这个**槽位**里的对象标识（id），用 `id(t[0])` 前后对比即可证伪 `[实测]`。

## 主问答
**Q：list 和 tuple 的区别？tuple 到底哪里不可变？**
**A：**
1. **先给结论**：list 可变、tuple 不可变，二者都是线性结构、都支持下标访问；但严格说是 **tuple 保存的引用不可变**。
2. **再给机制**：tuple 的每个槽位存的是对象引用；`t[0] = x` 被禁止（不支持项赋值），但 `t[0].append(x)` 是对**引用指向的那个 list 对象**做原地修改，槽位引用没动。
3. **最后给证据**：`t = ([1], 2)`，执行 `t[0].append(3)` 后 t 变成 `([1, 3], 2)`；`id(t[0])` 前后一致。
**加分层**：正因 list 不可哈希，**list 不能做 dict 的key**，tuple 可以（前提是元素都可哈希），需要时把 list 转成 tuple 再当键。

## 关键代码
```python
t = ([1], 2)
try:
    t[0] = [9]          # TypeError: 不支持项赋值
except TypeError as e:
    print("替换引用被拒:", e)
t[0].append(3)          # 元素本身可变，改得动
print(t)                # ([1, 3], 2)
print(hash((1, 2)), end=" ")   # tuple 可哈希
try:
    hash([1, 2])        # TypeError: list 不可哈希
except TypeError:
    print("list 不可哈希")
```

## ⚠️ 原文纠错
原文口语化地说"tuple 是不可变对象"后又自行更正为"保存的引用不可变"，**后者才是准确表述**，卡面采用后者。转写中的音译词已统一还原为 tuple / list / dict。未发现其他技术错误。

## 总结与追问预判
- 不可变 = 槽位引用不能换；元素若是可变对象，其内容仍可变。
