## 协作 · 测试（混沌）

- **事实**：多 Agent 协作混沌测试：注入单 Agent 故障/延迟/错误（AD-396 模板的多 Agent 面），验证群体降级与隔离（AD-465 验证）
- **原理**：多 Agent 混沌（AD-396 的协作面），注入点（Agent 间消息通道），与混沌知识联动
- **常见误区**：
  1. 多 Agent 无混沌测试（错）
  2. 注入点只有模型（错）
  3. 协作混沌是过度设计（错）
- **工程用法**：多 Agent 混沌
- **版本锚点**：实战共识
