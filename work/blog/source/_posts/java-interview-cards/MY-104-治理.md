## 实践 · 治理（慢 SQL）

- **事实**：慢 SQL 治理体系：上线前 SQL 审核（RDM/Inception 类工具）+线上慢日志监控+TopSQL 优化闭环
- **原理**：事前拦截（索引缺失/全表扫描 SQL 拒绝发布）优于事后救火，DBA 平台自动化审核+治理看板
- **常见误区**：
  1. 慢 SQL 靠 DBA 事后处理（错）
  2. SQL 审核工具没必要（错）
  3. 治理与开发流程无关（错）
- **工程用法**：数据库质量体系
- **版本锚点**：实战方法论
