## 架构 · 不该用（反模式）

- **事实**：不该用 Agent 的场景：固定流程（工作流更可控）、强一致要求（分布式事务）、毫秒延迟（Agent 多轮慢）
- **原理**：Agent 不是万能（JA-018 权衡的反面清单），"能不用就不用"是 P10 判断（AI-049），误用 Agent 是架构债
- **常见误区**：
  1. Agent 适用于一切场景（错）
  2. Agent 性能满足低延迟（错）
  3. 固定流程也该 Agent 化（错）
- **工程用法**：反模式清单
- **版本锚点**：实战共识
