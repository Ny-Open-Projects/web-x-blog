【学习目标】
- 盘点旅行规划涉及的五个智能体（路线制定 / 行程规划 / 费用统筹 / 主管 / 汇总）及其职责。
- 对比两种多 Agent 设计思想：Agent 自主代理（AgentScope 式）与工作流编排（Graph 引擎式）。
- 掌握三类工作流拓扑（线性 / 并行 / 混合），并判定旅行场景适用的混合形态。
- 用 Graph 引擎把「谁在哪一节点、平行为何、汇总为何」可视化，建立可编排心智。

【正文】

回顾前文：旅行规划需求拆出多个智能体。各智能体职责如下：
- **路线制定智能体**：规划路线、计算距离、坐标/经纬度转换、规划最优路线并可视化。
- **行程规划智能体**：查天气、搜景点，按偏好与天气推荐景点（含理由、图片），制定详细行程。
- **费用统筹智能体**：算住宿/交通/餐饮/景点费用，统计明细与总额，监控优惠券。
- **主管智能体**：识别用户意图、拆分任务、统筹分发。
- **汇总智能体**：汇聚前三者的结果反馈给用户。

共五个智能体。基于 Spring AI Alibaba 生态可便捷创建它们；前文把它们简单串联体验协同。

### 一、两种多 Agent 设计思想

课程开篇讲过，多 Agent 协同有两种设计思想：
- **Agent 自主代理**（如 AgentScope）：智能体自主决定按什么步骤、用什么工具完成任务。
- **工作流编排**（Graph 引擎 / 图形引擎）：以图为核心框架显式编排节点与边。Spring AI Alibaba 同样包含 Graph 引擎。本节看工作流编排如何设计协同。

### 二、三类工作流拓扑

五个智能体的协作流程分三类：

1. **线性**：主管→路线→行程→费用→汇总，严格顺序直线传递。
2. **并行**：主管把任务分别发给路线/行程/费用三个工作智能体，三者各自完成后并行发往汇总。
3. **混合**：主管先拆解，把两个任务并行发给路线与行程；二者完成后汇总到费用统筹（费用需含路线车费+景点住宿餐饮费）；最后三者结果都发往汇总，由汇总成表/图反馈。

### 三、旅行场景为何选混合

费用统筹要汇总：深圳→惠州的路线车费，以及景点/住宿/餐饮费。故费用统筹是「汇总角色」。路线制定（深圳→惠州距离花费）与行程规划（沿途景点住宿餐饮，不涉及大车费）互不相干，应并行。

因此本场景采用混合工作流：
1. 用户提出需求，主管做意图分析 + 任务拆解。
2. 路线相关任务分发给路线制定智能体；景点/住宿/餐饮相关任务分发给行程规划智能体（二者并行）。
3. 二者完成后，结果汇总到费用统筹智能体做费用汇总。
4. 三者结果最终发往汇总智能体，由它把交通工具、景点住宿餐饮安排、总开销与明细汇总成表/图反馈用户。

**为什么工作流编排有价值**：它以可视化方式清晰展示每个智能体处于流程哪一节点，以及智能体间是平行、顺序还是汇总关系，编排可控、可观测、易调试，区别于自主代理「黑箱自决」。

【易错点/面试题】
1. **面试问：Agent 自主代理 vs 工作流编排怎么选？** 答：流程固定、需可控可观测选工作流编排（Graph）；任务开放、需灵活探索选自主代理。旅行规划因步骤相对固定，适合混合工作流。
2. **为何费用统筹是汇总角色？** 答：它要聚合路线车费 + 景点/住宿/餐饮费，天然是汇聚节点，故置于并行结果之后。
3. **Graph 引擎的核心抽象？** 答：节点（Agent/步骤）+ 边（流转条件），以有向图表达协作，对应 Spring AI Alibaba 的 Graph 模块。

【小结】
本节以混合工作流编排旅行规划的五个智能体，明确「并行执行 + 费用汇总 + 结果汇总」的结构。本课程的 981-demo 以 AgentScope 离线桩复刻「主管调度成员」的编排形态，路径见 `981-demo/src/main/java/com/travel/agent/agent/SupervisorAgent.java`。技术前瞻：Spring AI 2.0 的 Advisor 链与 2.1 的 Message Parts、Spring AI Agents 项目（Skills / 子 Agent / 渐进披露）正把「图编排 + 自主代理」逐步融合，是后续演进方向。
