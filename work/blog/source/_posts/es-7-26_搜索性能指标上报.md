# Go 项目开发: 搜索性能指标上报（Prometheus + Grafana 全链路）

这一节把上一节的**指标定义真正接出去**：起监控三件套 → 配置进服务 → 定义 metric → 在接口入口上报 → **Grafana 画三个面板（QPS / 分位数 / 区间分布）**。中间塞了一段 `defer` 机制的讲解，因为上报代码就挂在 `defer` 上。

一条链路先看明白：**应用 → push 到 pushgateway（9091）→ prometheus 定期拉（9090）→ grafana（3000）展示**。

## 纲要

- 监控三件套：`docker-compose -d` 起 prometheus / grafana / pushgateway
- 同 docker 网络下**直接用服务名访问**，不用配 IP
- prometheus 端口 9090（容器内部），pushgateway 9091，grafana 3000
- config.yaml 加 `prometheus.pushgateway` 配置，`mapstructure` 标签对齐
- `InitPrometheus`：SDK 四个参数（host / 间隔 / appName / httpClient）
- **测试用 1 秒推送间隔，生产用 30~60 秒**
- 指标类型用 **histogram**（直方图），一个指标自动生成 `_count` / `_sum` / `_bucket` 三个序列
- 默认标签带 `hostname` + `appName`，自定义标签 `cluster` 区分打到哪个 ES 集群
- 上报放在接口入口的 `defer` 里，`defer` 在函数 return 前执行，算的正是接口总耗时
- **只标记名返回值 + defer 里改返回值**才生效，这是 defer 最容易踩的坑
- Grafana 面板一：QPS = `sum(rate(xxx_count[2m]))`
- Grafana 面板二：分位数 = `histogram_quantile(0.99, sum(rate(xxx_bucket[2m])) by (le))`
- Grafana 面板三：区间分布 = `increase(xxx_bucket{le="0.01"}[2m])`，大桶减小桶

## 上报链路总览

指标从应用侧到看板，是一条「push + pull」的链路：应用入口 `defer` 埋点累积到进程内 histogram，定时 push 给 pushgateway，prometheus 再拉取，最后 grafana 出三个面板。

```mermaid
flowchart LR
    A["应用<br/>搜索服务"] -->|"defer 埋点"| E["histogram<br/>_count/_sum/_bucket"]
    E -->|"push"| B["pushgateway<br/>9091"]
    B -->|"pull"| C["prometheus<br/>9090"]
    C --> D["grafana<br/>3000 看板"]
```

三个核心面板对应的 PromQL 要点：

| 面板 | 作用 | PromQL 关键 |
| --- | --- | --- |
| QPS | 每秒请求数 | `sum(rate(xxx_count[2m]))` |
| 分位数 | P90 / P95 / P99 | `histogram_quantile(0.99, sum(rate(xxx_bucket[2m])) by (le))` |
| 区间分布 | 各耗时区间请求数 | `increase(xxx_bucket{le="0.01"}[2m])`，大桶减桶 |

监控组件在 docker 网络里的拓扑（同网络下用服务名互访，不写死 IP）：

```dir
monitor-stack/
├── prometheus/             9090，定时 pull 指标
├── pushgateway/            9091，接收应用 push
├── grafana/                3000，可视化看板
├── alertmanager/           9093，告警分发
└── search-service/         应用侧上报
    └── defer 入口埋点      算接口总耗时
```

## 一、先把监控三件套跑起来

`docker-compose -d` 一键起三个服务：

```yaml
version: "3"
services:
  prometheus:
    image: prom/prometheus
    container_name: prometheus
    # 9090 只在容器内部暴露，grafana 通过服务名访问即可
    ports:
      - "9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
  pushgateway:
    image: prom/pushgateway
    container_name: pushgateway
    ports:
      - "9091"
  grafana:
    image: grafana/grafana
    container_name: grafana
    ports:
      - "3000:3000"
    depends_on:
      - prometheus
```
注意 prometheus 的 9090 **没有映射到宿主机**，它只在 docker 网络内生效。grafana 里配数据源时直接写 `http://prometheus:9090`，靠**服务名DNS**解析，不用找 IP。

## 二、配置与初始化

配置进 `config.yaml`，结构体用 `mapstructure` 标签对齐（同样的老问题：标签写错不报错，只静默填零值）。

```go
package main

import (
	"fmt"
	"net/http"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/push"
)

// ============ 配置层 ============

type PrometheusConfig struct {
	Host   string `mapstructure:"host"`    // pushgateway 地址，如 http://192.168.1.10:9091
	AppName string `mapstructure:"appName"` // 作为 jobname 上报
}

type Config struct {
	Mode        string            `mapstructure:"mode"`
	Prometheus  PrometheusConfig  `mapstructure:"prometheus"`
}

// ============ 指标定义：histogram ============

// defaultBuckets：注意这里的桶值必须和 Grafana 面板里写的 le 一一对应
var defaultBuckets = []float64{
	0.005, 0.01, 0.015, 0.02, 0.05,
	0.1, 0.15, 0.2, 0.3, 0.5,
	1, 2, 3, 5,
}

// metricProductSearch：直方图 + 自定义标签 cluster
var metricProductSearch = prometheus.NewHistogramVec(
	prometheus.HistogramOpts{
		Name:    "shop_product_search_duration_seconds",
		Help:    "shop product search duration seconds",
		Buckets: defaultBuckets,
	},
	[]string{"cluster", "hostname", "appName"},
)

// initMetric：注册到默认 registerer，并在 init 里做一次
func initMetric() {
	prometheus.MustRegister(metricProductSearch)
}

// ============ 上报：接口入口用 defer 打点 ============

// reportSearchDuration：cluster 标记这次请求打到哪个 ES 集群
func reportSearchDuration(cluster, hostname, appName string, elapsed time.Duration) {
	metricProductSearch.
		WithLabelValues(cluster, hostname, appName).
		Observe(elapsed.Seconds())
}

// ============ 推送到 pushgateway ============

// initPrometheus：定时把进程内指标推给 pushgateway
// 测试用 1 秒（方便立刻看到效果），生产用 30~60 秒
func initPrometheus(host, appName string, interval time.Duration, client *http.Client) {
	pusher := push.New(host, appName).
		Gatherer(prometheus.DefaultGatherer).
		Client(&http.Client{Transport: client.Transport})

	go func() {
		ticker := time.NewTicker(interval)
		defer ticker.Stop()
		for range ticker.C {
			if err := pusher.Push(); err != nil {
				fmt.Println("push metric error:", err)
			}
		}
	}()
	fmt.Println("prometheus init:", host, "interval:", interval)
}

func main() {
	cfg := &Config{
		Mode: "dev",
		Prometheus: PrometheusConfig{
			Host:    "http://192.168.1.10:9091",
			AppName: "shopsearchapi",
		},
	}

	initMetric()
	initPrometheus(cfg.Prometheus.Host, cfg.Prometheus.AppName, time.Second, http.DefaultClient)

	// 模拟一次搜索请求，在入口处记时并上报
	start := time.Now()
	doSearch("iphone")
	reportSearchDuration("clusterA", "node-1", cfg.Prometheus.AppName, time.Since(start))
}

func doSearch(kword string) {
	fmt.Println("search:", kword)
}
```
三个要点：

- **histogram 一个定义会生成三个序列**：`_count`（次数）、`_sum`（总耗时）、`_bucket`（各桶计数）。QPS 用 `_count`，分位数用 `_bucket`。
- **`_bucket` 的标签是 `le`（小于等于）**，画图时必须 `by (le)` 分组。
- **桶的值必须**：和代码里定义的步长一致，Grafana 里写个不存在的桶（比如 0.026）永远查不到数据。

## 三、defer 的返回值陷阱（上报代码就挂在这上面）

上报放在 `defer` 里，有两个好处：**函数无论如何 return 都会上报**，而且 `defer` 是在 return 之前执行的，所以算出来的是**接口总耗时**而不是 ES 那一段耗时。

但 `defer` 里改返回值，只有在**命名返回值**（显式 return 变量）的情况下才生效。看这五个例子：

```go
package main

import "fmt"

// f1：匿名返回值 + defer 里 s++
func f1() int {
	s := 5
	defer func() { s++ }()
	return s
}

// f2：s++ 等价于 s = s + 1，结果同 f1
func f2() int {
	s := 5
	defer func() { s = s + 1 }()
	return s
}

// f3：defer 里直接赋 6，结果仍是 5
func f3() int {
	s := 5
	defer func() { s = 6 }()
	return s
}

// f4：命名返回值（return 带变量），defer 里的自增会生效 → 输出 6
func f4() (s int) {
	s = 5
	defer func() { s++ }()
	return s
}

// f5：返回值变量是 y，defer 改的是 s，互不相干 → 输出 5
func f5() (y int) {
	s := 5
	defer func() { s++ }()
	return s
}

func main() {
	fmt.Println(f1(), f2(), f3(), f4(), f5())
	// 输出：5 5 5 6 5
}
```
原理是：函数 return 时**先把返回值赋值、再执行 defer、最后真正返回**。匿名返回值场景下，`defer` 里改的是另一个内存地址上的变量（值传递），改不到返回值上；**命名返回值是引用语义，`defer` 里改它就能改到返回值**。

另外 `defer` 是**后进先出**（LIFO）的栈：连续写三个 `defer d1() / d2() / d3()`，执行顺序是 d3 → d2 → d1。

## 四、压测跑指标，Grafana 画三个面板

先起搜索服务，再用测试程序循环打接口（比如循环调 `http://localhost:9090/api/v1/product/search`），指标就上报上去了。

**面板一：QPS**

```
sum(rate(shop_product_search_duration_seconds_count[2m]))
```
**面板二：分位数（P99 / P95 / P90）**

```
histogram_quantile(
  0.99,
  sum(rate(shop_product_search_duration_seconds_bucket[2m])) by (le)
)
```
把 `0.99` 换成 `0.95` / `0.90` 就是另外两条曲线，**从图上看 P90 < P95 < P99 才正常**，反过来说明数据有问题。

**面板三：各区间请求数**

```
increase(shop_product_search_duration_seconds_bucket{le="0.01"}[2m])
```
区间怎么算？**大桶减小桶**：

- `le="0.2"` 的数量 = ≤200ms 的请求数
- `le="0.1"` 的数量 = ≤100ms 的请求数
- 两者相减 = **100~200ms 区间**的请求数

如果我这边的 P99 落在 350~400ms，那 `le="0.01"`（10ms 以内）基本就是 0，`le="0.1"` 也只有零星——这正说明接口慢在 ES 查询这一段。

## 注意事项

1. **pushgateway 挂应用名**：`push.New(host, jobName)` 的第二个参数是 job，一般用 appName，多个实例会互相覆盖，所以**指标里一定要带 `hostname`/`instance` 标签**区分。
2. **生产推送间隔 30~60 秒**，测试才用 1 秒——1 秒推送太频繁会打垮 pushgateway。
3. **histogram 优于 summary**：histogram 在客户端存桶，服务端聚合，多机器汇总不会失真。
4. **`_bucket` 必须 `by (le)` 再算分位数**，直接 `sum` 掉会报错算不出来。
5. **桶值和 Grafana 的 `le` 必须一致**，写个不存在的桶过滤永远是 0。
6. **`cluster` 这种业务标签要有节制**：维度一多，时间序列数指数级膨胀，先评估 cardinality。
7. **上报要兜底**：`Observe` 失败不能影响主流程，别在指标库挂了的时候拖垮搜索接口。
8. **`defer` 上报算的是总耗时**（从入口到 return），不是 ES 耗时；要分段耗时就单独埋点。
9. **压测程序先起服务再跑**，否则看到的是连接失败的错误耗时。
10. **同一 docker 网络里用服务名**，别写死 IP，容器重建 IP 就变了。
11. **指标名要稳定，改 name 等于换指标**，历史数据全断，上线前定死。
12. **分位数面板至少放 P90 / P95 / P99 三条线**，一条线看不出长尾。

## 本节作业

1. 把 `reportSearchDuration` 拆成 `start := time.Now()` + `defer report(elapsed)` 的经典写法，并加一个 `if elapsed > time.Second { warn }` 的慢请求告警打点。
2. 给指标再加一个 `api` 标签（区分 `/search` 和 `/suggest`），并说明这样会让时间序列数增加多少，评估后决定是否保留。
3. 在 Grafana 里加一个「慢请求占比」面板：`P99 样本数 / 总样本数`，并用 `absent()` 做一个「进程挂了没人上报」的告警规则。

## 总结

把上一节的指标定义真正接出去，链路是：**应用入口用 `defer` 埋点 → 进程内 histogram 累积 → 定时 push 到 pushgateway（9091）→ prometheus（9090）拉取 → grafana（3000）画三个面板（QPS / 分位数 / 区间分布）**。

三个最该记住的点：**histogram 一个定义自动生成 `_count` / `_sum` / `_bucket` 三个序列，QPS 用 `_count`、分位数用 `_bucket` 且必须 `by (le)`**；**桶值必须和 Grafana 里写的 `le` 一一对应**，写个不存在的桶永远是 0；**上报挂在 `defer` 里算的是接口总耗时**，而 `defer` 改返回值只有在命名返回值下才生效（f4 输出 6、其余输出 5）。

生产环境推送间隔用 30~60 秒（测试才 1 秒），指标名和桶一旦定下就别改，免得历史数据断裂；`cluster` 这类高基数标签要有节制，否则时间序列数会指数膨胀。
