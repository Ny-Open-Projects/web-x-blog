## 纲要

- **核心思路**：把后续的「角色 + 结构化输出 + 分阶段 + 少样本」直接套到职场文档——PRD、周报。
- **PRD 生成**：设「20 年经验产品经理」角色，先出粗略大纲，回复「继续」再逐部分细化，避免一次性超长输出被上下文截断。
- **周报模仿**：给模型你过往写得好 的周报作示例，要求「模仿结构/口吻/表述」复写；再迭代精简（限字数、用 markdown）。
- **固化对话**：结尾加「如果你明白了，请回复明白了，之后我只需发本周内容」——把模板沉淀成常驻人设，后续只填输入。
- **少样本（few-shot）**：提供 1~2 个范例比纯文字描述风格更准，是原则一「少样本示例」的职场版。

> 本章按课程口径重构；剥离营销与课程群引流，保留可复用的职场 Prompt 范式。

## 一、PRD：分阶段输出防截断

- **Prompt 骨架**：`你是 20 年经验产品经理；基于我提供的需求全面考虑并完善细节，编写详实 PRD`。
- **输出要求**：因篇幅限制，先规划粗略大纲；当我回复「继续」时，按大纲**依次细化每部分**，直到写完。
- **迭代修正**：若模型跳过某部分，直接指令「补充第 X 部分内容」；对名称/背景/目标不满意，要明确告知期望（如「名称需包含 XX」），否则它只能猜。

## 二、周报：用少样本模仿你的风格

- **基础结构**：`你是高级产品经理；我需写周报，含本周进展/下周安排/思考总结；下面是我写过的周报，请按此风格复写`。
- **迭代精简**：首版偏长 → 追加「每条精简、起始点明核心、用 markdown 输出」重生成。
- **固化**：`现在起你是我的周报助手，我后续只发本周内容，按上述结构输出；明白了请回"明白了"`——之后每轮只丢工作内容。

## 三、为什么「示例」比描述更准

- 纯文字描述风格易跑偏；贴 1~2 篇真实范例（few-shot），模型对口吻/结构/表述的还原度显著提升。
- 范例要「好且典型」：删掉啰嗦废话的版本更佳，避免模型学到坏习惯。

## 四、常见误区

- 一次性要完整长文档 → 超上下文被截断；应分阶段「大纲→细化」。
- 对输出不满意却不给具体期望 → 模型只能猜；要指明「名称/背景/目标要什么」。
- 每轮重写完整 Prompt → 用「固化对话」沉淀人设，省 token 也省心智。

## 五、FAQ

**Q1：PRD 太长一次写不完？**
先要大纲，回复「继续」逐部分细化；缺哪部分定向补。

**Q2：周报怎么贴合我的风格？**
给 1~2 篇过往周报作 few-shot 示例，要求模仿结构/口吻/表述。

**Q3：固化对话怎么用？**
结尾声明「明白了请回明白了，之后我只发输入」，把模板沉淀为常驻指令。

**Q4：示例写得很啰嗦会怎样？**
模型可能学到坏风格；范例先自己删废话再贴。

## 六、面试高频问答

**1. 怎么用大模型生成专业 PRD？**
设资深角色 + 分阶段（先大纲后细化）+ 定向补充，规避上下文截断。

**2. few-shot 在职场写作的价值？**
贴真实范例比文字描述风格还原更准，是少样本原则的直接落地。

**3. 怎么让周报输出稳定贴合？**
用「固化对话」把结构/风格沉淀为人设，后续只填每周内容。

**4. 长文档输出被截断怎么办？**
拆「大纲 → 分部分细化」，配合「继续」式多轮而非单次硬写。

## 七、ops 提示（实践）

> **长文必分阶段**：PRD/方案类一律「先大纲后细化」，别赌单次上下文。
>
> **风格靠示例**：想要特定口吻，few-shot 比形容词描述可靠。
>
> **模板常驻化**：高频文档用固化指令沉淀，避免每轮重写长 Prompt。
