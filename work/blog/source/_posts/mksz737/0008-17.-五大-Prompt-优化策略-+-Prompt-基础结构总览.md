## 纲要

- **五大优化策略**（与「两大原则·六大策略」互通，更精炼）：
 1. **清晰具体**：避免模糊致模型编造（如「九一八历史事件」要写清，否则模型不知所指）。
 2. **提供上下文**：用分隔符区分背景；加限定词（「西北风」「全球气候变暖」）；避免模型通识泛答。
 3. **正确语法 + 避免生僻术语**：如 `MR` 是英语尊称还是学科名词？`CSP` 须写明 = 内容安全策略（Content Security Policy），否则模型猜错编造。
 4. **分布提示 / 分布提问**：拆解复杂任务；**反过来让模型反问所需背景信息再规划**（如「构建网站」案例：模型先列 9 问，答完再定制步骤）。
 5. **输出要求优化**：表格/特定格式/给示例（如把 Markdown 标题换成有序列表）。
- **Prompt 基础结构（四部分）**：**指令 / 输入数据 / 背景 / 输出要求**。背景限定专家角度（如让 ChatGPT 扮专家，从训练语料提炼专业而非中性信息）。
- **自检**：用五策略回看自己写的 Prompt——是否清晰简洁？有上下文？无生僻错词？复杂问题拆分？有输出要求/示例？

## 一、优化策略一~三（4-4）

| 策略 | 要点 | 反例→优化 |
|---|---|---|
| 清晰具体 | 避免模糊致编造 | 「讲述九一八」→「请描述历史事件九一八」 |
| 提供上下文 | 分隔符+限定词 | 「谈风」→「西北风/中国某地域的风」；「气温变暖」→「全球气候变暖」 |
| 语法+术语 | 避免生僻/错词 | 「解释 CSP」→「计算机网络中的 CSP（内容安全策略）工作原理」 |

- **关键坑**：专业缩写（MR/CSP/HGDP）不注明领域，模型会猜、会编。

## 二、优化策略四：分布提问

```mermaid
graph TD
    A[复杂目标:构建网站] --> B[Prompt:帮我梳理步骤<br/>并反问所需背景信息]
    B --> C[模型列问题(如9问)]
    C --> D[用户逐条回答<br/>目标/技术/功能/支付/预算...]
    D --> E[模型据此定制详细步骤]
    E --> F[对单步继续分布询问]
```

- **妙处**：非专家也可让模型先问清需求再规划，似「反过来面试模型」。

## 三、优化策略五：输出要求

- 要求表格/特定格式/给示例；如把 Markdown 标题换成有序列表，模型即按样输出。

## 四、Prompt 基础结构

| 部分 | 作用 |
|---|---|
| 指令 | 告诉模型如何处理后续数据与输出 |
| 输入数据 | 需处理的内容，缩小范围、贴合场景 |
| 背景 | 限定工作范围；加「扮专家」即从专家角度而非通识中性答 |
| 输出要求 | 字数、格式等（常写明） |

- **背景的价值**：无背景→通识角度；加背景/角色→专家角度，答案更贴合。

## 五、FAQ

**Q1：五大策略与两大原则关系？**
互通且更精炼；策略一~三对应原则一（清晰具体+上下文+语法），策略四对应原则二（拆解），策略五是输出要求。

**Q2：分布提问适合谁？**
尤其适合非专家——让模型先问清需求再规划，降低自写门槛。

**Q3：背景为什么重要？**
无背景模型通识泛答；加背景/角色（如专家）得专业角度答案。

**Q4：生僻缩写怎么处理？**
写明领域与全称（如 CSP=内容安全策略），避免模型猜编。

## 六、面试高频问答

**1. 五大 Prompt 优化策略？**
清晰具体、提供上下文、正确语法避免生僻术语、分布提问拆解、输出要求优化。

**2. Prompt 基础四结构？**
指令、输入数据、背景、输出要求；背景决定专家/通识角度。

**3. 分布提问是什么？**
让模型先反问所需背景信息再规划，适合非专家拆解复杂任务。

**4. 如何避免模型编造？**
指令清晰具体、提供上下文与限定词、注明术语领域，减少模型猜测。

## 七、ops 提示（实践）

> **写前套四结构**：指令/输入/背景/输出先列全，再补五策略。
>
> **术语必注领域**：MR/CSP/HGDP 类缩写不注领域，模型必编。
>
> **非专家用分布提问**：让模型问、你答，再要方案，比硬写长 Prompt 稳。
