# 给裸 Git 装个图形界面：Docker 部署 Gogs 并建好第一个仓库

> 🔒 安全提示：文中示例的口令/密钥均为课程教学环境演示口径，生产环境的安全要求见《安全与合规须知》。

Jenkins 要做持续集成，第一步就是从 Git 服务器抓取代码，所以 Git 环境必须先就位。在 CentOS 上装 Git 本身不难，课程环境也早已装好，麻烦在于裸 Git 不带图形界面：建仓库、管账号、浏览提交历史全靠命令行，日常管理很不方便。图形化 Git 服务里，Gogs 是轻量又够用的一个，这一课就用容器把它跑起来，装完顺手建好持续集成要用的第一个仓库。

## 先给结论

- Gogs 是用 Go 语言开发的轻量级自托管 Git 服务，功能与 GitHub 相似，企业常用它在局域网搭建自己的 Git 代码管理仓库。
- 安装走容器化路线：`docker pull gogs/gogs` 拉镜像，一条 `docker run` 建容器；22 端口映射出来给 SSH 克隆用，3000 端口是 Web 界面。
- 首次访问 `http://宿主机IP:3000` 会进入安装向导，数据库选 SQLite3 最省事，全部数据写进一个 `gogs.db` 文件。
- 「域名」一栏必须把默认的 `localhost` 改成宿主机真实 IP，它直接决定 SSH 克隆地址长什么样。
- 装完用管理员账号登录，点加号创建仓库，页面上「复制链接」拿到的地址，就是后面 IDEA 推代码、Jenkins 拉代码要用的那条。

## 一、为什么选 Gogs

课程安装文档对它的定位很直白：Gogs 是一个用于代码仓库管理系统的开源项目，使用 Git 作为代码管理工具，并在此基础上搭建 Web 服务。它解决的就是「有 Git、没界面」的问题：

**第一，仓库管理网页化。** 裸 Git 建一个共享仓库要 `git init --bare`、要管文件系统权限、要看日志还得登服务器。Gogs 把这些全搬到网页上，点加号就能建仓库，权限、分支、提交历史一目了然。

**第二，企业内网自建。** GitHub 在公网，代码放到外面很多公司不放心。Gogs 轻到一台普通服务器甚至一个容器就能跑，团队在局域网里就能拥有自己的「GitHub」，代码不出内网。

它和 GitHub 的关系是「同类产品、不同场景」：GitHub 面向公网开源社区，Gogs 面向企业私有部署，协议上都走 Git，本地操作习惯完全不变。

## 二、两条命令把 Gogs 跑起来

容器化安装，命令来自课堂文档实录：

```bash
# (1) 下载镜像
docker pull gogs/gogs

# (2) 创建容器
docker run -d --name=gogs -p 10022:22 -p 3000:3000 -v /var/gogsdata:/data/gogs gogs
```

三个关键参数拆开看：

**第一，`-p 10022:22`。** 容器内的 22 端口是 Gogs 内置的 SSH 服务，负责 `git@` 协议的克隆与推送。宿主机上 22 往往已被占用，所以映射到 10022。

**第二，`-p 3000:3000`。** 3000 是 Gogs Web 界面的端口，浏览器访问、HTTP 协议克隆都走它。

**第三，`-v /var/gogsdata:/data/gogs`。** 目录挂载，把 Gogs 的数据落到宿主机 `/var/gogsdata` 里。容器坏了直接删掉重建，数据还在，维护起来省心。

假设宿主机 IP 为 `192.168.184.141`，容器建好后浏览器访问 `http://192.168.184.141:3000`，就能看到 Gogs 的首次安装页面。

## 三、首次安装向导：数据库与域名

第一次打开会停在安装配置页，要动手的地方不多，逐项过一遍：

| 配置项 | 填写值 | 说明 |
|---|---|---|
| 数据库类型 | SQLite3 | 数据全部写进 `data/gogs.db` 单文件，个人与小团队首选 |
| 数据库文件路径 | `data/gogs.db` | 保持默认即可 |
| 仓库根目录 | `/data/git/gogs-repositories` | 保持默认 |
| 运行系统用户 | `git` | 保持默认 |
| 域名 | `192.168.184.141` | 默认 `localhost`，必须改成宿主机 IP |
| 应用 URL | 改成 IP 形式 | 与域名同步调整 |

**第一，数据库怎么选。** SQLite3 把整个站点的数据存成一个 `gogs.db` 文件，无需额外装数据库服务，课程环境选它；文档同时说明，规模较大的公司可以选择 MySQL，并发与数据量上来后更稳。

**第二，域名为什么必须改。** 这个字段会被拼进仓库的克隆地址里。保持 `localhost`，装出来的克隆地址就是 `git@localhost:...`，别的机器照着它克隆必然失败。改成宿主机 IP，SSH 克隆地址才是别人真正能连的。

页面底部可以顺手设置管理员账号，比如用户名 `liubei`、密码 `123456`，邮箱是必填项，但不必是真实存在的邮箱。填完点「立即安装」，几秒后用管理员账号登录，进入 Gogs 首页。

## 四、创建仓库，拿到克隆地址

登录后点右上角加号，选「创建新的仓库」，表单里真正要关心的就三项：

```text
拥有者:   liubei
仓库名称: tensquare
可见性:   该仓库为私有的
```

仓库名按项目起，课程里建的是持续集成要用的聚合工程 `tensquare`；可见性选私有，代码只对授权用户开放。点「创建仓库」，仓库就绪。

新建的空仓库页面会给出「快速帮助」命令，这就是标准的首推流程：

```bash
touch README.md
git init
git add README.md
git commit -m "first commit"
git remote add origin http://192.168.184.141:3000/liubei/tensquare.git
git push -u origin master
```

更省事的办法是点页面右侧「复制链接」按钮，把 `http://192.168.184.141:3000/liubei/tensquare.git` 这条地址直接放进剪贴板，下一篇在 IDEA 里关联远程仓库时粘贴即可。

把 Gogs 放进整条持续集成链路，它的位置一目了然：

```mermaid
flowchart LR
    A["开发机 IDEA"] -->|"git push 提交代码"| B["Gogs 服务器<br/>Web 端口 3000<br/>SSH 端口 10022"]
    B -->|"Jenkins 凭证拉取源码"| C["Jenkins 集成服务器"]
    C --> D["Maven 构建并产出镜像"]
```

关键路径是中间那一跳：Jenkins 凭什么能从 Gogs 拿到私有仓库的代码？靠的是之前在 Jenkins 里配好的 Git 凭证，两端就位，持续集成的源头才算打通。

## 常见误区

- **域名保持 `localhost` 不改。** 安装页默认值就是它，装完克隆地址里也带着 `localhost`，团队其他人连不上。装之前先把域名和应用 URL 都换成宿主机 IP。
- **只映射 3000 不映射 22。** 网页一切正常，但 SSH 方式克隆 `git@...` 连不通。22 端口同样要在 `docker run` 里映射出来。
- **不做 `-v` 目录挂载。** Gogs 的仓库数据全在容器里，误删容器就等于删库。挂载到宿主机目录，重建容器数据无损。
- **把 3000 当成 SSH 端口用。** 3000 只服务 Web 与 HTTP 克隆，SSH 协议走的是映射出来的 10022，两种地址不能混填。

## 面试可能被问到的问题

1. 面试官追问：「Gogs 和 GitHub、GitLab 是什么关系？」
   答：三者都是基于 Git 的代码托管服务。GitHub 面向公网社区，GitLab 功能全面但较重，Gogs 用 Go 语言开发、部署极轻，适合企业在局域网自建私有仓库，日常 Git 操作习惯完全一致。

2. 面试官追问：「Gogs 安装时数据库选 SQLite3 还是 MySQL，怎么权衡？」
   答：SQLite3 零依赖，数据落在一个 db 文件里，个人开发与小团队完全够用；MySQL 适合用户多、并发高、数据量大的场景，运维成本换来更强的扩展能力。课程环境选 SQLite3，生产大团队多选 MySQL。

3. 面试官追问：「容器里的 Gogs 升级或重建时，怎么保证仓库数据不丢？」
   答：创建容器时用 `-v` 把数据目录挂载到宿主机，如 `/var/gogsdata:/data/gogs`。仓库、用户、数据库文件都存在宿主机上，容器销毁重建后重新挂载即可恢复，这也是 Docker 有状态服务的通用做法。

4. 面试官追问：「安装页里那个『域名』字段到底影响什么？」
   答：它会被拼进 Gogs 生成给用户的克隆地址中。填 `localhost` 生成出的地址只有本机能用，填宿主机 IP 或域名，团队拿到的 SSH 克隆地址才是可用的，所以必须在安装时改对。

5. 面试官追问：「持续集成体系里，Git 服务器扮演什么角色？」
   答：它是整条流水线的源头。开发者把代码推到 Git 服务器统一汇总，Jenkins 持续集成时从仓库拉取最新源码进行编译构建。没有集中的代码仓库，自动集成的输入就无从谈起。
