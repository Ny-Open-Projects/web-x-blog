# ES 索引库批量/增量导入、商品搜索实现与 Freemarker 静态页生成

上一篇备好了分页查询秒杀商品的接口，这一篇把数据真正灌进 Elasticsearch：先建索引库映射对象，再走批量导入做数据初始化、增量导入应对日常变更，然后用 Spring Data ES 的命名规则方法实现按时间搜索，最后用 Freemarker 把商品详情页做成静态页，为高并发访问减压。

## 先给结论

- 存 ES 的过程类似「从 A 库查出数据插入 B 库」：数据库数据转成 Sku，再转成索引库对应的 SkuInfo，交给 API 写入索引；索引库 goodsindex 类似数据库，类型 skuinfo 类似表，字段类似列。
- 映射对象的关键注解：`@Document(indexName = "goodsindex", type = "skuinfo")` 绑定索引和类型，`@Id` 标唯一标识，`@Field` 配置类型与分词器——名称用 Text+ik_smart 支持分词，分类、品牌用 Keyword 整词不拆分，开始时间转成字符串便于直接搜索。
- 批量导入只在数据初始化（或数据清空后）用一次：查总数 → 算总页数 → 循环每页查 500 条 → 转 SkuInfo → `saveAll`；增量导入只需一个 modify 方法，type=1/2 走 save（ES 修改本质是删旧增新），type=3 走 deleteById。
- 搜索按秒杀开始时间做：DAO 按 Spring Data 命名规则定义 findByBtime，条件参数在前、Pageable 在后，顺序写反会报分页错误；`PageRequest.of` 的页码从 0 开始，前端传来的页码要减一。
- 详情页除商品数量外几乎不变，数据量庞大不适合放缓存，用 Freemarker 生成静态页：模板放 templates 目录、后缀 .ftl，模板名、输出路径、文件名（商品 ID.html）都装进数据模型 Map，输出目录用配置注入不写死。

## 索引库映射对象：SkuInfo 怎么对上 goodsindex

以前把商品数据存 MySQL，是先转成 Sku 这个 JavaBean，再通过相关 API 插入数据库。现在要把数据库数据取出来插进索引库，过程类似把数据从 A 数据库查出来插入 B 数据库，用文字翻译一遍：查出数据库数据，转成数据库表对应的 JavaBean，再转成索引库对应的 JavaBean，交给对应 API 插入索引库。

插入索引库之后的状态里有一个索引库名称和一个类型，索引库名称类似数据库名，下面挂的类型类似表，表里的字段类似列。所以要在搜索微服务对应的 API 里创建一个和索引库字段一一对应的 JavaBean，取名 SkuInfo：

```java
@Document(indexName = "goodsindex", type = "skuinfo")
public class SkuInfo {
    @Id
    private String id;          // 唯一标识，进详情页要靠它

    @Field(type = FieldType.Text, searchAnalyzer = "ik_smart", analyzer = "ik_smart", store = false)
    private String name;        // 商品名称，支持分词

    private Integer price;      // 价格
    private Integer seckillPrice; // 秒杀价格
    private String image;       // 商品图片
    private String updateTime;  // 更新时间，可用于排序
    private String category1Name; // 三级分类名称全存，可能按任一级搜索
    private String category2Name;
    private String category3Name;
    private String brandName;   // 品牌搜索用
    private String bttime;      // 秒杀开始时间，转字符串便于搜索
    private String seckillEnd;  // 秒杀结束时间
    private String spec;        // 规格
    // status 可要可不要：有开始结束时间就能判断是否处于秒杀时间段
}
```

`@Document` 里的 indexName 是索引库名称，type 是类型；把这个 JavaBean 填充数据后交给 API 执行增加，数据就会写到对应索引的对应类型里。`@Id` 类似数据库主键的唯一标识。`@Field` 是映射属性配置，不写时会在索引库添加与属性名对应的列并按默认类型处理，写上则可以自定义属性：

- `type = FieldType.Text` 表示文本类型，支持分词——分词就是从一段语句里把词语摘出来，比如「小方今天去吃饭」能分出「小方」「吃饭」；`searchAnalyzer` 是搜索时用的分词器，`analyzer` 是添加数据时用的分词器，这里都用 ik_smart，这个分词器已经装到 ES 里，直接用。
- `store = false` 表示不存储——不是数据不存，而是不额外再存一份 Lucene 的数据。
- 价格字段没有添加分词器，默认会和 price 对应的类型保持一致。
- 分类名称、品牌名的类型是 `FieldType.Keyword`：把整个语句作为一个词不可拆分。「华为手机」是一个分类，如果拆成「华为」「手机」两个词，按分类搜索的数据就不准确，所以分类、品牌都不建议拆分。
- 秒杀开始时间 bttime（即 beginTime）转成字符串类型，后面可以直接按字符串搜索。

## 批量导入与增量导入：Spring Data ES 两条路

### 批量导入：只在初始化时跑一次

集成 Spring Data Elasticsearch 分四步：配置 Elasticsearch 地址信息；编写 DAO 继承 ElasticsearchRepository；在 Service 中分页调用查询秒杀商品集合；分页导入到索引库。先在 bootstrap.yml 的 Spring 节点下加上 ES 的 IP 和端口配置，再建 controller、service、dao 三个包。

DAO 很简单，泛型第一个写 SkuInfo（操作这个对象对应的索引库），第二个写唯一标识的类型 String：

```java
public interface SkuInfoMapper extends ElasticsearchRepository<SkuInfo, String> {
}
```

业务层 SkuInfoServiceImpl（交给容器管理）里写批量导入方法，流程是：查总记录数 → 根据总数计算总页数 → 循环总页数查每页数据 → 转成 SkuInfo → 批量保存：

```java
@Autowired
private SkuFeign skuFeign;
@Autowired
private SkuInfoMapper skuInfoMapper;

public void addAll() {
    // 1.查询总记录数
    Integer total = skuFeign.count();
    // 2.计算总页数，从第1页开始每页500条
    int page = 1, size = 500;
    int totalPages = total % size == 0 ? total / size : total / size + 1;
    // 3.循环分页查询每页数据
    for (int i = 1; i <= totalPages; i++) {
        List<Sku> skus = skuFeign.list(page, size);
        // 4.转成 SkuInfo
        List<SkuInfo> skuInfos = JSON.parseArray(JSON.toJSONString(skus), SkuInfo.class);
        // 5.批量保存
        skuInfoMapper.saveAll(skuInfos);
        page++;
    }
}
```

为什么要转 SkuInfo？因为从商品微服务查出来的是 Sku，必须转成索引库对应的 SkuInfo 才能添加进去。另外 SkuInfo 里新加了 bttime 这个字符串属性，循环里要做一次时间转换：当前 SkuInfo 的开始时间不为空时，用 SimpleDateFormat 把秒杀开始时间格式化成字符串再赋值回去。

控制层加一个批量导入接口，别忘了跨域注解：

```java
@RestController
@RequestMapping("/search")
@CrossOrigin
public class SearchController {
    @Autowired
    private SkuInfoService skuInfoService;

    @GetMapping(value = "/add/all")
    public Result addAll() {
        skuInfoService.addAll();
        return new Result(true, StatusCode.OK, "批量导入成功");
    }
}
```

要测试就得先写启动类。搜索服务没有数据库，启动时要禁用数据源自动配置；再开启 ES 仓库扫描和 Feign 客户端扫描：

```java
@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
@EnableElasticsearchRepositories(basePackages = "com.seckill.search.dao")
@EnableFeignClients(basePackages = "com.seckill.goods.feign")
public class SearchApplication {
    public static void main(String[] args) {
        SpringApplication.run(SearchApplication.class, args);
    }
}
```

启动后请求 18082 端口的这个接口，页面会一直转圈——正在分页加载数据、批量写入索引库。导入成功后刷新 ES 界面（192.168.211.137:9200），立刻多了 goodsindex，能看到索引结构信息和数据浏览：goodsindex 类似数据库，里面的 skuinfo 类型类似表，列和数据展示都没有问题，bttime 也转换成了目标格式。这个批量导入在工作中只会用到一次，海量数据不可能天天导。

### 增量导入：一个 modify 方法搞定增删改

增量导入和批量导入的区别：批量导入导入所有数据，一般只用于数据初始化；增量导入是数据库数据发生变化时只更新指定数据——增加一条商品就往索引库导入那一条，某个商品更新了索引库跟着更新，删除了索引库删掉那一条即可。

实现上只需要写一个方法，用一个 type 区分操作类型：添加 type=1、修改 type=2、删除 type=3，参数里把要操作的对象转成 SkuInfo 传过来：

```java
@Override
public void modify(Integer type, SkuInfo skuInfo) {
    if (type == 1 || type == 2) {
        // 添加和修改本质都是增加，ES修改会先删旧数据再增加新数据
        skuInfoMapper.save(skuInfo);
    } else {
        // type=3 删除
        skuInfoMapper.deleteById(skuInfo.getId());
    }
}
```

控制层对应加一个接口，主要供内部使用：

```java
@PutMapping(value = "/modify/{type}")
public Result modify(@PathVariable Integer type, @RequestBody SkuInfo skuInfo) {
    skuInfoService.modify(type, skuInfo);
    return new Result(true, StatusCode.OK, "操作成功");
}
```

其他微服务要用它，就把方法同步到 seckill-search 对应 API 的 SkuInfoFeign 里（`@FeignClient("seckill-search")`），注意路径前面要加上 search 前缀。

## 按时间搜索秒杀商品：命名规则方法与两个坑

### 业务层：按 bttime 分页搜索

看京东秒杀页面：上面有一排时间段，每次点击会加载对应时间段的秒杀商品数据，所以秒杀商品的搜索一般具备按时间搜索的条件。ES 里 bttime 已经精确到年月日时分秒，页面每次点击把时间传过来，直接用它查询即可。搜索不是平白无故地搜，还要有分页——双 11、双 12 那种量级必须分页。

Service 定义搜索方法，将来可能传各种条件，封装成万能对象 Map：

```java
Page<SkuInfo> searchPage(Map<String, String> searchMap);
```

实现里先取页码：写一个 pageConverter 方法从 searchMap 里 get pageNum 转 Integer，转换异常（传的不是数字）就直接返回第一页。再取时间参数，参数名跟文档保持一致叫 startTime。然后根据 bttime 实现分页搜索，直接调 DAO，方法按 Spring Data ES 的命名规则定义，参数有三样：条件对应的值（startTime，即 bttime）、每页条数固定写死 20、分页对象 `PageRequest.of(pageNum - 1, 20)`——注意 PageRequest 最基础的页码从 0 开始，而页面从 1 开始，所以要减一：

```java
// DAO：按命名规则生成按时间分页查询，条件参数在前，Pageable在后
Page<SkuInfo> findByBtime(String startTime, Pageable pageable);
```

### 测试踩的两个坑

控制层暴露搜索接口，`@RequestParam(required = false)` 接收搜索数据，不传也不报错：

```java
@GetMapping(value = "/search")
public Page<SkuInfo> search(@RequestParam(required = false) Map<String, String> searchMap) {
    return skuInfoService.searchPage(searchMap);
}
```

第一次测试就报错了，问题出在分页：DAO 方法里参数顺序写反了，找不到分页信息。把两个参数对调——先写条件参数、后写分页对象——重启后解决。以后遇到这类问题，基本都是参数顺序导致的。

第二个坑在导入侧：检查 ES 数据时发现开始时间设置时误用了 endTime，改成 getBtTime 后重新执行一遍批量导入，索引里的 beginTime 才跟着修正。

修正后从 ES 里按时间排序找一个有差异的时间，请求 `/search?startTime=…`：默认第一页，某个时间只返回一条数据，结果正确；再换一个有几十条记录的时间，加参数 `pageNum=2`，返回的商品从第一页那条「…20」变成了「…32」，分页搜索完成。

## 详情页静态化：Freemarker 配置、通用工具与生成实现

### 为什么静态化

活动期间热卖商品详情页的访问频率非常高，直接查数据库会带来巨大压力甚至崩溃。详情页的主要内容是商品介绍、标题、图片、价格、数量等，除了数量可能变化，其他几乎不变。针对这种变更频率很低的数据可以优化：放 Redis 缓存或做成静态页；由于数据量非常庞大，不建议放缓存，建议做成静态页，用的技术主要是 Freemarker。

搭建静态化工程，引入 Freemarker 核心依赖，再配置几个关键项：

```yaml
spring:
  freemarker:
    template-loader-path: classpath:/templates  # 模板存放位置
    suffix: .ftl                                # 模板后缀
    cache: false                                # 模板不缓存，改动立刻生效
```

模板统一放 templates 目录，页面长什么样由模板决定；cache 关闭意味着模板每次修改立刻加载，不用缓存旧数据；模板后缀是 .ftl——新建文件时后缀是 .html 不算标准模板，改成 .ftl 才行。生成的静态文件存到哪里也要配置：自定义一个 htmlPath 配置项，文件生成后写到磁盘的 html 目录，代码里通过配置注入，不写死。

### 通用生成工具 BaseProcess

新建 BaseProcess 类实现通用生成流程，注入 Freemarker 的 Configuration 对象。生成一个静态页要四样东西：模板名称、填充模板的数据模型、生成静态页的存储路径、生成的文件名。这四点可以通通存进数据模型——建议用 Map，key 分别是 templateName、path、name，每次调用只要把数据模型传过来：

```java
public void writerPage(Map<String, Object> dataMap) throws Exception {
    // 从数据模型取模板名称、路径、文件名
    String templateName = dataMap.get("templateName").toString();
    String path = dataMap.get("path").toString();
    String name = dataMap.get("name").toString();
    // 根据模板名称获取模板对象
    Template template = configuration.getTemplate(templateName);
    // 生成文件并转成字符串
    String content = FreeMarkerTemplateUtils.processTemplateIntoString(template, dataMap);
    // 输出到磁盘，路径不存在则创建
    File file = new File(path);
    if (!file.exists()) {
        file.mkdirs();
    }
    FileUtils.writeStringToFile(new File(path, name), content);
}
```

模板里的占位符在渲染时被数据替换，比如一个最简的 items.ftl：

```html
<body>
    今天去${a}
</body>
```

`FreeMarkerTemplateUtils.processTemplateIntoString(template, dataMap)` 的第一个参数是模板对象，第二个是数据模型（整个 dataMap），返回值就是渲染好的文件内容字符串；FileUtils.writeStringToFile 把字符串写入文件，第一个参数是文件（路径加文件名），第二个是内容。

### 业务实现与 Feign 暴露

seckill-page 工程里建 SkuPageService 接口，定义生成静态页方法 `void itemPage(Map<String, Object> dataMap)`；实现类交给容器管理并继承 BaseProcess——生成静态页的工具已经写好，继承就能用，itemPage 里直接调 writerPage(dataMap) 即可。

控制器 SkuPageController 用 `@RequestMapping("/page")` 加跨域注解，生成静态页要接收数据，所以用 PostMapping：

```java
@RestController
@RequestMapping(value = "/page")
@CrossOrigin
public class SkuPageController {
    @Autowired
    private SkuPageService skuPageService;
    @Value("${htmlPath}")
    private String path;

    @PostMapping(value = "/html")
    public Result html(@RequestBody Sku sku) throws Exception {
        Map<String, Object> dataMap = new HashMap<>();
        dataMap.put("templateName", "items.ftl");        // 模板名称
        dataMap.put("path", path);                       // 输出路径，配置注入不写死
        dataMap.put("name", sku.getId() + ".html");      // 文件名：商品ID.html
        dataMap.put("address", "北京");                   // 自定义数据模型示例
        skuPageService.itemPage(dataMap);
        return new Result(true, StatusCode.OK, "生成静态页成功");
    }
}
```

数据模型里的内容按业务流程装：模板名称当前只有 items.ftl；文件名一般是商品 ID.html 的模式，用 sku.getId() 拼 .html 组装；路径从配置注入。调用完成后抛异常出去，其他微服务要调用时，在 Feign 接口里编写 `@FeignClient(name = "seckill-page")` 的 SkuPageFeign，把 `POST /page/html` 这个方法暴露出去即可。

## 小结

这一篇把索引库的数据链路全部打通：SkuInfo 用 @Document/@Id/@Field 把 goodsindex 索引的映射定下来，名称分词、分类品牌整词、时间转字符串的取舍各有理由；批量导入四步走，只在初始化跑一次，增量导入一个 modify 方法按 type 分流，修改在 ES 里本质是删旧增新；搜索靠 Spring Data 命名规则方法 findByBtime，踩过参数顺序和字段误用 endTime 两个坑后，按时间加分页的查询稳定可用；详情页静态化用 Freemarker 把四要素装进数据模型，BaseProcess 一套通用流程配合配置化的输出路径，商品 ID.html 直接落盘。下一篇继续在缓存与热点隔离上做文章。
