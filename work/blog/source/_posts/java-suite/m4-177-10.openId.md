# 微信 openId 机制与获取代码实现：jscode2session 四个参数、openid 与 unionid 的区别

立可得项目第五章进入订单支付与出货控制，动手支付之前先要解决一个前提问题：后端怎么知道一条请求来自哪个用户。微信小程序体系给出的答案是 openId。这一篇先把 openId 的概念、官方 jscode2session 接口的入参与返回讲清楚，顺带厘清容易混淆的 unionid，最后落到后端获取 openId 的完整代码实现：Consul 配置、WXConfig 配置类、WxService 业务封装与 OrderController 对外接口。

## 先给结论

- openId 是微信为每个用户在"当前公众号或小程序"下生成的唯一标识，本质上就是项目里的用户 ID：立可得 2.0 的订单查询功能，下单时把 openId 存入订单表专设的字段，查询时按 openId 过滤。
- 获取走微信官方 HTTP 接口 sns/jscode2session，GET 方式传四个参数：appid（小程序唯一标识）、secret（小程序密钥）、js_code（前端 wx.login 拿到的临时登录码）、grant_type（固定填 authorization_code）。
- 接口正常返回 openid、session_key、unionid 三个字段，立可得只取 openid；出错时返回 errcode 和 errmsg，例如 errcode 40029、errmsg "invalid code"。
- openid 与 unionid 的区别：openid 在"同一用户 + 同一应用"内唯一，换一个小程序或公众号就变成另一个号；unionid 在整个微信开放平台下唯一，多端要识别同一用户时必须用它。长度也不同：openid 28 位，unionid 29 位。
- 代码实现分四步：Consul 配置中心加 wx 配置项，WXConfig 绑定 appId 与 appSecret，WxServiceImpl 用 RestTemplate 调接口并解析 JSON，OrderController 暴露 /order/openid 接口。
- 这套获取 openId 的逻辑与具体业务无关，属于完全通用的代码，课程放在基础代码中直接提供，做其他微信小程序项目可以原样搬走。

## openId 是什么：小程序里的用户 ID

openId 是用户在当前微信公众号或小程序下的一个唯一标识，由微信平台生成。说白了，它就是项目体系里的用户 ID。

拿立可得 2.0 的订单查询功能来说：查订单总要有一个用户维度，这个用户 ID 就是 openId。用户下单时，前端把 openId 带过来，后端存进订单表——订单表上专门有一个 openId 字段；查询时按 openId 来查即可，链路就这么简单。

既然 openId 由微信生成，后端不能自己造，得调微信官方提供的 HTTP 接口去换。

## jscode2session 接口：四个入参、两类返回

官方接口地址，GET 方式传参：

```
https://api.weixin.qq.com/sns/jscode2session?appid=APPID&secret=SECRET&js_code=JSCODE&grant_type=authorization_code
```

四个请求参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| appid | 是 | 小程序唯一标识，申请小程序时微信分配的编号 |
| secret | 是 | 小程序密钥，用于验证调用方合法性 |
| js_code | 是 | 登录时获取的临时 code，前端开发小程序时调用 wx.login 获得 |
| grant_type | 是 | 授权方式，固定填写 authorization_code |

四个参数里唯一"变化"的是 js_code：前端每次通过 wx.login 拿到一个临时码，随请求传给后端，后端拿它去微信换取当前用户的 openId。appid 和 secret 是小程序的固定身份，secret 的存在是因为光有编号还不够，得有密钥来验证合法性。

返回分两种情况。正常时返回 JSON 数据包，包含 openid、session_key、unionid 三个字段：

```json
{
  "openid": "OPENID",
  "session_key": "SESSIONKEY",
  "unionid": "UNIONID"
}
```

session_key 是会话密钥，unionid 是开放平台标识，立可得这两个都没有用到，唯一取走的是 openid。出错时返回错误码与错误信息：

```json
{
  "errcode": 40029,
  "errmsg": "invalid code"
}
```

另外，unionid 的返回是有条件的，满足一定条件时才返回，具体看官方文档的 UnionID 机制说明即可，课程里不作重点展开。

## openid 与 unionid：学号和身份证的区别

两者的官方定位：

- openid：用户唯一标识，完整说法是"用户在当前的公众号或小程序中的唯一标识"。同一个用户在这个小程序里是一个号，跳到另一个小程序或公众号就是另一个号——类比学号、工号，只在特定范围内唯一。
- unionid：用户在整个开放平台的唯一标识。不管在哪个平台下都是同一个号——类比身份证号。

长度也不一样：openid 是 28 位，unionid 是 29 位。

由此得出选型结论：只开发一端（一个小程序或一个公众号），直接用 openid 就够了，不需要 unionid；如果要开发多个微信小程序或公众号，并且希望它们能识别出"这是同一个用户"，就必须用 unionid 做打通。立可得只有一个小程序端，所以用的是 openid。

## 代码实现：配置、Service、Controller 三层落地

实现按四步走：配置中心加配置，配置类读取，Service 封装获取逻辑，Controller 暴露接口。

第一步，在 Consul 配置中心的 wx 配置项里加上小程序的 appID 和 appSecret（连同服务地址等配置一起管理），敏感信息不写死在代码里。

第二步，写配置类绑定这两个值：

```java
@Component
@ConfigurationProperties("wx")
public class WXConfig {
    private String appId;
    private String appSecret;
}
```

第三步，定义接口与实现。接口只有一个方法，入参是 jsCode，返回 String：

```java
public interface WxService {
    String getOpenId(String jsCode);
}
```

实现类注入 WXConfig，拼接出上一节的接口地址，再用 Spring 里常用的 RestTemplate 发 GET 请求，接收返回的 JSON 字符串：

```java
@Service
public class WxServiceImpl implements WxService {

    @Autowired
    private WXConfig wxConfig;

    @Override
    public String getOpenId(String jsCode) {
        String getOpenIdUrl = "https://api.weixin.qq.com/sns/jscode2session?appid="
                + wxConfig.getAppId()
                + "&secret=" + wxConfig.getAppSecret()
                + "&js_code=" + jsCode
                + "&grant_type=authorization_code";
        RestTemplate restTemplate = new RestTemplate();
        String respResult = restTemplate.getForObject(getOpenIdUrl, String.class);
        log.info("weixin pay result: " + respResult);
        if (Strings.isNullOrEmpty(respResult)) return "";
        try {
            String errorCode = JsonUtil.getValueByNodeName("errcode", respResult);
            if (!Strings.isNullOrEmpty(errorCode)) {
                int errorCodeInt = Integer.valueOf(errorCode).intValue();
                if (errorCodeInt != 0) return "";
            }
            return JsonUtil.getValueByNodeName("openid", respResult);
        } catch (Exception ex) {
            log.error("获取openid失败", ex);
            return "";
        }
    }
}
```

解析逻辑与返回格式一一对应：返回为空直接返回空串；能读到 errcode（说明微信侧报错了）且转成 int 后不为 0，同样返回空串；都正常才提取 openid 返回。返回包里虽有三个字段，但业务只认 openid，所以只提取这一个，异常统一捕获并记日志。

第四步，在 http.controller 包下创建 OrderController，供前端调用：

```java
@RestController
@RequestMapping("/order")
public class OrderController {

    @Autowired
    private WxService wxService;

    /**
     * 获取 openId
     */
    @GetMapping("/openid")
    public String getOpenId(String jsCode) {
        return wxService.getOpenId(jsCode);
    }
}
```

前端把 wx.login 拿到的 js_code 传到这个接口，后端转发给 WxService，返回 openId。整条链路是：wx.login 产码 → /order/openid → jscode2session → openid 入库。

值得一提，这段业务逻辑课程没有要求手写——它已经在基础代码中提供。原因是它与业务完全无关、极度通用：之后做任何微信小程序开发都必然要用 openId，这套逻辑可以直接搬过去复用。

## 小结

- openId 是用户在当前公众号/小程序下的唯一标识，立可得把它当作用户 ID 用：下单存入订单表，查询按它过滤。
- 获取靠官方 jscode2session 接口，四个 GET 参数为 appid、secret、js_code、grant_type，其中 js_code 来自前端 wx.login 的临时码。
- 正常返回 openid、session_key、unionid；本项目只用 openid。unionid 用于多端识别同一用户，单端开发用不上。
- 实现链路由四块组成：Consul 配置中心管 appId/appSecret，WXConfig 绑定配置，WxServiceImpl 拼 URL、RestTemplate 调用并解析 JSON，OrderController 以 /order/openid 对外暴露。
- 这段代码与业务解耦、完全通用，可作为固定模块在后续微信项目中直接复用。
