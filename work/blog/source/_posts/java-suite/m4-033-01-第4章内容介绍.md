# 订单服务开篇：订单中心数据模型与百度地图入门实战

品达物流 TMS 项目进入第四章——订单中心服务开发，对应的 Maven 工程是 pd-oms。这一章的落脚点很明确：把"下单之后"的服务端逻辑补齐，也就是订单距离怎么算、订单价格怎么算。距离依赖百度地图开放平台，价格依赖规则引擎 Drools。本篇先讲清数据模型与业务需求，再把百度地图的账号注册、AK 申请与前四个入门案例跑通。

## 先给结论

- 本章对应的 Maven 工程是 pd-oms，订单的增删改查等基础维护代码初始工程已经提供，要补的是两块计算：新增订单时设置订单距离和订单价格。
- pd_oms 库共四张表：pd_order（订单）、pd_order_cargo（货物）、pd_order_location（订单位置）、rule（规则）。运单表 pd_transport_order 在后面的 pd_work 库里，货物表中的 transfer_order_id 只是逻辑外键。
- 页面上"填个地址点下单"很轻，服务端却要做三件计算：分配取件快递员（不能随机）、按收发件人地址算订单距离、按规则算订单价格。
- 价格规则按重量与距离分四档：1000 克以内一口价 20 元；超过 1000 克按距离分三档计续重，200 公里内每 1000 克 6 元、200~500 公里 9 元、500 公里以上 15 元，不足 1000 克的零头不计费。
- 百度地图开放平台按使用方式区分 AK 类型：网页 JS 方式选"浏览器端"，HTTP 调接口选"服务端"，本项目两种 AK 都要提前申请。
- 四个入门案例套路一致：引类库、放 div 容器、调 BMap API。地图展示、两点测距、点击取经纬度、圆形范围搜索，代码全部从官方示例改造，不需要背。

本章内容的主线如下：


## 数据模型：pd_oms 的四张表

订单中心微服务提供 TMS 中订单的维护功能：客户寄快递，在移动端下一个单，生成一条订单信息；下完单又可能取消，需要把订单删掉。这些操作都要有数据模型支撑，对应的就是 pd_oms 数据库，一共四张表。

第一张是订单表 pd_order，字段与订单本身相关：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | varchar(20) | 主键 |
| order_type | tinyint(2) | 订单类型，1 为同城订单，2 为跨城订单 |
| pickup_type | tinyint(2) | 取件类型，1 为网点自取，2 为上门取件 |
| create_time | datetime | 下单时间 |
| member_id | varchar(20) | 客户 ID |
| receiver_province_id / receiver_city_id / receiver_county_id | varchar(20) | 收件人省 / 市 / 区 ID |
| receiver_address / receiver_name / receiver_phone | varchar(255) | 收件人详细地址、姓名、电话 |
| sender_province_id / sender_city_id / sender_county_id | varchar(20) | 发件人省 / 市 / 区 ID |
| sender_address / sender_name / sender_phone | varchar(255) | 发件人详细地址、姓名、电话 |
| current_agency_id | varchar(20) | 订单当前所属网点 |
| 其余字段 | — | 付款方式、付款状态、金额、预计到达时间、订单距离、订单状态等 |

第二张是货物信息表 pd_order_cargo。订单主表只记录收发件人、流转状态这类信息，具体寄的是什么——一本书、衣服还是电子产品——放在这张表里：id 主键；order_id 外键关联订单；transfer_order_id 是运单 ID，注意它是逻辑外键，真正的运单表 pd_transport_order 不在当前库，而在后面要讲的 pd_work 数据库中；其余是 goods_type_id 货物类型 ID、货物名称、单位、货值、条码、数量、体积、重量，以及总重量、总体积等汇总字段。

第三张是订单位置信息表 pd_order_location：id 主键；order_id 外键关联订单；send_location 发货地址坐标、receive_location 收货地址坐标（经纬度）；send_agent_id 发货地址网点、receive_agent_id 收货地址网点；另有状态字段记录有效无效。这张表里的值都不是用户填的：用户只填"某街道某小区几单元"这样的地址，既不关心经纬度坐标，也不关心货由哪个网点负责。坐标和收发两侧负责的网点，都要由程序根据用户留下的地址动态计算出来再落库。之所以单独建这张表，是因为后续要靠它算订单距离，再由距离算订单价格。

第四张是规则表 rule：id 主键、content 规则内容、create_time 创建时间、last_modify_time 修改时间、rule_key 规则标识、version 规则版本。计算订单价格的规则内容动态存在这张表里，为第八节"实现动态规则"做铺垫。

## 业务需求与产品原型：前端越简单，后端越有得算

货物信息指用户所寄物品的相关信息，包括货物名称、货物单位、货物重量、所属订单 id、所属运单 id、货物数量等。产品原型对应寄件页上的"物品信息"入口：点击右侧箭头弹出弹窗，选择物品类型（文件、数码产品、服装等），填写物品名称，选择物品重量及其他信息，点保存后自动回显到寄件页。

订单是指客户下达运输业务的单个委托凭证。用户通过手机端品达速运 App 在寄件页输入寄件人、收件人信息，选择上门时间、物品重量、支付方式，点击"下单"按钮即可提交订单，成功后弹出"下单成功，请等待快递员上门取件！"。

从用户使用层面看，业务就是这么简单——寄件页录入信息、点下单。但服务端的业务逻辑并不轻，至少有三块计算藏在按钮后面：

1. 分配取件快递员：物流公司网点多、快递员多，具体派谁上门取件不能随机，需要服务端计算得出。
2. 计算订单距离：距离不是用户输入的，要通过寄件人地址和收件人地址动态计算。
3. 计算订单价格：依据货物重量和订单距离两个维度，按规则计算。

初始工程里订单基础的数据维护代码已经提供，直接使用即可；不完整的地方正是上面第 2、3 项——新增订单时需要设置的订单距离与订单价格。价格规则共四条：

| 条件 | 规则 |
| --- | --- |
| 货物 1000 克以内 | 不考虑距离，订单价格 20 元 |
| 1000 克以上，距离 200 公里以下 | 首重 1000 克 20 元，续重每增加 1000 克 6 元 |
| 1000 克以上，距离 200~500 公里 | 首重 1000 克 20 元，续重每增加 1000 克 9 元 |
| 1000 克以上，距离 500 公里以上 | 首重 1000 克 20 元，续重每增加 1000 克 15 元 |

举个例子：寄 3000 克货物，订单距离 150 公里，命中第二条规则。首重 1000 克收 20 元；超出部分 2000 克，按每 1000 克 6 元计 12 元，合计 32 元。如果寄的是 3500 克，多出的 500 克不足 1000 克，不计费。套路和打出租车一样：起步价包含起步量，超出部分按段累加，不满一段不加钱。这套规则后面会用规则引擎 Drools 落地，距离计算则要用到百度地图，也就是本文余下的部分。

## 百度地图开放平台：申请 AK 与四个入门案例

### 平台与 AK

百度地图开放平台面向政府、企业和互联网开发者开放地图服务能力，开发者市场占有率约 78%，累计服务移动应用超过 50 万，日均位置服务请求超 1200 万次，提供定位、地图、导航、轨迹、路况、路线规划、搜索七大服务能力。官网地址 lbsyun.baidu.com，站内还有基础服务、物流等行业特色应用、地图可视化以及行业解决方案。

按使用方式选产品：网页里嵌入地图用 JavaScript API；手机端分安卓与 iOS 两个阵营，各有对应 SDK；后台服务端通过 HTTP 方式调接口，则看 Web 服务 API，涵盖地点检索、路线规划、地理编码、逆地理编码、IP 定位等能力。此外还有百度鹰眼，用于路线分析和地理围栏。开发者平时重点看"开发文档"菜单和示例 demo，里面的文档相当于使用手册，参照例子改造成想要的效果即可。

使用前先注册百度账号并成为开发者，然后创建应用获取服务密钥 AK，流程四步：注册百度账号 → 申请成为百度开发者 → 获取服务密钥（AK） → 使用相关服务。登录后进控制台 → 应用管理 → 我的应用 → 创建应用：应用名称必填；应用类型按使用方式选——网页中通过 JS 方式使用百度地图就选"浏览器端"，通过 HTTP 方式调用就选"服务端"，另有微信小程序、Android SDK、iOS SDK 可选，类型不同，可选的服务列表也不同；勾选要启用的服务后提交。课程演示环境申请了三个 AK：两个服务端、一个浏览器端。AK 是很长的字符串，调用时随代码携带，相当于使用百度地图能力的认证凭证，AK 正确才能正常使用各项地图服务。本项目服务端要调接口、浏览器要嵌地图，所以两种 AK 都要提前申请好。

### 案例一：地图展示

网页使用百度地图的固定三步：引入类库、放置 div 容器、调用 API 设置地图特性。

```html
<script type="text/javascript" src="http://api.map.baidu.com/api?v=2.0&ak=您的浏览器端AK"></script>
<div id="allmap"></div>
<script type="text/javascript">
    var map = new BMap.Map("allmap");                       // 创建 Map 实例
    map.centerAndZoom(new BMap.Point(116.404, 39.915), 11); // 设置中心点坐标与地图级别
    map.addControl(new BMap.MapTypeControl({
        mapTypes: [BMAP_NORMAL_MAP, BMAP_HYBRID_MAP]        // 添加地图类型控件
    }));
    map.setCurrentCity("北京");                              // 设置地图显示的城市
    map.enableScrollWheelZoom(true);                        // 开启鼠标滚轮缩放
</script>
```

几个要点：

- script 引入类库时，ak= 后面换成自己申请的浏览器端 AK，类型不能选错。
- div 是地图展示容器，id 随意、唯一即可，new BMap.Map("allmap") 时对应上就行。
- BMap.Point 前一个参数是经度、后一个是纬度，116.404, 39.915 恰好是北京的经纬度，所以地图默认定位到北京。
- centerAndZoom 的第二个参数是地图级别，取值 1~19 共 19 级：数字越小显示范围越大，改成 1 就是世界地图；数字越大细节越多，19 已是极限。
- addControl 添加控件，MapTypeControl 对应地图右上角"地图 / 混合"切换按钮，可在标准地图与类似卫星地图之间切换；enableScrollWheelZoom 开启滚轮缩放，注释掉这一句，滚轮就不再缩放地图。
- 改 BMap.Point 的经纬度即可把中心设到任意位置，改成一组国外坐标，地图中心就移到国外去了。

把官方示例抄下来，本地建个 baidu map 目录存成 01.html，双击打开就能正常展示地图并用滚轮缩放。

### 案例二：计算两点距离

地图定位重庆（级别 12），new 两个坐标点 pointA、pointB（大渡口区、江北区各一点），调用 map.getDistance(pointA, pointB) 计算两点距离，返回单位是米，toFixed(2) 保留两位小数后用 alert 展示"从大渡口区到江北区的距离是……米"，演示结果约 16670.90 米。

计算之外还画了一条线把两点连起来：

```javascript
var polyline = new BMap.Polyline([pointA, pointB],
        {strokeColor: "blue", strokeWeight: 6, strokeOpacity: 0.5});
map.addOverlay(polyline);   // 向地图添加线覆盖物
```

Polyline 是覆盖物的一种：构造时把 pointA、pointB 放进去表示两点直线连接；strokeColor 是线色，strokeWeight 是线的粗细，strokeOpacity 是透明度——透明度改到 0.1 时线几乎看不清，改回 0.8 就清晰了。距离计算与画线并非必须同时出现：把 new Polyline 和 addOverlay 两句注释掉，getDistance 照样能算出距离。这段代码来自官方"地图示例 → 获取两点间的距离"。

### 案例三：点击地图获取经纬度

```javascript
var map = new BMap.Map("allmap");
map.centerAndZoom("北京", 12);
// 单击获取点击的经纬度
map.addEventListener("click", function (e) {
    alert(e.point.lng + "," + e.point.lat);
});
```

addEventListener 给地图挂事件监听器，监听 click 鼠标单击事件；回调参数 e 是事件对象，e.point 拿到点击位置的坐标点，lng 是经度、lat 是纬度，中间逗号分隔。在地图上任意单击就会弹出该点经纬度，例如 116.243212,40.024395；点击不同位置，数值随之变化——视图范围小时，经纬度前面几位基本不变，变的是小数部分。

### 案例四：圆形范围内关键字搜索

平时用地图 App 常搜"附近的餐馆、银行、超市"，这个功能用 API 这样实现：

```javascript
var map = new BMap.Map("allmap");
var mPoint = new BMap.Point(116.404, 39.915);   // 中心点：天安门
map.enableScrollWheelZoom();
map.centerAndZoom(mPoint, 15);
var circle = new BMap.Circle(mPoint, 1000,
        {fillColor: "blue", strokeWeight: 1, fillOpacity: 0.3, strokeOpacity: 0.3});
map.addOverlay(circle);                         // 添加圆形覆盖物
var local = new BMap.LocalSearch(map, {renderOptions: {map: map, autoViewport: false}});
local.searchNearby("餐馆", mPoint, 1000);       // 搜索附近 1000 米内的餐馆
```

BMap.Circle 创建圆形覆盖物（半径 1000 米、蓝色半透明填充）并用 addOverlay 加到地图上；LocalSearch 创建本地检索实例；searchNearby 按关键字、中心点、半径做附近搜索。以天安门为中心演示，搜"餐馆"会列出周边一公里内的餐馆，可点击查看详情；把关键字改成"银行"，搜出的就是中国银行等网点。

两个容易混淆的点：

- 圆形覆盖物与搜索结果无关，纯粹为了界面效果直观。注释掉 circle 与 addOverlay，搜索照常进行。
- 把 searchNearby 的半径改成 2000 而圆形仍是 1000 时，圆外的结果照样会被搜出来，再次印证覆盖物只是装饰。搜索参数都可以按需求改。

## 小结

本章开篇把订单中心的账算清了三笔。数据模型上，pd_oms 四张表各司其职：订单、货物、位置、规则一一对应，坐标和负责网点都是程序算出来的落库值。业务上，用户侧一个下单按钮背后是快递员分配、距离计算、价格计算三块服务端逻辑，价格按首重续重分四档，不足 1000 克的零头不计费。工具上，百度地图开放平台以 AK 区分使用方式：浏览器端 AK 配 JavaScript API，服务端 AK 配 Web 服务 API；四个入门案例跑下来，"引类库、放容器、调 API"的三步套路已经能覆盖地图展示、两点测距、取点击经纬度、范围搜索这些能力。下一篇继续用案例五到案例七补齐路线、算路相关用法，然后封装工具类计算订单距离。
