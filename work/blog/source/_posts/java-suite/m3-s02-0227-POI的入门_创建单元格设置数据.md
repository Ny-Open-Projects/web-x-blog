# 给格子填数据：createRow、createCell 与 setCellValue 的下标规则

上一篇生成了一个只有空表单的 `test.xlsx`，这一篇解决下一步：往格子里写内容。动手前有两个规则必须先钉死，一是行和格子都从 0 开始编号，二是格子只能由行创建、行只能由表单创建，跳级操作没有对应的 API。这两个规则想当然，写出来的文件就会「差一格」。

## 先给结论

- 行由 `sheet.createRow(行索引)` 创建，格子由 `row.createCell(列索引)` 创建，两个索引都从 0 开始。
- 「第 3 行第 3 列」对应索引 2、2，也就是 Excel 里的 C3 单元格。
- `setCellValue` 是重载方法，字符串、数字、布尔、日期各有对应版本，POI 会按类型写入。
- HSSF 与 XSSF 在行、格子这层的代码完全一样，差异只在 `new` 哪个工作簿实现。
- 内容写进的是内存里的工作簿，最后必须 `wb.write` 落盘，否则文件里什么都没有。

## 一、从表单到格子：一条逐级往下的定位链

写入内容的动作拆成三步：定位行、定位格子、写值。加上工作簿和表单的创建，完整代码如下：

```java
package com.example.poi.test;

import org.apache.poi.ss.usermodel.Cell;
import org.apache.poi.ss.usermodel.Row;
import org.apache.poi.ss.usermodel.Sheet;
import org.apache.poi.ss.usermodel.Workbook;
import org.apache.poi.xssf.usermodel.XSSFWorkbook;

import java.io.FileOutputStream;

/**
 * 创建单元格写入内容
 */
public class PoiTest02 {
    public static void main(String[] args) throws Exception {
        //1.创建工作簿
        Workbook wb = new XSSFWorkbook(); //2007 版本
        //2.创建表单 sheet
        Sheet sheet = wb.createSheet("test");
        //3.创建行对象，参数是行索引，从 0 开始
        Row row = sheet.createRow(2);
        //4.创建单元格对象，参数是列索引，从 0 开始
        Cell cell = row.createCell(2);
        //5.向单元格写入内容
        cell.setCellValue("Hello POI");
        //6.文件流并写出
        FileOutputStream fos = new FileOutputStream("E:\\excel\\poi\\test1.xlsx");
        wb.write(fos);
        fos.close();
    }
}
```

```mermaid

    A["Workbook 工作簿"] --> B["Sheet 表单 test"]
    B --> C["createRow 2 行索引 2 即第 3 行"]
    C --> D["createCell 2 列索引 2 即第 3 列"]
    D --> E["setCellValue 写入文本"]
    E --> F["Excel 中的 C3 单元格"]
```

这张图讲的是从工作簿到具体格子的定位链。运行后打开 `test1.xlsx`，C3 位置就是写入的那句话，与手工在 Excel 里点选第 3 行第 3 列输入内容的效果完全一致。

**下标从 0 起，是这段代码最容易出错的地方。** 想写「第 3 行」就传 2，因为 0、1、2 三个下标对应前三行；列同理。手工操作时数的是「第几」，代码里数的是「偏移量」，两者差 1。

**行和格子的创建权在上级对象手里。** `createRow` 是 `Sheet` 的方法，`createCell` 是 `Row` 的方法，没有 `sheet.createCell` 这种跨级调用。这个设计把 Excel 的物理结构直接编码进了 API，写代码时想跳级都跳不了。

## 二、setCellValue 的各个重载：格子里的数据类型

`setCellValue` 不只收字符串，它针对 Excel 支持的数据类型提供了一组重载：

```java
Cell cell = row.createCell(0);
cell.setCellValue("张三");        //字符串
cell.setCellValue(18);            //数字
cell.setCellValue(true);          //布尔
cell.setCellValue(new Date());    //日期
```

有一个类型细节值得提前记住：**Excel 内部的数字统一按 double 存储，日期本质也是数字**（某个基准时间偏移的天数），所以写 `18` 进去，POI 内部按 `18.0` 处理；写 `new Date()` 进去，最终落盘的也是一个数值加一个日期格式标记。这个设计在读取方向会还回来：下一篇解析 Excel 时，日期单元格的类型同样是「数字」，需要借助工具类二次判断。

另一个经验是，业务代码里最常见的是把对象字段转成字符串再写入，真实导出工具类里就是这样做的：

```java
// 真实代码：按注解声明的列序号把字段值写入对应格子
for (Field field : fields) {
    if (field.isAnnotationPresent(ExcelAttribute.class)) {
        ExcelAttribute ea = field.getAnnotation(ExcelAttribute.class);
        if (i == ea.sort()) {
            cell.setCellValue(field.get(t).toString());
        }
    }
}
```

这段来自课程资料包里的导出工具类：先按列索引 `i` 创建格子，再遍历实体类字段，字段上的 `@ExcelAttribute(sort = n)` 声明它属于第几列，匹配上就把字段值 `toString` 后写入。行列下标、字段、内容三者在循环里对齐，正是 `createCell` 与 `setCellValue` 在生产代码里的典型组合。

## 三、版本差异只在工作簿那一行

行与格子这层的 API，HSSF 和 XSSF 完全一致，`Row`、`Cell` 都是 `ss.usermodel` 包下的通用接口。把第一行换成 `Workbook wb = new HSSFWorkbook();`，其余代码一字不改，产出的就是 `.xls` 老格式文件。课堂演示时从上一案例复制代码，就出现过工作簿实现留着 `HSSFWorkbook`、目标文件后缀却还是 `.xlsx` 的情况：程序正常运行不报错，但打开文件时 Excel 会提示格式与扩展名不符。格式、后缀、实现类三者要对齐。

## 常见误区

- **下标当成「第几个」来传。** 想写第 3 行第 3 列却传 `createRow(3)`、`createCell(3)`，内容落到了第 4 行第 4 列的 D4。记住索引是偏移量，从 0 开始。
- **对同一个行索引重复 `createRow`。** `createRow(2)` 调两次，第二次返回的新行会替换内存里的旧行，之前写进去的内容全部丢失。写多行数据时用自增变量做索引，不要写死。
- **工作簿实现与文件后缀不匹配。** `HSSFWorkbook` 配 `.xlsx` 后缀不报错但有格式告警，`XSSFWorkbook` 配 `.xls` 直接打不开。复制旧案例改造时，先检查第一行 `new` 的是什么。
- **内存里写了、忘了落盘。** `setCellValue` 只改内存对象，没有 `wb.write` 和关流这一步，磁盘上的文件不会有任何新内容。排查「代码跑了文件没变」时先看写出那几行还在不在。

## 面试可能被问到的问题

1. 面试官追问：「POI 里行列的索引从几开始？」
   答：都从 0 开始。`sheet.createRow(2)` 创建的是第 3 行，`row.createCell(2)` 创建的是第 3 列的格子，两者组合对应 Excel 的 C3。界面上的「第几」和代码里的索引永远差 1。

2. 面试官追问：「setCellValue 支持哪些参数类型？」
   答：主要重载包括字符串、double 数字、布尔、`Date` 与 `Calendar` 日期、`RichTextString` 富文本。Excel 内部数字按 double 存储，日期也是数字加格式标记，所以数字与日期在底层是同一类存储，读取时需要按格式再区分。

3. 面试官追问：「用 HSSF 和 XSSF 写单元格的代码有区别吗？」
   答：没有区别。`Row`、`Cell`、`setCellValue` 都是 `ss.usermodel` 包的通用接口，两套实现只在创建工作簿那一行不同，`new HSSFWorkbook()` 对应 xls，`new XSSFWorkbook()` 对应 xlsx，这也是推荐面向接口编程的原因。

4. 面试官追问：「同一个索引调用两次 createRow 会发生什么？」
   答：第二次创建的行对象会替换该索引上的旧行，先前写入该行的内容丢失。批量写入时应当用递增索引逐行创建，或者先用 `getRow` 判断行是否存在再决定创建还是复用。

5. 面试官追问：「代码执行完没有异常，但 Excel 文件里没有内容，可能是什么原因？」
   答：最常见的是忘了调用 `wb.write` 写出，或者写出后流没有关闭导致缓冲区数据没落盘；其次是写错了目标路径，查看的是另一个旧文件；还有可能是内容写进了重复创建被覆盖的行。排查顺序是先确认写出代码，再核对路径与索引。
