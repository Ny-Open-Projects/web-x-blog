# 按设备指标查询指标值序列：空缺数据补全与看板预览收官

自定义指标看板的前置工作已经就绪：数值型指标列表、按指标查设备列表都能查了。本篇收尾三件事：把按设备指标查询指标值序列的 first 语句封装成业务方法；处理查询结果里大量 null 的空缺补全；再把整条链路包成看板的报表数据预览接口，给前端返回画曲线需要的完整格式。

## 先给结论

- 指标值可能是小数，新建 TrendPoint2（double 版）与整型的 TrendPoint 区分开，序列查询返回 List<TrendPoint2>。
- getQuotaTrend 用 StringBuilder 拼接 first 查询，type 决定切割粒度：一小时按 1m、一天按 1h、七天按 1d。
- 查不到数据的时间分组值为 null。不能按 0 补：没报数据和 0 度是两个概念。规则是 null 接上一个不为 null 的值；序列开头就是 null 时，用第一个不为 null 的值填充；整条序列全 null 才退化为 0。
- 看板预览的前端格式是 xdata 加 series，series 里一个对象一条线，内含 name（设备编号）与 data（每点的值），外层再带面板名称。
- 预览接口 POST /preview 接收一个 VO 对象（指标 ID、设备列表、时间类型、起止时间），x 轴在返回前复用 formatTime 格式化。

## 指标值序列：TrendPoint2 与 getQuotaTrend

按设备指标查询指标值序列，是自定义指标看板里最核心的一块。先解决封装类型：之前折线图用的 TrendPoint，值是整型，但指标值完全可能是浮点，所以复制一份建 TrendPoint2，把值的类型改成 double。整数用 TrendPoint，小数用 TrendPoint2，以此区分。

在 ReportService 里定义方法，返回 List<TrendPoint2>，五个参数：开始时间、结束时间、指标 ID、设备 ID 和时间选项 type（1 一小时、2 一天、3 七天）。实现就是对 first 语句的封装，依然用 StringBuilder，把语句拆成几段：固定开头、带起止时间的 where、指标 ID 条件、设备 ID 条件，group by 按 type 分支：

```java
@Override
public List<TrendPoint2> getQuotaTrend(String startTime, String endTime, String quotaId, String deviceId, int type) {
    StringBuilder ql = new StringBuilder("select first(value) as pointValue from quota ");
    ql.append("where time>='" + startTime + "' and time<='" + endTime + "' ");
    ql.append("and quotaId='" + quotaId + "' ");
    ql.append("and deviceId='" + deviceId + "' ");
    if (type == 1) {
        ql.append("group by time(1m)");
    } else if (type == 2) {
        ql.append("group by time(1h)");
    } else if (type == 3) {
        ql.append("group by time(1d)");
    }
    List<TrendPoint2> trendPointList = influxRepository.query(ql.toString(), TrendPoint2.class);
    return trendPointList;
}
```

type 与切割粒度的对应关系：选一小时，按每分钟切割，group by time(1m)；选一天，按小时切割，time(1h)；选七天，按天分割，time(1d)。

单元测试放 TestReport 里，新建 testQuotaTrend：时间传 2020-09-01 00:00:00 到 2020-09-30 23:59:59，前端实际传的就是带时分秒的完整时间；指标 ID 传 1，设备 ID 传 100001，type 传 3 按天统计；循环用 JsonUtil.serialize 把每个点打出来。运行结果和命令行一致：时间都打出来了，有值的部分如 32.0，已经是浮点；中间大量 null，那些天确实没有报文，null 不是异常，是空缺。

## 空缺数据补全：replenish 的两条规则

null 的问题在于线没法画。直觉的做法是按 0 补，这不合理：温度指标一直在 30 度左右，某个节点没数据被画成 0，下一个节点又跳回 30，曲线表现为剧烈波动，但实际温度根本没变。没报数据不等于 0 度，两个概念不能混。

补全规则有两条：某节点值为 null，就设置为上一个不为 null 的值，比如 22 号是 32、23 号为 null，23 号就补成 32；序列第一个值就是 null，则从开头到第一个不为 null 的值之间的所有 null，都用第一个不为 null 的值填充，示例里就是全部补成 32。还有一种极端情况：找一圈全为 null，只能整个序列都按 0 处理，画出来是一条没有任何变化的直线，实际中极少出现。

写一个私有方法 replenish（填充），传入带 null 的集合，返回不带 null 的集合：

```java
private List<TrendPoint2> replenish(List<TrendPoint2> trendPoint2List) {
    Double previousValue = null; // 上一个不为 null 的值
    for (TrendPoint2 trendPoint2 : trendPoint2List) {
        if (trendPoint2.getPointValue() != null) {
            previousValue = trendPoint2.getPointValue();
            break;
        }
    }
    if (previousValue == null) { // 整条序列全为 null 的极端情况
        previousValue = 0.0;
    }
    for (TrendPoint2 trendPoint2 : trendPoint2List) {
        if (trendPoint2.getPointValue() == null) {
            trendPoint2.setPointValue(previousValue);
        }
        previousValue = trendPoint2.getPointValue();
    }
    return trendPoint2List;
}
```

逻辑分两段：先循环找序列里第一个不为 null 的值，赋给 previousValue 后立即跳出循环；找不到（全 null）就置 0 兜底。主循环里当前值为 null 就用 previousValue 覆盖，并且每轮都把 previousValue 更新为当前值，保证 null 永远接到"上一个不为 null 的值"上。方法写完后在 getQuotaTrend 的返回处包一层：return replenish(trendPointList)。再跑测试：开头的 null 全部变成 32，中间的空缺接上前值，27 号之后全部补成最后一个值 23，与预期完全一致，补全逻辑没有问题。

## 报表数据预览：VO 封装与 preview 接口

业务方法完成后，最后一步是报表数据预览，给前端返回它画曲线需要的格式。整体结构是：xdata 是横轴，内容可能是"x月x日"、小时或分钟，取决于时间选项；series 是所有的线，一个对象一条线，每个对象有 name 和 data 两个属性，name 用设备编号，data 是这条线在每个时间点的值；最外层还有一个 name，是面板名称。

VO 封装本着由内到外的顺序：先建里面那条线的结构 BoardQuotaData，加 @Data、实现 Serializable，属性是 name（设备编号）和 data（List<Double> 的值序列）；再建外层 BoardQuotaVO，属性为 xdata（List<String>）、series（List<BoardQuotaData>）和 name（面板名称）。

业务方法 getBoardData 定义在报表服务里，参数是指标 ID、设备 ID 列表、开始时间、结束时间和时间选项。实现先做参数校验：指标 ID 为 null，或设备列表为 null、size 为 0，直接返回一个空对象，没必要往下走。通过校验后循环每个设备，调用 getQuotaTrend 拿到该设备的指标趋势；series 在上方初始化为空集合，每轮往里加一个 BoardQuotaData。x 轴从趋势集合里用 stream 提取 time，但每次查询的 x 轴都一样，循环里重复设置效率低，加一个 getXData() 为 null 的判断，只在第一轮设置：

```java
@Override
public BoardQuotaVO getBoardData(String quotaId, List<String> deviceIds, String startTime, String endTime, Integer type) {
    if (quotaId == null || deviceIds == null || deviceIds.size() == 0) {
        return new BoardQuotaVO();
    }
    BoardQuotaVO boardQuotaVO = new BoardQuotaVO();
    boardQuotaVO.setSeries(Lists.newArrayList());
    for (String deviceId : deviceIds) {
        List<TrendPoint2> trendPointList = getQuotaTrend(startTime, endTime, quotaId, deviceId, type);
        if (boardQuotaVO.getXData() == null) {
            boardQuotaVO.setXData(trendPointList.stream().map(TrendPoint2::getTime).collect(Collectors.toList()));
        }
        BoardQuotaData boardQuotaData = new BoardQuotaData();
        boardQuotaData.setName(deviceId);
        boardQuotaData.setData(trendPointList.stream().map(TrendPoint2::getPointValue).collect(Collectors.toList()));
        boardQuotaVO.getSeries().add(boardQuotaData);
    }
    return boardQuotaVO;
}
```

每条线的 name 直接用设备编号，data 用 stream 提出每点的 pointValue，加进 series，最后返回整个对象。

Controller 之前先看 API 定义：预览面板的地址是 preview，提交方式 POST，请求参数是一个对象，包含指标 ID、设备 ID 列表、type、start 和 end。这个对象目前没有，先建 PreviewVO（加 @Data、实现 Serializable），字段与 API 一一对应。Controller 用 @PostMapping("/preview") 加 @RequestBody 接收，方法体从对象里取出各参数调 getBoardData：

```java
@PostMapping("/preview")
public BoardQuotaVO getPreviewData(@RequestBody PreviewVO previewVO) {
    return reportService.getBoardData(previewVO.getQuotaId(), previewVO.getDeviceIdList(),
            previewVO.getStart(), previewVO.getEnd(), previewVO.getType());
}
```

用 VS Code 的"预览面板"脚本测试：指标 ID 传 1，设备传 100001 到 100005 五台，type 传 3，时间 09-20 到 09-27。返回里 xdata 有了，series 里正好五条线。但 x 轴还是 ISO 长串，直接显示到界面上太乱，复用之前写好的 formatTime：先构建一个新的 x 轴集合，循环原 xdata 的每个时间串，用 formatTime 转换后放进新集合，循环完再 setXData 设置回去：

```java
List<String> xData = Lists.newArrayList();
for (String x : boardQuotaVO.getXData()) {
    xData.add(formatTime(x, type));
}
boardQuotaVO.setXData(xData);
```

再测一次，x 轴已经完成时间格式化，显示成"x月x日"，整个预览面板功能到此全部完成。

## 小结

至此自定义指标看板的后端链路全部打通：getQuotaTrend 用 first 加 group by time，按设备指标取出每个时间点首次上报的值，TrendPoint2 承接浮点；replenish 按"null 接上一个不为 null 的值、开头用第一个非空值、全空才置 0"的规则补全空缺；getBoardData 循环设备拼出 xdata 与 series，PreviewVO 加 /preview 接口把数据交给前端，formatTime 顺手把 x 轴格式化到位。前端拿到这份数据，选好指标和设备，就能画出多台设备对比的指标趋势图。
