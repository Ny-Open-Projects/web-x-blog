# day8 开篇：数据可视化要解决什么，Superset 目标清单与路线

day7 收尾时平台的数据链路已经完整：设备快照实时进 Druid，接口一调就能吐出列表与曲线。但接口吐出来的终究是 JSON，让运营值班的人盯着响应报文看温度趋势并不现实。决策者要的是一张大屏：冷库温度曲线、告警分布、各仓库对比，一眼读完。day8 的数据可视化补的就是这一段，主角是 Apache Superset，开篇先把目标清单和技术路线列清楚。

## 先给结论

- day8 主角是 Apache Superset，一个开源的数据探索与可视化平台，使用路线三步走：接入数据源、创建图表、拼装看板。
- 目标共六条：维度与指标的含义和区别、数据可视化的意义、数据可视化的目标、表现方式、常用工具、掌握 Superset 的使用；前五条是铺垫，第六条是重点。
- 维度与指标是全天的概念地基，落到 Superset 图表配置里就是 Dimensions 与 Metrics 两个选项，分不清则图必配错。
- 可视化的目标可以和实时计算对照着理解：实时计算追求算得快，可视化追求看得懂，一个面向机器链路，一个面向人的决策。
- 画图的数据源就是 day7 摄入进 Druid 的 `all_device_message` 表，这一天不引入新数据链路，只把已有数据呈现出来。

## 算出来和看明白之间隔着可视化

平台的数据链路已经能把数据算出来、存起来、查出来，可视化在这条链路的末端再接一截，服务对象从程序换成人：

```mermaid
flowchart LR
    D["冷链设备"] --> K["Kafka"]
    K --> FL["实时计算"]
    FL --> DR["Apache Druid"]
    DR --> SS["Superset 数据源"]
    SS --> C["图表"]
    C --> B["看板"]
    B --> P["运营与决策"]
```

读图的关键是 Superset 的位置：它不碰设备与计算，只从 Druid 取数。前面实时计算那几天的目标是把结果算得快、写得准，考验的是链路与窗口；可视化的目标是把统计结果表达得让人一看就懂，考验的是维度指标的选取与图表形态的匹配。同一天温湿度数据，曲线回答「变化趋势」，柱状对比回答「哪个仓库最热」，饼图回答「告警占比」，选哪种形态由问题决定，这正是表现方式这一节要建立的感觉。

## Superset 三步走：接数据源、建图表、拼看板

Superset 的使用按三步展开。

**第一步接入数据源。** 在 Superset 里登记一个数据库连接，填一段 SQLAlchemy URI 就能让它连上 Druid 的 SQL 网关（示例，按 Superset 常用写法补全）：

```bash
# Superset 新建数据库连接时填写的 SQLAlchemy URI
druid://druid.example.com:8082/druid/v2/sql
```

连接测试通过后，Druid 里的数据表就会出现在 Superset 的数据集列表里，`all_device_message` 也在其中。

**第二步创建图表。** 选定数据集，配置维度、指标与图表类型，Superset 把配置翻译成查询发给数据源。一张「各仓库当天最高温度」的柱状图，背后是这条 SQL（示例）：

```sql
SELECT housename, MAX(tem) AS max_tem
FROM all_device_message
WHERE __time >= CURRENT_TIMESTAMP - INTERVAL '1' DAY
GROUP BY housename
```

`housename` 是维度，`MAX(tem)` 是指标，这一组选择正是开篇目标里「维度与指标」概念的用武之地。

**第三步拼装看板。** 图表逐个建好后拖进 dashboard，按冷链监控的实际关注点排版：温度湿度曲线放中间，告警统计放两侧，时间筛选器放在顶部全局生效。运营打开一个页面就能纵览全部冷库状态，这就是数据可视化在平台里的最终形态。

## 学习路线建议

概念先行、工具随后、项目收口。维度与指标两组概念先吃透，图表配置的每个选项才有判断依据；表现方式与常用工具过一遍建立全景，知道什么数据该配什么图、除了 Superset 还有哪些选择；重心落在 Superset 实战，从接数据源一路做到看板上线，把 day7 存下的数据真正变成能看的产品。学习中常见的问题，比如什么是数据可视化、怎样做可视化、有哪些场景和工具、过程中常踩什么坑，都会随着这条路线依次得到回答。

## 常见误区

- **把可视化理解成美化。** 错例：认为可视化就是给报表换配色。正解：可视化的本质是对数据做聚合与抽象，把多行明细压缩成图形表达的规律，选错维度指标的图表再好看也是错的。
- **跳过概念直接上手工具。** 错例：打开 Superset 就拖拽，把温度值拖进维度框。正解：先分清维度与指标，再做图表，工具操作的每一步背后都是概念判断。
- **图表越多越专业。** 错例：看板里塞满十几种图形。正解：每张图对应一个明确的问题，答不上问题的图删掉，看板的价值在于让人更快得出结论。
- **以为可视化要重建数据链路。** 错例：担心画图还要再采一次数。正解：Superset 直连既有数据源，day7 摄入的表直接可用，可视化的成本集中在图表配置而非数据搬运。

## 面试可能被问到的问题

1. 面试官追问：「数据可视化的目标和实时计算的目标有什么区别？」
   答：实时计算追求计算时效，把最新结果以最小延迟产出，面向数据链路；可视化追求表达效率，把统计结果转成人能快速解读的图形，面向决策者。一个解决算出来，一个解决看明白。
2. 面试官追问：「Superset 是什么，核心概念有哪几个？」
   答：开源的数据探索与可视化平台。核心概念包括数据源与数据集、图表（维度指标加图表类型的组合）与看板 dashboard，按接数据源、建图表、拼看板三步使用。
3. 面试官追问：「为什么选 Superset 做监控平台的前端呈现，而不是自己写页面？」
   答：Superset 免代码即可完成数据源接入、图表配置与看板拼装，自带权限与缓存，常规统计看板的开发成本远低于自研前端；自研更适合交互深度定制、嵌入业务流程的场景。
4. 面试官追问：「做可视化之前为什么要先讲维度与指标？」
   答：图表配置的本质是选维度定分组、选指标定算法，维度指标不分，配置出来的图表数字就失真。概念是工具操作背后的判断依据，先讲概念才能讲清楚为什么这么配。
5. 面试官追问：「你的可视化看板数据从哪里来？」
   答：来自平台已落地的时序库。设备快照经实时计算写入结果队列，摄入进 Druid 的 all_device_message 表，Superset 连接 Druid 的 SQL 网关直接取数，不重复采集与搬运。
