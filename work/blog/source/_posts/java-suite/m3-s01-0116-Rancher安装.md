# Rancher：给 Docker 装一个可视化管理后台

服务器上的容器一多，纯命令行的管理就开始吃力：谁在跑、谁挂了、谁把内存吃光了，全靠 `docker ps` 加 `docker stats` 一条条翻。Rancher 就是给这套东西配的管理后台，网页上点几下，容器状态、启停操作一目了然。本章持续集成链路已经走通，这一课进入第三个知识点「容器管理」，先把 Rancher 用容器方式装起来，跑出中文界面。

## 先给结论

- Rancher 通俗理解就是 Docker 的图形化管理界面，底层仍然是 Docker，它基于 Docker 之上做管理，不改变容器本身的运行方式。
- 除了日常启停监控，它还提供负载均衡、弹性扩容等更高级的运维功能，是企业常用的容器运维工具。
- 安装本身就是起一个容器：`docker run -d --name=rancher -p 9000:8080 rancher/server`，容器内 8080 映射到宿主机 9000。
- Rancher 启动时间偏长，首次打开页面空白不要急着判定失败，等一会儿再刷新。
- 默认英文界面，右下角语言菜单选「简体中文」即可切换。

## 一、Rancher 在容器体系里的位置

把关系一句话说透：Docker 负责真正创建和运行容器，Rancher 是架在 Docker 之上的管理平台。装了 Rancher 之后，运维人员用类似管理后台的方式操作服务器上的容器，底层每个动作最终仍由 Docker 执行。

```mermaid
flowchart LR
    A["运维人员浏览器"] -->|"访问 9000 端口"| B["rancher/server 容器<br/>内部监听 8080"]
    B -->|"调用 Docker 接口"| C["宿主机 Docker"]
    C --> D["业务容器集群"]
```

关键路径是中间那一段：Rancher 自己也以容器形态运行，通过 Docker 的接口去管理同一台机器（以及后续加入的机器）上的所有容器。它带来的增量能力有明确定位：负载均衡、弹性扩容这类实用运维功能，命令行里要写不少脚本的事，界面上点选即可，这也是企业愿意引入它的原因。

## 二、安装前的准备

课程给 Rancher 单独准备了一台全新虚拟机，安装步骤文档从下载镜像写起。动手前有三件事值得交代：

**第一，内存要给足。** Rancher 本身就是一套完整的 Web 服务，对内存要求比较高，课程环境把虚拟机内存调到接近 10G。内存抠太紧，轻则启动缓慢，重则页面永远刷不出来，排查半天发现是资源不足。

**第二，网络先确认。** 虚拟机启动后 root 登录，`ip addr` 查到本机 IP（课程环境是 `192.168.184.144`），再用 SSH 客户端工具连上去操作。后续浏览器访问用的是这个 IP，先记下。

**第三，Docker 服务先起来。** Rancher 以容器方式安装，宿主机上 Docker 必须先运行：

```bash
# 启动 Docker 服务
systemctl start docker

# 查看已有镜像
docker images
```

课程镜像里已经预置了常用镜像，`rancher/server` 就在其中，所以 `docker pull` 这一步可以直接省略；换到自己的环境，镜像列表里没有就先拉取。

## 三、创建容器并完成初始化

镜像就位后，创建 Rancher 容器（课堂命令实录）：

```bash
# (1) 下载镜像（已预置可跳过）
docker pull rancher/server

# (2) 创建容器
docker run -d --name=rancher -p 9000:8080 rancher/server
```

`docker ps` 确认容器已经在跑，接下来浏览器访问 `http://192.168.184.144:9000`。

这里有个新手必经的插曲：第一次访问多半是一片空白或加载失败，容器还没完全启动。Rancher 的启动时间明显比普通容器长，等半分钟到几分钟再刷新，多试几次就能看到页面，不要在这个阶段反复重建容器。

页面出来后先弹「Welcome to Rancher」欢迎框，点 Got It 关掉，进入主界面，能看到「创建第一个应用」的引导。默认界面是英文，用起来不顺手，点右下角的语言选项选「简体中文」，整个界面立刻切换成中文版，后续操作就轻松了。

## 四、初始化方向：环境的概念

进入中文界面后，界面上出现的第一个核心概念是环境。课程讲义的表述是：Rancher 支持把资源分组到多个环境，每个环境具有自己的基础架构资源及服务，并由一个或多个应用组成。

用大白话解释：环境相当于一道隔离墙，开发一套、测试一套、生产一套，每套里有独立的主机资源、镜像仓库和服务，互不干扰。在哪个环境下操作，就只会看到和影响那个环境的资源。环境的创建与服务的部署属于后续课程的内容，这里先把概念立住，看到主界面里的环境菜单不迷茫即可。

## 常见误区

- **页面空白就重建容器。** Rancher 启动慢是常态，首次访问空白属于正常现象，等待后刷新即可。反复 `docker rm` 重来反而每次都从零等起。
- **虚拟机内存给太小。** 两三个 G 的机器跑 Rancher 会异常吃力甚至起不来，安装前把内存调足，课程环境给到接近 10G。
- **端口写反。** `-p 9000:8080` 的顺序是宿主机端口：容器端口，Rancher 服务在容器内监听 8080，浏览器访问的永远是宿主机的 9000，两边搞混会一直 404。
- **忘了启动 Docker 直接建容器。** 虚拟机是新开的，Docker 服务未必自启，`docker run` 会直接报连不上守护进程，先 `systemctl start docker` 再说。

## 面试可能被问到的问题

1. 面试官追问：「Rancher 和 Docker 是什么关系？」
   答：Docker 是容器运行时，负责真正创建、运行容器；Rancher 是架在 Docker 之上的图形化容器管理平台，通过 Docker 接口对容器做集中管理，并额外提供负载均衡、弹性扩容等运维能力。装 Rancher 不替代 Docker，底层执行者仍然是 Docker。

2. 面试官追问：「安装命令 `-p 9000:8080` 里的两个端口分别是什么？」
   答：容器内的 rancher/server 服务固定监听 8080，9000 是映射到宿主机的对外端口。浏览器访问宿主机 IP 加 9000，流量经端口映射转到容器内的 8080。改宿主机端口只需改左边的数字。

3. 面试官追问：「Rancher 里的『环境』是用来做什么的？」
   答：环境是资源分组与隔离的单位，每个环境拥有自己的基础架构资源和服务，由一个或多个应用组成。典型用法是按开发、测试、生产划分，操作与资源互不影响，避免误操作跨环境扩散。

4. 面试官追问：「有了命令行为什么还要引入 Rancher 这类工具？」
   答：容器规模上去之后，逐台机器敲 `docker ps`、看日志、改配置的效率太低，状态也不直观。管理平台把多台主机的容器聚合到一个界面，启停、扩容、负载均衡变成点选操作，还天然具备多环境隔离，运维效率和安全性的提升都是命令行给不了的。

5. 面试官追问：「Rancher 本身是怎么部署的？」
   答：它自身就是一个容器，官方提供 `rancher/server` 镜像，一条 `docker run` 加端口映射即可运行。因为 Rancher 只通过接口管理其他容器，不要求必须和业务容器同机，部署在独立的管理机上更常见，课程也是装在一台全新虚拟机上。
