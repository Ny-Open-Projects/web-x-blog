## 纲要

- 引入依赖：Swagger 注解（`swagger2`）与 Freemarker 模板引擎，支撑自动生成带接口描述的代码
- 代码生成器 `MybatisPlusGenerator`：用 `AutoGenerator` 串联全局、数据源、包路径、策略四类配置
- 策略要点：`NamingStrategy.underline_to_camel` 下划线转驼峰、乐观锁字段 `version`、时间字段自动填充 `TableFill`
- 实战验证：以 `test` 表跑通生成，`TestService` / `TestController` / `TestMapper` 自动产出，证明后续所有模型可同法生成

## 为什么需要代码生成器

用户模块（前述）我们手动敲了一遍实体、`Mapper` 与控制器。后续商家、门店、商品、SKU、库存等十多张表如果都手写，工作量巨大且容易出错。MybatisPlus 的 `AutoGenerator` 可以依据数据库表结构，一键生成 `pojo` / `mapper` / `service` / `controller` 全套代码，正式进入规模化开发。

## 引入依赖

在 `pom.xml` 中加入两个关键依赖：

- **Swagger 注解**：生成代码时自动带上接口描述（`gc.setSwagger2(true)`）。
- **Freemarker**：作为模板引擎渲染 Mapper 的 XML 文件。

```xml
<dependency>
    <groupId>io.springfox</groupId>
    <artifactId>springfox-swagger2</artifactId>
    <version>2.9.2</version>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-freemarker</artifactId>
</dependency>
```

## 代码生成器四段配置

`MybatisPlusGenerator` 的核心是 `AutoGenerator`，依次装入四类配置：

```java
public static void main(String[] args) {
    AutoGenerator mpg = new AutoGenerator();

    // 1、全局配置
    GlobalConfig gc = new GlobalConfig();
    gc.setOutputDir(System.getProperty("user.dir") + "/src/main/java");
    gc.setAuthor("socialecom");
    gc.setOpen(false);
    gc.setFileOverride(true);              // 覆盖已有文件：首次用 true，后续建议 false 增量
    gc.setServiceName("%sService");
    gc.setIdType(IdType.AUTO);             // 主键自增
    gc.setSwagger2(true);
    mpg.setGlobalConfig(gc);

    // 2、数据源配置
    DataSourceConfig dsc = new DataSourceConfig();
    dsc.setUrl("jdbc:mysql://localhost:3306/socialecom?useUnicode=true&characterEncoding=UTF-8");
    dsc.setDriverName("com.mysql.cj.jdbc.Driver");
    dsc.setUsername("root");
    dsc.setPassword("123456");
    dsc.setDbType(DbType.MYSQL);
    mpg.setDataSource(dsc);

    // 3、包配置
    PackageConfig pc = new PackageConfig();
    pc.setParent("com.social.ecom");
    pc.setEntity("pojo");
    pc.setMapper("mapper");
    pc.setService("service");
    pc.setController("controller");
    mpg.setPackageInfo(pc);

    // 4、策略配置
    StrategyConfig strategy = new StrategyConfig();
    strategy.setNaming(NamingStrategy.underline_to_camel);
    strategy.setColumnNaming(NamingStrategy.underline_to_camel);
    strategy.setEntityLombokModel(true);
    strategy.setRestControllerStyle(true);
    strategy.setVersionFieldName("version");     // 乐观锁字段
    ArrayList<TableFill> fillList = new ArrayList<>();
    fillList.add(new TableFill("create_time", FieldFill.INSERT));
    fillList.add(new TableFill("update_time", FieldFill.INSERT_UPDATE));
    strategy.setTableFillList(fillList);          // 时间字段自动填充
    strategy.setInclude(scanner("表名，多个英文逗号分割").split(","));
    mpg.setStrategy(strategy);

    mpg.setTemplateEngine(new FreemarkerTemplateEngine());
    mpg.execute();
}
```

四个配置段的含义：

| 配置 | 作用 |
| --- | --- |
| `GlobalConfig` | 输出路径、作者、`service` 命名模板、主键策略、是否覆盖文件 |
| `DataSourceConfig` | 数据库连接串、驱动、账号密码 |
| `PackageConfig` | 各层包名（实体放 `pojo`，其余按 `mapper/service/controller` 分目录） |
| `StrategyConfig` | 命名策略、Lombok、REST 风格、`version` 字段、时间自动填充、目标表名 |

> `setFileOverride(true)` 会覆盖同名文件：首次生成用覆盖，后续改动过 `Mapper`/Service 后建议改 `false` 以追加，避免手工代码被冲掉。

## 跑通验证：以 test 表为例

新建一张最简单的 `test` 表（`id` 自增主键、`name varchar(60)` 非空默认空串、`create_time`/`update_time` `datetime`），运行生成器并输入表名 `test`。生成结果：

- `TestService` 继承 `IService<Test>`，`TestServiceImpl` 继承 `ServiceImpl<TestMapper,Test>`
- `TestMapper` 继承 `BaseMapper<Test>`，并生成 `TestMapper.xml`
- `TestController` 产出 REST 风格接口

把原 `UserController` 里最简单的 `get` 方法拷到 `TestController`（改用 `testService.getById(id)`），插入一条「测试记录」后启动应用，访问 `/test/get?id=1`，响应极快——证明自动生成的代码已经打通整条链路。

后续所有业务模型（商家、门店、商品、SKU 等）从 Mapper 到 Service 到 Controller，都可用同一套生成器一键产出，再在生成的骨架上补充业务逻辑即可。

## API 速览

| 类 / 方法 | 作用 |
| --- | --- |
| `AutoGenerator` | 代码生成器总入口，`execute()` 触发 |
| `GlobalConfig.setSwagger2(true)` | 生成 Swagger 注解 |
| `StrategyConfig.setVersionFieldName("version")` | 识别乐观锁字段 |
| `TableFill(col,FieldFill)` | 声明字段填充策略（`INSERT` / `INSERT_UPDATE`） |
| `FreemarkerTemplateEngine` | 用 Freemarker 渲染 XML 模板 |

## Demo 示例

**运行说明**：引入 Swagger 与 Freemarker 依赖；配置 `MybatisPlusGenerator` 的数据库连接；运行 `main` 方法并输入 `test`；启动应用后访问 `/test/get?id=1`。

**代码说明**：生成器依据表结构产出 `pojo/mapper/service/controller`；业务侧只需注入对应 `*Service` 调用 `getById` 等基类方法。

**技术点总结**：代码生成器把「建表 → 写实体/Mapper/Service/Controller」的低级重复劳动自动化，是规模化落地领域模型的前提；配合 `version` 与 `TableFill` 策略，生成即带上乐观锁与时间填充能力。
