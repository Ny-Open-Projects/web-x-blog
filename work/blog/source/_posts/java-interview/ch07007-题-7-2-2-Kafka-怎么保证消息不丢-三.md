### 题 7.2.2：Kafka 怎么保证消息不丢？（三端保障，必背矩阵）

**【参考回答（可背）】**
1. **生产端**：
   - `acks=all`（leader + 所有 ISR 副本确认）；
   - `retries=Integer.MAX_VALUE` + 幂等 producer（enable.idempotence=true，PID + 序列号防 broker 端重复）；
   - 发送用带回调的异步 API，失败记录补偿（本地消息表）；
   - 不要用 fire-and-forget。
2. **Broker 端**：
   - `replication.factor >= 3`；
   - `min.insync.replicas >= 2`（ISR 不足 2 拒写，牺牲可用性保一致——CAP 取舍）；
   - 禁 unclean.leader.election（不允许落后副本当 leader）。
3. **消费端**：
   - **先处理完再手动提交 offset**（enable.auto.commit=false），重复消费交给幂等；
   - 千万不要"先提交后处理"。
一句话总结：**发送端确认 + 多副本持久化 + 消费后提交 + 全链路幂等。**

**【追问链】**
1. ISR 是什么？→ 与 leader 保持同步的副本集合（replica.lag.time.max.ms 内追上）；ISR 收缩过多时 acks=all 会写入失败——可用性与一致性的旋钮。
2. HW 与 LEO？→ LEO 每副本日志末端；HW = ISR 中最小 LEO，消费者只能读到 HW 之前，防止读到未确认数据。

**【P10 加分项】**
端到端视角：技术不丢 ≠ 业务不丢——消费失败进死信、人工干预流程、**对账平台**（上游订单 vs 下游处理结果定时核对）才是最终兜底。"MQ 的可靠性 SLA 要写进与业务方的契约"。
