## 第 18 册 示例面试实录 —— 一面完整回放（带面试官批注）

> 用法：这是一份"范文"。左边（正文）是完整的对话流，【评注】框是面试官内心打分。
> 读两遍：第一遍看候选人怎么答，第二遍看面试官怎么想。
> 特别留意第 6 题——候选人答不上来时的**标准救场示范**，这段的价值高于所有标准答案。

---

**面试官**：开始吧，先简单介绍一下你自己和你最得意的项目。

**候选人**：我在 XX 团队负责交易核心链路，日均订单 8000 万、峰值 QPS 3 万。过去一年主导了三件事：一是订单库从单库 8 亿行迁到 16 库 64 表，写 TPS 提升三倍，双写灰度零事故；二是详情页多级缓存改造，P99 从 45ms 降到 8ms；三是牵头团队的稳定性建设，把同类缓存事故从月均 2 次压到零。我今天是来聊 P10 方向的，希望展示我在架构判断和组织能力上的积累。

> 【评注】✅ 90 秒内完成；三个数字；每个数字都有对应"决策动作"而非工作量；结尾一句话定调目标职级。这开场直接把二面的追问都引导到他准备好的领域——**面如其表，说出来的每个词都会被追**。

**面试官**：订单库迁移，为什么选 16 库 64 表？分片键怎么定的？

**候选人**：分片键是 user_id，取模 64。定 64 是因为按当时写增量预估五年后单表控制在 1500 万行以内，且 64 是 2 的幂、方便翻倍扩容（64→128 迁一半数据）。我们没用 hash(订单号) 是因为 80% 的查询带 user_id，按订单路由需要二次路由表或基因法，当时评估复杂度不值得，兜底方案是订单号内嵌 user 分片位（基因法）做订单维度查询。

> 【评注】✅ 这是教科书级回答：给出**计算依据**（五年预估）、**约束利用**（2 的幂+翻倍扩容）、**被否方案及理由**（订单号路由）、**兜底方案**（基因法）——面试官要的"取舍完整性"全齐了。追问就会顺着基因法或扩容走，而他显然都备好了。

**面试官**：双写灰度怎么保证不丢数据？

**候选人**：四步走：存量迁移（基于 binlog 的同步工具）→ 增量双写（旧库为准、新库异步写，失败进补偿队列）→ 全量对账（逐行 checksum + 采样业务对账，跑了三周差异归零）→ 切读切写（先切读 10%，观察一周，再切写）。唯一一次小插曲：补偿队列一次积压 40 分钟，根因是补偿消费单线程，当晚改批量 + 分片并行后消化完——对账工具救了我们。

> 【评注】✅ 步骤完整且有"插曲"——带瑕疵的真实故事可信度远高于完美故事。还主动暴露了一个事故并展示了修复，这在面试官眼里是加分而非扣分。**下一步他大概率被追对账工具的细节**，注意他后面能不能接住。

**面试官**：对账怎么做的？千万级数据怎么对？

**候选人**：两层：增量层用 binlog 消费做准实时（秒级窗口比对，主要抓双写 Bug），全量层 T+1 分片 checksum（按主键分 512 个区间，SQL 里对每行算 CRC 再聚合，避免全量拉到内存）。这里有个坑：CRC 在主从不一致时会抖动，我们改成"以主库为基准重算而非信任从库结果"。

> 【评注】✅ 给出了可复用的技术方案（分区 checksum）和一个真实的深坑（主从抖动）。这种"只有真做过的人才会知道的坑"是整场面试的黄金证据。

**面试官**：详情页 P99 从 45 到 8ms，说说架构。

**候选人**：四级漏斗：L1 Caffeine 本地缓存纳秒级、L2 Redis 毫秒级、L3 DB 限流保护、前置还有 CDN。一致性靠 binlog 广播失效+本地短 TTL 兜底；热点治理靠实时热 key 探测自动推送本地缓存。这里我要主动说代价：本地缓存只有秒级一致，我们跟业务确认过容忍窗口才上的——以及内存是双倍的，命中率 95% 才划算，我们是按 top1% 商品占一半流量的数据算出这个账的。

> 【评注】✅ 自动说出代价与"业务确认过"——P9/P10 评语的关键词是"**trade-off awareness**"，这句话直接命中。数字自洽（95% 命中率支撑 8ms）。

**面试官**：缓存击穿你们怎么防的？讲讲具体实现。

**候选人**：热点重建用单飞：本地一个 ConcurrentHashMap 做"进行中标记"+ 分布式锁，抢到的线程查库回填，其他线程自旋 50ms 读旧值兜底——我们没用逻辑过期，因为商品数据偶发旧值业务不可接受，宁可重建线程多一点。这是我评估过两个方案的取舍。

> 【评注】✅ 方案具体到"50ms 自旋"，且再次对比了被否方案（逻辑过期）及其业务理由（不接受旧值）。面试官此刻内部已写"架构判断 P9+"。

**面试官**：换个方向。G1 的 Remembered Set 为什么可能很大？你们遇到过吗？

**候选人**：（停顿两秒）RSet 的原理我清楚：Region 间跨代引用靠写屏障记录 card，引用密集且稀疏分布时 RSet 膨胀，可能吃掉 10%~20% 堆。但我们生产当时没有直接踩过 RSet 膨胀的案例——我们的问题更多在 Humongous 大对象引发的 to-space exhausted。如果真排查，我会看 `gc log` 的 Remembered Set 统计和 sum of remembered set sizes 曲线。这块我只能给到机制和排查入口，没有一手经验，抱歉不能给你"我们是怎么解决的"故事。

> 【评注】⭐⭐ **全卷最有价值的一段。** 面试官故意考了一个偏离其项目方向的题（诚实度+边界测试）。候选人的处理是满分模板：① 停顿两秒思考（不慌）；② 答出机制层（证明知识在）；③ **明确承认没有一手经验**；④ 给出排查入口（证明会用）；⑤ 不编故事。对比错误示范：编一个"我们 RSet 曾膨胀到 30%"——二面追问两句就穿帮，而且触发"真实性存疑"的全面降级。**承认边界 = 信任资产。**

**面试官**：（点头）好。那你们 to-space exhausted 是怎么定位的？

**候选人**：GC 日志里先出现 "to-space exhausted" 再退化 Full GC（JDK8 下还是单线程 Full，停顿秒级）。定位到是运营批量导入大字段（一张 5MB 的商品详情图 base64）——对象超过 Region 一半直接进 Humongous Region，连续分配挤占。修复分三层：导入走异步通道+压缩存储（治本）、G1HeapRegionSize 从 2M 调到 8M（治标）、代码评审加"单对象 >512KB 需说明"门禁（防复发）。

> 【评注】✅ 顺着承认的边界自然接到自己的真实案例——**"承认+转场"的组合**把短板题变成了主场题。修复的三层结构（治本/治标/防复发）再次命中 P10 叙事范式。

**面试官**：最后，虚拟线程你们评估过吗？什么结论？

**候选人**：评估过，结论是"局部用、不激进"。我们的 IO 聚合服务（BFF 层）同步链路 200 个平台线程是瓶颈，虚拟线程实测吞吐 x2.5，已上；但核心交易没迁——因为连接池容量才是真瓶颈，虚拟线程只会把阻塞更快地怼到连接池上，等于换了个排队的地方。另外我们踩过一个 pinning 坑：synchronized 包住的慢调用钉住载体线程，JDK21 上表现为吞吐不升反降，升到 JDK24 的优化才解决。所以我的判断标准是"**下游配额是不是瓶颈**"——是，先扩配额；不是，虚拟线程才有效。

> 【评注】✅ 与时俱进且有一手踩坑（synchronized pinning），并给出了**决策标准而非跟随潮流**——"下游配额是不是瓶颈"一句话值一道大题。面试官已确认 P9 评语，等待三面验证 P10 潜力。

**面试官**：今天就到这里。你有什么想问我的？

**候选人**：三个问题：一是团队目前最大的技术挑战是什么——是容量、一致性还是组织协作层面？二是上一个在这个位置的人，离开的原因是什么？三是如果我这轮过不了，您觉得我最需要补的是什么？

> 【评注】✅ 前两问是标准反问三连；第三问是**高级动作**——主动要负面反馈，既展示成长心态，又当场收集了真实评语（这比等offer反思强一百倍）。面试官通常会给出真话，这段话本身就是最后一轮加分项。

**面试官**：（合上电脑）聊得很好，我把你的情况如实反馈。祝你顺利。

> 【评注】终局定语。"如实反馈"四字意味着他没有发现任何真实性疑点——全场的诚实与自洽在此收口。

### 评分复盘（面试官视角终稿）

| 维度 | 证据 | 评语 |
|------|------|------|
| 基础下限 | 全场未踩雷 | ✅ 无减分 |
| 深度 | 分库分表四步+checksum 深坑 | ✅ P8 证据链完整 |
| 架构判断 | 缓存代价主动申报、虚拟线程决策标准 | ✅ P9 级 trade-off awareness |
| 诚实度 | RSet 边界承认+不编故事 | ✅ 信任满分 |
| 成长性 | 反问要负面反馈 | ✅ 潜力信号 |
| 待验证 | 组织能力、跨团队影响（本场未及） | → 留给三面/四面 |

**对照自查**：这份实录的每个"✅"都能在第 14 册剧本里找到对应考点——你演练时，用这份实录对照自己的回答，差异处就是你的提升清单。

### 速记卡

1. 开场 90 秒三个数字三个决策，为追问设主场。
2. 每个方案都带"被否方案与理由"——取舍完整即 P9 语言。
3. 主动申报代价与"业务确认过"——trade-off awareness 是评语关键词。
4. 没有一手经验的题：机制 → 排查入口 → 明确承认不编故事。
5. 承认边界后自然转场到自己的一手案例，短板题变主场题。
6. 新技术给"决策标准"而非"潮流跟随"。
7. 修复叙事永远三层：治本/治标/防复发。
8. 反问的第三问要负面反馈："我最需要补的是什么。"
