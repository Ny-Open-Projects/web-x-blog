### 题 6.7.2：Lua 脚本的使用边界？写多了会怎样？

**【参考回答（可背）】** 价值：多命令**原子性**（无中途插队）+ 减少网络往返。边界三铁律：① Lua 执行期间**单线程被独占**——脚本里禁用 O(N) 大命令（KEYS/SMEMBERS 大集合），必须用 SCAN 分片思维；② 脚本只操作 KEYS 参数里声明的 key（Cluster 下跨槽直接报错，且可被集群正确路由）；③ 脚本要有幂等性与超时意识（script kill 只能杀"没写过数据"的脚本——写了数据的只能等执行完或 reset 硬杀）。替代：复杂原子逻辑上移到应用+分布式锁，或下移到 Redis 7 的 Function（可管理、可重载）。
**【追问链】** ① 为什么说"Lua 里调 KEYS 是生产事故高发点"？（keys 全库扫描阻塞主线程数秒，且藏在脚本里慢日志都抓不到全过程）② Lua 与 WATCH/MULTI 取舍？（事务乐观锁轻量无原子计算；Lua 能"读后写"决策——按值条件操作只能 Lua）。
**【P10 加分项】** "我们给 Lua 定了'10 行以内、单 key 组、O(1) 命令'三红线并纳入 code review 清单——脚本复杂度失控等于把业务逻辑写进了单线程瓶颈里。"
