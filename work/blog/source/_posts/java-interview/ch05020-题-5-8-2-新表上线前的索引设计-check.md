### 题 5.8.2：新表上线前的索引设计 checklist（P10 会怎么评审建表 SQL）

**【参考回答（可背）】** 十条评审清单（背成模板）：① 主键趋势递增（自增/雪花，禁 UUID）；② 每个高频查询模式都有一条索引覆盖（联合索引列序：等值在前、范围在后、排序列跟后）；③ 区分度低的列（如性别/状态）不单独建索引，只能做联合索引前置等值；④ 长字符串用前缀索引且接受失去覆盖能力，或 hash 列辅助；⑤ 单表索引数 ≤5 且每个索引有明确服务对象（问"这个索引给哪条 SQL 用"答不上就删）；⑥ 外键不用（应用层保证一致性），但**逻辑外键关系要文档化**；⑦ 大字段（TEXT/BLOB）拆溢出表；⑧ 时间列必建（归档/范围查询刚需）；⑨ 每 DDL 走 Online DDL 评审（gh-ost）；⑩ 预估数据量 >千万的表提前规划分片键。
**【追问链】** ① 索引多了写放大怎么权衡？（写 TPS 下降可压测量化：每多一个二级索引，insert 成本 +一次 B+ 树写入，热点表 3 个以上二级索引就要压测）② 统计信息过期导致选错索引怎么办？（analyze table 定期 + 监控 explain 走错案例）。
**【P10 加分项】** "清单进 CI：DDL 上线卡点自动检查（无主键/无时间列/索引超限自动拦截）+ 大表 explain 成本门禁——索引设计从'师傅经验'变成'平台能力'。"
