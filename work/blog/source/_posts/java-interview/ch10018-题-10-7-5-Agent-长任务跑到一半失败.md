### 题 10.7.5：Agent 长任务跑到一半失败/中断了，怎么恢复？

**【参考回答（可背）】** 设计四件套：① **checkpoint**：每个步骤完成后持久化"任务状态+上下文快照+已完成结果"到 DB/对象存储（不只靠内存）；② **幂等步骤**：工具调用全部幂等（或记录调用凭证防重复执行——转账类工具先查询已执行凭证）；③ **恢复策略**：从中断的步骤续跑，而不是重头再来（上下文用快照重建）；④ **预算与熔断**：步数/token/时间的硬上限，超限转人工。生产级实现就是"把 Agent 当分布式工作流"：LangGraph 的 checkpointer、Temporal 的 workflow 持久化都是这个思想的现成实现。
**【追问链】** ① 外部副作用工具怎么防重复？（调用前写"意图凭证"行，返回后更新结果，恢复时见有凭证无结果则改为查询式验证）② 恢复后上下文超预算怎么办？（快照+摘要压缩，保留关键中间产物引用而非全文）。
**【P10 加分项】** 一句话点题："Agent 可靠性的上限不在模型，在工程——可恢复、幂等、可观测、可回放四性做完，失败率就变成'可工程化优化'的指标而不是玄学。把 SRE 方法论平移到 Agent，正是 Java 工程师的机会。"
