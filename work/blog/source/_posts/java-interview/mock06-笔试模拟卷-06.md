## 参考答案与解析（自测后再看）

**1.1**（来源 mongodb）
**答案：A**
**解析：** $jsonSchema 集合校验器（validationLevel/validationAction 可配）约束文档结构。原因：无 schema 不等于无约束：validator 在插入/更新时校验（可选 warn 只告警或 error 拒绝），渐进收紧用 validationLevel moderate。

**1.2**（来源 mq）
**答案：C**
**解析：** rebalance（再平衡）触发：组内成员增减、订阅变化、消费者超时（max.poll.interval.ms 超时）。原因：rebalance 期间整组停止消费（STW 式），长业务处理超时被踢出引发循环 rebalance，是经典生产事故。

**1.3**（来源 distributed）
**答案：D**
**解析：** 服务发现：提供者注册→消费者订阅（推送/拉取）→本地缓存+心跳保活。原因：注册中心故障时客户端本地缓存兜底（降级仍可调用已知实例），心跳剔除假活实例，推拉结合（首次拉取+变更推送）。

**1.4**（来源 ai）
**答案：D**
**解析：** SSE 流式断线处理：客户端断开停止生成（节约成本）与重连续传（Last-Event-ID）。原因：用户关闭页面应取消生成（省 token），意外断线用 Last-Event-ID 续传（SSE 标准），Java 侧 SseEmitter 完成/超时/错误回调清理资源。

**1.5**（来源 algorithm）
**答案：C**
**解析：** 原地操作：数组去重（同向指针）、移动零（交换）、颜色分类（三指针荷兰国旗）。原因：O(1) 空间约束下的数组操作，快慢指针写覆盖（读写下标分离），与 AL-012 三路分区同思想。

**1.6**（来源 java-ai）
**答案：B**
**解析：** 网关审计事件标准化输出：结构化审计事件（ who/when/what/cost/result）对接 SIEM/审计平台。原因：JA-322 审计的标准化面：事件 schema 固定（下游免解析适配），与安全日志（JA-520）联动。

**1.7**（来源 agent-dev）
**答案：C**
**解析：** 轨迹异步写入实现：内存队列（BlockingQueue）+后台消费线程批量落库，主循环只入队（不阻塞），队列满丢弃策略（采样）。原因：异步写入让轨迹不拖慢主循环（AD-040 异步落地），队列满策略（丢调试保审计 AD-106 分级），与异步日志实践联动。

**1.8**（来源 java-basics）
**答案：B**
**解析：** ArrayList 非线程安全：并发结构修改会抛 ConcurrentModificationException 或数据丢失。原因：多线程共享时用 CopyOnWriteArrayList 或 Collections.synchronizedList。

**1.9**（来源 concurrency）
**答案：D**
**解析：** 任务提交顺序是：核心线程未满则创建核心线程，满了先入队，队列满了才扩到最大线程，再满才拒绝。原因：注意是先入队后扩容而非先扩容，实测提交阻塞任务验证：4 核心队列容量 2 最大 8 时第 3、4 个任务入队第 5 个才创建非核心线程。

**1.10**（来源 jvm）
**答案：B**
**解析：** GC overhead limit exceeded：JVM 花超 98% 时间做 GC 但回收不足 2% 堆。原因：本质是堆接近死满，参数 -XX:-UseGCOverheadLimit 只是关闭该报错不解决问题，根因仍是泄漏或堆不足。

**1.11**（来源 spring）
**答案：D**
**解析：** @Validated/@Valid 触发 JSR-303 校验（Hibernate Validator 实现）。原因：@Valid 支持嵌套级联校验，@Validated 支持分组与类上标注触发方法级校验，校验失败抛 MethodArgumentNotValidException 进全局异常处理。

**1.12**（来源 mysql）
**答案：B**
**解析：** 列默认尽量 NOT NULL：null 影响索引统计、count(col) 忽略 null、is null 判断易错。原因：null 参与比较结果为 unknown、聚合跳过 null、可空列索引需要额外标记，默认 NOT NULL+默认值是规范，但 is null 查询可以走索引。

**1.13**（来源 redis）
**答案：B**
**解析：** 接口幂等辅助：Redis SET NX 请求 ID（token 机制）前置防重。原因：防重提交：提交前领 token（SET NX），提交时校验删除（Lua 原子），与 DB 唯一键双层兜底，TTL 控制防重窗口。

**1.14**（来源 mongodb）
**答案：B**
**解析：** 安全基线：SCRAM 认证（默认开启要求配置）、网络隔离、角色最小化（readWrite 按库）、审计。原因：未授权访问同样是事故源（与 Redis 同教训），x.509/LDAP 企业级认证可选，生产禁 eval 等危险命令。

**1.15**（来源 mq）
**答案：A**
**解析：** 消费端限流：RabbitMQ prefetch（未确认数上限）、Kafka 调 max.poll.records+处理速率。原因：下游 DB 慢时消费限流自保（防堆积转 OOM），prefetch=1 逐条处理 vs 批量权衡，限流与积压告警联动。

**2.1**（来源 distributed）
**答案：B**
**解析：** 正确表述应为——分布式追踪：traceId 贯穿全链路，span 记录每跳（服务/耗时/状态），context 跨进程传播。原因：span 树还原调用拓扑，异步/MQ 传播需显式处理（header/attachment），traceId 进日志（MDC）串联，排查"哪个服务慢了"的钥匙。

**2.2**（来源 ai）
**答案：B**
**解析：** 正确表述应为——推理模型（o1/R1 类）：生成前先"思考"（长 CoT），数学/代码/复杂推理显著提升，成本与延迟更高。原因：test-time compute 换质量（多想少错），适合难题不适合简单任务（浪费），输出思考过程可观测，按任务难度路由（与模型分级联动）。

**2.3**（来源 algorithm）
**答案：A**
**解析：** 正确表述应为——异或性质：a^a=0 a^0=a，找单数（其余成对）/交换两数/校验，O(N) O(1)。原因：出现一次的数（异或全数组），丢失数字（异或 1..N），位运算其他技巧（n&(n-1) 消最低位 1 判 2 幂）。

**2.4**（来源 java-ai）
**答案：C**
**解析：** 正确表述应为——Recall@K 统计实现：对 golden set 批量跑检索，断言期望片段是否出现在 topK（命中率聚合）。原因：把 AI-082 指标落到代码：批量跑+逐条判定+分域聚合，是检索回归的执行件。

**2.5**（来源 agent-dev）
**答案：B**
**解析：** 正确表述应为——长期记忆的读取：按当前任务检索相关历史（向量检索），注入上下文供决策参考。原因：记忆不是全量塞（JA-673 重排），检索注入让 Agent"记得该记的"，记忆写回策略（JA-504）配套。

**3.1**（来源 java-basics）
**答案：对。** 解析：switch 底层基于 tableswitch/lookupswitch 整数跳转指令。

**3.2**（来源 concurrency）
**答案：错。** 正确表述：StampedLock 提供乐观读：读时不加锁事后 validate 校验。原因：乐观读返回一个 stamp，读完后 validate 判断期间是否有写，失败升级为悲观读锁；吞吐高于读写锁，但不可重入且不支持 Condition

**3.3**（来源 jvm）
**答案：错。** 正确表述：GC 线程数由 -XX:ConcGCThreads 与 ParallelGCThreads 控制。原因：ParallelGCThreads 是 STW 阶段并行线程数（默认约 CPU 核数），ConcGCThreads 是并发阶段线程数（默认按比例），容器 CPU 限额影响默认值

**3.4**（来源 spring）
**答案：错。** 正确表述：Spring 事件机制：ApplicationEventPublisher 发布、@EventListener 监听默认同步执行。原因：监听器在发布线程内执行（同调用方法一样），异常会传播回发布者，解耦发布方与消费方

**3.5**（来源 mysql）
**答案：对。** 解析：RR 下可重复读与防幻读靠 Next-Key（左开右闭区间），RC 下禁用 Gap Lock 只锁记录（并发更好）

**3.6**（来源 redis）
**答案：对。** 解析：按面试频率排序，缓存一致性与分布式锁是 P7 分水岭，Cluster 细节是 P8+ 深度，场景设计（秒杀/排行榜/延迟队列）是 P9-P10 综合题

**3.7**（来源 mongodb）
