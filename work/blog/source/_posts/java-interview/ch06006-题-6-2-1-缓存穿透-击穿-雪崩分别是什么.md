### 题 6.2.1：缓存穿透、击穿、雪崩分别是什么？怎么解决？

**【参考回答（可背，出现率 Top3）】**
1. **穿透**：查**不存在**的数据，缓存和 DB 都没有，每次都打到 DB（可能是恶意攻击）。
   解决：① 缓存空值（短 TTL，如 60s）；② **布隆过滤器**前置（不存在直接拒绝，注意误判率与不可删除，可用 Counting BF/布谷鸟过滤器）；③ 参数校验与风控限流。
2. **击穿**：某个**热点 key 过期瞬间**，大量并发同时打到 DB。
   解决：① **互斥重建**（单飞：分布式锁/本地锁，一个线程查库回填，其他等待）；② 逻辑过期（不设物理 TTL，值里带过期时间，发现过期异步重建，读到旧值但不穿透）；③ 热点 key 永不过期 + 消息刷新。
3. **雪崩**：**大量 key 同时过期**或 Redis 整体不可用，流量全砸 DB。
   解决：① TTL 加随机抖动（错峰）；② 多级缓存（本地 Caffeine 兜底）；③ 限流降级（Sentinel 对 DB 保护）；④ Redis 高可用（哨兵/Cluster）；⑤ 大促前预热。

**【追问链】**
1. 布隆过滤器原理？→ bit 数组 + k 个哈希，插入置位、查询查位；**有误判（说存在可能不存在）但无漏判（说不存在必不存在）**，误判率与位数组大小/哈希数相关，不支持删除（删除用计数布隆）。
2. 逻辑过期的缺点？→ 短暂返回旧数据（业务要容忍）；重建线程管理复杂。

**【P10 加分项】**
指出三大问题的统一视角："**缓存与 DB 之间的'回源流量'治理**"——本质是保护回源路径：前置挡（布隆/空值）、收敛（单飞合并）、缓冲（队列削峰）、兜底（本地缓存+降级开关）。能把三个名词归纳成一个模型，是架构思维的信号。
