### 题 6.4.1：设计一个支撑百万 QPS 的商品详情页缓存架构

**【参考回答（分层可背）】**
1. **流量特征**：读多写少、热点集中（top 1% 商品占 50% 流量）、允许秒级不一致。
2. **多级缓存漏斗（必背顺序）**：
   - **L1 本地缓存**（Caffeine，进程内，纳秒级）：top 热点商品 + 静态化数据；TTL 1~5s 短窗口兜一致性；命中率 60%+；
   - **L2 Redis 集群**（毫秒级）：全量商品数据，分片；命中率 35%+；
   - **L3 DB**：仅 5% 未命中，限流保护。
3. **数据拆分**：主数据（标题价格库存状态）与扩展数据（详情图文）分 key，避免大 key；价格库存走独立实时服务（不强缓存）。
4. **一致性**：binlog（Canal）→ MQ → 广播失效 L2 + 各节点 L1（Pub/Sub 或 MQ 广播）；本地缓存短 TTL 兜底最终一致。
5. **热点治理**：实时热 key 探测（滑动窗口统计）→ 自动推送本地缓存；缓存预热（大促前按预测 top 列表提前加载）；**防击穿**：热点重建单飞。
6. **防雪崩**：TTL 抖动、DB 限流熔断（Sentinel）、降级开关（极端时返回静态兜底页/降级文案）。
7. **可观测**：各级命中率、回源 QPS、热 key 榜、大 key 榜——命中率突降告警。

**【追问链】**
1. 本地缓存内存多大？→ 有界（Caffeine maximumSize/权重），按"top N 商品 × 单条大小"预算，绝不能无界。
2. 多机房怎么做？→ 单元化部署（按用户分片各机房自闭环）或跨机房只读副本 + 本机房缓存。

**【P10 加分项】**
量化叙事："详情页 P99 从 45ms 降到 8ms，DB QPS 从 12 万降到 6000，成本是双倍内存与秒级一致性——这笔账跟业务方确认后落地。"**用成本与业务妥协讲清方案，而不是堆技术名词。**
