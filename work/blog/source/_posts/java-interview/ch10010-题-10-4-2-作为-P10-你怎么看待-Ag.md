### 题 10.4.2：作为 P10，你怎么看待 Agent 对软件工程与组织的长期影响？

**【参考回答（考察技术判断力与领导力，无标准答案）】**
1. **工程范式迁移**（背三段论）：
   - 代码 → 提示词 + 工具 + 评测集（"软件 2.0/3.0"）；
   - 确定性测试 → 概率性评测（单测测逻辑，评测集测效果，两者共存）；
   - 人写代码 AI 辅助 → 人定义意图与验收，AI 生成与执行（Dev in the loop 变 Human in the loop）。
2. **不变的东西**：架构能力（拆解、抽象、权衡）升值而非贬值——Agent 越强，"定义清楚问题与边界"越值钱；数据、权限、一致性这些后端基本功是 Agent 系统的地基，**Java 后端工程师的存量能力恰恰是 AI 应用的稀缺能力**。
3. **风险判断**：幻觉在资金/医疗等高风险场景的边界（高风险决策永远人审）；安全新面（Prompt 注入 = 新的 SQL 注入，工具调用 = 新的 API 面，要做输入净化与最小权限）；成本失控风险（预算熔断是标配）。
4. **组织行动**：建立 AI 使用规范（什么场景允许自动执行）、评测文化（一切 AI 变更过评测集）、技能转型（团队 30% 时间做 AI 提效实践）。
5. **收尾（可背金句）**："上一代架构师解决'不确定性下的系统可靠性'，这一代要解决'概率性组件进入系统后的工程可靠性'——方法论是相通的：隔离、降级、观测、评测。"

**【P10 加分项】**
给出自己团队的真实 AI 落地数据与教训（哪怕是小规模：内部运维问答机器人、代码评审助手），有"第一手实践"的候选人在此题有决定性优势。
