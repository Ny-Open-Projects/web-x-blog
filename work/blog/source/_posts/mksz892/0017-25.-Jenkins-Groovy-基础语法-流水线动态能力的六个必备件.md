## 纲要

- **Groovy 是 Jenkins Pipeline 的默认语言**，跑在 JVM 上的动态语言——会 Java 的人一周能上手，不会的一周也能上手
- **`script { }` 块是写 Groovy 的地方**，声明式语法表达不了动态逻辑时，全部在这里解决
- **六个必备件**：`def` 定义变量、`new Date().format()` 取时间、`for` 循环、`if/else if/else` 判断、`try/catch` 异常捕获、`def` 定义函数
- **时间格式化的第一用途是拼镜像 tag**：`yyyy/MMdd/HHmm/ss` 组合出唯一且可读的版本号
- **`if` 比 `for` 更常用**：分支判断（master/test）→ 环境域名 → 报警内容，是它的经典三段式
- **`try/catch` 的价值是精确定位失败步骤**：捕获后把错误信息塞进告警，不用翻完整日志
- **函数是消除重复的最小单位**：几十条流水线复制同一段逻辑时，先想到 `def`
- **测试场所是「系统管理 → 脚本命令行」**：粘贴 → 运行 → 看输出，语法对不对一秒知道

## 一、Groovy 是什么，在哪写

**Jenkins Pipeline 默认支持 Groovy 语言。Groovy 是一种基于 Java 的动态语言（跑在 JVM 上）。**

**我们需要掌握 Groovy 的基础语法，然后再把它运用到构建流水线当中。**

**写在哪？** 在 Pipeline 里，`stage` 下面的 **`script { }` 块**就是让我们写 Groovy 脚本的地方：

```groovy
stage('Example') {
    steps {
        script {
            // 这里写 Groovy
            def name = 'peter'
            echo "hello ${name}"
        }
    }
}
```

> 前面用过很多次 `script { }` 包 `docker.build`、`currentBuild.displayName`——那些本质就是 Groovy。

## 二、必备件一：`def` 定义变量

```groovy
def a = 1                      // 整数类型
def b = 'hello'                // 字符类型
def c = [1, 2, 3]              // 列表类型
def d = true                   // 布尔类型
def e = ['go', 'java', 'python']   // 字符串列表类型
println "${a} ${b} ${c} ${d} ${e}"
```

**用 `def` 关键字定义**，类型自动推导，不需要显式声明。五种常用类型一次覆盖。

## 三、必备件二：获取当前时间

```groovy
def year   = new Date().format("yyyy")     // 年
def month  = new Date().format("MMdd")     // 月日
def day    = new Date().format("HHmm")     // 时分
def second = new Date().format("ss")       // 秒
println "${year} ${month} ${day} ${second}"
```

**`new Date().format("pattern")` 是内置函数**，按 Java 的日期格式输出。

**为什么要获取当前时间？**

> 课件原话：一般我们在构建的时候都需要构建镜像，而**镜像的 tag 很有可能一部分就是由当前时间组合**。

真实用法（Kaniko 那篇会见到）：

```groovy
env.docker_image = "${image_prefix}:main-${year}${month}${day}${second}-${BUILD_ID}"
```

拼出 `repo:main-20261014120533-57` 这样的 tag——**带时间戳，唯一且可读，出问题能反查构建时刻**。

## 四、必备件三：`for` 循环

```groovy
def strList = ['go', 'java', 'python']
println "list size = ${strList.size()}"

for (int i = 0; i < strList.size(); i++) {
    println "item[${i}] = ${strList[i]}"
}
```

**执行流程**：

1. 定义字符串列表，赋给左边变量；
2. 用 **`size()`** 内置函数取列表大小；
3. `for (int i = 0;i < size;i++)` 循环；
4. **`i++` 默认加一**；
5. 用 **`列表名[索引号]`** 取元素值输出；
6. 当 `i >= size` 时循环结束。

**两个易错点**：

- **列表索引从 0 开始**——`strList[0]` 是第一个元素；
- **输出换行**：`println` 后想手动换行，加 `\n`；课件实测直接 `println` 会挤在一行，不好看。

## 五、必备件四：`if` 判断（比 for 更常用）

```groovy
def BRANCH_NAME = 'test'

if (BRANCH_NAME == 'master') {
    println "生产环境域名: www.example.com"
} else if (BRANCH_NAME == 'test') {
    println "测试环境域名: test.example.com"
} else {
    println "其他环境"
}
```

**四条语法规则**：

| 规则 | 说明 |
|---|---|
| 字符串判断用**两个等号** `==` | 不是单个 `=`（那是赋值） |
| 字符串加**单引号** | `'master'` |
| 变量名**直接写** | 不加引号、不加小括号 |
| 用小括号包条件，花括号包内容 | `if (条件) { 内容 }` |

**经典三段式场景**：

> 判断我们的分支等于哪一个 → 当等于 master 时，生产环境域名是哪个；等于 test 时，测试环境域名是哪个 → **获取到域名后，报警时把域名发到群里**。

这就是 `if` 在流水线里的核心用途：**按分支/参数动态决定后续行为与通知内容**。

## 六、必备件五：`try/catch` 异常捕获

```groovy
try {
    sh 'exit 1'                     // 发一个错误信号
    // 或者执行一个不存在的命令，如 sh 'PW'
} catch (e) {
    println "捕获到错误: ${e}"
    // 实际项目里这里发告警，带上 ${e}
}
```

**语义**：

- `try { }` 里放**可能出错的步骤**；
- 一旦某步执行出错，**立即跳进 `catch` 块**，`try` 里后续代码不再执行；
- `catch (e)` 小括号里的 `e` **就是捕获到的报错**，可以引用、可以输出、可以发告警。

**核心价值**：

> 当那个步骤执行出错了，那我们就要捕捉那一步的错误。我们就可以在捕获异常之后，再给它定一个变量名，我们再引用这个变量。**这样我们就可以通过告警，就知道是哪一个构建步骤出错了。**

对比一下就知道差别：

- **没有 try/catch**：告警只说"构建失败"，你得翻完整日志找哪一步挂的；
- **有 try/catch**：告警直接带 `第1步构建镜像失败：xxx`，一眼定位。

> Kaniko 那篇的生产级写法就是这么做的：把 `sh` 包在 `try` 里，`catch` 里拼错误信息 + `exit 1`。

## 七、必备件六：`def` 定义函数

```groovy
def printInfo(name, age) {
    println "name = ${name}, age = ${age}"
}

// 调用
printInfo("peter", 18)
printInfo("tom", 20)
```

**规则**：

- 用 `def` 定义函数，小括号里写**参数名**；
- 调用时**直接写函数名 + 小括号**；
- 传多个值用**逗号分隔**；
- **字符串要加双引号**引起来。

**什么时候用**：

> 我们在写流水线的时候，有很多的步骤都是相同的，我们都需要重复执行。这个时候我们就可以通过函数来解决代码重复使用的问题。

## 八、在哪里测试 Groovy 语法

**系统管理 → 脚本命令行（Script Console）**。

> 课件原话：这个脚本命令行，主要就是用于**测试我们的 Groovy 语法正不正确**的。

**用法**：把写好的 Groovy 粘贴进去 → 点**运行** → 下方立刻打印结果。语法有问题会直接报错，不用等跑流水线。

课件把六个必备件全贴进去跑了一遍：定义变量、取时间、for 循环、if 判断、异常捕获（故意执行不存在的命令 `PW`，`catch` 成功捕获并打印报错）、函数调用——**全部通过**。

> **这个 Console 是调试 Groovy 的第一现场**，比改 Jenkinsfile → 保存 → 构建 → 看日志快十倍。生产排查时也常用它直接查 Jenkins 内部状态。

## 九、常见报错与排查

| 现象 | 根因 | 解法 |
|---|--- --- | --- |
| `MissingPropertyException` | 变量未定义或拼错 | 检查 `def` 声明与引用名 |
| `if` 条件永远不成立 | 用了单个 `=` 或引号用错 | 字符串判断用 `==`，字符串加单引号 |
| 列表越界 | 索引从 0 开始，`list[size-1]` 才是最后一个 | 修正索引 |
| 输出全挤在一行 | `println` 未换行 | 加 `\n` 或用多个 `println` |
| `catch` 捕获不到 | 错误不在 `try` 块内 | 把可能出错的 `sh` 包进 `try` |
| 函数调用报参数数量不匹配 | 传参个数与定义不一致 | 核对 `def func(a,b)` 与 `func("x","y")` |
| 脚本命令行里能跑、流水线里报错 | 流水线有沙箱限制 | 勾"使用 Groovy 沙盒"或去脚本批准 |

## 十、面试考点与追问

**Q1：Groovy 在 Jenkins Pipeline 里写在哪？**
`script { }` 块内。声明式语法适合结构化描述（agent/stages/steps），动态逻辑（条件、循环、异常、函数）用 `script` 块写 Groovy。

**Q2：获取当前时间并拼镜像 tag 的写法？**
`new Date().format("yyyy")`、`format("MMdd")`、`format("HHmm")`、`format("ss")` 分别取年月日时分秒，拼接成 tag，如 `repo:main-20261014120533-${BUILD_ID}`。好处是唯一且可读，能反查构建时刻。

**Q3：`try/catch` 在流水线里的价值？**
精确定位失败步骤。把可能出错的 `sh` 包在 `try` 里，`catch` 捕获错误信息并拼进告警（如"第1步构建镜像失败：xxx"），比"构建失败" + 翻日志高效得多。生产级写法是 catch 里拼信息后 `exit 1`。

**Q4：`def` 函数与共享库的分工？**
`def` 函数解决**单条流水线内**的代码重复；共享库解决**跨多条流水线**的重复。前者写在 Jenkinsfile 里，后者抽到独立 Git 仓库由 Jenkins 全局加载。

**Q5：在哪里快速验证 Groovy 语法？**
**系统管理 → 脚本命令行（Script Console）**。粘贴运行立即出结果，不用改 Jenkinsfile → 保存 → 构建 → 看日志。也是生产排查 Jenkins 内部状态的常用入口。

**Q6：Groovy 的 `if` 字符串判断有什么语法要求？**
用 `==`（两个等号）而非 `=`；字符串加单引号；变量名直接写不加引号不加括号；条件用小括号、内容用花括号。写错是"条件永远不成立"的常见原因。
