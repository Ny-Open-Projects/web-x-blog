## 纲要

- 业务层直接操作 `*sql.Rows` 既冗长又重复：每次查询都要写 `Next` / `Scan` 循环
- 第一个封装 `QueryToMaps`：把整次查询结果转成 `[]map[string]interface{}`，每个 map 对应一行
- 第二个封装 `QueryOne`：只取首行，无数据时返回 `nil`，省去业务层对行数的判断
- 两个方法把「遍历 + 扫描」收口到 dogAPM 的 DB 组件里，业务侧只用拿到 map 取字段
- 实现要点：用 `Columns()` 拿列名，`RawBytes`/空接口接收每列，再按列名回填到 map
- 这两个工具方法是后面订单 / 商品 / 用户服务里所有 DB 读操作的基础

## 为什么要把 SQL 结果再包一层

在 dogAPM 项目里，订单、商品、用户三个微服务都会频繁地写 SQL。如果业务层每次都手写下面这段：

```go
rows, _ := db.Query("SELECT id, uid, price FROM t_order WHERE uid = ?", 3)
defer rows.Close()
for rows.Next() {
    var id string
    var uid int
    var price float64
    rows.Scan(&id, &uid, &price)
    // ... 处理单行
}
```

代码会非常啰嗦，而且「取哪些列」和「怎么塞进结构体」散落在各处，难以统一。更麻烦的是，不同查询返回的列集合不一样，业务侧还得为每个查询单独定义一组接收变量。

这一节要做的，是把「遍历行 + 扫描列」整件事封装成两个通用方法，让业务层只关心「我要哪张表的哪些数据」，拿到的直接是 `map[string]interface{}`，按列名取字段即可。

## QueryToMaps：整次结果转成 map 数组

第一个方法对应讲稿里的「将 SQL 得到的结果转换成一个 map 类型的数组」。核心思路是：先通过 `rows.Columns()` 拿到所有列名，再为每一行准备一组指向 `interface{}` 的指针交给 `Scan`，扫描完成后按列名回填到 map。

```go
// dogapm/db.go —— 根据讲稿逻辑补充
package dogapm

import (
	"database/sql"
)

// QueryToMaps 将一次查询的全部结果转换为 []map[string]interface{}，每个 map 对应一行
func QueryToMaps(rows *sql.Rows) ([]map[string]interface{}, error) {
	defer rows.Close()

	cols, err := rows.Columns()
	if err != nil {
		return nil, err
	}

	result := make([]map[string]interface{}, 0)
	for rows.Next() {
		// 每一行：一组值 + 一组指向这些值的指针
		values := make([]interface{}, len(cols))
		pointers := make([]interface{}, len(cols))
		for i := range values {
			pointers[i] = &values[i]
		}
		if err := rows.Scan(pointers...); err != nil {
			return nil, err
		}
		row := make(map[string]interface{}, len(cols))
		for i, col := range cols {
			row[col] = values[i]
		}
		result = append(result, row)
	}
	return result, rows.Err()
}
```

这样业务层拿到的是 `[]map`，循环处理即可，再也不用关心这次查了几列、每列是什么类型。

## QueryOne：只取首行

第二个方法对应讲稿里的「返回的单行数据」。它和 `QueryToMaps` 逻辑几乎一样，区别在于：只要 `rows.Next()` 命中第一行就立即扫描并返回，剩下的行直接丢弃。无数据时返回 `nil`，业务层拿到 `nil` 就知道「查无此记录」。

```go
// dogapm/db.go（续）

// QueryOne 只返回查询的第一行；无数据时返回 nil
func QueryOne(rows *sql.Rows) (map[string]interface{}, error) {
	defer rows.Close()

	cols, err := rows.Columns()
	if err != nil {
		return nil, err
	}
	if !rows.Next() {
		return nil, rows.Err() // 没有命中任何行
	}

	values := make([]interface{}, len(cols))
	pointers := make([]interface{}, len(cols))
	for i := range values {
		pointers[i] = &values[i]
	}
	if err := rows.Scan(pointers...); err != nil {
		return nil, err
	}

	row := make(map[string]interface{}, len(cols))
	for i, col := range cols {
		row[col] = values[i]
	}
	return row, nil
}
```

讲稿里提到的「在 query 的反馈结果上面判断返回结果的长度，如果大于零就只取一行」，本质上就是这里的 `rows.Next()` 判定：命中即返回，未命中即 `nil`。

## 为什么要统一返回 map 而不是结构体

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 直接 `Scan` 进结构体 | 类型安全、性能好 | 每个查询都要定义结构，重复样板代码多 |
| 返回 `map[string]interface{}` | 通用、业务侧无需预定义结构 | 取值时要做类型断言 / 转换 |

dogAPM 选择 map 方案，是因为后面三个微服务有大量的即席查询，且查询列经常随业务调整。用 map 可以把 DB 访问层做得极薄，业务侧配合 `cast` 这类类型转换库就能把 `interface{}` 安全地转回具体类型。代价只是一次类型转换，换来的是所有 DAO 方法签名高度一致：`(ctx,id) -> map`。

## API 速览

| API | 签名 | 说明 |
| --- | --- | --- |
| `QueryToMaps` | `func QueryToMaps(rows *sql.Rows) ([]map[string]interface{},error)` | 整次结果转 map 数组 |
| `QueryOne` | `func QueryOne(rows *sql.Rows) (map[string]interface{},error)` | 只返回首行，无数据返回 `nil` |
| `(*sql.Rows).Columns` | `func (r *sql.Rows) Columns() ([]string,error)` | 获取结果集列名 |
| `(*sql.Rows).Scan` | `func (r *sql.Rows) Scan(dest ...interface{}) error` | 将当前行写入目标指针 |
| `(*sql.Rows).Next` | `func (r *sql.Rows) Next() bool` | 游标移到下一行 |

## Demo 示例

下面给出一个**单文件可运行**的演示（根据讲稿逻辑补充），用纯 Go 的 SQLite 驱动 `modernc.org/sqlite` 模拟 dogAPM 的 DB 组件，演示 `QueryToMaps` 与 `QueryOne` 的真实行为。

**运行说明**

```bash
mkdir sqlhelper-demo && cd sqlhelper-demo
go mod init sqlhelper-demo
go get modernc.org/sqlite
# 把下方代码保存为 main.go
go run main.go
```

**代码**

```go
package main

import (
	"database/sql"
	"fmt"

	_ "modernc.org/sqlite"
)

// QueryToMaps 整次结果转成 []map[string]interface{}
func QueryToMaps(rows *sql.Rows) ([]map[string]interface{}, error) {
	defer rows.Close()
	cols, err := rows.Columns()
	if err != nil {
		return nil, err
	}
	result := make([]map[string]interface{}, 0)
	for rows.Next() {
		values := make([]interface{}, len(cols))
		ptrs := make([]interface{}, len(cols))
		for i := range values {
			ptrs[i] = &values[i]
		}
		if err := rows.Scan(ptrs...); err != nil {
			return nil, err
		}
		row := make(map[string]interface{}, len(cols))
		for i, c := range cols {
			row[c] = values[i]
		}
		result = append(result, row)
	}
	return result, rows.Err()
}

// QueryOne 只取首行
func QueryOne(rows *sql.Rows) (map[string]interface{}, error) {
	defer rows.Close()
	cols, err := rows.Columns()
	if err != nil {
		return nil, err
	}
	if !rows.Next() {
		return nil, rows.Err()
	}
	values := make([]interface{}, len(cols))
	ptrs := make([]interface{}, len(cols))
	for i := range values {
		ptrs[i] = &values[i]
	}
	if err := rows.Scan(ptrs...); err != nil {
		return nil, err
	}
	row := make(map[string]interface{}, len(cols))
	for i, c := range cols {
		row[c] = values[i]
	}
	return row, nil
}

func main() {
	db, err := sql.Open("sqlite", ":memory:")
	if err != nil {
		panic(err)
	}
	defer db.Close()

	_, _ = db.Exec(`CREATE TABLE t_order (id TEXT, uid INTEGER, price REAL)`)
	_, _ = db.Exec(`INSERT INTO t_order VALUES ('o1', 3, 9.9), ('o2', 3, 19.9), ('o3', 7, 5.0)`)

	// 整次结果
	rows, _ := db.Query(`SELECT id, uid, price FROM t_order WHERE uid = ?`, 3)
	all, _ := QueryToMaps(rows)
	fmt.Println("QueryToMaps =>", all)

	// 单行
	rows2, _ := db.Query(`SELECT id, uid, price FROM t_order WHERE id = ?`, "o1")
	one, _ := QueryOne(rows2)
	fmt.Println("QueryOne   =>", one)

	// 无数据
	rows3, _ := db.Query(`SELECT id, uid, price FROM t_order WHERE id = ?`, "not-exist")
	none, _ := QueryOne(rows3)
	fmt.Printf("QueryOne(空) => %v\n", none)
}
```

**代码说明**

- 两个方法都先 `defer rows.Close()`，调用方无需关心资源释放
- 用列名作 key 回填 map，业务侧 `row["uid"]` 即可取字段
- `QueryOne` 在 `!rows.Next()` 时直接返回 `nil`，等价于讲稿描述的「行数大于零才取一行」

**技术点总结**

- 把「遍历 + 扫描」下沉到框架层，业务侧代码量骤减
- 统一返回 `map` 让所有读操作的签名高度一致，便于后续接埋点与监控
- `Columns()` + 指针切片是 Go 中把任意结果集扫进 map 的通用范式
