## 纲要

- 全课主线：围绕一个 Web 项目，用**链路追踪 + 指标监控 + 日志采集**三板斧构建一套 APM 监控系统。
- 精细化：用 Go 的 `pprof` 把监控粒度做细，定位到具体的问题代码。
- 告警：手写自研告警系统，基于 Grafana / 日志采集暴露的 webhook 接收并分发告警。
- 拓展：讲清监控系统各组件的扩容思路（链路追踪、日志、指标）。
- 学习方法：跑官方 demo 易学用法，精通要靠研究高级特性 + 主动思考组件局限与容量上限。
- 性能分析心法：**由大到小**定位（整机 → 进程 → 代码），抽丝剥茧；先快速恢复线上，再分析根因；持续学习总结形成自己的方法论。

## 课程回顾

本课程从监控系统的基本概念讲起，带领大家基于一个 Web 项目构建 APM 监控系统，覆盖三条主线：

- **链路追踪**：用 OpenTelemetry SDK + Collector + Jaeger，把一次请求背后的调用链可视化，并解决慢查询、长事务、错误链路等问题。
- **指标监控**：用 Prometheus 采集四大黄金指标、runtime 指标，配合 Grafana 面板观察 QPS、错误数、延迟、资源占用。
- **日志采集**：用 filebeat + logstash + Elasticsearch + Kibana 把应用日志集中收集、检索与展示。

在此之上：

- 用 Go 的 **`pprof`**（含 `holmes` 自动化）把监控粒度进一步细化，能定位到具体哪一行代码引起 CPU、内存、阻塞、锁竞争等性能问题。
- 手写了一套**自研告警系统**（dogalarm），基于 Grafana 指标告警与日志采集的 webhook 接收告警，并接入电话、钉钉等通道，支持限流排重与保活自愈。
- 最后拓展讲解了监控系统自身的监控与各组件的**扩容思路**：链路追踪按 traceID 哈希建 Collector 集群、ES 加 Kafka 缓冲；日志用 logstash 集群与双时间戳算延迟；指标按服务维度拆分 Prometheus 节点。

## 如何掌握大量监控组件

课程涉及组件很多，一次性全掌握对不熟悉的同学有难度。建议分两层：

- **入门易**：跑官方简单 demo，试一下某属性怎么配、出现什么效果，就能了解基本用法。
- **精通难**：要去官网研究组件的高级特性，并**主动思考它的使用局限**。比如用 Prometheus 时要想：它的容量上限在哪？达到上限后怎么扩容？容量瓶颈往往先表现为查询性能变差，这时就要从架构乃至 CPU/内存层面去优化。养成"衡量一个组件性能"的习惯，是精通监控组件的关键。

## 性能问题分析心法

整门课程的最终目的，是让大家能便捷地发现并分析项目中的性能问题。两点要牢记：

- **由大到小、抽丝剥茧**：分析性能问题不是毫无章法，而是从整机到进程再到代码逐层缩小范围，像侦探一样逐一排除、定位线上事故的根因。
- **先恢复、后分析**：发生性能问题时，第一优先级是快速恢复线上正常环境，然后再分析产生问题的原因。性能问题涉及的知识面很广，可能包含从未接触过的内容，唯有保持学习热情、不断总结，才能形成自己的一套方法论。
