## 纲要

- compose 是什么：用单个 YAML 文件定义并运行多个容器应用服务的编排工具
- 一条命令即可创建并启动配置好的全部服务
- compose 文件的核心组成：version、services、networks、volumes
- `services` 下每一项是一个容器，可自由命名
- 关键配置项：image（镜像）、容器资源限制（CPU / 内存 / IO）、环境变量、端口映射
- 本课程以 APM 为主，compose 命令不多，用到时逐一讲解配置含义

## compose 是什么

Docker 官网对 compose 的定义是：一个**定义并运行多个 Docker 容器应用服务的工具**。借助 compose，你可以用一个 YAML 文件来配置你的应用服务，并且**仅用一条命令**就能创建并启动所有配置好的服务。

换言之，compose 是一个服务编排工具，能用一条简单的命令把你编排好的服务同时创建并启动起来。

## compose 文件的组成

compose 使用 YAML 文件描述应用。一个完整的文件通常由以下几部分组成：

```yaml
version: "3.8"   # 版本号
services:        # 要启动的各个容器服务（必填）
  app:
    image: nginx:latest
    deploy:
      resources:
        limits:
          cpus: "0.5"
          memory: 256M
networks:        # 自定义网络（可选）
  app-net:
volumes:         # 数据卷（可选）
  app-data:
```

其中 `services` 是必填项，其余可按需省略。

## services 下如何配置容器

`services` 下可以定义多个应用服务容器。每一项的第一层 key（如示例中的 `app`）是开发者自由命名的应用服务名称，其下才是该容器的具体配置。

可以在 compose 文档中按需查询每个配置项的含义。以容器的资源限制为例：

```yaml
services:
  app:
    image: nginx:latest   # 启动该容器所使用的镜像
    deploy:
      resources:
        limits:
          cpus: "0.5"     # 限制最多使用 0.5 个 CPU
          memory: 256M    # 限制内存上限 256MB
```

- `image`：容器启动时使用的镜像名；
- 资源限制：容器能独立地对 CPU、内存、IO 等硬件资源做限制（上面的 `cpus` 与 `memory` 即 CPU、内存限制配置）。

更多配置项（端口映射、环境变量、重启策略、依赖关系等）将在后续搭建 APM 组件时按需讲解——本课程以 APM 系统为主，涉及的 compose 命令不多，只需在搭建时理解每个配置项的含义即可。

## API 速览

| 配置项 | 位置 | 说明 |
| --- | --- | --- |
| `version` | 文件顶层 | compose 文件格式版本 |
| `services` | 文件顶层 | 必填，定义要启动的容器服务集合 |
| `image` | `services.<name>` 下 | 容器使用的镜像 |
| `deploy.resources.limits` | `services.<name>` 下 | 容器 CPU / 内存 / IO 资源限制 |
| `networks` | 文件顶层 | 可选，自定义网络 |
| `volumes` | 文件顶层 | 可选，数据卷 |
