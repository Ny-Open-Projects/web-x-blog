## 纲要

- 前面的装饰器还差两块：执行出错时调用 `OnError`，以及把参数"真实值"传给 hooks
- `OnError` 接入点：每个方法在底层返回错误后，先调用 `hooks.OnError` 再向上返回错误
- 参数修正：之前 `nameValuesToInterface` 传的是整个 `driver.NamedValue` 类型，应改成取 `a.Value`，日志 / 属性才能显示真实参数
- 验证：故意查询一张不存在的表，`Before` 正常执行、`After` 不执行（查询提前失败）、`OnError` 触发并打印错误
- 三个 hooks 全部验证完毕，装饰器已能在 SQL 前后插入任意业务逻辑

## 补上 OnError 调用

此前每个方法在底层返回错误时只把错误原样返回，还没有通知 `OnError`。补全方式一致：拿到 `err` 后先调 `hooks.OnError`，再把结果回传。

以 `wrapperConn.QueryContext` 为例（其余方法同理）：

```go
// sqlwrapper/conn.go 片段 —— 根据讲稿逻辑补充
func (c *wrapperConn) QueryContext(ctx context.Context, query string, args []driver.NamedValue) (driver.Rows, error) {
	if ctx, err := c.hooks.Before(ctx, query, args); err != nil {
		return nil, err
	}
	rows, err := c.conn.QueryContext(ctx, query, args)
	if err != nil {
		if e := c.hooks.OnError(ctx, query, args, err); e != nil {
			return nil, e // OnError 自身若返回错误，优先返回它
		}
		return nil, err
	}
	if err := c.hooks.After(ctx, query, args); err != nil {
		return nil, err
	}
	return rows, nil
}
```

`wrapperConn.ExecContext`、`wrapperStmt.QueryContext`、`wrapperStmt.ExecContext` 用同样的方式补上 `OnError` 调用即可。

## 修正参数取值：传真实值而非类型

此前留下的 `nameValuesToInterfaces` 有个隐患——它把整个 `driver.NamedValue` 放进了切片：

```go
out[i] = a // 传的是 driver.NamedValue 类型本身
```

`driver.NamedValue` 是个结构体（`Name`、`Ordinal`、`Value`），直接打印出来看到的是结构体而非用户实际传入的参数值，日志和 Span 属性都会失真。正确做法是取它的 `.Value` 字段：

```go
// sqlwrapper/util.go —— 根据讲稿逻辑补充（修正版）
package sqlwrapper

import "database/sql/driver"

// nameValuesToInterfaces 取每个命名参数的真实值，便于日志 / 属性展示
func nameValuesToInterfaces(args []driver.NamedValue) []interface{} {
	out := make([]interface{}, len(args))
	for i, a := range args {
		out[i] = a.Value // 取真实参数值，而非 NamedValue 类型
	}
	return out
}
```

这样 hooks 里 `Before` / `After` / `OnError` 拿到的参数，才是业务真正传给 SQL 的 `1`、`"abc"` 这类值。本系列代码统一改用这个修正版。

## 验证：用不存在的表触发错误链路

写一个测试方法，注册 `testDriver`，然后查询一张不存在的表：

```go
// 测试片段（示意）—— 根据讲稿逻辑补充
func TestOnError(t *testing.T) {
	Register("mysql-with-hooks", Hooks{
		Before: func(ctx context.Context, q string, a []driver.NamedValue) (context.Context, error) {
			fmt.Println("before:", q, nameValuesToInterfaces(a))
			return ctx, nil
		},
		OnError: func(ctx context.Context, q string, a []driver.NamedValue, err error) error {
			fmt.Println("onerror:", q, "err:", err)
			return nil
		},
	})

	db, _ := sql.Open("mysql-with-hooks", "user:pass@tcp(127.0.0.1:3306)/test")
	_, _ = db.Query("SELECT * FROM not_exist_table")
}
```

运行结果符合预期：

- `Before` 正常执行并打印 SQL 与真实参数；
- 查询因表不存在而提前失败，`After` **不会被调用**；
- `OnError` 被触发并打印底层错误。

至此，`Before` / `After` / `OnError` 三个钩子全部验证通过，装饰器已具备在 SQL 执行前后插入任意业务逻辑的能力——下一步就是把"统计 SQL 耗时、标记慢查询"这段真实业务填进 hooks。

## 技术点总结

- 每个方法底层返回错误后，要先调 `OnError` 再回传错误
- 参数必须取 `driver.NamedValue.Value`，否则日志 / 属性显示的是结构体而非真实值
- 错误场景下 `After` 不会执行，链路由 `OnError` 收尾
- 三个 hooks 验证完毕后，装饰器骨架完整可用
