## 纲要

- gRPC 面板是前述中 HTTP 面板的**复制 + 改协议标签**，无需从零搭建
- 唯一差异：指标过滤条件把 `type="http"` 改成 `type="grpc"`
- gRPC 的**成功状态码是 `0`**，因此错误数统计 `status != "0"`（与 HTTP 的 `status != "200"` 不同）
- 三类面板（QPS、P99 延迟、错误数）与 HTTP 一一对应，同属黄金指标分类

## 正文

### 为什么需要单独建 gRPC 面板

此前建 HTTP 面板时，如果当时没有在 PromQL 里限定 `type="http"`，那么 gRPC 请求进来后也会被 `server_handle_*` 这些通用指标捕获，直接出现在 HTTP 面板里——因为指标名相同，只是 `type` 标签值不同。加上 `type="http"` 过滤后，HTTP 面板就只显示 HTTP 接口了。

因此 gRPC 面板不需要重新设计，只要把 HTTP 的三个面板**逐个复制**，把过滤条件里的 `type` 值由 `http` 改为 `grpc` 即可。三者的查询逻辑（rate / histogram_quantile / 错误过滤）完全一致，只有协议标签值不同。

### QPS 面板（type=grpc）

```promql
sum by (method) (rate(server_handle_total{app="$app", host=~"$host", type="grpc"}[$__rate_interval]))
```

### P99 延迟面板（type=grpc）

```promql
histogram_quantile(0.99, sum by (method, le) (rate(server_handle_seconds_bucket{app="$app", host=~"$host", type="grpc"}[$__rate_interval])))
```

### 错误数面板（成功码=0）

HTTP 用 `status!="200"` 判定错误；gRPC 的**成功状态码是 `0`**，失败才是非零，因此错误数要统计 `status != "0"`：

```promql
sum by (method) (rate(server_handle_seconds_count{app="$app", host=~"$host", type="grpc", status!="0"}[$__rate_interval]))
```

## 技术点总结

- gRPC 面板 = 复制 HTTP 面板，仅把 `type="http"` 改为 `type="grpc"`
- gRPC 成功状态码为 `0`，错误数用 `status != "0"`（区别于 HTTP 的 `!= "200"`）
- 指标名、查询函数与 HTTP 完全相同，靠 `type` 标签值区分协议
