> 原文锚点：第 1~91 段「缓冲池链表管理…重做日志写入流程…写满会发生什么」

## 思路与架构

这一节的知识可以拆成**两条主线**：内存里怎么组织页，磁盘上怎么保证持久。两条线在"检查点"处交汇。

**主线一：缓冲池的页管理。** 缓冲池是一片连续内存，运行一段时间后空闲页与已用页混杂。若每次都从头遍历找页，代价不可接受。于是 InnoDB 把**控制块**当链表节点用：空闲页的控制块串成 free 链表，加载新页时摘一个节点、填好信息、移出链表；被修改的页成为脏页，其控制块挂进 flush 链表，后台线程只需遍历这条链表就能刷盘；干净页由 LRU 链表管理以便淘汰。三链分工的本质，是把"扫描"变成"摘挂"。

**主线二：预写日志。** 事务开始分配标识并记开始信息；执行修改时先更新内存中的数据页、同时把重做日志写进日志缓冲；随后日志缓冲按策略刷到磁盘上的日志文件——这是**顺序写**，性能好；最后提交时记下提交信息并再次刷盘，事务的持久性就此成立。注意关键一句：**提交时数据页通常还没落盘**，落盘的只是日志。崩溃后未刷盘的数据页靠重放日志恢复，这就是 WAL（预写日志）。

刷盘的时机不止提交一条：日志缓冲占用过半、缓冲被写满、检查点、后台周期线程、服务关闭，都会触发。而"提交时是否立即落盘"还要看刷盘参数——设 1 是每次提交同步到磁盘，设 0 与设 2 都退化到每秒一次，只是设 2 时日志已进系统缓冲，服务崩溃不丢、操作系统崩溃才丢。

**交汇点：检查点。** 重做日志空间固定、循环写。写满时先自动触发检查点，把脏页刷回磁盘以释放日志空间；刷不及就暂停新写入，表现为写入延迟抖动；释放出的记录标记为可覆盖，日志回到开头继续。调大日志能降低写满频率，但崩溃恢复要重放的日志更多，恢复时间变长——这是本节最典型的权衡。

## 方案取舍

| 决策 | 选项 | 取舍 |
|---|---|---|
| 刷盘策略 | 0 / 1 / 2 | 1 最安全但每次提交都 IO；0 与 2 换吞吐，丢数据窗口约 1 秒 |
| 日志容量 | 默认 / 调大 | 调大减少写满抖动，代价是崩溃恢复变慢 |
| 事务粒度 | 逐条 / 批量 | 批量化降低日志写入压力，但单事务过大拉长回滚与锁持有 |
| 检查点策略 | 默认 / 调优 | 频率高则写放大，频率低则写满风险高 |
| 脏页刷盘 | 后台异步 / 同步 | 异步保证响应，极端情况退化为暂停写入 |

取舍要点：

- **持久性由日志担保，不由数据页担保。** 这条理解错了，后面所有的刷盘问题都会答偏。
- **"双一"不是越严越好。** 它对写入吞吐的影响是实打实的，非金融场景常放宽二进制日志同步以换性能。
- **日志容量没有免费午餐。** 调大降低抖动与提高恢复时间是同一枚硬币的两面，须按业务的恢复时长目标反推容量。
- **区分服务崩溃与系统崩溃。** 丢数据窗口的边界必须说到这一层，否则只是背结论。

## 答题技巧

1. **用"内存组织 + 磁盘保证"两条线开场。** 有骨架的回答比散点强，也能自然引出检查点这个交汇点。
2. **把"提交时数据页没落盘"作为分水岭。** 答出这一句，基本可以确认理解 WAL。
3. **丢数据边界说到崩溃层级。** "设 2 时服务崩溃不丢、系统崩溃丢约 1 秒"这类精确表述，是 P7 的直接信号 `[经验]`。
4. **版本栅栏别漏。** 8.0.30 起重做日志改为容量参数（默认 100MB），报得出这个变化说明关注过新版本 `[源码]`。
5. **调优题必须给代价。** 每提一个优化就顺手说它换来什么——调大日志换恢复时间，批量化换锁持有时长 `[经验]`。

## 细节与核心 API

**缓冲池三链表（把"扫描"变成"摘挂"）**：

```text
free 链表  ：空闲页控制块，加载新页时摘一个节点填信息、移出链表
flush 链表 ：脏页控制块，后台线程遍历此链刷盘
LRU 链表   ：干净页淘汰管理
```

**WAL 预写日志四步（提交时数据页通常还没落盘，落盘的是日志）**：

```text
事务开始记标识 → 改内存页 + 写日志缓冲 → 日志缓冲按策略刷盘(顺序写)
             → 提交记提交信息再刷盘，持久性成立
刷盘时机：提交 / 日志缓冲过半 / 写满 / 检查点 / 后台周期 / 服务关闭
```

**刷盘参数 `innodb_flush_log_at_trx_commit`**：

```ini
1  每次提交 fsync（最安全）
0  每秒一次（约丢 1 秒）
2  每秒一次，但日志已进系统缓冲 → 服务崩溃不丢、操作系统崩溃丢约 1 秒
# 8.0.30+ 重做日志改为容量参数（默认 100MB）
innodb_redo_log_capacity = 100MB   # 旧版：innodb_log_file_size × innodb_log_files_in_group
```

> 边界：doublewrite 见 1212；脏页/空闲页管理见 1216；两阶段提交见 1208/124；本卡只讲重做日志与缓冲池协同。
