> 原文锚点：第 48~62 段「页落盘写到一半宕机；file trailer 校验和对比 header 检半写；后4B=LSN；MTR=一组 redo log 不可分割恢复」

## 一句话总述
16KB 数据页刷盘可能"写一半"宕机，InnoDB 靠 **file trailer** 兜底：其**前 4B 是校验和**，与 file header 里的校验和对比——一致=页完整，不一致=刷盘中断（半写）。**后 4B 是 LSN**（日志序列号，= 已写入 redo log 的量）；redo log 以 **MTR（mini transaction，对一页的一次原子访问，如 B+树插一条记录）** 为组写入，崩溃恢复时一组 MTR 的 redo log **不可分割地整体重放** `[经验]`。

## 面试官视角
- 考察意图：是否理解"InnoDB 怎么保证页落盘原子性"，这是 redo/B+树恢复的地基。
- 分档：P5 知 file trailer 校验防半写；P6 知 LSN 含义 + MTR 概念；P7 能讲清"MTR 不可分割恢复"与"校验和头尾不一致=半写"。
- 红旗：以为 16KB 页刷盘是原子的；或不知 LSN 与 redo log 量的关系。
- 惊艳点：点出"校验和头尾对比是检测半写的最简手段——header 先同步、trailer 后同步，中断则两者不同"；以及"MTR 把多次页修改打包成原子恢复单元"。

## 主问答
**Q（面试官原话）：** 数据页刷盘写到一半机器宕机，InnoDB 怎么知道？
**A：**
1. **半写检测**：file trailer 的**前 4B = 校验和**，与 file header 中的校验和对应。刷盘时 header 先同步、trailer 后同步；若中途断电，header 已是新页校验和、trailer 还是旧页校验和 → **两者不一致即判定半写**，恢复时丢弃/重放 `[经验]`。
2. **LSN**：file trailer 后 4B 是 **LSN（Log Sequence Number）**，表示当前已写入 redo log 的日志量；向 log buffer 写 redo 时以 MTR 为单位，每写一组 LSN 增长对应字节数（初始 LSN=8704，对应文件偏移 2048）。
3. **MTR 原子恢复**：**MTR（mini transaction）**= 对底层页的一次原子访问（如向 B+树索引插一条记录），包含一组 redo log；崩溃恢复时这组 redo **作为不可分割整体**重放，保证页修改要么全有要么全无。

## 总结与追问预判
页级崩溃恢复 = file trailer 校验和(防半写) + LSN(redo 位点) + MTR(原子重放单元)，是 redo/B+树恢复的地基。页结构见 1216；页目录见 1216；存储引擎层见 1210。
