## 思路与架构
map 底层实现题的架构是"**选型 → 冲突 → 结构 → 定位 → 注意**"五层：
- **选型层**：map 两种理论实现——哈希查找表（Go 选）vs 搜索树（AVL/红黑树）；哈希表均摊 O(1) 但有冲突。
- **冲突层**：链表法（Go 用，桶+溢出链）vs 开放地址法（探测序列，Go 不用）。
- **结构层**：hmap + bmap（top hash + keys[8] + values[8]，bucketCnt=8，溢出链）。
- **定位层**：低 B 位定桶、高 8 位 top hash 定桶内，均摊 O(1) 最差 O(N)。
- **注意层**：并发不安全（panic）/ float key / 无序。

## 方案取舍
| 维度 | 哈希表(Go) | 搜索树 |
|---|---|---|
| 查找 | 均摊 O(1)，最差 O(N) | 稳定 O(log N) |
| 冲突 | 链表法 | 无需冲突处理 |
| 有序 | 否（无序） | 是（中序有序） |
| 适用 | key 无顺序需求 | 需范围/有序遍历 |

**取舍**：Go 选哈希表因均摊更快、实现简单；要有序遍历须另排 key。

## 答题技巧
1. **先选型**：开口"map 是哈希查找表，不是红黑树"，显出与 1218 搜索树对比的视野。
2. **讲结构**：hmap/bmap + top hash + bucketCnt=8 + 溢出链，一轮讲清。
3. **定位算法**：低 B 位定桶、高 8 位 top hash，强调 top hash 先粗筛。
4. **三注意必答**：并发 panic / float key / 无序，接 sync.Map（见 107）。
5. **边界声明**：本卡聚焦 Go map 底层；哈希 vs 搜索树通用选型见 1218、并发安全 map 见 107、nil map 见 414、map 作参数见 923，均不重产。

## 细节与核心 API

```go
// 底层 hmap：buckets（2^B 个 bmap），每个 bmap 存 8 个 kv + tophash（key 哈希高 8 位）
// 查找：hash(key) -> B 位定 bucket，tophash 快速比对，再比 key 全等
// 负载因子触发扩容的阈值为 6.5（平均每个 bucket 6.5 个键）
// 迭代：从随机 bucket 起始，顺序遍历（因此 map 遍历顺序随机，故意防依赖）
m := map[string]int{"a": 1}
v, ok := m["a"]          // ok 区分“不存在”与“值为零”
// 并发读写 map 会直接 fatal error（不是 panic，无法 recover）——必须用 sync.Map 或加锁
// delete(m, "a") 仅标记 tombstone，空间延后回收
```
