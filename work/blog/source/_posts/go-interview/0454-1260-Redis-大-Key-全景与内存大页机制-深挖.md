## 一句话总述
本源把大 Key 串成"**定义→影响→处理**"一条线，并深挖两个底层机制：**fork 写时复制**（持久化时拷贝物理内存，大 Key 让复制极耗时）与**内存大页**（2MB 页使写时复制拷贝量从 4KB 放大到 2MB）。面试按"量化定义→六影响→六处理→底层机制"四步走，并明确与既有卡边界：持久化机制见 1253-*。

## 思路与架构
- **定义层**：经验线 1MB/1万，场景线 10KB，按耗时上报量化。
- **影响层**：内存/单线程/网络/持久化/主从/集群六线。
- **处理层**：拆/UNLINK/短过期/淘汰/扫描/压缩六法。
- **底层机制层**：fork 时内核复制父进程页表（不拷物理内存）；子进程改大 Key 触发写时复制拷贝物理内存；内存大页让单次拷贝从 4KB 升到 2MB。
- **边界**：与 1253(RDB/AOF/hybrid)互补，本卡只讲"大 Key 如何拖累持久化"，不重复持久化机制本身。

## 方案取舍
- **拆 vs 不拆**：拆解决单 key 体积与删除阻塞，但增加 key 数量与访问复杂度（需聚合 MGET）；小业务可接受不拆、用 UNLINK+短过期兜底。
- **UNLINK vs DEL**：UNLINK 异步、主线程零阻塞，是大 Key 删除唯一推荐；DEL 仅适合小 key。
- **LRU vs LFU**：LRU 看最近访问、易被扫描污染；LFU 看访问频率、更准逐出真正低频大 Key。
- **压缩存储**：省带宽但增 CPU；命中即作 gzip 流可免服务端解压，是"以算换带宽"的划算 trade。

## 答题技巧
1. **开口定调**："大 Key 无统一标准，按业务延迟定义"。
2. **给影响**：单线程阻塞 + 持久化写时复制（重点）+ 集群倾斜。
3. **抛处理**：UNLINK 异步删 + 集合取模拆分 + 压缩。
4. **挖底层**：内存大页放大写时复制拷贝量，秒杀深挖点。
5. **关联延展**：提 1253 持久化、1261 一致性，显示边界意识。

## 细节与核心 API

**大 key 识别与异步删除（UNLINK 主线程零阻塞，DEL 仅适合小 key）：**

```bash
redis-cli --bigkeys            # 扫描统计各类型最大 key
redis-cli MEMORY USAGE bigkey  # 看单 key 内存占用
UNLINK bigkey                  # 异步释放，引用计数 + 后台 unlink 线程
# 集合拆分：取模拆成 N 个子 key，读时 MGET 聚合，删时逐个 UNLINK
```

**gzip 压缩存储（以算换带宽，命中即作 gzip 流免服务端解压）：**

```go
var buf bytes.Buffer
gz := gzip.NewWriter(&buf)
gz.Write(payload)
gz.Close()
cache.Set(key, buf.Bytes(), ttl)
```

**内存大页放大写时复制（fork 时单次拷贝从 4KB 升到 2MB）：**

```conf
# Redis 官方建议关闭透明大页（THP），避免持久化 COW 拷贝量爆炸
# Linux 临时关闭：
echo never > /sys/kernel/mm/transparent_hugepage/enabled
# redis.conf 也可配合 disable-thp yes（部分发行版/版本支持）
```
