> 分类：Go 语言基础 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**切片传参**/**底层数组共享**/**重新赋值**
> 原文锚点：第 1~26 段「切片传参实际传的是直接部分…重新赋值后修改不影响外层」

## 一句话总述
切片传参拷贝的是 **slice header（直接部分）**，底层数组（间接部分）被共享；因此**函数内改元素会反映到外层**，但**函数内对参数重新赋值**只会改变函数内 header 的指向，不影响外层切片。

## 面试官视角
- 考察意图：能否区分"改元素"与"改参数本身"两种操作的不同后果。
- 分档：P5 知切片传参能改内容；P6 知重新赋值不影响外层；P7 能讲清 header 拷贝 + 底层共享的机制。
- 红旗答案：以为"切片传进去就完全独立"或"重新赋值也影响外层"。
- 惊艳点：现场画 header(ptr/len/cap)，说明"改 *ptr 共享、改 header 不共享" `[经验]`。

## 主问答
**Q（面试官原话）：** 切片当参数传进去，函数里改了外面看得见吗？
**A：**
1. **结论**：看得见——前提是"通过切片下标改元素"；若是"对参数重新赋值一个新切片"，则只影响函数内自己。
2. **机制**：传参拷贝 header，双方 ptr 指向同一底层数组。下标赋值 `s[0]=5` 改的是共享数组，外层自然变；而 `s = newSlice` 是把函数内的 header 指针换成别处，外层 header 毫发无损。
3. **边界**：只要没发生**扩容**，函数内对底层数组的任何写入外层都看得到；扩容会换底层数组（见 923）。

**加分层：** 用 `fmt.Printf("%p", &s[0])` 对比函数内外首元素地址，可直观证明"同一底层数组"。

## 关键代码
```go
func modify(s []int) {
    s[0] = 5        // 改共享底层数组 → 外层能看到
    s = []int{9, 9} // 只改函数内 header 指向 → 外层不变
}
func main() {
    a := []int{1, 2, 3}
    modify(a)
    fmt.Println(a) // [5 2 3]：下标改生效，重赋值不生效
}
```

## 总结与追问预判
切片传参核心："改元素共享、改参数不共享"。验证靠对比底层数组首地址。追问接"append 扩容换地址"与"直接/间接部分模型"。
