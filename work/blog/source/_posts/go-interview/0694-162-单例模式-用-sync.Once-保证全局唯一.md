## 一句话总述
单例保证进程内某类型只有一个实例并对外提供全局访问点；Go 里用 `sync.Once` 做并发安全的懒加载最地道，裸 `if instance==nil` 在并发下会建出多个。

## 面试官视角
- 意图：是否知道并发下双检锁的坑，以及 Go 的地道写法。
- P5 知用包级变量/Once / P6 说清 Once 保证恰好一次 / P7 知 Once 不能重置、不适合需重新初始化的场景。
- 红旗：手写 `if nil` 不加锁；以为包级变量在 init 外才安全；把 Once 当可重入锁用。
- 惊艳点：`sync.Once.Do` 在 N 个 goroutine 并发调用时只执行一次 f，且 Do 返回前其他调用阻塞等待完成 —— 验证：`go test -race` + N 协程计数，go1.26.5 `[源码]` runtime。

## 主问答
**Q（面试官原话）：** Go 里怎么写一个并发安全的单例？
**A：**
1. **结论**：用包级 `var` + `sync.Once`，在 `GetInstance` 里 `once.Do(func(){...})` 创建，保证只建一次。
2. **机制**：`Once` 内部用原子标志 + mutex，首个进入者执行 f，其余阻塞直到完成，避免重复初始化 `[源码]`。
3. **边界**：`Once` 不可重置，进程级单例若需热重启/多套配置应改用工厂或显式注入，不要复用同一个 Once。
**加分层：** 若实例创建极轻量、无依赖，直接用包级变量在 init 初始化比 Once 更简单且无运行时开销。

## 关键代码
```go
// 示意，未验证：并发安全单例
package singleton

import "sync"

type Config struct{ /* ... */ }

var (
	once     sync.Once
	instance *Config
)

func GetInstance() *Config {
	once.Do(func() { instance = &Config{} })
	return instance
}
```
