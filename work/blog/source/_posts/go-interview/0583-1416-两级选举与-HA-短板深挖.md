> 覆盖源 14-16 的机制延伸：控制器选举与分区 leader 选举的两级架构、ZooKeeper 过半机制为什么 3 节点、故障转移期间的数据语义、HA 的剩余短板（unclean 选举/跨机房）。主卡已给五支柱，本附录做选举与短板深挖。

## 思路与架构

```text
Kafka 的两级选举架构
├─ 第一级: 控制器选举 (集群级, 一个集群一个)
│   ├─ 旧: ZK 临时节点抢占 (先到先得, 会话失联则重选)
│   ├─ 新(KRaft): Raft 仲裁 quorum 投票
│   └─ 职责: 分区 leader 选举/副本管理/分区迁移指挥
├─ 第二级: 分区 leader 选举 (分区级, 每分区一个)
│   ├─ 控制器从 ISR 中选新 leader
│   └─ unclean.leader.election 关闭时宁可不选(停写)
├─ ZooKeeper 自身 HA
│   ├─ 过半机制: 3 节点容忍 1 挂, 5 节点容忍 2 挂
│   └─ 偶数节点无收益 (过半计算) -> 用奇数
└─ HA 短板清单
    ├─ ISR 全下线且 unclean 关闭 -> 分区停写
    ├─ unclean 开启 -> 可能丢已确认消息
    └─ 单机房部署 -> 机房级故障无解 (需跨机房/机架感知)
```

## 方案取舍
- **两级选举的职责切分**：控制器选举决定「**谁来指挥**」，分区 leader 选举决定「**谁来读写**」。控制器是集群单例（指挥官），分区 leader 是分区内多实例（每个分区一个）。两级都要高可用：指挥官挂了重选指挥官，士兵挂了在幸存者里提拔——把两级混着答（「leader 挂了就重新选举控制器」）是典型混乱 [经验]。
- **ZK 为什么至少 3 节点**：过半（quorum）机制下，N 节点容忍 ⌊(N-1)/2⌋ 个故障——2 节点容忍 0（任一挂即失 majority），3 节点容忍 1。**偶数无收益**：4 节点与 3 节点同样只容忍 1 挂（4/2+1=3，挂 2 即失去过半），却多一台成本。这不是 Kafka 特例，是所有 quorum 系统（etcd/raft）的通用算术 [经验]。
- **故障转移期间的数据语义**：leader 挂 → ISR 内选新 leader → 已被 ack 的消息（acks=all 时已在 ISR 落盘）不丢；但若 ISR 全部下线且 `unclean.leader.election.enable=false`（默认），分区**宁停不丢**；开启 unclean 则可能**丢消息换可用**——可用性与一致性的开关就在这一个参数上，交易类必须关闭 [经验]。
- **五支柱之外的短板清单**：HA 不是全覆盖——① ISR 全灭+unclean 关闭=停写（可用性受损）；② unclean 开启=可能丢数据（一致性受损）；③ 单机房部署防不了机房级故障（需机架感知 `broker.rack` 或跨机房镜像 MirrorMaker）；④ 消费端 lag 不会被 HA 机制保护（堆积治理是另一专题）。**答 HA 主动列「HA 保护不了什么」**，是从背机制到懂运维的分界 [经验]。

## 答题技巧
- 五支柱报完立刻分层：「ZK/控制器是控制面，副本机制是数据面，心跳检测和扩容是运维面」——三层结构一目了然 [经验]。
- 主动报 KRaft：「ZK 方案在 4.0 已移除，现在答 KRaft 才是现行版本」——版本意识强加分 [经验]。
- 被问「ZK 几个节点」→ 3 起步、奇数、过半算术现场推导（4 节点无收益）[经验]。
- 被问「leader 挂了消息会丢吗」→ 分三段：acks=all+ISR 内选=不丢；ISR 全灭+unclean 关=停写；unclean 开=可能丢——语义与参数挂钩 [经验]。
- 主动边界到 `1416-kafka-high-availability`（五支柱主线）、`147-isr-replication`（ISR 细节）、`1417-producer-acks`（acks 语义）、`148-rebalance-process`（消费组 rebalance，勿混）、`1413-kafka-exactly-once`（事务层保障），构成「Kafka 可靠性」专题 [边界]。

## 细节与核心 API

**两级选举配置（ZK 旧 / KRaft 新，4.0 移除 ZK）：**

```properties
# 分区 leader 选举：控制器从 ISR 选；unclean 关闭=宁可停写不丢数据
unclean.leader.election.enable=false   # 0.11+ 默认 false，交易类必须关
min.insync.replicas=2                  # 配合 acks=all，副本不足时拒绝写入
```

**ZK 过半算术（所有 quorum 系统通用）：**

```text
N 节点容忍 ⌊(N-1)/2⌋ 故障：2 节点容忍 0（任一挂失 majority），3 节点容忍 1
偶数无收益：4 节点与 3 节点同样只容忍 1 挂（4/2+1=3，挂 2 即失过半），却多一台成本 → 用奇数
```

**HA 短板清单（主动列"保护不了什么"）：**

```text
① ISR 全灭 + unclean 关闭 = 停写（可用性损）
② unclean 开启 = 可能丢已确认消息（一致性损）
③ 单机房部署防不了机房级故障（需 broker.rack 机架感知 / MirrorMaker 跨机房）
④ 消费端 lag 不被 HA 机制保护（堆积是另一专题）
```
