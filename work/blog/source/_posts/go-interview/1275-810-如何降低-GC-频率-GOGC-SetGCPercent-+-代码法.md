## 一句话总述
降低 GC 频率有两条路：① **参数法**——环境变量 `GOGC`（默认 100，表示存活堆增长 100% 触发下次）或 `debug.SetGCPercent(n)`（默认同 GOGC，返回旧值），调大即降频但增堆占用；② **代码法**——避免循环里 `defer`、避免热点分配大量短生命对象、大对象用指针传值权衡、用 `sync.Pool` 复用临时对象减少分配/回收。

## 面试官视角
- 意图：考察降频的可调旋钮与代码级优化手段，以及"调大 GOGC 的代价"。
- P5 知 GOGC / SetGCPercent / sync.Pool；P6 知 GOGC 默认 100、SetGCPercent 返回值旧值、代码四招；P7 知调大 GOGC 的权衡（降频但增堆、增单次工作量）、值类型 vs 指针对 GC 追踪范围的影响。
- 红旗：以为设 GOGC=off 是"优化"（实为关 GC 看压力，非生产）；或盲目 sync.Pool 一切对象。
- 惊艳点：点出"值类型减少指针、缩小 GC 追踪范围，但大对象仍用指针省拷贝"的权衡 `[边界]` 见 810（触发机制）、811-go-runtime-allocator（分配与追踪）、1006-setmemorylimit（软限制）。

## 主问答
**Q（面试官原话）：** 怎么减少 GC 的触发频率？
**A：**
1. **参数法 GOGC**：环境变量 `GOGC` 默认 100，含义是"存活堆较上次 GC 增长 100% 触发下次"；调大（如 200）降频，但增加内存占用与单次 GC 工作量，需慎重。
2. **参数法 SetGCPercent**：`debug.SetGCPercent(n)` 默认同 GOGC，入参是新分配量/上次剩余量的触发比例，返回设置前的旧值，便于还原。
3. **代码法-避坑**：避免在循环中使用 `defer`（函数结束才执行，延迟函数堆积栈上）；避免热点代码分配大量短生命对象（增扫描/清理开销）。
4. **代码法-复用**：尽量用值类型（指针会扩大 GC 追踪范围，但大对象用指针省拷贝需权衡）；用 `sync.Pool` 等复用临时对象，减少分配与释放次数。

## 关键代码
```go
package main

import (
	"runtime/debug"
	"sync"
)

func main() {
	prev := debug.SetGCPercent(200) // 调大=降频、增堆占用；返回旧值(默认100)
	_ = prev

	// 代码法：sync.Pool 复用临时对象，减少分配/回收次数
	p := &sync.Pool{New: func() any { return new([1024]byte) }}
	buf := p.Get().(*[1024]byte)
	defer p.Put(buf) // 用完归还池，下次 Get 复用
}
```
