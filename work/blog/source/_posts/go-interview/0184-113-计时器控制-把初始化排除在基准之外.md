> 分类：Go 测试 | 难度：L3 | 题型：实操题 | 频率：中 | 关键词：**ResetTimer**/**StopTimer**/**StartTimer**/**排除初始化**/**预热**

> 原文锚点：第 59~75 段「初始化干扰问题与三种计时器控制」

## 一句话总述
基准函数里的初始化代码不该计入耗时，用三种计时器控制排除：`ResetTimer` 重置后从下一行重新计时；`StopTimer` / `StartTimer` 配对使用可暂停再恢复，两段之间的耗时完全不计入。排除干扰后，同一函数的执行次数与单次耗时会回到真实水平。

## 面试官视角
这题区分「跑过 benchmark」和「跑对 benchmark」。考官想听你主动说「准备数据的耗时必须排除」。能讲清 Reset 与 Stop/Start 的适用场景差异（一次性前置 vs 循环内间歇），就是实战派。

## 主问答
**Q（面试官原话）：** 基准测试里有初始化代码怎么办？

1. **问题现象**：若基准函数开头休眠 1 秒，而默认只跑 1 秒，结果只能执行 1 次、平均每次一秒多——初始化时间被计入了总时间。
2. **ResetTimer 重置**：初始化完成后调用，计时从重置后的下一行开始，只统计后续 for 循环的耗时。
3. **Stop/Start 暂停**：先停止计时，执行初始化动作，再开启计时；被停止区间的耗时不计入基准。
4. **效果验证**：排除休眠后同一函数恢复到 78 次、每次约 16 毫秒，与未加休眠时的结果接近。
5. **适用场景**：一次性前置准备用 ResetTimer；需要在循环中反复加载或重置状态时用 Stop/StartTimer。

## 关键代码
```go
package demo

import (
	"testing"
	"time"
)

func BenchmarkF2(b *testing.B) {
	b.StopTimer()          // 暂停：下面的准备动作不计入
	time.Sleep(time.Second) // 模拟初始化
	b.StartTimer()          // 恢复：从此处开始计时

	for i := 0; i < b.N; i++ {
		time.Sleep(20 * time.Millisecond)
	}
}
```

## 总结与追问预判
核心：**初始化必须排除，Reset 管一次性、Stop/Start 管间歇**。追问常拐向「预热要不要排除」，备好「预热放在 ResetTimer 之前，这样连编译期抖动也一并消除」这句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称 ResetTimer「计时会从重置的下一行代码算起」——准确；补充：它会同时清零**计时、执行次数与内存分配统计**，因此在预热之后调用还能让 B/op、allocs/op 只反映稳态。
2. 事实核校： [经验] 原文称 StopTimer/StartTimer 之间「不会算到基准计时里」——正确；补充两点：暂停期间同样**不统计内存分配**，且 Stop 与 Start 必须配对，忘记 Start 会让该轮计时不完整。
3. 崩坏词归一：源码将基准测试 / 计时器 / 初始化 等音译为多组崩坏词，本卡统一为规范术语。
