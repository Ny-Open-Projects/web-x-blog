> 原文锚点：第 133~149 段「不存大量数据…不存密码密钥…只在请求范围内用，别跨请求共享」

## 一句话总述
context 只承载请求作用域的小元数据（requestID/userID），禁止存大对象、密码密钥等敏感信息，更不可当作跨请求共享的全局容器。

## 面试官视角
- 考察意图：是否分清 context 的"请求作用域"边界，知道滥用会带来泄漏与安全/耦合问题。
- P5 知只存小元数据 / P6 能说清为何不存敏感数据、为何不跨请求 / P7 知跨请求共享应换全局变量或 DB。
- 红旗：把业务大结构体塞进 context；用 context 在多个请求间共享状态。
- 惊艳点：context 值随请求结束即弃，若存敏感数据会被透传到下游所有 goroutine，扩大泄露面 `[经验]`。

## 主问答
**Q（面试官原话）：** context 里面可以放什么样的数据？
**A：**
1. **结论**：只放请求作用域内的必要小元数据，如 requestID、userID。
2. **机制**：Value 沿派生链查找键值，数据会透传到下游所有消费方，存大对象徒增内存与拷贝。
3. **边界**：敏感信息（密码、密钥）禁止入 context；跨请求共享请改用全局变量或数据库，context 不是全局状态。
**加分层：** 大对象建议用显式参数或专门的结构体传递，比塞 context 更清晰可追溯。
