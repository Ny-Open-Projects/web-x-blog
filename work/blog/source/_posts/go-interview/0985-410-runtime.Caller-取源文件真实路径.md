> 原文锚点：第 111~123 段「runtime.Caller 取当前文件所在路径，不受执行命令目录影响，是最推荐方式」

## 一句话总述
`runtime.Caller(skip)` 返回调用栈里某层源文件的路径，与"你在哪执行命令"无关；取两次 `filepath.Dir` 即可从 `configs/conf.go` 上溯到项目根——这是原文最推荐的做法。

## 面试官视角
- 意图：是否掌握调用栈取路径、懂它和 cwd/exe 路径的本质区别。
- P5 知 Caller 取文件路径 / P6 说清 skip 与 Dir 上溯 / P7 知层数硬编码脆弱、用 go:embed 更稳。
- 红旗：以为 Caller 取的是执行目录；以为上溯层数能自适应任何目录结构。
- 惊艳点：Caller 的基准是**编译期源码路径**，换目录 `go run` 结果不变 `[源码]` runtime 包。

## 主问答
**Q（面试官原话）：** 怎么让程序不管在哪运行都能找到项目根目录？
**A：**
1. **结论**：用 `runtime.Caller(0)` 拿当前源文件路径，再 `filepath.Dir` 上溯到根，基准与执行目录无关。
2. **机制**：Caller 返回的是**编译期记录的源文件路径**；无论从哪执行，路径都指向代码位置，故根目录恒定。
3. **边界**：上溯层数（几次 Dir）是按目录深度硬编码的，目录结构调整即失效；深层结构应改用 go:embed `[源码]`。
**加分层：** 比 cwd/exe 路径都稳，但层数脆弱，大型项目优先 go:embed 固化资源。

## 关键代码
```go
// 示意，未验证：runtime.Caller 上溯到项目根
package main

import (
	"fmt"
	"path/filepath"
	"runtime"
)

func root() string {
	_, file, _, _ := runtime.Caller(0) // file = 本源文件路径
	return filepath.Dir(filepath.Dir(file)) // 上溯两级到根
}

func main() {
	fmt.Println(root())
}
```
