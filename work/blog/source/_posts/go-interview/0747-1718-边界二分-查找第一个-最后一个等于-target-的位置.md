> 深挖卡：从「精确查找」推进到「边界查找」，以及二分思想在答案空间上的推广。

## 思路与架构

精确二分找到任意一个 `target` 就返回；边界二分要求找到**最左**或**最右**的那个。核心改动只有一句：**命中时不返回，而是继续把边界往目标方向压**，同时保留一个 `ans` 记录最后一次合法位置。

```text
查找第一个 >= target 的位置（lower_bound）
  left=0, right=n          ← 注意：右端取 n，是半开区间 [left, right)
  while left < right:
      mid = left + (right-left)/2
      if a[mid] < target:  left  = mid + 1
      else:                right = mid     ← 命中不返回，左压边界
  return left              ← 收敛点即答案，可能等于 n（全部小于 target）

查找最后一个 <= target 的位置，或 upper_bound（第一个 > target）
  镜像：if a[mid] <= target: left = mid+1 else: right = mid
```

三个必须想清楚的架构问题：

1. **区间形态**：边界二分用**半开区间** `[left, right)` 更干净——`right` 初始为 `n` 而非 `n-1`，循环条件是 `left < right`（不是 `<=`），收敛时 `left == right`，不需要 `-1` 哨兵。
2. **收缩必须排除 mid 或保留 mid 二选一**：`right = mid` 时 mid **不能**再写 `mid-1`，否则会跳过答案；同理 `left = mid+1` 不能写成 `left = mid`，否则 `left+1==right` 时死循环。判断标准：**会丢答案就保留 mid，不会就越过 mid**。
3. **答案落地**：要么用 `ans` 变量在每次命中时记录（闭区间写法），要么直接返回收敛后的 `left`（半开区间写法，更推荐）。

## 方案取舍

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 精确二分 + 线性左右扫 | 最好写 | 最坏退化 O(n)（全等元素） | 只在重复元素极少时用 |
| 闭区间 + `ans` 记录 | 心智负担低，容易调试 | 要额外变量，退出条件易写错 | 面试现场口述 |
| **半开区间 `[left,right)` 收敛返回** | 无哨兵、无 ans、可组合 | 一开始不直观 | **工程首选** |
| `sort.Search(n, f)`（Go 标准库） | 官方实现、泛型友好 | 传入的是「判定函数」，语义要转个弯 | 生产代码 |
| `slices.BinarySearch` + 前后扫 | 复用标准库 | 命中位置不确定，仍需边界处理 | 不推荐 |

时间复杂度上四者都是 O(log n)，真正拉开差距的是**边界正确性**：统计类需求（"有多少个数等于 x"）用两次 `lower_bound` / `upper_bound` 相减即可 O(log n) 得到，而线性扫是 O(k)。

## 答题技巧

1. **先复述定义再动手**：开口先说「我找的是第一个 `>= target` 的下标，找不到返回 `n`」——把语义钉死，后面所有分支都可由此推导，避免"我以为你要最后一个"。
2. **主动报出死循环判据**：写完立刻指着自己的代码说「这里 `left = mid+1`，mid 一定前进，不会死循环；如果写成 `left = mid` 在 `left+1==right` 时会卡住」——这是面试官真正想听的那句话。
3. **把二分讲成「在答案空间上二分」**：不只数组下标能用，只要**判定条件单调**（前半段 false、后半段 true）就能二分。举例：求满足 `x*x <= n` 的最大整数（整数开方）、在 `[]int` 上找"最小可行容量"（如二分答案求"最少几天完成"）、旋转数组找最小值——统一套路是「写 check(mid) → 判单调 → 套模板」。
4. **版本栅栏要带**：`slices.BinarySearch` / `slices.BinarySearchFunc` 是 Go 1.21+ 才有；老项目只有 `sort.Search`（返回第一个使 `f(i)` 为 true 的 `i`，找不到返回 `n`），语义等价于 `lower_bound`。
5. **收尾补一刀边界**：主动测 `n == 0`、`target` 比所有元素都小、比所有元素都大三种情况，用半开区间模板这三种天然正确；用闭区间 + `ans = -1` 的写法要确认 `-1` 能被正确返回。

## 细节与核心 API

```go
// 标准二分（找目标，存在返回下标，否则 -1）
func binarySearch(a []int, t int) int {
    lo, hi := 0, len(a)-1
    for lo <= hi {
        mid := lo + (hi-lo)/2 // 防溢出写法
        if a[mid] == t { return mid }
        if a[mid] < t { lo = mid + 1 } else { hi = mid - 1 }
    }
    return -1
}
// 左边界（第一个 >= t 的下标，找不到返回插入位）
func lowerBound(a []int, t int) int {
    lo, hi := 0, len(a)
    for lo < hi {
        mid := lo + (hi-lo)/2
        if a[mid] < t { lo = mid + 1 } else { hi = mid }
    }
    return lo
}
// 常见 off-by-one：循环条件 lo<=hi vs lo<hi、mid 更新 +1/-1、边界初值用 len 还是 len-1
// 记忆：求“第一个满足”用 lo<hi + a[mid]<t?lo=mid+1:hi=mid；求“最后一个”反向
```
