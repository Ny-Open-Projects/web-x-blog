> 分类：MySQL 事务 | 难度：L3 | 题型：场景题 | 频率：高 | 关键词：**幻读**/**并发插入**/**并发删除**/**并发更新**/**结果集条数**/**RC/RU 不避免**

> 原文锚点：第 2~7 段「幻读的定义与三类发生场景」

## 一句话总述
**幻读**是同一事务内按相同条件多次查询，因**别的事务提交**导致**结果集条数**变化（多出或少了行）。在**读未提交 / 读已提交**隔离级别下，只要出现**并发插入、并发删除、并发更新使行进出查询范围**三类情形之一，幻读就会发生；这两档级别**无法避免**幻读。

## 面试官视角
这道题考的是「幻读到底什么时候冒出来」。很多人只在 RR 层面背「靠 MVCC 避免」，却答不出「在 RC/RU 下具体哪些写操作会触发」。能枚举出插入/删除/更新-出范围三类，并指出 RC/RU 不防幻读，就是到位。

## 主问答
**Q（面试官原话）：** 什么情况下会出现幻读？

1. **幻读的本质是结果集条数变**：本事务内同一查询条件两次执行，第二次的行数因别的事务提交而改变——多出（插入）或少了（删除）都算幻读。
2. **并发插入触发**：本事务多次查同范围，别的事务在查询间隙插入新行并提交，本事务再查就多出几行。
3. **并发删除触发**：别的事务在查询前删掉部分行并提交，本事务再查就少了几行。
4. **并发更新（边界情形）触发**：别的事务更新了查询范围内的行，使其**不再满足本事务的查询条件**（或反之内行被改成满足条件），导致本事务再查时命中行变化；这属于「修改使记录进出范围」的边界型幻读。
5. **RC/RU 无法避免**：这两档级别每次查询都看最新已提交数据，别的事务的增删改一旦提交就会被本事务下次查询读到，因此**幻读必然可能发生**；要把它挡住至少得升到 RR。

## 追问链
| 档位 | 追问 | 答不出停在哪档 |
|------|------|----------------|
| L1 | 幻读是什么？ | 说不清结果集条数变化 |
| L2 | RC/RU 下哪些写入会触发？ | 说不全插入/删除/更新 |
| L3 | 更新怎么也算幻读？ | 说不清「进出查询范围」边界 |
| L4 | RC/RU 能避免幻读吗？ | 说不出否 |
| L5 | 提升到哪档才挡住？ | 说不出 RR + 快照/间隙锁 |

## 版本与兼容性
| 隔离级别 | 快照机制 | 幻读是否可能发生 |
|----------|----------|------------------|
| 读未提交 | 无 | 是 |
| 读已提交 | 每条语句新建快照 | 是 |
| 可重复读 | 事务级快照 | 大部分避免，特定当前读仍可能 |
| 串行化 | 加读锁/串行 | 否（代价高） |

## 关键代码
```sql
-- 会话 A（RC 级别）多次查同范围
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
START TRANSACTION;
SELECT * FROM t WHERE a > 16;          -- 第一次：N 行

-- 会话 B 在间隙插入并提交（并发插入 → 幻读）
INSERT INTO t(a) VALUES (20); COMMIT;

SELECT * FROM t WHERE a > 16;          -- 第二次：N+1 行（多出 B 插入的行 = 幻读）
```

## 总结与追问预判
核心：**幻读 = 结果集条数因别事务提交而变；RC/RU 下插入/删除/更新-出范围三类必触发**。追问拐向「RR 怎么避免」——备好「快照读靠 ReadView、当前读靠间隙锁/Next-Key 锁」（见 RR 幻读专题与锁专题卡）。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文把「修改」也列为幻读成因——严谨地说，单条记录的 UPDATE 属不可重复读；只有使记录**进出查询范围**、改变结果集条数的更新才兼具幻读特征，本卡将其归为边界情形单独说明。
2. 崩坏词归一：源码将事务 / 隔离级别 / 幻读 / 结果集 等音译为多组崩坏词，本卡统一为规范术语。
