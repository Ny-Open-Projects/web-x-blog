> 分类：数据库 / MySQL 锁 | 难度：L4 | 题型：原理题 | 频率：高 | 关键词：**临键锁、幻读、非唯一索引、记录锁、间隙锁、左开右闭**

> 原文锚点：第 35~44 段「为什么命中条件的这些二级索引记录都加了临键锁，而没有退化成记录锁呢？由于这个字段是非唯一索引，它不具有唯一性…如果只加记录锁，因为记录锁是无法防止插入操作的，只能防止删除或者修改…就会导致其他的事务插入了跟当前值一样的记录…当前事务前后两次查询的结果集就不相同了，就会出现幻读的现象」

## 一句话总述
普通索引是**非唯一索引**，若只加记录锁则**只能挡住删除和修改、挡不住插入**，其他事务仍可插入同值记录导致**幻读**；因此必须加**临键锁**，把命中记录及其之间的间隙一并锁死。

## 面试官视角
P6 知道「临键锁 = 记录锁 + 间隙锁」；P7 要能回答**「为什么不退化」这一层机理**——退化条件（唯一索引等值命中）与后果（幻读）的因果链，并准确说出临键锁的区间形状与覆盖范围。

## 主问答
**Q（面试官原话）：** 为什么范围查询不能用记录锁，非要上临键锁？

1. **根因是非唯一**：该字段是**非唯一索引**，索引值**不具有唯一性** `[源码]`。
2. **记录锁的局限**：记录锁**只能防止删除或修改，无法防止插入** `[源码]`。
3. **后果是幻读**：若只加记录锁，其他事务可插入与当前值相同的记录，导致**当前事务前后两次查询结果集不同**，即**幻读** `[源码]`。
4. **因此加临键锁**：需要对命中的索引记录都加**临键锁**，把记录本身与间隙一起锁住 `[源码]`。
5. **覆盖范围**：会把命中值之间**所有间隙全部锁住**，例如 name1~name2、name2~name3、name3~name4 全部区间 `[源码]`。
6. **区间形状**：临键锁是**左开右闭**区间——name1~name2 不包含 name1 但包含 name2 `[源码]`。
7. **复合效果**：每条命中记录**既加记录锁，又在其前面的间隙加锁**，即记录锁与间隙锁的组合 `[源码]`。
8. **最终效果**：其他事务**无法插入任何与命中值相同的记录** `[源码]`。

## 关键代码
```sql
-- 非唯一索引 name，RR 隔离级别
BEGIN;
SELECT * FROM t WHERE name > 'name2' LOCK IN SHARE MODE;
-- 命中项加临键锁（左开右闭），锁住记录 + 其前间隙

-- 若只有记录锁，则以下插入不会被阻塞 -> 幻读
INSERT INTO t(id, name) VALUES (99, 'name3'); -- 临键锁下会被阻塞

-- 退化仅发生在唯一索引的等值命中场景
-- CREATE UNIQUE INDEX uk_name ON t(name);
-- SELECT * FROM t WHERE name = 'name3' LOCK IN SHARE MODE; -- 退化为记录锁
```

## 总结与追问预判
**记住因果链：非唯一 → 记录锁挡不住插入 → 幻读 → 必须临键锁**。这是范围查询加锁的题眼，也是「临键锁为什么存在」的标准答案。扫描终止位置见同批 1238-range-le-scan。

## ⚠️ 原文纠错
1. 事实核校：非唯一索引不具唯一性、记录锁无法防插入、会导致幻读、须加临键锁锁住全部间隙、临键锁为左开右闭、既加记录锁又加间隙锁——均与 InnoDB 加锁规则一致 `[经验]`。
2. 补充：严格来说，在 RR 下**唯一索引的等值查询命中时**临键锁才会退化为记录锁；非唯一索引即便等值命中也不会退化，且需向右扫描到第一个不满足项并对其加间隙锁 `[经验]`。
3. 崩坏词归一：源码将临键锁、间隙锁、记录锁、幻读、唯一性等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
