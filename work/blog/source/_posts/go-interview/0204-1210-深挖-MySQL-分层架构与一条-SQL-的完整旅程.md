> 分类：数据库 / MySQL 架构 | 难度：L4 | 题型：综合题 | 频率：高 | 关键词：**Server 层、存储引擎层、系统文件层、优化器、执行流程、可插拔、查询缓存**

> 原文锚点：第 1~82 段「MySQL 依赖的是存储引擎提供的统计信息来评估成本，但是有的存储引擎提供的信息偏差有点大，InnoDB 因为 MVCC 并不能维护一个数据表行数的精确统计信息…MySQL 的存储引擎是可插拔的…表是由一行一行的记录组成的，但这个只是一个逻辑上的概念…系统文件层主要负责将数据库的数据和日志文件存储在文件系统上…一条 SQL 语句的过程大致可分为连接器、查询缓存、分析器、优化器、执行器、存储引擎、返回结果」

## 思路与架构

按「**分层 → 优化器 → 执行链路**」三层把握 MySQL：

1. **分层架构（自顶向下）**：
   - **Server 层**：含缓存与缓冲区，包括**预编译语句与存储过程的缓存**，以及引擎的缓存（**InnoDB buffer pool**、MyISAM 键缓存）；**8.0 之前还有查询缓存**。
   - **存储引擎层**：**可插拔**，表只是**逻辑概念**，物理上如何表示记录、如何读写磁盘都由引擎负责；引擎本质是**表处理器**，向上提供统一服务、向下屏蔽差异；换引擎**不需改应用代码**。
   - **系统文件层**：**物理存储层**，负责把数据与日志落到文件系统并与引擎交互，含**日志、数据、配置、PID、socket** 五类文件。
2. **优化器（两条主线）**：
   - **为什么会选错**：统计信息靠采样（InnoDB 因 **MVCC** 无法精确计数，改用**随机 8 个数据页**）、成本模型只看 **CPU 与 IO**、估算**不考虑缓冲池**、计划空间被**截断**、**存储过程与 UDF** 无法估算。
   - **能做什么**：重排关联顺序、外连接转内连接、简化恒等条件、优化 **COUNT/MIN/MAX**、表达式常量折叠、优先覆盖索引、子查询转 EXISTS/JOIN、**LIMIT** 提前终止、**等值传播**、**IN 列表排序后二分**。
3. **执行链路（七步）**：连接器（鉴权）→ **查询缓存（仅 8.0 前）** → 分析器（语法/语义/权限）→ 优化器（生成计划）→ 执行器（调引擎接口）→ 存储引擎（真正读写）→ SQL 接口返回结果。

## 方案取舍

| 关注点 | 结论 | 影响 |
|---|---|---|
| 引擎可插拔 | 表是逻辑、引擎管物理 | 换引擎不改应用代码 |
| 统计信息 | 采样而非精确 | 优化器可能选错计划 |
| InnoDB 计数 | MVCC 导致不精确 | COUNT(*) 需扫描，MyISAM 可直接取 |
| 查询缓存 | 8.0 移除 | 因表变更导致大范围失效、维护代价高 |
| 文件归属 | 按引擎分后缀 | .MYD/.MYI 属 MyISAM，.ibd/.ibdata 属 InnoDB |
| 优化器改写 | SQL 会被改写 | 书写顺序 ≠ 执行顺序 |

取舍要点：**MySQL 用「逻辑/物理分离 + 可插拔引擎」换取灵活性，代价是优化器只能靠采样估算**；因此「优化器选错」不是缺陷而是架构取舍，工程上需用 `EXPLAIN`、刷新统计信息或索引提示来纠偏。

## 答题技巧

1. **先画分层再讲流程**：Server 层 / 引擎层 / 文件层三层讲清，再串执行链路，结构最稳。
2. **版本点必须报**：**查询缓存 8.0 移除**、**.FRM 在 8.0 被数据字典取代**、**独立表空间自 5.6 起默认**。报版本号是 P7 硬证据。
3. **优化器讲两面对**：既说「会选错的五个原因」，也说「能做的十种优化」，体现全面理解。
4. **记住数字**：InnoDB **随机 8 个数据页**采样——这是最有辨识度的细节。
5. **止步档位**：能讲清三层架构与执行流程即达 L4；能完整说出优化器两面、文件后缀归属与版本差异，即达 L5。

## 细节与核心 API

**一条 SQL 的执行链路（8.0 前含查询缓存）**：

```text
连接器(鉴权) → [查询缓存(仅8.0前)] → 分析器(语法/语义/权限) → 优化器(生成计划)
  → 执行器(调引擎接口) → 存储引擎(真正读写) → SQL 接口返回结果
```

```sql
EXPLAIN SELECT * FROM t WHERE a=1 AND b>2 ORDER BY c LIMIT 10;
-- 看 type/key/rows/Extra 判断计划是否符合预期；优化器选错时用它纠偏
ANALYZE TABLE t;  -- 刷新统计信息（InnoDB 随机采样 8 个数据页估算，MVCC 致 COUNT(*) 不精确）
```

**版本边界（P7 硬证据）**：

```ini
查询缓存    8.0 移除（表变更大范围失效、维护代价高）
.FRM 文件   8.0 起取消，表元数据迁入 InnoDB 数据字典
独立表空间  5.6 起默认 .ibd；系统表空间 .ibdata
文件后缀    .MYD/.MYI 属 MyISAM；.ibd/.ibdata 属 InnoDB
```

> 边界：优化器选错五因见 1210 正文；redo/undo 与两阶段提交见 1209；本卡只讲分层架构与执行流程。
