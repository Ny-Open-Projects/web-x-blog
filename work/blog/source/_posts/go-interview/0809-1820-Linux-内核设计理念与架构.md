## 一句话总述
Linux 内核四大设计理念：**多任务**（高效调度支持多进程/线程并发）、**SMP 对称多处理**（多处理器共享内存/IO、扩展到多核）、**ELF**（可执行/共享库/目标文件通用格式，加载链接高效、跨架构）、**宏内核架构**（文件系统/驱动/内存管理集成在单一内核空间，性能优；用模块化设计动态加载卸载克服复杂度）。微内核（如 Windows）只留最小功能、其余在用户态 IPC 交互，可维护但性能低。

## 面试官视角
- 考察意图：是否讲清宏内核 vs 微内核的取舍，以及 Linux 为何选宏内核+模块化；SMP/ELF 是加分点。
- 分档：P5 知 Linux 是宏内核；P6 知宏内核集成、性能优但复杂；P7 知模块化补丁、微内核(Windows)对比、SMP/ELF。
- 红旗答案：以为 Linux 是微内核；或说不清宏内核为何性能高。
- 惊艳点：点出「宏内核减少用户↔内核上下文切换与通信开销故性能高；模块化动态加载弥补可维护性短板」。

## 主问答
**Q（面试官原话）：** Linux 内核有哪些设计理念？宏内核和微内核有什么区别？
**A：**
1. **四大理念**：① 多任务——高效进程调度与资源管理，多任务并发充分利用 CPU；② SMP——对称多处理，多处理器共享内存/IO、同时执行不同任务，扩展到多核；③ ELF——可执行文件链接格式，存可执行程序/共享库/目标文件，加载链接高效、跨处理器架构扩展好；④ 宏内核架构为主。
2. **宏内核（Linux 选用）**：文件系统、设备驱动、内存管理等大部分功能集成在单一内核空间；因少跨用户↔内核切换与通信开销，性能优于微内核；缺点是代码复杂、维护与稳定性挑战。
3. **模块化补丁**：Linux 用模块化设计，运行时动态加载/卸载功能模块，提升灵活性与可扩展性，缓解宏内核复杂度问题。
4. **微内核对比**：微内核（如 Windows）只含最基本功能（低级内存管理/进程管理/IPC），其余（文件系统/设备）在用户态独立服务经 IPC 交互，可维护可靠但性能较低；宏 vs 微是架构与功能划分的权衡。
