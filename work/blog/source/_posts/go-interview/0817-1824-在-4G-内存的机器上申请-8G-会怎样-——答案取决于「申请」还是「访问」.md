# 1824 在 4G 内存的机器上申请 8G 会怎样？——答案取决于"申请"还是"访问"

> 分类：操作系统 / 内存管理 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**虚拟内存**/**惰性分配**/**缺页异常**/**overcommit**/**32位3G**/**64位128TB**/**swap**/**OOM**
> 原文锚点：第 26~32 段「如果是在三十二位操作系统当中，因为进程理论上最大能申请 3G 大小的虚拟内存，所以如果我们在三十二位操作系统上，物理内存只有四个 G，我们直接去申请八个 G 的内存，就会导致申请失败…假设是在六十四位的操作系统上，进程理论上最大能申请 128TB 大小的虚拟内存，即使物理内存只有四个 G，申请 8G 的内存也是没有问题的，因为申请的内存是虚拟内存，并不会立马去分配」
> [边界] 本文只讲**"小内存机器申请大块内存"这道具体题的判定链**：页表与地址转换机制见 811，分段与分页的差异见 1825，`free`/`top` 等排查工具见 1810，均不重述。

## 一句话总述
**申请 ≠ 分配**。进程看到的是**操作系统给的独立、连续的虚拟地址空间**，`malloc`/`mmap` 只是**在页表里预留了一段虚拟地址**，**一块物理页都没碰**；只有**真正访问**时才触发**缺页异常**，由内核**分配物理页框并建立映射**。所以答案分三层：**① 32 位系统**用户态上限约 **3G**，申请 8G **直接失败**；**② 64 位系统**上限约 **128TB**，申请 8G **能成功**；**③ 一旦真的写遍这 8G**，就看有没有 **swap**——**没 swap 就 OOM 被杀，有 swap 就能正常跑**。

## 面试官视角
- 考察意图：这是**内存题里最经典的一道分水岭**。面试官用"4G 机器申请 8G"来验你是否真的理解**虚拟内存与物理内存是两层**，还是只会背"内存不够就 OOM"。
- 分档：P5 只会说"会 OOM"；P6 知道"申请的是虚拟内存，可以成功"；P7 能讲出**三层判定链**（位数上限 → 惰性分配 → swap 有无）、**缺页异常在哪个环节触发**、**TLB 与页表项的作用**，并**用 RSS 实测数据佐证惰性分配**。
- 红旗答案：「4G 机器肯定申请不了 8G」——**错**。64 位下**申请一定成功**，失败发生在**访问阶段**。
- 惊艳点：主动补「实测 `mmap` 预留 1GiB 后 RSS 只有 **2716 KB**，逐页写遍后飙到 **1051476 KB**，`munmap` 又回落到 **3188 KB**——**这就是"申请不等于分配"的硬证据**」[实测]。

## 主问答
**Q（面试官原话）：** 在一台只有 4G 内存的机器上申请 8G 内存，会发生什么？

**A：**
1. **先立前提——进程看到的是虚拟内存**：操作系统为每个进程提供**一块独立、连续的虚拟地址空间**，进程**独享**、**只能看到这片虚拟内存**，而**不是实际的物理内存**；虚拟地址到物理地址的映射由**内存管理单元（MMU）与页表**完成 [经验]。
2. **页表是关键数据结构**：它记录**虚拟地址空间中每一页**（通常是固定大小的内存块，如 **4KB**）与**物理内存中页框**的对应关系；每个**页表项**还带**物理页框号、访问权限、是否在内存中**等元信息 [经验]。
3. **地址转换**：程序访问虚拟地址时，MMU 查页表确定物理地址，这个过程叫**地址转换**；为加速，MMU 用 **TLB（转换后备缓冲器）**缓存最近使用的页表项，**TLB 命中则转换极快** [经验]。
4. **第一层判定——32 位还是 64 位**：**32 位**系统进程理论上最大只能申请约 **3G** 虚拟内存，物理内存 4G 时申请 8G **会导致申请失败**；**64 位**系统理论上最大约 **128TB**，物理内存只有 4G **也能申请成功** [经验]。
5. **第二层判定——申请只是预留**：申请的内存是**虚拟内存，并不会立马去分配**物理页。实测 `mmap` 预留 1GiB 之后 RSS 仅 **2716 KB**，几乎没动 [实测]。
6. **第三层判定——访问才真正分配**：一旦访问，MMU 发现页表里**没有对应映射**，就产生**缺页异常**；内核介入**分配一个物理页框并建立映射**（若页被换出到磁盘，则从磁盘换回并更新页表）。实测**逐页写遍后 RSS 涨到 1051476 KB** [实测]。
7. **第四层判定——有没有 swap**：如果**没有 swap 分区**，物理内存不够时**进程会被操作系统杀掉**，也就是 **OOM（内存溢出）**；如果**有 swap 分区**，即使物理内存只有 4G，程序**依然能正常使用 8G 内存并正常运行** [经验]。
8. **顺带说清内存保护**：页表项里带**读写执行权限位**，确保进程只能访问自己有权限的区域——这正是虚拟内存提供**内存保护、隔离与动态内存分配**的基础 [经验]。
9. **一句话总结**：**物理内存是否充足会不会影响申请，要看实际条件**——申请阶段看**地址空间位数**，运行阶段看**swap 有无与是否真访问** [经验]。

| 结论成立版本 | 翻转点 | 现在该怎么答 |

## 关键代码
```go
package main

import (
	"fmt"
	"os"
	"os/exec"
	"syscall"
)

func rssKB() string {
	out, err := exec.Command("ps", "-o", "rss=", "-p", fmt.Sprint(os.Getpid())).Output()
	if err != nil {
		return "?"
	}
	return string(out[:len(out)-1]) // 从 OS 读真实常驻集，而非 Go 的 MemStats
}

func main() {
	const size = 1 << 30 // 1 GiB
	b, err := syscall.Mmap(-1, 0, size, syscall.PROT_READ|syscall.PROT_WRITE,
		syscall.MAP_ANON|syscall.MAP_PRIVATE)
	if err != nil {
		fmt.Println("mmap 失败:", err) // 这一支才是"32 位申请 8G"的结局
		return
	}
	fmt.Printf("mmap 预留 1GiB 后 RSS = %s KB\n", rssKB())

	// 逐页写入：每写第一字节就触发一次缺页异常，内核才分配物理页框
	for i := 0; i < size; i += 4096 {
		b[i] = 1
	}
	fmt.Printf("逐页写遍 1GiB 后 RSS = %s KB\n", rssKB())

	_ = syscall.Munmap(b)
	fmt.Printf("munmap 后 RSS = %s KB\n", rssKB())
}
```

> 验证（`[实测]` 输出，macOS / go1.26.5）：`mmap 预留 1GiB 后 RSS = 2716 KB`；`逐页写遍 1GiB 后 RSS = 1051476 KB`（约 1.0 GiB，增长 **约 387 倍**）；`munmap 后 RSS = 3188 KB`。三组数字完整证明：**申请阶段只占虚拟地址，物理内存直到"被访问"那一刻才分配**。（补充实测：Go 的 `make([]byte, 1<<30)` 因运行时要**清零**，会立刻把 `HeapSys` 推到 1056384 KB——**看不到这个惰性过程**，所以演示必须用裸 `mmap`。）

## 总结与追问预判
- 一句话收尾：**"申请看位数，占用看访问，存活看 swap"**——三句话覆盖三层判定。
- 大概率被追的三问：① 为什么 Go/Java 里申请大对象不像 C 那样"看起来免费"（**运行时会清零或预触碰**，所以 RSS 立刻上去）；② 容器里为什么没 swap 也会 OOM（**cgroup 内存 limit 独立于 swap**，超限直接 kill）；③ 有 swap 就一定好吗（**不是**，换页把随机访问变成磁盘 IO，服务会"活着但不可用"）。
- 反向加分：主动指出**"4G 机器申请不了 8G"是最常见的错误直觉**，正确说法是**申请一定成功，风险发生在访问阶段**。

## ⚠️ 原文纠错
1. 源码称 32 位「最大能申请 3G」——准确说是**用户态**约 3G，内核态另占 1G [经验]。
2. 源码未提 **overcommit 是可配置策略**（`vm.overcommit_memory`），并非所有系统都允许超额申请 [经验]。
3. 源码未提**有 swap 虽能跑但会极慢**——换页把内存访问退化成磁盘 IO [经验]。
4. 源码未提**容器 cgroup limit 独立于 swap**，超限直接被 kill，与宿主机有无 swap 无关 [经验]。
5. 源码称页「通常是 4KB」——对，但**大页（2MB/1GB）能显著降低 TLB 缺失** [经验]。
6. 源码未提醒 **Go 的 `make` 会立即清零**，看不到 C `malloc` 的惰性效果，演示须用裸 `mmap` [实测]。
