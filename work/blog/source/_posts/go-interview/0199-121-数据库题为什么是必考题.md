> 分类：数据库 / 面试认知 | 难度：L1~L2 | 题型：认知题 | 频率：高 | 关键词：**后端心脏**/**性能瓶颈**/**基本功标尺**/**慢查询**/**索引**

> 原文锚点：第 1~16 段「出现概率最高没有之一…数据库是后端服务的心脏…性能瓶颈…基本功扎实与否的标尺」

## 一句话总述
数据库题必考的三层逻辑：① **角色重**——几乎所有后端都要存储/查询/管理数据，数据库是后端服务的**心脏**；② **瓶颈多**——绝大多数后端性能问题源于数据库本身或对数据库的**使用不当**，慢查询和索引问题是头号成因；③ **当标尺**——数据库技能已成后端基本功，基础题答不上会被贴上「基础不牢」的标签。

## 面试官视角
- 意图：认知题，看你是否理解数据库考察的权重逻辑，从而推断备考投入是否合理。
- 分档：P5 知数据库必考；P6 能讲三理由（心脏/瓶颈/标尺）并各自举例；P7 能接「性能问题归因数据库」的实战方法论（慢查询定位→索引→架构）。
- 红旗答案：说「背背八股就行」；讲不出「瓶颈在哪」的归因链。
- 惊艳点：极端案例反向佐证——有的面试官只出**一道场景 SQL** 定生死；再给归因量化口径「线上性能问题八成看得到数据库影子」 [经验]。

## 主问答
**Q（面试官原话）：** 为什么数据库类的面试题是必考题？

**A：**
1. **角色重·心脏**：后端服务由数据驱动，代码主要工作就是与数据库交互——存储、查询、管理数据缺了数据库转不动；它是不可或缺的核心组件。
2. **瓶颈多·归因**：后端性能问题大多数是数据库问题，或是对数据库**使用不当**（SQL 写差、索引缺失、大事务）造成的——慢查询与索引问题稳居成因榜首；面试官借数据库题评估你的性能优化经验与能力。
3. **标尺·基本功**：数据库已是后端必备基本技能，掌握程度直接衡量基本功扎实与否——基础问题答不上来，大概率被贴「基础不牢」标签，后面答得再好也难翻盘。
4. **备考启示**：性能与并发是面试常问、也是高并发服务绕不开的实战题——掌握它们既提通过率，也帮你在真实开发中避开大量坑。

## 关键代码
```go
package main

import "fmt"

// 数据库考点 → 对应能力 → 本库卡片映射（备考自检表）
var mapTab = []struct{ topic, skill, card string }{
	{"慢查询定位", "EXPLAIN + 慢日志分析", "12 章查询优化卡"},
	{"索引原理", "B+ 树 / 最左前缀 / 回表", "12 章索引系列"},
	{"事务与锁", "ACID / 隔离级别 / 间隙锁", "12 章事务系列"},
	{"主从与高可用", "binlog / 半同步 / 延迟", "1207-1208 系列"},
	{"高并发架构", "读写分离 / 分库分表 / 缓存", "12-13 章架构卡"},
}

func main() {
	for _, r := range mapTab {
		fmt.Printf("%-10s → %-24s → %s\n", r.topic, r.skill, r.card)
	}
}
```

[实测] 输出五行映射齐全——把「必考」认知转成这张自检表，逐行自问能不能讲透，缺口就是备考清单。

## 总结与追问预判
核心：**「心脏、瓶颈、标尺」六字答完三层逻辑，再主动接「所以我的备考是先慢查询定位、再索引原理」**。追问直接进技术纵深：binlog 与主从见 1207 / `1208-master-slave-replication`、两阶段提交见 1207；认知层的同源题——基础题必问见 401、runtime 必考见 801，三题共用「探测能力边界」的答题骨架。
