> 分类：Go 基础 / string | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**赋值不拷贝、底层字节数组、共享地址、置空不释放、传参共享、GC 引用**

> 原文锚点：第 7~25、43~49 段「字符串底层存储实际上是指向的一个字节切片的指针…我们将这个字符串 s 赋值给一个新的字符串，赋值完成之后，赋值后的字符串 s2 的地址和 main 函数里面这个字符串 s 的地址，它们指向的是同一个地址。也就是说字符串在赋值的过程中，它是不会发生拷贝的…当我们将字符串 s 置空之后，字符串 s 指向的指针就被赋值为 nil，而字符串 s2 的地址跟之前 s 的地址是一样的…即使我们将原始的字符串设置成一个空串，只要原始这个字符串之前的内存空间有被其他的字符串所引用，它的内存空间是不会被回收的」

## 一句话总述
`string` 的底层是**指向字节数组的指针 + 长度**，因此**赋值过程中不会发生拷贝**——赋值后新字符串与原始字符串**指向同一个地址**；**即使把原字符串置空，只要那一块内存还被其他字符串引用，就不会被回收**。函数传参同理：**按值传、传指针，参数与外层字符串的地址都一致**，行为与切片非常类似。

## 面试官视角
- 考察意图：是否知道 `string` 是**描述符（指针 + 长度）**而非数据本体，以及由此带来的**共享语义**。
- 分档：P5 知道字符串不可变；P6 能说"赋值不拷贝、共享底层"；P7 能推出"**置空原串不释放内存**"并解释"赋值只是改变指针指向"，还能说明**传参同样共享**。
- 红旗答案：以为 `s2 := s` 会把数据复制一份；或以为把原串置空就能立刻释放大内存。
- 惊艳点：**赋值的本质是"改变底层指针的指向"**——把空串赋给 `s` 时，`s` 的指针改指向了另一块空间，**而原来的字节数组依然在内存里，并且仍被 `s2` 引用** `[源码]`。

## 主问答
**Q（面试官原话）：** `s2 := s` 会拷贝字符串吗？把 `s` 置空后内存会释放吗？

1. **结论**：**赋值不拷贝**，两者**指向同一块内存**；**把原串置空也不会释放**——只要还有字符串引用那块内存就不会被回收 `[源码]`。
2. **底层结构**：**字符串底层存储实际上是指向的一个字节切片的指针**（描述符 = 指向底层字节数组的指针 + 长度）`[源码]`。
3. **赋值不拷贝**：把字符串 `s` 赋值给新的字符串 `s2` 后，**`s2` 的地址与 main 函数里 `s` 的地址指向的是同一个地址**——**字符串在赋值的过程中是不会发生拷贝的** `[源码]`。
4. **置空不释放**：把原始字符串 `s` 置空后，**`s` 指向的指针被赋值为 `nil`**，而 **`s2` 的地址跟之前 `s` 的地址还是一样的** `[源码]`。
5. **为什么会这样**：**赋值的过程其实是改变底层指针的指向**——**把空字符串赋值给 `s` 时，`s` 的指针指向了另一块新的空间**，**而原来声明的那个字节数组其实依然在内存里，并且还是被 `s2` 所引用**；**由于有 `s2` 的引用，原来那一块内存空间并不会被释放** `[源码]`。
6. **推广结论**：**即使我们把原始的字符串设置成一个空串，只要原始字符串之前的内存空间有被其他的字符串所引用，它的内存空间是不会被回收的** `[源码]`。
7. **引用赋值同样共享**：**不管是通过字符串的值来赋值，还是通过字符串的引用类型来赋值**，**最终这两个字符串指向的内存空间是同一个** `[源码]`。
8. **传参同样不拷贝**：把字符串按值传给函数、或把地址传进来，**函数内收到的字符串参数的地址与外层 `s` 的地址是一致的**，**这种传参方式其实和切片非常类似** `[源码]`。

**加分层：** 这三条（赋值 / 引用赋值 / 传参）指向同一个结论——**`string` 的复制成本是一个描述符（两个字长），但共享的是整块底层数据**；所以"拷贝成本低"和"占内存不释放"是一体两面。

## 关键代码
```go
package main

import (
	"fmt"
	"reflect"
	"strings"
	"unsafe"
)

// dataPtr 取出 string 描述符中指向底层字节数组的指针
func dataPtr(s string) uintptr {
	return (*reflect.StringHeader)(unsafe.Pointer(&s)).Data
}

func main() {
	// 构造一个"超长"字符串，便于观察共享与否
	s := strings.Repeat("A", 1<<20)

	// 1) 赋值：不拷贝，s2 与 s 指向同一块底层内存
	s2 := s
	fmt.Println("s :", dataPtr(s))
	fmt.Println("s2:", dataPtr(s2)) // 与上面相同
	fmt.Println("赋值是否共享底层:", dataPtr(s) == dataPtr(s2))

	// 2) 把原串置空：s 的指针改指别处，但原字节数组仍被 s2 引用 -> 不释放
	s = ""
	fmt.Println("置空后 s2 地址:", dataPtr(s2)) // 与原来 s 的地址一致

	// 3) 函数传参：按值传 / 传指针，内部看到的都是同一块底层数据
	byValue(s2)
	byPointer(&s2)
}

func byValue(v string)  { fmt.Println("按值传参:", dataPtr(v)) }
func byPointer(p *string) { fmt.Println("指针传参:", dataPtr(*p)) }
```

## 总结与追问预判
**最爱追问的是"那怎么才能真正释放那块大内存"**——**必须切断所有引用**：要么让 `s2` 也离开作用域或被赋新值，要么在需要保留子串时用 **`strings.Clone`**（Go 1.18+）或 **`[]byte` 中转再转回 `string`** 强制生成独立副本（见 905）。注意这与**切片截取泄漏**是同一类问题：`1111-slice-slice-memory-leak` 讲的是切片版本，本卡是字符串版本。
