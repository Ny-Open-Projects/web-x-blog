> 分类：Go 并发 / 调度 | 难度：中 | 题型：机制题 | 频率：中 | 关键词：**for 死循环、抢占式调度、GOMAXPROCS、Go 1.14、饿死**

> 原文锚点：第 4~13 段「for死循环占CPU；1.4前 GOMAXPROCS=1 时协程可能永不被调度；1.4 加入抢占式调度后让出CPU」

## 一句话总述
用 `for {}` 空转可卡住 main，但会**持续占 CPU**；更关键的是调度版本边界——**源码称 Go 1.4 引入抢占式调度，实际是 Go 1.14 才落地异步抢占**。在 1.14 之前、且 `GOMAXPROCS=1`（单逻辑核）时，一个不含函数调用的 `for {}` 会独占 P，导致其他 goroutine 长期得不到调度（饿死）。一句话背法：**「for{} 空转卡 main 但占 CPU；1.14 前单核紧循环饿死他人，异步抢占才是真解」**。

## 面试官视角
考官不止考"怎么卡 main"，更考对抢占式调度演进与单核饿死陷阱的理解。能讲清协作式 vs 异步抢占、Go 1.14 才是异步抢占落地点、以及 `runtime.Gosched`/函数调用可主动让出，说明功底深；照背"1.4 就解决了"、或以为死循环不影响其他协程，是红旗。
- **P5**：知道 for{} 空转占 CPU。
- **P6**：知道 GOMAXPROCS=1 单核下紧循环会饿死其他协程。
- **P7**：知道异步抢占实为 Go 1.14（非 1.4），以及主动让出手段。

## 主问答
**Q（面试官原话）：** for 死循环为什么能让主协程不退出？会不会有问题？

**先铺垫（由浅入深第 1 层）**：main 一 return 整个进程就退出。要常驻，最简单的办法就是让 main 自己"跑个不停的循环"。但"跑个不停"有两个代价：一是它一直在烧 CPU，二是它可能把整个 P 占住，让别的协程没机会跑——这就是调度视角的坑。

1. **空转占 CPU（第 2 层·代价）**：`for {}` 不含阻塞/让出，main 永远在跑，既卡住退出又空耗一个核。
2. **单核饿死（第 3 层·机制，1.14 前）**：在 `GOMAXPROCS=1` 时，不含函数调用的紧循环独占 P，其他 goroutine 拿不到调度机会；**异步抢占实为 Go 1.14 引入**，此前只有协作式（需函数调用/chan 操作才让出）。
3. **1.14 后缓解（第 4 层·边界）**：异步抢占可强制紧循环让出 CPU，其他协程获得执行机会，但 `for {}` 仍在空转轮转，资源浪费依旧。
4. **主动让出（第 5 层·治标）**：循环内插入 `runtime.Gosched()` 或函数调用（产生协作点）可在旧版本下缓解饿死，但治标不治本。
5. **误用风险（第 6 层）**：把 `for {}` 当生产常驻方案是大忌——既浪费 CPU 又依赖调度救场；生产用 `signal.Notify`（见 1024 signal.Notify）。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| Go < 1.14 | 协作式抢占，紧循环（无函数调用）在 GOMAXPROCS=1 下饿死其他协程 |
| Go 1.14+ | 异步抢占落地，强制紧循环让出 CPU，但空转仍浪费 |
| 源码表述纠正 | 源码称"1.4 引入抢占"，实为 **1.14 异步抢占**；1.4 及之前仅协作式 |
| 主动让出 | `runtime.Gosched()` 或循环内函数调用产生协作点 |
| Go 版本 | 异步抢占门控点为 Go 1.14（2020），本项目实测 Go 1.26.5 |

## 关键代码
```go
package main

import "runtime"

func main() {
	// 危险：GOMAXPROCS=1 且 Go<1.14 时，go work() 可能永不被调度（饿死）
	// go func() { for { work() } }()

	// for{} 空转卡住 main，但空耗 CPU
	for {
		// 旧版本在循环内插入让出点可缓解饿死（治标不治本）
		runtime.Gosched()
	}
}
```

## 总结与追问预判
**背这三句就够**：① **for{} 空转能卡 main，但持续占 CPU、浪费核**；② **Go 1.14 前单核（GOMAXPROCS=1）紧循环会饿死其他协程**；③ **异步抢占实为 Go 1.14（非源码所称 1.4），生产别用 for{} 常驻**。
**预判追问**：
- 「1.4 是不是就解决了？」→ 不是，1.4 只是协作式（需函数调用让出），异步抢占 1.14 才落地（见本卡第 3/5 层）。
- 「怎么让出 CPU？」→ `runtime.Gosched()` 或循环内函数调用产生协作点（见本卡第 5 层）。
- 「常驻进程正确写法？」→ signal.Notify 监听信号阻塞 main（见 1024 signal.Notify）。

## ⚠️ 原文纠错
1. 事实核校：for{} 空转占 CPU、GOMAXPROCS=1 单核紧循环饿死、Gosched 主动让出——均正确。
2. **版本事实更正（重要）**：源码称"Go 1.4 加入抢占式调度"，实际 **Go 1.14（2020）才引入异步抢占**；Go 1.4 及之前仅有协作式抢占（需 goroutine 调用函数/chan 操作才让出），紧循环 `for{}` 在 `GOMAXPROCS=1` 下仍会饿死其他协程。本卡已按规范版本边界修正。
3. 崩坏词归一：源码将 goroutine 音译为过入、抢占音译为崩坏词、GOMAXPROCS 音译为崩坏词；本卡统一为规范术语。
