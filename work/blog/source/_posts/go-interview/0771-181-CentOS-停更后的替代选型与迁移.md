## 一句话总述
迁移有两条路：**同系迁移**到 Rocky Linux / AlmaLinux（RHEL 1:1 二进制兼容，成本最低），或**跨系切换**到 Debian/Ubuntu / openEuler（要重做包管理、配置与运维工具链）；容器化虽弱化了 OS 绑定，但基础镜像、glibc 与内核特性仍需逐个验证。

## 面试官视角
考官想听的是**决策依据**，不是发行版名字。能说出「先看是否依赖 RHEL 二进制兼容，再看运维工具链与信创要求，最后看迁移工具是否成熟」，并且给出分批灰度与回滚方案，才是工程级的回答。

## 主问答
**Q（面试官原话）：** CentOS 不让用了，你们线上迁到哪里？怎么评估的？

1. **先问兼容性**：依赖 RHEL 二进制兼容（如闭源驱动、商业中间件）优先 Rocky Linux / AlmaLinux，几乎零改造。
2. **再看工具链**：包管理从 rpm/dnf 换到 deb/apt 会牵动部署脚本、CI 镜像、配置管理，跨系迁移成本主要在这里。
3. **考虑合规与信创**：国内场景常要求 openEuler 等国产发行版，需评估内核版本与生态适配度。
4. **云与容器化**：云厂商定制系统 + 容器镜像让应用层与 OS 解耦，但要重做基础镜像并验证 glibc、内核特性。
5. **落地节奏**：先无状态服务灰度，再数据库与中间件；全程保留回滚镜像与数据备份，按批次推进。

## 版本与兼容性
| 方案 | 兼容性 | 适用 |
|------|--------|------|
| Rocky/AlmaLinux | RHEL 1:1 | 依赖闭源驱动/中间件 |
| Ubuntu/Debian | 需重做包 | 社区生态优先 |
| openEuler | 需适配 | 信创与国产化要求 |
| 云厂商定制 | 视厂商 | 云上弹性场景 |

## 总结与追问预判
核心：**先看二进制兼容，再看工具链与合规，最后分批灰度**。追问常拐向「迁移中踩过什么坑」，备好三个真实点：glibc 版本差异、systemd 单元路径、监控 agent 的内核模块依赖。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文把替代方案收敛为单一发行版并称其为首选——实际选型取决于是否依赖 RHEL 二进制兼容：依赖则优先 Rocky/AlmaLinux，不依赖则 Debian/Ubuntu 亦可，国内信创场景另有 openEuler。
2. 事实核校： [经验] 原文认为停更主要冲击 OS 厂商；对后端团队而言，直接成本是安全补丁断供与镜像重建，需自行制定升级节奏。
