> 分类：并发模型 | 难度：中 | 题型：八股题 | 频率：中 | 关键词：**int32/64、unsafe.Pointer、atomic.Value、单变量**

> 原文锚点：第 5~14 段「原子操作保护单个变量…常用于计数器、状态变量」

## 一句话总述
原子操作只作用于"单个变量"，标准库支持 int32/int64/uint32/uint64/uintptr/unsafe.Pointer 及 atomic.Value；多变量组合一致性必须上锁。一句话背法：**「原子只护单变量：标量/unsafe.Pointer/atomic.Value，多字段上锁或聚合进 Value」**。

## 面试官视角
考官考察是否知道原子能保护哪些类型、边界在哪。能列支持类型与 atomic.Value、并讲清"多字段需锁或聚合到单个 atomic.Value"，说明有体系；对 struct 直接 atomic.Load、以为原子能保护一段逻辑，是红旗。
- **P5**：知道计数器用原子。
- **P6**：能列支持类型与 atomic.Value。
- **P7**：知道多字段需锁或聚合到单个 atomic.Value。

## 主问答
**Q（面试官原话）：** 哪些类型能用原子操作？原子能保护一段代码吗？

**先铺垫（由浅入深第 1 层）**：原子的"原子性"被绑定在"一个内存地址的一次读-改-写"上。所以它天生只能罩住"一个变量"。想护一个 struct、想护"先读后写带条件"的一段逻辑，都超出了它的能力圈——这是理解适用类型与范围的总钥匙。

1. **结论（第 2 层）**：原子仅保护单个变量，支持 int32/64、uint32/64、uintptr、unsafe.Pointer，以及承载任意值的 atomic.Value。
2. **机制（第 3 层）**：每个原子函数操作一个地址；atomic.Value 内部用指针原子交换实现类型安全的整体替换。
3. **边界（第 4 层）**：原子不能保护"多个变量 + 条件"的复合临界区，那样会出现竞态，必须 mutex。
4. **加分层（第 5 层）**：Go 1.19+ 推荐 `atomic.Int64` / `atomic.Bool` 等**类型化原子变量**，比手写地址更不易出错（编译期防类型错配）。
5. **误用风险（第 6 层）**：对 struct 直接 `atomic.Load(&s)` 编译不过；把多字段一致性塞进多个独立原子变量仍非事务——要上锁或把整个值聚合成一个 `atomic.Value`（存入类型须一致，否则 panic）。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| 支持类型 | int32/64、uint32/64、uintptr、unsafe.Pointer + atomic.Value |
| atomic.Value | 存任意类型但要求存入类型一致，否则 panic |
| 类型化 API | Go 1.19+ `atomic.Int64`/`atomic.Bool` 等，免手写指针 |
| 多字段 | 必须 Mutex 或聚合到单个 atomic.Value |
| Go 版本 | 类型化 API 始于 Go 1.19，本项目实测 Go 1.26.5 |

## 关键代码
```go
package main

import (
	"fmt"
	"sync/atomic"
)

func main() {
	// 类型化原子（Go 1.19+）：免手写指针，编译期防类型错
	var c atomic.Int64
	c.Store(42)
	c.Add(1)
	fmt.Println("atomic.Int64:", c.Load()) // 43

	var b atomic.Bool
	b.Store(true)
	fmt.Println("atomic.Bool:", b.Load()) // true

	// atomic.Value：可存任意类型，但后续 Store 必须同类型
	var v atomic.Value
	v.Store("hello")
	fmt.Println("atomic.Value:", v.Load()) // hello
	// v.Store(42) // panic：与首次存入类型不一致（string != int）
}
```

## 总结与追问预判
**背这三句就够**：① **原子只护单变量：int/uint 标量、unsafe.Pointer、atomic.Value**；② **atomic.Value 存任意类型但必须同类型，否则 panic**；③ **多字段一致必须上锁或聚合进单个 atomic.Value（Go 1.19+ 用类型化原子更稳）**。
**预判追问**：
- 「struct 能原子吗？」→ 不能，多字段上锁或聚合进 Value（见 104 原子陷阱）。
- 「复合逻辑怎么办？」→ CAS 循环或 Mutex（见 105 何时用原子 / 105 无锁原理）。
- 「类型化原子有啥好？」→ 编译期防指针/类型错配（见 104 原子本质）。
