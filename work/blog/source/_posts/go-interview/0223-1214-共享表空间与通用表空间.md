> 分类：MySQL 存储 | 难度：L3 | 题型：对比题 | 频率：中 | 关键词：**共享表空间**/**系统表空间**/**IBdata**/**通用表空间**/**64TB**
> 原文锚点：第 9~10 段、第 39~45 段「共享表空间 + 通用表空间」

## 一句话总述
**共享表空间**（典型是系统表空间 `IBdata`）多表共用一个文件，删除数据不回收、只复用，且 64TB 上限被所有表分摊；**通用表空间**（5.7+）是共享型、结合了系统表空间与 file-per-table 的优势，元数据内存占用更少、可放 mysql 目录外。

## 面试官视角
- 考察意图：是否分得清三类「共享型」表空间的取舍，尤其通用表空间的出现动机。
- 分档：P5 知共享=多表共用；P6 知 IBdata 删数据不回收；P7 知通用表空间 5.7+、内存优势、可挪目录。
- 红旗答案：以为共享表空间删表会回收空间；或不知道通用表空间版本起点。
- 惊艳点：点出「通用表空间数据可在 file-per-table 与系统表空间间移动，但二者之间不直接互移」。

## 主问答
**Q（面试官原话）：** 共享表空间有什么特点？通用表空间又是什么？
**A：**
1. **共享表空间（系统表空间）**：多表数据存进同一 `IBdata` 文件；删除的数据空间不回收，仅用于下次写入复用；64TB 上限由库内所有表共享，分摊到单表很小（万表时每表上限极低）。
2. **通用表空间（general tablespace）**：MySQL 5.7 引入，仍是共享型、可存多表，结合了系统表空间与 file-per-table 的优点；服务器在表空间生命周期内把文件元数据放内存，**同数量表下比 file-per-table 元数据内存占用更少**。
3. **通用表空间-位置**：数据文件可放在 mysql 数据目录之外，按表的性能要求绑定独立磁盘/DRBD，实现 IO 隔离；支持所有行格式。
4. **通用表空间-移动**：表数据可在 file-per-table 与系统表空间之间移动，但 file-per-table 与系统表空间两者不直接互移。

## 关键代码
```sql
-- 创建通用表空间（可指定数据目录外路径）
CREATE TABLESPACE ts1 ADD DATAFILE '/disk2/ts1.ibd' ENGINE=INNODB;
-- 建表时指定通用表空间
CREATE TABLE t1 (id INT) TABLESPACE ts1 ENGINE=INNODB;
-- 在 file-per-table 与系统表空间间移动
ALTER TABLE t1 TABLESPACE=innodb_file_per_table;
```

## 总结与追问预判
共享表空间省内存但空间不回收、上限被分摊；通用表空间两全其美但有版本门槛。临时/undo 表空间另走一套——下一张。
