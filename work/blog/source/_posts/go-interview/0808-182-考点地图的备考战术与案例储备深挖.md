> 覆盖源 18-2 的落地延伸：十大考点与本卡库的映射关系、案例储备的 STAR 化改造、「弱项主动暴露」话术、考点清单的时间分配。主卡已给三技巧与考点地图，本附录做战术深挖。

## 思路与架构

```text
十大考点 -> 案例化的备考优先级
├─ 必考且易拉分 (先攻)
│   ├─ TCP 握手/挥手/状态机 -> 卡库 1844/1847/1851
│   ├─ 进程调度/死锁/虚拟内存 -> 1826/1829 系列
│   └─ 性能四象限工具链 -> 188/1810/1811 系列
├─ 必考但答法模板化 (中攻)
│   ├─ TCP vs UDP / HTTP 版本演进
│   └─ OSI 与 TCP/IP 分层模型
└─ 加分项 (后攻)
    ├─ 网络设备/安全 (非后端岗核心)
    └─ Shell 编程细节
└─ 案例储备 (贯穿)
    ├─ OOM 案例: 现象->pprof->根因->修复->验证
    └─ 过载案例: 指标->归因->限流/扩容->复盘
```

## 方案取舍
- **考点清单的用法是「映射」不是「通读」**：把每个高频考点映射到自己的一张卡/一个实测——TCP 挥手映射 2MSL 实测、虚拟内存映射页缺失验证、IO 排查映射 iostat 对账。清单背完就忘，**「考点→证据」的映射结构**才能在追问时自动展开。备考的时间分配也照此排序：必考易拉分项吃透实测，模板化项背骨架，加分项扫读 [经验]。
- **案例储备的 STAR 化**：OOM/过载案例不能只讲故事，要压成四段——**现象**（什么指标在什么时间异常）、**定位**（用什么工具什么路径缩小到根因）、**修复**（改了什么、为什么这样改）、**验证与复盘**（怎么确认生效、沉淀了什么监控/流程）。考官追问任意一段都要能下钻一层：讲定位就要能答「为什么先看内存不看 CPU」的排除顺序 [经验]。
- **弱项主动暴露的话术价值**：地图感的最高级用法是主动划界——「网络设备这块我只有概念级了解， socket 编程和协议栈是我的强项，可以往深问」。收益有三：把考官的火力引向自己准备过的区域；展示自我认知的准确度；避免在弱区被动挨打后拖垮整场节奏。代价是必须真的有强项区，否则是自杀式引火 [经验]。
- **通用三技巧 vs 域专属技巧**：结构化回答、结论先行是全域通用（见 `902`），但网络/OS 题有专属结构——**排查题按层走（设备→进程→应用）、原理题按模型走（报模型图再下钻）、对比题按维度表走**。三种骨架各练 2~3 题，考场上骨架自动浮现 [经验]。

## 答题技巧
- 被问「网络 OS 怎么准备」先报地图再报自己的强弱分区——地图感 + 自我认知双信号 [经验]。
- 案例必须四段齐全且能白板画链路图：OOM 案例画出「指标异常 → 工具定位 → 根因 → 修复验证」的箭头图，比纯口述高一档 [经验]。
- 排查类问题的回答永远按「层」组织，从设备层往上——与考官的归因直觉同频 [经验]。
- 主动边界到 `902-internals-answer-method`（通用三件套）、`181-linux-interview-roadmap`（Linux 五域备考路线）、`171-dsa-interview-prep`（算法域）、`122-db-interview-map`（DB 域），构成「分域备考地图」系列 [边界]。
