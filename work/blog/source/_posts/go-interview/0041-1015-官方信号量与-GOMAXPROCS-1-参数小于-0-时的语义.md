> 分类：并发模型 | 难度：L3~L4 | 题型：陷阱题 | 频率：中 | 关键词：**semaphore、NewWeighted、GOMAXPROCS(-1)、逻辑 CPU、限流**

> 原文锚点：第 53~60 段「通过包提供的方法传一个资源的数量，这里传的是本机逻辑 CPU 的个数，调用 GOMAXPROCS 传负一，获取的就是当前逻辑 CPU 的个数」

## 一句话总述
官方扩展库的信号量用 `NewWeighted` 传入资源数；常用写法是传 `runtime.GOMAXPROCS(-1)`——**传负值不会修改设置，只返回当前值**，即本机逻辑 CPU 个数。一句话背法：**「GOMAXPROCS(-1) 是只读调用——不改设置、只返回当前逻辑 CPU 数，官方信号量拿它当并发上限」**。

## 面试官视角
这是 semaphore 与 runtime 的交叉考点。考官看你是否真读过 `GOMAXPROCS` 的语义，还是只会背"传 -1 拿 CPU 数"。
- **P5**：说出"传 -1 拿到逻辑 CPU 数"。
- **P6**：讲清这个调用的两重语义——值小于 0 时**设置不生效**，但**仍返回旧值** `[源码]`。
- **P7**：点出 Go 1.20 起默认就等于操作系统逻辑 CPU 数，返回值可作并发上限参考；并知道官方信号量比通道强在加权与上下文取消 `[经验]`。

## 主问答
**Q（面试官原话）：** `GOMAXPROCS(-1)` 到底做了什么？

**先铺垫（由浅入深第 1 层）**：`runtime.GOMAXPROCS(n)` 的作用是"设置可同时执行用户 Go 代码的操作系统线程数上限"。它既能读（不传有效值）也能写（改变调度并发度）。面试里那句"传 -1 拿 CPU 数"，本质是利用了它的**读**语义。

1. **定位（第 2 层·机制）**：参数小于 0 时**不会改变**并行执行的 CPU 上限，但函数**仍然返回修改前的值** `[源码]`。这是"只读不写"的惯用法。
2. **返回值（第 3 层）**：未显式设置过时，返回的就是当前默认的逻辑 CPU 个数；实测本机返回 12 `[实测]`。
3. **当资源数（第 4 层）**：把信号量的资源数设成逻辑 CPU 数，可让并发度与机器能力匹配，避免开太多 goroutine 抢占调度 `[经验]`。
4. **加权能力（第 5 层）**：与通道实现的计数信号量不同，官方信号量支持一次申请多个资源、支持尝试获取、还能绑定 `context` 做超时取消 `[源码]`。
5. **使用频率（第 6 层）**：通道写法已覆盖大多数限并发场景，官方信号量在日常开发中频率很低，但**读开源代码会遇到**，要认得 `[经验]`。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| Go 1.5 起 | `GOMAXPROCS` 默认取逻辑 CPU 数，可答"默认等于 CPU 数" |
| Go 1.20 起 | 默认值口径明确，返回值即逻辑 CPU 数 |
| Go 1.26 实测 | `GOMAXPROCS(-1)` 与 `NumCPU()` 均返回 12，可交叉验证 |
| 所属包 | `golang.org/x/sync/semaphore`（标准库外，需 `go get golang.org/x/sync`） |
| 核心 API | `NewWeighted(n)` / `Acquire(ctx, n)` / `TryAcquire(n)` / `Release(n)` |
| 生产建议 | 限并发更常见写法是通道或协程池；信号量属"认得即可" |

## 关键代码
```go
package main

import (
	"context"
	"fmt"
	"runtime"
	"time"

	"golang.org/x/sync/semaphore"
)

func main() {
	// ① GOMAXPROCS(-1)：不改设置，只返回当前值
	n := runtime.GOMAXPROCS(-1)
	fmt.Println("GOMAXPROCS(-1) =", n, " NumCPU =", runtime.NumCPU())
	// 两次调用结果一致 -> 确认是"只读"不修改

	// ② 用返回值作为信号量资源数（并发上限 ≈ 逻辑 CPU 数）
	ctx := context.Background()
	sem := semaphore.NewWeighted(int64(n))

	var done int
	for i := 0; i < n*2; i++ {
		if err := sem.Acquire(ctx, 1); err != nil {
			panic(err)
		}
		go func() {
			defer sem.Release(1)
			time.Sleep(10 * time.Millisecond)
			done++
		}()
	}
	// ③ 取满资源做"全部完成"的屏障
	_ = sem.Acquire(ctx, int64(n))
	fmt.Println("all", done, "workers done, max concurrency ≈", n)
}
```

## 总结与追问预判
**背这三句就够**：① **GOMAXPROCS(-1) 是只读调用，不改设置只返回当前值**；② **未设置时返回值即逻辑 CPU 数**；③ **官方信号量比通道强在加权 + 尝试获取 + ctx 取消，但用得少、认得即可**。
**预判追问**：
- 「GOMAXPROCS 设 0 或负数会怎样？」→ 负数=只读返回旧值；0=返回旧值且保持（等价 -1 的读语义）。
- 「信号量和通道限流怎么选？」→ 简单限并发用通道更直观；要加权/超时取消才上信号量。
- 「默认值现在是多少？」→ Go 1.20+ 等于 `NumCPU()`（逻辑 CPU 数）。

## ⚠️ 原文纠错
1. 事实核校：原文"传负一获取的是当前逻辑 CPU 个数"准确；补充——严格说是**返回修改前的值**，在未设置的情况下才等于逻辑 CPU 数，两句话不等价 `[源码]`。
2. 补充：原文称官方信号量"几乎用不到"是经验判断，准确说法是**简单限并发用通道更直观**，它价值在加权与上下文取消，读开源项目时会遇到 `[经验]`。
3. 崩坏词归一：源码将信号量、goroutine、逻辑 CPU、上下文等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
