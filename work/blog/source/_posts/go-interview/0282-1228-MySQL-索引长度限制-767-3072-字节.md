> 原文锚点：第 1~27 段「索引长度限制与行格式有关：compact/redundant 限 767 字节、dynamic/compressed 限 3072 字节；溢出阈值 768；UTF8MB4 下 varchar(255)*3=765 可、256*3=768 超限；联合索引总长也受限」

## 一句话总述
MySQL 单索引（含前缀/联合）最大字节数受**行格式**约束：COMPACT/REDUNDANT 上限 **767 字节**（因行溢出阈值是 768，索引只存前 767），DYNAMIC/COMPRESSED 上限 **3072 字节**。超限建表直接报 `Specified key was too long`（最大 3072）。UTF8MB4 每字符 4 字节，故 `varchar(255)` 在 utf8 下 255×3=765 勉强过关、`varchar(256)` 768 即超限——字符集与行格式共同决定上限。

## 面试官视角
- 考察意图：是否理解"索引长度限制"不是固定值，而随行格式/版本/字符集浮动
- P5 能说"索引有长度限制、超了建不了"；P6 能讲 767/3072 与行格式关系、UTF8MB4 数学；P7 能讲清"为什么是 767"（行溢出阈值 768→索引 767）+ 联合索引也累计受限
- 红旗：以为索引长度限制恒为 767；忽略字符集（UTF8MB4 4 字节）影响
- 惊艳点：点出"767 来自 compact 行溢出阈值 768——索引只存溢出前 767 字节"这一根因 [源码]

## 主问答
**Q（面试官原话）：** 为什么给字段加索引有时会报 key too long？
**A：**
1. **两个上限随行格式**：COMPACT/REDUNDANT 单索引上限 **767 字节**；DYNAMIC/COMPRESSED 上限 **3072 字节**——根因是 compact 行溢出阈值为 768 字节，索引只存溢出前 767 [源码]。
2. **字符集放大占用**：UTF8MB4 每字符最多 4 字节；`varchar(255)` 在 utf8（3 字节）下 255×3=765 ≤767 可建，`varchar(256)` 256×3=768 >767 即超限；若用 utf8mb4 则 255×4=1020 早已超 767 [源码]。
3. **联合索引也累计**：单列/前缀/联合索引的**字节总长**都不能超上限；如 `latin1` 下建 `varchar(3073)` 索引（3073>3072）直接报错，改 3072 即可 [源码]。

## 关键代码
```sql
-- utf8 下 varchar(255)*3=765 ≤767 可建；varchar(256)*3=768 超限
CREATE TABLE t1 (a VARCHAR(255), KEY(a)) CHARSET=utf8;   -- OK
-- CREATE TABLE t2 (a VARCHAR(256), KEY(a)) CHARSET=utf8; -- ERROR 1071: Specified key was too long; max 767
-- latin1 下单列超 3072 也报错
CREATE TABLE t3 (a VARCHAR(3072), KEY(a)) CHARSET=latin1; -- OK（3072≤3072）
```
