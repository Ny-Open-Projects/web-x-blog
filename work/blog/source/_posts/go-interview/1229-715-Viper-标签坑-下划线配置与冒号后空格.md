> 分类：配置中心 / Viper | 难度：L3 | 题型：排错题 | 频率：高 | 关键词：**mapstructure、yaml 标签、下划线字段、冒号空格、解析失败**

> 原文锚点：第 62~74 段「HTTPport 带下划线，用 yaml 标签解析不到，换成 mapstructure 才解析到 80；mapstructure 标签冒号后多一个空格也解析不到」

## 一句话总述
Viper 解析字段靠 `mapstructure` 标签，而非 yaml 标签：带下划线的配置项（如 http_port）yaml 标签解析不到，且 `mapstructure:` 后面绝不能有多余空格，否则该项静默读不到。

## 面试官视角
P6 知道换 mapstructure 能解；P7 要讲清根因——yaml 标签不支持带分隔符的键，且 Viper 按标签名精确匹配，空格会破坏匹配导致该字段零值，且**不报错**最易踩坑。

## 主问答
**Q（面试官原话）：** 为什么我改了配置，某个字段始终是零值？

1. **下划线字段**：配置键含下划线（http_port）时，yaml 标签兼容性差，Viper 解析不到，应改用 `mapstructure` 标签 `[源码]`。
2. **冒号后空格**：`mapstructure: port` 多一个空格，标签名变成含空格的字符串，与配置键不匹配，字段读不到 `[源码]`。
3. **零值不报错**：解析失败不 panic 而是给零值，问题被掩盖，靠打印结构体才能发现 `[实测]`。
4. **对齐写法**：所有字段统一用 `mapstructure:"xxx"`，键名与配置文件严格一致 `[经验]`。
5. **ENV 无下划线**：ENV 这类无连接符的字段即使有空格仍可读，但为一致仍建议无空格 `[经验]`。

## 关键代码
```go
type Config struct {
    HTTPPort int    `mapstructure:"http_port"` // 正确：下划线+无空格
    Env      string `mapstructure:"env"`
    // Bad: `yaml:"http_port"`      带下划线解析不到
    // Bad: `mapstructure:"http_port "` 空格破坏匹配
}
```

## ⚠️ 原文纠错
1. 事实核校：下划线字段 yaml 标签解析不到、换 mapstructure 解决、冒号后空格导致匹配失败——三点均准确 `[经验]`。
2. 补充：原文说 ENV 有空格仍能读到，根因是 ENV 无连接符不触发精确匹配差异；统一无空格最稳 `[经验]`。
3. 崩坏词归一：源码将 mapstructure、结构体等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
