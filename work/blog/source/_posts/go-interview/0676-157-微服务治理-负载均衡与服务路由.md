## 一句话总述
提供者多节点时，消费者靠**负载均衡**选节点、靠**服务路由**做定制：五种 LB（轮询/加权/最少连接/随机/源地址哈希）+ 路由规则（条件/正则，满足机房就近、灰度发布等复杂诉求）。

## 面试官视角
- 考察意图：能否列出常见 LB 算法并说清各自适用场景，以及 LB 与路由的区别。
- 分档：P5 知轮询/加权/最少连接；P6 知随机/源地址哈希及适用、LB 与路由区别；P7 知最少连接需维护连接数、源地址哈希保会话。
- 红旗答案：以为 LB 只有轮询；把路由当成 LB 的子集（路由是按规则限定范围，LB 是均等分发）。
- 惊艳点：点出「最少连接法适用于处理时间不均、源地址哈希适用于需保持会话」，以及「灰度/机房就近 LB 算法满足不了，必须靠路由规则」 [经验]。

## 主问答
**Q（面试官原话）：** 负载均衡有哪些算法？路由干嘛用？
**A：**
1. **五种负载均衡算法**：①**轮询**（性能相近）；②**加权轮询**（按权重分配，性能不同）；③**最少连接**（选连接数最少节点，处理时间不均）；④**随机**（性能相同，效果略逊轮询）；⑤**源地址哈希**（按客户端 IP 哈希，保同一客户端落同一节点、适需会话状态）[经验]。
2. **服务路由补 LB 不足**：LB 只解决「均等选谁」，复杂需求（**机房就近访问**、**灰度发布**让部分请求走指定环境）需**路由规则**（条件表达式/正则）限定节点选择范围 [经验]。
3. **多节点是前提**：负载均衡/路由成立的前提是提供者**部署多节点**，否则无「选哪个」可言 [经验]。

## 关键代码

```go
// 加权轮询（性能不同节点）：按权重轮流选中，权重高者多得
type WeightedRR struct {
    addrs   []string
    weights []int
    cursors []int // 每个节点当前累计（平滑加权轮询核心）
    total   int
}
func (w *WeightedRR) Next() string {
    best, bi := 0, 0
    for i := range w.addrs {
        w.cursors[i] += w.weights[i] // 累加权重
        if w.cursors[i] > best {
            best, bi = w.cursors[i], i
        }
    }
    w.cursors[bi] -= w.total // 选中节点扣回总权重
    return w.addrs[bi]
}
```
