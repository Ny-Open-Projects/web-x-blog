> 原文锚点：第 38~55 段「暴力 close+recover 不推荐；用 Once 或锁+标志位保证只关一次」

## 一句话总述
重复 `close(ch)` 会 panic；把 close 包进 `sync.Once.Do`，或用「互斥锁 + 已关闭标志位」封装，可保证 channel 只被关闭一次，调用方多次 close 也安全。一句话背法：**「Once 包 close，多 goroutine 调也只真正的关一次」**。

## 面试官视角
- 意图：有没有处理"多处可能触发关闭"的并发安全性。
- **P5**：知道 `Once` 只执行一次，能防重复 close panic。
- **P6**：说清锁+标志位的 double-check 写法，以及 Once 内部就是这套机制。
- **P7**：知道这是**兜底**手段，正常应靠「关闭责任唯一（发送方）」；并指出用 `recover` 吞 panic 是反模式。

## 主问答
**Q（面试官原话）：** 可能多处都要关 channel，怎么防重复关闭 panic？

**先铺垫（由浅入深第 1 层）**：向已关闭的 channel 再 `close` 会直接 panic（`close of closed channel`）；多 goroutine 或多次清理路径都去关同一个 ch 时极易踩中。

1. **结论（第 2 层·机制）**：把 close 包进 `sync.Once.Do`，或加锁读"已关闭"标志、关后置 true，确保只关一次。
2. **Once 机制（第 3 层）**：`Once.Do` 内部用「互斥锁 + 已执行标志」实现 double-check，多 goroutine 并发调用也只让闭包执行一次，天然防重复 close。
3. **锁+标志位写法（第 4 层）**：先加锁，再二次判「已关闭」标志，未关才 `close` 并置 true——避免「加锁前已被别 goroutine 关掉」的竞态。
4. **边界（第 5 层·最常考）**：这是**兜底**，正常设计应让关闭责任唯一（只由发送方关），封装只在责任难收敛时救急；向已关闭 channel **发送**依然 panic，Once 只防「关闭」不防「发送」。
5. **误用风险（第 6 层）**：用 `recover` 吞 close panic 当正常流程是反模式——它掩盖了「关闭责任归属错误」这一根因，且 recover 无法恢复已损坏的状态。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

// SafeChan：用 sync.Once 封装，Close 可多次调用而不 panic
type SafeChan struct {
	ch   chan int
	once sync.Once
}

func NewSafeChan() *SafeChan { return &SafeChan{ch: make(chan int, 1)} }

// Close：多次调用安全，真正的 close 只发生一次
func (s *SafeChan) Close() {
	s.once.Do(func() { close(s.ch) })
}

// 锁 + 标志位 写法（等价 Once，便于理解 double-check）
type SafeChan2 struct {
	ch     chan int
	mu     sync.Mutex
	closed bool
}

func (s *SafeChan2) Close() {
	s.mu.Lock()
	defer s.mu.Unlock()
	if !s.closed {
		s.closed = true
		close(s.ch)
	}
}

func main() {
	sc := NewSafeChan()
	var wg sync.WaitGroup
	for i := 0; i < 5; i++ { // 5 个 goroutine 同时 Close，不 panic
		wg.Add(1)
		go func() { defer wg.Done(); sc.Close() }()
	}
	wg.Wait()
	fmt.Println("多次 Close 未 panic（Once 保证只真正关一次）")
}
```

## 总结与追问预判
**背这三句就够**：① **重复 close 会 panic**；② **Once 包 close 只真正执行一次**；③ **它是兜底，正常应关闭责任唯一（recover 吞 panic 是反模式）**。
**预判追问**：
- 「关闭后还能发送吗？」→ 不能，向已关闭 channel 发送仍 panic，Once 只防关闭。
- 「正常设计怎么避免？」→ 关闭责任唯一归属发送方，收方不关（见 1021 责任矩阵）。
- 「Once 底层怎么保证一次？」→ 互斥锁 + done 标志 double-check（见 1021）。
