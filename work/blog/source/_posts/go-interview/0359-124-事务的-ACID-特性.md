> 分类：MySQL 内核 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**ACID**/**原子性**/**持久性**/**隔离性**
> 原文锚点：第 1~13 段「SID 特性…原子性/一致性/隔离性/持久性」

## 一句话总述
**ACID** 是事务四大特性——**原子性(Atomicity)**、**一致性(Consistency)**、**隔离性(Isolation)**、**持久性(Durability)**，是数据库可靠性的基石；其中原子性靠 undo、持久性靠 redo、隔离性靠锁+MVCC，一致性是它们共同维持的"结果约束"。

## 面试官视角
- 考察意图：是否分清四特性定义，以及"谁保证谁"。
- 分档：P5 能背四词；P6 说清各自含义；P7 能讲"D 靠 redo、A 靠 undo、I 靠锁+MVCC、C 是目标态"。
- 红旗答案：把 ACID 当成四个互不相关的独立机制，说不清谁保证谁。
- 惊艳点：指出 **C 不是靠单一日志，而是 A/I/D 共同维持的结果约束** `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是 ACID？四个特性分别是什么意思？
**A：**
1. **结论**：A=要么全做要么全不做；C=事务前后都满足一致性约束；I=并发事务互不干扰；D=提交后改动永久生效。
2. **机制**：原子性靠 **undo log** 回滚实现；持久性靠 **redo log** 崩溃重放实现；隔离性靠 **锁 + MVCC** 实现；一致性是上述三者共同保证的"数据库始终合法"的结果态。
3. **边界**：面试常问"D 靠谁保证"——提交后即便宕机，重启也能靠 redo 把已提交事务的改动重放到磁盘，所以不丢。

**加分层：** 一致性（C）更像"验收标准"而非"机制"——它要求 A/I/D 都正确，最终数据才满足业务约束（如余额不为负）。

## 关键代码
```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;   -- 成功→D 由 redo 保证；失败 ROLLBACK→A 由 undo 保证
```

## 总结与追问预判
ACID 四特性中，A/D/I 各有"负责人"（undo/redo/锁+MVCC），C 是结果。追问接"redo 与 binlog 区别"和"undo 与 MVCC"。

## ⚠️ 原文纠错
1. 机翻崩坏词归一：`SID`→**ACID**（Atomicity/Consistency/Isolation/Durability 缩写）；`原则性`→**原子性**(Atomicity)；`crushrecover`/`clashrecover`→**crash recovery**。事实正确，仅术语崩坏，本卡已归一 `[经验]`。
2. 原文"一致性指从事务一种一致态转移到另一种一致态"——表述准确，符合 C 的"约束满足"定义，本卡沿用。
