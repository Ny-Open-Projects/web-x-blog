> 分类：MySQL 调优 | 难度：中高 | 题型：原理深挖 | 频率：高 | 关键词：**EXPLAIN、执行计划、id、select_type、物化子查询、UNION**

> 原文锚点：第 1~109 段「EXPLAIN 各列、id 规律、select_type 谱系、物化/非物化、UNION」

## 思路与架构
读懂 EXPLAIN 要分三层：
- 列层：id（SELECT 编号）/ select_type（查询类型）/ table / type（访问方法）/ key（实际索引）/ rows（扫描量）/ Extra（覆盖/临时表/排序）。
- 拓扑层：id 相同=同 SELECT 多表（join，前驱动后驱动）；id 不同=多 SELECT（子查询/union）；union 比表数多一条（临时表）。
- 优化层：SUBQUERY=物化（一次、空间换时间、tmp_table_size 超限落盘）；DEPENDENT SUBQUERY=非物化（多次）；UNION RESULT=去重临时表；DEPENDENT UNION=子查询内受外层驱动。

## 方案取舍
- 看 id+select_type 先定拓扑，再看 type/key/rows 判定是否走索引、扫多少。
- 遇 DEPENDENT SUBQUERY：优先改写让子查询可物化（缩小范围），或改写为 join，避免每行重执行。
- 遇 UNION：确认是否真需去重，能 UNION ALL 就不用 UNION，省临时表。
- 物化临时表注意 tmp_table_size，过大落磁盘会拖慢；必要时调大或优化子查询范围。

## 答题技巧
1. 开口：EXPLAIN 是「不执行看执行计划」的第一工具，关键列 id/type/key/rows/Extra。
2. 读拓扑：同 id 是 join（前驱动后驱动），异 id 是子查询/union；union 多一条临时表。
3. 讲类型：SIMPLE/PRIMARY/SUBQUERY(物化)/DEPENDENT SUBQUERY(非物化)/UNION/UNION RESULT/DERIVED。
4. 优化落点：DEPENDENT 改物化或 join；UNION 能 ALL 就 ALL；关注 tmp_table_size。
5. 实战话术：「先用 EXPLAIN 看 id 和 select_type 定结构，再看 type/key/rows 找慢点，最后按拓扑优化子查询与 union。」

## 细节与核心 API

**拓扑判读（id / select_type）**：

```sql
EXPLAIN SELECT * FROM a JOIN b ON a.id=b.aid WHERE a.name='x';
-- id 相同 → join（a 驱动 b）；id 不同 → 子查询/union
-- select_type 谱系：SIMPLE / PRIMARY / SUBQUERY(物化,一次) / DEPENDENT SUBQUERY(非物化,逐行重执行)
--   UNION / UNION RESULT(去重临时表, union 比表数多一条) / DERIVED(派生表)
-- SUBQUERY 物化=空间换时间；DEPENDENT SUBQUERY 非物化=多次 → 改写 join 或缩小范围
```

```ini
tmp_table_size = 16M   # 物化临时表超此落盘，拖慢；必要时调大或优化子查询范围
# 能 UNION ALL 就不用 UNION，省去去重临时表
```
