> 分类：Elasticsearch | 难度：L3 | 题型：场景题 | 频率：中高 | 关键词：**副本提升、reroute、allocate_stale_primary、accept_data_loss、重平衡**

> 原文锚点：第 85~97 段「哪些情况下副本分片会升级为主分片…手动强制…接受数据丢失」

## 一句话总述
副本升级为主分片有**自动两条 + 手动一条**：节点宕机失联、集群重平衡、以及用集群路由 API 强制指定；若副本数据落后于原主，还需显式接受数据丢失才能强升。

## 面试官视角
P6 只知道"主分片挂了副本顶上"；P7 要报全三种触发，并给出**兜底判断**：当所有副本都不完整（原主数据最新），ES 默认**不会**把不完整的副本提上去，因为那会造成数据丢失 `[经验]`。确需强升要追加数据丢失参数，这是最后手段 `[源码]`。

## 主问答
**Q（面试官原话）：** 主分片所在节点挂了，集群怎么恢复？

1. **节点宕机或失联**：在其他可用节点上挑一个持有相同副本的分片，把它提升为主分片 `[源码]`。
2. **补副本**：若原主一段时期内未上线，会从新的主分片复制一份数据，补上缺失的副本 `[经验]`。
3. **集群重平衡**：节点数量变化（新增或移除）触发重平衡时，副本也可能被提升为主以均衡负载 `[源码]`。
4. **手动强升**：用集群路由 API 执行强制分配主分片命令，指定索引、分片编号与目标节点；副本不完整时必须附加接受数据丢失参数 `[实测]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ES 全版本 | 自动提升语义一致 | 节点失联即触发选新主 |
| ES 7.x 起 | 强制分配命令名固定 | 需指定索引、分片、节点 |
| ES 8.x | 数据丢失需显式声明 | 默认拒绝不完整副本上位 |

// 强制提升是最后手段：必须先确认可以接受该分片的数据丢失

	return errors.New("refuse: replica is stale, promotion would lose data")
