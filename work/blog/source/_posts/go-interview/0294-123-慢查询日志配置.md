> 分类：MySQL 日志 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**slow_query_log**/**long_query_time**/**mysqldumpslow**
> 原文锚点：第 22~39 段「慢查询日志开启与阈值配置」

## 一句话总述
慢查询日志记录执行时间超过 `long_query_time` 的 SQL，是定位与优化慢 SQL 的第一抓手，配 `mysqldumpslow` 分析。

## 面试官视角
- 考察意图：必考——"怎么开慢日志、阈值是否含等于、怎么分析"，常结合索引优化。
- 分档：P5 知慢日志找慢 SQL；P6 知阈值"大于不含等于"；P7 知动态/配置开区别。
- 红旗答案：说"等于阈值也记录"。
- 惊艳点：点出 `log_queries_not_using_indexes` 只记"慢且未用索引"。

## 主问答
**Q（面试官原话）：** 怎么开启慢查询日志并分析慢 SQL？
**A：**
1. **开启与路径**：`slow_query_log=ON` 开、`slow_query_log_file` 指定路径；动态设仅对新连接生效、重启失效，永久需写配置文件。
2. **阈值 `long_query_time`**：超过（**不含等于**）该秒数的查询才记——正好等于阈值**不**记；设为 2 仅 >2s 入日志。
3. **无索引也记**：`log_queries_not_using_indexes=ON` 时，达阈值**且**未用索引才记；默认 OFF（只要超时就记）。
4. **分析工具**：`mysqldumpslow <path>` 聚合，比直接读文件可视化更好。

## 关键代码
```sql
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 2;
SHOW VARIABLES LIKE 'slow_query%';
```
```bash
mysqldumpslow /var/log/mysql/slow.log
```

## 总结与追问预判
慢日志三要素：`slow_query_log` 开、`slow_query_log_file` 定路径、`long_query_time` 定阈值（不含等于）；配 `mysqldumpslow` 落地优化。

1. 事实核校： [经验]阈值"大于不含等于"、动态改仅新连接生效且重启失效、配置写文件才永久，均正确。
