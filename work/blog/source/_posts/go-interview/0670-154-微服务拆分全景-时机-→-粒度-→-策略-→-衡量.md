> 原文锚点：第 1~61 段「时机 + 粒度 + 策略 + 衡量」

## 思路与架构
微服务拆分是"时机→粒度→策略→衡量"的闭环，本波聚焦**拆分粒度决策**（全库无此专题，152 仅覆盖选型权衡/何时用）：
1. **时机层（154-split-timing）**：单体优先、被迫拆分、基础设施就绪、演进式；边界 152-when-to-use（选型权衡）。
2. **粒度层（154-split-granularity）**：中庸+三个火枪手+50/30/20 权重；微≠越细。
3. **策略层（154-split-strategy-metrics）**：六策略定序 + 绞杀者模式。
4. **衡量层（154-split-strategy-metrics）**：内部/外部复杂度 + 交付周期 + 跨团队成本四维度。

## 答题技巧
- 答拆分按"时机→粒度→策略→衡量"递进，显式边界到 152（选型）与 158（容错）。
- 口诀：**单体优先演进拆，合适中庸莫极细；火枪手定三人组，六策绞杀量复杂度**。
- 易混点：微服务拆分粒度 ≠ 选型（152）；容错是拆分后的治理（158）。

## 细节与核心 API

**拆分闭环（时机→粒度→策略→衡量）：**

```text
时机：单体优先、被迫拆分、基础设施就绪、演进式
粒度：中庸 + 三个火枪手(约 3 人团队拥有/负责一个服务) + 50/30/20 权重；微≠越细
策略：六策略定序 + 绞杀者模式(Strangler Fig：在旧系统外圈逐步包新服务，流量渐切)
衡量：内部复杂度 + 外部复杂度 + 交付周期 + 跨团队成本 四维度
```
