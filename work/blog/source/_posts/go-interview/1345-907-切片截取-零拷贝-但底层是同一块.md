> 分类：Go 语言 | 难度：L3 | 题型：陷阱题 | 频率：高 | 关键词：**截取、共享底层数组、地址偏移、零拷贝**

> 原文锚点：第 52~68 段「截取不会发生值拷贝…地址只增加了 int 的长度」

## 一句话总述
对切片再截取**不会复制元素**，新旧切片共享同一块底层数组；从头截取时首地址相同，从中间截取时首地址只是向后偏移若干个元素大小。

## 面试官视角
P6 说"截取会生成新切片"；P7 要补出**两条硬结论**：不发生数据拷贝；非从头截取得到的切片，其容量是从新起点到原底层数组末尾 `[经验]`。加分点：原文用逐元素打印地址来证明——第二个元素的地址恰好等于从下标 1 截取得到的切片首地址，差值正好是一个 int 的大小 `[源码]`。

## 主问答
**Q（面试官原话）：** 切片截取之后，数据被复制了一份吗？

1. **不复制元素**：截取只是生成一个新的描述符，指向同一块底层数组 `[源码]`。
2. **从头截取地址相同**：新切片首地址与原切片首地址一致，因为起点没变 `[实测]`。
3. **从中间截取地址偏移**：首地址向后移动若干元素大小，原文实测差值正好是一个 int 的长度 `[实测]`。
4. **逐元素比对可证明**：遍历原切片打印每个元素地址，会与截取后切片的首地址对上 `[源码]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Go 1.x 全版本 | 截取语义未变 | 一律零拷贝、共享底层 |
| Go 1.2 起 | 三索引截取可用 | 可显式限制容量，避免误改 |
| 任意版本 | 与元素类型无关 | 偏移量取决于元素大小 |

## 关键代码
```go
s := []int{1, 2, 3}
s2 := s[:2]   // 从头截取，首地址与 s 相同
s3 := s[1:]   // 从下标 1 截取，首地址前进一个 int
fmt.Printf("%p %p %p\n", s, s2, s3)
fmt.Println(unsafe.Sizeof(int(0))) // s3 与 s 的地址差 = 该值
```
> 验证：s 与 s2 地址相同；s3 地址比 s 大 8（64 位下 int 为 8 字节）`[实测]`。

## 总结与追问预判
**截取是换一个描述符，不是换一份数据**。这也正是截取后改元素会互相影响、以及大切片截取不放手会造成内存无法释放的根因。
