> 分类：Go 语法/内存 | 难度：L2 | 题型：概念题 | 频率：低 | 关键词：**空结构体**/**空数组**/**末位对齐**/**零尺寸值**/**地址越界**
> 原文锚点：第 40~53 段「空结构体 size=0；作字段一般不对齐；作最后一个字段需对齐避免地址越界」

## 一句话总述
空结构体/空数组是**零尺寸值**（占 0 字节），作字段一般不做对齐；但作为结构体**最后一个字段时需对齐**——否则取其地址会返回结构体之外的悬空地址，存在误引用导致内存泄露的风险。

## 面试官视角
- 考察意图：是否知道零尺寸值与「末位空字段对齐」这个反直觉特例，以及背后的安全动机。
- 分档：P5 知空结构体 size=0；P6 知末位空字段需对齐；P7 知动机是避免取地址越界/悬空引用。
- 红旗答案：说空结构体永远不占空间（忽略末位对齐）；或不知为何末位要对齐。
- 惊艳点：点出「末位对齐是为防止 `&lastField` 指向结构体之外、被长期持有引发内存泄露」 [经验]。

## 主问答
**Q（面试官原话）：** 空结构体作字段时对齐有什么特别？
**A：**
1. **空结构体/空数组是零尺寸值**：没有任何字段的空结构体、没有任何元素的空数组，占据内存 **0 字节**；作其他结构体字段时一般不参与内存对齐 [经验]。
2. **末位空字段需对齐（特例）**：当空结构体/空数组位于结构体**最后一个字段**时，编译器会对其做对齐；非末位（如开头）则按普通字段布局、无需额外对齐（示例：末位空结构 size=8、开头空结构 size=4）[经验]。
3. **动机：避免地址越界**：若末位空字段不对齐，对其取地址会返回**结构体之外的悬空地址**；该指针若长期存活不释放，对应内存将无法回收，造成泄露——末位对齐正是堵这个洞 [经验]。

## 关键代码

```go
package main

import (
    "fmt"
    "unsafe"
)

type ST2 struct { a int32; _ struct{} } // 空结构体在最后 → size 8（需对齐）
type ST3 struct { _ struct{}; a int32 } // 空结构体在最前 → size 4（前面已对齐不计）

func main() {
    fmt.Println(unsafe.Sizeof(ST2{}), unsafe.Sizeof(ST3{})) // 8 4
}
```
