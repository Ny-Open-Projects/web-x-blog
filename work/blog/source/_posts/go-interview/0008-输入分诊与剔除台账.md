## 一、判定规则：什么算「有技术含量」

出卡前逐篇过这四条，**命中任意一条即剔除或降级**：

| # | 判定 | 动作 |
|---|---|---|
| R1 | **全文无技术点**——只有行为、流程、礼仪、心理、薪资等话题 | **剔除** |
| R2 | **技术点覆盖度 < 20%**——主体是软技能，只夹带一两句技术话 | **降级**：只抽取那几句，合并进相邻技术卡 |
| R3 | **含风险内容**——性别 / 年龄 / 地域 / 学历刻板印象，或明确无效甚至有害的建议 | **剔除，且不进入任何复述** |
| R4 | **纯元内容**——课程导学、总结、卖课话术 | **剔除** |

> 关键原则：**宁可少出一张卡，不要硬凑一张。**
> 源素材深度不够时如实标注「素材上限 L2」，而不是靠模型补充冲深度——那会同时违反「零幻觉」铁律和面试可信度。

### 3.2 风险内容（R3，必须剔除且不复述）

## 四、可复用机翻解码案例（跨批次复用）

从本篇提取，**建议追加进 SPEC 的机翻解码表**：

| 原文（机翻） | 还原 | 错译类型 |
|---|---|---|
| 穿着要**裸体** | 穿着要**得体** | 近音替代 |
| **小r** 留下好印象 | **HR** 留下好印象 | 英文字母被识别成汉字 |
| **首时**穿着得体 | **守时**、穿着得体 | 同音 |
| 通过**几月份先行加三点愣**的方式 | 「**金字塔原理 + 结论先行 + 三点式**」`[存疑]` | 术语整串崩坏，需按上下文重建 |
| **云鸟游戏规则** | 「**了解游戏规则**」`[存疑]` | 同音 |
| 正是我所**找**的 | 正是我所**要**的 | 近音 |

> `[存疑]` 两条无法确证，**不得直接采信**，只能作为"该处原文有误"的标记。

**新增错译类型**（原 SPEC 三条通则未覆盖）：
- **术语整串崩坏**——连续多个词被识别错，导致整句不可读。处理方式：**按上下文重建语义，而非逐字还原**。
- **编号/列表结构崩坏**——讲稿的「首先/其次/第三」被识别错或漏掉。处理方式：**以语义顺序重建编号，不硬信原文序数词**。

## 五、下一步建议

### 5.1 对 SPEC 的必要修改（已由本篇实证）

| # | 修改 | 依据 |
|---|---|---|
| 1 | **新增「输入分诊」前置步骤**——不通过 R1~R4 判定的源文件，直接进剔除台账，**不进入出卡流程** | 本篇若无出口，子 Agent 只能硬编或卡住 |
| 2 | **新增硬红线：禁止保留刻板印象内容** | 本篇第 8 段的性别断言 |
| 3 | **机翻解码表补充「术语整串崩坏」「编号结构崩坏」两类** | 本篇实测 |
| 4 | **剔除必须留台账**——记录路径、判定码、理由，便于复核与统计 | 本篇 |

> 修改 #1 是**最关键的**：没有"拒绝执行"的出口，遇到非技术内容时子 Agent 的默认行为就是**编一张假技术卡**。
> 这属于提示词的**功能性缺陷**，不是优化项。

### 5.2 可选：软技能内容另立产品线

24 篇软技能并非没有价值——`3-4 接面试电话`、`3-6 HR 问题回答`、`3-9 该问面试官什么`、`3-10 职业规划` 是**可以练的行为面试题**。

建议**不要混进技术卡**，而是另建 `target/behavioral/`：
- 骨架简化：`问题 → 回答框架（STAR / 金字塔）→ 范例话术 → 避雷`
- **不要**强行加 mermaid / API / 代码（那是技术卡的字段）
- 与「禁止说法清单」天然契合——软技能最容易被说错

> 优先级：**低于技术章**。先把 372 篇技术篇跑通，再决定是否做。
