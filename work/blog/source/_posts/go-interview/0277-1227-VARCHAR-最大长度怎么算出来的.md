> 分类：MySQL / 数据类型 | 难度：L4 | 题型：计算题 | 频率：中高 | 关键词：**65535、行长度上限、长度信息、NULL 标志位、最大字符数**

> 原文锚点：第 34~64 段「行的 size 太大…减去长度信息…减去 NULL 值标志位…除以单字符最大字节」

## 一句话总述
一条记录全部字段的字节总和上限是 **65535 字节**；varchar 可用长度 =（65535 − 长度信息字节 − 可为 NULL 的标志位 − 其他字段字节）÷ 单字符最大字节数。

## 面试官视角
P6 只记"65535"；P7 要能**当场推导**：长度信息按字节数是否超过 255 取 1 或 2 字节；可为 NULL 的列再占 1 字节标志位；主键等其他字段也要扣掉；最后除以字符集的单字符最大字节数并向下取整 `[经验]`。加分点：报错信息说的是"行大小过大"而不是"字段过长"，这个措辞本身就是线索 `[源码]`。

## 主问答
**Q（面试官原话）：** utf8mb4 表里 varchar 最大能设多少？

1. **限制的是整行不是单列**：报错提示行大小过大，因为 65535 是对一条记录全部字段的约束 `[源码]`。
2. **先扣长度信息**：字段字节数若超过 255，需要 2 字节记录长度；不超过则 1 字节 `[经验]`。
3. **再扣 NULL 标志位**：列允许为空还要再占 1 字节标记位；NOT NULL 则省下这 1 字节 `[源码]`。
4. **最后除单字符最大字节**：utf8mb4 是 4，utf8mb3 是 3，latin1 是 1；结果向下取整 `[实测]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| MySQL 5.6 / 5.7 / 8.0 | 行上限一致 | 均按 65535 字节推导 |
| 8.0 默认 utf8mb4 | 除数变 4 | 上限比旧 utf8 更小 |
| latin1 场景 | 除数为 1 | 单列可接近 65533 |

## 关键代码
```sql
-- utf8mb4 + INT 主键 + 可为 NULL：(65535-2-1-4)/4 = 16382
CREATE TABLE t (id INT, content VARCHAR(16382) CHARACTER SET utf8mb4);
-- 改成 NOT NULL 且用 utf8mb3：(65535-2-4)/3 = 21843
CREATE TABLE t2 (id INT, content VARCHAR(21843) CHARACTER SET utf8mb3 NOT NULL);
```
> 验证：16382 与 21843 均可建表成功，各加 1 即报行大小过大 `[实测]`。

## 总结与追问预判
**四步扣减：整行上限 → 长度信息 → NULL 标志 → 其他字段，最后除单字符最大字节**。下一步会问 TEXT 是否也占这个额度。

## ⚠️ 原文纠错
1. 事实核校：原文推导过程与结果（16382 / 21842 / 21843 / 65533）均正确，本卡沿用四步法 `[经验]`。
2. 补充：原文强调"限制针对整行而非单列"准确，这正是报错信息提示行大小的原因，本卡强化 `[源码]`。
3. 补充：原文"utf8 编码"应理解为其旧称（最大 3 字节），与 utf8mb4 的最大 4 字节需区分，本卡统一术语 `[经验]`。
4. 崩坏词归一：源码将 varchar、字节、字段、字符集等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
