> 原文锚点：第 3~13 段「辅助最小栈 → 入栈/出栈的同步规则 → 2,3,1 示例」

## 一句话总述
普通栈只能访问栈顶，求最小值要么 O(n) 遍历；解法是**空间换时间**——再加一个辅助最小栈：入栈时「新值比当前最小还小才压入最小栈」，出栈时「弹出的值等于最小栈顶就同步弹出」，push/pop/getMin 全部 **O(1)**。

## 面试官视角
「设计一个支持 O(1) 取最小值的栈」是设计题第一课，考官三连击：① 双栈的**同步规则**（何时压、何时弹）；② **重复最小值**怎么处理——这是本题埋的雷，答不出直接暴露「只会背模板」；③ 追问空间账（最坏 O(n)）与变体（O(1) 空间的差值栈）。第一问答完主动提重复值的坑，是本题最大的加分动作。

## 主问答
**Q（面试官原话）：** 设计一个栈，可以 O(1) 获取栈中的最小元素？

1. **朴素方案的两难**：弹出/访问只动栈顶；遍历找最小 O(n)。想 O(1) 必须额外记账——空间换时间。
2. **双栈结构**：数据栈存全部元素；最小栈只存「每一历史阶段的当前最小值」。GetMin 恒等最小栈顶，O(1)。
3. **入栈同步规则**：元素压数据栈；若最小栈为空**或新值 < 最小栈顶**，同时压最小栈。
4. **出栈同步规则**：弹出数据栈顶；若该值 == 最小栈顶，最小栈同步弹出——最小值回退到「它入栈前」的那个值。
5. **[实测] 源文示例走通**（go1.26.5）：push 2 → min=2；push 3 → min=2；push 1 → min=1；pop 弹出 1 → **min 回到 2**。整个生命周期与源文描述一致。
6. **⚠️ 该规则的隐藏炸弹**：严格小于才压、相等就弹，遇到**重复最小值会 panic**——[实测] push 2,3,2 后 pop，最小栈被清空，GetMin 触发 index out of range [-1]。修法（`<=` 压栈）与逐字节实测对账见深卡 `174-min-stack-duplicates.deep.md`。

## 关键代码
```go
// MinStack 双栈: 最小栈存"每阶段的当前最小"
// 注意: 压栈条件用 <= 而非 <, 否则重复最小值会弹空 panic (见深卡实测)
type MinStack struct {
	data []int
	min  []int
}

func (s *MinStack) Push(v int) {
	s.data = append(s.data, v)
	if len(s.min) == 0 || v <= s.min[len(s.min)-1] {
		s.min = append(s.min, v)
	}
}

func (s *MinStack) Pop() {
	v := s.data[len(s.data)-1]
	s.data = s.data[:len(s.data)-1]
	if v == s.min[len(s.min)-1] {
		s.min = s.min[:len(s.min)-1]
	}
}

func (s *MinStack) GetMin() int { return s.min[len(s.min)-1] }
```

## 总结与追问预判
核心：**辅助最小栈 + 压弹同步规则，三操作全 O(1)；压栈条件必须 `<=` 防重复最小值**。追问常拐向「重复最小值」「空间优化」——实测 panic 与两种修法见 174.md`；栈的数组/链表实现底座见 173.md`/`173-linkedlist-stack.md`，栈队列互模拟见 175.md`。

## ⚠️ 原文纠错
1. 事实核校： [实测] 开篇「栈具有**先进先出**的特点」为转写错误——栈是**先进后出（FILO/LIFO）**，先进先出是队列；源文前节（17-6 相关内容）亦按 FILO 讲解，此处前后矛盾。
2. 事实核校： [经验] 「严格小于才压最小栈」配合「相等就弹」在重复最小值场景下会**把最小栈弹空**——[实测] push 2,3,2 后 pop 触发 index out of range panic，正确条件是 `<=`。原文 2,3,1 示例恰好不含重复值，掩盖了该缺陷。
