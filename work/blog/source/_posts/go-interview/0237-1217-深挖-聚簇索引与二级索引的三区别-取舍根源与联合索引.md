> 原文锚点：第 29~57 段「为什么不在非主键索引树的叶子节点上也存储完整的用户字段呢…第一个呢就是考虑到磁盘空间的占用…通过聚簇索引进行回表的查询，也就是主键查询，它的效率会比较高…并非所有的查询都需要回表…name和age的联合索引呢只会生成一棵B+树，而分别创建索引呢会生成两棵B+树…在存储方式上…在查询性能上…在数据更新的性能上」

## 思路与架构

按「**为什么这样设计 → 三条区别 → 联合索引**」三层把握：

1. **为什么二级索引叶子不存完整记录（三个原因）**：
   - **磁盘空间**：每对一个字段建索引就要**多存一棵 B+树**；若再把整表记录复制一遍，**占用过大**，对大字段尤甚 `[源码]`。
   - **回表已经够快**：**通过聚簇索引回表（即主键查询）效率较高**，没必要**牺牲太多空间换取少量时间** `[源码]`。
   - **并非所有查询都要回表**：**只取索引字段时无需回表**（覆盖索引） `[源码]`。
2. **三条区别**：
   - **存储方式**：聚簇索引**直接把数据存在叶子节点**，目录项是**主键 + 页号**，**一个表只能有一个**且由 InnoDB 自动创建；二级索引是**一棵独立的 B+树**，叶子存**主键值 + 索引字段值**，目录项是**索引字段 + 页号**，**一个表可以有多个**。聚簇索引记录**物理连续**，非聚簇索引**仅逻辑连续、物理不连续** `[源码]`。
   - **查询性能**：聚簇索引在叶子上**直接拿到全部字段**（索引即数据）；二级索引要**先找主键、再回表**，**多一次回表 → 额外 IO 开销**，性能通常低于聚簇索引 `[源码]`。
   - **更新性能**：聚簇索引按主键组织，为保证**物理顺序与索引顺序一致**，插入时**会对数据页重新排序**——真实物理存储顺序只有一种，插入必然引起主键索引树变化、叶子行数据随之变动，**发生大量数据移动**，**更新效率较慢**；二级索引叶子不存全字段，靠回表取值，**层次多但不造成数据重排** `[源码]`。
3. **联合索引**：同时给 `name`、`age` 建**联合索引**，目录项由 **name + age** 组成，叶子存**主键 + name + age**；页内与页间排序**先按 name、name 相同再按 age** `[源码]`。

## 方案取舍

| 关注点 | 聚簇索引 | 二级索引 | 取舍 |
|---|---|---|---|
| 数量 | 每表仅 1 个 | 每表可多个 | 物理顺序唯一，无法并行多套 |
| 叶子内容 | 完整记录 | 索引列 + 主键 | 用空间换"免回表" |
| 查询路径 | 一次查找拿全字段 | 查两棵树（顺序 IO + 随机 IO） | 二级索引多一次随机 IO |
| 更新代价 | 页重排、大量数据移动 | 不造成数据重排 | 写密集场景二级索引更轻 |
| 物理连续性 | 连续 | 仅逻辑连续 | 范围扫描聚簇更优 |
| 联合索引 | — | 一棵树而非两棵 | 省空间且支持最左前缀 |

取舍要点：**二级索引用"多一次回表"换"省空间 + 低维护成本"**；聚簇索引用"高更新代价"换"主键查询零回表 + 范围扫描顺序 IO"。联合索引相对多个单列索引，**一棵树省一半空间**，且能用**最左前缀**覆盖多种查询，是性价比最高的建索引方式。

## 答题技巧

1. **先讲"为什么"再讲"区别"**：面试官真正想听的是"为什么叶子不存完整记录"（空间 + 回表已够快 + 不是所有查询都回表），三原因说完再列三条区别，逻辑最顺。
2. **把更新性能的因果说完整**：不是"聚簇索引更新慢"一句话，而是**主键顺序 = 物理顺序 → 插入要重排页 → 大量数据移动**。说清因果才到 L4。
3. **IO 性质要报数字级别**：二级索引**一次顺序 IO** + 聚簇索引**一次随机 IO**，共查**两棵 B+树**。
4. **联合索引必带"一棵树 vs 两棵树"**：这是本节能拉开差距的细节——联合索引只生成**一棵** B+树，两个单列索引生成**两棵**。
5. **止步档位**：能讲清三条区别即达 L4；能补上"三原因 + 联合索引单树 + IO 性质"，即达 L5。

## 细节与核心 API

**联合索引只生成一棵 B+树；两个单列索引生成两棵**（省空间且支持最左前缀）：

```sql
CREATE TABLE u (id BIGINT PRIMARY KEY, name VARCHAR(50), age INT,
                KEY idx_name_age (name, age));
-- 页内/页间排序：先按 name，name 相同再按 age；叶子存 (name, age, 主键)

-- 覆盖索引：只取 (name,age) 时无需回表
SELECT name, age FROM u WHERE name='a' AND age>20;   -- 走 idx_name_age，免回表

-- 二级索引叶子存「索引列 + 主键」，回表查聚簇索引拿其余列
SELECT * FROM u WHERE name='a';   -- 先 idx_name_age 拿主键 → 再聚簇索引回表（多一次随机 IO）

-- 单列 vs 联合：(name)/(age) 两棵树；联合 (name,age) 一棵树，省一半空间
```

**聚簇 vs 二级 三区别速记**：聚簇叶子存整行（一表仅一个，主键查询零回表，但插入按主键重排页→大量数据移动）；二级叶子存「主键值」，查两棵树（顺序 IO + 随机 IO），层次多但不造成数据重排，写密集更轻。InnoDB 二级索引叶子存的是**主键值**不是物理指针。

## ⚠️ 原文纠错
1. 事实核校：二级索引叶子不存完整记录的三个原因（磁盘空间、主键回表已高效、并非所有查询都回表）、存储/查询/更新三条区别、联合索引一棵树且排序先 name 后 age——均与 InnoDB 实现一致 `[经验]`。
2. 补充：原文称"非聚簇索引采用了指向表中记录在数据页中的指针的方式"，**InnoDB 二级索引叶子存的是主键值，不是物理指针**；另"聚簇索引记录物理上连续存在"应精确为**页内与页间按主键逻辑有序、并尽量保持物理邻近**，页分裂后仍可能出现物理不连续 `[经验]`。
3. 崩坏词归一：源码将聚簇索引、二级索引、回表、联合索引、B+树、InnoDB 等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
