> 分类：Go/并发 | 难度：L2 | 题型：方案题 | 频率：中 | 关键词：**懒汉式** / **Mutex** / **双重检查锁定** / **数据竞争**
> 原文锚点：第 1~23 段「懒汉式非线程安全(并发多次创建); 加 Mutex 每次锁可行但性能差; 双重检查锁定(无锁先判+加锁再判)避免每次加锁」

## 一句话总述
懒汉式单例在 `if instance == nil` 处并发会多次创建实例（数据竞争）。**加 Mutex** 最直白：进入判断前加锁、创建后解锁——正确但每次访问都加锁，实例已存在时纯属浪费。**双重检查锁定(DCL)** 优化：先无锁判断，为空才加锁并二次判断，避免已初始化后的加锁开销。注意 Go 里外层无锁读若用普通指针/ bool 仍有内存可见性风险，工程首选 `sync.Once`。

## 主问答
**Q：** 懒汉式单例怎么保证线程安全？DCL 又是什么？
**A：**
1. **问题**：懒汉式 `if inst == nil { inst = new(T) }` 在多 goroutine 下，多个 goroutine 同时通过判断，实例被建多次——典型的 check-then-act 竞态。
2. **加锁**：在判断前 `mu.Lock()`、创建后 `mu.Unlock()`，保证同时只有一个 goroutine 进临界区——正确，但**每次** `GetInstance` 都加解锁，实例建好后纯浪费。
3. **DCL**：先无锁判断 `if inst == nil`（多数情况已建好直接返回，不加锁），为空才 `Lock` 并**二次**判断再创建。把加锁范围缩到"确实要创建"时才发生，显著降低开销。

## 关键代码
```go
// 懒汉式 + 双重检查锁定（DCL）：已初始化后不再加锁
var (
    inst *Singleton
    mu   sync.Mutex
)

func GetInstance() *Singleton {
    if inst == nil { // 第一次检查：无锁，已建好直接返回
        mu.Lock()
        defer mu.Unlock()
        if inst == nil { // 第二次检查：持锁，防竞态重复建
            inst = &Singleton{}
        }
    }
    return inst
}
// ⚠️ Go 中裸 DCL 的外层无锁读 inst 与其他 goroutine 持锁写存在数据竞争，
// 工程上更推荐 sync.Once（见 165）
```

## 总结与追问预判
- 加锁保正确但每次锁；DCL 缩锁范围省开销；Go 裸 DCL 有可见性 race，首选 Once。
