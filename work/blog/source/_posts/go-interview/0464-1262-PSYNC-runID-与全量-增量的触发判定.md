> 分类：Redis | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**PSYNC**/**SYNC**/**runID**/**FULLRESYNC**/**CONTINUE**

> 原文锚点：第 18~31 段「PSYNC 命令 / 运行 ID / 三种响应」

## 一句话总述
Redis 2.8 之前只有 `SYNC`（只支持全量）；2.8 起引入 `PSYNC`，同时支持全量与**部分（增量）**同步。从节点发 PSYNC 时带上自己的复制偏移量与主节点 runID，主节点据此回 `+FULLRESYNC`（全量）、`+CONTINUE`（增量）或 `-ERR`（不支持，退回 SYNC 全量）。

## 面试官视角
这题考「你知不知道断连重连为什么有时全量、有时增量」。能把 runID 变化触发全量、offset 落在缓冲区内触发增量讲清楚，并且说出首次连接发的是 `PSYNC ? -1`，就是完整的答案。

## 主问答
**Q（面试官原话）：** 什么时候全量同步，什么时候增量同步？

1. **2.8 是分水岭**：2.8 之前用 SYNC 命令，**只支持全量同步**；2.8 及以后支持 PSYNC，全量与部分同步都支持。
2. **PSYNC 带两个参数**：从节点执行 PSYNC 时带上自己读取的偏移量与主节点 runID；首次连接时偏移量为 -1，正常读取后记录真实偏移量。
3. **runID 标识节点**：每个节点启动时会生成一个 40 位的运行 ID 用于识别节点；若只用 IP 加端口识别，主节点重启后基于偏移量复制并不安全。
4. **重启即全量**：主节点重启后运行 ID 发生变化，从节点据此判定身份不匹配，从而触发**全量复制**。
5. **三种响应**：回 FULLRESYNC 触发全量；回 CONTINUE 触发部分（增量）复制，多发生在断线重连之后；回 ERR 说明不支持 PSYNC，退回用 SYNC 做全量。

## 版本与兼容性
| 响应 | 含义 | 结果 |
|------|------|------|
| +FULLRESYNC | 主库要求全量 | 全量复制 |
| +CONTINUE | 可续传 | 增量同步 |
| -ERR | 不支持 PSYNC | 退回全量 |

## 关键代码
```go
// Go 侧视角：对比本地记录与当前 runID，提前预判是否会被强制全量
package main

import (
	"fmt"
	"os/exec"
	"strings"
)

func main() {
	out, _ := exec.Command("redis-cli", "INFO", "server").Output()
	for _, l := range strings.Split(string(out), "\n") {
		if strings.HasPrefix(l, "run_id:") {
			fmt.Println("当前 runID:", strings.TrimSpace(strings.TrimPrefix(l, "run_id:")))
			// 与上次记录不同 => 重连必触发全量，应避开业务高峰
		}
	}
}
```

## 总结与追问预判
核心：**runID 变则全量，offset 可续则增量**。追问常拐向「主库重启为什么慢」「怎么减少全量」，备好「runID 变化」与「调大复制积压缓冲区」两句。
