> 原文锚点：第 1~15 段「幂等性数学定义；消息幂等防止网络故障重发；Kafka 0.11 引入幂等生产者，设 enable.idempotence=true(SDK>=1.2.0)，broker 空间换时间去重」

## 一句话总述
**幂等生产者**（Kafka 0.11 引入）开启 `enable.idempotence=true` 后，每条消息带 PID+序列号，broker 端按序列号对**单分区内**重复消息去重——本质是"空间换时间"，由 broker 多存字段识别重复。它只解决 producer 重试导致的重发，不影响 consumer。

## 面试官视角
- 意图：是否懂"幂等生产者解决什么问题、怎么实现、边界在哪"。
- P5 知开启幂等可去重；P6 知 0.11 引入、enable.idempotence + SDK>=1.2.0；P7 知"单分区单会话去重、broker 空间换时间、consumer 无感" `[边界]` 见 1418（机制概述）。
- 红旗：以为幂等=端到端精确一次；以为跨分区也去重。
- 惊艳点：点出"broker 多存字段做去重"是经典空间换时间，且 consumer 代码完全不用改 `[经验]`。

## 主问答
**Q（面试官原话）：** 幂等生产者怎么用，底层怎么去重？
**A：**
1. **解决的问题**：producer 未收到 broker ack（网络故障）会误以为未持久化而重发，导致消息重复；幂等性让"多次发送同一消息"对下游等价于一次。
2. **开启方式**：SDK 配置 `enable.idempotence=true`（要求客户端库版本 `>=1.2.0`）；开启后 producer 被分配 PID，每条消息带单调递增序列号。
3. **broker 去重**：broker 缓存每个 PID 的序列号，收到相同字段（同 PID+同序列号）的消息直接忽略——用额外存储换去重逻辑，consumer 端无感知、无需改动。

## 关键代码
```go
// 示意：sarama 开启幂等生产者（0.11+ PID+序列号单分区去重），未做端到端验证
cfg := sarama.NewConfig()
cfg.Producer.Idempotent = true                 // enable.idempotence=true
cfg.Producer.RequiredAcks = sarama.WaitForAll   // 幂等要求 acks=all
cfg.Net.MaxOpenRequests = 1                     // 幂等要求单 inflight
producer, err := sarama.NewSyncProducer(brokers, cfg)
// 之后 SendMessage 重试也不会在单分区内产生重复
```

## 总结与追问预判
- 幂等生产者 = 单分区内 broker 去重，consumer 无感；只去重 producer 端。
