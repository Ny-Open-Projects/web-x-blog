> 分类：SQL 技巧 | 难度：L2 | 题型：实操题 | 频率：中 | 关键词：**COUNT(DISTINCT)**/**客单价**/**客单件**/**平均购买频次**
> 原文锚点：第 20~43 段「去重统计用户数 + 订单表客单价/客单件/频次」

## 一句话总述
「用户数」要用 `COUNT(DISTINCT user_id)` 去重；客单价、客单件、平均购买频次都是「总量 ÷ 去重用户数」的变体，核心是**先去重再相除**避免同一用户多行被重复计入。

## 面试官视角
- 考察意图：是否理解「计数 vs 去重计数」的差异，能否从订单/登录明细表算出业务指标。
- 分档：P5 用户数用 COUNT(DISTINCT user_id)；P6 能写出客单价/客单件/频次的完整表达式；P7 知一条 SQL 用聚合一次算出多项指标，避免多次扫表。
- 红旗答案：用户总数用 COUNT(*)（同一用户多行被算重）；客单价分子分母口径不一致。
- 惊艳点：用一条带派生聚合的 SQL 一次性算出用户数/销售额/客单价/客单件/频次，少扫表、语义清晰 [经验]。

## 主问答
**Q（面试官原话）：** 怎么统计用户总数和客单价、客单件、平均购买频次？
**A：**
1. **用户总数必须去重**：登录记录表只有 `login_time` 和 `user_id`，一个用户多次登录有多行，统计总用户数要用 **`COUNT(DISTINCT user_id)`**，平均登录次数 = `COUNT(*) / COUNT(DISTINCT user_id)` [经验]。
2. **客单价 / 客单件 / 频次**：订单表含 `user_id, qty, price`。**销售额** = `SUM(qty*price)`；**客单价**（人均金额）= `SUM(qty*price) / COUNT(DISTINCT user_id)`；**客单件**（人均件数）= `SUM(qty) / COUNT(DISTINCT user_id)`；**平均购买频次**（人均下单次数）= `COUNT(*) / COUNT(DISTINCT user_id)` [经验]。
3. **一条 SQL 算全**：上述指标可放在一条语句里用聚合一次算出，避免多次查询、口径也更一致 [经验]。

## 版本与兼容性
- `COUNT(DISTINCT)` 各关系库通用；超大数据集下 DISTINCT 内存开销大，可用近似 `APPROX_COUNT_DISTINCT`（MySQL 8.0/BigQuery）替代。

## 关键代码

```sql
-- 登录表：用户总数 + 平均登录次数（同用户多行需去重）
SELECT
  COUNT(DISTINCT user_id)            AS user_cnt,
  COUNT(*) / COUNT(DISTINCT user_id) AS avg_logins
FROM user_login;

-- 订单表：销售额 / 客单价 / 客单件 / 平均购买频次 一次算清
SELECT
  COUNT(DISTINCT user_id)                    AS buyer_cnt,
  SUM(qty * price)                           AS sales,
  SUM(qty * price) / COUNT(DISTINCT user_id) AS avg_order_value,  -- 客单价
  SUM(qty)         / COUNT(DISTINCT user_id) AS avg_items,        -- 客单件
  COUNT(*)         / COUNT(DISTINCT user_id) AS avg_freq          -- 平均购买频次
FROM orders;
```

## 总结与追问预判
去重聚合是业务统计底层能力。更复杂的「每商品销售额 + 总计」与「分级打标」见同波 GROUP BY + ROLLUP / CASE WHEN 两张卡。
