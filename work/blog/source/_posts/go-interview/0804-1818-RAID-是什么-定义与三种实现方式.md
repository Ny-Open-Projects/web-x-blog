## 一句话总述
RAID（独立磁盘冗余阵列）是一种**存储虚拟化技术**：把多块物理磁盘组合成一个或多个逻辑单元，用来换冗余或换性能；实现上分硬件 RAID（专用控制器）、软件 RAID（操作系统实现，如 mdadm）与混合 RAID 三类。

## 面试官视角
这题是 RAID 系列的开场。考官要确认你知道「RAID 不是备份」以及「实现方式决定了故障后怎么恢复」。答出软硬 RAID 的取舍（性能/成本/可移植性）就算合格，能提到阵列元数据写在盘上是加分项。

## 主问答
**Q（面试官原话）：** 什么是 RAID？硬件 RAID 和软件 RAID 有什么区别？

1. **定义**：多块物理磁盘合成一个或多个逻辑单元，为的是冗余、性能改进，或两者兼有——不同级别侧重不同。
2. **硬件 RAID**：通过专用 RAID 控制器管理磁盘，性能好、对操作系统呈现为一块盘，但成本高、换卡要看元数据兼容。
3. **软件 RAID**：由操作系统实现，无需专用硬件，直接用系统命令即可组建；成本低，性能受 CPU 与内存影响。
4. **混合 RAID**：结合两者，用简单硬件辅助软件完成阵列管理，是成本与性能的折中。
5. **选型三要素**：数据重要性（要几级冗余）、性能需求（读密集还是写密集）、成本（硬件卡与磁盘利用率）。

## 版本与兼容性
| 实现方式 | 成本 | 性能 | 依赖 |
|----------|------|------|------|
| 硬件 RAID | 高 | 好 | 专用控制器 |
| 软件 RAID | 低 | 受 CPU 影响 | 操作系统 |
| 混合 RAID | 中 | 折中 | 简易硬件 |

## 关键代码
```go
// Go 侧视角：巡检时读 /proc/mdstat 判断软 RAID 是否降级
package main

import (
	"fmt"
	"os"
	"strings"
)

func main() {
	b, _ := os.ReadFile("/proc/mdstat")
	for _, line := range strings.Split(string(b), "\n") {
		if strings.Contains(line, "md") {
			fmt.Println(line) // 出现 [U_] 之类的降级标记即说明有盘掉线
		}
	}
}
```

## 总结与追问预判
核心：**RAID 是多盘虚拟化，实现方式决定性能与可移植性**。追问常拐向「卡坏了数据还能读吗」「RAID 能当备份吗」，备好「元数据在盘上、同系卡可接管」与「只防单盘故障，不防误删与勒索」两句话。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文只给出 Independent Disks 一种全称——早期 I 指 Inexpensive（廉价磁盘冗余阵列），现通用 Independent Disks，知道这一演变是加分项。
2. 事实核校： [经验] 原文称硬件 RAID「独立于操作系统」——严格说它独立于 OS 的磁盘驱动栈，但仍需 OS 侧驱动与管理工具，阵列元数据通常写在盘上，换卡要评估兼容。
3. 崩坏词归一：源码将 RAID / Linux 等音译为多组崩坏词，本卡统一为规范术语。
