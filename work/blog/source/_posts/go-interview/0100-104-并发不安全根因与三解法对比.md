> 分类：Go 并发 | 难度：中 | 题型：案例题 | 频率：高 | 关键词：**CNT++ 三指令竞争、锁、通道、原子操作**

> 原文锚点：第 4~56 段「并发不安全=CNT++ 拆 load/add/store 三指令多核竞争得 987≠1000、单核不出现；三解法(锁/通道缓冲1/原子 AddInt64)对比，原子最简洁高效」

## 一句话总述
`count++` 在机器层被拆成 **load（读内存到寄存器）→ add（加一）→ store（写回内存）** 三条指令；多核下多个 goroutine 同时 load 到相同旧值，各自加一写回，结果相互覆盖，最终 ≠ 期望（demo 得 987 而非 1000）。三种修法：① `sync.Mutex` 加锁；② 缓冲为 1 的 channel（写入即占坑、等效锁）；③ `atomic.AddInt64`（CPU 原子指令，最简洁高效）。单核（GOMAXPROCS=1）串行调度下不出现——但生产永远多核，必须保护。一句话背法：**「count++ 拆三指令多核竞争相互覆盖；三解法锁/通道/原子，原子最轻」**。

## 主问答
**Q（面试官原话）：** 为什么 `count++` 并发会出错？怎么修？

**先铺垫（由浅入深第 1 层）**：面试最爱拿 `count++` 当引子，因为它看着像一行、实则不是原子。它背后是三条 CPU 指令，多条 goroutine 一交叉，就出现"读到的旧值一样、写回的也一样"，凭空少加。讲清这个，再给解法光谱，故事就完整了。

1. **根因（第 2 层）**：`count++` 不是单指令，而是 load→add→store 三步。多核下 goroutine A、B 同时 load 到相同旧值 v，各加一得 v+1，先后 store 回——本应 +2 却只 +1，多次叠加后离 1000 差一截（demo 987）。
2. **解法一 锁（第 3 层）**：`mu.Lock()` 包住 `count++`，保证同时只有一个 goroutine 进临界区——正确，但每次都加锁。
3. **解法二 通道（第 4 层）**：用缓冲 1 的 channel，写前 `<-ch` 占坑、写完 `ch <- struct{}{}` 释放，等价于一把锁保护该行（写入即占坑）。
4. **解法三 原子（第 5 层）**：`atomic.AddInt64(&count, 1)`，底层 CPU 原子指令，同刻只允许一个 goroutine 对该地址加一——最简洁、最高效，是计数器首选。
5. **边界（第 6 层）**：单核 GOMAXPROCS=1 调度串行不交错，但生产永远多核，绝不能靠单核偷懒；且 Go 1.19+ 推荐 `atomic.Int64` 类型化原子免手写指针。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	const n = 1000

	// 解法三（推荐）：原子操作，终值稳定 1000
	var c atomic.Int64
	var wg sync.WaitGroup
	for i := 0; i < n; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			c.Add(1) // 底层 CPU 原子指令，变量级互斥
		}()
	}
	wg.Wait()
	fmt.Println("atomic 终值:", c.Load()) // 1000

	// 解法一：Mutex，同样正确（每次加锁）
	var mu sync.Mutex
	var count int64
	for i := 0; i < n; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			mu.Lock()
			count++
			mu.Unlock()
		}()
	}
	wg.Wait()
	fmt.Println("mutex 终值:", count) // 1000
	// ❌ 无保护 count++ 在多核下会得 987 等非 1000（非确定性，故不跑）
}
```

## 总结与追问预判
**背这三句就够**：① **count++ 拆 load/add/store 三步，多核同时 load 旧值导致相互覆盖**；② **三解法：Mutex / 缓冲1 channel（等价锁）/ atomic.AddInt64（最轻）**；③ **单核不出现但生产多核必须保护，计数器首选原子**。
**预判追问**：
- 「原子为什么最轻？」→ 靠 CPU LOCK 指令锁 cache line，无调度阻塞（见 104 原子本质 / 105 无锁原理）。
- 「多变量一致性怎么办？」→ 原子只保单变量，复合逻辑上 Mutex（见 105 何时用原子 / 104 原子陷阱）。
- 「高竞争下原子还快吗？」→ CAS 自旋可能不如锁，实测为准（见 104 原子陷阱）。
