> 分类：计算机网络 / TCP | 难度：L4 | 题型：记忆题 | 频率：高 | 关键词：**报文头、源端口、序列号、确认号、数据偏移、窗口、校验和、选项**

> 原文锚点：第 34~48、73~82 段「TCP 报文头通常为二十字节，这个二十字节是它的最小长度，我们可以通过添加选项字段将它扩展到最大六十个字节…序列号占三十二位，是在建立连接的时候由计算机生成的随机数作为初始值的…确认应答号是指下一次期望收到的数据的序列号…首部占了四比特，最小值是五，最大值是十五，以四字节为一个单位」

## 一句话总述
TCP 报文头**最小 20 字节、最大 60 字节**（靠选项字段扩展）；核心字段包括**源/目标端口、序列号、确认应答号、数据偏移、窗口大小、校验和、紧急指针与选项**，分别支撑复用、乱序重组、丢包重传、首部定位、流量控制与差错检测。

## 面试官视角
P6 知道端口与序号；P7 要能**逐字段说出位数与作用**，尤其要答出**「数据偏移单位是 4 字节、取值 5~15」**这个换算细节，以及**序列号解决乱序、确认号解决丢包**的分工。

## 主问答
**Q（面试官原话）：** TCP 报文头有哪些字段？各占多少位？

1. **长度范围**：**通常为 20 字节**（最小长度），加上选项字段可**扩展到最大 60 字节** `[源码]`。
2. **源端口号**：**16 位（2 字节）**，标识**发送方（客户端）的应用程序** `[源码]`。
3. **目标端口号**：**16 位（2 字节）**，标识**接收方（服务器端）的应用程序** `[源码]`。
4. **序列号**：**32 位（4 字节）**；建立连接时由**计算机生成的随机数作为初始值**，通过 SYN 包传给对端；**每发送一次数据累加一次数据字节数**；用于**解决网络包乱序问题** `[源码]`。
5. **确认应答号**：**32 位**，表示**下一次期望收到的数据的序列号**；发送端据此认为该序号**以前的数据都已被正常接收**；用于**解决丢包问题** `[源码]`。
6. **数据偏移（首部长度）**：**4 比特**；**最小值 5、最大值 15**，**以 4 字节为单位**——5×4=20 字节（不含选项），15×4=60 字节（含选项，已达最大） `[源码]`。
7. **保留字段**：**6 位**，保留未来使用，**默认为 0** `[源码]`。
8. **窗口大小**：**16 位（2 字节）**，表示**接收方缓冲区可接收的数据量**，是流量控制的依据 `[源码]`。
9. **校验和**：**16 位（2 字节）**，通过**计算报文头与数据部分的和**得到，用于检测传输错误 `[源码]`。
10. **紧急指针**：URG 标志位为 1 时，**指示紧急数据在数据流中的位置** `[源码]`。
11. **选项字段**：**可选且长度可变**，用于扩展功能，例如**最大报文段长度（MSS）、窗口扩大因子、时间戳**；**长度必须是 4 字节的整数倍**，不足则**补零** `[源码]`。

## 关键代码
```go
package main

import (
	"encoding/binary"
	"fmt"
)

// 解析 TCP 首部的关键字段（简化示例，仅演示字段布局）
func parseTCPHeader(b []byte) {
	srcPort := binary.BigEndian.Uint16(b[0:2])  // 源端口 16 位
	dstPort := binary.BigEndian.Uint16(b[2:4])  // 目标端口 16 位
	seq := binary.BigEndian.Uint32(b[4:8])      // 序列号 32 位
	ack := binary.BigEndian.Uint32(b[8:12])     // 确认号 32 位
	dataOffset := (b[12] >> 4) & 0x0F           // 数据偏移 4 比特，单位 4 字节
	headerLen := int(dataOffset) * 4            // 5 -> 20 字节；15 -> 60 字节
	flags := b[13]                              // 控制标志位 8 比特（含 6 个常用标志）
	window := binary.BigEndian.Uint16(b[14:16]) // 窗口大小 16 位
	checksum := binary.BigEndian.Uint16(b[16:18])
	urgentPtr := binary.BigEndian.Uint16(b[18:20])

	fmt.Printf("src=%d dst=%d seq=%d ack=%d hdrLen=%d flags=%02x win=%d chk=%#x urg=%d\n",
		srcPort, dstPort, seq, ack, headerLen, flags, window, checksum, urgentPtr)
}
```

## 总结与追问预判
**「数据偏移 × 4 = 首部字节数」是必考换算**。面试官常追问「为什么选项必须 4 字节对齐」——因为数据偏移字段以 4 字节为单位计数，不对齐就无法精确表达首部长度。六个标志位见同批 1840-tcp-flags。

## ⚠️ 原文纠错
1. 事实核校：20~60 字节长度、端口各 16 位、序列号 32 位解决乱序、确认号 32 位解决丢包、数据偏移 4 比特取值 5~15 且单位 4 字节、保留 6 位、窗口与校验和 16 位、选项需 4 字节对齐——均与 RFC 793 一致 `[经验]`。
2. 补充：原文称「首部通常为二十字节」准确；但在现代 Linux 上由于默认启用**时间戳等选项**，抓包常见实际首部为 **32 字节**，答题时可补充这一实测观察 `[经验]`。
3. 崩坏词归一：源码将端口号、序列号、确认号、数据偏移、校验和、选项等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
