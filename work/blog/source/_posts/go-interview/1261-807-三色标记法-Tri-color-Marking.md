> 分类：Go/运行时 | 难度：L3 | 题型：算法题 | 频率：高 | 关键词：**三色标记** / **白灰黑** / **并发标记** / **写屏障**
> 原文锚点：第 57~78 段「三色含义；新对象默认白；根入灰；遍历灰把可达入灰、原灰转黑；灰空为止白即垃圾；黑=存活白=不可达」

## 一句话总述
三色标记法用**白/灰/黑**三色描述对象被扫描的状态，从根集合出发把对象逐步"漂白→灰→黑"，直到灰色集合清空，剩余白色即不可达垃圾。它让 GC 能**渐进、并发**执行（不必每次扫整堆），是 Go 1.5 起并发 GC 的算法基础。

## 面试官视角
- 意图：考察对并发 GC 核心算法的理解，是"Go GC 怎么做到低 STW"的关键。
- P5 能说清三色含义；P6 能描述推进过程（根入灰→遍历灰转黑）；P7 能讲清"为何并发标记需要写屏障保护"（防止黑引用白被误回收）。
- 红旗：以为三色标记完全无 STW（仍需短暂 STW 启动/终止标记）；把白色说成"存活"。
- 惊艳点：点出三色标记只是"标记阶段可并发"，配合写屏障才保证并发正确性，自然引出 1.8 混合写屏障。

## 主问答
**Q（面试官原话）：** 三色标记法是怎么回事？为什么 GC 能并发？
**A：**
1. **结论**：三色含义——**白**：未被 GC 访问过（可能是垃圾，回收开始时所有对象皆白，结束时白即不可达）；**灰**：已访问但子对象未访问，需继续扫描；**黑**：已访问且子对象都已访问，确定存活。
2. **机制（推进）**：新对象默认白 → 从根对象出发将其入**灰色**集合 → 遍历灰色对象，把其可达子对象也入灰、原灰对象转**黑** → 重复直到灰色集合清空；此时只剩黑白，白色即不可达垃圾（如图中对象 4、5）。
3. **边界（并发正确性）**：三色标记使标记可**渐进并发**执行（不必扫整堆），但并发期间用户代码会改引用，若黑色对象新引用白色对象、白色又被回收就会漏标——因此并发标记须配**写屏障**保护（Go 1.8 引入混合写屏障）；标记启动/终止仍需短暂 STW `[经验]`。

## 关键代码
```go
// 三色标记推进（并发标记的基础版本，仍需短暂 STW 启动/终止）
// 白：未访问（可能是垃圾）  灰：已访问但子未访问  黑：已访问且子已访问
var (
    white = map[*obj]bool{} // 待回收候选
    grey  = map[*obj]bool{} // 待处理
    black = map[*obj]bool{} // 存活
)
func mark() {
    for _, r := range roots { // 根对象入灰
        grey[r] = true
    }
    for len(grey) > 0 {
        for o := range grey { // 取一个灰对象
            delete(grey, o)
            for _, c := range o.refs { // 子对象入灰
                if !black[c] {
                    grey[c] = true
                }
            }
            black[o] = true // 自身及子都已访问 → 转黑
        }
    }
    // 灰空后：white 集合即不可达垃圾
}
```

## 总结与追问预判
- 三色=白未访/灰待扫/黑存活；根入灰→遍历转黑→白即垃圾；并发需写屏障。
