> 分类：MySQL / InnoDB | 难度：L3 | 题型：场景题 | 频率：高 | 关键词：**innodb_flush_log_at_trx_commit、fsync、OS 缓冲、丢数据边界**

> 原文锚点：第 30~43 段「设置为零大约每秒刷入一次…设置成一不会丢失任何数据…设置成二」

## 一句话总述
该参数决定**每次提交时重做日志写到哪一层**：0 与 2 都是每秒落盘（丢数据窗口约 1 秒），1 是每次提交都立即同步到磁盘（不丢但 IO 代价高）。

## 面试官视角
P6 只会背"设成 1 最安全"；P7 要给出**丢数据的精确边界**：设 0 时服务崩溃丢约 1 秒；设 2 时日志已进操作系统缓冲，**服务崩溃不丢、只有操作系统崩溃才丢约 1 秒** `[经验]`。加分点：生产常见"双一"配置——该参数为 1、同时把二进制日志同步也设为 1 `[源码]`。

## 主问答
**Q（面试官原话）：** 这个刷盘参数三档怎么选？

1. **设 0：每秒一次**：提交时不主动写操作系统缓冲，由后台每秒同步再落盘；服务崩溃会丢约 1 秒数据 `[经验]`。
2. **设 1：每次提交都落盘**：提交即写入操作系统缓冲并立刻同步到日志文件，即使系统崩溃也不丢数据，但每次提交都有磁盘 IO `[实测]`。
3. **设 2：只写操作系统缓冲**：提交时写进系统缓冲，每秒再同步落盘；服务崩溃不丢，**操作系统崩溃丢约 1 秒** `[源码]`。
4. **推荐值**：追求异常重启不丢数据就设 1，原文同样建议设 1；代价是 IO 性能较差，高并发写入场景需评估 `[经验]`。

## 关键代码
```sql
SET GLOBAL innodb_flush_log_at_trx_commit = 1;  -- 每次提交立即落盘
SET GLOBAL sync_binlog = 1;                     -- 双一配置
SHOW VARIABLES LIKE 'innodb_flush_log_at_trx_commit';
```
> 验证：设 1 后高并发写入的每秒事务数明显低于设 2，但异常断电不丢已提交事务 `[实测]`。

## 总结与追问预判
**安全与吞吐在此二选一，边界要能说清到"服务崩溃"还是"系统崩溃"**。这是最能体现细节掌握度的一问。
