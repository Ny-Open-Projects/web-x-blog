> 分类：数据库 / MySQL 索引 | 难度：L3 | 题型：对比题 | 频率：中 | 关键词：**MyISAM、.MYD、.MYI、行号、索引与数据分离、二级索引**

> 原文锚点：第 58~72 段「mysam的索引方案呢，虽然也使用树形结构，但是它确实是将索引和数据分开存储的…将数据单独存储在一个文件中，这个文件我们称之为数据文件，也就是点MYD格式的文件…它获取数据呢是通过行号来获取数据的…把表的索引信息另外存储到一个称为索引文件的另一个文件中，也就是点MYI格式的文件…在叶子节点中存储的不是完整的用户记录，而是主键值和行号的组合…这就意味着mysam中建立的索引呢相当于全部都是二级索引」

## 一句话总述
MyISAM 把**索引和数据分开存**：数据按**插入顺序**塞进 `.MYD` 数据文件（不分页、不支持二分），索引单独放 `.MYI` 文件，叶子节点存的是"**列值 + 行号**"——**先查索引拿到行号，再用行号回数据文件取记录**，所以 **MyISAM 的所有索引（含主键索引）在性质上都相当于二级索引**。

## 面试官视角
- 考察意图：能否把 MyISAM 与 InnoDB 的索引实现**对照着讲**，而不是把两者混为一谈。
- 分档：P5 知道 MyISAM 不支持事务；P6 能说出 `.MYD`/`.MYI` 两个文件；P7 能讲清**行号定位 vs 主键定位**的差异，并推出"MyISAM 主键索引也要回表"。
- 红旗答案：把 `.MYD`/`.MYI` 说成 InnoDB 的文件（这两个后缀**只属于 MyISAM**）；以为 MyISAM 主键索引也是聚簇索引。
- 惊艳点：**MyISAM 的数据文件不划分数据页、按插入顺序堆记录**，所以其上的数据**不能用二分查找**——这一点决定了它必须靠索引 + 行号兜底 `[源码]`。

## 主问答
**Q（面试官原话）：** MyISAM 的索引和 InnoDB 有什么不一样？

1. **结论**：InnoDB 是**索引即数据**（聚簇索引叶子已含完整记录），MyISAM 是**索引与数据分离**——数据在数据文件、索引在索引文件，两者靠**行号**关联 `[源码]`。
2. **数据文件 `.MYD`**：表中的记录按**记录插入的顺序**单独存在数据文件里；这个文件**不划分为若干数据页**，有多少条记录就往里塞多少条；数据行靠**记录头信息**保存原信息 `[源码]`。
3. **不能二分**：由于插入时**没有刻意按主键大小顺序**插入，无法在这些数据上用**二分法**查找，只能靠索引 `[源码]`。
4. **索引文件 `.MYI`**：表的索引信息单独存在索引文件中；MyISAM **也会为主键单独建索引**，但叶子节点存的是**主键值和行号的组合**，不是完整用户记录——**先通过索引找到行号，再通过行号找记录** `[源码]`。
5. **关键差异**：InnoDB 根据主键对聚簇索引**查一次**就能拿到所有字段；MyISAM **必须回表一次**，所以 **MyISAM 中建立的索引相当于全部都是二级索引** `[源码]`。
6. **其他列索引**：对其他列建单列索引或联合索引，原理与非主键索引相近，**叶子存的是"对应列 + 行号"**；这些索引同样**全部是二级索引** `[源码]`。

**加分层：** MyISAM 用**行号**定位，行号在数据文件里是稳定的偏移量，所以**行被更新变长时可能触发行迁移**；而 InnoDB 用**主键值**定位，代价是多一次聚簇查找，收益是行移动时二级索引无需改动。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| MySQL 5.5 之前 | MyISAM 是默认引擎 | 需知当时默认无事务、表级锁 |
| 5.5 起 | 默认改为 InnoDB | 新表默认聚簇索引 |
| 8.0 起 | 系统表也转 InnoDB | MyISAM 仅历史存量 |
| 全版本 | 文件后缀按引擎分 | `.MYD`/`.MYI` 属 MyISAM，`.ibd` 属 InnoDB |

## 关键代码
```sql
-- 1) 建一张 MyISAM 表，观察磁盘上的三个文件
CREATE TABLE t_myisam (
  id   INT PRIMARY KEY,
  name VARCHAR(20),
  age  INT,
  KEY idx_name (name)
) ENGINE=MyISAM;
-- 数据目录下会出现：t_myisam.MYD（数据）、t_myisam.MYI（索引）

-- 2) 主键查询在 MyISAM 中同样要"索引 -> 行号 -> 数据文件"
EXPLAIN SELECT * FROM t_myisam WHERE id = 10;

-- 3) 对照 InnoDB：只有 .ibd（8.0 起），主键查询不回表
CREATE TABLE t_innodb (id INT PRIMARY KEY, name VARCHAR(20)) ENGINE=InnoDB;

-- 4) 看表用的是什么引擎
SELECT table_name, engine FROM information_schema.tables
WHERE table_schema = DATABASE();
```

## 总结与追问预判
**最爱考的是"文件后缀归属"**：`.MYD`/`.MYI` 只属于 **MyISAM**，`.ibd` 属于 **InnoDB**（独立表空间），不要把两者混用（这一条在 `1210-file-layer` 那张卡里也强调过）。追问常接"现在还该不该用 MyISAM"——**不该**：无事务、崩溃恢复差、表级锁；它唯一的旧优势是 `COUNT(*)` 可直接取行数，而这点在 InnoDB + 计数表/缓存方案面前已不成立。
