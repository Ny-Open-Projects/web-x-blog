> 原文锚点：第 18~33 段「不可重复读与幻读的定义及区别」

## 一句话总述
**不可重复读**是同一条记录被别的事务**修改**，导致本事务内两次读到不同的值；**幻读**是相同查询条件下**结果集条数**发生变化（别的事务新增或删除了行）。前者重点在 **UPDATE**，后者重点在 **INSERT / DELETE**。

## 面试官视角
这题几乎人人都背过定义，但一半人答不出区别。判据很简单：**看变的是「值」还是「行数」**。能给出「修改属不可重复读、增删属幻读」这条线，并补一句「修改若使记录进出查询范围则兼具两者」，就是高分。

## 主问答
**Q（面试官原话）：** 不可重复读和幻读有什么区别？

1. **不可重复读看值**：在一个事务内多次读取**同一个数据**，若前后两次读到的值不一样，就发生了不可重复读。
2. **幻读看行数**：在一个事务内多次按**相同条件查询**，若结果集的**记录条数**前后不一样，就发生了幻读。
3. **成因不同**：不可重复读由别的事务**修改**记录引起；幻读由别的事务**新增或删除**记录引起。
4. **类比记忆**：幻读就像发生了幻觉——同样的条件，第二次却多出（或少掉）了几行。
5. **边界情形**：若别的事务的修改使某条记录进入或退出本事务的查询条件范围，则既影响值也影响集合，需按具体表现归类。

## 关键代码
```sql
-- 不可重复读：同一行前后两次读到的值不同
SELECT a FROM t WHERE id = 1;  -- 第一次：17
-- 另一事务 UPDATE 并提交
SELECT a FROM t WHERE id = 1;  -- 第二次：18

-- 幻读：同一条件两次查询的行数不同
SELECT COUNT(*) FROM t WHERE a > 16; -- 第一次：N 行
-- 另一事务 INSERT 一条 a=20 并提交
SELECT COUNT(*) FROM t WHERE a > 16; -- 第二次：N+1 行
```

## 总结与追问预判
核心：**不可重复读变的是值，幻读变的是行数**。追问常拐向「RR 下幻读怎么解决」，备好「快照读靠 MVCC、当前读靠间隙锁」这条（详见 MVCC 与锁专题卡）。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称幻读「通常是由于另一个事务新增、修改或删除了数据」——把「修改」笼统列为幻读成因不够严谨：单条记录被**修改**导致值变化属**不可重复读**；只有影响结果集条数的增删才构成幻读。
2. 事实核校： [经验] 原文对两类现象的定义与举例准确，但缺少边界说明：当修改使记录进入或退出查询条件范围时，会同时呈现两种特征，本卡补入该情形。
