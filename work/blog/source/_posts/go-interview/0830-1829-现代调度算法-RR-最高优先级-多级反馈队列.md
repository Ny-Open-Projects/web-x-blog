## 一句话总述
现代分时三算法：**RR（时间片轮转）**最古老公平、时间片 20~50ms（太短切换多、太长响应差）；**最高优先级**按优先级选（静态/动态、抢占/非抢占，低优先级可能饿死）；**多级反馈队列**结合 RR+优先级，多队列优先级递减、时间片递减，新进程入首级、未完成降级，兼顾长短作业。

## 面试官视角
- 考察意图：是否掌握 RR 时间片取舍、最高优先级的静态/动态之分，以及多级反馈队列如何兼得公平与长短作业。
- 分档：P5 知 RR 轮转；P6 知时间片 20~50ms、最高优先级有饥饿；P7 知多级反馈队列的降级机制与长短作业兼顾。
- 红旗答案：以为 RR 给不同进程不同时间；或说不清多级反馈队列为何不饿死长作业。
- 惊艳点：点出「多级反馈队列里长作业虽等待久，但整体运行时间更短、响应更短」。

## 主问答
**Q（面试官原话）：** 时间片轮转、最高优先级、多级反馈队列分别怎么工作？
**A：**
1. **RR（时间片轮转）**：每进程分时间片，用完释放 CPU 给下一进程；提前结束/阻塞立即切换。时间片过短→上下文切换过多降效；过长→短作业响应差；典型 20~50ms。
2. **最高优先级**：从就绪队列选优先级最高者；优先级分静态（创建时定、全程不变）与动态（随运行增而降、随等待增而升）；分非抢占（跑完当前再切高优）与抢占（高优一到即挂起当前）。缺点：低优先级可能永不运行（饥饿）。
3. **多级反馈队列**：多个队列、优先级从高到低、时间片从高到低；新进程进第一级队尾按 FCFS 等；时间片内没完成就降级到下一队列队尾，直到完成；仅高优队列空才调度低优；高优新进程到来则暂停当前、移其回原队列尾、先跑高优。
4. **兼顾机理**：结合 RR 与最高优先级，短作业在前几级快速处理，长作业虽等待增但整体运行时间更短，故整体响应较短。

## 关键代码
```go
// 多级反馈队列（简化）：未完成则降级，高优空才调度低优
func mlfqDemo(queues [][]string) {
	for lvl := 0; lvl < len(queues); lvl++ {
		if len(queues[lvl]) == 0 {
			continue // 高优空才看低优
		}
		for _, p := range queues[lvl] {
			if !runWithQuantum(p) { // 本队列时间片内没完成
				queues[lvl+1] = append(queues[lvl+1], p) // 降级到下一队列
			}
		}
	}
}
```

## 总结与追问预判
六类算法（FCFS/SJF/HRRN/RR/最高优先级/多级反馈队列）构成 OS 进程调度全景。Go runtime 的用户态调度（GMP）是另一层——深卡划边界。
