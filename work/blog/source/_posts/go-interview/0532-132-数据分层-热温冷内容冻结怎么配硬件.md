> 分类：Elasticsearch | 难度：L3 | 题型：架构题 | 频率：中高 | 关键词：**data_hot、data_warm、data_cold、data_frozen、data_content、存储成本**

> 原文锚点：第 22~43 段「从 ES 七开始支持冷热温分层…按访问频率分布到不同角色」

## 一句话总述
数据访问有**时效性**——越新的数据越热；把数据节点再切成热、温、冷、冻结、内容五档，按访问频率配不同硬件，是降存储成本的核心手段。

## 面试官视角
P6 只知道冷热分离；P7 要报全五档并给出**硬件配比**：热层用高速固态与大内存，冷层用低速磁盘小 CPU，冻结层几乎不访问、可放归档或网络存储、查询需先解压加载 `[经验]`。加分点：内容层承载全文检索类业务数据，需要高 IO 与 CPU `[源码]`。

## 主问答
**Q（面试官原话）：** 日志类数据越老越没人查，集群怎么省钱？

1. **时效性是前提**：日志等数据近期访问频繁、远期几乎不查，用同一套硬件纯属浪费 `[经验]`。
2. **五档划分**：热（最近写入、访问最高）、温（较高但次之）、冷（很少访问或已过期）、冻结（几乎不访问、需解压）、内容（全文检索业务数据）`[源码]`。
3. **硬件随档递减**：热层高速固态盘 + 大内存 CPU，冷层低速磁盘 + 少量资源，冻结层可放归档与网络存储 `[经验]`。
4. **迁移靠生命周期管理**：按访问频率把数据分布到不同层，冷数据下沉即释放高成本资源 `[实测]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ES 7.10+ | 热温冷内容分层引入 | 用 node.roles 指定分层角色 |
| ES 7.17 / 8.x | 冻结层可用 | 冻结查询需先加载，延迟高 |
| ES 8.x | 生命周期策略默认 | 新集群按分层规划 |

## 关键代码
```yaml
# 热节点
node.roles: [ data_hot, data_content ]
# 冷节点：低速磁盘、较少 CPU 与内存
node.roles: [ data_cold ]
```
```go
// 按数据冷热选择写入目标（索引生命周期策略自动完成迁移）
_, _ = es.Index("logs-000001").BodyJson(map[string]any{"@timestamp": time.Now()}).Do(ctx)
```
> 验证：`GET _cat/nodes?v` 中 role 列分别显示 h / w / c / f / s `[实测]`。

## 总结与追问预判
**分层的本质是让硬件花在真正被访问的数据上**。追问常落在冻结层的查询代价上。
