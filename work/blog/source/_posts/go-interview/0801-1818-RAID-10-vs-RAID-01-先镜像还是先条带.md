> 原文锚点：第 52~78 段「RAID 10 与 RAID 01 结构及优劣」、第 84~91 段「选型因素」

## 一句话总述
RAID 10 是**先做镜像再做条带**（RAID 1+0），最少 4 块盘、利用率 50%，只要不是同一镜像对两块盘同时坏就能撑住；RAID 01 是**先条带再镜像**，一个条带内坏一块盘就会导致该条带整体失效，容错率明显更低。

## 面试官视角
考官用这题看你会不会**算容错概率**。不用给精确公式，但要说清：RAID 10 只在「同一镜像对双坏」时才丢数据，RAID 01 只要另一组再坏一块就全盘皆输。讲清这个差异比背定义有用。

## 主问答
**Q（面试官原话）：** RAID 10 和 RAID 01 有什么不一样？生产上选哪个？

1. **组合顺序不同**：RAID 10 先对每两块盘做镜像、再对镜像组做条带；RAID 01 先做条带、再把整组条带镜像出去。
2. **故障表现不同**：RAID 10 中一块盘损坏后，其镜像盘仍有完整数据，该条带继续工作；RAID 01 中一块盘损坏会让整个条带不可用，只能靠另一组条带支撑。
3. **二次故障风险**：RAID 10 只有同一镜像对双坏才丢数据；RAID 01 只要另一组再坏任意一块即整体失效，生存概率更低。
4. **容量与盘数**：两者利用率都是 50%；RAID 10 最少 4 块盘并按 2 递增，容量不等时以最小盘为准。
5. **选型三因素**：数据重要性决定冗余级别，读写比重决定级别（写密集偏向 RAID 10），成本决定用硬件卡还是软阵列。

## 关键代码
```go
// Go 侧视角：把"以最小盘为准"写成容量校验，避免扩容时算错可用空间
package main

import "fmt"

func raid10Usable(disks []int) int {
	min := disks[0]
	for _, d := range disks {
		if d < min {
			min = d
		}
	}
	return min * len(disks) / 2
}

func main() {
	fmt.Println("4×200GB 的 RAID10 可用:", raid10Usable([]int{200, 200, 200, 200}), "GB")
}
```

## 总结与追问预判
核心：**先镜像后条带 = 更高容错，生产优先 RAID 10**。追问常拐向「RAID 10 和 RAID 5 怎么选」，备好「写密集与高可靠选 RAID 10，读密集且容量敏感选 RAID 5/6」。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文举例称 4 块 200GB 组 RAID 10「可用 500GB」——按 4×200GB=800GB 与 50% 利用率计算应为 400GB，原文举例数字不自洽。
2. 事实核校： [经验] 原文称 RAID 10「提供百分之百的数据冗余」——指每个字节都有镜像副本（冗余开销 100%），并不等于任何故障都不丢数据；同一镜像对双坏仍会丢失。
3. 崩坏词归一：源码将 RAID / 条带化 / 镜像 等音译为多组崩坏词，本卡统一为规范术语。
