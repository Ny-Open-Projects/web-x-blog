> 分类：数据库 / MySQL 索引 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**B+树、有序性、单链表、双向链表、目录页嵌套、聚簇索引、索引即数据**

> 原文锚点：第 1~15 段「b加树呢有两个特性…数据页和数据行是以主键从小到大的顺序进行排列的…b加树的叶子节点存储的是完整的用户记录，也就是它包含所有列的数据…目录页呢它是可以建套的，那也就是说我们这个目录页的节点呢，它可以是另一个目录页…具有上面这两种特性的索引呢，我们就称为聚集索引」

## 一句话总述
聚簇索引的 B+树有两大特性：**①两级有序**（行按主键从小到大用单链表串起来，页与页之间也按主键有序并用双向链表串起来）；**②叶子节点存完整的用户记录**（含所有列）。同时目录页可以**嵌套**——目录页的子节点还可以是另一个目录页。

## 面试官视角
- 考察意图：是否真的理解"B+树长什么样"，而不是只背"多路平衡树"这个定义。
- 分档：P5 知道叶子存数据、非叶子存索引；P6 能说清**两级有序**；P7 能补上**目录页嵌套**与**页间双向链表**，并推出"索引即数据"。
- 红旗答案：把 B+树说成"只有叶子有序"，漏掉**页级有序**；不知道目录页之间也是链表。
- 惊艳点：**目录页（非叶子节点）之间同样是双向链表**，且**目录页可以嵌套**——所以 B+树不是"目录层 + 叶子层"两层，而是**可以有多层目录** `[源码]`。

## 主问答
**Q（面试官原话）：** InnoDB 的聚簇索引 B+树到底长什么样？

1. **结论**：聚簇索引的 B+树有**两个特性**——**有序性**（数据行与数据页都按主键从小到大排列）和**叶子存完整记录**；具备这两点的索引称为**聚簇索引（聚集索引）**，它由 **InnoDB 自动创建** `[源码]`。
2. **有序性其一 · 行级有序**：所有**非叶子节点以下的数据行**，都按主键**从小到大依次排列**，页内每一行通过**单链表**链接起来 `[源码]`。
3. **有序性其二 · 页级有序**：不仅行有序，**数据页本身也有序**——如页 1 主键 1~2、页 2 主键 3~4、页 3 主键 5~6；**页与页之间是双向链表** `[源码]`。
4. **目录页（非叶子节点）**：存放**目录项**的索引页位于非叶子节点，同层目录页也按**目录项记录主键大小**排成**双向链表** `[源码]`。
5. **目录页可嵌套**：**目录页的节点可以是另一个目录页**，形成嵌套的目录关系——例如目录页 4 的两个子节点都是目录页 `[源码]`。这正是 B+树能支撑千万级数据仍保持 3~4 层高度的原因。
6. **特性二 · 叶子存完整记录**：叶子节点的数据页存了**所有字段的字段值**；因为数据就在索引的叶子节点上，所以是**索引即数据、数据即索引** `[源码]`。
7. **边界**：一个表**只能有一个**聚簇索引（物理顺序只有一种），且由 InnoDB 自动按主键建立；若表无显式主键，InnoDB 会选第一个非空唯一索引，再没有则生成隐藏的 6 字节行标识 `[经验]`。

**加分层：** 正因为"页间双向链表 + 行间单链表"，**范围扫描才能顺序 IO**——找到左边界后顺着链表扫即可，不必反复回根节点。

## 关键代码
```sql
-- 1) 观察聚簇索引：主键就是聚簇索引，Extra 为空说明不用回表
EXPLAIN SELECT * FROM userbig WHERE id = 100;

-- 2) 范围扫描：页间双向链表让它可以顺序 IO 往下扫
EXPLAIN SELECT * FROM userbig WHERE id BETWEEN 100 AND 200;

-- 3) 看树的高度（InnoDB 通常 3~4 层即可存千万行）
SELECT index_name, page_no, btr_level
FROM information_schema.innodb_buffer_page
WHERE table_name LIKE '%userbig%' AND index_name = 'PRIMARY'
LIMIT 5;

-- 4) 无显式主键时：InnoDB 自动选唯一索引或生成隐藏行标识
CREATE TABLE t_nopk (a INT, b INT) ENGINE=InnoDB;
SHOW CREATE TABLE t_nopk\G
```

## 总结与追问预判
**最爱追问的是"为什么 B+树能范围扫描很快"**——答案不在"树矮"，而在**叶子层是双向链表**：定位左边界一次 B+树查找（O(log N)），之后沿链表顺序扫（顺序 IO）。追问常接"那二级索引回表为什么慢"——因为回表的主键**散落在聚簇索引的多个数据页**，变成随机 IO（见 1217）。
