> 分类：并发模型 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**goroutine** / **循环变量** / **per-iteration scope**

> 原文锚点：第 55~75 段「go 启动闭包读 i，调度顺序不定，输出最后值或不定值」

## 一句话总述
`go` 启动的闭包异步执行，读到的循环变量 `i` 是**共享的那一个**；旧版 Go 每轮复用同一变量，调度顺序不定 → 输出全 10 或乱序——Go 1.22 起每轮变量独立，该坑被修复。一句话背法：**「for 里 go 读循环变量 i：旧版共享同一变量→读终值/乱序，Go 1.22 起每轮独立自愈；正解显式传参」**。

## 面试官视角
这是并发题里的"版本翻转"高频考点。考官要看你既懂旧版竞态本质，又知道 Go 1.22 的语义变化。
- **P5**：知道输出不定。
- **P6**：说清异步 + 共享循环变量 = 读终值。
- **P7**：知道 1.22 翻转且旧代码仍兼容，并点出 GOMAXPROCS=1 不是保证 `[经验]`。
- **红旗**：以为 goroutine 一定按顺序读 i；以为设 GOMAXPROCS=1 就安全。
- **惊艳点**：同段代码 go1.21 输出全 10、go1.22 输出 0..9（顺序仍不定）`[源码]` release notes。

## 主问答
**Q（面试官原话）：** for 里 go 打印 i，为什么打出来都是 10 或者乱的？

**先铺垫（由浅入深第 1 层）**：`go func(){...}()` 不是"立刻执行"，而是"把这段闭包交给调度器，稍后某刻跑"。问题就出在"稍后"——闭包里要读的 `i`，和循环本身用的 `i` 是不是同一个。

1. **结论（第 2 层·机制）**：旧版循环变量 `i` 全程一个地址，闭包读的是"终值"；goroutine 异步调度，读到哪轮看运气 `[源码]`。
2. **机制（第 3 层）**：`i` 在循环外创建、每轮覆盖；闭包捕获该变量，执行晚于迭代，多半读到结束后的 10 `[源码]`。
3. **边界（第 4 层）**：Go 1.22+ 每轮 `i` 是独立变量，闭包各自捕获当轮值 → 输出 0..9（仍并发无序）`[源码]` release notes。
4. **修复（第 5 层·实战）**：显式把 `i` 当值参数传入闭包，断开心地址共享——新旧版本都正确 `[经验]`。
5. **误区（第 6 层）**：GOMAXPROCS=1 只是让循环抢满 CPU 延迟调度，属巧合非保证，勿依赖 `[经验]`。

## 版本与兼容性
| 维度 | 说明 |
|------|------|
| Go ≤1.21 | 循环变量全程单实例，闭包共享 → 读终值/乱序 `[源码]` |
| Go 1.22 起 | for/range 循环变量改为每轮独立（per-iteration scope），旧写法自愈 `[源码]` release notes |
| 兼容性 | 老代码在 1.22+ 不再踩坑；新代码仍建议显式传参更清晰 |
| 推荐写法 | `go func(v int){...}(i)` 传值，跨版本正确 |

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	const n = 5
	var wg sync.WaitGroup

	// 反例：闭包捕获同一个 i（≤1.21 全打印 n；1.22+ 打印 0..n-1 但顺序不定）
	for i := 0; i < n; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println("shared i =", i)
		}()
	}
	wg.Wait()

	// 正解：把 i 作为值参数传入，断开心地址共享（新旧版本都正确）
	for i := 0; i < n; i++ {
		wg.Add(1)
		go func(v int) {
			defer wg.Done()
			fmt.Println("captured v =", v)
		}(i)
	}
	wg.Wait()
}
```

## 总结与追问预判
**背这三句就够**：① **闭包异步读共享循环变量 → 读终值/乱序**；② **Go 1.22 起每轮独立变量，旧写法自愈**；③ **正解显式传参，跨版本正确**。
**预判追问**：
- 「1.22 改了什么？」→ for/range 循环变量每轮独立（per-iteration scope），见 1017 同号卡。
- 「GOMAXPROCS=1 能避免吗？」→ 不能，只是巧合延迟，非语义保证。
- 「和 for-range 取址陷阱啥关系？」→ 同源"循环变量单实例"，一个读值一个取址（见 1017 for-range 取址）。

## ⚠️ 原文纠错
原文将"循环变量每轮复用同一变量"作为**普适事实**叙述，未提示版本边界。正确结论：**Go 1.22 起 for 与 range 的循环变量改为每轮独立（per-iteration scope）**，旧版（≤1.21）才是共享单变量。现在面试应主动区分两版本：旧代码踩坑，1.22+ 该写法已自愈，但仍推荐显式传参。
