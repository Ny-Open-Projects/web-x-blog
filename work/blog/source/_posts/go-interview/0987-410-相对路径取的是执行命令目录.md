> 原文锚点：第 4~17 段「go 里用点表示相对路径，路径是相对执行命令时的路径，不是相对当前文件」

## 一句话总述
Go 里 `.` 相对路径与 `os.Getwd()` 取的都是**启动进程时所在的目录**，不是 .go 文件所在目录；换目录执行同一二进制，拿到的根目录就变。

## 面试官视角
- 意图：是否踩过"换目录跑就找不到配置"的坑，懂路径基准。
- P5 知相对路径随执行目录变 / P6 说清基准是进程 cwd / P7 知用 runtime.Caller 或 embed 消除依赖。
- 红旗：以为 `./conf` 指"代码相邻目录"；以为 go run 和 go build 路径行为一致。
- 惊艳点：`os.Getwd()` 等价于进程的 cwd，与 `.` 基准完全相同 `[源码]` os 包文档。

## 主问答
**Q（面试官原话）：** 为什么我的程序换个目录跑就找不到配置文件了？
**A：**
1. **结论**：`.` 与 `os.Getwd()` 都基于进程启动时的 cwd，不是源码文件位置。
2. **机制**：你 `cd` 到哪执行命令，cwd 就是哪；`go run main.go` 或二进制在哪启动，相对路径就相对哪。
3. **边界**：`go build` 后再跑，根目录仍取决于"你在哪敲的运行命令"，不在代码写死就随部署脚本而变。
**加分层：** 线上把打包+执行固化进脚本，相对路径才稳定，但这仍是脆弱解。
