> 原文锚点：第 31~36,51~52 段「索引字段类型不匹配（字符当数值不加引号）→隐式转换失效；OR 两字段都索引才走」

## 一句话总述
对**字符类型列**当数值用、不加引号，MySQL 会做**隐式类型转换**导致索引失效走全表扫描；`OR` 连接的条件**只有两侧字段都是索引列**才走索引，否则失效——可用 `UNION` 替代。

## 面试官视角
- 意图：考察对"索引为什么突然不生效"的排障能力。
- 分档：P5 知函数导致失效；P6 知隐式转换；P7 能讲 OR 规则 + 用 EXPLAIN 验证。
- 红旗：写出 `WHERE phone = 13800000000`（字符列不加引号）还奇怪全表扫。
- 惊艳点：点出"隐式转换本质是对列套了函数，等价于索引列上做计算"。

## 主问答
**Q（面试官原话）：** 字段有索引，查询却全表扫描，可能为什么？
**A：**
1. **隐式类型转换**：字符列当数值比较不加引号，如 `WHERE phone = 13800000000`；MySQL 自动把列转数值，等价于对列套函数 → 索引失效。必须 `WHERE phone = '13800000000'`。
2. **OR 条件**：`col1 = 1 OR col2 = 2`，只有 `col1`、`col2` **都为索引列**时才走索引，否则整句失效；可用 `UNION` 拆成两个索引查询替代。
3. **口诀辅助记忆**：全值匹配我最爱，最左前缀要遵守；索引列上少计算，字符引号不能丢；不等空值还有 `OR`，索引失效要注意。

## 关键代码
```sql
-- 失效：字符列当数值，隐式转换
EXPLAIN SELECT * FROM user WHERE phone = 13800000000; -- type=ALL
-- 生效：加引号
EXPLAIN SELECT * FROM user WHERE phone = '13800000000'; -- type=ref
-- OR 只有两侧都索引才走；否则拆 UNION
SELECT * FROM t WHERE a=1 UNION SELECT * FROM t WHERE b=2;
```

## 总结与追问预判
- 隐式转换 = 对列套函数；OR 需两侧都索引；`EXPLAIN` 是裁判。
- 预判：索引失效全汇总 → 见 1222；最左前缀 → 见 1222。
