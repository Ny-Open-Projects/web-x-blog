> 分类：数据库 / MySQL 架构 | 难度：L3 | 题型：流程题 | 频率：高 | 关键词：**连接器、查询缓存、分析器、优化器、执行器、存储引擎、返回结果**

> 原文锚点：第 66~81 段「通过连接器来建立连接，连接器会验证客户端的身份和权限…在 MySQL 8.0 之前，如果开启了查询缓存，它还会校验查询缓存，连接器会先检查查询缓存，尝试找到与当前 SQL 语句完全相同的查询，如果命中就直接返回…分析器会进行语法分析…还会进行语义分析并检查表和列以及函数这些对象的存在性和合法性并进行权限验证…优化器会根据统计信息和数据库的规则生成多个可能的执行计划…执行器会根据执行计划执行具体的查询操作，它会调用存储引擎的接口」

## 一句话总述
一条 SQL 的执行链路是**连接器（鉴权）→ 查询缓存（8.0 前）→ 分析器（语法/语义/权限）→ 优化器（生成计划）→ 执行器（调引擎接口）→ 存储引擎（读写数据）→ SQL 接口返回结果**。

## 面试官视角
P6 能说「解析、优化、执行」；P7 要**按七步完整串起来**，并点出两个版本相关细节：**查询缓存只在 8.0 之前存在**，以及**权限校验不止一次**（连接器鉴权、分析器再校验对象合法性）。

## 主问答
**Q（面试官原话）：** 一条 SELECT 在 MySQL 里是怎么执行的？

1. **连接器建立连接**：客户端与数据库建立连接并发送 SQL；连接器**验证客户端身份和权限**，确认用户**有足够权限执行该语句** `[源码]`。
2. **查询缓存校验（8.0 之前）**：若开启查询缓存，连接器**先检查查询缓存**，尝试找到与当前 SQL **完全相同**的查询；**命中则直接返回**，避免后续全部执行过程；前提是 **8.0 之前且启用查询缓存** `[源码]`。
3. **未命中则进分析器**：没有命中查询缓存时，连接器将 SQL 传给分析器 `[源码]`。
4. **分析器 · 语法分析**：确保语句的**结构和语法正确** `[源码]`。
5. **分析器 · 语义与权限**：进行**语义分析**，检查**表、列、函数**等对象的**存在性与合法性**，并进行**权限验证** `[源码]`。
6. **优化器**：根据**统计信息和数据库规则**生成**多个可能的执行计划**，包括选择不同索引、不同连接顺序、调整筛选条件顺序等；目的是**选出最优执行路径** `[源码]`。
7. **执行器**：根据执行计划执行具体操作，**调用存储引擎接口**处理数据的存储、检索和修改；从磁盘或内存获取数据，并执行**行连接、过滤、排序**等操作生成最终结果 `[源码]`。
8. **存储引擎**：负责**具体数据的存储、检索和修改**，根据执行器请求从磁盘或内存读取或写入 `[源码]`。
9. **返回结果**：存储引擎把结果返回执行器，执行器返回连接器，**连接器发回客户端**，完成整个执行过程 `[源码]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| 8.0 起 | 查询缓存被移除 | 流程中不再有缓存校验 |
| 8.0 之前 | 需显式开启才生效 | 完全相同才命中 |
| 所有版本 | 分析器校验 | 语法 + 语义 + 权限 |
| 所有版本 | 执行器 | 通过引擎接口读写 |

## 关键代码
```sql
-- 1) 连接器：身份与权限校验（8.0 前还会先查查询缓存）
-- mysql -u root -p

-- 2) 分析器：语法/语义错误在此暴露
SELECT * FORM userbig;   -- 语法错误
SELECT * FROM not_exist; -- 语义错误：表不存在

-- 3) 优化器：生成多个候选计划并选成本最低者
EXPLAIN FORMAT=JSON SELECT * FROM userbig WHERE name > 'name10'\G

-- 4) 执行器 + 存储引擎：真正取数的是存储引擎
SELECT * FROM userbig WHERE id = 1;

-- 5) 结果经执行器 -> 连接器 -> 客户端返回
```

## 总结与追问预判
**「查询缓存只在 8.0 之前」是最爱考的版本点**。追问常是「8.0 为什么移除查询缓存」——因为**表数据一变，涉及该表的缓存全部失效**，而一条数据可能存在于多个缓存列表中，维护代价极大（该思路也用于解释缓存一致性方案，见 1261-* 那批）。

2. 补充：原文说「连接器会先检查查询缓存」应更正为**该环节在 8.0 之前且需显式开启**；8.0 起查询缓存已被彻底移除，现代流程直接从连接器进入分析器 `[经验]`。
