## 一句话总述
公司内部私有包通常上传到企业内网 git 平台。本地开发时若包尚未上传，`go mod tidy` 会因拉取不到而报 404。解法是用 `go.mod` 的 **`replace`** 把远端模块路径替换为本地路径：`replace github.com/xxx/privatePKG => ../privatePKG`，随后依赖即可解析，并在 `require` 中生成伪版本号。

## 面试官视角
私有包导入是工程实战题。考官看你能不能讲清：① 为何 `go mod tidy` 报 404（包没上传）；② `GOPRIVATE` 的作用——匹配到的域名**绕过 Go 代理、直连源码站**，所以才走到真实路径去拉；③ `replace` 把远端路径映射成本地目录。能补「replace 只在主模块生效」是加分。

## 主问答
**Q（面试官原话）：** 本地还没上传的私有包，怎么在另一个工程里引用？

1. **问题现象**：在工程中 import 远端路径的私有包后执行 `go mod tidy`，会报 404——因为该包并未真正上传到平台。
2. **GOPRIVATE 的作用**：`GOPRIVATE` 配置匹配到的域名（如 `gitee.com`）会**绕过 Go 代理、直接从源码站拉取**；正因如此才暴露出包不存在。
3. **replace 解法**：在 `go.mod` 中写 `replace <远端模块路径> => <本地相对路径>`，把远端路径映射到本地目录。
4. **结果**：replace 后依赖被解析，`require` 中出现该模块并带**伪版本号**；即实现「用远端路径的包名，实际取本地代码」。
