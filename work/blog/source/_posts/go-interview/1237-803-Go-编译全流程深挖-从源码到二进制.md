## 思路与架构
Go 编译器（`cmd/compile`）与链接器（`cmd/link`）均用 Go 自写，分前后端：
- 前端：scanner（`syntax/scanner.go`）切 token → parser（`syntax`）组 AST → 类型检查（`types2`）做语义校验。
- 后端：AST → 带类型 IR → SSA（`ssa` 包，与机器无关）→ 多轮优化 → lowering 到目标架构 → `cmd/internal/obj` 产出 `.o` → `cmd/link` 把多个 `.o`（含 runtime、标准库）静态拼接成单文件二进制。
关键设计：**前端与机器无关、后端与语言无关**——`syntax` 包产出语言中立的 AST，SSA 框架屏蔽架构差异，便于新增 GOARCH。

## 方案取舍
- **自研编译器而非用 GCC**：启动快、跨平台一致、单体二进制无外部依赖（CGO 除外）。代价是优化广度弱于 GCC/LLVM，但 Go 团队持续在 SSA 阶段追赶。
- **静态单赋值（SSA）**：以"每个变量只赋值一次"的形式暴露数据流，让常量传播、死代码消除、寄存器分配等优化更彻底；缺点是 IR 体积与编译内存占用上升，故 Go 对大型包有并发编译与缓存（`-a` 强制失效缓存）。
- **静态链接默认**：省去运行时动态库依赖、部署简单；代价是二进制体积偏大。
- **逃逸分析在 SSA 之前**：先决定值堆/栈归属，SSA 阶段据此生成分配/取址指令，避免后端反复回溯。

## 答题技巧
1. **分层答**：先"前端（词法→语法→类型）"后"后端（IR→SSA→机器码→链接）"，用"与机器无关→相关"一句话点出分界。
2. **源码定位加分**：scanner/parser 在 `cmd/compile/internal/syntax`，类型检查 `types2`，SSA `cmd/compile/internal/ssa`，汇编 `cmd/internal/obj`，链接 `cmd/link`。
3. **`go build` 内省**：`-n` 打印不执行、`-x` 执行并打印、`-a` 强制重建、`-gcflags='-S'` 看汇编、`-gcflags='-m'` 看逃逸、`-race` 开竞态。把"怎么验证"带出来最显功底。
4. **反直觉点**：① 编译期就拦住多数错误（对比 Python 运行期）；② `.o` 不含完整程序，链接才成二进制；③ SSA 不是机器码，是优化载体。
5. **收尾钩子**：自然过渡到"逃逸分析""channel 底层"等相邻考点，体现知识网。

## 细节与核心 API

```bash
go build main.go                # 1) 词法/语法分析 -> AST
                                # 2) 类型检查（含泛型实例化）
                                # 3) 中间表示 SSA 生成 + 优化（内联/逃逸/死代码）
                                # 4) 生成机器码（obj）
                                # 5) 链接器 link 成单一静态二进制（默认静态）
GOSSAFUNC=main go build main.go # 生成 ssa.html 可视化各优化阶段
go tool compile -S main.go      # 打印汇编
go tool objdump ./main          # 反汇编最终二进制
CGO_ENABLED=0 go build .        # 纯静态（无 libc 依赖），便于极小镜像
# 阶段可观测：GODEBUG=inittrace=1 看 init 耗时；go build -gcflags="-m" 看逃逸分析
```
