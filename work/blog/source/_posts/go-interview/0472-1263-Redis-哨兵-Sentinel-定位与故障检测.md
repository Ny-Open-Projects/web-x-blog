> 分类：Redis/高可用 | 难度：L3 | 题型：概念题 | 频率：高 | 关键词：**哨兵**/**Sentinel**/**故障检测**/**主观下线**/**客观下线**/**pubsub组集群**
> 原文锚点：第 1~14 段「主挂需自动切换 + 哨兵三职责(故障检测/选主/故障转移) + pub/sub 组集群 + 心跳无响应→主观下线→多哨兵→客观下线」

## 一句话总述
主从复制解决了数据同步，但**主节点挂了从节点不会自动升主**。Redis 2.8+ 的**哨兵（Sentinel）**补上故障转移：它监控主从，通过 **pub/sub 相互感知组成哨兵集群**，连续多次心跳无响应则标记主节点**主观下线（sdown）**，多个哨兵都标 sdown 则升级为**客观下线（odown）**，触发故障转移。

## 面试官视角
- 考察意图：能否说清「为什么需要哨兵」以及 sdown/odown 的区别与升级条件。
- 分档：P5 知哨兵做故障转移；P6 能说 sdown→odown 升级；P7 知 pub/sub 组集群、哨兵是独立 Redis 进程。
- 红旗答案：把 sdown 当最终判定（需多哨兵共识才 odown）；认为哨兵只监控不修复。
- 惊艳点：点出「哨兵是独立运行的 Redis 进程、监控对象含主从、发现异常会主动修复」，以及「sdown 是单哨兵视角、odown 需 quorum 个哨兵共识」 [经验]。

## 主问答
**Q（面试官原话）：** Redis 哨兵是干嘛的？怎么检测主节点挂了？
**A：**
1. **定位**：主从架构主挂后无主可写，哨兵负责**故障检测、选主、故障转移**三件事，实现自动主从切换 [经验]。
2. **组集群**：哨兵通过 Redis 的 pub/sub 相互感知建连成集群，并通过主节点 `info` 拿到从节点信息建立监控 [经验]。
3. **下线判定**：连续多次心跳无响应→单哨兵标**主观下线 sdown**；多个哨兵都标 sdown→升级**客观下线 odown**，才触发故障转移 [经验]。

## 关键代码

```go
// 应用侧通过哨兵发现主节点地址（go-redis Failover 客户端）
// 哨兵负责在主挂时把主地址切到新主，客户端无需硬编码主 IP
import "github.com/redis/go-redis/v9"
func newClient() *redis.Client {
    return redis.NewFailoverClient(&redis.FailoverOptions{
        MasterName:    "mymaster",        // 哨兵监控的主名
        SentinelAddrs: []string{"127.0.0.1:26379", "127.0.0.1:26380", "127.0.0.1:26381"},
    }) // 哨兵返回当前主节点地址；主切换对客户端透明
}
// 哨兵判定：单哨兵心跳超时→sdown；quorum 个哨兵 sdown→odown→故障转移
```

## 总结与追问预判
哨兵是 Redis 高可用的「大脑」。sdown→odown 的「单点怀疑→多数共识」机制天然抗网络抖动误判，是后续 quorum 配置的基础。
