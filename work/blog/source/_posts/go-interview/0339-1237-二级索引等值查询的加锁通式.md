> 原文锚点：第 34~38 段「本质是扫描过程…扫描到的二级索引记录加临键锁…符合的主键加记录锁」

## 一句话总述
按二级索引做等值加锁读时，会沿索引扫描到**第一个不满足条件的记录**才停：扫过的二级索引记录加临键锁，命中的主键记录加记录锁；目标不存在时临键锁退化为间隙锁。

## 面试官视角
P6 只说"加行锁"；P7 要给出**三条规则**：扫描终止条件、二级索引上加什么、主键上加什么 `[经验]`。加分点是退化规则——等值查询的不满足项，临键锁会退化成纯间隙锁，这是等值区别于范围查询的关键 `[源码]`。

## 主问答
**Q（面试官原话）：** 普通索引等值查询，到底锁了哪些范围？

1. **扫描而非点查**：二级索引上同值可能有多条，因此是扫描过程，直到扫到第一个不符合条件的记录才停止 `[经验]`。
2. **二级索引加临键锁**：扫描过程中对扫到的二级索引记录加临键锁，即左开右闭区间，左端是同层前一个索引值 `[源码]`。
3. **主键补记录锁**：符合查询条件的主键索引记录会被回表加锁，锁型是**记录锁**而非临键锁 `[实测]`。
4. **不存在则退化**：目标不存在时不满足项上的临键锁退化成间隙锁，且因为无命中行，**主键不加锁** `[经验]`。

## 关键代码
```sql
-- 表 t：id 主键，name 普通索引；数据 name 值为 1,2,20,3,4,5,7
BEGIN;
SELECT * FROM t WHERE name = '7' LOCK IN SHARE MODE;
-- 二级索引：两条 name=7 记录加临键锁；主键 id=7、id=10 加记录锁
```
```go
// 记牢通式：命中 -> 临键锁 + 主键记录锁；未命中 -> 退化为间隙锁
switch {
case hit:
	lockNextKey(secondaryRec) // 左开右闭
	lockRecord(primaryRec)
default:
	lockGap(secondaryRec)
}
```
