## 一句话总述
鸭子类型=**关注行为而非类型**（"像鸭子走路游泳叫就是鸭子"）。Go 用 interface 实现：只要类型实现接口**全部方法**即视为满足该接口（结构化/隐式），编译器做隐式转换，故静态语言也有动态风格。附带两点：Go 面向对象"既是也不是"（有类型方法无继承语法，接口隐式实现轻量灵活）；函数式（数据流/纯函数）与 OO（数据状态/封装继承多态）本质区别在于"处理数据 vs 关注状态"。

## 面试官视角
- 考察意图：是否真懂鸭子类型的"行为判定"本质，以及 Go interface 的隐式实现（非 Java 式 implements 声明）。
- 分档：P5 知鸭子类型定义；P6 能写 interface 示例（实现即满足）；P7 能讲"Go 静态语言如何有动态风格（编译器隐式转换）"+ Go 是否 OO。
- 红旗答案：认为 Go 必须显式 implements；把接口当 Java 抽象类（需继承）。
- 惊艳点：点出「鸭子类型由当前方法集合决定语义，而非继承自特定类」「Go 编译器做隐式接口转换，静态语言也有动态风格」 [经验]。

## 主问答
**Q（面试官原话）：** Go 里怎么通过 interface 实现鸭子类型？
**A：**
1. **鸭子类型本质**：有效语义由对象"当前方法/属性集合"决定，而非继承自特定类或声明实现某接口——"像鸭子叫就是鸭子" [经验]。
2. **interface 是方法集**：Go 接口定义一组方法，描述对象应有的行为；只要类型实现接口**全部方法**，就被视为实现了该接口 [经验]。
3. **隐式实现+编译器转换**：无需 `implements` 声明，结构体方法集匹配即满足；Go 编译器在赋值时做隐式接口转换，使静态语言具备动态风格 [经验]。
4. **Go 是不是 OO**：既是也不是——有类型和方法、允许 OO 风格，但无 Java/C++ 式继承语法；接口隐式实现（"隐式继承"）更轻量通用 [经验]。
5. **函数式 vs OO**：函数式将计算视为函数求值，强调纯函数/不可变/数据流；OO 基于对象交互，强调封装/继承/多态/数据状态；本质区别在"处理数据 vs 关注状态" [经验]。

## 关键代码

```go
// 鸭子类型：只要类型实现接口全部方法，即视为该接口（隐式）
type Duck interface {
    Quack()
}

type YellowDuck struct{}
func (YellowDuck) Quack() { fmt.Println("yellow duck quack") }

type NormalDuck struct{}
func (NormalDuck) Quack() { fmt.Println("normal duck quack") }

// 入参是 Duck 接口，任何实现了 Quack 的类型都能传入——"像鸭子叫就是鸭子"
func quack(d Duck) { d.Quack() }

func main() {
    quack(YellowDuck{})
    quack(NormalDuck{})
}
```

## 总结与追问预判
鸭子类型核心是"行为判定"——Go 用 interface 的隐式实现把静态语言变得像动态语言。面试常追问「和 Java 接口有何不同」→ 答「无 implements 声明、方法集匹配即满足、编译器隐式转换」；再追问 OO 则讲"既是也不是+无继承语法"。
