> 分类：Go 语言基础 | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**整体赋值、头部替换、首元素地址变化、append 扩容**

> 原文锚点：第 81~86 段「函数里对整个结构体赋值，它的间接部分的地址就会改变…这种赋值方式不会影响外面的值」

## 一句话总述
在函数里**给切片字段整体赋新切片**（`ps.Names = ns`），副本头部的指针被换成新地址，与调用方的头部从此各走各路，外面自然看不到。

## 面试官视角
考的是同一模型的反面。能答出"整体赋值换的是自己那一格指针"即达标；加分是补上**地址会变**的实测证据，并指出这正是"想让函数内的 append 生效必须传 `*[]T` 或返回新切片"的原因，把语言机制落到 API 设计上 `[经验]`。

## 主问答
**Q（面试官原话）：** 同样是改这个切片字段，整体赋值为什么就不影响外面了？

1. **结论**：整体赋值改的是**副本头部里的 ptr**，让它指向另一块内存；调用方的头部仍指向原数组，双方彻底分家。
2. **证据**：原文在函数内重新赋值后再打印该字段，地址与调用前的原地址**不再相同**，而在此之前两者是一致的 `[实测]`。
3. **与 append 同源**：`append` 在容量不足时也会分配新数组、换掉副本头部的 ptr，所以"函数里 append 外面看不到"是同一条规则。
4. **解法**：要让调用方拿到新切片，**返回并重新赋值**，或者传 `*[]T`；这是 API 设计取舍，不是语言缺陷 `[经验]`。

## 关键代码
```go
type Team struct {
    Names []string
}

func changeStruct3(t Team) {
    t.Names = []string{"x", "y", "z"}  // 换掉副本头部的 ptr
}

func main() {
    t := Team{Names: []string{"a", "b", "c"}}
    changeStruct3(t)
    fmt.Println(t.Names)  // [a b c]，原文实测保持不变
}
```

## 总结与追问预判
**赋值的颗粒度决定可见性**：写元素 → 跨函数可见；赋整个字段 → 只有副本可见。答题时用这一句把两种情况一并收掉。
