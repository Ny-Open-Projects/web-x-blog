# 615 Go 接口的两种"实现"与隐式实现

> 分类：Go 语言 / 接口 | 难度：L3 | 题型：机制题 | 频率：高 | 关键词：**隐式实现** / **内嵌接口** / **空指针陷阱** / **全方法实现** / **nil pointer**
> 原文锚点：第 22~46 段「接口两种实现…内嵌接口可只实现部分方法(调用未实现报空指针)…实现全部方法…隐式转化」

## 一句话总述
Go 接口是**隐式实现**（struct 方法集匹配即满足接口，无需 implements 声明）。"实现接口"有两条路径：① 内嵌接口——可只实现部分方法，但调用未实现的方法会 nil pointer panic；② 实现接口全部方法——必须全实现才算满足。为健壮性建议用第二种。

## 面试官视角
- 意图：是否懂 Go 接口的隐式契约，以及"内嵌接口部分实现"的空指针陷阱。
- P5 知隐式实现；P6 说清两种方式差异与空指针陷阱；P7 知何时用内嵌接口、为何全实现更稳。
- 红旗：以为 Go 要显式声明 implements；不知道部分实现接口调用未实现方法会 panic。
- 惊艳点：隐式实现让"小接口+组合"成为 Go 惯用法；但内嵌接口留下 nil 方法指针，调用即 panic——这是经典坑 `[经验]`。

## 主问答
**Q（面试官原话）：** Go 怎么"实现"一个接口？两种方式有什么区别？
**A：**
1. **隐式实现**：struct 只要方法集涵盖接口全部方法即自动满足接口，无需 implements 关键字；可赋值给接口变量（如 person 隐式转 IPerson）`[源码]`。
2. **方式一·内嵌接口**：struct 内嵌接口类型，可只实现其中部分方法；但未实现的方法被调用时触发 nil pointer panic。
3. **方式二·全实现**：struct 显式实现接口的全部方法，才算真正满足接口，无空指针隐患。
4. **取舍**：为健壮性优先用全实现（第二种）；内嵌接口仅适合明确"可选方法"且调用前判空的场景。

## 关键代码
```go
// 示意，未验证：隐式实现 + 内嵌接口空指针陷阱 + 全实现
package main
import "fmt"
type IPerson interface {
    Talk(); Work()
}
type Person struct{ IPerson } // 内嵌接口：可只实现部分方法
func (Person) Talk()         { fmt.Println("person talk") }
// 未实现 Work —— 调用 p.Work() 会 nil pointer panic
type Teacher struct{}
func (Teacher) Talk()        { fmt.Println("teacher talk") }
func (Teacher) Work()        { fmt.Println("teacher work") } // 全实现，安全
func main() {
    var p IPerson = Person{} // 隐式满足（内嵌了 IPerson）
    p.Talk()
    // p.Work()              // 若取消注释：nil pointer panic（Work 未实现）
    var t IPerson = Teacher{} // 全实现，可直接调用 Talk/Work
    t.Work()
}
```

## 总结与追问预判
- 接口隐式实现；内嵌接口可部分实现但留空指针陷阱，全实现更稳。
