> 分类：Elasticsearch | 难度：L2 | 题型：原理题 | 频率：高 | 关键词：**节点角色、角色隔离、候选主节点、协调节点、摄取节点**

> 原文锚点：第 6~14 段「集群由多个节点构成…自动选举一个节点为 master 节点」

## 一句话总述
ES 把节点职责切成若干**角色**，每个节点可身兼多职；角色隔离的价值是按任务特点配硬件、并避免相互抢占资源。

## 面试官视角
P6 只知"有主节点和数据节点"；P7 要一口气报出五类角色并说清隔离动机 `[经验]`。加分点：生产建议**一台机器只跑一个 ES 实例**，否则资源竞争与故障域耦合；大型集群还会单独部署协调节点承接业务连接 `[源码]`。

## 主问答
**Q（面试官原话）：** ES 集群里都有哪些节点角色？

1. **候选主节点**：负责集群管理与协调——创建删除索引、分片分配、配置变更；配成候选不等于当选，最终由集群启动后投票决定 `[经验]`。
2. **数据节点**：存数据、处理读写与搜索聚合；默认所有节点都带这个角色，可显式关闭 `[源码]`。
3. **协调节点**：不存数据也不处理数据，只做请求路由与结果汇总；把主、数据角色全关掉即成为纯协调节点 `[源码]`。
4. **摄取节点**：写入前做预处理（提取、转换、加载），靠摄取管道实现；单独部署可避免抢占数据节点资源 `[经验]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ES 7.x 起 | 角色配置统一为 node.roles | 旧版 node.master/data 仍可识别 |
| ES 7.10+ | 数据分层角色引入 | 热温冷内容分层成为标配 |
| ES 8.x | 默认同时具备多角色 | 生产应按职责显式拆分 |

## 关键代码
```yaml
# elasticsearch.yml：专用协调节点
node.roles: [ ]          # 空角色 = 纯协调节点
# 专用数据节点
node.roles: [ data, ingest ]
```
```go
// 业务侧只连协调节点，不直连数据节点
cfg := elasticsearch.Config{Addresses: []string{"http://coord-1:9200"}}
```
> 验证：`GET _cat/nodes?v` 中该节点 role 列显示 `-`，即纯协调节点 `[实测]`。
