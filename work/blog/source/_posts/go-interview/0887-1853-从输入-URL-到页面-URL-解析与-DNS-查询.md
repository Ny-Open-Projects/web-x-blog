> 原文锚点：第 1~26 段「解析 URL 取协议域名端口 → 浏览器缓存→OS 缓存→本地 DNS→根→顶级域→权威 递归查询」

## 一句话总述
浏览器输入 URL 到拿到 IP，分两步：**先解析 URL** 取协议/域名/端口/路径（默认 http=80、https=443），**再走 DNS 查询** 把域名翻成 IP——优先查缓存链（浏览器→OS→本地 DNS），全未命中才发起「根→顶级域→权威」递归查询，本地 DNS 缓存结果供后续复用。

## 面试官视角
- 考察意图：能否按「缓存链 + 递归链」讲清 DNS 解析，而非只背「域名解析为 IP」。
- 分档：P5 知 DNS 把域名变 IP；P6 能量缓存层级与递归三级；P7 知各级 TTL 缓存与递归由本地 DNS 代发、客户端不直连根。
- 红旗答案：把递归查询说成「浏览器直连根服务器」；忽略缓存命中即短路。
- 惊艳点：点出「递归查询由本地 DNS 代发、客户端只与本地 DNS 交互」，以及「每层缓存带 TTL、命中即终止解析」 [经验]。

## 主问答
**Q（面试官原话）：** 浏览器输入 URL 后怎么解析出服务器 IP？
**A：**
1. **URL 解析**：先拆 URL 取协议/域名/端口/路径；端口缺省 http=80、https=443，拿到 (IP 用域名暂代, 端口) 后进入 DNS [经验]。
2. **DNS 缓存链**：依次查浏览器缓存 → 操作系统缓存 → 本地 DNS 服务器缓存，任一层命中即返回 IP、解析提前结束，免去递归 [经验]。
3. **递归查询**：本地 DNS 未命中则递归：先问根 DNS（管 .com/.org 等顶级域）→ 顶级域 DNS（管权威）→ 权威 DNS（返回目标 IP），结果回传并缓存 [经验]。

## 关键代码

```go
// URL 解析 + DNS 查询（缓存链短路、未命中才递归）
func resolve(host string) ([]net.IP, error) {
    // 1) URL 解析：拆协议/域名/端口（端口缺省按 scheme）
    u, err := url.Parse(host)
    if err != nil {
        return nil, err
    }
    port := u.Port()
    if port == "" {
        if u.Scheme == "https" {
            port = "443"
        } else {
            port = "80"
        }
    }
    // 2) DNS 查询：net 包内部已按 浏览器/OS/本地DNS 缓存链短路，全未命中才递归
    ips, err := net.LookupIP(u.Hostname()) // 底层走 本地DNS→根→顶级域→权威
    if err != nil {
        return nil, err
    }
    _ = port
    return ips, nil // 本地 DNS 会缓存结果供后续请求复用
}
```

## 总结与追问预判
DNS 解析本质是「从右往左逐级授权 + 就近缓存」的分布式查表。面试常追问「DNS 污染/劫持」「DNS 预取」「HTTPDNS」——均建立在「递归由本地 DNS 代发」这一事实上。
