> 原文锚点：第 9~11、46~62 段「缓冲与阻塞 / 发送接收具体过程」

## 一句话总述
**无缓冲 channel 是同步模式**：发送方与接收方必须同时就绪，任一方先到都会被 `gopark` 挂起，直到对方出现 handoff；**有缓冲 channel 是异步模式**：发送仅在**缓冲满**时阻塞、接收仅在**缓冲空**时阻塞。收发算法统一为「先抢 hchan.lock → 看对向等待队列(recvq/sendq)是否空 → 非空则直接 handoff 唤醒、否则写/读 buf、再不行挂自己入队」。

## 面试官视角
这题考「同步/异步」的本质区别，而非背定义。能说出「无缓冲=双方 rendezvous、有缓冲=解耦生产消费速度」，再补一句「收发都优先和对向等待队列 handoff、其次才碰 buf」的算法顺序，就是高分——后者是 609 结构卡没展开的算法步骤。

## 主问答
**Q（面试官原话）：** 有缓冲和无缓冲 channel 有什么区别？

1. **无缓冲=同步（rendezvous）**：没有 buf，发送方必须等接收方出现才能交棒；任一方先到都阻塞挂起，双方就绪才 handoff——天然用于「两个协程严格同步点」。
2. **有缓冲=异步**：buf 解耦生产/消费速度，发送在 **buf 未满** 时直接返回、仅在满时阻塞；接收在 **buf 非空** 时直接返回、仅在空时阻塞。
3. **send 算法顺序**：抢锁 → 若 `recvq` 非空（说明有接收方在等，buf 必空或本就是无缓冲），直接从 recvq 取队首 sudog 把值交给他并唤醒 → 否则若 buf 有空位写 buf → 否则封装 sudog 挂入 `sendq` 休眠。
4. **recv 算法顺序**：抢锁 → 若 `sendq` 非空（有发送方在等），无 buf 时直接取发送方值、有 buf 且满时从 buf 首取走一个并把 sendq 队首的值补到 buf 尾 → 否则若 buf 有数据读 buf → 否则挂入 `recvq` 休眠。
5. **优先级含义**：「对向等待队列优先于 buf」保证早阻塞的协程先被服务（FIFO 公平），也是无缓冲 handoff 的实现路径；buf 中数据停留时间比 sendq 更长（源于 609 结构卡的四路径）。

## 关键代码
```go
// 无缓冲：同步 rendezvous，双方必须同时就绪
done := make(chan struct{}) // 无缓冲
go func() { done <- struct{}{} }()
<-done // handoff，双方交接后同时继续

// 有缓冲：异步，buf 未满即返回
ch := make(chan int, 2)
ch <- 1 // 入 buf，不阻塞
ch <- 2 // 入 buf，不阻塞
// ch <- 3 // 此时 buf 满，阻塞直到有人接收
```

## 总结与追问预判
核心：**无缓冲同步 rendezvous、有缓冲异步解耦；收发算法 recvq/sendq 优先于 buf**。追问拐向「hchan 四路径」——备好「handoff / 写 buf / 挂队 gopark / 关闭唤醒」（见 609.md`）；或拐向「channel 并发安全靠锁」（见 609.md`）。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文 send/recv 算法描述「先判 recvq 空否→直接交接 / 写 buf / 挂 sendq」与 runtime 实现一致；本卡补入「recv 遇 sendq 非空时从 buf 首取走、并把 sendq 队首值补到 buf 尾」这一易漏分支（609 结构卡未展开）。
