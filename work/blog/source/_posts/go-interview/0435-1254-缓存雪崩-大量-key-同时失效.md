> 原文锚点：第 13~24 段「大量 key 同一时刻过期或缓存集群宕机，请求全打 DB；用过期抖动 / 多级缓存 / 熔断降级 / 热点永不过期规避」

## 一句话总述
**缓存雪崩** = **大量 key 在同一时刻同时过期**（或缓存服务整体宕机），瞬时请求全部穿透到数据库，DB 被压垮甚至 cascading 故障。解法：**过期时间加随机抖动**（错峰失效）、**多级缓存**（本地+Redis 兜底）、**熔断/限流/降级**（DB 超负荷时拒部分请求）、**热点 key 永不过期 + 后台刷新**。

## 面试官视角
- 考察意图：能否区分雪崩（集体失效）与穿透（查不存在）、击穿（单热点失效），并给工程化解法。
- 分档：P5 知雪崩=大量同时失效打 DB；P6 知过期抖动 + 多级缓存；P7 知熔断降级 + 热点永不过期 + "集群宕机"也要算雪崩。
- 红旗：把雪崩等同于"单 key 失效"（那是击穿）；或只说加集群不提过期错峰。
- 惊艳点：点出"**缓存集群整体宕机**也算雪崩"，故要多实例+高可用；以及"热点 key 永不过期、靠后台异步刷新，从源头消除失效瞬间"。

## 主问答
**Q（面试官原话）：** 缓存雪崩怎么防止？
**A：**
1. **过期时间随机抖动**：给 key 的 TTL 加随机值（如 base + rand(0,300s)），让失效时间**错峰**，避免集体过期把 DB 瞬间冲垮 `[经验]`。
2. **多级缓存**：本地缓存（Caffeine/进程内）+ Redis 双层；Redis 挂了本地还能兜底一部分，削峰。
3. **熔断/限流/降级**：DB 压力大时，对查询做限流、对非核心接口降级（返回默认/旧值），保护 DB 不被打死。
4. **热点 key 永不过期 + 后台刷新**：极热点 key 不设过期，由后台任务异步更新值，消除"失效那一瞬"的穿透。

## 关键代码
```go
// 过期时间加随机抖动，错峰失效，防雪崩
base := 30 * time.Minute
jitter := time.Duration(rand.Intn(300)) * time.Second
rdb.Set(ctx, key, val, base+jitter)

// 热点 key：永不过期，后台定时刷新值
rdb.Set(ctx, hotKey, val, 0) // TTL=0 永不过期
go func() { // 后台刷新
    for t := range tick.C {
        rdb.Set(ctx, hotKey, loadFromDB(), 0)
        _ = t
    }
}()
```

## 总结与追问预判
雪崩是"集体失效/集群挂"，核心是"错峰 + 兜底 + 保护 DB"。另两兄弟——穿透（查不存在，见 1254）、击穿（单热点失效，见 1254）。秒杀高可用视角见 196。
