## 思路与架构
```text
字面量体系分层：
- 基础字面量：整数(0b/0o/0x/十进制)、浮点(含10为底指数)、虚数(+i)、rune(单引号/八进制/十六进制/ASCII/Unicode)、字符串(双引号/反引号)、函数(func 关键字+签名)。
- 组合字面量：仅结构体/数组/切片/映射，语法 Type{elements}，其中元素可带键(结构体字段名/数组下标)或不带。
- 零值边界：切片/映射零值=nil，组合字面量必给非空容器；结构体/数组零值可用组合字面量(空字段)表达；指针/通道/接口无字面量形式。

记忆模型：能"直接写出来"的只有值类型聚合与基础量；需要"创建动作"(new/make/赋值)的没有字面量。
```

## 方案取舍
```text
- 结构体带字段名 vs 按位置：带名字段顺序无关、可缺省、可读性好，优先；按位置更短但脆弱（改字段顺序即错）。
- 数组 [... ] 推导 vs 显式长度：推导免数数、改元素不报错长度；显式长度自文档化、可越界检查。
- []T{} 非 nil 空 vs var s []T nil：需要"可安全 append/range"用前者；需要"表示不存在"语义用后者(如避免 JSON 输出 [] vs null)。
- new(T) vs &T{}：等价都给指向零值的指针；&T{} 可同时赋初值更灵活。
```

## 答题技巧
```text
- 被问"哪些能用组合字面量"：先抛四类(结/数/切/映)，立刻补"指/通/接不能"，再补"切/映零值 nil 不能被字面量表"——三层递进显深度。
- 必背 nil 对比：[]int{} 非 nil、var m map 是 nil、向 nil map 写 panic。
- 收尾举反例：map 没有 nil 字面量、接口没有字面量，逼出"字面量是值的文字写法"的本质定义。
```

## 细节与核心 API

```go
type Point struct{ X, Y int }
p1 := Point{1, 2}            // 按顺序（unkeyed）
p2 := Point{X: 1, Y: 2}     // 按字段名（keyed，推荐）
// Go 1.17+：跨包字面量禁止 unkeyed，强制 keyed 以防字段顺序变更踩坑
// ps := external.T{1, 2}   // 跨包编译错误
// 复合字面量可取地址，等价于创建匿名变量
pp := &Point{X: 1}
// map 字面量
m := map[string]int{"a": 1, "b": 2}
// 空标识 _ 占位忽略字段（仅适用于数组/结构体按位置）
_ = p1; _ = p2; _ = pp; _ = m
```
