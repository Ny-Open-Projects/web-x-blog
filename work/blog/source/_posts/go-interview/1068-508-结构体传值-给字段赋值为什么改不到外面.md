> 分类：Go 语言基础 | 难度：L2 | 题型：原理题 | 频率：中高 | 关键词：**结构体副本、字段赋值、直接部分、string 不可变**

> 原文锚点：第 65~74 段「person 有 name 和 age 字段…改变没有间接部分的值，不会影响结构体值」

## 一句话总述
函数拿到的是结构体的**整份副本**，给它重新赋 `Name`/`Age` 这类字段，改的是副本里的那一格内存，调用方的结构体纹丝不动。

## 面试官视角
考点是把"值传递"落到实处。能说出"形参 = 调用方结构体按字段拷贝出的新变量"即达标；加分项是主动区分两种改动：**给字段重新赋值**（改自己的格子，无影响）与**改字段指向的底层数据**（共享，有影响）。红旗：把"改字段没生效"记成特殊规则，其实它只是值传递的必然结果。

## 主问答
**Q（面试官原话）：** 函数里改了结构体参数的字段，外面为什么没变？

1. **结论**：调用时整个结构体被**按字段拷贝**一份给形参，函数里改的是副本字段，与调用方是两块内存。
2. **机制**：`Name string` 字段本身是个头部（指针 + 长度），属于结构体的直接部分；`ps.Name = "x"` 是**覆盖副本头部里的指针**，让副本指向新字符串，调用方的头部没被碰过。
3. **边界**：即使字段含指针，只要做的是"给字段赋值"而不是"改它指向的内容"，就一定影响不到外面。
4. **安全性**：字符串字段因此永远安全——底层字节虽被共享，但 Go 的 string 不可变，没有任何路径能让副本改动调用方看到的字节 `[源码]`。

## 关键代码
```go
type Person struct {
    Name string
    Age  int
}

func changeStruct1(p Person) {
    p.Name = "changed"  // 改副本字段，调用方看不到
    p.Age = 99
}

func main() {
    p := Person{Name: "go", Age: 1}
    changeStruct1(p)
    fmt.Println(p)  // {go 1} —— 与原文实测输出一致
}
```

## 总结与追问预判
关键区分：**给字段赋值 → 只动副本；改字段指向的底层数据 → 共享可见**。下一问通常是"那字段换成切片呢"（见 508）。
