> 分类：Redis | 难度：L3 | 题型：原理题 | 频率：中 | 关键词：**复制偏移量**/**REPLCONF ACK**/**心跳检测**/**slave-serve-stale-data**/**repl-timeout**

> 原文锚点：第 60~74 段「偏移量判定一致性」、第 38~47 段「全量期间是否服务与超时」

## 一句话总述
主从节点各自维护**复制偏移量**：主节点写完把命令字节数累加进自己的偏移量，从节点接收后累加自己的偏移量并**每秒上报**给主节点；主节点据此判断从节点是否落后并补发增量，同时兼作存活心跳。全量期间从节点是否继续服务由配置项决定，复制超时默认 60 秒。

## 面试官视角
考官想听「Redis 怎么知道从库落后了多少」。能说出偏移量是**按字节累加**、上报命令是 `REPLCONF ACK`，并且知道偏移量差是补发增量的触发条件，这题就到位了。

## 主问答
**Q（面试官原话）：** Redis 怎么判断主从数据是否一致？

1. **双方各自记账**：参与复制的主从节点都会维护自身的复制偏移量，主节点处理完写命令后把命令的**字节长度**做累加记录。
2. **主侧指标**：主节点写入偏移量可在 `INFO replication` 的主库偏移量指标中查看。
3. **从侧上报**：从节点接收到命令后同样累加自身偏移量，并**每秒上报**自己的复制偏移量给主节点，主节点因此也保存了各从节点的偏移量。
4. **双重作用**：上报既用于**心跳检测**判断从节点是否存活，也让主节点据此判断从节点是否丢数据。
5. **落后即补发**：一旦检测到从节点偏移量与主节点写入偏移量存在差距，主节点就把差距之后的全部增量数据发给从节点，从而恢复一致。

## 关键代码
```go
// Go 侧视角：巡检时算出主从偏移量差值，超过阈值就告警
package main

import (
	"fmt"
	"os/exec"
	"strconv"
	"strings"
)

func field(out, key string) int {
	for _, l := range strings.Split(out, "\n") {
		if strings.HasPrefix(l, key) {
			v, _ := strconv.Atoi(strings.TrimSpace(strings.TrimPrefix(l, key)))
			return v
		}
	}
	return 0
}

func main() {
	b, _ := exec.Command("redis-cli", "INFO", "replication").CombinedOutput()
	s := string(b)
	lag := field(s, "master_repl_offset:") - field(s, "slave_repl_offset:")
	fmt.Println("主从偏移量差值(字节):", lag)
}
```

## 总结与追问预判
核心：**按字节累加 + 每秒上报 + 差值补发 + 兼作心跳**。追问常拐向「全量期间从库读到旧数据怎么办」，备好「由配置项决定是否继续服务，设为否则返回同步中提示」这条。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称「从节点每秒钟上报自身的复制偏移量」——对应命令为 `REPLCONF ACK <offset>`，本卡补出命令名，面试中说出命令名是加分项。
2. 事实核校： [经验] 原文称全量复制超时「默认 60 秒，可通过参数配置」——数值正确；需补充该参数同时用于判定主/从两侧的超时，调得过小会在大流量或慢网络下频繁触发全量重来。
3. 崩坏词归一：源码将 Redis / 复制偏移量 / 心跳 等音译为多组崩坏词，本卡统一为规范术语。
