> 原文锚点：第 1~62 段「Linux 进程管理全节」

## 思路与架构
进程管理这条线按「**类型 → 状态机 → 僵尸/孤儿 → 查看工具 → 后台运行**」五层串：
- 类型层：守护进程（与终端无关、系统引导起）vs 前台进程（终端相关）。
- 状态机层：运行/就绪/睡眠（可中断/不可中断/停止）三态 + 僵尸态（对应 `187-process-states.md`）。
- 异常层：僵尸（父未 wait、占资源）vs 孤儿（父先死、init 收养无害）（对应 `187-zombie-orphan.md`）。
- 实操层：关终端仍跑的 nohup/exec/screen 三法与 Docker PID1 优雅关闭（对应 `187-background-nohup-exec-screen.md`）。
- 边界层：本卡是 **OS/Linux fundamentals**，与 Go runtime 的「goroutine / OS 线程(M) / 调度」属不同层面（见 `813-*`/`814-*`/`815-*` 调度卡），面试别把「进程状态机」和「goroutine 状态」混为一谈。

## 方案取舍
- **状态机给 process-states 卡**：重点画三态转换与不可中断态成因。
- **对比给 zombie-orphan 卡**：强调「都归 init、但僵尸占资源」。
- **实操给 background 卡**：落脚 Docker PID1 优雅关闭，是生产最常踩的点。
- **不碰 Go 调度**：goroutine 的 Grunnable/Gwaiting 等与进程三态概念相似但机制不同，交给 runtime 专题，本卡只在边界声明点一句。

## 答题技巧
1. 开场分两类：守护 vs 前台进程。
2. 接着状态机：运行/就绪/睡眠三态 + 僵尸，画转换。
3. 抛异常对比：僵尸 vs 孤儿，都归 init 但后果相反。
4. 收尾实操：nohup/exec/screen 区别，重点 Docker 用 exec 收信号优雅关闭。
5. 边界话术：**「这是 OS 进程管理，goroutine 调度是另一层」**——避免被追问时把两层概念搅在一起。

## 细节与核心 API

```bash
ps aux | grep app            # 看进程状态/CPU/内存
ps -eo pid,ppid,stat,comm    # stat: R 运行 S 睡眠 D 不可中断 T 停止 Z 僵尸
top -p <PID> -H              # 线程视图；-H 看 LWP
kill -TERM <PID>             # SIGTERM 优雅终止（进程应捕获清理）
kill -9 <PID>                # SIGKILL 强杀（不可捕获，慎用于卡死/僵尸的父进程）
pkill -f "app --mode"        # 按命令行匹配杀
nohup cmd &                  # 忽略 SIGHUP，退出终端仍运行（输出追到 nohup.out）
# 僵尸进程：子进程退出父未 wait，占 PID；杀父（或重启父）才回收
# 状态 D（不可中断睡眠）：通常等 IO（磁盘/网络），kill -9 无效，需解决底层 IO
# 容器：ps 看的是宿主机命名空间，容器内用 docker exec/kubectl exec 进容器看
```
