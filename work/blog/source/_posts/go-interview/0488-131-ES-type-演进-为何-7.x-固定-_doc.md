> 原文锚点：第 59~87 段「低版本一索引多 type…6.x 起一索引仅一个 type（可自定义）…7.x type 固定为 _doc…多 type 导致同索引字段冗余、映射冲突、数据稀疏、查询复杂」

## 一句话总述
ES 早期一个索引支持多个 type（类比库下表）；6.x 起一个索引只允许一个 type（可自定义）；7.x 把 type 固定为 `_doc`。废弃多 type 是因为同索引共享 Lucene 数据结构，导致字段冗余、映射冲突、数据稀疏、查询变复杂。

## 面试官视角
P6 知道 7.x type 固定 _doc；P7 要讲清「多 type 为何被弃」——同索引多 type 共享字段结构，A 表加字段会泄漏到 B 表，且同名异类型字段直接映射冲突。

## 主问答
**Q（面试官原话）：** ES 的 type 是什么？为什么高版本不支持多 type？

1. **type 是逻辑分类**：早期一个索引下可有多个 type，类比库里的多张表 `[源码]`。
2. **演进**：6.x 起一索引仅一个 type（可自定义名）；7.x 固定为 `_doc`，不可改 `[源码]`。
3. **字段冗余**：同索引多 type 共享 Lucene 结构，A 加的字段会分配给 B，造成冗余 `[源码]`。
4. **映射冲突**：不同类型同名字段若类型不同（如 int vs string）无法直接共存，报错 `[源码]`。
5. **稀疏与复杂**：多类型致数据稀疏、查询聚合需处理多结构，性能与维护变差 `[经验]`。
