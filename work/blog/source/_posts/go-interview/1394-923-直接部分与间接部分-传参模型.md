> 分类：Go 语言基础 | 难度：L2 | 题型：原理题 | 频率：高 | 关键词：**直接部分**/**间接部分**/**值拷贝**
> 原文锚点：第 38~44 段「直接直部和间接直部的概念…直接直部的拷贝」

## 一句话总述
Go 的**赋值与函数传参都只拷贝"直接部分"**；若值含有"间接部分"（如底层数组指针、map 的 hmap 指针），拷贝后**直接部分各自独立、间接部分被共享**——这是切片/map 传参表现差异的统一根源。

## 面试官视角
- 考察意图：是否真正理解 Go "一切传值"的本质，而非死记"切片是引用"。
- 分档：P5 知"Go 都是值传递"；P6 能说出直接部分/间接部分；P7 能用它解释切片 vs map 的差异。
- 红旗答案：说"map 是引用传递、切片是值传递"这种半对半错的话。
- 惊艳点：用"直接部分独立 + 间接部分共享"一句话统一切片改元素反映、map 改键值反映、append 换地址三种现象 `[经验]`。

## 主问答
**Q（面试官原话）：** 你刚说切片传参是值传递，那为什么改元素又能影响外面？
**A：**
1. **结论**：Go 只有值传递——拷贝的是"直接部分"；切片/map 的直接部分里含一个**指向底层数据的指针（间接部分）**，所以拷贝后双方共享底层数据。
2. **机制**：切片 header = (ptr, len, cap)，其中 ptr 指向底层数组；map header 含指向 hmap 的指针。**直接部分**（header 本身）拷贝后互不影响，**间接部分**（底层数组/hmap）仍被双方引用。
3. **边界**：正因直接部分独立，函数内"重新赋值"改变的是自己的 header 指针，不影响外层；但"通过指针改底层内容"双方都看得见。

**加分层：** 同理适用于 string、chan、func、指针——凡是 header 含指针的类型，都遵循"直接部分独立、间接部分共享"。

## 关键代码
```go
type sliceHeader struct {
    ptr *byte // 间接部分：指向底层数组
    len int   // 直接部分
    cap int   // 直接部分
}
// 传参时拷贝整个 header：ptr 相同(共享底层)、len/cap 各一份(独立)
// 故：改 *ptr 内容 → 双方可见；改 header.len → 只影响自己
```

## 总结与追问预判
"一切传值、拷贝直接部分、共享间接部分"是理解切片/map 传参的钥匙。追问接"切片传参改元素/append"与"map 传参改键值"。

## ⚠️ 原文纠错
1. 机翻崩坏词归一：`直接直部`/`直接值部`/`直接值步`→**直接部分**；`间接直部`→**间接部分**；`过入`→**goroutine**；`构`→**Go**。核心概念"直接部分/间接部分"原文表述正确，仅叠词崩坏，本卡已归一 `[经验]`。
2. 原文"赋值和函数传参都是直接部分的拷贝"——准确，是 Go 语义的精确描述，本卡据此展开。
