> 分类：设计模式/创建型 | 难度：L3 | 题型：对比题 | 频率：高 | 关键词：**简单工厂** / **工厂方法** / **抽象工厂** / **演进关系** / **Go 惯用法**
> 原文锚点：第 1~73 段「工厂模式三种实现：简单工厂（集中 if-else）、工厂方法（每产品一工厂）、抽象工厂（每族一工厂）」

## 一句话总述
三者是创建型模式的递进：简单工厂把分发集中在一处、工厂方法把"建哪个"推迟到子类、抽象工厂一次性产一族；Go 里常退化成 `func() Product` 这类函数工厂，比 Java 继承层级更轻。

## 面试官视角
- 意图：高频对比题，考察候选人能否按"扩展频率 / 是否产品族"两个维度决策。
- P5 能说出三者定义；P6 能讲清演进动机（消除分支→消除具体类依赖→保证族一致）；P7 能指出 Go 用函数类型替代类继承的惯用法。
- 红旗：把简单工厂当工厂方法；给单产品维度硬上抽象工厂。
- 惊艳点：Go 无继承，工厂方法/抽象工厂的"子类决定"在 Go 里就是"不同 factory 结构体实现同一接口"，本质相同。

## 主问答
**Q（面试官原话）：** 简单工厂、工厂方法、抽象工厂有什么区别？怎么选？
**A：**
1. **结论**：简单工厂=一个工厂 if-else 分发（少产品）；工厂方法=每产品一个工厂类，新增产品加工厂（中扩展）；抽象工厂=每产品族一个工厂，保证族一致（多产品成套）。
2. **机制**：演进主线是"把创建逻辑从集中 → 分散到子类/结构体"：简单工厂在工厂内分支，工厂方法让具体工厂决定实例，抽象工厂让工厂决定整族 `[源码]`。
3. **边界**：Go 里三者常写成 `func NewX() Product` 或 `type Factory func() Product`，用一等函数替代类继承；只有 1~2 个具体类型且无扩展预期时，三者都是过度设计，直接构造最清晰 `[经验]`。

## 关键代码
```go
// 示意，未验证：Go 惯用法——用函数类型替代工厂类
type Product interface{ Use() }

type Factory func() Product

func NewA() Product { return &A{} }
func NewB() Product { return &B{} }

var registry = map[string]Factory{"A": NewA, "B": NewB}

func Create(t string) Product {
    if f, ok := registry[t]; ok {
        return f()
    }
    return nil
}
```
