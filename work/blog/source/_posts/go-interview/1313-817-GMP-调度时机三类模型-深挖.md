> 覆盖源 8-17 全文：调度时机按方式分为主动调度（runtime.Gosched，入全局运行队列）、被动调度（休眠/channel/锁/网络 IO/系统调用/GC，不入全局队列）、抢占调度（sysmon 独立 M 不绑 P，10ms 时间片与 syscall 20μs 阈值），以及自旋线程（spinning M）的取舍与 GOMAXPROCS 上限。主卡已给三类结论与可运行示例，本附录做「入不入全局队列背后的状态语义」「为什么 1.14 是个分水岭」「自旋 vs 阻塞的量化取舍」「系统调用场景的三种抢占条件」「答题怎么结构化为满分」五层深挖。

## 思路与架构

```text
调度时机
├─ 主动(Gosched): g→g0, 解绑 g-m, g 入全局运行队列, schedule()
├─ 被动(等事件):  g→g0, 更新状态, 解绑 m, g 挂到"等待结构"(非运行队列)
│     触发源: sleep / channel / mutex / netpoll / syscall / GC
└─ 抢占(sysmon): 独立 M 不绑 P, 周期巡检
      ├─ 运行 >10ms(forcePreemptNS) → 信号异步抢占
      └─ syscall >1 tick(≥20μs) → 触发 retake 判定
           retake 三条件: ① P 本地队列有等待 G ② 无空闲 P 与自旋 M ③ syscall ≥10ms

M 无事可做时的两难: 阻塞休眠(唤醒要切内核/用户态) vs 自旋空转(烧 CPU 但省切换)
→ 取自旋, 但自旋 M 数 ≤ GOMAXPROCS, 其余游离 M 休眠
```

## 方案取舍
- **为什么主动与被动的落点不同**：这背后的分野是**状态语义**——主动让出的 G **仍然是可运行的**，只是自愿排队重来，所以进全局运行队列；被动让出的 G **已经不具备运行条件**（在等 channel、等锁、等 IO），把它塞进运行队列只会让调度器白白捞起又立刻挂起。所以它被挂到**与等待源绑定的结构**上，等事件就绪时由对应的唤醒方（如 channel 的发送方）把它重新标记为可运行。记住这条，**就把"背结论"升级成"懂设计"** [经验]。
- **为什么 Go 1.14 是分水岭**：1.14 之前只有**协作式抢占**——抢占点埋在函数调用时的栈增长检查上。这意味着只要你的代码**一直在算、不调用函数**（`for { i++ }`），就永远走不到检查点，整个 P 被这一个 G 独占。1.14 起引入**基于信号的异步抢占**（向 M 发信号，在信号处理的 asyncPreempt 里保存寄存器并进入调度器），不需要代码配合，死循环也能被抢。代价是要**陷入内核**走一遍信号路径，所以比直接调 `Gosched()` 慢——这就是原文那句"速度比不上"的真实含义 [经验]。
- **自旋 vs 阻塞的量化取舍**：阻塞要经历**用户态→内核态→用户态**的切换与可能的线程调度延迟；自旋则是**纯用户态空转**。当预期等待时间**很短**（下一个 G 马上就来）时，自旋的代价更低；当长时间没事干时，自旋是纯粹的 CPU 浪费。调度器选了「先自旋」的乐观策略，再用 **`GOMAXPROCS` 上限**给浪费封顶——因为一个 P 同时只能绑一个 M，自旋 M 超过 P 的数量毫无意义 [经验]。
- **syscall 场景的三种抢占条件**（retake 判定）：① **P 的本地运行队列里还有等待的 G**（说明有人被这个系统调用饿着，抢了能立刻给别人用）；② **没有空闲的 P 和自旋的 M**（系统已经比较忙，释放 P 才有价值；反之如果资源充裕，抢了也没意义）；③ **系统调用已经超过 10ms**（与时间片同长，说明陷得太久，必须立即抢）。三条是"或"的关系，前两条是机会判断，第三条是兜底 [经验]。
- **两个阈值不要混**：**10ms** 是给**运行中 G 的时间片**（`forcePreemptNS`），**20μs** 是 **syscall 场景 retake 的一个 tick 下限**；一个管"算太久"，一个管"陷太久"，用途不同 [经验]。

## 答题技巧
- 开场就给**三类划分**（主动 / 被动 / 抢占），把总结题答出结构，这比罗列十个触发点更得分 [经验]。
- 一定要咬出那个差异点：**「主动入全局运行队列，被动不入」**——这是面试官用来区分背过和懂了的分水岭 [经验]。
- 被问「1.14 之前怎么办」→ 答「协作式抢占逃得过空循环，所以库作者会在长循环里插 `Gosched()`」，再补「1.14 后靠信号异步抢占」 [经验]。
- 被问「自旋会不会烧 CPU」→ 答「会，所以**上限 GOMAXPROCS**，多余的游离 M 休眠」，一句话把取舍说完 [经验]。
- 主动边界到 `803-*`/`804-*`（GMP 模型与 P/M 绑定）、`808-*`（GC 与写屏障，GC 也是被动调度触发源）、`711-*`/`712-*`（协程池，把并发度显式收敛），构成调度全栈 [边界]。

## 细节与核心 API

```go
// go 关键字：把函数封装成 G，放入当前 P 的本地运行队列（或全局队列），唤醒调度
go func() { work() }()
// 三类调度时机（G 让出/切换 M 的时机）：
//  1) 主动让出：Gosched / channel 阻塞 / select 无就绪 / 调用 runtime 让权
//  2) 被动抢占：sysmon 监测到 G 运行超 10ms（协作式，基于栈标记）
//  3) 系统调用阻塞：G 与 M 解绑，P 转交其他 M 继续跑别的 G（handoff）
// 模型：G（协程）挂在 P（逻辑处理器）上由 M（系统线程）执行；M:P 默认 = GOMAXPROCS
// 观察：GOMAXPROCS(4) 限制并行 M 数；大量 syscall 会临时突破（需新 M）
```
