> 分类：并发模型 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**close** / **零值** / **ok**

> 原文锚点：第 3~7 段「关闭的通道不能再关、重复 close 会 panic；读关闭通道得零值…」

## 一句话总述
关闭态 channel 有四条稳定特性：不可再关、向它写会 panic、读它得零值且第二返回值 `ok==false`、for-range 读完即退出。一句话背法：**「关闭态 channel 四条：不可再关、向它写panic、读得零值ok=false、for-range读完退出；写/关会panic，读安全」**。

## 面试官视角
这是考察"是否把 close 后的读写行为当常识掌握"的题。
- **P5**：知道写 panic / 读安全。
- **P6**：能说清四条尤其是 ok 信号。
- **P7**：知道用 ok 或 for-range 做退出判定。
- **红旗**：以为读关闭 channel 也 panic；以为 close 后还能再写。
- **惊艳点**：读已关闭 channel 不会 panic，只是反复得零值且 `ok=false` `[源码]` 语言规范。

## 主问答
**Q（面试官原话）：** 关了的 channel 还能读吗？读完会怎样？

**先铺垫（由浅入深第 1 层）**：close 之后 channel 进入"关闭态"，这个状态下四种行为是被语言规范钉死的。最常考的混淆点是"读关闭 channel 安不安全"——答案是安全，只有写和再关才 panic。

1. **结论（第 2 层·机制）**：已关闭 channel 可继续读，不会 panic，只是取零值，第二返回值 `ok` 变 `false` `[源码]`。
2. **机制（第 3 层）**：close 置关闭态；接收端见关闭态即返回零值+false，for-range 在读完缓冲后自动退出 `[源码]`。
3. **边界（第 4 层）**：向已关闭 channel **发送**才会 panic；close 后再 close 也 panic——读是安全的，写/关不是 `[源码]`。
4. **四条（第 5 层）**：① 不可再关（重复 close panic）；② 向它写 panic；③ 读得零值且 ok=false；④ for-range 读完即退出 `[源码]` 语言规范。
5. **退出判定（第 6 层）**：退出读取循环优先用 `for range ch` 或 `v, ok := <-ch`，别自己猜是否还有值 `[经验]`。

| 维度 | 说明 |

## 关键代码
```go
package main

import "fmt"

func main() {
	ch := make(chan int, 1)
	ch <- 7
	close(ch)
	v, ok := <-ch // 缓冲里还有值：v=7, ok=true
	fmt.Println("first:", v, ok)
	v, ok = <-ch // 已空且关闭：v=0, ok=false
	fmt.Println("second:", v, ok)
	// 向已关闭 channel 写会 panic（仅说明，不执行）：
	// ch <- 1 // panic: send on closed channel
}
```

## 总结与追问预判
**背这三句就够**：① **关闭态读安全（零值+ok=false）**；② **写/再关会 panic**；③ **for-range 读完自动退出**。
**预判追问**：
- 「怎么安全退出读取循环？」→ for-range 或 v,ok := <-ch（见 1021 安全退出读取循环）。
- 「重复关闭？」→ panic（见 1019 重复关闭与向已关闭写）。
- 「谁负责关？」→ 单发送者关、多发送者用 stop 协调（见 1021 关闭责任）。
