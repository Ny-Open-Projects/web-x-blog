> 分类：Go 语言基础 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**append**/**共享底层**/**覆盖原数据**
> 原文锚点：第 16~22 段「截取后 append 会覆盖原切片…s3 追加 0 占用 s1[2]」

## 一句话总述
对"截取得到的切片"直接 `append`，若 **cap 足够不扩容**，新元素会**写回共享底层数组的原位置**，从而**覆盖/串扰原切片**的数据——这是切片截取最隐蔽的陷阱。

## 面试官视角
- 考察意图：是否理解 append 的"原地写 vs 换地址"取决于 cap 是否充足。
- 分档：P5 知 append 可能改原切片；P6 知"cap 够则原地覆盖"；P7 能讲清为何会覆盖、如何避免。
- 红旗答案：以为"只要 append 到子切片就一定不影响原切片"。
- 惊艳点：指出 **append 是否影响原切片，完全由 cap 是否触发扩容决定** `[经验]`。

## 主问答
**Q（面试官原话）：** 截取后再 append，为什么会改到原切片？
**A：**
1. **结论**：共享底层 + cap 充足 → append 原地写 → 覆盖原切片对应位置。
2. **机制**：`s3 := s1[0:2]`（共享 s1 前三格），`append(s3, 0)` 时 cap 还够 → 0 直接写入 s1[2] 的位置，于是 s1[2] 原值被覆盖。
3. **边界**：只要 append 触发**扩容**（分配新数组、换 ptr），就不会覆盖原切片（见 1110 / 1110-append-clone）。所以"是否串扰"看的是有没有扩容，不是"有没有 append"。

**加分层：** 真实坑：`res := src[:0]; res = append(res, x)` 会把 x 写进 src 开头，污染原数据——用三元表达式或显式克隆规避。

## 关键代码
```go
s1 := []int{0, 1, 2, 3}
s3 := s1[0:2]        // len=2, cap=4，共享底层
s3 = append(s3, 0)   // cap 够，不扩容 → 写入 s1[2]
fmt.Println(s1[2])   // 0（原值 2 被覆盖）
```

## 总结与追问预判
append 是否串扰原切片，看 cap 是否触发扩容。避免方法：三元表达式限 cap 或显式克隆。追问接"三元切片表达式"与"copy/append 克隆"。
