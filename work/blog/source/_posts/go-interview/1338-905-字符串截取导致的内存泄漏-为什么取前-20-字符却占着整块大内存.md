> 分类：Go 基础 / string | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**字符串截取、共享起始地址、内存泄漏、Reactor、strings.Builder、扩容**

> 原文锚点：第 26~43 段「我们对这个字符串 s 进行了截取，这里直接取了它前二十个字符，我们可以看到字符串在截取之后，它们指向的起始地址其实是同一个。那这种截取就很容易导致内存泄露。因为这个字符串 s 它所申请的空间是非常大的，而这里面我们只取了前二十个字符。那如果这个 s 在不使用的情况下，这个 s 的空间它是一直都不会被回收的…如果我们传的是一，它直接会将这个原始的字符串 return 回去，所以它们指向的地址是一样的。那如果我们传进来的参数大于一呢，它这里就会使用 strings.Builder 预分配空间的方式对字符串进行重复，在不断的重复过程中，这个字符串的空间会进行扩容，所以它的地址会发生改变」

## 一句话总述
对字符串做**截取**时，**截取后的结果引用了原始字符串的地址**——**两者指向的起始地址其实是同一个**；于是**切片（子串）会持有原始字符串的内存**，**即使不再需要这个子串，原始字符串的内存也无法释放**，造成泄漏。典型场景：**一个超大字符串只取前 20 个字符**，只要子串还活着，那块大内存就一直不会被回收。

## 面试官视角
- 考察意图：能否识别"**只取一小段却拖着整块大内存**"这类隐蔽泄漏，以及它在实际业务（如读大文件、大响应体取前几字节）中的表现。
- 分档：P5 知道有这回事；P6 能说"截取共享底层、不清释放"；P7 能讲清**泄漏的完整链条**（截取 → 引用原串地址 → 原串不可回收），并能解释 **`strings.Repeat` 参数为 1 与大于 1 时地址为何不同**。
- 红旗答案：以为"取 20 个字符就只占 20 个字符的内存"。
- 惊艳点：**`strings.Repeat(s, 1)` 与原串地址相同，`Repeat(s, 2)` 地址就变了**——前者源码**直接把原始字符串 return 回去**，后者走 **`strings.Builder` 预分配并扩容**，扩容必然导致地址改变 `[源码]`。

## 主问答
**Q（面试官原话）：** 从一个大字符串里截取一小段，为什么会导致内存泄漏？

1. **结论**：**截取后的字符串引用了原始字符串的地址**，导致**无法及时释放原始字符串的引用、原始字符串无法被垃圾回收**；**切片会持有原始字符串的内存，即使不再需要这个切片，原始字符串的内存也无法释放**，从而造成内存泄漏 `[源码]`。
2. **地址证据**：对一个很长的字符串 `s` **取前二十个字符**，可以看到**截取之后，新字符串与原始字符串 `s` 指向的起始地址其实是同一个** `[源码]`。
3. **泄漏链条**：**因为这个字符串 `s` 所申请的空间是非常大的，而我们只取了前二十个字符**；**如果这个子串还在被使用，那原本 `s` 的那块空间就一直都不会被回收** `[源码]`。
4. **放大场景**：**当有很多不同的字符串，对超长的字符串进行截取的时候，就很容易导致内存泄漏** `[源码]`。
5. **什么时候不会发生**：关键在于**是否生成了新的字符串**——只要发生了**数据拷贝**，地址就会改变，也就脱离了原始大内存。判断依据就是**看地址是否改变** `[源码]`。
6. **对照 · `strings.Repeat`**：
   - **重复 1 次**：**得到的字符串地址与原来的地址一样**——因为**源码里如果传的是一，它会直接把这个原始的字符串 return 回去**，所以**指向的地址是一样的** `[源码]`。
   - **重复大于 1 次**：**重复之后与原始字符串的地址就不一样了**——因为**源码里参数大于一时，会使用 `strings.Builder` 预分配空间的方式进行重复**，**在不断重复的过程中这个字符串的空间会进行扩容**，**所以它的地址会发生改变** `[源码]`。

**加分层：** 判据一句话——**"地址没变 = 还连着大内存；地址变了 = 已经拷出独立副本"**。面试里用这个判据去分析任何字符串操作，都能立刻判断会不会泄漏。

## 关键代码
```go
package main

import (
	"fmt"
	"strings"
	"unsafe"
)

func addr(s string) uintptr { return uintptr(unsafe.Pointer(unsafe.StringData(s))) }

func main() {
	// 模拟"超大字符串"：例如一次读进内存的大报文 / 大文件
	big := strings.Repeat("X", 1<<20)

	// 1) 截取：只取前 20 个字符，但起始地址与 big 相同 -> 整块 1MB 都被钉住
	sub := big[:20]
	fmt.Println("big addr:", addr(big))
	fmt.Println("sub addr:", addr(sub))
	fmt.Println("截取后是否共享底层:", addr(big) == addr(sub)) // true -> 泄漏风险

	// 2) 只要 big 不再被任何其他变量引用，即使 big 本身置零，sub 仍钉着整块
	//    big = ""   // 不会释放那 1MB，因为 sub 还引用着

	// 3) strings.Repeat 的对照：参数为 1 时不拷贝，>1 时走 Builder 扩容
	r1 := strings.Repeat(big, 1)
	fmt.Println("Repeat x1 地址是否相同:", addr(r1) == addr(big)) // true
	r2 := strings.Repeat(big, 2)
	fmt.Println("Repeat x2 地址是否相同:", addr(r2) == addr(big)) // false，发生扩容拷贝

	// 4) 需要长期持有子串时，必须强制脱离
	sub = strings.Clone(big[:20]) // Go 1.18+
	fmt.Println("Clone 后是否仍共享:", addr(sub) == addr(big)) // false -> 安全
}
```

## 总结与追问预判
**最爱追问的是"什么时候必须处理"**——判据是**生命周期**：如果子串要被**长期保存**（进缓存、放进 struct、跨请求传递），而原串很大，就必须切断；如果只是**函数内短暂使用、随栈一起消失**，通常不必特意处理。常见真实场景是**读大文件/大响应体后取前若干字节做校验或日志**，这条经验我建议背下来。具体的三种切断写法见 905。

## ⚠️ 原文纠错
1. 事实核校：截取后子串与原始字符串共享起始地址、子串持有原串内存导致原串无法回收、超大串只取少量字符会导致整块不释放、多子串截取同一超长串时泄漏更明显、判断是否安全看是否发生拷贝、`Repeat` 参数为 1 时源码直接返回原串故地址相同、参数大于 1 时走 `strings.Builder` 预分配并扩容故地址改变——均与 Go 标准库实现一致 `[经验]`。
2. 补充：本节所说的"切片会持有原始字符串的内存"，准确表述是**子串的 data 指针指向原串底层字节数组的某个偏移，整个底层数组因可达而无法回收**；现代 Go 首选的切断方式是 **`strings.Clone`（Go 1.18+）** `[经验]`。
3. 崩坏词归一：源码将字符串、截取、字节切片、strings.Builder、扩容、垃圾回收等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
