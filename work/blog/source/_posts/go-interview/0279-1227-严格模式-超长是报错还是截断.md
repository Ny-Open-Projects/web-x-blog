> 分类：MySQL / 数据类型 | 难度：L2 | 题型：场景题 | 频率：中高 | 关键词：**sql_mode、严格模式、截断、STRICT_TRANS_TABLES**

> 原文锚点：第 12~19 段「取决于 sql_mode 的配置…严格模式下直接报错」

## 一句话总述
写入超过字段长度的数据会报错还是被截断，取决于 **sql_mode 是否为严格模式**；严格模式下直接报错，非严格模式才静默截断。

## 面试官视角
P6 答"会截断"；P7 要先问**版本与模式**：只要 sql_mode 含 STRICT_TRANS_TABLES 或 STRICT_ALL_TABLES 即为严格模式，`[源码]`。加分点：MySQL 8.0 默认就是严格模式，所以线上大多数情况是直接报错而非截断 `[经验]`。

## 主问答
**Q（面试官原话）：** 插入超长的字符串会怎样？

1. **先看模式配置**：结果取决于 sql_mode 的取值，不是固定行为 `[源码]`。
2. **严格模式直接报错**：sql_mode 含 STRICT_TRANS_TABLES 或 STRICT_ALL_TABLES 时即为严格模式 `[经验]`。
3. **非严格才截断**：不在严格模式下，超出部分被截断后写入，不报错 `[源码]`。
4. **8.0 默认严格**：原文实测在该版本下默认即为严格模式，因此插入超长直接报错 `[实测]`。

| 结论成立版本 | 翻转点 | 现在该怎么答 |

| 非严格配置 | 行为回退 | 静默截断，有数据风险 |

## 关键代码
```sql
SELECT @@sql_mode;                       -- 查看当前模式
SET SESSION sql_mode = 'STRICT_TRANS_TABLES';
INSERT INTO user6 (name) VALUES ('abc'); -- name 为 CHAR(2)，严格模式报错
```
> 验证：严格模式下报数据过长错误；去掉严格项后写入成功但值被截断为两位 `[实测]`。

## 总结与追问预判
**先问模式再答行为**。这是数据一致性面试里的高频陷阱。

## ⚠️ 原文纠错
1. 事实核校：原文"严格模式下报错、否则截断，8.0 默认严格"准确；补充——严格模式自 5.7 起即为默认，不只是 8.0，本卡补全版本线 `[经验]`。
2. 补充：原文"两个中文字符可插入 CHAR(2)"正确——长度约束按**字符数**而非字节数，本卡与字符集卡联动说明 `[源码]`。
3. 崩坏词归一：源码将 MySQL、模式、字段、截断等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
