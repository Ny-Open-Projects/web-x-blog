> 分类：Go 语言基础 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**结构体传参、值拷贝、指针接收者、逃逸分析、copylocks**

> 原文锚点：第 1~13 段「函数的参数传递只有值传递，实参都是原始数据的一份拷贝」

## 一句话总述
Go **只有值传递**：传结构体拷整个结构体，传指针只拷一个地址。选值还是指针**先看语义**（要不要改调用方），再看成本与逃逸。

## 面试官视角
这题考判断力而非语法。P5 只会答"大的传指针"；P6 能给出**语义→成本→不可拷贝字段**三层判据；P7 会补"指针形参常把实参推到堆上、抬高 GC 压力，小结构体传值反而更快"。红旗：说"传指针就是引用传递"——传指针拷的依旧是指针这个值 `[经验]`。

## 主问答
**Q（面试官原话）：** 调用函数传入结构体时，是传值还是传指针？

1. **先澄清前提**：两种写法**都是值传递**，区别只在被拷贝的是什么——传值拷结构体本身，传指针拷指针变量的值。
2. **第一判据·语义**：要让函数改动调用方的结构体 → 传 `*T`；只读场景传值天然隔离副作用，更安全。
3. **第二判据·成本**：只有几个机器字的小结构体传值与传指针开销接近，且传值**不逃逸**、省一次堆分配；字段多或含大数组时才明显划算。
4. **第三判据·正确性**：含 `sync.Mutex`、`sync.WaitGroup` 的结构体**只能传指针**，拷贝会把锁状态一并复制，可能直接死锁，`go vet` 的 `copylocks` 会拦截 `[源码]`。
5. **一致性**：同类型的接收者不要值/指针混用，否则 `T` 与 `*T` 方法集不同，某些接口会静默不满足。

## 版本与兼容性

## 关键代码
```go
type User struct {
    mu   sync.Mutex   // 含锁字段：结构体不可拷贝
    Name string
    Age  int
}

func renameByValue(u User) { u.Name = "new" }  // 改副本，调用方无感
func renameByPtr(u *User)  { u.Name = "new" }  // 改到调用方的对象

func main() {
    u := User{Name: "old"}
    renameByValue(u)  // u.Name 仍是 "old"
    renameByPtr(&u)   // u.Name 变为 "new"
}
```

## 总结与追问预判
一句话：**语义决定要不要指针，成本决定是否值得，含锁字段一票否决**。追问会接"为什么改切片元素能影响到外面"（见 508）。

## ⚠️ 原文纠错
1. 事实核校：原文"只有切片、map、chan、func 属于引用类型"流传广但不严谨——Go 规范从未定义"引用类型"，这些变量本身同样是值，只是内部含指针；按"值传递 + 直接/间接部分"描述才不出错 `[经验]`。
2. 事实核校：原文"传指针即引用传递"不成立，传指针拷的仍是指针变量的值，形参重新赋值不影响调用方 `[经验]`。
3. 崩坏词归一：源码将 Go、new、结构体等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
