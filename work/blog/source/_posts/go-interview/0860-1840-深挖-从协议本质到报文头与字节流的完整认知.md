> 原文锚点：第 1~83 段「TCP 是一种面向连接的可靠的，并且是基于字节流的传输层协议…通过确认应答超时重传错误检测和校验等机制确保可靠性…通过滑动窗口机制来实现流量控制…用户的消息通过 TCP 协议传输的时候，消息就可能会被操作系统分组成多个 TCP 报文，接收方的程序如果不知道消息的边界，它是无法读出一个有效的用户消息的…TCP 报文头通常为二十字节，可以通过添加选项字段将它扩展到最大六十个字节」

## 思路与架构

按「**概念 → 特性 → 语义 → 报文**」四层建立 TCP 的完整认知：

1. **概念层：什么是协议**。协议是参与者之间约定的行为规范。理解它有五个维度——规范约定（数据格式、传输方式、处理过程）、交互过程（起止时机、角色行为、请求应答型/发布订阅型）、规则与算法（包格式、错误检测与纠正）、分层结构（TCP/IP 中 TCP 管可靠传输、IP 管寻址路由）、标准化（保证互操作性）。TCP 即**面向连接的、可靠的、基于字节流的传输层协议**。
2. **特性层：七条特性及机制**。可靠（确认应答、超时重传、错误检测、校验）、面向连接（三次握手/四次挥手）、流量控制（滑动窗口，依据**接收方能力**）、拥塞控制（降速与重传，依据**网络状况**）、有序传输、全双工、易于实现（操作系统内置）。
3. **语义层：字节流意味着什么**。消息会被分组成多个报文，**协议不保留消息边界**，因此接收方必须自己界定一条消息（长度前缀/分隔符/定长）；同时 TCP 保证**按序交付**（前序未到不交付给应用层）与**重复报文自动丢弃**。
4. **报文层：首部如何支撑上述能力**。首部 20~60 字节；序列号（32 位，随机初始值）解决**乱序**，确认应答号（32 位，期望收到的下一序号）解决**丢包**，数据偏移（4 比特，单位 4 字节，取值 5~15）定位首部长度，窗口大小（16 位）支撑流量控制，校验和（16 位）做差错检测，六个控制标志位（URG/ACK/PSH/RST/SYN/FIN）表达连接状态与传输语义，选项字段（4 字节对齐）承载 MSS、窗口扩大、时间戳等扩展。

## 方案取舍

| 关注点 | 机制 | 解决什么 | 代价 |
|---|---|---|---|
| 丢包 | 确认应答 + 超时重传 | 数据可达 | 重传带来延迟 |
| 乱序 | 序列号 | 按序重组 | 需缓存乱序段 |
| 重复 | 序列号去重 | 不重复交付 | 需维护接收窗口 |
| 收不下 | 滑动窗口（流量控制） | 匹配接收方能力 | 窗口受 16 位限制 |
| 网络堵 | 拥塞控制（降速 + 重传） | 保护网络 | 牺牲吞吐 |
| 边界 | **应用层自定协议** | 还原消息 | 增加协议复杂度 |
| 差错 | 校验和 | 检测损坏 | 不能纠正错误 |

取舍要点：**TCP 解决的是「字节可靠按序送达」，不是「消息完整送达」**。消息边界是应用层的责任，这是设计上的职责划分，不是缺陷——理解这一点，粘包问题就不再是玄学。

## 答题技巧

1. **先给定义再展开**：开口说「面向连接、可靠、基于字节流的传输层协议」，再逐条展开，结构最稳。
2. **把机制与问题配对**：序列号→乱序、确认号→丢包、窗口→流控、校验和→差错，配对记忆不易混淆。
3. **主动区分流控与拥塞控制**：前者看**接收方窗口**，后者看**网络状况**，这是高频追问点。
4. **必背换算**：数据偏移 × 4 = 首部字节数（5→20，15→60）；选项必须 4 字节对齐。
5. **字节流题要给出解法**：只说「会粘包」不够，必须给出**长度前缀 + io.ReadFull** 这类落地方案。
6. **止步档位**：能讲清特性与字节流语义即达 L4；能完整说出首部字段位数与作用、六标志位语义及 ACK 例外规则，即达 L5。

## 细节与核心 API

```go
import "encoding/binary"
// 以太网帧：14B 头(MAC dst/src/etype) + IP 包 + FCS
// IPv4 头（20B）：版本/IHL/总长/标识/标志/片偏移/TTL/协议/校验和/源IP/目的IP
// TCP 头（20B+）：源端口/目的端口/序号/确认号/窗口/标志(URG/ACK/PSH/RST/SYN/FIN)/校验和
// 抓包看原始字节：tcpdump -X 'tcp port 80'
// 用 Go 解析 TCP 头示例（简化）
func parseTCP(b []byte) (sport, dport uint16) {
    sport = binary.BigEndian.Uint16(b[0:2])
    dport = binary.BigEndian.Uint16(b[2:4])
    return
}
// 关键认知：网络是“字节流”，无消息边界；TCP 分段/粘包需应用层自定边界（长度前缀/分隔符）
// 字节序：网络一律大端（BigEndian），x86 主机小端，读写要转换
```
