> 分类：Go 并发 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**无缓冲**/**rendezvous**/**同步**
> 原文锚点：第 21~70 段「无缓冲 channel 也叫同步 channel…同一协程读写会死锁」

## 一句话总述
无缓冲 channel 容量为零，发送与接收必须**同时就绪（rendezvous 直接交接）**，任一方未就绪就阻塞；同一协程内既发又收必然死锁。

## 面试官视角
- 考察意图：是否真懂"无缓冲=同步交接"的阻塞本质，而非背"同步 channel"四个字。
- 分档：P5 知无缓冲会阻塞；P6 懂 rendezvous 与死锁条件；P7 能区分"死锁 panic"与"永久挂起"。
- 红旗答案：说无缓冲"能存一个数据"；认为无缓冲比有缓冲快。
- 惊艳点：**无缓冲发送方与接收方直接 handoff，缓冲区不暂存**；所以延迟更低但要求并发双方同时在线 `[源码]`。

## 主问答
**Q（面试官原话）：** 无缓冲 channel 为什么叫同步 channel？
**A：**
1. **结论**：无缓冲 channel 的发送和接收是**同步操作**——必须发送方和接收方同时就绪才能完成一次交接，否则阻塞。
2. **机制**：底层 `hchan` 缓冲区长度为 0，发送时若没有就绪的接收者就直接把发送 goroutine 挂到 `sendq` 等待，值通过**直接交接（handoff）**传给接收方，不在缓冲区停留 `[源码]`。
3. **边界**：同一协程内对无缓冲 channel 先写后读（或先读后写）必然死锁——写时无人收、读时无人发，该协程自锁；只有跨协程并发收发才正常。

**加分层：** 无缓冲天然实现"信号/同步"语义（如 `done <- struct{}{}` 通知），比用 `time.Sleep` 精确。

## 关键代码
```go
func main() {
    ch := make(chan int) // 无缓冲
    go func() { ch <- 1 }() // 并发发送
    fmt.Println(<-ch)       // 并发接收，正常完成
    // 若把 <-ch 写在同一个 goroutine 的发送之前 → fatal error: deadlock
}
```

## 总结与追问预判
无缓冲=同步交接+必须并发双方在线；死锁源于自锁。追问接"有缓冲为何能同协程暂存"。

## ⚠️ 原文纠错
1. 原文"不带缓冲区的 channel **只能存储一个数据**，取出来才能存下一个"不精确：无缓冲 channel **容量为零**，发送方与接收方是**直接交接（handoff）**，缓冲区不暂存任何数据；"只能存一个"易误解成"缓冲区能放一个"，实为放零个、纯交接 `[源码]`。
