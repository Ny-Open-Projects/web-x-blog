> 分类：Go 基础 / 数组 | 难度：L3 | 题型：排错题 | 频率：中 | 关键词：**nil 指针、空指针、panic、取址、数组初始化**

> 原文锚点：第 49~59 段「我们对这个 nil 的数组进行填充值，它就会报一个空指针异常…在 main.go 的第 42 行出现了空指针，指针类型的数组是不能直接使用的…我们需要先声明一个数组，再把它的地址赋值给 arr5」

## 一句话总述
`var p *[N]T` 声明的指针数组是 nil，未指向任何数组实体，直接对其赋值会触发 nil 指针 panic；正确做法是先有一个真实数组，再把它的地址赋给该指针。

## 面试官视角
P6 知道「nil 不能直接用」；P7 要能**一眼定位 panic 行**并说出修复的两条路径（`p = &a` 或 `p = new([N]T)`），同时讲清这是**编译期不报错、运行期才炸**的典型，属于上线风险点。

## 主问答
**Q（面试官原话）：** 这段代码为什么会 panic？怎么修？

```go
var arr5 *[10]int
arr5[0] = 1
```

1. **根因**：`var arr5 *[10]int` 只声明了指针变量，其零值是 **nil**，并未分配任何数组实体 `[源码]`。
2. **触发点**：`arr5[0] = 1` 会先对 nil 指针解引用再写入，运行期抛出 **nil 指针异常** `[源码]`。
3. **特征**：这类错误**编译期不报错**，只有执行到该行才崩，是典型的上线风险 `[经验]`。
4. **修法一**：先声明一个真实数组，再取址赋值——`a := [10]int{}; arr5 = &a` `[源码]`。
5. **修法二**：直接用 `arr5 = new([10]int)`，new 会分配并清零内存 `[源码]`。
6. **定位方法**：panic 信息会给出文件名与行号（原文示例中为第 42 行），据此即可定位到赋值语句 `[源码]`。

## 关键代码
```go
package main

import "fmt"

func main() {
	var arr5 *[3]int // nil 指针，尚未分配
	// arr5[0] = 1 // panic: runtime error: invalid memory address or nil pointer dereference

	// 修法一：先有实体数组，再取址
	a := [3]int{}
	arr5 = &a
	arr5[0] = 1

	// 修法二：new 直接分配并清零
	arr6 := new([3]int)
	arr6[1] = 2

	fmt.Println(*arr5, *arr6) // [1 0 0] [0 2 0]
}
```

## 总结与追问预判
**指针类型必须「先有实体再有地址」**。面试官常顺带追问「nil 切片为什么 append 却没事」——因为 append 的内置实现会在底层数组为空时自动分配，而数组下标写入没有任何兜底。对比见同批 414-slice-nil-vs-map。

## ⚠️ 原文纠错
1. 事实核校：var 指针数组为 nil、直接赋值 panic、修法为取址或 new、panic 信息含行号——均与 Go 规范一致 `[经验]`。
2. 补充：原文提到「指针类型的数组零值是 nil」属正确表述；但要区分「数组元素是指针」（`[N]*T`，数组本身可用，元素为 nil）与「指向数组的指针」（`*[N]T`，本身为 nil）——本卡讨论的是后者 `[经验]`。
3. 崩坏词归一：源码将数组、指针、空指针异常、赋值等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
