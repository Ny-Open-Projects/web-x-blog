> 覆盖源 17-6 后半「链表实现队列」：单链表队列的入队出队姿势、源码版 O(n) 走尾入队的隐患、尾指针演进、与数组队列/环形缓冲/标准库的选型账本。主卡已给数组队列主线与截取泄漏坑，本附录做链表侧与选型深挖。

## 思路与架构

```text
队列实现的演进链 (每步修上一步的死法)
├─ 数组 copy 前移
│   └─ 无泄漏, 但出队 O(n): [实测] n=10 万次入出队 1.37s
├─ 单链表 走尾入队 (源码版)
│   ├─ 出队 O(1): 弹 root.next
│   └─ 入队 O(n): for 循环走到尾
│       [实测] n=10 万: 9.02s, 比 O(1) 版慢 1055 倍
├─ 单链表 head+tail 双指针 (演进点)
│   ├─ 入队 O(1): tail.next=新节点; tail=新节点
│   ├─ 出队 O(1): 取 head, head=head.next
│   └─ [实测] n=10 万: 8.5ms
└─ 环形缓冲 (ring buffer)
    └─ 数组 + head/tail 下标取模: 零分配, 高吞吐首选
```

## 方案取舍
- **源码版走尾入队是最大暗坑**：源文入队「for 循环走到链表尾部再挂新节点」，每入队一个扫全表，入队退化为 O(n)。修法极简——**多存一个 tail 指针**，入队直接挂尾、tail 后移，O(1) 封顶。[实测]（go1.26.5，n=100000 次入队+出队）：走尾版 9.02s，尾指针版 8.5ms，**差 1055 倍**；「加一个字段换一个数量级」是链表队列面试的核心得分点 [实测]。
- **链表 vs 数组的队列选型账本**：链表 O(1) 入出但**每节点一次堆分配 + 两个指针开销**（16B/节点，缓存不友好）；数组连续内存但朴素实现总有 O(n) 半边（copy 前移出队 O(n)）。两头都要——**环形缓冲**用固定数组 + head/tail 下标取模，入出队均 O(1) 且零分配，`channel` 底层 hchan 缓冲正是环形队列（见 109.md` 的 channel 语义）。标准库 `container/list` 是双向链表，做队列反而多付 prev 指针成本 [经验]。
- **并发队列的层次**：主卡用 `sync.Mutex` 包「结构体级互斥」最简单；高并发下锁竞争集中在头尾，可演进为**两把锁**（head 锁/tail 锁分离，Michael-Scott 队列雏形）；Go 工程里更常见的是直接用 **channel**——带缓冲 channel 就是一个现成的线程安全队列，手写链表队列的价值在面试展示原理而非生产复用 [经验]。
- **空队列边界三态**：head==nil（空）、head==tail（仅一个）、出入队后 tail 必须回补（出队到空时 **tail 也要置 nil**，否则悬垂指向已弹节点，再入队会接到废链上）。单链表队列的 bug 九成出在 tail 回补这一步 [经验]。

## 答题技巧
- 先答「栈 FILO 队列 FIFO 一个只动头一个头尾都动」的点题，再给数组版与链表版两种实现——「一题两解」结构完整 [源码]。
- 主动报实测数字：「朴素走尾入队和尾指针版差 **1055 倍**」——把演进链的必要性钉死，比背复杂度符号有说服力 [实测]。
- 被问「生产里用什么」→ 环形缓冲/channel，别死磕手写链表；被问「channel 底层是什么队列」→ 环形缓冲，顺势勾连并发专题 [经验]。
- 主动边界到 `173-array-stack`/`173-linkedlist-stack`（栈的对称实现）、`173-stack-select`（数组栈链表栈选型）、`175-reverse-stack-queue`（两栈模拟队列的翻转技巧）、`1848-queue-buffer-loss`（channel 缓冲丢失问题），构成「线性结构实现」专题 [边界]。

## 细节与核心 API

```go
// 演进1：仅靠头指针，入队 O(n)（要走到尾）
// 演进2：加尾指针，入队 O(1)，出队 O(1)
type Queue struct { head, tail *Node }
type Node struct { Val int; Next *Node }
func (q *Queue) Enqueue(v int) {
    n := &Node{Val: v}
    if q.tail == nil { q.head = n } else { q.tail.Next = n }
    q.tail = n
}
func (q *Queue) Dequeue() (int, bool) {
    if q.head == nil { return 0, false }
    v := q.head.Val; q.head = q.head.Next
    if q.head == nil { q.tail = nil } // 队列空时尾指针也要归零
    return v, true
}
// 关键边界：出队后若 head 为空必须同步 tail=nil，否则尾指针悬空导致下次 Enqueue 错乱
// 环形数组实现更省内存、缓存友好（生产常用）
```
