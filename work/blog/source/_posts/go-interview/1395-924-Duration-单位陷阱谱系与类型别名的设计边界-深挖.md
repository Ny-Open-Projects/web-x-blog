> 覆盖源 9-24 全文：Duration 别名「为什么是纳秒」「为什么不做成带单位的结构体」的深层取舍、单位混算事故的完整谱系（毫秒/秒/纳秒三域互串）、类型别名 vs 定义类型的语言层差异、单调时钟与墙钟的分野。主卡已给事故复现与两种修正，本附录做设计取舍与谱系四层深挖。

## 思路与架构

```text
时间运算的三域地图 (事故 = 跨域裸加)
├─ 墙钟域: UnixMilli/UnixNano 时间戳 (int64, 单位自选)
│   └─ 风险: 回拨(补丁/校时), 只适合打日志/对外展示
├─ Duration 域: 固定纳秒的 int64 别名
│   └─ 安全规则: 只与 Duration 运算, 进出经 time.Time 中转
├─ 单调钟域: time.Now 内置单调分量, Sub/Add 走它
│   └─ 计时/超时必须用这里, 免疫 NTP 跳变
└─ 事故模式: 任意两域的 int64 直接 + - (编译器全程沉默)
    └─ 防线: 类型语义标注 + 显式中转 + code review 单位审查
```

## 方案取舍
- **为什么是纳秒、为什么是别名而不是结构体**：① **零开销穿透**——int64 可以直接进 runtime 定时器、atomic 原子读写、channel 传递、做 map key，结构体全都不行或要额外同步；② **与操作系统接口对齐**（Go 诞生于 C 生态，timespec 即纳秒）；③ 精度足够——64 位纳秒上限约 292 年，覆盖一切合理间隔。别名（`type Duration int64`）是**定义类型**而非真别名（`=` 别名），代价是 `Duration` 与 `int64` 不能隐式互转——这恰好把「忘记 `.Seconds()` 换算」的错误拦下一半 [源码]。
- **但「单位标注」防不住「域混算」**：`type Duration int64` 能阻止 `Duration + int64` 直接相加（编译报 mismatched types），**却防不住 `int64(ts) + int64(500*time.Millisecond)`**——一旦某处显式转回 int64，类型系统就彻底失明。这是本事故的根源：**类型安全在显式转换处结束**。工程防线只有两条：① 域内运算（毫秒域只在毫秒域内加）；② 域间必经 `time.UnixMilli/UnixNano` 显式中转，中转函数名里就带着单位 [经验]。
- **事故谱系：三域互串的六种组合**：毫秒戳+纳秒 Duration（本案，×10^6 错）、秒戳+毫秒（×10^3）、纳秒戳当毫秒用（÷10^6）、`time.Second` 当秒数 int 用（1 变 10 亿纳秒）……共同特征是**两边都是 int64、编译器全绿**。code review 里「时间量运算必查单位」应作为硬性检查项；更工程化的解法是封装 `type Milli int64` 这类带单位的领域类型，让不同单位**类型上不可加** [经验]。
- **墙钟 vs 单调钟是第二重坑**：`UnixMilli` 取自墙钟，NTP 校时/人工改时间会**回拨**——用它做超时计算可能「永远等不到」。Go 的 `time.Now()` 返回值内含**单调时钟分量**，`Sub/Add/Since` 优先走单调钟，免疫回拨；但 `Unix*` 系列、序列化、跨进程传时间都会丢单调分量退化成墙钟。**计时时长用 time.Since，打时间戳给人才用 UnixMilli**，这条分界要成为肌肉记忆 [经验]。
- **修正二为什么是推荐写法**：`time.UnixMilli(ts).Add(500*time.Millisecond).UnixMilli()` 看似绕，实则把「进入时间域 → 运算 → 退出」全程交给标准库，**单位换算零手写**；修正一（`ts+500`）在简单场景没错，但裸数字 500 的单位靠注释活着，注释一失真就是下一个事故。工程判断：**逻辑简单且域单一用修正一，跨域或复杂用修正二** [经验]。

## 细节与核心 API

```go
// time.Duration 底层是 int64，单位纳秒；time.Sleep(3) 是 3 纳秒不是 3 秒！
time.Sleep(3 * time.Second)  // 正确
time.Sleep(time.Duration(3)) // 错误：3 纳秒
// 类型别名（type X = Y）与类型定义（type X Y）区别：
type Celsius = float64       // 别名：与 float64 完全等价，可混用
type Meter float64           // 定义：是新类型，不能和 float64 直接运算
var c Celsius = 36.5
var f float64 = c            // 别名 OK
// 别名不产生新方法集；自定义类型可挂方法、可做类型安全边界
// 设计边界：用定义类型表达“单位/语义”，用别名仅做兼容性/重命名
```
