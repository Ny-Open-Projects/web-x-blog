> 原文锚点：第 38~50 段「先通过 viper.New 初始化一个 viper 的配置对象…调用 ReadInConfig 读取配置文件…再调用 Unmarshal 把配置项映射进结构体」

## 一句话总述
Viper 是 Go 生态里读取本地配置的事实标准库，流程是「初始化对象 → 设路径与类型 → ReadInConfig 读取 → Unmarshal 映射到结构体」，结构体字段靠 mapstructure 标签与配置项一一对应。

## 面试官视角
P5 能写出加载四步；P6 要讲清相对路径是「执行命令的目录」而非文件所在目录；P7 能指出 mapstructure 标签与 yaml 标签的兼容性差异，以及结构体字段必须和配置项同名。

## 主问答
**Q（面试官原话）：** Viper 怎么把配置文件读进 Go 结构体？

1. **初始化对象**：`v := viper.New()` 拿到独立实例，避免污染全局单例 `[源码]`。
2. **设路径与类型**：`SetConfigFile("config.yaml")` 给定路径；若文件名无后缀再 `SetConfigType("yaml")`，支持 yaml/toml/json 等 `[源码]`。
3. **读取**：`v.ReadInConfig()` 按路径加载，失败时应当 panic 或返回错误，不能静默继续 `[源码]`。
4. **映射**：`v.Unmarshal(&cfg)` 把配置项填进结构体；字段靠 `mapstructure` 标签与配置键对应 `[源码]`。
5. **相对路径陷阱**：路径相对「执行 main 的当前目录」，不是 main.go 所在目录；在子目录执行时前缀会变 `[经验]`。

## 关键代码
```go
v := viper.New()
v.SetConfigFile("config/config.yaml") // 相对执行目录
if err := v.ReadInConfig(); err != nil {
    panic(err) // 读不到配置应立刻失败，别静默
}
var cfg Config
v.Unmarshal(&cfg) // 按 mapstructure 标签填充
```

## ⚠️ 原文纠错
1. 事实核校：Viper 加载四步（New→SetConfigFile→ReadInConfig→Unmarshal）与相对路径语义准确，无误 `[经验]`。
2. 补充：原文强调「配置出错应抛 panic」，生产中更稳妥的是返回 error 由调用方决定降级，panic 仅适合启动期硬失败 `[经验]`。
