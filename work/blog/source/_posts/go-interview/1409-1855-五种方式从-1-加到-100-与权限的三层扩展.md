> 版本口径：macOS 14.5（BSD 工具链）实测；Linux/GNU 差异逐条标注。**setfacl/getfacl/chattr/lsattr 在 macOS 上不存在**，相应条目标 `[本机不可测，Linux 口径]`。sticky 与 /tmp 的 1777 见 1854。

## 一句话总述
求和题考的是「**把计算交给谁**」——shell 自己算（`while` + `$(( ))`）、`bc` 算（把序列粘成算式管道喂它）、`awk` 算（`BEGIN` 里带 `while`），五法本质是三类「计算器」；权限题考的是「普通 `rwx` 不够用时，还有**三层扩展**」——**ACL** 给单个用户单独授权、**sticky 位**保护共享目录（`/tmp` 的 1777）、**不可变/只追加**防篡改，每层都有 Linux 与 macOS 两套命令。最值钱的实测坑：`seq -s + 1 100 | bc` 在 macOS 直接 `Parse error`——**BSD seq 的 `-s` 是「终止符」**（末尾多一个 `+` 且无换行），跨平台正解是 `paste -sd+ -`。

## 面试官视角
- 考察意图：求和题探测「算式从哪来」的机制理解（不是背五种写法）；权限题探测你有没有处理过共享目录、防篡改这类真实运维需求，以及跨平台意识。
- 分档：P5 能写出一种求和一种授权；P6 说清五法归三类 + 三层扩展的两套命令；P7 能报出 BSD `seq -s` 终止符语义、ACL「覆盖不叠加」的行为。
- 红旗答案：把 `seq -s + | bc` 当跨平台写法；认为 ACL 是「在 other 权限上再叠加」。
- 惊艳点：能讲清「sticky 位为什么落在 others 的 x 位上」和「进目录需要 `x`、ACL 按匹配结果判定不再叠加」这两个机制点 [实测]。

## 主问答
**Q（面试官原话）：** 用命令行算 1 加到 100，几种方法？文件权限除了 rwx 还有什么扩展手段？
**A：**
1. **求和五法归三类**：①shell 自己算——`while [ "$i" -le 100 ]; do s=$((s+i)); done`（`[` 是命令，方括号两边必须有空格）；②`bc` 算——`echo {1..100} | tr ' ' '+' | bc`（花括号展开空格分隔，`tr` 只换空格、保留末尾换行，天然合法）；`seq 1 100 | tr '\n' '+' | sed 's/+$//' | bc`（seq 按行输出，要剪掉末尾多出的 `+`）；③`awk` 算——`awk 'BEGIN{i=1;s=0;while(i<=100){s+=i;i++}print s}'`（`BEGIN` 段无输入行也执行，awk 的 while 是类 C 语法）。**最稳的是 awk BEGIN**：不依赖外部命令、没有平台坑 [实测]。
2. **seq -s 的平台坑（本卡核心）**：GNU seq 的 `-s` 是「分隔符」且末尾补换行；**BSD/macOS seq 的 `-s` 是「终止符」**——最后一个数字后面也跟它、且整个输出没有换行，算式变成 `1+2+…+100+`，bc 直接 `Parse error: bad expression`。修法：`sed 's/+$//'` 剪掉，或改用 `paste -sd+ -`（跨平台一致）[实测]。
3. **权限三层扩展**：①**ACL**——给单个用户单独授权，不动 other；Linux `setfacl -m u:l1:rw` / `getfacl`，macOS 没有这两个命令，用 `chmod +a "user allow read,write"` / `ls -le`（`ls -l` 权限位后会出现 `+` 提示）[实测 macOS 侧]；②**sticky 位**——目录可写但只有文件属主/root 能删文件，`chmod +t`，`drwxrwxrwt` 末位 `t`；③**不可变/只追加**——连 root 都要先去掉标志才能改，Linux `chattr +i/+a` / `lsattr`，macOS `chflags uchg/uappnd` / `ls -lO` [实测 macOS 侧]。
4. **ACL 是「覆盖」不是「叠加」**：一旦设置 ACL，就**按 ACL 的匹配结果判定**，不再「在 other 权限上再加一点」——源文有个现场：给目录只加了「写」ACL，结果用户连目录都进不去，因为**进入目录需要 `x`**，ACL 里没给 `x` 就没有 [源码]。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| GNU seq / BSD seq | `-s` 分隔符 vs 终止符语义 | 跨平台用 `paste -sd+ -` 或先 `sed 's/+$//'` [实测] |
| Linux ACL 工具 | `setfacl`/`getfacl` macOS 不存在 | macOS 等价 `chmod +a` / `ls -le` [实测] |
| ext 文件系统属性 | `chattr +i/+a` 依赖文件系统 | XFS/Btrfs 支持有限或语义不同；macOS 用 `chflags` [实测] |
| sticky 位 | 仅对目录生效（现代 Linux） | 设在文件上无意义；`/tmp`=1777 即此意 |
| noclobber `set -C` | shell 级选项，非文件系统权限 | 只拦当前 shell 的 `>`；`>>` 追加不受限，`>|` 强制覆盖 |

## 关键代码
```bash
#!/usr/bin/env bash
# sum100-perm.sh —— 求和五法与权限扩展手段的可复现实现
set -u

echo "===== A. 五种方式从 1 加到 100 ====="
# 法一：while + shell 算术展开
i=1; s=0
while [ "$i" -le 100 ]; do s=$((s+i)); i=$((i+1)); done
echo "  法一(while):        $s"

# 法二：bash 花括号展开 → tr 把空格换成加号 → 交给 bc（末尾换行天然合法，不用剪）
echo "  法二(brace+tr+bc):  $(echo {1..100} | tr ' ' '+' | bc)"

# 法三：seq 生成 → tr 把换行换成加号（末尾多一个 + 要剪掉）→ bc
echo "  法三(seq+tr+bc):    $(seq 1 100 | tr '\n' '+' | sed 's/+$//' | bc)"

# 法四：seq -s 直接指定分隔符（⚠ BSD/macOS 的 -s 是「终止符」，末尾多一个 +，必须先剪掉）
echo "  法四(seq -s + bc):  $(seq -s '+' 1 100 | sed 's/+$//' | bc)   # 不剪尾分隔符则 bc 报 Parse error"

# 法五：awk 的 BEGIN 段（无输入行也执行）
echo "  法五(awk BEGIN):    $(awk 'BEGIN{i=1;s=0;while(i<=100){s+=i;i++}print s}')"

echo "===== B. 权限的扩展手段 ====="
D="$(mktemp -d)"
trap 'rm -rf "$D"' EXIT          # 无论怎么退出都清理临时目录

# B1: sticky 位 —— 目录加 t 后，只有「文件属主或 root」能删目录里的文件
mkdir "$D/shared"
echo "  B1 sticky 前: $(ls -ld "$D/shared" | awk '{print $1}')"
chmod +t "$D/shared"
echo "  B1 sticky 后: $(ls -ld "$D/shared" | awk '{print $1}')   # 末位 t = sticky"

# B2: noclobber（set -C）—— 禁止 > 覆盖已存在文件；>> 追加不受影响
f="$D/nc.txt"; echo hello > "$f"
set -C
echo x > "$f" 2>/dev/null || echo "  B2 set -C 下 > 覆盖被拒；>> 追加仍可用: $(echo y >> "$f"; cat "$f" | tr '\n' '/')"
set +C

# B3: macOS 的 ACL 写法（Linux 是 setfacl/getfacl，macOS 没有那两个命令）
chmod +a "everyone allow read,write" "$f" 2>/dev/null \
  && echo "  B3 macOS ACL 加成功，ls -le 可见:" && ls -le "$f" | sed 's/^/       /'

# B4: macOS 的「不可变」写法（Linux 是 chattr +i / lsattr，macOS 用 chflags / ls -lO）
chflags uchg "$f" 2>/dev/null && echo "  B4 chflags uchg 后: $(ls -lO "$f" | awk '{print $1, $5}')   # 第 5 列 = 文件标志位"
echo z >> "$f" 2>/dev/null || echo "  B4 uchg 生效：写入被拒（Operation not permitted）"
chflags nouchg "$f" 2>/dev/null
```

实测输出（macOS 14.5）[实测]：

```text

  法二(brace+tr+bc):  5050
  法三(seq+tr+bc):    5050
  法四(seq -s + bc):  5050   # 不剪尾分隔符则 bc 报 Parse error
  法五(awk BEGIN):    5050
===== B. 权限的扩展手段 =====

  B1 sticky 后: drwxr-xr-t   # 末位 t = sticky
  B2 set -C 下 > 覆盖被拒；>> 追加仍可用: hello/y/
  B3 macOS ACL 加成功，ls -le 可见:
       -rw-r--r--+ ... nc.txt
        0: group:everyone allow read,write

  B4 uchg 生效：写入被拒（Operation not permitted）
```

关键旁证 [实测]：`seq -s + 1 5 | od -c` 末尾为 `+` 且无 `\n`；`seq -s + 1 5 | bc` → `Parse error: bad expression`；`seq 1 5 | paste -sd+ -` → `1+2+3+4+5`；`command -v setfacl getfacl chattr lsattr` 全部不存在（exit=1）。

Linux 侧口径 `[本机不可测，Linux 口径]`：`setfacl -m u:l1:rw file` + `getfacl`、`chattr +i/+a` + `lsattr`、`seq -s + 1 100 | bc` 可直接算（GNU seq 末尾是换行）。

## 总结与追问预判
一句话记忆：**「求和先问计算交给谁，权限扩展三层各两套命令；`seq -s` 是终止符坑」**。追问预判：「ACL 和普通权限冲突谁优先」——按 owner → named user → owning group → named group → mask → other 逐段匹配、命中即停，受 mask 约束，改 ACL 前先 `getfacl`（macOS `ls -le`）看、改完再验。「`chattr +i` 保护的文件 root 能删吗」——能但必须先 `chattr -i`，这正是防误删价值；它是**文件系统层面属性**，`ls -l` 看不出来，换文件系统会失效。noclobber 与重定向的坑见 1813 [边界]。

## ⚠️ 原文纠错
1. `seq -s + 1 100 | bc` 直接算即可——**只在 GNU seq 上成立**；BSD/macOS 的 `-s` 是终止符，末尾多 `+` 且无换行，bc 报 `Parse error` [实测]。
2. 用 `setfacl`/`getfacl` 设置和查看 ACL——那是 **Linux 工具**，macOS 没有，等价物 `chmod +a` / `ls -le` [实测]。
3. 用 `chattr +i/+a`、`lsattr` 设不可变/只追加——**Linux 专有**（ext 系 inode 属性）；macOS 等价 `chflags uchg/uappnd` / `ls -lO` [实测]。
4. 命令名大面积音译：`比根语句`→BEGIN、`蛋/down`→done、`permissiondelight`→Permission denied、`tesetFACL/getFACL`→setfacl/getfacl、`stick/stickaway`→sticky、`set减c/set加c`→`set -C/set +C`，全系语音转写音译错误。
5. awk「BEGIN 在任何输入行被处理之前执行」——**对**；awk 的 `while` 是类 C 语法（无 `do...done`）[实测]。
