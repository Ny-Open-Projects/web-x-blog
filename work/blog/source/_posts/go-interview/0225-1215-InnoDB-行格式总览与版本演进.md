> 原文锚点：第 1~13 段「表空间→段→区→页→行、四种行格式、版本默认演进」

## 一句话总述
InnoDB 表空间由「段(segment) → 区(extent) → 页(page) → 行(row)」逐级构成，行是最终存放数据的单位，行内除字段数据外还有元信息。InnoDB 支持四种行格式：REDUNDANT（冗余）、COMPACT（紧凑）、DYNAMIC（动态）、COMPRESSED（压缩），由 `innodb_default_row_format` 指定默认。版本演进：5.1 前默认 REDUNDANT，5.1 起 COMPACT，**5.7 起默认 DYNAMIC（8.0 仍为 DYNAMIC）**。

## 面试官视角
行格式是「索引底层存储」系列的关键一环。考官看你能不能报出四种格式与版本默认演进，并说清设计目标：COMPACT 让「一页放更多行」以提升性能。能补一句「DYNAMIC 主要改进行溢出处理」就衔接上下了。

## 主问答
**Q（面试官原话）：** InnoDB 有哪些行格式？默认用的是哪个？

1. **层级**：表空间 → 段 → 区 → 页 → 行；行内存放字段数据与元信息。
2. **四种格式**：REDUNDANT（冗余，5.0 前）、COMPACT（紧凑）、DYNAMIC（动态）、COMPRESSED（压缩，额外 zlib 压缩）。
3. **版本默认**：5.1 前 REDUNDANT → 5.1 起 COMPACT → **5.7 起 DYNAMIC（8.0 默认 DYNAMIC）**；由 `innodb_default_row_format` 控制。
4. **设计目标**：COMPACT 的初衷是「让一个数据页存放更多行记录」，页内行数越多、扫描与缓存效率越高。

## 版本与兼容性
| 版本 | 默认行格式 |
|------|------------|
| < 5.1 | REDUNDANT |
| 5.1 ~ 5.6 | COMPACT |
| 5.7 / 8.0 | DYNAMIC |
