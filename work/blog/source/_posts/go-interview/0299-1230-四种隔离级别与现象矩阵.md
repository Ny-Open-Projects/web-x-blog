## 一句话总述
SQL 标准定义四种隔离级别，从低到高为**读未提交 → 读已提交 → 可重复读 → 串行化**：脏读在读已提交被解决，不可重复读在可重复读被解决，幻读理论上限串行化才能杜绝。级别越高并发性能越低，串行化因事务需排队而不建议生产使用。

## 面试官视角
这题必备的是**三行矩阵**。考官会故意问「读未提交能避免什么」，正确答案是「什么都避免不了」。能顺口背出矩阵并指出「不存在只挡幻读却留脏读的级别」，说明你真的理解而不是背串了。

## 主问答
**Q（面试官原话）：** 事务隔离级别有哪些？分别解决什么问题？

1. **读未提交**：一个事务可以看到其它尚未提交事务的修改，脏读、不可重复读、幻读**都会出现**。
2. **读已提交**：只能看到已提交的修改，**避免脏读**，但仍允许不可重复读与幻读。
3. **可重复读**：事务执行过程中看到的数据始终与启动时一致，**避免脏读与不可重复读**；它也是 MySQL InnoDB 的**默认隔离级别**。
4. **串行化**：最高级别，读写冲突时后访问的事务必须等待前一个完成，**三类问题全部避免**。
5. **权衡**：级别越高一致性越好但并发越低；串行化让事务排队、严重影响性能，一般不建议设置。

## 关键代码
```sql
-- 查看与设置当前会话隔离级别（只对后续事务生效）
SELECT @@transaction_isolation;                       -- 8.0+ 变量名
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
START TRANSACTION;
SELECT a FROM t WHERE id = 1;                         -- 只看到已提交的修改
COMMIT;
```

## 总结与追问预判
核心：**矩阵记牢，解决脏读到读已提交、不可重复读到可重复读**。追问常拐向「为什么不用串行化」，备好「事务排队、并发能力丧失」这句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文一处称「在读未提交级别下可以避免不可重复读和幻读，但不能避免脏读」——**错误**，且与同一章另一处「读未提交会出现脏读、不可重复读以及幻读」**自相矛盾**。读未提交是最低级别，三类现象**都会出现**；不存在「挡住幻读却留脏读」的级别，本卡以正确表述为准。
2. 事实核校： [经验] 原文称「隔离级别越高，读的效率就越低」——方向正确，更准确的说法是**并发度下降**（锁与可见性约束增强），单次读本身未必变慢。
3. 崩坏词归一：源码将事务 / 隔离级别 / 串行化 / 幻读 等音译为多组崩坏词，本卡统一为规范术语。
