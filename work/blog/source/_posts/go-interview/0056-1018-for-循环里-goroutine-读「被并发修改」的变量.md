# 1018 for 循环里 goroutine 读"被并发修改"的变量

> 分类：并发模型 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**数据竞争** / **字段级并发** / **只读拷贝** / **sync**

> 原文锚点：第 42~60 段「主循环边改 s2.f3 字段边启 goroutine 读该字段；读到的取值取决于调度时机，属真正的读写数据竞争」

## 一句话总述
比"循环变量捕获"更隐蔽的一类坑：for 循环里**主协程正在修改某变量/字段，同时启动的 goroutine 去读它**——这是读写两端的真数据竞争（非单纯读终值），结果非确定性，必须用同步或只读拷贝隔离。一句话背法：**「for 循环里主协程改、goroutine 读同一字段 = 真数据竞争（未定义行为），修法三选一：传值拷贝 / Mutex / channel」**。

## 面试官视角
这是并发题里的"事故复盘"型。考官要区分你会不会把"读终值不对"和"读写共享变量"两类竞态混为一谈——后者危害更大。
- **P5**：知道这种写法结果不定。
- **P6**：说清这是读写两端的数据竞争。
- **P7**：给出修法（传值拷贝 / 锁 / chan）并用 `go test -race` 验证。
- **红旗**：以为"只是读到旧值"没事；以为不加锁偶尔正确就安全。
- **惊艳点**：指出数据竞争是**未定义行为**——不是"偶尔错"，而是编译器/运行时可任意重排，必须修。

## 主问答
**Q（面试官原话）：** 主循环改一个字段、goroutine 里读它，为什么读到的不对？

**先铺垫（由浅入深第 1 层）**：我们熟悉的"循环变量捕获"bug，是 goroutine 闭包读到循环变量的"终值"；而这里更进一步——主协程**每一轮都在改写**那个字段，goroutine 还去读它，于是变成读写两端同时碰同一块内存，没有任何同步。

1. **结论（第 2 层·机制）**：主协程写、goroutine 读同一块内存且无同步 → 数据竞争（data race），读到的值取决于调度时机，且属**未定义行为** `[源码]`。
2. **机制（第 3 层）**：源中 `s2.f3` 在主循环每轮被赋值、goroutine 通过指针读 `f3`；两端无 happens-before 关系，读可能拿到修改前、修改中或修改后的任意值 `[源码]`。
3. **危害（第 4 层）**：不是"大概率读到对的值"就安全——数据竞争是未定义行为，编译器/CPU 可任意重排，结果不可预测 `[经验]`。
4. **修法（第 5 层·实战）**：三选一——① 传值拷贝（把字段值当参数传，断开心地址共享）；② 用 `sync.Mutex`/`atomic` 保护读写；③ 用 channel 传递值 `[经验]`。
5. **验证（第 6 层·工具）**：`go test -race` 能直接报出这类字段级竞争；上线前用它跑一遍并发路径 `[源码]`。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

type S struct{ F3 int }

func main() {
	const n = 5
	var wg sync.WaitGroup

	// 反例（竞态）：闭包读主循环变量 s2.F3，go test -race 报 data race
	for i := 0; i < n; i++ {
		s2 := S{F3: i}
		wg.Add(1)
		go func() {
			defer wg.Done()
			_ = s2.F3 // 读主循环正在写的内存，结果不确定
		}()
	}
	wg.Wait()

	// 正解：传值拷贝，断开心地址共享（无竞争）
	for i := 0; i < n; i++ {
		s2 := S{F3: i}
		v := s2.F3 // 取出字段做值拷贝
		wg.Add(1)
		go func(f3 int) {
			defer wg.Done()
			fmt.Println("read", f3) // 只读自己的拷贝
		}(v)
	}
	wg.Wait()
}
```

## 总结与追问预判
**背这三句就够**：① **读写同一字段无同步 = 真数据竞争（未定义行为）**；② **不是"偶尔对"就安全，必须修**；③ **修法三选一：传值拷贝 / Mutex / channel，用 -race 验证**。
**预判追问**：
- 「和循环变量捕获有什么区别？」→ 捕获是读终值（读端问题），这是读写同地址（两端竞争），危害更大。
- 「最快的修法？」→ 传值拷贝，零同步开销，断开心地址共享。
- 「怎么在 CI 拦住？」→ `go test -race` 直接报字段级竞争（见 1018 同号卡）。
