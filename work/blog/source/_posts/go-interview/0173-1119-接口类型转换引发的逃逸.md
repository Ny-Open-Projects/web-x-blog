> 分类：Go 编译器 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**interface**/**装箱**/**逃逸分析**
> 原文锚点：第 36~50 段「函数返回值是接口类型且发生类型转换…对象发生逃逸」

## 一句话总述
当具体类型被装进**生命周期超出当前栈帧的接口变量**（如作为返回值、存入全局）时，该值会逃逸到堆；**同栈帧内**的 interface→具体类型转换不一定逃逸。原文把"发生类型转换"当成逃逸充分条件，略粗糙。

## 面试官视角
- 考察意图：是否理解"逃逸真因是值被装箱进更长生命周期的接口"，而非字面上的"类型转换"动作。
- 分档：P5 知"转 interface 容易逃逸"；P6 能区分"返回接口且转换"vs"参数本就是接口"；P7 讲清装箱与栈帧生命周期。
- 红旗答案："只要发生类型转换就逃逸"；"interface 比具体类型慢是因为转换"。
- 惊艳点：**逃逸取决于值是否要活过当前栈帧**，不是转换本身——`string→interface` 不外传未必逃逸 `[源码]`。

## 主问答
**Q（面试官原话）：** 为什么把值转成 interface 就容易逃逸？
**A：**
1. **结论**：逃逸的真因是"值被装进生命周期超出当前栈帧的接口变量"，转换只是常见触发场景，不是充分条件。
2. **机制**：接口值底层是 `(type, data ptr)`；当接口要逃出函数（return/存全局/被取地址），被装的值必须放堆让指针稳定 `[源码]`。
3. **边界**：若转换后的接口只在当前栈帧内使用、不对外暴露，编译器可证明它不逃逸，就留在栈上——原文"f12 参数本就是接口返回接口不逃逸"正是此理。

**加分层：** 返回 `interface{}` 比返回具体类型更易让入参逃逸（调用方拿到装箱值）。

## 关键代码
```go
func f11() interface{} {
    s := "hello" // 具体类型
    return s     // 装箱成 interface{} 且作为返回值 → 逃逸
}
func f12(i interface{}) interface{} {
    return i // 参数本就是接口，无新装箱 → 通常不上堆
}
// go build -gcflags='-m'：f11 中 s "escapes to heap"，f12 无 moved to heap
```

## 总结与追问预判
逃逸的充要条件是"值要活过当前栈帧"，转换只是表象。追问常接"容器元素为接口/指针也逃逸"，下一张卡。

## ⚠️ 原文纠错
1. 原文把"**发生了类型转换**"直接列为逃逸条件，表述过粗：真实充要条件是"被装箱的值生命周期超出当前栈帧"。同帧内 `interface→具体类型` 或 `具体→interface` 若不外传，编译器可判定不逃逸，原文 f13/f12 案例本身也印证了这点，但文字总结却把"转换"当充分条件 `[源码]`。
