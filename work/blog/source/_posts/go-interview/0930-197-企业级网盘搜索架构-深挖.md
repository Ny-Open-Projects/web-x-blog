## 方案取舍
- **文件名 vs 内容索引**：按访问频率、成本、重建代价分离；内容搜索作会员权益，只对活跃付费用户建。
- **大文件隔离**：独立队列/解析/索引服务做背压，防长尾拖垮小文件 SLA；超大文件截断/放弃。
- **全量 vs 懒建**：搜索服务上线晚、非全员用，按用户首次使用懒重建，省海量计算/存储。

## 细节与核心 API

```go
// 架构：文件元数据变更 -> 消息队列 -> 索引服务 -> ES
// 1) 监听文件系统事件（inotify / 对象存储 PUT 事件）拿到新增/改名/删除
// 2) 抽取元数据：文件名、路径、大小、类型、修改时间、内容（文档解析全文）
// 3) 发 MQ（Kafka），削峰 + 解耦索引写入
producer.Publish("file-events", bucket, marshal(Event{Op: "upsert", Meta: meta}))
// 4) 索引消费：bulk 写 ES（见索引建模卡），失败重试 + 死信
// 5) 查询：ES 提供文件名/内容/类型多维检索 + 高亮
// 关键点：最终一致（秒级延迟可接受）；大文件内容抽取异步、限流；删除事件及时从索引移除
// 规模：分索引（按租户/时间）+ 别名滚动；冷热分离（旧文件降副本/冻结）
```
