## 思路与架构


## 方案取舍
- **注册中心摘除 vs 消费者摘除**：纯注册中心在「注册中心-提供者」网络隔离时会误删全部，消费者侧存活探测更稳；生产常两者结合。
- **LB 算法选型**：性能均→轮询/随机；性能异→加权；处理时间不均→最少连接；需会话→源地址哈希。
- **容错 vs 路由**：容错解决「调失败怎么办」，路由解决「该调谁」，分层不混。

## 细节与核心 API

**三层面治理手段：**

```text
① 节点管理(故障摘除)：注册中心主动摘除(心跳超时) vs 消费者侧存活探测(更稳，防注册中心-提供者隔离误删)
② 负载均衡 + 路由：轮询/随机(均) / 加权(异) / 最少连接(处理时间不均) / 源地址哈希(会话)
                      路由规则：机房就近 / 灰度
③ 服务容错：失败通知/自动切换/快速失败 / 失败缓存/熔断/限流/降级（非幂等不无脑重试）
```

**容错 vs 路由不混：容错解决"调失败怎么办"，路由解决"该调谁"。**
