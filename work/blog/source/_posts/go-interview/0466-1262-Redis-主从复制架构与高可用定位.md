> 分类：Redis | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**主从复制**/**读写分离**/**单点故障**/**命令传播**/**容灾**

> 原文锚点：第 1~9 段「持久化不足 / 多副本 / 主从同步机制」

## 一句话总述
持久化只能在宕机后恢复数据，重启与恢复本身仍要时间；要避免单点故障就得把数据复制到多台服务器。Redis 用**主从复制**打底：一主多从，从节点可分担读请求，主节点故障后可由从节点顶上，复制靠主节点把写命令持续发给从节点重放来保持一致。

## 面试官视角
这题的坑是**把主从复制当成高可用本身**。考官等你顺口说「主挂了从自动顶上」——那是否正确取决于有没有哨兵。能主动区分「复制」与「故障转移」两套机制，就是分水岭。

## 主问答
**Q（面试官原话）：** Redis 怎么做高可用？主从复制解决了什么问题？

1. **持久化不够**：宕机后靠持久化能恢复数据，但服务重启与数据恢复都需要时间，期间服务不可用。
2. **多副本才是解法**：把数据备份到其他服务器，让这些服务器也能对外提供服务，一台故障其余仍可服务。
3. **复制靠命令传播**：主节点把所有写命令（如 SET、DEL 等）发送给从节点，从节点执行这些命令来保持数据一致。
4. **支持读写分离**：主节点处理写、可扩展多个从节点分担读请求，从而提升整体吞吐。
5. **具备容灾基础**：主节点故障后，从节点持有完整数据副本，可被提升为主节点继续提供服务。

## 关键代码
```go
// Go 侧视角：巡检时拉取复制状态，判断从节点是否在线、是否落后
package main

import (
	"fmt"
	"os/exec"
	"strings"
)

func main() {
	out, _ := exec.Command("redis-cli", "INFO", "replication").Output()
	for _, l := range strings.Split(string(out), "\n") {
		if strings.Contains(l, "role:") || strings.Contains(l, "connected_slaves:") ||
			strings.Contains(l, "master_link_status:") {
			fmt.Println(l) // master_link_status:down 即表示主从断连
		}
	}
}
```

## 总结与追问预判
核心：**主从复制解决数据冗余与读扩展，不负责自动切换**。追问常拐向「主挂了怎么办」「复制是同步还是异步」，备好「靠哨兵或集群做故障转移」与「异步复制、存在短暂不一致」两句。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称「主节点出现故障时，从节点可以**自动**切换为主节点」——**主从复制本身不具备自动故障转移能力**；复制只负责数据同步，自动切换由哨兵或集群完成，本卡予以澄清。
2. 事实核校： [经验] 原文举例写命令为「set 命令、delete 命令」——Redis 实际命令名为 SET 与 DEL，本卡统一为规范命令名。
3. 崩坏词归一：源码将 Redis / 主从 / 宕机 等音译为多组崩坏词，本卡统一为规范术语。
