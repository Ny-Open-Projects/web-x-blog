> 分类：Go 并发 | 难度：中 | 题型：技巧题 | 频率：中 | 关键词：**WaitGroup 广播、ready 信号、Add(-1)、数据就绪、协程间依赖**

> 原文锚点：第 6~23 段「双 WaitGroup:WG2.Add(1)后协程内 WG2.Wait 阻塞;主调 WG2.Done 广播通知数据就绪协程才继续;Done=Add(-1)等价;用于协程间数据依赖」

## 一句话总述
当协程**依赖其他协程准备好的数据**才能继续时，可用**第二个 WaitGroup 当广播信号**：主协程 `ready.Add(1)`，子协程在 `ready.Wait()` 上阻塞，数据准备好后主协程调 `ready.Done()`（等价 `Add(-1)`）广播通知，子协程才往下执行。这是 WaitGroup 从"计数等待"升华到"条件通知"的妙用。一句话背法：**「双 WG 广播：ready.Wait 阻塞等数据，Done 即 Add(-1) 广播放行」**。

## 面试官视角
考官看你能不能把 WaitGroup 从"计数等待"升华到"条件通知"，理解 `Done` 即 `Add(-1)`。能讲清双 WG 分工、与 channel 通知的取舍，说明你真用过它做协程间协调；用单个 WG 既等退出又等数据导致语义混乱、或不知 Done 等价于 Add(-1)，是红旗。
- **P5**：知道双 WG 广播思路。
- **P6**：知道 `ready.Wait()` 阻塞、`Done()` 唤醒、Done=Add(-1)。
- **P7**：知道它实现的是"数据就绪通知"，能对比 channel 通知的区别与取舍。

## 主问答
**Q（面试官原话）：** 怎么用 WaitGroup 实现"数据准备好再通知协程继续"？

**先铺垫（由浅入深第 1 层）**：WaitGroup 本职是"等 N 个任务做完"。但有时协程不是要等"全部做完"，而是要等"某个前提条件（比如数据准备好了）成立"才继续。这时再加一个 WaitGroup 当"广播原语"，就能把"计数"变成"条件通知"。

1. **双 WG 分工（第 2 层·结构）**：`wg` 负责等所有协程退出，`ready` 充当广播信号——`ready.Add(1)` 后，子协程在 `ready.Wait()` 阻塞。
2. **广播通知（第 3 层·机制）**：主协程准备好数据后调 `ready.Done()`（等价于 `ready.Add(-1)`），阻塞的协程被唤醒、才真正使用数据；实现"数据就绪才继续"。
3. **语义本质（第 4 层）**：这里 WaitGroup 被当成一次性"条件变量"用——不是计数 N 个任务，而是等一个"就绪"事件。
4. **与 channel 对照（第 5 层·取舍）**：同样可用 `close(channel)` 或发信号实现通知；WaitGroup 广播胜在语义直观、无需额外 channel 变量。
5. **误用风险（第 6 层）**：别用单个 WG 既等退出又等数据，两套语义混在一个计数器上会乱；需要两件事就上两个 WG。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg, ready sync.WaitGroup

	// ready 充当"数据就绪"广播信号
	ready.Add(1)
	wg.Add(1)

	go func() {
		defer wg.Done()
		ready.Wait() // 阻塞，直到主协程广播数据就绪
		fmt.Println("worker 拿到就绪数据，开始处理")
	}()

	// 主协程准备数据 ...
	data := "prepared"
	fmt.Println("主协程准备数据:", data)

	ready.Done() // 广播：通知子协程继续（等价 ready.Add(-1)）
	wg.Wait()    // 等子协程退出
}
```

## 总结与追问预判
**背这三句就够**：① **双 WG 分工：一个等退出、一个（ready）当广播信号**；② **子协程 `ready.Wait()` 阻塞，主协程 `ready.Done()`（=Add(-1)）唤醒**；③ **本质是一次性"就绪通知"，比 channel 省变量**。
**预判追问**：
- 「WaitGroup 的 Done 和 Add(-1) 一样吗？」→ 完全等价，Done 就是 Add(-1)（见本卡第 2/3 层）。
- 「跟 channel 通知比有什么优劣？」→ 语义直观、不用额外 channel 变量；channel 则更灵活（可带值）（见本卡第 5 层）。
- 「等待方式怎么选型？」→ 见 1023 主协程等待总览；信号量本职限并发（见 1023 无缓冲 vs 信号量）。
