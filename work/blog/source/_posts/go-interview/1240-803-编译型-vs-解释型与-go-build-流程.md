> 原文锚点：第 1~34 段「go 是编译语言…go build -x/-a/-race 参数含义」

## 一句话总述
Go 是编译型语言：源码经 `compile`→`asm`→`link` 产出二进制；`go build -n` 只打印不执行、`-x` 打印并执行、`-a` 强制重建、`-race` 开竞态检测——原文对这几个标志的语义张冠李戴。

## 面试官视角
- 考察意图：是否真懂编译/解释区别，以及常用构建标志的正确语义。
- 分档：P5 知 Go 需编译；P6 懂 -n/-x/-a/-race 区别；P7 能讲清编译到链接的全过程。
- 红旗答案：把 `-a` 当"只打印不执行"；分不清 `-n` 与 `-x`。
- 惊艳点：**`-n` 才是 dry-run（只打印命令不执行），`-x` 是打印并执行，`-a` 是强制重建所有包** `[源码]`。

## 主问答
**Q（面试官原话）：** Go 为什么是编译型语言？`go build` 常用标志有哪些？
**A：**
1. **结论**：Go 源码必须经编译链接成机器码二进制才能运行；`-n` 只打印命令不执行、`-x` 打印并执行、`-a` 强制重建、`-race` 开竞态检测。
2. **机制**：编译把高级代码翻译成机器指令并打包成二进制；解释型（Python 等）靠解释器逐行执行、错误常运行期才暴露，Go 多数错误编译期即发现 `[源码]`。
3. **边界**：`-a` 的语义是"强制重新构建指定包及其依赖"，**不是** dry-run；dry-run 是 `-n`。原文把 `-n` 的行为错安到 `-a` 上。

**加分层：** `-race` 基于 happens-before 检测数据竞争（多 goroutine 并发访问同一地址、至少一个是写、无同步），支持平台有限但排查并发 bug 必备。

## 关键代码
```bash
go build -n ./...   # 只打印将执行的命令，不真正编译（dry run）
go build -x ./...   # 打印并执行每一条命令
go build -a ./...   # 强制重新构建所有包（含已是最新的）
go build -race ./... # 开启竞态检测器
```

## 总结与追问预判
编译型=编译期查错+高性能；四个构建标志语义要分清。追问接"编译内部经历了哪些阶段"。

1. 原文把 `go build` 标志语义张冠李戴：**`-a` 实为"强制重建所有包"，"只打印不执行"是 `-n` 的语义**；"打印并执行"是 `-x`；原文却把 dry-run 行为错安到 `-a` 上、把 `-x` 写成"杠s"。正确映射：`-n` 只打印不执行 / `-x` 打印并执行 / `-a` 强制重建 / `-race` 竞态检测 `[源码]`。
