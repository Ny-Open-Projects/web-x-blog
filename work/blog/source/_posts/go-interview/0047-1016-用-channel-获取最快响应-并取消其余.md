> 原文锚点：第 33~60 段「异步发 3 请求→结果写容量 1 channel 取最先返回→无缓冲 bool channel close 通知其余取消→实际 HTTP 取消用 context」

## 一句话总述
「取最快响应」是 channel 的另一妙用：异步发起 N 个请求，把结果写进**容量为 1** 的 channel，只有最先返回的 goroutine 能写入、主协程读到即视为最快响应；同时用一个**无缓冲 bool channel**，拿到最快响应后 `close` 它，其余请求在 `select` 中检测到 close 即退出函数释放资源——真实 HTTP 取消须靠 `context` 取消底层请求。一句话背法：**「取最快响应：N 请求写容量1 channel，仅最先返回者写入、主协程读到即最快；close 无缓冲 channel 广播取消其余；真实 HTTP 取消须 context」**。

## 面试官视角
这是考察"能否用容量 1 channel + close 广播实现最快响应与取消"的方案题。
- **P5**：知道容量 1 channel 只留最先结果。
- **P6**：能写 close 广播取消。
- **P7**：知道演示用 channel、真实 HTTP 须 context 取消。
- **红旗**：拿到最快响应后不取消其余请求（浪费资源）；把 channel close 当成真正取消了 HTTP 请求。
- **惊艳点**：点出"close 一个 channel 可被多个接收方同时感知、天然广播语义"，以及"channel 只取消函数、真实网络取消靠 context" `[经验]`。

## 主问答
**Q（面试官原话）：** 多个请求只要最快那个返回的结果，其余怎么处理？

**先铺垫（由浅入深第 1 层）**："竞速取最快"是典型的 fan-out/收敛模式。关键设施是两个 channel：一个容量 1 的结果槽（谁先写谁赢），一个无缓冲的取消信号（用 close 做广播）。

1. **容量 1 channel 取最快（第 2 层·机制）**：异步发 N 请求，完成写容量 1 的 channel，只有最先返回的 goroutine 写成功，主协程读到即最快响应 `[经验]`。
2. **close 广播取消其余（第 3 层）**：另起无缓冲 bool channel，拿到最快响应后 `close` 它；其余请求 `select` 检测到关闭即退出函数、不再占用资源 `[经验]`。
3. **真实 HTTP 用 context（第 4 层）**：演示用 channel 模拟取消；实际 HTTP 请求取消须用 `context` 取消底层连接，而非仅退出业务函数 `[经验]`。
4. **超时（第 5 层）**：配合 `context.WithTimeout` 构成"竞速 + 取消 + 超时"三件套，全部超时返回 `ctx.Err()` `[源码]`。
5. **本质（第 6 层）**：多生产者、单槽 channel、谁先谁赢的竞态收敛；close 的广播语义是无缓冲 channel 的天然能力 `[边界]`。

## 关键代码
```go
package main

import (
	"context"
	"fmt"
	"time"
)

// 模拟 HTTP 请求
func doHTTP(ctx context.Context, u string) (string, error) {
	select {
	case <-time.After(200 * time.Millisecond): // 模拟网络耗时
		return "resp from " + u, nil
	case <-ctx.Done():
		return "", ctx.Err()
	}
}

// 取最快响应：容量 1 channel 只留最先返回；close 广播取消其余
func fastest(urls []string) (string, error) {
	respCh := make(chan string, 1) // 容量 1：只有最先返回的能写入
	done := make(chan struct{})    // 无缓冲：close 即广播
	ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
	defer cancel()
	for _, u := range urls {
		go func(u string) {
			r, err := doHTTP(ctx, u) // 真实请求用 ctx，可被取消
			if err != nil {
				return
			}
			select {
			case respCh <- r: // 最先完成者写入
				close(done) // 通知其余退出
			default:
			}
		}(u)
	}
	select {
	case r := <-respCh:
		return r, nil
	case <-ctx.Done():
		return "", ctx.Err() // 超时取消全部
	}
}

func main() {
	r, err := fastest([]string{"svc-a", "svc-b", "svc-c"})
	fmt.Println("fastest:", r, err)
}
```

## 总结与追问预判
**背这三句就够**：① **容量 1 channel 只留最先返回的结果**；② **close 无缓冲 channel 广播取消其余**；③ **真实 HTTP 取消须 context，channel 只退函数**。
**预判追问**：
- 「超时怎么办？」→ context.WithTimeout 构成竞速+取消+超时三件套。
- 「和令牌桶啥关系？」→ 都是 channel 妙用，令牌桶控速率（见 1016 令牌桶）。
- 「context 取消模式？」→ 见 1025 singleflight / 1019 channel 泄漏治理。
