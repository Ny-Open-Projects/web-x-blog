> 分类：Redis · 缓存异常 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**缓存击穿**/**互斥锁**/**singleflight**/**逻辑过期**/**热点 key 并发回源**
> 原文锚点：第 25~36 段「单个极热点 key 过期的瞬间，大量并发请求同时打到 DB 回源；用互斥锁 / singleflight / 逻辑过期规避」

## 一句话总述
**缓存击穿** = **单个极热点 key 过期的那一瞬**，海量并发请求同时发现缓存没了，全部去数据库回源，把 DB 瞬时冲垮（与雪崩区别：雪崩是"大量 key 集体失效"，击穿是"一个热点 key"）。解法：**互斥锁**（只放一个线程回源、其余等待）、**singleflight**（同 key 并发合并成一次回源）、**逻辑过期**（值里带过期时间，异步刷新不阻塞）。

## 面试官视角
- 考察意图：能否精准区分击穿（单热点）与雪崩（集体）、穿透（不存在），并给出"只回源一次"的并发控制解法。
- 分档：P5 知击穿=单热点失效瞬间并发打 DB；P6 知互斥锁 / singleflight；P7 知逻辑过期（不阻塞读）+ singleflight 在 Go 里的 `golang.org/x/sync/singleflight` 落地。
- 红旗：把击穿说成"大量 key 同时失效"（那是雪崩）；或只加锁不知 singleflight 合并。
- 惊艳点：点出"singleflight 把 N 个并发回源合并成 1 个"，是 Go 微服务防击穿标配；逻辑过期让读永远不阻塞、只后台重建。

## 主问答
**Q（面试官原话）：** 一个热点 key 突然失效，一大波请求涌进来怎么办？
**A：**
1. **互斥锁**：第一个线程发现缓存空，加分布式锁（Redis `SET NX`）去 DB 回源并写回缓存，其余线程**抢不到锁就等待/稍后重试**，避免同时回源 `[经验]`。
2. **singleflight**：Go 里用 `golang.org/x/sync/singleflight`，同一 key 的并发回源**自动合并成一次**，其余直接拿同一结果——比手写锁更简洁。
3. **逻辑过期**：缓存值里带 `expireAt` 字段而非用 Redis TTL；读时若逻辑过期，返回旧值并**异步**起一个线程刷新，读请求不阻塞。热点场景体验最好。

## 关键代码
```go
import "golang.org/x/sync/singleflight"

var g singleflight.Group

func getWithProtect(key string) (string, error) {
    // 先读缓存
    if v, err := rdb.Get(ctx, key).Result(); err == nil {
        return v, nil
    }
    // 并发回源合并成 1 次（防击穿）
    v, _, _ := g.Do(key, func() (interface{}, error) {
        val := loadFromDB(key)
        rdb.Set(ctx, key, val, 30*time.Minute)
        return val, nil
    })
    return v.(string), nil
}
```

## 总结与追问预判
击穿是"单热点失效瞬间并发回源"，核心是"只回源一次"（锁/singleflight）或"不阻塞读"（逻辑过期）。三大异常对比见 1254。缓存一致性见 1261-*。
