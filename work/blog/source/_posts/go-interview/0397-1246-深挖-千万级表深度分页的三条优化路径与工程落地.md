> 分类：数据库 / MySQL 索引 | 难度：L4 | 题型：综合题 | 频率：高 | 关键词：**深度分页、覆盖索引、延迟关联、游标法、COUNT(*)、连接池**

> 原文锚点：第 8~82 段「深度分页的耗时主要花在两个方面：需要扫描一百万多条数据，以及需要对这一百一十多万条数据进行回表…可以使用覆盖索引…也可以通过 ID 去缩小查询范围…如果需要查全表的数据或者分页去获取表里面所有的数据，上面这个优化的查询还是有很多可以使用的场景的」

## 思路与架构

把「千万级表怎么分页」拆成**诊断 → 优化 → 落地**三段，按这条链路答题：

1. **诊断：先量化代价**。`LIMIT 0,10` 约 100+ ms，`LIMIT 1000000,10` 约 1650 ms，同样取 10 行差一个数量级。根因是两块成本：**扫描并丢弃前 offset 行**，以及**每命中一行就回表一次**（示例中回表约百万次）。关键认知是 **offset 不跳过数据，而是取出后丢弃**。
2. **优化：三条路径按代价从低到高选**。
   - 路径一 **覆盖索引**：只查索引列，免回表，1650 ms → 268 ms。局限是只能取索引列。
   - 路径二 **延迟关联**：子查询用覆盖索引只取主键，外层再按主键回表少量行，兼顾「要全字段」与「少回表」。
   - 路径三 **游标法（书签法）**：`WHERE id > last_id ORDER BY id LIMIT n`，直接落在主键区间，彻底避开扫描丢弃。代价是**与 offset 分页不等价**（id 有断层时结果错位），且**不支持任意跳页**。
3. **落地：Go 侧配套**。驱动必须空白导入（`init` 注册）、连接池设三项（最大连接数 / 最大空闲连接数 / 连接最大存活时间）、开启预编译、注册回调打印 SQL；遍历全表时先 `COUNT(*)`（Scan 必须传地址），再用游标逐页取。

## 方案取舍

| 方案 | 解决什么 | 代价 / 局限 | 适用场景 |
|---|---|---|---|
| 覆盖索引 | 消掉百万次回表 | 只能取索引列 | 只要少量列（如只取 id/name） |
| 延迟关联 | 全字段 + 少回表 | SQL 变复杂 | 要全字段且分页较深 |
| 游标法 | 彻底避开 offset 扫描 | 与 offset 不等价、不能跳页 | 顺序遍历、导出、批处理 |
| 限制翻页深度 | 从业务侧削峰 | 产品体验受限 | C 端列表（如最多 100 页） |
| 加缓存 | 避免重复深翻 | 一致性成本 | 热点列表页 |

取舍要点：**先判断业务是否需要「任意跳页」**——需要则只能在覆盖索引 / 延迟关联里选；不需要（导出、同步、批处理）则游标法是压倒性最优。

## 答题技巧

1. **先给数字再给方案**：开口报「1650 ms 降到 268 ms」比说「会变快」可信得多，面试官会认定你真跑过。
2. **说清「offset 不跳过」**：这是区分背答案与真理解的分水岭，务必主动点出。
3. **主动交代不等价性**：用游标法时主动说「因为删除会造成 id 断层，它与 offset 分页结果不完全一致」，体现语义敏感度。
4. **把 Go 工程细节串进来**：驱动空白导入、连接池三项、Scan 传地址——能讲三层（MySQL 原理 + SQL 优化 + Go 落地）的候选人极少。
5. **止步档位**：能讲清覆盖索引与游标法两条路径即达 L4；能再加延迟关联、说明不等价场景并给出 Go 侧落地细节，即达 L5。

## 细节与核心 API

**Go 侧连接池三项（database/sql，驱动必须空白导入）：**

```go
import (
    "database/sql"
    "time"
    _ "github.com/go-sql-driver/mysql" // 空白导入触发 init 注册驱动
)

db, err := sql.Open("mysql", dsn)
if err != nil {
    panic(err)
}
db.SetMaxOpenConns(100)         // 最大打开连接数
db.SetMaxIdleConns(10)          // 最大空闲连接数
db.SetConnMaxLifetime(time.Hour) // 连接最大存活时间
```

**路径一 覆盖索引（只取索引列免回表）：**

```sql
-- 原写法：LIMIT 1000000,10 约 1650ms（扫百万行 + 百万次回表）
SELECT * FROM orders ORDER BY id LIMIT 1000000, 10;

-- 路径一：覆盖索引，只取索引列，免回表 → 约 268ms
SELECT id, user_id FROM orders ORDER BY id LIMIT 1000000, 10;
```

**路径二 延迟关联（子查询覆盖索引只取主键，外层按主键回表少量行）：**

```sql
SELECT o.*
FROM orders o
JOIN (SELECT id FROM orders ORDER BY id LIMIT 1000000, 10) t
  ON o.id = t.id;
```

**路径三 游标法 / 书签法（直接落在主键区间，彻底避开 offset 扫描）：**

```sql
-- 每批取 max(id) 续作下界；结果集空即终止（删除致批 < k）
SELECT * FROM orders WHERE id > :last_id ORDER BY id LIMIT 10;
```

**遍历全表配套（先 COUNT(*) 再游标逐页）：**

```go
var total int
// Scan 必须传地址，否则 sql: expected pointer
if err := db.QueryRow("SELECT COUNT(*) FROM orders").Scan(&total); err != nil {
    return err
}
lastID := 0
for {
    rows, err := db.Query(
        "SELECT * FROM orders WHERE id > ? ORDER BY id LIMIT 1000", lastID)
    if err != nil {
        return err
    }
    batch := 0
    maxID := lastID
    for rows.Next() {
        var o Order
        if err := rows.Scan(&o.ID, &o.UserID /* ... */); err != nil {
            return err
        }
        if o.ID > maxID {
            maxID = o.ID
        }
        batch++
    }
    rows.Close()
    if batch == 0 {
        break // 终止条件
    }
    lastID = maxID
}
```
