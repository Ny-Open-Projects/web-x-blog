# 1841 TCP/UDP 深挖：选型决策树与"基于 UDP 做可靠"的代价

> 深挖卡：把七维对比推进到「怎么选」以及「自研可靠 UDP 到底要补哪些东西」。

## 思路与架构

选型不是比好坏，而是**按四个问题做决策**：

```text
Q1 数据不能丢？                     → 是：TCP 或 可靠 UDP（QUIC/KCP）
   └ 否（音视频、遥测、广播）        → UDP
Q2 时延敏感还是吞吐敏感？
   └ 时延（实时通话/竞技游戏/竞价）  → UDP + 应用层策略（宁可丢帧不等重传）
   └ 吞吐（文件/接口/数据库）        → TCP
Q3 需要一对多 / 多播 / 广播？        → 只能 UDP
Q4 能否接受内核协议栈的队头阻塞？
   └ 不能（多路复用在同一条连接上）  → QUIC（每流独立，丢包只影响一条流）
```

**为什么 QUIC 要基于 UDP 重做一遍 TCP**：TCP 由内核实现，改造牵一发动全身；HTTP/2 的多路复用跑在一条 TCP 连接上，一旦丢包，**所有流都要等这个包重传**（队头阻塞）。QUIC 把可靠传输搬到用户态，每条流独立编号与确认，丢包只阻塞对应流，还能把拥塞控制算法随应用一起升级。代价是 UDP 在部分网络（企业防火墙、NAT 老化策略）下可达性更差、首包 RTT 需要 0-RTT 会话复用来补。

**自研可靠 UDP 要补齐的六件事**（这也是面试官追问"UDP 怎么做可靠"的满分清单）：

| 能力 | 做法 | 备注 |
|---|---|---|
| 序号与确认 | 每包编号，对端 ACK | 基础 |
| 超时重传 | RTT 采样 + RTO 计算 | 照抄 TCP 的 Jacobson/Karn 算法 |
| 顺序重组 | 接收端缓存乱序包 | 或业务允许就直接丢弃（实时场景） |
| 流量控制 | 接收窗口通告 | 防止打爆对端 |
| 拥塞控制 | 慢启动/拥塞避免 | **不做就是网络公害** |
| **分段** | 大数据拆成 ≤ MSS 的块 | **最容易被漏掉**，漏了则丢一片重传整包 |

## 方案取舍

| 场景 | 选 TCP | 选 UDP | 关键理由 |
|---|---|---|---|
| 文件传输 / 接口调用 | ✓ | | 丢一个字节整个文件就废了 |
| 数据库 / 消息队列 | ✓ | | 强一致，不容错 |
| DNS 查询 | | ✓ | 一问一答、包小、可重试 |
| 实时音视频 | | ✓ | 迟到的数据等于丢数据，重传不如丢帧 |
| 竞技类游戏 | | ✓（KCP） | 牺牲 20~30% 带宽换更低时延 |
| HTTP/3 | | ✓（QUIC） | 解决队头阻塞、0-RTT、连接迁移 |
| 广播 / 多播 | | ✓ | TCP 天生不支持 |
| 物联网遥测上报 | | ✓ | 包小、频次高、可容忍丢失 |

取舍原则：**先问"丢了这个包，业务是变慢还是出错"。**变慢（视频卡一帧）就选 UDP；出错（订单金额错了）就选 TCP。中间地带（游戏状态同步）用 UDP + 选择性重传。

## 答题技巧

1. **七维清单要能一口气背完**：连接 / 服务对象 / 可靠性 / 流控拥塞 / 首部 / 传输方式 / 分片位置。面试官数的是维度数量，答 3 条和答 7 条是两个档位。
2. **把"连接"定义成状态机，这是最加分的一句**：「连接不是线缆，是内核为这条通信维护的状态机——三次握手建立、四次挥手拆除、RST/closing 是异常分支」。说完这句，后面所有关于 TIME_WAIT、握手丢包的追问都能接住。
3. **用丢包实测打脸"UDP 只是理论上会丢"**：「本机回环连发 20 万个 1000 字节 UDP 数据报，丢包率 6.3%；同样量的 TCP 一个字节都没丢」。回环都能丢 6.3%，跨网更不用说——**这个数字比任何形容词都有力**。
4. **"UDP 更快"要给边界条件**：无丢包、小包、不需要可靠时 UDP 确实更快（少握手、少首部、无状态机）；**一旦要可靠且会丢包，自研 UDP 若漏了分段，丢一片重传整包，反而不如 TCP**。答出这个反转就到 P7 了。
5. **带上 QUIC 与 KCP 两个现成答案**：不要说"自己在 UDP 上实现 TCP"这种大话，正确表述是「优先用 QUIC/HTTP3 或 KCP 这类成熟实现，只有极端场景才自研，且必须补上拥塞控制——不做拥塞控制的 UDP 是网络公害」。

## 细节与核心 API

```go
// TCP：面向连接、可靠、字节流、有拥塞控制
ln, _ := net.Listen("tcp", ":8080")
go func() { c, _ := ln.Accept(); buf := make([]byte, 1024); c.Read(buf) }()
c, _ := net.Dial("tcp", "server:8080"); c.Write([]byte("hi"))
// UDP：无连接、不可靠、数据报、无拥塞控制（快但可能丢/乱序）
uc, _ := net.ListenPacket("udp", ":53")
go func() { buf := make([]byte, 512); n, addr, _ := uc.ReadFrom(buf); uc.WriteTo(buf[:n], addr) }()
// 对比：
//  TCP 适合需可靠有序（HTTP/DB/文件）；UDP 适合实时低延迟（DNS/视频/游戏）
//  TCP 有三次握手开销；UDP 首包即达但需自管重传/保序
//  连接数：TCP 占 fd 与内存；UDP 一个 socket 服务所有对端（无连接状态）
```
