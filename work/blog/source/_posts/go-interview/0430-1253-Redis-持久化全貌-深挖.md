> 分类：Redis | 难度：中高 | 题型：原理深挖 | 频率：高 | 关键词：**RDB、AOF、混合持久化、写时复制、fsync、选型**

> 原文锚点：第 1~103 段「RDB/AOF/混合 三种持久化原理与对比」

## 思路与架构
Redis 持久化要解决「宕机重启后数据可恢复」，两条技术路线：
- 存数据（RDB）：某一时刻全量内存快照，二进制紧凑，fork 子进程 + 写时复制(COW) 落地，恢复直接加载。
- 存操作（AOF）：追加写命令，aof_buf→write→内核缓冲→fsync 落盘；三策略 always/everysec/no 权衡安全与性能；重写压缩体积。
- 融合（混合）：重写时前半 RDB 全量 + 后半 AOF 增量，4.0+ 推荐。

## 方案取舍
- RDB vs AOF：RDB 恢复快但丢间隔数据，适合做备份；AOF 丢得少但恢复慢、文件大，适合做主持久化。
- 刷盘策略：always 最安全但吃主线程 CPU；everysec 默认折中（最多丢 1 秒）；no 性能最好但不可控。
- 重写必要性：AOF 不控会无限膨胀，重写用「新文件+原子替换」防污染，后台子进程不阻塞主线程。
- 混合优先：4.0+ 环境下混合几乎集合两者优点，是新部署的默认推荐；老版本只能用 RDB/AOF 二选一或同开。

## 答题技巧
1. 先点题：持久化价值是「宕机后可恢复，避免大规模缓存失效」。
2. 分三条线讲：RDB（快照/COW/BGSAVE）、AOF（命令/fsync 三策略/重写）、混合（RDB+AOF 拼接）。
3. 用一张对比表收口：数据安全、恢复速度、文件大小三维度。
4. 选型话术：「高性能 RDB、高可靠 AOF、兼顾混合，生产常双开兜底」。
5. 细节加分：COW 按 4KB 页复制、everysec 最多丢 1 秒、aof-use-rdb-preamble 默认 yes。

## 细节与核心 API

**redis.conf 持久化关键配置：**

```conf
save 900 1            # RDB：900s 内至少 1 次写触发 BGSAVE
save 300 10
save 60 10000
appendonly yes        # 开启 AOF
appendfsync everysec  # always(最安全吃CPU) / everysec(默认,最多丢1s) / no(不可控)
aof-use-rdb-preamble yes  # 4.0+ 混合持久化：重写文件前半 RDB + 后半 AOF 增量
```

**写时复制（COW）与 fork：**

```text
BGSAVE / BGREWRITEAOF 时 fork 子进程：
- 父子进程共享 4KB 物理页，子进程读、父进程写
- 父进程改某页 → 内核复制该 4KB 页给父（写时复制），子进程仍看旧页
- 大 key 会让复制的物理页极多 → 持久化耗时陡增（见 1260）
```

**观测与手动触发：**

```bash
redis-cli INFO persistence   # 看 rdb_last_bgsave_status / aof_last_write_status
redis-cli BGREWRITEAOF       # 手动触发 AOF 重写
redis-cli LASTSAVE           # 最近一次 RDB 成功的时间戳
```
