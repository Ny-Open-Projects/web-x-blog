> 原文锚点：第 14~44 段「eq_ref 被驱动表唯一键等值、ref 普通二级索引等值、优化器改写」

## 一句话总述
eq_ref 出现在连接/子查询的「被驱动表」通过主键或唯一属性的二级索引做等值匹配时，每行驱动表最多匹配一行被驱动表。ref 是普通（非唯一）二级索引与常量做等值匹配，可能命中多行。两者都基于「等值」，差别在索引是否唯一。

## 面试官视角
eq_ref 与 ref 是最易被混淆的两档。考官听你能不能说清：eq_ref 的「唯一性」来自被驱动表的主键/唯一索引，且驱动侧的值是确定常量（如 join 时另一侧已算出的列值）；ref 用的是普通索引，可能回表多行。能点出「优化器会把子查询改写成 join」更佳。

## 主问答
**Q（面试官原话）：** eq_ref 和 ref 有什么区别？什么时候出现？

1. **eq_ref**：被驱动表通过「主键或唯一属性的二级索引」与驱动表列做等值；因唯一，驱动表每行最多匹配被驱动表一行。
2. **ref**：被驱动表用「普通二级索引」与常量等值；索引非唯一，可能匹配多行，需回表。
3. **常量来源**：子查询里 `t2.id = t1.id`，外层的 t1.id 对子查询而言是已确定的常量，故内层走 eq_ref/ref 而非 range。
4. **优化器改写**：很多子查询会被优化器重写成 join（如 `... IN (SELECT ...)` 变 `LEFT JOIN`），原本的范围条件随之转移到驱动表。

## 版本与兼容性
| 访问 | 索引要求 | 匹配行数 |
|------|----------|----------|
| eq_ref | 主键/唯一索引 | ≤1 |
| ref | 普通二级索引 | ≥0（可多） |

## 关键代码
```sql
-- t2.id 为主键，t1 驱动
SELECT * FROM t1 JOIN t2 ON t2.id = t1.id;   -- t2 侧 eq_ref
SELECT * FROM t WHERE k = 'x';               -- k 普通索引 → ref
```

## 总结与追问预判
核心：**eq_ref = 被驱动表唯一键等值（≤1 行）；ref = 普通索引等值（多行可）**。追问常接「const 与 eq_ref 到底差在哪」（见 1244）或「范围查询怎么走」（见 1244）。
