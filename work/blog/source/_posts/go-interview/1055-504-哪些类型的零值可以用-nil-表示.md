> 分类：Go 基础 / 类型系统 | 难度：L2 | 题型：记忆题 + 辨析题 | 频率：高 | 关键词：**nil、零值、指针、切片、map、chan、func、interface、可比较性**

> 原文锚点：第 3~29 段「布尔零值 false、数值零值 0、字符串零值空串；指针切片管道函数接口映射的零值都是 nil；不同 nil 尺寸不同；nil 不一定可比较；可比较的两个 nil 也不一定相等」

## 一句话总述
零值是 **nil** 的是 **6 类引用/派生类型**：**指针、切片、map、chan、func、interface**；数值（含 byte/rune）、bool、string、数组、结构体的零值**都不是** nil（分别是 0、false、空串、全元素零值、全字段零值）。且 nil 还有三个反直觉性质：**尺寸不同、不一定可比较、可比较也未必相等**。

## 面试官视角
P5 能背出「指针切片 map chan func interface」这串；P6 要补上「数组和结构体的零值不是 nil」以及「nil 是预声明标识符不是关键字」；P7 必须能解释**为什么两个 nil 不相等**（interface 的动态类型），并顺带踩准 `*T(nil)` 装进 interface 后 `!= nil` 这个经典 typed-nil 陷阱。

## 主问答
**Q（面试官原话）：** Go 里面哪些类型的零值是 nil？

1. **nil 六兄弟**：`指针 *T`、`切片 []T`、`map[K]V`、`chan T`、`func`、`interface` 的零值都是 **nil** `[源码]`。它们共同点是「底层都需要一块真实的数据/代码，声明时还没分配」。
2. **不是 nil 的那些**：bool→`false`；所有整型与浮点、复数→`0`（`0x0`、`0o0`、`0.0`、`0+0i` 只是不同写法）；string→`""`；**数组 `[N]T` 的零值是「每个元素各取自身零值」且内存已分配**；**结构体是「每个字段各取自身零值」** `[经验]`——这两条最容易被误答成 nil。
3. **nil 不是关键字**：它是**预声明标识符**，可以被局部变量遮蔽（`nil := 5` 能编译），但生产代码里这么干是自杀 `[经验]`。
4. **不同 nil 尺寸不同（64 位实测）** `[实测]`：指针 / map / chan / func 的 nil 都是 **8 字节**（一个机器字）；**切片 24 字节**（数据指针 + len + cap 三个字）；**interface 16 字节**（类型指针 + 数据指针两个字）。**"都是 nil 所以都占 8 字节"是错的**。
5. **nil 不一定可比较**：切片、map、func 这三种**只能与 nil 比较**，两个同类型的它们互比会**编译不过**——本机实测报错 `invalid operation: s1 == s2 (slice can only be compared to nil)` `[实测]`。要比较切片内容得用 `slices.Equal`（Go 1.21+）。
6. **可比较的两个 nil 也未必相等** `[实测]`：`var p *int = nil; var i interface{} = nil` 时 `p == i` 为 **false**——因为 interface 相等要求「动态类型 + 动态值都相等」，`i` 没有动态类型而 `p` 转换后有。反过来 `var ei interface{} = (*int)(nil)` 时 `ei == nil` 也是 **false**（有动态类型 `*int`，值才是 nil），这就是经典的 **typed-nil 陷阱**：函数返回 `error` 接口时直接 `return err` 而 `err` 是 `*MyError` 类型的 nil 指针，调用方 `err != nil` 判定为真。

## 追问链
| 层级 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 哪些类型零值是 nil？ | 基础记忆 | 指针/切片/map/chan/func/interface 六类 | 数不全六类，停在 L1 |
| L2 | 数组和结构体呢？ | 反直觉点 | 不是 nil，是全元素/全字段各取零值，且数组内存已分配 | 答成 nil，停在 L2 |
| L3 | nil 是关键字吗？ | 语言细节 | 不是，是预声明标识符，可被遮蔽 | 答"是关键字"，停在 L3 |
| L4 | 不同 nil 占多大？ | 底层布局 | 指针/map/chan/func 8 字节，切片 24，interface 16 | 以为都一样，停在 L4 |
| L5 | 两个 nil 一定相等吗？ | 类型系统 | 不一定；interface 相等需类型+值都等，typed-nil 陷阱 | 答"都相等"，停在 L5 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Go 全版本 | 零值与 nil 规则未变 | 按六类引用类型作答 |
| Go 1.18+ | `any` 取代 `interface{}` 写法 | 零值仍是 nil，表述用 `any` |
| Go 1.21+ | `slices.Equal` / `maps.Equal` | 替代手写循环比较不可比较类型 |
| 64 位平台 | 8 / 24 / 16 字节 | 32 位平台对应减半（4 / 12 / 8） |

## 关键代码
```go
var p  *int        // nil，8 字节
var s  []int       // nil，24 字节（ptr+len+cap）
var m  map[int]int // nil，8 字节
var c  chan int    // nil，8 字节
var f  func()      // nil，8 字节
var i  any         // nil，16 字节（type ptr + data ptr）

fmt.Println(unsafe.Sizeof(p), unsafe.Sizeof(s), unsafe.Sizeof(i)) // 8 24 16

// 编译不过：切片只能与 nil 比较
// fmt.Println(s == s) // invalid operation: s == s (slice can only be compared to nil)

// typed-nil 陷阱：接口里有动态类型，值虽为 nil 也不等于 nil
var ei any = (*int)(nil)
fmt.Println(ei == nil) // false
```

## 总结与追问预判
答题骨架：**「六类是 nil → 数组结构体不是 → 尺寸不同 → 不一定可比 → 可比也未必相等」** 五步递进。面试官下一步大概率追 typed-nil：让你写一个返回 `error` 的函数并问「为什么明明返回了 nil 指针，调用方 `err != nil` 却是 true」——答案是接口值由「动态类型 + 动态值」两部分组成，装进去的是 `*MyError(nil)` 时类型非空（深挖见 509、`509-interface-compare-runtime`）。

`[边界]` 本卡只讲**「哪些零值是 nil」以及 nil 的三个反直觉性质**，**不重述**完整零值表与数组/切片零值对比（见 414）、nil 切片与 nil map 的读写差异（见 414）、`new` 与 `make` 的分工（见 413）。
