# 1841 TCP 与 UDP 的区别：七维对比与"UDP 一定更快吗"

> 分类：网络 / 传输层 | 难度：L2 | 题型：对比题 | 频率：极高 | 关键词：**面向连接、可靠交付、拥塞控制、流式 vs 数据报、首部开销、MSS/MTU、QUIC/KCP**

> 原文锚点：第 1~37 段「连接、服务对象、可靠性、拥塞与流量控制、首部开销、传输方式、分片位置七个区别，以及 UDP 是否一定比 TCP 快的辨析」

## 一句话总述
TCP 是**面向连接、可靠、有序、有流控与拥塞控制**的**字节流**协议，首部 20 字节起；UDP 是**无连接、尽最大努力交付、保留消息边界**的**数据报**协议，首部固定 8 字节。二者不是"谁更好"而是"谁更适合"——**UDP 并非一定更快**：在需要可靠传输且丢包的网络里，基于 UDP 自研重传若没做分段，丢一个 IP 分片就要重传整个大数据包，此时 **TCP 反而更快**。

## 面试官视角
P5 能答"TCP 可靠、UDP 快"；P6 要按七个维度系统对比（连接 / 服务对象 / 可靠性 / 流控拥塞 / 首部 / 传输方式 / 分片位置）；P7 必须答出**「所谓连接就是内核维护的一套状态机」**这句本质定义，并能反驳"UDP 一定更快"——说出 QUIC/KCP 的分段差异。这两个点是分水岭。

## 主问答
**Q（面试官原话）：** TCP 和 UDP 有什么区别？UDP 一定比 TCP 快吗？

1. **连接性（本质）**：TCP 传输前要三次握手建立连接；UDP 无需建立，即刻发送。**所谓"连接"不是一根物理线缆，而是内核为这条通信维护的一套状态机**（三次握手、四次挥手、RST、closing 等状态与定时器） `[经验]`。UDP 用不上这套状态机，所以叫无连接。
2. **服务对象**：TCP 是**一对一**（一条连接只有两个端点）；UDP 支持**一对一、一对多、多对多**（广播、多播）。
3. **可靠性**：TCP 保证无差错、不丢失、不重复、按序到达；UDP 只尽最大努力交付 `[实测]`——本机回环实测连发 **200000 个 1000 字节 UDP 数据报，服务端只收到 187338 个，丢弃 12662 个，丢包率 6.3%**（注意这是在**没有跨机、没有路由器**的回环上）。**而同样发 200000×1000 字节的 TCP，服务端收到 200000000 字节，与应发总量差 0**——代价是 TCP 会降速重传，UDP 直接丢。
4. **流控与拥塞控制**：TCP 有滑动窗口（流控）+ 慢启动/拥塞避免/快重传/快恢复（拥塞控制），网络拥塞时主动降速；**UDP 没有**，网络再堵也按原速率发，所以堵的时候 UDP 会加剧拥塞并大量丢包。
5. **首部开销**：TCP 首部**无选项时 20 字节**、有选项更长；UDP 首部**固定 8 字节** `[实测]`。载荷 100 字节时 TCP 报文 140 B（利用率 **71.4%**）、UDP 128 B（**78.1%**）；载荷 1460 字节时分别是 97.3% 与 98.1%——**载荷越小，头部占比差距越明显**。
6. **传输方式**：TCP 是**字节流、无消息边界**（会粘包/拆包）；UDP 是**一个包一个包发、保留边界** `[实测]`——本机实测 TCP 两次 `write("hello")`+`write("world")`，对端**一次 read 就读到 10 字节 `"helloworld"`**；而 UDP 两次发，对端**两次 read 分别读到 5 字节 `"hello"` 与 `"world"`**。做 TCP 应用层协议必须自己处理分包（长度前缀 / 分隔符）。
7. **分片位置**：TCP 数据超过 **MSS**（`MTU 1500 - IP头 20 - TCP头 20 = 1460`）时在**传输层分段**，对端在传输层重组，**丢一个分段只重传该分段**；UDP 数据超过 `MTU - 20 - 8 = 1472` 字节时在 **IP 层分片**，对端在 IP 层重组，**丢任一片就要重传整个数据报** `[经验]`——这正是"UDP 不一定更快"的关键。

## 追问链
| 层级 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | TCP 和 UDP 最核心区别？ | 基础 | 一个可靠有序、一个尽最大努力 | 只说"一个快一个慢"，停在 L1 |
| L2 | 「面向连接」的连接是什么？ | 本质理解 | 内核维护的状态机（握手/挥手/RST） | 答"像打电话"，停在 L2 |
| L3 | TCP 会粘包吗？UDP 呢？ | 传输方式 | TCP 字节流无边界会粘包，UDP 保留边界 | 以为两者都有边界，停在 L3 |
| L4 | 首部各多少字节？ | 细节 | TCP 20（无选项）／UDP 8 固定 | 说不准确，停在 L4 |
| L5 | UDP 一定比 TCP 快吗？ | 反直觉 | 不一定：大包丢一片要整体重传，TCP 只重传分段 | 笃定"一定快"，停在 L5 |

## 版本与兼容性
| 场景 | 协议 | 说明 |
|---|---|---|
| HTTP/1.1、2、FTP、SSH、MySQL | TCP | 需要可靠有序 |
| HTTP/3 | **QUIC（基于 UDP）** | 在用户态实现可靠 + 拥塞控制，避开队头阻塞（见 1840） |
| DNS、SNMP、DHCP、NTP | UDP | 包小、一次交互、可容忍重查 |
| 音视频 / 实时游戏 | UDP（+ 应用层重传） | 时延敏感，容忍少量丢包 |
| 王者荣耀 KCP | UDP 上自研重传 | 牺牲带宽换低时延 |
| 广播 / 多播 | 只能 UDP | TCP 天生一对一 |

```go
// TCP：字节流无边界，两次写可能被一次读合并（粘包）
c.Write([]byte("hello"))
c.Write([]byte("world"))
n, _ := c.Read(buf)   // n=10, buf[:n]=="helloworld"  ← 边界消失

// UDP：数据报保留边界，一次 WriteTo 对应一次 ReadFrom

pc.WriteTo([]byte("world"), dst) // 对端第二次 ReadFrom 得 5 字节 "world"

// 常量推导：MSS 与 UDP 单包上限
const mtu, ipHdr, tcpHdr, udpHdr = 1500, 20, 20, 8
mss := mtu - ipHdr - tcpHdr        // 1460：TCP 在传输层分段
udpMax := mtu - ipHdr - udpHdr     // 1472：超过则在 IP 层分片
```

## 总结与追问预判
答题用**七维清单**：连接 / 服务对象 / 可靠性 / 流控拥塞 / 首部 / 传输方式 / 分片位置。面试官下一步常追「为什么 QUIC 用 UDP」「TCP 粘包怎么解决」「UDP 怎么做到可靠」——分别答「用户态实现可靠+避免队头阻塞」「长度前缀或分隔符」「应用层加序号+确认+重传+窗口」。

`[边界]` 本卡只做**七个维度的横向对比与"UDP 是否更快"的辨析**，**不重述** TCP 首部各字段含义（见 1840）、TCP 协议整体特性与标志位（见 1840、`1840-tcp-flags`）、三次握手细节与丢包处理（见 1843、`1843-handshake-loss-first`）、丢包与重传机制（见 1848）、keepalive（见 1849）。
