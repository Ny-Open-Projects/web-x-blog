> 分类：MySQL / InnoDB | 难度：L2~L3 | 题型：配置题 | 频率：中高 | 关键词：**innodb_buffer_pool_size、128MB、实例数、16KB、缺页中断**

> 原文锚点：第 12~22 段「默认配置下 buffer pool 只有一百二十八兆…通常我们会设置成物理内存的百分之六十到八十」

## 一句话总述
缓冲池在启动时向操作系统**申请一片连续内存**并按 16KB 切成缓存页；默认仅 128MB，生产上通常调到物理内存的 **60%~80%**。

## 面试官视角
P6 会背"越大越好"；P7 要说出**为什么不能贴着物理内存配**——还要给操作系统页缓存、连接缓冲、其他进程留余量 `[经验]`。加分点：启动后**虚拟内存很大、物理内存很小**，因为只有被访问到才触发缺页中断建立映射 `[源码]`。

## 主问答
**Q（面试官原话）：** 缓冲池配多大？配了就立刻占用这么多物理内存吗？

1. **默认值偏小**：默认配置下缓冲池只有 128MB，可用 `innodb_buffer_pool_size` 查看，远不够生产使用 `[实测]`。
2. **经验取值**：通常设为物理内存的 **60%~80%**，剩余留给操作系统与其他进程，避免换页 `[经验]`。
3. **不是立刻占用**：启动时只是申请连续虚拟地址空间并划分 16KB 的页，实际物理内存要等访问时触发**缺页中断**才逐页建立映射 `[源码]`。
4. **可以拆成多实例**：通过 `innodb_buffer_pool_instances` 配置实例个数，默认只有一个；拆多实例可减小并发访问时的锁竞争 `[源码]`。
5. **缓存内容不止数据页**：还缓存索引页、插入缓冲、自适应哈希索引与锁信息等，评估容量时要算进去 `[经验]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| MySQL 5.7 | 容量可在线调整 | 5.7.5 起支持动态改大小 |
| MySQL 8.0 | 同样支持在线调整 | 实例数在池 ≥1GB 时默认 8 |
| 任意版本 | 实例数受容量约束 | 池小于 1GB 时多实例无意义 |

## 关键代码
```sql
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';       -- 默认 134217728 字节 = 128MB
SHOW VARIABLES LIKE 'innodb_buffer_pool_instances';  -- 默认 1
SET GLOBAL innodb_buffer_pool_size = 4294967296;     -- 在线调到 4GB
```
> 验证：改大后立刻看进程虚拟内存上升，而常驻物理内存随访问逐步增长 `[实测]`。

## 总结与追问预判
**容量决定命中率，实例数决定并发度**。下一步常追问：缓冲池这么大，怎么快速找到空闲页与脏页——接 126 那组卡。

## ⚠️ 原文纠错
1. 事实核校：原文"默认只有一个实例"在池较小时准确；补充——池达到 1GB 量级时默认值会变为 8，别把"默认 1"说死 `[源码]`。
2. 易混点：原文"一启动就申请配置项大小的内存空间"指**虚拟地址空间**，不是物理占用，两者要分清 `[经验]`。
3. 崩坏词归一：源码将缓冲池、参数名、缺页中断等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
