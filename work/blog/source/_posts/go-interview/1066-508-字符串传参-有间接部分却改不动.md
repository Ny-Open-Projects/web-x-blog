> 分类：Go 语言基础 | 难度：L2 | 题型：原理题 | 频率：中高 | 关键词：**string 不可变、编译报错、间接部分、只读字节**

> 原文锚点：第 48~52 段「字符串的底层结构和切片非常类似…赋值的时候直接就报错了，这种类型不允许改变里面的值」

## 一句话总述
string 的头部和切片一样带指针（有间接部分），但 Go 在**语言层面**禁止写入它的字节——`s[i] = 'x'` 直接编译失败，所以传参共享也绝对安全。

## 面试官视角
考点是"能不能改"与"拷没拷"是两件事。P5 知道 string 不可变；P6 能说出底层是"指针 + 长度"的头部，因而传参拷贝很便宜；P7 会补 unsafe 绕过的风险：用 `unsafe.String`/`StringData` 强改会踩到只读段崩溃，且破坏"常量字符串可共享"的前提 `[源码]`。

## 主问答
**Q（面试官原话）：** 字符串传参和切片传参一样吗？

1. **相同处**：底层结构相似——头部里都有指向数据的指针和长度，传参时拷的是头部，双方共享底层字节。
2. **不同处**：字节不可写。`s[i] = 'x'` 报编译错误 `cannot assign to s[i]`，原文所说"赋值时直接报错"即此 `[实测]`。
3. **结果**：既然没有写路径，共享就不会产生任何跨函数副作用——调用方的字符串不可能被函数改掉，无需防御性拷贝。
4. **代价**：正因不可变，`s += "x"` 每次都可能分配新字符串，循环拼接要用 `strings.Builder`，这是更高频的追问点 `[经验]`。

## 版本与兼容性

## 关键代码
```go
func tryModify(s string) {
    // s[0] = 'x'  → 编译错误：cannot assign to s[i]
    fmt.Println(s)
}

func main() {
    str := "abc"
    fmt.Println(unsafe.StringData(str))  // 底层字节地址，传参前后相同
    tryModify(str)
    fmt.Println(str)  // 仍是 abc
}
```

## 总结与追问预判
**"有间接部分"不等于"可写"**：string 共享的是只读字节，切片共享的是可写数组，这就是两者传参行为的全部差异。追问会接 byte 与 string 互转的拷贝代价。
