> 分类：Go/类型系统 | 难度：L2 | 题型：概念题 | 频率：高 | 关键词：**可比较类型** / **comparable** / **nil 比较** / **map/slice/func 不可比较**
> 原文锚点：第 1~4 段「除 func/map/slice 等外其他类型可比较；数组元素不可比较则数组不可比较；结构体含不可比较字段则不可比较；map/slice/func 可与 nil 比较」

## 一句话总述
Go 中**除 func、map、slice 三种类型外，其余类型都可比较**（== / !=）。注意两条细则：**数组**若元素类型不可比较则整个数组不可比较；**结构体**若含不可比较字段则整个结构体不可比较。而 **map / slice / func 自身虽不可互相比较，却都可以与 `nil` 比较**——这是面试常踩的边界。

## 面试官视角
- 意图：考察对 Go 类型可比较性的**完整清单**记忆，是答 interface 比较题的前置地基。
- P5 能说出"map/slice/func 不可比较"；P6 能补上"数组/结构体含不可比较字段则整体不可比较"；P7 能点出"map/slice/func 可与 nil 比较"这一反直觉边界。
- 红旗：以为 map/slice/func 完全不能出现在比较里（漏掉 nil 比较）；把"可比较"等同于"可排序"（string 可比较但只有 < 等排序，chan 只可相等比较）。
- 惊艳点：点出"可比较 ≠ 可排序"，并自然引出"interface 比较比这更复杂，要看底层"（见 509）。

## 主问答
**Q（面试官原话）：** Go 里哪些类型是可以用 == 比较的？
**A：**
1. **结论**：除 **func、map、slice** 三类外，Go 所有类型都可比较。可比较类型包括：布尔、数值、指针、channel、结构体（字段全可比较时）、数组（元素可比较时）、字符串、接口（满足特定条件时）。
2. **机制（两条细则）**：
   - **数组**：仅当**元素类型可比较**时数组才可比较；元素含 map/slice/func 则数组整体不可比较。
   - **结构体**：仅当**所有字段都可比较**时结构体才可比较；任一字段为 map/slice/func 则整体不可比较。
   - **map/slice/func**：**彼此之间不可比较**（编译报错），但**都可以与 `nil` 比较**（未初始化时等于 nil）。
3. **边界（可比较 ≠ 可排序）**：可比较只保证 == / !=；只有布尔/数值/字符串支持 < > 等排序比较，chan/指针/数组/结构体只可相等比较不可排序 `[经验]`。

## 关键代码
```go
package main

import "fmt"

func main() {
    // 可比较类型
    var a, b int = 1, 1
    fmt.Println(a == b) // true

    // map/slice/func 彼此不可比较，但可与 nil 比较
    var m map[string]int
    fmt.Println(m == nil) // true（可与 nil 比；m == m 编译报错）

    var s []int
    fmt.Println(s == nil) // true

    var f func()
    fmt.Println(f == nil) // true

    // 含不可比较字段的结构体整体不可比较
    type T struct {
        m map[int]int // 不可比较字段
    }
    // var x, y T = T{}, T{}
    // fmt.Println(x == y) // 编译报错：struct containing map cannot be compared
}
```

## 总结与追问预判
- 除 func/map/slice 外皆可比较；数组/结构体含不可比较字段则整体不可比；map/slice/func 可 nil 比；可比较≠可排序。
- 预判：interface 比较底层 → 见 509；error != nil 陷阱 → 见 509；间接值部类型 → 见 420（不冲突，本卡讲可比较性清单）。
