> 原文锚点：第 95~103 段「exclude 排除指定版本、replace/exclude 仅主模块生效」

## 一句话总述
`go.mod` 中除 `require` 外还有两个常用指令：**`replace`**（把依赖替换为另一路径/版本，常用于本地调试或私有包）与 **`exclude`**（排除指定的依赖版本，用于规避已知有严重 Bug 的版本）。**关键限制：这两条指令只有在「当前模块是主模块」时才生效**——写在被依赖模块自己的 `go.mod` 里，对引用它的主模块无效。

## 面试官视角
这题考 go.mod 的细节掌握。考官期待你讲清 replace/exclude 的用途差异，并强调「**仅主模块生效**」这条最容易踩坑的规则——它意味着你无法通过在依赖库里写 replace 来影响下游。能补「exclude 实际项目几乎用不到，除非明确某版本有严重 Bug」说明有实战感。

## 主问答
**Q（面试官原话）：** go.mod 里的 replace 和 exclude 有什么区别？什么情况下生效？

1. **replace**：把依赖的模块路径/版本替换为另一个目标（路径或版本）；典型用途是本地私有包调试、临时打补丁、替换不可用源。
2. **exclude**：排除指定依赖包的指定版本，使本工程不会引入该版本；仅当确知某版本有严重 Bug 时才用，实际项目很少使用。
3. **生效范围（关键）**：`replace` 与 `exclude` **只在当前模块是主模块时生效**；写在被依赖模块（如 privatePKG）自己的 `go.mod` 中，对引用它的主模块**不起作用**。
4. **官方指令集**：按官方 go.mod 规范，标准指令为 `module` / `go` / `require` / `replace` / `exclude` / `retract` / `toolchain`。

## 版本与兼容性
| 指令 | 作用 | 生效条件 |
|------|------|----------|
| replace | 替换模块路径/版本 | 仅主模块 |
| exclude | 排除指定版本 | 仅主模块 |

## 关键代码
```go
// go.mod
exclude github.com/xxx/somepkg v1.1.0   // 排除有 Bug 的版本
replace github.com/xxx/old => github.com/xxx/new v1.2.3
```

## 总结与追问预判
核心：**replace 替换路径/版本、exclude 排除坏版本，二者仅在「主模块」生效，对下游不传递**。追问可回「私有包 replace 实战」（见 406）。

## ⚠️ 原文纠错
1. 事实核校： [经验] replace 与 exclude 语义、二者仅在主模块生效（写在被依赖模块中对下游无效）——均正确，本卡为准。
2. **事实订正**：源稿称 go.mod 还有 `include` 指令且于 Go 1.20 被移除。按官方 go.mod 规范，标准指令为 `module`/`go`/`require`/`replace`/`exclude`/`retract`/`toolchain`，**并无 `include` 指令**；本卡以官方规范为准，聚焦 replace 与 exclude。
3. 崩坏词归一：源码将 Go/go.mod/replace/exclude 等音译为多组崩坏词；本卡统一为规范术语。
