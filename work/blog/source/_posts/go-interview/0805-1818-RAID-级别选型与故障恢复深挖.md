## 思路与架构
所有 RAID 级别都能由**三种原子能力**组合出来，先建立这个心智模型，再谈选型：

- **条带化（striping）**：把数据切块铺到多盘，换的是**吞吐**——不提供任何保护。
- **镜像（mirroring）**：给每份数据留副本，换的是**可靠性**，代价是空间（利用率 50%）。
- **奇偶校验（parity）**：用 XOR / 伽罗华域运算生成校验块，换的是**低成本冗余**，代价是计算与写放大。

于是：RAID 0 = 纯条带；RAID 1 = 纯镜像；RAID 5 = 条带 + 单校验；RAID 6 = 条带 + 双校验；RAID 10 = 镜像 + 条带。**级别不是要背的清单，而是三种能力的排列组合。**

比较时统一用五维矩阵：**最少盘数 / 可用容量 / 读性能 / 写性能 / 容错盘数**。任何选型讨论填完这张表就有结论，不必靠感觉。

## 方案取舍
- **RAID 0 vs 任何有冗余的级别**：RAID 0 吞吐最高、容量 100%，但一块盘坏全阵列失效。只适合可随时重建的数据（缓存、中间结果、可重算的离线作业）。
- **RAID 1 vs RAID 5**：RAID 1 读好写不亏、结构最简单、恢复最快，但空间贵；RAID 5 空间省得多，代价是写放大与重建慢。盘数少（2~4 块）时 RAID 1/10 往往比 RAID 5 更划算。
- **RAID 5 vs RAID 6**：大容量盘（≥4TB）重建耗时以小时甚至天计，重建期再坏一块即数据全丢；RAID 6 多牺牲一块盘容量换二次故障容忍。**盘越大，越该上 RAID 6 或 RAID 10。**
- **RAID 5/6 vs RAID 10**：写密集、要求恢复快、预算够 → RAID 10；读密集、容量敏感、可接受重建慢 → RAID 5/6。数据库 redo/data 盘通常偏 RAID 10。
- **硬 RAID vs 软 RAID**：硬 RAID 有缓存与电池/电容保护，写性能好；但卡故障需同系卡接管，且缓存未落盘有丢数据风险。软 RAID 可移植性强、成本低，受 CPU 与内存影响。
- **热备盘 vs 手动换盘**：热备能把「无人值守时段的二次故障」窗口压到最短，代价是常备一块闲置盘。

## 答题技巧
- **先亮模型再给结论**：开口说「RAID 只有条带、镜像、校验三种原子能力」，考官立刻知道你不是背答案的。
- **数字要脱口而出**：RAID 5 最少 3 盘、可用 (N-1)/N；RAID 6 最少 4 盘、可用 (N-2)/N；RAID 10 最少 4 盘、50%。
- **被问选型先反问业务**：读写比多少？容量预算多少？能接受多长重建时间？——带着约束回答才像做过。
- **主动补一个反常识点**：**RAID 不是备份**。它只防磁盘硬件故障，不防误删、勒索、主库逻辑错误、机房故障；真正的备份是异地、异介质、可回滚的副本。
- **收尾给可验证动作**：巡检读 `/proc/mdstat` 看是否降级、压测确认写放大、定期做恢复演练——能讲出验证方式最加分。

## 细节与核心 API

```bash
# 级别取舍：0 条带（快无冗余）/1 镜像（可靠费盘）/5 奇偶（1块冗余、写放大）
#         10 镜像+条带（可靠且快，费一半盘，企业常用）
mdadm --create /dev/md0 --level=10 --raid-devices=4 /dev/sd[b-e]   # 建 RAID10
cat /proc/mdstat            # 看同步进度 / 状态
mdadm --detail /dev/md0     # 看成员盘
mdadm --manage /dev/md0 --fail /dev/sdb --remove /dev/sdb  # 标记坏盘、拔除
mdadm --manage /dev/md0 --add /dev/sdf                     # 加热备重建
# 故障：降级状态只读/写仍可，但失去冗余；重建窗口是二次故障高风险期
# 监控：mdadm --monitor 发邮件；云上优先用云盘多副本而非裸 RAID
```
