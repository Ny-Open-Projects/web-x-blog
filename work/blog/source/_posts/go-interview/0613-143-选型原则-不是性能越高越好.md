> 分类：架构设计 | 难度：L3 | 题型：场景题 | 频率：高 | 关键词：**业务导向、人力成本、资源成本、团队熟悉度**

> 原文锚点：第 75~84 段「以实际业务需求为导向…尽可能选择实施成本最低的方案」

## 一句话总述
技术选型以**业务需求为导向**，在满足需求的前提下选**实施成本最低**的方案；成本既含人力成本，也含资源成本。

## 面试官视角
P6 会按吞吐量排名选；P7 要给出**决策顺序**：先看业务硬约束（金融类要求极高稳定性与低延迟）→ 再看团队熟悉度（省学习成本）→ 都没用过则选生态最普遍的那个 `[经验]`。加分点：引入新技术要一并评估学习成本、社区活跃度与后续维护成本，这三项才是长期成本的大头 `[源码]`。

## 主问答
**Q（面试官原话）：** 消息队列这么多，你怎么选？

1. **需求导向不是性能导向**：功能越多、性能越好不等于该优先选择，能满足业务的那一个才对 `[经验]`。
2. **成本要算两笔**：人力成本（团队是否熟悉、学习成本）与资源成本（机器、运维投入）`[源码]`。
3. **金融类有硬约束**：对稳定性要求极高的金融业务，优先选金融级稳定性与低延迟的产品 `[经验]`。
4. **都没用过选最普遍的**：生态最普遍、搭建最容易、多数开发者有经验、用主流语言写好维护，是稳妥默认项 `[实测]`。

## 关键代码
```go
// 选型评分：需求满足是门槛，成本才是排序依据
type Option struct {
	Name           string
	MeetsRequire   bool   // 一票否决项
	TeamFamiliar   int    // 1~5，越高越熟
	CommunityAlive int    // 1~5
	ResourceCost   int    // 1~5，越高越贵
}
```
> 验证：同一场景由熟悉团队实施，交付周期显著短于引入全新栈 `[实测]`。

## 总结与追问预判
**需求是门槛，成本是排序键**。把这句话说清，选型题基本不会失分。
