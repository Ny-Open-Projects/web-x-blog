## 一句话总述
标记清除（Mark-Sweep）是最基础的 GC 算法：先 STW 从根集合出发标记可达对象，再回收不可达对象。它有三个硬伤——**必须 STW 暂停、需扫描整个堆、回收产生内存碎片**；Go 1.3 把"标记"与"清除"分离，让清除并发以缩短 STW。

## 面试官视角

- P5 能说清标记+清除两步；P6 能讲出三大问题（STW/扫整堆/碎片）；P7 能说出 1.3 如何分离标记清除、以及"为什么还不够"。
- 红旗：以为标记清除本身就能并发（基础版全程 STW）；忽略"扫描整堆代价大"这一点。
- 惊艳点：点出 1.3 之后"只标记阶段 STW、清除阶段并发"，但仍不够才引出 1.5 三色标记。

## 主问答
**Q（面试官原话）：** 标记清除算法是怎么工作的？有什么问题？
**A：**
1. **结论**：流程三步——① STW 暂停用户代码，从根对象出发遍历对象图、对可达对象做标记；② 解除 STW 恢复业务，后台**并发** sweep 回收未标记（不可达）对象；③ 重复直到生命周期结束。不可达对象（如图中对象 4、5）被回收。
2. **机制（三大问题）**：一是**必须 STW 暂停**业务，大堆时卡顿明显；二是标记需**扫描整个堆**，对象多时代价大；三是清除后空闲内存**易产生碎片**。
3. **边界（Go 优化）**：Go 1.3 把标记与清除**彻底分离**——仅标记阶段 STW，清除放到后台与普通 goroutine 并发（多核时放独立 CPU 核），STW 大幅降低，但离高性能后端要求仍有差距，才在 1.5 引入三色标记 `[经验]`。

## 关键代码
```go
// 标记清除（Mark-Sweep）核心流程示意
// 1) STW：暂停用户 goroutine
// 2) 从根集合(root)出发遍历对象图，可达对象 marked=true
// 3) 解除 STW，业务继续；后台并发 sweep 回收 marked=false 的对象
// 4) 回收产生的空闲内存易形成碎片
func sweep(heap []*obj) {
    for _, o := range heap {
        if !o.marked {
            free(o) // 不可达 → 回收
        } else {
            o.marked = false // 复位，供下一轮 GC
        }
    }
}
```
