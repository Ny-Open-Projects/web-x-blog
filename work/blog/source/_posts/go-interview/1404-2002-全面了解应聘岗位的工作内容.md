> 版本口径：**[2026 年·中国大陆]**，渠道与用法为方法论；拼图脚本为本机真跑 [实测]；涉及法条处已标注年份。本卡只讲「怎么把『这个岗位到底干什么』问清楚」；录用条件怎么读见 2001，谈薪见 2003，公司选择见 2004，试用期见 2005。

## 一句话总述
了解岗位工作内容，不是「知道它做什么」，而是回答三问——**我匹配吗 / 面试准备什么 / 符合职业规划吗**；方法八个字：**多渠道、交叉验证**。五个渠道并行：招聘启事（对外宣传，职责宽亮点满）、公司官网（雇主品牌，只讲好的）、求职网站（零散个体样本，薪资加班吐槽真伪混杂）、招聘会（能当场追问）、内部推荐（可信度最高但**有立场**）。关键动作是给每个维度找「第二个来源」：**哪个维度只有一个渠道说得清，就是单源孤证，片面风险最高**——这是本卡最该记住的判据。

## 面试官视角
- 考察意图：「你为什么选这个岗位？」「你怎么理解这个岗位？」是高频题——面试官测你有没有做过功课、动机是不是「随便投投」。
- 分档：P5 能说出岗位职责与技术栈；P6 能讲出多渠道交叉验证的方法论；P7 能说出「单源孤证」判据并主动给出「招聘启事没写、但我通过交叉验证知道」的信息。
- 红旗答案：把内部推荐的信息当「真实」（内推人有立场、只了解自己那条线）；泛泛说「贵公司平台好」。
- 惊艳点：报得出实测数字——样例 5 渠道 × 6 维度矩阵里，「团队协作」「发展前景」各只有一个具体来源 → **单源孤证 2 个、信息不足 0 个**，行动是优先给这两条补第二来源 [实测]。

## 主问答
**Q（面试官原话）：** 你为什么选这个岗位？你是怎么了解它的？
**A：**
1. **先讲岗位，再讲匹配，最后讲动机**：先把岗位理解讲对（核心产出、主要技术栈），再把自己的经历对上去（规模、解决的问题与岗位职责的重合度），最后补一句动机与三年方向的契合 [源码]。**岗位讲错了，匹配就无从谈起。**
2. **被问「怎么了解到这些的」如实说，还能加分**：主要看招聘启事和官网，然后在社区/求职网站核对团队与业务的说法，也找在职的朋友问过日常——把「多渠道交叉验证」当方法论讲出来，比背岗位信息更有说服力 [源码]。
3. **拼六维度**：职责范围 / 技术栈 / 团队协作 / 业务与用户 / 发展前景 / 薪资与加班，逐维度标「0 不知 / 1 模糊 / 2 具体」；哪个维度只有单一具体来源就优先补第二来源（尤其「内部推荐 vs 招聘启事」交叉）[实测]。
4. **时机**：了解岗位应在**面试前**做——投递前粗筛、面试前做深、offer 后确认细节；等拿到 offer 再了解，等于信息不足地参加完了面试（[法条：劳动合同法第 8 条，2026 年现行]——工作内容是单位法定必须如实告知的事项，你有权问清楚）[源码]。
5. **兜底话术**：「先讲岗位，再讲匹配，最后讲动机。」岗位讲准、经历对上，回答就立住了 [经验]。

## 关键代码
```go
// job_profile.go —— 岗位画像拼图：5 个渠道 × 6 个维度，看哪里是「单源孤证」
// 说明：这是「信息体检」工具，不是「岗位好不好」的评分器
package main

import "fmt"

func main() {
	sources := []string{"招聘启事", "公司官网", "求职网站", "招聘会", "内部推荐"}
	dims := []string{"职责范围", "技术栈", "团队协作", "业务与用户", "发展前景", "薪资与加班"}

	// rows = 渠道，cols = 维度；清晰度：0 完全不知道 / 1 只有模糊说法 / 2 有具体信息
	m := [][]int{
		{2, 1, 1, 1, 1, 1}, // 招聘启事：职责清楚，其余偏模糊
		{0, 0, 1, 2, 1, 0}, // 公司官网：业务清楚、团队略知
		{1, 1, 1, 1, 1, 2}, // 求职网站：薪资/加班有分享，其余零散
		{1, 2, 1, 1, 1, 1}, // 招聘会：技术栈能当场问
		{2, 2, 2, 2, 2, 2}, // 内部推荐：全维度都能问清（理想情况）
	}

	fmt.Println("=== 岗位画像拼图（清晰度 0=不知 / 1=模糊 / 2=具体）===")
	for i, s := range sources {
		fmt.Printf("%-8s", s)
		for _, v := range m[i] {
			fmt.Printf(" %-6d", v)
		}
		fmt.Println()
	}

	// 每维度：最高清晰度 + 提供「具体信息(2)」的来源数
	fmt.Println("\n--- 各维度体检 ---")
	insufficient, single := 0, 0
	for c, d := range dims {
		best, nConcrete := 0, 0
		for r := range sources {
			v := m[r][c]
			if v > best {
				best = v
			}
			if v == 2 {
				nConcrete++
			}
		}
		flag := ""
		if best < 2 {
			flag = "  <- 信息不足，需补"
			insufficient++
		} else if nConcrete <= 1 {
			flag = "  <- 单源孤证，片面风险高"
			single++
		}
		fmt.Printf("%-6s 最高清晰度=%d 具体来源数=%d%s\n", d, best, nConcrete, flag)
	}
	fmt.Printf("\n信息不足维度 = %d ；单源孤证维度 = %d\n", insufficient, single)
	fmt.Println("行动：先补「信息不足」，再对「单源孤证」找第二来源交叉验证（尤其内部推荐 vs 招聘启事）")
}
```

实测输出（go1.26.5 darwin/amd64）[实测]：矩阵中「团队协作」「发展前景」两列各只有一个 `2`（都来自内部推荐）→ 判为单源孤证；「职责范围」「技术栈」「业务与用户」「薪资与加班」各有两个及以上具体来源。**结论：0 个维度信息不足、2 个维度单源孤证 → 行动是给这两条补第二来源。**

## 总结与追问预判
一句话记忆：**「三问定目的、五渠道并行、单源孤证必补」**。追问预判：「这个岗位最核心的挑战是什么」——给出「招聘启事没写、但你通过多渠道知道」的信息（如历史技术债、数据规模、跨团队协作），直接证明做了功课。法律抓手：[法条：劳动合同法第 8 条，2026 年现行] 要求单位**如实告知**工作内容、条件、地点、职业危害、安全生产状况、劳动报酬——「以及劳动者要求了解的其他情况」这句是你问细节的依据。录用条件的三层拆解见 2001；敏感维度怎么影响决策见 2004 [边界]。

## ⚠️ 原文纠错
1. 「这些问题没有固定答案，只要政治正确，通常都没什么大问题」——双重问题：「只要…都没问题」过于乐观（答得空泛照样挂）；「政治正确」用词不当。正确说法：没有唯一标准答案，但**有判据——能不能用具体经历举证**。
2. 「通过内部员工可以了解到**真实的**工作内容」——过度乐观。内推信息质量最高但不等于「真实」：内推人有立场、通常只了解自己那条业务线，仍需与招聘启事、求职网站交叉验证。
3. 「在**拿到 offer 之后**全面了解工作内容，提前做好心理和技能准备」——时机偏晚。三个核心用途（判断匹配、准备面试、判断规划）全在面试前；offer 后该做的是确认细节。
4. 「第断自己是否适合」「良好的活作」「熟析解决问题的能力」「招聘和宣讲会」——转写崩坏，应为「判断」「合作」「熟悉」「招聘会和宣讲会」；「拉勾 boss 直聘」是拉勾 / BOSS 直聘两个平台。
