> 分类：Go 运行时 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**三色标记、对象丢失、两个必要条件、STW 快照**

> 原文锚点：第 1~17 段「对象的引用关系随时可能改变…这两种情况同时发生，就会出现对象被误杀」

## 一句话总述
并发标记时业务一边跑一边改引用图，可能把本该存活的对象留在白色集合里被回收。误杀需要**两个条件同时成立**：① 白色对象被黑色对象引用；② 它到灰色对象的可达路径同时断开。

## 面试官视角
这题是三色标记的"存在性证明"——先讲清为什么会错，后面的写屏障才有落脚点。P6 能复述场景；P7 能**精确给出两个必要条件**并说明"打破任意一个即可"，还知道并发标记至少在开头与结尾需要极短 STW 做快照。红旗：只答"要 STW"却说不出 STW 到底在防什么 `[经验]`。

## 主问答
**Q（面试官原话）：** 标记和业务一起跑，会有什么问题？

1. **结论**：黑色对象已扫描完毕不再回看，白色对象若被黑色引用、又失去了来自灰色对象的可达路径，就会在清除阶段被回收，这是必须防住的**漏标**。
2. **场景**：对象 6 已标黑且完成扫描，此时对象 2 对对象 3 的指针被删除，同时对象 6 新增引用对象 2；对象 2 仍是白色且没人再扫，于是 2 和 3 一起被回收 `[经验]`。
3. **条件拆解**：条件①（黑引用白）与条件②（灰到该白的可达关系断开）**同时满足**才误杀，因此任何屏障只要打破其一即可保证安全。
4. **朴素解法**：全程暂停业务直到标记完成——正确性有了，但停顿不可接受，这才引出写屏障 `[经验]`。

## 关键代码
```go
// 语义示意：两个条件同时成立且无屏障时，下游会被误回收
type Node struct{ Next *Node }

func rewire(a, b *Node) {
    a.Next = nil      // 灰 -> 白 断开   （条件②）
    black.Next = b    // 黑 -> 白 新增   （条件①）
}
```

## 总结与追问预判
答题骨架：**两个必要条件，打破任一即可**。下一问必然是"强/弱三色不变式"（见 808）。
