## 一句话总述
`go build -x` 打印底层命令、`go tool compile` 单独编译单包；Go 1.10+ 用 build cache 缓存编译单元，cgo 关默认静态链接、开则动态链接。

## 面试官视角
- 意图：是否会在编译出问题时"下钻"到工具链，懂缓存与链接差异。
- P5 会用 -x / P6 说清 build cache 与 cgo 链接策略 / P7 知 cache 失效场景、交叉编译链接差异。
- 红旗：以为 `go build` 每次都全量重编译；以为有 cgo 也一定静态。
- 惊艳点：无 cgo 时 `go build` 默认静态链接（单一可执行、易分发），`CGO_ENABLED=1` 引入 libc 才动态 —— 验证 `[源码]`。

## 主问答
**Q（面试官原话）：** 编译出问题怎么排查？Go 默认静态还是动态链接？
**A：**
1. **结论**：`go build -x` 看实际调用的 compile/link 命令，`go tool compile` 可单独编译某包；Go 1.10+ 用 build cache 按内容哈希缓存编译结果 `[源码]`。
2. **机制**：build cache 以输入(源码/flag/依赖)哈希为键，命中即复用，所以"改一行只重编受影响的包"；链接阶段无 cgo 默认静态、有 cgo 走动态链接 `[源码]`。
3. **边界**：`-a` 强制重编、清 `$GOCACHE` 可让缓存全失效；交叉编译时静态/动态还受目标平台 C 工具链影响。
**加分层：** 静态链接方便容器分发，但引入 cgo 后会依赖宿主机 libc 版本，部署要小心。
