> 分类：Go 并发 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**单向 channel**/**隐式转换**/**编译期**
> 原文锚点：第 1~10 段「单向只读 channel…双向可隐式转单向，单向不可转双向」

## 一句话总述
channel 按方向分双向、只读(`<-chan`)、只写(`chan<-`)；**双向可隐式转单向，单向不可转双向，单向之间也不可互转**；对只读写、对只写读都编译报错。

## 面试官视角
- 考察意图：是否理解 channel 方向是编译期类型系统层面的约束，而非运行期行为。
- 分档：P5 知有单向 channel；P6 懂箭头方向与转换规则；P7 能讲清"方向是类型、编译期检查"。
- 红旗答案：把 `chan<-` 说成接收、`<-chan` 说成发送；认为单向能转回双向。
- 惊艳点：**单向约束在编译期**，运行时无额外开销——这是类型系统帮你在编译阶段挡住误用 `[源码]`。

## 主问答
**Q（面试官原话）：** Go 的单向 channel 是什么？怎么转换？
**A：**
1. **结论**：接收型 `<-chan T`（箭头在 chan 左）、发送型 `chan<- T`（箭头在 chan 右）；双向 `chan T` 可隐式转单向，反向不可。
2. **机制**：方向是**类型的一部分**，编译器在类型检查阶段就禁止"对只读 channel 写 / 对只写 channel 读"，这类错误编译期即报错，不拖到运行期 `[源码]`。
3. **边界**：单向之间（`<-chan` 与 `chan<-`）不能互转，也不能转回双向；转换只在"双向→单向"单向成立，且是隐式的（赋值时自动收窄）。

**加分层：** 函数参数用单向 channel 能强制调用方只按约定方向使用，是 API 设计的编译期契约。

## 关键代码
```go
func consume(ch <-chan int) { // 只收，编译期保证不会误写
    v := <-ch
    _ = v
}
func produce(ch chan<- int) { // 只发
    ch <- 1
}
// 误用：ch <- 1 在 consume 内、<-ch 在 produce 内 → 编译报错
```

## 总结与追问预判
方向是编译期类型约束，无运行期成本；这是 API 契约的利器。追问常接"缓冲/非缓冲区别"，是下一张卡。

## ⚠️ 原文纠错
1. 原文"单向只读与单向只写的箭头方向**始终一致**"表述模糊：精确应为接收 `<-chan`（箭头在 `chan` 关键字**左**）、发送 `chan<-`（箭头在 `chan` 关键字**右**），二者方向相反而非一致 `[经验]`。
