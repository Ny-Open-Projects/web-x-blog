> 覆盖源 18-31 的变体延伸：N-Step/C-N-Step 的防插队机制、SCAN 家族的等待时间分布、饥饿的成因与三种治理思路、SSD/NVMe 时代调度器的退化与 Linux 块层现状。主卡已给七族主线，本附录做变体与现代语境深挖。

## 思路与架构

```text
磁盘调度算法的"病-药"演进链
├─ FCFS: 病=寻道 640 [实测] -> 药=贪心
├─ SSTF: 病=远端饥饿 -> 药=定向扫描
├─ SCAN: 病=边界空跑 + 中部磁道偏好
│   ├─ 药1: LOOK (到最近请求折返, 省空跑)
│   ├─ 药2: C-SCAN (回程不服务, 等待均匀)
│   └─ 药3: N-Step (请求分批, 防新请求插队)
├─ 饥饿治理三思路
│   ├─ 定向循环 (SCAN 家族)
│   ├─ 分批锁定 (N-Step: 新请求等下一轮)
│   └─ 老化加权 (aging: 等待越久优先级越高)
└─ SSD 语境: 无寻道 -> 算法退化为合并 (merging)
    Linux 块层: none/kyber/mq-deadline/bfq
```

## 方案取舍
- **N-Step 的防插队是「批处理锁」思想**：SCAN 家族仍有偏置——磁头附近的新请求总能被优先扫到，持续的新请求流会把远端老请求无限推后。N-Step 把请求**分代**：磁头只服务当前代（已有请求），新请求进下一代等下一轮——用「一代一轮」的锁把插队封死。C-N-Step 再叠加 C-SCAN 的单向循环。与操作系统的**多级反馈队列**同构：都是「新老分批 + 队内规则」，防止流量形态操纵调度 [经验]。
- **SCAN 家族的等待时间分布**：SCAN 单向扫，磁道位置决定等待——刚扫过的要等近一整轮，将扫到的立等可取；C-SCAN 的单向+立即回跳把所有磁道的最大等待拉平到「一轮」，**用一点平均寻道换均匀延迟**——延迟敏感场景（如日志盘多写者）选 C-SCAN，吞吐敏感选 LOOK [经验]。
- **SSD 时代调度器的退化**：无机械寻道后，「最短寻道」失去优化对象——剩余可优化的是**写放大与合并**。Linux 块层的现代调度器：**none**（NVMe 直通，靠硬件深队列）、**kyber**（低延迟目标队列）、**mq-deadline**（deadline 保底防饿）、**bfq**（公平带宽，交互友好）——**「deadline 防饿」取代「最短寻道」成为主矛盾**，电梯思想以 deadline 的形态活了下来。答题收尾必报这层，否则像「上个时代的人」[经验]。
- **饥饿治理的通用三思路（可迁移）**：定向循环、分批锁定、老化加权——不止磁盘：CPU 调度的 aging、锁实现的公平模式（Go mutex 饥饿模式）、MQ 消费的公平分发，都是同一组思想的变体。**把算法题答成设计模式题**，是从「背 OS」到「懂系统」的跨维信号 [经验]。

## 答题技巧
- 用「病-药」链讲演进：每报一个算法先说它治上一个的什么病——FCFS 慢→SSTF 饿→SCAN 空跑→C-SCAN 不均匀→N-Step 插队 [经验]。
- 报 [实测] 三数字：FCFS 640 / SSTF 236 / SCAN 331（磁头 53 经典队列）——数学功底立现 [实测]。
- 被问「SSD 还要吗」→ 寻道消失、调度退化成合并，报 Linux none/kyber/mq-deadline/bfq 四调度器现状 [经验]。
- 被问「饥饿怎么根治」→ 三思路 + 迁移例（Go mutex 饥饿模式/MQ 公平分发）——算法题跨维到设计层 [经验]。
- 主动边界到 `1831-disk-scheduling`（七族主线）、`1811-io-reading-priority.deep`（IO 性能判读）、`1818-raid-selection.deep`（RAID 选型）、`1014-mutex-mode-switch`（mutex 饥饿模式——同一思想的 Go 落地），构成「调度与公平」专题 [边界]。

## 细节与核心 API

```bash
# 普通调度 CFS 也可能“饥饿”：长耗时 batch 任务压低其它 vruntime 增长，交互任务被拖
# 治理：把耗时任务 renice 调低；或用 cgroup cpu 限额隔离
# 实时变体：SCHED_FIFO 无时间片，高优先级可永久饿死低优先级（含普通进程）
chrt -r 20 cmd             # SCHED_RR 轮转，避免 FIFO 单任务独占
# SSD 语境：随机 IO 不再昂贵，CFS 下 IO 等待（D 状态）不再像 HDD 那样长期阻塞
#  IO 调度器：HDD 用 mq-deadline/bfq；SSD/NVMe 用 none（noop，交给设备自身队列）
cat /proc/sys/block/sda/queue/scheduler   # 查看/选择
echo mq-deadline > /sys/block/sda/queue/scheduler
# 要点：SSD 下 CPU 调度与 IO 调度都要相应“去机械盘假设”
```
