## 一句话总述
切片底层数组**长度固定**，append 超容量时必须**申请新内存、把旧元素 `memmove` 拷到新数组、并预留 buffer**，代价是内存分配 + 拷贝。已知大致容量时，用 `make([]T, 0, cap)` **预分配**可避免反复扩容拷贝，显著提升性能。

## 面试官视角
- 意图：能否把"扩容代价"落到工程优化（预分配）。
- P5 知底层数组固定、扩容要拷贝；P6 知 make 预分配避免频繁扩容；P7 知"拷贝大小=旧 len、预留 buffer 是为 amortized 成本"。
- 红旗：频繁 append 不知预分配；或以为切片能原地无限增长。
- 惊艳点：点出"拷贝的是旧 len 个元素、新 cap 只预留不立即占用，amortized 摊还后单次 append 仍近似 O(1)" `[边界]` 见 923（扩容换地址）、907-slice-reslice-share（底层共享）。

## 主问答
**Q（面试官原话）：** 切片扩容有什么代价，怎么优化？
**A：**
1. **代价来源**：底层数组长度固定，append 超 cap 时 runtime 分配新数组、把**旧 len 个元素** `memmove` 拷过去，再写新元素——有内存分配 + 拷贝开销。
2. **预留 buffer**：growslice 算出的新 cap 大于所需 len，预留空间减少后续扩容次数（amortized 摊还）。
3. **优化：预分配**：已知容量上界时用 `make([]T, 0, n)` 一次性给足，避免循环中反复扩容拷贝。
4. **陷阱**：大切片 append 小数据会长期持有大底层数组（retention），必要时用副本切断（见 923）。

## 关键代码
```go
// 示意：预分配避免频繁扩容（未验证）
// 反例：循环中反复扩容拷贝
var s []int
for i := 0; i < 10000; i++ {
    s = append(s, i) // 可能多次扩容
}
// 正例：已知上界，一次预分配
s := make([]int, 0, 10000)
for i := 0; i < 10000; i++ {
    s = append(s, i) // 零扩容
}
```
