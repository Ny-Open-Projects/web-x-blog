> 分类：内存与 OS / 文件系统 | 难度：L2 | 题型：机制题 | 频率：高 | 关键词：**用户缓冲区** / **page cache** / **延迟写回** / **write 非落盘** / **脏页**
> 原文锚点：第 2~17 段「write→用户空间缓冲区→内核page cache→更新元数据→延迟写回磁盘…write返回不代表落盘」

## 一句话总述
进程用缓冲 IO 写文件，数据依次经过**用户空间缓冲区 → 内核 page cache →（延迟写回）磁盘**；`write()` 返回成功只代表数据进入了 page cache，并不保证落盘——真正刷盘由内核按脏页阈值/定时延迟完成，目的是减少磁盘 IO、提升吞吐。

## 面试官视角
- 意图：是否清楚 `write()` 返回 ≠ 数据落盘，以及 page cache 在其中的位置。
- P5 知 write 进 page cache；P6 说清用户缓冲→page cache→延迟写回两段拷贝；P7 知脏页阈值触发、write 返回与落盘解耦。
- 红旗：以为 `write()` 返回就是落盘；不知道 page cache 属内核、跨进程可见。
- 惊艳点：无论什么语言，`write` 系统调用实际操作的是 page cache，磁盘 IO 被"延后批量"了——这是所有文件写快的根因 `[经验]`。

## 主问答
**Q（面试官原话）：** 调用 write 写文件，数据是直接写到磁盘吗？
**A：**
1. **用户缓冲→page cache**：内核把用户空间缓冲区的数据拷贝进内核 page cache（文件在内存中的缓存副本）`[源码]`。
2. **更新元数据**：写入同时更新文件大小、修改时间等元数据。
3. **延迟写回**：脏页（已改未写回）累积到阈值或定时，内核才批量写回磁盘，减少 IO 次数。
4. **write 返回≠落盘**：`write()` 成功仅表示数据入了 page cache，磁盘写入是异步延迟的——进程崩溃也不影响已在 cache 中的数据 `[边界]` 见 144。

## 关键代码
```go
// 示意，未验证：write 只把数据送入 page cache，f.Sync() 才真正刷盘
package main
import ("os"; "fmt")
func main() {
    f, _ := os.CreateTemp("", "demo")
    defer f.Close()
    n, _ := f.Write([]byte("hello")) // 数据进入 page cache，write 即返回
    fmt.Println("write 返回:", n, "(此时未必落盘)")
    // f.Sync() // 取消注释才强制把 page cache 写回磁盘并等待完成
}
```

## 总结与追问预判
- write → page cache → 延迟刷盘；write 返回非落盘，跨进程可见靠内核 cache。
- 预判：崩溃是否丢数据 → 见 1835；强制落盘 → 见 1835；page cache 通用行为 → 见 144。
