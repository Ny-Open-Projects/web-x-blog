> 分类：Go 并发 | 难度：L3 | 题型：细节题 | 频率：中 | 关键词：**64KB、元素尺寸、复制成本、直接部分、缓冲队列、传指针**

> 原文锚点：第 52~62 段「channel中传输数据的大小呢是有限制的…它提示我们这个channel元素的类型太大了，它大于六十四KB，也就是超过六十四KB呢，我们这个channel是拒绝执行的…元素的值是需要经过复制的，在一个值从一个channel中传递到另一个channel的过程中，这个值至少会被复制一次…如果这个传递的值在某个channel的缓存队列中停留过，那这个值在传递过程中将会被复制两次…只有它的直接部分被复制。所以为了避免过大的复制成本，官方编译器中对channel元素的尺寸进行了限制」

## 一句话总述
channel 的**元素类型尺寸有上限**：超过 **64KB** 时编译器/运行时**拒绝执行**；原因是 channel 传值是**按值复制**的——至少要复制**一次**（发送方 → 接收方），若中途在**缓冲队列**里停留过就要复制**两次**（发送方 → 队列、队列 → 接收方），且**只有值的直接部分被复制**；官方用尺寸上限来避免过大的复制成本。

## 面试官视角
- 考察意图：是否知道 channel 传值有复制开销，以及这个开销出现的**次数与位置**。
- 分档：P5 知道 channel 传值会复制；P6 能说出 **64KB 上限**；P7 能讲清**一次 vs 两次复制**的分界条件（是否经过缓冲队列），以及"**只复制直接部分**"的含义。
- 红旗答案：以为 channel 传的是引用/零拷贝；以为大 struct 走 channel 没有代价。
- 惊艳点：**无缓冲 channel 是 1 次复制，有缓冲 channel 是 2 次复制**——缓冲虽然解耦了收发节奏，却**多付了一次复制成本** `[源码]`。

## 主问答
**Q（面试官原话）：** 用 channel 传一个很大的结构体有什么问题？

1. **结论**：channel 中传输的**数据大小有限制**，元素类型**大于 64KB** 时会被拒绝执行；日常编程要**避免用 channel 传输过大的数据** `[源码]`。
2. **至少复制一次**：channel 传递元素时**元素的值需要经过复制**；一个值从一个 channel 传递到另一个 channel 的过程中，**至少会被复制一次** `[源码]`。
3. **缓冲队列导致两次**：如果这个传递的值在某个 channel 的**缓存队列中停留过**，那么它在传递过程中**会被复制两次**——第一次发生在**发送协程把值推入缓冲队列**时，第二次发生在**接收协程从缓冲队列取出**时 `[源码]`。
4. **只复制直接部分**：当一个 channel 的值被传递时，**只有它的直接部分被复制**（与赋值、函数调用传参一致）——指针/切片头部/字符串头部这类"直接部分"被复制，其指向的底层数组**不随复制而拷贝** `[源码]`。
5. **限制的目的**：**为了避免过大的复制成本**，官方编译器对 channel 元素的尺寸做了限制 `[源码]`。
6. **工程解法**：要传大对象时**传指针**（或传切片、传索引），让被复制的"直接部分"固定为一个指针宽；同时注意指针传递后**不要在被传递侧原地修改**以免引入新的数据竞争。

**加分层：** 判断代价不要只看 struct 的字段数，要看**直接部分的大小**：`[4096]byte` 数组 4096 字节×1 = 4KB 是直接部分；改成 `*[4096]byte` 后直接部分只有 8 字节，复制成本立刻降到指针级别。

## 关键代码
```go
// 1) 超过 64KB：编译/运行时拒绝（原文示例 4096 个 int64 = 32KB 量级，超限即报错）
type Big struct{ buf [4096]int64 } // 32KB，已接近上限
// ch := make(chan Big, 1) // 若元素类型 >64KB 会报 "channel element type too large"

// 2) 正确姿势：传指针，直接部分只有一个指针宽
type BigOK struct{ buf [4096]int64 }
ch := make(chan *BigOK, 1)
ch <- &BigOK{}
b := <-ch // 复制的是 8 字节指针，底层数组不拷贝

// 3) 只复制直接部分：切片头被复制，底层数组共享
s := make([]int, 1000)
sch := make(chan []int, 1)
sch <- s
got := <-sch // 复制 slice header（ptr+len+cap），底层数组同一份

// 4) 无缓冲 vs 有缓冲的复制次数差异（示意）
unbuf := make(chan *BigOK)     // 无缓冲：1 次复制
bufc := make(chan *BigOK, 1)   // 有缓冲：推入 + 取出 = 2 次复制
```

## 总结与追问预判
**面试官常接着问"那有缓冲是不是一定更好"**——不一定：缓冲**多一次复制**、多一块内存，换来的是收发解耦与削峰。回答要落到"**用缓冲换吞吐，用无缓冲换同步语义与更低的一次复制**"。另一条常见追问是"传指针会不会有竞争"——会，指针被多个 goroutine 共享后读写同一块内存需要额外同步，这是传指针的代价。
