> 分类：计算机网络 / TCP | 难度：L4 | 题型：原理题 | 频率：高 | 关键词：**字节流、粘包、拆包、消息边界、顺序交付、去重**

> 原文锚点：第 30~33 段「用户的消息通过 TCP 协议传输的时候，消息就可能会被操作系统分组成多个 TCP 报文…接收方的程序如果不知道消息的边界，它是无法读出一个有效的用户消息的…TCP 报文是有序的，当前一个 TCP 报文没有收到的时候，即使先收到了后面的 TCP 报文，那么它也是不能交给应用层去处理的。同时被重复的 TCP 报文会自动丢弃」

## 一句话总述
TCP 是**字节流**协议：发送方的消息可能被**拆分或合并**成多个报文，协议本身**不保留消息边界**；它保证的是**字节按序交付且不重复**，而「一条消息」的边界必须由应用层自己界定。

## 面试官视角
P6 会说「TCP 是字节流」；P7 必须讲清**三个推论**：可能被分组（拆包/粘包的根源）、无边界导致应用层需自定协议、以及顺序交付与自动去重是字节流可靠性的具体体现——并能给出**定长 / 分隔符 / 长度前缀**三种边界方案。

## 主问答
**Q（面试官原话）：** TCP 是字节流协议，这句话到底意味着什么？

1. **消息会被分组**：用户的消息通过 TCP 传输时，**可能被操作系统分组成多个 TCP 报文** `[源码]`。
2. **没有消息边界**：接收方程序**如果不知道消息边界，就无法读出一条有效的用户消息** `[源码]`。
3. **这就是粘包/拆包的根源**：TCP 只保证字节正确送达，**不保证一次读写对应一条完整消息** `[经验]`。
4. **顺序交付**：TCP 报文是有序的，**前一个报文未收到时，即使先收到后面的报文，也不能交给应用层处理** `[源码]`。
5. **重复自动丢弃**：**重复的 TCP 报文会被自动丢弃**，应用层不会看到重复字节 `[源码]`。
6. **应用层要自己定边界**：常用做法是**固定长度、分隔符、或长度前缀（Length-Prefix）** `[经验]`。
7. **与 UDP 对比**：UDP 保留消息边界（一次一报），而 TCP 只是一串无边界字节 `[经验]`。

## 关键代码
```go
package main

import (
	"bufio"
	"encoding/binary"
	"fmt"
	"io"
	"net"
)

// 方案一：长度前缀（最常用）——先读 4 字节长度，再按长度读消息体
func readFrame(r io.Reader) ([]byte, error) {
	var head [4]byte
	if _, err := io.ReadFull(r, head[:]); err != nil {
		return nil, err
	}
	n := binary.BigEndian.Uint32(head[:])
	buf := make([]byte, n)
	if _, err := io.ReadFull(r, buf); err != nil { // 必须读满，不能只读一次
		return nil, err
	}
	return buf, nil
}

// 方案二：分隔符 —— 适合文本协议
func readLine(r *bufio.Reader) (string, error) {
	return r.ReadString('\n')
}

func main() {
	conn, err := net.Dial("tcp", "127.0.0.1:8080")
	if err != nil {
		fmt.Println("跳过演示：需要本机 8080 端口的演示服务：", err)
		return
	}
	defer conn.Close()
	_, _ = conn.Write([]byte("hello")) // 写入字节，不携带任何边界信息
}
```

## 总结与追问预判
**「TCP 不保留消息边界」是字节流的核心，也是粘包问题的唯一根源**。答题务必给出长度前缀等应用层解法，否则只停留在现象描述。报文头如何支撑顺序与去重，见同批 1840-tcp-header。

## ⚠️ 原文纠错
1. 事实核校：消息被分组成多个报文、无边界则无法读出有效消息、报文有序且前序未到不交付、重复报文自动丢弃——均与 TCP 字节流语义一致 `[经验]`。
2. 补充：原文未展开应用层解法，实际工程中最常用的是**长度前缀（Length-Prefix）**方案，配合 `io.ReadFull` 保证读满整帧；仅用一次 `Read` 取字节是最常见的错误写法 `[经验]`。
3. 崩坏词归一：源码将字节流、分组、报文、乱序等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
