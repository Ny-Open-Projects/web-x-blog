> 分类：Go/并发 | 难度：L2 | 题型：概念题 | 频率：中 | 关键词：**令牌桶限速率**/**信号量限并发**/**channel妙用**/**漏桶**

> 原文锚点：第 1~3 段「回顾令牌桶限流器 + channel 对请求限速，本节再回顾」

## 一句话总述
同样用 channel，两种经典限流语义易混：**令牌桶 = 限速率**（按固定速率放令牌，控制「每周期最多 N 请求」），**信号量 = 限并发**（channel 容量 = N，控制「最多 N 个同时在飞」）。前者管「多快」、后者管「多少」；还有漏桶（恒速流出、突发被缓冲）与分布式令牌桶（Redis）等不同形态。一句话背法：**「令牌桶=限速率(每周期最多N请求，允许积存突发)；信号量=限并发(容量=N，最多N个在飞)；前者管多快、后者管多少」**。

## 面试官视角
这是考察"能否区分速率限制与并发限制两种语义并据此选型"的题。
- **P5**：知道 channel 能限流。
- **P6**：能说清令牌桶 vs 信号量。
- **P7**：知道漏桶/滑动窗口/分布式形态与选型。
- **红旗**：把限速率和限并发混为一谈；认为信号量也能平滑突发速率。
- **惊艳点**：点出"令牌桶允许短时突发（桶内有积存令牌）、信号量只卡在飞数"，以及"单机 channel 限流无法跨实例、分布式须 Redis" `[经验]`。

## 主问答
**Q（面试官原话）：** 用 channel 既能限速又能限并发，两者啥区别？

**先铺垫（由浅入深第 1 层）**：channel 是个"容器 + 阻塞"原语，把它当令牌桶用时控制的是"时间维度上放行的节奏"，当信号量用时控制的是"空间维度上同时在飞的个数"。同一个 `chan struct{}`，语义全看你往里写、什么时候写。

1. **令牌桶 = 限速率（第 2 层·机制）**：按固定速率生成令牌、取走才放行，控制「每周期最多 N 请求」，允许桶内积存令牌短时突发（见 1016 令牌桶）`[经验]`。
2. **信号量 = 限并发（第 3 层）**：channel 容量 = N 表示最多 N 个 goroutine 同时在飞，控制「并发数」而非「速率」（见 1015 信号量）`[经验]`。
3. **其他形态（第 4 层）**：漏桶恒速流出、突发被缓冲排队；滑动窗口/分布式场景用 Redis+令牌桶或滑动窗口计数（见 108）`[经验]`。
4. **跨实例（第 5 层）**：单机 channel 限流无法跨实例一致，多副本须集中式限流（Redis/网关）`[边界]`。
5. **选型（第 6 层）**：要「平滑 QPS」用令牌桶/漏桶，要「保护下游并发」用信号量 `[经验]`。

## 关键代码
```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	// ① 信号量：容量=N，控制"最多 N 个同时在飞"（限并发，不论速率）
	const maxConcurrency = 2
	sem := make(chan struct{}, maxConcurrency)
	var wg sync.WaitGroup
	for i := 0; i < 5; i++ {
		sem <- struct{}{} // 占一个并发位
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			defer func() { <-sem }() // 释放并发位
			time.Sleep(100 * time.Millisecond)
			fmt.Println("job", id, "in-flight:", len(sem))
		}(i)
	}
	wg.Wait()

	// ② 令牌桶：定时写令牌，读即消费，控制"每周期最多 N 请求"（限速率）
	rateLimit := 2
	quota := make(chan struct{}, rateLimit)
	go func() {
		tick := time.NewTicker(500 * time.Millisecond)
		for range tick.C {
			quota <- struct{}{}
		}
	}()
	for i := 0; i < 4; i++ {
		<-quota // 无令牌则阻塞，控制速率
		fmt.Println("request", i, "at", time.Now().Format("15:04:05.000"))
	}
}
```

## 总结与追问预判
**背这三句就够**：① **令牌桶 = 限速率（每周期最多 N，可突发）**；② **信号量 = 限并发（容量 N，最多 N 在飞）**；③ **前者管多快、后者管多少，别混用**。
**预判追问**：
- 「令牌桶实现？」→ 容量=峰值 channel + 定时写令牌（见 1016 令牌桶）。
- 「信号量实现？」→ channel 容量=N 或官方 semaphore（见 1015）。
- 「分布式怎么一致？」→ Redis 令牌桶/滑动窗口（见 108）。
