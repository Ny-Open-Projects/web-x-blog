> 分类：并发模型 | 难度：L2 | 题型：陷阱题 | 频率：高 | 关键词：**闭包、循环变量、估值时机、变量捕获**

> 原文锚点：第 12~37 段「直接 go 打印是零到九…放到匿名函数里打印是十个十」

## 一句话总述
`go f(i)` 与 `go func(){ f(i) }()` 的差别在**估值时机**：前者参数在 go 语句执行时立即求值，后者闭包捕获的是**变量本身**，要等真正执行时才读。

## 面试官视角
P6 会背"循环变量要复制"；P7 要说清**捕获的是变量不是值** `[经验]`。加分点是为什么最后读到 10 而不是 9：`i++` 在第十轮结束后仍执行了一次，循环退出时 i 已是 10，此时 goroutine 才读到它 `[源码]`。再补一句：这个坑不只 goroutine，凡是**延迟执行**的闭包都中招。

## 主问答
**Q（面试官原话）：** 循环里起 goroutine 打印 i，为什么全是 10？

1. **两种写法估值时机不同**：`go fmt.Println(i)` 的参数随 go 语句一起求值，所以打出 0~9（顺序随机）；`go func(){...}()` 里 i 要等函数体跑起来才读 `[实测]`。
2. **闭包捕获的是变量**：匿名函数引用外层变量时，共享同一块内存，不是拷贝一份值 `[源码]`。
3. **循环变量被复用**：为省内存、提效率，循环迭代变量始终指向同一个地址，每一轮只是改写它的值 `[经验]`。
4. **读到的是退出时的值**：循环跑完时 i 已被自增到 10，晚一步执行的 goroutine 读到的自然是 10 `[源码]`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| Go 1.21 及以前 | 循环变量复用 | 必须手动复制，否则全是末值 |
| Go 1.22 起 | 每次迭代新变量 | 需 go.mod 声明 go 1.22 才生效 |
| 任意版本 | 闭包语义未变 | 捕获变量这一条始终成立 |

## 关键代码
```go
for i := 0; i < 10; i++ {
	go fmt.Println(i)        // 参数立即求值：0~9，顺序随机
}
for i := 0; i < 10; i++ {
	go func() { fmt.Println(i) }() // 闭包延迟读：通常十个 10
}
```
> 验证：第一段输出 0~9（乱序），第二段输出十个 10 `[实测]`。

## 总结与追问预判
**捕获变量而非值，加上延迟执行，就是 bug 的全部**。下一步必问怎么修（见循环变量复制那张卡）。
