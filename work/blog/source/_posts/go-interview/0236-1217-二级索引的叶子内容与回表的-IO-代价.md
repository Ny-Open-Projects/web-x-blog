> 分类：数据库 / MySQL 索引 | 难度：L3 | 题型：原理题 | 频率：高 | 关键词：**二级索引、辅助索引、回表、顺序IO、随机IO、目录项、页号**

> 原文锚点：第 19~28、48~51 段「非主键生成的索引树呢它的叶子节点并不是完整的一行记录，而只是两个列的值…一个列呢是非主键字段列的值，另一个列呢就是主键列的字段值…目录项记录里面存放的就是索引字段和它所在的页号…这个过程呢我们就称为回表…访问二级索引呢需要一次顺序IO，而访问聚集索引树呢需要一次随机IO」

## 一句话总述
二级索引的 B+树**叶子节点只存「索引列值 + 主键值」**（不是完整行），**目录项**也从"主键 + 页号"变成"**索引列 + 页号**"；要拿其他字段必须**回表**——回表 = **一次顺序 IO（扫二级索引）+ 一次随机 IO（按主键回聚簇树）**。

## 面试官视角
- 考察意图：能否从"叶子存什么"推出"为什么会有回表"，并说清回表的**IO 性质**。
- 分档：P5 知道二级索引要回表；P6 能说清叶子存"索引列 + 主键"；P7 能点出**目录项也从主键变成索引列**，并区分**顺序 IO 与随机 IO**。
- 红旗答案：以为二级索引叶子存的是"行地址/指针"（InnoDB 不是，存的是**主键值**）；以为回表只有一次 IO。
- 惊艳点：**回表是随机 IO**——因为要回的主键**散落在聚簇索引的多个数据页**，这也是大范围回表会被优化器放弃、改走全表扫描的根本原因 `[源码]`。

## 主问答
**Q（面试官原话）：** 二级索引的叶子节点存的是什么？回表到底慢在哪？

1. **结论**：二级索引（辅助索引/非聚簇索引）是**一棵独立的 B+树**，叶子节点**只存两个列的值**——**索引列的值**和**主键列的值**，不包含其他字段 `[源码]`。
2. **叶子内容**：以 `name` 建索引，叶子上就只有 `name` 与主键 `id` 两个列的值，**不会有 `age` 的值** `[源码]`。
3. **目录项的变化**：聚簇索引的目录项是"**主键 + 页号**"，二级索引的目录项变成"**索引字段 + 页号**"——例如 `name` 索引的目录项存的是**最小的 name 及其所在的数据页**，排序也按 **name 字段的字符集顺序**而非主键顺序 `[源码]`。
4. **回表的触发**：定位到二级索引叶子后，**若要取索引字段和主键之外的字段**，就必须拿这个主键值回到聚簇索引查完整记录，这个过程叫**回表**；需要回表才能拿全字段的索引称为**二级索引** `[源码]`。
5. **IO 代价**：回表一共要**查两棵 B+树**——**访问二级索引是一次顺序 IO**（按当前索引字段顺序扫），**访问聚簇索引是一次随机 IO**（要回的主键可能分散在多个数据页）`[源码]`。
6. **边界**：**只取索引字段时不需要回表**（覆盖索引）；二级索引**一个表可以有多个**，且**物理存储不连续、只是逻辑连续**，与聚簇索引的"物理连续"相对 `[源码]`。

**加分层：** 优化器拒绝用二级索引的常见情形就是"**回表行数太多**"——随机 IO 成本超过全表顺序扫描时，会直接走全表。

## 关键代码
```sql
-- 1) 二级索引：叶子只有 (name, id)，取 age 必须回表
ALTER TABLE userbig ADD INDEX idx_name (name);
EXPLAIN SELECT id, name, age FROM userbig WHERE name = 'name10';  -- 需回表

-- 2) 覆盖索引：只取索引列 + 主键，Extra 出现 Using index，不回表
EXPLAIN SELECT id, name FROM userbig WHERE name = 'name10';

-- 3) 回表行数过多时，优化器可能放弃二级索引改走全表
EXPLAIN SELECT * FROM userbig WHERE name > 'name1';   -- 可能 type=ALL

-- 4) 用 FORMAT=JSON 观察回表成本估算
EXPLAIN FORMAT=JSON SELECT id, name, age FROM userbig WHERE name = 'name10'\G
```

## 总结与追问预判
**"回表为什么慢"的标准答案是：随机 IO**。二级索引按索引列顺序扫是顺序 IO，但拿到的主键在聚簇索引里**并不相邻**，回表就退化成逐行随机 IO。追问常接"怎么避免回表"——**覆盖索引**（把要取的列都放进联合索引）、**索引下推**（5.6+ 在索引层先过滤，减少回表行数）、或**限制返回行数**（LIMIT / 游标分页，见 `1246-*` 那批）。

## ⚠️ 原文纠错
1. 事实核校：二级索引叶子存"索引列 + 主键值"、目录项存"索引列 + 页号"、回表需查两棵 B+树、二级索引顺序 IO + 聚簇索引随机 IO、二级索引物理不连续——均与 InnoDB 实现一致 `[经验]`。
2. 补充：原文称"辅助索引叶子节点采用指向表中记录在数据页中的指针的方式"，**InnoDB 实际存的是主键值而非物理指针**；存主键值的代价是要再走一次聚簇索引查找，好处是行被移动/页分裂时二级索引不必同步修改 `[经验]`。
3. 崩坏词归一：源码将二级索引、辅助索引、回表、目录项、页号等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
