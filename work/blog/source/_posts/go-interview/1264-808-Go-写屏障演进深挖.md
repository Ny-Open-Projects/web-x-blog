> 分类：Go 运行时 | 难度：L3 | 题型：原理深挖 | 频率：高 | 关键词：**三色标记、插入屏障、删除屏障、混合写屏障、STW、Go 1.5/1.8**

> 原文锚点：第 1~101 段「从 STW 到屏障，再到 Go 1.8 混合写屏障的完整演进脉络」

## 思路与架构

把整条演进看成"**如何安全地让标记与业务并发**"这一条主线：

- **起点**：三色标记把对象分成白、灰、黑，**白色 = 尚未确认可达**，清除阶段会被回收。
- **矛盾**：并发时业务随时改引用关系，会留下"被黑引用、又失去灰路径"的白色对象，即漏标；归纳为**两个必要条件**。
- **翻译**：把"不漏标"转成两条不变式——强（黑不引用白）/ 弱（黑引用白但白的上游有灰）。
- **落地**：插入屏障维持强不变式、删除屏障维持弱不变式，两者各有短板。
- **终局**：Go 1.8 混合写屏障同时保护新值与旧值，豁免栈重扫，把 STW 压到毫秒级。

抓住这条主线，回答问题就不再是一堆零散名词，而是"问题 → 条件 → 不变式 → 屏障 → 代价"的因果链。

## 方案取舍

- **全程 STW**：实现最简单、绝对安全，但业务停顿不可接受，只适合教学模型或极小堆。
- **插入屏障（增量更新）**：精确度高，理论上不产生额外浮动垃圾；代价是**每次堆指针写都要判断**，且**对栈无效 → 结束需 STW 重扫栈**，停顿随 goroutine 数量与栈深度增长。
- **删除屏障（起始快照）**：只需一次极短 STW 记录快照，后续无需重扫栈；代价是**保守**：本轮被删引用的对象即便已死也只能等下轮，浮动垃圾抬高堆占用。
- **混合写屏障**：两条保护都做，单次写成本略高于任一单独屏障，但换来"不重扫栈 + 精度可控"，综合停顿最短，这是 Go 的实际选择。
- **工程视角**：写屏障成本计入所有堆上指针写，所以减少指针字段、在热路径用值类型容器确实能降 GC 压力；但这是有 benchmark 支撑后的优化，不应牺牲可读性去换取。

## 答题技巧

1. **先讲为什么会错**：用"6 引用 2、同时 2 断开对 3"的图复述漏标场景，这是后面所有机制存在的理由。
2. **再用两个条件收口**：① 黑引用白 ② 灰到白路径断开，**打破任一即可**，这句话能显示你抓住本质。
3. **不变式对号入座**：强对应插入、弱对应删除，别只背名字，要说出"它维持了什么性质"。
4. **讲短板而不只讲优点**：插入要重扫栈、删除有浮动垃圾，面试官真正想听的是 trade-off，不是名词表。
5. **版本锚点收尾**：Go 1.5 并发化 → Go 1.8 混合写屏障 → 回答"Go 的 GC 流程"应以 1.8 之后为准；可用 `GODEBUG=gctrace=1` 观察各阶段停顿作为佐证。
6. **预留接口**：本讲只到屏障为止，混合写屏障的**具体标记流程**在下一节展开，答到这里主动交接，被追问时不至于卡壳。

## 细节与核心 API

```go
// 写屏障解决的问题：并发标记时 mutator 修改指针，可能把“白对象”挂到“黑对象”下导致误回收
// 演进：
//  Go 1.4 前：Dijkstra 插入写屏障（仅写操作插桩，栈不插 -> 需 rescan 栈，STW 较长）
//  Go 1.5：Dijkstra 插入屏障（仍要 STW 重扫栈）
//  Go 1.8+：混合写屏障（hybrid，插入+删除），只需要在标记开始短暂 STW 一次
//  混合屏障保证：被覆盖的老指针（删除）和被指向的新对象（插入）都不会被漏标
// 影响：开启写屏障后指针写多一次函数调用开销（小）；换来实现几乎无 STW
// 调试：GODEBUG=gcstoptheworld=1 可强制全 STW（仅诊断，勿生产用）
```
