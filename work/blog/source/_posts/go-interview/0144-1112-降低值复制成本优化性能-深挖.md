## 一句话总述
降值复制成本是一条"先看尺寸、再定取舍、最后验证"的链路：用 `unsafe.Sizeof` 建立值尺寸认知 → 大 struct/array 用指针（权衡 GC 压力）、header 类用值传递 → for-range 大元素避双变量 → 全部用 benchmark 量化。与 923/508 互补（923 讲传值机制、508 讲字段拷贝，本卡讲尺寸体系与全局优化决策）。

## 思路与架构
- **认知层（值尺寸体系）**：各类型直接值部固定（基础类型）/动态（struct=字段和+padding、array=元素×长）；零尺寸值占 0。这是判断"复制贵不贵"的前提。
- **决策层（指针取舍）**：大值类型用指针省复制，但指针增 GC 压力；slice/map/chan/func/string/interface 只复制 header（间接值部共享），不用指针。
- **陷阱层（for-range）**：大元素双变量每次复制，单变量+s[i] 或 for 下标规避；小元素可忽略。
- **验证层**：用 `go test -bench` 量化，不凭直觉。

## 方案取舍
- **为何 header 类不用指针**：复制只十余字节、底层共享，加指针反而增 GC 扫描/回收压力，得不偿失。
- **为何大 struct 用指针**：直接值部可能 KB 级，每次传参/通道发送都全量复制，指针把复制降到 8B，代价是 GC 多追踪一个对象——高频小对象需权衡。
- **与既有卡边界**：923-slice-pass-by-value / 923-map-pass-by-value 讲"传值只复制 header"机制，508-struct-copy-field 讲结构体字段拷贝，本卡在二者之上补"尺寸体系 + 优化决策 + for-range 陷阱"，角度互补。

## 答题技巧

## 细节与核心 API

**① 先用 `unsafe.Sizeof` 建立尺寸认知**

```go
import "unsafe"

type Big struct {
	a, b, c, d int64      // 32B
	name       string     // 16B（header：ptr+len）
	buf        [1024]byte // 1024B ← 大头
}

func sizes() {
	var s []int
	var m map[int]int
	var ch chan int
	var str string
	var i interface{}
	fmt.Println(unsafe.Sizeof(Big{})) // 1072+：struct = 字段和 + padding
	fmt.Println(unsafe.Sizeof(s))     // 24：slice 只复制 header（ptr+len+cap）
	fmt.Println(unsafe.Sizeof(m))     // 8 ：map 是指针，复制只 8B
	fmt.Println(unsafe.Sizeof(ch))    // 8 ：chan 同理
	fmt.Println(unsafe.Sizeof(str))   // 16：string header（ptr+len）
	fmt.Println(unsafe.Sizeof(i))     // 16：interface（type ptr + data ptr）
	var e struct{}
	fmt.Println(unsafe.Sizeof(e))     // 0 ：零尺寸值，白嫖
}
```

**② 大 struct 用指针，header 类用值**

```go
// ✗ 大 struct 值传递：每次调用复制 1KB+
func slow(b Big) int { return len(b.buf) }

// ✓ 指针传递：复制从 1KB+ 降到 8B（代价：GC 多追踪一个对象）
func fast(b *Big) int { return len(b.buf) }

// ✓ slice/map/chan/string/interface 直接值传即可：只复制十几字节的 header，
//   加指针反而增加 GC 扫描压力，得不偿失
func fine(s []int) int { return len(s) }
```

**③ for-range 双变量陷阱（大元素时最痛）**

```go
type Item struct{ payload [512]byte }

// ✗ 双变量：每次迭代都把元素复制一份（512B × N）
for i, it := range items {
	_ = it.payload
}

// ✓ 单变量 + 下标取：零复制
for i := range items {
	_ = items[i].payload
}

// ✓ 或只取下标，配合 items[i] 使用（同上）
for i := 0; i < len(items); i++ {
	_ = items[i].payload
}
```

**④ 用 benchmark 量化，别凭直觉**

```go
func BenchmarkBigByValue(b *testing.B) {
	big := Big{}
	for i := 0; i < b.N; i++ { slow(big) }
}
func BenchmarkBigByPointer(b *testing.B) {
	big := Big{}
	for i := 0; i < b.N; i++ { fast(&big) }
}
// go test -bench=. -benchmem
// 关键看 B/op（每次操作分配字节数）与 allocs/op（分配次数）
```

> 决策速记：**大 struct/array → 指针**（复制 1KB+ → 8B，代价是 GC 压力）；**slice/map/chan/func/string/interface → 值传递**（本身只复制 header，加指针反增 GC 负担）；**零尺寸值 → 白嫖**。

1. **先报尺寸**：开口用 unsafe.Sizeof 表建立"复制多少"的量化认知。
2. **给决策**：大 struct/array→指针（权衡 GC）；slice/map 等→值传递；零尺寸值→白嫖。
3. **点陷阱**：for-range 大元素避双变量，用 bench 验证。
4. **关联延展**：提 923（传值机制）、508（字段拷贝），显示体系化。
