> 分类：MySQL / 数据类型 | 难度：L4 | 题型：原理题 | 频率：中 | 关键词：**行溢出、TEXT、BLOB、溢出指针、行大小**

> 原文锚点：第 74~87 段「TEXT 类型和 BLOB 类型都不会参与 65535 的限制…但额外占用十字节」

## 一句话总述
TEXT 与 BLOB 的内容存在行外，**不计入 65535 的行长度限制**，但在行内仍要占少量字节记录长度与溢出指针。

## 面试官视角
P6 以为 TEXT 完全免费；P7 要给出**官方口径与实测的对应**：行内只贡献 9~12 字节（长度信息与溢出指针），原文实测为 10 字节 `[源码]`。加分点：几个量级要记牢——TEXT 最大 65535 字节，MEDIUMTEXT 可达 16MB，LONGTEXT 可达 4GB `[经验]`。

## 主问答
**Q（面试官原话）：** 表里加了 TEXT 字段，还会受行长度限制吗？

1. **内容不参与计数**：TEXT 与 BLOB 的内容存于行外，因此不计入 65535 的行长度限制 `[源码]`。
2. **行内仍有开销**：需要额外字节记录长度信息与溢出行的指针，官方口径为 9~12 字节，原文实测 10 字节 `[实测]`。
3. **可空属性也占位**：可为 NULL 的 TEXT 同样要占一个标志位，原文去掉该属性后报错发生变化 `[经验]`。
4. **容量量级**：TEXT 最大 65535 字节，MEDIUMTEXT 可达 16MB，LONGTEXT 可达 4GB `[源码]`。

## 关键代码
```sql
-- latin1 表：varchar 与 text 合计看似超限，仍可建表成功
CREATE TABLE t (id INT, content1 TEXT NOT NULL, content VARCHAR(65519) CHARACTER SET latin1);
```
> 验证：content 改为 65520 即报行大小过大，反推出 TEXT 行内占 10 字节 `[实测]`。

## 总结与追问预判
**内容豁免、指针照占**。把这句说清，行长度这一章就闭环了。
