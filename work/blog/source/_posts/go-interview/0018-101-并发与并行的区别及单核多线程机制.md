> 原文锚点：第 13~30 段「为什么必须掌握并发编程 + 并发与并行 + 单核多线程」

## 一句话总述
**并发**是「同一时间段内多个任务交替执行、都未结束」，强调交替；**并行**是「单位时间内多个任务真正同时执行」，需要多核。单核 CPU 靠时间片轮转实现多线程并发，任意时刻只有一个线程的指令在核上运行。一句话背法：**「并发是交替推进（单核可），并行是真正同时（需多核）；单核靠时间片伪造同时」**。

## 面试官视角
考官看你是否真正分清并发（concurrency）与并行（parallelism）这对高频混淆概念，以及是否理解单核也能跑多线程的底层机制。能讲清"并发必然伴随上下文切换、多核时代并发才容易变成并行"，说明理解到位；把并发并行混为一谈、或认为单核不能跑多线程，是红旗。
- **P5**：知道并发 ≠ 并行。
- **P6**：知道并发=交替、并行=同时。
- **P7**：知道单核靠时间片切换、并发程序「可能并行也可能不」。

## 主问答
**Q（面试官原话）：** 并发和并行有什么区别？单核处理器能支持多线程吗？

**先铺垫（由浅入深第 1 层）**：很多人把 concurrency 和 parallelism 当同义词。其实一个说的是"多个任务都在推进"（不要求同时），一个说的是"多个任务真在同一刻跑"（必须多核）。单核能不能多线程？能——靠的是"快速轮流"，制造同时的错觉。

1. **并发（concurrency）（第 2 层）**：同一时间段内多个任务都在推进但未结束，任务间交替执行；某一时刻（单位时间）只有一个任务在运行，因此并发必然伴随上下文切换。
2. **并行（parallelism）（第 3 层）**：单位时间内多个任务真正同时执行，需要多核/多 CPU 支撑；并发程序若跑在多核上「可能」是并行的，单核上则只是并发。
3. **单核多线程机制（第 4 层）**：CPU 用时间片分配算法循环执行任务，给每个线程分配一段 CPU 时间（通常几十毫秒），时间片用完就让出 CPU 给下一线程，靠快速切换制造「同时运行」的错觉。
4. **比喻（第 5 层）**：多核好比多个饮水机，每台可同时给一人接水；单核则是一台饮水机大家排队接水——靠快换人显得"同时"。
5. **误用风险（第 6 层）**：别以为"开了 goroutine 就一定更快"——单核上它们是交替而非并行，且切换有成本（见 101 上下文切换代价）；要并行得 `GOMAXPROCS>1`。

## 关键代码
```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	fmt.Println("GOMAXPROCS =", runtime.GOMAXPROCS(0)) // 并行度上限

	// 并发：两个 goroutine 交替推进（单核下靠调度器时间片轮转）
	done := make(chan struct{}, 2)
	go func() { // goroutine A
		for i := 0; i < 3; i++ {
			fmt.Println("A", i) // 与 B 交替输出
		}
		done <- struct{}{}
	}()
	go func() { // goroutine B
		for i := 0; i < 3; i++ {
			fmt.Println("B", i)
		}
		done <- struct{}{}
	}()

	time.Sleep(time.Millisecond) // 等两个 goroutine 跑完
	<-done
	<-done
	// 若 GOMAXPROCS>1，A、B 可真正同时在不同核上运行（并行）
}
```

## 总结与追问预判
**背这三句就够**：① **并发=同时间段交替推进，并行=单位时间同时执行（需多核）**；② **单核靠时间片轮转（几十毫秒）伪造多线程同时**；③ **并发必然伴随上下文切换，有性能代价**。
**预判追问**：
- 「开 goroutine 一定更快吗？」→ 单核下是交替非并行，还要付切换成本（见 101 上下文切换代价）。
- 「Go 怎么控制并行度？」→ `runtime.GOMAXPROCS(n)`，默认等于 CPU 核数（见 815 GMP）。
- 「并发的坑有哪些？」→ 见 102 Go 并发假象与雷区。
