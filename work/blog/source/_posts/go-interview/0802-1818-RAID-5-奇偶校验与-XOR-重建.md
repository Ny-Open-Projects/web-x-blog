> 原文锚点：第 18~30 段「RAID 5 结构与校验重建」、第 48~49 段「异或可逆性」

## 一句话总述
RAID 5 用**带奇偶校验的条带化**：至少 3 块盘，数据与校验信息分散在所有盘上且校验位轮换分布，单盘故障时可借剩余数据与校验块做 XOR 反推重建；代价是可用容量 (N-1)/N，且小写要四次 IO。

## 面试官视角
这题的关键不在结构图，而在**你能不能解释重建为什么成立**（XOR 可逆）和**为什么写慢**（读改写放大）。能画出一次小写要读旧数据、读旧校验、写新数据、写新校验，这题就稳了。

## 主问答
**Q（面试官原话）：** RAID 5 坏了一块盘，数据为什么能恢复？

1. **校验分散**：数据与其奇偶校验信息被分布在三块或更多磁盘上，校验位在各盘间轮换，避免单盘成为写入热点。
2. **异或可逆**：对 A、B 求 XOR 得 C，则 A 与 C 异或可还原 B，B 与 C 异或可还原 A——这就是重建的数学基础。
3. **单盘可重建**：三盘阵列中若第三块损坏，把前两块数据逐位异或即可还原第三块上的内容。
4. **容量代价**：可用容量为 (N-1)×单盘，即牺牲一块盘的容量换取单盘容错。
5. **写性能代价**：小写需读旧数据、读旧校验、写新数据、写新校验，即读改写放大，故写性能弱于条带与镜像阵列。

## 关键代码
```go
// Go 侧视角：用异或演示校验生成与单盘重建
package main

import "fmt"

func main() {
	a, b := 0b011, 0b101 // 3 和 5
	c := a ^ b           // 校验位 = 6（0b110）
	fmt.Println("校验:", c)
	fmt.Println("由 b,c 还原 a:", b^c) // 3
	fmt.Println("由 a,c 还原 b:", a^c) // 5
}
```

## 总结与追问预判
核心：**XOR 可逆 + 校验轮换 + 读改写放大**。追问常拐向「为什么大容量盘不建议 RAID 5」「RAID 5 和 RAID 10 怎么选」，备好「重建窗口长、二次故障风险高」这条论据。

## ⚠️ 原文纠错
1. 事实核校： [经验] 原文称 RAID 5「也提高了整体的读写性能」——读因并行而提升，写因读旧数据/读旧校验/写新数据/写新校验的放大而下降，不能笼统说写性能提升。
2. 事实核校： [经验] 原文把「奇偶校验位（奇校验/偶校验）」与 RAID 的块级校验混讲：前者只能**检测**奇数位错误，后者按位异或可**重建**丢失数据，二者不是同一机制。
3. 事实核校： [经验] 原文示例「3 与 5 异或得 6」计算正确（011 ^ 101 = 110），可放心用于口算演示。
4. 崩坏词归一：源码将 RAID / 异或 / 奇偶校验 等音译为多组崩坏词，本卡统一为规范术语。
