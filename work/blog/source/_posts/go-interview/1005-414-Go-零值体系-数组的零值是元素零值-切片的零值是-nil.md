> 分类：Go 基础 / 类型系统 | 难度：L3 | 题型：记忆题 | 频率：高 | 关键词：**零值、nil、数组、切片、指针、零值表**

> 原文锚点：第 17~23 段「数组和切片的零值是不同的，数组的零值是每个元素类型的零值，而切片的零值是 nil…bool 的零值是 false，int 的零值是 0…指针类型的零值是 nil…管道函数接口映射这几种类型的零值也都是 nil」

## 一句话总述
数组的零值是「每个元素各取自身类型的零值」并真实占内存；切片的零值是 nil，不指向任何底层数组。指针、chan、func、interface、map 的零值同样是 nil。

## 面试官视角
P6 能背零值表；P7 要讲清**数组零值不是 nil 而是「全零元素」**这一反直觉点，以及**指针类型的数组/切片声明后为 nil、不能直接使用**的后果（见同批 414-nil-pointer-array）。

## 主问答
**Q（面试官原话）：** 数组和切片的零值有什么不同？Go 里常见类型的零值都是什么？

1. **数组零值**：数组是值类型，零值是**每个元素取自身类型的零值**，且这块内存已真实分配 `[源码]`。
2. **切片零值**：切片的零值是 **nil**，即 len/cap 为 0 且不指向任何底层数组 `[源码]`。
3. **数值与布尔**：bool→false；int/uint 及各整型（含 byte、rune）→0；float→0；complex→0+0i `[源码]`。
4. **字符串与结构体**：string→空字符串；struct→**每个字段取自身类型的零值** `[源码]`。
5. **nil 五兄弟**：指针、chan、func、interface、map 的零值都是 **nil** `[源码]`。
6. **关键推论**：数组声明后可直接赋值（元素已存在），而 nil 切片虽不能直接索引，却可安全 append `[经验]`。

## 关键代码
```go
package main

import "fmt"

func main() {
	var a [3]int      // 数组零值：[0 0 0]，内存已分配
	var s []int       // 切片零值：nil，len/cap 均为 0
	var p *int        // 指针零值：nil
	var m map[int]int // map 零值：nil

	fmt.Println(a, s == nil, p == nil, m == nil)
	// 输出：[0 0 0] true true true

	a[0] = 1 // 合法：数组元素已存在
	// s[0] = 1 // panic: index out of range（nil 切片不可索引）
	s = append(s, 1) // 合法：nil 切片可 append
}
```

## 总结与追问预判
**数组零值「有内存的全零」，切片零值「nil 无底层数组」**。追问方向通常是「nil 切片能不能 append」——能；「nil map 能不能写」——不能，会 panic。这条对比见同批 414-slice-nil-vs-map。

## ⚠️ 原文纠错
1. 事实核校：数组零值为元素零值、切片零值为 nil、五类引用类型零值为 nil、byte/rune 零值为 0——均与 Go 规范一致 `[经验]`。
2. 补充：原文把 byte、rune 归入整型说明零值为 0 是正确的（二者分别是 uint8、int32 的别名），答题时可直接说「它们本质是整型」 `[经验]`。
3. 崩坏词归一：源码将切片、指针、管道、接口、映射、零值等术语音译为多组崩坏词，本卡统一为规范术语 `[经验]`。
