> 原文锚点：第 59~97 段「索引与文档的增删改 API」

## 一句话总述
索引操作先判存在（内存缓存或 force 直查 ES 的 IndexExists）再建；文档操作走 Index 方法指定 OpType(create/update)、doc ID、routing；refresh 默认 false（写完不立即刷新，性能优先），bulk 提交另有「逐条 Add」与「批量 Do」两式。

## 面试官视角
- 考察意图：清不清楚「refresh 语义」与「bulk vs 单条」的取舍，以及 OpType/routing 怎么传。
- 分档：P5 知 Index 写文档；P6 知 refresh 默认 false、OpType；P7 知 force 直查、bulk 两式、版本控制。
- 红旗答案：以为写完立即可查（默认不 refresh）；或 bulk 与单条混用不清。
- 惊艳点：点出「refresh=true 只刷该条相关的主副本分片，不刷整索引」，以及乐观锁 version 控制。

## 主问答
**Q（面试官原话）：** 怎么用 Go 创建索引和写入文档？
**A：**
1. **索引存在判断**：先内存判断；force=true 则跳过缓存直查 ES 的 `IndexExists`，返回 exist 布尔。
2. **创建索引**：先判存在，存在直接返回，否则带 mapping JSON 创建。
3. **写入文档**：Index 方法，OpType 指定 create 或 update；可带 doc ID 与 routing。
4. **refresh 语义**：默认 false（写后不刷新，实时性低但性能高）；true 立即刷该条相关主副本分片，写完即可 search。
5. **bulk 两式**：① processor.Add 逐条入 channel 后台批提交；② 自初始化 bulk service 批量 Add 后 Do 立即提交；另含 version 乐观锁控制。
