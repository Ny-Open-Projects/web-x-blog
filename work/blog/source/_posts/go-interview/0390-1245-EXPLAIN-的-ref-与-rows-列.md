## 一句话总述
`ref` 列表示：当访问方式是 const / eq_ref / ref / ref_or_null / unique_subquery / index_subquery 这类**索引等值匹配**时，与索引列做等值匹配的「对象」是什么——常见显示 `const`（常量），多列等值匹配则显示多个 `const`，也可能是 `func`（函数）。`rows` 是优化器**预估**需要扫描的记录数，是估值非精确值，越小通常越快。

## 面试官视角
ref/rows 是配套读的两个列。考官看你能不能说清：ref 只在等值匹配类访问方式下有意义，值是「匹配对象」；rows 是预估值、用来衡量扫描量。能补「rows 越小越好，是判断是否需要优化的重要依据」即可。

## 主问答
**Q（面试官原话）：** EXPLAIN 的 ref 和 rows 分别表示什么？

1. **ref 的含义**：展示与索引列进行**等值匹配的对象信息**；仅当 type 为 const / eq_ref / ref / ref_or_null / unique_subquery / index_subquery 时才有内容。
2. **ref 常见值**：`const` 表示与常量等值匹配；多个索引列各做常量等值匹配时，会列出多个 `const`；也可能是 `func`（函数）或具体列名。
3. **rows 的含义**：优化器**预估**需要读取/扫描的记录条数，**是估值不是准确值**。
4. **rows 用途**：扫描行数越多通常越低效，是判断该查询是否需要优化的重要依据之一。
