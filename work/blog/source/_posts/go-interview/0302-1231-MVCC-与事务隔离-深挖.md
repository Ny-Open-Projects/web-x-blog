> 原文锚点：第 1~91 段「RR 默认、快照读/当前读、MVCC 原理、ReadView 时机、可见性、事务ID、二级索引」

## 思路与架构
MVCC 可拆成「版本从哪来 + 怎么判断」两条线：
- 版本链：聚簇索引行隐藏列 DB_TRX_ID(6B，最近修改事务ID) + DB_ROLL_PTR(7B，回滚指针) → 沿 undo log 串成历史版本链；无主键再补 DB_ROW_ID(6B)。
- 判断依据：ReadView（一致性视图）= 某时刻活跃事务 ID 列表快照；把版本 trx_id 与列表的 min/max 比较，分三区间决定是否可见，不可见则回溯上一版本。
- 时机差异：RC 每语句前重建 ReadView，RR 仅事务启动时建一次 → 这是两者语义差异的唯一根源。
- 二级索引退化：不存行级 trx_id，改用页头 PAGE_MAX_TRX_ID(8B) 粗判，判不了就回聚簇索引。

## 方案取舍
- RR 选「启动时一次 ReadView」：牺牲一定实时性换取事务内可重复读，是默认级别的根本原因。
- RC 选「每语句重建」：每次都看最新已提交数据，并发好但事务内可能不一致。
- 幻读治理：快照读（MVCC 无锁）解决大部分场景；必须实时性时用当前读 FOR UPDATE 加 next-key 锁，代价是阻塞插入、降低并发。
- 事务 ID 刷盘粒度 256：平衡持久性开销与安全余量，重启 +256 确保 ID 不回退。
- 二级索引不逐行存 trx_id：避免每次更新维护所有索引，代价是可见性判断可能需回表。

## 答题技巧
1. 开口定义：MVCC = 多版本并发控制，读写互不阻塞，版本来自 undo log 版本链。
2. 讲隐藏列：DB_TRX_ID / DB_ROLL_PTR / DB_ROW_ID，各自字节数与作用。
3. 讲 ReadView 时机：RC 每语句 vs RR 启动一次（**这是 RC/RR 唯一区别**），并补 BEGIN 不立即启动事务。
4. 讲可见性三区间：小于 min 可见；区间内看是否在活跃表（自身 ID 例外可见）；大于 max 不可见；都靠 undo log 回溯。
5. 收尾幻读：快照读 + 当前读双机制「很大程度上」避免；实战话术「普通查询走快照读无锁，需要强一致再上 FOR UPDATE 加 next-key 锁」。

## 细节与核心 API

**版本从哪来（隐藏列，COMPACT/DYNAMIC 行格式）**：

```text
DB_TRX_ID   6B  最近修改事务 ID
DB_ROLL_PTR 7B  回滚指针，沿 undo log 串成历史版本链
DB_ROW_ID   6B  仅无主键时补充
```

**版本怎么判断（ReadView 一致性视图）**：

```text
ReadView = 某时刻活跃事务 ID 列表快照
可见性三区间：
  trx_id < min_active      → 可见（已提交）
  min ≤ trx_id ≤ max       → 看是否在活跃表（自身 ID 例外可见）
  trx_id > max             → 不可见，沿 undo log 回溯上一版本
```

```sql
-- 快照读（MVCC 无锁）vs 当前读（加锁）
SELECT * FROM t WHERE id=1;             -- 快照读：走 undo 版本链，不阻塞写
SELECT * FROM t WHERE id=1 FOR UPDATE;  -- 当前读：加 next-key 锁，防幻读、阻塞插入
-- RC 每语句重建 ReadView；RR 仅事务启动建一次（两者唯一区别）
-- 事务 ID 刷盘粒度 256：重启 +256 确保 ID 不回退
```
