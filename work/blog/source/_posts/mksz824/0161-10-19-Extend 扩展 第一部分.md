前面的课程中，我们抽丝剥茧地对 Egg.js 的几大概念进行了简单的描述。这节课讲解另外一个权重比较低的概念：extend，也就是扩展。Egg.js 这个框架带来了许多新的概念，对这一堆眼花缭乱的名词，记得要多总结、多写笔记、多练习。用得多了自然就知道它们是什么，也就能记住它们的用法了。

扩展这个词听起来很好理解。Egg.js 当中有一系列重要的对象，我们已经使用过很多次了，做个简单回顾：application，也就是 app，全局应用对象，只有一个实例，app 上面有 config 等一系列的属性；context 上下文对象，这是我们用最多的，每次请求生成一个实例，这一点跟 application 有区别；request 请求对象来自 Koa，跟 Koa2 中完全一样，可以在 ctx 上面取得它；response 响应对象也来自 Koa。

现在介绍一个新的对象，称之为 helper。helper 对象用来提供一些实用的 utility 函数，框架内置了几个简单的函数，作用大家很容易理解：可以把一些常用的动作放在 helper 当中，形成一系列独立的函数，这样可以用 JavaScript 写复杂的逻辑，避免这些逻辑分散到各个位置。简单看一下内置的 helper 有什么：直接在 ctx 上面访问，可以联想出来两个函数，escapePathFor 和 escapeUrlFor（原文为 spathfor/surlfor），都是用来处理对应的路径的。

现在来完成这节课 extend 的任务。在开发中，我们既可以 使用已有的 API 方便地开发，也希望可以对这些一系列的对象进行自定义的扩展，进一步加强框架的功能。比如我这里有一个微信支付的功能，希望在 application 上面扩展一个微信 pay 的实例，供整个应用使用：使用的时候直接 app.wxPay 就能拿到这个实例。这节课先学习 Helper 上的扩展，也就是 ctx.helper。

我们的任务：现在每次返回对象都要写这么两行相同的代码，先设 body 再设 status。我们希望用 helper 上的一个方法替代。还记得接口设计文档中的统一返回格式吗？我们希望它能返回统一的格式，所以这个函数还要帮我们统一形成这个格式。

第一步是新建文件。特别注意，在 app 当中这些文件名称是有特定要求的，必须用这些名称。在 app 下面先创建一个 folder，既然是扩展，就叫 extend。要扩展 helper 对象，所以文件叫 helper.ts。在其中就可以在上面添加一系列的函数进行扩展：直接 export default 导出一个对象，在这个对象上就可以添加各种扩展。

我们这里称之为 success。这个函数需要哪些参数？首先肯定要把 ctx 传进来；然后看我们的格式，有 ctx 以后肯定有 data（即 response）要传进来；还有 message。errorNumber 因为是成功、成功是零，是定死的，不用传。这几个参数可以都放在一个对象中。我这里定义一个 interface，叫 responseType，来确定参数的类型：第一个是 ctx，是 Context 类型，从 egg 导入；第二个是 data，它是可选的，有些请求的 response 是空的；message 也是可选的，有一个默认值，想自定义也可以。参数我们希望是一个 object，包括这几项，所以直接使用展开运算符更方便，把 ctx、data、message 都取出来，获得确定的类型。

接下来完成任务，其实就是把两步写在一起：ctx.body 等于一个对象，第一项是 errorNumber，定死为 0，表示没有错误；data 这一项要判断 data 存不存在，存在就返回 data，不存在返回 null；最后是 message，存在就返回 message，不存在返回一条字符串"请求成功"。别忘了还有一行 `ctx.status = 200`。这样就完成了这个简单的扩展。

完成以后，在 test.ts 中进行替换。来到 controller 的位置，不需要那两行了，直接使用 ctx.helper，可以看到 success 现在就出现了。有 success 之后把参数传进去：第一个参数 ctx，第二个是 response 的 resp。这样就完成了替换，第一个 helper 写完了。刷新看它是否好用：标准的统一返回格式出现了，有 errorNumber，data 里面是一系列的数据，message 是"请求成功"。

这就是扩展 helper 的方式：在 extend 文件夹下创建完全同名的 helper.ts，在里面导出一个 object，把想要扩展的 function 添加上去就可以了。它是这几种扩展里面最简单的一种。下节课解释其他几个对象的扩展方式，比这个要稍微复杂一些。
