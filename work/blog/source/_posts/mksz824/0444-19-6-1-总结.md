这一周我们学习了 Vue CLI 构建的原理。它的底层是通过 Webpack 处理的，所以我们又学习了 Webpack 的基础和进阶，最后完成优化。优化的本质有两点：一是减少代码体积，二是加快响应速度，我们从构建过程和 HTTP 传输过程两方面进行了详细阐述。

谈优化要杜绝纸上谈兵，你需要有一定代码量的项目，才能深刻感受到优化的价值。性能优化要实事求是，最好用直观的数据展示效果，所以每节课我们都做了处理前和处理后的数据对比。这部分内容可以直接体现在简历和面试中：把数据摆出来，在数据后面贴上分析文章的链接，吸引面试官的注意，这是非常好的亮点。

下面回顾知识点。

第一是环境的概念，我们有开发环境（development）、预发布（staging）和生产（production）三种环境。Vue CLI 的 build 有不同的模式，不同模式对应不同的 Webpack 配置；还可以使用 `.env` 结尾的环境变量文件，把不同模式对应到环境变量中，并植入到脚本或项目里。

接下来是 Webpack，这很重要，因为 Vue CLI 底层使用的就是它。核心是 `webpack.config.js`，以及 loader 和 plugin 的使用。loader 本身就是一个 function，可以拿到原始代码 source，用想要的工具对它进行转换；多个 loader 可以串联，下一个 loader 拿到上一个的处理结果，最后一个 loader 输出最终的 JS 模块代码。plugin 则是一个有 apply 方法的类，apply 可以拿到 compiler 对象，通过 hooks 拿到编译过程的不同阶段，比如 done 阶段，tap 到不同的 plugin 中，拿到参数后做自定义处理。

然后进入优化。第一步是优化构建出来的静态文件，修改 `vue.config.js` 做构建优化。工具是 Webpack Bundle Analyzer，它可以用可视化的形式把打包结果的大小展示出来。具体步骤：

1. 移除不需要的第三方库，我们移除了 Lodash 和 Moment。这里学到的经验是，优先选用支持 ES Module 的库，lodash-es 和 lodash 的对比就是很好的例子。
2. 大型组件库要做到按需加载。一开始把 ElementUI（原稿记为 Undesired）一股脑全部引入项目是坏做法，添加单独的入口文件、按需引入之后，代码量减少很多。
3. 分离第三方库。之前所有第三方库打到一个大文件里，我们讲了分离的好处，并通过手动配置和按大小自动分割两种方式处理。
4. 路由懒加载，通过动态 import 的方式，在访问到路由时再加载对应的脚本代码。

构建优化之后是部署和 HTTP 传输优化。对前端来说，构建产物都是静态代码，部署就是把它们传输到服务器上。服务器是安装了 Nginx 的机器，我们先对 Nginx 做了简介。传输优化用到了 HTTP 的一系列特性，比如缓存：从 Expires 谈到 Cache-Control，再到 ETag 和 Last-Modified，深入理解了缓存机制。数据压缩也是见效极快的方法，从大家都在用的 Gzip，讲到更前沿的 Brotli，再进一步，在构建阶段就静态生成压缩后的文件，减少了服务器运行时的计算压力。最后用协议本身的特性优化，从 Keep-Alive 到 HTTP/2，大幅提升传输效率。

希望通过这一周的学习，大家可以掌握编译、部署以及优化的通用手段，在自己或工作中的项目中用起来。
