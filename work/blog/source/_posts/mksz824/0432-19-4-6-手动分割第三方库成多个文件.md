上节课介绍了将第三方库分割成几个小模块的原因和来龙去脉，这节课来动手实践。

## optimization 与 splitChunks

先来到 Webpack 文档页面。文档按不同的功能很清楚地划分了非常多的模块：我们已经接触过入口和上下文、输出模块，还有用得最多的 Loaders。这里要使用的是一个全新的模块，称之为 optimization（优化）。Webpack 配置中提供了一系列关于优化的选项，比如第一个很好理解的 minimize，就是压缩代码、最小化代码，它使用了现在非常流行的 TerserPlugin。其余选项不一一介绍，直截了当来到完成第三方库分割的配置中。

先看看 Vue CLI 已经完成的一个优化配置：它将 vendors 单独打成一个包，是怎样实现的？还记得可以用 inspect 选项把 webpack 配置导出到一个文件（我这里叫 sample.webpack.js）。来到 1659 行左右的 optimization 配置：可以看到刚才说的 minimizer（最小化代码的插件）已经使用了，并且有一系列选项；而我们想要的分割，使用的就是 splitChunks。

splitChunks 顾名思义，要完成的就是将第三方库分割的任务。它比较复杂，有一个单独的文档，里面有非常多的参数，大部分比较好理解，这里不逐个过，直接看一个非常重要的参数：cacheGroups。

## cacheGroups

cacheGroups 是完成第三方库打包成单独文件的根本。从配置可以看到，它是一个对象，里面有一系列参数。官方文档写得比较晦涩，直接看代码更好理解。看 Vue CLI 的默认配置：

- name：文件名称，对应的文件名就是 chunk-vendors；
- test：用正则控制匹配的资源模块，这里就是 node_modules，也就是说从 node_modules 引入的模块都会被它感知到，单独进行打包处理。特别注意这个正则里两种斜杠的写法，是为了处理路径的兼容性：文档描述说它始终包含 Unix 系统的斜杠和 Windows 系统的斜杠，所以在 cacheGroups 的 test 字段中使用这两个斜杠表示路径分隔；
- priority：优先级，优先级越高的先处理；
- 还有一个 common 的配置项（chunk-common），它是针对多入口文件设计的，可以将复用多次的代码单独提取成一个文件。它生成的 chunk-common 文件我们并没有见到，因为项目中没有多入口这种情况，就不展开了。

## 覆盖 splitChunks 默认值

我们在 cacheGroups 的基础上做进一步修改，让 vendors 里面可以细分。第一种采取手动的方式：自己决定哪些文件要单独输出。图中我希望把比较大的单独输出，比如 Ant Design Vue 和排名第二的 html2canvas，其他第三方库还是打成一个包。

在 vue.config.js 中新添加一项 configureWebpack，加上 optimization 的 splitChunks。它等于一个 object。要给它多加几项，因为 Webpack 对 splitChunks 有一系列默认值，这些默认值看起来很智能，但用起来不好用，我们需要覆盖：

```js
splitChunks: {
  maxInitialRequests: Infinity,
  minSize: 0,
  chunks: 'all',
  cacheGroups: { ... },
},
```

第一个参数是 maxInitialRequests，即入口点的最大并行请求数，默认值是 30（注意这是最新版 Webpack 文档的值，旧版是 3），所以要给它设置一个大的数，这里希望 Infinity，可以无限多。第二个是 minSize，生成 chunk 的最小体积，默认 20KB，存在更小的文件就把它拼接起来。我希望最小是 0，也就是没有这个限制，多小都可以单独生成一个文件。还有一个参数 chunks，添加一个 all，意味着 chunk 可以在异步和非异步的 chunk 之间共享，也就是包括所有的 chunk 文件。

再强调一次 TS 的重要性：这里属性非常多，自己手打时一定要小心不要打错。你也可以把 vue.config.js 改成 TS，不过 Vue CLI 到目前为止还没有支持 vue.config.ts（有人提过 issue，非常火）。有个人给出了一个解决方案：先创建一个 TS 文件，每次使用之前用 TSC 编译一下，转换成 JS 文件。如果实在觉得配置写得很麻烦，可以采用他的方式。

## 编写 cacheGroups

回到代码中，添加这几个参数之后就可以编写 cacheGroups 了，它是一系列的 key value。第一个希望把 Ant Design Vue 单独拿成一个包，命名为 antdv：

```js
cacheGroups: {
  antdv: {
    name: 'antdv',
    test: /[\\/]node_modules[\\/]ant-design-vue[\\/]/,
    priority: 2,
  },
  html2canvas: {
    name: 'html2canvas',
    test: /[\\/]node_modules[\\/]html2canvas[\\/]/,
    priority: 2,
  },
  vendors: {
    name: 'chunk-vendors',
    test: /[\\/]node_modules[\\/](?!html2canvas|ant-design-vue)[\\/]/,
    priority: 1,
  },
},
```

name 是希望生成的文件名 ant-design-vue；test 是一串正则，先拷贝基础部分 node_modules，更进一步匹配 node_modules 下面的文件夹，也就是先拿到 ant-design-vue，不要忘记最后的斜杠，并且要加两种方案，和前面保持一致，两种斜杠（Unix 和 Windows）都匹配。

第二个是把 html2canvas 单独拿过来，直接照抄就好。第三个是剩余的第三方库打成的整体包，name 是 chunk-vendors，test 的正则写法不一样：要使用正则里的非（!），也就是既不是 html2canvas，也不是 ant-design-vue 的，这些单独打成一个包。priority 上单独的包要设置得高一些，让它优先被匹配到。

## 验证

现在运行多次使用的 npm run build:analyze。build 完毕后看图：任务成功了。ant-design-vue 单独打成了一个文件，html2canvas 单独打成了一个文件，剩下的第三方库打成了一个整体的文件，最后还有应用代码 app.js 单独一个文件。
