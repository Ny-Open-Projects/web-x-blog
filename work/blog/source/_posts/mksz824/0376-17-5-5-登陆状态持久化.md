上节加了全局错误处理，现在应用里已经有读取状态和错误状态。但还有个问题：登录之后，下次刷新进入应用时登录状态就消失了，得重新走一遍登录流程。记住用户的登录状态是网站的常见需求，这节来实现。

## 存储方案的选择

登录状态要存在一个可持久化的地方，针对浏览器有三种选择：cookie、localStorage 和 sessionStorage。localStorage 和 sessionStorage 类似，区别在文档里写得很清楚：localStorage 中的数据可以长期保留；sessionStorage 的数据在会话结束（页面关闭）时会被清除。

所以实际是在 localStorage 和 cookie 之间选，两者都能完成任务，这里选 localStorage。

## 要存什么、流程怎样

要不要把登录后的整个 user 信息存进去？不要。localStorage 是前端完全可控的，用户可以伪造里面的内容，存一个大而全的 object 既没有必要也不安全。token 才是唯一需要的凭证，所以只把 token 存进 localStorage。

流程是：登录成功时调用 `localStorage.setItem` 持久化 token；第二次进入应用时，第一步检查 token 是否存在（从 localStorage get token），此时 isLogin 肯定是 false；如果 token 存在，就把它设置到通用的 Authorization header 中，发送 fetchCurrentUser 请求。这个请求有两种结果：

- **成功**：token 仍然可用，拿到用户信息，isLogin 置 true，自动登录完成；
- **失败**：后端的 token 有过期时间，失败说明 token 已过期或非法，显示提示，并做两部分清理：清掉 localStorage 里的 token，删掉刚才设置的通用 Authorization header。

## 编码实现

第一步是登录成功时持久化。在 user.ts 的 login mutation（登录成功时执行）里调用 `localStorage.setItem('token', token)`。同时把 state 里 token 的初始值改为有意义的：`localStorage.getItem('token')`，不存在则给空字符串。

第二步是重新进入应用时的判断，用 HomeView 做测试。创建 computed 的 currentUser，返回 `store.state.user`。onMounted 里判断两个条件：`!currentUser.value.isLogin`（没登录），且 token 存在（state 初始值直接从 localStorage 取，有的话会自动反射进来）。条件满足后，把 axios 的通用 header 设置上（之前做过，复制过来），值改为 `currentUser.value.token`，然后 `store.dispatch('fetchCurrentUser')` 发起请求。

特别注意失败的情况：之前在 main.ts 的拦截器里加过逻辑，errno 不等于零时会 setError 并返回 Promise.reject。所以这里能 catch 到错误。处理方式两种都行：要么 watch 已经加好的全局 error，要么直接在 catch 里做。这里在 catch 中添加 `message.error('登录状态已过期，请重新登录')`，然后做两步清理：

```ts
localStorage.removeItem('token')
delete axios.defaults.headers.common.authorization
```

## 验证

先完整登录一遍：获取验证码、点击登录，两秒后跳转到首页，isLogin 为 true，用户信息正常显示。刷新页面，条件满足，自动发送了 getUserInfo 请求，并且请求头里带着 Authorization，成功返回用户信息，isLogin 置为 true。

再模拟 token 过期或被篡改：手动把 localStorage 里的 token 改错，刷新页面，"登录状态已过期，请重新登录"的提示弹出，Application 面板里的 token 也已被删除。登录状态持久化完成。
