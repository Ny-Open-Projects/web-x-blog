上一部分内容我们了解了 Vue 应用的构建过程、它内部的 Webpack 运作方式，以及优化 Webpack 构建资源大小的一系列手段。现在我们已经能够生成一系列静态文件，下一步就是完成部署。这一章的任务是完成部署，但这不是最主要的任务：最主要的任务是通过服务器和 HTTP 协议的一些优化方案，进一步提升传输过程的速度。

## 前端部署

Vue 官方文档有专门的部署章节。它说的事情是：当你要部署一个独立于后端的前端应用（也就是我们现在这种应用），后端暴露一个前端可以访问的 API，前端实际上是一个纯静态的应用，那么可以将 dist 目录里构建的内容部署到任何静态文件服务器中就可以了。

对于前端纯静态的部署很简单，抛开高深的概念，它的本质就是将构建生成的产物，也就是那些 JS、CSS 的静态文件，直接拷贝到任何支持静态文件的服务器中。后面我们的脚手架会实现直接的云端部署，到时候可以学习更高级的方式，其实也就是将这些静态文件全部上传至 CDN，原理完全一样。

## 后端部署

扩展一下，讲讲后端部署。后端部署和前端纯静态部署不太一样。看 Egg.js 的文档，应用部署这一节：对后端来说几乎没有构建的过程，除非你使用了 TypeScript 等需要编译的语言。它的过程很简单，有两种方式。

第一种：直接把电脑上的源代码打个包，使用 `npm install --production` 安装生产依赖，打完包直接拷贝到目标服务器中，就完成了。

第二种：登录服务器，git pull 特定的源代码，运行 npm install，然后在服务器用特定的脚本启动整个应用的入口文件即可。第十五章讲过的 Docker Compose 采用的就是方案二：在服务器上直接铺源代码进行 install，然后启动。

## nginx 的角色

我们的应用要在服务器上运作，需要支持两部分内容：第一部分是前端部署，也就是打包出来的静态资源（dist 文件夹下的 js、css、图片等）；第二部分，因为还要访问后端的接口，有可能要支持动态的 RESTful 接口转发。这里我们使用 nginx 作为服务器来完成这两个任务。

nginx 是一款轻量级的 web 服务器，或者说是反向代理服务器，它占用内存少，启动很快，高并发能力很强。这部分内容之前的课程有过简单介绍，这里再复述一遍。这里的重点不是讲 nginx 的使用，而是讲服务器端的一些配置，或者说是 HTTP 的一些返回值对我们传输加载优化的影响。

看一下图来说明 nginx 扮演的角色。它在架构中经常充当最前面的一层：用户访问 test.com，首先就来到 nginx 这个软件，它像一个门卫一样帮助我们完成接下来的工作。它做的事情包括：

1. 把访问的地址 proxy 到对应的服务。比如服务器中有好几个服务对应不同的端口：API 服务 api.test.com 可以转发到 Node.js 应用的 7001 端口；mail 邮件服务可以转发到 Node.js 的 7002 端口；还有我们真正要访问的网站的静态文件，它可以直接完成静态文件的访问。通过访问网址就能拿到静态文件，还通过二级域名的方式访问到对应的端口。它就像一个中转站，源源不断地把请求转发到不同的服务中去，这个过程就叫反向代理。

2. 负载均衡。假如一个网站每天吸引非常多的用户，可能无法用单个服务器处理所有的站点流量，这时可以买多台服务器处理同一个站点的请求。使用 nginx 作为入口服务器，它可以让 server 一、server 二、server 三平均分配传入的流量，防止单个服务器过载，就像一个工作分配员，让每个人的工作量都差不多。

## 反向代理的优点

这样的做法优点有四条：

1. 特别适合前后端分离开发。前端静态文件放在一个地方，后端的 RESTful API 是另外的服务，可以转发到不同的模块中去。
2. 可以保证安全。应用由 nginx 这个门卫把守，外来的访问无法到达真正的应用，应用对外界不可见，外界也无法获取它们的真实 IP，这使得攻击者更难利用针对性攻击。
3. 速度非常快。nginx 比直接使用 Node.js 占用更少的内存，它采用异步非阻塞的模块，可以在高并发下依然保持低资源、低消耗并且高性能。
4. 负载均衡。

这节课简介了部署的过程：前端部署和后端部署一般是两种不同的过程，也介绍了我们要采用的软件 nginx。下节课在本地安装使用它，模拟对应的过程，让它完美地为我们的静态资源提供服务。
