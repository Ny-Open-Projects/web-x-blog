上节课讲述了挂载组件和选择元素，这节课继续测试的后面几部分内容。上节课我们也发现了，Vue Test Utils 的宗旨就是模仿真实的界面：写测试就像真实模拟自己的手动操作一样，这些 API 也是语义化的体现。这节课的内容没有特别难度，只是学习一些常规 API 的用法。

第一步任务是触发事件，方法也叫 trigger，它是 Vue Test Utils wrapper 上面的又一个方法，帮我们完成触发事件的任务。先看组件：HelloWorld 上面多了一些东西，就是 button，点击时会触发 setCount，setCount 很简单，就是把 count.value 加一，显示出新的 count。

现在要测试点击 button 以后 count 是否会更新。来到测试用例，我新建了一个用例，并且 wrapper 已经挂载好了。测试很简单：第一步触发事件，get button，实例上有一个 trigger 方法，参数就是你要触发的事件，这里是 click。触发完以后 expect：wrapper.get(button).text() 现在应该是字符串 '2'。运行看看能否通过：断言失败了，我们希望它是 2，但 receive 还是 1，也就是旧的值。

原因大家应该都知道：trigger 是一个异步的过程，而这里明显是同步的赋值和测试过程，所以断言运行的时候界面还没有更新。对于这个问题，可以使用 async 和 await：所有引起 DOM 更新的操作，都要在它前面添加 await。这里我已经添加了 async，只要给 click 加 await 就可以，保存后测试通过了。

除了直接点击触发，还有一个重要的部分：表单，输入内容并根据内容触发一些变化。把组件进行简单的改写：添加一个 input，v-model 绑定 todo，输入时 todo 值会跟着变化；下面又添加一个 button，class 等于 add-todo，点击 add-todo 时调用 addTodo 这个 function：判断一下假如 todo 有值，就 push 进 todos 数组；后面还有数组循环输出 todos 里面的内容。

现在的测试过程是：先把 input 的值改变，然后点击 button，最后查看 li 界面是否根据 todos 数组进行更新。为了获得表单并触发表单的修改，要接触一个新的 API：setValue。我新建了一个测试用例。第一步触发表单的更改：await wrapper.get('input')（我们只有一个 input），然后调用 setValue，这里我创建了一个 toDoContent 为 buy milk，setValue(toDoContent)。特别注意：因为这里要引起 DOM 的变化，所以特意使用了 await。

然后测试真实界面是否获得更新：expect(wrapper.get('input').element.value).toBe(toDoContent)。element 可以拿到真实的 DOM 节点，它是 input，value 应该更新成 toDoContent。接着触发点击：wrapper.get('.add-todo')，trigger 一个 click，前面要加 await。我们希望 li 的长度为 1：添加以后 li 会添加一项。expect(wrapper.findAll('li'))，记得 findAll 返回一个数组，可以用它来判断：添加一个新的断言 toHaveLength，希望它的 length 是 1。

运行看测试是否通过：没问题，说明这个过程完成了。当然我们还希望看看 li 第一项的 text 是否跟 buy milk 一样，继续写：expect(wrapper.get('li').text()).toBe(toDoContent)。OK，现在都完美通过了。

这里我希望同学们自己写一个用例：当 input 没有 setValue 的时候，直接点击 add-todo button，是否不会添加对应的值？这正好是一个反向验证的 case。

最后还有一个测试的重要方面：看事件是否成功发送出来。组件中已经在 addTodo 上面添加了逻辑：context.emit('send')，并且把 todo 的值发送了出来。现在测试事件是否发送以及发送的内容。wrapper 上有一个 emitted 函数，调用它会返回事件发送的 key 和 value 的一个 object。我们先用 console.log 看一下：wrapper.emitted()（它是个函数，记得要调用）。可以看到打出了一个 object：send，它以数组套数组的形式记录了发射出来的值。

现在可以先断言它是否发射出了 send 事件：判断一个 object 里有没有某个 key，我们学一个新的断言。刚才学了 toHaveLength，再来看一个 toHaveProperty：expect(wrapper.emitted()).toHaveProperty('send')。

既然已经检验了 send 事件发射出来了，现在可以使用 wrapper.emitted 的参数拿到具体事件的值：wrapper.emitted('send') 就可以拿到和 send 相关的事件值。测试里面的内容是否是 toDoContent：expect(events[0])，因为它是数组套数组，这里应该等于一个数组，用 toBe，然后是数组 [toDoContent]。看一下结果：失败了。特别注意：我们要判断一个对象（array）是否相等，不要使用 toBe，toBe 检查的是严格相等，引用也必须相等。检查对象内容是否相同应该使用 toEqual。再来试一下，现在测试完全通过了，非常完美。

这节课我们学习了四个知识点：触发事件使用 trigger 方法；测试界面是否更新时特别注意 DOM 更新是异步的过程，要使用 async/await 来检查；更新表单选择 setValue 方法；验证事件是否发送，可以使用 wrapper.emitted 拿到它发送事件的 object，然后进行判断。

现在我们掌握了测试的大体过程，下节课学点更高级的知识。这节课到这里，谢谢大家。
