上节课可以创建镜像并推送到阿里云镜像服务了，这节课要把推送好的镜像在服务器上完成启动。这两个过程本应合二为一，但为了测试先分成两步（两个分开的 job），降低调试成本；全部调通后再结合测试。

分析第二步之前，请大家做一件事：登录自己的服务器，把原来的应用停止掉，并把对应的代码都删除掉。我们要模拟一次全新的部署，看看新流程的效果。

## 步骤分析

第一步 checkout 代码，不用多说。要在服务器上做任何操作，需要先把一些必要的文件拷贝到服务器。所以要在 runner 上创建这些必须的文件，有哪些呢？

1. `.env` 文件。第一步里也有 .env，但两个文件的内容不一样：这个需要添加应用所有的环境变量，比较多。具体的变量就是各种各样的 secret，可以在 config.default.ts 里找到应用需要的变量逐一添加。
2. `docker-compose-online.yaml`，这个文件在代码库里，直接拷贝即可。
3. 一个文件夹：mongo-entrypoint。Docker 每次启动时如果是第一次启动，要用它创建一系列数据库相关的文件。

有了这三个文件就可以拷贝了。拷贝到服务器可以使用 SCP 命令，GitHub 上有一个好用的 scp action，可以快速方便地进行 SCP 拷贝。它也是 appleboy 出品的，appleboy 做了很多服务器操作相关的 action，口碑很好。

这样第二步大步分成两个小步：创建必须的文件、拷贝到服务器。这节课的目标是拷贝。记住：写的越多越容易出错，把多个步骤细分，在 GitHub Actions 的书写中是一个很好的实践。运行完 action 后可以在服务器上检查文件是否拷贝成功。

## 编写 deploy.yml

先做一件事：把之前的 push-image 禁用掉。禁用很简单，改一下后缀名即可，因为 GitHub Actions 只会运行 .yml 或 .yaml 文件里的 jobs，改了就不会运行。然后新建 deploy.yml，用来完成第二步任务。

```yaml
steps:
  # checkout 代码
  - uses: actions/checkout@v2

  # 创建 env 文件
  - name: Create env file
    run: |
      touch .env
      echo "MONGO_INITDB_ROOT_USERNAME=${{ secrets.MONGO_ROOT_USERNAME }}" >> .env
      echo "MONGO_INITDB_ROOT_PASSWORD=${{ secrets.MONGO_ROOT_PASSWORD }}" >> .env
      # …… 应用启动需要的其余环境变量，都来自 secrets

  # 拷贝必须的文件到一个文件夹
  - name: Copy necessary files into one folder
    run: |
      mkdir opsflow-backend
      cp .env docker-compose-online.yml opsflow-backend
      cp -r mongo-entrypoint opsflow-backend
      ls -a opsflow-backend

  # 通过 scp 复制文件到服务器
  - name: Copy opsflow-backend folder via scp
    uses: appleboy/scp-action@master
    with:
      host: ${{ secrets.HOST }}
      username: ${{ secrets.USER }}
      password: ${{ secrets.PWD }}
      source: "opsflow-backend"
      target: "~"
```

要点：

- checkout 直接复制上节课的即可。创建 env 文件时加一个 name 叫 create env file；因为要运行很多命令，没必要一条一条写，利用 YAML 的竖线语法写多个命令：先 touch 一个 .env，然后把一系列内容追加进去（都是上节课在 secrets 创建的、应用启动需要的环境变量）。
- 拷贝必须的文件这一步加 name：copy necessary files into one folder。多命令同样用竖线格式：先 `mkdir` 创建一个文件夹（名字随意，这里叫 opsflow-backend），希望最后整个文件夹拷到远程服务器；然后 `cp` .env 和 docker-compose-online.yml 这两个单独文件到该文件夹；再拷贝文件夹要加 `-r`，递归拷贝 mongo-entrypoint 里面的所有内容；为了测试还可以 `ls -a` 看文件夹里是否有需要的文件。
- scp action 的参数有几个：host、username、password（上节课 SSH 用过的那几个 secret）；两个特殊参数是 source（拷贝哪些文件，这里是刚创建的 opsflow-backend 文件夹）和 target（服务器上的目标位置）。target 写 `~`，Linux 中波浪线代表 home folder（cd 一下就能验证），我们把文件夹拷到用户的 home folder 即可。

也可以不用文件夹、直接把这几个文件拷过去，但为了不影响服务器原来的文件系统、显得比较乱，我们单独创建了一个文件夹。

上传代码之前最好用工具检查一下 YAML 语法有没有问题，能减少很多出错的可能。

## 运行验证

push 两个文件（commit "perm test scp action"，这节课完成了 scp 的步骤），还是 week17-test 分支。push 成功后看 action 的运行情况：很快就成功了。看每一步的运行状况：touch、copy 那几个文件成功，scp 也成功。

最后 ssh 到服务器检查：home 目录下出现了 opsflow-backend，`ll -a` 看里面的文件，需要的三样东西都在，任务完成。

这节课完成了第二步的一半工作：必须的文件已经成功拷贝到目标服务器。下一步就是到服务器上启动应用。
