上节课定义了 model，接下来创建对应的接口：密码登录体系下"创建用户"这个功能，默认使用 email 进行创建。这里先不管 email 格式验证、密码加密等功能，先完成最基本的一步：往 user 这个 collection 里添加一条数据。同时添加一个测试接口，通过 users 名称直接拿到数据，验证插入是否成功。

## Service 层

与数据库操作的抽象逻辑放在 service 中，所以先建 user.service。第一个方法是 `public async createByEmail(payload: UserProps)`，payload 就是用之前定义的 interface 类型。方法里先从 this 上拿到 ctx，然后从 payload 中取两条主要数据：username 和 password。

接着创建一个 JSON 对象 userCreatedData，类型用 `Partial<UserProps>`（UserProps 的一部分）。它有三个属性：username、password，以及 email，因为用邮箱创建时 email 和 username 完全一样。

有了数据就可以调用 model 的方法：return `ctx.model.user.create(userCreatedData)`。注意命名规则：model 文件叫 user.ts，在 ctx.model 上会被转换成大写，因为 loadToApp 里有一个参数 uppercase 设成了 true，之前手写插件时演示过。create 方法用于创建一条数据。

第二个测试方法叫 `findById`，传入数据的 id，return `this.ctx.model.user.findById(id)`。这里用的是 mongoose 提供的快捷方法 findById，可以直接用 id 查询，而且 id 不用转换成真实的 `_id` 的 ObjectId 类型，直接写字符串，内部会自动转换。

## Controller 层

在 controller 里调用 service 拿数据。第一个方法与 service 同名 createByEmail，从 this 上解构出 ctx 和 service，直接把传入的数据交给 service 创建。这里不需要做数据校验，所以先直接把整个 body 传进去。POST 请求的数据在哪个属性上？在 `ctx.request.body` 上。

复习一下文档：egg 内置了 Body Parser 插件，用来把请求 body 解析成 Object 并挂载到 `ctx.request.body`。发送请求时 Content-Type 很重要：`application/json` 会按 JSON 格式解析，`application/x-www-form-urlencoded` 会按表单格式解析。发请求时要特别注意添加对应的 Content-Type。

文档里还提到一个大家经常犯的错误，要特别注意：`ctx.request.body` 和 `ctx.body` 是两回事。前者是请求 body 中的数据，后者是 `ctx.response.body` 的简写，用来返回响应。返回时调用我们封装的 helper：`ctx.helper.success(ctx, responseData)`，这里的 response 就是查询到的 userData。

第二个方法叫 show，同样先解构 ctx 和 service，调用 service 的 findById，传入对应的 query。我们期望的路径是 `users/:id`，参数从 `ctx.params` 上拿，属性名与路由中的占位符相对应，这里就是 id。拿到 userData 后按同样方式返回。

## Router

把两个接口添加到 router 上（之前的测试接口都注释掉）。第一个用来创建：`router.post('/api/users/create', controller.user.createByEmail)`。第二个测试接口：`router.get('/api/users/:id', controller.user.show)`，注意路径里是冒号 id。具体写法对照 egg 的路由文档。

## 测试

打开 Postman，新建一个 collection，两个接口分别命名为 create new user 和 get user info。

create 接口特别注意要在 Headers 里添加 `Content-Type: application/json`，body 才能被正确解析。Body 用 Raw 加 JSON 格式，添加一条 username 为邮箱、password 为 666666 的数据。现在没有任何验证：密码没加密、长度没验证、username 的 email 格式也没验证，只是做最快的测试。点击 Send，数据创建成功，并按我们想要的格式展示。

再测 get user info：把路径中的 id 替换成刚才返回的 id，点击 Send，数据被找到，username 和 password 都正确。特别注意 createdAt 和 updatedAt 也成功添加了，说明 mongoose 的 timestamps 属性起了作用。

## 遗留的 TS 问题

接口测试成功了，但进入下一步之前，有两个点值得改进，尤其是 TS 支持。第一个：service 里写 `ctx.model.` 时，不能联想出在 model 上定义的模型名称。原因之前讲过，它的定义文件是个 indexable type，key 是任意字符串，所以联想不出来。第二个：查询结果的类型。假如用 find 查询，userData 会变成 any，拿不到正确类型。我们希望查询结果直接是 model 上定义的类型，可以点出那一串属性。为了让 TS 支持更完美、方便下一步开发，下节课要做一些有趣的修改。
