前面的内容在宏观维度分析完了整个项目可能遇到的难点，并产出了一系列技术文档。技术文档中我们都在宏观层次用伪代码描述解决方案，并没有设计具体使用什么技术来完成任务。有了解决方案的指引，现在考虑做技术选型：使用什么技术完成整个项目。

对一个现代、完整、复杂的前端项目，技术栈大体是自上而下的分层结构。要先确定最上层用什么，才能根据上层确定下面用什么适配技术。最上层是语言和技术框架。也许有人说，前端项目语言只能选 JS。除了 JS，还有 Web Assembly，但肯定不会选它。这里要介绍的是 JS 的扩展 TypeScript，我认为它是针对复杂大型项目的不二之选。

## TypeScript 的生态

看官网就能发现，现在什么样的项目在用 TypeScript：Vue 3 已完全使用 TypeScript 重写；还有许多耳熟能详的大项目，比如 Google 出品的大而全框架 Angular、Redux、Jest 测试框架、Yarn，以及阿里出品的 React 组件库 Ant Design。2020 年是 TypeScript 大火的一年，你会越来越频繁地听到别的工程师提及它。

TypeScript 这个词是 Type 和 Script 两个词的组合，它的目标是把不看重类型的动态语言变成关注类型的静态语言。官方口号是"适用于任何规模应用的 JavaScript"，可以理解成可扩展的 JavaScript 或 JavaScript 超集。除了原生 JavaScript，它还提供类型系统和 ES6 到 ES10 甚至 ES Next 的语法支持。大家都知道，使用最新的 ES 标准编码时，为了保证对不同系统和浏览器的兼容性，一般会用 Babel 转换，而 TypeScript 一举两得，既有静态类型的类型系统，又提供一揽子的 ES 语法支持。

当然，选择语言要避免人云亦云。给已经复杂的前端项目再添加一个工具链，是不是只是增加复杂度和不必要的依赖？大家对前端不断出现的新工具可能已经审美疲劳，甚至有畏惧心理。所以在选择 TypeScript 之前，需要通过自己的经验和调研来判断。下面介绍我认为 TS 对大型项目的四个加持。

## 特点一：程序更容易理解

编码时我们一般很关心这几个问题：一个函数或方法接受什么类型的参数，返回值和类型是什么，有什么其他外部数据需要引入。为了解决这些问题，我们通常要详细查询文档，搞清楚所有来龙去脉。动态语言的约束让我们很难完成这项任务，往往要在代码真正运行时调试才知道答案：加断点，写一大堆 console.log 看输出，甚至需要"社交"过程，去问同事或原来写代码的人这些字段究竟是干什么的。

有了 TypeScript，这些问题迎刃而解，代码就是全部的注释，不需要猜测，直接就有答案。拿 jQuery 这个上古的库举例，引入后访问它的方法，输入点号会出现一系列方法。比如要用 ajax 方法，提示写得非常详细：有什么参数、文档地址，下面甚至还有例子。写参数时 method 用什么都提示得清清楚楚。

## 特点二：效率更高

有了 IDE 和 compiler 的帮助，可以在不同的代码库和定义之间方便地跳转，还有代码补全和丰富的接口提示，事半功倍。

写一个自己的例子：创建一个 interface 叫 TestData，下面有一个 props，含 string 类型的 name 属性。然后 declare 一个 TestData 类型的变量 data，访问里面的属性时，自动补全先提示 props，再提示 name。想想程序非常复杂时，一个对象有很复杂的结构，这时快速自动补全非常方便。

## 特点三：更少的错误

在编译期间就能发现大部分错误，远远比运行时再出现这些错误好得多。TypeScript 之前，不知有多少次出现变量名打错（typo）的问题。比如粗心把 props 打成 prop，它会立刻提示：TestData 这个数据结构上没有 prop 属性，你是不是要写 props？连怎么修改都给我们准备好了。

第二个是经典错误：无法在 undefined 上读取某属性。原因是某个变量一开始未赋值，比如异步请求一开始数据结构是空的，属性后来才赋值。TS 可以很好地规避：假如把 props 设成可选，一开始 TestData 可能是空的，直接访问 props 上的 name 就会提示错误 object is possibly undefined，意思是它有可能一开始是 undefined，不能直接访问。假如先判断 props 是否存在，再访问它的属性，就没有任何错误了。

## 特点四：良好的包容性

TypeScript 是 JS 的超集，即使把 JS 文件直接命名为 TS 文件也不会有任何问题。它兼容第三方库：即使这些库没有用 TS 编写，我们也可以给它们单独编写类型文件进行读取。大部分项目现在都支持 TS，即使没用 TS 编写，也会提供写好的类型文件供开发者使用，可谓无缝衔接。

所以要学会根据自己的需求和项目的规模合理选用工具。如果你的应用只是一个简单的展示页面加几个 UI 状态改变，就完全没必要用 TS；但对大型项目，使用 TS 是必不可少的。

这节课分析了 TypeScript 这一层的优点，确定使用 TS 为我们服务。下节课继续技术选型之旅。
