这节课完成移动的最后一步工作：发送事件出去，更新 store 中保存的属性。事件应该在 mouseup（鼠标松开）的时候发射，在整个流程的最后一步完成更新。

## 定义事件与优化：isMoving

首先确定事件的名称，称为 `updatePosition`。刚才说过要在 handleMouseUp 里发射，所以首先要在这里把值计算出来，调用 `calculateNewPosition(e)` 拿到 left 和 top，然后通过 `context.emit('updatePosition', data)` 发射。

发送的值：首先是 left 和 top 两个值；同时要知道当前是哪个元素在进行修改，所以 id 很重要，取 `props.id`。

这里可以加一点优化：更新 position 应该只在移动过以后才进行。假如直接在元素上点击，只触发一套 mousedown 和 mouseup，没有经过 handleMove（mousemove），那么这个更新就没有必要。所以设定一个变量检测元素是否移动过：声明 `isMoving`，初始值为 false；在 handleMove 里把 `isMoving = true`；然后在 handleMouseUp 里判断 `if (isMoving)`，已经移动过才发送事件。最后要把 `isMoving` 设置回 false。

这一套流程就走完了。

## EditorView 中更新 store

现在可以在 EditorView 中创建对应的响应并完成数据的更新。创建函数 `updatePosition`，发射出来的 data 类型明确：left 是 number，top 是 number，id 是 string。先把这三个值从 data 中解构出来，然后调用 `store.commit` 进行更新。

事件名对应 editor 中的 mutation 是 `updateComponent`，更新组件的 props。要更新两个值，所以发送两次 commit：

```ts
store.commit('updateComponent', { key: 'left', value: left + 'px', id })
store.commit('updateComponent', { key: 'top', value: top + 'px', id })
```

注意要加 `px`，因为最终保存的是字符串。

把 `updatePosition` 返回出去，然后创建事件监听：应该是在中间的 EditWrapper 上，添加 `@updatePosition="updatePosition"`。

保存测试：进行拖动，属性位置会同步更新；再拖动一下，值也更新了，说明功能已经成功。

## 清理工作

最后做一点清理工作：EditWrapper 中 mouseup 的监听没有清理。可以使用 nextTick，在属性更新完毕以后把这个绑定清理掉，也就是在 handleMouseUp 函数体内自己清理自己：

```ts
nextTick(() => {
  document.removeEventListener('mouseup', handleMouseUp)
})
```

事件名是 mouseup，最后的函数是 handleMouseUp 自己。这样清理工作就完成了。

## 小结

现在移动比较完美了：每次移动的时候，它会迅速更新到新的值。

经过三节课，拖动改变位置的功能就完成了。和拖动排序一样，关键也是整个流程的分析，以及其中一个难点：移动过程中对坐标的动态计算。事后可以把整个流程再过一遍，了解了流程，也就掌握了拖动移动的大体原理。以后工作中遇到同样的情况，可以照猫画虎复用。
