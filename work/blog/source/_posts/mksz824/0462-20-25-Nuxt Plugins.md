上节课介绍了服务器端的插件：它可以通过钩子函数获取服务器端的各种生命周期，在特殊时期按我们的意愿做自定义处理。既然 server 端有这样的功能，Nuxt 应用端是否也有相同的概念？答案是肯定的。这节课回到 Nuxt 应用的知识，看看应用端的插件，它可以让项目功能更强大。

先了解 plugins 到底是什么。可以简单把它理解为一种扩展 Nuxt 3 默认功能的方式：在程序启动之前，它会把我们自定义插件的内容引入到项目的入口文件当中。简单来说，plugins 就是一种代码及功能的插入器，通过它可以给整个应用添加更多实用的功能扩展。

它的位置要特别注意：是项目根目录下的 plugins 文件夹，要和 server 下面的 plugins 做区分。放在根目录 plugins 里的任何文件都会被自动扫描并执行。

下面写一个 Nuxt 应用插件，看看它和服务器端插件的区别。已创建一个 test.ts。任何插件都有一个特殊的全局函数来定义，应用端叫 defineNuxtPlugin（服务器端是 defineNitroPlugin，注意区分）。它有一个重要参数，称为 nuxtApp。这里简单介绍一下 nuxtApp：文档里有对它的详尽介绍。它是 Nuxt 最核心的对象，当应用渲染时会有一个共享的变量被创建，这就是 NuxtApp，是整个应用的核心枢纽，保存着各种和应用全局相关的信息。看它的定义文件，里面有非常多的属性和方法，比如 vueApp（就是 Vue 实例）、hooks（各种运行时的 hooks），还有一系列前加下划线的内部状态等等。所以 NuxtApp 也被称为 runtime core。

通过插件，我们可以使用它上面的属性和方法，在几个方面完成自定义。

第一，和服务器端插件一样，可以介入生命周期的方方面面。打印 nuxtApp 上的 hooks 属性，hooks 上有 hook 方法，第一个参数就是生命周期的命名，有非常多的自动提示。官方文档有一张表，描述了每个生命周期在什么环境下运行：一类在 server 和 client 都会运行，一类只在 client 运行。比如 app:created，在 vueApp 被创建时调用，两端都会运行；app:mounted（大家应该很熟悉），是在浏览器端 mounted 之后运行，只在 client。

验证一下，注册这两个钩子并各打印一行信息，运行应用：vue app created 的信息在终端和浏览器里都能看到；而 vue app mounted 只出现在浏览器端，服务器端没有输出，验证了生命周期的执行时机。

第二是获取 vueApp 实例并做对应的处理。nuxtApp 上的 vueApp 属性就是我们熟悉的 Vue 实例，在上面可以：使用 use 方法添加插件（前面是插件名称，后面是插件内容）；用 component 注册全局组件（前面是组件名称，后面是对应的 object）；用 directive 注册全局指令。这些就是和 VueApp 相关的用途，其中最重要的就是插件。

第三，可以扩展 NuxtApp 本身，提供全局可用的实例方法和属性。比如有个第三方库要做初始化，完全可以用这种方式扩展到 NuxtApp 全局上，在每一处都能使用。举个例子：

```ts
export default defineNuxtPlugin((nuxtApp) => {
  const user = { name: 'Viking' }
  nuxtApp.provide('author', user)
})
```

provide 有两个参数，第一个是 key 的名称（这里叫 author），第二个是传进去的对象。怎样拿到这个属性？Nuxt 提供了另一个全局函数 useNuxtApp，通过它能拿到整个全局实例。特别注意，取值时不是原封不动地用属性名，而是要在前面加一个 `$` 做区分：`useNuxtApp().$author` 就能拿到注册好的全局属性或方法。打印出来，输出的正是我们提供的内容。

这节课关于 NuxtApp 的插件就讲到这里。我们只是简单讲了概念和用途，没有深入写法。说起来其实很简单：它提供给我们一个固定的区域，可以对整个应用的生命周期、VueApp 等进行自定义，和我们之前写后端插件做的事情类似。如果把两个插件结合起来，应该能做更多有意思的事情，可以自定义应用的方方面面，这也是下节课要讲的概念。
