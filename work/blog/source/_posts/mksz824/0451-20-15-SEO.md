这节课继续说样式问题，顺便引出一个新的基础知识：SEO and Meta。

第一个任务是全局设置一个 CSS 文件。之前我们是在组件中设置的，有没有一劳永逸的办法把样式文件添加到整个应用中？这就隆重推出 `nuxt.config.ts`。从文件名就能看出，它是一系列配置的文件，非常重要，和 Nuxt 应用相关的特性都可以在里面配置，后面我们还会多次遇到它。

完成全局 CSS 的任务很直观，它里面有一个 `css` 属性，是一个数组，添加几个样式文件都可以。把之前的路径复制过来就完成了。特别注意：修改这个文件后，Nuxt 应用会自动重启一次。重启之后，全局样式就生效了（之前在 App 中加的那份已经删掉）。

除了 css，这里还能配置很多内容。比如想添加全局的第三方样式文件，可以用另一个属性 `app`。app 是对整个应用程序的配置，它下面有个 `head` 属性，看名字就知道是对 HTML head 标签里的内容进行修改。要添加第三方样式，就加一个 link，link 也是数组，可以添加多个。每个元素带 rel 属性（stylesheet）和 href，随便找一个第三方的 CSS 文件填进去，保存等待重启。切到页面的 head 里查看，link 已经添加上了。所以可以通过这种方式添加第三方 CSS。

既然能设置 head 的属性，SEO 的 meta 标签自然不在话下，这是 Nuxt 作为前后端一体框架的一大优势。先看怎样在整个应用中统一设置 meta。可以在 head 中添加各种属性，和 HTML 对应的标签一一对应：charset 设置页面编码（UTF-8）、title 设置标题（比如 my test app）、meta 是数组，可以设置多个，比如添加一个 description，name 为 description，content 为 my test app desc。保存等待重启后，title 出现了，head 中也出现了我们设置的 description、charset 等，整体设置没问题。

除了整体设置，还需要在不同页面中分别设置，毕竟 pages 下每个页面的 SEO 信息应该不一样。这要用到 Nuxt 提供的组合式函数。首先是 `useHead`，看名字就非常明晰。在页面中直接调用：

```ts
useHead({
  title: 'user detail page',
  meta: [{ name: 'description', content: 'user detail page desc' }],
})
```

结构和配置文件里 head 下面的设置完全一致。设置完进入 user one，title 就被改写成了 user detail page。这样就能给每个页面设置不同的 SEO 信息。

还有一个设置 SEO 的快捷方式 `useSeoMeta`，它提供全部自动补全，非常快捷，可以杜绝拼写错误，专注于一整套 meta 信息。用它添加 description 就不需要写 meta 数组了，直接写对象属性即可，title 也能直接设置。把它替换 useHead 后保存验证，首页刷新后进入 user one 同样没问题。

组合式函数比配置文件更强大的地方是支持响应式数据，功能更丰富，不像配置文件里只能写死字符串。比如想让 title 展示当前用户的 name：title 传响应式数据时要写 getter function 而不是字符串，返回一个模板字符串，把 `data.value.name` 放进去。验证一下：点击 user one，数据获取完毕后 title 变成了对应用户名；点 user two 一开始是 undefined，数据获取完毕后就变成了用户名。

除了组合式函数，Nuxt 还提供了一系列全局组件，可以直接在 template 中使用，非常方便。它们和普通 HTML 标签的区别是首字母大写，以此告诉 Vue 这是一个自定义组件而不是默认标签。可以用 `<Title>` 包裹标题，还有 `<Meta>` 组件，甚至 `<Style>` 也可以添加样式。注意把之前的写法注释掉，避免互相影响。保存后看结果：user two 的 title 更新完毕，样式也生效了，整个界面变成绿色；点击 user one，title 同样完成更新。

总结这节课：先引出了 nuxt.config.ts，可以配置全局和应用相关的配置，我们配置了 CSS；然后引出 app 下的 head 属性，进而了解了设置 SEO and meta 的几种方式：组合式函数（useHead 和 useSeoMeta）以及全局组件（Title、Meta、Style 等）。大家可以选择自己喜欢的方式来配置。
