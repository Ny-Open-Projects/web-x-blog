上节课分析了语言层面 TypeScript 的优势，接下来选择我们采用的主要框架。整个 B 端是典型的 SPA 项目，市面大热的无非两个框架：Vue 和 React。两位候选人都是非常出色的项目，而且随着 Vue 3 的推出，它和 React 在一些内部思想和实现方案上变得殊途同归。

这门课尽量不去比较框架之间的优劣，不讨论哪个更好，而是关注解决问题本身。我认为选哪个框架都能很好地胜任这个任务，有能力的话甚至可以两个方案都试试。star 数字、下载量、第三方库这些共性数据就不比了，反正都是使用人数非常多、久经考验的成熟框架。它们的一点共性是组件化：都用组件来描述外部世界的组成，都是关注 UI 层面的框架，内部采用 Virtual DOM 完成 UI 的更新。

除此之外，我从三个维度谈谈对它们的认识，这是我总结的三个比较另辟蹊径的点。

## React：三个维度

**代码实现风格。** 我认为 React 现在最大的概念是把组件抽象成函数，也就是函数型组件。特别是推出 Hook 以后，在函数式组件中可以使用一系列钩子函数，函数式编程更是大行其道。新版 React 已在全面推动 function component 的趋势，class component 渐渐退居第二选择。它全盘接纳了函数式编程的一些概念，比如副作用：可以用 useEffect 创建一个副作用，在 count 每次变化时调用 alert 触发。React 的核心理念是：组件只是一个返回特定界面的函数，App 函数返回的就是一系列用 JSX 写的界面。用 Vue 的同学会说 Vue 也有函数式组件、也可以用 JSX，但要记住，这类型的组件不是 Vue 官方推荐的写法，不是它的中心思想，而是一个扩展。

**数据更新机制。** React 采用 Immutable 的方式：需要调用特定的函数，也就是 useState 返回数组中的第二项，只有调用这个函数才能进行数据更新、更新界面。比如 setCount 把 count 加一。这一点有利有弊，也是比较有争论的点。

**代码重用性。** 这是 React Hooks 最大的创新：把给定的 Hooks 抽象成一系列函数，在组件内部用函数调用的方式重用逻辑。比如我创建了一个 useMousePosition 函数，返回 positions，使用时直接调用，返回值里有 x、y 可以访问。它非常符合我们正常的逻辑，能清楚地了解变量到底从哪儿来。当然 Hooks 在使用规则、用 useMemo/useCallback 做性能优化、调用顺序和依赖等方面有一定难度，对有经验的 React 开发者来说也是一个不小的心智负担，但总体来说是非常好的创新。

## Vue：对应的三个维度

**代码实现风格。** Vue 最早推出时就打着简单易用的口号，事实也是如此。它推崇 SFC 单文件组件，把前端工程师最关心的模板、数据和样式分成三部分，放到自创的 .vue 文件中，非常清晰。它还推出了一系列简单好用的指令，可以在 template 上直接使用，吸取了一些 Angular 的特点，帮我们快速搭建工程。它没有采用类似 React 函数式编程的极致模型，而是另辟蹊径从简单易用入手。

**数据更新机制。** Vue 推出了响应式数据：要修改界面，直接修改数据就可以完成界面更新。比如 count 在这里，要更新它直接 count.value++ 就行。这种思考方式更贴近程序员的思考模型：对象本来就应该可变，要更新界面，更新对象就够了。

**代码重用性。** Vue 3 最大的更新是 Composition API，就是为了解决 Vue 2 比较欠缺的代码重用性问题。它推出了类似 React Hooks 的系统并加以发扬光大，做了一系列优化。和 React 类似，可以把一系列功能抽象成函数：创建一个 useMousePosition 函数返回 x、y，调用时像函数一样使用，直接在模板里使用，非常符合正常思维，也能了解重用逻辑的代码来源和返回值。

## 选型结论

从这三个点分析了两者的异同。建议对不同的框架和技术，不要非要比个高低，文无第一，而是要博采众长，不妨都试试，总结特点，理解设计思路。你会发现两者异曲同工、殊途同归。

这门课我选用新推出的 Vue 3 作为框架，我认为它在性能和设计上都非常出色。如果你愿意，用 React 也完全可以。

确定了框架，其他技术栈的选择迎刃而解：

- **脚手架**：使用自研的 imooc-cli。
- **测试**：通用测试框架用 Jest，测试 Vue 组件用官方的 vue-test-utils。
- **构建工具**：脚手架中包含 webpack；为了拓展知识面，我加了 rollup 供对比学习。
- **持续集成**：imooc-cli 脚手架内置持续集成工具；另外加了一道菜 Travis 作为扩展知识。
- **UI 组件库**：现在支持 Vue 3 的有两大组件库，Ant Design Vue 和最近新推出的 Element Plus，都很优秀。我决定使用 Ant Design Vue。
- **状态管理和路由**：直接用官方的 Vuex 和 Vue Router。

第三方库插件、样式解决方案等，可以等主要语言框架选择完毕后，随着项目的进行再做调研和选择。作为架构师，到时候可以对这些工具做调研、写实践方案，看看哪个最适合自己团队。

通过两节课我们完成了基本的技术选型之路。请记住：技术选型一定是为业务功能负责的，没必要人云亦云，选用最适合你业务的工具才是王道。
