## 从业务中挑选有代表性的知识点

设计这门课时我反复告诉自己：不要将课程陷入业务的泥潭。业务本身是非常具象的内容，肯定伴随着重复，如果面面俱到、所有需求都写，肯定会让同学们产生厌烦情绪，甚至不想学下去。所以要选择有个性的、没有重复的业务进行讲解，并由此引出全新的知识点，这才是重点。

接下来接触一个有趣的知识点：图片处理。在我们的需求中，已上传的图片可以进行裁剪并生成一张新的图片。这是 Web 世界常见的需求，也算一个不大不小的难点。常见的场景比如生成头像：上传一张图片，将它裁剪到适合的尺寸并进行显示。

说起图片编辑器，估计很少有人自己从头到尾完成一个图片编辑器，因为功能繁复、处理过程复杂，一般都会使用第三方开源的图片编辑器。现在的问题是：要找一个完美适配的开源库来完成这项工作。

## 怎样搜索开源库

选择一个合格的开源库，我一般怎么做？说说我的经验之谈，这个技能挺重要，因为日常开发中经常面临这样的问题。

一般使用 GitHub 或 Google 搜索对应的关键词，最好使用英文搜索，这不是崇洋媚外，因为英文作为通用语言，搜索匹配度会高一点。试试看：输入 JavaScript image cropping（cropping 是裁剪的意思），第一个映入眼帘的就是 Cropper.js 这个库，后面还有一系列关于它的链接。再用中文关键字"JavaScript 图片裁剪"搜索，也会有一些若隐若现的 Cropper.js 结果（比如"移动端 Cropper.js 裁剪图片并且上传"），但都没法直达官网或库的 GitHub 地址，得到的都是一些博客文章。

搜索得到的内容最好是一手消息。所以我看文档一般都是看官网或 GitHub 中的内容，其他文档（比如博客文章）很容易是二手消息，引用的库更新以后，这些文档很容易过时和落伍。

## 考量标准

在 Google 里初步选定 Cropper.js 作为图片处理库后，还要考量它是否符合我们的需要。几个考量因素：

- Star：多少人收藏。这里有 9k，说明使用和收藏的人比较多。
- Issues：这里有三十八个。issue 多并不是坏事，说明用的人非常多。
- Releases：最新的发布在七天前。这是一个创建于四年前的老项目，最新版七天之内发布，说明维护非常积极，这是一个非常好的讯号。
- Demo：点开它的 website，发现 demo 非常简单易懂，可以在上面随便进行裁剪，它做的就是这么一个具体的事情。它的 API 还以一系列按钮的方式展示在下面：放大、缩小、移动等，其实就是调用类上面的方法，点击每个按钮就调用对应的 API，可以非常直观地了解方法的功能。

看起来这个工具就是我们心仪的对象。这就是开源世界的奇妙：这个项目不仅仅是一位程序员完成的结果，它的 contributor 达到了 37 个人，每个程序员都为做出一个好用的产品而努力，听起来还挺热血的。希望我们每个人也都有开源的精神，有机会为别人解决难题。
