上节课我们完成了 `useHotKeys` 这个 hook，快捷键已经能触发了。这节课要让它们真正生效，数据操作归根结底就是触发 store 里的 mutation，现在来完成这部分编码。

要触发 mutation，先拿到 store。这里还是用 vuex 提供的 `useStore` hook，并给它套上全局的类型 `GlobalDataProps`：

```ts
const store = useStore<GlobalDataProps>()
```

调用 mutation 时还要传当前被操作元素的 ID，也就是 `currentElement` 中的 UUID。注意这里要用 `computed` 拿计算值，而不是一个写死的普通值：

```ts
const currentId = computed(() => store.state.editor.currentElement)
```

接着就可以写第一个 mutation 调用了。Command+C 对应的是 `copyComponent`，传入 `currentId.value`，它是响应式对象，别忘了调用 `value`：

```ts
useHotKeys('ctrl.c, command.c', () => {
  store.commit('copyComponent', currentId.value)
})
```

然后在 store 中实现 `copyComponent`，接收 `state` 和 `id` 两个参数。先用 `find` 判断这个 id 对应的 component 是否存在，存在才继续拷贝。拷贝的本质是把当前数据保存在一个地方，所以要在 store 上新建一个字段：

```ts
copiedComponent?: ComponentData
```

它是可选的（可能还没有复制过任何东西）。复制本身很简单，直接赋值即可，再借助 Ant Design Vue 的 `message` 弹出一个「已拷贝当前图层」的提示。

下一步是粘贴。粘贴的 mutation 不需要传参，因为它直接从 store 里已保存的复制结果中取数据，命名为 `pasteCopiedComponent`。实现时先判断 `copiedComponent` 是否存在，存在就把它 push 进 `state.components`。

这里有一个非常典型的问题：如果直接把保存的响应式对象 push 进去，push 进去的是同一份引用，画布上的两个图层会指向同一个对象，改第一个，第二个跟着动。测试时就能清楚看到这个现象。

解决办法是把响应式对象转换成普通对象，推荐用 lodash 的 `cloneDeep` 做深拷贝：

```ts
const clone = cloneDeep(state.copiedComponent) as ComponentData
clone.id = uuid()
clone.layerName += ' 副本'
state.components.push(clone)
```

注意两处细节：新元素的 `id` 必须重新生成，它是元素的唯一标识符；`layerName` 加上「副本」后缀，方便区分。这样两个元素就是完全独立的个体了。

最后把 delete 和 ESC 也补全。backspace 和 delete 按键时调用 `deleteComponent`；ESC 则把 `setActive` 设为空字符串，取消选中状态。`deleteComponent` 的实现和前面类似：先判断要删除的元素是否存在，然后用 `filter` 过滤掉目标 id：

```ts
state.components = state.components.filter(
  component => component.id !== id
)
```

这里出现了重复的「查找当前元素」逻辑，写了好几遍比较繁琐，下节课会用高阶函数来解决这个问题。删除成功后再弹一个「删除当前图层成功」的提示，`message.success` 的第二个参数可以设置显示时长，这里给一秒。

跑一遍完整流程验证：复制、粘贴，图层列表里出现「图层一副本」，修改属性互不影响；按 delete 删除成功；按 ESC 取消选中也没问题。

这节课的核心是给快捷键添加对应的 mutation，其中最值得记住的点：复制响应式对象时必须特别小心，如果想让副本脱离响应式，用深拷贝就能完成。
