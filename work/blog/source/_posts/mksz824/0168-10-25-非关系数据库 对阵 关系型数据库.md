之前我们通过一系列内容完成了 Egg.js 基础内容的串讲，现在已经拥有了完成 CRUD 接口的能力。是时候聊聊数据需要储存在哪里的问题了，也就是数据库的选型。

数据库的类型大家已经耳熟能详，分为两大类：关系型数据库（SQL）和非关系型数据库（NoSQL）。关系型数据库是指采用关系模型来组织数据的数据库。简单来说，关系模型就是二维表格模型，并且它会给不同的表格用一些特定的键建立联系，在查询中可以把多个表格的数据拿出来。可以把它想象成 Excel 表格，这是一种非常容易理解的数据结构，因为我们在日常生活中也经常以表格的形式记录各种数据。

它的一大特点是：在储存数据的时候，每个数据表都必须对各个字段定义好，也就是要先定义好表的结构，叫 predefined schema，定义好以后再根据表的结构存入数据。用过关系型数据库的同学都知道，第一件事就是建立表的结构：分析里面有哪些键、这些键都是什么类型，然后根据这些完成表的创建。这样做的好处是，数据的形式和内容在存入之前就已经定义好了，整个数据表的可靠性和稳定性都比较高。但带来的问题是，一旦存入数据以后，需要修改数据表的结构就会变得非常困难，这是它最大的特点。

还有一个关于扩展的问题。纵向扩展是什么意思？关系型数据库储存在好多数据表中，数据操作的瓶颈有可能出现在多张数据表的操作中，而且数据表越多、联系越多，这个问题越严重。要缓解这个问题，其实很简单，只能提高处理的能力，比如选择更快、性能更高的计算机，提升 CPU、提升内存。这种方式是一个纵向的，所以称之为 vertical scaling。这种方式虽然有一定的拓展空间，但拓展空间非常有限，也就是说关系型数据库只具备纵向扩展的能力。

另外是 SQL。SQL 是结构化查询语言，是用于和关系型数据库通讯的主要接口，可以用于添加、更新或者删除数据行。经过多年的进化，它演变成了一门很强大的查询语言，但要精通它也要花费很多时间。主要的代表软件有 MySQL、SQL Server 等等。

说完关系型数据库，说说非关系型数据库。非关系型数据库最主要的就是"非"字，也就是 non-relational：它不是关系型的，所以仅仅是一个概念，是一个泛指，泛指各种非关系型数据库的集合，区别于关系型数据库。我认为跟关系型数据库相比，它最大的特点就是灵活的数据模型。刚才说了，关系型数据库要预先定义表结构，增删字段是非常麻烦的事；而在 NoSQL 中，你无需事先为要储存的数据建立字段，不需要预定义数据结构的类型，完全可以随着项目的进展对数据模型进行扩展，我认为这是一个很大的优势。

NoSQL 数据库的种类非常多，但有一个共同特点：去掉了数据库的"关系"这个特性。关系型数据库中表是相互连接的，在 NoSQL 中，unstructured data 没有太多联系，数与数之间无联系，这样就非常容易扩展，无形之间在架构层面上就带来了可扩展的能力。比如现在一台 server 顶不住了、压力太大，我们就可以增加多台 server，或者有一些数据库提供特有的分片技术（其实也是一种和多加 server 类似的策略），这样可以完成横向扩展（horizontal scaling）。总体来说，这种扩展方式要比纵向扩展好得多。

它还有一些代表。因为它是区别于关系型数据库的一个集合，实现有非常多种不同的手段：可以使用文档储存，直接储存成 JSON 格式，代表是 MongoDB；可以使用 Key-Value 储存的形式，代表是 Redis；还可以使用图储存的形式，代表是 Neo4j。

以上就是 SQL 和 NoSQL 的简单类比。说完了，回到我们的应用中。搞清楚了它们的来龙去脉，现在可以完成技术选型。技术选型要特别注意：一定要和你自己所做的项目需求挂钩。我认为 SQL 和 NoSQL 最大的区别就是对数据模型和格式的规定。分析我们目前做完的前端代码和需求就可以得知：我们需要在作品信息中存入大量的元素信息，比如这些字和图片放在哪个位置、具体有什么样的内容，这些元素都是可变的非结构化数据，所以直接把元素作为一个数组存入 JSON 是最好的方案。通过这一条，我们的选择肯定倾向于 NoSQL。

在 NoSQL 当中，MongoDB 使用了文档存储，是基于文档存储的 NoSQL 数据库，这里的文档指的就是 JSON 格式，所以它自然是我们最佳的候选人。另一个特点是：假如你是一个前端工程师，以前没使用过关系型数据库，可能对 SQL 语言也不太熟悉，而 MongoDB 中的 JSON 格式以及它提供的一系列基于 JavaScript 的 driver 和实现方案，对我们非常友好，学习成本也很低，易于上手。同时特别注意，它的社区版本是完全开源的、免费的，可以直接拿来使用，不用担心钱的问题。

最终，通过这节课的分析对比，我们得到结论：采用 MongoDB 作为我们的数据库。本周的后面内容就会围绕 MongoDB 展开，讲解它的基础和进阶知识。
