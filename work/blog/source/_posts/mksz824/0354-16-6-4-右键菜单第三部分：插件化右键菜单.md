上节课用 `render` 函数和 `createVNode` 实现了函数调用方式把组件渲染到固定节点。这节课完成后续工作。

在快捷键那一章我们建立了 plugin 的概念，`hotkeys.ts` 就是把增强界面交互的操作以插件形式添加到 editor 中。快捷键是其中一种，右键菜单是另外一种。同样在 plugins 文件夹里添加对应内容：创建 `contextMenu.ts`，存放任何跟右键菜单配置相关的内容，其实就是把当时在 editor.vue 里写的逻辑挪过来。

写完整后只差 `onMounted` 的部分：在里面调用 `createContextMenu`，把 `testActions` 传进去即可。然后在 editor.vue 里做替换：原来的相关代码全部删除，改为导入 `initContextMenu`（from `plugins/contextMenu`）并调用一次，完成同样的工作。

## 支持多区域右键菜单

用这种方式还可以做一个增强：在不同区域创建不同的右键菜单。在 ContextMenu.vue 组件上多添加一个参数 `triggerClass`，string 类型，默认值设为 `edit-wrapper`。然后把 `getParentElement` 那里的写死类名替换成 `props.triggerClass`。

`createContextMenu` 的 options 里也加上这一项，默认同样写 `edit-wrapper`。这样传入不同的 triggerClass，就能在不同区域触发不同的右键菜单。

测试一下：再创建一组 `testActions2`，在 `onMounted` 中再次调用，这次传入 `triggerClass: 'settings-panel'`，也就是右侧面板区域。实际中我们并没有这个需求，只是演示能力。验证：在画布元素上点击右键出现第一个菜单（含「删除图层」），在 settings-panel 区域点击出现第二个菜单。多个区域、多套配置同时工作没问题。`onMounted` 里创建了多少个组件一目了然，有更多需求都写在这里即可。

## 传递参数：从 DOM 节点上取 id

接下来完成参数的传递。调用 mutation 时可能需要一系列参数，比如删除图层需要 componentId。前面说过，在 ContextMenu 的回调里我们已经拿到了 `wrapperElement` 这个 DOM 节点，所以可以把数据储存在节点上，之前拖动改变排序时用过这招，现在故技重施。

第一步是保存数据。数据在 `edit-wrapper` 上，拿的是 DOM 节点，所以在那里多添加一项 `dataset`：`data-component-id`，值就是组件的 id。

第二步在 ContextMenu 里取。创建一个响应式对象，因为它是变化的数据：

```ts
const componentId = ref('')
const cid = wrapperElement.dataset.componentId
if (cid) {
  componentId.value = cid
}
```

通过响应式对象拿到对应的值后返回出去。有了这个值，ActionItem 的 `action` 在调用时就可以传入 componentId。现在会报错，因为 action 本来没有参数，把 ActionItem 的类型改成 `action: (cid?: string) => void`，cid 可选，类型就齐了。

测试能否拿到正确的 id：在 testActions 的回调里把传入的 cid alert 出来。点击「删除图层」，id 显示出来了，没问题。

## 调用 mutation

既然能拿到 id，调用 mutation 就简单了。在 `initContextMenu` 里引入 vuex 的 `useStore` 创建 store，然后：

```ts
store.commit('deleteComponent', cid)
```

点击「删除图层」，图层成功被删除。其他操作（复制、粘贴等）自行添加即可，拿到 cid 之后都不在话下。settings-panel 那组测试配置可以暂时删掉，它只是多个右键菜单的演示。

小结一下这节课：创建了 contextMenu 插件文件，可以把多个右键菜单的配置写在一起生成多个菜单；在 DOM 节点上拿到了 id 信息；最后用它在 action 中完成了 mutation 的调用。
