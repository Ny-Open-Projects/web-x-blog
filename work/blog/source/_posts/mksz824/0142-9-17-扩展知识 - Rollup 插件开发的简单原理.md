通过这一章的内容不难发现，Rollup 中的插件（plugin）对不同文件的转换和抽取起着至关重要的作用。作为一个加餐，这节课简单学习一下 Rollup 插件是怎样运作和开发的。我们只简单理解它的原理，不会深入写很复杂的例子。如果同学们有兴趣开发自定义插件，可以顺着我的思路继续深入研究。

Rollup 的插件其实没有什么神奇的，它就是一个对象，上面有一些特殊字段的名称。这些字段分别指示了构建的不同阶段，也就是所谓的生命周期或者 Hooks，并且每个阶段都有一些独特的参数，让你可以根据这些阶段拿到的内容做自定义处理。

我们来创建一个插件。官方的简单例子中，插件是一个函数，这里称之为 myExample。这个函数返回一个 object，object 上有一系列规定的属性名称，第一个是 name，也就是插件的名称，很好理解。创建完插件之后，在文档中可以发现，从 Rollup 真正开始处理文件之前，它提供了一系列 Build Hooks，类似生命周期的概念，来完成输入文件的转换。这里的 Hook 非常多，全讲的话很复杂，两个小时也不见得搞定，所以我们只讲几个比较重要的生命周期。

首先从 build 开始讲起。第一个是 buildStart，顾名思义，就是 build 开始前的准备。这个函数有一个参数 options，可以拿到打包时候的所有参数，在这里你可以根据你的插件定制化里面的内容。buildStart 完毕以后，来到第二个生命周期 load。在这里我们正式进入文件系统，加载不同的模块。它有一个参数 id，是文件的绝对路径，在这里可以做一些转换前的代码更改，它需要返回特定的格式。假如你什么都不转换，可以返回 null，这里就先返回 null。

接下来是重头戏 transform，名称就是转换，代表转换的过程。它可以拿到每个模块的源代码和 id，一般的转换过程都发生在这里。请记住，Rollup 本身只认识 ES modules 类型的代码，也就是 import export 类型的模块代码，所以假如你想做转换，必须往这个方向努力。transform 有两个参数：一个是 code，要转换的代码；第二个是 id，转换的是哪个模块。最后是 buildEnd，和 buildStart 相呼应，是 build 结束时触发的。它接受一个参数 error，能展示转换过程中你是否出现了错误或问题。

现在插件把这四个主要生命周期都写好了，把它添加到 rollup.config.js 的 plugins 里面。还记得之前我添加过一个 JSON 插件，现在把它删掉，所以转换过程应该是会出错的，我们只是了解一下这个过程。添加完毕后运行一次 `npm run build` 看看各阶段的输出。

最上面当然会出现错误。可以看到，第一个打出来的是 buildStart 阶段，它能拿到所有的参数：你自定义的 input、output，还有它默认的参数都 merge 了上去，里面内容非常多，这里就不一一讲了。接下来是 load 阶段，它的参数是 id，也就是文件地址，可以看到它确实能拿到。然后是 transform 阶段，两个参数：code 和 id。code 可以看到就是 main.js 的主要代码，id 和前面一样是文件路径。因为 main.js 加载了 hello 和 version 这两个内容，所以它要分别处理这两个文件，依次进行处理，下面的输出是同样的过程。最后出现错误了：buildEnd 的时候 error 在这里打印出来，console.error 输出一系列错误信息，告诉你哪里解析出错。当然最后出错了，因为 JSON 文件不是标准的 ES modules，它没法解析，自然出错。

通过 console.log 我们了解了来龙去脉。现在在插件里添加一个功能，做最原始的 JSON 插件做的事：让自定义插件处理 JSON 文件。在哪处理呢？自然想到肯定是在 transform 里面。我们的目标是把 JSON 字符串处理成支持 import export 的 ES modules。打开 package.json 看一下，它其实就是一个 JavaScript 的 object，我们需要将它转换成一个把上面字段都 export 出去的对象，这样才能在 main.js 里用 import 的方式引用。

怎么做呢？来到 transform，把里面的 console 先删掉。首先判断文件是否是 .json 格式：先判断 id 的后缀名，用 slice 拿到最后五个字符，假如不等于 .json，就直接返回 null 不处理。剩下的情况是需要处理的情况，这里用一个 try catch：现在是字符串，需要拿到它的对象，调用 `JSON.parse(code)` 得到一个 object，称为 parsed。拿到对象以后，可以使用 Rollup 提供的方法将这个对象转换成 import export 格式。这个方法是内置的，称为 dataToEsm，从 pluginutils 导入。新建一个 transformCode，调用 dataToEsm 把对象传进去。把它打印出来，等会儿看看转换后的格式。最后将转换后的代码以特定的形式返回：最简单的形式是一个 object，里面有一个 key 叫 code，就是转换后的代码，这里写 transformCode。这样转换的过程就完成了。当然返回的 object 里还有更多 key 代表不同的意思，想了解详情可以自己看文档。catch 里暂时什么都不做。

插件就完成了。再运行一遍 `npm run build`，看看还会不会出现之前的错误。现在成功了。看刚才打印的内容，它就是把 object 里所有的项都进行了一个 export：打印的 transformCode，也就是 dataToEsm 返回的内容，是一个字符串，所有字段都变成了 export。通过这种方式它就支持了 ES modules 格式。最后看一下 bundle 文件：没问题，package.json 中的信息被完美地取了出来，完成了任务。

Rollup 插件的简单原理就介绍到这里。这里只是冰山一角，作为一个扩展知识让大家简单了解。虽然它有很多生命周期，各个生命周期的参数可能非常繁杂，但大家记得，大道至简：它做的事情其实就是将各种格式的代码转换成 Rollup 只认识的 ES modules 代码这么一件事。知道这一点，你就知道插件的精髓了。有兴趣的话，欢迎大家课下研究文档，进入深入的过程。这节课就到这里，谢谢大家，再见。
