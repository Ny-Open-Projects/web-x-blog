这节课完成下一个任务：自定义表格的单元格。表格除了展示数据，还需要添加一些和数据无关的额外列，完成额外操作。现在的场景是：管理员可以通过表格快速封禁用户，也就是添加一个额外的列，在列中展示一个 toggle，点击后发送特定请求，把对应属性设为 true 或 false，快速完成任务。

## 添加列与 disabled 字段

多添加一列，所有列都在 columns 里定义。新列 key 叫 disable，label 设为"禁用"。

后端也要做对应操作。MongoDB 是非常灵活的数据库，可以随时添加属性，所以添加一个新属性 `disabled`，代表用户是否被封禁：默认 false，true 则表示已被封禁，登录应该失败。它是可选的布尔类型。注意 user schema 中的定义也要有这个值：类型为 Boolean，默认值 false（正常用户）。

另外在 `index.ts` 里要把这个值返回回来，注意拼写不要错：disabled。

## column-data slot

前端怎样把单元格展示成 toggle？要用到文档里的个性化 slot。这里推出的 slot 叫 `#column-data`，使用它可以自定义单元格的属性和样式，并且能拿到整个 row 的数据（每行单独从数据库返回的数据），想怎么用都可以。

文档示例里创建了一个叫 actions 的 key，渲染一个按钮列表；往下看渲染方式：在 UTable 里添加一个特殊的 slot（template），命名很有讲究：column 的 key 名称加上 `-data`，slot 还提供一个叫 row 的数据，通过它可以拿到整行数据完成想要的操作。

来到 UTable，添加 slot 需要给它加上结束标签。命名特别注意：我们的 key 是 disable，所以写 `#disable-data`：

```vue
<template #disable-data="{ row }">
  <UToggle v-model="row.disabled" />
</template>
```

看最终结果能否成功渲染出禁用列：出现了。

## 发送请求

有了 toggle，还要决定点击时发送怎样的请求。UToggle 支持 v-model，可以拿到标准事件 `update:modelValue`（特别注意拼写不要错），里面会拿到新的值。用 inline 箭头函数处理：第一个值当然是 disabled 当前值。我们要把这个值传过去，同时要知道它是哪条数据，哪条数据从 row 中拿。

创建函数 `toggleDisable`，两个参数：第一个 disabled 布尔值，第二个 id（这条数据在数据库里独一无二的 ID）。先打印两个值测试。调用时注意写法：

```vue
@update:model-value="(value: boolean) => toggleDisable(value, row.id)"
```

为什么要这么写？因为除了当前是否禁用的值，我们还需要拿到 id，所以通过箭头函数直接赋值的方式完成。保存后点开 console：点击后第一个值是 true（确实勾选了），第二个是对应的 ID；再点击一次，false，ID 不变，传值完全正确。

## PATCH 接口

接下来创建对应的接口。更新操作且只更新一个字段（数据库这一条记录的 disabled 值），所以要创建一个 PATCH 接口。来到 server 的 users 目录新建文件：前面是对应的 ID，后面写特殊的 HTTP method，发送 PATCH 请求，即 `[id].patch.ts`。

处理函数大家已经非常熟悉了：`defineEventHandler`，写过很多次，async 函数，参数是 event。函数体里先拿值：id 从 URL 上传过来，用已经定义好的全局函数 `getRouterParam`，把 event 传进去，拿的值是 id；payload 用 `await readBody(event)`，里面是 disabled 的 true 或 false。

更新数据调用 UserSchema 上的 `findByIdAndUpdate`。它有一系列参数：第一个是要更新哪条记录，传 ID；第二个是更新的数据，传 payload；最后可以加 options，用 `new: true`，之前介绍过，代表返回最新的值，更新结果会实时显现。最后把 newUser 返回出去，这就是 PATCH 请求更新数据的标准流程。

## 前端发送请求

回到前端发送请求，使用 `$fetch`：

```ts
await $fetch(`/api/users/${id}`, {
  method: 'patch',
  body: { disabled }
})
```

URL 发送到 api/users 加 ID，把传进来的 ID 替换进去；method 是 patch；body 传要修改的 disabled 值。请求写完后可以把返回的 data 打出来看看是不是最新的值，然后去掉 console.log。

保存测试：刷新页面，切到 network 清空记录，希望禁用 789 这条记录，点击 toggle，请求已发送，payload 里是 disabled: true；看 response，返回了新值 disabled 为 true。刷新页面看是否持久化：对应的值已经被持久化掉了，功能实现。当然再点击可以置回 false，再刷新，值也没问题。
