现在按照上节课的思路完成对应的功能。第一项工作就是创建拖动改变大小需要的 handler 元素，也就是四个点。

## 修复一个样式小问题

先修复一个样式 bug：蓝色 border 之前显示不完全。原因是外层的 EditWrapper 使用了 `box-sizing: border-box`，导致它的宽度和高度跟下面的业务组件完全相同（100px × 100px），一部分 border 被遮挡。改成 `content-box` 之后，宽高会多两个像素，整个 border 就显示完全了。

## 创建四个拖动点

既然要显示四个拖动点，就要添加对应的 DOM 元素。在 slot 下面创建一个 div，class 称为 `resizers`；在 resizers 下面创建四个对应的 handler 小圆点，各自有独特的 class 代表方向：`top-left`、`top-right`、`bottom-left`、`bottom-right`。

添加一系列样式，其中一部分我手写一下。首先 resizer 的 display 是 none 和 block 的切换，只有元素被激活（添加了 active 状态，表明正在编辑它）时才显示出来。然后是每个 resizer 的样式：

- `width: 10px; height: 10px;` 先做成正方形；
- `border-radius: 50%;` 变成圆形；
- `background: #fff;` 白色；
- `position: absolute;` 绝对定位。

然后添加位置：以 top-left（上方左侧）为例，`left: -5px; top: -5px;`，白色圆点出现在角上（缺了一个角的位置）。

再加鼠标样式。鼠标有一系列重设大小的样式，比如单向的 `n-resize`（N 指北方，向上）。我们需要的是双向的：这里对应 `nwse-resize`，指 North West to South East（西北到东南）。写上之后，鼠标放上去就出现了这个样式。知道了这只是添加不同方向而已，把下面的四个直接复制，给另外三个方向配置对应的鼠标样式。

四个点添加完毕，出现了四个圆点，各自有对应的鼠标样式。再做好看一点：给它添加一个蓝色 border（3px），看得更清楚。这样指示出它是可以拖动的。

## 实现右下角拖拽

样式写到这里，现在添加功能。做法是在最简单的逻辑上测试：只计算右下侧的拖拽，它最简单，只需重新计算宽度和高度。

和之前一样创建一个 function，之前叫 startMove，这里叫 `startResize`，参数是 MouseEvent。复习一下要做哪个减法：第一种情况，高度是 clientY 减去 top，宽度是 clientX 减去 left。所以要知道原始元素的 top 和 left 值，也就是拿到外侧 wrapper 的数值。editWrapper 我们已经有了，创建变量 `currentElement = editWrapper.value` 拿到 DOM 节点。

然后创建 `handleMove`（mousemove 触发），在里面处理一系列计算。首先判断 currentElement 存在，用已经熟悉的 `getBoundingClientRect` 方法拿到 left 和 top 两个值，然后计算：

```ts
currentElement.style.height = `${e.clientY - top}px`
currentElement.style.width = `${e.clientX - left}px`
```

计算完毕。接着把 mousemove 添加到 document 上（跟之前一样）：`document.addEventListener('mousemove', handleMove)`。最后添加 `handleMouseUp` 清除事件：`document.removeEventListener('mousemove', handleMove)`。

最后绑定：mouseup 触发 handleMouseUp，mousedown 触发 startResize，返回 `startResize`。把 startResize 赋给最简单的情形 bottom-right。

## 事件冲突与解决

先看好不好使，发现出现问题：注意我们在这里也绑定了 mousedown，这个事件会冒泡到 EditWrapper 上，触发它随鼠标移动的事件，两者互相干扰。

有两个解决方案：一个是禁止事件冒泡，很简单，加一个 `.stop`；第二个方法是在 slot 外面再包裹一层 div，多加一层 wrapper，把 mousedown 的 startMove 添加到这个 wrapper 上，这样两者是平行的，就不会发生冲突。我添加了一个简单的 `.stop`。

再试：开始拖拽，改变尺寸如约发生了，看起来很好。但拖拽时里面的业务组件并没有跟随外侧一起更改。这和之前解决的二次偏移问题是一样的：既然现在 EditWrapper 已经变成里面业务组件的"代理人"，那么关于尺寸和定位都应该由它来管，所以添加两条样式信息，让里面的尺寸按 100% 展示，不按原来的尺寸。写粗糙一点，直接 `width: 100% !important` 和 `height: 100% !important`，解决这个问题。

当然还有别的解决方法：一种是拿到里面的元素，在计算的时候做两次计算，给两个元素都进行更改，但这样需要 JS，更麻烦一点，使用样式更简单。另一种是不在这里修改，直接发送事件出去。但一直发送事件的方法不太好，因为后面有一个历史记录功能，这样会产生非常多的历史记录。我更喜欢在 mouseup 的时候再发一次事件，把整个数据更改掉。

## 验证

看最后的结果：现在已经很完美了，里面的元素随着外面的更改而更改，右下侧的缩放功能完成。
