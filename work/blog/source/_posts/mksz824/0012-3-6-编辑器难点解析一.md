上节课介绍了业务组件库的实现方法，这节课来分析和解决编辑器的难题，这是整个项目的关键点。

先看编辑器页面的三个部分。左侧是业务组件模板库，有一系列模板，这些文本其实是传入不同属性的一系列模板数据，还有图片、形状等模板。中间是画布，可以在里面对这些元素进行一系列修改。右侧是设置面板。总结一下：左侧预设各种组件模板并添加，是增加的过程；中间用交互手段更新元素的值，也可以删除；右侧用表单元素更新元素的值。两者都是更新，但方式不一样。

## 编辑器的整体状态设计

根据之前总结的难点，第一个问题是编辑器的整体状态设计。不难看出，编辑器是围绕着中间的画布进行一系列操作的，那么这一系列元素应该抽象成拥有特定数据结构的数组。

先定义编辑器整体的结构，这是整个项目的核心。以下都是伪代码，有些错误不用放在心上。

```ts
interface EditorStore {
  components: ComponentData[];
  currentElement: string;
}

interface ComponentData {
  props: { [key: string]: any };
  id: string;
  name: string; // 'l-text' | 'l-image' | ...
}
```

最重要的是中间画布渲染的数组，我们称之为 components，里面是 component data 格式的数据。此外还有一系列和其他状态相关的信息，这里暂时随便定义一个 currentElement，它是 string，代表当前编辑的是哪个元素，存的是某个 component 的 id 值，比如点击高亮了某个元素，就代表正在编辑它。

接着定义 component data。它要有每个元素 props 上的所有属性。上节课说过，业务组件的属性是 CSS 属性和其他属性的混合体，并且我们会把这些属性完全平铺开来，在编辑器分析之后更能感受到平铺的好处。这里使用一个 index type，代表有一系列的值，定义成 any。除了 props，还需要一些额外的信息：id，这个元素当前唯一的 ID；name，业务组件库的名称，要渲染哪个组件，可以是之前定义的 l-text、l-image 等。之后会有更多扩展信息，但 components 数组就是核心结构。

## 场景一：渲染画布

有了这个结构，就可以针对不同需求做技术方案设计。第一个是把元素渲染到画布上，很简单，循环渲染组件即可。

```ts
components.map(component =>
  componentMap[component.name]({ ...component.props })
)
```

先定义一个 components 数组，添加一些测试数据。渲染时用 componentMap，拿到每一个 component，根据它的 name 找到对应类型的组件，把 props 完全展开传进去。图上示意就是：循环这批数据，调用这个方法，最终生成中间画布上的元素。

## 场景二：渲染左侧组件模板

原理和上面完全一样，只不过数据是预设好的，可以完全写死在本地，也可以在模板比较多时放到后端配置，从服务器获取。和中间元素不一样的是，这些组件一般都有一个点击事件，所以要添加一层 wrapper 来解决，同时也可以和内部的 OpsFlow 组件库做到隔离，互不影响。

```ts
templateComponents.map(tpl => (
  <wrapper onClick={() => addComponent(tpl)}>
    {componentMap[tpl.name]({ ...tpl.props })}
  </wrapper>
))
```

wrapper 上可以添加一系列事件，比如 onClick。逻辑和渲染画布完全一致，了解意思即可。

## 场景三：添加和删除组件

添加删除的逻辑非常简单，就是对 store 中的数据进行添加删除。

添加的典型场景是点击左侧模板：在 wrapper 上加一个 onClick，把模板的数据添加过去，最终的操作就是在 components 上 push 一个已有的值，比如这个模板的值，功能就完成了。

删除同样如此，右键菜单有 delete，或者用 delete 快捷键，触发删除时传入一个 ID：

```ts
components = components.filter(c => c.id !== id)
```

## 小结

这节课解决了编辑器整体结构的初步设计、画布和左侧模板的渲染方式，以及增加和删除组件的问题。掌握了核心问题就会发现：画布元素其实就是一系列组件的元素而已，操作这些元素，最终就是操作数组中的数据。

编辑器的第一部分先分析到这里。下节课讲另一个难点：编辑器元素属性更新的逻辑。记得把分析结果写到技术解决方案当中，对它进行一点点细化。
