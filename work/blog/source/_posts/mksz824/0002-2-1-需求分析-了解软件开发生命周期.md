这门课由两位老师主讲。我更贴近业务，负责带大家完成 OpsFlow 项目的前端和后端开发，以及和开发相关的一系列流程，比如单元测试、部署、上线等工作。这些只是整个项目的冰山一角，架构层面还有更拔高的内容，它们是从前后端的复杂需求中衍生出来的，我们称之为研发架构，包括脚手架、组件平台和监控平台，由另一位老师讲解。两部分内容相辅相成、层层递进：从业务中拔高，发现研发的痛点，再针对痛点做工具开发。

对这种规模的产品，不能一上来就打开代码编辑器开始写代码，必须先完成一个准备过程。这一周的前半部分，我就带大家做写代码之前的准备工作。这部分不会讲得冗长，我们只做简单分析，不过度设计，少谈概念和空话，完成任务即可。

整个闭环看起来复杂，但再复杂的项目都是从第一步开始的。这个第一步就是需求：我们要做一个怎样的产品。在谈需求之前，先回顾一个概念，看看中大型公司里一个产品正常的研发流程。了解它有助于我们从上帝视角理解接下来的每一步工作。

## 软件开发生命周期

这个概念叫软件开发生命周期，英文 Software Development Life Cycle，简称 SDLC。它是所有现代软件开发流程的鼻祖，是个专有名词。用中文搜索"软件研发流程"，得到的步骤图和它几乎完全一样。

图上一共六步，层层递进：

1. **Analysis（分析）**：包含需求分析。参与人员有 Project Manager、Business Analyst 和 CTO，共同进行需求分析，产出需求报告或需求文档。
2. **Design（设计）**：分两部分。UI/UX Designer 负责界面设计，决定项目长什么样；System Architect 负责技术架构的设计。
3. **Development（开发）**：由前端工程师和后端工程师共同完成。
4. **Testing（测试）**：由测试相关人员完成。
5. **Deployment（部署）**：测试通过后进行部署，由 Database Administrator 和 DevOps 共同完成，到这里项目就上线了。
6. **Maintenance（维护）**：上线后处理用户或测试人员发现的 bug、添加新的 feature。如果有复杂的新 feature 要加，就重新走一遍这个流程。
