上节课我们在 `middleware` 文件夹里创建了独立文件 `auth.ts`，用 `definePageMeta` 引用了它，这是定义中间件的第一种方式。这节课把剩下的两种补齐，顺便理清中间件的执行顺序。

## 内联中间件

第二种方式是在 `definePageMeta` 里直接写内联函数。`middleware` 数组里除了引用外部的 `auth`，还可以直接添加一个函数，参数和外部中间件完全一致，也就是 `to` 和 `from`。

我们做一个假需求：当访问 id 为 2 的 users 页面时，直接导航回首页。注意 `params.id` 是 String 类型，不能写数字 2，要写成字符串 `'2'`：

```ts
if (to.params.id === '2') {
  return navigateTo('/')
}
```

现在页面上有两个中间件了，哪个先执行？验证一下：点击 user 1 会跳到 login 页，说明外部中间件在运作；点击 user 2 却直接到了首页，说明内联的那个先跑了。结论是：中间件按数组顺序执行，内联函数排在第一位就先执行，后面的 `auth` 就不再生效。

## abortNavigation

中间件里还有一个全局函数 `abortNavigation`，顾名思义就是终止导航。如果把它直接返回，点击对应路由时页面不会有任何反应：user 2 点不动，user 1 不受影响。

这里要特别注意，Nuxt 是前后端通用的框架。如果直接在地址栏访问 user 2 这个路由，得到的不是"点不动"，而是直接返回 404。因为直接访问 URL 走的是 SSR 流程，服务器端执行中间件逻辑后直接跳到 404；而点击事件走的是客户端（browser）逻辑。所以同一段中间件代码，实际上存在两条分别独立的路径：一条针对服务器端渲染，一条针对客户端。

`abortNavigation` 还可以接收一个参数，用来自定义服务器端渲染时返回的错误内容。比如传入一个 error 信息，再直接访问这个 URL，就会返回 500 并显示我们自定义的错误。这个错误页面本身也是可以自定义的，后面再探讨。另外，如果是首次渲染首页之后再去点击，加不加这个错误参数效果完全一样，都只是无法跳转而已。

## 全局中间件

第三种是全局中间件，它在每个路由上都会运行。定义方式是给文件名加一个特殊后缀 `.global`。

在 `middleware` 目录里创建 `test.global.ts`，内部写法和普通中间件一样，比如放一段 `console.log('test global middleware')`。刷新页面后随便切换路由，控制台都会打印这条信息，说明它在每个路由上都会执行。

全局中间件可以添加多个，比如再来一个 `setup.global.ts`。多个全局中间件有执行顺序问题：按文件名字母排序运行。`s` 排在 `t` 之前，所以先运行 setup 再运行 test，刷新页面验证确实如此。

总结一下中间件的运行顺序：先运行全局中间件（按字母顺序），再运行针对单个页面的中间件（按数组顺序）。

如果想改变全局中间件的顺序，可以用字母或数字前缀控制。比如把文件重命名为 `1.test.global.ts` 和 `2.setup.global.ts`，刷新后就能看到 test 先于 setup 执行。

## 在 DevTools 里查看

最后打开 Nuxt DevTools 的 Pages 面板，往下滑能看到每个路由的中间件配置。users/id 这个路由上配置了两个中间件；后面还列出了全局中间件，带绿色标识的就是 global。其中有两个是 Nuxt 自带的全局中间件，`validate` 和另一个，我们自己添加的两个也会出现在这个列表里。

这节课我们补齐了中间件的三种定义形式，也理清了它们的执行顺序。中间件的部分就讲到这里。
