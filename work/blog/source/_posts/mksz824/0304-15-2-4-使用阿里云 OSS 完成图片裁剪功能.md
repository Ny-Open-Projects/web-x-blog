上节课成功初始化了 Cropper 的编辑区域，它会显示一个遮罩层，在上面拖动就可以展示不同的选择区域。代码中，Cropper 实例最重要的是可以在 crop 回调中拿到一系列和用户选择区域相关的数据，这些区域数据和我们要切割获得图片的信息密切相关。

## detail 数据

event 里有一个属性 detail，是要重点关注的一系列数据。打印出来：拖动选择区域时会打出一系列新值，它是关于选择区域最重要的数据，包括选择区域的长宽（width 和 height）、x 和 y 两个坐标值（x 是从这个点到选择区域起点的距离，y 同理，都以像素为单位），还有缩放值 scaleX、scaleY 和旋转值 rotate，这几个没做处理，都是默认值。

有了这些数据，给大家介绍两种方法完成图片的裁剪并重新上传。第一种：根据裁剪的数据拿到新的图片数据，生成新的二进制数据，重新完成一次上传，上传完毕后生成新的图片地址进行替换，这是大家都能想到的常规做法。第二种有意思了：根据阿里云 OSS 特殊的图片处理功能，修改特定的 URL 参数完成裁剪。我们从第二种开始，因为它比较简单。我给大家测试的地址也使用了阿里云的对象存储，真实的后端都采用阿里云 OSS，所以这个方法是完美适配的。

## OSS 的图片处理参数

图片上传服务使用的是阿里云 OSS（对象存储），它可以实现特殊的图片处理。最简单的方法就是通过文件访问 URL 处理图片：在原来的地址后面添加一系列参数，比如 `x-oss-process=image` 是固定参数，接下来是 action、parameter 和 value，代表图片处理的操作，多个值用斜线分割。文档的例子有两个处理：resize 是缩放（缩放到 300×300），quality 是质量（q_90 表示质量为 90）。

它支持非常多的处理效果，都是日常图片处理的常用操作，比如图片缩放在日常项目中也经常使用。我们这里应该用自定义裁剪：操作名称是 crop，参数是 w、h、x、y，宽度和高度、x 轴坐标、y 轴坐标，跟我们需要的参数完全一致。把拿到的值直接填充到参数里，就能获得新的裁剪结果。

看它的示例：一张叫 example.jpg 的狗狗照片，裁剪起点为 150，使用默认宽高的最大值（可以省略参数），再加裁剪范围 w_100h_100，图片就变成了新的样子，URL 后面添加了 crop 的一系列参数。跟它做同样的事情就可以了。这就是云服务的好处：使用云服务后，一些复杂的工作让提供商完成，省时省力。假如是你自己的文件系统，肯定少不了重新上传的过程。

## 代码实现

现在写代码。要拿到当前 event 的值，并且在点击 OK 的时候使用，所以要创建一个新变量保存 x、y、width、height 四个值。创建一个 interface，称之为 CropDataProps；再创建变量 cropData，类型是 CropDataProps 或 null，初始值为 null。在 crop 回调中赋值：把 event.detail 中的 x、y、width、height 拿出来。有同学会问为什么不直接赋值，因为最好做一个简单的转换：这些值都是小数，转换成整数更好。用 Math.floor 转换，`cropData = { x: Math.floor(detail.x), ... }`，其他值对应转换。

然后添加 handleOk 函数：if 判断 cropData 存在，从中拿出 x、y、width、height，进行 URL 的整合，把传入的原始 URL（props.value）加上对应的参数，用模板字符串：`x-oss-process=image/crop,x_${x},y_${y},w_${width},h_${height}`（和刚才演示的一样）。拿到新值后发射出去：`context.emit('change', croppedUrl)`，不要忘记我们的原则是 change 事件。最后 handleOk 里把 showModal.value 改成 false，并把它 return 出去。

界面上验证：点击裁剪图片，选择区域，点击确认，裁剪图片通过添加 URL 参数完美实现了。

## 两个小问题及修复

不过还有一个小问题：再次点击裁剪、修改后确认，图片直接消失了。打开检查看一下图片地址：URL 被多次添加到默认的 URL 后面，造成整张图片的地址出问题。所以每次要拿到基础的 URL，而不是把每次的参数都追加到地址后面。

处理很简单：在 setup 中添加一个 computed，叫 baseImageUrl：`computed(() => props.value.split('?')[0])`，图片参数是加在问号后面的，split 后取第一项就拿到了最原始的 URL。把拼接处从 props.value 改成 baseImageUrl.value。再试：第一次裁剪确认，第二次裁剪也没问题了。

虽然没出现错误，但其实还有一个小问题：在已裁剪的区域再次裁剪时，坐标会出现问题。所以要把每次裁剪的图片改成原始图片：把 baseImageUrl return 出去，再把 Cropper 处理的 src 改成 baseImageUrl.value。重新验证：第一次放在这里，再次裁剪时回到原图裁剪，没问题。使用 OSS 的一个小局限就是不能在已裁剪的区域继续裁剪，因为每次拿到的都是原始图片。不过这也不算什么问题，在原图上操作就可以满足需求。
