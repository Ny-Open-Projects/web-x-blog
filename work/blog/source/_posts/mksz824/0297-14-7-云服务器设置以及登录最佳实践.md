搞懂了 Egg.js 针对生产环境的启动过程之后，接下来完成传统的部署过程，也就是把应用部署到远程服务器上，所以首先得有一台远程服务器。

## 云服务器选购

和之前一样，先对云服务器做一个简单调研，直接把结果分享出来供参考。对这类要花钱的服务，都不是强制购买的，但有一台自己的服务器我还是建议尝试一下：可以用它干很多有趣的事情，比如搭建个人网站、上线个人应用、实验一些项目，能大大扩展作为程序员的思路和视野，对职业发展也有好处。

云服务器长期都有优惠，促销时（双十一、双十二、618 等）经常十元以下就能买到，相比其他服务非常划算。调研的三大平台是阿里云 ECS、腾讯云 CVM 和华为云 ECS。学习目的不需要买配置最好的，买最低配即可。当下看的活动价格：阿里云 ECS 一核两G 一年 38 元起；腾讯云上新活动一核两G 也是 38 元，另外还有学生云活动，25 岁以下用户可以非常低廉的价格长期购买，而且硬盘更大；华为云同样是一核两G 38 元。三家最便宜的配置价格不约而同，选一家购买即可。

购买之后会获得一个 IP 地址和一个 root 用户，可以按喜好选择 Ubuntu 或 CentOS 这两大主流 Linux 发行版。我这里有一台使用 Ubuntu 的阿里云测试机。

## 服务器登录最佳实践

刚买完服务器会设置一个登录密码，这时就可以用 root 加密码登录：

```bash
ssh root@<服务器IP>
```

输入密码后就能登录到服务器上。但每次都直接使用 root 登录是不好的实践，原因有三条：

1. 网络上有非常多的 bot（黑客设置的机器人），会尝试使用 root 加 password 的方式通过 ssh 暴力登录机器，像爬虫一样不断对各种 IP 尝试 root 加密码。机器是完全开放的，一旦密码猜中，黑客就控制整个系统。
2. 如果我们创建一个特定用户，bot 需要先猜用户名（n 次），再猜密码（m 次），复杂度就提升到了 n 乘以 m，能最大限度保证系统安全。
3. root 是 Linux 默认拥有最多权限的用户，一旦被登录会影响整个系统；而某个特定用户被登录，只能影响它自己的文件系统，危害范围小得多。

所以第一步最佳实践是：创建一个用户账户，用权限较低的账户登录。

## 创建用户并赋予 sudo 权限

一开始的操作需要 root，先以 root 登录，然后用 adduser 创建用户：

```bash
adduser worker
```

它会让你输入 Unix password，设置两遍；后面的 full name 等信息直接回车跳过，最后输入 Y 确认，新用户就创建成功了。

接着要把这个用户设置为拥有 sudo 权限，也就是登录后可以切换到 root。需要说明的是，这种方式和一开始直接用 root 登录完全不一样：它是先用普通用户登录，再用 root 密码切换，等于多了一重保护，安全得多。

所有可以 sudo 的人都在 /etc/sudoers 文件里配置。默认情况下这个文件对新服务器是不可写的，先用 chmod 给所有者加上 w 可写权限：

```bash
chmod u+w /etc/sudoers
```

然后用 vim 编辑 /etc/sudoers，找到 root 那一行，复制一行，把新用户名填进去：

```
root    ALL=(ALL:ALL) ALL
worker  ALL=(ALL:ALL) ALL
```

保存退出，sudo 权限就添加好了。

## 测试新用户

退出 root，用新用户重新登录，用 `whoami` 确认身份，可以看到分配了单独的用户空间（home/worker 目录）。然后测试切换 root 的两种方式：第一种是直接 `su`，输入 root 密码后就变成 root 权限，原来不可操作的文件现在都可以操作了，`exit` 退出；第二种是 `sudo` 加上具体命令来操作文件，同样需要输入 root 密码。

## 禁止 root 远程登录

第三步是禁止 root 远程 SSH 登录，非常实用，因为 bot 就在尝试用 root 加密码的方式远程登录各种机器。

先切到 root（修改需要 root 权限），然后编辑 SSH 配置文件：

```bash
vim /etc/ssh/sshd_config
```

这个文件里有各种配置，比如打开的端口等。搜索 permit root login，可以看到它现在设置为 yes，把它改成 no，保存。

保存完毕后还要重启对应的 service。在 Ubuntu 中各种 service 都是用这种方式重启的：

```bash
service sshd restart
```

用 status 看一下状态，显示 loaded 且 active running，说明重启成功了。退出后再尝试用 root 登录：即使输入正确的密码，也会弹出 permission denied, please try again，说明禁止 root 登录的功能已经生效。

## 小结

这节课对服务器做了第一步的基础设置。以后拿到新机器，最好都先按这套最佳实践设置一遍，因为直接用 root 登录是非常危险的。虽说是小项目，也要遵守最佳实践，这是生活和工作中都适用的重要一点。
