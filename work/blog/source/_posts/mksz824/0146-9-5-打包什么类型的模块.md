上节课我们选定了 Rollup 作为打包工具。工具有了，接下来要谈谈用 TypeScript 写的代码，打包成什么类型的模块给别人使用。目前这种模块主要分几类。

第一类是我们熟悉的 CommonJS 和 ES6 Modules，这两种模块需要用户使用特殊的 module bundler 才能使用，比如 Webpack 或者 Rollup。第二类是 AMD，它已经显得有些过时了，而且也需要特殊的 loader，比如很多人在用的 RequireJS。还有一种在浏览器中可以直接使用的格式，叫 UMD，全称 Universal Module Definition。

UMD 推出时想形成一种通用的 JavaScript 格式，可以兼容 CommonJS、AMD 和浏览器这三种场景。它是怎么做到的？看一下最简单的 UMD 格式定义。它首先判断 `typeof define === 'function'`，并且 define 下面有 AMD 这个属性，说明当前环境注入了 AMD 的全局变量，就以 AMD 的形式来写模块语法；假如 `typeof module === 'object'` 并且 `module.exports` 存在，说明这是 Node 环境，也就是 CommonJS 类型，就以 CommonJS 的写法返回；假如 define 和 module 都不存在，那就是在浏览器中使用，直接把一个全局变量挂载到 window 上，可以看到它写的 `root = window`，root 从参数传进来其实就是 window，挂载上去后返回。

说白了，UMD 就是做了好几层兼容，支持三种格式，生成的文件可以直接在浏览器中引入使用。Vue 就提供了这样的支持：在浏览器里新建一个 HTML 文件，用 script 标签以 CDN 的形式引入 Vue，有开发环境版本和生产环境版本两种。打开它的源文件一看，似曾相识：一大堆 `typeof exports === 'object'`、`typeof module !== 'undefined'` 的判断，一看就知道它是 UMD 格式的。

这种格式看起来挺美好，使用也方便，支持多种使用场景。但对一个组件库来说，用它会有什么问题？看看 Ant Design 官网是怎么做安装引导的。它的第一种方式当然是 npm 和 yarn 安装，官方强烈推荐这种方式：不仅可以在开发环境轻松调试，也可以放心在生产环境打包部署使用，还能享受生态圈和工具链带来的诸多好处。第二种方式是浏览器使用，用 script、link 标签直接引用文件就可以获得全局变量。dist 下提供了一系列文件供自行引用。但下面有一条特别提示：强烈不推荐使用已构建文件，这样无法按需加载，并且难以获得 bug 的快速修复。

我们知道，ES Modules 的一大特点就是支持 Tree Shaking：需要哪个组件，只加载那个组件的逻辑就可以，这就是按需加载。Ant Design 的代码默认支持 ES Modules 的 Tree Shaking，这是一个很大的优化。那假如用 UMD 会怎样？即使只想用一个组件，也要引入整个文件。打开 npmjs 提供的 CDN 链接看一下，antd 主库的大小达到了 4.06M。只用几个组件却要引入 4M 多的文件，非常得不偿失。

再看 Element Plus，就是之前说过支持 Vue 3 的组件库。它同样是 npm 安装为推荐方式，能和 Webpack 打包工具配合使用；也支持 CDN 方式，通过 unpkg 获取最新资源后引入样式和组件库。点开看一下，index.full.js 也达到了 650k，同样是很大的负担。

所以遇到"该打包什么类型的文件"这种问题时，一个很实用的办法就是去看大型项目是怎么做的，照猫画虎。经过分析，我们的结论是：打包出来的格式应该以 ES Modules 为主。用户想使用的话，可以配置 Webpack 或者 Rollup 这种 module bundler；而且现在用 Vue 开发的项目一般都通过脚手架创建，天生就支持并采用 ES Modules 形式。同时要特别注意，由于我们用 TypeScript 开发，在其他项目中使用时还需要提供对应的类型文件。第二个方案是提供 UMD 格式作为备选，虽然直接用 script 标签引用几乎都不是推荐模式，但这些大型库都提供了这样的访问形式作为备选，并支持 CDN 直接引用。

讲了这么多节课的概念，下节课我们开始真正动手，看看怎样把 TS 源代码通过 Rollup 转换成这两种格式的文件。
