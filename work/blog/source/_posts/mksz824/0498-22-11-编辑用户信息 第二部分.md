上节课我们可以在页面中成功获取数据，还讲了两种方式。接下来的任务当然是完成更新用户：点击按钮时发送一个 PATCH 请求到后端，完成信息更新。看看怎样完成这个功能。

## 修改表单字段

先简单修改：现在按钮文字是创建，希望根据 isCreatingMode 显示不同的文字，直接复制然后替换。接下来添加一些属性：username 是独一无二的字段，不希望在更新时修改它，给它加一个 disabled 属性禁用掉；那它什么时候生效？编辑的时候生效，所以加一个条件。password 同理也加一下，因为我们不希望修改用户的 password。当然这按你的想法来：如果觉得管理员可以修改密码，就不需要加，按需求添加。

保存后：编辑模式下 username 字段没法修改，password 也一样，这样就区分了创建和更新时字段的不同规则。

## 发送 PATCH 请求

接下来发送不同的请求，逻辑根据是否是 creatingMode 处理。创建的逻辑写在原处；更新写在另一分支，叫 updateUser：await $fetch 发送到 api/users 加 ID，用 userId 替换，method 是 patch，data 和创建一样也是 event 的 data。加一个 console log 便于观察。

## 后端验证：omit 忽略规则

接下来要修改后端 API。之前的接口做得非常简单（列表里快速处理 disabled 用的），没有添加任何验证，需要把原来的验证机制补上去。

为了区别这两种更新，加一个参数 mode，以 query 形式传 `mode=updateUser`。后端针对验证要有不同的处理。特别注意：这里的验证逻辑和 create 有区别：更新用户时，有的字段并不是必选。创建时 username 是必选的；更新时它不能修改，所以要把 username 规则去掉。

假如直接从 userCreateSchema 复制字段过来就显得比较蠢，因为大部分和 create 相同，未来添加字段时两个地方都要改。我们希望根据 userCreateSchema 做一些修改，比如忽略掉某字段。这里是一个新知识点：创建新的验证规则 `userUpdateSchema`，完全基于 userCreateSchema 处理，它上面有个方法叫 `omit`，顾名思义就是忽略（TypeScript 里也用过对应的泛型）。传入一个 object，想忽略哪个属性就把 key 传进去设为 true：

```ts
export const userUpdateSchema = userCreateSchema.omit({
  username: true
})
```

这样 userUpdateSchema 把所有规则复制过来，只是忽略了想要的字段。

使用新规则验证：后端先拿 query（getQuery 传 event），判断 query.mode 等于 updateUser 时，走特别的验证过程：await runValidate(userUpdateSchema, event)，和 create 一样。这样通过 result.data 拿到值。

这里还有一个意想不到的结果：result 获取的字段和 schema 是相依赖的。用的是 userUpdateSchema，result.data 里的值就不会有 username 这个字段。即使前端把整个 data 都发送过来、username 有填充，经过处理 result.data 中也不会有 username，就实现了设想：不会更新这个唯一的值。

最后做更新：把 payload 放在外侧，创建一个空 payload，根据两个不同的条件重新赋值，更新分支的 payload 是 result.data。后端修改完毕。

## 测试

把 result.data 打印出来，验证字段是否被忽略。刷新页面，有值后修改 nickname 和 phoneNumber，点击更新：network 发送成功，后端返回的数据没问题。查看 data，username 被成功过滤掉了，正是想要的结果。重新进入页面，值更新成功，phoneNumber 也更新了，更新功能实现。

这节课的知识点：想通过一个 schema 创建一个非常类似的新 schema，可以在原 schema 上调用一系列方法，其中 omit 就可以忽略掉对应的规则。
