上节课讲了依赖注入的大体功能，这节课探索它怎样和 TypeScript 结合，获取更准确的类型。两个目的：一是 provide 时可以提供类型检查，只能传入特定类型的数据；二是 inject 时能获取数据的类型，language 有具体类型，而不是现在的 unknown。

## InjectionKey

Vue 提供了一个接口叫 InjectionKey，它是一个继承自 symbol 的泛型类型，可以在 provide 和 inject 之间同步注入值的类型。在 keys.ts 中用类型断言改造：

```typescript
import { InjectionKey, Ref } from 'vue';

export const languageKey = Symbol() as InjectionKey<Ref<string>>;
```

如果泛型写成 string，保存时会报错：因为我们传入的是一个 ref 响应式对象，类型不匹配，TS 帮我们检查出了问题。把泛型改成 `Ref<string>`（大写的 Ref 是响应式对象的类型）后错误消失。

再看返回值：使用 `inject(languageKey)` 时，language 自动获得了 `Ref<string> | undefined` 类型。带上 undefined 是因为值可能没有传入。inject 也支持传入默认值，传了默认值之后 undefined 就不存在了：

```typescript
const language = inject(languageKey, ref('en'));
```

这就是使用 symbol 的优点：只需在一个地方设定泛型，provide 和 inject 都能受益。很多组件要 inject 时每次都能获得对应类型。对比一下用普通字符串的情况：inject 返回的是 unknown，没法判断是什么类型，还得在 inject 上传泛型告诉它最终的值。所以我推荐使用依赖注入时用 symbol 作为 key：对 TS 的支持更好，比传泛型更简单，适用范围更广。

## 应用实例 API

除了在根组件上提供数据，还可以在整个 App 实例上提供，此时该实例上的所有组件都能通过 inject 拿到。来到 main.ts，我们之前没有好好审视过这个文件，它是整个应用的入口文件，负责将组件挂载到 DOM 节点上。把它分步改写以便理解：

```typescript
import { createApp, ref } from 'vue';
import App from './App.vue';

const app = createApp(App);
app.provide('userKey', { name: 'Viking' });
app.mount('#app');
```

createApp 传入根组件 App，创建应用实例；根组件有非常多的子组件，共同构成应用。然后调用实例的 mount 方法，把应用挂载到 DOM 节点上，节点就是 index.html 里的那个。

应用实例上还有很多属性和方法可以控制应用的行为，举几个例子：

- unmount：卸载组件。调用后页面一片空白，因为组件已经卸载掉了。
- app.config.globalProperties：配置全局属性，每个实例中都能拿到，比如配置一个 message。
- app.component：注册全局组件，比如把 HelloWorld 挂上去，使用时就不用每次导入了。

注意：配置属性和全局组件要在挂载之前完成。官方文档的应用实例 API 页面列出了所有属性和方法，课程会一点一点展开，这里简单了解即可。

## 在实例上注入依赖

在 app 上同样有 provide 方法，用法和组件里一样：提供一个 key 和值。把一个全局的用户名称挂上去，先导出 key：

```typescript
// keys.ts
interface IUser {
  name: string;
}

export const userKey = Symbol() as InjectionKey<IUser>;
```

```typescript
// main.ts
import { userKey } from './keys';

app.provide(userKey, { name: 'Viking' });
```

使用时同样用 inject 加 userKey，拿到 `IUser | undefined` 类型，用 type guard 类型收窄先判断存在，再取 name。刷新后整个应用都能注入这个依赖，Viking 显示在页面上，非常方便。

## 多个应用实例

最后讲一点：应用实例并不限于一个。Vue3 突破了 Vue2 的限制，一个应用中可以有多个应用实例，每个实例都是独立的，有自己的属性、配置和作用域。创建第二个实例并挂载到新的 DOM 节点（不能两个都插到同一个节点）：

```typescript
const app2 = createApp(App);
app2.mount('#app2');
```

两个应用都出现了，但有区别：第一个实例注入了 Name Binding 依赖所以能显示，第二个实例没有注入就无法显示，侧面印证了每个实例都是独立的。用 Vue Devtools 看也很清晰，能看到 App 和 App2 两个应用实例。
