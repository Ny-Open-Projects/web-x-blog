上节课完成了数据的创建，但现在创建完了没有任何交互，这不符合整体流程。接下来完成用户创建的扫尾工作，添加创建之后的动作。可以使用 modal 组件，它是 Nuxt UI 提供的，很简单，就是显示一个弹出窗。

我们希望在弹出窗中添加两项内容，也就是两个按钮：第一个点击后回到列表，第二个点击后再创建一个新的用户。现在来完成这个任务。modal 的使用非常简单，用一个 v-model 控制它是否显示，里面的内容想写什么都可以。这里就写一些简单的内容，添加两个按钮即可。

首先像文档示例一样把 isOpen 拿过来，放到 form 下面，然后添加 modal，把它和 uForm 放在同一层级。特别注意，modal 有一些属性可以修改样式：任何 Nuxt UI 的组件都可以通过 ui 属性修改里面的内容。我添加了一个 width，让它变成固定宽度，因为原来的宽度是 w-full，占满整行，我觉得太长不太美观，就简单修改了一下。在 config 当中可以找到所有和 ui 相关的类型，去修改对应的值，可以看到 width 在这里原来是 w-full。

样式调试阶段先把 isOpen 改成 true，让弹窗一直显示。在内部先添加最外层的容器，加一个 padding 和 text-center，让里面的内容居中显示。样式类的代码我就不一行行手写了，都是常规样式，大家能看懂就可以。里面添加一个标题「用户创建成功」，下面是一段描述性的文字（p 标签），再下面是最重要的两个按钮，用一个 div 包裹。

保存后应该会出现弹窗：「用户创建成功，请选择下一步操作」。首先添加回到列表的操作，用一个 UButton，样式和创建按钮一致，也是希望宽度百分之百。特别注意，UButton 支持 to 属性，也就是 link 上的属性，可以直接把它变成链接，跳转到之前的页面。color 和 variant（solid）这些样式属性可以直接查文档。现在生成了这么一个按钮，点击后跳转到 users 列表页，功能非常简单。

第二个功能，两步操作的第二步：再创建一个。把按钮拷贝过来，样式和上面完全一致，删掉 to 和 submit，把文本改成「再次创建」。

点击再次创建后，需要把表单里已有的数据恢复到最初的原始状态，这才是真正要完成的任务。来处理这个逻辑。

首先要修改之前的一点小代码，它带来了一个小 bug。来到 userCreateSchema 这个 zod object 创建的 schema，会发现里面没有 picture 这个验证规则，也就是我们要上传的图片。这会造成在后端的 post 接口里，payload 没有这个字段时会被自动过滤掉。所以大家特别注意：假如你希望最后获取到什么字段，即使它的规则是一个无关紧要的规则（就像 nickname 那样），也要把这个字段添加到 schema 当中。把 picture 加进去，它才会出现在最终的字段里。这是个小问题，请大家注意并修改。

接下来改进 UI。现在点击创建以后没有动画交互，我们希望添加一个 loading 状态，告诉用户正在创建，并禁止多次点击创建按钮，这是非常有必要的交互。添加一个 isLoading，初始为 false。样式已经调试完毕，接下来调试功能，把 isOpen 也变回 false。isLoading 可以添加到 submit 按钮上，它有 loading 属性，把 isLoading 绑上去。

有了这两个属性，发起请求时把 isLoading 置为 true：来到 onSubmit，在 clear 之后置为 true；再添加一个 finally，在最后的逻辑里把它置回 false，不管请求是否成功。同时在 createUser 创建成功以后，要把 modal 打开，把 isOpen 的 value 设置为 true。

整个流程到这里就差不多了，剩下的任务是把这么多属性恢复到最初的值。假如一条一条去写，会发现非常繁琐，因为属性实在太多。我们现在是一条一条写的方式，目前数量还不多，不会觉得冗余，但随着它不断增长，一直这样写肯定不切实际。所以要想一个新方法完成这个功能。

先创建一个响应式函数，叫 recreate。首先把 isOpen 的 value 设置为 false，把弹窗隐藏掉，然后处理数据。创建一个最初的数据叫 initialUserData，单独放到一个 object 当中，因为要对它单独使用。初始化的时候也可以直接使用这个值，不需要再写一遍。这里特别注意，不能把 initialUserData 直接传进去，因为整个操作是 mutable 的：当你修改了 userData 的 value 时，里面的值也会跟着修改，最终这个原始值就变了。所以要把它展开一份，等于拷贝一份，原始值就不会受影响了。

修改完毕后，完成重置功能其实很简单：使用 Object.assign 做重置，第一个值是 userData.value，后面是 initialUserData。通过这种方式一行就完成了值的重新赋值。这种方式请大家特别注意，想用同样的方式修改别处也完全可以。recreate 就完成了。

把这个回调添加到「再次创建」按钮上面。有了这些以后，测试整个流程。刷新页面，创建一个条目：输入 viking567，nickname 填 Viking，上传一张比较小的图片，其他暂时填简单的，邮箱 viking@test。填完点击创建，弹窗出现了。测试「再次创建」，点击以后希望所有值都被置为原始值。可以看到大多数值都已经被置为原始值了，但是 uploader 这里的值没有被置为原始值。而从属性列表上看，picture 其实已经是空值了，说明组件本身写得有一些问题，来对它做一个小修改。

看到这行代码就知道缺少了一个处理：这是一个经典问题，innerValue 是从 props.modelValue 赋值的 ref，当外面进行修改的时候，它这个值并没有跟着修改。这是处理 v-model 时非常常见的问题，之前也多次说过。解决很简单，添加一个 watch 就可以。watch 哪个值呢？添加一个 getter function，watch props 上面的 modelValue。拿到 newValue 以后给它完成一次重新赋值。但这里首先简单判断一下：判断 newValue 是一个 string，是 string 的时候再重新赋值。使用 lodash 的帮助方法 isString。如果 newValue 是 string，就把 innerValue.value 等于 newValue。

通过这种方式应该就解决了这个问题。再验证一下：刷新页面，创建一个新条目，输入 910，其他暂时不填，测试是否会进行修改。还是传这张图片，上传完毕后点击创建，再点击再次创建。可以看到值被重置了，并且组件现在也可以成功工作，还原到了最初始的状态。

整个任务就完成了：不光完成了用户的创建，创建之后的收尾处理也都完成了。这节课就到这里。
