上节课我们在交互上取得了突破：元素被拖动时会显示一个浮层并跟随鼠标移动。交互完成之后，现在要讨论数据排序的更改。需求中数据是在拖动的过程中发生更改的，这节课先简化一下，在 drop（松开鼠标）的时候完成修改顺序。通过这个相对简单的过程了解整个编码后，下节课再移植到拖动过程中进行交换。

## 记录起点索引

列表排序说白了就是数组操作：把一个索引移动到另一个索引的位置。所以要知道被移动条目在数组中的起始索引，以及要移动到的索引。在响应式数据中添加变量来记录：添加一个 `currentIndex`，初始设为 -1（是数字而不是字符串）。在 `onDragStart` 时给它赋值，所以要多加一个参数 index（number 类型），函数内部执行 `dragData.currentIndex = index`。模板中把 `v-for` 的 index 也传给 `onDragStart` 即可。

## 用 dataset 在 DOM 上保存目标索引

drop 的时候要拿到新的 index。onDrop 时只有事件对象，怎样获得要 drop 到的条目的索引呢？事件对象可以通过 `e.target` 取得正在被触发的 DOM 节点，如果把对应的 index 保存在 DOM 节点上，就能拿到索引。

这就回到了怎样在 DOM 上保存数据的问题。可以使用 HTMLElement 上的 `dataset` 属性，它是 JavaScript 的一个接口，可以读取元素上设置的所有自定义数据属性，即 `data-` 后面接自定义名称，称为自定义数据属性。

先在每个条目上创建自定义数据属性 `data-index`，然后在 onDrop 中取值：

```ts
const currentElement = e.target as HTMLElement
const moveIndex = parseInt(currentElement.dataset.index)
```

注意 `e.target` 是 EventTarget 对象，要断言成 HTMLElement。dataset 取到的值是 string 或 undefined 类型，所以要加 `parseInt` 转换成数字。

保存测试：拖动图层一放到图层二上，打印索引 1（第一个是 0）；拖动到图层三，打印 2，没问题。

## 向上检索父元素

但要注意一个坑：`e.target` 是鼠标指向的元素。当你在某个子元素上释放时，target 会是那个子元素。比如在图层一的锁图标上拖放，什么都没有打印，currentElement 打印出来是锁这个 DOM 元素，它上面没有 data-index。

所以需要一个方法在 DOM 上向上检索，找到符合特定条件的父元素就停止：从锁往上找，直到找到 li 并读取上面的属性为止。创建一个新的导出函数 `getParentElement`，两个参数：要查找的 element（HTMLElement）和 className，查到符合类名的元素就停止。

实现用 while 循环：element 存在就继续找；如果 `element.classList` 存在且 `element.classList.contains(className)`，说明找到了，直接 `return element`；否则往上走，`element = element.parentNode as HTMLElement`，因为 parentNode 可能是 null（Node | ParentNode | null 的联合类型），这里做类型断言为 HTMLElement。最后如果什么都没找到，return null。

在 onDrop 中使用它：先导入这个 helper，把 `e.target as HTMLElement` 和类名 `list-item` 传进去。返回值 currentElement 可能是 null，所以要先做 type guard 判断它存在、并且 `dataset.index` 也存在，才继续取值。加了 type guard 之后类型错误消失。

测试：故意往犄角旮旯拖，拖动图层一放到锁上面，依然能拿到索引 1，说明 getParentElement 往上查找到了 li 并停止，正确读出了属性值。

## 用 array-move 完成交换

能成功拿到两个索引，就可以开始完成交换了。数组条目的移动相信大家都有自己的方法，这里我直接用一个第三方库：array-move，一个非常流行的小工具，可以方便地完成数组的移动，并提供了两种方式：immutable 方式调用 `arrayMove`，不改变原数组；mutable 方式调用 `arrayMove.mutate`，会改变原数组。安装直接 `npm install array-move` 即可。之前提到非常流行的 React Sortable HOC 列表排序库，内部用的就是 array-move。它自带类型文件，不需要额外安装 @types。

现在在 onDrop 中使用。因为我们的数据是响应式的，可以直接 mutate 修改原数组：

```ts
arrayMove.mutate(props.list, dragData.currentIndex, moveIndex)
```

三个参数依次是：要修改的数组（这里是 `props.list`）、起始索引（`dragData.currentIndex`）、移动到的位置（`moveIndex`）。

看最终结果：把图层一移到图层二，现在是图层二、图层一，没问题；移到最下面也没问题。我们就通过了这一系列编码，完成了拖动排序的任务。

不过目前只是在 drop 的时候进行了重新排序，下节课我们将在拖动的交互过程中实现更具体的功能。
