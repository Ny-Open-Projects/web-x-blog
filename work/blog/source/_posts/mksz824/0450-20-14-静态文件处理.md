上节课探讨了 Nuxt 3 的数据获取，接下来几节课继续补充基础知识。Nuxt 3 的基础知识比较庞杂，有很多规范，但正因为有了这些规范，我们才能更快、更容易地写出最终的应用。这节课讲一个相对简单的内容：静态文件（Assets）。

在 Nuxt 3 中，可以用静态文件存放不需要经过编译的资源，比如图片、字体文件等等。首先要了解两个概念：静态文件主要被组织在两个文件夹中，public 和 assets。

public 可以看作静态服务器的根路径，放在 public 文件夹中的任何静态资源，都可以通过 URL 直接访问，是最直观的存放位置。assets 则用于组织未编译的静态资源，注意"未编译"这个说法：比如 CSS、LESS、Stylus 等样式文件，需要编译工具处理后才能展示；或者某些特殊的图像资源，需要经过 bundler（默认是 Vite，也可以自己配置成 Webpack）处理后才能使用。

先详细介绍 public。存放在这里的文件会被原封不动地复制到编译后的输出目录。public 文件夹本来就有，里面已有一个 favicon 文件，我又放进去一个 logo.png 和一个 style.css。比如访问 `/logo.png`，可以直接打开；`/style.css` 也可以直接访问。这样就能很方便地引入这些静态文件：想在 app.vue 中展示 logo，直接把 src 设为根路径下的 logo.png，加上 alt 描述即可，首页就能完美显示这张图片。

再看 assets 文件夹，它需要自己在根目录下创建。assets 中的文件会经过 Vite（默认）处理后在项目中使用。同样展示这张图片，就不能用普通 URL 了，要加一个波浪号 `~` 表示项目根目录，然后写 `~/assets/logo.png`，通过这种方式引入 assets 下的静态文件，它实际是经过 Vite 处理的。保存后最终效果完全一样，但两者的处理方式不同。特别注意：assets 中的内容不会像 public 那样生成静态 URL，直接访问 `/assets/logo.png` 会得到一个 404 页面。

单个图片的例子两者效果差不多，样式文件就不同了。想在应用中引入一个 CSS，这种文件经常需要 bundler 处理。假设 assets 中已放了 style.css，可以在组件中直接使用，有两种方式。

第一种是在组件的 style 模块中 import，路径同样用 `~/assets/style.css`：

```vue
<style>
@import url("~/assets/style.css");
</style>
```

保存后整个页面背景变成蓝色，引入成功。第二种是在 script 中引入，同样是 `import '~/assets/style.css'`。正是因为它经过 Vite 处理，我们才能这样导入样式，最终效果也一样。

总的来说，public 和 assets 是 Nuxt 3 对静态资源的两种不同处理方式，根据实际情况恰当使用，可以让项目更灵活高效。下一章我们继续看看样式还有什么玄机。
