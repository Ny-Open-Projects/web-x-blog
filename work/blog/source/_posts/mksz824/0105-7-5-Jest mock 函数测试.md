上节课学习了异步代码的测试方法。这节课来看 Jest 另一个重要功能：mock。mock 这个单词是造假的意思，大家肯定听说过 mock server，就是为前端提供假的后端。那在我们的代码中为什么要有 mock 呢？

想一想，开发前端项目时，很多时候需要根据后端返回的数据来渲染页面，我们通常用 AJAX 发送请求到服务端；开发后端代码时，有时需要连接数据库，根据数据库中的数据执行后续的逻辑，或者还有其他依赖。这些开发都有一个公共的局限性：依赖别的服务，需要别的系统的支持。怎么解决这个问题呢？这就是 Jest 提供的 Mock 解决方案。它通过所谓测试替代的方法，轻松消除测试的复杂度。测试替代顾名思义，就是测试中使用真实代码的替代品：回头看 AJAX 的例子，我们不需要设置服务器，而是直接使用 AJAX 的替代代码。

所以在测试中，mock 就有造假的意思：把一些和测试无关的、或者需要自定义的实现用 mock 替代，让测试更好地分离成单独的模块，不被第三方内容影响。mock 有两个大的用途。第一个是代码中需要回调的时候，创建一系列 mock function，测试这些回调是否被调用。这个功能在单向数据流的组件框架中特别好用，比如 React 和 Vue，它们不直接修改父节点传来的数据，而是经常使用回调函数或事件把新的值传出去，这时就可以测试这些回调是否被成功调用。比如 click 一个 button 要发送事件，就可以用这种方法测试。第二个用途是直接替换一些有副作用的第三方模块的实现，所谓狸猫换太子，让测试顺利执行下去。

这节课主要看 mock 的第一大功能：创建 mock 函数。我这里已经写好了两个空的 test case，并且有一个函数叫 mockTest。现在要测试传入参数的时候，cb 是否被调用。

写法是创建一个变量 mockCb，调用 jest.fn()。jest.fn 创建一个假的函数实现，你可以把它想象成一个监听器，主要收集函数调用的信息，用来验证一些事件：是否调用了函数、调用时传的参数是多少。有点像窃听器，监听这个函数有哪些进、哪些出、做了什么事，而监听过程是不会被 mockTest 函数感知到的。

接着写测试：mockTest 第一个参数 shouldCall，为 true 时会调用 cb，暂时传 true；第二个参数是回调，把 mockCb 传进去。然后写 expect：`expect(mockCb).toHaveBeenCalled()`，断言它是否已经被调用。跑一下，case 过了，说明 mockCb 被成功调用了。再把 true 换成 false，验证这个测试是否好用：这时报错了，函数没有被调用，而我们的断言是 toHaveBeenCalled。改回来，说明测试是有效的。

它还可以测被什么参数调用。mockTest 内部是 `cb(42)`，所以可以测它是否被 42 这个参数调用：`expect(mockCb).toHaveBeenCalledWith(42)`。还可以测被调用了多少次：`expect(mockCb).toHaveBeenCalledTimes(1)`。跑一下，这些应该全部通过。假如再给它加一次 cb 调用，改成两次，也能通过。

新建的 mockCb 本身是一个函数，上面还有一系列属性。console.log 打印一下，mockCb 上有一个 mock 属性，里面包含更多信息。第一个是 calls，它是一个数组，数组每一项代表每次调用的情况。可以看到数组只有一项，说明被调用过一次，并且能看到传入的参数是 42。除了 calls 还有 results，代表每次调用的返回值。可以看到被调用过一次，value 是 undefined，因为 mockCb 没有具体的实现，默认返回 undefined。

现在给 cb mock 一个实现。在第二个 case 中，把想要的实现写到 jest.fn 的函数体内：比如希望它返回参数乘以二，就写 `return x * 2`。cb 被替换成这个实现之后，返回值应该是 42 乘以 2，也就是 84。打印一下 results，现在 value 是 84，jest.fn 里的逻辑被成功实现了。

除了这么写，还有一个快捷方式：mockReturnValue。可以直接 mock 它的返回值，再打印看一下，value 变成了我们指定的值。

这节课先到这里。我们讲了 mock 的来历和功能，以及它两大用途中的第一个。不过在第二个用例里，我们也多多少少接触了第二个功能的皮毛。下节课继续狸猫换太子之旅，看看它还有什么更强大的功能。谢谢大家，再见。
