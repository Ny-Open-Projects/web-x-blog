Docker 镜像的优化都完成了，是时候把应用部署到服务器了。登录服务器，先完成一些配置，再运行，看看能否成功启动。

## 第一步：安装 Docker

登录服务器后先安装 Docker。一些云平台的主机直接提供预装好的 Docker：比如 Digital Ocean 创建主机时可以选择 Distribution（操作系统），还有 Marketplace 提供预设置的镜像，直接选 Docker on Ubuntu 就会把 Docker 预装好。国内的主机一般也有类似功能，创建镜像时可以留意。

如果没有预装，就手动安装。这里提供两个教程：Runoob 和 Docker 官方文档，都可以，按步骤安装即可，其他操作系统也都有对应文档。注意安装时要切换到 root 用户。安装完毕后启动 Docker 服务并确认它在运行：

```bash
service docker status
```

显示 running 说明准备工作第一步完成。

## 第二步：配置用户组

因为是用 root 完成安装的，普通用户执行 Docker 命令有时会报错：cannot connect to the Docker daemon / permission denied while trying to connect to the Docker daemon socket。这说明当前用户没有权限操作对应的文件。

先观察这个文件需要什么权限：cd 到 /var/run，`ll -a` 后 grep docker，找到 docker.sock。顺便复习一下文件权限的含义（很有用的 Linux 知识）：第一位是文件类型，常见的 d 是 directory（文件夹），这里的 s 是特殊类型，指 local socket file；后面每三位一组，第一组是 owner 的权限（root 具有 r w，即 read 和 write），第二组是所属组 docker 组成员的权限（也是 r w），第三组是其他用户的权限（这里毫无权限）。另外紧跟着的分别是 owner 和所属组的名称。

所以要做的事就是把我们的用户添加到 docker 组里。Linux 天生是多用户系统，可以通过用户组完成权限控制。用到一个新命令 usermod（修改用户账户），配合两个选项：`-a` 是 append，将用户添加到对应的组；`-G` 是 groups：

```bash
sudo usermod -aG docker viking
```

这就把 viking 添加到 docker 组。如果报错说没有这个组，先 `sudo groupadd docker` 创建。添加完后用 `groups` 查看当前用户所属的组：应该属于 viking 自己的组和 docker 组，之后就有权限执行对应操作了。

## 第三步：配置国内镜像加速

直接使用 Docker 官方镜像源，下载速度会很慢，所以要配置国内镜像加速，和本地使用时类似，通过配置文件完成。Docker Desktop 里是 Docker Engine 的 JSON 配置；Linux 主机上对应的是 `/etc/docker/daemon.json`（要用 root 修改）。把之前写的 registry-mirrors 两个地址拷进去，镜像加速就配置完毕了。

第二步和第三步是可选的：如果你的普通用户本来就有执行权限，就不用配置用户组。

## 运行

准备工作完成后开始运行。首先拉取最新代码：项目里已经有最新的 Dockerfile。启动前特别注意：先查看目前端口是否被占用。之前服务器上本地跑过一系列服务，比如 `service mongodb status` 显示 Mongo 在运行并占据了 27017 端口，Redis 也是；再用这些端口启动就会报错。

两种解决方案：一是关闭本地的 MongoDB、Redis；二是改变 docker-compose 中的映射端口。这里采用第二种：cat docker-compose.yml 可以看到，mongo 的外部端口改成了 27018，opsflow-redis 的暴露端口改成 6378，就不会占用对应端口了。

现在见证奇迹：

```bash
docker compose up -d
```

因为之前运行过，镜像已经生成，速度很快。可以看到 creating a network，然后依次启动 opsflow-mongo、opsflow-redis，最后启动 opsflow-backend，全部 done，没有错误。

验证：这次端口改成了 7002（7001 之前已经跑着一个本地部署的服务），访问 API，查看我们设置的 ping 接口：主机上启动成功，dbVersion、readyStatus、appVersion 都正常，env 成功读取，config 没问题。再看 templates，预置的数据也成功插入并可以返回，整个运行过程成功。

回顾部署到服务器的过程，有了 Docker，各种软件的安装不再是问题，一共四步：安装、配置用户组、添加下载镜像加速、运行。现在我们成功在服务器上运行了 Docker 服务。
