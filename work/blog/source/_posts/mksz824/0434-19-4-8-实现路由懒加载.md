上节课我们完成了关于第三方库的优化过程，这节课进入下一步优化。之前一直在给第三方库做优化，现在看看除了第三方库之外，应用 App 这个主要脚本有没有可以优化的点。

## 动态 import 规范

对于大型应用来说，首当其冲的问题就是所需加载的 JavaScript 的大小。程序应该只加载当前渲染所需要的 JS 文件，将所有代码分拆成多个小包、在用户浏览过程中按需加载，是一个很好的想法。而路由非常适合做代码拆分：路由的责任就是配置好每个 view，它们之间不会有功能冲突。我们有这么多路由，每个路由针对一个 component，假如把这些 component 拆分在不同的文件，访问这个路由的时候再加载这个文件，就是很完美的解决方案。

完成这个任务首先需要规范的支持：动态 import，来自 ES2015 的最新规范。关于模块的 import，我们大部分时间用的是静态方式，但它还有一种异步的方式，叫动态 import。使用方法很简单：直接调用 import 传入模块名称，它返回一个 promise，可以使用 then 拿到模块相应的内容做对应的处理。

Webpack 可以很好地支持这个已经属于规范的动态导入，采取的方法一模一样。

## 实验：点击时动态加载

来到之前的 webpack-test 项目。main.js 中添加了 lodash 模块，使用它的方法把字符串做转换。现在修改一下：一开始 root 中不输出这个信息，只有点击某个按钮时，动态加载第三方模块 lodash，再输出对应的信息。

在 index.html 中添加一个 button，点击时执行对应的逻辑。main.js 里监听这个 button 的事件：

```js
document.getElementById('test').addEventListener('click', () => {
  import(
    /* webpackChunkName: "my-lodash" */
    'lodash'
  ).then(({ default: _ }) => {
    document.getElementById('root').innerHTML = _.join(['Hello', 'Viking'], ' ');
  });
});
```

监听的是 click 事件，里面使用动态的 import 加载模块名称 lodash。then 的第一个参数就是 lodash 模块，在里面做对应的处理，把字符串进行转换。

运行 npm run build（这里也添加了 bundle analyzer）。首先可以看到它打出了两个文件：一个是 main.js，是里面的这些逻辑；同时还生成了一个 bundle.js，其中是 lodash。它是自动帮我们做的：当有动态模块的时候，会帮我们单独打出一个文件。

刷新页面，一开始只加载了 main bundle，也就是主要的入口文件。清空之后点击 Click to Load，可以看到点击时动态加载了那个文件，然后输出了对应的信息，任务完成。

## Magic Comments 魔法注释

这个例子可以完美运行，但有个问题：打包出来的都是模块的 ID，我们根本不知道这些 chunk 文件到底是哪些模块。如果某个 chunk 文件太大，怎样知道它对应的是哪个文件呢？所以有必要加入人类可读的信息。

ES2015 的规范中不支持指定动态导入模块生成的文件名称，不过 Webpack 玩了一点小花招：Magic Comments 魔法注释。使用这些魔法注释就可以添加一系列操作，比如给 chunk 命名或者选择不同的模式：webpackChunkName 加上你的信息，还有 webpackMode 等等。我们在 import 的最前面（module 的前面）添加一个 webpackChunkName，名称称之为 my-lodash，保存后重新打包，这时模块就有了对应的命名，知道这个模块是从哪来的了。

## 应用到路由

做完第一个实验，有了这个前提，优化路由就变得很简单了。切换到我们的项目，来到定义路由的地方。component 现在是一个个静态的组件，但除了这样的写法，它还支持动态 import。Vue Router 文档里有一节 lazy loading routes，描述是 supports dynamic imports out of the box，也就是直接支持动态加载路由。

只要把一个路由写成一个 function，function 当中使用 import 直接加载，返回的 promise 赋值给 component 就可以了。文档还特别说明：we only fetch when enter the page for the first time，只有进入到这个路由时才会加载对应的脚本。

我们使用两个比较大的页面，editor 和 login，做两个例子。把静态的组件修改成 function 的形式：

```ts
{
  path: '/editor/:id',
  name: 'editor',
  component: () =>
    import(
      /* webpackChunkName: "editor" */
      '../views/editor/index.vue'
    ),
},
```

也就是返回一个 function，里面是一个 import，指向组件的位置，然后添加 webpackChunkName 魔法注释来改变打包文件的名称。再把 login 做对应的修改。修改完毕后，原来的那两个静态 import 就没用了，删掉。

## 验证

首先看打包文件会变成怎样，运行 build:analyze。可以看到原来应用有一个大的文件 app.js，现在分成了好几块，按照我们的设想在工作：一块叫 editor.js，是分割出来的关于编辑器那一部分的代码；还有 app.js；最下面还有特别小的 login.js，是关于登录的代码。通过这种方式就完成了大文件的分割。

再试一下访问对应路由时会不会动态加载这些脚本。运行 npm run serve，来到首页。现在没有登录，点击登录时希望它动态加载脚本：点击登录，发现它动态加载了 login.js，和 login 相关的逻辑都写到了这个文件中。editor 大家可以自己试，其实也是一样的规则。

这节课了解了动态导入的规范和使用，最后将路由中的组件以懒加载的方式进行了替换。现在我们的应用文件得到了优化，收获了异步加载的能力。
