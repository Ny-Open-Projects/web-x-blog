这节实现获取验证码的功能。整个过程不复杂：发送验证码和用户的 store 没有关系，验证码是否发送成功、返回什么都无需存入 store，这个请求就是一次性的，直接用 axios 发送即可。

唯一需要留意的是获取验证码按钮的状态。初始状态下按钮不可点击，用户填入正确的手机号后才能点击；点击后进入六十秒倒计时，期间同样不可点击，倒计时结束才恢复。这是各类网站发送验证码的通用逻辑，关键就是倒计时状态的变化和切换。

## 按钮禁用状态

先创建一个判断按钮是否禁用的状态，命名为 `codeButtonDisabled`。它是一个计算属性，返回条件取反后的校验结果，手机号没通过校验（`form.cellPhone.trim()` 为空）时就禁用：

```ts
const codeButtonDisabled = computed(() => !form.cellPhone.trim())
```

把它绑到 AButton 的 disabled 属性上。页面里可以看到按钮已经变灰，只有输入正确的手机号才会变成可点击状态。

## 发送请求

接下来处理点击后的请求。创建一个 `getCode` 方法，先对照接口：接口是 `user/generateVerifyCode`，body 里需要一个 phoneNumber，请求方式是 POST。因为不需要经过 store，直接用 axios 发送：

```ts
const getCode = () => {
  axios.post(url, { phoneNumber: form.cellPhone }).then(() => {
    message.success('验证码已发送，请注意查收')
  })
}
```

成功时暂时简单提示一条消息即可。把 getCode 绑到按钮的 click 事件上，打开 Network 面板测试：输入手机号点击获取验证码，请求成功发出，同时页面上出现对应的提示。

## 六十秒倒计时

发送成功之后是倒计时逻辑。自然的思路是用 setInterval 频繁修改一个响应式对象的值。先创建响应式对象 `counter`，初始值为六十；再单独写一个 `startCounter` 函数，内部用 setInterval 每秒把 counter 减一。在 getCode 成功后调用 startCounter 开始倒计时。

模板文案也要跟着变：counter 等于六十（即初始状态）时显示"获取验证码"，否则显示"多少秒后重新发送"，把 counter 渲染出来即可。同时禁用条件扩展为两个：手机号未通过校验，或者 `counter.value < 60`，倒计时期间按钮保持禁用。

此时点击获取验证码，能看到倒计时正常进行，按钮处于禁用状态。

## 倒计时结束的复原

最后是复原：倒计时结束后按钮恢复可点击，counter 重置为六十。最简单的办法是 watch counter 的值，回调拿到 newValue（number 类型），当它减到零时做两件事。

第一件事是清理定时器。之前创建的 setInterval 一直没有清除，所以需要一个 `timer` 变量保存 setInterval 的返回值，在 newValue 为零时调用 clearInterval 清掉它。第二件事是把 `counter.value` 复原为六十。

```ts
watch(counter, (newValue) => {
  if (newValue === 0) {
    clearInterval(timer)
    counter.value = 60
  }
})
```

再跑一遍完整流程：倒计时从 6、5、4、3、2 减到 0 后，按钮恢复为"获取验证码"文案，可以重新点击。至此验证码获取功能完成，下一节开发登录和获取用户信息的流程。
