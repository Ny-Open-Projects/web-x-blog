这一周刚开始我们就说过开发理念：从简单的流程入手，先完成一个基本流程，再在流程中抽丝剥茧地发展出更多的需求和场景。可以把最基本的流程看作一颗种子，种下去慢慢成长成参天大树。现在基本流程已经超额完成：能成功完成上传、用列表形式展示上传文件、三个阶段都支持自定义模板，还完成了生命周期钩子中最前面的 beforeUpload 上传前验证。

开发这种大型任务，中期回顾非常有必要。任务比较多，做到一半时对现有功能和进度进行回顾总结，可以审视进度到哪里，并预估什么时候能完成整个任务。

在开发进度表中，我把完成的功能都用 checkbox 做了标注。非常建议大家都维护一份对应的知识点笔记，记录开发每一项任务时学到的知识和经验，回顾时就能把这些知识点重新过一遍。现在这颗种子已经长成了小树，是时候讨论更多的场景和需求了。

## 留作业：生命周期事件

我再次审视还没完成的需求，这里想给大家留个作业。开发过程中的方法论都已经教给大家了，你们需要花时间实践，我会把一些琐碎的点留给大家完成。标红的就是希望大家完成的任务。

首先是一系列生命周期事件。目前只做了 beforeUpload，剩下的有 onProgress、onSuccess、onError 和 onChange，实现起来应该都不难。唯一要动脑子的就是 onProgress：怎样拿到上传进度？其实 axios 已经提供好了对应的 API，大家自己去参阅文档。拿到上传进度后，还可以把界面升级一下，显示一个上传进度条之类的。

第二个是怎样设计事件发送的参数。使用时监听这些事件，肯定希望拿到特定的参数，通过参数做一些判断和操作。可以参考 Ant Design Vue 和 Element Plus 的实现。Ant Design Vue 的事件有三个参数：第一个是 file，当前操作的文件对象，包含 uid、name、status 等，和我们的 UploadFile 类型非常相似，我们的数据结构设计就是借鉴了它；第二个是 fileList，当前的文件列表数组；第三个是 event，上传中服务器端的响应内容。Element Plus 的 onSuccess、onError 等参数是分开的：第一个 response（服务器的返回），第二个 file，第三个 fileList。可以看出两者殊途同归，参数几乎完全一样。

## 细碎需求：丰富上传数据

除了这块大需求，还有一些比较细碎的需求，是参阅他们的文档后发现的，希望大家自己完成。

第一类是丰富上传数据的定制。目前 upload 组件发送 HTTP POST 请求的可定制性很差。发送请求时有几个重要属性用户可能要自定义，比如自定义 headers，发送什么样的 header，我们目前不支持。

另外，post 是以 key-value 的形式发送数据的。看我们的 postFile 实现：formData 中只有一个字段，而且字段名写死成了 uploadedFile 的 name，这是一个很错误的做法，后端肯定需要一个特殊的 key 来处理上传上来的文件。所以要添加一个 name 属性，确定 file 对应的 key 名称。发送 post 时除了 file 对象还可能有更多数据，所以需要一个 data 参数，它是一个对象，用 key-value 添加更多 post 数据。

第二类是 input 本身支持的约束 file 的属性：multiple 支持文件多选，设成 true 后打开选择框就可以选多个文件；accept 支持限定可选择什么样的文件。这些原生属性都要一一添加上。

最后一个属性也非常常见：POST 发送时是否携带 Cookie，默认是 false。可以使用 withCredentials 支持，这也是 axios 默认支持的属性，大家可以查文档。

以上就是中期回顾：了解目前的开发进度，并通过研究成熟上传组件的 API 获得新的需求。标红的内容大家可以用任何方式完成，先写测试或先写实现都可以，看自己喜欢。对于这种复杂需求，中期回顾是非常有必要的。这节课到这里，谢谢大家。
