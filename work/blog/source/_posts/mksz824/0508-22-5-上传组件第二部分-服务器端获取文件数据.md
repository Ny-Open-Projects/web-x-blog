上节课完成了上传组件的初步功能，这节课来完成真正的文件上传。需要创建一个新接口，把文件发送到这个接口，并在接口中获取文件内容。看看 Nuxt 当中 Nitro（也就是 H3）是怎样完成这个功能的。

先回顾文件上传的原理。本章「文件上传本地加 OSS 云服务」对文件上传的知识已经学习得非常充分了，从简单到复杂，还有源代码解读，几乎把文件上传的方方面面都讲到了，有遗忘不妨回看。那个阶段我们大量使用了 stream（流）这个特性，而在 H3 当中要使用的是 Buffer，它是 Node.js 用于处理二进制数据的标准对象。

现在来看怎样完成这个功能。前端要先发送请求，现在已经能拿到文件了，就是 uploadedFile，所以新建一个函数，叫 postFile。它接受一个参数，可以叫 readyFile，也就是已经准备好的文件，类型是 File，并且应该是一个 async 方法。

上传文件要使用 FormData，Content-Type 是 multipart/form-data 这个标准类型。所以先创建一个 `new FormData()`。在 FormData 当中可以调用 append 方法把数据添加进去，名称叫 file，添加的数据就是 readyFile。

添加完毕后发送请求。我已经创建好了请求函数，看它的路径：api 下的 utilities/upload。注意要发送的是 POST 请求。这里自然调用 await，应该使用 $fetch。第一个参数是发送到哪里，我们把它配置为可变的属性 action，类型是 string，传入 props.action。后面是更多信息：method 设为 post；body 直接把 formData 放进去就可以。这里不需要添加任何 headers，不需要手动添加 Content-Type，$fetch 会帮我们自动分辨并添加，写这两个参数就够了。外面用 try catch 包住，错误时处理，最后再加一个 finally。

接下来是在 upload 接口中获取文件对象。保存后回到页面，刚才添加了 action 属性，现在要把它传上，路径是 api/utilities/upload。

H3 提供了两个命名非常明晰的方法。第一个是 readMultipartFormData，顾名思义，用来获取 multipart/form-data，也就是上传文件想要的效果，调用很简单，直接获取即可。和它相对的还有一个 readFormData，用于不包括二进制文件的基本类型。另外还有一个 readRawBody，直接获取原始的 body 信息，之后也会演示。

第一步使用这个全局方法，称之为 formData，`await readMultipartFormData(event)`，把 event 传进去。然后用 console.log 把 body 打出来，最后做一个返回。这里先不处理真正的上传，因为之后会用阿里云上传。我们先看文件数据放在哪里、怎样获取，使用文件数据完成上传是下节课的任务，所以先返回上节课那个假的 URL。

接下来把 FileUploader 当中的逻辑写完。result 应该包含对应的 URL，先 console 一下看是否成功返回了 url，它应该在 result 上的 url。可以看到返回的是 unknown，其实已经返回成功了，只是没有实时获取到类型，因为 props.action 没法做类型联想。给它设置最终返回的类型，在 $fetch 上传递一个泛型，告诉它最后返回的数据类型，就不会出现这个错误了。

在其中首先要更新 v-model，这里直接调用 postFile，把 uploadedFile 传过去。这两个添加好以后，再多添加一些事件。一个标准的上传组件除了支持 v-model，还会支持一系列事件，之前的编程中写过很多。这里简单加两个：第一个是 change 事件，数据发生变化时触发；另一个是 error，出现错误时触发。上传成功时也会触发 change，甚至文件格式可以写得复杂一些，不只返回 URL，把 result 返回出去，再把 file 返回出去，把 readyFile 传进去。

error 同样处理，直接把 error 对象绑出去。在 function 里还要特别注意：需要把 input 的值清空，否则下次选择相同文件就不会触发。当 fileInput.value 存在时，把它上面的 value 置为空。

第一部分代码写完了，测试上传流程。点击 upload，选择一个文件，点击打开。可以看到请求发送成功，URL 也直接返回了。我们不关心这些，关心的是文件数据到底在哪里。之前在接口中 console.log 了 body（formData），看真正的 formData 是什么。可以看到它返回一个数组，数组中有多项，这里只传了一项，只有文件，name 是 file，和前端一一对应。其中还有更多信息，比如 filename 和 type。最后我们关心的是 data，可以看到它返回的是 Buffer 对象。Buffer 是 Node.js 中和二进制相关的标准处理对象，有了它就可以使用阿里云完成整个上传流程了。

这是第一种获取信息的方式。之前看文档时还提到 readRawBody，看用这个函数怎样获取真正的文件信息。这里就不需要 formData 了，直接把文件放置到 body 当中去。保存并修改：把 readMultipartFormData 那一行注释掉，改用 `await readRawBody(event, encoding)`。第一个参数还是 event，后面是编码 encoding，默认是 UTF-8。我们不希望拿到 UTF-8 格式，因为它是二进制文件，可以设置为 false。当它是 false 时会返回 Buffer 对象。

再看看另一个全局函数 readBody 能否获取文件信息。刷新后重新上传，选择文件打开，同样可以成功返回，body 也返回了 Buffer 对象，其中存的就是和文件相关的信息。

这样我们就掌握了获取文件的两种方式：第一个是 readMultipartFormData，第二个是 readBody，两者都可以拿到文件信息。拿到它之后，下节课就可以真正使用阿里云 OSS 来完成上传了。
