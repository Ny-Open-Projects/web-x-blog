组件库结构改造完毕以后，我们想做的事情和最早演示 Rollup 的任务是一样的：将入口文件 index.ts 转换成最终想要的 ES modules 和 UMD 两种格式。这节课的内容属于基础知识，但很多同学只接触过 webpack，没接触过 Rollup，所以还是带大家过一遍。

回到之前那个简单项目。之前已经用命令行工具做过一次打包，命令很长：`npx rollup main.js --file dist/bundle.js --format es`，还有一大堆参数。痛点就是参数太多，未来还可能添加更多参数，这种方式显得太麻烦了。所以可以创建配置文件来涵盖所需的选项。配置文件由 js 写成，比直接使用命令行参数要更加灵活。webpack 大家熟悉，也是一样的，用 webpack.config.js；Rollup 的配置文件则称为 rollup.config.js，它使用 ES6 进行书写，最终导出一个对象，包含一系列配置。

写一下：`export default {}`。首先写输入，也就是 input，值为 main.js。输出自然是 output，它有两个需要填的属性：第一个是 file，输出到哪里，这里写 dist/bundle.js；第二个是 format，跟之前一样写 es。简单写这些就够了。如果想看全部配置，官方文档有个章节叫 Big List of Options，里面有非常多的配置，大家可以自己去看，我这里就不一一过了。

Rollup 运行这个文件的时候，会先把配置转换成 CommonJS 格式，也就是 Node.js 格式，这样更适合 Node.js 的运行环境。这个过程我们不用管，它自动帮我们完成。运行配置使用 `npx rollup --config rollup.config.js`，点击回车，打包完毕。查看生成的文件内容，可以看到生成了一个 ES 格式的代码文件，第一个配置文件就写好了。

当然，为了完成最终任务，简单的配置文件肯定不够。对业务组件库来说，我们有 Vue 格式的文件、TS 格式的文件，直接处理这些文件肯定会报错。为此可以使用 Plugin，也就是插件，在打包过程中改变 Rollup 的行为，这和 Webpack 的思路是一样的。所有插件的地址可以在 Awesome Rollup 里找到，有一系列官方和第三方的插件。

这里添加第一个插件做个简单演示：Rollup-plugin-json，它可以增加对 JSON 文件的处理，让 Rollup 从 JSON 中处理信息。首先安装：`npm install @rollup/plugin-json --save-dev`。注意，官方的 Rollup 插件使用 @rollup 开头，看到这个前缀就知道它是官方插件。

安装完毕后，在代码中就可以从 JSON 中读取信息了。在 main.js 中，从本地的 package.json 里把 version 拿出来，在后面的输出中把它拼接上去。添加完毕后，记得在配置文件中添加一项：首先 `import json from '@rollup/plugin-json'`，然后在配置里添加 plugins 选项。它是一个数组，可以添加多个处理插件，这里只有一个，写入 json。

为了让命令更好打，创建一个 npm 命令，免得每次打很长的命令：在 package.json 里添加一个 build，内容是 `rollup --config rollup.config.js`。现在运行 `npm run build`，可以看到打包成功。

看一下最后生成的文件：JSON 信息被成功导入了，是 1.0.0，也就是 package.json 中的一个信息，而且 tree-shaking 也生效了。package.json 还有其他一系列属性，并没有被导入，只有这一个字段被导入了。这节课简介了 Rollup 的配置文件和插件系统，这其实就是 Rollup 的基本思想。下节课详细介绍完成最终任务需要什么样的插件和配置。到这里，谢谢大家，再见。
