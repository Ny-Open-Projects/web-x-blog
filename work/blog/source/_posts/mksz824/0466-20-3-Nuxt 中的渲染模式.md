上节课多次提到了服务器端渲染，它是 Nuxt 非常重要的特性之一。这节课先不着急写代码，而是探讨这个特性，了解了再动手才能成竹在胸。本节的任务是探索 Nuxt 3 的 Universal Rendering（通用渲染）和传统的 Client Side Rendering（客户端渲染），并比较它们的优势和异同。

这里有一份非常重要的文档：Nuxt 官网关于 Rendering 的文档，详尽介绍了各种渲染模式及其优劣，本课内容就取自这里，想看更详尽的指南可以去阅读原文。

首先介绍传统的渲染形式 client-side rendering，即在浏览器端完成页面渲染。它是怎样运作的？传统 CSR 通常加载一个空壳的 HTML：浏览器先下载一个空的 HTML 文档，然后下载文档里的 JS，此时页面还是空壳状态，什么都显示不出来；JS 下载完成后再通过 JavaScript 动态渲染页面、获取数据、进行 DOM 渲染，这时页面出现了，交互也产生了。传统的 Vue 和 React 应用都是这样完成的。

看一个传统的 SPA 项目（比如我自己的项目）的源代码就会发现：HTML 非常简单，没有任何复杂结构，只有一个空的 app 节点，里面渲染出的内容全靠 JS 完成。这种模式的好处是能提供更好的交互体验，但由于渲染在客户端进行，有两个问题：

一是首屏渲染速度较慢。用户要等浏览器下载并运行对应的 JavaScript，才能显示 DOM 节点并完成交互，这受用户网速、电脑性能等因素影响。

二是 SEO 不友好。真正的 HTML 结构要等一会儿才能渲染完成，同理，搜索引擎的爬虫来爬取网站时也不会等待生成最终结构，它最终拿到的可能就是一个毫无意义的 HTML 空壳：非常有价值的文本内容都在 app 里渲染，爬虫爬不到。这种无内容的页面对搜索引擎没什么意义，权重也不高，SEO 就会受影响。

当然 CSR 也有优点，SPA 已经运行了很长时间，从最早的 Backbone.js 到 Vue.js、React 都是 SPA 项目。第一，开发速度快，不需要任何后端支持就可以开始开发；第二，部署便捷而且价格便宜：产物是一系列静态文件，上线只需要一个静态服务器，不需要搭建任何后端服务；第三，它是离线的：代码都在浏览器运行，断网时一些特定功能还可以使用，不像服务器端渲染那样断网就什么都显示不出来。

接下来是 Nuxt 3 的创新：Universal Rendering，叫通用渲染或同构渲染。它把页面的渲染工作分成两部分：一部分在服务器端，一部分在客户端。具体流程：浏览器请求 URL 时，先到服务器，服务器返回一个完全渲染好的 HTML 页面（the full HTML is sent to the browser and rendered），这时用户已经可以看到内容、滚动页面、点击上面的链接，但要特别注意此时还没有交互。这一步类似于由 PHP、Ruby 或 Java 应用执行的传统服务器端渲染，直接返回 HTML 结构。

下一步，browser downloads and runs the JS in the background：浏览器在后台下载并运行 JS，然后通过 Vue.js 接管文档，此时页面就完整了，不仅有结构，交互也完全实现了。在浏览器中变成完全交互式的这个过程称为 hydration（注水）：原来只是一个空空的骨架、没有任何交互，注水等于给它注入灵魂，让它可以拥有 Vue.js 在客户端的各种功能。文档中的 Client Hydration 部分写到，底层使用的是 createSSRApp 这个 API；创建普通 SPA 项目用的是 createApp，注水要用 createSSRApp。

所以我们会发现，自己使用 Vue 3 的 API 也能完成通用渲染，但会非常繁琐，还有很多细节要注意。而 Nuxt 提供了开箱即用的全面支持，并帮我们规避了常用的陷阱，不需要知道任何技术细节就可以享用通用渲染的红利。

它的优势，对比之前就很明显了。第一，首屏渲染速度更快：一开始就在服务器端渲染出来，可以提高用户的感知加载速度，优化体验。第二，SEO 友好：在服务器端渲染，搜索引擎可以直接获取完整的页面内容，里面的静态 HTML 都能爬取到，提高了网站的可搜索性。第三，减轻客户端的压力：相比传统 CSR，可以减轻客户端的渲染压力，提高客户端设备的性能和响应速度。

选择渲染模式时需要根据实际情况：如果对首屏渲染速度和 SEO 有较高要求，universal rendering 是不二之选；反之，注重交互体验、需要较多客户端计算的应用，传统客户端渲染也是不错的选择。

最后简单说一下 Nuxt 还创造的混合模式 Hybrid Rendering：根据需求按路由划分渲染模式，有的路由用通用渲染，有的用客户端渲染，都可以通过配置文件配置。这里不展开，之后用到时再介绍。

随着 Nuxt 渲染模式的出现，前端开发有了更多选择：通过通用渲染可以在服务器端和客户端同时渲染，提高首屏渲染速度和 SEO 友好度。选择渲染模式时还是要根据实际需求权衡。
