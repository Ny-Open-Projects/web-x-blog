这节课按照上节课的思路完成编码。第一步先简单一些：不创建所有表单，只选取一部分最基础的属性做实验，看能否成功渲染出来。

来到路由 `users/[id].vue`。这本来一般是编辑用户的路由，但我们先做创建，暂时不和 ID 产生任何关系；完成创建后再把编辑加上，现在先借用这个路由完成工作。

## 准备 state 数据

第一步创建数据，叫 `userData`，是一个响应式数据。从 User Data Props 中选取几个有代表性的值：

- **username**：每个用户独一无二的值，非常重要。
- **nickname**：用户昵称。
- **type**：很特殊，只能从三种类型里选（email 电子邮件、cell 手机、oauth），是枚举，需要不同的控件，和普通 string 用的组件不一样。给它初始值 email，先用电子邮件形式创建。
- **disabled**：布尔类型，true 或 false，也需要额外的组件。

## 创建 fields 对应关系

有了中枢神经（显示数据），接下来创建表单控件和数据之间的对应关系，叫 `fields`，是一个数组。数组里的项有几个必备属性：

1. **label**：渲染表单时显示在标签位置的值。第一项的 label 写"用户名"。
2. **name**：出现在 UFormGroup 上的属性，同时还是 v-model 对应的属性，特别注意要和 key 对应：第一项用来渲染 username，就要写 username。
3. **as**：和组件的对应关系。特别注意不能写字符串，要使用组件实例。

组件实例从哪里拿？Nuxt 3 支持自动导入，也可以手动导入全局组件。有一个特殊路径 `#components`，从它当中能拿到所有需要的全局组件。所以第一项写：

```ts
import { UInput, USelect, UToggle } from '#components'

const fields = [
  { label: '用户名', name: 'username', as: UInput },
  { label: '昵称', name: 'nickname', as: UInput }
]
```

第二项 nickname 也是 string，拷贝一下即可。

第三项 type 不一样了：从三个值里选一个，应该用 select。as 换成 USelect，还需要额外属性：select 要显示出来自然有 options，每个 option 有 name 和 value。所以除了 label、name、as 三个必备属性，还要提供 options，三种类型 email、cell phone、oauth，value 和我们数据里的值一一对应，直接写在下面即可。

最后是 disabled：只能是 true 或 false，用之前用过的 toggle 最合适，as 拿 UToggle。

## 创建验证规则

fields 设定完毕，还缺最后一项：验证规则，同样和 key 一一对应。用 z.object 创建后直接传入 schema。命名为 `userCreateSchema`，把 z 导过来，里面有一系列的值：

- **username**：string，设一个最小位数，暂且设为三位（可根据需求调整）。
- **nickname**：可选，创建用户时可加可不加。这里推荐一个新的链式方法名：`optional()`，完全可选。
- **type**：枚举值。Zod 完全支持枚举，用 `z.enum()` 传入数组，把三个值传进去。
- **disabled**：布尔类型，也是可选的，可传可不传。

## 渲染表单

三份数据齐了，开始渲染表单。把 UForm 拿过来，它需要几个属性：第一个是 schema，完成验证规则，传 `userCreateSchema`；除了 schema 还有 state，把 userData 传进去。

之后完成循环：循环 UFormGroup，内部动态渲染不同的组件。UFormGroup 加一个简单 class，属性比较多就分几行写：加 Tailwind 的 `mb-3`，和下面的组件隔开一定距离。

UFormGroup 需要 name 和 label，自然要开始循环：用 v-for 循环 fields，解构出每项都有的 as、name、label，其他剩余的用三个点拿出来（rest），这些就是 options 或更多属性，希望用 v-bind 直接放到内部组件上，把各种各样的属性直接作用到子组件上。

```vue
<UFormGroup v-for="{ as, name, label, ...attrs } in fields" :key="name"
  :name="name" :label="label" class="mb-3">
  <component :is="as" v-model="userData[name]" v-bind="attrs" />
</UFormGroup>
```

内部动态渲染子组件：用 `component` 关键字，它的 `is` 属性指代用哪个动态组件渲染，传 as。同时这里的子组件都支持 v-model，要把 v-model 传过去，绑定的值是 userData 上的动态值，对应 name。

这时会出现一个 type error：name 是 string 类型，而 userData 上是一系列具体类型。想简单处理就做类型断言，告诉编译器 name 是 userData key 的一部分：`userData[name as keyof typeof userData]`。不处理也完全可以，这个错误不会让页面 crash。断言后 name 被断言成上面的任意一项值，错误消失。

最后不要忘记 v-bind 把额外的属性动态添加上去，这里就是 attrs。

## 提交与验证

在 UFormGroup 下面添加一个创建按钮。UForm 还可以传一个 submit 相关的属性：创建 `onSubmit`，简单地把值 console 出来（`console.log(userData.value)`），绑定到 @submit 事件上。再把这个值动态打印出来（用 pre 展示 userData），观察值的变化做测试。

保存看效果：表单成功渲染出来了。上面的是 userData，数据的中枢神经；在上面改任何值，下面完整联动修改；反过来在表单里改，pre 里也完成联动。

测试验证：现在完全通过验证，点击后值可以输出。唯一的必选项是 username，把 username 清空，错误出现了，点击也不会通过，onSubmit 没有被调用，说明验证没通过。
