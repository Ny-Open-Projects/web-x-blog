这节课继续完成表单字段的编码。上节课接触了几个简单的表单属性类型，接下来陆续添加剩下的字段。先注意一下这些字段的特点：createdAt、updatedAt 是创建时自动生成的，不用管；email、phoneNumber、provider、authId 这几个字段和其他选项有关系，这个选项就是 Type：选择 Type 不同的时候，对应的选项也不同。

比如选择 email 创建，就要传入 email 和 password；选择 cell phone 就需要传入 phoneNumber；选择 oauth 就是和 OAuth 相关的两个字段。所以要在表单上良好展示的话，不能把所有字段都展示出来，而要根据选择做不同的显示。剩下的 picture 和图片地址相关，需要单独组件，之后再讨论。

## 添加 belongsTo 字段

回到代码，先把 email 添加上，前面都一样：label 是 email，name 是 email，as 用 UInput。这里要多添加一个字段，表明该类型和某个特殊属性及特殊值有关系，添加一个叫 `belongsTo` 的属性，需要两个值：key 是和哪个属性相关（这里是 type）；value 是和哪个值相关，即只有值等于 email 时这个表单才出现：

```ts
{ label: 'Email', name: 'email', as: UInput,
  belongsTo: { key: 'type', value: 'email' } }
```

剩下的照此办理。password 字段和 email 完全一样，只是加了 `type: 'password'`，让 input 以密码形式显示。phoneNumber 拷贝过来，特别注意它归属的 value 是 cell phone，选择 cell phone 时才出现。还有两个直接复制：oauthProvider 和 oauthId，都是和 OAuth 相关的，oauthProvider 的 options 里有 GitHub 等，oauthId 是 input，两者归属的 value 都是 oauth。

值也要顺便添加：userData 里加上 email、password、phoneNumber、provider、oauthId，全部添加完毕。

## v-show 联动显示

什么时候显示、什么时候隐藏？在 v-for 解构时把 belongsTo 拿出来，在 UFormGroup 上添加 `v-show` 控制出现时机。这里有两个条件：

1. belongsTo 根本不存在，因为它是可选的，没有它所有字段都应该显示。
2. belongsTo 存在时，取 userData 中 belongsTo.key 的当前值，和 belongsTo.value 相等才显示。比如 type 的值等于 email 时，email 字段才出现。

```vue
v-show="!belongsTo || userData[belongsTo.key as keyof typeof userData] === belongsTo.value"
```

这里出现的类型错误和之前完全一样，拷贝过来做类型断言即可。不解决也行，只是红线难看。保存刷新验证：选择 email 时，email 和 password 出现；选择 cell phone，只剩 phoneNumber；选择 oauth，oauthProvider 和 oauthId 都能出现。联动添加成功。

## 切换类型时清空旧值

联动完成后做一点小处理：切换 userType 时希望把之前的值清空。比如已写了 email 的值，切换到另一种类型再切回来，值还保留着；但切换 type 后之前的值是无效的，传给后端时也不希望把这些值传回去。

实现很简单，在 select 上添加一个 change 事件。Vue 中 `@change` 是 onChange 的缩写，所以在 fields 的属性中多加一项 onChange。事件对象不使用，直接设 any 类型，在其中把这些和选项有关的值都置回空字符串：

```ts
onChange: () => {
  userData.value.email = ''
  userData.value.password = ''
  userData.value.phoneNumber = ''
  userData.value.provider = ''
  userData.value.oauthId = ''
}
```

注意 onChange 和 options 都属于 attrs，等于用 v-bind 把这两个属性直接加到了内部的 component 上。测试：添加 email 和 password，切换到 cell phone 再回到 email，值已经消失了，pre 里也能看到 email 和 password 消失。

## 补全验证规则

联动和清空完成后，补全验证。添加 phoneNumber 的规则：特别注意我用了 refine 添加手机号码相关规则，必须是合法手机号，否则报"手机号码格式错误"，并且它是 optional。现在必选的只有 username 和 type，其余都是可选的。email、password、provider、oauthId 直接粘贴复制即可，都是 optional，没有一个是必须的。

顺带修改 user.ts：之前 password 设为必选，其实不是，调整为 cell phone 形式时没有 password，把它改成可选。

## 过滤空字符串

测试验证：直接点 submit，应该只有 username 报必选，但发现 email 和 password 都变红了，没按预期工作。原因是 optional 是可选，但可选不包含空字符串：可选指值可传可不传，而我们实际传入的是空字符串。

解决方案：当传入的字符串为空时，把对应的 key 直接从对象里删除。这样做还一箭双雕：之后发请求给后端时要把 data 发过去，也应该把这些空字符串过滤掉。

用 lodash 快速完成。lodash 有个 `omitBy` 函数：满足回调函数条件的 key 会被过滤掉。文档示例里值是 number 时就过滤，最终 b 只剩下字符串 '2'，一和三都被过滤掉了。我们要过滤空值和 undefined 值，推荐两个函数：`isNil` 可以过滤 null 和 undefined，空字符串用 `isEmpty`，把两者组合。

安装 lodash 的 es 版本：`lodash-es`，还要单独安装类型 `@types/lodash-es`（我已装完）。

创建一个 computed 值做 filter，叫 `filteredObject`，直接 `return omitBy(userData.value, (v) => isNil(v) || isEmpty(v))`。最后把这个 filteredObject 传入 UForm 的 state 做替换。

保存测试：点击创建，只有 username 变红，email 和 password 不再验证；给 email 加值、password 加一位，再点击，进入了验证规则：email 不是合法邮箱、password 不足六位都不满足。再看 cell phone：什么都不输，通过验证；输入错误字段，弹出手机号码格式错误，验证正常工作。

这节课完成了表单联动效果，创建了新的验证规则，并用 lodash 的帮助函数对字段做了过滤。到这里。
