上节课完成了 mongoose 结合 egg.js 的任务。现在重新审视一下这个功能：我们通过添加代码实现了一个 mongoose 功能，它非常模块化。如果想和别人分享这段特定功能怎么办？不可能把代码 copy 过去，那太笨了。这正是之前说的 egg 插件的定义：一个完成特定功能的模块。这样有利于和 egg 核心模块解耦，也有利于业务逻辑复用、生态圈的形成。文档里回答了为什么要用插件，大家可以看一下。

现在就通过 mongoose 这个例子，自己创建一个插件并完成使用，顺便了解插件在官方文档中的定义。一个插件其实就是一个迷你的应用，和应用几乎一样，也包含 service、中间件、配置、框架扩展等等。但特别注意两个重要区别：它没有独立的 router 和 controller，也就是没有任何业务代码；它没有 plugin.js，只能声明跟其他插件的依赖，而不能决定其他插件开启与否。

再看插件的目录结构，和应用几乎完全一样。看 egg-hello 这个示例插件的目录，结构和我们的应用非常相似，只是缺少 controller 和 router 这几个模块。

插件能做什么？第一，扩展内置对象的接口，应用里也写过，在 extend 对应的文件里添加属性就能扩展基本基类。第二，插入自定义中间件：在 middleware 中定义实现，然后在入口文件（自定义生命周期的 app.js）中用 coreMiddleware 数组进行自定义插入。第三，在应用启动时做初始化工作，mongoose 正符合这个场景，我们要做的就是这类初始化。

现在创建自定义插件。先创建文件夹，我已建好叫 egg-hello。egg 提供了初始化插件的命令，和之前 TS 的很像：egg-init，注意 --type 变成了 plugin。在文件夹内运行这个命令，会创建一系列模板文件并弹出信息让你填写插件名称等。生成的 egg-hello 模板代码结构跟应用非常相似，可以往里面添加任何想添加的文件夹。特别注意：由于初始化的文件类型是 JS 的，所以要以 JS 格式写代码；想用 TS 也没问题，用之前 TS 类型的模板就行，但要根据文件结构和内容做一些微调。

代码逻辑和之前写的一样，我就不再写一遍，直接讲解写好的内容。插件要确定的第一部分是配置：在 config/config.default.js 中确定配置参数的类型，导出一个 export，里面只有 url 一个参数。第二步是 app.js，插件的逻辑都在这个文件里：连接数据库和加载 model 文件。特别注意要把写法换成 Node.js 的 CommonJS，意味着 ES modules 的语法不能用了，比如 import、export 我都没有使用。把 JS 版和之前 TS 写的版本对比着写一遍，就能体会到 TS 的美妙之处了，这也是一开始选择 TypeScript 的重要原因。最后是类型文件：为了适配 TS 开发，每个插件都要提供一个单独的 TS 定义文件 index.d.ts，这样类型会不断重载加到 egg 对应的类型上去。这里多添加了一项 EggAppConfig，希望配置上有 mongoose 字段，并且配置里可以有 url 一项，它也会被加到对应类型上去。

插件就这几部分内容：配置、自定义启动的逻辑、类型文件。写完就可以发布了。发布前看 package.json，有几个点特别注意。一是特殊字段 eggPlugin，声明 egg 插件必须有它，声明插件的名称和依赖等；我们没有其他插件依赖，所以只有 name，我这里叫 hello。二是 files，npm 发布时要包括哪些具体文件，需要的文件或文件夹都包含在内，不需要的就不发布，比如 test 文件夹就没有包括。这些字段是插件自动生成的，了解就好。

发布试试：把版本改成新的（1.0.3 我已经发布过了），在文件夹下直接 npm publish，1.0.4 发布成功，就可以使用了。回到我们的应用 OpsFlow 后端，安装这个插件，按具体版本安装 1.0.4。这个模块的名称叫 egg-viking，注意这个名字，因为 egg-hello 已经被发布过了，所以起了个新名字。安装完毕就能在里面使用了。

使用插件第一步大家都记得：在 plugin.ts 中开启它，插件名称 hello，enable 设为 true，package 写刚才说的 egg-viking。还需要 mongoose 的配置：来到 config.default.ts，插件的配置不是业务逻辑，写在这里（它能获得自动补全）。mongoose 的类型就是刚才在插件的 index.d.ts 中设置的，所以能自动补全；url 也是我们定义的，把 URL 拷贝进来，还是 hello 这个数据库。有了 config 和开启插件，插件就算开启完毕了。

测试一下，注入的东西应该都会出现：this.app.mongoose 是 connection 类型，方法和属性都出现了；this.app.model 上打一个 User，model 上的方法也出现了。特别注意测试之前要把原来的逻辑都删除掉：我们之前自己实现的逻辑全部注释掉，说明插件可以工作了。最后验证能否很好运作：npm run dev 启动，输出 connected successfully，连接成功；刷新页面数据正常返回，和之前一样，整个插件逻辑全部写通了。

通过这三节课学习了 egg 插件的原理，自己创建了一个插件并在应用中使用。相信大家对什么是插件、插件的作用有了新的认识。下节课去看 egg-mongoose（官方的亲儿子）和我们的插件在代码上有什么区别，解读一下它的源代码，加深对 egg 插件原理的理解。
