这节课讲后端 middleware。中间件大家已经很熟悉了，它是后端很重要的模块。要特别注意和 Nuxt 前端 middleware 做区分：之前的 middleware 是通过路由守卫做一些特殊处理，而后端中间件是在任何 server 端 API 执行的前后进行操作，和我们之前学的 Nest.js 的 middleware 类似。

Nitro 中间件的设计非常简单：在 server 文件夹下创建一个 middleware 文件夹（注意不要拼错），里面任何文件都会自动执行，时机是在后端真正路由处理之前。它不需要返回任何东西，直接写代码就行，比 Nest.js 或 Koa 简单很多。

来建第一个中间件 logger.ts：

```ts
export default defineEventHandler((event) => {
  console.log('new request', getRequestURL(event))
})
```

和之前一样使用 defineEventHandler，回调里用内置的全局函数 getRequestURL 拿到当前请求的 URL。保存后访问任何 API 路由（比如 /api/test），终端就会输出 new request 和对应的地址；再访问 users/1 也有输出，说明这个中间件已经在所有路由上运行了。

再新建一个最典型的中间件：路由保护，比如某些路由需要特殊权限才能运行。写一个 auth.ts：

```ts
export default defineEventHandler(async (event) => {
  const user = await Promise.resolve({
    isLogin: true,
    userName: 'Viking',
  })
  if (!user.isLogin) {
    throw createError({
      statusCode: 401,
      message: 'unauthorized',
    })
  }
})
```

同样做一个假数据，await 一个 resolve 的 Promise，数据里有 isLogin 和 userName。如果用户没登录，就抛出一个错误。这里要讲一个知识点：如果没有任何错误抛出，返回的 status code 就是 200；任何没有被捕捉的错误被抛出，就会返回 500 internal server error。要返回自定义错误，使用内置函数 createError，参数有 statusCode（这里用 401）和 message（输出 unauthorized，表示没有对应的权限）。

保存后访问，可以看到两个中间件都在运行，输出 user 信息和 new request。中间件按字母排序运行：auth 排在前面第一个运行，logger 的 l 排在后面第二个运行。想改变顺序，可以像之前一样加数字前缀，按需求排列。

现在把 isLogin 改成 false，再运行 /api/test，会弹出一个 401 的错误，这是它定制化的错误界面。如果用异步请求访问（比如从首页发请求），返回的就是一个 JSON；如果是直接页面访问，就会有个定制化页面，这个页面之后也可以自定义。

现在的另一个问题是：所有后端路由都会执行这个中间件，而我们希望这个鉴权判断按路由来分配。Nitro 或 H3 没有提供对应功能，所以可以用最原始的方式甄别：直接判断 path。event 对象可以拿到对应的 path，用 startsWith 判断，只有以 /api/users 开头的路由才继续运行，其他直接 return：

```ts
if (!event.path.startsWith('/api/users')) return
```

这样路由就有区别了：访问 test 时直接返回，两个中间件都运行但没有拦截；访问 users/1 时，鉴权逻辑被执行并返回 401。

还有一种方式是根本不用中间件，直接抽象成一个函数，体现极简的设计思路。在 server 中创建一个新文件 protected-routes.ts，把鉴权逻辑复制进去，导出一个 async 方法，参数是 event，类型从 h3 中拿到（叫 H3Event）：

```ts
import { H3Event } from 'h3'

export default async (event: H3Event) => {
  const user = await Promise.resolve({ isLogin: false, userName: '' })
  if (!user.isLogin) {
    throw createError({ statusCode: 401, message: 'unauthorized' })
  }
}
```

然后把中间件里的逻辑注释掉，不让它干扰结果。现在想在哪个路由做保护，直接使用这个函数就好：比如保护 user/[id] 这个路由，把函数 import 进来，命名为 protectedRoute，在 handler 开头 `await protectedRoute(event)`。

试一下：test 路由现在可以直接运行；来到 user/1 的 URL，同样弹出 401 错误。这样我们就用另一种方式完成了中间件，甚至已经和中间件没关系了，只是抽象成一个简单的函数。这种设计思路清晰简单，一眼就能看懂它在干什么。

通过这节课可以发现 Nitro 中间件的设计思路非常简单，直接避免了复杂性；同时有多种方式都能完成路由保护。下节课继续看其他内容。
