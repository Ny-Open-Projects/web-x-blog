上一周我们完成了 LText 业务组件的样式和编码部分的工作，以及编辑器的一部分功能。现在是否要赶快进行下一步的开发呢？答案是否定的。我们已经发现了开发中的一些痛点，需要引出一个很多同学比较陌生的领域：测试。用测试来解决现在的痛点。大家都知道，写测试在国内的互联网公司是不受欢迎的，没有多少人写测试。这一周我就带着大家去探索这个陌生的领域，希望通过这一周能抓住测试的一些精髓，让大家喜欢上测试。

先说主要内容。这周知识点众多，而且都比较深入，绝不像写一个 to-do list 那样简单完事。基本上围绕两大框架来讲：第一个是通用测试工具 Jest，从基础到进阶的用法；另一个是 Vue 专属的测试工具 Vue Test Utils，也是从基础到进阶。最后我还会给大家灌输一种新的开发方式：TDD（Test Driven Development），用这种方式完成一个表单组件的开发。

我们会收获什么呢？第一是测试的定义、分类，有什么种类的测试，以及它的重要性。接下来是对市面上通用测试框架的分类和它们不同特点的对比。之后是 Jest 和 VTU 基础到进阶的知识，不仅仅是皮毛，会比较深入，文档中的 API 我们几乎大部分都会使用到。最后是 TDD，一种非常有趣的开发方式，相信大家如果和我走一遍这个流程，会感受颇多。

几个关键词。第一个是单元测试：单元测试是测试大类的一个分类，这一周里面写的都是单元测试。它由开发人员撰写，也就是我们撰写的，运行比较快，写得最多，而且是最重要的一类测试。注意这一系列"最"字。

第二个是 mock。单元测试特别讲究独立性，要保证不同的模块不会相互影响。假如在一个模块中使用了另外一个模块，最重要的事情就是 mock 这个模块的实现。mock 就是造假的意思：把依赖的第三方模块用假的代码代替，让它不会影响到我们要测试的内容。最后一个是 TDD，刚才讲过了，不再重复。

最后是学习方法。对写测试来说，最重要的学习方法就是思维转换。很多同学没写过测试，会有"测试应该没什么用"的想法。我希望通过这一周的实践转变大家的认知，让大家喜欢上测试，并且在以后的工作中有意愿去实践。

前言就说到这里，下面让我们一起进入这个对很多人来说比较陌生的领域，看看我们能发现什么吧。谢谢大家。
