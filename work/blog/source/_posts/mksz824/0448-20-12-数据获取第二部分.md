上节课介绍了 `useFetch` 的功能和用法，这节课来看另外两个函数，以及它们和 `useFetch` 的区别。

第一个是之前简单介绍过的 `$fetch`，一个发送网络请求的通用函数，基于 ofetch 库。它是一个全局函数，可以直接使用，可以把它想象成类似 axios 的库。用法很简单：

```ts
const data = await $fetch<UserData>(url)
```

直接把 URL 传进去，想要类型就传泛型，data 就能获取对应类型。它没有 `useFetch` 那么多功能，也没有那些状态，因为它是较底层的库，所以把原来的状态相关代码都删掉，只留下用户数据。

刷新页面，user one、user two 都能正常获取数据，但有几点不一样。第一，返回的 data 不是响应式的，只是普通的 JS 数据结构，非常类似我们之前重度使用的 axios。第二，它没有避免重复发送请求的机制，会造成网络请求发送两次：一次在服务端第一次渲染时，一次在渲染完成后由前端发送。打开控制台的 network 面板清空后刷新，可以看到这个请求在页面首次渲染时就被发送了；而用 `useFetch` 时这个额外的请求是不会发的，只有前端接管后点击路由才会发送。

所以 `$fetch` 可以作为一个通用库，更推荐处理纯前端发起的请求或其他通用网络请求。

下一个是 `useAsyncData`，一个和 `useFetch` 类似的组合式函数，用来包裹任何异步逻辑并返回请求结果。`useFetch` 其实就是它的语法糖。两者可以这样对应：调用 `useFetch(url)` 大致等价于调用 `useAsyncData(url, () => $fetch(url))`，返回的数据完全一样。区别在于 `useAsyncData` 有两个参数，第一个参数是一个字符串 key，是独一无二的标识，用来把请求返回的结果缓存到本地的一个 key-value 数据结构中。

所以 `useAsyncData` 比 `useFetch` 用途更广泛：第二个参数的回调只要返回一个标准的 Promise 就可以胜任，可以用 `$fetch`，也可以直接用熟悉的 axios，甚至是第三方提供的异步函数和 API。它更通用，而 `useFetch` 是一个更小、更精准的语法糖。

实际写一下 `useAsyncData`，写法和 `useFetch` 类似：

```ts
const { data } = await useAsyncData('user', () => $fetch<UserData>(url))
```

第一个参数是 key 字符串，第二个回调返回 Promise。保存后刷新页面，行为和第一次用 `useFetch` 时一样，首次渲染不会在前端重复发异步请求。

打开 DevTools 的 Payload 面板，可以看到 data 就是我们缓存到本地的数据，其中的 user 就是我们起的 key 名称，和代码里对应；之前用过的 useState 的值也能在这里直观看到。

既然数据缓存到了本地，就可以在缓存上做点文章：现在每次进入新的 user ID 都会调用一次发送请求，我们希望用缓存判断一下，没有对应数据就发请求，有就直接从数据结构中取。Nuxt 提供了一个配套的组合式函数 `useNuxtData`，用起来非常方便：只需传入 key，返回的 data 是一个响应式对象。

现在做对应的改进。首先把写死的部分改成和 ID 相关，缓存的是和 ID 对应的数据。把 id 单拿出来做成变量：`const userId = route.params.id`，并替换到各处使用它的地方。接着，缓存数据的 key 也要带上 ID 信息，比如写成 `user/${userId}`。

然后先从缓存取值：

```ts
const { data: cachedUser } = useNuxtData(`user/${userId}`)
```

data 重名了没关系，用冒号起个别名叫 cachedUser。判断 `if (cachedUser.value)` 存在，说明不用发请求，直接赋值；不存在才发送请求。为了赋值需要一个初始值：`const data = ref<UserData | null>(null)`。请求部分起别名 fetchUser，请求完成后把结果赋给 data，类型都是匹配的。

刷新验证。进入 user two 的路由刷新，第一次肯定要发请求，因为缓存中还没有数据，Payload 里只有 user 二。清空后点击 user one，因为缓存中也没有，同样发送了新请求，数据也获取到了（DevTools 的 data 显示可能不会实时更新，切走再切回来就能看到）。此时缓存里已经有 user 一和 user 二两条数据，再次点击任何一个路由都不会发送新的异步请求，数据直接从缓存更新，效果符合预期。

总结这节课：学了另外两个数据获取函数，`$fetch` 是发送网络请求的通用函数，`useAsyncData` 是更强大的组合式函数，而 `useFetch` 是两者组合起来的语法糖。最后学了缓存知识，可以用 `useNuxtData` 取回缓存数据，配合判断优化程序。
