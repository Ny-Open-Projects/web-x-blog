上节课成功使用阿里云完成了上传，但还遗留一个问题：每次上传都需要创建一个阿里云 OSS 的实例。我们希望不用每次都做重复的工作，而是在启动应用的时候只执行一次这个逻辑，然后在后端应用的任何部分都可以自由使用这个实例。

怎样完成这个任务呢？这时就想到后端的插件系统，也就是 Nitro 下面的 Plugins。大家应该还记得这个特性：插件只会在 Server 启动的时候执行一次，官方说法是 executed once during server startup，并且可以获取 NitroApp 这个上下文对象。

思路就清晰了：在 Plugins 里面创建这个实例，它只会执行一次；把返回的实例挂载到 NitroApp 对象上；之后就可以尽情使用这个实例了。这是一种很通用的做法，如果有第三方库需要初始化后或实例化后使用，都可以采用这种插件的做法，是一次可以举一反三的经历。听起来很简单，现在看看怎样完成。

我已经创建了一个插件，称之为 oss。位置在 server 下面的 plugins 文件夹，文件名是 oss.ts。

首先把原来的代码直接复制过来就可以运行。第一步把 import 拿过来，把 OSS 的初始化也复制过来。现在 store 已经有了，下一步自然是把它挂在 NitroApp 这个上下文对象，也就是这里的 app 对象上面。直接挂载，命名为 aliOSS，等于 store，这个工作就完成了。

但可以看到现在出现了一个红色的提示，告诉我们 NitroApp 对象上并没有这个属性。所以需要在它上面完成类型扩展。这个做法大家应该非常熟练了，之前在 nuxt.config 上就多次对内置类型做过扩展，这里使用同样的方法。

看具体操作。types 文件夹下面的文件，在 tsc 运行的时候会自动加载里面的 ts 文件，所以这里是放置自定义扩展类型的绝佳位置。已经有了 user.ts，现在创建一个叫 shapes.d.ts 的文件，命名可以选自己喜欢的，但特别要注意加上 .d.ts 后缀，告诉系统这是一个定义文件，用来修改一系列变量的类型定义。

来到这个文件，首先把 class 引过来，一会儿要使用它。然后完成扩展。这里很有趣：先 declare module，要知道模块的名称。Nitro 的模块名称叫 nitropack，大家特别注意，它就叫这个名称，输入的时候会自动出现对应的位置。这个名称是我查了 Nitro 的一系列文档才获得的，是一个很新鲜也很重要的知识点。在它下面就可以完成扩展了：拿到 interface，interface 的类型是 NitroApp。给它添加属性 aliOSS，类型是什么？OSS 的实例，自然就是 OSS。可以看到添加了这个类型以后，之前的错误就消失了，成功在 NitroApp 上完成了扩展。保存，然后回到插件文件再保存一下，接下来就可以成功使用了。

回到 upload.post.ts。首先需要拿到 app，Nitro 提供了一个全局函数：useNitroApp，通过它就能拿到上下文，类型也是 NitroApp。拿到它以后工作就很简单了，直接在这里做替换：app 下面的 aliOSS，然后 .put，后面完全一样。这时就不需要初始化了，把 store 相关的代码直接删掉就可以。以后想使用这个实例化后的对象，直接在 app.aliOSS 上都可以拿到，任何地方都可以直接使用，非常方便。把不需要的内容都清理掉。

现在测试它是否可以良好工作。特别注意，写完代码以后要重新启动一下应用，因为添加了插件，要重启才能生效。关闭再启动，稍微等待。应用重启后，验证新添加的 plugin 方式是否好用：再上传一张图片，点击打开，可以看到图片上传成功，URL 是正确的值，说明改造成功，这节课的任务就完成了。

这里要掌握两个知识点。第一个是 plugins 的作用：假如有一些需要初始化的第三方库或者类，不妨放到 plugins 当中，它只在程序运行的时候执行一次，之后在各种地方都可以使用，可以挂载到 app 上面去。第二个是对 app 的类型要特别注意，因为它有对应的 TS 定义，没法随便挂载属性，需要添加对应的类型声明来完成这个工作。
