现在我们的生产环境已经准备完毕，是时候将代码部署上去了。但先别着急，部署之前还需要修改一些特定的配置。对于生产环境，心里要有一个固定的 checklist：和开发环境相比，配置上需要做一些调整，主要是安全性上的一些策略和配置的修改。

第一部分，数据库和 Redis 的安全性。我们知道在本地访问这两个服务都是没有密码的。看对应的配置：mongoose 这里直接提供了 url，Redis 这里的 password 也是空的。但大家都知道，生产环境中必须注意安全，要使用对应的密码来访问。这里只是让大家留意一下，加密需要两个方面：一是服务启动的时候要添加配置，也就是需要密码来进行访问；启动以后才能在配置中添加对应的选项。至于怎样在 MongoDB 和 Redis 启动时设置密码，后面讲 Docker 的时候会仔细讲解。所以我们这里启动就不添加密码了，先写一点伪代码，把这个事情作为以后的待办选项记住即可。

来到 config.prod.ts。第一件事就是给 MongoDB 和 Redis 添加密码。config.mongoose 下面的 client，第一项一样要提供 url，这个 url 在之后有可能和开发环境不一样。然后 options 提供了用户名密码访问的能力：dbName 这里应该是 OpsFlow，user 比如说是 xyz，pass 就是密码选项。这里特别注意，user 和 pass 是两个需要保密的信息，所以之后可以想到需要使用环境变量来保存这些内容。这就是给 mongoose 添加密码的方法，我们把它注释掉，以后作为参考。

接下来是 Redis，密码很简单，直接复制过来，对应的 password 添加到这里即可。同样，这里也需要环境变量的支持。这个待办项就添加完毕了。

第二部分，和跨域相关。开发环境中跨域访问无所谓，但在正式环境中一定要注意：应该只允许特定的域名访问。注意我们还没有把对应的 IP 对应成域名，所以这里暂且先写到这里。看一下之前的写法：我们使用的是 cors 配置选项，但这个配置里只有一个 origin，只能写一个对应的网址；假如有多个，还需要写函数的写法。这里我们使用 security 内置插件中的一个选项，它也是完成 CORS 的功能，但可以配置多个 url，很方便。

找到 security 插件，对应的选项名称叫 domainWhiteList，是一个数组，把要允许的域名添加进去即可。比如开发环境是 localhost:8080，添加过来。这样原来的 cors 选项就可以下岗了，我们把它注释掉，因为 cors 和 domainWhiteList 其实做的是同一件事情。保存，在 production 配置中添加一个注释：配置 CORS 允许的域名。然后写 config.security，里面添加 domainWhiteList。我们希望有两个域名都可以跨域访问：一个是 OpsFlow 的主域名，另一个是带 www 的域名，都是 https 的。现在 CORS 的设置就完成了。

下一步，修改 JWT（JSON Web Token）的失效时间。代码中现在对失效时间没有做特殊的规定，这是一个很不好的实践。首先我们希望它是可配置的，其次希望在开发环境和生产环境采用不同的过期时间。看业务代码，sign 方法这里并没有添加任何关于时间的内容，所以它会使用默认时间。对应的配置是在 jwt 选项中完成的，它的时间采用了之前说过的 ms 这个库，可以轻松地把人类可读的可视化时间转换成毫秒数，非常方便，支持各种各样的格式。现在添加一下，直接加到 basicConfig 中，叫 jwtExpires。开发环境希望是一个小时，时间比较短；生产环境给它长一点，config.jwtExpires 设为 '2 days'（两天）。

这三步做完以后，别忘了在代码中进行修改。在 user.ts 中修改，过期时间是 sign 的第三个参数，其中有 expiresIn 这个对应的时间格式，把刚才添加的 appConfig.jwtExpires 填进去就可以了。代码中有很多处采用 sign 方法，请大家课下自己做修改，可以直接搜索 jwt.sign 这个函数，把过期时间一一添加上去。

还有第四部分。开发环境中的配置使用的都是 localhost:7001 这样的本地 url，生产环境中需要进行替换。有两部分：一个是 redirectUrl，另一个是 h5BaseURL。现在完成替换。第四步本地 url 替换：第一个是 jwt 的 config，要替换的是 redirectUrl，把问号去掉（前一部分肯定是存在的，default 中已经赋值了），把前面的 localhost:7001 替换成最终的 API 域名 ops-flow.com。第二部分是 h5BaseURL，这里特别注意：我们返回 h5 页面的地址，最后要使用 nginx 进行 rewrite 重定向到对应的地址（之前已经说过了），所以这里不用写那么长，直接写 h5 的前缀就可以了，这样就完成了对应的替换。

这四步完成以后，针对生产环境的配置修改就完成了。当然现在还有一些半成品，比如最重要的密码，我们只是把它注释掉作为以后的待办项。大家只要有这个概念就好，毕竟传统部署不是我们最终的解决方案，只是让大家了解一下整个的步骤。

这节课的任务就完成了。
