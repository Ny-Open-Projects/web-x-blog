上节课完成了更新属性一半的工作，同时做了一个类型方面的升级改造：把定义对应关系的 PropToForm 和渲染表单组件的类型分割开来，不仅实现的代码更清爽，逻辑关系也非常舒服。上节课完成了一半的更新逻辑，事件已经发射出去了。但遇到的问题是：event 里面的 value 千奇百怪，没法直接作用到 store 中的数据里。假如直接作用过去，这里面有可能是复杂的 object 类型，再次流动回来的时候展示肯定会有问题。

记得在展示属性的时候，有一个方法叫 initalTransform，把存的值转换成组件属性适用的值。很自然能想到：把组件表单发射出来的值照猫画虎再做一次转换，转换成适用于 store 的结构，不就解决问题了吗？这是一个很自然的思考：既然输入有转换，输出也可能有转换。

所以肯定要定义到 PropToForm 当中，而不是 PropsTable 当中。定义一个 afterTransform，和 initalTransform 相对应，类型也很相似，做一个转换。有了这个就来完成对应的转换。首先 text 要转换它的值：它最终的值存在 event.target.value 当中，发射出来的是一个 input event，所以做一个转换。fontSize 呢？它输出的值是一个数字，字号直接输出出来，而我们要把它转换成多少 px，因为存入的值应该是多少 px，所以要做对应的转换：传出的值是 number，把它转成 `${v}px`。接下来 lineHeight 很简单：输入时把 string 转换成了数字类型，输出时把数字转换回 string 就可以了。最后一个 text-align：它输出的值也是 event 类型，值最终也藏在 event.target.value 当中，跟 text 一样，复制一下就可以。最后是 fontFamily：上节课已经看过，它出来的值直接就是弄好的值，不需要转换，所以不添加。

有了这个定义，就改造输出的值。来到 PropsTable，现在值是孤零零直接输出的，有了 afterTransform 就可以判断：拿到 afterTransform，假如存在就转换一下，`item.afterTransform(e)`；不存在就直接返回 e。做完转换后验证值对不对：还是用 console.log 看对应的值，现在能拿到最终可以直接存起来的值。点击 hello，value 是 hello；第二个 fontSize，值是 1px，没问题；lineHeight 是 1.1；text-align 的 value 等于 center、right；随便选一个字体。看起来都没问题了，可以直接做转换。

在 editor.vue 当中改变 store 中的值：store.commit，mutation name 称之为 updateComponent，把 e 传过去，它其实就是一个 key 和 value 的对儿。最终在 editor store 的 mutations 中做修改：刚才说了叫 updateComponent，第一个参数是 state，第二个是 key 和 value 的对，直接解构出来。

要更新一个 component，首先要到 components 当中寻找。其实和 getters 里面的逻辑一样，但 getter 不能在 mutation 中调用，所以把逻辑复制一遍：还是使用 find 方法，寻找和 state.currentElement 相等的元素，找到 updatedComponent。它有可能是 undefined（没选中的时候），所以首先做一个判断：假如 updatedComponent 存在，再做下面的更新操作。更新很简单：拿到 updatedComponent 上面的 props，然后 `props[key] = value`。

这时发现出现了一个错误：因为 key 是 string 类型（实际解构出来比较宽泛），而 props 需要的是 Partial<TextComponentProps> 的 key。做一个类型转换，把它转换成 keyof TextComponentProps 就可以了。这个技巧之前用过：props 上面使用 keyof 来限制一系列确定的 key，把它断言成 key 的一部分，一个联合类型就可以了。

现在完成了整个逻辑，来看看见证奇迹的时刻：界面上最终的值能否被成功更新？选择 hello，改变它的值，输入的时候它就进行了改变。再把字号扩大一下：点击后不仅右边的字号扩大了，画布里的值也改变了，之前是不会改变的。试一下行高，把它调大一点：随着调整，行高会改变，这里也会改变。测试对齐：点击中，它跑到中间；再点击右，它去了右边，没问题。最后试字体：点击宋体，它改成了宋体；再点击黑体，也改成了黑体。

通过三节课，我们完成了表单组件更新的过程。对于整个大体思路，建议大家多看一看那张图，通过它可以带来更深刻的理解，尤其是单向数据流这个概念。这节课大功告成，到这里，谢谢大家。
