这节课完成上节课分析的简单功能：展示图层列表，并实现锁定、隐藏和点击选中。这部分代码我已写好一部分，前面讲解代码，后面手写几块核心内容。相信大家对单个功能的实现都没有问题，重点还是理解整个数据流。

## 用 Tabs 组件切换面板

首先完成 tab 功能，切换显示对应区域，直接使用 Ant Design Vue 提供的 `a-tabs` 组件。它有一个父组件 `a-tabs`，可以设置 `v-model:value` 表示当前切换到哪个 tab。这里绑定的值叫 `activeKey`，我创建了一个演示对象 `activePanel`，初始值是 `component`，也就是先展示最原始的第一项内容。然后创建两个选项区域：第一个 `a-tab-pane` 的 key 是 `component`，第二个是 `layer`，分别展示属性设置和图层设置。对应的内容放到 slot 里即可。

页面上可以看到：属性设置在没有选中元素时没有内容，点击图层设置就能切换到第二个图层面板。

## LayerList 组件

接下来完成 `LayerList` 组件，展示图层列表。图层的每一项和编辑器中的元素一一对应，所以它有一个 `list` 属性，类型是数组，每项的类型就是 `ComponentData`。

组件本身没什么难度，主要是循环展示 list 并展示对应的图标。展示图标需要额外的属性，我在 `editor.ts` 的 store 中已经添加了三个属性：`isHidden` 表示图层是否隐藏，`isLocked` 表示图层是否锁定，以及图层名称 `layerName`。有了这些属性，剩下的就是根据不同的值展示不同的图标：比如 hidden 时显示 `eye-outline`（眼睛），不是 hidden 时显示 `eye-invisible`。这些图标都可以在 Ant Design Vue 官网查找，我都是直接从那里引入的。最后我给列表加了一些样式，图标展示在左边，并给它们加了 tooltip。

## 锁定功能：自上而下的数据流

手写锁定行为的代码。需求没什么难度，只要掌握一个原则：自上而下的数据流。

点击锁定时要触发一个事件，所以到 LayerList 中添加一个新的事件处理函数，按惯例叫 `handleChange`。它接收三个参数：`id`（触发哪个 component 的改变）、`key`（触发哪个键）、`value`（布尔值）。把这三项放进一个 data 对象，通过 `context.emit('change', data)` 发送出去，最后在 return 中暴露 `handleChange`。

然后在模板中给锁定的 `a-button` 添加 click 事件调用 `handleChange`，三个参数分别是 `item.id`、键名 `isLocked`，以及新值，直接对 `item.isLocked` 取反即可。

事件发送出去以后，要在父组件 Editor 上添加监听：`@change="handleChange"`，这里的 `handleChange` 触发后调用 `updateComponent`，这是 editor store 里的一个 mutation。

不过现在还不能满足需求，要改两个地方。第一，`updateComponent` 要支持传入 id：目前它直接用 `state.currentElement` 来定位组件，但如果传了 id，应该以 id 为优先，所以写成 `id || state.currentElement` 这样的逻辑。第二，查看 store 中的实现，发现它直接修改的是 props 中的属性，和我们的预期不符。需要一个字段来区分是在修改 props 还是一级属性，于是我添加一个参数 `isRoot`。在 LayerList 发送事件时把它带上，这里值为 true。mutation 里做一个简单判断：如果有 `isRoot`，就直接修改根属性，即 `component[key] = value`；如果没有，就按原来的方式修改 props，把原来的拷贝逻辑保留。

## 一个 TS 类型的坑

写到这里出现了类型错误：`Type 'any' cannot be used to index type ...`。这和之前处理 `TextComponentProps` 的方式一样，用 `keyof`，不过这里不是 `TextComponentProps`，而是 `ComponentData`。改过来之后按理说完全正确，但它又爆出一个更奇怪的错误：`type 'any' is not assignable to type 'never'`。

这个错误令人费解，因为 `keyof ComponentData` 返回的就是 ComponentData 所有 key 的联合类型，写法看起来没问题。经过多次实验，我发现它和里面的布尔类型有关系，把布尔属性注释掉，错误就消失了。key 本来应该和值的类型没有关系，于是我又查了一个多小时，最后在 GitHub 上找到了一个 issue：`type 'any' is not assignable to type 'never'`，和遇到的问题一模一样。issue 里说，只要对象中有布尔值，这里就会报这种类型错误，很多人遇到了相同的情况。最后的结论居然是这是一个至今还没修复的 TypeScript bug。找到原因让我心安了，至少说明不是我们写法的问题。感兴趣的话可以自己看看那个帖子，来龙去脉写得非常清楚。

这个小插曲的收获是：既然是 TS 的 bug，我就可以心安理得地用 any 绕过去，把 `updatedComponent` 断言成 any，key 放进去，问题解决。

现在测试一下：点击图层设置，点击锁定，图标发生了变化，说明整个值的设置流程成功了。

## 锁定时的编辑界面

接着处理属性界面：元素被锁定时不能编辑，显示不同的界面。在 EditorView 中用 `isLocked` 属性做判断即可。原来的判断是 `v-if="currentElement"`，现在改成 `v-if="currentElement && !currentElement.isLocked"`，然后加一个 `v-else` 分支：元素被锁定时显示一个独特的界面，"该元素被锁定，无法编辑"。这里我用 Ant Design Vue 提供的 `a-empty` 组件，看起来更好看一些。

测试：给图层一加锁，切换到属性设置，点击文本时显示"该元素被锁定，无法编辑"；点击解锁后再回来，属性又出现了，可以继续编辑。

## 点击选中

最后添加点击选中的特性，这也是自上而下数据流的典型例子。

首先在 LayerList 添加一个属性，代表列表中当前选中的元素，叫 `selectedId`。选中的那一项添加一个独特的 class：在 `li` 上用表达式判断，如果 `item.id` 等于外面传进来的 `selectedId`，就添加 `active` 样式（一个蓝色边框）。

点击时要发送一个特殊的事件。添加一个 `handleClick`，参数是 string 类型的 id，内部通过 `context.emit('select', id)` 把 id 发出去。然后把 `handleClick` 绑到 `li` 的 click 上，参数传 `item.id`。

最后在父组件上添加对应的事件处理。先把 `selectedId` 传进去，它的值自然是当前选中元素的 id，也就是 `currentElement && currentElement.id`。然后监听 `select` 事件，其实我们已经有一个对应的处理了，就是 `setActive`，这正是我们想做的事，直接把它绑过来即可。

测试：来到图层设置，点击图层一，编辑器中对应元素被选中；反过来点击画布中的元素，图层列表也会联动。点击图层二再切换回属性设置，它的属性也会出现。整个过程完成。

剩下隐藏元素的功能大家课下自己完成即可，和锁定是一样的套路。通过本节课的编码，我们对单向数据流的理解应该更清晰了。另外有个小收获：当你过于纠结一个问题的时候，早点去网上找解决方案，它最终可能是个 bug。
