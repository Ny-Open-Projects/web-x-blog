## 项目全景

回到大的框架图，从整个项目入手。我们的 B 端项目称之为 OpsFlow 主站，使用 Vue3、TypeScript 以及 Vue 全家桶搭建，主要有几个路由，目前实现了首页和编辑器页面，重点和难点就是编辑器页面。第二个项目是在第二阶段后期才分离出来的业务组件库，是一系列组成编辑器和 H5 页面中基本元素的业务组件，目前有 LText、LImage 和 LShape 三种，是一个可以扩展的业务组件库，由 Vue3 和 TypeScript 编写。它在两个项目中都有使用：B 端的 OpsFlow 主站，以及 H5 展示端（后端项目）。所以我们将组件库分离出来，单独发布成 NPM 包供两者共享，这个包我们称之为 OpsFlow 组件库。通过发布过程我们还学习了 CI/CD 的一些简单知识。

## 数据流：展示

现在深入 B 端编辑器页面，重申一下数据流。数据流我认为是整个项目中最重要的一部分。

第一步是展示：将业务组件根据保存的组件属性渲染在编辑器中，过程很简单，循环已经存在的组件属性数组即可。看代码：这里添加了一个 testComponent 作为数据来源，它是特殊的 ComponentData 数据类型，里面有 id、name（对应组件的名称）和对应的 props 属性。将它放置在 editor state 的 components 当中，渲染时渲染对应的数据即可。渲染位置在 editor.vue：从这里拿到 components computed（即 store.state.editor.components），然后 `v-for="component in components"`，因为 component 是动态变化的名称，所以使用 `<component :is="component.name">` 对应上业务组件的名称，再用 v-bind 把 props 渲染上去。界面中可以看到，四个测试组件都已经渲染在画布区域，并且有不同的效果。

## 数据流：属性展示

第二步是编辑组件的属性，分两步。第一部分是将属性展示成对应的表单组件：创建属性和表单组件的对应关系。看 props-map.tsx 文件，比如第一个属性 text，对应关系是 PropToForm 类型，其中一项是 component，对应哪个表单组件：text 对应的是 a-textarea 组件，还有其他用于展示的属性，比如帮助文字等。然后通过一个比较复杂的组件 PropsTable 完成对应的展示：过程其实就是循环属性并展示对应的表单组件，拿到 finalProps 后 v-for 循环，拿到每个属性，component 动态绑定展示出来。

界面上点击第一个组件，可以看到它渲染出属性界面，每一项都有对应的表单组件：text 对应 a-textarea，并且把值灌进去，文字是 hello 就显示 hello，字号是 20px 就转换成 20。

## 数据流：更新属性

最后一部分是表单组件更新至组件的属性。做法是每次修改都发送一个统一的 change 事件，包含修改的是哪个元素、哪个属性、新的值是多少。具体实现：PropsTable 中 event name 是可变的，默认值是 change，通过 context.emit 发送 change 事件，把 key 和 value 发送出去。整个应用的每个 change 都发送到 Vuex store 中完成：editor.ts 中拿到对应的 mutations，即 updateComponent，根据其中的属性完成值的更新，整个应用遵循自上而下的单向数据流，完成界面的更新。界面上点击颜色等每一项，都会做出对应的更新。

这就是项目完成的大体进度。

## 两个作业

之前给大家留的两个作业，代码中已经全部添加上去了，简单讲一下。第一个是 LImage 组件的 src 属性的处理：新建了对应的表单，点击后有 src 和 width 两个属性。src 用了一个新表单 ImageProcessor 来处理，最终渲染出来的样子：它跟之前说的表单组件原则完全一样，应该很容易写出来。传入的 value 就是 LImage 的 src 属性（图片地址），所以左边渲染出了这张图片。右侧是写好的 StyleUploader 组件，要完成的效果是上传图片完毕后更改这个值：在 StyleUploader 上添加 success 事件，上传完毕后 emit change 事件并把新的 URL 发送出去，就完成了重新上传后图片地址的修改。

第二个任务是将业务组件库使用到编辑器项目中：直接 import 过来，import 样式，再通过 use 把 OpsFlow 组件库安装进去，然后替换所有使用业务组件库的代码。没有特别的难度，但要注意两点（我在组件库项目中简单修改了一下）：第一，生成定义文件时不要生成 test 的定义文件，所以把 test 文件添加到 exclude 里；第二，将 defaultProps（包含 TextComponentProps 等各种组件的类型和默认数据）在入口文件 index.ts 中做中继导出（export * from）。这样编辑器中要大量使用这些属性和 interface 时，就可以直接从 OpsFlow 组件库导入使用，不用再从 defaultProps 中导入。比如 components-list 中要使用 imageDefaultProps 和 TextComponentProps，就可以直接从组件库导出，非常方便。
