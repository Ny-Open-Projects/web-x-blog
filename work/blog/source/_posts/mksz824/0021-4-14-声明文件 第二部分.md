上节课了解了第三方库定义文件的来龙去脉，这节课带大家给一个小模块写定义文件，加深对声明文件的了解。

写之前再次重申一点：假如你的项目本身就是 TS 书写的，是不需要写定义文件的，因为库经过 tsc 编译以后，不仅有 JS 代码，还会自动生成一个 .d.ts 文件，后面学习配置文件时会演示。要单独写定义文件的场景，一般是针对原来 JS 写的模块，现在想在 TS 项目中使用。

## 待定义的模块

现有模块叫 Calculator，是个计算器，完成计算的一些小功能。它的主体是一个函数，有两个参数：第一个参数叫 operator，是操作符，可以是 plus（加）或 minus（减）；第二个参数是要被计算的值，是一个数字数组。比如传 1 和 2，进行 plus 操作返回 3；minus 操作返回 2。

除了主体函数之外，函数上面还挂了两个方法，代表两个简写方法：plus 和 minus。用这两个方法可以节省时间、更直观，等于函数的两个快捷方式，参数也可以少写一些。这是很多 JS 库常见的做法。

## 编写定义文件

创建 calculator.d.ts 定义文件。先写主体，它是一个函数类型。先用类型别名：

```ts
type Operator = 'plus' | 'minus'

type Calculator = (
  operator: Operator,
  numbers: number[]
) => number

declare const calculator: Calculator
```

第一个参数看起来是 string，但其实是一系列有限制的 string，因为是操作符，这里应该使用字符串字面量：type Operator 是 'plus' 或 'minus'（可能还有更多，这里示范只写两个）。第一个参数是 Operator 类型，第二个参数是 number 数组，最终返回 number。用这个定义描述了函数完成的结果。

再使用 declare const 声明模块变量 calculator，类型是 Calculator。到这里主体写完了。测试一下：输入 calculator 后会弹出定义的字符串字面量 minus 或 plus，第二个参数是一系列 number，返回 number，没问题。

## 用 interface 描述带属性的函数

下面要往函数上添加两个属性，这时有些犯难：JavaScript 有非常灵活的机制，函数上还能添加属性，怎样描述一个函数并且函数上有两个属性呢？这时想到了 interface，传说中的鸭子类型，可以非常灵活地描述世间万物。

所以要把类型别名改成 interface：

```ts
interface Calculator {
  (operator: Operator, numbers: number[]): number
  plus(numbers: number[]): number
  minus(numbers: number[]): number
}
```

用 interface 描述函数时，特别注意这里不是箭头，而是冒号。描述完函数本体后，就可以往上挂属性了：第一个 plus，参数是 number 数组，返回 number，这里用箭头函数写法（特别注意不是冒号）；第二个 minus，和 plus 完全相同。

测试一下：函数主体的写法正常，上面的属性也出现了，plus 和 minus 都有，参数都是数组，没问题。

请多次审视这个 interface，通过它可以深入了解 interface 强大的功能：它可以描述各种各样不同的类型。

## 变成第三方模块

现在 calculator 还是个全局变量，可以直接调用，跟 jQuery 一样。我们想把它变成一个第三方模块，像 axios 那样使用。声明文件中完全可以兼容 ES6 的 export 写法，把整个变量导出：

```ts
export default calculator
```

它就变成了一个第三方模块。可以看到业务代码中出现红线，因为全局的 calculator 不存在了，需要导入：

```ts
import calculator from './calculator'
```

导入后 calculator 就有了对应的类型和方法。

## 挪进 node_modules

上节课说过，TS 默认加载 node_modules 下的所有定义文件，第三方模块的定义文件都在 @types 文件夹下。为了让我们这个小工具看起来真正像个模块，把定义文件挪到 node_modules 里：打开 node_modules，再打开 @types 文件夹，新建一个 folder，名称是 calculator（第三方模块的名称）。文件夹建立后在里面建立一个文件 index.d.ts，把定义文件挪进去。

这时可以直接导入第三方模块而不是使用相对路径：@types 文件夹下的模块会自动提示出来，导入 calculator 后类型也没问题。

## 小结

这节课使用定义文件给一个 JS 原生模块成功添加了定义。课下希望大家尝试看一下 axios 的定义文件，它比较长，可能有很多看不懂的地方，没关系，了解它的大体结构和基本书写方式就好。把它滑到最下面可以看到：不管中间多复杂，最后两句话跟我们写的非常相似，也是 declare 了一个变量 axios，类型上是一系列属性和方法，本身也是一个 function，跟我们的写法大同小异，最后把这个模块导出，也是这么一个过程。
