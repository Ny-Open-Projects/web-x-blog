到上节课为止，我们已经介绍了三大块的内容：Router、Controller 和 Service，相信大家对它们都有了比较直观的感受。这节课来介绍 Egg.js 自己独创的一个概念：Plugin。插件这个词，大家在其他框架或系统中应该也经常听说，而它是 Egg.js 的一大特色。之前说过，Egg 有着丰富的扩展机制和可定制性，正是 plugin 让它可以实现这样的特性。插件可以保证框架的核心足够精简、稳定、高效，同时还能促进业务逻辑的复用，促进一个生态圈的生成：因为这样会有很多程序员帮你开发第三方的插件，供各种功能使用。

我这里有一个 egg 社区的插件列表，打开对应的网址可以看到各种各样的插件，有些名称听起来都非常熟悉：egg-mongoose、egg-graphql、egg-mysql、egg-redis 等等。这节课先学习最浅显的插件使用方法，至于插件的原理、怎样自己写一个插件，会随着对插件更深入的了解一点点演示给大家。

可以暂时将插件理解为某个特定功能的合集。看这些名称也会发现，社区列表中的东西就是一些常用的功能：想实现 mongoose 就用 egg-mongoose，想在应用中添加 redis 就用 egg-redis，从名称就可以看出来。Egg.js 还内置了一部分插件，可以直接使用。文档中列出了内置的企业级应用常用插件，比如我们之前修改过的 security 就是个内置插件，我们还改过它的配置，这个插件管着整个 Egg.js 应用的安全；想使用 session 就用 session 插件。对它们的认识会随着开发的进行逐渐加深。

现在用一个对应的需求来演示第三方插件的使用。目前我们的应用仅仅输出的是一个图片地址，我们希望把这个地址转化为一张图片，直接展示在一个 HTML 页面中。这就要求不是输出 JSON 数据，而是直接输出 HTML 代码。对于简单的 HTML 可以直接拼接字符串，但当数据过多时就需要模板引擎的帮助。前端的大家应该对模板引擎非常熟悉，前端也会使用模板引擎进行数据到 HTML 结构的拼接和生成，所以这里需要选择一个模板引擎。

这里自然就想到了插件。Egg.js 内置的插件里有一个 View，是模板引擎的插件，叫 egg-view，它是内置的，不用你去安装。它作为基本的模板解决方案，每个模板引擎都可以以插件的方式引入。因为对模板引擎大家都有特殊的爱好：有人喜欢 Mustache，一个老牌的模板引擎；有人喜欢 EJS，很多人听说过，它使用尖括号加百分号做模板标签；有人喜欢 Nunjucks，它使用两个大括号声明变量，跟 Vue 很像。你可以根据自己的爱好选择。egg-view 可以让不同的模板引擎保持渲染的 API 一致，所以它是一个类似双层架构：最基本的下面是 egg-view，上面是不同的模板引擎，供你自行选择。

我这里使用 Nunjucks 作为模板引擎，需要安装对应的插件：`npm install egg-view-nunjucks --save`。安装完毕后需要启用。对于任何插件的启用要特别注意，需要来到 plugin 文件，也就是 plugin.ts。可以看到里面有一个 plugins 变量，它是默认生成的并被直接导出，类型确定为 EggPlugin。在这里面你可以设置任何插件是否开启。内置的插件有自动提示，但第三方的插件没有自动提示，所以大家要特别注意把单词拼对。这里写 nunjucks。有两个选项：第一个是 enable，是否启用，布尔类型，这里是 true；第二个是 package，对应你使用的包是哪个，写 `egg-view-nunjucks`。这样插件就打开了。

打开以后，有的插件需要进行设置才能使用，比如我们要用的 egg-view。记住，任何插件的设置都在 config.default 这个文件当中。打开后，之前我们已经修改过 security 插件的配置，把 CSRF 关掉了。现在来修改 View 的设置，也就是 config.view：因为 View 是 Nunjucks 的根本，里面有个参数叫 defaultViewEngine，设置默认的模板引擎是什么，把我们安装的 nunjucks 放进去。这样配置就完成了：先启用插件，再在 config.default 中进行配置。有的插件默认不用配置，但我们这里特别注意是要配置的。

两步做完以后就可以使用它的功能了。在 app 当中 new folder 创建一个 view 文件夹。注意这个文件夹也可以在配置里设置它需要的 root，看 config.view 的 root 参数，默认就是在 view 文件夹下。里面创建一个 test.html，nunjucks 的后缀名是 html。创建完毕后，把默认的 HTML 代码复制一份进来，加了个 h1。我们希望在 h1 下面进行一个 image 的显示，也就是添加一个 img 标签，设置一个 src。src 我们希望用变量代替，变量是一个 URL，称之为 url，保存。

最后一步是在 controller 里对它进行渲染。这里是 Controller 的 getDog 方法，进行修改：不需要 ctx.body 返回了，而是直接使用 ctx 上的一个方法，叫 render。这个 render 是被插件植入的，也就是说插件可以在 ctx 或者 app 上面植入一些方法。render 的第一个参数是模板的名称 test.html，后面是变量：刚才加了一个变量 url，给它对应的值，就是 response.message。特别注意它是一个 Promise，所以要添加 await。

大功告成，看一下最终结果：刷新页面，出现了 Welcome to Dog Show，并且这张狗狗图片也完全显示在了页面中。

通过这节课，我们了解到了插件最浅显的基本用法。暂时将插件理解为提供某种功能的合集，三步走回顾一下：第一步，将第三方插件单独安装，然后在 plugin.ts 中启用，写 nunjucks 的 enable 和 package 两个参数；第二步，启用完毕后，有特殊配置的插件在 config.default.ts 中进行配置；配置完毕后，它会在 ctx 上面或者 app 对象上面进行一些方法的扩充，比如扩充出了 render 这样的方法，然后进行使用，最终完成对应的功能。课后大家可以去自己安装一下 EJS 这个插件来使用一下，装到 egg-view 上，跟 Nunjucks 做个对比，对插件的概念就会了解得更加深刻。
