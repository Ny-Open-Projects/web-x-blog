这节课来到开发阶段的最后一个概念，也是本项目的一个难点：权限验证，也就是权限控制。这是本课程的亮点之一，学完以后可以在面试中作为一个亮点来描述。我们的每个接口都规定了一种操作特殊资源的权限，所以针对这些资源，需要有一定的访问控制。

到目前为止，我们只实现了最简单的模型：某种或某些特定资源是登录用户才能访问的，其他用户不能访问。这远远不够，我们需要的操作和场景可能有这些。

第一，只有特定角色的用户才能操作特定的资源。比如管理员 administrator 可以删除创建的用户，而其他角色比如普通用户就不能删除用户。

第二，不同的用户能操作同类资源的特定实体。听起来有点拗口，但其实之前已经实现了：A 用户创建的作品只能被他本人更新或删除，B 用户没法修改或删除。这个我们之前使用 CheckPermission 这样的装饰器完成过类似功能，现在需要把这个概念整体抽象一下，统一完成。

第三，不同的用户操作特定资源的不同属性，这就更细了。比如管理员可以更新作品的所有字段，包括 isTemplate 这个属性，也就是将作品设置为模板；普通用户只能更新 title、content 等和作品信息相关的字段。

所有访问控制模型实际上都在解决同一个问题：谁（user）拥有什么样的权限（authority）去操作（operation）哪些资源（resource）。可以通过多种方式解决这个问题。注意在上述概念中我们多次提到"角色"这个词，角色大家都熟悉，比如管理员、论坛的版主、VIP 用户、普通用户等等。

其中一种解决方案就是基于角色的解决方案，根据角色完成权限控制。这种方式有一个专有名词，请大家记住：RBAC，也就是 Role-Based Access Control 的缩写。RBAC 可以用非常简单的方式描述这个模型：为了避免对每一个用户设定权限，我们可以将权限从用户身上剥离，改为绑定到角色（Role）上面。

对应关系就变成了图里描述的样子：有一系列用户 user A、B、C、D，隶属不同的角色。这里有三种角色：最大权限的 administrator（管理员）、经理 manager、普通用户 general。第三列是 permission，也就是一系列权限：一种是 system settings，即更改系统设置；还有针对 user 的操作，包括 select、create、update、delete 这些 CRUD，以及 password reset。

administrator 可以操作所有权限；manager 的权限就少一些，可以实现用户的查（select）、创建和更新，但不能删除和 password reset，在 system setting 当中只能进行 select；general 普通用户可以对用户进行一系列操作，可以 select、update 和 delete 自己的信息，还可以进行 password reset。这就是一个 RBAC 描述的图。了解了这个定义，就可以用它来实现上述的场景和功能。

这就需要第三方库了。我特意调研了市面上流行的 Node.js 实现 RBAC 的库，大家看一下调研结果。搜索 Node.js RBAC，第一个映入眼帘的是 Access Control.js。它有 1.7k 个 star，还不错，但有个问题：上一次 release 是 2018 年 2 月 24 号，距今已经三年多，而且 issues 里有很多都没有解决，说明作者处于不维护状态。使用这种库其实很危险，另一个原因是它不支持 TypeScript，所以选择 pass。

第二个叫 Casbin，地址是 node-casbin，有 1.7k 个 star，几乎百分之百用 TypeScript 书写，支持 TS。它还是个跨语言的工具，除了 Node.js，还可以用 Java、C++ 等实现对应的功能。我对它简单试用了一下，有一点诟病：API 使用起来概念稍微比较多、偏复杂。可以看到要先 new 一个 Enforcer 创建对象，再用 enforcer.enforce 进行权限管理。我觉得概念比较复杂、用起来繁琐，但它也是一个很好的选项，感兴趣可以去尝试。

第三个就是我们最终要用的工具，叫 CASL。它的读音是 castle，和城堡那个词一样。它的 star 数是最多的，我调研时有 3.4k，现在已经 3.6 了。它完全支持 TypeScript，API 看起来简单易懂。它有一些概念：User、Action、Subject、Conditions、Fields，很快就能创建权限。可以看到它可以用 AbilityBuilder 创建对应的权限，比如 can('read', 'BlogPost')，非常清晰，意思是用户可以读取对应的 BlogPost，还有 manage、delete 之类的写法。我认为这个 API 简单易用、可读性良好，看一段代码就能很快了解它在做什么。
