上一章完成了表格相关的功能，那是管理系统最常见的数据展示和管理方式。这一章来到新话题：创建或编辑条目，这是管理系统中另外一种非常常见的场景。创建或编辑数据自然会遇到大量表单，所以怎样渲染和管理这些表单是这章的重点，也可以说是一个举一反三的典型用例。

开始写代码前，先分析两个核心问题。

## 问题一：创建与编辑共用页面

需求有两个：一是创建用户，二是编辑已存在的用户。它们的界面非常相似，区别在于有没有预先填充好的数据，以及数据最终发送的接口不同：一个是创建，一个是更新。

所以可以想到：两者可以共同使用一个相同的页面，通过某些特定参数做区分；如果是编辑用户，就预先发送一个请求获取这个用户的一系列数据。第一个分析点得出的结论是：创建用户和编辑用户非常相似，可以共用同一个路由。

## 问题二：数据怎样渲染

另一个难点是数据渲染。我们需要编辑用户模型下的大多数数据：User Data Props 里有一大堆各种各样的属性，每一条属性都应该对应一个表单控件，需要渲染这些编辑数据的表单。假如平铺直叙地写下来，可以预见会非常麻烦。

用 UForm（Nuxt UI 的表单组件）举例：如果有十个属性，就要重复写十个表单；而且不同属性对应不同类型的表单控件：string 类型对应 input；枚举类型（比如 type 只能在三种类型中选）自然想到 select 下拉框；布尔类型可能用 toggle。直接拷贝粘贴也需要逐个做出修改。

## 解决方案：数据驱动渲染

怎样解决这个重复的噩梦？不希望把表单一个个拷贝。在海报编辑的前端里我们已经处理过大量表单，自然想到：使用特定的数据结构替代平铺直叙的写法，用数据结构里的属性循环渲染对应的表单，这样扩展也非常容易。

要渲染 UForm 结构，需要三份数据：

1. **展示结构**：存放和表单对应的一系列信息，比如 label（展示的标签）、name（对应哪个属性，一一对应）、as（对应哪种表单控件，用它建立联系），其他更多属性写在后面。
2. **数据**：一个响应式对象，存放和表单相关的一系列数据。
3. **验证**：和 key 一一对应，后面存放用 zod 创建的一系列验证条件。

有了这三者，就可以构建表单：schema 对应验证数据，state 是第二个响应式对象的数据，里面通过循环就可以展示出千变万化的 UFormGroup，完成整个表单。

用伪代码看一下：

```vue
<UForm :schema="schema" :state="state" @submit="onSubmit">
  <UFormGroup v-for="field in fields" :name="field.name" :label="field.label">
    <component :is="field.as" v-model="state[field.name]" v-bind="field" />
  </UFormGroup>
</UForm>
```

在 fields 数组中渲染 UFormGroup，拿出 as、name、label 一一传过去；内部用 `component` 关键字动态渲染，通过 `is` 属性把 as（需要使用哪个控件）传进去。通过这种方式就能完成整个表单的动态渲染。
