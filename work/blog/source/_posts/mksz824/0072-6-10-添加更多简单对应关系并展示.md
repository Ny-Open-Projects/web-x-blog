上节课我们完成了业务组件属性到 form 表单的最简单映射关系，并把它展示到了编辑器右侧。但它现在还是孤零零的，因为只确定了 text 和 input 的对应关系。这节课补充其他属性和组件的对应关系，看看完成这个任务会不会有一些玄机。

看看技术文档是怎么写的。业务组件需求中属性都写得很全，并且写了这些属性要使用什么组件来对应渲染。组件分为几类：有的是 Ant Design Vue 已经有的，有的在 Ant Design Vue 中没有特别对应，需要我们自研。我用一个简单的图来对应一下。

第一类是已经接触过的文本，目前有提供好的组件：a-input 和 a-text-area，分别渲染一行和多行文本。第二类很自然是数字，使用 a-input-number 来渲染，它渲染出一个输入框，带两个箭头，点击可以增加和减少数字，并且只能输入数字。这里用一个属性来试验：字号 fontSize。还有一种是数字在特定范围内选择，使用 a-slider 来控制，它是一个滑块，可以滑动到任意位置。对应的属性可以使用行高 lineHeight 来规定。

这节课先关注这三种比较简单的组件，分别用三个典型的对应属性来描述。原始数据中除了 text，fontSize 和 lineHeight 也已经添加了。现在到 propsMap 中添加它们的对应关系。很简单，除了 text，添加 fontSize，它的 component 是 a-input-number（这个名称大家可以自己去看 Ant Design Vue 的文档，都写得很清楚）；另一个是 lineHeight，component 称之为 a-slider。添加完毕后在界面上看看效果，它已经出现了。

但有一个问题：a-slider 的范围太大了，默认是 1 到 100，而对 lineHeight 我们希望给它一个比较小的固定范围，比如 0 到 3，并且希望最小单位是 0.1，而不是每次 1。a-slider 其实支持这样的属性：它有 max、min，还有 step，正好完成刚才说的三个功能。但我们现在没办法把它加上去，因为 v-bind="value" 是一个特别通用的规则。所以需要有一个属性，可以给表单组件添加不同的对应属性。

于是在 PropToForm 里加一个属性，代表要给表单组件添加的一系列属性，称之为 extraProps，可选。它应该是个 object，还是使用 key 为 string 的 indexable type，返回值只能是 any，因为可能要添加很多种。添加完毕后就可以给 lineHeight 添加 extraProps：min 从 0 开始，max 最多 3，step 是 0.1，因为行高可能要微调，不能每次以 1 进位。

再给组件加上：在模板的 value 上再添加一个 v-bind，绑定 value.extraProps，就完成了修改。看效果，明显起作用了：最大是 3，值是 1。现在还不能滑动，因为还没添加表单更新，但看这个样子已经生效了。

之后把 text 的渲染也改一下：希望用 a-text-area 渲染一个多行组件，rows 等于 3。改起来很容易：component 改成 a-text-area，再给它添加 extraProps，rows 是 3。保存后可以看到变成了三行，组件的属性起作用了。

最后再做一点优化：希望给每一个属性添加一个对应的 text，告诉大家这个属性是什么，也就是属性的说明，显示在左侧，右侧是对应的表单。很简单：在 PropToForm 里再加一个属性 text，是 string，然后给每一项都加上。三个都添加完毕后，把结构修一下，改成左右结构，把我写好的样式复制过来。这时特别注意：出现了一个类型错误，其实和上节课遇到的是同一个问题。PropsToForms 里的 value 是可选的，它是 PropToForm 或者 undefined。可以在外层加一个 div 判断 value 是否存在（加 v-if），其实就能解决。

但我们自己知道：finalProps 里循环的内容，key 存在的时候 value 肯定存在，所以我不想多加一层结构，这里用一个小的技巧：使用内置的 Required，把可选变成必选，它也接受泛型。使用 Required 后错误就消除了。注意我们这样做只是为了消除类型错误，并不是说 finalProps 里真的存在所有的 key，请记清楚这点。

解决了错误以后，把样式拷贝进来，让它显示左右两栏的格式。保存后看界面：左右两栏出现了，text 说明也都显示在这里了。文本和对应的说明都出现了，这节课的任务完成。下节课来接触几个更复杂类型的组件。这节课到这里，谢谢大家。
