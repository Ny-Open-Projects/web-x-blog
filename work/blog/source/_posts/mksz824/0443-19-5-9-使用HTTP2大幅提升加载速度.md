上节课我们用 Keep-Alive 保持连接，加快了资源加载速度。这节课来看 HTTP 的新版本 HTTP/2 在性能上的一系列优化。

先说 HTTP/2 的来历。和其他众多 Web 技术标准一样，推动 HTTP/2 的依旧是谷歌。谷歌在 2010 年推出了自己的 HTTP 协议 SPDY（Speedy 的缩写），到 2015 年，在 SPDY 的基础上进行了一系列优化，正式推出了 HTTP/2。

兼容性方面，既然是 2015 年才推出的，肯定有问题。第一是浏览器支持，在 Can I use 输入 HTTP/2 可以看到兼容性很不错：IE 不支持，Edge 全支持，Firefox 和 Chrome 只是 2015 年之前的版本不支持，之后都做到了全量支持。第二，它需要 HTTPS 协议的支持，要启用 HTTP/2 必须先上 HTTPS。

再了解它的主要特性，看看它为什么这么快。

第一点是二进制协议。HTTP/2 采用二进制格式传输数据，HTTP/1.1 则是我们熟悉的文本协议，它的请求和响应报文由起始行、首部和实体等内容组成，各部分之间用换行分割。HTTP/2 把请求分为更小的帧，并使用二进制编码，加快了传输速度。

第二点是多路复用，这是 HTTP/2 最重要的特性。它可以解决浏览器限制同一域名下并发请求数量的问题。在测试站点刷新页面可以清楚看到：请求开始时间正常，但超过一定数量后，后面的资源会出现灰色的 stalled 阶段，一直处于等待状态。原因就是静态资源的并行请求数达到了浏览器限制的上限（约 7 到 8 个），必须等之前的加载完才能开始。使用 HTTP/2 后，同个域名只需要占用一个 TCP 连接，一个连接并行发送多个请求和响应，消除了多个 TCP 连接带来的延时和内存消耗。HTTP/1.1 下三个资源可能要建三个 TCP connection，HTTP/2 只需要一个，所有资源都可以并行收发。

第三点是 header 压缩。HTTP/1.1 用文本形式传输 header，header 里的信息可能很多，甚至包含很大的 cookie，每次都可能重复传输几百到几千字节。HTTP/2 对首部采取了压缩策略：客户端和服务器使用首部表来跟踪和储存之前发送的键值对，相同的数据不再随每次请求和响应重复发送。请求一发送了 method、schema 等一整套信息，转换成 headers 帧；到第二次请求时可以复用之前的信息，其中大部分字段已经有了，只有一个新的 path 是新信息，那只要添加这个新字段就好，重复的部分全部舍弃，效率大大提升。

讲完概念，来实际操作一下，看它能节省多少时间。基线数据是 HTTP/1.1 下的 DOM Content Loaded 时间：4.26 秒。

在 Nginx 上开启 HTTP/2 非常简单，就是一个指令的事，但要求 1.9.5 以上的版本。登录线上服务器，`nginx -V` 看到版本是 1.17.3，可以使用；模块列表里也有对应的 `http_v2_module`，支持 HTTP/2。

再看线上配置 `/etc/nginx/sites-enabled` 下的域名文件。配置里有两个 block：第一个是 listen 80，走 HTTP/1.1；由于 HTTP/2 需要 HTTPS，我们添加了新的 block，listen 443，同时在上面写上 `listen 443 ssl http2`，把指令加进去就能启用。

访问 https 网址就能命中这个 block。刷新页面，加载完毕后可以看到 Protocol 列是 h2，说明 HTTP/2 已经启用。再看 waterfall：几乎没有很长的 stalled 等待阶段，所有资源平行发出，非常快。最终 DOM Content Loaded 时间是 2.33 秒，从 4.26 秒到 2.33 秒，提升了接近两秒，非常可观。

短短一个模块加一行指令的改动，就让页面加载快了近两秒，改观非常明显。建议以后大家的服务器都升级到 HTTP/2，传输效率会大幅提升。
