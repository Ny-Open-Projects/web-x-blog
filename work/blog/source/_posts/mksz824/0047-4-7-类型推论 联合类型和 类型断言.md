这节课标题有点长，要介绍几个相互关联的概念：类型推论、联合类型、类型断言和类型守护。它们听起来拗口，理解起来并不难，而且层层递进，放到一节课正合适。先从上节课的悬念开始。

## 类型推论（Type Inference）

上节课的函数表达式里，我们没有声明 add 的类型，它却自动获得了函数类型。原因就是 TypeScript 的类型推论原则：在没有明确指定类型时，编译器会推测出变量的类型。

再举一个简单的例子，声明变量时不写任何类型：

```typescript
let str = 'str';
str = 123; // Type '123' is not assignable to type 'string'
```

str 被推断为 string 类型，再赋数字就会报错。这是 TypeScript 为我们提供的一项帮助。

## 联合类型（Union Types）

回到 any 的问题。any 是大而全的类型，万不得已才该用。但有时候变量的取值范围没那么宽，只是允许几种类型，比如既可以是字符串也可以是数字，其他类型不行。这种情况下用联合类型，写法是在多个类型之间加竖线：

```typescript
let numOrStr: number | string;
numOrStr = 'abc';
numOrStr = 123;
```

赋字符串和数字都不会报错。但当 TypeScript 不确定联合类型的变量具体是哪个类型时，我们只能访问所有类型共有的属性和方法。比如直接访问 length（string 上的属性）会报错；访问 toString、valueOf 这类共有成员则没问题。

## 类型断言（Type Assertion）

有时确实需要在不确定类型时访问其中一个类型的成员。比如写一个 getLength 函数，参数是 `string | number`，返回长度：

```typescript
function getLength(input: string | number): number {
  const str = input as string;
  if (str.length) {
    return str.length;
  } else {
    const num = input as number;
    return num.toString().length;
  }
}
```

这里用 as 关键字做类型断言，意思是告诉编译器：你没法判断我的代码，但我本人很清楚，把它看成一个 string，之后就可以使用 string 的属性和方法了。

注意两点：类型断言不是类型转换，断言成联合类型中不存在的类型会报错。另外它以后会经常用到。

## 类型守护（Type Guard）

解决这个问题还有另一种方式。Type Guard 能在遇到联合类型时，通过条件语句自动缩小类型范围。最常见的两个关键字是 typeof 和 instanceof，后者作用于类的实例，这里先讲 typeof。改写同样的函数：

```typescript
function getLength2(input: string | number): number {
  if (typeof input === 'string') {
    return input.length;
  } else {
    return input.toString().length;
  }
}
```

在 if 分支里 input 被缩小成 string，可以直接访问 length；在 else 分支里它自然变成了 number。不同分支中智能缩小范围，代码出错的几率大大降低。

## 小结

从类型推论到联合类型，再到类型断言和类型守护，这些概念一脉相承，大家好好消化。
