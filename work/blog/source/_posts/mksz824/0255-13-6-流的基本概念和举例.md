上节课我们用 sharp 完成了文件的缩放以及展示。大家都记得，multipart 插件除了基本的 file 模式，还有一个模式叫 stream。在学习这种模式之前，需要发散一下思维，讲讲 Node.js 中的重要模块 stream。为什么在这里要讲另外一个概念呢？因为之后我们使用 stream 进行文件上传，以及 file 模式上传的一系列原理，其实都大量使用到了流的概念。

有人说过，stream 是 Node.js 中最好也是最容易误解的概念。所以虽然它属于基础知识，我还是必须单独拿出来详细讲解。这其实就是我们这门课的一个目的：在一个真实的项目中，通过出现的需求，带着大家学习基础以及拔高的知识。我认为流是非常有意思也很有魔力的一个模块，想学好 Node.js 就必须把它吃透。

首先要知道流是什么。流是数据的合集，数据可以是字符串，也可以是二进制。它和直接读取字符串有什么区别呢？区别在于：流的数据不是一次性全部获得的，它是通过管道慢慢获得的。

举一个形象的例子帮助大家理解。假如有一座糖果山，也就是我们要读取的文件，我作为一个小孩，需要把糖果山中的糖果搬运到另外一个地方，也就是输出到一个文件中。有两种方式可以完成这个任务。

第一种方式：开一辆大卡车到山上，把糖果山上的糖果全部搬到卡车上，再开走。你可以把卡车想象成内存。这种方法需要消耗大量内存，因为文件的内容都要临时存放到内存里，而且运输能力的极限就在内存上。

第二种方式很有意思：在山上铺设一条神奇的糖果管道，打开开关以后，糖果就会自动从山上的输入文件流动到输出文件中去。这种方式不需要把所有数据都缓存到卡车（内存）上。大家可以看到，这里的数据是一块一块的，也就是一点一点、一部分一部分地从输入文件流动到输出文件。

光说概念比较清楚但缺乏实践，现在通过一个例子证明 stream 的好处。我创建了一个 big file，大家可以自己循环创建一个这样的文本，它有一百多兆。任务是先用第一种方法，也就是同步的方法读取这个文件。用 Node.js 创建一个最基本 web server，在特定请求的时候返回文件的内容。在 onRequest 里先 readFile：从 fs 模块把 readFile 拿出来 import，第一个参数是文件名 bigFile，它有一百多兆。回调有两个参数，一个是是否有错误，第二个是对应的 data。有错误直接 throw，没有错误就 response.end(data) 输出。

观察一下：把大文件写入响应对象的时候，会把整个 big file 的内容写入内存。把 Chrome 放在前面，打开 Activity Monitor。现在没有 Node 进程，启动 ts-node stream.ts，启动完毕搜索一下，可以看到 Node 进程占用了 127M 内存。现在访问对应的接口（localhost 8000），它会触发文件读取，看看内存是否有变化。它开始写入文件，稍等一下，内存使用占到了 323M，从 120 直接提升到 323，这是非常恐怖的内存占用。然后它回落到 96，原因是整个程序崩溃了，文件太大，输出过程崩掉了。

现在做一个修改。HTTP 响应对象（response）是一个可写流。这就意味着，如果我们有一个可以代表 big file 的可读流，就可以把两个对象互相导入，达到同样的目标，但不会消耗那么多内存。创建一个可读流：从 fs 中把 createReadStream 拿过来，把原来的代码删掉，const src = createReadStream(bigFile)，它接受一个参数就是 bigFile。然后可以使用 src 上的 pipe 方法，这个跟管道非常类似：把可读流 pipe 到可写流。刚才说过 response 就是一个可写的，所以 src.pipe(response)，整个过程就结束了。

再运行一次看内存的变化。先关掉重新运行 ts-node stream.ts，现在是 128M。访问 localhost 8000 重新读取，它不断输出。观察内存，只上升了二三十兆，比之前小非常多，然后回落到 126，而且程序没有崩溃。我们就使用 stream 见证了一个不大不小的奇迹：当客户端请求这个大文件的时候，一次流入一个数据块，意味着再也不用在内存中缓存这个大文件了，内存使用最多也就增长到三四十兆。你还可以修改这个例子测试临界值，比如重新生成一个更大的文件，超过 2GB，甚至生成比 Node 缓冲区上限还大的文件都可以。

通过这个直观的例子，大家都感受到了 stream 的魔力。很多 Node.js 内置模块都实现了流接口。比如刚才使用的 HTTP 的 response 模块，它是支持流的。其实还有很多，可以简单看一下这张图：一边是 readable stream，一边是 writable stream。有一些既支持可读流又支持可写流，比如 HTTP 的 request 和 response、zlib、crypto、TCP，还有 stdin 和 stdout；还有一些只有可读或者可写，比如 fs 的 readStream 和 writeStream。
