上一章我们通过一系列课程完成了一个钩子函数的进化。对于整个应用来说，已经没有什么大的难点，基本上都是增删改查的操作，使用 action 发送异步请求、在 mutation 中完成对应操作，对大家来说都轻车熟路了。应用的最后，我给大家介绍一个听起来很简单、其实能学到不少知识点的功能：下载文件。

在详情页中有一个按钮用来下载图片，点击之后我们希望能下载这张海报。下载文件是 Web 界面的常见功能，它是怎样完成的？我们的下载都基于 URL 完成。大家知道，a 链接有着天然打开 URL 的能力：设置对应的 href 属性并点击，就会打开一个 URL。我在页面上加了一个 URL，点击后会跳转到新地址，但不会下载文件，这是它默认的行为。

有没有方法改变这种行为？a 链接上有一个特殊属性：download，这是实现下载功能非常关键的一点。文档里可以看到，它是 HTML5 新增的属性，描述是让浏览器下载 URL 而不是导航到它，因此会提示用户将其保存为本地文件。注意这个属性是可以赋值的：如果它有一个值，这个值会在下载保存过程中被作为预填充的文件名。所以 download 属性就是完成下载的重要工具。

除了这个属性，还有一个属性必须一提，大家应该不常见：rel。它的值是列表类型，可以看到有一份链接类型的文档，里面有非常多的值，描述不同的内容，大家可以自行了解。这里我想特别介绍一个值：noopener。它的作用是让浏览器打开链接时不赋予新的浏览器上下文对打开文档的访问权限。听起来拗口，用通俗的话描述一下：当我们用 a 链接打开新标签页时（比如设置了 target 等于 blank），新页面的 window 对象有一个属性 opener，它指向前一个页面的 window 对象。后一个页面通过 `window.opener` 就能拿到前面页面的控制权，这是非常可怕的，对钓鱼网站来说这个属性非常关键。React 的 ESLint 有一条规则：当你设置 target 等于 blank 时，必须把 rel 设置成 noopener。很多现代浏览器把这个行为设为了默认，所以在 Chrome 里操作时 opener 返回的是 null。

了解了这两个属性，就可以完成下载了，其实就是模拟整个过程：创建一个 a 链接，设置 href 和 download 属性，通过程序触发 a 链接的 click 事件。

页面里准备了两张图片：一张是本地的静态文件，另一张是要下载的、OSS 上的远程文件。先试本地文件。虽然可以直接写一个 a 链接，但我们想用程序实现，所以创建一个 function，称为 downloadFile，拿到图片想要下载的地址：`const image = document.getElementById('logoImage') as HTMLImageElement`，取它的 src。

然后按步骤来：创建链接 `const link = document.createElement('a')`；设置属性，第一步设置 href 为 image 的 src；第二步设置关键的 `link.download = 'test.png'`，这样就会触发下载动作，赋的值还可以作为文件名；再把 `link.rel = 'noopener'` 设置上，这个属性在 Web 安全上很重要。都设置好之后触发事件：用 `link.dispatchEvent(new MouseEvent('click'))` 触发一个 click 事件。

把这个函数返回出去，在按钮上绑定 click 触发 downloadFile。现在验证：点击下载海报图片，这张图片被成功下载了，本地的场景没有问题。

再看第二种情况：下载远程图片。把代码里的 id 换成 coverImage，再点击下载海报图片，期望的下载没有发生，而是直接跳转到了那个 URL。

为什么会出现这种情况？download 属性的文档里有一条提示：此属性仅适用于同源 URL。我们这里不是同源而是跨域的情况，这种方式没法实现直接下载，只会直接跳转到 URL。这个问题该如何解决？下节课我们再深入了解。
