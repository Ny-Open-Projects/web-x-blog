这节课把镜像推送到阿里云 ACR，需要几条命令完成对应功能。第一步前提：确保上节课的任务已完成，即创建好了命名空间和镜像仓库。帮助文档里的步骤可以归纳为登录、打 tag、推送三步。

## 登录私有仓库

登录私有仓库使用 docker login。到实例列表的镜像仓库，点击你创建的仓库，首页有一系列帮助说明，复制登录命令即可。特别注意后面的地址可能不一样，跟你一开始选择的 region 有关，中间这段 URL 会不同：

```bash
docker login --username=<你的用户名> registry.cn-xxx.aliyuncs.com
```

回车后输入密码，这是你一开始为 Docker 服务设置的专有密码（注意它和整个阿里云的登录密码不一样），显示 login succeed 说明登录成功。

## 构建并打 tag

推送前需要 build 镜像，并且要打一个阿里云专属的 tag。地址结构和登录地址类似：前面是专属 URL，然后是命名空间、镜像仓库名，最后加一个版本号。这些信息在页面上都能直接复制。两种方式：

1. build 的同时打 tag：

```bash
docker build --tag <registry地址>/<命名空间>/<镜像仓库>:0.0.1 .
```

2. 先正常 build（比如 `docker build -t opsflow-backend .`），再给已有的 image 打 tag：

```bash
docker tag <image id> <registry地址>/<命名空间>/<镜像仓库>:0.0.1
```

这里采用第一种，build 和打 tag 一步完成。版本号按自己的想法写，测试就随便写一个 0.0.1。回车构建，完成后用 `docker images` 确认镜像 build 成功。

## 推送并验证

```bash
docker push <registry地址>/<命名空间>/<镜像仓库>:0.0.1
```

版本号要和之前打的 tag 一致。因为之前推送过有缓存，很快就 push 完毕；第一次推送会等待一段时间。到 ACR 页面点"镜像版本"，可以看到 0.0.1 版本已经推过来了，最近推送时间也正确，说明没问题。

## 用新镜像启动应用

有了远端镜像，就可以创建一个新的 docker-compose 文件来启动应用。这个文件不是本地 build 用的那种：opsflow-backend 不再需要 build 过程，而是直接从 ACR 拉取镜像。理论上有两个文件就够：一个 .env（使用了一系列环境变量），一个 mongo-entrypoint 文件夹（初始化脚本），YML 放在任何位置都可以。我在项目文件中创建了一个 docker-compose-online.yml，专门用来运行线上应用，内容与原来基本一致，区别是后端直接写 image 地址（版本 0.0.1）；端口我也改了，测试使用 7002。

启动时 docker compose 要多加一个参数 `-f`，指定用哪个 YML 文件作为启动脚本：

```bash
docker compose -f docker-compose-online.yml up -d
```

等待之后，三个服务都启动成功。到本地 7002 的 API 查看 ping 接口：版本号都正确输出了；再看 templates，数据也能完美读取，说明没问题。

关闭同样加 `-f` 参数，一一对应：

```bash
docker compose -f docker-compose-online.yml down
```

大家可以自己测试一下：把拉取的这个 image 删掉再重新启动，它会进行一次真正的远端拉取。

任务完成：我们把 build 好的镜像推送到了私有仓库，应用不再局限于本地；又新建了一个 docker-compose 文件，通过它就能轻松在任何服务器启动应用，非常方便。
