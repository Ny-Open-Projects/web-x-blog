这节课渐进地完成右键菜单的编码。最初的方案大家都能想到：创建一个组件，对应的选项是一系列操作组成的特定数据结构的数组，作为属性传入，再把组件引入 editor 即可。这节课就先完成这个容易想到的方案。

## 组件与数据结构

我创建了 `ContextMenu` 组件，初始结构里特别注意类名，它们复用了 Ant Design Vue 的 Menu 组件的一些类名，加上之后整个样式更美观。初始样式中，最外层的 `menu-container` 设置为 `display: none`、`position: absolute`。

接着确定 ActionItem 的数据结构。看最终效果：左边一行文本，右边是快捷键，点击执行对应操作。所以：

```ts
interface ActionItem {
  action: () => void
  text: string
  shortcut: string
}
```

`action` 是函数，`text` 是左侧文字，`shortcut` 是右侧快捷键。组件 props 有一个 `actions` 属性，类型是 `PropType<ActionItem[]>` 的数组，必传（required）。

有了属性之后，在 ul 里循环展示：

```html
<li v-for="(action, index) in actions" :key="index" @click="action.action">
  {{ action.text }} {{ action.shortcut }}
</li>
```

点击后调用对应的 `action`。

## 接入 editor

在 editor.vue 中引入组件，放在 ALayout 的最外面，并在 setup 中创建一组测试数据 `testActions`（含撤销的 shortcut 和 action）传给组件。页面出现菜单，点击能调用对应的 action。

## 显示、隐藏与定位

下一步：让它先消失，再在右键点击时出现，且位置跟鼠标有关。

创建 `triggerContextMenu` 回调，参数 `e` 是 MouseEvent。第一步检查是否点击到了期望的元素，`edit-wrapper` 或其子元素。用之前写过的 `getParentElement`（循环检查 parentNode 是否有对应类名）：

```ts
const wrapperElement = getParentElement(
  e.target as HTMLElement,
  'edit-wrapper',
)
```

判断命中后再处理：先 `e.preventDefault()` 取消默认的右键菜单，然后改菜单组件的样式。拿 DOM 节点用 ref：

```ts
const menuRef = ref<HTMLElement | null>(null)
```

初始值 null，通过 ref 绑定到模板上。触发右键菜单时它肯定已经存在，所以做一次类型断言拿到 `domElement`。之后改样式：`display: block` 让它显示；位置用 `e.clientX` 和 `e.clientY` 加上 `px` 分别赋给 `top` 和 `left`。

关闭的处理写一个 `handleClick`：拿到 `domElement` 后直接把样式设为 `display: none`。两个函数写完，在 `onMounted` 里注册事件：

```ts
document.addEventListener('contextmenu', triggerContextMenu)
document.addEventListener('click', handleClick)
```

`onUnmounted` 里把这两个事件全部移除。

## 测试与两个遗留问题

页面测试发现菜单位置不对，追查原因发现写错了：`top` 应该用 `e.pageY`，`left` 用 `e.pageX`（client 坐标相对视口，page 坐标才包含滚动偏移）。修改后位置正确了；点击撤销或点击页面任何地方，右键菜单都能消失。

第一步编码完成，组件已经能成功出现在界面中。但我认为还有两个问题：

1. 调用时需要知道右键点击元素的 ID，执行 delete 或 copy 这些操作时，必须知道当前点的是哪个元素才能继续；
2. ContextMenu 虽然是 UI 的一部分，但它和快捷键（用 `initHotKeys` 调用）非常相似，很适合插件化的表达。能否改成调用一个函数来生成 context menu，而不是像普通组件一样挂到模板里？
