上节完成了发布任务，这节展示发布成功后的一系列信息。从需求得知，之后要弹出一个表单，上面展示的数据包括：左侧的作品截图（page 的 coverImage，即已上传的截图）；右侧的标题、描述和分享图（分享图在"预览和设置"里设置，先不管）；静态的 tab 不用管；最重要的是渠道列表 channels。

## publish 后会有默认渠道吗

表单上 channels 默认应该有一个 channel，那对一个新的作品，publish 完毕后是否自带默认渠道？看接口：作品 71 调用 `channel/getWorkChannels/{作品ID}`，send 后确实有一个默认 channel；但最新创建的作品 232，send 后返回是空的，**publish 后不会自动创建默认渠道**。

所以要根据是否有渠道来创建默认渠道。在 publish 之后、展示发布成功浮层之前，还需要两个异步步骤。加两个注释：第五步 getChannelsList，第六步判断 `if (channelsList.length === 0)` 就 createChannel。

## store 中的 channels

channels 列表要显示在页面中，得存进 store。还是存在 editor 里；如果觉得 editor 这个 module 已经太庞大，也可以创建一个单独的 module 存放。

先添加新的 interface ChannelProps。看作品 71 返回的数据有四项：id、name、workId、status，id 是 number；name 是 string；workId 表示属于哪个作品，也是 number；status 是状态，先放在这里不管。

然后在 editorProps 中添加 channels 字段（注释：当前 work 的 channels），类型是 ChannelProps 数组，默认值空数组。

## action 与 mutation

两个 action 都用 actionWrapper：

```ts
const fetchChannels = actionWrapper('/channel/getWorkChannels/:id', 'fetchChannels')
const createChannel = actionWrapper('/channel', 'createChannel', { method: 'post' })
```

fetchChannels 的 URL 稍长，把 id 改成冒号形式传变量。createChannel 的 URL 就是 channel，method 设为 post。

对应的 mutation 两个。fetchChannels 的参数 data 要和后端打交道，类型正好用之前定义的 ListData（它返回一系列数组），泛型传入 ChannelProps，即 `ListData<ChannelProps>`；内部直接 `state.channels = data.list`。createChannel 返回的是单个对象，用 ResponseData 包 ChannelProps，内部 `state.channels.push(data)`。

## 串进发布流程

第五步在 publishWork 之后执行 `await store.dispatch('fetchChannels', { urlParameters: { id: currentWorkId } })`，URL 与接口文档一致，要传入作品 id。

第六步判断长度：添加 computed 的 channels，返回 `store.state.editor.channels`，然后 `if (channels.value.length === 0)` 就 `await store.dispatch('createChannel', ...)`。因为是 POST 要传 data，对照接口 body 有 name 和 workId 两个参数：name 写默认值，workId 是 currentWorkId。

## 一个真实的类型错误

页面验证：点击发布，请求依次发出，uploadImage、works/publish、getWorkChannels（返回 list 为空），然后发送创建渠道的 POST，但全局错误弹出来了，提示数据格式有误，错误信息说 workId should be number。

原因清楚了：currentWorkId 现在是 string 类型（路由参数可能是 string 或 string 数组），后端要求 number。需要做类型转换：先 `as string` 断言，再 `parseInt` 转成 number。

重新执行一遍：点击发布，各种请求依次完成，getWorkChannels 返回空，channel POST 创建成功，返回新渠道数据。再点一次发布验证：请求到 getWorkChannels 返回有数据后就结束了，没有再发创建渠道的 POST，因为 list 里已经有数据了。

至此，展示表单之前的最后准备工作，获取渠道列表和创建默认渠道，全部完成。
