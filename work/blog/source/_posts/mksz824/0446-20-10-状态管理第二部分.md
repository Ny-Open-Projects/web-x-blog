上节课的痛点是 `useState` 没法被类型推论：在 app.vue 中初始化的全局状态，每次都要手动传入类型才能被推论成具体类型。这节课首先来改进这个问题。

第一种方式是通过组合式函数。在 composables 目录下创建一个 `useCurrentUser`。之前在自动导入一章讲过，组合式函数会被自动导入，通过它们可以定义类型安全、全应用可用的全局状态，从而避免每次都手动传类型。

具体做法：先把类型引入过来，在 types 中用 `UserProps`（嫌麻烦也可以直接把这个类型写进当前文件，因为目前只有它在使用）。然后创建函数 `useCurrentUser`，它要 return 初始状态：

```ts
export const useCurrentUser = () => {
  const user = useState<UserProps>('currentUser', () => ({
    isLogin: false,
    userName: '',
  }))
  return user
}
```

创建完之后，就可以在需要这个状态的地方直接使用。首先改 app.vue，原来繁杂的两行定义变成直接 `const user = useCurrentUser()`。因为新建了函数，需要重新运行一遍 dev 服务，让类型重新生成。重启完成后，`useCurrentUser` 已经出现在自动导入提示里，user 也拿到了对应类型，value 上的 isLogin 和 userName 都能正确推论。其他用到这个状态的地方（包括 login）也一并改掉，每处只需一行。这样就完成了上节课留下的任务。

这是一个非常通用的知识：如果有一个状态要在全局共享，就可以用组合式函数的形式，初始化写在函数里，应用的任何地方都能使用，并且是 type safe 的。

接下来讲一个关于状态的新知识点：异步初始化。定义组合式函数时已经完成了初始赋值，但很多情况下初始化需要异步完成，通常要发一个异步请求获取最新数据，获取当前用户信息更是如此。典型场景是：上次登录成功后，用户的登录信息（JWT 记录的 Token 值）被记录在本地，再次访问时通过这个 Token 给后端发请求，验证登录信息是否正确。之前在 OpsFlow 前端项目中就是这么做的。

现在隆重推出 Nuxt 的一个全局函数 `callOnce` 来完成这个功能。它要在入口文件 app.vue 中调用，顾名思义会在初始化时调用一次，通过它就可以完成状态的异步初始化。

先创建一个假的请求函数，返回一个 Promise，模拟异步请求：

```ts
const getUserInfo = () => {
  return Promise.resolve({ userName: 'Viking' })
}

callOnce(async () => {
  const info = await getUserInfo()
  user.value.userName = info.userName
  user.value.isLogin = true
})
```

刷新页面可以看到登录状态已经生效，页面显示了 Viking，说明请求被成功调用，user 的值也能正常显示。

那么这段逻辑实际在哪里执行？很多写惯前端项目的人会认为应该在组件 mounted 之后、在浏览器里调用。验证一下：在 callOnce 的回调里加一句 `console.log('init here')`，打开浏览器控制台清空后刷新，什么都没有输出；而终端里却打印出了 init here。这说明在 Nuxt 这种前后端一体的框架中，很多看似前端代码的逻辑，其实是和后端整合在一起运作的，这次初始化是在后端（服务端渲染阶段）完成的。要跳出纯前端的思考范畴，用前后端一体的框架来思考问题。

简单回顾这节课的两个知识点：一是用组合式函数管理全局状态，在应用中直接调用函数获取状态并获得类型；二是用 `callOnce` 在初始化阶段异步初始化状态。后面还会用到这个方法，到时再加深印象。
