根据上节课的分析结论开始写代码。第一步是创建保存历史记录的数据结构。在 editor.ts 中新建 interface，命名为 `HistoryProps`，每一项长这样：

```ts
interface HistoryProps {
  id: string        // 历史记录每项的独立标识符
  componentId: string  // 记录的是哪个 component
  type: 'add' | 'delete' | 'modify'  // 操作类型，共三种
  data: any         // 数据形态多样，可能是复杂 object，也可能是 oldValue/newValue/key
  index?: number    // 删除时记录原位置，回插时可插回原处
}
```

`type` 用字符串字面量：`add`（添加）、`delete`（删除）、`modify`（修改）。`data` 因为有多种形态，先设成 `any`。`index` 是可选的，只在删除时用来保存被删除的位置，恢复时能插回原处。

然后把它加进总的 `EditorProps`：一个 `histories: HistoryProps[]` 数组，以及一个 `historyIndex` 记录当前历史操作的位置，数组指针会来回移动，靠它知道现在走到了哪一步。加完之后类型不完整会报错，补上初始值：`histories` 是空数组，`historyIndex` 设为 -1，代表还没有移动过。

接下来在对应的 mutation 里添加历史记录。三种情形分别处理。

## 添加图层

`addComponent` 里直接 push：

```ts
state.histories.push({
  id: uuidv4(),
  componentId: component.id,
  type: 'add',
  data: cloneDeep(component),
})
```

特别要注意 `data`：这个对象之后可能会发生一系列修改，我们要拿到它最原始的值，所以不能直接存响应式对象，必须用 `cloneDeep` 克隆一份。`pasteCopiedComponent` 也是新建图层，复制同样的 push 逻辑，把 `componentId` 改成 clone 的 id、`data` 改成 clone 即可。

## 删除图层

delete 需要的值有 componentId、type、data 和 index。因为要拿 index，先找到它：`find` 已经拿到 currentComponent，再补一次 `findIndex`：

```ts
const currentIndex = state.components.findIndex(
  c => c.id === id
)
```

逻辑和上面的 find 完全一致。然后 push：

```ts
state.histories.push({
  id: uuidv4(),
  componentId: currentComponent.id,
  type: 'delete',
  data: currentComponent,
  index: currentIndex,
})
```

这里的 `data` 不需要 cloneDeep。原因想一下就明白：组件被删除后就不存在了，不可能再被修改，数据会保持原始样子，直接保存即可。

## 修改属性

修改发生在 `updateComponent`，且只有修改 props 时才记录。`isRoot` 分支修改的是图层是否隐藏、是否锁定和图层名称这些根级属性，不是画布上的操作，暂时不存历史记录（想存也可以，这里定下规矩：它不算历史操作）。所以存储逻辑放在 props 更新的分支里。

先取 `oldValue`，也就是属性更新之前的值，然后 push：

```ts
state.histories.push({
  id: uuidv4(),
  componentId: data.id || state.currentElement || '',
  type: 'modify',
  data: {
    oldValue,
    newValue: value,
    key,
  },
})
```

`data` 里三个键：`oldValue` 旧的值、`newValue` 要更新到的值、`key` 更新的是哪个属性。键值和变量名相同时直接简写。componentId 这里有可能是修改当前选中的元素而没传 id，所以做一个兜底，用保存的 `state.currentElement`。

这节课完成了历史记录的添加，三种操作都会把对应的记录写进数组。有了 histories 之后，下节课添加对应的 undo/redo mutation，让数据可以在不同时间点之间漫游。
