按之前的计划，这节课完成表格展示的分页功能，非常常规的操作。第一步是让后端支持分页。

## 后端实现分页

分页自然需要一系列 query。先用 `getQuery(event)` 拿到 query object，通过两个参数控制：`currentPage` 表示现在展示第几页，`pageSize` 表示每页展示多少条。比如 currentPage 为 1、pageSize 为 10，就是展示第一页且每页十个条目。

特别注意：从 query object 拿到的值都是 string，之后要当 number 用，需要转换。用构造函数转换，并给默认值：currentPage 不传默认第一页，pageSize 同理默认 10：

```ts
const currentPage = Number(queryObject.currentPage) || 1
const pageSize = Number(queryObject.pageSize) || 10
```

在 MongoDB 中实现分页用 skip 值，代表跳过多少条记录。比如总共 20 条，取第二页就是跳过 10 条。skip 的算法很简单：当前页减一，乘以 pageSize。验证一下：第二页时 2 减 1 等于 1，pageSize 是 10，跳过 10 条就拿到了第二页的数据。

把 skip 添加上去，在原有查询上链式调用 `skip()` 即可。有了 skip 还需要一个 total：返回总共有多少条。它不需要任何跳过，就是计算现在 user 里有多少条，做一次新查询：`UserSchema.find({})` 条件为空获取所有，调用 `countDocuments()` 计算当前条件下总共多少值。

信息齐全后返回值要简单修改一下：不再是简单的数据结构，而是 `{ data, total, pageSize, currentPage }`，这是通用的分页列表逻辑。保存后 index.vue 有问题，因为数据结构变了：`data.value` 上面要再取一层 `.data` 再 map，修改完毕。

测试：返回 currentPage 是 1，data 是这些值，pageSize 是 10，total 等于 16。把 currentPage 设为 2 再请求，应该返回 6 条记录（跳过前 10 条），果然只有 6 条，分页完成。

## 前端分页组件

接下来实现前端的分页交互：点击分页后发送新请求。表格下面分两块：左边显示 total 多少条，右边是分页。

先显示 total。我在 UTable 下面创建了一个 div，缩进简单调整。同样用 flex 布局加 `justify-between`，左右两侧分开。左侧放 total，使用 Nuxt UI 的 UBadge 组件，就是一个带背景的展示 div，非常简单：

```vue
<UBadge>共有 {{ data?.total ?? 0 }} 条</UBadge>
```

total 没有就直接返回 0。现在显示出来了：共有 16 条。

分页在 Nuxt UI 有现成的解决方案，组件叫 Pagination。使用它最简单的参数就够了：`v-model` 是当前页码；`page-count` 是每页多少条（参数含义和我们的参数一致）；还有 `total` 总共的值。这三个条件我们都具备，直接拿来用。

先创建响应式变量：

```ts
const currentPage = ref(1)
const pageCount = ref(10)
```

currentPage 初始为 1，pageCount 为 10。然后展示 UPagination：

```vue
<UPagination v-model="currentPage" :page-count="pageCount" :total="data?.total ?? 0" />
```

看发送的请求：现在有 16 条，自然分两页；请求是 currentPage 等于 1、pageSize 等于 10，没问题。点击第二页，值也都能正常切换。

## 用 computed URL 自动重新请求

下一个问题：这些值修改时要使用新参数发送新请求。Pagination 已经支持 v-model，点击时 currentPage 会变成新值。常规做法是用 watch 监听 currentPage 和 pageCount 的改变，在内部调用 refresh 重新发送请求。

但 useFetch 有一个特别好用的内置功能，可以直接实现 watch 加重新请求。看文档 data fetching 一节：可以给 useFetch 传一个 watch 数组，响应式变量变化时就重新请求，变量还可以放进 URL，改变时自动发送新请求。

还有更方便的形式：computed URL。把第一个参数从直接的字符串改成回调函数，返回带 query 的完整 URL：

```ts
const { data, pending } = await useFetch(() =>
  `/api/users?currentPage=${currentPage.value}&pageSize=${pageCount.value}`
)
```

这种形式它会直接分析里面的响应式对象有没有变化，有变化就重新发送请求，非常强大。

保存测试：点击第二页，依赖的 currentPage 发生变化，新的请求完全发送了，功能实现。这个 watch 功能非常方便，把原来很复杂的逻辑简单一写就能重新发送请求。

大家也可以试试 pageCount 修改的情况，比如做一个下拉菜单选择一页显示多少条，修改时请求也会重新发送，课下可以做实验。
