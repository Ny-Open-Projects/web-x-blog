上节课完成了上传组件，文件上传相关的知识点就到此结束了。先做一个小回顾：在 Nuxt 中使用 Nitro 进行上传不是一件难事，拿到 Buffer 以后按照自己想要的方式处理就可以了。同时我们也掌握了动态表单构建的关键方式，就是把组件转化为特定的数据结构。只要我们数据结构里的组件支持 v-model 这个标准，任何第三方组件都可以完美适配这套动态表单系统，这是一个简单又非常实用的实现方案。想做得更复杂或更个性化，都可以按这套解决方案在上面扩展。

回顾完毕，这节课的任务是继续页面最实际的部分：完成用户信息的创建。需要和服务器端一个新的创建用户接口打交道。任务不算难，就是之前知识的一个汇总，来完成它，看看实践中会有哪些新的知识点。

首先我在应用中做了一些小改动，都非常简单，不手把手写，直接讲一下。第一是添加了 role，也就是用户的角色，有两种：normal 和 admin，代表普通用户和管理员。有了 role 之后，还添加了对应的数据结构 userRole，它是一个 select，options 有两个，normal 和 admin。另外还添加了验证规则。验证规则我把它挪到了外面：之前有 validators/user 这个文件，里面放置了和 user 相关的验证数据结构。userCreateSchema 就放在这里，也添加了 role 选项，两个值 normal 和 admin。之后后端也可以使用这个 zod object 来做验证。

接下来书写后端逻辑。创建了一个新接口：users 下面的 index.post.ts，用它完成用户的创建。

首先是验证。验证已经非常熟悉了，把提炼的 userCreateSchema 拿过来，用我们自己封装的方法 runValidate，先把 schema 传进去，再把 event 传进去，就完成了验证。验证完毕拿到数据，叫 payload，也就是 result.data。

拿到 payload 后要完成创建。这里特别注意要先做一个检查：检查用户是否存在。这是常规检查，因为 username 是用户的唯一 key，要保证这个 username 不存在时才可以创建成功。用 userSchema 直接调用 findOne，条件是 username 等于 payload.username。假如用户已经存在，就抛出一个对应的错误，告诉客户端已经存在了，需要换一个用户名。直接 throw 出去，使用之前的 error code 409，并输出一个 statusMessage：该用户名已经被注册。

除了检查用户名存在，另一种情况：如果是使用 email 和 password 的创建方式，还需要给 password 做加密，这在 sign up 那部分已经说过了，直接写即可。首先要判断，因为 password 是完全可选的，不一定传。password 存在的时候再加密，直接把加密结果写到 payload 上。这里需要把之前使用的 bcrypt 拿过来：`await bcrypt.hash(payload.password, saltRounds)`。需要加密的值是 payload.password，后面是 salt rounds，它可以在 configure 当中拿到，所以要用 useRuntimeConfig 拿到配置，取 config.decrypt 上的 salt rounds。这样加密就完成了。

最后很简单：创建 user，`await userSchema.create(payload)`，然后返回。返回时调用 toJSON，因为我们不希望把 user 的密码暴露出去。

后端就写完了。后端写起来和之前的逻辑非常一致，所以写得很快，是一个温故而知新的过程。下面自然是点击 submit 时发送请求。看起来简单，但特别注意要处理一个特殊问题：后端会抛出一些特殊的错误。我们不仅有客户端验证（runValidate 通过 zod 完成数据验证），后端也会抛出特殊错误，比如用户名已经被注册。我们希望这个错误可以显示到特定的字段上，它自然是和 username 字段相关联的，要把这个个性化的错误显示到对应字段上。

怎样完成呢？Nuxt UI 的 UForm 可以获取它的实例，实例上面有一系列方法和属性，可以自定义各种功能，这就是这节课要掌握的新知识点。先看文档，Form 这里有一个 Backend Validation 章节，前面和我们写的很一样，不一样的是 submit：这里 form 是一个空的 ref 对象，赋值给 uform 之后就获取了 uform 上的实例，有实例就可以调用一系列方法。其中最重要的一个方法叫 setErrors，通过它可以给上面的字段设置自定义错误并进行显示。

再看它的 API，form 上有一系列方法：submit 手动调用提交；validate 校验；clear 把所有错误信息删除；getErrors 获取当前错误；setErrors 自定义设置错误；还有 errors 获取错误。

开始实现。第一步拿到类型。文档示例里其实没有写 TS 类型，直接获取了一个空的 form 对象。我们希望拿到它的类型，以便调用属性和方法。Nuxt UI 已经提供了这样的类型：`import type { Form } from '#ui/types'`，通过它拿到 Nuxt UI 上的所有类型。这里要拿 form 的实例类型 Form。可以 go to type definition 看一下：Form 要接受一个泛型，上面有这些属性和方法，泛型是 validate 最后返回的类型，这里用不到，直接传 any 也没问题。

现在创建一个新变量 form，等于一个 ref，并给它类型断言。外层是 ref 类型，里面才是 Form，所以还需要把 Vue 的 Ref 类型拿过来：`import type { Ref } from 'vue'`。断言写法是外层 Ref，里面是 Form 实例类型，泛型传 any。现在 form 已经有了类型，属性和方法都提示出来了，很方便。

有了 form 之后特别注意要做赋值：模板里 ref 的名称应该等于变量名，不要写错，这里叫 form，上面也叫 form。

接下来完成 submit 当中的处理。回到 onSubmit，第一步在提交开始时先把上一次的错误 clear 掉，然后来一个 try catch，error 给 any 类型。try 里发送请求，叫 createUser，`await $fetch('/api/users')`，method 是 post（注意要发送 POST 请求），第二个是数据 body。

body 用哪个数据？filteredObject 是响应式对象，用它还要取 value，比较麻烦。其实 form 的 submit 有一个事件对象，事件对象上也包含对应的数据，而且是一个普通的 object，用它更方便。所以我们改用 event 的数据。event 也有对应类型，同样从 #ui/types 拿到，叫 FormSubmitEvent，它也接受一个泛型，同样设为 any。设置好类型后，event 上的属性都出来了，我们需要的是 data，它是提交成功后最终获取的值。加一个 console，创建成功时把它输出出来。

catch 是真正有意思的地方，处理自定义错误。判断依据是 status code：409 代表用户名已经被注册，就用这个错误来处理。当它等于 409 时，设置自定义错误，使用 form.value.setErrors。errors 是一个数组，类型里的值是 FormError，数组中包含多个 object，object 上有两个值：第一个是 path，也就是字段在 userData 上的 key；我们要设置 username，所以 path 设为 username。第二个是 message，想给它设置的错误内容。这里直接使用后端返回的值，也就是 e.data 上的 statusMessage。通过这种方式就完成了自定义。

这段逻辑可以胜任两种情况：创建成功时弹出对应的信息；如果使用了之前已经用过的 username，就会执行 catch 这一段。

代码写得不少了，验证功能是否实现。刷新应用，完成一次创建。先打印一下 event.data 看数据是否是想要的。输入一个之前没有的名称，比如 viking012，nickname 也是 viking012，邮箱输 viking012@test.com，password 六个一。信息输完整后点击创建。可以看到 console 输出的 data 是表单成功提交后对应的数据，没有问题，展开看没填的东西都是 undefined（自动删掉了）。然后是 newUser，也就是后端创建成功的值，里面返回了一系列信息，说明创建成功了，请求也是成功的。

接下来复制一下刚才的名称，看看错误的情况能否出现。清空表单，填入 username（这里只有 username 是必填的，type 有预填值），直接点击创建，应该会出现错误。可以看到 user API 输出了对应的值，是后端抛出的，我们自定义的错误信息也完全显示在了 username 字段上，整个流程成功完成。

这个过程中我们温故而知新：复习了后端之前的一些逻辑写法，也学到了一个新的重要知识点，就是 UForm 的实例上有一些属性和方法，可以通过其中的 setErrors 添加一系列自定义错误。这节课就到这里。
