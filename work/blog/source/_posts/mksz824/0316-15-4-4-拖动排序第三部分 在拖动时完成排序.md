这节课完成拖动中自动排序的功能。上节课是在 drop（松开鼠标）时完成任务，这节课希望监控拖动的过程，自动完成换位。

## 用 dragenter 监控拖动过程

监控拖动过程可以使用一些事件来完成。有一个拖动事件叫 `dragenter`：拖动进入特定的可拖动区域时触发，对我们这种要实时完成的操作看起来很合适。只需在 li 上添加对应的事件，拖动进去时触发即可。

新建一个回调 `onDragEnter`，两个参数：第一个还是 drag event；第二个直接把 index 传进来，这样就不需要再拿 DOM 节点取值，更方便一些，类型是 number。先简单打印两个值看看效果：打印 enter 时的新 index，以及 `dragData.currentIndex` 的当前值。然后 return 出去，在 li 上添加 `@dragenter`，两个参数分别传 event 事件对象和 index。

drag 事件系列包括 drag、dragend、dragenter、dragleave、dragover、dragstart，顾名思义大家应该能猜到各自的用途。

界面测试：拖动第一项，鼠标还没有进入其他区域时不触发；移动到第二项时触发 enter，新 index 是 1、旧的是 0；再拖到第三项，也触发了第三项的 enter。所以我们可以在里面做具体的操作。

## 换位逻辑

逻辑很简单：在 onDragEnter 里直接调用上节课的 `arrayMove.mutate`，把 moveIndex 换成当前的 index。另外要注意：换位完成后，`dragData.currentIndex` 要更新成新的值，这样才是正确的起始索引，即 `dragData.currentIndex = index`。

看最终效果：拖动图层一到图层二，它会实时反应；再拖到图层三，也完成转换。

这里有一点不完美：拖动过程中，完成一次转换后还会触发一次新的 enter，此时 current index 和 index 是完全相同的（因为其实还在最初移动的元素上）。可以加一个简单的判断优化：当两者不相等时才进行移动，即 `index !== dragData.currentIndex` 时才执行换位。

再测试：拖动图层二到图层三，触发了一次；再次拖动经过时不再重复触发；图层一和图层二互换后也没有重新触发事件。任务完成。

## 更精细的时机（原理介绍）

目前的换位发生在鼠标移入目标元素的那一刻。如果想做得像 demo 那样完美，被拖动条目的下沿覆盖到目标元素一半的时候才发生转换，就需要新的解决方案：必须能持续监控精确的像素值。可以使用 drag 或 dragover 这两个事件，它们都会在拖动过程中每隔几百毫秒自动触发一次。这里只讲述拖动排序的简单原理，就不编码这个具体需求了。

## 补充 drop 事件通知

既然现在 dragenter 时就能发生换位，onDrop 里原来的交换逻辑就不需要了，可以去掉。但希望松开鼠标（onDrop）时发送一个事件出去，把最初的 index 和移动到的 index 这两个值发给外界，外界可以用它们做后续操作。

新建两个普通变量来记录这两个值，它们不在 template 中使用，没必要声明成响应式对象，普通变量即可：`start` 和 `end`，都声明为 -1。在 emits 里多添加一个 drop 事件，在 onDrop 中通过 `context.emit('drop', { start, end })` 发送对象。赋值：`start` 在拖动开始（onDragStart）时赋为开始的 index；`end` 在 onDragEnter 时赋为最后的 index。

## 关于数据流的说明

注意现在的数据流不是自上而下的：数据是直接在组件中修改的（props.list 是响应式数据），所以组件完成排序时，右侧画布区域也会自动完成排序。如果你想严格遵守自上而下的数据流、让全局修改在 Vuex 的 mutation 中发生，可以对组件做一个简单修改：组件内部保存一个内部状态，不直接使用 props.list，通过发送出去的 drop 事件，在 mutation 中完成修改。这里我就不这样改了，有兴趣可以自己写这部分代码，写的时候会发现里面还有几个要注意的小点。

通过三节课的编码，我们完成了拖动排序的任务。其实主要就是和 drag 以及相关的一系列事件打交道。相信大家对 HTML 提供的原生拖动操作有了初步的了解，以后遇到拖动相关的需求，不妨先想想用浏览器支持良好的原生拖动来完成。
