Express 作为一个无规则、简单、快速的 Web 框架，自身定位就是一个路由和中间件的框架，自身只有最低程度的功能。所以 Express 应用程序基本上是一系列中间件函数调用。这里把中间件单独拿出来介绍，特别要注意它和之后 Koa2（也就是 Egg.js 的底层）的中间件实现进行对比，这两种中间件模型是面试常见的考题。

Express 中间件非常简单，看图就能看出来，它的执行是一个线性的过程，可以想象成一个类似管道或队列的结构。一个 client 的 request 从左边流入，每个中间件函数都能访问到请求对象 request、响应对象 response，以及应用程序请求响应循环中的下一个中间件函数 next。调用 next 就可以前进到下一个中间件，以此循环，最后到达 response。最重要的点：中间件的执行顺序是一个类似队列的结构，先进来的先执行，这是它最重要的特质，请大家特别注意。

中间件有什么作用？整个 Express 都是基于中间件的框架，你能想到的任何工作都可以在中间件中进行：可以执行任何代码；可以对请求和响应对象进行更改，在上面添加属性；可以结束请求响应循环，提前结束，直接给 response 赋值就可以；还可以调用堆栈中的下一个中间件，也就是用 next 到下一个中间件去。

现在编写几个简单的中间件测试一下。第一个是最简单的例子：定义一个 function 叫 myLogger，记录一行日志。它有三个参数：request、response 和 next。函数内部直接 console.log('logged')，然后调用 next 向下执行。使用中间件可以用 app.use 方法，把 myLogger 添加进去；还可以在路由上添加回调函数，这里可以添加多个，每一个都代表一个对应的中间件，所以那些回调函数其实也是中间件。保存后请求一下，可以看到 logged 被打印出来了，说明中间件实现了功能。

再写第二个，叫 requestTime，记录请求开始的时间，演示它的第二个作用：改变某个特定的属性。先 console.log time，然后在 request 上面添加一个属性 requestTime，值为 `Date.now()`，最后调用 next。这里特别注意：中间件装入的顺序很重要，首先装入的中间件函数也会被首先执行。把 requestTime 放在第一位，再在后续中间件里输出 req.requestTime，请求一下可以看到属性被成功添加，顺序验证也正确：先是 time，然后是 logged。

这样就简单了解了中间件。但这个模型有一个问题比较难解决：假如有一个中间件需要记录每次请求从开始到结束总共花了多长时间，由于它是线性的结构，通过一个中间件很难完成这个任务，可能必须使用两个：在开始的时候记录开始时间，在结束的时候记录结束时间。但这个功能又明显应该属于一个中间件的范畴，实现起来就比较挠头。

举个例子：我们需要在 response headers 添加一个 header 来记录每次请求到响应的时间。没法在一个中间件中完成，所以要添加两个。第二个我们叫 responseTime，参数是 req、res 和 next。在这个中间件里完成一个减法，计算 duration：`new Date()` 减去 `req.requestTime`，这样就能拿到从开始到结束花费的时间。然后再设置一个 header，调用 response 上的 setHeader 方法，名称叫 X-Response-Time，把 duration 添加进去。最后别忘了调用 next，让它到下一步去。把这个 responseTime 中间件注册进去，再访问对应的请求。特别注意要看 network 当中的 response header：刷新后可以看到 X-Response-Time 已经记录上了，值等于 0，因为处理很快，直接就返回了。

现在的问题就是：看起来应该在一起的功能，却要花费两个分离的中间件来完成。当然也有通过事件的方式、以一个中间件的形式完成这个任务的，那属于另辟蹊径。这就是业界认为 Express 中间件模型的一个小小的弊端。

通过这节课我们简单了解了 Express 中间件模型的运行规律，非常简单，也是很经典的模型，相信很多同学之前都有所了解。关于 Express 的调研就到这里，下节课调研 Koa2，看看它有什么样的特性和优劣。
