上节课简单介绍了流的概念，这节课讲讲它的简单用法。注意这里是简单用法，不会非常深入、把所有 API 面面俱到，只是针对后面的任务展开一定的讲解。想了解全部内容请去看 Node.js 官方文档。

Node.js 中有四种基本的流类型：第一种叫 readable，可读流；第二种叫 writable，可写流；后面两种叫 duplex，双向流，和 transform，转换流。双向流和转换流在内部的实现方式其实是一样的。这里主要讲 readable 和 writable，另外两种最后稍微提一下。

先说可读流。可以把它想象成数据的源头，比如一个水龙头。上节课说过，Node.js 内置的很多模块都支持 stream，现在用读取文件举一个例子。来到 stream-basic 代码，我建立了一个原始文件 text.txt，里面有几行文本。流的开始都是从源头，也就是可读流开始的。可以认为我们创建一个水龙头：从 fs 中把这个"水龙头"的建立方法拿出来，叫 createReadStream。创建它的实例，称为 readableSrc：`createReadStream('./text.txt')`，它接受一个参数，是你想读取的文件的路径。到这里可读流就创建好了。

接下来需要一个可写流做输出。这里可以采用 Node.js 内置模块 process 上的 stdout，可以看到它是一个可写流，功能是把内容输出到界面上。可以把可写流看成一个水桶：把可读流送到可写流里去，需要调用一个方法，这个方法的名字非常神奇和形象，上节课也接触过，叫 pipe。pipe 就是管道的意思。在可读流上调用这个方法，把水龙头里的水流到水桶里去，完成输出：`readableSrc.pipe(process.stdout)`。运行 ts-node stream-basic.ts，可以看到文件的内容成功输出了，第一个任务完成。

接着把可写流更换一下。现在希望读取文件内容，写到另外一个文件中。这时需要手动创建一个可写流，而不是使用内置定制好的。这就是第二种流的类型：从 fs 中拿 createWriteStream。创建一个称为 writeDest（destination）：`createWriteStream('./text-2.txt')`，输入你要写入的文件名称。建立以后还是使用相同的方法，pipe 到这个可写流里去，这样应该会生成一个新文件。再运行一次，运行完毕出现了 text-2.txt，打开看，内容跟 text.txt 完全一致，任务完成。

现在要说一下，看似这么简单的 pipe 方法怎么就完成了写入呢？其实当你调用 pipe 方法的时候，它帮你自动完成了一些事情。首先要知道，这些流都是基于事件的。说起事件大家已经驾轻就熟，流的这些类继承自 EventEmitter。常见的事件可以看这张图，分为 readable stream 和 writable stream，它们有一些不同。简单浏览一下：readable 有 data、error、close、readable 等事件；writable 有 finish、error、close、drain 等。还有一些对应的方法，比如 readable 上的 pipe、read、pause，writable 上有 write 和 end。这些方法我们不会依次详细说明，就拿几个简单解释。可读流在读取数据的时候自然会触发 data 事件，读完的时候触发 end 事件；writable 在写完的时候触发 finish 事件。看这些名称，大家多少能了解其中的意思。writable 里的 write 是写入数据，end 是结束写入。

现在来实现 pipe 到底是怎么完成任务的。它其实等于一个快捷方式，完成了对应的操作。把 pipe 那行注释掉，把 text-2 删掉，使用基于事件的写法：readableSrc.on('data', chunk => {...})，data 是标准的事件，参数 chunk 指的是一小部分数据。在回调里调用 writeDest.write(chunk) 把 chunk 写入。当 readable 结束的时候，事件名称是 end，在 end 回调里调用 writeDest.end() 结束对应的写入。这样就完成了把 pipe 改写成基于事件的操作。

从代码可以看出：在可读流获取 data 的过程中，可写流开始对应的写入；当可读流读取完毕的时候，也把可写流关闭。验证一下最后的过程是否成功：text-2 也生成了，内容也没问题。所以说 pipe 其实就是通过事件写的一个快捷方式。stream 的主要知识其实也就是这些，我们没有从 readable/writable 构造函数开始花大量时间解释它的事件和方法，因为那是课下可以自己了解的，我们只需要知道 stream 最基本和最精髓的特点就可以了。

最后提另外一种流：转换流。它是双向流的一种。在我们水龙头的比喻中，可以把转换流想象成安装在水管中的一种神奇转换器，它可以把水流做转换，然后再继续运输下去。比如一开始传送的是自来水，它可以把它变成橙汁，然后继续放到可写流中去。这就是转换流本身要做的：就像图里一样，通过内部的写入过程，将一个可读流转换为另外一个可读流，再传输到可写流里。

现在进化一下我们的例子：把读入的文件生成一个对应的压缩包。压缩可以使用 Node.js 提供的原生模块 zlib。zlib 下面有一系列压缩相关的方法，很多都是转换流。看一下它的类型，点进去可以发现它们都继承自 stream.Transform 这个类，说明它们是一系列转换流。转换流嘛，就可以进行转换。

重新来写：从可读流开始，readableSrc pipe 到一个转换流，这个转换流就是 zlib.createGzip() 的返回结果，调用这个 function 返回的是一个转换流；然后在最终 pipe 到 writeDest，也就是对应的写入地址，这样就完成了工作。当然把后缀名改一下，叫 text.txt.gz。运行脚本看最后的结果：text.txt.gz 已经生成了，点击它不能直接打开，因为它是一个压缩文件。

现在我们就完成了这个过程，也能理解流的特点了。如果你用过打包工具 Gulp，就会非常熟悉这种写法，在那里有非常多的转换流用法，都是进行文件的转换。我希望大家在课后做进一步练习：把 gz 文件再解压回来。我们这里已经成功把它压缩了，希望使用 pipe 的格式完成对应的解压。

再看上节课的代码，相信大家已经能够理解其中的道理了：我们创建了一个可读流，而 response 之前说过是一个可写流，所以把它 pipe 进去，就可以直接写出来。通过这节课我们了解了 stream 的几种类型和基本用法，下节课进一步在应用中使用 stream 完成对应的任务。
