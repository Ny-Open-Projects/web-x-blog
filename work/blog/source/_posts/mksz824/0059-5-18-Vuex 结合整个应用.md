上节课创建了一个 store，但只是测试，它还游离在整个应用外面。现在把它和整个应用整合在一起。过程不困难，但要特别讲讲 store 和 TS 的结合，过程中穿插几个知识点。

## 定义类型

项目结构保持一致，创建一个 store 文件夹，里面有 index.ts，Vuex store 的信息写在这里。第一步导入 createStore。假定全局数据有两部分：template 模板的数据，以及 user 当前用户的数据（是否登录等）。虽然没有对应功能，先用假数据做实验。

接下来定义类型。user 类型称为 UserProps：isLogin 是布尔，userName 是用户名称。template 类型有 id、title、cover、author 和 copyCount：

```typescript
export interface UserProps {
  isLogin: boolean;
  userName?: string;
}

export interface TemplateProps {
  id: number;
  title: string;
  cover: string;
  author: string;
  copyCount: number;
}

export interface GlobalDataProps {
  user: UserProps;
  templates: TemplateProps[];
}
```

最后把两者整合成整个应用的类型：user 是 UserProps，templates 是 TemplateProps 的数组。有同学可能问，为什么费力不讨好写这么多类型？再次重申 TS 的优势：第一是自动补全，interface 上的属性都可以自动补全；第二是类型检查。不管千变万化，TS 的意义都在这两个词里。

再创建一些 test data，六个 template 的数据，和原来一样。

## 创建并挂载 store

现在创建 store。createStore 接受一个泛型，可以把定义的全局结构传递下去。泛型的作用就是让自定义的类型流动到函数内部或返回值，最终是为了自动补全：

```typescript
import { createStore } from 'vuex';

const store = createStore<GlobalDataProps>({
  state: {
    templates: testData,
    user: {
      isLogin: false,
    },
  },
});

export default store;
```

加了泛型后，state 立即报错，因为缺少定义的两个属性；自动补全出 templates 和 user，testData 类型完全相同所以没问题，user 里定义 isLogin 也有补全。

store 创建好后在 main.ts 里引入，和 router 一样用 use 以插件的形式挂上去：

```typescript
import store from './store';

createApp(App).use(store).use(router).mount('#app');
```

## 在组件中使用 useStore

改一下首页，让 template 数据从 store 获得。Home.vue 里删掉写死的测试数据，Vuex 也提供了钩子函数，和 vue-router 非常一致，以 use 起名叫 useStore。调用它返回 store 实例。特别注意：响应式地呈现数据必须用 computed 包裹：

```typescript
const testData = computed(() => store.state.templates);
```

但会发现这里面的数据没法自动补全。追求完美的心思又活络了。因为 useStore 是一个单独的函数，和 store 里的类型没有关联，所以要手动把 state 的结构传递过去。想到什么？没错，泛型。一个函数的返回值想要用户自定义的结果，只能用泛型。每次我都强调这个概念，就是希望通过多次强化，把泛型这个思想刻进大家的习惯。

先从 store/index.ts 导入 GlobalDataProps 类型。特别注意：要在组件里使用 TS 的特性，script 必须加 lang="ts"，不加的话写 TS 会报错。建议大家以后创建的 vue 文件都加上。然后给 useStore 传泛型：

```typescript
const store = useStore<GlobalDataProps>();
```

再感受一下：点出来 user 和 templates 都出现了，自动补全又起作用了。刷新页面，数据没问题，现在数据是从全局 store 取出来的，而不是写死的静态数据。

## 用 PropType 约束组件 props

下一步：数据多了两个属性 author 和 copyCount，希望显示出来。改 TemplateList，地球人都知道怎么写，但有个让我很不爽的地方：没有自动提示。我希望所有数据都获得对应的类型，这已经成了我用 TS 后的代码洁癖。为什么没有提示？因为 props 里 list 声明的是 Array 构造函数，不是有类型的数组。list 每一项应该是 TemplateProps，所以引进类型：

```typescript
import { PropType } from 'vue';
import { TemplateProps } from '../store';

props: {
  list: {
    type: Array as PropType<TemplateProps[]>,
    required: true,
  },
},
```

大家想到的做法可能是类型断言，直接断言成 TemplateProps 数组，但会报错：vue 的 type 接受的是一个构造函数，不能把构造函数断言成数组类型。为解决这个问题，Vue 推出了 PropType，它接受一个泛型，把想要的类型传进去，就完成了类型转换。现在 item.author 和 item.copyCount 都有自动补全，一一添加上，组件就比较完美了，TS 特性用得淋漓尽致。

## 小结

这节课讲了三个知识点：全局 store 的创建以及和 Vue 结合的过程；在组件中怎样使用钩子函数拿到全局状态；怎样使用类型约束组件的 props。下节课让状态动起来，尝试更新整个全局 store。
