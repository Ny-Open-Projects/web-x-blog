上节课讲了 container 的概念和简单用法。在开始定制镜像（image）之前，还要解决一个启动容器时的重要问题：数据持久化。

从上节课可以看出，每次从镜像启动容器，等于启动了一个全新的虚拟空间。每个容器的空间是独立的，在里面创建、删除、更新都只发生在自己的空间里，多个容器不能共享或影响彼此的操作。这一方面是优势，另一方面我们希望有些数据能被持久化，不因为从一个特定 image 启动新容器就被抹掉。怎么办？这节课介绍一个新参数 `-v`，它是 volume 的简写，用来设定数据的映射关系：

```bash
docker run -d -p 81:80 -v <主机地址>:<容器内地址> nginx
```

前面是主机的地址，后面是容器内部的 path。

## 用 nginx 验证目录映射

先建一个文件夹 mount-nginx，里面放一个 index.html，内容是 hello world from outside。把它的地址映射到容器内的地址。nginx 默认页面的位置上节课进去看过，是 `/usr/share/nginx/html`：

```bash
docker run -d -p 81:80 -v /你的路径/mount-nginx:/usr/share/nginx/html nginx
```

启动完成后访问 81 端口，刷新一下，原来的默认 HTML 页面变成了自定义的 hello world from outside，说明映射成功。这个 HTML 例子很简单，用 Mongo 举例会更明显。

## 用 Mongo 验证数据映射

先启动一个 Mongo 实例（`docker run -d mongo`），它会自动启动 MongoDB 服务。进去看看数据库里有什么：用 `docker ps` 拿到 ID，再用上节课学的 `docker exec -it <id> bash` 进入容器，运行命令行工具 mongo，`show dbs` 可以看到里面完全是一个全新的数据库。

现在想让容器使用外部的数据库。照猫画虎，退出并把容器关掉，重新启动：

```bash
docker run -d -v /data/db:/data/db mongo
```

本机默认存放 MongoDB 数据的位置就是 `/data/db`，容器内也用这个位置。但回车后会报一个错误，意思是这个 path 在 host 当中没有被 shared，特殊路径没有被共享到，需要做一次配置：打开 Docker Desktop 的 Preferences，到 Resource 下的 File Sharing，可以看到列表里的地址（及其子文件夹）都可以被映射，但不包括 `/data/db`。点加号把 data 文件夹添加进来，Apply 并重启 Docker Desktop，再运行刚才的命令就不会报错了。

再进去验证：`docker ps` 拿到 ID，`docker exec` 进去运行 mongo，`show databases`，之前创建的数据库都出现了，说明容器内部直接使用了外部的数据库地址，工作成功。

## 数据卷 volume

每次手动输入地址比较麻烦，还可以创建数据卷 volume。volume 叫数据卷，可以供多个容器使用：它是一个特殊的地址，可以在容器之间共享和重用，对数据卷的更新不会影响镜像本身。

```bash
docker volume create mongo
docker run -d -v mongo:/data/db mongo
```

创建一个名为 mongo 的数据卷，映射时 `-v` 后面不再写路径，直接写数据卷名称，后面仍然接容器内地址。进到新容器内部，会发现还是一个空的数据库，因为它映射到了一个特殊的文件位置，目前为空。可以造一条数据验证：`show dbs` 后 `use test`，然后 `db.test.insert({test: 123})`，添加成功后 test 数据库就出现了。退出，把容器关掉，重新启动一个新容器进去看：test 数据库还在，之前添加的数据保留下来了，持久化成功。

## docker volume inspect

数据卷还有个对应的检查命令：

```bash
docker volume inspect mongo
```

能看到 Mountpoint，也就是数据文件的存放路径，数据库文件都存在这个文件路径下。但特别注意：在 Mac 和 Windows 系统中，inspect 出来的路径不是物理机器的真实路径，直接 cd 过去是找不到的。因为 Docker Desktop 启动时又包了一层虚拟机，Linux 下这里直接是真实路径，Mac 和 Windows 下面则是虚拟路径。

这节课搞清楚了 Docker 数据持久化的概念，这在后面的内容里非常有用：我们希望在应用每次更新重启的时候，数据库中的数据都可以持久化。
