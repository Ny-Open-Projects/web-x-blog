上节课写了测试用例，这节课来完成特性的实现。

## 调整组件结构

首先可以确定，这些修改都在 button 也就是上传区域的展示上，所以要把 slot 都添加到这个区域。由于 slot 中要展示不同的内容，目前的结构不太贴切，button 放在最外面。把结构略微修改一下：外面套一个 div，加一个特殊的 class 叫 upload-area，表示上传区域；disabled 去掉不需要了，然后在里面添加不同的 slot。

第一个是 isUploading 时的 slot，name 为 loading，默认内容是一个 disabled 的 button。第二个也很简单，什么都没有时的最初始状态，name 为 default，默认值也是一个写着"点击上传"的 button。

## 最后一项的上传数据

最后一个区域是难点。它什么时候展示？答案是：上传文件是一个数组，当数组最新一项（也就是最后一项）加载完毕的时候展示。需要绑定的数据是最后一项上传完毕后服务器返回的数据。这个数据目前还没有，所以要在 UploadFile 里新加一项 response，存原始返回值，类型是 any。然后在成功上传时赋值：success 回调里 `fileObj.response = resp.data`，这样数据就传递过去了。

当然我们还需要"最新一项上传完成的情况和数据"这个从原始数据派生出来的值，很自然用 computed。写一个 lastFileData：

```ts
const lastFileData = computed(() => {
  const lastFile = last(uploadedFiles.value)
  if (lastFile) {
    return {
      loaded: lastFile.status === 'success',
      data: lastFile.response,
    }
  }
  return false
})
```

取数组最后一项用 lodash 完成，非常方便：`from 'lodash'`（lodash es）导入 last 函数，调用 `last(uploadedFiles.value)` 得到 lastFile。如果 lastFile 存在，返回一个 object：loaded 表示它已经加载完毕，即 lastFile.status 等于 success；data 就是 lastFile.response。如果 lastFile 不存在（没上传过），直接 return false。最后把 lastFileData return 出去。

## uploaded slot

有了数据就可以添加最后一种也是最复杂的情形。先把这个 slot 写在 upload-area 里，name 是 uploaded，用 v-if 判断展示时机：lastFileData 存在且它的 loaded 属性为 true 时展示。展示时把属性绑定上去，之前在测试里约定的名称是 uploadedData，绑定 `:uploadedData="lastFileData.data"`，并给它赋一个默认值：什么都不传时默认渲染"点击上传"的 button，上传完毕后仍恢复到这个 button。

看起来写完了，运行测试：通过，完美。

## 补一个连续上传的测试

但我还有一点想优化的心思：用户再上传一张图片时，组件还能完美运作吗？第二次上传是否还能拿到正确的结果？所以在测试中多加一点逻辑，再上传一次验证。在最后一个测试用例里，给第二次调用返回一个新值（瞎改一个 xyz 的 url），然后把这个过程完全重新进行一遍：从 await 开始再 trigger 一次 change，第二次就会发送第二次 post 请求，断言结果等于 xyz url。运行发现，这个更复杂的测试用例可以通过，新加的用例应该没什么问题了。

最后一步，把 only 去掉，看看对之前的逻辑有没有影响，有没有 regression。运行后出现了一系列错误，之前的 case 全都 fail 了。原因是改变了整个组件的结构：之前测试里 `get('button span')` 拿的 span 标签已经完全消失了。把这些测试结构稍作修改，把多余的 span 删掉即可（上面一处、下面还有两处）。修改完毕，测试全部通过，绿色的 pass 又出现了。
