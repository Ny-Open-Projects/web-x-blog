在本地开发环境下把所有功能开发完毕后，正常的工作流程就剩最后一步：将应用部署上线，让所有人都能公开访问。完成这个任务需要两个流程，先说第一个：构建。JavaScript 本身不需要编译，JS 代码在浏览器中可以直接运行，但现代前端项目使用的开发源代码无法直接拷贝到服务器上运行，浏览器里真正运行的是经过特定工具转换过的代码，这些工具就是介绍过很多次的 bundler。Vue CLI 脚手架中使用的 bundler 是 Webpack。

应用在不同环境都要经历这个过程，而针对不同环境的转换有一些特殊的区别，所以先来了解开发一个项目所面对的几种环境。

## 几种环境

第一种是生产环境（production environment），一般有一个固定的 URL 供用户访问，对我们来说就是 OpsFlow.com 主站，并且支持 HTTPS。

第二种是我们日常编码的开发环境（development environment），也就是使用 npm run serve 启动、在 localhost:8080 访问的环境。

一般还有一个测试环境，夹在开发和线上之间。有的公司体量比较大，还会把测试分成 test 和 staging 两种。test 给测试人员使用，测试开发完毕后的功能是否好用；staging 叫预发布环境，一般和生产环境高度相似，通常是产品同学进行验收，看看开发是否按照需求完成流程、有没有没考虑到的问题。我们也有一个 staging 环境，在 OpsFlow 前面加上 test 前缀就能访问，它和生产环境非常类似。

## 生产环境与开发环境的区别

用一个例子帮助理解。设想排练一场话剧：开发环境就是排练过程，封闭或者说私人，允许修改、允许有各种瑕疵，你作为导演指挥每个人的配合，尽量做到最后的完美。所以开发环境主要是为了解决各种 bug，可以输出各种各样的错误信息，可以有各种各样的 console；保存的数据可能来自 mock server 或者你本地的后端；还有开发服务器供我们使用，提供 hot reload、自动刷新等便利功能，让开发更便捷；另外它不太关心静态资源的大小，最好提供最丰富的调试信息帮助程序员开发。

生产环境则是彩排结束、剧院大门敞开、观众买票入场、大戏如期上演。这个环境最好不要有任何差错，否则受罪的就是对你来说非常重要的观众。所以第一点，生产环境要非常稳定，这是最重要的原则；之前的错误和调试信息都不向用户展示，因为用户不关心，还可能泄露重要的安全信息；数据也要真正存储到线上数据库中。第二点，速度是第一要务，没有人想打开你的网站还要忍受静态资源和数据加载超过十秒。所以生产环境使用的静态文件，也就是 JS、CSS 以及图片，都需要尽可能合并和压缩大小到极限。

staging 环境的要求和生产环境完全一样，因为它就是生产环境的预览，但有细微差别：使用的后端服务很可能不一样，测试环境和线上环境的后端服务很可能部署在不同的服务器中。从代码中可以看到，main.ts 里有一个 baseURL 和 baseURL2，都是测试环境的地址；到真正的生产环境时可能是另外的地址。所以构建代码时需要一个特殊机制来区分两种不同的环境，让它采取不同的接口。

## 各框架对环境的适配

各种库和框架也会对这两种环境做相应的适配。先看主框架 Vue，官方文档中关于生产环境部署的介绍和我们的原则一致：开发环境下 Vue 会提供很多警告，帮你对付常见的错误与陷阱；但在生产环境下这些警告语句没有用，反而会增加应用体积，而且有些警告检查还有小的运行时开销。所以 Vue 针对不同环境有两份代码：更大更全的开发环境版本，和更小更精简的生产环境版本。不使用构建工具时，可以看到有两种 script 可以引入：开发版本包括完整的警告和调试模式；生产版本删除了警告，在 minify 和 gzip 之后只有 33.30KB。这么做的目的正是为了生产环境的两个目标：更稳定和更快速。

使用脚手架工具时怎样选择不同环境的代码呢？Vue CLI 把整个过程完全自动化：运行 npm run serve 时自动选择开发版本；运行 npm run build 时选择生产环境版本，并顺带做一些其他优化工作，之后我们会详细了解。

再拓宽一下思路，看 React 是怎么做的。它的文档 Optimizing Performance 里写道：React 默认包含许多有用的警告信息，在开发过程中非常有帮助，但这使得 React 更大而且更慢，所以要确保部署时使用了生产环境版本。它还提供 React 开发者工具，可以根据不同的图标提示你现在使用的是什么版本的 React。结论就是：开发时使用开发模式，为用户部署时使用生产模式。
