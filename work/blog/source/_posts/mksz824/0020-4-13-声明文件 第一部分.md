之前的内容中我们一直都在和 TypeScript 文件打交道。TS 是静态编译工具，最后可以帮我们生成对应的 JS 代码。但创建项目时会用到很多不是 TS 书写的库，假如在 TS 代码中使用这些模块会发生什么呢？

用一个大名鼎鼎的异步请求库 axios 来做例子，后面也会大量使用它。假如直接在 TS 中使用 axios，输入变量名称 axios 就会出现一道红线，报错了。这是肯定的，因为 TS 并不知道 axios 是什么东西、有哪些方法。需要一个方式告诉 tsc 编译器，这个变量到底是什么类型。这就需要这节课要讲的声明文件。

## 编写声明文件

首先创建一个声明文件。文件的名称无所谓，可以起任何名称，但后缀名有格式要求：必须遵循 `.d.ts` 的格式。这个 d 是英文 declaration（声明）的缩写。

特别注意，声明文件的目的就是给实际的业务逻辑代码提供类型，所以它里面没有任何实际实现逻辑的代码，只有类型声明，比如 interface、函数类型或 class 类型等。我说的 function 指的是函数类型，并不是函数的具体实现。每次看到 .d.ts 文件，心里都要默念一遍这个原则。

给 axios 添加类型声明。声明具体变量的类型要使用一个特殊的关键字 declare，declare 后面加变量名称。先学习最简单的用法：声明它是一个函数类型。写 function 加上函数名称，只要写函数类型就好，传参是 url，为了简单起见返回值定义为 string（真实的 axios 复杂得多，这里只是举例）：

```ts
declare function axios(url: string): string
```

写完类型文件后回到业务代码，错误就消失了。axios 已经有了对应的类型：有一个参数 url，可以传入字符串，能约束或提示我们的行为。

也可以把它改成另外的类型：不是 function，而是一个 object，上面有两个方法。先写一个 interface：

```ts
interface AxiosInstance {
  get(url: string): string
  post(url: string, data: any): string
}
declare const axios: AxiosInstance
```

interface 叫 AxiosInstance，有两个方法：get 请求返回 string；post 请求多一个 data 参数（因为要发送数据），返回也是 string。然后添加 declare const axios，类型是 AxiosInstance。这时原来的类型提示就变了：axios 变成了一个有两个方法的对象，get 有一个参数，post 有两个参数，会提示这里还有一个 data。

通过声明文件，我们在使用第三方库时也能享受 TS 的便利：自动补全、类型提示等。

还要注意类型的作用域。我们没有做任何特殊设置时，类型的生效范围是当前编辑器中打开的所有文件。把 .d.ts 文件关闭，类型错误又出现了，因为当前作用域中对应的定义消失了。之后我们会特殊设置，把类型文件都放置在某个文件夹中，这时就和文件是否关闭没有关系了。

## 第三方声明文件

写了这么多类型文件，大家可能有顾虑：使用第三方库时，是否要费力把它的定义文件一一书写？这么大的工作量会让人直接放弃。别着急，社区或官方早就写好了第三方声明文件。

打开 TypeScript 官网的一个 URL：TypeScript Language .org 下的 dt-search（文档中会提供）。在这个网站中可以搜索某个第三方库安装时是否需要安装对应的类型文件。市面上几乎所有的第三方库都能在这里找到，安装 Types 有两种情况：

1. **模块自带类型文件**：开发者开发时就写好了 .d.ts 文件，直接安装模块即可，这是最简单的。
2. **需要单独安装类型文件**：开发者写代码时没有写定义文件，需要单独安装 @types 前缀的类型文件，使用者才能享受类型提示。

比如 superagent，除了安装本体还需要安装类型文件。这些类型文件都以 @types 为前缀，与普通 npm 模块不同，@types 由一个专门的组织统一管理，意在为不同库提供高质量声明文件的社区。要把声明文件发布到 @types 名下，需要提交 pull request，包括类型声明文件、测试代码以及 tsconfig.json 等。查询发现 axios 只要安装一个就好：

```bash
npm install axios --save
```

安装完毕后使用它。注意 axios 是以模块方式存在的，并不是全局变量，需要 import 进来：

```ts
import axios from 'axios'
```

这时 axios 就获得了类型，是 AxiosStatic 类型，上面有一系列方法：get 有 url 参数，post 有 url 和 data 两个参数，还有第三个参数 config；它本身还可以以函数形式创建，第一个参数是 config，返回 AxiosPromise 等，都已经定义完毕。

再安装一个老朋友 jQuery。搜索可以看到 jQuery 本身不带 type，除了安装本体还需要安装 @types/jquery。这两个都安装完毕后，jQuery 和 axios 有些不同：它是一个全局变量，不需要以模块方式引入。直接输入 jQuery 就有对应的类型了，上面有一系列链式方法：get、hasClass、hide 等，大家可以自己去感受。

所以使用任何第三方库之前，都可以在这里搜索一下，看是否需要另外安装 types 文件，这一点非常重要。

## 类型文件如何被加载

除了之前说的作用域，node_modules 中的定义文件也会被自动加载，所以 jQuery 可以直接获得类型。你去 node_modules 下面看，会找到一个 @types 文件夹，里面有这些对应的定义文件。

最后教大家一招：对任何变量都可以去看它的定义文件。点击右键选 Go to Type Definition，或者按住 Control 或 Command 键点击，就可以跳到对应的定义文件，看 axios 到底有哪些方法、有怎样的配置。慢慢学习过程中大家会发现，会看定义文件对学习 TypeScript 大有裨益，之后我们会经常看定义的原始文件。

## 小结

这节课简单了解了声明文件的来龙去脉：写了一个简单的声明文件，讲了怎样安装第三方声明文件。特别注意有两类：一种不需要单独安装（模块自带），另一种需要单独安装 @types 文件。下节课再深入了解声明文件。
