上节课完成了移动图层的快捷键，这节课来处理编码过程中遇到的几个 bug。

## 第一个 bug：滚动条跟着方向键滚动

按方向键时页面滚动条会跟着移动，这是浏览器的默认行为，可以用 `event.preventDefault()` 阻止。逻辑应该写在 `useHotKeys` 回调的第一个参数，原生键盘事件对象上。

问题是 up、down、left、right 每个方向都要写一遍同样的逻辑，非常繁琐。解决办法是给回调函数再包一层，返回一个新函数，这就是高阶函数（Higher Order Function）。React 的 HOC（High Order Component）概念正是从这里来的。维基百科的定义是：高阶函数接受一个或多个函数作为输入（或输出）。它的实用价值就在于处理这种多处重复的回调逻辑。

创建一个 `wrap` 函数，入参是回调 `callback`，类型用 hotkeys-js 导出的 `KeyHandler`，返回一个参数完全相同的新函数：

```ts
function wrap(callback: KeyHandler): KeyHandler {
  return (e: KeyboardEvent, event: HotkeysEvent) => {
    e.preventDefault()
    callback(e, event)
  }
}
```

返回的函数参数必须和原回调一模一样：第一个是原生 `KeyboardEvent`，第二个是 hotkeys 自己定义的 `HotkeysEvent`。公共逻辑写在返回的新函数里，这里只有一行 `preventDefault`。当然这里还可以放更多共用操作，比如通过 `e.target` 判断当前焦点是不是 input，是的话就跳过快捷键处理等等。

写完之后在内部调用 `callback(e, event)` 返回即可，类型完全匹配。如果回调可能有不定量的多个参数，也可以用剩余参数加 `callback.apply` 的写法，但这里是特定情形，直接把参数写定就可以了。

代码虽然只有几行，思想很重要。现在把需要复用这段逻辑的地方都替换上：up、down、left、right 四个快捷键都套上 `wrap`；shift 相关的不是浏览器默认行为，不用处理。测试结果：把滚动条拖到下方，按方向键时页面不再跟着滚动，功能正常工作了。

## 第二个 bug：右侧添加组件属性不全

编辑器和右侧面板改版之后，左侧添加组件的流程可能有问题。点击添加「大标题」，进画布后发现它的属性残缺，很多属性都没有，样式也变成奇怪的样子；而且 `layerName` 没有设定，切到图层设置面板时直接报错。

第一步修 `layerName`。在 store 的 `addAction` 里找到 `addComponent` 的地方，单独加一个属性：

```ts
component.layerName = `图层${state.components.length + 1}`
```

希望新图层的序号是最后一个，所以取组件数组长度加一。

第二步是属性不全的问题。组件数据来自 `defaultTemplates`，它里面只有模板自带的属性。要做一次混入，把 OpsFlow 组件库的通用默认属性合并进去。从组件库引入 `textDefaultProps`，其中也有需要修正的属性：`position` 默认是 `static`，但画布定位需要 `absolute`；另外希望每一项有个宽度限制，不然显示太长不美观。直接复制一份默认属性做修正：加上 `width`，去掉 `position`。

然后对模板列表做一次 map：

```ts
export default defaultTextTemplates.map(template => ({
  ...textDefaultProps,
  ...template.props,
}))
```

先展开通用属性，再展开模板自己的属性，得到一份完整的新属性列表。由于改成了默认导出，editor.vue 里的导入路径报错，把原来的命名导入删掉保存即可。

这又引出新问题：列表里所有属性的 `position` 都变成了 `absolute`，左侧组件列表整个坍缩到了一起。给左侧展示加一条样式覆盖：`position: static !important`，让列表里显示正常，而添加到画布时依然用 `absolute`。验证一下：删除画布上的组件，重新点击添加，属性齐全、宽度 100px、样式正确，position 也是 absolute。

整个应用重新焕发生机，可以良好运作了。高阶函数这个特性后面还会多次用到，建议大家多看几遍这段内容。
