上节课完成了自动部署的第一步：把新建文件夹里的一系列文件拷贝到服务器。这节课完成拷贝之后的工作：登录服务器，成功启动应用。

## 步骤分析

在服务器上要按顺序完成这些工作：

1. 登录阿里云 ACR。这是特别容易被忽略的一步：我们要 pull 的镜像来自私有镜像源，必须先登录，和本地一样。
2. 进入拷贝的文件夹（上节课说过可以按自己的意愿命名，这里叫 opsflow-backend）。
3. 停止服务：`docker compose down -f <文件名>`。这里有两种情况：第一次运行没有启动任何服务时，执行它不会报错；之前已经运行过时，它就会停止服务。所以这个命令可以适用两种情况，不会 break 整个流程。
4. 启动服务：`docker compose up -f 对应文件`。
5. 最后做一些清理工作，主要是为了安全：删除 .env 文件、docker logout。这两步也是为安全服务的，即使黑客登录了我们的服务器，也拿不到这些敏感信息。

## 编写脚本

在 deploy.yml 中接着写：

```yaml
      # 通过 SSH 登录，然后重启服务
      - name: Executing SSH and restart Docker
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.HOST }}
          username: ${{ secrets.USER }}
          password: ${{ secrets.PWD }}
          script_stop: true
          script: |
            docker login --username=${{ secrets.ACR_USERNAME }} --password=${{ secrets.ACR_PASSWORD }} registry.cn-hangzhou.aliyuncs.com
            cd ~/opsflow-backend
            docker compose -f docker-compose-online.yml down
            docker compose -f docker-compose-online.yml up -d
            rm -rf .env
            docker logout registry.cn-hangzhou.aliyuncs.com
```

用的是 appleboy 出品的另一个 SSH action，参数和上节课的基本一样（都是完成一系列远程操作，非常相似），可以直接复制。多加了 `script_stop` 参数：如果 script 出错，自动中断后面的一系列过程。script 多行用竖线语法，多行没法写注释，把注释写在上面看得清楚。

逐行看 script：

- 登录：runner 上用的是 ACR login action，但服务器上没法用任何 action，直接用原生命令就好。`docker login` 接 `--username` 和 `--password` 两个参数，值都来自 secrets（请大家自己去创建），最后跟上 registry 地址（cn-hangzhou），就能完成登录。
- 用波浪线进入本人的文件夹，再进入 opsflow-backend。
- 停止服务：`docker compose -f docker-compose-online.yml down`，第一次启动和再次更新都适用。
- 启动：命令和前面一模一样，把 down 换成 `up -d`，后台运行。
- 清理：删除 .env 用 `rm -rf .env`；docker logout 时特别注意，命令后面要跟上你要登出的 registry 地址才行。

一个教训：这里我写错了一个参数（username 写成了另一个形式），第一次 push 出错，修改后重新 push 才成功。workflow 经常出现这类小问题，参数一定要写对。

## 运行验证

commit（test deploy step two）后 push。push 成功后看结果：完全成功，Deploy and restart 变绿。看每一步，最关键的是最后一步：输出里有 stopping、creating 的过程。然后线上验证：访问 ping 接口，应用已成功启动；env 显示的是我在 GitHub secrets 里添加的环境变量，证明这次部署确实是通过 GitHub Action 完成的。再看 templates，初始化数据也能成功创建，说明初次部署完全成功（之前我们把服务器上的数据都删了）。

到服务器上看文件：opsflow-backend 在这里，查看所有文件会发现 `.docker-volumes` 已经创建了，这是只有初始化数据库时才会创建的文件夹，说明第一次初始化数据库也成功了。

现在应用可以成功部署到一台全新的服务器，第一次部署或更新都没问题。大家可以把这个 job rerun 一次，模拟更新的过程，看看 job 会不会出问题；甚至可以用这一个 workflow 部署到多台机器，非常方便。

两节课跑通了整个流程，但流程还没合二为一。最终的流程应该是：提交代码，根据提交信息 build 镜像，复制必须的文件到对应的服务器，登录服务器完成启动。接下来的课程把步骤完全融合在一起，让一次完整的自动部署成功运行。
