之前演示的泛型都作用在函数中，在函数的参数和返回值里使用泛型。这节课看看泛型在其他方面的使用：类和接口。

## 泛型类：先抛出问题

新建一个队列类，实现两个方法：进入队列和离开队列。队列是先进先出的数据结构。创建一个 Queue 类，其中有一个存放数据的数组，加 private 修饰符，因为它是内部私有的。一开始我们做得最简单，data 暂时写成 any 数组：

```ts
class Queue {
  private data: any[] = []
  push(item: any) {
    this.data.push(item)
  }
  pop(): any {
    return this.data.shift()
  }
}
```

第一个方法 push，操作 this.data.push 把 item 放进去；第二个方法 pop，调用数组上的 shift 把值拿出来。

用这个队列做一些事：初始化一个新队列，调用 push 插入数字 1，再创建变量 popped 调用 pop 拿出来。因为拿出来的数据可能是 undefined（队列里没有值时），所以先判断它存在，再调用数字类型上的方法 toFixed。

这段代码存在一个问题：我们允许向队列中添加任何类型的数据，没有任何约束，data 是 any 类型，数据被弹出时也是 any。假如向队列中添加 string 类型的数据，TS 并不会发现任何错误。但实际结果是这样吗？把代码运行起来：tsc 编译后调用生成的 JS，会抛出错误 pop.toFixed is not a function，运行时错误才暴露出来，而 TS 层面完全没有捕捉到。这是代码写得有缺陷：写成了 any，所以任何类型都能放进去。

## 最笨的解决方案与泛型类

最简单的解决方案是为队列创建特殊类型，比如 data 设置成 number 数组，这样就能捕捉到错误：插入 string 时会提示错误。但快速也意味着痛苦，假如想创建一个可以插入字符串的队列，就得再修改一大堆代码。

我们真正想要的是：不论什么类型被推入队列，推出的都与推入的类型一样。这样既省去大量时间，又能获得对应的类型。这时候应该让泛型来帮忙：创建一个泛型类。之前是在函数名后面加尖括号，现在是在类名后面加尖括号：

```ts
class Queue<T> {
  private data: T[] = []
  push(item: T) {
    this.data.push(item)
  }
  pop(): T | undefined {
    return this.data.shift()
  }
}
```

泛型称为 T，把所有需要的地方一一加上：数组中的元素是 T 类型，推入的类型也只能是 T。这时候就没有对应的错误了。

验证一下修改后能否获得类型信息：实例化时传入 number，插入 string 就会报错，只允许 number 类型。改成 1 以后，popped 的类型是 number 或 undefined，调用 toFixed 没问题。换成 string 类型时，这里会帮你捕捉错误，因为 popped 是 string，没法在上面调用 toFixed。经过改造，TS 既能帮我们快速获取类型，也能帮我们捕捉错误。

## 泛型接口

类可以用泛型描述，interface 接口经过泛型的洗礼也可以更灵活。定义一个 interface 叫 KeyPair，对象中有两个值：key 和 value，两者在使用时动态传入。给 KeyPair 添加两个泛型，位置和 class 一样放在名称后面，一个称 T、一个称 U，key 传入 T 类型，value 传入 U 类型：

```ts
interface KeyPair<T, U> {
  key: T
  value: U
}
```

定义类型时就可以动态定制：第一个 kp1 希望 key 是 number、value 是 string，就写 KeyPair<number, string>，然后 key 是 number、value 是 string；第二个 kp2 变化一下，KeyPair<string, number>，前面是 string，后面是 number。

其实之前学过的数组类型定义也是这样表示的。定义 number 数组很简单：number 加方括号，比如 [1, 2, 3]。现在用泛型的写法，叫 arr2，类型是 Array<number>。Array 是 TypeScript 内部定义好的一个 interface，上面定义了数组的各种方法和属性，通过泛型传入数组元素的类型。这里希望是 number，就只能传入 number，传入 string 时会报错。

这就是 interface 搭配泛型后，可以灵活地返回不同的类型。

## 三节课的总结

通过三节课我们简单介绍了泛型的用法。对 TS 最难啃的这部分，还需要更多实践才能更好地掌握，但这几节课应该能掌握它的基本用法。从后往前总结它解决的问题：

1. 泛型在类和接口上的使用：创建特定类型的容器，仿佛给容器贴了一个标签。拿 Array<number> 举例，它告诉你这是一个装满数字的数组；告诉一个类，我希望这个类里面装着数字的队列。甚至可以把它想象成可变参数，使用时传入，生成不同的容器。
2. 上节课讲的约束泛型：更灵活地约束参数的类型。参数不需要是特别死板的 string 或 number，而是必须具有某某属性某某方法，否则报错。
3. 第一节课讲的函数泛型：函数的类型推论不会流入函数体内，表达式没法明确建立类型的绑定，用泛型可以打破这个鸿沟。
