作为一个程序员，我完成了老大给的第一个任务：上传组件的基本流程已经完成，可以把文件成功传到远程服务器。这节课在展示上下点功夫，即进度表中的第二个任务：展示上传文件列表。

## 交互需求

除了上节课的基础内容，界面下方增加了一个列表，列表条目会根据上传状态做出不同的改变：上传中有 loading 效果，上传成功或失败时用不同的 class 指示状态，暂时定为灰色、绿色和红色。同时按钮文字会变化：上传中时按钮状态为只读（disabled），防止上传过程中再次触发选择文件；上传成功以后不显示"上传成功"，而是恢复到最初的"点击上传"。还有一个更深入的需求是显示上传进度条，留待完成最基础的内容之后再处理。

对于这个需求，我决定用 TDD 的方式开发。在 uploader 组件的开发过程中，我会交替使用普通开发和 TDD 开发，让大家真正感受不同开发方式对写代码过程的冲击。

## 补充第一个测试

先把要测的东西列出来。在第一个 case 中做补充：上传时 button 应该是 disabled 的。断言用 `wrapper.get('button')` 拿属性，这里使用 vtu 提供的 attributes 方法，传入属性名 disabled，断言 `toBeTruthy`。

接下来列表长度要增加，并且条目有正确的 class，这就需要在 DOM 结构上做一些假定。文件列表结构我简单定了一下：因为是列表，外层是 ul，每一项是 li，根据状态有不同 class，upload-loading（上传中）、upload-success 或 upload-error。每一项里左侧是 file-name 显示名称，右侧是 delete-icon，点击 delete 可以删除该条目。

有了 DOM 结构就可以写判断了。断言 li 的长度：`expect(wrapper.findAll('li')).toHaveLength(1)`，现在只有一条。然后取第一个条目判断 class：用 `wrapper.get('li')` 加上 first-child 选择器拿到第一项。查找 class 这次不用 DOM 节点的 classList，而用 vtu 提供的 classes 方法，它返回元素上 class 的数组（内部也是通过 classList 拿到的）。判断数组中是否含有某一项，用 JS 的 toContain，这里希望含有 upload-loading 这个 class。

## 借鉴 React Testing Library

flushPromises 之后文件上传完毕，先断言 class 从 upload-loading 变成了 upload-success。再判断文件名称是否对应上传文件的名称：取 firstItem 下 class 为 file-name 的元素，断言 text 是 test file。

在判断 file name 时，我其实用了一个比较别扭的逻辑：从测试和用户的角度看，断言的意义应该是看"test file"这样的字符是否出现在整个界面上，而不是判断 file-name class 节点下的文字内容是否等于 test file 的 name。假如有 getByText 这样的方法就贴切直观多了。这也是另外一个测试库的编程思想，React Testing Library，现在比较火，也是 React 官方推荐的默认测试库。它的核心理念是：测试用例越接近真实的场景，就越能给代码带来更多自信；与其一直操作不同的 React 组件，不如操作真实的 DOM 节点。它提供了很多反映真实用户操作的方法，比如通过 label 文本查找表单元素、通过按钮文字查找元素等。它的 querying API 包括 getByLabelText、getByPlaceholderText 等，都很接近用户的操作习惯。

这里只是把它当作一个扩展例子，感兴趣可以研究一下，它也提供绑定 Vue 的测试工具。测试工具用到一定程度时要多对比它们之间的差异，才能有不同的收获。React Testing Library 其实是从另一个角度来写测试用例。

## Error 流程和删除功能

接下来写 error 的过程：error 之后同样要增加一项，断言列表长度比原来多一项（toHaveLength(2)），并且列表最后一项有正确的 class。取 lastItem：`wrapper.get('li:last-child')`，判断方式与刚才相同，断言 classes 中 toContain upload-error。

最后一项测试：点击列表右侧的 delete-icon 时删除这一项。用 await 让交互完成：`await lastItem.get('.delete-icon').trigger('click')`，然后断言 `expect(wrapper.findAll('li')).toHaveLength(1)`，说明这一项被删除了。

测试用例就写到这里。有了它，下节课就可以开始 TDD 大法，去完成这个需求的代码，看看这样的流程是否 work。谢谢大家，下节课见。
