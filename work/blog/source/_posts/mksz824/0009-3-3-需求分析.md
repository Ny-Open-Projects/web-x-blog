上节课分析了什么是心目中的复杂前端项目，所以在选项目时，三位老师绞尽脑汁。市面上大量课程都是 demo 类型的项目，某某商城、某某专栏、某某微博，都没法满足需求。最后经过头脑风暴，我们决定挑战一下自己，做一款可视化编辑器。

这个编辑器可以生成 H5 页面或海报图片，是现在特别常见的需求，市面上也有一系列同类型产品。生成的作品可以在微信中传播，可以把链接分享给朋友或朋友圈，也可以直接分享图片，整体是一个功能闭环。我们的 B 端占据其中一部分，也就是这个复杂项目：它是展示给用户的最主要产品，负责作品的创建、管理、展示等功能。

## B 端在架构中的位置

之前的课程已经分析了整个项目的需求和架构，得出了整体架构图。这里把需求圈定在作品管理前端这个项目中，其他项目暂不考虑。

从图中可以清楚看到 B 端的位置：它面向运营人员或普通用户，用来创建、管理和编辑作品。创建完毕后可以发布和预览，之后在 H5 端展示和分享。同时它还有另一条功能线，可以在页面中查看统计数据。

所以 B 端需要两个 API 服务支撑，正好对应这两大功能线：一是作品管理的服务端，提供作品的增删改查等操作；二是统计服务的 Open API，提供作品统计数据。它们都以 RESTful API 的形式和 B 端对接。

## 页面与功能

原型图、UI 设计稿在语雀文档里都有，包括管理后台需求、B 端需求和单独拆出来的编辑器需求，文档会持续更新。这里我直接用做好的 OpsFlow 网站作为原型演示，把它看成高保真原型，从中提炼需求。我不会像 PM 开需求会那样冗长，只简单列出要点，毕竟没有程序员喜欢需求文档会议，大体了解做什么即可。也希望大家自己去网站逛逛，发现一些亮点。

**首页**。最上面是导航条，有两个状态：未登录时显示登录按钮；登录后变成已登录状态，出现创建设计、我的作品按钮和一个下拉菜单（个人设置、登出）。往下是热门海报列表，每一项包含海报图片、标题，左边是作者信息，右边是使用人数，hover 上来会显示"创建"按钮。列表下面还有搜索功能：搜索"前端"后，标题会变化并多出一个清空按钮，点击清空回到原始界面；再往下有"加载更多"按钮，点击加载更多海报，每页只展示八条。热门海报区域之后是我的作品区域，展示自己创建的作品，只展示四条，右侧有链接可跳到自己的作品页面。

**登录页**。很简单，一个表单两个 input：填入手机号，点击获取验证码，提示验证码已发送，填入验证码后点击登录。注意这里有一个隐藏需求：两个输入项都需要表单验证，手机号还要匹配号码格式。

**模板详情页**。从首页点击海报的创建按钮进入。页面比较简单，主要展示信息：完整的图片、标题、描述、作者信息、一个二维码，以及两个按钮，点击"使用模板"进入编辑器，点击"下载图片海报"下载一张图片。

**我的作品页**。和首页列表类似，但多一些功能。首先有一个 tab 分割"我的作品"和"我的模板"，这是作品的两种不同表现形式。作品卡片上有编辑功能，hover 上去还有更多操作：复制作品、删除、下载图片、转赠等。我的模板略有不同：hover 显示的是"继续编辑"，还有一个显示二维码的操作，并且模板有统计功能，点进去会展示统计图表，同样有搜索和翻页。

**编辑器页**。这是项目最重要的部分，分为左、中、右三个区域。左侧是组件面板，预设了三种组件：文本、图片和形状，点击某个组件就会往中间画布添加对应元素。中间是编辑器画布，功能很丰富：点击可以选中元素，拖动能改变位置，拖动四个角可以改变大小，还支持一系列快捷键，比如复制图层、Delete 删除图层，点问号能看到所有快捷键操作。可以点击回退做撤销。除快捷键外还有右键菜单，算是快捷键的另一种形式。

右侧是元素属性面板。选中元素后可以看到非常多的属性，实现时再详细讨论，并且属性修改是实时反馈到中间画布的。属性面板中还有图层设置：可以设置图层的隐藏和显示、锁定和解锁，可以拖动排序。右侧最后是页面设置，可以设置背景颜色、更换背景图片。

顶部有三个按钮。第一个是保存，点击后保存作品。第二个是预览和设置，点击后左边出现手机壳内的预览，右边可以扫码预览、上传封面、设置标题和副标题等。第三个是发布按钮，点击后稍等片刻会弹出发布成功的提示框，左侧显示作品截图，右侧显示默认的渠道。渠道可以添加、删除，只有一个渠道时不能删除，还可以发布为模板。

此外还有一些不属于界面上的功能，比如定时保存（隔几秒自动保存一次）、退出前提示（"作品还未保存，是否保存？"）。

## 难点伏笔

大体的需求就这些，再讲下去大家要昏昏欲睡了。根据刚才的内容可以列出不少功能点。这些功能点中，有些是不加思索就能想到解决方案的，比如显示一个模板列表；有些是稍微思索就能得出结论的，比如点击"加载更多"显示更多列表；有些则是一下想不到解决方案的，比如怎样展示元素的属性，并且修改时实时反映到编辑器中。

从庞杂的需求里抽象出项目难点并攻坚，是需求分析中架构师角色特别注重的能力。下节课就带大家从需求中寻找项目难点，或者说卡脖子的技术要点，看看我们能找到哪些技术难点。
