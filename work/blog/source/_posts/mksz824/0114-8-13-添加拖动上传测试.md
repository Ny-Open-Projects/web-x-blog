上节课完成了 drag and drop 的开发工作。这个特性其实不难，主要是掌握三种类型的事件，以及 drop event 这个特殊的事件对象可以从 dataTransfer 中拿到对应的 file。

对于特别重 UI 的功能，可以使用"先编码、手动测试、再补充单元测试"的做法。后面的课程也会有类似的功能，比如编辑器中元素的拖拽、改变大小和位置，就是典型的场景，写再多的单元测试也需要手动测试，这种情况下手动测试比单元测试更准确。所以要学会对不同类型的功能区别对待。

## 手动测试

为了让拖拽功能更直观，需要添加一些样式。我在主页中添加了一系列 CSS，主要让它显示一个比较大的拖拽区域，并且 is-dragover 这个 class 启用时有一个 2px 的 border 效果，背景色也会改变。同时记得把组件上的 drag 属性打开。

试一下：渲染出一块比较大的区域后就可以开始拖拽了。从桌面上找一个图片文件，放上去后区域会添加 is-dragover 这个 class，拖出去后 class 消失，dragover 和 dragleave 就是这样的效果。再测试 drop：放到区域里松开鼠标，文件立刻上传完毕（上传很快），并且因为有自定义区域，显示了自定义的样式，上传的文件也显示在列表里。手动测试完成。

## 单元测试

要测试的内容之前已经从三个方面分析过了：第一个 case 是 dragover 和 dragleave 要添加或删除对应的 class；第二个 case 是 drop 相关，拿到正在被拖拽的文件，删除 class 并触发上传。

打开测试，给 case 添加 only：testing drag and drop function。空 case 目前是通过的，开始写第一个逻辑。触发区域是 class 为 upload-area 的元素：`wrapper.get('.upload-area')`。然后触发两个事件并断言：

```ts
uploadArea.trigger('dragover')
expect(uploadArea.classes()).toContain('is-dragover')
```

再复制一份测试 dragleave，把断言换成 not.toContain。保存运行，第一个 case 通过。

## 触发 drop 事件的关键

接下来触发 drop 事件。它很特殊：除了事件本身，还有一个特殊的事件对象。这个情形似曾相识，最开始给 input 设置 file 时，我们在最上面写了帮助函数 setInputValue，用比较 tricky 的 Object.defineProperty 给 input 设定了 files 属性。现在遇到 dataTransfer 怎么办？求助文档。

文档在 trigger 一节写道："is not possible to edit the target value of event object"，意思是 target 对象没法被编辑，想给 target 添加新值需要拿到元素本身，在 trigger 之前赋值。我认真读了几遍，发现它说的是 target 没法赋值，但事件对象上除了 target 还有很多其他属性，dataTransfer 就是其一。那 dataTransfer 应该怎样赋值？

这时候我想到有了 TS，代码就有了注释。点进 trigger 方法的定义文件：它有两个参数，第一个是 event string，第二个是可选的 options，这很有意思。继续跟踪 TriggerOption 这个 interface，里面有一系列事件对象上的常用属性，还看到一个完全可自定义的类型。看起来第二个参数就可以给除 target 以外的事件属性赋值。

为了确认，回头再看文档，这次我注意到，之前查文档时直接拖到最下面只看了 event target 那一段，但文档最上面写得很清楚："trigger takes an optional options object, properties in the options will be added to the event"，即 options 里的属性会添加到 event 上。第一次看文档应该从这里看起，而不是直接找要解决的问题的那一段。这样遇到问题时就能清楚 API 该怎么用了。

现在就可以在 options 里添加想要的对象了。写法是：

```ts
await uploadArea.trigger('drop', {
  dataTransfer: {
    files: [testFile],
  },
})
```

drop 事件触发后，测试正常的逻辑即可：post 应该被调用（toHaveBeenCalledTimes(1)）；然后 await flushPromises，promise 结束后列表中多了一项，`wrapper.findAll('li').length` 等于 1，文件上传成功。因为我新开了这个 case 避免与其他测试冲突，计数从零开始。保存运行，测试完美通过。

最后把 only 去掉，测一下有没有 regression，全部通过，drag and drop 的开发和测试就完成了。

这节课还有一个目的：让大家了解怎样通过 TS 和文档找到正确完成功能的方法。刚才演示了这个过程，另外阅读文档要细心，不要只找到要解决问题的那个点，而是把文档从头到尾看一遍。我之前就犯过这个错误，重新读以后才知道这个 API 究竟怎么用。这节课到这里，谢谢大家。
