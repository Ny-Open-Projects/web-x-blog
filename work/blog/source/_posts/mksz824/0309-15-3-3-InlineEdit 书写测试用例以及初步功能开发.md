上节课完成了图层列表以及锁定、隐藏和选中的功能，这几个都没有特殊难度。这节课来完成图层的重命名。这个任务本身并不困难，而且可以抽象成一个全新的组件，这是一个非常常见的组件，很多场景下都需要这样的功能。

## InlineEdit 的需求

这个组件叫 InlineEdit，需求总结如下：

- 一开始显示为一个文本节点，显示默认的文本；点击这个区域时切换成 input，并且 input 中的值就是文本中的值。
- 更新值之后的一系列事件。第一个是键盘事件，这里会抽象出一个 hook 方法，叫 `useKeyPress`：按 Enter 时恢复为文本区域，并显示已更新的值；按 Esc 时恢复为文本区域，但显示刚开始的旧值，而不是更新后的新值。
- 第二个关键事件是点击外侧：更新值以后不按任何键盘事件，直接点击 input 区域外侧，也会恢复成文本区域，并显示更新后的值。为此可以抽象出另一个 hook 函数 `useClickOutside`，监测是否点击到了这个区域之外。
- 最后还有简单验证：当 input 值为空时不恢复，并显示错误提示，要求用户必须通过验证。这里只加一条简单规则，想扩展更复杂的规则可以自己去做。

## 为什么适合 TDD

有了需求以后，我们发现它特别适合测试驱动开发。之前的课程为了硬性讲测试知识点，有些组件其实不适合写单元测试我也硬要写，顺便讲了它们的测试方法。而这里，需求本身就直接构成了一条条 case。

用测试来覆盖这些需求，不需要每次都在本地开发服务器的页面上点点点，速度快很多。而且对于这种渐进式的开发方式，后面需求越来越多时，不用担心 regression，也就是添加新功能时把旧功能搞坏。

我的编程理念是实用主义：不搞硬性规定，对编程过程有利的方式就去使用。对测试，希望大家也抱同样的态度。

## 前两个需求：测试与实现

这节课先完成前面几个需求，从测试写起。第一个需求非常简单，我把测试和实现直接都写出来了。

新建一个组件 InlineEdit，接受一个属性 `value`，就是要显示的内部值。第一个需求的测试：组件要显示这个值，暂定它渲染成 span，`wrapper.get('span').text()` 应该等于传入的文本。

第二个需求的测试是 "should render input when clicking the element"：点击 wrapper 时应切换成 input，所以断言 `wrapper.find('input').exists()` 为 true，并且 input 的值和最初传入的 value 相同。这个测试用例完美描述了整个过程。

实现大家都会写：在 InlineEdit 最外层绑定 click 事件，注意加一个 `.stop` 停止冒泡，不影响外层元素的点击事件；创建响应式对象 `isEditing` 表示当前是否在编辑，点击后切换为 true；再创建一个响应式对象存放内部值，初始为传入的 value，把 input 的 `v-model` 绑给它，值就可以随 input 的修改而更新了。这个内部值现在还没用到，等实现更新逻辑时才有关系。

此时测试可以完美通过。测试用例就是从用户真实操作的角度出发描述真实场景。

## Enter/Esc 的测试用例

下面写后两个测试用例：测试 Enter 和 Esc 触发不同的行为。

第一步是更新值：用 async/await，`await wrapper.getInput().setValue('test new')` 完成更新。

第二步是按 Enter 或 Esc，这需要发出一个键盘事件。这里可能让大家犯难。我特别理解大家不愿意写测试的原因：经常遇到不会写的 case，很沮丧，可能就在这里半途而废。写测试就是这样，当你把所有问题都趟平了，写起来就非常容易。这节课我就带着大家摸着石头过河，把这些 case 都趟平，希望趟过这些门槛以后，大家能在编程生涯中真的用测试帮助自己。

回到问题：怎样触发事件？你可能想到 wrapper 的 trigger 方法，但注意，我们的实现希望后期通过一个通用的 hooks function 完成任务，所以最好不要和某个特定的 wrapper 或 DOM 绑定，而是用全局通用的触发方式。

## 用程序触发全局事件

这就要求助文档了。学 HTMLImageElement 的时候给大家留过作业，分析 Event 家族的对应关系。Event 表示 DOM 中出现的事件，它的触发方式有三种：一是用户触发，比如鼠标或键盘事件；二是由其他事件或 API 生成，比如动画完成、视频被暂停等；三是通过脚本代码触发，比如调用 `HTMLElement.click()` 触发 click 事件，或者定义自定义事件，再用 `dispatchEvent` 方法触发。

第三种就是我们要的。触发事件要先创建事件对象。这里需要 `KeyboardEvent`，它描述键盘交互，每个事件描述用户对一个按键的单次交互，正是我们要的事件对象。它是一个 interface，同时也是一个构造函数。构造它：

```ts
const event = new KeyboardEvent('keydown', { key: 'Enter' })
document.dispatchEvent(event)
```

构造函数第一个参数是事件名称，这里叫 `keydown`；第二个参数是一个 `KeyboardEventInit` 字典，包含 keyCode、location、key 等字段。`key` 是字符串类型，表示按的是哪个键，每个按键对应不同的字符串，回车就是 `'Enter'`。

事件创建后，在 document 上调用 `dispatchEvent` 把 event 传进去，就完成了全局触发事件的过程。这是本节的核心知识点，请记住，以后再遇到就知道怎么办了。

触发完以后要特别注意：事件调用是异步的，需要等 DOM 更新。之前我们用 `await trigger(...)` 这种方式，而 `document.dispatchEvent` 不返回 promise，所以要用之前用过的 `nextTick` 等待 DOM 更新，我已经从 vue 导入了它，直接 `await nextTick()` 即可。

## 断言

更新完毕后写断言。首先是回到之前的界面：`wrapper.find('span').exists()` 应该为 truthy；然后里面的值是新的值：`wrapper.get('span').text()` 应该等于 `'test new'`；最后还要确认它发送了 change 事件通知外界：先拿事件数组 `wrapper.emitted('change')`，事件名和之前保持一致叫 change，然后 `expect(emitted[0]).toEqual(['test new'])`，发送出去的值就是新值。

这样这个 case 就写完了。Esc 的 case 和它几乎完全一致，大家自己去写。

别看这么简单的两行代码，其实富含的知识点很多：怎样用程序触发一个事件。我争取做到在这些看起来平淡重复的需求中，一直带给大家新鲜的知识点，让大家不要陷入疲惫无聊的持续 coding 状态。
