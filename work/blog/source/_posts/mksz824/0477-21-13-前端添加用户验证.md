给后端添加了身份验证之后，是时候在前端完成验证了。这节课有三个任务：

1. **修改 currentUser 的数据结构**：它应该和后端返回的数据更接近，不只是保存一个 username，而是把返回的数据悉数保存。现在的结构是之前测试用的，已不适合现在的数据系统。
2. **修改每个路由的验证机制**：管理系统里任何页面都应该登录后才能访问，所以需要一个中间件保护所有页面，登录页和注册页除外。
3. **持久化登录状态**：现在的状态登录成功后只保存在本地的 currentUser 里，刷新页面就消失，这不合理。用户登录一次后，登录状态应该和 JWT、Cookie 的过期状态相辅相成，之后的访问可以自动完成登录。

这节课先完成前两个任务，都比较简单。

## 改造 currentUser 类型

先看 currentUser 的数据结构，它的类型来自 types 里定义的接口，点过去可以看到现在只有 isLogin 和 username。而我们在 server 的 model 中已经存放过用户数据的详情，直接拿过来用即可。

model 里的 interface 叫 UserProps，和我们这里的名称完全重合，先改名为 `UserDataProps`（你也可以用更喜欢的名称）。顺手修一个小问题：时间格式 CreatedAt 和 UpdatedAt 应该是 string 类型而不是 Date 类型。

改完这两处，回到 currentUser 的定义。从 server 导入类型：`import type { UserDataProps } from '~/server/models/user'`，原来的旧类型完全没用了可以删掉。结构改成两项：isLogin 是判断是否登录的状态；另一项是 data，类型是联合类型：登录完毕后获取到数据，登录之前是 null：

```ts
const currentUser = useState<UserDataProps | null>('currentUser')
```

保存后会出现一些类型错误，一一修改：初始化时给 data 加上默认值 null；login 里原来是设置 username，改成 `currentUser.value.data = result`，错误消失；global header 里原来直接在 user 上取 username，已经不存在了，应该改为在 data 上取 username。保存，第一个任务完成。

## 全局中间件保护路由

第二个任务：修改每个路由的验证机制。管理系统里除了登录和注册这两个页面，其他页面都要先登录才能访问。在每个页面里通过 definePageMeta 添加中间件太繁琐，用全局中间件更贴切：在全局运作，把不需要权限的路由排除出去就好。

重命名中间件文件，加上 `.global` 字样，它现在就是全局中间件了。逻辑里排除两个路由：`to.path` 是 login 或 signup（管理系统本没有注册页，这里只是为了让大家练手添加的），这两个路由不做检查，直接 return。

看一下结果：直接访问 localhost:3000，会跳转到 login 页面，因为我们没有任何权限；其他路由也一样，比如 user one 也跳到 login。走一遍流程完成登录：输入 viking@test.com，密码六个 1，点击登录，成功跳转到首页，username 显示正常，路由可以访问；点击其他路由，中间件触发但已有登录状态，都能正常访问，home 也没问题。

第一个和第二个问题解决了，剩下第三个最重要的问题：持久化登录状态。现在登录完毕、cookie 其实也生成了，但一刷新就回到 login 页面。下节课一起解决这个问题，并学习一些新知识。
