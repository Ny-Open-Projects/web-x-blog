上节课说到路由，自然会想到和路由相关的一系列内容。第一个是导航。Nuxt 提供了非常方便的全局组件 NuxtLink 来完成这个工作。对 Vue Router 熟悉的话看到它会很亲切，它其实就是 router-link 全局组件的一个变种，在其上做了一些简单扩展，很好理解。

在 app.vue 中添加一个头部导航，放在 div 下面，这样所有路由都会包含这个导航。这里有两种类型的导航：NuxtLink 的内部导航，跳转到页面里定义好的路由；以及外部导航，比如跳转到 nuxtjs.org 的文档页面，需要添加 external 属性，告诉 NuxtLink 这是一个外部链接，这种情况下它会转换成一个 a 标签，工作原理和内部导航完全不一样。保存后导航出现了，点击任何页面都可以跳转，点击外部链接也能到达需要的文档页面。

除了通过组件导航，还有另外的需求。一是获取链接的信息，比如上面的参数、query 等；二是通过程序动态完成导航，也就是不点击链接，而通过一个 function 完成跳转。在 Vue Router 中有两个 composition API 完成对应的工作：useRoute 和 useRouter，非常常用。Nuxt 把它们原封不动地拿过来，做成了全局 composables，不需要任何导入直接使用。

演示一下。在动态匹配的路由里，希望拿到对应的 ID。创建 script（使用 TS），用熟悉的 useRoute 拿到 route，它上面有一系列属性，其中 parameters（route.params）可以拿到一系列参数：

```ts
const route = useRoute()
console.log(route.params.id)
```

特别注意名称要一一对应：文件里叫 id，这里自然也是 id。更多的属性比如 query 等，大家可以查文档。刷新后，User Detail Page 显示 2 就输出 2，显示 1 就输出 1。useRouter 动态跳转就不再演示了，很简单，之前课程用过很多次。

接下来介绍关于 routing 的一个新内容，也是 Nuxt 中的全新概念：中间件 middleware，算是一大创新。写后端的对中间件都很熟悉，比如在 OpsFlow 后端的 Nest.js 中就多次使用过。现在作为一个前后端一体的框架，Nuxt 给前端应用也提出了这个概念。文档在这里可以自己看。它很好理解：进入路由的过程中要做的一些处理，比如判断权限等。大家可能想到 Vue Router 中的路由守卫，确实它就是改版的路由守卫，但通过文件系统组织，比路由守卫方便好用、直观很多。

来写第一个中间件。在根目录创建一个 middleware 文件夹（注意拼写），里面创建 auth.ts。先写一段伪代码：判断这个路由可不可以进入。需要默认导出一个 function，它要被定义好的全局函数 defineNuxtRouteMiddleware 包裹，里面是一个回调函数，两个参数：to 和 from。和 Vue Router 上的 navigation guard 非常一致，所以它就是路由守卫的改版。在里面可以写任何逻辑，比如没权限就完成跳转。写一个伪函数 isAuthenticated 判断当前有没有权限，之后可能会写一些异步逻辑（先请求接口看有没有权限），这里为了试验直接 return false：

```ts
export default defineNuxtRouteMiddleware((to, from) => {
  if (!isAuthenticated()) {
    return navigateTo('/login')
  }
})
```

没有权限时用全局函数 navigateTo 跳转到 login 页面。特别注意这个全局函数 defineNuxtRouteMiddleware，用它来定义中间件。

定义完了怎么使用？方法有很多，这里用最直观的方式。比如 user/[id] 里的信息希望被保护，没有权限就没法查看。到 script 中，还有一个全局定义好的函数 definePageMeta，用来定义和页面相关的一系列属性。用到的属性叫 middleware，可以添加多个所以是数组，这里只添加一个：middleware: ['auth']。名称要和中间件文件名一致（会有自动提示）。这样这个路由就被中间件保护了。

验证：回到首页刷新，点击 user one，可以看到虽然点击的是 user one，但已经跳转到了登录页面，因为中间件里的授权判断返回了 false，被导航到了 login 页面。

这节课补充了 routing 相关的知识，并且提出了中间件的概念，一个全新的、很有意思的概念。下节课继续深入中间件的知识。
