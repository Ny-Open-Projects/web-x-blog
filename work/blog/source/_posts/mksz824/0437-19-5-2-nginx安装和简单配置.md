上节课介绍了 nginx 的概念和用途，这节课在本地安装并对它的配置做一个简单的讲解。本地使用 nginx 完全是出于学习目的，最终的 nginx 应该是安装在服务器上使用的。

## 安装

nginx 在 Mac、Windows 以及 Linux 中的安装过程不一样，这里只讲 Mac 的安装方法。Windows 安装可以去参考它的文档，有 download 和一系列 version，去安装就好；Linux 系统有一系列包管理器供大家使用。

Mac 中一般采用 brew 安装软件：

```bash
brew install nginx
```

安装完毕后会有一个全局的命令，称之为 nginx。输入 `nginx -v` 可以查看版本号以及一系列其他的信息：首先输出版本号（我这里是 1.17.10）；除了版本号之外还有很多 configure arguments，代表启动 nginx 命令时会附加的一系列信息，它们指出了启动时配置文件的位置、路径，以及启动了哪些模块。不同的版本、实例或操作系统中这些信息会有一些出入。

## 启动与关闭

只需要运行 nginx，不加任何参数，就可以启动这个服务器。命令执行后没有任何提示，就说明已经成功了。访问 localhost:8080，刷新一下，可以看到一个经典的 nginx 启动页面。

关闭服务使用：

```bash
nginx -s stop
```

## 配置文件

nginx 的配置文件位置可以用刚才的命令查看。在 `nginx -V` 输出的一系列参数中，要找一个很重要的参数：--conf-path，它就是配置文件的路径，比如 /usr/local/etc/nginx/nginx.conf。用 VS Code 打开它，里面是一个类似 JSON 的配置文件，有很多配置项，不会逐项解释，英文比较好的话大体就能弄懂意思。

要找的是一个称为 server 的模块，一般在 http 下面。server 规定了服务器的一系列信息：

- listen：监听哪个端口，这里是 8080；
- server_name：服务器的名称，在本地是 localhost；
- location：字段前面会加一个 `/`，意思是路径为根目录时，访问下面的对应信息；
- root：指的是这个文件夹下的静态文件，首页应该是 index.html 或 index.htm。

root 的路径写的是一个 html，这是什么意思？它其实是一个环境变量，具体指代一个路径。回到配置文件里找一个称为 --prefix 的配置，它也是一个路径。到这个路径下去看，用 ll 一下，发现 html 其实是一个软链接，链接到往上三级的 /usr/local/var/www，这就是项目的根目录。里面有 index.html，内容跟刚才 8080 端口里看到的完全一致，说明我们访问到的就是这些静态文件。

## 部署打包产物

现在让 nginx 帮我们完成第一个功能：访问网站的静态文件。要做的事就是把已经 build 好的静态文件拷贝过去，看看好不好用。

进入项目，public/OpsFlow 下面进入 dist（已经 build 完成）。注意这次 build 用的是 staging 的 build，因为正式环境的后端不支持跨域访问。然后拷贝：

```bash
cp -r dist/* /usr/local/var/www/
```

拷贝到刚才看到的根目录下面。回车之后拷贝完毕。把 nginx 启动一下，刷新页面，就能访问到我们线上的地址了，任务完成。

## 线上机器的配置示例

最后再看一台线上机器的 nginx 配置，分享一个简单的例子。进入一台阿里云的机器，运行 `nginx -V`，它跟我们本机就不太一样了：有非常多的模块，并且换行了，其中有一系列 --with-http 什么的 module，这些是 nginx 的模块，用来添加或者拓展功能。里面同样有我们熟悉的 config-path，看它的配置文件，位置在 /etc/nginx/nginx.conf。

进来以后也是这样的配置文件。注释写得很好，说明每个模块是干什么的；被注释掉的一些模块就表示没有加载。来到熟悉的 http 模块：有一段 basic settings 的基本设置，都是按分类分好的（gzip 等等）。继续往下滚，具体的服务添加到哪里呢？可以看到它可以使用 include 来包含一些外部的文件，称为 virtual host configs，也就是把网站分割成一些独立的文件进行配置。位置是 /etc/nginx/sites-enabled。

进去以后有一系列网站，使用不同的文件来区分。看一下其中一个测试用的配置文件（不是线上正式配置，只是当年做测试时用的，但可以了解大体原理）：经典的 server block 出现了。listen 80 监听 80 端口；server_name 是服务器的名称，这里是线上的域名；root 大家很熟悉，就是根目录的名称；index 刚才都看到了。来到对应的文件夹验证一下，里面放了一个文件，cat 以后输出一个 h1，这样就完成了对应的过程。
