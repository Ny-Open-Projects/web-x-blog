这节课来学习 CASL 的用法。我们还是在 learn-mongo 这个仓库中进行测试和学习。第一步安装。参考文档的 Installation 部分，文档里说 CASL 这个名字有同构的意思，也就是在浏览器端和 Node.js 中都可以使用。它有一些官方包，我们需要的是 @casl/ability，这是 CASL 的核心包。它还有一系列插件可以跟不同框架结合使用，比如 React、Vue 都有，这里不需要，只要安装核心包就可以了，命令是 `npm install @casl/ability`。我这里已经装好，大家自己安装。它是用 TS 编写的，所以不用安装任何定义文件。

现在完成对应的例子。CASL 有三种方法定义规则（rules）。既然做 RBAC，就需要定义权限、角色和规则。三种方式分别是：defineAbility、AbilityBuilder 和 JSON object。我们采用第二种 AbilityBuilder 这个 class。它虽然不是最简单的（最简单是第一种），但是最强大的，可以比较轻松地完成复杂的验证。另外两种方法不讲了，感兴趣自己看文档试一下。

写代码。第一步需要两个依赖：AbilityBuilder 和 Ability。定义一个 function 来确定规则，叫 defineRules。然后实例化这个 class：`new AbilityBuilder(Ability)`，传入 Ability 作为参数，这是写死的用法，照着写就行。这个实例会返回三个方法：第一个叫 can，可以做什么；第二个叫 cannot，不能做什么；第三个是 build，生成最终的 rules。有了它们就可以定义规则了。

CASL 中有三个概念，分别对应 can 和 cannot 的参数。第一个称为 action，也就是用户的一些行为，可以和 CRUD 对应：create、read、update、delete。比如 can('read', ...)，可以读取什么呢？

第二个参数是 subject，也就是你要操作的资源实体。用我们项目中的例子，这里写 work，这句话的意思就是可以读取 work 这个实体对应的资源，非常简单。

第二个测试一下 cannot，跟刚才一样，行为是 delete，不能删除 work，意思就是不能删除 work 这个资源。

第三个还有更复杂的，称为 condition，可以表明用户可以操作什么样的实体。比如我们要表达：不能更新 isTemplate 属性为 true 的实体。写法是 can('update', 'work', condition)，condition 这里直接写对象：isTemplate 为 false 的 work 是可以更新的。

现在规则定义好了，有了规则以后直接 return build()，它是一个 function，调用它，rules 就定义好了。这三条规则大家可以再复习一下，非常方便地完成了权限的定义，跟英语语法一样，看起来非常明了。

接着检查对应的权限。定义一个 rules 变量，调用 defineRules，它会返回 build 的内容，也就是权限。console.log 一下，我们可以问它：可以 read work 吗？写法跟定义时一样，rules.can('read', 'work')。再把剩下的都写上：能 delete work 吗？能 update work 吗？运行 `ts-node casl.ts`，返回 true、false、true：可以读取 work，不能 delete work，可以 update work。注意 update 这条有一个条件，isTemplate 为 false 的时候可以 update，所以总体来说可以更新 work，这是语义上的内容。

还有一个很重要的点是 condition，update work 是有条件的。这时可以创建一个 work 类来界定不同的实体。我直接复制过来，创建一个 class Work，constructor 里只有一项 attr，简单地把属性添加到类的实例上，用 Object.assign(this, attr)。有了它就可以新建两个 work：第一个叫 templateWork，new Work({ id: 1, isTemplate: true })，它是一个模板；第二个叫 normalWork，它不是模板。

新建好以后，把规则中的字符串转换为实例。把 work 换成 templateWork 放进 console.log，然后再写 normalWork 也就是不是 template 的情况。想要的结果是：templateWork 应该返回 false，也就是不能更新一个模板；normalWork 应该返回 true，可以更新一个不是模板的作品。保存运行，结果一个是 false 一个是 true，没问题，CASL 的工作完全成功。

大家也许会有疑问：在 CASL 定义规则的时候写的是字符串 work，那传入一个对象时，字符串和对象是怎么产生对应关系的？原来当你第二个参数传入的是一个对象时，CASL 会查看一个特殊的属性，看这个属性是否跟字符串相对应。这个属性是什么？console.log 对应实例的 constructor，构造函数上面有一个特殊属性 name，运行结果是 work，跟字符串相对应。通过这种方式就将两者产生了对应关系。

当然还有其他方式。假如这里只有一个普通对象而不是一个类，可以使用一个参数，把 subject（也就是实体）跟对象对应起来，之后会介绍这部分内容。

这节课简单介绍了 CASL 的用法，会发现 CASL 写规则特别接近英语语法，即使看不懂代码的人，看这么一段话也能轻松读懂它的意思。下节课再深入一些，介绍 rules 和特定字段的一系列规则。
