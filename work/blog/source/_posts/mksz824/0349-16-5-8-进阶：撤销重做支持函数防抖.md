这节课完成第二个优化点：面对非常频繁的操作（比如在 input 中连续修改值），我们不希望每次修改都被记录，只记录最后一次。这类需求大家应该都处理过：输入框输入字符发起异步搜索时，不是每次都发请求而是只发最后一次；窗口 resize 时做 layout 尺寸计算，也是只算最后一次。

这个操作有个专有名词：函数防抖，lodash 里的函数叫 `debounce`。这节课不用现成实现，也不谈 debounce 源码，而是用我们自己的思路，在这个特定场景下把它写出来。

## 防抖的核心思路

问题发生在 `updateComponent` 的 pushHistory 处，每次都 push。我们希望让 history 只 push 一次。大体的思路：

1. 第一次执行时，函数延迟执行（callback 在之后执行）；
2. 第二次很快又触发的话，把上一次的 timer 清除掉，它就不会再执行；
3. 这样只有最后一次触发真正执行对应逻辑。

## 实现 debounceChange

在 mutation 外部（state 的作用域之外）创建一个函数，叫 `debounceChange`：

```ts
function debounceChange(
  callback: (...args: any[]) => void,
  timeout = 1000,
) {
  let timer: any = 0
  return (...args: any[]) => {
    clearTimeout(timer)
    timer = window.setTimeout(() => {
      callback(...args)
    }, timeout)
  }
}
```

第一个参数是想调用的回调，第二个是延迟时长，这里设一秒（1000 毫秒）。内部先创建 `timer` 初始为 0，然后返回一个新函数，这和之前学的 HOC 概念一致，同时能让 `timer` 一直保存在内存中，这就是闭包的妙用。

返回的新函数用剩余参数（三个点）把调用参数收成数组，每次先清除上一次的 timer，再用 `window.setTimeout` 重新计时，内部执行 `callback(...args)`，最后一个参数是 timeout。

## 接入 pushHistory

接着封装一个 `pushModifyHistory` 函数，把之前 push 的操作收进去。注意它也要放在 editor 外侧，和 `debounceChange` 在同一作用域中。参数有三个：`state`（EditorProps）、`data`（UpdateComponentData 类型，含 key、value、id）、`oldValue`。

然后用 `debounceChange` 包裹它，创建防抖版本：

```ts
const pushHistoryDebounce = debounceChange(pushModifyHistory)
```

函数体里不再调用旧的每次都触发的函数，只调用一次 `pushHistoryDebounce`，把 `state`、`key`、`value`、`id`、`oldValue` 依次传进去。为了观察 timer 的变化，测试时先把它打印出来。

界面上验证：选中元素后快速连续输入新值，console 显示 history 只保存了一次，防抖生效。但点撤销时发现一个问题：只回滚到了上一次保存的值，而没有回到最开始修改前的值（hello）。

## 保存最初的旧值

原因在代码里能看到：callback 虽然被清掉了，但最后一次调用传入的 oldValue 是每次更新前取的新旧值，不是开始时的值。所以需要想办法保存第一次开始更新时的值，在全局状态上做文章。

给 store 添加一个新的键 `cacheOldValue`，初始设为 null。然后在 `updateComponent` 里做个简单判断：如果它是 null，说明还没有保存过，就把这次的 oldValue 存进去：

```ts
if (state.cacheOldValue === null) {
  state.cacheOldValue = oldValue
}
```

之后 push 历史记录时不再用本地的 oldValue，而用已缓存的 `state.cacheOldValue`。最后别忘了在 push 完成后把它清空回 null，为下一次操作做准备。

再打印验证：快速输入时保存下来的旧值确实是 hello。界面上测：选中、快速输入新值，点撤销，回到 hello 而不是中间某个值；点重做，回到 sdf。

这样就完成了给 history 添加函数防抖，并且保存了最开始修改时的旧值。这也是函数防抖的常规做法，希望大家记住它的原理。
