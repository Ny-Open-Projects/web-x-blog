这节课接触一个新需求：列表拖动排序。这是非常常见的需求，很多场景下都会出现它的身影。

## 学习方法：先原理后成熟方案

对这类需求，我们以后都采用一种学习方法：我会先用一种简单的方法实现具体功能，这个过程中可能不会考虑到那么多 case，目的是让大家了解功能的原理。简单实现之后，再换用业界比较成熟的第三方方案做一次，这类解决方案一般覆盖了各种棘手的边界条件，比我们自己的简单方案全面。这样既学习了原理，又学习了成熟方案的用法，一举两得。

## 两个主流 demo

先从 demo 感受一下。第一个是 Vue 的：Vue 中使用最多的列表排序功能库叫 Vue Draggable；另一个是 React，用的是 React Sortable HOC。这两个库是目前排序列表用得最多的解决方案，完成的都是同一个任务。这里只看它们最简单的例子，一个简单的列表进行排序：给定一串列表，每个条目都可以被拖动，拖动过程中移动到对应位置会发生列表条目的移动，松开手时右边的数据会显示响应式对象已被修改更新完毕。React demo 的交互和 Vue 几乎完全一样。

## 三个阶段

从这些操作中可以总结出，列表排序分为三个阶段。

**第一阶段：拖动开始（dragstart）。** 按住一个条目并开始拖动时进入。这个阶段有两个要注意的地方：一是被拖动条目的状态变化，它会添加不同的颜色或 class name，代表它正在被拖动（demo 中被拖动项变成浅蓝色）；二是会出现一个浮层，一个脱离 DOM 定位存在的白色浮层，随鼠标移动而移动。

**第二阶段：鼠标移动。** 拖动着移动时进入。需求有两个：一是浮层随鼠标移动而移动（这个在第一阶段就已经出现）；二是当鼠标移动到特定位置时，条目会发生换位。仔细观察：当浮层的下沿超过被拖动条目二分之一的时候，就会触发换位。这是一个比较独特的需求点。

**第三阶段：松开鼠标（drop）。** 这个阶段有几个需求：浮层消失；被拖动条目的状态复原，变回白色背景的普通条目；最终数据被更新，只有在松开时，list 数据才会被更新掉。
