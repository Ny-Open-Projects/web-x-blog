上节课我们讲了本地调试，其中使用了 logger 插件，并且用 logger 上面的 debug 方法进行了调试，它可以在终端输出比 console 更丰富的信息。但其实这不是 logger 的主要功能。logger 顾名思义，就是为了提供日志功能而存在的。

日志对 Web 开发的重要性毋庸置疑，它对于监控应用的运行状态、问题排查等等都有非常重要的意义。Egg.js 中我们采用 egg-logger 这个 plugin 插件来支持，它有一系列强大的特性。

首先了解日志存在哪儿。日志的存放地址是 appInfo.root 下的 logs 文件夹，里面还会单独创建一个以 appInfo.name 命名的文件夹。这几个变量我们都很熟悉，之前讲全局变量的时候讲过。appInfo.root 是应用根目录，注意它是会发生变化的，在不同环境下有不同的值：只有在 local（也就是 npm run dev）和 unittest 环境下，它为 baseDir，也就是应用代码的目录；其他环境比如生产环境下直接运行 npm run start，它应该是 home，也就是用户的目录。因为我们经常在 dev 环境下运行，所以日志首先应该在应用代码的目录下。到 logs 下面看，会有一个跟应用同名的文件夹（logger-backend），找到了日志的地址，里面有一系列的日志文件。另外，之前测试 TypeScript 的时候我们用 npm run start 启动过，等于在 production 下运行过，所以日志还应该在用户目录下面。用户目录在 Mac 和 Windows 下面不一样，以我的为例，在 users 目录下面进入 logs，可以看到一系列文件夹，名称和应用同名，跟刚才一样。进去以后它也有一系列 log，因为这个应用只在生产环境运行过一次，所以 log 会比本地开发环境少很多。

第二个特点：Egg.js 通过不同的用途将日志进行了分类。看本地的地址，有一系列文件。第一个叫 appLogger，文件名是 `应用名-web.log`，它是应用的相关日志，供应用开发者使用，我们在绝大多数情况下都是在使用它。看这里的文件：应用名称加 -web.log，有很多类似的文件。它是按天分割的，每天一个文件，查看每一天的日志直接进入对应的文件查看就好，这是 egg-logger 内置的功能。

第二种是 errorLogger，文件名是 common-error.log。一般不会直接使用它，但是任何 logger.error（上节课用过这个方法）调用输出的日志都会重定向到这里，所以这个文件是用来通过查看日志定位异常的。

另外还有 coreLogger，文件名是 egg-web.log，一般是框架的内核以及插件的日志；还有进程日志 agentLogger，文件名是 egg-agent.log。这两个我们讲得不多，因为现在还用得很少。

讲完分类，说说怎样进行日志的打印。上节课讲调试的时候其实已经使用过这些方法了。现在我们了解到，这些方法不仅有往终端打印字符串的功能，还有添加到对应日志中的功能。特别注意 error 这个方法：除了会打印到对应的 web.log 当中，还会重定向打印到 common-error.log 里面。所以当你想查找任何错误的时候，直接看 common-error.log 就可以了。

还要特别强调一点：日志级别还是那五个级别，但只会输出 info 及以上（warn 和 error）的日志到文件中。也就是说在代码里调用 debug 是不会写入日志文件的。它也提供一个配置项，注意是 level，不是 consoleLevel，用来界定最低什么程度写入日志文件，跟上节课说的那个配置是一个意思，只不过是不同的用途。

现在测试一下上节课的代码。上节课使用这些代码测试调试的时候，其实已经不知不觉把它们写到了日志当中。再来看一遍：首先把 info 改一下，都写上 new，这样比较好查看。保存后访问对应的 URL，返回成功后看 log：用 tail -60 看最后六十行的内容。可以看到 info、warn 和 error 都被记录到了文件当中，时间也是对的，说明往文件中插入的功能已经生效了。再看错误的信息：common-error.log 会单独进行一次输入，也是四点四十二的时候输入的，之前的错误跟这次没关系。说明单独的错误信息也记录到了日志当中。

通过这节课我们简单讲了 Egg.js 关于日志的用法和概念，请大家记住这几方面：第一个是日志的位置，要知道怎样找到日志对应的位置；然后是日志的分类，它会根据不同的功能分成好几个不同的文件；最后是怎样写入日志（不是打印，叫写入更贴切），可以使用 ctx.logger 上面的一系列方法，上节课已经接触过了，进行写入。
