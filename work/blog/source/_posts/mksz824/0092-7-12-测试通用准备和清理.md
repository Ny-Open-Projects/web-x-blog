现在我们已经掌握了测试组件的基本流程：不仅能测组件的基本四个步骤，还能测异步行为。但写测试的过程中遇到了一些痛点。回头看代码会发现，每个 case 开始时都要写一大堆重复的代码：先创建 message，再用 shallowMount 完成挂载，费时费力。那么测试框架有没有提供一些钩子函数，用来做通用的准备或清理工作呢？答案是肯定的。

这节课暂时离开 Vue 组件的测试，看看 Jest 提供的通用功能。我们知道可以用 describe 把一系列相关用例组织在一起，比如把所有关于 HelloWorld 的测试都放进一个 describe 中。现在想在它下面的每个用例之前都运行一段逻辑，也就是 mount 组件，这时可以用 beforeEach。先把 message 和 wrapper 提到外面：wrapper 用 `let wrapper` 声明，类型是 VueWrapper，接受一个泛型，这里可以设为 any。然后把原来创建 wrapper 的逻辑挪进钩子，把 const 删掉，这样每个用例之前就自动完成了 wrapper 的创建，把各 case 里重复的代码删掉之后，测试文件清爽了很多。

与之相对的还有 afterEach，在每个用例跑完之后运行；以及 afterAll，在所有 case 都跑完之后运行一次，这里就不演示了。要特别注意 beforeAll 是 one time setup，在多个 case 之间只运行一次。

做个实验说明这件事：初始 button 的值是 1，某个 case 里点击一次之后它变成了 2。如果期望它还是 1，测试就会出错。这说明组件在整个测试过程中只被 mount 了一次，所有 case 用的是同一个实例，并不会因为换了用例就把 wrapper 复原一遍。

但有些逻辑我们希望彼此独立，共享状态就可能出问题。看下面的例子：有两个异步 case，一个成功、一个失败，想测 mock 的 get 被调用的次数，在 trigger 之后写 `expect(...).toHaveBeenCalledTimes(1)`，按理说这个用例里只调用了一次。结果测试报错，期望 1 次实际调用了 2 次。这时候很容易怀疑是不是自己的业务逻辑写错了，其实原因是上一个 case 里已经调用过一次 get，两个 case 的调用次数被累加到了一起。

为了让测试更准确，需要另外一组钩子：beforeEach 和 afterEach。顾名思义，每次 case 跑之前、跑之后都会运行。我们可以在 afterEach 里把 mock 重置：mockedAxios 的 get 上有一个 mockReset 方法，调用一下即可。再跑测试，这次完美通过，用例之间不再互相影响，测试行为也更符合常理。

这就是今天的小知识：用 before / after 两类钩子函数，添加多个用例共用的准备和清理逻辑。官方文档还有一条建议值得一读：如果一堆用例里有一个测试失败了，首先注意它单独运行是否也失败，可以用 only 把它隔离出来单独跑。如果隔离运行没问题、合在一起跑就出问题，那就要特别留意用例之间的共享状态是否互相影响，是否需要在 beforeEach 或 afterEach 中做重置或清理。

最后送大家一个小 tip：已经学会用 only 在 test suite 上隔离运行某个测试，它还有一个相对的功能 skip，可以跳过一个对应的测试。写成 `test.skip` 或 `it.skip`，这个测试就不跑了。应用场景也真实存在：比如某个用例暂时失败了，你急需让整个测试通过先跑一次构建，就可以先用 skip 把它临时失效。这节课到这里，谢谢大家，再见。
