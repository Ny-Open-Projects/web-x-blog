上节课完成了元素的拖拽改变大小，这节课做最后一步：发射事件，更新 store 中的值，让它和界面保持一致。整体逻辑和移动元素时完全一样，采用相同的途径，同时看看编码过程中有没有可以优化的点。

## 在 handleMouseUp 中发射事件

发送事件的时机和之前一样，放在 `handleMouseUp` 里。先调用 `calculateSize` 拿到新的值，e 是 MouseEvent，要传进去：

```ts
const size = calculateSize(direction, e)
context.emit('updatePosition', { ...size, id: props.id })
```

除了 size 这一系列的值，还需要当前元素的 id，所以把 size 展开后附带 `props.id` 一起传出去。这样所有的值就都传递过去了。接下来在 `Editor.vue` 里做对应的处理。

## 用 lodash 消除重复逻辑

来到 `updatePosition` 的处理逻辑，会发现这里有大量重复的代码。当时事件只带两个键值，逐一判断着写还可以接受；现在传过来的是一系列值，如果还一个一个判断，重复逻辑就太多了。传过来的对象都是以 key-value 的形式排列的，自然可以循环处理。

首先要把 id 拿出来，它不是需要更新的属性，属于特殊属性，要从对象中剔除掉。遇到对象或数组的计算，首先应该想到 lodash。

在 lodash 文档里可以找到 `pickBy` 这个方法：传入一个 object 和一个回调，回调返回布尔值，为 true 的项会被保留，最终返回一个过滤后的对象，正是需要的。从 `lodash-es` 中导出 `pickBy`，用它生成需要更新的数据：

```ts
const updateData = pickBy(data, (v, key) => key !== 'id')
```

第二个参数是 key，当 key 不等于 id 时保留，就拿到了过滤后的数据。

有了 updateData，接下来循环提交。循环 object 也可以用 lodash 提供的 `forEach`：第一个参数是 collection（数组或对象都可以），第二个是回调。从 lodash 中导出 `forEach`，在回调里循环调用 `store.commit`，事件名称用已有的 `updateComponent`：

```ts
forEach(updateData, (v, k) => {
  store.commit('updateComponent', {
    key: k,
    value: v + 'px',
    id: props.id,
  })
})
```

value 等于 `v + 'px'`。注意 v 的类型原本是 string 或 number（id 是 string 类型），如果想让类型更精确，可以给 `pickBy` 传一个泛型：现在剩下的都是 number 类型的值，指定成 number 后返回值就变成 number 了。key、value、id 三个参数都齐全了，原来那一长串逐一判断的代码就可以删掉了。

## 清理事件监听

更新完毕后要清除事件监听，做法和移动元素的收尾一样。在 `nextTick` 中，也就是下一次 DOM 更新的时候，移除 document 上的 mouseup 监听：

```ts
nextTick(() => {
  document.removeEventListener('mouseup', handleMouseUp)
})
```

整个逻辑就写完了，到页面上验证：选中元素，把属性面板里的尺寸和位置都展开。拖到中间，x、y 会变化；拖动角上的点，高度、宽度、x 轴、y 轴都会正常更新，计算没有问题。

## 修复滚动条导致的抖动 bug

接下来修复一个计算中的特例 bug。中间的编辑区域是可以滚动的：container 是固定高度，内容长度可配置，纵向会出现 y 轴滚动条。当把滚动条滚动到下方，再往上拖动元素时，元素会出现向上的突然抖动，造成数据错误。

图上分析原因。计算元素 top 坐标时，用的是 clientY 减去某个距离，剩下的那一段就是 top 值。但这里忘了一个小问题：container 纵向可能有滚动条。它一旦向下滚动了，就等于已经滚掉了灰色那部分的距离，而计算没有算上它，计算出的距离就少了一部分。距离顶部的坐标应该是这两段相加，再加上滚动掉的距离，才是正确的 top 值。横向不用担心，横向是 hidden 的，不会出现滚动条。

修复只需要在所有改变 top 的地方加上 container 的滚动值：拿到 container 这个 element，读取它的 `scrollTop`（向上滚动的距离），加进计算即可。两处计算 top 的代码都要做这个加法。

保存后刷新界面验证：把元素拖到下面一点，向下滚动滚动条，此时已经有 scrollTop，再往上拖动，没有出现抖动；再移动一下也没有问题。整个过程就完美了。
