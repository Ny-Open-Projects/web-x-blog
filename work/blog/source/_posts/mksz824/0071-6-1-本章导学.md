欢迎来到新一周的学习。上一周我们完成了项目的整体搭建：从前端工具链的各种标准说起，到最后使用 Ant Design Vue、Vue Router 和 Vuex 完成了项目的几个基本框架。有了这个架子，这一周就可以真正开始业务代码的书写。看标题就知道，本章内容分为两大部分。

第一部分是业务组件库的初步开发，也就是第一个业务组件 LText 的书写。业务组件库经过之前技术文档的分析，逻辑并不复杂，但属性很多，怎样使用 TS 进行属性添加和逻辑重用，是我们要关注的几个点。第二部分是画布逻辑的关键点：将组件的属性以不同的表单组件进行展示，并且实现表单组件更新带动画布的实时更新。最后一部分是一个小的代码升级需求，通过这个需求不只是实现简单功能，而是发散性地介绍 Vue 组件渲染的过程和真谛，并比较书写 Vue 时 JSX 和 Template 两种写法的优劣。

这一周我们收获什么？第一点是渐进式的开发方式。我们已经有了技术实现文档，了解了整体开发思路，它就像一个基础的骨架，保证开发不会跑偏。而实现细节的时候，没必要一开始就想一个大而全的解决方案，那样有时会让你陷入困境：想实现的东西越多，一次性完成的难度就越大。可以从最简单的 case 入手，在过程中不断发现问题、添加功能，让它一点点丰满起来。在开发业务组件和实现表单属性实时更新这两方面，我都会采用这种开发手段，大家可以感受一下它的好处。

第二点，业务组件虽然不难，但几个业务组件共享了同样的一些逻辑，怎样设计组件的属性和重用性，是要重点讲解的一点。第三，TypeScript 始终是贯穿整个课程的重要点，这一周也不例外：我们希望把类型进行精心的设计，尤其是组件的属性。到了实际项目阶段，更能体现这个过程。第四，我们会以 Vue 的多种写法入手，比如 SFC 常见的单文件形式、Function 组件的形式、Render Function 等等，最后对比一下 template 和 JSX 写法的异同和优劣。

再说说学习方法。第一是渐进式开发，这也是学习方法之一：小步快跑，一步步完善最终需求。在比较复杂困难的问题上，大家不妨也试试这种方法。第二是对比学习，这是课程一直采用的方法：我们对比过框架（React 和 Vue）、工具（ESLint 和 Prettier），这次对比框架中不同的实现方法，让大家收获更多，在选择实现方法时更加游刃有余。第三是流程图：对于代码和逻辑的数据流动过程，可以用流程图描述，图像这种更直观的方式能让头脑中的思路更清晰，做到下笔如有神，这是处理复杂逻辑的灵丹妙药。

第四是以技术文档为指引。第一周我们辛辛苦苦写了技术文档，现在是它一显身手的时刻。本章要完成的任务中，两个技术文档完美地描述了组件的属性设计和编辑器场景的基本实现，对应的 case 和注意事项已经写得非常清楚。它是我们整个项目的蓝图，所以一定要根据它来完成真实的代码、具体的需求。

这周的开端就讲这么多。本周难度算是中等，有一点难度，主要在于和 TS 结合时对类型的考虑。让我们一起开始吧。
