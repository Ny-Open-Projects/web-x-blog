这节课来完成整个项目的构建，采用上一节课说的第一种方式，也就是使用 Node Server 这种最基本的方式。整个流程其实非常简单，因为 Nuxt 已经封装得很完善，只需要运行 npm run build，就能生成最终可以部署的代码。

构建需要稍微等待一会儿，因为它要构建好几个不同的部分，会花费一定的时间。来看一下 build 的过程，它分为这么几部分。

第一部分是使用 vite，针对前端代码的构建。从 building for production 开始，先是 building client，构建前端的一系列代码，输出位置在 .output 下的 client 目录。第二部分是 building server，也就是 building SSR bundle for production，对应后端的一系列文件。

接下来是使用 Nitro 针对后端所有功能的构建。这里为了加速加载，会把代码分割成几部分进行优化，输出里可以看到 Building Nitro Server 和 Preset 信息，它使用的就是 Node Server 模式，也就是上节课讲的最基础的模式。

经过这两个部分，整个构建就完成了。Total size 显示总共 15.6 MB，压缩后是 4.46 MB。如果要运行，执行对应的命令即可。最终生成的代码都在 .output 文件夹下面。

看一下最终的代码结构。.output 下面分为两大部分：第一部分是 public 文件夹，也就是前端部分，_nuxt 下面是构建生成的所有需要的文件；另一部分是 server 文件夹，顾名思义存放的是后端服务器的代码。其中的 index.mjs 就是整个应用的入口文件。

部署其实也不难。最简单的方式就是把 .output 文件夹中的内容通通拷贝到服务器上，这样就完成了构建和部署。当然，使用 Docker 也完全可以，过程就是先完成构建，然后在入口文件上运行对应的命令。如果想采用之前用过的 GitHub Actions 结合 Docker，或者 GitHub Actions 结合 SCP 的方式，也都可以自己尝试。

最终的启动命令要注意后缀名是 .mjs。之前的 Node.js 支持的是 CommonJS 格式，而新版的 Node.js 已经可以完美支持 ESM（ES Modules）格式，这对前端来说是一个巨大的进步。它意味着可以使用前后端统一的 ESM 格式来书写代码，甚至不需要任何转换。Nuxt 构建以后使用的就是这种最新的格式，后端也一样，非常方便。

Node.js 官方有关于 ESM 格式的文档，感兴趣可以去看看。文档里讲了如何启用这种格式。如果想用 .mjs 格式，有几种方式：第一种是修改后缀名，把文件改成 .mjs 之后，Node.js 运行时默认把它当作 ESM 格式的文件；或者是在 package.json 中设置 type 字段为 module，也可以。更详细的用法看文档即可。结论就是：Node.js 现在已经支持 ESM 格式，以后写任何针对 Node.js 的库，也都可以使用 ESM。

现在把它运行起来。拷贝对应的命令直接运行，会发现运行失败，弹出了错误。错误出现在阿里云 OSS 这部分：启动 OSS 需要 Access Key 和 Access Key Secret 这两个参数，但现在没有。原因在于 .env 文件中写了一系列环境变量，而 Node.js 并不会自动读取 .env 文件中的内容。启动失败说明环境变量没有被读取，应用自然无法运行。

所以需要手动设置环境变量。看一下 Node.js 关于使用环境变量的文档。在 Node 20 之前，如果想使用环境变量，方式是在运行命令前面添加参数，比如文档里的 USER_ID 和 USER_KEY，通过这种方式在运行应用时把这两个环境变量注入进去。但这是一个非常笨重的方式，因为环境变量很多的话，就要一行一行都写在这里，非常繁琐。

Node 20 之后有了新的解决方式：Node.js 正式推出了 .env 文件支持。使用时只要加一个参数 `--env-file=.env`，就可以把所有环境变量都读取进去。

所以建议安装 Node 20 的版本，用之前的 NVM 安装即可。安装完毕后切换版本：nvm use 20.12.2，切换到刚才安装的最新版本，然后就可以使用对应的命令来运行了。

特别注意，运行这个命令时还有几个默认的环境变量可以使用：第一个是要绑定到哪个端口，默认是 3000；HOST 默认是 localhost；还能提供 HTTPS 的支持。如果想使用不同的配置，把这些环境变量添加进去即可。

现在用刚才的命令来运行：`node --env-file=.env` 加上入口文件的名称。回车之后可以看到 listening on 3000，说明成功启动了。验证一下整个应用能否正常运作：一开始需要登录，两秒后登录成功，整个应用可以完美运行，修改操作也没有问题。

这就是整个本地构建的过程。这里要特别注意几个知识点：第一是运行命令 npm run build 的流程；第二是 .mjs 格式，Node.js 现在对它的支持情况；第三是 Node.js 关于环境变量使用的文档。构建就到这里，下节课来看怎么完成部署。
