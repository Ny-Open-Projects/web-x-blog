按照计划，这节课完成搜索功能。通过给定的关键字检索结果，是表格以及各类列表操作的常用需求，需要一个对应的表单来完成。

## 自建搜索表单

Nuxt UI 自带表单组件 UForm，但我们之前对 VeeValidate 成竹在胸，而且这个表单非常简单：一个 input 加一个 submit，希望是 inline 左右排列，label 也不需要渲染。这种自定义布局在 UForm 里实现比较麻烦，所以我选择自己完成表单。UForm 内部和我们非常相似，也支持 Zod，大家有需求也可以使用它。

创建表单：先把外层的 pre 删掉，添加一个带 `border-bottom` 的 div，在其中创建 form。因为要左右排列，加一个 flex。左边是 input，用 Nuxt UI 提供的 UInput 组件，样式更美观，给它加一个放大镜 icon 代表搜索；右边用 UButton，加 `ml-3` 让两者略有分割。

接下来写熟悉的验证逻辑，把三个依赖拿过来：Zod 的 z、useForm、toTypedSchema。

首先创建 schema，只有一条规则：object 里一项叫 keyword，规则是 string，不允许为空，最小值设为 1。然后用 useForm 处理，把经过 toTypedSchema 转换的 schema 作为 validationSchema 传进去，拿到 handleSubmit。

再用 defineField 创建字段，返回数组第一项是 keyword 显示变量，第二项是 keywordAttrs。绑定到 UInput 上：`v-model="keyword"` 加 `v-bind="keywordAttrs"`。

错误信息就不显示了，想显示可以自己加，这里只加一个状态：出错时边框变红。UInput 有个 `color` 属性支持修改颜色：没出错时是 gray，出错后变 red。把 useForm 的 errors 拿出来，动态修改 color：`errors.keyword` 存在返回 red，否则 gray。

最后创建 onSubmit 处理提交：用 handleSubmit 包裹，里面有 values，打印出来，绑定到表单的 submit 事件上。

测试：什么都不填点查找，红框出现；添加值再点，没有问题，值打印出来了。验证完成。

## searchText 与请求时机

下一步是服务器端查找。请求该用哪个值？直接用 keyword 不行：它是 v-model 上的值，会一直变化；放进 query 的话每次变化都要发请求，而我们只希望在点击 submit 后发送一次。所以再创建一个响应式变量 `searchText`，默认空字符串，只在 submit 成功（无错误）时改变：

```ts
searchText.value = values.keyword
currentPage.value = 1
```

同时把页码重置为第一页。特别注意：一次修改两个响应式变量不会发送两次请求，两次改变会合并成一次。把 searchText 加进 query 的 keyword 里。

保存测试：输入 Viking 点击查找，成功发送一次请求，keyword 等于 Viking 传过去了。接下来只需在后端处理这个值。

## 后端 regex 搜索

来到 `index.ts`，把 query 拿过来，keyword 创建默认值：不传或传空就给空字符串。此时 find 不应该是空对象，而要有意义的条件。创建 findCondition，里面判断：有 keyword 时进行搜索。

MongoDB 有个特殊关键词帮我们完成搜索。我们用 username 字段搜索，MongoDB 的特殊搜索关键词都以 `$` 开头，这个词叫 `$regex`，可以传入正则。这里直接把 keyword 传进去，它会自动搜索 username 中带有 keyword 的值：

```ts
const findCondition = keyword
  ? { username: { $regex: keyword } }
  : {}
```

另一种情况 keyword 为空就是空对象。用它替换 find 的条件，total 的查询同样替换。

刷新测试：输入 viking 点击查找，值发生了变化，返回的所有用户名里都带有 viking 这个单词，只剩九条，其余被过滤掉了；keyword 成功传递并返回了最终值，搜索功能实现。

## 清空按钮

还想多做一点：查找完毕后没法清空，想回到原来的值只能刷新。在查找按钮后面再添加一个清除按钮，用起来更方便。

复制查找的 UButton，把 `type="submit"` 删掉，color 改为 white，文案写"清除"。它什么时候出现？很简单：searchText 不等于空时说明已发起搜索，就让清除按钮出现。创建一个 computed：

```ts
const showClear = computed(() => searchText.value !== '')
```

以 v-if 形式加到清除按钮上。点击逻辑叫 onClear，也很简单：把 searchText.value 还原到最初始的空值；currentPage.value 还原回 1，重新从第一页搜索；最后还要把表单还原到原始状态，否则一些错误状态还残留着。useForm 返回了 `resetForm` 函数，调用它就可以把整个表单状态还原到最初。

把 onClear 绑定到清除按钮的 click 事件上。测试：先做一次搜索成功检索出结果，点击清除，值消失了，完成了一次成功检索，keyword 也清除掉，最终返回 16 条所有结果。
