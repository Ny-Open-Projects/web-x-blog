这节课完成最后的优化：组件实例的销毁。

ContextMenu 组件是在进入 editor 路由时、`onMounted` 的时候渲染的，但离开 editor 时并没有做对应的销毁。先看页面会出现什么状况。我在 editor 里加了一个 Home 的 router-link，点击跳回主页。第一次进入编辑器时，DOM 里多了两个节点，因为插件里调用了两次 `createContextMenu`，自然出现两个节点。现在离开路由去 home，再通过「使用模板」回到 editor：节点变成了四个。之前的两个节点并没有被销毁。

更致命的是事件监听：ContextMenu 组件上绑定的 `document.addEventListener('contextmenu', ...)` 的 remove 写在 `onUnmounted` 里，但现在并没有被清除，事件会越积越多。打开 DevTools，选中 body，在 event listeners 里可以看到四个 contextmenu 事件，被添加了两次且从未移除。所以我们需要一个方法，在特定时刻销毁组件实例及对应节点。

## render(null, container)

回到 `createContextMenu`。特别注意：`render` 函数返回 void，没有提供销毁方法。查文档后我找到了一个办法，再次调用 `render`，第一个参数传 `null`，第二个还是 container，即可完成销毁：

```ts
render(null, container)
```

当然不能把销毁逻辑直接写在这里，否则刚创建就销毁了。我们要在特定时刻（离开路由时）从外部调用它。

## 闭包返回销毁函数

需求是「把内部提供的方法返回到外部」，大家应该都想到了闭包。在 `createContextMenu` 里直接返回一个函数：

```ts
return () => {
  render(null, container)
  document.body.removeChild(container)
}
```

调用这个返回的函数，就会完成销毁：先 `render(null, container)` 清掉 vnode，再从 body 上移除 container 节点。

于是在 contextMenu 插件里创建变量承接它：

```ts
let destroy: (() => void) | undefined

onMounted(() => {
  destroy = createContextMenu({ actions: testActions })
})

onUnmounted(() => {
  destroy?.()
})
```

`onMounted` 里赋值之后，`destroy` 就是可调用的销毁函数；组件离开路由时触发的 `onUnmounted` 正是销毁的时机。（我为了做实验还临时建了第二个变量 `destroy2`，验证完就删掉。）

## 验证

重新实验：刷新页面，Elements 里有两个 div；点击 home，两个 div 被删除，同时 console 打出了 remove，这是我在 ContextMenu 里加的一行 `console.log`，代表销毁逻辑被触发，随之 contextmenu 和 click 两个事件也解除了绑定。再次通过「使用模板」进入 editor：只有两个新建的 div，没有多余节点；刷新后再看事件监听，还是两个 contextmenu 事件，没有越积越多。

优化完成：函数方式添加的组件现在可以成功销毁了。这节课有两个关键知识点：

1. `render(null, container)` 这种写法可以销毁渲染的组件，这是我查了很久文档才发现的，请记住；
2. 用闭包把销毁函数返回给外界调用，两者配合完成任务。

右键菜单的开发到这里告一段落。大家可以把自己想添加的右键操作一一加到 contextMenu 插件中，这里就不多加了。
