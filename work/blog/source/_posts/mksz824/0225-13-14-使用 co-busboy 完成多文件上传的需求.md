上节课学习了用底层库 Busboy 完成 multipart 数据的解析，这节课更进一步，完成最终的多文件上传接口。上节课讲了 Busboy 的原理，它是基于事件的，而 egg 推崇 Promise based（大家知道在 egg 里我们大量使用 async/await 方法），事件和这种方式不太适配。所以 egg 使用了 Busboy 的一个改版，叫 co-busboy，是 @eggjs 旗下的一个库。它基于 Busboy，把实现修改成 promise 风格，把 multipart 中的数据流变成一系列基于 generator 的 promise。

## 探索 ctx.multipart

在 controller 里创建新方法 uploadMultipleFiles。先复习之前的 stream 用法：`await ctx.getFileStream()`。注意 getFileStream 只能拿到一个文件流，有多个文件时不能用，这里要用一个叫 multipart 的东西：`const parts = ctx.multipart()`，它是一个 function，可以调用。

multipart 究竟是什么？看一下 egg-multipart 插件的源码。文件是 app/extend/context.js，自然是在 context 上扩展。往下翻找到 multipart 方法：前面是一系列参数判断，缺参数会发出警告之类的东西；最关键的是最后 `return parse(this, parseOptions)`，说明 parse 一系列 options 可能与传入的属性有关。翻到最上面会发现，parse 其实就是 co-busboy 对应的返回。所以 ctx.multipart 就是 co-busboy 的封装。

## parts 的返回形态

它返回的是一个 promise，可以调用。`const partOne = await parts()`，然后用 app.logger.info 打印 partOne 观察形态。

请求里放两段数据：一个 text 类型的字段，一个 file 类型的字段。点击 Send，响应 404（没有写返回，无所谓），日志里出现了输出：Hello Test，以及一个值为 false、false 的数组。后面两个参数不用管，那是 busboy callback 里的四个参数中的后两个，我们需要的是前面两个。Hello Test 对应的就是 key 和 value（fieldName 和对应的值），上节课说过。这说明它是一个分段返回：取到的第一部分就是这个文本项。

继续 `const partTwo = await parts()`，再打印。再次 Send 后可以看到：第一部分还是 Hello Test；第二部分出现了熟悉的老朋友 file stream 类型，一个 readable stream，上面还添加了 filename 等属性。大家会联想到单文件上传时使用的 getFileStream，类型其实完全相似。

继续拿第三部分会返回什么？复制成 partThree 并打印，点击 Send，发现 Sending request 一直被 Pending 住，请求不结束。原因就是上节课讲的：read stream 必须被消费掉，不消费整个请求会卡死。所以要在 partTwo 处用 sendToWormhole 把 stream 消费掉：`await sendToWormhole(partTwo)`。cancel 掉未结束的请求，重新 Send，很快返回了。

结论：第一部分是数组，说明它是普通文本类型；第二个是文件（file stream）；第三部分拿完后直接返回 undefined。所以每调用一次 parts，就返回一部分 multipart 数据，所有数据拿光后返回 undefined。数据有两种类型：文本类型时是一个数组；文件类型时是一个 file stream。

## 实现多文件上传

理解了原理就可以实现多文件上传了。需求是返回一个对象，里面有一项 urls，是一个包含多个上传成功 URL 的数组。

思路：多次调用 `await parts()` 直到没有数据。先构建最终想要的值 `const urls: string[] = []`。每一部分 part 有两种类型：文件类型是 file stream，普通表单是 string 的数组。用 while 循环，每次 `const part = await parts()`，停止条件写成表达式：有值就继续，变成 undefined 就停止。

循环体内先判断是哪类数据。如果是普通表单（用 Array.isArray(part) 判断，是数组说明不是文件），就不处理，直接跳过（调试时可以打印，最终代码里删掉）。另一种类型就是 file stream 了，这里 try/catch，逻辑和单文件一致：先生成要保存的路径，用 part.filename 拿文件名。可以看到 file stream 类型的属性补全都有效，因为 if/else 的 type guard 缩小了类型范围。

拿到路径后上传：`const result = await ctx.oss.put(savePath, part)`，然后从 result 中拿出 url，push 到 urls 数组。catch 里特别注意：要把可读流消耗掉，`await sendToWormhole(part)`，这一步很重要，然后再返回错误：`ctx.helper.error(ctx, 'uploadImageFail')`。

while 循环结束后，所有 url 都已生成，返回 `ctx.helper.success(ctx, { urls })`。

## 测试

选两个文件测试，点击 Send。可以看到返回了 urls，两个文件都上传成功，没问题。多文件上传的任务完成了。
