继续学习 setup 语法糖。上节课说了它的基本用法：顶层作用域的变量自动暴露给模板。但一个组件除了变量还有别的内容：审视 MyProfile 组件，很重要的就是它的属性 props 和发射的事件 emits。之前是在 defineComponent 的 object 上用 props 和 emits 两个字段定义的，setup 语法里怎么做呢？

## 编译器宏

setup 语法提供了两个编译器宏：defineProps 和 defineEmits。它们不需要导入，直接拿来使用，并且会随 script setup 的处理过程一同被编译掉。

defineProps 顾名思义用来定义属性。它接受的参数和 props 选项完全一样：比如有一个 user 属性，type 用 `Object as PropType` 获得更准确的类型：

```typescript
const props = defineProps({
  user: {
    type: Object as PropType<IPerson>,
    required: true,
  },
});
```

特别注意，如果不加 required: true，TS 会捕捉到 user 有可能是 undefined 的错误；加上之后错误立刻消失。

defineEmits 用法同样简单，参数和之前一样传事件名：

```typescript
const emit = defineEmits(['change']);
```

修改后刷新页面，App.vue 中一切正常运行。defineProps 和 defineEmits 也能做恰当的类型推论，props 和 emit 都能获得对应类型。

## 纯类型声明

这两个宏还有 TS 特供的升级用法：可以传递字面类型的纯类型语法作为参数，也就是通过传泛型的形式声明。这正是我们之前诟病的地方：事件没法标注准确的类型，现在可以改造了。

先改造 props，不用写运行时声明了，直接传泛型：

```typescript
const props = defineProps<{
  user: IPerson;
}>();
```

简单一行纯类型写法就完成了定义，props.user 显示为 IPerson 类型。

不过这种声明有不足：没法给 props 提供默认值。Vue 为此提供了 withDefaults 编译器宏，同样不需要导入。它接受两个参数：第一个是 defineProps 的调用，第二个是默认值对象：

```typescript
interface Person {
  name: string;
  age: number;
}

const props = withDefaults(
  defineProps<{
    user?: Person;
  }>(),
  {
    user: () => ({ name: 'Viking', age: 30 }),
  }
);
```

有默认值之后 user 改成可选即可。这里会触犯一条 ESLint 规则：当默认值是 object 时，必须以 function 的形式返回，不能直接写对象；普通类型（如 string）没有这个限制。不喜欢这条规则也可以关闭。改成箭头函数返回 object 后，错误消失。

withDefaults 还提供了对默认值的类型检查：虽然 user 声明为可选，但因为有默认值，props.user 最终会是必选的 IPerson 类型，它帮我们做了额外的工作。验证默认值：模板里不传 user 也没问题，刷新后页面显示了默认值的内容。

## 事件类型

再来看 emit 的类型声明。defineEmits 传一个 interface，事件写成函数签名的形式：第一个参数是事件名，第二个是要传出去的值，返回 void：

```typescript
interface IEvents {
  (e: 'change', hidden: boolean): void;
}

const emit = defineEmits<IEvents>();
```

现在 emit 有了准确的类型：第一个参数能自动补全事件名，第二个参数提示是布尔值；如果传一个字符串 'abc'，会报错 `string is not assignable to boolean`。

## 注意事项

defineProps 和 defineEmits 只能二选一：要么使用运行时声明（传入 object），要么使用类型声明（传入泛型），同时使用两种声明方式会导致编译报错。

## 小结

setup 语法有一个很重要的意义：完善了 TypeScript 的使用，让它更好地帮我们完成类型检查和类型推断。以后我们的组件都可以使用这种语法糖的书写模式。
