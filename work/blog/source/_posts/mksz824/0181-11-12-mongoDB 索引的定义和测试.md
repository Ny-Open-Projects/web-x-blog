学完增删改查，我们来学习一个新课题：索引。数据库索引大家多少都听说过，它通常能极大提高查询效率。

先补充一个背景。前面说过，可以把 MongoDB 存储的数据看成一个巨大的 JSON 对象，事实确实如此，只不过在上面做了优化：它的数据库文件格式叫 BSON。BSON 这个名字源于 JSON，前面是 B，也就是 Binary JSON，二进制 JSON，一种二进制表达形式，主要用作 MongoDB 的数据存储和网络传输格式。

假如没有索引，MongoDB 读取数据时就必须扫描这个巨大 BSON 集合中的每个文档，选出符合查询条件的记录。这种全集合扫描效率非常低，处理大量数据时一次查询可能花几十秒甚至几分钟，对网站性能是致命的，所以就有了索引。索引是一种特殊的数据结构，存储在一个易于遍历读取的数据集合中，是对数据库表中一列或多列的值进行排序的结构。

最简单的理解方式：查一本英文字典时有目录，目录针对每个字母所在的区域给出页码，我们不用从头翻到尾，直接看目录、从对应字母开始查就行。索引完成的是同样的任务。看这张图更清楚：图右侧是 collection 里的 documents，真正的文档，每个文档有很多属性。假设要按 last name 查，直接遍历右侧的文档集合，一条两条三条去查，速度肯定慢。所以我们建立了一个全新的数据结构，这就是索引。索引里用非常简单的数据结构，只存 last name，并将它和真正文档在集合中的位置建立对应关系，比如 Billy 对应某条文档。再次查询时就在这个优化过的简单结构里遍历，因为结构足够简单，查询非常快；查到 Billy 后通过对应关系很快定位到文档，查询效率就提升了，这就是索引的作用。

搞清了来龙去脉，用真实代码测一下索引的威力。原来的数据量太小，只有二三十条，感知不到索引的作用，所以先造五万条数据：创建一个 testArray，for 循环从 1 到 50000，把要插入的对象 push 进去，每个对象加一个 type 字段（和现有数据区分，删除时也方便）、name 字段（test 加上数字）、age 字段（数字类型），最后 await userCollection.insertMany(testArray) 把数组传进去并输出结果。运行脚本，不同性能的电脑耗时不一样，我这里很快就插完了五万条。

然后查最后一条记录（遍历是从上往下的，查最后一条花的时间最长）：find({name: 'test50000'})。要看查询分析，find 上有一个链式方法叫 explain，返回一系列和查询相关的信息，打印出来即可。运行后出现一堆数据，我们不深度解读，只看几个属性。重点关注 executionStats 里的内容：nReturned 为 1，查到一条；executionTimeMillis 是 21，花了 21 毫秒；totalDocsExamined 是遍历的文档数，50012，也就是五万加上原来的十二条。可以看到找到数据需要 20 毫秒左右，说明五万条数据起作用了，之前只有二三十条时这个时间都是 0，感知不到。

看完直接遍历查询的数据，再看索引的威力。_id 字段大家都记得，是 MongoDB 创建数据时自带的 ObjectID 类型，默认情况下它会自动创建索引，这是 MongoDB 默认的优化行为。所以先找到 _id，直接在数据库软件里查 name 等于 test50000 那条，把它的 _id 复制出来。然后写 userCollection.find({_id: new ObjectId('...')})，最后加上 explain 测试。运行后看分析输出：执行时间从 21 直接变成 0，totalDocsExamined 直接变成 1。使用索引后这两个数据大幅变化，索引确实有威力。

这节课搞清了索引的来龙去脉，并通过实实在在的数据观察分析了索引的威力。下节课简单学一下索引的操作，提高查询效率。
