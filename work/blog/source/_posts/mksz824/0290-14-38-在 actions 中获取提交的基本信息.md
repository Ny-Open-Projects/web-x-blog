在开始最后的流程合并之前，先完成一个预先任务。看现在的流程：构建时发布的镜像和部署到服务器使用的镜像，都是同一个写死的版本，而现实中肯定不能这样。需要解决两个问题：

1. 不是每次 commit 都需要构建并部署上线，只有特定情况下才发布。
2. 构建镜像时要使用和该次提交相关的特殊信息作为 tag，也就是说 YAML 里那些写死的版本号都要换成变量。

解决方案：常见的发布策略是 main 或 master 有提交或 merge 时才发布，更常用的是使用 tag（之前学 Travis 发布组件库时也用的 tag），tag 是标记版本的最好实践，这里也用 tag。tag 确定后，自然要拿到对应的 tag 名称作为镜像 tag；其他情况也可以选择 commit id，看你自己的意愿。

这节课的预先任务有三项：一是在 push tag 时才触发 job；二是学会获取每次提交相关的特殊信息；三是把特殊信息替换进文件。拿到变量后在 workflow YAML 里用比较简单，但 docker-compose-online 里就复杂些：要用一个占位符，再把占位符替换成拿到的信息。

## 触发条件：push tag

我创建了一个 tag-test.yaml，并把之前的两个 workflow disable 掉（不影响测试）。触发条件去查文档 events that trigger workflows：之前只简单讲过单一事件或数组，文档里还有更细的例子，比如 `on: push` 加 `branches`，可以限定在哪个 branch 提交时触发（main 有提交才触发 action）。我们想在 tag push 时触发，照猫画虎：

```yaml
on:
  push:
    tags:
      - 'v*.*.*'
```

事件还是 push，加上 tags，只有发布 tag 时才触发；tag 格式加数组项确定：v 开头加几个星号，代表版本有三位。第一个任务完成。

## 获取提交信息

job 名叫 test-tags，steps 第一步自然是 checkout（直接复制）。第二步获取具体信息，通过 GitHub Context 获取，文档叫 Context：You can access context information in workflows and actions。最早我们简单接触过但没细讲，现在看一下：有一系列上下文信息，github 是和提交、分支相关的信息，env 是环境变量，job 是和 job 相关的信息。我们需要的是 github，点开能看到 action、event、ref、sha 等非常多字段，都有具体解释。

测试三项信息：

```yaml
      # 测试 GitHub Context
      - name: Test github context info
        run: |
          echo ${{ github.ref }}
          echo ${{ github.ref_name }}
          echo ${{ github.sha }}
```

- `github.ref`：the branch or tag ref that triggered the workflow run，完整的信息。branch 时是一种格式，tag 时是另一种。
- `github.ref_name`：the branch or tag name that triggered the workflow run，直接拿到 branch 名或 tag 名，这是我们要拿 tag 时该用的变量。
- `github.sha`：触发这次 workflow 的 commit sha。有同学可能想用 commit id，它也是独一无二的，是很好的版本信息。

## 占位符替换

在 docker-compose-online 里替换占位符。可以用 Linux 命令，但更推荐一个写好的 action，就叫 find-and-replace，用起来非常方便：with 里有 find（查找哪个字符）、replace（替换成什么字符），还支持是否开启正则，以及 include（包含哪个文件）、exclude（不包含哪个文件）等参数。我认为它是查找替换的很好方案，文档贴在这里供以后参考：

```yaml
      # 测试查找并且替换
      - name: Find and replace
        uses: hiroyago/find-replace@v1
        with:
          find: "{{TAG}}"
          replace: ${{ github.ref_name }}
          include: "docker-compose-online.yaml"
```

先在 docker-compose-online 里把 0.0.2 直接替换成占位符。占位符可以随便写，只要是一个不容易重复的字符串即可，这里用两个花括号包一个 TAG。find 查找这个字符串，replace 成拿到的信息（github.ref_name，即 push 的 tag），include 限定只处理 docker-compose-online.yaml 这一个文件。最后测试替换是否成功：添加一个 run，cat 一下这个文件，看内容是否被替换。

保存后先用工具测一下语法有没有错，然后 push：commit（test tag info），特别注意打 tag 和 push 是两个过程，要单独打 tag。用 `git tag -a` 加版本号，之前打过 0.0.2，这次打 0.0.3；commit 打上 tag 后再用 `git push --tags` 提交 tag（tag 的 push 和 commit 的 push 是分开的两步）。

看结果：action 成功。点开 github context info：ref 输出了一长串完整信息；ref_name 是 v0.0.3，正是刚才打的 tag；sha 是一串与 commit 相关的独一无二的信息，说明成功。find replace 也成功：cat docker-compose-online，原来占位符的位置已被替换成 v0.0.3。

这节课完成任务，扫清了流程完全连接起来的最后障碍。下节课见证大一统的局面，把所有 action 组合在一起。
