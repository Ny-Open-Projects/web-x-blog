上节课通过两节内容介绍了中间件的知识。这节课介绍 Nitro 内置的另一个非常有用的模块：Storage Layer（存储层）。它内置了一套完全可扩展的存储层，可以实现一套简易的 Key Value 存储系统，默认使用内存来储存数据，同时还可以扩展使用各种熟悉的数据库或文件系统，提供了二十多种不同工具的驱动。

在底层，它使用的是第三方工具 Unstorage，slogan 是 Universal Key Value Storage，一看就知道它为 Key Value 这种存储类型提供了一套通用解决方案，用起来也非常方便。这节课学习它的基础用法，默认是内存存储。

结合一个实际情况：上节课写的 auth handler 用的是假数据（直接 Promise.resolve）。现在把假数据推进一下，实现一个具体的登录功能。登录方式还是点击即登录，然后看持久化的数据是否存在：存在就让 user 生效，没有就弹出对应的提示。

所以要添加一个登录接口。期望的 API 是 /api/users/login，POST 方法。在 users 下面新建 `login.post.ts`，用之前学的文件后缀名方式定义 method：

```ts
export default defineEventHandler(async (event) => {
  const body = await readBody<{ name: string }>(event)
  const storage = useStorage()
  await storage.setItem('current-user', body.name)
  return body.name
})
```

用 readBody 拿到 body，期望其中有一个 name 字段（可以用泛型标注它是 string），然后把一个叫 current-user 的数据保存到内存中。Nuxt 3 提供了全局函数 `useStorage`，它就是 Unstorage 这个 layer 的实例，调用它就拿到了实例，可以直接使用。Key Value 存储系统里最常见的方法是 setItem，第一个参数是 key（这里叫 current-user），第二个是要储存的数据。最后把数据返回出去，这样通过登录过程，数据就持久化到了 storage 中。

前端添加一个简单的登录过程：把 send 函数的 URL 改成 users/login，name 传 Viking。

下一步在 auth handler 里把储存的数据取出来，替换掉假数据。从 setItem 就能猜到 useStorage 上有另一个方法 getItem：

```ts
const userName = await useStorage().getItem<string>('current-user')
```

特别注意 key 不要打错，应该是 current-user。想返回得更精确，可以传泛型（储存的是 string 类型的 userName），这样 user 变成了对应的 string 或 null 类型，就可以判断了。假如 user 不存在，把 error 抛出去；存在则继续下一步操作。

验证功能。访问 user one 这个路由，返回 401 unauthorized，因为现在还没有储存任何值，接口返回的是 null。然后点击 login，让请求储存对应的数据，成功后再访问 /api/users/1，就能成功进入路由了。在 DevTools 的 Payload 里也能看到期望的数据已经通过 useStorage 保存在内存中了。

这就是 useStorage 的简单用法。除了这两个最常用的 API，它还有很多其他 API，看名字基本能知道用途，有兴趣可以课后感受一下。
