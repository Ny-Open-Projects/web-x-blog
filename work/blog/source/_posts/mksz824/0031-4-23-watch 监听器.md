这节课学习 Composition API 的一个新内容：watch 监听器。之前学过的 ref 和 reactive 作为响应式对象，可以让视图随数据变化而更新；computed 可以根据响应式对象的值创建派生状态。但还有一类需求：状态发生变化时，直接执行一些其他逻辑，即副作用（Side Effects）。比如值变化时要修改 DOM，Vue 提供了 watch 这个 API 来完成。大家可以结合官方文档来对照例子。

## 监听一个 ref

最简单的用法：watch 的第一个参数传一个响应式对象，第二个参数是回调函数，回调里可以拿到新值和旧值两个参数。现在实现一个需求：点击次数变化时，把浏览器标题更新成当前点击数。

```typescript
import { ref, watch } from 'vue';

const count = ref(0);

watch(count, (newValue, oldValue) => {
  console.log('old count', oldValue);
  console.log('new count', newValue);
  document.title = `目前点击的数是 ${newValue}`;
});
```

点击 increase 之后，count 变化触发回调：old count 是 0，new count 是 1，标题也被更新成了当前点击次数。

## 监听 reactive 的属性

如果要监听一个 reactive 对象的属性，比如 user.age，直接写 `watch(user.age)` 会报类型错误，因为属性值是普通的 number，watch 的第一个参数必须是响应式对象。这时要用 getter function 的形式，传入一个返回想监听值的函数：

```typescript
watch(
  () => user.age,
  (newAge, oldAge) => {
    document.title = `目前点击次数 ${newAge}`;
  }
);
```

特别要注意这个写法：不能直接写 user.age，必须以 getter function 的形式返回要监听的值。点击后可以看到 old age 和 new age 被正确打印，标题也更新了。

## 监听整个 reactive 对象

也可以直接把 reactive 对象传给 watch，比如 `watch(user)`。这时会隐式创建一个深层监听器，对象上任何嵌套属性的变更都会触发回调。特别注意：这种情况下 newValue 和 oldValue 是同一个对象，值完全相同。

TypeScript 的类型推论在这里也能发挥作用：传入 count 是 ref<number> 时，新旧值会被推断成 number；传入 user 时会被推断成它的类型。这样使用起来很方便。

不过要留意性能：如果 watch 的是一个大型、属性众多且嵌套很深的数据结构，深层监听开销很大。假如只需要监听单个属性，建议改成 getter function 的形式。

## 数组形式

watch 还可以传入一个数组，数组中的每一项都可以是前面说的任意形式，比如 `[count, () => user.age]`。当 watch 一个数组时，回调拿到的值也是数组，按传入顺序排列：第一项对应 count，第二项对应 user 的 age。

## 立即执行

目前的 watch 都要等状态更新后才调用。如果希望监听器创建后立即执行一次，可以传第三个参数，它是一个对象，设置 immediate 为 true（默认 false）：

```typescript
watch(count, (newValue, oldValue) => {
  console.log('old count', oldValue);
  console.log('new count', newValue);
}, { immediate: true });
```

刷新页面就能看到：还没点击按钮就执行了一次，old count 是 undefined，new count 是 0。之后再点击会继续正常运作。

## 回调触发时机

默认情况下，watcher 回调都会在 Vue 组件更新之后被调用，这意味着回调中访问到的 DOM 是被 Vue 更新之前的状态。验证一下：给 h1 加一个 id，在回调里用 `document.getElementById('age')?.innerHTML` 输出它的内容。这里用了问号的简写：getElementById 可能返回 null，问号会先判断节点存在再访问属性，是更安全的写法。

点击 increase 后，DOM 输出的是旧值 8，而页面上的值已经是 9，验证了"回调先于 DOM 更新"的说法。要修改这个机制，可以在参数对象里设置 flush：默认是 pre（之前），改成 post 后，回调会在 DOM 更新完毕后再调用，此时输出的就是 9 了。

## 小结

这节课学了监听器的几种形式：直接监听 ref、getter function、直接监听 reactive、数组形式；以及立即执行的 immediate 参数和回调触发时机的 flush 参数（默认 pre，可改成 post）。
