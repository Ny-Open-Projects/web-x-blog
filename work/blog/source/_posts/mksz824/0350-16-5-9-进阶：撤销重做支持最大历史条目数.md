这节课完成 undo/redo 的最后两个优化：一是历史记录的最大条目数限制，二是回滚途中重新编辑的处理。

## 两个问题的思路

**第一个问题**很简单：需要一个可配置的值规定最大条数，然后判断 histories 数组的长度是否超过它。没超过就直接 push；超过了为了保证总数不超过上限，先删掉第一项，再添加到最后一项。大多数人都能想到这个解法。

**第二个问题**先明确需求。操作一遍：给元素依次添加「挪动位置、变大、改粗体、改斜体」几条记录，然后连续撤销几次，回到只剩位置改变的状态。此时再添加新操作（输入 x y z），新记录默认是追加在 history 末尾的，但我们想要的是：把回滚点之后的旧操作全部删掉，新操作接在当前位置后面，并且 index 要重置成「没有操作过」。大家可以多操作几遍，或者用 VS Code 自己试试，体会这个需求。

最终得到的需求描述：检查是否处于历史回滚途中（`historyIndex !== -1` 表示已经移动过）；如果移动过，把之后的所有记录清除，再 push 新操作；最后把 `historyIndex` 重置为 -1。

## 编码

### 添加最大条数配置

在 `EditorProps` 里新增一项：

```ts
maxHistoryNumber: number
```

初始值设为 5，方便等会儿测试。

### 新建 pushHistory 方法

用一个新方法替代当前直接往 histories 里 push 的操作，两个参数：`state`（EditorProps）和要写入的 `historyRecord`（HistoryProps）。逻辑配上注释：

```ts
function pushHistory(state: EditorProps, historyRecord: HistoryProps) {
  // 判断当前条目数
  if (state.histories.length < state.maxHistoryNumber) {
    // less than max number，直接 push
    state.histories.push(historyRecord)
  } else {
    // larger than max number：shift first, push to last
    state.histories.shift()
    state.histories.push(historyRecord)
  }
  // check historyIndex is already moved
  if (state.historyIndex !== -1) {
    // delete all the records after the index
    state.histories = state.histories.slice(0, state.historyIndex)
    // move historyIndex to unmoved
    state.historyIndex = -1
  }
}
```

超过上限时用数组的 `shift` 删第一项再 push 到最后，保证条数不变。后半段处理回滚途中编辑的情况：`historyIndex` 不等于 -1 说明已经移动过，用 `slice(0, historyIndex)` 保留到当前位置为止的记录（相当于删掉之后的），然后把 index 重置为 -1，代表没有移动过。

有注释之后逻辑很清楚，和思路完全一致。

### 替换调用点

把 `addComponent`、`updateComponent` 等所有直接 `state.histories.push` 的地方，逐个替换成新的 `pushHistory` 方法。

## 验证

多添加几条记录（移动位置、修改大小、加粗、改斜体），然后连续回滚到只剩位置改变那条。此时添加新文本 x y z：历史记录只剩两条，位置改变和新的文本修改，之后的旧记录被清掉了；因为回到了「最新」状态，redo 按钮不能再往前重做，只能继续撤销。点两次撤销，先回到 hello，再回到元素最初的位置。

历史记录最大数的优化完成。这个逻辑不难，重点是「回滚到一半后重新编辑」这个场景的处理要想清楚：之后的记录删除、新记录从当前指针开始、index 重置。
