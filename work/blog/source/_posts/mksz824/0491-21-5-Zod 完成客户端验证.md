上节课介绍了 Zod，这节课用它完成登录界面的前端验证。最终效果是：输入信息点击 sign in 后，错误能显示出来。写代码之前我先做了一点修缮：把 global header 里原来自动登录的测试代码删掉，加了一些简单样式让界面更清晰。

## 准备工作

上节课在 app 里写过测试用的规则，测试登录需要 email 和 password 两条规则。我把它们放到了一个专门的文件夹：项目根目录下的 `validators/user.ts`，和 user 相关的验证都写在这里。代码直接从上节课拷贝过来。

正式编码第一步是把 schema 导入进来，路径是 `validators/user`，schema 名称为 `userLoginSchema`。然后准备响应式数据，Vue 相关的 API 都是自动导入的，不需要手动 import：

```ts
const formData = reactive({
  email: '',
  password: ''
})
```

把这两个数据通过 `v-model` 绑到两个 input 上，分别是 `formData.email` 和 `formData.password`。接着在表单上添加 submit 事件，加 `.prevent` 修饰符阻止默认提交行为，处理函数是 `login`。

## 执行验证

`login` 里使用上节课学的 API，用 `safeParse` 而不是 `parse`，不抛错误而是返回对象：

```ts
const result = userLoginSchema.safeParse(formData)
if (!result.success) {
  console.log(result.error?.issues)
  return
}
// 验证通过，继续登录流程
```

测试一下：什么都不填直接点 sign in，出现两个错误，一个是 email 的，一个是 password 的；满足规则后（password 至少六位，我们写七位）就能成功登录。验证已经起作用了。

## 把错误展示到界面

下一步是把错误信息显示到界面上：先拿到错误信息，再通过响应式对象赋值。目前 `issues` 是数组格式，不友好，要遍历查找每条错误属于哪个字段。Zod 贴心地提供了 `error.format()` 方法，调用后会生成更友好的对象形式：email 的错误放在 `_errors` 数组里，password 同理。所以只需取 errors 数组的第一项展示即可。

创建两个 ref 分别放置两类错误，我完成 email 的，password 规则完全相同，大家可以自行补上：

```ts
const emailError = ref<string[] | undefined>()
```

初始值是 undefined；出现错误时赋值。注意 `error.format()` 返回的 email 字段可能不存在，取值时要加问号。为了让类型更完美，给 ref 传入泛型：`string[] | undefined`，和实际值保持一致，方便后续判断。

界面上要显示两部分：错误信息和 input 的错误样式。正常情况下 input 的 border 是 gray-200，出现错误时变成红色。这里有个细节：模板拷贝过来的代码样式已过时，`border-gray-200` 并没有显示出来，需要单独加一个 `border` 类（代表 border width 1px）边框才出现。把它加到两个 input 上。

然后用动态 class 做判断：有 emailError 时添加 `border-red-500`，否则用默认的 `border-gray-200`。点击验证，红色边框成功出现。

错误文字放在 input 下面一行小字：在外层 div 里加一个 span，类名用 `text-red-500`（和边框颜色一致）、`text-xs`（12px）再加斜体 `italic`。渲染时先判断 emailError 是否存在，type guard 生效后它已经是数组类型，直接取第一条即可，不需要额外判断：

```vue
<span v-if="emailError" class="text-red-500 text-xs italic">
  {{ emailError[0] }}
</span>
```

保存后点击 sign in，界面上出现了 invalid email 的提示。最后别忘了一个细节：在验证通过的分支里把 emailError 重置为 undefined，否则上一次的错误会短暂停留在界面上。

到这里客户端登录验证就完成了。password 的验证请大家自己补上，我也会在提交的代码里添加，想了解写法可以看提交的代码。下节课在服务器端实现同样的验证。
