## 思路：HTML 默认的 drag 操作

从第一步开始：拖动开始（dragstart）有两个具体需求，被拖动条目的状态变化，以及拖动时出现浮层。

一个常见的想法是：添加 mousedown 事件，检查当前的 target 是哪个元素，按下去以后给它添加特定状态（比如蓝色背景，代表这个元素正在被移动）；然后添加 mousemove 事件，拖动时创建一个和被拖动元素一模一样的浮层，被拖动元素本身还在，上面创建一个定位为绝对定位、随鼠标坐标更新的浮层。这样做肯定可以，但会有更多的逻辑和代码，比较繁琐。

我们使用一个全新的概念：开发 Uploader 组件时做过类似 drag and drop 的功能，这里要使用 HTML 默认支持的拖拽操作，也就是 drag，我认为它是更方便快捷的选择。它是浏览器默认的拖拽行为，默认支持三种元素：图像、链接和选中的文本。可以做个实验：拖动一个链接，它有一个特定的拖拽效果；选一段文本拖拽，也有默认效果。

但我们要拖拽的是 HTML 节点，也就是 UL 中的一项。默认情况下，除上述三种元素外的其他元素都是不可拖拽的。HTML 提供了 `draggable` 属性，添加以后会发生神奇的魔力。给 li 添加 `draggable="true"`，特别注意，属性的值必须写成字符串的 `"true"`。

保存后到应用里感受一下：拖动对应的条目时，它会自动生成一个半透明的条目，并且跟随鼠标移动。一个简单的属性就完成了之前一大堆要模拟的逻辑，何乐而不为？

## dragstart 事件与状态标记

现在想想我们要完成的特性：给被拖动元素添加特殊状态。和鼠标事件类似，也有一系列事件可以监控拖动的进度，首当其冲的就是 `dragstart`（开始拖拽）。可以在 dragstart 中修改被拖拽元素的样式。

首先需要一个响应式对象记录现在被拖拽的是哪个 id 的条目。因为可能有多个数据，创建一个 reactive 的 `dragData`，里面添加 `currentDragging`，初始为空字符串。再创建一个 `onDragStart`，第一个参数是 dragging event，第二个参数是传进来的 id；内部把 `dragData.currentDragging` 设置为 id，代表现在正在拖动这个元素。

把这两者 return 出去，然后在模板的 li 上添加 `@dragstart`，调用 `onDragStart`，第一个参数是 event 事件对象，第二个是 `item.id`。

接着添加对应的 class 让它显示不一样的结果：li 上添加一个称为 ghost 的 class，当 `dragData.currentDragging === item.id` 时添加。ghost 样式很简单，设置 opacity 为 0.5，半透明效果。

看最终结果：开始拖动时，图层一变成了半透明效果；拖动图层二，图层二也变成半透明。交互完成。

## DataTransfer 的额外能力

查看文档，dragstart 事件中可以使用 DragEvent 设置更多有意思的内容。DragEvent 中有一个特别有意思的属性叫 `DataTransfer`，上传文件时我们也接触过它。可以用它设置拖拽中的数据：DataTransfer 有一个 `setData` 方法，可以设置 drag 过程中携带的一系列数据。另外还可以设置拖拽的反馈图像：文档中写到，当拖拽发生时，会生成拖拽目标的一个半透明图像，并在拖拽过程中跟随鼠标指针，这个图像是自动创建的，不需要自己创建，就是我们看到的那层浮层。如果想自定义，可以用 `setDragImage` 方法，有兴趣可以去看看文档。

## drop 事件与 preventDefault 的坑

接下来是松开鼠标时让特定状态消失，不加思索就能想到添加 drop 事件，上传文件时也处理过这个事件。创建一个 `onDrop`，参数同样是 DragEvent，内部把 `dragData.currentDragging` 恢复到初始值（空字符串）。

由于这个事件是冒泡的，可以把 onDrop 放在 UL 上面：`@drop="onDrop"`。但测试发现：放下以后状态并没有被清除，onDrop 事件本身没有被触发，里面的逻辑根本没走。

原因在文档下方的"指定放置目标"章节：网页或应用程序的大多数区域都不是放置数据的有效位置，因此这些事件的默认处理是不允许放置（drop）。正因为不允许放置，drop 根本没有触发。想要允许放置，必须取消 dragenter 和 dragover 事件的默认行为，也就是调用 `e.preventDefault()`。

所以创建一个 `onDragOver`，参数还是 DragEvent，内部只需调用 `e.preventDefault()`，把它 return 出去并添加到模板上：`@dragover="onDragOver"`。

再测试：拖动图层一然后放下，onDrop 被成功触发，状态恢复原样。
