# 定制化排序的骚操作

默认相关度评分（BM25）往往不能满足业务排序需求。本篇把「前缀匹配提权、关键词加权、高斯衰减、rescore 二次精排、pinned 置顶」这几类实战排序手段串起来，全部给出可跑的 DSL 思路。注意：**额外的排序逻辑必然拖慢查询，要在响应时间和排序效果之间权衡。**

## 纲要

- `function_score` + `script_score` 实现前缀匹配文档提权（需 keyword 子字段）
- `function_score` 的 `filter` + `weight` 实现指定关键词翻倍加权
- 三种衰减函数 `linear / exp / gauss` 及 `origin/offset/scale/decay` 参数
- `boost_mode` 五种组合方式（total/multiply/avg/min/max）
- `rescore_query` 先广召回再精排，兼顾性能
- 7.5+ 的 `pinned query` 把热点文档置顶

## 前缀匹配提权

想让「以『测试』开头的文档」排更靠前，用 `function_score` 包一个 `script_score`：脚本判断字段是否以指定前缀开头，命中返回 1 分，再用 `boost_mode=sum` 叠加到相关度上。

```mermaid
flowchart LR
    A["match 召回文档"] --> B["function_score"]
    B --> C["script_score 判断前缀"]
    C --> D["命中 +1 分"]
    D --> E["boost_mode=sum 叠加"]
```

```json
{
  "query": {
    "function_score": {
      "query": { "match": { "name": "测试" } },
      "functions": [
        {
          "script_score": {
            "script": "doc['name.keyword'].value.startsWith('测试') ? 1 : 0"
          }
        }
      ],
      "boost_mode": "sum"
    }
  }
}
```

> **坑**：`name` 是 `text` 类型，分词后 `doc['name']` 拿不到原始文本。必须为 `name` 建一个 `keyword` 子字段（`fields`），用 `doc['name.keyword'].value` 才能取到原文。

## 关键词加权与衰减函数

包含指定关键词的文档整体翻倍，用 `filter` + `weight` 即可：

```json
{
  "query": {
    "function_score": {
      "query": { "match": { "name": "iphone" } },
      "functions": [
        { "filter": { "match": { "name": "plus" } }, "weight": 2 }
      ],
      "boost_mode": "multiply"
    }
  }
}
```

衰减函数适合「越新/越近/越便宜越好」的场景（发布时间、价格、地理距离）。以商品价格为例，`origin` 取受欢迎价格区间中点，`offset` 内满分，`scale` 控制衰减速率：

```json
{
  "query": {
    "function_score": {
      "query": { "match": { "name": "iphone" } },
      "functions": [
        {
          "gauss": {
            "price": { "origin": 2500, "offset": 2500, "scale": 1000 }
          }
        }
      ],
      "boost_mode": "multiply"
    }
  }
}
```

| 参数 | 含义 | 备注 |
| --- | --- | --- |
| `origin` | 中心点/最佳值 | 落其上评分=1 |
| `offset` | 偏移量范围 | 该范围内均满分 |
| `scale` | 衰减速率 | 从 origin 起衰减速度 |
| `decay` | 衰减到 scale 处评分 | 默认 0.5，一般不动 |
| `boost_mode` | 分数组合方式 | total/multiply/avg/min/max |

三种衰减函数形态：`linear` 直线、`exp` 先剧后缓、`gauss` 钟形（最常用，先缓→快→缓）。

## rescore 二次精排与 pinned 置顶

`match` 召回率高但 `match_phrase` 精排贵（带 slop 时约慢 10 倍）。先用 `match` 广撒网，再用 `rescore` 只对前 N 条用短语查询精排，兼顾性能：

```json
{
  "query": { "match": { "name": "测试" } },
  "rescore": {
    "window_size": 10,
    "query": {
      "rescore_query": {
        "match_phrase": { "name": { "query": "测试", "slop": 1 } }
      },
      "query_weight": 0.7,
      "rescore_query_weight": 1.2
    }
  }
}
```

7.5+ 提供的 `pinned query` 可把指定文档 ID 的权重钉在前面（热点商品运营置顶）：

```json
{
  "query": {
    "pinned": {
      "ids": ["6", "8"],
      "organic": {
        "bool": {
          "must": [
            { "term": { "category": "phone" } },
            { "match": { "name": "iphone" } }
          ]
        }
      }
    }
  }
}
```

```dir
定制化排序手段/
├── function_score/
│   ├── script_score     # 前缀/自定义逻辑提权
│   ├── filter+weight    # 关键词加权
│   └── gauss/exp/linear  # 衰减函数
├── boost_mode/           # total/multiply/avg/min/max
├── rescore_query/        # 前N条二次精排
└── pinned query/         # 7.5+ 文档置顶
```

## 总结

定制化排序的本质是在 BM25 之上叠加业务规则：**前缀/自定义判断用 `script_score`（务必走 keyword 子字段）**；指定关键词加权用 `filter+weight` 配 `boost_mode=multiply`；随时间/价格/距离衰减用 `gauss` 钟形函数最自然；要在性能和精排间取舍就用 `rescore` 只对前 N 条做短语精排；热点文档置顶用 7.5+ 的 `pinned query`。记住一点——这些额外排序都会增加查询开销，排序越复杂响应越慢，生产上要实测 P95/P99 再定方案。
