## 元信息驱动：低代码的第一性原理

低代码的本质一句话：**用元信息（Schema/DSL）描述应用，由通用引擎解释执行，把"写代码"变成"配数据"**。页面 = 一份 JSON，应用 = 一组 JSON + 一套引擎。

三个推论：
1. 编辑器与运行时共享同一份数据契约——编辑器是数据的"可写视图"，运行时是"只读投影"。
2. 一切画布操作（拖拽、排序、删除）本质都是对数据结构的增删改，视图只是投影。课程编辑器把组件配置存成 MobX 字典 + 排序数组，视图只是渲染这两个数据源。
3. 因为产物是数据，天然可序列化、可版本管理、可跨端消费（编辑端 React / 发布端 Next.js SSR 用同一套 share 组件渲染同一份配置）。

**本项目实例**：组件属性以 JSON 存 component 表的 `options` 字段（simple-json 列），页面顺序由 page 表的 components id 串表达。

**边界**：适合"模式可枚举"的场景（表单/后台/官网）；强定制 C 端动效不适合。
