## 撤销/重做的实现模型：状态快照与命令模式

编辑器的撤销/重做本质是对 Schema 数据做**快照栈**：每步操作前压入当前状态，undo 弹栈恢复、redo 反弹。两种实现路线：命令模式（记录操作+逆向操作）vs 快照模式（直接存状态副本）。快照实现简单，适合结构化 JSON 数据。

**本项目实例**：课程版用 `mobx-shallow-undo` 包住 MobX store——shallow 只是快照间的比较/去重方式，快照函数是对整份 store 做 toJS 深拷贝——每步操作 O(组件数) 内存，大页面有放大，这是能讲清楚的实现取舍；`hasUndo/hasRedo` 用于兜底提示（无可撤销时 message.warning）。键盘层用 ahooks `useKeyPress` 统一捕获 Cmd+Z / Cmd+Shift+Z（Mac）。

**本项目实例**（自研参考实现）把同一思想推广到工作流：编辑操作均落到图 DSL JSON，快照天然可序列化。

配套的键盘操作家族：上移/下移（arrayMove + 边界提示）、删除（同时清排序数组与配置字典并重设选中）、复制粘贴（**必须 ulid 重新分配 ID**，否则粘贴项与原项共抢一个 key）。

核心思想一句话：视图操作 = store 数据的增删改查，撤销重做只是给这份数据加了个时间维度。
