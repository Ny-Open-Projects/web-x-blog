## 纲要

- **两类相似度度量**：欧式距离（L2，越小越相似，完全重合 = 0）；余弦相似度（夹角余弦，范围 −1~1，1 同向完全相同，忽略向量长度，适合文本 / 高稀疏数据）。Chroma / Milvus 均支持自定义度量。
- **为什么需要索引**：索引 = 快速检索定位的方法（如图书馆「书架-层-格」）；无索引即 Flat 全表扫描（query 与 base 逐一算相似度再排序取 top-k），小数据或 GPU 并行尚可，大数据慢。
- **近似最近邻（ANN）**：以少量精度换速度，不直接保 100% 精确，适合语义向量场景。
- **IVF 倒排文件索引**：kmeans 将数据集分 k 块、块中心作索引；检索先找最近块中心、块内再全表扫描取 top-k（千万向量分 1000 块：原 1000 万次 → 约 1.1 万次）；选多个块中心可提精度。
- **HNSW（分层可导航小世界）**：Chroma 默认索引；分层图索引，从上往下「粗→细」检索；层数符合指数衰减（第 0 层全量，越往上越少）；支持千万级，但**耗内存**。
- **PQ 乘积量化**：用 int8 替 float32 构建索引，压缩高维向量，省 ~97% 内存、检索提速 ~5.5 倍；过程＝向量切 m 子向量 → kmeans 分 256 块（uint8 范围）→ 子向量用块 ID（0–255）表示 → 原向量降为 m 维 int8。
- **索引选型（按准确性 + 数据量）**：100% 精确只能 Flat；512 维 float32 下，<10MB（≈千条）用 Flat；10MB~2GB（≈百万条）用 IVF；2GB~20GB（≈千万条）用 HNSW 或 PQ+IVF 混合；>20GB（≈亿条）用 PQ+HNSW+IVF 混合。
- 本章按课程口径重构；算法名已规范化（Flat / IVF / HNSW / PQ / kmeans）；剥离营销与课程群引流。

## 一、两种相似度度量

- **欧式距离（L2）**：各元素差的平方和开根；越小越相似，完全相同为 0。
- **余弦相似度**：两向量夹角余弦，范围 −1~1；1 表示方向完全相同，−1 相反。**关键优势是忽略向量长度**——非常适合文本（不受文档长短影响）与高稀疏数据（只看非零元素贡献）。
- 两者都可在 Chroma / Milvus 中手动设定，可对比哪种对结果更好。

## 二、Flat 与 ANN 索引

- **Flat（全表扫描）**：query 与集合中每个向量逐一算相似度 → 排序 → top-k。耗时在相似度计算与排序；数据小或 GPU 并行可接受。
- **ANN（近似最近邻）**：用划分或特殊数据结构减少计算量、加速，但不保 100% 精确——语义向量本身已是压缩表示，差一点数值通常影响有限。

## 三、IVF 倒排文件索引

- **构建**：kmeans 把数据集划分为 k 块，块中心作为索引（类比图书馆书架）。
- **检索**：先算 query 与块中心的相似度找最近块 → 块内全表扫描取 top-k。
- **效果**：千万向量分 1000 块（每块约 1 万），计算量从 1000 万次降到约 1000+1 万 = 1.1 万次。
- **提精度**：初步筛选时选多个块中心（如 top-3），扩大召回范围。

## 四、HNSW 分层可导航小世界

- **特点**：Chroma 默认索引；分层图结构，从粗到细检索。
- **构建四步**：① 决定层数；② 每层数据量指数衰减（第 0 层全量，往上递减，如 1 万→280→7）；③ 按衰减量随机抽数据分层；④ 每层为每个点连 k 近邻建图。
- **检索**：从最上层随机切入点出发，逐层在 k 邻居中找最近点，直到第 0 层。支持千万级，但**内存占用大**。

## 五、PQ 乘积量化

- **动机**：高维 float32 向量占用大（数据内存 + 索引内存），PQ 用 int8 替 float32。
- **构建三步**：① 向量切 m 个子向量；② 对 n×m 子向量 kmeans 分 256 块（ID 0–255 = uint8）；③ 每个子向量用块 ID 表示 → 原向量降为 m 维 int8。
- **检索**：query 同样切 m 块、映射到块 ID，再用新向量在索引中检索最近。
- **收益**：省 ~97% 内存，最近邻检索提速 ~5.5 倍。

## 六、索引如何选

- 需要 100% 精确 → 只能 Flat。
- 512 维 float32 估算：5000 条≈10MB。
 - <10MB（≈千条）：Flat 足够；
 - 10MB~2GB（≈百万条）：IVF；
 - 2GB~20GB（≈千万条）：HNSW 或 PQ+IVF；
 - >20GB（≈亿条）：PQ+HNSW+IVF 混合。

## 七、FAQ

**Q1：余弦和欧式怎么选？**
文本 / 长文档 / 稀疏向量优先余弦（忽略长度）；关注绝对距离差异用欧式。

**Q2：IVF 为什么是「近似」？**
块划分不精确可能漏掉真正最近向量，故取多块中心提升召回。

**Q3：HNSW 最大缺点？**
内存占用高；常与 PQ 组合降内存。

**Q4：PQ 真能省那么多内存吗？**
float32→int8 且维度 m 远小于原维度，理论可省 ~97% 内存、提速 ~5.5 倍。

## 八、面试高频问答

**1. 列举两种向量相似度并说区别。**
欧式距离（越小越相似，看绝对距离）；余弦相似度（看方向，忽略长度，更适合文本）。

**2. 什么是 ANN？为什么 RAG 常用？**
近似最近邻，牺牲少量精度换速度；语义向量本身压缩，数值略差影响小。

**3. IVF 与 HNSW 的检索思路？**
IVF：kmeans 分块，先找最近块再块内扫描；HNSW：分层图，自上而下粗到细。

**4. 给一个索引选型经验法则。**
千条 Flat；百万 IVF；千万 HNSW/PQ+IVF；亿级 PQ+HNSW+IVF。

## 九、ops 提示（增效）

> **精度可妥协**：语义检索不必追求 100% 精确，ANN 性价比高。
>
> **内存是 HNSW 痛点**：亿级或内存紧 → 上 PQ 压缩。
>
> **IVF 提召回**：初筛多取几个块中心，精度换少量计算。
