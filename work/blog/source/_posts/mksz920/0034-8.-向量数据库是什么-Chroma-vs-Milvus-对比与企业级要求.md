## 纲要

- **向量数据库定义**：存储「文档 + 其 embedding 向量」的数据库，提供特定存储结构与索引算法，高效存储 / 查询 / 处理向量数据；RAG 中**查询性能**是关键指标（千万级向量要考虑检索延迟）。
- **与关系型数据库对比**：都支持持久化、增删改查（RAG 侧重查询）；向量库必备相似度计算；关系库按字段建 B+ 树索引，向量库按高维向量建 IVF / PQ 等索引。
- **两大主流开源库**：
 - **Chroma**：AI 原生、极简、易上手；支持本地 / 服务端部署（`pip install` + `chroma run`），多语言（Python/JS），LangChain / LlamaIndex 已集成；适合千万级以内、中小型项目。
 - **Milvus**：云原生、灵活可靠快；支持本地 / 服务端 / 分布式（本地百万、服务端千万、分布式亿级），支持 GPU 加速、metadata 过滤、访问权限控制；需先声明 schema 再建集合、手动建索引；适合中大型项目。
- **企业级三要求**：可扩展性（加节点扩容量 / 算力）、吞吐量（QPS 压测）、稳定性（故障不丢数据、备份恢复、监控告警）。
- 本章按课程口径重构；产品 / 框架名已规范化（Chroma / Milvus / LangChain / LlamaIndex / B+ 树 / IVF / PQ）；剥离营销与课程群引流。

## 一、什么是向量数据库

- 把数据对象的语义向量与原文一并存储，并通过专用索引算法实现高效相似检索。
- **与 MySQL 等关系库异同**：都持久化、都增删改查（RAG 重查询）；向量库多「相似度计算」；索引机制不同——关系库按字段（B+ 树），向量库按高维向量（IVF / PQ 等）。

## 二、Chroma：易上手的 AI 原生库

- 安装简单（`pip install chromadb`），`chroma run --path ... --host ... --port 8000` 起服务端。
- 操作范式：`create_collection(name,embedding_function)` → `add(documents,ids,metadatas)` → `query(n_results)` 检索；metadata 可做混合过滤。
- 对千万级向量友好，分布式支持尚不成熟；**默认仅 HNSW 一种索引**，创建集合即自动建索引。
- 适合中小型项目、快速入门。

## 三、Milvus：云原生分布式库

- 容器化部署（Docker / docker-compose），`pymilvus` 连接（`host=127.0.0.1,port=19530`）。
- 与 Chroma 区别：**建集合前需声明 schema**（PK、文档字段、embedding 向量字段及维度、metadata 字段）；入库需手动把文档转向量再插入；**需手动 create_index**（可选多种索引类型与相似度）。
- 原生支持分布式（亿级）、GPU 加速、权限控制、混合查询（metadata + 向量）。
- 功能更完备，适合中大型项目。

## 四、Chroma 与 Milvus 对比小结

| 维度 | Chroma | Milvus |
|---|---|---|
| 部署 | 本地 / 服务端 / 云；分布式不成熟 | 本地 / 服务端 / 分布式（云原生） |
| 索引 | 仅 HNSW（自动） | 多种（需手动建） |
| 权限/监控 | 暂无 | 支持权限 + 监控 |
| 适用 | 中小型、易上手 | 中大型、功能完备 |

## 五、企业级向量数据库三要求

1. **可扩展性**：数据 / 访问量增长时能否加节点扩展容量与算力。
2. **吞吐量**：高并发下能否短时处理更多请求——通过 QPS（每秒查询数）压测预判是否需加资源或重设计。
3. **稳定性**：故障时不丢数据、可备份恢复、有监控告警辅助运维。

## 六、FAQ

**Q1：向量库和关系库能互相替代吗？**
不能。向量库专为高维向量相似检索设计（IVF/PQ 索引），关系库擅长字段索引的事务查询；RAG 以向量库为主，常配合关系库存结构化元数据。

**Q2：Chroma 和 Milvus 怎么初选？**
想快速验证、数据量千万内 → Chroma；要分布式、亿级、权限管控 → Milvus。

**Q3：Milvus 为什么建集合要先声明 schema？**
因它支持多种字段与索引类型，需先定义 PK / 文档 / 向量维度 / metadata 才能正确建表与建索引。

**Q4：企业选向量库最该盯哪三点？**
可扩展性、吞吐量（QPS）、稳定性（备份 / 恢复 / 监控）。

## 七、面试高频问答

**1. 向量数据库与关系数据库的核心区别？**
索引对象不同：关系库按字段（B+树），向量库按高维向量（IVF/PQ/HNSW）；向量库必备相似度计算，RAG 侧重查询。

**2. Chroma 与 Milvus 各自定位？**
Chroma 简易 AI 原生、适合中小 / 千万内；Milvus 云原生分布式、适合中大型 / 亿级，含权限与监控。

**3. 企业级向量库的三个硬指标？**
可扩展性、吞吐量（QPS）、稳定性（备份恢复 + 监控告警）。

**4. 为什么 Milvus 需要手动建索引而 Chroma 不用？**
Chroma 仅 HNSW 且自动创建；Milvus 支持多种索引，需按场景主动指定类型与相似度。

## 八、ops 提示（增效）

> **选型看规模**：中小选 Chroma，亿级 / 分布式选 Milvus。
>
> **元数据很关键**：用 metadata 做预过滤，能大幅降低向量检索范围、提精度。
>
> **压测先行**：上线前用 QPS 压测验证吞吐与稳定性，别只看功能。
