## 纲要

- **Agent 定义**：以大模型为核心计算引擎，模拟人类「感知→规划→行动」自动完成用户设定目标的系统（常被译作智能体/代理）。本质是代替人类做事。
- **Agent 总览（四大部分）**：① **规划**（任务分解，用 CoT 思维链、自我批判等）；② **记忆/知识存储**（短期记忆 + 长期记忆）；③ **工具选择**（为子任务选合适工具）；④ **工具执行**（调用工具自动完成任务）。
- **另一种框架视角**：强调**环境感知**（文本/图像/音频多模态输入）→ 感知+推理规划+记忆 → 选工具 → 执行。例：「看天空问明天是否下雨，会下雨就给伞」→ 调天气预报工具判断。
- **Agent 不修改大模型参数**：所有能力靠定制 Agent 提示词实现。
- **规划（CoT）**：提示词要求大模型「停下来逐步拆解」大任务为可管理的子目标（如开发绿程提醒程序，要求 JSON 返回任务名/类型/函数/状态/优先级）。
- **记忆双模块**：短期记忆（本次提示词中信息、多轮对话历史，不放入即遗忘）；长期记忆（外挂知识库 = 本课程重点的 RAG，每次检索返回相关知识，长期存在）。
- **著名 Agent 项目**：通用（AutoGPT / BabyAGI / 微软 AutoGen）；领域（HuggingGPT 调不同 AI 算法作工具、MetaGPT / ChatDev 多智能体软件开发、斯坦福小镇多 Agent 社交模拟）。
- **大模型四种交互方式对比**：QA 问答（ChatGPT）→ RAG（外挂知识库增强）→ Agent（融合前两者 + 规划 + 工具自动完成）→ 多 Agent（多个协作）。Agent 是通往 AGI 的有效途径，但对模型能力要求更高。
- 本章按课程口径重构；产品名已规范化（AutoGPT / BabyAGI / AutoGen / HuggingGPT / MetaGPT / ChatDev）；剥离营销与课程群引流。

## 一、什么是 Agent

Agent（智能体/代理）以大模型为核心，自动完成用户给定的目标或任务。类比「去北京旅游」：人类会先确定人数/时间 → 规划订机票/酒店/行程 → 找软件执行；Agent 则读取任务配置 → 把任务拆解成小任务 → 为每个小任务选合适工具与外部知识/记忆辅助执行，模拟人类思路自动完成。

> 关键：Agent **不修改大模型参数**，所有规划/工具调用能力都靠**定制 Agent 提示词**实现。

## 二、Agent 设计框架（四大部分）

| 模块 | 内容 | 关键技术 |
| --- | --- | --- |
| 规划 | 任务分解规划 | CoT 思维链、自我批判（self-critique） |
| 记忆/知识 | 信息存储 | 短期记忆 + 长期记忆 |
| 工具选择 | 为子任务选工具 | 工具描述与参数约束 |
| 工具执行 | 调用工具完成任务 | 执行返回结果 |

**环境感知视角**：Agent 感知用户任务所处环境（文本/图像/音频多模态输入）→ 解析 → 结合短期/长期记忆用大模型推理规划 → 选工具执行。例：用户「看天空问明天下不下雨，下就给伞」→ 调天气预报工具判断 → 给伞。

## 三、规划与记忆的实现要点

**任务分解（CoT）**：提示词让大模型逐步拆解大任务为可行子目标。例：要求开发绿程提醒程序，提示词指定返回 JSON（含任务名称/类型/调用函数/完成状态/优先级），并设定角色让模型理解场景。

**短期记忆**：本次提示词中描述的个人信息、人设、要求，及多轮对话历史。不放入提示词模型即「忘记」。

**长期记忆 = 外挂知识库 = RAG**：RAG 为 Agent 提供大模型认知外知识，辅助自动完成任务——这是 RAG 与 Agent 结合的核心方式之一。

## 四、著名 Agent 项目

- **通用场景**：AutoGPT、BabyAGI、微软 AutoGen。
- **特定领域**：HuggingGPT（把社区不同 AI 算法/模型当工具调用来完成 AI 任务）、MetaGPT（多智能体软件开发，分解流程设不同 Agent 负责模块）、ChatDev（模拟软件公司，不同角色协作）、斯坦福小镇（每个角色一个 Agent 模拟人类社区社交）。
- 多 Agent 强调多个 Agent 协调完成复杂任务。

## 五、大模型四种交互方式演进

1. **QA 问答**（ChatGPT）：人与模型问答交互。
2. **RAG**：外挂领域知识库增强问答。
3. **Agent**：融合 QA + RAG，模拟人类规划 + 用工具自动完成任务，无需人过多干预。
4. **多 Agent**：多个 Agent 协作。

> Agent 自主性更强，但对大模型能力（规划、工具使用）要求更高——因为这些能力本质都由大模型完成。

## 六、FAQ

**Q1：Agent 和 RAG 什么关系？**
RAG 是 Agent 的长期记忆/外挂知识库，为 Agent 提供认知外知识；Agent 在此之上加规划与工具调用自动完成任务。

**Q2：Agent 怎么做到不训练就能用工具？**
靠定制提示词：详细描述工具功能与参数，让大模型据此判断调用哪个、传什么参。

**Q3：短期记忆和长期记忆区别？**
短期=本次提示词与对话历史（不放入即忘）；长期=外挂知识库（RAG），长期存在、随检索返回。

**Q4：为什么 Agent 对模型要求更高？**
它的规划、工具选择、推理都由大模型完成，自主性强意味着单次推理出错会连锁放大。

## 七、面试高频问答

**1. Agent 四大模块？**
规划、记忆/知识存储、工具选择、工具执行。

**2. Agent 与 RAG 结合点？**
RAG 作为 Agent 长期记忆（外挂知识库），提供认知外知识辅助自动完成任务。

**3. 列举几个著名 Agent 项目？**
AutoGPT/BabyAGI/AutoGen（通用）、HuggingGPT/MetaGPT/ChatDev（领域/多智能体）。

**4. 大模型四种交互方式？**
QA → RAG → Agent → 多 Agent。

## 八、ops 提示（增效）

> **工具描述决定 Agent 成败**：功能 + 参数写得越准，模型选工具越对；需实测不同写法调优，别一次定稿。
>
> **RAG 是 Agent 最稳的长期记忆**：把企业知识库挂成 RAG 工具，比让模型死记参数可靠得多。
>
> **Agent 适合「流程型」任务**：有明确多步规划 + 可调用工具（查库/API）才上 Agent；单轮问答别硬套。
