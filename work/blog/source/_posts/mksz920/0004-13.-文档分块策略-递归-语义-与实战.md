## 纲要

- **为什么要分块**：长文档含多语义会干扰 embedding、检索长文本易带入无关内容、embedding 有最大 token 限制（超出截断丢信息）。
- **分块核心原则**：一个块只能表示「完整且语义相关」的上下文；块太小 → 语义割裂、检索错过；块太大 → 异语义混杂、干扰检索。
- **策略一 · 递归文本分块（规则式）**：按分隔符由粗到细递归（段落 → 句子 → 单词 → 字符），直到每块 ≤ 设定块大小；关键参数 `chunk_overlap`（块间重叠，保上下文连贯）；中文需加逗号 / 句号分隔符；Markdown 用 `MarkdownTextSplitter`（按标题层级 → 代码块 → 分割线），Python 用 `PythonCodeTextSplitter`（按类 / 函数 / 方法）。
- **策略二 · 语义分块**：
 - **基于 embedding**：拆句 → 滑动窗口（长度 n）→ 算前后窗口 embedding 相似度 → 按阈值（百分位 / 标准差 / 四分位数，如 95 分位）分割；超长块再递归细分。
 - **端到端基于模型**（阿里达摩院，BERT 文档分割）：窗口 n 句 → 每句 token 编码取均值得句向量 → 接二分类层判是否分割点；ModelScope `pipeline` 调用；须验证模型在你的数据上的泛化能力。
- **实战（制度问答模块）**：用 LangChain `Document` 统计句长分布（平均 / 最大 / 95 分位）指导块大小；`RecursiveCharacterTextSplitter`（块 128、overlap 小于平均句长、中文分隔符）做递归分块（`load_and_split` / `split_documents`）；`SemanticChunker`（BGE-M3 embedding、百分位阈值、正则句分隔符、buffer_size=2）做向量语义分块；ModelScope 文本分块模型做端到端语义分块（去换行符）。
- 本章按课程口径重构；产品 / 框架名已规范化（LangChain / BGE-M3 / ModelScope / RecursiveCharacterTextSplitter / SemanticChunker）；剥离营销与课程群引流。

## 一、为什么必须分块

- 长文档往往包含多个语义，整段向量化会稀释语义、降低检索精度。
- 即便能匹配，长文本也夹带无关内容，增加 LLM 生成准确答案的难度。
- embedding 模型有最大输入长度，超长会被截断造成信息缺失。

## 二、分块的核心原则与两忌

- **原则**：一个块 = 一段完整且语义相关的上下文。
- **两忌**：块太小（完整语义被拆 → 上下文不全、检索错过真相关）；块太大（异语义混一块 → 检索噪声、结果不准）。

## 三、递归文本分块（规则式）

- **思想**：先按段落分隔，超块大小再按句子、单词、字符逐级细分，直到每块 ≤ 设定大小。
- **关键参数**：
 - `chunk_size`：块大小，须 < embedding 模型输入上限。
 - `chunk_overlap`：块间重叠字符数，增强上下文连贯（如块间重叠 30 字符）。
 - `separators`：中文需加 `，` `。` 等，避免只按英文标点切。
- **变体**：`MarkdownTextSplitter`（标题层级 → 代码块 → 分割线）、`PythonCodeTextSplitter`（按类 / 函数 / 方法层级）。

## 四、语义分块（基于含义）

- **基于 embedding 的语义分块**：拆句 → 滑动窗口（如 3 句）→ 算前后窗口相似度 → 超过阈值（百分位 / 标准差 / 四分位数）即分割点；95 分位例：对所有相似度排序取第 95% 作阈值。超长块再递归细分。
- **端到端基于模型（达摩院 BERT 分割）**：给定窗口 n 句 → 逐句 token 编码取均值得句向量 → 二分类层直接判该句是否分割点；一步到位不需阈值；ModelScope 有开源，`pipeline` 调用简单，但须测泛化能力（训练集 ≠ 你的任务）。

## 五、实战：制度问答模块的分块

- **先统计句长分布**：按句号切句，算平均 / 最大 / 最小 / 95 分位句长（如 95 分位 ≈ 101），据此定块大小。
- **递归分块**：
  ```python
  from langchain.text_splitter import RecursiveCharacterTextSplitter
  splitter = RecursiveCharacterTextSplitter(
      chunk_size=128, chunk_overlap=<略小于平均句长>,
      separators=["\n","。","，","、"])   # 中文语境加句号/逗号
  docs = splitter.split_documents(loaded_docs)   # 或 load_and_split
  ```
 结果每块语义相对完整，块间有 ~30 字符重叠。
- **向量语义分块**：
  ```python
  from langchain.text_splitter import SemanticChunker
  chunker = SemanticChunker(embeddings, breakpoint_threshold_type="percentile",
                            sentence_split_regex=r"[。；：]", buffer_size=2)
  ```
 用 BGE-M3 作 embedding；分出的块较长且语义完整，超长再递归细分。
- **模型语义分块**：ModelScope `pipeline(task="text-segmentation",model=...)`，传入去换行文本即得分块。

## 六、FAQ

**Q1：chunk_overlap 有什么用？**
块间保留一定重叠文本，增强上下文连贯性，减少割裂。

**Q2：百分位是怎样定分割阈值的？**
对所有窗口间相似度从小到大排序，取第 95% 的值作阈值，超过即切分。

**Q3：语义分块和递归分块怎么选？**
递归快且可解释、适合结构化文本；语义更贴合含义、适合叙述性长文，但需 embedding / 模型且更慢。

**Q4：为什么语义分块后还要再递归？**
语义块可能超过 embedding 最大长度，需二次递归细分防截断。

## 七、面试高频问答

**1. 分块的核心原则与两忌？**
原则：一块 = 完整且语义相关上下文；忌太小（割裂）、忌太大（混杂）。

**2. 递归文本分块的关键参数？**
chunk_size（<模型上限）、chunk_overlap（块间重叠）、separators（中文加句号逗号）。

**3. 基于 embedding 的语义分块怎么做？**
拆句 + 滑动窗口 + 算前后窗口相似度 + 按阈值（百分位等）分割，超长再递归。

**4. 端到端模型语义分块的优势与注意？**
一步判分割点、不需阈值；但须验证泛化能力，可能不适用于你的数据。

## 八、ops 提示（增效）

> **先统计后设参**：用句长分布（尤其 95 分位）定 chunk_size，别拍脑袋。
>
> **中文必改分隔符**：递归分块默认英文标点，中文要加 。，、。
>
> **语义块兜底**：叙述长文用语义分块，但记得超长再递归防截断。
