## 纲要

- **基准榜单 MTEB**：提供多种 embedding 任务的评测数据集与排名，是挑选 embedding 模型的起点。
- **两大主流中文模型（均基于 BERT 改进）**：
 - **GTE（阿里，通用文本向量）**：在 BERT 上加入**度量学习**与**对比学习**。度量学习＝两相关句各自 token 均值得句向量 → 余弦相似度，目标相关→1、不相关→0（数据如新闻摘要↔正文、代码注释↔代码）；对比学习＝三元组 (q,a 相关 / q,i 不相关)，目标 q-a 距离小、q-i 距离大，在有标签数据上微调。
 - **BGE-M3（智源）**：支持多语言、多类型检索（密集 / 稀疏 / 多向量）、多文本粒度（词级 / 段级 / 文档级）；训练思路同 GTE（度量 + 对比），相似度计算涵盖 dense（全局均值）、sparse（字符匹配）、multi-vector（局部细粒度），是「从总体到局部」的混合检索模型。
- **选型六维度（从 MTEB 入手）**：① 任务类型——RAG 选 retrieval 检索类；② 支持语言——中文语境选多语言（尤其中英）；③ MTEB 得分——靠前且机构有名；④ 模型大小 / 部署资源 / 延迟——不建议选大模型微调后的 embedding（资源消耗大、收益不明显）；⑤ 维度——512 / 1024 折中；⑥ 最大 token 数——超出截断，影响 RAG 分块。
- **MTEB 不可全信**：榜单公开可能有水分，需结合机构与维度初筛 → 定为 baseline → 自建数据集多轮迭代测试。
- **实战三种调用方式**：transformers（底层）、sentence-transformers（句级封装）、LangChain 的 HuggingFaceEmbedding（再封装）；基本操作＝相似度（余弦 / 欧氏）+ 聚类（KMeans 验证语义分组）。

## 一、MTEB 基准与从哪入手

- **MTEB** 聚合多种 embedding 任务（分类 / 聚类 / 检索 / 总结等）的评测集与排名，还展示模型属性（大小、最大 token 数等）。
- RAG 重在检索，应直接看 **retrieval（检索）任务**下的模型排名。

## 二、GTE：度量学习 + 对比学习

- **度量学习**：两相关句 a、b 各自过 BERT → token embedding 取均值（pooling）得句向量 → 算余弦相似度；目标：相关句余弦≈1、不相关≈0。训练数据强调高质量配对（如新闻摘要↔正文、代码注释↔代码）。
- **对比学习**：构造三元组 (q,a 相关;q,i 不相关)，目标使 q-a 距离尽量小、q-i 距离尽量大；在**有标签数据**上微调，高度契合 embedding「相似近、不相似远」的定义。

## 三、BGE-M3：混合检索三合一

- 三大能力：多语言、多检索类型（dense / sparse / multi-vector）、多粒度（词 / 段 / 文档级）。
- 相似度计算三路并行：
 - **dense（密集检索）**：同 GTE，所有 token 均值，全局视角；
 - **sparse（稀疏检索）**：基础字符匹配；
 - **multi-vector（多向量）**：每个 token 映射多维向量后细粒度计算，局部视角。
- 整体是「从总体到局部、从语义到文本匹配」的混合检索模型，当前较强。

## 四、为 RAG 选 Embedding 的六维度

1. **任务类型**：选 retrieval 类模型。
2. **支持语言**：中文任务选多语言（尤其中英）模型；纯英文训练的模型中文检索表现差。
3. **MTEB 得分**：选排名靠前、发布机构有名的。
4. **模型大小 / 资源 / 延迟**：避免大模型微调后的 embedding——资源消耗巨大而相对收益有限。
5. **维度**：512 / 1024 折中（长维度捕捉复杂语义但更占存储与算力）。
6. **最大 token 数**：超出自动截断，是 RAG 文本分块必须考量的参数。

## 五、实战：三种调用与两个基本操作

- **三种调用**（本质都基于 transformers）：
 - `transformers`：AutoTokenizer + AutoModel，手动 pooling，CPU/GPU 皆可。
 - `sentence-transformers`：句级封装，`model.encode(...)` 一步出句向量，更便捷。
 - `LangChain` 的 `HuggingFaceEmbedding`：对 sentence-transformers 再封装，`embed_documents` / `embed_query`。
 - **GTE 输出 1024 维**，常用第一个 token（`CLS`）的向量代表整句（训练 / 推理须一致）。
- **基本操作**：
 - 相似度：余弦相似度（夹角 0 → 1）、欧氏距离（相似 → 距离趋 0）。
 - 聚类：KMeans 验证「水果」与「动物」在向量空间自然分组，印证语义相近者聚拢。

## 六、FAQ

**Q1：GTE 和 BGE-M3 怎么选？**
追求简单通用选 GTE；需要多语言 / 多粒度 / 混合检索选 BGE-M3。

**Q2：为什么不建议用大模型微调后的 embedding？**
相对收益不明显，却带来巨大部署资源与延迟成本，性价比低。

**Q3：CLS token 作句向量合理吗？**
CLS 在训练时已聚合全句信息，用作句向量是常见做法，但须保证训练与推理一致。

**Q4：MTEB 排名高就一定能用吗？**
不一定，榜单可能有水分（训练集泄露），关键场景要用自建数据集实测迭代。

## 七、面试高频问答

**1. 简述 GTE 的训练思路。**
在 BERT 上加度量学习（句向量余弦，相关→1）与对比学习（三元组，相关近、不相关远，有标签微调）。

**2. BGE-M3 的「混合检索」指什么？**
同时支持 dense（全局均值）、sparse（字符匹配）、multi-vector（局部细粒度）三种相似度计算。

**3. 为 RAG 选 embedding 看哪六个维度？**
任务类型（retrieval）、语言、MTEB 得分、模型大小/资源/延迟、维度、最大 token 数。

**4. embedding 实战有哪三种调用方式？**
transformers（底层）、sentence-transformers（句级封装）、LangChain HuggingFaceEmbedding（再封装）。

## 八、ops 提示（增效）

> **起点=MTEB retrieval 榜**：但只作 baseline，别盲信。
>
> **维度与截断双约束**：选 512/1024，分块长度务必小于最大 token 数。
>
> **优先多语言**：中文 RAG 选中英兼顾模型，避免英文训模型中文翻车。
