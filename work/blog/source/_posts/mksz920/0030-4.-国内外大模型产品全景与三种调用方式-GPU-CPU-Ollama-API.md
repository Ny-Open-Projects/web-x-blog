## 纲要

- **为什么要懂「怎么调」**：AI 三驾马车（算法 / 数据 / 算力）中，算力多为 GPU；掌握本地部署（有 GPU）、CPU 部署（Ollama）、厂商 API 三种调用方式，是 RAG 落地的第一步。
- **GPU 为何适合大模型**：Transformer 内部是海量矩阵乘加，GPU 拥有大量计算单元 + 专用 Tensor Core，并行能力远胜 CPU（对比：1.6 万 CPU 才能与 1 块 GPU 达到同等图像分类效果）。
- **模型文件组成**：参数文件（如 7B / 72B 的权重）、分词信息、词表、模型配置（层数等）。
- **调用方式一 · transformers + GPU**：用 AutoTokenizer / AutoModel，`device_map="auto"` 自动选 GPU。
- **调用方式二 · Ollama（CPU 友好）**：底层 llama.cpp 对 CPU 推理做指令集优化，支持几乎所有开源模型，提供 OpenAI 兼容接口（默认端口 11434）。
- **调用方式三 · 厂商 API**：开放平台注册 → 创建应用 → 拿密钥；多数提供 OpenAI 兼容接口，便于无缝迁移。
- **产品全景**：开源（Meta Llama、阿里 Qwen、智谱 GLM、DeepSeek、百川、面壁 CPM、MiniMax、阶跃星辰、Mistral）；闭源 API（百度文心一言、月之暗面 Kimi、讯飞星火、MiniMax 海螺、智谱、字节豆包、昆仑天工、腾讯混元、OpenAI GPT 系列、Google Gemini、Anthropic Claude）。
- 本章按课程口径重构；产品 / 框架名已规范化（Llama / Qwen / GLM / DeepSeek / Ollama / llama.cpp / vLLM 等）；剥离营销与课程群引流。

## 一、GPU vs CPU：大模型算力的底层逻辑

- **架构差异**：CPU 核少（笔记本 4 核、服务器数十核）但控制单元复杂，负责全局调度；GPU 拥有大量计算单元（含 Tensor Core 专攻矩阵），控制单元相对弱，擅长并行。
- **契合点**：Transformer 大量矩阵运算可拆为乘加，正需要 GPU 的并行算力。
- **量化印象**：谷歌早年猫狗识别，1.6 万个 CPU 才抵 1 块 GPU 的效果，直观体现差距。

## 二、模型文件与推理三步

- **文件组成**：① 参数文件（权重，决定 7B / 72B 等规模）；② 分词信息（分词 / 逆分词操作）；③ 词表；④ 模型配置（层数 / 结构）。
- **推理三步**：加载分词器 → 加载模型参数 → 推理生成（文本 → token → 模型 → token → 文本）。

## 三、三种调用方式

1. **transformers + GPU**：`AutoTokenizer.from_pretrained` / `AutoModel.from_pretrained` 加载，`device_map="auto"` 自动识别 GPU；输出参数含温度 / top-p / top-k。
2. **Ollama（CPU / GPU 皆可）**：一行安装脚本即可；底层 llama.cpp 对 CPU 推理做指令集优化，支持当前几乎所有开源模型；启动后提供 OpenAI 兼容接口（本地端口 11434，API key 任意填）。
3. **厂商 API**：在开放平台注册、创建应用、获取密钥；国内主流（百度千帆 / 腾讯 / 阿里通义 / 讯飞 / 智谱 / 月之暗面 / DeepSeek 等）多提供 OpenAI 兼容调用，迁移成本低。

## 四、开源大模型产品

- **Meta Llama**：最早也最出名的开源系列，Llama 3.1 提供 8B / 405B 等规模。
- **阿里 Qwen（通义千问）**：Qwen2 最大 72B。
- **智谱 GLM**：GLM 系列，GLM-4 最大开源 9B。
- **DeepSeek**：MOE 架构（DeepSeek-V2）。
- **百川**：13B 级别。
- **面壁 CPM**：主打边缘 / 终端小模型（「小钢炮」）。
- **MiniMax / 阶跃星辰**：国内新锐。
- **Mistral（国外）**：MOE（Mixtral 8×7B），推理时仅部分专家激活，省时。

## 五、闭源 / API 大模型产品

- **国内**：百度文心一言、月之暗面 Kimi、讯飞星火、MiniMax 海螺 AI / Glow、智谱、字节豆包、昆仑万维天工 AI、腾讯混元。
- **国外**：OpenAI GPT 系列（GPT-4o、推理模型 o1）、Google Gemini（含 nano 端侧模型）、Anthropic Claude 3.5。
- 闭源产品通常不提供权重下载，主要通过官方 AI 助手或 API 调用。

## 六、FAQ

**Q1：没有 GPU 能在本地跑大模型吗？**
能。Ollama（llama.cpp 后端）对 CPU 推理做了优化，支持几乎所有开源模型，并提供 OpenAI 兼容接口。

**Q2：Ollama 和直接 transformers 调用有什么区别？**
Ollama 封装了 llama.cpp、对 CPU 推理加速且一行装好，还内置 OpenAI 兼容服务；transformers 更底层、可控，但 CPU 推理慢。

**Q3：为什么厂商都做 OpenAI 兼容接口？**
便于开发者从 OpenAI 平滑迁移到自家模型，几乎不改调用代码。

**Q4：选开源还是闭源？**
涉及企业私有数据且安全严格 → 本地开源部署；求省事、追最强能力 → 闭源 API；按成本与安全权衡。

## 七、面试高频问答

**1. 一句话说明 GPU 为何适合大模型。**
Transformer 海量矩阵乘加可被 GPU 大量并行计算单元 + Tensor Core 高效承载，远胜 CPU。

**2. 列举大模型推理的三个步骤。**
加载分词器 → 加载模型参数 → 推理生成（文本↔token 互转）。

**3. 本地无 GPU 部署开源模型用什么？**
Ollama（底层 llama.cpp，CPU 优化，OpenAI 兼容接口，默认端口 11434）。

**4. 给出 3 个开源 + 3 个闭源大模型。**
开源：Llama、Qwen、GLM（或 DeepSeek / Mistral）；闭源：GPT-4o、Gemini、Claude（或文心 / Kimi / 星火）。

## 八、ops 提示（增效）

> **部署选型**：有 GPU 用 transformers/vLLM；只 CPU 用 Ollama；要省心追强用 API。
>
> **接口统一**：优先选 OpenAI 兼容接口，未来换模型迁移成本最低。
>
> **端口与安全**：本地 OpenAI 兼容服务（如 11434）勿暴露公网，避免权重 / 数据泄露。
