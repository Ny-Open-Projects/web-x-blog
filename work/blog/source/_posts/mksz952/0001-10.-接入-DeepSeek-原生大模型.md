## 纲要

- **平台准备**：DeepSeek 官网 API 开放平台，需注册 / 实名 / 充值后获取 API Key
- **三要素**：`base-url`（`https://api.deepseek.com/v1`）、`api-key`、`model-name`
- **模型区分**：聊天模型 `deepseek-chat` vs 推理模型 `deepseek-reasoner`
- **复用 OpenAI 链路**：因兼容 OpenAI 标准，仅改配置即可，无需新依赖
- **调试**：开 `logging.level.dev.langchain4j=DEBUG` 看请求/响应

> 本章落地第一个国内模型，按课程口径重构；代码为课程示意，密钥脱敏处理（勿硬编码）。

## 一、获取接入凭证

1. 进入 DeepSeek 官网 → **API 开放平台**。
2. 注册并完成实名（平台安全要求）。
3. 充值后创建 **API Key**（密钥仅展示一次，妥善保存）。
4. 在「接口文档」确认 `base-url` 与可用模型名。

## 二、关键配置

DeepSeek 兼容 OpenAI 协议，因此复用 `langchain4j-openai` 依赖，只改三项配置：

```properties
langchain4j.openai.base-url=https://api.deepseek.com/v1
langchain4j.openai.api-key=YOUR_DEEPSEEK_API_KEY
langchain4j.openai.model-name=deepseek-chat
# 调试日志：看清与大模型的交互报文
logging.level.dev.langchain4j=DEBUG
```

## 三、模型类型选择

| 类型 | model-name | 用途 |
|---|---|---|
| 聊天模型 | `deepseek-chat` | 通用对话、业务调用 |
| 推理模型 | `deepseek-reasoner` | 复杂推理、数学 / 逻辑链 |

## 四、调用

由于基于 OpenAI 规范，之前的 `OpenAIChatModel` 测试类无需改代码，只改配置后重跑：

```java
@Autowired
OpenAIChatModel model;

@Test
void hello() {
    System.out.println(model.chat("你是谁？"));
}
```

控制台日志可见：客户端经 LangChain4j API → 底层走 `base-url` 与 DeepSeek 交互 → 返回角色与回答，说明接入完成。

## 五、FAQ

**Q1：DeepSeek 需要新依赖吗？**
不需要；它兼容 OpenAI 标准，复用 `langchain4j-openai` 即可。

**Q2：chat 和 reasoner 怎么选？**
常规业务用 `deepseek-chat`；需要长链条推理（数学证明、复杂规划）用 `deepseek-reasoner`。

**Q3：为什么建议开 DEBUG 日志？**
能直接看到请求报文与模型返回，排查「无响应 / 报错」最快。

## 六、面试高频问答

1. **DeepSeek 接入为什么简单？** 遵循 OpenAI API 规范，改端点与 key 即可，零新增依赖。
2. **生产接 DeepSeek 注意什么？** 密钥托管、限流重试、推理模型延迟更高需设超时。
3. **chat 与 reasoner 差异？** 前者通用低延迟，后者强推理高耗时。

## 七、ops 提示

> **密钥安全**：`YOUR_DEEPSEEK_API_KEY` 必须走环境变量 / 配置中心，严禁明文提交仓库；泄露立即在平台吊销。
>
> **成本与限额**：按调用量计费，设置预算告警；高并发场景加限流与重试退避。
>
> **超时配置**：推理模型（`reasoner`）响应慢，务必配置更长超时，避免网关 504。
