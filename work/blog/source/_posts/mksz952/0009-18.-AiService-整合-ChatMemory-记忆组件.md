## 纲要

- **组件**：`MessageWindowChatMemory` —— 滑动窗口保留最近 N 条消息
- **编程式**：`AiServices.create(...).chatMemory(memory).build()`
- **声明式**：`@AiService(chatMemory="beanName")` + `@Bean` 实例化记忆组件
- **逐步简化**：手动拼历史 → 窗口组件 → 注解两行搞定
- **关键点**：`@Bean` 方法名须与 `@AiService(chatMemory=...)` 指定名一致

> 本章用 ChatMemory 替代手动历史，按课程口径重构；代码为课程示意，去品牌与脱敏处理。

## 一、MessageWindowChatMemory

```java
ChatMemory memory = MessageWindowChatMemory.builder()
        .maxMessages(10)   // 仅保留最近 10 条，超出窗口自动遗忘
        .build();
```

## 二、编程式整合

```java
Assistant assistant = AiServices.create(Assistant.class)
        .chatLanguageModel(model)
        .chatMemory(memory)
        .build();

// 后续每次调用都自动带上窗口内的历史
assistant.chat("我是玄风");
assistant.chat("我是谁？");   // 模型记得「玄风」
```

## 三、声明式整合

在接口标 `@AiService(chatMemory=...)`，并在配置类用 `@Bean` 提供记忆组件：

```java
@AiService(chatMemory = "myMemory")
public interface Assistant {
    String chat(String message);
}

@Configuration
class ChatConfig {
    @Bean
    public ChatMemory myMemory() {
        return MessageWindowChatMemory.builder()
                .maxMessages(10)
                .build();
    }
}
```

> 注意：`@Bean` 方法名 `myMemory` 必须与 `@AiService(chatMemory="myMemory")` 完全一致。

## 四、为什么比手动优雅

| 方式 | 代码量 | 维护成本 |
|---|---|---|
| 手动拼历史 | 随轮次线性增长 | 高 |
| ChatMemory 编程式 | 固定几行 | 低 |
| @AiService 声明式 | 两行注解 | 最低 |

## 五、FAQ

**Q1：maxMessages 设多大合适？**
看模型上下文上限与业务；客服场景 10~20 条常见，过长浪费 token。

**Q2：窗口满了会怎样？**
最旧的消息被移出窗口（遗忘），只保留最近 N 条。

**Q3：Bean 名不一致会怎样？**
框架找不到指定记忆组件，启动报错或记忆不生效。

## 六、面试高频问答

1. **ChatMemory 作用？** 自动维护多轮对话历史，替代手动拼消息列表。
2. **两种整合方式？** 编程式 `AiServices.create().chatMemory()` 与声明式 `@AiService(chatMemory=bean)`。
3. **窗口机制？** `MessageWindowChatMemory` 保留最近 N 条，超出遗忘。

## 七、ops 提示

> **Bean 命名一致性**：`@AiService(chatMemory=...)` 与 `@Bean` 方法名必须对齐，否则装配失败。
>
> **窗口大小**：结合模型上下文与成本调 `maxMessages`，避免 token 浪费或截断。
>
> **隔离预留**：多用户需隔离，见。
