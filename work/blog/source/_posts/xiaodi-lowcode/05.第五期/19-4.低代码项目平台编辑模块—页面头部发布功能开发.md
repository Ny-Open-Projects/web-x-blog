# 低代码项目平台编辑模块—页面头部发布功能开发

> **导语**：发布功能是低代码编辑平台“编辑—预览—发布”闭环的最后一步。本文讲解编辑页面头部「发布」按钮的实现：如何把 MobX store 中的组件数据结构转换成后端接口要求的入参，如何通过 `useRequest` 调用发布接口，以及发布成功后本地缓存时间的处理。

## 前置知识

- 已掌握 store 中组件数据的组织方式（组件 ID 排序数组 `sortableComponentConfig` + 组件配置映射 `componentConfigs`），见《低代码项目平台编辑模块—页面组件拖拽排序功能开发》。
- 已了解头部的动态标题、草稿、预览逻辑，见《低代码项目平台编辑模块—页面头部草稿功能开发》《低代码项目平台编辑模块—页面头部预览功能开发》。
- 后端发布接口已开发完成，见「后端接口开发—低代码项目编辑模块发布接口」上、中、下三集。

## 正文

### 发布入口：handleGoRelease 方法

页面头部的发布逻辑统一收敛在 `handleGoRelease` 方法中。点击「发布」按钮即触发该方法，同时给按钮绑定一个 `loading` 状态：在请求发布接口尚未返回前，按钮处于 loading 样式，防止用户重复提交。

### 把 store 组件数据转成后端入参结构

发布接口入参与 store 内部数据结构并不一致，因此第一步要把前端储存在 store 里的组件数据，转换成后端要求的 `{ type, options }` 数组结构：

1. 从 store 取出按组件 ID 排序好的数组，遍历每个 ID；
2. 调用「按 ID 获取组件配置属性」的方法，拿到每个组件的属性信息；
3. 把每个组件转成 `{ type, options }` 的对象，再拼成一个 `components` 数组。

`options` 里存放该组件全部的配置信息（如标题、默认值、选项列表等）。除了 `type` 与 `options`，发布接口还需要 `desc`（页面描述）、`page_name` 以及 `tdk`（关键字，对应全局属性里的页面关键字；描述与标题分别是独立的 `desc` 与 `page_name` 列），一并作为参数传入。

### 调用发布接口与 onSuccess 回调

发布接口的请求封装在 `api/low-code` 中，路径为 `POST /api/low_code/release`，使用 `POST` 方式并把上述参数传递进去。前端通过 `ahooks` 提供的 `useRequest` 引入该接口：

- 它返回 `run` 与 `loading`，执行 `run(...)` 才会真正发起请求；
- 默认配置 `manual` 为 `true`，即初始化时不自动执行，只有显式调用 `run` 时才请求；
- `onSuccess` 回调里可以拿到接口返回的数据 `data`，用于后续跳转与提示。

`onSuccess` 里做两件事：一是跳转发布后的页面（该页面由 Next.js 开发，本阶段先注释掉，等发布页面模块完成后再放开）；二是提示用户「发布成功」。

### 缓存本地发布时间

发布成功后，除了写入服务端，还会在本地缓存里记录本次发布时间：

```ts
localStorage.setItem('release_time', String(Date.now()));
```

这与 store 工具方法 `storeInLocalStorage` 对应——组件存入 `localStorage` 时会自动执行一次「存草稿」操作，而「发布时间」是写入服务端成功后才需要记录的时间戳。后续判断「最新配置来自草稿还是来自服务端」，正是依赖草稿时间与发布时间的先后比较。

### 联调验证

开发时若后端未启动，点击发布会报错；启动 `server` 子项目后再请求即可成功。验证要点：

- 在编辑页配置轮播图、卡片、列表、图片、文本等组件，点击发布；
- 调用 `GET /api/low_code/release_with_user` 等已开发的获取页面组件接口，确认数据库里该页面（如 `page_id=3`、`account_id=8`）的标题、`tdk`、`desc` 以及组件信息都被正确更新；
- 发布成功只记录 release_time；刷新后若草稿时间早于发布时间则自动转服务端读取（源码 onSuccess 不调 storeInLocalStorage），所以即使后续刷新也能看到最新配置。

> 配套物料：前端工程依赖见 `代码（已8期）/19-4/lowcode/packages/client/package.json`，其中 `antd`、`mobx`、`mobx-react-lite`、`ahooks`、`axios` 是发布功能的关键依赖；根工程脚本见 `代码（已8期）/19-4/lowcode/package.json`（`run:server` 用于启动后端）。

## 小结

1. 发布逻辑集中在头部的 `handleGoRelease`，按钮带 `loading` 防重复提交。
2. 发布前需把 store 的组件数据转成 `{ type, options }` 数组，并补充 `page_name`、`tdk`、`desc`。
3. 通过 `ahooks` 的 `useRequest`（`manual: true`）调用 `POST /api/low_code/release`，用 `run` 触发请求。
4. 成功后写入 `localStorage` 的 `release_time`，作为与服务端/草稿时间比较的依据。
5. 发布成功会自动执行一次存草稿；跳转发布页需待 Next.js 发布页面模块完成。
