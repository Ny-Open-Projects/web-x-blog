# 低代码项目发布页面—后端接口提交问卷信息

> **导语**：用户填写完问卷点击提交，数据就要落库。本文讲解「提交问卷信息」后端接口：如何定义入参类型、用「IP + 设备」加密 key、向 `component_data` 表插入或（理论上）更新一条记录，以及 Apifox 联调。

## 前置知识

- 已了解 `component_data` 表与 `IComponentData` 类型，见《低代码项目发布页面—需求分析》。
- 已掌握 TypeORM 的 `save` 操作，见《TypeORM 框架—配置实体和自动同步数据库》。

## 正文

### 接口与入参类型

在 `LowCodeController` 中新增 `question_data` 路径，使用 `POST` 请求，方法名 `postQuestionData`。请求体为 JSON，包含：

- `page_id`：发布页面 ID；
- `props`：问卷组件的用户填写内容数组，每个元素含组件 `id` 与 `value`。

入参类型 `IComponentData` 定义在 `share` 公共项目中，属性含 `id`、`user`、`page_id`、`props`（数组）。因为 `share` 是公共子包，改动后需重新打包才能在前端/服务端使用其中的类型。

### 生成 key 并写入 component_data

服务层接收 `page_id`（配置 ID）与 `props`，同时后端自行取出 `ip` 与 `device` 并加密生成 `key`。接着按 `key` + `page_id` 去 `component_data` 表查找：

- 若不存在 → 调用 `this.componentDataRepository.save(...)` 插入一条新记录，把 `props` 传入；
- 若存在 → 理论上更新内容。

但由于前端逻辑规定「提交过问卷后整页置灰不可再提交」，所以这个「更新」分支实际不会被触发——只需保证首次提交成功插入即可。

### Apifox 联调

构造用例：

- 请求方式 `POST`，路径 `question_data`（方法名 postQuestionData）；
- body 为 JSON，传 `page_id`（如 `3`）与 `props`（测试可先用随机字符串）；
- 发送后返回成功，Navicat 中可见 `component_data` 表新增一条以 `page_id=3` 插入、携带随机 `props` 的记录。

## 小结

1. 提交接口 `question_data` 为 `POST`，body 含 `page_id` 与 `props`。
2. 入参类型 `IComponentData` 定义在 `share`，改动后需重新打包。
3. 后端用「IP + 设备」加密得到 `key`，按 `key` + 配置 ID 查表，无则 `save` 插入。
4. 因前端限制重复提交，更新分支实际不生效，核心是保证首次插入成功。
