# 后端接口开发—用户的注册接口开发

> **导语**：本文从零实现用户注册接口 `POST /user/register`。你将学到密码为何要用 MD5 加密、如何用 JWT 在注册后直接签发 Token 提升体验，以及 NestJS 中 Providers、Module 注入与 TypeORM 仓储的完整协作链路。

## 前置知识

阅读前建议先看《什么是装饰器和Nestjs中的应用》，理解 `@Controller`、`@Post`、`@Body`、DTO 与依赖注入的基本概念。本文会用到 JWT 与 TypeORM，相关基础可回顾《Nestjs框架课程介绍+适合人员+学后水平》。

## 正文

### 接口定义与前置准备

注册接口为：

```
POST http://localhost:3000/user/register
```

前端会传递 `username` 与 `password`。后端拿到密码后**绝不能明文入库**，否则既不安全也不合规，因此需要先对密码做加密处理，再写入数据库。

工程中采用 **MD5** 加密。借助 Node 内置的 `crypto` 模块即可：

```ts
import { createHash } from 'crypto';

export function getSecret(password: string): string {
  return createHash('md5').update(password).digest('hex');
}
```

此外，用户注册成功后我们希望他**无需再登录一次**就能访问有权限的页面，以提升体验。因此注册逻辑中要一并**生成 JWT Token**。

### 加密与 JWT 的配置

加密工具封装在 `utils/secret-tool.ts` 中（上面的 `getSecret` 即取自此处）。JWT 需要一段自定义密文与过期时间，并通过 `JwtModule.register` 配置，且把 `global` 设为 `true` 以全局可用：

```ts
import { JwtModuleOptions } from '@nestjs/jwt';

export const jwtConfig: JwtModuleOptions = {
  secret: 'class_nest',
  signOptions: { expiresIn: '7d' },
  global: true,
};
```

> 若本机未安装 `@nestjs/jwt`，执行 `pnpm i @nestjs/jwt` 即可。

### 在 User Module 中完成依赖注入

配置就绪后，必须在 `user.module.ts` 中把它们「接」进当前模块才能使用：

- `providers` 里注入加密工具 `SecretTool`（写法和注入 `UserService` 类似）；
- `imports` 里引入 `JwtModule.register(jwtConfig)`；
- 操作数据库需引入 `TypeOrmModule.forFeature([User])`，把 `User` 实体纳入本模块仓储。

```ts
@Module({
  imports: [
    JwtModule.register(jwtConfig),
    TypeOrmModule.forFeature([User]),
  ],
  controllers: [UserController],
  providers: [UserService, SecretTool],
})
export class UserModule {}
```

### 控制器：路由与入参

用 Nest CLI 生成 RESTful 资源时会带一堆占位代码，先精简只保留要用的。把创建方法改为 `register`，并通过 `@Body()` 接收 DTO：

```ts
@Controller('user')
export class UserController {
  constructor(private readonly userService: UserService) {}

  @Post('register')
  register(@Body() registerDto: RegisterDto) {
    return this.userService.register(registerDto);
  }
}
```

`RegisterDto` 对应前面章节配置的 DTO 文件，用于约束入参。

### 服务层：注册核心逻辑

`UserService` 的构造函数中声明三类依赖：TypeORM 仓储、加密工具、JWT 服务。

```ts
@Injectable()
export class UserService {
  constructor(
    @InjectRepository(User)
    private readonly userRepository: Repository<User>,
    private readonly internalTools: SecretTool,
    private readonly jwtService: JwtService,
  ) {}

  async register(dto: RegisterDto) {
    // 1. 查重
    const foundUser = await this.userRepository.findOneBy({
      username: dto.username,
    });
    if (foundUser) {
      throw new BadRequestException('用户已存在');
    }

    // 2. 插入新用户（密码 MD5 加密，头像给默认值）
    const user = await this.userRepository.save({
      username: dto.username,
      password: this.internalTools.getSecret(dto.password),
      head_img: 'https://example.com/default-avatar.png',
    });

    // 3. 返回提示 + Token
    return {
      msg: '注册成功',
      data: this.jwtService.sign({ id: user.id }),
    };
  }
}
```

逻辑要点：

1. 先按 `username` 查询是否已存在，存在则抛 `BadRequestException('用户已存在')`；
2. 不存在则 `save` 插入一条新数据，密码经 `getSecret` 做 MD5 加密；头像实际项目由用户上传，这里先写死一张默认图（课程管理页要展示头像、点击可退出）；
3. 返回 `msg: '注册成功'` 以及用 `jwtService.sign({ id: user.id })` 签发的 Token。**注意不要把密码写进 Token 载荷**。

### 接口联调验证

用接口调试工具（Apifox / Postman 等）切换到开发环境，发送：

```
POST http://localhost:3000/user/register
Body: { "username": "yuyang", "password": "123456" }
```

返回 `注册成功` 与 token。再到数据库查看，密码字段已是 MD5 密文。再次用同一用户名请求，会返回「用户已存在」，说明查重生效。

## 小结

- 密码绝不明文入库，统一用 MD5（借助 `crypto.createHash('md5')`）加密后存储。
- 注册成功后直接签发 JWT，免二次登录，提升用户体验；Token 载荷只放 `id`，不放密码。
- 模块注入三板斧：`providers` 注入工具类、`imports` 引入 `JwtModule` 与 `TypeOrmModule.forFeature([User])`。
- 控制器用 `@Post('register')` + `@Body(RegisterDto)` 收参，服务层用 `@InjectRepository(User)` 拿仓储做查重与 `save`。
- 查重未过抛 `BadRequestException`，通过则 `save` 并返回 `msg` + `data(token)`。
