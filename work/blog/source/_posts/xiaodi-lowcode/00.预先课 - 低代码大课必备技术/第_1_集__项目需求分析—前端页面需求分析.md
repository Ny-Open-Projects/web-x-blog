# 项目需求分析—前端页面需求分析

> **导语**：本章进入「前端页面开发和接口联调」阶段，后端的课程查询、创建、修改、删除接口已经就绪，本节先把要做的页面逐一拆解清楚。你会弄明白登录/注册、课程管理这几块页面各自承担什么职责、分别对应哪些后端接口、用什么路由组织，以及样式方案为什么选 Tailwind CSS。先把需求边界划清楚，后面写 React 页面、做接口联调时才不会反复返工。

## 前置知识

阅读本文需要掌握 React 的组件、路由与状态基础，并对 NestJS 后端接口有基本认识。本课程前序已经完成后端接口开发，建议先回顾《后端接口开发—课程的查询接口开发》与《项目需求分析—接口和数据库数据结构分析》，把「页面要展示什么数据、数据从哪个接口来」对齐；前端工程如何搭建可对照《项目初始化—创建React项目和初始配置》。如果 React 基础尚不牢固，先补一门 React 专题内容再往下看会更顺。

## 正文

### 先搞清楚这一章要解决什么

前面几章我们一直在写 NestJS：装环境、连数据库、定义实体、把课程的增删改查接口一个个做出来。接口写完了不等于项目能用，还得有前端页面把这些接口「用起来」。所以本章的主线只有两件事：用 React 把页面写出来，再和已经开发好的接口联调。

这正是大厂产研流程里最朴素也最容易被跳过的一步——动手写代码之前先做需求分析。到了后面正式的低代码平台项目，这套思路会被进一步放大：先有需求文档，再拆功能点、画流程图与原型图，然后才落到组件 Schema 与 DSL 的设计上。预先课这里页面少、逻辑简单，正好用来把「需求先行」的习惯练熟。

### 三类页面，各自的分工

从需求上看，前端一共要交付三类页面：

- **登录页（login）与注册页（register）**：都是用户名加密码两个字段。注册要先于登录，用户先注册成为合法账号，才能登录系统。这一版刻意保持最简；如果是给真实消费者使用的商业级产品，还需要手机验证码登录、微信登录等方式，这些内容会在低代码平台正式项目里完整展开，预先课不在这里堆复杂度。
- **课程管理页（course management）**：这是本章的主页面。它要请求后端的课程查询接口，把数据库中预先定义好的课程数据拉回来，用表格展示出来；同时提供创建、编辑、删除三个操作入口，分别对应之前已经写好的三个接口。

也就是说，页面不是孤立存在的，每一个交互背后都要能指向一个明确的接口。做需求分析时把这条对应关系列清楚，联调阶段就不会出现「按钮点了没反应、不知道该调谁」的情况。

### 用路由把页面组织起来

路由规划直接照着页面清单来即可：`/login`、`/register`，以及课程管理对应的 `/course`。通过路由切换页面，而不是把所有内容塞进一个组件里。

课程管理页内部还需要再拆一层组件：

- **表格组件**：负责展示课程列表数据，是查询接口的数据落点。
- **创建/编辑组件**：以弹窗形式存在。点击「创建」或「编辑」时弹出，同一套表单既承担新建课程、也承担修改课程，只是提交时调用的接口不同。

这种「列表 + 弹窗表单」的结构是后台管理类页面的常见范式，后面低代码平台的编辑模块虽然复杂得多，但骨架仍然是「左侧组件列表、中间画布、右侧属性配置」这一套分区思路的延伸。

### 样式方案：Tailwind CSS

样式这一块选用 Tailwind CSS。它以工具类的方式写样式，不必为每个元素单独起名、再切到样式文件里维护，写样式代码更直接，开发效率也更高。对低代码语境还有一层额外的意义：低代码平台最终也是用一份结构化的 Schema 去描述组件长什么样、用什么样式，预先课先用这种「约定式、原子化」的写法建立直觉，后面理解 Schema 驱动渲染会更轻松。

### 关联工程与本地启动

后端工程配置见 `代码（已8期）/代码（已8期）/10-2/nest-cli.json`：

```json
{
  "$schema": "https://json.schemastore.org/nest-cli",
  "collection": "@nestjs/schematics",
  "sourceRoot": "src",
  "compilerOptions": {
    "deleteOutDir": true
  }
}
```

同目录 `package.json` 里提供了 `start`（nest start）、`start:dev`（nest start --watch）等脚本，前端联调时把服务用 `start:dev` 起在本地即可，接口地址形如 `http://localhost:3000`。配套资料还包含 `10-2` 到 `10-5` 各小节的 `tsconfig.json`、`tsconfig.build.json` 与 `test/jest-e2e.json`，需要核对编译与测试配置时按相对路径对照即可。

## 小结

- 本章主线是「React 写页面 + 与已完成的 NestJS 接口联调」，需求分析先于编码。
- 页面分三类：登录页、注册页、课程管理页；登录/注册最简实现，商业级登录方式留到正式项目。
- 课程管理页对应查询接口展示表格，创建/编辑/删除分别对应此前三个接口。
- 路由按 `/login`、`/register`、`/course` 划分；课程管理页内部拆表格组件与弹窗表单组件。
- 样式采用 Tailwind CSS 提效；后端服务用 `start:dev` 本地启动供联调。
