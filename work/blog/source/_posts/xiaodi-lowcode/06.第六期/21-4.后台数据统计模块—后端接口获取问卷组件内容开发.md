# 后台数据统计模块—后端接口获取问卷组件内容开发

> **导语**：后台统计的第二个接口是「获取问卷组件内容」，用于渲染左侧表格的每一行用户数据。本文讲解如何先校验页面是否存在、再查 `component_data`、并用 `Promise.all` 把每条记录的异步查表结果聚合成数组返回。

## 前置知识

- 已开发获取问卷组件接口，见《后台数据统计模块—后端接口获取问卷组件开发》。
- 已掌握 `component` 表与 `component_data` 表关系，见《后台数据统计模块—页面需求分析+接口分析》。
- 已了解 `Promise.all`，见《掌握Rxjs和在Nest中的应用》（异步聚合基础）。

## 正文

### 接口定义

在 `LowCodeController` 中新增 `getQuestionData`（路径 `question_data`）（路径对应后台统计问卷数据），`GET` 请求，同样需登录鉴权。方法 `getQuestionData` 解析 token 拿到 `user.id` 传入服务层。

### 服务层：先查页面再查 component_data

服务层逻辑分三步：

1. **校验页面是否存在**：用 `user.id` 查 `page` 表。若用户从未发布过页面，直接抛出「未找到页面，请先发布页面信息」；
2. **查 component_data**：拿到页面 ID 后，按 `page_id` 在 `component_data` 表中 `find` 出该页所有提交记录（可能多条，对应多个用户）；
3. **聚合每条记录的组件详情**：遍历每条记录，对其中每个组件项用 `item.id`（组件 ID）再去查 `component` 表，拿到它的 `type` 与 `options`（如单选「男/女」、多选「爱好」选项）。

### 用 Promise.all 聚合异步结果

因为遍历中对 `component` 表的查询是异步的，所以把每个异步查询放进数组，用 `Promise.all(...)` 等待全部完成再返回正常数组：

```ts
const matchesComponetDatas = await Promise.all(
  componentDatas.map(async (comp) => await Promise.all(
    comp.props.map(async (item) => {
      const componentResult = await this.ComponentRepository.findOneBy({ id: item.id });
      return {
        result: item,
        type: componentResult?.type,
        options: componentResult?.options?.options || {},
      };
    }),
  )),
);
```

`component_data` 中只存「组件 ID + 用户 value」，而 `title`/选项等描述信息在 `component` 表，因此需要这一步二次查表补全。最终返回「数组包裹数组」的结构（外层按用户、内层按组件），便于前端表格渲染。

### 联调验证

Apifox 中 `headers` 带 `Bearer <token>`，请求 `questionData`：返回数据含输入框（value=老王，options 空）、文本域（value=小滴课堂讲师）、单选（options 男/女）、多选（options 游泳/篮球/按摩）。Navicat 中 `component_data` 可见老王（Chrome 提交）与冰冰（Firefox 提交）两条记录，对得上。

## 小结

1. 接口 `questionData`（`GET`）需登录，用于返回左侧表格内容。
2. 服务层先按 `user.id` 查 `page` 表校验是否发布过，否则报错。
3. 按 `page_id` 查 `component_data`，再对每条用组件 ID 查 `component` 补全 `type`/`options`。
4. 用 `Promise.all` 聚合异步查表结果，返回「数组包裹数组」结构。
