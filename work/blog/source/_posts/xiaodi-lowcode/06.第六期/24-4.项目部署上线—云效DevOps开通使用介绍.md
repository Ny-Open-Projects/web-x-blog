# 项目部署上线—云效DevOps开通使用介绍

> **导语**：前面把 Dockerfile、docker-compose、各类镜像都准备好了，本节讲怎么把它们串成一条自动化流水线。内容是阿里云云效 DevOps 的开通与使用：从控制台进入流水线 Flow、把代码托管到 Codeup、新建空模板流水线、配置 monorepo 构建与 OSS 上传、镜像构建推送，直到最后在服务器上用 `docker compose up -d` 部署。这一节偏「认识界面与流程」，下一节开始实操。

## 前置知识

需要先理解 DevOps 与 CI/CD 的概念，建议看过《项目部署上线—互联公司的DevOps和CI-CD你知道多少？》；流水线里构建的镜像对应《项目部署上线—构建后端nginx镜像的Dockerfile配置》与《项目部署上线—Docker-compose运行多容器的配置》，代码托管部分可对照《低代码平台项目代码管理—云效 Codeup》。

## 正文

### 进入云效与前提条件

在阿里云官网控制台搜索「云效 DevOps」即可进入，平台定位是「云原生时代的新 DevOps 平台」。进入后点击「流水线 Flow」开始配置。

**前提是代码必须托管在云效 Codeup 里**——它和 Git / GitHub 类似，Dockerfile、docker-compose 等部署文件都要提交到这个仓库。云效 DevOps 整条流水线都依赖这份代码源，没有仓库就没法往下走。课程的代码仓库里能看到之前提交的各类配置与代码。

### 新建流水线：空模板 + 添加流水线源

新建流水线时选「空模板」即可，其它模板不用管。创建后第一步是**添加流水线源**：选择 Codeup 代码仓库（如课程仓库 `lowcode`）、指定分支，点击添加。这一步回答的是「代码从哪来」。

接着添加任务与步骤。备课示例里把流水线分成两个阶段，下面按阶段拆解。

### 阶段一：构建、上传前端、上传编排文件

**1. 打包构建 monorepo**：项目用 pnpm workspace 在一个工作区里维护多个子包，这一步选预置的 Node 版本，执行的命令大致是：设置 pnpm 镜像源 → 安装依赖 → 提前构建 `share` 子包 → 构建前端 React 项目（`client`）。`release` 对应发布页、`server` 对应后端，按需要分别构建。因为 `share` 是其它子包的依赖，必须先构建它，否则前端找不到共享组件与类型。

**2. OSS 上传**：提前在对象存储里创建一个 Bucket（例如 `lowcode-client`），把前端构建产物上传进去。Bucket 侧还要配置静态页面（默认首页 `index.html`）、域名管理（绑定域名后续再讲）、地域等；源文件目录填 `packages/client/dist`——工作区里维护着 `client`、`release`、`share`、`server`，构建产物就在各自子包的 `dist` 目录。

**3. 上传 docker-compose 制品**：把 `docker-compose.yml` 作为制品上传到云效，记录制品名称与打包路径。后面部署阶段会把这个制品下载到服务器。

### 阶段二：镜像构建、下载制品、部署

这一阶段可以添加并行任务：

**1. 镜像构建**：分别构建后端 nginx 镜像、后端服务镜像、release nginx 镜像、Redis 镜像，并自动推送到阿里云镜像仓库（需提前创建镜像仓库并指定地域）。镜像标签用变量映射，例如 `docker_nginx_tag`、`backend_tag` 一类，对应前面 Dockerfile 里定义的镜像名称变量——标签指向的就是上一步构建出来的镜像。

**2. 下载 docker-compose 制品**：指定制品名称与下载/解压路径，把阶段一上传的 compose 文件放到服务器上。

**3. 部署**：因为可能是二次、三次部署，若旧容器和旧镜像没删除会报错，所以顺序是**先停止并删除容器、再删除旧镜像**，最后启动：

```bash
docker compose -f ./docker-compose.yml up -d
```

`-f` 指定上一步下载解压出来的 compose 文件路径，`up` 启动，`-d` 表示后台运行。

### 配置完成后能拿到什么

全部配置完成后，项目即可部署上线，通过自己的域名访问低代码平台本身、发布出去的项目页面，以及后端接口——三者都能正常请求。本节主要是把云效的界面、概念和流水线结构讲清楚，口播里也提到网络偶尔慢、页面加载慢属于环境问题，重试即可；从下一节课开始进入实操。

> 说明：本节课程未提供配套代码物料，上述命令来自课程口播中的部署步骤，具体配置以云效控制台与官方文档为准。

### 关联工程与配套资料

根目录 `课程配套代码/24-4/lowcode/` 下的各子包 `package.json` 提供了流水线里 `build:client`、`build:server`、`build:release`、`build:share` 等脚本；本节课程未附带代码片段，部署相关文件以仓库中已提交的 Dockerfile、docker-compose 与 nginx 配置为准。前几节已逐项讲过它们的写法，这里只是把「构建 → 上传 → 部署」串起来。

## 小结

- 从阿里云控制台搜索「云效 DevOps」进入，点「流水线 Flow」；代码必须先托管在云效 Codeup。
- 新建流水线选空模板，先添加流水线源（Codeup 仓库 + 分支），再添加任务/步骤。
- 阶段一：构建 pnpm workspace monorepo（先构建 `share`）、前端产物上传 OSS Bucket（`packages/client/dist`）、上传 docker-compose 制品。
- 阶段二：并行构建并推送后端 nginx / 后端服务 / release nginx / Redis 镜像（标签用变量映射）、下载 compose 制品、先删旧容器旧镜像再 `docker compose -f ... up -d`。
- 配置完成后可通过自有域名访问低代码平台、发布页面与后端接口；本节为流程介绍，下节起实操。
