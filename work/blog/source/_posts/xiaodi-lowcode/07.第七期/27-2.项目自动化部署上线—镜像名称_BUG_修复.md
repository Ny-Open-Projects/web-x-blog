# 项目自动化部署上线—镜像名称_BUG_修复

> **导语**：第一次运行自动化部署，流水线触发后逐步执行三个阶段。本集记录运行后端 / 前端发布 Nginx 镜像构建时遇到的第一个真实报错——Dockerfile 里 `FROM nginx` 多写了一个冒号，导致拉取基础镜像失败，并演示如何修复后重新提交运行。

## 前置知识

- 已完成《第1集 项目自动化部署上线—更改线上 ip+端口》，代码已改成线上配置并提交。
- 了解云效流水线运行与日志查看，参见《DevOps自动化部署实现—多个镜像运行在服务器配置《下》》。

## 正文

### 触发流水线运行

回到云效流水线，点击**运行**。代码源已自动绑定，分支选 `master`（若你自建了其他分支可选对应分支）。运行备注可写"bug 修复 / 功能测试"便于追溯。

构建阶段是并行执行的：React 打包 → OSS 上传 → compose 文件上传，这三个步骤会同步跑。可以点**日志**看详细输出：设置镜像源、全局安装 pnpm、下载依赖、打包 `share` 公共包、打包 `client` 前端、生成 `dist`、OSS 上传、compose 文件上传，每一步都有清晰日志。

### 遇到的第一个报错

后端项目配置里出现"运行失败，请查看日志"。点开日志发现：在构建**后端 Nginx 镜像**和**前端发布 Nginx 镜像**时，报错指向 Dockerfile 里的这一行——`FROM nginx::`（拉取基础镜像时**多了一个冒号**）。

正常应该只有一个冒号，例如：

```dockerfile
# 错误写法（多了一个冒号）
FROM nginx::

# 正确写法
FROM nginx
```

> 备注：从海外 Docker Hub 拉取基础镜像时，云效会提示"海外网络速度慢、不稳定"，这只是**提醒不是报错**，可以忽略；真正失败的是上面这个多冒号的问题。

### 修复并重新提交

打开对应 Dockerfile：`server.nginx.Dockerfile` 与 `release.nginx.Dockerfile`，把多余的冒号删掉，保存。提交信息写"fix: 修复 Nginx 镜像名称"，推送到远程后重新点击**运行**。

重新运行后，这两个 Nginx 镜像构建步骤恢复成功。其余步骤因流水线排队可稍后观察，下一集继续排查。

## 小结

1. 首次运行流水线，构建阶段三步骤（打包 / OSS / compose）会并行执行，日志可逐步查看。
2. "海外镜像源速度慢"只是提醒，不是报错，可忽略。
3. 真正的报错：Nginx 镜像 Dockerfile 里 `FROM nginx::` 多了一个冒号。
4. 修复方式：删掉多余冒号，改为 `FROM nginx`，重新提交并运行（最终仓库为 `FROM nginx:1.25.0-alpine`，pin tag 是生产惯例）。
5. 修复后后端 Nginx 与前端发布 Nginx 两个镜像构建成功。

## 下一步

Nginx 镜像的多冒号已修复，但运行后前端发布项目镜像又报"找不到文件"。建议接着看《项目自动化部署上线—Dockerfile名称 BUG 修复》，解决 Dockerfile 文件名多字母的问题。
