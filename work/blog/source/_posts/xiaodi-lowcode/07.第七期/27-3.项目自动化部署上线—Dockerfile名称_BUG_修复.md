# 项目自动化部署上线—Dockerfile名称_BUG_修复

> **导语**：上一集修复了 Nginx 镜像多冒号的问题，重新运行后后端两个镜像构建成功，但前端发布项目镜像又报"找不到 release.Dockerfile"。本集定位到是 Dockerfile 文件名多写了一个字母 s（Releases），改名后重新运行，四个镜像全部构建成功。

## 前置知识

- 已完成《项目自动化部署上线—镜像名称 BUG 修复》，Nginx 镜像多冒号问题已解决。
- 了解阿里云 ACR 镜像仓库的查看方式。

## 正文

### 前端发布项目镜像报错

重新运行流水线后，后端项目镜像、后端 Nginx 镜像均构建成功并推送到 ACR 的 `local-images` 命名空间。但前端发布的并行任务里，前端发布**项目镜像**构建失败。

查看日志，报错信息是：**没有找到 `release.Dockerfile` 这个文件**——既不是路径问题，也不是构建指令问题，而是文件本身不存在。

### 定位：文件名多了一个 s

回到代码源检查，发现前端发布目录下的 Dockerfile 文件名被写成了 `Releases.dockerfile`（多了一个字母 **s**），而流水线配置里填写的是 `release.Dockerfile`，大小写 / 拼写对不上，自然找不到文件。

在本地把它重命名为正确的 `release.Dockerfile`：

```bash
# 把多了一个 s 的文件名改回正确名称
mv Releases.dockerfile release.Dockerfile
```

### 重新运行并验证四个镜像

提交代码（备注"fix: 修复 release.Dockerfile 文件名称"），重新点击**运行**。待流水线跑完后，到阿里云 ACR 镜像仓库验证：

- 注意**地域**要选对（本课程是广州），否则会显示"无数据"；
- 刷新后能看到四个镜像：前端发布项目、后端项目、前端发布 Nginx、后端 Nginx，全部就位。

> 小提示：ACR 里会保留历史镜像，若存储空间告警，可手动清理备课阶段产生的无用镜像。

## 小结

1. 前端发布项目镜像报错"找不到文件"，根因是 Dockerfile 文件名多写了一个 s（`Releases.dockerfile`）。
2. 流水线配置填的是 `release.Dockerfile`，文件名拼写不一致导致构建失败。
3. 修复：重命名为 `release.Dockerfile` 后提交。
4. 重新运行，四个镜像（前端发布项目 / 后端项目 / 前端发布 Nginx / 后端 Nginx）全部构建成功并推送 ACR。
5. 验证时记得选对 ACR 地域（广州），并可清理无用历史镜像。
