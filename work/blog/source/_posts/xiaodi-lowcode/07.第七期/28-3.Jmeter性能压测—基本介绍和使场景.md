# Jmeter性能压测—基本介绍和使场景

> **导语**：本集介绍 JMeter 的基本身份——Apache 基于 Java 开发的开源性能测试工具，并重点澄清一个关键认知：JMeter 不是浏览器，它在协议层工作、不执行 JS / 不渲染 HTML，因此最适合压测的是后端异步接口（axios / fetch），而非 UI 功能。

## 正文

### 什么是 JMeter

JMeter 是由 **Apache** 基于 **Java** 开发的一款开源性能测试工具，免费提供给所有人使用。其官方文档（Overview）清晰说明了它"支持什么协议 / 应用、怎么做、如何开始"，作为程序员提升英文文档阅读能力也很有帮助。

### 核心特点

- **开源免费、功能强大**，互联网公司不少会使用并二次封装出自家压测平台；
- 支持功能测试与单机 / 分布式压力测试（分布式实际用得较少，单机通常已能定位性能问题）；
- 基于 Java 开发，上手容易、性能高；
- 提供测试数据分析与图形化报表。

### 关键认知：JMeter 不是浏览器

这一点务必记住——JMeter 不在浏览器层面工作，它是在**协议级别**工作。官方也明确强调 JMeter 不是一个浏览器：它不渲染 HTML 页面，也不执行页面里的 JavaScript，因此**不适合做 UI 功能的自动化测试**。

我们可以用浏览器控制台 Network 验证：刷新一个网站会产生大量请求，包含 JS、Image、HTML 等静态资源。JMeter 无法识别 JS 类型的请求，自然不能像真实浏览器那样"看"页面。

### JMeter 真正擅长压测什么

JMeter 最重要的是压测**异步接口请求**——也就是 axios、fetch 发起的那些后端接口。对于静态资源（CSS、JS、图片），想看性能可直接在浏览器 Network 里筛选对应类型、看响应时间（Time）与体积即可，无需 JMeter。

后续课程里，我们就会用 JMeter 去压测本低代码平台由 Node / **NestJS** 开发的后端异步接口，找出瓶颈并做缓存等优化。

### 与 UI 自动化测试的区别

UI 功能自动化测试是模拟人为操作（点击、搜索、登录、退出、观看视频等），属于功能测试范畴；而 JMeter 在协议层模拟请求，更适合测后端接口与高并发场景。两者分工明确。

## 小结

1. JMeter 是 Apache 基于 Java 的开源性能测试工具，免费且功能强大。
2. 支持功能测试、单机 / 分布式压测，提供图形化报表。
3. 关键特性：JMeter 不是浏览器，在协议层工作，不渲染 HTML、不执行 JS。
4. 因此不适合 UI 自动化测试，最适合压测 axios / fetch 等异步后端接口。
5. 后续将用 JMeter 压测本平台 NestJS 开发的后端接口并优化。
