# 项目自动化部署上线—Docker-compose上传_BUG_修复

> **导语**：四个镜像构建成功后，部署阶段的"Docker-compose 文件上传"任务却失败了。本集定位到解压脚本里把 `tar` 的 `-C`（指定目标目录）误写成了 `-c`（创建归档），导致解压报错，修正后整条流水线跑通。

## 前置知识

- 已完成《项目自动化部署上线—Dockerfile名称 BUG 修复》，四个镜像已成功推送 ACR。
- 了解 `tar` 命令参数，参见《DevOps自动化部署实现—Docker-compose 文件上传服务器配置》。

## 正文

### 部署阶段 compose 文件上传失败

重新运行流水线：构建阶段三个步骤完成，其中的"Docker-compose 文件上传"步骤却报错。

问题出在上传时配置的 Linux 解压命令。原本意图是：把下载到 `/root/yx/` 的压缩包解压，并把内容复制到上一级目录 `/root/yx` 下。脚本里写的是：

```bash
# 错误写法：用了小写 -c（创建新归档），与 zxvf 冲突
tar zxvf /root/yx/backend.tgz -c /root/yx
```

### 根因：-c 与 -C 用错

`tar` 的两个参数含义完全不同：

- **`-c`（小写）**：Create，创建一个新归档文件；
- **`-C`（大写）**：Change directory，解压 / 操作时切换到指定目标目录。

我们这里是要"解压到目标目录"，必须用大写 `-C`。小写 `-c` 和 `zxvf`（解压）语义冲突，所以命令执行失败。

```bash
# 正确写法：用大写 -C 指定解压目标目录
tar zxvf /root/yx/backend.tgz -C /root/yx
```

### 修正后重跑，整条流水线跑通

在部署脚本里把 `-c` 改为 `-C`，保存后重新**运行**。观察结果：

- 第一阶段三个构建步骤完成；
- 构建阶段的 Docker-compose 文件上传步骤成功（部署详情显示"已完成"，日志无报错）；
- 第三阶段 Docker 部署也完成：脚本关联了四个镜像变量（`backend_tag`、`backend_nginx_tag`、`frontend_tag`、`frontend_nginx_tag`），把 ACR 里的四个镜像拉到自有服务器，`docker compose up -d` 启动容器。

日志里可以看到 `docker stop` / `docker rm` / `docker rmi` 清理旧容器旧镜像，再拉起新容器的过程。部分 `docker compose` 执行细节若未打印也属正常。

## 小结

1. 部署阶段 compose 文件上传失败，根因是 tar 参数用错。
2. 小写 `-c` 是"创建归档"，大写 `-C` 是"指定目标目录"，解压到目录必须用 `-C`。
3. 修正为 `tar zxvf ... -C /root/yx` 后重新运行。
4. 修正后三阶段全部成功：构建 → compose 上传 → Docker 部署启动四个容器。
5. 部署日志可验证四个镜像变量已正确关联并拉起。
