# 低代码项目平台需求文档—非功能需求+项目规划

> **导语**：本文讲解需求文档中的非功能需求与项目规划。我们将说明非功能需求（产品经理侧）的关注点，以及一套标准互联网项目的开发规划：从需求评审、UI 设计、前后端同步开发、联调提测，到预发上线与二次迭代，并介绍用甘特图落实任务到人的方法。

## 前置知识
阅读本文建议先看完《低代码项目平台需求文档—功能描述流程图+原型图》，完成功能描述后再补充非功能需求与项目规划。

## 正文

### 非功能需求（了解即可）
非功能需求偏产品经理职责，开发者了解即可，包括：

- 产品在市场中的定位、目标群体、目标客户；
- 品牌建设、推广、合作伙伴与运营；
- 财务与法务需求。

产品经理除了画原型图、流程图、开会讲解逻辑，还需掌握运营，这部分同样重要。

### 项目规划：标准开发流程
需求文档写好后，按以下节奏推进：

1. **需求评审**：组织前端、后端、测试、UI 评审需求，区分合理与不合理，规划时间并落实到开发者；
2. **UI 设计**：设计师输出 UI 图；
3. **前后端同步开发**：前端可基于 Mock 数据先行开发，不必等后端；后端负责数据库设计、架构设计与编码，并提前与前端对齐接口协议（入参类型、出参格式）；
4. **联调**：前端调用后端接口，验证功能在开发/测试环境运行；
5. **提测**：自测无大问题后提交测试，由测试挖掘细节 Bug；
6. **测试用例评审**：测试主持，拉齐前后端、设计、产品，明确测试功能点、性能目标（如 QPS）；
7. **上线**：回归测试 → 申请线上资源 → 预发布环境验证 → 确认上线 → 通知全员。

### 用甘特图落实任务
更细致时引入甘特图，把需求拆成具体任务并指定负责人与预估时间：

- 前端：负责哪些页面；
- 后端：负责哪些接口；
- 测试：负责测试；
- UI：负责设计。

### 运营与迭代
上线后进入日常运营放量、常规运营与适当推广。若需二次迭代，则重新走「二期需求评审」，严格按项目规划再来一遍，使项目有条不紊推进。

### 配套资料
完整需求文档与流程可对照：`笔记+资料-已8期/全栈低代码平台需求文档.pdf`。

## 小结
- 非功能需求偏产品/运营，开发者了解即可；
- 标准流程：评审 → UI 设计 → 同步开发（先对接口协议）→ 联调 → 提测 → 用例评审 → 上线；
- 前端可用 Mock 提前开发，前后端并行；
- 甘特图把任务落实到人，明确负责人与预估时间；
- 二次迭代需重新走需求评审。
