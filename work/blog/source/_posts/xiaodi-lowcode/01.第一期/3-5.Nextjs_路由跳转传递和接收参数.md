# Nextjs_ 路由跳转传递和接收参数

> **导语**：页面跳转不丢数据，是路由的基本功。本文系统梳理 Next.js（App Router）中标签跳转与编程式导航的传参方式：字符串拼接 query、对象形式 pathname + query，以及接收侧的 useSearchParams 与 props.searchParams 两条路径，并解释为什么 push 的第二个参数只有 scroll。读完你能根据组件运行在客户端还是服务端，选对传参与取值方式。

## 前置知识

建议先读《Nextjs 应用路由器和导航跳转》熟悉 Link 与 useRouter 的基本跳转，再读《Nextjs 路由处理 Route Groups + 动态路由》了解路由组织；对客户端组件 / 服务端组件的区分有概念即可，本篇会反复用到。

## 正文

### 标签跳转的两种传参方式

第一种是字符串拼接：在路径后加问号，多个参数用 & 连接，值写在等号后面。例如从 personalOne 跳到 aboutOne：

```tsx
<Link href="/aboutOne?id=小滴课堂&name=老王">去关于页面</Link>
```

第二种是对象形式：用大括号包裹（JSX 里大括号表示写表达式），设置 pathname 指定目标路径，query 以对象形式承载参数：

```tsx
<Link href={{ pathname: '/aboutOne', query: { id: '小滴课堂', name: '老王' } }}>
  去关于页面
</Link>
```

两种方式最终都会生成带查询串的 URL，区别只在书写习惯：参数少、来源动态时用字符串更直接，参数多、结构清晰时用对象更好维护。

### 接收参数：useSearchParams 与 props.searchParams

接收侧有两条路径，对应两类组件。

其一是客户端组件里用 useSearchParams（来自 next/navigation）：它是一个函数，调用后通过 .get('id')、.get('name') 逐个取值。

```tsx
'use client';
import { useSearchParams } from 'next/navigation';

export default function AboutOne() {
  const searchParams = useSearchParams();
  const id = searchParams.get('id') as string;
  const name = searchParams.get('name') as string;
  return <p>personalOne 页面传递过来的参数：{id}、{name}</p>;
}
```

这里有两个必须注意的点。第一，useSearchParams 只支持客户端组件，若留在服务端组件里编译会直接报错，所以文件顶部要加 'use client'。第二，TypeScript 下 .get() 的返回值可能为空，会有类型警告，显式标注为 string（或做空值兜底）即可消除。演示中把 aboutOne 路径少写了末尾的 "one"，浏览器报"没有找到该路径"，修正后参数才正常渲染出来——路由路径本身也要逐字核对。

其二是页面组件（服务端）直接读 props.searchParams，打印 props.searchParams 就能拿到同样的参数对象，无需引入任何 hook。它适合在服务端渲染阶段就读取查询参数的场景。

```tsx
export default function AboutOne({ searchParams }: { searchParams: Record<string, string | string[] | undefined> }) {
  console.log(searchParams);
  return <p>关于页面</p>;
}
```

### 编程式导航：只支持字符串，第二个参数是 scroll

编程式路由导航（useRouter().push）也能传参，但方式有限制：只支持字符串拼接，不支持对象形式。

```tsx
'use client';
import { useRouter } from 'next/navigation';

const router = useRouter();
router.push('/aboutOne?id=小滴课堂&name=老王');
```

为什么不支持对象？直接看源码就清楚了：按住 Command 点击 push 方法跳进去，它接收的第一个参数是要跳转的路径，第二个是 options；再顺着类型接口往下点，会发现 options 里只定义了 scroll 这个属性。也就是说，push 的第二个参数是控制跳转后是否滚动到页面顶部的布尔值，与传参无关：

```tsx
router.push('/aboutOne?id=小滴课堂', { scroll: true });
```

接收侧与标签跳转完全一致，仍用 useSearchParams 或 props.searchParams。这也提醒我们：很多 API 的用法不必死记，顺着类型定义看一遍源码往往最直接。

## 小结

- 标签跳转传参两种写法：字符串 `?id=...&name=...`，或对象 `{ pathname, query }`。
- 接收参数两条路径：客户端组件用 useSearchParams().get()，服务端页面组件用 props.searchParams。
- useSearchParams 必须配合 'use client'；TS 下 .get() 可能为空，需断言为 string 或兜底。
- 编程式导航 push 只支持字符串传参，第二个参数 options 仅有 scroll 属性，用来控制是否回到顶部。
- 工程为 Next.js 14.0.1 + React 18 的 App Router，路由 API 以 next/navigation 为准。
