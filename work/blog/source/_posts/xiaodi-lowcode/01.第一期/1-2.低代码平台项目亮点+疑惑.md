## 正文

### 项目亮点：三档难度递进

课程亮点分为 P3、P2、P1 三档，难度逐级上升，越往下越难。

#### P3：对标中级前端开发工程师

- **B 端（低代码编辑端）**：使用大厂标配技术栈 **React + TypeScript**，实现复杂低代码逻辑；公共状态管理用 **MobX**，相比 **Redux** 配置和使用都更简单，能提升开发效率。
- UI 与样式：依赖第三方组件库 **Ant Design**，配合 **Tailwind CSS** 写样式更轻松。
- 数据可视化：**ECharts**。
- **C 端（用户发布页）**：使用服务端渲染框架 **Next.js**（SSR）开发 H5 用户端，用户在编辑端发布官网、问卷或答题页面后，C 端即可访问。

#### P2：对标高级前端工程师

- 引入 **ahooks** 与大量自定义 Hooks，处理复杂状态管理与性能优化。
- 低代码平台内含多种组件，需要思考组件的数据结构设计，并把公共组件模块抽离复用——编辑端和发布页复用同一套组件。
- 低代码多功能设计：拖拽排序、预览草稿、一键发布 C 端页面等。
- 两个业务场景：**自定义官网** 与 **自定义问卷**。流程上保存/发布官网，H5 的 C 端展示线上官网；问卷编辑发布后用户扫码或访问地址填写，后台用 ECharts 统计可视化，并支持导出 Excel 下载。
- **Redis 自定义 key 规则**：结合图形验证码 + 原子性防重提交，保证「写入 Redis 的两个操作」与 MySQL 数据一致性（参考前面前端大课讲过的防短信盗刷方案）。
- 前端性能优化。

#### P1：对标前端技术组长

- 大量 **React 函数式组件**；后端使用 **Nest** 框架（课程上线前已发布 Nest 专题课，不熟悉可先看）。
- 三个端协同：B 端、C 端（Next.js 开发官网/问卷系统）、后端（Nest + TypeORM 操作数据库，Redis 做接口数据缓存提升性能）。
- 前后端交互通过 **Nginx** 代理，可多服务器负载均衡、压缩。
- 自定义字段、线下预览、压缩文件下载；云服务器部署，用 **OSS** 存储静态资源（图片、视频、卡片等体积较大的资源不占业务服务器，交由阿里云 OSS 维护）。
- **Docker** 生成自定义镜像、运行容器；全栈 **DevOps** 用阿里云**云效**做 CI/CD 流水线，实现一键上线。
- 用 **JMeter** 对后端接口做性能压测与优化；前端 **CDN** + 阿里云 OSS 综合实战。

### 大家常见的疑惑

- **平台能提供哪些功能？** 前面反复强调过：零代码发布网站与问卷系统。
- **什么时候开始 / 完结？** 课程从 2023 年 11 月开始，次年上旬完结（正文后续章节已全部产出）；项目可实操、已上线。
- **大课是否适合我？** 请对照自己属于哪一类人群（见课程介绍篇），先想清楚对标层级。
- **面试官问「有没有在线地址」怎么答？**
  - 在校生：可说是比赛项目或毕业设计。
  - 在职：可说项目已停止维护。**关键是项目亮点和技术方案必须真正掌握**，否则一问三不知就是减分项。简历里写亮点但答不上来，反而扣分。
- **技术栈很多、只会一部分能不能学？** 必须掌握 **React** 和 **Next.js**，缺这两块可五折购买对应专题课（联系客服或讲师）。强烈建议跟着视频进度学习，并加入大课群讨论，保持学习氛围。

## 小结

1. 亮点分 P3（中级）/ P2（高级）/ P1（技术组长）三档，难度递进。
2. P3 核心是 React+TS+MobX+AntD+Tailwind+ECharts 的编辑端，以及 Next.js SSR 的 C 端。
3. P2 重点是自定义 Hooks、组件复用、拖拽/预览/发布、问卷可视化与 Redis 防重提交。
4. P1 覆盖 Nest 后端、Nginx、OSS、Docker、云效 CI/CD、JMeter 压测等全栈 DevOps。
5. 简历亮点的前提是真懂，面试官追问要能答上来。
6. 硬性基础要求：React 与 Next.js，缺课可五折补。
