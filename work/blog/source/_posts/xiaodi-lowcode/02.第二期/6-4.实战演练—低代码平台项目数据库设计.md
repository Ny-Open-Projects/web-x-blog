# 实战演练—低代码平台项目数据库设计

> **导语**：本文落地本项目的数据库设计，给出低代码平台的五张核心数据表（user / page / component / component_data / resources），说明每张表的字段与表间关系，并演示如何用 Navicat 与 MySQL Workbench 绘制 ER 图、导入 SQL。

## 前置知识
阅读本文建议先看完《数据舞台上的编织艺术-数据库ER图设计》，理解实体、属性、关系与关系类型。

## 正文

### 五张核心数据表
**1. 用户表 user**
项目需要注册登录，故维护用户信息：`username`（用户名）、`phone`（手机号）、`password`、`open_id`（微信扫码登录的微信索引值）等。

**2. 页面表 page**
进入编辑端时，若上次编辑过会从草稿缓存/服务端恢复（最终实现里服务端恢复链路受限，实际主要靠 localStorage 草稿），因此需页面表维护「一个用户发布的一个页面」。一个用户只能发布一个页面，重新编辑发布会替换上一次。字段含页面名、TDK（Title/Description/Keywords）与 SEO 描述等。

**3. 页面组件表 component**
记录页面包含哪些组件：轮播图（banner）、列表（list）、视频（video）等。每条组件含 `pageId`（归属哪个页面）、组件类型字段，以及与页面表的一对多关系（一个页面多个组件）。

**4. 问卷数据表 component_data**
发布后的问卷组件（输入框、单选、多选等）收集到的用户填写数据单独维护在此表。字段含 `page_id`（对应页面）、`user`（访客匿名标识，服务端按 MD5(ip+ua) 生成，并非登录用户名）、`props`（用户提交的数据，simple-json 数组，形如 `[{id, value}]`）。

**5. 资源表 resources**
专门存放静态资源（视频、图片），但存的是**访问该资源的 URL** 而非文件本身——上传时文件进 OSS 文件服务器，调用 API 得到访问 URL 后存入本表。字段含资源地址、类型（`video`/`image`）、所属用户 ID、名称等。

### 组件属性如何存：option 字段
每个组件有专属属性，如视频的播放地址、起始秒数、是否循环；轮播图的图片数组、速度、跳转 `link`。这些统一以 JSON 存于 `options` 字段。例如轮播图 `option` 内是 `images` 数组，每项含图片地址、样式、跳转 URL、名称。

### 表间关系（ER）
- user : page = **1:1**（一个用户一个页面）；
- user : component = **1:n**（一个用户多个组件）；
- user : resources = **1:n**（一个用户可上传多个视频/图片）；
- page : component = **1:n**；
- page : component_data = **1:n**。

### 用工具绘制与导入
- **Navicat**：可视化查看已建表与字段；
- **MySQL Workbench**：通过 `Database → Reverse Engineer` 从数据库反向导出 ER 图，用 1:1（两横杠）、1:n（一端两竖线、多端符号）等标记关系；
- **导入 SQL**：资料中提供 `xdclass-lowcode.sql`，在 Navicat 中右键运行 SQL 文件即可导入建好的表、字段与数据。

### 配套资料
数据库脚本与模型文件：`笔记+资料-已8期/xdclass-lowcode.sql`、`笔记+资料-已8期/低代码平台数据库设计.mwb`。

## 小结
- 五张表：user、page、component、component_data、resources；
- 组件属性统一以 JSON 存于 `option` 字段；
- resources 表存 OSS 返回的访问 URL，而非文件本体；
- 关系：user:page 1:1，其余多为 1:n；
- 用 Navicat 查看、MySQL Workbench 反向生成 ER 图、导入 .sql 建表。
