# 全栈高级工程师简历编写实战—个人技术栈模块

> **导语**：课程走到简历篇，第一集专门讲「个人技术栈」怎么写。技术栈太少显得单薄，堆得太多又显得乱，正确的做法是「有横有纵」：核心框架懂原理，周边框架会用，同时守住几条铁律——千万别写「精通」、不懂的别写、学会引导面试官。本文把这些原则，以及面试前该补齐的知识面一次性梳理清楚。

## 前置知识

这一章默认你已经学完课程主体内容，建议先回看《低代码平台项目大课介绍+适合人员+学后水平》明确目标岗位，再对照《大展经纶—低代码项目大课的技术栈选择》复习本项目的技术选型；框架层面的对比可看《龙争虎斗—前端开发必学框架之 Vue 和 React》与《群雄纷争—高级+全栈前端工程师必学之 Express+Koa+Nestjs》。

## 正文

### 技术栈要「有横有纵」

对高级/全栈工程师来说，只写几个框架、写得太简单肯定不行；但写一大堆、写得杂乱同样减分。合理的结构是分层：

- **必须懂原理的核心框架**：本项目编辑端用的是 React，它是重中之重，原理要真正吃透；
- **会用、了解部分原理即可的框架**：服务端渲染的 Next.js（发布页用）、后端 NestJS（Node 生态）。不必过度深究，但框架的设计思想、优缺点必须知道；
- **要有几个「很懂」的框架**：比如 React 与 Vue 3，包含原理以及业界同类解决方案的对比。

这三个框架在本课程里都有对应位置：低代码编辑端 React、发布之后的服务端渲染页面 Next.js、后端通过 Node 的 NestJS 开发。写简历时正好用「项目里真实用过」来支撑每一条技术栈，而不是凭空罗列。

### 一条铁律：千万别写「精通」

这点值得强调三遍：**技术栈里不要写「精通」**。可写「熟悉」「掌握」「了解」，但「精通」是大忌——除非你确实是非常资深的高级工程师。写「精通」等于主动把面试官的提问难度拉到最高，一旦答不上来，整份简历的可信度都会被打折。

### 写技术栈与应对面试的四个问题

- **问题一：按自己的真实情况写，不懂的一定不要写。** 简历上每一个词都可能是追问入口，写上去就要能讲清楚。
- **问题二：不要被面试官挖坑，要学会引导。** 主动把话题引到自己熟悉的框架；遇到不会的框架，尽量周旋、转到自己会的框架上展开讲，而不是硬答。
- **问题三：初中级工程师要适当删减技术栈。** 写得过满与当前级别不匹配，反而暴露短板，宁可少而扎实。
- **问题四：必须有几个很懂的框架。** 如 React、Vue 3，要能讲原理、能做同类方案对比；不熟的框架直接到官网专题课程补齐。

学习路径上，按官网的学习路线把每个专题视频仔细学完，再进阶到大课——专题课里会把重点讲出来，大课负责把它们串成完整项目经验。

### 面试前要补齐的知识面

投递校招、社招之前，除了框架，还要系统准备这些方向：

- 计算机编程语言基础；
- 框架（结合自己熟悉的，以及目标公司实际使用的技术栈——提前了解对方用 React 还是 Vue、Node 侧用 NestJS 还是 Express）；
- 网络、算法、数据库、设计模式；
- 高并发、高可用、分布式、性能优化；
- 逻辑思维、测试、安全、产品运营思维。

很多同学会问：我只是前端或后端工程师，为什么要懂测试、安全、产品运营？因为这一阶段的目标是**高级 / 全栈工程师**：产品思维可以略懂，但安全、测试要着重懂，运维侧的自动化部署也要懂，性能优化与逻辑思维更是重中之重。这些内容课程前面都有讲解与实战——比如 Jmeter 性能压测、Docker 与云效 DevOps 自动化部署——正好可以写进简历并支撑面试问答。

## 小结

- 技术栈要「有横有纵」：React 懂原理，Next.js / NestJS 会用并了解设计思想与优缺点，另需几个很懂的框架（React、Vue 3）能做同类方案对比。
- **绝不写「精通」**，可用熟悉、掌握、了解；这是简历大忌。
- 四个注意点：不懂的不写、学会引导面试官问自己会的框架、初中级适当删减、必须有几个深挖的框架。
- 面试知识面：语言基础、框架、网络、算法、数据库、设计模式、高并发/高可用/分布式、性能优化、逻辑思维、测试、安全、产品运营思维。
- 目标是高级/全栈工程师，安全、测试、自动化部署要着重准备，性能优化与逻辑思维尤其重要。
