> 分类：版本差异/异常 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**raise from** / **__cause__** / **__context__** / **traceback**
> 原文锚点：第 69~85 段「Python 2 里重新抛出异常之后会丢失当前的栈信息，Python 3 里就不会丢失」

## 一句话总述
`raise NewError(...) from exc` 会把原异常挂到新异常的 **`__cause__`**，traceback 同时打印两条链；裸 `raise` 只填 `__context__`。

## 面试官视角
- **考察意图**：是否做过异常包装——只有真排过错的人才会关心栈信息丢没丢。
- **P5** 知道 3 里能保留栈 / **P6** 能写出 `raise ... from` / **P7** 能区分 `__cause__` 与 `__context__`。
- **红旗**：① 说"Python 3 自动保留所有栈"；② 只会 `raise X` 丢掉原因；③ 分不清 `from` 与裸 `raise`。
- **惊艳点**：**只有 `from` 才会设置 `__cause__`**；在 `except` 里直接 `raise` 新异常只设置 `__context__`，语义是"处理另一个时又冒出来的" `[经验]`。

## 主问答
**Q：包装异常时怎么保留原始错误信息？**
**A：**
1. **先给结论**：用 `raise NewError(...) from exc`，traceback 会先打印新异常，再打印"The above exception was the direct cause"及原始异常。
2. **再给机制**：`from` 把原异常写入 `__cause__`；若不使用 `from`，解释器只把当前处理的异常放进 `__context__`，输出文案也不同（"During handling of..."）`[经验]`。
3. **最后给边界**：`raise ... from None` 则**主动抑制**上下文，只显示新异常——适合对外隐藏内部细节的场景。
**加分层**：库代码应**保留**原因（方便调用方排查），网关/API 层应**抑制**原因（避免泄漏内部堆栈），这是两套相反的策略。

| Python 3.x 全系（PEP 3134） | Python 2 无异常链，重新抛出会丢原始栈 | 一律答 `raise ... from`；维护 2 代码需手工保存原异常 |

## 关键代码
```python
try:
    open("/nope")
except OSError as exc:
    raise NotImplementedError("不支持的路径") from exc   # 保留原始栈
```

## ⚠️ 原文纠错
原文表述「Python 3 里不会丢失栈信息」略笼统：栈能保留是因为**显式使用 `raise ... from`**，仅靠在 `except` 里 `raise` 只得到 `__context__`。机翻中的语法音译已还原。

## 总结与追问预判
- `from` 保因、`from None` 隐藏；库保留、边界抑制。
