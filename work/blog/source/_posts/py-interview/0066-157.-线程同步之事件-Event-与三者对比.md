> 分类：并发 | 难度：L2 | 题型：原理题 | 频率：中 | 关键词：**Event** / **线程通知** / **同步三件套**
> 原文锚点：第 45~47 段「通过互相通知的方式保持多个线程间同步；threading 的 Event」

## 一句话总述
**Event** 是线程间的**信号通知**机制：一个线程 `set()` 唤醒等待的线程，`wait()` 阻塞等待。它与**锁（互斥，1 个）**、**信号量（限流，N 个）** 共同构成 Python 线程同步三件套，定位不同。

## 面试官视角
- **考察意图**：是否理解三种同步原语的适用边界，而不是只会用锁。
- **P5** 知道 Event 用来"等一个信号再继续" / **P6** 能说清 `set/clear/wait` 语义与内部标志位 / **P7** 能对比三者并给出选型：互斥用锁、限流用信号量、阶段协同用 Event。
- **红旗**：三个原语混着用还说不清差异；或业务代码里滥用 Event。
- **惊艳点**：Event 是"**广播**"语义——`set()` 后所有 `wait()` 的线程同时被唤醒，区别于锁的独占 —— 验证：`threading.Event` 一个 `set` 唤醒 N 个等待者 `[实测]`。

## 主问答
**Q（面试官原话）：** 锁、信号量、事件你都会用吗？分别什么时候用？

**A · 标准答案骨架：**
1. **先给结论**：**锁**保护互斥资源（1 个进）、**信号量**限制并发度（N 个进）、**Event**做线程间**通知/等待**。
2. **再给机制**：Event 内部是**布尔标志**，`wait()` 阻塞直到 `set()`，`clear()` 复位；用于"主线程发令、工作线程开工"的协同。
3. **最后给边界**：Event 不保护数据，只管"时机"；和业务里 Kafka/RabbitMQ 的"消息通知"是同一思想的不同层级。

**加分层**：三者不是替代品：锁管"能不能进"，信号量管"能进几个"，Event 管"什么时候进" `[经验]`。

## 关键代码
```python
import threading
ready = threading.Event()

def worker():
    ready.wait()          # 阻塞，直到主线程 set [实测]
    print("go")

t = threading.Thread(target=worker); t.start()
ready.set()               # 广播：唤醒所有 wait 的线程
```

## ⚠️ 原文纠错
原文第 45~46 段将「事件」音译为「**事件件**」，正确术语为 **Event（事件）**；三种同步方式（锁/信号量/事件）的区分论述正确。核对范围：第 35~47 段线程同步三方式。

## 总结与追问预判
- 锁=互斥(1)、信号量=限流(N)、Event=通知；定位互补不替代。
