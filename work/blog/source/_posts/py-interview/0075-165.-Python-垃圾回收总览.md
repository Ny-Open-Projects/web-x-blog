## 一句话总述
CPython 的垃圾回收以 **引用计数（reference counting）为主**，**标记清除（mark-sweep）+ 分代回收（generational）为辅**：引用计数处理绝大多数对象，标记清除解决它搞不定的**循环引用**，分代回收提升回收效率。

## 面试官视角
- **考察意图**：是否知道 Python GC 是"三件套"而非单一机制，以及为什么需要辅助机制。
- **P5** 能说出引用计数 + 标记清除 + 分代回收 / **P6** 能讲清"为什么引用计数不够"——循环引用致内存泄露 / **P7** 能对比三者分工与代价（计数即时但慢路径、GC 暂停）。
- **红旗**：只答"Python 有 GC 自动回收"就结束；或说"引用计数能解决所有回收"。
- **惊艳点**：引用计数是**即时**回收（对象死即释放），但每次赋值/销毁都要维护计数有开销；循环引用只能靠周期性 **generational GC** 兜底 —— 验证：`gc.get_stats()` 能看到各代回收次数 `[源码]`。

## 主问答
**Q（面试官原话）：** Python 是怎么做垃圾回收的？

**A · 标准答案骨架：**
1. **先给结论**：CPython 以 **引用计数** 为主，辅以 **标记清除** 与 **分代回收**。
2. **再给机制**：对象被引用时计数 +1、不再被引用 -1，**计数为 0 立即回收**；但**循环引用**让计数永不为 0，故引入**标记清除**回收不可达环，并用**分代回收**按对象"年龄"分层扫描提效。
3. **最后给边界**：引用计数解决 99% 场景且即时；循环引用与全程扫描的代价由后两者兜底，不是替代关系。

**加分层**：引用计数+追踪式 GC 的混合方案，是 CPython 在"实时性"与"完整性"间的权衡 `[经验]`。

a = []; b = []
