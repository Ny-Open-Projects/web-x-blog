## 一句话总述
合并 K 个有序链表有两条路：**顺序两两归并**实现简单但约 `O(kN)`；**堆（多路归并）**复杂度 `O(N log k)`（惰性写法）或 `O(N log N)`（一次性读值），k 越大堆的优势越明显。

## 面试官视角
- **考察意图**：考**复杂度敏感度**——能不能对比两条路并说明各自适用边界，而不是只给一个答案。
- **P5** 只给一种 / **P6** 给出两种并说对复杂度 / **P7** 指出**分治归并**（两两配对，也是 O(N log k)）与**堆的惰性写法**二者等价，并讨论 k 极小时的选择 `[实测]`。
- **红旗**：① 把两两归并说成 O(N)；② 说不清 N 与 k 的定义；③ 认为堆一定更快（k=2 时差异可忽略，还多一次建堆）。
- **惊艳点**：第三条路——**分治归并**：像归并排序那样两两配对，每轮规模减半，共 log k 轮，总 `O(N log k)`，且**不需要堆** `[实测]`。验证：三种写法跑同一组随机有序链表对拍。

## 主问答
**Q：合并 K 个有序链表，两两归并和用堆哪个好？**
**A：**
1. **两两归并**：把前两条合并的结果再与第三条合并，如此递推；每轮都要重扫已合并部分，最坏约 `O(kN)`，但**代码复用 78、实现最简**。
2. **堆（多路归并）**：堆里始终保存 k 条链表的**当前头节点**，弹出最小后把该链表的下一个节点补入；每个节点一次 push/pop，总 `O(N log k)`，空间 `O(k)`。
3. **选型**：k 很小（2~3）时二者差别不大，选**好写好维护**的；k 大或链表很长时**堆明显更优**；不允许一次性读入全部数据时，只有**惰性堆解法**可行。
**加分层**：还有**分治归并**——两两配对、轮轮减半，`O(N log k)` 且不需要堆；面试中提一句能显著加分。

def merge_k_sequential(lists):         # 顺序两两归并：O(kN)
    if not lists: return None
    res = lists[0]
    for nxt in lists[1:]:
        res = merge_two(res, nxt)
    return res

def merge_k_heap(lists):               # 惰性堆：O(N log k)，空间 O(k)
    heap = [(i, hd.val, hd) for i, hd in enumerate(lists) if hd]
    heapq.heapify(heap)
    dummy = cur = type(heap[0][2])(0) if heap else None
    while heap:
        i, _, node = heapq.heappop(heap)
        cur.next = node; cur = cur.next
        if node.next: heapq.heappush(heap, (i, node.next.val, node.next))
    return dummy.next if dummy else None

def merge_k_divide(lists):             # 分治归并：O(N log k)，无需堆
    if not lists: return None
    while len(lists) > 1:
        lists = [merge_two(lists[i], lists[i+1]) if i+1 < len(lists) else lists[i]
                 for i in range(0, len(lists), 2)]
    return lists[0]
