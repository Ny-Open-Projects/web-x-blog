> 原文锚点：第 97~104 段「新增 yield from 语法来链接子生成器，asyncio 内置异步编程库…」

## 一句话总述
Python 3 补齐了三块短板：**异步编程**（`asyncio` + 原生协程）、**标准库缺口**（`enum`、`unittest.mock`、`ipaddress`）、**并发抽象**（`concurrent.futures`）。

## 面试官视角
- **考察意图**：有没有跟进版本演进——只会 2 的人答不出这批新增项。
- **P5** 能说出 `asyncio` / **P6** 能列出 3 个以上新增库 / **P7** 能说明各自解决什么问题。
- **红旗**：① 把 `yield from` 说成"返回生成器"；② 只知道 `asyncio` 一个；③ 说 `asyncio` 能提速 CPU 密集任务。
- **惊艳点**：**`asyncio` 只解决 IO 并发，不解决 CPU 并行**——CPU 密集要上 `concurrent.futures.ProcessPoolExecutor` `[经验]`。

## 主问答
**Q：Python 3 相比 2 新增了哪些值得说的东西？**
**A：**
1. **先给结论**：三类——**语法**（`yield from` 委托子生成器）、**异步**（`asyncio` 提供事件循环与原生协程）、**标准库**（`enum`、`unittest.mock`、`concurrent.futures`、`ipaddress`）。
2. **再给机制**：`yield from` 把子生成器的产出与 `send`/`throw` 双向透传，是协程嵌套的基础；`asyncio` 则用 `async/await` 语法统一了异步网络编程模型 `[经验]`。
3. **最后给边界**：异步与并发不是一回事——`asyncio` 靠单线程事件循环处理 IO 等待，CPU 密集场景必须用进程池，否则反而阻塞整个循环。
**加分层**：`unittest.mock` 解决的是"单测里替换外部依赖"，是工程成熟度的标志，比背库名更有说服力。

## 关键代码
```python
def inner():
    yield from range(3)        # 委托子生成器，双向透传
print(list(inner()))           # [0, 1, 2]
```
