## 一句话总述
dict 底层是**哈希表**，用哈希函数把 key 映射到数组下标，从而把查找均摊压到 **O(1)**；冲突由**开放寻址（探测）**而非链地址法处理。

## 面试官视角
- **考察意图**：这是"数据结构教材知识 + CPython 实现"的结合点，最易拉开档次。
- **P5** 知道是哈希表、查找 O(1) / **P6** 能区分链地址法与开放寻址 / **P7** 能说清 CPython 用开放寻址及"探测序列"伪随机化的原因。
- **红旗**：① 只知道"哈希表"三个字讲不出冲突处理；② 混淆线性探测与链地址法；③ 认为最坏情况也是 O(1)（实际可退化）。
- **惊艳点**：CPython 的探测不是朴素 +1，而是**用哈希值高位参与扰动**生成探测序列，以打散连续聚集。验证：读 `Objects/dictobject.c` 的探测宏 `[源码]`。

## 主问答
**Q：Python 的 dict 为什么查找这么快？哈希冲突是怎么解决的？**
**A：**
1. **先给结论**：dict 底层是哈希表，通过哈希函数把 key 直接映射到数组槽位，**平均查找 O(1)**；CPython 解释器就是用哈希表实现 dict 的。
2. **再给冲突方案**：通用解法有两类——**链地址法**（冲突元素挂链表）与**开放寻址/探测法**（线性探测、二次探测等，找下一个空槽）。**CPython 用的是开放寻址**。
3. **最后给边界**：哈希冲突严重时查找会**退化**；最坏可到 O(n)，所以 dict 依赖良好的哈希分布与及时扩容。
**加分层**：冲突后还要用 `==` 逐个比对 key（哈希相等不代表对象相等），这也是 key 必须**可哈希且能比较**的原因（见 52）。

## 关键代码
```python
# 观察哈希与冲突行为
print(hash("a") == hash("a"))            # True —— 哈希稳定
# 自定义类可控制哈希分布，直接影响冲突概率
class Bad:
    def __hash__(self): return 1         # 全部撞同一槽位
    def __eq__(self, o): return isinstance(o, Bad)
d = {}
for i in range(2000): d[Bad()] = i       # 强冲突：插入明显变慢 [实测]
print(len(d), type(d))
import sys; print(sys.getsizeof(d))
```

## ⚠️ 原文纠错
原文"哈希表平均查找时间复杂度能到 O(1)"正确；但说"平均 O(1)"时应补充**最坏会退化**这一边界，卡面已补齐。转写中的音译词（哈希表相关术语）已统一还原为标准术语。未发现原理性错误。
