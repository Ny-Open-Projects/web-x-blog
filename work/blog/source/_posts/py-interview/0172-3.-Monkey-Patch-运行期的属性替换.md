> 分类：Python 语言基础 | 难度：L3 | 题型：八股题 / 工程题 | 频率：中 | 关键词：**monkey patch** / **运行时替换** / **gevent** / **局部性原理**
> 原文锚点：第 33~47 段「这个所谓的 monkeypeass 这个猴子补丁就是运行时属性替换……比如说我们最常用的一个并发库叫 event。因为他需要修改我们这个内置的阻侧的 socket 为非左侧的 socket」

## 一句话总述

**Monkey patch = 不改源码，在运行期把模块/对象的属性换成自己的实现——威力与代价同源：改的是全局可见的对象，影响所有调用方。

## 面试官视角

- **考察意图**：不是问「会不会打补丁」，而是看候选人是否理解**它破坏局部性**——改一处，所有 import 方同时中招。
- **分档**（挂可验证判据）：
  - `P5 能干活` = 说出定义（运行时属性替换）+ 一个真实场景（gevent 打 socket / 测试替身）。
  - `P6 懂原理` = 说清「为什么能生效」（模块是单例对象，属性查找在运行期）+ 一个具体代价（第三方库行为被静默改变，难复现）。
  - `P7 有判断` = 知道**测试场景首选 `mock.patch` 上下文**（自动还原、作用域明确），生产场景只在没有扩展点可用时才动手，并能说出替代设计（依赖注入 / 适配器）。
- **红旗答案**：
  - 「monkey patch 很方便，推荐多用」——暴露没有在协作代码库里被它坑过。
  - 分不清 monkey patch 和继承/装饰器——三者改写行为的时机与范围完全不同。
  - 只会背 gevent 例子，说不出「为什么 gevent 必须用它」（标准库 socket 没有注入点）。
- **惊艳点**：**gevent 的 monkey patch 本质是「没有依赖注入点的妥协」**——标准库 `socket` 在 gevent 出现前就是全局函数式 API，gevent 无法让调用方改用协程版 socket，只能运行期整体替换。
  > 验证：`import socket; print(socket.socket)` 前后对比 `gevent.monkey.patch_socket()` 的输出变化 `[源码]`（gevent/gevent.monkey.py 的 `patch_socket` 将 `socket.socket` 指向 `gevent.socket.socket`）。

## 主问答

**Q（面试官原话）：** 什么是 monkey patch？你用过吗？它有什么问题？

**A · 标准答案骨架：**

1. **先给结论**：monkey patch 是在**运行期**替换模块或对象的属性/方法，从而改变其行为，而不修改其源代码。常见于测试替身和给没有扩展点的老库改行为。
2. **再给机制**：Python 的模块是 `sys.modules` 里的单例对象，属性查找发生在调用时——所以 `time.time = my_func` 之后，**所有**通过 `time.time()` 访问的代码（包括尚未调用的第三方库）拿到的都是替换后的实现。
3. **最后给边界**：代价是**隐式且全局**——打补丁的代码和受影响的代码可能毫无关系，出问题极难定位；测试场景应改用 `unittest.mock.patch` 上下文管理器（进上下文打、出上下文自动还原、作用域显式），生产场景能依赖注入就不 patch。

**A · 加分层：** 猴子补丁的名字来自「偷偷摸摸改东西」的意象——它违反局部性原理：**一段代码的行为不再由它自己决定**。这也是它在生产代码里口碑差、在测试代码里口碑好的原因：测试要的就是「临时假装」。

## 关键代码

```python
import time
import unittest.mock as mock

# 1) 裸 monkey patch：生效但容易忘还原 [实测 CPython 3.13.12]
orig = time.time
time.time = lambda: 1234567890.0     # 运行期替换：全局生效
print(time.time())                    # 1234567890.0
time.time = orig                      # 手动还原——忘了就污染整个进程

# 2) 推荐：mock.patch 上下文，作用域显式 + 自动还原 [实测 CPython 3.13.12]
with mock.patch("time.time", return_value=1234567890.0):
    print(time.time())                # 1234567890.0
print(time.time())                    # 真实时间戳——出上下文自动恢复

# 3) 影响面演示：sys.modules 里是同一个模块对象 [实测 CPython 3.13.12]
import sys
print(sys.modules["time"].time is time.time)   # True——patch 它俩谁都一样
```

## 总结与追问预判

- **三行总结**：monkey patch = 运行期属性替换；靠「模块单例 + 运行期查找」全局生效；威力与代价同源，测试用 `mock.patch`、生产慎用、能注入不 patch。
- **预判追问 1**：「gevent 为什么必须 monkey patch？」→ 标准库无注入点，答不出停 L3；延伸看深卡的方案取舍。
- **预判追问 2**：「线程安全吗？」→ 替换瞬间非原子可见，必须启动前完成 patch，见深卡 L5 行。

## ⚠️ 原文纠错

1. **「修改内置的阻塞 socket 为非阻塞的 socket」表述不准**：gevent 替换成的不是朴素的非阻塞 socket（那需要调用方自己处理 EAGAIN），而是**协程版 socket**——遇到阻塞时把当前协程挂起、切到事件循环跑其他协程，语义仍是「阻塞式调用」 `[源码]`（gevent/socket.py 的 socket 类继承自 `gevent._socket3.socket`，阻塞点走 `hub.switch()`）。
2. 「monkeypeass」等为音译崩坏词，本卡统一为 monkey patch。
