> 分类：编程范式/函数式 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**filter** / **谓词** / **惰性** / **列表推导替代**
> 原文锚点：第 23~29 段「filter 接收 function 和可迭代对象，对每个元素应用谓词，保留为真的元素；可用列表推导替代」

## 一句话总述
**`filter(pred, iterable)`** 用谓词 `pred` **逐元素判断**，只保留使 `pred` 为真的元素；和 `map` 一样 **Py3 返回迭代器**，且日常更推荐用**列表推导** `[x for x in it if pred(x)]` 替代。

## 面试官视角
- **考察意图**：考你能否把 `filter` 与 `map` 区分（一个变值、一个筛选），并给出"用列表推导还是 filter"的判断。
- **P5** 能写出 `filter(lambda x: x%2==0, range(10))` 取偶数 / **P6** 能区分 `map`（变换）vs `filter`（筛选），并指出 **Py3 返回迭代器**、更推荐列表推导 / **P7** 能指出 `filter` 配 `None`（`filter(None, it)` 去空）的历史用法已不推荐，复杂条件用推导更清晰 `[经验]`。
- **红旗**：① 把 filter 当 map 用（filter 不改值只筛选）；② 以为 Py3 直接返回 list；③ 在 filter 的 lambda 里写复杂逻辑（难读，应改推导）。
- **惊艳点**：`filter` 是"保留为真"——谓词返回假值（`0/None/False/空`）的元素会被丢弃。验证：`list(filter(None, [0,1,'',2]))` 得到 `[1,2]` `[实测]`。

## 主问答
**Q：filter 和 map 有什么区别？为什么常用列表推导？**
**A：**
1. **结论**：`filter` **筛选**（保留谓词为真的元素），`map` **变换**（对每个元素改值）——两者目的不同。
2. **机制**：`filter(pred, it)` 等价于 `[x for x in it if pred(x)]`；Py3 同样返回**迭代器**，要结果需 `list()`。
3. **边界**：谓词简单时 `filter` 还行，但条件一长就难读；列表推导把"遍历+判断"写一起，更 Pythonic，社区推荐。
**加分层**：`filter(None, it)` 能快速去空值，但可读性差，现代写法用推导 `[x for x in it if x]`。

## 关键代码
```python
evens = filter(lambda x: x % 2 == 0, range(10))
print(list(evens))                 # [0,2,4,6,8]
print([x for x in range(10) if x % 2 == 0])   # 等价、更推荐
print(list(filter(None, [0, 1, '', 2])))      # [1, 2] —— 去空值
```
