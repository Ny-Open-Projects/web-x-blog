> 分类：语言基础/异常 | 难度：L1 | 题型：八股题 | 频率：高 | 关键词：**异常机制** / **错误码** / **控制流**
> 原文锚点：第 1~6 段「异常就是一种错误处理机制…有些语言使用返回码来做错误处理」

## 一句话总述
异常是**打破程序正常执行流程的错误事件**；Python/Java 走异常机制，C 走返回码——两者的本质差别在于**错误能否被静默忽略**。

## 面试官视角
- **考察意图**：是"会写 try"还是"理解为什么要有异常"。
- **P5** 会用 try/except / **P6** 能说清异常与错误码的取舍 / **P7** 能指出"异常不能用于正常控制流"这条边界。
- **红旗**：① 用异常做正常的分支跳转；② 裸 `except` 吞掉一切；③ 断言"异常一定比错误码慢很多"而不给场景。
- **惊艳点**：CPython **不抛异常时 try 块几乎零成本**（3.11 起进一步采用零成本异常实现），开销集中在**抛出**路径。验证：对比加/不加 try 的循环耗时 `[实测]`

## 主问答
**Q：Python 为什么用异常而不是返回码来做错误处理？**
**A：**
1. **先给结论**：异常把**错误检测**和**错误处理**在代码位置上强行分离，且**不允许被静默忽略**。
2. **再给机制**：出错时解释器**抛出**异常对象，沿调用栈向上传播直到被 `except` 捕获，中间层**不需要层层判断返回值**；返回码风格则要求每一层都写 `if err != nil`。
3. **最后给边界**：异常只服务于**异常**情况；拿它做正常分支跳转会让控制流不可读，而且构造 traceback 的成本不低。
**加分层**：取舍点在"强制性"——返回码可以被调用方忘掉，异常不处理就一直往上冒，这个强制性对可靠性是加分项。

## 关键代码
```python
def div(a, b):
    return a / b                       # b=0 抛 ZeroDivisionError，无需返回码
try:
    div(1, 0)
except ZeroDivisionError as e:
    print("caught:", e)

def div_code(a, b):                    # 错误码风格：每一层都要判断
    return (None, "div by zero") if b == 0 else (a / b, None)
```
