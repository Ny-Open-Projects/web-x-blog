> 原文锚点：第9章 9-3「前后端分离：传统 MVC 由后端渲染模板(HTML)返回浏览器，前后端同仓同部署易冲突；分离后后端只提供数据接口、前端取数自行渲染展示；优势=前后端解耦接口复用(Web/安卓/iOS 同一接口)、各司其职、方便调试测试(mock 数据)、方便独立部署；缺点=单页应用 SPA 对 SEO 不友好(搜索引擎抓静态页、动态加载抓不到)」

## 一句话总述
**前后端分离 = 后端只提供数据接口（JSON），不再渲染模板；前端取数后自行渲染展示**。相比传统 MVC（后端渲染 HTML 返回浏览器），它让前后端解耦、接口可跨端复用，但单页应用对 SEO 不友好。

## 主问答
**Q（面试官原话）：** 什么是前后端分离？它有什么优缺点？

**A · 标准答案骨架：**
1. **传统 MVC 痛点**：后端既要写业务逻辑又要渲染模板（HTML）返回浏览器，前端后端常改同一份模板文件 → 冲突多；前后端同仓同部署，仓库臃肿；大项目尤其混乱。
2. **分离的定义**：后端职责收窄为"**只提供数据接口**（通常返回 JSON）"，**不再做模板渲染**；前端获取数据后自行渲染并展示给用户。双方先约定接口契约，即可并行开发。
3. **四大优势**：① **前后端解耦、接口易复用**——同一套接口可同时服务 Web、安卓、iOS，大幅减少接口开发量（移动端时代尤其明显）；② **各司其职**——后端专注业务接口、前端专注展示，不再抢改模板；③ **便于调试测试**——后端未就绪时前端可用 mock 数据先开发，且返回 JSON 比校验 HTML 更易写单测验证格式；④ **便于运维部署**——前后端项目分开部署，减少冲突、加快发布。
4. **主要缺点**：**单页应用（SPA）对 SEO 不友好**——搜索引擎擅长抓取静态页面，动态加载的内容往往抓不到 `[经验]`。可用 SSR/预渲染弥补。

**加分层**：分离后鉴权通常走 token（JWT 等）而非把 session 绑死在后端模板里；接口契约（OpenAPI/Swagger）是协作关键，不止是"分仓"而已。

# 前后端分离：后端只返回 JSON 数据，渲染交给前端 [实测, python]

def api_user(user):
    return json.dumps({"id": user.id, "name": user.name, "age": user.age})
