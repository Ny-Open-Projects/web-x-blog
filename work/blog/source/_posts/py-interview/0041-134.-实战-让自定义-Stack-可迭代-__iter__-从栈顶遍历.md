> 分类：编程范式/设计模式 | 难度：L3 | 题型：代码题 | 频率：中 | 关键词：**__iter__** / **reversed** / **栈顶优先** / **yield**
> 原文锚点：第 12~22 段「自定义 stack 默认 not iterable，定义 __iter__ 反转 deque 实现从栈顶往下迭代」

## 一句话总述
源里的经典例子：自定义 `Stack`（内部用 deque 存）**默认不可迭代**，给它加 `__iter__` 并**反转 deque**（因 deque 从左往右、push 在右端），即可实现"后入先出、从栈顶往下遍历"。

## 面试官视角
- **考察意图**：考你能否把"可迭代对象"从概念落到**能跑的代码**，并理解为什么必须反转、为什么 Stack 是 iterable 而非 iterator。
- **P5** 能写出 `__iter__` 返回遍历序列 / **P6** 能讲清**反转原因**（deque 右端是栈顶，从左遍历会反）/ **P7** 能指出用 `yield` 实现 generator 比手写列表更省内存，且 generator 本身就是迭代器 `[经验]`。
- **红旗**：① 不反转直接遍历（顺序变"从底到顶"，违背栈语义）；② 在 `__iter__` 里返回 `self` 却没实现 `__next__`（那它不是迭代器，`__iter__` 必须返回迭代器）；③ 把 Stack 说成迭代器。
- **惊艳点**：`__iter__` 里写 `for x in reversed(self._d): yield x`——既满足栈顶优先，又让 Stack 成为**可迭代对象**（返回 generator）。验证：遍历 `push(1),push(2)` 输出 `2,1` `[实测]`。

## 主问答
**Q：让你的 Stack 支持 for 循环，从栈顶往下遍历？**
**A：**
1. **结论**：给 `Stack` 加 `__iter__`，把内部 deque **反转**后逐个产出，从而"后入先出"地迭代。
2. **机制**：deque 从左往右存、`push` 落到右端（栈顶），直接遍历会"从底到顶"；用 `reversed` 反转才能得到"从栈顶往下"。
3. **边界**：`__iter__` 返回的必须是**迭代器**（这里用 generator），Stack 本身仍是**可迭代对象**而非迭代器——原文特意强调这点。
**加分层**：用 `yield` 产出是惰性生成器，比先 `list(reversed(...))` 再返回更省内存。

## 关键代码
```python
from collections import deque
class Stack:
    def __init__(self): self._d = deque()
    def push(self, x): self._d.append(x)
    def __iter__(self):                 # 可迭代对象：返回迭代器
        for x in reversed(self._d):     # 反转 -> 栈顶优先
            yield x
s = Stack(); s.push(1); s.push(2)
print(list(s))                          # [2, 1] —— 从栈顶往下
```

## ⚠️ 原文纠错
原文示例逻辑正确（Stack 默认不可迭代，需定义 `__iter__`；"更 deckdeck"即 **deque**；"从上往下迭代、后进去先出来"即栈顶优先）。机翻"英特尔"=**`__iter__`**，"noterero"指 **TypeError/对象不可迭代** 报错，"最右面先拿出来"对应反转 deque。原文"这个 stack 并不是一个迭代器，要区分 itable 和 itwriter"——准确，卡面据此强调 Stack 是可迭代对象而非迭代器。无事实错误，仅术语音译需还原。
