> 原文锚点：第 70~86 段「有哪些措施来优化程序的性能…从算法、数据库、缓存、异步几个角度」

## 一句话总述
按**算法与数据结构 → 数据库（索引/慢查询/批量/连接池）→ 缓存（Redis/Memcached）→ 异步与并发**四层推进，每上一层都要**先证明瓶颈确实在那里**。

## 面试官视角
- **考察意图**：是背优化清单，还是能说清每条手段的**代价与不适用边界**。
- **P5** 会说"加索引加缓存" / **P6** 能分层说清每层具体手段 / **P7** 能主动交代代价（缓存一致性、索引写放大、异步传染性）。
- **红旗**：① 张口就是"加缓存"（追问一致性必穿帮）；② 无前提说"加索引一定快"；③ "全改异步就快了"。
- **惊艳点**：**索引不是免费的**——加速读、拖慢写、占空间；批量操作省的是**往返次数（RTT）**，一个 200ms 的 RTT 通常比 SQL 本身更贵。验证：对比逐条插入与 `executemany` `[实测]`

## 主问答
**Q：Python 这么慢，你们后端怎么提升性能？**
**A：**
1. **先给结论**：四层——**算法/数据结构 → 数据库 → 缓存 → 异步并发**，从收益大、代价小的开始做。
2. **再给机制**：数据库层靠**加索引消除慢查询**、**批量操作减少往返**、**连接池**复用连接；缓存层用 Redis/Memcached 扛高并发读；并发层用协程/多线程把一次请求内的多次 IO 并行掉，Celery 把可延后的任务丢到独立进程。
3. **最后给边界**：缓存引入**一致性**问题（失效策略、穿透/击穿/雪崩）；索引拖慢写入；异步会把调用链"传染"成全异步，误用同步库反而阻塞事件循环。
**加分层**：**语言执行效率通常不是瓶颈**——先跑 profiler 和慢查询日志证明热点在 Python 代码里，再考虑 C 扩展或换实现；顺序反了就是纯浪费。

## 关键代码
```python
import sqlite3, time
rows = [(i,) for i in range(5000)]
con = sqlite3.connect(":memory:"); con.execute("create table t(a int)")
t0 = time.perf_counter(); con.executemany("insert into t values(?)", rows)
print("批量插入:", round(time.perf_counter() - t0, 4))
con2 = sqlite3.connect(":memory:"); con2.execute("create table t(a int)")
t0 = time.perf_counter()
for r in rows: con2.execute("insert into t values(?)", r)
print("逐条插入:", round(time.perf_counter() - t0, 4))
# 索引加速读、拖慢写：explain query plan 看是否走索引
print(con.execute("explain query plan select * from t where a=1").fetchall())
```
