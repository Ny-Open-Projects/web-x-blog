> 原文锚点：第 63~64 段「如果你传递了一个可变对象作为参数，你在里面修改它的话，对外面是可见的」

## 一句话总述
把入参当**只读**：确实要改就先拷贝（`list(x)` / `dict(x)` / `copy.deepcopy`），或者干脆**返回新对象**而不是原地改——这是消除共享传参副作用的两种标准姿势。

## 面试官视角
- **考察意图**：有没有被"函数改脏了上游数据"这种真实 bug 教育过，以及能不能权衡拷贝成本。
- **P5** 知道用 `list(x)` 拷贝 / **P6** 能说清浅拷贝挡不住嵌套 / **P7** 能讲清"热路径故意原地改 + 命名上写清楚"的取舍。
- **红旗**：① 说"deepcopy 就完事了"——它慢且拷不动文件句柄/锁/连接；② 所有参数无脑拷贝；③ 不知道 `sort()` 与 `sorted()` 的语义差别。
- **惊艳点**：`dict(src)` 浅拷贝后改**嵌套 list** 仍会污染原对象，只有 `deepcopy` 能挡住；而 `deepcopy` 在一个 1 万元素嵌套结构上的耗时量级远高于浅拷贝。验证：`timeit` 对比 `[实测]`

## 主问答
**Q：你写的工具函数会不会不小心改掉调用方传进来的 list/dict？怎么避免？**
**A：**
1. **先给结论**：**默认只读**；需要修改就先拷贝，或者**返回新对象**（推荐），让副作用显式化。
2. **再给机制**：浅拷贝 `list(x)` / `dict(x)` / `x.copy()` 只复制**容器本身一层**，嵌套结构里的子对象仍与原对象共享；`copy.deepcopy` 递归复制，能彻底隔离，但**慢得多**且遇到文件句柄、锁、数据库连接会失败。
3. **最后给边界**：拷贝是有成本的，热路径上为了省内存**故意原地改**完全合理，但必须在**函数名和 docstring 里写明**（标准库的 `list.sort()` 原地、`sorted()` 返回新列表就是这个约定）。
**加分层**：对外 API 优先设计成"不可变风格"（`sorted()` / `str.replace()` 这类返回新对象的写法），调用方零惊吓，代价是多一次分配。

## 关键代码
```python
import copy, timeit
def bad(tags, tag):            # 坏：原地改，污染调用方
    tags.append(tag); return tags
def good(tags, tag):           # 好：返回新对象
    return [*tags, tag]
src = ["py"]; bad(src, "go"); print(src)          # ['py', 'go'] 被改脏

src2 = {"a": [1]}
shallow = dict(src2); shallow["a"].append(2)
print(src2)                                        # {'a': [1, 2]} 浅拷贝挡不住嵌套
deep = copy.deepcopy(src2); deep["a"].append(3)
print(src2)                                        # {'a': [1, 2]} 深拷贝才隔离
print(timeit.timeit(lambda: dict(src2), number=10000) > 0)   # True，拷贝有成本
```

- 只读优先；要改就拷贝或返回新对象；浅拷贝挡不住嵌套，深拷贝有成本。
