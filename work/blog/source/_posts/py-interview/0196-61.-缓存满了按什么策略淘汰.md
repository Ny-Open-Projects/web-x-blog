> 分类：算法与数据结构/缓存 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**LRU** / **LFU** / **FIFO** / **随机淘汰**
> 原文锚点：第 102~117 段「当缓存不够的时候，我们就需要剔除…最近最少使用的对象给它剔除掉」

## 一句话总述
内存有限时必须**挑一个 key 淘汰**：常见策略是 **LRU**（最久未用）、**LFU**（使用次数最少）、**FIFO**（先进先出）与**随机**；LRU 从**时间维度**衡量，LFU 从**频次维度**衡量。

## 面试官视角
- **考察意图**：是否理解缓存是"容量受限下的置换决策"，而不是随便删。
- **P5** 知道 LRU 含义 / **P6** 能区分 LRU 与 LFU 的维度差异 / **P7** 能指出各自失效场景并给出改进（如 LRU-K、TinyLFU）。
- **红旗**：① 把 LRU 和 LFU 说成同一件事；② 讲不出 LFU 的"历史热点赖着不走"问题；③ 以为存在 universally 最优策略。
- **惊艳点**：LRU 怕**偶发全表扫描**（冷数据冲掉热数据），LFU 怕**老热点过期后仍在榜**。验证：构造扫描型访问序列观察命中率 `[实测]`。

## 主问答
**Q：常见的缓存淘汰策略有哪些？区别是什么？**
**A：**
1. **先给结论**：**LRU** 淘汰**最久没被访问**的；**LFU** 淘汰**访问次数最少**的；**FIFO** 淘汰最早进入的；还有随机淘汰。
2. **再给机制**：LRU 需要维护**访问顺序**（最近访问的挪到一端，另一端即淘汰位）；LFU 需要维护**访问计数**。
3. **最后给权衡**：LRU 易被**一次性批量扫描**污染；LFU 会让**历史热点长期滞留**且需衰减机制；二者在真实系统里常组合（如 Redis 支持配置多种策略）。
**加分层**：选型看访问分布——有明显时间局部性用 LRU；有明显长尾热点且分布稳定用 LFU；两者都没有时用随机，实现简单且效果不差。

## 关键代码
```python
# 用访问序列观察命中/淘汰：手写一个极简 FIFO vs LRU 计数对比
def simulate(policy, cap, seq):
    cache, order, freq, hit = set(), [], {}, 0
    for k in seq:
        if k in cache:
            hit += 1
            freq[k] = freq.get(k, 0) + 1
            if policy == "lru": order.remove(k); order.append(k)
        else:
            if len(cache) >= cap:
                victim = order.pop(0) if policy == "lru" else next(iter(cache))
                cache.discard(victim)
            cache.add(k); order.append(k)
    return hit
seq = ["a","b","a","c","d","a","e"]
print(simulate("lru", 3, seq), simulate("fifo", 3, seq))   # 对比命中数 [实测]
```
