## 一句话总述
后端应用多部署在 **Linux 服务器**（容器技术也基于 Linux），面试常考基础命令；查命令用法首选 **`man`**，嫌手册晦涩可用带示例的 **`tldr`**（man 的现代替代品），以及命令自带的 **`--help`**。

## 面试官视角
- **考察意图**：看你是否真在服务器/容器里排过障，而非只会背命令。
- **P5** 能说出"应用跑在 Linux、要会查命令" / **P6** 能对比 `man`（全、晦涩）vs `tldr`（示例友好）vs `--help`（简版）/ **P7** 能指出 `tldr` 需额外安装、且**不同发行版命令略有差异**，以及在容器里缺 man 时的替代 `[经验]`。
- **红旗**：① 以为只在本地开发就无需 Linux；② 把 `tldr` 说成系统自带（需 `pip install tldr`）；③ 不会 `tar`/`ssh`/`scp` 等高频命令。
- **惊艳点**：`tldr tar` 直接给"如何创建/解压归档"的示例，比 `man tar` 易读。验证：`tldr tar | head` 输出示例命令 `[实测]`。

## 主问答
**Q：为什么后端要学 Linux？命令忘了怎么查？**
**A：**
1. **结论**：生产应用大多跑在 **Linux 服务器 / 容器**上，登录调试离不开命令；忘了用法用 `man`、`--help` 或 `tldr`。
2. **机制**：`man cmd` 看完整手册（权威但长）；`cmd --help` 看精简参数；`tldr cmd` 给**实例**（如 `tldr tar` 直接示范打包/解压），更适合速查。
3. **边界**：`tldr` **不是系统自带**，需 `pip install tldr`；容器镜像常精简掉 `man`，此时 `--help`/`tldr` 更实用。
**加分层**：熟记高频命令（`tar/ssh/scp/ps/kill/ss/netstat`）比临时查更稳；推荐《鸟哥的 Linux 私房菜》系统学。

| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 各发行版 | 命令大同小异 | 以 man 为准 |
| tldr | 需 pip 安装 | 容器里优先 --help |
| 容器 | 常缺 man 页 | 精简镜像注意 |

## 关键代码
```bash
man tar              # 完整手册（权威但长）
tar --help          # 精简参数
tldr tar            # 实例：直接给打包/解压示例
```

```python
import shutil
print(shutil.which("tar"))        # 等价于 which tar：查命令是否在 PATH
```
