> 分类：编程范式/函数式 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**map** / **高阶函数** / **迭代器** / **列表推导替代**
> 原文锚点：第 8~16 段「map 接收 function + 可迭代对象，对每个元素应用函数；Python3 返回可迭代对象，推荐用列表推导替代」

## 一句话总述
**`map(fn, iterable)`** 把 `fn` **依次作用**到可迭代对象的每个元素上；**Python 3 里它返回迭代器**（惰性），需 `list()` 落定——但日常更推荐用**列表推导**替代，可读性更好。

## 面试官视角
- **考察意图**：考你知不知道 `map` 在 Py2/Py3 的返回值差异，以及能否权衡"map vs 列表推导"。
- **P5** 能写出 `map(lambda x: x*2, range(10))` / **P6** 能指出 **Py3 返回迭代器**（Py2 返回 list），并说明更推荐列表推导 `[x*2 for x in range(10)]` / **P7** 能指出 `map` 配合**多参数/None 技巧**的少数优势，以及"为 map 而 map"反而难读 `[经验]`。
- **红旗**：① 以为 `map` 在 Py3 直接返回 list（须 `list()`）；② 在 `map` 里用有副作用的 lambda（违背函数式）；③ 不知道列表推导通常更 Pythonic。
- **惊艳点**：`map` 的"惰性"意味着**不立即计算**——对超长序列可省内存；但可读性上 `[f(x) for x in it]` 往往更直观。验证：`type(map(...))` 是 `map`（迭代器）而非 list `[实测]`。

## 主问答
**Q：map 怎么用？为什么现在更推荐列表推导？**
**A：**
1. **结论**：`map(fn, it)` 对每个元素套 `fn`；Py3 返回**迭代器**，要结果需 `list()`。
2. **机制**：它和列表推导 `[fn(x) for x in it]` **语义等价**；但推导式把"遍历+变换"写在一行，意图更直白，社区也更推荐。
3. **边界**：`map` 仍有用武之地（如 `map(int, '1 2 3'.split())` 多参数），但单纯"映射"别硬用 map。
**加分层**：需要惰性时 `map` 比一次性 list 推导更省内存——超大序列用 `map` 或生成器表达式。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| Python 2 | map 返回 list | 旧代码注意 |
| Python 3 | map 返回迭代器 | 须 list() 落定 |
| 可读性 | 列表推导优先 | 非惰性小数据用推导 |

## 关键代码
```python
r = map(lambda x: x * 2, range(10))     # Py3：惰性迭代器
print(type(r))                          # <class 'map'>
print(list(r))                          # [0,2,4,...,18]
print([x*2 for x in range(10)])         # 等价、更推荐
```
