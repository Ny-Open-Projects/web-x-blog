> 分类：编程范式/设计模式 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**迭代器模式** / **可迭代对象** / **__iter__** / **__next__**
> 原文锚点：第 8~11 段「iterator 内置支持，for 遍历就是迭代器；迭代器实现 next 和 iter，可迭代对象只实现 iter」

## 一句话总述
**迭代器模式**提供一种**顺序访问**聚合对象元素、又不暴露内部结构的方式；在 Python 里**可迭代对象**实现 `__iter__`（返回迭代器），**迭代器**额外实现 `__next__`（产生下一个元素），二者不是一个东西。

## 面试官视角
- **考察意图**：专考你能否分清 **iterable（可迭代）** 与 **iterator（迭代器）**——这是 Python 面试高频陷阱。
- **P5** 能说出"for 循环底层就是迭代器" / **P6** 能准确区分：可迭代对象有 `__iter__`、迭代器还有 `__next__`，且迭代器本身也是可迭代的（`__iter__` 返回自身）/ **P7** 能说明**迭代器是一次性的**（耗尽即空）、`iter(obj)` 调 `__iter__`、`next()` 调 `__next__`，并指出 `for` 的等价展开 `[实测]`。
- **红旗**：① 说"实现了 `__iter__` 就是迭代器"（错，还要 `__next__`）；② 把迭代器和可迭代对象混为一谈；③ 不知道迭代器耗尽后再次遍历为空。
- **惊艳点**：`for x in obj` 等价于 `it = iter(obj); while True: x = next(it)`。验证：手写展开与 for 输出完全一致 `[实测]`。

## 主问答
**Q：说说迭代器模式，Python 里 iterable 和 iterator 到底差在哪？**
**A：**
1. **结论**：迭代器模式 = 不暴露内部结构就能逐个取值；Python 中**可迭代对象**只实现 `__iter__`，**迭代器**还要实现 `__next__`。
2. **机制**：`for` 会先 `iter(obj)` 拿到迭代器，再反复 `next()` 直到 `StopIteration`；迭代器自己的 `__iter__` 返回 `self`，所以它也是可迭代的。
3. **边界**：迭代器**消费后一次性作废**——list 可重复遍历（每次 `iter` 新建迭代器），生成器/手写迭代器遍历一次就空了。
**加分层**：`collections.abc` 的 `Iterable`/`Iterator` 可用 `isinstance` 判别，比记方法更稳。

## 关键代码
```python
class MyIter:                       # 迭代器：同时实现两方法
    def __init__(self, n): self.n = n; self.i = 0
    def __iter__(self): return self          # 返回自身
    def __next__(self):
        if self.i >= self.n: raise StopIteration
        self.i += 1; return self.i
```

## ⚠️ 原文纠错
原文"迭代器需要实现 next 和 iter 两个魔方方法，可迭代对象只要实现 iter"——准确，并予以保留（机翻"魔方方法"=**魔术方法**，"eter"=**`__next__`**，"inter"=**`__iter__`**，"interwriter/itwriter"=**迭代器**，"itable"=**可迭代对象**，"interval"=**iterable**）。原文"itwriter 在 python 里面定义不一样"——指 iterable 与 iterator 定义不同，正确。原文未展开"迭代器一次性耗尽"与 for 等价展开，已在机制与惊艳点补充 `[实测]`。无事实错误，仅术语音译需还原。

## 总结与追问预判
- 可迭代对象只 `__iter__`；迭代器再加 `__next__`；迭代器**一次性**。
