## 一句话总述
**内存抖动（thrashing）**指页面频繁换入换出，进程不断产生**缺页中断**，性能急剧下降；根因常是页面置换策略不当或物理内存不足。常见策略：**LRU / LFU / FIFO**。

## 面试官视角
- **考察意图**：是否理解"为什么加了虚拟内存反而可能更慢"，以及置换策略的取舍。
- **P5** 能说出抖动=频繁缺页、常见 LRU/FIFO / **P6** 能解释"刚换出又要换回"的恶性循环、LRU 思想 / **P7** 能给出解法（杀无关进程/加物理内存）并联系 Redis 的 LRU 淘汰。
- **红旗**：把抖动说成"内存不够"就结束，不提置换策略与缺页中断。
- **惊艳点**：Redis 内存超限时默认用 **LRU** 剔除冷 key——业务侧"淘汰策略"本质就是 OS 页面置换的同源思想 —— 验证：`maxmemory-policy allkeys-lru` 配置项 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是内存抖动？页面置换有哪些策略？

**A · 标准答案骨架：**
1. **先给结论**：**内存抖动**=页面被频繁换出后又立即需要、反复触发**缺页中断**，CPU 大量时间花在等待换页而非干活。
2. **再给机制**：当物理内存吃紧、置换策略（**LRU/LFU/FIFO**）选错 victim，会出现"刚换出立刻又要换回"的死循环，性能雪崩。
3. **最后给边界**：解法——**减少并发进程**（杀无关进程）或**增加物理内存**；业务侧缓存（如 Redis）要配好淘汰策略，避免冷数据挤占。

**加分层**：FIFO 可能有 Belady 异常（分配帧增多反而缺页更多），LRU 更接近局部性但需维护访问序——无完美策略 `[经验]`。

## 关键代码
```python
from collections import OrderedDict
class LRU:                      # 简易 LRU：访问即移到末尾，超容淘汰头部 [实测]
    def __init__(self, cap):
        self.cap = cap; self.d = OrderedDict()
    def get(self, k):
        if k not in self.d: return -1
        self.d.move_to_end(k); return self.d[k]
    def put(self, k, v):
        if k in self.d: self.d.move_to_end(k)
        self.d[k] = v
        if len(self.d) > self.cap: self.d.popitem(last=False)
```
