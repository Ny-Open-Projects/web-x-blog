## 一句话总述
**缓存雪崩 = 大量缓存同时失效或缓存集群不可用，瞬间海量请求打到 DB 把它打挂**。解法：多级缓存、随机 TTL 错峰失效、提升可用性与监控。

## 面试官视角

- **P5** 能定义雪崩（大量 key 同时失效/缓存不可用→打 DB）并说出"随机 TTL""多级缓存" / **P6** 能解释"随机 TTL 如何避免集中失效"与"多级缓存如何分摊压力" / **P7** 能补充"提升系统可用性、完善监控报警提前发现问题"的架构视角。

- **惊艳点**：能点出"缓存集群部分宕机→请求倾斜到剩余节点→连锁打挂"的级联风险，以及熔断/限流兜底 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是缓存雪崩？和击穿有什么区别？怎么解决？

**A · 标准答案骨架：**
1. **定义**：两种场景——① 大量缓存 key **同时失效**（如设了相同过期时间），请求集中打 DB；② 缓存集群中部分节点宕机，请求倾斜到剩余节点、把它也打挂。两者都让 DB 瞬间承压。
2. **解法一（随机 TTL）**：给缓存过期时间加**随机值**，避免大量 key 同一时刻失效。
3. **解法二（多级缓存）**：一级扛不住用多级（如本地缓存 + 分布式缓存），不同级别设不同超时，分摊压力。
4. **解法三（架构兜底）**：提升系统可用性、完善监控报警，提早发现问题。

**加分层**：雪崩与击穿区别——击穿是**单热点**过期，雪崩是**大批**同时失效或集群不可用；雪崩还需熔断/限流防止 DB 被连锁打挂。

## 关键代码

```python
# 随机 TTL 避免雪崩（redis-py）[实测, redis-py]
import redis, random
r = redis.Redis()
def set_cache(key, val, base=300):
    ttl = base + random.randint(0, 120)     # 基础 300s + 随机 0~120s
    r.set(key, val, ex=ttl)                 # 错峰失效，避免大量 key 同时过期
```
