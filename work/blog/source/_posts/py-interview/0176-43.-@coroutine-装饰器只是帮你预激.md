> 分类：并发/协程 | 难度：L2 | 题型：八股题 | 频率：低 | 关键词：**预激** / **装饰器** / **语法糖**
> 原文锚点：第 35~38 段「coroutine 装饰器…直接接收一个协程函数，调用 next 方法，返回一个已经调用过 next 的生成器」

## 一句话总述
`@coroutine` 装饰器唯一的作用就是**自动预激**——包装后调用协程函数直接返回"已经跑到第一个 yield"的生成器，省掉每次手写 `next(c)`。

## 面试官视角
- **考察意图**：会不会把语法糖误当成机制。
- **P5** 知道协程要预激 / **P6** 能三行写出这个装饰器 / **P7** 知道它已被 `async/await` 淘汰、只用于读老代码。
- **红旗**：① 说它能提升性能；② 说它是原生协程；③ 在新项目里推荐复刻它。
- **惊艳点**：实现只有三步——调原函数、调一次 `next()`、返回生成器。验证：下方代码可直接跑 `[实测]`

## 主问答
**Q：老代码里那个 @coroutine 装饰器是干什么的？**
**A：**
1. **先给结论**：它是**预激糖**，不引入任何新机制。
2. **再给机制**：`wrapper` 里先 `gen = fn(...)`，再 `next(gen)` 推进到第一个 yield，最后返回 gen——这样调用方拿到手就能直接 `send`。
3. **最后给边界**：它只对**基于生成器的协程**有意义；3.5 之后的原生协程由事件循环调度，**不需要也不支持**这种预激。
**加分层**：tornado 等老框架大量使用它，读代码时会碰到——**知道它做了什么**就够了，别在新代码里复刻。

## 关键代码
```python
def coroutine(fn):
    def wrapper(*args, **kwargs):
        gen = fn(*args, **kwargs)
        next(gen)                 # 预激：推进到第一个 yield
        return gen
    return wrapper

@coroutine
def echo():
    got = yield "ready"
    yield got
e = echo()
print(e.send("payload"))          # payload —— 无需手动预激
```
