> 原文锚点：第 75~81 段「假如我们需要 c 来显式传入，我们可以在这里加星号…防止把顺序搞混」

## 一句话总述
在参数列表里放一个**裸 `*`，其后的参数必须按名字传**，不能靠位置——用来消灭"一堆布尔/同类型参数靠顺序传"的经典事故。

## 面试官视角
- **考察意图**：是否写过参数较多的公共 API，以及有没有做过防误用的设计。
- **P5** 知道 `*` 后的参数要写名字 / **P6** 能举出防误用场景 / **P7** 能区分它与 `**kwargs`、`/` 位置参数的边界。
- **红旗**：① 把 `*` 当成"可变参数"；② 不知道它与 `*args` 可以同时出现；③ 说它可以省略名字传。
- **惊艳点**：裸 `*` **不接收任何实参**，它只是分隔符；而 `*args` 既分隔又收集——两者语义不同但常一起写 `[经验]`。

## 主问答
**Q：怎么强制调用方把某个参数用关键字传进来？**
**A：**
1. **先给结论**：在参数列表中间放一个裸 `*`，它后面的参数就变成**限定关键字参数**，必须写名字。
2. **再给机制**：Python 遇到 `*` 后停止按位置绑定，剩余实参只能按名字匹配，传错顺序会直接 `TypeError` 而不是静默算错 `[经验]`。
3. **最后给边界**：它只约束 `*` 之后的参数，之前的仍可按位置传；若同时需要收集位置参数，写成 `def f(*args, c)`——`args` 承担收集，`c` 仍只能按名传。
**加分层**：对称地，Python 3.8 起可用 `/` 定义**仅限位置参数**，两者配合能精确表达一个参数的调用方式。

## 关键代码
```python
def add(a, b, *, c):        # c 必须按名传
    return a + b + c

add(1, 2, c=3)      # 6
add(1, 2, 3)        # TypeError: takes 2 positional arguments but 3 were given
```
