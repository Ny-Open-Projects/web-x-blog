> 原文锚点：第 31~46 段「闭包是绑定了外部作用域变量的函数；即使外部函数结束，被引用的外部变量仍不被销毁；每次调用外层都重建闭包」

## 一句话总述
**闭包**是一个**函数**，它**捕获并记住**了定义时所在**外部作用域的变量**（即**自由变量**）——即使外层函数已返回，只要内部函数还持有引用，那些变量就**不会**被销毁。

## 面试官视角
- **考察意图**：闭包是 Python 高频考点，考你能否准确说出"自由变量""变量为何不销毁"，而不仅是"函数里套函数"。
- **P5** 能说出"函数里定义函数、内层用了外层变量" / **P6** 能讲清**自由变量**（不在本函数定义、来自外层作用域的变量）与**变量延长生命周期**（外层返回后仍存活）/ **P7** 能指出**每次调用外层都新建一份闭包环境**（互不干扰），以及**延迟绑定陷阱**（`lambda i: i*x` 在循环里共享） `[经验]`。
- **红旗**：① 以为"函数嵌套"就是闭包（必须**引用外部变量**才算）；② 不知道变量为何不释放（因为被内层引用，GC 不回收）；③ 踩过 `for` 循环里 `lambda` 捕获循环的延迟绑定坑。
- **惊艳点**：闭包是装饰器的实现根基——装饰器就是"返回闭包的外层函数"。验证：`__closure__` 单元保存的自由变量可经由 `cell_contents` 查看 `[实测]`。

## 主问答
**Q：什么是闭包？为什么外层函数结束后变量还在？**
**A：**
1. **结论**：闭包 = **引用了外部自由变量的内层函数**；关键是这些外部变量被"绑"进了闭包环境。
2. **机制**：Python 的变量回收看**引用**——只要内层函数还持有该变量，GC 就不会回收它，所以外层返回后变量依然可读写。
3. **边界**：**每次**调用外层函数都会**新建独立**的闭包环境，多次调用之间变量互不影响；且捕获的是变量**本身**（可变对象共享、循环变量有延迟绑定坑）。
**加分层**：装饰器的 `@wraps` 包裹、工厂函数返回带状态的函数，底层都是闭包。

## 关键代码
```python
def outer():
    store = []                 # 自由变量（被闭包捕获）
    def inner(x):
        store.append(x); return store
    return inner               # 返回闭包
f = outer()
print(f(1), f(2))              # ([1], [2]) —— store 随 f 存活
```
