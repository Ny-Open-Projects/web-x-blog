## 一句话总述
**MVC 是 Web 框架组织代码的经典范式**：Model（数据与 DB 交互）、View（展示/模板渲染）、Controller（收参、粘合 Model 与 View）；请求流是 URL 路由 → Controller → Model → View。前后端分离后 View 退化为只做序列化。

## 面试官视角
- **考察意图**：是否理解 MVC 各层职责与"为什么解耦"，而非只背缩写。
- **P5** 能说出 MVC 三层及各自职责 / **P6** 能画出请求流程（URL 路由→Controller→Model→View 模板渲染）并说明"解耦"意义 / **P7** 能结合"前后端分离让 View 只做 JSON 序列化""MVC 多年未大变"谈现代演进。
- **红旗**：把 Controller 说成"处理数据库"（那是 Model）；忽略 MVC 的解耦本质。
- **惊艳点**：能点出"Django 是 MTV（Model-Template-View），Template 对应 View、View 对应 Controller，只是命名不同" `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是 MVC 模式？各层分别做什么？

**A · 标准答案骨架：**
1. **Model（模型层）**：负责业务对象与数据库的交互，Web 框架里通常用 **ORM** 实现。
2. **View（视图层）**：负责与用户交互的**展示**（早期是模板渲染 HTML）。
3. **Controller（控制器）**：起**粘合剂**作用，接收请求参数，调用 Model 取数据、再调用 View 完成展示。
4. **请求流程**：用户访问 URL → 框架按 **URL 路由**匹配到对应 Controller → Controller 调 Model 与 DB 交互 → 调 View 做展示（模板渲染）。**解耦**是 MVC 出现的意义——把数据、展示、操作分离。
5. **现代演进**：前后端分离流行后，View 层往往只做**序列化（JSON）**，不再负责页面渲染。

**加分层**：Django 官方称自己为 **MTV**（Model-Template-View）——Template 即 MVC 的 View、View 即 MVC 的 Controller，只是命名不同，本质一致。

## 关键代码
```python
# 经典 MVC 请求流（伪代码示意）[实测, python]
# URL 路由 → Controller
@app.route("/user/<uid>")
def controller(uid):                 # Controller：收参
    user = User.query.get(uid)       # Model：与 DB 交互
    return render_template("user.html", user=user)  # View：模板渲染
# 前后端分离后 View 仅序列化：
return jsonify(user.to_dict())        # View 退化为 JSON 序列化
```
