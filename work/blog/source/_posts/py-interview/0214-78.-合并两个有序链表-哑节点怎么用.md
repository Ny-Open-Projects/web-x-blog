> 分类：算法与数据结构/链表 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**哑节点** / **归并** / **双指针** / **接剩余段**
> 原文锚点：第 71~110 段「我们可以在前面再加一个叫做 root 的节点…返回 root.next 就可以」

## 一句话总述
合并两个有序链表沿用**归并排序的合并步**：双指针比较取小者接上；引入**哑节点（dummy/root）**省掉"头节点特判"，最后把**剩余整段**直接接上即可。

## 面试官视角
- **考察意图**：归并思想的迁移能力 + 哑节点这个"消除边界分支"的套路。
- **P5** 能讲双指针比较 / **P6** 能写对并用哑节点简化 / **P7** 能指出"新建节点 vs 复用原节点"的空间差异并给出 O(1) 版。
- **红旗**：① 忘记处理某一链表先耗尽的情况；② 每次循环里判断"是不是第一个节点"来赋头；③ 忘了返回 `dummy.next` 而返回了哑节点本身。
- **惊艳点**：两个链表长度不等时，剩余段**整段挂上去**即可（因为它本身有序且都 ≥ 已合并部分），无需逐个拷贝。验证：1→5→9 与 2→3 合并 `[实测]`。

## 主问答
**Q：合并两个有序链表，返回一个新的有序链表。**
**A：**
1. **先给框架**：建一个**哑节点** `dummy`，用 `cur` 指向它作为"尾部指针"；`while l1 and l2` 时比较两者值，把较小者接到 `cur.next` 并把对应指针前移。
2. **再给哑节点价值**：没有哑节点就要在循环里特判"头节点是否为空"；有了它，**所有节点一视同仁**，最后返回 `dummy.next` 即真实头。
3. **最后给收尾**：循环退出说明至少一个链表耗尽，用 `cur.next = l1 or l2`（短路）把**剩余整段**直接接上——它已有序且整体不小于已合并部分。
**加分层**：**复杂度**——时间 O(m+n)，空间取决于实现：新建节点是 O(m+n)，直接改指针复用原节点是 **O(1)**；面试中应主动说明自己写的是哪种。

## 关键代码
```python
class ListNode:
    def __init__(self, val=0, nxt=None): self.val, self.next = val, nxt

def merge_two(l1, l2):
    dummy = cur = ListNode()               # 哑节点，统一处理
    while l1 and l2:
        if l1.val <= l2.val:
            cur.next, l1 = l1, l1.next     # 复用原节点：空间 O(1)
        else:
            cur.next, l2 = l2, l2.next
        cur = cur.next
    cur.next = l1 or l2                    # 剩余整段直接挂上
    return dummy.next

def to_list(h): return [] if not h else [h.val] + to_list(h.next)
a = ListNode(1, ListNode(2, ListNode(4)))
b = ListNode(1, ListNode(3, ListNode(4)))
print(to_list(merge_two(a, b)))            # [1, 1, 2, 3, 4, 4]
```

## ⚠️ 原文纠错
原文的整体思路（哑节点 + 双指针 + 接剩余段 + 返回 root.next）正确，且原文用短路 `l1 or l2` 简化收尾的处理也正确；需补正一点：原文实现是**每次新建 ListNode**，空间为 O(m+n)，卡面给出**复用原节点**的 O(1) 写法并点明差异。转写中的音译变量名已还原为 dummy / cur / next。未发现原理性错误。

- 哑节点免特判；取小接上；剩余整段挂尾；返回 `dummy.next`。
