> 原文锚点：第 39~44 段「通过下标的话，它不太可读。但是我们通过这个属性名称的话，它会变得比较可读」

## 一句话总述
`collections.namedtuple` 生成一个**带字段名的 tuple 子类**：既能 `p.x` 按名字访问（可读），又能 `p[0]` 按下标访问、可解包、可哈希（tuple 兼容性全保留）。

## 面试官视角
- **考察意图**：看你是否只会用裸 tuple / 裸字典，还是知道"轻量记录类型"这一档工具。
- **P5** 知道有这个类 / **P6** 说清"是 tuple 子类"及其代价 / **P7** 能对比 dataclass 并给出选型。
- **红旗**：① 以为它是 dict；② 不知道它不可变、没有默认值；③ 拿它当可变记录改字段。
- **惊艳点**：`_replace()` 返回**新对象**而非原地修改——这是它"不可变"的自洽设计。验证：改前后 id 不同 `[实测]`。

## 主问答
**Q：namedtuple 是什么？什么时候用它？**
**A：**
1. **先给结论**：`namedtuple` 是**工厂函数**，产出一个带字段名的 tuple 子类，内存开销和普通 tuple 一样小。
2. **再给优势**：`p.x` / `p.y` 可读性远好于 `p[0]` / `p[1]`；同时**保留**下标访问、解包、比较、可哈希等 tuple 全部能力。
3. **最后给边界**：字段**不可变**，改值要用 `_replace()` 生成新实例；没有默认值（可用 `defaults` 参数补）；字段多、要方法、要可变时改选 `dataclass`。
**加分层**：适合数据库行、坐标、配置项的轻量承载；接口返回用它比返回裸 tuple 更能自解释。

## 关键代码
```python
from collections import namedtuple
Point = namedtuple("Point", ["x", "y"])
p = Point(1, 2)
print(p.x, p[0], p == (1, 2))   # 1 1 True —— 名字与下标并存
print(hash(p) == hash((1, 2)))  # True —— 仍是 tuple，可哈希
p2 = p._replace(y=20)           # 返回新对象，不原地改
print(p, p2, p is p2)           # Point(x=1, y=2) Point(x=1, y=20) False
Car = namedtuple("Car", "color mileage", defaults=["white", 0])
print(Car())                    # Car(color='white', mileage=0)
```

## ⚠️ 原文纠错
原文演示中把访问下标与属性混读（转写造成顺序错乱），卡面按标准语义还原：`p[0]` 对应第一个字段、`p[1]` 对应第二个。转写中的音译词已统一还原为 namedtuple / tuple。未发现原理性错误。
