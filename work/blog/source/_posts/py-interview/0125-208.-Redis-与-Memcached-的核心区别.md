## 一句话总述
**Redis 与 Memcached 的三大区别**：① Redis 数据类型丰富（string/list/hash/set/zset），Memcached 仅简单 KV；② Redis 单进程单线程 + IO 多路复用，Memcached 多线程；③ Redis 支持 RDB/AOF 持久化，Memcached 不支持。

## 面试官视角
- **考察意图**：能否结构化对比两者，并理解"单线程为何还能高并发"。
- **P5** 能说出数据类型、IO 模型、持久化三点区别 / **P6** 能解释"Redis 单线程 + IO 多路复用也能高并发"（避免锁竞争、CPU 不阻塞在 IO） / **P7** 能补充"单线程的缺点：某个命令阻塞会拖住全部"与"Memcached 多线程无此问题"。
- **红旗**：认为"单线程 = 并发低"；以为 Memcached 也支持持久化。
- **惊艳点**：能点出"实际很多公司 MySQL + Redis 就能扛业务，未必需要 Memcached"的工程现状 `[经验]`。

## 主问答
**Q（面试官原话）：** Redis 和 Memcached 有什么区别？为什么 Redis 单线程还能高并发？

**A · 标准答案骨架：**
1. **① 数据类型**：Redis 支持丰富类型（string/list/hash/set/zset 等），能支撑更多业务场景；Memcached 只支持简单 KV。
2. **② 网络 IO 模型**：Redis 是**单进程单线程 + IO 多路复用**，避免了多线程锁竞争，且 CPU 不阻塞在 IO 上，所以单线程也能高并发；Memcached 是多线程模型。
3. **③ 持久化**：Redis 支持 **RDB 与 AOF** 两种持久化；Memcached 不支持——内存断电即失，只能靠外部写文件。

**加分层**：Redis 单线程的代价是"一个命令被阻塞（如大 key、慢命令），其他命令也受影响"；Memcached 多线程则一般不会因单命令卡住全部。所以"单线程"是取舍而非绝对优势。
