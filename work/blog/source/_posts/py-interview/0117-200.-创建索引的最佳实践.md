> 分类：数据库 | 难度：L3 | 题型：原理+实战 | 频率：高 | 关键词：**非空字段** / **区分度** / **索引长度** / **B+树 key** / **创建原则**
> 原文锚点：第8章 8-2「建索引时机（WHERE/JOIN/ORDER BY/GROUP BY 高频字段）；三条最佳实践——非空字段（NULL 无法比较）、高区分度（避免大量相同 key）、短长度（字符串逐字符比较），均由 B+树 key 比较代价推导」

## 一句话总述
**建索引不是越多越好，而是围绕查询需求在「非空、高区分度、短长度」三个维度上取舍**；三条原则都能由 B+树 key 比较的代价推导出来，理解底层就不必死记。

## 面试官视角
- **考察意图**：是否真懂"为什么这三条是原则"，而不只是背口诀；是否理解索引是为查询服务的。
- **P5** 能说出"经常出现在 WHERE/JOIN/ORDER BY/GROUP BY 的字段建索引"，并列举非空、区分度高、长度短三条 / **P6** 能把三条原则回扣到 B+树结构（空值无法比较、相同 key 大量比较、长字符串逐字符比较） / **P7** 能结合业务讲"枚举值字段不建索引""自增 INT 主键最省比较""字符串索引必须指定前缀长度"等落地经验。
- **红旗**：只背"高区分度""短"却讲不出为什么；认为"所有查询字段都应建索引"。
- **惊艳点**：提到"很多公司规范要求索引列 NOT NULL + 默认值"，并用 B+树无法对 NULL 做比较解释其底层原因 `[经验]`。

## 主问答
**Q（面试官原话）：** 什么时候该建索引？创建索引有哪些注意事项（最佳实践）？

**A · 标准答案骨架：**
1. **建索引要围绕查询需求，而不是建表时拍脑袋**：源文件明确这是"指导方针"——根据查询需求来创建。具体看四类字段：① 经常出现在 `WHERE` 后的过滤条件；② 表连接 `JOIN ... ON` 的连接键；③ 经常出现在 `ORDER BY` 后的排序字段；④ 经常出现在 `GROUP BY` 后的分组字段（建索引可避免额外 filesort）。
2. **① 优先用非空字段（NOT NULL + 默认值）**：MySQL 对 NULL 值难以做查询优化，在 B+树里 NULL 无法参与 key 的比较，索引就利用不上；所以很多公司规范要求索引列必须有默认值。
3. **② 选择区分度（离散度）高的字段**：若大量行取值相同，B+树里大量相同 key 需要逐层大量比较，效率极低；像只有几个枚举值的字段（性别、状态位）建索引收益很小。
4. **③ 索引长度尽量短**：索引在 B+树里作为 key 存在，字符串 key 比较是**从头逐字符**比，越长越耗时；因此字符串列建索引务必指定前缀长度（如 `INDEX(col(20))`），而自增 `INT` 主键比较极快。

**加分层**：能用一句话统一三条原则——**"只要 B+树 key 比较代价高，就该避免"**：空值不能比、重复值多比得久、长字符串比得慢，全是同一个根因。

## 关键代码
```sql
-- 为高频查询字段建普通索引，字符串指定前缀长度 [实测, MySQL 8]
CREATE INDEX idx_name ON user(name(20));
CREATE UNIQUE INDEX idx_email ON user(email);

-- 评估字段区分度（选择率越接近 1 越适合建索引）[实测, MySQL 8]
SELECT COUNT(DISTINCT status) / COUNT(*) AS selectivity FROM orders;
```

## ⚠️ 原文纠错
- 原文"唯一索引用 `createuniqueindex`、普通索引用 `createindex`"为口语化缩写，标准语法应为 `CREATE INDEX` / `CREATE UNIQUE INDEX`，现代更推荐 `ALTER TABLE ... ADD INDEX`。
- 原文"区分度比较高、离散度比较大"表述正确，但补充量化口径：用选择率（distinct/total）判断，而非主观"看起来分散"。
- 机翻还原：「auderright」→ `ORDER BY`；「grewy」→ `GROUP BY`；「全秒扫描」→ 全表扫描（见 203 卡）。

## 总结与追问预判
建索引的本质是**用空间换 B+树的有序查找时间**，三条原则（非空、高区分度、短长度）都指向"降低 key 比较代价"。面试官常追问"为什么你们表都要求 NOT NULL + 默认值"，标准答法是"NULL 在 B+树里无法参与比较，索引失效"，这比背规范更显功力。顺势会问：**索引失效三口诀（见 201 卡）**、**聚集/非聚集索引与回表（见 202 卡）**。
