> 分类：算法与数据结构/堆 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**heapq** / **最小堆** / **原地建堆** / **O(n)**
> 原文锚点：第 32~43 段「heapify 把一个列表转化成一个堆，并且是原地转化的，在线性时间去转化的」

## 一句话总述
`heapq` 是 Python 的**最小堆**实现，常用就三个动作：`heappush(h, x)` 入堆、`heapify(h)` **原地线性时间**把一个列表变成堆、`heappop(h)` 弹出最小；牢记它是**最小堆且不是排序后的列表**。

## 面试官视角
- **考察意图**：考**标准库熟练度**——时间紧时能不能直接用 heapq 解决问题，而不是手搓堆。
- **P5** 只会 `sort` / **P6** 用 heapq 三步走并知道是 O(n) 建堆 / **P7** 知道 `heapq` 无最大堆、需**存负值**模拟，以及 `nlargest/nsmallest` 的适用边界 `[经验]`。
- **红旗**：① 以为 `heapify` 后列表是有序的；② 以为 `heapq` 是类（`heapq` 是**模块 + 函数**，堆就是普通 list）；③ 对空堆 `heappop`（抛 `IndexError`）。
- **惊艳点**：`heapify` 是**自底向上下沉**，复杂度 `O(n)`，比逐个 `heappush`（`O(n log n)`）更快；而 `heappush`/`heappop` 各自 `O(log n)`。验证：`heapify([2,5,0])` 后列表可能是 `[0,5,2]` 而非排序结果 `[0,2,5]` `[实测]`。

## 主问答
**Q：Python 里怎么用堆？heapify 的复杂度是多少？**
**A：**
1. **三板斧**：`heappush(h, x)` 插入（O(log n)）、`heappop(h)` 弹出最小（O(log n)）、`heapify(h)` 把已有列表**原地**调整为堆（**O(n)**）。
2. **关键认知**：`heapq` 只提供**最小堆**，且**堆不是有序数组**——它只保证"父 ≤ 子"，`h[0]` 恒为最小。
3. **最大堆怎么办**：把值取负存入（`heappush(h, -x)`），弹出时再取负；这是 `heapq` 下的标准做法 `[经验]`。
**加分层**：`heapq.nlargest/nsmallest` 适合 k 远小于 n 的场景；k 接近 n 时直接 `sorted` 更快。

## 关键代码
```python
import heapq

h = [2, 5, 0]
heapq.heapify(h)
print(h)                       # [0, 5, 2] —— 堆不保证整体有序，只保证 h[0] 最小
print(heapq.heappop(h), heapq.heappop(h), heapq.heappop(h))   # 0 2 5

h2 = []
for x in (3, 1, 4): heapq.heappush(h2, x)
print(h2[0])                   # 1 —— 堆顶即最小值

# 模拟最大堆：存负值
maxh = []
for x in (3, 1, 4): heapq.heappush(maxh, -x)
print(-heapq.heappop(maxh))    # 4

print(heapq.nlargest(2, [5, 1, 3, 2]), heapq.nsmallest(2, [5, 1, 3, 2]))
# [5, 3] [1, 2]
```

## ⚠️ 原文纠错
原文"heapify 原地、线性时间"的说法正确，予以保留；演示序列 `[2,5,0] → heapify → 依次 pop 得 0,1(应为2),2(应为5)" 中，原文对具体中间值的口述有轻微出入，卡面以 heapq 实际行为为准（`[2,5,0]` heapify 后得 `[0,5,2]`，pop 序列为 0、2、5），已在关键代码中给出可运行验证。转写中的音译词已还原为标准术语。
