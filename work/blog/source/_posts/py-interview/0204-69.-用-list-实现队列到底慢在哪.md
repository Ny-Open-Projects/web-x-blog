> 分类：算法与数据结构/队列 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**list.pop(0)** / **搬移** / **O(n)**
> 原文锚点：第 89~91 段「对于列表的话，我们可以很方便往后面去追加元素，但往第一个位置去插一个元素，需要移动后面所有的元素」

## 一句话总述
list 尾部 `append` 是 O(1)，但**头部 `insert(0, x)` / `pop(0)` 需要整体搬移元素，是 O(n)**；所以拿 list 当队列，出队会随着长度增长线性变慢。

## 面试官视角
- **考察意图**：这是"知道复杂度"与"知道实现细节"的分水岭。
- **P5** 知道 list 头插慢 / **P6** 说清搬移机制与均摊 / **P7** 能量化差距并给出替代方案与适用场景。
- **红旗**：① 以为 list 头尾操作对称；② 只知道"慢"说不出 O(n) 原因；③ 反过来说 deque 中间插入也快。
- **惊艳点**：list 的 `append` 也不是每次 O(1)，它靠**超额分配**做**均摊**——这和哈希表扩容（见 59）是同一套摊销思路。验证：十万级 `pop(0)` 与 `popleft()` 计时对比 `[实测]`。

## 主问答
**Q：能不能用 list 实现队列？有什么问题？**
**A：**
1. **先给结论**：**能跑，但不该用**。入队 `append` 是 O(1)，出队 `pop(0)` 是 **O(n)**。
2. **再给机制**：list 底层是**连续数组**，删除首元素后必须把后面所有元素**整体前移一格**，元素越多搬得越多；`insert(0, x)` 同理。
3. **最后给选型**：需要队列用 `collections.deque`（两端 O(1)）；注意 deque **中间**插入删除仍是 O(n)，要按下标随机访问就用 list。
**加分层**：如果确实只有 list，可**倒着用**——用 `append` 入队、`list.pop()`（尾部）出队，把队列方向反过来即可全程 O(1)，代价是语义反直觉、易写错。

## 关键代码
```python
import timeit
from collections import deque
n = 200_000
lst = list(range(n)); dq = deque(range(n))
t1 = timeit.timeit(lambda: lst.pop(0), number=1000)   # O(n) 搬移
t2 = timeit.timeit(lambda: dq.popleft(), number=1000) # O(1)
print(f"list.pop(0): {t1:.4f}s  deque.popleft: {t2:.4f}s")  # 差距显著 [实测]
```

## ⚠️ 原文纠错
原文"往第一个位置插元素需要移动后面所有元素，效率不如 deque"的判断正确；需补正一点：list 的**尾部** `append`/`pop` 是**均摊** O(1) 而非绝对 O(1)（依赖超额分配），卡面已说明。转写中的音译词已还原为 list / deque。未发现原理性错误。

## 总结与追问预判
- list 头操作 O(n)、尾操作均摊 O(1)；队列请用 deque。
