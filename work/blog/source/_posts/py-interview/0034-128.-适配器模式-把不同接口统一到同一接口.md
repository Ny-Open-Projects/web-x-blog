> 原文锚点：第 24 段「适配器模式把不同对象的接口适配到同一个接口上」

## 一句话总述
**适配器模式**通过一个**间接层**，把**多个不兼容的接口**统一成**同一个接口**，使调用方可以用一致的方式使用它们（如万能充电头适配不同电器）。

## 面试官视角
- **考察意图**：考你能否分清**适配器（改接口）**与**代理（控访问）**与**装饰器（加功能）**三者。
- **P5** 能说出"把不同接口统一" / **P6** 能区分**对象适配器**（组合，推荐）与**类适配器**（继承，需多继承）/ **P7** 能指出适配器**只适配接口、不改行为**，以及过度适配会导致"间接层爆炸" `[经验]`。
- **红旗**：① 把适配器当代理（一个是改接口形状，一个是控访问）；② 说适配器"增强功能"（那是装饰器）；③ 在单继承语言里硬套类适配器。
- **惊艳点**：对象适配器用**组合**所以能适配**任意**被适配者且运行时可换；类适配器靠**继承**只能适配固定父类。验证：对象适配器构造时传入被适配实例 `[实测]`。

## 主问答
**Q：适配器模式解决什么问题？对象适配器和类适配器怎么选？**
**A：**
1. **结论**：当已有类的接口和调用方期望**不匹配**时，加一个适配器把它的方法**改名/转接**成统一接口，避免改原类。
2. **机制**：**对象适配器**持有被适配对象（组合），最常用；**类适配器**继承被适配类（多继承），受语言单继承限制。
3. **边界**：适配器**不改业务逻辑**，只做接口搬运；若需要改行为，那不是适配器该做的事。
**加分层**：适配器常和**Facade**混淆——Facade 是"简化一整组接口"，适配器是"把一个接口换成另一个"。

## 关键代码
```python
class Adapter:                      # 对象适配器（组合）
    def __init__(self, adaptee): self._a = adaptee
    def make_noise(self): return self._a.bark()   # 把 bark 统一成 make_noise
```
