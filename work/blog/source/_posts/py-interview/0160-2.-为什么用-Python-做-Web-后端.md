> 原文锚点：第 11~23 段「作为一个胶水语言，Python 轮子非常多…动态语言一时爽，代码重构火葬场」

## 一句话总述
Python 的核心优势是**生态广度 + 开发效率**，代价是**运行性能、大型项目维护性与 2/3 不兼容**——选型时要明确自己买的是什么、付的是什么。

## 面试官视角
- **考察意图**：有没有真实项目体感，而不是背"Python 简单易学"这类空话。
- **P5** 能说出生态广 / **P6** 能说清性能与维护两项代价 / **P7** 能给出"什么时候不该用 Python"的判断。
- **红旗**：① 只说"简单、优雅"；② 说"Python 性能差所以不适合后端"这种无前提断言；③ 完全不提 2/3 不兼容。
- **惊艳点**：**性能瓶颈多数在 IO 与数据库，而非语言本身**；先用 profiling 定位再谈换语言 `[经验]`。

## 主问答
**Q：你们为什么选 Python 做后端？它的缺点你怎么看？**
**A：**
1. **先给结论**：优点是**胶水语言、轮子多、生产力高**；代价是**性能、动态语言维护成本、2/3 不兼容**三件事。
2. **再给机制**：同一门语言可覆盖爬虫、Web 后端、数据分析、量化投资与机器学习，团队复用度高；但缺少类型声明，重构时缺少编译期保护，"动态一时爽、重构火葬场"说的就是这件事 `[经验]`。
3. **最后给边界**：CPU 密集且无法下推到 C 扩展的场景，Python 不是好选择；但 IO 密集、需要快速迭代的业务，它的综合成本更低。
**加分层**：现在主流解法是**类型注解 + 静态检查 + 关键路径用 C 扩展或独立服务**，把三笔代价分别抵消掉。

## ⚠️ 原文纠错
原文称「Python 的发布时间比 Java 还要早一年」不准确：Python 首个公开版本为 **1991 年**，Java 1.0 为 **1996 年**，相差约 **5 年** `[经验]`。其余优缺点表述与公认事实一致。
