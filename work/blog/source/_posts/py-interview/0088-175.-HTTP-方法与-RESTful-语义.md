> 分类：网络/HTTP | 难度：L2 | 题型：概念主问 | 频率：高 | 关键词：**GET** / **POST** / **PUT** / **DELETE** / **RESTful**
> 原文锚点：第 66~77 段「常用四方法 GET/POST/PUT/DELETE 对应 RESTful 获取/创建/更新/删除；GET 参数在 URL 明文有长度限制，POST 在 body 更安全」

## 一句话总述
RESTful 下四个常用方法语义分明：**GET 获取 / POST 创建 / PUT 更新 / DELETE 删除**。GET 参数在 URL（明文、有长度限制、幂等），POST 参数在 body（相对隐蔽、非幂等）。

## 面试官视角
- **考察意图**：是否理解方法的"语义契约"而非只会 GET/POST，以及能否说清 GET vs POST 的真实差异。
- **P5** 能说出四方法对应 CRUD / **P6** 能讲清 GET（URL 明文/有长度限制）vs POST（body/更隐蔽）/ **P7** 能指出"POST 更安全的说法不严谨"——只是不暴露 URL，仍需 HTTPS 加密。
- **红旗**：认为"POST 比 GET 安全"就结束；或把 PUT 当"部分更新"（PATCH 才是）。
- **惊艳点**：GET 有**长度限制**是浏览器/服务器对 URL 的限制（非 HTTP 规定）；真正"安全"指**不修改服务端数据**，GET 是 safe 方法 —— 验证：表单用 GET 刷新会重提交，POST 不会 `[经验]`。

## 主问答
**Q（面试官原话）：** HTTP 有哪些方法？GET 和 POST 到底有什么区别？

**A · 标准答案骨架：**
1. **先给结论**：RESTful 四件套——**GET 获取 / POST 创建 / PUT 更新 / DELETE 删除**（HEAD/PATCH/OPTIONS 较少用）。
2. **再给机制**：**GET** 参数拼在 **URL**（明文、受 URL 长度限制、幂等）；**POST** 参数放 **body**（不在地址栏暴露、无硬长度限制、非幂等）。
3. **最后给边界**："POST 更安全"只是**不暴露在 URL**——明文仍需 HTTPS；真正"安全方法"指不改服务端数据（GET/HEAD 是 safe，POST/PUT/DELETE 不是）。

**加分层**：幂等性上 GET/PUT/DELETE 幂等、POST 非幂等——这是重试与接口设计的关键，见 176 卡 `[经验]`。
