> 分类：算法与数据结构/缓存 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**LRUCache** / **move_to_end** / **popitem(last=False)**
> 原文锚点：第 118~140 段「我们使用 python 的 dict 加 collections 模块里面的 OrderedDict 来实现」

## 一句话总述
用 `OrderedDict` 同时承担**KV 存储**与**访问顺序**：`get` 命中后 `move_to_end` 标记为最新，`put` 超容量时 `popitem(last=False)` 淘汰最旧者，两个操作都是 **O(1)**。

## 面试官视角
- **考察意图**：白板手撕经典题，看数据结构选型与边界处理是否完整。
- **P5** 能写出思路 / **P6** 能一次写对 get/put 两个方法并说明复杂度 / **P7** 能指出线程安全、`# type: ignore` 之外的类型注解、以及并发下退化问题。
- **红旗**：① 容量判断写成 `>` 导致多留一个；② 更新已存在 key 时忘记先删再插（顺序不刷新）；③ 用 list 维护顺序导致 O(n)。
- **惊艳点**：`popitem(last=False)` 弹出的是**最早插入/最近被移到前端**的元素；把 move_to_end 放在命中分支里是关键。验证：构造访问序列断言淘汰结果 `[实测]`。

## 主问答
**Q：手写一个 LRUCache，要求 get 和 put 都是 O(1)。**
**A：**
1. **先给选型**：`OrderedDict` 既存 KV 又记录插入/移动顺序，天然满足需求；哈希表 O(1) 定位 + 顺序链表 O(1) 移动。
2. **再给流程**：**get**——命中则取值并 `move_to_end(k)`（标记最新），未命中返回哨兵（原文用 -1）；**put**——已存在则**先删后插**以刷新顺序，不存在则直接写入，写后若 `len > capacity`，`popitem(last=False)` 淘汰最旧。
3. **最后给边界**：容量为 0 或负数要先校验；返回值用 `-1` 需与合法值区分（真实场景建议约定 `None` 或抛出自定义异常）；多线程下需加锁。
**加分层**：若不想依赖 OrderedDict，标准解法是**哈希表 + 手写双向链表**；而 Python 3.7+ 的 dict 只需 `d.pop(k); d[k]=v` 即可把键挪到末尾，也能 O(1) 实现。

## 关键代码
```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        if capacity <= 0: raise ValueError("capacity 必须为正")
        self.cap, self.od = capacity, OrderedDict()
    def get(self, key: int) -> int:
        if key not in self.od: return -1
        self.od.move_to_end(key)          # 命中 -> 标记为最新
        return self.od[key]
    def put(self, key: int, value: int) -> None:
        if key in self.od: del self.od[key]   # 先删后插以刷新顺序
        self.od[key] = value
        if len(self.od) > self.cap:
            self.od.popitem(last=False)       # 淘汰最旧的

c = LRUCache(2)
c.put(1, 1); c.put(2, 2)
print(c.get(1))          # 1 —— 1 变最新
c.put(3, 3)              # 淘汰 key=2
print(c.get(2))          # -1 —— 已被淘汰
print(list(c.od))        # [1, 3]
```
