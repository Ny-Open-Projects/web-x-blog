> 分类：编程范式/Python 类 | 难度：L3 | 题型：事故题 | 频率：中 | 关键词：**可变类变量** / **共享** / **别名** / **__init__ 初始化**
> 原文锚点：第 42~53 段「类变量由所有实例共享」→ 反推可变对象情形

## 一句话总述
类变量若是 `list`/`dict`/`set` 这类**可变对象**，它只有**一份**，任何实例做**原地修改**（`append` 等）都会让**所有实例**看到变化——这是类变量最经典的线上事故源。

## 面试官视角
- **考察意图**：从"知道类变量共享"进阶到"知道共享带来的**副作用**"，看你是否踩过坑。
- **P5** 只知道类变量共享 / **P6** 能说出可变类变量被全实例共享 / **P7** 能给出修复写法并关联**可变默认参数**同类陷阱 `[经验]`。
- **红旗**：① 在类体写 `items = []` 当"每个实例的默认容器"；② 以为 `self.items = []`（赋值）和 `self.items.append()`（原地改）等价；③ 排查"数据串了"时想不到查类变量。
- **惊艳点**：一句话——**赋值是新建，原地改是共享**；`self.x = v` 建实例属性，`self.x.append(v)` 改的是类里那个。验证：两个实例 append 后 `len` 都是 2 `[实测]`。

## 主问答
**Q：类里写 `items = []` 会有什么问题？怎么修？**
**A：**
1. **成因**：类体执行**一次**，`[]` 只创建**一个** list 对象，挂在类上；所有实例的 `self.items` 都**读到同一个对象**（读时实例没有 → 回落类）。
2. **现象**：`a.items.append(1)` 后，`b.items` 也变成 `[1]`；换成赋值 `a.items = [1]` 则不影响 `b`（因为这是给 a 建实例属性）。
3. **修复**：把可变容器放到 `__init__` 里 `self.items = []`，**每个实例各建一份**；确实要共享时显式写 `ClassName.items` 并加注释。
**加分层**：同源陷阱是**可变默认参数** `def f(x, buf=[])`——默认参数在函数定义时求值，同样只创建一次（见 24 卡，传参系列）。

## 关键代码
```python
class Bad:
    items = []                    # 类变量：只创建一次
    def add(self, x): self.items.append(x)

a, b = Bad(), Bad()
a.add(1); b.add(2)
print(a.items, b.items, Bad.items)   # [1, 2] [1, 2] [1, 2] —— 串了

class Good:
    def __init__(self): self.items = []   # 每个实例各一份
    def add(self, x): self.items.append(x)
```

## ⚠️ 原文纠错
原文只讲到"类变量由所有实例共享"，**未涉及**可变对象的共享副作用，本卡系由该知识点反推的扩展题，已注明推导来源。原文示例中的类变量是不可变字符串，本身不存在该问题。转写中的音译词已还原为标准术语。

## 总结与追问预判
- 可变类变量**只有一个**；原地改 = 全实例受害；**移进 `__init__`** 是唯一正解。
