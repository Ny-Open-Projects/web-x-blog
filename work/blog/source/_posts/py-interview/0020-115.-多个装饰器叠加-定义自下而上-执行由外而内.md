> 分类：编程范式/装饰器 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**叠加** / **执行顺序** / **等价展开** / **洋葱模型**
> 原文锚点：第 22~31 段「@ 只是语法糖，等价于 f = deco(f)」→ 反推多层情形

## 一句话总述
叠多个装饰器时，**等价展开是自下而上**：`@a` `@b` `def f` ≡ `f = a(b(f))`；因此**定义（包装）顺序自下而上，调用执行顺序由外而内**（先 `a` 的前置、`b` 的前置、原函数、`b` 的后置、`a` 的后置）。

## 面试官视角
- **考察意图**：考你能不能把"语法糖展开"推广到多层，而不是靠猜。
- **P5** 说"从上往下执行"（错）/ **P6** 能写出 `a(b(f))` 等价式并说清执行顺序 / **P7** 能结合**洋葱模型**解释"为什么鉴权装饰器要写在最上面"，并说出 `@wraps` 链在多层时的行为 `[源码]`。
- **红旗**：① 认为最靠近 `def` 的装饰器最先执行（它是最先**包装**、但最后**执行**）；② 把顺序依赖的装饰器（如先缓存后鉴权）写反造成**越权缓存**；③ 多层时中间层忘了 `wraps` 导致链断裂。
- **惊艳点**：顺序即安全——**鉴权必须包在缓存外面**，否则未鉴权的结果会被缓存下来返给其他人。验证：交换两层顺序后未登录用户也能拿到缓存数据 `[实测]`。

## 主问答
**Q：一个函数上叠了多个装饰器，执行顺序是什么？**
**A：**
1. **等价式**：`@a` `@b` `def f()` 等价于 `f = a(b(f))`，即**靠近 `def` 的先被应用**，`a` 包在最外层。
2. **执行顺序**：调用时**由外而内**——`a` 前置 → `b` 前置 → 原函数 → `b` 后置 → `a` 后置（洋葱/栈式）。
3. **实践**：把**横切且需最先拦截**的逻辑（鉴权、限流）放**最上面**（最外层）；把**依赖结果**的逻辑（缓存、日志耗时）放内层或按依赖排列。
**加分层**：每层都应加 `@functools.wraps`，否则中间层会把 `__name__` 改掉，后续层拷到的是错误的元信息；多层还叠加了等量函数调用开销。

## 关键代码
```python
def outer(func):
    def w(*a, **k):
        print('outer before'); r = func(*a, **k); print('outer after'); return r
    return w

def inner(func):
    def w(*a, **k):
        print('inner before'); r = func(*a, **k); print('inner after'); return r
    return w

@outer
@inner                      # 等价于 f = outer(inner(f))，inner 先包装
def f(): print('  body')

f()                         # outer before → inner before → body → inner after → outer after
```

## 总结与追问预判
- `@a`+`@b` ≡ `a(b(f))`；**包装自下而上、执行由外而内**；鉴权放最外层。
