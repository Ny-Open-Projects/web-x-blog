> 分类：数据库 | 难度：L2 | 题型：概念题 | 频率：高 | 关键词：**脏读** / **不可重复读** / **幻读** / **丢失更新** / **并发控制**
> 原文锚点：第 39~51 段「不加并发控制会产生四种异常：幻读(phantom)、不可重复读(non-repeatable)、脏读(dirty)、修改丢失(lost update)」

## 一句话总述
多个事务并发读写同一数据时会产生四类异常：**脏读**（读到别的事务未提交的修改）、**不可重复读**（同一事务内两次读同一行得到不同结果）、**幻读**（同一事务内两次范围查询，第二次多出原本没有的行）、**丢失更新**（两个事务改同一行，后写覆盖前写）。

## 面试官视角
- **考察意图**：能否准确区分这四种异常，尤其是"不可重复读 vs 幻读"这一高频混淆点。
- **P5** 能说出四个名字 / **P6** 能讲清定义且区分不可重复读（针对**已存在行的修改**）与幻读（针对**新插入的行**） / **P7** 能说清每种异常由哪个隔离级别解决，以及 InnoDB 在 RR 下靠 MVCC + Next-Key Lock 顺带防住幻读。
- **红旗**：把幻读说成"读到别人提交的修改"（那是不可重复读）；或认为脏读是"读到旧值"（脏读是读到**未提交**的脏数据）。
- **惊艳点**：不可重复读与幻读的本质区别——前者是**同一行的 update** 导致、后者是**其他事务 insert 新行**导致；SQL 标准里 RR 解决不可重复读，防幻读需 Serializable（InnoDB 例外，靠间隙锁） `[源码]`（SQL:2011 隔离级别定义）。

## 主问答
**Q（面试官原话）：** 事务并发会有哪些问题？不可重复读和幻读有什么区别？

**A · 标准答案骨架：**
1. **先给结论**：四类——**脏读、不可重复读、幻读、丢失更新**；面试最常考的是区分**不可重复读**（改）与**幻读**（增）。
2. **再给机制**：**脏读**=读别的事务**未提交**的修改（它一回滚你就读到脏的）；**不可重复读**=同一事务两次读**同一行**却不同（别的事务把它**改了并提交**）；**幻读**=同一事务两次**范围查**多出原本没有的行（别的事务**插入**了新行）；**丢失更新**=两事务先后改同一行，后写覆盖先写。
3. **最后给边界**：不可重复读侧重"已存在行的数据变了"，幻读侧重"结果集多了新行"——这是 SQL 标准把两者分开定义的原因；丢失更新要靠**锁或乐观锁版本号**解决（见 192 卡）。

**加分层**：InnoDB 在 **Repeatable Read** 下用 **MVCC 快照**解决不可重复读，再用 **Next-Key Lock（间隙锁+记录锁）** 额外防住幻读，比 SQL 标准要求的更强 `[经验]`。

## 关键代码
```sql
-- 演示不可重复读：事务A两次读同一行，事务B在中间提交修改 [实测]
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
START TRANSACTION;                 -- A
SELECT bal FROM account WHERE id=1;   -- 读到 100
-- 另一会话 B：UPDATE account SET bal=200 WHERE id=1; COMMIT;
SELECT bal FROM account WHERE id=1;   -- RC 下读到 200（不可重复读）
```

## ⚠️ 原文纠错
原文音译需还原：「**幻多 / fantmread**」→ **幻读（phantom read）**；「**非重复读 / notrepeatableread**」→ **不可重复读（non-repeatable read）**；「**脏毒**」→ **脏读（dirty read）**；「**修改丢失**」→ **丢失更新（lost update）**；「**数据扩答**」→ **SQL 标准（ANSI/ISO）**（定义四类隔离级别）。概念正确：四类并发异常的定义与举例（转账/查询）。核对范围：第 39~51 段 并发异常。

## 总结与追问预判
- 脏读=未提交；不可重复读=同行被改；幻读=多了新行；丢失更新=后写覆盖前写。
