## 一句话总述
**Tornado** 是 **FriendFeed** 开源的**并发框架 + Web 微框架**，靠**自身 IOLoop + 非阻塞 socket + 协程（回调/async）**实现高并发，适合轻量微服务与 RESTful 接口；**底层仍是 IO 多路复用**，并非另起炉灶。

## 面试官视角
- **考察意图**：是否用过 Tornado，能否说清它"不靠多线程"却高并发的原因。
- **P5** 能说出 Tornado 是 Web 微框架、适合微服务 / **P6** 能讲清它用 IOLoop + 非阻塞 socket + 协程实现异步，底层是 epoll / **P7** 能对比 Tornado 与 Flask/Django（后者同步阻塞、靠 WSGI 多线程），并指出 Tornado 生态较小的现实。
- **红旗**：说 Tornado 像 Flask 一样"每请求一个线程"（Tornado 是单线程事件循环）；或认为 Tornado 必须 monkey patch 才能异步。
- **惊艳点**：Tornado 的 `IOLoop` 就是它自己的事件循环，等价于手写 `selectors` 的事件循环——**它和 gevent/asyncio 是同一套 IO 多路复用思路的不同封装**，只是 Tornado 不改写标准库 `[经验]`。

## 主问答
**Q（面试官原话）：** 你提到用过 Tornado，它为什么能高并发？和 Flask 有什么区别？

**A · 标准答案骨架：**
1. **先给结论**：Tornado 是**单线程事件循环 + 非阻塞 socket**，一个线程就能扛大量并发连接；而 Flask/Django 默认**同步阻塞**，靠 WSGI 多线程/多进程扛并发——这是范式差异。
2. **再给机制**：Tornado 内置 **IOLoop**（事件循环），配合**非阻塞 socket** 与**协程（早期回调、后来 `@gen.coroutine` / `async`）**；当请求要访问外部（如下游 HTTP）时，不会阻塞事件循环，而是让出控制权，等 IO 就绪再回来——**底层就是 epoll/kqueue 多路复用**。
3. **最后给边界**：Tornado **不依赖 monkey patch 改写标准库**（那是 gevent 的做法）；它适合 IO 密集的轻量微服务，但**生态比 Flask/Django 小**，同步阻塞的 ORM/库在 Tornado 里反而是包袱。

**加分层**：用它做**高并发网关 / 代理 / 实时推送**很合适；纯 CRUD 业务不如直接上 Flask/FastAPI `[经验]`。

## 关键代码
```python
import tornado.ioloop, tornado.web
# Tornado 单线程事件循环 + 非阻塞 handler [实测]
class Main(tornado.web.RequestHandler):
    async def get(self):
        self.write("ok")          # 异步发下游请求时不阻塞事件循环
app = tornado.web.Application([(r"/", Main)])
app.listen(8888); tornado.ioloop.IOLoop.current().start()
```
