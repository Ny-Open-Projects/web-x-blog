> 原文锚点：第9章 9-2「XSS=Cross-Site Scripting(因CSS被样式表占用改XSS); 原理: 恶意JS植入页面, 其他用户浏览器执行→盗取document.cookie; 两类: 反射型(非持久, URL参数+诱导点击) / 存储型(持久, 评论等存DB后他人浏览执行); 演示 评论框提交<script>alert('hello')</script> 被user2执行(存储型)」

## 一句话总述
**XSS = 攻击者把恶意 JS 注入页面，其他用户浏览时脚本在其浏览器执行**（如盗取 `document.cookie` 冒用账号）；分**存储型（持久，存库后他人浏览触发）**与**反射型（非持久，URL 参数 + 诱导点击）**。

## 面试官视角
- **考察意图**：是否分清两类 XSS 并说清危害与防御，而非只背缩写。
- **P5** 能定义 XSS（恶意脚本在他人浏览器执行）并说出"转义输出/不信任输入" / **P6** 能区分存储型（存库持久）vs 反射型（URL 参数、诱导点击）并举例 / **P7** 能系统防御：输入校验 + **输出转义（HTML 转义）+ CSP + HttpOnly Cookie + 不回显**。
- **红旗**：把 XSS 和 CSRF 混为一谈；认为"前端 JS 校验"能防 XSS（攻击者可绕过前端直发请求）。
- **惊艳点**：能点出"HttpOnly 标记 Cookie 后 JS 无法读 `document.cookie`，即使有 XSS 也拿不到会话" `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是 XSS？有哪些类型？怎么防范？

**A · 标准答案骨架：**
1. **原理**：恶意用户把 JS 代码片段植入页面（如评论框提交 `<script>`），页面未转义就渲染，其他用户浏览时该脚本在其浏览器执行——可盗取 `document.cookie`、冒用账号（HTTP 无状态，网站靠 Cookie 识别用户）。
2. **两类**：
   - **存储型（持久）**：恶意脚本被存进数据库（如评论），任何用户打开页面都会执行（源文件演示：user1 提交 `<script>`，user2 刷新也执行）。
   - **反射型（非持久）**：脚本放在 **URL 参数**里，攻击者通过邮件等诱导用户点击，一次性反射执行。
   - （注：还有基于 DOM 的第三类，由前端 JS 不安全操作 DOM 触发。）
3. **防范**：① 输入校验 + **输出时 HTML 转义**（核心）；② 设 **Content-Security-Policy（CSP）** 限制脚本源；③ Cookie 加 **HttpOnly** 防 JS 读取；④ 错误信息不回显。

**加分层**：只做"前端 JS 校验"不够——攻击者可绕过前端直接构造请求，防御必须在**服务端做输入校验 + 输出转义**这一对组合拳。
