> 分类：数据库·缓存 | 难度：L3 | 题型：实战 | 频率：高 | 关键词：**缓存穿透** / **查不到的数据** / **缓存空值** / **短TTL** / **布隆过滤器**
> 原文锚点：第8章 8-4「缓存穿透：大量查不到的数据请求穿透到后端DB(如爬虫按ID扫不存在的ID);解决——查不到也缓存空值(NULL)并设短TTL，或后续插入时删缓存」

## 一句话总述
**缓存穿透 = 查询根本不存在的数据，缓存与 DB 都没有，请求每次都打到 DB**。解法：缓存空值（NULL）并设短 TTL，或用布隆过滤器拦截。

## 面试官视角
- **考察意图**：是否分得清穿透/击穿/雪崩（三者极易混），并给出落地解法。
- **P5** 能定义穿透（查不存在的数据打 DB）并说出"缓存空值"解法 / **P6** 能解释"为什么缓存空值有效"以及"短 TTL 防止脏数据长期留存" / **P7** 能补充"布隆过滤器前置拦截"与"空值缓存的存储代价权衡"。
- **红旗**：把穿透说成"热点 key 过期"（那是击穿）；或只答"加锁"却说不清锁解决的是哪类问题。
- **惊艳点**：能点出"布隆过滤器有误判率，适合海量不存在 ID 的拦截；空值缓存适合少量" `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是缓存穿透？怎么解决？

**A · 标准答案骨架：**
1. **定义**：大量请求查询**数据库和缓存都不存在**的数据（如爬虫按 ID 扫一堆不存在的 ID），缓存无法命中、每次都落到后端 DB，DB 压力陡增。
2. **解法一（缓存空值）**：即使查不到也把结果（NULL）缓存下来并设**较短 TTL**——后续同样请求直接走缓存返回，不再打 DB；若之后真插入了该 ID 数据，删除对应缓存即可。
3. **解法二（布隆过滤器）**：在缓存前加布隆过滤器，不存在的 key 直接拦截，根本不进缓存/DB 查询。

**加分层**：空值缓存要注意"无效 key 也可能占用内存"，适合量不大的场景；海量不存在 ID 用布隆过滤器更省，但有误判率需权衡。

## 关键代码
```python
# 缓存空值防穿透（redis-py）[实测, redis-py]
import redis
r = redis.Redis()
def get_article(aid):
    v = r.get(f"article:{aid}")
    if v is None:
        row = db.query("SELECT * FROM article WHERE id=%s", aid)
        if row is None:
            r.set(f"article:{aid}", "", ex=60)   # 空值缓存，短 TTL
            return None
        r.set(f"article:{aid}", row, ex=300)
        return row
    return None if v == "" else v
```

## ⚠️ 原文纠错
- 机翻还原：「穿透」→ **缓存穿透**；「now这个结果」→ **NULL（空值）**；「nownow」→ **NULL**；「文档的缓存」→ **对应数据的缓存**；「便」→ **遍历/扫描**（爬虫按 ID 遍历）。
