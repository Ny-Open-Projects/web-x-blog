> 分类：网络/HTTP | 难度：L2 | 题型：概念主问 | 频率：高 | 关键词：**请求行** / **请求头** / **状态行** / **状态码**
> 原文锚点：第 6~46 段「HTTP 请求=请求行+请求头+消息主体；响应=状态行+响应头+响应正文；GET 无 body，POST 有 body」

## 一句话总述
HTTP 报文分**请求**与**响应**两类，每类都由"**行 + 头 + 主体**"组成：**请求行**（方法+路径+版本）+ 请求头 + 消息主体；**状态行**（版本+状态码）+ 响应头 + 响应正文。GET 通常无 body，POST 把参数放 body。

## 面试官视角
- **考察意图**：是否看清 HTTP 是"文本协议、三段式"的基本结构，而非只会调 API。
- **P5** 能说出请求/响应各有"行+头+体" / **P6** 能讲清请求行三要素、GET 无 body / **P7** 能下钻到头字段语义（Host/Content-Type/Content-Length）与分块传输。
- **红旗**：把"状态码"说成只在请求里；或认为 POST 一定比 GET 安全（只是不暴露在 URL）。
- **惊艳点**：HTTP 本质是**可读文本**——`curl -v` 直接能看到三段结构，不需要抓包工具 —— 验证：`curl -v https://example.com` 打印请求行/头与状态行/头 `[实测]`。

## 主问答
**Q（面试官原话）：** HTTP 的请求和响应都是由什么组成的？

**A · 标准答案骨架：**
1. **先给结论**：两者都是 **行 + 头 + 主体** 三段式。
2. **再给机制**：**请求**= 请求行（方法+URL 路径+HTTP 版本）+ 请求头 + 消息主体（GET 无、POST 有）；**响应**= 状态行（版本+状态码）+ 响应头 + 响应正文（如 HTML）。
3. **最后给边界**：头部与主体间有**空行**分隔；主体长度由 `Content-Length` 或分块传输界定，否则接收方不知何时结束。

**加分层**：请求头里的 `Host` 是 HTTP/1.1 强制字段（虚拟主机靠它区分），这是"一个 IP 托管多域名"的基石 `[经验]`。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 报文有几部分 | 基本认知 | 行/头/体 | 换题 → 不及格 |
| L2 | 请求行有什么 | 是否背的 | 方法+路径+版本 | 判 P5 |
| L3 | GET/POST 主体区别 | 有没有真理解 | GET 无 body | 判 P6 |
| L4 | 主体怎么界定长度 | 架构判断 | Content-Length/chunked | 判 P6+ |
| L5 | 你调过哪些头字段 | 实战经验 | Host/Content-Type 等 | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| HTTP/1.1（RFC 7230） | HTTP/2 为二进制帧、头部压缩 | 三段式文本结构以 1.1 为准；可提 2/3 已非文本 |

## 关键代码
```python
import http.client
conn = http.client.HTTPConnection("www.example.com", 80, timeout=5)
conn.request("GET", "/")                     # 请求行 + 请求头 [实测]
resp = conn.getresponse()
print(resp.status, dict(resp.getheaders()))   # 状态行 + 响应头
```
