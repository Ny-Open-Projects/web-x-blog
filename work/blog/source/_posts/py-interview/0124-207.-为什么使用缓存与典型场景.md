## 一句话总述
**缓存本质是"用内存换速度"**：把热点数据放内存，缓解后端关系库压力、降低响应延迟（内存读取 μs 级 vs 磁盘 ms 级）、提升单机吞吐（QPS）。

## 面试官视角
- **考察意图**：是否说清"为什么用缓存"的三条收益，而非只答"快"。
- **P5** 能说出缓存缓解 DB 压力、降延迟、提吞吐三点 / **P6** 能用数量级对比（内存 μs vs 磁盘 ms）解释"快"从哪来 / **P7** 能结合"热点数据扛流量""多级缓存"讲生产落地。
- **红旗**：只说"缓存快"不解释机制；把缓存当"万能提速"忽视一致性代价。
- **惊艳点**：能点出"内存是易失存储，断电即失，所以才需要持久化/回填机制配合" `[经验]`。

## 主问答
**Q（面试官原话）：** 什么是缓存？为什么要用缓存？什么场景用？

**A · 标准答案骨架：**
1. **缓解关系数据库压力**：热点数据（高频访问）若每次都打 MySQL，会给 DB 很大压力；用缓存扛热点，DB 只扛非热点/写。
2. **减少响应时间**：内存读取是**微秒（μs）级**，机械磁盘是**毫秒（ms）级**，差数量级——这是"快"的根本来源。
3. **提升吞吐量**：像 Redis 这种内存型数据库单机即可支撑极高 QPS。

**加分层**：典型内存型缓存数据库是 **Redis** 与 **Memcached**；缓存不是银弹，引入后必须面对"缓存与 DB 一致性"问题（见 215/516 卡）。

## 关键代码
```python
# 典型缓存读取：命中返回，未命中查 DB 并回填 [实测, redis-py]
import redis
r = redis.Redis()
val = r.get("hot:1")
if val is None:
    val = db.query("SELECT ...")      # 回源
    r.set("hot:1", val, ex=60)         # 回填 + TTL
```

## ⚠️ 原文纠错
- 机翻还原：「REDIS / REDS / REDI / reeliase / realism / reedit / reeisit / relix / redce」→ **Redis**；「memorycatch / memmocash / memocath / mmarrycatch」→ **Memcached**；「阿多洛夫用 / 多罗费用」→ **IO 多路复用**（Redis 单进程单线程 + IO 多路复用）。
- 原文"打开网站几秒、磁盘寻址几毫秒、内存一道数据微秒级、机械磁盘毫秒级"——量级表述准确（内存 μs < 磁盘 ms）。
- 原文"单机支撑非常高的 QBS"→ **QPS**。
