> 分类：编程范式/设计模式 | 难度：L1 | 题型：八股题 | 频率：中 | 关键词：**创建型** / **结构型** / **行为型** / **23 种**
> 原文锚点：第 1~7 段「二十三种设计模式，总的分类上分三大类：创建型、行为型、结构型」

## 一句话总述
GoF《设计模式》收录 **23 种**模式，按目的分 **创建型 / 结构型 / 行为型** 三类；Python 讲得少，是因为**语言本身已内置**了迭代器、装饰器等模式，且大量 Python 代码偏脚本/数据分析，规模没到必须用模式的程度。

## 面试官视角
- **考察意图**：看你有没有"模式的分类框架"，而不是零散背几个。
- **P5** 能说出三大类 / **P6** 每类各举 2~3 个代表模式 / **P7** 能指出**动态语言淡化模式**的原因（一等函数、鸭子类型、内置语法糖）并说明何时仍需要 `[经验]`。
- **红旗**：① 把 23 种硬背成清单却说不出解决什么问题；② 认为"Python 不需要设计模式"；③ 把 MVC 当成 GoF 23 种之一（它是**架构模式**，不是 GoF 模式）。
- **惊艳点**：模式是**沟通词汇**而非目标——Python 里很多模式"消失"了，因为语言直接支持：`for` 即迭代器、`@` 即装饰器、`with` 即模板方法的资源版 `[实测]`。

## 主问答
**Q：设计模式分哪几类？Python 里为什么谈得少？**
**A：**
1. **三类**：**创建型**（解决对象创建：工厂、建造者、原型、单例）、**结构型**（解决组合与接口：代理、适配器、装饰器、外观、享元）、**行为型**（解决交互与职责：观察者、策略、模板方法、迭代器等）。
2. **语言内置**：动态语言**自己已实现**不少模式——迭代器模式、装饰器模式都由语法直接支持，无需手写样板。
3. **场景差异**：很多 Python 使用者写爬虫/脚本/数据分析，项目规模小；**一旦项目上规模**，模式能让代码更优雅。
**加分层**：学模式的有效路径是**看完概念立刻写小 demo**，只用不读很难形成印象；同时要警惕"为用模式而用模式"的过度设计。

## 关键代码
```python
# 迭代器模式被语言吸收：实现 __iter__/__next__ 即可 for
class Range3:
    def __init__(self, n): self.n, self.i = n, 0
    def __iter__(self): return self
    def __next__(self):
        if self.i >= self.n: raise StopIteration
        self.i += 1; return self.i

print(list(Range3(3)))          # [1, 2, 3]
```

- 三类：**创建型 / 结构型 / 行为型**；Python 讲得少是因为**内置 + 规模**；模式是沟通词汇不是目标。
