> 原文锚点：第10章 10-2「短码算法两种：A.MD5摘要(任意长度→定长32位十六进制)+截断前7位，可行但有冲突概率，高并发插入需查库检测冲突不友好；B.递增序列算法：自增ID→62进制编码(字符集a-z A-Z 0-9共62)，62^7≈万亿够用无冲突；进制转换=不断取余(divmod)+倒序输出；边界 num=0 返回字符集[0]；ID 由 Redis INCR 全局计数器生成；最终选型 B」

## 一句话总述
**短码生成有两种路线**：① **MD5 摘要 + 截断前 7 位**——简单但有冲突概率，高并发插入要查库检测冲突，不友好；② **自增 ID → base62 编码**（字符集 62 个，62^7≈3.5 万亿足够），用 **Redis INCR** 生成全局自增 ID，再"不断取余 + 倒序输出"转 62 进制。**实战选②**，无冲突、无需查库。

## 主问答
**Q（面试官原话）：** 短码怎么生成？为什么不用哈希？

**A · 标准答案骨架：**
1. **方案 A：MD5 + 截断**（不推荐）：对长 URL 求 MD5（任意长度 → 定长 32 位十六进制串），取前 7 位作短码。**缺陷**：截断必然有**冲突概率**，高并发插入时每次都要查库判冲突再重试，非常不友好 `[经验]`。
2. **方案 B：自增 ID → base62 编码**（实战选用）：字符集 = `a-z`(26) + `A-Z`(26) + `0-9`(10) = **62 个**；62^7 ≈ **3.5 万亿**，7 位足够且**天然无冲突**。全局自增 ID 由 **Redis `INCR`** 计数器原子生成，再把这个十进制 ID 编成 62 进制短码。
3. **进制转换核心**：十进制 → 62 进制的口诀是"**不断取余、倒序输出**"——用 `divmod(num, 62)` 循环取商与余数，余数映射字符集下标，循环到商为 0，最后把余数序列反转。注意 **num=0 边界**直接返回字符集第 0 个字符 `[经验]`。
4. **选型结论**：方案 B 无冲突、无需查库、ID 单调递增易分库，完胜方案 A。

**加分层**：能讲"若想隐藏序号可加随机盐或混淆映射表"；或"62 进制比 36/16 进制更短，7 位即可覆盖万亿级"。

## 关键代码
```python
# 十进制 → 62 进制短码（短网址核心算法）[源码, python]
CHARS = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789"  # 62 个字符

def encode(num: int) -> str:
    if num == 0:
        return CHARS[0]                 # 边界：num=0 直接返回首字符
    res = []
    while num:
        num, rem = divmod(num, 62)      # 不断取余：divmod 返回 (商, 余数)
        res.append(CHARS[rem])
    return "".join(reversed(res))       # 倒序输出

# 62^7 ≈ 3.5 万亿，7 位短码足够覆盖
print(encode(0))    # 'a'
print(encode(61))   # '9'
print(encode(1))    # 'b'
```
