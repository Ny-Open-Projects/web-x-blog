> 分类：操作系统/Linux | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**软链接** / **硬链接** / **inode** / **符号链接**
> 原文锚点：第 33~39 段「软链接类似 Windows 快捷方式，保存原文件绝对路径，inode 与原文件不同；硬链接 inode 相同，同指一块磁盘区块」

## 一句话总述
**软链接（符号链接）**是一个独立文件，里面存**原文件的路径**，其 **inode 与原文件不同**；**硬链接**与原文件**共享同一个 inode**，指向同一块磁盘数据——这是二者最常被考的区别。

## 面试官视角
- **考察意图**：考你是否真懂 inode 与"链接"的底层差异，而不只是"软链接像快捷方式"。
- **P5** 能说出"软链接是快捷方式、硬链接同 inode" / **P6** 能讲清：删原文件后**软链接失效**（悬空）、**硬链接仍可用**（只要还有一个链接在）；软链接可跨文件系统、可链目录，硬链接不行 / **P7** 能指出硬链接**不能跨文件系统**、**不能链目录**（避免环），以及软链接的"路径替换"机制 `[经验]`。
- **红旗**：① 以为硬链接也独立占一份数据（错，同 inode 共享）；② 以为删原文件硬链接也失效（错，硬链接仍可读）；③ 说软链接与原文件同 inode。
- **惊艳点**：`ln -s a b` 建软链接、`ln a c` 建硬链接；`ls -i` 看 inode——硬链接的 inode 编号与原文件**完全一致**。验证：`ln a c && ls -i a c` 编号相同 `[实测]`。

## 主问答
**Q：软链接和硬链接有什么区别？**
**A：**
1. **结论**：硬链接与原文件**共用 inode**（同一份磁盘数据）；软链接是独立文件，**存路径、inode 不同**。
2. **机制**：操作系统靠 **inode** 找磁盘区块；硬链接只是多一个"名字"指向同一 inode，所以删原文件数据还在（还有别的链接）；软链接只记路径，原文件一删就**悬空失效**。
3. **边界**：硬链接**不能跨文件系统、不能链目录**；软链接都可以，但路径变动会失效。
**加分层**：`ln -s`（软）/ `ln`（硬）；`ls -li` 一眼看出 inode 是否相同。

## 关键代码
```bash
echo hi > a
ln a c            # 硬链接：c 与 a 同 inode
ln -s a b         # 软链接：b 是独立文件存路径
ls -li a b c      # a 与 c 编号相同；b 不同
rm a; cat c       # 硬链接 c 仍能读；软链接 b 悬空失效
```

```python
import os
os.symlink("a", "b")              # 软链接：b -> a（独立 inode）
os.link("a", "c")                 # 硬链接：c 与 a 同 inode
print(os.path.samefile("a", "c")) # True —— 硬链接共享 inode
```

## ⚠️ 原文纠错
原文"软链接类似 Windows 快捷方式，保存原文件绝对路径，inode 与原文件不同；硬链接 inode 相同，都指向同一磁盘区块"——准确，并予以保留（机翻"inote"=**inode**，"luws文件系统"=**Linux 文件系统**，"软件"=软链接）。原文"硬链接相当于创建普通文件、inode 相同"表述正确。无事实错误，仅术语音译需还原。

- 硬链接同 inode 共享数据；软链接存路径、独立 inode。
