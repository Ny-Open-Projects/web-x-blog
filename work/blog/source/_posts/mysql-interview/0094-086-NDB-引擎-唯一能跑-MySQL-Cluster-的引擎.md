> 分类：存储引擎 | 难度：L2 | 题型：八股题 | 频率：低 | 关键词：**NDB** / **MySQL Cluster** / **READ COMMITTED** / **T 树索引**
> 原文锚点：第 250~275 段「NDB 引擎是 MySQL 集群所使用的存储引擎…只有使用这种引擎的表，才能在集群中的各个节点中保持数据的一致性」

## 一句话总述
NDB 是 **MySQL Cluster（NDB 集群）** 专用引擎：事务型、行级锁、**只支持 READ COMMITTED**、数据需**加载到内存**才能用、索引是 **T 树**，只有它的数据能在集群节点间同步。

## 面试官视角
- **考察意图**：区分"主从复制 / MGR / NDB Cluster"三种高可用方案，这是架构题的分水岭。
- **P5** 知道 NDB 用于集群 / **P6** 能说出只支持读已提交、数据要进内存 / **P7** 能指出**只有 NDB 是节点间完全同步**，以及内存容量是它的硬伤。
- **红旗**：① 把主从复制叫成"MySQL 集群"；② 以为 InnoDB 表能在 NDB 集群节点间同步；③ 不知存储过程/视图在集群内不共享。
- **惊艳点**：只有 **NDB 集群**能做到节点间**强同步**，主从复制与 MGR 都不是 `[经验]`。验证：`SHOW ENGINES` 看有无 NDB。

## 主问答
**Q（面试官原话）：** MySQL Cluster 和主从复制有什么区别？

**A：**
1. **先给结论**：MySQL Cluster 指 **NDB 集群**，是独立于主从复制、**也不同于 5.7 的 MGR** 的另一套高可用方案；只有 **NDB 引擎**的表会在各节点间同步，InnoDB/MyISAM 的表不会。
2. **再给机制**：NDB 是事务型引擎但**只支持 READ COMMITTED** 一种隔离级别（InnoDB 支持四种）；支持**行级锁**，但性能不如 InnoDB；索引不是 B+ 树而是 **T 树**（平衡二叉树，常见于内存数据库）。
3. **最后给边界**：数据**必须全量加载进内存**才能使用（与 Memory 引擎不同——NDB 磁盘上真的存数据，重启不丢，但内存随数据量线性增长），这正是它在**高并发大数据量**场景用得少的主因；另外**存储过程、函数、视图**等定义不会在集群节点间共用。

**加分层**：普通发行版里看不到 NDB，必须安装**专门的 NDB Cluster 版本**。

| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |

## 关键代码
```sql
SHOW ENGINES;                        -- 普通发行版看不到 NDB
SHOW VARIABLES LIKE 'transaction_isolation';   -- NDB 仅 READ COMMITTED
CREATE TABLE t_ndb (id INT PRIMARY KEY) ENGINE=NDBCLUSTER;   -- 需集群版
```

## ⚠️ 原文纠错
原文关于 NDB"只支持读已提交""数据需加载内存""使用 T 树索引""只有 NDB 表能在集群节点间同步"的描述正确。原文称 MGR 是"5.7 中推出的集群"——**MGR（组复制）与 NDB Cluster 是不同机制**，且 MGR 自 **5.7.17** 起可用，卡面已区分并标注 `[经验]`。核对范围：第 250~275 段。

## 总结与追问预判
- NDB = 集群专用、**强同步**、**只支持 RC**、**吃内存**。
- 主从复制 / MGR / NDB Cluster 是三回事，别混称。
