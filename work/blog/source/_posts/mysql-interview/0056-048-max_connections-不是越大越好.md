> 分类：服务器配置 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**max_connections** / **每连接内存** / **OOM**
> 原文锚点：第 274~280 段「并不是说这个参数可以无限大或越大越好…每个连接都会占用一定的内存，设置太大会引起内存溢出，造成 MySQL 服务崩溃」

## 一句话总述
`max_connections` 决定实例允许的**最大并发连接数**；**不是越大越好**——每个连接都占内存，设太大在连接打满时会**直接 OOM 崩溃**。

## 面试官视角
- **考察意图**：这是"参数调优有没有代价意识"的试金石，几乎必问。
- **P5** 知道它控制最大连接数。
- **P6** 能说出"每个连接占内存，太大会 OOM"。
- **P7** 能给出配套打法：调 `wait_timeout` 回收空闲连接、用连接池限流、监控 `Threads_connected / Max_used_connections`。
- **红旗**：① 说"设大点更保险"；② 遇到 "too many connections" 只会继续调大该值；③ 不知道它是**全局级**变量没有会话级。
- **惊艳点**：正确姿势是**控制连接总量**而不是放大上限——配合 `wait_timeout` 与连接池，比把值调到几万靠谱 `[经验]` —— 验证：`SHOW STATUS LIKE 'Max_used_connections';` 看实际峰值再定上限。

## 主问答
**Q（面试官原话）：** 报 too many connections 了，把 max_connections 调大就行吧？

**A：**
1. **结论**：**不能只调大**——每个会话都占用一定内存，值设太大时若真被打满，实例会**内存溢出崩溃**。
2. **机制**：该参数控制服务器同时接受的连接上限；它是**全局级**变量（没有会话级），`SET GLOBAL` 后**只对新连接生效**。
3. **边界**：真正要做的是**降连接总量**——缩短 `wait_timeout` 回收空闲连接、用连接池复用、排查连接泄漏。

**加分层**：先看 `Max_used_connections` 峰值再定上限，留出余量但不要盲目放大；改完记得同步配置文件或 `SET PERSIST`。

## 关键代码
```sql
SHOW VARIABLES LIKE 'max_connections';
SHOW STATUS LIKE 'Max_used_connections';   -- 实际峰值，据此定上限
SHOW STATUS LIKE 'Threads_connected';      -- 当前连接数
SET GLOBAL max_connections = 1000;         -- 仅全局级，且只影响新连接
```

## 总结与追问预判
- `max_connections` 上限 ≠ 越大越安全，**内存是有上限的**。
- 治本靠**降连接总量**（空闲回收 + 连接池），上限看 `Max_used_connections` 峰值。
