## 一句话总述
MySQL 8.0 支持**不可见索引（Invisible Index）**：对优化器**不可见**但仍被维护；用于安全地评估「删掉某个索引会不会影响查询」，避免盲删后无法回滚。

## 面试官视角
- **考察意图**：是否懂索引生命周期管理的最佳实践。
- **P5** 知道 8.0 能标记索引不可见。
- **P6** 能说清不可见≠删除、优化器忽略但它仍维护。
- **P7** 能讲用它做索引瘦身灰度验证的完整流程。
- **红旗**：说「不可见索引就是删了」。
- **惊艳点**：点出「先 INVISIBLE 观察一段时间再 DROP，出问题秒级改回 VISIBLE」`[实测]`。

## 主问答
**Q：8.0 的不可见索引有什么用？**
**A：**
1. **结论**：不可见索引让优化器**忽略**该索引但仍持续维护，用来灰度验证「这个索引是否真被用到」，安全决定删留。
2. **机制**：标记 `INVISIBLE` 后优化器不再选它，但写入时仍更新；观察业务无慢查询回退再 `DROP`，若异常立刻改回 `VISIBLE`。
3. **边界**：全局开关 `optimizer_switch='use_invisible_indexes=on'` 可临时让所有不可见索引生效，便于排错。
**加分层**：比直接 DROP 安全，是索引瘦身的标准动作。

## 关键代码
```sql
-- 标记索引不可见（优化器不再使用，但仍维护）
ALTER TABLE orders ALTER INDEX idx_status INVISIBLE;
-- 观察无影响后删除，或异常时秒级恢复
ALTER TABLE orders ALTER INDEX idx_status VISIBLE;
```
