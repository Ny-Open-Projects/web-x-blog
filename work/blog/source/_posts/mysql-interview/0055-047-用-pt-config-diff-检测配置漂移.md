> 分类：服务器配置 | 难度：L2 | 题型：排障题 | 频率：中 | 关键词：**pt-config-diff** / **配置漂移** / **运行时 vs 配置文件**
> 原文锚点：第 254~269 段「我们可以提供连接 MySQL 的参数以及所要对比的配置文件的位置…就可以对比出系统运行时的参数信息与配置文件中配置的差异」

## 一句话总述
`pt-config-diff`（Percona Toolkit）把**运行时参数值**与**配置文件值**逐项对比，输出差异清单——这是发现"改了 `SET GLOBAL` 却忘了改配置文件"的标准手段。

## 面试官视角
- **考察意图**：问的是"怎么发现配置漂移"，考你有没有可执行的检测手段而不是"人工核对"。
- **P5** 知道运行时配置可能与配置文件不一致。
- **P6** 能说出用 `pt-config-diff` 传入连接参数与配置文件路径做对比。
- **P7** 能指出该工具**对 8.0 支持有限**（原文演示为 5.7.19 实例），8.0 应改用 `SET PERSIST` + 配置基线比对。
- **红旗**：① 只答"人工检查 my.cnf"；② 不知道差异会包含 `basedir` 这类**软链接造成的假差异**；③ 以为工具输出每一条都要处理。
- **惊艳点**：对比结果里会出现**软链接导致的假差异**（如 `basedir` 路径不同），需人工甄别 `[经验]` —— 验证：用 `realpath` 核对是否同一目录。

## 主问答
**Q（面试官原话）：** 我怎么知道现在实例跑的参数，和我配置文件里写的是不是一回事？

**A：**
1. **结论**：用 Percona Toolkit 的 **`pt-config-diff`**，传入连接参数（`-u`/`-p`/`-h`）与配置文件路径，输出不一致项。
2. **机制**：一侧取**运行时实际值**，另一侧解析**配置文件的值**，逐项比对列差异。
3. **边界**：结果**含假差异**（如 `basedir` 因软链接被判不一致）；该工具对 **8.0 支持有限**，8.0 应改用 `SET PERSIST` 与基线比对。

**加分层**：发现差异后要**统一两边**：同步改配置文件或 `SET PERSIST` 持久化。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 运行时和文件会不一致吗 | 概念 | 会，动态参数会漂移 | 换题 → 不及格 |
| L2 | 怎么检测 | 工具 | pt-config-diff | 判 P5 |
| L3 | 输出里全是真差异吗 | 甄别能力 | 有软链接造成的假差异 | 判 P6 |
| L4 | 8.0 还能用吗 | 版本边界 | 支持有限，改用 PERSIST | 判 P6+ |
| L5 | 怎么纳入日常巡检 | 工程实践 | 定期比对 + 告警 | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.6 / 5.7 | `pt-config-diff` 可用，原文演示为 5.7.19 | 老版本直接用 |

## 关键代码
```bash
# 对比运行时配置与 /etc/my.cnf 的差异（示意，未实跑）
pt-config-diff -u root -p 'xxx' -h 127.0.0.1 /etc/my.cnf
```
```sql
-- 8.0 替代方案：持久化，避免漂移
SET PERSIST max_connections = 1000;
SELECT * FROM performance_schema.persisted_variables;
```

## ⚠️ 原文纠错
原文把工具名读作"PT 杠 configure 杠 DIFF"，按上下文（Percona 提供的 MySQL 管理工具集、比对配置文件）应为 **pt-config-diff** `[存疑]`；原文"目前还并不支持 MySQL 8.0"符合该工具当时的状态，卡面已按"8.0 支持有限、改用 PERSIST"表述。机翻音译（corchernel、baseDAR）已还原为 Percona、basedir。

- 8.0 转向 `SET PERSIST` + 基线比对。
