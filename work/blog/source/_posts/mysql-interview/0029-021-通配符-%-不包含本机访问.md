> 分类：用户管理 | 难度：L2 | 题型：工程题 | 频率：中 | 关键词：**%** / **localhost** / **本机授权**
> 原文锚点：第 35~37 段「对于单独的百分号控制符来说，它并不包括从数据库服务器本地的访问授权」

## 一句话总述
`'user'@'%'` **只覆盖外部地址、不含数据库服务器本机**；要在本机连接，必须**再单独建一个 `'user'@'localhost'` 账号**。

## 面试官视角
- **考察意图**：看你是否踩过"应用部署在数据库本机却连不上"这个经典坑。
- **P5** 知道 `%` 表示任意地址。
- **P6** 能说出 `%` **不包含 localhost**，本机访问需单独授权。
- **P7** 能进一步指出本机走的是 Unix socket、与 TCP 是不同连接路径，并说明两者在权限与连接数上的差异。
- **红旗**：① 说"建了 `%` 就等于全部放开"；② 本机连不上就改用 `%` + 关防火墙（把安全问题放大）；③ 不知道 `localhost` 与 `127.0.0.1` 在 MySQL 里是**两个不同的 host**。
- **惊艳点**：`localhost` 走 Unix domain socket、`127.0.0.1` 走 TCP 回环，MySQL 把它们视为**两个不同的 host 值**，因此 `'u'@'localhost'` 授权对 `mysql -h127.0.0.1` **无效** `[经验]` —— 验证：`SHOW GRANTS` 与实际连接对比。

## 主问答
**Q（面试官原话）：** 我已经建了 `'app'@'%'` 并授了权，为什么在这台数据库服务器上用 mysql 客户端登录却连不上 / 没权限？

**A：**
1. **结论**：因为 `'app'@'%'` **不包含本机连接**，MySQL 把本机访问视为独立的 host（`localhost`），需要**单独再建一个 `'app'@'localhost'`**。
2. **机制**：`%` 通配的是"除本机外的任意来源"；本机连接还要区分 `localhost`（Unix socket）与 `127.0.0.1`（TCP 回环），两者在 `mysql.user` 里是两个独立 host 值。
3. **边界**：授权时**不写 host 会默认用 `%`**，等于对除本机外的任意来源开放——既不安全，又恰好漏掉本机，属于两头不讨好。

**加分层**：生产上不建议开 `%`（尤其不要对公网 IP 开），确需远程访问应限定网段并开启 SSL 加密链路。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | `%` 代表什么 | 概念 | 任意外部地址 | 换题 → 不及格 |
| L2 | 包不包括本机 | 关键细节 | 不包括，需单独授权 | 判 P5 |

| L5 | 远程访问怎么开才安全 | 安全判断 | 限网段 + SSL 加密链路 | 答上判 P7 |

## 关键代码
```sql
-- 正确姿势：外部网段 + 本机 分别建账号，各自最小授权
CREATE USER 'app'@'192.168.1.%' IDENTIFIED BY 'Pwd#2026a';
CREATE USER 'app'@'localhost'  IDENTIFIED BY 'Pwd#2026b';
GRANT SELECT, INSERT, UPDATE, DELETE ON appdb.* TO 'app'@'192.168.1.%';
GRANT SELECT, INSERT, UPDATE, DELETE ON appdb.* TO 'app'@'localhost';
```

## ⚠️ 原文纠错
未发现技术错误。核对范围：第 35~37 段关于 `%` 不含本机访问、需单独增加 localhost 授权的描述，与 MySQL 官方行为一致。机翻音译（logohouse、幺九二点幺六八点一）已还原为 localhost、192.168.1。

## 总结与追问预判
- `%` = 任意**外部**地址，**不含本机**；本机要另建 `'u'@'localhost'`。
- `localhost`（socket）与 `127.0.0.1`（TCP）是两个 host 值。
