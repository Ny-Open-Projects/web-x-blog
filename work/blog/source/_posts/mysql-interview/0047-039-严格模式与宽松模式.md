> 分类：服务器配置 | 难度：L3 | 题型：八股题 | 频率：高 | 关键词：**STRICT_TRANS_TABLES** / **宽松模式** / **隐式截断**
> 原文锚点：第 127~158 段「设置 STRICT_TRANS_TABLES 表示在事务性存储引擎上启用严格的数据模式，STRICT_ALL_TABLES 表示在所有存储引擎上都启用严格模式」

## 一句话总述
**严格模式**下非法/越界数据**直接报错拒绝写入**；**宽松模式**下则**隐式调整（截断或转 0）后写入并只给一条警告**——同样的 SQL，数据结果完全不同。

## 面试官视角
- **考察意图**：这是 sql_mode 里最有业务杀伤力的一组，看你是否知道"写进去的数据可能不是你以为的那个"。
- **P5** 知道严格模式会报错。
- **P6** 能对比三类场景：非法值（字符串插 INT）、超范围、超长度。
- **P7** 能说明 `STRICT_TRANS_TABLES` 与 `STRICT_ALL_TABLES` 的差别，并指出非事务引擎下部分更新已生效的尴尬。
- **红旗**：① 以为"插入成功就是数据对了"；② 不看 warning。
- **惊艳点**：宽松模式下把字符串插进 INT 列会**变成 0 并插入成功**，只给一条 warning `[实测]` —— 验证：`INSERT INTO t(id) VALUES('abc'); SHOW WARNINGS;` 结果为 0 + "Incorrect integer value"。

## 主问答
**Q（面试官原话）：** 把字符串插到 INT 列里，严格模式和宽松模式分别会怎样？

**A：**
1. **结论**：**严格模式报错拒绝写入**；**宽松模式转成 0 写入成功**，只产生一条警告。
2. **机制**：严格模式对三类情况报错——**非法值**（类型不符）、**超范围**（超过列类型上限，宽松下取边界值）、**超长度**（字符串被截断）；且**非空列必须有默认值**才能写入。
3. **边界**：`STRICT_TRANS_TABLES` 只对**事务引擎**生效，`STRICT_ALL_TABLES` 才覆盖所有引擎——后者在非事务引擎（如 MyISAM）上会出现"部分行已改、中途报错"的半成品状态。

**加分层**：生产应**开严格模式**——宽松模式的静默截断会让脏数据进库，且事后几乎无法追溯。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 严格模式是什么 | 概念 | 非法数据报错 | 换题 → 不及格 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| ≤ 5.5 | 默认**宽松**模式 | 老版本脏数据风险高 |
| 5.6 起 | 默认 `STRICT_TRANS_TABLES` | 现在默认即严格（详见 044 卡） |

## 关键代码
```sql
CREATE TABLE t (id INT NOT NULL);
SET SESSION sql_mode = 'ANSI';
INSERT INTO t(id) VALUES('abc');   -- 成功，写入 0，SHOW WARNINGS 有告警
SET SESSION sql_mode = 'STRICT_TRANS_TABLES';
INSERT INTO t(id) VALUES('abc');   -- ERROR 1366：Incorrect integer value
```

## ⚠️ 原文纠错
原文"在启用严格模式时，对于具有非空属性的列必须要有默认值，否则无法写入数据"——表述略绝对：准确说法是**严格模式下向 NOT NULL 且无默认值的列省略赋值会报错**，显式给值则不受影响，卡面已按准确语义表述。机翻音译（strengthstrength、tabinfttupdate）已还原为 STRICT、INSERT/UPDATE。

## 总结与追问预判
- 严格 = **报错拒绝**；宽松 = **隐式调整 + 仅警告**。
- 生产**开严格模式**；`STRICT_TRANS_TABLES` 只管事务引擎。
