> 分类：日志类 | 难度：L3 | 题型：工程题 | 频率：中 | 关键词：**审计日志** / **企业版** / **Percona** / **社区版替代**
> 原文锚点：第 8~11 段「如果我们使用的是 MySQL 企业版或者 Percona 版本的 MySQL，本身可以提供审计日志功能…如果仅仅使用官方社区版本，是不是就没有办法对用户操作数据库的行为进行审计了呢」

## 一句话总述
**企业版 / Percona / MariaDB** 自带审计插件；**社区版没有**审计日志，只能用**通用查询日志 + 错误日志**组合凑出可用的行为审计。

## 面试官视角
- **考察意图**：考"社区版没有的功能怎么办"——看你是两手一摊还是能给出落地替代。
- **P5** 知道社区版没有 / **P6** 提出用通用日志 / **P7** 给出完整组合并说明代价与边界。
- **红旗**：① "社区版也能开 audit_log"；② 只答"装插件"不说哪个；③ 建议长期开通用日志做审计。
- **惊艳点**：社区版审计是**拼出来的**——通用日志补"做了什么"，错误日志 `Access denied` 补"谁在试图进来" `[经验]` —— 验证：见 062、065 卡检索命令。

## 主问答
**Q（面试官原话）：** 社区版 MySQL 没有审计日志，怎么审计用户操作？

**A：**
1. **先给结论**：**企业版、Percona、MariaDB** 有审计插件；社区版没有，只能用日志组合替代。
2. **再给机制**：**通用查询日志**记录连接期间客户端发来的**全部请求**（含失败请求与连接事件），**错误日志**记录**被拒绝的登录**；合起来覆盖"做了什么"与"谁在尝试未授权访问"。
3. **最后给边界**：通用日志**量大且默认关闭**，只能短时取证，不能常驻；合规硬要求的正解是**换发行版**或加第三方审计插件。

**加分层**："短时取证"与"常驻合规审计"是两件事——后者靠日志拼不出来。

## 关键代码
```sql
-- 社区版替代方案：短时开启取证
SET GLOBAL log_output = 'TABLE';
SET GLOBAL general_log = ON;

SELECT event_time, user_host, argument
FROM mysql.general_log
WHERE user_host LIKE 'appuser%' ORDER BY event_time DESC LIMIT 50;

SET GLOBAL general_log = OFF;      -- 用完必须关
TRUNCATE TABLE mysql.general_log;  -- 并清理
```

## ⚠️ 原文纠错
原文"企业版或 Percona 版本本身可以提供审计日志功能"正确；**MariaDB 同样内置审计插件**，原文未提及，作补充。原文设问"社区版是否就没办法审计"，准确答案是"**可近似替代，但不等于合规审计**"，不能简单答"可以"。机翻音译（posinl）已还原为 Percona。

## 总结与追问预判
- 社区版**无审计日志**；替代 = 通用日志 + 错误日志。
- 只能**短时取证**，合规审计要换发行版或加插件。
