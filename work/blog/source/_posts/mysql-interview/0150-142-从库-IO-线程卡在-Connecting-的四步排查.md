> 分类：复制/排障 | 难度：L2 | 题型：事故题 | 频率：高 | 关键词：**Connecting** / **ping** / **telnet** / **账号权限**
> 原文锚点：第 113~145 段「slave 端的 IO 进程处于 connection 状态…账号是无法连接到服务器的」

## 一句话总述
IO 线程停在 **Connecting** 只有三类可能——**网络不通、端口被拦、账号/权限不对**；按顺序三步排除，最后一步看授权。

## 面试官视角
- **考察意图**：有没有"从底层往上"的排障顺序，而不是一上来就重启复制。
- **P5** 知道 `ping` / **P6** 知道再 `telnet` 测端口 / **P7** 知道最后用客户端**用复制账号实连一次**验证凭据。
- **红旗**：① 反复 `START SLAVE` 碰运气；② 只测网络不测端口；③ 忘记确认账号是否有复制权限。
- **惊艳点**：网络和端口都通、账号也能登录，**不代表有复制权限**——必须 `SHOW GRANTS` 确认 `[经验]`。

## 主问答
**Q：从库 IO 线程一直是 Connecting，你怎么查？**
**A：**
1. **先给结论**：按 **网络 → 端口 → 账号凭据 → 复制权限** 四步排，每步一个命令，不要跳。
2. **再给机制**：`ping` 验主机可达；`telnet <主库IP> 3306` 验端口是否被防火墙过滤；再用复制账号通过客户端直连主库，验用户名密码；最后 `SHOW GRANTS FOR ...` 看授权。
3. **最后给边界**：案例中网络通、端口通、账号也能登录，真实原因是**账号建了但没有任何授权**——这类问题只能靠最后一步发现。
**加分层**：修完授权后 IO 线程**不会自动重连**，必须 `STOP SLAVE; START SLAVE;` 才会重新发起连接，这一步极易漏。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | IO 线程有哪几种状态 | 概念 | Connecting/Yes/No | 换题 |
| L2 | 用什么测端口 | 工具 | telnet 或 nc | 判 P5 |
| L3 | 账号能登录不代表什么 | 边界 | 不代表有复制权限 | 判 P6 |
| L4 | 修完为什么要重启线程 | 机制 | 连接不自动重连 | 判 P6+ |
| L5 | 线上怎么预防 | 实战 | 建账号即授权并验证 | 答上判 P7 |

## 关键代码
```sql
-- 修复授权后必须重启复制线程，IO 线程才会重新发起连接
STOP SLAVE;
START SLAVE;
SHOW SLAVE STATUS\G   -- 看 Slave_IO_Running 是否变为 Yes
```
