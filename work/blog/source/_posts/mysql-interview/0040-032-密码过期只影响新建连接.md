> 分类：用户管理 | 难度：L3 | 题型：事故题 | 频率：中 | 关键词：**旧连接不受影响** / **沙箱模式** / **重连失败**
> 原文锚点：第 151~166 段「如果在设置密码过期之前你建立的连接是不受影响的，但是设置密码过期之后新建的连接就会受到影响」

## 一句话总述
密码过期是**建连时**才校验：**旧会话无感，新会话进沙箱**（只能改密码）。

## 面试官视角
- **考察意图**：给"应用 A 正常、B 全挂"的现象，看结论能否落到**连接生命周期**上。
- **P5** 知道过期会导致登录受限。
- **P6** 能说清"旧连接不受影响、新连接须重设密码"。
- **P7** 能给出处置：定位过期账号 → 确认程序能否自动续密 → 改密或关策略 → 复盘。
- **红旗**：① 认为一过期所有连接立刻断开；② 只会 `FLUSH PRIVILEGES`（无效）。
- **惊艳点**：**沙箱模式下连 `SHOW DATABASES` 都被拒**，是排障时极强的信号 `[经验]` —— 验证：新开连接执行 `SHOW DATABASES` 报 ERROR 1820。

## 主问答
**Q（面试官原话）：** 线上突然一批应用报"必须先重置密码"，另一批同账号应用却一直正常，为什么？

**A：**
1. **结论**：**密码过期只作用于新建连接**——已存在的会话不受影响，新连接必须重设密码。
2. **机制**：校验发生在**连接建立阶段**；过期新会话进入**沙箱模式**，除改密码外几乎所有语句都被拒。
3. **边界**：与权限变更一样**不回溯已有会话**；立即生效需应用重连或重建连接池。

**加分层**：根因通常不是过期本身，而是**程序不支持密码失效后自动取新密码**——开启策略前必须先验证。

## 关键代码
```sql
ALTER USER 'test'@'localhost' PASSWORD EXPIRE;
-- 旧连接：仍可 SHOW DATABASES
-- 新连接：ERROR 1820 — 必须先重置密码
SET PASSWORD = 'NewPwd#2026b';   -- 重置后恢复可用
```

## ⚠️ 原文纠错
原文"退出重连后执行 SHOW DATABASES 提示必须重新设置密码"与 MySQL 实际行为一致（ERROR 1820），未发现技术错误。补充原文未提的关键点：此时会话处于**受限沙箱**，只能执行改密码相关语句。机翻音译（localhop、ucheruser）已还原为 localhost、ALTER USER。

## 总结与追问预判
- 密码过期在**建连时**校验：**旧会话无感，新会话进沙箱**。
- 排障信号：能登录但 `SHOW DATABASES` 都被拒 → 极可能是密码过期。
