> 分类：用户管理 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**CREATE** / **ALTER** / **DROP** / **INDEX**
> 原文锚点：第 62~69 段「DDL 语句的主要作用就是建立数据库的对象…如果要想对一个表添加索引就需要 index 权限」

## 一句话总述
DDL 权限管的是**数据库对象结构**（建库建表、改表、删表、加索引），属 DBA 常用、普通应用账号**不该有**的一类权限。

## 面试官视角
- **考察意图**：看你能不能区分"改数据"与"改结构"。
- **P5** 能说出 CREATE / ALTER / DROP / INDEX 四种。
- **P6** 能说清各自作用域与"只有 CREATE 不能改表"这类组合约束。
- **P7** 能指出线上 DDL 要走审核与在线工具，应用账号根本不需要。
- **红旗**：① 认为有 CREATE 就能改表；② 把"删表重建"当常规手段。
- **惊艳点**：`CREATE` 与 `DROP` 是**两个独立权限**，"删表重建"还额外需要 `DROP` `[经验]` —— 验证：只授 `CREATE` 后执行 `DROP TABLE` 报 ERROR 1142。

## 主问答
**Q（面试官原话）：** 建表、改表、加索引分别需要什么权限？只给 CREATE 够不够？

**A：**
1. **结论**：不够。DDL 权限按动作拆开：**CREATE**（建库建表）、**ALTER**（改结构）、**DROP**（删对象）、**INDEX**（建/删索引）。
2. **机制**：只有 `CREATE` 而**没有 `ALTER`**，建出来的表无法修改结构；要"删表重建"还额外需要 `DROP`。
3. **边界**：线上大表加索引会锁表或产生大量开销，必须走审核与在线 DDL 工具，不是应用账号该有的能力。

**加分层**：DDL 不像服务器管理权限那样必须严控，但对业务账号仍应默认关闭——**应用只碰数据，不碰结构**。

## 关键代码
```sql
GRANT CREATE ON appdb.* TO 'dev'@'10.0.0.%';
-- 以 dev 身份执行下面两条都会被拒绝（ERROR 1142）
ALTER TABLE appdb.t1 ADD COLUMN c2 INT;
DROP TABLE appdb.t1;
```

## ⚠️ 原文纠错
原文"只有 create 权限而没有 alter 权限就不能修改表"表述正确。补充原文未提的事实：8.0 起 DDL 具备原子性，与 5.7 的中断残留行为不同。机翻音译（art/ut 权限）已还原为 ALTER。

## 总结与追问预判
- DDL 四件套：**CREATE / ALTER / DROP / INDEX**，缺哪个就干不了哪件事。
- 应用账号默认不给 DDL；线上 DDL 走审核与在线工具。
