> 分类：服务器配置 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**sql_mode** / **SQL 行为** / **数据校验严格度**
> 原文锚点：第 39~58 段「sql_mode 的主要作用就是配置 MySQL 所执行的 SQL 语句的语法…以及应该在数据上执行何种的合规性检查」

## 一句话总述
`sql_mode` 决定 **MySQL 如何解释 SQL 语法**与**如何校验数据**：同一个语句在不同 sql_mode 下可能一个报错、一个静默成功，是"配置类问题伪装成 SQL 问题"的根源。

## 面试官视角
- **考察意图**：看你是否意识到**配置能改变 SQL 语义**，而不只会查语法。
- **P5** 知道 `sql_mode` 影响 SQL 行为。
- **P6** 能说出两类作用：语法行为（如是否要求完整 GROUP BY）+ 数据校验严格度。
- **P7** 能说出设置方式的三条路径（session / global / 配置文件），并强调 8.0 用 `SET PERSIST` 防丢失。
- **红旗**：① 认为"SQL 结果不对一定是 SQL 写错了"；② 只会 `SET GLOBAL` 却不同步配置文件。
- **惊艳点**：多个值用**逗号拼接**同时生效，且 8.0 默认 `sql_mode` 已包含 `ONLY_FULL_GROUP_BY` 与 `STRICT_TRANS_TABLES` `[经验]` —— 验证：`SELECT @@sql_mode;` 看默认值。

## 主问答
**Q（面试官原话）：** 一条 SQL 在 SQL Server 里报错、在 MySQL 里却能跑出奇怪结果，为什么？

**A：**
1. **结论**：多半是 **`sql_mode` 不同**——它控制 MySQL 的 SQL 语法解释与数据校验行为，不是语法本身的问题。
2. **机制**：`sql_mode` 管两类事：① **语法行为**（如 GROUP BY 是否必须完整）；② **数据合规检查**（如是否允许零日期、非法值是否截断）。
3. **边界**：它是**动态变量**，可 `SET SESSION` / `SET GLOBAL` 改，也可写进配置文件；多个值用**逗号分隔**叠加生效。

**加分层**：`SET GLOBAL` 改的值**重启即丢**，8.0 应用 `SET PERSIST`（详见 016 卡），否则下次重启问题复现。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.6 | 默认变为 `STRICT_TRANS_TABLES,NO_ENGINE_SUBSTITUTION` | 按"5.6 起默认严格"答 |
| 5.7 / 8.0 | 默认增加 `ONLY_FULL_GROUP_BY`、`NO_ZERO_*`、`ERROR_FOR_DIVISION_BY_ZERO` | 现在要按 8.0 默认集答（详见 044 卡） |

## 关键代码
```sql
SELECT @@session.sql_mode, @@global.sql_mode;
SET SESSION sql_mode = 'ONLY_FULL_GROUP_BY,STRICT_TRANS_TABLES';
-- 8.0：持久化，重启不丢
SET PERSIST sql_mode = 'ONLY_FULL_GROUP_BY,STRICT_TRANS_TABLES';
```

- `sql_mode` = **语法行为 + 数据校验**的总开关；多值逗号叠加。
- 排查"SQL 结果怪异"时**先查 sql_mode**。
