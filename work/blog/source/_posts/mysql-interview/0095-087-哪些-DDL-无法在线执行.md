> 分类：存储引擎 | 难度：L3 | 题型：工程题 | 频率：高 | 关键词：**Online DDL** / **全文索引** / **删除主键** / **改字段类型** / **元数据锁**
> 原文锚点：第 290~310 段「我们再来看看 InnoDB 在什么情况下不支持在线对表结构进行修改」

## 一句话总述
五类 DDL **无法在线执行**：**首次建全文/空间索引、删主键、加自增列、改列类型、改字符集**；且 DDL 需拿**元数据锁**，同表不能并发、长事务会堵塞。

## 面试官视角
- **考察意图**：大表 DDL 锁表是典型事故，看你会不会先判"能不能在线"。
- **P5** 知道有在线 DDL / **P6** 能列出不支持的场景 / **P7** 会补上**元数据锁**与**主从延迟**风险。
- **红旗**：① 以为所有 DDL 都在线；② 不知同表 DDL 不能并发；③ 忽略长事务会阻塞 DDL。
- **惊艳点**：**同表 DDL 无法并发**，一个挂起的 ALTER 会让后续排队 `[实测]`。验证：两会话对同表 ALTER，看第二个是否等待。

## 主问答
**Q（面试官原话）：** 加索引会锁表吗？什么情况一定锁？

**A：**
1. **先给结论**：普通加索引 5.6 起基本可在线；这五类不行——**首次建全文/空间索引**（要加隐藏列、重建表）、**删主键**（数据重排）、**加自增列**（自增列须属主键）、**改列类型**（逐行校验）、**改字符集**。
2. **再给机制**：前三类触发表重建或数据重排，无法"边改边服务"；改类型与字符集要对**所有行校验**，只能离线做。
3. **最后给边界**：能在线的也要先拿**元数据锁**——**同表 DDL 不能并发**、**长事务**持锁会堵住 DDL；主库跑很久的 DDL 会造成**从库长延迟**；DDL 无法限 CPU/IO 且需**临时空间**，大表易因临时目录不足失败。

**加分层**：第二次在同一表上建全文/空间索引**就能在线**——隐藏列已存在，不必重建表。

## 版本与兼容性

## 关键代码
```sql
ALTER TABLE stock ADD INDEX idx_c1 (c1), ALGORITHM=INPLACE, LOCK=NONE;  -- 显式声明，不行会直接报错
ALTER TABLE stock MODIFY c1 INT;            -- 改类型：需复制表，无法在线
ALTER TABLE stock DROP PRIMARY KEY;         -- 删主键：数据重排，无法在线
SHOW PROCESSLIST;                           -- 排查 DDL 是否被长事务阻塞
```

## ⚠️ 原文纠错
原文列出的限制（首次全文/空间索引、删主键、加自增列、改列类型、改字符集）与官方文档一致；原文提到"对同表的 DDL 不能并发执行、长事务会阻塞 DDL"，这正是**元数据锁（MDL）** 的表现，卡面已规范命名。原文未提 8.0.12 的 INSTANT DDL，卡面补充并标 `[经验]`。核对范围：第 290~320 段。

## 总结与追问预判
- 五类 DDL 必离线；其余也要防 **MDL 阻塞**与**主从延迟**。
- 用 `ALGORITHM=INPLACE, LOCK=NONE` 显式声明，让风险在**执行前**暴露。
