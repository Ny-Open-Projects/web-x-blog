> 分类：复制/GTID | 难度：L4 | 题型：事故题 | 频率：中 | 关键词：**gtid_next** / **空事务** / **AUTOMATIC** / **丢数据风险**
> 原文锚点：第 162~186 段「如果使用 GTID 复制，想跳过这个故障的错误，只能使用注入空事务的方法」

## 一句话总述
GTID 复制下跳过错误的唯一手段是：**手动指定 gtid_next 为该事务号 → 提交一个空事务 → 改回 AUTOMATIC → 重启复制**，代价是该事务的数据修改在从库丢失。

## 面试官视角
- **考察意图**：知不知道 GTID 模式下跳过计数器失效，以及这套"占位"操作的完整顺序。
- **P5** 知道要注入空事务 / **P6** 能背出五步 / **P7** 能说出"漏掉改回 AUTOMATIC 会怎样"与丢数据补救。
- **红旗**：① GTID 下还说用跳过计数器；② 忘记改回 `AUTOMATIC`；③ 注入完不校验。
- **惊艳点**：忘记把 `gtid_next` 改回 **AUTOMATIC**，后续所有事务都会被卡在这一个 GTID 上，复制直接停摆 `[经验]`。

## 主问答
**Q：GTID 复制下从库报错，怎么跳过这一个事务？**
**A：**
1. **先给结论**：五步——`STOP SLAVE` → `SET gtid_next='<uuid>:<n>'` → `BEGIN; COMMIT;` → `SET gtid_next='AUTOMATIC'` → `START SLAVE`。
2. **再给机制**：提交空事务是给这个 GTID **占位**，让从库认为它已执行，从而跳过真实回放；GTID 模式下跳过计数器不可用，这是唯一办法 `[经验]`。
3. **最后给边界**：**该事务的数据修改在从库永久缺失**，所以注入后必须用校验工具比对并用同步工具修复，否则就是"复制正常但数据不一致"。
**加分层**：事务号要从已接收但未执行的 GTID 集合里取（已接收到 19 却只执行到 18，就跳 19），取错了会跳掉不该跳的事务。

## 关键代码
```sql
STOP SLAVE;
SET gtid_next = 'da474...:19';   -- 要跳过的那个事务号
BEGIN; COMMIT;                   -- 提交空事务占位
SET gtid_next = 'AUTOMATIC';     -- 关键：必须改回
START SLAVE;
```

## ⚠️ 原文纠错
原文把跳过计数器与注入空事务并列为可选项，表述不够准确：**GTID 模式下跳过计数器会被拒绝**，只能用注入空事务。机翻中的变量名与事务号音译已还原为 `gtid_next` / `AUTOMATIC`。

## 总结与追问预判
- 五步缺一不可，尤其"改回 AUTOMATIC"；跳过后必补校验。
