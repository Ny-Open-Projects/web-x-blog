## 一句话总述
MySQL 8.0 引入**角色（Role）**：把一组权限授予角色，再把角色授予用户，避免逐用户授权；是权限管理的标准化手段，类似其他关系库早有的 RBAC。

## 面试官视角
- **考察意图**：是否了解 8.0 权限模型的改进。
- **P5** 知道 8.0 有角色。
- **P6** 能说出「角色→用户」的授权链路。
- **P7** 能讲生产如何用角色做最小权限与离职回收。
- **红旗**：说「角色就是用户别名」。
- **惊艳点**：点出角色可 `SET DEFAULT ROLE` 控制登录生效，且 `mandatory_roles` 强制挂载 `[源码]`。

## 主问答
**Q：MySQL 8.0 的角色有什么用？**
**A：**
1. **结论**：角色是**权限的集合**，把权限授权给角色、再把角色授予用户，简化批量权限管理。
2. **机制**：`CREATE ROLE` 建角色 → `GRANT privs TO role` → `GRANT role TO user`；用户登录默认角色由 `SET DEFAULT ROLE` 决定。
3. **边界**：角色不等同用户，本身不可登录；可配置 `mandatory_roles` 让所有用户强制继承某角色（如审计只读）。
**加分层**：用角色实现最小权限 + 一键回收，合规友好。

## 关键代码
```sql
CREATE ROLE 'app_ro', 'app_rw';
GRANT SELECT ON app_db.* TO 'app_ro';
GRANT 'app_ro','app_rw' TO 'dev'@'%';
SET DEFAULT ROLE ALL TO 'dev'@'%';
```
