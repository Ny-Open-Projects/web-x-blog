## 纲要

- **MySQL8**：建目录 `/home/docker/mysql`（log/data/conf/mysql-files）→ 改密码**别用 root** → 端口改 **5506**（非 3306）→ 安全组放通 5506 → 部署 → Navicat 连公网 IP:5506 → 建库（utf8mb4_0900_ai_ci） → 本地表「结构和数据」拖到云库。
- **Redis Stack**：密码改非 123456 → 端口 **9379**（非 6379）→ 安全组放通 → RDM 连接测试 → 测完改回拒绝降风险。
- **SearXNG**：端口 **6080**（非 8080）→ 安全组放通 → 浏览器访问改中文 + 启用搜狗/百度/bing/360 引擎 → 测试搜索。
- **通用铁律**：云服务器最易被攻击端口 = 6379、3306、22；**默认端口一律改掉 + 强密码 + 安全组最小开放**。
- **生产化（本节新增）**：用一份 `docker-compose.yml` 一次性编排三中间件 + 真实 `my.cnf` / SearXNG `settings.yml` 配置，替代手工 `docker run`。

> 本章代码基于课程标准工程（`com.itzixi` 包）按课程口径重构，外部代码卷暂未挂载，重挂后可切换为逐文件提取的真实代码。下列 compose / 配置为可独立落地的标准写法。

## 一、Docker 安装 MySQL8 与数据迁移

### 1.1 建目录 + 改配置

```bash
cd /home && mkdir -p docker/mysql
cd docker/mysql
mkdir -p log data conf mysql-files     # 日志/数据/配置/文件目录
pwd                                    # 记下绝对路径
```

`docker run` 命令关键修改点（对照文档模板）：
- 四个路径映射（log/data/conf/mysql-files）替换为上述真实路径
- **密码**：绝不用 `root`，改成强密码（课程用 `fenjianyingyuan` 示例）
- **端口**：`-p 5506:3306`（对外 5506，容器内 3306）

### 1.2 拉取 + 运行 + 安全组

```bash
docker pull mysql:8.0          # 约 859MB，带宽高下载快
docker run -d ... -p 5506:3306 -e MYSQL_ROOT_PASSWORD=强密码 ... mysql:8.0
docker ps                      # 看到 mysql 容器 UP
```

> 云控制台 → 安全组 → 编辑规则，把 3306 改成 **5506** 放通（或新增一行 `TCP:5506` 允许）。

### 1.3 Navicat 连接 + 建库 + 迁表

1. Navicat 新建 MySQL 连接：主机=公网 IP、端口 **5506**、密码=强密码 → 连接测试成功。
2. 新建数据库：名同本地库、`utf8mb4` + 排序规则 `utf8mb4_0900_ai_ci`（与本地一致）。
3. 本地表右键 → 数据传输/复制 → 选「结构和数据」→ 导入到云库。

## 二、Docker 安装 Redis Stack

```bash
docker pull redis/redis-stack:latest
docker run -d -p 9379:6379 -e REDIS_ARGS="--requirepass 强密码" redis/redis-stack
docker ps                      # redis-stack UP
```

- **端口 9379**（非 6379）；**密码非 123456**。
- RDM 新建连接：地址=公网 IP、端口 **9379**、密码=强密码 → 测试（不通先去安全组放通 9379）。
- ⚠️ 老师强调：测试完就把安全组 9379 改回**拒绝**，Redis 极易被攻击。
- ⚠️ **重启后公网 IP 变**：所有本地客户端（RDM/Navicat）host 要改成新 IP。

## 三、Docker 安装 SearXNG

```bash
docker pull searxng/searxng
mkdir -p /home/docker/searxng   # 映射 volumes 本地路径
docker run -d -p 6080:8080 --name searxng searxng/searxng
docker ps                      # 6080 端口启用
```

- **端口 6080**（非 8080，生产绝不用 8080）。
- 安全组新增 `TCP:6080` 允许（来源 `0.0.0.0/0` 即任意 IP 可访问）。
- 浏览器访问 `http://公网IP:6080` → 首选项改**中文** → 保存 → 搜索引擎**禁用全部后单独启用**搜狗/百度/bing/360。
- 测试搜索（中英文均可）。

## 四、生产化：一份 docker-compose 编排三中间件（新增）

手工 `docker run` 参数多易错，生产推荐用 `docker-compose.yml` 一次性编排，密码走 `.env` 不进仓库。

```yaml
# /home/docker/docker-compose.yml
version: "3.8"

services:
  mysql:
    image: mysql:8.0
    container_name: mysql80
    restart: always
    ports:
      - "5506:3306"                       # 对外非标端口
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_PWD}    # 从 .env 读，勿硬编码
      TZ: Asia/Shanghai
    volumes:
      - ./mysql/data:/var/lib/mysql
      - ./mysql/conf:/etc/mysql/conf.d
      - ./mysql/log:/var/log/mysql
      - ./mysql/mysql-files:/var/lib/mysql-files
    command: --default-authentication-plugin=mysql_native_password

  redis-stack:
    image: redis/redis-stack:latest
    container_name: redis-stack
    restart: always
    ports:
      - "9379:6379"
    environment:
      REDIS_ARGS: "--requirepass ${REDIS_PWD}"

  searxng:
    image: searxng/searxng:latest
    container_name: searxng
    restart: always
    ports:
      - "6080:8080"
    volumes:
      - ./searxng:/etc/searxng           # 持久化 settings.yml
    environment:
      - SEARXNG_BASE_URL=http://0.0.0.0:8080/
```

```bash
# .env（与 compose 同目录，加入 .gitignore）
MYSQL_PWD=你的强密码
REDIS_PWD=你的强密码

# 启动 / 停止
docker compose up -d
docker compose ps
docker compose down
```

> 用 compose 的好处：端口/卷/密码集中管理、可复现、回滚简单；配合 `.env` 把密钥移出仓库。

### 4.1 MySQL 自定义配置 my.cnf（conf.d 下）

```ini
# /home/docker/mysql/conf/my.cnf
[mysqld]
character-set-server = utf8mb4
collation-server     = utf8mb4_0900_ai_ci
default-time-zone    = '+08:00'
max_connections      = 500
slow_query_log      = ON
long_query_time      = 2
```

### 4.2 SearXNG 关键 settings.yml

```yaml
# /home/docker/searxng/settings.yml（节选）
general:
  instance_name: "my-searxng"
  language: "zh"
search:
  default_language: "zh"
  engines:
    - name: baidu
      engine: baidu
    - name: bing
      engine: bing
    - name: sogou
      engine: sogou
    - name: 360
      engine: 360so
```

## 六、排错 SOP

1. **Navicat/RDM 连超时**：安全组未放通对应端口（5506/9379/6080）；先放通再测。
2. **MySQL 连上但库表空**：只建了库没迁表；本地表「结构和数据」传输到云库。
3. **Redis 被改/中招**：用了 6379 或弱密码；改 9379 + 强密码 + 测完安全组拒。
4. **SearXNG 保存跳 localhost**：它默认 8080，保存后显示回本地；确认访问地址用 `公网IP:6080`。
5. **重启后连接全失效**：公网 IP 漂移，更新所有客户端 host。
6. **docker run / compose 端口冲突**：改宿主机映射端口（如 5506 已占则换 5516）；compose 改 `ports` 左值。
7. **compose 起不来**：`.env` 是否存在且变量名一致；`docker compose logs <svc>` 看报错。

## 七、FAQ

**Q1：为什么不用默认端口 3306/6379/8080？**
这些是扫描器重点照顾端口，云上裸奔几小时被攻破/勒索；改非标端口是第一道防线。

**Q2：云上数据库密码怎么设？**
绝不用 root/123456；用强密码，且别硬编码进可公开仓库，走 `.env` / 配置中心。

**Q3：MySQL 数据怎么从本地迁云？**
Navicat 选本地表 → 数据传输「结构和数据」→ 目标选云库连接。

**Q4：Redis Stack 和传统 Redis 区别？**
Redis Stack 带 RediSearch/向量等模块，课程用于向量库；部署方式一样，注意端口/密码。

**Q5：SearXNG 搜索引擎怎么配？**
首选项禁用全部、再单独启用搜狗/百度/bing/360 等，避免默认引擎不可用。

**Q6：测试完为什么要回收端口？**
安全组开着即暴露面；不用时改回拒绝，降低被扫描攻击风险。

**Q7：compose 与 docker run 怎么选？**
单容器临时验证用 `docker run`；多容器/生产用 `docker-compose.yml` 集中管理与复现。

## 八、面试高频问答

**1. 容器化部署 MySQL 的关键安全点？**
改默认端口、强 root 密码、数据目录卷映射持久化、安全组最小开放、备份策略、`my.cnf` 字符集时区。

**2. Docker 数据持久化怎么做？**
`-v 宿主机目录:容器目录` 映射（如 mysql 的 data），容器删数据不丢；compose 用 `volumes`。

**3. 云安全组与端口安全关系？**
安全组是防火墙，默认拒绝；即使服务监听默认端口，未放通也不可达；但仍建议改非标端口减少扫描。

**4. Redis 为何易被攻击？**
默认无密码 + 6379 闻名，暴露在公网会被植入挖矿/勒索；必须密码 + 非标端口 + 绑内网/安全组。

**5. SearXNG 作用？**
自托管元搜索引擎，聚合百度/bing 等结果，课程用于大模型联网搜索后端。

**6. 容器重启 IP 变化如何处理？**
云弹性公网 IP 会漂移；生产用 EIP 绑定固定，或内部服务用内网 IP 通信不受公网漂移影响。

**7. 密钥如何不进仓库？**
用 `.env`（gitignore）+ 配置中心/Secret 管理，compose 中 `${VAR}` 引用。

## 九、ops 提示（安全与网络）

> **强密码硬要求**：云上 root/123456 几小时被攻破中勒索；三中间件统一强密码，且别复用。
>
> **默认端口改造清单**：MySQL 3306→5506、Redis 6379→9379、SearXNG 8080→6080、SSH 22 也建议改。
>
> **安全组最小开放**：仅放通必要端口，测试完立即回收（老师反复强调 Redis/MySQL 测完改拒绝）。
>
> **公网 IP 漂移**：按量/弹性场景 IP 会变，客户端连接要同步更新；生产优先 EIP 固定。
>
> **数据备份**：MySQL 迁表后定期 `mysqldump` 备份到对象存储；容器删了数据卷别误删。
>
> **compose 密钥**：`.env` 务必加 `.gitignore`，避免强密码进公开仓库。
