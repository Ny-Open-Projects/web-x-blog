# Go 项目开发: 服务隔离下解决数据同步--项目环境配置及整体介绍

服务间通信无非几条路：**RPC、HTTP、消息队列**。本节解决的是**商城服务与搜索服务之间的数据同步**，走的是消息队列这条路 —— 商品变更（上架、下架、修改、删除）由商城主服务产生事件丢进 Kafka，下游搜索侧消费后再写索引。数据不直连、服务不耦合，这就是服务隔离。

本节先把**环境、目录、依赖版本**铺平，避免后面写代码时卡在环境上。

## 纲要

- 数据同步的整体链路：商品变更 → Kafka → 搜索侧消费
- 商城系统的技术栈与版本要求
- Go 环境三件套：GO111MODULE、GOPROXY、GOPRIVATE
- IDE 里怎么配，以及为什么必须配 GOPRIVATE
- 数据库导入与 config.yaml 的关键项
- 前后端启动流程
- 后端目录结构与 viper + mapstructure 的关系
- sarama 的版本坑：ZSTD 与 cgo

## 整体链路

```txt
商品变更（上架 / 下架 / 修改 / 删除）
        │
        ▼
  商城主服务（supermain）
        │  同步发送
        ▼
      Kafka
        │   consumer group
        ▼
  商品消费服务（productconsumer）
        │
        ▼
       ES 索引
```

关键点：**主服务只管发消息，不关心谁消费、什么时候消费**。搜索侧挂了、慢了，不影响交易主链路 —— 这就是隔离带来的收益。

## 技术栈与版本要求

商城系统是一个前后端分离的电商管理后台：

| 层 | 技术 |
| --- | --- |
| 后端 | Gin + GORM + Casbin + JWT + Redis + MySQL 5.7 |
| 前端 | Vue |
| 权限 | RBAC |
| 语言 | Go ≥ 1.15 |

环境硬要求：**Go ≥ 1.15、MySQL > 5.7、ES ≥ 7.0**。

## Go 环境三件套

```txt
# 开启 go module
go env -w GO111MODULE=on

# 配代理（国内拉包用）
go env -w GOPROXY=https://goproxy.cn

# 配私有仓库：从 gitee 拉代码时不走代理
go env -w GOPRIVATE=gitee.com
```

`GOPRIVATE` 容易被忽略，但它决定了**私有仓库的请求是否会走代理**。不配的话，`go get` 私有库时会绕去 goproxy 找，直接 404。

## IDE 里怎么配

IDE 方式更常用（File → Settings → Go → Go Module）：

1. 勾选 **Enable Go modules**；
2. 环境变量里加 `GOPROXY=https://goproxy.cn`；
3. 再加一个 `GOPRIVATE`，值用通配域名 `gitee.com`；
4. Apply 完在终端 `go env` 里确认三项都生效。

## 数据库导入与配置修改

商城主程序工程的 `circle` 目录下有一个 `shop.sql`，**里面是主程序用到的全部建表语句**。

```txt
# 1. 先建 shop 库，再把 shop.sql 导进去
右键 → Run SQL Script → 选择 supermain/circle/shop.sql

# 2. 改配置：config/config.yaml
#    把 DB、Redis、Kafka 的组件地址换成你本机的
database:
  host: 127.0.0.1:3306
  user: root
  password: xxx
  name: shop
redis:
  host: 127.0.0.1:6379
  password: ""
  idle_timeout: 100
  read_timeout: 10
kafka:
  hosts:
    - 127.0.0.1:9092
  sync_producer: default_kafka_sync_producer
```

这份 yaml 是后面所有初始化的唯一数据源：**改地址只改这个文件，代码里不写死**。

## 后端目录结构

```txt
supermain/
├── config/          # 公共配置：config.yaml + config.go（配置映射结构体）
├── controllers/     # 控制器，分前端 / 后端两套
├── middleware/      # gin 中间件：接口鉴权、跨域
├── models/          # 模型，与表结构一一对应
├── netser/          # Redis 监听
├── pkg/             # 应用内部包：base(日志)、cache、db、mq
│   ├── base/        # setupLog 初始化日志
│   ├── cache/       # Redis 封装
│   ├── db/          # MySQL 封装
│   └── mq/          # Kafka 封装
├── router/          # 全部 API 接口定义（router.go）
└── runtime/         # 上传目录 + 日志目录
```

`config.go` 里用 **viper 读 yaml**，映射成结构体。这里有个高频坑：

> **结构体字段必须打 `mapstructure` 标签，且标签名要和 yaml 里的 key 对上。**

```go
package main

// 正确：mapstructure 的 key 必须与 config.yaml 的键一一对应
type Config struct {
	Database struct {
		Host     string `mapstructure:"host"`
		User     string `mapstructure:"user"`
		Password string `mapstructure:"password"`
		Name     string `mapstructure:"name"`
	} `mapstructure:"database"`
}

// 实际项目里这份配置挂在全局：global.GCONFIG
func main() {}
```

标签名和 yaml 键对不上时**不报错，只是静默填零值** —— 这个坑排查起来最费时间。

## 怎么从页面反查代码

改一个商品保存，抓到请求地址 `shop/product/info/save`：

```txt
1. 去 router/router.go 搜 save，找到 group = shop + 路径 product/.../save
2. 顺着找到 ProductController 的 Post 方法
3. 业务逻辑就在这个方法里
```

以后调试任何接口，都是这条路径：接口路径 → router 定义 → controller → service。

## sarama 的版本坑

Kafka 依赖第三方包 sarama，**选版本有讲究**：

- sarama **1.2 之后引入了 ZSTD 压缩算法**，依赖 cgo；
- **Windows 平台编译会直接报错**；
- 规避办法：**开发环境用 sarama v1.19**，等上线跑 Linux 时再换高版本。

```txt
# 开发环境（Windows）
require github.com/IBM/sarama v1.19.0

# 生产环境（Linux）
require github.com/IBM/sarama v1.19.0+   # 可升到更高版本
```

商城主服务和下游的 `productconsumer` 都要锁这个版本，两边不一致容易出诡异的序列化问题。

## 注意事项总结

1. **数据同步走消息队列**，主服务只发不关心消费方，这是服务隔离的核心。
2. **Go ≥ 1.15、MySQL > 5.7、ES ≥ 7.0** 是硬门槛。
3. **`GO111MODULE=on` + `GOPROXY` + `GOPRIVATE`** 三件套，少一个都拉不到包。
4. **`GOPRIVATE` 用通配域名**，否则私有仓库请求会走代理然后 404。
5. **建表用 `shop.sql`，配置改 `config.yaml`**，代码里不写死任何地址。
6. **viper 解析靠 `mapstructure` 标签**，标签名与 yaml 键对不上是静默失败，必须逐项核对。
7. **sarama 锁 1.19**，Windows 下 ZSTD 依赖 cgo 会编译失败；Linux 生产再升版。
8. **接口反查路径**：路径 → router → controller → service，是调试的固定路线。

## 总结

数据同步走消息队列，是商城服务与搜索服务解耦的核心：**主服务只管发商品变更事件，不关心谁消费、什么时候消费**。这样搜索侧挂了、慢了，都影响不到交易主链路。

工程落地上，先把环境、目录、依赖版本铺平——Go ≥ 1.15、MySQL > 5.7、ES ≥ 7.0 是硬门槛，`GO111MODULE / GOPROXY / GOPRIVATE` 三件套少一个都拉不到包；viper 解析靠 `mapstructure` 标签，标签名对不上会静默填零值；Kafka 依赖的 sarama 在 Windows 下要锁 1.19 避开 ZSTD 的 cgo 编译坑。把这些地基打牢，后面写代码才不会卡在环境上。
