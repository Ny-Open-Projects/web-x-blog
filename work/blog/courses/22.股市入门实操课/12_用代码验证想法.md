# 第 12 章 用代码验证想法（可选）

> 本章写给有编程基础的人。
> 核心不是教你会写回测，而是教你**知道回测有多容易骗自己**。
> 完全不懂代码可以跳过——但第 12.3 节（三个陷阱）建议读一下，它和第 9 章的认知偏差是同一个东西的不同表现。

## 12.1 为什么程序员更容易在股市亏钱

先说一个反直觉的观察，再说正事。

程序员做量化有一个天然优势和三个天然劣势。

**优势**：你有能力把想法变成可验证的代码，而不是停在"我感觉"。

**劣势一：过度拟合的诱惑太大。**

写代码的人喜欢"调参调到最优"。你会自然地想：把均线周期从 20 调到 19 会不会更好？从 19 调到 18 呢？

**这就是过拟合的开始。**

**劣势二：把回测当成证明。**

代码跑出来一条漂亮的资金曲线，你会觉得"这个策略有效"。但回测是一条**已经被你反复调整过的**曲线，它证明的是"你的参数能拟合历史"，不是"你的策略能赚钱"。

**劣势三：低估执行摩擦。**

代码里 `order(order=100)` 一行就成交了。现实里你要面对：T+1、涨跌停买不进、停牌、成交价滑点、佣金 5 元。

**这三个劣势加起来，会让一个技术很强的程序员，做出一个回测年化 60%、实盘年化 -20% 的系统。**

## 12.2 回测能告诉你什么，不能告诉你什么

| 能做 | 不能做 |
|---|---|
| 快速排除明显无效的想法 | 证明策略未来会盈利 |
| 量化一个想法的历史表现 | 反映真实的成交摩擦 |
| 发现"我这个想法在 2015 年就崩了" | 预测未来的市场结构 |
| 训练你不靠感觉做判断 | 告诉你该下多少仓位 |

**最重要的那句**：

> **回测的作用是"证伪"，不是"证实"。**
>
> 一个好的回测结果只有一个含义：**这个想法在历史上没被证伪**。它不等于有效。

## 12.3 三个会让回测撒谎的陷阱

### 陷阱一：过拟合（Overfitting）

**现象**：你把均线周期从 5 试到 200，发现 37 日均线在 2019–2023 年表现最好，年化 28%。

**问题**：37 这个数字没有任何经济含义。它是**你从历史数据里挖出来的噪音**。

```
你试了 196 个参数 → 其中必然有几个"看起来很好"
这不是策略有效，这是数学必然
```

**如何识别**：

| 信号 | 说明 |
|---|---|
| 参数是一个奇怪的非整数（37、83、147） | 强烈暗示过拟合 |
| 参数微小变动，结果剧烈变化 | 参数不稳定 |
| 只在特定区间表现好 | 拟合了特定行情 |
| 换一个市场/时段就失效 | 无普适性 |

**如何缓解**：

- **样本外测试**：用 2010–2020 调参，用 2021–2026 验证。后者不许再调。
- **参数平原**：不要选"最优点"，选"最优区域"。如果 35–40 都能到 25% 以上，说明这个区间稳健。
- **少调参**：参数越少越抗过拟合。用 3 个参数比用 10 个好。

### 陷阱二：前视偏差（Look-ahead Bias）

**现象**：你的策略用"当日收盘价"决定是否买入，并用"当日收盘价"成交。

**问题**：你在收盘那一刻才知道收盘价，怎么可能在收盘价成交？

```
错误写法：
if close_price > ma20:
    buy(price=close_price)     # 用了当天收盘价，但决策也是基于它
```

**真实世界**：你看到收盘价时是 15:00，只能第二天开盘买。

**正确写法**：
```
用 T 日收盘数据做决策 → T+1 日开盘价成交
```

**更隐蔽的前视偏差**：

- 用了"调整后价格"但没注意复权时点
- 用了当季财报，但财报公布有滞后（Q1 财报可能 4 月底才出）
- 用了"今天的行业分类"，但十年前的分类不同

**如何识别**：问自己一句话——**"这个数据在那一刻，我拿得到吗？"**

### 陷阱三：幸存者偏差（Survivorship Bias）

**现象**：你用"当前沪深300 成分股"回溯十年。

**问题**：今天的成分股，是**十年来表现好的那些**。已经被剔除的（表现差的、退市的）不在你的样本里。

```
你今天看到的 300 只 = 十年筛选后的赢家
用它们回测十年 = 你提前知道了答案
```

**正确的数据池**：必须用**历史上的成分股名单**（point-in-time），而不是当前的。

**这就是为什么免费数据常常不可靠**：多数免费数据只提供当前成分股。

### 陷阱四：忽略成本

**现象**：回测里每次交易零成本，年化 22%。

**问题**：加上每次 0.12% 的成本（佣金+滑点），一年做 30 次交易 → 扣掉 3.6%，变成 18.4%。

**如果策略本身只有 8%**，扣完成本就只剩 4.4%——跑输买入持有。

**回测里必须加的三项**：

```python
commission = 0.0003      # 佣金万3
min_commission = 5       # 最低 5 元（小资金必加！）
slippage = 0.001         # 滑点 0.1%
stamp_tax = 0.0005       # 印花税（卖出，ETF 为 0）
```

**这四项里，`min_commission = 5` 对 1000 元本金是致命的**——它会让你的回测收益直接砍半。

## 12.4 RQAlpha 上手

RQAlpha 是米筐开源的回测框架，专门支持 A 股，是入门最合适的选择。

### 安装

```bash
pip install rqalpha
rqalpha update_bundle    # 下载历史数据（约几百 MB，需要一段时间）
```

**注意**：`update_bundle` 需要联网下载，首次执行较慢。如果失败，检查是否需要注册米筐账号（部分数据包需要）。

### 最小可运行示例

```python
from rqalpha.api import *
from rqalpha import run_func

def init(context):
    """策略初始化，只在回测开始时执行一次"""
    context.s1 = "510300.XSHG"      # 沪深300ETF
    context.ma_short = 20
    context.ma_long = 60
    subscribe(context.s1)

def handle_bar(context, bar_dict):
    """每个交易日执行一次"""
    # 取历史收盘价
    prices = history_bars(context.s1, context.ma_long, '1d', 'close')
    if len(prices) < context.ma_long:
        return

    ma_s = prices[-context.ma_short:].mean()
    ma_l = prices[-context.ma_long:].mean()

    # 当前持仓
    pos = context.portfolio.positions[context.s1].quantity

    if ma_s > ma_l and pos == 0:
        # 金叉且空仓 → 买入
        order_target_percent(context.s1, 0.9)
    elif ma_s < ma_l and pos > 0:
        # 死叉且持仓 → 清仓
        order_target_percent(context.s1, 0)

config = {
    "base": {
        "start_date": "2020-01-01",
        "end_date": "2026-11-01",
        "accounts": {"stock": 1000},        # 1000 元本金
        "benchmark": "000300.XSHG",
    },
    "mod": {
        "sys_analyser": {"enabled": True},
        "sys_transaction_cost": {
            "enabled": True,
            "commission_multiplier": 1.0,
        },
    },
}

run_func(config=config, init=init, handle_bar=handle_bar)
```

> **免责**：RQAlpha 的 API 在不同版本间有变动（`history_bars` 的签名、`order_target_percent` 的可用性等）。上面是 4.x 的结构示意，**跑之前请对照你安装版本的官方文档**。跑不通是正常的，改到能跑是这一章的第一课。

### 你应该跑一遍这个策略，然后失望

这个双均线策略跑 2020–2026 的结果，大概率是：

```
总收益：略低于或接近买入持有
最大回撤：比买入持有小一些
交易次数：几十次
扣除成本后：跑输买入持有
```

**这个失望是本章最重要的收获。**

因为它让你亲手验证了 11.3 的结论：**均线策略长期接近买入持有，扣成本后跑输。**

### 然后你该做什么

把 `ma_short` 改成 15、25、30、40，`ma_long` 改成 50、55、70、90，跑 16 个组合。

**你会看到结果差异很大**，有的年化 5%，有的年化 15%。

**然后问自己：我怎么知道哪个是"对"的？**

答案：**你不知道。** 你只会选出历史上最高的那个，然后它在未来失效。

**这就是过拟合的现场体验。** 比读十篇文章有用。

## 12.6 从回测到实盘，那道跨不过去的沟

即使你的回测完全干净（无过拟合、无前视、含成本），实盘仍会打折扣。原因是结构性差异：

| 差异 | 回测 | 实盘 |
|---|---|---|
| 成交 | 立刻按理想价成交 | 排队，可能部分成交 |
| 涨跌停 | 常被忽略 | 涨停买不进、跌停卖不掉 |
| 停牌 | 常被忽略 | 复牌可能跳空 -20% |
| 流动性 | 无限 | 你的单会推动价格 |
| 滑点 | 固定 0.1% | 剧烈波动时可能 1% 以上 |
| **心理** | **不存在** | **最大变量** |

**经验值**：一个干净的回测，实盘通常打 **5–7 折**。

```
回测年化 20% → 实盘可能 10%–14%
回测年化 10% → 实盘可能 3%–7%（甚至跑输买入持有）
```

**如果你的回测年化是 50%，先不要高兴。** 大概率是上面某个陷阱在起作用。真能做到长期年化 50% 的策略，不会出现在你的电脑上。

## 12.7 如果你只有一个周末，该做什么

按优先级：

| 优先级 | 做什么 | 时间 |
|---|---|---|
| **1** | 跑"买入持有 vs 双均线"，对比扣成本后的净收益 | 2 小时 |
| **2** | 把交易频率从每月 1 次改到每周 1 次、每天 1 次，看收益如何衰减 | 1 小时 |
| **3** | 手动调参数 16 组，体验过拟合 | 1 小时 |
| 4 | 读 RQAlpha 文档，理解 `slippage` 和 `commission` 怎么配 | 1 小时 |
| 5 | 找一个"样本外"区间验证 | 1 小时 |

**做完 1 和 2，你已经比 95% 的"量化爱好者"更懂这件事了。** 因为大多数人直接从第 3 步开始，然后带着一个过拟合的策略冲进市场。

---

## 本章要记住的 3 件事

1. **回测是用来证伪的，不是用来证实的。** 好的回测结果只说明"在历史上没被推翻"。
2. **三个杀手：过拟合、前视偏差、幸存者偏差。** 加上"最低 5 元佣金"，这四项能让任何策略从盈利变亏损。
3. **实盘打 5–7 折是常态。** 回测年化 20% 的干净策略，实盘能到 12% 就是成功。

## 动手做

### 练习 12-1：跑通最小策略（2 小时）

按 12.4 的代码跑一次，哪怕报错也要改到能跑。

**记录你遇到的每个报错**——这些坑下次还会遇到。

### 练习 12-2：做一次成本敏感性测试（1 小时）

同一个策略，跑三次：

```
A. 零成本
B. 佣金万 3，无最低 5 元
C. 佣金万 3，最低 5 元（真实情况）
```

**对比三次的年化收益。** 你会看到 C 比 A 低多少——这就是第 3 章讲的事情在代码里的样子。

### 练习 12-3：手动做一次"假回测"（30 分钟，不用代码）

如果你想验证"我的参数是不是过拟合"，有个不用写代码的方法：

```
1. 在纸上写下 5 组均线参数（20/60, 15/50, 30/90, 25/75, 10/40）
2. 用行情软件逐个手工看它们在 2020–2023 年的表现（软件能画均线）
3. 挑出表现最好的那组
4. 再看它在 2024–2026 年的表现
```

**第 4 步的结果通常会让你失望。** 这就是样本外测试的意义。
