# 第6课 · 交易所接口与自动下单

> 量化的运行时闭环是三步：**① 从交易所获取实时数据 → ② 本地策略处理产生信号 → ③ 把信号变成真实委托下单**。本课讲 ① 和 ③。

## 6.1 API 概述

数字货币交易所有上千个（CoinMarketCap 可查）。每家接口结构各异，自己逐个对接非常麻烦——所以取数和下单都要借助工具。

## 6.2 用 REST API 获取实时数据

以 OKEx 为例，本质是**拼 URL + 发 HTTP 请求**：

```python
import requests, pandas as pd

symbol = "LTC_BTC"
url = "https://www.okex.com/api/v1/ticker.do?symbol=" + symbol
data = requests.get(url, timeout=10).json()      # 返回 JSON
print(data["ticker"]["last"])                     # 最新价

# 注意：网络超时/连接失败要用 try/except 兜底（见第3课异常处理）
```

> 坑：部分交易所对境内 IP 有限制，需代理；请求务必设 `timeout` 并容错。

## 6.3 用 CCXT 统一接入与自动下单

**CCXT** 是开源第三方库，帮你封装好几十家交易所的统一接口：

```python
import ccxt

ex = ccxt.okex({"apiKey": "YOUR_KEY", "secret": "YOUR_SECRET"})
# 取行情
ticker = ex.fetch_ticker("BTC/USDT")
print(ticker["last"])
# 下限价买单：买 0.01 BTC，价格 50000
order = ex.create_limit_buy_order("BTC/USDT", 0.01, 50000)
print(order["id"], order["info"])   # 订单ID + 交易所原始返回
```

- `fetch_ticker / fetch_ohlcv`：取行情/K线。
- `create_limit_buy_order / create_limit_sell_order`：下限价单。
- 返回含 `id`（交易所订单号）与 `info`（原始数据：类型、价格、数量、时间、成交量…）。

## 6.4 番外：读 CCXT 源码

CCXT 把每个交易所的差异封装在统一接口之下。想深入，可对着 `fetch_ticker`、`create_order` 等常用函数读它的源码，看每家交易所在统一外壳下各自做了什么——这也是学习「如何用库提高生产力」的好范例。

> 小结：取数靠 REST/库，下单靠 CCXT 统一封装，配合异常处理与超时，就能稳定地和交易所通信。下一课进入策略核心——择时策略。
