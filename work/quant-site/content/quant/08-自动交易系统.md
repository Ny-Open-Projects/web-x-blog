# 第8课 · 自动交易系统

> 前面已会取数（第6课）、会择时策略（第7课），本课把它们组装成一个能自己跑的**自动交易系统**。

## 8.1 一个简单自动交易系统

```python
import time

def run():
    while True:
        df = fetch_recent_klines("BTC-USDT", "15min")   # ① 取数
        signal = ma_signal(df)                            # ② 策略信号（同回测逻辑）
        if signal == 1 and not holding():
            ex.create_market_buy_order("BTC/USDT", amount)  # ③ 下单
        elif signal == 0 and holding():
            ex.create_market_sell_order("BTC/USDT", amount)
        time.sleep(15 * 60)   # 每 15 分钟遍历一根 K 线

run()
```

> 文件名/变量避免用中文，防止编码问题。

## 8.2 参数选择

寻优只是第一步。关键是：**定下参数后坚决执行**，不要因为一两笔盈亏就盘中改参数、加条件。

- 加任何新条件（如“盘中实时止损”）前，**先回测验证**，否则等于在跑一个从没回测过的策略——和裸奔没区别。
- 相信大样本历史数据，而非自己的一两笔主观判断。

## 8.3 实盘心理（重点）

| 常见错误 | 正确做法 |
|---|---|
| 没回测就上实盘 | 任何策略先过回测与模拟盘 |
| 亏一笔就改参数/加条件 | 寻优后锁定参数，执行到底 |
| 盘中人工干预信号 | 排除情绪，让系统按规则运行 |
| 用没回测的条件“打补丁” | 新条件先回测再上线 |

## 8.4 实盘信号 vs 回测信号

- 回测代码计算复杂、允许冗余，重在**正确**；
- 实盘信号代码**越快越好**（每根 K 线要在窗口内算完），重在**低延迟**。
- 因此两者的 signal 代码**可以是不同实现**（只要逻辑等价）；简单策略（如均线）也可共用。

## 8.5 大作业

把第 7 课的**布林带策略**（可多空、带杠杆）从回测搬到 **Bittrex** 实盘：参照第 7 课回测 + 第 8 课下单框架自行实现。重点体会：可多空的策略在单边下跌市里比“只能做多”的均线策略更能产生收益，但风险也更高。

> 小结：自动交易 = 取数 + 信号 + 下单的循环；工程上要处理延迟、容错、去重下单；心态上要“回测过才上、寻优后不动”。下一课讲选币——决定“买卖什么”。
