# 数据报告实战与求职面试

学完前九个模块，你已经会取数、会处理、会可视化、会建模。最后一课解决另一个问题：怎么把分析结果**讲清楚、写漂亮、变成 offer**。这门课的原作者在结课篇里分享过一份真实的双十一股价研究报告，这里把它作为案例完整展开，并给出可运行的代码。

## 一、数据分析报告的框架

一份能过评审的报告，骨架是固定的四段，外加附录：

- **分析背景**：为什么要做这次分析，要解决什么问题。市场容量、产品设计、业务方向、转化提升，先界定清楚，看报告的人才知道你要干嘛。
- **分析思路**：用什么数据、怎么验证。获取哪些字段、从数据库取还是从外部服务商买、用统计描述还是建模型（RFM、聚类、回归），在动手前就要定下来，并写进报告。
- **分析主体**：分析过程本身。从哪些维度拆、建模分几步、得出什么结论和规律。涉及的工具（Python、Excel）和思维模型都在这一步呈现。
- **结论与建议**：提出解决方案。基于分析结果，优化方向是什么、具体怎么提升。这是上级和团队最想看的部分。
- **附录**：参考资料、数据来源、版权声明。

常见错误是把力气全花在「分析主体」的图表堆砌上，背景一笔带过、建议含糊其辞。评审往往只看两头：问题定义得准不准，建议落不落得了地。

## 二、案例：双十一股价季节性报告

原作者的报告背景是这样的：双十一期间互联网股价普遍下跌，市场情绪恐慌。他想验证一个猜想，双十一前后股价是否存在**周期性规律**，比如节前涨、节后跌。

报告主体只做了三件事：

- 获取五家互联网公司 2014 至 2020 年的历年收盘价；
- 做归一化处理后按「双十一前后十个交易日」切片观察；
- 用同一套「节前买入、节后第十天卖出」的策略逐年回测。

结论是：2018 至 2020 年呈现先涨后跌的规律，策略在 2014 至 2020 年**平均年化收益 5.3%**，且每年都是正收益。

这份报告短小但完整，背景、思路、主体、建议一样不缺。用代码把它的核心回测复现出来：

```python
# 双十一季节性策略回测
# 真实结论需接入真实行情复算，此处用合成数据演示完整流程
import csv
import io

def backtest(rows, buy_day="11-01", sell_day="11-11"):
    """rows: [(date_str, close)]，按年切片执行 节前买、节后卖"""
    years = {}
    for d, c in rows:
        y = d[:4]
        years.setdefault(y, {})[d] = float(c)
    report = []
    for y in sorted(years):
        px = years[y]
        b = px.get(f"{y}-{buy_day}")
        s = px.get(f"{y}-{sell_day}")
        if b and s:
            report.append((y, (s - b) / b * 100))
    return report

# 合成一份行情（2014-2020，每年 11 月两个交易日），仅演示流程
sample = []
for y in range(2014, 2021):
    sample.append((f"{y}-11-01", 100 + y % 5))          # 节前价
    sample.append((f"{y}-11-11", 103 + y % 7))          # 节后价（略高，制造正收益）

report = backtest(sample)
print("年份  收益率")
for y, r in report:
    print(f"{y}  {r:+.2f}%")
avg = sum(r for _, r in report) / len(report)
print(f"平均年化收益 {avg:+.2f}%")
```

跑出来的输出是一张逐年收益表加一个均值。接真实行情时，把 `sample` 换成从行情源导出的 CSV 即可，回测逻辑不用动。报告里的 5.3% 就是这条曲线在真实数据上的均值。

这个案例值得学的不只是结论，而是它的**结构意识**：一个猜想、一份数据、一个策略、一张年报，四段框架每一段都有对应物。

## 三、汇报与演讲

分析师绕不开汇报：跟领导讲产值，跟团队讲方法，跟客户讲价值。同样的内容，讲法不同效果差很远。四条经验：

- **先搞清楚谁在听、想听什么**。领导关心你为公司做了多少产值、KPI 完成如何；客户关心你为他创造了什么价值、怎么用。教客户用报表系统时，直接带电脑录屏操作，比念操作手册强得多，这就是投其所利。
- **讲得有逻辑，深入浅出**。穿插例子，让听众听完能上手。讲系统操作就现场点一遍流程，遇到典型问题顺手解决，听众代入感最强。
- **主动抓注意力**。人的专注度撑不久，连续讲二十分钟，底下已经走神了。每过一段就停一下，「这块大家有什么问题」「这里可以怎么改进」，把注意力拉回来，也逼自己观察听众反应。
- **讲稿分场合**。原作者复盘过自己的三个阶段：早期只写大纲；操作演示类场合仍只写大纲，但补上难点和技巧提示；面对高管、CEO 级别汇报则写逐字稿，因为工作内容繁杂，靠临场反应容易翻车。写完逐字稿再演练一到三遍，场合越重要练得越多，但别超过三遍，否则自己也会失去新鲜感。

PPT 模板按需取用，选简单大方的：封面、目录、详情页结构完整，数据和表格位置留好，信息量足就好。花里胡哨的图形反而是干扰。

## 四、简历怎么写

简历的核心原则：**写你实现了什么、解决了什么问题，用数字体现价值**。不要写岗位职责式的描述。

对比一下。数据分析师常见写法：

> 负责数据报表制作，拆分数据维度，与同事沟通支持业务。

这句话放在任何一家公司的 JD 里都成立，也就没有信息量。改成：

> 搭建运营日报体系覆盖 6 个业务线，定位到注册流程断点，推动改版后转化率提升 12%。

实现了什么（日报体系、定位断点）、解决了什么（转化率低）、价值多大（12%），三样都在，且全部可量化。

结构上应届和社招有区别：

- **应届生**：基本信息、求职意向、教育经历、项目或实习经历、社团与竞赛、技能证书。重在校经历，GPA、奖学金、名校背景都可以放。篇幅压到**一页**，HR 看一份简历只有几秒。
- **社招**：重工作背景和教育背景之外的实战。工作经验与项目经历分开写，一个程序员可能同时接手三到五个项目；期望薪资建议直接写上，避免谈不拢浪费双方时间；自我评价一栏写别人最认可你的一点，最好挂博客、作品这类证明。

通用规则：每一栏内**时间倒序**，离现在越近放越前；格式统一为「时间 - 公司/学校名 - 岗位/专业」，学历标注学位与全日制属性；技能栏与岗位对齐，错配会让 HR 困惑。

## 五、面试准备

数据分析岗位的面试准备分三块：面经从哪来、问题有哪些类型、现场怎么应对。

**面经渠道**：牛客网有按岗位分类的面经汇总和题库，可按新旧或热度排序，找匹配自己方向的刷；知乎、CSDN、简书上有大量真实面经汇总帖，好处是真情实感，能跟着对方的思路自己再过一遍题。看到有人面了二十多家公司的完整复盘，就跟着把题练一遍。

**三类高频问题**：

- **统计与建模**：A/B 实验怎么做（前九课的实验模块就是答案）、用过哪些算法、原理和参数怎么设。
- **业务**：处理过什么业务、转化率多少、DAU 怎么样。有经验的人可以主动讲完整案例。注意商业机密边界：具体数字涉密时，说「我不能给你准确值，但可以告诉你量级」，这是被接受的做法。
- **技能**：SQL 和 Python 用过哪些库、做过什么。可能现场出题，让你用 SQL 或 Python 实现一个需求，平时练手足够就不会慌。

**表达**：准备一个「完整分析案例」的故事线，目标、取数、方法、结论、价值五要素齐全，讲三分钟版本和五分钟版本各一版。

## 迁移到量化

双十一这个案例，本身就是一份**量化季节性策略**的雏形。从数据分析报告走到可交易的策略，还差四步：

- **样本内外分离**：报告的规律基于 2018 至 2020 年观察、2014 至 2020 年回测，重叠在一起。严格做法是用前段定策略、后段做检验，避免用同一段数据又发现规律又验证规律。
- **显著性检验**：5.3% 的平均收益要看波动。算年化波动、夏普比率，样本量只有七年，结论置信度有限，报告里应当主动披露。
- **加风控**：季节性规律可能被突发事件打破。策略要预设止损，比如节后十天窗口内回撤超过 3% 即离场，并限定单策略仓位占比。
- **季节性因子的通用化**：双十一只是一个个案，同一套「事件前买入、事件后卖出」的框架可以扩展到年报季、双十二、春节前。把事件日历系统化，才是季节性策略库的起点。

这条迁移路径说明一件事：数据分析的终点不是图表，而是**可验证、可执行、可复盘的决策**。本模块之后，三轨课程（量化基础、数字货币量化实战、数据分析）形成完整闭环，剩下的就是在真实数据里反复练。
