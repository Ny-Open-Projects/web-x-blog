## 第 1 章 Java 语言基础与集合

1. Integer 缓存 -128~127；包装类比较必须 equals。
2. String 不可变 4 大好处：池化、hash 缓存、线程安全、安全。
3. 重写 equals 必重写 hashCode；可变对象别做 key。
4. ArrayList 扩容 1.5 倍、懒初始化 10；LinkedList 工程上基本不用。
5. HashMap：hash=高16异或低16；容量 2 的幂；负载 0.75；树化阈 8（bin 8 个后第 9 插触发）容量 64；尾插。
6. CHM：CAS+synchronized 锁桶头；size 用 CounterCell；key/value 不许 null；get 无锁。
7. 泛型擦除 4 限制；PECS；Signature 属性可反射拿泛型。
8. ThreadLocal：key 弱 value 强；用完 remove；线程池传上下文用 TTL。
9. LinkedHashMap accessOrder=true + removeEldestEntry = LRU；工业级用 Caffeine（TinyLFU）。
10. 异常：Error 别捕、别吞、留链（cause）、别重复打日志；-OmitStackTraceInFastThrow 排查无栈 NPE。

## 第 2 章 并发编程与 JUC

1. volatile = 可见性 + 有序性，≠ 原子性；标志位/DCL 用它。
2. 锁升级：无锁→偏向→轻量→重量；JDK15 禁用、JDK21 已彻底移除偏向锁（实测标志位 Unrecognized）。
3. 线程池口诀：先核心、再队列、后非核心、最后拒绝；禁 Executors、必有界队列。
4. 线程数靠压测，公式只是起点：N = C×U×(1+W/C)。
5. AQS = volatile state + CLH 双向队列 + park/unpark + 模板方法。
6. CAS 三坑：ABA（加版本）、自旋烧 CPU（LongAdder 分段）、单变量（封装对象）。
7. LongAdder 读弱写强；sum() 是近似快照。
8. CF 生产三件套：自定义线程池、allOf 聚合、orTimeout 超时；异常用 handle/exceptionally。
9. ThreadLocal：key 弱 value 强、用完 remove、线程池传值用 TTL。
10. happens-before 是可见性承诺，不是时间顺序；8 条规则能默写 6 条。
11. 虚拟线程：IO 密集收益大；资源模型从"线程数"迁移到"连接数/下游配额"；防 pinning。
12. commonPool 只给纯 CPU 计算；IO 进去就是全局故障域。
13. JUC 弱一致迭代器：无锁读换最终一致；强一致需求换语义不是换参数。
14. 限流/倒计数/栅栏：Semaphore 管许可、Latch 一次性、Barrier 可重用、Phaser 多阶段。
15. 死锁防固定顺序、活锁防退避、饥饿防配额；并发治理靠 CI 门禁。

## 第 3 章 JVM 与性能调优

1. 五区：程序计数器不 OOM；栈溢出 SOE；元空间 JDK8 在本地内存。
2. 分配路径：TLAB → Eden CAS → Survivor 复制 → 年龄 15/动态年龄 → 老年代。
3. Full GC 触发 5 条：老年代满、元空间满、System.gc、CMS 失败、G1 失败。
4. 双亲委派三目的：安全、唯一、复用；打破场景：SPI/Tomcat/热部署。
5. 三色标记漏标两条件：黑引白 + 灰断白；CMS 增量更新，G1 SATB，ZGC 读屏障自愈。
6. G1：Region 化、停顿预测、Humongous 是大坑、小堆 CMS 反而优；RSet/写屏障有代价。
7. ZGC：着色指针+读屏障；JDK21 分代 ZGC 是生产推荐。
8. 排查三板斧：jstat 看趋势 → jmap dump → MAT 找支配树；Arthas 线上诊断。
9. OOM 三件套必开：HeapDumpOnOutOfMemoryError、GC 日志、ExitOnOutOfMemoryError。
10. JIT 三板斧：分层编译、内联、逃逸分析；新实例要预热。
11. 元空间泄漏五成因：CGLIB/脚本/反射膨胀/加载器不释放/热更新；动态能力要有配额。
12. 容器 JVM：MaxRAMPercentage 50~70、cgroup 感知、区分 JVM OOM 与 OOMKilled、堆外合计 ≤85%。
13. 9 种 OOM 先分流：堆类（有 dump）vs 资源类（看线程数/堆外）——分流错了浪费时间。

## 第 4 章 Spring 与框架生态

1. Bean 生命周期口诀：实例化→注入→Aware→前置→初始化→后置→使用→销毁；AOP 代理在后置生成。
2. 三级缓存：成品/半成品/工厂；第三级为 AOP 延迟决定；构造器循环依赖无解。
3. AOP 失效根因一句话：绕过代理。同类自调用是头号坑。
4. 事务失效：非 public、自调用、catch 吞、默认只回滚 RuntimeException、受检异常要 rollbackFor。
5. REQUIRES_NEW 挂起新开（双连接）；NESTED 保存点（同连接）。
6. 自动装配：imports 文件 + 条件注解；@ConditionalOnMissingBean = 用户优先。
7. Mapper 无实现类 = JDK 动态代理 + FactoryBean + ImportBeanDefinitionRegistrar。
8. 先提交后通知：afterCommit 里发 MQ；事件监听默认同步、@TransactionalEventListener(AFTER_COMMIT)。
9. @Async 四坑：默认池不池化、自调用失效、异常静默、上下文丢失（TaskDecorator/TTL）。
10. prototype 注入 singleton：ObjectProvider / @Lookup / scoped proxy 三正解。
11. Boot 启动优化：先测量 → 懒加载 → 扫描收敛 → CDS → AOT。
12. 迁移即治理：老 SpringMVC 迁 Boot 四步渐进，禁业务变更混入迁移分支。

## 第 5 章 MySQL 与存储

1. B+ 树：矮胖省 IO、叶子链表扫范围；主键自增防页分裂。
2. 二级索引存主键，回表是成本；覆盖索引免回表；ICP 引擎层先过滤。
3. MVCC 四要素 ReadView + 版本链；RC 每语句、RR 每事务一次视图。
4. RR 防幻读：快照读靠 MVCC，当前读靠 Next-Key；混用仍有幻读。
5. 两阶段提交：redo prepare → binlog → redo commit；崩溃看 binlog 定夺。
6. 双 1 最安全；组提交提吞吐；参数翻译成业务风险再定。
7. 死锁预防：固定顺序、小事务、热点分段、RC 减间隙锁。
8. 主从延迟：关键读走主库；并行复制 writeset；半同步保不丢；GTID 必开。
9. 分库分表：先榨干单库，分片键选 user_id，扩容用双写四步，基因法兜底。
10. 资金三道闸：幂等 → 条件更新 → 对账冲正。
11. 索引评审十条：趋势递增主键、覆盖高频模式、区分度、单表≤5、每索引有主。
12. Buffer Pool 双 LRU 防污染；命中率骤降=查新增大扫描。
13. 大表 DDL 走 gh-ost：binlog 流+cut-over，DDL 平台化。

## 第 6 章 Redis 与缓存体系

1. Redis 快四因：内存、epoll、单线程无锁、专用数据结构。
2. ZSet = 跳表 + 字典双结构；小对象 listpack 压缩。
3. 过期 = 惰性 + 定期抽样；淘汰必配 allkeys-lru/lfu。
4. 穿透挡（布隆/空值）、击穿合（单飞/逻辑过期）、雪崩抖（TTL 随机+多级）。
5. 一致性标准答案：先更新 DB 再删缓存 + binlog 异步删 + TTL 兜底。
6. 锁：SET NX PX + 唯一 value + Lua 删 + 看门狗；正确性靠 DB 兜底。
7. RDB 快恢复丢数据，AOF everysec 丢 1 秒，4.0 混合是推荐默认；fork 卡顿看 latest_fork_usec。
8. 哨兵：主观→客观→Raft 选 leader→四步选从；奇数 ≥3 防脑裂。
9. 热 key：本地缓存+打散；大 key：UNLINK+分桶+巡检；大 key 是 Cluster 扩容前置工程。
10. 单实例内存 <10G；KEYS 禁用；Lua 三红线（10 行内/单 key 组/O(1)）。
11. 碎片 ratio>1.5 用 activedefrag；<1 是 swap 更紧急；无界增长查大 key。
12. 版本演进主线：编码简化（listpack）→ IO 并行化（多线程 IO/Sharded PubSub）。

## 第 7 章 消息队列与异步化

1. MQ 三作用：异步、解耦、削峰；代价：最终一致+排障链长。
2. 语义：至少一次 + 消费幂等 = 工程上的恰好一次。
3. 不丢三端：发送确认（acks=all+幂等 producer）、broker（3 副本+minISR=2）、消费（先处理后手动提交）。
4. Kafka 快五因：顺序写、Page Cache、zero-copy、批量压缩、分区并行。
5. rebalance 头号诱因：处理时间超 max.poll.interval.ms。
6. 事务消息 = 半消息 + 本地事务 + 回查；只保证发送侧原子。
7. 顺序消息：key 同分区 + 状态机兜底；默认不追求全局顺序。
8. 延迟消息：RocketMQ 时间轮；Kafka 需自建；任务表防丢。
9. 幂等四法：唯一键、状态机、版本号、去重表。
10. 死信队列必须有告警与 SOP；消息带 traceId。
11. HW=ISR 最小 LEO；minISR=⌊replicas/2⌋+1；ISR 不足拒写是 CAP 落点。
12. 积压应急五步：定性→修慢消费→扩容→批量多线程→转储重置。
13. EOS 无免费午餐：Kafka 买单限内部，业务买单靠幂等。

## 第 8 章 分布式理论与微服务

1. CAP：分区时 C/A 二选一；注册中心选 AP，协调选 CP。
2. Raft：选主（term+多数派）→ 复制（多数派提交）→ 安全（选举限制）；成员变更单步法。
3. TCC 三坑：空回滚、悬挂、幂等——都以事务记录表解决。
4. 最好的分布式事务是设计掉它：聚合库、状态机、对账。
5. 限流四算法：计数器（突刺）→ 滑动窗口 → 漏桶（恒速）→ 令牌桶（允许突发）。
6. Sentinel 熔断三策略：慢调用比例/异常比例/异常数，半开试探恢复。
7. 可观测三支柱一条链：Metrics 告警 → Tracing 定位 → Logging 取证。
8. traceId 必须跨 MQ/线程池传递；错误请求强制采样。
9. 稳定性四段：预防（冗余隔离）、感知（SLO）、止血（回滚优先）、复盘（无责）。
10. 拆分跟随团队边界；拆细了要敢合并；禁止共享库。
11. 分布式 ID：雪花防回拨四对策、号段双 buffer、ID 兼顾路由（基因法）。
12. 全链路压测三环节：染色透传、影子隔离、非入口流量识别。
13. Mesh 是"治理一致性"税：规模不到别付；Sidecarless（eBPF）是方向。
14. 单元化 LDC：容量/容灾/灰度三合一，路由键一致性是命门；分阶段演进（双活→同城→异地）。
15. 时钟三路线：逻辑时钟/HLC、共识序、Spanner TrueTime；TSO vs HLC 是延迟与去中心的权衡。

## 第 9 章 亿级高并发场景设计

1. 场景题五步：澄清→估算→主干→难点→演进；先问规模再画图。
2. 秒杀漏斗：CDN/风控 → 网关限流 → Redis 预扣 → MQ 削峰 → DB 条件更新 → 对账。
3. 防超卖：Redis 原子 + DB `n>0` 条件更新 + 幂等回补。
4. Feed 混合推拉：小 V 推、大 V 拉、收件箱 ZSet 截 3000 条。
5. 红包：发时预拆（二倍均值）、抢时取池、领时异步、过期退回；金额用分。
6. 排行榜：Top N 用 ZSet 候选池，全民排名用分桶前缀和。
7. QPS = 线程数/RT；RT 涨→线程涨→切换涨→RT 更涨（死亡螺旋）。
8. 优化优先级：缓存 > 异步并行 > 批量 > 分片 > 换语言。
9. 一切写幂等；降级开关要演练过才算数。
10. 大对象三宗罪：大 key、大事务、大查询。
11. 调度平台：分片抢占防重复、执行器幂等、触发时间打散。
12. 营销系统按资金标准建：券超发损失真金白银，幂等/对账/审计三件套。

## 第 10 章 AI：LLM 与 Agent

1. LLM = 概率续写机器：无记忆、会幻觉、上下文为王。
2. Temperature 低温做结构化任务；结构化输出用 JSON Mode/FC，别抠正则。
3. RAG 链路：切分 → Embedding → 向量库 → 混合检索 → 重排 → 生成带引用。
4. RAG 调优第一原则：检索归因 vs 生成归因，分开查。
5. 企业 RAG 三命门：权限过滤、知识时效、评测集。
6. Agent 六模块：规划、记忆、工具（MCP）、编排、护栏、可观测。
7. 上下文管理 = 成本与效果核心：滑动窗口 + 摘要压缩 + 结构化提取。
8. 成本四刀：降单价（路由/私有化）、降 token、降次数（语义缓存）、预算熔断。
9. 模型网关 = AI 时代的 API 网关：路由/缓存/配额/审计/降级。
10. AI 输出必须有三出口：可用、人审、拒绝；高风险操作永远 human-in-the-loop。
11. Prompt 注入 = 新 SQL 注入：防线在系统层（最小权限/沙箱/审计），prompt 规则只是概率性的。
12. 多模态解析成本账：分层解析（轻 OCR→命中再深解析）+ 结果缓存。
13. Agent 可恢复四件套：checkpoint、幂等工具、续跑策略、预算熔断。
14. 评测集是 AI 团队最值钱的资产；LLM-as-judge 要双评交换顺序 + 人工校准。

## 第 17 册 流程定级

1. P10 = 技术战略 × 组织建设 × 业务价值，三合一才有定级证据。
