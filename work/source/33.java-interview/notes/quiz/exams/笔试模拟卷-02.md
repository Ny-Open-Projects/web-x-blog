# 参考答案与解析（自测后再看）

**1.1**（来源 jvm）
**答案：A**
**解析：** G1 出现 to-space exhausted 表示晋升时 Survivor/Old Region 不足。原因：并发标记期间老年代同时被消耗，晋升失败触发 Full GC，解法：预留空间（-XX:G1ReservePercent 默认 10）、提前并发标记（InitiatingHeapOccupancyPercent）。

**1.2**（来源 spring）
**答案：D**
**解析：** @ConfigurationProperties 批量绑定前缀下的属性并支持校验与元数据。原因：relaxed binding 支持 kebab-case 与驼峰互转，配合 @Validated 做 JSR-303 校验，IDE 有元数据提示，优于散落的 @Value。

**1.3**（来源 mysql）
**答案：D**
**解析：** sync_binlog=1 每次提交刷 binlog（默认，与 redo 1 组成双 1）。原因：双 1 配置保证事务提交不丢，性能敏感可用 100/1000 组提交（主库宕机可能丢 binlog），从库可放宽。

**1.4**（来源 redis）
**答案：A**
**解析：** RedisInsight 是官方免费可视化管理工具（键浏览/慢查询分析/集群拓扑）。原因：比 redis-cli 直观（大 key 分析/内存分布/CLI 自动补全），生产排查辅助，与 redis-cli 组合使用。

**1.5**（来源 mongodb）
**答案：B**
**解析：** $in 是多组等值官方按 E 处理（组内排序仍有效）。原因：{status:{$in:[A,B]}} 对排序列仍有连续性，按 ESR 设计索引时 $in 归入等值位。

**1.6**（来源 mq）
**答案：A**
**解析：** Kafka/RocketMQ 是 pull（客户端拉取长轮询），RabbitMQ 是 push（服务端推送）。原因：pull 语义消费者自主控速（防压垮），push 容易压垮慢消费者（prefetch 限流补救），长轮询（long polling）兼顾延迟与效率。

**1.7**（来源 distributed）
**答案：C**
**解析：** Raft 把共识拆解为 leader 选举、日志复制、安全性三个子问题易理解易实现。原因：leader 全权管理日志复制（follower 被动接收），term 单调递增保证时序，工业界主流（etcd/TiKV/Dledger），本项目 AQS/Redis/MySQL 知识多处关联。

**1.8**（来源 ai）
**答案：A**
**解析：** 内容安全：输入侧（敏感词/注入检测）+输出侧（合规审查/免责声明），金融医疗等垂直域强监管。原因：生成内容责任归属企业（模型说错话企业背锅），垂直域加规则层（话术边界），红队测试（越狱/诱导）常态化，与 AI-025 联动。

**1.9**（来源 algorithm）
**答案：A**
**解析：** LFU：频次桶+双向链表（同频按时间），O(1) get/put，比 LRU 多频次维度。原因：频次桶数组+桶内 LRU 链，淘汰最小频次最久未用，与 Redis LFU（RD-024）概念联动，实现复杂度高于 LRU。

**1.10**（来源 java-ai）
**答案：B**
**解析：** Spring MVC 栈桥接 Flux 流式：SseEmitter 订阅 Flux 逐段转发，客户端断开触发取消。原因：非 WebFlux 项目也能做流式（桥接层），桥接要处理背压与取消，与 JA-098 联动。

**1.11**（来源 agent-dev）
**答案：C**
**解析：** Agent 生成代码执行防线：生成代码→静态扫描（危险 API 黑名单）→沙箱执行（AD-077）→人工确认（高危），多层防线。原因：生成代码执行是最高危 Agent 能力（JA-156 沙箱的完整防线链），黑名单+沙箱+确认三层缺一，与代码沙箱纪律联动。

**1.12**（来源 java-basics）
**答案：C**

**1.15**（来源 spring）

**2.5**（来源 distributed）
