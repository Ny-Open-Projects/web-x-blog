# 参考答案与解析（自测后再看）

**1.1**（来源 mysql）
**答案：C**
**解析：** online DDL：INPLACE 算法大部分操作不锁表（加列 8.0 支持 INSTANT 秒级）。原因：INSTANT 只改元数据（8.0.12+），INPLACE 重建表仍需时间且 MDL 短锁，COPY 全量拷贝最慢，DDL 前查支持算法。

**1.2**（来源 redis）
**答案：A**
**解析：** 主从复制以 Replication ID + offset 定位复制进度（PSYNC 基础）。原因：每个主库有唯一 replication id，从库携带 id+offset 请求增量，id 匹配且 offset 在 backlog 内则部分重同步，id 变了（切主/重启）触发全量。

**1.3**（来源 mongodb）
**答案：A**
**解析：** 扩展路线：先副本集（读扩展/高可用）→垂直扩容到极限→才分片（写/容量水平扩展）。原因：分片引入复杂度（分片键/广播/jumbo），过早分片是常见失误，官方路线也是先副本集。

**1.4**（来源 mq）
**答案：C**
**解析：** Kafka exactly-once 仅限 Kafka 流内部（读-写闭环），端到端需业务幂等。原因：消费到外部系统（写 DB）不在此保证内，落地口径：Kafka 内 exactly-once+业务侧幂等（去重表），P10 级别的语义边界认知。

**1.5**（来源 distributed）
**答案：A**
**解析：** 一致性哈希环+虚拟节点（物理节点映射 100-200 个虚拟点）平衡负载。原因：普通哈希节点增删导致全量重映射（模数变化），一致性哈希只迁移相邻区间（1/n），虚拟节点解决节点少时的数据倾斜。

**1.6**（来源 ai）
**答案：D**
**解析：** 幻觉检测：答案与检索来源比对（faithfulness：生成是否被资料支持）、无来源任务用事实核查 API/规则。原因：RAG 场景自动检测（NLI 模型比对答案与 chunk），无来源（闲聊/创作）靠约束与免责，抽样人工复核校准自动检测，与 AI-011 溯源配合。

**1.7**（来源 algorithm）
**答案：D**
**解析：** Fisher-Yates 洗牌：从后往前每个位置与前面随机位置交换，均匀 O(N)。原因：从后往前保证每个排列等概率（1/n!），从前往后交换是有偏洗牌（经典错误），Collections.shuffle 即此实现。

**1.8**（来源 java-ai）
**答案：C**
**解析：** 结构化输出失败路径：模型输出不合规 JSON 时反序列化异常，需重试（带错误反馈）或降级（放宽约束/兜底值）。原因：entity 转换不是百分百成功，失败重试喂回解析错误可修复多数，与 AI-070 结构化双保险联动。

**1.9**（来源 agent-dev）
**答案：D**
**解析：** 记忆检索延迟预算：记忆检索在 Agent 循环内（每次决策前），延迟预算独立（如 100ms），超预算降级（少注入）。原因：记忆检索在关键路径（循环内检索），延迟预算与降级策略（JA-667 同思想），与延迟知识联动。

**1.10**（来源 java-basics）
**答案：A**
**解析：** JDK9 引入模块系统（JPMS）：module-info.java 声明依赖与导出，JDK 内部 API（如 sun.misc.Unsafe 部分）被强封装。。原因：强封装破坏了直接依赖 JDK 内部 API 的老代码——升级 JDK 的最大阻力源。。

**1.11**（来源 concurrency）
**答案：D**
**解析：** 虚拟线程默认调度器是专用 ForkJoinPool（FIFO 模式）并行度默认 CPU 核数。原因：可用 jdk.virtualThreadScheduler.parallelism 调整，载体线程数少于虚拟线程数百万级，阻塞 IO 时载体立即被复用。

**1.12**（来源 jvm）
**答案：D**
**解析：** JVM 进程内存 = 堆 + 元空间 + 线程栈合计 + Code Cache + GC 开销 + Direct Memory。原因：容器里按此总账设 limit（如堆 70% 留 30% 给其余），只算堆会撞 cgroup OOMKill，这是容器 OOMKill 的第一根因。

**1.13**（来源 spring）
**答案：B**
**解析：** JDK 动态代理要求目标实现接口，CGLIB 生成子类代理无接口要求。原因：JDK 代理实现 Proxy+InvocationHandler，CGLIB 用 ASM 生成子类覆写方法，final 类与 final/private 方法无法被 CGLIB 增强且 final 方法不进入代理。

**1.14**（来源 mysql）
**答案：B**
**解析：** join 优化核心是小表驱动大表。原因：驱动表行数决定外层循环次数，straight_join 强制指定驱动顺序，"小表"指过滤后行数少而非物理小。

**1.15**（来源 redis）
**答案：B**
**解析：** Redisson 可重入锁用 hash 结构（field=线程标识 value=重入次数）。原因：加锁 hash increment、解锁 decrement 到 0 删除，Lua 保证判断与操作原子，比 SETNX 版本功能完整（可重入/公平/读写锁）。

**2.1**（来源 mongodb）
**答案：C**
**解析：** 正确表述应为——WiredTiger（3.2+ 默认）提供文档级并发控制与 MVCC。原因：写不同文档不互斥（3.0 前 MMAPv1 库级锁），写冲突重试，是 MongoDB 并发能力跃升的根基。

**2.2**（来源 mq）
**答案：B**
**解析：** 正确表述应为——消息保留策略：按时间（默认 7 天）与按大小，压缩主题（compact）按 key 保留最新。原因：retention 只影响磁盘不丢已消费（消费位移独立），compact 适合状态快照主题，磁盘规划=吞吐×保留期。
