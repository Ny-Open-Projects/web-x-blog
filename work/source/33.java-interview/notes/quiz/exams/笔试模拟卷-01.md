# 参考答案与解析（自测后再看）

**1.1**（来源 concurrency）
**答案：D**
**解析：** 创建虚拟线程的 API 是 Thread.ofVirtual().start() 或 Executors.newVirtualThreadPerTaskExecutor()。原因：与平台线程同一 Thread 抽象，可加名字便于排查，Spring Boot 3.2 开 spring.threads.virtual.enabled 一键切换。

**1.2**（来源 jvm）
**答案：B**
**解析：** G1 日志中 Humongous regions 关键字提示巨型对象分配频繁。原因：巨型缓存数组、大集合拷贝、一次性读大文件进堆是常见根因，解法：拆分、走堆外、控制缓存上限，Humongous 对象会加剧并发标记与碎片。

**1.3**（来源 spring）
**答案：B**
**解析：** BeanFactoryPostProcessor 在 Bean 实例化前修改 BeanDefinition。原因：作用于"配方"阶段（改定义），与 BeanPostProcessor（改实例）区分，属性占位符解析（PropertySourcesPlaceholderConfigurer）就是 BFPP。

**1.4**（来源 mysql）
**答案：D**
**解析：** InnoDB 默认隔离级别 REPEATABLE-READ。原因：SQL 标准要求 RR 下有幻读，InnoDB 在 RR 下用 MVCC（快照读）+间隙锁（当前读）基本消除幻读，这也是 MySQL 默认 RR 的底气。

**1.5**（来源 redis）
**答案：D**
**解析：** Redis 不用 B+ 树：内存场景 hash/skiplist/listpack 更快且快照友好。原因：B+ 树为磁盘优化（减少 IO 深页缓存），内存访问 hash O(1) 已够，持久化用整体快照而非 B+ 树原地更新。

**1.6**（来源 mongodb）
**答案：D**
**解析：** 版本升级路径：4.x→5.0（reshard/时序集合）→6.0→7.0（查询引擎优化）。原因：升级评估 feature compatibility version（先降级兼容设置），从库先升再切主灰度，驱动与 ODM 同步升级。

**1.7**（来源 mq）
**答案：D**
**解析：** log.cleanup.policy=compact 按 key 保留每个 key 最新值（状态快照主题）。原因：适合"最新状态"数据（K/V：配置表/状态表/数据库变更 CDC 主题），与 delete 策略共存（compact+delete），消费方总是拿到每个 key 最新状态。

**1.8**（来源 distributed）
**答案：A**
**解析：** gRPC：HTTP/2 多路复用+protobuf 二进制序列化（跨语言 IDL）。原因：HTTP/2 流复用单连接并发多请求，protobuf 体积小解析快（IDL 生成强类型代码），云原生与跨语言场景主流。

**1.9**（来源 ai）
**答案：C**
**解析：** Agent 架构六模块：规划（任务拆解）、记忆（短期上下文+长期向量库）、工具（function calling）、执行循环、护栏（安全边界）、可观测（追踪评估）。原因：Agent=LLM+工具+循环（观察-思考-行动），规划与记忆决定复杂任务能力，护栏与可观测决定能否生产化，本项目总结的架构框架。

**1.10**（来源 algorithm）
**答案：D**
**解析：** 大 O 表示增长趋势：O(1)<O(logN)<O(N)<O(NlogN)<O(N²)<O(2^N)。原因：只保留最高阶项与常数忽略，O(NlogN) 与 O(N) 在 N 小时差距不明显（常数项主导），面试先给复杂度再给推导。

**1.11**（来源 java-ai）
**答案：A**
**解析：** 智能客服 Java 架构深化：意图路由→RAG 答复→情绪识别升级人工→会话摘要转接，四级漏斗。原因：AI-037 的架构细化：情绪/升级漏斗控制转人工率（北极星），会话摘要让人工接手有上下文，与 JA-289 指标联动。

**1.12**（来源 agent-dev）

**1.14**（来源 concurrency）
