# 全卷复审校验标准 —— 代码参照 open-code-review / 《阿里巴巴 Java 开发手册》，语言参照 P10 面试者标准

> 本文件是全卷持续校验的**标准基线**。每篇内容按此逐条核对，发现即修，修必留痕（本文件 23.x 修订记录）。

## 一、代码标准（基于《阿里巴巴 Java 开发手册》嵩山版 + 开源 code review 通识）

### C1 线程与并发（手册并发处理章节）
- C1.1 **禁止显式 new Thread 创建线程**：必须使用线程池（ThreadPoolExecutor）。*教学演示/测试代码中裸线程若为必要（如直接观测 getState、attach 目标），须在注释显式声明豁免理由。*
- C1.2 线程池必须 ThreadPoolExecutor 显式创建，**禁用 Executors 快捷方法**；必须指定有界队列、线程命名 ThreadFactory、拒绝策略。
- C1.3 **count++ 等复合操作必须原子类或锁**；volatile 只用于状态标志与发布。
- C1.4 DCL 必须 volatile；单例初始化需防反射/序列化（或用 Holder/枚举）。
- C1.5 **捕获 InterruptedException 必须恢复中断位**（Thread.currentThread().interrupt()）或按语义处理，禁止静默吞掉。
- C1.6 等待条件判断必须 while 而非 if（防虚假唤醒）；notify 必须考虑 notifyAll。

### C2 集合与泛型
- C2.1 多线程共享集合必须用并发容器（CHM/COW），禁用裸 HashMap。
- C2.2 集合声明必须带泛型；LinkedBlockingQueue 显式容量（默认 Integer.MAX_VALUE 是坑）。
- C2.3 迭代中修改集合必须用迭代器 remove / removeIf，禁止裸 put/add。

### C3 异常与资源
- C3.1 禁止捕获后吞掉（空 catch / 仅 printStackTrace 不留痕）——生产代码用日志（SLF4J 占位符），演示代码须注释说明。
- C3.2 资源（流/连接/锁）必须 try-with-resources 或 finally 关闭。
- C3.3 不要用异常做流程控制；不要捕获 Throwable/Error 除非框架边界。

### C4 命名与可读性
- C4.1 类 UpperCamelCase、方法/变量 lowerCamelCase、常量 UPPER_SNAKE_CASE；**杜绝无意义命名（s2/a1/b1）**。
- C4.2 魔法值常量化或有注释（教学片段可豁免，需说明）。
- C4.3 位运算技巧（如 `h & 0x7fffffff`）须注释意图——Math.abs 对 Integer.MIN_VALUE 的坑属于 review 高频标记项。

### C5 安全
- C5.1 SQL 必须 #{} 预编译；${} 仅限白名单列名。
- C5.2 日志禁打敏感信息（token/密码/身份证）。
- C5.3 随机数安全场景用 SecureRandom。

## 二、语言标准（专业 P10 面试者口径）

### L1 结论与证据
- 结论先行；量化指标必须可追溯（监控/压测/公式），禁止拍脑袋数字。
- 关键断言带"实证锚点"（本机验证/源码核对/官方文档）。

### L2 边界与版本
- 每个方案显式给出适用条件与代价；版本锚定（JDK8/21、Boot 2.x/3.x、MySQL 5.7/8.0、Redis 6/7）。
- JDK 行为差异必须标版本（例：树化第 9 插触发、AQS 15+ 重构、偏向锁 21 移除）。

### L3 禁用语
- 禁绝对化未验证表述（"一定/绝对/永远"）——已实证的除外（须挂证据）。
- 禁名词堆砌不带取舍；禁"看情况"式废话——要给决策矩阵。
- 禁把推荐当默认（例："Boot 默认 SimpleAsyncTaskExecutor"这类以讹传讹）。

### L4 结构
- 每答：结论 → 机制 → 实证/案例 → 边界/代价 → 治理动作。
- 数字对比（改造前后）必须成对出现。

## 三、教学代码豁免规则（重要）

教学片段（第 13 册手写、沙盘、验证套件）允许以下豁免，**但必须在代码注释或所在文档声明**：
- 裸 Thread（观测 getState / attach 目标）；
- System.out / printStackTrace（演示输出）；
- 省略日志框架与配置类；
- 省略防御式校验（聚焦主干）。

豁免声明缺失 = 按 review 缺陷计。

### 24.0 用户新增两条标准（2026-11-15，自此生效）

#### 标准 A：面试题必须有"标准回答话术"（经验面试官视角）
【参考回答】必须写成**可背、可说出口的第一人称话术**，五要素：
1. **开口句**：第一句就是结论/框架（"三个原因…"/"分两层…"），禁止绕弯铺垫；
2. **分点展开**：一二三四编号，每点一句机制 + 一句证据；
3. **实证锚点**：量化数字或"本机验证过/官方文档原文"；
4. **边界主动交代**：适用条件、代价、反例；
5. **治理收尾**：落到规范/门禁/团队动作。
长度 45~90 秒口播达标。纯 bullet 知识堆砌 ≠ 话术——判定为不达标。

#### 标准 B：笔试题必须有【思路】【分析】【标准答案】【常见错误】四要素
- **【思路】**：为什么选这个数据结构/算法——从需求特征推导（如"get/put 都要 O(1) → hash 定位 + 双链表维护顺序"），不是报答案；
- **【分析】**：复杂度、边界 case（空/1/满/并发）、备选方案为什么不行；
- **【标准答案】**：完整高质量实现（非伪码）+ 实测输出；
- **【常见错误】**：面试/笔试中真实的翻车点（每题至少 2 个）。
选择题判分点：答案 + 一句"为什么对 + 干扰项为什么错"。简答题按标准 A 的话术结构作答。
