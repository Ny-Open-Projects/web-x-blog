# 题 5：预算与三条件终止

## 题目（15 分钟）

实现 `BudgetCounter`（线程安全的 token 预算计数器）与 `TerminationPolicy`（三条件终止组合器）：
① `BudgetCounter`：AtomicLong 累加（多 Agent 共享池场景），阈值判断，线程安全
② `TerminationPolicy`：三条件（模型完成声明/步数上限/预算耗尽）任一触发即终止，条件可扩展注册
③ 预算耗尽时的**优雅收尾**（输出当前进度与未完成事项，非抛异常）
要求：计数器支持多 Agent 共享池与任务独立池两种模式。

## 参考实现

```java
public class BudgetCounter {
    private final AtomicLong used = new AtomicLong();
    private final long limit;
    private final String poolId; // 共享池标识（多 Agent 共享 vs 任务独立，AD-500）

    public BudgetCounter(String poolId, long limit) { this.poolId = poolId; this.limit = limit; }

    /** 每轮响应后累加 usage；返回剩余额度 */
    public long addAndGet(long tokens) {
        long now = used.addAndGet(tokens);          // CAS 无锁（AD-275 线程安全）
        if (now > limit) throw new BudgetExceededException(poolId, now, limit);
        return limit - now;
    }
    public long used() { return used.get(); }
    public boolean exhausted() { return used.get() >= limit; }
}

public interface TerminationCondition {
    /** @return null=继续；否则返回终止原因 */
    String check(AgentContext ctx);
}

public class TerminationPolicy {
    private final List<TerminationCondition> conditions = new ArrayList<>();
    public void register(TerminationCondition c) { conditions.add(c); }  // 可扩展（AD-245）

    /** @return 终止原因；null=继续循环 */
    public String evaluate(AgentContext ctx) {
        for (TerminationCondition c : conditions) {
            String reason = c.check(ctx);
            if (reason != null) return reason;
        }
        return null;
    }
}

// 优雅收尾（预算耗尽 ≠ 报错）
public String gracefulShutdown(AgentContext ctx, String reason) {
    return "任务因[%s]提前终止。\n已完成：%s\n未完成：%s\n建议：%s"
        .formatted(reason, ctx.completedSteps(), ctx.pendingSteps(), ctx.nextSuggestion());
}
```

## 追问清单

1. 为什么 AtomicLong 而不是 synchronized？→ CAS 无锁吞吐（JC-046），竞争下 LongAdder 更优
2. 多 Agent 共享池的竞态场景？→ 并发累加超限的检查-扣减竞态（先 addAndGet 再判断仍有窗口），严格场景用信号量预留
3. 预算耗尽为什么优雅收尾而非异常？→ 收尾保留价值（已完成部分），异常丢上下文（AD-005/633 案例）
4. 条件如何扩展（如时间窗终止）？→ 策略注册（AD-245 组合器），不改循环代码
5. 预算池与重试的交互？→ 重试消耗预算（AD-303），预算压力收紧重试策略

## 常见错误

预算用普通 long（竞态）｜超限抛异常不收尾｜终止条件硬编码 if（不可扩展）｜共享池与独立池混用无区分。
