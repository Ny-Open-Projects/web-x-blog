# 附录 A-D —— P10 软实力、简历方法论、反问清单、备考计划

> P10 面试的技术部分只占 70%，剩下 30% 是"这个人能不能扛起一条技术线"的判断。
> 本附录解决被大多数候选人忽视的 30%。

---

## 附录 A：P10 级"软实力"题（总监面/交叉面必考）

### A.1 考察逻辑
P10 交叉面通常由另一条线的资深专家/总监进行，问题不再有标准答案，考察的是：
**判断力（怎么做取舍）、驱动力（为什么是你来做）、复制力（你的方法能不能教给团队）**。

### A.2 高频题与回答框架

**Q1：讲一个你最失败/最艰难的技术决策。**
框架（诚实 + 学习闭环）：背景与当时的约束 → 我怎么判断的 → 结果哪里错了 → 根因是信息不足/流程缺陷/个人盲区 → 之后建立了什么机制防止复发。
禁忌：把失败说成成功（"其实很成功"），或把责任推给环境。
加分：讲"信息完全时做了错决策"而非"信息不足导致失误"——暴露的是更深的认知盲区。

**Q2：你怎么做技术选型？举一个被你否决的方案。**
框架：候选方案矩阵（≥3 个）→ 评估维度（成本/团队/演进/退出成本）→ 决策与量化 → **重点讲被否决方案里"最诱人"的那个**——能说出"为什么不要它"才是判断力。

**Q3：你和业务方/产品对技术投入有分歧怎么办？**
框架：先翻译（把技术债翻译成业务风险语言：故障概率、需求响应速度）→ 给选项（方案 A 立刻上线带风险、方案 B 延期两周还清风险）→ 用数据（事故统计、压测数据）→ 设止损点（先 A 后 B 的分期承诺）。
核心语言：**P10 的技术方案必须让业务方能"读懂风险"**。

**Q4：你怎么带团队？怎么让团队技术成长？**
框架：机制 > 个人——code review 文化、技术评审门禁、分享机制、轮岗与背锅文化（给成长机会也给出错空间）；量化（多少人晋升/多少人成为某领域 owner）。
加分：讲一个"把平庸项目带出技术影响力"的实例。

**Q5：如果给你 10 个人和一年时间，你会做什么？**
框架：从"业务最重要的问题"倒推（不是从技术炫技倒推）→ 分季度目标 → 风险与里程碑 → 需要组织给什么支持。

**Q6：你如何看待 AI 对你们团队/行业的影响？（必考趋势题）**
参考第 10 章题 10.4.2，重点表达"已经在做"而不是"正在观察"。

### A.3 增补题（v1.1 扩充）

**Q7：你给公司"省过钱/赚过钱"吗？量化给我听。**
框架：选一个可审计的口径（资源成本 / 人力释放 / 收入或转化提升）→ 基线数字 → 动作 → 结果数字 → 佐证方式（账单对比/工单量/业务指标）。
示例骨架："客服 Agent 上线后人工会话占比 100%→40%，单会话成本 3 元→0.4 元（含模型与基础设施），季度省 XX 万，佐证是财务侧账单对比。"——**"佐证方式"这个词必须出现**，没有审计口径的数字在总监面前是空头支票。

**Q8：上级的技术决策你不认同，你怎么办？**
框架：① 先自我校验（我的信息是否比决策者全？反对的是目标还是路径？）→ ② 找对场合（一对一陈述，不动员他人）→ ③ 带着方案反对（给"如果按我的方案"的代价对比与验证方式）→ ④ 决策后全力执行 + 记录风险登记册（谁提过、什么条件下方案会失败，届时归位）。
禁忌：公开场合唱反调；"反正听他的"式躺平；事后"我早说过"。
加分金句："I disagree, but I commit——分歧要表达在决策前，承诺要给足在决策后。"

**Q9：你推动过什么规范/技术变革？怎么让团队真正落地而不是发个邮件？**
框架：动机（用数据证明问题存在）→ 最小可行版（先在 1 个团队试点出结果）→ 机制化（接入 CI 门禁/oncall SOP，让"不遵守有摩擦"而不是"只靠自觉"）→ 推广（试点数据 + 领导背书）→ 迭代（收集反对意见改进规范本身）。
加分：讲"规范落地率"的度量（如门禁拦截次数、规范覆盖率），说明你有运营思维而非发文思维。

**Q10：重大 P0 事故，你是事故负责人（IC），头 30 分钟做什么？**
框架（时间轴背诵）：0~5min 判级（影响面/止血优先级，拉群宣布自己是 IC 与沟通节奏）→ 5~15min 止血三选一（回滚/扩容/降级——**回滚通常是最快且最安全的选项**，谁最近改了什么第一优先怀疑）→ 15~30min 沟通（对内：专人跟进各止血路径；对外：统一话术告知业务方预期恢复时间，非最终原因不下结论）。
要点：IC 不亲自修代码——你的职责是"信息汇聚 + 决策 + 沟通"，同时指定一人做时间线记录（复盘素材）。
禁忌：一头扎进去自己排查（丢掉指挥位）；未定级先发全员公告；恢复后立刻谈根因（先恢复，后复盘）。

**Q11：你的技术深度和广度怎么权衡？**
框架：一句话定调——**"一深两宽"**：一个领域深入到源码/协议层（你的立身之本），两个相邻领域到架构与选型层（协作与判断），其余保持技术雷达灵敏度即可。
例证结构：深——举你吃得最透的一个系统（从业务到 JVM 都能讲）；宽——举你两次"用广度救场"的经历（如用对中间件选型避免了错误自研）。
加分：反向承认（"广度是深度的副产品，追逐广度本身是陷阱——我的第二三领域都是被第一个领域的问题牵引出去的"）。

**Q12：为什么你应该定级 P10？（终极题，答错直接定级失败）**
框架：三层递进——① **证明能力已到位**：用 2~3 个"超出当前职级职责"的案例（你已经在做 P10 的事：跨团队架构、平台化治理、组织能力建设）；② **证明能力不可替代**：你的方法论/资产（规范、平台、人才梯队）离开你会断代；③ **证明投入产出**：给你 P10，公司能在哪个业务问题上的期望收益变大（把职级谈判翻译成业务承诺）。
禁忌：谈工龄、谈辛苦、谈"别人也这样"；和 peer 比较。
核心逻辑一句话："**职级不是给过去的补偿，是对未来承诺的定价。**"

## 附录 B：简历与项目包装方法论（STAR-R 法则）

### B.1 STAR-R 结构
- **S**ituation：业务背景与量级（一句话，数字说话）；
- **T**ask：你负责的部分与目标（明确边界，不贪功）；
- **A**ction：关键决策与方案（写"决策"不写"劳动"，1-3 个即可）；
- **R**esult：量化结果（QPS/RT/成本/稳定性，改造前后对比）；
- **R**eflection：沉淀（规范/工具/方法论——证明可复制）。

### B.2 改写示例
- 病句："负责订单系统的开发和优化。"
- 改后："负责订单核心链路（日均 8000 万单）：主导分库分表改造（单表 8 亿行→16 库 64 表，双写灰度 4 周零事故），写 TPS 提升 3 倍；引入多级缓存使详情页 P99 从 45ms 降至 8ms；沉淀团队数据迁移工具，复用于 5 个业务线。"

### B.3 P10 简历的三条军规
1. **每条都带数字**：没有数字的项目经历在 P10 简历里约等于零；
2. **写决策不写堆砌**：技术名词列表是 P5 简历，"在 X 约束下选 Y 而放弃 Z"是 P10 简历；
3. **留好追问钩子**：简历上每个亮点都会被深挖，写你真能讲 20 分钟的，删掉只能讲 2 分钟的。

## 附录 C：面试结尾"反问面试官"清单（按目的选用）

**判断团队质量（聪明反问）**
1. "团队目前最大的技术挑战是什么？"（答案空泛 = 团队无深度）
2. "这个岗位上一个做到 P10 的人是怎么失败的/离开的？"（敢回答 = 文化健康）
3. "技术方案评审在团队是怎么运作的？最近一次被否掉的方案是什么？"

**判断空间与风险**
4. "未来一年这个方向的资源投入和预期目标？"
5. "团队与业务方对技术债的处理机制是什么？"

**展示自己的思考（降维反问，慎用但高分）**
6. "我理解贵团队在 X 场景用了 Y 方案，我们在类似场景踩过 Z 坑，想听听你们的取舍……"（**先展示判断再提问，这是 P10 间平等对话的信号**）

**禁忌**：第一轮反问薪资福利细节（HR 轮再谈）、反问"公司加班吗"这类封闭问题。

## 附录 D：30/60/90 天备考计划（从零基础 → P10 战备）

> 前提假设：每天可投入 2~3 小时。若基础薄弱，先完成"第 0 月"。

### 第 0 月（可选）：基础补课（零基础者）
- 目标：能独立写出多线程 + MySQL + Redis 的小项目（如短链服务）；
- 材料：本卷第 1/2/5/6 章的"零基础卡片"部分 + 官方入门教程；
- 验收：不看书能复述每章的"一页速记卡"。

### 第 30 天：基础与原理（第 1~3 章）
- 每章读 2 遍：第 1 遍理解，第 2 遍背诵速记卡 + 追问链图谱；
- 动手：Arthas 完成一次本地 OOM 排查模拟（附材料在 notes/）；手写 DCL 单例、手写简化 AQS；
- 验收：HashMap put 流程、锁升级、GC 流程可白板画图讲解。

### 第 60 天：存储与架构（第 4~8 章）
- 每章速记卡 + 一道压轴题的完整口头表达（录音自评）；
- 动手：搭建 Nacos+Sentinel+RocketMQ 的 demo，跑通限流与事务消息；
- 准备 3 个"自己的故事"：一次事故复盘、一次技术选型、一次性能优化（STAR-R 改写，见附录 B）；
- 验收：缓存一致性矩阵、分布式事务矩阵能脱稿讲清取舍。

### 第 90 天：场景题 + 模拟面试（第 9~10 章 + 附录）
- 五步法练习：每天 1 道场景题（短链/秒杀/Feed/红包/排行榜），30 分钟白板推导 + 10 分钟自评；
- AI 章：跑通一个 Spring AI + 向量库的 RAG demo（P10 差异化分）；
- 模拟面试 ≥4 场（同事/AI 陪练），录音复盘：口头禅、逻辑断点、时间控制；
- 简历定稿：每条经历过 STAR-R 与追问压力测试；
- 验收：任选一场景题，5 分钟澄清 + 15 分钟设计 + 10 分钟难点攻防。

### 每日节奏建议
- 30 分钟：过 1 张速记卡（滚动复习，艾宾浩斯）；
- 60~90 分钟：本章正文深读 + 追问链自问自答；
- 30 分钟：动手实验/写复盘笔记。

## 附录 E：全卷速查（总速记卡 · 十章一图）

1. **Java 基础**：HashMap 高16异或低16、2 的幂、树化阈 8（第 9 插触发）；CHM CAS+桶锁；泛型擦除 PECS。
2. **并发**：volatile 可见+有序非原子；线程池先核再队后非核再拒；AQS=state+CLH；CF 必自定义线程池。
3. **JVM**：TLAB→Eden→Survivor→Old；G1 Region+SATB；ZGC 着色指针+读屏障；排查三板斧 jstat/jmap/Arthas。
4. **Spring**：三级缓存解循环依赖+AOP；AOP 失效=绕过代理；先库后删事务+afterCommit 发消息；自动装配=imports+条件注解。
5. **MySQL**：B+ 树矮胖；MVCC=版本链+ReadView（RC 每语句 RR 每事务）；两阶段提交；分库分表先榨干单库。
6. **Redis**：穿透挡、击穿合、雪崩抖；先库后删+binlog 异步删+TTL 兜底；锁 NX+PX+Lua+看门狗。
7. **MQ**：至少一次+消费幂等；不丢三端（ack=all/3 副本/手动提交）；事务消息=半消息+回查。
8. **分布式**：CAP 分区二选一；TCC 三坑（空回滚/悬挂/幂等）；SLO 错误预算；拆服务跟随团队边界。
9. **高并发**：五步法答题；漏斗削峰；防超卖三道锁；QPS=线程数/RT；大对象三宗罪。
10. **AI**：RAG=检索+生成+引用；Agent=规划+记忆+工具+编排+护栏+观测；成本四刀；人审出口必须有。
