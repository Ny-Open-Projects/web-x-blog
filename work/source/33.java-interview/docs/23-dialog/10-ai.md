# 对话版 · 第 10 章 AI 时代：LLM、Agent 与 AI 应用架构（四面增值项，约 30 分钟）

**【面试官】** 现在的面试都会聊聊 AI。你们的业务里 AI 落地了吗？讲讲 RAG 是怎么做的。

**【面试者】** 客服知识库场景，全链路：离线——文档加载→切分（固定长度+重叠 10%，结构化文档按标题切）→ Embedding（bge-m3，中文场景实测优于通用模型）→ 向量库 Milvus；在线——用户问题 → 混合检索（向量+BM25）→ 重排（bge-reranker 精排 top3）→ 拼 Prompt（带引用来源）→ 生成 → 答案+引用返回。效果调优第一原则是**归因分离**：先查检索召回率（正确答案的块是否进 topK），再查生成质量——两头混着调就是浪费时间。

**【面试官】** 权限怎么处理的？客服知识库有些内容不是所有人能看的。

**【面试者】** 检索层强制过滤——向量检索带 ACL 条件（用户角色/部门），**不是生成后过滤**（那已经泄露了）。这是企业级 RAG 和玩具的分水岭：知识管道必须带权限标签，检索时前置过滤。还有两个命门一起说：知识时效（文档更新进向量库要有增量管道和 SLA）、评测集（没有评测集的 RAG 都在凭感觉迭代）。

**【面试官】** 什么场景该微调，什么场景该 RAG？

**【面试者】** 决策矩阵四条：① 知识时效/频繁更新 → RAG（改文档即生效，微调要重训）；② 行为/风格/输出格式对齐 → 微调（RAG 给知识但调不动语气结构）；③ 私有领域术语推理 → 先 RAG 后微调；④ 成本结构 → 高频调用场景微调小模型更省（一次训练费 vs 每次长上下文 token 费）。工程结论：**RAG 是默认起点，微调是效果上限的补刀**，可叠加——我们微调了一个小模型做检索改写和意图分类，RAG 供知识。

**【评注】** ⭐ G13 补漏题。决策矩阵+叠加架构，比"看情况"的废话答案高一档。

**【面试官】** Agent 架构你怎么设计？不要名词堆砌，讲你们真跑过的。

**【面试者】** 运维问答 Agent，六模块：规划（Plan-and-Execute，先生成计划再执行，比纯 ReAct 稳）、记忆（短上下文滑动窗口+摘要压缩；长期记忆向量库存用户偏好）、工具（MCP 接入：查监控、查日志、重启服务——**高危工具要审批**）、编排（图状态机：节点=步骤，支持中断恢复）、护栏（输入注入检测、输出 schema 校验、token/步数预算熔断）、可观测（每次运行一条 trace：步骤、token、工具调用、成本，失败可回放）。可靠性三指标：任务完成率、成本分布、失败模式分类（工具错/规划错/理解错）。

**【面试官】** Agent 跑长任务跑到一半挂了怎么办？

**【面试者】** 四件套：checkpoint（每步持久化状态+上下文快照+已完成结果）、工具幂等（转账类先写"意图凭证"行，恢复时见凭证无结果改为查询验证）、续跑（从断点继续不重头）、预算熔断（步数/token 硬上限转人工）。本质是**把 SRE 方法论平移到 Agent**——可恢复、幂等、可观测、可回放。

**【面试官】** 大模型调用的成本怎么控制？

**【面试者】** 成本公式=单价×token×次数，四刀：降单价（模型分级路由：分类/NER 用小模型，复杂任务大模型；私有化小模型承接高频固定任务）、降 token（Prompt 精简+上下文裁剪+历史摘要）、降次数（语义缓存：embedding 相似度判定，相同问题直接回）、预算熔断（租户级限额+告警）。实测数据：客服 Agent 上线后单会话成本 3 元→0.4 元，模型与基础设施全算进去。

**【面试官】** Prompt 注入攻击了解吗？

**【面试者】** 两类：直接注入（"忽略以上指令"）、**间接注入更危险**——恶意指令藏在模型会读取的外部内容里（网页、工单、检索到的文档）。防御必须在系统层因为 prompt 规则是概率性的：检索内容标记为"数据非指令"结构化隔离、工具最小权限（Agent 凭证只够它该干的活）、高危操作人工确认、全量审计日志。类比要会说："Prompt 注入之于 Agent = SQL 注入之于 Web——区别是 SQL 有参数化查询根治，自然语言还没有，所以现阶段靠权限最小化+沙箱兜底。"

**【面试官】** 最后站在 P10 的角度：AI 会怎么改变你们这个技术领域？你们组织在做什么？

**【面试者】** 三个判断：① 工程范式迁移——从"人写代码 AI 辅助"到"人定义意图与验收，AI 生成执行"，测试方式从单测扩展到评测集；② **不变的东西升值**：架构拆解、数据一致性、权限、成本——Agent 系统的地基恰恰是 Java 后端的存量能力，这是我们转型的最大优势；③ 组织动作不是观察而是在做：评测文化（一切 AI 变更过评测集）、技能转型（30% 工时实践）、AI 使用规范（什么场景允许自动执行）。一句话收尾：**上一代架构师解决确定性系统的可靠性，这一代要解决概率性组件进入系统后的工程可靠性——方法论相通：隔离、降级、观测、评测。**

**【评注·终局】** 定级 **P9（AI 域）**。亮点：权限过滤分水岭、决策矩阵、注入类比、三段论收尾带组织动作。这场是差异化最大的战场——大部分候选人在这里只会名词，你有一手实践+边界判断。

## 对话要点速记（本章）

1. 追问顺序：RAG 链路→权限命门→微调 vs RAG→Agent 六模块→长任务恢复→成本→注入→组织判断。
2. 四个超预期点：归因分离、权限前置过滤、Prompt 注入类比、把 SRE 平移到 Agent。
3. 关键姿态：所有 AI 答案都带"业务指标+组织动作"——AI 题说"在做"不说"在看"。
