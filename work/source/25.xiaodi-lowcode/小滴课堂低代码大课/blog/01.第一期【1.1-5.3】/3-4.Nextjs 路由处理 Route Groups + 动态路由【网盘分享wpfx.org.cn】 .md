# Nextjs 路由处理 Route Groups + 动态路由

> **导语**：当路由页面变多，路径会又长又乱。本节讲解 Next.js 的**路由组（Route Groups）**如何给路由分类却不污染 URL，以及**动态路由**（单段 `[slug]` 与批量 `[...slug]`）如何根据后端数据动态渲染页面。

建议先看《Nextjs 应用路由器和导航跳转》，已掌握基础路由与嵌套路由。本文工程依赖见 `代码（已8期）/代码（已8期）/3-4/package.json`。

## 正文

### 路由分类带来的「长路径」问题

假设按业务把路由分两类：

- `father router 一`：`about1`、`about2`
- `father router 二`：`personal1`、`personal2`

按嵌套规则，访问地址会变成 `/father router 一/about1`、`/father router 二/personal2`——多层嵌套导致 URL 过长、繁琐。

### Route Groups（路由组）

Next.js 提供路由组：把文件夹名用**英文括号**包裹即可标记为路由组，括号内的层级**不出现在 URL 中**。

```
src/app/(father router 一)/about1/page.tsx
src/app/(father router 二)/personal2/page.tsx
```

访问时直接是 `/about1`、`/personal2`，中间那段分类路径被隐藏。注意：**必须用英文括号**，中文括号会报错。

### 动态路由（单段）

若要根据后端返回的数据动态展示页面，就用动态路由：把文件夹名改成 `[slug]`（`slug` 可换成别的名字）。

```tsx
// src/app/personal1/[slug]/page.tsx
export default function Page({ params }: { params: { slug: string } }) {
  console.log('当前动态路径', params.slug);
  return <div>动态路径为：{params.slug}</div>;
}
```

访问 `/personal1/a` 时，`params.slug` 即为 `"a"`；改成 `/personal1/b` 则取到 `"b"`。

### 批量动态路由

要支持任意多层路径（如 `/personal1/a/b/c`），把文件夹名改为 `[...slug]`（三个点）：

```tsx
// src/app/personal1/[...slug]/page.tsx
export default function Page({ params }: { params: { slug: string[] } }) {
  console.log('当前动态路径数组', params.slug); // ["a","b","c"]
  return <div>动态路径：{params.slug.join('/')}</div>;
}
```

此时 `params.slug` 是**字符串数组**，无论追加多少段都能打印出来。要点：**单段用 `[slug]`，批量用 `[...slug]`**。

### 其他高级路由

官网还提供：

- **并行路由（Parallel Routes）**：同一页面同时渲染多个路由（如 `team` 与另一页面并排显示）；
- **路由拦截 / 中间件**：如未登录禁止跳转某页；
- **路由处理程序（Route Handlers）**。

> 提示：中文官网文档更新往往滞后，App Router 的不少细节建议查**英文官网**获取完整教程。

## 小结

1. 路由组用 `(文件夹名)` 包裹，分类但不污染 URL，须用英文括号。
2. 动态路由单段用 `[slug]`，`params.slug` 为字符串。
3. 批量动态路由用 `[...slug]`，`params.slug` 为字符串数组，支持任意多层。
4. 路由组隐藏分类层级，解决长路径问题。
5. 并路由、路由拦截、中间件可查官网（英文更全）。
6. 单段与批量的区别仅在文件名是否带 `...`。
