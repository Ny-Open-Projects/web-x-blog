# Next.js 接口请求数据与项目部署

> **导语**：Next.js 里取服务端数据和写普通 React 组件不太一样：`fetch` 可以直接用，组件可以声明成 `async`，数据会在服务端就渲染进 HTML。本文先在页面上请求真实接口并渲染标题，再讲清楚为什么 Network 面板里看不到这条请求、它对 SEO 有什么好处，最后走一遍 `pnpm build` 与 `npm start` 的生产部署流程。

## 前置知识

建议先读《Nextjs 路由跳转传递和接收参数》，熟悉 App Router 下的页面文件与路由跳转。另外需要了解 `async` / `await`、`fetch` 与 `Response.json()` 的基本用法。本篇配套工程见 `代码（已8期）/代码（已8期）/3-6/package.json`。

### 定义 getData：fetch 不需要引入

在 Next.js 的服务端组件里，`fetch` 是全局可用的，不用 `import`。我们定义一个异步方法请求官网提供的 Hot Product 接口，并对返回结果做两层防御：

```ts
// 接口地址由环境变量注入，示例不绑定任何具体域名
const HOT_PRODUCT_API = process.env.HOT_PRODUCT_API as string;

async function getData() {
  const response = await fetch(HOT_PRODUCT_API);

  if (!response.ok) {
    throw new Error('未找到');
  }

  const result = await response.json();

  if (!result.data) {
    throw new Error('error 404');
  }

  return result.data;
}
```

- 先用 `response.ok` 判断请求是否成功，失败就 `throw new Error(...)`；
- 再用 `response.json()` 把响应体转成 JSON；
- 数据体里若没有 `data`，同样抛错；
- 一切正常才 `return`，把数据交回给页面。

`HOT_PRODUCT_API` 用环境变量占位，实际值就是课程中官网提供的 Hot Product 接口地址。

### 在页面中 await 并渲染

页面组件本身声明成 `async`，直接 `await getData()` 即可：

```tsx
export default async function About() {
  const data = await getData();
  const title = data[0].title;

  return <div>{title}</div>;
}
```

运行后终端就能打印出接口返回的课程数组；取第 0 条的 `title` 渲染到 `<div>` 里，刷新页面即可看到标题。写法上比「`useEffect` 里发请求 + `useState` 存数据」简洁得多，因为数据获取发生在服务端。

### 为什么 Network 里看不到请求

打开 DevTools 的 Network 面板，会发现并没有这条接口请求；再查看网页源代码，页面里显示的文字却能直接搜到。这正是服务端渲染（SSR）的作用：HTML 在服务端就拼装完成，浏览器拿到的是已经含内容的成品。

对官网、内容站这类页面，描述性文字越多，越有利于搜索引擎抓取与收录，搜索结果排名也更靠前。这也是低代码平台最终选择用 Next.js 承载发布页的原因——发布出去的 H5 页面需要被搜索引擎友好地索引。

### 构建与部署

代码开发完成后：

```bash
pnpm build
```

构建会重新生成 `.next` 目录，里面是生产环境可运行的代码。把它上传到服务器后，进入对应路径执行：

```bash
npm start
```

项目即以生产模式运行，访问页面验证即可。注意先把本地的 `next dev` 停掉，避免端口冲突；课程里演示时访问 `/person-one` 等路由都能正常打开，说明构建产物没问题。

## 小结

- Next.js 服务端组件里 `fetch` 全局可用，组件可声明为 `async` 直接 `await` 数据。
- 取数要做两层判断：`response.ok` 与业务数据 `result.data`，失败尽早抛错。
- 服务端渲染下 Network 看不到接口请求，但查看源码能看到完整内容，利于 SEO。
- `pnpm build` 生成 `.next` 产物，上传服务器后用 `npm start` 启动生产服务。
- 部署前先停掉开发服务器，避免端口占用。
