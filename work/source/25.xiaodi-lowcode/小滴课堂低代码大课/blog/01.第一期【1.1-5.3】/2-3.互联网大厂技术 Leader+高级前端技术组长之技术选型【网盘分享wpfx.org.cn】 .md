# 互联网大厂技术 Leader+高级前端技术组长之技术选型

> **导语**：技术选型是每个团队都要面对的重要任务，作为组长更要主导整理一套方案与规范。本文从「项目、团队、技术」三个维度，给出可落地的选型标准，帮你避开「开发到一半才发现框架不可行」的坑。

## 前置知识

建议先看《工作协同—提高团队开发工作效率》，了解协作工具链。选型决策需结合团队实际。

## 正文

### 选型是组长主导的系统工程

技术选型不只是选一个框架，还包括代码开发规范、辅助文档工具等。过程中要在各种技术间权衡，根据团队整体情况做决策。

选型标准分三个维度：**项目方面**、**团队方面**、**技术方面**。

### 维度一：项目方面

要明确项目的周期与特点。

- **周期长短**：一两天能完成的小型活动页，选擅长/提效快的框架即可（如用 Vite 创建 Vue/React 项目）；周期长、规模大的正式项目，要从整体角度选型。
- **规模与重要程度**：规模大就要慎重选技术栈，规模小则灵活。
- **是否要求 SEO / 动态渲染**：
  - 需要 SEO 且要动态渲染 → 选服务端渲染框架。团队倾向 React 用 **Next.js**，倾向 Vue 用 **Nuxt**。
  - 需要 SEO 但数据不需要动态渲染（简单页面）→ 直接用低代码平台发布即可。
- **是否跨端**：要支持 App / 小程序 / iOS / Android，跨端首选 **Uni App**，或 **Flutter**、**React Native**。

### 维度二：团队方面

主要看团队成员因素与招聘成本。

- **成员技术栈**：选的技术栈应让团队大部分人掌握。例如团队多会 Vue、少会 React，项目尽量选 Vue；若选了某栈，最好有「兜底人」——比如团队里有一个极熟悉 Vue 的人，出问题有人扛。
- **招聘成本**：作为管理者要算招聘账。人员变动时，如果组内只有一人会某冷门技术（如 Angular），他突然离职又招不到替代，项目维护和迭代会非常被动。冷门技术既影响招聘成本，也影响项目可持续性。主流仍是 Vue / React。

### 维度三：技术方面

评估易用性、可维护性、可拓展性、性能、技术成熟度、跨平台兼容、周边生态等。

- **参考 GitHub Star 数 / npm 下载量**：最受欢迎、用户多的技术通常更可靠，是重要的参考依据（如组件库可去 npm 官网或 GitHub 官方地址查下载记录与活跃度）。
- **可维护性与生态**：引用第三方 UI 组件库时，要确认它是否还在维护。若组件库停止维护，出问题无法解决，项目后续迭代要重写大量代码，代价很高。
- **兼容性**：该技术能否与其他技术栈兼容，避免踩坑。

## 小结

1. 选型是组长主导的工程，涵盖框架、规范与工具。
2. 项目维度看周期、规模、SEO/动态渲染需求、是否跨端。
3. 团队维度看成员技术栈、是否有兜底人、招聘成本，慎选冷门技术。
4. 技术维度看易用性、可维护性、性能、成熟度与生态活跃度。
5. GitHub Star 与 npm 下载量是重要的客观参考。
6. 选型失误会导致开发中途返工，务必前期定清楚。
