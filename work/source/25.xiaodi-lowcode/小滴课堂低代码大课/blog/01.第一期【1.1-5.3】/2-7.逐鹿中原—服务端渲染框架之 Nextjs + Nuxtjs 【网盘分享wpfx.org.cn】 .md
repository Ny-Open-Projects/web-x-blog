# 逐鹿中原—服务端渲染框架之 Nextjs + Nuxtjs

> **导语**：服务端渲染（SSR）对 SEO 至关重要。本文对比两大 SSR 框架——React 系的 Next.js 与 Vue 系的 Nuxt，从 GitHub 热度、定位、特性到本大课的选型，帮你理解「为什么需要 SSR 框架」。

## 前置知识

建议先看《群雄纷争—高级+全栈前端工程师必学之 Express+Koa+Nestjs》，区分 NestJS（Node 后端）与 Next.js（React SSR）。本文的 Next.js ≠ NestJS。

## 正文

### 为什么需要 SSR

打开小滴课堂官网（用 Next.js 开发）查看源代码，可见网页文字已在 HTML 中一五一十渲染出来——这正是服务端渲染的优势：搜索引擎能直接抓到内容，**利于 SEO**，让网站更容易被搜到。

### 两者热度（GitHub Star）

- **Next.js**：约 114k
- **Nuxt**：约 48k（不到一半）

显然 Next.js 更受开发者欢迎。

### Next.js（React 系）

- 由 **Vercel** 团队开发，2016 年开源于 GitHub，现主流版本为 **14**；
- 是「用于生产环境的 React 框架」——注意 React 严格说是 JS 库，Next.js 才是框架；
- 可开发 React 静态页 / SPA 单页应用，也可在其内开发后端数据接口，作为全站 Web 应用；
- 提供生产环境所需的所有功能与最佳开发体验：静态 + 服务端融合渲染、智能打包、路由预取等，**几乎零配置**；
- 熟悉 React 的开发者做 Web 全站或服务端渲染应用，建议选 **Next.js**；
- 本大课发布页（C 端 H5）就是用 Next.js 开发的。

### Nuxt（Vue 系）

- 2016 年发布，现版本约 **3.8**，是 Vue.js 生态下的应用框架，提供更丰富高级的功能；
- 熟悉 Vue 的开发者做 Web 全站或服务端应用，建议选 **Nuxt**；
- Nuxt 相对坑略多，可结合 GitHub issue 与社区反馈解决（上一门前端大课已踩过并解决）。

### 选型建议

Next.js 更成熟、生态更完善，因此服务端渲染场景更推荐 Next.js。但选型仍取决于团队主力框架：React 团队用 Next.js，Vue 团队用 Nuxt。

## 小结

1. SSR 让内容直出 HTML，利于 SEO（以小滴课堂官网为例）。
2. 热度：Next.js(114k) 远超 Nuxt(48k)。
3. Next.js 由 Vercel 开发、2016 开源、现 V14，是生产级 React 框架。
4. Nuxt 是 Vue 生态的 SSR 应用框架，现约 3.8 版。
5. React 团队选 Next.js，Vue 团队选 Nuxt；Next.js 更成熟。
6. 本大课 C 端 H5 选用 Next.js。
