# 项目部署上线—构建后端镜像的Dockerfile配置

> **导语**：前面把 Dockerfile 的语法和指令过了一遍，这一集动手写真正能用的 `Server.Dockerfile`，把 NestJS 后端服务打成镜像。本文逐行拆解 FROM、WORKDIR、COPY、镜像源、pnpm 安装、share/server 构建、EXPOSE 与 CMD，并说明为什么后端前面还要再架一层 Nginx 做反向代理与负载均衡。

- 已了解 Dockerfile 的常用指令与自定义镜像的作用，可回顾《项目部署上线—构建自定义镜像的利器 Dockerfile》《项目部署上线—构建自定义镜像Dockerfile的配置介绍》。
- 知道本项目是 pnpm-workspace 多包工程，后端依赖 `share` 公共包里的 TypeScript 类型。
- 了解 Docker 镜像、容器、端口映射的基本概念。

## 正文

### 文件放哪、叫什么

在工程根目录新建一个 `Server.Dockerfile`。注意命名：**首字母 `Server` 要大写**，编辑器才能识别并显示 Docker 图标。后面几集还会继续写 `Release`、`ReleaseNginx`、`ServerNginx` 等几份，先把后端这份做出来。

### 逐行拆解 Server.Dockerfile

```dockerfile
FROM node:18
WORKDIR /app
COPY . .

# 将 npm 源指向国内镜像以加速下载（命令：npm config set registry <镜像源地址>）
RUN npm install -g pnpm
RUN pnpm install

# server 依赖 share 里的 TS 类型，先打包公共包，再构建后端
RUN pnpm build:share
RUN pnpm build:server

EXPOSE 3000
CMD ["pnpm", "start:server"]
```

逐条看：

- `FROM node:18`：NestJS 是 Node 框架，跑起来必须有 Node 环境，所以基础镜像选 Node 18。指令一律大写。
- `WORKDIR /app`：设定工作目录，容器从这里启动、按这个路径找代码。
- `COPY . .`：把当前工作区的代码复制进容器。需要自动解压压缩包的场景可以改用 `ADD`，本例用 `COPY` 即可。
- 设置国内 npm 镜像源：用 `npm config set registry <镜像源地址>` 把源指向国内，下载依赖更快（注意命令是 `config`，别拼错）。
- `npm install -g pnpm` + `pnpm install`：全局装 pnpm，再安装依赖。
- `pnpm build:share` / `pnpm build:server`：这是本项目的关键点——后端用到了 `share` 公共包里的大量 TypeScript 类型，**必须先把 share 打包出来**，再构建 server，否则编译期找不到类型。
- `EXPOSE 3000`：声明后端服务端口。
- `CMD ["pnpm", "start:server"]`：数组形式，第一个元素是包管理器 `pnpm`，第二个是启动脚本。

这些脚本名不是随手写的，都能在 `代码（已8期）/23-3/lowcode/package.json` 里对上：

```json
{
  "scripts": {
    "build:share": "pnpm --filter share run build",
    "build:server": "pnpm --filter server run build",
    "start:server": "pnpm --filter server run start:prod"
  }
}
```

镜像构建完成后，用对应的 docker 命令生成容器并运行，后端服务就起来了。

### 为什么后端前面还要一层 Nginx

讲师在结尾点出了下一步的动机：光把 server 跑起来还不够，正式部署会在它前面再加一层 **Nginx** 做反向代理。好处有两个：

- 请求先到 Nginx，再由它代理到**多个**后端服务器实例，减轻单台服务器的压力；
- Nginx 配置里支持**负载均衡**，高并发场景下能把流量摊开。

所以这一集是「先有后端镜像」，下一集再补「后端 Nginx 镜像」，两者配合才算完整的后端部署单元。

> 配套资料：部署相关的其余 Dockerfile 与编排文件见 `代码（已8期）/23-3/lowcode/` 下的 `packages/release`、`packages/server` 等目录。

## 小结

- 文件名用 `Server.Dockerfile`（首字母大写），放在工程根目录。
- `FROM node:18` 提供 Node 环境，`WORKDIR /app` 定工作目录，`COPY . .` 复制代码。
- 设国内 npm 源、全局装 pnpm，再 `pnpm install` 装依赖。
- 顺序不能错：先 `build:share` 打包公共包，再 `build:server` 构建后端，最后 `CMD` 启动。
- `EXPOSE 3000` 声明端口；前面再加 Nginx 做反向代理与负载均衡。
