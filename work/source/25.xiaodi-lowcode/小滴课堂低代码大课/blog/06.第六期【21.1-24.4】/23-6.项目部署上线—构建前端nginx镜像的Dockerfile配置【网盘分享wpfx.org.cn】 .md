# 项目部署上线—构建前端 Nginx 镜像的 Dockerfile 配置

> **导语**：发布页是 Next.js 服务端渲染项目，不能像静态站点那样丢个 `dist` 就完事，前面挂一层 Nginx 做反向代理，才能横向扩到多台服务器、做负载均衡。本文讲清第四个容器镜像怎么配：新建 `release.nginx.dockerfile` 与 `release.nginx.conf`、为什么服务名必须改、以及服务器 IP 为什么一定要换成自己的。

## 前置知识

建议先读《项目部署上线—构建前端发布Nextjs镜像的Dockerfile配置》，此时发布页自身的镜像已构建完成。另需了解 Dockerfile 基础镜像、`COPY` 配置文件、`EXPOSE` 端口，以及 Nginx 反向代理与 upstream 的基本概念。配套工程见 `代码（已8期）/代码（已8期）/23-6/lowcode/`。

## 正文

### 为什么要给发布页单独配一层 Nginx

发布项目是服务端渲染的，运行在自己的容器里。前面挂一个 Nginx 反向代理容器后，就能把请求转发到后端多个实例，实现负载均衡，也方便后续横向扩容。

到此这套系统一共四类容器：后端服务、后端 Nginx、发布页（Next.js）、发布页 Nginx。每个容器各自监听 80 端口，互不冲突——端口是容器内部的，由 Docker 网络区分。

### 新建 release.nginx.dockerfile

在根目录新建 `release.nginx.dockerfile`，内容可以从上一节的 `server.nginx.dockerfile` 复制过来再改：

- **基础镜像不变**，依旧是 Nginx 镜像；
- **复制的配置文件要换成 release 对应的**：不再 `COPY server.nginx.conf`，而是 `COPY release.nginx.conf`；
- **容器内目标路径保持一致**，沿用上一节 `server.nginx.dockerfile` 里写好的那个路径即可；
- **同样 `EXPOSE 80`**，与另外三个容器保持统一。

这里没有贴具体 Dockerfile 全文，是因为配置片段以课程源码为准；复制后逐行核对「文件名」与「路径」两处，比照抄一份容易出错。

### 新建 release.nginx.conf 并改服务名

同目录再新建 `release.nginx.conf`，把上一节的 Nginx 配置复制过来。真正需要改的是**代理目标的服务名**：后端那层 Nginx 代理已经占用了原来的名称，发布页这层必须改成 `release`，否则两个 upstream 撞名，请求会转错地方。

另外提醒一处容易踩的坑：配置里写的服务器 IP，是讲师备课时临时使用的地址。等到真正部署上线、走完一键部署链路时，一定要改成自己阿里云服务器的 IP。老师那台服务器课程结束后会挪作他用，既没有权限也访问不到，照抄只会连不上。

### 至此镜像全部就绪

这一节配完，需要运行在服务器上的容器镜像就全部构建完成了：

| 容器 | 作用 |
| --- | --- |
| server | NestJS 后端服务 |
| server nginx | 后端反向代理 |
| release | Next.js 发布页（SSR） |
| release nginx | 发布页反向代理、负载均衡 |

后续用 docker 命令把这些 Dockerfile 构建成镜像、再运行成容器，发布页与后端服务就都能跑起来了。发布页子项目在根 `package.json` 里的脚本如下，构建时会用到：

```json
{
  "scripts": {
    "run:release": "pnpm --filter release run dev",
    "build:release": "pnpm --filter release run build",
    "start:release": "pnpm --filter release run start"
  }
}
```

## 小结

- 发布页是 SSR，需要独立 Nginx 容器做反向代理与负载均衡。
- `release.nginx.dockerfile` 由 `server.nginx.dockerfile` 复制改造：基础镜像不变、换 `release.nginx.conf`、同样 `EXPOSE 80`。
- `release.nginx.conf` 必须把代理服务名改成 `release`，避免与后端 Nginx 代理撞名。
- 配置里的服务器 IP 是备课临时值，上线前务必替换成自己的阿里云服务器 IP。
- 四类容器镜像至此全部构建完成，下一步是用 docker 命令统一编排运行。
