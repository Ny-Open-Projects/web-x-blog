# 项目部署上线：Docker Compose 运行多容器的配置

> **导语**：几个镜像分别构建好之后，总不能一个个手动 `docker run`。本文用一份 `docker-compose.yml` 把后端、后端 nginx、发布页前端、前端 nginx 四个容器一次性拉起来，讲清 `image` 变量映射、`restart: always`、端口映射为什么是 `5001:3000` 这种写法，以及别把「镜像」和「容器」搞混。最后串起云效一键部署的 DevOps 闭环。

## 前置知识

- 建议先了解《项目部署上线—运行容器Docker-compose的介绍和使用》，熟悉 Docker Compose 的启动命令与基本结构。
- 建议先了解《项目部署上线—构建后端镜像的Dockerfile配置》与《项目部署上线—构建前端发布Nextjs镜像的Dockerfile配置》，四个容器对应的镜像正是由这些 Dockerfile 构建出来的。

## 正文

### 一份文件，四个容器

在项目根目录新建 `docker-compose.yml`（配套代码 `代码（已8期）/代码（已8期）/24-2/lowcode/docker-compose.yml`），完整配置如下：

```yaml
version: '3'
services:
  backend:
    image: ${backend_tag}
    restart: always
    ports:
      - "5001:3000"
  backend_nginx:
    image: ${backend_nginx_tag}
    restart: always
    ports:
      - "5000:80"
  frontend:
    image: ${frontend_tag}
    restart: always
    ports:
      - "4001:3000"
  frontend_nginx:
    image: ${frontend_nginx_tag}
    restart: always
    ports:
      - "4000:80"
```

`version` 与 `services` 的含义上一节已讲过；`services` 底下并列配置四个服务，就是四个容器：后端、后端 nginx、前端（发布页）、前端 nginx。

### image 为什么是变量

`image: ${backend_tag}` 这类写法不是镜像的真实名字，而是做了一层**变量映射**：这些镜像由对应 Dockerfile 构建出来（例如 `server.Dockerfile`），但课程后续用阿里云云效来执行构建与部署，镜像会保存在阿里云的**镜像仓库**里，因此 `docker-compose.yml` 里依赖的镜像名要按云效中设置的标签变量来填。

这里特别容易混：**Dockerfile 构建出来的是镜像，Docker Compose 运行起来的是容器**。如果镜像只保存在自己的服务器上，你可能会直接写死一个 `server-image` 之类的名字；走云效时则换成变量，听不懂可以先放一放，等讲云效拉取镜像时再回来看这段。

### 端口映射：外面几号、里面几号

`ports` 的写法是 `"宿主机端口:容器端口"`，四个服务要一一对应各自 Dockerfile 里声明的端口：

| 服务 | 宿主机端口 | 容器端口 | 对应 Dockerfile 里的端口 |
| --- | --- | --- | --- |
| `backend` | 5001 | 3000 | 后端 3000 |
| `backend_nginx` | 5000 | 80 | nginx 80 |
| `frontend` | 4001 | 3000 | release 3000 |
| `frontend_nginx` | 4000 | 80 | nginx 80 |

也就是说，访问后端服务用的是服务器的 **5001**，而不是容器内的 3000；发布页走 4001（容器内 3000）。两个 nginx 分别是 5000、4000，容器内都是 80。配置好之后，记得在服务器安全组里**开放 5001、5000、4001、4000** 这四个端口，外部才访问得到接口，否则一律不通。

`restart: always` 表示 Docker 重启时容器也会跟着重启，保证服务常驻。

### 一键启动与 DevOps 闭环

用上一节讲的那条 Docker Compose 命令，一行就能把四个容器同时启动：后端、后端 nginx、前端、前端 nginx 一起运行。至于编辑平台的 React 单页应用，仍然放在阿里云 OSS 上，这一步同样在云效里完成。

于是整个 DevOps 闭环就清楚了：本地改代码 → 提交到阿里云云效 → 点击运行 → 一键把所有项目重新发布到测试环境，就能验证新功能或修好的 bug。测试环境迭代如此，线上亦同理。

## 小结

- 一份 `docker-compose.yml` 的 `services` 里并列配置四个容器：backend、backend_nginx、frontend、frontend_nginx。
- `image` 用 `${xxx_tag}` 变量，是为阿里云云效 + 镜像仓库做的映射；Dockerfile 产出镜像、Compose 运行容器，别混淆。
- `ports` 是「宿主机:容器」：5001:3000、5000:80、4001:3000、4000:80，与各自 Dockerfile 的端口一一对应。
- 服务器必须开放 5001 / 5000 / 4001 / 4000 四个端口，`restart: always` 保证常驻。
- 一条 Docker Compose 命令同时拉起四个容器；React 编辑平台仍托管在 OSS。
- 本地提交代码到云效、一键重新发布，构成完整的 DevOps 闭环。
