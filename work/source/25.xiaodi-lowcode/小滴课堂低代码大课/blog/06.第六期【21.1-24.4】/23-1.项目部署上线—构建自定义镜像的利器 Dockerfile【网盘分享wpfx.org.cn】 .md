# Dockerfile 入门：把三个项目打包成可运行的镜像

> **导语**：课程进入部署上线阶段。低代码平台有三个前端/后端项目要跑，如果沿用"登服务器、拉代码、装依赖、逐个启动"的老办法，每次改一个 bug 都要重来一遍，还要兼顾 Nginx 配置，本地开发与测试环境都会被拖慢。本文讲清为什么要用 Docker 把项目打包成镜像，以及 Dockerfile 在这条链路里扮演什么角色。读完后你能说清 Docker 三大核心，也知道镜像是怎么被构建出来的。

## 正文

### 传统部署为什么不够用

这套低代码平台一共有三个项目需要上线：

1. **React 项目**：客户端编辑平台；
2. **Next.js 项目**：面向用户的发布页面，服务端渲染；
3. **NestJS 项目**：后端接口服务。

按常规思路，把三个项目代码都放到服务器里，上线时登进服务器拉代码、下载依赖、逐个运行。问题在于：每次修 bug、迭代新功能，都得把这套流程重走一遍；而且发布页与后端还各带 Nginx，要启动的东西又多又杂。无论本地开发还是发到测试环境联调，都相当麻烦。

更合理的做法是用 Docker 把项目连同它所需的依赖一起打包成**容器**，容器里环境已经就绪，直接运行即可，不必重新配置环境。再往后一章的 DevOps，还会把这件事做到"一键把代码部署上线"。但在讲一键部署之前，得先解决最基础的一步：如何生成镜像。

### 镜像 → 容器 → 项目启动

整体链路是三步：通过 Dockerfile 构建出**镜像**，由镜像生成**容器**，把容器运行起来，项目就启动了。Dockerfile 就是这个链路的起点——它是一个配置文件，把运行环境、依赖、启动所需的配置都提前写好，之后只要执行一条命令就能把项目跑起来。

Docker 官方那张示意图很贴切：像一艘船把所有集装箱一次性装好，所有配置环境打包完毕，只要一个命令让船"开起来"就行。

### Docker 三大核心

要自定义镜像，先认清 Docker 的三个核心概念：

- **仓库（Repository / Docker Hub）**：存放镜像的线上地址。前面线上跑的 MySQL、Redis，都是从 Docker Hub 拉取官方镜像后运行的；第三方和自己构建的镜像也都可以推送上去。
- **镜像（Image）**：一个静态的、包含了全部配置与依赖的模板，本身不能直接跑，但可以通过命令运行成容器。
- **容器（Container）**：由镜像生成、真正在运行的实例，运行它就能启动项目。

前面我们用的是别人提供的镜像；现在要为自己的三个项目**定制镜像**，于是就需要 Dockerfile。

### Dockerfile 到底是什么

按官方定义，Dockerfile 是一个**由一系列指令和参数构成的脚本文件**，也就是 Docker 镜像的描述文件。它包含了构建整个镜像所需的完整命令，通过 `docker build` 执行其中的一系列指令，就能自动构建出镜像。

光看定义还是抽象，讲师用了一个通俗的例子：老王给冰冰买生日礼物，挑了一辆需要自己组装的玩具赛车，拆开包装直接送了过去，冰冰还得手动拼装，最后转手扔进了垃圾桶。对应关系是：

- **没有镜像的项目**＝一堆待组装的零件：要自己把运行环境、路径、依赖全部配置齐才能启动；
- **有 Dockerfile 生成的镜像**＝已经组装好的赛车：打开开关就能跑。

Dockerfile 做的事，就是把一堆零散、待执行的命令与参数整理进一个脚本文件，执行它便生成一个开箱即用的镜像。命令形式大致如下（示意，具体指令在下一节展开）：

```bash
docker build -t <镜像名> .
```

### 谁需要认真看这一节

对 Dockerfile 已经很熟、能独立给项目写镜像配置的同学，可以快速跳过；第一次接触容器化部署、或者对 Dockerfile 里各项配置不熟的同学，建议跟着后面的章节把细节补齐——因为自定义镜像是后面 Docker Compose 多容器编排与云效 DevOps 一键部署的地基。

本文只讲 Dockerfile 的定位与核心概念，它没有关联到具体项目源码文件；具体的指令与参数写法会在下一节结合三个项目逐一给出。

## 小结

- 三个待上线项目：React 编辑平台、Next.js 发布页、NestJS 后端，外加各自的 Nginx。
- 传统部署每次迭代都要重配环境，容器化能把依赖与环境一次打包、直接运行。
- Docker 三大核心：仓库（Docker Hub）、镜像（静态模板）、容器（运行实例）。
- 链路是 Dockerfile → 构建镜像 → 生成容器 → 运行容器启动项目。
- Dockerfile 是指令与参数构成的脚本，用 `docker build` 自动构建镜像，相当于"组装好的赛车"。
