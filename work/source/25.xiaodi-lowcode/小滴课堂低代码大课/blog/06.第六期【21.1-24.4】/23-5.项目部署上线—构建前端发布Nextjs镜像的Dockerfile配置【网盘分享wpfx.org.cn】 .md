# 项目部署上线：构建前端发布 Next.js 镜像的 Dockerfile 配置

> **导语**：发布页是 Next.js 服务端渲染项目，必须像后端服务一样跑在服务器里，因此也要单独构建一个镜像。本文讲清如何由 server.Dockerfile 复制出 release.Dockerfile、逐条改哪些命令，以及为什么 React 编辑器前端反而不用进容器、直接放阿里云 OSS 即可。读完你能分清项目里三类前端产物各自的部署去向。

## 前置知识

建议先读《项目部署上线—构建自定义镜像Dockerfile的配置介绍》熟悉 Dockerfile 基本指令，再读《项目部署上线—构建后端镜像的Dockerfile配置》——本篇就是在它基础上改命令；另外可参照《低代码项目发布页面—前端 Nextjs 项目初始化》，明确 release 子包是什么。

## 正文

### 为什么发布项目要单独一个镜像

这套低代码平台里有三类前端产物，去向并不相同：

- **client**：React 编辑器页面，纯静态资源，构建后直接上传到阿里云 OSS Bucket 即可，不需要容器；
- **server**：NestJS 后端服务，需要常驻运行，走后端镜像；
- **release**：Next.js 服务端渲染的发布页面，同样需要在服务器端运行、对外提供渲染能力，因此也要构建成镜像并在服务器里启动。

本篇做的就是第三类。整体思路和后端服务镜像几乎一样：复制一份 server.Dockerfile 为 release.Dockerfile，只把与子包相关的命令改掉。

### 指令序列：改哪几处

按视频演示，release.Dockerfile 的指令顺序是：以 `node` 为基础镜像 → 设置 `WORKDIR` 工作目录 → `COPY` 代码进容器 → 把镜像源改成国内源以加快依赖下载 → 全局安装 pnpm → 用 pnpm 安装依赖 → 先打包构建 share（公共类型与公共组件子项目）→ 再打包构建 release → `EXPOSE 3000` → 启动命令 `start:release`。

需要改动的关键点只有两处：

1. **构建命令**：server.Dockerfile 里是 `build:server`（构建后端服务），这里要改成 `build:release`（构建发布项目）。注意仅改这一处，前面的 `build:share` 保留——release 依赖公共子项目，必须先构建 share。
2. **启动命令**：由 `start:server` 改为 `start:release`。

这里顺带纠正前两节课的一处口误：server.Dockerfile 中那一段 `build:server` 是"打包构建后端服务"，不是"启动服务"，启动是后面 `start:server` 那一步。构建与启动是两件事，别在配置里混为一谈。

### 命令以根目录 package.json 为准

Dockerfile 里用到的脚本，全部来自根目录 package.json 已配置好的 scripts，不需要自己发明命令（来自 `代码（已8期）/代码（已8期）/23-5/lowcode/package.json`）：

```json
{
  "scripts": {
    "build:client": "pnpm --filter client run build",
    "build:server": "pnpm --filter server run build",
    "build:release": "pnpm --filter release run build",
    "build:share": "pnpm --filter share run build",
    "start:server": "pnpm --filter server run start:prod",
    "start:release": "pnpm --filter release run start"
  }
}
```

可以看到它们都是 `pnpm --filter <子包>` 的形式：先 `build:share` 再 `build:release`，最后 `start:release`，与 Dockerfile 里的顺序一一对应。让 Dockerfile 直接复用仓库里已有的脚本，是保证本地与镜像内行为一致的关键。

另一个细节：这一期 client 子包的 build 脚本是 `vite build`（见 `代码（已8期）/代码（已8期）/23-5/lowcode/packages/client/package.json`），产物是静态文件，正好支撑"直接传 OSS"的部署方式；release 子包的配置见同目录 `代码（已8期）/代码（已8期）/23-5/lowcode/packages/release/package.json` 与 `tsconfig.json`。

### 别把两类镜像搞混

后端服务镜像与发布项目镜像虽然结构相似，但一个是 NestJS 服务、一个是 Next.js SSR 服务，`EXPOSE` 的都是 3000 端口（各自容器内），由外层 nginx 与 Docker Compose 统一编排。真正要牢记的是分工：**需要服务端运行的（server、release）进容器，纯静态的（client）进 OSS**。

## 小结

- 发布页是 Next.js 服务端渲染项目，必须常驻服务器，因此要单独构建镜像；client 静态资源直接放阿里云 OSS。
- 做法：复制 server.Dockerfile 为 release.Dockerfile，只改构建命令（build:server → build:release）与启动命令（start:server → start:release）。
- 通用指令：node 基础镜像、WORKDIR、COPY、国内镜像源、全局 pnpm 安装依赖、EXPOSE 3000。
- 构建顺序保持先 share 后 release；server.Dockerfile 里的 build:server 是"打包构建"而非"启动"，注意纠正口误。
- 所有命令复用根 package.json 的 `pnpm --filter` 脚本，保证镜像内外一致。
