# 前端页面开发：图片组件展示视图

> **导语**：视频组件跑通之后，编辑模块里的其它组件就能照着同一套流程批量推进了。轮播、卡片、列表都依赖图片，所以先把图片组件做出来。本文讲在 share 公共项目里新增 `local-image`、定义属性类型与默认值、实现 `<img>` 与可点击跳转的 `<a>` 包裹、把类型并入通用组件联合，以及重新打包 share 后前端如何零改动接入——最后用一个临时占位解决右侧配置面板尚未开发时的报错。

## 正文

### 为什么先做图片组件

上一章用视频组件走通了「左侧点击 → 中间视图展示 → 右侧配置属性」的完整链路。本来接着要做轮播组件，但轮播、卡片、列表里都包含图片，所以先把图片组件抽出来开发，后面几个组件可以直接复用。本节只做**展示视图**，配套一张 380×200 的自定义兜底图；图片组件的**配置属性组件**留到下一节。

### 在 share 里新增 local-image

在公共项目的 `components` 下新建 `local-image` 文件夹，与已有的 `local-video` 对齐；再新建 `index.ts`，统一抛出类型与组件，组件命名为 `ImageComponent`。目录结构、导出方式都照搬视频组件，这是「跑通第一个、复制后面每一个」的省力做法。

### ImageComponent 的属性与渲染

图片组件的属性（props）有：

| 属性 | 说明 |
| --- | --- |
| `id` | 每个组件都必须有的唯一 ID |
| `url` | 要展示的图片地址 |
| `name` | 图片名称 |
| `height` | 高度 |
| `handleClick` | `'open-url'` 可点击跳转 / `'none'` 点击无反应 |
| `fit` | 填充样式，默认 `cover` |
| `link` | 可选，跳转地址；设置了 `open-url` 时才用得上 |

组件本体就是一个 `<img>` 标签：`src` 取 `url`、`alt` 取 `name`，宽度 100%，高度来自 `props.height`，`object-fit` 来自 `fit`。样式用 Tailwind CSS 的类名表达（`w-full`、`object-cover`、`outline` 等），装了 Tailwind CSS 插件后在编辑器里能直接看到类名对应的样式提示，不必反复查官网。

渲染前做一个判断：当 `handleClick === 'open-url'` 时，用 `<a>` 标签把 `<img>` 包起来，`href` 取 `link`（讲师一开始误写成了 `url`，随即改回 `link`），以新标签页打开并做来源处理；否则直接返回 `<img>`。

### 属性变化时重置与重渲染

这段逻辑与 `VideoComponent` 完全一致：取到所有默认属性，把 props 里传进来、有改动的部分覆盖默认值；没改动就用默认。深层嵌套的默认配置先转成一维、再累加，得到最终用于渲染的配置属性。

### 类型：从图片属性到通用组件类型

- 先定义图片属性类型，再通过泛型 `interface` 转成**通用组件类型**：传入 `T` 表示组件类型字符串（`'video'` / `'image'`），返回形如 `{ type, id, props }` 的结构。
- 剔除可选属性后，给图片设一批默认值：`fit = 'cover'`、`height = 200`、`handleClick` 默认可点击跳转、`link` 默认小滴课堂官网、`name` 默认「图片的名称」。
- 每个配置项用 `value` / `defaultValue` / `isHidden` 这种格式描述：`id` 项设为 `isHidden: true` 隐藏，高度等需要用户配置的设为 `isHidden: false` 显示。
- 最关键的一步：组件类型联合里要加上 `TImageComponentConfig`，并在工具组件导出里把图片组件一并抛出。凡是引用这个联合类型做 TS 校验的地方，漏加就会报错。

### 重新打包 share

在 `lowcode` 根目录执行：

```bash
pnpm build:share
```

配套代码 `代码（已8期）/代码（已8期）/15-1/lowcode/package.json` 里能看到这条脚本的真实定义：

```json
{
  "scripts": {
    "run:client": "pnpm --filter client run dev",
    "run:server": "pnpm --filter server run start:dev",
    "run:share": "pnpm --filter share run dev",
    "build:share": "pnpm --filter share run build",
    "build:client": "pnpm --filter client run build"
  }
}
```

注意**一定要在根目录执行**：一旦 `cd` 进 `share` 子目录，对应的打包命令就不一样了。

### 前端零改动接入与临时占位

client 侧不用改任何代码。刷新后点击视频组件一切正常，但点击图片组件会报错。原因不在 share 的导出，而在右侧配置属性的获取逻辑：它通过 `getComponent.get(type)` 按组件类型取配置组件，而图片组件的**配置属性组件还没开发**，自然取不到。

临时方案是把这里写死为 `'video'` 占位。再点击图片组件，就能看到图片正常展示、`hover` / 选中样式齐全、点击可新增。等下一节把占位换成图片组件自己的配置属性组件即可。

## 小结

- 轮播、卡片、列表都含图片，因此先做图片组件；本节只做展示视图，配置属性组件留到下一节。
- 在 share 的 `local-image` 里新建 `index.ts` 统一导出 `ImageComponent` 与类型，结构对齐 `local-video`。
- 属性含 `id / url / name / height / handleClick / fit / link`；`handleClick === 'open-url'` 时用 `<a>` 包裹、href 取 `link`。
- 类型要并入通用组件联合 `TImageComponentConfig`，并在工具组件导出里抛出，否则 TS 校验报错。
- 修改 share 后须在根目录执行 `pnpm build:share`；右侧配置面板未完成时，可先写死 `'video'` 占位。
