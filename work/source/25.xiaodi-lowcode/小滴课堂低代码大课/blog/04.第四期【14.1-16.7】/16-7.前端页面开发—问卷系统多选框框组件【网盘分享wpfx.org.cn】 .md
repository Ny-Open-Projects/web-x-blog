# 前端页面开发—问卷系统多选框框组件

> **导语**：多选框（Checkbox）组件是问卷系统选择类控件的收尾一课。它和单选框几乎同构，唯一关键区别在于“选中态”从单个值变成了数组——用户可以同时勾选多个选项。本节课我们用 Ant Design 的 `Checkbox.Group` 实现视图，并复用单选框那套配置面板思路完成属性配置。

## 前置知识

阅读本文前，建议先掌握《前端页面开发—问卷系统单选框组件》。多选框的页面形态、配置面板与单选框高度一致，本文重点放在两者的差异上。

## 正文

### 单选与多选的本质差异

单选框一旦选中第二项，第一项就会被置空，始终保持“唯一选中”；而多选框允许同时选中选项一、选项二、选项三中的任意多个。配置面板上，标题、候选项名称的设置方式和单选框完全一样——区别只在于“默认选中哪些”以及“用户最终选了哪些”用数组来表达。

### 在 share 层定义 LocalCheckbox 视图组件

在 `share` 公共子项目的 `src/components` 下打开 `LocalCheckbox`，同样使用 Ant Design 的 `Checkbox.Group`（因为它本质是一个选项列表）。核心逻辑：

- 从 store 的 state 里拿到 `options` 数组，循环遍历渲染出所有候选项；
- 哪些是选中的，体现在 `value` 这个数组对象上；
- 默认值为空数组，但我们按业务约定默认选中第一项。

属性类型与单选框类似，多了 `defaultChecked` 来表示默认选中项：

```ts
interface CheckboxComponentProps {
  id: string;
  title: string;
  defaultChecked: string[]; // 默认选中的选项 id 列表
  options: { id: string; value: string }[];
  onUpdate?: (value: string[]) => void;
}
```

对照 antd 官方 `Checkbox.Group` 的用法，`options` 即要展示的候选项（官方称为 `plainOptions`，例如 apple / pear / orange），而实际选中的项通过 `value` 控制。课程里对应 `defaultCheckedList`，默认选中 apple 和 orange 两个。

### 选中与取消：数组回调

`onChange` 在用户勾选或取消某个选项时触发，回调抛出的就是一个选中的 `id` 数组：

```tsx
<Checkbox.Group
  value={defaultChecked}
  options={options.map((o) => ({ label: o.value, value: o.id }))}
  onChange={(checkedIds) => onUpdate?.(checkedIds as string[])}
/>
```

发布项目时调用这个 `onUpdate` 回调，就能拿到用户勾选的全部选项，随问卷一起提交到后端。

### 在 client 层实现配置属性组件

`client` 层的配置属性组件 `LocalCheckbox` 与单选框几乎一模一样，不再赘述。唯一的区别是：单选框的“默认选项”用的是 `Select` 单值组件，而多选框这里换成 `Checkbox.Group`——可以设置多个默认 `options`，并随着 store 里 state 的变化实时同步。

### 前端组件阶段告一段落

讲到多选框，从视频组件一直到多选框，**所有前端组件的逻辑就都开发完成了**。接下来要补齐的是：图片/视频等资源的上传与删除接口、发布接口、组件获取接口，以及拖拽排序、键盘操作、预览、草稿等编辑态小功能。这些会进入后端接口与联调阶段。

## 小结

- 多选框与单选框结构同构，区别在选中态用数组表示（可同时选中多个）；
- `share` 层用 `Checkbox.Group` 实现 `LocalCheckbox`，`value` 为选中 id 数组，`defaultChecked` 表示默认选中；
- `onChange` 回调抛出选中 id 数组，发布页据此收集多选答案；
- `client` 层配置面板复用单选框思路，仅把 `Select` 替换为 `Checkbox.Group`；
- 至此所有前端视图/配置组件开发完毕，下一阶段转向资源上传等后端接口。
