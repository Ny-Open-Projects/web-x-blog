# 前端页面开发—富文本视图组件+属性配置组件

> **导语**：视频、轮播、卡片、列表、图片、文本、分割组件之后，本节补上富文本组件：中间画布用 `dangerouslySetInnerHTML` 渲染，右侧用 `react-quill` 编辑，靠 MobX store 做双向绑定。除了实现细节，本文重点记录一个很典型的样式坑——Tailwind CSS 的 base 样式把 `h1~h6`、`ol`、`ul` 的默认样式重置掉，导致富文本标题不生效，以及怎么用「检查元素 + 调整样式顺序」定位和解决它。

## 前置知识

需要熟悉编辑器「视图展示 ⇄ store ⇄ 右侧配置」的联动范式，建议先看《前端页面开发—文本视图组件+属性配置组件》与《前端页面开发—图片组件展示视图》；公共状态的组织方式见《低代码项目前端项目开发—公共状态管理+自定义 hooks》，整体骨架参考《前端页面开发—低代码项目编辑模块整体布局》。

## 正文

### 数据链路：HTML 字符串进 store，视图响应式渲染

富文本组件分两块：中间视图负责展示，右侧属性面板负责编辑。链路是：

右侧 `react-quill` 编辑内容 → `onChange` 里通过编辑器实例的 `getHTML()` 拿到 HTML 字符串 → 调用 store 的 `updateCurrentComponent` 写入 `content` → 视图组件从 store 取数据渲染。

因为视图读的是 store，store 一变视图就跟着变，这就是响应式双向绑定：在右侧设标题、加粗、改颜色，中间画布同步呈现。沿用这个套路，前面那些组件其实都是同一套模式。

### 视图组件：`dangerouslySetInnerHTML`

`share` 子项目 `components/local-rich-text` 下的视图组件很简单：返回一个 `div`，在它上面用 React JSX 特有的 `dangerouslySetInnerHTML` 属性，以对象形式插入 HTML 字符串。这样富文本里编辑出的 `span`、`h1`、`ol`、`ul` 等标签连同字体颜色、背景色都能原样渲染出来。

两个细节：

- 内容为空时做判断，显示占位提示「请在富文本输入内容」，引导用户去右侧输入；
- 内容变化时重新处理、重新计算缓存，再通过 props 插入显示。

类型定义上，富文本组件的属性只有一个 `content`；转成提交后端的通用数据格式时，再补齐组件 `id`、`type`、`props` 等通用字段，并给表单数据一个空字符串默认值。改完同样记得重新打包 `share`。

### 属性配置组件：`react-quill`

在 `client` 子包 `components/` 下新建富文本配置组件，先 `pnpm install react-quill` 安装插件。要点：

- 外层 `div` 用 flex 做垂直居中；
- 用 React 的 `useRef` 创建富文本编辑器实例，并通过 `ref` 绑定到组件上，之后才能调用实例方法；
- 设置 `theme="snow"`，即 Quill 的白色简洁主题；
- `value` 绑定 store 里的内容；
- `onChange` 触发时调用 `updateCurrentComponent`，用 `editor.getHTML()` 取当前 HTML 字符串作为 `content` 写回 store；
- `modules` 配置工具栏：标题 `h1`~`h4`、加粗/斜体/下划线、字体颜色与背景色、对齐方式、有序/无序列表、字体、`code-block` 等。数组里每一项对应一组工具，按需要增删即可。

于是标题、序号列表、点列表、代码块、颜色、对齐等能力都能在右侧配置，结果实时同步到画布。

### 样式坑：Tailwind CSS 覆盖了标题与列表样式

开发时遇到一个现象：在右侧把文本设为 H1，富文本编辑器里生效了，但中间画布里虽然 DOM 上确实是 `<h1>` 标签，却既不加大也不加粗。

排查思路很通用：**先看元素、再看样式**。用浏览器检查元素，确认视图里的 HTML 标签没问题，那问题一定出在样式上；再看样式面板，会发现 `h1`~`h6` 的字体大小、颜色、加粗都被重置成了 normal——根源是引入了 Tailwind CSS，它的 preflight/base 样式把标题、列表等元素的默认样式统一清掉了。

验证方法也简单：把这些标题样式临时写到 Tailwind 引入之前，保存后再看，H1 依旧不生效，说明被后面的 Tailwind 覆盖；反过来把恢复样式写在**后面**（同一样式文件里后写的覆盖先写的），`h1`~`h6` 的字号/加粗、`ol`/`ul` 的列表样式就都回来了。最终做法是在全局基础样式文件里补回这些元素样式，并保证顺序在 Tailwind 之后。注意有序列表与标题样式会互相冲突，同一处通常只能生效一种。

这类样式问题本身不难，难的是有没有清晰的定位思路：先看 DOM 结构对不对，再看样式被谁覆盖，最后用顺序或优先级解决。业务开发里这套思路比记住某个属性更值钱。

### 沉淀出的开发范式

到这里再回头看，新增一个组件已经很机械：

- 视图要响应式，与 store 里的数据双向绑定；
- 右侧配置属性时更新 store；
- store 变化驱动视图同步更新；
- store 变量放 store，相关逻辑维护在 hooks 里，通过 action 方法响应式地改变量。

第一次做 `local-video` 时可能会懵，但按这个套路走，再多加几个组件也不会乱。

## 小结

- 富文本链路：`react-quill` 编辑 → `getHTML()` 取 HTML 字符串 → store 的 `updateCurrentComponent` 写 `content` → 视图响应式渲染。
- 视图用 `dangerouslySetInnerHTML` 插入 HTML，空内容时显示占位提示，属性只有 `content`。
- 配置组件用 `useRef` + `ref` 绑定实例、`theme="snow"`、`value` 绑定 store、`onChange` 回写，`modules` 配工具栏。
- Tailwind CSS 的 base 样式重置了 `h1~h6`、`ol`、`ul`，需在全局样式里补回并放在 Tailwind 之后。
- 统一范式：视图与 store 双向绑定，右侧配置更新 store，逻辑放 hooks、变量放 store、通过 action 响应式修改。
