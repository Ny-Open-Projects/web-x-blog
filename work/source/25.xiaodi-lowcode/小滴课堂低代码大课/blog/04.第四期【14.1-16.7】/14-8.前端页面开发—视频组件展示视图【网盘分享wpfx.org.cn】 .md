# 前端页面开发—视频组件展示视图

> **导语**：点击左侧组件列表里的「视频」，中间画布要立刻出现一个 `<video>`。这件看似简单的事，在低代码平台里牵出一整套架构：组件为什么要抽到 `share`、配置与排序为什么必须放进 MobX store、`observe` 为什么不能省、以及 `objectOmit` 这种工具函数到底在解决什么。本文以视频组件为例，把这条渲染链路完整走一遍。

## 前置知识

建议先读《前端页面开发—低代码项目编辑模块左侧组件列表样式》，此时编辑页三栏布局与组件列表已经就绪。另需熟悉 React + TypeScript、MobX（`makeAutoObservable` / `observer` / `toJS` / `computed`）、`classnames` 与 `ulid` 的基本用法。配套工程见 `代码（已8期）/代码（已8期）/14-8/lowcode/`。

## 正文

### 组件为什么放到 share 公共包

最直觉的做法是在画布里 `return` 一段 JSX 就完事。但低代码平台有两处要用同一批组件：编辑页的画布，以及发布之后供用户访问的 H5 页面。用户配了多少组件，这两处都要完整渲染。

所以组件统一抽到公共子项目 `share` 的 `components` 下，比如视频组件放在 `localVideo`；再建 `componentExport` 作为组件出口，集中维护一个 `componentList` 映射。新增一个组件（swiper、image……）就往映射里加一项，编辑端通过 `getComponentByType(type)` 取到对应组件。

### store 里要维护哪些状态

组件的配置、排序、选中态都是公共数据，放进 store 才能得到响应式。`useStoreComponents` 里用 MobX 的 `makeAutoObservable` 包裹一个对象，主要五个变量：

- `componentConfigs`：键值对，键是组件 ID，值是该组件的完整配置（`id`、`type`、`props`）。后端把 `props` 叫 `Options`，前端统一命名 `props`，是一个对象。
- `sortableComponentConfig`：只存组件 ID 的数组，用来表达画布里的顺序，也供拖拽排序使用。
- `currentComponentConfig`：当前选中的组件 ID（`string`），控制蓝色选中边框与右侧属性面板。
- `copyComponentConfig`：复制组件时的中间变量。
- `itemsExpandIndex`：`number`，属性选项的展开 / 折叠（0 折叠、1 展开）。

组件类型在 `share` 里定义为 `TComponentPropsUnion` 与 `TComponentTypes`，当前示例只有 `TVideoComponentConfig`，后续新增再联合进去。

### push：点击组件后发生了什么

左侧组件列表循环渲染，点击时调用 store 的 `push`，把「要展示什么类型」告诉 store：

```ts
const push = (type: TComponentTypes) => {
  const id = ulid(); // 随机生成唯一 ID
  const config = { id, type, props: {} };

  store.componentConfigs[id] = config;
  store.sortableComponentConfig.push(id);
  store.currentComponentConfig = id; // 新增的即为选中
};
```

要点：ID 用 `ulid` 保证唯一；`props` 初始为空，要等右侧属性面板设置了 `src`、播放时间、是否循环等才有值；同时写「配置字典」和「排序数组」两处，最后把新组件设为选中。这些修改 store 的方法都通过 MobX 的 `action` 执行，才能触发响应式更新。

对 store 变量的读取与修改方法，统一收敛在 `useStoreComponents` 这个 hook 里，用到哪个再看哪个，不必一次性读完全部实现。

### EditCanvas：从排序数组到真实 DOM

画布组件要随 store 变化重新渲染，React 里必须用 `observer`（MobX）包裹函数组件——这是它和 Vue 的显著差别，Vue 的响应式自动更新，React 单向数据流下得显式声明：

```tsx
const EditCanvas = observer(({ store }: { store: TStoreComponents }) => (
  <>
    {store.sortableComponentConfig.map((id) => {
      const config = getComponentById(id);
      return (
        <ComponentWrapper
          key={id}
          id={id}
          isCurrent={getCurrentComponentConfig()?.id === id}
        >
          {generatorComponent(config)}
        </ComponentWrapper>
      );
    })}
  </>
));
```

链路是：遍历 `sortableComponentConfig` 拿到每个 ID → `getComponentById(id)` 从 `componentConfigs` 取配置 → `ComponentWrapper` 包一层布局与选中样式 → `generatorComponent` 生成真实组件。

`generatorComponent` 内部调 `getComponentByType(config.type)` 拿到 `share` 里的组件，用 `toJS` 把 MobX 代理对象转成普通对象，再把 `config.props` 展开传进去。因为 `props` 经过 MobX 装饰，不转普通对象没法直接展开。

`ComponentWrapper` 负责公共的外观：用 `classnames` 拼动态样式，`isCurrent` 为选中时显示蓝色边框，hover 时换成更深的 `border-blue-500` 且边框更粗；`data-id` 挂在元素上，供后续拖拽排序取用。判断选中用 MobX 的 `computed` 计算属性对比 `currentComponentConfig` 与当前 `config.id`。

### 视频组件与两个对象工具函数

`localVideo` 里就是一个 `<video>`：`controls` 按参数决定是否展示；`onLoadedMetadata` 触发 `handleLoadMetadata`，加载成功后把控制器 `isReady` 置为 `true`，并按 `props.startTime` 设置起播时间（例如从第 5 秒开始播放）。`useMemo` 监听 `props` 变化，属性改了（如 `loop` 改为 `false`）就重新取配置并渲染。

配置默认值来自 `videoComponentDefaultConfig`（`autoPlay`、`post` 封面、`loop`、`muted`、`src`、`startTime` 等），通过 `getDefaultValueByConfig` 把「深层配置」压成一维，直接取每项的 `defaultValue`。展开时若参数里带了新值，会覆盖默认值——这就是属性面板能实时生效的原因。

还有两个 TS 工具函数值得记：

```ts
// 从对象中剔除指定属性，例如 video 标签不存在的 startTime
function objectOmit<T extends object, K extends keyof T>(t: T, k: K[]): Omit<T, K> {
  const result: any = {};
  (Object.keys(t) as K[]).forEach((key) => {
    if (!k.includes(key)) result[key] = t[key];
  });
  return result;
}
```

因为原生 `<video>` 上没有 `startTime` 这个属性，把 `props` 整体展开到标签上之前必须先剔除它；否则会挂上一个无意义的 DOM 属性。`objectPick` 则相反——只挑选指定 key 组成新对象。一个删、一个选，逻辑都是遍历 + `includes` 判断，只是条件取反。

## 小结

- 组件抽到 `share` 公共包，编辑页与发布页共用；`componentExport` / `componentList` 是统一出口。
- store 维护 `componentConfigs`、`sortableComponentConfig`、`currentComponentConfig` 等五个状态，配置与排序分离。
- `push` 用 `ulid` 生成唯一 ID，同时写配置字典与排序数组，并把新组件设为选中。
- React 中用 MobX 必须用 `observer` 包裹才能响应式重渲染；`toJS` 负责把代理对象转普通对象。
- `objectOmit` 剔除 `startTime` 这类非原生属性，`getDefaultValueByConfig` 把深层配置压成默认值。
