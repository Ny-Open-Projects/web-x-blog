# 编辑器右侧属性面板：全局属性与视频组件配置

> **导语**：低代码编辑器的"所见即所得"，一半靠中间画布渲染，另一半靠右侧属性面板。本文补齐右侧面板的两块内容：全局页面属性（标题、描述、TDK）与具体组件属性（以视频组件为例），并拆解其中最绕的一段逻辑——如何把 props 在一维表单值与二维配置对象之间来回转换。读完后你能理解面板如何与 MobX store 双向同步，以及为什么配置属性组件不放在 `share` 包里。

## 正文

### 右侧面板要填的两个空位

上一节把中间视图的公共渲染逻辑封装好了，视频、轮播图、图片、列表等组件都能复用。这一节处理右侧编辑面板里遗留的两块：**组件属性**（某个选中组件自己的配置）与**全局组件属性**（整个页面的配置）。

面板通过 items 数组渲染，每一项是个对象；组件属性交给 `ComponentFields`，全局属性交给 `GlobalFields`，两者都从 store 取数据。把它们抽离到 `rightPanel` 里维护，结构就清晰了。

### 全局属性：title / description / TDK

先在 store 目录新增 `page.ts`，并在主入口 `index.ts` 抛出。`useStorePage` 这个 hook 里通过 `createStorePage` 创建 store 并重命名导出，全局只维护三个变量：

- `title`：页面标题叫什么；
- `description`：页面描述；
- `TDK`：页面关键字。

`GlobalFields` 本身是一个简单的表单：外层用 Ant Design 的 `Form`，里层用三个 `Form.Item` 各包一个输入框，`layout` 设为竖向排版，默认值直接读 store 里定义的三个默认文本。

关键在 `onValuesChange`：任意输入框的值发生变化都会触发它，然后调用 `updatePage` 同步更新 store。参数是一个对象，`key` 属于 `TStorePage`（可以是 `title`、`TDK` 或 `description`），`value` 是字符串。`updatePage` 定义在 `useStorePage` 里，用 MobX 的 `action` 包裹：

- 若没有值发生修改，直接停止（一层兜底）；
- 有修改则用 `Object.entries` 把对象转成数组，解构出 `key` 与 `value`；
- 以 `key` 为索引把对应 `value` 写回 store。

所以页面上改一个字，store 里的 `title` 立刻同步，中间画布与后续发布数据都能拿到最新值。这里还提前定义了 `setPageTitle`，供后续"页面头部动态标题"逻辑使用。

### 组件属性：按类型找配置组件

`ComponentFields` 是函数式组件，入参类型通过 TypeScript 工具类型从 store 方法推导而来。它先判断 `currentComponentConfig` 有没有值：没选中任何组件就显示"未选中组件"；选中了才从 `useStoreComponents` 里取出当前组件的 `props`（这是经过 MobX 装饰的对象，需要转成普通 JS 对象），解构后连同 `id` 传给 `ComponentProps`。

`getComponentPropsByType` 负责**按组件类型映射到对应的配置属性组件**：传入 `type`，返回一个表单组件。类型定义放在 `share` 包里的 `TBasicComponentConfig`，通过索引取到 `type` 字段，结果就是 `video`、`swiper` 这样的字符串字面量。后续新增图片、轮播图，只要在这个映射里加一项、再新建对应文件夹即可。

这里有个工程上的取舍值得注意：**视图组件的映射 `getComponentByType` 放在 `share` 公共包**，因为发布页面同样要渲染这些组件；而**配置属性组件的映射放在 `client` 的 `components` 下**，因为发布页面根本不需要属性面板。两端共用的才下沉到 `share`，只属于编辑器的就留在 client，避免公共包被无关代码污染。

### 一维 props 与二维配置对象

视频组件的表单放在 `components/localVideo` 下，外层是二次封装的 `FormContainer`，子项是二次封装的 `FormItem`。中间最关键的一步是 `formatComponentPropsByConfig`：把原来一维的 props 转成二维结构。

原本 `src` 只是一个值，转换后变成一个对象：

```ts
{
  src: {
    defaultValue: '',
    isHidden: false,
    value: '实际设置的值',
  },
}
```

三个字段各有用途：`value` 是用户实际设置的值，`defaultValue` 是没设值时的默认展示内容，`isHidden` 为 `true` 时整条配置项直接隐藏。同一个方法还会做类型归一：字符串里若是纯数字则转成 `number`，若是 `true / false` 则转成 `boolean`，其余原样返回字符串——这部分通常用正则校验实现。

但 Ant Design 的 `Form.setFieldsValue` 只接受一维对象，所以在真正设置表单值之前，又要用 `reduce` 累加把二维对象还原成一维：

```ts
form.setFieldsValue(propValues);
```

于是数据流形成闭环：store 里的 props → 转二维（带上默认值与隐藏标记）→ 转一维喂给表单 → 用户修改触发事件 → `updateCurrentComponent` 把新的 `key / value` 写回选中组件的 store 配置。

### 表单子项的隐藏与属性剔除

二次封装 `FormItem` 只多做了一件事：判断传入的 `prop.isHidden`，为 `true` 就 `return null` 不渲染；否则用 `objectOmit` 把 `prop` 这个属性从传入对象里删掉，只保留 `name` 与 `label` 交给原生 `Form.Item`。这样每个配置项都能通过数据决定是否显示，而不必在 JSX 里堆条件判断。

视频组件最终的表单项包括：播放地址（Input，后续加上传按钮）、初始播放时间（`InputNumber`，默认 0）、是否自动播放、循环播放、是否静音播放（均为 `Switch`）。`isHidden` 设为 `true` 的项（如某些暂时不开放的配置）就不会出现在面板上。

## 小结

- 右侧面板分 `GlobalFields`（全局页面属性）与 `ComponentFields`（选中组件属性），都从 store 取数。
- 全局属性是 title / description / TDK 三个输入框，`onValuesChange` 经 `updatePage` 用 MobX `action` 同步回 store。
- `getComponentPropsByType` 按组件类型映射配置组件；视图映射放 `share`，配置映射只放 `client`。
- props 需要在一维表单值与带 `defaultValue / isHidden / value` 的二维对象间来回转换，并对数字、布尔字符串做类型归一。
- 二次封装 `FormItem` 用 `isHidden` 控制显隐、`objectOmit` 剔除多余属性；表单改动经 `updateCurrentComponent` 回写 store。
