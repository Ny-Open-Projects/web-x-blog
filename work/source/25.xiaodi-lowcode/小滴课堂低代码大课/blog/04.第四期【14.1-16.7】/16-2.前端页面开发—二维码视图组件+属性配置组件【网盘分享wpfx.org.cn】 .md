# 前端页面开发：二维码视图组件+属性配置组件

> **导语**：二维码组件一半在 share（视图渲染），一半在 client（属性配置），是理解低代码平台"公共子项目 + 编辑器"协作方式的好样本。本文讲清 Ant Design QRCode 的参数与纠错等级、share 中的默认值与类型定义，以及 ColorPicker 返回颜色对象时为什么要断言再调 toHex 才能存进 store。读完你能独立给编辑器新增一个带颜色配置的视图组件。

## 前置知识

建议先读《前端页面开发—富文本视图组件+属性配置组件》，熟悉"share 里放视图组件、client 里放属性配置组件"的分工；再了解二次封装的 FormContainer / FormItem 及 store 双向绑定机制（可参考《前端页面开发—轮播图组件配置属性》）。

## 正文

### 视图组件：直接用 Ant Design 的 QRCode

在公共子项目 share 的 components 下新建 LocalQRCode，视图部分不必自己画，直接引入 Ant Design 的 QRCode 组件并传入参数即可。对照官方 API，主要属性含义如下：

| 属性 | 含义 |
| --- | --- |
| value | 扫描后展示的文本内容 |
| icon | 二维码中间图片的地址 |
| size | 二维码尺寸 |
| iconSize | 中间图片尺寸 |
| color | 二维码（码点）颜色 |
| bgColor | 背景颜色 |
| errorLevel | 纠错等级 |

纠错等级分 L / M / Q / H 四档，对应可容忍的遮挡比例约为 7% / 15% / 25% / 30%——等级越高，二维码被遮挡或污损后仍能被正确扫描的能力越强。需要说明的是，这个比例是**分散分布**的缺损：遮挡若集中在一整块区域，即便在比例内也可能扫不出来；而零散分布的小块缺损才更容易被纠错算法容纳。

```tsx
<QRCode
  value={props.value}
  size={props.size}
  iconSize={props.iconSize}
  color={props.color}
  bgColor={props.bgColor}
  errorLevel={props.errorLevel}
  icon={props.icon}
/>
```

（参数对应视频演示；配套工程见 `代码（已8期）/代码（已8期）/16-2/lowcode/`。）

### share 里的类型与默认值

类型上先定义二维码组件属性，再剔除统一类型中的公共部分，得到表单数据格式。默认值有几个讲究：

- value 默认给一个横杠 "-"。二维码必须有一个基础内容，若为空就渲染不出二维码，用占位内容保证组件在画布上始终可见。
- 背景色默认白色，二维码颜色默认黑色，纠错等级默认 L。
- icon、size、iconSize 等也都给出初始值，中间图标功能演示里未实现，读者可自行按带 icon 的示例补上地址。

定义并抛出后，share 需要重新打包，client 才能用到这个新组件——这是 monorepo 里公共子项目的常规发布节奏。

### 属性配置组件：表单与颜色选择器

client 侧的 LocalQRCode 复用二次封装的 FormContainer 作为外层表单，除 props 外还传入一个 handleValuesChangeAfter 方法，专门处理颜色与背景色的变化。

表单项依次是：二维码内容（Input，因设置了默认值，占位内容不生效）、背景颜色与二维码颜色（均用 Ant Design 的 ColorPicker，点击即可选色）、容错率（Segmented，传 options 提供 L/M/Q/H 多个选项，默认 L）、二维码尺寸、以及中间图标大小（后两项演示里未设置，留作自行实现）。

### 关键细节：颜色对象要转成十六进制

ColorPicker 的回调返回的不是字符串，而是一个颜色对象。直接往 store 里存会出问题：TypeScript 会提示"该类型上不存在 toHex 方法"。做法是先把它断言为对应的颜色类型，再调用 toHex() 得到十六进制字符串：

```ts
const hex = (color as ColorType).toHex();
// 之后把 hex 存入 store，并双向绑定回 ColorPicker 才能正确回显
```

因为组件要展示的是十六进制色值，存进 store 的数据格式必须与表单控件接受的格式一致，否则选完颜色面板上看不到效果。讲师在二次封装的 FormContainer 里新增了一个**可选**的回调 props：表单项变化时，除了照常更新 store，还会执行父组件传进来的这个回调来处理颜色。其他组件引用公共表单时不必传它，只有二维码这类需要特殊处理的组件才传——可选参数让扩展不侵入既有调用方。

### 效果与应用场景

把默认横杠换成真实内容、设置背景色后，用手机微信扫码即可读出文本，点击还能跳转到对应官网地址。实际用途很直接：用户在编辑器里搭建个人网站时，可以放一个自己的微信或其他联系方式二维码，粘贴地址、调整容错率让它在有遮挡时更容易扫出，再按需调小尺寸，最终随页面一起发布。

### 配套工程

前端子包依赖如下（来自 `代码（已8期）/代码（已8期）/16-2/lowcode/packages/client/package.json`）：

```json
{
  "dependencies": {
    "react-quill": "^2.0.0",
    "mobx": "^6.12.0",
    "mobx-react-lite": "^4.0.5",
    "ulid": "^2.3.0",
    "antd": "^5.11.2"
  }
}
```

QRCode、ColorPicker、Segmented 均由 Ant Design 5 提供；MobX 负责 store 响应式；share 与 client 通过 workspace 依赖协作。tsconfig.json 里同样用 `~/*` 别名指向 src。

## 小结

- 视图组件在 share 的 LocalQRCode，直接复用 Ant Design QRCode，传 value / icon / size / iconSize / color / bgColor / errorLevel。
- 纠错等级 L/M/Q/H 对应约 7%/15%/25%/30% 可容忍缺损，等级越高越耐遮挡；缺损需分散分布才易被纠错。
- 默认值里 value 用 "-" 占位保证二维码可见，背景白、码点黑、等级默认 L；share 改动需重新打包才能被 client 使用。
- 属性面板用 FormContainer + Input / ColorPicker / Segmented；颜色回调返回对象，需断言后调用 toHex() 存十六进制字符串。
- 二次封装表单新增的是可选回调 props，仅二维码等需特殊处理的组件传入，不影响其他调用方。
