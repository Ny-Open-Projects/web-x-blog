# 前端页面开发：轮播图组件配置属性

> **导语**：轮播图的右侧属性面板是低代码编辑器里最复杂的一块：既有整体设置，又有可增删的图片列表，还要保证表单与 store 双向同步。本文拆解 LocalSwiper 的两层表单封装、一维属性到 { defaultValue, value, isHidden } 的转换、添加新项与手风琴展开，以及 handleValuesChange / setFieldsValue 构成的双向绑定闭环。读完你能看懂"改表单即改画布"的完整数据链路。

## 前置知识

建议先读《前端页面开发—轮播图组件展示视图》，了解点击左侧轮播图后中间画布如何呈现；再熟悉前面二次封装的 FormContainer / FormItem、MobX store 以及 React 的 useMemo / useEffect。本篇会大量复用这些基础。

## 正文

### 属性面板包含哪些配置

右侧配置分两层。整体层有：自动切换时间（interval）、是否自动播放（autoplay）、是否展示面板指示点、指示点位置（左 / 右 / 上），以及"添加新项"。图片层默认只有一张，点击添加新项就能增加多张；每张图片又有自己的属性：图片覆盖方式、点击方式、跳转地址（link）、图片地址（url）、高度等（高度项演示里未开启）。

交互上还有一个约定：多项之间是手风琴互斥——展开第一项时其他项收起，展开第二项时第一项收起。

### 两层表单组件

在公共 components 里新建 LocalSwiper 文件夹，index 抛出 SwiperComponent。它渲染两块表单：

- **FormContainer**：轮播图整体设置，复用之前二次封装的外层表单组件。
- **FormContainerWithList**：图片列表表单，是本篇新抽出的二次封装组件，接收 keyName（images）、id、图片 value 数组、newItemDefaultValue 四个参数。

注意 id 的含义：`props.id.value` 是**轮播图组件**的 ID，不是某张图片的 ID——整份 props 描述的是这一个轮播图，图片只是它内部的数组。

### 数据形态：从一维到三维属性

整体表单里有个关键处理：当 store 里的 props 变化时，用 useMemo 重新处理数据，把原本"属性 = 值"的一维结构，转成每个属性都带 defaultValue、value、isHidden 三个字段的对象：

```ts
// autoplay: false  →  { defaultValue: false, value: false, isHidden: false }
// images: [...]    →  { defaultValue: [...], value: [...], isHidden: false }
```

图片数组同理：value 是数组，每个元素是一个 IImageComponentProps 对象，描述一张图片应有的全部属性（类型定义在 ISwiperComponentProps / IImageComponentProps 里）。这样每个表单子项（二次封装的 FormItem）都能自行判断 isHidden 决定是否展示，外层表单再把数据转回一维双向绑定到 form。

### 添加新项与展开索引

FormContainerWithList 里放了一个"添加新项"按钮，点击触发 addNewValue：通过 updateCurrentComponent 修改 store，把原有项与新项（带上新生成的图片 ID）一起写入 keyName 对应的数组（keyName 用 ?? 做兜底）。新项的默认值来自 share 里定义的 defaultImageInfo——图片 ID 默认空、URL 等字段都有初始值。

展开/折叠不用布尔值，而是一个 **expandIndex 索引**：值为 0 表示第 0 项展开。循环遍历图片时，判断当前 index 是否等于 expandIndex，相等则 expand=true 传给 FormListItem；点击子项时调用 setExpandIndex 更新。当 props.id（轮播图 ID）变化——即切换到另一个轮播图组件时——重置展开状态，保证新选中组件默认展开第一项。

子组件 FormListItem 接收 item、index、key、newItemDefaultValue、setExpandIndex、keyName，以及 children（四个 FormItem）。children 在内部用 Form 包裹并竖向排版，只有展开时才真正占据内容。

### 双向绑定闭环

这是本篇最核心的一条链路，两个方向都要通：

**视图 → 数据**：表单项值变化触发 handleValuesChange。changeValues 是形如 `{ link: 新值 }` 的对象，用 Object.entries 转成二维数组后取第一项得到 `[key, value]`。第一次初始化时组件属性里还没有对应 key，需要通过 updateCurrentComponent 新增（把默认对象放前、新值放后，用拓展运算符让同名属性被后者覆盖）；之后再用 updateCurrentComponentConfigWithArray，按 keyName（images）、数组索引、field（如 link）精确定位并修改 store。

这里有个 MobX 细节：store 里的数据经过响应式包装是 Proxy，打印观察或取真实值时要先用 toJS 转成普通对象。

**数据 → 视图**：store 变化后，用 omit 去掉循环渲染时额外带入的无用 key，再在 useEffect 里调用 form.setFieldsValue 更新表单；且只在展开状态下执行，否则表单尚未渲染，调用会报错。

两者合起来，就是"改表单 → 更新 store → 画布刷新"与"store 变化 → 表单回填"的完整双向绑定。

### 收尾清理

新加的 SwiperComponent 要补进组件抛出与引入列表；useStoreComponents 里新增 updateCurrentComponentConfigWithArray；右侧属性面板删掉之前写死的 image；store 里早期定义的折叠/展开变量因逻辑调整已无用处，一并删除——避免留下误导后人的死代码。

```json
  "compilerOptions": {

```

MobX + mobx-react-lite 支撑 store 响应式，ulid 用于生成组件/图片 ID，Ant Design 提供表单控件；`~/*` 别名让二次封装组件能被各属性面板统一引用。

## 小结

- 属性面板分整体设置（interval、autoplay、指示点、位置）与图片列表两层，多项展开互斥。
- LocalSwiper 用 FormContainer + 新抽出的 FormContainerWithList 分别承载；id 是轮播图组件 ID，不是图片 ID。
- useMemo 把一维属性转成 { defaultValue, value, isHidden } 结构，供 FormItem 判断显隐。
- 添加新项走 addNewValue → updateCurrentComponent；展开状态用 expandIndex 索引控制，切换组件时重置。
- 双向绑定：handleValuesChange（视图→数据，Object.entries + toJS + 两个 update 方法）与 omit + form.setFieldsValue（数据→视图）缺一不可。
