## 正文

### 从成品效果反推需求

这一章的定位是"沙场秋点兵"：项目其实已经开发完成，我们先不写代码，而是把成品跑起来，倒推它到底需要哪些能力。

演示流程很清晰：未登录时访问课程管理页会被自动重定向到登录页；注册时填写用户名和密码，后端在注册成功后直接下发 token，前端随即处于登录态；点击头像可退出登录。登录后进入课程管理页，右上角展示个人头像，主体是带分页的课程列表，支持创建新课程、编辑已有课程信息、删除课程，刷新后数据依然生效。前端由 React 负责页面与交互，后端接口提供完整的增删改查能力——这里的"查"就是进入页面时拉取课程列表，"增"是创建课程，"改"是编辑，"删"是删除。

把画面翻译成需求，是需求分析最实用的一步：页面上每一个可点击的动作，背后都对应着一个接口。

### 七个后端接口是怎么定出来的

按业务对象拆分，接口可以分成两组。

用户相关三个：注册接口、登录接口、以及登录成功后用于展示头像的个人信息查询接口（用户查询）。课程相关四个：查询列表、创建、修改、删除。加起来一共七个接口，正好覆盖演示里出现的所有操作。

这里有个容易忽略的细节：注册成功后之所以能"自动登录"，是因为后端在注册逻辑里就签发了 token，前端拿到后直接进入登录态，不需要再手动调一次登录接口。把这种联动在需求阶段确认下来，能避免联调时反复改动。

### user 表与 course 表的字段设计

接口确定后，字段就顺理成章了。两张表都以 id 作为唯一主键，保证数据唯一性。

user 表（用户）保留最精简的三个业务字段：

| 字段 | 含义 | 说明 |
| --- | --- | --- |
| id | 主键 | 唯一标识 |
| username | 用户名 | 注册、登录凭证 |
| password | 密码 | 注册、登录凭证 |
| image | 头像地址 | 演示中由后端接口写死，前端未做头像上传 |

course 表（课程）字段稍多：

| 字段 | 含义 |
| --- | --- |
| id | 主键 |
| title | 课程标题 |
| price | 价格 |
| point | 评分 |
| category | 分类 |
| picture | 课程封面图 |
| del | 删除标记（软删除） |

讲师特意说明：真实商用项目的注册信息远不止这几项，还可能支持手机号注册，届时就要补充手机号、验证码等字段；这里为了讲清主线，只保留最小集合。同理，"操作"列（编辑、删除按钮）只是页面上的交互，不该落成数据库字段——把展示层动作和持久化数据混在一起，是新手建表常见的坑。

### 用 del 字段实现软删除

course 表里最值得单独讲的是 del。它是一个软删除标记：默认值为 0 表示未删除，被删除时改为 1。后端查询课程列表时先判断 del，只有 del 为 0 的记录才返回给前端。

所以在页面上点"删除"，课程消失了，但数据库里那一行还在——演示中打开 Navicat 刷新 course 表，可以看到被删课程以及临时新建课程的 del 字段都从 0 变成了 1。这种做法的好处是数据可追溯、可恢复，也避免了误删导致关联数据丢失；代价是查询条件必须始终带上 del 过滤，否则"已删除"的数据会重新冒出来。

### 从 entity 到 Navicat：两种建表方式

字段确认后有两种落地方式。第一种是在后端代码里创建 entity 实体文件，用 TypeORM 声明表名和字段，项目初始化启动时由框架自动把表结构同步到数据库——这也是课程后续采用的工程化方式。第二种是直接用 Navicat 手动建表，或者把已建好的库"转储"成 SQL 文件（结构 + 数据），下次在目标库中运行该 SQL 文件即可一次性还原表、字段和初始数据。配套资料 `笔记+资料-已8期/笔记+资料-已8期/xdclass-lowcode.sql` 就是这类转储文件，另有 `全栈低代码平台需求文档.pdf` 与 `图.drawio` 可供对照整体设计。

还有一个演示里的小经验：课程封面图用的是官网经阿里云 OSS 裁剪优化后的图片地址，体积更小。直接复制控制台里带省略号的缩略路径会显示失败，要点击链接跳转后复制完整地址再入库。

### 工程结构与配套资料

本篇虽然停在需求分析，但可以先看一眼后面要用的工程骨架。配套工程是一个 pnpm workspace 多包仓库，根目录脚本用 `pnpm --filter` 分别驱动 client、server、share、release 四个子包：

```json
{
  "scripts": {
    "run:client": "pnpm --filter client run dev",
    "run:server": "pnpm --filter server run start:dev",
    "run:share": "pnpm --filter share run dev",
    "run:release": "pnpm --filter release run dev",
    "build:client": "pnpm --filter client run build",
    "build:server": "pnpm --filter server run build"
  }
}
```

该片段来自 `代码（已8期）/代码（已8期）/9-1/lowcode/package.json`，client 子包基于 Vite + React + TypeScript（见同目录 `packages/client/package.json` 与 `tsconfig.json`）。需求确定之后，就在这个骨架里逐层把接口和表结构实现出来。

## 小结

- 需求分析的正向顺序是：页面功能 → 接口清单 → 数据表字段，先跑通成品演示再反推，最不容易漏需求。
- 本项目共七个接口：用户侧注册、登录、个人信息查询，课程侧增、删、改、查。
- user 表取 username / password / image 的最小集合，course 表含 title / price / point / category / picture / del。
- del 是软删除标记，0/1 两态，查询时必须过滤 del = 0，删除后数据仍保留在库中。
- 建表可用 TypeORM entity 自动同步，也可用 Navicat 转储的 SQL 文件直接导入；页面上的"操作"按钮不是数据库字段。
