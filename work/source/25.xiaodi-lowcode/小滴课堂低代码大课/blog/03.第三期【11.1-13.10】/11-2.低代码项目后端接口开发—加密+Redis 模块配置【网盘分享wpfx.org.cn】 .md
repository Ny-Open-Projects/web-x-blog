# 低代码后端接口开发：加密工具与 Redis 动态模块配置

> **导语**：图形验证码、手机验证码这类接口会被用户高频请求，如果每次都直接读写 MySQL，接口性能很快就会成为瓶颈。本文讲两件配套的基础设施：一是用 MD5 把用户 IP、设备、密码等隐私信息加密后再落库；二是把 Redis 封装成 NestJS 的全局动态模块，用 `set / get / del / exists` 承接验证码的短时存储。读完后你能说清"为什么用 Redis 替 MySQL"，也能照着把模块注册进 `app.module.ts`。

## 正文

### 为什么要加密，为什么要 Redis

像用户密码、IP、设备这些属于隐私信息，无论存进 MySQL 还是缓存 Redis，都应该先加密，不能直接明文落库。上一节已经能从请求里拿到 IP 与设备，把它们拼成字符串后加密，正好可以作为验证码在 Redis 里的 key。

至于为什么引入 Redis，可以从请求链路看：用户频繁请求图形验证码或手机验证码接口时，若每次都直接操作 MySQL，磁盘读写会让接口响应时间变长、性能下降。把随机生成的图形验证码、手机验证码放进 Redis 缓存，读写都在内存里完成，速度更快，接口性能自然就上来了。这也是验证码这种"短时、高频、可丢弃"的数据最适合放缓存的原因。

### 加密工具：用 crypto 做 MD5

在 `utils` 下新建 `secret.ts`，借助 Node.js 内置的 `crypto` 模块实现。类用 `@Injectable()` 装饰，暴露一个 `getSecret(data: string)`，把待加密的字符串传进去，返回加密结果：

```ts
import { Injectable } from '@nestjs/common';
import { createHash } from 'crypto';

@Injectable()
export class Secret {
  getSecret(data: string): string {
    return createHash('md5').update(data).digest('hex');
  }
}
```

三步对应得很清楚：`createHash('md5')` 创建一个 MD5 哈希对象，`update(data)` 把要加密的数据更新进哈希对象，`digest('hex')` 以十六进制形式返回摘要。用户的 IP 拼接设备、或用户密码，都可以作为 `data` 传进来。

### Redis 动态模块的结构

接着在 `utils` 下创建 `redis.module.ts`。它用 `@Module()` 定义，内部通过 `ioredis` 创建一个私有的 Redis 实例（构造时传入连接配置），并把实例的操作重新封装成一组异步方法。对外则通过一个静态 `forRoot` 返回 `DynamicModule`（动态模块），把实例作为 Provider 导出，且设为 `global: true`，这样其他模块不必重复 `imports` 就能注入使用。

结构示意如下（用于说明模块形态，非项目完整源码）：

```ts
import { DynamicModule, Module } from '@nestjs/common';
import Redis, { RedisOptions } from 'ioredis';

@Module({})
export class RedisModule {
  static forRoot(options: RedisOptions): DynamicModule {
    const provider = {
      provide: RedisModule,
      useValue: new Redis(options),
    };
    return {
      module: RedisModule,
      providers: [provider],
      exports: [provider],
      global: true,
    };
  }
}
```

这里的思路和 `TypeOrmModule.forRoot` 类似：官方模块把 `forRoot` 配好了直接调用，而我们要自定义 Redis 模块，就得自己写 `forRoot`、自己声明 Provider、自己指定 `module` 与 `exports`。

### 封装四个操作方法

在模块里把 `ioredis` 的原生方法包一层，方便业务层用异步方式调用：

- `set(key, value, expire?)`：插入数据，若传了过期时间，就在原生 `set` 后追加 `EX` 参数设置有效期；没传则直接写入。
- `del(key)`：按 key 删除。
- `get(key)`：异步取值，从 Redis 拿到的不是字符串，需要转成字符串；没有值则返回 `null`。
- `exists(key)`：判断指定 key 是否存在。

### 验证码的 key 怎么设计

多人同时注册或登录、获取图形验证码时，Redis 里会存很多条记录。设计方式是：把**用户 IP 拼接设备**得到一个字符串，用 MD5 加密后作为图形验证码的 key，value 就是验证码本身，形成一条 `{ key: value }` 数据。

查找时同样先拿到当前用户的 IP 与设备，加密还原出同一个 key，再取出验证码比对；删除和判断存在也都基于这个 key。这样既能隔离不同用户的验证码，又不会把隐私信息明文暴露在 key 里。

### 配置与注册

`config.ts` 里新增 Redis 配置，类型用 `ioredis` 提供的 `RedisOptions`：

```ts
import { RedisOptions } from 'ioredis';

export const RedisConfig: RedisOptions = {
  port: 6379,
  host: '你的服务器 IP',
  password: '创建 Redis 应用时设置的密码',
};
```

端口默认 `6379`，`host` 填自己的服务器地址，`password` 是创建 Redis 应用时设置的密码。

最后在 `app.module.ts` 的 `imports` 里注册，和 `TypeOrmModule.forRoot` 并列：

```ts
@Module({
  imports: [
    TypeOrmModule.forRoot(TypeOrmConfig),
    RedisModule.forRoot(RedisConfig),
  ],
})
export class AppModule {}
```

## 小结

- 用户密码、IP、设备等隐私信息一律加密后再存 MySQL 或 Redis。
- 验证码类接口高频请求，用 Redis 缓存替代直接读写 MySQL 能明显提升接口性能。
- 加密工具基于 Node.js `crypto` 的 `createHash('md5').update(...).digest('hex')`。
- Redis 模块用 `@Module` + 静态 `forRoot` 返回 `DynamicModule`，Provider 设为全局导出。
- 封装 `set / del / get / exists`，其中 `set` 支持 `EX` 过期时间，`get` 需把值转成字符串。
- 验证码 key 由"IP + 设备"经 MD5 生成，兼顾隔离性与隐私。
