# 轮询接口开发—前端监听用户扫码事件请求获取登录状态

> **导语**：本文实现时序图的最后一步——**轮询接口**。前端没有用 WebSocket，而是通过定时请求该接口，传入 `ticket` 查询 Redis 中 `isScan` 是否为 true，从而得知用户是否扫码并拿到后端已生成的 token，完成登录。

## 前置知识

- 已完成《当用户扫码登录时微信服务器发送数据的处理》，Redis 中 ticket 的 `isScan` 会在扫码后变为 `true` 并写入 token。
- 了解 GET 接口与 `@Query()` 参数校验。

## 正文

### 新增轮询控制器

在 `wechat-login.controller.ts` 中加 GET 接口 `check_scan`：

```ts
@Get('check_scan')
async checkScan(@Query() query: { ticket: string }) {
  return this.wechatLoginService.checkScan(query);
}
```

参数只有一个 `ticket`（字符串）。

### 服务层查询 Redis 状态

```ts
async checkScan({ ticket }: { ticket: string }) {
  const redisKey = `wechat:ticket:${ticket}`;
  const redisData = JSON.parse(
    (await this.redis.get(redisKey)) as string
  );
  if (redisData && redisData.isScan === true) {
    return { data: redisData.token, msg: '登录成功' };
  }
  return { data: null, msg: '等待用户扫码' };
}
```

从 Redis 取出的 JSON 字符串需 `JSON.parse` 还原为对象，再判断 `isScan`。为 `true` 时返回 token，否则提示「等待用户扫码」。

### 接口联调

1. 先请求「获取二维码」接口拿到 `ticket`。
2. 在未扫码时请求 `/api/wechat_login/check_scan?ticket=xxx`，返回「等待用户扫码」。
3. 用手机微信扫码后，再次请求同一接口，返回 `data` 为 token、提示「登录成功」。

> 二维码有效期仅 120 秒，扫码动作要快，过期需重新获取。

## 小结

- 轮询接口为 GET `/wechat_login/check_scan`，唯一参数是 `ticket`。
- 前端定时请求该接口，后端查 Redis 的 `isScan` 与 token。
- `isScan === true` 即扫码完成，返回 token 给前端；否则返回「等待用户扫码」。
- 本项目用轮询而非 WebSocket 实现扫码状态通知。
