# 低代码项目后端接口开发：图形验证码接口

> **导语**：注册、登录前的第一道人机校验，往往是一个图形验证码。本文把低代码平台后端这个接口完整拆开：统一 `/api` 前缀、用 svg-captcha 生成 SVG 验证码、用「用户 IP + 设备」加密出 Redis key、按业务类型分层缓存 60 秒，并把 SVG 与随机文本返回前端。末尾还会复盘一个真实的启动报错——把 `RedisModule` 误当成 provider 注册。

## 正文

### 统一接口前缀

为了把「用户相关」与「低代码 / 页面编辑相关」的接口区分开，先在 `main.ts` 设置全局前缀：

```ts
app.setGlobalPrefix('api');
```

此后所有接口都挂在 `/api` 下，例如用户模块的图形验证码接口就是 `/api/user/captcha`。

### 生成图形验证码的工具类

图形验证码借助第三方插件 `svg-captcha` 生成。新建一个工具类（如 `captcha.util.ts`），引入插件后导出 `CaptchaTool`，内部调用插件的 `create` 方法拿到验证码对象。可配置项包括：验证码长度、排除容易混淆的数字与字母、干扰线、背景颜色、图片高度等。生成结果是 **SVG 格式**，后端不做图片处理，把 SVG 数据交给前端渲染成图片即可。

### DTO：用 type 区分场景

控制器里把 POST 路径改为 `captcha`，方法名改为 `getCaptcha`，调用 `this.userService.getCaptcha(...)`；同时加 `@Body()` 接收参数。DTO 重命名为 `captcha.dto.ts`、类名 `CaptchaDto`，只接收一个字段：

- `type`：`string` 类型、不能为空。
- 用来区分这次验证码是**注册**（`register`）还是**登录**（`login`）场景下请求的，便于后面按场景做校验与缓存隔离。

### Controller：算出加密 key

拿到 body 之后，把「用户 IP + 设备」通过加密工具 `SecretTool` 的 `getSecret` 算出一个 `key`，再把 `key` 与 `type` 一起传给服务层。用 IP + 设备加密的目的，是让同一台设备/用户对应一个稳定的缓存键，避免不同用户的验证码互相覆盖：

```ts
@Post('captcha')
async getCaptcha(@Body() body: CaptchaDto) {
  const key = this.secretTool.getSecret(/* 用户 IP + 设备 */);
  return this.userService.getCaptcha(key, body.type);
}
```

### Service：生成、缓存、返回

服务层注入两个依赖：`CaptchaTool` 与 Redis 服务，并在 `user.module.ts` 的 `providers` 里把工具类与加密工具声明好。核心流程四步：

1. `await this.captchaTool.captcha()` 异步拿到 SVG 数据与四位随机文本 `text`。
2. 调用 Redis 的 `set` 写入：key 用冒号**分层**，区分业务（图形验证码用 `captcha`，以后短信验证码用 `code`）、前端传来的 `type`、以及加密后的 `key`。
3. 设置 **60 秒**过期时间，超时自动失效。
4. 把 `data`（SVG）与 `text`（四位随机验证码）返回给前端。

```ts
async getCaptcha(key: string, type: string) {
  const svgCaptcha = await this.captchaTool.captcha();
  await this.redisService.set(
    /* captcha:type:key 形式的分层键 */,
    svgCaptcha.text,
    /* 60 秒过期 */,
  );
  return { data: svgCaptcha.data, text: svgCaptcha.text };
}
```

注意 `captcha()` 是异步方法，服务层要加 `async/await`；控制器那一层只是转发，不需要重复加。

### 报错复盘：providers 里放错了模块

启动时抛出 `RedisModule` 相关错误。排查发现：`RedisModule` 已经在 `app.module.ts` 里通过 `imports` 全局引入，而 `user.module.ts` 里复制粘贴时把 `RedisModule` 误放进了 `providers`——这里真正该放的是加密工具 `SecretTool`。改回来重新加载，服务即启动成功。这个坑的本质是「全局模块」与「本模块 provider」混淆。

### 联调验证

在 ApiFox 里用 POST 请求 `/api/user/captcha`，body 传 `{ "type": "register" }`。第一次失败是因为路径少写了一个斜线；修正后返回成功，响应 `data` 里是 SVG 字符串、`text` 是四位随机验证码，前端拿 `data` 渲染成图片即可。

## 小结

- 用 `app.setGlobalPrefix('api')` 统一接口前缀，区分用户模块与低代码编辑模块。
- `svg-captcha` 生成 SVG 验证码，配置项含长度、排除字符、干扰线、背景色、高度；后端只返回数据，渲染交给前端。
- `CaptchaDto` 的 `type` 区分注册/登录场景，校验为非空字符串。
- 用「IP + 设备」加密得到 key，Redis 以冒号分层缓存、60 秒过期，返回 `data` 与 `text`。
- 全局模块（RedisModule）通过 `imports` 引入，不要误放进子模块的 `providers`。
