# 低代码项目后端接口开发—获取用户信息装饰器配置

> **导语**：开发图形验证码之前，必须先解决一个问题：张三和李四同时点「获取验证码」，后端怎么保证两人拿到的是各自的那张图？答案是把用户 IP 与设备信息拼成唯一标识，绑定到验证码上存进 Redis。本文用 NestJS 的 `createParamDecorator` 封装 `GetUserIp` 与 `GetUserAgent` 两个自定义参数装饰器，并在控制器里验证返回 127.0.0.1 与 user-agent。

## 前置知识

建议先读《什么是装饰器和Nestjs中的应用》，理解装饰器与参数装饰器的基本写法。另需了解 NestJS 的 `ExecutionContext`、HTTP 请求对象上的 `ip` 与 `headers`，以及 Redis 在验证码场景中的作用。配套工程见 `代码（已8期）/代码（已8期）/11-1/lowcode/`。

## 正文

### 开发流程：一个模块一个模块地推进

本课程按模块推进：先把注册登录模块做完，再开发低代码编辑页、后台数据管理页与发布页。每个模块都遵循同一节奏——**先准备后端接口，接口开发完成再写前端页面并联调**。

本章第一节先做注册，注册要用到图形验证码与手机验证码。图形验证码的作用是拦住恶意用户或非人为脚本盗刷短信验证码，避免短信成本被拉高。

### 为什么要取 IP 和设备

设想两台电脑：张三和李四同时登录系统、同时点击「获取图形验证码」。如果后端只生成一张图，两人的验证码就会串。

不同设备、不同网络访问时，IP 与设备信息都不一样。于是把「张三的 IP + 设备」生成一个唯一标识，绑定到他这次点击生成的图形验证码上，存进 Redis；请求返回时取到的就是张三那张。李四同理，互不混淆。

另外，注册、登录、修改密码都会用到图形验证码，所以前端请求后端时会带一个 `type` 参数区分场景，后端按需生成即可。

### 用 createParamDecorator 封装两个装饰器

在 `src/utils/` 下新建工具文件（如 `getUserMsg.ts`），从 `@nestjs/common` 引入 `createParamDecorator` 与 `ExecutionContext`。自定义参数装饰器的工厂回调接收两个参数：`data` 与执行上下文 `ctx`。

```ts
import { createParamDecorator, ExecutionContext } from '@nestjs/common';

// 获取用户 IP（匹配 IPv4 并转成字符串）
export const GetUserIp = createParamDecorator(
  (_data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return String(request.ip).match(/\d+\.\d+\.\d+\.\d+/)?.[0] ?? '';
  },
);

// 获取用户设备信息
export const GetUserAgent = createParamDecorator(
  (_data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return request.headers['user-agent'] ?? '';
  },
);
```

几个关键点：

- `ExecutionContext` 继承自 NestJS 的参数主机接口，通过 `switchToHttp().getRequest()` 拿到当前 HTTP 请求对象。
- IP 装饰器里 `request.ip` 在本地常是 `::1`、`::ffff:127.0.0.1` 这类格式，不是我们想要的 `127.0.0.1`，所以用正则匹配 IPv4 片段再转成字符串；用 `?.` 可选链保证匹配不到时不报错。
- 设备装饰器取的是 `headers['user-agent']`，注意拼写必须是 `user-agent`。课程里这里曾写错成别的字符串，接口直接返回 500，排查时回头对照笔记才修正——这类低级拼写错误在调试里很常见。
- `data` 参数本篇用不到，保留占位即可。想深挖 `createParamDecorator` 的实现，可以直接读 NestJS 源码。

### 在控制器里挂载并验证

在 `user.controller.ts` 的请求方法参数里使用这两个装饰器：

```ts
@Get('info')
getUserInfo(
  @GetUserIp() ip: string,
  @GetUserAgent() agent: string,
) {
  return { ip, agent };
}
```

启动项目后用 Apifox 请求该接口，返回的 `data` 里应包含：

```json
{
  "ip": "127.0.0.1",
  "agent": "ApiFox/1.0.0"
}
```

`ip` 正是本机请求地址，`agent` 是接口调试工具的标识。若启动时报某个包找不到，执行 `pnpm install` 补齐依赖即可——备课时的 `package.json` 偶尔会漏掉个别插件。

## 小结

- 图形验证码要用「IP + 设备」生成唯一标识绑定用户，存 Redis 后才不会串号。
- 注册 / 登录 / 修改密码共用验证码，靠前端传入的 `type` 区分场景。
- `createParamDecorator` 的工厂回调拿到 `ExecutionContext`，`switchToHttp().getRequest()` 取请求对象。
- IP 需要正则匹配转成标准 IPv4 字符串；设备取 `headers['user-agent']`，拼写务必准确。
- 两个参数装饰器挂在控制器方法参数上，返回 `{ ip, agent }` 即可验证。
