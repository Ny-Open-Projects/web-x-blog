## 正文

### 新增前端发布的并行任务

在构建阶段再**添加一个并行任务**，专门用于前端发布（Next.js）项目。和后端一样，前端发布也有两个镜像：Nginx 镜像 + 项目镜像。本集先构建 Nginx 镜像。

### 配置前端发布 Nginx 镜像

选择**阿里云镜像构建个人版**，关键配置：

- 步骤名称：`部署前端releaseNginx镜像`（前端发布 Nginx 镜像）；
- 地域：广州；
- 仓库 / 命名空间：自动匹配到 `local-images`；
- **标签（Tag）**：自定义为 `frontend-nginx-<环境变量>`，对应 `docker-compose.yml` 里的 `frontend_nginx_tag`；
- **Dockerfile 路径**：填 `release/nginx.dockerfile`。

```yaml
# docker-compose.yml 中前端发布 Nginx 服务的镜像引用
frontend_nginx:
  image: ${frontend_nginx_tag}
  restart: always
  ports:
    - "4000:80"
```

### 任务输出

执行后流水线会输出标签 `frontend-nginx-<环境变量>`，后续部署阶段就是凭这个标签把前端发布 Nginx 镜像拉到自己的服务器。

### 镜像命名不要混淆

前端发布这条线容易和后端混淆，记住两个镜像的差异：

- `frontend-nginx-<环境变量>` → 前端发布的 Nginx 代理镜像（`release/nginx.dockerfile`）；
- `frontend-<环境变量>` → 前端发布的项目镜像（`release.dockerfile`），下一集讲解。

## 小结

1. 前端发布 Nginx 镜像通过新的并行任务 + 阿里云镜像构建个人版完成。
2. 标签 `frontend-nginx-<环境变量>` 对应 `docker-compose.yml` 中的 `frontend_nginx_tag`。
3. 对应的 Dockerfile 是 `release/nginx.dockerfile`。
4. 命名空间仍统一使用 `local-images`。
5. 前端发布还差一个项目镜像，下一集补齐。
