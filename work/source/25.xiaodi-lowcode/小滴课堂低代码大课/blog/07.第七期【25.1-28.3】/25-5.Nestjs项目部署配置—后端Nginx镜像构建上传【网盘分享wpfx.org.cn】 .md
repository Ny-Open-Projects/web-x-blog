## 正文

### 新增一个并行任务

在流水线构建阶段里，前面已经有前端 React 的并行任务。我们再**添加一个并行任务**，选择**阿里云镜像构建个人版**。这一步和前端打包是同时进行的，互不阻塞。

### 关联 ACR 服务连接

镜像要推送到阿里云容器镜像服务，前提是在阿里云开通了 ACR（个人版即可免费使用），并创建了命名空间。本课程的命名空间叫 `local-images`，所有镜像都集中放在这里。

在流水线里选择**服务连接**时，如果之前已经关联过 ACR，会直接列出；没有的话点击"添加服务连接"并授权即可。本集我们已关联好，直接使用。

### 配置后端 Nginx 镜像

镜像构建步骤的关键配置项：

- 步骤名称：`部署后端Nginx镜像`（即后端 Nginx 镜像）；
- 地域：选择与你的云服务器同地域（本课程服务器在广州，选**广州**）；
- 仓库 / 命名空间：自动匹配到 `local-images`；
- **标签（Tag）**：自定义为 `backend-nginx-<环境变量>`，作为后续拉取该镜像的别名；
- **Dockerfile 路径**：填 `server/nginx.dockerfile`，这是生成后端 Nginx 镜像的构建文件。

配置示例如下（docker-compose 中对应服务引用的就是该标签变量）：

```yaml
# docker-compose.yml 中后端 Nginx 服务的镜像引用
backend_nginx:
  image: ${backend_nginx_tag}
  restart: always
  ports:
    - "5000:80"
```

### 四个镜像的整体规划

后端 Nginx 镜像只是其中之一。整套平台一共需要构建**四个镜像**：

1. 后端项目镜像（`backend`）；
2. 后端 Nginx 镜像（`backend_nginx`）；
3. 前端发布（Next.js）项目镜像（`frontend`）；
4. 前端发布 Nginx 镜像（`frontend_nginx`）。

四个镜像都推送到同一个 ACR 命名空间 `local-images`，后续由 `docker-compose.yml` 统一拉起。

## 小结

1. 后端镜像构建通过"阿里云镜像构建个人版"步骤完成，与前端任务并行。
2. 必须先在阿里云开通 ACR 并创建命名空间（本课程用 `local-images`）。
3. 标签 `backend-nginx-<环境变量>` 是后续部署阶段拉取镜像的凭据。
4. 后端 Nginx 镜像对应的 Dockerfile 是 `server/nginx.dockerfile`。
5. 四个镜像统一归集到 ACR，等待部署阶段一起启动。
