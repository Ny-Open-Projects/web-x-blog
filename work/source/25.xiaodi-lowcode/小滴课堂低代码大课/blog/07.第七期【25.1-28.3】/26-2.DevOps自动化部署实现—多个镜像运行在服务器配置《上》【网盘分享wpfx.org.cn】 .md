# DevOps自动化部署实现—多个镜像运行在服务器配置《上》

> **导语**：`docker-compose.yml` 已经上传到自有服务器，但四个镜像还躺在 ACR 里。本集讲解部署阶段的第三个任务——"Docker 部署"，重点剖析启动前清理旧容器 / 旧镜像的脚本逻辑，以及 `docker compose up -d` 一键启动四个服务。

## 正文

### 第三个阶段：Docker 部署任务

在流水线里再添加一个任务，类型选择 **Docker 部署**，主机选择已关联的自有服务器，执行用户为 `root`。这一阶段的目的是：从 ACR 拉取四个镜像，用 `docker-compose.yml` 把它们启动成容器。

### 启动前的清理脚本（为什么要先 stop / rm / rmi）

每次重新上线，都必须先把旧容器和旧镜像清掉，否则同名容器已存在会直接报错。脚本核心逻辑如下：

```bash
# 1. 停止所有 name 含 local 的容器（取容器 ID 第一列）
docker stop $(docker ps -a | grep local | awk '{print $1}') || true

# 2. 删除这些容器
docker rm $(docker ps -a | grep local | awk '{print $1}') || true

# 3. 删除对应镜像（取镜像 ID 第三列）
docker rmi $(docker images | grep local | awk '{print $3}') || true
```

说明：

- `docker ps -a` 列出所有容器（含已停止）；`grep local` 过滤出本项目相关容器；`awk '{print $1}'` 提取容器 ID 第一列。
- `|| true` 很关键：第一次部署时可能没有任何容器，命令失败也不能让流水线中断，必须允许继续往下执行。
- 删除镜像用 `docker images` 取第三列（IMAGE ID）而非第一列。

### 启动四个服务

清理完成后，用指定文件启动所有服务，并后台运行：

```bash
# 使用指定的 compose 文件，后台(-d)启动其中定义的所有服务
docker compose -f /root/yx/docker-compose.yml up -d
```

`docker compose -f` 表示使用指定路径的编排文件；`up` 是启动；`-d` 是后台运行。执行后 compose 文件里引用的四个镜像会被拉取、生成容器并运行起来，项目随即启动。

## 小结

1. Docker 部署任务在自有服务器上执行，从 ACR 拉取四个镜像。
2. 上线前必须先 `docker stop` / `docker rm` / `docker rmi` 清理同名旧容器与镜像，否则会冲突报错。
3. 用 `grep local` + `awk` 提取容器 / 镜像 ID，`|| true` 保证首次部署不中断。
4. `docker compose -f <文件> up -d` 一键启动四个服务并后台运行。
5. 脚本之所以这样写，是为了支持"改代码 → 重新上线"的反复部署。
