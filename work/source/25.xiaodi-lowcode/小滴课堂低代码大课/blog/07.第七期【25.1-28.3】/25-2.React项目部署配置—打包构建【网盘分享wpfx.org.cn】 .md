# React 项目部署配置—打包构建

> **导语**：代码源关联到阿里云云效之后，流水线的第一步就是「打包构建」。本文讲清在云效里新建任务、把步骤换成 Node.js 构建、选对 Node 版本，以及那段构建脚本为什么必须先 `build:share` 再 `build:client`。跑完这一步会产出 `dist` 目录，下一步才轮到上传 OSS。

## 前置知识

建议先读《DevOps自动化部署实现—流水线关联代码源》，此时低代码项目的代码仓库已关联到云效流水线。另需了解 pnpm workspace 的多包结构、单页应用（SPA）构建产物与 OSS Bucket 托管的关系，以及 `build:share` / `build:client` 这类根目录脚本的作用。

## 正文

### 三个项目，先部署 React

关联进来的仓库里有三个子项目：React 编辑端（`client`）、NestJS 后端（`server`）、Next.js 发布页（`release`）。本节先只处理 React 项目。

React 是单页面应用，部署路径最短：把打包后的代码上传到 OSS Bucket，指定入口为 `index.html`，再给 Bucket 绑定域名即可访问。后端与服务端渲染项目不同，它们要传到自己的服务器上，后面再分别配置。

### 新建任务与构建步骤

在云效流水线里点「新建任务」，模板选择「镜像构建并推送阿里云镜像仓库个人版」，把任务名改成「React项目部署配置」。前三步保持默认容器环境即可——这些脚本跑在云效流水线提供的服务器上，代码已经关联过去，能直接找到仓库内容。

然后删掉默认步骤，添加一个「Node.js 构建」步骤，重命名为「打包构建」，Node 版本选 **18.12**。注意：任务模板虽然叫「镜像构建」，但这里实际要的是 Node.js 构建环境，别被模板名带偏。

### 构建脚本的五个动作

流水线里要执行的脚本按这个顺序写：

```bash
# 1. 切换为国内镜像源，加速依赖下载
npm config set registry <国内镜像源地址>

# 2. 全局安装 pnpm
npm install pnpm -g

# 3. 安装整个工程的依赖
pnpm install

# 4. 先构建公共子包 share
pnpm run build:share

# 5. 构建 React 编辑端
pnpm run build:client
```

顺序里最值得注意的是第 4 步：`share` 公共子包提供了公共组件与类型定义，`client`、`release`、`server` 都依赖它，所以**必须先打包 share**，其他子包才能正常引用。这些 `build:*` 脚本都配置在根 `package.json` 里，流水线直接调用即可。

`pnpm install` 之所以能一次装完，是因为代码源已关联、整仓代码都在流水线工作区里。构建完成后会生成 `dist` 目录——这就是后面要上传到 OSS 的产物。

### 这一节只做了一半

到这一步为止，只是把代码构建成了线上环境可运行的产物，还没真正上线。保存流水线配置后，`dist` 仍躺在云效的构建服务器上，下一步要把它上传到 OSS、配置 Bucket 与域名，用户才能访问到编辑端页面。

## 小结

- 仓库含 React / NestJS / Next.js 三个子项目，本节先部署 React 这个 SPA。
- SPA 打包产物上传 OSS Bucket，指定 `index.html` 并绑定域名即可访问。
- 任务模板选「镜像构建…个人版」，但步骤要改成「Node.js 构建」，Node 版本 18.12。
- 构建脚本顺序：设镜像源 → `npm install pnpm -g` → `pnpm install` → `build:share` → `build:client`。
- 必须先构建 `share`，其余子包才能引用公共类型与组件；最终产物是 `dist` 目录。
