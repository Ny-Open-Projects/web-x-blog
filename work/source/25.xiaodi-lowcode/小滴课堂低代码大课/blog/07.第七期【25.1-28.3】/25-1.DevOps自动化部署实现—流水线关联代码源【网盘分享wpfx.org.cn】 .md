# DevOps 自动化部署实现：流水线关联代码源

> **导语**：自动化部署的第一步，是让流水线知道"代码在哪"。本文以阿里云云效为例，讲清从控制台进入云效 DevOps、在 Codeup 代码仓库里创建空模板流水线、添加流水线源并关联代码仓库的完整操作，并对比"从代码仓库创建"与"从流水线模块创建"两条路径在代码源、服务连接上的差异。读完你能把低代码项目的代码源正确接入流水线。

## 前置知识

建议先读《项目部署上线—互联公司的DevOps和CI-CD你知道多少？》建立 CI/CD 的整体概念，再读《项目部署上线—云效DevOps开通使用介绍》完成云效开通（创建流水线的前提）。此外，前面几集的 Dockerfile 与 Docker Compose 文件是本流水线的构建依据，可参照《项目部署上线—构建后端镜像的Dockerfile配置》。

## 正文

### 目标：一键部署要先把代码接进来

上一节介绍了阿里云云效的流水线：代码提交后，在平台上点击运行，就能自动把代码部署上线。本集先做最基础也最关键的一步——**流水线关联代码源**，即让这条流水线绑定低代码项目的代码仓库。后面往流水线里加构建、镜像、部署等步骤，都建立在这个关联之上。

### 进入云效与代码管理

在阿里云控制台搜索"云效"，点击"云效 DevOps"进入。云效包含多个模块，先进入代码管理 **Codeup**，这里维护着本地开发提交上来的全部代码。

打开仓库能看到前面课程产出的部署配置：前端 nginx 与前端项目的 Dockerfile、后端服务与后端 nginx 的 Dockerfile，以及 Docker Compose 文件——后者正是用来一键完成镜像生成、容器创建与容器运行的。这些文件都在仓库里，流水线才能读取并据此构建。

### 创建空模板流水线

在 Codeup 仓库页面右上方点击"创建流水线"（需先开通流水线功能）。平台会弹出模板选择，选中**空模板**再点击创建，得到一条空的流水线。

之所以选空模板，是因为我们要按项目实际需要自己编排各阶段；模板自带的通用步骤反而用不上。

### 添加流水线源：两条路径的差别

创建后第一步是"添加流水线源"。这里有个容易忽略的差异，取决于你是从哪条链路创建流水线的：

| 创建路径 | 代码源 | 是否自动关联 | 额外操作 |
| --- | --- | --- | --- |
| 在 Codeup 代码仓库内创建 | Codeup | 自动带出仓库与服务连接 | 基本无需手填 |
| 在"流水线 Flow"模块里新建 | Codeup / GitHub / Gitee / GitLab 等 | 不自动关联 | 需填仓库地址、添加服务连接 |

本项目走的是第一条：因为流水线直接从代码仓库里创建，点击"添加流水线源"后会自动生成好关联，代码源选择 **Codeup** 即可。此时服务连接也已自动带出（若之前建过多个，会看到不止一个）；代码仓库自动填充为项目仓库，分支选 **master**，其余勾选项都不用勾选，点击"仅保存"即完成。

若代码并不托管在云效，而是 GitHub、Gitee、GitLab 等，就得走第二条路径：在流水线 Flow 模块新建空模板流水线，添加流水线源时选择对应的代码源，填入仓库地址，并通过"添加服务连接"完成授权。这条链路不会自动帮你关联。

### 完成状态与后续

保存后，这条空流水线就已经关联上了云效里的项目代码，代码源、仓库、分支、服务连接四项都就位。注意此时流水线还是空的——它只知道代码在哪，还没配置"拿到代码后做什么"，那是后续集数要往里添加的步骤。

## 小结

- 自动化部署第一步是关联代码源：让流水线绑定到低代码项目的代码仓库。
- 入口：阿里云控制台 → 云效 DevOps → 代码管理 Codeup → 右上角创建流水线 → 选空模板 → 创建。
- Codeup 仓库里已有各 Dockerfile 与 Docker Compose 文件，是流水线后续构建的依据。
- 从代码仓库创建会自动带出代码源（Codeup）、仓库、服务连接；从流水线 Flow 模块新建则需手填仓库地址并添加服务连接。
- 分支选 master、其余不勾选、点"仅保存"即可；保存后流水线仍为空，构建部署步骤留待后续添加。
