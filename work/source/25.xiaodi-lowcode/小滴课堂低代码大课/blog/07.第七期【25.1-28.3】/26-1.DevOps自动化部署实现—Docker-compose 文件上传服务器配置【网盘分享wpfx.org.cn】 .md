# DevOps自动化部署实现—Docker-compose 文件上传服务器配置

> **导语**：构建阶段把 `docker-compose.yml` 暂存到了云效公共存储空间，本集进入部署阶段的第一步——通过"主机部署"把这个编排文件真正上传到我们自己的服务器，并解压到指定目录，为后续一键启动四个容器做准备。

## 前置知识

- 已完成《Nextjs项目部署配置—服务端渲染项目镜像构建上传》，四个镜像已推送到 ACR。
- 已在云效关联自己的服务器（主机组），并理解"制品"的概念，参见《DevOps自动化部署实现—流水线关联代码源》。

## 正文

### 新建部署阶段与主机部署任务

在流水线里**新建一个阶段**，添加一个任务，选择**主机部署**。部署阶段必须等前面的构建阶段（四个镜像 + compose 文件）全部完成才能执行。

### 下载制品：取回 compose 文件

任务配置要点：

- 任务名称：`Docker-compose文件上传`；
- 勾选**部署时下载制品**；
- **选择制品**：就是构建阶段"Docker-compose.yml文件上传"步骤产出的那个制品（如 `doc-compose-<环境变量>`）。凭这个制品名称，云效会把暂存在公共存储空间的压缩包下载到执行机。

回顾一下前面各步骤产出的制品：后端项目镜像 `backend-<环境变量>`、后端 Nginx 镜像 `backend-nginx-<环境变量>`、前端发布项目镜像 `frontend-<环境变量>`、前端发布 Nginx 镜像 `frontend-nginx-<环境变量>`，以及本集要用的 compose 文件制品。

### 配置主机组与下载路径

- **主机组**：选择已关联的自有服务器（首次使用需"新建主机组"，环境选日常环境）；
- **下载路径**：自定义为 `/root/yx/backend.tgz`。`.tgz` 表示这是一个经过 tar 压缩的文件，目录不存在时会自动创建。

```
/root/yx/backend.tgz   # compose 文件压缩包上传到自有服务器的路径
```

### 执行脚本：解压到目标目录

文件上传后仍是压缩状态，需要在 Linux 上解压。执行用户用 `root`，脚本大致如下：

```bash
# 解压压缩包，并把内容放到上一级目录 /root/yx 下
tar zxvf /root/yx/backend.tgz -C /root/yx
```

这样 `docker-compose.yml` 就落在 `/root/yx/docker-compose.yml`，后续可以直接 `docker compose` 调用。

## 小结

1. 部署阶段用"主机部署"任务，把 compose 文件从云效公共存储空间拉到自有服务器。
2. 通过"下载制品"选中构建阶段产出的 compose 制品即可取回文件。
3. 主机组指向已关联的自有服务器，下载路径自定义（如 `/root/yx/backend.tgz`）。
4. 用 `tar zxvf ... -C /root/yx` 解压，使 `docker-compose.yml` 落到目标目录。
5. 文件就位后，还缺四个镜像，下一集把它们也拉到服务器。
