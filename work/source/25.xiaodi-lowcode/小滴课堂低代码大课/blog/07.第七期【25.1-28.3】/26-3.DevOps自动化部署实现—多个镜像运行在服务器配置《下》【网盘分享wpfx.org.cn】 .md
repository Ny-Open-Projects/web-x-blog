# DevOps自动化部署实现—多个镜像运行在服务器配置《下》

> **导语**：上一集的部署脚本用 `docker compose up` 启动了服务，但 compose 文件里的镜像是通过变量引用的，变量从哪来？本集讲解如何在部署任务中配置四个镜像变量，并把它们关联到上游构建阶段产出的制品，完成整条自动化部署链路。

## 正文

### 为什么需要四个镜像变量

`docker-compose.yml` 里四个服务的 `image` 字段都是变量，而不是写死的镜像地址：

```yaml
backend:         image: ${backend_tag}
backend_nginx:   image: ${backend_nginx_tag}
frontend:        image: ${frontend_tag}
frontend_nginx:  image: ${frontend_nginx_tag}
```

在自己的服务器上执行 `docker compose up` 时，必须让这些变量有值，否则不知道去哪拉镜像。这些变量的值，正是上游构建阶段"镜像构建并推送"步骤输出的制品标签。

### 在部署任务中配置变量

在 Docker 部署任务的**变量**配置区，依次添加四个变量，并分别关联上游制品：

| 变量名 | 关联的上游制品（标签） |
| --- | --- |
| `backend_tag` | 后端项目镜像 `backend-<环境变量>` |
| `backend_nginx_tag` | 后端 Nginx 镜像 `backend-nginx-<环境变量>` |
| `frontend_tag` | 前端发布项目镜像 `frontend-<环境变量>` |
| `frontend_nginx_tag` | 前端发布 Nginx 镜像 `frontend-nginx-<环境变量>` |

配置时可以直接从下拉里选择对应制品，无需手动复制粘贴，避免选错（尤其 `frontend_tag` 与 `frontend_nginx_tag` 容易混淆）。

### 整条链路总结

至此三个项目全部打通：

1. **React 编辑平台**：打包构建 → 上传 OSS Bucket，绑定域名即可访问；
2. **后端（NestJS）**：两个镜像（项目 + Nginx）推到 ACR，由 compose 拉起；
3. **前端发布（Next.js）**：两个镜像（项目 + Nginx）推到 ACR，由 compose 拉起；
4. **一键启动**：`docker compose up -d` 同时运行四个容器。

镜像来源就是这里配置的四个变量，它们把"上游构建产出的制品"和"自有服务器上的启动"关联了起来。

### 触发方式：手动 or 自动

配置完成后，在云效流水线点击**运行**即可一键上线（前提是代码已提交到云效代码源）。也可以配置**定时触发**或 **WebHook 触发**，实现推送代码自动部署。不过课程建议手动点"运行"更稳妥——避免把还没开发完的功能误上线。

## 小结

1. compose 文件用变量引用镜像，变量值来自上游构建阶段输出的制品标签。
2. 四个变量 `backend_tag` / `backend_nginx_tag` / `frontend_tag` / `frontend_nginx_tag` 需逐一关联对应制品。
3. 变量配置支持从下拉选择，避免手动填错。
4. 整条链路：React→OSS、后端两镜像→ACR、前端发布两镜像→ACR、compose 一键启动。
5. 推荐手动触发流水线运行，谨慎使用 WebHook 自动触发。
