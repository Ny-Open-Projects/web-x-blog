# 前端 client 项目使用公共项目 share 变量

> **导语**：在 pnpm workspace 多包架构里，前端 client 与后端 server 往往需要复用同一份类型、常量或工具方法。本节演示如何在 client 子项目中引入公共包 `@lowcode/share`，把共享变量渲染到页面，并同理在 server 中使用，为后续联调打好基础。

## 前置知识
- 已搭建 pnpm workspace 多包工程，公共包 `@lowcode/share` 已创建：建议先看《公共组件+类型子项目 share 创建和项目配置》。
- 了解 pnpm 的 `--filter` 按包过滤执行命令的基本用法。

## 正文
### 为什么需要共享包
低代码平台采用 monorepo 结构，client、server、release、share 四个子包同仓维护。share 负责存放跨端复用的类型定义、常量与工具函数。若每个子项目都手动拷贝一份，极易出现版本不一致。通过 workspace 协议把 share 作为依赖引入，既能共享又能保证单一数据源。

### 在 client 中安装 @lowcode/share
根目录执行过滤安装，只对 client 包生效：

```bash
pnpm --filter client add @lowcode/share
```

安装完成后，client 的 package.json 中会出现如下依赖声明（节选自关联代码 `代码（已8期）/8-6/lowcode/packages/client/package.json`）：

```json
{
  "name": "@lowcode/client",
  "dependencies": {
    "@lowcode/share": "workspace:^"
  }
}
```

`workspace:^` 表示指向工作区内同名的本地包，而不是从 npm 远程下载，这正是 pnpm workspace 实现子项目联动的关键。

### 在页面中引入共享变量
打开前端入口文件 `src/App.tsx`，先清理掉脚手架默认内容，再按需引入 share 导出的变量并渲染：

```tsx
import { sharedText } from '@lowcode/share';

function App() {
  return <div>{sharedText}</div>;
}
```

启动开发服务：

```bash
pnpm run client
```

访问终端打印的本地地址（默认 `http://localhost:5174`），即可看到 share 提供的文本内容成功渲染，说明跨包引用已生效。

### 在 server 中同样使用
后端服务使用方式一致，先为 server 安装依赖：

```bash
pnpm --filter server add @lowcode/share
```

随后在控制器里引入共享变量并返回给接口即可。Nest 默认监听 3000 端口，访问 `http://localhost:3000` 就能在接口返回的 JSON 中看到来自 share 的数据。

## 小结
- pnpm workspace 通过 `workspace:^` 把本地子包作为依赖，实现多包联动。
- client 与 server 共用 `@lowcode/share`，避免重复拷贝代码。
- 用 `--filter 包名` 可以只对指定子项目执行安装、构建等命令。
- 公共变量改动后，依赖方无需手动同步，统一由 share 一处维护。
