# TypeORM 框架—一对多关系表关联和查询

> **导语**：上一节讲了一对一，本节进入更常见的一对多：一个班级对应多个学生。你会看到 `@OneToMany` 与 `@ManyToOne` 如何成对出现、`relations` 选项怎样在一次查询里把关联数据一起带出来，以及两个特别容易忽略的坑——外键字段没填导致关联结果为空、关系属性名写错导致查询报错。掌握之后，就不用再手动查多张表再拼数据了。

## 前置知识

需要先能连上数据库并定义实体，建议先看过《TypeORM 框架-轻松掌握链接 Mysql 数据库配置》与《TypeORM 框架—配置实体和自动同步数据库》，并熟悉《TypeORM 框架—实现数据库增+查操作》里的仓储查询写法。本节紧接《TypeORM 框架—一对一关系表关联和查询》，把 `@OneToOne` 的思路迁移到一对多即可。

## 正文

### 用班级与学生建立一对多

例子很直观：数据库里有两个班级（六年一班·实验班、六年二班·普通班），三个学生（张三、李四、王五），每个学生通过 `classId` 记录自己属于哪个班级。班级是「一」、学生是「多」，一个班级对应多个学生，这就是一对多。

与一对一不同的是装饰器要**成对、且方向相反**：

- 班级侧 `@OneToMany()`，指向 `Student`；
- 学生侧 `@ManyToOne()`，指向 `Classes`。

两侧的回调参数除了「关联到哪个实体」，还要指明「用对方哪个属性回指自己」，关系才算建立完整。中间靠 `classId` 这个字段把两条记录串起来。

### 实体定义与命名避坑

新建班级实体时不要直接叫 `Class`——它容易和语言里的 `class` 关键字/已有命名冲突，改名为 `Classes`。字段大致是 `id`、班级名称、班级类型（实验班/普通班），再加一个 `@OneToMany(() => Student, (student) => student.classes)` 关联到学生表，查询结果挂在一个数组属性（如 `studentList`）上。这个属性就是「查班级时顺带带出学生列表」的落点，类型声明也要按数组来写。

学生实体 `Student` 原本只有 `id`、`name`，现在补上 `classId` 与 `@ManyToOne(() => Classes, (classes) => classes.studentList)`，把所属班级信息挂到 `classes` 属性上。于是：

- 查学生 → 通过 `classId` 找到对应班级，`classes` 里带回班级名称、类型；
- 查班级 → 通过 `studentList` 带回该班所有学生，是一个数组（六年二班就有两个学生）。

### 在模块与控制器里注册实体

到用户主模块里把 `Student`、`Classes` 两个实体都引入到 TypeORM 的实体列表中，再在 Controller 里注入对应的两个 Repository，才能分别对两张表做查询。上一节一对一关系的示例代码可以先注释掉，换成本节的两个查询方法，注意新增注入项之间别漏了逗号。

### 用 `relations` 做关联查询

关联查询的核心就是查询时的 `relations` 选项：

- **查学生带班级**：`relations: ['classes']`，返回三个学生，每个学生对象里多出 `classes`，里面是他所属班级的信息。
- **查班级带学生**：`relations: ['studentList']`，返回两个班级，每个班级对象里多出 `studentList` 数组，装着该班学生。

这样一次请求就把主表和关联表的数据都取回来了，不必先查学生、再循环查班级、最后手工把数据拼进结果里。手写拼接不仅代码啰嗦，还容易引入数据冗余；用 ORM 的关系映射，结构清晰且只查一次。后面《实战演练—低代码平台项目数据库设计》里，页面、组件、问卷、用户数据之间大量都是一对多，靠的正是这套关联。

### 两个真实的坑

**坑一：`classId` 为空，关联结果为空。** 第一次请求查学生，三个学生都查出来了，但 `classes` 全是 `null`。原因不是代码写错，而是往数据表里手动插数据时只填了 `id`、`name`，忘了填 `classId`。外键没有值，ORM 自然不知道该关联到哪个班级。把每个学生的 `classId` 补上（例如张三、李四填二班，王五填一班）再查，`classes` 就有内容了。造测试数据时，外键字段和主字段一样不能漏。

**坑二：关系属性名写错。** 查班级时把 `studentList` 少写了一个字母，接口直接报错。这类错误和实体里定义的属性名强绑定，`relations` 里写的名字必须与实体上挂关系的属性完全一致，改实体名时尤其要回来同步检查。

## 小结

- 一对多由 `@OneToMany`（一的一侧）与 `@ManyToOne`（多的一侧）成对定义，回调里要指定对方用于回指的属性。
- 班级实体改名 `Classes` 避开命名冲突；用 `studentList` 数组存学生，学生实体用 `classes` 存所属班级，靠 `classId` 关联。
- 两个实体都要注册进模块，Controller 注入两个 Repository 分别查询。
- 查询用 `relations: ['classes']` / `relations: ['studentList']` 一次带出关联数据，避免多次查表与手工拼接带来的冗余。
- 外键 `classId` 不填则关联结果为空；`relations` 的属性名必须与实体定义完全一致，拼错会直接报错。
