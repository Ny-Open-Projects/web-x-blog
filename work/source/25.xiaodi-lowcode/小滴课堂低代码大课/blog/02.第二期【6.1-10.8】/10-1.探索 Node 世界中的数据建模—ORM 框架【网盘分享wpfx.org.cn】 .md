## 正文
### 什么是 ORM
ORM 即 Object Relational Mapping（对象关系映射）。它的本质是**把数据库里的数据映射成编程语言中的对象**，让我们用操作对象的方式去增删改查，而不必频繁手写原生 SQL。

```
原生 SQL 操作  ──►  ORM 框架（如 TypeORM）  ──►  以对象方式操作数据
```

### ORM 的核心优势
- **高度抽象**：以面向对象的方式处理数据库，开发者专注业务逻辑而非 SQL 细节。
- **减少出错**：底层 SQL 由框架生成，避免手写拼写与拼接错误，提升可维护性。
- **关系管理**：自动处理一对一、一对多、多对多等表关系，还能自动同步表结构。
- **原生兜底**：需要复杂查询时仍可直接写原生 SQL。

### Node 主流 ORM 对比
| 框架 | 特点 | 注意点 |
| --- | --- | --- |
| TypeORM | 支持 Active Record 与 Data Mapper，与 TypeScript 高度集成，装饰器语法贴近 Nest，社区活跃（GitHub 约 32.5k star） | 上手门槛略高 |
| Prisma | 类型安全查询、迁移工具完善，较新（约 34k star） | 缺失多库联合查询，支持的数据库较少（如 Oracle、SQL Server） |
| Sequelize | 基于 Promise，历史久、数据库支持广、事务强大 | 配置繁琐，回调风格易嵌套过深（约 28.6k star） |

### 为什么低代码平台选 TypeORM
本课后端使用 Nest + TypeScript 编写，而 TypeORM 是与 TypeScript 高度集成的数据建模框架，与 Nest 共享相似的语法和设计理念：
- 更好的类型安全与代码提示，开发阶段即可捕获错误；
- 支持 MySQL、PostgreSQL、SQLite 等多种数据库，也能直接写原生 SQL；
- 提供强大的迁移工具与灵活查询语法，比 Sequelize 更灵活轻便。

## 小结
- ORM = 对象关系映射，把数据库数据映射为程序对象。
- 它带来抽象层、少写 SQL、自动关系管理与表同步。
- 主流方案有 TypeORM、Prisma、Sequelize，各有取舍。
- 因 Nest + TypeScript 技术栈，本项目采用 TypeORM。
