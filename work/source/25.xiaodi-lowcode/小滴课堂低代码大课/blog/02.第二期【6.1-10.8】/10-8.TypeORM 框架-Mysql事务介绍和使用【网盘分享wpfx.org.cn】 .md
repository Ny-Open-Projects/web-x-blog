# TypeORM 框架：MySQL 事务介绍和使用

> **导语**：多条写操作必须"同生共死"，这是事务存在的理由。本文用转账红包的故事讲清事务的原子性，再给出 TypeORM 新版基于 DataSource 与 QueryRunner 的标准事务流程：connect、startTransaction、commit、rollback、release 一步不落。读完你能判断哪些场景必须上事务，也能避开已弃用的 getConnection 老 API。

## 正文

### 什么是事务

先给定义：当有多个对数据库操作的 SQL 语句时，要么全部成功，要么其中一条失败就整体回滚。这就是事务的原子性。

用一个通俗例子更好理解：老王想追冰冰，给她发了 200 元生日红包。这个事件包含两步数据库操作——先从老王钱包余额扣 200，再给冰冰钱包余额加 200。两步有严格先后：扣款成功，加款才允许发生。

如果扣款因故失败，加款却成功了，会怎样？老王余额没变，冰冰凭空多了 200，相当于"零成本"发了红包，账目彻底对不上。要避免这种中间状态，就必须把两步绑进同一个事务：任何一步抛错，已执行的操作一并回滚，数据库回到事务开始前的状态。

### TypeORM 新版事务流程

有了概念，看代码。这里要特别注意版本：中文官网里常见的 getConnection() 属于已被弃用的旧 API，新版的写法要去英文官网看，核心是 DataSource + QueryRunner。

DataSource 由 NestJS 容器注入（构造函数里声明即可，无需自己 new）：

```ts
@Injectable()
export class StudentService {
  constructor(private readonly dataSource: DataSource) {}
}
```

标准事务分五步，缺一不可：

```ts
async runInTransaction() {
  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();          // 建立真实数据库连接
  await queryRunner.startTransaction(); // 开启事务

  try {
    // 操作一：新增一条"老王"学生记录（演示中同时指定班级等信息）
    await queryRunner.manager.save(Student, { name: '老王', /* 班级等字段 */ });
    // 操作二：把名字为老王的记录改为老六
    await queryRunner.manager.update(Student, { name: '老王' }, { name: '老六' });

    await queryRunner.commitTransaction(); // 全部成功才提交
  } catch (err) {
    await queryRunner.rollbackTransaction(); // 任一步失败，整体回滚
    throw err;
  } finally {
    await queryRunner.release();             // 无论成败都释放实例
  }
}
```

（流程与实体、字段对应视频演示；配套工程见 `代码（已8期）/代码（已8期）/10-8/`。）

几个要点值得拆开说：

- createQueryRunner() 创建实例，connect() 才真正连上库，startTransaction() 标记事务开始。
- 所有数据库操作必须走 queryRunner.manager，不能混用普通 repository，否则那些操作不在事务管辖范围内。
- commitTransaction() 只在 try 末尾调用；一旦进入 catch，用 rollbackTransaction() 撤销。
- release() 放在 finally，成功失败都会执行，避免连接泄漏。

### 跑一遍验证

演示前 student 表里是三条数据：张三、李四、王五。调用接口后返回为空（方法没有 return 任何数据，需要的话直接 return 即可），刷新数据库可以看到：新增的老王记录已写入，且名字被改成了老六——两个操作作为一个整体生效。调试接口用的仍是 Apifox，与前面几集一致。

## 小结

- 事务保证多条 SQL 要么全成功、要么一条失败就整体回滚；转账红包是理解原子性的经典例子。
- 新版 TypeORM 用 DataSource.createQueryRunner()，不再用已弃用的 getConnection()；中文官网旧写法要避开。
- 完整流程：createQueryRunner → connect → startTransaction → try 内多操作 → commitTransaction / catch 内 rollbackTransaction → finally release。
- 事务内的操作必须走 queryRunner.manager，混用普通 repository 会脱离事务管辖。
- 配套依赖为 NestJS 10 + TypeORM 0.3.17 + mysql2 3.6.3，版本决定 API 形态。
