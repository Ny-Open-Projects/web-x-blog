# TypeORM 框架—一对一关系表关联和查询

> **导语**：一个学生对应一张桌子，是解释「一对一」最直观的例子。这一集用 student 与 desk 两张表，讲清 TypeORM 里如何用 `@OneToOne` + `@JoinColumn` 建立关系、如何在实体里指定关联数据存放到哪个属性，以及查询时怎样用一个 `relations` 就把学生信息顺带带出来。看完你能把任意两张一对一的表接起来。

## 前置知识

- 已会用 TypeORM 定义 Entity、开启自动同步，并做过增删改查，可回顾《TypeORM 框架—配置实体和自动同步数据库》《TypeORM 框架—实现数据库增+查操作》《TypeORM 框架—实现数据库改+删操作》。
- 会在 NestJS 的 Module 里注册实体、在 Service 里注入 Repository。
- 了解数据库外键与表关系的直觉即可，不需要先懂 SQL JOIN 细节。

## 正文

### 例子与想要的数据结构

准备两张表（在 Navicat 里能看到）：

- `student`：`id`、`name`，数据如张三（1）、李四（2）、王五（3）；
- `desk`：`id`、`color`（红、蓝、绿），以及一个 `studentId` 外键，记录这张桌子归哪个学生用。红桌 → 学生 3（王五），蓝桌 → 学生 1（张三），绿桌 → 学生 2（李四）。

目标是：**查 desk 表时，除了桌子本身的信息，还要把对应学生的详细信息一并带出来**，并放在一个叫 `studentDetail` 的属性里：

```json
[
  { "id": 1, "color": "red",   "studentDetail": { "id": 3, "name": "王五" } },
  { "id": 2, "color": "blue",  "studentDetail": { "id": 1, "name": "张三" } },
  { "id": 3, "color": "green", "studentDetail": { "id": 2, "name": "李四" } }
]
```

也就是说，一次查询就能拿到「桌子 + 它对应的学生」，不用自己查两遍再拼。

### 定义两个 Entity

先建 `Student` 实体（只有 `id`、`name`），再建 `Desk` 实体（`id`、`color`、`studentId`，以及关系属性）。TypeORM 的关键是装饰器的组合：

```ts
import { Entity, Column, PrimaryGeneratedColumn, OneToOne, JoinColumn } from 'typeorm';
import { Student } from './student.entity';

@Entity()
export class Desk {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  color: string;

  @Column()
  studentId: number;

  @OneToOne(() => Student)
  @JoinColumn({ name: 'studentId' })
  studentDetail: Student;
}
```

拆开看三步：

1. `@OneToOne(() => Student)`：声明「Desk 与 Student 是一对一」，参数是个回调函数，把要关联的实体传进去；
2. `@JoinColumn({ name: 'studentId' })`：声明**通过哪个字段建立关系**——这里就是 desk 表里的 `studentId`。对应到数据库，就是在桌子里多存一个学生 id，红桌存 3，就指向王五；
3. `studentDetail: Student`：声明**查出来的学生信息放到哪个属性上**。想要的属性名由你定，本集用 `studentDetail`。

（实体字段与文件命名以 `代码（已8期）/10-6` 下源码为准。）

### 同步建表与补数据

实体建好后重新初始化/启动项目，TypeORM 的自动同步会在 Navicat 里把 `desk`、`student` 两张表建出来。但要注意：**表结构自动建，`studentId` 这类关联值不会自动填**，需要手动把颜色、学生 id、学生姓名这些数据补进去，否则关联查询出来是空的。同时记得把 Module、Controller 里原本 `user` 相关的注入与路径改成 `desk`，让接口查的是桌子这张表。

后端依赖可对照 `代码（已8期）/10-6/package.json`：`@nestjs/typeorm`、`typeorm`、`mysql2` 一套齐全，`nest-cli.json` 里也开着 `deleteOutDir`。

### 查询：一个 relations 就够

真正的查询代码反而最简单——和普通的 `find` 几乎一样，只是在参数里多传一个 `relations` 对象：

```ts
async findAll() {
  return this.deskRepository.find({
    relations: { studentDetail: true },
  });
}
```

`relations` 里写的是**实体上声明的那个关系属性名**（`studentDetail`），不是数据库列名 `studentId`，这一点最容易搞混。设为 `true` 后，TypeORM 就会把关联的学生对象查出来挂到每条桌子的 `studentDetail` 上。

用接口调试工具 GET 请求一次，就能看到三条桌子数据，每条既有 `color`，也带上了完整的 `studentDetail`。相比自己查两次再手工拼装，这套声明式写法省事得多。

### 复盘：三处配置各管什么

整节课其实只回答了三个问题：

- 跟哪张表建立一对一？→ `@OneToOne(() => Student)`
- 靠哪个字段关联？→ `@JoinColumn({ name: 'studentId' })`
- 查出来的数据放哪？→ 实体上的 `studentDetail` 属性 + 查询时的 `relations: { studentDetail: true }`

## 小结

- 例子是 student / desk 一对一，desk 用 `studentId` 记录归属的学生。
- `@OneToOne` 声明关系，`@JoinColumn({ name: 'studentId' })` 指定关联字段。
- 关联数据存放到实体自定义的属性（此处 `studentDetail`）上。
- 查询用 `find({ relations: { studentDetail: true } })`，相比手工联表大幅简化。
- 自动同步只建表结构，关联值需要手动补数据；`relations` 写属性名而非列名。
