# 编辑器工具栏《上》：用 IntersectionObserver 控制显隐与定位

> **导语**：选中画布里的某个组件时，右侧会浮出一个工具栏（组件名、删除、上移、下移）。但当用户滚动画布、把选中组件滑出可视区域时，工具栏若还悬在原地就很奇怪。本文讲第一部分的工具栏功能：用浏览器原生的 `IntersectionObserver` 判断选中组件的可见比例来控制显隐，再用 `getBoundingClientRect` 算出工具栏该贴在哪个坐标。读完后你能复现这套"跟随组件、随可见性显隐"的定位逻辑。

## 前置知识

- 已完成组件拖拽排序与键盘操作，建议先阅读《低代码项目平台编辑模块—页面组件拖拽排序功能开发》与《低代码项目平台编辑模块—页面组件键盘操作功能开发》。
- 了解 MobX 的 `observer` 包裹、计算属性与 store 中"当前选中组件"的维护方式。
- 了解 `classnames` 与 TailwindCSS 的动态样式写法。

## 正文

### 认识 IntersectionObserver

`IntersectionObserver` 是浏览器原生 API，无需引入任何库。按 MDN 的定义，它提供了一种**异步观察目标元素与其祖先元素或顶级文档视口交叉状态**的方法，那个祖先元素或视口被称为「根（root）」。

抽象地看，画个图就清楚：一个大的父级 `div` 里排着若干个子 `div`，当容器高度不够时，靠后的子 `div` 会被遮住。`IntersectionObserver` 的作用，就是持续判断某个目标子元素（比如最后一个）与这个父容器之间"覆盖了多少、露出了多少"，并在交叉状态变化时触发回调。

在本项目里，目标元素就是**当前选中的组件**，根是中间画布那个大容器。需求是：选中组件在容器内可见比例足够高时显示工具栏，被滚动遮挡到不足阈值时隐藏工具栏。

### 阈值 0.9 与显隐状态

使用方式是 `new IntersectionObserver(callback, options)`，其中 `options.threshold` 定义可见性阈值，本例设为 `0.9`：

- 选中组件露出比例达到或超过 0.9，回调里把 `localHidden` 置为可显示；
- 露出比例低于 0.9（也就是被遮挡超过约 0.1），把 `localHidden` 置为隐藏。

回调的 `entries` 里能拿到被观察元素的交叉信息。监听用 `observe(target)`，不再需要时用 `disconnect()` 停止监听。

父组件 `EditCanvas` 里还有一个由 `showToolBar` 控制的 `hidden`，它和子组件内部的 `localHidden` 是两条独立的显隐来源：`hidden` 留给下一节的滚动逻辑（滚动时隐藏、停止滚动时显示），`localHidden` 专管"组件是否可见"。两者共同决定工具栏的 `className`——用 `classnames` 拼出动态样式，`hidden` 为 `true` 时 TailwindCSS 直接把整个工具栏 `div` 隐藏。

子组件因为要响应 store 变化，需要用 MobX 的 `observer` 包裹，这样当前选中组件一变，工具栏就会重新计算。

### 有没有选中组件：计算属性兜底

工具栏显示的前提是"确实选中了组件"。`getCurrentComponentConfig.get` 是定义在 `useStoreComponents` 里的 `computed` 计算属性：先看 store 里有没有 `currentComponentConfig`（选中的组件 ID），有则拿这个 ID 去所有组件属性数组里找出对应的那份配置。没选中任何组件时直接不渲染工具栏，避免空态下出现一个没有归属的浮层。

### 工具栏的结构

工具栏外层是一个 `div`，内容包含四部分：组件名称、删除按钮、向上移动按钮、向下移动按钮，鼠标悬浮时还有 hover 效果。样式上用 `absolute` 绝对定位，再通过内联 `style` 设置 `left` 与 `top`——接下来重点就是这两个值怎么算。

### 用 getBoundingClientRect 定位

第一步要拿到选中组件的 DOM 元素。`resizeComponent` 里通过 `document.querySelectorAll` 取出所有组件 DOM，遍历时读每个元素上的 `data-id`（这是组件包裹层 `ComponentWrapper` 绑定的组件 ID），与 store 里 `currentComponentConfig` 的 ID 比对，一致的就是目标 DOM。

拿到 DOM 后调用浏览器 API `getBoundingClientRect()`，返回一个 `DOMRect`，包含 `width`、`height` 以及 `top / bottom / left / right / x / y`。理解坐标是关键：

- 除宽高外，`top / bottom / left / right` 都是**相对于视口左上角零点**的距离；
- `right` 是组件最右边到零点的距离，不是到视口右边缘的距离；
- `x` 等于 `left`，`y` 等于 `top`。

于是工具栏坐标可以直接推出来：

```ts
// 示意：由选中组件的 DOMRect 计算工具栏位置
const rect = targetEl.getBoundingClientRect();
const TOOLBAR_HEIGHT = 28;
const left = rect.right;                 // 贴在组件右边缘
const top = rect.bottom - TOOLBAR_HEIGHT; // 底部对齐，减去工具栏自身高度
```

`left` 取组件的 `right`，让工具栏落在组件右侧临界点；`top` 用 `bottom` 减去工具栏高度（约 28px），让它贴在组件底部。相比用 `top` 再加一堆偏移，这个算法最简洁。

### 组件名称怎么来

工具栏上显示的"视频组件""轮播组件"，来自 `componentList` 配置数组——每项含 `type`、`name`、`icon`。用 `useMemo` 遍历该数组，把选中组件的 `type` 与配置项比对，一致就取它的 `name`；取不到则回退显示"组件名称"。由于依赖 store 里当前选中组件，切换选中项时名称与位置都会重新计算：点视频，工具栏叫"视频组件"并贴在视频旁；点轮播图，它就移到轮播图旁并改名。

## 小结

- `IntersectionObserver` 异步观察目标元素与根容器的交叉状态，`threshold: 0.9` 决定可见比例阈值。
- 显隐由两条来源共同控制：父组件 `showToolBar`（滚动逻辑，下节讲）与子组件 `localHidden`（组件可见性）。
- 没选中组件时不渲染工具栏；选中组件配置由 `computed` 计算属性从 store 取出。
- 通过 `data-id` 匹配选中组件 DOM，再用 `getBoundingClientRect()` 拿到 `DOMRect` 坐标。
- 工具栏 `left = rect.right`、`top = rect.bottom - 工具栏高度`，用绝对定位贴合组件。
- 组件名由 `componentList` 按 `type` 匹配得到，随选中项变化重新计算。
