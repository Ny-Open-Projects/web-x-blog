# 低代码项目发布页面—后端接口低代码组件获取

> **导语**：发布页面的第一个后端接口是「获取发布页面组件」。它与编辑平台里的获取组件接口逻辑几乎一致，但最大的区别是——发布页面不需要登录。本文讲解如何复用服务层、通过页面 ID 查找并组装组件数据，以及联调中 `user` 为空导致报错的处理。

- 已掌握编辑平台获取页面组件的服务层逻辑，见《后端接口开发—低代码项目编辑模块页面组件获取接口》。
- 已了解 TypeORM 查询，见《TypeORM 框架—实现数据库增+查操作》。

## 正文

### 发布页接口与编辑平台接口的区别

编辑平台获取组件走 `GET /local/releaseWithUser`，需要用户登录（通过 token 解析出用户 ID 再查）。而发布页面面向的是「不需要登录的第三方访客」，因此新接口不鉴权，而是让前端直接传一个页面 ID（如 `pageId=3`）来查找。

两者调用的是同一个服务层方法，参数 `id` 与 `user` 都是可选的——可以只传 `id`，也可以只传 `user`。

### 服务层查找逻辑

服务层方法内部：

1. 先查该用户/页面是否发布过页面（先前已开发的逻辑）：若 `id` 为空则按 `user.id` 查，若 `user.id` 为空则按页面 `id` 查；
2. 未发布过则直接终止返回；
3. 已发布则定义 `components` 数组，取出页面排序好的组件 ID 数组；
4. 遍历每个组件 ID，查询组件表，把每个组件 `push` 进 `components`；
5. 返回 `components`、`componentIds`（排序数组），以及剔除 `components` 后的页面级字段（`title`、`description`、`tdk`、用户 ID、页面 ID）。

### 联调踩坑：user 为空导致报错

在 Apifox 中用 `GET /local/release?` 传 `query` 参数 `id=3` 调用时，最初返回 500，报错 `Cannot read id`（指向 `user.id`）。原因是发布页接口没有传 `user`，`user` 为 `undefined`，访问 `user.id` 直接抛错。

修复方式是给 `user?.id` 加一个可选链兜底，保证未传 `user` 时也不会报错。重新请求后成功返回：每个组件含 `id`、`type`、`options`、所属 `pageId`、`accountId`，输入型组件（如输入框）`options` 里带 `title`（如「请输入姓名」），选择型组件（如单选/多选）则带选项列表。

## 小结

1. 发布页获取组件接口不鉴权，前端传页面 `id` 即可，复用编辑平台同一服务层。
2. 服务层优先按页面 ID 查「是否发布过」，再查组件表拼装 `components` 与 `componentIds`。
3. 返回数据含 `title`/`description`/`tdk` 等页面级字段，供发布页回填全局属性。
4. 联调注意 `user` 可能为空，务必用可选链 `user?.id` 兜底。
