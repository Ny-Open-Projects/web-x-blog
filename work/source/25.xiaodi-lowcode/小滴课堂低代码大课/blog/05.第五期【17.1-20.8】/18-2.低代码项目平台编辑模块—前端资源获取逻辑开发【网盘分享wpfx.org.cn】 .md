## 正文

### 公共组件与三层拆分

资源选择能力被抽成一个公共组件 `UploadEditorChoiceInput`（定义在 `utils/components` 并汇总导出）。图片、列表、卡片、轮播图、video 这些组件都要引它，只是当前先接了图片和列表两个，其余待补。

整套 UI 拆成三层，职责很清晰：

| 组件 | 职责 |
| --- | --- |
| `UploadEditorChoiceInput` | 最外层：一个按钮，点击打开资源弹窗 |
| `UploadComponent` | 弹窗本体：打开时拉资源列表，循环渲染每一项 |
| `LowResource` | 最里层：单个资源卡片（图片、名称、悬浮态、删除、点击选中） |

`handleChoice` 定义在外层，传给 `UploadComponent` 时改名 `onChoice`，再继续下传到 `LowResource`，最终绑在每张图片的点击方法上。这种「逐层透传回调」是低代码编辑器里很典型的组织方式。

### handleChoice：单个与列表两种场景

点中某个已上传资源后，弹窗关闭、图片映射到当前位置，本质是**改 store 里的值**。下面是整理后的逻辑示意，store 方法的具体命名以工程源码为准：

```ts
if (listOption !== undefined) {
  // 列表/轮播等多图场景：按 keyName 找到数组，展开运算追加或替换
  // keyName：图片 image、视频 video，未指定时默认 items
  updateListComponent({ keyName: listOption.keyName ?? 'items', value: src });
} else {
  // 单个图片：直接按 propName 更新当前组件
  updateCurrentComponent({ [propName]: src });
}
```

- **没有 `listOption`**：说明组件只挂一张图（如图片组件），直接 `updateCurrentComponent`，把 `propName`（这里是 URL）传进去即可。这个 store hooks 会通过解构修改当前组件的属性。
- **有 `listOption`**：说明是列表、轮播这类多项场景。要判断选中项数组里有没有 `item` 属性，没有就先新增；更新时传 `keyName`（图片 `image`、视频 `video`，没给就默认 `items`），用展开运算把新值加入再替换。数组形式的 store 更新走的是「多维取值」的路径，和之前非数组形式的更新方法不一样，不能混用。

### 弹窗打开即拉资源：useEffect + visible

`UploadComponent` 里维护一份 state 存所有已上传资源，弹窗打开时默认请求一次：

```ts
useEffect(() => {
  if (visible) {
    fetchResources();   // 获取资源接口，上一集已讲
  }
}, [visible]);
```

拿到资源后循环遍历渲染 `LowResource`，每项传入 `onDelete`（删除后重新获取资源）、id、类型、名称、`src`、`key` 和 `onClick`。另外还有 `iconClassName` 动态样式、`tabItem` 区分图片还是视频资源。

`LowResource` 里用一个 `useState` 的 `hover` 控制显隐：鼠标移入显示图片名称与「选择此图片」文本，移出隐藏。图片本身设置了地址（直接展示图片，或取视频第一帧作封面）、宽高样式，加载失败时用一张 **base64 兜底图**顶上，避免破图。

### 顺带修的两处基础问题

**一、统一响应格式**。服务层在包装响应数据时加了一层判断：如果返回的 `data` 里带有 `msg`（不为 undefined），就整理成 `{ code, message, data }` 的一维对象返回。不做这一步，结果会变成 `data` 里再套一层 `data`，前端取值要连剥两层，既啰嗦又容易错。统一之后，前端调需要鉴权的 API 时拿到的结构才是对的。

**二、token 要加 Bearer 前缀**。有权限的接口要求请求头里的 token 带 `Bearer ` 前缀才能被正确解析。登录时把 `useStore` 里 auth hooks 存的 token 用模板字符串拼一下：

```ts
const authorization = `Bearer ${token}`;
```

之前直接在浏览器里改 localStorage 时 token 是裸值，会解析失败；补上前缀后才通。这两处都不属于「资源获取」本身，却是联调能不能跑起来的前提，值得单独记一笔。

前端工程用 `~/*` 指向 `src/*`，依赖可对照 `代码（已8期）/18-2/lowcode/packages/client/package.json`：`mobx` / `mobx-react-lite` 管状态、`antd` 管 UI、`ahooks` 管请求、`react-quill` 是后面富文本组件要用的。

## 小结

- 资源选择抽成公共组件 `UploadEditorChoiceInput`，拆成外层按钮 / `UploadComponent` 弹窗 / `LowResource` 单卡三层。
- `handleChoice` 按 `listOption` 是否存在区分「单个图片」与「列表多项」两种 store 更新方式。
- 列表场景用 `keyName`（image / video / items）定位数组，数组更新走多维取值，不能复用单个的更新方法。
- 弹窗打开靠 `useEffect` 监听 `visible` 拉资源；`LowResource` 用 `hover` 控制悬浮信息、base64 图兜底。
- 服务层统一 `{ code, message, data }` 响应格式；鉴权请求头 token 要拼 `Bearer ` 前缀。
