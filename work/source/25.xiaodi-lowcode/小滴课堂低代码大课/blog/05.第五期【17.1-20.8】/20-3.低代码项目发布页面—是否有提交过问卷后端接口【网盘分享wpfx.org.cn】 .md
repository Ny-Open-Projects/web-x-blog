# 低代码项目发布页面—是否有提交过问卷后端接口

> **导语**：同一台设备/同一个 IP 不应重复提交问卷。本文讲解「是否提交过问卷」后端接口的开发：如何根据「IP + 设备」加密出的 key 值，去 `component_data` 表查找记录，并把结果转成 `true/false` 返回给前端以决定是否整页置灰。

## 前置知识

- 已了解发布页需求与 `component_data` 表设计，见《低代码项目发布页面—需求分析》。
- 已开发获取发布页面组件接口，见《低代码项目发布页面—后端接口低代码组件获取》。
- 已掌握 TypeORM 的 `findOne` 查询，见《TypeORM 框架—实现数据库增+查操作》。

## 正文

### 接口定义

在 `LocalController` 中新增路径 `isQuestionDataPost`，使用 `GET` 请求。方法接收多个参数：

- 前端传来的 `configId`（即页面/配置 ID）；
- 从请求中取出的用户 `ip` 与 `device`（设备信息）。

### key 值的生成

后端把 `ip` 与 `device` 两个字符串拼接后加密，得到一个 `key` 值。这个 `key` 正是写入 `component_data` 表时用来标识「某设备某次访问」的唯一值，也是后面判断重复提交的依据。

### 服务层查找逻辑

服务层方法接收 `key` 与 `pageId`，去 `component_data` 表中按这两个条件查找：

- 查到记录 → 说明该设备已提交过问卷，返回 `true`；
- 查不到 → 返回 `false`。

返回前用 `!!` 双感叹号把结果强制转成布尔值，便于前端直接判断。前端据此决定是否把发布页整体置灰（`opacity` 降低、`pointer-events: none`、`user-select: none`）并提示「问卷已提交，感谢参与」。

### 联调验证

用 Apifox 调用 `GET /local/isQuestionDataPost`，传 `id=3`：首次访问（表中无记录）返回 `data: false`；若该页面已有提交记录，则返回 `true`，前端随即禁用整页交互。

## 小结

1. 接口 `isQuestionDataPost` 为 `GET`，接收配置 ID、IP、设备信息。
2. 用「IP + 设备」拼接加密生成 `key`，作为去重依据。
3. 服务层按 `key` + `pageId` 查 `component_data`，用 `!!` 返回布尔值。
4. 前端依据 `true/false` 决定是否置灰发布页并提示。
