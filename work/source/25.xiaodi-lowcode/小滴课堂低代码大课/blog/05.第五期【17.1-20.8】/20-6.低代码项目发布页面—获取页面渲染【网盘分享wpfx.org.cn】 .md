# 低代码项目发布页面—获取页面渲染

> **导语**：Next.js 发布项目初始化后，下一步是请求后端「获取发布页面组件」接口，把数据渲染成真实页面。本文讲解动态路由取参、`fetch` 请求、用 `useImmer` 管理本地组件数据，以及如何复用 `share` 中的公共组件完成渲染。

## 前置知识

- 已初始化 `release` 子项目，见《低代码项目发布页面—前端 Nextjs 项目初始化》。
- 已开发获取发布页面组件接口，见《低代码项目发布页面—后端接口低代码组件获取》。
- 已了解 `getComponentByType` 公共方法，见《前端页面开发—低代码项目编辑模块整体布局》。

## 正文

### 动态路由与页面取参

在 `app` 同级新建 `components` 目录，并在 `app` 下建立 `[id]` 路由目录，把 `page.tsx` 放进去。这样访问 `/release/3` 时，`params.id` 就能拿到页面 ID（`3`）。这正是 Next.js 的动态路由传参方式。

### 用 fetch 请求后端接口

在 `page.tsx` 中定义 `getData(id)` 方法，用原生 `fetch` 请求后端：

```ts
const res = await fetch('http://127.0.0.1:3006/api/local/release?id=' + id, {
  cache: 'no-cache',
});
const json = await res.json();
return json!.data;
```

注意 `cache: 'no-cache'` 关闭缓存。返回的 `response` 是一个 fetch 响应对象（含请求头、响应头等），需判断 `res.ok` 确认成功，再用 `.json()` 取出真实数据。用 `!` 断言数据存在，最后把 `data` 与当前页面 `id` 一起传给渲染子组件 `ComponentRender`。

### 组件渲染子组件 ComponentRender

`ComponentRender` 用 `useImmer` 管理一份本地拷贝 `localData`（从父组件 `data` 克隆而来），核心是 `generateComponents` 与 `generateComponent` 两个方法：

1. `localData.components.map(...)` 遍历每个组件，组装成 `{ id, type, props }`；
2. 调 `generateComponent(item, onUpdate)`：`onUpdate` 是回调，用于输入型组件（输入框、文本域、单选、多选）内容变化时回写 `localData`；
3. 通过 `getComponentByType(type)`（定义于 `share` 公共包）拿到对应组件；
4. 用扩展运算符把 `props` 摊开到组件标签上，并加 `key`；
5. 判断类型是否属于输入型（`input`、`textarea`、`radio`、`checkbox`），若是则绑定 `onChange` → `onUpdate`。

### 输入型组件的回写逻辑

`onChange` 触发 `onUpdate`，内部用 `useImmer` 的 `setLocalData` 直接修改深层对象：先 `draft.components.find(...)` 定位组件，再借助 `getQuestionComponentValueFeed` 映射出属性名（input/textarea → `text`，radio → `defaultRadio`，checkbox → `defaultCheckbox`），把新 `value` 写入。这样视图输入与数据保持同步，无需手动深拷贝。

打印 `localData` 可看到：每个组件含 ID、类型（`list`/`text`/`card`/`input`/`textarea`/`radio` 等）与 `options`。渲染时 input/textarea 取 `props.text`，radio/checkbox 取 `props.defaultRadio` / `props.defaultCheckbox`，与 `share` 中公共组件的定义一一对应。

## 小结

1. 用 `[id]` 动态路由拿到页面 ID，通过 `params.id` 取参。
2. `fetch` 请求 `GET /api/local/release?id=`，`cache:'no-cache'`，再 `.json()` 取 `data`。
3. `ComponentRender` 用 `useImmer` 克隆数据，遍历组件调 `getComponentByType` 渲染。
4. 输入型组件通过 `onChange`→`onUpdate` 回写 `localData`，属性名由 `getQuestionComponentValueFeed` 映射。
