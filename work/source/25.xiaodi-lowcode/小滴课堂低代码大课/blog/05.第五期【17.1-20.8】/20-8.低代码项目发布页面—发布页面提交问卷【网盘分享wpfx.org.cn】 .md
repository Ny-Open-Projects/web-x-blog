# 低代码项目发布页面—发布页面提交问卷

> **导语**：发布页的最后一步交互是「提交问卷」。本文讲解提交按钮的显隐条件、提交前的完整性校验、把问卷数据整理成后端要求的 `{id, value}` 数组，以及调用提交接口后整页置灰的完整流程。

## 前置知识

- 已掌握发布页渲染与是否提交判断，见《低代码项目发布页面—获取页面渲染》《低代码项目发布页面—前端项目检查是否提交问卷》。
- 已开发后端提交问卷接口，见《低代码项目发布页面—后端接口提交问卷信息》。
- 已了解 `getQuestionComponentValueFeed` 属性名映射，见《低代码项目发布页面—获取页面渲染》。

## 正文

### 提交按钮的显隐

在 `ComponentRender` 的 JSX 中，根据 `data.components` 是否存在问卷类型组件来决定是否展示「提交问卷」按钮：用 `some` 遍历，若组件类型包含 `input`、`textarea`、`radio`、`checkbox` 中任意一个，才渲染按钮；否则不显示。

按钮点击触发 `useRequest` 的 `run`，并带 `loading` 状态（请求未完成时按钮显示 loading）。

### 提交前完整性校验

点击后先做校验：遍历 `localData.components`，对每个组件取出其类型，经 `getQuestionComponentValueFeed` 映射出属性名（`text` / `defaultRadio` / `defaultCheckbox`）。校验规则：

- 单选框、多选框有默认选中值，本身一定有值，排除它们；
- 只校验输入型 `input` 与 `textarea`：其映射到 `options.text`，若为空则判定「问卷信息未填写完整」；
- `isNotComplete` 为 `true` 时提示「请填写完整的问卷信息」，阻止提交。

### 组装并提交数据

校验通过后，再次筛选问卷类型组件，遍历把每条数据整理成后端要求的结构：`{ id, value }`。`value` 由组件 `options` 经类型映射取出（input/textarea → `text`，radio → `defaultRadio`，checkbox → `defaultCheckbox`）。

随后用 `fetch` 发 `POST` 请求（注意路径中的下划线），设置 `headers` 为 JSON，body 传 `pageId` 与 `props`：

```ts
fetch('http://127.0.0.1:3006/api/local/questionDataPost', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ pageId: data.id, props }),
});
```

### 提交成功后置灰

接口返回成功后：

- 若无数据返回则警告；
- 若有数据则提示成功，并把 `isPost` 设为 `true`，使整页置灰、不可再点击（与「是否已提交」的置灰样式一致）。

联调示例：姓名填「老王」、建议填「一」、单选选第二项，点击提交 → 成功提示「感谢您的参与」，Navicat 中 `component_data` 表出现 `configId=3` 的记录，`props` 含老王、建议、单选选项 ID 等。

## 小结

1. 「提交问卷」按钮仅当页面含问卷类型组件（`input/textarea/radio/checkbox`）时显示。
2. 提交前校验：仅校验 `input`、`textarea` 是否填写，`radio`/`checkbox` 有默认值直接排除。
3. 提交数据整理为 `{ id, value }` 数组，`value` 经类型映射取出。
4. `POST /api/local/questionDataPost`，成功后 `isPost=true` 整页置灰防重复提交。
