# 低代码项目发布页面—前端 Nextjs 项目初始化

> **导语**：发布页面由独立的 Next.js 服务端渲染项目承载。本文讲解如何在 pnpm-workspace 中初始化名为 `release` 的子项目、接入公共包 `share`、配置 Ant Design（App Router 模式），并跑通第一个测试按钮。

## 前置知识

- 已掌握 pnpm-workspace 多包管理，见《深度解析 pnpm-workspace 的灵动工作空间管理》《项目管理 pnpm-workspace 初始化项目》。
- 已了解 Next.js 基础与 App Router，见《Nextjs 应用路由器和导航跳转》。
- 已了解 Ant Design 在 React 中的使用，见《低代码平台项目前端 React 项目配置—Ant-design+TailwindCSS》。

## 正文

### 在 workspace 中创建 release 子项目

发布页面是第四个子项目（与 `client`、`server`、`share` 并列）。进入 `lowcode` 根目录下的 `packages`，执行 Next.js 创建命令，项目命名为 `release`，选择 TypeScript、不使用 ESLint 严格规则。

创建后做几处整理：

- 它默认用 npm 下载依赖并生成 `package-lock.json`，删掉该 lock 文件（workspace 用 pnpm 统一管理）；
- 在 `package.json` 中把项目名改为 `@lowcode/release`，与 `client` 等项目命名风格一致；
- 执行 `pnpm --filter release` 关联公共包 `@lowcode/share`，以便复用公共组件与类型配置。

> 配套依赖见 `代码（已8期）/20-5/lowcode/packages/release/package.json` 与 `代码（已8期）/20-5/lowcode/packages/client/package.json`（二者依赖结构一致）。

### 接入 Ant Design（App Router 模式）

Next.js 服务端渲染下使用 Ant Design 与纯客户端不同。按官方文档（App Router 分支）操作：

1. 安装官方提供的 Ant Design 适配插件；
2. 在 `layout` 文件中引入并在最外层用 `AntdRegistry` 组件包裹 `children`，这样服务端渲染时样式才能正确注入；
3. 子组件中即可直接使用 antd 组件与图标。

### 清理默认样式与跑通测试按钮

Next.js 脚手架自带 `page.css`、示例首页样式与默认 `metadata`（title）。这些在发布页里大多冗余，可直接删除，仅保留必要的布局。项目中已默认集成 TailwindCSS，无需二次配置。

在首页引入一个 antd 的 `Button`，设置 `type="primary"`，启动项目（默认端口 3001，视频中演示为 3002）。访问页面即可看到渲染出的主色按钮，证明 antd 已可用。为避免内容区高度塌陷出现多余留白，可在首页容器上加 Tailwind 的 `min-h-screen`，使其占满视口高度。

## 小结

1. 在 pnpm-workspace 中新增 `release` 子项目，命名 `@lowcode/release`，删除 npm 的 lock 文件。
2. 关联公共包 `@lowcode/share`，复用组件与类型。
3. 服务端渲染用 Ant Design 需装适配插件，并在 `layout` 用 `AntdRegistry` 包裹。
4. 清理脚手架默认样式，用 Tailwind `min-h-screen` 撑满高度，跑通主色按钮验证环境。
