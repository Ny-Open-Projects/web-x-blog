# 低代码项目平台编辑模块：页面组件拖拽排序功能开发

> **导语**：画布里把组件上下拖动换位置，涉及传感器、碰撞检测、虚拟拖拽层与 store 数组重排一整套机制。本文基于 dnd-kit 拆解 DndContext / SortableContext / useSortable 的分工、PointerSensor 与 closestCenter 的配置，以及 onDragEnd 如何把 oldIndex / newIndex 交给 arrayMove 更新 store。读完你能复刻一个样式不跳变、状态可回写的拖拽排序画布。

## 前置知识

建议先读《前端页面开发—低代码项目编辑模块整体布局》与《前端页面开发—低代码项目编辑模块左侧组件列表样式》，熟悉画布组件列表与 store 里维护的组件配置数组；再了解 React 的自定义 hook 与 MobX 的 action。

## 正文

### 为什么用 dnd-kit

实现效果是：画布里选中多个组件后，可把某个组件向上/向下移动一位，或一路拖到顶部。自己手写拖拽逻辑相当复杂，所以这里借用第三方库 dnd-kit，按其官方文档组合三层 API：最外层的 DndContext、负责排序的 SortableContext、以及每个拖拽项的 useSortable。

配套依赖版本如下（来自 `代码（已8期）/代码（已8期）/18-4/lowcode/packages/client/package.json`）：

```json
{
  "dependencies": {
    "@dnd-kit/core": "^6.1.0",
    "@dnd-kit/sortable": "^8.0.0",
    "@dnd-kit/utilities": "^3.2.2"
  }
}
```

### 容器层：SortableContainer

自定义 SortableContainer 按官方提示包了两层：DndContext 在最外层，内部用 SortableContext 包裹子元素，并把**组件 ID 数组**（store 中维护）传给它，排序策略设为垂直列表 verticalListSortingStrategy。

另外两个配置决定了拖拽手感：

- **传感器**：用 useSensors / useSensor 创建鼠标传感器，设置激活约束为移动 2 像素才触发一次监听（官方示例常用 10 像素，这里调小更灵敏）。每移动 2 像素就重新判断一次是否该换位置。
- **碰撞检测**：采用 closestCenter 中心点算法。拖动中的元素是虚拟的，算法比较它与上下目标元素中心点的距离：离哪个中心更近，就判定要占据哪个位置。此外还有矩形边缘等其他策略，按需在官方文档里选。

### 拖拽项：SortableItem 与样式保真

画布 EditCanvas 原先只是循环渲染组件配置，现在给每个子组件外面套一层自定义的 SortableItem。SortableItem 内部调用 useSortable，解构出 attributes、listeners、setNodeRef（DOM 节点引用）、transform、transition，设置到外层 div 上，再把原本的组件内容作为 children 插入。

这样拖动时那个"悬浮的虚拟元素"才能保留原组件的宽高等样式与事件，看起来和静态渲染一模一样。有个容易踩的坑：transform 在 Y 轴上的部分要用正则 replace 替换为空，否则过渡过程中拖拽元素会突然变得和目标元素一样高/宽（演示里一瞬间变大或变矮）。加上这层处理后，拖动全程样式稳定。

### 拖拽开始：选中态与边框

onDragStart 触发时做两件事：把当前拖拽的组件设置为 store 中默认选中的组件，并把 isDraggable 置为 true。这个变量传给公共布局组件，用来把当前组件边框加粗、变成蓝色，与其他组件形成视觉区分。平时单选组件也有蓝色边框，拖拽态复用同一套样式逻辑。

### 拖拽结束：索引交换与 store 更新

onDragEnd 里从事件取出 active（被拖动元素）和 over（目标元素）。若 over 为 null，说明还没到需要换位置的地方，直接 return 回到原位。否则根据 items 数组找到两者的索引，得到 oldIndex / newIndex，交给 moveComponent。

moveComponent 定义在 useStoreComponents 里：用 MobX 的 action 包裹回调，调用 @dnd-kit/sortable 提供的 arrayMove，按两个索引返回一个排好序的新数组，再写回 store 中的组件配置数组。结束后把 isDraggable 置回 false。

一句话概括：**所有拖拽动作，最终都被转换成数组里两个索引的位置交换**，视图只是这份数组的投影。

```ts
const moveComponent = (oldIndex: number, newIndex: number) => {
  runInAction(() => {
    store.components = arrayMove(store.components, oldIndex, newIndex);
  });
};
```

（结构对应视频演示；配套工程见 `代码（已8期）/代码（已8期）/18-4/lowcode/`。）

循环渲染时每个 SortableItem 都要把对应组件 ID 传进去，并以 ID 作为唯一 key——拖拽库靠这个 ID 识别是谁在移动。

### 收尾与后续预告

这一集把 dnd-kit 的父容器与子项各做了一层二次封装，画布本身不用关心拖拽细节。视频末尾还预告了下一集的键盘操作：上下键移动组件、Delete 删除、Command+Z 撤销/前进、Command+C / Command+V 复制粘贴，并要兼顾 Windows 与 macOS 的按键差异（Meta / Control、Backspace / Delete）。本篇先把拖拽这一条线讲完。

## 小结

- 拖拽排序基于 dnd-kit：DndContext（外层）+ SortableContext（排序，传组件 ID 数组，垂直列表策略）+ useSortable（每项）。
- useSensors 设 2 像素激活约束提升灵敏度；closestCenter 按中心点距离判定放置位置。
- SortableItem 解构 attributes / listeners / setNodeRef / transform / transition 挂到外层 div；transform 的 Y 轴部分需 replace 为空，避免拖动态样式突变。
- onDragStart 设置选中组件并置 isDraggable=true 显示蓝色边框；onDragEnd 取 active / over，over 为 null 直接 return。
- moveComponent 用 MobX action + arrayMove(oldIndex, newIndex) 重排 store 数组；拖拽本质是数组索引交换。
