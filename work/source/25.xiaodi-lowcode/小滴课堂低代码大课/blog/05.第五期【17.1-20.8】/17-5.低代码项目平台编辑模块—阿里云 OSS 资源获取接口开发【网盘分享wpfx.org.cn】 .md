# 低代码项目平台编辑模块—阿里云 OSS 资源获取接口开发

> **导语**：资源上传、删除之后，还差“把已上传的资源列出来”。编辑器里打开上传弹窗时，需要回显用户之前传过的图片/视频供其直接选用。本节课用一条 `GET` 接口，按当前登录用户 + 资源类型从 `resource` 表查出全部记录并返回。

## 前置知识

阅读本文前，建议先掌握《低代码项目平台编辑模块—阿里云 OSS 资源删除接口开发》。获取接口是 resource 后端三件套（上传、删除、获取）的最后一环，同样复用登录鉴权与 `ResourceEntity` 表。

## 正文

### 为什么要获取接口

进入上传资源的弹窗时，编辑器需要先把“你之前上传过哪些资源”查出来展示；当用户在某个图片/视频组件里想复用旧资源，直接点选即可，不必重复上传。由于上传时已经把每条资源的 URL 存进了数据库，获取接口本质上就是一次按用户维度 + 类型维度的查询。

### 控制层：GET 获取接口

在 `resource.controller.ts` 中再新增一个 `getResource` 方法，用 `GET` 装饰器：

- 不强制传参也能调，但支持通过 Query 传 `type` 来筛选；
- 必须登录，解密 token 拿到 `userId`；
- `type` 取值为 `image`（图片）或 `video`（视频），对应上传时传入的 `UploadType`。

```ts
@Get('resource')
@UseGuards(AuthGuard)
async getResource(
  @Query() query: { type: UploadType },
  @User() user: { id: number },
) {
  return this.resourceService.getResource(query.type, user.id);
}
```

请求参数类型定义在 `share` 项目里，这里只用到一个字符串字段 `type`。

### 服务层：按用户 + 类型查询

`ResourceService.getResource(type, accountId)` 接收两个参数：资源类型 `type` 与用户 `accountId`（number）。逻辑非常直接——按这两个条件 `find` 出全部记录返回：

```ts
async getResource(type: UploadType, accountId: number) {
  return this.resourceRepo.find({
    where: { type, userId: accountId },
  });
}
```

返回的是该用户、该类型下的所有资源行，包含 `url`、`accountId`、`type`、`name` 等字段，前端据此渲染已上传列表。

### Apifox 联调实测

在 Apifox 里复制出一个“资源获取接口”用例：

- 请求方式：`GET`；
- Query 参数：`type`，默认值 `image`（字符串），表示要取图片类资源；
- Headers：同样需要登录态（`Authorization: Bearer <token>`）。

发送后，接口按当前登录用户（例如 `accountId = 8`）去 `resource` 表查 `userId = 8` 且 `type = image` 的记录，把对应的 URL、accountId、type、name 等一并返回。课程里该用户只有一条图片记录，就返回了那一条。

## 小结

- 获取接口是 resource 后端三件套的收尾，用于弹窗回显已上传资源；
- 控制层为 `GET`，需登录鉴权，支持 `type`（image/video）Query 参数筛选；
- 服务层按 `userId + type` 两个条件 `find` 全量返回，字段含 url、type、name 等；
- Apifox 实测：传 `type=image` + token，即可取回当前用户对应类型的资源列表。
