# 低代码项目平台编辑模块—页面头部动态标题开发

> **导语**：编辑器下半部分（组件拖拽、联动、属性设置、资源管理、工具栏）都完成后，第 19 章转向页面头部。第一集做左侧的动态标题：把标题值放进 store，点击编辑按钮切成输入框，改完点勾选确认保存。本文讲清 `useStorePage` 与 `setPageTitle` 的响应式链路、`isEditState` 双态切换，以及用扩展运算符把 `className` / `onClick` 抽成公共 props 的小技巧。

## 正文

### 需求与整体思路

头部左侧原来只是一句占位文本，现在要变成可修改的动态标题。交互分两步：默认是展示态，显示标题文字和一个编辑按钮；点击编辑按钮进入编辑态，变成输入框；改完内容点击勾选图标确认，回到展示态并显示新标题。

关键在于标题值不能写死在组件里，而要维护在 store 中：页面读的是 store 里的值，改的也是 store 里的值，这样才能和编辑器其它部分共享同一份页面信息（后续草稿、预览、发布都依赖它）。

### `EditHeader` 抽离 `Left` 子组件

在 `EditHeader` 里把左侧区域抽成独立的 `Left` 组件，头部相关组件统一放在 `edit/` 下新建的 head 目录里集中管理。这样头部将来加预览、草稿、发布、数据统计入口时，每个功能都是独立子组件，不会把 `EditHeader` 撑成一个大文件。

`EditHeader` 调用之前定义好的 `useStorePage` hook——它专门用来处理页面标题设置、页面信息更新。store 的 `page` 模块里有一个 `title` 变量，通过 action `setPageTitle` 动态修改它，就能响应式地更新到页面上。把 `store.page.title` 作为 props 传给 `Left`，子组件只负责渲染与交互，不自己持有标题状态。

### 用 `isEditState` 切换两种 JSX

`Left` 组件里用一个 `isEditState` 变量（初始 `false`）判断渲染哪一段 JSX：

- **展示态（`false`）**：用 `h1` 渲染 `props.title`，右侧放一个编辑按钮（图标从 `@ant-design/icons` 引入）。点击按钮时把 `isEditState` 取反为 `true`，切到编辑态。
- **编辑态（`true`）**：用 Ant Design 的 `Space` 包裹一个 `Input`，`value` 绑定 `props.title`；输入变化触发 `handleEdit`，从 `event.target.value` 取到输入框内容，传给修改 store 的方法，实时响应式更新标题；再放一个 `CheckOutlined` 确认按钮，点击后把状态取反切回展示态。

输入过程中 store 已经在同步更新，所以点确认只是收起输入框，不需要再单独「提交」一次数据。

### 把样式与点击方法抽成公共 props

有个很实用的写法：标题的 `className`（一串 Tailwind CSS 类）和 `onClick` 方法，在展示态的一段 JSX 和编辑态的另一段里几乎都要用。与其各写一遍，不如把它们定义成一个对象，再用扩展运算符展开到元素上：

```tsx
<div {...publicProps} />
```

这一行等价于分别写 `className={...}` 与 `onClick={...}` 两行。两段 JSX 复用同一组属性，改样式或改点击逻辑时只动一处，既省心又不会两边不一致。

## 小结

- 头部动态标题的值维护在 store 的 `page.title`，通过 `useStorePage` hook 与 `setPageTitle` action 响应式更新。
- `EditHeader` 把左侧抽成 `Left` 子组件，头部组件统一放 `edit/head` 目录。
- `isEditState` 控制展示态（`h1` + 编辑按钮）与编辑态（`Space` + `Input` + `CheckOutlined`）切换。
- 编辑态 `value` 绑定 `props.title`，`onChange` 用 `event.target.value` 实时写回 store，确认按钮只负责收起输入框。
- 用扩展运算符把公共的 `className` / `onClick` 抽成对象展开，避免两段 JSX 重复写。
