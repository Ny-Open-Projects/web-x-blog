# JMeter 压测接口：发布页面是否提交过问卷接口

> **导语**：压测系列推进到「发布页面是否提交过问卷」这个 GET 接口。本文讲一次标准的单接口压测怎么在 JMeter 里落地：禁用其它线程组、复制并改请求路径、配置 `pageId` 查询参数、清空历史结果后执行，最后从察看结果树确认响应、从聚合报告读平均耗时与 TPS。下一节会拿另一个接口做优化前后的性能对比。

## 前置知识

- 建议先了解《Jmeter5.X查看测试结果结果树+聚合报告》，熟悉察看结果树与聚合报告两块面板。
- 建议先了解《Http取样器复用和Http请求头管理实战》，本文沿用其中的取样器配置方式。

## 正文

### 只跑这一个接口

JMeter 计划里往往同时存在多个线程组，直接执行会把其它接口一起跑起来，结果互相干扰。所以第一步是把前面几组**全部禁用**，只保留本次要压测的「发布页面是否提交过问卷」这一组。做法是复制出一份线程组/取样器，再把请求路径改成该接口对应的地址。

### 请求配置

这个接口是 **GET**，需要带查询参数：传一个 `pageId`（配置 ID），用来查询当前发布页面是否已经提交过问卷。在取样器的参数面板里增加这一项，演示中取值为 `4`，即针对 ID 为 4 的发布页面做查询。

| 项 | 值 |
| --- | --- |
| 请求方法 | GET |
| 参数位置 | query / 参数面板 |
| 参数名 | `pageId`（配置 ID） |
| 示例值 | `4` |

配置完成后，先**清空全部历史结果**再执行，避免旧数据混进这次的聚合报告。

### 看结果：响应与聚合报告

执行完成后，在察看结果树里能看到接口返回「提交过问卷」，说明请求本身是通的、参数也传对了。

再看聚合报告，本次的关键指标：

- 平均响应时间约 **18ms**；
- 吞吐量约 **55/s**，也就是对应的 TPS。

对这样一个只做「是否提交过」判断的查询接口来说，路径短、逻辑轻，数值也在预期范围内。真正要留意的不是单次的绝对值，而是把它作为**基线**：后面优化别的接口时，才有可比较的参照。

### 配套资料

本节不改动工程代码，压测脚本的备份可作为对照：`安装包（已8期）/安装包（已8期）/apache-jmeter-5.6.3/apache-jmeter-5.6.3/backups/` 下有一组 `发布页面获取低代码组件接口-000013.jmx` 至 `发布页面获取低代码组件接口-000022.jmx` 的脚本，需要复用线程组与取样器配置时可以直接参考。

## 小结

- 单接口压测前先禁用其它线程组，复制取样器并改请求路径，避免多组一起执行。
- 「是否提交过问卷」是 GET 请求，通过 query 传 `pageId`；演示取值为 4。
- 执行前清空历史结果，保证聚合报告只统计本次请求。
- 察看结果树确认返回「提交过问卷」；聚合报告读到约 18ms 平均耗时、约 55/s 的 TPS。
- 这组数值作为基线，用于后续接口优化前后的对比。
