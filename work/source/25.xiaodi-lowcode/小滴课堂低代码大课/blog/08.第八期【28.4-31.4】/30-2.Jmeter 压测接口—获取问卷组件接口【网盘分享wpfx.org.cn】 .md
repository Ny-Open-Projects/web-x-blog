# JMeter 压测接口实战：获取问卷组件接口

> **导语**：后台数据统计模块需要登录后才能拉取问卷组件。本集我们复用上一集的登录脚本，改成"获取问卷组件接口"的压测，并补上 **Authorization: Bearer token** 鉴权头，跑通带权限的 GET 请求。

## 前置知识

本文建立在《Jmeter 压测接口—用户登录接口》之上，沿用其中的 HTTP 请求默认值、HTTP 信息头管理器与监听器配置。后端服务需已启动。

## 正文

### 这个接口有什么不同

"获取问卷组件接口"位于课程低代码平台的**后台数据统计**（React 管理端）中，用于拉取问卷类组件数据。它和登录接口的关键区别在于：

- 它是一个 **GET 请求，无需请求体**；
- **必须登录授权**——请求头要带登录后拿到的 `token`，否则无权限调用。

所以我们需要在登录接口脚本基础上，把取样器改成该接口，并额外加上鉴权头。

### 复用脚本 + 改造取样器

高效做法：直接**复制**上一集的"用户登录"线程组，粘贴为新的线程组，重命名为"低代码相关"，再改取样器：

1. 取样器名称改为"获取问卷组件接口"；
2. 对照 Postman 里低代码后台数据统计的问卷组件接口，把路径粘贴进来；
3. 因为是 GET 且无参，把消息体数据里的内容**清空**；
4. 查看结果树、聚合报告沿用不变。

### 加上 Bearer 鉴权头

由于该接口需要登录态，要在 HTTP 信息头管理器里**新增一项**：

| 名称 | 值 |
| --- | --- |
| Authorization | Bearer 你的token |

注意格式：`Bearer` 后跟一个**空格**，再接登录接口返回的 `token`。原来的 `Content-Type: application/json` 仍保留（信息头管理器可同时有多个条目）。

> 实践提示：压测时把登录接口返回的 token 复制过来填入即可。若做完整自动化，可结合"正则表达式提取器 / JSON 提取器"把登录响应里的 token 提取为变量，再由后续接口引用，避免手动拷贝。

### 跑通并看报告

确认后端服务已启动，清空结果树与聚合报告后点击开始。接口成功响应，返回了对应问卷组件内容。聚合报告显示：样本 1，平均 RT 约 51ms，异常 0%，吞吐量（TPS）约 19.6/s。

同样，这只是单次基线；要得到该带鉴权接口的最优 TPS，仍需按《Jmeter 压测接口—用户登录接口》讲的逐步加压法去测。脚本保存到本集目录 `30-2`。

## 小结

- 获取问卷组件接口是 **GET、需登录授权** 的后台数据统计接口，无请求体。
- 复用登录脚本最快：复制线程组 → 改路径 → 清空消息体 → 加鉴权头。
- 鉴权头格式为 `Authorization: Bearer <token>`（Bearer 后有一个空格）。
- 单次基线：平均 51ms、异常 0%、TPS 约 19.6/s；最优性能仍需逐步加压测定。
- 脚本存到 `30-2` 目录。
