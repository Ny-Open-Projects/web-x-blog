# HTTP 取样器复用与 HTTP 请求头管理实战

> **导语**：当压测接口一多，每个取样器都重复填协议、IP、端口既麻烦又难维护。本文讲两个提效利器——**HTTP 请求默认值**做公共参数复用，**HTTP 信息头管理器**统一设置请求头，并以课程登录接口为例演示 POST + JSON 的正确姿势。

## 前置知识

本文依赖《特殊的线程组setUP-tearDown和调度器实战》的线程组与取样器基础，并需要本地后端服务（端口 3000）已启动。

## 正文

### 为什么需要"复用"

JMeter 里每个 HTTP 取样器都要填协议、服务器 IP、端口号。如果只压一个接口无所谓，但当线程组里挂了十几个接口、甚至多个线程组时，逐个填写既繁琐又容易改漏。

前提条件：**这些相同参数必须一致**才能抽出来复用。比如课程本地所有接口都是 `http://127.0.0.1:3000`，就可以把这部分统一提取。

### HTTP 请求默认值（HTTP Request Defaults）

右键 **线程组 → 添加 → 配置元件 → HTTP 请求默认值**，在里面填好：

- 协议：`http`
- 服务器名称或 IP：`127.0.0.1`
- 端口号：`3000`

之后该线程组下的所有 HTTP 取样器**都不用再填这三项**，会自动继承默认值。原来的取样器（如"发布页面获取低代码组件接口"）可以直接删掉它自己填的协议/IP/端口，由默认值接管，请求依然成功返回数据。

如果把"HTTP 请求默认值"移到**测试计划**级别（即线程组的外层），那么它对**所有线程组**生效，而不只是当前这一个。

### 案例：新增登录接口并遇到请求头错误

新增一个线程组"用户相关"，在其下添加 HTTP 请求取样器，压测课程的**密码登录接口** `/api/user/password_login`：

- 方法：`POST`
- 路径：`/api/user/password_login`
- 消息体数据（Body）：JSON 形式的账号密码，例如：

```json
{
  "account": "你的账号",
  "password": "你的密码"
}
```

> 说明：GET 请求的参数在"参数"选项卡添加即可；POST 且带请求体时，要在"消息体数据"里填 JSON。

直接运行会**失败**，响应提示请求头有问题。原因在于：JMeter 默认的 `Content-Type` 是 `text/plain`，而我们的接口期望接收 `application/json`，导致后端解析不了请求体。

### HTTP 信息头管理器（HTTP Header Manager）

解决办法是添加 **HTTP 信息头管理器**：

1. 右键 **测试计划（或对应线程组）→ 添加 → 配置元件 → HTTP 信息头管理器**。
2. 点击"添加"，设置一行：

| 名称 | 值 |
| --- | --- |
| Content-Type | application/json |

放在测试计划级别，则所有线程组的请求都会带上这个请求头。

重新运行登录接口，结果树显示请求成功，响应体返回 `code = 0`、`message = 登录成功`，并带上了 `data` 里的 `token`。说明 `Content-Type: application/json` 生效后，后端正确解析了登录参数。

> 实践建议：把"HTTP 请求默认值"和"HTTP 信息头管理器"都放在测试计划级别，作为全局公共配置，下游所有线程组/取样器直接复用，是大型压测脚本的标准做法。配套示例可参考 `apache-jmeter-5.6.3/bin/templates/simple-http-request-test-plan.jmx` 模板。

## 小结

- 重复的公共参数（协议/IP/端口）用 **HTTP 请求默认值** 提取，避免逐个填写。
- 默认值放线程组级只对本组生效；放测试计划级对所有线程组生效。
- POST + JSON 必须设置 `Content-Type: application/json`，否则默认 `text/plain` 会导致后端解析失败。
- 用 **HTTP 信息头管理器** 统一管理请求头，推荐放测试计划级全局复用。
- 脚本记得保存到本集目录（如 `28-9`）以便复现。
