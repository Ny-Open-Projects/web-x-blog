# JMeter 压测接口实战：用户登录接口

> **导语**：前面学的都是通用能力，从本章起我们逐一压测课程低代码平台的真实业务接口。第一篇就拿最核心的"用户密码登录接口"开刀，串联 HTTP 请求默认值、信息头管理器、监听器等全套配置，并演示如何逐步加压找到最优 TPS。

## 前置知识

本文建立在《高并发业务下Jmeter集合点应用实战》之上，需要已掌握线程组、HTTP 请求默认值、HTTP 信息头管理器与聚合报告。本地后端服务（端口 3000）需已启动。

## 正文

### 从零搭建登录接口压测脚本

登录接口在 Postman 里调试时已知参数，照搬即可。完整搭建步骤：

1. 右键 **测试计划 → 添加 → 线程组**，本集先用"三个 1"（线程数 1、Ramp-Up 1 秒、循环 1 次）跑通。
2. 在**测试计划底部**添加 **配置元件 → HTTP 请求默认值**，填公共参数：协议 `http`、IP `127.0.0.1`、端口 `3000`。移到脚本顶部，全局复用。
3. 线程组下添加 **取样器 → HTTP 请求**，命名为"用户登录接口"，方法 `POST`，路径 `/api/user/password_login`，消息体数据填 JSON 形式的账号密码。
4. 因是 POST + JSON，需添加 **HTTP 信息头管理器**，设置 `Content-Type: application/json`（否则默认 `text/plain` 会导致后端解析失败）。同样放测试计划级全局复用。
5. 添加监听器 **查看结果树** 与 **聚合报告**。
6. 保存到本集目录 `30-1`（如 `用户登录接口.jmx`），方便复现。配套资料提供 `用户登录接口-000036.jmx` 等示例脚本。

### 跑通单次请求

选中取样器点击执行，查看结果树显示请求成功，响应体带回了登录 `token`，说明接口联调无误。聚合报告里样本数为 1，平均 RT 约 55ms，异常 0%，吞吐量约 18/s。

### 找最优 TPS：逐步加压

单次请求只证明"接口能跑"，不代表"扛得住压"。拿到最优 TPS 的方法是前面讲过的**逐步加压法**：

- 在线程组里逐步调大线程数（如 1 → 50 → 100 → 200 ……）；
- 每档跑一轮，观察聚合报告的吞吐量与异常%；
- 当**异常% 降为 0 且吞吐量达到最大**时，对应的线程数即为该接口在当前环境下的性能水位，此时的吞吐量就是最优 TPS。

> 提示：登录接口涉及写库/查库与 token 生成，压测时建议用测试账号，避免对真实用户数据造成干扰；高并发下若数据库或后端撑不住，会出现异常，应调小线程数重测。

## 小结

- 登录接口压测四件套：线程组 + HTTP 请求默认值（公共协议/IP/端口）+ HTTP 信息头管理器（application/json）+ 监听器。
- 路径 `POST /api/user/password_login`，请求体为 JSON 账号密码。
- 单次跑通不代表性能达标，需逐步加压用"零异常 + 最大吞吐"定位最优 TPS。
- 脚本存到 `30-1` 目录，配套 `用户登录接口-*.jmx` 可作参考。
