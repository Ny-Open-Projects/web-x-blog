## 关联锚点（本期比渡一项目强得多）

课程资料包里有一份**权威总纲** `全栈多端低代码平台项目大课.md`（229KB，31 章 / 190 集），
每集带「简介 + 配图 + 课件正文」。破译出三方同构：

```
视频 x-y 编号  ≡  总纲「第 x 章第 y 集」  ≡  代码包目录 <x-y>/
```

于是有了**零歧义的硬锚点**：

| 锚点 | 命中 | 说明 |
|---|---:|---|
| `lesson_no` | 115 | 课号目录精确匹配（视频 `x-y` ↔ 代码包 `x-y`），零歧义 |
| `pre_chapter` | 40 | 预先课（NestJS 基础，独立大纲）→ 代码演进链课号目录 |
| `code_feature` | 7 | 中文标题 → 英文源码文件名 技术词映射（`tools/zh_en_map.py`） |
| `orphan_code` | 1 | 孤儿代码目录（`13-4` 该课未录视频）→ 同章最相关课 `13-3` |
| `toolkit` | 41 | 课程工具包（jmeter / Navicat / jdk8）整包挂到用得上的课 |

### 关键破译：代码包是「累积快照」

代码包每个课号目录都存着「到该课时为止的完整项目」。实测演进链：

```
8-2 起步(3 文件) → 8-3 client(18) → 8-4 +server(44) → 8-5 +share(53)
→ 8-6(53) → 9-1 ORM(144) → 9-2 用户接口(225) → 9-3 拦截器(272)
→ 9-4 课程接口(286) → 10-2~10-8 前端联调 → … → 30-6
```

由此推出预先课（第 1~10 章）→ 代码课号目录的映射表（`zh_en_map.PRE_CHAPTER_MAP`），
并解释了「为什么预先课没有自己的 x-y 编号」。

## 三个必须做的精细处理

### 1. 孤儿图片归位（一张不漏）
img 目录 213 张，总纲只引用 150 张，其余 63 张是历史遗留截图。用三级策略归位
（`tools/map_orphan_images.py`）：
- md5 精确对齐内容重复（不同文件名同一张图）→ 14 张
- **感知哈希 dHash**（Pillow + numpy）找最相似已挂图 → 30 张
- **mtime 最近邻**（同批制作，7 天内）→ 18 张
- 剩余 `docker.svg` 按名称关键词挂到第 7 章 Docker 课

结果：**213/213 全部归位**。

### 2. 公共资料按主题挂，不是一股脑挂全部
用户明确要求「挂到相关的」。做法是**双向主题规则**——资料侧强特征 + 文章侧强特征
都必须命中，且文章侧只看**标题+子目录**（正文噪音大，压测课正文里也会出现「技术栈」）。

结果：
- 压测课 → 只有 jmeter 工具包（不再误挂数据库 sql）
- 简历课 → 只有简历模板
- 数据库课 → sql + mwb + 总纲 + Navicat
- 需求课 → 需求文档 + drawio + 总纲

### 3. 工具包 vs 教学资料分开
安装包 2643 个文件里 2620 个是 jmeter 软件本体（1474 个官方 API 文档 html + 540 张
内置截图 + 159 个 jar）。这些**不是教学资料但也不能丢** —— 整包挂到用得上的课，
在 graph 里用 `toolkit` 维度与内容型资料区分开。
