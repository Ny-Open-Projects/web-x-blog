## 三、技术准确性双人复核

涉及以下高敏感信息时，**以关联代码（materials）为准，不允许凭口播记忆**：

1. **接口名 / 路由**：对照 `graph.json` 中该篇的 `materials.data` 关联代码路径（如 `代码（已8期）/.../14-6/lowcode/packages/client/package.json`）；
2. **类名 / 装饰器**：如 `AliOssModule`、`@Global()`、`useSortable`、`arrayMove` 等，须能在关联工程中找到；
3. **版本号**：依赖版本以 `package.json` 片段为准（如 `antd ^5.11.2`、`@dnd-kit/core ^6.1.0`、`react-router-dom ^6.20.1`）；
4. **数字 / 配置项**：端口、地域（`oss-cn-guangzhou`）、Bucket 名等，以代码与配置为准。

**复核机制**：作者自校（跑六点终检）→ 第二人对照 `materials` 抽验关键接口/类名/版本 → 双方签字（或 PR review 记录）后方可并入主文档集。课程已建立"关联物料注入机制"（每篇博客带 `materials` 字段），**该机制必须延续**，不得退化成纯口播改写。

## 四、版本与密钥安全规范（生产红线）

课程在《低代码项目平台编辑模块—阿里云 OSS 资源上传配置》（17-1）中已用**占位符**填写密钥，并提示：

> `accessKeyId: '你的AccessKeyId'`、`accessKeySecret: '你的AccessKeySecret'`；secret 仅在阿里云控制台创建时展示一次，之后无法再查，只能重建。

《项目自动化部署上线—线上前端项目编辑平台功能确认》（27-7）同样触及线上密钥配置。**这是教学占位，绝不可直接用于生产。** 落地部署须遵守：

1. **禁止硬编码密钥**：`config.ts` / `.env` 中的 `accessKeySecret`、`数据库密码`、`JWT 私钥` 等一律通过**环境变量或密钥管理服务**（如云效密钥库、KMS、Vault）注入，不入库、不进镜像层。
2. **最小权限**：OSS AccessKey 仅授予所需 Bucket 的 `Put/Get/Delete`，不开 `*` 全量；数据库账号按需建库建表权限。
3. **安全评审**：任何密钥变更、域名绑定（如 27-6 Bucket 绑定域名）、公网暴露前，走安全评审。
4. **密钥轮换**：AccessKey 定期轮换，离职/交接即废。
5. **不要把课程占位符当真实配置**：`local-is`、`16web.net`、`oss-cn-guangzhou` 等均为讲师演示值，生产替换为自有资源。
