## 二、定位：它是谁、不是谁（明确边界）

这批内容来自一套**讲"如何自研一套低代码平台"的全链路代码级实战课**。因此它的定位必须清晰：

### ✅ 它适合做（研发侧资产）

- **自研低代码平台的技术底座**：从需求分析 → 系统架构 → 后端（NestJS）→ 前端（React/Next.js）→ 组件拖拽与配置 → 发布页 Schema 渲染 → OSS 资源 → 压测运维，全链路可复现。
- **研发团队 onboarding 教材**：新人跟着做一遍，即掌握一套现代全栈低代码平台的搭建链路。
- **内部技术踩坑 / 复盘库**：实战细节丰富，错误处理、联调踩坑、Docker/DevOps 配置详尽。

### ❌ 它不适合做（边界）

- **不用于对外平台选型决策**：缺少平台横向对比、能力矩阵、ROI 分析。
- **不用于售前 / 方案材料**：缺少业务价值抽象、方法论包装、客户视角叙事。
- **不面向公民开发者（业务侧）自助搭建**：课程面向研发，不讲解零代码边界与业务配置范式。

> 一句话：**这是「研发侧的自研实战资产」，不是「选型/售前/零代码」材料。**

## 三、低代码 vs 零代码 边界（必须区分）

| 维度 | 低代码（本资产所属） | 零代码 |
|------|----------------------|--------|
| 是否需要研发介入 | **需要**（写组件、接接口、改渲染器） | 不需要（纯配置） |
| 灵活度 | 高，可深度定制与集成 | 受限，受平台能力边界约束 |
| 适用人群 | 研发 / 全栈工程师 | 业务运营 / 产品经理 |
| 典型产物 | 本平台（拖拽编辑器 + 自研渲染器 + 后端） | 表单工厂、轻流、简道云类 |
| 何时选 | 业务差异化强、需深度集成、长期演进 | 标准化后台、快速交付、人力有限 |

若业务侧确有"公民开发者自助搭建"诉求，应**另起一套零代码材料**，并与本资产在边界上明确区分，避免读者混淆"配置即所得"与"研发介入才能扩展"两种范式。

## 五、如何使用这套资产

1. **新人 onboarding**：先看本总览 → 读原理综述（上/下）→ 按生命周期导航从「需求分析」顺着学到「压测运维」。
2. **查具体实现**：用门户检索关键词（如 `dnd-kit`、`TypeORM`、`OSS`、`Dockerfile`），直达对应博客。
3. **做技术决策**：参考原理综述（下）的「自研 vs 采购决策树」与工程实践手册的架构决策。
4. **内容续写 / 复用**：严守 `工程实践-03-内容治理规范.md` 的门禁与术语表，延续关联物料注入机制。
