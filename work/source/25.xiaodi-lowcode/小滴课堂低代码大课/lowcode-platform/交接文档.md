## 1. 与用户协作的铁律（先读这段，避免重蹈覆辙）

### 1.1 「讨论 ≠ 授权开工」

用户在连续多轮咨询/方案讨论里给出的参数（端口号、目录、形态选择、功能取舍等）**只是需求输入**，不代表让你动手。
**必须等用户明确说「开工 / 开始 / 部署 / 动手 / 继续执行 / 全部实现」才可写文件、建目录、改代码。**

> 历史教训（2026-09-28）：用户连续细化视频转文本方案并给出端口等参数，我误判为授权，建了目录并写了 4 个代码文件，被用户纠正「没让你开工」。

### 1.2 用户的风格偏好

- 指令极简（如「只部署不要运行」「继续执行」），不喜欢多余客套。
- **已完成的事不需要再展开**，直接给增量结论与证据。
- 交付物要有**可复现的验证证据**（构建退出码、测试通过数），不要只说「已完成」。

### 1.3 汇报口径

- 分阶段结论用**表格**（阶段 / 内容 / 验证）。
- 如实标注**未做 / 需用户决策 / 环境受限**的部分，不要含糊带过。
- 涉及外部依赖（密钥、镜像、账号）时，明确列出**需要用户提供什么**。

## 3. 核心设计约定（改代码前必读）

### 3.1 契约唯一真源
`PageSchema` / `WorkflowContract` 只在 `packages/shared` 定义。**任何端不得私自加字段**；破坏性变更必须走版本化（`schema.version`）。
新增组件类型：改 `ComponentType`（它有 `(string & {})` 兜底，允许扩展）+ 在 `render-page.ts` 加渲染分支 + 在 `PageBuilder.tsx` 的 `PALETTE` 登记。
新增工作流节点：改 `nodes/registry.ts` 的 `NODE_CONTRACTS` + `execs`，前端画布**自动出现**；前端结构化参数面板需在 `ParamEditor.tsx` 的 `PARAM_SCHEMAS` 登记字段。

### 3.2 工作流是平台内模块，不是独立系统
工作流与 page/component 同级，共用主库（仅 `wf_*` 表），随平台一体部署。
> 历史教训：初版曾把工作流画成「独立系统/平级外挂」，被用户明确批评「主次不分」，已修正为平台内 module。**不要再退回独立系统的设计。**

### 3.3 节点端口类型
`data` / `schema` / `trigger` 三类端口，连线时前端 `WorkflowCanvas` 会做类型校验，不匹配拒绝连线。

### 3.4 图 DSL
```json
{ "nodes": [{ "id": "n1", "type": "trigger.formSubmit", "params": {}, "position": {"x":0,"y":0} }],
  "edges": [{ "id": "e1", "from": "n1", "fromPort": "out", "to": "n2", "toPort": "in" }] }
```
⚠️ `edges` **必须带 `id`**（DTO 校验），`position` 可选。

### 3.5 副作用全部走 Provider
短信 / OSS / 表单存储都不直接调外部服务，统一走 `nodes/providers.ts` 的 Provider 接口：
- `SmsProvider`（当前 `ConsoleSmsProvider`）
- `OssProvider`（当前 `LocalOssProvider`）
- `FormProvider`（`MemoryFormStore` / **`DbFormStore` 真实落库 `wf_submission`**）

**接真实云厂商 = 在 `workflow.module.ts` 换 Provider 实现 + 填 env 密钥，节点代码零改动。**

### 3.6 密钥纪律
`LLM_API_KEY` / OSS 密钥**只从 env 读取**，绝不进前端、绝不进图 JSON、绝不进沙箱。

## 4. 环境与运行

### 4.1 安装
```bash
cd "F:/ai-done/小滴课堂低代码大课/lowcode-platform"
npm install --registry=https://registry.npmmirror.com/   # 大陆网络必须指定镜像源
```
- **必须用 npm 10.9.7**（`packageManager` 已锁定）。**不要用 pnpm**——本机缺 `@pnpm/exe.win32-x64` 原生二进制会卡死。
- `.npmrc` 已设 `node-linker=hoisted` + `package-import-method=copy`，避开 Windows 符号链接权限拒绝（os error 5）。
- npm workspaces 中 `workspace:*` 协议要写成 `*`。

### 4.2 基础设施
```bash
docker compose up -d mysql redis
# 或用本机已起的容器；server 本地跑时连 127.0.0.1，不要用 compose 里的服务名
```

### 4.3 构建
```bash
npm run build     # shared → server(nest build) → studio(vite build)，按依赖序
```

### 4.4 启动
```bash
# 后端
cd apps/server
DB_HOST=127.0.0.1 DB_PORT=3306 DB_USER=lowcode DB_PASSWORD=change_me DB_DATABASE=lowcode \
  node dist/main.js          # 默认 3000 端口，全局前缀 /api
# 前端
cd apps/studio && npx vite    # 5173 端口，/api 代理到 :3000
```
- `TypeORM synchronize: true` —— **仅开发期**；生产需改用迁移脚本（README 已标注）。
- CORS：设 `CORS_ORIGINS=域名1,域名2` 可锁域名；不设则开发期全放开。
- 前端**不发** `x-tenant-id` 头 → `TenantGuard` 不挂租户 → 查询不过滤（本地可用但无隔离）。生产由网关注入。

## 8. 本机环境坑位（Windows，踩过的别再踩）

### F 盘（exFAT）的写入特性 —— 改文件前必读

F 盘是外接 Samsung T5（exFAT），**不支持原地覆盖写入**：新建文件可写、改名可以、删除可以，但**直接覆盖已有文件会拒绝（Permission denied）**。

> 正确写法：先写到 `<file>.tmpnew` 临时文件 → `os.remove(原文件)` → `os.replace(tmp, 原文件)`。`sed -i` 在这个盘上也会失败。

> 另：**exFAT + 128KB 簇**（每小文件最少占 128KB）——**不要把 `node_modules`（数万小文件）放到 F 盘**，会挤掉数 GB 空间且极慢；依赖在 D 盘内置 NVMe 重装。


| 坑 | 现象 | 正解 |
|---|---|---|
| Docker Hub 不通 | `docker pull node:20-alpine` 10 分钟 0 字节；daocloud/1ms.run 镜像源极慢 | 用 `apps/server/Dockerfile.sandbox` 本地构建 `lowcode-node-sandbox:20`（npmmirror 下 node 二进制 → Dockerfile 内解压） |
| NTFS 存不住 exec 位 | `cp -r` 解出的 node 是 `-rw-r--r--` → 容器报 `executable file not found in $PATH` | **必须在 Dockerfile 里（Linux 内）解压**，别在 Windows 侧拼 rootfs |
| `docker export \| tar -x` / `docker import -` 走管道 | 二进制被 Git Bash 改写，import 失败 | 先 `tar -cf 落盘文件`，再 `docker import 文件` |
| Git Bash 路径转换 | `docker run ... /bin/sh` 被转成 Windows 路径 | 加 `MSYS_NO_PATHCONV=1` |
| pnpm | 缺原生二进制卡死 | 用 npm 10.9.7 + `--registry=https://registry.npmmirror.com/` |
| Windows 符号链接权限 | npm install 报 os error 5 | `.npmrc` 的 `node-linker=hoisted` + `package-import-method=copy`（已配好） |
| `ValidationPipe({whitelist:true})` | 无 class-validator 装饰器的 DTO 字段被剥掉 → INSERT 报 "doesn't have a default value"(500) | DTO 字段必须加 `@IsString()`/`@IsObject()` 等装饰器 |
| `--experimental-strip-types` | 不解析无扩展名导入（ERR_MODULE_NOT_FOUND） | 涉及相对导入的测试改用 **dist 产物** `require('../dist/...')` |
| `.cjs` 顶层 await | SyntaxError | 包一层 `async main()` |
| `docker.createContainer` 类型 | `await` 推断成交叉类型 `void & Promise<Container>` | `as any` + `as Docker.Container` 双重断言 |
| `User` 字段位置 | 报错「not exist in type HostConfig」 | `User` 在 createContainer **顶层**，不在 `HostConfig` 内 |

## 9. 接手后建议的下一步（按优先级）

1. **接真实云厂商**（唯一明确待办）：需用户提供阿里云/腾讯云 AccessKey + 短信签名模板。改动面极小——`workflow.module.ts` 换 Provider + `.env` 填密钥 + 补一个 Provider 单测。
2. **补 RBAC 第二层**：当前只有租户头，需要在 `TenantGuard` 之上加角色（owner/admin/editor/viewer）与操作级鉴权，否则多租户只是隔离数据、不是隔离权限。
3. **数据库迁移脚本**：把 `synchronize: true` 换成 TypeORM migration，为生产部署做准备。
4. **前端租户头与登录态**：studio 目前不发 `x-tenant-id`，接入真实登录后需统一注入。
5. **补组件资产市场 / 模板沉淀**：配合治理规范，沉淀业务表单模板降低公民开发者从零搭的成本。
