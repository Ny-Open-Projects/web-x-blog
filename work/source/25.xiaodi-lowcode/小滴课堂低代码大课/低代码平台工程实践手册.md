## 二、架构决策（引用《放长线钓大鱼—规划低代码平台的系统架构》6-2）

```
访问层      后台编辑端(含数据统计 ECharts)  +  发布页 H5
   │
Nginx 网关  反向代理 + 高并发负载均衡(多节点)
   │
后端服务    NestJS（编辑/发布/问卷/微信登录 等模块）
   │
存储层      MySQL(主业务)  +  Redis(缓存)  +  OSS(静态资源/CDN)
   │
基础设施    ECS  +  域名/DNS  +  CDN
   │
外部服务    云效 DevOps  +  云短信  +  微信登录  +  Jmeter  +  Docker
```

**决策要点**：
- 编辑端与发布页**共享同一后端服务层**，仅鉴权策略不同（编辑端需登录、发布页凭 `pageId` 免登录，见 20-2）；
- 静态资源走 OSS + CDN，减轻应用服务器带宽；
- 多节点部署时 Nginx 做负载均衡，Jmeter 压测结果反推带宽/内存配置（28-1、30-6 优化接口性能）。

## 三、关键代码模式（带课程锚点，可直接复用）

### 模式 1：Monorepo 分包与共享
- `client`（React 编辑器）、`server`（NestJS）、`share`（公共组件 + 类型）三包；
- `share` 以 `workspace:^` 被引用（14-6 的 `@lowcode/share`）；
- **原则**：只在本页用的组件放 `pages/editor/`，跨页复用的才放 `components/`（14-6）。

### 模式 2：NestJS 分层与装饰器
- Module / Controller / Service / DTO / 拦截器 / 管道 / 装饰器 分层清晰；
- **用户信息装饰器**（`@User()` 解析 token→user，11-1）全局复用；
- **验证码装饰器封装**（11-5 第三方短信验证码发送装饰器）把横切逻辑收口；
- 响应拦截器（Nest 的响应拦截器）、异常拦截器统一出参。

### 模式 3：TypeORM 实体与关系
- 实体定义 + 自动同步数据库（10-3）；
- 一对一（10-6）、一对多（10-7）关系表关联与查询；
- Mysql 事务（10-8）保证发布/提交一致性。

### 模式 4：Schema 驱动渲染（平台内核，见原理综述·上）
- 编辑端把组件（含 `type`+`props`）存为数组 Schema；
- 发布接口按 `pageId` 捞出返回（20-2）；
- 前端 `getComponentByType(type)` 映射组件 + 扩展运算符摊开 `props`（20-6）；
- 输入型组件 `onChange→onUpdate` 回写 `localData`（useImmer）。

### 模式 5：拖拽编辑器（dnd-kit + MobX）
- `DndContext`(外层) + `SortableContext`(传组件 ID 数组,垂直策略) + `useSortable`(每项)；
- `useSensors` 设 2px 激活约束、`closestCenter` 碰撞检测（18-4）；
- **避坑**：`transform` 的 Y 轴部分需 `replace` 清空，否则拖动态样式突变；
- 拖拽本质 = `arrayMove(oldIndex, newIndex)` 重排 store 数组。

### 模式 6：OSS 上传（动态模块 + multer）
- `AliOssModule` 用 `@Global()` 动态模块注入 `ALI_OSS` 实例（17-1）；
- `multer` 处理 `multipart/form-data`；
- `uploadToAliOss`：文件名 latin1→utf8、拼 `upload-files/原名-时间戳.扩展名`、put、删本地临时、正则把默认域名替换为自有 CNAME。

### 模式 7：容器化与 DevOps
- 每个运行时一个 Dockerfile：后端 Nest、后端 Nginx、Next 服务端、前端 Nginx（23-3~23-6）；
- `docker-compose` 编排多容器（24-1/24-2）；
- 云效流水线关联代码源 → 构建 → 推送镜像 → 服务器运行（25-1、26-x）。

### 模式 8：性能压测闭环
- Jmeter 线程组 + 取样器 + 聚合报告 + 响应断言（28-x、29-x）；
- 对登录、获取问卷组件、提交问卷等接口压测（30-x）；
- 据聚合报告优化（30-6 优化获取低代码组件接口性能）。

## 四、Do / Don't（从踩坑篇提炼）

### Do ✅
- **样式先行、逻辑重点讲**：先把布局骨架立起来，复杂逻辑再逐行讲（14-6）；
- **先把数据链路想清再画 UI**：发布接口 + 页面组件获取接口就绪后再搭编辑器（14-6、20-2）；
- **接口梳理先于联调**：编辑模块后端接口先梳理（14-1）再开发；
- **密钥用占位符 + 环境变量**：绝不硬编码（17-1、27-7）；
- **拖拽 transform 的 Y 轴清空**：避免样式跳变（18-4）；
- **`user?.id` 可选链兜底**：发布页接口 `user` 可能为空（20-2）；
- **目录按"页面专属 vs 公共复用"划分**：避免组件到处乱放（14-6）。

### Don't ❌
- 不要硬编码 `accessKeySecret` / 数据库密码；
- 不要把页面专属组件塞进公共 `components/`；
- 不要给发布页误加鉴权（它本就凭 `pageId` 免登录，20-2）；
- 不要在拖拽时漏置 `isDraggable`，否则选中态/边框错乱（18-4）；
- 不要忽略数组越界：`over` 为 `null` 时直接 return（18-4）；
- 不要把"配置即所得"误传给业务方（那是零代码范畴，见原理综述·下）。

## 六、商用化补齐清单（从"能跑"到"可商用"）

课程是**优秀的研发侧实战样本**，但距生产级低代码平台还差以下一层（呼应原理综述）：

| 维度 | 现状（课程） | 商用化补齐 |
|------|--------------|------------|
| Schema 协议 | 组件 `type`+`props` 直驱 | 固化**版本化 Schema 协议** + 组件市场 |
| 逻辑能力 | props 内简单 `defaultXxx` | 引入 **DSL / 可视化逻辑编排**（条件显隐、跨页联动） |
| 流程引擎 | 仅草稿/发布/提交状态 | 接入 **BPMN / 状态机**，与表单引擎解耦 |
| 权限 | 编辑端登录 + 发布页免登录 | 统一 **RBAC**（角色×资源×操作）+ Guard |
| 组件库 | 课程内置若干组件 | 可插拔**组件市场** + 第三方组件接入规范 |
| 运维 | Docker + 云效 + Jmeter | **监控告警、日志、灰度发布、回滚** |
| 多租户 | 单租户演示 | 租户隔离（数据/资源/配置） |

> 把这七项补齐，本资产即可从"一套课程博客"升级为"团队自研低代码平台的**技术底座 + 实施手册**"。
