# 阶段七面试专题 · 技术博客改写规范（批次宪法 v1.0）

> 每个批次必须完整阅读本规范后再动手。原料：`_clean/NNN-标题.md`（已机械清洗：
> 广告水印/品牌名/AI 元叙述/口语框架词/弯引号/破折号/系统性 ASR 错识已归零）。
> 产物：`blog_interview/NNN-标题.md`（与原料同文件名，写在 blog_interview 根目录）。
> 原稿权威源：`_src/NNN-标题.md`（代码块守恒校验用，**永不修改**）。

## 1. 质量目标（用户原话）

细节、精度、深度、广度、通俗易懂、由浅入深、按面试题要求。
读起来像一位有经验的工程师给朋友讲面试题：概念讲透、原理挖到底、例子说活、
面试答案能给模板。不是字幕整理，不是教科书摘录。

## 2. 文章结构模板

```
# <标题：文件名去掉 NNN- 前缀，保留主题，如「JVM 内存结构：一段代码的执行流程》>

<2-4 句开场：这道面试题考什么、为什么考、怎么答才出彩。>

## 先给结论
<3-6 条可背的回答要点，面试直接可用。>

## 是什么
<概念定义，配合原料中的比喻/例子。>

## 为什么这样设计
<设计动机、要解决的问题。原料不讲就略过，不编。>

## 深入细节
<原理/流程/源码级细节。声音线的讲解顺序为骨架，画面线的 PPT 结构、
图表要点、代码细节全部并入。代码块逐字保留。>

## 面试怎么答
<分点作答模板 + 常见追问与应答。原料里有追问就整理，没有不编。>

## 常见误区
<原料提到的易错点；没有则整节省略。>
```

短素材（不足 500 字有效内容）可合并「是什么/为什么」章节，但结论区和面试作答区不可省。

## 3. 铁律（违反任何一条即返工）

1. **代码块逐字保留**：原料代码块原样落入成稿，一个字符不改（含缩进、注释、反例）。
   成稿代码块数量 **≥** 原料。围栏数必须偶数。
2. **不新增事实**：原料没有的技术点不许编；不许把没说过的源码细节"补全"。
3. **不删技术点**：声音线讲过的每个技术点、画面线 PPT 上的每个要点都要在成稿中有对应。
4. **术语/API/类名/数字/端口/结论一字不差**：`-Xmx`、`-XX:+PrintGCDetails`、
   `ReentrantLock`、`8192` 这类原样保留，大小写不改。
5. **不新增 mermaid/表格/图**：原料没有就不画。
6. **引号统一「」**；破折号原则上不用（确需停顿用逗号/冒号）；整句加粗不取
   （只加粗术语和标签）；每篇恰好 1 个 H1。
7. **零容忍残留**：口播框架词（感谢大家/同学们/咱们/对不对/慕课网…）、
   AI 元叙述（"好的，这是根据…"/"结构化分析"/"综上所述"…）、品牌名
   （黑马/heima/itcast/itheima/leadnews）、广告水印（海量资源/ubkz/wpfx/666java/网盘分享/
   【…com】）、课程宣传语（"0基础 学IT 月薪过万"、二维码、领取教程、咨询、
   "就来"、机构 Logo 描述）—— 成稿中一律为 0。
8. **画面线里的宣传场景描述直接丢弃**：视频开场标语、结束页 Logo/二维码、
   "本视频是XX教育机构出品"这类元信息，不是技术内容。
9. 自然口语中文，短句为主，允许"你/咱们"称呼，禁止书面腔 AI 味
   （值得注意的是/换句话说/综上所述/我们需要/通过…来实现）。

## 4. ASR 错识速查（机械层已处理确定性项，LLM 层处理上下文项）

已机械归零（见到即为漏网，顺手修）：
事物→事务、对列→队列、现成→线程（"现成的"除外）、现场→线程、
虚拟站/虚拟机站→虚拟机栈、本地方法站→本地方法栈、方法站→方法栈、
对内存→堆内存、局务→局部、程序技术器→计数器、技术器→计数器、
字件→字节、字典码→字节码、B加→B+、讯息/讯息机→虚拟机、HousePulse→HotSpot、
GIG→JIT、NewSuite→new Thread、JavaC→javac、空前→空闲、本地酷→本地库、
wait not file→wait/notify、死丢→SDK、Java虚拟机机→Java虚拟机。

**LLM 层按上下文判定（重点）**：
| 形态 | 判定规则 |
|---|---|
| MVC | 数据库/隔离级别/MVCC 语境 → MVCC；Spring Web 语境 → MVC 保持 |
| 布隆过 | → 布隆过滤器 |
| redolog / binlog | → redo log / bin log |
| 对中 / 队中 | 内存语境 → 堆中 |
| 裸"站"（如"这个站""站内存"） | JVM 语境 → 栈 |
| 裸"对"（如"分配到对里"） | 内存语境 → 堆 |
| 其他明显同音错识 | 按技术语境修正，拿不准保留原文并在回报中列出 |

## 5. 声音线 × 画面线合并规则

- **声音线（教师讲解）是骨架**：保留讲解顺序、逻辑、比喻、口吻（去口语碎屑后）。
- **画面线（PPT/图表/代码）是权威细节补充**：结构化的要点、图表组成、代码细节
  全部并入对应章节；画面线与声音线重复的内容合并去重，不重复叙述。
- 画面线的时间戳章节（"0:00-0:02 展示标语"这类）除非有技术内容，否则不保留时间轴。
- 画面线的"关键场景与演示描述"只取技术相关部分（讲师在图上指方法区/堆 → 可化为
  "看图时注意方法区和堆的分工"这类自然表述）。

## 6. 批次纪律与回报

- 每批 12 篇，按 `_state.json` 的 `done_files` 集合判断进度（**不是计数**）；
  以磁盘现存文件为准重建状态。
- 每篇写完自检：围栏偶数且 ≥ 原料、H1 唯一、无第 3/7 条残留、代码块逐字。
- 回报格式：处理文件清单 + 每篇代码块数（原料→成稿）+ 拿不准的错识清单 +
  未触碰文件确认。

## 7. 完成判定（全库终检，三重）

1. 围栏偶数 & 代码块数 ≥ `_src/` 对应原稿；
2. 内容特征：口播词/AI 元叙述/品牌/广告/宣传语全库为 0，碎片行比 < 0.35；
3. 代码块守恒：成稿代码块逐字包含于原稿（允许块级缩码归一）。
+ 标点洁癖：破折号/弯引号/HTML 实体（&rarr;/&ldquo;/&rdquo;）为 0；
  每篇恰好 1 个 H1；H1 与文件名（去 NNN- 前缀）一致。
