*   **PPT 标题与章节**：

    *   `两阶段提交协议的演变`

*   **关键术语定义**：
    *   `TC - 事务协调者`：维护全局和分支事务的状态，驱动全局事务提交或回滚。
    *   `TM - 事务管理器`：定义全局事务的范围，开始全局事务、提交或回滚全局事务。
    *   `RM - 资源管理器`：管理分支事务处理的资源，与 TC 交谈以注册分支事务和报告分支事务的状态，并驱动分支事务提交或回滚。

*   **AT 模式前提条件**：
    1.  基于支持本地 ACID 事务的关系型数据库。
    2.  Java 应用，通过 JDBC 访问数据库。

*   **“两阶段提交协议的演变”流程图**：
    *   **一阶段**：业务 SQL 与 undo log 在本地事务中提交，释放本地锁和连接资源。
    *   **二阶段**：提交异步化，非常快速完成。回滚通过一阶段的回滚日志进行反向补偿。

*   **“写隔离”规则**：
    1.  一阶段本地事务提交前，需要确保先拿到“全局锁”。
    2.  拿不到“全局锁”，不能提交本地事务。
    3.  拿“全局锁”的尝试被限制在一定范围内，超出范围则放弃，并回滚本地事务，释放本地锁。

*   **示例说明**：
    *   两个全局事务 `tx1` 和 `tx2`，分别对表 `a` 的 `m` 字段进行更新，`m` 的初始值为 1000。
    *   `tx1` 先开始，更新操作 `m = 1000 - 100 = 900`。
    *   `tx2` 后开始，更新操作 `m = 900 - 100 = 800`。
    *   通过“全局锁”机制，确保了事务的顺序性和数据一致性。

*   **流程图关键步骤**：
    *   `Get local lock` (获取本地锁)
    *   `Get global lock` (获取全局锁)
    *   `Local Commit` (本地提交)
    *   `Release global lock` (释放全局锁)
    *   `Require local lock` (需要本地锁)
    *   `Branch rollback` (分支回滚)
    *   `Branch rollback Done` (分支回滚完成)
