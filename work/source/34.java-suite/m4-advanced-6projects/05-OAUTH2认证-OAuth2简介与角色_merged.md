### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **图表：单点登录认证流程图**
    *   **内容**：图中展示了“客户”与“服务A”、“服务B”之间的交互，所有服务都通过“统一认证授权服务”进行认证。
    *   **关键步骤**：
        1.  **① 登陆请求**：客户向服务A发起登录请求。
        2.  **② 重定向**：服务A将客户重定向至统一认证授权服务。
        3.  **③ 登陆认证/返回令牌**：统一认证授权服务完成认证后，将令牌返回给客户。
        4.  **④ 访问资源**：客户使用令牌访问服务A或服务B的资源。
    *   **核心思想**：通过一个中心化的授权服务器，实现多服务的单点登录，简化了开发和运维。

*   **文本：OAuth2.0 角色定义**
    *   **resource owner**：资源所有者，具备访问该资源的实体，如果是某个人，被称为 end-user。
    *   **resources server**：资源服务器，受保护的资源服务器，具备提供资源能力，如订单服务、商品服务等。
    *   **client**：客户端，指对资源服务器发起请求的应用程序，如前后端分离项目中的前端或后台接口。
    *   **authorization server**：授权服务器，能够给客户端颁发令牌，即我们上面所讲的统一认证授权服务器。
    *   **user-agent**：用户代理，作为资源所有者与客户端沟通的工具，如 APP、浏览器等。

*   **文本：OAuth2.0 介绍**
    *   **核心定义**：OAuth 2.0 是一个行业的标准授权协议。
    *   **主要目标**：专注于简化客户端开发，同时为 Web 应用程序、桌面应用程序、手机等各种设备接入提供特定的授权流程。
    *   **核心机制**：为第三方应用颁发一个具有时效性的 Token 令牌，使其能够通过令牌获取相关资源。
    *   **常见场景**：
        *   用户在网站上通过 QQ、微信、支付宝等账号进行登录，采用的就是 OAuth2 协议。
        *   对外 API 服务接口，也一般采用 OAuth2 授权，如微信 API、新浪 API 等。
    *   **优势**：只需一台认证服务器，统一用户数据库，完成用户认证授权，控制资源访问，支持其他服务或第三方应用接入，扩展性强，开发和运维成本降低。
