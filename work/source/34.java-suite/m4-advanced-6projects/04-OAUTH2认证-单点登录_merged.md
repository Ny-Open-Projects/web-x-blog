*   **图表（架构图）**:
    *   **图1：单点登录（SSO）架构图**
        *   **核心组件**:
            *   **客户端 (Client)**: 代表用户，如手机或网页。
            *   **服务A、服务B**: 代表需要用户登录的各个业务服务。
            *   **统一认证授权服务 (Identity Provider)**: 核心组件，负责用户认证和授权。
            *   **统一用户数据库 (Unified User Database)**: 存储所有用户的凭证信息。
        *   **交互流程**:
            1.  **① 登陆请求**: 客户端向服务A发起登录请求。
            2.  **② 重定向**: 服务A将客户端重定向至统一认证授权服务。
            3.  **③ 登陆认证/返回令牌**: 统一认证授权服务处理登录，认证成功后返回令牌给客户端。
            4.  **④ 访问资源**: 客户端携带令牌访问服务A或服务B，服务端验证令牌后允许访问。
    *   **图2：传统登录架构图（对比图）**
        *   **核心组件**:
            *   **客户端 (Client)**: 代表用户。
            *   **服务A、服务B、服务C、服务D**: 代表各个业务服务。
            *   **用户数据A、用户数据B、用户数据C、用户数据D**: 每个服务都有自己的独立用户数据库。
        *   **交互流程**:
            *   客户端需要分别向服务A、服务B、服务C、服务D发起登录请求，每个服务都独立处理认证逻辑，导致数据分散和开发成本高。
