### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

#### **PPT 内容**

*   **标题**: `Apache Druid 架构设计`
*   **核心节点描述**:
    *   **1. Realtime Node**: 即时摄入实时数据，生成 `Segment` (LSM-Tree 实现与 HBase 基本一致) 文件。
    *   **2. Historical Node**: 加载已生成好的数据文件，以供数据查询。
    *   **3. Broker Node**: 对外提供数据查询服务，并同时从 Realtime Node 和 Historical Node 查询数据，合并后返回给调用方。
    *   **4. Coordinator Node**: 负责 Historical Node 的数据负载均衡，以及通过 Rule 管理数据生命周期。
*   **外部依赖描述**:
    *   **1. 元数据库 (Metastore)**: 存储 Druid 集群的元数据信息，如 Segment 的相关信息，一般使用 MySQL 或 PostgreSQL。
    *   **2. 分布式协调服务 (Coordination)**: 为 Druid 集群提供一致性服务，通常为 Zookeeper。
    *   **3. 数据文件存储 (DeepStorage)**: 存储生成的 Segment 文件，供 Historical Node 下载，一般为使用 HDFS。
*   **数据摄入架构图**:
    *   **数据源**: Streaming Data (实时) 和 Batch Data (批量)。
    *   **核心组件**: Druid 系统由 Real-time Nodes, Historical Nodes, Broker Nodes, Coordinator Nodes 组成。
    *   **外部依赖**: MySQL, Zookeeper, Deep Storage (HDFS)。
    *   **数据流向**: 实时数据流经 Real-time Nodes，批量数据流经 Deep Storage，最终由 Broker Nodes 处理查询请求并返回结果。
*   **数据摄入方式图**:
    *   **查询** -> **Druid** -> **实时摄入 (Kafka)** / **批量摄入 (HDFS, CSV)**。
