        *   主库处理写操作 (INSERT, UPDATE, DELETE)。
        *   从库处理读操作 (SELECT)。

    *   **SQL语句优化要点**：
        *   调整WHERE子句连接顺序，自下而上解析。
        *   尽量将多条SQL语句压缩成一条，减少网络开销和IO开销。
        *   用WHERE替换HAVING，避免全表扫描。
        *   使用表别名，减少解析时间。
        *   in和exists中优先使用EXISTS。
        *   用union all替换union，避免排序。

        *   连接数
        *   缓存
        *   吞吐量
        *   IO线程

### 4) 关键场景与演示描述

*   **场景一：业务设计合理性**
    *   **描述**：讲师首先强调，业务设计并非要满足所有需求，而是在性能瓶颈处要学会“权衡取舍”。例如，对于不需要强实时性的业务数据报表，可以采用“预生成”方式，即不直接查询核心数据表，而是预先计算好结果，从而既满足业务需求，又保护了核心表的性能。

*   **场景二：索引优化详解**
    *   **描述**：讲师重点讲解了索引的作用和类型。他指出，索引可以极大优化查询性能，并列举了主键索引、唯一索引、常规索引和全文索引。随后，他深入讲解了两种底层索引结构：
        *   **B-Tree索引**：讲师解释了B-Tree是一种自平衡的树结构，能保持数据有序，从而优化了查找、插入和删除操作。其核心优势是可以通过索引根节点快速定位数据，避免全表扫描。
        *   **Hash索引**：讲师介绍了Hash索引通过哈希算法将数据映射到哈希数组上，实现一次定位，效率高。但其缺点是：只能进行等值比较，不能用于范围查询；数据在哈希表中不一定按顺序排列，无法加速排序操作；当哈希值重复或数据量大时，其效率可能不如B-Tree。

*   **场景三：分库分表与读写分离**
    *   **描述**：讲师介绍了分库分表用于分解数据压力，提升系统I/O吞吐能力。他以“基因法”为例，说明如何通过取模（如 `uid % 8`）将用户数据路由到不同的数据库实例。同时，他也指出了分库分表的局限性，如不支持跨库关联查询、分页查询等。接着，他讲解了读写分离，即主库处理写操作，从库处理读操作，通过主从复制和读写分离来提升数据库的并发负载能力。

*   **场景四：SQL语句调优**
    *   **描述**：讲师展示了如何通过调整SQL语句来优化响应时间。他给出了多个优化建议，如调整WHERE子句的连接顺序、将多条SQL语句合并、用WHERE替换HAVING、使用表别名、优先使用EXISTS代替IN、以及用UNION ALL代替UNION等。

*   **场景五：MySQL配置与执行计划**
    *   **描述**：讲师提到了MySQL的配置优化，包括连接数、缓存、吞吐量、IO线程和闲置连接回收等参数。最后，他引出了“执行计划分析”这一高级主题，指出执行计划是分析SQL语句执行过程的关键，包括查询顺序、是否使用索引等信息，是优化SQL语句的重要依据。
