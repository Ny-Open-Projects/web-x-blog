### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

#### PPT / 图表内容：

- **Druid 数据结构**：
  - 数据被组织成“段”（Segment），每个段最多有数百万行。
  - 数据存储在“数据源”中，与传统关系型数据库中的“表”类似。
  - 三类列：
    - **Timestamp column (时间戳列)**：将时间字段单独处理，所有查询围绕时间轴进行。
    - **Dimension columns (维度列)**：存储数据的属性，按原样存储，可用于查询时的分组、筛选。
    - **Metric columns (指标列)**：以聚合形式存储，用于做聚合计算，如 `count`、`sum`。

- **Druid 系统架构图**：
  - **Master Servers**：包含 `Coordinator` 和 `Overlord`，负责管理集群数据可用性和工作负载分配。
  - **Query Servers**：包含 `Router`（可选）和 `Broker`，处理来自外部客户端的查询。
  - **Data Servers**：包含 `MiddleManager` 和 `Historical`，负责数据的采集和存储。
  - **外部依赖**：
    - `Metadata Storage`：存储元数据。
    - `Zookeeper`：用于协调服务。
    - `Deep Storage`：用于存储数据段。

- **Druid 进程功能说明**：
  - `Coordinator`：管理集群数据可用性。
  - `Overlord`：控制数据摄取工作负载的分配。
  - `Broker`：处理来自外部客户端的查询请求。
  - `Router`：可选进程，将请求路由到 `Brokers`、`Coordinators` 和 `Overlords`。
  - `Historical`：存储历史查询到的数据。
  - `MiddleManager`：负责摄取数据。

- **Druid 在本项目中的应用流程图**：
  - “司机App” → “上报位置信息” → `pd-netty` → “发送消息” → `kafka` → Druid。

#### 代码内容：

- **启动命令行**：
  - `bin/druid-overlord-server.sh`：用于启动 Overlord 进程。
  - `bin/druid-coordinator-server.sh`：用于启动 Coordinator 进程。
  - `bin/druid-broker-server.sh`：用于启动 Broker 进程。
  - `bin/druid-historical-server.sh`：用于启动 Historical 进程。
  - `bin/druid-middlemanager-server.sh`：用于启动 MiddleManager 进程。
