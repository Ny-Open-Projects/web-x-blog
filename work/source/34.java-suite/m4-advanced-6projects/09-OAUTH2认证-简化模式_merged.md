### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **图表**:
    *   **简化模式流程图**: 展示了资源拥有者（Resource Owner）、用户代理（User-Agent）、客户端（Client）和认证服务器（Authorization Server）之间的交互。关键步骤包括：
        1.  用户代理访问客户端。
        2.  客户端向认证服务器发起请求，携带 `client_id` 和 `redirect_uri`。
        3.  用户在认证服务器上认证。
        4.  认证服务器将带有 `Access Token` 的重定向 URI 返回给用户代理。
        5.  用户代理将重定向 URI 传递给客户端。
        6.  客户端从重定向 URI 中提取 `Access Token`。
        7.  客户端使用 `Access Token` 向资源服务器请求资源。
    *   **授权码模式流程图**: 展示了客户端、用户代理和认证服务器之间的交互。关键步骤包括：
        1.  用户代理访问客户端。
        2.  客户端向认证服务器发起请求，携带 `client_id`、`redirect_uri` 和 `response_type=code`。
        3.  用户在认证服务器上认证。
        4.  认证服务器将 `code` 返回给客户端。
        5.  客户端使用 `code`、`client_id` 和 `client_secret` 向认证服务器请求令牌。
        6.  认证服务器返回 `Access Token`。
        7.  客户端使用 `Access Token` 向资源服务器请求资源。

*   **代码/参数**:
    *   **授权请求参数**:
        ```text
        response_type=token
        &client_id={客户端的ID}
        &redirect_uri={重定向URI}
        &scope={申请的权限范围}
        &state={任意值}
        ```
    *   **授权响应参数**:
        ```text
        &access_token={令牌信息}   // 必填
        &expires_in={过期时间}     // 任意
        &state={任意文字}          // 如果授权请求中包含 state 那就是必填
        &scope={授权范围}          // 如果请求和响应的授权范围不一致就必填
        ```
    *   **令牌响应**:
        ```json
        {
          "access_token": "{访问令牌}",
          "token_type": "{令牌类型}",
          "expires_in": {过期时间},
          "refresh_token": "{刷新令牌}",
          "scope": "{授权范围}"
        }
        ```
    *   **简化模式与授权码模式的主要区别**:
        *   **简化模式**: 缺少 `code` 验证环节，令牌直接返回给客户端，存在安全风险。
        *   **授权码模式**: 通过 `code` 验证环节，客户端在后台与认证服务器交互获取令牌，用户代理无法获取令牌，安全性更高。
