### 1) 视频摘要

本视频课程讲解了如何在 Spring Boot 项目中实现一个全局权限过滤器，以控制用户对不同菜单和接口的访问权限。核心内容包括：
- **功能设计**：通过流程图说明了用户请求的权限校验逻辑。
- **过滤器实现**：创建并实现 `GlobalSecurityFilter`，用于拦截请求并判断用户是否有权限。
- **性能优化**：利用 Spring Cache（Redis）缓存权限菜单数据，避免每次请求都查询数据库，从而提升性能。
- **数据初始化**：在服务启动时，将系统默认的公开菜单和权限数据加载到缓存中。
- **功能验证**：通过 Swagger 接口文档和 Postman 工具，演示了用户登录、新增用户、以及访问受权限控制的接口的完整流程。

  - **核心逻辑**：
    - 获取请求的 URI。
    - 判断是否需要权限校验。
    - 如果需要，调用 `filterChain.doFilter`。

    - `t_authority_menu` 与 `t_authority_menu_operation`：菜单和操作数据。

#### 代码

- **过滤器核心代码 (3.2)**：
  ```java
  // 1. 获取请求的相对路径，去除contextPath
  HttpServletRequest request = (HttpServletRequest) servletRequest;
  String uri = getActRequestUri(request);

  // 2. 针对需要权限判断的数据做拦截，提升处理性能
  if (isNeedAuth(uri)) {
      filterChain.doFilter(servletRequest, servletResponse);
      return;
  }

  // 3. 系统忽略的菜单，直接放行
  Cache cache = cacheManager.getCache(GlobalConstants.AUTHORITY_MENU_KEY);
  if (null != cache) {
      Set<String> noLimitUri = (Set<String>) cache.get(GlobalConstants.AUTHORITY_MENU_NO_LIMIT_KEY).get();
      if (noLimitUri.contains(uri)) {
          filterChain.doFilter(servletRequest, servletResponse);
      }
  }
  ```
