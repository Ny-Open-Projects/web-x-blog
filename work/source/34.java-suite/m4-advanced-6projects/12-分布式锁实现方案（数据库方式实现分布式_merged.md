### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **代码 (Code)**:
    *   **核心业务逻辑**:
        ```java
        @GetMapping("/stock")
        public String stock() {
            MyLock myLock = new MyLock();
            myLock.setMethodName("stock");

            try {
                myLockMapper.insert(myLock); // 获取锁

                int stock = Integer.parseInt(redisTemplate.opsForValue().get("stock"));
                if (stock > 0) {
                    stock--; // 扣减库存
                    redisTemplate.opsForValue().set("stock", stock+""); // 更新库存
                    System.out.println("库存扣减成功，剩余库存：" + stock);
                } else {
                    System.out.println("库存不足！！！");
                }

                // 释放锁
                myLockMapper.deleteByMethodName("stock");
            } catch (Exception ex) {
                System.out.println("没有获得锁，不能执行减库存操作...");
            }

            return "OK";
        }
        ```
    *   **关键注释**:
        *   `// 当前线程获得锁，可以执行下面的业务代码`
        *   `// 释放锁`
        *   `// 没有获得锁`

*   **PPT / 文档 (PPT / Document)**:
    *   **文档标题**: `品达物流TMS项目 - 第9章 TMS后台管理端开发(pd-web-manager)`
    *   **章节结构**:

        *   2.1 数据库实现分布式锁
        *   2.2 ZooKeeper实现分布式锁
        *   2.3 Redis实现分布式锁
        *   3. 导入功能代码
    *   **关键内容**:
        *   **数据库实现分布式锁的缺点**:
            1.  数据库可用性影响锁的可用性，需要双机部署、数据同步、主备切换。
            2.  不具备可重入性，需要在表中新增一列记录当前线程信息。
            3.  没有锁失效机制，需要定时任务清理失效数据。
            4.  不具备锁租约特性，需要优化获取逻辑。
            5.  实际实现会越来越复杂，依赖数据库资源和性能。
        *   **ZooKeeper 实现分布式锁**:
            *   数据存储结构像一棵树，节点称为 ZNode。
            *   默认的节点类型是持久节点 (PERSISTENT)。
