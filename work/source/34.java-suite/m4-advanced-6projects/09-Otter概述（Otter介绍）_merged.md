### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **PPT 内容**:
    *   **章节标题**: “2. Otter概述”、“2.1 介绍”、“2.2 架构”。
    *   **核心介绍**: Otter 依赖 Canal 接收和解析 MySQL binlog 日志，提供可配置的同步机制，纯 Java 开发，免费开源，基于数据库增量日志解析，准实时同步到本机或异地机房的 MySQL/Oracle 数据库，是一个分布式数据同步系统。
    *   **典型应用场景**:
        1.  **异构库同步**: `mysql -> mysql/oracle` (当前开源版只支持 MySQL 增量，目标库可以是 MySQL 或 Oracle，取决于 Canal 的功能)。
        2.  **单机房同步**: 数据库之间 RTT < 1ms (RTT: 往返延迟)。
        3.  **异地机房同步**: (如阿里巴巴国际站就是杭州和美国机房的数据库同步，RTT > 200ms)。
        4.  **双向同步**: 包含“避免回环算法”和“数据一致性算法”。
        5.  **文件同步**: “站点镜像” (进行数据复制的同时，复制关联的图片，比如复制产品数据，同时复制产品图片)。
    *   **架构图**:
        *   **顶层**: `manager` (管理请求)。
        *   **中间层**: `Zookeeper` (状态存储)。
        *   **底层**: 多个 `db` (数据库) 节点。
        *   **数据流向**: `Canal` (配置) -> `manager` -> `Zookeeper` -> `db`。
        *   **节点内部**: 包含 `arbitrate`, `config`, `statistics` 等模块。
