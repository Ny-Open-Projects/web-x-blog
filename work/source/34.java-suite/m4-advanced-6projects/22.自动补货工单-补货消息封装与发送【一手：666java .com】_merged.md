            .eq(VendingMachineEntity::getVStatus, VMSYSTEM_STATUS_RUNNING);

        for (VendingMachineEntity vm : vmList) {
            int count = vmService.inventory(percent, vm);

### 4) 关键场景与演示描述

*   **场景 1: 业务逻辑实现** (00:05-00:15)
    开发者在 `VendingMachineServiceImpl` 中定义了 `sendSupplyTask` 方法。该方法接收一个 `VendingMachineEntity` 对象，用于计算需要补货的渠道数量。通过 `QueryWrapper` 构建查询条件，筛选出当前容量低于预警值的渠道。

*   **场景 2: 流式数据处理** (00:15-00:35)
    开发者使用 Java Stream API 对查询到的渠道列表进行转换。通过 `.map()` 方法，将每个 `ChannelEntity` 对象转换为一个 `SupplyChannel` 对象，并设置其属性（如商品ID、补货量等）。最后，使用 `.collect(Collectors.toList())` 将流转换为一个 `SupplyChannel` 列表。

*   **场景 3: 消息封装与发送** (00:35-00:45)
    开发者将 `SupplyChannel` 列表封装到 `SupplyCfg` 对象中。`SupplyCfg` 包含了补货任务的详细信息，如售货机内码、补货数据和消息类型。随后，通过 `mqttProducer` 将 `SupplyCfg` 对象发送到指定的 MQTT 主题，触发下游服务的补货操作。

*   **场景 4: 任务调度与处理** (00:45-01:05)
    开发者展示了 `SupplyJobHandler` 类，该类负责处理消息队列中的补货任务。它首先获取需要补货的百分比，然后查询所有状态为“运行中”的售货机。对于每台售货机，它调用 `inventory` 方法计算需要补货的数量，如果数量大于0，则调用 `sendSupplyTask` 方法发送补货任务。最后，返回成功状态。
