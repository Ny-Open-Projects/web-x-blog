### 4) 关键场景与演示描述

*   **场景一：HA 机制启动流程演示**
    *   **描述**: 讲师通过 PPT 图表，演示了两个 Canal Server (A 和 B) 如何竞争成为主节点。当 Server A 启动时，它会向 ZooKeeper 创建一个短暂的节点。如果创建成功，ZooKeeper 会允许 Server A 启动其对应的 Canal Instance，并将 Server A 标记为 `Running` 状态。Server B 会检测到 Server A 的节点存在，从而保持 `Standby` 状态。
*   **场景二：故障切换演示**
    *   **描述**: 讲师模拟 Server A 故障，其在 ZooKeeper 上的节点消失。ZooKeeper 会立即通知 Server B。Server B 会执行步骤 1，尝试创建自己的节点。如果成功，Server B 就会启动其 Canal Instance，成为新的 `Running` 节点，而 Server A 则进入 `Standby` 状态。
*   **场景三：客户端连接流程演示**
    *   **描述**: 讲师演示了 Canal Client 如何连接。客户端会先向 ZooKeeper 查询当前 `Running` 的节点信息，然后与该节点建立连接。如果连接失败，客户端会重新查询 ZooKeeper 并尝试连接新的 `Running` 节点，从而保证服务的连续性。
