本视频片段是关于分布式事务解决方案的讲解，核心内容是使用 **Seata** 框架来实现“抢单”场景下的分布式事务。讲师首先指出，在高并发抢购场景下，仅依靠数据库的乐观锁或库存减扣操作是不够的，因为可能存在“库存扣减成功但订单创建失败”的情况，这会导致数据不一致。为了解决这个问题，讲师引入了 **Seata** 的 **AT（Automatic Transaction）模式**，通过在业务数据库中记录“undo_log”日志，实现最终一致性。视频通过展示 `OrderService` 的 Java 代码和 Seata 的架构图，详细说明了如何在业务代码中集成 Seata，并通过日志记录和补偿机制来保证事务的完整性。

### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **PPT 内容**:
    *   **章节标题**: “3.3 抢单分布式事务实现”。
    *   **核心问题**: “非热点商品抢单的时候...库存扣减成功，但创建订单失败了...需要回滚库存...可以使用Seata实现。”
    *   **Seata AT 模式实现步骤**:
        1.  在需要控制分布式事务的数据库中添加日志表 `undo_log`。
        2.  安装 TC。
        3.  配置数据源。
        4.  配置微服务与 Seata 的 TC 交互信息及注册地址。
        5.  使用全局分布式事务的方法上添加注解 `@GlobalTransactional`。
    *   **日志表结构**:
        ```sql
        CREATE TABLE undo_log (
            branch_id bigint(20) NOT NULL AUTO_INCREMENT,
            context varchar(128) NOT NULL,
            ...
        );
        ```
    *   **Seata AT 模式架构图**:
        *   **一阶段**: 业务数据和回滚日志记录在同一个本地事务中提交，释放本地锁和连接资源。
        *   **二阶段**: 提交异步化，非常快速地完成。回滚通过一阶段的回滚日志进行反向补偿。
        *   **隔离性说明**:
            1.  一阶段本地事务提交前，需要确保先拿到“全局锁”。
            2.  拿不到“全局锁”，不能提交本地事务。
            3.  “全局锁”的尝试被限制在一定范围内，超出范围则放弃，并回滚本地事务，释放本地锁。

*   **代码内容**:
    *   **`OrderService` 中的 `add` 方法**:
        ```java
        @Override
        public int add(Order order) {
            // 1. 库存减扣
            String userKeys = "USER" + order.getUsername() + "ID" + order.getSkullId();
            Sku dc = skuFeign.count(order.getSkullId(), order.getTotalNum());
            if (dc.getCode() == StatusCode.DECOUNT_OK) {
                // 2. 下单
                Sku sku = dc.getData();
                order.setId("No" + idWorker.nextId());
                order.setOrderStatus("0");
                order.setPayStatus("0");
                order.setConsignStatus("0");
                order.setSkullId(sku.getId());
                order.setName(sku.getName());
                order.setPrice(sku.getSeckillPrice() * order.getTotalNum());
                orderMapper.insertSelective(order);
                // 3. 记录当前用户订单的提交时间点，24小时内不能抢购该商品
                redisTemplate.boundValueOps(userKeys).set("*");
                redisTemplate.expire(userKeys, 1, TimeUnit.MINUTES);
                // 4. 发送消息，通知库存服务
                String key = "SKU" + order.getSkullId();
                Boolean bo = redisTemplate.boundHashOps(key).hasKey(userKeys);
                if (bo) {
                    Map<String, String> orderMap = new HashMap<>();
                    orderMap.put("username", order.getUsername());
                    orderMap.put("id", order.getId());
                    orderMap.put("skullId", order.getSkullId());
                    kafkaTemplate.send(topic, JSON.toJSONString(orderMap));
                }
                return StatusCode.ORDER_OK;
            } else {
                return 202;
            }
        }
        ```
