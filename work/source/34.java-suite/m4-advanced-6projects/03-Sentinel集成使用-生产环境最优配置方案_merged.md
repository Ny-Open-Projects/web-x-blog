### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **PPT 表格：配置模式选择**
    *   **推送模式**: 原始模式 (Push)
        *   **说明**: API 将规则推送至客户端并直接更新到内存中，扩展写数据源 (`WritableDataSource`)。
        *   **优点**: 简单，无任何依赖。
        *   **缺点**: 不保证一致性；规则保存在内存中，重启即消失。严重不建议用于生产环境。
    *   **推送模式**: Pull 模式
        *   **说明**: 扩展写数据源 (`WritableDataSource`)，客户端主动向某个规则管理中心定期轮询拉取规则，这个规则中心可以是 RDBMS、文件等。
        *   **优点**: 规则持久化。
        *   **缺点**: 不保证一致性；实时性不保证，拉取过于频繁也可能会有性能问题。
    *   **推送模式**: Push 模式
        *   **说明**: 扩展读数据源 (`ReadableDataSource`)，规则中心统一推送，客户端通过注册监听器的方式时刻监听变化，比如使用 Nacos、Zookeeper 等配置中心。这种方式有更好的实时性和一致性保证。
        *   **优点**: 规则持久化，一致性，快速。
        *   **缺点**: 引入第三方依赖。

*   **架构图：原始模式 (Push)**
    *   **结构**: 一个 `Sentinel Dashboard` 通过 `push rules` 的箭头，分别指向部署在 `Machine 1`、`Machine 2`、`Machine 3` 上的三个 `Sentinel 客户端`。
    *   **说明**: 规则由 Dashboard 主动推送，客户端被动接收。

*   **架构图：Pull 模式**
    *   **结构**: `Sentinel Dashboard` 通过 `1. 推送规则` 的箭头指向 `Sentinel 客户端`，再通过 `2. 内存中更新规则` 和 `3. 将规则更新至文件` 的箭头指向 `本地文件`。
    *   **说明**: 客户端主动从 Dashboard 拉取规则，并更新本地文件。

*   **架构图：Push 模式**
    *   **结构**: `Sentinel Dashboard` 通过 `1. 推送规则` 的箭头指向 `远程配置中心 (e.g. Nacos, ZooKeeper)`，再通过 `2. 将规则更新至文件` 的箭头指向 `本地文件`。
    *   **说明**: Dashboard 将规则推送到远程配置中心，客户端从中心拉取规则。
