### 1) 视频摘要

本视频课程讲解了 **Otter 数据同步服务** 的核心架构。课程内容主要围绕 Otter 如何基于 **Canal** 开源项目实现数据库增量数据的实时同步。核心架构由三个主要组件构成：**Manager**（管理节点，负责任务配置和调度）、**Node**（工作节点，负责具体的数据处理）和 **Zookeeper**（协调服务，用于分布式状态调度）。课程首先介绍了单机房的复制示意图，随后扩展到跨机房的复制场景，强调了数据“On-Fly”（实时）同步、高可用（failover）和负载均衡（loadBalancer）等关键特性。课程旨在为开发者提供一个清晰的系统架构认知，为后续的安装配置和任务设置打下基础。

### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

#### **PPT / 图表内容**

*   **核心架构图 (2.2 架构)**:
    *   **组件**: `db` (数据源)、`Canal`、`manager`、`zookeeper`、`Node` (包含 `S`、`E`、`T`、`L` 四个阶段)。
    *   **数据流向**: 数据库变更通过 `Canal` 捕获，经由 `manager` 推送配置到 `Node`，`Node` 处理后写入目标数据库。
    *   **Zookeeper 作用**: 协调 `Node` 之间的分布式状态，确保高可用。

*   **单机房复制示意图**:
    *   **流程**: `Admin` 自助定义任务 -> `Manager` 推送配置 -> `Node` 开启数据同步 (S/E/T/L) -> 数据写入目标 `db`。
    *   **状态反馈**: `Node` 将同步状态反馈给 `Manager`。
    *   **关键特性**: 数据 `On-Fly` 同步，Node 支持 failover / loadBalancer。

*   **跨机房复制示意图**:
    *   **架构**: 包含 `A机房` 和 `B机房`，中间由 `Zookeeper` 协调。
    *   **数据流向**: 数据在 A 机房的 `Node` 和 B 机房的 `Node` 之间通过 `网络传输` 进行同步。
    *   **任务调度**: `Manager` 负责向两个机房的 `Node` 推送任务配置和状态反馈。
    *   **数据流向标识**: `A→B数据流` (黄色) 和 `B→A数据流` (红色)。

#### **文字说明内容**

*   **组件说明**:
    *   `db`: 数据源以及需要同步到的库。
    *   `Canal`: 获取数据库增量日志，支持独立部署和内嵌使用两种模式。Otter 使用 Canal 的内嵌方法获取数据库增量日志。
    *   `manager`: 配置同步规则，设置数据源同步等。
    *   `zookeeper`: 协调 Node 进行协调工作。
    *   `node`: 负责任务处理，即根据任务配置对数据源进行解析并同步到目标数据库的操作。

*   **原理描述**:
    *   基于 Canal 的开源产品，获取数据库增量日志数据。
    *   典型管理系统架构：`manager (web管理) + node (工作节点)`。
    *   `manager` 运行时推送同步配置到 `node` 节点。
    *   `node` 节点将同步状态反馈到 `manager` 上。
    *   基于 `zookeeper`，解决分布式状态调度，允许许多 `node` 节点之间协同工作。

*   **应用场景说明**:
    *   **文件同步**: 例如，账户信息表和交易明细表。交易明细表数据量大，可通过 Otter 将其同步到历史表，并进行分表处理，以解决查询慢的问题。
