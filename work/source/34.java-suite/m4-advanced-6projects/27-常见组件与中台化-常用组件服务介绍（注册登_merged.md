### 1) 视频摘要

本视频课程主要讲解了在微服务架构中，如何通过 Spring Cloud Gateway 实现基于 Nacos 的动态路由和权限控制。核心内容包括：
- **演示一个简单的用户认证服务** (`cust-auth`)，该服务提供两个接口：一个无需认证（`/user/noVerify`），一个需要认证（`/user/verify`）。
- **配置 Spring Cloud Gateway 的路由规则**，通过 Nacos 动态管理服务的路由信息，包括服务名、路径匹配（`Predicate`）和请求头过滤（`Filter`）。
- **演示如何通过 Postman 工具测试接口**，验证在未携带认证 token 时，需要认证的接口会返回 `401 Unauthorized` 错误。
- **展示 Nacos 配置中心**，用于管理服务的配置文件（如 `bootstrap.yml`）和路由规则。

整个课程旨在说明如何将认证服务集成到微服务网关中，并通过配置中心实现服务的动态发现和路由。

    ```java
    @RestController
    @RequestMapping("user")
    public class UserController {

        // 不需要鉴权的接口测试
        @GetMapping("noVerify")
        public String noVerify(@RequestHeader(required = false) String authId) {
            return "不需要鉴权的接口,获取到的用户ID: " + authId;
        }

        // 需要鉴权的接口测试
        @GetMapping("verify")
        public String verify(@RequestHeader(required = true) String authId) {
            return "需要鉴权的接口,获取到的用户微信信息: " + authId;
        }
    }
    ```

### 4) 关键场景与演示描述

*   **场景一：演示 `UserController` 接口**
    *   **描述**: 讲师在 IntelliJ IDEA 中打开 `UserController.java` 文件，高亮显示了 `noVerify` 和 `verify` 两个方法。`noVerify` 方法的 `@RequestHeader` 注解设置为 `required = false`，表示该接口不需要认证头；`verify` 方法的 `@RequestHeader` 注解设置为 `required = true`，表示该接口需要认证头。
    *   **目的**: 说明服务端如何区分需要和不需要认证的接口。

*   **场景二：演示 Nacos 配置中心**
    *   **描述**: 讲师切换到浏览器，打开 Nacos 配置中心的界面，展示了 `cust-auth` 服务的配置文件列表。他点击了 `cust-auth-common.yml` 文件，查看了其中的配置信息。
    *   **目的**: 说明如何通过 Nacos 管理服务的配置文件。

*   **场景三：演示 Spring Cloud Gateway 路由配置**
    *   **描述**: 讲师在 Nacos 配置中心的路由配置文件中，展示了如何配置 `id`、`uri`、`predicates` 和 `filters`。他特别强调了 `predicates` 中的 `Path` 用于匹配请求路径，`filters` 中的 `StripPrefix` 用于移除路径前缀。
    *   **目的**: 说明如何通过 Nacos 动态管理服务的路由规则。

*   **场景四：演示 Postman 测试接口**
    *   **描述**: 讲师在 Postman 中创建了一个 `GET` 请求，目标地址为 `http://localhost:8782/user/user/verify`。他设置了请求头，但没有设置 `token`。点击 `Send` 后，返回了 `401 Unauthorized` 错误。

*   **场景五：演示服务启动日志**
    *   **描述**: 讲师在 IntelliJ IDEA 的终端中，查看了 `UserApplication` 启动后的日志。日志中显示了 `GatewayApplications` 的信息，以及 `SendCodeLystrix` 等服务的启动信息。
    *   **目的**: 说明服务启动成功，并且网关能够正常工作。
