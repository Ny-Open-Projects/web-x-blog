关于这几个系统,我们来讲解一下。

首先,我们秒杀后台的一个管理员系统,它主要是实现秒杀商品的管理,秒杀商品的修改,增加,查询,还有审核这些基本的操作。

这是管理员后台。

那这一块它的一些基本功能,我们都不去讲解了。

因为这些功能呢,挑战性不是很大。

搜索系统呢,是去实现我们商品的一个搜索的。

比如你后台这里添加了一个商品,审核通过了。

那么在我们搜索系统这里,是可以查询到的。

那用户来搜索的时候呢,他其实是走的我们。

这一块就是我们秒杀抢单脚本控制。

脚本控制这一块呢,主要控制一些热点商品抢单和非热点商品抢单。

那这一块抢单的时候,它又会走我们的秒杀抢单系统。

秒杀抢单系统呢,在这一块会处理两类商品。

第一类是非热点商品订单。

第二类是热点商品订单。

所以这一块抢单的时候,也会走不同的模式。

热点数据发现系统呢,它主要是针对用户访问的一个实时数据进行收集,然后进行分析。

那分析到了之后,我们可以定义一系列的规则。

判断一下哪些商品是正常的。

第一类是属于热点商品。

比如访问频率很高的。

比如在一分钟内访问频率非常高的。

这一类我们可以定义为热点商品。

这个是实时热点数据的收集。

还有一个是历史热点数据的收集。

我们可以统计过往的订单数据,过往的购物车数据,过往的搜索记录,过往的详情搜索记录。

像这些信息,我们可以全部统计。

然后把这些导入到我们的热点数据发现系统里面。

然后进行分析。

可以分析出历史商品里面哪些数据是热点数据,再把它进行隔离。

这个就是我们秒杀的一个业务流程设计。
