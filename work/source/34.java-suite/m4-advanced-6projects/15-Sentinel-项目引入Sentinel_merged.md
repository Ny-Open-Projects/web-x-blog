### 1) 视频摘要

本视频课程主要讲解如何在微服务架构中，利用 **Sentinel** 框架对 **Nginx 网关** 进行限流操作，以保护后端服务在高并发（如秒杀）场景下的稳定性。课程通过一个名为 `seckill` 的项目进行演示，首先在网关服务中引入 Sentinel 依赖，配置其控制台地址，然后在网关的配置文件中设置限流规则。最后，通过 Sentinel 控制台实时监控限流效果，验证了限流策略的有效性。

### 4) 关键场景与演示描述

1.  **场景一：项目初始化与依赖引入**：
    *   讲师在 IDE 中打开 `seckill-gateway` 项目的 `pom.xml` 文件，通过鼠标高亮并讲解需要添加的 `spring-cloud-starter-alibaba-sentinel-gateway` 依赖，强调这是实现网关限流的核心。

    *   讲师切换到 `bootstrap.yml` 文件，高亮并解释 `sentinel.transport.port` 和 `sentinel.dashboard` 的配置项，说明它们分别用于指定 Sentinel 传输端口和控制台地址。

3.  **场景三：服务启动与调试**：

    *   修正配置后，商品服务成功启动，控制台显示了服务注册到 Nacos 的成功日志。

4.  **场景四：Sentinel 控制台监控**：
    *   讲师打开浏览器访问 Sentinel 控制台（`http://192.168.211.137:8888`）。
    *   在控制台中，为网关服务配置了限流规则，如对 `goods_sale` 路由设置 QPS 限制。
    *   通过 Postman 发起大量请求，观察控制台中 `goods_sale` 路由的 QPS 数据，验证限流策略是否生效。

5.  **场景五：错误处理与调试**：
    *   在启动商品服务时，讲师展示了因未配置 Redis 导致的 `Connection refused` 错误，以及因 `@ConfigurationProperties` 注解导致的 `BeanCreationException`，并解释了错误原因和解决方案。
