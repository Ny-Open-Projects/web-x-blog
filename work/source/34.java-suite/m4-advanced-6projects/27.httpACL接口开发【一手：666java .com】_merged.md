### 1) 视频摘要

本视频课程聚焦于 **EMQX MQTT 消息中间件的 HTTP ACL（访问控制列表）接口开发**。讲师通过一个名为 `emq-demo` 的 Spring Boot 项目，演示了如何在后端服务中实现基于 HTTP API 的用户认证与权限控制。核心内容包括：
*   **超级用户认证 (`/superuser`)**：通过检查客户端 ID 或用户名中是否包含 `"admin"` 字符串来判断用户身份。
*   **精细化权限控制 (`/acl`)**：根据用户名、客户端 ID、主题（Topic）、访问级别（Access Level）等多个参数，对 MQTT 操作（如发布、订阅）进行权限验证。
*   **演示环境**：使用 EMQX 的 Web 管理后台（Dashboard）作为客户端，通过 WebSocket 连接并测试 HTTP API 的权限控制效果。

整个过程旨在展示如何将后端服务与 MQTT 中间件的权限管理进行集成，实现对消息发布的精细化控制。

### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

#### PPT / 文档内容

*   **文档标题**：`8.2.2 HTTP ACL接口开发`。
*   **核心说明**：在 `emq-demo` 项目中，基于 HTTP API 开发认证控制器 `AuthController`，用于进行 ACL 权限检查。

#### 代码关键内容

1.  **超级用户认证接口 (`/superuser`)**
    ```java
    @PostMapping("/superuser")
    public ResponseEntity<?> superuser(@RequestParam("clientId") String clientId,
                                       @RequestParam("username") String username) {
        if (clientId.contains("admin") || username.contains("admin")) {
            log.info("用户{}是超级用户", username);
            return new ResponseEntity<>(HttpStatus.OK);
        } else {
            log.info("用户{}不是超级用户", username);
            return new ResponseEntity<>(HttpStatus.UNAUTHORIZED);
        }
    }
    ```

2.  **精细化权限控制接口 (`/acl`)**
    ```java
    @PostMapping("/acl")
    public ResponseEntity<?> acl(@RequestParam("access") int access,
                               @RequestParam("username") String username,
                               @RequestParam("clientId") String clientId,
                               @RequestParam("ipaddr") String ipaddr,
                               @RequestParam("topic") String topic,
                               @RequestParam("mountpoint") String mountpoint) {
        log.info("EMQX发起客户端操作请求参数: access={}, username={}, clientId={}, ipaddr={}, topic={}, mountpoint={}", access, username, clientId, ipaddr, topic, mountpoint);

        if (username.equals("eqm-client1") && topic.equals("testtopic/#") && access == 1) {
            log.info("客户端{}有权限订阅主题{}", username, topic);
            return new ResponseEntity<>(HttpStatus.OK);
        }

        if (username.equals("eqm-client2") && topic.equals("testtopic/123") && access == 2) {
            log.info("客户端{}有权限订阅主题{}", username, topic);
            return new ResponseEntity<>(HttpStatus.OK);
        }

        // 其他情况返回 401
        log.info("客户端{}没有权限订阅主题{}", username, topic);
        return new ResponseEntity<>(HttpStatus.UNAUTHORIZED);
    }
    ```

2.  **场景二：精细化权限控制测试**
    *   **操作**：讲师在 Dashboard 中，使用 `user` 用户连接。
    *   **结果**：在后端日志中看到 `用户user不是超级用户` 的日志，并尝试发布消息。
    *   **结果**：在 Dashboard 的消息接收区，没有收到任何消息，表明权限被拒绝。
    *   **目的**：验证 `acl` 接口的逻辑，确认非超级用户无法访问受限主题。

3.  **场景三：权限验证日志分析**
    *   **操作**：讲师在 IntelliJ IDEA 的控制台中查看日志。
    *   **结果**：日志清晰地记录了每个客户端的请求参数、权限判断结果和最终的 HTTP 状态码。
    *   **目的**：通过日志分析，直观地理解权限控制的执行过程和结果。

4.  **场景四：主题权限测试**
    *   **操作**：讲师在 Dashboard 中，为 `eqm-client1` 设置 `access=1`，并订阅 `testtopic/#`。
    *   **结果**：成功收到消息。
    *   **操作**：为 `eqm-client2` 设置 `access=2`，并订阅 `testtopic/123`。
    *   **结果**：成功收到消息。
    *   **目的**：验证基于主题和访问级别的权限控制，确保只有符合规则的客户端才能访问特定主题。
