### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

#### **代码关键内容**

*   **`Mock.java` 文件中的核心代码**：
    ```java
    @Component
    public class Mock {
        @Autowired
        private QuotaService quotaService;
        @Autowired
        private EmqClient emqClient;

        @Scheduled(cron = "0/10 * * * * ?") // 每10秒执行一次
        public void addDatas() {
            System.out.println(LocalDateTime.now() + "模拟数据产生");
            List<QuotaEntity> quotaList = quotaService.list(); // 获取所有指标定义

            for (int i = 1; i <= 10; i++) { // 模拟10台设备
                String deviceId = "100000" + i + ""; // 设备编号
                Map<String, Object> map = Maps.newHashMap(); // 原文
                map.put(quotaEntity.getsKey(), deviceId); // 设备ID
                // 产生随机数
                Random random = new Random();
                int quotaValue = random.nextInt(48); // 指标值
                map.put(quotaEntity.getValueKey(), quotaValue); // 指标值

                try {
                    String json = JsonUtil.serialize(map); // 序列化为JSON
                    emqClient.publish(quotaEntity.getObject(), json); // 发送数据
                    Thread.sleep(20); // 等待20毫秒
                } catch (JsonProcessingException e) {
                    e.printStackTrace();
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
            }
        }
    }
    ```

### 4) 关键场景与演示描述

*   **场景一：模拟数据生成器开发**
    *   **描述**：讲师在 IntelliJ IDEA 中创建了一个 `Mock` 类，并使用 `@Scheduled` 注解设置了一个每 10 秒执行一次的定时任务。
    *   **演示**：讲师通过 `quotaService.list()` 获取预定义的指标信息，然后使用 `for` 循环遍历 10 次，为每次循环生成一个唯一的设备 ID（`1000001` 到 `1000010`），并为每个设备生成一个 0-47 之间的随机指标值。
    *   **技术点**：使用 `Maps.newHashMap()` 构建数据映射，使用 `JsonUtil.serialize()` 将数据序列化为 JSON 字符串，最后通过 `emqClient.publish()` 方法将数据发送到指定的 MQTT 主题。

*   **场景二：后端服务启动与日志验证**
    *   **描述**：讲师在完成代码编写后，点击运行按钮启动 Spring Boot 项目。
    *   **演示**：在控制台中，讲师看到程序成功启动，并且定时任务开始执行，输出了类似 `2020-09-22 21:31:48.181 模拟数据产生` 的日志，证明模拟数据生成器已成功运行。

*   **场景三：HTTP API 接口测试**
    *   **描述**：讲师切换到 Visual Studio Code，打开 `yikong.http` 文件，展示了一系列用于测试后端服务的 HTTP 请求。
    *   **演示**：讲师逐个解释了每个请求的作用，例如如何通过 `PUT` 请求更新设备状态，如何通过 `POST` 请求上报指标数据，以及如何通过 `GET` 请求获取报警趋势和设备详情。
    *   **技术点**：这些请求都包含了 `Authorization` 和 `Content-Type` 头，用于模拟真实客户端的请求。讲师通过这些请求验证了后端服务对设备状态、指标和报警数据的处理能力。
