### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **核心图表**：
    *   **TCC事务流程图**：一个三节点的流程图，包含“应用程序”、“订单系统”和“库存系统”。
    *   **交互流程**：
        *   **Try阶段**：应用程序向订单系统和库存系统发起“检查、预留资源”请求。
        *   **Confirm阶段**：应用程序向订单系统发起“confirm 下单”，向库存系统发起“confirm 减库存”。
        *   **Cancel阶段**：应用程序向订单系统发起“cancel 释放资源”，向库存系统发起“cancel 释放资源”。

*   **关键文字内容**：
    *   **TCC定义**：
        1.  Try：检查及预留业务资源，完成提交事务前的检查，并预留好资源。
        2.  Confirm：确定执行业务操作，对try阶段预留的资源正式执行。
        3.  Cancel：取消执行业务操作，对try阶段预留的资源释放。
    *   **优点**：最终保证数据的一致性，在业务层实现事务控制，灵活性好。
    *   **缺点**：开发成本高，每个事务操作每个参与者都需要实现try/confirm/cancel三个接口。
    *   **幂等性定义**：幂等性是指同一个操作无论请求多少次，其结果都相同。
    *   **实现幂等性的方式**：
        1.  在业务方法中判断是否已执行过。
        2.  缓存所有请求和处理的结果，对已处理的请求直接返回。
        3.  在数据库中增加一个状态字段（未处理，已处理），数据操作时判断未处理时再处理。
