### 1) 视频摘要

本视频课程为“规则引擎 Drools”系列的第五章，主题为“规则属性”。讲师通过演示和代码实例，系统讲解了 Drools 规则文件中五个核心属性的含义、用法及实际效果：
- **5.1 enabled属性**：控制规则是否启用。
- **5.2 dialect属性**：指定规则使用的语言类型（Java 或 MVEL）。
- **5.3 salience属性**：指定规则的执行优先级，数值越大优先级越高。
- **5.4 no-loop属性**：防止因修改 Fact 对象导致的死循环。
- **5.5 activation-group属性**：将规则分组，同组内仅有一个规则可被触发。

讲师通过编写和修改规则文件，并配合 Java 单元测试代码，直观地演示了每个属性对规则执行流程的影响，旨在帮助学习者深入理解规则引擎的控制机制。

### 4) 关键场景与演示描述

*   **场景一：演示 `enabled` 属性**  
    讲师展示了一个规则 `rule_comparison_notMemberOf`，并将其 `enabled` 属性设置为 `false`。通过控制台输出，验证了当 `enabled` 为 `false` 时，该规则不会被触发，从而证明了该属性对规则生命周期的控制作用。

*   **场景二：演示 `salience` 属性**  
    讲师首先展示了一个未设置 `salience` 的规则文件，其中三个规则的执行顺序为由上至下。随后，讲师修改规则文件，为 `rule_2` 设置 `salience 10`，为 `rule_3` 设置 `salience 8`，并为 `rule_1` 设置 `salience 9`。通过控制台输出，清晰地展示了规则执行顺序已按 `salience` 值从大到小排列，即 `rule_2` -> `rule_1` -> `rule_3`，从而验证了 `salience` 属性对执行优先级的控制。

*   **场景三：演示 `no-loop` 属性**  
    讲师编写了一个规则 `rule_noloop`，其中包含一个 `update` 操作。在未设置 `no-loop` 属性的情况下，通过单元测试，控制台输出显示规则被反复触发，形成了死循环。随后，讲师在规则中添加 `no-loop true`，再次运行测试，控制台输出显示规则仅触发一次，成功避免了死循环。

*   **场景四：演示 `activation-group` 属性**  
    讲师编写了两个规则 `rule_activationgroup_1` 和 `rule_activationgroup_2`，并为它们都设置了相同的 `activation-group "mygroup"`。在未设置 `activation-group` 属性的情况下，两个规则都会被触发。讲师通过单元测试，控制台输出显示仅有一个规则被触发，从而验证了 `activation-group` 属性的作用：在同一个分组内，仅允许一个规则被触发。
