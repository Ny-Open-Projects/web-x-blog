### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **核心图表**：
    *   **OAuth2.0 协议流程图**：图中清晰展示了四个核心角色及其交互。
        *   **Resource Owner (资源所有者)**：代表用户，通过客户端（如手机APP）发起认证。
        *   **Client (客户端)**：代表服务网站或应用，负责与用户和授权服务器交互。
        *   **Authorization Server (授权服务器)**：统一认证服务，负责验证用户身份并颁发访问令牌（Access Token）。
        *   **Resource Server (资源服务器)**：后台服务，存储并提供受保护的资源。
    *   **交互流程**：
        1.  Resource Owner 向 Client 发起认证请求。
        2.  Client 将请求发送给 Authorization Server。
        3.  Authorization Server 认证后返回 Access Token。
        4.  Client 使用 Access Token 向 Resource Server 请求资源。
        5.  Resource Server 验证 Token 后返回资源。
        6.  Resource Server 可以通过 JWT 在本地验证，或访问 Authorization Server 验证。

*   **关键文本内容**：
    *   **角色定义**：
        *   `user-agent`: 用户代理，作为资源所有者与客户端沟通的工具，比如APP、浏览器等。
        *   `resources server`: 资源服务器，受保护的资源服务器，具备提供资源能力，如订单服务、商品服务等。
        *   `client`: 客户端，指对资源服务器发起请求的应用程序，如前后端分离项目中的前端。
        *   `authorization server`: 授权服务器，能够给客户端颁发令牌，即统一认证授权服务器。
    *   **授权类型**：
        *   `Authorization Code (授权码模式)`: 先通过认证获取授权码，然后申请 Access Token。
