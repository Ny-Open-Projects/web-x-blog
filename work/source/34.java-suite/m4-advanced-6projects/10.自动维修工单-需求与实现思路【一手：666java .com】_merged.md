    *   **分配**: 系统根据售货机所在区域，将工单分配给区域内“当日分配工单最少”的维修人员。

#### **代码**

*   **早期实现方案 (Java)**:
    *   **方法签名**: `public Integer getLeastUser(String innerCode, Boolean isRepair)`
    *   **步骤 1**: 根据设备编号获取所在区域的维修人员或运营人员列表。
    *   **步骤 2**: 使用 `QueryWrapper` 构建 SQL 查询，按 `assignor_id` 分组统计工单数量。
        *   **条件**: 如果是维修工，查询状态为 `VMSYSTEM_TASK_TYPE_SUPPLY` 的工单；如果是运营人员，查询状态为 `VMSYSTEM_TASK_TYPE_SUPPLY` 且未被取消的工单。
    *   **步骤 3**: 遍历用户列表，查找没有工单的用户。
    *   **步骤 4**: 对所有有工单的用户，按工单数量升序排序，返回第一个（即工单最少的）。

*   **更优方案 (Redis ZSet)**:
    *   **核心思想**: 使用 Redis 的 ZSet 数据结构，其中分数（score）代表工单数量，成员（member）代表人员ID。
    *   **数据结构**: `ZSET`，key 为 `区域_工单类别_时间`。
    *   **初始化**: 由 xxl-job 负责，每日下午2点，将所有人员的工单数初始化为0。
    *   **分配逻辑**: 创建工单时，将人员ID作为成员，工单数作为分数，加入 ZSet。系统只需调用 `ZREVRANGE` 或 `ZRANGE` 获取分数最小的成员即可。
