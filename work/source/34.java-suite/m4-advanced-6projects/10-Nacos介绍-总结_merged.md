### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **PPT 内容：**
    *   **Nacos 简介：** 定义为服务注册发现、配置和管理的开源组件，于 2018 年 7 月开源。
    *   **Nacos 特性：**
        *   **服务发现与服务健康监测：** 支持基于 DNS 和 RPC 的服务发现，提供基于 TCP/HTTP 的健康检查，支持 agent 上报和主动检测两种模式。
        *   **动态配置服务：** 提供 UI 管理服务配置，支持配置版本跟踪、灰度发布、一键回滚等。
        *   **动态 DNS 服务：** 支持更灵活的路由策略和流量控制。
    *   **Nacos 横纵对比：** 一张表格，对比了 Nacos、Eureka、Consul、CoreDNS、ZooKeeper 在一致性协议、健康检查、负载均衡、雪崩保护、自动注册实例、访问协议、监听支持、多数据中心、跨注册中心、SpringCloud 集成、K8s 集成等方面的特性。
    *   **Nacos 架构设计：**
        *   **基本架构图：** 展示了 Provider APP、Name Server、Consumer APP 三者通过 OpenAPI 交互。
        *   **逻辑架构图：** 展示了 Console、SDK、Agent、CLI 通过 OpenAPI 访问核心模块，包括服务管理、配置管理、元数据管理等。
    *   **领域模型设计：**
        *   **数据模型：** Key 由三元组唯一确定，Namespace 默认为空，公共命名空间为 `public`，分组默认为 `DEFAULT_GROUP`。
        *   **服务领域模型：** 服务包含健康检查、元数据、路由机制与阈值保护；集群包含健康检查、元数据和同步机制；实例包含 IP、端口、权重、运行状态、元数据和响应时间。
        *   **配置领域模型：** 主要包含配置变更历史和一个服务标签，通过 ID 关联。
    *   **UML 类视图图：** 展示了 `NacosFactory`、`ConfigFactory`、`NamingFactory`、`NacosConfigService`、`NacosNamingService` 等核心类及其方法。
    *   **服务设计图：**
        *   **配置服务：** 客户端通过 HTTP 访问 Nacos 配置中心获取或修改配置。
        *   **注册服务：** 客户端向 Nacos 注册中心注册服务。
    *   **总结：** 重申了学习目标，包括了解 Nacos 概念、功能、架构设计、工作原理，并学会在项目中整合与验证。
