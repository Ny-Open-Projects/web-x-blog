### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **PPT 图表 1: Reactor 线程模型 (3.8节)**
    *   **结构**：一个 `ServiceHandler`（事件分发器）接收来自多个 `Client` 的事件请求。
    *   **分发**：`ServiceHandler` 将事件分发给多个 `EventHandler`（处理程序），每个 `EventHandler` 运行在独立的“处理线程”中。
    *   **核心概念**：`Reactor` 是一个单线程，负责监听和分发事件；`Handlers` 是处理具体业务逻辑的线程。

*   **PPT 图表 2: Netty 主从 Reactor 多线程模型 (3.9节)**
    *   **结构**：
        *   `client` 连接到 `acceptor`。
        *   `acceptor` 将连接请求分发给 `mainReactor`。
        *   `mainReactor` 将连接请求分发给 `subReactor`。
        *   `subReactor` 负责处理该连接的 IO 读写请求。
        *   `subReactor` 将非 IO 任务（如业务逻辑）放入 `Thread Pool`（线程池）中，由 `worker threads` 处理。
    *   **关键组件**：
        *   `mainReactor`：负责客户端连接。
        *   `subReactor`：负责 IO 读写。
        *   `Thread Pool`：处理非 IO 任务。
        *   `queued tasks`：任务队列。

*   **文字内容**：
    *   **Reactor 模型定义**：`Reactor` 是一个执行 `while (true) { selector.select(); ... }` 循环的线程，会源源不断地产生新的事件，类似反应堆。
    *   **Reactor 模型别名**：也叫 `Dispatcher` 模式。
    *   **Reactor 组成**：
        *   `Reactor`：单线程，负责监听和分发事件。
        *   `Handlers`：处理程序，执行具体的 I/O 事件。
    *   **Netty 主从 Reactor 模型职责**：
        *   `MainReactor`：负责客户端连接请求，并将请求转交给 `SubReactor`。
        *   `SubReactor`：负责相应通道的 IO 读写请求。
        *   `非 IO 请求`：直接写入队列，等待 `worker threads` 处理。
