### 1) 视频摘要

本视频课程旨在演示如何在 Spring Boot 应用中使用 `synchronized` 关键字解决单个 JVM 内的线程安全问题，特别是针对库存扣减场景。课程通过一个简单的 Java 代码示例，展示了在单机环境下，使用 `synchronized` 可以有效防止并发修改导致的库存数据不一致问题。视频还提及了后续将要探讨的分布式锁（如 Redisson）在集群环境下的应用，为后续学习埋下伏笔。

        @Controller
        @RequestMapping("/stock")
        public class StockController {
            @Autowired
            private StringRedisTemplate redisTemplate;
        
            @GetMapping("/stock")
            public String stock() {
                synchronized (this) {
                    int stock = Integer.parseInt(redisTemplate.opsForValue().get("stock"));
                    if(stock > 0) {
                        stock--;
                        redisTemplate.opsForValue().set("stock", stock+"");
                        System.out.println("库存扣减成功，剩余库存：" + stock);
                    } else {
                        System.out.println("库存不足！！！");
                    }
                }
                return "OK";
            }
        }

### 4) 关键场景与演示描述

*   **场景一：单机环境下的并发问题演示**
    *   **描述**: 教师在 IntelliJ IDEA 中展示了一个简单的库存扣减接口。该接口使用 `synchronized (this)` 对代码块进行加锁。通过在控制台连续发送多个请求，演示了在单机环境下，`synchronized` 机制如何确保库存值被正确、有序地递减，从而避免了并发修改导致的“超卖”问题。

*   **场景二：集群环境下的问题引入**
    *   **描述**: 教师切换到 PPT 页面，展示了一个包含 Nginx、两个 Tomcat 实例和一个 Redis 的集群架构图。通过文字说明，指出在集群环境下，每个 Tomcat 实例都运行在独立的 JVM 中，`synchronized` 无法跨 JVM 保证数据一致性，因此需要引入分布式锁（如 Redisson）来解决。

*   **场景三：Redis 数据操作演示**
    *   **描述**: 教师使用 Redis Desktop Manager 工具连接到 Redis 服务器，展示了 `stock` 键的初始值为 `50`。随后，通过在 IDEA 控制台发送请求，观察到 `stock` 键的值被正确地从 50 递减到 37，验证了 `synchronized` 机制在单机环境下的有效性。

*   **场景四：控制台日志观察**
    *   **描述**: 教师在 IDEA 的控制台中展示了多个并发请求的执行日志。日志显示了“库存扣减成功，剩余库存：”的输出，数值从 49 递减到 37，证明了 `synchronized` 语句成功地将并发请求串行化，保证了数据的最终一致性。
