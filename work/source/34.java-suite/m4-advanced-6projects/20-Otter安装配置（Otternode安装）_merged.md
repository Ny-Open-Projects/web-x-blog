### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **PPT 关键内容**:
    *   **章节标题**: “3.6 Otter node”。
    *   **架构图**: 展示了 Otter 的典型系统架构，包含 `manager`、`node` 和 `zookeeper` 三个核心组件。
    *   **组件说明**: `db` (数据源) -> `Canal` -> `node` -> `other` (目标库)。
    *   **功能说明**: `manager` 负责任务配置和调度；`node` 负责数据解析和同步；`zookeeper` 负责分布式协调。
    *   **下一章节预告**: “4. 设置同步任务”，并提示需要创建数据库 `otter_test`。

*   **代码关键内容**:
    *   **解压部署包**:
        ```bash
        cd /opt/otter/
        mkdir node
        tar -zxvf node.deployer-4.2.18.tar.gz -C node/
        ```
    *   **添加 Node 标识符**:
        ```bash
        cd /opt/otter/node/conf/
        echo 1 > nid
        ```
    *   **配置文件 `otter.properties`**:
        ```properties
        # otter node root dir
        otter.nodeHome = ${user.dir}/..

        # otter node dir
        otter.htdocs.dir = ${otter.nodeHome}/htdocs
        otter.download.dir = ${otter.nodeHome}/download
        otter.extend.dir = ${otter.nodeHome}/extend

        # default zookeeper session timeout = 60s
        otter.zookeeper.sessionTimeout = 60000

        # otter communication payload size (default = 8388608)
        otter.communication.payload = 8388608

        # otter communication pool size
        otter.communication.pool.size = 10

        # otter arbitrate & node connect manager config
        otter.manager.address = 127.0.0.1:1099
        ```
    *   **启动 Node 服务**:
        ```bash
        cd /opt/otter/node/bin/
        ./startup.sh
        ```

### 4) 关键场景与演示描述

*   **场景一：部署环境准备**
    *   **描述**: 讲师首先在 Linux 终端中，通过 `cd` 命令进入 `/opt/otter/` 目录，并创建 `node` 文件夹。接着，使用 `tar -zxvf` 命令解压 `node.deployer-4.2.18.tar.gz` 文件，将部署包解压到 `node` 目录下。此步骤为后续配置和启动服务奠定了基础。

*   **场景二：配置 Node 标识符**
    *   **描述**: 讲师进入 `node/conf/` 目录，执行 `echo 1 > nid` 命令。此操作为当前 Node 节点创建了一个唯一的标识符 `nid`，该标识符在 Otter 系统中用于区分不同的工作节点，是节点注册和管理的关键信息。

*   **场景三：配置核心属性文件**
    *   **描述**: 讲师在 `node/conf/` 目录下编辑 `otter.properties` 文件。他重点修改了 `otter.manager.address` 参数，将其值设置为 `127.0.0.1:1099`。这个配置指定了 Node 节点需要连接的 Manager 服务地址和端口，是 Node 节点与 Manager 通信的必要条件。

*   **场景四：启动并验证 Node 服务**
    *   **描述**: 讲师执行 `./startup.sh` 命令启动 Node 服务。在终端中，他通过 `tail -500f /opt/otter/node/logs/node.log` 命令实时查看日志，确认服务已成功启动。随后，他在浏览器中访问 Otter Manager 的 Web 界面，成功看到新注册的 Node 节点（IP 为 `127.0.0.1`，状态为“已启动”），从而验证了部署和配置的正确性。

*   **场景五：过渡到下一阶段**
    *   **描述**: 在确认 Node 节点成功启动后，讲师在 PPT 上切换到“4. 设置同步任务”章节。他提示学员，现在可以开始设置数据同步任务了，但在此之前，需要在源库和目标库中创建名为 `otter_test` 的数据库，为后续的 SQL 语句操作做准备。
