### 1) 视频摘要

本视频片段是关于一个电商系统中“订单支付与出货控制”模块的实现讲解。核心内容是通过分布式锁（Distributed Lock）机制来确保在高并发场景下，同一商品的出货请求只能由一台机器处理，从而避免超卖问题。讲解分为两个主要部分：
1.  **在支付服务端（`OrderController`）添加分布式锁**：在调用微信支付接口前，先获取一个基于商品编码的分布式锁，如果锁获取失败，则抛出异常，提示用户“机器出货中请稍后再试”。
2.  **在售货机服务端（`VendoutMsgHandler`）添加锁的释放逻辑**：在收到微信支付成功的回调后，需要根据订单的唯一标识（`sessionID`）来释放之前获取的分布式锁，以保证锁的生命周期与业务流程一致。

整个实现依赖于 Consul（用于服务发现和注册）和 Redis（用于分布式锁的存储）。

**第一部分：在 `OrderController` 中添加分布式锁**

```java
@PostMapping("/requestPay")
public String requestPay(@RequestBody RequestPay requestPay) {
    // 判断库存
    if (vmService.hasCapacity(requestPay.getInnerCode(),
            Long.valueOf(requestPay.getSkuId()))) {
        throw new LogicException("该商品已售空");
    }

    // 设置微信OpenID
    if (Strings.isNullOrEmpty(requestPay.getOpenId())) {
        requestPay.setOpenId(wxService.getOpenId(requestPay.getJsCode()));
    }

    // 分布式锁，机器同一时间只能处理一次出货
    DistributedLock lock = new DistributedLock(
            consulConfig.getConsulRegisterHost(),
            consulConfig.getConsulRegisterPort());
    DistributedLock.LockContext lockContext = lock.getLock(requestPay.getInnerCode(), 60);
    if (lockContext.isLock()) {
        throw new LogicException("机器出货中请稍后再试");
    }

    // 存入redis是为了释放锁
    redisTemplate.boundValueOps(WSYSTEM_VM_LOCK_KEY_PREF + requestPay.getInnerCode())
            .set(lockContext.getSessionId(), Duration.ofSeconds(60));

    String responseData = orderService.requestPay(requestPay);
    if (Strings.isNullOrEmpty(responseData)) {
        throw new LogicException("微信支付接口调用失败");
    }
    return responseData;
}
```

**第二部分：在 `VendoutMsgHandler` 中添加锁释放逻辑**

```java
@Override
public void process(String jsonMsg) throws IOException {
    boolean success = JsonUtil.getTreeNodeByName("success", jsonMsg).asBoolean();
    if (!success) return;
    VendoutResp vendoutResp = JsonUtil.getByJson(jsonMsg, VendoutResp.class);
    if (Strings.isNullOrEmpty(vendoutResp.getInnerCode())) return;
    vmService.vendoutResult(vendoutResp);

    // 解锁售货机状态
    DistributedLock lock = new DistributedLock(
            consulConfig.getConsulRegisterHost(),
            consulConfig.getConsulRegisterPort());
    String sessionId = redisTemplate.boundValueOps(WSYSTEM_VM_LOCK_KEY_PREF + vendoutResp.getInnerCode()).get();
    lock.releaseLock(sessionId);
}
```

#### 关键概念

*   **分布式锁 (Distributed Lock)**: 用于在分布式系统中保证同一资源在同一时间只能被一个节点访问。
*   **Consul**: 服务发现和配置管理工具，用于获取服务的注册信息。
*   **Redis**: 用于存储锁的状态，实现锁的释放。
*   **`lock.getLock(...)`**: 获取锁，参数为锁的唯一标识（商品编码）和超时时间（60秒）。
*   **`lock.isLock()`**: 判断锁是否已被占用。
*   **`lock.releaseLock(...)`**: 释放锁，参数为锁的唯一标识（sessionID）。
