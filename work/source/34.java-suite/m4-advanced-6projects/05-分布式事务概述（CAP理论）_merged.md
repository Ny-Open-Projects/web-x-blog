### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **核心图表**：
    *   **架构图**：一个中心为“Nginx”的树状结构，下方连接三个节点：节点A（用户数据）、节点B（用户账户）、节点C（用户产生）。该图用于说明分布式系统中数据的分布和CAP理论的场景。
    *   **顶部示意图**：展示了“订单系统”和“库存系统”分别连接各自的“订单数据库”和“库存数据库”，并最终合并为“同一个数据库，存储订单，库存”，用于引出CAP理论的背景。

*   **关键文字内容**：
    *   **CAP理论定义**：分布式系统在设计时只能在一致性（Consistency）、可用性（Availability）、分区容忍性（Partition Tolerance）中满足两种，无法兼顾三种。
    *   **一致性（Consistency）**：服务A、B、C三个结点都存储了用户数据，三个结点的数据需要保持同一时刻数据一致性。
    *   **可用性（Availability）**：服务A、B、C三个结点，其中一个结点宕机不影响整个集群对外提供服务，增加服务B、C是为了保证系统的可用性。
    *   **分区容忍性（Partition Tolerance）**：分布式系统不可避免地会出现网络分区，数据需要复制到多个节点。
    *   **CAP组合方式**：
        1.  **CA**：放弃分区容忍性，加强一致性和可用性，关系数据库按照CA进行设计。
        2.  **AP**：放弃一致性，加强可用性和分区容忍性，追求最终一致性，很多NoSQL数据库按照AP进行设计。
        3.  **CP**：放弃可用性，加强一致性和分区容忍性，一些强一致性要求的系统按CP设计。
    *   **最终总结**：在分布式系统设计中，即保证分区容忍性和可用性，牺牲强一致性。例如：订单退款，今日退款成功，明日账户到账，只要在预定的用户可以接受的时间内退款事务走完即可。
