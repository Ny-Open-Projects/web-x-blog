### 1) 视频摘要

本视频课程讲解了 EMQ X Broker 中的 WebHook 插件功能。主要内容包括：
- **功能概述**：WebHook 是一个允许 EMQ X 将内部事件（如客户端连接、消息发布等）通过 HTTP 请求转发到外部 Web 服务的机制。
- **工作原理**：EMQ X Broker 作为中间件，将事件通过 `emqx_web_hook` 插件，以 HTTP 请求的形式发送给指定的 Web 服务器。
- **配置方法**：通过编辑配置文件 `etc/plugins/emqx_web_hook.conf` 来设置 WebHook 的行为，包括目标服务器地址 (`api.url`) 和消息体编码方式 (`encode_payload`)。
- **事件触发规则**：支持多种事件类型（如 `client.connect`, `message.publish` 等），用户可以通过配置规则来精确控制哪些事件被转发。
- **实践演示**：视频通过在 EMQ X 的管理界面中启用插件，并在终端中查看和编辑配置文件，展示了如何实际配置和使用 WebHook。

### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

#### PPT 内容

- **工作流程图**：
  - **组件**：Client → EMQ X Broker → `emqx_web_hook` → HTTP Request → Web Server。
  - **说明**：WebHook 对事件的处理是单向的，仅将 EMQ X 中的事件转发给 Web 服务，不关心 Web 服务的返回。

- **配置文件 `emqx_web_hook.conf`**：
  - **配置项**：
    - `api.url`：字符串类型，指定目标 Web 服务的地址，默认值为 `http://127.0.0.1:8080`。
    - `encode_payload`：枚举类型，可选值为 `base64` 或 `base64`，默认值为 `undefined`。用于对消息体进行编码，以便在 HTTP 协议中传输。

- **事件触发规则**：
  - **格式**：`web.hook.rule.<Event>.<Number> = <Rule>`
  - **示例**：
    ```json
    web.hook.rule.message.publish.1 = {"action": "on_message_publish", "topic": "a/b/c"}
    web.hook.rule.message.publish.2 = {"action": "on_message_publish", "topic": "foo/#"}
    ```
  - **支持的事件**：
    - `client.connect`：处理连接报文。
    - `client.connack`：下发连接应答。
    - `client.connected`：成功接入。
    - `client.disconnected`：连接断开。
    - `client.subscribe`：订阅主题。
    - `client.unsubscribe`：取消订阅。
    - `session.subscribed`：会话订阅主题。
    - `session.unsubscribed`：会话取消订阅。
    - `message.publish`：消息发布。
    - `message.delivered`：消息投递。
    - `message.acked`：消息回执。
    - `message.dropped`：消息丢弃。

#### 代码/终端内容

- **终端命令**：
  ```bash
  # 进入 EMQ X 容器
  docker exec -it emqx /bin/sh

  # 查看配置文件
  cat /etc/plugins/emqx_web_hook.conf
  ```

- **配置文件内容**：
  ```ini
  # Web services URL for hook request
  value string
  web.hook.api.url = http://127.0.0.1:8080

  # Encode message payload field
  value base64 | base64
  web.hook.encode_payload = base64

  # Hook Rules
  # These configuration items represent a list of events should be forwarded
  web.hook.rule.client.connect.1 = {"action": "on_client_connect", "topic": "a/b/c"}
  web.hook.rule.client.connected.1 = {"action": "on_client_connected", "topic": "foo/#"}
  ```
