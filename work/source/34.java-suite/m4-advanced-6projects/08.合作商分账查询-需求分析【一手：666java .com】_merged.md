好,接下来我们来学习第三小节的内容,合作商分账查询,首先我们看一下需求信息,在管理后台中有这么一个功能,就是能够查询每一个合作商在每一天给整个公司带来的收入,以及他发生的订单数,另外还有就是他应该分得的那部分的分成收益。

那么下面就是一个效果图,那么这个时候我们可以看到,我们可以指定条件,就是对我们的结果进行一个筛选,可以指定某一个合作商在某一个时间范围通过这种方式来进行查询。

当然如果说你不指定合作商,那么他查询的其实就是所有的合作商。

那么具体这样功能怎么做呢?咱们看一下实现思路。

那么首先这个数据呢是来自于我们的订单数据是吧?

但是订单表非常大,

如果说我们对订单表进行一个聚合统计,是吧?

那这个功能是能实现,但是效率太低。

所以说我们在第二小节的时候,我们通过一个定时任务,做了一个订单数据的汇总,把它汇总到了这个什么呢?

叫TB Order Collect,这么一个表中,对吧?

而这个表中呢,它其实就记录着每一个合作商在每一天的这么一个收益,包括期到什么程度呢?

就是说每一个合作商每一个点位,他每一天的收益。

而这个上面的数据是什么呢?是每一个合作商的收益。

而每个合作商又包括了很多点位是吧?

所以说这里的这个收入比数和分成几乎上,其实并不是这个表直接的数据。

而是什么呢?而是要对这个表再次的来进行聚合统计。

但是你要想啊,这个表其实比订单表已经小很多了是吧?

所以说你对这个小表进行聚合统计。

那性能上呢,就不会很差了啊。

但如果你对订单表进行聚合,那这个就很慢了。

所以说呢,这是我们大体一个思路哈,其实就是对这个订单的这个合并表啊,来进行再次的来进行聚合。
