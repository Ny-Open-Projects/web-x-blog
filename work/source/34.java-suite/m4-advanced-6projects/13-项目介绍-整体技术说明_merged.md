### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **架构图 (Architecture Diagram)**：
    *   **分层结构**：清晰展示了从“接入层”到“基础服务层”的五层架构。
    *   **接入层**：包含 LVS、NGINX、KEEPALIVED，用于负载均衡和高可用。
    *   **业务服务层**：基于 Spring Boot + Spring Cloud Gateway，支持自定义路由。
    *   **交易服务层**：采用 Netty NIO，内部通信使用 gRPC+PB。
    *   **服务注册与配置**：Nacos 集群，MariaDB 作为数据源。
    *   **中间件层**：包含 Redis、MongoDB、ElasticSearch、XXL-JOB、Seata Server 等组件。
    *   **基础服务层**：包含 API 服务、配置中心、日志服务等。

*   **关键文本内容**：
    *   **接入层技术**：采用 LVS+NGINX+KEEPALIVED，实现负载均衡与高可用。
    *   **业务服务**：集成 Spring Cloud Gateway，支持自定义路由转发，支持 OAUTH2 权限。
    *   **交易服务**：采用高效 Netty NIO 接入，内部采用高性能的 gRPC+PB 方式通讯。
    *   **服务注册与统一配置**：采用 Nacos 集群，以 MariaDB 作为数据源，Nginx 作负载。支持服务的注册发现与统一配置管理。
    *   **应用层与通信技术**：
        *   采用 Spring Boot Starter gRPC + ProtoBuf 实现，gRPC 通讯性能高于 HTTP 的 Feign，PB 数据效率高于 JSON。
        *   采用 Netty 作为长连接的 NIO 框架，处理交易数据与行情数据，因为交易数据存在异步特征，以及行情数据的高度特征，使用高效的 NIO 框架加上长连接的方式更为合适。
    *   **中间件**：
        *   **Redis集群**：三主三从集群部署模式，支持更多数据量及灵活扩展，同时保障高可用。主要处理用户数据、产品数据等热点信息。
        *   **MongoDB集群**：对于高频次存取，同时要保障数据的持久化，MongoDB 相比传统 DB 更为合适。主要负责支付信息日志以及二次加工数据的处理。
        *   **Ceph分布式文件存储**：强一致性，保障数据的可靠，基于此特征，适合金融交易平台，主要处理一些小文件，比如用户证明文件，图像，验证码等信息。
        *   **ElasticSearch集群**：在搜索方面目前有最为广泛的应用及优越的性能表现，主要处理用户点信息，登陆操作日志行为等搜索功能。
        *   **XXL-JOB分布式任务调度框架**：轻量级分布式任务调度平台，核心设计目标是开发迅速、学习简单、轻量级、易扩展。适合处理异步任务，回调任务，返回任务，统计报表等。
        *   **Seata Server (Fescar)**：分布式事务框架，阿里开源组件，用于微服务架构的分布式事务解决。特点是高性能且易于使用，代码侵入性低，底层采用 Netty 实现，负责处理交易服务与业务服务之间的事务处理。
