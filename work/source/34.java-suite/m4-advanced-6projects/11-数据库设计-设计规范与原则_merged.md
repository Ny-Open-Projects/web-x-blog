### 1) 视频摘要

本视频课程为“数据库设计规范与模型”章节的讲解，主要聚焦于数据库设计的**命名与表设计规范**，以及后续的**数据库设计原则**。讲师通过在 Typora 文档编辑器中逐条展示和讲解规范内容，强调了在项目中建立有效规范的重要性。内容覆盖了命名规范（如表名、索引名的命名规则）、表设计规范（如引擎选择、字段类型、索引策略）以及核心设计原则（如避免在数据库中做运算、控制字段数量、拒绝大事务等），旨在帮助学习者构建清晰、高效、可维护的数据库架构。

*   **3.3 命名与表设计规范 (00:00:00 - 00:00:05)**
    *   **1. 命名规范 (00:00:00 - 00:00:03)**
        *   命名需有意义。
        *   数据库和表名均使用小写。
        *   数据库示例：`backend`。
        *   数据表示例：`client_device_info`（客户端设备信息）。
        *   索引命名以 `idx_` 为前缀。
        *   命名不宜过长（建议少于25字符）。
        *   不要使用保留字。
        *   同一字段在不同表中类型和长度应一致。
        *   同一数据库下不同模块的表可使用不同前缀标识。
        *   备份表需加上时间标识。
    *   **2. 表设计规范 (00:00:03 - 00:00:08)**
        *   建议选择 `InnoDB` 引擎。
        *   每个表应有主键，可选自增字段或长整型字段。
        *   可使用复合主键（如用户编号+交易商编号）。
        *   **(不做强制要求)** 尽量将字段设置为 `NOT NULL`，因 `NULL` 值占用额外空间且影响优化。
        *   使用更短的列（如整型）。
        *   存储精确浮点数必须使用 `DECIMAL` 代替 `FLOAT` 和 `DOUBLE`。
        *   建议使用 `unsigned` 类型存储非负值。
        *   建议使用 `int unsigned` 存储 `ipv4`。
        *   整型定义中不添加显示长度，使用 `int` 而非 `int(4)`。
        *   尽可能不要使用 `text`、`blob` 类型。
        *   `varchar(n)` 中 `n` 表示字符数，非字节数（如 `varchar(255)` 最大可存255个汉字）。
        *   字符集建议选择 `utf-8`。
        *   存储年份时使用 `year` 类型。
        *   存储日期时使用 `date` 类型。
        *   存储时间时，建议使用 `timestamp` 类型（4字节），`datetime` 为8字节。
        *   不要在数据库中使用 `varbinary` 或 `blob` 存储图片及文件。
        *   `join` 操作的字段在不同表中的类型和命名需一致。
        *   如果更改表结构会影响性能，需DBA和表设计人员联合评审。

*   **3.4 数据库设计原则 (00:00:08 - 00:00:15)**
    *   **1. 核心原则 (00:00:08 - 00:00:10)**
        *   **不在数据库做运算**，CPU计算务必移至业务层。
        *   控制每个表的列数量（字段少而精），字段数建议在20以内。
        *   平衡范式与冗余（效率优先，往往牺牲范式）。
        *   拒绝3B：拒绝大SQL语句（`big sql`）、拒绝大事务（`big transaction`）、拒绝大批量（`big batch`）。
    *   **2. 字段类型原则 (00:00:10 - 00:00:12)**
        *   用好数值类型（用合适的字段类型节约空间）。
        *   字符串转化为数字（能转化的最好转化），同样节约空间、提高查询性能。
        *   避免使用 `NULL` 字段（`NULL` 字段很难查询优化，`NULL` 字段的索引需要额外空间，`NULL` 字段的复合索引无效）。
        *   少用 `text` 类型（尽量使用 `varchar` 代替 `text` 字段）。
    *   **3. 索引类原则 (00:00:12 - 00:00:14)**
        *   合理使用索引（改善查询，减慢更新，索引一定不是越多越好）。
        *   字符字段大量重复属性时，尽量建前缀索引（如 `alter table x_test add index(x_city(6))`）。
        *   不在索引做列运算。
        *   `InnoDB` 主键推荐使用自增列（主键建聚簇索引，主键不应该被修改，字符串不应该做主键）。
        *   **不用外键**（由程序保证约束）。
    *   **4. SQL类原则 (00:00:14 - 00:00:15)**
        *   SQL语句尽可能简单（一条SQL只能在一个CPU运算，大语句拆分小语句，减少锁时间，一条大SQL可以堵死整个库）。
        *   避免使用触发器、函数（采用程序取而代之）。
        *   大批量SQL的更新操作要开启事务，越多效果性能越明显。

### 3) 出现的 PPT / 公式 / 图表 / 代码的关键内容

*   **PPT / 文档内容**：

        *   **SQL类原则**：SQL语句简单、避免触发器函数、大批量更新开事务。
