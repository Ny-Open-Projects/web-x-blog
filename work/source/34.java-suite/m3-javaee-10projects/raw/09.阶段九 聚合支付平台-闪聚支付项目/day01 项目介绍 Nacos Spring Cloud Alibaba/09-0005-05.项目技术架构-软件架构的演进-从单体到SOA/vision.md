画面1：
- 标题：2 项目的技术架构
- 子标题：2.1 软件架构的演进
- 内容：软件架构的发展经历了从单体架构、垂直架构、SOA架构到微服务架构的过程。
- 子标题：2.1.1 单体架构
- 内容：Web应用程序发展的早期，大部分web工程师将所有的功能模块打包到一起并放在一个web容器中运行，所有功能模块使用同一个数据库。
- 图形：单体架构系统图，包含“订单管理”、“商品管理”、“用户管理”模块，指向“电子商务数据库”。

画面2：
- 内容：特点：
  1. 所有的功能集成在一个项目工程中。
  2. 所有的功能打在一个war包部署到服务器。
  3. 通过部署应用集群和数据库集群来提高系统的性能。
- 内容：优点：
  1. 项目架构简单，前期开发成本低，周期短，小型项目的首选。
  2. 开发效率高，模块之间采用本地方法调用。
  3. 容易部署，运维成本小，直接打包为一个完整的包，拷贝到web容器的某个目录下即可运行。

画面3：
- 图形：单体架构系统图，包含“订单管理”、“商品管理”、“用户管理”模块，指向“电子商务数据库”。

画面4：
- 标题：2.1.2 分布式架构
- 内容：针对单体架构的不足，为了适应大型项目的开发需求，许多公司将一个单体系统按业务垂直拆分为若干系统，系统之间通过网络交互来完成用户的业务处理，每个系统可分布式部署，这种架构称为分布式架构。
- 图形：分布式架构图，包含“电子商务”、“CRM系统”、“物流系统”三个子系统，分别连接各自的数据库，并通过箭头表示系统间的数据交互。

画面5：
- 内容：特点：
  1. 按业务垂直拆分成一个一个的单体系统，此架构也称为垂直架构。
  2. 系统与系统之间的存在数据冗余，耦合性较大，如上图中三个项目都存在客户信息。
  3. 系统之间的接口多为实现数据同步，如上图中三个项目要同步客户信息。
- 内容：优点：
  1. 通过垂直拆分，每个子系统变成小型系统，功能简单，前期开发成本低，周期短。
  2. 每个子系统可按需伸缩。

画面9：
- 标题：2.1.3 SOA架构
- 内容：SOA是一种面向服务的架构，基于分布式架构，它将不同业务功能按服务进行拆分，并通过这些服务之间定义良好的接口和协议联系起来。
- 图形：SOA架构图，包含“电子商务”、“CRM系统”、“物流系统”三个子系统，通过“web service”连接到“ESB企业服务总线”，再连接到“用户管理服务”、“单点登录服务”、“XX服务”，并连接到各自的数据库。

画面10：
- 内容：特点：
  1. 基于SOA的架构思想，将重复公用的功能抽取为组件，以服务的方式向各系统提供服务。
  2. 各个系统与服务之间采用webservice、rpc等方式进行通信。
  3. ESB企业服务总线作为系统与服务之间通信的桥梁。
- 内容：优点：
  1. 将重复的功能抽取为服务，提高开发效率，提高系统的可用性、可维护性。
  2. 可以针对不同服务的特点按需伸缩。
  3. 采用ESB减少系统中的接口耦合。

画面11：
- 内容：缺点：
  1. 系统与服务的界限模糊，会导致抽取服务的程度过大，系统与服务之间耦合性高。
  2. 虽然使用了ESB，但是服务的接口协议不固定，种类繁多，不利于系统维护。
