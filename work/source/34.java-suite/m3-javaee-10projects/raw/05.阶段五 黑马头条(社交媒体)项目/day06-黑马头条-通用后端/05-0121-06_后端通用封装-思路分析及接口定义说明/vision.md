标题：2.2 实现思路
- 【持久层】：通过动态SQL或者SQL拼接方式，实现通用的持久层
- 【业务层】：
  - 定义操作权限类，控制数据表的基本操作权限（是否允许CRUD），每次操作之前都需要检查此表
  - 每次操作之前都需检查当前登录人员是否有此功能操作权限（此步要与RBAC进行基础，此例不做实现）
  - 参数校验（比如更新时需要查询条件）
  - 参数合法性校验（放置SQL注入）
  - 前置处理逻辑通用（前置结果可影响程序的继续执行，此例作为练习内容，在此步实现）
  - 数据持久化操作
  - 后置处理逻辑通用（后置结果可影响返回结果）
  - 返回结果

标题：3 通用封装-定义
- 3.1 接口定义
  - 通用操作功能，主要实现CRUD的功能：
    - 列表接口：用户加载数据表分页数据，并提供字段搜索功能
    - 删除接口：用于删除满足条件的某行数据（考虑安全，每次操作只能删除一条数据）
    - 修改和删除接口：用于新增和修改数据表数据
