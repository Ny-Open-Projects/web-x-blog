1) 这一组画面整体在讲Elasticsearch中文档路由的计算原理，即如何通过哈希算法确定文档存储在哪个分片节点上。

2) 按时间顺序列出每张画面的要点：
画面1：
- 展示了“2.5.1. 路由”章节内容。
- 图表结构：文档数据 → 集群 → node01 (M)、node02、node03。
- 文档数据指向集群，集群分发到三个节点，其中node01标注为“M”，表示主分片。
- 文档数据旁有红色文字：“我该存储到哪里？”。
- 文字说明：“如图所示：当我们想一个集群保存文档时，文档该存储到哪个节点呢？是随机吗？是轮询吗？”
- 文字说明：“实际上，在Elasticsearch中，会采用计算的方式未确定存储到哪个节点，计算公式如下：”
- 代码公式：`shard = hash(routing) % number_of_primary_shards`
- 代码说明：`routing`值是一个任意字符串，默认是_id但也可以自定义。
- 代码说明：`这个routing字符串通过哈希函数生成一个数字，然后除以主切片的数量得到一个余数(remainder)，余数的范围永远是0到number_of_primary_shards - 1，这个数字就是特定文档所在的分片。`
- 文字说明：“这就是为什么创建了主分片后，不能修改的原因。”
