## 二、画面线（屏幕 / PPT / 代码，VLM 抽帧抄录）

1) 这一组画面整体在讲什么（一句话）：
本课程系统讲解了MySQL数据库集群的多种架构方案，包括读写分离、中间件（MyCat）、负载均衡（HAProxy）和PXC集群，并最终介绍如何部署混合架构。

2) 按时间顺序列出每张画面的要点，标注它对应的画面序号：
画面1：
- 标题：课程介绍
- 内容：分析当前系统架构中的数据库扩展存在的问题；分析MySQL数据库的集群方案；学习主从复制（读写分离）架构方案；掌握MyCat数据库中间件的使用；掌握HAProxy负载均衡的使用；多种集群架构的综合应用。
- 图表：系统架构图，包含ELK、Redis、MySQL（主）、MySQL（从）、Apache Dubbo、DB Server等组件。

画面2：
- 标题：2、MySQL数据库的集群方案
- 内容：在我们的系统架构中，DBServer方面只是使用了单节点服务，如果面对大并发、海量数据的存储，显然单节点的系统架构存在很严重的问题，所以接下来，我们将实现MySQL的集群，来应对大并发、海量数据存储等问题。
- 图表：架构图，显示了MySQL（主）和MySQL（从）通过同步连接，中间有Apache Dubbo和DB Server。

画面3：
- 标题：2.1、读写分离架构
- 内容：我们一般应用对数据库而言都是“读多写少”，也就说对数据库读取数据的压力比较大，有一个思路就是说采用数据库集群的方案。其中一个主库，负责写入数据，我们称之为：写库；其它都是从库，负责读取数据，我们称之为：读库。
- 要求：1. 读库和写库的数据一致；2. 写数据的须写到写库。

画面4：
- 标题：从该系统架构中，可以看出：
- 内容：数据程序需要连接到多个节点提供服务；主节点数据，同步到从节点数据；应用程序需要连接到2个数据库节点，并且在程序内部实现判断读写操作。
- 问题：这种架构存在2个问题：1. 应用程序需要连接到多个节点，对应应用程序而开发变得复杂；2. 主从之间的同步，是异步完成，也就意味着这是“弱一致性”。
- 图表：架构图，显示了MySQL（主）和MySQL（从）通过同步连接，中间有写操作和读操作。

- 标题：2.4、PXC集群架构
- 内容：在前面的架构中，都是基于MySQL主从的架构，那么在主从架构中，“弱一致性”问题依然没有解决，如果在需要强一致性的场景下，显然这种架构是不能应对的，比如：交易数据。
- 图表：架构图，显示了MySQL（主）和MySQL（从）通过同步连接，中间有PXC。

- 内容：在前面的PXC架构中，虽然可以实现了事务的一致性，但是它是通过牺牲了性能换来的一致性，如果在某些业务场景下，如果没有强一致性要求，那么使用PXC就不合适了，所以在我们的系统架构中，需要将这两种方式结合起来，这样才是一个较为完整的架构。

  2. Docker volume create haoke-v2
  3. Docker volume create haoke-v3

画面14：
- 标题：部署PXC集群
- 内容：部署了2个PXC集群节点，作为2个Mycat分片，每个PXC集群中有2个节点，作为数据的同步存储；部署了1个主从复制节点，其余数据保存到PXC分片中。
- 命令：
  1. Docker create -p 13306:3306 -v /var/lib/mysql -e MYSQL_ROOT_PASSWORD=root -e CLUSTER_NAME=pxc --name=pxc_node3 --net=pxc_network --ip=172.30.0.4 pxc
  2. Docker create -p 13306:3306 -v /var/lib/mysql -e MYSQL_ROOT_PASSWORD=root -e CLUSTER_NAME=pxc --name=pxc_node4 --net=pxc_network --ip=172.30.0.5 pxc
  3. Docker start pxc_node1 && Docker logs pxc_node1
  4. Docker start pxc_node2 && Docker logs pxc_node2
  5. Docker start pxc_node3 && Docker logs pxc_node3
  6. Docker start pxc_node4 && Docker logs pxc_node4
  7. #查看集群节点
  8. show status like 'wsrep_cluster%';
- 结果：2个集群，4个节点，均已启动成功。
