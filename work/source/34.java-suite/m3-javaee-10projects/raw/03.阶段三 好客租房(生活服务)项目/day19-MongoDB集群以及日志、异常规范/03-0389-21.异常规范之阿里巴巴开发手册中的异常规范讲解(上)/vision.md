1) 这一组画面整体在讲什么（一句话）：
讲解阿里巴巴Java开发手册中关于“异常处理”的强制性规范，包括如何正确使用try-catch、避免异常用于流程控制、区分稳定与非稳定代码的异常处理、事务中的异常处理、finally块的使用规范等。

2) 按时间顺序列出每张画面的要点，标注它对应的画面序号：
画面1：展示“异常处理”章节第1条强制规范：Java类库中定义的一类RuntimeException可以通过预检查进行规避，而不应该通过catch来处理，比如：IndexOutOfBoundsException, NullPointerException等。说明：无法通过预检查的异常除外，如在解析一个外部传来的字符串形式数字时，通过catch NumberFormatException来实现。正例：if (obj != null) {...} 反例：try { obj.method() } catch (NullPointerException e) {...}

画面5：新增第6条强制规范：finally块必须对资源对象、流对象进行关闭，有异常也要做try-catch。说明：如果jdk7及以上，可以使用try-with-resources方式。
画面6：新增第7条强制规范：不能在finally块中使用return，finally块中的return返回后方法结束执行，不会再执行try块中的return语句。
画面7：新增第8条强制规范：捕获异常与抛异常，必须是完全匹配，或者捕获异常是抛异常的父类。说明：如果预期对方抛的是球，实际接到的是铅球，就会产生意外情况。
画面8：新增第9条推荐规范：方法的返回值可以为null，不强制返回空集合，或者空对象等，必须添加注释充分说明什么情况下会返回null值。调用方需要进行null判断防止NPE问题。说明：本手册明确防止NPE是调用者的责任。即使被调用方法返回空集合或者空对象，对调用者来说，并非高危无忧，必须考虑到远程调用失败、序列化失败、运行时异常等场景返回null的情况。
