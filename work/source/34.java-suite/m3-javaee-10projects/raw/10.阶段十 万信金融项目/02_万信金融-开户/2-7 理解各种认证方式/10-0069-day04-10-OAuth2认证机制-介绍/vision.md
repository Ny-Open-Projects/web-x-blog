画面 9: PPT 标题为“OAuth2.0 授权流程”，流程图结构如下：
- Client (黑马技术论坛) → (A) Authorization Request → Resource Owner (小王)
- Resource Owner (小王) → (B) Authorization Grant → Authorization Server (QQ认证服务器)
- Authorization Server (QQ认证服务器) → (C) Authorization Grant → Client (黑马技术论坛)
- Client (黑马技术论坛) → (D) Access Token → Authorization Server (QQ认证服务器)
- Authorization Server (QQ认证服务器) → (E) Access Token → Resource Server (QQ资源服务器)
- Resource Server (QQ资源服务器) → (F) Protected Resource → Client (黑马技术论坛)

画面 13: PPT 标题为“在咱们P2P项目中，引入OAuth2.0的主要目的”，内容为：
- 客户端(Client): 第三方应用，本身不存在资源，需要通过资源拥有者程序去请求资源服务器的资源。本例中指的是黑马技术论坛。
- 资源拥有者(Resource Owner): 通常为用户，也可以是应用程序，即该资源的拥有者。本例指的是小王。对访问资源进行授权，授权后会给出资源访问令牌(access_token)，作为客户端访问资源服务器的凭证。本例指的是QQ为用户提供OAuth2.0授权机制，而专门搭建的认证服务器。
- 资源服务器(Resource Server): 服务提供商专有生成的资源的服务器。本例指的是QQ用于存放用户数据的服务器。
