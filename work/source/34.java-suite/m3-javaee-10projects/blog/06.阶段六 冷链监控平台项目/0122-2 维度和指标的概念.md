# 维度与指标：图表两组字段的分法，冷链监控里的对照

产品经理一句「按仓库看一下这周温度」，落到图表配置界面就是两组字段的选择：仓库放进分组框，温度放进数值框。选错了组，图能画出来但数字对不上需求。维度与指标这对概念在任何可视化工具里都躲不开，把它们的分法想透，后面 Superset 的每一个配置项才都有判断依据。

## 先给结论

- 维度是事物或现象的某种特征，回答「从哪个角度看数据」：性别、地区、时间都是维度，主机、仓库、公司在冷链监控里也是维度。
- 维度按数据类型分定性（字符型，如地区）与定量（数值型，如收入、年龄），定量维度要做数值分组离散化，分组越细规律越不明显，细到原始流水就无规律可循。
- 指标是衡量事物发展程度的单位或方法，IT 领域常称度量：可以是基本属性，也可以由求和、平均等加工计算得出汇总指标。
- 指标分绝对数（反映规模大小，如用户数、收入）与相对数（反映质量好坏，如利润率、留存率），评价事物要数量与质量两大方面、横比纵比全方位比较。
- 映射到工具：Druid 查询的 `dimensions` 与 `aggregations`、SQL 的 `GROUP BY` 字段与聚合函数、Superset 的 Dimensions 与 Metrics，说的都是同一组概念。

## 维度：看数据的切分角度

维度这个字面意思就是「方面」。评价任何一件事，先问从哪些方面看，这些方面就是维度。性别是维度、地区是维度、时间是维度，它们都是数据的特征属性，本身不参与大小计算，只负责把数据切开分组。

时间是一种常用又特殊的维度，它的特殊性在于支撑纵比：用户数环比上月增长 10%，同比去年同期增长 20%，都是拿当前时间和过去比，同一个事物跨时间的对比，看的是发展趋势。与之相对的是横比，把同一时间点上的不同对象并排放：不同国家的人口数与 GDP、不同省份的收入与用户数、不同公司与部门之间的比较。纵比看自己变好还是变坏，横比看自己在群体里排第几，两个方向合起来，结论才有说服力。

落到冷链监控平台，维度俯拾皆是：主机名、仓库、公司、设备编码，还有采集时间。查报警记录时按仓库过滤、按公司汇总，用的全是维度。

## 定性与定量：维度分两种，数值维度要离散化

按数据类型分，维度有定性定量两种。字符型的是定性维度，如地区、性别、业务线，值本身就是类别标签。数值型的是定量维度，如收入、年龄、消费能力，值有大小可运算。

定量维度直接拿来分组往往没法看，几万个工资数值能切出几万个组，这时要做数值分组处理，也就是离散化：把收入划成三千以下、三千到五千、五千到一万这样几档。离散化的目的是让规律更明显。分组的粗细直接决定图表可读性：分组越细，每组样本越少，规律越不明显；一路细下去到最原始的流水数据，就彻底无规律可循了。所以做图时的分档数是一个权衡，太粗丢信息，太细变噪音。

冷链数据里同样有这个转折：温度本身是可运算的数值，直接当维度用会碎成无数个组；但把它划成低温、合规、超温三个区间之后，区间就成了定性维度，可以统计每个区间里有多少设备、哪个仓库超温最频繁。原始值是指标，分箱后的区间是维度，一个字段两种身份，取决于有没有先做离散化。

## 指标：衡量发展程度的单位或方法

指标回答的是「在这个方面，用什么数来体现」。人口数量、GDP、收入、用户数、利润率、留存率都是指标，很多公司把它们里最关键的几个组织成 KPI 指标体系，用来衡量经营状况。

指标有两个来源：一是基本属性，数据里天生就带着的列，如设备上报的温度原值；二是加工计算，对基本指标做求和、平均、计数得出汇总或聚合指标，如平均温度、告警次数。图表里看到的多数数字其实是第二类，聚合发生在查询阶段。

按反映的内容再分两类：绝对数指标反映规模大小，人口数、GDP、用户数、收入都算，回答「有多大」；相对数指标反映质量好坏的程度，利润率、留存率这一类，回答「好不好」。只看绝对数会误判，用户量涨了留存率却在跌，增长是在漏水的桶里倒水；数量与质量两大方面、横比与纵比两个方向全方位比较，才能全面判断事物发展的好坏。

用银行风控的例子把两者合起来看。银行判断哪些客户可以贷款，从多个维度审视这个人：收入水平、年龄、是否有车、是否有房、所在地区、甚至身边朋友的信用状况，这些是维度。每个维度上再看指标：月收入落在三千到五千这个档的人违约率是多少，五千到八千、一万到两万、五万到十万各档的违约率呈现什么趋势。维度定位人群，指标给出量化结论，组合起来就是一张可执行的风控画像。

## 在 Druid 与 Superset 里的对应

概念落到工具上是同一件事的三个说法。一条 groupBy 查询里（示例，按 Druid 常用写法补全，表名沿用平台数据表）：

```json
{
  "queryType": "groupBy",
  "dataSource": "all_device_message",
  "granularity": "day",
  "dimensions": ["hostname", "housename"],
  "aggregations": [
    {"type": "max", "name": "max_tem", "fieldName": "tem"},
    {"type": "min", "name": "min_tem", "fieldName": "tem"},
    {"type": "count", "name": "sample_count"}
  ],
  "intervals": ["2026-11-01/2026-11-08"]
}
```

`dimensions` 数组里放维度，`aggregations` 数组里放指标的算法，等价的 SQL 一眼能对上：

```sql
SELECT hostname, housename,
       MAX(tem) AS max_tem,
       MIN(tem) AS min_tem,
       COUNT(*) AS sample_count
FROM all_device_message
WHERE __time >= TIMESTAMP '2026-11-01 00:00:00'
  AND __time <  TIMESTAMP '2026-11-08 00:00:00'
GROUP BY hostname, housename
```

`GROUP BY` 后面的是维度，聚合函数算出来的是指标。Superset 图表配置里的 Dimensions 与 Metrics 两个选项，分别接住这两组。定量维度离散化在 SQL 里就是一个 CASE 表达式（示例）：

```sql
SELECT CASE WHEN tem < 2 THEN '低温'
            WHEN tem <= 8 THEN '合规'
            ELSE '超温' END AS tem_band,
       COUNT(DISTINCT metercode) AS device_count
FROM all_device_message
WHERE __time >= CURRENT_TIMESTAMP - INTERVAL '1' DAY
GROUP BY CASE WHEN tem < 2 THEN '低温'
              WHEN tem <= 8 THEN '合规'
              ELSE '超温' END
```

冷链平台常用地段的字段判定可以整理成一张速查表：

| 字段或口径 | 角色 | 判定理由 |
|---|---|---|
| hostname 主机名 | 维度 | 特征属性，回答按谁分组 |
| housename 仓库名 | 维度 | 同上，横比的基本单位 |
| curtime 采集时间 | 维度 | 常用特殊维度，支撑纵比趋势 |
| tem 温度原值 | 指标 | 可聚合可比较的数值 |
| 平均温度、最高温度 | 指标 | 由原值加工出的聚合指标 |
| 告警次数 | 指标 | 计数得到的相对规模的汇总指标 |
| 温度区间（低温、合规、超温） | 维度 | 定量维度离散化后的定性标签 |

```mermaid
flowchart LR
    RAW["原始流水数据"] --> DIM["按维度分组 主机 仓库 时间"]
    DIM --> MET["组内按指标聚合 最高温度 平均湿度 告警次数"]
    MET --> CHART["图表"]
    CHART --> DASH["看板"]
```

这张图把两个概念的位置钉死：维度管从流水里切出组，指标管在每组里算出一个数，图表与看板消费的都是聚合后的结果。

## 常见误区

- **把温度原值直接拖进维度。** 错例：按温度值分组看设备数，出图碎成几十个点。正解：温度是定量数据，先分箱成区间再做维度，或把它放指标框里做聚合。
- **认为维度越多图表越细越好。** 错例：一次按公司、仓库、主机、设备、分钟五层分组。正解：分组越细越接近原始流水，规律反而被稀释，维度层数以能回答业务问题为度。
- **只看绝对数指标下结论。** 错例：本周告警数比上周多，就断言设备劣化。正解：相对数要跟上，告警数除以在线设备数算比率，再横比各仓库，才能区分是设备劣化还是监控覆盖变多。
- **把聚合前的值当聚合后的指标讨论。** 错例：拿单条快照的温度说「仓库平均温度超标」。正解：指标是聚合的产物，先明确聚合方式与时间范围，再引用数值。

## 面试可能被问到的问题

1. 面试官追问：「维度和指标到底怎么区分？」
   答：维度是事物或现象的特征，回答从哪个角度看数据，用来切分分组；指标是衡量发展程度的单位或方法，回答这个方面表现如何，用来聚合计算。一句话验证：能放进 GROUP BY 的是维度，要套聚合函数的是指标。
2. 面试官追问：「定量维度为什么要离散化，不分会怎样？」
   答：数值型维度的取值太多，直接分组会碎成海量小组，每组样本极少，规律被稀释到最原始的流水状态。离散化把数值划成有限区间，让规律重新显现，分档粗细是信息量与可读性的权衡。
3. 面试官追问：「绝对数指标和相对数指标有什么区别，为什么都要看？」
   答：绝对数反映规模，如用户数、收入；相对数反映质量，如利润率、留存率。只看绝对数会误判增长质量，比如用户量上涨而留存率下滑；数量与质量两大方面结合，横比纵比全方位比较，结论才全面。
4. 面试官追问：「Druid 的 dimensions 和 aggregations 对应可视化里的什么？」
   答：对应图表配置里的维度与指标两个概念。dimensions 决定按哪些字段分组，aggregations 决定组内做什么聚合，Superset 的 Dimensions 与 Metrics 下拉框就是这两个概念的产品化表达。
5. 面试官追问：「在冷链监控里举一个维度加指标的组合例子。」
   答：主机是维度、温度是指标。按主机名分组，组内对温度求最大值、最小值和平均值，再加告警次数这一计数指标，就得到每台主机的当日温度画像；把主机换成仓库就是仓库对比，换成时间窗就是温度趋势。
