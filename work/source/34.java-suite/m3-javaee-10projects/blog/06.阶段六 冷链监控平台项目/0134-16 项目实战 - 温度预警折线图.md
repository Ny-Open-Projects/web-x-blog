# Superset 温度预警折线图：从配置到嵌进 Vue 页面

数据已经在 Apache Druid 里躺了两天（day7 用 cold-druid 工程做过查询统计），可统计接口再快也不如一张图直观。传统做法要写按仓库按小时分组的接口，前端再接一层 ECharts；Superset 给出的路径是配置即出图，再把图嵌回冷链监控平台的前端页面。这一课把平台的第一个图表完整走一遍：需求拆成维度与指标，图表配置逐项落定，iframe 贴进工程，浏览器里看到曲线。

## 先给结论

- 需求按仓库维度查看每小时的预警数量，拆成三件事：分组字段是仓库，时间粒度是 1 小时，指标是 count 计数。
- 数据源选 Druid 的 all_device_message，图表类型选 Line Chart（折线图），时间范围选 No filter 不做限制。
- 只统计有告警的记录：过滤条件 temalert 不等于 0；字段取值 1 是高温预警、-1 是低温预警、0 是正常。
- 分组先用 housecode（仓库编码）出图，页面可读性差，换成 housename（仓库名）重新拷贝一次 iframe；序列限制设为 5。
- 出图后点 iframe 按钮拷贝嵌入代码（宽 1000 高 400），贴进前端 dashboard/index.vue 的对应位置，dev server 自动编译，浏览器刷新即见曲线。

## 一、需求先拆成维度与指标

「按仓库维度查看每小时预警数量」这句话里有三个配置项。查看角度是仓库，对应分组字段；时间切到小时，对应时间粒度；统计对象是预警条数，对应 count 指标。维度与指标的拆法在前几课已经铺垫过，这里第一次把它落到真实的告警数据上。

预警数量的口径靠 temalert 字段实现。这个标记在 day6 实时计算阶段就写进了数据：0 表示正常，1 表示高温预警，-1 表示低温预警。所以统计预警不是把所有记录数一遍，而是只数 temalert 不等于 0 的记录。落到 SQL，图表配置最终执行的查询口径长这样（示例按本课写法补全，与图表界面上的配置一一对应）：

```sql
-- 仓库维度、每小时粒度的温度预警计数
SELECT TIME_FLOOR(__time, 'PT1H') AS hour_bucket,
       housename,
       COUNT(*)                   AS alert_count
FROM all_device_message
WHERE temalert <> 0
GROUP BY TIME_FLOOR(__time, 'PT1H'), housename
```

先在 SQL 层把口径钉死有个好处：图表向导里每一项配置都能找到对应位置，出图后数字对不对、和预期差在哪，一眼能对出来。

## 二、图表配置逐项落定

进入 Superset 管理页（课程环境访问宿主机 7088 端口，admin/admin123 登录），在 Charts 页点加号新建图表。整条配置链路画成一张图：

```mermaid
flowchart LR
    A["新建 chart"] --> B["数据源 all_device_message"]
    B --> C["图表类型 Line Chart"]
    C --> D["时间粒度 1 hour 范围 No filter"]
    D --> E["指标 count"]
    E --> F["过滤 temalert 不等于 0"]
    F --> G["分组 housecode 序列限制 5"]
    G --> H["run query 预览曲线"]
    H --> I["保存命名 仓库温度预警折线图"]
```

逐项说。数据源选 all_device_message，这是 day7 已经接进来的 Druid 数据源，界面里不用再改。图表类型选 Line Chart，折线看趋势。时间粒度选 1 hour，需求里的「每小时」就是它；时间范围选 No filter，把库里的历史数据全部纳入。指标选 count，数每组的记录条数。过滤条件用简易表达式：subject 选 temalert，operator 选不等于，comparator 填 0。分组字段选 housecode；序列限制（Series Limit）控制返回的分组个数，课程环境仓库不多，填 5 足够。

点 run query，曲线当场出来。演示数据集中在最近一段时间，曲线呈急速下降的形态，形态本身取决于库里的告警分布，不影响流程。给图表起名「仓库温度预警折线图」，点 Save 保存，这张图在 Superset 侧就完成了。

## 三、iframe 贴回前端页面

图留在 Superset 里还不够，要进冷链监控平台的工作台。图表右上角有嵌入按钮，点开就是一段现成的 iframe 代码，拷贝前把宽度改成 1000、高度改成 400：

```html
<!-- 主机地址以 example.com 占位，课程环境访问宿主机 7088 端口 -->
<iframe
  width="1000"
  height="400"
  seamless
  frameBorder="0"
  scrolling="no"
  src="http://example.com:7088/superset/explore/?form_data=%7B%22datasource%22%3A%22all_device_message%22%2C%22viz_type%22%3A%22line%22%7D"
>
</iframe>
```

src 指向的是 Superset 的 explore 页，form_data 参数里序列化了数据源与图表类型，浏览器加载 iframe 时按这份配置向 Superset 请求渲染。嵌入位置在前端工程的 dashboard/index.vue，也就是工作台页面，把代码贴到温度预警折线图的占位区域：

```html
<div class="disFlex">
  <div class="cont" style="height:450px;">
    <div class="title">仓库温度预警折线图</div>
    <div class="content">
      <!-- 上面拷贝的 iframe 贴在这里 -->
    </div>
  </div>
</div>
```

保存文件后，前端 dev server（npm 启动的 Node.js 服务）监测到改动自动重新编译，编译完成浏览器刷新，折线图就出现在工作台页面上。

这时暴露一个展示问题：X 轴分组显示的是 housecode，即仓库编码，看图的人很难把编码和仓库对应起来。回到 Superset 把分组字段换成 housename（仓库/主机名），保存后重新 run query，确认曲线按仓库名展示，再重新拷贝一次 iframe 覆盖前端里的旧代码。前端再次自动编译，页面上的每条曲线就有了可读的仓库名。项目真实工程里正是这么拼的：cold-chain-ui 的工作台页与统计报表页，最终都是一块块这样的 iframe 组出来的。

## 四、口径背后的三个细节

**第一，可视化层只做筛选，不重新判警。** temalert 是接入与计算链路（Netty 采集、Flink 流计算）写好的标记，Superset 的过滤条件只是把告警记录挑出来计数。判警阈值变化时改的是计算侧，图表不需要动。

**第二，维度字段选编码还是名称，取决于图的读者。** housecode 适合程序内部关联，housename 适合给人看。分组字段一旦确定，统计口径随之确定，换成名称后每组含义直观，代价是名称变化（仓库改名）会影响分组稳定性。

**第三，iframe 是配置的序列化而不是截图。** explore 页每次加载都按 form_data 里的配置向 Superset 现查现画，数据更新后前端无需重发版；代价是样式定制受限于 Superset 的渲染，深度定制要回到图表配置或二次开发。

## 常见误区

- **把告警标记当数值聚合。** 错例：指标选 SUM(temalert)，正负相加数字毫无意义。正解：temalert 是标记字段，指标用 count，配合过滤条件不等于 0。
- **分组直接用编码上线。** 错例：housecode 出图后直接交付，轴上是仓库 ID。正解：对外展示换 housename，编码只用于内部关联。
- **时间范围沿用默认值。** 错例：没核对时间范围，图里只有默认窗口的数据。正解：需求要全量历史就选 No filter，要当天就选当天，配置与需求逐字对齐。
- **Superset 改完配置不动前端。** 错例：换了分组字段，页面还显示旧图。正解：重新拷贝 iframe 覆盖旧代码，等 dev server 编译完再刷新页面。

## 面试可能被问到的问题

1. 面试官追问：「按仓库看每小时预警数量，在 Superset 里怎么配？」
   答：维度与指标三件套：分组字段选仓库（housename），时间粒度选 1 hour，指标选 count；过滤条件 temalert 不等于 0 只统计告警记录，时间范围按需求选 No filter。这套配置对应的 SQL 就是按小时截断时间、按仓库分组计数。
2. 面试官追问：「告警过滤为什么是不等于 0，不是等于 1？」
   答：告警标记有三个值，1 高温预警、-1 低温预警、0 正常。等于 1 会漏掉低温预警；不等于 0 把两类告警都收进来，先看总量，需要细分时再按标记值拆两条过滤。
3. 面试官追问：「Superset 的图怎么进自研前端？」
   答：图表保存后通过 iframe 嵌入，src 指向 Superset 的 explore 页，form_data 参数序列化了数据源与图表配置，页面加载时由 Superset 现查现画。改图表配置只需重新拷贝 iframe，前端不用改逻辑；代价是样式定制受限于平台渲染。
4. 面试官追问：「维度用 housecode 还是 housename，怎么权衡？」
   答：编码稳定、适合内部关联，名称可读、适合展示。给业务看的图选名称；需要跨表关联或担心改名影响分组时用编码。也可以在数据集层建立编码与名称的映射，图表统一用编码、展示时翻译成名称。
5. 面试官追问：「为什么不直接写统计接口加 ECharts？」
   答：固定口径的高频图表写接口没有问题；但告警这类需求经常调整维度、粒度与过滤条件，Superset 配置即改即生效，业务人员也能自助出图，把开发排期省下来。两条路径按需求稳定度取舍。
