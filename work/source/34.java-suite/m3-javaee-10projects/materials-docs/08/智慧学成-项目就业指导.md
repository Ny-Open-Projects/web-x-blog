4 数据仓库是如何设计的 ?  
4.1 数据仓库分层  
项目中采集的数据分层如下图所示 :

<!-- page 4 -->
ODS : 
 ODS 层是数据运营层 , 即与采集的原始数据对应。 
DW : 
 DW 层是数据仓库层 , 存储经过清洗后的数据、初步数据聚合后的数据、为业务层需求存储的宽表数
据。此层有又分为三层 :
DWD : 存储明细数据，此数据是最细粒度的事实数据。
DWM : 存储中间数据，为数据统计需要创建的中间表数据，此数据一般是对多个维度的聚合数
据，此层数据通常来源于 DWD 层的数据。
DWS : 存储宽表数据，此层数据是针对某个业务领域的聚合数据，业务层的数据通常来源与此层，
为什么叫宽表，主要是为了业务层的需要在这一层将业务相关的所有数据统一汇集起来进行存储，
方便业务层获取。此层数据通常来源与 DWS 层的数据。
APP : 
 APP 层是业务层 , 存储业务层所需要的数据，如：分析数据、查询数据等。
Dimension:
 Dimension 层是维度层 , 存储所有维度数据，维度数据是共用数据 , 通常会被 DW 层使用
 
4.2 数据仓库分区  
基本数据仓库的分层 , 每层又按照时间分区 ( 年、月、日 ) 存储 , 这样的好处是 :  能够还原历史时间点上的
产品状态、用户状态、用户行为等，以便于能更好的回溯历史，分析历史，跟踪用户的历史行为
 
4.3 数据仓库存储  
项目数据仓库采用 Hive, 存储在 HDFS 上，  数据存储也采集用了不同格式：
1. TEXTFILE ：文本格式，主要用于存储维度数据
2. PARQUET ：是以二进制方式存储的，支持嵌套的数据模型，  主要用于存储 DW 层数据， 
3. ORC ：也是以二进制方式存储，支持事务，不支持嵌套数据格式，主要用于存储采集 MySQL 的数
据。

6.1 数据抽取  
 数据抽取是从数据源采集需要的原始数据，抽取的方式多种多样，要根据数据源的特点来确定，通常
有如下几种数据抽取的方式：
1 、从关系数据抽取数据
通常 OLTP 系统采用关系数据库存储业务操作数据，从关系数据库抽取操作型数据是最多一种数据抽取
方式。
数据从关系数据库抽取后通常会先以文件的方式存储到分布式文件系统中（例如 HDFS ），方便 ETL 程序
读取原始数据。也有的是将抽取后的数据直接存储到数据仓库中，采用第二种方法需要提前在数据仓库
创建与原始数据相同结构的数据仓库模型。
2 、从日志文件抽取
 OLTP 系统通过日志系统将用户的操作日志、系统日志等存储在 OLTP 服务器上，由专门的采集程序从服
务器上采集日志文件信息。
3 、从数据流接口抽取
OLTP 系统提供对外输出数据的接口（比如 telnet ），采集系统与该接口对接，从数据流接口抽取需要的
数据。
 
6.2 数据转换  
数据转换也叫数据清洗转换，是将采集过来的原始数据（通常原始数据存在一定的脏数据）清洗（过
虑）掉不符合要求的脏数据，根据数据仓库的要求对数据格式进行转换，经过数据清洗转换后是符合数
据仓库要求的数据。
要清洗的脏数据的形式有：

<!-- page 7 -->
1 、错误的数据
存在数据内容错误的信息，比如学生选课信息中课程标识错误或选课日志非法等。
2 、不完整的数据
是指信息不完整，比如学生选课信息中缺少学生或缺少课程的信息，这类信息是不符合学生选课数据模
型的要求。
3 、重复数据
第三类数据是要根据具体的业务进行单独去重操作，比如：同一个课程学习会话中只允许有一条学习记
录，这里就要根据会话 ID 对数据进行去重操作。
 
数据转换的形式有：
1 、数据格式转换
对数据的格式进行转换，通常转换后数据内容是不变的，比如：数据仓库要求的日期存储格式是
yyyymmdd ，而采集过来的数据格式是 yyyy-mm-dd ，这里需要将 yyyy-mm-dd 的格式转换为
yyyymmdd 。
2 、数据内容转换
对数据内容进行转换，通常数据内容转换后是不会改变原始数据内容的意义的，比如：数据仓库要求存
储用户所在区域，这里就需要根据采集过来的用户 IP 地址从 IP 库中查找出用户的 IP 地址所对应的区域信
息，这里根据 IP 地址转换为区域就是数据内容的转换。
 
6.3 数据加载  
数据加载就是清洗转换后的数据存储到数据仓库中，数据加载的方式包括：全量加载、增量加载。
全量加载：
全量加载相当于覆盖加载的方式，每个加载都会覆盖原始数据将数据全部加载的数据仓库，此类加载方
式通常用于维度数据。
增量加载：
增量加载按照一定的计划（通常是时间计划）逐步的将数据一批一批的将数据加载到数据仓库，此类加
载方式通常用于 OLTP 的业务操作数据。
 
 
7 离线分析是如何实现的  
 离线分析是今天分析前一天数据 ,  使用 SparkCore 和 SparkSQL 实现 , 以下是每个指标的实现逻辑
 
7.1 课程访问量  
 课程访问量完整流程如下 : 
1. 数据采集 :

<!-- page 8 -->
用户访问业务系统产生课程访问行为数据
JS 埋点将数据发送到采集系统
采集系统将数据发送到 Kafka
自定义 Kafka-Connecter 将数据持久化到 hdfs
2. 数据清洗 :
SparkCore 根据日期读取 hdfs 上的用户访问数据
使用 map 和 ﬁlter 算子对数据进行过滤去重
过滤后的关联相关维度 , 得到事实表基础数据 , 数据格式为 RDD
RDD 数据转换为 DataFrame
DataFrame 数据使用 SparkSQL 保存到数据仓库 ( 课程访问量事实表中  )
3. 数据统计分析 :
SparkSQL 根据日期读取数据清洗得到的事实表数据
计算当前日期范伟内课程访问量
计算后的数据使用 SparkSQL 保存到数据仓库 ( 课程访问量业务表中  )
4. 落到业务库 :
使用 NiFi 读取数据仓库中统计分析的业务数据
读取的数据转换 MySQL 可以识别格式
将数据保存到业务 MySQL 中
 
7.2 课程购买量  
课程购买量完整流程如下 : 
1. 数据采集 :
使用 NiFi 监控 MySQL 的 binlog 
NiFi 过滤 binlog 中的订单数据
NiFi 将订单数据保存到数据仓库中
2. 数据清洗 :
SparkSQL 根据日期读取数据仓库中的订单数据
关联相关维度 , 得到事实表基础数据
使用 SparkSQL 保存到数据仓库 ( 课程购买量事实表中  )
3. 数据聚合 :
SparkSQL 根据日期读取数据仓库中的课程购买量数据
根据课程 id 进行轻度聚合 , 得到这个课程当天的课程购买量
使用 SparkSQL 保存到数据仓库 ( 课程购买量 DWM 层  )
4. 数据统计分析 :
SparkSQL 根据日期读取数据仓库中课程购买量 DWM 层数据
计算当前日期范伟内课程购买量
计算后的数据使用 SparkSQL 保存到数据仓库 ( 课程购买量业务表中  )
5. 落到业务库 :
使用 NiFi 读取数据仓库中统计分析的业务数据
读取的数据转换 MySQL 可以识别格式
将数据保存到业务 MySQL 中

8 同比分析在项目中的应用  
 同比: 即同期相比，表示某个特定统计段今年与去年之间的比较。例 :   比如 2009 年中国第一季度 GDP
为 G9 亿元，则 2010 年第一季度的 GDP 同比增长为（ G10-G9 ） / G9 。
项目中热门学科排名这个指标中计算了销售额、销售量、学生人数的增幅 , 采用同比的方式进行计算 , 分
别是同比比较 : 年、月、周 
 环比：表示连续 2 个统计周期内的量的变化比。
