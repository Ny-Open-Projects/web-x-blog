1.1 数据仓库概念  
数据仓库概念创始⼈在《建⽴数据仓库》⼀书中对数据仓库的定义是：数据仓库（ Data Warehouse ）
是⼀个⾯向主题的（ Subject Oriented ）、集成的（ Integrated ）、相对稳定的（ Non-Volatile ）、反
映历史变化（ Time Variant ）的数据集合，⽤于⽀持管理决策 (Decision Making Support) 。
数据仓库是⽤于决策⽀持系统如下图，决策⽀持系统基于数据仓库进⾏联机分析处理  ( OLAP ) 。常⽤的
技术有， HDFS 、 HBase 、 Hive 、 Spark 等。

1.3 数据仓库的特点  
1.3.1 ⾯向主题  
理解主题的概念可以和数据库应⽤系统对⽐理解，数据库应⽤是以业务内容来划分应⽤程序和数据库，
⽐如 ERP （ Enterprise Resource Planning ）包括：进销存系统、⼈⼒资源管理系统、财务管理系统、
仓库管理系统等，进销存系统管理了进货、销售、存储等业务流程，⼈⼒资源系统管理了员⼯的信息、
待遇等相关信息；数据仓库是以数据分析需求来对数据进⾏组织划分若⼲主题，⽐如销售主题、员⼯主
题、产品主题，主题是⼀个抽象的概念，可以理解为相关数据的分类、⽬录等，通过销售主题可以进⾏
销售相关的分析，如年度销量排⾏、⽉度订单量统计等。
总之，主题是以分析需求为导向来组织数据，数据库应⽤系统是以业务流程为导向来组织数据，注意：
主题中的数据是跨应⽤系统的。
 
1.3.2 数据集成  
主题中的数据是跨应⽤系统的，也就是说数据是分散在各各应⽤系统，⽐如销售数据在进销存系统中
有，财务系统中也有，为了进⾏销售分析需要将销售数据进⾏集成，集成在销售主题中，就可以从销售
主题来进⾏数据分析。
1.3.3 ⾮易失  
数据库应⽤系统是根据业务需求进⾏数据处理和存储，⽽数据仓库是根据数据分析需求来进⾏数据存
储，数据仓库中的数据⽤于查询和分析，为了保证数据分析的准确性和稳定性，数据仓库中的数据⼀般
是很少更新的。
1.3.4 时变

<!-- page 3 -->
数据仓库中的数据存储的是历史数据，历史数据是随时间变化的，⽐如历年的销售数据都会存储到数据
仓库中，即使数据仓库中的数据很少更新，但也不能保证没有变化，如下需求：
1 ）会不断添加新数据
每年的销售数据会逐渐添加到数据仓库。
2 ）删除过期数据
数据仓库中的数据会保存很⻓的时间（ 5--10 年），但也有过期时间，到过期  时间会删除过期  数据。
3 ）对历史明细数据进⾏聚合
为了⽅便数据分析，根据分析需求会将⽐较细粒度的数据进⾏数据聚合存储，这也是时变的⼀种表现，
⽐如：为了⽅便统计年度销售额会将销售记录按⽉进⾏统计，统计年度销售额时只需要针对⽉度销售结
果进⾏统计即可。
 
2 维度分析  
2.1 指标与维度  
要进⾏维度分析需要先理解两个术语：指标和维度。指标是衡量事物发展的标准，也叫度量，如价格，
销量等；指标可以求和、求平均值等计算，指标分为绝对数值和相对数值，绝对数值反映具体的⼤⼩和
多少，如价格、销量、分数等；相对数值反映⼀定的程度，如及格率、购买率等。
维度是事物的特征，如颜⾊、区域、时间等，可以根据不同的维度来对指标进⾏分析对⽐。⽐如根据区
域维度来分析不同区域的产品销量，根据时间来分析每个⽉产品的销量，同⼀个产品销量指标从不同的
维度分析会得出不同的结果。维度分为定性和定量两种，定性维度就是字符类型的特征，⽐如区域维度
包括全国各省份；定量维度就是数值类型的特征，如价格区间、销量区间等，如价格区间维度分为 0-
-100 、 100-1000 两个区间，可以按价格区间维度来对指标进⾏分析，说到这⾥，其实指标是可以转成
维度的，所转成的维度就是定量维度。

3.1 常⻅的建模⽅法  
1. 星型模型：是⼀种多维的数据关系，它由⼀个事实表和⼀组维度表组成。每个维度表都有⼀个维作为
主键，所有这些维的主键组合成事实表的主键。强调的是对维度进⾏预处理，将多个维度集合到⼀个事
实表，形成⼀个宽表。如下图所⽰ :
2. 雪花模型：当有⼀个或多个维表没有直接连接到事实表上，⽽是通过其他维表连接到事实表上时，就
像多个雪花连接在⼀起，故称雪花模型。雪花模型是对星型模型的扩展。它对星型模型的维表进⼀步层
次化，原有的各维表可能被扩展为⼩的事实表，形成⼀些局部的  " 层次  " 区域，这些被分解的表都连接

3.2 数据分层⽅法  
1 ） ODS 层  -- 数据运营层
ODS （ Operational Data Store ）层数据是原始业务操作数据，即与采集的原始数据对应，数据经过初
步过虑后存储到 ODS 层。
2 ） DW 层  -- 数据仓库层
DW （ Data Warehouse ）存储经过清洗后的数据、初步数据聚合后的数据、为业务层需求存储的宽表
数据。
此层分为三层：
DWD （ Data Warehouse Detail ）：存储明细数据，此数据是最细粒度的事实数据。
DWM （ Data WareHouse Middle ）：存储中间数据，为数据统计需要创建的中间表数据，此数据⼀般
是对多个维度的聚合数据，此层数据通常来源于 DWD 层的数据。
DWS （ Data WareHouse Service ）：存储宽表数据，此层数据是针对某个业务领域的聚合数据，业务
层的数据通常来源与此层，为什么叫宽表，主要是为了业务层的需要在这⼀层将业务相关的所有数据统
⼀汇集起来进⾏存储，⽅便业务层获取。此层数据通常来源与 DWS 层的数据。
3 ） APP 层  -- 业务层
存储业务层所需要的数据，如：数据分析、数据查询等。
4 ） Dimension 维度层
存储所有维度数据，通常维度数据会 DW 层使⽤，也可能被多个主题库所共⽤。

3.3 数据仓库分层  
3.3.1 空间换时间  
通过建设多层次的数据模型供⽤⼾使⽤，避免⽤⼾直接使⽤操作型数据，可以更⾼效的访问数据。把复
杂问题简单化。讲⼀个复杂的任务分解成多个步骤来完成，每⼀层只处理单⼀的步骤，⽐较简单和容易
理解。⽽且便于维护数据的准确性，当数据出现问题之后，可以不⽤修复所有的数据，只需要从有问题
的步骤开始修复。便于处理业务的变化。随着业务的变化，只需要调整底层的数据，对应⽤层对业务的
调整零感知。

<!-- page 9 -->
3.3.2 分层的价值  
1. 易维护 清晰数据结构：每⼀个数据分层都有它的作⽤域，这样我们在使⽤表的时候能更⽅便地定
位和理解
2. ⾼性能 数据仓库的构建将⼤⼤缩短获取信息的时间，数据仓库作为数据的集合，所有的信息都可
以从数据仓库直接获取，尤其对于海量数据的关联查询和复杂查询，所以数据仓库有利于实现复杂
的统计需求，提⾼数据统计的效率。
3. 简单化 讲⼀个复杂的任务分解成多个步骤来完成，每⼀层只处理单⼀的步骤，⽐较简单和容易理
解。⽽且便于维护数据的准确性。
4. 存档 记录历史是数据仓库的特性之⼀，数据仓库能够还原历史时间点上的产品状态、⽤⼾状态、
⽤⼾⾏为等，以便于能更好的回溯历史，分析历史，跟踪⽤⼾的历史⾏为，更好地⽐较历史和总结
历史，同时根据历史预测未来。
