# 022 CREATE USER 取代隐式建账号

> 分类：用户管理 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**CREATE USER** / **GRANT 隐式建用户** / **5.7 分界**
> 原文锚点：第 42~51 段「在 MySQL 5.7 之前的版本中我们可以使用 grant 命令在为用户授权的同时来建立一个用户，而 5.7 之后则不再推荐」

## 一句话总述
5.7 之前可以**用 GRANT 顺手建出用户**（隐式创建），5.7 起必须**先 `CREATE USER` 再 `GRANT`**；**8.0 已移除**隐式建账号能力。

## 面试官视角
- **考察意图**：看你的操作习惯停留在哪个版本。
- **P5** 知道建账号用 `CREATE USER`。
- **P6** 能说清 5.7 是分界点，8.0 已不支持隐式建用户。
- **P7** 能顺带说出 `CREATE USER` 可一并指定认证插件、过期、历史密码、连接数限制。
- **红旗**：① 张口就是"用 GRANT 建用户"；② 以为 `CREATE USER` 不能带账户属性。
- **惊艳点**：5.7 用 `sql_mode=NO_AUTO_CREATE_USER` 就能**禁掉 GRANT 隐式建用户**，8.0 直接移除 `[经验]` —— 验证：`SELECT @@sql_mode;` 与 8.0 上对不存在的用户 GRANT 观察报错。

## 主问答
**Q（面试官原话）：** 现在要新建一个应用账号，步骤是什么？能不能用 GRANT 一步到位？

**A：**
1. **结论**：标准做法是**先 `CREATE USER` 再 `GRANT`** 两步；不推荐（8.0 上也不支持）用 GRANT 隐式建账号。
2. **机制**：5.7 之前 GRANT 对不存在的用户会顺带创建；**8.0 已移除该行为**。
3. **边界**：`CREATE USER` 只建**零权限空账号**；8.0 下它还能一次指定认证插件、密码过期、历史策略、每小时连接数。

**加分层**：两步走的价值是**账号与权限生命周期解耦**——改权限不必动账号密码，审计更清晰。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| ≤ 5.6 | GRANT 可隐式创建用户 | 老版本答"能用但不推荐" |
| 5.7 | 不推荐，`NO_AUTO_CREATE_USER` 可禁 | 答"应改两步走" |
| 8.0 | 隐式建用户**已移除** | 统一答：CREATE USER → GRANT |

## 关键代码
```sql
CREATE USER 'app'@'192.168.1.%'
  IDENTIFIED WITH caching_sha2_password BY 'Pwd#2026a'
  PASSWORD EXPIRE INTERVAL 90 DAY
  PASSWORD HISTORY 5
  MAX_CONNECTIONS_PER_HOUR 1000;
GRANT SELECT, INSERT, UPDATE, DELETE ON appdb.* TO 'app'@'192.168.1.%';
```

## ⚠️ 原文纠错
原文说"5.7 之后不再推荐"用 GRANT 建用户——**更准确的说法是 8.0 起该能力已被移除**，5.7 只是不推荐，此处按官方事实补全。机翻音译（current、createuser、mysk 五点七）已还原为 GRANT、CREATE USER、MySQL 5.7。

## 总结与追问预判
- 两步走：**CREATE USER → GRANT**；8.0 不能再隐式建。
- `CREATE USER` 建出来的是**零权限空账号**。
