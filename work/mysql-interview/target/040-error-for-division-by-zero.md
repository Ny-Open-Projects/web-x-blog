# 040 ERROR_FOR_DIVISION_BY_ZERO

> 分类：服务器配置 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**ERROR_FOR_DIVISION_BY_ZERO** / **除零** / **警告**
> 原文锚点：第 159~171 段「严格模式下当除数为零时结果为空同时会产生一个 warning，而非严格模式下结果依然为空但并不会产生警告」

## 一句话总述
`ERROR_FOR_DIVISION_BY_ZERO` 让**除数为 0 时产生警告**（在严格模式下更进一步可视为错误）；不开则**结果同样是 NULL，但一声不吭**。

## 面试官视角
- **考察意图**：考的是"静默失败比报错更危险"这个意识，而不是除零本身。
- **P5** 知道 MySQL 除零返回 NULL。
- **P6** 能说出严格/宽松下**结果相同、是否告警不同**。
- **P7** 能指出 8.0 中该值与严格模式配合时，**除零会直接报错**（`ERROR 1365`），而不是只警告。
- **红旗**：① 以为除零在 MySQL 里会直接崩；② 说"开了这个值结果就不一样了"（结果都是 NULL）；③ 不看 warnings。
- **惊艳点**：关键差异**不是结果而是有没有警告**——结果都是 NULL `[实测]` —— 验证：两种模式下 `SELECT 1/0;` 均返回 NULL，仅严格模式 `SHOW WARNINGS` 有 "Division by 0"。

## 主问答
**Q（面试官原话）：** 我有个报表 SQL 里做了除法，除数可能是 0，MySQL 会怎么处理？

**A：**
1. **结论**：不开 `ERROR_FOR_DIVISION_BY_ZERO` 时，除零**返回 NULL 且不产生任何警告**——业务看到的是空值，没人知道出错了。
2. **机制**：开启后除零**产生警告**；与**严格模式**配合时进一步升级为**错误**（语句失败）。
3. **边界**：注意结果集层面 `1/0` 恒为 NULL，**两种模式的结果一致**，差别只在是否告警/报错——所以排查这类问题必须主动 `SHOW WARNINGS`。

**加分层**：写报表 SQL 更稳妥的做法是**用 `NULLIF(除数,0)` 显式处理**，不依赖 sql_mode 兜底。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.7 / 8.0 | 该值**默认包含**在默认 sql_mode 中 | 现在按"默认已开启、严格模式下会报错"答 |

## 关键代码
```sql
SET SESSION sql_mode = 'ANSI';
SELECT 1/0;          -- NULL，无警告
SHOW WARNINGS;       -- 空
SET SESSION sql_mode = 'STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO';
SELECT 1/0;          -- NULL + 警告；严格下写表可升级为 ERROR 1365
SELECT 1/NULLIF(0,0);-- 防御写法：显式返回 NULL
```

## ⚠️ 原文纠错
原文说"严格模式下产生警告、宽松模式下无警告"——与 MySQL 行为一致。补充原文未展开的一点：在 8.0 的严格模式下，**数据修改语句**中的除零会**直接报错**而非仅警告，卡面已补充该边界。机翻音译（errorfordivisionbydeal、running）已还原为 ERROR_FOR_DIVISION_BY_ZERO、warning。

## 总结与追问预判
- 除零**结果恒为 NULL**；该值决定的是**是否告警/报错**。
- 报表 SQL 用 `NULLIF` 显式防御，别依赖 sql_mode。
