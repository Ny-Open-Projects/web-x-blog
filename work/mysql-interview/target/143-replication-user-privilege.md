# 143 复制账号到底需要什么权限

> 分类：复制/权限 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**REPLICATION SLAVE** / **GRANT** / **SHOW GRANTS** / **最小权限**
> 原文锚点：第 133~145 段「这个账号并没有任何授权…复制账号需要具有 replication 的权限」

## 一句话总述
复制账号只需 **REPLICATION SLAVE**（8.0.22+ 可加 CONNECTION_ADMIN 替代 SUPER）；**建了用户不等于有权限**，这是最常见的复制故障根因。

## 面试官视角
- **考察意图**：最小权限意识，以及"建账号"和"授权"是两件事。
- **P5** 知道要 `REPLICATION SLAVE` / **P6** 会 `SHOW GRANTS` 反查 / **P7** 能给出网段限定与最小权限建议。
- **红旗**：① "复制账号给 ALL PRIVILEGES 最省事"；② 授权不限网段；③ 不知道授权后要重启复制。
- **惊艳点**：**只建用户不授权时，账号仍能登录成功**——这会让前两步排查全部通过，极具迷惑性 `[经验]`。

## 主问答
**Q：搭建复制时，复制账号要怎么建？**
**A：**
1. **先给结论**：`GRANT REPLICATION SLAVE ON *.* TO 'repl'@'网段'` 即可，不需要任何库表权限，遵循最小权限。
2. **再给机制**：IO 线程靠这个权限向主库拉取增量日志；没有它，连接能建立但拉取会被拒，表现为 IO 线程停在 Connecting。
3. **最后给边界**：授权后**必须重启复制线程**才生效；另外要把账号限定在具体网段，不要用 `'%'` 全开。
**加分层**：排障时用 `SHOW GRANTS FOR CURRENT_USER()` 反查当前账号权限，比翻配置文件快得多。

## 关键代码
```sql
-- 在主库执行：只给复制所需的最小权限，并限定来源网段
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'192.168.1.%' IDENTIFIED BY 'pwd';
SHOW GRANTS FOR CURRENT_USER();   -- 从库侧反查当前账号有什么权限
```

## ⚠️ 原文纠错
未发现技术错误。原文「复制账号需要 replication 权限」表述正确，完整名为 `REPLICATION SLAVE`；机翻中的账号名与权限名音译已还原。

## 总结与追问预判
- 建账号 ≠ 授权；最小权限 + 限定网段 + 重启线程。
