# 079 慢查询日志怎么分析：mysqldumpslow 与 pt-query-digest

> 分类：日志类 | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**mysqldumpslow** / **pt-query-digest** / **慢查分析** / **聚合**
> 原文锚点：第 306 段「在慢查询执行日志中记录了我们 SQL 所执行的时间以及执行的用户…下面还有一些统计信息…（需要）分析工具去进行分析，并找出需要优化的 SQL」

## 一句话总述
慢日志原始文件不可直接看量，**`mysqldumpslow`** 做轻量聚合（官方自带），**`pt-query-digest`**（Percona Toolkit）做深度报告，二者都是"按语句模板聚合 + 排序 Top N"。

## 面试官视角
- **考察意图**：给你一份慢日志，你能不能在 5 分钟内说出"最该优化的三条 SQL"。
- **P5** 听过工具名 / **P6** 能报出常用参数与排序维度 / **P7** 知道**看总量而非单次耗时**（低频但超慢 vs 高频但略慢），并会把结论落到索引与改写。
- **红旗**：① 只看单条最慢不看调用次数；② 拿生产慢日志直接在主库跑分析（IO 冲击）；③ 不知道要先 `FLUSH SLOW LOGS` 取一份干净样本。
- **惊艳点**：优化优先级看 **总耗时 = 平均耗时 × 次数**，一条 0.1s 执行 10 万次的 SQL 往往比一条 30s 的更值得改 `[经验]`。

## 主问答
**Q（面试官原话）：** 拿到一个几 GB 的慢日志文件，你怎么下手？

**A：**
1. **先给结论**：先把文件**拷到分析机**（别压主库），用 `mysqldumpslow` 快速看 Top，再上 `pt-query-digest` 出完整报告。
2. **再给机制**：两者都会把 SQL **参数归一化**成模板（`WHERE id = 1/2/3` 归为一类），再按次数、总耗时、扫描行数聚合排序——这是"从百万行日志里找出几种坏 SQL"的关键。
3. **最后给边界**：排序维度选错会误导决策，优先按**总耗时/总扫描行数**排；分析前用 `FLUSH SLOW LOGS` 切一份新文件，避免读到历史数据；`long_query_time` 设太高会漏掉高频慢查。

**加分层**：报告里最该盯 **Count、平均 Rows_examined**，以及 **Rows_sent/Rows_examined 比值**——比值低说明索引选择性差。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 用什么分析慢日志 | 工具 | mysqldumpslow / pt-query-digest | 换题 → 不及格 |
| L2 | 它们做了什么 | 原理 | 归一化 + 聚合排序 | 判 P5 |
| L3 | 按什么排序 | 判据 | 总耗时、扫描行数 | 判 P6 |
| L4 | 优化优先级怎么定 | 决策 | 次数×耗时，而非单次 | 判 P6+ |
| L5 | 怎么落地 | 工程 | 加索引 / 改写 SQL / 控返回行 | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 变化点 | 现在该怎么答 |
|---|---|---|
| MySQL 全版本 | mysqldumpslow 随服务自带 | 快速排查首选 |
| 5.7 / 8.0 | Percona Toolkit 独立安装 | 深度报告用 pt-query-digest |
| 8.0 | Performance Schema 可选 | 也可查 events_statements_summary `[经验]` |

## 关键代码
```sql
SET GLOBAL long_query_time = 1;      -- 采样前先把阈值调到业务可接受线
FLUSH SLOW LOGS;                     -- 切出一份干净样本文件
SHOW VARIABLES LIKE 'slow_query_log_file';
```

```bash
# 官方自带：按总耗时取 Top 10
mysqldumpslow -s at -t 10 /data/mysqllog/slow.log
# Percona：完整报告（示意，未验证）
pt-query-digest --limit 10 /data/mysqllog/slow.log > /tmp/slow_report.txt
```

## ⚠️ 原文纠错
原文只泛称"用分析工具去进行分析"，**未点名任何工具**；本卡工具名与参数属通用工程实践，标注 `[经验]`，命令为**示意、未在本机实跑**。原文关于慢日志字段（执行时间、执行用户、来源主机、锁时间、返回行数、扫描行数）的描述与 5.7/8.0 实际格式一致。核对范围：第 296~306 段。

## 总结与追问预判
- 流程：**切样本 → 拷走 → 聚合 Top N → 按总耗时定优先级**。
- 判据是"次数 × 耗时"，不是单条最慢。
