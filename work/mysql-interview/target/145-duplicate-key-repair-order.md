# 145 主键冲突的处置顺序：先删数据，再谈跳过

> 分类：复制/排障 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**处置优先级** / **删除冲突行** / **跳过事务** / **补做校验**
> 原文锚点：第 153~161 段「建议如果能够通过直接删除从库主键冲突的方式来解决，最好使用这种方式」

## 一句话总述
主键冲突的处置有明确优先级：**能删从库冲突行就删**（数据仍等价），删除不了才跳过；**一旦跳过就必须补做校验与修复**。

## 面试官视角
- **考察意图**：有没有"跳过等于丢数据"的风险意识，这是区分背题和实战的分水岭。
- **P5** 知道可以跳过 / **P6** 知道优先删数据 / **P7** 知道跳过之后必须跑校验工具。
- **红旗**：① 不问原因直接 `SET GLOBAL sql_slave_skip_counter=1`；② 跳过完不校验；③ 认为跳过没有代价。
- **惊艳点**：跳过会让**该事务的修改在从库彻底缺失**，所以跳过只是"让复制继续"的止血，不是修复 `[经验]`。

## 主问答
**Q：从库报主键冲突，你会怎么处理？**
**A：**
1. **先给结论**：**优先删除从库上的冲突行**再重启 SQL 线程，让主库数据正常复制过来——这样两端仍等价。
2. **再给机制**：删除冲突行后，主库的该条记录可以完整重放，数据最终一致；而跳过则意味着该事务在从库**永远不落地**。
3. **最后给边界**：只有当冲突行无法删除（如业务上它是合法数据）时才走跳过；GTID 复制下跳过只能用**注入空事务**，不能用跳过计数器 `[经验]`。
**加分层**：无论走哪条路，收尾都应是"跑一次校验工具 + 不一致就用同步工具修"，把跳过留下的坑补上。
