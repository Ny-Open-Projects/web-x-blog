# 080 常用存储引擎有哪些，各自什么场景

> 分类：存储引擎 | 难度：L1 | 题型：八股题 | 频率：高 | 关键词：**插件式引擎** / **MyISAM** / **InnoDB** / **Memory** / **Archive**
> 原文锚点：第 1~5 段「它和关系数据库相区别的最大特点之一呢，就是它是一种插件式的存储引擎架构，可以支持多种不同类型的存储引擎」

## 一句话总述
MySQL 是**插件式存储引擎**架构：MyISAM（非事务、堆表、表锁）、CSV（文本交换）、Archive（高压缩归档）、Memory（内存易失）、**InnoDB（事务型，5.6 起默认）**、NDB（集群专用）。

## 面试官视角
- **考察意图**：这是 MySQL 面试开场题，测的是"知不知道事务能力在引擎层实现"这个分水岭。
- **P5** 能列举 3~4 种引擎 / **P6** 能说清各自场景 / **P7** 会点出"事务支持由存储引擎层而非服务层实现"，所以**不要在同一事务里混用事务型与非事务型引擎**。
- **红旗**：① 只会说"用 InnoDB"；② 不知道 5.6 起默认引擎变了；③ 在事务里混用引擎。
- **惊艳点**：非事务引擎（如 MyISAM）在事务回滚时**无法回滚** `[源码]`。验证：同一事务里写 InnoDB + MyISAM 表后 ROLLBACK，比对两表结果。

## 主问答
**Q（面试官原话）：** 你用过哪些存储引擎？分别适合什么场景？

**A：**
1. **先给结论**：常用五种——**MyISAM / CSV / Archive / Memory / InnoDB**，另有 NDB 用于 MySQL Cluster；新应用**默认 InnoDB**。
2. **再给机制**：MySQL 对事务的支持是**在存储引擎层实现的**（不同于多数数据库由服务层实现），所以有引擎支持事务、有引擎不支持；MyISAM 是堆表 + 表级锁、CSV 用逗号分隔文本存数据、Archive 只支持插入与查询并高比例压缩、Memory 数据在内存重启即失。
3. **最后给边界**：因此**不要把事务型与非事务型引擎混在同一事务里**——一旦回滚，非事务引擎的写入无法撤销，一致性被破坏。

**加分层**：MyISAM 在 5.6 前是默认引擎，直到 5.7 系统库（mysql 库）仍有表用它；8.0 起表定义并入数据字典，不再有 .frm 文件。

## 版本与兼容性

## 关键代码
```sql
SHOW ENGINES;                                   -- 看当前实例支持哪些引擎
SHOW TABLE STATUS LIKE 'stock'\G                -- 看单表引擎
CREATE TABLE t1 (id INT PRIMARY KEY) ENGINE=InnoDB;
```

## ⚠️ 原文纠错
原文"MyISAM 是 5.6 版本之前的默认存储引擎"表述准确；"5.7 中 mysql 系统库的表还在使用 MyISAM"与实际一致（8.0 已全面改为 InnoDB）。原文说 InnoDB 是"5.6 之后默认"，精确点是**自 5.6 起**。核对范围：第 1~60 段。

## 总结与追问预判
- 五种常用引擎 + NDB；**事务能力在引擎层**，别混用。
- 新项目默认 InnoDB，5.6 是默认引擎翻转点。
