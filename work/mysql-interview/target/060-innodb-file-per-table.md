# 060 innodb_file_per_table 独立表空间

> 分类：服务器配置 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**独立表空间** / **收缩空间** / **共享表空间不回收**
> 原文锚点：第 335~336 段「innodb_file_per_table 控制了 InnoDB 如何使用表空间…会为每个表建立一个单独的表空间，否则会把所有的 InnoDB 表的数据全存储到系统表空间中」

## 一句话总述
开启后每张 InnoDB 表有自己的 `.ibd`，`DROP/TRUNCATE/OPTIMIZE` 才能**把空间还给操作系统**；关掉则全塞进共享系统表空间，删表后空间只可复用、**永不归还**。

## 面试官视角
- **考察意图**：考"磁盘满了怎么办"的处置能力，是否踩过"删了表但空间没降"的坑。
- **P5** 每表一个文件 / **P6** 说清**空间回收**与系统表空间只增不减 / **P7** 延伸到 `TRUNCATE` 与 `DELETE` 差异及重建代价。
- **红旗**：① "删表就能释放空间"（共享表空间不成立）；② 说 5.7 才默认（实际 **5.6.6** 起）；③ 不知 `OPTIMIZE` 要重建表且占额外空间。
- **惊艳点**：独立表空间下 `TRUNCATE` 是**丢弃并重建 .ibd**，瞬间释放；`DELETE` 只打删除标记，空间仍留在表里 `[经验]` —— 验证：`TRUNCATE` 前后 `du -sh <db>/<table>.ibd`。

## 主问答
**Q（面试官原话）：** 磁盘快满了，我删了几张大表，为什么空间没降？

**A：**
1. **先给结论**：要么表在**共享系统表空间**里（`innodb_file_per_table=OFF`），要么你用的是 `DELETE` 而非 `TRUNCATE/DROP`——两种都不还给 OS。
2. **再给机制**：开启后每表一个 `.ibd`，`DROP`/`TRUNCATE` 直接删除或重建该文件，空间立即归还；`ibdata1` **只增不减**，删表空间只能后续复用。
3. **最后给边界**：`DELETE` 清空后空间只是标记可复用、仍占着 `.ibd`，要靠 `OPTIMIZE TABLE` 重建才收缩——重建需额外空间并重建索引，大表要评估窗口。

**加分层**：5.6.6 起已是默认值；老实例若关着，迁移需**导出导入**或 `ALTER TABLE ... ENGINE=InnoDB` 重建。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ≤ 5.6.5 | 默认 **OFF**（共享系统表空间） | 老实例常见"删表不释放"的成因 |
| ≥ 5.6.6（含 5.7 / 8.0） | 默认 **ON** | 新实例默认独立表空间，无需干预 |
| 8.0 | 数据字典改 InnoDB 存储、取消 `.frm` | "默认 ON，不再有 .frm" |

## 关键代码
```sql
-- 1. 确认开关
SHOW VARIABLES LIKE 'innodb_file_per_table';   -- ON 为独立表空间

-- 2. 收缩独立表空间的表（DELETE 之后用；会重建表，需额外空间）
OPTIMIZE TABLE large_table;

-- 3. 立即释放空间：TRUNCATE 会丢弃并重建 .ibd
TRUNCATE TABLE large_table;

-- 4. 老表迁移到独立表空间（需 OFF->ON 后重建）
ALTER TABLE large_table ENGINE=InnoDB;
```

```bash
# 验证空间是否真的归还文件系统
du -sh /var/lib/mysql/db_name/large_table.ibd
ls -lh /var/lib/mysql/ibdata1     # 共享表空间：只增不减，删表不会变小
```

## ⚠️ 原文纠错
原文"自 MySQL 5.7 之后这个参数实际上已经是默认启动的状态"不准确——默认开启的翻转点是 **5.6.6**，5.7 之前即已默认 ON，按 5.7 作答会被认为是记错版本。原文"强烈建议启用"的结论正确，保留。机翻音译（引noDBfillpotable、引ODDB、引头DB、买c个五点七）已还原为 innodb_file_per_table、InnoDB、InnoDB、MySQL 5.7。

## 总结与追问预判
- 独立表空间 = **空间可回收**；共享表空间 = 只增不减。
- 收缩靠 `TRUNCATE` / `OPTIMIZE`，`DELETE` 不行。
