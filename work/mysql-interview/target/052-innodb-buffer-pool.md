# 052 InnoDB 缓冲池与实例数

> 分类：服务器配置 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**innodb_buffer_pool_size** / **75% 内存** / **instances**
> 原文锚点：第 324~334 段「如果系统中只使用了 InnoDB 表，通常建议缓冲池大小为服务器内存的 75% 以上…每个实例不能小于 1G，一般不要超过 8 个」

## 一句话总述
InnoDB 缓冲池**既缓存索引也缓存数据**，`innodb_buffer_pool_size` 通常设为**服务器内存的 75%**；再通过 `innodb_buffer_pool_instances` 拆成多实例降低锁竞争，**每实例 ≥1G、总数不宜超过 8**。

## 面试官视角
- **考察意图**：最基础的性能参数题，看你会不会给数量级和约束条件。
- **P5** 知道缓冲池缓存数据与索引。
- **P6** 能说出 75% 的经验值，并知道拆多实例是为减少锁竞争。
- **P7** 能补上约束（每实例 ≥1G、8.0 后实例数在小于 1G 时自动调整为 1）与调大后的重启代价。
- **红旗**：① 说"越大越好，直接给 90%"；② 不知道多实例是全局共享而非每连接；③ 忘了它是**全局**参数、占用的是常驻内存。
- **惊艳点**：缓冲池是**全局共享**的，与 050 卡每线程缓冲不同——调大不会随连接放大 `[经验]` —— 验证：`SHOW ENGINE INNODB STATUS` 看 Buffer pool 段。

## 主问答
**Q（面试官原话）：** innodb_buffer_pool_size 一般怎么设？实例数设多少？

**A：**
1. **结论**：只跑 InnoDB 的实例通常设为**服务器内存的 75%**；实例数按"每实例不小于 1G、总数不超过 8"来定。
2. **机制**：缓冲池缓存**索引 + 数据 + 自适应哈希索引 + 插入缓冲**等，还能把多次写合并为顺序写，InnoDB 性能**严重依赖**它。
3. **边界**：拆多实例是为**减少资源锁、提高并发**，实例太小则浪费内存；调大后需为连接缓冲与 OS 预留内存。

**加分层**：不要只盯这一个值——要按"缓冲池 + 每线程缓冲 × max_connections"做整机内存预算，否则连接一多照样 OOM。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.6 / 5.7 | 需手动配 `innodb_buffer_pool_instances` | 按"手动设，8 以内"答 |
| 8.0 | 缓冲池**可在线调整**（无需重启）；实例数较小时自动归一 | 补一句"8.0 支持在线调整" |

## 关键代码
```sql
SHOW VARIABLES LIKE 'innodb_buffer_pool_size';
SHOW VARIABLES LIKE 'innodb_buffer_pool_instances';
SET GLOBAL innodb_buffer_pool_size = 8589934592;   -- 8G，8.0 可在线生效
SHOW ENGINE INNODB STATUS\G   -- 查看 Buffer pool size / Free buffers
```

## ⚠️ 原文纠错
原文"每个缓冲池实例不能小于 1G、一般不要超过 8 个"属经验值，与业界通行建议一致；补充一点原文未提：8.0 起缓冲池大小**支持在线调整**，且实例过小时会自动归一。机翻音译（引诺 DB、beoubleprocess）已还原为 InnoDB、buffer_pool_size。

## 总结与追问预判
- 缓冲池设 **内存 75%**，实例 **≥1G/个、≤8 个**；全局共享不随连接放大。
- 调参要连带做**整机内存预算**（见 050 卡）。
