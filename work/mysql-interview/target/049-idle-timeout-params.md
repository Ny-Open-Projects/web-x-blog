# 049 空闲连接超时参数

> 分类：服务器配置 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**wait_timeout** / **interactive_timeout** / **sleep 连接**
> 原文锚点：第 281~286 段「interactive_timeout 和 wait_timeout 设置的是会话连接到 MySQL 后如果处于 sleep 状态的时间…通常把这两个参数设置为相同的值」

## 一句话总述
`wait_timeout`（非交互连接）与 `interactive_timeout`（交互连接）控制**空闲（sleep）连接**多久被服务端主动断开；两者**只作用于 sleep 状态**，生产通常设为同一个较小值（如 300 秒）。

## 面试官视角
- **考察意图**：看你是否知道"空闲连接会白占连接数"，以及两个参数的分工。
- **P5** 知道空闲连接会被超时断开。
- **P6** 能说清两者的**交互/非交互**区别，以及只影响 sleep 状态。
- **P7** 能指出默认值 28800 秒过长带来的连接堆积风险，并说明要**与应用连接池的空闲检测配合**设置。
- **红旗**：① 以为超时会杀掉正在执行 SQL 的连接；② 只设一个不管另一个；③ 应用层不配空闲检测导致拿到已被断开的连接。
- **惊艳点**：默认值 **28800 秒（8 小时）**对高并发服务太长，容易堆满连接 `[经验]` —— 验证：`SHOW PROCESSLIST` 统计 sleep 状态连接数与时长。

## 主问答
**Q（面试官原话）：** 数据库里 sleep 连接特别多，怎么治？

**A：**
1. **结论**：调小 `wait_timeout` 与 `interactive_timeout`（如 300 秒），让服务端主动回收空闲连接。
2. **机制**：两者区别在连接类型——**交互连接**用 `interactive_timeout`，**非交互连接**（绝大多数程序连接）用 `wait_timeout`；**只对 sleep 状态生效**，正在执行语句的连接不受影响。
3. **边界**：连接类型由**建连时的连接参数**决定，不同客户端默认值不同，所以通常**把两个值设成一样**；同时应用侧连接池要有空闲检测/心跳，否则会拿到已被服务端断开的连接。

**加分层**：改 `SET GLOBAL` 后**当前会话不变**，需重连或再 `SET SESSION`（详见 046 卡）。

## 关键代码
```sql
SHOW VARIABLES LIKE '%timeout%';
SELECT id, user, host, command, time FROM information_schema.processlist WHERE command='Sleep';
SET GLOBAL wait_timeout = 300;
SET GLOBAL interactive_timeout = 300;   -- 两者保持一致
```

## ⚠️ 原文纠错
原文"这两个参数只会影响处于 sleep 状态的会话"与官方一致，未发现技术错误；原文说"通过指定连接参数区分交互与非交互"亦正确（客户端 `CLIENT_INTERACTIVE` 标志）。机翻音译（waittimepameout、viicuretimeralt）已还原为 wait_timeout。

## 总结与追问预判
- 两个超时参数只管 **sleep 连接**；生产设小值并保持一致。
- 应用侧必须配**连接池空闲检测**，否则会拿到已断连接。
