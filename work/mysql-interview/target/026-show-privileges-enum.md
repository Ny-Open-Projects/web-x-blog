# 026 用 SHOW PRIVILEGES 查全部权限

> 分类：用户管理 | 难度：L1 | 题型：八股题 | 频率：低 | 关键词：**SHOW PRIVILEGES** / **权限清单** / **上下文说明**
> 原文锚点：第 78~85 段「我们可以在 MySQL 命令行工具中使用 SHOW PRIVILEGES 命令来查看当前版本所支持的权限的列表」

## 一句话总述
拿不准该授什么权限时，直接在实例上执行 **`SHOW PRIVILEGES`**——它返回**当前版本**支持的全部权限及每条权限的上下文说明。

## 面试官视角
- **考察意图**：看你遇到"不知道该给什么权限"时，是查文档现编还是有一套可复现的做法。
- **P5** 知道有 `SHOW PRIVILEGES` 这条命令。
- **P6** 能说出输出包含权限名、作用对象上下文（Context）与说明列。
- **P7** 能把它接到授权流程里：先查清单 → 按最小权限挑 → 再 `GRANT`，并说明不同版本输出条数不同。
- **红旗**：① 背一份"完整权限表"却说不出在哪查；② 把 5.7 的权限清单当成 8.0 的；③ 不看 Context 列就照抄授权语句。
- **惊艳点**：`SHOW PRIVILEGES` 的 **Context 列**标明该权限能作用在哪个层级（Server Admin / Databases / Tables / Columns），照着它就能判断该写 `ON *.*` 还是 `ON db.tbl` `[源码]` —— 验证：在实例上执行后观察 Context 取值。

## 主问答
**Q（面试官原话）：** 我要给一个新业务授权，怎么知道 MySQL 到底有哪些权限、该给哪些？

**A：**
1. **结论**：在目标实例上执行 **`SHOW PRIVILEGES`**，拿到的是**这个版本真实支持**的权限清单，比任何网上的整理表都准。
2. **机制**：输出包含**权限名 + Context（作用层级）+ 说明**；Context 决定该权限能授予到哪一层，例如 Server Admin 只能 `ON *.*`，表级权限可以 `ON db.tbl`。
3. **边界**：不同大版本支持的权限**数量和种类不同**（8.0 增加了动态权限），清单必须以目标实例的实际输出为准。

**加分层**：授权流程应是**查清单 → 按场景挑最小集 → GRANT → SHOW GRANTS 复核**，而不是复制一条 `GRANT ALL`。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.7 | 静态权限集合 | 答"以 SHOW PRIVILEGES 输出为准" |
| 8.0 | 新增**动态权限**（如 SYSTEM_VARIABLES_ADMIN） | 现在要补：8.0 清单比 5.7 更长，含动态权限 |

## 关键代码
```sql
-- 查当前实例支持的全部权限（含作用层级与说明）
SHOW PRIVILEGES;
-- 复核某个账号实际拿到什么
SHOW GRANTS FOR 'app'@'192.168.1.%';
```

## ⚠️ 原文纠错
原文提到"授权 value"来查看权限列表，按上下文应为在客户端执行 `SHOW PRIVILEGES` 后展示的表格（疑似命令行回显被识别为乱码）`[存疑]`；核心结论（用 SHOW PRIVILEGES 查看当前版本支持的所有权限）无误。机翻音译（showprysql、action 权限）已还原为 SHOW PRIVILEGES、ALTER。

## 总结与追问预判
- 不确定给什么权限 → **`SHOW PRIVILEGES` 查当前版本真实清单**。
- Context 列决定 `ON` 后面写 `*.*` 还是 `db.tbl`。
