# 010 MySQL 8.0 数据字典与系统表变革

> 分类：MySQL 8.0 新特性 | 难度：L3 | 题型：概念主问 | 频率：中 | 关键词：**数据字典** / **去 FRM** / **mysql.ibd** / **InnoDB 系统表**
> 原文锚点：第 233~239 段「8.0 移除 FRM 文件、元数据进数据字典、系统表改用 InnoDB」

## 一句话总述
MySQL 8.0 把基于文件的元数据管理**改为统一数据字典**：**移除 FRM 文件**，所有元数据入数据字典；系统表改用 **InnoDB** 存于独立表空间 **mysql.ibd**，提升系统更新的完整性。

## 面试官视角
- **考察意图**：是否了解 8.0 架构级变更及其迁移影响。
- **P5** 知道 8.0 去掉了 FRM 文件。
- **P6** 能说清数据字典统一与系统表 InnoDB 化。
- **P7** 能讲这对升级/备份工具（如依赖 FRM 的脚本）的连锁影响。
- **红旗**：说「8.0 只是加功能，存储没变」。
- **惊艳点**：点出旧版系统表用 MyISAM/CSV，8.0 全改 InnoDB，崩溃恢复更可靠 `[源码]`。

## 主问答
**Q：MySQL 8.0 在元数据/系统表上有什么重大变化？**
**A：**
1. **结论**：8.0 **废弃 FRM 文件**，元数据全部进入统一数据字典；系统表由 MyISAM/CSV 改为 **InnoDB**，存于独立表空间 `mysql.ibd`。
2. **机制**：之前每张表一个 FRM 存元数据、系统库多为文件表；8.0 中央化到数据字典，系统表也享受 InnoDB 的事务/崩溃恢复。
3. **边界**：依赖读取 FRM 或老系统表类型的运维/备份脚本在 8.0 需改造；升级必须跑 `mysql_upgrade`。
**加分层**：数据字典还带来原子 DDL 等连锁收益（见 018）。

## 关键代码
```bash
# 8.0 升级后必须升级系统表
mysql_upgrade -u root -p --force
```

```sql

SELECT TABLE_NAME, ENGINE FROM information_schema.tables
  WHERE TABLE_SCHEMA='mysql' AND ENGINE='InnoDB';
```
