# 006 GTID 跨版本复制兼容

> 分类：复制/版本 | 难度：L3 | 题型：排障题 | 频率：高 | 关键词：**GTID** / **复制兼容** / **只能作从**
> 原文锚点：第 78~85 段「MariaDB 的 GTID 生成规则不同…MariaDB 只能作从、不能作主」

## 一句话总述
GTID 自 MySQL 5.6 引入；**MariaDB 的 GTID 生成规则与官方版不同**，导致 MariaDB 可作为 MySQL 的从库，但 MySQL **不能**作为 MariaDB 的从库——混部复制必须注意方向。

## 面试官视角
- **考察意图**：是否真正理解 GTID 的实现差异，而非只知道「开了 GTID」。
- **P5** 知道 GTID 用于唯一标识事务、简化复制。
- **P6** 能说清官方版间 GTID 一致，MariaDB 规则不同。
- **P7** 能给出混合环境下的复制拓扑建议（避免反向）。
- **红旗**：说「开了 GTID 所有 MySQL 系都能互为主从」。
- **惊艳点**：点出 MariaDB 把官方版 GTID 复制转成基于位点处理，故只能单向 `[源码]`。

## 主问答
**Q：MySQL 和 MariaDB 之间能用 GTID 互为主从吗？**
**A：**
1. **结论**：**不能双向**。MariaDB 的 GTID 格式与 MySQL 官方版不互通，MariaDB 可作 MySQL 的从，MySQL 不能作 MariaDB 的从。
2. **机制**：官方版与 Percona 的 GTID 实现一致；MariaDB 实现时把官方版 GTID 复制转换为「基于位点」复制来处理，方向天然单向。
3. **边界**：纯官方版/Percona 混部可正常 GTID 复制；一旦掺入 MariaDB，复制拓扑必须 MariaDB 在下游。
**加分层**：新架构若需双向同步，应统一发行版，或改用基于位点+外部同步工具。
