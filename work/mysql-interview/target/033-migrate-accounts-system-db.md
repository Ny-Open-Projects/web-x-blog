# 033 账号迁移方案一：备份恢复 mysql 系统库

> 分类：用户管理 | 难度：L3 | 题型：设计题 | 频率：中 | 关键词：**mysql 系统库** / **整库恢复** / **mysql_upgrade**
> 原文锚点：第 174~180 段「如果源和目的实例的版本一致，我们可以采用备份原实例中的 mysql 系统库，再在目的实例中恢复 mysql 系统库的方式来完成账号迁移」

## 一句话总述
版本一致时直接**备份源实例的 `mysql` 系统库并在目标实例恢复**，一次搬走全部账号与权限；版本不一致还要更新系统表。

## 面试官视角
- **考察意图**：看你是否知道账号信息本质上存在 `mysql` 库里。
- **P5** 知道账号信息存在 mysql 系统库。
- **P6** 能说出"备份 + 恢复 mysql 库"，版本不一致要更新系统表。
- **P7** 能指出两个硬约束（**只能低→高**、会**带入非账号元数据**）并给替代方案。
- **红旗**：① 认为任意版本都能迁；② 不知道会连存储过程一起搬。
- **惊艳点**：该方案**只能低版本 → 高版本**——反向会因系统表结构不兼容出错 `[经验]` —— 验证：比对两实例 `mysql.user` 列数即可预判。

## 主问答
**Q（面试官原话）：** 新建了一套实例，希望账号和老集群完全一致，怎么做？

**A：**
1. **结论**：先比对**源与目标版本**；一致（或低→高）时，备份源实例的 **`mysql` 系统库**并在目标实例恢复。
2. **机制**：账号、权限、密码哈希全落在 `mysql` 库系统表里，整库恢复即把记录原样搬过去。
3. **边界**：**两个硬伤**——① **只能同版本或低→高**；② 库里**存储过程、函数等非账号元数据**会一并被搬走。

**加分层**：版本不一致时恢复后还要更新系统表结构，否则实例可能异常。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 账号信息存在哪 | 概念 | mysql 系统库 | 换题 → 不及格 |
| L2 | 怎么整体迁移 | 方案 | 备份 + 恢复 mysql 库 | 判 P5 |
| L3 | 跨版本怎么办 | 版本约束 | 只能低→高 + 更新系统表 | 判 P6 |
| L4 | 有什么副作用 | 方案缺陷 | 带入存储过程等非账号元数据 | 判 P6+ |
| L5 | 有更通用的办法吗 | 替代方案 | 导出授权语句重放（见 034） | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.7 及之前 | `mysql_upgrade` 是独立外部命令 | 老版本答"跑 mysql_upgrade" |
| 8.0 | 升级并入服务器启动流程，`mysql_upgrade` **已废弃** | 补一句"8.0 由服务器自动完成系统表升级" |

## ⚠️ 原文纠错
原文"这种方式只能用于同一个版本，或者是低版本实例向高版本实例迁移"与官方约束一致，未发现技术错误。补充时效说明：原文提到的 `mysql_upgrade` 在 **8.0 起已废弃**，系统表升级改由服务器启动时自动完成。机翻音译（分户空表、买监控）已还原为分库分表、mysql。

## 总结与追问预判
- 方案一 = **备份恢复 mysql 系统库**，**只支持同版本或低→高**。
- 副作用：连存储过程等非账号元数据一起搬走。
- 下一题：见 034（导出授权语句重放）。
