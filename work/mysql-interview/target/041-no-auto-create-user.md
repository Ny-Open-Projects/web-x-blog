# 041 NO_AUTO_CREATE_USER 的生命周期

> 分类：服务器配置 | 难度：L2 | 题型：八股题 | 频率：中 | 关键词：**NO_AUTO_CREATE_USER** / **GRANT 建用户** / **8.0 默认行为**
> 原文锚点：第 172~177 段「NO_AUTO_CREATE_USER 只存在于 MySQL 5.6 和 5.7 版本中…在 MySQL 8.0 中这已经变成了默认行为」

## 一句话总述
`NO_AUTO_CREATE_USER` 禁止 **GRANT 顺带创建用户**；它只在 **5.6 / 5.7 存在**，**8.0 起该行为已成默认**（GRANT 不再能建用户），因此这个值在 8.0 被移除。

## 面试官视角
- **考察意图**：用一个"已经消失的配置项"来测你是否真的跟过版本演进，是很好的版本敏感度题。
- **P5** 知道 8.0 建用户必须用 `CREATE USER`。
- **P6** 能说清该值在 5.6/5.7 的作用与 8.0 的处置方式。
- **P7** 能指出 **8.0 里再写这个值会报错**，并给出升级时的整改动作（拆成 CREATE USER + GRANT）。
- **红旗**：① 在 8.0 的 sql_mode 里还写这个值；② 以为 8.0 只是"不推荐"而非"不支持"。
- **惊艳点**：8.0 中**显式设置 `NO_AUTO_CREATE_USER` 会直接报错**（该值已移除）`[经验]` —— 验证：`SET sql_mode='NO_AUTO_CREATE_USER';` 在 8.0 上返回 1231 错误。

## 主问答
**Q（面试官原话）：** 听说有个 sql_mode 能防止用 GRANT 建用户，现在还能用吗？

**A：**
1. **结论**：`NO_AUTO_CREATE_USER` **只存在于 5.6 / 5.7**；**8.0 起"GRANT 不建用户"已成默认行为**，该值被移除。
2. **机制**：5.6/5.7 中开启它后，GRANT 遇到不存在的用户会**报错**而不是顺手创建，强制走 `CREATE USER`。
3. **边界**：8.0 上再把它写进 sql_mode 会**报错**；升级时要把"GRANT 建用户"的脚本拆成 `CREATE USER` + `GRANT` 两步。

**加分层**：这个变化体现了官方强制"账号与权限解耦"的方向——详见 022 卡。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.6 / 5.7 | 该值**存在**，需显式开启才生效 | 老版本答"可开启强制两步走" |
| 8.0 | 该值**已移除**，语义变为默认行为 | 现在答"8.0 无需也不该再设置" |

## 关键代码
```sql
-- 5.7：开启后 GRANT 不再隐式建用户
SET SESSION sql_mode = CONCAT(@@sql_mode, ',NO_AUTO_CREATE_USER');
GRANT SELECT ON db1.* TO 'nobody'@'%';   -- 报错，需先 CREATE USER
-- 8.0：该值已移除，写出会报错（ERROR 1231）
```

## ⚠️ 原文纠错
原文"NO_AUTO_CREATE_USER 只存在于 MySQL 5.6 和 5.7 版本中，8.0 中这已经变成了默认行为"——与官方一致，未发现技术错误。补充：8.0 中该值被**移除**而非保留为可选项，显式设置会报错。机翻音译（crerent、mysluser、seser）已还原为 GRANT、mysql.user、user。

## 总结与追问预判
- `NO_AUTO_CREATE_USER` = **5.6/5.7 专属**；8.0 已成默认，值被移除。
- 升级动作：把 GRANT 建用户脚本拆成 **CREATE USER + GRANT**。
