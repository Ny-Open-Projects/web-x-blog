# 130 数据库可用性怎么监控

> 分类：管理监控 | 难度：L1 | 题型：工程题 | 频率：高 | 关键词：**可用性** / **mysqladmin ping** / **SELECT 1** / **探活**
> 原文锚点：第 120~129 段「周期性地使用 mysql 客户端执行如 select version() 检查是否能正常返回结果，也可以用 mysqladmin 命令检查」

## 一句话总述
可用性监控就两招：**周期性执行一条轻量 SQL**（如 `SELECT 1`）看能否返回，或用 **`mysqladmin ping`** 探活——但要防「能连上 ≠ 能服务」的假阳性。

## 面试官视角
- **考察意图**：会不会把「端口通」当成「可用」，忽略了连接打满、只读、磁盘满这些「连得上但用不了」的状态。
- **P5** 知道用 `SELECT 1` 或 `mysqladmin ping` / **P6** 能说出探活频率与超时设置 / **P7** 会补「还要探**可写性**（写一张心跳表）和**复制状态**，否则主库只读了探活仍是绿的」。
- **红旗**：「ping 通就是可用」；「探活越频繁越好」；「不需要探写」。
- **惊艳点**：`mysqladmin ping` 只验证**进程能响应握手**，在 `max_connections` 打满时它同样会失败，但**不会告诉你为什么**——所以探活之外必须配指标告警（8.0.36 `[经验]`）。

## 主问答
**Q：怎么监控 MySQL 是否可用？**
**A：**
1. **先给结论**：周期性执行轻量查询（`SELECT 1` / `SELECT VERSION()`）或 `mysqladmin ping`，能正常返回即视为可用。
2. **再给机制**：探针应模拟真实链路（走 TCP、带账号密码、设超时），返回 mysqld is alive 才判定存活；连续 N 次失败才告警，避免网络抖动误报。
3. **最后给边界**：「能连上」不等于「能服务」——连接打满、磁盘写满、实例被置 `read_only`、从库复制中断，都可能让探活仍然成功；所以可用性格要**搭配 QPS/连接数/复制延迟**一起看。
**加分层**：对主库额外做一次**写心跳**（往心跳表写时间戳），是发现「只读了但还能连」这类故障最省事的手段。
