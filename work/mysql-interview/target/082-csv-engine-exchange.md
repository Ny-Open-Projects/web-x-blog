# 082 CSV 引擎为什么适合做数据交换中间表

> 分类：存储引擎 | 难度：L1 | 题型：八股题 | 频率：低 | 关键词：**CSV 引擎** / **数据交换** / **不支持索引** / **NOT NULL**
> 原文锚点：第 105~130 段「CSV 存储引擎的表的数据呢，是以 CSV 文件的格式来进行存储的…因此是可以作为一种数据交换的中间表来使用的」

## 一句话总述
CSV 引擎把表存成**逗号分隔、字符串加双引号的文本文件**，可直接查看与编辑，适合做**数据交换中间表**；但**所有列必须 NOT NULL**、**不支持索引**，不能当高频查询表用。

## 面试官视角
- **考察意图**：这是一道"你见过几种引擎"的加分题，重点在**限制**而不是用法。
- **P5** 知道它以 CSV 文件存数据 / **P6** 能说出 NOT NULL 与无索引两个硬限制 / **P7** 能给出"Excel → CSV → 拷进数据目录 → 打开即用"的完整交换链路。
- **红旗**：① 拿它做业务主表；② 忘记列必须非空；③ 编辑文件后不 `FLUSH TABLES` 就去查。
- **惊艳点**：**编辑物理文件后必须 `FLUSH TABLES` 关闭再打开**才能看到新数据 `[实测]`。验证：vi 加一行后直接 SELECT 看不到，FLUSH 后可见。

## 主问答
**Q（面试官原话）：** 怎么把 Excel 的数据快速导进 MySQL？

**A：**
1. **先给结论**：把电子表格另存为 CSV 文件，**复制到数据目录**下对应库目录，CSV 引擎表即可直接读取（也可反向导出给外部程序）。
2. **再给机制**：CSV 引擎以文本方式落盘，列间逗号分隔、字符串用双引号包裹，所以外部程序与 MySQL 可以**共享同一份文件**——这正是"中间表"的价值。
3. **最后给边界**：两个硬限制——**每列必须 NOT NULL**（否则建表报错），**完全不支持索引**（建索引报"最多允许 0 个 key"）；数据量大时查询更新很差，只适合交换与临时中转；严格 `sql_mode` 下还需给默认值。

**加分层**：MySQL 的**通用查询日志表**正是 CSV 引擎，便于用文本工具分析。

## 关键代码
```sql
CREATE TABLE my_csv (
  id INT NOT NULL, c1 VARCHAR(20) NOT NULL, c2 VARCHAR(20) NOT NULL
) ENGINE=CSV;                     -- 少了 NOT NULL 会直接建表失败
FLUSH TABLES;                     -- 手工编辑 .CSV 文件后必须执行
```

```bash
cat /data/mysql/stock/my_csv.CSV   # 直接查看/编辑表数据
```

## ⚠️ 原文纠错
原文关于"列必须非空""不支持索引""可作为数据交换中间表"的描述均正确；机翻「noteno/ momoml」还原为 NOT NULL、默认值，「prayindex」还原为 `CREATE INDEX`，「flash」还原为 `FLUSH TABLES`。原文说编辑后"先把表关闭再重新打开"，卡面明确为执行 `FLUSH TABLES`。核对范围：第 105~150 段。

## 总结与追问预判
- CSV 引擎 = **文本可编辑 + 无索引 + 列非空**，定位是**交换中间表**。
- 改文件后必须 `FLUSH TABLES`。
