# 029 数据库账号安全四原则

> 分类：用户管理 | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**最小权限** / **限网段** / **密码强度** / **流程规范**
> 原文锚点：第 106~124 段「我们可以从几个方面来保证数据库账号的安全…管理流程、最小权限、密码强度策略」

## 一句话总述
账号安全靠**外部流程 + 数据库能力**两层：流程管住"人"，最小权限/限网段/密码策略管住"账号本身"。

## 面试官视角
- **考察意图**：开放题，看你能不能给出**结构化**答案。
- **P5** 能说出"最小权限"和"密码要复杂"。
- **P6** 能给出四层：管理流程、最小权限、限制来源与加密、密码强度。
- **P7** 能指出密码过期/历史策略必须与程序能力匹配，否则自造故障。
- **红旗**：① 只答"密码设复杂点"；② 说"用 `%` 方便"。
- **惊艳点**：**密码过期不是越严越好**——程序不支持自动取新密码就会全线连接失败 `[经验]` —— 验证：手工 `ALTER USER ... PASSWORD EXPIRE` 后观察连接池报错。

## 主问答
**Q（面试官原话）：** 你在之前的工作中是如何加强数据库账号安全的？

**A：**
1. **结论**：四个抓手——**管理流程规范**、**最小权限**、**限制来源与加密链路**、**密码强度策略**。
2. **机制**：流程上禁止把账号密码上传公共代码仓库；技术上只给必要权限、不开 `%`、必要时走 SSL 链路。
3. **边界**：**密码过期与历史重用策略要慎用**——程序支持自动到配置中心取新密码才能开。

**加分层**：密码里**慎用特殊字符**——部分程序解析有差异，可能导致连接串失效。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 账号安全从哪几方面做 | 结构化 | 流程 / 权限 / 来源 / 密码 | 换题 → 不及格 |
| L2 | 什么叫最小权限 | 核心原则 | 只给必需的，不给 SUPER | 判 P5 |
| L3 | 为什么不能用 `%` | 安全意识 | 等于对任意来源开放 | 判 P6 |
| L4 | 密码过期能直接开吗 | 权衡判断 | 要看程序能否自动续密 | 判 P6+ |
| L5 | 你们有哪些规范 | 实战 | 账号分级、审计、密钥托管 | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.7 | 引入**密码过期**（`default_password_lifetime`） | 老版本只能做过期，历史策略需自研 |
| 8.0 | 新增**历史密码重用次数/时间**限制 | 现在把"过期 + 历史"作为一组能力答 |

## 关键代码
```sql
SET PERSIST default_password_lifetime = 90;
ALTER USER 'app'@'192.168.1.%' PASSWORD EXPIRE INTERVAL 90 DAY PASSWORD HISTORY 5;
```

## ⚠️ 原文纠错
原文"5.7 引入密码过期、8.0 引入历史密码重用"与官方一致；但另一处口述为"5.6 引入过期"属口误，已按 **5.7 过期 / 8.0 历史** 的正确事实重写。机翻音译（YC 六五点七、满 CQ）已还原为 MySQL 5.7、MySQL。

## 总结与追问预判
- 四抓手：**流程规范 → 最小权限 → 限来源+SSL → 密码策略**。
- 开启过期策略**必须先确认程序能自动续密码**。
