# 134 CPU 飙高的四类根因与工具矩阵

> 分类：排障/性能 | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**IO 瓶颈** / **阻塞线程** / **并发慢查询** / **排查工具**
> 原文锚点：第 27~38 段「引起 CPU 负载高的主要原因…通过 iostat 和 lsof 检查磁盘 IO」

## 一句话总述
CPU 飙高只有四类根因——**磁盘 IO 超负荷、MySQL 内阻塞、大量并发慢查询、外部服务或硬件**；每类对应固定工具，按表排即可。

## 面试官视角
- **考察意图**：有没有成体系的排查路径，而不是想到哪查到哪。
- **P5** 能背出四类根因 / **P6** 能给出每类对应的命令 / **P7** 能说明"为什么先排除 IO 再看 MySQL"。
- **红旗**：① 上来就调参数；② 只会 `SHOW PROCESSLIST`；③ 忘记排查同机其他服务。
- **惊艳点**：说出"非高速存储时**最先到瓶颈的是磁盘 IO 而非 CPU**"这条顺序判断 `[经验]`。

## 主问答
**Q：数据库 CPU 高了，你的排查路径是什么？**
**A：**
1. **先给结论**：按"**IO → 阻塞/慢查询 → 外部服务 → 硬件**"四级排除，每级一个工具，不跳级。
2. **再给机制**：`iostat` 看系统整体 IO、`lsof` 看某进程打开了哪些文件；MySQL 内部用 `SHOW PROCESSLIST` 或上一章的阻塞监控 SQL 看阻塞与慢查询；系统侧用 `top` 看进程级 CPU 归属。
3. **最后给边界**：硬件故障（内存、磁盘损坏）在软件层查不到，必须靠硬件监控或带外管理口确认。
**加分层**：存储是机械盘或普通云盘时，IO 先满会把 CPU 拉高，此时优化 SQL 不如先降 IO。
