# 141 用校验工具对比并修复主从差异

> 分类：复制/工具 | 难度：L3 | 题型：工程题 | 频率：中 | 关键词：**CHECKSUM TABLE** / **pt-table-checksum** / **pt-table-sync** / **sync-to-master**
> 原文锚点：第 90~112 段「使用 pt-table-sync 这个工具来修复主从数据库的数据异常」

## 一句话总述
先**定量证明不一致**（`CHECKSUM TABLE` 或 `pt-table-checksum`），再用 `pt-table-sync` **只同步差异行**修复——校验与修复必须分成两步。

## 面试官视角
- **考察意图**：知不知道有现成工具，以及修复方向（以谁为准）能不能说清。
- **P5** 知道 `CHECKSUM TABLE` / **P6** 知道 `pt-table-sync --sync-to-master` / **P7** 能指出校验的执行位置与修复的不可逆性。
- **红旗**：① 手工导数据"覆盖"从库；② 修复前不校验、修完也不校验；③ 把 `--sync-to-master` 后面写成主库地址。
- **惊艳点**：`--sync-to-master` 后面跟的是**从库**地址——工具据此定位从库并以主库为准对齐 `[经验]`。

## 主问答
**Q：确认主从不一致后，怎么把数据修回去？**
**A：**
1. **先给结论**：`pt-table-sync` 只同步**不一致的行**，一致的数据不动，比整表重灌轻得多。
2. **再给机制**：指定 `--execute` 才真正执行（不加则只打印差异，可先干跑）；用 `--databases`/`--tables` 限定范围；`--sync-to-master` 表示**以主库为基准**，后面接从库连接信息 `[经验]`。
3. **最后给边界**：修复是**写操作**且不可逆，务必先干跑看差异量；若从库有多余数据（如被人为插入的行），工具默认会补/改不一致行，评估业务后再执行。
**加分层**：修完**必须回到从库再校验一次**，两边校验值相同才算闭环——案例里修复后两端同为 1770005017。

## ⚠️ 原文纠错
未发现技术错误。原文用 `CHECKSUM TABLE` 在两端分别取值对比，结论正确；补充一点：该语句会**扫描全表**，大表上应在低峰执行。机翻中的工具名音译已还原为 `pt-table-checksum` / `pt-table-sync`。
