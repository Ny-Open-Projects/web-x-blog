# 067 慢查询日志开关与输出路径

> 分类：日志类 | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**slow_query_log** / **slow_query_log_file** / **目录权限**
> 原文锚点：第 246~253 段「控制是否打开慢查询日志的参数 slow_query_log，这是一个全局的动态参数…要保证 mysqld 的启动系统用户对目录有读写权限，否则无法把日志输出到这个目录」

## 一句话总述
慢查询日志由 `slow_query_log` 动态开关（**默认 OFF**），路径由 `slow_query_log_file` 指定；**必须与数据目录分盘**，且 mysqld 运行用户要对该目录有读写权限。

## 面试官视角
- **考察意图**：慢查是性能优化入口，看你能不能正确打开它而不踩权限坑。
- **P5** 知道用来找慢 SQL / **P6** 说出默认关闭且可动态开 / **P7** 补上**分盘**与**目录权限**两个坑。
- **红旗**：① 以为默认开启；② 放数据目录还说没问题；③ 配了路径不生成却想不到权限。
- **惊艳点**：路径配错权限时日志**静默不产生**——参数看起来是对的，但文件就是不出现 `[经验]` —— 验证：`ls -ld <日志目录>` 与 `ps aux | grep mysqld` 核对属主。

## 主问答
**Q（面试官原话）：** 线上要抓慢 SQL，慢查询日志怎么开？有什么要注意的？

**A：**
1. **先给结论**：`SET GLOBAL slow_query_log = ON` 即可动态开启（默认 **OFF**），路径用 `slow_query_log_file` 指定。
2. **再给机制**：两者都是**全局动态**参数，不用重启；不指定路径时会落到**数据目录**下，默认文件名为 `host_name-slow.log`。
3. **最后给边界**：生产上要把日志目录与数据目录**分盘**（减少 IO 争用、便于保留），并且必须确认 **mysqld 的运行系统用户对该目录有读写权限**——否则日志根本写不出去，且不会报错。

**加分层**：慢查日志只记**执行成功**的查询，且不记连接/断开事件，所以它不能替代通用查询日志做客户端行为审计（见 065 卡）。

## 关键代码
```sql
SHOW VARIABLES LIKE 'slow_query_log';
SHOW VARIABLES LIKE 'slow_query_log_file';
SET GLOBAL slow_query_log = ON;
SET GLOBAL slow_query_log_file = '/data/mysqllog/slow.log';   -- 改路径后需重开才生效
SET PERSIST slow_query_log = ON;                              -- 8.0 持久化
```

```bash
# 权限核对：mysqld 运行用户必须对该目录可写
ps aux | grep mysqld | grep -v grep      # 看运行用户，通常 mysql
ls -ld /data/mysqllog                    # 属主/权限
```

## ⚠️ 原文纠错
原文关于开关、分盘与"必须保证 mysqld 启动系统用户对目录有读写权限"的描述准确，未发现技术错误。补充一点：修改 `slow_query_log_file` 后需要**重新开启**慢查日志才会切到新文件，仅 SET 路径不会立即迁移 `[经验]`。机翻音译（slockalock、slowkerlock still、setgroup、satllog）已还原为 slow_query_log、slow_query_log_file、SET GLOBAL、slow log。

## 总结与追问预判
- 默认 **OFF**、可动态开；路径分盘 + **权限**是唯二真实坑。
- 只记执行成功的查询，不记连接事件。
