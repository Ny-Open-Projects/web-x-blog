# 135 磁盘 IO 打满的三类成因与 iostat 定位

> 分类：排障/性能 | 难度：L3 | 题型：事故题 | 频率：中 | 关键词：**iostat** / **IO 100%** / **大表更新** / **临时表**
> 原文锚点：第 39~52 段「磁盘的 IO 达到了一百八十多兆每秒…io 占用率已经达到了百分之百」

## 一句话总述
用 `iostat -dm -x 1` 确认 IO 打满后，只剩三类嫌疑：**大量日志输出、大批量写、慢查询落磁盘临时表**——其中第三类最可能是真凶。

## 面试官视角
- **考察意图**：能否从"IO 满了"继续往下钻到具体写入来源，而不是停在现象层。
- **P5** 会用 `iostat` 看 IO / **P6** 能列出三类成因 / **P7** 能说出"日志是顺序写、临时表是随机写"这个关键差别。
- **红旗**：① 只说"IO 高"不定位来源；② 把顺序写和随机写混为一谈；③ 漏掉慢查询临时表。
- **惊艳点**：**日志基本是顺序写，很少把 IO 打满；磁盘临时表是随机写，才是 IO 飙升的常见元凶** `[经验]`。

## 主问答
**Q：`iostat` 看到磁盘 IO 已经 100% 了，下一步怎么定位是谁在写？**
**A：**
1. **先给结论**：先拿 `iostat -dm -x 1` 定量（本案约 180 MB/s，远超普通磁盘能力），确认"真满"而非采样抖动。
2. **再给机制**：三类来源——① 繁忙实例开了通用日志或用 **ROW 格式 binlog** 且正在大表更新；② 大表批量更新，既写 binlog 又写表文件；③ 慢查询产生大量**磁盘临时表**，随机写最容易把 IO 拉满 `[经验]`。
3. **最后给边界**：日志属顺序写，靠它打满 IO 的情况少见，排查时应把权重放到第二、三类。
**加分层**：机械盘看 `%util` 接近 100 就够了；SSD 要同时看 `await`，单看 `%util` 会误判。
