# 013 降序索引

> 分类：MySQL 8.0 新特性/优化 | 难度：L2 | 题型：概念主问 | 频率：中 | 关键词：**降序索引** / **DESC** / **真正支持**
> 原文锚点：第 268~271 段「之前只支持升序、DESC 也按升序存；8.0 真正支持降序存储」

## 一句话总述
MySQL 8.0 **真正支持降序索引存储**；此前 `DESC` 选项虽能写，但实际仍按升序存储，只能靠反向扫描。降序索引对 `ORDER BY a ASC, b DESC` 这类混合排序可免去反向读、提升性能。

## 主问答
**Q：MySQL 的降序索引是什么，有什么用？**
**A：**
1. **结论**：8.0 起索引可**真正按降序存储**；此前 `DESC` 仅语法支持，物理仍升序，排序需反向扫描。
2. **机制**：`CREATE INDEX ... (a ASC, b DESC)` 直接存降序，优化器对混合排序可顺序读取，省掉 filesort/反向扫描。
3. **边界**：降序索引主要收益在**混合排序**；纯升序/纯降序场景与升序索引无差；索引体积略增。
**加分层**：排查慢查询时先看执行计划是否用上降序索引，而非盲建。

## 关键代码
```sql
-- 混合排序场景：建降序索引避免反向扫描
CREATE INDEX idx_mix ON orders (user_id ASC, created_at DESC);
EXPLAIN SELECT * FROM orders
  WHERE user_id=10 ORDER BY created_at DESC;  -- 应走 idx_mix 顺序读
```
