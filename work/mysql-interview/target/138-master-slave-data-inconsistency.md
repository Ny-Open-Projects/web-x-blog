# 138 无延迟却数据不一致的判读与成因

> 分类：复制/排障 | 难度：L3 | 题型：事故题 | 频率：高 | 关键词：**无延迟** / **checksum 不一致** / **从库被写** / **跳过事务**
> 原文锚点：第 70~80 段「主从数据库并不存在任何延迟…相同查询在主从中得到的结果就是不一样」

## 一句话总述
**延迟为零、双线程 Yes，但数据仍不一致**——说明复制链路是通的，问题出在"数据被改了"或"回放内容本身不等价"，共三类成因。

## 面试官视角
- **考察意图**：会不会把"数据不一致"简单等同于"主从延迟"，这是最常见的误判。
- **P5** 会看 `Seconds_Behind_Master` / **P6** 能列全三类成因 / **P7** 能用 checksum 定量确认并给出修复顺序。
- **红旗**：① "不一致就是有延迟"；② 只想到从库被写，漏掉跳过事务与 statement 格式；③ 不提校验工具。
- **惊艳点**：先用 **checksum 定量**确认"确实不一致"，再谈成因——**先证明，再归因** `[经验]`。

## 主问答
**Q：主从没有延迟，但两边查出来数据不一样，可能是什么原因？**
**A：**
1. **先给结论**：复制链路正常只说明"日志传到了"，不保证"数据等价"；三类成因是**从库被写了**、**用跳过手段略过了事务**、**用了 statement 格式**。
2. **再给机制**：从库上的写不会反向同步到主库，直接产生差异；用 `sql_slave_skip_counter` 或注入空事务会让主库已执行的事务在从库不落地；statement 格式是在两端**分别执行 SQL**，遇到不确定函数就会算出不同结果 `[经验]`。
3. **最后给边界**：诊断顺序要**先看延迟和线程状态排除链路问题**，再用校验工具定量，最后才逐条对成因。
**加分层**：回答时补一句"修复前先对从库做一次备份或快照"，是运维素养的加分项。
