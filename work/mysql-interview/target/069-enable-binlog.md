# 069 启用 binlog 与 log_bin_basename

> 分类：日志类 | 难度：L2 | 题型：工程题 | 频率：高 | 关键词：**log_bin** / **log_bin_basename** / **7 位序号** / **静态参数**
> 原文锚点：第 330~345 段「5.7 之前默认情况下并不会启用二进制日志…5.7 之后 log_bin 分成了两部分：log_bin 是布尔值，log_bin_basename 代表存储目录与文件名前缀」

## 一句话总述
`log_bin` 同时指定**目录 + 文件名前缀**，实际文件是"前缀 + **7 位自增序号**"；5.7 起系统变量拆成 `log_bin`（布尔开关）与 `log_bin_basename`（路径前缀）。

## 面试官视角
- **考察意图**：考"能不能正确打开 binlog"以及是否知道文件名不是你配的那个。
- **P5** 知道配 `log_bin` 开启。
- **P6** 能说出文件由前缀 + 序号组成，未指定时落在数据目录、以主机名为前缀。
- **P7** 能点出 5.7 起变量拆分、以及它是**静态参数需重启**。
- **红旗**：① 以为 `log_bin=ON` 就够了（不配路径）；② 说"文件就叫 mysql-bin.log"；③ 不知道 8.0 默认已开。
- **惊艳点**：`log_bin` 是**静态**参数，只能改配置文件重启生效——这也是很多人"改了没生效"的原因 `[经验]` —— 验证：`SET GLOBAL log_bin=1;` 会直接报错。

## 主问答
**Q（面试官原话）：** 怎么开启 binlog？文件路径怎么定？

**A：**
1. **先给结论**：配置文件里写 `log_bin = /path/prefix`，改完**重启**生效；8.0 起默认已开启。
2. **再给机制**：等号后是**目录 + 文件名前缀**，实际磁盘文件是"前缀 + **7 位自增序号**"（如 `mysql-bin.000001`）；未指定则落在**数据目录**、以**主机名**为前缀。
3. **最后给边界**：5.7 起系统变量拆为 `log_bin`（布尔，表示是否启用）与 `log_bin_basename`（目录与前缀）；这是**静态**参数，不能在线开——所以新实例规划期就得定好。

**加分层**：开了 binlog 还必须配 `server_id`（复制环境下唯一），否则从库连不上主库——这题常连着问。

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在该怎么答 |
|---|---|---|
| ≤ 5.6 | 默认**关闭**，需手动配 `log_bin` | "5.7 前必须手动开" |
| 5.7 | 仍默认关闭；变量拆为 `log_bin` 与 `log_bin_basename` | "手动开 + 注意变量拆分" |
| 8.0 | 默认**开启** | 补一句"8.0 默认有 binlog" |

## 关键代码
```sql
SHOW VARIABLES LIKE 'log_bin';            -- 5.7+ 显示为 ON/OFF（布尔）
SHOW VARIABLES LIKE 'log_bin_basename';   -- 目录 + 前缀
SHOW BINARY LOGS;                         -- 实际文件列表与大小
```

```bash
# 配置文件（静态参数，必须重启）
# [mysqld]
# log_bin   = /data/mysqllog/mysql-bin
# server_id = 1001        # 复制环境必配，全局唯一
```

## ⚠️ 原文纠错
原文"5.7 之前默认不启用二进制日志"与 5.7 变量拆分的说明均正确，未发现技术错误。补充原文未提的两点：① `log_bin` 是**静态**参数，`SET GLOBAL` 无法开启；② 8.0 起 binlog **默认开启**，按"必须手动开"作答在新版本上不成立。机翻音译（logb、logbbasename、布尔什、序列）已还原为 log_bin、log_bin_basename、布尔值、序号。

## 总结与追问预判
- 配 `log_bin=目录/前缀`，文件是**前缀 + 7 位序号**；**静态**需重启。
- 5.7 起拆成 `log_bin` 与 `log_bin_basename`；8.0 默认开。
