# 018 原子 DDL

> 分类：MySQL 8.0 新特性/一致性 | 难度：L3 | 题型：概念主问 | 频率：中 | 关键词：**原子 DDL** / **数据字典** / **崩溃一致性**
> 原文锚点：第 294~297 段「8.0 DDL 支持原子操作，数据字典+存储引擎+binlog 合成一个事务」

## 一句话总述
MySQL 8.0 的**原子 DDL**：数据字典更新、存储引擎操作、binlog 写入被合并为**一个事务**，DDL 要么全成功要么回滚；旧版在 DDL 中途崩溃可能留下"改了一半"的中间态。

## 面试官视角
- **考察意图**：是否理解 8.0 一致性改进与旧版 DDL 的隐患。
- **P5** 知道 8.0 DDL 是原子的。
- **P6** 能说清"三件事合成一个事务"。
- **P7** 能讲旧版崩溃残留（半完成 DDL）的运维痛点。
- **红旗**：说「DDL 本来就是原子的」。
- **惊艳点**：点出原子 DDL 依赖 8.0 的数据字典（去 FRM + InnoDB 系统表），是架构变更的连锁收益 `[源码]`。

## 主问答
**Q：什么是原子 DDL，解决了什么问题？**
**A：**
1. **结论**：8.0 把 DDL 的**数据字典更新 + 存储引擎操作 + binlog 写入**合成一个事务，保证 DDL 全成功或全回滚。
2. **机制**：依赖 8.0 统一数据字典（表元数据 + 系统表 InnoDB 化），使跨组件的一致性得以用事务保证。
3. **边界**：旧版（如 5.7）DDL 中途实例崩溃可能留下部分完成的表/文件，需人工清理；8.0 从机制上消除该中间态。
**加分层**：原子 DDL 让自动化运维（批量加字段）崩溃后可安全重试，不必人工核对残留。

## 关键代码
```sql
-- 8.0 支持原子 DDL（对比旧版崩溃后的中间态风险）
ALTER TABLE orders ADD COLUMN note VARCHAR(200), ALGORITHM=INPLACE, LOCK=NONE;
-- 崩溃后：8.0 自动回滚该 DDL，无残留
```
