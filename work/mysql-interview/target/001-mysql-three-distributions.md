# 001 MySQL 三大发行版概览

> 分类：版本选型 | 难度：L2 | 题型：概念主问 | 频率：高 | 关键词：**官方版** / **Percona Server** / **MariaDB**
> 原文锚点：第 26~50 段「mysql常见的发行版本都有哪些…官方版本、percona、mariaDB」

## 一句话总述
面试里「用过哪些版本、为什么选」考的是**发行版差异与选型判断**；主流三家：Oracle 的**官方版**、Percona 的 **Percona Server**、MariaDB 基金的 **MariaDB**。

## 面试官视角
- **考察意图**：是否真懂各发行版定位，而非只会背版本号。
- **P5** 能说出三家名字与归属。
- **P6** 讲清官方版与另两家的核心差异（兼容/性能/功能）。
- **P7** 能结合业务推荐，并点出版本滞后、GTID 不互通等坑。
- **红旗**：只答「用过 5.7」不解释；把 MariaDB 当 MySQL 闭眼说 100% 兼容。
- **惊艳点**：点出 MariaDB 的 GTID 格式与 MySQL 不互通、只能作从不能作主 `[经验]`。

## 主问答
**Q：你用过哪些 MySQL 版本，为什么选它？**
**A：**
1. **结论**：主流三家——Oracle 官方版（社区/企业）、Percona Server、MariaDB，选型看兼容性、性能与功能需求。
2. **机制**：官方版生态最正统且 InnoDB 最纯；Percona 在官方版上二次开发、性能更优且自带审计/线程池；MariaDB 由 MySQL 原作者另立、10.2 起领先支持窗口函数。
3. **边界**：Percona/MariaDB 新版通常滞后官方 2~3 个月；MariaDB 与 MySQL 非 100% 兼容（GTID 算法不同）。
**加分层**：回答前可反问面试官「当前公司用哪个版本」，再结合自身经验作答更专业。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 三家名字 | 是否接触过 | 列名+归属 | 换题→不及格 |
| L2 | 官方版与 Percona 差在哪 | 是否背的 | 性能/插件/滞后 | 判 P5 |
| L3 | MariaDB 和 MySQL 兼容吗 | 踩坑经验 | GTID 不互通、只能作从 | 判 P6 |
| L4 | 高并发选哪家 | 架构判断 | 看审计/线程池/窗口函数需求 | 判 P6+ |
| L5 | 线上出过版本故障吗 | 实战经验 | 讲 JDBC 驱动不匹配案例 | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| MySQL 5.5+ / 8.0 | MariaDB 基于 5.5 分支，GTID 格式自 10.x 与 MySQL 不互通 | 仍按「三家 + GTID 不互通」答；补充 8.0 已成主流 |
