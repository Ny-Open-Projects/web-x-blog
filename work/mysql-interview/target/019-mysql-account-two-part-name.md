# 019 MySQL 账号的两段式定义

> 分类：用户管理 | 难度：L2 | 题型：八股题 | 频率：高 | 关键词：**user@host** / **用户名长度** / **访问控制列表**
> 原文锚点：第 28~32 段「用户名是由两部分来组成的，并且中间是由 @ 字符来进行分割」

## 一句话总述
一个 MySQL 账号 = **用户名 + 访问控制列表（host）**，中间用 `@` 分隔；**同名不同 host 是两个独立账号**，权限各自独立计算。

## 面试官视角
- **考察意图**：确认你理解 MySQL 账号的唯一键是两列，而不是把它当"用户名唯一"的账号体系。
- **P5** 能说出账号写作 `'user'@'host'`，两部分一起才唯一。
- **P6** 能说清用户名长度的版本翻转（5.7 前 16 字节、5.7 起 32 字节），并列举 host 的四种写法。
- **P7** 能指出 `mysql.user` 的主键是 `User`+`Host`，并据此给出"授权了却不生效"的排障路径。
- **红旗**：① 说"MySQL 里用户名不能重复"；② 把 host 当登录时才填的参数；③ 不知道 `%` 与 localhost 的区别。
- **惊艳点**：`mysql.user` 表主键是 `User` + `Host` 两列，所以 `'app'@'%'` 与 `'app'@'10.0.0.1'` 可并存且权限不同 `[源码]` —— 验证：`SHOW CREATE TABLE mysql.user;` 看 PRIMARY KEY。

## 主问答
**Q（面试官原话）：** MySQL 的一个账号到底是怎么定义的？我在两台应用机器上配了同一个用户名，算同一个账号吗？

**A：**
1. **结论**：**不算同一个账号**。MySQL 账号由**用户名**和**访问控制列表**两部分组成，写作 `'user'@'host'`，两者合起来才唯一确定一个账号。
2. **机制**：后半段 host 限定该账号可从哪些来源地址连接，支持具体 IP、`192.168.1.%` 网段、`%`（任意外部地址）、`localhost` 四种写法。
3. **边界**：用户名本身有长度上限——**5.7 之前 16 字节，5.7 起 32 字节**；超长会被拒绝，长用户名方案要提前验证。

**加分层**：授权时省略 host 会默认填 `%`，等于对除本地外任意来源开放，这是账号安全事故最常见的源头。

## 追问链
| 层 | 追问 | 在测什么 | 怎么接 | 答不出停在哪档 |
|---|---|---|---|---|
| L1 | 账号怎么书写 | 概念 | `'user'@'host'` | 换题 → 不及格 |
| L2 | 用户名最长多少 | 版本敏感度 | 16→32 字节，5.7 翻转 | 判 P5 |
| L3 | 同名不同 host 是几个账号 | 唯一键理解 | 两个，权限独立 | 判 P6 |
| L4 | 登录时要不要带 host | 客户端行为 | 不带，客户端自动识别 | 判 P6+ |
| L5 | 排过"授权了却不生效"吗 | 实战 | 查 `SHOW GRANTS FOR 'u'@'具体IP'` | 答上判 P7 |

## 版本与兼容性
| 结论成立版本 | 翻转点 | 现在怎么答 |
|---|---|---|
| 5.7 之前 | 用户名上限 **16 字节** | 老版本按 16 字节答 |
| 5.7 / 8.0 | 上限放宽到 **32 字节** | 现在统一答 32 字节，并补一句"5.7 之前是 16" |

## 关键代码
```sql
-- 建两个同名不同 host 的账号，验证它们是独立账号
CREATE USER 'app'@'%' IDENTIFIED BY 'Pwd#2026a';
CREATE USER 'app'@'10.0.0.1' IDENTIFIED BY 'Pwd#2026b';
SELECT user, host, plugin FROM mysql.user WHERE user = 'app';
-- 返回两行 → 证明唯一键是 (User, Host)
```

## ⚠️ 原文纠错
未发现技术错误。核对范围：第 28~32 段的账号组成、用户名 16/32 字节长度限制、host 四种写法，与 MySQL 官方手册一致。机翻音译（买 vito、满七十五点七、mysqit）已还原为 MySQL、5.7、@。

## 总结与追问预判
- 账号 = 用户名 + host；**同名不同 host 是两个账号**，主键是 `User`+`Host`。
- 授权省略 host 会默认 `%`，等于对外网开放。
