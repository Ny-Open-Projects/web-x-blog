# 六大数据库存储实战: HBase 的优劣势全景（上）——写廉价、扩容易，却输在索引

## 纲要

- HBase 建在 HDFS 之上，直接继承 HDFS 的 replication 与 partition 能力，天生能分片、能吃吞吐
- 基于 key-value 分片，水平扩展可靠且高可用
- 列式存储（按列簇组织）：同列簇数据集中在同一文件，跨列簇可分散存储，列可无限横向扩展，利于分析型场景
- 劣势一：自身架构复杂（ZooKeeper / HMaster / RegionServer / Client），运维成本高
- 劣势二：数据无论大小都会分片到集群，吞吐不随数据量大小明显波动；散列不佳的高吞吐场景反而不适合
- 劣势三（致命）：没有二级索引，只能走 RowKey 查询，非 RowKey 字段需借助外部存储自建索引
- 底层机制（HDFS 的 NameNode / DataNode 如何产出上述特性）留待下文，本文先给结论

## 站在 HDFS 肩膀上的三个优势

HBase 并不是一个"自己管文件"的数据库，它的数据最终落在 HDFS（Hadoop 分布式文件系统）上。正因如此，HDFS 的 replication（副本）与 partition（分片）机制被 HBase 直接复用，让它成为 NoSQL 家族里对"大数据 + 高并发"支持最到位的方案之一。

具体落到三个层面：

### 优势一：分片与吞吐来自 HDFS

因为底层是分布式文件系统，HBase 不需要自己实现一套分片调度，数据天然可以被打散到多个存储节点。写入可以分布到不同节点并行落盘，读也可以借多副本做加速。这一点是它扛高并发写入的底座。

### 优势二：key-value 分片带来可靠的水平扩展

HBase 本质是基于 key-value 的分片数据库。按 RowKey 做散列分片后，集群可以不停机地横向加节点，分片随节点数重新均衡，因此具备非常可靠、高可用的水平扩展能力。

### 优势三：列式存储（按列簇）

这里要先纠正一个常见误解：HBase 是**列式存储**，更准确地说，是按 **列簇（Column Family）** 组织的。

传统关系型数据库或很多 NoSQL 是行存储——一行数据必然落在同一个文件里，按主键或行键抓取时，一次 IO 就能把整行读出来。HBase 不同：

- **同一列簇内的列**集中存储在同一个文件系统（HFile）中；
- **不同列簇**的数据可以分布到不同的文件甚至不同的存储上。

这样做有两个直接好处：

1. 列簇本身是分布式存储的，列簇内的列可以近乎无限地横向扩展，不会因为某行字段过多而把单文件撑爆；
2. 因为同一列的数据物理上挨在一起，基于列做聚合、统计这类分析型操作非常快，适合在线实时分析场景。

> 注意：HBase 的"列"扩展是宽松 schema 的，新增列不需要像关系型数据库那样 `ALTER TABLE` 重定义历史结构，这正是它灵活的一面。

## 三个绕不开的劣势

优势讲完，劣势同样关键，而且每一项都直接影响选型。

### 劣势一：架构复杂，运维成本高

HBase 集群涉及 ZooKeeper、HMaster、RegionServer 以及相当复杂的 Client，角色多、依赖链长。要搭建并长期运维这样一套集群，需要付出不小的运营成本。即便是社区提供的集成版镜像，也只是降低部署门槛，集群本身的复杂度无法回避。

### 劣势二：吞吐不随数据量大小明显波动

因为数据是基于 HDFS 分片的，哪怕数据量很小，也会被分片到不同节点；数据量很大时也不会因此变慢。换句话说，HBase 是一个"既不会明显变快、也不会明显变慢"的存储。

这带来一个选型结论：**如果你的数据量很小、或虽然量大但 RowKey 散列效果很差，不建议选 HBase**。它擅长的是"数据量大且能均匀散列"的高并发准实时场景，小数据量下它的分布式开销反而是负担。

### 劣势三（致命）：没有二级索引

这是 HBase 最常被诟病的一点。它**只有 RowKey 这一个索引**，查询只能沿 RowKey 做散列或前缀区间扫描，语义上等价于关系型数据库的主键查询。一旦查询条件落在非 RowKey 字段上，HBase 自身没有能力建二级索引，只能全表扫描，或者借助外部缓存 / 另一套存储来自己构建二级索引。

当然，在时序类场景里，HBase 可以通过 **RowKey 编码方案**（把访问条件翻译成 RowKey 的前缀与起止区间，用 `startRow` / `stopRow` 做筛选）来弥补这一短板——这正是后续 RowKey 三段式设计要解决的问题。

## 优劣势速查

| 维度 | 结论 | 影响 |
| --- | --- | --- |
| 写吞吐 | 优势：追加写、分布式落盘 | 高并发写入廉价 |
| 水平扩展 | 优势：key-value 分片 + 副本 | 加节点即可扩 |
| 列扩展 | 优势：列式 / 列簇，schema 宽松 | 适合分析、易加字段 |
| 运维 | 劣势：ZK + HMaster + RegionServer 复杂 | 成本高 |
| 小数据 | 劣势：吞吐不随规模明显变化 | 小量场景不划算 |
| 索引 | 劣势：仅 RowKey，无二级索引 | 非主键查询需外挂 |
