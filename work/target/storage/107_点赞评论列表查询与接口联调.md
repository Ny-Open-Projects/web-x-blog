# 107. 六大数据库存储实战: 用 Java API 实现点赞评论的列表查询与接口联调

## 纲要

- 先补两个实体类的集合映射：点赞 `like`、评论 `remark` 都靠 `@Document` 指定集合名，否则数据无处落地
- 唯一索引兜底：同一用户对同一消息重复点赞会抛 `duplicate key`，天然保证"一人一赞"
- 列表查询三件套：按 `messageId` 过滤 + `limit`/`skip` 分页 + 按时间字段倒序
- 点赞列表需把 `userId` 还原成用户信息：先查出点赞记录，再按 userId 批量查用户并拼装
- Controller 层接 `messageId`（必填）、`limit`、`offset` 三个参数，对外暴露 list 接口
- 实测：列表按时间倒序正确返回

## 补上集合映射，否则写不进去

调试时发现点赞数据一直没进库——排查结果是实体类漏了集合名声明。Spring Data MongoDB 靠 `@Document` 决定文档落到哪个集合，不写就不知道往哪塞：

```java
@Document(collection = "like")
public class LikeInfo { ... }

@Document(collection = "remark")
public class RemarkInfo { ... }
```

补上之后重新发起点赞，数据顺利进入 `like` 集合。

## 唯一索引保证"一人一赞"

再点一次赞，直接抛错，错误码是 `duplicate key`：

```text
E11000 duplicate key error collection: ... like
```

这正是前面在 MongoDB 上对 `(userId,messageId)` 建唯一索引的效果——同一个用户对同一条消息只能赞一次，重复点赞在存储层就被拦下，不需要应用层先查再写。评论没有这个约束，可以重复评论。

## 点赞列表：条件 + 分页 + 时间倒序

列表查询的核心是三件事：按消息过滤、分页、按时间倒序。用 `Query` + `Criteria` 拼出来：

```java
public List<UserInfo> listLike(LikeInfo likeInfo, int limit, int offset) {
    Query query = new Query();
    // 1. 过滤：只取这条消息下的点赞
    query.addCriteria(Criteria.where("messageId").is(likeInfo.getMessageId()));
    // 2. 分页
    query.limit(limit);
    query.skip(offset);
    // 3. 时间倒序：按 likeTime 降序
    query.with(Sort.by(Sort.Direction.DESC, "likeTime"));

    List<LikeInfo> likeList = mongoTemplate.find(query, LikeInfo.class);
    // 把点赞记录里的 userId 还原成用户信息
    return likeList.stream()
            .map(like -> userInfoMapper.selectById(like.getUserId()))
            .collect(Collectors.toList());
}
```

评论列表同理，只是字段换成 `remarkTime` 和 `RemarkInfo`：

```java
public List<RemarkInfo> listRemark(RemarkInfo remarkInfo, int limit, int offset) {
    Query query = new Query();
    query.addCriteria(Criteria.where("messageId").is(remarkInfo.getMessageId()));
    query.limit(limit);
    query.skip(offset);
    query.with(Sort.by(Sort.Direction.DESC, "remarkTime"));
    return mongoTemplate.find(query, RemarkInfo.class);
}
```

要点：列表本身只存"谁赞了 / 评了"的引用（userId + messageId），展示昵称头像时再按 userId 回查用户表拼装，避免在大文档里冗余用户资料。

## Controller 暴露列表接口

最后把两个列表接到 HTTP 层。参数里 `messageId` 必填，分页参数可选：

```java
@GetMapping("/likeRemark/listLike")
public Result listLike(@RequestParam(required = true) String messageId,
                       @RequestParam(defaultValue = "20") int limit,
                       @RequestParam(defaultValue = "0") int offset) {
    LikeInfo cond = new LikeInfo();
    cond.setMessageId(messageId);
    return Result.ok(likeRemarkService.listLike(cond, limit, offset));
}

@GetMapping("/likeRemark/listRemark")
public Result listRemark(@RequestParam(required = true) String messageId,
                         @RequestParam(defaultValue = "20") int limit,
                         @RequestParam(defaultValue = "0") int offset) {
    RemarkInfo cond = new RemarkInfo();
    cond.setMessageId(messageId);
    return Result.ok(likeRemarkService.listRemark(cond, limit, offset));
}
```

## 实测验证

浏览器里带 `messageId` 调 `listLike` 和 `listRemark`：三条点赞按时间倒序返回 `3、2、1`，三条评论也按时间倒序正确列出。至此点赞评论的基础读写与列表能力用 Spring Data MongoDB 完整跑通。

## API 速览

| API | 说明 |
| --- | --- |
| `@Document(collection="like")` | 指定文档集合，缺失会导致写入无目标 |
| `Criteria.where("messageId").is(v)` | 等值条件，对应二级索引字段 |
| `Query.limit / skip / with(Sort)` | 分页 + 排序三件套 |
| `MongoTemplate.find(query,Cls)` | 执行查询，返回实体列表 |
| 唯一索引 `duplicate key` | 存储层保证一人一赞，无需应用先查 |
