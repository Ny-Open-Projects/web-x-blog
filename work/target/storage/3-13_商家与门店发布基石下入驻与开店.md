# 六大数据库存储实战: 商家入驻与门店发布的建表与接口落地

## 纲要

- 商家表 `seller` 设计：自增主键、时间字段、`seller_name` / `seller_tel` / `seller_password`、`version` 乐观锁字段
- 商家入驻即 `INSERT`：生成器产出 `SellerController`，`POST /seller/create` 调 `sellerService.save` 完成创建
- 门店表 `shop` 设计：`seller_id` 标示所属商家（多对一），在 `seller_id` 上建 B+ 树索引加速查询
- 应用层维护关系：不使用外键约束，由应用层保证数据一致性，避免级联删除/更新带来连锁问题
- 门店发布即 `INSERT`：`POST /shop/create` 调 `shopService.save`，首版 `seller_id` 误写 0 已在重创时修正

## 商家表与入驻流程

商家入驻在数据库层就是一次 `INSERT`。先建 `seller` 表：

```sql
CREATE TABLE seller (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  create_time  DATETIME,
  update_time  DATETIME,
  seller_name  VARCHAR(255) NOT NULL DEFAULT '',
  seller_tel   VARCHAR(255) NOT NULL DEFAULT '',
  seller_password VARCHAR(255) NOT NULL DEFAULT '',
  version      INT DEFAULT 0
);
```

字段说明：`seller_name` 商家名、`seller_tel` 登录手机号、`seller_password` 登录密码，均设 `NOT NULL` + 空串默认；`version` 用于乐观锁并发保护。

用代码生成器生成 `seller` 表对应的 `SellerController`，其创建方法仅一行 `save` 即完成入库：

```java
@RestController
@RequestMapping("/seller")
public class SellerController {

    @Autowired
    private SellerService sellerService;

    @RequestMapping(value = "create", method = {RequestMethod.POST})
    @ResponseBody
    public JsonReturnType create(@RequestBody Seller seller) {
        sellerService.save(seller);
        return JsonReturnType.createType(seller);
    }
}
```

`sellerService.save` 由 MybatisPlus 自动实现，内部即调用 `Mapper.insert`。用 Postman 以 `POST /seller/create` 发送 `{"sellerName":"apple","sellerTel":"...","sellerPassword":"123456"}`，首条商家记录即生成。这便完成了商家入驻的 `create` 流程。

## 门店表与发布流程

门店与商家是**多对一**关系：一个商家可拥有多家门店，一家门店只属于一个商家。先建 `shop` 表：

```sql
CREATE TABLE shop (
  id           BIGINT PRIMARY KEY AUTO_INCREMENT,
  create_time  DATETIME,
  update_time  DATETIME,
  version      INT DEFAULT 0,
  name         VARCHAR(255) NOT NULL DEFAULT '',
  address      VARCHAR(255) NOT NULL DEFAULT '',
  business_hour VARCHAR(255) NOT NULL DEFAULT '',
  seller_id    BIGINT
);

CREATE INDEX idx_shop_seller_id ON shop(seller_id);
```

两个关键设计点：

- **`seller_id` 记录所属商家**，并在其上建 B+ 树索引，使商家能快速查出自己的门店列表。
- **不使用外键约束**。互联网应用一般不在数据库层加外键，而是在应用层保证关联正确——否则联动的更新/删除会触发级联，带来性能与维护上的大问题。

同样用生成器产出 `ShopController`，发布接口与商家如出一辙：

```java
@RestController
@RequestMapping("/shop")
public class ShopController {

    @Autowired
    private ShopService shopService;

    @RequestMapping(value = "/create", method = {RequestMethod.POST})
    @ResponseBody
    public JsonReturnType create(@RequestBody Shop shop) {
        shopService.save(shop);
        return JsonReturnType.createType(shop);
    }
}
```

用 `POST /shop/create` 发送 `{"name":"陆家嘴苹果门店","address":"上海浦东新区陆家嘴","businessHour":"每日早8点至晚10点","sellerId":1}`，门店即写入。

> 调试小记：首版本地联调时 `seller_id` 被误写入 0，删除该条数据重新创建后恢复正常。这也提醒我们：关联字段在写入前一定要由调用方正确赋值，并在服务端做基本校验。

## API 速览

| 接口 / 方法 | 说明 |
| --- | --- |
| `POST /seller/create` | 商家入驻，请求体为 `Seller` |
| `POST /shop/create` | 门店发布，请求体含 `sellerId` |
| `IService.save(entity)` | MybatisPlus 基类保存，返回是否成功 |
| `CREATE INDEX ... ON shop(seller_id)` | 门店按商家查询的加速索引 |
