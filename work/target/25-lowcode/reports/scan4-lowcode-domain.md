# 低代码平台技术要点体系（领域知识整理，不限于本课）

> 本文档把"低代码平台"作为一门技术领域做体系化梳理，结合课程25（小滴课堂低代码大课）的实践样本与业界通行做法。
> 与 scan4-docs.md 的分工：那边是"这批文档讲了什么"，这边是"低代码这个主题本身的知识体系"。

---

## 0. 领域全景

低代码平台的本质一句话：**用元信息（Schema/DSL）描述应用，由通用引擎解释执行，把"写代码"变成"配数据"**。围绕这句话展开出八个技术要点域：

```
元信息驱动（哲学层）
  ├─ DSL / Schema（数据契约层）
  ├─ 物料体系（资产层）
  ├─ 渲染引擎（运行时层）
  ├─ 协议与标准化（生态层）
  ├─ 权限模型（治理层）
  ├─ 发布与部署（交付层）
  └─ 性能与稳定性（运维层）
```

---

## 1. 元信息驱动：低代码的第一性原理

- **核心思想**：UI 和逻辑不再是编译产物，而是**数据**。页面 = 一份 JSON；应用 = 一组 JSON + 一套引擎。
- **推论一**：编辑器与运行时共享同一份数据契约——编辑器是这份数据的"可写视图"，运行时是"只读投影"。
- **推论二**：一切画布操作（拖拽、排序、删除、连线）本质都是对数据结构的增删改，视图只是投影。这是所有编辑器实现的心法。
- **推论三**：因为产物是数据，所以天然具备可序列化、可版本管理、可 diff、可跨端消费（H5/小程序/桌面/服务端渲染）的能力。
- **反面边界**：元信息驱动适合"模式可枚举"的场景（表单、报表、后台、流程）；模式无法枚举的（复杂交互游戏、强定制 C 端动效）不适合。

## 2. DSL 与 Schema：数据契约层

| 形态 | 代表 | 特点 | 适用 |
|------|------|------|------|
| JSON Schema 直驱 | Amis、本课平台 | 简单直接、易序列化 | 表达力够用时首选 |
| 协议式 Schema | 阿里 LowCodeEngine（assets 协议 + schema 协议） | 物料协议、编辑器协议分层，生态开放 | 多方共建的大平台 |
| 数据绑定/表达式 DSL | Retool | 紧凑、带逻辑 | 复杂数据流 |
| 可视化逻辑编排 | 工作流产品（n8n、ComfyUI、简道云流程） | 图形化表达分支/循环 | 流程、自动化 |
| 出码路线 | 各种 lowcode-to-code | 生成源码可脱离平台 | 需要源码自主权的场景 |

**设计要点**：
1. **先固化协议再写渲染器**：组件 type 枚举、每个 type 的 props 规范、Schema 版本号。协议没定就写代码，后面必然推倒重来。
2. **Schema 必须版本化**：`schema.version` 单调递增；组件 type 对外发布后改名即破坏存量页面，破坏性变更走 version + 迁移脚本。
3. **简单逻辑进 props，复杂逻辑进 DSL/编排层**：条件显隐、跨页联动、循环分支表达式超出"表单填属性"承载力时，升级到 DSL 或可视化编排，再编译回 Schema 交给渲染器。
4. **契约唯一真源**：Schema 类型定义放共享包，编辑器/渲染器/服务端三端共用，任何端不得私自加字段。

## 3. 物料体系：低代码的"资产"

- **物料 = 平台可复用资产的统称**，分三层：
  - **基础物料**：input/select/button/form 等原子组件；
  - **业务物料/模板**：登录表单、审批页等组合块，降低从零搭建成本；
  - **区块/页面模板**：整页级复用。
- **物料规范**：每个物料需声明 `ComponentNode = {id, type, options}` 中的 type 唯一标识 + 属性 Schema（供属性面板自动生成）+ 编辑态（canvas 展示）与渲染态（真实运行）两套视图。
- **组件注册表模式**：`Record<type, Component>` 映射表是物料体系的最小可行实现；新增物料 = 登记，编辑器与渲染器自动感知。
- **进阶形态**：组件市场（第三方物料热插拔）、物料资产的版本管理与依赖隔离、自定义组件沙箱（防物料拖垮平台）。

## 4. 渲染引擎：运行时核心

- **职责**：读 Schema → 按 type 查注册表 → 摊开 props 渲染组件 → 处理数据回写（onChange → 回写 Schema）与联动。
- **关键设计**：
  - **递归渲染**支持容器嵌套（栅格/表单嵌子组件，树形 Schema）；
  - **编辑态/渲染态同构**：编辑器画布里的组件要能接受选中/拖拽等交互包装，渲染态只保留纯组件；
  - **数据绑定与作用域**：组件取数、上下文变量、表达式求值；
  - **服务端渲染出 HTML**（SSR 或直接 `renderPageToHtml`）保证首屏与 SEO。
- **编辑器侧配套**：拖拽引擎（dnd-kit / react-dnd / 自研）、状态管理（MobX/Redux/Zustand，"数组即 Schema"）、撤销重做（对 Schema 数组做命令模式快照）、画布缩放与栅格系统。

## 5. 协议与标准化

- **业界协议参照**：阿里 LowCodeEngine 的《低代码引擎搭建协议规范》《物料描述协议》、 amis 的 JSON Schema 渲染格式、OML/《Web 系统搭建协议》等社区尝试。
- **协议要解决的四件事**：物料如何描述（让属性面板自动生成）、Schema 如何描述（跨端可渲染）、事件/逻辑如何表达（扩展性）、版本如何演进（兼容性）。
- **工作流协议**：节点 `NodeContract {type, ports, execute}` + 图 DSL（nodes/edges 带端口），与页面 Schema 并列为平台两大契约；端口类型（data/schema/trigger）校验在连线时完成。

## 6. 权限模型

- **公式**：角色（Role）× 资源（页面/组件/数据）× 操作（读/写/发布/删除）= RBAC 基础；进阶加 ABAC（按属性）与数据行级权限。
- **多端差异化鉴权**（本课样本）：编辑端需登录（token→用户）、发布页免登录（凭 pageId 取数，接口不含敏感数据）、统计端登录+数据权限。
- **工程要求**：统一 Guard/中间件层鉴权，不在 Controller 散写 if；数据权限与菜单/功能权限分层；前端路由级 + 接口级双重拦截（前端藏按钮、接口不能裸奔）；多租户场景全表预留 tenant_id + 租户守卫（跨租户 403），租户隔离 ≠ 权限隔离，后者要 RBAC 第二层。

## 7. 发布与部署

- **发布语义**：草稿 → 预览 → 发布三态。发布 = 把编辑态 Schema 固化为对外可见版本；商用级要做**发布历史与回滚**（版本列表 + 一键回退）与**灰度发布**（按比例/人群生效）。
- **部署形态**：
  - 传统：Nginx 网关 + 应用多节点 + MySQL/Redis + 对象存储（OSS）+ CDN，Docker/Compose 容器化，CI/CD 流水线（本课的云效路线）；
  - 静态化：发布产物出 HTML/静态资源推 CDN，运行时压力极小；
  - 出码部署：导出源码走客户自己的 CI。
- **密钥与安全红线**：AccessKey/DB 密码/JWT 私钥只走环境变量或密钥管理服务（KMS/Vault），不硬编码不入镜像；最小权限（OSS 仅授予所需 Bucket 操作）；公网暴露接口一律鉴权；密钥定期轮换。
- **执行用户代码的安全**（脚本/AI 节点）：分级方案——进程内 vm 软隔离（超时+配额+审计）→ 容器硬隔离（一次性容器+禁网+只读根+非 root+资源限额）→ 失败自动降级；未做隔离不得对外开放脚本编辑。

## 8. 性能与稳定性

- **渲染性能**：组件懒加载/按需注册（Schema 组件多时注册表分片）、虚拟滚动长列表、memo 避免整页重渲、表达式求值缓存。
- **接口性能**：Schema 获取接口加缓存（Redis/CDN）、发布产物静态化、压测驱动优化（JMeter 线程组/聚合报告/断言，先测高频接口再针对性优化——本课 30-6 是标准案例）。
- **稳定性运维**：监控告警、日志埋点、审计日志（who/what/when/output）、限流防刷（验证码）、灰度与回滚、DB migration（生产禁用 synchronize:true）。

## 9. 低代码 vs 零代码 vs 无代码：概念边界

| 维度 | 低代码 | 零代码 |
|------|--------|--------|
| 研发介入 | 需要（写组件/接接口/改渲染器） | 不需要，纯配置 |
| 灵活度 | 高，可深度定制与系统集成 | 受平台能力边界约束 |
| 适用人群 | 研发/全栈工程师 | 业务运营/产品经理 |
| 典型产物 | LowCodeEngine、Retool、自研平台 | 简道云、轻流、表单工厂 |
| 何时选 | 业务差异化强、需深度集成、长期演进 | 标准化后台、快速交付、人力有限 |

**选型决策树（ROI 视角）**：
```
业务是否高度差异化 / 需深度集成 / 长期自主演进？
├─ 是 → 自研（前期成本高，长期可控不锁定供应商）
└─ 否 → 采购/开源：
     ├─ 要 JSON 配置出页面 → LowCodeEngine / Amis
     ├─ 要数据后台+流程 → aPaaS（简道云/轻流类）
     └─ 标准化管理后台 → Admin 框架，别造轮子
```
自研的真正价值不在省写页面时间，而在**把业务差异化能力沉淀为可复用资产**。

## 10. 自研平台的方法论缺口清单（从"能跑"到"可商用"）

1. 版本化 Schema 协议 + 组件市场；
2. DSL / 可视化逻辑编排层（条件、联动、表达式）；
3. 流程引擎（BPMN/状态机），与表单引擎解耦；
4. 统一 RBAC + 数据权限 + 多租户；
5. 监控告警、日志、灰度发布、回滚；
6. 物料资产治理（模板沉淀、评审机制、变更审计——组织侧制度）；
7. 沙箱与安全评审流程（对外开放脚本编辑的前提）。

补齐这七项，一套"课程级/能跑的"低代码平台才升级为商用技术底座。
