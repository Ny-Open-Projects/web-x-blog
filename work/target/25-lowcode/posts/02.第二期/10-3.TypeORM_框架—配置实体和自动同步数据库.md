# TypeORM 框架—配置实体和自动同步数据库

> **导语**：ORM 的核心是用实体（Entity）描述数据表。本节演示创建 User 实体、在模块中注册、借助 `synchronize` 让代码驱动数据库表字段自动同步，并验证查询接口。

## 前置知识
- 已完成 TypeORM 连接 MySQL 配置：建议先看《TypeORM 框架-轻松掌握链接 Mysql 数据库配置》。
- 掌握 Nest 资源生成命令：可参考《后端子项目 Nest 创建和项目配置》。

## 正文
### 精简默认脚手架
初始工程自带的 `AppController`、`AppService` 在本练习中用不到，先从 `app.module.ts` 中移除它们的引用，保持入口干净。

### 生成 User 模块
使用 Nest CLI 生成 RESTful 风格的用户模块：

```bash
nest g resource user
```

选择 CRUD 模式后，脚手架会生成独立的 `user` 文件夹，并自动在主模块中引入。其中 `user.entity.ts` 就是我们定义表结构的地方。

### 定义实体字段
`user.entity.ts` 用装饰器声明列：练习阶段先定义 `id`、`name`、`phone`、`password` 四个字段：

```ts
import { Entity, Column, PrimaryGeneratedColumn } from 'typeorm';

@Entity()
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  name: string;

  @Column()
  phone: string;

  @Column()
  password: string;
}
```

### 在模块注册实体
`user.module.ts` 中通过 `TypeOrmModule.forFeature([User])` 把实体注册进该模块，这样 `UserRepository` 才能注入使用：

```ts
@Module({
  imports: [TypeOrmModule.forFeature([User])],
  controllers: [UserController],
  providers: [UserService],
})
export class UserModule {}
```

### 自动同步并验证
由于 `config.ts` 里 `synchronize: true`，项目启动时 TypeORM 会按实体自动更新数据库表结构。启动后刷新数据库工具，可见 `user` 表的字段已与实体一致。

控制器里保留一个查询方法验证：

```ts
@Get()
findAll() {
  return this.userRepository.find();
}
```

用 API 工具请求 `GET /user`，即可返回库中数据，说明实体配置与自动同步均生效。本练习临时占用了 `user` 表，后续正式章节会替换回真实字段。

## 小结
- 实体用 `@Entity()` 装饰器定义，列用 `@Column()`，主键用 `@PrimaryGeneratedColumn()`。
- `TypeOrmModule.forFeature([User])` 将实体注册到具体模块。
- `synchronize: true` 让启动时代码驱动表/字段自动同步。
- 实体是 TypeORM 一切操作的基础，后续增删改查都围绕它展开。
