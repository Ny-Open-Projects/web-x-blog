# 后端子项目 Nest 创建和项目配置

> **导语**：本文承接前端子项目，用 Nest 脚手架创建后端子项目 server，并演示删除自带重复依赖、统一命名 `@lowcode/server`、重新安装依赖、启动验证返回 `Hello World`，以及清理子项目 Git 以便统一托管到远程仓库。

## 前置知识
阅读本文建议先看完《前端子项目 React 创建和项目配置》，workspace 根目录与 client 子项目已就绪。

## 正文

### 用 Nest 脚手架创建 server
进入 `packages` 目录，用 Nest CLI 初始化后端子项目，命名为 `server`：

```bash
nest new server
```

Nest 初始化完成后会自带 `node_modules`（与 Vite 不同，Vite 需手动安装）。为统一依赖管理，先把自带的 `node_modules` 删除，回到根目录重新用 workspace 安装：

```bash
# 在 packages/server 下删掉自带 node_modules 后，回到根目录
pnpm install
```

pnpm 会依据根与子项目 `package.json` 的声明，把依赖装到根 `node_modules`，server 直接复用。

### 删除重复公共依赖
打开 `server/package.json`，把已在根目录统一的类型依赖（`@types/node`、`typescript` 等）剪切删除，保持单一来源：

```bash
# 示例：从 server/package.json 移除 @types/node、typescript 等公共项
```

> server 的 `package.json`、`nest-cli.json`、`tsconfig.json`、`tsconfig.build.json` 等文件见课程代码：`代码（已8期）/8-4/lowcode/packages/server/`。

### 重命名为 @lowcode/server
把子项目名称改为从属 workspace 的 `@lowcode/server`，命名与 client 保持一致。

### 启动验证
在根目录执行根 `scripts` 中已配置的调度命令：

```bash
pnpm run:server
```

启动后访问 `localhost:3000`，接口返回 `Hello World`（即 Nest 中 `getHello()` 方法的内容），说明后端子项目接入成功。

### 清理子项目 Git
为把整体项目统一推送到远程仓库，需删除各子项目自带的 Git 与 `.gitignore`，避免 VS Code 出现多余的 Git 更改：

```bash
cd packages/client && rm -rf .git
cd ../server && rm -rf .git
```

删除后重载 VS Code 窗口（Mac：`Shift + Cmd + P` → Reload Window），左侧 Git 更改即消失，便于整体托管。

## 小结
- `nest new server` 创建后端子项目，自带 `node_modules` 需删除后由根目录统一安装；
- 剪切 server 中与根重复的公共类型依赖，单一来源；
- 重命名为 `@lowcode/server`；
- `pnpm run:server` 启动后访问 `localhost:3000` 返回 `Hello World`；
- 删除子项目 `.git` 便于整体推送到远程仓库。
