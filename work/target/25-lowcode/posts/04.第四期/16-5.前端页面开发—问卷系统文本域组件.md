# 前端页面开发—问卷系统文本域组件

> **导语**：在问卷系统组件体系中，文本域（Textarea）组件是输入框组件的“近亲”。本节课我们基于上一节输入框组件的基础，几乎零成本地复用一个配置属性面板，把单行 Input 换成多行 Textarea，从而让发布后的页面能收集用户的长文本作答内容。

## 前置知识

阅读本文前，建议先掌握《前端页面开发—问卷系统输入框组件》。文本域组件的视图组件、配置属性组件都直接沿用输入框的实现，本文只讲解两者的差异点。

## 正文

### 文本域组件与输入框组件的关系

问卷系统里，文本域组件本质上是输入框组件的一个变体：视图层唯一的区别是渲染的表单控件从单行 `Input` 变成了多行的 `TextArea`。而右侧那块配置属性面板，因为字段结构（placeholder、默认值、是否必填等）完全一致，所以本节课直接复用上一节讲解过的输入框配置属性组件，不需要重新开发。

### 在 share 公共层定义视图组件

在 `share` 公共子项目的 `src/components` 目录下，我们定义一个本地文本域视图组件（可理解为 `LowCodeTextArea`）。打开它的源码你会发现，组件内部声明的内容、props、回调，跟输入框组件几乎一模一样——不同的只是把表单控件从 `Input` 换成了 `TextArea`。

在 Ant Design（antd）里，`Input` 组件本身就提供了 `TextArea` 这个子组件，即 `Input.TextArea`，所以我们可以直接从 `antd` 的 `Input` 对象上拿到它：

```tsx
import { Input } from 'antd';

// 多行文本域，从 antd 的 Input 上取 TextArea
const { TextArea } = Input;
```

该视图组件同样暴露 `placeholder`、当前值（text）以及内容变化时的回调（`onUpdate`）。当文本域里的内容改变时，会触发对应的方法：

```tsx
<TextArea
  placeholder={placeholder}
  value={value}
  onUpdate={(e) => onUpdate?.(e.target.value)}
/>
```

### 在 client 中复用并导出

来到 `client` 子项目的 `components` 目录，输入框组件的实现我们直接沿用，只是这次额外抛出了一个 `TextArea` 视图组件（即 client 的属性组件导出表 attributeExport——源码把 textArea 也映射到输入框的配置组件）。它沿用的就是输入框的 `ComponentProps` 类型定义，配置属性面板保持不动。

也就是说，新增文本域组件的成本极低：

1. 在 `share` 层新增一个文本域视图组件，复用 `Input.TextArea`；
2. 在 `client` 层复用输入框的 props 与配置属性组件，仅导出一个 `TextArea` 视图；
3. 当发布项目调用该组件的 `onUpdate` 回调时，就能拿到访问者填进来的长文本内容，供后续问卷提交使用。

### 数据如何回流到发布页面

用户在发布后的页面填入文本域内容时，组件内部的内容变更回调会把最新值抛出去。发布页（Next.js 渲染链路）正是通过这个回调拿到用户作答数据，并在提交问卷时一并上报后端。整条数据流与输入框组件完全一致，只是承载的是多行文本而已。

## 小结

- 文本域组件是输入框组件的变体，核心区别仅在于表单控件由 `Input` 变为 `Input.TextArea`；
- 配置属性面板与输入框完全通用，直接复用，无需重复开发；
- 在 `share` 公共层定义 `LowCodeTextArea`（基于 `Input.TextArea`），在 `client` 层复用输入框的 props 与配置组件并导出文本域视图；
- 内容变更通过 `onUpdate` 抛给发布页面，最终随问卷一起提交。
