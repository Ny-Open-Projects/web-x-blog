# 前端页面开发—问卷系统单选框组件

> **导语**：问卷系统里，单选题是收集结构化答案的基础控件。本节课我们来开发单选框（Radio）组件：在 `share` 公共层提供一个基于 `Radio.Group` 的视图组件，在 `client` 层用配置面板让运营人员可配置标题、默认选项和多个候选项，并把用户选中的选项 ID 通过回调回传给发布页面。

## 前置知识

阅读本文前，建议先掌握《前端页面开发—问卷系统文本域组件》。单选框、输入框、文本域这类组件在编辑态都无法直接交互，必须发布后才由真实用户操作；同时它们都复用了课程里封装的表单容器公共组件，本文会用到 `FormContainerWithList`。

## 正文

### 单选框在编辑器中的形态

在编辑器的画布上，单选框组件做三件事：

1. 一个标题（例如“你的性别是？”），由后台在右侧配置属性里设置；
2. 一组候选项（如“男 / 女 / 不男不女”），运营可以通过右侧的“添加新项”按钮不断追加；
3. 默认会选中第一项，但可以在配置里改。

最终用户在发布后的页面点击其中一个 Radio，才算完成“选择”动作——编辑器内是点不动、也输不进内容的。

### 在 share 层定义 LocalRadio 视图组件

在 `share` 公共子项目的 `src/components` 下打开 `LowCodeRadio` 组件。它接收从父组件（经由 store 数据）传递进来的 props，并渲染标题与一组 Radio。

核心要点：

- 因为候选项可能有多项，所以要用 Ant Design 的 `Radio.Group` 来承载；
- 默认选中的值放在 `defaultRadio` 字段里；
- 提供 `onChange` 与 `onUpdate` 回调——和输入框、文本域的回调用法一致，发布项目时调用它即可拿到用户选中的内容。

属性类型定义上，单选框组件在通用属性之外多了 `defaultRadio` 和 `options` 两项：

```ts
interface RadioComponentProps {
  id: string;
  title: string;       // 组件标题
  defaultRadio: string; // 默认选中的选项 id
  options: RadioOption[]; // 候选项数组
}

interface RadioOption {
  id: string;   // 选项唯一标识
  value: string; // 选项显示的文本
}
```

### 选中逻辑：按选项 ID 比对

`options` 里每一项都是一个对象 `{ id, value }`，`value` 是展示给用户的文本，`id` 是循环遍历时的 `key` 和 Radio 的 `value`。用户点击某个 Radio 时，触发 `onChange`：

```tsx
<Radio.Group value={defaultRadio} onChange={(e) => onUpdate?.(e.target.value)}>
  {options.map((item) => (
    <Radio key={item.id} value={item.id}>
      {item.value}
    </Radio>
  ))}
</Radio.Group>
```

把当前选中 Radio 的 `id`（即 `value`）回传给父组件的 `onUpdate` 回调，父组件再与 `options` 里的 `id` 逐一比对，相等即视为选中，从而知道用户选的是第几个选项。这就是单选框与多选框的本质区别：单选只保留一个 `id`，多选则需要保存多个 `id` 的数组。

### 在 client 层实现配置属性组件

来到 `client` 子项目的 `components` 目录，右侧配置属性组件 `LowCodeRadio` 同样复用了二次封装的表单容器，顶部两块分别是：

- **标题**：普通输入框，设置组件的 `title`；
- **默认选项**：用一个 `Select` 组件来设置。它循环遍历 store 里的 `options`，按 `Select` 要求的格式 `{ value: id, label: 名称 }` 传入，value 取选项的 `id`，label 取选项的显示文本，让运营可以指定默认选中第几项。

往下就是“添加新项”，逻辑和列表组件、轮播图组件的“添加新项”完全一致——这也是我们把它封装成公共组件 `FormContainerWithList` 的原因。传入当前字段名 `keyName = "options"`，再传入 `id` 与 `items`（即 `options` 数组），由它负责渲染 `Form.Item` 的 label（选项名称输入项，`label="选项名称："`、`name="value"`）。

每次“试一试”或新增/删除选项时，`FormContainerWithList` 都会触发更新 store 里的 `state`，页面随之刷新。

## 小结

- 单选框组件在 `share` 层用 `Radio.Group` 实现，支持配置标题、默认选项和多个候选项；
- 属性类型在通用字段外新增 `defaultRadio` 和 `options`，`options` 中每项包含 `id` 与 `value`；
- 选中逻辑按选项 `id` 比对，回传给 `onUpdate` 回调，发布页据此识别用户选择了第几项；
- 配置面板复用 `FormContainerWithList` 公共组件完成“添加新项”，与列表、轮播图组件共用同一套增删逻辑。
