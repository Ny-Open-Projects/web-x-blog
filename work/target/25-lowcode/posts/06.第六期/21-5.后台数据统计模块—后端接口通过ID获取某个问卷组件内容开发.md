# 后台数据统计模块—后端接口通过ID获取某个问卷组件内容开发

> **导语**：后台统计右侧动态图表，需要在点击某个组件时按组件 ID 拉取其所有用户的填写内容。本文讲解第三个接口的实现：校验页面、按 `page_id` 查 `component_data`、用 `filter` 筛出目标组件、统一 `value` 为数组格式，并用 `flat` 降维。

## 前置知识

- 已开发获取问卷组件内容接口，见《后台数据统计模块—后端接口获取问卷组件内容开发》。
- 已了解 `component_data` 表中 `props` 为数组结构，见《低代码项目发布页面—需求分析》。
- 已掌握数组 `filter`/`map`/`flat` 操作。

## 正文

### 接口定义

在 `LowCodeController` 中新增 `getQuestionDataByIdRequest`，`POST /api/low_code/get_question_data_by_id`，需登录鉴权。解析 token 拿 `user.id`，并接收前端传来的某个问卷组件 `id`，调用同名服务层方法。

### 服务层：按组件 ID 筛选

逻辑与前一个接口类似，但多了一步精确筛选：

1. 先按 `user.id` 查 `page` 表，未发布则抛错；
2. 拿页面 ID 查 `component_data`，得到该页所有提交记录；
3. 每条记录的 `props` 是数组，用 `filter` 遍历，按组件 `id` 相等筛选出目标组件；
4. 对筛选出的对象，再用组件 ID 查 `component` 表，补全信息。

### 统一 value 为数组并用 flat 降维

返回结构统一为 `{ value, options }`：

- **value**：判断 `item.value` 是否为数组。输入型（input/textarea）的 `value` 是字符串（如「老王」），多选框的 `value` 本身就是数组；非数组包成单项数组 `[item.value]`，null 保持 null，保证前端统一处理；
- **options**：对 radio/checkbox 来自 `component.options.options`（选项列表，如男/女、游泳/篮球/按摩），输入型则为 `null`。

最后用 `.flat()` 把「数组包裹数组」降成一维数组。初次忘记 `flat` 时返回的是「数组包裹每个元素又是一个数组」，加 `flat()` 后变为「数组包裹一个大对象」，每个对象对应一个用户的该组件数据。

### 联调示例

- 查 `id=339`（radio 性别）：返回两个用户对象，老王默认选第一项（value=男，选项 ID 为空），冰冰选女（value=女，选项 ID 对应）；
- 查 `id=340`（checkbox 爱好）：老王选按摩，冰冰选游泳（第一项默认 ID 为空）；
- 查 `id=337`（input 姓名）：老王 value=老王、冰冰 value=冰冰，`options` 为 `null`。

## 小结

1. 接口 `getQuestionDataByIdRequest`（`POST`）需登录，接收目标组件 `id`。
2. 服务层校验页面后按 `page_id` 查 `component_data`，再用 `filter` 按组件 ID 精确筛选。
3. `value` 统一包成数组（非数组包成 `[item.value]`），`options` 来自 `component.options.options`，输入型为 `null`。
4. 末尾 `.flat()` 降维，返回「数组包裹对象」结构供前端画图。
