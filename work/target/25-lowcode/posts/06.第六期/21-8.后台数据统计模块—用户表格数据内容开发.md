# 后台数据统计模块—用户表格数据内容开发

> **导语**：表头就绪后，要把每个用户在 `component_data` 中的填写内容渲染成表格行。本文讲解请求「获取问卷组件内容」接口、把「数组包裹数组」结构重组成 antd Table 的 `dataSource`，并处理 radio/checkbox 的特殊取值与逗号拼串。

## 前置知识

- 已开发表头，见《后台数据统计模块—用户表格数据表头开发》。
- 已开发获取问卷组件内容接口，见《后台数据统计模块—后端接口获取问卷组件内容开发》。
- 已了解 antd Table 的 `dataSource`，见上节。

## 正文

### 请求内容接口

在 `ComponentDatas` 中定义 `dataSource` 状态（`useState`，初值空数组），用 `useRequest` 请求 `getQuestionData`（路径 `/api/low_code/question_data`）：

- 成功回调解构 `data`；
- 若 `data.length === 0`，说明无用户提交，调用父组件传入的 `handleDisable` 置灰并提示「还未有用户提交数据」；
- 有数据则走重组逻辑后 `setDataSource(...)`。

### 接口返回的数据结构

接口返回是「数组包裹两个数组」，内层每个元素是一个对象 `{ result: { id, value }, type, options }`。其中 `result.value` 即该组件用户填写值（输入框为字符串如「老王」，单选可能为空、多选为数组如 `[按摩]`）。

### 重组为 dataSource

目标格式：一个数组，每个元素是一个对象，对象的 key 是组件 `id`（与表头的 `dataIndex` 对应），value 是用户填写内容。多个对象对应多个用户。

处理步骤：

1. `data.map` 取出每个用户数组，再 `.map` 遍历其中每条，得到 `item`；
2. 取 `item.result.value` 作为 `value`、`item.result.id` 作为 `key`；
3. 为兼容 radio/checkbox 的特殊情况，先定义 `value` 变量并按类型调整：
   - `radio`/`checkbox` 若 `value` 为空 → 给默认值「选项一」（避免后续取不到值）；
   - `checkbox` 的 `value` 是数组（多选）→ 用 `join(',')` 转成逗号分隔字符串；
   - 数字类型兜底转字符串；
4. 用数组 `reduce` 累加器把 `{ key: id, value }` 聚合成一个对象（初始值 `{}`），最终得到「每个用户一条记录」的对象；
5. 多条记录组成 `dataSource` 数组传给 `Table`。

`reduce` 为什么初始值是 `{}` 而非 `0`：这里不是累加数字，而是往一个对象里不断新增「组件ID → 填写值」属性。

### 注意事项

- 直接用组件 `id` 当 key 在 Table 内部循环时会触发 React key 冲突警告（多条记录各自带 337/338…），课程中暂忽略该警告，重点是数据正确渲染；
- 单选/多选的选项 ID 与「组件 ID」要区分清楚：组件 ID 是 337 这类，选项 ID 是男/女各自的子 ID；
- 处理完可打印中间结果核对：每个对象含 337→老王、338→小滴课堂讲师、339→男、340→按摩，第二条为冰冰的数据。

## 小结

1. `useRequest` 请求 `getQuestionData`，无数据则置灰提示。
2. 接口返回「数组包裹数组」，需两层 `map` 取出 `{ result:{id,value}, type }`。
3. 用 `reduce`（初始值 `{}`）把每条 {id,value} 聚合成「一个用户一条记录」的对象。
4. radio/checkbox 空值给默认、多选数组 `join(',')` 转字符串；组件 ID 当 key 会有警告但数据正确。
