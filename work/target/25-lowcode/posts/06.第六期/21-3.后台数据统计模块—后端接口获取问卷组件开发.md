# 后台数据统计模块—后端接口获取问卷组件开发

> **导语**：后台统计的第一个接口是「获取问卷组件」，用于渲染左侧表格表头和右侧组件列表。本文讲解如何在 `LowCodeController` 中新增该接口、用 TypeORM 的 `In` 操作符一次性查出四种问卷类型组件，并强调它与「填写内容」接口的区别。

- 已掌握 TypeORM 查询与 `In` 操作符，见《TypeORM 框架—一对多关系表关联和查询》。

## 正文

### 接口定义与鉴权

在 `LowCodeController` 中新增 `getQuestionComponents`，路径 `question_components`，使用 `GET` 请求。该接口属于后台，必须登录——通过 `getUserMess` 装饰器解析 token 拿到 `user.id`，未登录用户无权访问统计数据。

注意区分两类用户：此处是「在平台注册、发布页面的运营者」，不是「填写问卷的访客」。

### 服务层查询四种问卷类型

服务层方法 `getQuestionComponents(user)（控制器传整个 user）` 查询 `component` 表，条件是 `type` 属于四种问卷类型：`input`、`textarea`、`radio`、`checkbox`。

若逐个类型查询需发多次请求，因此用 TypeORM 的 `In` 操作符一次性匹配：

```ts
this.componentRepository.find({
  where: { account_id: user.id, type: In(['input', 'textArea', 'radio', 'checkbox']) },
});
```

`In([...])` 满足括号内任一类型即可查出，避免了拼接多个 `type` 条件。查出的正是发布页面时存入 `component` 表的这些问卷组件（输入框、文本域、单选、多选），而列表/卡片/图片等非问卷组件会被过滤掉。

### 返回与联调

查询结果（含 `type`、`page_id`、`account_id`、`options` 等）直接返回前端，用于渲染表头。注意 `options` 中存的是组件配置（如多选框「爱好」及选项 游泳/篮球/按摩 与各自选项 ID），并非用户填写内容。

Apifox 联调时需在 `headers` 的 `Authorization` 带 `Bearer <token>`（注意 Bearer 后有一空格），发请求即可拿到满足条件的全部问卷类型组件记录。

## 小结

1. 接口 `getQuestionComponents`（`GET /api/low_code/question_components`）需登录鉴权，凭 token 取 `user.id`。
2. 服务层查 `component` 表，用 `In(['input','textArea','radio','checkbox'])` 一次查出四类问卷组件。
3. 返回的是组件配置（含 `options` 选项列表），不含用户填写内容。
4. 注意区分「平台运营者」与「问卷访客」两类用户。
