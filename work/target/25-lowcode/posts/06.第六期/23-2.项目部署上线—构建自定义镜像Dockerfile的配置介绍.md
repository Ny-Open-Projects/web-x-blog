# 项目部署上线—构建自定义镜像Dockerfile的配置介绍

> **导语**：部署这一章的起点，是先把 Dockerfile 读明白。本文按课程笔记梳理自定义镜像里最常用的指令——`FROM`、`RUN`、`CMD`、`EXPOSE`、`ADD`/`COPY`、`WORKDIR` 等，再用一个 Node 后端服务的 `server.Dockerfile` 串起完整流程，最后交代本项目的部署分工：React 编辑平台走 OSS，Next.js 发布页与 NestJS 后端才需要打成镜像。

## 正文

### 文件命名与官方文档

Dockerfile 的官方文档内容非常多，自学效率不高；想深入拓展时再查官方文档，本节只聚焦配置自定义镜像时**常用的指令**。文件命名上，配置文件以 `.Dockerfile` 作为后缀（`Docker` 的 `D` 大写），例如给前端自定义镜像命名成 `front.Dockerfile`。

### 常用指令一览

| 指令 | 作用 |
| --- | --- |
| `FROM` | 指定依赖的基础镜像（环境），如 React 项目依赖 Node，可写 `FROM node:18` |
| `MAINTAINER` | 镜像维护者姓名，可有可无 |
| `RUN` | 容器**构建时**执行的命令 |
| `CMD` | 容器**启动时**执行的命令，通常是数组形式 |
| `EXPOSE` | 对外暴露的端口 |
| `ENV` | 设置环境变量 |
| `ADD` / `COPY` | 把宿主机文件复制进镜像，需指定好路径 |
| `VOLUME` | 数据保存与持久化，容器路径与服务器路径做映射 |
| `USER` | 指定运行容器时的用户名，可有可无 |
| `WORKDIR` | 配置工作目录，指定运行时去哪个目录找代码与环境 |
| `ONBUILD` | 被作为基础镜像时执行的命令，较少用 |

几点说明：

- `FROM` 后面接空格再写镜像名，带版本时写成 `node:18` 这种形式。
- `RUN` 与 `CMD` 容易混：前者在构建镜像时跑，后者在启动容器时跑。想在 `CMD` 里用 `pnpm`，得先 `RUN npm install -g pnpm` 全局装好；启动前端项目一般就是 `pnpm run dev`。
- `EXPOSE` 声明容器向服务器暴露的端口（比如 3000），外部访问服务器时也要用对端口。
- `ADD` 与 `COPY` 都用于把宿主机上已上传的代码复制进镜像、需要指定路径；两者在是否自动解压归档文件等细节上有区别，配置时以官方文档为准。
- `VOLUME` 做的是容器内外路径的一一映射，用来持久化数据。

### 一个 Node 后端服务的例子

下面是一份按本节讲解整理的**语法示意**（不代表工程里的具体文件），对应 `server.Dockerfile`：

```dockerfile
# 语法示意：按本节讲解整理，不代表工程中的具体文件
FROM node:16-alpine
ADD ./server /app
WORKDIR /app
RUN npm config set registry <国内镜像源>
RUN yarn install
RUN pnpm add -g pm2
EXPOSE 8081
CMD ["pnpm", "run", "start"]
```

逐段对应讲师的思路：

- 基础镜像选 `node:16`，带 `alpine` 后缀的镜像体积更小。
- `ADD` 把宿主机上的代码复制进镜像，`WORKDIR` 把工作目录设成 `/app`——Dockerfile 一般就放在代码工作区里。
- 代码就位后还要装环境：`RUN` 设置国内 npm 镜像源加速下载，再用 `yarn` 安装依赖。
- 全局安装 `PM2`，用于在服务器里启动 Node 后端服务；配合配置文件还能一次管理、监控多个 Node 应用。
- `EXPOSE 8081` 声明端口，访问时除了 IP（或映射好的域名），端口号也必须写对。
- 最后用 `pnpm run start`（或 PM2 配合配置文件）把服务跑起来。

执行 Dockerfile 时，文件里写好的这些命令会依次被执行，最终生成一个镜像。

### 本项目的部署分工

课程里一共有三个项目：

- **React 编辑平台**：单页应用（SPA），不需要打镜像，直接放到阿里云 OSS 的 Bucket，指定好 `index.html` 作为访问入口，再绑定域名就能访问。
- **Release 发布页面**：Next.js 服务端渲染项目。
- **后端服务**：NestJS。

后两者要跑在服务器里，所以需要用 Dockerfile 各配好一个镜像。之后通过阿里云云效自动拉取代码、执行对应 Dockerfile、把镜像上传到**镜像仓库**，再在服务器上拉取运行，项目就启动起来了。本节先把指令认全，下一节开始给真实项目写 Dockerfile。

## 小结

- 自定义镜像文件以 `.Dockerfile` 为后缀（`D` 大写），如 `front.Dockerfile`。
- `FROM` 定基础环境，`RUN` 构建时执行、`CMD` 启动时执行，`EXPOSE` 声明端口。
- `ADD`/`COPY` 复制宿主机文件，`WORKDIR` 指定工作目录，`VOLUME` 做持久化映射，`ENV`/`USER`/`MAINTAINER`/`ONBUILD` 按需使用。
- 示例 `server.Dockerfile` 里用 `alpine` 减小体积、设国内镜像源、`yarn` 装依赖、`PM2` 管进程、暴露 8081。
- React SPA 放 OSS；Next.js 发布页与 NestJS 后端打成镜像，经云效上传镜像仓库后在服务器运行。
