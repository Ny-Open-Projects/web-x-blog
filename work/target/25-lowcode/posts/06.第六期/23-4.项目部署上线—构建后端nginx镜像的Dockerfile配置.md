# 项目部署上线—构建后端nginx镜像的Dockerfile配置

> **导语**：前端用户量上来后，直连单台后端服务器扛不住高并发，需要在中间加一层 Nginx 做反向代理与负载均衡。本文讲清后端 nginx 镜像的 Dockerfile 怎么写、`nginx.conf` 里 `upstream`、`location`、`worker_connections` 各自管什么，以及权重如何决定各台服务器分到的连接数。文末还会记一个很容易犯的命名错误：后端配置别写成 `release`。

## 前置知识

需要先理解自定义镜像与 Dockerfile 的基本结构，建议看过《项目部署上线—构建自定义镜像的利器 Dockerfile》与《项目部署上线—构建自定义镜像Dockerfile的配置介绍》；本节紧接《项目部署上线—构建后端镜像的Dockerfile配置》，把「后端服务镜像」再包一层 nginx 代理。DevOps/CI-CD 的整体背景见《项目部署上线—互联公司的DevOps和CI-CD你知道多少？》。

## 正文

### 为什么需要这一层 Nginx

正常情况前端直连一个后端服务。但用户量多、并发高时单台服务器不够，需要横向加几台。前端代码里写死连某台服务器显然不行，于是在中间加一层 Nginx：前端统一连 Nginx，由它按配置的权重把请求转发到后端的多台服务器。

比如再增加一台服务器（IP 加端口，例如 5002），在 `upstream` 里多写一条 `server`，把权重设成 2，它就会比权重 1 的机器分到更多连接——当然，这也要求那台机器本身配置更好、能扛更大压力。这就是通过 Nginx 实现负载均衡的价值。

### Dockerfile：基础镜像、配置、端口

在根目录新建 `server.nginx.Dockerfile`（后端服务对应的 nginx 镜像），三步：

- **基础镜像**：`FROM nginx:1.25.0-alpine`。`1.25.0` 是版本号，后面的 `-alpine` 后缀代表精简版镜像，体积更小，适合部署。
- **复制配置**：配置文件没有压缩，用 `ADD` 即可，把根目录下的 `nginx/server.nginx.conf` 复制进容器的 `/etc/nginx/nginx.conf`，覆盖默认配置。相当于重新编辑默认 `nginx.conf`：写了的模块按我们的配置生效，没写到的模块继续用默认值。
- **暴露端口**：`EXPOSE 80`，对外抛出 80 端口。

### 目录规划与命名坑

根目录建一个 `nginx/` 目录，用来同时维护后端 `server` 与发布页 `release` 两套 nginx 配置。这里踩过一个命名错误：配置文件一开始写成了 `release.nginx.conf`，Dockerfile 里也照着复制；但本节做的是**后端服务**的 nginx，不是发布页面项目，所以必须改成 `server.nginx.conf`，Dockerfile 里的复制路径也要同步改掉。命名和用途对不上，容器启动时就会去找错误的文件，排查起来很费时间——配置类文件尤其要养成「改一处、查全部引用」的习惯。

### `nginx.conf` 的关键模块

配置里几个核心块：

- **`http {}`**：一个大对象，负载均衡相关配置写在里面。
- **`upstream backend { ... }`**：`upstream` 是固定写法，用来定义一组后端服务器并做负载均衡。每条 `server IP:端口 weight=N` 代表一台机器，权重越高分到的连接次数越多。`backend` 这个名字不是随便起的，后面 `location` 里要一一对应。
- **`server { listen 80; location / { proxy_pass http://backend; } }`**：监听 80 端口，把请求反向代理到名为 `backend` 的 upstream。当前只支持 HTTP；如果配了证书要走 HTTPS，就需要加 S 并补相应配置。其余保持默认即可。
- **`events { worker_connections 1024; }`**：限制同时处理的连接数。设太高会耗尽服务器资源，设太低则新连接可能被拒绝，要按服务器实际负载与可用资源调整。

Nginx 配置模块很多，靠死记不现实，遇到陌生模块查官方文档；想系统补基础可以看官网的 Nginx 专题课程。课程笔记里给出了可直接复制的固定写法，实操时以笔记与官方文档为准。

## 小结

- Nginx 反向代理让前端统一连代理层，再按权重转发到多台后端，支撑高并发。
- `server.nginx.Dockerfile`：`FROM nginx:1.25.0-alpine` + `ADD ./nginx/server.nginx.conf /etc/nginx/nginx.conf` + `EXPOSE 80`。
- 配置文件未压缩用 `ADD`；写入的模块生效，未写的模块沿用默认。
- `upstream backend` 里每条 `server ... weight=N` 决定分发权重；`location` 的 `proxy_pass` 名字必须与 upstream 一致；`worker_connections 1024` 按实际负载调整。
- 后端配置应命名 `server.nginx.conf`，别误写成 `release.nginx.conf`，Dockerfile 复制路径要同步。
