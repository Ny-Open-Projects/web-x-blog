# 全栈高级工程师简历—低代码项目大课项目讲解

> **导语**：课程走到最后一集，我们要把这套低代码平台项目正式写进简历。要点不是堆砌名词，而是按「项目名称 → 项目描述 → 分模块技术栈 → 个人职责 → 项目亮点」的结构，把课程里真实做过的东西讲清楚。本文逐块拆解简历里这个项目的写法，并纠正几处常见的名词笔误。读完后你能对照自己的掌握程度做取舍，也能应对面试官追问"亮点"和"难点"。

## 正文

### 项目名称与描述

简历里第一个项目是前端大课的项目，没学过、不掌握就别硬写；低代码平台项目则是本大课的主项目。项目名称可以写「小滴课堂低代码平台项目」——它带问卷系统，能发布出问卷系统与官网系统。若自己公司业务正好适合，也可以把它写成实际参与的项目，因为学完大课后你对它已有足够了解。

综合描述要简洁，抓住最大功能点：低代码平台让运营、产品经理或不具备代码开发能力的人，也能发布自己的官网与问卷系统，从而大幅提高项目开发时效、节省企业的开发人力成本。项目里的多个子项目，用 **pnpm workspace** 统一维护。

### 技术栈按模块分点列举

别把技术名词乱写成一坨，按模块分点，面试官一眼就能看清。

**前端**：React、服务端渲染 Next.js、图表 ECharts、TypeScript 静态类型校验、MobX 公共状态管理、Ant Design 等第三方样式组件库、Tailwind CSS、拖拽排序 @dnd-kit。

**后端基础设施**：Node.js + NestJS 框架开发接口，TypeORM + MySQL 数据库，Redis 缓存。这里提醒一处笔误：简历里若把 TypeORM 多写成一个 `OM`，记得删掉。

**第三方服务**：阿里云服务器、阿里云 OSS 管理静态资源（图片、视频访问更快，也节省部署服务器的内存），以及用 JMeter 做接口压测、优化后对比不同接口的 TPS。

**运维**：DevOps 部署链路用阿里云 ECS、OSS、云效 DevOps 与 Docker；Docker 生成自定义镜像、运行容器把项目在服务器里跑起来；Nginx 反向代理实现负载均衡，避免请求全压在单台服务器上，提高多服务器场景的利用率。

三个子项目的落点也要写清楚：React 编辑平台部署在 OSS，Next.js 服务端渲染项目与 NestJS 后端服务部署在自己的服务器。

### 个人职责：写真实做过的东西

个人职责可以写"小组组长 / 负责开发组"，再分点列负责内容。这些内容都对应课程里写过的代码，不是凭空编的：

- **低代码编辑端**：用 @dnd-kit 实现组件拖拽排序、键盘快捷键操作，并同步组件状态；封装自定义 Hooks 处理组件键盘事件、用户登录权限、组件选中移动、全局页面信息（代码在 `packages/client/src/hooks`）。
- **React 渲染优化**：用 `useMemo` 优化渲染、简化对象与数组数据的生成逻辑；用高阶函数封装组件实现高复用；全项目 TypeScript 静态类型校验，开发阶段就能更早发现类型问题。
- **第三方 Hooks 与组件二次封装**：用 ahooks 优化代码逻辑（如 `useRequest` 请求接口、`useTitle`），并二次封装 Ant Design 样式组件。
- **全局状态管理**：MobX 集中管理各模块公共数据，用 `observer` 实现响应式。这里有个易错点：Vuex 的数据源码默认就是响应式的，而 MobX 里若要让组件随变量更新，必须用 `observer` 包裹组件。
- **DevOps**：CI/CD 流水线结合 Docker 与阿里云 ECS 实现前后端及服务端渲染项目一键部署；OSS 存静态资源优化服务器空间。
- **服务端渲染与 SEO**：用 Next.js 实现服务端渲染，让发布后的问卷系统、官网页面在被其他用户访问时获得 SEO 优化。（简历里若写成 "Nest 框架实现服务端渲染" 要改回 Next.js，这是两处容易混的名词。）
- **跨项目复用**：pnpm workspace 维护多个子项目，最大程度实现组件、类型、依赖的复用。工程里除 client、server、release 外还有 `share` 公共子项目：Ant Design 样式组件 client 与 release 都用；`types` 集中放低代码、资源、用户相关的 entity 与 request 入参类型；`utils` 放"从对象指定属性返回新对象""根据输入字符串计算数据类型"等工具方法，`componentExport`（share/src/utils/componentExport.ts）做统一导出。
- **后台数据统计**：自定义字段生成在线 Excel 预览、压缩文件下载，按不同字段动态生成图表统计用户数据；前后端交互用 Nginx 反向代理与负载均衡。

对自己不熟悉的模块，建议回看对应课程：从零到一怎么实现、用了什么技术栈、具体怎么落地、有没有更好的方案。不熟的点可以适当删减，但删减前先补一遍课更稳妥。

### 项目亮点：面试官追问时讲这些

"项目有什么亮点 / 遇到过什么困难"是高频追问，可以准备以下几条：

- 组件、类型、依赖借助 pnpm workspace 做到最大程度的跨项目复用；
- 拖拽排序（@dnd-kit）与键盘操作；
- 云服务器上一键部署前后端项目，Docker 生成自定义镜像并运行容器；
- Redis 自定义 key 值；企业级图形验证码、短信验证码与图形验证码 + 短信验证码防刷、基于 MD5(ip+ua) 匿名标识的防重复提交；
- 自定义在线 Excel 预览与压缩文件下载。

其中图形/短信验证码这条要讲出业务动机：第三方运营商按套餐收费，注册、登录接口若被盗刷或频繁获取验证码会产生真实成本，所以才需要图形验证码拦截与防重提交。这类"为什么做"的解释，比单纯罗列技术更能打动面试官。

## 小结

- 结构固定：项目名称 → 项目描述 → 分模块技术栈 → 个人职责 → 项目亮点。
- 项目描述抓核心：让非开发人员也能发布官网与问卷系统，提效、省人力。
- 技术栈按前端 / 后端 / 第三方服务 / 运维分点，注意 TypeORM、Next.js 等名词别写错。
- 个人职责只写课程里真实实现过的：@dnd-kit、自定义 Hooks、useMemo、ahooks、MobX + observer、DevOps、share 复用、数据统计。
- 三个子项目部署位置要区分：React 上 OSS，Next.js 与 NestJS 上自有服务器。
- 亮点要能讲清"为什么做"，例如验证码防刷背后的套餐成本。
