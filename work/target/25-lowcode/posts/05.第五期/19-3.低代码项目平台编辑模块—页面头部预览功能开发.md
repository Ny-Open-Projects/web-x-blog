# 低代码项目平台编辑模块—页面头部预览功能开发

> **导语**：草稿功能做完，编辑页头部还差「预览」。点一下预览，就要把当前画布存成草稿、跳到新路由、并按发布后的真实样式渲染出来。本文讲清这三步怎么串：按钮里写缓存、`useNavigate` 跳路由、Preview 页在 `useEffect` 里从本地缓存恢复组件，以及为什么预览页仍然复用编辑页那套 `generateComponent` 渲染链路。

## 前置知识

建议先读《低代码项目平台编辑模块—页面头部草稿功能开发》，此时「把组件配置、排序、选中态写入 `localStorage`」与「从本地 / 服务端读取组件」两个方法都已就绪。另需熟悉 `react-router-dom` 的 `useNavigate`、React 的 `useEffect`，以及 MobX `observer` 包裹组件的写法。配套工程见 `代码（已8期）/代码（已8期）/19-3/lowcode/`。

## 正文

### 预览效果与背后的草稿逻辑

在画布里放好列表、卡片、文本、轮播图等组件，点击头部「预览」，页面会跳转到 `/preview`，展示的正是发布之后的实际效果。再换一批组件（比如二维码、警告）点预览，同样会提示「保存成功」，新页面里只出现这两个组件。

关键在于：预览功能本身**包含了草稿功能**。用户点预览，就等于要把当前页面配置存入草稿，所以系统自动执行这一步，随后预览页再从草稿里读取数据。这样既不会丢编辑现场，也能保证预览看到的是最新一次改动。

### 按钮：写缓存 + 跳路由

在页面头部 `Center` 的预览按钮上绑定 `onClick={handleGoPreview}`，方法里做两件事：

```ts
const navigate = useNavigate();

const handleGoPreview = () => {
  // 1. 复用草稿功能：把配置、排序、默认选中三个变量写入 localStorage
  storeInLocalStorage();

  // 2. 跳转到预览路由
  navigate('/preview');
};
```

`storeInLocalStorage()` 对应上一节在 `useStoreComponents` 里定义好的「将组件储存在本地缓存中」函数，直接调用即可，不必重写（读取方法则是 `localStorageInStore`，见下文）。

跳转前还有个前提：路由表里要新增 `/preview` 路径与对应的页面组件。预览页放在 `pages` 下，与 `editor`、`index`、`loginOrRegister` 同级；根 `package.json` 里各子包的启动脚本也早已备好：

```json
{
  "scripts": {
    "run:client": "pnpm --filter client run dev",
    "run:server": "pnpm --filter server run start:dev",
    "run:release": "pnpm --filter release run dev",
    "build:client": "pnpm --filter client run build",
    "build:release": "pnpm --filter release run build"
  }
}
```

### 预览页：挂载时恢复数据

预览页外层是发布后的容器样式，内部两块内容：

- `PreviewCanvas`：真正渲染组件的子组件；
- antd `FloatButton`：返回按钮，带一个图标，点击时调用 `navigate(-1)` 返回上一级（编辑页）。

数据恢复放在 `useEffect` 里，页面挂载时执行上一节开发的 `localStorageInStore` 读取方法：从本地缓存（或从服务端）取组件信息，检查是否有值并对比操作时间，决定读本地还是读服务端。服务端读取那部分逻辑会在后续课程补上，当前阶段只走 `localStorage` 这条链路。

### PreviewCanvas：复用编辑页的渲染链路

`PreviewCanvas` 用 MobX 的 `observer` 包裹——只要用到 store 里的变量、且希望变量变化时组件自动重渲染，就必须这么包。内部逻辑与 `EditCanvas` 几乎一致：

```tsx
const PreviewCanvas = observer(（源码 PreviewCanvas 无 props，内部 useStoreComponents() 自取） => (
  <>
    {store.sortableCompConfig.map((id) => {
      const config = getComponentById(id);
      return <Fragment key={id}>{generateComponent(config)}</Fragment>;
    })}
  </>
));
```

循环遍历 store 的排序数组 → 每个 ID 调 `getComponentById` 拿到完整配置 → 传给 `generateComponent` 生成组件。而 `generateComponent` 里又是 `getComponentByType(type)` 从 `share` 的 `componentList` 取组件、`toJS` 把 MobX 代理对象转普通对象、再展开 props 渲染。

也就是说，预览页没有另写一套渲染器，完全复用编辑页打磨过的那条链路。区别只在于数据来源：编辑页靠用户点击 `push` 往 store 里加，预览页靠 `useEffect` 从缓存里恢复。

## 小结

- 预览包含草稿：点击时先把当前配置写入 `localStorage`，再从草稿读取渲染。
- 按钮逻辑两步：调 `storeInLocalStorage()` 写缓存（localStorageInStore 是读取函数），`useNavigate()` 跳 `/preview`；路由表需先注册该路径。
- 预览页在 `useEffect` 中恢复数据，对比操作时间决定读本地还是服务端。
- `PreviewCanvas` 必须用 `observer` 包裹，才能随 store 变化自动重渲染。
- 渲染链路与 `EditCanvas` 完全一致：`getComponentById` → `generateComponent` → `getComponentByType` → `toJS` → 展开 props。
