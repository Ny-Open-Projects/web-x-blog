# 低代码项目平台编辑模块—阿里云_OSS_资源上传配置

> **导语**：前面我们已经把低代码平台的所有前端组件开发完成，并实现了编辑模块的“发布接口”与“页面组件获取接口”。但图片、视频这类大资源还差对应的处理能力。本节课我们先把阿里云 OSS 的接入配置搭好——创建动态模块、在 `config` 中填入密钥与 Bucket 信息、接入 multer 文件中间件，并封装好 `uploadToAliOss` 上传方法，为下一节的上传接口开发铺路。

## 前置知识

阅读本文前，建议先掌握《后端接口开发—低代码项目编辑模块页面组件获取接口》。本文是在 server 子项目里新增一个资源处理模块，沿用此前 `redis.module.ts`、`wechat-login-tool.module.ts` 等模块的动态模块写法，与 Redis 模块的配置思路一致。

## 正文

### 为什么要接 OSS

在编辑页面里，用户点击图片或视频组件后会上传本地资源。如果把这些图片、视频都存到自己的应用服务器上，既要占用磁盘，又要承担带宽压力。所以更合理的做法是：把静态资源托管到阿里云 OSS，上传成功后拿到一个可访问的 URL，前端只存这个 URL 即可。

本节课只做“配置 + 上传方法封装”，真正暴露成 HTTP 接口放到下一节讲。

### 创建 OSS 动态模块

在 server 子项目的 `src/utils/modules` 下，我们新建 `ali-oss.module.ts`。此前的 `redis.module.ts`、`wechat-login-tool.module.ts` 等公共模块都维护在这里，阿里云 OSS 同样作为一个可全局复用的公共模块。

它是一个**动态模块（Dynamic Module）**：通过 `@Module` 装饰器声明，内部先定义一个私有变量 `aliOss` 作为阿里云 OSS 实例（从 `ali-oss` 这个 npm 包引入）。配置 `aliOssConfig` 的类型也来自 `ali-oss` 包。

```ts
import * as OSS from 'ali-oss';
import { Module, Global } from '@nestjs/common';

@Global()
@Module({})
export class AliOssModule {
  private static aliOss: OSS;

  // 动态模块入口，调用时把 options 传进来
  static forRoot(options: OSS.Options) {
    this.aliOss = new OSS(options);
    return {
      module: AliOssModule,
      providers: [{ provide: 'ALI_OSS', useValue: this.aliOss }],
      exports: ['ALI_OSS'],
      global: true,
    };
  }
}
```

`providers` 数组里放入 OSS 实例，并通过 `global: true` 声明为全局模块——这样其它模块（上传、删除、获取）都能直接注入使用，不必反复 import。

### 在 config 中填写阿里云配置

具体的连接信息写在最外层的 `config.ts` 里，备课阶段已经提前填好。一份典型的 `aliOss` 配置包含：

```ts
export const aliOssConfig = {
  region: 'oss-cn-guangzhou',        // OSS 所在地域，这里用的是广州
  accessKeyId: '你的AccessKeyId',     // 阿里云账号 > AccessKey 管理里创建
  accessKeySecret: '你的AccessKeySecret',
  bucket: 'local-is',                 // 你创建的 Bucket 名称
  // endpoint / 自有域名（CNAME）后续用于替换默认域名
};
```

几点注意事项：

- **accessKeyId / accessKeySecret**：在阿里云控制台“AccessKey 管理”中创建，创建时系统会给你一次密钥，**secret 只展示这一次**，务必保存好，之后无法再查询，只能重新创建；
- **bucket**：讲师在阿里云上创建的 Bucket 叫 `local-is`；
- **自有域名**：讲师通过 `16web.net` 解析出一个带 `local` 前缀的 CNAME 域名，用来替换 OSS 默认域名，让访问地址更短、更可控。

### 接入 multer 处理文件上传

上传接口前端会以 `multipart/form-data` 形式把文件作为参数传进来。为了在 NestJS 里以对象形式拿到 `file`（即 `Express.Multer.File`），需要安装并使用 `multer` 中间件，同时装上 `@types/multer` 类型声明，否则 `express.multipart.file` 会报“找不到”的警告。

```bash
pnpm add multer
pnpm add -D @types/multer
```

NestJS（底层基于 Express）全局启用 multer 后，上传的文件就能以对象参数形式进入我们的方法，方便取 `file.originalname`、`file.buffer` 等字段。

### 封装 uploadToAliOss 方法

资源处理模块里最核心的就是 `uploadToAliOss(file)` 方法，调用方传入一个 `file` 对象。处理流程如下：

**1. 文件名编码修正**

原始文件名可能是 `latin1` 编码，先用 `buffer` 转成 `utf-8`，保证中文名不乱码：

```ts
const fileName = Buffer.from(file.originalname, 'latin1').toString('utf-8');
```

**2. 生成两个路径**

- OSS 存储路径：资源最终放在阿里云 OSS 的哪个位置；
- 本地临时路径：上传前文件先落盘到本地临时目录，上传完即删。

**3. 拼接 OSS 路径**

约定一个固定文件夹 `upload_files`，再拼上“原始文件名 + 时间戳 + 扩展名”：

```ts
const name = fileName.split('.')[0];          // 原始文件名（不含扩展名）
const ext = fileName.split('.').pop();         // 扩展名（最后一个元素）
const ossPath = `upload_files/${name}-${Date.now()}.${ext}`;
```

例如原名 `qd.png`，最终会变成 `qd-<时间戳>.png`，避免重名覆盖。

**4. 调用阿里云 put 并清理本地文件**

```ts
await this.aliOss.put(ossPath, localTempPath);
// 无论成功失败，都删除本地临时文件
（成功失败都清理）`.finally(() => { unlinkSync(localPath) })`;
```

`put` 的第一个参数是 OSS 目标路径，第二个参数是本地源文件路径。上传结束后务必调用 Node.js `fs` 的 API 删除临时文件，不占用磁盘。

**5. 处理返回 URL，替换默认域名**

`put` 成功后返回 `url` 和 `res`，当 `res.status === 200` 时拿到资源路径。默认返回的是阿里云默认域名，形如：

```
https://local-is.oss-cn-guangzhou.aliyuncs.com/fs/qd.png
```

默认域名又长又不好记，我们用正则把它替换成自己的 CNAME 域名：

```ts
const finalUrl = url.replace(
  /https:\/\/[^.]+\.oss-[a-z-]+\.aliyuncs\.com/,
  customDomain,
);
```

正则匹配“`https://` + Bucket + 地域 + `aliyuncs.com`”这一串，整体换成我们配置的自有域名。这样前端拿到的就是一个干净、可控的访问地址。

如果 `status` 非 200，则抛出“上传失败，请重试”。

## 小结

- 大资源（图片/视频）托管到阿里云 OSS，能显著减轻应用服务器的存储与带宽压力；
- OSS 作为动态模块 `AliOssModule` 接入，标记 `@Global` 全局可用，配置写在 `config.ts`；
- 配置关键信息：region、accessKeyId、accessKeySecret、bucket、自有域名；secret 仅创建时可见，需妥善保管；
- 文件上传依赖 `multer` 中间件（配合 `@types/multer`），才能以对象形式拿到 `file`；
- `uploadToAliOss` 负责文件名转码、OSS 路径拼接（`upload_files/原名-时间戳.扩展名`）、`put` 上传、删除本地临时文件，并用正则把默认域名替换为自有域名。
