# 低代码项目发布页面—需求分析

> **导语**：编辑平台发布的页面要让「第三方用户」直接访问并填写问卷，这就引出了独立的发布页面模块。本文做需求分析：明确发布页用 Next.js 服务端渲染实现、需要哪三个后端接口、前端渲染链路如何打通，以及问卷数据表 `component_data` 的设计要点。

- 已掌握编辑模块整体能力（组件编辑、草稿、发布），见《低代码项目平台编辑模块—页面头部发布功能开发》。
- 已了解 Next.js 基础，见《初出茅庐—使用 Nextjs 创建初始化项目》《Nextjs 应用路由器和导航跳转》。
- 已了解数据库表设计，见《实战演练—低代码平台项目数据库设计》。

## 正文

### 发布页面的定位与渲染链路

编辑平台本身是用 React 开发的（端口 5173），而发布页面用 Next.js 服务端渲染开发（端口 3001）。二者是两个独立项目，渲染链路如下：

1. 用户在编辑平台配置好页面（含问卷类组件）后点击「发布」，跳转到一个 React 路由页面 `release`；
2. `release` 页面并不自己渲染内容，而是请求 Next.js 发布项目、用 `<embed type="text/x-scriptlet" src={url}>` 直接内嵌 URL；
3. 真实用户访问的是 Next.js 服务端渲染出来的地址，可直接填写问卷。

也就是说，编辑平台里的 `release` 路由是「壳」，真正的页面由 Next.js 项目产出。

### 后端需要开发的三个接口

发布页面不是纯静态的，它需要后端支撑，共三个接口：

1. **获取发布页面组件接口**：根据页面 ID 返回该页面要渲染哪些组件（列表、文本、卡片、问卷组件等）。
2. **是否提交过问卷接口**：用于判断当前访问者（按 IP + 设备区分）是否已经提交过问卷。已提交则整页置灰、禁止再编辑。
3. **提交问卷信息接口**：把用户在问卷组件中填写/选择的内容写入 `component_data` 表。

### 问卷数据表 component_data

第三方用户填写的数据统一维护在 `component_data` 表中，字段包括：

- `page_id`：发布页面的 ID；
- 组件 ID：不在表列上，存于 `props` 数组每项的 `{id, value}` 里（提交时组装的 item.id）；
- `user`（值 = `MD5(ip + ua)`）：由「用户 IP + User-Agent（`GetUserIp()` + `GetUserAgent()` 拼接后 MD5；单机直连下有效，经反代需 trust proxy + XFF）」拼接字符串后加密得到的值，用于唯一标识一台设备的一次访问，实现「同一设备不可重复提交」；
- `props`：该问卷组件用户填写/选择的具体内容（如输入框文本、单选框选项、多选框选项数组）。

通过 IP + 设备组合加密，既能区分不同用户，又无需登录即可防重复提交。

### 前端页面逻辑流程

- 初始化 Next.js 服务端渲染项目；
- 请求后端「获取发布页面组件」接口，拿到组件并渲染；
- 在 `release` 路由页面内嵌 Next.js 产出的页面 URL（转 JSON 后渲染）；
- 页面加载时请求「是否提交过问卷」接口决定置灰与否；
- 用户填写完毕后请求「提交问卷信息」接口写入数据。

## 小结

1. 发布页面由独立的 Next.js 服务端渲染项目产出，编辑平台通过 `release` 路由内嵌渲染。
2. 后端需三个接口：获取组件、是否提交过问卷、提交问卷信息。
3. 问卷数据落在 `component_data` 表，用「IP + 设备」加密值防重复提交。
4. `props` 字段保存用户填写的具体内容，支持输入框、单选、多选等类型。
