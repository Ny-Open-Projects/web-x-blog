# 低代码项目平台编辑模块—阿里云_OSS_资源上传接口开发

> **导语**：配置好阿里云 OSS 之后，本节课把它落地成一个真正的 HTTP 上传接口。我们会新建 `resource` 模块、建一张资源表落库 URL、用 Multer 接收前端文件、在 service 里调用上节课封装的 `uploadToAliOss` 完成上传并替换域名，最后用 Apifox 实测联调，并讲解跨服务器域名的绑定方式。

## 前置知识

阅读本文前，建议先掌握《低代码项目平台编辑模块—阿里云 OSS 资源上传配置》。本文在上一节封装好的 `AliOssModule` 与 `uploadToAliOss` 方法之上，继续开发对外接口，并复用此前已经做好的登录鉴权与 token 解密逻辑。

## 正文

### 为什么要落库 URL

通过上传到 OSS，图片/视频会得到一个可访问的 URL。这个 URL 必须存进数据库：前端后续请求接口时，后端从数据库读出对应资源的 URL 返回，前端才能打开资源。因此第一步是设计资源表。

### 资源表结构（ResourceEntity）

`resource` 模块下创建一个实体 `ResourceEntity`，包含五个字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 主键 |
| `url` | 资源在 OSS 上的访问地址（字符串） |
| `account_id` | 上传该资源的用户 |
| `type` | 资源类型：图片 or 视频 |
| `name` | 资源名称 |

### 用 nest 脚手架创建模块

通过 `nest g resource resource` 生成 `resource` 模块，包含控制层、服务层与实体。在它的 `module` 里需要做三件导入：

```ts
@Module({
  imports: [
    // 1. multer 处理文件上传，dest 指定本地临时目录（项目启动自动创建）
    MulterModule.register({ dest: '__temps__' })（与 ali-oss 模块取文件路径一致）,
    // 2. 把上一节的阿里云 OSS 配置注入进来
    AliOssModule,
    // 3. 注册资源实体，供 TypeORM 操作
    TypeOrmModule.forFeature([ResourceEntity]),
  ],
  controllers: [ResourceController],
  providers: [ResourceService],
})
export class ResourceModule {}
```

### 控制层：POST 上传接口

控制层定义一个 `POST /api/resources/upload` 接口。要点：

- 用户必须登录后才能上传，复用之前开发好的鉴权；
- 用 `FileInterceptor('file')` 处理文件类型数据；
- 用 `@UploadedFile()` 拿到 `file` 对象（内含文件名、buffer 等）；
- 用 `@Body()` 拿到 `type`（图片还是视频）。请求体类型定义在 `share` 项目的 request 里，`UploadType` 与 `ResourcesRequest` 通过 `Pick` 取出需要的字段——上传只用 `type`，删除 `DeleteResourcesRequest` 只用 `id`；
- 通过解密 token 拿到当前用户数据，取出 `account_id`。

```ts
@Post('upload')
@UseInterceptors(FileInterceptor('file'))
async upload(
  @UploadedFile() file: Express.Multer.File,
  @Body() body: ResourcesRequest,
  @getUserMess() user: TCurrentUser,
) {
  return this.resourceService.upload(file, body.type, user.id);
}
```

### 服务层：上传并落库

`ResourceService.upload` 的逻辑：

1. 调用上一节配置好的 `this.aliOss.uploadToAliOss(file)`，传入 file 对象，由它负责文件名处理、上传到 OSS 的哪个路径、从哪个本地临时路径取资源，并返回可访问的 `URL`；
2. 这个 URL 默认带阿里云默认域名（较长），用 `replace` + 正则把它替换成自有域名 `local.16web.net`；
3. 把 `url`、`type`、`account_id`、`name` 写入数据库。其中 `name` 要注意转成 UTF-8，否则中文名会乱码（课程联调时就踩过这个坑：一开始中文名“头像”没处理直接入库变成乱码，改成 ASCII 名或转 UTF-8 后才正常）。

```ts
async upload(file, type, account_id) {
  const url = await this.aliOss.uploadToAliOss(file); // 已在模块内替换为自有域名;          // 含默认域名
  const finalUrl = url.replace(/...aliyuncs\.com/, customDomain);
  const name = Buffer.from(file.originalname, 'latin1').toString('utf-8');
  await this.resourceRepo.save({ url: finalUrl, type, account_id, name });
  return { msg: '上传成功' };
}
```

### Apifox 联调实测

打开 Apifox，构造请求：

- 路径：`POST /api/resources/upload`
- Body：`form-data`，第一个 key 为 `file`（类型选 file，选本地文件），第二个 key 为 `type`（图片 / 视频）；
- Headers：`Authorization: Bearer <token>`（注意 Bearer 后带空格）。

点击发送，上传成功后去阿里云 OSS 控制台刷新，能看到形如 `upload_files/三个一-<时间戳>.jpg` 的文件；再查数据库，会多出一条记录，URL 已变成 `http://local.16web.net/upload_files/三个一-<时间戳>.jpg` 这样的短域名地址，复制到浏览器即可访问。当前是 http（浏览器提示不安全），配置 HTTPS 只需在阿里云申请免费 SSL 证书即可。

### 跨服务器域名绑定 Bucket

讲师用的 `local.16web.net` 并不在当前这台服务器上，而是在另一台服务器的域名下。要把它绑定到当前 Bucket，需要在阿里云**域名管理**里“添加记录”：

- 主机记录填 `local`；
- 记录值填目标 Bucket 的访问地址（按 Bucket 绑定指引粘贴主机记录与记录值）；
- 确认后回到 Bucket 侧点击“我已配置完成”，即可成功把另一台服务器的域名解析到当前 Bucket。

## 小结

- 资源表 `ResourceEntity` 存 URL、account_id、type、name，让前端按记录取资源；
- `resource` 模块同时导入 `MulterModule`、`AliOssModule`、`TypeOrmModule.forFeature`；
- 上传接口用 `FileInterceptor` 收文件、`@UploadedFile` 取对象，并复用登录鉴权与 token 解密；
- service 调用 `uploadToAliOss` 拿 URL，正则替换为自有短域名，入库时把中文名转 UTF-8 防乱码；
- 用 Apifox 以 `form-data` + `Authorization: Bearer` 实测；跨服务器域名通过阿里云“添加记录”绑定到 Bucket。
