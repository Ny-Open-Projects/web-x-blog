# 低代码项目平台编辑模块—页面组件键盘操作功能开发

> **导语**：拖拽排序做完之后，编辑器的操作效率还能再上一层：用键盘完成上移、下移、删除、复制、粘贴、撤销与重做。本文讲 `useKeyPress` 如何监听按键，以及每个快捷键背后如何把「视图操作」翻译成 store 里数组与对象的增删改查——这才是这类功能真正的核心。

## 前置知识

建议先读《低代码项目平台编辑模块—页面组件拖拽排序功能开发》，此时 `sortableCompConfig` 与 `arrayMove` 排序逻辑已就位。另需熟悉 ahooks 的 `useKeyPress`、MobX 的 `action` / `toJS`，以及 `@dnd-kit/sortable` 的 `arrayMove`。配套工程见 `代码（已8期）/代码（已8期）/18-5/lowcode/`。

## 正文

### 事件集中放在一个 hook 里

所有键盘监听收敛到 `useComponentKeyPress`（在 `pages/Editor/EditorCanvas.tsx` 中执行），要调用的业务方法都来自 `useStoreComponents`：撤销、重做、上移、下移、复制、粘贴、移除当前组件、获取当前组件配置等。

监听用 ahooks 的 `useKeyPress`：第一个参数是按键映射（如 `uparrow`），第二个参数是命中后的回调，第三个参数可开启严格匹配。本阶段相关依赖见 `代码（已8期）/代码（已8期）/18-5/lowcode/packages/client/package.json`：

```json
{
  "dependencies": {
    "@dnd-kit/core": "^6.1.0",
    "@dnd-kit/sortable": "^8.0.0",
    "@dnd-kit/utilities": "^3.2.2",
    "mobx-shallow-undo": "^1.1.0",
    "mobx-react-lite": "^4.0.5"
  }
}
```

### 每个操作前先验证选中

上移、下移、删除、复制前都要先 `validateComponent`：通过 `getCurrentComponentConfig` 取（源码 `validateComponent` 判 `getCurrentComponentConfig.get() !== null`，提示「请先选择组件」） store 里的默认选中组件，若为 `none` 就提示「请先选择一个组件」并停止——没选中就不知道该操作谁。同时兼顾拖拽场景下的 `active` 状态。撤销 / 重做不必做这层校验。

### 上移与下移：本质是数组换位置

`moveUpComponent` 先用 `getCurrentComponentIndex`（MobX `computed`）拿到选中组件在 `sortableCompConfig` 里的旧索引，判断不是第一个才允许移动；已经是第一个就提示「此组件已经是第一个了」。移动交给 `arrayMove` 完成，返回新数组写回 store。

`moveDownComponent` 完全对称：拿旧索引，判断是不是最后一个，不是就 `index + 1` 再 `arrayMove`。

### 删除：两处数据要一起清

Windows 用 `Delete`、Mac 用 `Backspace` 触发 `removeCurrentComponent`。先查当前 ID 在排序数组里的索引，没有就停止；有则 `splice` 删除，并且**同时**清两个地方：

- `sortableCompConfig`：由组件 ID 组成的排序数组；
- `compConfigs`：以 ID 为键、组件配置为值的对象字典。

这俩数据形态不同，一个数组一个对象，漏删一处就会出现「画布没组件但配置还在」的脏数据。删除后还要重设选中：一般取上一个，删的是第一个就取下一个。

### 复制与粘贴：ID 必须重新分配

复制监听 `Ctrl + C` / `Cmd + C`，把 `toJS(currentCompConfig)` 存进中间变量 `copyedCompConig`。粘贴监听 `Ctrl + V` / `Cmd + V`：先看中间变量有没有值，没有就停止。

关键在于**不能直接把复制来的对象塞回去**——它的 ID 和原组件一模一样，而画布里每个组件 ID 必须唯一。所以先整体拷贝一份配置，再用 `ulid` 重新分配 ID，然后：

```ts
const id = ulid();
const comp = { ...JSON.parse(JSON.stringify(copyedCompConig)), id: ulid() }; compConfigs[comp.id] = comp;（存 {id,type,props} 完整结构）
store.sortableCompConfig.push(id);
store.currentCompConfig = id; // 粘贴出来的组件默认选中
```

配置字典新增一项、排序数组追加一个 ID、并把新组件设为当前选中，三步缺一不可。效果上粘贴出的卡片与原卡片内容一样，但 ID 不同、且带蓝色选中边框。

### 撤销与重做：交给 mobx-shallow-undo

`Ctrl + Z` / `Cmd + Z` 撤销，`Ctrl + Shift + Z` / `Cmd + Shift + Z` 重做。注意必须先有**撤销**，才有可**重做**的步骤。

实现借助 `mobx-shallow-undo` 的 `trackUndo`：把 store 转成普通 JS 对象作为响应式快照，第二个回调里拿到历史值，再调用 `useStoreComponents` 里我们自定义的替换方法，把旧 `config` 等变量写回当前 store——相当于保存了一组切片，撤销就是回退到上一个切片，重做就是前进到下一个。

判断条件用插件提供的 `hasUndo` / `hasRedo`：有上一步才执行撤销，有下一步才执行重做，否则提示无可撤销 / 无可重做操作。具体 API 用法以插件官网示例为准，第三方库要学会读文档拿来为自己所用。

### 核心：把视图操作翻译成数据操作

把上面所有快捷键摊开看，它们做的事惊人一致——上移、下移、删除、粘贴，最终全是对数组 / 对象的排序与增删改查。编辑器开发最核心的能力，就是**把用户在视图上的操作方式，转成对数据的操作方式**。想通这一点，加新功能就是加一条数据变换，而不是到处改 DOM。

## 小结

- 键盘事件集中在 `useComponentKeyPress`，用 ahooks `useKeyPress` 监听。
- 上移 / 下移靠 `getCurrentComponentIndex` 取旧索引 + `arrayMove` 换位置，首尾要做边界提示。
- 删除要同时清 `sortableCompConfig` 与 `compConfigs`，并重设选中组件。
- 复制粘贴必须用 `ulid` 重新分配 ID，保证组件唯一性，粘贴项默认选中。
- 撤销 / 重做交给 `mobx-shallow-undo`，用 `hasUndo` / `hasRedo` 判定可用性。
