# 低代码项目平台编辑模块—页面组件工具栏功能开发《下》

> **导语**：上一节留了删除、向上、向下三个按钮没接逻辑，这一节补完，并顺带讲清两个更硬核的前端问题：组件增删/排序后，工具栏的位置和名字怎么自动跟着变；以及用 `IntersectionObserver` 判断选中组件露出了多少，决定工具栏显不显示。核心是一个 `useState` + `useEffect` 的「强制刷新」技巧，值得反复看。

- 建议先了解《低代码项目平台编辑模块—页面组件拖拽排序功能开发》，理解组件顺序变化对工具栏的影响。

## 正文

### 三个按钮的样式与图标

删除、向上、向下三个按钮都被同一个样式组件 `EditorChooiseToolbarIconContainer` 包裹：hover 时鼠标变成手型、图标置灰并改变颜色。图标 `DeleteOutlinedd` / `UpOutlinedd` / `DownOutlinedd`（少 ed 会 import 失败） 从 `@ant-design/icons` 引入。刷新页面 hover 一下就能看到三个图标的置灰效果。

### 复用键盘操作里的方法

点击删除按钮会调用 `handleOnClick`，并把对应方法传进去。上一节做键盘操作时已经定义过删除、`moveUpComponent`、`moveDownComponent`，这里只是把「键盘事件」换成「鼠标点击」来触发同一批方法：

- 删除：键盘 `Backspace` / `Delete`，或选中组件后点工具栏垃圾桶。
- 上移、下移：键盘操作，或点向上/向下箭头。

逻辑不重复写，是这一节结构上最省事的地方。

### ifReach：用一个 state 触发 useEffect 重算工具栏

难点在于：删除或移动一个组件后，默认选中的组件会变（演示里删掉轮播图后默认选中第一个视频组件，再删视频就变成卡片组件），工具栏的**位置**和**名称**（如「卡片组件」）都必须跟着变。

做法是定义一个布尔 state（下称 `ifReach`，初始 `false`）。每次点工具栏按钮、在执行移动/删除方法之前，先 `setIfReach(true)`。由于 `ifReach` 在 `useEffect` 的依赖数组里，它一变，`useEffect` 就重新执行，从而重新计算工具栏的位置与显隐。

### 首次挂载：延迟 500ms

`useEffect` 里用 `isFirst` 区分首次与非首次：

- `isFirst` 默认 `false`，首次执行时取反为 `true`，走首次分支。
- 首次时组件 DOM 可能还没渲染完，同步执行拿不到元素坐标，工具栏就画不出来。所以用 `setTimeout` **延迟 500ms** 再调用 `resizeComponent`（它负责获取 DOM 元素的浏览器坐标与宽高）来定位工具栏。

### 非首次：改回 state，再走一遍 = 强制刷新

非首次分支把 `ifReach` 从 `true` 改回 `false` 并 `return`。但这次改动又让依赖变量发生了变化，`useEffect` 会**再执行一次**：这时既不是第一次、`ifReach` 也是 `false`，于是走到末尾调用 `resizeComponent` 重置工具栏位置。

也就是说，一次点击通过「置 true → 改回 false」让 `useEffect` 跑了两遍，第二遍才真正完成刷新。这是本节最巧妙、也最需要多看几遍的地方：不直接调函数，而是借 state 变化驱动副作用重跑，保证 DOM 更新之后再量位置。

### IntersectionObserver 控制显隐

工具栏是否可见，由 `IntersectionObserver` 判断，结果写进 `setLocalHidden`。流程：

1. 用 `document.querySelector` 拿到 canvas 容器元素，作为视口根元素 `root`（祖先元素）。
2. `getCurrentComponentConfig` 拿到当前默认选中组件的 DOM 元素，作为目标元素。
3. `new IntersectionObserver(callback, options)` 创建观察器——这是浏览器原生 API，不需要引入。

```js
const observer = new IntersectionObserver(
  (entries) => {
    // entries 里逐项判断 entry.target 是否为当前选中组件
    // 再结合 entry.isIntersecting 决定工具栏显隐
  },
  { threshold: 0.9, root: canvasRoot },
);
```

回调里循环遍历 `entries`，先判断 `entry.target` 是不是当前组件，不是就直接 `return`；是且 `entry.isIntersecting` 为 `true` 才显示工具栏。

关键在于 `threshold: 0.9`：目标组件露出超过 0.9 才显示工具栏，被遮挡超过 0.1 就判定不可见。演示里把选中组件向上移动、遮住一小部分，`isIntersecting` 立刻变 `false`，工具栏随之隐藏。`root` 设成 canvas 容器，保证是相对编辑画布而不是整个窗口来判断。

### 监听与清理

目标元素与根元素都存在时才创建监听并 `observer.observe(targetElement)`；组件卸载时，在 `useEffect` 的 `return` 回调里调用 `observer.disconnect()` 清除监听，避免残留观察器。

### 遗留的滚动 bug

本节最后还留了个问题：滚动画布时，工具栏位置没有跟着修正——默认选中卡片组件，一滚动工具栏却跑到下面去了。这个正是下一节要处理的内容。

## 小结

- 三个按钮由统一样式组件包裹，图标来自 `@ant-design/icons`，点击复用键盘操作里已有的删除/上移/下移方法。
- 用布尔 state `ifReach` 作为 `useEffect` 依赖：点击时置 `true` 触发重算，非首次分支再改回 `false`，借第二次执行完成「强制刷新」。
- 首次挂载要延迟 500ms 再调 `resizeComponent`，否则 DOM 未就绪拿不到坐标。
- `IntersectionObserver` 以 canvas 容器为 `root`、`threshold: 0.9`，露出不足九成就隐藏工具栏。
- `observe()` 开始监听，`useEffect` 的 `return` 里 `disconnect()` 清理；滚动时的工具栏错位留待下一节修复。
