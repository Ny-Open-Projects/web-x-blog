# 项目自动化部署上线—访问后端接口+发布页面

> **导语**：自动化部署跑通后，本集在浏览器里实际验证线上服务：访问后端接口（直连 5001 与 Nginx 代理 5000），以及访问前端发布页（直连 4001 与 Nginx 代理 4000），并实测提交问卷数据落库，确认整条链路可用。

## 前置知识

- 已完成《项目自动化部署上线—Docker-compose上传 BUG 修复》，三个项目已全部部署启动。
- 端口规划参见《第1集 项目自动化部署上线—更改线上 ip+端口》。

## 正文

### 访问后端接口

部署成功后，后端服务已经启动。根据 `docker-compose.yml` 的端口映射：

- 直连后端：**5001**（NestJS 服务）；
- 走 Nginx 代理：**5000**。

浏览器访问 `http://<服务器IP>:5001`，会返回"接口不存在"的提示——这恰恰说明服务已启动，只是根路径没有路由。换一个真实接口验证，例如发布页数据获取接口（该接口无需登录鉴权）：

```
GET http://<服务器IP>:5001/api/low_code/release?id=<页面id>
# 或走 Nginx 代理
GET http://<服务器IP>:5000/api/low_code/release?id=<页面id>
```

能返回数据即代表后端项目与 Nginx 代理都正常工作。若本地 / 线上从未发布过问卷类组件（input、textArea、radio、checkbox），该接口会返回空，这是正常的。

### 访问前端发布页

前端发布（Next.js）页面同样有两个入口：

- 直连：**4001**；
- 走 Nginx 代理：**4000**。

直接访问 `http://<服务器IP>:4001` 会提示"页面未找到"，因为发布页 URL **必须带上页面 ID**，例如：

```
http://<服务器IP>:4001/4     # 4 是数据库里的页面 ID
# 或走 Nginx 代理
http://<服务器IP>:4000/4
```

### 实测提交问卷并落库

打开发布页后，填写问卷类组件并提交。系统会按 MD5(ip+User-Agent) 区分是否已提交过——该判定在单机直连下有效；经 Nginx 反代需配 trust proxy 与 X-Forwarded-For，否则同 UA 用户互挤、换 UA 可绕过。提交成功后，到数据库 `component_data` 表查看：

- 提交内容存入 `props` 字段（JSON 数组，每项 `{id, value}`），访客标识存 `user`（MD5(ip+ua)）；
- 选项、问卷数据均正确落库，说明发布页 + 后端接口 + 数据库全链路打通。

## 小结

1. 后端接口：直连 5001、Nginx 代理 5000，根路径报"接口不存在"属正常（服务已起）。
2. 发布页数据接口 `/api/low_code/release?id=<页面id>` 无需登录，可直接 GET 验证。
3. 前端发布页：直连 4001、Nginx 代理 4000，URL 必须带页面 ID 才能打开。
4. 提交问卷按 MD5(ip+ua) 去重（单机直连下有效，反代需 trust proxy + XFF）。
5. 数据落入 `component_data` 表，证明发布页到后端到数据库全链路可用。
