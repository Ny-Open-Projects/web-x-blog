# 大展经纶—低代码项目大课的技术栈选择

> **导语**：前面铺垫了框架对比与组件库选型，本节正式拍板本大课的技术栈。你会看到编辑端为什么选 React 而非 Vue、后端为什么选 NestJS、发布端为什么选 Next.js，以及这套组合如何环环相扣。

## 前置知识

建议依次阅读《龙争虎斗—前端开发必学框架之 Vue 和 React》《群雄纷争—高级+全栈前端工程师必学之 Express+Koa+Nestjs》《逐鹿中原—服务端渲染框架之 Nextjs + Nuxtjs》《择其善者而从之—前端页面开发提效之 UI 组件库》。

## 正文

### 前端编辑端（B 端）：React

编辑端没有用 Vue，而选 **React**，主要三点原因：

1. **低代码编辑页复用组件、逻辑复杂**：用 React 处理这类灵活逻辑更得心应手。
2. **React 18 默认函数组件**：官方文档几乎找不到 `class` 字眼，逐步摒弃类式开发，代码更简洁、易维护（并非 18 之后不能用 class，而是主流已转向函数式）。
3. **自定义 Hook + 第三方 Hook**：结合 ahooks 等实现低代码编辑的多重功能，开发更方便。

### UI 组件库：Ant Design React

确认使用 **Ant Design React**——当前最受欢迎、稳定运行且持续维护的组件库，完美契合 React，提供大量精美便捷的组件，显著提升页面开发效率。

### 后端：NestJS

后端用 **NestJS**（基于 Node 的框架）开发接口，选更全面的 NestJS 让后期迭代更简单。其设计思想基于**控制反转（IoC）与依赖注入（DI）**——学 Spring Boot 的同学会很熟悉，不熟悉可看 NestJS 专题课。

NestJS 还提供 **Nest CLI** 脚手架，用快捷命令生成接口模板（控制层、数据层、模块），并自动生成好相互引用，开发者只需补接口逻辑。自定义或第三方依赖在构造器里声明即可，NestJS 会自动实例化对象，无需手动 `new`。

### 前端发布端（C 端 H5）：Next.js

发布端用 **Next.js**（服务端渲染，注意与 NestJS 的 S/X 区别）：

1. 编辑端用 React，发布端要契合 React 生态，Next.js 是最佳搭档；
2. Next.js 更受欢迎（参考其 GitHub 热度），是近年最热门的 React Web 框架，文档清晰，也是 React 官网推荐的 Web 框架；
3. 既可构建 SPA 单页应用，也可构建 Web 全站应用。

### 大方向定调

本大课主要技术栈：**前端 React + 后端渲染 Next.js + 后端 NestJS + 组件库 Ant Design React**。

细节技术（如数据可视化 ECharts、拖拽组件、问卷系统导出在线 Excel 与压缩下载等）留到具体编码章节逐一演练。

## 小结

1. 编辑端选 React：低代码逻辑灵活、18 默认函数组件、自定义 Hook 加持。
2. 组件库选 Ant Design React：最受欢迎、稳定维护、契合 React。
3. 后端选 NestJS：IoC/DI 设计、CLI 脚手架自动生成模板与依赖注入，迭代省力。
4. 发布端选 Next.js：契合 React、热度最高、React 官网推荐、支持 SPA 与全站。
5. 整体组合：React + Next.js + NestJS + Ant Design React。
6. 细分技术（ECharts、拖拽、Excel 导出）在后续编码章节展开。
