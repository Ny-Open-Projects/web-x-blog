# 16-2-1-拖动移动元素的原理分析

本周都和画布中的元素打交道，核心工作是编辑器的交互：用鼠标拖动改变元素的位置，或者拖动改变元素的大小，比在表单里填 x、y 坐标或宽高方便得多。这些交互的实现是整个编辑器实现的一个重点。

本章分析鼠标拖动改变定位的实现方法。

## 定位革命：绝对定位

首先要对元素的定位来一次革命。目前元素都是按块级元素自上而下排列在画布中。为了让元素实现精确的定位和调整，需要改变定位实现：让元素在画布区域中使用绝对定位。

假如一个元素已经保存了这些 CSS 属性：`position: absolute; top: 10px; left: 10px; width: 200px; height: 100px`，就可以在编辑器区域根据这些属性渲染出对应的元素，或者在 H5 端渲染出同样样式位置的元素。

交互的最终结果只是修改这些样式而已：拖动定位最终修改的是 top 和 left 的值，缩放大小最终实现的是 width 和 height 的改变。值一变，元素也就变了。

## 鼠标拖动位置的实现分析

有了这个指导思想，来分析鼠标拖动位置的实现。可能有人第一个想到之前学过的 drag and drop 特性：将元素设置 `draggable` 为 true，拖动时产生系统默认的半透明浮层，移动过程不需要操心，drop 时重新计算鼠标走过的距离，更新 top 和 left 即可。这种方法没有问题，但那个半透明浮层是系统默认的，不好自定义样式。

这里介绍一种通用做法，也是各种交互工具拖动的基本实现。掌握以后，再遇到拖动改变位置的交互都可以复用。

先明确几个步骤：

1. **mousedown**：拖动是在按下鼠标之后、鼠标移动的过程中发生的。所以要响应鼠标按下事件，拖动从这里开始运作。
2. **mousemove**：鼠标移动时，把 top 和 left 更新到新的值，这是过程的重点。移动过程中能取得的值只有一个：鼠标目前的位置，可以从 event 的 `clientX` 和 `clientY` 中获取。

那么能否把鼠标位置直接设置成元素的 top 和 left？显然不行。拖动不是从元素的角开始的，是有偏移量的。如果直接这样设置，一开始拖动元素就跑偏了：从这个位置开始拖，元素却跳到鼠标所在的位置。

怎样解决？要利用一个特性：**拖动过程中，鼠标在元素内的相对位置不会变**。用这个特性完成计算。

## 偏移量计算

用两张图描述这个过程。图一是元素的初始位置，top 是 10、left 是 10，黄色大圆点代表鼠标拖动开始的位置；图二是移动后的位置，鼠标在元素内的相对位置没有改变，红色的两根线就是我们要计算的坐标值。

移动开始时，能拿到鼠标的当前位置，比如 y 是 50px、x 是 15px。通过减法可以算出鼠标在元素内的偏移量：例中这两条紫色的线，x 轴偏移量是 5px，y 轴偏移量是 50 - 10 = 40px。这个偏移量非常关键。

移动到新位置后，再通过事件对象拿到最终的坐标值，y 是 100px、x 是 60px。这时要拿到红线的坐标就很简单了，用当前坐标减去偏移量：y = 100 - 40 = 60px，x = 60 - 5 = 55px。

通过这种方式持续计算，就实现了元素随着鼠标移动的效果。
