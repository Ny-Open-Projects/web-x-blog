# 13-28-创建展示渠道

上面一部分我们了解了 SSR 渲染的方式，以及配合 webpack 生成服务器端渲染页面需要的一系列静态文件。到这里，SSR 渲染海报这一块内容就告一段落。完成 SSR 需求之后，剩下一个渠道功能没有做。

渠道之前分析过，属于作品的一个实体。work 上面对应的属性就是 channels。根据最早的数据库设计，它和作品是一对多的关系，一个作品可以有多个渠道，但数量肯定不多，属于 one to few 的范畴。按照 MongoDB 设计的最佳实践，这里直接用内联的方式，把它保存为 work 其中的一项，名称叫 channels，是一个数组。数组中有两项，一个是 name，一个是独一无二的 id。

对这个数据实体的增删改查，大家通过之前的内容应该烂熟于心了。本来不准备带大家写代码，但数组的操作属于全新内容，实践的是 MongoDB 对数组的一系列操作，算是温故知新，所以带着大家再写一遍，以后遇到数组操作就可以成竹在胸了。还记得我们之前画的思维导图吗？现在可以拿出来看一下，找到数组操作那一节，就知道需要一系列特殊的操作符（operator）。

现在来写代码。第一步在 work.ts 的 WorkProps 里添加一项 channels。先确定它的 interface，称之为 ChannelProps。按照设计，channels 是可选的数组，所以给它加上 ChannelProps 类型的数组类型，数据结构就写完了。

之后写 controller 中的处理。第一个是 async createChannel。发送的请求接口是这样的：POST 请求到 api/channel，数据是 name 和 work_id。这里的 RESTful 设计其实不太好，按理应该用复数 channels。这是因为课程更新过，原来的接口就是之前那位老师设计的 channel，没有用复数，为了兼容性沿用它的做法，其实用复数更好。

知道了数据来自 name 和 work_id，就把它们取出来。第一步当然是把 ctx 拿过来，然后从 body 中取出这两部分：name 和 work_id，来自 ctx.request.body。记得要添加 validate 校验，跟之前一样，写过很多次了，我这里就不写了，大家可以课后补上。

拿到两个值后，创建对应的数据。新建一个对象 newChannel，要保存两项：一个是对应的 name，第二个是一个独一无二的 id，以后可以根据这个 id 进行查询。所以需要 nanoid，用它生成一个六位的独一无二的 id。有了 newChannel 这个对象以后就可以创建了。注意这里是添加到 work 上，应该用 update 而不是创建，也就是 findOneAndUpdate。第一个参数是 query 条件，这里应该是 id 等于对应的 work_id，因为我们要操作的是这个对应的 work。

第二个参数是更新内容，特别注意这里要操作数组了，跟原来直接赋值的写法不一样。假如是新建一条数组数据，应该使用哪个操作符？翻一下之前整理的文档，是 $push。点开看看当时是怎么写的：$push 加上你要操作的数组字段，把值添加进去即可。它还有一个 $each 操作符，那是添加多个值的时候才用的，我们这里不需要。所以按照之前总结的知识来写：$push 的目标是 channels 这一项，注意字段名要和 work 模型上的名称对应，不要写错，添加的内容是 newChannel。

这样整个添加逻辑就写完了，添加完毕后直接返回，用 ctx.helper.success 把新建的 channel 返回给客户端即可。

权限方面，这里有两个层次：一是登录用户才能 createChannel，二是更复杂的，登录用户只能创建自己作品下面的渠道，要先查找这个作品是否属于这个用户，是的话才能在它下面创建 channel。这部分逻辑我们先不写，因为之后就要讲权限管理，可以把所有权限问题放到那里统一处理，这里暂且略过。不过因为要求登录用户才能访问，所以要在 config.default.ts 中给这个 url 添加一项需要登录的配置。

接着添加对应的 router，直接复制一份放在最下面，路径是 /api/channels。现在测试一下功能是否成功。首先要登录，点击 send，用 234 这个用户登录，把 token 复制一下添加到 header 中。当前用户是 234，它的作品我们用 work_id 为 10 的，然后希望创建一个叫 Tencent 的 channel。点击 send，返回了数据，可以看到 id 是 nanoid 生成的，name 是 Tencent，创建成功了。

我还想带大家再写一个获取接口，这个真的非常简单，我就直接复制了。逻辑是根据作品传入的 id 获取它的 channels。看一下代码：id 来自 params，取出 channels 后做处理，因为要返回一个 count（有多少个）和一个 list（数组结构），没有什么花头。保存后添加对应的 router，接口叫 getWorkChannels，GET 请求 /api/channels/:id，对应的处理是 getWorkChannel。

看看能否获得对应的 channels。刚才处理的是 id 为 10 的作品，所以用 10 这个 ID，把权限 header 配置好，点击 send，数据就出来了。我之前又点了一次创建，所以 channel 中有两条数据，获取也没问题。
