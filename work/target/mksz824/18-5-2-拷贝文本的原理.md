# 18-5-2-拷贝文本的原理

这节课聊一聊在浏览器中拷贝文本的原理。上节课说过，它看起来应该是一个内置 API 就能搞定的问题。我参考了 clipboard.js 的源代码，整理出如今主流或者说通用的实现方案。这里不带着大家读源代码，而是以写代码的方式实现一遍，了解其中的基本原理。

这个问题有多种实现方式，先看第一种：最新的、也可以说最现代的 API，称为 Clipboard API，是一种异步实现方式。文档描述它提供了响应剪贴板命令（剪切、复制和粘贴）以及异步读写系统剪贴板的能力，该 API 被设计用来替代使用 document.execCommand 的原有剪贴板访问方式，也就是我们等会儿要讲的第二个方法。

它很简单，可以直接使用全局的 navigator.clipboard 访问系统剪贴板。演示一下：在 onMounted 中写入剪贴板，`navigator.clipboard.writeText('hello')`，它返回一个 Promise，then 的成功回调里 alert 一个结果，reject 时 console.error。刷新页面，弹出了提示，说明写入成功。按 Command 加 V，hello 能够粘贴出来，在其他地方粘贴也一样，说明 hello 已经成功写入了系统剪贴板。这是面向未来的完美方案，一行代码就能搞定。

但有悲剧：它的浏览器兼容性。很多浏览器不支持，而且它的规范状态还是 working draft，处于草稿阶段，目前不是一个通用的解决方案。

所以来看方法二：document.execCommand。它是通用的解决方案，也是 Clipboard API 要替代的方法，但现在仍是主流，因为浏览器支持最全面，clipboard.js 内部采用的也是这个 API。它的文档上标了已废弃，但其实并没有真正废弃，要等 Clipboard API 完全成熟以后才有可能被替代。

文档描述比较拗口：HTML 文档切换到设计模式时，会暴露这个方法，允许运行命令来操纵可编辑内容区域的元素。看语法：它返回一个布尔值，false 表示操作失败。参数是一个 commandName，一个特殊的 DOMString，即命令名称。看看有哪些命令，你会发现它的设计不只是解决复制场景，而是给编辑区域提供一系列功能：切换粗体、拷贝、createLink、剪切、delete 等等，非常多。

特别注意：这个 API 并没有像 Clipboard API 那样提供一个参数直接传入要拷贝的文本，而是首先要让用户选中对应的区域，必须有一个选择的过程；其次必须在某次事件中调用对应的方法才能触发。所以我们把它添加到发布按钮的 click 事件里测试。先注释掉之前的测试代码，在 publish 中写：`const result = document.execCommand('copy')`，然后 console.log(result)。

测试：先选中页面上的大标题，点击发布，可以看到返回了 true。粘贴一下，大标题出现了，说明复制成功。再试其他命令，比如 delete：清除后选中大标题，点击发布，文本就被清除掉了。这就是 execCommand 的基本用法，它有很多针对可编辑区域的操作。

我认为它并不是一个设计得很成熟的 API，因为它居然没有一个参数直接指定拷贝哪些文本，而是要用户先完成 select 再操作。那么 clipboard.js 内部是怎样完成对某个元素的选择的呢？下节课我们来看它使用了一个非常奇怪的招数来拷贝指定元素的内容。
