# 2-2-宏观需求分析

上节课说了软件的开发流程，那么作为系统架构师，介入的位置应该在哪里？应该在 System Architect 这一环介入，也就是说 Analyze 和 Design 都已完成。这时手上应该有几块现成的内容：原型图、需求文档和 UI 设计稿。

课程资料里已经提供了这些内容，文档很详尽，大家可以自己去看。UI 设计稿这边比较特殊，是花钱请设计师专门设计的。要特别关注的是 B 端需求，它是 OpsFlow 所有需求的集合。其中还单独衍生出一份编辑器需求文档，因为这部分需求比较复杂，所以单独成文。

按理说开发之前有这三样就够了，但我们毕竟是讲研发和架构的课程，以技术为主，所以直接看一遍线上网站，有助于快速了解需求、快速进入设计和开发。可以把这个系统看成高保真模型。在公司里大家也会用到类似工具，叫 UX prototypes，比如 Axure RP、Figma 或 Adobe XD，它们能生成可交互的模型，有 UI 也有逻辑，点击某个按钮会跳到什么页面。我们直接用最终成品系统代替这类工具。

请记住一句话：需求指导设计，设计指导开发。下面带着大家把系统简单用一遍，对需求做分类和汇总。

## 需求分类

**模板**。首页内容不多，第一个要关注的是热门海报。这些海报是一系列 template，可以看到海报的分类，点击加载可以加载更多内容，点进每张海报就是海报详情。所以第一个需求分类是模板，包含模板列表和单个模板的详情。

**用户**。登录需要先获取验证码：输入手机号，点击获取验证码，手机收到短信，输入验证码点击登录，提示成功并跳转到首页显示用户名。所以用户实体下有几个对应的行为：获取验证码、手机号登录、获取用户信息。有了用户信息，他就可以创建作品了。

**作品**。登录后顶部导航栏会出现几个按钮，点击"我的作品"可以展示已创建的作品，旁边还有"我的模板"。要特别注意，模板和作品是同一类型的实体，模板只是一个有特殊属性的作品。作品的功能包括创建、获取作品列表和对应信息。创建作品并输入标题后，还有作品的保存、作品信息的设置、预览，以及最重要的发布。

**发布与分享 H5**。点击发布，提示发布成功。这一步不仅仅是保存，而是设置了一个特殊的状态。同时会出现一个二维码，扫码就能预览作品。二维码对应一个 URL，也就是说系统用一个新的 URL、新的域名来展示作品，在 H5 端进行分享。这里要画个星号，之后会专门讲这块比较特殊的内容。

**渠道**。发布成功后还有一个渠道的概念。渠道就是可以把作品分享到多个不同平台，比如微信、QQ、微博。点击创建新渠道，它的基本 URL 是一致的，只是会多加一个 channel ID 属性，供你在不同平台分享。系统里默认有一个 channel，还有一个微信的 channel。渠道本身也可以管理，可以创建、删除。

编辑器的详细需求这里没看，因为它太复杂，等实现前端功能时再细分，宏观上把握即可：编辑器页面就是完成对用户作品的管理。

## 小结

从数据结构的角度看，系统并不复杂，复杂的是编辑器界面的交互和实现，这是本项目的难点。有了需求分类，下节课就进入架构师职责的第一步：System Architect 介入，进行技术架构层面的 design。
