# 17-6-4-保存作品数据

这节完成编辑器数据的保存，并以此延伸出更多功能。先做最简单的：点击按钮保存。

## 接口与 PUT/PATCH 之辨

接口选择"修改作品数据"：method 是 PATCH，URL 是 `api/works/{id}`，body 和 GET 返回的数据很相似，title、description（现在还没有）、content（里面是要提交的修改完毕的 components 和页面属性 props）。

看到 PATCH 不禁想起一个面试题：PUT 和 PATCH 的区别。先说共同点，两者都是为了更新资源。区别看一个例子就明白：现在有一段描述房子的数据，windows 是 12 个窗户、doors 是 4 个门、balcony 是 false。

用 PUT 更新时只传入 `doors: 5`，返回的结果实体里只剩 doors，windows 和 balcony 都消失了；用 PATCH 传入 `doors: 5`，返回的数据只把 doors 更新成 5，windows 和 balcony 得到保留。

结论：PUT 通常代表整体更新，PATCH 代表局部更新，patch 这个词也有给软件打补丁的意思，相当于把新结果补在旧结果上。当然这只是 RESTful 设计期望的规范，是否遵守取决于后端的实现。

## 编写 saveWork

到 editorView 中创建函数 saveWork。要拿的数据都在现有变量里：从 page.value 取 title 和 props；content 里放 components，直接用 editorView 中现成的 `components.value`。payload 组装完毕后 dispatch saveWork action（action 还没写，先写在这里）。注意 payload 走之前讲过的特殊格式，data 和 urlParameters 分开：

```ts
store.dispatch('saveWork', {
  data: payload,
  urlParameters: { id: currentWorkId },
})
```

然后到 editor.ts 添加 action。saveWork 用 actionWrapper 包裹，第一个参数是 `works/:id`（id 从 dispatch 时传入），mutation name 是 saveWork，最后特别注意要传 AxiosRequestConfig，里面 `method: 'patch'`。

把 saveWork 绑到保存按钮的 click 事件上测试：打开 Network，改一下标题点击保存，请求发送成功，数据传递正确；刷新页面，title 已更新。再随便改点样式，把文字居中、字体颜色改成黄色，保存后刷新，修改完美保存。

## 加上保存的 loading

有个问题：点击保存时按钮没有任何效果，让人不知所云。最好加一个只针对 saveWork 的 loading 状态，正好用之前全局加的 getter isOpLoading。在 editor 中添加变量 saveIsLoading，computed 返回 `store.getters.isOpLoading('saveWork')`，然后绑到 AButton 的 loading 属性上。

验证：改一下对齐方式点击保存，loading 效果出现，保存成功，刷新后字体已更新为向左对齐。

这节完成了编辑区数据的保存。但保存这个功能对实时性要求高的应用来说还有增强空间，下节逐个实现。
