# 15-6-4-页面设置完成更新背景图片逻辑

上节课完成了正则表达式的书写，这节课把整个编辑流程完善。现在数据展示没有问题，value 的传递已经成功了。下一步要遵循数据流：属性更新的时候发送对应的 change 事件。这个事件的第一种情况是在上传完成的时候触发，StyleUploader 和 ImageProcessor 两个组件中都需要处理对应的事件。

## StyleUploader 的 success 事件

第一个要处理的是 StyleUploader：它上传成功后会发送一个 success 事件。创建它的回调，称为 `onImageUploaded`。

它的数据是什么类型呢？这里暴露出 Vue 对 TypeScript 支持不好的一个点：组件的事件没有办法完成对应的类型推断，每次都要查看事件发射出来的数据类型，可能要进入组件内部，比较麻烦。

我们都知道它发送出来两个数据：第一个是 data object，里面的类型当时创建过对应的 response 类型，位置在上一级的 types 里，类型叫 `UploadResponse`，专门放置上传成功以后的数据类型（我现在用的是本地服务器，接到线上以后可以统一修改类型）。第二个参数是原生的 file。这样就确定了 data 的类型。

使用时只需要从 data 里拿出 response。上传成功后发送一条 message，使用 Ant Design Vue 提供的 `message` 函数，`message.success('上传成功')`。然后发送对应的 change 事件：`context.emit('change', ...)`，值是 response.data.url，就是真正上传成功的地址。最后把它 return 出去，赋值给 success。

## ImageProcessor 的上传与删除

第二个处理 ImageProcessor 的上传过程，很简单：它已经暴露出来处理好的 URL。新建一个函数，称为 `handleUploadUrl`，它直接接收 string，内部直接把它以 change 事件发送出去，再暴露出去。然后添加 `@change="handleUploadUrl"`。

同时要注意这里加了一个 `showDelete`，因为我们要显示删除按钮。ImageProcessor 里会多一个按钮，由 showDelete 属性控制，设置为 true 后显示"删除图片"按钮。删除图片其实很简单：handleDelete 内部就是发送一个 change，同时把值置为空。我们给它添加 `:show-delete="true"` 即可。

## EditorView 监听与 updatePage

change 事件发送完成后，要在 EditorView 中监听这个事件。它发送的事件也叫 change。创建一个监听函数，称为 `pageChange`，参数是 any，先 console 出来让大家看得更清楚：打印 page 和 e，然后 `store.commit`，这里需要新建一个 mutation 名称，叫 `updatePage`。把它返回出去，添加到页面设置 tab 上的 props-table 的 change 监听上。

最后在 editor store 中像 updateComponent 那样添加对应的事件处理：照猫画虎，而且比它简单很多。创建 `updatePage`，第一个参数 state，传过来的是 key 和 value 两个值。这里先处理 props 即可：`state.page.props[key] = value`，key 需要做类型断言为 `keyof PageProps`，PageProps 是之前定义的一系列页面配置属性。它就是一个 updatePage 的简化版本。

## 发现问题：值需要 url() 包裹

页面上试一下：页面设置中点击删除图片，没问题，value 变成空，并且转换成上传图片组件，发送的类型是 page、key 是 backgroundImage、新 value 是空。再上传一张图片，上传成功，显示 background-image 的 value 是图片地址，但外部的背景并没有更新。

原因在于：background-image 的合法 value 应该是 `url(...)` 包裹的形式，而不是直接写地址。之前也分析过，所以这里要做类型转换。在哪里做？应该在 propsMap 这一层。里面有 initialTransform，但我们忘记了 afterTransform 里做反向转换，用 url 加括号的形式包裹这个值。

添加 afterTransform，它的参数是 string 传过来的值。新的 URL 给它包裹：先判断一下 e 存在（不为空），再进行包裹。使用模板字符串，里面是 url 加 `e`，注意地址外面再加一层引号（单引号、双引号都可以）。假如 e 是空的，就返回空。

## 验证与小结

重新走一遍流程：点击删除图片，删除成功；再点击上传图片，选择同一张图片，点击打开，现在传递就没问题了，value 是 `url("...")` 加上真实的地址，背景也能成功获得新的值并渲染出来。

这样这个属性就没有问题了。我们通过 BackgroundProcessor 这个比较复杂的组件，组合了几个组件的逻辑，完成了背景图片的修改。其实对于任何一个属性，掌握原则就没有什么难的：传入 value，更新后发射 change 事件并带新的值。

这里还有一个优化点：上传的图片最好能根据图片的高度自动调整画布的高度，让背景图片完全贴合整个画布区域。大家可以想想怎样实现：其实就是在上传完毕后发送一个新的事件出去，获取图片的宽高，和画布的宽度做对比，然后发送一个新的 mutation 更新高度。这个优化点我会提交到代码中供大家参考。
