# 10-15-Middleware 中间件第一部分

上节课简单了解了 plugin，这节课画风一转，来到一个我们之前已经有所涉猎的概念：中间件 middleware。了解了 middleware，才能让我们在 plugin 的了解上更进一步。中间件在前端开发中属于比较重要的概念，出现在多种框架中，它特指在输入和输出之间一次性编写特定逻辑来完成重复性的工作。Express、Koa 以及 Redux 中都有类似的概念。

Egg.js 是基于 Koa 的，所以它继承了 Koa middleware 的概念。对 Koa 的中间件，再次强调一下特殊的洋葱圈模型，这是它特有的精髓和特点。看这张图：多个中间件，每个颜色代表一个对应的中间件，会生成一个类似栈的结构，以先进后出的顺序执行。一个请求进来时，最外层的中间件首先执行，当你调用 next 函数时，执行权交给下一个中间件；它再调用 next，一直到最内层的中间件最后执行。执行结束以后，把执行权交回给上一层中间件，再一层层向外，最外层的中间件收回执行权之后，执行 next 函数后面的代码。这就是整个闭环，我们叫它洋葱圈。中间件的每一块逻辑以 next 为界被分为两部分，Koa 的模型可以非常方便地实现后置处理逻辑，在之前和 Express 的对比中我们也强调过这一点。

现在不说概念了，在 Egg.js 中完成一个中间件来做特定功能的测试。我们称这个中间件为 logger，希望它可以记录每一次请求的响应时间，并把时间记录在一个文件中。思路很清楚：这个中间件应该位于最外层（图中灰色的部分）。在最外层中间件开始时记录一个时间，让后面的逻辑执行，执行回到最外层、在最终输出之前再记录一个时间，两者相减就得到时间差，记录到文件当中。

Egg.js 的标准是把中间件放置到 app 当中的 middleware 文件夹下。新建一个文件夹 middleware，里面新建一个文件 logger.ts。每个中间件要导出一个函数，这是一个默认的规则：export default 导出一个函数。在这个函数中还要返回一个 async 的函数。注意这个 async 函数有两个参数：第一个是 ctx，类型是 Context，把 Context 类型引进来；第二个是 next，让它继续执行下一步中间的操作。它的类型首先是一个函数，函数返回一个 Promise，所以我们给它设置一个自定义的类型，返回 Promise< any > 就好了。确定了两个参数之后，就可以在里面写对应的逻辑了。

逻辑上，首先记录一个时间，称之为 startTime，值为 Date.now()。拿到 startTime 后直接执行下一步：await next。执行完所有的 next 之后回到这里，算出当前的时间：Date.now() 再减去 startTime，就算出了流逝的时间。然后写一段字符串，把字符串记录到特定的文件中。写一个 logTime，里面要记录一些信息：先记录时间，新建一个变量 requestTime，用 new Date() 生成一个 Date 对象，把时间打印在开头；然后记录请求的方法，用 ctx.request 的快捷方式 ctx.method；再记录请求的 URL，同样有快捷方式 ctx.url；最后记录花了多少毫秒，写上 ms 单位。

最后把它写入文件。写入文件可以使用 fs 模块上面的方法 appendFileSync，使用同步的方法。这个方法假如没有这个文件会自动创建，假如有了，会把一串字符串添加到文件的最后面。appendFileSync 的第一个参数是文件的路径，我们写一个绝对路径 log.txt，第二个参数是 logTime，最后加上 `\n` 输出一个换行，看起来比较舒服。这样中间件就完成了。

写完之后要让它生效，要添加到 config 的 default.ts 当中。记住所有配置第一时间就要想到这个文件。可以看到这里有个数组，写的就是 middleware，中间件可以按数组添加的顺序来执行。我们只有一个，把 logger 填进去，名称要跟文件的名称对应。添加完毕后试一下是否可以成功运作：随便发一次请求，因为填的是绝对路径，文件应该生成在根目录。可以看到 log.txt 已经出现了，点开看：时间是 GET 方法，URL 是 test/2，花了 3 毫秒。再发送一次请求，它又有了一条新的记录，非常快，0 毫秒 GET。

通过这节课我们编写了 Egg.js 的第一个中间件。由于 Egg 底层采用了 Koa 的实现，Koa 的中间件可以完全兼容 Egg，也就是说把一个 Koa 的中间件下载下来，可以直接在 app 中使用。这是一个初步的学习，下节课我们更深入一些中间件的概念。
