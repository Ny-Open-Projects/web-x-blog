# 17-5-7-路由权限验证 第二部分 - 编码实现

有了上节的流程分析，这节编码实现权限验证。之前在 HomeView 中添加的持久化登录逻辑可以完全删掉了，不需要在组件里做，每次进入路由之前统一完成即可。所有改动都落在路由入口文件 `index.ts`。

## 添加路由元数据

先给各路由补上 meta。Home 和 Template 这两个路由没有权限约束，只加一个 title，用于切换路由时动态更新 document.title。Editor 加 `requiredLogin: true`，必须登录才能访问。Login 页加 `redirectAlreadyLogin: true`，已登录再访问会被重定向到首页。

## return 值替代 next

接着写 `router.beforeEach`。参数有 to（去哪里）和 from（从哪里来）。至于第三个参数 next，查看文档的 navigation guards 一节会发现它已经变成可选参数：不使用 next 也能继续路由，只要 return 对应的值即可，官方现在不推荐 next。return 的几种情况：

- `return false`，取消这次跳转，到此结束；
- return 一个 route location，跳转到新路由，比如直接 `return '/login'` 就会跳到登录页；
- 什么都不 return（undefined）或 return true，路由继续进行，相当于自动调用 next。

新行为的好处是能省掉一些 next 的样板代码：else 分支里"放行"的调用不用写了。

## 编写守卫逻辑

先从 store.state 中取出 user，再解构出 isLogin 和 token，以及 meta 上的三个自定义值：redirectAlreadyLogin、requiredLogin、title。title 变换最简单，判断它存在时赋给 `document.title`。

然后按流程图写主要逻辑。已登录（isLogin 为 true）的分支：判断 redirectAlreadyLogin，为 true 就 `return '/'` 跳回首页；为 false 则什么都不返回，自动放行。

未登录、token 不存在的分支更简单：判断 requiredLogin，需要登录就 `return '/login'`。

最后是 token 存在但 isLogin 为 false 的情况，即上节持久化登录的流程。要把守卫回调改成 async，用 try/catch 包住异步请求。try 里先设置带 token 的 header，然后 `await store.dispatch('fetchCurrentUser')`，成功后判断 redirectAlreadyLogin，true 就 return 首页。catch 里则要弹提示、清理状态并跳转登录页。

清理逻辑提炼成一个 logout mutation：移除 localStorage 里的 token、delete 掉通用 header、state 的 token 置空。它以后还能充当登出功能。守卫里只需 `store.commit('logout')`，然后 `return '/login'`。

## 验证

想看清流程可以在关键位置加 console 或断点走一遍。实测各场景：

1. 未登录状态访问 editor，被弹到 login，受保护路由生效；
2. 登录成功后刷新首页，自动重新登录且不跳转（首页无权限约束）；回车重新进入 editor，可以进入；
3. 登录状态访问 login，自动跳回首页；
4. 把 token 改错后在 editor 页刷新，跳到登录页，并显示"登录已过期，请重新登录"。

核心其实就是这一段守卫代码。建议对照上节的流程图在代码里补上注释，思路会更清楚。
