# 14-39-整合流程，完成自动部署以及回滚

这节课把流程组合起来。目前流程写在三个文档里，先再次梳理要完成的任务，再把三段分开写好的流程组合到一起。最早分析过：大体是两步。第一步在 GitHub Runner 上运行，主要是 build 和 push 镜像，再加上用 SCP 把文件拷到服务器；第二步在服务器上部署并运行。唯一要特殊注意的一点：创建 .env 这一步，之前第一段里只加了两个环境变量，后来又加了多个，现在可以合二为一，创建一个拥有所有环境变量的 .env 文件。

了解了流程就开始写代码。手把手写一遍有助于理解整个流程。job 叫 publish-release，在 ubuntu-latest 上运行；触发条件是特定 tag 被 push（上节课说过）。

```yaml
jobs:
  publish-release:
    runs-on: ubuntu-latest
    steps:
      # checkout 对应的代码
      - uses: actions/checkout@v2

      # 创建包含所有环境变量的 .env 文件
      - name: Create env file
        run: |
          touch .env
          # echo 所有的 secrets 到 .env

      # 登录到阿里云 ACR
      - name: Log into Aliyun ACR
        uses: aliyun/acr-login@v1
        with:
          login-server: https://registry.cn-hangzhou.aliyuncs.com
          region-id: cn-hangzhou
          username: ${{ secrets.ACR_USERNAME }}
          password: ${{ secrets.ACR_PASSWORD }}

      # 使用正确的 GitHub tag 对应 ACR tag
      - name: Build image for Docker
        run: docker build --tag <registry地址>/<命名空间>/<仓库>:${{ github.ref_name }} .

      # 使用标记的 tag 进行 push
      - name: Push image to ACR
        run: docker push <registry地址>/<命名空间>/<仓库>:${{ github.ref_name }}

      # 替换 docker-compose-online 中的占位符
      - name: Find and replace tag
        uses: hiroyago/find-replace@v1
        with:
          find: "{{TAG}}"
          replace: ${{ github.ref_name }}
          include: "docker-compose-online.yaml"

      # 拷贝必须的文件到服务器
      - name: Copy opsflow-backend folder via scp
        uses: appleboy/scp-action@master
        with:
          host: ${{ secrets.HOST }}
          username: ${{ secrets.USER }}
          password: ${{ secrets.PWD }}
          source: "opsflow-backend"
          target: "~"

      # 通过 SSH 登录并重启服务
      - name: Executing SSH and restart Docker
        uses: appleboy/ssh-action@master
        with:
          host: ${{ secrets.HOST }}
          username: ${{ secrets.USER }}
          password: ${{ secrets.PWD }}
          script_stop: true
          script: |
            docker login --username=${{ secrets.ACR_USERNAME }} --password=${{ secrets.ACR_PASSWORD }} registry.cn-hangzhou.aliyuncs.com
            cd ~/opsflow-backend
            docker compose -f docker-compose-online.yml down
            docker compose -f docker-compose-online.yml up -d
            rm -rf .env
            docker logout registry.cn-hangzhou.aliyuncs.com
```

要点回顾：

- checkout 之后创建 .env：它有两个用途（build docker image、start 对应的 app），两个用途的变量不一样但是包含关系，所以只创建一个文件，touch 之后把所有信息 echo 进去。
- 登录 ACR：直接用之前写过的 action。login-server 和 region-id 这里写死没问题；username 和 password 用 secrets，想用 secret 也可以。
- build：特别注意之前版本号是写死的，这里要用对应的 tag。name 写 build image for Docker（对应 ACR 的 tag 更清楚）。命令和之前一样，唯一注意的是最后的内容：tag 位置填 `github.ref_name`，它就是 push 的 tag，这里就是神奇发生的地方，对应关系建立起来了。
- push：同样使用正确的 tag（ref_name）。
- push 完成后，把文件拷到服务器。第一步先做替换：docker-compose-online 里的 `{{TAG}}` 占位符要替换成刚 push 成功的版本号，用上节课的 find-and-replace（find 是 {{TAG}}，replace 是 github.ref_name），和 push 的镜像对应起来。替换后 cat 一下做个简单测试。
- 然后拷贝文件夹到服务器，用 scp action：要拷三个东西，.env 文件、刚替换过的 docker-compose-online、mongo-entrypoint（第一次启动时的数据库初始化文件）。参数和之前完全一样：source 是创建的 opsflow-backend 文件夹，target 是目标服务器用户的 home 目录（波浪线）。
- 最后通过 SSH 登录重启服务，和原来完全一致。复习一下步骤：登录阿里云 ACR；停止服务（第一次启动时停止不会报错，不会中断整个运行）；启动服务；可选的清理工作：删掉 .env 等敏感信息文件，logout 对应的阿里云 registry。

整个流程就是把三节课的内容整合成一个文件，比较长，大家要仔细看一遍。写完先检查语法有没有错误，确认没问题。

为了把应用的版本和 tag 对应起来，把 package.json 的版本改成 1.0.6（ping 接口里会输出这个 version，可以验证部署的镜像是否正确）。commit（update version 1.0.6），打 tag v1.0.6，然后 `git push --tags`。

tag push 成功后看 Actions：正在运行且带着对应的标签。点进去整个流程时间稍长，build 和 push image 都需要时间，大约三分钟，耐心等待。等待之后整个流程完成，看到这么一长串自动化流程变绿，作为前端第一次在 DevOps 上花这么多时间，会有一种特殊的成就感。

验证结果：到阿里云的镜像版本页，可以看到 v1.0.6 已 push 成功；再到应用里刷新 ping 接口，出现 app version 1.0.6，说明部署成功且版本号完全正确。

部署成功后，一键回滚也非常方便：只要重新执行对应的任务。比如之前部署过 1.0.5，进入那个 job 点 re-run all jobs 就可以完成回滚。已经 push 过的 image 再次 push 相同版本也没问题：layer 都存在，push 会比较快。这次回滚的 job 运行了 2 分 34 秒，之后刷新服务器上的版本，回滚到了 1.0.5，版本回滚成功。

经过这一段奋斗，我们用 GitHub Actions 完成了自动部署，并且可以相对轻松地完成部署和回滚。请记住：GitHub Actions 只是完成 CI/CD 的一个工具，如果你公司用 Jenkins 或其他工具，也可以参考这个流程，流程本身才是关键。
