# 6-9-添加属性和表单的基础对应关系并展示

上一节课完成了编辑组件属性的第一步工作，现在到了第二步：将属性以不同类型的表单呈现到右侧。在最初的技术实践方案文档中，我们描述了这个过程，看看当时是怎么想的。可以从另一个维度理解这个问题：使用特定的数据结构，把业务组件的属性和它需要对应编辑的组件对应起来。比如有 text 和 color 两个业务组件属性，我们就创建一个对应关系：text 使用 a-input 来渲染，color 使用 a-color-picker 来渲染。这样完成了界面到数据的抽象。

现在来完成这个任务。这节课的难点还是 TS：想获得精确的类型，确实要下一些功夫和思考。第一个任务是创建对应关系。我们希望获得这样一个数据结构：key 和业务组件的属性一一对应，值描述用什么组件渲染这个内容，以及其他一系列属性。

先确定一个接口来规定这些属性。我创建了一个文件 PropsMap.ts，所有对应关系都放到这个文件里。首先 export interface，称之为 PropToForm，里面的属性有：component，表示用什么组件来渲染 form 表单；再加一个 value，是它对应的值，可选。有了这个类型，就可以确定整体类型了，称之为 PropsToForms。最简单的想法是使用 indexable type：key 是 string，值都是可选的 PropToForm。

但这样做是否是最好的解决方案呢？能否更进一步？我们知道 key 其实是确定的，和文本组件的属性是对应的。这时可以使用之前在 TS 中学到的属性遍历。首先把类型引过来：from './defaultProps' 里的 TextComponentProps，然后进行循环，拿到它所有的 key：`[p in keyof TextComponentProps]?`（还记得吧，in 后面是关键的 keyof），每个 key 对应的类型是 PropToForm。回溯一遍：先拿到它所有的 key，再用 in 循环。看最后的结果：text、fontSize 所有属性都出来了，和 TextComponentProps 一一对应。再给它加一个问号，因为不是所有属性都有一一对应关系的表单。这样转换就完成了。

最后添加测试数据，它是具体真正的实现，也就是这个对应关系本身。它称之为 mapPropsToForms，类型是 PropsToForms。可以看到自动补全都有了，所有的属性都出现了。text 用什么 component 渲染呢？a-input，这是 Ant Design Vue 提供好的 input 组件，我们使用它来渲染。

确定了对应关系后，就可以使用它来渲染组件了。这时需要一个新组件：输入的是每个业务组件对应的属性，输出的是每个属性对应的一系列表单组件。用图来描述这个过程：创建一个新组件 PropsTable，传入一个属性 props，就是业务组件传入的一系列属性；假如是文本组件，里面就有 text: hello 等一系列内容。这个组件要做的事情是把这些数据转换成界面，转换需要两部分：把这种数据结构转换成那种数据结构，text 不变，上面变成 component（对应关系里的 component），value 直接转换到 value 属性中。当然转换时需要我们定义的 PropsMap 对应结构辅助，使用 props 和定义好的结构转换出新结构，然后展示。展示很简单，只要 v-for 把里面的属性一一展示即可。

现在来书写这个组件 PropsTable。首先确定属性：它的属性称为 props，类型当然是 object，但有没有更详细的类型？有，就是 TextComponentProps。可以使用 PropType，用 TextComponentProps 做精细的类型标注。

接下来完成数据的转换。要生成的数据结构可以是数组也可以是 object，看大家喜好，我按图上的做法转换成一个对象。将一个对象转换为另一个对象，之前用过 mapValues，很好用。但注意转换的对象不是一一对等的：比如输入一系列属性，最后转换出来要先判断这个属性在 propsMap 里有没有被定义，有定义才转换。所以转换出来和输入的数目可能不对等。这里想到的方法是使用 reduce，用 lodash 当中的 reduce 函数，它可以作用在对象上面，比原生 reduce 方便一些。

最终的转换属性称之为 finalProps。注意要用 computed，因为它要根据传入的属性改变。return reduce：第一个参数是我们的 props（这里要加一下非空断言，因为它是必传的 props!），第二个是回调函数。回调有三个参数：第一个是一直累加的数据 result，它的初始值在第三个参数位置定义，这里定义为空对象；第二个是循环中的 value，第三个是循环中的 key。先直接把 result 返回出去，然后在里面做判断和处理。

首先判断这个 key 在 propsMap 中是否存在。取出来的值称之为 item，它是 mapPropsToForms 中取出的一项。这时发现出现了一个类型错误：因为 key 是普通的 string 类型，而 mapPropsToForms 定义的 key 需要 TextComponentProps key 的联合类型。所以做一个类型断言：新建变量 newKey，`key as keyof TextComponentProps`，把 newKey 传进去，就没有问题了。

接着判断到底有没有 item：循环中判断有没有对应关系，假如有的话，就把这个结构放入最终的结构中。在最终结果上累加：先把 value 添加上，现在这个取出来还没有 value，`item.value = value`，属性就都全了，可以放到最终结果上：`result[key] = item`。根据数据结构想一想：key 是 text，最终的数据结构就是那样的形式，放置完成。

但这时又出现了一个错误。为什么？因为 result 一开始被定义成了 object 类型，不能在一个普通的 object 类型上使用 indexable type 进行值的索引。还是用类型断言转换：我们知道最后输出的应该是 PropsToForms 类型，把它 `as PropsToForms`。现在就成功得到了 finalProps。它的推论类型也很对：ComputedRef<PropsToForms>。看 finalProps.value 点，可以点出所有的属性，component、value 都能拿到，类型运作得很完美。把 finalProps return 出去。

有了 finalProps 就可以展示对应的属性了，这步很简单。创建一个 div，v-for 循环：value, (key, index) in finalProps，加一个 key，再加一个 class 称为 prop-item。里面渲染真正的表单组件，已经试过很多次了：使用 component 标签，:is 应该是 value.component。但发现有个错误：因为 value 有可能是 undefined，所以要做判断，v-if="value"，有值再进行渲染。除了 is，还要添加 value 属性，取 value.value，也就是最终的值。通过这样完成了整个界面的展示。

最后把这个组件放到 editor 的右侧，并把 currentElement 的 props 赋值进去，这里我已经写好了。直接在页面中感受一下：刷新，点击 hello，可以看到右侧渲染出了一个 a-input，并且它的 value 已经放在中间，hello 显示在那里。再点击 hello2，hello2 也放进去了。再添加几个内容，没问题，它可以实时地改变。

这节课实现了一个简单的属性和表单对应关系，点击画布中的组件，可以在右侧成功渲染出对应的表单组件和值。但目前 propsMap 里的值还非常少，接下来的课程中会慢慢扩充它，让所有属性都有对应的 component。任务到这里完成，谢谢大家。
