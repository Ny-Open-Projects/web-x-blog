# 16-3-1-拖动改变大小的原理

上一章完成了拖动改变位置的需求，这一章把交互升级，完成拖动改变大小的需求。和拖动改变位置一样，改变大小最终的目的也是通过一系列的鼠标事件改变一系列定位的值。上次改变的值只有 top 和 left，现在还要改变元素的 width 和 height，也就是宽度和高度。

## 拖动把手：四个角上的点

首先要知道处理拖动大小的 handler 在哪里，也就是在哪个元素上触发对应的机制。用交互工具看一下：元素被选中时，改变大小的关键点是图层周围围绕的一圈小方块，总共八个点，这些点都可以拖动，鼠标放上去还会有鼠标样式的改变。

在我们的需求中，创建四个点就够了，让它们分别位于图层的四个角上。创建这四个点不难：创建四个对应的 div，做成圆形，设置鼠标样式（resize 类光标），使用绝对定位并设置 top/left/right/bottom，就能创建出对应的样式。

第二步是添加事件。其实和改变位置是一个意思：需要分别在这四个点（四个元素）上添加 mousedown（鼠标按下去）、mousemove（鼠标移动的时候）到 mouseup 一系列事件，在这些事件过程中改变一系列的坐标或大小，完成整个过程。

## 四种拖动情形的计算

之前改变定位时，只需要在移动的时候改变 top 和 left 的值。现在比拖动改变位置更复杂一些：还需要改变 width 和 height，并且对四个角度的拖动有不同的处理。

**情形一：拖动右下角（最简单）。** 为什么简单？因为拖动过程中整个定位（top 和 left 值）不用改，只修改元素的宽度和高度。图示：黄色区域是元素原始的位置，绿色区域是拖动右下角到达的位置。计算新的宽度：拿鼠标的 clientX，减去原始元素的 left 坐标（从那里到这里的位置），就获得了新的宽度。高度完全一样：用 clientY 减去原始元素的 top 值。非常简单，第一种情况就解决了。

**情形二：拖动右上角。** 宽度的计算完全一样：鼠标到这里的位置减去 left 值。高度的计算有区别，因为这个点跑到了上面去：拿到原始方块（橙色）的 bottom 值（从这里到这里的距离），减去 clientY（现在鼠标的坐标），最终获得高度，也就是那条红色的线。当然它的 top 值也发生了改变，原来在上面这个点，现在变成了上面的点。top 值是根据外侧画布（container）的坐标计算的：用 clientY（从这里到这里的值）减去 container 的 top 值（从这里到这里的值），就算出了新的 top 值。

**情形三：拖动左下角。** 有了前两种分析，这个情况就轻车熟路了。高度跟第一种情况一样：clientY 减去原始的 top 值，算出新的高度。宽度发生了变化，跟情形二的 top 计算异曲同工：拿到原始方框（黄色）的 right 值，减去鼠标的 x 坐标，得到新的宽度（绿色部分）。最后还要算 left 值，它的 left 也改变了。根据之前的经验，这时候又要借助 container：拿鼠标的 clientX 减去 container 的 left 值，就能算出新的 left 值。

**情形四：拖动左上角。** 不详细分析了，它是最复杂的，但其实就是前面三种情况的组合：四个值都要改变。

## 所需的数据

通过图的分析，整个算法的过程已经清楚了。过程中需要几组数值：

1. 鼠标的位置：clientX 和 clientY；
2. 被拖动的原始元素的几个坐标值：top、left、right、bottom；
3. 外侧画布 container 的 left 和 top 值。
