# 18-2-1-发布作品需求分析

保存作品的功能完成后，接下来是保存之后的一项重要工作：发布。发布意味着把作品从私人状态转换成公共可访问的状态。先在已完成的应用页面上看看有什么需求。

点击发布，会有一个发布状态，时间稍长，因为中间有审核过程，检查作品里有没有非法数据。发布成功后弹出一个浮层，上面有一系列操作，需求就按这些操作来讲：

- **左侧封面图**：它其实是当前作品页面的截图，所以需要一个把 DOM 节点转换成图片并上传的工具；
- **右侧信息分四块**。第一块是作品标题、描述和分享图，标题在这里设置，分享图和描述在"预览和设置"里设置，这部分简单，先不管；第二块是两个 tab："发布为作品"已经完成，切换到"发布为模板"再点击发布，会重新发一个新的 POST 请求，发布为另一种作品形态，模板；第三块是作品的渠道列表：每个条目左侧是 URL 的二维码，中间是显示 URL 的输入框和名称，点击复制按钮自动复制 URL，删除按钮在只有一个渠道时是 disabled 的；第四块是创建渠道区域：左侧输入渠道名称，点击右侧按钮完成新建，新建后就能看到多渠道列表，删除按钮随之可用，点击即可删除渠道。

## 需要的接口

| 功能 | 接口 | 说明 |
|---|---|---|
| 发布作品 | `api/works/publish/{id}` | POST，body 不需要数据 |
| 获取渠道列表 | `api/channel/getWorkChannels/{id}` | 返回所有渠道的数组，id 是作品 ID |
| 创建渠道 | `api/channel` | POST，body 有 name 和 workId 两个参数 |
| 删除渠道 | `api/channel/{id}` | DELETE |
| 发布为模板 | `api/works/publishTemplate/{id}` | POST，无参数，URL 与发布作品不同 |

## 可能用到的第三方库

任务里有几个复杂操作需要第三方库：一是截图，把 DOM 结构转换成图片并上传持久化；二是把 URL 生成二维码；三是复制一段文字到剪贴板这个常见需求。

截图的解决方案选择大名鼎鼎的 **html2canvas**：GitHub 上有 23k star，是 web 页面截图的通用解决方案。看 README 里 "how does it work" 一节：它把页面渲染成对应的 canvas image，渲染过程中把 DOM 节点上的各种样式都添加到对应的元素上。特别注意它**不需要任何服务器端渲染**，整个页面都来自客户端浏览器。但要留意处理图片时的跨域问题，比如我们的背景图片上传到了 OSS，就可能遇到跨域，后面使用时再细说。

它的用法非常简单：html2canvas 接受一个 DOM 节点作参数（文档示例是 document.body），返回一个 Promise，then 里拿到的是一个 Canvas element，用 Cropper.js 做截图时也遇到过这个类型的元素。

这节完成了需求分析、接口分析、第三方库梳理，并选定 html2canvas 作为截图工具。下节完成发布的第一个任务：将编辑器区域截图。
