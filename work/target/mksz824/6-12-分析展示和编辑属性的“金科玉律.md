# 6-12-分析展示和编辑属性的“金科玉律

上节课我们完成了一系列属性的展示。现在我们支持了一系列 Ant Design Vue 内置组件的属性，包括两种：一种是直接进行展示的，还有一种是拥有子属性 options 的。当然还有一部分是目前 Ant Design Vue 里没有的组件，需要我们自己开发，或者用其他组件进行二次开发。

当时其实已经在文档中写了：比如颜色选择组件 Color Picker 需要二次开发；或者某种样式的 Checkbox，Ant Design Vue 里也没有实现，也要自己开发。但请记住，不管多复杂的组件，它们最终实现的需求都非常简单。任何我们需要编辑的组件，都应该有一个传入的属性，可以输入想编辑的值，这个值可以是丰富的数据类型：颜色值、字符串、数字，或者是一个复杂的 object、一个数组等等。

现在有个小问题：我们目前都使用 value 这个属性名称，但为了适配更多组件，需要在 PropToForm 上面再添加一个 valueProp 的动态属性。为了适配这些组件，传入的属性名称有可能不叫 value，比如叫 value2，或者叫 model 等等一系列的名称。我在源代码里已经做了这个修改，就不手把手写代码了，其实很简单：在 propsMap 多加一项 valueProp，渲染时判断 valueProp 是否存在，存在就使用它，没有就默认 value。这里用方括号动态地赋一个值，这样就完成了这个功能。

说完属性的展示，现在来到最重要的部分：属性的编辑和更新。开发 Vue 或 React 的过程中，大家应该都知道一个术语：单向数据流。它非常简单，但强大地描述了展示和编辑流程中数据传递的过程。

简单看一下数据过程。任何的属性都从这里开始：来自全局的 store。editor.vue 使用 useStore 钩子函数拿到全局 store 里的数据，并将值（比如 store.state.name，值是 123）传递给对应的编辑组件。这里只有一个金科玉律：value，传入你想要编辑的值。这时候组件中就已经展示出 123 这个属性值，这就是已经描述过的属性展示，大家应该非常熟悉。

现在谈属性更新。当数据发生任何改动时，比如从 123 变成 1234，改动完后，这个组件应该发射一个事件，图上写的是 @change 1234。事件名称跟传入一样可以自定义，默认为 change，这是数据改动时发射出来的通用事件名称。这个数据会发射出我们想要进行改动更新的值，比如 1234。

组件外层拿到这个事件以后（比如 editor.vue），因为它可以和全局 store 连接，这时候就可以进行 commit：传入当前的 key 和更新的数据这两个参数，然后 store 中有特定的 mutation 对它进行修改。修改完毕以后，store 的响应式数据就被更新掉了，name 从 123 变成了 1234。然后数据再次从顶部流动下去，组件的值就被更新了，这样就完成了整个流程的闭环。

这个方案其实在编辑器技术方案里面已经记录过了，现在用图的方式再给大家描述一遍，让大家有更深刻的认识和思路。刚才分析以后，我们可以得到这样的一个标准：对于任何想要实现属性编辑的组件，首先它必须提供一个属性，名称可以变换，默认为 value，这节课我已经支持了自定义写法，可以写任何值，但只有一个，用于传入需要编辑的属性，这是属性的显示。

那么更新呢？必须在更新后提供一个事件，发射出编辑后新的值。事件名称也可以变化，默认为 change。这个编辑的事件中包含更新完成的值，就像这样（伪代码）：handleChange 里面有 newValue 新的值。这就是我们得到的显示和更新属性的金科玉律。如果你想开发一个自定义组件，要支持属性编辑，也必须遵守这个规则。
