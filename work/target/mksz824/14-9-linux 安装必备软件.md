# 14-9-linux 安装必备软件

上节课完成了初始的安全设置，这节课来完成和应用相关的软件安装。应用需要在特定软件基础上才能运行，所以要在云服务器上装好这些依赖。这其实也是传统部署的一个弊端：在新的云服务器上部署（尤其是多台服务器部署）时，第一步都得安装特定依赖软件；不同操作系统还可能有不同的安装方式、版本兼容性问题，很容易出错。这也为之后要学的内容埋下伏笔。

## 必备软件清单

必须安装的软件有四个：

1. Node.js，最好安装 16 以上的版本，因为代码中用到了 fs 的 stream 模块；
2. MongoDB，我们的数据库；
3. Redis；
4. Git，用来 clone 代码。

有了这三个运行时软件加 Git，整个应用才能跑起来。

## 两大 Linux 发行版家族

Linux 发行版简单来说可以划分为 Debian 和 Red Hat 两大家族。Debian 是完全免费的 Linux 发行版，代表发行版是 Ubuntu，它基于 Debian，为新手做了很多优化，更容易上手，使用 APT 包管理系统，软件格式是 Deb 包。Red Hat 是商用 Linux 发行版，旗下有完全免费的 CentOS，它等于 Red Hat 减去一系列收费软件，使用 YUM 包管理系统，软件格式为 RPM。

## 安装 Node.js

安装方式有两种：一种是 NVM，和 Mac 本地安装一样，这里不展开；我们只关注使用包管理器。注意，安装软件最好切换成 root 用户，普通用户很多权限是不够的。

在 Ubuntu 下面可以用 `apt-get install` 安装软件源里的软件。但很多软件并不包括在官方软件源中，Node.js 就是如此：直接运行安装命令会报错，说 nodejs 这个软件包不存在。

这时软件源提供了一种特殊的扩展机制。官方文档给出了 Ubuntu 的两行安装命令：第一行用 curl 下载一个文件，然后用 sudo bash 运行这个脚本；如果你去看这个 URL 的源文件，会发现它是一个 shell 脚本，目的是在特定文件中添加特殊内容。第二条命令就可以直接用 apt-get install 安装了。所以第一行的作用是添加一个特定的软件源，让安装 Node.js 变成现实。

这就是 apt 包管理器的扩展机制：任何人都可以发布对应的 PPA（个人软件源），提供第三方软件的下载。添加了软件源之后，再用 apt-get install 就能找到对应的软件并下载了。

## 软件源的存放位置

登录服务器看一下。node -v 可以看到安装的是 16.13.1，最新的 16 版本。留意两个路径：第一个路径里的文件由阿里云添加了很多软件源，所以我们下载时经常走阿里云的代理，速度快很多。第二个路径是一系列第三方软件源，它是个文件夹，进去 ls 一下，每一个文件代表一个软件源，其中的 nodesource.list 就是刚才添加的 Node 安装源头，内容就是简单两行，代表一个对应的 URL。

CentOS 有着一样的机制，执行官网摘抄的命令添加源之后，就可以 `yum install nodejs` 安装了。查看 CentOS 的所有软件源用 `yum repolist all`。

## 安装 MongoDB 与服务管理

第二步安装 MongoDB。可以像之前一样从源代码下载安装（回顾之前的内容即可），它也提供包管理器安装方式。Ubuntu 下的步骤同样是添加软件源、更新，然后：

```bash
apt-get install -y mongodb-org
```

安装完毕后，简单谈谈 Linux 中的服务管理。我们安装的软件中有些需要管理状态，比如 MongoDB 这样的数据库就有状态，需要启动、关闭、查看当前状态等操作。新的 Linux 发行版提供了一个内部模块 SystemD 专门管理服务，在它之上衍生出两个快捷管理服务的命令：service 和 systemctl。systemctl 比 service 功能更强大一点，两者语法很接近：

```bash
service mongod status    # 服务名在前，操作在后
systemctl status mongod  # 操作在前，服务名在后
```

操作指令有 status、start、stop、restart 等。其实 service 就是在 systemctl 上面包了一层，是它的快捷方式而已，我个人更喜欢 service，拼写更简单。

service mongod status 可以看到 mongo 是 active running，运行良好。重启操作普通用户 viking 没有权限完成。任何安装的服务（比如数据库、缓存等）都可以这样管理，看一下 redis 的 status，同样是 active running。service 命令之后要经常使用，请记住它的基本用法。

## 收尾

Redis 和 Git 从源代码安装可以回顾之前的章节；用包管理器安装则很简单，它们都在官方软件源中，不用添加第三方 PPA，直接安装就好，这两个任务交给大家。

最后验收四个软件：node -v、mongo、redis-cli、git --version，全部安装完毕且 Redis 也在运行，环境就准备完成了。

回顾一下，这节课还学了包管理器如何添加第三方软件源，以及 service 服务管理机制。也再次体会到，准备环境是一件费时费力的事情：假如应用要部署到多个环境、多个操作系统（有 Linux 还有 Windows），不同系统不能共享同一个脚本操作，要人工登录一台一台去配，非常耗时，还可能出现兼容性问题。怎样解决这个问题？之后几章会慢慢揭示答案。
