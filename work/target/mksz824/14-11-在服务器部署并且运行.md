# 14-11-在服务器部署并且运行

上节课我们完成了配置的修改。开始部署之前，我要先修改上节课代码中的一个错误，在这里向大家表示抱歉。还记得设置生产环境配置的时候，我们对 jwtConfig 中的 redirectUrl 是这样修改的：直接把问号去掉，当时错误就消失了。但其实这样做是有问题的，因为 jwtConfig 是 undefined，我们在 undefined 上再取值，最后其实是会报错的。这里需要把它改成对象的形式。请大家特别注意：如果是多层嵌套的配置，都不要直接去修改里面的值，而是要以对象的形式再写一遍。其实上节课写代码的时候，出现错误时编辑器已经及时提示了，但我们没有特别注意，造成了这个问题的出现。

修改完这个问题，我们就可以把代码部署到机器上去了。部署大体的流程，就是把本机中运行 npm run start 的启动过程复制到服务器上运行，是同样的过程，只不过运行环境换成了 Linux 主机。

第一步，登录我们的服务器。特别注意不要使用 root 进行登录，root 登录已经被禁止了。登录进来以后，第二步，我把这些步骤都写到了对应的文档当中，大家可以自己去看。第二步是 clone 代码，大家可以自己上传到你的代码库。我选择了 GitHub，大家可以看到我已经 clone 下来了，进入 OpsFlow 后端目录。大家也可以选用自己喜欢的 repository 地址。

第三步是安装依赖。这里要注意一点：我们有一个比较大的库，就是处理文件的 sharp。这个库下载起来比较慢，大家很可能想到使用淘宝代理进行 npm install，但即使用了淘宝代理，它还是需要安装一个二进制文件，这个文件是从 GitHub 下载的。和 Electron 的道理一样，下载过程中非常容易出错，并且破坏整个安装流程。由于现在我们使用了 OSS，其实 sharp 已经不使用了，可以将它从代码中去掉。如果还想留着，今天我查了对应的文档，sharp 其实是支持使用淘宝镜像下载对应的二进制文件的。文档里写：a mirror site based in China provided by Alibaba，包括二进制的各种文件，sharp 和 libvips 都有，这样下载就会非常快。大家可以按照文档去设置，也就是 npm config set sharp_binary_host、npm config set sharp_libvips_binary_host，其实就下载这两个二进制文件。这个留给大家自己去设置，然后进行 npm install。

下载完依赖以后，下一步先不要着急启动，也就是设置 .env 文件。大家都知道 .env 文件是运行必不可少的，里面包含各种我们需要的私密信息。但这个文件特别注意：它不在代码库当中，所以需要我们手动创建。直接 touch 一个 .env，我这里已经创建了。可以看到 .env 已经出现，我把它需要的一些环境变量都复制进去并保存。这一点大家要特别注意。

现在完成了前四步。第五步，需要开启云服务对应的端口 7001，后面这个端口有可能会做具体修改。为了给大家演示，我们把 7001 端口在阿里云的 ECS 中开放一下，它默认是不对外开放的。这里我只说阿里云的设置过程，其他云平台大家可以自己去查看。点击你对应的资源，到云平台控制台下面，在左侧列表点击安全组，然后点击配置规则。点击以后可以看到一系列对应的端口，System Created Rules 是默认的，比如 -1 和 22（22 是 SSH 使用的端口）。在这里我多添加了几个：HTTP 经常用的端口 80，HTTPS 的端口 443，还有刚才说的 7001 和 7002，这两个是为了测试使用。大家可以点击手动添加，添加具体的值就可以了。

添加完毕以后，现在就可以启动服务器了。启动时特别注意：首先确定 MongoDB 和 Redis 都在运行状态。可以用 service 来看：service mongod status，可以看到它是 active (running) 的；再看 service redis status，两个都在运行。

然后第一步当然不是 run start，而是要生成具体的 js 文件，因为我们还有一个编译的过程：npm run tsc。等一会儿以后，js 文件成功生成，就可以 npm run start。这里我把 port 简单修改了一下，改成了 7002。大家使用默认的 7001 也是可以的，在 egg-script 后面添加一个 --port 这样的参数。看一下 package.json 的 scripts，我这里简单改成了 7002，因为我要测试一下这个参数能不能使用。

现在就可以通过 IP 加端口的形式来访问了。访问对应的 IP 加端口看是否部署成功：我的 IP 是 121 开头的这个地址，端口号是刚才修改过并且开放的 7002，访问它的 /api。可以看到它能成功返回信息，我这里把所有的 config 都输出了，所以都显示在这里了。这说明我们成功地在服务器端把应用运行起来了，这节课的任务也就完成了。

请特别注意，我们说的这一系列步骤是缺一不可的，大家要按照这些步骤来完成。
