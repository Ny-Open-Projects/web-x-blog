# 4-2-安装 Typescript

上节课说了 TypeScript 的来源和优势，这节课的任务就是安装并使用它。安装之前，先确定本机的 node 和 npm 版本。我建议 node 升到 16 以上，我们本机是 16.13.0，这个版本会作为项目的主要版本。

每次说到 node 安装，我都会安利 node 版本管理软件 NVM，它非常方便，可以安装多个版本的 Node，没试过的同学可以去官网按步骤安装。

## 安装 TypeScript

确定好本机环境后，来到 TS 官网，点击下载，可以看到两种安装方式：在项目中安装，或者全局安装。这里先使用全局安装，直接复制官网的命令：

```bash
npm install -g typescript
```

`-g` 就是 global，全局安装。稍等片刻安装完毕，它会把一个全局命令 tsc 装到全局。使用 `tsc --version` 可以查看版本，当前是最新版 5.1.6。

做课难免遇到版本升级的问题。我在之前做课的过程中，经常遇到学生安装的版本比我做课时更新的版本，一些课中的 API 可能会发生简单变化，使用时会出现问题。所以如果你想和本课完全相符，可以指定版本号安装；如果想用最新版，遇到问题不妨查查对应文档和 changelog，自己解决一下。

tsc 的全称是 TypeScript Compiler，就是 TS 的编译器。安装完编译器，还需要一个称手的编辑器来写代码。TypeScript 最大的优势就是增强了编辑器和 IDE 的功能，包括上节课演示的代码补全、接口提示、跳转到定义、重构等。主流编辑器都支持 TypeScript，这里推荐老朋友 Visual Studio Code 作为主力编辑器，它对 TS 的支持非常完美、非常强大。

## 第一个编译实验

打开编辑器，创建一个测试文件夹叫 test，在其中添加一个以 .ts 结尾的文件。可以看到，文件内容和普通的 JS 文件没有任何区别。

接着在命令行用 tsc 编译这个文件：输入 tsc 加上文件名 test.ts，回车。会发现多出一个新文件，打开看，它和源文件没有什么区别，说明 TS 天生适配 JS。

现在加一点 TS 的特性，让大家简单了解一下（下节课详细讲解）：在 name 后面加一个冒号再加 string，这样就指定了传进来的 name 必须是 string 类型。

```ts
function greet(name: string) {
  console.log(`Hello, ${name}`)
}
greet('world')
```

为了保险起见，先删掉生成的 JS 文件，再编译一次。点开新的编译结果，发现它和之前完全一样：编译为 JS 以后，并没有插入检查代码。结论是 TS 只会做静态检查，如果发现错误，编译的时候就会报错。

那我们故意把类型弄错看看结果：原来指定的是 string 类型，传入的也是 string，现在改成传入 123。编辑器立刻提示类型错误。删掉再运行编译，稍等片刻后 tsc 也会抛出对应的错误，告诉我们传入的是 number，而这里需要的是 string。

注意一个细节：虽然编译时报错了，但编译结果 test.js 还是生成了，里面传入的是 123，我们仍然可以使用编译之后的文件。如果要停止这个过程，可以在 tsc 的配置中完成。
