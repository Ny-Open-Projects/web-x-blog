# 14-24-使用.env 保存 docker 中的敏感信息

上节课用 Docker 的特殊文件夹里的脚本，完成了数据库初始化和连接验证。但现在有个重要问题：Docker Compose 的 environment 中 root username 和 password 都是明文，setup 脚本里的用户名密码也都是明文。这些文件一旦不小心提交到代码库，很容易造成隐私泄露。最好的方式还是把环境变量写入一个文件，就是我们一直在用的 .env，隐私数据都应该写进去。

## env_file 字段

怎样在 Docker Compose 运行时加载这些环境变量？用一个特殊字段 env_file。它和 environment 是一个意思，只不过会从对应的文件中读取所有环境变量，这样私密信息就都放在 .env 里，不用担心泄露。

把这一系列环境变量添加到 .env（敏感内容就不展示了）：因为要创建 root 用户，需要 root username 和 root password，必须写成 Mongo 启动时内置的那两个环境变量格式（MONGO_INITDB_ROOT_USERNAME / MONGO_INITDB_ROOT_PASSWORD）；另外还要创建数据库管理员，加两个自定义变量 MONGODB_USERNAME 和 MONGODB_PASSWORD。

还有一个关键问题：怎样在 setup.js 中访问这些环境变量？很遗憾，经过探索发现没有办法。因为 .js 脚本在一个独特的沙盒中运行，只提供了 Mongo shell 的内置环境（比如全局方法 connect），无法访问常见的全局变量：运行时 `console.log(process.env)` 会发现 process 直接是 undefined。

## 改用 shell 脚本

好在 `/docker-entrypoint-initdb.d` 除了 .js 还支持 .sh。shell 脚本可以轻松访问所有环境变量，所以改弦更张，用 shell 脚本重写这个任务。Mongo shell 的语法我们其实已经很熟了，之前 docker exec 进去用的就是它。把 setup.js 里的语句翻译成 shell 写法：

```sh
#!/bin/sh

# set -e：脚本中任何命令出错（返回值非零）就停止执行并退出
set -e

mongo -- "$MONGO_INITDB_ROOT_USERNAME" <<EOF
use admin
db.auth('$MONGO_INITDB_ROOT_USERNAME', '$MONGO_INITDB_ROOT_PASSWORD')

use opsflow
db.createUser({
  user: '$MONGODB_USERNAME',
  pwd: '$MONGODB_PASSWORD',
  roles: [{ role: 'readWrite', db: 'opsflow' }]
})

db.createCollection('works')
db.works.insertMany([ { /* 模板数据 */ } ])
EOF
```

开头是标准 shell 头，然后加一条特殊命令 `set -e`：只要脚本中发生任何错误（后面的语句返回值不等于零），就停止执行并退出。默认情况下 shell 脚本碰到错误虽会报错，但会继续执行后面的命令，`set -e` 经常放在脚本最开始使用。

这里有个难题：需要先运行 mongo 命令，它会进入一个子命令行（新的 CLI），后续命令要在子命令行里输入。shell 中有个很好用的技巧：命令加 `--` 再结合 `<<EOF`，表示后续输入作为子命令行或子 shell 的输入，直到遇到 EOF 为止，再返回主调 shell。写法就是 `mongo -- <<EOF` 开始，中间写 Mongo 的处理命令，结尾加 EOF 退出子 shell。

授权部分：可以像之前一样用 `-u`，也可以直接在 shell 里授权。第一步 `use admin`，用 `db.auth` 把两个内置环境变量添加进去完成授权。成功后依次：`use opsflow` 切换数据库；`db.createUser` 创建真正的业务子用户，用 $MONGODB_USERNAME 和 $MONGODB_PASSWORD，roles 是 readWrite、作用于 opsflow；最后和之前一样 `createCollection` 创建 works，`insertMany` 插入一条模板数据（insertMany 里是数组），稍后可以查看是否添加成功。全部处理完毕，记得一定要加上 EOF，代表子 shell 中的工作处理完毕。

## 注入环境变量并联合运行

写完后删掉 setup.js，只留下这个脚本。回到 docker-compose.yaml：去掉 opsflow-backend 的注释，让它和 Mongo 一起运行；在两个服务上分别通过 env_file 注入 .env，后端需要拿到环境变量里的信息去连接数据库。

环境变量注入以后，修改 config 的 production：地址 opsflow-mongo:27017/opsflow 没问题，但连接要提供用户名密码 options：user 和 pass 分别用 `process.env.MONGODB_USERNAME` 和 `process.env.MONGODB_PASSWORD`。特别注意：平时用 dotenv 库对 .env 做处理，但在 Docker 中环境变量会直接被注入到 process.env，不需要另外处理，直接使用即可。

运行前还是先把 .docker-volumes 删掉，做一次全新的运行。然后 `docker compose up -d`，因为要重新 build image，稍等一会儿。容器重启成功后两个服务都是绿色。

再强调一点：每次重新运行都会重新 build 一个 image，记得把不再使用的旧 image 删掉，否则会积累大量废弃镜像，浪费空间。

验证：访问 api/templates，可以看到初始化脚本中的数据已经插入，并且能成功连上数据库，说明使用环境变量中的用户名密码连接成功，任务完成。

这节课完成了 Docker 中使用 .env 文件保存环境变量敏感信息，改造了 Mongo 的启动脚本，最后用 docker compose 启动 Mongo 和 OpsFlow 后端做了联合测试，两者都能良好运行。下节课把第三个服务 Redis 添加上去，完成整个 Docker Compose 的内容。
