# 19-2-2-使用vuecli生成生产环境代码

上节课简介了生产环境和开发环境的异同，并且提到不同框架和库针对这两种环境都会做一些区别和优化。这节课就使用默认的 build 命令来生成代码。这部分难度不大，很多同学可能已经接触过这个命令，我们就利用这节课理清它的来龙去脉。

## Vue CLI 的命令体系

我们的脚手架是 Vue CLI，它是一个很成熟的基于插件的脚手架平台，内置了几个最基本的命令，比如一直在用的 npm run serve，还有即将使用的 npm run build。先回顾一下 package.json：在 devDependencies 里，使用 Vue CLI 会有一系列以 @vue/cli 开头的依赖，其中最基础的是 @vue/cli-service（当前版本 4.5.0）。它安装完毕后会向项目内注入 vue-cli-service 这个可运行命令，帮助我们完成几个基本功能：npm run serve 在本地运行开发服务器，npm run build 为生产环境打包生成静态代码。

其他命令是通过 @vue/cli 开头的 plugin 插件注入的，比如 test:unit 和 lint 都是插件安装后向 cli-service 注入的命令。

可以用内置命令查看目前注册过的所有命令：

```bash
npx vue-cli-service help
```

它会弹出所有已经注册的命令：serve 运行开发服务器；build 为生产环境构建代码；inspect 查看内部的 webpack 配置。前三个是装最基本的 cli-service 就会提供的，后两个是通过插件注入的。

## build 命令的参数

构建命令有一系列参数，想看详情可以在 help 后面加上命令名：

```bash
npx vue-cli-service help build
```

这时会弹出一大堆 options，每个都有对应的含义，官方文档也写得很清楚，简单解读几个：mode 指定环境的模式（下节课会讲，很重要，默认是 production）；dest 指定输出目录，默认是 dist；modern 是面向现代浏览器自动回退的构建方式，其他选项大家可以自己去研究。

## 执行构建并分析产物

明白了命令和选项之后，在命令行键入 npm run build，这里不添加特殊参数，使用默认值。稍等片刻，终端会输出一系列信息，其中还有一些 warning，先不管它们，重点看最终生成了什么样的文件。

所有生成的文件都在 dist 文件夹下，分为 css、image 和 js 三个文件夹，另外根目录还有两个文件。最重要的是 index.html，这是入口 HTML 文件。看它的源代码，所有逻辑代码都是经过混淆的，但文件本身很简单，格式化之后会发现里面其实就是引用了一系列静态资源。这是一个典型的 SPA 项目，JS 完成主要的渲染和行为。favicon 就是显示在浏览器 Tab 旁边的小图标。

最重要的文件分布在这几个文件夹中：

- 样式：打了两个文件，一个是 app.css，一个是 chunk-vendors，因为我们使用了一系列第三方库，它们的样式被打进 chunk-vendors，app 中是项目单独的样式。
- JS：也是两个文件，app 加一系列随机字符串，chunk-vendors 加一系列字符串，另外两个是它们的 map 文件。
- 媒体文件：项目用到的图片和视频等，这里只有图片。

## 产物里内置的优化

整个 Vue CLI 脚手架的底层封装了 Webpack，帮我们完成本地开发服务器、代码 build、文件转换等一系列工作。生成的静态文件已经为生产环境做了优化：首先选用了 Vue 的 production build，符合上节课说的对 production 的处理和优化；打开一个 CSS 看看，代码也经过了压缩。

文件名也做了重命名，采取了中间是哈希值的命名规范。这样解决一个问题：新版本功能上线时，原来的静态资源一般会被缓存在本地，但我们希望浏览器拿到新的代码，所以在文件后面加一段独一无二的哈希值。有了这段哈希值，浏览器就知道这是一个新文件，需要从服务器再次请求它，缓存就被更新了，我们就能访问到添加了新功能的应用。

刚才还发现 CSS 和 JS 都不是一个文件，而是 app 和 chunk-vendors 两个。这也是一个内置的优化策略：将项目中的第三方文件打成一个文件，我们写的应用代码打成另外一个文件，可以加快加载速度，都是为了生产环境的宗旨而服务的。后面我们会更进一步，使用自定义配置优化静态文件的体积和大小。

这节课了解了 Vue CLI 最基本的 build 命令的使用和生成文件的分析，为后面进一步的自定义打下基础。
