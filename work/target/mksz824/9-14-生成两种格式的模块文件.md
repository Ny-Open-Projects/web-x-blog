# 9-14-生成两种格式的模块文件

上节课我们根据入口文件 index.ts 成功地优化了配置文件。现在整理一下流程：我们需要生成两种格式的模块，也就是两个文件，所以自然需要两个单独的配置文件来完成两个不同的任务。这两个配置文件非常相似，唯一不同的是生成的类型 format 和文件名称，也就是 output 里的两个字段。当然未来可以根据两种不同的格式添加更多有区分的内容，所以我认为把两种格式写成两个配置文件是非常好的实践。

我这里添加了两个配置文件：rollup.umd.config.js 和 rollup.esm.config.js，代表生成两种不同的 JavaScript modules。它们都会以基本配置作为蓝图，修改 output 字段。为了方便生成不同的文件名，我把 name 和 file 函数导出，同时 export default 基本配置。

先写 ESM 格式。很简单，导入基本配置：`import { name, file, basicConfig } from './rollup.config'`。然后 export default：先用三个点把 basicConfig 展开，后面写想覆盖的 output，即两者独特的内容：name 是 esm，file 用函数生成对应的名称，format 是我们熟悉的 es。写完了。复制一份写第二个 UMD：大部分一样，只要把名称改成 umd、format 改成 umd，就改完了。

感觉不错，但现在还有一点瑕疵：每次生成之前，都要手动删除 dist 文件夹。应该添加一个命令，让 build 开始之前自动删除 dist。提到删除命令，大家可能知道 Linux 里有 rm，但这个方法不兼容 Windows，所以需要安装一个跨平台完成删除任务的模块。它叫 rimraf，下载量非常多，大家用 `npm install rimraf --save-dev` 自行安装。

安装完毕后整理命令。首先把 build:esm 的 config file 修改为 rollup.esm.config.js；复制一行，创建新命令 build:umd，对应的文件是 rollup.umd.config.js。再创建一个新命令 clean，用来删除文件夹：`rimraf ./dist`。然后把这些命令组合起来：原来的 build 删掉，第一步先清除，`npm run clean`；接下来 build ESM，`npm run build:esm`；再是 `npm run build:umd`。命令就修改完毕了。

运行一下 `npm run build`。运行完毕，ESM 生成得很完美，但 UMD 出现了一系列警告。第一个警告是 missing global variable names。我很喜欢 Rollup 的一点就是它的错误提示做得非常完美，我多次从错误提示顺藤摸瓜找到文档，或者直接看错误就解决了问题。可以看到，这个问题是因为现在是 UMD 格式，外部依赖都是全局变量。我们的代码中有 `import from 'vue'` 和 `import from 'lodash-es'` 这两个全局变量，但没有设定全局变量的名称，所以出现了警告。它猜测的名称：Vue 的全局变量名是 vue，lodash-es 猜测是这样。但我们知道这是不对的：Vue 的全局变量名首字母是大写的 Vue，而 lodash 直接是一个下划线。

这里就要用 output 的 globals 属性，它可以自行设定全局变量的名称。着眼于 UMD 的配置，在 output 里新添加一个 globals 属性：vue 对应大写的 Vue，lodash-es 对应一个下划线。问题就解决了。再运行一次，第一个问题消失了。

第二个问题两种格式都有：Unused external imports。这和我们的配置没有关系，是 Vue plugin 转换的时候多导入了几个变量没有使用而已，我们没法解决。最后一个问题只在 UMD 出现：mixing named and default exports。由于是 UMD 格式，导出的模块也需要有全局变量的名称。它的提示说：现在没有全局变量名称，需要用 default 去拿到，可能不是我们想要的，可以使用 output 的 exports 属性来去掉这个 warning。它又帮我们发现了一个问题，所以说 Rollup 的错误提示做得非常不错。

修改一下：name 就对应全局变量的名称，这里不使用 package.json 里的 name，因为全局变量很少有叫那种名字的，直接写一个 name 为 OpsFlowComponents。再按提示修改 exports: 'named'。修改完毕，UMD 生成的全局变量名称就是 OpsFlowComponents。再运行一遍 `npm run build`，再进行一次，这两个问题就都消失了，完美。看起来两种格式的模块都生成完毕了。下节课在本地测试一下它们是否好用。到这里，谢谢大家，再见。
