# 14-21-mongoDB 设置访问权限

在进入 Docker Compose 的高级内容之前，先补充一点 MongoDB 的知识，它在生产环境启动 MongoDB 服务时非常有用：生产环境必须开启用户名密码访问，也就是 authentication，来保证安全。

之前用 MongoDB 时发现，安装后启动默认没有任何权限验证：连接时只需要填 IP、端口号和数据库名，就能连上直接使用。所以如果你在公网上运行 Mongo 服务并开放了 27017 端口，任何人都可以不需要任何验证地连上你的数据库进行操作。前几年就闹过一次很大的事件：黑客扫描公网 IP 的 27017 端口，发现大量开放且没有密码保护的 MongoDB，利用这些数据库信息勒索了非常多的钱。结论很明确：必须用用户名密码保护 MongoDB 的访问。

## 用户体系：基于数据库而非系统

MongoDB 的用户名密码和 MySQL 这类传统数据库有些区别。MySQL 的用户密码是基于整个系统的，只要连接上，所有库和表都可以操作；MongoDB 的用户则是基于特定数据库的，每个数据库都可以设置不同的用户名密码。

在客户端软件里可以看到一个特殊的 system：里面有两个安装后自动内置的数据库。一个是 admin，用来创建不同权限的数据库用户（当前 user 为 0）；每个业务数据库下面也有各自的 users，针对特定数据库设置用户密码及权限。

这节课先创建整个系统的大 boss 级别用户：在 admin 中创建一个拥有最高权限的用户，可以管理所有数据库操作以及创建删除用户。

## 创建 root 用户

保证 Mongo 服务开启，进入 Mongo CLI，`show dbs` 后 `use admin`，然后使用 `db.createUser`：

```js
use admin
db.createUser({
  user: "root",
  pwd: "123456",
  roles: [{ role: "root", db: "admin" }]
})
```

几个字段：user 是用户名，pwd 是密码，最后有一个特殊字段 roles，是个数组，可以添加一系列不同的角色。roles 这个概念很亲切：之前学过 RBAC 这种基于角色的权限验证系统，MongoDB 采用的也是同样的基于角色的权限管理，内置了很多 roles。查文档里的 built-in roles，可以看到 read（只读）、readWrite 等，不同的角色对应一系列不同的操作。其中最高级别的权限叫 root，几乎拥有最高权限。把 root 放进 roles，回车后显示成功添加用户。

可以用 `db.auth("root", "123456")` 验证，返回 1 说明用户创建成功并可以运作了。

## 开启身份验证

建好 root 用户后要重启 Mongo 服务，添加一个开启身份验证的参数。先把当前的 Mongo 进程 kill 掉（`kill -9 <pid>`），然后重启。这个参数可以加到配置文件里，也可以直接加到命令行：

```bash
mongod --auth
```

`--auth` 开启整个数据库的权限验证。启动成功后，连接任何数据库都要带用户名密码了：

```bash
mongo -u root -p 123456 --authenticationDatabase admin
```

`-u` 是用户名，`-p` 是密码，还有一个特殊参数 `--authenticationDatabase`，指定进行验证的数据库，这里选 admin，它里面保存的是系统级别用户的信息。进入后 `show dbs` 能拿到所有数据库的信息，说明这个用户有最高权限。

## 客户端验证

再用客户端软件验证一次。直接连 27017 点 Connect 会报错，因为没有提供任何权限。点 Edit 切换到第二个选项卡，勾选验证，database 填 admin，用户名 root，密码 123456，保存后再 Connect，就能拿到数据了。在 OpsFlow 库里搜索 collection，数据也能取到，最高权限用户创建完毕。

这节课初步了解了 Mongo 的权限管理。MongoDB 是多数据库系统，还可以基于每个数据库设定对应用户，这也是 best practice：给每个数据库一个对应的用户及权限信息，细分后更容易维护。下节课深入一点，设置数据库级别的用户。
