# 17-5-4-将全局读取和错误添加至根组件

前面几节已经拿到了三个状态：全局 loading、细颗粒 loading、是否出错。但要用这些通用状态时，还得在不同路由里重复引用 store 的变量做标记。能不能一劳永逸地把通用状态加到页面上？

答案是肯定的：用整个项目的根组件 App.vue。所有路由组件都渲染在根组件包裹的 RouterView 里，在这里添加，其他组件自然就能显示这些状态。

## 在 App.vue 中添加

App.vue 很简单：一个 AppContainer 包裹一个 RouterView。逻辑自然加在 setup 中，拿 store，取 isLoading 和 error，watch error 弹出提示（把之前的代码搬过来即可），最后把 isLoading 返回。模板里在 AppContainer 中加 ASpin，v-if 条件是 isLoading，并用 tip 属性显示提示文字。

保存后把登录页和首页原来的 loading 效果删掉刷新验证：`读取中` 已经出现，但位置很怪。简单改下样式，添加 class 为 globalSpinner，style 里写 `.app-container .global-spinner`，position 为 fixed，top 是 px 值、right 百分之五十，现在图标居中显示了。

## 用路由元信息做开关

还要给用户充分的选择权：某个路由可能不想显示全局读取或错误效果。方案是路由元信息，路由 object 上有个特殊属性 meta，可以存放任意信息。比如登录页不想显示全局读取，就给它的路由配置加 `meta: { disableLoading: true }`。

回到 App.vue 使用这个标记。引入 useRoute 拿到 route 对象，route 上能取到 meta。创建 computed 的 showLoading，两个条件同时满足才显示：isLoading 为 true，且 `route.meta.disableLoading` 不为 true。模板里用 showLoading 替换 isLoading。想让某个路由不显示网络错误提示，做法完全一样。

## 顺手修一个拦截器的 bug

验证效果。首页的读取效果正常；故意把 URL 改错（TemplateStore 里的地址改成 Templates2），404 Not Found 错误提示如期出现。

这里顺便修一个小 bug：之前在 main.ts 加的拦截器，在真正出错（服务器错误）的分支里没有调用 finishLoading。不清空的话：断网刷新，弹出"服务器错误"，但 loading 状态永远不会清空，还会报一大堆错误。

修复方法是给 rejected 回调里也补上 finishLoading，这需要从错误对象上拿到 opName。axios 对应的错误类型是 AxiosError，它有 config 属性，把参数 e 的类型断言成 AxiosError，然后 `const newConfig = e.config as ICustomAxiosConfig`，取 `newConfig.opName`，处理方式和正常分支一模一样。改完刷新，服务器错误出现后两个 loading 状态都被清空，恢复正常。

## 最终验证

最后确认登录页不出现全局读取：进入登录页点击获取验证码，全局 loading 没有出现；点击登录，"验证码不正确"的错误提示弹出，全局错误也已生效。

这节一劳永逸地完成了通用读取和错误处理的添加，整个应用不需要任何额外逻辑就能享受这些红利。
