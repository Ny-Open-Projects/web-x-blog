# 5-3-使用 OpsFlow CLI 创建项目

上节课介绍了脚手架诞生的原因：它可以快速完成复杂项目前端工具链的整合。了解了这个前提，这节课就可以用为本次项目自研的 OpsFlow CLI 来创建 B 端项目了。之前讲 Vue3 基础知识时没有特别展开脚手架创建项目的过程，大家可以自行选择喜欢的脚手架，重心放在知识点上。现在到了里程碑，要正式开始 B 端项目，我还是完整演示一遍创建过程，并讲解默认生成的代码。

OpsFlow CLI 和 Vue CLI 这类脚手架有一个很大的不同。Vue CLI、Create React App、Angular CLI 都是针对某个特定前端框架的脚手架，而我们走的是大而全、更针对业务的路线。它有一系列特性：首先支持各种模板，通过模板插件机制极大丰富可支持的项目类型；其次内置很多与部署运维相关的功能，比如云构建、预发布和正式发布、项目回滚，甚至还有远程 Git 操作、Git Flow 等。和上节课那几种绑定框架的脚手架相比，它走的是另一条路线和维度。

下面实际感受一下。相信大家都已经安装过脚手架，没有安装的请运行安装命令。先看版本，输入 `npm i -g` 之后执行 version 查看，我的版本是 1.1.2，大家使用时版本可能更新一些，因为这个工具会持续迭代。另外它有一个依赖是 cnpm，用来避免国内直接用 npm 太慢的问题，没装过的也请装一下。

接着创建一个文件夹作为 B 端项目的根目录，就叫 OpsFlow，进入文件夹后运行 init 命令。这时它会让你选择初始化的类型，我们选择项目；名称输入 OpsFlow，版本号用默认的；然后进入标准模板的选择。这里就能看出脚手架的可扩展性：只要自己提供模板，它可以支持任何类型的前端框架。选第一个模板后它开始一系列工作，先是下载模板，下载完毕开始安装依赖，这一步时间稍长。依赖安装成功后会弹出信息，并自动执行启动命令，等于一步到位。启动成功后访问 localhost 的 8080，刷新就能看到我们支持的特性：开箱即用、支持 TypeScript、采用 Vue3、支持 TSX、内置 ESLint，而且简单易用、可扩展。

再来看项目默认结构。如果观察过 Vue3 基础项目的结构，应该不会陌生。与项目有关的源代码都放在 src 文件夹下，main.ts 是整个项目的入口文件：它用 createApp 函数传入根组件 App，然后挂在 id 为 app 的 DOM 节点上。这个节点在 public 下的 index.html 里，其实真正的入口在这里，最终要生成的静态页面也是这个 HTML。App.vue 是入口组件，非常简单，就不展开了。

要特别注意的是 shims-vue.d.ts 这个文件。之前在 TS 环节讲过，.d.ts 文件是定义文件。它处理的情况是：Vue 的 SFC 单文件组件以 .vue 结尾，TS 并不知道有这么一个后缀名的文件，如果没有这个定义，导入 .vue 文件肯定会报错；有了它，在其他页面直接导入 .vue 类型的文件就不会报错，还能获得对应的类型。src 里没有其他需要特别关注的文件了。

最外层则由一系列配置文件组成，因为我们的工具链用了 TypeScript、ESLint 和 Babel：tsconfig.json 是 TypeScript 的配置，.eslintrc.js 是 ESLint 的配置，babel.config.js 是 Babel 的配置，它们都可以自定义。后面会针对每个工具深入了解。

演示一下 ESLint 的效果。写一行 `let a = 1`，上面立刻出现两个错误：一个是 a is assigned a value but never used（声明后没有使用），另一个是 a is never reassigned, use const instead（提示改用 const）。这说明 ESLint 的规则已经生效。

最后演示项目对 TSX 的支持。新建一个 hello.tsx，把代码复制进来。这个文件不仅使用了 JSX 语法，还用了 Vue3 函数式组件的写法，React 开发者看到会非常亲切。接着把它导入到 App.vue 里：import Hello from './components/Hello'，注册后在模板里使用 `<hello message="hello world"/>`。保存后页面上立刻出现 hello world，说明 TSX 组件运行成功。

这节课我们用 OpsFlow CLI 成功创建了项目，讲解了项目的大体结构和支持的一系列功能。这节课到这里，谢谢大家。
