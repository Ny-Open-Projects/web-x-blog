# 7-8-配置测试开发环境

上一章我们讲述了通用测试框架 Jest 的几种用法。这一章进入 Vue 的专属测试工具：Vue Test Utils。想测试特定界面，光用 Jest 明显不够，还需要 Vue 特定的工具来实现：把组件挂载到测试用例中，用特定的方法触发组件的特定行为，然后测试界面是否发生了对应的变化。

这个工具就是 Vue Test Utils，Vue 的官方测试工具。特别注意，在 Vue 3 推出以后，Vue Test Utils 也推出了适配 Vue 3 的新版本，即 2.0 版本，目前最新版本是 2.0.0-beta.12，所以我们要采用新的版本。文档里写得很好：这个工具提供了一系列方法，可以在隔离的环境下进行组件的挂载以及一系列的交互。

现在来安装这个工具以及相关配置。由于项目一开始并没有安装关于测试的内容，如果手动安装，可预见的工作有很多：Jest 的安装、Jest 运行时遇到 Vue 文件需要转换的配置、Vue Test Utils 的安装和配置，甚至还有 types 文件的安装。非常繁琐，不搞一下午是不可能的。看到这里我就想起刚开始接触 Webpack 时被各种 Loader 支配的恐惧。

这个问题怎么解决呢？我们的项目搭建在 Vue CLI 上，这里就要提一下 Vue CLI 的架构：一套基于插件的架构。查阅项目的 package.json 可以看到，下面有一系列以 @vue/cli-plugin 为前缀的内容，这些就是插件。插件能做三件事：第一，安装对应功能的依赖，它会自动收集需要哪些依赖并一次性安装；第二，修改内部配置，比如需要什么特定的配置文件或选项，它都可以直接修改；第三，有可能向 vue-cli-service 注入命令。可以看到我们项目里就注入了一些命令，都是通过插件完成的。创建项目过程中的绝大多数特性都是通过插件实现的，基于插件的架构让 Vue CLI 灵活且可扩展。

已经创建好的项目想添加新插件要运行什么命令呢？运行 `vue add` 加上插件名称。添加测试的话，官方有写好的插件。带 Jest 的叫 @vue/cli-plugin-unit-jest。它应该还有以其他测试工具为主框架的插件，没错，还有 unit-mocha，以 Mocha 作为主测试工具。从下载数量看，一个四万七千多，另一个二十七万多，差别很大，大多数人都选了 Jest 作为主框架，也印证了 Jest 更流行的说法。

现在运行 `vue add unit-jest`。我这里已经运行完毕，大家运行后回车，稍等一会儿，它就会完成整个安装工作。安装完毕后，探究一下插件的工作过程。先看 package.json：它安装了什么呢？dependencies 里可以看到，安装了 vue-cli-plugin-unit-jest（就是我们安装的插件）、vue-jest（一个转换器），还有 Vue Test Utils（肯定要装的官方工具）。大体装了这三样东西，并且注入了一个新命令：test:unit，它运行的是 vue-cli-service test:unit。

从这条命令入手，看它究竟是干什么的。文档写得很清楚：vue-cli-service test:unit，run unit test with jest，其实就是运行 Jest 命令，并且明确了两个路径，这两个路径下的测试文件会被运行。一个是 tests/unit 文件夹下、以 .spec 结尾的系列文件；或者任何 __tests__ 文件夹下的文件。这两种路径的文件会被当做测试用例运行。

但我们引入的文件中很可能有 Vue 格式的文件，比如 import 一个组件进来，Jest 是没法识别的，所以需要完成对应的转换。怎么完成的呢？打开 jest.config.js，这也是插件安装时添加修改的一部分。它是 Jest 的配置文件，有两个字段。第一个叫 preset，看到这个词可以联想到 ESLint 的配置，它是一系列已定义好规则的合集。第二个是 transform，顾名思义是一个转换过程：当跑特定 case 时遇到以 .vue 结尾的文件（这里是一个正则），就会用特定的插件进行转换。什么插件呢？可以看到这里出现了 vue-jest，就是刚安装的转换器。

再看 vue-jest 是干什么的：它的功能就是把 Vue 的 single file components 转换成对应的 TS 或 JS 文件。转换完以后我们得到的是 TS 文件，而 Jest 只能运行 JS 文件，所以再看上一步 preset 里有什么。找到 preset.js，不看 deep merge 那些杂项，我们找到了熟悉的字段 transform：当它遇到 ts 或 tsx 文件时，就使用 ts-jest 进行转换。这样，Vue 文件先转成 TS，再转成 JS，整个转换过程就完成了。

有了 JS 文件，就可以使用 Jest 进行测试，整个测试也就这样进行下去了。这节课的任务完成了：我们简介了 Vue Test Utils，配置了测试环境，讲了 Vue CLI 的插件化系统，以及安装插件后运行命令的整个运行机制：怎样把 Vue 文件转换并完成测试。知道了这些以后，下节课就可以用这套测试环境来运行测试用例了。这节课就到这里，谢谢大家，再见。
