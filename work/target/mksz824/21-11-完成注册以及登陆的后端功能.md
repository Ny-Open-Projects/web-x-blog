## 注册接口 signup.post.ts

先安装加密用的模块：`bcrypt`，它还要单独安装类型定义 `@types/bcrypt`，两个都要装。

来到 `signup.post.ts`。首先拿 `userSignUpSchema` 做验证，现在用之前封装好的 `runValidate` 就很方便。其实用 login 的验证也可以，因为后端只关心 email 和 password，confirmPwd 对后端没用，就看前端发送时传不传；这里还是用 signup schema。快速完成前后端通用的验证：

```ts
const result = await runValidate(userSignUpSchema, event)
```

bcrypt 有个配置选项 `saltRounds`，即加盐加密多少轮。它是配置项，自然要加到 config 里：在 runtime config 里加一项 `decrypt.saltRounds`，设置为 10，这也是比较默认的值。

通过 `useRuntimeConfig` 拿到 config，然后从 `result.data` 取两块数据：email 和 password。注册第一步要看用户是否已注册：email 是唯一值，可以直接用它查找。在 models 文件里的 user schema 上调用 `findOne`，查 username 为该 email 的一条记录，并链式调用 `.lean()` 返回普通 object，数据更轻量。

接着是第一个分支：如果查到了，说明用户已存在，抛出错误提示换一个用户名：

```ts
if (user) {
  throw createError({
    statusCode: 409,
    statusMessage: '邮箱已经被注册，请直接登录'
  })
}
```

statusCode 精心选了 409，它是 conflict 的含义，代表数据冲突（已注册）。

如果不存在就可以创建了。创建前先加密密码，用 bcrypt 的 `hash` 方法：加密 password，传入 config 里的 saltRounds（10 轮）。然后组装创建数据：

```ts
const newUserData = {
  username: email,
  password: hashedPassword,
  email
}
const newUser = await UserSchema.create(newUserData)
return newUser
```

注册需要 username、password、email 三个值，其他暂时不需要。到此后端就写完了，逻辑和之前几乎完全一样，只是换用了 Nuxt 3 特有的 API（如 createError），看一遍就清楚。

## 前端交互提示

后端完成后补上交互。现在有表单错误，还需要一个提示框告诉用户注册是否成功，因为接口可能抛错，要把错误显示到界面。创建一个 `callbackMessage` 的 ref，上面保存三个状态的值：

```ts
const callbackMessage = ref({
  isShow: false,
  isValid: false,
  message: ''
})
```

isShow 是提示框是否出现，初始 false；isValid 表示是否成功，false 代表请求出错；message 是提示的具体信息。

注册提交加 try catch（e 是 unknown，手动设为 any 类型），用 `$fetch` 发请求到 signup 接口，body 直接传 values（包含 email、password、confirm password），method 为 post。成功时修改 callbackMessage：isShow 设为 true，isValid 为 true，message 填返回的值。catch 里说明出错了，同样修改：isValid 为 false，message 从 `e.data` 上拿返回的 statusMessage。最后加一个 setTimeout，两秒后跳转到登录页面。

界面加一个显示错误的 div：`v-if="callbackMessage.isShow"` 时出现，上面加一些 Tailwind 样式类，内容显示 callbackMessage.message。成功和失败的样式要区分：失败时浅红底色、红色 border、红色文字，通过时全换成绿色，用 `callbackMessage.isValid` 做动态 class 区分。

## 登录接口的验证逻辑

注册流程完成后看 login 的后端逻辑。login 前端代码和注册高度相似，留给各位当作业。后端首先把 decrypt 配置拿过来用。登录有两种特殊情况：

第一种是 user 不存在。和之前一样先查询，user 不存在就 `throw createError`，404，说明用户不存在或密码错误。

第二种是比较密码。需要 bcrypt 提供的 `compare` 方法：

```ts
const verifyPwd = await bcrypt.compare(password, user.password)
if (!verifyPwd) {
  throw createError({
    statusCode: 404,
    statusMessage: '用户不存在或密码错误'
  })
}
```

比较用户传入的 password 和数据库里存的加密密码 user.password。没通过就抛错。注意这里不给用户非常明确的提示，而是写得模糊：用户不存在和密码错误用同一句话。这样用户就不知道具体是哪种错误，可以防止黑客或别有用心的人探测出"密码错误还是用户不存在"，缩小甄别范围。

两种情况都不存在就完全通过，说明登录成功，接下来可以把这些信息持久化到缓存。这部分先不写，下节课完成登录的整个流程，本节课只要完成验证即可。
