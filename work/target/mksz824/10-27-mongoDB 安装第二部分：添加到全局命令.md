# 10-27-mongoDB 安装第二部分：添加到全局命令

上节课我们完成了 MongoDB 的安装和运行，但运行起来有一个非常繁琐的点：每次都要进入特定的文件夹，敲这么长的一串路径，再用 ./ 这种形式运行。我们希望有一个像其他工具一样的全局命令，不需要进入路径，直接键入 mongod 就能执行对应的二进制文件。这是一个非常常见的需求，不仅仅限于这个场景。

要完成这个任务，首先要了解 Linux 系统中一个特殊的环境变量：$PATH。这个环境变量很神奇，可以把它打印出来看一下：使用 echo 加 $PATH，会输出一系列路径，中间用一个奇怪的符号连接，也就是冒号。这一系列路径使用冒号分割，形成很多个路径。只要这些路径中任何一个包含一个可执行的二进制文件，运行的时候就不需要进入前面的路径，直接输入二进制文件名就可以执行。听起来比较拗口，拿其中一个路径做例子：进入这个路径，ls 看看里面的内容，大家应该恍然大悟，因为这些命令我们都很亲切：tsc、vue-cli、npm、npx 等等，都是通过 npm -g 全局安装的一系列模块。正是因为这些命令对应的文件夹被添加到了 PATH 当中，所以运行它们的时候可以直接运行。

现在要想把 mongodb（也就是我们对应的文件夹）添加到 PATH 当中，应该就可以完成任务了。方法很简单：修改 $PATH。Linux 提供了一个叫 export 的命令，可以修改当前的环境变量。

首先要对 mongodb 做一个重命名。回到之前的文件夹，它现在的路径太长了，不利于输入。我把它重命名为 mongodb，使用 mv 就好。特别注意有权限的问题，这里需要 sudo 让它自己完成任务。然后运行对应的命令：`export PATH=...`，简单解释一下 export：PATH 是环境变量的名称，等号是赋一个新的值。赋什么？先看后面，$PATH 是它旧的值，前面加上我们的路径，等于把这个路径添加到旧值的前面，形成新的 PATH。回车完毕以后再看一下 PATH：可以看到我们的路径已经添加到最前面了。

现在再运行 mongodb 的命令：可以看到它已经变绿了，说明可以运行了。运行一下是否能够运行：没问题，它已经运行起来了。

但是用 export 语法直接在 shell 当中运行有一个问题：它是一锤子买卖，是临时的，会话关闭以后就失效了。可以新建一个 terminal 验证，输入 mongod 还是找不到。所以需要另外一个配置：把这句命令写到用户文件夹的终端配置中。在 Mac 当中，先到你的用户文件夹，一般是 Users/你的名称，可以使用 `cd ~` 直接到这个文件夹下。这个文件称之为 .bash_profile，编辑它，把刚才的 export 放进去，把前面的空格去掉，然后保存。这个文件在任何 terminal 窗口被新建的时候都会被运行。

如果和我一样使用了 zsh 的 shell（Mac 原始的是 bash），还会有一个配置文件叫 .zshrc，看名称也知道它是一个配置文件，把刚才这句写到对应的配置文件当中。因为我是 zsh，所以两个都要写入。写入完毕以后，要使用 source 命令运行一下：source 可以把配置文件的一系列配置写入到当前的 shell 当中。运行 `source .bash_profile`（假如你使用 bash），像我一样使用 zsh 的，就再 source 一下 zsh 的配置文件。两个都写入以后，打开一个新的窗口，输入 mongod，你会发现全局变量就永久地存在了。运行一下，肯定没有问题，非常方便。

现在我们就可以非常舒服地全局运行一系列的二进制命令了。特别注意：这个技巧对非常多的软件都是同一个意思，请大家举一反三，一定要记住。
