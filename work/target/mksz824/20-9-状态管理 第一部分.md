# 20-9-状态管理 第一部分

这节课进入新话题：状态管理（State Management）。前面的课程里我们大量用过 Vuex 这类状态管理工具，Nuxt 这边有所不同，它直接提供了一个写好的组合式函数来完成这件事，就是 `useState`。

## useState 的基本特性

`useState` 用起来很简单，而且完全 SSR 友好，服务器端一样能用。它会在服务器端渲染完毕后，经过注水（hydration）过程生成完全响应式的对象。服务器端初次渲染时，数据是通过序列化成 JSON 传递的，所以 state 里不能存放无法 JSON 化的数据，比如 class 实例、函数、symbols 这些。

## 一个登录状态的例子

我们用一个现实的例子来演示：保存一个用户对象，展示用户是否登录、用户信息等。计划是在 login 页面点一个按钮完成"登录"（伪代码，只为演示概念），然后根据用户状态显示或隐藏页面上的信息。用户状态显然是整个应用的全局状态。

`useState` 应该在哪里初始化？入口文件 `app.vue`。目前它还没有 script 部分，先补上，然后创建 user 状态：

```ts
const user = useState('currentUser', () => ({
  isLogin: false
}))
```

`useState` 有两个参数：第一个是 state 的名称，必须保证唯一，这里叫 `currentUser`；第二个是一个回调函数（init），用来初始化值。回调里返回一个 object，所以要额外用圆括号包裹。初始值里放一个 `isLogin: false`。

为了让状态里能装更多信息，比如用户名，我们发挥 TS 的功力补充类型。目前 user 只有 `isLogin` 字段，而 `useState` 是支持泛型的。先定义接口，命名为 `UserProps`：除了布尔类型的 `isLogin`，再加一个可选的 `username?: string`（未登录时没有这个属性）。然后把这个 `UserProps` 作为泛型传给 `useState` 即可。

## 根据状态渲染

类型写好后，回到模板做点文章：已经登录就不再显示 login 链接，用 `v-if="!user.isLogin"` 控制；header 里还想显示用户名，加一个 `li`，条件同样是 `user.isLogin` 为真时展示 `user.username`。

## 登录逻辑

下一步添加登录流程。页面底部创建一个 button，文案写 login，绑定 click 事件。点击时要修改状态，直接用 `useState` 获取即可：读取已初始化的 state 不需要传第二个参数，只传 key `currentUser`。

拿到 `currentUser` 后会发现它的类型是 unknown，因为我们这里没传泛型，又得重复用 `UserProps`。更好的做法是把它提取出去供所有地方复用：新建一个 `types` 文件夹，创建 `user.ts`，把 `UserProps` 接口移过去并加上 `export`。然后在用到的地方 `import type { UserProps } from '~/types/user'`。注意 `app.vue` 和 `types` 是同级目录，导入路径不要多写一层。

回到登录回调，把状态改为已登录：

```ts
currentUser.value.isLogin = true
currentUser.value.username = 'Viking'
navigateTo('/')
```

刷新页面验证整个流程：初始时 login 链接可见（未登录），点击按钮后跳转到首页，login 消失，用户名 Viking 显示出来。

## 在中间件里使用全局状态

上节课写的 `auth.ts` 中间件里有一个假的判断函数，现在可以用真正的全局状态替换它。同样导入 `UserProps` 类型，然后获取状态并传入泛型：

```ts
const currentUser = useState<UserProps>('currentUser')
if (!currentUser.value.isLogin) {
  return navigateTo('/login')
}
```

判断未登录时跳转到 login 页，这里直接用叹号取反即可。

刷新验证：点击 user 1，因为未登录会跳到 login 页；点击按钮完成登录后再点 user 1，就能正常进入了。这说明 state 在全局生效，不同的组合式函数、不同的组件里都能拿到同一个值。
