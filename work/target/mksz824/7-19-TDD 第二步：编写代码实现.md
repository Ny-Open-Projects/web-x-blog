# 7-19-TDD 第二步：编写代码实现

上节课完成了 TDD 开发的前两步：根据需求写了测试用例，目前全部失败。有了测试用例的指导，写代码的思路也很清楚了，顺着这几个用例完成即可。

首先给组件添加属性。写好 props：第一个是最熟悉的 value，必须有，类型是 string；第二个是 colors，用来渲染右侧的颜色列表。测试里我们用的是 defaultColors，所以给 colors 一个默认值，类型是 string 数组，default 设为 defaultColors。属性就确定了。

有了属性就可以实现第一个 case 的内容。先给它标上 only，让别的用例不要干扰，保存后开始创建结构，最重要的就是写出左右两栏的结构。先创建一个 div，加一个 class 叫 native-color-container，里面放一个 input，type 为 color，value 绑定传入的值，左侧就写完了。

右侧是一个 ul 列表，li 根据传入的 colors 循环生成。创建 ul，class 是 picked-color-list，里面用 li 写 v-for，值叫 item，索引叫 key，遍历 colors。给每个 li 添加一个独特的 class 指代它是第几项：用模板字符串 `item-${key}`。然后 li 里面再放一个 div，这是真正渲染色块的地方，给它设置 style 的 backgroundColor 为 item，再加一个 class 叫 color-item 作为区分。

这里有一点逻辑上的区别：最后一项，或者说不是以井号开头的颜色值，要渲染一个 transparent-background。所以加一个 v-if，简单用 startsWith 判断即可，你也可以用更精确的方法判断它是不是合法的十六进制颜色。另一个分支用 v-else，里面没有 background，只有 color-item，再加一个 transparent-background 的 class。整个界面就写完了。

跑一下测试看看。前面几条都通过了，失败出现在第三十行：background 的期望值是井号 fff，实际拿到的是 rgb(255, 255, 255)。原因是从 style 中取出的颜色属性会被浏览器自动转换成 rgb 格式，而不是原来的十六进制格式，所以需要做一次格式转换。找一个开源库，叫 rgb-hex，功能就是把 rgb 格式转换成十六进制格式。我已经安装好了，直接导入使用：`import rgbHex from 'rgb-hex'`，在测试用例里对出错的地方包一层：`expect(element.style.backgroundColor).toBe('#' + rgbHex(defaultColors[0]))`。注意 rgbHex 的输出不带井号，要手动补一个。改完之后，熟悉的绿色勾又出现了，pass，完美。

现在做事件部分，第一个是在 input type color 上发送 change 事件。给第二个用例加上 only。在 setup 中拿到 props 和 context 两个参数，并且声明 emits，要发送的是 change 事件，这是表单组件千年不变的定律。创建一个函数 onChangeColor，参数是 color: string，内部调用 `context.emit('change', color)`，最后把 onChangeColor 返回出去。

接下来要在 input 上触发这个事件。文档中有明确的指导：监听颜色变化部分。这个 input 类型虽然特殊，但颜色改变有两个事件：input 事件在每次颜色变更时都会触发；change 事件只在用户关闭选择器之后触发。这里我们选择 input 事件：`@input="onChangeColor($event.target.value)"`，用 $event 拿到原始对象，取 target 的 value 作为参数。跑一下，第二个用例通过了。

删掉 only 标记，写最后一个用例：点击右侧颜色列表后是否发送对应的值。这个太简单了。点击位置在 li 上，click 加一个 prevent，调用的还是 onChangeColor，值是循环时拿到的 item。跑一下最终结果，所有测试全部通过，ColorPicker 组件就开发到这里。

大家注意，整个过程我们甚至都没有打开页面看这个组件到底长什么样。这就是 TDD 的魅力，也是测试的魅力：不需要手动操作就能确认组件是否完美工作。当然组件可能还存在样式问题，没打开页面就不知道样式具体如何，但功能上肯定没问题。下节课把它和整个应用整合，看看实际效果。这节课到这里，谢谢大家，再见。
