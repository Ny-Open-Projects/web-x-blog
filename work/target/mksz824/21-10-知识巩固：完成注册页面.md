## 定义 sign up 的 schema

一开始当然是定义和 sign up 相关的一系列规则。这里有个非常有趣的点，等会儿会遇到。先把 login 的 schema 复制过来改名，叫 `UserSignUpSchema`。

sign up 的字段和 login 非常类似，也有 email 和 password，但注册一般会有一个重复密码的字段：希望用户把密码填两遍，避免填错或不记得。添加一项 `confirmPwd`（重复密码），规则和 password 完全一样。

特别注意，这里有一项自定义规则：我们希望 password 和 confirmPwd 完全相同，不相同就抛出错误。这个任务用 Zod 提供的 `refine` 方法完成，它可以通过 refinements 提供自定义验证逻辑，这里只是拿重复密码做个例子。

在 z.object 后面直接链式调用 `refine`。第一个参数是回调函数，data 就是 schema 定义的类型，有了类型和数据就可以在上面处理：判断 `data.password` 和 `data.confirmPwd` 完全一致，验证才通过。第二个参数是一个 object，可以添加更多信息：`message` 选项告诉用户错误信息，写 passwords don't match；`path` 可以精确控制错误添加到哪里，是加到 password 还是 confirmPwd 上，这里应该是 confirmPwd：

```ts
export const userSignUpSchema = z
  .object({
    email: z.string().email(),
    password: z.string().min(6),
    confirmPwd: z.string().min(6)
  })
  .refine((data) => data.password === data.confirmPwd, {
    message: "passwords don't match",
    path: ['confirmPwd']
  })
```

这就是这节课要学的新知识：用 refine 自定义添加验证规则。大家可以写任何自定义逻辑，也可以线下对 refine 多做练习。然后把 type 也导出去，叫 `UserSignUpType`，用 `z.infer` 传进去。
