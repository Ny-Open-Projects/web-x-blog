# 11-7-mongoDB 整体结果的处理

上节课用内置操作符筛选数据，这节课学对结果做整体操作：拿前几条、排序、选取特定属性等。MongoDB 提供了一些常用方法。

先看 find 方法的定义：它有两个参数。第一个是上节课学的 filter，用来过滤数据；第二个叫 options，是一个特殊的 FindOptions 类型，用来对返回结果设置特定选项，完成特定任务。

第一个学 limit，顾名思义确定返回结果的个数。比如只想返回两条：创建一个 options 对象并标注成 FindOptions 类型（这样编辑器能提示有哪些参数），里面写 limit: 2，把它作为 find 的第二个参数传入，特别注意是第二个参数。运行 ts-node index.ts，resultArray 只返回两条，limit 生效了。

第二个学的和 limit 相对，叫 skip，跳过指定个数的结果。希望跳过最前面两条：写 skip: 2。原来数据的前两条是 Viking 和 Lucy，保存运行后返回的是小宝和东东，说明跳过了前两条，直接到第三条和第四条。这里大家应该发现了：limit 和 skip 结合可以完成分页。一页两条数据的话，第一页 skip 等于 0，第二页 skip 等于 2，第三页 skip 等于 4，以此类推。MongoDB 的分页实现，恰好就是通过 limit 和 skip 的结合使用来做的。

第三个选项是 sort，用来排序。通过 sort 指定排序字段，用 1 和 -1 两个值：1 是升序，-1 是降序。把前面的注释掉，加 sort，用 age 字段，age 指定为 1。运行后结果从最小的 5 排到最大的 40，是升序。改成 -1 再运行，顺序反过来，40 在上、5 在下，排序成功。非常简单：选一个字段，用 1 或 -1 排序。

第四个叫 projection，投影的意思。用它规定最后的数据需要哪些字段返回，用 0 和 1 表示，实际工作中很有意义，比如密码字段不希望返回给用户，就不让它显示。我们先隐藏 _id：projection 里写 _id: 0，保存运行后 _id 都消失了，剩下其他字段。再测等于 1 的情况：只展示 name，写 name: 1。运行后结果里有 _id 和 name，说明只包含了 name。但注意我们没写 _id，为什么它还在？因为 _id 是个非常特殊的值：只要你不显式排除它（不写 _id: 0），它默认会包含在所有 query 结果中。这就是 projection 的用法。

除了在 find 的第二个参数里写 options，这些选项还都支持在 find 上链式调用。比如直接在 find 后面 .sort()、.project()、.limit()、.skip()，都能用链式写法完成同样的处理，大家可以试试，选自己喜欢的写法。

这节课在筛选的基础上讲了整体结果的处理，就是通过 options，也就是 find 的第二个参数完成的。这些属性大家可以再温习一遍。
