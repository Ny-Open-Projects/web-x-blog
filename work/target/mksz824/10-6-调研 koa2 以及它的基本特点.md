# 10-6-调研 koa2 以及它的基本特点

上节课简介了 Express 的中间件模型。现在来说技术选型考虑的第二个 Web 框架：Koa2。Koa2 是一个轻量级的 Node.js Web 框架，由原来的 Express 团队成员打造。在 Express 的基础上，他们采取了一种全新的思路，提供了一套优雅的方案，帮助我们可以快速而愉快地编写服务器端应用。

先看它和 Express 的几大区别，也就是它的创新之处。第一个是最最重要的区别：使用了 Promise，也就是 async/await 这样的语法，代替了 Express 当中 callback 回调函数的写法。特别注意，因为要使用 async/await 语法，Node 版本要大于 7.6。当然现在大家的版本一般都在 7.6 以上。

第二个特点：它使用了一个 ctx 上下文对象。还记得 Express 每个回调中有两个对象，封装了 Node 的 request 对象和 response 对象吗？现在 ctx 把 request 和 response 都封装在内，还提供了一些更多常用的功能。

第三个是重中之重：完全不同的中间件机制，和 Express 是完全不一样的思路，这个下节课再说。上节课说的 Express 中间件的那个小瑕疵，我认为在 Koa2 的中间件机制下可以得到完美的解决。

第四个是更轻量级，没有捆绑任何中间件。它只有一个核心，路由、body parser 等等什么都没有。官方有一篇文章讲解 Koa2 和 Express 的区别，提出了几个问题并很好地回答了它们，建议课下自己看一下。

现在直接用一个例子看它的基本语法。由于我们后面采用的 Egg.js 基于 Koa2，这里只是简单过一下语法，验证它和 Express 的这几个区别，不会展开，后面的内容到了 Egg.js 都会涉猎。

把官方 Hello World 的例子拿过来，发现它只有一个依赖，就是 koa 核心，安装的是 2.13.3 版本。它是一个构造函数，可以 new 出一个实例。app 就是应用程序的实例，是一个包含一组中间件函数的对象，在一个应用中是唯一的。应用对象中还有一些其他的属性，可以完成整个应用的一系列配置，这里不详细说。

和 Express 一样，可以使用 use 来添加中间件。注意 use 当中的 function 可以使用 async，这就引出了它的第一个特点：任何中间件都是 async function，支持 Promise 的写法。

第三个特点，一个 Node.js 框架不管多复杂，要弄懂的就是请求和响应两部分内容。Koa2 中每次请求的所有内容都绑定在刚才说的 context 对象上，包括请求、响应以及一些框架常用的功能。简单演示一下：要拿到 headers，`ctx.request` 就是所有的请求，`ctx.response` 就是所有的响应。要拿 headers 就写 `ctx.request.headers`，这样拿到了所有的请求 headers，然后返回。返回时可以直接使用 ctx.body。

这里要特别注意：它添加了一些别名供我们快速访问。比如 `ctx.request.query` 是拿 URL 上的 query，它和 `ctx.query` 完全等价，等于添加了一个 alias，不用打那么多字符了。同样，ctx.body 其实是 response 上的一项，等价于 `ctx.response.body`，不需要打中间那个属性就可以直接返回。保存一下，看是否能返回对应的 headers：现在 headers 就出现了。

除了 request 和 response，它还封装了一些常用的方法。比如 `ctx.throw` 可以直接抛出一个错误：写 `ctx.throw(404)`，刷新几下就能看到直接返回了 error，返回值是 404。这个 404 就是刚才通过 throw 抛出的错误，下面的代码不会再继续执行了。
