# 10-16-Middleware 中间件第二部分

上节课我们简单了解了 middleware 的运行原理，这节课在中间件上再稍微深入一点。

第一点是让中间件支持配置。一般来说中间件也会有自己的配置，在框架中，一个完整的中间件是包含配置处理的。还记得我们直接导出的那个 function 吗？它其实可以接受两个参数：第一个参数可以称之为 options，这里先给它设置成 any 类型，之后的内容中会让它获得正确的类型；第二个参数是 app，就是 app.ts 中唯一的一个应用实例，类型来自 Application。

获得了这两个参数，options 的配置应该从哪里传入？一想到配置，自然要想到 config.default.ts，它汇总了所有的配置。在配置文件中，对于中间件的配置，可以将和文件同名的配置信息直接传递过来。比如我们这里叫 logger.ts，那么在 config 当中可以设置一个对应的 logger，里面就是它的一系列配置信息。

我们希望实现这样的功能：只有特定的 HTTP verb（请求方法）被调用的时候，比如 post 的时候才添加记录。这里先抛出一个问题：我们不添加任何配置，把 config 里的 logger 删掉，然后在中间件里直接 console.log(options)，按理说这个东西应该是没有的，因为我们没有传递任何信息。但是去测试，访问我们的 URL，会发现直接输出了一堆已经配置好的信息。什么原因？因为在 Egg.js 内部已经有一个内置并且启用的插件，称之为 logger，它有一个默认的配置。这个 logger 是 Egg.js 内置的日志模块，功能很强大，有一系列丰富的配置。

其实配置也可以从这里拿到：`app.config.logger`。再测试一下，输出 default options 为 `app.config.logger`，可以看到输出的 options 和这个 default options 是完全一致的，这就验证了我们的想法。

为了避免冲突，解决方法就是修改文件名，因为 logger 跟内置插件重名了。做一个 rename，把它变成 myLogger，同时特别注意 middleware 配置里也要做对应的修改。修改完毕后就可以添加 myLogger 的配置了。对于业务逻辑的配置，记得要添加到 baseConfig 当中。具体原因是类型断言的原因，后面讲解配置文件的时候会详细说明，这里姑且先添加进去。称之为 myLogger，添加一个参数叫 allowedMethod，意思就是只有在这个 method 情况下面才会添加日志。给它添加 post：只有发送 POST 请求的时候才添加日志，GET 时不添加。

中间件里就可以拿到同名的 myLogger 的 options，加一个对应的判断：`if (options.allowedMethod.includes(ctx.method))`，在条件满足时才进行记录。特别注意这里面没有自动提示，因为它是 any 类型，要靠手把代码打对。保存后测试一下：把 log 文件打开，现在里面有五项。发送 GET 请求，它并没有多添加；发送一个 POST 请求（用之前的 curl 比较快），POST 请求发送成功后，日志从五条变成了六条，说明配置文件已经生效了。这就是在中间件上添加配置的方法。

第二个话题是中间件的使用。现在我们学习的唯一一种使用方法，是在 config.default.ts 当中进行全局配置、全局使用。另外还有第二种方法：假如想在特定的路由上使用也是可以的。做法是来到 router.ts 当中，把这个中间件拿出来。中间件其实在 app 上面，可以从 app.middleware 当中拿到，可以看到 myLogger 已经能输出提示信息。大家都知道这个函数有两个参数：第一个是 options，跟之前一样是个对象，这里也写 allowedMethod，但值添加一个 get；第二个是 app，直接传进来就可以了。这样这个中间件就生成了，它是 function 的返回结果。把这个 logger 只添加到 dog 这个路由上面。特别注意：router.get 的第一个参数是 URL，后面可以添加多个中间件进行串行，如果还有更多的话可以继续以参数的形式添加进去。保存后要再修改一下，把原来的全局中间件删掉，这时候它就只在 router 上起作用。

测试一下：现在日志有六项，我们应该只在特定的 URL 进行 log。先访问 test，发现日志并没有多添加；再访问 dog，日志被多添加了一项，GET 写在这里。因为这次中间件发起了一个 HTTP 请求，所以它的时间要远远高于其他的这些请求。这就是中间件在 router 上面的使用方式。还有一种使用方式是在 app 入口文件进行加载，这种方式会放到后面学习入口文件的时候一并解释。

通过这节课，我们进一步加深了对中间件的印象，内容有两方面：一方面是中间件的配置，配置选项可以在 config.default.ts 中添加跟中间件同名的配置，它会自动把配置读取进来；另一方面是中间件的使用，除了在配置文件中开启，还可以添加到单个路由上面，仅在某个路由上响应。
