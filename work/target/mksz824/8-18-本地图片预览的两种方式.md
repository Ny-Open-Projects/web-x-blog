# 8-18-本地图片预览的两种方式

上节课介绍了 Element Plus Upload 组件的基础架构。我们还有一个没完成的需求：更丰富的列表展示效果。其中有一个效果是上传图片时展示缩略图。如果都等上传完成再展示，对于稍大的图片或响应较慢的请求，会给用户非常不好的感觉，所以要有一个快速预览的方法。这是一个非常有趣的新知识点：现在我们手里有的是一个 File 对象，怎样完成图片的预览？

## 方法一：URL.createObjectURL

第一种方法使用 `URL.createObjectURL`。它是一个静态方法，创建一个 DOMString，返回一个 URL。这个 URL 和 Document 绑定，指示对应的 file 对象。简单理解：将一个 File 类型的对象转换成一个 UTF-16 的字符串，保存在当前操作的 Document 下，以 URL 的形式存在。文档地址在这里，想深入了解可以自己看。

在代码里试一试。我添加了一个 listType，展示两种不同的形式：text 和 picture，picture 带预览功能。另外在 UploadFile 类型中添加了一个新字段 url，String 类型，保存对应的展示 URL。当 listType 为 picture 时把它填上。位置应该在 addFileToList 里判断：`props.listType === 'picture'` 时执行。为了防止转换错误，加一个 try/catch：

```ts
try {
  fileObj.url = URL.createObjectURL(uploadedFile)
} catch (e) {
  console.error('upload file error', e)
}
```

catch 里在传入类型有问题、无法处理时简单打印错误。然后把图片展示到模板中：添加一个 img，v-if 条件是 file.url 存在且 listType 等于 picture，src 就是 file.url。

验证一下。先把后面上传的过程注释掉（addFileToList 里），只看预览效果。选择一张图片，它显示在列表最左边（我简单加了一点样式，可能不太好看）。选择这个元素看看有什么端倪：它的 src 是一个 blob 开头的 URL，指向内存中存放的图片地址。选择 Open in New Tab，这个 URL 对应的就是这张图片。特别注意，它是使用 UTF-16 字符串形式保存的。第一种方法完成。

## 方法二：FileReader

除了 URL.createObjectURL，还有另一个方式作为扩展：FileReader。它是新建实例上的实例方法，有个方法叫 readAsDataURL，传入的参数也是 file，读取指定的 file，读取完成时触发回调，它是基于事件的，返回的不是 URL，而是一个 base64 格式的字符串。文档地址在这里。

用新方式处理一下，把刚才的实现注释掉。它是实例方法，所以要先创建实例 `const fileReader = new FileReader()`，然后调用 `fileReader.readAsDataURL(uploadedFile)`。因为基于事件，要用事件的处理方式：`fileReader.addEventListener`，成功读取的事件叫 load，load 完成后赋值：`fileObj.url = fileReader.result`，这是最终读取出来的结果。这里报了一个类型错误，因为 result 可能是 ArrayBuffer 类型，做一个类型断言 as string。当然还可以再添加一个 error 事件的错误处理，这里只添加一个演示即可。

保存后选择一张图片，也成功预览出了图片。点击元素查看：跟 createObjectURL 相比，可以清晰地看到返回的是一大串 base64 编码。这就是两者最大的区别。

## 对比总结

两种方法都了解后，做个对比总结，供以后选择时参考：

1. 返回值：FileReader 返回一段 base64 字符串；createObjectURL 返回一个指向内存的简单 URL。
2. 执行机制：FileReader 通过回调返回，异步执行，需要 addEventListener 监听 load 事件；createObjectURL 直接返回，同步执行。
3. 内存清理：FileReader 依照 JS 垃圾回收机制自动从内存中清理；createObjectURL 的结果一直存在于当前 document 内，只有 unload 事件或手动调用 revokeObjectURL 才能清除。

再总结一下：URL.createObjectURL 得到的是本地内存容器的 URL 地址，同步使用，方便快捷，性能优秀，多次使用时要注意手动释放内存的问题；FileReader 胜在直接转为 base64 编码，很多时候可以直接用于业务，无需二次转换格式。

通过图片预览这个需求，我们了解了两种在本地快速预览图片的方式。不知道同学们更喜欢哪个？可以使用你喜欢的方法，把预览图添加到我们的 uploader 当中。这节课到这里，谢谢大家。
