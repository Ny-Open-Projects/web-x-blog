# 22-17-扩展内容：使用 Bun 来运行应用

在部署运行的最后一节课，来一节扩展花絮，介绍一款我最近非常喜欢、也是 2024 年很火的工具：Bun。我们会用 Bun 代替 Node.js 来运行应用。它的官网是 bun.sh，官方 slogan 是 a fast all-in-one JavaScript runtime。

特别注意 all-in-one 这个词，不难看出它是一个大一统的解决方案，包罗万象，拥有开发一个 Node.js 项目所需的全部工具链。可以说是 Node 有的我都有，Node 没有的我也全都有。看看它提供了哪些工具。

第一个当然和 Node.js 一样，它是一个 JavaScript runtime，也就是运行时，提供运行程序的环境。但它比 Node.js 做到更多。第一是速度快，官网有对比图，Bun 远比 Node.js 更快。第二是全面兼容 Node.js API，所以 Node.js 能运行的程序，用 Bun 也完全可以运行。第三点很有意思：直接支持 TypeScript。用 TS 编写的程序可以用 Bun 直接运行，不需要先用 tsc 预编译成 Node.js 可以使用的代码。运行 TS 项目时它比 Node.js 更快，因为它把两步并为了一步。

还有一个特点是无脑支持 JSX，不需要安装任何其他插件，JSX 可以直接使用，官方的说法是 JSX just works。关于模块格式，我们知道 Node.js 很晚才支持 ESM，而 Bun 原生兼容 CommonJS 和 ESM，无需任何配置，甚至可以在同一个文件中同时写 import 和 require，支持这种混合方式，看起来非常神奇。

这就是 runtime 方面的特性。往下看还有更多工具。它内置了包管理器，用 bun install 完成包管理器的任务，最大的特点还是快，对比图里比 pnpm、npm、yarn 都快很多。其他特性包括：兼容 Node.js 不用多说；支持 monorepo，可以直接开发 monorepo 项目，也就是支持 workspaces；最后是它有非常快的全局 cache，所有安装过的包都以全局 cache 的方式存放在本地，只要下载一次，之后的安装都直接从本地获取，这也是它快的原因之一。

除了包管理器，还有 bun test，一个内置的 test runner。它的特点：第一是完全支持 Jest 的语法；第二当然是快，对比下来比我们最常用的 Vitest 还要快很多；同时直接支持 DOM APIs，还有 Snapshot Testing 等等很多特性。不难看出，所有这些工具都体现了一个"快"字，使用它是一种很愉快的开发体验。

现在来完成安装并使用，看看有什么玄机。安装就是运行官网那一行命令。我登录到服务器上，已经安装完毕。装好后可以运行 bun --help 看看它有哪些功能。可以看到非常多的参数，从不同的颜色分组就能看出哪些是关于运行，哪些是关于包管理器。还能看到更多：它还可以 build，也就是可以像 webpack 或 rollup 这样的工具一样工作。

运行非常简单，和 Node.js 完全一样，但可以做到更多。文档里提到，Bun 对环境变量是天生直接支持的：只要本地有 .env 这样的文件，不用做任何配置，它就会直接读取其中的环境变量并运行。这比 Node 20 还要更高级，不需要使用任何参数。当然也可以用参数指定某个文件，它同样是 `--env-file` 这个参数；不指定的话就直接读取本地已有的 .env 文件。

所以运行非常简单，只需要把 node 替换成 bun，不需要添加参数。先进入 .output 所在目录，这个文件夹下面有 .env，直接运行 .output/server/index.mjs，可以看到运行成功了，风格和 node 完全一样。

运行成功以后，它也可以和 pm2 无缝配合。只需要多添加一个参数，叫 interpreter，可以指定用哪个解释器执行。看一下 bun 安装在哪里：which bun，可以看到它安装在某个路径下，把这个完整路径填给 interpreter，它就会用 Bun 来运行。我已经把配置文件创建好了，bun.config.cjs，里面添加了这个参数，并且把之前的环境变量配置删掉了。

现在用它启动：pm2 start bun.config.cjs，可以看到 pm2 成功启动完毕了。

这就是一个小花絮，关于 Bun 的一些基础知识。它是我最近非常喜欢的一个工具，大家做项目也可以考虑尝试。使用它就不需要安装那么多杂七杂八的内容，一个工具就可以搞定，同时不需要任何配置，速度很快，还有各种其他特性。推荐给大家，这节课就到这里。
