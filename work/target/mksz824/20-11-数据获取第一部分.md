# 20-11-数据获取第一部分

这节课探讨 Nuxt 3 中的一个新知识点：数据获取（data fetching）。无论从后端取数，还是在前端发异步请求，都是实战开发的重要部分。Nuxt 3 可以无缝地在服务器端和客户端之间进行数据获取，语法和 Vue 3 比较一致，提供了一系列组合式函数，还自动附带响应式状态、错误处理等功能。

数据获取有三种方式：

1. `useFetch`：组合式函数，在组件 setup 中获取数据最直接的方式。在组件中取数，它是最好用、也是第一个应该考虑的选项。
2. `$fetch`：偏底层的通用网络请求函数，基于另一个库 ofetch，可以把它想象成类似 axios 的库。
3. `useAsyncData`：同样是组合式函数，可以和 `$fetch` 搭配，更精确地控制请求的发送。

补充一个备注：`useFetch` 其实是 `$fetch` 和 `useAsyncData` 一起使用的语法糖，使用它可以避免重复发送请求。本节重点介绍最常用的 `useFetch`。

为什么用组合式函数，而不直接用 `$fetch` 或 axios 这样的底层库？要特别注意，Nuxt 是前后端一体的 SSR 框架，前端和后端都要完成页面渲染，所以不只是在前端发异步请求。之前写 Vue 项目时，异步请求一般都在前端发起；而 `useFetch` 可以确保同样的请求在服务端初次渲染时发送完毕后，前端的 hydration（注水）阶段不再重复发送。换句话说，在 Nuxt 中做数据获取，按场景最好无脑使用 `useFetch`。

写代码前，先修复上节课遇到的一个小 bug。在 auth.ts 中，我们把自动导入的组合式函数（比如 `useCurrentUser`）写在了中间件函数体的外部，也就是文件第一行。直接加载首页没问题，但直接刷新需要该中间件的 URL 时会报 500 错误：组合式函数需要 Nuxt 实例，而此时实例还没创建。原因是这些自动导入的内容没有放在合适的位置，在 Nuxt app 实例创建之前就被使用了。解决方式是把它们移到函数体内部。修改后直接访问 users/1，能成功跳到 login 页面，问题解决。写中间件时要记住：使用自动导入的特性，一定要放在函数体内部，后面的编码中还会反复强调这一点。

接下来开始正式开发。目标是在 id.vue 中，每次进入路由时获取对应用户的信息。数据源推荐一个很好的测试站点：JSON Placeholder（Free Fake API for Testing），它提供了一系列免费 API，比如 posts 返回一百篇文章，users 返回一系列用户，并且严格遵守 URL 格式：访问 `/users/1` 就返回 id 为 1 的 user，假数据非常详细（userName、email 等），以后做类似学习时可以直接用它。

使用很提供的 useFetch，只需传入 URL 即可发送请求。这里要传入路由参数中的 id，所以用模板字符串根据 URL 中的 id 请求对应数据。先把 middleware 暂时注释掉，避免影响测试。

`useFetch` 返回一系列参数，逐一解释。第一个是 `data`，就是请求返回的数据，它是一个响应式对象，但初始是 null 类型，可以用 TS 完善：在之前创建的 user.ts 中添加一个 `UserData` interface（导出几个有代表性的字段即可），然后导入进来。给 `useFetch` 传入泛型后，data 的类型就变成了 `UserData | null`。

展示数据时，因为 data 可能是 null，先用 type guard 把 null 去掉，之后的数据就都带类型了。展示 `data.name` 可以看到自动补全，还可以输出 userName，或者在 pre 标签下输出整个 data。

保存后点击 user one，数据成功获取；进入 user two 也一样。关键验证：首次渲染是否发送异步请求？直接在 user two 路由上刷新，控制台里没有任何异步请求，页面是服务端直接渲染出来的；而 hydration 结束后点击 user one，就会发出对应的 GET 请求。这证实了 `useFetch` 在前后端有不同逻辑，不会重复发送请求。

再介绍几个有用的属性。`pending` 表示当前请求是否正在 loading；`status` 则有四种不同的状态，提供更详尽的网络请求状态。可以把它们加进页面：请求中显示 loading 字样，同时输出 status 的值。刷新后显示 success；请求 user two 时先显示 loading，结束后渲染数据，status 也变为 success。注意它们都是响应式对象，取值时要加 `.value`。

还有一个 `refresh` 函数，看名字就知道用于重新发送请求。在页面最前面加一个按钮 refresh data，点击时调用 refresh，可以看到请求被重新发送，界面重新渲染一次。

最后看第二个参数上的选项，它们和发送请求相关：比如 body（发送其他类型请求时传输更多数据）、method（指定 HTTP 方法）。还有一个很有意思的 `pick`，可以快速筛选返回值。现在 data 返回所有字段，在 pick 中传入想要的 key（比如 name 和 username），保存后返回的数据就只剩这两个字段了。

结尾再介绍 DevTools 上的 Payload 模块，它可以监控当前数据的发送情况：能看到后端发送的请求、请求的 ID 和返回值。这节课讲了 `useFetch` 的用法，下节课再深入看另外两个函数的玄机。
