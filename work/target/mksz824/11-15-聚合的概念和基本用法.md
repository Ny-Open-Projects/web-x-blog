# 11-15-聚合的概念和基本用法

上节课讲了 MongoDB 数据之间的关系：把对方的 ID 存到相应字段就能完成两个集合的对应关系。但要同时取得两部分数据时都得用两次 query。有没有办法一次 query 拿到两部分数据？答案是肯定的，为此引出 MongoDB 的新概念：聚合 Aggregation。聚合操作可以把多个文档的值组合在一起，并对分组数据执行各种操作，返回相应的结果，算是一个比较高级的功能。

光看概念肯定云里雾里。这里讲聚合中的一种方式：管道聚合，它是聚合中最常见的方式。管道 Pipe，用过 Linux 或 Node.js Stream 的可能听说过：把操作分解为多步，第一步的输出作为第二步的输入，通过多次处理获取最终结果。我们用一个示例来讲解。

首先明确目的：聚合也是为了获得结果，只不过要比之前的过滤更复杂。创建 const results = await userCollection.aggregate()。注意它返回的是一个 aggregation cursor，所以也需要 toArray 转成数组。aggregate 接受一个数组参数，描述聚合的过程，我们创建一个数组叫 pipeline，把步骤一步步写进去。TS 对 aggregate 的类型帮助不太完全，直接描绘成一个 doc 的数组，所以这里不给它添加类型了，写操作符时要特别注意别写错。

第一步做查询操作，输出 age 大于 30 的条目。聚合有一系列常用管道操作符：$match 最常见，过滤数据只输出符合条件的文档；还有一系列其实已经见过的，比如 $project、$sort、$limit、$skip 等。先写 $match：第一项写操作符 $match，后面写条件，条件和 find 里的 query 完全一样，写 age 大于 30（$gt）。运行 ts-node relation.ts，拿到了大于 30 的系列数据，和之前的过滤完全一样，大家应该很清楚了。

第二步来点新东西：分组，把相同球队的球员分在一起，用新的管道操作符 $group。分组是聚合中最重要也比较难理解的部分。先看简单格式：$group 对应一个 object，里面最重要的是 _id 字段，必须写也最重要，它指代你想按哪个条目分组，相同的值会自动分到一项。我们希望按球队分组：pipeline 第二项写 $group，_id 是强制的，后面写分组的字段，格式是美元符号加字段名称，这里就是 $team。这样分组就完成了。

运行前先想一下期望结果：数据里有两个条目有 team 且完全相同（都以七开头结尾的 ID），剩下的没有 team，所以应该分两组：有 team 的一条组，没 team 的一组。运行后确实分组成功，和预想一样：没有 team 的分成一组，有 team 的一组。大家可以添加更多不同 team 的数据试试是不是分成多组。

有了 _id 之后，可以用特殊的表达式操作符操作组内的结果，其中有一系列数学操作符，比如 $sum 计算总和、$avg 求平均数等等。写法：field 是你想起的名称，然后是对应的操作符，最后是 expression。现在希望把分组里的年龄都加起来：新建一个属性 total，值是 $sum 操作，对哪个值相加呢？写 $age（美元符号加原数据的属性名 age），表示对原数据中的 age 属性相加。运行后结果是 76 和 105，就是两组相加的最终结果。

$sum 还可以实现 count 效果：不用具体属性，每项加 1 即可。再添加一个属性 count，也用 $sum，操作值写 1，等于把每一项（值为 1）都加起来。运行后 count 是 3 和 2：没有球队的一组三个条目，有球队的一组两个条目。

再测一个操作符：求平均值 $avg，多添加一个条目 average，操作符写 $avg，字段还是 age，算出年龄的平均数。运行后 total、count、average 都输出了，一个 38，上面是 35。

通过这两步，大家对聚合有了粗浅的认识：用管道的形式分多步组合处理，最终输出结果。管道还可以继续，比如对现在的结果排序：添加第三步，操作符 $sort，和 find 第二个参数里的 sort、之前写的链式写法都是一个意思。字段很多了（_id、total、count、average），我们用 total 正序排序。运行后 76 那项排到了上面，105 排到下面，整个过程成功。

回顾一下：第一步用 $match 过滤结果，条件几乎和 query 一样；然后学了比较难的 $group，参数是分组的 key，必须有 _id，写你想分组的属性，相同值自动一组，后面加操作符可以算出总数、平均数等；最后加 $sort 排序，多步组合获得最终结果。$group 这个内容我觉得还是有点难度的，写法比较特殊、难以理解，请大家课后多多复习。
