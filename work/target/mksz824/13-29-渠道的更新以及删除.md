# 13-29-渠道的更新以及删除

上节课我们完成了渠道的创建和展示。这里说明一下，我在上节课代码的基础上添加了一些错误的边界处理，因为都写过多次了，上节课就没有做演示。代码主要针对 id 错误、找不到对应作品的情况给出提示：update 之后返回一个 response，假如 response 存在，说明更新成功，这时才返回 success，否则直接返回 error。

现在的任务是完成渠道的更新和删除。希望大家通过学习数组操作可以举一反三，比如以后作品要添加 tag 系统，其实和 channel 是一样的，自然应该联想到这些对应的操作。和创建一样，更新和删除其实都是作品的更新操作，用的都是 findOneAndUpdate，只是更新 channels 这个数组的方式不同。

先写更新操作，命名为 async updateChannelName。前面部分和创建完全一样：拿出 ctx，拿到 params 上的 id，再从 body 上取 name，因为要更新的是 channel 的 name，work_id 是不需要的。特别注意这个 id 是 channel 创建时生成的那个 id，不是 work 的 id。

要更新数组中的一项，需要复习一下 MongoDB 的基础知识。首先是查询数组中的一项。回到 MongoDB 数据更新操作符的文档，先做查询。逻辑还是 ctx.model.work 上的 findOneAndUpdate。第一个参数是查询条件，查询数组中的一项该怎么写？如果当时没有总结这个知识点，可以点文档里的链接跳转到具体章节，有一节叫 query condition on the field in the array：如果要查询数组中嵌套 object 里的项，可以使用点号加上嵌套文档中的字段名。所以我们知道了，可以用点加属性名来指代数组里的数据。写出来就是 `channels.id`，让它等于我们的 id，查询条件就完成了。

接下来是更新。复习数组更新操作符，这里需要 $set，它的作用是更新其中的几项。第二个参数写 `$set`，要更新名称该怎么写呢？这里引入一个新概念，叫占位符。文档里用的是 `$`，这个 $ 代表你查到的对应数据要更新的那项的下标。你可以用 0 代表更新数组的第一项，而 $ 就是对应前面查询条件的这么一项。所以前面要指定更新哪一项，写 channels.$，然后是哪个属性：name，把它更新成 body 中的新 name。

到这里整个流程就完成了。虽然只有短短一行，但蕴含了两个知识点：一是在数组中怎样查找，二是怎样更新数组中的一项，特别注意点号和 $ 这两个写法。错误边界处理大家可以照着上节课的方式自己添加，我这里直接返回，用 ctx.helper.success 把 name 返回即可。

updateChannel 写完了，测试一下好不好用。我把 URL 贴在 Postman 里，请求是 PUT /api/channels/:id，对应的 controller 就是刚创建的。先用 GET /api/channels/10 获取，里面有一系列 channel，我们希望修改其中的微信4，也就是那个 id。把它的 id 复制进 URL，body 里 name 写成微信New，再把登录 token 复制到 header，点击 send，返回了微信New，表示请求成功。再获取一次 id 为 10 的作品，可以看到微信New 已经更新，update 完成。

最后是删除的 controller。命名为 deleteChannel，前面还是一样，需要 ctx 和对应的 id，注意这个 id 同样是 channel 的 id。逻辑还是 ctx.model.work 上的 findOneAndUpdate，虽然是 delete，但它本质上还是一个更新操作。第一项搜索条件跟前面一样，根据 id 查找，直接把条件复制过来。第二项就不一样了：要删除一项，看看之前的文档怎么写的。pop 是删除数组首尾的项，删除特定的项需要用一个新的操作符 $pull。文档里写，从数组中删除一项时，它的值对应一个 value 或者 condition。我们这里应该用查询条件，也就是查这个 id。所以写出来是：channels 后面跟一个条件对象，条件是 id 等于传入的那个特殊值。这样删除就写完了。可以给它加一个 new: true 选项，然后把 work 返回出去，helper.success 返回 response 的 work。

唯一的新知识点就是 $pull 以及它的参数是一个查询条件。把 router 添加上去，复制一份改成 delete 方法，路径对应 deleteChannel。

最后验证 delete 是否好用。我已经创建好对应的接口，希望把刚才那条 channel 删掉，把 token 拿过来用一下，点击 send，返回的值描述了删除的内容，剩下两条。再用 get channel 验证一下，原来的三条现在只剩两条，说明删除工作完成了。

渠道的操作就全部完成了，请大家自己去把对应的边界条件添加一下，比如没有找到 work、id 传错等一系列情况。通过这两节课我们又复习了 MongoDB 中数组的操作，完成了渠道的一系列操作。
