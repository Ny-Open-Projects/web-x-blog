# 5-2-大话前端工具链

在正式用脚手架创建工程之前，值得先梳理一下前端工具链诞生的前因后果。工具都是随着需求出现的，经过多年发展，JavaScript 早已不是当年那个不起眼的脚本语言。现在的 Web 前端项目，已经不是写几个 HTML 页面加点 CSS 和 JS 就能完事的了。

一个实用项目往往会用到大量框架和第三方库，随之带来包管理、预编译、构建打包、压缩合并等一系列需求。纯手工完成这些任务几乎不可能，于是有了前端工程化的概念。有了工程，就需要一套标准流程和对应的工具来支撑，这些工具覆盖复杂前端工程的不同阶段，相互衔接就构成了前端工具链。这门课带有科普性质，下面按类别列出常用工具和它们之间的关系。

第一类是静态类型语言。JS 属于动态语言，简单灵活易学，但在大型项目里开发效率可能下降，也容易产生 bug，于是有了 TypeScript。它在编译阶段就能发现错误，并转换成 JavaScript，属于源代码阶段的工具。除了 TypeScript，还有 Facebook 推出的 Flow，两者非常类似，也用 annotation 加冒号类型的方式描述，同样有 interface、generic 等特性，不过 Flow 在流行度和特性上与 TypeScript 已有明显差距，有兴趣可以翻翻它的文档。

第二类是代码风格检查工具 Linter。还是因为动态语言写法灵活，多人协作项目里代码风格各异，给维护和扩展带来不少麻烦。Linter 不但能检查代码书写格式，还能查出引用未定义变量之类的低级错误。江湖上曾有许多 Linter，比如 JSLint、JSHint、TSLint 等，如今基本是 ESLint 一统江湖。刚开始用会觉得不适应，限制多、动不动就警告报错，但从长远看，尤其是多人协作项目，引入 Linter 非常有必要。

第三类是包管理器。Node.js 的诞生带来了前端生态的极度繁荣，第三方库应有尽有，因此需要一个平台负责包的托管、版本管理、下载安装和依赖管理，这就是大家最熟悉的 NPM。此外还有 2016 年 Facebook 推出的 Yarn，它与 NPM 的 registry 完全兼容，主打 safe（安全）、stable（稳定）、reproducible（可重复构建），依赖锁定后不会因为依赖变化导致项目出问题。

第四类是转译器 transpiler，作用是将非 JavaScript 语言（比如 TypeScript、CoffeeScript、Livescript），或者不同版本的 JavaScript（ES6、ES7、ES8），翻译成符合目标平台要求的等价代码，比如满足一系列兼容性要求、做变量混淆等。现在最流行的是 Babel，它的工具链主要用于将 ES6 以上版本的 JavaScript 转译成向后兼容的浏览器代码。比如放入使用了 Optional Chaining 特性的 next-gen JavaScript，它就能转译成各种浏览器都兼容的语法。

第五类是开发服务器。开发过程中最好有一个本地服务器展示结果，而且除了直接展示页面，还应该提供更丰富的功能：改动代码后尽快展示最新结果，不用手动刷新页面，也就是 live reload，检测到变化就刷新页面。更进一步还有 hot module replacement（HMR）热替换，发现某个组件或样式改变后，直接在 DOM 中修改这一部分，不用整页刷新，实时把最新结果呈现出来。

前面说的都是开发环境的工具，接下来是面向生产环境的。第一类是打包工具 Bundler。实际的生产项目通常不会把直接写的代码发布到服务器，而是通过工具对各种静态和动态资源整合处理，最终生成的代码可能跟源代码完全不一样。常见的是 Webpack，几乎是大部项目的标配。它本身只能识别 JavaScript 和 JSON 文件，但架构提供了无限可能：通过 Loader 处理任何类型的资源，通过插件统筹管理、优化打包结果，还能做资源管理和环境变量注入。不同类型互相依赖的一系列资源，经过它的打包就变成了系列的 static assets。

除了 Webpack，还有两个值得认识的打包器。一个是 Rollup，支持输出 library 或者 application，最大的卖点是最早默认支持 ES 模块、很早就实现了 tree shaking，同时具备插件和 hook 功能，定制化也不错。另一个是 Parcel，属于比较小众的后起之秀，号称零配置、不用写一大堆配置文件，不过现在已经不太火，了解一下即可。

从工具链的全景图看，打包工具有可能包含转译器，把静态类型语言转译生成代码，同时还有打包其他类型资源等更多功能，最终生成符合兼容性和生产环境要求的代码。

再一类是任务管理工具 Task Runner，作用是自动化执行项目所需的各种重复性任务，比如 CSS 预处理、添加前缀、优化图片、合并压缩文件、拷贝删除、监听文件变化并自动执行任务。代表工具一个是 Gulp，它采用流式管道组合多个任务，任务之间的临时结果放在内存里，执行效率高很多；另一个是 Grunt，任务管理只是它强大功能的一部分，通过不同插件在构建的不同阶段执行个性化任务，算是一个混合多种场景的工具。如果需求比较简单，其实没必要用这些复杂工具，直接写 npm scripts 或者脚本就够了。

至此会发现，从头开始一个复杂项目，这些工具势必要做一大堆配置，非常繁琐。几年前还有人戏称自己是 Webpack 配置文件工程师，可见配置复杂到什么程度。所以可以针对特定前端框架抽象出一个工具，把整个工具链都包含进去，把复杂的配置过程在内部处理掉，最后呈现给开发者的只是一个非常简单的安装过程。为了简单，它甚至可以提供 GUI 界面这种更容易理解的方式，还可以根据项目需求扩展出部署、CI/CD 等更多功能，算是一个集大成的解决方案。

脚手架工具一般按前端框架分类：Vue 阵营有 Vue CLI、Vite 和我们自研的 OpsFlow CLI；React 有 create-react-app；Angular 有 Angular CLI。当然不少公司也会根据自身业务开发强绑定的内部脚手架。

这节课描述了前端工具链的概念，也解释了市面上流行工具的定位。后面讲到具体工具时，我会尽量用对比的方式讲解异同和背后隐藏的思想，就像之前讲 Vue3 基础知识时会穿插 React 的知识对照着学。这节课就到这里，谢谢大家。
