# 6-8-获取正在编辑的元素的属性

之前我们完成了创建和删除组件的逻辑，现在来完成编辑器中一个比较复杂和有难度的问题：编辑业务组件的属性。基础文档中也写了整个编辑组件的流程，但可以直接从"将属性映射到表单"这个抽象过程往前看，其实还少一步：找到目前正在编辑的组件。我认为编辑的流程应该是这样的：第一步点击某一个组件，该组件呈现选中的状态，然后将被选中组件的属性以不同类型的表单呈现在右侧；之后编辑表单中的值，在值更新的同时把数据更新到页面。现在的文档缺少第一步，这就是具体实现细节和技术指导方案之间的 gap。

现在来完成第一步的流程。它和上次添加组件的流程非常相似，还是使用流程图来描述做法。画布区域中存在多个已经添加过的组件，我们用 id 1 和 2 来表示。点击的时候要更新 store，所以想到跟上次一样的方法：需要一个包裹的组件，称之为 edit-wrapper，将真正的业务组件包裹在其中，做到逻辑和业务的隔离。点击时和之前一样要发射一个事件，称之为 set-active，自然需要把一些 component 数据传递进去，id 肯定要传。

看图编码。我已经创建了 edit-wrapper 组件。刚才分析了它的属性：首先要传入一个 id，type 是 string，required 为 true。然后它要发射一个事件，emits 里写 set-active。setup 的第一个参数是 props，第二个是 context。里面应该有一个 function 跟点击时调用，称之为 onItemClick：context.emit('set-active', props.id)，把事件发射出去，附带 id。最后把这个函数 return 出去。

之后稍作修改：给外层加一个 @click，点击时调用 onItemClick，并且传 id。特别注意要加一个 slot，把渲染的内容放在其中。有了 slot，它就展示包裹的内容，我们可以把业务组件包裹在其中。

到 editor.vue 中做替换。现在还是直接把 component 展示在这里，有了 edit-wrapper 后就替换过去，把 edit-wrapper 闭合好，里面传入我们的 component。把原来的展示代码删掉，它包裹在业务组件外面。这时还缺一个属性，称之为 id，也就是 component.id，看起来没问题。

它点击后会发射一个事件 set-active，在 editor.vue 里对应加上：在 set-active 中调用 store.commit 来真正更新 store 中的值。很简单，再添加一个方法 setActive，参数 id 是 string，store.commit('setActive', id)，然后把这个方法返回，并添加到 edit-wrapper 标签上：@set-active="setActive"。这一步就完成了，点击事件能发射出来了。

之后是在 editor 中提交 commit 来更新 store。来到 editor store，更新它的 mutations。这个 mutation 很简单，叫 setActive，第一个参数是 state，第二个是传入的 currentId，是 string。之前在 store 中已经有这个设计了：有一个叫 currentElement 的字段，用来保存当前编辑的是哪个元素。自然把它更新一下：state.currentElement = currentId。现在 store 中的 currentElement 已经被更新了。

可以用它取出当前被点击的 element。它应该属于基于 state 的计算属性，用 getters 再适合不过了。添加一个 getters，称之为 getCurrentElement，参数是 state，返回 state.components.find(component => component.id === state.currentElement)，这样就能找到当前的 element。

有了 getter，下一步在 editor.vue 中找到当前使用的元素。添加一个 computed：currentElement，里面是 store.getters.getCurrentElement，然后把 currentElement return。特别注意这里要添加一个泛型，对应 ComponentData（我已经从类型文件中取出来了）。不过还有点不一样：在点击之前可能没有选中任何元素，currentElement 可能是 null，所以创建一个联合类型 ComponentData | null：点击以后它是 ComponentData 类型，之前是 null。这样就保证了类型的正确。

拿到 currentElement 后，可以将它展示在界面中了。先用 pre 标签把它的 props 打印在属性区右侧：currentElement.props。大家可以看到这时候会报错，因为 currentElement 是 ComponentData 或 null 类型，所以要先做一个类型判断，它存在（type guard 起作用）以后才能这样访问。设定了正确类型以后，TS 又帮了我们一把。

试一下吧。点击第一个，它的属性就完全展示在这里了，同时它也被选中了。点击 hello，也会被选中。再添加几个比较复杂的组件，点击后这些 props 都显示在这里，没问题。

功能写到一半，自然最后再来一点美化工作：希望在画布中，被选中的组件有一个边框高亮来指示它是否被选中。很自然地想到给 edit-wrapper 添加一个 active 属性，当它等于 true 时表示已被选中。说干就干：在 EditWrapper 中添加一个属性 active，type 是布尔类型，default 是 false。有了 active，希望用样式控制它，动态添加一个样式：当 active 为 true 时给它添加 active 类名，然后加一些 CSS：active 会给它加一个蓝色的边框。

最后要把这个属性从 editor 传入：在 edit-wrapper 标签上传入 :active="isActive"，判断条件是当前 component.id 等于 currentElement（记住它有可能是 null，要先判断存在）的 id。当被选中的和我们本身的 id 相同时，这个属性就变成 true，样式也就添加上了。看看好不好用：点击以后出现了蓝色的边框，美化工作完成。

完成了编辑属性的第一步，来回顾一下我们的图和整个数据流转。有流程图，我们对数据的流动就了如指掌。其实这次和上次添加组件的流程非常相似，只不过多添加了一个 getter，可以很快取到当前需要的值。大家可以好好回味一下这张图。这节课的任务就到这里，谢谢大家。
