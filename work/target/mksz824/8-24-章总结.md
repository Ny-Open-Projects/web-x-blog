## 开发主线与方式

课程脉络是随着 uploader 组件的真实开发过程展开的。在这个过程中我们使用了 TDD（先写测试后写实现）和普通开发混合的方式。选择什么样的方法，根据功能侧重的点来决定，没有硬性的规则。标黑色的是 TDD 方式，其他的是普通开发方式。整体是由浅至深：从最基本的原理出发一步一步扩展，完成 uploader 的总体功能，期间还扩展了一系列知识，丰富大家的知识库。

## Vue3 实例与通信

扩展知识第一项：Vue3 的三种实例。第一种是 app instance，整个应用的实例，由 createApp 方法返回；第二种是 component instance，组件实例，使用 ref 或 app.mount 返回，上面除了组件 setup return 的一系列数据，还有全局属性和第三方挂载上去的属性；最后一种是组件内部实例，用 getCurrentInstance 返回，它和 component instance 看起来比较像，但还有更多的属性和功能。

接着是通信的四种方法。第一种：父组件获取子组件实例，使用 ref；第二种：子组件获取父组件实例，使用内置属性 $parent，只要拿到 component instance 就可以访问它；第三种：provide / inject，自上而下跨层传递数据；第四种是比较独特的方式：emitter 事件发射器，可以跨层传递数据。

## 源码分析与扩展知识

我们根据自己的实现，再去分析了 Element Plus Upload 的源码。它跟我们的区别：第一是组件的分割，分割成 index、uploader、upload-list、dragger 等不同功能的组件；第二是数据操作的分割，Composition API 很重要的一部分就是用函数把一些数据操作进行分割（hooks），它的 use-handlers 就是把一系列数据操作单独封装成函数并有具体的返回。

作为扩展，我们实现了图片预览，总结了本地读取并展示图片的两种方法：一种是静态方法 URL.createObjectURL，另一种是实例方法 FileReader.readAsDataURL，两者各有千秋，大家自己选择就好。

最后测试时遇到了 jsdom 的运行环境之谜：为什么它看起来是浏览器，但一些浏览器标准的 API 却不存在？我们了解到，其实它是用 JS 模拟的一个浏览器环境，这个东西叫做 jsdom。

之后是功能落地：把上传组件添加到编辑器，完成对应功能。期间也有扩展知识：第一个是 HTMLImageElement 的家族传承。我们经常接触这些类型的元素，但搞不清楚来龙去脉，现在分析了一遍：从最下面的"孙子"说起，HTMLImageElement 到 HTMLElement，再到 Element，再到 Node，最后到 EventTarget。另一个扩展知识：了解了这些类型之后，在上面找到具体的属性，获得了获取图片真实大小的方法。

## TDD 的感受

谈谈 TDD 的感受。我们不是强制采用这种开发模式，而是选择正确的开发方式来完成对应的功能。不过它给我很强的信心，测试给我的信心：我对之前开发的功能更有信心了，不怕新功能搞坏老功能，不用每次开发完新功能就赶紧手动把之前的 case 全部测一遍；重构也更方便了，改动一大段代码也不担心重构过程会 break 掉之前的功能。

## 作业

最后说说作业。第一个：按照自己的想法继续完成 uploader 组件的开发。讲课中说过它还缺失一些功能，可以自己添加，也可以根据 Element Plus Upload 组件的一些特性把它优化得更完美。第二个：根据 MDN 文档分析 Event 对象的家族关系，像这样看文档，看它是怎样的继承关系，还有哪些不同的 interface，以及上面有意思的属性和方法。第三个：我们只是上传了图片，但还没有处理图片 src 属性的对应组件。希望大家完成一个 image-processor 的组件开发，并为其写测试。这个处理图片属性（src，即传入图片地址）的组件：首先显示出一张图片，旁边应该有一个按钮，重新上传后可以改变图片地址。开发过程大家应该已经很熟悉了，特别注意组件属性处理的标准：传入一个 value，并发送出一个事件。
