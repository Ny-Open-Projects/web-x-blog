# 14-6-Egg.js 启动的不同进程的分类以及特点

通过三节课我们了解了 cluster 是什么、它的优势以及进程间的通讯。现在是时候介绍 Egg.js 在生产环境启动时针对 cluster 做的特别优化。这里从大面上介绍，不深入 Egg 的源代码，理解它的大体工作原理即可。想了解更多可以去看官方文档，里面写得很详细，下面内容是对文档的提取。

## 启动后到底有哪些进程

第一个任务是使用脚本启动，也就是 `npm run start`。启动之后到底有多少个进程？可以在终端观察一下。先用 `ps aux | grep` 搜 start 关键字，会发现只有一个进程，它使用 egg-cluster 中的 start-cluster 来启动 master 进程，然后由 master 去启动别的进程。

再用 `ps aux | grep agent` 搜一下，就会弹出一连串的进程。仔细观察可以发现，其中一六一七一八一九这几个是连续的，它们运行在 app_worker.js 上，对应一系列用 cluster 启动的 worker process。数一下总共五个：四个连续的 worker 加上一个不连续的四九零一，它运行的是 agent_worker.js，也就是所谓的 agent。

所以结构是这样的：有一个主要的 master 进程，由它启动多个 worker；worker 里分两类，一个是 agent，其他的按 CPU 核数启动，之前说过机器是四核，所以这里有四个 app worker 进程。

## 进程守护

针对企业级应用，使用 cluster 之后必须考虑应用的健壮性，第一个要考虑的问题就是进程异常退出后该怎么处理。异常分两种情况。

第一种是代码抛出异常且没有被捕获，也就是业务代码出了问题。这时 worker 会通过 process 上的 uncaughtException 事件拿到错误。捕获之后进程已经处于不确定状态，需要一个优雅退出的过程。官网有一张图描述了 worker 出现这种问题时的处理流程：

- worker 出现 uncaught exception，第一步先做 disconnect：关闭这个异常 worker 的所有 TCP server，断开和 master 的 IPC 通道，不再接受新的用户请求；
- disconnect 之后，master 会立刻 fork 一个新的 worker，保证在线工人数量不变；
- 异常 worker 等待一段时间，处理完已经接受的请求后再退出。

第二种是系统异常，也就是某个 worker 进程 crash 或者被系统杀死。这时没有机会让它优雅退出，master 会立刻 fork 一个新的 worker。可以演示一下：拿刚才的某个 worker 进程直接 kill 掉，再看进程列表，数量依然是五个，消失的那个位置上 master 立刻创建了一个新的进程补上。这就是它保证系统健壮性的过程。

## Agent 进程是干什么的

一个 master 加几个 worker 的机制看起来已经比较完美，但有一些特殊需求并不需要几个 worker 一起合作完成。比如后台性质的工作、定时任务：在特定时间整理日志，或者每天检查用户表中是否有封禁的用户，有就删除掉。如果几个 worker 一起来做这些任务，不仅浪费资源，还有可能结果互相冲突，造成混乱。

所以对于这类后台工作，Egg 不希望由所有处理业务逻辑的 worker 共同完成，而是启动了一个全新的进程，叫 agent。它不对外提供服务，只对 master 负责，专门处理公共事务、协调特殊工作。遇到这类需求时，agent 会协调其中的一个 worker 去完成任务，其他 worker 不参与。

## 启动顺序

官网还有一张图描述了整个启动顺序：第一步 master fork 一个 agent 进程；agent 通过上节课学的 IPC 管道通知 master，我已经启动好了；然后 master fork 多个 app worker，数量根据 CPU 核数决定，这里是四个；这些 worker 初始化成功后，同样通过 IPC 告诉 master 已经准备好了；所有进程都初始化成功后，master 通知 agent 和 worker 应用启动成功。

## 三种进程小结

| 进程 | 数量 | 主要作用 | 稳定性 | 是否运行业务代码 |
|---|---|---|---|---|
| master | 1 | 进程管理、进程间消息转发 | 非常高 | 不运行任何业务代码 |
| agent | 1 | 后台运行工作 | 比较高 | 有可能自定义运行少量业务代码 |
| worker | CPU 核数 | 执行业务代码 | 一般 | 只运行业务代码 |

master 承担进程管理工作，类似之前介绍的 PM2，只需要把它运行起来，worker 和 agent 进程的初始化、重启等一系列工作它都会搞定。

agent 比较特殊。大部分情况下写业务代码时完全不用考虑它的存在，但遇到特殊场景，只想让代码运行在一个进程上时，agent 就派上用场了。由于 agent 只有一个，而且负责许多维持连接的脏活累活，不能轻易挂掉和重启，所以 agent 进程在监听到未捕获异常时是不会退出的。

worker 大家就很熟悉了，数量和 CPU 核数相同，只运行业务代码。

一个启动命令看起来很简单，其实内部蕴含了很多内容和一系列机制。这节课对于 Egg 的启动过程就介绍到这里。
