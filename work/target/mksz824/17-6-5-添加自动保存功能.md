# 17-6-5-添加自动保存功能

上节完成了手动保存。对于频繁改动的应用，自动保存非常有用，它避免了用户在没保存的情况下丢失最新的编辑结果。自动保存一般有两种做法，用两个在线文档看看它们的实现：

- **语雀**：定时保存。实测它大约每隔三分半自动发一次保存请求；
- **石墨文档**：实时保存。在文本区域输入字符的当下就触发保存，也就是 onChange 时绑定事件，有新内容就发一次保存请求。

我们采用第一种比较常见的做法：定时触发保存请求。触发之前还有个小优化：不能一股脑发请求，用户打开页面什么都不做，到点照样发请求就浪费了。所以要加一个特殊字段 **isDirty**，标记数据是否被修改过，有修改才保存。思路和添加历史记录类似：不采用对比新旧数据这种耗时的方法，而是触发特定 mutation 时直接标记字段。

## isDirty 字段与高阶函数包装

字段加在 editor.ts 的 editorProps 里，布尔类型，注释写清"标记数据是否有修改"，初始值为 false。

接下来要把一系列增删改 mutation 里都设置 `state.isDirty = true`，这又是一批重复工作，自然想到用高阶函数。先确认 mutation 的类型：MutationTree 是一个 indexable type，key 为 string，value 是 Mutation；点进去看，就是一个接受 state 和 payload（any）、返回 any 的函数。

创建高阶函数 `setDirtyWrapper`：返回一个 EditorProps 类型的 state 加 payload 的函数，内部先执行公共操作 `state.isDirty = true`，再顺延调用 callback，它的签名与 mutation 完全一样，即上面分析出的 Mutation 类型，泛型传 EditorProps：

```ts
function setDirtyWrapper(callback: Mutation<EditorProps>) {
  return (state: EditorProps, payload: any) => {
    state.isDirty = true
    callback(state, payload)
  }
}
```

写高阶函数的三步原则我们已经很熟了。然后在需要标记 dirty 的 mutation 处替换：把 addComponent 等改成箭头函数，用 wrapper 包裹原逻辑。所有增删改 mutation 处理完毕后，给 saveWork mutation 添加置回初始状态的逻辑，它只需要 state 参数，`state.isDirty = false`。这里还可以顺手加更多字段，比如上次修改时间，想在界面展示更丰富的信息就加在这里。

## 定时器

到 editorView 里操作。添加 computed 的 isDirty，返回 `store.state.editor.isDirty`。然后创建定时器：定义 timer 变量初始为 0，onMounted 里赋值 setInterval，回调中判断 `isDirty.value === true` 就调用 saveWork；测试用的时间先设成 5 秒。最后在 onUnmounted 里 `clearInterval(timer)` 清理。

页面测试：随便改动一下，把斜体去掉，到点自动保存触发；再修改一次，对齐变到右边，保存同样自动触发了。自动保存功能实现完毕。
