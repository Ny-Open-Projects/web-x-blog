# 17-5-1-添加全局读取状态 - 整体通用读取状态

现在程序里已经有好几个异步请求在跑了。发请求时最好在界面上给用户一个提示，告诉用户数据正在读取、请稍候，这就是经典的 loading 问题。loading 显然是全局状态，各个页面都可能用到；提到全局状态，自然就想到 Vuex。

## 为什么布尔值不够用

store 里新加一个全局模块，loading 就是其中之一。用什么值表示？最直觉的做法是布尔值：请求开始置 true，结束置 false，界面上用它显示任意喜欢的 loading 样式。

但请求经常一次发多个，布尔值会出问题。串行发送时：request1 开始置 true，结束置 false，loading 图标消失；request2 开始又置 true，结束又消失，图标会先出现消失、再出现消失，不停地闪烁。并行发送时更糟：一个页面同时发两个请求，其中一个结束时状态已被置为 false，可另一个请求还没结束，这就是错误行为了。

解决办法是创建一个计数器记录进行中的请求数量：任何一个请求开始就加一，结束就减一，计数器归零即所有请求完毕。判断是否在 loading，用一个 getter，只要计数器大于零，就处于 loading。

## 编码实现

新建 `global.ts` 存放全局数据（已挂到 index.ts 里）。state 中加 `requestNumber`，number 类型，初始值为零。

两个 mutation：`startLoading` 在任何请求开始时把 `state.requestNumber++`；`finishLoading` 中做相反操作 `state.requestNumber--`（这里人为延时一秒再执行，方便观察效果）。再加一个 getter `isLoading`，返回 `state.requestNumber > 0`，只要大于零，就说明还有请求没结束。

```ts
const mutations = {
  startLoading(state) { state.requestNumber++ },
  finishLoading(state) { setTimeout(() => { state.requestNumber-- }, 1000) },
}
const getters = {
  isLoading: (state) => state.requestNumber > 0,
}
```

## 用 axios 拦截器免去重复代码

接下来要把对应的 commit 放进页面。问题是要在每个发请求的地方都手写 commit 吗？所有异步请求都要重复这段逻辑，一出现"拷贝粘贴大法"就该想想有没有优化方案。axios 提供了拦截器（interceptors）：在全局层面拦截请求发送和响应返回的时机，在其中完成逻辑。它分两种：`request.use` 和 `response.use`。

思路清晰了：request 拦截器里调用 startLoading，response 拦截器里调用 finishLoading。这些代码放在 `main.ts`：

```ts
axios.interceptors.request.use((config) => {
  store.commit('startLoading')
  return config
})
axios.interceptors.response.use((response) => {
  store.commit('finishLoading')
  return response
})
```

特别注意：request 拦截器必须返回 config，否则请求会报错；response 拦截器同样要把 response 返回，流程才能继续。

## 页面验证

到 `LoginView` 里验证。先给 useStore 泛型传入类型，从 index 导入 store，加 GlobalDataProps。创建 computed 的 isLoading，返回 `store.getters.isLoading` 并暴露出去。模板顶部加一个 ASpin，Ant Design Vue 自带的 loader，样式可以自行美化，isLoading 为 true 时显示。

运行：填手机号点击获取验证码，loader 立即出现；填入验证码点击登录，同样处于 loading，登录成功后跳转，一切正常。每次请求的开始和结束都被拦截器完美捕获，自动触发对应的 mutation，非常好用。

但还有个需求会让我们犯难：怎样知道具体是哪个请求在运行？比如点击登录后希望登录按钮变灰防止重复点击，发送验证码时也希望验证码按钮 disabled。这需要更精确的控制机制，下节来看。
