# 13-23-使用 webpack 的解决对应的引用第三方库的问题

上节课我们解决了 px 到 vw 的转换，现在展示 H5 页面只剩下一个悬而未决的问题：把组件库的样式文件也添加到展示页面中去。最简单的做法大家都能想到，直接拷贝对应的样式文件到 public 文件夹，然后在模板文件中引用，一条 `cp` 命令就能搞定。

但简单的方法在这里有几个弊端，我们一一来看。第一个是组件库升级的问题。组件库升级后样式可能随之更新，也就是 OpsFlow 组件库的 CSS 文件被更新了，这时就需要在安装新版本后重新拷贝一次。这个流程比较繁琐，而且很容易忘记拷贝，最后造成样式没有更新、样式错乱等一系列问题。

第二个问题更关键。当静态页面包含更多逻辑的时候，这么做就力不从心了。现在页面里只有静态文件，但要从长远着想，未来这个页面很可能要添加 JS 功能，比如统计、分享等等，这些功能可能会用到第三方库。而在直接引用 JS 文件的写法下，我们没法使用 ES6 的模块系统，只能写出很多很原始的代码。

举个例子，假如要引用一个第三方库 third-party.js。第一步安装它，安装完以后又会遇到样式文件同样的问题：需要拷贝这个库的 UMD 模式文件，注意必须是浏览器能使用的模式。拷到 public 文件夹下后，在 page.html 中添加引用，比如 `public/third-party.js`。第三步再写一个入口文件使用它完成功能。但这个入口文件不支持 ES6 模块系统，很可能要直接在全局变量上做引用，整个流程非常别扭。

我们希望的是能用 ES6 模块的方式书写代码。写了这么多代码，大家对这种模块方式早已得心应手。这里只需要一个单文件入口，比如 index.js，在里面统一加载需要的 CSS 文件（比如 OpsFlow 组件库的样式），需要哪个第三方库就 import 哪个，然后把一系列逻辑都写在这个文件里，任务就完成了。

为了使用 ES6 模块方式书写，就需要一个特定的工具，也就是我们之前介绍过的 bundler。打包组件库的时候我们用了 rollup，这里则使用 webpack。这一部分以 webpack 的简单使用为主，满足眼下的需求即可。下一章的最后我们会深入了解 webpack，包括优化构建结果、插件以及 Loader 的原理等等，想深入了解的可以关注那部分内容。

关于要完成的任务，之前已经介绍过 webpack 的概念，这里不再写简单 demo，直接说目标。我们可以用一张图来描述：使用一个 ES Modules 书写的入口文件，在里面导入 CSS，也可以导入第三方库来书写逻辑。另外不要忘记我们有一个设定好的模板文件 template.html，里面可能有 nunjucks 的占位符等一系列需要传入的变量。

我们希望经过 webpack 的处理得到这样的结果：最重要的是 page.html，也就是最后渲染的文件。它和 template.html 应该高度相似，只是多了两个静态文件的引用。这两个静态文件都从 index.js 打包而来，一个是 JS 文件 main.js，另一个是把 CSS 抽出来单独打包生成的 bundle.css。这是一步到位、非常自动化的过程。

这节课我们明确了要解决的问题，摒弃了最简单的直接拷贝方式，为了长远着想，需要 webpack 来协助，一劳永逸地解决这个问题。
