# 13-17-重构 Router：添加 Prefix 和简单的权限验证

上节课完成了上传图片的全部需求，并且把 egg 上传文件的全过程几乎从头到尾学了一遍。作为这部分最后的收尾，要给 upload 接口添加对应的权限。在这个过程中会发现一些问题，同时重构一些令人不悦的代码。

## 用 match 代替逐路由挂中间件

添加登录权限验证大家都熟悉，就是把 JWT middleware 添加到对应的 router 上去。但一直这样做，我们已经闻到了一些烂代码的味道。如果路由比较少（只有四五个），这种写法直截了当、非常明晰，很快能看出哪些接口需要权限。但路由一多，这样写就显得重复繁琐，需要重构。

这时可以借助 egg 文档里 Basic Middleware 的通用配置：特别注意最后有 match 和 ignore 两个选项，可以匹配中间件在哪些路由被调用。egg-jwt 作为插件也继承了这些配置选项。

配置项 enable 直接开启；要关注的是 match 和 ignore，它们支持的参数一样，作用正好相反：match 指哪些路由开启中间件，ignore 则相反，匹配到的不采用中间件。这个配置的源头来自 path-matching 这个库，它支持几种写法：string 类型（部分匹配）、正则表达式，还有 function（函数会拿到 ctx 对象，可以在上面操作属性和方法，返回布尔值）。它还支持数组，可以添加多种类型的判定规则。match 与它完全一致，只是作用相反。

有了基础就来做修改。打开 config.default.ts：首先修改之前忘记的一个地方，secret 作为隐私值要放到环境变量里（环境变量中已经创建好）。第二步把 enable 打开，意味着所有路由都要经过 JWT 校验；然后添加 match，希望它是一个数组。

匹配哪些项？把接口暂且分为三类。第一类是用户相关：其中只有 get user info 需要权限，作为第一项添加 `/api/users/:id`（get user info）。第二类是 works 类型，要匹配的非常多，只有 api/templates 和 templates/:id 不需要匹配，所以以 `/api/works` 开头的应该全要匹配。记得 string 是部分匹配的，直接添加 `/api/works` 这一项即可。第三项就是上传文件的接口路径，它需要权限。

添加完毕后，把 router 里各个路由上的 jwt 中间件删掉（删除的代码量比较大，直接替换）。现在它应该在所有路由都会作用，并且符合匹配规则。

测试：get user info 应该被保护，点击 Send，返回"登录校验失败"；upload 同样返回登录校验失败；login（/api/users/login）不需要权限，点击 Send，登录成功；再做一次带权限的校验，添加 Cookie 后请求，能返回对应的用户信息。说明修改没问题。

## router.prefix 统一前缀

重构了第一处，第二处不爽的地方是每个 API 的 URL 都要手写 `/api` 这个前缀字符串，重复繁琐，可以重构。这时求助 egg-router 的文档。egg-router 是为路由负责的中间件，是 egg 独创的，它 fork 了 koa-router，并在上面做了一些更高级的调整和 features。

我们要用它的一个实例方法：prefix。调用 `router.prefix('/api')` 之后，后面的路由会自动添加对应的前缀，不用每次手写。在哪里添加呢？在 router 创建之后、所有路由定义之前加上这一句，然后把后面每个路由里的 `/api` 都删掉（修改量比较大，直接复制替换）。

完成后简单测试：get user info 还是能生效（当然带权限校验），upload 也能生效，login 正常。说明没问题。

## 关于路由拆分

还可以针对路由进行分类：这一部分是 user 的路由，这一部分是 works 和 templates 的，这一部分是 upload。但文档 basic router 最后有一段描述：不建议把路由规则逻辑散落在多个地方，因为会给排查问题带来困难。如果确实有需求，可以按文档的方式拆分：创建一个 router 文件夹，把路由拆分到多个文件，然后在主 router 里调用。我更喜欢把 router 放在一起，和这个思想不谋而合，所以这里不做这个修改。

这节课完成了简单的收尾工作。最后想强调一个观念：重构是在项目的进行过程中不断迭代产生的，希望大家把这个观念深入到思想中去。做项目不应该想一口吃成个胖子、一开始就是最佳架构，架构是随着时间慢慢精进的。
