# 18-4-1-创建和删除渠道

之前的工作中，我们已经完成了一系列发布相关的异步请求任务，现在是时候显示发布成功以后的弹窗了。这个弹窗要显示页面和渠道的一系列信息，它算是编辑页面的一部分，但又是独立的弹窗，所以像 historyArea 一样，我们新建一个组件 PublishForm，作为子页面或子组件，用来显示发布成功以后的信息。

这个页面的第一部分没有什么太大难度，渲染页面的过程我就不手把手带着写了，代码已经写好，简单讲解一下。在 EditorView 中发布成功以后，把 showPublishForm 设置为 true，就会弹出对应的界面。界面左边显示封面图，从 page 的 coverImage 上拿到对应的信息。右边是 title 和 page 的 description 这两部分。分享图我们还没有做，在预览设置里暂时定死传了一张图片。

下面是比较关键的渠道列表。使用一个 a-row，配合 `v-for="channel in channels"` 进行循环。左边因为是二维码，之后再做；中间显示渠道名称，右侧暂时显示渠道的 ID，URL 后面再做。右侧还有一个删除渠道的按钮，点击后删除该渠道；复制功能以后再做，点一下会复制对应的 URL。最下面是一个表单，输入渠道名称，点击创建新渠道就会创建对应的渠道并添加到列表中。

页面只完成了展示，接下来重点实现创建和删除的逻辑。先做表单处理，现在还没有添加任何验证，正好复习一下 a-form 的用法。我添加了一个 a-form，layout 是 inline，表单会横向显示；a-input 的 placeholder 是渠道名称。

完成验证需要两个值：input 里的值和对应的 rules。先新建一个 reactive，值叫 channelName，初始为空。再建立一个 rules，规则很简单，就是不能为空：channelName 对应 required 等于 true，message 是「标题不能为空」，trigger 是 blur。有了这些之后，使用 useForm 拿到 validate 函数，传入 form 和 rules 两个参数。

接下来新建一个 createChannel 方法，它应该是 async 的。首先要准备创建时需要的数据 payload：第一个参数是 name，也就是 form.channelName；第二个是 workId，即当前作品的 ID，注意要 parseInt 转换。我已经把 currentWorkId 断言成了 string，所以这里不会报错。

然后是 try 块，第一步 `await validate()`，验证通过之后就可以创建了。创建的 action 之前已经写好，`store.dispatch('createChannel')`，把 payload 放进 data，这是我们的特殊格式：post 的数据放在 data 里面。最后一步把 form 的 channelName 置空，再加上 catch 里的 console.error，创建流程就完成了。

别忘了在 setup 中把 form 和 rules 返回出去，同时补上 a-input 的 `v-model:value`，绑定到 form.channelName。页面上试一下：blur 的时候会提示标题不能为空；键入值之后点击创建新渠道，可以成功创建一个新的渠道，它的 ID 是 101。

接下来是删除逻辑。删除的 action 还没有写，先到 editor.ts 中添加一个 deleteChannel，用 actionWrapper 包裹：第一个参数是 channelUrl，也就是 channel；然后是变量 id，mutationName 也是 deleteChannel，method 是 delete。

有了 action 之后，在 PublishForm 中建立一个 deleteChannel 函数，把 id 作为 number 传进去，`store.dispatch('deleteChannel')`，格式还是 urlParameters 传 id。另外还有一个状态：当只剩一个渠道时不允许删除。建立一个 computed，名为 deleteDisabled，当 channels.value.length 等于 1 时为 true。把这两个值返回出去。调用放在按钮上，click 时调用 deleteChannel 并传 `channel.id`，再给按钮加上 disabled 属性，直接把 deleteDisabled 传进去。

最后添加 mutation。editor.ts 里添加 mutation 时会遇到一个问题：现在只能拿到后端返回的数据，而这个数据中没有我们要删除的 ID。后端的返回是一个 errorNumber 为 0、data 为空的对象，没有 ID，我们不得而知具体删除的是哪个元素。

解决办法是把一开始传入的 payload 原封不动地传递到最后的 mutation 中，这样就可以从 url 或 data 中拿到有用的信息。所以要在 actionWrapper 中做修改：现在 commit 只提交 responseData，除了后端返回的 data，还需要把 payload 也包括进去。创建一个对象，先展开后面的内容，再把 payload 放进去。同时还要修改 ResponseData 的类型：editor.ts 中都拿的是 responseData，所以要把 payload 作为参数添加进去。

来到 ResponseTypes，把 payload 的类型引进来，它是 index 中的 ActionPayload，包括两项：url 参数和 post 的 data。在类型上多添加一个可选项 payload 即可。这样 mutation 中就可以拿到对应的值了。

回到 editor.ts 的 deleteChannel mutation。第一个参数 state 不变，第二个参数从 ResponseData 中不再取 data，而是取 payload。拿到的 payload 是可选的，所以要判断 payload 存在，并且 payload.urlParameters 也存在，然后取出 urlParameters，就能完成删除了。删除很简单，用 filter：`state.channels = state.channels.filter(channel => channel.id !== urlParameters.id)`。

测试一下：重新发布，现在有两个渠道，第一个是微信，第二个是默认。点击删除渠道，微信被成功删除，并且当只剩一个的时候按钮是 disabled 的，不可点。

至此表单、数据展示、创建渠道和删除渠道都完成了。接下来还有生成二维码的工作：input 中现在只显示了 ID，而最终要显示 URL，所以需要把 ID 拼接成对应的 URL，再把 URL 转换成二维码，下节课来完成。
