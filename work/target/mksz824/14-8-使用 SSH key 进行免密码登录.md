# 14-8-使用 SSH key 进行免密码登录

上节课完成了服务器最佳实践的初步配置，这节课作为一个可选修的内容，介绍不用密码的登录方式。

## 为什么密码登录不是好实践

密码是计算机诞生以来使用最多的认证方式，但它有时候是不好的实践，原因很简单：用户经常使用非常错误或者过于简单的密码。全球最常用的密码是 123456 和 abc123，黑客攻击时非常容易猜到。而且用户会在多个账户大量重复使用相同的密码，比如微博的密码可能和淘宝完全一样，黑客从别处盗取了你的密码，很可能在其他账户也能用。所以最好在不同的软件中使用不同的密码，这样才安全。

## SSH key 的原理

我们使用的 SSH 协议支持 key，也就是密钥的登录方式。key 采用经典的非对称加密技术：用工具创建一个公钥和一个私钥，公钥放置在任何云服务器中，本地保留私钥。登录时 SSH 协议会验证公钥和私钥的合法性，匹配时就可以免密码登录。

证书的私钥由 1024 位到 4096 位（128 到 512 个字符）的随机字符组成，这么长的字符串要比自己的密码安全多了，黑客想猜出来非常困难。最早使用 GitHub 时我们见过它的 SSH clone 方式，还需要在设置里添加公钥，和这里是异曲同工。

## 创建 SSH key

创建之前先验证是否已经有了：进入用户目录，看看是否有 .ssh 这个隐藏目录。进去之后 ls 一下，假如有 id_rsa 和 id_rsa.pub 这两个文件，说明之前创建过公钥和私钥，直接使用就好。

假如没有，就需要创建一次。Mac 下面内置了 ssh-keygen 工具：

```bash
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
```

-t 指定算法，这里使用 RSA；-b 是长度，取最长的 4096；-C 是用户标识，可以填一个邮箱地址。回车之后就可以创建了。

Windows 平台的同学可以使用 Putty 或者 Git 自带的工具，它们都能生成对应的 SSH key pair。

## 把公钥放到远程机器

第一步登录上节课配置好的机器：`ssh viking@<机器IP>`，输入密码进入。然后创建一个特殊的文件：

```bash
mkdir ~/.ssh
cd ~/.ssh
touch authorized_keys
vim authorized_keys
```

特别注意这个文件必须叫 authorized_keys，文件中的公钥会被当前主机设置为信任方。在本地编辑器打开 id_rsa.pub（公钥），把内容复制粘贴到 authorized_keys 里，保存。

保存完毕应该就生效了。退出后用 viking 用户重新登录，可以看到不需要密码就能成功登录服务器，功能完成。

## 可选：彻底关闭密码登录

还有一个可选功能：彻底关闭密码登录服务器。过程和上节课非常类似，先 `su` 切换成 root，编辑 /etc/ssh/sshd_config，搜索 password authentication 这个选项，它决定是否允许 password 登录。想禁用密码登录就把它改成 no，然后重启 service 就可以了。

通过这种方式只能使用 ssh key 登录，安全性更高。不过这个设置是可选的：如果你自己设置了足够强的密码，也可以不关闭密码登录，看个人喜好。

这节课我们就完成了服务器安全的第二个增强功能。
