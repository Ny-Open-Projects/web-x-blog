# 4-24-生命周期和模版引用

上节课了解了监听器，这节课讲另一个概念：生命周期。每个组件从初始化、挂载到 DOM 节点，到之后的更新和销毁，都要经历一套固定流程，有时我们需要在这些特定时机执行对应操作，所以 Vue3 提供了一系列生命周期钩子函数。

## 生命周期图

官网有一张生命周期图，不需要完全理解所有内容，先大体了解即可，为以后深入学习打基础。流程大致是：

1. 渲染开始，先执行 setup 中的逻辑，也就是我们一直在写的那些内容。
2. beforeCreate：创建之前。
3. 初始化 Options API。如果用过 Vue2 会很熟悉，就是选项式写法：data 属性放数据、computed 属性放计算属性等。
4. created：初始化完毕。之后的 pre compile template 等环节可以先不理会。
5. beforeMount：挂载之前。从这里开始初始化渲染器，创建并插入 DOM 节点。
6. mounted：挂载完毕，这是我们使用最多的钩子，此时组件的效果已经可见。
7. 之后组件会监听 setup 中的数据，数据变化时先触发 beforeUpdate，再 re render patch 更新 DOM，完毕后到 updated。
8. 销毁阶段：beforeUnmount 之后是 unmounted，整个流程结束。

## 钩子函数

针对这些阶段，Vue3 提供了一系列钩子函数，和图中红色节点一一对应，写法都是在生命周期名前加 on（图上没有 beforeCreate 和 created 的对应函数）。验证一下运行过程：

```typescript
import { onMounted, onUpdated } from 'vue';

onMounted(() => {
  console.log('mounted');
});

onUpdated(() => {
  console.log('updated');
});
```

刷新页面，mounted 出现在控制台；点击 increase 更新数据，updated 也出现了，两个钩子都成功运行。其中 mounted 用得最多，加载完毕后的操作，比如发送异步请求，一般都在这里做。

## 模板引用

接下来验证 DOM 节点是否已经存在。上节课我们用了一种笨拙的方式，直接调 document.getElementById。有没有更简单的方式？这就是新的知识点：模板引用（Template Refs）。

Vue 的渲染方式抽象了大部分对 DOM 的直接操作，但某些情况下仍需访问底层 DOM 元素，这时可以使用特殊的 ref 属性。在 setup 中创建一个 ref 并返回出去：

```typescript
const headline = ref(null);
```

然后在想访问的 DOM 节点上添加 ref 属性，值设为 headline。特别注意：模板上 ref 的名称必须和返回的变量名一一对应，这是定死的规则。

因为是 ref，访问值要用 `headline.value`。在 onMounted 里输出它，刷新页面后打印出了 h1 这个 DOM 节点，访问成功。

## 类型标注

只有在组件挂载以后才能访问模板引用。初次渲染时这个元素还不存在，验证一下：在 setup 中输出 headline.value，结果是 null；mounted 之后才有节点。这进一步验证了钩子函数的执行顺序。

所以为了安全使用，需要给它标注类型，否则直接访问 innerHTML 之类会报错，因为 TS 把它推断成了 null。给 ref 加上联合类型：

```typescript
const headline = ref<null | HTMLElement>(null);
```

访问属性时做一次判断：

```typescript
if (headline.value) {
  console.log(headline.value.innerHTML);
}
```

这就是前面多次说过的 type guard 类型收窄。或者用简写 `headline.value?.innerHTML`，问号和 if 判断最终达到同样的效果，选择喜欢的方式即可。保存后成功输出了 innerHTML，值为 8，没有问题。

## 小结

这节课讲了两个知识点。一是组件的生命周期，官网那张图很重要，要基本掌握；我们用 onMounted 和 onUpdated 做了验证。二是模板引用：在 DOM 节点上添加 ref 属性，并保证 ref 名称和返回的变量名相同，就能访问到最终的 DOM 节点。
