# 19-2-5-环境变量设置第二部分创建预发布环境变量文件

上节课介绍了 Vue CLI 中的环境变量文件：可以在程序根目录创建 .env 加 mode 的文件，以键值对的形式添加想要的环境变量，并且环境变量有优先级：cross-env 最高，.env 文件第二，运行时默认的 mode 第三。同时上节课留了一个疑问：在文件中定义的环境变量不是所有都能出现在最终打包生成的客户端代码中，比如 bar 打出来就是 undefined。这节课来看它的机制是怎样运作的。

## 编译与运行两个阶段

先明确从源代码到浏览器运行的过程，它有两个阶段：第一个阶段是编译阶段，使用 Webpack 将源代码编译成浏览器可以使用的 JS 代码；第二个阶段是浏览器运行，运行编译后的 JS 代码，展示出最终的应用。

在第一阶段中，所有环境变量都是可用的：.env 文件里定义的所有变量在 Webpack 配置中都能访问到。但到了浏览器运行阶段（也就是打包生成 JS 文件以后），只有特殊的环境变量可用，需要使用特殊的变量名称。客户端中可用的环境变量有三类：

1. 以 `VUE_APP_` 开头的变量，这是必须遵守的特殊格式，以这种格式开头的变量会被嵌入到客户端代码中，可以在应用代码里访问到；
2. NODE_ENV，表示当前使用的模式；
3. BASE_URL，部署时的基础路径，跟 Webpack 的配置有关，之后会了解。

上节课添加的 bar 不属于这三类，所以只能在编译阶段使用，客户端中没法使用。

## 变量是怎样嵌入客户端的

在源代码中搜寻一下答案。打开 DevTools 的 sources，选择 app.js，直接搜索 console.log，可以看到我们打的一系列 console.log。这里有一个很奇特的现象：源代码中打印的是 process.env 上的变量（NODE_ENV、VUE_APP_FOO），但真正生成的代码中，变量被我们定义的字符串直接代替了，变量本身被去掉。

这就是 Webpack 在构建过程中做的工作：任何这种环境变量，尤其是以 VUE_APP_ 开头的，都会被对应的值直接替换。所以打印 VUE_APP_FOO 时，自然会被赋的值 hello 所替代。

## 创建 staging 环境变量文件

搞清楚这个道理，就可以完成预发布环境 URL 修改的任务了。我创建了 .env.staging 文件：

```ini
NODE_ENV=production
VUE_APP_STAGING=staging
```

首先明确它的 NODE_ENV：staging 想使用 production 的生产环境编译过程，所以设置为 production。同时还需要一个另外的变量来鉴别是不是 staging 环境，注意必须用 VUE_APP_ 前缀（VUE_APP 后两个单词中间用下划线连接），后面加任意想要的名称，我这里称之为 STAGING，值设置为 staging。这样我们就创建了一个客户端中可以使用的变量。

有了这个变量，就可以在 main.ts 中处理了：

```ts
// use test backend URL when:
// 1. development
// 2. staging
if (process.env.NODE_ENV === 'development' || process.env.VUE_APP_STAGING) {
  baseURL = 'test backend url';
  baseURL2 = 'test h5 url';
} else {
  baseURL = 'prod backend url';
  baseURL2 = 'prod h5 url';
}
```

两种情况下使用测试环境的 URL：一是开发环境，二是 VUE_APP_STAGING 存在（特别注意只有 staging 模式下这个变量才存在）；其他情况下（即生产环境）使用正式的后端 URL。

## 添加 build:staging 命令

最后需要在 package.json 里添加一个命令。原有的 build 是为 production 构建的，我们再创建一个为 staging 构建的命令，称之为 build:staging：

```json
"build:staging": "vue-cli-service build --mode staging"
```

命令和 build 一样，但要指定一个特殊的 mode，用 vue-cli-service 接受的 `--mode` 参数，设置为 staging，和文件名后缀一致。

复盘一下整个流程：运行这个命令时，因为有 `--mode staging`，它会从 .env.staging 文件中拿到环境变量。首先 NODE_ENV 被设置为 production，会使用为生产环境打包的 Webpack 配置；然后 VUE_APP_STAGING 被嵌入到客户端代码中，main.ts 里获取到它之后就可以使用测试的 backend API，整个任务就完成了。

## 验证

运行 npm run build:staging，打包完毕后看源文件：在 app 加哈希的 js 里直接搜索测试后端的 API，代码出现在了这里，说明源代码中成功使用了测试地址的 URL，打包按预期工作了。

这节课进一步学习了 .env 文件的使用和环境变量的奥秘：怎样的变量会被植入客户端代码。理清这些规则后，我们成功完成了预发布环境 URL 的设置。
