# 4-34-Vue3.3 更新简介

这一节简单介绍一下 Vue3.3 的升级内容。3.3 不是一个特别大的版本，升级内容不算多，其中更好的类型支持占了一大块，而且没有 breaking change，3.2 和 3.3 完全兼容。官方博客列出了 3.3 发布的全部变化（由尤雨溪本人发布），喜欢看中文的同学可以找掘金的全文翻译版对照阅读。

新版本的代号叫浪客剑心，说明和日本漫画颇有渊源。官方提到它聚焦提升开发体验：最重要的改进就是 script setup 和 TypeScript 一起使用时的体验。这对我们是个重大利好，因为后面写的所有组件都是 script setup 语法糖配合 TS。代码录制时 3.3 还未推出，前期都用的 3.2；组件库代码写完后，最后一章会一起升级到 3.3 看看新体验。

升级 3.3 时官方推荐同时升级一系列依赖：vue-tsc、Vite、@vitejs/plugin-vue，课下使用时记得把这三个都更新。

## 支持外部类型导入

第一个也是最重要的特性：支持从外部导入类型。3.2 中 defineProps 和 defineEmits 只支持本文件内的局部类型，不能使用导入的类型。举例来说，MyProfile 组件声明属性和事件用的 interface 都写在组件文件里，这样都挤在一起不好管理，而且类型往往要在多个文件间复用。常规做法是新建一个 types.ts，把类型集中放进去再导入。

动手改一下：把 IPerson 和 IEvents 加上 export 移到 types.ts，组件里删除本地的两个 interface，直接 import 进来。看起来很美，但运行 npm run dev 会报错：defineProps must be a literal type。这个错误就是说不能从外部引入类型，只能在本文件中声明，比较繁琐。

怎么解决？早先录制的 3.2 版本中，我们其实用 Vue Macros 这个插件解决过。它包含一系列编译器宏（可以直接使用的 define 系函数）以及类型增强，类型增强正是解决 import 问题的。它的很多方案后来被直接吸收进 Vue3.3，为 3.3 做了很大贡献。

升级到 3.3 后这个问题迎刃而解，内部实现就是用的 Vue Macros。安装最新的 Vue 并更新三个依赖，完成后版本分别是：Vue 3.3.4、Vite 4.4.5、vue-tsc 1.8.5，@vitejs/plugin-vue 也完成升级。再次运行 npm run dev，之前的错误消失了，可以流畅地从外部引入类型文件，这对工程架构是极大的进步。

## defineEmits 类型写法

第二个改进也是 TS 相关：defineEmits。以前使用的类型参数是函数调用签名的写法，和 emit 返回类型匹配，但编写起来有点冗长。3.3 引入了更符合直觉的写法：key 是事件名，value 是事件参数的数组类型：

```typescript
const emit = defineEmits<{
  change: [id: number];
}>();
```

原来的函数调用签名语法仍然支持，喜欢原写法可以继续用。

## defineSlots

defineSlots 是一个新推出的宏，不需要导入就能使用，可以为 slots 设置类型。它只接受一个类型参数：key 是 slot 的名称（可以有多个具名 slot），value 是这个 slot 接收的 props 的类型。defineSlots 返回的 slots 对象和 useSlots 相同，借此获得更好的 TS 支持。

## defineOptions

defineOptions 是完全从 Vue Macros 引入的特性。以前要给组件设置 name 之类的选项属性，由于 setup 中没法直接做默认导出，只能写两个 script：一个普通 script 写 export default 和 name，另一个 script setup 写其他逻辑，非常繁琐。3.3 中直接在 setup 里写 defineOptions，把属性添加进去就可以了：

```typescript
defineOptions({
  name: 'MyProfile',
});
```

## 小结

3.3 的这些改进笔墨都落在 setup 语法结合 TS 的开发体验上，对我们非常有利，因为我们的组件从一开始就用 TS 和 setup 语法编写。想了解更多特性，可以阅读官方博客的英文版或中文版，看看还有没有自己喜欢的内容。
