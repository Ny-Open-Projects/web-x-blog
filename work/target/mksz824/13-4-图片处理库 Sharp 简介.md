# 13-4-图片处理库 Sharp 简介

上节课我们使用 egg 内置的 multipart 和 static 插件完成了图片的上传和展示。当 multipart 的 mode 设置为 file 时，它会自动把 HTTP request 中文件相关的数据读取出来并保存在特定的位置，我们修改了这个位置，保存在代码库的 uploads 文件夹中。然后使用 static 插件完成静态文件的展示，它原始只有 public 一个映射，我们给它添加了对应的路由，也就是上传完成的 uploads 文件夹。这样就完成了整个上传并展示的流程。

这节课需要完成一些简单的图片处理，这也是图片上传非常常见的需求。大多数后端应用都会对上传完毕的图片做一些简单的处理，最常见的缩放：没有人愿意给用户展示完全原始大小的图片，那是对资源和流量的极大浪费。拿知乎来举个例子，信息流左侧有一张文章相关的图片，查看图片的地址就会发现它是经过缩放的，从 URL 也能看出端倪：400x224。这样把图片缩放之后，就节省了整个流量。当然还可能有更高级的图片处理需求，比如旋转、裁剪、加水印等等。

我们这里完成一个简单的需求：对每个上传成功的图片都进行缩放，缩放成宽度 300 的图片，并且另存为一个新文件。所以第一个任务是选择一款趁手的工具。经过一系列调研，Node.js 处理图片最好的工具叫 sharp。看一下它的 GitHub 主页：首先它有 20.9k 个 star，用的人非常多，符合我们选择开源软件的第一个标准。然后再看它的 release，release 代表现在的开发是否活跃，有些老的库 star 很多但已经不维护了，通过 release 可以看到它现在的状态。我们会发现它 16 个小时之前还发布了新版本，更新非常频繁，符合开源库的第二个标准。

再来看它的特点。官方简介里说它支持多种图片格式，可以把图片转换成各种各样丰富的格式，都是常用的图片类型：JPEG、PNG、WebP 等等。如果你听说过别的图片处理工具，比如 ImageMagick 和 GraphicsMagick，那是我之前处理图片常用的两个库，sharp 底层基于的是 libvips，是一个新的处理库，处理速度比那两个工具快四到五倍，这是一个非常大的优势。

官网里还有一系列 API 的讲解。第一个操作是图片导出，也就是转换 to file，从这里可以看出它支持多种类型的图片，很符合我们的需求。第二个是我们要的主要需求：resizing images，对图片进行缩放。它可以基于 width、height 或者 width 乘 height 进行缩放，并且提供了多种模式，比如 cover、contain、fill。看这些参数其实就是 CSS background-size 对应的取值，如果你了解那个属性，对它们的含义就会更清楚。当然它还有 extend、extract、trim 等等更多功能。

还有一个 composite image，就是图片的组合：可以把多个图片组合在一起，拿一个 input 和一个 overlay，把两张图片组合生成一张组合图片。还有更多 image operations，基于图片的处理，比如旋转、flip、flop、sharpen（锐化）、blur（模糊）等等一系列操作。最后还有 color，也就是色彩的处理，可以转换成灰阶、转换色彩空间等等。你会发现它提供了这么多功能，都可以拿它做一个图片处理软件了，当然也符合我们最基本的简单需求。

我希望通过这次架构师的课程达到一个重要目的：给大家推荐一些非常优秀的开源库。希望大家以后遇到图片处理的时候，能想到有这么一个叫 sharp 的库，可以拿到的项目中安装使用。
