# 9-1-本章导学

欢迎来到新一周的学习。上一周我们在一个比较复杂的组件上花了非常多的精力，从零到一用各种有意思的开发方式完成了它的开发。这节课暂时离开编辑器的开发，来到另一个项目：业务组件库。目前我们的组件库是和主项目混在一起的，这不是完美的形态。业务组件库作为要为两个项目服务的公共组件，应该把它抽取出来发布至 npm，让两个项目共享。组件库打包有很多有意思的知识点，这周就一起学习。

先看最终的成果。第一个成果：一个发布至 npm 并且支持两种模块格式的组件库，也就是 OpsFlow 组件库。第二个成果：组件库连通了 Travis CI 这个工具，支持 CI CD，也就是自动运行测试，并且在特定 tag 提交的时候自动发布至 npm。

为了实现这个最终结果，我们要接触以下知识点。首先要学习 JavaScript 模块以及打包工具：模块从 AMD 进化到 CommonJS 再到 ES Modules 的历程；打包工具会对比介绍 Webpack 和 Rollup，最终选择 Rollup 使用。作为扩展知识，还会讲解另辟蹊径的打包工具 Snowpack。第二步的主要内容是创建业务组件库的代码：因为现在是混在一起的，我们要抽取出来单独做一个项目，之后开始打包。打包使用 Rollup，添加它的配置并完成打包，过程中会学习它的配置文件怎么写、插件怎么使用，还会分析它插件的简单原理。第三步是分析源代码这种经常使用的手段：分析 Element Plus 打包过程的代码实现。打包完成就可以发布到 npm 了，所以最后是发布到 npm 以及使用 Travis CI 完成 CI CD：包括 npm 的简介和它的 publish 过程，还有发布前如何验证代码质量、用什么工具来做，最终用 Travis 完成 CI 和 CD 两个流程。

看完主要内容，再来看看这一周的关键词。学完之后可以回到导学，看看这些关键词你是否有了新的理解。第一个是 module，模块。简单来说，模块是一段能以特定形式进行重用的代码，这里特指 JavaScript 模块。它有几种类型，分别是什么形式，学完以后你应该知道。第二个是 Bundler，打包工具。Bundler 是一些特殊的命令行工具，用来将多文件模块系统打包生成一系列符合浏览器兼容性的文件。这里会简介 Rollup、Webpack，以及一个比较另类的 Snowpack。第三个就是这周主要使用的工具 Rollup，Bundler 中的一个。接下来是打包后发布的过程，也就是 npm。npm 是我们的老朋友，要学习它的发布流程、发布前的验证，以及 npm script 的知识。最后是 CI CD，一个听起来很高大上的词汇，它代表持续集成、持续交付和部署几个概念。还有 Travis CI，一个支持 GitHub 实现 CI/CD 的在线工具，我们要用它实践上述两个概念。

学习方法跟之前一样：实践出真知。这周知识点比较多，涉及的工具也比较多，请大家一定要动起手来，只有实践以后才能加深理解、掌握这众多的知识点。导学就到这里，让我们开始本周的学习吧。谢谢大家，再见。
