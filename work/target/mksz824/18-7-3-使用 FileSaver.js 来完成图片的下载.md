# 18-7-3-使用 FileSaver.js 来完成图片的下载

前两节课了解了不同类型文件的下载方式和背后的原理，这节课照例用知名的第三方库来完成最终任务。这个库叫 FileSaver.js，有 16.6k 的 star，是客户端下载文件最常用的解决方案。说实话，这个库的代码本身不算惊艳，但文档写得非常好，详细解释了整个库的下载原理。我之前总结的下载文件通用实现方案，很大一部分就是阅读它的文档和源码得来的。

文档先讲了这个库的局限：它是基于 Blob 的方案，如果文件非常大，超过了 Blob 的大小限制，就无能为力。不同浏览器的 Blob 上限不一样，Firefox 是 800MB，Chrome 可以到 2GB。想下载超过上限的大文件，作者推荐改用 StreamSaver.js，它基于新的 Streams API 实现。

文档还提出了一个通用方案，借助服务器端实现：只要在任何文件的 HTTP 响应头里添加一个特殊的 header，也就是 `Content-Disposition`，并设置正确的值，浏览器打开这个 URL 时就会直接弹出下载，而不是在页面中打开。

`Content-Disposition` 的作用是指示响应内容以何种形式展示。第一种是 inline，内联形式，作为网页或页面的一部分直接展示，这是我们平时打开一张图直接显示的原因；另一种是 attachment，表示消息体应该下载并保存到本地，大多数浏览器会弹出"保存为"对话框。如果在后面添加 filename 值，它会预填为下载后的文件名。这就是服务器端支持下载的基本原理。阿里云 OSS 也支持设置这个响应头，需要用到的值都可以配置。当然，针对我们目前处理的图片并不需要这么做，这里只是让大家了解原理：以后如果服务器上的文件需要提供下载，加这样一个响应头就能轻松完成，不依赖任何 JavaScript。

下面正式使用 FileSaver.js。安装时注意要单独安装类型文件，`@types/filesaver`，用 saveDev 装到开发依赖里。装好后就可以使用它最重要的方法 saveAs，文档示例是 `import { saveAs } from 'file-saver'`。

把下载方法添加到现有方法列表的最下面并导出，命名为 downloadImage，参数是 string 类型的 URL。saveAs 接受两个参数：第一个是要下载的文件，可以是 string 或 Blob 类型；第二个是文件名 filename。URL 我们有现成的，文件名则要从 URL 里解析出来。我们项目里的文件 URL 都有固定规则，取最后一个斜杠后面的部分，比如 greenshot 加上对应的 `.png` 后缀，就是最终需要的文件名。

这是一个简单的字符串处理：用 `url.substring`，第一个参数是起始索引，用 `lastIndexOf('/')` 拿到最后一个斜杠的位置，再加一，让起点落到下一个字符，就能拿到完整的 filename。两个参数齐了，downloadImage 就完成了。

接着在 TemplateDetail 里替换：不用之前的 downloadFile，改用 downloadImage，参数直接传 template 的 coverImage。页面上点击下载图片海报，图片成功下载。

通过这节课我们掌握了 FileSaver.js 的用法，也理解了一个我认为比较重要的知识点：通过设置一个 HTTP 头，就能让服务器端完成下载。下节课我们来简单看一下 FileSaver.js 的源码实现，看看里面有什么有意思的地方。
