# 21-6-使用 Zod 添加服务器端验证

上节课在客户端完成了登录验证，这节课在服务器端做同样的任务。代码加在 login 的 post 接口处理里，也就是 `login.post.ts`。现在能通过 `readBody` 拿到请求的 object，按说可以直接套用相同方式处理，但 h3 提供了更方便的全局函数。

## readValidatedBody

之前用 `getQuery` 和 `readBody` 获取 query 和 body 的值，h3 在此之上还提供了两个一步到位的函数：`getValidatedQuery` 和 `readValidatedBody`，在获取的同时完成验证，可以和 Zod 很方便地配合。

依样画葫芦来开发，后面的旧代码先不管，一会儿删掉。核心写法：

```ts
const result = await readValidatedBody(event, (body) => {
  return userLoginSchema.safeParse(body)
})
```

`readValidatedBody` 接受两个参数：第一个是事件对象 event，第二个是一个函数，里面写验证方式，函数的参数就是校验的数值（箭头函数可以把括号省去）。先把 validator 目录里的 `userLoginSchema` 导过来，内部仍然用 `safeParse` 处理 body 数据，和客户端完全一致。

result 拿到后只需判断：`result.success` 为 false 时抛出错误。错误处理之前介绍过，直接 `throw createError`：

```ts
if (!result.success) {
  throw createError({
    statusCode: 403,
    statusMessage: '验证失败',
    data: result.error.format()
  })
}
```

验证失败一般用 403，`statusMessage` 填充错误信息。除此之外还要附加一段数据，告诉用户具体错在哪里，用 `data` 属性，值取 `result.error.format()`，拿到更好处理的格式。失败处理完成后，继续用假数据把 email 从 data 里取出来，把 currentUser 的名称设置为 email，后面逻辑保持不变，等真正用数据库登录后再修改，这里暂时是伪代码。

## 测试

试一下好不好用。可以用 Postman，也可以直接在 `login.vue` 里发异步请求测试。我们把客户端验证先注释掉，把 data 改成 async 方法，点击 login 时发送请求：

```ts
const res = await $fetch('/api/login', {
  method: 'post',
  body: { ...formData }
})
```

`$fetch` 会贴心地列出所有可选路由，选 login，method 用 post，body 里直接展开 formData。

到界面点 sign in，错误出现了：statusCode 是 403，data 里也显示出之前那种格式的错误详情，说明服务器端验证完全生效了。

## 抽象成全局函数

进一步的处理：验证是通用逻辑，注册接口很可能也要写这一套，所以可以抽象到一个全局函数里。我创建了 `runValidate`，放在 `server/utils` 下，这个目录下的文件会被自动注册成全局函数，不用导入就能直接使用。

先确定参数：第一个是各种不同的 schema，第二个是 event，这两个最重要；其余如 statusCode、statusMessage 想自定义可以自己加参数，这里先写简化版本。

这里有个关键问题：schema 参数要有一个通用类型，并且必须配合泛型，因为希望最终结果随传入的 schema 而不同，现在的 data 能自动推知 email 和 password 两种类型就是靠这个。Zod 文档专门有一节讲怎样和泛型配合，叫 writing generic functions：如果参数是 Zod 类型，用官方提供的 `ZodType` 类型配合泛型写即可：

```ts
import { ZodType } from 'zod'
import type { H3Event } from 'h3'

export function runValidate<T>(schema: ZodType<T>, event: H3Event) {
  const result = await readValidatedBody(event, (body) =>
    schema.safeParse(body)
  )
  // ...createError 失败处理
  return result
}
```

把 ZodType 类型从 zod 导入并加泛型 T，schema 参数类型写成 `ZodType<T>`；event 是 h3 中定义的事件对象，类型叫 `H3Event`，一并导入。然后把之前的具体逻辑搬进来，schema 替换掉写死的 userLoginSchema，最后把 result 返回，全局函数就写完了。

回到 `login.post.ts`，把原来那一段直接替换成 `runValidate(userLoginSchema, event)`，两个参数依次是 schema 和 event。再次点击测试，错误照样弹出来且内容与之前一致，重构成功。

小结一下这节课的两个要点：服务器端验证和客户端逻辑完全一样，唯一区别是 h3 提供了预设好的全局函数，让获取与验证一步完成；Zod 类型和泛型的配合方式，文档里有详细记载。这节课就到这里。
