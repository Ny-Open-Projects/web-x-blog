# 17-2-2-分析后端接口和需求

上节课介绍了前后端分离开发，以及使用和调试 API 不可或缺的两类工具。这节课对项目使用的接口，对照项目需求做一个简单分析。

先做准备工作：在上节课提供的文档中下载 Postman 接口文件并导入 Postman；如果上一阶段已经跟着完成了后端接口开发，也可以对着自己的接口测试。本节课先分析与编辑器相关的接口，借助已完成的成品网站来描述需求。

## 两类接口

编辑器页面是有权限需求的：只有登录用户才能进入特定路由（比如 editor），才能调用特定接口做操作，所以要先登录或注册。我把接口分为两大类：

1. 需要特殊权限才能访问的，比如编辑器中的各种操作；
2. 无需权限即可直接访问的，比如获取热门海报。

以「获取公共模板」为例：请求地址是测试后端（大家都可以用，注意 IP 和端口），路径是 `api/templates`，后面跟一系列分页参数（不加也可以）。它是 GET 请求，不需要任何特殊的 header 和 body，点击 Send 就能拿到数据，热门海报的展示不需要任何权限。

## 登录与 token

问题来了：怎么获取权限？来到「用户」分类，它有三个接口。我们用手机号加验证码的方式登录。

**第一步：获取验证码。** 「获取短信验证码」是 POST 请求，后缀 `user/generateVerifyCode`。特别注意要添加 header：`content-type: application/json`。Postman 里 Body 面板的 raw 和类型选择是联动的，点 JSON 就自动加了这条 header。后来发请求时也要记得 header 必须加。body 传一个 `phoneNumber` 参数（你的手机号），点 Send 会返回一个 code，比如 7315，这就是发到手机上的验证码。

**第二步：登录。** 「登录」接口叫 `loginByPhoneNumber`，两个参数：`phoneNumber` 和刚才拿到的 `verifyCode`，body 依然是 JSON 类型。点击 Send 后返回一大堆数据，其中就有一个 token，上一阶段讲过，权限验证用的是 JSON Web Token，这就是它的一部分。把它保存下来，非常重要。

**使用 token。** 用它可以访问需要权限的接口，比如「获取当前用户信息」（`getUsers/getUserInfo`）。它是 GET 请求，token 要加到 header 上：新建一个 key 叫 `authorization`（授权的意思），value 必须写成 `Bearer` 加空格加你生成的 token。点击 Send 就能拿到对应的用户信息。记住这个格式：authorization header + `Bearer <token>`，就能访问需要权限的接口。

## 编辑器核心接口

有了权限，就可以访问编辑器相关的接口了。

**创建空白作品**：POST 请求。header 里的 authorization 换成新生成的 token，body 里传：

- `title`：作品名称；
- `description`：作品简介；
- `content`：这是有意思的地方，里面的 `components` 对应编辑器里一系列元素的信息，正好就是 vuex store 里渲染画布的那个 components 数组，可以把它塞进去；`props` 对应 `pageData`，一般保存页面整体的 CSS 设置，比如背景颜色、是否重复、高度等；
- `settings`：一系列与页面相关的设置，我们目前还没遇到，遇到了再讲。

点击 Send，创建成功，返回一系列信息，注意其中有一个 `id`，是作品独一无二的标识符，还有 title、description、author 等。

**查询单个作品**：创建完毕想渲染出界面，就要用 id 查询。header 记得填上 authorization，id 填入路径（比如 213），Send 之后能拿到作品的一系列详细信息，content 里的 components、props，以及创建时的 settings 都在这里。

**保存（修改作品信息）**：渲染出画布后还有保存、发布、预览设置几件事。保存对应「修改作品信息」，是 PATCH 请求，body 里传和 POST 创建时一样的作品信息（title、description、content 等一一对应），header 加上 content-type 和 authorization。点击 Send 后什么都没返回，说明保存成功了。

**发布**：把编辑的临时状态变成可供外界访问的公共状态，海报编辑好了就可以发布。发布接口叫 `works/publish`，在路径上添加对应的 id（213），同时更新 authorization，点击 Send 就完成发布。响应时间会稍长，因为中间加了一个审核功能；成功后会生成一个封面图。后面还有创建渠道之类的更多请求和操作，这里暂不讨论。

**预览和设置**：它没有对应的接口，其实是嵌入了一个 iframe，后端直接提供写好的地址，把它嵌进来即可，同时里面也有一些保存、发布等快捷操作。

## 小结

现在我们捋清了对应的接口：特别注意有两类不同的接口，需要权限的和无需权限的；并且把接口和应用中的需求做了对应的分析（登录、创建作品、查询、保存、发布、预览）。有了这些前提，接下来就可以完成接入后端的工作了。
