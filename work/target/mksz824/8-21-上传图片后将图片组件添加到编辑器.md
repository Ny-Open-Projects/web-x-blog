# 8-21-上传图片后将图片组件添加到编辑器

上节课把写好的 uploader 组件添加到了左侧组件列表中，可以完成上传图片的功能。现在要完成的是：上传完毕以后，把图片组件显示在中间的编辑器中。大家对这个过程应该很熟悉了，这里复习一遍。上传图片的接口到时候会提供给大家使用，接口地址写在文档中。

代码我已经写好了，过程比较简单，采用过一遍代码的方式讲解，并提一些经验教训。

## LImage 组件与通用化 mutation

要展示图片组件，自然要新建一个 LImage 组件。它和 LText 很类似，但要注意创建 Image 专属的属性和类型。之前分析过：图片组件只有一个专属属性 src，即图片要展示的 URL 地址；其他都是 common defaultProps。默认属性和样式属性可以和 text 的一一对应。

有了业务组件，来到 components-list（上节课改的地方），要做的就是在 onImageUploaded 的时候新建一个组件的数据，并使用 onItemClick 发射出去。

注意，我修改了 editor 中 mutation 的参数：addComponent 原来的参数是和 TextComponentProps 强绑定的，但我们现在的场景更广阔，不仅有 text 类型的 component，还有 image 类型的 component。所以要推翻之前的错误，把强绑定去掉，直接传一个 ComponentData 就完了。在外面传 component 时也要提供更丰富的数据，它的应用范围更广了。同时不要忘记更新测试，因为测试中传的数据还是旧的 props。

## 一个不爽的地方：commit 的类型

对 Vuex 我有一点很不爽的地方。在 editor.vue 中调用 store.commit('addComponent') 时，mutation 中设定的参数类型没法通过 commit 映射过去。比如这里我希望 component 是 ComponentData 类型，但 payload 实际上可以是任何类型，这就丧失了类型检查的重要作用。由于它的这个局限，我们只能暂时这样。

## 完整的处理流程

现在处理最终的结果，也就是 onImageUploaded 的地方。首先看到 response 为 any 就很不爽，要给上传返回的数据添加对应的类型。这里我认为很重要：不要怕麻烦，类型总有一天会帮助到你。

先观察上传完毕的返回结构：点击上传图片随便上传一张，可以看到 code 为 0，data 里有一系列数据，message 是请求成功。据此创建一个类型。如果找不到很好的地方存放这些类型，可以建一个 types.d.ts（extra type）文件，存放这些和任何其他文件没有强关联的类型。我把这个类型定义为 UploadResponse，即应用中上传数据后 HTTP 返回的数据。

有了它，就可以创建最终的 ComponentData（与 onItemClick 一致）：name 是 l-image；id 用 uuid v4 创建；props 使用展开的 imageDefaultProps，即 image 默认的 props。

上传成功后添加一个提示，使用 we-design 里面添加的 message 方法（success）提示上传成功。然后替换 props：由于我在 props 上做了交叉类型，TextComponentProps 和 ImageComponentProps 上的属性都可以取出来，所以 data.props.src 也是可以出来的，让它等于 `response.data.url`，刚才设定的类型在这里起到帮助了，两者都是 string 类型，可以相等。至此 componentData 建立完毕，所有属性齐全，可以发射出去了。

发射用的还是 context.emit('on-item-click')，其实这个名称不太语义化，应该叫 onItemCreated 之类的，大家课下可以换一下。发射出去的是 componentData。

## 验证与遗留问题

测试一下：点击上传图片，图片就创建成功了。

但现在有一点很烦人：图片的大小是固定的，因为默认宽度设置的是 318px，和中间编辑器的宽度一样。这不符合常见的需求，上传完毕后图片大小应该动态变化，然后设定一个最大值，框定在编辑器里。下节课看看怎样完成图片大小的功能。这节课到这里，谢谢大家。
