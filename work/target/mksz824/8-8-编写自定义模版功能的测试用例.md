# 8-8-编写自定义模版功能的测试用例

上节课我们添加了列表，留的作业是美化整个列表，我已经自行完成了：使用 Ant Design Vue 提供的图标做了一些美化，用到了 delete、loading 和 file-outline 三个图标，并添加了自定义样式。

特别注意，添加这些图标后它们属于第三方组件，所以在测试中要稍作修改：我用了 stubs 来模拟它们的实现。还记得之前我们用的是 components 属性吗？它们的区别是：components 是全局注册的组件，而 stubs 是在组件中注册的组件。这三个图标在 uploader 中属于组件内注册的 components（从 Ant Design Vue 导入），所以用 stubs 模拟。

回顾完毕，看一下下一步需求。

## 三个阶段的自定义

下一步要支持自定义模板，这是非常有用的特性。对上传组件来说，可定制化非常重要。假设组件有一个新任务：胜任上传头像的场景。这就需要支持三个阶段的自定义：刚开始还没有上传时，显示一个头像样式的点击上传；上传中需要支持加载中的样式；上传成功后的样式。

特别要注意上传成功之后还需要根据数据自定义：我们很可能把服务器返回的数据传给模板，让它根据数据进行自定义展示，展示一张图片也好，一行文字也好，都可以。

解决方案肯定是 slot 了，所以需要三个 named slot 来完成任务。

仍然采用 TDD 的开发方式，这种方式不需要界面，让我感觉非常方便快捷，甚至有点停不下来的感觉。

## 在测试中传入 slot

这节课面临一个新知识点：单元测试中怎样给组件添加 slot。由于这个 case 需要给测试组件传入不同的属性，为了不和之前的两个用例冲突，单独开一个用例，已经添加到最后了，名称是 "show the correct interface when using custom slot"，并打开 only。

首先创建新的 wrapper：mount uploader，props 与原来一样（action 为 test url）。不一样的部分是使用 slots 属性添加不同的 slot 模板。三个 slot 分别是：

- default：默认状态，直接放一个 custom-button，里面文字改成对应内容。
- loading：加载时的第二个阶段，加一个独特的 class，文字设为 custom-loading。
- uploaded：上传完毕后的第三个阶段，有点特别，因为需要根据服务器返回的数据来渲染 slot，所以要用到 scoped slot。

scoped slot 在文档中有一节专门讲写法。它的 template 需要在外层再用 template 包裹，传递过来的变量通过 scoped slot 的写法接收，名称设置为 uploadedData。说实话，scoped slot 在 template 中的写法有点绕，我每次使用都可能要查文档。它可以使用解构的方法：用一个花括号把里面的变量包裹起来。所以这里写成 `#uploaded="{ uploadedData }"`，内部渲染想要的内容。

接下来模拟 post 的返回值：mockedAxios.post 用 mockResolvedValueOnce，外层包裹一个 data，里面放一个测试用的 URL（dummy url）。

然后就可以写断言验证内容了。首先断言默认情况下 button 里的文字是 custom button。

由于是新组件，触发上传还需要设置 files 值。为了避免写重复的逻辑，我创建一个函数 setInputValue 来完成这个任务，放到最上面，替换之前设置 files 的重复代码。之后 `await wrapper.get('input').trigger('change')`。

此时应该是 custom-loading 在起作用：拿到 loading 区域的 text，断言等于 custom loading。然后 `await flushPromises()` 让 promise 结束。

最后测试自定义内容：因为有服务器返回的数据，custom-loaded 里面的内容应该等于 dummy url。断言加上后，测试用例看起来就写完了，三种情况都包含：初始化、loading、完毕后显示服务器返回的数据。
