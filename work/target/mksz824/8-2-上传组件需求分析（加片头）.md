# 8-2-上传组件需求分析（加片头）

## 为什么需要上传组件

上一周我们大规模接触了测试的知识，但只用测试开发了一个 ColorPicker 组件，对测试来说太单薄了。我们急需一个比较复杂的组件来体现测试的优势和标准流程。另外，现在的 Web 框架都是组件的世界，Vue 和 React 都是如此，而我们大多数时间都在使用 Ant Design Vue 提供好的现成组件，缺少开发复杂组件的经验。既然做的是架构式课程，从零开发一个复杂的通用组件是必须有的经验和过程。

从业务上看，业务组件中已经有了 LText 这样的组件，接下来自然会有图片上传，也就是 LImage 组件。LImage 这种纯展示组件跟 LText 非常相似，本身不难，但它带来了一个难点：上传文件。要展示图片组件，首先要经过上传过程；要编辑业务组件的 src 属性，也可能需要重新上传。而上传组件本身是一个流程化、有一定难度的通用组件。看看 Ant Design Vue 和 Element Plus 的 Demo 就会发现，它有非常多的属性、方法和生命周期。而且上传组件的开发是非常渐进式的，不是一堆零散的特性，而是整块的内容，非常适合用测试来驱动开发，正好是实践上节课测试知识的道场。

这一周我使用一个有趣的情景开发模式：模拟公司中的一个程序员，老大要求给公司组件库开发一个通用上传组件，为期一周。接下来我就演示整个开发过程。

## 上传文件的基本形态

首先要弄清楚上传组件究竟是什么。上传文件是 Web 应用里最基本的需求。在 Ajax 出现之前，我们一般使用传统的 form：一个简单的 input 框，把 type 设置成 file，就可以选择文件；点击提交后交给后端处理，流程就完成了。这种方式现在也仍然存在。

有了 Ajax 之后，JS 有了异步发送请求的能力，我们就可以在不跳转页面的情况下完成文件上传，同时获得很好的可视化效果，比如上传百分比、图片预览、最终状态等一系列信息。演示里点击 Click Upload 选择一张图片后，页面会显示一系列信息，最后告诉你上传成功或失败，比传统方式直观得多。

## 需求清单

看完演示就可以开始需求分析，通过刚才的场景或头脑风暴得出上传组件的需求。在 TDD 中我们也讲过，大块的任务可以拆解成一系列 To Do List，然后用测试驱动开发把完成的任务一项项划掉。这样做的好处是工作目标非常清晰：明确工期、明确待办事项、明确难点，并且可以在持续细微的反馈中有意识地做调整，比如添加新任务、删除冗余的测试。它还能让程序员更有掌控感，随着任务被划掉，可以大致知道什么时候完工，对开发进度有更精确的把控。

根据演示和组件的使用场景，我列出了这些需求：

- 基本的上传流程：点击按钮选择文件，完成上传。
- 上传文件列表：列表项可以显示文件名称和上传状态（成功与否），文件可以删除，上传时显示进度。更丰富的显示支持（比如把列表形式变成图片列表）先打个问号，可能放到最后完成。
- 自定义模板：可以把默认的上传按钮自定义成任何样式，上传完毕后也可以改变展示的内容。比如上传头像后直接显示头像，这是很实用的模板自定义。
- 生命周期钩子函数：上传是非常讲究生命周期的过程，所以要定义一系列钩子函数，告诉用户现在处于哪个阶段，想监听某个过程就在对应函数上操作。一开始是 before-upload，在开始之前能拿到要上传的 file 信息，做文件类型、文件大小等判断；然后是 on-progress 对应上传过程；之后是 on-success（成功）和 on-error（失败）；还有 on-change，在状态发生变化（无论成功或失败）时做通用操作。
- 拖拽上传：这也是非常常用的需求，我自己在 Web 上也经常使用拖拽上传。

还有等等一系列需求，这里先不写，等开发完了再 review，看看有没有新的需求可以加进去。
