# 20-22-存储层 第二部分

上节课学习了 storage layer 的基本用法，这节课给它添加一个驱动，使用我们熟知的 Redis 来进行数据操作。

Unstorage 这个库的设计很巧妙：它的宗旨是让千变万化的数据储存工具都用同一套 API 操作，用户只需配置不同的驱动。它已经适配了非常多的工具，这种设计思路很超前，我很喜欢。文档里有 Redis 的具体用法。

开始配置前，确保本地 Redis 已经启动：输入 `redis-cli`，可以看到它已经在 6379 端口启动了。

然后在 Nuxt config.ts 中添加配置选项。新添加一个属性 `nitro`，它下面还有一个属性 `storage`，在 storage 里新添加一项 redis（这里没有自动提示，注意不要打错）：

```ts
nitro: {
  storage: {
    redis: {
      driver: 'redis',
      port: 6379,
      host: '127.0.0.1',
      password: '',
      db: 0,
    },
  },
},
```

具体属性可以参考文档，它底层使用的是 ioredis，就是我们之前用过的很出名的第三方 Redis 操作库。第一个属性 driver，告诉它使用 redis 这个 driver，这是 Unstorage 提供的一系列 driver 之一，安装了这个库这些 driver 都是内置的，不需要额外安装其他库。第二个是 port，即刚才看到的 6379。然后是 host，本地就是 localhost（127.0.0.1）。password 本地没有设置，留空即可。最后还有 db，可以设置多个 db，默认就是 0，不加也可以。这样就把额外的 storage 的 redis 实例添加好了。

现在验证。useStorage 有一个参数，和配置里的名称一一对应，所以传入 redis：

```ts
await useStorage('redis').setItem('current-user', body.name)
```

现在数据就保存在 Redis 里了。setItem 还可以接收第三个参数 options，它是一个 object，把各驱动的参数统一化。比如 Redis 有自动过期的机制，对应参数叫 ttl，单位是秒。设置为 20，表示这个值在二十秒后会过期。

保存后把 auth handler 里取值的部分也改成 useStorage('redis')。这里还可以尝试一个新 API：getItem 是直接取值，我们只需要验证里面是否有值，所以改成 hasItem，泛型也删掉，直接判断即可。

看看使用 Redis 的版本能否成功运行。刷新页面，点击 login，应该会在 Redis 中设置数据并带有 20 秒过期。login 成功后访问被保护的 API users/1，可以看到可以正常返回。到 redis-cli 里执行 `get current-user`，也有值，没问题。等几秒过了二十秒，重新刷新，返回 401，说明值已过期被删除了。

这样我们就配置完了 Redis。建议大家课后根据文档再尝试其他工具的驱动，都不需要额外安装，直接包含在 Unstorage 中，可以感受它们使用起来有多方便。

最后补充一点：Nuxt 3 的很多依赖，比如 Nitro、Unstorage、ofetch（$fetch 背后的库），都来自同一个来源 UnJS。UnJS 是一系列高质量的、单一目的（Single Purpose）的库。使用它们不仅体验好，我认为用来学习也很棒。比如我们重度使用的 Unstorage，做了一个统一化的 Key Value 存储接口，可以接这么多 driver，用完全统一的 API 操作不同的工具，好用也好记。它的源代码非常值得学习：从设计思想到代码架构，再到代码的友好程度，都很舒服，容易看懂，比直接看 Vue 或 React 源码有帮助多了。点开 src 可以看到每个 driver 都有一个单独的文件，设计非常清楚。

这节课用 Unstorage 成功配置了 Redis，希望大家课后尝试一下其他工具。
