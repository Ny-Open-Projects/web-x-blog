# 21-21-表格编码第三部分 完成排序功能

上节课完成了分页，这节课完成数据排序。按特定字段排序是非常常见的功能，我们的期望是通过"创建于"和"更新于"两个字段排序。由于有多页数据，每次点击排序都要按特定条件重新发一遍异步请求，而不是仅靠前端排序：前端排序只能给最前面的十条排序，不能胜任这种需求。所以这里不仅有前端工作，也有后端工作。

## 前端：开启 sortable

给表格添加排序很简单，Nuxt UI 提供了类似功能：在 column 的一系列属性里有一个管排序的 `sortable`，设为 true 就完成了前端默认排序。给 `createdAt` 和 `updatedAt` 两个字段都添加 sortable: true。

保存后"创建于"和"更新于"都出现了排序图标，点击有默认效果：它会完成排序。但这不是我们最终想要的结果，因为这只是针对已有的十条记录，通过 JS 在前端排序；我们需要的是根据后端请求重新发送排序请求。

## 前端：默认排序与 v-model:sort

先添加初始的默认排序：希望默认按"创建于"倒序，最新条目在前面，老的在后面。UTable 提供了 default sorting 功能：添加一个 sort 响应式对象，里面两个属性：column 是用哪个字段排序，direction 是排序方向（asc 正序，desc 倒序）：

```ts
const sort = ref({
  column: 'createdAt' as const,
  direction: 'desc' as const
})
```

把 sort 传到 UTable 上，属性叫 `v-model:sort`。这样当我们点击排序时，这个响应式对象就会随之修改。再添加一个 pre 标签把 sort 输出来看看：传了默认排序后，箭头获得了默认样式，使用"创建于"倒序，最新在最前；点击列头时，column 会变成 updatedAt，再点一下 direction 会翻转。前端这部分的工作完成了。

## 后端：query 参数与 sort

接下来在后端添加对应字段。排序信息肯定是通过 query 传递的，在 query object 上添加两个和排序相关的参数：第一个叫 `orderBy`，即通过哪个字段排序，默认值 createdAt；第二个是排序方法 `order`，默认 desc。这两个字段和前端是一一对应的。

MongoDB 支持排序，使用一个 object：key 是要排序的字段，值是排序方法，命名和前端完全一致。比如用 createdAt 倒序：

```ts
const customSort = { [orderBy as string]: order }
```

key 要传递变量，用方括号包裹 orderBy；orderBy 类型很多，做 `as string` 类型断言就没问题了。

有了 customSort 后链式调用 `sort()` 传进去。同时 limit 也要补上：之前没加，这里把 pageSize 传进来（每页多少条）。此时会发现一个类型错误：sort 期望一种特殊类型，叫 SortOrder，从 mongoose 中定义。所以要从 mongoose 导入这个类型，对 order 做类型断言：

```ts
import type { SortOrder } from 'mongoose'

.sort({ [orderBy as string]: order as SortOrder })
```

错误消失，后端代码开发完毕。

## 手动排序 + 自动重请求

接下来把前后端结合起来。在表格上开启手动排序：UTable 有个参数叫 `sort-mode`，设为 manual。保存后点击列头不会再有任何前端更新，因为我们进行了完全接管。

然后使用 useFetch data fetching 上的 watch 功能完成点击后的重新请求。sort 已经是响应式对象了，添加进去非常方便，把两个参数按之前一样拼进 URL：`orderBy` 等于 sort 的 column，`order` 等于 direction。值改变时会自动重新发送请求。

保存测试：点击"创建于"，新请求发送了，参数 orderBy 是 createdAt、order 是 asc，传递正确，返回的数据也没问题，第一条明显更早；再点击一次，发送新请求，最新数据放在了前面；"更新于"同样没问题。

## 重构：query 参数写法

最后做一点小的修正。随着参数越来越多，URL 变得越来越长，不太美观。computed URL 其实有两种写法：一种是我们采用的回调函数拼 URL 的写法；另一种是直接传 URL 字符串、在后面添加 `query` 参数的写法，参数多的时候更明晰。现在参数变多了，自然要改成后者。

特别注意：query 里对应的是响应式对象本身。把后面的参数全删掉，第一个参数改回普通字符串，回调函数不需要了，然后添加 query 参数，把之前的参数复制过去。

保存测试：分页没问题；但点击排序时没有任何变化。其实 v-model 绑定的响应式对象已经改变了，为什么？仔细看：query 里需要的是响应式对象，而我们直接 `sort.value.column` 取出来的是值，不再是响应式对象，所以不会触发任何效果。

修改方法：针对这种值，包一层 computed 让它变成 computed value：

```ts
const orderBy = computed(() => sort.value.column)
const order = computed(() => sort.value.direction)
```

query 里传 `orderBy` 和 `order` 两个 computed。direction 同样修改。

彻底刷新后验证：初始请求没问题；分页没问题；点击"创建于"成功发送对应请求，"更新于"也没问题，发送的数据都是正确的。

这节课完成了排序功能，并针对更长的 URL 使用了新的书写方式，看起来明晰多了。到这里。
