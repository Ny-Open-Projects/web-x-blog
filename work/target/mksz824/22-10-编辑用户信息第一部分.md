# 22-10-编辑用户信息第一部分

这节课来添加编辑功能。编辑是在创建的基础上发展而来的，两者非常类似，不同的点有三处：一是路由上的参数，编辑有一个 userId，创建没有具体的 userId；二是编辑一开始需要数据获取，额外发送一次请求拿到当前用户的数据并完成赋值；三是点击提交后发送的请求不同，创建发送 POST 请求，编辑发送到 user edit 的 PATCH 请求。

针对这几个不同点，我们要用同一个页面完成创建和编辑两个功能。任务看起来不难，一起来看看怎样完成。

## 路由参数与创建模式判断

首先获取路由参数。我们希望新建使用一个固定的路由叫 create，其他编辑路由都带一个 ID。用 `useRoute` 拿到路由信息，取路由参数里的 userId。什么情况下是 create、什么情况下是编辑？创建一个变量 `isCreatingMode`：当 userId 等于定死的 create 时就是创建模式：

```ts
const route = useRoute()
const userId = route.params.id
const isCreatingMode = userId === 'create'
```

有了它以后，添加一个新按钮，点击导航到对应路由完成创建：目标就是 `/users/create`，其余情况都是编辑。再加一个 flex 加 `justify-between` 排列。回到用户管理页：点击新按钮进入 create 路由；点击其他条目进入的是带 ID 的编辑路由，这样就能区分当前要做什么操作。

## 后端获取用户数据

接下来发送请求，先把后端写一下，很简单：之前写的是假数据，现在改成真的查数据库。把假数据删掉，获取 ID 的部分之前已经做了。要做的就是查询数据库获取 userData 并返回：在 UserSchema 上直接调用 `findById`，把 ID 传进去，最终返回数据。

注意要调用 `toJSON()`，把没用的字段过滤掉，尤其是 password 也要过滤掉：即使是管理员，也不应该随便看到或修改用户的密码。

## 前端发送请求

接口加完后回到 `[id].vue` 页面判断。第一种写法很简单：假如不是 creatingMode，就发送请求，直接用 useFetch：

```ts
const { data } = await useFetch<UserDataProps>(`/api/users/${userId}`, {
  pick: ['username', 'nickname', 'email', 'type']
})
```

路由是 api/users 加上 ID，用 userId 替换。请求参数里有个 `pick`，可以只返回具体的值，把想要的相关信息都返回，其他不需要。

用 pick 后会出现一些类型错误，可以给 useFetch 添加泛型把具体类型加上，字段存在泛型上就不会报错了。泛型值从 server 的 model 拿过来：`import type { UserDataProps } from '~/server/models/user'`。添加后错误消失。

拿到 data 后就是赋值，上节课讲过，直接调用 `Object.assign`：初始值是 userData.value，后面的值是 data.value。测试：数据出现了；刷新页面也能按预期获取；从路由点第一条记录过来，也发送请求并取得值。

## 延迟发送请求的新玩法

观察请求发送的时机：点击后是在路由跳转之前发送请求，然后直接渲染上去；直接刷新页面则是 SSR 的玩法，请求不是在客户端发送的，而是直接在服务器端完成并赋值。

这里我想玩点不一样的，同时讲一个新知识点：一种适用于延迟发送请求场景的发送方式。我们希望请求在 mounted 以后再发送。useFetch 有一系列参数，其中 `immediate` 控制发送请求的时机，设为 false 后请求不会立刻发送。这时可以把请求挪到外面，把原始那行注释掉：虽然写了这行代码，但请求不会发送，而是可以在预定时机发送。

useFetch 还返回另一个函数 `execute`，调用它就真正把请求发送出去。我们希望在组件 mounted 的时候发送，这就是标准 SPA 的请求形式。当然加条件：不是 creatingMode 才调用 execute。这种方式不仅在 onMounted，任何延迟发送请求的场合都可以使用，是一个比较有趣的数据请求发送方式。

```ts
const { data, execute } = await useFetch(..., { immediate: false })

onMounted(() => {
  if (!isCreatingMode.value) execute()
})

watch(data, (newData) => {
  if (newData) Object.assign(userData.value, newData)
})
```

赋值不能直接像之前那样写，要使用 watch：watch data 的值变化，变化之后再赋值，先判断 newData 存在，再用 Object.assign 完成最终赋值。保存测试：一开始值是空的，等组件 mounted 以后才发送请求，最终把值填充上；到另一个路由看，也是先空，短暂延迟后值填充上去，表单获得了对应的值。

## 两种方式对比

两种方式都能完成任务，第一种更简单，但两者理念完全不同。这节课的关键是学会另类的请求发送方式：immediate 设为 false，返回一个 execute，在特殊的时间点调用 execute 把请求发送出去。这种方式适合需要延迟发送请求的场景，请大家掌握。大家完全可以按自己的喜好选择喜欢的解决方式使用。

这节课的任务到这里就完成了：可以根据不同的参数使用编辑或创建对应的功能。
