# 22-15-完成部署脚本

上节课完成了构建，这节课来做部署。在之前的架构师课程 OpsFlow 后端部署过程中，已经介绍了非常多的部署方式：传统方式部署、使用 docker 和 docker compose 部署，还有 GitHub Actions 用 CI/CD 进行部署。

这里从最简单的开始，用脚本直接上传的方式来完成部署。如果想采用 Docker 结合 CI/CD 的方式也完全可行，之前章节已经讲得很详细，这里就不再展开。我们返璞归真，采用最简单也最直接的方式，因为 .output 文件夹包含了项目所需的全部内容，在任何环境下只要有这一系列文件和合适的环境变量，就可以成功启动应用。

现在有了 .output 下面的这一系列文件，可以想到用 scp 就能把它们拷贝到远程服务器上。但 .output 当中有非常多的文件，大大小小各种各样，如果直接拷贝会非常浪费时间，因为 scp 一次只能拷贝一个文件。所以常见的方式是把整个 .output 文件夹打包，上传压缩包，上传完毕后解压，最后清理临时文件。

写脚本之前，先看看服务器。服务器要按照之前讲的云服务器设置和登录的最佳实践进行配置，比如免登录、安装必备软件等，这里不再赘述，大家自己配置。我登录服务器看一下，这里已经有 viking 用户，IP 是某个国外服务器，也设置了免登录。SSH 上去以后里面没有任何内容，这是新建的用户。先建一个 admin 文件夹，之后所有内容都放到 admin 当中。看完服务器后退出，接下来就可以写脚本了。

先写伪代码。脚本需要几步：第一步打包，把 .output 文件夹打包为一个压缩文件；第二步把压缩包 scp 上传到服务器；第三步在服务器上解压；最后清理本地和服务器上的临时压缩文件。

一步一步来完成。第一步打包，大家对 tar 命令应该很熟悉了，不过由于它参数复杂，每次可能都要去 Google 一下参数含义。这里添加四个参数 z、c、v、f：z 代表使用 gzip 进行压缩；c 是 compression，表示进行压缩操作；v 是显示整个压缩过程；f 表示后面跟的是文件名。

文件名定为 dist.tar，文件名之后输入要压缩的文件夹名称，这里是 .output。第一步就完成了。

第二步是 scp，远程拷贝一个文件，这是必须掌握的命令。前面是文件名 dist.tar，然后是目标机器，后面添加机器上的路径。特别注意这里的分隔是一个冒号，冒号后面写你想要的路径，这里是用户目录下的 admin 文件夹。

前两步完成后保存，先运行一次看是否成功：`sh deploy.sh`，我在根目录下建的文件名就叫 deploy.sh。运行后可以看到先是打包过程，打包完毕后进行 scp 上传。上传需要一段时间，完毕后到服务器上确认：进入 admin 文件夹，ls 可以看到压缩包已经上传过来，说明没有问题。把它删掉，继续下一步。

下一步是解压缩，需要在服务器端运行命令。教大家一招，这是 ssh 的一个管道用法：先写 ssh 到对应的服务器，后面直接跟要执行的命令，用双引号包起来，双引号中就可以添加要在服务器上执行的操作。这里要完成解压，还是使用 tar 命令。

参数和之前非常相似，前面还是 z，唯一的区别是把 c 换成 x，x 表示解压缩操作，其他参数完全一样。然后写文件名，.tar 后面是 dist 这个文件，再后面跟解压到的目标目录。特别注意这里用的参数是大写的 C，表示把文件内容解压到指定目录，后面跟目录就好。我们把它解压到用户根目录的 admin 下面，也就是和上传包同级的位置。

最后是清理文件，大家应该很熟悉了。第一步在本地清理，把刚才打包出来的文件删掉；然后在服务器上清理，方式一样，还是用刚才那招：前面写 ssh，冒号后面写想在服务器上运行的命令，这里是 rm 加上文件地址。通过这种方式就可以远程在服务器上执行命令。

整个脚本写完了，运行一遍看结果。执行 deploy，稍微等待，打包完毕，上传完毕后进行解压，把所有文件解压出来，最后删除压缩包。登录服务器验证：ls 进入 admin，直接 ls 看不到，因为 .output 是以点开头的文件夹，用 ls -a 可以看到 .output 在这里，压缩文件已经被删除。进入 .output 看一下，之前构建生成的代码成功上传到了服务器，部署完成。

使用 Nitro 部署还是很简单的，只需要把构建生成的文件夹通过某种方式上传到服务器上，就完成了整个部署流程。这节课希望大家掌握两点：一是这种脚本部署方式；二是想在服务器上执行远程命令时，可以用 ssh 后面加命令（冒号加双引号）的方式来运行。
