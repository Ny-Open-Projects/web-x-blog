# 16-5-1-撤销重做需求分析

这节课来完成编辑器里非常常见的一个特性：撤销和重做。大家平时用 VS Code 或自己的编辑器时，经常按 Command+Z 或 Ctrl+Z 回到之前的修改。这也算是本周里比较有难度的内容。

和之前的特性一样，第一节课先思考怎么完成这个问题。画布中的操作，无非是在修改 `components` 数组中的一些属性，通过各种 mutation 完成。每一次操作就是一次需要被记录的值，自然需要一个数组来保存一系列操作，比如叫 `histories`。

## 关键问题：记录什么样的值

最直接的想法是把 `components` 整个克隆一份存进去，每次操作都存一次。弊端也很明显：数据太冗余，可能只改了其中一项的一个属性，却要把整个数组保存下来，完全没有必要。

换一个角度，给操作分类。看一下现有的 mutation：

- `addComponent`：新建图层；
- `pasteCopiedComponent`：同样在新建图层；
- `deleteComponent`：删除图层；
- `moveComponent`：调用的是 `updateComponent`，本质是更新属性。

所以操作大体就三种：创建图层、删除图层、修改属性。这三种基本操作构成了编辑器所有可能的修改。我们是否可以只保存这三种特殊修改呢？

## 三种历史记录的结构

想象一个画布状态，里面已经有一个元素，逐步推演：

**添加图层**的记录：保存一个 componentId（新添加项的 id）、type 为 `add`，还有 data，为了不影响原对象之后的响应性，要做一份深拷贝，保证它是最初的样子。

**删除图层**的记录：type 为 `delete`，同样保存 id 和 data，还要保存它在哪个位置被删除的，`index` 在恢复时很重要。

**修改属性**的记录：type 为 `modify`，要保存哪个 component 在发生修改（id），以及 data 里的四个信息：`oldValue` 旧的值、`newValue` 要修改到的值、`key` 是哪个属性发生修改。

现在时间线上有了三条记录。接下来推演对应的操作。

## 回滚（undo）

回滚应该从最后一条开始。这里需要一个指针告诉我们走到了哪条记录，保存一个 `index` 就可以了。

- 回滚 modify：能找到对应的 component、key 和 oldValue，恢复到旧值即可；
- 回滚 delete：做相反操作，恢复删除的这一项，有保存的数据和位置，重新插入 `components` 数组即可（所以 index 特别重要，保证插回原位置）；
- 回滚 add：add 的相反就是删除，有了保存的 id，把它删掉就行。

经过这三步，画布恢复到最初状态。

## 重做（redo）

反向进行即可，和历史记录中的操作一致：add 是插入到 components 中，delete 是把它删掉，modify 是恢复到 newValue。这样画布就恢复到了最新状态。

## 结论

当然还有一些细节和潜在的 edge cases 暂不考虑，比如最多保存多少条记录、回滚到某个状态后继续编辑怎么办。先从最基本的做起，得出三条结论：

1. 需要一个 `histories` 数组保存历史记录，每项包含类型、componentId 和数据；还需要一个单独的指针记录当前走到数组哪个位置。
2. 需要两个 mutation：`undo` 和 `redo`，在历史记录中来回穿梭。
3. 要针对不同类型分别完成不同的反向操作。
