# 7-11-测试组件：异步请求

上节课我们走完了测试组件的大体流程，从一个 case 的开始到结束完整地过了一遍。有了这套流程之后，这节课来补充几个进阶知识点。有了前面 Jest 的基础，今天的内容其实难度不大，核心是一个非常常见的需求：组件中会发送异步请求，比如用 axios 发一个 request，然后测试组件在发送前和发送后界面的不同状态。

先看组件改成了什么样子。在 HelloWorld 中添加了一系列数据：一个 reactive 的 user，上面有 data、loading、error 三个属性；又加了一个叫 loadUser 的 button，点击时触发 loadUser 函数。这个函数的逻辑是：先把 loading 设为 true，然后发送请求，拿到数据后把返回的 data 赋给 user，同时加了 catch，出错时把 user 的 error 设为 true，最后把 loading 设回 false。

模板部分根据这些状态做区分：loading 的时候显示一个 p 标签，内容是 loading；拿到真实数据后显示 user.data 的 username；如果出现 error，也会把错误显示出来。

有一点要特别注意：为了写得快，我把 data 断言成了 any，因为不断言的话这里可能出现类型错误。这只是测试用的组件，不追求类型层面的完备，真实项目中千万不要这么写。

接下来写测试用例。第一个规则前面学 Jest 时就写过：mock 第三方模块，不依赖第三方库、不发真实请求，模拟第三方库的实现。复习一下做法：要模拟哪个模块，就先把它引入进来，`import Axios from 'axios'`，然后调用 `jest.mock` 方法，注意传入的字符串，这样 mock 就完成了。

但这里有个问题：写 `axios.get` 时，编辑器没有任何补全，它还是原来的对象类型。mock 之后的方法名都很长，比如 mockImplementation、mockResolvedValue、mockResolvedValueOnce，手打非常容易出错而且耗时。所以需要把它断言成真正的 mock 类型，同时保留 axios 原有的属性和方法。

做法是创建一个 mockedAxios 变量，等于 `axios as jest.Mocked<typeof axios>`。jest 提供了一个叫 jest.Mocked 的类型，它接受一个泛型，把原来的类型传进去；用 typeof 拿到 axios 的类型，这样就完成了类型转换。之后 mockedAxios 上既有 get 方法，又把各种 mock 方法一一补全了，非常好用。这是个很重要的知识点，我当初搜索了好一阵才找到答案，等于帮大家省了时间，请务必把这种写法记下来。

有了这个之后就可以拦截原来的 get 了。在 case 中写 `mockedAxios.get.mockResolvedValueOnce`，只需要一次，返回值和上次写 Jest 时一样：data 里是 username 为 Viking，mock 就完成了。

这里出现第二个知识点：跑测试时经常想只跑某一个特定的 case，看它单独的结果。当前场景就是这样，我们只测当前这个 case，其他一概不管。it 上有一个 only 属性，写成 `it.only` 就表示只跑这一个测试，其他全部跳过。

有了 mock 之后，完成测试逻辑本身就不难了。第一步是点击，记得加 await：`await wrapper.find('.load-user').trigger('click')`。然后判断 axios 是否被调用，因为点击之后它应该被调用：`expect(mockedAxios.get).toHaveBeenCalled()`。接着判断 loading 状态是否出现：`expect(wrapper.find('.loading').exists()).toBe(true)`，exists 返回 true 或 false。到这里逻辑写完了，跑一下，测试是通过的。

再往下就有点犯难了：怎么让处于 pending 状态的 promise resolve，并且等界面更新完成？因为请求是异步的，promise 发出去之后要过一段时间才能完成界面更新。这时可以借助一个第三方库 flush-promises，它能把所有 pending 的 promise resolve 掉，并等待界面更新完毕。用 `npm install flush-promises` 安装，然后在文件顶部引入。

有了它之后很简单：点击之后 `await flushPromises()`，调用一次，界面就更新完毕了。之后就可以做更新后的断言：先断言 loading 已经消失，把前面那条的 toBe(true) 改成 `toBe(false)`，或者用 toBeFalsy；再断言 username 的值已经被填充，`expect(wrapper.find('.username').text()).toBe('Viking')`。跑一下，测试全部通过，这个异步 case 就算写完了。

还有另外一个 case 留给大家自己练手：请求出错的时候，界面上会出现错误提示，写一个对应的 test case 去测试这个错误界面是否出现。参照前面的写法，应该很容易完成。

总结一下这节课：我们主攻了组件中有异步请求时的测试方法。第一，复习了 Jest mock 第三方模块的做法；第二，学习了 Jest 和 Vue Test Utils 结合的测试方式，特别要注意用 flush-promises 处理异步；另外还有两个小知识点：一是把 mock 对象断言为特定类型，用 jest.Mocked 传一个泛型进去；二是用 it 上的 only 属性单独跑一个 case。这节课就到这里，谢谢大家，再见。
