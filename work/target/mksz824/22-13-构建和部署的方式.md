# 22-13-构建和部署的方式

欢迎来到关于 Nuxt 的最后一章：构建和部署。这是任何项目开发完毕后不可或缺的环节。现在我们要把使用 Nuxt 3 开发完的全栈应用部署到服务器上，让用户通过互联网随意访问。具体文档已经列出来了，内容非常多，这里列一个提纲，先了解有几种部署方式。Nuxt 3 提供了非常丰富的部署方式，适用于各种不同的场景。

## 第一种：Node.js Server

第一种称为 Node.js Server，也就是我们之后要采用的模式，后面会一步一步讲解和实操。顾名思义，Nuxt 是全栈应用，代码里不仅有前端还有后端；有后端就需要启动对应的服务来完成工作，仅有静态文件是不够的。

Nuxt 3 针对 Node.js Server 做了一系列优化：

- 它是没有特殊配置时的默认输出格式：不做任何配置直接 `npm run build`，就会采用 Node.js server 模式。
- 优化了启动速度，有按需加载，加速冷启动过程。
- 适配任何 Node.js 环境：服务器装了 Node.js 就能运行这个应用。特别注意版本要 Node 18 以上，原因等 build 之后再讲，就能明白为什么需要这么高的版本。
- 内置 Cluster Mode：之前讲过 Node.js 有多进程模式，使用它可以让效率更高。

## 第二种：Static Hosting

第二种是静态文件的部署方式。它有一个适用条件：整个应用中没有后端代码，只有前端代码的情况。静态部署又有两种子模式。

第一种叫 SSG 模式（Static Site Generation），静态网站生成，很有意思：在这种模式下 build，构建后会自动生成所有相关路由的静态文件。内部是通过 Nitro 做了一个爬虫，会爬一个个路由，把整个文件都爬出来，有多少个路由就有多少个静态页面。这种模式有利于 SEO 和加载速度。它还有一篇对应的原理介绍，感兴趣可以看看怎样通过 Nitro 爬虫完成 pre rendering 预渲染过程。

第二种我们已经非常熟悉了：client only rendering，即 SPA 应用。它通过参数 `ssr: true` 或 `false` 切换：true 就是前面说的模式；设为 false 就是我们熟悉的 SPA 应用模式，只有一个入口文件。入口文件很熟悉，生成一个 index.html，里面只有一个 `div id="__nuxt"` 这样的 DOM 节点，所有内容都通过 JavaScript 加载，也就是通过 JS 往这个节点里塞内容。

## 第三种：第三方平台

第三种很有意思：可以部署到第三方平台，文档里叫 hosting providers。可以部署到任意的第三方平台，适配的平台非常多，可以非常方便地完成一键部署：后期点一键或者走一个 GitHub push 流程就完成部署，非常便捷，而且不需要维护任何基础架构。

其中一些平台很强大：不仅能 host 静态文件，还有云端完整的 Node.js 运行时，直接运行后端也不在话下；同时提供一系列 serverless 功能，不用自己搭服务器就可以使用数据库、Redis 缓存等等一系列服务。比如大家已经非常熟悉的 Vercel 和 Cloudflare Pages，都可以完成这样的功能。感兴趣的话可以自己试试，我觉得这种方式非常有趣且便捷。

当然，使用第三方平台有利有弊：自己搭服务器看起来麻烦，但整个成本完全可控；使用第三方服务，定价方式都在对方平台，它突然涨价你也没有办法。而且有时因为写了一些和平台相关的代码，迁移时也要注意，可能是个问题。

以上就是 Nuxt 3 构建和部署的三种方式，适用于不同的情况，请大家了解。之后我会针对第一种方式进一步讲下去。这节课就到这里。
