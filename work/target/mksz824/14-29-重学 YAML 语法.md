# 14-29-重学 YAML 语法

在开始 GitHub Actions 之前，先补充一点基础知识。这是我后加的内容：发现很多人（包括我自己）写 YAML 配置文件时其实并不完全了解它的语法，它看起来简单，我们凭经验揣测语法的意思，所以经常写错。后面会大量使用 YAML，先把语法彻底搞清楚，避免低级错误。

## YAML 是什么

YAML 是一个标记语言（markup language）。有个程序员熟悉的玩笑：它的全称是递归写法 YAML Ain't Markup Language。它使用空格缩进，看起来非常简洁，可读性很好，适合内容大纲和配置文件。它最终通过对应工具转化为 JSON，最终数据格式还是 JSON，但可读性比 JSON 强很多，所以复杂配置都会选用 YAML。GitHub Actions、Travis 都选用了这种格式。

## 纯量 Scalars

第一个概念是纯量（Scalars），听起来高深，对应 JavaScript 就是 primitive values。

- 字符串：`key: value`，不需要加引号。
- number：直接写数字。
- boolean：true。

字符串不加引号即可，加了也不会报错，比如 `oneString: string` 也是合法的。

还有一个特殊类型：多行字符串，叫 literal block，用一个新的符号（竖线）：

```yaml
multipleString: |
  line one
  line two
  line three
```

使用竖线后，回车接着写多行文本。这个语法比较难理解但很有用，后面会接触到，请记住。

## 集合类型

第二种是 collection types（集合类型），可以直接看成 key value 形式，和 JavaScript 对象非常接近。表示层级关系靠缩进，推荐使用两个空格：

```yaml
person:
  name: viking
  age: 30
  address:
    city: shanghai
```

person 下再有对象就继续加两个空格的缩进，这样就表示了两层关系。用三个空格也没问题，但要保证同一层级前面的缩进相同；不过建议统一使用两个空格表示一层缩进。

## 序列 Sequence

最后一种数据结构是 sequence，对应数组或列表。用一个新的符号：横线。先缩进两个空格，然后每个横线一项：

```yaml
items:
  - item one
  - item two
  - name: viking
    reason: xyz
    address:
      city: beijing
```

数组里当然还可以嵌 collection types（对象），甚至继续往下嵌套，比如 address 里的 city。

## 校验工具

总结一下：YAML 就是三种数据结构，纯量、collection type（对应 JavaScript object）、sequence（对应 JavaScript array）。因为靠缩进表达层级，写错很常见（我使用 GitHub Actions 时也经常写错 YAML）。推荐一个检测工具：yamllint 类的 YAML Checker（yamlchecker.com）。把写错的配置粘进去，它会指出哪一行语法错了；把缩进改对后显示有效。写完 YAML 后用这类工具过一遍，可以避免低级错误。

有了这个基础，就可以学习 GitHub Actions 后面的知识了。
