# 22-12-编辑用户编码第三部分

这节课完成编辑用户的收尾工作。知识点是学习更多 Nuxt UI 组件的使用，没有特殊难度，就是熟能生巧。我们从三个方面对现在的 UI 进行增强。

## 第一步：更新成功的通知反馈

上节课说过，编辑用户后没有任何反馈，这里添加一个漂亮的反馈告诉用户编辑成功。使用 notification 组件：它非常像其他组件库的 message，点击后会弹出一个信息，出现在右下角，点击叉就可以消失。

它和一般组件的调用不一样：message 一般都是函数调用方式，这里也是使用 `toast.add` 来添加信息，是函数调用而不是组件形式。

使用步骤：第一步在根组件 `app.vue` 添加 UNotification 组件（可以放在 NuxtLayout 外侧），然后才能使用组合式函数 toast 添加通知。先用组合式函数创建一个实例，放哪里都可以，命名为 toast，全局函数叫 `useToast()`。

有了它就可以轻松添加信息。它有一系列属性，感兴趣的可以自己看，我们添加一个简单的 title 就够了。位置自然是在更新完毕以后，即 updateUser 后面：toast 上有 add 和 remove 方法，用 add 添加一条新的。第一个参数 title 是想添加的内容，和 updateUser 结合：希望拿到 updateUser 返回的 username 做处理。返回类型是 unknown，不是想要的，所以传一个泛型 UserDataProps 获取对应类型。文本用模板字符串拼接。第二个参数是 timeout，希望对话框停留多久，设为 2000，两秒后消失：

```ts
toast.add({ title: `已更新用户 ${res.username}`, timeout: 2000 })
```

测试：修改一个名称点击更新，弹出框成功出现；鼠标放上去倒计时会暂停，拿走以后才消失。这样就能良好地反馈更新成功。这是第一个 UI 增强。

## 第二步：面包屑导航

第二个增强是添加面包屑导航：根据层级添加导航。现在没法很好地导航，比如要回到用户管理或首页，必须在侧边栏点击，比较繁琐，面包屑可以很方便地完成这个任务。组件是 breadcrumb 开头的，没有任何难度。

它有几个属性：label 是里面的文本，icon 是图标，to 是可以点击跳转的目标（也可以不点击）。创建 links，希望有这样的层级：首页、用户列表和用户详情，三层。首页图标用 home，用户列表和用户详情的图标是我自己选的，大家可以按需求选合适的。

把 links 传给 UBreadcrumb 就能出现导航。放到页面上方，把之前展示数据用的部分删掉。保存后导航成功出现，方便很多。再把 UForm 加一些 class 让它离得远一点：加 `mt-5`，和上面做区分。有了面包屑，点击任何路由都轻松多了。

## 第三步：骨架屏加载效果

最后一个增强是读取效果。因为一开始没有数据而是把表单展示出来，里面空空的，这种交互不好。针对异步读取，都要添加读取提示，这是常见的提醒方式。选择 skeleton 组件：可以展示简单的骨架屏。你可以给它传任何 class，效果就是一个灰色背景，特别注意它有简单的渐变，仔细看会发现有动态效果，更符合读取的直觉。

什么时候出现？两个条件：一是编辑模式，二是尚未加载完毕。加载状态可以从 useFetch 返回的 status 中拿到，之前知道 status 有一系列值，对应 AsyncDataRequestStatus，需要判断它是 success 时才展示表单：数据加载完毕后再把表单加载出来。

骨架屏应该和 UForm 是并列关系，把面包屑移到外面一点。添加一个 div，加 `space-y`，在里面加 v-if 判断：第一个条件是不是 creatingMode，第二个是 status 不等于 success 时加载。里面放 skeleton，添加三个对应的条即可，长宽自己写。然后在另一种情况下加 v-else，让表单出现。

保存测试：退回到用户列表，点进第一条，一开始出现三个条告诉用户正在加载，之后才把数据加载出来；如果是 create 创建新用户，不会出现骨架屏，直接渲染表单。

## 收尾说明

编辑功能开发到这里。特别注意这次的教学理念是不手写所有代码逻辑，以抛砖引玉为主，有些细节没有添加：比如路由权限，创建和编辑都没加路由权限，因为之前已经讲过怎样添加，自己去修改中间件就可以；比如登录用户需要是管理员这类限制也没有加。这些都是小问题，掌握整个应用的大体开发思路后，可以很容易针对这些细节做对应的开发。这节课到这里。
