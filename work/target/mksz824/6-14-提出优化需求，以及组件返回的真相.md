# 6-14-提出优化需求，以及组件返回的真相

通过几节课的学习，我们完成了两个大任务：一是组件的属性可以使用不同的表单组件进行展示；二是更新某一个表单组件的值，画布上的组件也会同步更新。剩下的就是添加更多属性和表单的对应关系，内核和原理是不变的。这一章来优化目前解决方案的两个点，同时发散性地补充两个知识点。这也是我的教学理念之一：通过优化方案和需求来带动知识点的学习。假如有些需求是重复性的劳动，我就不会特别讲解，留给大家自己完成。

第一个优化点：字体有一个下拉菜单，我们发现选择字体的时候，下拉菜单里没有对应的字体样式。这是一个常见需求：在下拉菜单里最好能直接看到字体的样式，想选哪个字体先看到它长什么样，非常直观。想想怎样完成这个任务。看代码：在 PropsTable 里，我们直接渲染了 option.text 这个文本。假如能直接渲染一个带样式的模板结构，不就解决这个问题了吗？

看它真正定义的地方：text 定义成了一个纯文本。怎样创建一个带样式的 HTML 结构呢？为了解决这个问题，先岔开话题讲一个基本原理。大家都知道，Vue 和 React 组件都是由 Virtual DOM（虚拟 DOM 节点）构成的，整个应用由多个组件嵌套构成一棵虚拟 DOM 树。虚拟 DOM 就是组件的产出。那么一个组件是怎样转换成虚拟 DOM 的呢？

用 Hello 做个实验。大家记得 Hello 是用 TSX 写的一个组件，里面非常简单，直接 return 了一段 JSX 语法。现在把它打印出来，看看它究竟是什么东西。打印后发现：我们之前写的 JSX 语法，return 的那个结构，被转换成了 new object 之类的 createVNode 调用，前面是 Webpack 的转换，但特别注意 createVNode 后面还有 h1、还有 props 的 message。也就是说它里面的实现已经不是原来的 HTML 标签了。HTML 标签的写法叫 JSX，它不过是一种语法糖，是 createVNode 这个方法函数的语法糖。看到 VNode，应该和刚才说的 Virtual DOM 很亲切了：它的值就是 Virtual DOM Node，虚拟 DOM 的节点。所以可以得出结论：组件就是虚拟 DOM 的一个映射。

再看看单文件模板 SFC 把 .vue 格式的文件转换成什么样。用最简单的 App.vue 做转换：直接打印 App 的内容，页面上可以看到它转换成了一个对应的 object，有 name 之类的属性。但有一个属性非常关键，称之为 render。把 render 的实现再打出来看一下：虽然里面有一大堆混淆过的代码，但不难找到它的核心内容，其实就是 createVNode component router view。这和我们之前讲的 function 写法非常类似，返回的也是 createVNode 的结构。两个例子再次印证了结论：组件是虚拟 DOM 的一个映射。

了解到这个以后，如果抛开 Vue Template 的写法，想创建一个复杂的 HTML 结构，我们可以采用创建 VNode 节点的写法。上面两个例子都是使用 createVNode 这个方法。这里再给大家介绍 Vue3 的另一个方法，称之为 h。看官方文档：h 内部包含了 createVNode 的实现，更具有兼容性。

现在使用它创建一个虚拟节点。把 h 引进来，创建一个称之为 node 的变量，返回值是 VNode。h 有三个参数：第一个是元素的类型，假如是 HTML 元素就可以写任何节点名称，这里写 div；第二个是 props 数据对象，主要表示上面的属性或者 attributes、DOM 的 props 和 style，这里随便写一个 class: 'test'；第三个是 children 子节点，可以是其他的 VNode，也可以直接是一个字符串，这里写 hello vnode。

把 node 打印出来看是什么。控制台里可以看到，它其实就是一个大的 object，没有什么神奇之处。上面有一大堆的属性，就是一个简单对象的组合，构成了整个应用的虚拟 DOM 树，可以高效地完成 DOM 的更新和修改。

这节课简介了 Virtual DOM 和组件的关系，同时学会了使用 h 函数创建对应的 VNode 节点。有了 VNode 节点，就可以展示更丰富的数据结构了。下节课尝试使用 VNode 给下拉菜单添加更丰富的展示。这节课到这里，谢谢大家。
