# 4-1-什么是 Typescript 为什么要学习它

欢迎来到 TypeScript 的世界。这节课作为本章的开端，先做一个简单的导学。本章讲述 TS 的基础知识，算是打基础的一章，它和下一章 Vue 3 的技术知识一起构成课程基础知识的两部分。如果你之前学过相关课程，已经比较深入地了解 TS 的特性，可以选择跳过本章，直接快进到组件开发；否则还是建议大家好好看一下。

## 什么是 TypeScript

我们要学习的 Vue 3 现在完全使用 TS 重写。不只是 Vue，很多耳熟能详的大项目都用了 TS：谷歌出品的大而全框架 Angular、Vue 3 的组件库 Element Plus、React 组件库 Ant Design、Next.js 等。非常多知名的工具完全使用 TS 开发，说明它现在是做大型项目的首要选择。

理解 TS 要先了解两个概念。第一个是动态类型语言。动态和静态两种语言构成了整个编程语言的大家族。动态类型语言指在运行期间才做数据类型检查，编程时不用给变量指定数据类型。一个变量可以是字符串，之后可以被赋值变成数字，非常灵活。第一次赋值给变量的时候，在内部将数据类型记录下来。JavaScript、Ruby 和 Python 都是典型的动态类型语言。这意味着用 JS 写好的程序，只有运行的时候才能发现错误。听起来有点危险，所以前端发明了一系列静态代码检查器，比如非常流行的 ESLint，在编码期间就可以根据一定的规则提示有问题的地方。

静态类型语言刚好相反，数据类型检查发生在编译阶段，写程序时要声明变量的数据类型。C、C++、C#、Java 都是典型代表。

有了这两个概念，TS 就好理解了。TypeScript 这个词是 Type 和 Script 的组合：Type 是类型，Script 是 JS。它的目标是把不看重类型的动态语言变成关注类型的静态语言。官网口号是"TypeScript is JavaScript with syntax for types"，可以理解为可扩展的 JavaScript，或 JavaScript 超集。除了原生 JS，它还提供类型系统和 ES6 到 ES10 甚至 ES Next 的语法支持。使用最新的 ES 标准编码时，为了保证对不同系统和浏览器的兼容性，一般会用 Babel 转换，而 TS 一举两得，既有静态类型语言风格的类型系统，又提供 ES6 到 ES10 的一揽子语法支持。此外，它还可以运行在任何浏览器、任何服务器和任何系统上，并且是完全开源的软件。

## 为什么要学习它

学习任何新技术之前，我最喜欢问自己的问题是：我们为什么要使用它？它解决什么问题？对我的技术水平和项目架构有怎样的帮助？不要光听别人忽悠就人云亦云地学习某项技术，不管它是否符合你的知识体系和水平。

我在开始学 TS 的时候也经过了一番考量。说实话，第一个星期有点挫败和烦人：添加很多类型定义浪费了大量时间，还有很多根本看不懂的错误。但情况很快就变了。当代码中打入越来越多类型的时候，我的效率变得很高，遇到各种傻瓜错误的几率越来越少。在之后几年的工作生涯中，我在很多比较大型的项目里都使用了它，越来越感受到它的优势。下面把这几年使用 TS 的优势总结给大家做参考。

**第一个：程序更容易理解。** 编码时我们非常关心这几个问题：一个函数或方法接受什么类型的参数，返回值和类型是什么，有什么其他外部数据需要被引入。为了解决这些问题，一般都要详细查阅文档，搞清楚所有来龙去脉。动态语言的约束让我们很难完成这项任务，需要在代码真正运行时调试才知道答案：加 debugger 断点，加一系列 console.log 看输出，甚至还需要"社交"过程，去问同事或原来写代码的人这些字段究竟是干嘛的。有了 TS，这几个问题迎刃而解，代码就是全部的注释，不需要猜测，直接就有答案。

拿上古的 jQuery 举例，它的 API 非常多。引入 TS 后输入对应的方法，比如 ajax，它会告诉我们里面有哪些参数、文档地址，还有一系列使用例子，非常丰富，不用再去看文档了。

**第二个：效率更高。** 有了 IDE 和 compiler 的帮助，可以非常方便地在不同的代码块和定义之间跳转，同时进行代码补全，还有丰富的接口提示，事半功倍。可以看到更多方法，参数看得很清楚，甚至可以跳转到定义文件，详细了解参数和返回的类型，效率嗖嗖上升。

**第三个：更少的错误。** 编译期间就能发现大部分错误，远远比运行时才发现要好得多。TS 之前，不知有多少次出现变量名打错的问题。还有一个排在前端错误第一位的经典错误：cannot read property xxx of undefined，通常出现在从一个对象上取属性的时候。回到例子：当我们打错的时候，它会很快变红，告诉我们这里写错了，这个方法根本不存在。

**第四个：非常好的包容性。** TS 是 JS 的超集，即使把 JS 文件直接命名为 TS 也不会有任何问题。它兼容第三方库：即使库没有用 TS 编写，也可以给它们编写单独的类型文件进行读取。大部分项目现在都支持 TS，即使没用 TS 编写，也会提供写好的类型文件供开发者使用，可谓无缝衔接。

## 一点点不足

说了这么多优点，再说一点点不足。这其实不是 TS 本身的缺点，而是对学习者的成本。第一，增加了一些学习成本，要学习一些前端工程师平时没接触过的概念，比如 interface、generic、enum 等。第二，短期内增加了一些开发成本，因为要写一些类型定义。但对于一个长期维护的大型项目来说，这样做肯定是帮你节省时间。

要学会根据自己的需求和项目的规模合理选用工具。如果你的应用只是一个简单的展示页面加几个 UI 状态改变，就没有必要使用 TS 了。

说了这么多优点，相信大家已经跃跃欲试。别着急，下节课就可以开始学习使用了。
