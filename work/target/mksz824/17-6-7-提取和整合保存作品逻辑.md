# 17-6-7-提取和整合保存作品逻辑

完成一系列保存工作后发现一个问题：随着保存功能的加入，editorView 的代码量越来越大，后面还有其他功能要一一加入，势必越来越臃肿。而保存功能其实可以完美地抽离到另一个位置，把所有和保存相关的逻辑集中到某个文件里。

想到的方式是创建一个钩子函数，把 save 逻辑都放进去。有同学会问：钩子函数是不是应该只存放脱离项目的通用功能，比如已经创建的 useKeyPress、useHotKeys、useClickOutside？其实不然。我认为任何一段抽象逻辑代码，只要能在 setup 中执行，就可以提取成一个钩子函数，不管它是针对项目的还是公共模块的。

## 结构：三段式

新建 `useSaveWork.ts`，先把需要的依赖导入（复制过来即可），然后创建函数 useSaveWork，目前不接参数，随着功能增多可能再添加；函数注释写明"在 editor 中完成保存作品相关的一系列功能"。

保存相关功能一共三部分：saveWork 本身、自动保存（setInterval 定时保存）、离开路由前的保存提示。函数体也按此分成三块，前面加一段数据准备：

1. **数据准备**：所有需要的 store 或 route 上的数据放在这里，包括通过 computed 派生的值，比如 saveLoading、components、page 等保存要用到的变量；
2. **saveWork 函数**：保存函数本身，逻辑拷贝过来；
3. **自动保存**与**离开路由前的提示**：分别对应 setInterval 和 onBeforeRouteLeave 两段，直接拷贝。

## 返回什么

函数可能被外界需要，返回哪些内容？可以参考界面上 useForm 组件给我们的灵感。目前外界用到的是：保存作品的交互绑定事件、特殊情况下调用 saveWork 函数本身、作品是否正在保存的状态。所以返回两项：

```ts
return {
  saveWork,
  saveIsLoading,
}
```

未来有可能会添加更多变量。

## 替换原逻辑

抽象完成后，把 editorView 中从 saveWork 开始到 onBeforeRouteLeave 的所有相关逻辑删掉，导入写好的 hook，路径是 hooks 下的 useSaveWork，在 setup 中调用，解构出 saveWork 和 saveIsLoading；原来重复定义的 isDirty、saveIsLoading 等没用的部分也一并清理。

整合完成后 editor 的代码重新清爽起来。以后想看任何和保存相关的功能，直接到 useSaveWork 里一探究竟。
