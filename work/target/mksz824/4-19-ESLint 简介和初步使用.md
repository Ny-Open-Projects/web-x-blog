# 4-19-ESLint 简介和初步使用

上节课创建了项目文件并安装了几个好用的插件。在开始写代码之前，还需要完成一个准备工作：谈谈代码规范的问题。

只有你一个人做项目时，什么问题都不是问题，只要你能看懂自己写的代码就可以。但现代社会讲究团队合作，一个项目只有一个人从头写到尾的情况很少，所以代码规范很重要。刚入职新公司时，要做的几件事之一肯定是熟悉公司的代码格式和规范，因为规范的代码格式可以让整个工作效率在一定程度上提升到最高。

## 没有规范的代码会出现什么问题

**第一，代码难以读懂。** 假如每个人都有一套自己风格的代码，修改别人的代码时势必会遇到自己不熟悉的格式，很可能难以理解。同时，你可能把代码改成自己熟悉的格式，在这种情况下，整个代码库会充斥着各种风格的代码。

**第二，代码提交时有很多格式问题的修改，造成不必要的时间消耗。** 举个例子：你喜欢用两个空格，李四喜欢用 Tab，你在修改逻辑的同时，顺便帮他调整了之前代码的格式，自认为帮了大忙，然后提交了 PR。李四作为 reviewer 看到自己的代码被改得面目全非，很气愤，愤怒地拒绝掉了你的 PR，还可能有无休止的争吵。

这个故事告诉我们一个道理：要解决问题，要先把规矩列出来写在文件里。代码规范有点像项目中的法律条款，写代码时必须遵守。

## ESLint 初体验

这时大名鼎鼎的 ESLint 出现了。官网是 eslint.org。它的描述是：一个开源的 JavaScript 工具，使用 Espree 将 JavaScript 代码解析成抽象语法树（AST），然后通过 AST 来分析我们的代码。

ESLint 是一个命令行工具，首先要安装。在项目文件夹下做一个测试：

```bash
npm install eslint --save-dev
```

它是开发时的工具，所以是 devDependency。安装完毕后测试是否成功：使用 `npx eslint --version` 查看版本，当前是 8.33.0。

ESLint 由一系列规则和其他配置组成，需要一个配置文件来设定规则。它提供了自动生成配置文件的命令：

```bash
npm init @eslint/config
```

运行后有一系列问题（这里是测试，简单选一下）：目的？只检测语法。使用什么 module？JavaScript modules，即 import/export 写法。在什么 framework 上使用？先不绑定 framework。项目是否使用 TS？Yes。代码在哪里运行？先简单检测一个文件，选 Node。配置文件要什么格式？JavaScript。最后确认 package 使用的包管理器是 npm。完成后生成了配置文件 .eslintrc.cjs。

看一下配置文件的内容：它导出了一个 object，里面有一系列配置。env、parser、parserOptions 和 plugins 这几项可以先不看，大家自己去文档了解。我们主要看 rules：你需要配置怎样的规则。

ESLint 默认提供了一系列 rules，可以在文档的 rules reference 中查看，非常非常多，想了解某个规则点进去就能看到详情。

## 添加一条规则

现在配置文件中还没有任何规则。先添加一条：希望 main.ts 的每一行后面都加分号。规则名称叫 semi，开启它有三个等级：0 代表关闭；1 代表 warning，输出警告但不是错误；2 代表 error，直接抛出错误。这三个数字也可以用单词代替，分别是 off、warn 和 error。设置为 2：

```js
rules: {
  semi: 2
}
```

保存后检验这个文件。检验也是到命令行，使用 npx eslint 加上文件路径：

```bash
npx eslint src/main.ts
```

回车后它会输出对应的错误，都是刚配置的 semi 错误：四处都没有添加分号。假如把规则关掉（设置为 0），再运行就没有任何错误，说明规则生效了。

在编辑器中，假如安装了 ESLint 插件，编辑文件时会自动检验：设置为 2 打开分号检测，输入任何字符它就自动检验并告诉你哪里出错了。还有一个提示：规则具体是什么，可以点击 URL 跳到对应的规则详情页，看它的解释，非常方便。修正以后错误就消失了。这就是单条规则的用法。

## extends：使用规则合集

我们发现还有很多格式需要讨论并添加：用单引号还是双引号？加分号还是不加分号？用 tab 还是空格？假如每一条都添加，rules 会非常多，并且很耗时。

打开 Google 搜索一下，发现很多公司都有和我们一样的问题。很多大公司提出了自己公司的标准，公开了一系列规则作为一组，可以直接拿过来放到自己的项目中。这时就提出了一个新的字段 extends。它是一个数组，里面每一项都是一组规则。

其中有一个特殊的规则集叫 eslint:recommended，也就是 ESLint 推荐的规则合集。在文档里可以看到，有些规则后面打绿色对勾，这些就包含在 recommended 当中。

添加一下：

```js
extends: [
  'eslint:recommended'
]
```

验证是否生效：先把分号规则关掉（0），应该是没有错误了。然后添加这组规则当中的一个特殊规则：写一个 debugger 语句，这时会发现它标红了，因为这组规则中有一条 no-debugger 不允许写 debugger。运行一下命令行检验，同样输出 unexpected debugger statement，说明整组规则生效了。
