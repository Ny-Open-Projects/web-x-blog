# 21-1-安装 tailwind.css

从这节课开始，我们进入管理系统项目的开发。经过前面复杂的前端项目和非常详尽的 Nest.js 后端项目的洗礼，应用里的基本逻辑和知识点大家都已经接触过了。所以这次项目开发换个思路：不再开发全部功能，而是挑典型的功能，看看它们在 Nuxt 中怎样实现，剩下的留给大家自己完成。

第二点是使用更新的技术，并且往底层下潜一些：先不用任何组件库，用最原始的方式开发，之后再慢慢添加常用的组件库。这样做的收益是解决方案不会和特定工具、框架强耦合，能沉淀出一套通用的开发思想。

## 为什么选 Tailwind CSS

项目开始前先面对样式问题。平时用组件库时样式都自带了，很少自己写；这次贯穿上面说的开发思想，采用更底层、更通用的方案，也就是大名鼎鼎的 Tailwind CSS。我自己的项目几乎都在用它，它到底有怎样的魔力？先搞清楚它和其他 CSS 框架的区别。

Tailwind 是一个高度可定制的 CSS 框架，提供一系列现成的样式类，用于快速构建用户界面。它和其他 CSS 框架最大的不同在于：没有预定义大量组件样式，而是提供原子级的样式类，开发者逐个选择、组合这些类来构建界面。它的 slogan 概括得很准：不需要离开 HTML 就可以创建现代的网站应用。在元素上添加一系列类名，就能组合出千变万化的界面。

官网还列了几个值得了解的特点：

- **Design system API**：样式分成若干大类，比如 sizing 提供预设好的宽度，颜色几乎涵盖市面上所有流行的色板，还有字体、shadows 等。点 Learn More 能看到非常多的原子级样式。
- **高度可定制**：开发者自由组合这些原子类，就能快速做出独特且美观的界面。官网演示用的是同一套 HTML 结构，只切换类名就能生成完全不同的界面。
- **性能优化**：它会自动扫描项目中实际使用的类名，只生成用到的那部分 CSS，最大程度减小文件体积。
- **Mobile First 响应式**：提供一系列前缀类名，通过前缀在不同宽度下应用不同样式，页面会随断点变化。
- **状态样式**：hover 之类的状态也有对应类名，在类名前加 `hover:` 前缀即可实现。

也就是说，所有样式和行为都可以直接在 HTML 上定义。此外还有 dark mode（暗黑模式），支持自定义色板、字体，直接覆盖默认变量；CSS Grid、Transform、Filters 这些较新的特性也都有覆盖。

## 在 Nuxt 中安装

Nuxt 安装 Tailwind 非常方便，官方提供了现成的模块 `@nuxtjs/tailwindcss`，按文档里的命令安装即可。安装完成后把它添加到模块配置里，同时删掉原来写的全局 CSS：

```ts
// nuxt.config.ts
modules: ['@nuxtjs/tailwindcss']
```

保存后启动项目，控制台会弹出一条 log，说明 Tailwind 已安装成功。它还提供一个独特的 URL 用于查看所有 Tailwind 相关的变量：访问 `/_tailwind`，能把所有类名列出来，内容非常丰富。

## 配置编辑器插件

手写这些类名普遍偏长，Tailwind 官方提供了编辑器插件 Tailwind CSS IntelliSense，可以自动联想补全类名。装好插件后到 `app.vue` 里输入 class 时会发现，首次安装它并不会弹出提示。

原因是 nuxt.config 生成 Tailwind 配置时并没有单独输出一个配置文件，而是直接放在内存里。解决办法是加一个 `exposeConfig` 配置，让它生成真实的配置文件，插件就能正常运作了：

```ts
tailwindcss: {
  exposeConfig: true
}
```

每次配置文件修改时整个 Nuxt 都会重新运行，稍等片刻。重启完成后可以在 `.nuxt` 目录下看到多出一个 `tailwind.config` 相关文件。此时再输入 class 和 `bg`，就能弹出一系列提示，选中某个背景色后，前面还会显示颜色小图标预览对应的颜色。

再给 `ul` 设置 `display flex`（类名 `flex`），保存后到首页查看：背景颜色已经加上，banner 区域也变成了横向排列的 flex 布局。中间还顺带修正了一个写错的 li 标签。

到这里，Tailwind 的安装和简单使用就完成了。
