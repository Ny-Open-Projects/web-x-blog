# 21-15-总结

本章到这里告一段落。这一章的知识点非常丰富，接触了很多前沿的库，编程过程也很有趣，学到了 Nuxt 3 实战的关键一部分知识。用户权限控制（注册登录并持久化登录状态）是每个系统都要遇到的重要功能之一，下面一起回顾成果。

## Tailwind CSS 与 Hyper UI

首先介绍了现在最流行的 CSS 框架 Tailwind CSS：高度可定制化，提供一系列现成的样式类，用于快速构建用户界面。大家应该已经感受到这些类名是怎样工作的，我们讲了它的命名规律，也可以随时在官网上查询。

还介绍了一个写好一系列 UI components 的开源项目 Hyper UI：直接把带着 Tailwind CSS 类名的 HTML 代码片段拷贝到项目中使用。

## Layouts

中间插叙了一个 Nuxt 3 的概念 Layouts，可以用它实现多种布局的效果。

## Zod

之后讲了 Zod。当时的痛点是：前后端验证需要不同的方案，TS 验证又没法用于运行时。Zod 有两种解析方式，用伪代码回忆一下：

- `parse`：出错时直接抛出异常。
- `safeParse`：出错时不抛出，而是在返回对象里指示成功或失败。`success` 为 false 时返回 error，可以从 error 中拿到一系列错误信息。

它的一大优势是链式写法，比如 `z.string().email()` 一路写下去，还支持非常多的类型，能想到的基本都有。另外是静态类型推论：拿到 schema 后用 `z.infer` 推出对应的 TypeScript 类型。

我们还把 Zod 和后端完美接入：h3 提供了全局函数 `readValidatedBody`，和 Zod 配合运作，可以方便地拿到验证结果及附加信息。

## VeeValidate

验证方案选型上选了 VeeValidate。它有两种形式，很有创新性：一是组件形式，和之前的组件库类似，我们没选；二是组合式函数 API 形式，可以实现高度自定义的布局，我们选了它。

一开始学的是 `useForm` 和 `defineField` 两个 API。把 schema 传给 `useForm`，它返回一系列和表单相关的字段：values 是表单的值，errors 是对应的错误，handleSubmit 管表单提交，isSubmitting 是提交状态等等，表单中枢神经相关的属性都能拿到。`defineField` 是每个表单元素和整个表单交互的重要工具，调用它定义 email、password 等字段，供表单元素使用。最后在 login 上用 handleSubmit 包裹提交函数，验证通过才能拿到最终的值。

后来发现字段多（比如十几个）时这种方式比较繁琐，又学了抽象成单独组件的做法 `useField`：在组件内部把字段名传进来，拿到单个表单相关的一系列信息，比如值、errorMessage、handleChange、meta 等，可以基于单个字段的状态做细粒度控制。

完成 sign up 注册功能时又学了 Zod 的 refine：在 `.object()` 上面链式调用 refine 自定义规则，比如要求 password 和 confirmPwd 相等，不相等就弹出错误。这体现了 Zod 的高可定制性。

以后遇到表单、验证相关的需求，可以考虑这两个库结合使用：好用、现代、高自定义，这是它们的三个优点。

## 登录解决方案

最后是前后端配合的登录方案。之前学过很多相关知识，这里主要是根据 Nuxt 3 不同的知识点做替换学习。认证还是采用 JWT，用 cookie 保存 token 信息，Nuxt 3 已提供好了一系列全局函数。从最终代码里提取核心部分：用 JWT 的 `sign` 加密生成 token，保存用户的关键信息；再调用 `setCookie` 把信息保存到 cookie 中，供前后端使用。

登录功能完成后，后端还需要中间件保护需要权限的路由，这个很简单。掌握几个小知识点：`getCookie` 和 `setCookie` 相对，用它取到 token 值；用 JWT 的 `verify` 验证保存的信息是否合法；通过后把最终信息放到 event.context 上，event.context 可以存放一系列信息供之后的逻辑使用。

## 持久化登录状态

最后一部分是持久化登录状态，这是本章的小难点之一：在前端中间件中添加对应的逻辑完成验证。前端用 `useCookie` 拿到 token 值，注意它是响应式对象，可以轻松修改它的值。用 `useFetch` 发请求是不带 cookie 的，需要用 `useRequestHeader` 把 header 原封不动地传过去。

拿到 data 和 error 后做判断，条件要特别注意：`token.value` 有值且用户目前未登录，说明是第一次进入应用，才发送这个请求。出现 error 说明 token 有问题或已过期，把 isLogin 置为 false、清空 cookie、返回登录界面；没问题则登录成功、持久化成功，自动完成登录并获取 currentUser 对应的值。

这就是本章的全部功能。通过这些开发，大家应该能感受到 Nuxt 3 全栈框架的全新体验，这是之前 SPA 开发方式和 Nest.js 后端都没有的体验。本周的回顾就到这里，接下来继续开发新功能。
