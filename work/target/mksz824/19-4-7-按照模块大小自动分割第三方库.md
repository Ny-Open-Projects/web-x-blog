# 19-4-7-按照模块大小自动分割第三方库

上节课简介了分离第三方包的第一种做法：使用 Webpack 的 optimization 字段中的 splitChunks 属性来完成处理。但问题是必须手动完成第三方包的分割。有没有办法让它自动完成？比如当其中一个包大于特定大小时，就把它分割成一个单独的包。这节课就来看怎样完成这个任务。

## 修改 minSize

首先修改一个字段，上节课解释过的 minSize，也就是最小分包大小。我们希望当一个第三方包大小大于一定数量时，就单独分割成一个文件。把它改成 300KB，也就是 300 乘以 1024：

```js
splitChunks: {
  chunks: 'all',
  minSize: 300 * 1024,
  maxInitialRequests: Infinity,
  cacheGroups: { ... },
},
```

## 动态计算 name

然后修改 cacheGroups：把其中的值删得只剩一项，test 直接 test 整个 node_modules，把原来的正则删掉。

特别注意 name：不能像原来一样定死，而需要动态计算。这样动态返回不同名称时，它就可以生成不同的文件了。name 除了是字符串，还可以接受一个 function 作为回调：

```js
cacheGroups: {
  npm: {
    test: /[\\/]node_modules[\\/]/,
    name(module) {
      const packageName = module.context.match(/[\\/]node_modules[\\/](.*?)([\\/]|$)/)[1];
      return `npm.${packageName.replace('@', '')}`;
    },
  },
},
```

name 这个 function 有一个参数 module，可以拿到模块的一系列信息。module 上有一个属性 context，可以拿到具体的文件路径。特别注意这里的文件路径有两种：node_modules 里引入的模块类型，一种是可能有子路径的，即 packageName 加 subPath；一种是没有子路径的，到 packageName 就结束了。

我们的任务是 get the name，拿到 packageName。所以又变成了一个正则的处理。用 regexr 网站来调试：测试路径使用带 subPath 的这种。模块名称的特征是前面有 node_modules 这个字段，所以先拿它来匹配；接下来想匹配到模块名称这一段，加上一个斜杠就可以了，用分组 `(.*)` 拿到具体信息。一开始发现拿多了，要改成非贪婪匹配，加一个问号 `(.?)`，遇到第一次匹配就立马停止。这样就可以完美拿到这一段字符串，有分组之后拿数组的第一项就可以了。

还有第二种格式的 URL（不带子路径的），把测试路径里的 subPath 去掉，直接到结尾，发现这种情况下正则就不好使了。修改方式是把结束的地方做成可选：加一个分组，里面用或连接两种情况，第一种是后面跟一个斜杠，第二种是直接到字符串的末尾，加一个 `$`。可以看到它和第一种情况实现了同样的效果。这就是千辛万苦拿到的正则：`[\\/]node_modules[\\/](.*?)([\\/]|$)`。

回到代码中：packageName 等于 module.context（拿到具体文件路径）调用 match，第一个参数是刚才的正则（在 JS 里要写成两个反斜杠）。match 以后拿到一个数组，返回的分组的数组中第二项（索引 1）是我们想要的，这样就拿到了 packageName，最后 return 出去。

return 之前要做一点小处理：node_modules 里有很多以 @ 开头的模块名称，但 @ 开头的名称做 URL 的时候（比如在 .NET 服务器中）会出现一些问题，所以要做特殊处理把 @ 去掉。创建一个字符串字面量 `npm.`，里面调用 replace，把 packageName 中的 @ 替换掉。

## 验证

写完了 cacheGroups 的动态计算，它应该返回 npm.packageName 这样的一系列文件名。运行 npm run build:analyze，经过一段时间的等待生成了新的分析图，任务完成了：

- ant-design-vue 单独生成了一个文件，命名格式和我们的 name 一致：npm.antdv.js；
- 有一个 374KB 的包，大于 300KB 的限制，也单独生成了文件；
- Vue 是 363KB，也生成了一个文件；
- 最后这些小于 300KB 的文件都打包成了一个文件。

通过几节课，我们就将一个比较大的第三方库文件，一步一步按照规则拆分成了一系列小的文件。这样做对浏览器的缓存以及并行加载都有好处。任务完成，这节课就到这里。
