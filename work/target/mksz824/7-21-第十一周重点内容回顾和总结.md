# 7-21-第十一周重点内容回顾和总结

经过一周的学习，大家对测试是否有新的认识？是否觉得它实实在在地帮助我们提高代码质量、减少 bug？这一周讲了很多新知识点和概念，先大体回顾一遍。

最先遇到的是 Jest，一个通用测试框架。在讲框架之前，我们讲了为什么要有测试，我觉得这个为什么还是很重要的，并且简单讲了测试的分类，有哪几种测试。然后讲了 Jest 和 Mocha 之间的异同，选择 Jest 作为主力测试框架。之后是它的安装，以及一个很重要的概念：断言（expect）。接着学的是异步测试的方法，因为 JavaScript 经常遇到异步模块，里面分为回调和 Promise 两种情况。

接下来是 mock。首先是 mock 函数，使用 jest.fn()；然后是 mock 第三方模块，用 jest.mock 添加第三方模块的一系列假实现；最后是 mock timers，使用 Jest 提供的一系列 API 对 setTimeout 或 setInterval 做 mock。

讲完 Jest 测试框架的基础内容，就可以进入 Vue 专属测试工具的阶段了。用的工具是官方推荐的 Vue Test Utils，简称 VTU。第一步是把组件渲染到测试用例中，遇到了两个方法：mount 和 shallowMount，我们讲了它们的区别。mount 之后经常需要获取元素进行操作，也有两个方法：get 和 find，异同也讲过了。接下来是表单，表单是用户和 Web 世界交互的重要方式，最重要的操作是填写和更新表单，这里讲了 setValue。因为 DOM 更新需要时间，所以要特别注意添加 await，等 DOM 更新完毕后再做后续操作。然后是事件，拿到元素和表单之后需要触发 DOM 事件，用 trigger 方法。还有一个重点是组件会发射一系列事件，要验证这些事件是否发射、参数是否正确，用 emitted 方法拿到发射出来的数据进行验证。最后做了一个综合例子，把 Jest 和 VTU 联合在一起，测了异步请求的场景。

以上是基础部分，还有一些高级技巧，我们借助 UserProfile 这个组件的测试把它们串了起来。第一，需要 mock 全局组件：main.ts 提供了一系列全局注册的组件，怎样在单元测试里替换它们是一个小技巧。第二，mock 第三方模块的实现：组件代码虽简单，但用了 Vuex、Vue Router 等一系列第三方模块，用 jest.mock 把它们的实现整个替换掉，是另一个技巧。第三种方法是另辟蹊径：在 mount 的实例中注入真实的 Vuex Store，观察 store 状态变化之后能否拿到预想的值，同样可以完成测试。最后，因为 Vuex Store 是脱离界面完全独立存在的一种数据结构，我们还可以对它做单独测试，把数据逻辑和 UI 分开，这是非常有意思的概念。

再往后我们学了一种特殊的开发方式：TDD，Test Driven Development，并用它开发了 ColorPicker 组件，这应该是很多同学第一次使用 TDD。它的流程是：先写测试用例，让所有用例失败，全是红叉；然后根据用例写实现代码，让用例全部通过；最后把组件放到应用中验证，如有需要再做一系列重构。这样完成了一个闭环，可以用这个闭环持续开发，让组件或功能变得非常完善。

大部分知识点总结完了，还想单独强调一下单元测试的重要性。到目前为止我们写的都是单元测试：它由开发人员撰写，成本最低、运行最快，应该是写得最多的测试，它的核心特点是独立。测试工具都为此提供了一系列概念，出现最多的单词就是 mock。mock 可以让单元测试互相独立、互不影响，这是非常重要的概念。

第二，什么时候要写测试？我在课中多次强调，不要用教条主义的眼光看测试。使用任何技术都应该实用，切合自身的实际开发利益，没必要追求表面工程，比如必须把测试覆盖率（coverage）做到百分之百，或者给一些看起来非常简单的组件强行加测试，这些都没必要。我想灌输的思想是：写单元测试，是因为它真的能帮助到你，尤其是对一些稍微复杂的逻辑，它真的能减少 bug 和工作量，这才是测试的真谛。

最后留一个简单的作业。现在属性对应的表单组件还有一个没完成，叫 IconSwitch。它非常类似 Checkbox，但样式比较另类。建议大家自己开发一下，需求其实很简单：它有两种状态，高亮和未选中，由此可以想到它应该传入一个 value 来确定是否高亮。特别注意它的内容既可以是图标也可以是文字，图标可以在 Ant Design Vue 的图标库里找到，鼠标移上去要有一个 Tooltip 显示描述性的文字。大家可以先把这个需求简单写下来，然后进行实现，可以用 Ant Design Vue 提供好的组件比如 a-tooltip，也可以自研，都可以。最后写单元测试。当然我认为这个组件并不能很好地体现单元测试的优越性，但它功能比较完整，可以很好地练习这周学的内容。

这周就到这里。我希望通过这一周，真的能把测试的概念灌输到大家的日常开发中。如果你以后的工作里，经常冒出写个单元测试来保证代码运行成功的念头，那这周的任务就算圆满完成了。谢谢大家，下周见。
