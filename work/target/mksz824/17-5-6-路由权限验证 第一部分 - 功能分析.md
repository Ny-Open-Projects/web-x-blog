# 17-5-6-路由权限验证 第一部分 - 功能分析

上节把持久化的登录状态存到了本地，刷新进入路由时能直接自动登录。现在还面临路由验证的问题：不同路由要验证用户是否登录。有些路由必须登录后才能访问，比如编辑器 editor 页面；有些页面登录后反而不该再访问，比如登录页，已登录再进入时希望直接跳回首页。

## 方案一的问题：写在页面组件里

最直接的做法是在对应的路由组件里写逻辑，比如在 OtherView 中判断 `currentUser.isLogin === false` 就 `router.push` 到首页。但有两个问题要特别注意：

1. **判断时机**：如果是带 token 进来的，要先执行 fetchCurrentUser 获取用户信息，isLogin 要到异步请求结束才会变成 true。所以必须等请求完毕再做判断，直接取 isLogin 很可能取到初始值 false，误判成未登录。
2. **逻辑重复**：所有需要验证的组件都要写类似的逻辑，就算抽成独立函数也很繁琐。

所以需要找一个一劳永逸的地方。既然打交道的是路由，就向 Vue Router 寻求帮助。

## beforeEach 与 navigation guard

Vue Router 提供了路由钩子函数：beforeEach，顾名思义是进入每个路由之前执行的一系列操作，能监控路由开始的生命周期；与之并列的还有 beforeResolve。它们的参数叫 navigation guard，是一个回调函数，提供三个参数：

- **to**：要到哪个路由去；
- **from**：从哪个路由来；
- **next**：可选函数，调用它才继续往下进行。

看到 next 就会联想到 middleware 的概念，在中间加一层，处理其中的一些行为。

既然能拿到 to 对象（包含目标路由的全部信息），就可以在每个路由上标记它是否是受保护的路由。Vue Router 提供了保存这类信息的地方：路由元信息（meta）。在 routes 的 object 上添加 meta 字段，里面可以存任意想存的信息，比如：

- `requiredLogin: true`，只有登录以后才能访问这个路由；
- `redirectAlreadyLogin: true`，登录后再访问会跳转走。

## 整体流程图化

有了这两个标记，beforeEach 的逻辑稍微复杂，用流程图细化一下：

进入 beforeEach 后，先判断 `user.isLogin` 是否为 true。为 true 说明用户已登录（可能是登录成功后的继续访问），这时只需判断 redirectAlreadyLogin：false 就 next 继续；true 说明该路由登录状态下不该访问，跳转到首页。

isLogin 为 false 时，token 是关键判断条件：

- **token 不存在**：从来没登录过，逻辑简单，判断 requiredLogin，为 true 就 next 到 login 页（必须登录才能访问）；否则（比如首页这种不需要权限的）继续。
- **token 存在**：这条线就是上节持久化登录的流程，原样搬到这里，发送 fetchCurrentUser，成功后判断 redirectAlreadyLogin，false 继续、true 跳首页；失败说明 token 已过期或是伪造的，弹出提示并跳转到登录页。

通过这节的分析，我们理清了路由验证的机制和做法，并用流程图把逻辑梳理成型，下节照着它编码实现。
