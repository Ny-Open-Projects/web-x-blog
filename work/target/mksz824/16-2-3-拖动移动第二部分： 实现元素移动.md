# 16-2-3-拖动移动第二部分： 实现元素移动

上节课拿到了鼠标在元素中的偏移量，这节课完成鼠标移动时动态计算元素位置。

## 监听 mousemove 并计算新坐标

首先监控鼠标移动事件，创建一个 function，称为 `handleMove`，参数是 MouseEvent。这个过程中要一直计算理想的 top 和 left 值，所以在外侧再创建一个函数专管计算，叫 `calculateNewPosition`，传入 MouseEvent，返回 left、top（或 x、y）的坐标。

计算方式回顾图示：用现在的 `e.clientX` 减去之前算出来的 gap.x，得到横向坐标；纵向同理：

```ts
const calculateNewPosition = (e: MouseEvent) => ({
  left: e.clientX - gap.x,
  top: e.clientY - gap.y,
})
```

然后 return 这个 left 和 top。回到 handleMove 里拿值：调用 `calculateNewPosition(e)`，解构出 left 和 top。先把值打印出来验证一下。

接着添加事件回调监听：这里不添加到某个元素上，而是直接添加到 document 上，`document.addEventListener('mousemove', handleMove)`。

按住元素开始挪动，一系列坐标出现了，但值似乎不对：都达到了三百到四百，实际移动的距离远没有这么远。在界面上观察画布区域就恍然大悟了：元素的坐标值是相对于中间画布区域的，而两个值相减算出来的是相对于视口的距离。要算出最终位置，还要减去外侧画布区域相对左边和上边的偏移。

## offsetLeft 与 offsetParent

现在来拿这个值。画布区域元素上已经添加了一个 id，叫 canvas-area，代码里称之为 container：`document.getElementById('canvas-area')`，类型是 HTMLElement。

获取元素相对左侧和上方的坐标，之前用的是 `getBoundingClientRect`。这次换个方法，顺便扩展知识面。`getBoundingClientRect` 返回的是相对于视口（也就是窗口）的位置：top 从窗口顶端开始算，left 从浏览器左边缘开始算。

还有一个可能更熟悉的属性：`offsetTop` 和 `offsetLeft`，是 HTMLElement 上的只读属性，返回当前元素相对于其 offsetParent 元素顶部内边距的距离，和刚才那个非常相似，只不过参照物是 offsetParent。

offsetParent 是什么？文档讲得很清楚：指该元素最近的 position 不为 static 的祖先元素，如果没有，则指向 body 元素。还有特例：元素隐藏时 offsetParent 变成 null；元素的 style position 被设定为 fixed 时，这个属性也返回 null。

画布 canvas-area 就是 position fixed，所以它的 offsetParent 应该返回 null，它相对 body 的距离应该和 getBoundingClientRect 返回的值完全一样。为了验证这个猜想，打印出来比较一下：打印 container 的 offsetParent、container 的 offsetLeft，以及之前用的 `container.getBoundingClientRect().left`。

移动一下，可以看到 offsetParent 打出来是 null；两个值的比较结果显示它们非常相近，只差 0.5。所以这两个值用哪个都可以。

## 更新元素样式

现在算出正确的值：在计算中多减一下，减去 `container.offsetLeft` 和 `container.offsetTop`。删掉调试代码。

正确算出 left 和 top 以后，最终把元素的样式更新一下：假如 currentElement 存在，就执行：

```ts
currentElement.style.top = `${top}px`
currentElement.style.left = `${left}px`
```

注意 top 现在是 number，而 style 期望的是字符串，别忘了加上 `px`。left 同理更新。

界面上感受一下：按下鼠标进行拖动，元素跟着一起动，会移动到正确的位置。

## 松开鼠标与遗留问题

最后一部分工作：鼠标松开时，将 mousemove 的监听清除掉。再创建一个函数叫 `handleMouseUp`，参数也是 MouseEvent，内部只做一件很简单的事：`document.removeEventListener('mousemove', handleMove)`。最后把它绑定上：`document.addEventListener('mouseup', handleMouseUp)`。

测试：开始移动没问题。但松开鼠标时出现一个问题，元素弹回了原来的位置。说明还有遗留工作：数据流是自上而下的，坐标值从上层的属性（props）传递下来，而现在只是直接在样式中修改，松开鼠标时原来的属性并没有更改，所以元素回到原位。

现在需要在松开鼠标的时候发射一个事件，触发对应的 mutation 更新 store 中的坐标值，这样就完成了自上而下的一个轮回。下节课完成这最后的工作。
