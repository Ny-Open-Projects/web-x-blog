# 11-5-插入和简单查询

上节课用 MongoDB Node.js driver 成功连上了数据库，这节课学数据操作，先从插入开始。插入的 API 和之前 shell 里的非常相似。

首先要选择一个 collection，比如我们已经建好的 user，用 db.collection() 方法选择。和 db() 一样，有就选择，没有就新建。然后调用方法，注意这些方法都是 Promise，要用 await。user collection 上有 insertOne 和 insertMany 两个熟悉的方法，特别注意最上面的 insert 方法已过时、未来将被删除，要用下面这两个。

用 insertOne 可以插入任何想要的数据，这里插一个湖人球员：name 是 AD（安东尼·戴维斯），age 是 28。运行 ts-node index.ts，输出 connect OK，然后 acknowledged: true，insertedId 返回成功插入的 id，插入成功。

插入一条成功后演示插入多条，换成 insertMany 就行。它接受一个数组，我准备了一个叫 records 的数组，两个球员：Westbrook 和欧文·哈登。插入后输出 results，两个方法都成功了：acknowledged: true，insertedCount: 2，insertedIDs 里 0 和 1 分别对应两个 ObjectID。特别注意这个 id 不是字符串，是 MongoDB 提供的特殊数据结构，类型就叫 ObjectID，是内置类型。

插入说完说查找，查找就更有意思了，有几个没接触过的点。先把前面的插入代码注释掉，避免重复插入同样的数据。

查一条用 findOne，比如查 name 为 James 的数据（之前插入过），把结果打印出来。运行后查到 id、name James、age 36，id 类型就是刚才说的 ObjectID。查一条和 shell 没什么差异。

但查多条就不一样了。用 user collection.find()，不添加条件应该是全部查出来。结果没有如愿返回一系列数据，而是返回了一个特殊的类 FindCursor。这是个指针类，是 MongoDB 非常特殊的设计：执行读取多个结果的操作时，MongoDB 不会直接返回所有结果，因为一个查询可能包含特别多的文档，直接返回会降低查询速率。它返回一个 cursor 对象，可以分多次返回结果，减少内存消耗和带宽消耗。用过 JS 的迭代器就会发现有异曲同工之妙。文档里 access data from a cursor 介绍了 cursor 的相关信息，可以看到一系列方法都会返回指针类，find 也在其中。

有了指针，怎么读数据呢？有几种方法。第一种用 cursor 的 forEach 方法。注意 forEach 返回的是 Promise，所以要 await；而且前面 find 要把 await 去掉，直接返回 cursor 对象（叫 results 不太精确，干脆叫 cursor）。forEach 里拿到 document，在方法体内 console.log(document)。运行后成功输出，一条一条地打印出数据，我这里已经插了不少条。

第二种方法用 toArray，直接把 cursor 转成数组，简单直接暴力。但要注意这会丧失 cursor 的优化效果，数据特别大时要小心内存被爆掉。新建一个查询：const results = await userCollection.find().toArray()，然后输出 resultArray。运行后返回的是一个 array，终端里只看到一个方括号结尾，说明 cursor 被转成数组输出了。

到这里我们已经掌握了怎么循环 cursor 类的结果。但现在的查询能力还非常弱，只能按某个属性的特定值查询，高级查询无能为力。MongoDB 的查询其实非常强大，下节课学习查询的条件和逻辑。最后再强调一遍：查询多个文档时 find 返回的是 cursor 指针对象，而不是最终结果。
