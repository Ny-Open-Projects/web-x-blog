# 11-25-章总结

经过一段时间的学习，本周的内容告一段落。大家应该能感受到这是一周内容非常充实的日子，完成了很多任务，为下一步应用的实际编码打下了坚实基础。这里回顾一下本周主要完成的任务、产出的文档和代码，温故而知新。

首先这周完成的任务是后端的需求文档：根据整个应用的需求，设计了要完成的 Restful API 的一系列接口，文档已经分享出来，大家可以看一下。

然后是技术调研。我们调研了 Express 和 Koa 2 两种 Node.js 框架，它们作为最流行的两个 Node.js 后端框架，都有灵活、快速、轻量级的特点，只是在中间件的实现上是完全不同的思路。但轻量级有时候是把双刃剑：大型企业级应用需要更多规范，包括代码规范、结构的最佳实践以及良好的可扩展性。所以我们选择了基于 Koa 2 的 egg.js 作为主力框架，并使用很熟悉的 TypeScript 进行复杂开发。整体感受相信大家也感受到了：真香。

数据库方面，鉴于应用的数据特征有多变的数据结构、要保存大量 JSON 数据，我们选择了 MongoDB 这个非关系型数据库，并在其上选择了 ODM 工具 mongoose，它是搭建在 MongoDB 上层的工具。

接着是基础知识的学习。这部分内容很多同学可能接触过但掌握得不够详尽，所以我们花了大量时间深入浅出地介绍了 egg.js 和 MongoDB 的各个知识点。具体内容可以参见我提供的两个思维导图，对这种基础知识的总结，思维导图准没错。知识点非常丰富，不仅有基础也有拔高，两个地址已经分享出来，大家可以过一遍。

egg.js 这边有这么多知识点，每个上面我都添加了链接，并把知识点发散了出去：内置对象 controller、service、router、middleware；config 里这些知识点的具体规则；plugin，我们特别学习了插件开发和一份源代码解读，供大家拔高学习；extend，扩展全局内置对象；启动自定义 app，里面有一系列生命周期函数；最后是 log 日志，这是 egg.js 的内置亮点，可以分日志路径产生不同日志、日志的分类、日志的概念，还有日志级别，文件日志级别和终端日志级别等等。

这之后还产出了一个文档：数据库设计的最佳实践。它来自 MongoDB 官方的一篇文章，介绍了一对多关系时直接内嵌和引用两种方式；还有数据量不同的情况，one to few（一对几个）、one to many（一对很多）、one to squillions（一对海量），不同结构下怎样设计。最终产出了数据库设计文档，文档在这里，那张图的 PDF 也已更新，大家可以看一下。

最后是源代码分支。我们有两个源代码：一个是 OpsFlow 后端作为主要应用（目前都是基础知识），branch 名称叫 feature/week14，十四周的一系列代码；还有学习 MongoDB 数据库的单独代码库 learn-mongo，用 master 作为主要分支。

另外说一下其中提到过的两个课后作业。一是数据库设计多添加两个数据结构：category 和 tags，它们怎样跟作品结合？有可能在最终实现中不会添加，但为了锻炼大家对最佳实践的理解特别添加了，大家可以根据自己的想法和对那篇文章的读后感来设计这两种数据结构。二是 egg.js：我们已经书写了自己的插件、分析了 egg-mongoose 的源代码，希望最终使用官方版本，对自己的插件进行替换。大家可以自行完成这两个任务。

本周总结就到这里。希望大家跟着我把基础知识都打牢了，复习时可以特别参见那两个思维导图，知识点都在里面。任何大厦的根基都很重要。下周让我们一起开始业务逻辑的开发。
