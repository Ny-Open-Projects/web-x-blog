# 22-6-上传图片第三部分-使用阿里云完成上传

上节课成功获得了文件的 Buffer 对象，这节课就使用阿里云 OSS 完成文件的真正上传。关于阿里云 OSS 的使用，之前课程已经详细讲解过，本地上传那一周的第四章讲的都是使用 OSS 完成文件上传的过程，概念这里就不再细讲，直接写代码。有遗忘的话回去看一下对应章节。

首先安装依赖。之前安装的是 nuxtjs 的插件，它内部使用的就是阿里云 OSS 官方提供的 SDK，叫 ali-oss。安装很简单：`npm install ali-oss --save`。特别注意，因为是在 TS 环境下，还需要单独安装类型定义文件，也就是 `@types/ali-oss`。装这两个包就够了。

安装完毕后看怎样初始化。初始化需要四个参数，相信大家都很熟悉，在阿里云控制台都能找到对应的值。特别注意 accessKeyId 和 accessKeySecret，一看就是要保密的信息，所以要写到 .env 环境当中。我这里就不展示了，因为是敏感信息。然后把这两个配置写到 runtimeConfig 里，我已经写了 ossAccessKey 和 ossSecretKey，还有对应的覆盖方式 env，这个命名方式请大家不要忘记。和 JWT 那种方式的命名格式对比一下就想起来了，通过这种方式可以把 .env 当中的变量直接对它进行覆盖。

有了这两个配置就可以初始化并操作了。先做一点修改：上节课结束时用的是 readRawBody 这种方式，这里我们改回第一种 readMultipartFormData，因为它的信息更全一些。rawBody 只有一个 Buffer 对象，我们还需要文件名、类型等信息。修改之后特别注意 FileUploader 也要改，把 readyFile 替换成 formData 就可以了。

两处替换完毕后，第一步初始化 OSS。先 import，`import OSS from 'ali-oss'`。这里先看 formData 对象：它有可能是 undefined，也可能是空数组，只有当 formData 不是空数组时，后面的流程才有意义。所以加一个 if 判断：首先 formData 要存在，另外 formData 的 length 要大于零。另一种情况是报错，把 return 拿到成功的情况当中去。假如没有 data，说明数据传输有问题，直接 throw 掉。

初始化 store 需要先拿到配置。调用 useRuntimeConfig，从中拿到刚才创建的 oss 配置，然后在成功的条件分支里初始化，传入 endpoint、accessKeyId、accessKeySecret 和 bucket。四个参数都传入后，初始化对象就成功了，接下来就可以完成上传。

上传用哪个方法？文档当中有详细描述，直接使用 put 方法，它的功能是 add object to the bucket，也就是上传一个文件。put 有多种用法：第一种最基础的是直接传入文件路径，传入 path 后就可以完成上传；第二种是传 content Buffer，这正是我们想要的，第二个参数支持 Buffer；第三种是使用 ReadStream，也就是流的格式，第二个参数传 fs.createReadStream，这是之前描述过的方式。它可以支持三种不同的类型，我们这里使用 Buffer 的形式。

现在完成上传。先把数据拿过来，叫 uploadedData，等于 formData 的第一项。它的形式很丰富，MultipartData 里有 filename 以及原始数据等。看它的定义：data 就是我们想要的 Buffer；name 是文件名称；filename 也是文件名称；type 是它的类型。一共这四个属性。

通过它完成上传。当然我们希望把文件重命名，而不是直接使用文件本身的名称。命名规则是这样：前面是一串随机数，比如创建六位的随机数，后面的扩展名保持和之前一致，上传的是 png 就保持 png 格式。

这个工作不难。第一步要取得 filename 的扩展名，可以通过 Node.js 自带的 path 模块中的 extname 来完成，调用 extname，第一个参数把 uploadedData 上面的 filename 传进去。特别注意，filename 有可能是 undefined，但我们知道上传的肯定是一个文件，是有文件名的，所以直接使用类型断言，把它断言成 string 就可以了。拿到扩展名，叫 extension。

第二步创建一个随机的文件名。大家对 NanoID 应该非常熟悉，我们之前也大量使用它，可以创建独一无二的 ID。它自带 TypeScript 类型，直接安装一个就行，安装完毕后使用：用 nanoid 创建 fileName，希望它是六位。

有了这两部分就可以完成上传了。调用刚才的 put 方法：`await store.put(...)`，第一个参数是新的命名，前面是刚创建的 fileName，后面接上 extension，文件名就确定了；第二个参数是 uploadedData 上面的 data 属性，也就是 Buffer。最终拿到返回的 URL，把 URL 返回出去。不再需要之前的假地址了，现在用真地址。保存，这部分就完成了。

在 FileUploader 这里还要简单修改一点。之前用的是假地址，updateUrl 是写死在代码里的。现在改用 result.url，把不需要的假地址删掉。

编码应该完成了，测试是否能成功上传。刷新页面，点击 Upload，选一个头像。可以看到头像成功上传完毕了，看它返回的 URL：前面是随机的名称，后面是扩展名，如我们所想。上传成功了，整个过程比较丝滑。

当然现在会遇到一个问题：post 接口每次调用都会初始化一次 OSS 对象，但这应该是在应用启动的时候只初始化一次就够了，多次初始化是一种浪费。下节课看看怎样解决这个问题，使用 Nuxt 当中的什么概念来完成这个任务。
