# 8-16-Element Plus Upload 组件源码分析第一部分

通过上两节课总结了 Vue3 中实例的类型和不同组件之间互相访问的几种方式。这里想给大家展示的是：当你在项目中遇到一些自己之前不清楚的小知识点时，可以动用发散性思维，将这些小知识点联动起来，把相关的知识进行总结。经常这样总结，就能把知识吃得更透彻、更丰富。

## 我们自己的组件：可改进之处

现在上传组件的开发已经告一段落。虽然还有几个小功能没有带着大家完成，比如更丰富的显示支持，但我相信那个特性只是通过提供一个参数的不同值、修改产出的列表结构，大家应该都能自己完成。

代码方面有什么可以改进的地方吗？从现在的代码规格和清晰度来看，我基本满意。唯一要预防的是：当添加的特性更多时，内部实现会越来越冗长，这时就需要将实现进行适当的拆分。有了 Composition API 的 Hooks 之后，这个任务会变得简单很多。除了逻辑代码的拆分，template 的实现部分也可以拆分：下面的展示列表可以拆分成一个单独的组件，称为 UploadList；拖动部分算是一个很特殊的附加需求，可以拆分成一个组件 Dragger，处理通用的拖动需求，暴露特定的事件供父组件使用。当然，对于目前的实现和功能，重构应该伴随着功能的开发过程来进行，而不是一开始就绞尽脑汁思考该怎么重构。

## Element Plus 的组件拆分

这节课分析 Element Plus 的 uploader 源码，看看一个特别成熟、功能完善的开源库是怎样进行代码架构的，和我们的实现有什么异同。

来到 packages/upload/src 的 source code，可以看到它将组件拆分成了几个部分。第一个部分是组件主体 index.vue。它是一个 Vue 组件，但注意它没有 template，整个返回是用 render 函数写的。

先看 props，一大堆属性，和文档一一对应。然后来到 setup 部分，这里写得挺有意思：它是整个 uploader 的根组件，是数据的来源，数据要想办法共享给其他组件。最简单的方法是 props 传递；除了 props，它还使用了 provide，将整个根组件的内部实例传递进去（上节课讲过）。还有一点跟我们的想法类似：它把所有的数据操作都封装到了一个 hooks 中，称为 use-handlers。

点开 use-handlers：它将整个 props 作为函数参数传入，函数内部创建了 uploadedFiles 这个响应式对象，后面就是对上传文件列表的一系列操作，比如修改状态：handleError、handleProgress、success 等都是修改对应 file 的状态；start 当中跟我们想法一样，创建新的 file。最后把这些操作都返回出来。

从图上看：index.vue 是所有属性以及数据操作的来源，它由两部分提供数据，所有的属性，以及调用第三方函数 use-handlers 得到的数据操作和回调。另外它使用 provide 把整个 uploader 的内部实例挂了上去。这样 index.vue 上就有了所有传入的属性和 use-handlers 的数据操作，混合在一起。

## render 中的分发

有了属性和操作数据的方法，就可以往下传递了。继续看 index.vue 的 render 部分：渲染的组件分为两个，UploadList 负责上传列表的展示区域，Uploader 是 input 和上传按钮那个区域。针对这两个组件，把 setup 中返回的数据以及属性分门别类地传递。list 只传了几个属性，没什么可说的；upload 稍微复杂一点。但这两个组件是一个道理：都是属性 props 和 setup 返回的数据操作的组合。

最后是组件的返回：根据特定属性做调整，如果 listType 等于 picture-card，就返回 uploadList；不等于的话就把 uploadList 放在后面。其实就是根据 picture-card 决定 uploadList 放前面还是后面，就这么简单。

## 子组件的处理

接下来看 uploader 组件：它接受特定的属性，在里面完成上传的过程。上传过程看着非常熟悉，和我们的代码几乎一样：在上传的各个阶段调用对应的生命周期函数，触发 use-handlers 里数据的变化。里面还传入了 onRemove、onProgress、onSuccess 等一系列回调操作。UploadList 是一样的意思，更简单，源码就不看了。图上表示：传入数据后在里面进行处理，处理数据更新的是 index.vue 里的数据，数据就对应发生了变化和更新。

最后还有一个组件 Dragger.vue，被单独拿出来，是 uploader 的一个子组件。看它的源码：接受一个简单的参数 disabled，在文件 drop 以后发送一个 file 事件，把上传的 file list 发送出来，就完成了整个过程。

这里只有一点让我比较疑惑：index 上辛辛苦苦 provide 了整个 uploader 的内部实例，但我发现只在 Dragger 里简单用了一下，inject 取出来后只用了它的一个属性 uploader.accept。我不清楚作者的意图，我觉得直接使用属性传递更简单，因为它只需要传递一个属性。

## 小结

到目前为止，我们分析完了 uploader 组件的大体结构，都在预料之中。它做的事情：第一是对组件结构进行拆分，把一个大组件拆分成 index.vue、uploader、uploader-list 和 dragger 几个组件；第二是对数据处理逻辑进行拆分，使用了 hook 函数 use-handlers，把数据操作都放在里面。

但还有一个问题：它暴露出了一系列静态方法，比如 submit（手动上传文件列表），这代表要在 index.vue 里调用 uploader 组件实例上的一些方法进行手动上传等工作，最终通过 index.vue 暴露出来。它是怎样完成的呢？下节课针对这个过程做分析。谢谢大家，这节课到这里。
