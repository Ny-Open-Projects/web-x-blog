# 14-1-导学

我们的后端应用代码开发得差不多了，现在来到后端相关的最后环节：部署上线。也许大家之前并没有太多接触过这部分工作，而是由公司的专人（比如 DevOps）完成；或者有的同学在小公司，整个部署上线显得非常随意，和本地开发没有什么特别大的区别。我们这里需要一个更标准、更完美的流程，为整个线上应用保驾护航。

有同学也许会有疑问：一个前端开发是否要掌握部署的知识？我认为非常有必要。前端飞速发展的现在，大前端这个概念被不断提起。掌握相关的部署知识可以大大丰富你的整个技术武器库，让你在市场上更有竞争力。从实用性来讲，这周的内容也是非常实用的，虽然脱离了前端的范畴，但可以让你更全面地向全栈工程师发起冲击。

这周我们通过循序渐进的方式，教授的是一套非常现代（modern）、符合云原生（cloud native）概念的最流行的技术趋势，希望大家认真学习。本周的要点没什么特别的，因为会涉及大量的概念以及新的工具，最重要的我已经写在这里了：实践，实践，再实践。实践里面出真知。

再来看看会收获什么。一开始会讲 egg 应用在生产环境和本地环境的异同，由此引出一个基础知识：Node.js 的 Cluster。我们会简介它的优势、Cluster 之间的通讯，还会总结 egg 在生产环境启动时多个进程的不同种类。

有了这个基础知识作铺垫，我们来讲云服务器。因为我们的应用要部署到一台云服务器上，这里会首先调研不同的云服务器服务商，然后讲初次使用 Linux 系统时的一系列安全设置，这也是非常关键的。接着进行一个传统部署的过程，也就是假如没有 Docker，大多数人会选择的一个部署流程。

讲了传统部署的流程以后，我们介绍一个新的知识：Docker。我认为这是这个时代必须要掌握的基础工具。首先是安装，然后是 images（镜像）的操作，接着是一个新概念 container（容器）的基本概念以及进阶操作，再使用 Dockerfile 构建自定义的镜像，最后讲 Docker 多个容器之间的互相通讯。

有了多个容器以后，我们需要进行管理。这里讲解一个新工具 Docker Compose，它可以管理多个容器之间互相的关系，使用一个文件完成基本使用。这里会讲服务的权限，因为我们有 MongoDB 和 Redis，这些服务需要一定的权限保护，比如用户名、密码。然后是保存敏感信息：启动过程中会有一系列敏感信息，我们怎样保存它们。最后讲一些进阶知识，比如优化 Docker 的构建速度以及大小，最快和最小是我们追求的两大标准。

有了 Docker 的知识，就可以开始 CI/CD，也就是自动部署的概念了。首先讲工具 GitHub Actions。大家对 GitHub 可能有一些顾虑，因为它在国内访问有时不太通畅。不过对于 GitHub Actions 大家不必担忧：只要能够成功 push 代码，它就可以触发，运行环境在 GitHub 自己的服务器上，不会有任何影响。而且 GitHub Actions 是当前最好用的 CI/CD 工具，后面我们会给出一些观点和对比。对于 CI/CD，工具不是第一位的，搞清楚概念以后能在应用中实践才是最重要的。这里会讲基本概念的学习以及进阶内容，然后我们会使用一系列第三方的 Action，最后讲敏感信息的保存，也就是使用 GitHub Secrets。

有了这些基础知识以后，我们就可以使用 GitHub Actions 结合 Docker 完成自动部署了。首先来一个初级的解决方案：每次 push 代码以后，服务器每次构建本地镜像的方式完成自动部署。然后介绍一种高级的方式：每次 push 代码以后，GitHub 的服务器（Runner）自动构建，并且使用 ACR 上传镜像。这就有两个过程：第一步上传镜像，第二步服务器每次自动拉取镜像并重新运行。这个方式要比第一种高级很多。

这个内容的特点就是实用性很强，我们要学习具体的思路，并且争取能在工作中实践使用起来。这就是本周关于部署的所有内容，不多说了，让我们一起写代码吧。
