# 16-4-4-快捷键编码第三部分：添加移动元素的快捷键

这节课来完成移动元素的快捷键。移动元素本质上触发的是 `updateComponent`：拿到当前 props 里的 `left` 和 `top`，根据方向做计算，再提交更新。实现上可以单独封装一个 `moveComponent` mutation，把计算逻辑收在里面；也可以直接在 `useHotKeys` 的回调里计算后触发 `updateComponent`，两种做法都可以。

先解决上节课遗留的问题：查找当前组件的逻辑重复了多次，到处都在调 `find`。之前计划用一个 getter 来收口，现在补上。这个 getter 和 `getCurrentElement` 很像，区别是要接收一个 `id` 参数：

```ts
getElement: (state) => (id: string) => {
  return state.components.find(c => c.id === id)
}
```

不传 id 时退回到当前选中的元素，于是 `getCurrentElement` 就可以删掉了，`getElement` 不传参数时拿到的就是当前选中项。

下一个问题是在 mutation 里怎么调用 getters。官方文档没有这种用法的示例，也不推荐，但可行：把整个 store 引进来，在 store 上取。回到 index 中把 `store` 拿过来，它就是 `Store` 类型，之后就能 `store.getters.getElement(id)` 这样调用完成删除逻辑。

不过这样做有个比较致命的问题：getters 的返回值没有具体类型，是 `any`。对比之前用 `find` 时能推断出 `currentComponent` 是 `ComponentData` 类型，差了不少。进到 vuex 的类型文件里看，`Store` 类的 `state` 和 `getters` 是两个只读属性，`getters` 直接被声明成了 `any`，看起来没有给单个 getter 指定类型的方法。查 PR 和 issues 会发现有人提过同样的问题：提议给 `createStore` 增加第二个泛型 G，让 getters 获得类型，但那个 PR 还没有被 merge，所以目前 getters 只能是 `any`。想绕过只能在调用处加类型断言，两种选择看个人偏好，我个人还是更喜欢返回正确类型的写法。

回到移动的编码。创建 `moveComponent` mutation，第二个参数比较复杂，先定义类型。方向是上下左右四个定死的值，适合用字符串字面量类型：

```ts
type MoveDirection = 'up' | 'down' | 'left' | 'right'
```

payload 是一个对象，包含三个字段：`direction`（`MoveDirection` 类型）、`amount`（移动距离，number）、`id`（要移动哪个元素，string）。

实现时先拿到目标组件，这里还是用 `find`，只是 id 换成 `data.id`，然后判断存在才继续。接着取旧值：

```ts
const oldTop = parseInt(currentComponent.props.top || '0')
const oldLeft = parseInt(currentComponent.props.left || '0')
```

注意 `props.top` 是 string 类型，要转成数字；`parseInt` 的入参可能是 `string | undefined`，会有类型报错，所以要给 undefined 一个默认值 `'0'`。属性确定好之后，写代码时的自动补全会方便很多。

四种情形的计算适合用 `switch`：

```ts
switch (data.direction) {
  case 'up': {
    const newValue = oldTop - data.amount + 'px'
    store.commit('updateComponent', { key: 'top', value: newValue, id: data.id })
    break
  }
  default:
    break
}
```

向上移动就是减小 `top`，新值等于旧值减去 `amount`，再拼上 `px` 单位。这里出现了在一个 mutation 中调用另一个 mutation，同样是通过 store 上的 `commit` 完成，key 是 `top`，value 是新算出的值，id 用 `data.id`。写完记得 `break`，并补一个 `default: break`。

up 这种情况写完后，就可以在 hot keys 里响应了。创建一个向上的 `useHotKeys('up', ...)`，内部直接提交 `moveComponent`。这里又暴露了 vuex 的 `useStore` 不方便的地方：它没法很好地约束 commit 的第二个参数类型，第二个参数应该传什么 object 本可以完全确定，算是 vuex 类型定义需要改进的点。这里只能手动写：`direction` 为 `'up'`，`amount` 为 1，`id` 用 `currentId.value`。

测试一下：点击上键，元素确实向上移动了。但发现一个问题：如果页面滚动条在下面，滚动条会跟着一起动，这个 bug 后面再修。其余三个方向照猫画虎即可，添加对应的 hotkey 和处理分支就行。

到这里快捷键功能就添加完毕了。
