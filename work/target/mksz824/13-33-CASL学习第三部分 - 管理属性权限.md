# 13-33-CASL学习第三部分 - 管理属性权限

这节课继续学习 CASL，内容是最复杂的针对每一个实体的属性管理，这也是一个非常常见的需求。用一个例子来讲解：现在的用户有 VIP（付费用户）和普通用户，我们希望 VIP 可以更新 work 的三个字段，包括还没有添加的 title、content 和 uuid。VIP 有一个特权，可以修改每个作品的 uuid，从而使用个性化的 URL；而普通用户 normalUser 只能更新作品的 title 和 content，不能自定义个性化的 uuid。

现在可以这样写。因为两者要分开，把原来共用的 update 删掉，分别拷贝两份，read 也拷贝过来。处理的是 update 请求：can 和 cannot 的第三个参数可以修改为一个数组，用来限定可以修改的属性 key，第四个参数还是对应的 condition。VIP 用户可以修改 title、content 还有 uuid；普通用户复制过来后把 uuid 删掉，不能修改 uuid。这样就完成了属性的限定。

有了这个设置，就可以检查是否可以修改对应属性了。先把数据修改一下，把 title、content 和 uuid 属性添加上去，并把名称改一下：normalWork 是普通用户创建的作品，author 对应 2；VIPWork 是付费用户创建的作品，id 对应 3。再把测试语句里的实体名称换成 normalWork 和 VIPWork，确认没有错误。

先检查 VIP 用户是否可以更新对应的字段。多添加几行 console.log，叫 VIP update，用 rulesTwo，还是 can('update', ...)，实体是 VIPWork 它自己的作品。先测试 title 是否可以更新，再复制一条测试 uuid。期望值是两个都返回 true。运行 ts-node casl.ts，VIP update 都返回了 true，说明都可以更新。

同理检查普通用户 normalWork 是否可以更新，放到下面，叫 normal update，一个 title 一个 uuid。我们希望 uuid 是不能更新的，应该返回 false。运行结果没问题，uuid 返回了 false，第一个需求完成。

当然这样做还不能满足我们的需求。我们希望能获得当前角色能够修改实体的所有字段，比如返回一个数组，然后和请求发送过来的字段（比如 patch 方法的 request.body 中的字段）进行对比，有非法字段就过滤掉。这需要一个新的内置方法，文档里叫 permittedFieldsOf，把它导入进来。

使用它之前，还要规定现在所有能够修改的字段。我给大家复制一个数组 workFields，意思是假如某条规则没有限定 fields（就是这样的规则），就会返回所有字段，说明所有字段都可以修改。另外还需要创建一个 options，里面有一个特殊的 key 叫 onlyFrom，要检查这一系列 fields 是从哪里来。它接受一个箭头函数，参数 rule 就是 CASL 创建的一系列 rule，rule 上有一个 fields 属性，对应的就是设定规则时传入的值，假如没有 fields 就代表所有都能更新。把它设置成返回 rule.fields。这段代码官方文档里都有，搞不清楚的话可以回顾讲解再看文档，照着这种写法写就可以了，不必深入追究。

有了 options 就可以进行获取了。新加一个注释叫 checkAllowedFields，检查可以使用的字段。定义 fieldsOne，调用 permittedFieldsOf，第一个参数传入 rulesTwo（要检查 VIP 用户可以更新哪些字段），然后是动作 update，作品 VIPWork，最后把 options 传进去，就完成了。console 出来看看哪些是它允许的。再把普通用户的拿出来，直接复制，叫 fieldsTwo，参数换成 rulesThree、update、normalWork、options。

运行 casl.ts 看最下面的结果：VIP 用户可以更新 title、content 和 uuid；普通用户只能更新 title 和 content，和一开始定义的一致。

拿到 fields 后要完成最后一步工作。我们现在有了每个角色针对不同实体的权限，可以想象一个场景：普通用户调用更新接口更新对应的 work，但是传入了这样的数据结构。normalUserRequest 的 request.body 里有 title 和 content，这是可以更新的，但还传了 uuid。我们都知道只有 VIP 才能修改这个字段，所以要阻止它修改 uuid，在 MongoDB 使用 findOneAndUpdate 之前要把这个字段过滤掉。

所以需要从刚才获取的数组出发，从 request.body 中摘取它可以修改的字段，再进行更新。可以用 lodash 的一个函数，大家自己去安装 lodash（用过多次了，我这里不装），注意也要安装它对应的定义文件，因为它没有自带定义文件。

使用的是 pick：lodash.pick。创建一个新的变量 rawWork，这是过滤以后的 work。第一个参数传入 requestBody，第二个参数传入一个数组，也就是要摘取哪些 fields，这里传我们已经拿到的普通用户允许的字段 fieldsTwo。然后 console 出来，名称叫 normal user after filter，打印 rawWork。注意这里应该用 fieldsTwo 而不是 fieldsOne，fieldsOne 是 VIP 用户的，我们现在处理的是普通用户。

修改完毕，运行 ts-node casl.ts，可以看到 normal user after filter 只剩下它允许的 title 和 content。这时就可以放心大胆地把它交给 update 在数据库里进行更新了。

这节课我们学习了 CASL 针对属性的权限管理。到这里 CASL 的基础知识告一段落，我们发现它不仅有简明的语法，还有强大的功能，所有的权限设置都可以在里面完成。下节课将它和我们的系统结合在一起，实现对应的功能。
