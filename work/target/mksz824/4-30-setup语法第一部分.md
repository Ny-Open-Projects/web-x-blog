# 4-30-setup语法第一部分

这节课讲 Vue3.2 推出的 setup 语法糖。示例代码最早就是采用这种模式写的，它已经作为各种脚手架默认生成的代码模式。如果还有印象，会记得 script 上有一个奇怪的属性叫 setup。我们一开始没有使用它，是想带着大家了解 Vue3 组件原始写法的来龙去脉，最后再切换成语法糖，理解会更透彻。

## 版本与定位

首先要搞清楚：这个特性是 Vue3.2 及以上版本才支持的，学习前先确认你的 Vue 版本。setup 语法本质上就是组合式 API 的语法糖，最终和普通 script 写出的内容殊途同归，目的只是提供更多便利。官网列出的优点有四条：更少的样板内容、更简洁的代码；能够使用纯 TypeScript 声明 props 和抛出的事件；更好的运行时性能；更好的 IDE 类型推断性能。

## 用不用？

好坏见仁见智。有人认为"想使用什么就返回什么"的写法更清晰，setup 让值不知道从哪来，看着糊涂；还有人认为它有太多不像普通 JavaScript 的语法内容。用不用按自己的爱好来，没有硬性规定。顺便说明，我们后面的课程都将使用 setup 语法糖，也推荐大家和官网保持一致。

## 基本用法

最简单的用法就是在 script 上添加 setup 属性。使用之后，在这个 script 中声明的顶层绑定，包括变量、函数以及 import 引入的内容，都能在模板中直接使用。所以改造方式是：删掉 defineComponent 的外壳和 setup 函数，只留里面的逻辑；return 也不需要了，它会自动处理。

保存后页面没有任何报错，所有功能照常运作。变量、函数都验证过了，再验证 import 的内容：引入自定义组件 MyProfile，不需要像原来一样在 defineComponent 的 components 属性上注册，引入后直接就能在模板里使用：

```html
<MyProfile :user="user" />
```

组件正常显示，功能也正常。对 MyProfile 做同样的改造：删掉外层结构，留下 setup 里的内容，script 上加 setup 属性，修改就完成了。代码简洁了很多，看起来也舒服。

不过这时会发现有些原有功能在 setup 里暂时没法实现，比如定义 props、定义 emits 等。下一节课继续讲这种语法和 TS 相关的高级用法。
