# 12-6-规范化错误信息和错误码

上节课用 egg-validate 添加了验证，但验证信息还没有固定格式，直接写死在函数里。我们希望把所有错误统一管理，能想到的办法就是添加一个对象来完成错误的统一管理。这里把验证错误添加到 controller 当中；如果你愿意，也可以单独放在一个文件里，模块性更好，按自己的喜好来。

## 统一错误对象

添加 `export const userErrorMessages`，key-value 形式。key 最好写得长一点，能描述请求错误的类型。第一个需要描述的类型是"创建用户时验证失败"，就叫 createUserValidateFail。每个条目有两个字段：errorNumber 和 message。

## 错误码方案

设置 errorNumber 需要一个方案。网上目前没有比较成熟或通用的方案，这里参考了几个互联网巨头的设计方法，结合项目实践设计了一套自己的方案，分享给大家。

统一格式是 `a-bb-ccc`，分成三段：

- a 代表错误级别：1 代表系统级错误，2 代表服务级错误；
- bb 代表项目或模块编号。一般公司不会超过 99 个项目，两位数够用。用户模块是第一个模块，用 01；
- ccc 代表具体错误的编号，自增即可，一个项目 999 种错误也应该够用。

所以第一个错误类型就是 101001：1 代表系统级错误，01 是用户模块，001 是第一个错误，message 为"创建用户验证失败"。

## 改造 helper.error

现在改造 error 函数，让它可以传入错误类型，而不是手动填写一系列内容。修改 helper：import 刚才的 userErrorMessages，函数签名改成 `error(ctx: Context, errorType: keyof typeof userErrorMessages, error?: any)`。

说明两点：errorType 指代的就是对象里的 key。这些 key 是很长的字符串，手写很容易写错，所以要用 TS 帮忙，用 `keyof typeof userErrorMessages` 拿到对象所有 key 的联合类型。第三个参数 error 是你想附加的自定义数据，类型不限，可选。

函数体里先取 `userErrorMessages[errorType]`，从中拿到 errorNumber 和 message 分别赋值。对于可选的 error，要判断它存在才往 ctx.body 上添加一个属性。很多同学会写 if 判断再加一行赋值，要写好几行；这里可以用一行代码搞定，而且这个技巧在其他场景也通用：在对象展开符里写一个表达式，`...(error && { error })`，error 存在时才展开进这个对象，非常方便。

改造完毕后调用试试：参数第一个传 errorType，编辑器自动联想出了 createUserValidateFail，非常方便；第二个把 errors 作为自定义错误传进去。测试点击 Send，返回 errorNumber 101001、message 创建用户验证失败，并且具体的错误信息也附在里面，用户可以直接观测到问题所在。

## 处理重复用户名

第一个任务完成，再添加一个验证场景。先观察一个现象：用之前添加过的数据再添加一次，直接报了一个 500 错误，内容其实是数据库抛出来的错误，意思是 username 字段是唯一的，重复插入会报错。这个唯一性是在 model 里定义的 `unique: true`，它的原理是 MongoDB 在字段上建立索引（比如 OpsFlow users 集合里的 username_1 这个索引），索引已存在同样的值，再创建就会报错。

数据库错误直接透出非常不友好，所以要先加一层检查。先添加对应的错误信息：key 叫 createUserAlreadyExists（同样写得长一点），errorNumber 101002，message 是"邮箱已经被注册，请直接登录"。

实现上，先要在插入之前查一下数据是否存在。在 service 中添加一个方法 `findByName(username: string)`，调用 `this.ctx.model.user.findOne({ username })`，按 username 字段查找。

然后在 controller 的 createByEmail 里、调用 create 之前进行查询：从 `ctx.request.body` 中拿出 username，`const user = await service.user.findByName(username)`。如果 user 已存在，就直接 return `ctx.helper.error(ctx, 'createUserAlreadyExists')`，errorType 用我们添加的第二个类型。

## 测试

用已经注册过的数据点击 Send，返回 errorNumber 101002，message 是"邮箱已经被注册，请直接登录"，符合预期。

这节课完成了错误信息的统一添加。归类以后代码清爽了很多，错误信息可以自动带出来，统一管理之后所有错误都在一个地方维护，其他地方不用管。你还可以创建一个 errors 文件夹，把各种实体的错误信息按文件类型分文件存放，抽象程度看自己的需求。我们暂时把错误信息写在 controller 里，后面有需求再抽离出去。
