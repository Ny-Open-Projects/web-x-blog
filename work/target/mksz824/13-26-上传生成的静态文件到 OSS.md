# 13-26-上传生成的静态文件到 OSS

上节课我们完成了 SSR 的实现，页面已经能够比较完美地展示作品了。这个页面里引用的静态文件来自 public 文件夹，靠 egg-static 插件提供支持。我们之前说过，Node.js 展示静态文件并不是它的强项，而且上传图片已经有了对应的 OSS。如果在生产环境中直接使用 OSS 里的静态文件，速度肯定更快；而开发环境就没必要用 OSS 上传浪费带宽，直接用 public 文件夹即可。

所以任务就明确了：在生产环境渲染作品页面时多加一步，静态文件生成以后上传到 OSS，甚至可以配置 CDN 进一步加快加载速度。

第一步完成上传。我在 webpack 文件夹同级的位置创建了一个脚本文件 upload-to-oss.js。大家知道，之前上传用的是插件，在 utilities 中我们多次使用 `ctx.oss.put` 这个方法。oss 实例来自于 context，但看过它的源码就知道，`ctx.oss` 其实就是阿里 oss 包的一个实例。所以现在我们自己创建这个实例。

先引入阿里 oss，require('ali-oss')，然后 `const client = new OSS({...})` 创建实例。参数之前是用环境变量添加的，现在也用环境变量，可以使用同一套代码，所以需要 dotenv。参考 config.default.ts 里的用法，把 dotenv 引进来（这里用 require 的写法），调用 dotenv 的 config 方法就能完成加载。

但是如果你完全照搬原来的写法，就会报错，找不到 .env 文件。这是为什么？看一下文档，config 会读取 .env 文件、解析内容并赋值给 process.env，路径是这样确定的：默认 path 是 `path.resolve(process.cwd(), '.env')`。process.cwd 代表 Node.js 进程当前的工作目录。在应用里打印 process.cwd 会发现它不是 config 文件夹，而是整个 OpsFlow 后端的根目录，所以能直接找到 .env 文件。但我们运行这个脚本时，工作目录是 webpack 文件夹，什么都不加就会报找不到 .env 的错误。所以这里要手动指定 path 参数。

要指定 path 就把 path 模块拿过来操作路径。路径应该是从当前目录向上一级到达根目录，再拼接 .env 文件，这样就能拿到环境变量了。有了环境变量，按照原来的参数一一填进去，AccessKeyId、AccessKeySecret、bucket、endpoint，大家自己补齐，我这里加几行注释说明是设置环境变量和新建实例。

有了实例就可以上传了。写一个入口 async function run，里面使用 async/await。第一步是把文件拿出来，也就是从文件夹获取文件列表。这个文件夹是 public，所以设置一个 publicPath 变量指向 public 文件夹。获取里面的所有文件可以用 fs 上的方法：`fs.readdirSync(publicPath)`（把 fs require 进来）。public 里除了 JS 和 CSS 静态文件，还有 page.html，这个文件我们要忽略，不希望它上传上去，所以做一个 filter：`files = publicFiles.filter(f => f !== 'page.html')`。

下一步是上传。上传方法是 promise，所以直接用一个 promise 数组：`Promise.all(files.map(async filename => {...}))`。上传的写法大家都已经很熟悉了，再写一遍加强记忆。第一个是 saveOssPath，希望存在哪里？这里新建一个文件夹，path.join 拼一个 h5ss 文件夹加上 filename。第二个是 filePath，从哪里读取文件？自然是 path.join 拼接 publicPath 和 filename。有了这两个就可以调用我们一直使用的 `await client.put(saveOssPath, filePath)`，两个参数分别是存到哪里和来自哪里。最后把 result.url 取出来 return 回去。

这样 promise 部分就写完了。在 Promise.all 的结果上 console.log 一下"上传成功"和 response，最后调用 run() 即可。整个脚本其实跟之前写的非常类似，只不过现在要从文件夹读取一系列文件再逐一上传。另外一个注意点就是设置环境变量时要手动指定 path，因为脚本的工作目录不是根目录。

现在验证上传脚本能否成功运行。在 package.json 中添加一个 script，叫 upload，内容是 `node webpack/upload-to-oss.js`。测试一下：clear 之后运行 npm run upload，很快就返回上传成功，并且输出了 OSS 对应的地址 h5ss 加文件名，生产环境就可以使用这些文件了。
