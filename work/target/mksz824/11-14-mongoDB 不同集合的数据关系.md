# 11-14-mongoDB 不同集合的数据关系

上节课讲了索引，这节课讲基础知识最后一个知识点：数据之间的关系。之前的内容都在描述单个集合的操作，我们一直在 user 里折腾。但真实数据肯定有多个集合，集合之间会产生关系，也就是传统说的一对一、一对多、多对多。

在 MongoDB 中实现关系有两种手段。第一种叫内嵌：像我们的用户数据，针对一个用户的爱好，创建 hobbies 数组，把爱好信息都添加到数组里，这就是内嵌方式。另一种叫引用：引用式关系是设计数据库时经常用到的方法，把不同的实体按多个集合分开，通过引用文档的唯一标识符（也就是 _id）建立对应关系。具体选哪种形式，后面数据库设计的时候会详细说明。这里先学引用应该怎么做。

为了演示，我新建了一个叫 team（球队）的集合。球队和球员是一对多关系，一个球队可以有多个球员。新建了两条球队数据：Lakers 湖人队和 Nets 篮网队。

第一种引用方式：在球员（也就是我们的用户）中添加特殊字段来引用球队信息。我添加了两条数据：LeBron 中加了 team 字段引用它对应的球队，也就是 Lakers 的 ID，可以看到这两个 ID 的值是相同的；第二条霍华德也创建了对应的 team 信息。大家可以自行创建这样的数据。

这种方式下怎么查询一个球队所有球员的信息呢？我新建了一个脚本 relation.ts，因为之前 index.ts 里的代码已经比较多了，套路还是一样。我把两个 collection 单独取出来，一个 teamCollection，一个 userCollection。先查球队信息：const lakerTeam = await teamCollection.findOne({name: 'Lakers'})，拿到球队信息后用它的 ID 查球员：const players = await userCollection.find({team: lakerTeam._id})，因为查多个用 find，最后注意要 toArray，因为 find 返回的是 cursor 对象。运行 ts-node relation.ts，通过这种方式就查到了一个球队下面所有球员的信息，LeBron 和霍华德都出现了。注意这种引用查询至少要用两次 query 才能完成任务。当然也可以通过球员反查球队信息：先拿到某个球员，想知道 LeBron 在哪个球队，反查和这个非常相似，就不演示了。

第二种引用方式反过来：刚才是在球员信息里引用球队，现在可以在球队里插入一个数组，数组代表多个球员，把球员的 ID 都包含在内，球员那边就不需要引用信息了。我加了哈登和杜兰特两条数据，都在篮网下面，他们的 ID 已添加到球队数据里，注意这两个球员我没有添加球队的引用信息。演示查询一个球队的所有球员：第一步还是拿到 team，叫 netTeam，findOne 的 name 应该是 Nets。第二步查球员：const netPlayers = await userCollection.find(...)，区别在 find 的条件。现在手里是一系列 ID 的数组，要查"ID 是否在这个数组当中"，可以用一个特殊的操作符 $in，它判断数组中有没有对应的 ID，写 {team: {$in: netTeam.players}}，条件就写完了。区别在于：第一种方式直接拿到 team 的 ID 做字段查询，第二种拿到的是数组，要在数组范围内查询。toArray 后运行 relation.ts，上面是 Lakers 的查询结果，下面是篮网队的球员信息，哈登、杜兰特两条都包含在内。

这两种方式都能实现两个集合一对多的关系，关键是 ID 的引用。至于现实中选哪种方案，数据库设计时会针对不同情况讨论，非常灵活。注意这两种情况我们都需要查询两次，写两个 query 才能拿到最终结果。有没有更简单的方式，一次 query 就拿到结果呢？答案是肯定的，下节课学通过特殊操作符一次查询拿到引用的结果。
