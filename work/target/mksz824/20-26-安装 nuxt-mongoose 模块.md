# 20-26-安装 nuxt-mongoose 模块

这节课探讨 Nuxt 3 中一个很重要的特性：modules（模块）。上节课我们用两节讲了两种插件（服务器端插件和 Nuxt 应用插件），这节课说 modules。

modules 我认为也是 Nuxt 3 的关键特性之一。它允许开发者使用预置的、独立的模块来扩展和定制整个 Nuxt 应用。简言之，modules 是一种将功能组织和封装起来的方式，让开发更加模块化、可维护。所以 modules 不是 server 端独有的概念，而是整个 Nuxt 应用的概念，可以扩展方方面面。

可以认为模块是比插件更大的概念，模块可以包括插件，一个模块是应用的一个子集。官方有个模块市场，有点像 Nuxt 旗下的 App Store：想要什么内容都可以在这里查看，比如 Tailwind、ESLint 等都能找到。想在 Nuxt 中使用一个第三方模块，先到 modules 市场搜索，有的话安装非常方便，比手动安装省很多步骤，还会带来很多优点。

modules 的优点：

1. 简化开发流程。提供了一种简单快捷的方式，把常用功能封装成模块，减少重复的代码编写和配置，直接使用模块而不需要从头编写功能逻辑。
2. 提供一致的项目流程。它的设计原则就是将通用功能标准化，使开发团队可以更轻松地合作和共享代码。
3. 强大的生态系统支持。生态中已经有很多广泛使用的 modules，从自动化部署到国际化都可以通过简单配置一键引入，给开发者提供了各种解决方案，节省时间和精力。

至于 modules 怎样编写，这里不深入，我们做到会用就可以。有兴趣的话可以去看官方的文章，写得很详细。最后看文档说的一个 modules 能提供哪些功能。对 Nuxt App，它可以提供三项扩展：Vue 的全局组件、组合式函数、Nuxt Plugins。对 Server 端，它能做的更多：自动注册一系列 API 路由、添加 middleware 中间件、添加后端 plugins，还可以按需求添加一系列静态文件，比如样式、图片、3D 模型等。

回到应用，用现实场景学习这个知识点。和之前的后端项目相比，现在后端有了 Redis，自然还需要数据库。我们还是使用 Mongoose 来连接 MongoDB 数据库，并用对应的模块举例。

在模块市场搜索 mongoose，就能找到 nuxt-mongoose 模块，点进去有对应的规范和使用方式可以参考。第一步安装（我已安装过，直接启动应用），第二步把模块加进配置。在 nuxt.config.ts 下有 modules 这个数组，每个模块是数组中的一项，把 nuxt-mongoose 添加进去。

模块还需要配置。配置在 nuxt.config 中的 mongoose 选项下，最重要的是 uri，也就是连接地址。填地址前先确认本地 MongoDB 已启动。确认后把 uri 填进去，我本地是 27017 端口，直接复制。保存后看终端，输出了一行 connected to MongoDB，说明成功连上了，Mongo 的配置就结束了。

不过我们还是希望把这个地址写到 .env 中，因为连接串里可能含有比较私密的信息，比如地址、用户名密码都可能出现在 URL 中。文档提供了一个环境变量来完成这个工作：只要提供了对应的环境变量，就会自动替换。把变量名 NUXT_MONGOOSE_URI 拿到 .env 中添加，有了它就不需要 uri 选项了，甚至整个 mongoose 对象都可以去掉。保存后重启应用，终端依然显示 connected to MongoDB，添加成功。使用环境变量的形式比原来更安全、更方便。

这节课初步使用了 Nuxt 的 modules 概念，并安装了其中的 nuxt-mongoose。下节课继续用这个模块做数据库的查询及配置。
