# 7-20-TDD 第三步：和应用整合

上节课我们用 TDD 的方式开发出了 ColorPicker 组件，但根本没有在页面中测试使用它。它是否真能胜任对应的任务？相信大家和我一样内心都在打鼓。现在就把它放进真正的应用里看看好不好用。

首先在 Editor 的初始数据中给属性添加 color 测试属性。如果你愿意，还可以把这些数据和之前定义的 defaultProps 做一个混入，让每个组件都能显示对应的属性，我这里简单改一下，想做的同学可以课后自己完成。把第一个属性的值替换成黑色的十六进制颜色，只测第一个，其他两个就不测了。

接下来在 propsMap 中添加对应关系。目前还没有 color 的映射，添加上去：component 是我们自研的 ColorPicker，text 是字体颜色。然后把 ColorPicker 组件添加到 propsTable 中，因为自研组件没有全局注册，使用时要自行引入：在 renderNode 后面写上 color-picker，对应 ColorPicker.vue，并把它放到 components 里。到这里应该都添加完了，怀着疑惑的心情打开页面看看。

记得我们给第一个属性加了 color，点开 Hello，颜色选择器出现了，但下面的十个小方块没有出现。没关系，这是样式问题。先测功能：点击任何选色的地方，都可以实时更新，没问题。

现在做一个小重构，给它添加样式。我这里已经写好了，大家也可以自己写，直接粘贴到 ColorPicker.vue 空的 style 里就行。我主要用 flex 布局完成左右两列和右侧五列的布局，最后注意里面添加了一个透明的背景图，用于颜色列表的最后一位，也就是测试里那个 transparent-background。样式文件提交到 Git 之后，大家可以自行复制使用。保存后看效果：样式都出来了，变得很好看。左侧刚才已经测过没问题，右侧点击每个色块，color 也随之对应变化。最后一项是特殊的透明背景，背景其实是张图片，点击它会删除 color 里的颜色属性，让它变回默认值。

这个组件用 TDD 的开发方式就完美完成了。经过这次实践的洗礼，相信大家能感受到 TDD 的一些特点。简单总结一下：它就是一个循环，或者说一个口号。第一步是不可运行：写一个功能最小完备的单元测试，让这些单元测试编译失败，红框红叉出现。然后是可运行：快速编写刚刚能使测试通过的代码，这时可以不用考虑太多。最后是重构（refactor）：消除刚刚编码过程中引入的重复设计，对代码或结构做优化。这个过程可以循环进行。我们这个组件功能比较简单，没有完成两次循环，但一次循环大家应该已经能感受到了。

那么采用 TDD 的动机是什么呢？第一个动机很有意思：有一个现象，当我们感到编码压力越大、任务越困难的时候，自身就越不想去做足够多的测试；而当你知道自己测试不够时，反而会增加心理压力，因为担心代码有 bug，对自己写的代码不够自信，这是一种心态上的变化。测试就是开发人员的试金石，它把对压力的恐惧变成平日的例行任务；采用自动化测试，就有机会选择你克服恐惧的程度。

第二个动机也挺有意思：它可以把编程过程任务化。如果做了一个星期的功能规划，就可以把它量化成一个个可操作的任务，写进 To Do List，然后使用测试驱动编码：把任务一个个写成测试用例，完成一个就划掉一个。工作目标会变得非常清晰，因为明确了工期、待办事项和难点，就可以对进度做更精确的把握。

TDD 的过程就介绍到这里。不知道这种开发方式是否合你的口味？在未来的开发生涯中，你会使用它吗？到这里，谢谢大家，再见。
