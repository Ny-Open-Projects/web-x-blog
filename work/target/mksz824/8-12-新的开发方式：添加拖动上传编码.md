# 8-12-新的开发方式：添加拖动上传编码

上节课回顾了中期任务，不知道大家完成得怎么样。这节课完成需求中比较靠后的一个任务：拖拽上传，它属于视觉和交互方面的增强。这节课的重点是完成 drag and drop 功能，它应该通过一个属性控制是否开启。我已添加了一个叫 drag 的 props，type 是布尔值，默认是 false。

开启的时候，在触发点击的区域应该支持一系列 drag 事件。看一下具体交互，这里画了一个简易的交互图：支持 drag 时，会把区域修饰得大一点，更容易交互，这是样式问题，大家可以按自己的爱好装扮。然后给这块区域添加一系列 drag 事件，相关的事件有三种：

- dragover：文件被拖动到这个区域时触发。要做的其实是增强视觉效果，添加一个 class，称为 is-dragover，加上之后大家可以自己修饰它的样式，让用户知道文件已经拖动到上面了。
- dragleave：文件被拖出这个区域时触发，这时只要移除这个 class，回到原来的状态即可。这里肯定需要一个响应式对象来管理 class 的添加。
- drop：在这个区域里松开鼠标时触发，文件被 drop 进来。这时从 drop 的事件对象里拿到上传的文件，完成上传过程。

## 换一种开发方式

有了需求，要做的事情已经非常清楚。这里换一种开发方式，不使用 TDD：这个需求和界面非常强绑定，单元测试模拟的事件有可能无法达到我们要求的精度。所以这节课先写代码，在界面上测试，之后再添加单元测试。开发方式是可以根据具体需求和喜好调整的。

根据需求，得到几个要完成的点：一是 dragover 和 dragleave 添加或删除对应的 class；二是 drop 事件拿到正在被拖拽的文件，做两件事，删除 class 并触发上传；三是要特别注意，只有在 drag 属性为 true 时这些事件才生效。把需求分割成多个小的点大有裨益，尤其是在已经比较大的组件中添加新功能时，可以保证思路清晰。

## 编码实现

我把代码稍微重构了一下：多添加了一个函数 uploadFiles，因为文件上传流程现在要在两处调用（input change 时和 drop 时），所以单独拎出来做成函数。

先处理第一个任务。添加响应式对象 isDragover，初始值 false。创建函数 handleDrag，事件对象是 DragEvent，并加第二个参数 over，想让布尔值变成 true 还是 false，代表 class 添加或不添加。函数内首先 `e.preventDefault()`，这很重要：drag 有一些默认行为，比如拖动图片到浏览器里会用新 tab 打开这张图，需要把这些默认行为都取消掉。然后把 `isDragover.value = over`，任务完成。把 isDragover return 出去，并添加动态 class 到上传区域：class 名为 is-dragover，生效条件有两个，开启了 drag 属性，并且 isDragover 为 true。

第二个任务是添加 drop 事件处理。写 handleDrop，参数还是 DragEvent，同样别忘了 preventDefault。要做两件事：第一件，把 isDragover 置成 false；第二件，从 drop 事件里拿到 files 数据。怎么拿？可以求助 DragEvent 上的一个神奇属性。查文档：DragEvent 上有一个 DataTransfer，"用于保存拖动并放下过程中的数据"，它上面有一个我们很熟悉的属性 files，也是一个 FileList 类型，和我们之前使用的 `target.files` 完美对应。由于 e.dataTransfer 有可能是 undefined，先判断它存在，再调用 `uploadFiles(e.dataTransfer.files)`。

第三个任务是把 dragover、dragleave、drop 以及已有的 click 这些 handler 添加到最上面的 upload-area。Vue template 中添加多个事件可以用 v-on="object" 的写法，之前其实已经用过。创建一个 events 对象：它的类型是 `{ [key: string]: (e: any) => void }`，key 是 string，值是接收事件对象（不同事件的类型不一样，这里用 any）返回 void 的函数。第一个事件自然是 click，对应已有的 triggerUpload。然后 if (props.drag) 存在时给 events 重新赋值：展开之前的 events，再添加 dragover、dragleave 和 drop 三个事件。注意 dragover 和 dragleave 都调用 handleDrag，分别传 true 和 false，这样一个函数就省了一个。最后把 events return 出去，模板上删掉原来的单独绑定，改用 v-on="events"。

至此整个编码工作完成。事先分析需求以后，对要做的事非常清楚，可以井井有条地逐项完成。下节课看看它在真实应用中的效果是否完美，以及测试应该怎样写。谢谢大家。
