# 17-6-6-跳转路由前提示保存

上节做了自动保存，这节再加一个保存的增强功能：离开编辑器时弹出提醒，提示用户保存。这需要获取离开路由的钩子函数。做权限管理时我们用过 router 实例上的钩子函数 beforeEach，在每个路由进入前触发；但这次要的不是全局逻辑，而是针对一个具体路由的操作。Vue Router 在文档的 Composition API 一节提供了对应的 hook：onBeforeRouteLeave（离开路由前触发）和 onBeforeRouteUpdate（路由更新前触发），我们用前者。它的参数同样是熟悉的 navigation guard 回调，三个参数：to、from、next。

## 编写逻辑

到 editorView 中，从 vue-router 引入 onBeforeRouteLeave，逻辑加在 setup 末尾。有一点和全局 beforeEach 不同：在 index.ts 的 beforeEach 里我们没用 next，直接 return 新路由或不返回就继续；**但在这个钩子函数里必须调用 next 指引下一步处理**，什么都不 return 是不会继续的。

首先判断 isDirty，数据是否脏了。有改动才弹提示。提示用 Ant Design Vue 的 Modal：它有组件形式的调用，也有更简洁的 `Modal.confirm` 语法糖，后者更适合这里。引入 Modal 后：

```ts
onBeforeRouteLeave(async (to, from, next) => {
  if (!isDirty.value) {
    next()
    return
  }
  Modal.confirm({
    title: '提示',
    okText: '保存',
    okType: 'primary',
    cancelText: '不保存',
    onOk: async () => {
      await saveWork()
      next()
    },
    onCancel: () => next(),
  })
})
```

confirm 接受一个 object，参数名都很直白：title 是显示的标题，okText 是确认按钮上的文字，okType 是 primary 之类的按钮类型，cancelText 是取消按钮上的文字。两个回调很关键：onOk 在点击确认时执行，先 await saveWork，保存完毕后用 next 跳转；onCancel 在直接点击取消时执行，直接 next 即可。最后别忘了 else 分支：数据没改过就直接 next，不做任何处理。

## 验证

页面测试：故意改一下数据（加个斜体），然后点击跳转首页的路由，弹出"是否保存"；点击保存，很快出现 loading，值被保存下来。离开前提示保存的功能完成。

顺带一提：关闭编辑器窗口时也应弹出同样的提示，原理完全一样，只是要监控另一个事件，window 的 onbeforeunload，代码逻辑与此处一致，可以自行添加。

随着 editor 功能越来越多，setup 函数体内的逻辑也在增加，代码越来越冗长。虽然最早用插件抽离了一部分，但保存作品逻辑加入后代码量又涨了上去。下节研究有没有简单易用的方法让代码更有条理。
