# 19-1-1-前言

这一周来完成大型项目开发完毕之后的过程：把本地运行的项目编译成符合线上要求的版本，然后部署上线，并尽可能完成性能优化。对用户访问的页面来说，时间就是金钱，多加载一秒都可能面临用户跳出，所以这块内容非常重要。

这一周以实践为主，从项目出发、以数据为依托，没有多少虚头巴脑的概念，都是为优化服务的干货。优化手段很多，但优化的本质就是两件事：减少代码体积、加快响应速度，这周也以这两个宗旨为脉络。难度中等，但这部分内容是面试中非常容易出现的，希望大家从整个过程中总结出属于自己的方法论，用这方面的经验打动面试官。

说说这周的知识点。第一部分是编译。我们的编译依靠 Vue CLI，会先介绍几种环境的概念：开发环境、预发布环境和正式的 production 生产环境，需要为不同的环境打包不同的代码。然后是 Vue CLI 中的模式，讲怎样适配这几种环境，以及怎样使用环境变量文件，往里面插入一系列环境变量。

Vue CLI 底层打包使用的是 Webpack，所以要先学 Webpack 的基础，这部分很多人已经掌握；然后会拔高：Webpack 有两个重要概念，Loader 和 Plugin，我们会手写一个 Loader、手写一个 Plugin，让大家知道它们内在是怎样运作的。

之后进入优化环节，需要个性化 Vue CLI 的编译来做打包分析和优化，这就用到一系列 Webpack 配置。我们知道 vue.config.js 可以个性化整个 Vue CLI 的 Webpack 配置。第一步是安装分析插件 webpack-bundle-analyzer，搞清楚最终的包是由哪些文件打包生成的。接着学习各种 Webpack 打包优化策略，采用渐进式的几种方式不断优化，同时输出一系列数据做对比，内容非常丰富，这里先卖个关子。

优化完代码体积之后，来到另一个维度：部署以及 HTTP 传输的优化，目的是加快响应速度。首先要安装 nginx 服务器，在本地安装并做个简介，它承担服务器的任务。然后使用 HTTP 的一系列优化措施：首先是缓存，从 Expires 到 Cache-Control 两个关于缓存的 Header；然后是数据压缩，从 Gzip 到比较先进的 Brotli，以及这两个文件的静态生成的一系列手段；还会利用协议的特性，从 HTTP 1.1 的 Keep-Alive 到最终的 HTTP2，快速加快响应速度。

从上面这些内容也能看出，这周的学习方法是实践出真知。我们的项目代码量比较庞大，正好为性能优化带来了实验田。优化必须有真正的场景才能见到效果，所以每一次优化都有实实在在的数据支持，能看到从多少 K 变到多少 K，从最初的大体积到最终的体积、最快的速度，感同身受，也就能更深刻地理解优化的方式方法。

那么就开始这周的学习吧。
