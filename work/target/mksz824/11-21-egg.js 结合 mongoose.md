# 11-21-egg.js 结合 mongoose

上节课讲了 mongoose 的基本用法，它和 MongoDB 官方的 Node.js SDK 非常相似，只是提出了 Schema 和 Model 的概念，可以更好地约束集合中的数据类型。这节课为开始写正式业务代码做最后铺垫：把 mongoose 添加到 egg.js 中。

这段时间一直在学 MongoDB，现在要转换思路回到 egg.js，把具体概念复习一下，可以用之前教过的思维导图形式回顾。有一个概念大家都记得：plugin 插件，当时把插件简单描述为实现某些特定功能的合集。mongoose 自然就是这样的功能，egg 官方有特定插件实现，就是 egg-mongoose。这里我们先不用官方插件，而是自己完成，封装成自己的插件，最后根据写的代码解读 egg-mongoose 的源代码，了解 egg 中插件怎样编写、原理是什么。掌握插件编写是吃透 egg 的重要技能。

把 mongoose 添加到 egg.js，我们采取小步快跑的方式：先根据上节课内容完成最简陋、最简单的实现，再一步步优化。使用 mongoose 分两个步骤：创建连接，创建 schema 和 model，最后用这些数据结构发送请求。

第一步创建连接。当然要先安装 mongoose（我这里不再演示安装，装完是 6.0.10 的版本）。自定义启动自然想到 app.ts，里面有一系列生命周期。创建数据库连接的逻辑放到哪个生命周期都可以，但我们希望越早越好，放到构造函数中就可以。

首先把连接的 URL 添加到配置文件里，用户就能方便地修改。这属于业务逻辑的配置，就加在那里：mongoose: { url: ...}，URL 就是之前一直在用的 27017 端口上的 Mongo 服务。有了配置，app.ts 里就可以取出来：this.app.config.mongoose.url。

特别注意：这个 URL 必须存在，要判断一下。用 Node.js 原生模块 assert，它主要用于断言，表达式不符合预期就抛出错误，提供十一个方法但只有少数几个常用。用最简单的 assert 函数，接受两个参数：第一个为 true 时不会有任何提示，为 false 时抛出错误。导入时会出现一个错误，因为 assert 没有默认导出，改成 import * as assert 即可。然后 assert(url)，URL 不存在时就弹出一行错误。

接着创建 connection。上节课用的是 connect 方法，这次用一个新函数 createConnection，它可以返回一个特定的 mongoose connection 对象。const db = createConnection(url)，db 是 connection 类型。它基于事件，要判断是否连接成功，监听它上面的 connected 事件，成功后用 logger.info 打印一行 connected successfully 说明启动成功。

为什么用 createConnection 而不用上节课的 connect？因为我们可以把 db 对象保存在 app 上，以后在应用中直接从 app 获取这个对象，进行数据库属性和方法的操作。未来如果有多个 MongoDB 实例（我们有可能连接多个实例），这种方式能完成多实例功能；用 connect 的话没法实现多实例。在启动过程中顺便完成内置对象的扩展：直接添加到 app 上，作为一个属性叫 mongoose，等于 db。

这时会报一个类型错误，因为 app 上没有对应类型，egg-ts-helper 不会帮我们自动生成直接添加的属性，需要自行添加。来到 typings 文件夹，根目录下有一个 index.d.ts，它不是自动生成的，是一次写死的，任何想添加的自定义类型都可以写进去。想扩展到 app 上就是扩展 Application 接口：在 Application 上添加属性 mongoose，类型用 mongoose 内置的 Connection（从 mongoose 导入），mongoose 属性赋为 Connection 类型，红色报错就消失了，类型对应上了。

启动阶段的工作完成：创建连接，并把 db 扩展到 app 上。npm run dev 启动，输出 connected successfully，数据库连接成功。

有了连接，代码中就能完成数据库操作了。之前说过数据库的抽象最好放在 service 中，就不创建新 service 了，直接在现有的 doctor.ts 里操作（有点文不对题，先这样）。先创建 model：创建一个私有方法 getPersonModel，里面把 app 拿过来，创建 schema，和上节课一样，从 mongoose 里导入 Schema，把上节课的 userSchema 代码直接复制过来。

这里特别注意：创建 model 时，既然用了 createConnection 创建连接，新建 model 要使用连接返回的实例（也就是 connection 实例）上的 model 方法，不能用上节课 mongoose 全局模块的 model 方法！这一点特别重要，之前我出现错误后调整了半天才知道是这原理。实例在 app 上已经添加好了，现在大显身手：app.mongoose 上面有个 model 方法，和全局 model 一个意思，但它在实例上，必须采用这种方式。传入 'User' 和 userSchema，model 创建完毕。

再写一个 async 方法 showPlayers：拿到 model，const personModel = this.getPersonModel()，发起查询 const result = await personModel.find({age: {$gt: 30}}).exec()，拿到 result 返回出去。service 方法写完，最后 controller 里拿数据：把之前测试用的 console 和 response 都删掉，persons 等于 await ctx.service.doctor.showPlayers()，打印 persons，并把它添加到 response 中。顺便测试一下全局挂载的 mongoose：输出 ctx.app.mongoose 上面有个特殊属性 id，看挂载是否有问题。

总结一下流程：app.ts 里创建连接并把 db 挂到实例上；service 中创建 model 并通过 model 进行 find。特别强调那行：创建 model 要从创建连接的实例上去定义，不能用全局方法，说了好几遍了。最后在 test 路由发起请求，刷新后 persons 的信息都返回了，说明跟数据库连通并且能查询，没问题。

egg 结合 mongoose 的写法就这样完成了。但有个让我很不爽的点：每个 model 现在都要跟 service 绑在一起，不能模块化。我们希望把 model 都放到特定文件夹下，比如 app 中的 model 文件夹，在里面放置所有 model 文件进行定义，访问任何 model 时从 app 或 ctx 上通过特定属性访问，这就深得 app 的精髓了，非常完美。下节课继续进化，看看怎么完成这个任务。
