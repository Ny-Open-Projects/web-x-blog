# 7-9-测试组件：渲染和元素获取

上节课我们搭建了整体的测试环境，这节课通过一系列例子来了解 Vue Test Utils 的写法。安装插件后，它会自动帮我们添加一个测试用例。当然这是一个模板文件，会引入 HelloWorld 等组件。我们现在已经没有 HelloWorld 了，所以把这个组件添加回来，做一个教学组件，在里面添加一系列功能，用来测试组件的不同方面。这节课完成第一部分的测试。

我把组件的测试分为四个基本步骤：第一步是渲染组件，把组件渲染到测试用例里；第二步判断元素是否成功显示；第三步触发事件，不管是 click 也好、修改 input 也好，让它触发对应的事件；最后观察测试的界面是否更新。这四个步骤里都有一些要点，写代码的时候一点点讲解。

先让测试运行起来。上节课知道测试运行是 `npm run test:unit`，现在希望用 watch 的方式：Jest 有一个 --watch 参数。怎么把这个参数加进去呢？`npm run test:unit` 执行的是它本身的命令，在后面加一个 --，再接你想添加的参数，就会传给 Jest 本身。回车之后，测试运行起来了，里面已有的测试用例通过了，当然里面什么都还没写。

第一步，渲染组件，把组件挂载到测试用例里面。它提供了两个方法：mount 和 shallowMount。用真实的例子看它们的区别。注意我在 HelloWorld 里引入了一个子组件 Hello，它非常简单，就是一个 h1，传入 props 的 message 属性进行渲染。

首先用 mount 方法挂载：创建一个 wrapper，调用 mount。第一个参数是要挂载的组件，这里是主组件 HelloWorld；第二个参数是一个对象，上面有 props 属性，传入组件需要的参数，比如 msg。wrapper 创建成功后，它的类型是 VueWrapper，TypeScript 也可以查看，上面有一系列方法和属性。其中有一个方法可以显示渲染后的 HTML：console.log(wrapper.html())，输出渲染出的 DOM 结构。跑一下可以看到，父组件的结构渲染出来了，子组件的 h1 也渲染出来了，一二三四都在。

现在把 mount 改成 shallowMount 试一下，直接替换。发现它和 mount 唯一的区别是：子组件被替换成了一个 hello-stub 标签。这就是 shallow render 的最大区别：它只渲染组件本身，对所有外来子组件一概不管，都使用假的标签代替；而 mount 是一股脑全部渲染。这样做有什么用途呢？shallowMount 因为不用渲染子组件，会更快一些；对单元测试来说它也更适合，因为它会把其他组件隔离开，只测试自己的逻辑。当然这个结论不能一概而论，要看测试的具体需求。

有了实例之后，要做的就是查找结构上的元素，看看对应的界面是否显示成功。这里有两个非常相似的方法：get 和 find，它们都接受一个 CSS 选择器作为参数，用法和 DOM 上的 querySelector 非常相似。`wrapper.get('h1')`，然后输出它的 text，可以看到输出了 new message，拿到了里面的文本。换成 find 试试，也输出了 new message，看起来完全一样。

那两者究竟有什么区别？区别就在于没有匹配时的返回。查找一个完全不存在的 hr：先使用 get，因为里面没有 hr，找不到的时候它直接抛出一个错误，中断这个 case，并判定失败。再用 find，可以看到虽然没找到，但 find 返回一个 null，case 没有中断。这就是两者的区别：没有匹配时的返回不同。

什么时候用 get，什么时候用 find？文档给我们提供了总则：总是使用 get，除了一种情况，就是你想判断某个元素不存在的时候，可以使用 find。另外还有两个方法：findAll 和 get.findAll，它们返回一个对象数组，有点像 querySelectorAll，很简单就不展开了。

除了找元素，还能找组件中是否包含另外一个组件。比如 HelloWorld 中包含 Hello 这个组件，可以使用 getComponent 或 findComponent 去查找，区别和刚才一样。查找时的参数有多种类型，可以自己看文档：selector、name、ref 或者 SFC，我们直接使用最后一种方式，传入组件对象。`wrapper.findComponent(Hello)`，跑一下，它找到了，返回的是一个 VueWrapper。可以看它上面的属性：props 是一个 function，调用一下，可以看到 message 的值一二三四传递过来了。

假如查找一个根本不存在的组件，肯定会有问题。跑一下可以看到，因为用的是 findComponent，它返回了 null，说明没有这个组件。那 findComponent 或 getComponent 的意义在哪里？这个方法对单元测试有很深远的意义：我们不必测试子组件里面的内容，只要判断是否渲染了这个子组件、并且是否传递了正确的属性就可以了。至于子组件怎样运作，那是它自己的事情，它可以自己写单元测试保证正确性。这就是单元测试的意义：把代码分成独立、互不影响的模块，并对它们一一进行单独测试。

这节课讲了渲染组件的两种方法：mount 和 shallowMount，以及获取元素或组件的一系列方法：get、find 和 findComponent。下节课继续讲触发事件和测试界面是否更新的内容。到这里，谢谢大家，再见。
