# 12-1-本章导学

欢迎来到新一周的学习！从这周开始正式进入业务开发，本周要关注的是用户系统的设计与实现。对架构师课而言，这周的思考是贴近真实的工作需求，让大家真正学以致用，这才符合整个课程的宗旨：多写代码，多思考，少说一些有的没的虚的东西。

对用户系统这块业务，我的思考是：首先要做到覆盖面广，把目前市面上所有关于用户系统的解决方案都进行编码讲解和使用；并且在过程中进行深入，添加一些源代码解析，让课程以深入浅出的方式推进。本周内容非常丰富，大约有八个小时，因为我想尽可能全面、尽可能多地把知识点带给大家。

具体讲哪些内容？第一块是多种创建用户的实现方式，目的是扩大知识面。第一种是传统的用户名密码模式，大家都了解。有密码自然要讲加密手段，这里会对比几种常见的加密手段并选取其中一种。第二种是现在市面上非常流行的手机号加短信验证码模式。这里会带入一个新知识：Redis，它的使用场景、对应实现和基础知识。学了 Redis 后，就要接触我们使用的第一个真正的云服务：阿里云的 SMS，用它完成真实的短信发送。第三种是现在也很流行的 OAuth 2 模式。提起 OAuth 2，市面上的微信扫码登录、QQ 扫码登录、GitHub 登录等都是用 OAuth 2 实现的。这里我们选择 Gitee 这个服务来演示 OAuth 2 怎么完成。先讲它的基本流程，流程稍微复杂一点，有好几步；然后特殊讲一点前后端分离下 OAuth 2 登录实现的全过程，里面有一些小技巧，很有意思。第三点要实现 CORS，也就是跨域访问，这个大家很清楚，但我们会把里面的小细节捡起来，争取讲一些大家不了解的知识。

讲完用户的创建方式后是用户鉴权，这也很重要。第一种是大家都熟悉的传统 cookie + session 方案，这里会把 cookie 的知识再回首，把里面的小知识点讲透。之后分析一个源代码：session 的源代码，看 session 使用的实现方案到底是什么。这应该是我们遇到的最复杂的源代码，所以分两节课讲解。最后还可以使用 extend 来实现一个外部存储，让大家对它更了解。

之后是我们选用的方案：JWT（JSON Web Token）的实现方案编码，讲它的原理和编码实现。实现了中间件之后，还会对 egg-jwt 这个 plugin 的源码进行解读和实现。

讲完用户相关的，还会开始第二个集合的开发，也就是作品相关接口的开发。这里会遇到第一个多集合关系：一个用户可以有多个作品。除了多集合的实现，还会学 mongoose 的一些高级内容，比如聚合查询以及各种新 API 的使用。这里会对代码进行重构，并给大家介绍一个非常有意思的全新特性：装饰器 decorator，通过它可以重构部分功能和代码，让大家看到装饰器的威力。

以上就是全过程，内容比较丰富。教学上有几个特点：由浅入深、覆盖面广、实用性强，希望大家学完可以真正用到工作当中，而且这些内容都和真正的工作非常贴近。第二点，我想给大家讲：重构是随着项目的进行诞生的，一开始就想设计一个大而全的结构是不现实的，从整个过程可以深切体会到这一点。

这就是本周要学习的所有内容。废话不多说，让我们开始编码，进入项目的正式开发。
