# 8-20-将上传组件添加到左侧组件列表

经过好几章的篇幅，我们介绍了一个复杂组件使用 TDD 的开发过程，还衍生出了一系列扩展知识，甚至了解了 Element Plus 开源库中 uploader 的开发过程。希望大家对复杂组件的开发有了新的理解。现在把开发好的上传组件用到编辑器应用中。

## 二次封装的思路

第一个场景是在左侧组件列表中，除了文字，还要提供一个上传图片的按钮。上传图片成功以后，创建一个类似 LText 的 image 类型的业务组件。这节课我不会带着大家一步步写代码，因为内容并不难，但有几个思想可以分享。

观察这个入口：上传图片是一个按钮样式，点击选择图片后触发上传，上传完成后恢复"上传图片"的文案，并且应该有通用的上传格式检查。这种上传组件在应用中可能出现多次，比如这里、后来的图片编辑里都可能用到。为了不重复写这些通用逻辑，自然要对已完成的 uploader 做二次封装，我称之为 StyleUploader，特殊样式的 uploader。要做的事：

1. 设置上传前、上传中、上传完毕的模板，通用 uploader 都提供了这些能力。上传前展示一个 FileImageOutlined 图标加文字；上传中添加 LoadingOutlined 并且让它转动，显示上传中；上传完毕的模板和上传前完全一样。
2. 设置 show-upload-list 为 false，因为只想展示一个按钮，不显示上传列表。
3. 设置 beforeUploadCheck，定义特定规则的检查函数。
4. 使用一个新的事件，中继 uploader 的 success 事件。原始事件提供了很丰富的参数，而我们只用其中的 response，所以只中继出 response 的 data 参数，拿到上传后的图片 URL 地址即可。
5. 设置一些自定义样式，让它更好看。

## 通用校验与 UI 话术分离

关于 beforeUploadCheck 我特别想展开说一下。看到这个 function，很自然会这么写：参数是 file（file 对象）、formatArray（支持的格式 string 数组）、size（大小），然后 if 判断，file 的 type 不在 format 里就 return false，大小超过指定的 size 就 return false，都没问题就 return true。

这是很线性的想法。但如果现在来了一个需求：失败时弹出提示框，你就会在里面加 error 提示 file type 什么什么；size 有问题再加一段 size 的提示。需求满足了，但假如这个 uploadCheck 是个通用函数，还要在另一处 uploader 组件中使用，而那里的显示话术不同，不叫 file type，要显示中文"文件类型什么什么"，怎么办？你只能再传一个参数 messages，可能是个 object，包含 format 和 size 两种话术。这个函数就被搞得四不像了。

所以我们的办法是拆分：把通用验证和可能出现的定制化内容分成两个函数。第一个函数不做任何交互，只做逻辑判断：beforeUploadCheck 的参数是 file 和 condition（CheckCondition 类型，是个 object，里面写 format 有哪些类型、size 有多大，可以用 M 作单位）。它返回一个对象，代表 check 是否通过、error 是什么，是 format 错误还是 size 错误。这样就把校验和界面剥离开了。接下来可以自定义一系列函数，根据逻辑判断的返回值在界面上做定制：拿到是否通过和错误类型后，添加你想要的出错信息。可以做一个 commonUploadCheck，将来也可以做 fancyUploadCheck。

看源代码的实现：我创建了一个 helpers.ts，里面 beforeUploadCheck 接收 file 和 condition，取出 condition 的内容判断 validFormat 和 validSize：不是 validFormat 就把 error 设置成 format，不是 validSize 就设置成 size，最后 return 是否 passed 以及 error 是什么。再创建 commonUploadCheck：调用 beforeUploadCheck 传入参数，拿到返回值后用 message.error 弹出错误信息，最后返回是否通过。

虽然是个简单的改动，但看起来舒服多了。记住：将通用逻辑和一些自定义内容（UI 话术、弹框话术等）分开，是一个很好的考量和改进。

## 验证

最后试一下组件的运行效果。点击上传图片，先选一个不符合类型的文件，点击打开，弹出了错误信息。再点击一次上传图片，选一个 53K 的文件，可以看到 loading 状态，loading 完成后恢复"上传图片"，并且拿到了上传成功后的地址。我们关心的就是这个 URL，最终图片上传的地址，它将作为 image 组件的 URL 展示出来。
