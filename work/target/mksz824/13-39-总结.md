# 13-39-总结

这一周到这里告一段落，整个应用的剩余需求都已经开发完毕。相信通过这两周的学习，大家对后端各种功能的开发有了详细的了解。如果对后端功能做一个简单的总结，对于一个功能比较丰满的后端项目，我认为要掌握的知识有这么几个方面。

第一，掌握 HTTP 相关的一系列功能。Web 世界一切皆是 HTTP，要掌握 HTTP 请求和响应的一系列方式，还要掌握框架相关的一些概念，比如中间件、插件等等。第二，掌握数据库的操作。应用要跟数据库做大量的交互，所以首先要知道 MongoDB 的增删改查等基本操作是怎样完成的。第三，学习和掌握和用户相关的功能，包括使用多种方式实现用户的创建，以及用户状态的管理：你是使用 session 还是 JWT 的方式？第四，和文件相关的功能，我们学习了几种文件上传的方式，以及上传完毕后的处理。第五，是重构的一些概念，表现为 view 的 SSR 实现。虽然这部分功能比较简单，但我们还是通过它了解了 SSR 的基本原理。最后，是权限和角色相关的功能：怎样完成一个应用中比较复杂的权限控制？

掌握了这几个方面，可以说后端的功能就了解了大部分。现在回顾一下本周的知识点。我们从文件上传开始。文件上传一开始讲的是最简单的模式，也叫 file 模式。file 模式完成上传以后，我们使用 egg-static 插件完成了静态文件的展示。本地保存文件以后，还有本地图片处理的过程，经常要对图片进行缩放、旋转等操作，我们学习了使用 sharp 这个库完成图片缩放。对于图片的一系列操作，我建议大家之后在学习或工作中就使用 sharp，它现在非常好用。

之后我们学习了 Node.js 中很重要的知识：Stream，也叫流。讲了它的优缺点（跟直接操作文件相比），以及一些基本的编码例子。然后我们使用 @eggjs/multipart 提供的第二种方式，也就是 stream 完成了对应的上传，和 file 相比它虽然比较复杂，但有得天独厚的优势。接下来还讲了 stream 的高级知识，比如使用 pipeline 代替 pipe 方法。掌握了 stream 以后，我们使用了云服务，也就是阿里云 OSS 完成上传。一开始学习了上传单文件到 OSS，这时插件给我们提供了 getFileStream 这样的方法，可以非常方便地完成任务。要完成多文件上传时，要知道它究竟是怎样运作的，所以我们学习了 stream 底层一个叫 Busboy 的库的用法，然后使用 co-busboy 结合 OSS 完成了多文件上传。最后在了解了 co-busboy 的工作原理之后，我们来到了源代码解析的环节，了解了 @eggjs/multipart 插件的来龙去脉：它是怎样实现 file 模式上传的？又是怎样实现 stream 模式上传的？通过这些课程，大家对文件上传应该有了比较深入的了解。

第二部分来到服务器端页面渲染，也就是 SSR 这个任务。要完成的需求是使用前后端同样使用的业务组件库 OpsFlow 组件库来渲染对应的 H5 页面。一开始讲了 SSR 的概念和特点，说了 Vue 实现 SSR 的基本用法。这里我们没有选择比较大的框架（比如 Nuxt.js），而是选用了最基本的方法，因为需求很简单，没必要使用那么复杂的框架。然后我们使用业务组件库渲染了 H5 页面，做了一些样式上的调整，针对不同的屏幕分辨率，比如添加 body 的样式、把 px 转换成 vw 单位。最后还要处理静态文件，因为模板文件有可能需要动态计算生成，所以我们学习了 webpack 怎样处理：添加了一些配置、plugin 和 loader。生成以后还需要多做一步工作，使用插件完成拷贝以及清理生成的文件。最后讲了生产环境需要上传到 OSS，所以又创建了一个脚本完成对应的功能。通过这一部分，我们就完成了渲染页面的需求。

最后讲了本课程的一个亮点，也就是基于 RBAC 的权限管理。一开始引出的是渠道的处理，这里我们复习了数组操作的方式，讲了 RBAC 的基本概念以及 Node.js 多个库的对比。最后选择了现在最为流行的 CASL 这个库，讲了它的基本用法，比如 action、subject、condition 等一系列基本概念。然后添加了对应的 role，以及每个 role 应该有的 condition。最后学习了针对不同属性的管理。我们会发现 CASL 简单易用，而且功能非常强大。

最后我们使用 CASL 结合代码中的 decorator（装饰器）完成了项目中对应的功能。这里是一步一步进化完成的，花了四节课把装饰器最终编写完毕。通过这一系列内容，我们了解了在一个项目中怎样使用 CASL 来完成 RBAC 这种形式的权限管理。源代码分支还是来自 OpsFlow 后端主库，branch 的名称叫 feature-week-16。learn-mongo 里还会讲一些基础知识，是基于 CASL 的基本操作，还是推送到了 master 分支。大家可以在课后去看源代码。

这里给大家留一个简单的课后作业，是针对 RBAC 实现的扩展。我认为这一块算是一个难点，所以大家要重复多练习。作业是添加一个特殊的角色，称为 Moderator，也就是版主的概念。它和普通用户的权限类似，但有一个特点：可以更新别人的 work，比如可以设置别人 work 中的 isTemplate 属性。这个版主就可以帮 admin 下放一些权限，帮他管理一些对应的工作。想一想，这样的需求课后作业应该怎样完成？

这周的内容就到这里。业务功能开发到这里已经差不多都完成了。下一周我们来学习部署相关的知识，看看怎样把开发完成的应用部署到对应的服务器中。
