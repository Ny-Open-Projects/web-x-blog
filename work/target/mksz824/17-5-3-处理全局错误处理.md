# 17-5-3-处理全局错误处理

上节完成了 loading 状态，全局状态现在有通用 loading 和细颗粒 loading 两种。但还有一类问题没处理：通用错误处理。故意输入错误的验证信息点击登录试试：请求返回的 errno 是错误值，message 是"验证码不正确"，但页面上没有任何提示，而且代码本身报错了，因为 login mutation 要从返回数据里取 token，错误发生时返回的并没有 token。

所以要处理的错误有两类：

1. **服务器反馈的业务错误**：比如验证码输入错误。接口设计上这类请求 HTTP 状态码都是 200，用 errno 是否等于零界定成功，非零一律视为有错。
2. **200 以外的通用错误**：网络错误、服务器错误，可能是 404 或 500 等等。

## 在 store 中加 error 状态

全局错误显然属于 store，到 `global.ts` 里添加 error 字段：`{ status: boolean, message?: string }`。默认值 status 为 false，初始没有任何错误。mutation 非常简单，一个 `setError` 直接把 payload 赋给 `state.error`。

## 拦截器统一处理

错误状态的改变需要一个统一的地方，axios 全局拦截器是绝佳去处。拦截器有两个回调：第一个在请求成功（fulfilled）时调用，第二个在失败（rejected）时调用。

request 拦截器里先做一件事：每次请求开始时把错误清空，上一次的 response 可能已经设置了错误，重新开始前先 commit setError，status 为 false、message 为空。

response 拦截器里处理业务错误。先给 response 定义类型：在 ResponseData 的基础上添加可选的 message 字段，泛型 T 默认值为空 object，然后从 `../store` 导入 ResponseData。axiosResponse 接受泛型，现在还是 any，替换成我们的类型，response 就有了完整类型。

```ts
axios.interceptors.response.use((response) => {
  const { errno, message } = response.data
  if (errno !== 0) {
    store.commit('setError', { status: true, message })
    return Promise.reject(response.data)
  }
  store.commit('finishLoading')
  return response
}, (e) => {
  store.commit('setError', { status: true, message: '服务器错误' })
  return Promise.reject(e)
})
```

从 response 中拿出 data，再取 errno 和 message 两个属性。由于业务错误时 HTTP 状态码仍是 200，判断就落在 `errno !== 0`：不为零说明这次请求有问题，commit setError，status 置 true，message 用 data 里返回的自定义错误信息。最后很关键的一步：**不要再 return response**，而是 `return Promise.reject(data)`，中断后续流程，不再跑到 mutation 里去取 token，避免代码报错。

第二个参数处理 rejected 的情况：手动 commit 一次服务器错误，然后 `return Promise.reject(e)`。

## 界面展示

有了数据，展示方式不止一种：可以直接根据 global 里 error 的 status 渲染静态模板；也可以用 Ant Design Vue 的 message 函数。因为它是函数调用，需要用 watch 监听。在 login 里添加：computed 拿到 `store.state.global.error`，watch 时用 getter 写法返回 `error.value.status`（布尔值），只在为 true 时调用 `message.error`，展示 message 内容；没有 message 就显示"未知错误"，停留两秒。

验证：输入错误验证码点击登录，"验证码不正确"成功弹出，一段时间后消失。全局错误处理完成，靠的依然是拦截器和全局 state 的变更。
