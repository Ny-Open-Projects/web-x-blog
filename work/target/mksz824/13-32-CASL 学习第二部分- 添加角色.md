# 13-32-CASL 学习第二部分- 添加角色

上节课介绍了 CASL 的简单用法，这节课来添加一个最重要的概念，它是 RBAC 的根基所在：Roles，也就是角色。为了测试，先创建几个对应的角色。

第一步创建一个 interface IUser，描述 User 这个对象应该长成什么样：有一个 id，是 number 类型；还有一个 role 代表对应的角色。角色暂定三种：第一种是 admin，管理员；第二种叫 VIP，也可以称为付费用户；第三种是普通的注册用户，称为 normal。

定义完了就创建三种用户。第一种叫 adminUser，类型是 IUser，id 为 1，role 是 admin。另外两种复制过来，一个是 normalUser，一个是 VIP，也叫 paidUser。几个用户创建完毕后，要把角色的逻辑添加到 defineRules 这个 function 中去。

defineRules 是一个普通的函数，自然可以给它传一个参数，称为 user，类型是 IUser。传入以后很神奇的是，可以在这里面直接写逻辑判断。假如 user.role 等于 admin，它应该拥有最大的权限，也就是所有资源都可以管理。CASL 给我们提供了两个保留字：第一个是操作层面的 manage 关键字，意思是可以做所有的操作；第二个是 subject 层面的 all。写法就是 can('manage', 'all')，意思就是当用户是 admin 时，可以操作所有的资源。特别注意 manage 和 all 是两个保留字，想表达所有权限必须使用它们。

规定完 admin 的权限，再来规定 VIP 也就是付费用户。写 else if，user.role 等于 vip 时添加一个新权限。大家都知道 work 作品应该是可以被用户下载的，可以认为 work 是一个需要付费的服务。添加 download，然后是 work。这个权限只有 user.role 等于 VIP 时才有，也就是只有付费才可以下载对应的 work。

接着是普通用户。else if，user.role 等于 normal，或者 user.role 等于 vip，因为 VIP 也应该拥有普通用户的这些权限。它可以做两件事：第一，可以读取对应的作品，can('read', 'work')；第二，可以 delete，但 delete 有条件，只能删除自己创建的作品。

写 deleteWork 的条件时需要用 condition 来限定 work 实体上的属性，跟上节课一样。这里创建一个 author 字段，所以要把测试数据稍微改一下：第一个作品叫 ownWork，自己的作品，author 设为 2，也就是 normalUser 的 id；第二个作品叫 notOwnWork，不是他的作品，author 设为 3。两个作品设置完毕后，在规则里添加：它只能删除自己的作品，也就是 author 属性等于 user.id，因为 user.id 保存了用户的唯一标识符。同理，也只能 update 自己的作品，can('update', 'work', { author: user.id })，condition 和 delete 一样。

到这里规则就规定完了，上节课写的那些测试规则就不需要了，删掉。用条件表达的方式很快就写完了对应的权限，看起来很清楚。

现在测试。第一组叫 admin rules，把 adminUser 传进 defineRules。测试项目里 ownWork、notOwnWork 都写上。既然是 admin，所有资源都可以管理，不管写什么都应该返回 true。运行 ts-node casl.ts，果然所有都返回 true，说明 manage all 起作用了。

第二组测试 VIP role，rulesTwo 调用 defineRules 传入 paidUser。paidUser 有一项特殊权利就是下载，测试 rulesTwo.can('download', 'work') 是否为 true。VIP 用户只测试这一个权限，因为其他的它跟普通用户一样，等会儿在普通用户里测。运行结果 VIP 为 true，说明它可以下载对应的作品。

第三组是普通用户，rulesThree 调用 defineRules 传入 normalUser。这里要测试多项，把 console.log 复制过来：第一个测试它是否可以 download 作品；然后是 update，这里有意思了，一个是他自己的作品，一个不是。我们用刚才说的 author 来对应：ownWork 的 author 是 2，normalUser 的 id 本身就是 2，这种情况可以相等；notOwnWork 的 author 是 3，不相等。运行看看是否按期望运作：normal 第一个是 false，不能 download 作品，符合需求；第二个是 true，可以 update 自己的作品；第三个 update notOwnWork 是 false，不能更新别人的作品。都按预期工作了。

通过这节课我们学习了 CASL 结合角色的用法，可以非常轻松地用条件语句把不同角色的权限拆分，看起来非常清晰。下节课更进一步，学习针对一个实体（work）中特殊属性的权限管理。
