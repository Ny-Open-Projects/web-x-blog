# 5-20-使用 Module 分割 Vuex 模块

上节课我们在应用中添加了 Vuex 的 mutations 和 getters，这节课学习它的另一个概念：module。应用状态会比较复杂，尤其是接下来要完成的重中之重，编辑器模块会有高复杂度的状态管理。可以想象，如果使用单一状态树，也就是之前创建的 index.ts，把应用的所有状态都放在里面，会集中成一个非常大的对象。当应用变得非常复杂时，store 里的操作就会非常臃肿，index 文件可能非常长，具体哪个模块的操作也很难寻找。

这里必须未雨绸缪。为了解决这个问题，Vuex 允许我们把 store 分割成不同的模块（modules），每个模块都可以拥有自己的 state、mutations、actions 和 getters。

很自然，现在的 store 应该分割成两个模块：user 和 template。虽然这些模块里面现在还很简单，但请大家记住，由于前期做了难点分析，我们很清楚这里的逻辑复杂度会增长得非常迅速，所以这样做是有意义的。我给大家展示 template 模块的写法，user 怎么写请大家参考 template 自己完成。

还是在这个 store 文件夹下，创建 templates 和 user 两个文件夹，分别代表两个不同的模块。先把相关内容拷贝到 templates 里，比如 template 的 interface（跟 template 相关），还有它的测试数据，都放在这里。

接下来定义模块的类型。因为单独定义模块，需要在这里多加一个层级，把 templates 相关的属性都放在里面，并导出，因为别的地方肯定要使用。我把它称为 TemplatesProps（注意加了 s，说明是整个模块的类型）。它里面有什么呢？创建一个 data，里面的数据类型是 TemplateProps 的数组，这样就多加了一个层级。

然后开始定义模块本身。模块其实很简单，就是一个普通的 object，用 const 定义，称之为 templates，把之前的内容复制进去。现在里面只有一个 state 和一个 getters。要特别注意一点：在任何函数调用中，比如 getters 里的 state，指的是本地的这个状态，而不是 index 里全局的状态。到这里都很简单。

但现在出现了一个错误：state 没有了类型，变成了 any。因为 template 只是一个 object 放在这里，肯定没有类型，这是我最不愿意看到的。所以给 module 加一点类型，至少把 state 是什么类型推断出来，这也算本节课的一个小难点。Vuex 提供了一个类型，从 vuex 中 import，它是一个 TypeScript 的 interface，叫 Module。

给 templates 定义成 Module 类型。想也不用想，它肯定有泛型支持：果不其然，可以看到熟悉的尖括号，它接受两个泛型。第一个泛型是本地 state 的形状，直接传进去即可；第二个泛型是全局状态的形状，也就是最外层全局状态的形状。为什么需要这个类型？因为 getters 里有三个参数，第三个参数可以拿到全局状态使用，所以这里要传全局状态，稍后会演示 getters 的参数。

全局状态在哪里？在 index.ts 当中。注意两者是互相牵连的，全局状态应该引用这个状态，把它导出来。从 ./templates 导入的是 TemplatesProps（注意不是第一个）。有时候全局状态里就是 TemplatesProps 数组。定义好全局状态后，从这里把它拿过来，from './index'，然后传递进去，错误就消失了。state 获得了类型吗？现在 state 变成了 TemplateProps，很自然，data 也可以自动补全，data 里面的每个属性都变成了 TemplateProps 类型，很完美。

现在测试第三个参数。getters 的第三个参数是 rootState，用 rootState 点一下，可以看到 templates、users 都获得了对应的类型，挺完美。有同学经常问：老师你是怎么知道这个类型有这样的功效的？哪里有文档告诉我们应该使用什么类型？答案在这里。官方文档对 TS 支持还很有限，所以我喜欢直接看类型文件，在里面寻找答案。这是一个有趣但有点耗时的工作，但我还是建议大家多看类型定义文件，找找有什么可用的类型帮你减轻负担、快速写代码；同时也可以参考别人写的类型文件，一举两得。

定义完毕后导出：export default templates，然后在全局 store 里 import 进来，放到 modules 属性上，把 templates 添加进去，整个工作就做完了。注意要修改页面上的一些字段，因为现在的数据存放在 templates.data 中，而不是原来一层结构的 template 中。不过这些错误都有提示，很快就能改完，这里就不展示了。

最后一个任务请大家自己完成：user 模块参考 template 的写法，我这里已经写完，就不再带大家写一遍。最后测试一下页面，数据可以成功获得，点进去用 getters 也能拿到对应的数据。

这节课学习了 Vuex module 的用法，可以把 store 按照特性分割成多个模块，非常方便进行有条理的管理。到这里，谢谢大家。
