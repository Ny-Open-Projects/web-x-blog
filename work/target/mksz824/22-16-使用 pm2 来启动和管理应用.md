# 22-16-使用 pm2 来启动和管理应用

上节课完成了部署，把构建生成的代码拷贝到了服务器上。这节课来完成最后一步：启动应用，然后通过 IP 进行访问。在服务器上启动和本地启动没有区别，先要做好准备工作，安装必要的服务。要安装的第三方服务有这么几个：第一个是 MongoDB，第二个是 Redis，第三个是最新版的 Node，特别注意版本应该大于等于 20。最后还要准备 .env 文件，写入必需的环境变量。

如果忘记了在 Linux 主机上怎么安装，之前「使用传统模式部署」里有一节 2-8「Linux 安装必备软件」讲得很详细，可以去回看。

然后就可以登录服务器完成启动了。登录后先查看 Node 版本，可以看到是 20.12.2，符合要求。其他软件和 .env 文件也都已准备完毕。进入 admin 文件夹，开始启动。启动命令和本地完全一样：`--env-file=.env` 后面跟入口文件的名称。运行后可以看到应用在 3000 端口上监听。特别注意，如果要通过 IP 访问，还要把主机的 3000 端口开启，不同主机商的开启方式不一样，去看你的提供商文档即可。

现在访问 IP 加 3000，页面出现了，说明应用已经成功启动。但会发现，直接用 node 启动会输出一系列信息，整个终端就卡住了，接下来要输入其他命令只能另开窗口。在生产环境，可以使用更专业的工具来管理 Node 应用，它就是 PM2。

PM2 是一个流行的 Node.js 进程管理工具，可以管理 Node.js 应用的生命周期，包括启动、停止、重启和监控等服务，帮助我们更方便、更高效地管理和监控 Node.js 应用，提高应用程序的稳定性和可靠性。

看它的优点和功能。第一个是进程管理：可以管理多个 Node.js 应用程序进程，确保它们持续运行，还能执行启动、停止、重启以及查看状态等操作。第二个是集群模式（Cluster Mode）：支持根据服务器的 CPU 核心数自动启动多个 Node.js 进程，充分利用服务器资源，提高应用程序的性能和稳定性。第三个是性能监控：可以实时监控应用程序的 CPU 使用率、内存占用等，及时发现和解决性能问题。此外它还有自动重启功能，在崩溃和意外退出时自动重启应用程序；部署也简便，一条命令就能启动应用程序。

安装很简单，使用 `npm install -g` 全局安装 pm2 即可。我已经装好了，登录上去查看 `pm2 --version`，当前版本是 5.3.1。接下来启动程序，用 pm2 start，后面跟入口文件。但特别注意，之前有一个 `--env-file` 参数，不能原封不动地复制过来，而要通过 node-args 来添加这个参数。很多应用不需要添加参数，这时直接把 node 替换成 pm2 start 就可以；要添加更多参数的话，可以通过 pm2 提供的参数来启动。

直接操作。先进到 admin 文件夹，然后启动。启动后会输出一个列表，包括应用的 ID、程序 name、以什么方式启动的（可以看到是 fork）、状态、CPU 使用率以及 memory 占用。到这里就已经启动成功了。

再看 pm2 的其他命令。第一个是 `pm2 list`，展示当前所有的 Node 应用。这里只有一个应用，可以看到 Memory 占用是 71.7 MB。第二个是 `pm2 logs`，可以输出一系列 log，分为两部分：第一部分是 pm2 这个工具本身的 log，另一部分大家应该很熟悉，是应用程序的 log。除了 logs，它还有监控功能，之前提过监控是它的优点之一。通过 `pm2 monitor` 可以启动一个监控界面，里面是 process list 和对应的参数。index 的 logs 现在为空，访问一下应用，再看 logs，访问记录也就是 node 程序输出的日志都被记录到这里了。

退出监控，继续看下一个命令：停止和重启。停止用 `pm2 stop`，接受两个参数，name 和 id 都可以。name 是 index，或者用 id 0，都可以。停止后可以看到状态变成 stopped。注意 stop 只是停止，应用并没有被删除，可以快速重启。如果要删除，用 `pm2 delete`，输入 0，应用就被删掉了，整个表格空了。

还有一个很重要的功能，就是之前说的 cluster mode。之前课程对 Node.js 的 cluster 模式做过详细介绍，它能充分利用多核 CPU，提高应用程序的性能和稳定性，在负载均衡、自动重启、资源利用和管理方面都有优势。使用 Cluster Mode 也很简单，加一个参数 `-i max` 就可以。之后会用配置文件来展示。

参数会越来越多，参数多了就容易出错，所以通过配置文件启动是一种非常好用的方式。pm2 文档里有关于配置文件（configuration files）的说明，可以通过 `pm2 init simple` 生成一个配置文件，名称叫 ecosystem.config.js，是 CommonJS 格式，里面通过一个对象添加各种配置项。我已经写好了，直接看。服务器上用 vim 会稍微卡一些，就不一个个写了。

配置很简单，看一遍就知道什么意思：应用名称、在哪个端口启动、exec mode 用什么模式执行（这里采用 cluster mode）、instances 设为 max（使用最多的实例）、script 是要启动的脚本位置，还有刚才添加的 node_args，里面加了 env_file。

有了这个配置文件就可以轻松完成启动。把配置文件放到 admin 当中，内容跟刚才手动写的完全一样。现在启动：`pm2 start` 后面跟配置文件名，注意不要写错。可以看到已经成功启动，ID 是 0，Name 是设定的 nuxt，模式是 Cluster Mode，跟刚才的 Fork Mode 不一样。通过这种方式也很容易启动应用。我更推荐配置文件的方式，因为命令行参数多了容易出错，写在配置文件里更方便。

这节课的任务到这里就完成了。现在成功在服务器上把应用运行起来了，还学习了 pm2 这个进程管理工具。如果大家在服务器上有多个 Node 进程要启动和管理，我推荐使用 pm2，希望以后在生产环境上多用这个工具。
