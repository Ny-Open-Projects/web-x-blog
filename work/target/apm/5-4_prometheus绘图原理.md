# Go APM 监控系统实战: Prometheus 绘图原理与 PromQL 表达式数据类型

## 纲要

- Prometheus 存储不限于本地 TSDB，也支持远程写 / 远程读到 InfluxDB、ClickHouse 等时序存储
- 用户主要通过 **PromQL 表达式**与 Prometheus 交互
- PromQL 只有四种数据类型：瞬时向量（instant vector）、范围向量（range vector）、浮点型（float）、字符串型（string）
- `floor` 函数：入参瞬时向量，逐样本向下取整，返回瞬时向量
- `rate` 函数：入参范围向量（用 `[5m]` 表示），返回区间内每秒平均增量，结果是瞬时向量
- 绘图核心：选定时间范围 + `interval`，大范围被切成多个小段，每段产出一个描点；每个描点以**自身时间戳**作为 PromQL 的参考「当前时间」求值
- 只有最终结果为**瞬时向量**才能绘图——因为每次求值只产出「当前时间戳下的一个或多个点」

## 正文

### 数据存储与查询

在第一章提过，Prometheus 采集数据有推（push）和拉（pull）两种模式。这里补充一点：Prometheus 对时序数据的存储，不只有本地 TSDB，也可以通过远程存储把数据写进 InfluxDB、ClickHouse 等支持时序存储的组件；查询 likewise 支持远程读，从远端把这些存储读回来。本地则是直接从 TSDB 读。

用户侧最常用的是通过 **PromQL 表达式**和 Prometheus 交互，理解表达式的数据类型，是看懂绘图原理的前提。

### PromQL 的四种数据类型

PromQL 表达式只有四种数据类型：

| 类型 | 含义 |
| --- | --- |
| 瞬时向量（instant vector） | 同一时间戳下的多个时间序列（同一时刻的多个样本） |
| 范围向量（range vector） | 一个时间范围内的多个时间序列（含多个时间戳） |
| 浮点型（float） | 普通数值 |
| 字符串型（string） | 字符串 |

注意「瞬时向量」的关键：同一时刻会有很多个指标样本，也就是很多条时间序列，所以瞬时向量指的是**相同时间戳下的多条时间序列**，而不是单条。

### 怎么看函数声明

以 `floor` 为例：它要求传入一个**瞬时向量**——也就是带相同时间戳的多条时间序列。返回值是对其中每个不重复的样本做向下取整后，逐条收集回来，结果仍是瞬时向量。

再看 `rate`。`rate` 的入参是**范围向量**。在 PromQL 里要表示范围向量，就在指标名后跟上方括号，例如：

```promql
rate(http_request_total{job="apiserver"}[5m])
```

含义是：取出指标名为 `http_request_total`、标签 `job=apiserver`、过去 5 分钟内的所有样本，传给 `rate`。`rate` 会计算这 5 分钟里每秒的平均增量，每个时间序列都得到一个「过去 5 分钟每秒增量」的数值，**返回的也是瞬时向量**。

### 绘图是怎么描点的

这是本节最关键的部分。在 Grafana（或 Prometheus 自带的 Graph 界面）里，我们选好一个时间范围后，还有一个 `interval` 选项——它决定「大时间范围被切成多长的小段」。比如选了 1 小时范围、`interval=15s`，就是把这 1 小时分成很多个 15 秒的小窗口，每个小窗口最终产出一个描点。

Prometheus 接到绘图请求后，会先算出每个描点对应的时间戳位置，再**以该描点的时间戳作为 PromQL 的参考「当前时间」去求值**。

```mermaid
flowchart TD
    A[选定时间范围 + interval] --> B[大范围切成 N 个小窗口]
    B --> C[计算每个描点的时间戳 t_i]
    C --> D[以 t_i 作为 now 执行 PromQL]
    D --> E[rate 等函数取 t_i 前 [5m] 样本计算]
    E --> F[得到 t_i 时刻的瞬时向量 = 一个或多个点]
    F --> G[所有描点连成时间序列图]
```

举个例子：你写的是 `rate(...[5m])` 算过去 5 分钟每秒增量。这里的「过去 5 分钟」是**相对当前时间**的。Prometheus 在计算第 i 个描点时，会把第 i 个描点的时间戳当作「当前时间」，取它往前 5 分钟的样本来算，得到该描点的值。所以**每个描点都会独立经历一次 `rate` 运算**。

这也是为什么「PromQL 最终结果必须是瞬时向量才能绘图」——因为每一次求值（每个描点）得到的就是一个或多个点（取决于瞬时向量里包含几条时间序列）。如果在同一时间戳下用筛选条件去掉了某条序列，就可能只剩一条；不去掉时同一个时间戳下能看到两条序列。绘图引擎把这些点按时间顺序连起来，就形成了我们看到的时序图。

### 小结

Prometheus 绘图的本质，无非是：把一大段时间切成很多小段，每段产出一个描点；每个描点以自身时间戳为参考，用 PromQL 算出当前值（瞬时向量），最终连成曲线。理解「每个点都独立以自身时间为 now 求值」，是写好、调对 PromQL 的根本。
