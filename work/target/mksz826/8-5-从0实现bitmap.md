# 8-5-从0实现bitmap

前面已经了解到，消息的已读与未读会基于自实现的 Bitmap 来完成，本节从 0 实现 Bitmap。内容分四个环节展开：先理解 Bitmap，再针对 Bitmap 的实现继续分析；回顾位运算，因为 Bitmap 的实现会用到位运算；之后编写 Bitmap。

首先理解 Bitmap。可以把 Bitmap 理解为一个数组，但这个数组中只存储 0 和 1，类型是 bit。在当前的已读与未读业务中，1 代表已读，0 代表未读。其次，通过用户 ID、根据 Bitmap 的长度进行计算，会得到一个唯一的用户标识，再查找对应的位置，把这个位置从 0 标记为 1。理解起来并不复杂：根据用户的 UID 确定 Bitmap 中对应的位置，再将对应的值设置为 1 标记为已读，就实现了已读的记录。

再分析 Bitmap 的实现，这里会有一定的难点。首先在 Go 中没有比特类型，最小的类型是字节类型。运算方式上会通过位运算，采取亦或、与、或等方式来计算统计哪些是已读、未读。同时要通过 UID 计算用户在 Bitmap 中的位置，UID 肯定要通过一定的算法来计算它落在哪一个位置上。所以实际编写过程中需要考虑三个话题：一个字节等于 8 个比特，用 byte 来代替；运算方式稍后回顾位运算解决；UID 的计算方式会在后面提供详细的算法。

接下来看需求。需求一是设置好 Bitmap 的大小：Bitmap 的大小可以理解为一个群的大小，设置时要足够大，因为还要考虑进群退群的情况。第二，能够根据 UID 设置 Bitmap 中的属性值。第三，需要验证某一个用户是否在 Bitmap 中。此外，还需要能够将 Bitmap 导入导出并存储在数据库中，不存储在数据库中，下一次读取时数据就无从得知。还需要对传入的 UID 做一定的计算，把它映射到 Bitmap 中的位置。总共五个需求。

了解完需求，回顾一下位运算。目前常用的是这四种：位与、位或、左移运算符以及右移运算符，掌握这四个符号就可以满足课程中的需求。位运算还有很多其他符号，这里一一列举出来，总结在文章中，课后也可以进一步了解。

先了解左移和右移，用代码来演示。写一个用来演示位运算的 main 方法，将 WebSocket 中的相应位置注释掉，定义一个变量 A，打印出 A 的二进制值，然后让 A 分别左移、右移看结果：先让 A 左移两位，同样打印这个值的二进制，只不过打印的是 B 而不是 A；再让 A 右移两位，看输出的结果。

运行可以看到：第一栏输出的是 A 的值，它的二进制是三个一。左移是在原二进制的基础上面，在后面加 N 个 0，往左移两位，就在后面增加两个 0。第二组是右移，从最后一位开始计算往前去掉几位，右移两位就去掉两位，变成了 1。也可以试试其他的值，效果一样。左移和右移其实并不复杂。

之后是位与和位或。位与和位或是对应位进行运算：如果它们都为真，输出 1；如果其中有一个不为真，则输出 0。现在有两个值 A 和 B，A 是 20，B 是 7，分别打印出两者的二进制，位运算演示的代码如下：

```go
a := 10100, 20; b := 111, 7;
c := a & b
d := a | b
```

在这个基础上先进行位与，再位或。A 和 B 的二进制结果都已经输出。这两个运算都是选择同位比较：最后一位和最后一位比。根据前面的结论，当这两位一个为 1、一个为 0，在位与的情况下输出结果就是 0，符合；第二个位置同理；第三个位置 B 是 1、A 也是 1，所以输出了一个 1，这就是位与的结果。

再看位或。位或的规则是只要有一个 1，就输出 1。可以看到输出的二进制，后面没有值，虽然 A 这里还有，但 B 的这两位都是 0，位与时直接舍去；而位或不一样，只要有一个为 1 就输出 1。这就是位或和位与这两个运算。

位运算了解到这里，接下来实现 Bitmap。进到代码中，在 pkg 下增加一个包 Bitmap。在 Bitmap 中定义文件 bitmap.go，并定义一个 Bitmap 的结构对象，里面定义两个值：一个是 bits，用于存储 Bitmap 的结果；第二个是 size int。两个值定好之后提供构造方法 NewBitmap，在其中做一个判断：如果传递的大小等于 0（没有指定），给它一个默认值 250。设置完之后定义对应的方法：空间已经通过 make 创建好了，接下来为这个空间设置值，比如定义一个 Set，Set 要传递一个 string 类型的 ID，根据这个 ID 计算在 Bitmap 中的位置。

在计算的时候需要单独定义一个方法来处理 ID 的计算。业界中有一个算法可以用上：它可以将 string 类型转化成 int 类型，再通过取模的方式计算 ID 在 Bitmap 中的哪一个位置。

这里应该如何计算？这个大小指的是整个 Bitmap 的大小，不是字节的大小，字节只是存储 Bitmap，每个字节里面有 8 个 bit，这里指定的是多少个字节、总共有多少个 bit。计算分三步：先根据 ID 取模得到 ID 落在哪个 bit（序号从 0 往后累加），再根据 bit 的位置计算在哪个字节里，最后计算在这个字节中的哪个 bit 位置。

之后就是设置。设置采取位或加左移的方式：已经得到它是在哪一个 bit 位置，比如要设置在第四位，就需要先在后面加四个 0 代表要设置的位置，再通过位或的方式将它设置为 1。下面的赋值就用到了位运算。

```mermaid
flowchart TD
    A[「用户UID」] --> B[「hash后取模得到bit位置」]
    B --> C[「计算在哪个字节」]
    C --> D[「计算字节中的哪个bit」]
    D --> E[「位或加左移将该bit置1」]
```Bitmap 的核心实现如下：

```go
type Bitmap struct {
    bits []byte
    size int
}

func NewBitmap(size int) *Bitmap {
    if size == 0 {
        size = 256
    }
    return &Bitmap{
        bits: make([]byte, size/8),
        size: size,
    }
}

func (b *Bitmap) Set(id string) {
    // id在那个bit
    idx := hash(id) % b.size
    // 计算在哪个byte
    byteIdx := idx / 8
    // 在这个byte中的哪个bit位置
    bitIdx := idx % 8
    // 设置该位
    b.bits[byteIdx] |= (1 << bitIdx)
}
```

设置就完成了。再提供一个判断是否已经设置的方法，本质上是和 Set 一样的写法：先计算位置，再通过位与来判断，将结果 return，如果不等于 0，就代表已经有设置了。这两个方法写法本质一致，并不复杂。

最后提供导入和导出的方法。导出就是导出一个 byte 字节，return 把这个字节数组输出去。导入即加载：根据字节数组进行加载，改造成对象。先判断长度是否为 0，等于 0 就直接返回；不等于 0 就整体加载。导入导出就写好了，整体方法不复杂。

理解之后定义一个单元测试来测试这里的设置。测试时首先通过 NewBitmap 创建一个 bitmap，给它输入一个 100 的空间，然后设置值（设置一个 pp）。设置完之后输出 bits，打印每个 bit 的二进制结果：

```go
func TestBitmap_Set(t *testing.T) {
    b := NewBitmap(10)
    b.Set(「pppp」)
    b.Set(「222」)
    b.Set(「pppp」)
    b.Set(「ccc」)
    for _, bit := range b.bits {
        t.Log(fmt.Sprintf(「%b」, bit))
    }
}
```

输出结果显示总共有三个值，因为前面只输入了三个值（其中一个是重复的）。把空间调小一点，再增加几个值，可以看到有 1、2、3、4、5 个值，符合需求。但这几个值是分开的；再输入一个 5，可以看到有两个字节合在一起了，一个字节里有两位为 1，证明符合实际需求。

到此一个 Bitmap 类就实现好了。本节主要是实现一个 Bitmap，应用于项目中已读未读功能的实现。
