# 12-9-配置Kibana仪表盘实现可视化

基于 ELK 架构，Filebeat 已经将日志信息推送给了 Elasticsearch，并且基于 Kibana 已经能分析日志了。接下来要做的事情是简单介绍 Kibana 的仪表盘，将数据可视化。本节主要有两个话题：第一，数据准备；第二，创建索引，并且使用 Kibana 的可视化。

## 数据准备

数据准备可以按照这个流程：提前准备好要去检测的慢查询日志信息，或者是 Nginx 日志信息，然后先将这些数据清空，以免影响结果，再重新把数据导到 ELK 中。这里不做处理，直接用之前提前的数据来进行分析。

## 创建索引与可视化

接下来进行仪表盘的使用。进到 Kibana 中，这里有几个索引模式，选 MySQL 的索引然后进行创建。创建完成之后就要去使用它：点击创建仪表盘，点击创建可视化，它是应用范围较广、也是最基础的仪表盘。

分析的对象以 SQL 为例，创建图表，看一看目前执行 SQL 最多的是哪一条 SQL。可以看到它展示出的结果。

展示之后，明显能发现哪个 SQL 执行最多，这三个 SQL 是否是执行最多的，比如其中的某一条 SQL 语句。也可以采用饼图这种可视化形式，选择一个 key 作为查询的字段，然后它就能分析出 SQL 的执行情况。

重点是可以通过这么一个仪表盘，得到 SQL 的执行情况。得到结果之后，可以把这个结果进行保存，这就有一个可视化图表了。还可以再增加一个可视化再保存。这样就可以通过这么一个仪表盘来观察各个数据的情况。

Kibana 仪表盘的使用流程如下：

```mermaid
flowchart LR
    A[「选择索引模式」] --> B[「创建仪表盘」]
    B --> C[「创建可视化：图表或饼图」]
    C --> D[「以 SQL 为例分析执行情况」]
    D --> E[「保存可视化结果」]
    E --> F[「通过仪表盘观察数据」]
```

具体的一些操作，更多的还是需要配合业务以及数据需求去配置。所以仪表盘的使用是不复杂的，可以后续根据自己的数据情况去进行分析。前面的过程中也了解了哪些 SQL 搜索是比较多的。
