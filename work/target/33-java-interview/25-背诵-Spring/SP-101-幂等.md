## AOP · 幂等（场景）

- **事实**：幂等注解切面：@Idempotent + Redis setnx + 拦截器/AOP
- **原理**：请求携带唯一键（token/参数 hash），切面前置检查已处理则拒绝，TTL 覆盖业务最长处理时间
- **常见误区**：
  1. 幂等靠数据库唯一键就够（也是方案之一但接口层先行）（错）
  2. 幂等注解必须配合事务（错）
  3. Redis 幂等绝对可靠（宕机窗口需 DB 兜底）（错）
- **工程用法**：防重提交的通用架构
- **版本锚点**：实战共识
