## SQL · 列表（in）

- **事实**：in 大列表问题：几千个 id 的 in 查询解析与优化器成本上升
- **原理**：拆批（每批 500-1000）、临时表 join、或业务上用缓存，MyBatis foreach 大列表是线上故障常见根因
- **常见误区**：
  1. in 列表无大小限制（错）
  2. in 比 join 慢是绝对的（错）
  3. 拆批对性能无影响（错）
- **工程用法**：ORM 层的隐性坑
- **版本锚点**：实战共识
