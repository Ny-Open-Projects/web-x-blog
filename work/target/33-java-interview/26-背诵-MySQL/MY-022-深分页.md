## SQL · 深分页（分页）

- **事实**：深分页 limit 100000,10 需扫描前 100010 行再丢弃
- **原理**：优化：游标方式 where id>last_id limit 10（连续翻页）或延迟关联（先查 id 再回表），ES 与业务层配合规避深翻页
- **常见误区**：
  1. MySQL 深分页自动优化（错）
  2. offset 越大越快（错）
  3. 加索引就能解决深分页（错）
- **工程用法**：游标分页是标准解
- **版本锚点**：实战共识
