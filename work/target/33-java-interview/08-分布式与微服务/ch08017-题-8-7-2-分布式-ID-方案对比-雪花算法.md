### 题 8.7.2：分布式 ID 方案对比？雪花算法时钟回拨怎么处理？

**【参考回答（可背）】** 三方案矩阵：① 雪花（64 位：时间戳+机器位+序列）：本地生成无网络开销，但依赖时钟与机器位分配；② 号段模式（DB 批量取号段）：简单可控，DB 是瓶颈点，双 buffer 预取优化；③ Redis 自增：性能好但持久化丢号风险。雪花时钟回拨对策（背四条）：回拨小（<5ms）等待；回拨大报警拒绝服务；机器位用持久化配置防重复分配；或改用"逻辑时钟"（时间戳用上次最大值取 max）。
**【追问链】** ① 雪花 ID 为什么趋势递增但不严格递增？（同毫秒内序列递增，跨节点无法保证全局顺序）② 号段+雪花混合怎么做？（Leaf-segment 与 Leaf-snowflake 并存，按场景选）。
**【P10 加分项】** 讲"ID 即索引"的隐藏代价：分库分表后 ID 作为主键要兼顾路由（基因法把 user 分片位嵌入 ID）——把 ID 设计与第 5 章分库分表串起来，属于架构级答案。
