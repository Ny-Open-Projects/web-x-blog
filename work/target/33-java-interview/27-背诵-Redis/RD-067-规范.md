## 设计 · 规范（key）

- **事实**：key 设计规范：业务前缀:模块:id 分层+避免超长+禁止特殊字符
- **原理**：可读可管理（SCAN 按前缀统计/批量清理），超长 key 浪费内存且网络放大，统一命名便于治理
- **常见误区**：
  1. key 命名随意不影响功能（错）
  2. key 越短越好不管可读性（错）
  3. key 可以包含换行等任意字符（错）
- **工程用法**：工程规范第一条
- **版本锚点**：实战共识
