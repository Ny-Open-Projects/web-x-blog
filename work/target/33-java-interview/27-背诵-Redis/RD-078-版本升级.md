## 运维 · 版本升级（升级）

- **事实**：Redis 升级路径：4.0（lazy-free/LFU）→5.0（Stream）→6.0（多线程/ACL）→7.0（listpack/Functions）
- **原理**：升级前评估命令兼容与持久化格式（7.0 可读 6.0 RDB 反之不行），灰度从库先升级再切换
- **常见误区**：
  1. 版本可以任意混搭（错）
  2. 升级无需兼容性评估（错）
  3. RDB 格式完全向后兼容（老版本读不了新格式）（错）
- **工程用法**：版本治理
- **版本锚点**：实战方法论
