## 顺序 · 分区内（保证）

- **事实**：Kafka 只保证分区内有序，全局有序需单分区（牺牲吞吐）
- **原理**：需要顺序的消息按业务键路由到同一分区（订单 ID），全局有序方案：单分区+单消费者（吞吐瓶颈）或业务侧缓冲重排
- **常见误区**：
  1. Kafka 全局有序（错）
  2. 多分区也能保证顺序（错）
  3. 按 key 路由后顺序自动全局（错）
- **工程用法**：顺序消息方案权衡
- **版本锚点**：官方文档
