## 线程基础 · priority（优先级）—— 7 类问法与标准话术

**Qconcurrency-610（概念考察·P1-P3）**
【面试官】请谈谈你对「线程基础」中「priority」的理解。
【标准回答话术】线程优先级只是提示不可作为正确性工具。背后的原理是：优先级映射到 OS 线程优先级但 JVM 不保证严格生效，跨平台行为不一致，正确性永远靠同步原语。
【评分点】① 准确说出核心机制（priority）；② 能带出原理层而非背结论。 ③ 版本锚点：JCiP

**Qconcurrency-611（误用纠错·P4-P7）**
【面试官】我在别的团队见过这样的说法：「优先级高的线程一定先执行」。你觉得对吗？
【标准回答话术】这个说法不正确。准确的表述是：线程优先级只是提示不可作为正确性工具。原因是：优先级映射到 OS 线程优先级但 JVM 不保证严格生效，跨平台行为不一致，正确性永远靠同步原语。
【评分点】① 快速识别误区不顺着说；② 给出正确的版本锚定表述（JCiP）。

**Qconcurrency-612（原理深挖·P5-P7）**
【面试官】「priority」为什么会这样设计？背后的机制是什么？
【标准回答话术】机制层面：优先级映射到 OS 线程优先级但 JVM 不保证严格生效，跨平台行为不一致，正确性永远靠同步原语。落到结论：线程优先级只是提示不可作为正确性工具。
【评分点】① 讲出优先级层面的机制；② 结论与机制对应不脱节。

**Qconcurrency-613（工程落地·P7-P9）**
【面试官】在你带过的项目里，「priority」你是怎么用的？踩过什么坑？
【标准回答话术】使用要点：线程优先级只是提示不可作为正确性工具。补充要点：不要用优先级做业务调度。常见误区要规避：优先级高的线程一定先执行。
【评分点】① 给出可落地的要点而非概念；② 主动暴露一个真实踩坑并给出规避方案。
