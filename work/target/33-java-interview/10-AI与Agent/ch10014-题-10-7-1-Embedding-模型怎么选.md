### 题 10.7.1：Embedding 模型怎么选？维度大小意味着什么？

**【面试官意图】** 检验你是调 API 的"玩具玩家"还是真做过向量检索调优。
**【参考回答（可背）】** 选型看三件事：① **领域匹配度**：中文优先 BGE/m3e 系列，通用语义 OpenAI text-embedding-3/开源 bge-m3（多语言混合）——用你自己的业务问答对做小规模召回评测，别只看 MTEB 榜单；② **维度权衡**：768~1536 维是主流，维度高表达力强但存储/检索成本高（内存≈条数×维度×4 字节，亿级 1536 维≈600GB 原始向量，需要 PQ/量化压缩）；③ **归一化与距离**：常用余弦相似度，归一化后点积等价——换模型必须全量重建索引，切分策略也要重新评测。
**【追问链】** ① 1024 维和 512 维效果差多少？（视任务，多数场景量化后差距 <2%，成本省一半——用评测说话）② 检索慢了怎么优化？（ANN 索引 HNSW 参数 M/ef_search 调优、标量量化 SQ/二值化、分区过滤前置）。
**【P10 加分项】** 强调"Embedding 是整个 RAG 的地基"：模型一换，切分长度、重排策略、评测基线全部要重跑——所以生产上要"锁定模型版本"，并预留"双索引灰度切换"的架构余量。
