### 题 10.2.1：什么是 RAG？为什么需要？完整链路是什么？

**【参考回答（可背）】**
RAG = 检索增强生成：**先检索私有知识，再让模型基于检索结果回答**。解决 LLM 三大缺陷：知识过期、私有知识缺失、幻觉（有据可依）。
完整链路（离线 + 在线，必背）：
1. **离线入库**：文档加载 → **切分（Chunking）**→ Embedding 向量化 → 存向量库（Milvus/ES/Elasticsearch kNN/PgVector）；
2. **在线查询**：用户问题 → 检索（向量相似度 topK，混合检索：向量+关键词 BM25）→ **重排（Rerank，交叉编码器精排）**→ 拼 Prompt（带引用来源）→ LLM 生成 → 返回答案+引用。
切分策略（决定效果的第一因素）：固定长度 + 重叠（Overlap 10~20%）、按语义/标题结构切、父子块（小块检索大块喂给模型）；chunk 大小 300~800 token 起步调优。

**【追问链】**
1. 向量检索为什么不用传统索引？→ 高维向量（768/1536 维）的近邻搜索用 HNSW 图索引/IVF 量化，近似最近邻（ANN）换取毫秒级检索；ES 8+/PgVector 让现有存储直接支持。
2. 效果差怎么排查？→ **先分开归因**：检索没检到（查召回率：正确答案所在块是否进 topK）还是生成不行（检到了没答对）。检索问题调切分/混合检索/重排；生成问题调 Prompt/换模型。**"归因分离"是 RAG 调优第一原则。**
3. 怎么评估？→ 检索层：Recall@K、MRR；生成层：忠实度（答案是否忠于检索内容）、答案相关性、正确性；构建评测集（标注 QA 对）+ LLM-as-judge 自动化评审 + 人工抽检。

**【P10 加分项】**
给出"RAG 失败模式清单"：切分破坏语义、多跳问题（需要跨块推理）、表格/图片等非文本、权限过滤（检索结果必须带 ACL！）、时效性（增量更新管道）。**权限过滤**是企业级 RAG 与玩具的分水岭，面试官必挖。
