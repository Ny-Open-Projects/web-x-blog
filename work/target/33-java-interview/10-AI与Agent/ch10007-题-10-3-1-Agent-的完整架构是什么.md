### 题 10.3.1：Agent 的完整架构是什么？规划、记忆、上下文管理怎么做？

**【参考回答（架构可背）】**
一个生产级 Agent 系统六模块：
1. **规划（Planning）**：任务拆解（Plan-and-Execute：先生成计划再逐步执行，比纯 ReAct 更稳）、反思（Reflexion：失败后自我修正）；复杂任务用 DAG 工作流（确定性）+ Agent 节点（概率性）混合编排。
2. **记忆（Memory）**：
   - 短期 = 上下文窗口内的对话历史（**上下文管理是成本与效果核心**：滑动窗口、摘要压缩、重要信息结构化提取）；
   - 长期 = 向量库存储的用户偏好/事实（个性化），检索时注入。
3. **工具（Tools）**：MCP 协议统一接入（文件、数据库、HTTP、内部 RPC）；工具描述质量直接决定调用准确率。
4. **编排（Orchestration）**：状态机/图执行（LangGraph 思想：节点=步骤，边=流转条件），支持中断恢复、人工审批节点。
5. **护栏（Guardrails）**：输入过滤（注入攻击检测）、输出校验（schema/敏感词/事实校验）、预算熔断（token/步数上限）。
6. **可观测**：每次 Agent 运行 = 一条 trace（步骤、token、工具调用、耗时、成本），失败可回放。

**【追问链】**
1. 上下文窗口够大还需要 RAG 吗？→ 需要：成本（每 token 都计费）、延迟（长上下文慢）、噪声（大海捞针效应：长上下文中部信息召回率下降）、权限（不是所有文档都该进上下文）。
2. 多 Agent 协作什么时候值得？→ 单 Agent 上下文/工具过载、职责可并行、需要不同模型分工（便宜模型做草稿，贵模型做审核）；代价：通信开销与错误传播——**先用单 Agent 到瓶颈再拆**，和微服务拆分同构（呼应第 8 章）。

**【P10 加分项】**
指出"Agent 可靠性工程"三指标：任务完成率、步数/token 成本分布、失败模式分类（工具错 vs 规划错 vs 理解错）；上线策略：评测集回归 + 灰度 + 人审队列。把 Agent 当分布式系统做 SRE，这个视角就是 P10 级。
