### 题 10.4.1：把 AI 能力引入一个亿级用户的电商系统，你的架构与落地路径？

**【参考回答（框架可背：场景盘点 → 分层架构 → 灰度落地 → 组织保障）】**
1. **场景盘点（按 ROI 排序）**：
   - 客服助手（RAG + 工单工具，人力替代最直接）；
   - 搜索与推荐增强（语义检索、意图理解）；
   - 商品运营（自动生成标题/详情/审核辅助）；
   - 内部研发提效（代码助手、SQL 助手、运维问答）。
   **先做边缘场景验证，再进核心链路**——AI 先辅助人，再替代流程。
2. **分层架构（背图）**：
   - **应用层**：各业务 Agent（客服/运营/开发）；
   - **平台层**：Agent 编排平台（工作流+工具注册+评测）、Prompt 管理、评测平台；
   - **网关层**：模型网关（路由/缓存/配额/审计）；
   - **模型层**：API 大模型 + 私有化小模型（分类/NER/ embedding 便宜任务）；
   - **数据层**：向量库、特征库、会话存储、RAG 知识管道（含权限过滤）。
3. **落地四步**：POI 试点（1 个场景闭环 + 基线指标）→ 灰度（5% 流量 + 人审队列）→ 评测驱动迭代（评测集 + LLM-as-judge + 回归）→ 平台化（沉淀为 AI 中台，业务自助接入）。
4. **治理四件套（P10 必讲）**：
   - 数据安全：脱敏进入模型、私有模型承接敏感数据、输出侧敏感过滤；
   - 幻觉治理：引用溯源、置信度阈值、高风险操作人审；
   - 成本治理：网关计量 + 租户预算 + 语义缓存；
   - 合规审计：全量调用日志、内容安全审核（生成内容过安全模型）。
5. **组织**：AI 平台团队（基建）+ 业务 AI 小组（场景）双轨；工程师转型路径（应用层 Java → Agent 开发 → 平台架构）。

**【追问链】**
1. 私有化 vs API 怎么选？→ 数据敏感度（金融/政企私有化）× 规模（token 量大到自建更省）× 人才（有推理优化团队才自建）；混合模式是主流：敏感小任务私有化，通用能力走 API。
2. 传统微服务架构怎么演进？→ AI 服务作为新的领域服务加入现有架构（网关/限流/可观测全复用），增量演进而非推倒重来——**AI 不是新架构，是新服务类型**。

**【P10 加分项】**
差异化观点："AI 项目的瓶颈不在模型而在**数据管道与评测体系**——知识 freshness（文档多久更新一次进向量库）、权限正确性、评测集质量决定上限。架构上要为'不确定性'设计：所有 AI 输出都要有降级路径和人审出口。"
