## 选型 · 适配（场景）

- **事实**：MongoDB 四类适配：schema 多变、嵌套整体读、海量写入水平扩展、快速迭代
- **原理**：商品异构属性、内容详情、行为日志是典型场景，强事务多表关联资金账务仍留 MySQL
- **常见误区**：
  1. MongoDB 全面替代 MySQL（错）
  2. MongoDB 不支持事务所以不适合任何场景（错）
  3. 选型只看数据量（错）
- **工程用法**：NoSQL 选型判断题
- **版本锚点**：实战共识
