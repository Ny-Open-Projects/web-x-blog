## 工程 · A/B（灰度）

- **事实**：prompt/模型灰度：按用户/流量分组对比效果指标（采纳率/失败率），评估集回归先行（AI-063 联动）
- **原理**：线上 A/B 是 prompt 变更的最终验证，离线评估过了仍需小流量观察，与发布灰度（DF-050）同构
- **常见误区**：
  1. prompt 改动无需灰度（错）
  2. A/B 只看成本（错）
  3. 灰度不需要对照组（错）
- **工程用法**：变更流程设计
- **版本锚点**：实战共识
