## 工程 · 分享（团队）

- **事实**：AI 工程内部分享节奏：双周案例分享（踩坑/优化），案例沉淀进知识库（JA-343 文档联动）
- **原理**：团队学习飞轮（JA-342 技能矩阵的成长面），踩坑案例是最好的教材，与复盘文化（MQ-075）联动
- **常见误区**：
  1. 分享是形式主义（错）
  2. 案例无需沉淀（错）
  3. 节奏不重要（错）
- **工程用法**：团队学习机制
- **版本锚点**：实战共识
