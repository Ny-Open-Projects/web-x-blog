## 对话版 · 第 8 章 分布式理论与微服务（三面，约 30 分钟）

**【面试官】** CAP 定理说说什么？注册中心你选 CP 还是 AP？

**【面试者】** 分区发生时一致性与可用性二选一；P 是必选（网络必故障），真实选择是 CP（ZK/etcd，分区时拒绝服务）vs AP（Nacos AP/Eureka，返回旧数据）。**服务发现选 AP**——宁可旧列表别没列表；协调/锁选 CP。一个系统两个都要：服务发现 Nacos AP + 分布式锁 etcd。客户端韧性补刀：本地缓存服务列表，注册中心挂了流量照跑。

**【面试官】** Raft 流程说说？为什么需要多数派？

**【面试者】** 三子问题：选主（term+1 拉票、日志不全拿不到票）、日志复制（多数派确认才提交）、安全（选举限制保证新 Leader 有全部已提交日志）。多数派：2N+1 容忍 N 故障；写无法凑齐多数派时旧 Leader 自然失效——脑裂防护。工程化追问接得住：成员变更用单步法（joint consensus 太复杂）、读线性化用 ReadIndex/Lease、日志压缩快照。

**【面试官】** 分布式事务怎么选？TCC 的坑？

**【面试者】** 决策树：能不用就不用（事务边界聚合，最好的分布式事务是设计掉它）→ 资金强一致 TCC → 长流程 SAGA/消息最终一致 → 通知类最大努力通知。TCC 三坑：空回滚（Try 没到 Cancel 先到）、悬挂（Cancel 后 Try 才到）、幂等——都以事务记录表解决。2PC 互联网基本不用（阻塞+协调者单点）。

**【面试官】** 限流算法对比？分布式限流怎么做？

**【面试者】** 四算法：固定窗口（临界突刺）→ 滑动窗口（Sentinel LeapArray 分格）→ 漏桶（恒速，保护脆弱下游）→ 令牌桶（允许突发，贴近真实流量）。分布式：Redis+Lua 原子取令牌或 Sentinel 集群流控 token server；折中方案是网关粗限+单机均分配额（容忍误差）。**限流值来自压测不是拍脑袋**：单实例安全水位×实例数×冗余系数，运行时按 P99 自适应。

**【面试官】** 可观测性三支柱怎么做才"有价值"？

**【面试者】** 三支柱一条链：Metrics 告警（Prometheus+Grafana）→ Tracing 定位（SkyWalking，traceId 必须跨 MQ/线程池传递——MQ 消息体带、线程池 TTL）→ Logging 取证（结构化 JSON+traceId 注入）。高级形态是 SLO 体系：定义用户视角目标（99.95%、P99<200ms）→ 错误预算（月 21.6 分钟）→ 预算耗尽冻结发布优先修复——把救火文化变成预算管理。

**【面试官】** 分布式系统的时钟问题怎么解决？

**【面试者】** 三路线：逻辑时钟（Lamport/HLC 保因果序）、共识序（Raft 日志顺序即全序，etcd watch revision）、物理时钟+误差区间（Spanner TrueTime 原子钟+GPS，commit wait 换外部一致性）。TiDB 用中心 TSO 换单点授时（RT 稳定），CockroachDB 用 HLC 无中心（RT 受时钟误差影响）——**时间戳分配方式决定延迟与扩展性，选型即权衡**。

**【面试官】** 一致性哈希的原理？为什么需要虚拟节点？

**【面试者】** 哈希空间成环（0~2^32），节点与 key 都映射到环，key 顺时针找第一个节点——增删节点只影响相邻区段（对比取模扩容全量迁移）。虚拟节点：物理节点少时分布倾斜，每节点映射几百个虚拟点摊平。场景：缓存分片、多活路由。Redis Cluster 用预分槽是折中方案（确定性归属，迁移显式可控）。

**【面试官】** 微服务的服务间调用，你关注什么细节？（Feign 层）

**【面试者】** Feign 原理一句话：接口+注解 → 动态代理 → 签名翻译 HTTP → LoadBalancer 选实例。调优三件套：**超时分设**（connect/read，默认 read 过长拖死线程池）、重试慎用（默认 GET 才重试，POST 重试必须幂等——重试引发重复下单是真实事故）、连接池化（默认每请求新建连接，换 OkHttp/HttpClient）。这三条都和"第 2 章线程池、第 7 章幂等"串成体系。

**【面试官】** 单元化（异地多活）怎么做？

**【面试者】** 用户按 ID 分片映射到物理机房，每单元自闭环（应用+数据），写流量只落归属单元，网关按 user_id 解析路由。命门：**路由键一致性**——DB 分片键=单元分片键。收益：容量按单元复制、故障爆炸半径=单单元可切流。演进分阶段：同城双活→同城单元化→异地多活，中小业务"双活+应用层灰度"性价比更高。

**【面试官】** 全链路压测怎么落地？

**【面试者】** 三环节：染色（网关打标，RPC/MQ/线程池全链路透传——MQ 消息属性、线程池 TTL）→ 隔离（影子表/影子 Redis 前缀，定时任务与回调也要识别压测标——漏一处就是生产数据污染）→ 压测（影子库+逐步加压找瓶颈拐点）。通过标准：目标 QPS 下 P99 达标+无错误爬升+中间件水位<70%。

**【评注·终局】** 定级 **P8**。亮点：时钟三路线、Feign 重试幂等事故视角、单元化分阶段演进。分布式域过——这轮答完，三面基本收口。
