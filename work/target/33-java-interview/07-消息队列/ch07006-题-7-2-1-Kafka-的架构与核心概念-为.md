### 题 7.2.1：Kafka 的架构与核心概念？为什么快？

**【参考回答（可背）】**
概念：Producer → Topic（逻辑分类）→ Partition（物理分片，顺序追加日志）→ Consumer Group（组内每个分区只被一个消费者消费）→ Offset（消费位移，存内部 topic __consumer_offsets）。
**为什么快（必背 5 条）**：
1. **顺序写**：分区日志追加写磁盘，顺序 IO 接近内存速度；
2. **Page Cache**：读写都走 OS 缓存，不自己管堆内存（避免 JVM GC 抖动）；
3. **Zero-copy**：sendfile 系统调用，数据从页缓存直达网卡，跳过用户态两次拷贝；
4. **批量 + 压缩**：producer 攒批（linger.ms/batch.size）+ snappy/gzip/lz4；
5. **分区并行**：水平扩展的单位。

**【追问链】**
1. 分区数怎么定？→ 目标吞吐 ÷ 单分区吞吐（经验 10MB/s~50MB/s），预留扩容余量；**分区只能增不能减**（减少会破坏 offset 映射）。
2. 消息怎么保证按 key 有序？→ 同 key 哈希到同分区，分区内有序；全局有序 = 单分区（牺牲并行）。

**【P10 加分项】**
解释"为什么 Kafka 分区多了性能反而下降"：每个分区对应文件句柄、rebuild 元数据、fetcher 线程，页缓存碎片化；KIP-500（KRaft 替代 ZooKeeper）消除元数据瓶颈——说明你跟进了版本演进（Kafka 3.x 已生产 KRaft）。
