### 题 7.4.2：MQ 用法反模式清单（你们踩过哪些坑？）

**【参考回答（背 6 条 + 各配一个坑故事）】**
1. **同步链路里等消费结果**：发消息后立即查下游数据 → 查不到（还没消费）→ 改同步 RPC 或状态轮询；MQ 是最终一致，别当同步调用用。
2. **消息当数据库用**：把大 JSON 全量塞消息做存储 → 消息积压=数据丢失风险、重放不可控 → 消息只传"发生了什么"（事件），数据以存储为准。
3. **无幂等消费**：重复消费造成重复发货 → 唯一键/状态机，幂等是消费端义务。
4. **广播当集群用（或反之）**：Kafka 组内竞争、RocketMQ 广播模式每实例都收——语义弄反直接事故。
5. **Topic 大杂烩**：一个 topic 承载 N 种业务消息，消费端解析所有 → 拆分 topic 或消息体带类型+过滤；topic 是隔离单位也是运维单位。
6. **无死信处理**：失败消息堆重试队列无人管 → DLQ 必须有告警与处理 SOP，死信不是垃圾桶。
7. （加分）**链路追踪缺失**：消息体带 traceId + 消息轨迹平台，否则跨系统排障是大海捞针。

**【P10 加分项】**
上升为治理：MQ 使用规范（命名、topic 治理、消息体 Schema 演进与兼容性、消费 SLA 分级）+ 平台化（消息轨迹、积压看板、一键限速）。"中间件治理"叙事是 P9→P10 的分水岭。
