## 异常 · 吞异常（误用）

- **事实**：捕获异常后既不处理也不抛出（空 catch 或仅 printStackTrace）是高危反模式：故障被静默掩盖。
- **原理**：异常包含故障现场，吞掉等于销毁证据链。
- **常见误区**：
  1. 捕获异常后打个日志就算完整处理了。（错）
  2. 异常被捕获后对系统没有任何影响。（错）
  3. finally 里抛异常会覆盖原异常——所以 finally 只做资源清理。（错）
- **工程用法**：空 catch 在静态检查中应标记为阻断级问题。
- **版本锚点**：代码规范通用条款
