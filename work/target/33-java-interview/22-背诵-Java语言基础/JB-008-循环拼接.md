## String · 循环拼接（性能）

- **事实**：循环体内拼接字符串必须手动使用 StringBuilder（在循环外创建）。
- **原理**：循环内即使编译器改写，每轮也会新建 Builder 对象，产生大量临时对象与 GC 压力。
- **常见误区**：
  1. 编译器会把循环内的 + 拼接优化成一个 StringBuilder 复用。（错）
  2. 循环拼接字符串对性能没有影响。（错）
  3. StringBuffer 在单线程下比 StringBuilder 更快。（错）
- **工程用法**：JDK9+ 单行拼接走 StringConcatFactory，循环仍需手动 Builder。
- **版本锚点**：JDK9+
