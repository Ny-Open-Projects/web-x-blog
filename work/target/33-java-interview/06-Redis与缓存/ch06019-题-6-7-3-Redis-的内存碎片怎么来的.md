### 题 6.7.3：Redis 的内存碎片怎么来的？怎么治理？

**【参考回答（可背）】** 来源：jemalloc 按尺寸类分配，大量"写后删+写"的负载（特别是频繁 set 不同长度的大 value、ziplist/listpack 频繁扩缩容）产生类间空隙。观察：`INFO memory` 的 mem_fragmentation_ratio（>1.5 且 RSS 远大于 used_memory 即碎片严重；<1 反而说明发生了 swap，更危险）。治理：① 4.0+ 的 **activedefrag**（active-defrag-enabled，利用 jemalloc 空闲页实时整理，在线不阻塞）；② 极端情况重启（受控 failover 逐节点）；③ 源头治理：value 长度稳定化、避免频繁大对象写删。
**【追问链】** ① mem_fragmentation_ratio 正常区间？（1.0~1.4；容器环境要算上预留页，读 RSS 才准确）② 为什么 <1 比 >1.5 更紧急？（used_memory 比 RSS 大=数据被换到 swap，性能塌方）。
**【P10 加分项】** "内存三大症候的分流诊断：碎片（ratio>1.5）→ activedefrag；swap（ratio<1）→ 限内存+迁移；增长无上限 → 大 key/集合无界巡检。三条曲线看懂 Redis 内存体检单。"
