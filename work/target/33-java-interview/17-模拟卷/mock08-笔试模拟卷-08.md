## 参考答案与解析（自测后再看）

**1.1**（来源 distributed）
**答案：B**
**解析：** P10 架构答题框架：目标定义（SLA/约束）→方案空间（2-3 个候选+trade-off）→选型论证（数据/经验支撑）→风险与预案→演进路径。原因：禁绝对化（"保证不丢"带条件），结论先行+证据锚点，主动暴露权衡（没有完美方案），与前面各域答题方法论一致。

**1.2**（来源 ai）
**答案：A**
**解析：** RAG 评估维度：检索质量（召回率/MRR）+生成质量（忠实度/相关性），工具 RAGAS/自建评估集。原因：没评估的 RAG 无法迭代（改切分/模型无依据），评估集 50-200 条业务真实问题人工标注，回归跑分防退化。

**1.3**（来源 algorithm）
**答案：D**
**解析：** 背包问题：0-1 背包（每件一件，倒序遍历容量）vs 完全背包（无限件，正序遍历）。原因：遍历顺序决定语义（倒序防重复选），空间优化一维 O(V)，变形（分割等和子集/零钱兑换），笔试 DP 最高频族。

**1.4**（来源 java-ai）
**答案：B**
**解析：** 灰度期用户通知：灰度用户可见"体验新版功能"标识（反馈通道绑定版本），反馈可归因到版本。原因：反馈归因（JA-451/404）的前提：无版本标识的反馈无法分桶，通知与反馈通道设计联动。

**1.5**（来源 agent-dev）
**答案：B**
**解析：** 多模型路由实现：按任务特征（类型/长度/租户档位）查路由表（AD-722 路由表）选模型，路由决策记录进轨迹（可归因）。原因：路由的代码实现（JA-232 的手写面），路由决策可观测（归因 JA-208），与分级路由联动。

**1.6**（来源 java-basics）
**答案：D**
**解析：** static 字段在类初始化（<clinit>）时按代码顺序赋值，仅执行一次且线程安全（JVM 保证）。原因：<clinit> 由 JVM 加锁保证单线程执行。

**1.7**（来源 concurrency）
**答案：C**
**解析：** 捕获 InterruptedException 后必须恢复中断标志或继续向上抛。原因：异常被吞掉后中断信号丢失，上层无法再感知停止请求，这是阿里手册明确条款（恢复用 Thread.currentThread().interrupt()）。

**1.8**（来源 jvm）
**答案：A**
**解析：** 跨代引用通过记忆集与写屏障维护避免老年代全表扫描。原因：Minor GC 只扫新生代，但老年代可能引用新生代对象，写屏障在引用赋值时记录（卡表/RSet），空间换时间。

**1.9**（来源 spring）
**答案：C**
**解析：** Micrometer 是 Boot 的指标门面对接 Prometheus/Grafana。原因：自动暴露 JVM（内存/GC/线程）、HTTP（QPS/P99）、连接池指标，自定义 @Timed/MeterRegistry 埋业务指标。

**1.10**（来源 mysql）
**答案：A**
**解析：** explain analyze（8.0.18+）真实执行并报告每算子实际耗时与行数。原因：普通 explain 是优化器预估可能骗人，analyze 给出实际执行计划与耗时分布，是 SQL 优化利器。

**1.11**（来源 redis）
**答案：C**
**解析：** 排行榜实现：ZSet ZINCRBY 累分+ZREVRANGE 取榜+ZRANK 查排名。原因：分数相同按 member 字典序（可拼时间戳保证先到先得），分页 ZREVRANGE start stop，百万级成员性能仍可用。

**1.12**（来源 mongodb）

**1.13**（来源 mq）

**1.14**（来源 distributed）

**1.15**（来源 ai）

**2.1**（来源 algorithm）

**2.2**（来源 java-ai）

**2.3**（来源 agent-dev）

**2.4**（来源 java-basics）
**答案：B**
**解析：** 正确表述应为——Checked 异常编译期强制处理，RuntimeException 及其子类不强制。原因：Checked 的初衷是强制调用方处理可恢复错误，但工程实践暴露了大量吞异常问题。

**2.5**（来源 concurrency）
**答案：D**
**解析：** 正确表述应为——Java 线程有 6 种状态 BLOCKED 与 WAITING 语义不同。原因：BLOCKED 是等 monitor 锁，WAITING 是等 notify、join 或 LockSupport.park，TIMED_WAITING 是限时版。

**3.1**（来源 jvm）
**答案：对。** 解析：着色指针 + load barrier，应用线程访问时完成引用修正（并发转移期间对象搬迁无感知），这是 ZGC 停顿亚毫秒的机制核心，代价是每次访问带屏障开销

**3.2**（来源 spring）
**答案：错。** 正确表述：MyBatis 二级缓存 namespace 级多 SqlSession 共享但生产慎用。原因：跨 namespace 不可见（关联查询更新不失效）、序列化开销、集群下各节点独立（除非第三方实现），生产多用 Redis 缓存替代

**3.3**（来源 mysql）
**答案：错。** 正确表述：唯一索引不能使用 change buffer 而普通二级索引可以。原因：change buffer 把非唯一二级索引的写缓存起来合并减少随机读页，唯一索引必须立即判重无法缓存，写多读少场景普通索引更优

**3.4**（来源 redis）
**答案：对。** 解析：CONFIG SET 改淘汰策略/超时不用重启，变更后 CONFIG REWRITE 落盘，危险命令 ACL 治理

**3.5**（来源 mongodb）
**答案：错。** 正确表述：$lookup（关联查询）是性能黑洞能冗余就冗余。原因：跨集合关联相当于 SQL JOIN 但无索引优化时全扫，建模时冗余热点字段（如类目名进商品文档）避免 lookup

**3.6**（来源 mq）
