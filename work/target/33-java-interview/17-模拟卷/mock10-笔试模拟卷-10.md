## 参考答案与解析（自测后再看）

**1.1**（来源 algorithm）
**答案：B**
**解析：** 岛屿数量（DFS/BFS 沉岛）：网格图遍历（上下左右），访问标记（原地改 2 或 visited）。原因：网格图是图论的二维形态（笔试高频），沉岛（访问过改 0）免 visited 数组，BFS 版防栈深（大网格），与 AL-023 联动。

**1.2**（来源 java-ai）
**答案：D**
**解析：** 注入内容排序：检索片段按重要性重排（最相关放首尾，JA-510 布局工程），而非按检索分数顺序。原因：分数序≠注意力序（中间遗忘），布局策略是免费的精度提升，与上下文预算（JA-223）联动。

**1.3**（来源 agent-dev）
**答案：A**
**解析：** 自主性与确定性权衡：自主性高（灵活）但不可控，确定性高（可控可测）但不灵活，按任务错误代价定。原因：错误代价高的任务（支付/删除）要确定性（工作流/强人审），代价低的（总结/草稿）给自主性，与 JA-368 选型联动。

**1.4**（来源 java-basics）
**答案：D**
**解析：** ConcurrentSkipListMap 用跳表（多级索引链表）实现有序 + 高并发，基本操作 O(log n)。原因：跳表无需旋转即可维持平衡，天然适合无锁化并发读。

**1.5**（来源 concurrency）
**答案：B**
**解析：** CountDownLatch 计数不可重置用完即弃。原因：await 等计数到零，countDown 递减，构造时固定 count，重复使用需重建对象或改用 CyclicBarrier。

**1.6**（来源 jvm）
**答案：A**
**解析：** NMT 开启后 jcmd VM.native_memory summary 分项展示内存去向。原因：分类包括 Java Heap、Class、Thread、Code、GC、Internal、Other，把"消失的内存"按项对号，开销约 5%（detail 模式更高）。

**1.7**（来源 spring）
**答案：B**
**解析：** 自定义 starter：写自动配置类+条件注解+配置绑定+注册到 AutoConfiguration.imports。原因：命名规范官方 x-spring-boot-starter 自家 spring-boot-starter-x，提供 spring-configuration-metadata.json 让 IDE 补全。

**1.8**（来源 mysql）
**答案：A**
**解析：** MDL 元数据锁保护表结构：查询持 MDL 读锁 DDL 需 MDL 写锁。原因：长事务/慢查询持 MDL 读锁时 DDL 阻塞，且后续所有查询排在 DDL 之后（表完全不可用），online DDL 与运维操作必须避开高峰。

**1.9**（来源 redis）
**答案：B**
**解析：** AOF 重写（bgrewriteaof）按当前数据状态生成最小指令集压缩文件。原因：重写用 fork 子进程读当前数据写新 AOF，期间写命令进 aof_rewrite_buf 追加，文件膨胀与恢复变慢的解法。

**1.10**（来源 mongodb）
**答案：D**
**解析：** 分片三层架构：mongos（路由）→config 副本集（元数据）→shard（每个是副本集）。原因：mongos 无状态可扩容，config 存 chunk 分布元数据，shard 是普通副本集参与分片，各层独立伸缩。

**1.11**（来源 mq）
**答案：B**
**解析：** RocketMQ 顺序消费：MessageListenerOrderly+broker 队列锁，单队列单线程。原因：生产按 shardKey 路由到同一 queue，消费端锁队列保证单线程消费该队列，全局顺序仍需单队列（性能极低）。

**1.12**（来源 distributed）
**答案：B**
**解析：** 雪崩防护四板斧：超时（快速失败释放线程）、熔断（断开故障下游）、限流（入口保护）、隔离（舱壁限制爆炸半径）。原因：四者组合成纵深防御，缺一都有放大路径，配置随全链路对齐评审（超时预算），演练验证每层生效。

**1.13**（来源 ai）
**答案：D**
**解析：** 混合检索：向量（语义）+关键词（BM25 精确）双路召回后融合（RRF）。原因：向量对专有名词/编号召回弱（精确匹配是关键词强项），混合+重排是生产 RAG 标配，纯向量是常见质量短板。

**1.14**（来源 algorithm）
**答案：C**
**解析：** 摩尔投票求多数元素：候选人+计数抵消，出现超半数元素必胜出。原因：成对不同元素两两抵消，超半数元素在抵消后仍有剩余，O(N) O(1) 超过计数哈希方案。

**1.15**（来源 java-ai）
**答案：B**
**解析：** 长期记忆读取也要重排：向量召回的记忆条目经相关性重排（与 RAG 重排 JA-102 同构），记忆检索质量决定"人设连贯"。原因：长期记忆是二次 RAG（记忆库=特殊知识库），召回排序差则 Agent"健忘/记错"，重排同样适用。

**2.1**（来源 agent-dev）
**答案：B**
**解析：** 正确表述应为——MCP server 开发流程（Java）：定义工具 handler（请求→结果）→注册到 McpServer →选择 transport（stdio/SSE）→打包供宿主拉起。原因：流程四步与 JA-023 SDK 对应，每步有独立测试点（handler 单测/注册验证/transport 联调），是 MCP 工具开发的标准路径。

**2.2**（来源 java-basics）
**答案：B**
**解析：** 正确表述应为——重写 equals 必须满足自反、对称、传递、一致、非空（对 null 返回 false）五条。原因：违反任何一条都会导致该对象在集合中的行为异常。

**2.3**（来源 concurrency）
**答案：C**
**解析：** 正确表述应为——AQS 核心是一个 volatile int state 加 CLH 变体等待队列。原因：获取失败的线程封装成 Node 入队 park，释放时唤醒队首后继；state 语义由子类定义（重入次数、许可数、闩计数）。

**2.4**（来源 jvm）
**答案：C**
**解析：** 正确表述应为——CPU 100% 排查流程：top 找进程、top -Hp 找线程、printf '%x' 转十六进制、jstack 按线程号定位。原因：把 nid=0x十六进制 与线程栈对上，常见根因：死循环、正则回溯、GC 线程疯狂运转、JIT 编译。

**2.5**（来源 spring）
**答案：A**
**解析：** 正确表述应为——@MapperScan 通过 MapperScannerRegistrar 动态注册每个 Mapper 的 MapperFactoryBean。原因：每个接口变成 FactoryBean 产出的代理对象（MapperProxy），这就是"接口没有实现类却能注入"的原理。

**3.1**（来源 mysql）
**答案：对。** 解析：先看 type/rows/Extra 三要素，改索引最常见，改写（join 顺序、子查询转 join）其次，最后才是参数与架构

**3.2**（来源 redis）
**答案：对。** 解析：全量定时删除开销大，惰性漏删靠定期补偿，redis 的周期任务 hz 参数控制

**3.3**（来源 mongodb）
**答案：错。** 正确表述：副本集成员配置：priority（选举权重）、hidden（不可读）、delayed（延迟从库）。原因：priority 0 节点不主动竞选，hidden 从库专供备份/分析，delayed 从库（延迟 N 秒）防误操作恢复，官方文档核对

**3.4**（来源 mq）
**答案：错。** 正确表述：Kafka client quota 按 clientId/user 限速（生产/消费带宽与请求时间占比）。原因：防单业务打满 broker 网卡（多租户隔离），配额动态生效（kafka-configs 命令），超限被节流而非拒绝，与网关限流分层

**3.5**（来源 distributed）

**3.6**（来源 ai）
