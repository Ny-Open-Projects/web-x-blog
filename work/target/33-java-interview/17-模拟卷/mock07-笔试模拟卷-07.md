## 参考答案与解析（自测后再看）

**1.1**（来源 mq）
**答案：C**
**解析：** 乱序处理：按 key 分区路由保序+消费端单线程/串行队列。原因：跨分区无法保序，消费端并发处理同 key 需按 key 分发到串行队列（内存排队），P10 级别能说出"保序的完整链路"（生产路由+分区+消费串行）。

**1.2**（来源 distributed）
**答案：D**
**解析：** 性能三指标关系：并发数=QPS×RT（Little's Law）。原因：QPS 1000、RT 200ms → 并发 200（线程数/连接数规划依据），RT 上升时并发数暴涨（雪崩机制），容量规划与线程池参数的计算基础。

**1.3**（来源 ai）
**答案：C**
**解析：** 语义搜索：embedding 召回+关键词混合，解决"意思对但词不同"的召回。原因：传统搜索（分词+BM25）对同义改写弱，向量补语义召回，两者融合（RRF）+重排是现代搜索标配，与 RAG 检索（AI-008）同构。

**1.4**（来源 algorithm）
**答案：C**
**解析：** 拓扑排序：DAG 顶点线性序（依赖调度），Kahn 算法（入度表+BFS）或 DFS 后序逆序。原因：入度归零入队（BFS 版好写），存在环则顶点数<N（检测依赖循环），任务调度/构建顺序/课程表应用。

**1.5**（来源 java-ai）
**答案：C**
**解析：** RAG 语料质量检查器：重复段落/占位文本/乱码/超长行自动扫描（入库前质量门）。原因：垃圾进垃圾出（AI-039）的自动化门禁，入库前扫描比检索后排查便宜，与 MY-104 审核思想同构。

**1.6**（来源 agent-dev）
**答案：A**
**解析：** Agent 输入规范化：输入清洗（编码统一/控制字符剔除/超长截断 JA-397），规范化让注入检测更可靠（绕过编码的注入被规范化暴露）。原因：输入规范化是注入检测的前置（绕过手法常利用编码差异），规范化规则集（编码/空白/字符白名单），与输入校验（SP-068）联动。

**1.7**（来源 java-basics）
**答案：D**
**解析：** 两个编译期常量拼接（final String a="x"; String s=a+"y";）在编译期直接折叠为常量；含变量的拼接只能运行期计算。原因：常量折叠是编译器优化，变量拼接无法折叠。

**1.8**（来源 concurrency）
**答案：C**
**解析：** JDK9 引入 orTimeout 与 completeOnTimeout 给 CF 加超时。原因：超时不取消底层任务只是让 CF 以异常或默认值完成，任务线程仍可能在跑，彻底取消需要 cancel 配合任务自身响应中断。

**1.9**（来源 jvm）
**答案：C**
**解析：** AppCDS 把类加载产物缓存为文件加速启动。原因：-XX:SharedArchiveFile 预生成存档，微服务与 Serverless 冷启动场景收益明显（启动时间可降 30-50%），JDK10 起 AppCDS 开源。

**1.10**（来源 spring）
**答案：B**
**解析：** Spring 复习优先级：事务失效与传播 > Bean 生命周期与三级缓存 > AOP 原理 > Boot 自动配置 > MVC 流程。原因：按面试命中率排序（P7 岗位 JD 高频），每块都配手写复述（不看书讲清楚）再进下一块。

**1.11**（来源 mysql）
**答案：B**
**解析：** MVCC 靠 undo log 版本链：每行隐藏字段 trx_id 与 roll_pointer 指向历史版本。原因：读旧版本不加锁实现读写并行，回滚时沿版本链还原，undo log 在无活跃事务引用后由 purge 线程清理。

**1.12**（来源 redis）
**答案：D**
**解析：** SCAN 用游标渐进遍历不阻塞，但可能返回重复元素且不保证一致快照。原因：游标记录遍历位置，rehash 期间反向二进制迭代器保证不漏（可能重），业务侧去重。

**1.13**（来源 mongodb）
**答案：D**
**解析：** 副本集复制靠 oplog（固定容量循环覆盖的操作日志）从库拉取回放。原因：oplog 是 capped collection，从库异步回放，回放完成度决定读一致性，oplog 窗口是从库落后容忍上限。

**1.14**（来源 mq）
**答案：A**
**解析：** MQ 压测基线：生产 TPS、端到端延迟 P99、消费 TPS、积压恢复速度。原因：工具：Kafka 自带 perf / rocketmq-benchmark，按业务模型（消息大小/分区数/副本数）压，线上流量 <60% 基线预留。

**1.15**（来源 distributed）
**答案：B**
**解析：** K8s：Pod（实例）+Service（稳定虚拟 IP+负载均衡）+Deployment（副本管理）+ConfigMap/Secret（配置）。原因：服务发现内建（Service DNS），滚动发布/自愈（探针）声明式，Java 应用适配：优雅停机（preStop）、探针配置（liveness 不做重检查）。

**2.1**（来源 ai）
**答案：C**
**解析：** 正确表述应为——LLM 应用成本控制：模型分级（简单任务小模型）、缓存（相同请求/语义缓存）、压缩（精简 prompt/历史摘要）、批处理（离线任务半价）。原因：大模型成本占应用成本大头（计费按 token），分级路由（80% 简单任务用便宜模型）省 50%+，语义缓存（相似问题命中）是 RAG 场景利器，本项目总结的四招。

**2.2**（来源 algorithm）
**答案：C**
**解析：** 正确表述应为——双指针：对撞（有序数组两数之和 O(N)）、快慢（环形链表判环）、同向（去重）。原因：有序性是对撞指针的前提（单调性剪枝），快慢指针判环用速度差，空间 O(1)，与二分互补。

**2.3**（来源 java-ai）
**答案：B**
**解析：** 正确表述应为——图像理解任务分层：OCR（文字提取）/VQA（视觉问答）/图表理解（数据还原）三类难度与模型能力不同。原因：分层选模型与方案（JA-109/387），OCR 用专用模型更稳、图表理解需强视觉模型，混用导致质量错配。

**2.4**（来源 agent-dev）
**答案：B**
**解析：** 正确表述应为——Agent 执行循环骨架：while（任务未完成 && 步数未超限 && 预算未耗尽）{ 调模型→执行工具→回填结果 }。原因：三条件缺一不可：完成条件驱动终止、步数上限防死循环、预算防成本失控（JA-276/505 联动），手写 Agent 就是这个骨架。

**2.5**（来源 java-basics）
**答案：D**
**解析：** 正确表述应为——JDK8 的 ConcurrentHashMap 用 CAS + synchronized 锁单个桶头节点实现线程安全。原因：锁粒度细到桶级，冲突概率低时 synchronized（锁升级后）开销小且免额外内存。

**3.1**（来源 concurrency）
**答案：对。** 解析：两把锁分离读写提高并发但默认容量形同无界，用在 newFixedThreadPool 就是 OOM 根源

**3.2**（来源 jvm）
**答案：错。** 正确表述：方法内创建并只在本方法使用的对象理论上可栈上分配（经标量替换实现）。原因：HotSpot 不做真正的栈上分配而是把对象拆成标量进寄存器/栈，效果等同（分配消失），前提是不逃逸

**3.3**（来源 spring）
**答案：错。** 正确表述：多个切面的执行顺序由 @Order 值决定数字越小优先级越高。原因：事务切面 Order 默认 Ordered.LOWEST_PRECEDENCE，自定义切面想包在事务外需要更小值（先进入后退出）

**3.4**（来源 mysql）
**答案：错。** 正确表述：字符串列与数字比较发生隐式转换使索引失效。原因：MySQL 把字符串转数字比较（相当于对列套 cast 函数），手机号 varchar 列 where phone=13800138000 失效，参数必须传字符串

**3.5**（来源 redis）
**答案：错。** 正确表述：maxmemory 设置与 used_memory_rss 的差值监控防 OOM。原因：容器部署 Redis 必须设 maxmemory 且低于容器 limit（留 fork COW 与复制缓冲余量），超限触发淘汰或拒绝写

**3.6**（来源 mongodb）
**答案：错。** 正确表述：projection 排除 _id 且所有返回字段在索引中则覆盖查询免回表。原因：explain 看 FETCH 阶段消失（PROJECTION_COVERED），与 MySQL 覆盖索引同构

**3.7**（来源 mq）
