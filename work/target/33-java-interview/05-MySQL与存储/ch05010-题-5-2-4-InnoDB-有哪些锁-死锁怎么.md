### 题 5.2.4：InnoDB 有哪些锁？死锁怎么办？

**【参考回答（可背）】**
锁分类：
1. 粒度：全局（FTWRL）、表级（表锁、**元数据锁 MDL**、意向锁 IS/IX）、行级；
2. 行锁三种（RR）：**记录锁**、**间隙锁**（锁区间不锁记录，RR 防幻读的关键，RC 无）、**Next-Key**（记录+间隙，左开右闭）；
3. 意图：共享 S / 排他 X（select for update、DML 自动加 X）；
4. 插入意向锁（gap 冲突时的兼容协调）；
5. 其他：自增锁（auto-inc，MySQL 8 改为轻量级互斥量，innodb_autoinc_lock_mode=2 交错模式配合批量插入最佳）、外键锁。

死锁：两个事务互相等待对方持有的锁。排查：`show engine innodb status` 的 LATEST DETECTED DEADLOCK 段（生产建议打开 innodb_print_all_deadlocks 记全量到错误日志）。
预防清单：**多表/多行操作按固定顺序、大事务拆小、RR→RC 消间隙锁、热点行用乐观锁版本号或排队串行化、索引避免锁升级为表扫（无索引 where 会锁全部扫过的行）**。

**【P10 加分项】**
热点行更新（秒杀扣库存）专项：单行锁成为瓶颈时——① 库存分段（拆 N 行轮询）② Redis 预扣 + 异步落库 ③ 排队（串行化消除锁竞争）；并讲 MySQL 8.0 的热点更新优化（innodb 允许 skipping lock wait 的 SKIP LOCKED / NOWAIT）。
