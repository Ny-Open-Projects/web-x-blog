### 题 5.2.1：什么是索引下推？什么是最左前缀？联合索引 (a,b,c) 能支持哪些查询？

**【参考回答（可背）】**
- **最左前缀**：联合索引按 a→b→c 排序，查询条件必须从最左列开始连续命中：`a=1`、`a=1 and b=2`、`a=1 and b=2 and c=3` 可用；`b=2`、`a=1 and c=3`（c 断层，只能用到 a）。范围查询（a>1）后右边的列用不上索引排序，但过滤仍可走（ICP）。
- **索引下推 ICP（5.6+）**：`where a like '张%' and b=10`，没有 ICP 时引擎要回表所有"张"姓行再由 Server 过滤 b；有 ICP 时**在引擎层先用索引里的 b 过滤**，回表次数大幅减少（explain 出现 Using index condition）。
- 排序优化：`order by a, b` 可用索引免排序；`where a=1 order by b` 也可用（a 是常量后 b 有序）。

**【追问链】**
1. 建索引原则？→ 区分度高、查询频繁、联合索引把等值条件放前、区分度放后（视场景）；前缀索引（长字符串取前 N 位，注意失去覆盖能力）；不超过太多列（写放大）。
2. 为什么主键要自增？→ 顺序插入页尾，避免**页分裂**（随机主键如 UUID 导致频繁分裂+碎片+缓存命中率低）。分布式下用雪花 ID 等"趋势递增"。

**【P10 加分项】**
讲"索引是双刃剑"：每个索引都是一棵要维护的 B+ 树，写放大 = 每个索引都要写；change buffer 对二级索引写优化（非唯一索引，页不在内存时先记 buffer，读时合并）。给出团队规范示例：单表索引 ≤5 个（经验值不是教条）、上线前慢 SQL 门禁（explain 成本预估）。
