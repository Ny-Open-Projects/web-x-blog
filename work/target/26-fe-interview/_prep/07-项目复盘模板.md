# 项目复盘模板

> 一句话：**八股决定你过不过一面，项目决定你过不过二面。**
> 大厂二面的 60 分钟里，至少 20 分钟在问项目。项目讲砸了，八股再熟也救不回来。

---

## 一、先选题：从你的经历里挑 1~2 个

| | 技术难度低 | 技术难度高 |
|---|---|---|
| **业务价值高** | 可用作"协作/推进"故事 | ✅ **首选**：既难又有价值 |
| **业务价值低** | 不用讲 | 可讲"技术探索"，但要能说清业务收益 |

**选题标准**：你亲手做过核心模块 + 有可量化的结果 + 踩过真实的坑。

**每个方向各备一个**：一个"性能优化"、一个"架构/基建"、一个"复杂业务"。面试官问什么方向，你都能接。

---

## 二、复盘模板（照这个填，一个项目一页）

```markdown
## 项目名：______

### 1. 背景（30 秒能讲完）
- 业务是什么：
- 用户/数据量级：（DAU/QPS/SKU 数/团队规模，至少给一个）
- 原来存在什么问题：（越具体越好，带现象和数据）

### 2. 我的角色（20 秒）
- 团队规模与我的位置：
- 我负责的模块：
- 我做的关键技术决策：（1~2 个，必须是"我定的"）

### 3. 方案与取舍（90 秒，核心）
- 方案 A：…… 优点/代价
- 方案 B：…… 优点/代价
- 最终选：______，因为______
- 关键技术难点：______，怎么解的：______

### 4. 结果（30 秒，必须有数字）
| 指标 | 优化前 | 优化后 | 手段 |
|---|---|---|---|
| 首屏/LCP |  |  |  |
| 接口耗时 |  |  |  |
| 研发效率 |  |  |  |
| 线上错误率 |  |  |  |

### 5. 复盘（30 秒，最加分）
- 如果重来，我会先做______（体现判断力）
- 遗留问题：______（体现诚实与持续思考）
- 沉淀了什么：规范/工具/文档，被谁复用了
```

## 三、面试官一定会追问的 6 个问题（提前准备答案）

1. **"这个方案为什么不用 XXX？"** → 准备 2 个被否掉的替代方案及原因。
2. **"数据是怎么测出来的？"** → 说清采集方式（Lighthouse/埋点/RUM），别说"感觉快了"。
3. **"如果流量翻 10 倍会怎样？"** → 说瓶颈点 + 扩容/降级手段。
4. **"你个人具体做了什么？"** → 区分"团队做的"和"我做的"，别揽功也别谦让。
5. **"遇到过最大的坑是什么？"** → 一个真实故障 + 排查过程 + 后续机制。
6. **"这个项目有什么不足？"** → 别答"没有"，答 1 个真实的技术债 + 你的改进计划。

---

## 四、数据准备清单（面试前必须能脱口而出）

- [ ] 项目的用户量/请求量级
- [ ] 至少 2 个性能指标的前后对比
- [ ] 至少 1 个研发效率指标（构建时间/发布频率/缺陷率）
- [ ] 团队规模与你协作的角色
- [ ] 一次真实故障的影响面与恢复时间

**没有数字的项目叙述 = 没有说服力。** 记不清就去查监控/看周报/问老同事。

---

## 五、常见坑

- ❌ **流水账**："我先做了 A，又做了 B" —— 面试官要听**决策**，不是排期。
- ❌ **只讲技术不讲业务**：说不出"为什么要做"，会被判定为执行层。
- ❌ **揽全功**：说"我主导了整个系统"，一追问细节就穿帮。
- ❌ **没有失败**：讲一个"全程顺利"的项目，反而显得没深度。
- ❌ **超时**：主项目控制在 18~22 分钟，留时间给追问。

---

## 六、练法

1. 按模板填完，**写成一页纸**；
2. 对着录音讲 3 遍，第 3 遍控制在 20 分钟内；
3. 找朋友扮演面试官，专挑第 3 节的"取舍"追问；
4. 把答不上来的问题补进模板，再讲一遍。
