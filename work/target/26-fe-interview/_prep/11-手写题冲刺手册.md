## 1. 手写题到底在考什么

面试官让你手写，不是为了看你能不能写出可用代码（那些库都有），而是在 10~15 分钟里判断三件事：

| 考察维度 | 面试官在看什么 | 你的信号 |
|---|---|---|
| **边界意识** | 你有没有主动想到空值、重复调用、并发、异常 | 写完主动说"这里我处理了 X 情况" |
| **抽象能力** | 你能不能在没框架的情况下把逻辑拆清楚 | 先写骨架函数签名，再填内部 |
| **真实经验** | 你写的东西有没有踩过坑的痕迹 | 追问时能说出"生产里这里会出 X 问题" |

**最容易被忽略的一条**：手写题的评分，**追问占一半**。写出 `Promise.all` 只是及格，能答上"如果要求限并发怎么办"才是通过。

### 三类手写题，三种准备方式

| 类型 | 例子 | 准备方式 |
|---|---|---|
| **工具函数**（有标准答案） | 防抖、节流、深拷贝、柯里化、call/bind | **背模板**，练到肌肉记忆，5 分钟内写完 |
| **原理模拟**（有内在逻辑） | Promise 核心、Vue reactive、diff、useState | **理解机制**再写，重点是能解释"为什么这样设计" |
| **设计题**（无标准答案） | 任务队列、限流器、表单引擎、路由 | **练抽象**，先讲清接口再写实现 |

## 3. 四步答题法（白板上就这么做）

### 第 1 步 · 先问清楚（30 秒）

不要提笔就写。先问三句：

> "这个函数需要支持取消吗？"
> "调用频率大概什么量级——是滚动事件还是按钮点击？"
> "入参可能是 null / 循环引用吗？"

这三句问出去，面试官立刻知道你想过真实场景。**这是手写题最快的加分动作，成本只有 30 秒。**

### 第 2 步 · 写骨架（1 分钟）

```javascript
function debounce(fn, wait, options = {}) {
  // 1. 状态：timer、lastCallTime、lastResult
  let timer = null;

  function debounced(...args) {
    // 2. 边界：清理 → 判断 leading → 设置 trailing
  }

  debounced.cancel = () => {};
  debounced.flush = () => {};
  return debounced;
}
```

骨架里先写注释标出「状态 / 边界 / 返回值」，再填。**这比边想边写快一倍**，而且面试官能看到你的思路结构。

### 第 3 步 · 填核心逻辑（5~8 分钟）

按骨架填。填的时候**嘴里不要停**：

> "这里是清理上一次的定时器，否则会重复触发……这里判断 immediate，如果是首次调用就立刻执行……"

边说边写的好处：即使写错一点，面试官也知道你思路对——**分数给的是思路，不是代码**。

### 第 4 步 · 主动报边界（2 分钟）

写完不要等面试官问，自己说：

> "这里有几个我特意处理的边界：第一，重复调用会清掉旧 timer；第二，cancel 之后 timer 置空，避免误触发；第三，如果 wait 传 0 会退化成同步执行，生产里我会加个下限。"

**这一步是区分"背过"和"想过"的唯一标志。**

## 4. 12 个万能模板

### 4.1 防抖（完整版，含 leading/trailing/cancel/flush）

```javascript
/**
 * @param {Function} fn 目标函数
 * @param {number} wait 等待时间
 * @param {{leading?:boolean, trailing?:boolean}} options
 */
function debounce(fn, wait, { leading = false, trailing = true } = {}) {
  let timer = null;
  let lastArgs = null;
  let lastThis = null;
  let invoked = false;                       // 本轮是否已执行过 leading

  function invoke() {
    if (lastArgs) {
      fn.apply(lastThis, lastArgs);
      lastArgs = lastThis = null;
      invoked = true;
    }
  }

  function debounced(...args) {
    lastArgs = args;
    lastThis = this;
    const isFirst = timer === null;

    if (timer) clearTimeout(timer);

    if (leading && isFirst && !invoked) {     // 首调立刻执行
      invoke();
    }

    timer = setTimeout(() => {
      timer = null;
      invoked = false;
      if (trailing && lastArgs) invoke();     // 尾调补一次
    }, wait);
  }

  debounced.cancel = () => {
    clearTimeout(timer);
    timer = null;
    lastArgs = lastThis = null;
    invoked = false;
  };
  debounced.flush = () => {
    if (timer) { clearTimeout(timer); timer = null; invoke(); }
  };

  return debounced;
}
```

**必答边界**：重复调用清旧 timer / leading 只在本轮首次生效 / cancel 后不残留 / `this` 与 `arguments` 要透传 / 返回值（异步的没法返回，要说明）。

**追问**：为什么不能用箭头函数接 `this`？（箭头函数没有自己的 this，拿不到调用方上下文）

### 4.2 节流（时间戳 + 定时器双保险）

```javascript
function throttle(fn, wait) {
  let last = 0;
  let timer = null;

  return function throttled(...args) {
    const now = Date.now();
    const remaining = wait - (now - last);

    if (remaining <= 0) {
      // 已经过了一个周期，立即执行
      if (timer) { clearTimeout(timer); timer = null; }
      last = now;
      fn.apply(this, args);
    } else if (!timer) {
      // 周期内，安排一次尾部执行（保证最后一次不丢）
      timer = setTimeout(() => {
        last = Date.now();
        timer = null;
        fn.apply(this, args);
      }, remaining);
    }
  };
}
```

**为什么两个都用**：纯时间戳版会丢最后一次（用户停止操作后不再触发）；纯定时器版首次不立即执行且间隔不准。**两个结合才能既不丢首次也不丢末次。**

### 4.3 `Promise.all`

```javascript
function myAll(promises) {
  return new Promise((resolve, reject) => {
    const arr = Array.from(promises);        // 兼容 iterable
    const results = new Array(arr.length);   // 按索引放，保证顺序
    let count = 0;
    if (arr.length === 0) return resolve([]);

    arr.forEach((p, i) => {
      Promise.resolve(p).then((val) => {     // 非 Promise 值也要包一层
        results[i] = val;
        if (++count === arr.length) resolve(results);
      }, reject);                             // 任一失败立即失败
    });
  });
}
```

**必答边界**：空数组立即 resolve / 非 Promise 值原样进入结果 / **结果按入参顺序而非完成顺序** / 任一 reject 立即 reject（但其他请求无法取消，这点要说）。

### 4.4 深拷贝（面试够用版）

```javascript
function deepClone(obj, cache = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj;
  if (cache.has(obj)) return cache.get(obj);       // 循环引用

  let clone;
  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj.source, obj.flags);
  if (obj instanceof Map) {
    clone = new Map();
    cache.set(obj, clone);
    obj.forEach((v, k) => clone.set(deepClone(k, cache), deepClone(v, cache)));
    return clone;
  }
  if (obj instanceof Set) {
    clone = new Set();
    cache.set(obj, clone);
    obj.forEach((v) => clone.add(deepClone(v, cache)));
    return clone;
  }
  if (Array.isArray(obj)) {
    clone = [];
    cache.set(obj, clone);
    obj.forEach((v, i) => (clone[i] = deepClone(v, cache)));
    return clone;
  }

  clone = Object.create(Object.getPrototypeOf(obj));  // 保留原型
  cache.set(obj, clone);
  for (const key of Reflect.ownKeys(obj)) {            // 含 Symbol 键
    const desc = Object.getOwnPropertyDescriptor(obj, key);
    if (desc && 'value' in desc) {
      clone[key] = deepClone(obj[key], cache);          // 只拷值，保留 getter
    } else {
      Object.defineProperty(clone, key, desc);
    }
  }
  return clone;
}
```

**必答边界**：循环引用（WeakMap）/ Date、RegExp、Map、Set / Symbol 键 / 原型链 / 函数不拷（直接返回引用）/ getter 保留语义。

**追问必答**：`structuredClone` 能替代吗？→ 能，但不支持函数、DOM 节点、自定义类原型、Symbol 键。`JSON.parse(JSON.stringify())` 的问题？→ Date 变字符串、undefined/函数丢失、NaN→null、循环引用抛错、RegExp 变空对象。

### 4.5 `EventEmitter`

```javascript
class EventEmitter {
  constructor() { this.events = new Map(); }

  on(name, fn) {
    if (!this.events.has(name)) this.events.set(name, []);
    this.events.get(name).push({ fn, once: false });
    return this;                                  // 支持链式
  }

  once(name, fn) {
    if (!this.events.has(name)) this.events.set(name, []);
    this.events.get(name).push({ fn, once: true });
    return this;
  }

  off(name, fn) {
    const list = this.events.get(name);
    if (!list) return this;
    // 注意：同一函数注册多次只删一个，或全删？面试时先问清楚
    const idx = list.findIndex((l) => l.fn === fn);
    if (idx > -1) list.splice(idx, 1);
    if (list.length === 0) this.events.delete(name);
    return this;
  }

  emit(name, ...args) {
    const list = this.events.get(name);
    if (!list) return false;
    [...list].forEach((l) => {                    // 拷贝，防止回调里 off 破坏遍历
      l.fn.apply(this, args);
      if (l.once) this.off(name, l.fn);
    });
    return true;
  }
}
```

**必答边界**：`emit` 时拷贝数组（否则回调里 `off` 会让遍历错位）/ `once` 执行后自删 / 同名多注册的处理 / 是否需要 `removeAllListeners` / 是否需要 `error` 事件特殊处理（Node 的约定：无监听时抛错）。

### 4.6 `p-limit`（并发控制）

```javascript
function pLimit(concurrency) {
  const queue = [];
  let active = 0;

  const next = () => {
    if (active >= concurrency || queue.length === 0) return;
    active++;
    const { fn, resolve, reject } = queue.shift();
    Promise.resolve()
      .then(fn)
      .then(resolve, reject)
      .finally(() => { active--; next(); });      // 完成一个补一个
  };

  return function limit(fn) {
    return new Promise((resolve, reject) => {
      queue.push({ fn, resolve, reject });
      next();
    });
  };
}
```

**关键洞察**：不是"分批跑"，而是"完成一个补一个"。分批跑会让长任务拖慢整批。

### 4.7 `retry`（指数退避 + 抖动）

```javascript
async function retry(fn, { times = 3, base = 300, jitter = true } = {}) {
  let lastErr;
  for (let i = 0; i < times; i++) {
    try {
      return await fn(i);
    } catch (err) {
      lastErr = err;
      if (i === times - 1) break;
      let delay = base * 2 ** i;
      if (jitter) delay = delay * (0.5 + Math.random() * 0.5);   // 防雪崩
      await new Promise((r) => setTimeout(r, delay));
    }
  }
  throw lastErr;
}
```

**为什么要抖动**：不抖动的话，一批同时失败的请求会在同一时刻重试，形成"重试风暴"把刚恢复的服务再打挂。

### 4.8 `call` / `apply` / `bind`

```javascript
Function.prototype.myCall = function (ctx, ...args) {
  ctx = ctx ?? globalThis;
  const key = Symbol('fn');                 // 用 Symbol 避免属性冲突
  ctx[key] = this;
  const ret = ctx[key](...args);
  delete ctx[key];                          // 用完必须删，否则污染 ctx
  return ret;
};

Function.prototype.myApply = function (ctx, args = []) {
  return this.myCall(ctx, ...args);
};

Function.prototype.myBind = function (ctx, ...preset) {
  const fn = this;
  function Bound(...later) {
    // new 调用时，this 应指向新对象而不是 ctx
    return fn.apply(this instanceof Bound ? this : ctx, [...preset, ...later]);
  }
  Bound.prototype = Object.create(fn.prototype);   // 保留原型链（instanceof 才有效）
  return Bound;
};
```

**必答边界**：`ctx` 为 null/undefined 时要回退到全局 / Symbol 做键防冲突 / 用完 delete / **`bind` 后的函数被 `new` 调用时 this 要指向新对象**（这是最高频的追问点）。

### 4.9 柯里化（含占位符）

```javascript
const PLACEHOLDER = Symbol('placeholder');

function curry(fn) {
  return function curried(...args) {
    // 参数够了、且没有占位符 → 执行
    const hasPlaceholder = args.slice(0, fn.length).includes(PLACEHOLDER);
    if (args.length >= fn.length && !hasPlaceholder) {
      return fn.apply(this, args);
    }
    return function (...next) {
      const merged = args.map((a) => (a === PLACEHOLDER ? next.shift() : a));
      return curried.apply(this, merged.concat(next));
    };
  };
}
```

### 4.11 `useState`（React 原理版）

```javascript
let hookIndex = 0;
const states = [];

function useState(initial) {
  const i = hookIndex;                                   // 闭包锁定当前 hook 位
  states[i] = states[i] ?? (typeof initial === 'function' ? initial() : initial);

  const setState = (next) => {
    const val = typeof next === 'function' ? next(states[i]) : next;
    if (Object.is(val, states[i])) return;               // 相同值不触发渲染
    states[i] = val;
    scheduleRender();                                    // 触发重渲染，重置 hookIndex
  };
  hookIndex++;
  return [states[i], setState];
}

function scheduleRender() {
  hookIndex = 0;                                          // 关键：每次渲染前重置
  /* 真实环境：重新执行组件函数 */
}
```

**为什么 hook 不能写在条件里**：靠调用顺序（下标）定位状态，条件分支会打乱顺序。

### 4.12 LRU

```javascript
class LRUCache {
  constructor(capacity) { this.cap = capacity; this.map = new Map(); }
  get(key) {
    if (!this.map.has(key)) return -1;
    const v = this.map.get(key);
    this.map.delete(key);
    this.map.set(key, v);        // 重新插入 = 移到最新
    return v;
  }
  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    else if (this.map.size >= this.cap) {
      this.map.delete(this.map.keys().next().value);   // 第一个 = 最久未用
    }
    this.map.set(key, value);
  }
}
```

**追问必答**：为什么 `Map` 能做到 O(1)？→ 它内部是哈希表 + 插入序链表。手写版怎么实现？→ 哈希表 + 双向链表（必须双向，单链表删尾要 O(n)）。

## 5. 十个高频追问与标准答法

| 追问 | 标准答法（照这个说就能过） |
|---|---|
| **"防抖和节流什么区别？"** | 防抖是"等你不动了才执行"，节流是"不管你多快，我按固定频率执行"。滚动加载用节流，搜索输入用防抖。 |
| **"`bind` 后能再 `bind` 吗？"** | 不能改变 this，第一次 bind 的 ctx 就锁死了。这是规范行为。 |
| **"`Promise.all` 里某个失败，其他会取消吗？"** | 不会。JS 的 Promise 没有取消语义，其他请求照常跑完，只是结果被丢弃。要真取消得用 AbortController。 |
| **"深拷贝会不会有性能问题？"** | 会。大对象是 O(n) 全遍历。React 里更常用结构共享（只复制改动路径上的节点），成本 O(log n)。 |
| **"为什么用 WeakMap 存循环引用？"** | 两个原因：键是弱引用，对象被回收时缓存自动清掉不会内存泄漏；而且键必须是对象。 |
| **"你的节流为什么首次也执行？"** | 因为 `last` 初始化为 0，`now - last` 远大于 wait，所以首次必定立即执行。如果要禁止首次，把 `last` 初始化为 `Date.now()`。 |
| **"限流为什么不用 `setInterval` 补桶？"** | 定时器有精度问题、页面切后台会被节流、还容易泄漏。惰性补桶（每次取令牌时按时间差算）零开销且精确。 |
| **"虚拟列表为什么用 `transform` 不用 `top`？"** | `transform` 走合成层，只触发重绘/合成，不触发重排；改 `top` 会走 layout，代价高得多。 |
| **"`useEffect` 和 `useLayoutEffect` 区别？"** | 前者在浏览器绘制后异步执行，不阻塞渲染；后者在 DOM 更新后、绘制前同步执行，适合测量布局。 |
| **"手写题写完你会怎么测？"** | 报边界清单 + 说清怎么验证。比如防抖：连点 10 次只执行 1 次、cancel 后不再执行、leading 模式首次立即执行。 |

## 6. 训练方法（三遍法）

手写题的核心不是"看懂"，是"手能写出来"。看懂和写出之间差着 10 遍练习。

**第一遍 · 抄（30 分钟）**
照着手册的模板抄一遍，边抄边念注释。目的是建立"骨架记忆"。

**第二遍 · 默（40 分钟）**
关掉参考，凭记忆写。写不出来就卡在那，**不要偷看**——卡住的地方就是你真正的盲点。写完再对照，把差异标出来。

**第三遍 · 讲（20 分钟）**
写完后对着空气讲一遍："这个函数解决什么问题、关键在哪里、我处理了哪些边界。"讲不顺的地方说明你还没真懂。

**每 3 天做一轮**，20 道 L1 题循环。两周后这 20 道会变成条件反射，那时再攻 L2。

**判断标准**：不是"我能写出来"，而是"**我在紧张状态下、没有 IDE 补全、边讲边写，也能 8 分钟内写对**"。达不到就再练一轮。

---

## 7. 白板环境的四个现实问题

这些问题真实考场上会遇到，提前想好：

1. **没有自动补全** → 常用 API 要背：`Object.getOwnPropertyDescriptor`、`Reflect.ownKeys`、`Symbol.iterator`。写不出 API 名就说"这里我需要拿到所有自有键，用 Reflect.ownKeys"，面试官会认可。
2. **没有运行环境** → 写完靠"脑内执行"。养成习惯：写完立刻用一个小例子走一遍代码路径（`[3,3], 6` 走一遍两数之和）。
3. **空间有限** → 白板别写注释占地方，只写关键变量名和边界分支。注释用嘴说。
4. **写错要擦** → 不要怕改。发现错了立刻说"这里我改一下，因为 X 情况没处理"，改正的过程本身是加分项。

## 8. 最后一句

手写题是前端面试里**投入产出比最高**的一块：20 道 L1 题，练两周，几乎覆盖所有一面的手写环节。

但它也是最容易"自以为会"的一块——看得懂模板 ≠ 写得出代码。所以：

> **不要用"读"的方式准备手写题。用"默写"的方式。**

配套：`../20-手写题专题/` 有 10 个专题的完整实现与追问链，每个专题都标了 L1/L2/L3 分层，按层推进即可。
