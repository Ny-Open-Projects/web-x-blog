# 场景算法冲刺手册

> 配套题库：`../19-场景算法专题/`（10 个专题 · 精讲 60 题 · 覆盖原卡 550 道）
> 一句话定位：**LeetCode 考"你能不能想到正确解法"，场景题考"你能不能在模糊需求里选出对的数据结构"。**

---

## 1. 场景题和 LeetCode 题的本质区别

| | LeetCode 类 | 场景类 |
|---|---|---|
| 题目形态 | 输入输出明确、有标准答案 | 只给业务描述，边界要自己问 |
| 考察重点 | 算法正确性、复杂度 | **抽象能力**：把业务映射成数据结构 |
| 难度来源 | 想不出来 | 想太多 / 想太少 |
| 及格线 | 代码跑通 | 方案能落地 + 说清代价 |
| 典型题 | 接雨水、编辑距离 | "虚拟列表怎么定位锚点"、"权限树半选怎么算" |

**关键区别**：场景题**没有唯一解**，面试官看的是"你的选择有没有理由"。所以答题时要主动说取舍，而不是闷头写一种解法。

### 场景题的三层结构

```
业务需求（模糊）
   ↓ 抽象
数据结构（选型）      ← 分水岭在这里
   ↓ 映射
算法手法（模板）
   ↓ 落地
复杂度与边界
```

**90% 的人卡在第二层**：他们会写算法，但不知道"这个需求该用 Map 还是 Trie 还是单调栈"。这份手册的主干，就是解决第二层。

## 3. 五步答题法

场景题不是"读完就写"，是"读完先框定"。这五步在面试里全程说出口。

### 第 1 步 · 复述 + 追问（1 分钟）

把需求用自己的话说一遍，然后问三个问题：

> "数据量大概什么量级——几百条还是十万条？"
> "这个操作是一次性的，还是高频反复触发？"
> "并发场景要考虑吗——多个标签页 / 多个用户同时改？"

**为什么必须先问**：数据量决定复杂度上限（10 万条就不能 O(n²)），触发频率决定要不要缓存，并发决定要不要加锁/幂等。**这三问不问，方案一定是错的。**

### 第 2 步 · 定数据结构（2 分钟）

说出你的选择，并给理由：

> "我会用 Map 存 id → 节点引用，因为需要 O(1) 反查父节点；如果只用数组，找父节点要 O(n)。"

**这一步是全场最关键的 2 分钟。** 说清楚"为什么不用另一个"，比说出正确选择更值钱。

### 第 3 步 · 说方案 + 复杂度（1 分钟）

> "整体是一次遍历 O(n)，空间 O(n) 存这个 Map。如果内存敏感，可以改成两次遍历、O(1) 空间，但会慢一点。"

主动给替代方案，展示你考虑过取舍。

### 第 4 步 · 写核心代码（8~10 分钟）

只写关键函数，不写 UI 胶水。写完标出边界。

### 第 5 步 · 报边界 + 扩展（2 分钟）

> "几个边界我处理了：空数据、单节点、id 重复。如果要支持增量更新，这里再加一个 dirty 标记就行。"

## 4. 十个场景范式（可直接套）

### 范式 1 · 扁平 ↔ 嵌套（最高频）

```javascript
// 扁平转树：一次遍历 + 引用回填，O(n)
function listToTree(list, rootId = null) {
  const map = new Map();
  for (const item of list) map.set(item.id, { ...item, children: [] });

  const roots = [];
  for (const item of list) {
    const node = map.get(item.id);
    const parent = map.get(item.pid);
    if (item.pid === rootId || !parent) roots.push(node);
    else parent.children.push(node);
  }
  return roots;
}
```

**为什么不用递归找父节点**：那是 O(n²)。引用回填是 O(n)，这是这道题的采分核心。

### 范式 2 · 树的后序聚合（半选、剪枝、深度）

```javascript
// 权限树半选：后序返回二元组，避免两次遍历
function computeCheckState(node) {
  if (!node.children?.length) {
    return { checked: !!node.checked, some: false };
  }
  let allChecked = true, anyChecked = false;
  for (const child of node.children) {
    const s = computeCheckState(child);
    if (!s.checked) allChecked = false;
    if (s.checked || s.some) anyChecked = true;
  }
  node.checked = allChecked;
  node.indeterminate = !allChecked && anyChecked;   // 半选
  return { checked: allChecked, some: anyChecked };
}
```

**为什么用后序**：父的状态依赖所有子节点的结果，必须先算完子再算父。前序做不到。

### 范式 3 · 一次遍历多维聚合

```javascript
// 单次遍历完成分组 + 求和 + 计数，避免多次 filter
function aggregateByCity(orders) {
  const map = new Map();
  for (const { city, amount } of orders) {
    const acc = map.get(city) || { city, total: 0, count: 0, max: -Infinity };
    acc.total += amount;
    acc.count += 1;
    acc.max = Math.max(acc.max, amount);
    map.set(city, acc);
  }
  return [...map.values()];
}
```

### 范式 4 · 滑动窗口（限流、去重窗口、连续片段）

```javascript
// 滑动窗口限流：队列裁剪版，消除固定窗口的边界突刺
class SlidingWindowLimiter {
  constructor(limit, interval) {
    this.limit = limit;
    this.interval = interval;
    this.hits = [];                     // 存时间戳
  }
  allow(now = Date.now()) {
    const cutoff = now - this.interval;
    while (this.hits.length && this.hits[0] <= cutoff) this.hits.shift();
    if (this.hits.length >= this.limit) return false;
    this.hits.push(now);
    return true;
  }
}
```

### 范式 5 · 惰性计算（补桶、缓存失效、脏检查）

```javascript
// 令牌桶：不用定时器，取令牌时按时间差惰性补
class TokenBucket {
  constructor(capacity, rate) {
    this.capacity = capacity;
    this.rate = rate;                   // 每秒补多少
    this.tokens = capacity;
    this.last = Date.now();
  }
  take(n = 1) {
    const now = Date.now();
    const delta = ((now - this.last) / 1000) * this.rate;
    this.tokens = Math.min(this.capacity, this.tokens + delta);
    this.last = now;
    if (this.tokens < n) return false;
    this.tokens -= n;
    return true;
  }
}
```

**为什么不用 `setInterval`**：定时器精度差、后台标签页会被节流、还容易泄漏。惰性补桶零开销。

### 范式 7 · 合并标记（请求去重、单飞）

```javascript
// 同 key 并发请求共享同一个 Promise
const inflight = new Map();

function dedupeRequest(key, request) {
  if (inflight.has(key)) return inflight.get(key);
  const p = request().finally(() => inflight.delete(key));
  inflight.set(key, p);
  return p;
}
```

**注意**：`finally` 里删除，否则失败后永久缓存了 rejected Promise。

### 范式 8 · 空间换时间（前缀和、缓存、索引）

```javascript
// 二维前缀和：区域查询 O(1)
function buildPrefix2D(matrix) {
  const m = matrix.length, n = matrix[0].length;
  const pre = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      pre[i][j] = matrix[i - 1][j - 1] + pre[i - 1][j] + pre[i][j - 1] - pre[i - 1][j - 1];
    }
  }
  return pre;
}
// 查询 (r1,c1)~(r2,c2)：pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1]
```

### 范式 9 · 分片与让路（长任务不卡 UI）

```javascript
// 时间切片：每片 30ms 预算，让出主线程
function scheduleChunked(items, handle, budget = 30) {
  let i = 0;
  function tick() {
    const start = performance.now();
    while (i < items.length && performance.now() - start < budget) {
      handle(items[i++]);
    }
    if (i < items.length) setTimeout(tick, 0);   // 让出主线程
  }
  tick();
}
```

**为什么是 30ms**：一帧 16.7ms，超过 50ms 会被记为 Long Task。30ms 留出余量。

### 范式 10 · 一致性保障（幂等 + 版本号 + 对账）

```javascript
// 幂等键：同一业务操作重复提交只生效一次
function makeIdempotencyKey(bizType, bizId, extra = '') {
  return `${bizType}:${bizId}:${hash(extra)}`;   // 服务端按此键去重
}
// 乐观锁：带版本号提交，冲突时 412，前端提示刷新
// 对账：本地乐观更新 + 服务端返回后按 id 归并，冲突以服务端为准
```

## 5. 五个最容易犯的错

| 错误 | 为什么错 | 正确做法 |
|---|---|---|
| **上来就写代码** | 没有框定数据量，可能选错复杂度 | 先问数据量、频率、并发 |
| **过度设计** | 几百条数据用线段树，面试官会认为你不懂取舍 | 说出"当前量级哈希就够，如果到百万级再换 XX" |
| **只给一种解法** | 场景题没有唯一解，只给一种显得没想过替代 | 给主方案 + 一句替代方案的取舍 |
| **忽略真实约束** | 只说算法，不说内存、首屏、交互体验 | 主动提"这里会阻塞主线程，要切片" |
| **答完就停** | 场景题常追加"如果数据翻 100 倍呢" | 主动说扩展路径，或预留钩子 |

## 8. 最后一句

场景算法题是**最像真实工作**的一类题。它考的抽象能力——把模糊需求映射成数据结构——正是从"能写代码"到"能设计方案"的那道坎。

所以准备它的时候，别只问"这题怎么写"，多问一句：

> **"如果这个需求明天变了，我的方案还撑得住吗？"**

能回答这个问题，这道题才算真的会了。
