## PER-650：手写一个密钥泄漏应急轮换脚本：检测到 AK 泄漏后生成新密钥、灰度替换、旧密钥延迟吊销

**答**：
- 轮换 SOP 脚本化：检测泄漏 -> 生成新密钥并写入密钥管理服务 -> 灰度切换（新密钥先给一部分服务用）-> 确认无调用失败 -> 旧密钥进入宽限期（7 天只告警不拒绝）-> 正式吊销。
- 要点：宽限期的意义是未知的使用方"（没进清单的调用方）在宽限期内被发现而不是直接被打挂；轮换期间双密钥并行验签；吊销前最后确认访问日志里旧密钥调用量归零。
- 边界：脚本幂等（重复跑不产生新密钥对）；所有步骤留审计记录；泄漏来源若是仓库历史，还要清理 git 历史（filter-repo）并强制所有协作者重新克隆。
- 评分点：宽限期设计与幂等。

```javascript

async function rotateKey(keyId, { graceDays = 7 } = {}) {
  const state = await kms.get(keyId);                        // { active, pending, graceUntil }
  if (state.pending && !state.rotatedAt) {                   // 幂等：续跑而非新建
    await kms.activate(state.pending);
    await kms.setGrace(keyId, state.active, Date.now() + graceDays * 86400e3);
    await kms.markRotated(keyId);
    return { step: 'activated', note: '双密钥并行验签中' };
  }
  if (!state.pending) {
    const newKey = await kms.create(keyId);
    await kms.stage(keyId, newKey);                          // stage -> activate 两阶段
    return { step: 'staged', note: '新密钥已生成，等待灰度验证' };
  }
  const usage = await audit.oldKeyCalls(keyId, '7d');
  if (state.graceUntil < Date.now() && usage === 0) {
    await kms.revoke(state.graceKey);                        // 调用量归零才吊销
    return { step: 'revoked', note: '旧密钥已吊销' };
  }
  return { step: 'grace', note: `宽限期中，旧密钥 7 日调用量=${usage}，未归零不吊销` };
}
// 配套：git filter-repo 清历史 + 全员重新克隆 + CI 密钥扫描常开
```
