## PER-347：为什么 transform/opacity 动画不卡而 width 动画卡？合成器线程与主线程动画的本质区别？

**答**：
- 两条动画路径：主线程动画（JS/改 layout 属性）——每帧都要 JS/CSS 执行 + style/layout/paint，主线程忙时动画卡顿掉帧；合成器线程动画（CSS transform/opacity 的 CSS transition/animation 或 Web Animations）——**属性提升为合成层后由合成器线程独立驱动**，主线程阻塞（长任务）也不影响动画流畅，每帧只是 GPU 重拼图层。
- 适用范围：能走合成器线程的只有 transform（translate/scale/rotate）与 opacity，外加 CSS filter 部分情况。改 width/height/top/left 都触发 layout/paint——即使没有长任务也是每帧全量渲染管线，成本高一个量级。
- 触发条件细节：元素不能被"未提升的父层"拖累；动画开始瞬间可能有一帧掉帧（提升层发生在首帧）——可用 will-change 预提升或用 `element.animate()` 提前声明。
- JS 驱动的动画（rAF 里改 transform）仍在主线程——要流畅请用 CSS animation/Web Animations API（合成器路径），JS 只负责启动与参数。

```css
/* 卡：主线程 layout 动画 */
.drawer { transition: left .3s; }
.drawer.open { left: 0; }
/* 好：合成器线程动画（主线程忙也流畅） */
.drawer { transition: transform .3s; transform: translateX(-100%); }
.drawer.open { transform: translateX(0); }
```
```javascript
// Web Animations API：启动即走合成器路径，还能精确控制
el.animate([{ transform: 'translateX(-100%)' }, { transform: 'translateX(0)' }],
  { duration: 300, easing: 'ease-out', fill: 'forwards' });
// 主线程 rAF 动画（仅在需要逐帧计算时用，且注意 yield）：
function tick() { el.style.transform = `translateX(${calc(t)}px)`; requestAnimationFrame(tick); }
```
