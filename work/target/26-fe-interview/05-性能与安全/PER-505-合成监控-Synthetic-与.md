## PER-505：合成监控（Synthetic）与真实用户监控（RUM）有什么区别？二者如何配合组成完整体系？

**答**：
- 合成监控是**受控环境的主动测量**：固定设备、固定网络、定时跑，数据稳定可比，适合做回归门禁与上线前验证；RUM 是**真实环境的被动采集**：真实设备、真实网络、真实用户行为，反映用户实际体验的分布。
- 两者各有一个致命盲区：合成环境测不到长尾用户（老旧安卓、弱网、低端机房出口），RUM 受采样与上报成功率影响且难以逐字段复现。
- 配合模式：合成做"门禁与巡检"（每次发版前后跑基线），RUM 做"验收与告警"（上线后看 p75 是否达标、异常时触发告警），二者指标口径必须统一（同一套 Web Vitals 定义），否则会出现"合成全绿、RUM 报警"的口径打架。
- 追问钩子：为什么 Lighthouse 分数高但用户仍说慢？——因为 Lighthouse 是模拟单次冷加载，用户是热缓存、多 Tab、真实交互的混合体。

```javascript

// 二者的职责用一段配置表达清楚：口径统一，分工不同
const monitoring = {
  synthetic: {  // 主动、受控、可比：守门
    cron: '*/15 * * * *',       // 每 15 分钟巡检一次
    pages: ['/home', '/pay'],
    budget: { lcp: 2500 },      // 与 RUM 用同一口径
    role: '回归门禁 + 可用性巡检',
  },
  rum: {        // 被动、真实、长尾：验收
    sampleRate: 0.2,            // 会话级采样
    dimension: ['region', 'deviceClass', 'netType'], // 长尾下钻维度
    alert: { metric: 'LCP', agg: 'p75', over: 3000, window: '5m' },
    role: '线上验收 + 异常发现',
  },
};
// 经典组合拳：发版前 synthetic 卡口 -> 发版后 rum 观察 24h p75 -> 回归再由 synthetic 复现
```
