## PER-691：小程序分包加载的性能设计：主包预算、分包策略与预下载怎么排？

**答**：
- 主包预算：微信主包 < 2MB，主包只放启动必需（首页/公共资源/框架），其余业务全部分包——主包越小启动越快。
- 分包策略：按用户路径聚合（首页常去的下一跳放主包或 A 分包），避免跨包跳转频繁（跨包有加载等待）；公共依赖（组件库）放主包或用分包异步化（`componentPlaceholder`）。
- 预下载：`preloadRule` 按页面配置进入页面后静默预下载下一跳分包（WiFi/全网络分档配置），把点击后的下载提前到浏览时"——分包体验的核心手段。
- 独立分包：活动页等无登录态依赖的页面用独立分包（不依赖主包可独立启动，分享进入秒开）。

```javascript

// app.json 分包与预下载配置
const appJson = {
  pages: ['pages/home/index'],                                  // 主包只留启动必需
  subpackages: [
    { root: 'pkg-order', pages: ['list', 'detail'] },
    { root: 'pkg-activity', pages: ['landing'], independent: true },  // 独立分包：分享直达
  ],
  preloadRule: {
    'pages/home/index': { network: 'all', packages: ['pkg-order'] },   // 进首页预下载订单分包
    'pkg-order/list': { network: 'wifi', packages: ['pkg-activity'] }, // WiFi 才预下载活动包
  },
  lazyCodeLoading: 'requiredComponents',                        // 注入未用组件代码
};
// 原则：主包 < 2MB；跨包跳转用 preloadRule 提前；无依赖页面独立分包
```
