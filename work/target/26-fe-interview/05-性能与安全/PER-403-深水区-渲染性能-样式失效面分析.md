## PER-403：一次 className 变更为什么让 8000 个节点重算样式？样式失效面分析与收敛？

**答**：
- 失效面机理：样式计算不是"改哪个元素算哪个"——选择器匹配依赖文档结构，`.list .item.active` 的变更可能使整个 `.list` 子树失效重算；深层后代选择器让"祖先状态变化"波及全部子孙。Recalculate Style 的 Elements Affected 数量在 Performance 面板可见。
- 常见放大器：① 深后代选择器（`.app .page .section .list .item`）——失效沿祖先链全传播；② 全局状态挂 body（`body.dark .xxx`）——切主题全页重算（一次性可接受，频繁切换致命）；③ 通配与属性选择器（`[data-x]`）匹配成本高；④ CSS-in-JS 运行时插入样式表触发全文档重算。
- 收敛手段：扁平选择器（BEM 类名 + 最多 2 层）；主题切换用 CSS 变量（`--bg` 变量变更不触发选择器重匹配，只触发重绘）；状态类挂最近公共容器而不是 body；CSS-in-JS 用构建期静态提取或 CSSStyleSheet 共享。
- 验证方法：Performance 面板对比改动前后 Recalculate Style 耗时与 Affected 数；大型列表上做"改一个 class"的微基准（CI 可跑）。

```css
/* 反例：深后代 + body 状态 → 失效面 = 全文档 */
body.theme-dark .page .section .list .item { color: #eee; }
/* 修复一：扁平化（BEM 风格） */
.item--dark { color: #eee; }
/* 修复二：主题用 CSS 变量（不触发选择器重匹配） */
:root { --text: #222; }
:root[data-theme='dark'] { --text: #eee; }
.item { color: var(--text); }        /* 切主题只换变量值：重绘不重算匹配 */
```
