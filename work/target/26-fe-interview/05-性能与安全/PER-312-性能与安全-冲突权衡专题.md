## PER-312：性能与安全的经典冲突场景盘点：SRI/nonce/审计/加密各自的性能代价与取舍？

**答**：
- SRI：几乎零运行时开销（哈希校验微秒级），代价在"工程复杂度"（发布时序、字节一致）与"缓存不可变性要求"（文件名必须内容 hash）。性能友好，收益高——优先做。
- CSP nonce：与 HTML 缓存冲突（PER-306），要么 HTML 放弃长缓存（TTFB/LCP 变差）要么边缘改写（架构成本）。取舍：动态页用 nonce，静态高缓存页用 hash + strict-dynamic。
- 安全审计 SDK（RASP/行为采集）：监听全量事件、hook 关键 API（fetch/XHR/console），主线程开销 1~5%——必须采样与批量上报（PER-246 的 SDK 预算同款纪律），且审计 SDK 自身要性能评审。
- 加密与认证：TLS 1.3 已把握手压到 1-RTT（PER-048），WebCrypto 的对称加解密微秒级；真正贵的是"同步密钥派生"（PBKDF2 上万次迭代）——挪 Worker 或用 WebAuthn。字段级加密（前端加密存储）能用 IndexedDB 内建加密就别自己加密。
- 决策框架：先算"安全收益 × 攻击面"，再看"性能代价是否在预算内"；凡是能用构建期/服务端解决的（SRI/CSP 头）不占运行时，凡是必须运行时的（审计/加密）必须预算化与采样。

```text
冲突决策表（示例）：
措施            性能代价           取舍方案
SRI            ~0                 全量启用（内容 hash 文件名 + 发布探活）
CSP nonce      HTML 缓存失效       动态页 nonce / 静态页 hash+strict-dynamic
审计 SDK       CPU 1~5%           采样 10% + 批量上报 + 独立线程
CSP report     每违规一次 POST     Report-Only 期全量，强制期采样 1%
前端字段加密    PBKDF2 迭代贵      Worker 派生 + 缓存派生密钥（会话级）
```
