## PER-416：性能值班的 Runbook 设计：每个告警对应一套可执行动作？

**答**:
- Runbook 标准：一个告警规则对应一个 runbook 条目——触发条件回顾、5 分钟内判断动作（看哪个面板、跑哪个查询）、判定分支（真问题/误报/已知问题）、每分支的执行动作（回滚开关位置/降级命令/升级路径）、联系人与升级链。核心要求：**新人也能照着执行**（不依赖个人记忆）。
- 编写纪律：动作必须是"可复制粘贴的命令/链接"（不是"去检查一下 CDN"这种模糊描述）；每次真实值班后更新 runbook（发现的信息差补进去）；runbook 与告警规则同仓库版本管理。
- 演练：季度故障演练（Chaos 式注入性能故障），值班按 runbook 走全流程，记录"卡壳点"回填文档；runbook 的验证指标——MTTA 与平均处置时长趋势。
- 与自动化的边界：能自动化的判断（版本 diff、回滚评估）做成自动化，runbook 只保留人工决策点——runbook 越短越好。

```text
Runbook 条目模板（示例）：
告警：lcp-p75-mutation（LCP p75 环比 +20%）
判断（5min）：
  1. 打开看板链接 → 确认页面与切片
  2. 看版本 diff 链接 → 是否伴随发版？
分支 A 伴随发版且显著 → 执行回滚开关（链接）→ 拉owner
分支 B 无发版 → 查 CDN 命中率面板（链接）→ 命中率 < 80% 切备用源（命令）
分支 C 已知问题（见 issue 链接）→ 静默至修复，备注值班记录
升级链：owner(10min 无响应) → lead → 委员会
纪律：动作全部是可复制的命令/链接；每次值班后回填；季度演练验证卡壳点
```
