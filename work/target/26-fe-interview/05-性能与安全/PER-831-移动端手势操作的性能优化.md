## PER-831：移动端手势操作的性能优化：多手势并发、手势冲突与 passive 优化的实践边界

**答**：
- 并发手势场景：列表滚动 + item 侧滑、捏合缩放 + 双击、横竖向手势并存——冲突的本质是"谁消费这个手势"，需要仲裁（位移主方向判定、等待阈值、组件优先级声明）。
- 性能要点：手势回调逐帧执行，里面做 setState/布局读取会强制重排——统一改为 rAF 合帧 + transform 更新；监听一律 passive（除非需要 preventDefault 阻断滚动）。
- 仲裁模式：手势识别器带状态机（idle/possible/began/failed），possible 阶段只记录不响应，超过位移阈值或时间阈值才 began；后注册的手势默认让先（列表滚动优先于 item 手势）。
- 低端机边界：多指手势在低端机事件频率低，识别阈值要放宽（防误判为 tap）。

```javascript
class Gesture {
  constructor(el, { onMove, threshold = 10 }) {
    this.el = el; this.onMove = onMove; this.th = threshold;
    this.state = 'idle'; this.claim = null;   // 仲裁所有权
    el.addEventListener('touchstart', this.start.bind(this), { passive: true });
    el.addEventListener('touchmove', this.move.bind(this), { passive: true });
    el.addEventListener('touchend', () => { this.state = 'idle'; this.claim = null; }, { passive: true });
  }
  start(e) { this.sx = e.touches[0].clientX; this.sy = e.touches[0].clientY; this.state = 'possible'; }
  move(e) {
    if (this.state === 'idle') return;
    const dx = e.touches[0].clientX - this.sx, dy = e.touches[0].clientY - this.sy;
    if (this.state === 'possible') {          // 位移主方向仲裁
      if (Math.hypot(dx, dy) < this.th) return;
      this.claim = Math.abs(dx) > Math.abs(dy) ? 'h' : 'v';
      this.state = 'began';
    }
    if (this.claim === 'h') requestAnimationFrame(() => this.onMove(dx));   // rAF 合帧
  }
}
```
