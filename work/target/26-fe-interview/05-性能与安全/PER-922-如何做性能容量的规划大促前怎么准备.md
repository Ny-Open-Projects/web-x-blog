## PER-922：如何做性能容量的规划？大促前怎么准备

**答**：
- 容量模型：估算大促峰值 QPS 下前端各环节承载——CDN 带宽预算、页面并发渲染复杂度、API 依赖的 P99（影响加载链路）。
- 前端容量三件事：静态资源预热（提前推送 CDN）、降级预案演练（关动效/关非核心模块/切静态兜底页）、压测关键页面（用 headless 批量模拟）。
- 清单化：输出大促性能 checklist（资源预热/降级开关/告警阈值调整/值班表），上线前逐项确认。
- 事后复盘：峰值期间的指标数据回放，校准容量模型供下次迭代。

```javascript
// 大促压测编排：批量模拟关键路径
async function stress(routes, { runs = 50, conc = 10 } = {}) {
  const results = [];
  for (let i = 0; i < runs; i += conc) {
    const batch = routes.flatMap(r =>
      Array.from({ length: conc }, () => runLabTest(r)));   // headless 执行
    results.push(...(await Promise.all(batch)));
  }
  const t = results.map(r => r.lcp).sort((a, b) => a - b);
  return { p50: t[t.length >> 1], p99: t[Math.floor(t.length * 0.99)] };
}
// p99 超阈值 -> 触发降级预案演练而非临时救火
```
