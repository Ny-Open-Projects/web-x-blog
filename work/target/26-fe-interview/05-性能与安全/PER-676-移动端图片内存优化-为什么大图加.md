## PER-676：移动端图片内存优化：为什么大图加载会 OOM？降采样、内存缓存与解码时机怎么管？

**答**：
- OOM 机制：一张 4000×3000 的图解码后位图内存 = 4000×3000×4 字节 ≈ 45MB（RGBA8888），列表里几十张直接爆内存；且 iOS 的UIImage 解码是同步的，解码瞬间打满内存与 CPU。
- 优化四层：**降采样**（按显示尺寸×DPR 解码，`decodePixelWidth`/`inSampleSize`）、**格式**（WebP/HEIC 减小体积；`RGB_565` 无透明场景省一半内存）、**缓存策略**（内存缓存按当前屏幕 + 相邻裁剪，磁盘缓存全量）、**解码时机**（离屏解码延迟到可视前 1 屏，回收离屏 3 屏以上的位图）。
- Web 端对应：`<img decoding="async">`、`createImageBitmap(blob, { resizeWidth })` 手动降采样、列表用 IntersectionObserver 控制加载与回收（src 置空释放位图）。
- 度量：列表滚动时的内存曲线（稳定不爬升）与大图页的峰值内存。

```javascript

// Web 移动端图片降采样加载器：按显示尺寸解码，滚动离屏回收
async function loadImageSmart(img) {
  const rect = img.getBoundingClientRect();
  const targetW = Math.ceil(rect.width * devicePixelRatio);    // 显示尺寸×DPR
  const blob = await fetch(img.dataset.src).then(r => r.blob());
  const bitmap = await createImageBitmap(blob, {
    resizeWidth: Math.min(targetW, 1080), resizeQuality: 'medium',  // 降采样解码
  });
  const canvas = new OffscreenCanvas(bitmap.width, bitmap.height);
  canvas.getContext('2d').drawImage(bitmap, 0, 0);
  img.src = canvas.convertToBlob ? URL.createObjectURL(await canvas.convertToBlob()) : img.dataset.src;
  bitmap.close();                                              // 释放位图内存
}
function recycleOffscreen(list) {
  const io = new IntersectionObserver(entries => {
    entries.forEach(e => {
      if (!e.isIntersecting && Math.abs(e.boundingClientRect.top) > innerHeight * 3) {
        e.target.src = PLACEHOLDER;                            // 离屏 3 屏回收位图
        e.target.dataset.src = e.target.dataset.origSrc;
      }
    });
  }, { rootMargin: '200% 0px' });
  list.forEach(img => io.observe(img));
}
```
