## PER-579：监控数据的保留与成本策略：全量留存为什么不可行？分层保留怎么设计？

**答**：
- 成本结构：明细数据（每条错误/每个样本）量大但查询频率低；聚合数据（分钟级分位数）量小但查询频率高——两者分开存储，明细滚动窗口短、聚合保留长。
- 分层保留参考：原始明细 7 天 -> 降采样明细 30 天 -> 小时级聚合 13 个月（支持同比）-> 日级聚合永久（年报）；每层存储介质不同（热/温/冷）。
- 成本杠杆：上报端压缩与字段短名（省 60% 存储）、按业务重要性分优先级（核心业务多保留、边缘页少留）、TTL 自动清理而非人工清理。
- 保留策略要有数据价值依据：排障需要最近 7 天明细；复盘需要季度聚合；更老的只有趋势价值——按用途定保留，不为万一用到买单。

```javascript

const retentionPolicy = {
  tiers: [
    { kind: 'raw-detail', ttl: '7d',  store: 'hot',  use: '实时排障' },
    { kind: 'detail-ds',  ttl: '30d', store: 'warm', use: '周/月复盘，降采样10%' },
    { kind: 'hourly-agg', ttl: '13mo', store: 'cold', use: '同比分析' },
    { kind: 'daily-agg',  ttl: 'forever', store: 'archive', use: '年度趋势' },
  ],
  levers: ['上报 gzip+短名(-60%)', '核心/边缘业务分级保留', 'TTL 自动清理'],
  rule: '按数据用途定保留期，不为万一用到买单',
};
console.log(retentionPolicy.rule);
```
