## PER-1227：如何设计"性能故障"的事后复盘模板（不同于可用性故障）

**答**：
- 差异：性能劣化无明确"故障时刻"，是渐变——复盘重点是"为什么检测晚了"与"为什么没被门禁拦住"。
- 模板：劣化时间线（何时引入/何时发现/何时修复）、检测缺口（指标盲区/告警阈值）、门禁缺口（哪条规则缺失）、改进项（规则/阈值/流程）。
- 归档：复盘产出转 RUNBOOK 条目与 lint 规则，形成闭环。
- 度量：同因复发次数为 0 是复盘有效的唯一标准。

```javascript
// 性能复盘模板
function perfPostmortem(ev) {
  return {
    timeline: { introduced: ev.introduced, detected: ev.detected, fixed: ev.fixed,
      detectionLag: days(ev.introduced, ev.detected) },
    detectionGap: ev.detectedVia === 'user-complaint'
      ? '用户先行——告警缺口' : '系统发现',
    gateGap: ev.gateMissing ? `缺失规则: ${ev.gateMissing}` : null,
    actions: ev.actions.map(a => ({ ...a, owner: a.owner, due: a.due })),
    successCriteria: '同因复发 = 0',
  };
}
function days(a, b) { return Math.round((b - a) / 86400_000); }
```
