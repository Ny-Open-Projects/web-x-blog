## PER-881：移动端首屏图片的优先级编排：LCP 图与懒加载图的优先级冲突与解决

**答**：
- 冲突场景：懒加载库统一给图片 loading=lazy，导致 LCP 首图（位于首屏）也被延迟；或预加载轮播全部图片抢占带宽，LCP 图反而变慢。
- 原则：首屏 LCP 图 fetchpriority=high + preload，明确排除出懒加载；首屏外的图懒加载 + 低优先级；轮播只预加载当前帧与下一帧。
- 手段组合：`<link rel=preload as=image fetchpriority=high>`（HTML 头）+ img 属性 fetchpriority=eager/lazy + 懒加载 rootMargin 提前量（200~400px）。
- 度量验证：LCP 元素标记（埋点确认哪张图是 LCP），对比编排前后 LCP 与首屏总流量——目标 LCP 缩短且总流量不涨。

```javascript
// 首屏优先级编排
const plan = {
  lcp: `<link rel="preload" as="image" href="hero.avif" fetchpriority="high">
        <img src="hero.avif" fetchpriority="high" loading="eager">`,   // LCP 图
  below: '<img loading="lazy" decoding="async">',                      // 首屏外
  carousel: '只预加载 index 0 与 1，切换时预取下一帧',
};
function orchestrate(images, lcpSrc) {
  return images.map(img => {
    if (img.src === lcpSrc) return { ...img, fetchpriority: 'high', loading: 'eager' };
    return { ...img, fetchpriority: 'low', loading: 'lazy' };
  });
}
// 验证：LCP 埋点确认元素
new PerformanceObserver(list => {
  for (const e of list.getEntries())
    report('lcp-element', { src: e.element?.src, ms: +e.startTime.toFixed(0) });
}).observe({ type: 'largest-contentful-paint', buffered: true });
```
