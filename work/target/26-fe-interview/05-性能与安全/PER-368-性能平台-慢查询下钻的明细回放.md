## PER-368：看板发现慢样本后如何"回放"现场？会话回放与明细数据的成本平衡？

**答**：
- 回放三层（成本递增）：① 结构化明细回放——慢样本的资源瀑布（Resource Timing 全量）、交互三段、LoAF 脚本榜，JSON 结构化展示（成本低，覆盖所有慢样本）；② 事件流回放——该会话的用户操作序列（click/scroll/input 时间线）+ DOM 快照 diff（中等成本，抽样 10%）；③ 视频级回放（rrweb 录制）——完整 DOM 变化流（成本最高，只对超阈值慢样本采样 1~5%，且压缩存储）。
- 采样策略：回放录制由 SDK 配置下发（采样率/触发条件——只录"INP > 300ms 或 CLS > 0.15 的会话"的条件触发采样，比全量采样信息密度高 10 倍）。
- 成本控制：rrweb 数据压缩（DOM 快照增量 + 事件去重 + gzip）、保留期 7 天、大小上限（单会话 5MB 截断）、隐私脱敏（录制时掩码输入框内容——PII 不进回放）。
- 使用闭环：看板慢样本点"查看现场"→ 明细瀑布 +（如有）会话回放，直接看到"用户在哪个操作后卡了、哪个资源拖了后腿"。

```javascript
// 条件触发的回放录制（rrweb 示意）
let recorder = null;
new PerformanceObserver((l) => {
  for (const e of l.getEntries()) {
    if (e.interactionId && e.duration > 300 && !recorder) {
      // 慢交互触发：才开始录制（捕获问题前后现场，而不是全程录制）
      recorder = startRRWeb({ maskAllInputs: true, maxSize: 5 * 1024 * 1024 });   // PII 脱敏 + 大小上限
      setTimeout(() => { const events = recorder.stop(); recorder = null; upload(events); }, 30000);
    }
  }
}).observe({ type: 'event', durationThreshold: 300, buffered: false });
// 成本对比：全程录制 100% 会话 = 存储成本爆炸；条件触发 1~5% 采样 = 信息密度最高
```
