## PER-574：指标异动后如何快速定位是不是发版引起的？发布时间线与监控数据怎么对齐？

**答**：
- 核心是把版本-时间轴叠加到指标时间轴上：每次发版记录（版本、开始/结束时间、灰度比例、范围）入发布事件库，异动告警自动拉取异动窗口内的发布事件并标注在图上。
- 判断规则：异动开始时间落在发版窗口 ±15 分钟内且与灰度比例爬升曲线同步 -> 高嫌疑；再验证对照组（未灰度人群）无变化即可定案。
- 反向操作：一键回滚联动——告警确认与发版强相关时，告警卡片直接给回滚按钮（有权限控制），把 MTTR 压到分钟级。
- 注意区分发版引起与发版暴露"：新版本流量放大了既有慢接口（非代码原因），归因要结合接口维度下钻再下结论。

```javascript

function correlate(anomaly, releases, metrics) {
  const WINDOW = 15 * 60 * 1000;
  const hits = releases.filter(r =>
    anomaly.startAt >= r.startAt - WINDOW && anomaly.startAt <= r.endAt + WINDOW);
  if (!hits.length) return { suspect: 'release: no', next: '查配置变更/依赖升级/运营活动' };
  const r = hits[0];
  const grayCurve = metrics.grayShare.map(m => ({ ts: m.ts, share: m.share }))
    .filter(m => m.ts >= anomaly.startAt - 5 * 60000);
  const synced = grayCurve.some(m => m.share > 0.05);      // 灰度比例在爬升
  const ctrlClean = metrics.controlGroupDelta < 0.05;      // 对照组无变化
  return { suspect: synced && ctrlClean ? 'release: yes' : 'release: maybe',
    version: r.version, action: synced && ctrlClean ? '提供一键回滚入口' : '继续下钻接口维度' };
}
```
