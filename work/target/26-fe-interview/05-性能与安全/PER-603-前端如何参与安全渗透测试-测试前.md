## PER-603：前端如何参与安全渗透测试？测试前要准备哪些配合项、如何高效接洞？

**答**：
- 渗透前的配合清单：**测试账号**（高/低权限各一套 + 测试数据隔离）、**测试范围声明**（哪些域名可测、哪些接口禁测——支付/第三方不可乱打）、**环境与窗口**（预发环境 + 流量低峰）、**应急联系人**（测出高危立即通知）、**WAF 临时策略**（防测试 IP 被封导致测试不完整）。
- 前端要主动提供的攻击面地图"：所有入口点清单（URL 参数、postMessage、iframe、上传、导出、SSO 回调、WebHook），渗透方按图索骥效率高很多，也避免遗漏隐蔽入口。
- 接洞流程：漏洞报告 -> 前端评估前端可否独立修复"（DOM-XSS 可，服务端注入不可）-> 修复 -> 复测验证 -> 归档防复发（同类点全量排查，不是只修被报的那一个点）。
- 追问钩子：渗透报告说存在 XSS 但没给触发路径怎么办？——让渗透方补 PoC，无法触发的 XSS 按低危处理，避免为理论漏洞过度投入。

```javascript

const pentestPrep = {
  accounts: { high: 'test-high/隔离数据', low: 'test-low/隔离数据' },
  scope: { allowed: ['*.test.example.com'], forbidden: ['/api/pay/**', '第三方回调'] },
  window: { env: '预发', time: '周二~周四 10:00-18:00' },
  attackSurface: [   // 前端主动输出的攻击面地图
    'URL query/params 渲染点 x14', 'postMessage 监听 x3', 'iframe 嵌入 x2',
    '上传入口 x1', '导出下载 x2', 'SSO 回调 x1', 'WebHook 配置页 x1',
  ],
  contact: '安全值班 + 前端 oncall',
};
// 接洞原则：修一个点 -> 全量 grep 同类 sink 排查 -> 回归用例固化
```
