## PER-398：INP 数据的分布解读：p75 达标但 p98 灾难时怎么办？双分位治理策略？

**答**：
- 分布解读：p75 达标（200ms）+ p98 灾难（900ms）意味着"大多数交互还行，但 2% 的交互是灾难"——这 2% 通常是特定场景（大数据量表格操作/特定低端机/特定三方触发）。CWV 验收看 p75，但 p98 是"最差体验修复清单"的来源。
- 双分位治理：p75 达标后不停止——把 p98 交互抽样分析（Event Timing 样本 + LoAF），定位"灾难交互"的共性（同一页面？同一交互类型？同一设备档位？）。常见发现：大数据导出按钮（同步 3s 计算）、低端机上的地图组件、某个低频但重的管理操作。
- 修复策略按共性选：灾难集中在特定操作 → 该操作切片/Worker 化；集中在低端设备 → 设备分级降级（PER-373 映射）；分布均匀的长尾 → 整体切片与渲染优化。
- 看板设计：INP 双分位视图（p75 主线 + p98 辅线），p98 超 500ms 的页面进"最差体验清单"，与达标率并列展示——防止"均值幻觉"。

```text
INP 双分位治理流：
p75 = 180ms（达标）但 p98 = 920ms
→ 抽样 p98 交互样本（Event Timing + LoAF）
→ 共性聚类：73% 来自"导出报表"按钮（同步聚合 3 万行）
→ 修复：导出改异步任务 + Worker 聚合 + 进度提示
→ 复测：p98 920ms → 380ms；p75 不回退
看板：p75 主线 + p98 辅线并列；p98 > 500ms 页面进"最差体验清单"
```
