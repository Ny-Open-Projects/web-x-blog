## PER-477：性能问题的知识图谱：症状-根因-修复的图结构检索？

**答**:
- 从文档到图：案例库（PER-340）是文档集合，检索靠全文——弱在"关联推理"（这个症状常见三个根因、其中两个的修复互斥）。知识图谱把三元组（症状-根因、根因-修复、修复-前置条件）结构化，支持多跳查询。
- 图结构设计：节点 = {症状, 根因, 修复方案, 工具, 前置条件}；边 = {症状-可能因(权重), 根因-修复(收益), 修复-需要前置(依赖), 修复-与X互斥}；每条边带来源案例引用（可回溯到完整案例）。
- 检索场景：输入"INP 高 + 大列表页" → 图查询返回候选根因按权重排序 → 每个根因的修复方案与其互斥项 → 工程师带着"已知陷阱"去修。构建来源：案例库抽取（LLM 辅助三元组抽取 + 人工评审）+ 归因数据自动补充（PER-390 诊断包的统计）。
- 维护成本控制：图谱是辅助不是权威（文档仍是权威），季度修剪（过时边清理）；边的权重由"历史命中"自动更新——用得越多越准。

```text
性能问题知识图谱：
节点：症状 / 根因 / 修复 / 工具 / 前置条件
边：症状→根因(权重) / 根因→修复(收益) / 修复→前置(依赖) / 修复↔互斥
检索："INP高+大列表" → 根因候选排序 → 修复方案 + 互斥警告
构建：案例库三元组抽取（LLM+人工评审）+ 归因统计自动补权
治理：文档是权威、图谱是辅助；季度修剪；权重随历史命中自更新
```
