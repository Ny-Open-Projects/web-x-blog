## PER-263：前端内存泄漏有哪些常见来源？各自的定位手段是什么？

**答**：
- 高频来源：① 未解绑的全局监听器（window/document 的 listener 随组件销毁残留）；② 被闭包引用的大对象（回调持有列表数据引用）；③ 定时器未清理（setInterval 引用 DOM/数据）；④ 全局缓存无上限（Map/数组当缓存只进不出）；⑤ 已卸载 DOM 的引用（ detached node）；⑥ 遗留的 WeakMap 误用成 Map。
- 定位三板斧：① 性能面板 Memory 齿轮录制堆快照对比（Allocation instrumentation 找持续增长的分配点）；② Heap snapshot 三快照法（操作前/操作 N 次/操作后，对比增长对象与 Retainers 链）；③ detached DOM 检查（快照过滤 Detached 关键字）。
- 判定标准：反复操作同一流程，内存台阶式上涨且不回落 → 泄漏；涨后 GC 回落到基准 → 只是分配压力，不是泄漏。
- 预防：组件卸载统一走 cleanup（框架的 useEffect return / onUnmounted）；全局缓存一律带 TTL 或容量上限；监听器用 AbortController 统一解绑。

```javascript
// 统一清理样板：一个 AbortController 管所有监听器，一次 abort 全解绑
class Widget {
  #ac = new AbortController();
  mount(el) {
    el.addEventListener('scroll', this.onScroll, { signal: this.#ac.signal, passive: true });
    el.addEventListener('resize', this.onResize, { signal: this.#ac.signal });
    this.timer = setInterval(this.poll, 5000);
  }
  unmount() {                              // 一次调用清干净
    this.#ac.abort();                      // 所有带 signal 的 listener 一起解绑
    clearInterval(this.timer);
  }
  onScroll = () => {}; onResize = () => {}; poll = () => {};
}
```
