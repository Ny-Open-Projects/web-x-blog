## PER-551：用户说我这里很慢但测试复现不了，性能测试体系如何建设复现能力？

**答**：
- 复现困难的根因是"环境维度组合爆炸"：设备 × 网络 × 数据 × 账号态 × 时间段，测试只覆盖了典型组合；解决思路是**从用户侧采集环境现场**而不是盲猜。
- 现场采集三件套：用户会话回放（rrweb，带脱敏）、该会话的性能指标与资源瀑布（RUM SDK 已有）、环境指纹（UA/内存档/网络类型/时区/AB 分支）。
- 复现剧本化：拿到现场后在测试环境按"同设备档位 + 同网络档位 + 同数据快照 + 同实验分支"重建，仍不能复现的（如地域性 DNS 污染）保留为"环境类不可复现"并归类到相应团队。
- 体系建设方向：慢会话自动聚类（把 p95 之外的慢样本按特征聚类），每次聚类结果生成一个"复现剧本"沉淀进测试套件——复现能力是积累出来的。

```javascript

// 慢会话现场快照：一个 payload 重建整个复现场景
function slowSessionSnapshot() {
  return {
    env: {
      ua: navigator.userAgent, dpr: devicePixelRatio,
      deviceMemory: navigator.deviceMemory ?? null,
      net: navigator.connection?.effectiveType,
      ab: window.__abBranch,                             // 实验分支
    },
    vitals: window.__vitals,                             // RUM 已采的指标
    waterfall: performance.getEntriesByType('resource')
      .slice(-50).map(e => ({ url: e.name, dur: Math.round(e.duration) })),
    replayId: window.__rrwebSessionId,                   // 会话回放引用（脱敏）
  };
}
// 上报后入库按特征聚类 -> 每类生成自动化复现剧本进 perf 套件
```
