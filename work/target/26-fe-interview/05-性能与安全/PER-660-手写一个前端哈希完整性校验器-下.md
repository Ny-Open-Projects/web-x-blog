## PER-660：手写一个前端哈希完整性校验器：下载资源后用 SM3/SHA-256 双算法校验并支持流式大文件

**答**：
- 大文件校验不能一次读进内存：`file.slice` 分块 + `crypto.subtle.digest` 不支持流式（需全量），改用 `digest` 逐块不可行——流式 SHA 用 JS 实现增量哈希（或 WASM），SM3 同理用库的增量接口。
- 要点：分块顺序更新状态、最后 finalize；双算法并行（Promise.all）；校验失败阻塞使用（fail-closed）并告警。
- 边界：分块大小对齐（如 4MB）；进度回调；对照值（expected hash）来自可信通道（签名清单）而不是同一下载源——同源自带 hash 没意义。
- 评分点：增量哈希与可信对照源。

```javascript

import { SM3 } from 'sm-crypto-hash';                            // 支持增量更新
async function verifyBigFile(file, expectedSha256, expectedSm3, { chunk = 4 * 1024 * 1024, onProgress } = {}) {
  // SHA-256：WebCrypto 不支持增量 -> 分块后用 JS 增量实现（这里用 keccak 系占位说明结构）
  const sha = await incrementalSha256();
  const sm3 = new SM3();
  let offset = 0;
  while (offset < file.size) {
    const buf = await file.slice(offset, offset + chunk).arrayBuffer();
    sha.update(new Uint8Array(buf));                             // 增量喂入
    sm3.update(new Uint8Array(buf));
    offset += chunk;
    onProgress?.(offset / file.size);
  }
  const shaHex = sha.finalizeHex(), sm3Hex = sm3.finalizeHex();
  const ok = shaHex === expectedSha256 && sm3Hex === expectedSm3;
  if (!ok) report('hash-mismatch', { name: file.name });         // fail-closed
  return { ok, shaHex: shaHex.slice(0, 16) + '...', sm3Hex: sm3Hex.slice(0, 16) + '...' };
}
// expected 值必须来自带签名的清单文件，与资源不同源，否则校验形同虚设
```
