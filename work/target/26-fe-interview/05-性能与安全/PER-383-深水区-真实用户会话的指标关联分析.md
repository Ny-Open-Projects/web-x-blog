## PER-383：单个用户会话的指标串（多页面 LCP/INP 序列）能分析出什么？会话级性能画像？

**答**：
- 会话画像定义：同一匿名会话（sid）内按时间序列串联的指标——/home LCP 1.9s → /list LCP 3.4s → /goods LCP 2.2s → /pay INP 480ms → 转化成功/流失。比单页指标多出"路径"维度。
- 三类分析价值：① 路径级瓶颈——某条转化路径整体慢（列表→详情→下单的 LCP 序列都 >3s），修复价值高于单页优化（转化漏斗上连续慢的路径流失叠加）；② 劣化转折点——会话中第 N 页开始指标陡增（内存泄漏/长会话漂移的现场证据，PER-356）；③ 跨页归因——下单页 INP 慢可能与前序页面塞进全局状态的大对象有关（会话串才看得见）。
- 隐私边界：sid 是随机会话标识（非用户 ID），会话内数据保留 14 天后聚合删除；画像粒度到"会话"为止，不跨会话拼用户。
- 落地：RUM 上报带 sid（PER-251），聚合层按 sid 分组产出会话视图；看板提供"Top 流失路径"（性能差的转化路径排行）直接对接业务价值。

```text
会话画像视图（示例）：
sid=a3f9 · 新用户 · 手机 · Chrome
  t+0s   /home        LCP 1.9s  CLS 0.02
  t+18s  /list        LCP 3.4s  ← 路径瓶颈
  t+41s  /goods/88    LCP 2.2s
  t+63s  /pay         INP 480ms ← 交互瓶颈（LoAF: vendor-sdk.js 310ms）
  t+71s  流出（未下单）
分析结论：/list 数据链路 + /pay 三方脚本 → 该路径转化损失估计 X%
隐私：sid 随机会话标识，14 天 TTL，不跨会话拼用户
```
