## PER-899：移动端性能与安全的交叉点：性能优化手段可能引入的安全风险清单

**答**：
- 性能手段的安全暗面（要成对审视）：离线包/拦截 → 恶意包替换（需签名校验）；HTTPDNS/IP 直连 → 证书校验绕过风险（必须保留 SNI/Host 校验）；预取 → 敏感数据提前拉取（登录态下预取他人可见数据=越权风险）；缓存（SW/本地）→ 敏感信息落盘（加密/退出清理）。
- 压缩与拆包 → 边界混淆：拆分接口时鉴权字段遗漏（聚合时在网关校验，拆开后子接口忘了）。
- 灰度与配置下发 → 配置注入：配置值未校验直接进 dangerouslySetInnerHTML/URL → XSS；下发通道要签名+白名单值域。
- 治理机制：性能方案评审带安全 checklist（每类手段固定问题清单）；安全扫描纳入性能 CI（预取接口鉴权自动化检测）。

```javascript
const perfSecurityChecklist = {
  'offline-bundle': ['签名校验', '版本黑名单通道', '包内文件路径穿越检查'],
  'httpdns': ['SNI/Host 校验保留', '兜底 IP 列表来源可信'],
  'prefetch': ['预取接口鉴权一致', '不预取他人数据', 'TTL 防旧数据越权展示'],
  'cache': ['敏感字段不落盘', '登出清理', '缓存加密选项'],
  'config-push': ['签名验证', '值域白名单', '禁止未校验进 innerHTML'],
};
function auditPerfFeature(feature) {
  const checks = perfSecurityChecklist[feature] || [];
  return checks.map(c => ({ check: c, status: 'manual-review-required' }));
}
// 预取越权自动检测示例：预取请求不带本人凭证时服务端应拒绝
async function assertPrefetchAuth(prefetchUrl) {
  const r = await fetch(prefetchUrl, { headers: { Authorization: 'invalid' } });
  report('prefetch-auth-check', { url: prefetchUrl, rejected: r.status === 401 });
  return r.status === 401;                                     // 应被拒绝才是正确行为
}
```

**追问**：

1. 离线包签名校验，公钥放客户端里被替换怎么办？ → 公钥要内置在原生包或系统信任链，不能放在可被覆盖的 H5 资源里。
2. HTTPDNS IP 直连保留 SNI/Host 校验，但证书按 IP 签发时怎么办？ → 仍按域名校验证书，IP 只做连接目标，证书 CN/SAN 必须匹配域名。
3. 预取「不预取他人数据」怎么自动化测？ → 用无效或他人凭证请求预取接口，断言返回 401/403，并纳入 CI。
