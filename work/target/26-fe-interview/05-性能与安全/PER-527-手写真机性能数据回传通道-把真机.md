## PER-527：手写真机性能数据回传通道：把真机上的 FPS/内存/指标数据可靠回传并落库到测试报告

**答**：
- 真机调试的痛点是数据出不来：方案是页面内埋探针 + 定期 sendBeacon 批量回传，测试同学扫码打开测试页，数据实时进看板。
- 要点：批量聚合（每 10 秒一包）减少上报本身对性能的干扰；带设备指纹（UA、deviceMemory、屏幕 DTR）以便分档分析；对 `performance.memory` 缺失的 iOS 做降级（只报 FPS 与指标）。
- 边界：上报通道自身要用 requestIdleCallback 或节流，避免采集工具反而制造卡顿；页面关闭前 flush 残留数据。
- 评分点：批量聚合、能力降级、卸载前 flush 三处。

```javascript

class DevicePerfReporter {
  constructor(endpoint) {
    this.endpoint = endpoint; this.buf = []; this.meta = {
      ua: navigator.userAgent.slice(0, 80),
      dpr: devicePixelRatio, memGB: navigator.deviceMemory ?? null,
    };
    let last = performance.now();
    const loop = (t) => {
      const gap = t - last; last = t;
      if (gap > 50) this.buf.push({ t: Math.round(t), drop: Math.round(gap) }); // 掉帧样本
      requestAnimationFrame(loop);
    };
    requestAnimationFrame(loop);
    setInterval(() => this.flush(), 10000);                        // 每 10s 批量上报
    addEventListener('pagehide', () => this.flush());              // 卸载前 flush
  }
  flush() {
    if (!this.buf.length) return;
    const payload = JSON.stringify({ meta: this.meta, drops: this.buf.splice(0) });
    navigator.sendBeacon(this.endpoint, payload);                  // 不可靠场景的兜底通道
  }
}
// new DevicePerfReporter('https://test-lab.internal/api/perf/device');
// 服务端按 meta 分档聚合，输出"真机掉帧热力表"进测试报告
```
