## PER-871：移动端深链与唤端场景的性能：scheme、universal link 唤端耗时与失败兜底

**答**：
- 唤端链路：页面触发 → scheme/universal link → 系统判定 → App 冷启/热启 → 落地页路由；各段都有损耗，总耗时常 1~3s（冷启）。
- 方案对比：URL Scheme 兼容全但微信内被拦；Universal Link/App Link 体验好（无确认弹窗）但配置成本高；建议双通道：UL 优先 + scheme 兜底。
- 失败兜底：未安装时 scheme 无响应——定时器检测可见性（timeout 后引导下载页/降级 H5 版）；可见性变化（visibilitychange hidden）视为唤端成功，取消兜底。
- 度量：唤端成功率、唤端耗时（点击→App 可用）、兜底页转化；失败要区分"未安装"与"被拦"（UA 判定）。

```javascript
function deepLink({ ul, scheme, fallbackUrl, timeout = 2000 }) {
  const t0 = performance.now();
  let launched = false;
  document.addEventListener('visibilitychange', () => {
    if (document.hidden) launched = true;                      // 跳走即视为唤起
    else report('deeplink', { ok: launched, ms: +(performance.now() - t0).toFixed(0) });
  });
  const inWX = /MicroMessenger/i.test(navigator.userAgent);
  const go = () => {
    if (!inWX) location.href = ul;                             // UL 优先
    location.href = scheme;                                    // scheme 兜底/微信内
    setTimeout(() => {                                         // 未唤起兜底
      if (!launched && !document.hidden) location.href = fallbackUrl;
    }, timeout);
  };
  document.getElementById('open-app').addEventListener('click', go);
}
```
