## PER-232：手写"业务首屏可交互时间"采集（mark + 主线程空闲 + 双条件取大 + 上报去重）

**题目**：实现 `trackBizFMP(report)`：① 业务方在首屏渲染完成后调用 `bizReady()` 打 mark；② 采集器等待"主线程安静期"（连续 600ms 无 longtask，最长等 10s）；③ 上报值为 max(mark 时间, 安静期开始时间)，标注是否超时；④ 全程只上报一次；⑤ 若 mark 迟迟未打（10s 超时仍未打），按超时路径上报并附原因。

**答**：双条件设计防止两个假象——只有 mark 会把"画完但点不动"误判为快，只有 idle 会把"白屏空转"误判为快；取大者才是用户真实可用时刻。

```javascript
function trackBizFMP(report, { quietMs = 600, maxWait = 10000 } = {}) {
  let markTime = null, reported = false, t0 = performance.now();

  window.bizReady = () => { markTime = performance.now(); };   // 业务打点入口

  function tryReport(reason) {
    if (reported) return;
    reported = true;
    const idleFrom = markTime ? Math.max(markTime, t0) : null;
    report({
      type: 'BizFMP',
      value: Math.round(idleFrom ?? (performance.now() - t0)),
      hasMark: markTime != null,
      reason,                                   // 'ok' | 'timeout-no-mark' | 'force'
    });
  }

  // 主线程安静期检测
  const io = new PerformanceObserver(() => { /* 长任务出现即重置安静计时 */ resetQuiet(); });
  io.observe({ type: 'longtask' });

  let quietStart = performance.now(), lastTaskAt = performance.now();
  function resetQuiet() { lastTaskAt = performance.now(); }
  (function poll() {
    if (reported) return io.disconnect();
    if (performance.now() - t0 >= maxWait) {           // 整体超时
      tryReport(markTime == null ? 'timeout-no-mark' : 'force');
      return io.disconnect();
    }
    if (markTime != null && performance.now() - lastTaskAt >= quietMs) {
      tryReport('ok'); return io.disconnect();
    }
    setTimeout(poll, 100);
  })();
}
// 首屏组件挂载后：window.bizReady()  —— mark 与空闲双条件齐备才上报
```

**评分点**：
- 双条件（mark + 主线程安静期）取大者，明确说出为什么单一条件会失真。
- 安静期检测正确：longtask 重置计时，连续 quietMs 无任务才算可交互。
- 全程只上报一次（reported 去重），超时路径完整（含无 mark 的 reason 区分）。
- observer 在结束时 disconnect，无泄漏。
