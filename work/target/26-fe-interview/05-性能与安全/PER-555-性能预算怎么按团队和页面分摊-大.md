## PER-555：性能预算怎么按团队和页面分摊？大平台几十个业务线共用一个站点时预算如何管理？

**答**：
- 分摊原则：**总量预算按流量占比切分**——首页 40% 流量拿 40% 的 JS 预算；每个业务线领到"页面预算"，页面内再按模块拆（路由级 chunk 预算）。
- 管理机制：预算文件进仓库按目录归属（`/pay/**` 的 chunk 算支付团队），CI 按归属 @ 责任人；预算调整要走评审（流量占比变化/合理需求），防止悄悄膨胀。
- 冲突处理：共享依赖（公共组件/工具库）是公摊面积，单独设公共包预算并指定 owner，任何一方塞大依赖进公共包要评审。
- 治理节奏：预算只紧不松为主（每季度收紧 5%），确需放宽的要拿"业务收益"换（新功能带来的转化收益 > 性能损失估值）。

```javascript

const budgetAllocation = {
  total: { jsGzipKB: 1000 },
  byTeam: {   // 按流量占比切分
    home:  { share: 0.4, jsKB: 400, owner: 'home-team' },
    pay:   { share: 0.3, jsKB: 300, owner: 'pay-team' },
    order: { share: 0.3, jsKB: 300, owner: 'order-team' },
  },
  shared: { jsKB: 120, owner: 'infra-team', rule: '公共包加依赖需评审' }, // 公摊
  policy: {
    tightenPerQuarter: 0.05,   // 只紧不松
    loosenRequires: '业务收益评审 > 性能损失估值',
    ciRule: 'chunk 按目录归属 team，超预算 @owner，warning 带宽 90%',
  },
};
console.log(budgetAllocation.policy.ciRule);
```
