## PER-1064：前端如何参与服务端性能容量评审

**答**：
- 前端视角输入：页面请求模型（首屏依赖几个接口/多大 payload/并发峰值）、峰值场景（大促）、弱网占比。
- 评审要点：接口 P99 与前端预算匹配（首屏接口 P99 < 500ms 才能保住 LCP 目标）、限流策略对前端的影响（限流后的前端降级方案）、长连接数容量。
- 产出：容量评审检查单 + 前端降级预案（限流时显示什么、排队 UI、静态兜底）。
- 价值：把"前端被后端拖慢"的归因前置到设计期，而不是上线后互相甩锅。

```javascript
// 首屏请求模型清单（评审输入）
function screenRequestModel(routes) {
  return routes.map(r => ({
    route: r,
    apiCount: r.apis.length,
    payloadKB: +(r.apis.reduce((s, a) => s + a.respKB, 0)).toFixed(0),
    serialDepth: r.apis.reduce((d, a) => Math.max(d, a.deps.length + 1), 1),
    p99Ms: Math.max(...r.apis.map(a => a.p99)),
    lcpBudget: 2500,
    ok: Math.max(...r.apis.map(a => a.p99)) + 300 <= 2500,
  }));
}
// ok=false 的路由在评审期就要定后端目标或前端降级方案
```
