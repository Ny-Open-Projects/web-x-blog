## PER-1258：手写一个首屏阻塞资源识别器

**答**：
- 需求：实现 blockingResources(entries, nav)。entries 为 resource timing；阻塞判定：type css/script 且 startTime < nav.domContentLoadedEventStart 且无 async/defer 标记信息时（用 responseEnd 与 DCL 比较）参与阻塞；输出 { blocking: [name], dclDelay }（这些资源合计拖慢 DCL 的估算）。
- 边界：entry 无 name 跳过；跨域 css 视为阻塞；fetchpriority=low 的 script 不算（标记信息由调用方传入 meta）。
- 评分点：类型判定；DCL 关联；低优排除；延迟估算

```javascript
function blockingResources(entries, nav, meta = {}) {
  const dcl = nav.domContentLoadedEventStart;
  const blocking = [];
  let delay = 0;
  for (const e of entries) {
    const path = new URL(e.name, location.href).pathname;
    const isScript = /\.js$/.test(path);
    const isCss = /\.css$/.test(path);
    if (meta[path]?.lowPriority) continue;
    if ((isScript || isCss) && e.responseEnd > dcl - (nav.domContentLoadedEventStart - nav.fetchStart)) {
      // 近似：responseEnd 接近或超过 DCL 说明在阻塞链上
      if (e.responseEnd <= dcl) {
        blocking.push(path);
        delay += Math.max(0, e.responseEnd - e.startTime - (e.startTime > nav.responseStart ? 0 : 0));
      }
    }
  }
  return { blocking, dclDelay: +delay.toFixed(0) };
}
// 简化说明：真实实现需结合 resource initiatorType 与解析顺序，此处按 endTime 贴近 DCL 近似
```
