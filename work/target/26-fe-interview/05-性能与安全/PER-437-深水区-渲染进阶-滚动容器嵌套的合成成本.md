## PER-437：嵌套滚动容器的合成成本与 will-change 的正确挂法？

**答**:
- 嵌套滚动的问题：内层滚动容器若未提升为合成层，每次滚动引发外层文档的滚动联动判定与重绘；提升了但尺寸巨大（整页内容进一层）→ 层内存爆炸。正确做法：滚动容器自身提升（overflow: auto + contain: paint），内容不做整层提升。
- 滚动联动成本：浏览器需要判定"滚动事件应该给哪层"（事件冒泡链），嵌套 3 层以上每帧判定成本上升；内层滚到边界后 momentum 交接（scroll chaining）的判定也有成本——用 overscroll-behavior: contain 显式切断（语义上也不该让内层滚完带动外层）。
- will-change 挂法：挂在"滚动容器本身"（transform: translateZ(0) 或 will-change: transform），让滚动内容在独立层上合成——滚动时只动层的 transform，不触发文档重绘；不要挂在每个列表项上（层爆炸，PER-405）。
- 验证：Layers 面板确认滚动容器是独立层且尺寸合理；Performance 面板滚动录制无外层 Layout 块。

```css
/* 嵌套滚动的正确姿势 */
.outer { overflow: auto; }
.inner-scroll {
  overflow: auto;
  contain: paint;                 /* 限制子树绘制影响范围 */
  overscroll-behavior: contain;   /* 内层滚到边界不带动外层（省联动判定 + UX 正确） */
  will-change: transform;         /* 滚动容器本身提升：滚动走合成器 */
  /* 不要在 .inner-scroll 的每个子项上挂 will-change —— 层爆炸 */
}
```
