## PER-754：移动端弱网下的乐观更新：本地先行、服务端确认与失败回滚的完整策略

**答**：
- 模式：写操作立即更新本地 UI（乐观态）-> 异步发请求 -> 成功锁定（服务端数据对齐）-> 失败回滚 + 提示；弱网价值巨大（用户不等 RTT 就看到结果）。
- 回滚要求：乐观操作必须可逆（有逆操作函数）；服务端确认后要用服务端返回的最终状态覆盖本地（本地推导可能与并发操作冲突）；连续失败要有重试队列（694）而不是直接放弃。
- 冲突处理：多端并发写（另一设备已改）时以服务端版本为准，UI 提示内容已更新"；乐观期间禁止对该对象的二次乐观写（排队）。
- 度量：乐观命中率（最终成功比例）、回滚率、回滚到用户感知延迟。

const optimisticPolicy = {
  flow: '本地乐观态 -> 异步请求 -> 成功：服务端终态覆盖 -> 失败：逆操作回滚+提示',
