## PER-968：视口外渲染跳过对滚动性能的收益边界在哪里

**答**：
- 收益：未渲染子树不参与 Style/Layout/Paint，长页面初始布局从 O(全部) 降到 O(视口+估算)。
- 边界一：估算尺寸不准（contain-intrinsic-size 偏差）导致滚动条跳动与 CLS。
- 边界二：频繁进出视口的元素反复布局，反向增加成本——需要 rootMargin 预热与合理的项高估计。
- 边界三：依赖"全部元素存在"的逻辑（如 getBoundingClientRect 汇总、查找全部文本）会拿到未渲染状态，需探测 element.checkVisibility()。

```javascript
// content-visibility 与全局逻辑的兼容检查
const item = document.querySelector('.item');       // 视口外
console.log(item.clientHeight);                      // 0 或占位值，非真实高度
console.log(item.checkVisibility?.());               // false：未实际渲染
// 需要真实测量时：
function realHeight(el) {
  const cv = el.style.contentVisibility;
  el.style.contentVisibility = 'visible';
  const h = el.getBoundingClientRect().height;
  el.style.contentVisibility = cv;                   // 恢复
  return h;
}
```
