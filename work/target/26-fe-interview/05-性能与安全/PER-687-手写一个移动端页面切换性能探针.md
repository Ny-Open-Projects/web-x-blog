## PER-687：手写一个移动端页面切换性能探针：记录路由切换的分段耗时（容器/加载/渲染）并检测切换卡顿

**答**：
- 路由切换分段：触发点（点击）-> 旧页面冻结（卸载时机）-> 新页面首帧 -> 数据就绪 -> 可交互；前端侧用 history API 钩子 + 性能 mark 分段，容器启动段由 Native 塞入时间戳。
- 要点：切换卡顿的常见根因是旧页面卸载阻塞（大组件卸载、同步清理）——探针要测旧页面 unmount 耗时单独分段；切换期间的主线程长任务关联记录。
- 边界：SPA 内切换无容器段（t0 用点击时刻）；后退（popstate）与前进分开统计；快速连续切换（防抖场景）要合并样本。
- 评分点：旧页面卸载段独立测量。

```javascript

function routeTransitionProbe() {
  let mark;
  const origPush = history.pushState.bind(history);
  history.pushState = (...args) => {
    const t0 = performance.mark('route:click').startTime;
    mark = { t0 };
    const r = origPush(...args);
    observeUnload(mark);                                        // 旧页面卸载段
    observeFirstPaint(mark);                                    // 新页面首帧段
    return r;
  };
  function observeUnload(m) {
    const t0 = performance.now();
    requestIdleCallback(() => {
      m.unloadMs = +(performance.now() - t0).toFixed(1);        // 卸载完成耗时
      if (m.unloadMs > 100) report('route-unload-slow', m);     // 卸载阻塞嫌疑
    });
  }
  function observeFirstPaint(m) {
    requestAnimationFrame(() => requestAnimationFrame(() => {
      m.firstPaintMs = +(performance.now() - m.t0).toFixed(1);  // 双 rAF 首帧
      navigator.sendBeacon('/collect/route', JSON.stringify(m));
    }));
  }
}
// 分段：unloadMs（旧页卸载）+ firstPaintMs（新页首帧）-> 快速定位切换卡在卸载还是渲染
```
