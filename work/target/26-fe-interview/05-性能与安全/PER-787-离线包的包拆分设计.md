## PER-787：离线包的包拆分设计：基础包、业务包与按页面分包的边界与合并加载策略

**答**：
- 拆分原则：被多页面共享的资源进基础包（框架、公共 SDK、公共图片），单页面独有资源进业务包；基础包常驻，业务包按路由挂载。
- 粒度权衡：包太细 → 管理成本与请求次数上涨；太粗 → 单包过大、任一页面改动触发全包更新。经验：基础包 < 2MB，业务包 < 1MB。
- 合并加载：进入页面时并行请求"基础包（已常驻）+ 当前业务包"，业务包内 manifest 记录依赖版本，与基础包版本做兼容校验（semver 区间）。
- 追问钩子：跨包资源引用如何处理？——统一走 URL 映射表（文件 hash 命名），跨包引用在映射表中解析，避免硬编码路径。

```javascript
// 离线包 manifest 拆分示例
const baseManifest = { id: 'base', version: '3.2.0', files: { 'framework.js': 'a1b2', 'common.png': 'c3d4' } };
const bizManifest = {
  id: 'goods-detail', version: '1.8.0',
  requiresBase: '>=3.0.0 <4.0.0',            // 兼容区间，不满足则回退在线
  files: { 'page.js': 'e5f6', 'style.css': 'f7g8' },
};
function checkCompat(biz, base) {
  return semverSatisfies(base.version, biz.requiresBase)
    ? { ok: true }
    : { ok: false, action: 'fallback-online' };   // 版本错配：整页回退在线加载
}
```
