## PER-515：性能测试的设备矩阵怎么选？全量设备跑不起，如何用最小矩阵覆盖主要用户？

**答**：
- 选型依据来自 RUM 用户分布：按"设备档位 × 系统版本 × 网络类型"聚类，取覆盖率排序，而不是拍脑袋选 iPhone 15 Pro——那测的是最好的用户体验，风险最低的那部分。
- 最小可行矩阵三层：**代表机 1 台**（占用户 40%+ 的中端安卓）、**下限机 1 台**（内存 2GB / 4 年前的低端机，定义能跑的下限）、**天花板 1 台**（旗舰，确保没有低端限定的退化）。
- 实验室缺真机时用降速模拟（CPU throttle × 设备性能系数 + 网络档位），但要留 10~20 台真机做抽检校准。
- 追问钩子：为什么低端机是"下限"而非"平均"？——性能优化保的就是最差那档用户，下限机决定产品能不能用。

```javascript

// 从 RUM 聚合用户分布，自动推荐最小设备矩阵
function recommendMatrix(rumDevices, coverage = 0.8) {
  const ranked = Object.entries(rumDevices)
    .sort((a, b) => b[1].share - a[1].share);          // 按占比排序
  const picked = []; let acc = 0;
  for (const [cls, { share, sampleDevice }] of ranked) {
    picked.push({ cls, sampleDevice, share });
    acc += share;
    if (acc >= coverage) break;                        // 覆盖 80% 用户即停
  }
  picked.push({ cls: 'floor', sampleDevice: '2GB-RAM Android Go', share: 0 }); // 下限机
  return picked;
}
recommendMatrix({
  midAndroid: { share: 0.42, sampleDevice: 'Redmi Note 12' },
  flagship:   { share: 0.25, sampleDevice: 'iPhone 15' },
  lowAndroid: { share: 0.2,  sampleDevice: 'Redmi 9A' },
});
```
