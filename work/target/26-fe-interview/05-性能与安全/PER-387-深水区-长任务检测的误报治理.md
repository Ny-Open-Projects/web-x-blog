## PER-387：长任务监控的误报治理：GC/浏览器内部任务/后台标签页如何从数据中剥离？

**答**：
- 误报源三类：① GC——Major GC 是浏览器内部任务，longtask observer 也会收到（attributed to 'unknown'），不是业务代码的锅；② 后台标签页——页面 hidden 时浏览器仍可能跑任务（如定时器），这些"长任务"与用户体验无关；③ 首次加载的编译任务——大 bundle 的解析编译长任务（可优化 bundle，但口径上与交互卡顿不同）。
- 剥离手段：GC 识别——longtask entry 的 attribution 里 containerType 为 window 且 name 为空、且紧跟 Performance 面板的 GC 标记；更可靠的做法是配合 `performance.memory` 的突降（GC 后水位下降）交叉验证。后台标签——visibilitychange 期间的任务全部丢弃（PER-206 同款过滤）。编译任务——只统计 first paint 之后的长任务（首屏编译单独口径）。
- 口径分层：交互相关长任务（用户操作 500ms 窗口内的）才是 INP 问题的证据；加载期长任务归 TBT 口径；两者分开看板，混在一起互相污染。

```javascript
// 长任务误报剥离
let visible = true;
document.addEventListener('visibilitychange', () => visible = document.visibilityState === 'visible');
let gcWatch = new PerformanceObserver((l) => gcRecently = true);   // memory 压力交叉验证（Chrome）
gcWatch.observe({ type: 'longtask' });   // 简化示意：真实实现用 performance.memory 采样

new PerformanceObserver((list) => {
  for (const e of list.getEntries()) {
    if (!visible) continue;                                   // 后台标签：丢弃
    const isGC = e.name === 'unknown' && !e.attribution?.[0]?.containerName;
    const duringInteraction = e.startTime >= lastUserInput && e.startTime - lastUserInput < 500;
    report({
      type: 'long-task', dur: Math.round(e.duration),
      bucket: isGC ? 'gc' : duringInteraction ? 'interaction' : 'other',   // 分口径看板
    });
  }
}).observe({ type: 'longtask', buffered: true });
```
