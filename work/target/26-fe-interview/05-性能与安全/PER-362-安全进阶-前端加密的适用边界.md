## PER-362：前端加密的适用边界：哪些场景该做哪些是伪安全？密钥管理怎么做？

**答**：
- 伪安全场景：前端"MD5 密码"（攻击者拿到的就是 hash 直接重放，HTTPS 已保证传输）；前端硬编码密钥加密业务数据（密钥就在 JS 里，等于没加密）；"防爬虫加密参数"（JS 可逆向，只提高成本不构成安全边界）。
- 真实价值场景：① 端到端场景——密钥只在用户侧生成（如加密笔记、加密相册，服务端只见密文），WebCrypto 非对称 + 会话密钥；② 本地敏感数据——IndexedDB 敏感字段加密（密钥派生自用户口令，PBKDF2/Argon2 + WebAuthn 绑定），丢设备不丢数据；③ 完整性——WebAuthn/签名防重放与防篡改（支付确认）。
- 密钥管理：密钥不入 JS 包、不进 localStorage（用内存 + WebAuthn/口令派生）；派生计算挪 Worker（PER-312）；会话密钥生命周期与页面一致；密钥轮换有版本号。
- 边界结论：前端加密是"端侧信任边界"工具——它保护"设备被拿走/服务端被拖库"的场景，永远不能替代 HTTPS 与服务端权限校验。

```javascript
// 真实场景：本地敏感数据加密（口令派生密钥，WebCrypto）
async function deriveKey(password, salt) {
  const base = await crypto.subtle.importKey('raw', new TextEncoder().encode(password), 'PBKDF2', false, ['deriveKey']);
  return crypto.subtle.deriveKey(
    { name: 'PBKDF2', salt, iterations: 310000, hash: 'SHA-256' },   // OWASP 推荐迭代数
    base, { name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt']);
}
async function encryptField(key, plaintext) {
  const iv = crypto.getRandomValues(new Uint8Array(12));               // 每次随机 IV
  const ct = await crypto.subtle.encrypt({ name: 'AES-GCM', iv }, key, new TextEncoder().encode(plaintext));
  return { iv: [...iv], ct: [...new Uint8Array(ct)] };
}
// 迭代贵（310000 次 ≈ 100ms+）→ Worker 里派生 + 会话内缓存派生结果
// 伪安全对照：crypto.subtle.digest('SHA-256', pwd) 当"加密"——只是 hash，无密钥无认证
```
