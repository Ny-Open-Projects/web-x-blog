## PER-1122：如何向业务方解释"为什么要花时间做安全"

**答**：
- 翻译成本：把漏洞风险折算成业务语言——资损金额/用户流失/监管处罚案例，而非技术名词。
- 数据支撑：行业事故案例（同类业务被攻击损失）、自家风控拦截数据（每月拦下 X 次攻击尝试）。
- 成本对比：一次安全专项 3 人日 vs 一次安全事件的应急成本（全组停摆 + 修复 + 赔偿）。
- 机制化：把安全做成"默认包含"（脚手架/门禁），业务无需额外决策——最好的说服是不需要说服。

```javascript
// 风险敞口量化
function riskExposure(assets, incidents) {
  const base = assets.reduce((s, a) => s + a.value * a.probability, 0);
  const recent = incidents.slice(-3).reduce((s, i) => s + i.loss, 0);
  return {
    expectedLoss: Math.round(base),                // 期望损失/年
    avgIncident: recent / 3,
    invest: 15,                                    // 安全投入人日/季
    roi: recent / 3 > 0 ? +(recent / 3 / (15 * 3)).toFixed(1) : '预防性',
  };
}
// 汇报口径：安全投入 45 人日/年，期望损失下降 x 万元
```
