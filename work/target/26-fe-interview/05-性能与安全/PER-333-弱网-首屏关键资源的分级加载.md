## PER-333：弱网下首屏资源如何分级加载？关键路径保底与可延迟清单怎么定义？

**答**：
- 分级框架：P0 关键（首屏可见必需：核心 CSS/首屏 JS/主图/关键数据接口）——立即、高优先级、弱网也不降级；P1 重要（首屏交互必需：非首屏交互组件代码）——网络空闲后 1s 内；P2 可延迟（推荐/评论/埋点/三方）——idle 或用户触发，弱网直接跳过 prefetch。
- 弱网自适应：tier 检测（PER-325）驱动分级行为——弱网时 P2 全部跳过、P1 降为"用户触发"、P0 保底；图用低清版本。
- 实现载体：fetchpriority + preload 控制 P0；import() 动态与 idle 队列控制 P1/P2；Service Worker 网络优先级控制（弱网时改路由策略）。
- 预算化：P0 总量预算（HTML+CSS+JS+图 ≤ 200KB 弱网档），CI 校验 P0 清单产物体积，防"关键路径悄悄变胖"。

```javascript
// 分级加载器：tier 驱动
const TIERS = {
  fast:   { p1: 'auto',   p2: 'idle' },        // 快网：P1 自动、P2 空闲
  mid:    { p1: 'auto',   p2: 'on-demand' },   // 中网：P2 用户触发
  slow:   { p1: 'on-demand', p2: 'skip' },     // 弱网：P1 触发式、P2 跳过
};
const tier = networkTier();
const cfg = TIERS[tier];

function loadTier2(loader, key) {
  if (cfg.p2 === 'skip') return Promise.resolve(null);
  if (cfg.p2 === 'idle') return idleQueue.push(loader, { priority: 0, timeout: 5000 });
  return onDemandOnce(key, loader);            // 首次用户交互时加载
}
// P0：HTML 里 fetchpriority=high + preload（构建期静态声明，不受 tier 影响）
// P0 预算：CI 检查 P0 清单 gzip 总量 <= 200KB，超了拦发布
```
