## PER-664：手写一个接口响应信任层：所有服务端数据渲染前过类型校验，防服务端被攻破后注入前端

**答**：
- 威胁视角：接口响应被劫持/服务端被攻破时，响应里的恶意 HTML/脚本会经 `v-html/dangerouslySetInnerHTML` 落地——前端渲染层加信任边界：所有动态 HTML 必须走净化，所有数据先过 schema。
- 实现：统一 renderHtml（内部强制 DOMPurify）+ response 校验中间件（zod/手写轻 schema），校验失败丢弃并告警（fail-closed）。
- 要点：schema 校验放拦截器层（fetch 封装），业务代码拿到的数据默认可信；超长字段截断防 DoS 渲染；嵌套深度限制防解析卡死。
- 评分点：拦截器层统一校验与 DoS 防护。

```javascript

function schemaValidate(data, schema, { maxStr = 5000, maxDepth = 5 } = {}) {
  const check = (v, s, depth) => {
    if (depth > maxDepth) throw new Error('depth-exceeded');     // 防嵌套 DoS
    if (s === 'string') {
      if (typeof v !== 'string') throw new Error('type-mismatch');
      if (v.length > maxStr) throw new Error('oversized');
      return v;
    }
    if (s === 'number') { if (typeof v !== 'number' || !Number.isFinite(v)) throw new Error('type-mismatch'); return v; }
    if (Array.isArray(s)) return v.map(x => check(x, s[0], depth + 1));
    if (typeof s === 'object') {
      const out = {};
      for (const [k, sub] of Object.entries(s)) {
        if (v[k] === undefined) continue;                        // 宽进：缺字段跳过
        out[k] = check(v[k], sub, depth + 1);
      }
      return out;
    }
    throw new Error('bad-schema');
  };
  return check(data, schema, 0);
}
// fetch 拦截器：校验失败 -> 丢弃响应 + 告警（fail-closed），业务拿不到未校验数据
// HTML 渲染强制走 renderHtml：v-html 的唯一合法来源
```
