## PER-375：一次完整的首屏优化战役复盘：从 LCP 6.8s 到 2.1s 的完整改造路径？

**答**：
- 起点：核心商品页 LCP p75 = 6.8s（移动端）。四段拆解（PER-302）：TTFB 2.4s、资源发现 0.6s、资源加载 2.1s、渲染延迟 1.7s——四段全超标，属于系统性问题，需要分阶段战役而不是单点修复。
- 第一阶段（网络层，TTFB 2.4→0.5s）：接口串行改 BFF 并行聚合（瀑布砍两跳）+ HTML 边缘缓存 SWR + CDN 回源预热带；接口 P99 瘦身（砍非首屏字段 40%）。
- 第二阶段（资源层，加载 2.1→0.5s）：LCP 主图 PNG 1.2MB → AVIF 180KB（fetchpriority=high + preload）；字体子集化 + size-adjust；JS 入口 chunk 从 480KB 砍到 210KB（树摇 + 依赖替换 + 动态 import 非首屏）。
- 第三阶段（渲染层，渲染延迟 1.7→0.3s）：关键 CSS 内联（render-blocking 砍掉 80%）、render-blocking script 全部 defer、骨架屏尺寸对齐真内容（CLS 同时从 0.28 降到 0.04）。
- 收益验证：灰度 5% 跑一周，RUM p75 LCP 6.8→2.1s，转化率 +2.3%（A/B 显著）；方法论沉淀：每次只动一个变量、灰度验证、双指标验收（性能 + 业务）。

```text
战役时间线（复盘模板）：
W0  基线审计：LCP 6.8s 四段拆解定位（TTFB/发现/加载/渲染全超标）
W1-2 网络层：BFF 并行 + SWR 边缘缓存 + 接口瘦身    → TTFB 2.4s → 0.5s
W3-4 资源层：AVIF 主图 + 字体子集 + bundle 减量     → 加载 2.1s → 0.5s
W5   渲染层：关键 CSS 内联 + defer + 骨架对齐       → 渲染延迟 1.7s → 0.3s
W6   灰度 5% 一周：LCP 2.1s 达标，CLS 0.28→0.04，转化 +2.3%（显著）
W7   全量 + 案例库归档 + 预算收紧到新基线
纪律：单变量、灰度验证、双指标验收、案例沉淀 —— 缺一步都可能导致"优化了但说不清"
```
