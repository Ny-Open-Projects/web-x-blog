## PER-241：CrUX 为什么永远不会有 p99 或单用户数据？隐私约束如何决定数据形态？

**答**：
- k-匿名原则：任何统计单元（origin、URL、桶）必须覆盖足够多的真实用户，否则一条数据可被反推到个体浏览行为（比如"p75=这个值 → 你大概率访问过该页面"）。这是 CrUX 只有 p75、只有粗直方图、低流量页无数据的唯一原因。
- 数据形态的全部设计都源于此：28 天滚动窗口（样本量充足）、三桶直方图（不暴露精细分布）、无维度下钻（设备/连接仅两三个枚举）、无 p99（尾部极端值对应极少用户）。
- 对比自建 RUM 的合规红线：自己采集也要遵守同等精神——不上报精确用户指纹、明细数据设保留期、聚合展示不再下钻到可识别个体；国内还需符合个人信息保护法对"性能数据是否关联用户"的判断。
- 面试要点：理解"k 匿名决定数据形态"比背字段有用得多，能推演出"为什么这里没有 p99、那里没有小页面数据"。

```text
CrUX 一条 URL 数据的最小发布单元（伪约束）：
  count(users in bucket) >= K          # 桶内用户数达标才发布
  28-day rolling window                # 窗口保证样本量
  granularity: {good, ni, poor} x3     # 只给三桶，不给完整分布
推论：p99 桶内用户 < K => 永不发布；小页面 users < K => 整条无数据
自建 RUM 同理：看板展示层应限制"样本数 < 30 的分组不可见"（等价 k-匿名实践）
```
