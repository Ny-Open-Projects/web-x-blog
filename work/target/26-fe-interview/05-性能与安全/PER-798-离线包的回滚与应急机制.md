## PER-798：离线包的回滚与应急机制：包出问题的快速止损流程与演练

**答**：
- 止损手段按速度排序：① 版本黑名单（服务端下发强制失效，客户端下次心跳即弃包，最快）；② 强制升版（推新包覆盖，受下载周期限制，慢）；③ 客户端侧包校验失败自动回在线（兜底，依赖防线质量）。
- 前置要求：拦截器必须保留"一键全量回在线"总开关（杀鸡用牛刀但救火必需）；黑名单生效要有埋点可验证（下发后 N 分钟内黑名单包命中率应归零）。
- 流程：告警（错配/崩溃突增）→ 定位到包版本 → 拉黑 → 验证归零 → 修复后发新包 → 灰度恢复。
- 演练：每季度做一次"毒包演练"——故意推一个校验失败的包，验证客户端自动回在线与告警链路真实可用。

```javascript
// 止损链路实现要点
const killSwitch = {
  async onHeartbeat() {
    const blacklist = await fetchBlacklist();                // 服务端版本黑名单
    for (const pkgId of blacklist) {
      const local = OFFLINE_MAP.get(pkgId);
      if (local) {
        OFFLINE_MAP.delete(pkgId);
        report('bundle-killed', { pkg: pkgId });             // 生效埋点（验证归零用）
      }
    }
    if (blacklist.includes('*')) OFFLINE_MAP.clear();        // 一键全量回在线
  },
  onInterceptFail(pkgId) {                                   // 校验失败自动止损
    OFFLINE_MAP.delete(pkgId);
    report('bundle-corrupt-fallback', { pkg: pkgId });       // 触发告警
    return { type: 'network' };
  },
};
```
