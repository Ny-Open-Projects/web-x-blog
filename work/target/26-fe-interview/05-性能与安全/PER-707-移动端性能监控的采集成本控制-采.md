## PER-707：移动端性能监控的采集成本控制：采集本身的性能税怎么量化与管理？

**答**：
- 采集税来源：rAF 探针每帧回调、 MutationObserver 全页监听、 PerformanceObserver buffer、上报序列化与网络——总量要控制在 CPU < 3%、内存 < 5MB。
- 量化方法：开/关采集的 A/B 对比（同页两组会话对比秒开率与帧率差值）、DevTools Profiling 对比采集器自身的 self time、内存快照对比。
- 管理手段：采样分档（低端机更低采样率）、探针懒安装（首屏后才装非核心探针）、批量上报（10s 一包）、序列化抽样、探针注册表统一开关（一键全关保命）。
- 红线：采集导致页面卡顿即事故——探针改动必须过采集税 CI"（对比开关 A/B 指标差 < 1%）。

```javascript

const collectTaxPolicy = {
  budget: { cpu: '< 3%', memory: '< 5MB', jank: '探针自身不得产生 longtask' },
  measure: ['开关 A/B：秒开率/帧率差值', 'Profiler self time', '内存快照对比'],
  controls: { sampling: '低端机采样减半', lazyInstall: '首屏后才装非核心探针',
    batch: '10s 批量上报', sampleJson: '序列化抽样', killSwitch: '探针注册表一键全关' },
  redline: '采集致卡 = 事故；探针改动过采集税 CI"（开关 A/B 差 < 1%）',
};
console.log(collectTaxPolicy.redline);
```
