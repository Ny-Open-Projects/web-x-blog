## PER-1243：如何设计"性能冒烟测试"（每次发版 5 分钟内完成）

**答**：
- 目标：发版后自动跑 3~5 条关键路由的 Lab 指标（固定环境），5 分钟出结果，超标即通知。
- 实现：headless 批量（922 的 stress 简版）+ 固定机型网络模拟 + 只测 LCP/INP/TTFB 三指标。
- 成本控制：复用预热实例、并行 3 路、指标采集最少化。
- 联动：超标自动 @ 发版人并附对比基线。

```javascript
// 冒烟测试编排
async function smokeTest(routes, baseline) {
  const results = [];
  for (const r of routes) {
    const m = await labRun(r, { preset: 'mobile4G', runs: 3 });
    const p75 = medianOf(m.map(x => x.lcp));
    results.push({ route: r, lcp: p75,
      pass: p75 <= baseline[r] * 1.05 });
  }
  const failed = results.filter(r => !r.pass);
  if (failed.length) notify(releaser,
    `冒烟失败: ${failed.map(f => f.route).join(', ')}`);
  return { results, pass: !failed.length };
}
function medianOf(a) { const s = [...a].sort((x, y) => x - y);
  return s[s.length >> 1]; }
```

**边界与易错**：

1. `runs: 3` 取中位数，三次抖动很大时机房噪声能把中位数带偏——要先丢离群值或提高 runs，否则误报会让人直接无视告警。
2. `baseline[r] * 1.05` 是 5% 阈值，但 LCP 本身波动常超 5%，阈值太紧会天天红，应按历史方差定阈值。
3. 只测 LCP/INP/TTFB，`labRun` 在没有交互脚本时根本拿不到 INP，冒烟里的 INP 往往是「无数据」，别当 0 处理。

**追问**：

1. 冒烟只跑 3~5 条关键路由，漏掉的页面怎么防回归？ → 关键路由进冒烟、其余进每日全量，两层覆盖。
2. 发版是灰度发布，冒烟测的是新版本还是线上旧版？ → 冒烟要打灰度环境或指定版本地址，测线上主版本等于没测。
3. 超标通知发版人，但发版人判断是噪声不服怎么办？ → 附基线对比与三次样本明细，允许带证据申请豁免并留档。
