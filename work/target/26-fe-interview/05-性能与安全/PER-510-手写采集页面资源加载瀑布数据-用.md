## PER-510：手写采集页面资源加载瀑布数据：用 Resource Timing 把每个请求分解为 DNS/TCP/TLS/等待/下载各阶段

**答**：
- 考察 Resource Timing 各阶段的计算公式：`domainLookupEnd - domainLookupStart`（DNS）、`connectEnd - connectStart`（TCP，含 TLS）、`requestStart` 到 `responseStart`（等待/首字节）、`responseEnd - responseStart`（下载）。
- 要点：跨域资源需要 `Timing-Allow-Origin` 才能拿到精确时间，否则全是 0——采集端要做 TAO 缺失标记。
- 边界：buffer 默认 250 条会被大页面打满，要监听 `resourcetimingbufferfull` 并及时 `clearResourceTimings` 或调大 buffer。
- 评分点：能否按域名聚合出"哪个第三方域最耗时"，这才是瀑布数据的落地价值。

```javascript

function collectWaterfall() {
  const Stage = (e) => ({
    name: e.name.replace(/^https?:\/\/([^/]+).*/, '$1'),
    initiator: e.initiatorType,
    dns: e.domainLookupEnd - e.domainLookupStart,
    tcp: Math.max(0, e.connectEnd - e.connectStart),          // 含 TLS
    wait: e.responseStart - e.requestStart,                    // 首字节等待
    download: e.responseEnd - e.responseStart,
    tao: e.requestStart > 0,                                   // TAO 缺失时各段为 0
  });
  performance.addEventListener?.('resourcetimingbufferfull', () => {
    performance.clearResourceTimings(); // 防止大页面打满 250 条 buffer
  });
  const rows = performance.getEntriesByType('resource').map(Stage);
  // 按域名聚合：找出最拖后腿的第三方
  const byHost = {};
  rows.forEach(r => {
    const t = byHost[r.name] ??= { count: 0, total: 0 };
    t.count++; t.total += r.wait + r.download;
  });
  return { rows, topHosts: Object.entries(byHost).sort((a, b) => b[1].total - a[1].total).slice(0, 5) };
}
console.table(collectWaterfall().topHosts);
```
