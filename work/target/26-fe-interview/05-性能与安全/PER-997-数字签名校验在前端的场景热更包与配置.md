## PER-997：数字签名校验在前端的场景：热更包与配置文件

**答**：
- 场景：小程序/混合容器动态下发 JS 包、运营配置 JSON——下发通道被劫持即可注入代码。
- 方案：服务端对包内容做 Ed25519/ECDSA 签名，客户端用内置公钥验签后才执行；哈希（sha256）只能防误传，防不了主动篡改（攻击者可换哈希）。
- 工程：公钥随主包内置（可升级需双钥过渡）、验签在沙箱内完成、失败静默拒绝并上报告警。
- 组合：HTTPS + 签名 + 包体压缩加密，签名是唯一可信根。

```javascript
// 热更包验签（WebCrypto，Ed25519 需现代实现，示例用 ECDSA P-256）
async function verifyBundle(bundle, sigB64) {
  const key = await crypto.subtle.importKey('raw', PUB_KEY,
    { name: 'ECDSA', namedCurve: 'P-256' }, false, ['verify']);
  const sig = Uint8Array.from(atob(sigB64), c => c.charCodeAt(0));
  const ok = await crypto.subtle.verify({ name: 'ECDSA', hash: 'SHA-256' },
    key, sig, bundle);
  if (!ok) { report({ type: 'bundle-signature-fail' }); throw new Error('验签失败'); }
  return bundle;                              // 验签通过才可 new Function/eval 沙箱执行
}
```
