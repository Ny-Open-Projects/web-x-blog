## PER-350：IM/行情类长连接应用的事件风暴：消息积压、缓存淘汰与背压怎么设计？

**答**：
- 事件风暴形态：行情 200 条/秒、IM 群消息高峰 50 条/秒——每条消息触发事件 → 渲染 → 状态更新，主线程被打满（INP 爆炸）+ 消息数组无限增长（内存爆炸）。
- 分层缓冲设计：① 网络层——WS 消息入队（RingBuffer 固定容量，满则丢最旧并标记 gap，行情可容忍、IM 不可丢要 ACK 机制）；② 聚合层——rAF/定时器批量 flush（每帧最多处理一批，行情类按 key 只保留最新值）；③ 渲染层——虚拟列表 + 增量 append（不重渲染整个列表）。
- 内存治理：消息存储用环形缓冲（容量上限，IM 超限翻页从服务端拉）；已渲染离屏消息位图/引用及时释放；行情类旧 tick 全丢只留当前值。
- 背压联动：处理不过来时（队列水位 > 80%）主动降级——暂停订阅低优先级频道、拉长 UI 更新间隔（500ms 一批）、提示用户网络/设备压力。

```javascript
class EventStreamBuffer {
  constructor({ capacity = 5000, flushMs = 100, onFlush } = {}) {
    Object.assign(this, { capacity, flushMs, onFlush });
    this.buf = []; this.timer = null; this.paused = false;
  }
  push(msg) {
    if (this.buf.length >= this.capacity) { this.buf.shift(); this.dropped++; }  // 丢最旧（行情语义）
    this.buf.push(msg);
    if (!this.timer) this.timer = setTimeout(() => this.flush(), this.flushMs);
  }
  flush() {
    this.timer = null;
    const batch = this.buf.splice(0, this.buf.length);
    this.onFlush?.(batch);                       // 渲染层：增量 append / 最新值覆盖
    if (this.dropped > this.capacity * 0.2) this.pause?.();  // 丢弃超 20%：触发背压降级
  }
}
// 行情渲染：flush 里对同 key 只取最新 tick：
// const latest = new Map(batch.map(m => [m.symbol, m])) —— 200 条/秒最终每帧只渲染一次
```
