## PER-1027：重试风暴与退避策略：如何让失败重试不放大故障

**答**：
- 朴素重试（固定间隔、立即重试）在服务端故障时会形成重试风暴放大故障——重试流量叠加真实流量。
- 正确姿势：指数退避 + 抖动（jitter），上限次数（3 次）、只重试幂等请求或带幂等键、区分可重试错误（503/超时）与不可重试（400/401）。
- 熔断联动：连续失败达到阈值后停止重试一段时间（熔断），恢复期半开试探。
- 前端视角：重试决策放在统一请求层，业务代码不自己重试。

```javascript
function retry(fn, { times = 3, base = 300, cap = 5000 } = {}) {
  return async function (...args) {
    for (let i = 0; i < times; i++) {
      try { return await fn(...args); }
      catch (e) {
        const retriable = e.status === 503 || e.type === 'timeout';
        if (!retriable || i === times - 1) throw e;
        const exp = Math.min(cap, base * 2 ** i);
        const jitter = Math.random() * exp * 0.5;      // 抖动防同步重试
        await new Promise(r => setTimeout(r, exp + jitter));
      }
    }
  };
}
// 幂等键：POST 重试时复用同一 requestId，服务端去重
```
