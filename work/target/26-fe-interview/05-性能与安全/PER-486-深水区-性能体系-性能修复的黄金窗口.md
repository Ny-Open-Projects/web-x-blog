## PER-486：发现性能问题后多久内修收益最大？

**答**:
- 黄金窗口逻辑：① 告警后 24h 内——问题新鲜（上下文齐全、相关变更都在记忆里），修复成本最低；② 一周内——指标恶化会被后续发版"掩盖"（新版本引入更多变化，归因变难）；③ 一个月后——问题进入"习以为常"状态（用户与团队都适应了慢），修复动力消失，且基线被污染（SLO 基线默认了慢的存在）。
- 时间预算分配（发现→关闭）：MTTA < 4h（认领）、诊断 < 1 天、修复 < 3 天、验证 < 3 天——总窗口 7 天内闭环（PER-245 工单闭环指标）。
- 无法黄金窗口修复的（架构级）：标注"还债项"进账本（PER-465 定价）+ 临时缓解措施（降级/缓存兜底）——"缓住体验恶化，等待结构性修复"，两者并行而不是二选一。
- 度量：黄金窗口达成率（7 天闭环比例）；超窗口问题的"基线污染度"（问题存在期间达标的 SLO 是否被隐性放宽）。

```text
修复黄金窗口（发现→关闭 7 天）：
24h 内修复最便宜（上下文新鲜）；一周内归因仍清晰；一个月后基线污染 + 习以为常
预算：MTTA < 4h / 诊断 < 1d / 修复 < 3d / 验证 < 3d
架构级问题：进账本定价（PER-465）+ 临时缓解（降级兜底）并行 —— 不二选一
度量：7 天闭环达成率；超窗口问题的基线污染审计
```
