## PER-391：首屏接口预取的命中率优化：预测用户路径与预取策略的迭代闭环？

**答**：
- 预取的收益与浪费：命中 = 用户到达时数据已就绪（省一个接口 RTT）；浪费 = 预取了没走的路径（流量白花，PER-372）。命中率 < 50% 时预取弊大于利，优化闭环的目标是把命中率推到 70%+。
- 预测策略阶梯：① 规则式——静态热门路径（首页 → 排行榜 Top3 详情页）、视口内链接预取（hover 100ms 延迟触发，防误滑）、路由 idle 预取（PER-088）；② 统计式——按页面 × 入口统计路径转移概率，预取概率 Top2 的下一页；③ 用户级——会话内行为修正（已浏览过的品类优先）。策略由服务端配置下发，可快速迭代。
- 命中率度量：预取请求打上标记（prefetch: true），服务端统计"预取后 5 分钟内被真实使用"的比例，按策略分策略命中率；浪费率（预取后未用）驱动策略下线。
- 边界纪律：saveData 尊重（PER-326）、弱网不预取（PER-325）、单会话预取并发 ≤ 2、预取数据 TTL（过期即弃）。

```javascript
// 预取策略执行器（策略由服务端下发）
const strategies = [
  { type: 'hover', selector: 'a[data-prefetch]', delay: 100 },    // hover 100ms 防误滑
  { type: 'transition', from: '/home', to: '/ranking', prob: 0.62 },
  { type: 'idle', routes: ['/ranking', '/recs'] },
];
let inflightPrefetch = 0;
function tryPrefetch(url) {
  if (navigator.connection?.saveData || networkTier() === 'slow') return;   // 纪律
  if (inflightPrefetch >= 2) return;                                        // 并发上限
  inflightPrefetch++;
  fetch(url, { headers: { 'X-Prefetch': '1' } }).catch(() => {}).finally(() => inflightPrefetch--);
}
// 服务端统计：X-Prefetch 请求在 5min 内被同会话真实请求命中的比例 = 命中率
// 命中率 < 50% 的策略自动下线（浪费率驱动迭代）
```
