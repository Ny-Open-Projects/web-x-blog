## PER-568：监控上报的数据质量问题：丢失、重复、乱序分别怎么治理？

**答**：
- **丢失**：sendBeacon 也有极限（大 payload 丢）、页面被杀、网络失败——治理靠重试队列（IndexedDB 暂存失败包，下次启动补发）+ 数据侧可用性优先"（丢失容忍，不阻塞主流程）。
- **重复**：重试导致的重复上报——每包带唯一 `msgId`，服务端按 msgId 去重（幂等），客户端不做确认后删除的复杂协议（成本高于重复代价）。
- **乱序**：批量补发导致时间乱序——每包带客户端时间戳 + 服务端接收时间戳双字段，聚合按客户端时间为主、偏差超阈值（时钟漂移）用服务端时间校正。
- 治理的度量：上报成功率（服务端收到/客户端发送）、重复率、时钟偏差分布，三项进监控的数据质量看板——数据质量本身也要被监控。

```javascript

class ReliableReporter {
  constructor() { this.store = indexedDB.open('report-queue'); this.msgId = 0; }
  send(payload) {
    const id = `${Date.now()}-${this.msgId++}`;
    const body = JSON.stringify({ id, clientTs: Date.now(), ...payload });
    navigator.sendBeacon('/collect', body)
      ? undefined
      : this.persist(body);                               // beacon 失败 -> 落盘补发
  }
  async persist(body) {
    const db = await this.store;
    db.transaction('q', 'readwrite').objectStore('q').add({ body, ts: Date.now() });
  }
  async replay(max = 50) {                                // 启动时补发
    const db = await this.store;
    const all = await new Promise(r => {
      const req = db.transaction('q').objectStore('q').getAll();
      req.onsuccess = () => r(req.result);
    });
    all.slice(0, max).forEach(item => navigator.sendBeacon('/collect', item.body));
    db.transaction('q', 'readwrite').objectStore('q').clear(); // 服务端按 msgId 幂等去重
  }
}
```
