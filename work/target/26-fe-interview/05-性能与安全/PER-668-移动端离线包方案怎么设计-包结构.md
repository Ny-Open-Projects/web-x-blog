## PER-668：移动端离线包方案怎么设计？包结构、更新流程与灰度发布如何落地？

**答**：
- 包结构：业务包 = HTML/JS/CSS/静态资源 + manifest（文件清单含 hash）；按业务拆包（首页包/详情包），控制单包大小（< 5MB）与公共依赖包。
- 更新流程：启动/进页前查版本接口 -> 下载新包 zip -> 差量（bsdiff/brotli patch）或全量 -> 校验（包级签名 + 文件 hash）-> 解压落盘 -> 原子切换（新目录写完 rename，失败回滚旧包）。
- 灰度发布：版本接口按设备/用户尾号下发目标版本，问题版本秒级下线（服务端下发 kill，回退到上一稳定版本）；拦截层按当前包版本匹配资源。
- 关键坑：拦截要在请求发出前（容器 webview scheme 拦截/shouldInterceptRequest），拦截失败的兜底是真网下载；包内绝对路径要改成相对路径，否则拦截匹配不上。

```javascript

// 离线包更新器（容器 JSAPI 协议示意）
class OfflinePackageManager {
  constructor(bridge) { this.bridge = bridge; }
  async check(route) {
    const local = await this.bridge.getLocalVersion(route);
    const remote = await fetch(`/offline/manifest?route=${route}&v=${local.version}`).then(r => r.json());
    if (remote.version <= local.version) return { upToDate: true };
    const zip = await this.bridge.download(remote.url);        // 支持差量 patch
    const ok = await this.verify(zip, remote);                 // 包级签名+文件 hash
    if (!ok) throw new Error('离线包校验失败');
    await this.bridge.extract(zip, `${route}@${remote.version}`); // 新目录
    await this.bridge.switchVersion(route, remote.version);    // 原子切换
    return { updated: remote.version, killSwitch: remote.kill }; // kill=true 回退上一稳定版
  }
  async verify(zip, manifest) {
    const sigOk = await this.bridge.verifySignature(zip, manifest.sig);
    const files = await this.bridge.listZip(zip);
    return sigOk && files.every(f => hashOf(f) === manifest.files[f.name].hash);
  }
}
// 拦截层：webview 请求 /offline/detail/index.html -> 本地文件命中即返回（相对路径才能命中）
```
