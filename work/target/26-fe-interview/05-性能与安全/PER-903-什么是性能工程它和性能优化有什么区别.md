## PER-903：什么是性能工程？它和性能优化有什么区别

**答**：
- 性能工程是把性能当作工程属性全生命周期管理：预算制定→开发期度量→上线门禁→线上监控→回归复盘，而不是事后的"救火式优化"。
- 性能优化关注单点问题修复，性能工程关注让问题不发生：通过预算、CI 门禁、劣化告警把性能约束前置到流程里。
- 核心交付物：性能预算文档、构建期体积/指标门禁、RUM 采集体系、性能看板与值班机制。
- 追问点：性能预算如何定（对标竞品 P75 而非拍脑袋）、门禁拦截后如何豁免（审批单 + 有效期）。

```javascript
// 性能预算示例：budget.json，被 CI 门禁读取
{
  "resourceCounts": { "script": 12, "total": 60 },
  "resourceSizes": { "script": 350, "total": 900 },   // 单位 KB
  "timings": [
    { "metric": "largest-contentful-paint", "budget": 2500, "p75": true },
    { "metric": "cumulative-layout-shift",  "budget": 0.1 },
    { "metric": "interaction-to-next-paint","budget": 200,  "p75": true }
  ],
  "stickyEnforcement": true   // 指标劣化未修复前持续拦截，不允许"下次再改"
}
```

**边界与易错**：

- 别把性能工程等同于一次调优，缺基线与门禁时优化成果会在下个迭代回吐。
- 指标口径要区分实验室（固定环境跑分）与真实用户（RUM 分位），两者不能互相替代。
- 只报"LCP 3.2s"不构成结论，归因必须落到具体资源或代码位置，否则无法验证改进。

## 追问（补充）

**追问**：

1. 和性能优化的区别？ → 优化是单点项目，工程是体系：度量、预算、门禁、归因、复盘形成闭环。
2. 怎么证明优化有效？ → 灰度 A/B 加 RUM 分位对比，而不是单次实验室跑分或主观感受。
3. 团队落地第一步做什么？ → 建性能预算并接进 CI 门禁，让指标成为发布流程的一部分。
