## PER-452：iframe 的内存隔离与成本？

**答**:
- 隔离收益：iframe 是独立文档+独立 JS 堆——iframe 内的泄漏随 iframe 移除整堆释放（主页面泄漏则要整页刷新才能清）。微前端/三方嵌入场景，iframe 是"内存防火墙"：不可控三方 SDK 的泄漏不污染主应用。
- 成本清单：每 iframe 独立堆基线（约 10~30MB）、独立解析编译（同库重复加载——共享依赖失效）、postMessage 通信开销（PER-358）、bfcache 与 SW 覆盖复杂化。
- 决策框架：不可控三方（广告/聊天）→ iframe 隔离收益 > 成本；可控自有代码 → 同文档组件化（共享框架省内存）；介于两者 → 同文档 + 严格泄漏监控（PER-266/278）+ 兜底"软刷新"。
- 量化验证：Chrome 任务管理器逐进程看内存（iframe 独立进程可见），对比"同文档集成 vs iframe 集成"的内存曲线（加载同等功能）。

```text
iframe 内存隔离决策：
收益：独立堆——iframe 移除即整堆释放；三方泄漏不污染主应用（内存防火墙）
成本：独立堆基线 10~30MB/个、共享依赖失效（同库重复加载）、postMessage 开销、
      bfcache/SW 覆盖复杂化
决策：不可控三方 → iframe；自有代码 → 同文档组件化；中间态 → 同文档 + 泄漏监控 + 软刷新兜底
验证：Chrome 任务管理器逐进程内存曲线对比两种集成方式
```
