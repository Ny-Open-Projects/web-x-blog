## PER-446：性能平台自身的合规审计：PII 扫描、跨境与删除权？

**答**:
- 平台也是数据处理器：性能明细里有 URL（可能带用户参数）、UA（指纹性）、回放数据（PER-368）——平台自身要过合规三关：① PII 扫描——自动巡检上报样本（正则扫手机号/身份证/邮箱，PER-411 的 sanitize 上游 + 服务端抽样复核），命中即告警并清理；② 跨境传输——数据存储地域策略（境内站点境内存储），跨境部分脱敏/聚合后才出；③ 删除权——按设备标识/会话 ID 的删除接口（用户行使删除权时，明细与回放按标识清除，聚合数据不可反推个体天然合规）。
- 回放数据的特殊性：rrweb 录制含用户输入画面——脱敏必须在录制端（maskAllInputs，PER-368），服务端不可逆——"录制时脱敏"是唯一安全位置（后端解密再脱敏等于没有脱敏）。
- 审计节奏：季度合规审计（PII 扫描报告 + 保留期执行情况 + 删除权响应时长）；数据地图（哪些数据/存哪/多久/谁能看）文档化。

```text
性能平台合规三关：
PII 扫描：SDK sanitize 上游（PER-411）+ 服务端抽样正则复核 → 命中告警清理
跨境：境内站点境内存储；跨境仅聚合/脱敏后数据
删除权：按设备标识/会话 ID 清明细与回放；聚合数据不可反推个体
回放特殊：脱敏只能在录制端（maskAllInputs）—— 服务端再脱敏=没有脱敏
审计节奏：季度审计（PII 报告/保留期执行/删除响应时长）+ 数据地图文档
```
