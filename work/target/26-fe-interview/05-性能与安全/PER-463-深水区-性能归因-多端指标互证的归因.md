## PER-463：多端指标互证：Web/App/小程序的差异如何归因？

**答**:
- 归因分层：多端指标差异 = 渲染引擎差异（Web vs 原生 vs 小程序内核）+ 业务代码差异（各自实现质量）+ 网络环境差异（App 内嵌 vs 浏览器）。归因方法：控制变量——同功能同数据同网络档下对比各端，差异中"结构性的"（原生列表永远比 Web 流畅）记为引擎差异，"可优化的"（某端多一次接口串行）记为业务差异。
- 互证技术：接口耗时多端应一致（同接口同网络）——若某端明显慢，查该端请求层（DNS/Bridge/代理）；渲染差异用"同屏元素数 × 帧耗时"归一比较。
- 实践价值：App 端列表流畅而 Web 卡顿 → 不是需求问题而是 Web 实现问题（虚拟化/切片缺失），修复方向明确；小程序慢于 Web 且结构相近 → 查小程序 setData 频率与分包。
- 度量基建：统一 schema（PER-369）+ 按端切片对比视图；差异 > 30% 的"同功能跨端差距"自动进治理清单。

```text
多端互证归因法：
差异 = 引擎差异（结构性） + 业务代码差异（可优化） + 网络环境差异
控制变量：同功能 × 同数据 × 同网络档 → 结构性差异记引擎，可优化差记业务
互证：接口耗时跨端应一致（同接口同网络），某端慢查该端请求层
渲染归一比较：同屏元素数 × 帧耗时
案例：App 流畅 Web 卡 → Web 实现问题（虚拟化缺失）；小程序慢于 Web 结构相近 → setData 频率
治理：同功能跨端差距 > 30% 自动进清单（统一 schema，PER-369）
```
