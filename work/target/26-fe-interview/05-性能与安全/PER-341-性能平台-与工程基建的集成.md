## PER-341：性能平台如何与工程基建集成？脚手架/组件库/监控的默认性能保障怎么设计？

**答**：
- 理念：性能保障要"默认内置"而不是"事后审计"——新项目从脚手架出来就带着正确的分包配置、图片组件（aspect-ratio + 懒加载）、监控 SDK 接入、CI 预算卡口。绝大多数性能问题应该在项目出生时就被结构排除。
- 脚手架层：模板内置路由级 code splitting、关键 CSS 内联方案、字体加载方案（size-adjust）、三方加载器（白名单 + idle 触发）、RUM SDK 与 vitals 上报。
- 组件库层：组件自带性能约束——图片组件强制尺寸声明、列表组件内置虚拟化（超过阈值自动启用）、弹窗组件用 content-visibility；组件文档标注每个组件的性能画像（渲染成本、内存）。
- 监控层：新项目接入即自动注册页面模板与 SLO 基线（按同类页面默认值），不用每次手工配。
- 集成的衡量：新项目"性能就绪度"检查表——出生 1 天内全部绿灯的比例；模板升级的推送机制（脚手架出新版主动推迁移 PR）。

```text
脚手架内置清单（create-app 默认携带）：
[x] 路由级 code splitting（React.lazy/Vue defineAsyncComponent）
[x] 图片组件 <Img>：强制 width/height 或 aspect-ratio + 自动 AVIF/WebP 协商
[x] 字体方案：font-display swap + size-adjust 度量对齐 + 子集化构建插件
[x] 三方加载器：白名单 + idle 触发 + 超时熔断（PER-223）
[x] RUM SDK：vitals + 自定义指标 + 采样（默认 10%，核心页全量）
[x] CI：bundle 预算卡口 + LHCI 基线 + budgets.json 就绪
出生即绿的验收：新项目 Day1 全部通过性能就绪度检查
```
