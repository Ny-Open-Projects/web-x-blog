## PER-719：移动端触摸响应延迟的测量与优化：从 touchend 到 UI 反馈的耗时怎么压到 16ms 内？

**答**：
- 延迟构成：touch 事件派发（浏览器合成器 -> 主线程）-> JS 处理（handler 执行）-> DOM 更新 -> 合成绘制——四段任何一段超预算都表现为按了没反应。
- 测量：touchstart/touchend 打点 + 双 rAF 确认绘制完成（同交互分段计时思路）；合成器可响应的部分（transform 动画、:active 伪类）不受主线程阻塞——优先用这些做即时反馈。
- 优化清单：handler 轻量（重逻辑 requestIdleCallback 延后）、:active 高亮用 CSS（零 JS）、避免点击时同步读布局、点击目标不要太小（命中判定开销小但误触率高反而二次点击）。
- 快速点击的边界：连续点击（双击缩放判定）在 touch-action: manipulation 下不再有 300ms 等待；按钮防抖与响应性平衡（防重复提交用幂等 token 而不是简单禁用 500ms，禁用会让用户觉得卡）。

```javascript

// 触摸响应分段测量 + 即时反馈优化
function touchLatencyProbe(el) {
  let t0;
  el.addEventListener('touchstart', () => { t0 = performance.now(); }, { passive: true });
  el.addEventListener('touchend', () => {
    const dispatch = performance.now() - t0;                    // 事件派发耗时
    requestAnimationFrame(() => requestAnimationFrame(() => {
      const total = performance.now() - t0;                     // 到绘制完成
      if (total > 100) report('touch-slow', { el: el.tagName, dispatchMs: +dispatch.toFixed(1),
        totalMs: +total.toFixed(1) });
    }));
  }, { passive: true });
}
// 即时反馈三板斧：
// 1) CSS :active 高亮（合成器响应，主线程阻塞也有效）
// .btn:active { opacity: .7; }
// 2) handler 只做状态标记，重逻辑 idle 延后
function onTap() {
  renderFeedback();                                             // 同步轻反馈 <5ms
  requestIdleCallback(() => doHeavyWork());                     // 重逻辑延后
}
// 3) 防重复提交用幂等 token，不用 500ms 禁用（禁用伤响应感）
```
