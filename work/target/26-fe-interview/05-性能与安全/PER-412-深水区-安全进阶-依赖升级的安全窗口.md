## PER-412：依赖升级的安全窗口：补丁如何快速落地而不破坏稳定性？

**答**:
- 张力：安全补丁要求"尽快升级"，稳定要求"不能破坏线上"。解法是分级响应——按 CVE 严重级定升级窗口与流程：Critical（24h 内，可跳过常规评审走紧急通道）；High（1 周）；Medium/Low（随例行升级窗口）。
- 紧急通道流程：lockfile 最小 diff 升级（只动受影响包及其必要依赖，不捎带其他更新）→ 自动化回归（构建 + 冒烟测试 + 性能基准 diff）→ 灰度 10% → 全量。整个链路预演过、工具化（一条命令出升级 PR + 回归报告）。
- 兼容性风险控制：补丁版本（patch）低风险直接升；跨大版本的 CVE 修复（需要升 major）评估"是否可用 fork/patch-package 临时止血"——临时补丁要带过期时间，转正或回归正式升级。
- 制度：升级窗口写进安全基线（PER-364 巡检检查"高危依赖存在时长"）；Renovate/Dependabot 自动 PR + 自动回归，人工只审异常。

```text
CVE 分级响应窗口：
Critical（可远程利用/涉登录态）：24h 内紧急通道 —— lockfile 最小 diff + 冒烟 + 灰度 10% → 全量
High：1 周内随常规窗口
Medium/Low：月度例行升级
跨 major 的 CVE：评估 patch-package 临时止血（带 30 天过期标记）→ 排期正式升级
工具化：Renovate 自动 PR + CI 自动回归（构建/冒烟/性能基准 diff）——人工只审异常
巡检项：高危依赖存在时长 > 窗口 = 违规（PER-364）
```
