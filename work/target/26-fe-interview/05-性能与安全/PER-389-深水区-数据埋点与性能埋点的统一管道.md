## PER-389：业务埋点与性能埋点如何统一管道？

**答**:
- 统一的价值：一条通道（队列/批量/重试/采样/上报协议）服务两类数据——减少重复代码与请求数、共享限流与丢数策略；性能埋点还能借用业务埋点的维度（AB 实验分组、用户 cohort）做交叉分析。
- 管道分层：采集层（业务 tracker 与 perf tracker 各自产出标准化事件，schema 统一：{type, name, value, dims, ts}）→ 缓冲层（同一队列，按 type 分优先级——性能指标优先级高于业务埋点，超限时先丢埋点）→ 上报层（批量 sendBeacon，PER-252）→ 路由层（服务端按 type 分流到性能库与业务库）。
- 互不拖累的设计：优先级丢弃（性能保尾部样本 PER-243 的规则，业务埋点允许丢中间）；通道级限流（整站上报 QPS 上限，防大促埋点洪峰拖垮性能数据）；schema 演进向后兼容。
- 度量：通道丢数率按 type 分开监控；性能数据完整性（采样后会话覆盖率）有专门 SLO。

```javascript
// 统一管道：优先级缓冲
class TelemetryChannel {
  constructor() { this.buf = { perf: [], biz: [] }; }
  push(type, event) {                       // type: 'perf' | 'biz'
    (this.buf[type] ??= []).push(event);
    if (this.total() >= 30) this.flush();
  }
  flush() {
    let batch = [...this.buf.perf];         // 性能优先全保（尾部样本不能丢）
    const room = 30 - batch.length;
    if (room > 0) batch = batch.concat(this.buf.biz.slice(0, room));   // 埋点截断
    this.buf = { perf: [], biz: [] };
    navigator.sendBeacon?.('/telemetry', JSON.stringify(batch));
  }
  total() { return this.buf.perf.length + this.buf.biz.length; }
}
// 服务端按 type 路由：perf → 性能库（分位数聚合），biz → 业务库（漏斗/留存）
// 超限时丢 biz 保 perf —— 性能数据的完整性 SLO 独立考核
```
