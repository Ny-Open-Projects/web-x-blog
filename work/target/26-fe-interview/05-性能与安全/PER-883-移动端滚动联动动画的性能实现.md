## PER-883：移动端滚动联动动画的性能实现：滚动驱动动画的正确姿势与替代方案

**答**：
- 错误做法：scroll 事件里直接改样式（每帧重排重绘、且 scroll 回调频率不稳定）。
- 正确姿势一：CSS scroll-driven animations（animation-timeline: scroll()），纯合成器线程驱动，零 JS；姿势二：IntersectionObserver 触发一次性动画（进入视口才动）；姿势三：必须 JS 时 rAF 内读 scrollY 一次、全部写 transform（读写分离，避免强制同步布局）。
- 低端机替代：视差/跟随类动画低端机直接关闭或降为静态（滚动是第一优先，动画让路）。
- 度量：动画开启时滚动 FPS 对比（开关动画各测一次），FPS 下降 > 5 即认为该动画过重，触发降级。

```javascript
// 姿势一：CSS 滚动驱动（现代浏览器零 JS）
const cssScrollAnim = `
.progress {
  transform-origin: 0 50%;
  animation: grow linear;
  animation-timeline: scroll(root);
}
@keyframes grow { from { transform: scaleX(0); } to { transform: scaleX(1); } }`;
// 姿势三：JS 兜底（读写分离 + transform）
let ticking = false;
addEventListener('scroll', () => {
  if (ticking) return;
  ticking = true;
  requestAnimationFrame(() => {
    const y = scrollY;                       // 读一次
    bar.style.transform = `scaleX(${Math.min(y / docHeight(), 1)})`;   // 只写 transform
    ticking = false;
  });
}, { passive: true });
// 低端机降级
if (deviceTier === 'low') bar.style.display = 'none';
```
