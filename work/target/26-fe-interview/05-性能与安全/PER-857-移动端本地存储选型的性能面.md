## PER-857：移动端本地存储选型的性能面：localStorage、IndexedDB、SQLite 的读写量级与场景

**答**：
- 量级认知：localStorage 同步阻塞（>100KB 读写就有感知，上限 ~5MB）；IndexedDB 异步、容量大（可达数百 MB~GB），但 API 繁琐、事务开销明显（单次写 ~5-20ms）；容器内 SQLite（桥）适合结构化查询、量大（万条级查询 < 50ms）。
- 场景映射：小配置/开关 → localStorage；列表/日志/缓存数据 → IndexedDB；复杂查询/聚合/多条件筛选 → SQLite（或干脆服务端查询）。
- 共同坑：主线程 IDB 大事务也会卡（大数据写分批）；localStorage 在 WebView 多实例下同步问题；iOS 隐私模式（低电量/无痕）存储禁用要有 try/catch 降级。
- 度量：先跑存储基准（批量写/读/查询耗时）再定方案，不凭感觉选型。

```javascript
const storageChoice = {
  small: { api: 'localStorage', limit: '< 100KB，同步阻塞注意', case: '配置项/开关' },
  medium: { api: 'IndexedDB', limit: 'MB 级，异步', case: '列表缓存/日志/离线数据',
    pitfall: '大事务分批写（每批 < 1MB）' },
  large: { api: 'SQLite(bridge)', limit: '万条级', case: '复杂查询/聚合',
    pitfall: '桥通信成本，批量结果回传' },
};
// IDB 分批写防长任务
async function idbBulkWrite(store, items, { batch = 200 } = {}) {
  for (let i = 0; i < items.length; i += batch) {
    const tx = store.transaction(store.name, 'readwrite');
    items.slice(i, i + batch).forEach(it => tx.objectStore(store.name).put(it));
    await done(tx);
    await new Promise(r => setTimeout(r));     // 批间让出主线程
  }
}
// 降级：隐私模式存储禁用
function safeSet(k, v) { try { localStorage.setItem(k, v); return true; } catch { return memoryFallback(k, v); } }
```
