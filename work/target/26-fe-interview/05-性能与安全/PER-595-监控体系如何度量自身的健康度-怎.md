## PER-595：监控体系如何度量自身的健康度？怎么监控监控本身？

**答**：
- 监控的自监控四指标：**采集可用性**（上报接口成功率、SDK 加载成功率）、**数据时效**（采集到可见的延迟 p95）、**告警质量**（误报率/漏报复盘数）、**覆盖度**（核心页面的 SDK 覆盖率、关键指标空窗数）。
- 实现方式：旁路探测（拨测脚本定时打开核心页面验证指标产出）、心跳信号（每分钟一条心跳数据，心跳断流本身触发告警）、SDK 自身错误自捕获（采集器崩了要能被发现）。
- 典型故障模式：SDK 版本升级后静默失效（新浏览器兼容问题）、存储写满采集静默丢数据、告警通道（IM bot）token 过期没人发消息——每种都要有对应探测。
- 价值：监控体系自己的 SLO（如数据延迟 p95 < 1 分钟"）与错误预算，用同一套燃烧率逻辑管理自己。

```javascript

const metaMonitoring = {
  probes: [
    { kind: 'synthetic', run: '每 5min 拨测核心页，断言 vitals 上报成功' },
    { kind: 'heartbeat', run: '每分钟心跳数据，断流 3min 即告警' },  // 监控断流=监控挂了
    { kind: 'sdk-self', run: '采集器 try/catch 自捕获，错误走备用通道' },
    { kind: 'channel', run: 'IM bot 每天 9 点自测发消息' },           // 防 token 过期
  ],
  selfSlo: { ingestDelayP95: '60s', reportSuccessRate: 0.995, alertFalseRate: 0.3 },
  rule: '心跳断流与拨测失败都视为监控自身事故，用同一套燃烧率治理',
};
console.log(metaMonitoring.rule);
```
