## PER-599：告警规则怎么管理才不会腐化？规则漂移、僵尸告警、口径变更的治理机制是什么？

**答**：
- 僵尸告警识别：连续 90 天零触发或零处理（触发后无人认领）的规则进下线评审——告警是资产也是负债，规则数量要预算制（每团队 page 规则上限）。
- 规则即代码：告警规则进仓库（YAML），变更走 PR 评审 + 版本化，谁改的、为什么改、预期影响可追溯；与控制台手改互斥（控制台改动会被 CI 对账打回）。
- 口径变更管理：指标口径变更 = 破坏性变更，要兼容期双跑（新老口径并行两周）+ 看板标注切换点 + 基线重算，否则历史曲线突然跳变引发大量误判。
- 定期审计：季度告警审计（触发分布、处理时长、误报率），输出下线/合并/保留清单——告警治理是持续工程不是一次性项目。

```javascript

// alert-rule.yaml 的治理字段与审计脚本
const ruleSpec = {
  id: 'lcp-p75-burn',
  owner: 'fe-platform',          // 必填：无 owner 的规则不能存在
  level: 'page',
  expr: 'burnRate(fast5) > 14.4 AND burnRate(slow60) > 14.4',
  runbook: 'runbooks/lcp.md',    // 必填：page 必须有手册
  audit: {                       // 审计脚本每周计算
    fired: 12, acked: 12, falsePositive: 2,
  },
  policy: {
    zombie: '90 天零触发或零处理 -> 下线评审',
    budget: '每团队 page 规则 <= 10 条',
    change: 'PR 评审 + 版本化；控制台手改被 CI 对账打回',
    metricChange: '口径变更双跑两周 + 看板标注切换点',
  },
};
const zombie = ruleSpec.audit.fired === 0;   // -> 进季度审计下线清单
```
