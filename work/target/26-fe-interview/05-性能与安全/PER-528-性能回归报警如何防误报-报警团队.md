## PER-528：性能回归报警如何防误报？报警团队每天收到 20 条假警报后会发生什么？

**答**：
- 误报三大来源与对策：环境噪声（用对照页/中位数/多次采样过滤）、时段效应（错峰比较，同环比只在相同时段比）、数据断层（发版回滚、数据回填导致的假尖刺，用邻域连续性校验）。
- 防误报设计：报警必须带**证据链**——当前值、基线、偏离幅度、相关变更（发版/配置/依赖升级），让接警人 30 秒内判断真假；没有变更关联的性能报警优先降级为"观察"。
- 阈值策略：静态阈值只守红线，动态基线（过去 7 天同时段 p95）守回归，双条件都满足才 page，避免单条件误触。
- 狼来了效应：假警报率高的团队会形成"报警疲劳"，真事故被淹没；宁可少报漏报日常小抖动，也要保证 page 类报警的可信度。

```javascript

function perfAlert(cur, base, ctx) {
  const deviated = cur.lcpP75 > base.p95SameHour * 1.15;     // 条件1: 超动态基线
  const hasCause = ctx.deploy || ctx.configChange || ctx.depUpgrade; // 条件2: 有变更佐证
  if (deviated && hasCause) return { level: 'page', evidence: {
    cur: cur.lcpP75, baseline: base.p95SameHour,
    change: ctx.deploy ? `发版 ${ctx.deploy.version}` : ctx.configChange || ctx.depUpgrade,
    ctrlPageDelta: ctx.ctrlPageDelta,                         // 对照页是否同步恶化
  }};
  if (deviated && !hasCause && ctx.ctrlPageDelta > 0.1) return {
    level: 'page', evidence: { note: '对照页同步恶化 -> 环境问题，转基础设施' }};
  return { level: 'observe', note: '偏离但无变更佐证，观察下一窗口' }; // 降级不 page
}
```
