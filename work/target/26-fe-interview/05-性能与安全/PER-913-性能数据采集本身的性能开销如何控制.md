## PER-913：性能数据采集本身的性能开销如何控制

**答**：
- SDK 自身预算：体积 < 10KB gzip、初始化 < 5ms、运行期 CPU < 1%，超预算即架构问题。
- 采集策略：Metrics API（PerformanceObserver）被动监听而非轮询；长任务/资源记录用 buffered + entryTypes 精确订阅。
- 上报开销控制：批量（30 条或 5s 触发）、压缩（pako/protobuf）、sendBeacon/fetch keepalive、页面隐藏时 flush、失败静默丢弃不重试阻塞。
- 避免观察者反噬：不要为每个节点挂 MutationObserver；采样率按流量调；SDK 延迟到 idle 初始化（首屏指标用 buffered 补采）。

```javascript
// 低开销采集骨架
const queue = [], MAX = 30;
function flush() {
  if (!queue.length) return;
  navigator.sendBeacon('/rum', JSON.stringify(queue));
  queue.length = 0;
}
function track(entry) {
  queue.push({ t: entry.entryType, s: entry.startTime, d: entry.duration, n: entry.name });
  if (queue.length >= MAX) flush();
}
new PerformanceObserver(list => list.getEntries().forEach(track))
  .observe({ type: 'longtask', buffered: true });
document.addEventListener('visibilitychange', () =>
  document.visibilityState === 'hidden' && flush());
```
