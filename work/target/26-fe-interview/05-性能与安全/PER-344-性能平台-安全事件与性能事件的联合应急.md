## PER-344：性能劣化与安全事件有时是同一根因，联合应急响应流程怎么设计？

**答**：
- 同根因场景盘点：三方脚本被入侵（既慢又可能注入——LoAF 阻塞排行突变 + CSP report 异常同时出现）；CDN 故障（TTFB 飙升 + SRI 失败率上升）；依赖升级投毒（构建变慢/体积异常 + 供应链审计告警）；爬虫/攻击流量（接口延迟 + WAF 日志）。两个监控域的信号交叉时优先按安全事件处理。
- 联合流程：统一事件分级（P0~P3）；性能 oncall 发现"异常归因到外部资源"时立即拉安全 oncall 联判；共享取证时间轴（LoAF invoker、CSP report、CDN 日志、WAF 日志同一视图）。
- 止血优先级：安全止血优先于性能止血（下线可疑资源 → 恢复正常 → 再优化性能）；止血动作预置化——一键下线某三方脚本、CDN 切备用、回滚到上一个 manifest。
- 复盘联合化：性能复盘与安全复盘合开（同根因只复一次盘），产出双清单（性能修复项 + 安全加固项），互相交叉验证。

```text
联合应急决策树：
性能突变告警 → 归因（LoAF/Resource Timing/CDN）
  ├─ 归因到外部资源/新增三方 → 拉安全 oncall（5min 内）
  │     ├─ CSP report 异常 / 未知域 → 按安全事件处理：下线资源 + CDN 切换 + 账号审计
  │     └─ 确认良性（供应商发版）→ 走性能流程：facade/延迟加载 + 沟通供应商
  └─ 归因到自有代码 → 性能流程：版本 diff → 回滚/修复
预置一键止血：下线三方脚本开关、CDN 备源切换、回滚 manifest（演练每季度）
```
