## PER-847：万级节点与百兆数据在低端机上的极限场景优化：可行方案与取舍

**答**：
- 万级 DOM 节点：唯一可行路径是"不渲染看不见的"——虚拟列表（节点数恒定几百）+ 分步挂载 + Web Worker 预处理；任何"直接渲染万节点再优化"的路线在低端机都失败。
- 百兆数据：永不全量进内存/主线程——分片下载（Range 请求）+ Worker 流式解析 + IndexedDB 落盘 + 按需读取窗口；聚合统计（求和/过滤）尽量在 Worker/服务端做。
- 取舍原则：功能完整性与体验完整性冲突时，低端机取"可用性"（先保证核心流程 30fps 可完成）；砍掉的是边缘功能而非核心功能的质量。
- 验收方式：容量压测找拐点（多少行开始掉帧、多大文件开始 OOM），以拐点为容量红线，超出红线的产品需求要拆分或分页。

```javascript
// 极限场景三板斧：虚拟化 + Worker 分片 + 按需窗口
async function loadHugeDataset(url, { chunkMB = 2, onProgress } = {}) {
  const total = await headContentLength(url);
  let offset = 0;
  while (offset < total) {
    const end = Math.min(offset + chunkMB * 1048576, total) - 1;
    const buf = await fetch(url, { headers: { Range: `bytes=${offset}-${end}` } }).then(r => r.arrayBuffer());
    offset = end + 1;
    await idbAppend('huge', buf);              // 落盘不占内存
    onProgress && onProgress(offset / total);
    await new Promise(r => requestIdleCallback(r));   // 让出主线程
  }
  return { readWindow: (start, n) => idbRead('huge', start, n) };   // 按需读取
}
// Worker 内做聚合，主线程只拿结果
worker.postMessage({ op: 'sum', range: [0, 100000] });
```
