## PER-328：弱网下接口超时与重试怎么设计才不雪崩？超时预算与退避矩阵？

**答**：
- 超时分层：连接超时（5~10s，弱网 RTT 大）、响应超时（关键接口 8s、普通 15s）、总预算（一次用户操作内所有重试的总耗时上限，如 20s——超了直接给用户失败反馈，别无限转圈）。
- 重试纪律：只重试幂等请求（GET/幂等写）；指数退避 + 抖动（HW-063）；**重试次数 ≤ 2**，弱网下重试风暴只会更堵；AbortController 让新请求取消旧请求（搜索场景）。
- 防雪崩：全局并发重试上限（所有接口同时最多 N 个重试在途）；熔断——连续失败达阈值后直接快速失败 30s（不让用户等超时），期间读缓存兜底。
- 用户体验配套：失败要有明确状态与重试按钮（不是静默失败）；关键路径失败降级到缓存数据（stale 也可用）；超时文案区分"网络慢"与"服务异常"。

```javascript
class WeakNetFetcher {
  constructor({ rtBudget = 20000 } = {}) { this.rtBudget = rtBudget; this.retrying = 0; this.maxRetryConc = 4; }
  async fetch(url, { timeout = 8000, retries = 2 } = {}) {
    const deadline = performance.now() + this.rtBudget;   // 总预算
    for (let i = 0; i <= retries; i++) {
      const left = deadline - performance.now();
      if (left <= 0) throw new Error('总超时');            // 预算耗尽：快速失败
      const ctrl = new AbortController();
      const timer = setTimeout(() => ctrl.abort(), Math.min(timeout, left));
      try {
        const res = await fetch(url, { signal: ctrl.signal });
        clearTimeout(timer);
        if (res.ok) return res;
        if (i === retries || ![429, 500, 502, 503].includes(res.status)) throw new Error(String(res.status));
      } catch (e) { clearTimeout(timer);
        if (i === retries) throw e; }
      // 退避 + 抖动 + 全局重试并发上限
      while (this.retrying >= this.maxRetryConc) await sleep(200);
      this.retrying++;
      try { await sleep(500 * 2 ** i * (0.5 + Math.random() / 2)); } finally { this.retrying--; }
    }
  }
}
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
```
