## PER-869：移动端图片手势（捏合缩放）的性能：缩放渲染策略、清晰度切换与内存控制

**答**：
- 缩放性能核心：缩放过程用 transform（GPU 合成，零重排），绝对不要缩放过程中改 img 的 width/height（逐帧重排必然卡）。
- 清晰度切换：缩放时先用当前档位图拉伸（模糊但流畅），缩放稳定（手势结束/超过阈值）后异步换高清晰度档位图——流畅优先于清晰，避免缩放中解码大图。
- 内存控制：多图缩放页同时只允许一张图处于高清解码态；缩略图用 CSS transform 即可，高清原图仅在稳定放大 > 2x 时加载并限制解码尺寸。
- 边界细节：双指捏合锚点计算（以两指中点为缩放中心）、缩放范围限制（0.5~4x）、与页面滚动冲突（放大态下禁用页面滚动）。

```javascript
class PinchZoom {
  constructor(img, { min = 0.5, max = 4 } = {}) {
    this.scale = 1; this.img = img; this.min = min; this.max = max;
    this.hdLoaded = false;
  }
  onPinch(dist0, dist1, cx, cy) {                              // 双指
    const next = clamp(this.scale * (dist1 / dist0), this.min, this.max);
    this.img.style.transform =                                 // transform 缩放零重排
      `translate(${cx}px, ${cy}px) scale(${next})`;
    this.scale = next;
    if (next > 2 && !this.hdLoaded) this.loadHD();             // > 2x 换高清
  }
  async loadHD() {
    const src = hdUrl(this.img.src);                           // 高清档
    const bitmap = await decodeLimited(src, 2048);             // 限制解码尺寸
    if (this.scale > 1.5) { this.img.src = src; this.hdLoaded = true; }   // 仍放大态才替换
    else bitmap.close();                                       // 已缩回：释放解码内存
  }
  end() { this.commit(); }                                     // 手势结束固化
}
```
