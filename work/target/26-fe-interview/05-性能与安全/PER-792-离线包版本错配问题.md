## PER-792：离线包版本错配问题：页面版本与包版本不一致时的兼容与降级策略

**答**：
- 错配来源：页面 H5 版本新（引用了新文件）但本地离线包还旧；或包新但页面 JS 还旧（引用旧文件名）——hash 命名下都会 miss。
- 防御一：页面不硬编码文件名，统一走版本接口（页面启动时拉 manifest，按 manifest 解析资源 URL），页面与包永远以 manifest 为准。
- 防御二：兼容窗口——发新包时旧包保留 2~3 个版本（灰度期新旧页面共存），映射表同时保留新旧 URL 条目。
- 降级链：manifest 请求失败 → 用上次缓存的 manifest；URL miss → 回源在线加载；回源也失败 → 错误页带重试。错配率要作为离线包健康度指标单独监控。

```javascript
async function loadWithVersionGuard(pageVersion) {
  let manifest;
  try {
    manifest = await fetchLatestManifest(pageVersion);         // 1. 以 manifest 为准
  } catch {
    manifest = readCachedManifest();                            // 2. 失败用缓存版本
    if (!manifest) return renderErrorPage('no-manifest');       // 3. 连 manifest 都没有
  }
  if (!compat(pageVersion, manifest.minPageVersion)) {          // 4. 版本区间校验
    return fallbackOnline();                                    //    错配 → 整页在线
  }
  const urls = resolveAssets(manifest);                         // 5. 按映射表解析
  return urls.map(u => OFFLINE_MAP.resolve(u) ?? u);            //    miss 项回源
}
```
