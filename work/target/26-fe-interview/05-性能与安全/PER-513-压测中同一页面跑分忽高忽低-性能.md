## PER-513：压测中同一页面跑分忽高忽低（性能抖动），如何识别噪声来源并让数据可信？

**答**：
- 抖动来源排查顺序：测试机自身（后台进程、 thermal 降频）→ 网络抖动（CDN 边缘切换、DNS 漂移）→ 数据漂移（缓存命中率、后端波动）→ 页面本身随机性（A/B、广告位、个性化文案）。
- 识别手段：对照组页面法——拿一个不改动的历史稳定页同批采样，若对照组也抖，说明是环境噪声而非被测页回归；再用方差/变异系数量化，CV > 10% 的批次作废重跑。
- 收敛手段：增加采样次数取中位数、固定时段跑（避开业务高峰）、关掉页面随机性（mock 广告与 ABSDK）、浏览器预热一轮丢弃首跑。
- 原则：**先让环境稳定，再谈指标好坏**；带噪声做优化对比是性能测试最常见的事故。

```javascript

function qc(samples, { cvLimit = 0.10 } = {}) {
  const a = samples.filter(Number.isFinite);
  const mean = a.reduce((s, v) => s + v, 0) / a.length;
  const sd = Math.sqrt(a.reduce((s, v) => s + (v - mean) ** 2, 0) / a.length);
  const cv = sd / mean;                          // 变异系数：噪声量化
  return {
    cv: +(cv * 100).toFixed(1) + '%',
    verdict: cv > cvLimit ? '批次噪声过大，作废重跑' : '可信',
    advice: cv > cvLimit ? '检查对照组是否同抖 / 加采样 / 固定时段 / 丢弃首跑' : '',
  };
}
// 对照组：稳定历史页与被测页同批跑，对照页 CV 也超标 -> 环境问题，不是页面回归
console.log(qc([2100, 2300, 2150, 3300, 2200]));
```
