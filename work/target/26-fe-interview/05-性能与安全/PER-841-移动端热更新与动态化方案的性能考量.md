## PER-841：移动端热更新与动态化方案的性能考量：bundle 大小、增量与容灾

**答**：
- 动态化（RN bundle 热更/小程序整包更新/自渲染 DSL）的性能三问：包多大（首启下载时间）、增量怎么做（diff patch 省流量）、失败怎么办（回退上一个可用版本）。
- bundle 体积治理：按业务模块拆 bundle（按需下发）、公共依赖抽离（基础包）、字节码/压缩产物下发；体积预算纳入 CI 门禁（超预算阻断合并）。
- 增量策略：模块级 diff（对比模块 hash，只下发变化模块）优于文件级整包；patch 应用要原子（失败保留旧版本可用）。
- 容灾铁律：本地永远保留"上一个验证可用"的版本；新版本启动失败（加载超时/初始化异常）自动回退旧版并上报——用户看到的永远是可用页面，而不是白屏。

```javascript
const hotUpdater = {
  async update(manifest) {
    const cur = readLocalVersion();
    const patch = diffModules(cur.modules, manifest.modules);   // 模块级 diff
    try {
      const files = await download(patch.changed, { timeout: 30000 });
      verifyHashes(files, manifest);                            // 原子校验
      stageNew(files, manifest.version);                        // 先暂存不启用
    } catch (e) { return report('update-fail', { v: manifest.version, msg: String(e) }); }
  },
  boot() {
    const staged = readStaged();
    if (staged) {
      try { bootWith(staged); markGood(staged.version); return; }
      catch (e) { rollback(); report('boot-fail-rollback', { v: staged.version }); }  // 自动回退
    }
    bootWith(readGoodVersion());                                // 兜底：上一个可用版
  },
};
```
