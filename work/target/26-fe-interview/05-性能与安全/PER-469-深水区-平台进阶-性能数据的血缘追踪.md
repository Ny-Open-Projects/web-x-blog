## PER-469：一个看板数字的血缘如何回溯？

**答**:
- 血缘链：浏览器采样 → SDK 计算（口径 A）→ 上报 schema → 接入层清洗（规则 B）→ 聚合任务（分桶 C + 窗口 D）→ 宽表 → 看板查询（维度 E）——任何环节变更都会改变数字。血缘追踪 = 每环节记录"变换规则版本"，数字可回溯到完整变换链。
- 实现：① 数据带版本戳（sdkVersion/cleanRuleVersion/aggVersion，PER-435）；② 变换规则代码化（清洗/聚合逻辑进 Git，PER-335 口径即代码）；③ 看板查询透出元信息（悬停数字显示：采集口径/清洗版本/聚合窗口/样本数）——"这个数字怎么来的"三秒可答。
- 口径争议流程：争议 → 血缘定位分歧环节 → 规则评审 → 修正版本化 → 历史标注（PER-455）。血缘齐备时争议从"扯皮半天"变"定位十分钟"。
- 治理：血缘完整性进平台健康度（覆盖率 < 100% 的指标标"血统不明"，不进 SLO 判定）。

```text
指标数据血缘链：
采样 → SDK 计算(A) → 上报 schema → 清洗(B) → 聚合(C桶+D窗) → 宽表 → 查询(E维度)
实现：每环节版本戳（sdkVer/cleanVer/aggVer）+ 规则代码化（Git）

治理：血缘覆盖率 < 100% 的指标不进 SLO 判定
```
