## PER-560：监控指标体系怎么分层？北极星/过程/诊断指标各自解决什么问题？

**答**：
- 三层结构：**北极星指标**（LCP p75/INP p75/JS 错误率）是给管理层的体检结论，数量少、口径稳、与业务体验强相关；**过程指标**（TTFB、资源耗时、接口耗时分布）是定位用的中间量；**诊断指标**（某个接口的 p99、某 chunk 的体积）是排障时的下钻细节。
- 分层的意义在于告警与看板分工：北极星进值班群、有 page 告警；过程指标进周报表；诊断指标只在排障时查询——全都进告警群的结果是告警疲劳。
- 指标定义要写口径文档：分子分母、采样方式、剔除规则（爬虫/自动化测试流量）、变更流程，口径漂移是监控体系烂掉的开始。
- 健康度自检：北极星指标能不能回答用户体验变好还是变坏了这个问题？答不了说明选错了指标。

```javascript

const metricHierarchy = {
  northStar: {  // 北极星：进值班告警
    lcpP75: { target: 2500, alert: 'burnRate' }, inpP75: { target: 200 }, jsErrorRate: { target: 0.01 },
  },
  process: {    // 过程指标：周报与趋势
    ttfbP75: true, resourceTotalKB: true, apiP75ByRoute: true,
  },
  diagnostic: { // 诊断指标：排障时按需查询
    apiP99ByEndpoint: true, chunkSizeByRoute: true, longTaskTopUrls: true,
  },
  rule: '北极星进告警、过程进报表、诊断只在排障时查，口径文档化并有变更评审',
};
console.log(metricHierarchy.rule);
```
