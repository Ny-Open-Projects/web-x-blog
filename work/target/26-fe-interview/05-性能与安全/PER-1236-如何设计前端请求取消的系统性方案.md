## PER-1236：如何设计"前端请求取消"的系统性方案

**答**：
- 场景：路由切换后旧请求还在跑（浪费+状态错乱）、输入联想旧结果覆盖新结果。
- 方案：AbortController 体系——路由级取消（切路由取消未完成请求）、查询级取消（新查询取消旧查询）、组件级取消（unmount 取消）。
- 封装：请求层持有 cancelMap（按 scope 分组），scope 销毁即 abort；fetch 层支持 signal 透传。
- 验证：E2E 断言切换后无旧请求落地（服务端日志/拦截器计数）。

```javascript
// 分 scope 的取消管理
class CancelGroup {
  constructor() { this.controllers = new Set(); }
  signal() {
    const c = new AbortController();
    this.controllers.add(c);
    c.signal.addEventListener('abort', () => this.controllers.delete(c));
    return c.signal;
  }
  abortAll() { for (const c of this.controllers) c.abort();
    this.controllers.clear(); }
}
const routeCancel = new CancelGroup();
router.beforeEach(() => routeCancel.abortAll());   // 切路由全取消
function api(url, init) { return fetch(url,
  { ...init, signal: routeCancel.signal() }); }
// 联想场景：
let seq = 0;
async function suggest(q) {
  const c = new AbortController();
  seqCancel?.abort(); seqCancel = c;
  return fetch(`/suggest?q=${q}`, { signal: c.signal });
}
```
