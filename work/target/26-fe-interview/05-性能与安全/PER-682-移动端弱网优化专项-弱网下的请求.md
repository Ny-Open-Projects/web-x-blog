## PER-682：移动端弱网优化专项：弱网下的请求策略、界面降级与数据同步怎么做？

**答**：
- 弱网识别：navigator.connection（effectiveType/rtt/downlink）+ 实测 RTT（关键接口计时）双信号，判定后切换策略档位——识别要动态（进出电梯/地库网络突变）。
- 请求策略：弱网下并发减半、超时缩短+快速失败、禁预加载、关键接口用 HTTP/3 或 QUIC（弱网抗丢包）、图片请求低清档、接口合并（多次小请求并成一个批量接口减少 RTT）。
- 界面降级：骨架屏常驻、图片占位图、非核心模块折叠、文案提示当前网络弱"；断网态（离线缓存 + 乐观更新 + 恢复后同步）。
- 数据同步：写操作进本地队列（幂等 id），网络恢复按序重放，冲突以服务端为准 + 用户提示——弱网优化的本质是让用户始终有可控预期。

```javascript

const weakNetPolicy = {
  detect: { signal: 'connection.effectiveType + 实测 RTT', switch: '动态判定，网络突变即切档' },
  request: { concurrency: '弱网减半', timeout: '缩短+快速失败', preload: '禁用',
    quic: '关键接口走 HTTP/3', merge: '小请求合并为批量接口' },
  ui: { skeleton: '常驻', image: '低清档占位', modules: '非核心折叠', offline: '离线缓存+乐观更新' },
  sync: {
    queue: '写操作带幂等 id 进本地队列',
    replay: '网络恢复按序重放',
    conflict: '以服务端为准 + 用户提示',
  },
  essence: '弱网优化的本质：让用户始终有可控预期，而不是追求快',
};
console.log(weakNetPolicy.essence);
```
