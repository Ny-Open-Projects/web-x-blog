## PER-526：真机测试和模拟器测试在移动端性能上有哪些系统差异？什么时候必须真机？

**答**：
- 系统差异五类：CPU/GPU 真实降频与 thermal 限频、真实内存压力（后台 App 挤压导致更频繁 GC/回收）、真实 GPU 光栅化（模拟器可能走软渲染）、真实网络基带功耗、WebView/浏览器内核版本差异——模拟器只能近似前两项的组合。
- 必须真机的场景：动画掉帧判定（GPU 光栅化差异会让模拟器误判）、内存告警与崩溃复现、thermal 场景（连续操作 10 分钟后的降频性能）、低端真机的 LCP 长尾。
- 模拟器定位：开发期快速粗筛与回归 diff（同环境可比），真机定位：验收测试与长尾摸底；两者结论都要写明"哪类环境"。
- 经验法则：模拟器跑分好看 ≠ 真机可用，差 2~3 倍很正常；真机矩阵至少覆盖发布机型的下限档。

```javascript

// 真机跑分页面：性能探针 + 结果回传，替代"肉眼看流畅"
const probe = {
  fps: (() => { let last = performance.now(), frames = 0, worst = 0;
    const loop = t => { frames++; const gap = t - last; last = t;
      if (gap > 50) worst = Math.max(worst, gap); // 掉帧最大间隙
      requestAnimationFrame(loop); };
    requestAnimationFrame(loop); return () => ({ frames, worst }); })(),
  memory: () => performance.memory ? +(performance.memory.usedJSHeapSize / 1048576).toFixed(1) : null,
  thermalNote: () => navigator.deviceMemory ?? 'n/a', // 低端档标记
};
// 交互 10 分钟后导出：window.__fps = probe.fps(); sendBeacon 回传统计
// 真机关键看 worst gap（最大掉帧间隙）与 usedJSHeapSize 增长曲线（是否持续上涨不回落）
```
