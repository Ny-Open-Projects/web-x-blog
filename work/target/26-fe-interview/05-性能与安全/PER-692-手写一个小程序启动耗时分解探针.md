## PER-692：手写一个小程序启动耗时分解探针：从冷启动到首页渲染的分段统计与瓶颈定位

**答**：
- 分段：进程创建（Native 侧 ts）-> 逻辑层启动（App onLaunch）-> 首页分包加载完成 -> 页面 onLoad -> 首屏 onReady；前端侧在 App/Page 生命周期打点，与 Native 的启动时间戳（启动参数注入）对齐。
- 要点：onLaunch 里的同步操作（getSystemInfo/初始化 SDK）是常见瓶颈——分段后每个生命周期耗时单独上报；冷启动与热启动分开（是否进程存活）。
- 边界：onReady 表示首次渲染完成不代表可交互，加首屏接口完成标记；低端机分档阈值。
- 评分点：生命周期级分段与冷热分离。

```javascript

// app.js
App({
  onLaunch(opts) {
    this.t0 = opts.query?.__nativeStart ?? Date.now();           // Native 注入启动时间戳
    this.cold = !getApp()?.__launched;                           // 冷热分离
    mark('launch');
    initSyncMinimal();                                           // 同步操作最小化
    mark('launch-done');
  },
});
// pages/home/index.js
Page({
  onLoad() { mark('home-onload'); },
  onReady() {
    mark('home-ready');
    flushStages({
      stages: ['launch', 'launch-done', 'home-onload', 'home-ready', 'first-api-done'],
      cold: this.getCold(), tier: deviceTier(),                  // 分档上报
    });
  },
});
// mark 实现：performance.mark + 最终 measure 出各段耗时
// 定位：launch->launch-done 耗时大 = onLaunch 同步操作过重；onload->ready 大 = 首页渲染重
```
