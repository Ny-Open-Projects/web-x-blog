## PER-339：性能预算如何落地到 CI 与团队流程？谁定预算、谁守预算？

**答**：
- 预算三种类别：数量预算（JS 总量 gzip、请求数、三方脚本数）、时间预算（LCP/TBT/INP 实验室代理）、比率预算（图片/字体占总传输比）。每类给核心页面模板建档，预算值来自"当前 p75 × 1.1"或竞品对标，不是拍脑袋。
- CI 落地：构建产物体积 diff 卡口（超预算 5% 拦、超 10% 必须附带优化方案 PR）；Lighthouse CI 时间预算（TBT/LCP）对 PR 基线对比；预算文件版本化进仓库（budgets.json），改动要评审——**预算本身也是被治理的资产**。
- 守预算的分工：平台团队守工具（卡口准确性、误拦率）；业务团队守自己的页面预算（PR 里超了谁改谁修）；架构组守全局预算（总量、三方数）。
- 预算调整机制：季度评审——预算不是一成不变（新功能合理增重可申请），但要"先还债再加杠杆"（超预算的页面必须先还到预算内才允许新功能增重）。

```json
// budgets.json（CI 消费）
{
  "pages": {
    "/goods/:id": {
      "resourceSizes": [
        { "resourceType": "script", "budget": 180 },     // KB gzip
        { "resourceType": "image",  "budget": 300 },
        { "resourceType": "third-party", "budget": 50 }
      ],
      "timings": [ { "metric": "TBT", "budget": 200 }, { "metric": "LCP", "budget": 2500 } ],
      "counts": [ { "metric": "third-party-requests", "budget": 6 } ]
    }
  }
}
// CI 逻辑：lhci autorun --budgets=budgets.json
// 超预算 5%：警告注释到 PR；超 10%：block merge（可申请豁免标签 perf-exception，48h 有效）
```
