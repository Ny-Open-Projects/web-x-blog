## PER-503：性能测试与功能测试有什么本质区别？性能测试立项要明确哪些前置条件？

**答**：
- 功能测试关心"对不对"，性能测试关心"多快、多稳、在什么资源约束下"——结论是分布而非布尔值，必须用 p75/p95/p99 分位数说话。
- 立项前置条件四件套：**明确的性能目标**（如 LCP p75 < 2.5s）、**代表性设备与网络档位**（Moto G4 / Fast 3G）、**固定的测试环境与数据集**、**通过/不通过的裁决口径**。
- 测试类型要区分：基准测试（Baseline）测现状、负载测试测目标并发、压力测试找崩塌点、浸泡测试（Soak）找内存泄漏，混着做会得到互相污染的结论。
- 追问钩子：为什么性能测试不能用同事的开发机跑？——因为环境不受控，结论不可复现，性能测试的第一原则是可复现。

```javascript

// 性能测试的立项清单可以固化成 CI 配置，保证每次跑的口径一致
const perfPlan = {
  target: { LCP: 2500, INP: 200, CLS: 0.1 },   // 目标口径，p75
  device: { cpuThrottlingRate: 4, network: 'Fast 3G' }, // 受控降速
  runs: 5,                                      // 每页跑 5 次取中位数，消除抖动
  pages: ['/home', '/list', '/detail'],
  judge: (metrics) => Object.entries(perfPlan.target)
    .map(([k, v]) => `${k}: ${metrics[k]}ms ${metrics[k] <= v ? 'PASS' : 'FAIL'}`),
};
// 可复现 = 同一设备档位 + 同一网络 + 同一数据 + 同一版本，缺一个结论就不可信
console.log(perfPlan.judge({ LCP: 2600, INP: 180, CLS: 0.05 }));
// => ['LCP: 2600ms FAIL', 'INP: 180ms PASS', 'CLS: 0.05ms PASS']
```
