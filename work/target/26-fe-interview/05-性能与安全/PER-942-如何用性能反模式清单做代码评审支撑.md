## PER-942：如何用「性能反模式清单」做代码评审支撑

**答**：
- 清单来源：历史劣化案例 + 常见错误（同步大脚本、未压缩图片、内存泄漏模式、布局抖动、未做 font-display）。
- 落地形态：ESLint 规则自动化一部分；其余做成 review checklist 供评审者勾选；高危项接 CI 检查。
- 持续更新：每次劣化复盘后把新反模式入库并标注出现频次，高频项自动化、低频项人工。
- 教育价值：清单附"为什么"与正确写法，作为团队学习材料而非打人工具。

```javascript
// 反模式自动检测示例：布局抖动
function detectLayoutThrashing(fnSrc) {
  const bad = [];
  const lines = fnSrc.split('\n');
  lines.forEach((l, i) => {
    if (/\.offsetWidth|\.offsetHeight|getBoundingClientRect/.test(l)) {
      for (let j = i + 1; j < Math.min(i + 6, lines.length); j++)
        if (/\.style\./.test(lines[j])) { bad.push(i + 1); break; }  // 读后紧跟写
    }
  });
  return { thrashLines: bad,
    advice: bad.length ? '读布局与写样式交叉，批量写或用 transform 替代' : null };
}
```
