## PER-715：移动端页面的可交互时间怎么定义与测量？按钮可点但无响应的假可交互怎么识别？

**答**：
- 定义之争：JS 加载完 ≠ 可交互——真实可交互 = 首屏元素**事件处理器已绑定**且点击后 N ms 内有视觉反馈；假可交互（按钮可见可点但 handler 未绑定或 JS 阻塞无响应）是移动端体验投诉的高发区。
- 测量方法：启动后在首屏关键交互元素上部署**探针点击**（模拟 click 测响应时间，仅自动化测试）或运行时监听首屏首次真实点击的响应延迟（TBT 思路：点击时刻是否有 longtask 挡住处理）；自动化用 Playwright 点击测反馈。
- 识别假可交互：元素存在 + click 事件派发后 100ms 内无 DOM 变化/无网络请求 -> 判假可交互并上报（绑定时机问题：事件委托缺失/延迟绑定）。
- 治理：事件委托提前绑定（DOMContentLoaded 时即委托到容器）、首屏 handler 随 HTML 内联、防止启动期长任务挡住首次交互（INP 优化同源）。

```javascript

const realInteractivity = {
  define: '可交互 = 首屏元素 handler 已绑定 且 点击 N ms 内有视觉反馈',
  measure: ['自动化探针点击测响应', '运行时监听首帧后首次真实点击延迟'],
  fake: { detect: 'click 派发后 100ms 无 DOM 变化且无请求 -> 假可交互',
    causes: ['延迟绑定', '无事件委托', '启动期 longtask 挡住处理'] },
  fix: ['DOMContentLoaded 即委托绑定', '首屏 handler 内联', '启动长任务治理（INP 同源）'],
};
function fakeInteractivityProbe(root) {
  root.addEventListener('click', (e) => {
    const t0 = performance.now();
    requestAnimationFrame(() => requestAnimationFrame(() => {
      if (performance.now() - t0 > 100) {                       // 双帧后仍超 100ms
        report('fake-interactive', { el: e.target.tagName, delayMs: Math.round(performance.now() - t0),
          hasLongTask: window.__recentLongTask });
      }
    }));
  }, { capture: true });
}
```
