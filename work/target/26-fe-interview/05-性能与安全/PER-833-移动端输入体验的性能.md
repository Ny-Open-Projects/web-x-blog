## PER-833：移动端输入体验的性能：输入防抖、受控组件重渲染与输入法 composition 处理

**答**：
- 受控输入的性能坑：每敲一个字符全量 setState → 大表单页输入卡顿；优化：输入层本地 state + 失焦/防抖后同步到全局 store（受控到"全局"解耦）。
- 输入法 composition 是移动端第一坑：拼音组合期（isComposing/input 事件 compositionupdate）触发 onChange 会读到中间态，且防抖会打断候选——组合期内不触发业务逻辑，compositionend 才处理。
- 校验时机分级：组合期只做长度截断（不弹错）；compositionend/失焦做格式校验；提交前做全量校验。错误提示避免在校验时引起布局跳动（预留错误区高度）。
- 度量：输入到回显延迟（< 50ms 才顺滑）、键盘弹出后的重排次数。

```javascript
function attachSmartInput(input, { onChange, onCommit, debounce = 300 } = {}) {
  let composing = false, timer = null;
  input.addEventListener('compositionstart', () => { composing = true; });
  input.addEventListener('compositionend', () => {
    composing = false;
    onCommit && onCommit(input.value);        // 组合结束才提交业务逻辑
  });
  input.addEventListener('input', () => {
    if (composing) return;                    // 组合期不触发防抖逻辑（防打断候选）
    clearTimeout(timer);
    timer = setTimeout(() => onChange && onChange(input.value), debounce);   // 防抖同步
  });
  // 受控重渲染优化：input 本地持有 value，防抖后 sync 到 store
}
// 长度截断可在组合期做：input.value = input.value.slice(0, maxLen)（不弹错）
```
