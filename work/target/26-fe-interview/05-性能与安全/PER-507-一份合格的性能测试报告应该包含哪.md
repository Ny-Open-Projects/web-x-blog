## PER-507：一份合格的性能测试报告应该包含哪些要素？如何让报告驱动决策而不是归档吃灰？

**答**：
- 报告五要素：**环境声明**（设备/网络/版本/数据快照）、**指标分布**（p50/p75/p95/p99 而非平均值）、**对比锚点**（vs 上一版本、vs 目标线、vs 竞品）、**失败样本率**、**可复现命令**（拿到报告能一键重跑）。
- 必须回答三个问题：达不达标（裁决）、比上次好了还是坏了（回归）、瓶颈在哪（归因），缺一项报告就只是数据堆砌。
- 让报告驱动决策的诀窍：接 CI 在 PR 里留评论、指标 diff 超 5% 自动 @owner、报告链接进发版 checklist——归档吃灰的根因是报告没长在决策流程上。
- 追问钩子：报告里为什么坚决不放"平均加载时间"？——平均数掩盖长尾，用户抱怨的恰恰是被平均掉的那 10%。

```javascript

// 报告即代码：结构固定，机器可读、人可扫
function renderReport(env, samples, prev, target) {
  const pct = (a, q) => [...a].sort((x, y) => x - y)[Math.floor(a.length * q)];
  const row = (k) => ({
    p75: pct(samples.map(s => s[k]), 0.75),
    prev: prev?.[k] ?? 'N/A',
    target: target[k],
    verdict: pct(samples.map(s => s[k]), 0.75) <= target[k] ? 'PASS' : 'FAIL',
  });
  return {
    env: `${env.device} / ${env.network} / v${env.version} / 数据快照 ${env.dataset}`,
    metrics: { lcp: row('lcp'), inp: row('inp'), cls: row('cls') },
    failRate: samples.filter(s => s.ok === false).length / samples.length,
    rerun: `node perf/audit.js --device=${env.device} --net=${env.network} # 可复现`,
  };
}
// 渲染成 Markdown 进 PR 评论：指标 diff > 5% 自动标记回归并 @ owner
```
