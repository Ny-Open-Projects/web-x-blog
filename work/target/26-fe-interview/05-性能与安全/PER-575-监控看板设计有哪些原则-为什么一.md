## PER-575：监控看板设计有哪些原则？为什么一张大屏解决不了排障效率问题？

**答**：
- 看板分层：**值班看板**（一屏回答现在有没有事"：SLO 状态、活动告警、发版时间线）、**专题看板**（某业务线性能全景）、**排障看板**（按 traceId/指纹下钻的查询界面）——三层的用户和阅读节奏完全不同。
- 设计原则：每屏一个问题的答案、时间轴默认对齐发版事件、数字可下钻（点 p75 能展开分布直方图与慢样本列表）、颜色语义固定（红=坏且新）。
- 大屏的失败原因：把 50 个图塞一屏，没人能从很多线里得出行动；看板的价值度量是值班从看到告警到定位根因的时间，不是图的数量。
- 自助化：允许业务方基于指标 DSL 自建看板但锁定口径来源（引用注册过的指标而非临时写查询），防止口径分裂。

```javascript

const dashboardSpec = {
  oncall: {  // 值班看板：一屏回答有没有事"
    widgets: ['sloStatus', 'activeAlerts', 'releaseTimeline', 'errorRateSparkline'],
    rule: '所有时间轴对齐发版事件，颜色语义固定',
  },
  drilldown: {  // 排障看板：查询式
    inputs: ['traceId', 'errFingerprint', 'route'],
    views: ['分布直方图', '慢样本列表(带会话回放链接)', '关联后端 trace 跳转'],
  },
  governance: {
    metricRegistry: true,   // 自助看板只能引用注册指标，防口径分裂
    valueMetric: 'MTTD(从告警到定位) < 5min',
  },
};
console.log(dashboardSpec.governance.valueMetric);
```
