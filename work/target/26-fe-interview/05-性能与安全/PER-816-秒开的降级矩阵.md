## PER-816：秒开的降级矩阵：当某一段超预算时各端的兜底手段（骨架、缓存、简化版）

**答**：
- 降级矩阵按段 × 手段组织：加载段超 → 缓存上一版页面数据（秒出旧内容 + 后台刷新）；数据段超 → 骨架屏 + 分步渲染（关键列先行）；渲染段超 → 简化版页面（低端机裁剪动效/图片档位）；容器段超 → App 侧预热（前端无法干预但要有上报推动）。
- 触发原则：降级不是常开——由运行时信号（实测耗时/设备档/网络档）触发，且要有恢复条件（网络恢复/数据到达）。
- 一致性要求：降级态与正常态的数据版本标识要区分，避免旧缓存内容被当成新数据（时间戳/版本角标）。
- 验收：每个降级手段要有独立开关（服务端下发），可以单独演练与关闭，出问题时按段定位、按手段止血。

```javascript
const degradeMatrix = {
  'container->blank-gone': {                 // 加载段
    action: 'cached-page',                   // 缓存上版页面
    trigger: s => s.p75 > 500,
    recover: 'network-ok && new-data-arrived',
    flag: 'degrade_cached_page',
  },
  'blank->first-screen': {                   // 数据段
    action: 'skeleton + step-render',
    trigger: s => s.p75 > 800,
    flag: 'degrade_skeleton',
  },
  'render': {
    action: 'lite-page',                     // 低端机简化版
    trigger: s => s.tier === 'low',
    flag: 'degrade_lite',
  },
};
function pickDegrade(ctx) {                  // ctx: {seg, p75, tier, flags}
  const rule = degradeMatrix[ctx.seg];
  if (!rule || !rule.trigger(ctx) || !ctx.flags[rule.flag]) return null;
  return { action: rule.action, recover: rule.recover ?? 'data-arrived' };
}
```
