## PER-373：DevTools 的 4x CPU 降速对应什么真实设备？实验室模拟与真实设备性能的映射怎么校准？

**答**：
- 映射常识：DevTools 4x 降速 ≈ 中端 Android（如 2019-2021 年主流机型）；Lighthouse 默认 Moto G4 + 4x ≈ 低端机。但这是粗映射——CPU 架构（ARM 优化）、单核/多核差异、散热降频（持续高负载后真实设备更慢）都让模拟失真。
- 校准方法：真实设备矩阵跑固定基准脚本（同页面同操作），记录 LCP/INP/TBT；与实验室模拟值建立"设备 × 场景"映射系数表；RUM 侧按设备档位（UA/内存 deviceMemory 分组）看真实分布，反推实验室档位是否合理。
- 局限性清单：模拟器无真实 GPU 合成差异、无散热降频、无后台进程干扰、网络 throttling 与真实弱网（RTT 抖动/丢包）不同。实验室是"可复现的回归工具"，不是"真实体验的预言机"——两者配合（PER-367 双轨制）。
- 工程纪律：性能预算以"真实设备矩阵 + RUM 分布"为最终标准，实验室阈值定期（季度）按映射系数校准。

```text
校准流程：
1. 设备矩阵（3~5 台代表机：旗舰/中端/低端）跑基准脚本，记录指标
2. 实验室同脚本（各档降速）记录指标
3. 拟合映射：中端机 INP ≈ 实验室 4x × 1.3（示例系数，按实测）
4. RUM 按 deviceMemory 分组（<=4GB 低端）验证分布
5. 季度复测：新机型发布、系统更新后系数漂移 → 更新实验室阈值
结论：4x 降速是"可复现的中端机近似"，最终标准永远是 RUM 真实分布
```
