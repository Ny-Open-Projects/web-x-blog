## PER-550：手写一个前端长连接消息洪泛接收压测：模拟服务端每秒推送 N 条消息，验证渲染合并与内存稳定

**答**：
- 压测对象是前端的**消息处理管道**：mock 一个 WS 服务（或本地 ws），以可调速率推送，观察三件事——主线程长任务（消息处理是否成批）、渲染帧率、内存是否随消息量无界增长（未清理的消息缓冲区）。
- 关键实现：消息进入队列，rAF 或 250ms 定时批量 flush 渲染，这是 IM/行情类页面的标准做法；压测要验证"洪泛时队列有上限丢弃策略"，否则弱网慢消费会 OOM。
- 边界：压测结束后要断言内存回落（强制 GC 可用 `--expose-gc` 的 Node 侧或多次导航触发）。
- 评分点：批量渲染与队列上限丢弃两处设计。

```javascript

class MessagePipeline {
  constructor(maxQueue = 5000, flushMs = 250) {
    this.queue = []; this.maxQueue = maxQueue; this.dropped = 0;
    setInterval(() => this.flush(), flushMs);            // 批量渲染节流
  }
  push(msg) {
    if (this.queue.length >= this.maxQueue) {            // 洪泛保护：丢最旧
      this.queue.shift(); this.dropped++;
    }
    this.queue.push(msg);
  }
  flush() {
    if (!this.queue.length) return;
    const batch = this.queue.splice(0, 200);             // 单帧最多渲 200 条
    render(batch);                                       // UI 层一次 setState
  }
}
// 压测驱动：mock 推送源
const pipe = new MessagePipeline();
let sent = 0;
const flood = setInterval(() => {
  for (let i = 0; i < 50; i++) pipe.push({ id: ++sent, t: performance.now() }); // 50msg/tick
}, 100);
setTimeout(() => {
  clearInterval(flood);
  console.log({ sent, dropped: pipe.dropped,             // 丢弃率即过载保护是否生效
    heapMB: +(performance.memory.usedJSHeapSize / 1048576).toFixed(1) });
}, 60000);
```
