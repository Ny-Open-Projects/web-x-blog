## PER-260：如何基于 Event Timing 建立"慢交互排行榜"？聚合维度与防误报怎么做？

**答**：
- 聚合维度：交互类型（click/keydown）× 目标元素（tagName + 关键属性如 class 的前缀/按钮文案/测试 id）× 页面模板。每维度出 p75/p98 与样本数。
- 目标元素标识：直接报 e.target.tagName 会全是 DIV；要把语义选择器提出来——closest('button,a,[role]') 的文案或 data-test-id，做归一化（长文案截断、数字替换成 :n），保证同元素聚合在一起。
- 防误报：① 主线程被三方脚本占满导致的"误伤"要按 LoAF invoker 二次归因；② durationThreshold 16ms 起但排行榜只收 >200ms 的交互；③ 用户输入后 500ms 内的已知抖动窗口排除；④ 低样本组（< 20 次）不进榜。
- 落地：排行榜每周自动生成，Top 项直接转工单，修完观察 p75 回落验证。

```javascript
function semanticTarget(el) {
  const meaningful = el.closest?.('button, a, [role=button], input, [data-test-id]');
  if (!meaningful) return el.tagName;                       // 容器兜底
  return meaningful.dataset.testId
    || (meaningful.tagName === 'INPUT' ? `input[${meaningful.type}]` : meaningful.textContent.trim().slice(0, 12))
    || meaningful.tagName;
}
// 上报聚合键：`${routeTemplate(path)}|${e.name}|${semanticTarget(e.target)}`
// 看板按聚合键出 p75/duration 与样本数，>200ms 且样本 >= 20 才入榜
```
