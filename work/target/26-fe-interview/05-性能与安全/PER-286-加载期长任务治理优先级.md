## PER-286：加载期的长任务（解析/注水/三方脚本）怎么按优先级治理？

**答**：
- 先分类再治理：① 关键路径任务（首屏渲染、核心交互绑定）——保留但瘦身（拆包、树摇）；② 可延后任务（非首屏组件注水、统计上报、预取）——移出加载窗口（idle/交互后/3s 延迟）；③ 纯计算任务（排序、过滤、解析大 JSON）——Worker 隔离。
- 三方脚本是大头：按 LoAF invoker 排行处理，能 facade 的 facade、能 idle 的 idle、能 worker 的 worker；禁止同步脚本。
- 注水切片：React 18 并发注水、Vue islands、或手动把非关键区块延后挂载（Suspense/条件渲染），把一次几百 ms 的注水拆成多次小任务。
- 验收：TBT < 200ms、加载后 3s 内无 >150ms 长任务；用 Performance 面板录制"打开页面到可交互"检查红色块分布。

```javascript
// 加载期任务分级调度器：关键任务立即、可延后任务 idle、纯计算进 worker
const schedulerQueue = {
  critical: (fn) => fn(),                                       // 立即
  deferred: (fn) => (window.requestIdleCallback || ((f) => setTimeout(f, 50)))(fn, { timeout: 3000 }),
  compute: (fn) => runInWorker(fn),                             // worker 隔离
};
// 首屏路径只跑 critical：
schedulerQueue.critical(() => bindCoreHandlers());
schedulerQueue.deferred(() => loadRecommendations());           // 推荐：3s 内空闲时
schedulerQueue.compute(() => sortHugeList(rows));               // 排序：worker
// 三方脚本按 LoAF 排行治理：chat SDK → idle + facade；analytics → deferred 批量
```
