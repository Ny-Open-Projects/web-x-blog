## PER-943：性能平台的接口性能依赖（后端拖慢前端）如何归因

**答**：
- 拆解加载瀑布：TTFB 里区分 DNS/TLS/服务端处理；服务端部分再拆网关/业务 RPC/DB，需要前后端 trace 贯穿（traceId 透传）。
- 接口预算：给关键接口定 SLO（如首屏依赖接口 P90 < 300ms），超标的接口进入后端治理而非前端背锅。
- 联合治理机制：性能平台输出"前端受后端拖慢 Top10 接口"月报给服务端团队，附影响页面与用户数。
- 前端自保：接口超时与降级（缓存兜底/骨架屏/非关键请求延后），确保后端慢时体验损失可控。

```javascript
// TTFB 归因上报：结合 resource timing
function ttfbBreakdown(entry) {   // entry: navigation resource timing
  return {
    dns: entry.domainLookupEnd - entry.domainLookupStart,
    tls: entry.connectEnd - entry.secureConnectionStart,
    server: entry.responseStart - entry.requestStart,   // 真正服务端时间
    total: entry.responseStart - entry.startTime,
    suspect: entry.responseStart - entry.requestStart >
             (entry.responseStart - entry.requestStart + 0) * 0.6 ? 'server' : 'network',
  };
}
// server 占比高 -> 生成接口治理单给后端；附 traceId 查后端 span
```
