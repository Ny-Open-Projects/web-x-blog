## PER-534：大促全链路压测中，前端要承担哪些准备工作和压测动作？

**答**：
- 前端在全链路压测的角色是"承接与配合"：改造埋点与打标（压测流量带压测标 header，前端透传）、关闭或 mock 非必要第三方（广告/推荐）、准备压测版数据（预生成足够量级的列表数据）、把限流降级 UI 做出来并演练。
- 前端自身的压测项：静态资源 CDN 容量（打包产物预热到 CDN、评估边缘节点命中率）、接口并发下的防重复提交（按钮防抖 + 幂等 token）、秒杀场景的轮询/长连接频率是否会把后端打挂。
- 压测动作：按大促流量模型（小时级 QPS 曲线）驱动页面脚本回放，观察前端侧指标（接口 RT、错误率、切页耗时）随并发增长的劣化曲线，找出拐点。
- 收尾：压测报告产出"降级预案触发条件"（如错误率 > 5% 切静态兜底页），大促当天值班按条件执行。

```javascript

// 压测打标透传 + 前端限流自保
const IS_PRESSURE = () => location.search.includes('__pt=1'); // 压测入口标识
const origFetch = window.fetch;
window.fetch = (input, init = {}) => {
  if (IS_PRESSURE()) {
    init.headers = { ...init.headers, 'X-Load-Test': '1' };  // 压测标透传给后端
  }
  return origFetch(input, init);
};
// 秒杀按钮：幂等 token 一次性
let token = null;
async function seckillClick() {
  if (token) return;                       // 压测验证：狂点不会发多笔
  token = await getIdempotentToken();
  try { await origFetch('/api/seckill', { method: 'POST', headers: { 'X-Idem': token } }); }
  finally { token = null; }
}
```
