## PER-426：如何在运行时准确知道"当前页面跑的是哪个构建"？

**答**:
- 为什么需要：RUM 分析的第一步是"这个慢样本来自哪个版本"——没有版本指纹，所有归因都是猜。版本指纹要满足：构建时唯一、运行时可读、缓存场景不漂移。
- 三层指纹：① 构建号注入——`__BUILD_VERSION__ = git-sha + build-id`（DefinePlugin/环境变量）；② HTML 时间戳注释——HTML 内嵌 `<!-- build:20241119-a3f9 -->`（HTML 是版本真相源）；③ 产物 hash 聚合——运行时读 manifest（入口 chunk 的 hash 组合），校验与版本号一致（不一致 = 混版，PER-388 直接告警）。
- 缓存漂移防线：用户拿着旧 HTML 但 CDN 已是新版——此时用户跑的确实是旧版本，指纹如实反映旧版本（正确）；危险的是"HTML 与 chunk 版本不一致"的混版——③ 的聚合校验兜住。
- 落地：RUM 全量上报带指纹；看板按指纹分组；指纹缺失的样本单独标记（无法归因的样本占比应 < 1%）。

```javascript
// 构建时：DefinePlugin 注入
// new webpack.DefinePlugin({ __BUILD_VERSION__: JSON.stringify(GIT_SHA + '-' + BUILD_ID) })
// HTML 真相源：<!-- build:20241119-a3f9c2 -->
// 运行时校验（混版检测）：
async function verifyBuildFingerprint() {
  const manifest = await fetch('/build-manifest.json').then((r) => r.json()).catch(() => null);
  const expected = manifest?.[window.__BUILD_VERSION__];
  if (!expected) return report({ type: 'fingerprint-unknown', v: window.__BUILD_VERSION__ });
  const entryHash = await hashOfMainChunk();                  // 实际加载的入口 chunk hash
  if (entryHash !== expected.entryHash) {
    report({ type: 'mixed-version', v: window.__BUILD_VERSION__, actual: entryHash });  // 混版实锤
  }
}
// RUM 样本带 __BUILD_VERSION__；指纹缺失样本占比 < 1% 是归因可信度的前提
```
