## PER-337：性能告警体系怎么设计才"有人管、不狼来了"？阈值/突变/预算三条告警链路？

**答**：
- 三条告警链路各有分工：① 阈值告警——p75 超 SLO 持续 2h 且样本充足，告"慢性病"，路由到页面 owner 周期性跟进；② 突变告警——环比昨日同时段恶化 > 20%（bootstrap 显著性），告"急性病"，实时到值班群，多为发版引入；③ 预算告警——CI 阶段 LH 指标/体积超预算直接拦发布（最便宜的处理时机，问题还没到线上）。
- 防狼来了三件套：样本下限（<100 不告）、静默期（同页面 24h 不重复）、自愈识别（发版预热抖动 1h 内静默）；告警必须带"初步归因 + owner + 看板深链接"，不能裸发数字。
- 路由与升级：阈值类进工单（MTTA 考核），突变类进值班群（响应分钟级）；连续 2 个周期未处理自动升级（owner → 团队 lead）；每周告警复盘——误报率 > 30% 的规则回炉调参。
- 度量告警体系本身：MTTA（认领时长）、误报率、告警后指标回落率——告警系统也是被治理的对象。

```yaml
# 告警规则注册（示例）
- name: inp-p75-threshold
  metric: core_inp_p75
  cond: "value > 200 for 2h AND samples >= 200"
  route: ticket
  owner: page-owner
  silence: { same_target: 24h, after_release: 1h }

- name: lcp-p75-mutation
  metric: core_lcp_p75
  cond: "p75(today 10-12h) > p75(yesterday 10-12h) * 1.2 AND bootstrap_significant"
  route: oncall
  attach: [ loaf_top5, version_diff ]

- name: bundle-budget
  stage: ci
  cond: "entry_chunk_gzip > 300KB OR tbt > 300ms"
  action: block_merge
```
