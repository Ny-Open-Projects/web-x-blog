## PER-366：业务自定义指标如何在平台上注册、采集与防泛滥？

**答**：
- 注册流程：指标申请（业务方提需求：名称/口径/采集点/SLO/owner）→ 平台评审（口径可自动采集吗、与既有指标是否重复、维度是否收敛）→ 注册进指标中心（YAML，PER-335）→ SDK 按配置下发采集 → 看板自动生成。
- 采集封装：SDK 提供 `metric.mark('biz-content')` / `metric.measure('order-flow', startMark, endMark)` 原语，业务方只打 mark，平台统一计算与上报——业务方不直接 sendBeacon（口径统一、体积可控）。
- 防泛滥机制：指标必须有 owner 与 SLO 才能注册；季度审计——无人看的指标（看板 0 访问）下线；命名规范（前缀域 biz_）；每个页面自定义指标 ≤ 5 个（防埋点膨胀拖累性能）。
- 与 CWV 关系：自定义指标是诊断层/业务层（PER-335 三层），不进北极星；北极星只允许 CWV 级别的标准指标。

```javascript
// SDK 业务指标原语
const perf = window.__perf__;
perf.mark('biz:order:start');                       // 关键操作开始
await submitOrder();
perf.mark('biz:order:end');
perf.measure('biz:order-duration', 'biz:order:start', 'biz:order:end', {
  slo: { p75: 1500 }, owner: 'trade-team',          // 注册时声明的元信息随上报走
});
// 平台侧：measure 结果进聚合引擎，看板自动出 p75/达标率；
// 审计任务：90 天看板 0 访问的 biz_ 指标自动标记下线候选 → 通知 owner 确认
```
