## PER-703：小程序性能审计怎么做？一次完整的小程序性能审计要检查哪些项、输出什么？

**答**：
- 审计维度六项：**启动**（onLaunch 同步耗时/首屏分包/冷热分离）、**渲染**（setData 频率与大小/长列表/图片尺寸）、**包体积**（主包占比/未用组件/图片未压缩）、**网络**（请求并发与串行/未缓存/重复请求）、**内存**（图片内存/全局对象膨胀）、**体验**（骨架屏/降级路径/弱网表现）。
- 工具链：微信开发者工具 Audits 面板 + 体验评分 + 自研探针（671/692 的 setData 与启动探针）+ 真机 profiling。
- 输出物：审计报告（问题清单按影响排序 + 每项带证据截图/数据 + 修复建议 + 预估收益）、复测基线（修后同口径复测对比）。
- 关键习惯：审计季度化（不是一次活动）、Top 问题进版本计划、修复必须带度量证明（改前改后数据）。

```javascript

const mpAuditChecklist = {
  startup: ['onLaunch 同步耗时 < 50ms', '首屏分包命中', '冷启动 < 2s(低端 3s)'],
  render: ['setData 单次 < 100KB、每秒 < 5 次', '长列表虚拟化', '图片按显示尺寸'],
  bundle: ['主包 < 2MB', 'lazyCodeLoading 开启', '图片压缩率检查'],
  network: ['启动串行请求 < 2 个', '接口缓存命中', '无重复请求'],
  memory: ['页面切换内存回落', '全局对象无膨胀', '图片内存受控'],
  ux: ['骨架屏覆盖', '弱网降级路径可用', '失败重试提示'],
  output: '问题清单(影响排序) + 证据数据 + 修复建议 + 预估收益 + 修后复测基线',
};
console.log(mpAuditChecklist.output);
```
