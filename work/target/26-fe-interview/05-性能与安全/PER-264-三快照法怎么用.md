## PER-264：DevTools 堆快照三快照法怎么定位泄漏？Retainers 视图怎么读？

**答**：
- 操作流程：打开 Memory 面板 → 快照 1（基准）→ 执行可疑操作 N 次（如打开/关闭弹窗 5 次）→ 强制 GC（垃圾桶按钮）→ 快照 2；选快照 2 视图切换到 Comparison 对比快照 1，按 "#Delta" 排序找正增长对象。
- 读数要点：优先看构造函数名（如闭包是 `(closure)`、全局是 `(global)`）与 "#Delta"；Shallow Size 是对象自身内存，Retained Size 是"释放它能省下的总内存"——泄漏排序看 Retained。
- Retainers 链从下往上读：最下面是被泄漏对象，往上每一层是"谁引用着它"，一直到根（window / detached DOM 树 / 被闭包捕获的作用域）。中断链条的那层就是修复点。
- 常见模式：`Detached <div>` 挂在某个监听器 closure 下 → 未解绑监听；`(closure)` 持有大数组 → 回调闭包引用未置空。

```text
三快照实操：
snapshot1 → [打开/关闭弹窗 ×5] → GC → snapshot2 → Comparison 视图
典型结果：
  (closure)        +5    # 每次操作多一个闭包
  Detached <div>   +10   # 弹窗 DOM 没释放
Retainers 链（从泄漏对象往上）：
  Detached <div class="modal"> ← HTMLElement 缓存 Map ← modalCache(window)   ← 全局缓存没清理
  Detached <div class="modal"> ← onBtnClick closure ← listener(document)     ← 监听器没解绑
修复点 = 中断最近的一层：unmount 时 cache.clear() / removeEventListener
```
