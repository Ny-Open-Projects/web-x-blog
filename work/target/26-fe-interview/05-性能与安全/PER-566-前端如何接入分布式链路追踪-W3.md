## PER-566：前端如何接入分布式链路追踪？W3C Trace Context 的 traceparent 在前端怎么生成与传播？

**答**：
- 前端是 trace 的源头：页面加载生成 `traceId`（32 hex 随机），每个发出去的请求带 `traceparent: 00-{traceId}-{spanId}-01` header；同页面所有请求共享 traceId，形成一次页面会话一棵 trace 树。
- 要点：跨域请求要服务端配 CORS 允许 `traceparent` header，否则预检失败；第三方域名不透传（隐私与兼容）；traceparent 之外再带 `baggage`（用户分桶/灰度标）可串业务上下文。
- 前端价值链路：RUM 错误上报带上 traceId -> 排障时用 traceId 直查后端 APM 全链路（网关/服务/DB 耗时），把前端页面慢和哪个后端环节慢接通。
- span 划分建议：页面加载、每个 API 请求、资源加载聚合、用户交互各一个 span；前端 span 尽量少而粗，太细上报成本高。

```javascript

function initTracer() {
  const traceId = crypto.randomUUID().replace(/-/g, '');  // 32 hex
  return {
    traceId,
    header(extra = {}) {
      const spanId = crypto.randomUUID().slice(0, 16).replace(/-/g, '');
      return {
        ...extra,
        traceparent: `00-${traceId}-${spanId}-01`,        // W3C Trace Context
        baggage: `bucket=${window.__abBranch ?? 'none'}`,
      };
    },
  };
}
const tracer = initTracer();
const origFetch = window.fetch;
window.fetch = (input, init = {}) => {
  const url = new URL(input instanceof Request ? input.url : input, location.href);
  if (url.origin === location.origin) {                   // 同源才透传，防第三方污染
    init.headers = { ...init.headers, ...tracer.header() };
  }
  return origFetch(input, init).then(res => {
    reportSpan({ traceId: tracer.traceId, url: url.pathname, dur: 0 }); // span 上报
    return res;
  });
}
```
