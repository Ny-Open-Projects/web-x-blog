## ZSM-288：store 写入侧要不要做 schema 校验，怎么平衡性能

**答**:
- 校验放「边界」不放「每次写」：接口响应、storage 复水、跨应用事件 payload 是外部不可信输入，入口校验；内部 setState 高频路径不校验
- dev/生产分级：dev 全量校验（zod parse，违规即抛错早发现），生产关闭或仅对关键域（支付/权限）保留轻量断言
- 校验失败策略：字段缺失给默认值（宽容读）、关键域违规直接丢弃并上报（fail-fast + 观测）
- 类型系统前置：TS 类型 + 接口 DTO 生成（OpenAPI）消除 80% 违规，运行时校验只兜真实外部输入

```javascript
const userSchema = z.object({ id: z.string(), role: z.enum(['admin', 'user']) })
function setUser(u) {
  const parsed = userSchema.safeParse(u)
  if (!parsed.success) { report('store_invalid_user', parsed.error); return }   // 丢弃+上报
  store.setState({ user: parsed.data })
}
```
