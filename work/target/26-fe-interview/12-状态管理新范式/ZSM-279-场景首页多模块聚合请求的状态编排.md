## ZSM-279：首页十个模块的数据聚合请求怎么编排

**答**:
- 反模式：一个聚合接口串行依赖+全部阻塞首屏。正解：按优先级分批（首屏关键 LCP 内容先行，次要模块 idle/滚动触发），各模块独立 Query 缓存独立失败
- 编排手段：并行 useQuery（天然并行）+ dependent query（有依赖的）+ requestIdleCallback/IntersectionObserver 延迟非关键模块
- 失败隔离：某模块失败只降级该模块（骨架/重试），不阻塞整页；聚合接口失败会导致全页失败，优先拆
- 缓存复用：多模块同源数据（用户信息）共享 key 避免重复请求；SSR 下服务端 prefetch 全部关键模块一次性 dehydrate

```javascript
const a = useQuery({ queryKey: ['banner'], queryFn: fetchBanner })            // 关键
const b = useQuery({ queryKey: ['feed'], queryFn: fetchFeed })                // 关键
const c = useQuery({ queryKey: ['rank'], queryFn: fetchRank, enabled: ready,  // 非关键：视口内才拉
  placeholderData: keepPreviousData })
```
