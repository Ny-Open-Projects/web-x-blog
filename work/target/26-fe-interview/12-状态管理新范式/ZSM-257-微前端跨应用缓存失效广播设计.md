## ZSM-257：主应用改了数据怎么广播让所有子应用缓存失效

**答**:
- 广播事件协议：`invalidate { domain, ids? }`，子应用监听后失效自己持有的对应域缓存（各自的 queryClient/atom）
- 分层失效：精确 id 失效 > 域级失效 > 全量失效；高频写入用节流合并，避免失效风暴（所有子应用同时重拉打爆后端）
- 未挂载的子应用无需处理：挂载时按「事件版本号」判断是否需要跳过缓存——主应用维护 domain version，子应用挂载时对比
- 实现载体：CustomEvent 或共享 bus；关键在「失效语义」标准化，而不是引入统一缓存库（各子应用技术栈不同）

```javascript
// 主应用
bus.emit('cache:invalidate', { domain: 'order', ids: [1001], version: 42 })
// 子应用监听
bus.on('cache:invalidate', ({ domain, ids, version }) => {
  if (domain !== 'order') return
  ids?.length ? ids.forEach(id => qc.invalidateQueries({ queryKey: ['order', id] }))
              : qc.invalidateQueries({ queryKey: ['order'] })
  lastVersion = version   // 挂载时对比决定是否全量刷新
})
```
