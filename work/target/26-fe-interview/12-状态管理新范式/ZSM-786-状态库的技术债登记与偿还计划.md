## ZSM-786：状态库的技术债登记：每笔债的利息计量与偿还排期

**答**：
- 状态层典型技术债的登记（每笔债有 ID/类型/利息/偿还成本）：1) **形状债**——高耦合树（ZSM-618 反模式），利息 = 每次新增订阅的重渲成本；2) **协议债**——跨模块直接 import 对方 store，利息 = 重构时的耦合爆炸；3) **兼容债**——persist migrate 链断档，利息 = 升级时的全量清缓存；4) **测试债**——竞态用例缺失，利息 = 线上竞态事故的排查时间；5) **文档债**——无 ADR，利息 = 新人上手时间与重复踩坑。
- 利息计量：把「每次触碰该债的额外成本」量化——形状债利息 = `变更影响组件数 × 平均重渲耗时`（Profiler 实测）；协议债利息 = `跨层违规修复工单数`。有利息数字，债的优先级排序才有依据。
- 偿还策略三选：**立即还**（利息高且偿还便宜：lint 修复）、**计划还**（进季度排期：形状重构）、**永不还**（利息低且偿还昂贵：历史遗留的死 store 标记 deprecated 不动）。三选的判断标准是「利息 ÷ 偿还成本」比值。
- 与健康分（ZSM-784）的联动：技术债登记项直接映射健康分扣分项——债的偿还即分数回升，治理闭环可量化。
- 追问钩子：技术债登记的格式示例（评审会用）——「TD-012 形状债：userStore 高耦合树，利息 12ms/变更（实测），偿还 5 人日（拆三个切片），计划 Q1」——一行讲清债的因果与计划。

```javascript
// 技术债登记表
const TECH_DEBT_REGISTRY = [
  {
    id: 'TD-012', type: '形状债',
    desc: 'userStore 高耦合树（profile+settings+draft 混存）',
    interest: { metric: '12ms/变更重渲', measured: 'Profiler 2026-11 实测', freq: '高频（每次输入）' },
    cost: { payback: '5 人日（拆三切片 + 订阅点迁移）', risk: '结算链路回归' },
    strategy: '计划还（Q1 排期）', ratio: '利息/成本 高', adr: 'ADR-0007 关联',
  },
  {
    id: 'TD-015', type: '协议债',
    desc: 'checkoutStore 直接 import cartStoreApi（跨域写）',
    interest: { metric: '每次 cart 重构 checkout 联动修复', measured: '工单 #881 #902', freq: '中频' },
    cost: { payback: '1 人日（改为 invalidate 协议）', risk: '低' },
    strategy: '立即还（lint 修复即可）', ratio: '利息/成本 极高',
  },
  {
    id: 'TD-018', type: '文档债',
    desc: 'themeStore 无 ADR',
    interest: { metric: '新人 onboarding 时间 +0.5 天', measured: '估算', freq: '低频' },
    cost: { payback: '0.5 人日' },
    strategy: '立即还', ratio: '高',
  },
  {
    id: 'TD-020', type: '兼容债',
    desc: 'persist migrate 链 v1→v2 断档',
    interest: { metric: '下次升级全量清缓存', measured: '结构性', freq: '升级时' },
    cost: { payback: '2 人日（补迁移函数）' },
    strategy: '计划还（升级前必须）', ratio: '中',
  },
]
// 排序：利息/成本比值降序 = 偿还优先级（TD-015 → TD-018 → TD-012 → TD-020）
```
