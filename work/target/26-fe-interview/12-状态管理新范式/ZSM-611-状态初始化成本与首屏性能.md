## ZSM-611：状态初始化成本与首屏性能：store 创建的开销藏在哪

**答**：
- 初始化开销四来源：1) **模块顶层副作用**——store 创建时同步执行重逻辑（索引构建、Map 填充、大默认值构造），阻塞首包 JS 执行；2) **persist 同步 hydrate**——localStorage.getItem + JSON.parse 大快照在主线程；3) **默认值膨胀**——初始化就构造完整列表/模拟数据；4) **惰性失效**——本该懒加载的 store 在入口文件被 import 连带创建。
- 修法：1) **懒创建**——store 工厂函数按需调用（`getCartStore()` 惰性单例），或把初始化挪到首次订阅时；2) **hydrate 异步化**——persist 用异步 storage（IndexedDB）+ 骨架先渲染，数据到达后二次渲染；或同步读但 partialize 只带关键切片；3) **默认值瘦身**——初始空结构 + onMount 时再填充。
- 度量方式：Performance 面板看「脚本执行」阶段各模块 top-level 耗时；或给 create 包计时探针输出「每个 store 初始化 ms」。
- SSR 视角：服务端每请求创建 store，初始化成本直接乘以 QPS——服务端 store 创建必须轻（无 IO、无大常驻结构），重数据走异步 loader。
- 追问钩子：初始化成本是「一次性」的但会进 TTI/FCP——首屏关键 store 与非关键 store 分包，非关键 store 延迟到交互后再创建。

```javascript
// 惰性单例 store 工厂 + 初始化计时
let _cartStore = null
export function getCartStore() {
  if (!_cartStore) {
    const t0 = performance.now()
    _cartStore = createStore((set) => ({ items: [], heavyIndex: buildIndex() }))
    const dt = performance.now() - t0
    if (dt > 5) console.warn(`[init] cartStore 初始化 ${dt.toFixed(1)}ms`)
  }
  return _cartStore
}

// persist 异步 hydrate：不阻塞首屏
const useUser = create(persist((set) => ({ name: '', hydrated: false }), {
  name: 'user',
  storage: createJSONStorage(() => asyncIDBStorage),   // 异步：首屏不 parse
  partialize: (s) => ({ name: s.name }),
  onRehydrateStorage: () => (state) => {
    useUser.setState({ hydrated: true })                // 数据到达后再渲染依赖部分
  },
}))

// 组件：未 hydrate 前渲染骨架
function Profile() {
  const { name, hydrated } = useUser(useShallow((s) => ({ name: s.name, hydrated: s.hydrated })))
  if (!hydrated) return <Skeleton />   // 而不是同步卡在 parse 上
  return <div>{name}</div>
}
```
