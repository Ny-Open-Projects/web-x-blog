## ZSM-270：动作流回放数据太大怎么压缩与限量

**答**:
- 压缩三板斧：payload 白名单裁剪（只留回放必需字段）、批量合帧（连续同类 action 合并）、通用压缩（gzip/字典编码，action type 用枚举 id 替代字符串）
- 上限策略：环形缓冲固定条数（如最近 500 条）+ 触发式导出（错误发生时才 flush）；超长会话按「检查点快照 + 增量流」分段
- 检查点设计：每 N 条 action 存一次状态快照，回放时从最近检查点开始，回放成本从 O(全量) 降为 O(分段)
- 存储落点：Error 上报通道限 KB 级 → 只放最后 50 条 + 检查点；完整流走专门的录制存储（IndexedDB/对象存储）按需拉取

```javascript
function recorder(limit = 500, checkpointEvery = 100) {
  const buf = []; let checkpoint = null
  return {
    record(action, state) {
      if (buf.length % checkpointEvery === 0) checkpoint = state   // 检查点
      if (buf.length >= limit) { buf.shift() }                     // 环形
      buf.push([TYPE_ID[action.type], minifyPayload(action)])
    },
    dump() { return { checkpoint, actions: buf, schema: 1 } },     // 检查点 + 增量
  }
}
```
