## ZSM-167：状态层的测试怎么分层？store 单测、缓存集成测、组件测各自测什么？
**答**：
- store/selector 单测（最便宜）：直接 getState/setState 断言纯逻辑，不渲染组件；selector 派生逻辑（合计、过滤）是回归重灾区，必须覆盖边界（空列表、缺失实体）。
- 缓存层集成测：用 msw mock 接口，验证「取数→缓存→失效→重取→乐观更新回滚」整链路；重点断言 key 结构与失效范围（改一条不能把全站刷了）。
- 组件测只测「状态驱动的 UI 分支」：loading/empty/error/data 四态渲染，不重复测缓存细节（下层已测）。
- 反模式：组件测试里 mock 底层 fetch 断言请求参数——那是缓存层测试的职责，重复且脆弱；分层的意义就是每层只测自己的契约。

```javascript
// 1. store 单测：不渲染
test('addCart 合并同商品数量', () => {
  const { addCart } = useCartStore.getState()
  addCart('g1', 1); addCart('g1', 2)
  expect(useCartStore.getState().items).toEqual([{ goodsId: 'g1', qty: 3 }])
})

// 2. 缓存集成测：msw + 独立 QueryClient
test('乐观更新失败回滚', async () => {
  server.use(http.patch('/api/goods/1', () => HttpResponse.error()))
  const qc = new QueryClient()
  qc.setQueryData(['goods', '1'], { id: '1', likes: 1 })
  await expect(likeGoodsWith(qc)).rejects.toThrow()
  expect(qc.getQueryData(['goods', '1']).likes).toBe(1)   // 回滚成功
})

// 3. 组件测：四态分支
test('错误态展示重试按钮', async () => {
  server.use(http.get('/api/goods', () => HttpResponse.error()))
  render(<GoodsList/>, { wrapper: TestProviders })
  expect(await screen.findByRole('button', { name: /重试/ })).toBeInTheDocument()
})
```
