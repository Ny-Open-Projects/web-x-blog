## ZSM-621：状态层优化的渐进式策略：不重构也能拿到 80% 收益

**答**：
- 渐进式三档：**零侵入档**（不动业务代码）：合并 set、persist partialize+节流、devtools 节流、通知批处理——全部是中间件/包装层改动，收益常占一半。**低侵入档**（改订阅点）：selector 拆标量、useShallow、useMemo 派生——改的都是消费端一行代码。**结构档**（动形状）：切片拆分、大数组迁 worker、写时算——收益最大但风险最高，放最后。
- 顺序依据：收益/风险比递减——先做「一次改动全局生效」的中间件优化，再做「局部见效」的订阅点优化，最后才动结构。每档之间立基线对比，确认收益达标就停。
- 风险控制：低侵入档的正确性风险是「useShallow 漏比较嵌套字段」（浅比较不到深差异）——用快照测试守护（优化前后渲染输出一致）；结构档风险是「派生字段脏读」——写路径收口 + 单测覆盖每个 action。
- 团队维度：把渐进策略写成 checklist 进 code review（新 selector 必须标量或带 shallow、新 store 必须声明消费域），防止优化成果被新代码回退。
- 追问钩子：面试时给一个真实数字的案例叙事（基线 → 优化项 → 复测）比罗列技巧更有说服力。

```javascript
// 渐进式优化 checklist（review 用）
const REVIEW_CHECKLIST = [
  { level: '零侵入', item: 'persist 有 partialize 且节流？', check: (store) => store.persist?.partialize != null },
  { level: '零侵入', item: '多次 set 已合并？', check: (action) => action.setCalls <= 2 },
  { level: '零侵入', item: 'devtools 推送节流？', check: (cfg) => cfg.devtoolsThrottle > 0 },
  { level: '低侵入', item: 'selector 返回标量或带 shallow？', check: (sel) => sel.returns === 'scalar' || sel.hasShallow },
  { level: '低侵入', item: '派生有 memo 且输入引用稳定？', check: (d) => d.memoized && d.inputsStable },
  { level: '结构档', item: '新字段过四问评审（谁读谁写多频多大）？', check: (field) => field.reviewed },
  { level: '结构档', item: '写时算派生走唯一写路径？', check: (field) => field.writers === 1 },
]

// 守护测试：优化前后渲染输出一致（快照）
test('优化不改变渲染输出', () => {
  const { container } = render(<CartList />)
  expect(container.firstChild).toMatchSnapshot('pre-optimization')
})
```
