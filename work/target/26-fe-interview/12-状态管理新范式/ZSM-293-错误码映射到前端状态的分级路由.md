## ZSM-293：接口错误码怎么分级路由到前端状态而不是一律 toast

**答**:
- 分级路由：401 → 登录流（全局拦截）；403 → 权限态视图（页面级）；404/410 → 空态；429 → 静默退避重试；5xx → 局部错误+重试按钮；网络错误 → 离线提示
- 落点分层：请求层（拦截器做认证/重试/退避）、cache 层（onError 分级标记）、UI 层（按 error.kind 渲染对应态）——每层只处理自己该处理的
- 业务错误码表：与后端约定错误域（order.* / auth.*），前端按域决定「toast / 局部提示 / 静默」，避免每个调用点散落判断
- 统一出口：错误对象标准化为 { kind, code, message, retryable }，UI 只认 kind，不认原始 HTTP

```javascript
function classify(err) {
  const s = err?.status
  if (s === 401) return { kind: 'unauthenticated' }
  if (s === 403) return { kind: 'forbidden' }
  if (s === 429) return { kind: 'throttled', retryable: true }
  if (s >= 500 || !s) return { kind: 'transient', retryable: true }
  return { kind: 'expected', code: err.code }    // 业务错误
}
// UI: kind==='transient' → 重试按钮；kind==='forbidden' → 权限提示页
```
