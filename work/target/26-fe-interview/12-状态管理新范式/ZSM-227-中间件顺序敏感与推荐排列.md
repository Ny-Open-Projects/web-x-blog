## ZSM-227：多中间件组合的顺序为什么敏感，怎么排

**答**：
- 顺序决定「谁先看到 set 调用」：最外层最先包装、运行时最后收到调用（洋葱模型），内层中间件的副作用会被外层覆盖或放大
- 官方推荐的固定模式：`devtools(persist(...(immer(...))))` 类似分层——devtools 在最外层记录所有包装后的变更；persist 内部要拿到「业务最终 state」才能 partialize 正确
- 典型错序 bug：persist 在 immer 外层时序列化的是草稿结构而非最终 state；devtools 放内层时看不到其他中间件的变更
- 调试手段：在每层中间件入口打印 state 身份/快照，确认执行链与预期一致

```javascript
export const useStore = create<Store>()(
  devtools(            // 最外层：记录一切
    persist(           // 拿到最终 state 做 partialize
      immer(           // 最内层：业务写法
        (set) => ({...}),
      ), { name: 'app' }
    )
  )
)
```
