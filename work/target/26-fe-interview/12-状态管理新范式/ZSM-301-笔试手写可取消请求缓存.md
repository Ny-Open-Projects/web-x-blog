## ZSM-301：手写可取消且防重复的请求缓存
**答**：实现 `cachedFetch(key, fn)`：1) 相同 key 并发调用共享同一 Promise（去重）；2) 成功结果缓存，staleTime 内直接命中；3) 新一轮调用发起时可取消旧请求（AbortController）；4) 组件卸载语义由调用方通过 `dispose(key)` 模拟——dispose 后正在进行的请求被 abort 且不写缓存；5) 失败不缓存。

```javascript
function createCachedFetch({ staleTime = 30_000 } = {}) {
  const inflight = new Map()   // key → { promise, ac }
  const cache = new Map()      // key → { data, ts }

  return {
    fetch(key, fn) {
      const hit = cache.get(key)
      if (hit && Date.now() - hit.ts < staleTime) return Promise.resolve(hit.data)
      if (inflight.has(key)) return inflight.get(key).promise       // 并发去重
      const ac = new AbortController()
      const promise = (async () => {
        try {
          const data = await fn(ac.signal)                          // fn 需透传 signal
          cache.set(key, { data, ts: Date.now() })
          return data
        } finally {
          inflight.delete(key)                                      // 成败都清 inflight
        }
      })()
      inflight.set(key, { promise, ac })
      return promise
    },
    dispose(key) {                                                  // 卸载：取消 + 不缓存
      const cur = inflight.get(key)
      if (cur) { cur.ac.abort(); inflight.delete(key) }
    },
  }
}
```
**评分点**：
- 并发去重必须共享同一 Promise 且 finally 清理 inflight（否则泄漏导致永久去重）
- AbortController 要真正传给底层 fn，而不是只 abort 一个没人听的 signal
- dispose 后 abort 错误不得写入缓存；失败请求不得污染缓存
- staleTime 命中判断要在发请求之前；key 相同才去重（正确区分参数）
