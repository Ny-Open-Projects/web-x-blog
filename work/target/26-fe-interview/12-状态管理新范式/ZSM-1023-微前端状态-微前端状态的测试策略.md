## 1023：微前端状态层的测试策略（跨应用集成）

**答**：
- 测试三层：单应用单测（各子应用 store/机器——独立仓库独立测）、契约测试（事件 schema 与 manifest 的双向校验——发布方验证自己发的符合契约、消费方验证自己能处理契约样本——pact 式双向）、跨应用集成（总线 + 多应用编排——真实交互场景）。
- 契约测试的价值：跨应用集成测试要求所有应用同时在场（环境重），契约测试让「消费方独立验证」（用契约样本 mock 提供方——两两独立验证，集成测试只测编排）。
- 泄漏与生命周期的回归：mount/unmount 20 次内存断言（泄漏回归）、总线订阅计数断言（卸载后订阅归零）。
- 追问钩子：为什么契约测试是微前端测试的核心增量？——单应用测试单体时代就有；微前端新增的风险全在「契约交互」（事件/共享数据）——契约测试正好卡在「独立验证」与「集成成本」的平衡点。

```js
// 契约测试：消费方用契约样本独立验证
describe('order-app consumes user.changed', () => {
  it('handles v1 payload', () => {
    const sample = contractSamples['user.changed'].v1;   // 契约样本
    expect(() => handler(sample)).not.toThrow();
  });
});
// 生命周期回归：mount/unmount 20 次
for (let i = 0; i < 20; i++) { mount(el, deps); unmount(); }
expect(bus.subscriberCount()).toBe(0);                    // 订阅归零
```
