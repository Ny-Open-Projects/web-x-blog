## ZSM-136：把「全家桶 Redux」项目迁移到分层架构，路径怎么规划？怎么不中断业务迭代？
**答**：
- 第一步盘点：把现 store 里的状态分类标注（服务端数据/客户端全局/URL 可代管/局部可下沉），产出迁移清单——多数「全家桶 Redux」里 60% 以上是服务端数据副本。
- 迁移顺序：先增量引入 Query 承接新页面（旧页面不动）→ 逐页把「接口数据」从 Redux 摘出换 Query（Redux 里留一个薄适配 selector 过渡）→ 客户端状态迁 Zustand/Jotai → 最后删适配层。
- 兼容技巧：过渡期让旧 selector 直接读 Query 缓存（`queryClient.getQueryData`），业务组件零改动；双写窗口要短，控制在 1~2 个迭代。
- 保障手段：迁移按页面/模块立小步 PR，关键路径加快照与 E2E，每步可独立回滚。

```javascript
// 过渡期适配：旧组件的 selector 改为读 Query 缓存，组件不动
// 旧代码：const goods = useSelector(s => s.goods.byId[id])
// 新代码：保持同名 Hook 签名，内部换源
export function useGoods(id) {
  return useQuery({ queryKey: ['goods', id], queryFn: () => api.goods(id) }).data
    ?? store.getState().goods.byId[id]   // 迁移尾巴兜底，迁完即删
}
```
