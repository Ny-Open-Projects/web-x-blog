## ZSM-268：服务端状态（Query 缓存）的时间旅行为什么难做

**答**:
- 服务端状态的真相在服务器：缓存只是某一时刻的投影，回放到过去只是恢复「旧投影」，服务端早已变化——时间旅行语义与数据所有权冲突
- 技术面：Query 缓存含 fetchStatus/updatedAt 等运行时元信息，dehydrate/rehydrate 不是为回放设计的；mutation 的副作用更无法逆放
- 可做的近似：调试场景录制 queryKey→data 的时间线（devtools 已有），支持「查看某时刻缓存」而非「真正回到过去」
- 设计启示：时间旅行只对「客户端自治状态」有意义；服务端状态用「失效 + 重拉」表达回退，别硬造缓存回放

```javascript
// 近似方案：缓存时间线录制（调试用）
const timeline = []
queryCache.subscribe((e) => {
  if (e.type === 'updated') timeline.push({ t: Date.now(), key: e.query.queryKey, data: e.query.state.data })
})
// 查看历史：timeline.filter(x => x.key 匹配).slice(-n) —— 只读回看，不写回缓存
```
