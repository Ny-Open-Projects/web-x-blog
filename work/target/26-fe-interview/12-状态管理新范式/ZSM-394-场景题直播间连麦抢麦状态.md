## ZSM-394：场景题示范：直播间连麦抢麦（并发申请/仲裁）状态

**答**:
- 仲裁在服务端：抢麦是竞争资源——申请走请求（幂等），服务端裁决唯一成功者，广播麦位变更；前端绝不本地「先到先得」
- 麦位状态机：空闲→申请中→连麦中→下麦；申请中状态有服务端确认或超时回滚（申请失败静默回到空闲，不发错误弹窗刷屏）
- 一致性：麦位广播带版本号，落后版本丢弃；断线重连拉快照重建麦位
- 本地资源联动：抢到麦后 WebRTC 资源建立（设备权限/推流）失败要主动下麦释放麦位（资源状态与业务状态联动收敛）

```javascript
const applyMic = async () => {
  setStage('applying')
  try {
    const r = await api.applyMic(roomId)          // 服务端仲裁
    if (!r.ok) return setStage('idle')            // 失败静默
    await setupWebRTC()                           // 资源建立
    setStage('live')
  } catch (e) { await api.releaseMic(); setStage('idle') }   // 资源失败释放麦位
}
```
