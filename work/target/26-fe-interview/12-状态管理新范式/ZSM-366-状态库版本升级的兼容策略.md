## ZSM-366：状态库大版本升级（如 Query v4→v5）怎么平稳推进

**答**:
- 升级三步：breaking changes 清单化（官方 migration guide 逐条核对）+ codemod 优先（官方提供）→ 分层替换（hook 签名/回调语义/配置项逐块迁）→ 全量回归（关键流程 E2E）
- 典型 v5 变化：callbacks 移除（onSuccess/onError → cache 事件/effect）、isFetching 语义拆分、placeholderData/keepPreviousData API 变化、双括号泛型必带——这些是面试常考点
- 平行期：新旧版本可短暂共存（v4 封装层未迁的页面继续用 v4，包体积短期翻倍可接受），按页面/模块逐步切换
- 契约回归：持久化结构（persist v4 数据能否被 v5 读）、devtools、SSR dehydrate 兼容都要专项验证

```javascript
// v4 → v5 典型迁移
// v4: useQuery({ queryKey, queryFn, keepPreviousData: true, onSuccess: fn })
// v5:
useQuery({ queryKey, queryFn, placeholderData: keepPreviousData })   // API 变化
useEffect(() => { if (q.isSuccess) fn(q.data) }, [q.data])           // 回调 → effect
```
