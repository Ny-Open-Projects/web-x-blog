## ZSM-585：跨端同步的「可见性暂停」：后台 tab 怎么省流量又不丢消息

**答**：
- 背景：后台 tab 被 Chrome 降频（timer 最小 1 分钟）、断网省电，但 WebSocket 仍占连接——多 tab 场景下非 leader tab、后台 tab 都应该「暂停重活」。可见性暂停的核心：**不是断开同步，而是降级为摘要模式**。
- 分级策略：1) 前台聚焦：全量实时（WS 推送 + 立即渲染）；2) 前台非聚焦：保留 WS 但暂停高频渲染（变更攒批，visibilitychange 时一次性 flush）；3) 后台：降频拉取（每次 visibility 恢复时 diff 拉取）或只收「摘要信号」（version 号），恢复时按版本增量同步。
- 不丢消息的保障：服务端事件带 `seq`，客户端记录 `lastSeq`；恢复时带 `lastSeq` 请求增量（服务端补发缺口），或者直接全量 revalidate（状态量小）。「恢复时全量刷新」通常比增量补发更简单可靠，除非状态树很大。
- 配合 leader 选举：只有 leader tab 保持长连接与轮询，其他 tab 通过 BroadcastChannel 从 leader 转发——整组 tab 只有一条连接，流量最省。
- 追问钩子：`document.visibilityState` 与 `pageshow/pagehide`（bfcache 恢复）都要处理——从 bfcache 恢复时 WS 可能早已断开，必须重连。

```javascript
class VisibilityAwareSync {
  constructor(sync, { broadcast = true } = {}) {
    this.sync = sync
    this.pending = []                       // 非聚焦时攒批
    this.lastSeq = 0
    document.addEventListener('visibilitychange', () => this.onVisibility())
    window.addEventListener('pageshow', (e) => { if (e.persisted) this.reconnect() }) // bfcache
    if (broadcast) this.setupLeaderForward()
  }

  onVisibility() {
    if (document.visibilityState === 'visible') {
      // 恢复：flush 攒批 + 增量补齐
      this.flushPending()
      this.sync.fetchIncremental({ since: this.lastSeq }).then((missed) => {
        missed.forEach((msg) => this.apply(msg))
      })
    } else {
      this.sync.pauseRender()               // 后台：停渲染不.Stream
    }
  }

  apply(msg) {
    this.lastSeq = Math.max(this.lastSeq, msg.seq)
    if (document.visibilityState === 'visible' && document.hasFocus()) {
      this.sync.apply(msg)                  // 聚焦：立即应用
    } else {
      this.pending.push(msg)                // 非聚焦：攒批
    }
  }

  flushPending() {
    this.pending.forEach((m) => this.sync.apply(m))
    this.pending = []
  }

  // leader 模式：非 leader tab 不连 WS，从 leader 转发
  setupLeaderForward() {
    const ch = new BroadcastChannel('sync-forward')
    ch.onmessage = (e) => this.apply(e.data)
    this.sync.onMessage((msg) => { if (this.isLeader) ch.postMessage(msg) })
  }

  reconnect() { this.sync.connect({ since: this.lastSeq }) }  // bfcache 恢复重连
}
```
