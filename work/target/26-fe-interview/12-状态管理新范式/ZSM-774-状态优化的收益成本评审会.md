## ZSM-774：状态优化的收益成本评审：用数据说服团队投入重构

**答**：
- 性能重构要立项就需要「收益成本评审」材料，四段式：1) **问题量化**（基线数据：INP p75、重渲次数、阻塞时长——ZSM-601 的测量，不是「感觉卡」）；2) **收益预估**（方案对标实验数据：同类优化的行业数字 + 本项目小范围 POC 实测）；3) **成本清单**（人日、风险面——重构涉及 N 个订阅点、回滚方案）；4) **验证承诺**（上线后复测同口径 + 回滚标准）。
- 说服力的关键在 **POC 实测**：全量重构前先做单点改造（一个页面 selector 拆分），跑基准对比——有真实数字的提案通过率远高于理论分析。POC 的成本控制在 2-3 人日。
- 成本的诚实申报：状态重构的隐藏成本包括「测试重录」（快照全变）、「联调窗口」（后端接口可能要配合）、以及**学习成本**（团队不熟悉的库/API 要 ramp-up）——漏报这些是评审被打回的主因。
- 优先级矩阵：影响用户数 × 严重程度 vs 成本——「10 万 DAU 页面的 INP 200ms→100ms」优先于「内部工具的重渲优化」，即使后者技术上更漂亮。
- 追问钩子：评审的反面案例——「为了用新库而优化」（趋势驱动）与「为了性能而牺牲可维护性」（transient 满天飞导致状态不可追踪）都要在评审里主动指出并设护栏（transient 只允许在标注的模块用，ZSM-618 形状纪律）。

```javascript
// 收益成本评审模板（立项材料）
const PROPOSAL = {
  title: '购物车渲染性能重构',
  problem: {
    metrics: { inpP75: '280ms', rendersPerAdd: 87, blockingMs: 310 },   // ZSM-601 基线
    affectedUsers: '10万 DAU 购物车路径',
    evidence: 'RUM INP 分布 + Profiler 录制（附报告链接）',
  },
  benefit: {
    poc: '单页 selector 拆分 POC：renders 87→23，blocking 310→46ms（2 人日实测）',
    projection: '全量后预估 INP p75 → 140ms',
    business: '加购转化率预期 +0.3%（行业对标数据）',
  },
  cost: {
    engineering: '5 人日（cart/checkout 拆分 + 订阅点迁移）',
    hidden: ['快照测试重录 1 人日', 'persist migrate 联调 0.5 人日', '团队 Zustand middleware ramp-up 1 人日'],
    risk: '结算链路回归——回滚方案：feature flag 切旧实现',
  },
  verification: {
    postCheck: '上线后 7 天 RUM 对比 + CI 预算门禁常驻（ZSM-616）',
    rollbackCriteria: 'INP p75 未降或对账失败率 >0.5% 即回滚',
  },
  priorities: '10万DAU×P1体验 > 内部工具重构（成本高收益低）',
}
// 护栏声明：transient 只限拖拽模块（ZSM-618 形状纪律），不扩散
```
