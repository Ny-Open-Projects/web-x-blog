## ZSM-753：大表格（10万行）的状态切片策略：行级订阅与聚合分离

**答**：
- 10 万行表格的状态建模三层：**行数据层**（`Map<rowId, Row>`，归一化）、**视图层**（当前窗口的 rowIds + 排序/筛选派生）、**聚合层**（合计/统计，写时算）。行组件订阅自己的 rowId（`useTable(s => s.rows.get(id))`——标量引用），单行更新只重渲一行；整表排序变更才触发窗口层重渲。
- 行级订阅的实现：行组件 key=rowId + selector 按行取——10 万行渲染的是虚拟窗口（~50 行），活跃订阅数 50 个，扇出可控（ZSM-643）；**排序变更的批量通知**是热点——一次 sort 产生 10 万行「新序」，但只有窗口内 50 行真正重渲，前提是行组件的 selector 只依赖 row 引用不依赖 order。
- 聚合的写时算（ZSM-612）：合计行订阅 `s.aggregates.total`（单字段），行更新时 store 内重算聚合（O(n) 但只在变更时）——读侧 O(1)。10 万行全量重算聚合每次 5ms+，批处理合并（一次操作多行变更算一次）。
- 编辑态分离：行内编辑的草稿（正在输入的单元格）独立小 store/atom，不进表格主 store——否则一次击键触发聚合重算。
- 追问钩子：列宽/滚动位置等「视图态」不进主 store（虚拟列表 ZSM-547 的滚动锚定）——表格 store 只管数据，视图态由表格组件内部管理，两层通过受控 props 桥接。

```javascript
// 大表格三层切片
const useTable = create((set, get) => ({
  rows: new Map(),          // 行数据层：rowId -> Row
  order: [],                // 视图序（排序结果）
  aggregates: { total: 0, count: 0 },   // 聚合层：写时算

  updateRow(rowId, patch) {
    set((s) => {
      const rows = new Map(s.rows)
      rows.set(rowId, { ...rows.get(rowId), ...patch })
      // 聚合写时算：一次变更一轮重算
      const total = [...rows.values()].reduce((a, r) => a + r.amount, 0)
      return { rows, aggregates: { ...s.aggregates, total } }
    })
  },

  sortBy(field) {
    set((s) => {
      const sorted = [...s.rows.values()].sort((a, b) => a[field] - b[field])
      return { order: sorted.map((r) => r.id) }   // 只改序：行引用不变 → 行组件不重渲
    })
  },
}))

// 行组件：行级订阅（窗口内 ~50 个活跃订阅）
const Row = memo(function Row({ id }) {
  const row = useTable((s) => s.rows.get(id))       // 只订阅自己
  return <td>{row.name}</td><td>{row.amount}</td>
})

// 聚合组件：单字段订阅
function TotalRow() {
  const total = useTable((s) => s.aggregates.total)  // O(1) 读
  return <td colSpan={2}>合计: {total}</td>
}

// 编辑草稿：独立 atom（不打扰主 store）
const editingCell = atom(null)   // { rowId, field, draft }
// 输入只写 atom；blur 时才 commit 进主 store（触发聚合重算一次）
```
