## ZSM-405：手写增量同步引擎（游标 + 补拉 + 冲突覆盖）
**答**：实现 `createSyncEngine({ fetchDelta, fetchSnapshot })`：1) `start()` 先拉快照建立基线（记 serverCursor），再循环拉增量 `fetchDelta(cursor)` 返回 `{ changes: [{id, data, deleted?, ts}], cursor }`；2) 增量按 id upsert 到本地 store（deleted 用墓碑）；3) 同 id 冲突按 ts 新者胜；4) 断网暂停、恢复后从上次 cursor 继续；5) 提供 `stop()`。

```javascript
export function createSyncEngine({ fetchDelta, fetchSnapshot, apply }) {
  let cursor = null
  let running = false
  let stopped = true

  async function fullSnapshot() {
    const snap = await fetchSnapshot()
    snap.items.forEach((it) => apply({ id: it.id, data: it, type: 'upsert' }))
    cursor = snap.cursor
  }

  async function loop() {
    while (running && !stopped) {
      try {
        const { changes, cursor: next } = await fetchDelta(cursor ?? 0)
        // 同 id 冲突：ts 新者胜（apply 内处理，这里按序透传）
        changes.forEach((c) => apply({ ...c, type: c.deleted ? 'tombstone' : 'upsert' }))
        cursor = next
      } catch {
        await new Promise((r) => setTimeout(r, 3000))       // 断网退避，cursor 不丢
      }
    }
  }

  return {
    async start() {
      stopped = false
      await fullSnapshot()                                  // 基线
      running = true
      loop()
    },
    stop() { running = false; stopped = true },
    getCursor: () => cursor,
  }
}
```
**评分点**：
- 快照基线 + 游标续传结构正确（cursor 与快照同一空间）
- 增量失败不丢游标（catch 里保持 cursor 重试）
- tombstone 区分删除与更新；冲突裁决 ts 新者胜（同 ts 的平局规则可提及）
- stop 幂等且可 restart（cursor 保留支持续传）
