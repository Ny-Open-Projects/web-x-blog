## ZSM-781：状态库的代码分割：store 级懒加载与 chunk 边界

**答**：
- 状态库进首包的隐形体积：Zustand ~1KB 可忽略，但 store 的**业务模块**（重校验器/规则引擎/常量表）常被 store 文件连带拖进首包。分割原则：store 定义轻（状态形状+action 签名），重逻辑单独模块按需 `import()`。
- store 级懒加载三种姿势：1) **路由级**——feature store 随路由 chunk（dynamic import），路由懒加载自然带动 store；2) **动作级**——重 action（如导出 Excel 的数据组装）放独立模块，action 内部 `const { build } = await import('./heavy')`；3) **状态独立**——非首屏 store 完全懒创建（ZSM-611 的 getStore 工厂），引用处动态 import。
- chunk 边界与 store 的坑：**模块级单例 + 动态 import 的双重实例问题**——两个 chunk 各自 import 同一 store 模块，若打包策略不当（如两个入口）会创建两个实例。解法：store 模块强制走单入口（app shell 导出）或 webpack `splitChunks` 共享 chunk。
- 预加载策略：路由 prefetch 时连带 store chunk（`<link rel=modulepreload>` 或路由 loader 里 `import('./feature-store')`）——懒加载不等于延迟体验。
- 追问钩子：状态库代码分割的度量——首包中「状态相关体积」单独统计（bundle analyzer 按 store 目录过滤），目标 < 20KB；业务重逻辑在用到的首帧后 1s 内完成加载（不阻塞交互）。

```javascript
// store 级懒加载三种姿势
// 1) 路由级：feature store 随路由 chunk
// routes/order.tsx
const OrderPage = lazy(() => import('./OrderPage'))        // 页面 chunk 连带 orderStore

// 2) 动作级：重逻辑按需
export const useReportStore = create((set, get) => ({
  report: null,
  exportExcel: async (params) => {
    const { buildWorkbook } = await import('./heavy/xlsx-builder')   // 重模块按需
    const wb = await buildWorkbook(get().report, params)
    return wb
  },
}))

// 3) 状态独立：完全懒创建
// stores/lazy/dashboard.ts
let _store = null
export async function getDashboardStore() {
  if (!_store) {
    const { createDashboardStore } = await import('./dashboard-impl')   // 定义与实现分离
    _store = createDashboardStore()
  }
  return _store
}

// 双重实例防御：store 单入口导出
// apps/web/src/stores/index.ts —— 唯一出口
export { useCartStore, cartStoreApi } from './cart'
// webpack splitChunks: { cacheGroups: { stores: { test: /stores/, name: 'stores', chunks: 'all' } } }

// 预加载：路由 prefetch 连带 store
router.beforeEach((to) => {
  if (to.meta.preloadStore) import(to.meta.preloadStore)   // 提前加载 store chunk
})
```
