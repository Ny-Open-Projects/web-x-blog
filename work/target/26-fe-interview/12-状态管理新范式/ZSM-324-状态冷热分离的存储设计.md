## ZSM-324：大状态树怎么冷热分离（runtime 层与 cache 层）

**答**:
- 热数据（当前交互路径）：进内存 store，订阅粒度细、更新频繁；冷数据（历史页数据/旧游标/归档消息）：出内存进 IndexedDB/缓存层，按需载回
- 边界判定：访问频率（超 N 分钟未触达降级）+ 体积（超阈值强制降级）+ 可再取性（服务端可重取的优先降级）
- 载回协议：冷→热走异步「hydrate on demand」，消费方用 Suspense/loading 承接；热→冷走 LRU 淘汰，淘汰前可选写盘
- 收益：内存曲线平稳（不再随使用时长单调增长）、GC 压力小、persist 负担小

```javascript
// 分层示意
const hotItems = useQuery({ queryKey: ['page', page], queryFn: fetchPage })       // 热：内存缓存
async function loadCold(id) {                                                      // 冷：按需载回
  const cached = await idb.get('doc:' + id)                                        // 先查 IndexedDB
  return cached ?? fetchDoc(id)                                                    // 未命中再请求
}
// 淘汰：LRU 每超 20 条把最旧条目写盘后从内存 store 移除
```
