## ZSM-302：手写乐观更新（回滚 + 409 冲突提示）
**答**：基于一个简化 store 实现 `optimisticUpdate(id, patch, api)`：1) 立即把 patch 应用到本地并标记 `_pending`；2) 调用 `api.update(id, patch, baseVersion)`；3) 成功用服务端返回数据覆盖并清除 pending；4) 普通失败回滚到快照；5) 409 时保留本地编辑并挂 `conflict: serverData` 供 UI 弹对比框。并发多次更新要按序回滚不互相覆盖。

```javascript
function optimisticUpdate(store, id, patch, api) {
  const prev = store.getState().items.get(id)
  if (!prev) return Promise.reject(new Error('not found'))
  store.setState((s) => ({
    items: new Map(s.items).set(id, { ...prev, ...patch, _pending: true }),
  }))

  return api.update(id, patch, prev.version).then(
    (server) => {                                   // 成功：服务端数据覆盖
      store.setState((s) => ({
        items: new Map(s.items).set(id, { ...server, _pending: false }),
      }))
    },
    (err) => {
      const cur = store.getState().items.get(id)
      if (err?.status === 409) {
        store.setState((s) => ({
          items: new Map(s.items).set(id, { ...cur, conflict: err.body.server }),
        }))                                          // 409：保留本地 + 冲突现场
      } else {
        store.setState((s) => ({
          items: new Map(s.items).set(id, prev),     // 普通失败：快照回滚
        }))
      }
      throw err
    },
  )
}
```
**评分点**：
- 乐观写入必须先快照 prev，回滚用「快照覆盖」而不是 reverse patch
- 409 与普通失败分支不同：409 保留本地 + server 数据，普通失败整体回滚
- pending/conflict 标记要落进状态供 UI 区分展示
- 用 Map 新引用（不可变更新），直接改对象引用不会触发订阅
