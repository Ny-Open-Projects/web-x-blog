## ZSM-544：权限接口失败时的缓存降级与保守策略怎么设计

**答**：
- 权限状态的特殊性：它是「安全敏感」状态，失败降级不能像普通数据一样「用旧值凑合」——**默认方向必须是收紧（deny）**：接口失败时按「最小权限」处理，而不是沿用上次可能已撤销的权限。
- 缓存分层：内存缓存（TTL 短，5~10 分钟）→ sessionStorage（会话级）→ 完全失效走 deny。缓存的权限只能用于「展示优化」（隐藏按钮），不能用于「写操作放行」——写操作以服务端校验为准，前端缓存只是体验层。
- 失败策略分级：1) 读接口失败且有缓存 → 用缓存但打标 `stale: true`，界面提示权限可能过期；2) 无缓存 → deny 兜底 + 重试按钮；3) 写操作在权限 stale 时二次确认或拒绝提交。
- 权限刷新时机：切换租户/组织、token 刷新、长时间闲置恢复 focus 时强制 revalidate；不要只在登录时拉一次。
- 追问钩子：前端权限永远只是 UX，真正的安全边界在服务端——面试时主动说这句是加分项。

```javascript
const useAuth = create((set, get) => ({
  permissions: new Set(),
  stale: false,
  phase: 'loading',

  refresh: async () => {
    set({ phase: 'loading' })
    try {
      const { permissions } = await api.getPermissions()
      sessionStorage.setItem('perm', JSON.stringify({ permissions: [...permissions], ts: Date.now() }))
      set({ permissions: new Set(permissions), stale: false, phase: 'ready' })
    } catch {
      // 降级：有缓存用缓存但标 stale；无缓存收紧为空集
      const cached = JSON.parse(sessionStorage.getItem('perm') ?? 'null')
      const isFresh = cached && Date.now() - cached.ts < 10 * 60 * 1000
      set({
        permissions: new Set(cached?.permissions ?? []),
        stale: !isFresh,
        phase: isFresh ? 'ready' : 'degraded',
      })
    }
  },
}))

// 写操作守卫：stale 权限不放行
async function guardedSubmit(action, payload) {
  const { stale, permissions } = useAuth.getState()
  if (stale || !permissions.has(action)) {
    await useAuth.getState().refresh()          // 先刷新再判
    if (!useAuth.getState().permissions.has(action)) throw new Error('forbidden')
  }
  return api[action](payload)                   // 服务端终审
}
```
