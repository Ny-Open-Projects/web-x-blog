## ZSM-863：场景深化：音乐播放器的状态全景（队列+进度+多端接力）

**答**：
- 播放器的状态特征是「媒体层事实 + 队列操作 + 多端接力」，四域：
- 1) **媒体域**：播放进度（currentTime）是媒体层事实——store 只存「锚点」（切歌/暂停时刻），UI 进度条走 timeupdate 事件直写（transient，ZSM-518）；播放模式（循环/随机）进 store。
- 2) **队列域**：播放队列是「可重排列表 + 当前指针」——随机模式 = 乱序指针历史（可回溯上一首：随机也要有历史栈）；队列操作（插入下一首/拖拽排序）用 ZSM-680 的 order+指针模型。
- 3) **接力域**：多端接力 = handoff（746）——进度锚点 + 队列快照迁移；「手机暂停，电脑接着播」的进度校准（±2s 容忍）。
- 4) **缓存域**：音频预加载策略（当前 + 下一条 URL 预解析）+ 播放历史进离线队列（弱网上报 588）。
- 播放器特有「自动下一首与人工切歌竞态」：歌曲自然结束（ended 事件）与用户切歌并发——队列指针操作必须幂等（指针偏移锁），否则跳两首。
- 追问钩子：播放器的「状态最小化」示范——整个播放器 store 只有 5 个字段（queue/queueIndex/mode/anchor/volume），其余全部 transient 或派生——这是「媒体应用状态最小化」的经典范例。

```javascript
// 音乐播放器状态全景
const PLAYER_STATE_MAP = {
  媒体域: {
    core: '进度 = 媒体层事实；store 只存锚点（切歌/暂停时刻）',
    detail: '进度条 timeupdate 直写（518 transient）；播放模式进 store',
  },
  队列域: {
    core: 'order + 当前指针（680）；随机模式 = 乱序指针历史栈（可回溯上一首）',
  },
  接力域: {
    core: 'handoff（746）：进度锚点 + 队列快照迁移；±2s 容忍',
  },
  缓存域: {
    core: '当前+下一条 URL 预解析；播放历史离线队列（588）',
  },
  竞态: 'ended 自动下一首 vs 用户切歌并发 → 指针偏移锁（幂等）',
  状态最小化: 'store 仅 5 字段（queue/queueIndex/mode/anchor/volume）——媒体应用经典范例',
}
```
