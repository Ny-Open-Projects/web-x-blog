## ZSM-332：状态结构大重构怎么做到用户无感迁移

**答**:
- 迁移三阶段：双读（新旧结构并存，读优先新结构回退旧）→ 双写（写时同时更新两份，埋点对比）→ 单写双读灰度收尾删旧；每阶段可独立回滚
- 持久化迁移一次性做：启动时检测旧 key 存在 → migrate 成新 key → 删除旧 key（带备份窗口），避免长期双 key 语义混乱
- 在途兼容：迁移上线瞬间可能存在「旧结构数据 + 新代码」，入口必须能接受两代数据（version 字段判别）
- 验证：迁移函数用真实线上样本回放测试（脱敏抽样），迁移成功率、异常率、恢复耗时进灰度看板

```javascript
function migrateStorage() {
  const old = localStorage.getItem('cart_v1')
  if (!old) return
  try {
    const next = transform(JSON.parse(old))        // 真实样本验证过的转换器
    localStorage.setItem('cart_v2', JSON.stringify(next))
    localStorage.setItem('cart_v1.bak', old)       // 备份窗口 30 天
    localStorage.removeItem('cart_v1')
  } catch (e) { report('migrate_fail', e) }         // 失败保留旧数据下次重试
}
```
