## ZSM-855：场景深化：C 端信息流页面的状态全景（无限流+互动+预渲染）

**答**:
- 信息流（feed）的状态特征是「无限列表 + 高频互动 + 预渲染敏感」，四域：
- 1) **流域**：cursor 列表（695 幂等合并：prepend 新内容/append 加载更多/refresh diff）+ 虚拟窗口（547）+ `placeholderData` 翻页防闪烁。
- 2) **互动域**：点赞乐观（对账器 528）+ 计数 op 合并（584）+「互动态与流分离」（互动数据进独立 Map，不触发流重排）。
- 3) **预渲染域**：首屏 SSR 注入（751）+ 滚动预取（IntersectionObserver 提前 2 屏）+ 图片懒加载 srcset。
- 4) **会话域**：滚动位置恢复（导航返回 ZSM-772）+ 已读去重（内容指纹）。
- 信息流特有的「互动不重排」约束：点赞改变热度排序时应「下一屏生效」——当前可视区冻结排序（快照窗口），用户无感；重排发生在加载下一页时。这是「排序一致性 vs 交互稳定」的经典取舍。
- 追问钩子：信息流的「内存红线」——无限列表的内存增长：虚拟化 + 已滚出窗口的数据页卸载（保留 anchor 便于恢复）+ 互动 Map 上限——长会话 30 分钟内存曲线平稳是验收标准。

```javascript
// C 端信息流状态全景
const FEED_STATE_MAP = {
  流域: {
    core: 'cursor 列表（695）+ 虚拟窗口（547）+ placeholderData 防闪烁',
    detail: 'prepend(WS 新内容)/append(加载更多)/refresh(diff) 幂等',
  },
  互动域: {
    core: '点赞乐观（528）+ 计数 op 合并（584）+ 互动态独立 Map',
    constraint: '互动不触发流重排——独立存储',
  },
  预渲染域: {
    core: 'SSR 注入（751）+ 滚动预取 2 屏 + srcset',
  },
  会话域: {
    core: '滚动位置恢复（772）+ 已读内容指纹去重',
  },
  排序取舍: '可视区冻结排序（快照窗口），重排只在下一页生效——交互稳定 > 排序一致',
  内存红线: '虚拟化 + 滚出窗口页卸载（留 anchor）+ 互动 Map 上限——30 分钟曲线平稳为验收',
}
```
