## ZSM-680：拖拽排序的状态管理：本地序、服务端序与并发重排冲突

**答**：
- 拖拽排序的状态结构：**本地 order: string[]（id 序列）与实体数据分离**——拖拽只改 order 数组（O(n) 移动一个 id），实体不动。高频移动过程用 transient（ref + transform 直写 DOM），drop 才提交到 store（ZSM-518 混合模式）。
- 持久化协议：把 order 差异转为「相邻操作」或「绝对位置字段」。两派：1) **数组整传**（服务端覆写顺序，简单但并发丢更新）；2) **分数定位**（每项存 `rank: number`，插入取相邻 rank 的中值——如 1.5；分数太密时重排分数，rebalance 事件广播）。并发友好是分数派，但实现复杂；内部后台工具用数组整传够用。
- 并发重排冲突：A 拖动 + B 拖动几乎同时提交——服务端按提交序采纳（last-write-wins），客户端收到对账事件后**以服务端 order 为准覆盖本地**；本地若有未提交的拖拽（用户正在拖）要标记「有新变更」提示刷新，而不是静默覆盖。
- 乐观 + 回滚：drop 立即应用本地序 + 异步提交；失败回滚到快照并 toast；成功后服务端返回权威 order 做校准（顺序可能被服务端规则重排）。
- 追问钩子：跨容器拖拽（看板列间移动）状态 = `{ itemColumn: Map<itemId, columnId>, columnOrder: Record<columnId, itemIds[]> }`——归属与序分开存，移动是「改归属 + 两列 order 各 splice」两个原子操作。

```javascript
const useBoard = create((set, get) => ({
  order: ['a', 'b', 'c', 'd'],           // 本地序（拖拽可变）
  snapshot: null,                          // drop 前快照（回滚用）

  onDragStart: () => set({ snapshot: get().order }),
  onDrop(fromId, toId) {
    const next = moveTo(get().order, fromId, toId)   // 纯函数：重排
    set({ order: next })                              // 乐观应用
    api.reorder(next).then((serverOrder) => {
      set({ order: serverOrder })                     // 权威校准（服务端可能重排）
    }).catch(() => {
      set({ order: get().snapshot })                  // 失败回滚
      toast.error('排序保存失败')
    })
  },
  // 服务端对账：他人重排事件
  onRemoteReorder(serverOrder) {
    if (get().snapshot) {           // 用户正在拖：提示而非覆盖
      toast.info('列表已被他人更新，松手后将合并')
    }
    set({ order: serverOrder })
  },
}))

function moveTo(order, fromId, toId) {
  const next = [...order]
  const fi = next.indexOf(fromId)
  next.splice(fi, 1)
  next.splice(next.indexOf(toId) + (fi < next.indexOf(toId) ? 0 : 1), 0, fromId)
  return next
}

// 分数定位插入（并发友好派）
// rank(a=1, b=2) 插中间 → 1.5；密度告警触发 rebalance（等比重排）
function midRank(prev, next) { return (prev + next) / 2 }
```
