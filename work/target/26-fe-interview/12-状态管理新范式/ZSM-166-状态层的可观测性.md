## ZSM-166：状态层怎么加可观测性？渲染次数、缓存命中率、store 体积这些指标怎么落地？
**答**：
- 渲染计数：Why Did You Render / React DevTools Profiler 是开发期工具；生产上轻量做法是给关键组件包 `useRenderCount` 上报（按采样），定位「谁在无谓渲染」。
- 缓存命中率：Query 的 devtools 有面板；生产用 QueryCache 的 onSuccess/onError 钩子统计 fetch 次数与缓存读次数，算出「接口去重收益」。
- store 体积：定期序列化 getState() 量体积，超阈值告警（防止字段越塞越多）；缓存层用 queryCache.getAll().length 监控 key 增长。
- 异常闭环：状态相关错误（undefined 渲染崩溃、竞态串数据）在上报里带「缓存快照摘要」，复现时能对上时间线——可观测性的价值是把「状态类难复现 bug」变成可检索事件。

```javascript
// 1. 渲染计数 HOC（生产采样）
export function trackRender(Component, name) {
  return function Tracked(props) {
    const n = useRef(0)
    n.current++
    useEffect(() => { if (n.current % 20 === 0) report({ name, renders: n.current }) })
    return <Component {...props}/>
  }
}

// 2. 缓存指标：挂 QueryCache 生命周期
const queryClient = new QueryClient({
  queryCache: new QueryCache({
    onSuccess: (_d, q) => metrics.count('query.success', { key: q.queryKey[0] }),
    onError: (e, q) => metrics.count('query.error', { key: q.queryKey[0], code: e.status }),
  }),
})

// 3. store 体积巡检
setInterval(() => {
  const size = JSON.stringify(useShopStore.getState()).length
  if (size > 500_000) alert({ msg: 'store 体积超阈', size })
}, 60_000)
```
