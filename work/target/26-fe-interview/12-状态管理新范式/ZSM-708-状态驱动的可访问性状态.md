## ZSM-708：可访问性状态：aria 属性与 store 状态的映射纪律

**答**：
- a11y 的核心纪律：**aria 状态是 store 状态的投影，不允许手工维护**——`aria-expanded` 必须绑定 store 的 open 字段、`aria-busy` 绑定 fetchStatus、`aria-invalid` 绑定校验错误。手工写死的 aria（`<div aria-expanded="true">` 永真）是 a11y 事故的主要来源。
- 映射清单（常用对应）：store 的 `phase: 'loading' → aria-busy=true`；弹窗栈（ZSM-545）→ `role="dialog" aria-modal` + 焦点管理（打开时 focus 到 dialog，关闭还原）；三态选择（ZSM-537）→ `aria-checked="true|false|mixed"`——半选天然映射 mixed；错误信息 → `aria-live="polite"`（错误区）+ `aria-describedby`。
- 状态语义对齐（ZSM-568 的 tags）：XState 的 tags/状态名与 aria 语义天然同构——`hasTag('busy') → aria-busy`，`matches('error') → role="alert"`；状态机文档同时是 a11y 行为说明书。
- 不可见状态变更的通告：store 变了但 DOM 不动（如后台完成下载）——用 aria-live region 播报（`announce('下载完成')` 写入隐藏 live region），这是「状态变更驱动屏幕阅读器」的唯一通道。
- 追问钩子：a11y 状态测试——Playwright 的 `toHaveAttribute('aria-expanded', 'true')` 纳入组件测试，断言源也是 store（投影一致性测试：改 store → aria 必须跟着变）。

```javascript
// 投影式 a11y 组件
function Accordion({ id }) {
  const open = useAccordion((s) => s.openIds.includes(id))
  return (
    <button
      aria-expanded={open}                    // 绑定 store：open 变 aria 必变
      aria-controls={`panel-${id}`}
      onClick={() => useAccordion.getState().toggle(id)}
    >
      标题
    </button>
  )
}

// 三态选择的 aria-checked
function Checkbox({ node }) {
  const s = useTreeStatus(node)               // 'all' | 'some' | 'none'
  return (
    <input
      type="checkbox"
      aria-checked={s === 'some' ? 'mixed' : s === 'all'}
      aria-disabled={s === 'excluded'}
    />
  )
}

// 不可见变更播报
const liveRegion = create(() => ({ message: '' }))
export function announce(msg) {
  liveRegion.setState({ message: '' })
  requestAnimationFrame(() => liveRegion.setState({ message: msg }))   // 触发重播
}
// 消费：<div aria-live="polite">{message}</div>
// 用法：下载完成时 announce('报表已下载')
```
