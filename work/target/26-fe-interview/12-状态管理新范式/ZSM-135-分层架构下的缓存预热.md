## ZSM-135：分层架构下怎么做缓存预热和预取？路由级、交互级、空闲级三档怎么设计？
**答**：
- 路由级：跳转前 `queryClient.prefetchQuery({ queryKey, queryFn })`（loader/中间件里做），进页即命中缓存零 loading；Next 里用 loader + dehydrate，纯客户端用 prefetch 在链接 hover 时触发。
- 交互级：hover 详情链接预取详情、聚焦输入框预取联想词，把用户「即将发生」的请求提前到交互瞬间。
- 空闲级：requestIdleCallback / setTimeout 0 在首屏稳定后预取下一步大概率要用的数据（如列表第一页的详情批量），要注意配额与取消。
- 纪律：预取必须复用与正式取数完全相同的 queryKey（工厂函数保证），否则预热是无效缓存；预取失败静默，不能打断主流程。

```javascript
// queryKey 工厂：预取与正式取数共用
export const goodsKeys = {
  detail: (id) => ['goods', id],
  list: (q) => ['goods-list', q],
}

// 路由级：链接 hover 预取详情
function GoodsLink({ id }) {
  const qc = useQueryClient()
  const prefetch = () => qc.prefetchQuery({
    queryKey: goodsKeys.detail(id),
    queryFn: () => api.goods(id),
    staleTime: 60_000,
  })
  return <Link to={`/goods/${id}`} onMouseEnter={prefetch}>查看详情</Link>
}

// 空闲级：首屏稳定后预取下一页
useEffect(() => {
  const idle = window.requestIdleCallback?.(() =>
    qc.prefetchQuery({ queryKey: goodsKeys.list({ page: page + 1 }),
                       queryFn: () => api.goods({ page: page + 1 }) })
  ) ?? setTimeout(() => {}, 2000)
  return () => window.cancelIdleCallback?.(idle) ?? clearTimeout(idle)
}, [page])
```
