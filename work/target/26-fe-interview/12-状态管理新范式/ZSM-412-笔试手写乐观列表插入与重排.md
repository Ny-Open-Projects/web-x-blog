## ZSM-412：手写乐观列表（插入/重排/失败恢复原序）
**答**：实现 `optimisticList(store)`：1) `insert(item, at)`：本地立即插入（带临时 id `tmp:*`）；2) `move(id, to)`：本地重排；3) `commit()` 把本地顺序+新条目提交服务端（返回权威列表）；4) commit 失败回滚到提交前快照（临时条目保留为「未保存」态标记，不直接消失）；5) 服务端返回后整体替换并给临时 id 换绑真实 id；6) 并发保护：commit 进行中禁止二次 commit。

```javascript
export function optimisticList(store, api) {
  let committing = false

  return {
    insert(item, at) {
      const tmp = { ...item, id: `tmp:${crypto.randomUUID()}`, _unsaved: true }
      store.setState((s) => ({ list: [...s.list.slice(0, at), tmp, ...s.list.slice(at)] }))
      return tmp.id
    },
    move(id, to) {
      store.setState((s) => {
        const list = [...s.list]
        const from = list.findIndex((i) => i.id === id)
        if (from < 0) return s
        const [x] = list.splice(from, 1)
        list.splice(Math.min(to, list.length), 0, x)
        return { list }
      })
    },
    async commit() {
      if (committing) return            // 并发保护
      committing = true
      const snapshot = store.getState().list
      try {
        const server = await api.saveOrder(
          snapshot.map(({ id, _unsaved, ...rest }) => ({ ...rest, clientRef: id })))
        store.setState({                // 整体替换 + 临时 id 换绑
          list: server.map((it) => ({ ...it, _unsaved: false })),
        })
      } catch (e) {
        store.setState({                // 回滚序，临时条目保留未保存标记
          list: snapshot.map((i) => ({ ...i, _failed: true })),
        })
        throw e
      } finally { committing = false }
    },
  }
}
```
**评分点**：
- 临时 id（tmp:）与换绑协议（clientRef），提交后服务端返回权威列表整体替换
- 回滚保序保条目：失败不吞掉用户输入（_unsaved/_failed 标记驱动 UI 重试）
- 并发 commit 锁（committing）防止双提交乱序
- move 的 from/to 边界（splice 越界取 min）
