## ZSM-174：场景：多租户（SaaS）应用的状态怎么设计？切换租户时缓存和数据边界怎么处理？
**答**：
- 租户身份是「最高层上下文」：tenantId 进 URL（域名/路径）或会话 store，所有 queryKey 必须带 tenantId（`['tenant', tid, 'orders']`），否则 A 租户数据渲染进 B 租户页面是最严重的数据泄露事故。
- 切换租户 = 环境切换：`queryClient.clear()`（或按租户前缀 remove）+ 客户端 store reset + 路由跳转；持久化 store 里带租户标记，恢复时校验「storage 里的 tenantId === 当前 tenantId」不符即丢弃。
- 服务端兜底：每个请求带租户 header/token 作用域，前端缓存清不干净时接口层也要拒绝跨租户访问——前端缓存隔离是体验优化，服务端鉴权才是安全边界。
- 面试要点：主动说出「前端隔离不可信任，安全边界在服务端」。

```javascript
// queryKey 一律带租户前缀
const tk = (tid, key) => ['tenant', tid, ...(Array.isArray(key) ? key : [key])]

export function useOrders(tid) {
  return useQuery({ queryKey: tk(tid, ['orders']),
                    queryFn: () => api.orders(tid), enabled: !!tid })
}

// 切换租户：三步清理
export async function switchTenant(nextTid) {
  const cur = useSessionStore.getState().tenantId
  if (cur === nextTid) return
  await api.checkTenantAccess(nextTid)
  queryClient.removeQueries({ predicate: (q) => q.queryKey[0] === 'tenant' })
  useShopStore.getState().reset()                       // 业务 store reset
  useLocalCart.getState().clear()
  await queryClient.prefetchQuery({ queryKey: tk(nextTid, ['me']),
    queryFn: () => api.tenantMe(nextTid) })             // 预取新租户上下文
  router.replace(`/t/${nextTid}/dashboard`)
}
```
