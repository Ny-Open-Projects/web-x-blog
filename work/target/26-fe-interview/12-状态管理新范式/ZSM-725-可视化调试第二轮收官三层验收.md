## ZSM-725：可视化与调试第二轮收官：采集、隔离、可解释三验收线

**答**：
- 第二轮（ZSM-701~725）落定的三条验收线，团队状态工程达标与否就看它们：
- **采集线**：任何状态 bug 能在 30 分钟内拿到「变更时间线 + DOM 回放 + 复现 JSON」——探针/日志/快照导出齐备（701/707/710），生产有采样通道（617/720）。
- **隔离线**：测试不互相污染（706/707 重置守护）、租户/模块/微前端状态不串（722/724）、HMR 状态策略明确（718/719）——「隔离清单」每个作用域一份。
- **可解释线**：状态架构有 ADR（712）、状态图自动生成（715/716）、埋点与状态同源（720）、a11y 投影纪律（708）——新人 onboarding 一天内能画出状态架构图。
- 三线之外的共识沉淀：a11y/埋点/HMR 这类「状态的外围消费」都要走「投影纪律」——外围系统只读投影不自持状态，这是第二轮最重要的架构结论。
- 收官自检问题清单：能答出「谁改了状态/为什么变/怎么复现/怎么防劣化/架构怎么解释」五个问题，状态工程才算有工具链。

```javascript
// 三验收线的自检清单（团队定期巡检）
const ACCEPTANCE = {
  采集线: {
    items: [
      '探针+日志生产可用（采样）',         // 617/720
      '快照导出/导入白名单+防注入',        // 561
      '回放工具链（状态流+DOM流对齐）',    // 701/553
    ],
    owner: '平台组',
  },
  隔离线: {
    items: [
      '测试重置守护接入 CI',              // 706/707
      '租户 cacheKey + LRU 淘汰',         // 722/724
      'HMR 保留器覆盖全部 store',          // 718/719
    ],
    owner: '各业务组',
  },
  可解释线: {
    items: [
      '新 store 必须有 ADR',              // 712
      '状态图 CI 自动生成',                // 715/716
      'a11y/埋点走投影纪律',               // 708/720
    ],
    owner: '架构组',
  },
}
// 投影纪律：外围系统只读投影、不自持状态 —— 第二轮核心结论
```
