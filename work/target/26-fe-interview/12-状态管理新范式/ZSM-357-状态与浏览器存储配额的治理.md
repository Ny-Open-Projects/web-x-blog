## ZSM-357：localStorage/IndexedDB 配额不足时状态怎么治理

**答**:
- 探测与分级：navigator.storage.estimate() 查用量配额；写入失败（QuotaExceededError）分级处理——裁剪重试（只存必要字段）→ 淘汰旧条目（LRU）→ 放弃持久化（降级为内存）+ 上报
- 预防性治理：persist 前算尺寸（字符串长度估算）、大对象禁止进 localStorage（上限 5MB，走 IndexedDB）、按域设限额（每域最多 N KB）
- 清理优先级：过期缓存（stale 持久化条目）> 低频数据 > 用户草稿（最后清且优先告知）
- 跨域污染：多应用同源共享 localStorage 时要命名空间隔离，清理只清自己的前缀

```javascript
async function safePersist(key, value) {
  try { await idbSet(key, value) }
  catch (e) {
    if (e?.name === 'QuotaExceededError') {
      const est = await navigator.storage.estimate()
      if (evictLRU(est.usage)) return safePersist(key, slim(value))   // 淘汰后重试
      report('storage_full', { key })                                 // 降级内存
    } else throw e
  }
}
```
