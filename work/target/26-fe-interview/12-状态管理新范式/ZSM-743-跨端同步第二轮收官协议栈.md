## ZSM-743：跨端同步第二轮收官：从通道到业务的协议栈总览

**答**：
- 两轮跨端（576-600 通道/协议/收敛 + 726-743 实战协议）合并为完整协议栈，自底向上五层：
- **通道层**：WS/SSE/轮询降级链（731/732）、心跳与退避重连（726）、BroadcastChannel/SharedWorker（576）、原生桥（579/589）。
- **可靠性层**：seq 去重 + 缺口检测（726）、断线追平三策略（727）、ack 机制（726）、乱序缓冲（593）。
- **会话层**：leader 选举（577/599）、可见性暂停（585）、ready 握手（579/587）。
- **业务层**：消息 seq 插入（733/734）、购物车服务端权威合并（736/737）、通知聚合（741/742）、扫码授权（728/729）、流式输出（735）。
- **一致性层**：LWW/op 计数/版本向量（583-596）、离线队列与冲突（588/590/738）、CRDT（591/592）。
- 排查口诀：**消息丢了查通道与追平，顺序乱了查 seq 与缓冲，状态不一致查合并语义与版本裁决，多端不同步查 leader 与会话层**。
- 追问钩子：协议栈的文档化——每层一个「协议契约文档」（信封格式、seq 语义、合并规则），跨团队协作时契约先行，这是「状态协议」成为公共资产的方式。

```javascript
// 协议栈速查（自底向上）
const PROTOCOL_STACK = {
  L1_通道: 'WS(双向) | SSE(单向+续传) | 轮询(兜底) | BroadcastChannel(同源) | 原生桥',
  L2_可靠性: {
    dedupe: 'seq 去重（{tabId,seq} / {deviceId,seq}）',
    gap: '缺口检测 → onGap → 补拉/追平（replay|incremental|snapshot 三策略）',
    ack: 'needAck + 5s 超时重试',
    order: 'hold-back buffer 按 seq 补齐',
  },
  L3_会话: 'leader 选举（WebLocks/心跳）| visibility 分级 | ready 握手 | 单连接聚合',
  L4_业务: {
    message: 'seq 升序二分插入 + 撤回挂起队列',
    cart: '服务端权威 + version 裁决 + pending 保留 + max 合并',
    notify: 'dedupeKey 折叠 + 已读游标 + busy 降级',
    stream: 'delta 去重 + lastEventId 续传 + abort partial',
  },
  L5_一致性: 'LWW(ts+device 决胜) | op 计数 | 版本向量并发识别 | 离线队列 baseVersion 冲突 | CRDT',
}
// 排查口诀：丢→通道追平；乱→seq 缓冲；不一致→合并语义；不同步→leader 会话
```
