## ZSM-720：状态侧的埋点：把业务漏斗事件从状态机迁移自动上报

**答**：
- 埋点与状态结合的核心收益：**从「业务代码里手动埋点」变成「状态机迁移自动产出事件」**——XState 的 transition meta（ZSM-668）或 Zustand 的 action 探针统一产出 `{ event, from, to, duration, context 摘要 }`，漏斗定义与状态定义天然一致（状态机变了埋点自动跟上，不会漏埋）。
- 漏斗建模：下单漏斗 = `submitting → awaitingPayment → paid` 三状态的到达率；用状态日志（ZSM-560）按会话聚合即可算漏斗，不需要额外埋点体系——「状态即埋点」。
- 时长类指标：状态停留时长（awaitingPayment 平均多久）从状态日志的 ts 差值派生——发现「支付页停留 5 分钟的人转化率最高」这类洞察。
- 上报纪律：1) 事件命名规范（`{domain}:{action}:{result}`）与 action 名同构；2) **不埋敏感字段**（金额/手机号进 context 摘要前脱敏）；3) 采样（漏斗页 100%，高频页 1%）；4) 失败静默（埋点失败不影响业务）。
- 与 A/B 的联动：flag 命中（ZSM-683）作为事件属性随行——漏斗可以按实验桶切片分析。
- 追问钩子：埋点架构的反模式——「组件里 this.track()」散点埋点会随重构腐烂；状态侧自动埋点的维护成本集中在「状态定义」一处。

```javascript
// 状态迁移自动埋点桥
function attachAnalytics(actor, { sampleRate = 1, sink = analytics } = {}) {
  actor.subscribe((snapshot) => {
    if (Math.random() > sampleRate) return
    const meta = Object.values(snapshot.meta).at(-1) ?? {}
    if (!meta.analyticsId) return                       // 无 meta 不上报
    sink.track(meta.analyticsId, {
      event: snapshot.value,                            // 状态名
      from: meta.prevValue,                             // 前状态
      dwellMs: meta.enteredAt ? Date.now() - meta.enteredAt : undefined,   // 停留时长
      expBucket: flags.getBucket(),                     // A/B 桶
      ctx: sanitize(meta.trackFields?.(snapshot.context) ?? {}),   // 脱敏摘要
    })
  })
}

// Zustand 版：action 探针 + 漏斗状态白名单
const FUNNEL = new Set(['order/submitting', 'order/awaitingPayment', 'order/paid'])
useOrderApi.setState = new Proxy(useOrderApi.setState, {
  apply(target, thisArg, [updater, replace, name]) {
    target(updater, replace, name)
    if (FUNNEL.has(name)) {
      const { orderId, phase } = useOrderApi.getState()
      analytics.track(name.replace('/', ':'), { orderId, phase, ts: Date.now() })
    }
  },
})

// 漏斗计算（从状态日志聚合）
function funnelStats(events, steps) {
  const sessions = groupBy(events, 'traceId')
  return steps.map((step, i) => {
    const reached = sessions.filter((evts) => evts.some((e) => e.event === step)).length
    return { step, reached, rate: sessions.length ? reached / sessions.length : 0, prev: i > 0 ? steps[i - 1] : null }
  })
}
```
