## ZSM-398：场景题示范：千人千面首页（分桶/模块排序/兜底）状态

**答**:
- 配置即数据：模块布局（顺序/开关/实验桶）来自服务端下发的 layout 配置（进缓存带版本），前端按配置驱动渲染——布局逻辑不在前端写死
- 分桶一致：实验分桶在 layout 响应里由服务端统一下发（前端不自分桶），保证 SSR/CSR 与埋点归因一致
- 兜底链：layout 配置失败 → 使用默认布局（内置常量）+ 上报；单模块数据失败 → 该模块降级占位不阻塞其他模块（模块独立 Query）
- 模块契约：每个模块自治（自己管理自己的数据获取），layout 只管「谁出现、在哪」——模块间不共享状态（除非显式注入）

```javascript
const { data: layout } = useQuery({ queryKey: ['layout', uid, ver], queryFn: fetchLayout })
const modules = layout?.modules ?? DEFAULT_LAYOUT       // 兜底
return modules.map((m) => (
  <ModuleSlot key={m.id} config={m} fallback={<Placeholder />}>   // 单模块降级
    <ModuleRegistry module={m} />
  </ModuleSlot>
))
```
