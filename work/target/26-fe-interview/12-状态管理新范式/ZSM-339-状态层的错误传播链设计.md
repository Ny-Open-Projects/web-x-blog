## ZSM-339：状态层错误怎么传播到 UI 而不炸整个应用

**答**:
- 错误三型三路：数据错误（接口失败）→ 存进状态由 UI 条件渲染；逻辑错误（代码 bug）→ 抛给 ErrorBoundary 隔离子树；环境错误（storage 满/SDK 挂）→ 降级开关静默处理 + 上报
- 传播原则：错误也是状态（error 对象进 store/Query 缓存），但「致命与可恢复」分级——致命才有资格炸边界，可恢复错误永远局部呈现
- 防炸机制：订阅回调隔离（try-catch 每个 listener）、派生函数只读、全局 unhandledrejection 兜底上报不吞
- 用户感知分级：致命（整页错误 + 重试）、模块级（局部降级）、行级（单条失败提示）——错误传播链与 UI 分级一一对应

```javascript
// 分级错误对象
class StateError extends Error {
  constructor(msg, { level = 'recoverable', cause }) { super(msg); this.level = level; this.cause = cause }
}
// 订阅隔离：一个 listener 错不炸其他
for (const l of listeners) { try { l(state) } catch (e) { report(e); if (e.level === 'fatal') throw e } }
```
