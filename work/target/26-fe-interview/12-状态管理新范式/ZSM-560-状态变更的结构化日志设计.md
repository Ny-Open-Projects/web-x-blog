## ZSM-560：状态变更的结构化日志设计：日志里必须有哪些字段

**答**：
- 字段清单（缺一难排查）：`traceId`（贯穿请求/用户会话）、`seq`（变更序号，保序依据）、`ts`、`store`、`action`（命名动作）、`keys`（变更字段，不记值）、`stack`（触发源前 3 帧）、`cause`（上游事件：click/ws/poll）、`durations`（setState 耗时 + 通知耗时分离）。
- 不记什么：状态值（PII 与体积）、高们高频无意义字段（如鼠标坐标 tick）；黑名单由 store 声明，日志层统一过滤。
- 分级：debug 级全量（本地 dev）、info 级采样（生产 1%）、error 级全量（错误时强制带前后各 10 条上下文——「时间窗上下文」是排查的关键，孤立的错误日志没有意义）。
- 存储与查询：本地 IndexedDB 存最近 N 分钟环形缓冲（用户报 bug 时一键导出 JSON 给研发）；生产侧批量上报到日志平台，按 traceId 聚合成时间线。
- 追问钩子：日志的最小可用单位是「变更对」——每次记录必须同时含变更前后的可辨识信息（keys + seq + action），只有 next 没有来源的日志基本无效。

```javascript
function createStructuredLogger({ bufferSize = 200, onFlush } = {}) {
  const buf = []

  function log(entry) {
    buf.push({
      traceId: entry.traceId ?? TRACE.current,
      seq: buf.length,
      ts: Date.now(),
      store: entry.store,
      action: entry.action ?? 'anonymous',
      keys: entry.keys ?? [],
      cause: entry.cause ?? 'unknown',        // click | ws | poll | route
      stack: entry.stack?.split('\n').slice(1, 4),
      durations: { set: entry.setMs, notify: entry.notifyMs },
    })
    if (buf.length >= bufferSize) buf.shift()  // 环形缓冲
  }

  return {
    log,
    recent: (n = 10) => buf.slice(-n),          // 错误时带上下文
    flush: () => onFlush?.(buf.splice(0)),
    exportAll: () => JSON.stringify(buf),       // 用户一键导出
  }
}

// 与 store 集成
const logger = createStructuredLogger({ onFlush: (b) => navigator.sendBeacon('/api/log', JSON.stringify(b)) })
useCartApi.setState = new Proxy(useCartApi.setState, {
  apply(target, thisArg, [updater, replace, actionName]) {
    const t0 = performance.now()
    const prev = useCartApi.getState()
    target(updater, replace, actionName)
    const setMs = performance.now() - t0
    logger.log({
      store: 'cart',
      action: actionName,
      keys: Object.keys(prev).filter((k) => prev[k] !== useCartApi.getState()[k]),
      cause: LAST_INTERACTION.type,
      setMs,
    })
  },
})
window.addEventListener('error', () => console.warn('context', logger.recent(10)))
```
