## ZSM-163：场景：后台管理表格页（筛选/分页/列配置/批量操作）的状态怎么设计最清爽？
**答**：
- 归层：筛选 + 分页 + 排序 = URL 状态（可分享可刷新）；表格数据 = 服务端缓存（key 由 URL 参数派生）；列配置 = 用户偏好 = 持久化 store（按用户 id 存储）；选中行 = 瞬时 store/useState；批量操作的 mutation 结果 → 失效列表缓存。
- 关键设计：「查询参数单一来源」——组件里所有取数参数都从 URL 解析，表单只是 URL 的草稿编辑器，点「查询」才把草稿写入 URL，避免边输边请求。
- 选中跨页语义要明确：跨页全选时存「选中 id 集合 + 排除集合」两种模式，否则翻页选中丢失或误选；操作完成后清空选中并失效列表。
- 面试要点：能指出「列配置不该放 URL」（太长）、「选中不该放缓存」（不是服务端数据）这类归层判断。

```javascript
function OrderTablePage() {
  const [sp, setSp] = useSearchParams()
  const filter = useMemo(() => ({
    page: Number(sp.get('page') ?? 1), status: sp.get('status') ?? 'all',
    kw: sp.get('kw') ?? '',
  }), [sp])

  const orders = useQuery({                       // 数据：缓存层
    queryKey: ['orders', filter],
    queryFn: () => api.orders(filter),
    placeholderData: keepPreviousData,            // 翻页平滑
  })
  const columns = useUserPrefs(s => s.orderColumns)  // 偏好：持久化 store
  const [selected, setSelected] = useState(new Set())// 选中：局部瞬态

  const { mutate: batchShip } = useMutation({
    mutationFn: api.batchShip,
    onSuccess: () => {                            // 操作成功 → 失效 + 清选中
      queryClient.invalidateQueries({ queryKey: ['orders'] })
      setSelected(new Set())
    },
  })
  return <Table filter={filter} onFilter={(f) => setSp(toParams(f))}
                 data={orders.data} columns={columns}
                 selected={selected} onSelect={setSelected}
                 onBatchShip={batchShip}/>
}
```
