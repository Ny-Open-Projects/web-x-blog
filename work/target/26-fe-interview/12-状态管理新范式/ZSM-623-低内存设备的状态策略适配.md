## ZSM-623：低内存设备的状态策略适配：deviceMemory 分级降载

**答**：
- 问题：同一套状态策略在 8G 桌面机和 2G 低端安卓上的表现天差地别——时间旅行缓冲、快照缓存、undo 栈这些「拿空间换体验」的设计在低端机直接 OOM。需要按设备能力分级降载。
- 分级信号：`navigator.deviceMemory`（GB，Chrome）、`navigator.hardwareConcurrency`（核数）、`performance.memory?.jsHeapSizeLimit`（JS 堆上限）、UA/机型表兜底。低配判定：memory <= 2 或 heap limit < 1GB。
- 分级降载清单：1) 历史/时间旅行缓冲：高端 1000 条 → 低端 0（禁用）或 50；2) 快照/调试工具：低端禁用探针（本来就按需开）；3) 派生缓存：低端缩短 TTL 或直接禁用 useMemo 化的长列表缓存；4) 虚拟列表 overscan：低端 2 行 vs 高端 5 行；5) 离线队列容量：低端 100 op vs 高端 2000。
- 运行时自适应比启动分级更好：监听 `performance.memory` 堆增长趋势（连续 GC 后仍高位），动态收缩缓冲——「软 OOM」前主动降级，而不是等崩。
- 追问钩子：降载要可感知——设置面板显示「性能模式已开启」，避免用户误解为功能缺失。

```javascript
// 设备分级
function deviceTier() {
  const mem = navigator.deviceMemory ?? 4
  const cores = navigator.hardwareConcurrency ?? 4
  const heapGB = (performance.memory?.jsHeapSizeLimit ?? 2 ** 31) / 2 ** 30
  if (mem <= 2 || heapGB < 1 || cores <= 2) return 'low'
  if (mem <= 4) return 'mid'
  return 'high'
}

const TIER_CONFIG = {
  high: { historyMax: 1000, overscan: 5, offlineQueueMax: 2000, debugProbes: true },
  mid:  { historyMax: 200, overscan: 3, offlineQueueMax: 500, debugProbes: false },
  low:  { historyMax: 0, overscan: 2, offlineQueueMax: 100, debugProbes: false },
}

// 运行时自适应：堆增长趋势收缩
function adaptiveDownscale(tier, applyConfig) {
  if (!performance.memory) return
  let highStreak = 0
  setInterval(() => {
    const { usedJSHeapSize, jsHeapSizeLimit } = performance.memory
    const ratio = usedJSHeapSize / jsHeapSizeLimit
    highStreak = ratio > 0.8 ? highStreak + 1 : 0
    if (highStreak >= 3) {           // 连续 3 次采样高位（GC 后仍高）
      const cfg = TIER_CONFIG[tier]
      applyConfig({ ...cfg, historyMax: Math.floor(cfg.historyMax / 2) })  // 缓冲减半
      highStreak = 0
    }
  }, 30000)
}

// 应用
const tier = deviceTier()
const config = TIER_CONFIG[tier]
// undo 限长：低端直接禁用时间旅行
createHistory(initial, { limit: config.historyMax || 1 })
```
