## 1031：子应用适配不同主应用版本的适配层设计

**答**：
- 适配动机：同一子应用可能被多个主应用版本加载（灰度期主应用新旧并存/被多个产品线主应用集成）——主应用 API 不同版本（注入参数/事件名不同）。
- 适配层设计：子应用定义「宿主接口」的期望（需要的 capabilities），适配层按宿主版本选择实现（v1 宿主走 legacy 路径/v2 走新 API）——子应用核心代码不感知宿主差异。
- 能力探测优于版本判断：不按 hostVersion 分支（版本号维护累），按「能力探测」（typeof deps.getUser === 'function'——有则用，无则降级）——能力探测对未知版本也健壮。
- 追问钩子：为什么「能力探测」优于「版本号判断」？——版本号假设「v2 一定有 X」（主应用 hotfix 可能回退功能）；能力探测检查「当下有没有」（直接检测事实）——与浏览器特性检测同理。

```ts
// 适配层：能力探测
export function createHostAdapter(deps) {
  return {
    getUser: typeof deps.getUser === 'function'
      ? deps.getUser
      : () => window.__legacy_user,           // 能力降级
    subscribeUser: deps.theme?.subscribe
      ?? legacyBus.subscribe,                  // 能力探测选实现
  };
}
// 核心代码只依赖 adapter，不感知宿主版本
```
