## ZSM-267：结构共享为什么是大状态时间旅行的唯一可行解

**答**:
- 深拷贝快照 100 个 10MB 对象 = 1GB，不可行；结构共享只复制「路径上变化的节点」，未变子树引用复用，单步开销 O(变更路径长度)
- immer 的 produce 天然产出结构共享快照：copyOnWrite 让每次 set 的草稿最终态与历史快照共享 99% 节点
- 配合策略：快照节流（拖拽等连续操作 rAF 级合并）、上限淘汰、大数组用索引化分页快照
- 验证方法：用 Map/Set/Set 记录节点身份，统计「历史 N 步的真实内存」而非「N × 全量大小」；浏览器 devtools 的 Retained Size 是事实标准

```javascript
import { produce } from 'immer'
const history = []
function commit(state, recipe) {
  const next = produce(state, recipe)   // next 与 state 结构共享
  history.push(state)
  if (history.length > 50) history.shift()
  return next
}
```
