## ZSM-792：状态架构反模式自检表：十二种坏味道与重构方向

**答**：
- 状态架构的十二种坏味道（季度巡检的判定依据，每种给出「识别信号 → 重构方向」）：
- 1) **上帝 store**——一个 store 超 500 行/15 个字段 → 按变更频率与消费群体拆切片（ZSM-618）。2) **镜像态**——store A 存了 store B 数据的副本 → 改派生（读时 join）。3) **布尔爆炸**——`isLoading && isSubmitting && !hasError` 组合判断散落 → 状态机化（phase 字段）。4) **订阅泄漏**——组件外 subscribe 无退订 → 平衡检查器 + lint（ZSM-610）。5) **回调级联**——订阅回调里 set 另一个 store → 改派生或显式编排。6) **深路径硬编码**——`state.a.b.c.d` 到处都是 → 归一化 + selector 封装。7) **派生存值**——小计/总数存进 store 但有多写路径 → 写时算收口或读时算。8) **双源竞态**——WS 与 HTTP 都写同一字段无裁决 → 版本号单源裁决（ZSM-737）。9) **过期快照依赖**——闭包里读 getState 旧值 → selector 参数化或事件里现读。10) **全局 mutation**——直接改 store 外部持有的引用（push 不 set）→ 唯一写路径收口。11) **状态即转存**——把 props/路由参数复制进 store → 用 URL/props 为事实源（ZSM-536）。12) **测试盲区**——store 无任何测试 → 金字塔配比补齐（ZSM-783）。
- 自检的执行：巡检脚本自动检出 2/4/6/8/10（可静态分析），1/3/5/7/9/11/12 人工评审。每种坏味道在 registry 标注即生成整改单（ZSM-791 流程）。
- 追问钩子：坏味道的「组合致癌性」——单独的布尔爆炸可忍，布尔爆炸+上帝 store+回调级联叠加是「状态架构死亡三件套」，此时重构优先级高于任何新功能。
