## ZSM-851：场景深化：电商大促页面的状态全景（秒杀+库存+优惠券联动）

**答**：
- 大促页面的状态全景是「高并发 + 强一致 + 限时」三属性叠加，五个状态域的协作：
- 1) **活动域**：phase 派生（ZSM-687）+ 服务端时钟对齐（686）——upcoming 预热倒计时/active 抢购/ended 收尾。
- 2) **库存域**：服务端权威 + 本地乐观扣减显示（「仅剩 N 件」的紧张感）——库存为 0 前端即锁门禁（体验优化），真实扣减服务端裁决；WS 库存推送节流合并（1s 一批）防推送风暴。
- 3) **优惠域**：券池快照（领券后快照金额，ZSM-527 语义）+ 使用互斥（券与活动价二选一派生计算）。
- 4) **下单域**：幂等键 + 排队令牌（服务端发号，前端持令排队——防超卖的用户侧表达）。
- 5) **UI 域**：按钮四态（可抢/已抢完/未开始/已参与）纯派生自前四域，不单独存。
- 联动的关键取舍：**库存显示的「紧张感」与「真实性」平衡**——本地乐观扣减后不再与服务端对账（短会话可接受），显示误差窗口 < 30s。
- 追问钩子：大促的「降级预案」——库存推送断线时退化为轮询（自适应频率 760）、秒杀接口熔断时进入「排队页」而非报错——降级链在业务场景的完整表达。

```javascript
// 大促页面状态全景

  库存域: {
    core: '服务端权威 + 本地乐观扣减（体验层）',
    detail: 'WS 推送节流 1s/批（646）+ 门禁前端锁（687）',
    tradeoff: '紧张感 vs 真实性：乐观后不对账，误差窗口 <30s',
  },
  优惠域: { core: '券池快照（527）+ 券与活动价互斥派生', states: ['已领/未领/已用/过期'] },
  下单域: { core: '幂等键（542）+ 排队令牌（服务端发号）', states: ['排队中/下单成功/失败重试'] },
  UI域: { core: '按钮四态纯派生：可抢/已完/未开始/已参与', rule: '不单独存——派生自前四域' },
  降级预案: {
    库存断线: '退化为自适应轮询（760）',
    秒杀熔断: '排队页而非报错（759 熔断的业务表达）',
    推送风暴: '节流合并（646）',
  },
}
```
