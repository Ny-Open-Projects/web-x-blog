## ZSM-896：状态工程的错误恢复总策略：三层降级与不可用兜底

**答**：
- 全部错误场景的恢复总策略——三层降级模型：
- **D1 数据降级**（数据错/旧）：stale 缓存 + skeleton + 重试（ZSM-544/541/628）——用户看到旧数据但功能可用。
- **D2 功能降级**（功能不可用）：替代路径（排队页/手动复制/离线模式——ZSM-731/740/588）——功能换形式存在。
- **D3 应用降级**（状态层崩溃）：ErrorBoundary + store 重置到初始值 + 会话恢复（快照导入）——最少可用面（登录+浏览）。
- 三层的触发判定：D1 由「查询失败/超时」触发；D2 由「熔断 open/通道全失败」触发；D3 由「未捕获异常/注水失败」触发——每层有独立的监控指标（降级触发数，ZSM-768 P3）。
- 兜底的「最后防线」设计：D3 之后的「只读镜像」——localStorage 上次的持久化快照（persist）以只读模式展示 + 「重新加载」按钮——连 ErrorBoundary 都挂了还有静态内容（SSR HTML 残留）。
- 恢复的「对账闭环」：任何降级恢复后必须 revalidate（753 的恢复纪律：冻结期数据可能过期）——降级不是终点，恢复对齐才是。
- 追问钩子：降级策略的「用户沟通」分级——D1 静默（旧数据无感）、D2 明示（「离线模式」横幅）、D3 致歉（「页面出错已恢复部分功能」）——技术降级映射到用户语言。

```javascript
// 三层降级总策略
const DEGRADATION_MODEL = {
  D1_数据降级: {
    trigger: '查询失败/超时',
    actions: ['stale 缓存展示（544）', 'skeleton（541）', '重试退避（628）'],
    metric: 'D1 触发数（P3）',
    user: '静默——旧数据无感',
  },
  D2_功能降级: {
    trigger: '熔断 open / 通道全失败（731/759）',
    actions: ['排队页（秒杀）', '手动复制（剪贴板）', '离线队列（588）'],
    user: '明示——「离线模式」横幅',
  },
  D3_应用降级: {
    trigger: '未捕获异常 / 注水失败',
    actions: ['ErrorBoundary + store 重置', '快照导入恢复（561）', '只读镜像兜底（persist 静态展示）'],
    user: '致歉——「已恢复部分功能」',
  },
  恢复闭环: '任何降级恢复后必须 revalidate（753 冻结纪律）——降级不是终点，对齐才是',
  触发判定: { D1: '查询失败', D2: '熔断/通道失败', D3: '未捕获异常' },
}
```
