## ZSM-823：白板表达技巧：状态架构图的现场画法与图层顺序

**答**：
- 白板画状态架构图的「图层顺序」（先画什么决定讲解是否顺畅）：
- **第一层：域框**（3-5 个大方框：会话/消息/购物车/UI）——先定空间格局，让面试官有坐标系。
- **第二层：层间箭头**（数据流方向：服务端→缓存→派生→组件）——箭头就是数据流故事线，按箭头顺序讲解最顺。
- **第三层：关键标注**（seq/版本号/乐观标记/leader）——可靠性语义标在箭头上，不是文字堆砌。
- **第四层：故障点**（红笔圈：断线/冲突/超时的处理点）——最后画故障层，主动展示「我想过失败」，是行为分关键。
- 画图纪律：一次只讲一层（画完域框先讲「这几个域是什么」，再画箭头再讲流）——边画边讲会两边都乱；留白 20%（后续追问在留白处补画，展示从容）。
- 远程面试的替代：共享文本画 ASCII 图（域框用 `┌─┐`、箭头用 `→`）或提前准备 mermaid 源码现场渲染——工具准备也是面试素养。
- 追问钩子：图的「自检口令」——画完必说一句「这张图上每个箭头都是一个可测试的数据流，我可以任选一条展开」——把图变成追问的入口而非终点。

```javascript
// 白板图层顺序与 ASCII 范式
const WHITEBOARD_LAYERS = {
  layer1_域框: {
    draw: '3-5 个大方框（会话/消息/购物车/UI态）',
    say: '先讲每个域是什么——建立坐标系',
    rule: '一次只讲一层：画完→讲完→下一层',
  },
  layer2_数据流: {
    draw: '箭头：服务端→WS→缓存→派生→组件（单向）',
    say: '按箭头顺序讲数据流故事',
  },
  layer3_语义标注: {
    draw: 'seq/版本号/乐观标记/leader 标在箭头上',
    say: '可靠性语义嵌入流，不堆文字',
  },
  layer4_故障点: {
    draw: '红笔圈：断线重连/冲突裁决/超时回滚的处理点',
    say: '最后画故障层 =「我想过失败」行为分',
  },
  留白: '留 20% 空间给追问补画',
  自检口令: '每个箭头都是可测试的数据流，任选一条展开',
}

// ASCII 范式（远程面试）
const ASCII_TEMPLATE = `
┌─────────┐    seq/ack     ┌──────────┐
│ 服务端   │ ─────────────▶ │ WS 网关   │
└─────────┘                └────┬─────┘
                                ▼ lastSeq追平
┌──────────────────────────────────────┐
│ 客户端状态层                          │
│  会话Map ──▶ order派生 ──▶ 会话列表   │
│  消息seq ──▶ pending区 ──▶ 聊天窗     │
└──────────────────────────────────────┘
  ⚠断线: 退避重连+追平   ⚠冲突: 版本裁决`
```
