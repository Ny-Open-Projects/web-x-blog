## ZSM-548：灰度配置状态的下发与生效模型：配置变更怎么不重启生效

**答**：
- 配置状态三层：**默认值（代码内置）→ 远端配置（下发覆盖）→ 本地覆盖（调试用）**。合并顺序 local > remote > default，任何一层缺省自动回退，这就是「配置即状态」的分层事实源。
- 下发与生效：页面加载时随 HTML/接口下发快照，运行期通过轮询（低频 5min）或 SSE 长连接推送增量；生效路径——配置变更写入 store，订阅该配置的组件自动重渲；非响应式消费点（如 WebSocket URL）需要「配置变更回调」触发重建，列出所有非响应消费点是审计重点。
- 灰度语义：配置带 `expId + bucket`，用户命中实验桶才用实验值；命中规则（uid hash）在服务端算好下发，前端只存结果，避免把分桶逻辑复制到客户端造成两端不一致。
- 版本与回滚：每次配置变更有版本号，生效的配置记录版本；出问题按版本回滚，前端缓存两版配置可即时切换。
- 追问钩子：配置变更是「事件」不是「状态替换」——关键配置（如 CDN 域名）变更要广播事件让命令式代码响应，纯渲染订阅只覆盖声明式消费。

```javascript
const DEFAULTS = { feedSize: 20, cdnHost: 'cdn.a.com', newCartUI: false }

const useConfig = create((set, get) => ({
  remote: {},                    // 服务端下发
  local: {},                     // 调试覆盖（仅 dev 生效）
  version: 0,

  applyRemote(payload) {
    set({ remote: payload.config, version: payload.version })
    get().onChange?.(payload)    // 通知非响应式消费点
  },

  setLocal(patch) {
    set((s) => ({ local: { ...s.local, ...patch } }))
  },

  get resolved() {} // store 里不放 getter，用下面选择器
}))

// 派生：三层合并 + 层级标签（调试面板显示值来自哪层）
const useConfigValue = (key) => useConfig((s) => {
  if (s.local[key] !== undefined) return { value: s.local[key], from: 'local' }
  if (s.remote[key] !== undefined) return { value: s.remote[key], from: 'remote' }
  return { value: DEFAULTS[key], from: 'default' }
})

// 非响应式消费：配置变更重建连接
useConfig.subscribe((s, prev) => {
  if (s.remote.cdnHost !== prev.remote.cdnHost) {
    wsClient.reconnect(`wss://${s.remote.cdnHost}/ws`)   // 命令式消费点
  }
})
```
