## ZSM-161：场景：电商购物车的前端状态怎么分层设计？本地购物车和服务端购物车怎么合并？
**答**：
- 分层：购物车列表本体是服务端状态（登录后走 Query 缓存 `['cart']`）；未登录的本地购物车是持久化客户端状态（Zustand persist，storage key 带设备维度）；「选中/勾选」是纯客户端瞬时态；价格合计是 selector 派生。
- 合并时机：登录成功回调里把本地车 POST 给「合并接口」，服务端去重返回最终车，前端失效 `['cart']` 重取并清空本地车——绝不在前端做复杂的合并逻辑（重复商品、限购、价格冲突都是服务端规则）。
- 数量修改走乐观更新：本地先改 + mutation 回滚（072 已考机制，这里考整体设计），失败提示并失效重取。
- 面试要点：能说出「购物车本质是服务端聚合视图，前端只有瞬态与乐观副本」的定位。

```javascript
// 本地车（未登录）：持久化 store
const useLocalCart = create(persist((set) => ({
  items: [],                       // [{ goodsId, qty }]
  add: (goodsId, qty = 1) => set(s => ({ items: mergeQty(s.items, goodsId, qty) })),
  clear: () => set({ items: [] }),
}), { name: 'local-cart' }))

// 登录合并 + 缓存失效
export async function mergeCartOnLogin(token) {
  const local = useLocalCart.getState().items
  if (local.length) {
    await api.cart.merge(local)          // 合并规则全在服务端
    useLocalCart.getState().clear()
  }
  await queryClient.invalidateQueries({ queryKey: ['cart'] })   // 服务端车重取
}

// 派生合计：现算不存储
export const selectCartTotal = (s) =>
  s.items.reduce((t, i) => t + i.price * i.qty, 0)
```

**追问**：

1. 未登录加购后登录，合并时价格变了怎么办？→ 合并只合商品与数量，价格一律以服务端返回为准，本地价不参与结算。
2. 合并接口失败但本地车已清空会丢数据吗？→ 顺序必须是合并成功再清空，`clear()` 要在 await 之后；失败保留本地车并提示重试。
3. 多端同时改购物车怎么收敛？→ 服务端按版本号或 updatedAt 做冲突处理，前端以重取结果为准，不要在前端做双向合并。
