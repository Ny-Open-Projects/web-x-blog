## ZSM-126：多标签页之间服务端缓存怎么同步？和 Zustand 跨 tab 同步的差异在哪？
**答**：
- 服务端缓存的天然优势：真源在服务端，跨 tab 同步只需「广播失效信号」而不是广播数据——收到信号的 tab 各自重取即可，数据量小且永不失真。
- 实现路径：BroadcastChannel / storage 事件发 `{ type: 'invalidate', keys }`，对端 tab 收到后 `queryClient.invalidateQueries`；TanStack Query v5 内置了 `broadcastQueryClient` 实验方案，SWR 可用自定义 provider + BroadcastChannel。
- 与 Zustand 跨 tab 的差异：客户端 store 同步必须广播「数据本身」（persist + storage 事件），因为本地状态没有远端真源可回查；缓存同步广播的是「失效意图」。
- 细节坑：失效风暴（一个 tab 改数据全站 tab 重取）要节流；隐私模式下 storage 事件可能不可用，需降级轮询或忽略。

```javascript
// 统一失效总线：写入方广播，各 tab 缓存自行重取
const bc = new BroadcastChannel('app-cache')

export function broadcastInvalidate(prefixes) {
  bc.postMessage({ type: 'invalidate', prefixes })
}

bc.onmessage = ({ data }) => {
  if (data.type !== 'invalidate') return
  data.prefixes.forEach(prefix =>
    queryClient.invalidateQueries({
      predicate: (q) => String(q.queryKey[0]).startsWith(prefix),
    })
  )
}

// 在 mutation 成功后调用
async function updateOrder(id, patch) {
  const order = await api.updateOrder(id, patch)
  broadcastInvalidate(['orders', 'dashboard'])   // 订单域 + 统计域失效
  return order
}
```
