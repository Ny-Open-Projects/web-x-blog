## ZSM-280：编辑器关闭/崩溃前怎么保全未保存状态

**答**:
- 三道防线：自动草稿（debounce 3s 写 storage，带文档 id 与 updatedAt）、beforeunload/pagehide 兜底同步写入（不能异步）、崩溃恢复（启动时检测有未提交草稿 → 提示恢复）
- 数据完整性：草稿带 schema 版本与内容 hash，恢复时校验 hash 防损坏，版本不符走迁移
- 双写策略：草稿（本地，快）与提交（服务端，事务性）分离，提交成功后清草稿；脏标记（isDirty）驱动 UI 提示
- 局限：beforeunload 里只能同步 API，IndexedDB 是异步的，兜底只能 localStorage sync 写小快照

```javascript
useEffect(() => {
  const t = setInterval(() => {                       // 轻量自动保存
    if (dirty) localStorage.setItem(draftKey(id), JSON.stringify({ content, updatedAt: Date.now() }))
  }, 3000)
  const guard = (e) => { if (dirty) { syncWriteDraft(); e.preventDefault() } }  // 兜底
  window.addEventListener('pagehide', guard)
  return () => { clearInterval(t); window.removeEventListener('pagehide', guard) }
}, [dirty])
```
