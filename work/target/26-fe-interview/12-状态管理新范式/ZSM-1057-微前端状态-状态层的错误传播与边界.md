## 1057：跨应用状态错误的传播边界（错误不串门）

**答**：
- 传播风险：子应用未捕获的错误沿事件链传播（订阅者抛错炸掉发布者的调用栈——allSettled 防的是异步传播，同步链仍有风险）；错误边界失效（React ErrorBoundary 只拦本应用渲染树——跨应用边界的错误要用总线错误通道）。
- 边界设计：每个应用边界的「错误闸门」（mount 包裹 try/catch + window.onerror 按应用标签归因——错误归到正确的应用）、总线订阅者的错误收集与上报（带 app 标签）。
- 错误归因的价值：错误带应用标签（哪个应用产生的）——责任矩阵的执行基础（见责任矩阵卡）。
- 追问钩子：为什么跨应用错误要「归因标签」？——无标签的错误日志在微前端里无法定位来源（控制台一堆错不知道谁的）——归因标签是责任矩阵到调试现场的数据桥梁（没有标签的矩阵是空话）。

```ts
// 应用边界错误闸门
export function mount(el, deps) {
  const onErr = e => reporter.error({ app: 'order', ...e });
  window.addEventListener('error', onErr);
  window.addEventListener('unhandledrejection', onErr);
  return () => {
    window.removeEventListener('error', onErr);
    window.removeEventListener('unhandledrejection', onErr);
  };
}
// 总线订阅者错误带标签
bus.subscribe('order.updated', safeHandler('order', handler));
```
