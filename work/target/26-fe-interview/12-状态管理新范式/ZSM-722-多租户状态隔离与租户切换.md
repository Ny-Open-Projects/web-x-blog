## ZSM-722：多租户状态隔离：租户切换时哪些状态要清、哪些要留

**答**：
- 租户切换（切组织/切工作区）的状态清理清单必须显式化，三类判定：1) **必须清**——租户作用域数据（列表缓存、当前选中、草稿里含租户 id 的内容、权限集）；2) **必须留**——用户个人态（theme、语言、快捷键偏好）；3) **带条件留**——跨租户通用的会话（token 留但要 revalidate）。漏清的结果是「切到 B 公司看到 A 公司的数据」——资损级事故。
- 实现模式：租户作用域 store 挂 `tenantId` 命名空间——`scopes: Map<tenantId, TenantState>`（切换时惰性重建或保留缓存），而不是单一 store 里全量换值。切换 = 指针切换 + 订阅通知，天然隔离。
- TanStack Query 侧：租户 id 进 queryKey（`['todos', tenantId]`）或干脆切换时 `queryClient.removeQueries()` + cache 禁用跨租户命中；**推荐 key 含租户**（切回来缓存还在，体验好），但必须配「切换时 cancelQueries」防旧租户响应晚到写入。
- 权限与配置随租户切换：permissions/flags 都是租户作用域——切换时重新拉取（白名单外的缓存全部视为失效，stale 降级按 ZSM-544 收紧策略）。
- 追问钩子：URL 层的租户上下文（`/t/{tenantId}/...`）与 store 同步——store 的 tenantId 必须以路由为事实源（SSR 注入），防 store 与 URL 不一致导致的「前端拿 A 租户调 B 租户接口」。

```javascript
// 租户作用域 store
const useTenantState = create((set, get) => ({
  tenantId: null,
  scopes: new Map(),        // tenantId -> { lists, selection, permissions }

  switchTenant(tenantId, { tenantData, permissions }) {
    // 1) 持久态保留（theme 等），由独立 store 持有，不动
    // 2) 取消在途请求：防旧租户响应晚到
    queryClient.cancelQueries()
    // 3) 指针切换：目标租户惰性建 scope
    const scopes = new Map(get().scopes)
    if (!scopes.has(tenantId)) {
      scopes.set(tenantId, { lists: {}, selection: new Set(), permissions })
    }
    set({ tenantId, scopes })
    // 4) 租户作用域缓存以 key 隔离，切换后 active 租户的 query 正常订阅
    return scopes.get(tenantId)
  },
}))

// queryKey 含租户
const useTenantTodos = () => {
  const tenantId = useTenantState((s) => s.tenantId)
  return useQuery({
    queryKey: ['todos', tenantId],           // 切回来缓存还在
    queryFn: () => api.listTodos(tenantId),
    enabled: !!tenantId,
  })
}

// 清理清单（显式化）
const TENANT_SCOPED_RESETS = [
  'selection',          // 选中集合
  'drafts',             // 含租户 id 的草稿
  'permissions',        // 重新拉取
  'featureFlags',       // 重新拉取（ZSM-544 收紧策略）
]
```
