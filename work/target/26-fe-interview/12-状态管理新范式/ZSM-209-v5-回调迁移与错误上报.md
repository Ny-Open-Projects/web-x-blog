## ZSM-209：v4 到 v5 回调体系怎么迁移，成功失败回调去哪了

**答**：
- v5 删除了 `onError/onSuccess/onSettled` 在 useQuery 上的用法（副作用不可靠且与缓存模型冲突），查询侧统一走 cache 事件或 effect
- mutation 保留 `onMutate/onError/onSuccess/onSettled`，但语义收紧：回调必须幂等、只做副作用，不做派生 state
- 全局默认回调从 `defaultOptions.queries.onError` 改到 QueryCache 构造参数；QueryClient 没了 `QueryClientProvider` 外的 logger 默认值
- 迁移原则：数据派生用 `select`，UI 副作用用组件 effect + `isSuccess`，全局副作用用 cache 事件

```javascript
// ❌ v4 写法（v5 已删除）
useQuery({ queryKey, queryFn, onSuccess: (data) => setLocal(data) })

// ✅ v5：派生用 select
const { data: total } = useQuery({
  queryKey: ['cart'],
  queryFn: fetchCart,
  select: (d) => d.items.reduce((s, i) => s + i.price, 0),
})

// ✅ v5：UI 副作用用 effect
useEffect(() => {
  if (query.isSuccess) analytics.track('cart_loaded', query.data)
}, [query.isSuccess, query.data])
```
