## ZSM-778：微前端状态治理：从「共享 store」到「契约化事件协议」

**答**：
- 微前端状态的反模式演进：直接共享全局 store（主子应用改同一对象）→ 单向 props 下发（主应用当 provider）→ **契约化事件协议**（各自持有状态 + 显式事件交换）。第三阶段的契约：`{ event, schema, direction, qos }` 注册到共享契约表——子应用间不感知彼此的实现，只依赖契约。
- 契约表设计：`registry = { 'user:changed': { schema: {userId, name, avatar}, from: 'shell', to: ['app-a', 'app-b'], qos: 'at-least-once' } }`——schema 校验（运行时 zod）拦截不符契约的消息；qos 区分「必须送达」（重试）与「尽力」（丢弃）。
- 事件总线实现要点：主应用作为 hub（子应用消息经 hub 路由，防子应用直连成网）；消息带 `{ source, seq, schemaVersion }`——source 便于调试归因，seq 去重（ZSM-578 协议复用）。
- 状态所有权的明确化：每个状态字段有唯一 owner（哪个子应用写），其他应用只能「读快照 + 监听变更」——写路径唯一是防「两个子应用同时改主题」类事故的根本。
- 追问钩子：契约的演进治理——schema 变更走「加字段（兼容）→ 双写 → 删旧字段」三步，禁止直接改字段类型；契约表版本化 + 破坏性变更需所有消费方确认（类似 API 网关的契约测试）。

```javascript
// 微前端契约化事件协议
// contracts.ts（共享包，所有子应用依赖）
export const CONTRACTS = {
  'user:changed': {
    schema: z.object({ userId: z.string(), name: z.string(), avatar: z.string().nullable() }),
    from: 'shell', to: ['app-order', 'app-analytics'],
    qos: 'best-effort',
  },
  'cart:updated': {
    schema: z.object({ version: z.number(), count: z.number() }),
    from: 'app-order', to: ['shell'],
    qos: 'at-least-once',
  },
}

// hub（主应用）：schema 校验 + 路由 + seq 去重
class ContractHub {
  #seen = new Map()
  emit(contractKey, payload, source) {
    const c = CONTRACTS[contractKey]
    const parsed = c.schema.safeParse(payload)
    if (!parsed.success) {
      console.error(`[contract] ${contractKey} schema 违反`, parsed.error, 'from', source)
      return false                                  // 契约外消息拦截
    }
    const dedupeKey = `${source}:${contractKey}:${payload.version ?? ''}`
    if (this.#seen.has(dedupeKey)) return false
    this.#seen.set(dedupeKey, Date.now())
    c.to.forEach((app) => this.#route(app, contractKey, payload))
    return true
  }
  #route(app, key, payload) { /* 内部总线/qiankun initGlobalState */ }
}

// 写路径唯一：cart 只有 app-order 能改
// shell 与其他 app 只读 cart:changed 快照 + 监听事件
```
