## ZSM-541：骨架屏的占位数据状态与真实数据怎么平滑切换

**答**：
- 三态模型：`'placeholder' | 'ready' | 'error'` 加上刷新场景的 `'refreshing'`。关键区分：**首屏无数据**（placeholder 骨架）和**刷新已有数据**（保留旧数据 + 局部 loading）是两个状态，共用一个 loading 布尔必然闪骨架。
- 平滑切换的核心：真实数据到达后**不要瞬间替换骨架**——骨架高度和真实内容布局要预先对齐（骨架块尺寸来自接口字段的预估），否则替换瞬间布局跳动（CLS）。列表类用「占位行数 = 真实行数或固定 6 行 + 滚动条预占」。
- 渐进填充：分页/流式数据「旧数据保留 + 新数据追加」而不是整体替换；图表类可做 200ms 淡入过渡。CSS 层面骨架用 `animation: shimmer`，ready 后同一容器换内容类名，避免 DOM 重建。
- 反模式：把骨架做成「每张卡片一个 useState isLoading」——状态提升到数据层（TanStack Query 的 `isPending && isFetching` 组合），组件只消费状态。
- 追问钩子：SSR 场景骨架由服务端直接输出（HTML 里就是骨架），客户端注水后填充，首屏没有「白屏→骨架」的二段跳。

```javascript
const useList = create((set) => ({
  phase: 'placeholder',       // placeholder | refreshing | ready | error
  items: [],
  async load(initial = false) {
    if (initial) set({ phase: 'placeholder' })
    else set({ phase: 'refreshing' })          // 旧数据保留
    try {
      const items = await api.fetchList()
      set({ items, phase: 'ready' })
    } catch {
      set((s) => ({ phase: s.items.length ? 'ready' : 'error' })) // 有旧数据不出 error 页
    }
  },
}))

function ListView() {
  const { phase, items } = useList(useShallow((s) => ({ phase: s.phase, items: s.items })))
  if (phase === 'placeholder') return <Skeleton rows={6} />       // 首屏骨架
  if (phase === 'error' && !items.length) return <ErrorRetry />
  return (
    <ul aria-busy={phase === 'refreshing'}>                       // 刷新时 UI 保持可读
      {items.map((it) => <li key={it.id}>{it.title}</li>)}
    </ul>
  )
}
```
