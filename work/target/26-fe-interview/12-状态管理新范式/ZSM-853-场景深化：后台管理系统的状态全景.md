## ZSM-853：场景深化：后台管理系统的状态全景（列表+权限+多租户）

**答**：
- 后台系统的状态特征是「列表密集 + 权限敏感 + 多租户」，四域协作：
- 1) **列表域**：URL 事实源（筛选/排序/页码，ZSM-536）+ cursor 分页合并（695）+ 行级订阅（753）——后台列表是「查询态」密集区，TanStack Query 为主战场。
- 2) **权限域**：RBAC 派生（532）+ 权限缓存降级（544 收紧策略）+ 两层门禁（flag+perm，683）——后台的「按钮灰显 vs 隐藏」语义要严格。
- 3) **租户域**：scope 隔离（722/724）+ 切换清理清单——后台切租户是高频操作，缓存 key 租户前缀是底线。
- 4) **批量操作域**：结果集归并（693）+ 部分成功展示（691）——后台的核心交互。
- 后台特有的「表格密度」问题：一行 20 列 × 50 行可视——单元格级订阅过细（订阅管理成本）行级订阅过粗（任一格更新全行重渲）——**折中：行级订阅 + 列组件 memo + 编辑草稿独立**。
- 追问钩子：后台状态的最佳实践总结——「URL 管查询态、Query 管数据态、store 管选择态、权限走派生、批量走结果集」五句话即可覆盖 90% 后台场景。

}
