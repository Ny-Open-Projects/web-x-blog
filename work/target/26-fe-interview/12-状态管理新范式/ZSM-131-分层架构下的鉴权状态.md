## ZSM-131：登录态/鉴权信息应该放在哪一层？token、用户资料、权限三者的分层方案是什么？
**答**：
- token：不进任何内存状态库的常态层——httpOnly cookie 最优（XSS 拿不到），退而求其次放 localStorage 但要接受 XSS 风险；内存里由 fetch 封装统一读写，组件永远不碰。
- 用户资料：是服务端数据，用 `['me']` 一个 key 走 Query/SWR 缓存，登出时失效，不要复制进 Zustand。
- 权限：属于「服务端数据的派生 + 客户端规则」，抽成 selector/usePermission Hook，从 ['me'] 缓存派生出 can(action)，组件只问「能不能」不问「角色是什么」。
- 登出要一次清干净：缓存 clear + store reset + URL 回登录页，三层的清理清单放一个 logout 函数里，漏一层就是「登出后还能看到别人数据」的线上事故。

```javascript
// 权限派生：唯一 owner 是 ['me'] 缓存
export function usePermission() {
  const { data: me } = useQuery({ queryKey: ['me'], queryFn: api.me, staleTime: 60_000 })
  return (action) => {
    if (!me) return false
    return me.permissions.includes(action) ||
           me.roles.some(r => ROLE_ACTIONS[r]?.includes(action))
  }
}

function AdminButton() {
  const can = usePermission()
  return can('goods:delete') ? <button>删除</button> : null
}

// 登出：三层清理清单
export async function logout() {
  await api.logout()
  queryClient.clear()                       // 1. 服务端缓存
  useUiStore.getState().reset()             // 2. 客户端 store
  router.replace('/login')                  // 3. URL 与路由
}
```
