## ZSM-365：多个派生值同时读会不会读到「撕裂」的数据

**答**:
- 同一次渲染内多次读 store：React 18 下 useSyncExternalStore 保证同一渲染批次内快照一致（读的是同版本）；风险在「渲染中途外部写入」的历史版本（React 会重放渲染）
- 自定义订阅库要保证：getSnapshot 在无变更期间返回同引用（否则无限重渲染），变更原子（一次 set 一个版本，不存在半更状态）
- 多 atom 读撕裂：Jotai 单 store 内同一渲染一致；跨 store 各自快照可能不同版本——关键联动数据放同一 store 或用 derived atom 聚合
- 业务侧防线：涉及联动的派生（总价 = 明细 × 汇率）在单一派生函数内算完，不在组件里拼两次读取

```javascript
// 联动派生聚合，避免两次读取撕裂
const totalAtom = atom((g) => {
  const items = g(itemsAtom)          // 同一快照内读全
  const rate = g(rateAtom)
  return items.reduce((s, i) => s + i.price * rate, 0)   // 原子计算
})
```
