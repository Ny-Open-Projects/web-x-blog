## ZSM-358：从 URL/storage 恢复的状态是「不可信输入」吗

**答**:
- 是。URL 可被任意构造（用户手改、外部链接、攻击载荷），storage 可被同源其他应用/扩展写——恢复路径必须等同接口响应做校验
- 攻击面：注入非法类型导致渲染崩溃（undefined.filter）、状态注入绕过前端权限 UI（直接设 admin 态——服务端校验才是墙）、超长字符串卡死渲染
- 防线：恢复时 schema 校验 + 字段白名单 + 尺寸上限 + 类型归一化；权限类状态绝不由 URL/storage 恢复，登录后从服务端拉取
- 原则表述：「信任边界内的状态才可信」，一切跨界进入（网络/storage/URL/postMessage）都过同一套校验器

```javascript
const filterSchema = z.object({
  kw: z.string().max(100).default(''),
  page: z.coerce.number().int().min(1).max(1000).default(1),
})
function parseFilters(search) {
  const r = filterSchema.safeParse(Object.fromEntries(new URLSearchParams(search)))
  return r.success ? r.data : filterSchema.parse({})     // 非法整体回默认，不逐字段猜
}
```
