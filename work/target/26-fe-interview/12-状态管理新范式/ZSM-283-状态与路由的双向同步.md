## ZSM-283：状态和路由参数双向同步怎么写才不抖

**答**:
- 单向流优先：URL 是真相源，state 是 URL 的派生（读 URL → 初始化内存态）；需要改状态时改 URL（history API），让派生自然更新，避免双真相
- 必须双向时（如筛选面板即时反馈 + 可分享）：写入合并（用户操作一次 = 一次 pushState）+ 相等短路（URL 已一致则不写），防历史栈污染与循环
- 序列化规范：嵌套对象用紧凑编码（qz 库/自写 encode），undefined 与 null 语义区分，数组有序保证幂等
- 性能：URL 更新用 replaceState 打底（不产生历史噪音），显式操作才 push

```javascript
// 单向派生模式
const [tab, setTab] = useState(() => searchParams.get('tab') ?? 'all')
function switchTab(t) {
  setTab(t)
  const url = new URL(location)
  url.searchParams.set('tab', t)
  history.replaceState({}, '', url)          // 状态 → URL（不产生回环，因为 URL 不反向驱动）
}
```
