## ZSM-702：状态驱动的视觉回归测试：同一状态一棵快照

**答**：
- 传统视觉回归（截图 diff）的脆弱点：加载时机、动画、随机数据导致误报。修正思路：**先固定状态再截图**——测试第一步是「把 store 设置到确定状态」（直接 setState 或注入 mock API），等待 `waitForUIStable`（网络空闲 + 动画结束 + 字体加载），再截图。快照命名含状态语义（`cart-3items-discounted.png`），diff 报告才能定位「哪个状态变了」。
- 状态矩阵生成：组件的状态组合（loading/error/empty/data × 布局）逐个截图——用「状态工厂」批量构造（`renderInState(['loading'], <Table />)`），矩阵化覆盖交互态，避免手写几十个 story。
- 动画/时间敏感元素的处理：`@media (prefers-reduced-motion)` 强制关闭动画、`date` mock 固定时钟（vitest fake timers / 注入 Date）、滚动位置清零——所有「非状态因素」在 fixture 层归一。
- 误报裁决流程：diff 报告 → 检查是否状态等价（同状态不同像素 = 真 bug；不同状态 = 基线过期更新）——把「状态语义」写进快照名就是为了让裁决时能一眼判断。
- 追问钩子：视觉回归的位置——组件级（Storybook + Chromatic，PR 门禁）与页面级（Playwright screenshot，回归巡检），两者状态来源都是「显式 setState」，不要用「点击路径」构造状态（慢且脆）。

```javascript
// 状态工厂 + 稳定等待 + 截图
async function renderInState(page, states, mount = () => {}) {
  await page.goto('/app')
  await page.evaluate((states) => {
    // 显式构造状态（不用点击路径）
    states.forEach(([store, patch]) => window.__stores[store].setState(patch))
  }, states)
  await mount()
  await page.waitForLoadState('networkidle')
  await page.addStyleTag({ content: '*, *::before, *::after { animation: none !important; transition: none !important; }' })
  await page.evaluate(() => document.fonts.ready)
}

test('购物车三态视觉回归', async ({ page }) => {
  const cases = [
    ['cart-empty', [['cart', { items: [] }]]],
    ['cart-3items', [['cart', { items: [FIXTURE_A, FIXTURE_B, FIXTURE_C] }]]],
    ['cart-discounted', [['cart', { items: [FIXTURE_A], coupon: { type: 'flat', amount: 500 } }]]],
  ]
  for (const [name, states] of cases) {
    await renderInState(page, states)
    await expect(page.locator('#cart')).toHaveScreenshot(`${name}.png`, {
      maxDiffPixelRatio: 0.01,
    })   // 快照名 = 状态语义，diff 裁决可读
  }
})
```
