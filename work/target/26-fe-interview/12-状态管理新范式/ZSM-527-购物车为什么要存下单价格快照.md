## ZSM-527：购物车状态为什么必须存价格快照而不是引用商品原始价格

**答**：
- 反模式：cart item 只存 `goodsId + qty`，展示时从商品表 join 出 `price`——商品改价/做活动，购物车显示价与下单价不一致，用户先看到 A 价结算是 B 价，资损与客诉直接来源。
- 正确建模：加入购物车那一刻写入 `price: number` 快照 + `priceVersion`（当时的价格版本号），购物车内所有展示、小计计算都读快照；价格变更由服务端结算时校验。
- 对账机制：展示层可周期性 `refreshPrices()` 拉取最新价并给「已变价」条目打标（红色提示用户重新确认），但不能静默替换快照——变价必须用户可感知。
- 与归一化的边界：商品基础信息（标题/图）可以归一化引用 goods 表（展示不资损），但价格、库存、优惠额度这类「交易敏感字段」必须快照进 cart item。
- 追问钩子：优惠券也是同理——券的可用门槛、折扣力度在「加入结算单」时快照，防止券配置变更导致金额漂移。

```javascript
const useCart = create((set) => ({
  items: [],   // { goodsId, qty, price, priceVersion, title, addedAt }
  add(goods, qty) {
    set((s) => ({
      items: [
        ...s.items,
        {
          goodsId: goods.id,
          qty,
          price: goods.price,          // 快照：交易敏感字段
          priceVersion: goods.priceVersion,
          title: goods.title,
          addedAt: Date.now(),
        },
      ],
    }))
  },
  // 变价检测：只打标不静默改价
  markPriceDrift(drifts) {
    set((s) => ({
      items: s.items.map((it) =>
        drifts[it.goodsId] && drifts[it.goodsId] !== it.price
          ? { ...it, drifted: true, latestPrice: drifts[it.goodsId] }
          : it
      ),
    }))
  },
}))

const subtotal = (items) => items.reduce((a, it) => a + it.price * it.qty, 0) // 永远基于快照
```
