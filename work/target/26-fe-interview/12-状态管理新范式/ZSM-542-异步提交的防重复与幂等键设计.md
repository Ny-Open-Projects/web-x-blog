## ZSM-542：异步提交的防重复状态设计：双击下单怎么防

**答**：
- 前端三层防线：1) **UI 层**：submitting 时按钮禁用/显示 loading；2) **状态层**：提交状态机 `idle → submitting → done/error`，submitting 中直接拒绝再次进入；3) **协议层**：幂等键（idempotency key）——这是唯一能防住「网络超时但请求实际到达」的层。
- 为什么 UI 防不住：双击之间第二次点击可能落在第一次请求发出后（UI 已禁用没问题），但**超时重试**场景（请求超时用户再点）两次请求都会到服务端，没有幂等键就下单两单。
- 幂等键设计：进入表单时生成 UUID，成功后销毁；重试沿用同一 key，服务端以 key 去重（返回首次结果）；网络层重试（fetch retry）也带同 key。
- 状态细节：error 后按钮恢复可点但**生成新幂等键**（明确的新提交），还是沿用旧键（重试同一意图）？取决于业务——支付类沿用（避免双扣），编辑类新键。
- 追问钩子：多 tab 同时下单——幂等键放在 per-tab 的 sessionStorage，配合服务端的用户级并发锁。

```javascript
const useOrder = create((set, get) => ({
  phase: 'idle',       // idle | submitting | done | error
  idemKey: null,

  beginSubmit() {
    const { phase } = get()
    if (phase === 'submitting') return false     // 状态机拒绝重入
    set({
      phase: 'submitting',
      // 空闲进入生成新键；error 重试沿用旧键（支付场景防双扣）
      idemKey: phase === 'error' ? get().idemKey : crypto.randomUUID(),
    })
    return true
  },

  submit: async (order) => {
    if (!get().beginSubmit()) return
    try {
      const res = await fetch('/api/orders', {
        method: 'POST',
        headers: { 'Idempotency-Key': get().idemKey, 'Content-Type': 'application/json' },
        body: JSON.stringify(order),
      })
      if (!res.ok) throw new Error('server reject')
      set({ phase: 'done', idemKey: null })       // 成功销毁键
    } catch {
      set({ phase: 'error' })                     // 键保留供重试
    }
  },
}))

// 按钮层：phase 驱动，双击在状态机就被拦
const phase = useOrder((s) => s.phase)
<button disabled={phase === 'submitting'} onClick={() => useOrder.getState().submit(draft)}>
  {phase === 'submitting' ? '提交中…' : '提交订单'}
</button>
```
