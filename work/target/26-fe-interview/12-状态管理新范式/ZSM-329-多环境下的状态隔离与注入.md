## ZSM-329：测试/预发/生产的环境差异怎么注入状态层

**答**:
- 注入点收敛为三处：API base（请求层）、storage namespace（持久化 key 前缀隔离，防测试污染真实数据）、feature flags——状态层自身不做环境判断
- 持久化隔离是重灾区：测试环境直接读写 localStorage 会覆盖用户真实数据，key 必须带环境前缀（`dev:cart`），或测试用内存 storage stub
- 测试环境状态初始化：可注入初始快照（mock 用户/权限），让 E2E 不用走真实登录链路；种子数据与断言共用同一 fixture
- 环境探测用构建时变量（import.meta.env）编译进代码，运行时 URL 判断只作兜底且要防伪造

```javascript
const env = import.meta.env.MODE            // build 时确定
const ns = `${env}:`
const useStore = create(persist(fn, {
  name: ns + 'cart',                        // dev:cart / prod:cart
  storage: createJSONStorage(() => env === 'test' ? memoryStorage : localStorage),
}))
```
