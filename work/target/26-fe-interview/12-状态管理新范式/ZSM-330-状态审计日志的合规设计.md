## ZSM-330：合规要求下的状态变更审计日志怎么做

**答**:
- 审计域限定：只审计「敏感域」（资金/权限/数据导出/配置变更），不是全量状态——全量日志本身是隐私风险与存储灾难
- 记录四要素：who（用户/租户 id）、what（字段级 diff：old→new，脱敏后）、when（时间戳）、where（来源：UI 操作/服务端同步/系统迁移）；附操作前后快照 hash 做完整性
- 落地位置：状态层 wrapper（set 拦截对敏感 key 打点）优于散落业务代码；日志先本地缓冲批量上报，失败本地暂存防丢
- 完整性与保留：关键域用哈希链（每条含上一条 hash）防篡改，保留期按合规要求，查询侧提供按用户/时间反查

```javascript
function auditWrap(setState, sensitiveKeys) {
  return (patch, meta) => {
    const before = pick(getState(), sensitiveKeys)
    setState(patch)
    const after = pick(getState(), sensitiveKeys)
    const diff = diffFields(before, after)
    if (Object.keys(diff).length)
      auditLog.push({ who: currentUser.id, diff: mask(diff), ts: Date.now(), src: meta?.source,
                      prevHash: lastHash, hash: hashEntry(diff, lastHash) })
  }
}
```
