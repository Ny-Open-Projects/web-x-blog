## ZSM-353：骨架屏状态（何时显示/何时消失）怎么用状态驱动

**答**:
- 判定矩阵：无缓存首载 → 骨架；有缓存后台刷新 → 保留旧内容（不闪骨架）；缓存过期但可展示 → 先旧数据 + 局部 loading 条——三种状态各对应不同 UI，错误是第四态
- 关键区分 isLoading（无数据加载）与 isFetching（有数据的刷新）——TanStack Query 的语义区分就是为骨架策略服务的
- 最小展示时间：骨架闪现 <100ms 反而比不闪更难受——骨架显示加最小 300ms 保留（延迟显示 + 最小时长合并）
- 骨架还原度：骨架结构贴近真实布局（CLS 为零），占位尺寸由数据 schema 推导而不是随便画

```javascript
const q = useQuery({ queryKey, queryFn, staleTime: 30_000 })
const [showSkeleton, setShow] = useState(false)
useEffect(() => {                            // 最小展示时间
  if (q.isPending) { const t = setTimeout(() => setShow(true), 150); return () => clearTimeout(t) }
  setShow(false)
}, [q.isPending])
return q.isPending && showSkeleton ? <Skeleton /> : q.data ? <Content data={q.data} /> : <Error />
```
