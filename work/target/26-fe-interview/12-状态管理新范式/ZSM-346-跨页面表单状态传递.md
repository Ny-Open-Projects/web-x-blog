## ZSM-346：多页面组成的流程（下单→支付→结果）状态怎么传

**答**:
- 按可恢复性分流：流程身份（orderId）进 URL；流程中间态（未提交草稿）进 store + 草稿持久化；已提交事实（订单详情）进服务端缓存按 orderId 查——刷新任何一步都能重建
- 前进防抖：防 URL 手改跳步（支付页校验 orderId 存在且状态为待支付，不满足重定向回前置步）；服务端校验才是硬防线
- 返回语义：已完成步骤允许回看（只读），修改后需重新走后续步骤；「下一步」按钮前置条件依赖缓存状态自动判活
- 流程失败恢复：支付中刷新页面 → 从服务端拉单状态重建流程 FSM（见 ZSM-278），不依赖前端内存

```javascript
// 支付页进入校验
const { data: order } = useQuery({ queryKey: ['order', orderId], queryFn: fetchOrder })
useEffect(() => {
  if (order && order.status !== 'PENDING') navigate(`/order/${orderId}`)   // 防跳步
}, [order])
```
