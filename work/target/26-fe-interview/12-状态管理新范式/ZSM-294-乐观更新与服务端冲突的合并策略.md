## ZSM-294：乐观更新遇到服务端数据已变化怎么合并

**答**:
- 提交时带 baseVersion（乐观锁）：服务端比对版本，一致即成功返回新数据直接落缓存；不一致 409 → 走合并或冲突提示
- 合并策略分级：字段级无交集（我改标题、他改状态）→ 自动合并；同字段 →「服务端优先」或「用户优先」按业务定；结构冲突（他删了我在编辑的行）→ 必须人工决策
- UI 呈现：可自动合并的静默落地，需决策的弹对比面板（local/remote/合并预览三栏）
- 失败恢复：乐观数据标记 pending → 409 后要么回滚要么转为「本地编辑 + 远端基线」双份，让用户在真实基线上重放

```javascript
onMutate: async (vars) => {
  const prev = qc.getQueryData(['doc', id])
  qc.setQueryData(['doc', id], (o) => ({ ...o, ...vars, _pending: true }))
  return { prev }
}
onError: (err, vars, ctx) => {
  if (err.status === 409) {
    qc.setQueryData(['doc', id], (o) => ({ ...ctx.prev, remote: err.body.server }))  // 保留冲突现场
    openConflictDialog({ local: vars, remote: err.body.server })
  } else qc.setQueryData(['doc', id], ctx.prev)   // 普通失败回滚
}
```
