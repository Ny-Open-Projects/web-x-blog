## 997：状态机的错误恢复路径建模（重试/降级/放弃）

**答**：
- 错误恢复的建模三路：重试（error -> retry 事件回原状态，after 延迟+计数 context 限次）、降级（error -> degraded 状态——用备用流程继续）、放弃（error -> failed 终态——用户明确重来）；三种路径在图上显式画出（而不是 try/catch 一把抓）。
- 计数与退避：context.tries 计数，guard 限制最大重试（tries < 3），after 指数延迟（1s/2s/4s）——重试策略是机器定义的一部分（可评审可测试）。
- 恢复的用户可见性：每个错误状态对应 UI 提示（重试中第 N 次/已降级/失败可重来）——状态即 UI（状态机的可预测性延伸到错误处理的可预测性）。
- 追问钩子：为什么错误恢复要「图上显式」？——try/catch 的错误处理藏在代码里（「失败后会发生什么」没人说得清）；状态图上的错误路径是产品/测试都能看见的契约。

```ts
const resilient = createMachine({
  context: { tries: 0 },
  states: {
    running: {
      on: { ERROR: [{ target: 'retrying', guard: c => c.tries < 3 },
                    { target: 'degraded' }] },
    },
    retrying: {
      entry: assign(c => ({ tries: c.tries + 1 })),
      after: { delayMs: c => 1000 * 2 ** c.tries, target: 'running' }, // 指数退避
      on: { GIVE_UP: 'failed' },
    },
    degraded: { type: 'final' },     // 降级可用
    failed: { type: 'final' },       // 明确失败
  },
});
```
