## ZSM-547：虚拟滚动列表的状态建模：窗口偏移和数据窗口怎么维护

**答**：
- 虚拟滚动的状态核心就三个数：`scrollTop`（滚动位置）、`viewportH`（可视高度）、`rowH`（行高或每行实际高度数组）。派生值：`start = floor(scrollTop / rowH) - overscan`、`end = start + ceil(viewportH / rowH) + 2*overscan`，只渲染 [start, end)。
- 状态更新频率问题：scrollTop 是滚动事件高频值——**不进 React 状态**（每次滚动 setState 会卡），放在 ref/rAF 里更新，触发 DOM 层的 translate + 重渲染用 `useSyncExternalStore` 或直接命令式。高度固定时甚至可以纯 CSS 派生，零状态。
- 动态行高：每行实测高度存 `heights: Map<index, h>`，未知的用估高 `estimatedH` 前缀和近似；实测后修正偏移量（累计差值 `offsetAdjust`），这就是「滚动锚定」难题——修正要用 scroll anchoring 防跳变。
- 数据窗口与状态窗口分离：虚拟化只管「渲染哪些行」，数据是否已加载（无限滚动的 fetch 窗口）是另一层——滚到 `end + buffer > loadedCount` 时触发加载，两层状态解耦。
- 追问钩子：scroll anchoring、二分查找定位（不定高时用前缀和 + 二分找 start）、池化 DOM 复用是虚拟列表的三个深水点。

```javascript
class VirtualList {
  constructor(rowH = 40, overscan = 5) {
    this.rowH = rowH
    this.overscan = overscan
    this.heights = new Map()      // index -> 实测高
    this.estimated = rowH
  }

  // 前缀和定位 start（定高 O(1)，不定高二分）
  findStart(scrollTop) {
    let acc = 0, low = 0
    for (const [i, h] of [...this.heights.entries()].sort((a, b) => a[0] - b[0])) {
      if (acc >= scrollTop) { low = i; break }
      acc += h; low = i + 1
    }
    return Math.max(0, low - this.overscan)
  }

  window(scrollTop, viewportH, total) {
    const start = this.findStart(scrollTop)
    let end = start
    let acc = 0
    while (end < total && acc < viewportH) {
      acc += this.heights.get(end) ?? this.estimated
      end++
    }
    return { start: Math.max(0, start - this.overscan), end: Math.min(total, end + this.overscan) }
  }

  // 前方高度修正：实测后调用，返回应补偿的滚动差
  offsetAdjust(startIndex, actualH) {
    const guess = this.heights.get(startIndex) ?? this.estimated
    this.heights.set(startIndex, actualH)
    return actualH - guess      // 上层用 window.scrollBy(diff) 补偿防跳
  }
}

// 渲染容器：总高 = Σheights + (total - measured) * estimated，translate3d 定位窗口
```
