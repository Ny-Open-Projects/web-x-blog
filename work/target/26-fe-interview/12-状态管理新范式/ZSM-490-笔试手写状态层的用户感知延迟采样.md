## ZSM-490：手写用户感知延迟采样
**答**：实现 `trackInteraction(actionName)`：1) 返回 `done()`：调用时计算「点击到状态生效到可见」的完整延迟（INP 语义）；2) 计时三段：输入（sync 更新）→ 渲染（下一帧 rAF）→ 稳定（无 pending 请求）；3) 采样上报：P95 聚合（每分钟上报一次），慢样本（>200ms）带上下文（actionName/pendingQueries）；4) 与 INP 对齐：取「到下一次渲染完成」为感知点；5) 长任务期间自动标记 attribution（长任务来源）。

```javascript
export function createPerceivedLatency(store, report) {
  let pendingStart = null

  function trackInteraction(actionName) {
    const t0 = performance.now()
    let done = false
    return {
      done() {
        if (done) return                                       // 幂等
        done = true
        return new Promise((resolve) => {
          requestAnimationFrame(() => {                        // 下一帧 = 可见
            const visibleAt = performance.now()
            const pending = store.pendingCount?.() ?? 0        // 待定请求（稳定段）
            const sample = {
              action: actionName,
              inputMs: visibleAt - t0,                         // 交互到可见
              pendingQueries: pending,
              slow: visibleAt - t0 > 200,
            }
            report('interaction', sample)
            resolve(sample)
          })
        })
      },
    }
  }

  return { trackInteraction }
}

// 用法（配合按钮 onClick）

```
**评分点**：
- INP 语义对齐（交互到下一帧渲染完成 = 用户感知点）
- rAF 作为「可见」判定（不是 setState 返回就算完成）
- 慢样本带上下文（pendingQueries 归因——慢是因为没等请求还是渲染重）
- done() 幂等（重复调用不产生双样本）
