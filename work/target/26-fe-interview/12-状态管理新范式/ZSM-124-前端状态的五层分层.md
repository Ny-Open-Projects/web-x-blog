## ZSM-124：现代前端的状态分层模型有哪几层？每层该用什么工具、边界在哪？
**答**：
- 常见五层：URL 状态（页码/筛选/路由参数，工具 Next router/query-string）、服务端缓存（TanStack Query/SWR/RSC）、全局客户端状态（Zustand/Jotai）、局部 UI 状态（useState/useReducer）、表单与瞬时状态（react-hook-form/useRef）。
- 判断归属的两个问题：「刷新页面后它还在吗」（在→URL 或持久化，不在→内存层）、「它是从服务端来的吗」（是→缓存层）。
- 典型错层：页码放 store 里不进 URL（刷新丢位置、无法分享）、接口返回的字典放 useState 逐组件请求（不去重不共享）、把表单草稿放进全局 store（生命周期失控）。
- 面试答题结构：先画分层图，再结合项目举例说明某数据放哪层、为什么，最后提「层间通过失效和派生连接，不做双向复制」。

```javascript
// 一张页面的分层示例：商品列表页
// 1. URL 层：?page=2&kw=手机&sort=price
const [sp, setSp] = useSearchParams()
const page = Number(sp.get('page') ?? 1), kw = sp.get('kw') ?? ''

// 2. 服务端缓存层：随 URL 派生的取数
const goods = useQuery({ queryKey: ['goods', { page, kw }],
                         queryFn: () => api.goods({ page, kw }) })

// 3. 全局客户端层：跨页面共享的购物车选中项
const cart = useCartStore(s => s.items)

// 4. 局部 UI 层：本组件私有的展开态
const [expandedId, setExpanded] = useState(null)

// 5. 表单层：搜索输入（提交时才写 URL）
const form = useForm({ defaultValues: { kw } })
// 层间连接规则：URL -> Query 的 key；表单提交 -> 写 URL；Query 失效 -> 缓存重取
```
