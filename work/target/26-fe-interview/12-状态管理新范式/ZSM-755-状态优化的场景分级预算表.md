## ZSM-755：状态优化的场景分级预算表：不同交互类型的性能红线

**答**：
- 「状态变更应该多快」没有统一答案，按交互类型分级定预算（团队制度化的性能红线）：
- **每帧类**（拖拽/手势/滚动联动）：单次变更+渲染 ≤ 8ms（120fps 余量），高频路径禁止 setState 走 transient。
- **输入类**（打字/搜索框）：keydown 到回显 ≤ 16ms，派生计算走 useDeferredValue。
- **点击类**（按钮/切换）：INP ≤ 200ms，状态变更+重渲 ≤ 50ms，超出必须 transition 化。
- **页面级**（路由切换/首次加载）：数据状态就绪 ≤ 500ms（骨架兜底下可放宽到 2s），状态注入 ≤ 100KB。
- **后台类**（轮询/WS 批量应用）：每批 ≤ 30 个组件重渲（扇出红线），批处理间隔 ≥ 100ms。
- 预算的落地：写入 ADR/lint 注释（「此 action 属点击类，预算 50ms」），CI 用 ZSM-616 门禁跑关键场景，超标阻断合并。预算表是「性能九步法」第 8 步（门禁）的输入。
- 追问钩子：预算的来源要有依据——按目标设备 p75 采样（不是旗舰机）定基线，每季度随设备分布复查；预算不达标的例外要走 ADR 豁免（写明原因与限期）。

```javascript
// 场景分级预算表（制度化）

  '点击类': { budget: 50, unit: 'ms 变更+重渲', enforcement: 'transition 化 + CI 门禁', example: '筛选/切tab' },
```
