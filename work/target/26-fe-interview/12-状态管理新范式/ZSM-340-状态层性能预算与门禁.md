## ZSM-340：怎么给状态层定性能预算并进 CI 门禁

**答**:
- 预算四项：单次 setState 处理耗时（P95 < 2ms，含派生与通知）、订阅扇出（单次通知触达组件数 < N）、序列化体积（persist 单条 < 100KB）、selector 执行成本（关键 selector < 0.5ms）
- 度量手段：包装层埋点采集（dev + 性能采样环境）、React Profiler 自动化（Playwright 跑关键交互录 Profiler 数据）、内存快照 diff
- 门禁落地：关键交互脚本在 CI 跑 headless，超预算即 fail 并输出 top 违规 setState；体积类用 bundle 门槛
- 预算治理：预算值随机器基线校准（CI 机器 vs 真机折算），违规分「红线阻断/黄线告警」两级，避免门禁被绕过或误报泛滥

```javascript
// setState 计时包装（CI 用）
const t0 = performance.now()
store.setState(patch)
const dt = performance.now() - t0
if (dt > 2) violations.push({ key, dt, stack: captureStack() })
// 门禁输出：violations 按 dt 排序，红线 > 10ms 直接 fail
```
