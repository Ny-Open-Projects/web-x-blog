## ZSM-441：手写状态树订阅分析器（找出过度订阅）
**需求**：实现 `createSubAnalyzer(store)`：1) 包装 subscribe：记录每个 listener 的「注册路径（组件名）」与每次通知时它是否真正消费了变化（通过 hook：listener 注册时声明关心的 path 列表）；2) `notify(patch, changedPaths)`：listener 关心 path 与 changedPaths 无交集 → 记「无效通知」；3) `report()` 返回无效通知率 top 组件与建议（改用 selector/path 订阅）；4) 支持导出 JSON 供 CI 断言「无效通知率 < 20%」。

```javascript
export function createSubAnalyzer(store) {
  const subs = []                // { name, paths, hits, wasted }

  const origSubscribe = store.subscribe
  store.subscribe = (fn, meta = {}) => {
    const rec = { name: meta.name ?? 'anon', paths: meta.paths ?? ['*'], hits: 0, wasted: 0 }
    subs.push(rec)
    return origSubscribe((...args) => { rec.hits++; return fn(...args) })
  }

  const origSet = store.setState
  store.setState = (patch, _a, changedPaths = inferPaths(patch)) => {
    subs.forEach((r) => {
      const relevant = r.paths.includes('*') || changedPaths.some((p) =>
        r.paths.some((rp) => p.startsWith(rp) || rp.startsWith(p)))
      if (!relevant) r.wasted++                                  // 无效通知计数
    })
    return origSet(patch)
  }

  function report() {
    return subs.map((r) => ({ ...r, wasteRate: r.hits ? r.wasted / r.hits : 0 }))
      .sort((a, b) => b.wasteRate - a.wasteRate)
  }
  return { report, exportJSON: () => JSON.stringify(report()) }
}

function inferPaths(patch) { return Object.keys(patch) }   // 简化：顶层 key
// 建议：wasteRate > 0.8 的组件改用 path 订阅或 selector 收窄
```
**评分点**：
- 无效通知判定（关心 path 与变更 path 无交集）——过度订阅的量化
- 通配订阅（'*'）永远 relevant 的保守语义正确
- 建议输出（wasteRate 排序 + 修复方向）——工具要有可行动性
- CI 断言接入（exportJSON + 阈值），防回归
