## ZSM-171：场景：多步审批流页面的状态怎么设计？「流程态」和「页面态」怎么避免搅在一起？
**答**：
- 分离两类状态：流程态（当前节点、审批历史、可执行动作）是服务端数据，owner 是缓存 `['approval', id]`；页面态（表单草稿、展开面板、附件上传进度）是客户端状态，owner 是组件/store。
- 可执行按钮由流程态派生：`canApprove = flow.currentNode.role === me.role && flow.status === 'pending'`，写进 selector；组件永远不自己判断「我能不能批」，防止流程态更新后按钮忘记刷新。
- 审批提交是 mutation：成功后失效流程缓存；驳回带意见走乐观 UI 要谨慎（131/128 已考权限与乐观边界），审批动作建议悲观渲染 + pending 态，因为结果对其他角色可见且有外部通知。
- 面试要点：审批流的状态机本质（节点 × 事件）可以画出来，说明「页面态围绕流程态派生渲染」。

```javascript
function ApprovalPage({ id }) {
  // 流程态：服务端缓存
  const { data: flow } = useQuery({ queryKey: ['approval', id],
                                    queryFn: () => api.approval(id) })
  const { data: me } = useQuery({ queryKey: ['me'], queryFn: api.me })
  // 页面态：本地
  const [comment, setComment] = useState('')
  const [uploading, setUploading] = useState(0)

  // 可执行动作派生：唯一判定点
  const canAct = flow?.status === 'pending' && me?.role === flow?.currentNode?.role

  const { mutate: approve, isPending } = useMutation({
    mutationFn: (v) => api.approve(id, v),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['approval', id] }),
  })

  return <Flow flow={flow}>
    {canAct && <ApprovalPanel
      comment={comment} onComment={setComment} uploading={uploading}
      onApprove={(pass) => approve({ pass, comment })} pending={isPending}/>}
  </Flow>
}
```
