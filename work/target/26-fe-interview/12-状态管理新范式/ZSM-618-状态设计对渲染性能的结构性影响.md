## ZSM-618：状态「形状」设计对渲染性能的结构性影响：高耦合树 vs 分离切片

**答**：
- 状态「形状」（shape）决定性能上限：所有数据塞一个大 store、深层嵌套高耦合——任何变更都在同一棵订阅树里传播，重渲是结构性的（selector 怎么拆都省不回来）。
- 分离原则三条：1) **变更频率分离**——高频字段（滚动位置、输入草稿）与低频字段（用户资料、配置）不同 store/不同切片，避免高频更新打爆低频订阅者；2) **消费群体分离**——不同组件树消费的字段分开（侧边栏状态 vs 主内容状态），缩小通知半径；3) **读写分离**——服务端数据（查询缓存）与客户端 UI 态分开（TanStack Query + Zustand 各管一摊），缓存失效不牵连 UI。
- 反模式对照：把「表单草稿」和「提交状态」「历史记录」放一个对象——输入一个字符触发提交按钮、历史列表、校验区全重算；拆成三个切片后各管各的。
- 形状重构的成本评估：结构性拆分要在早期做（拆 store、拆 atom 域），后期做成本高（所有订阅点迁移）；selector 层优化是「打补丁」，形状设计是「根治」。
- 追问钩子：形状评审清单——每个新字段问「谁读、谁写、多频、多大」四问，不通过就不进当前切片。

```javascript
// 反模式：高耦合树
const state = {
  user: { ... },
  formDraft: { title: '', body: '' },     // 高频：每键一次
  submitState: 'idle',                    // 低频
  history: [],                            // 中频
}
// 输入一个字 → user/formDraft/submitState/history 的订阅者全部比对

// 重构：按变更频率与消费群体分离
const useFormDraft = create(() => ({ title: '', body: '' }))     // 高频，只被编辑器订阅
const useSubmit = create(() => ({ phase: 'idle' }))              // 低频，只被按钮订阅
const useHistory = create(() => ({ entries: [] }))               // 中频，只被历史面板订阅
const useUser = create(() => ({ profile: null }))                // 独立域

// 形状评审清单
function reviewShape(field, { readers, writers, freqHz, sizeKB }) {
  const issues = []
  if (freqHz > 10 && sizeKB > 100) issues.push('高频大对象：考虑 transient 或 worker')
  if (readers > 20 && freqHz > 1) issues.push('宽读高频：拆切片或 selector 细化')
  if (writers > 1) issues.push('多写路径：收口为唯一 action（防脏派生）')
  return issues
}
```
