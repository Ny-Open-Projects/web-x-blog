## ZSM-286：从 Redux 迁移到 Zustand/Query 怎么渐进式推进

**答**:
- 先分层再替换：把存量 Redux 状态分三类——服务端数据（迁 TanStack Query）、UI/业务态（迁 Zustand slice）、跨页全局单例（可暂留）；一次性大迁移必炸
- 桥接期双库共存：Redux store 与新 store 并存，写路径单点化（写新库后同步 dispatch 兼容层），消费方按模块逐个切换读取
- 兼容层实现：监听新 store 变化 → dispatch 到 Redux（或反之），限期拆除（加 TODO 与监控覆盖率，迁移完即删）
- 验收指标：模块级 store 读写统计、双写不一致告警、按模块灰度切流

```javascript
// 兼容桥：新 store → 老 Redux（只读消费方未迁移时）
useCartStore.subscribe((s) => {
  legacyStore.dispatch({ type: 'cart/sync', payload: s })   // 兜底读取
})
// 迁移完成后删除此桥，监控双写差异
```
