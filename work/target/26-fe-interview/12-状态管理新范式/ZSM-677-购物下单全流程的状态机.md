## ZSM-677：下单全流程的状态机：从提交到支付超时的完整建模

**答**：
- 下单流程的事件与状态必须穷举：提交中（锁单防重）→ 创建成功（进入 15min 支付倒计时）→ 支付中（跳转第三方，回来要对账）→ 支付成功/失败/超时关单 → 取消（用户主动，需在未支付时）。漏掉任何中间态（如「支付返回但服务端未确认」）就是线上 bug 源。
- 关键设计点 1：**支付中状态的三次落点**——跳转第三方回来后本地不知道结果（回调可能未达），状态机在 `awaitingResult` 状态轮询服务端订单状态（带超时上限），结果驱动迁移而不是「假设成功」。这就是「done 是服务端事实」（ZSM-533）的交易版。
- 关键设计点 2：**倒计时用 after 而不是 setInterval**——离开支付中状态定时器自动清除；倒计时只是 UI 显示（context.remaining 每秒减），真正迁移由服务端关单事件或本地 after 兜底。
- 关键设计点 3：**final 状态只有 paid/cancelled/expired**——不可逆终点；重试/重开订单是「新订单新实例」，旧 actor 只读展示（历史不可变）。
- 与对账器的关系：乐观场景（本地已跳支付页）+ 服务端事件双源，冲突时以服务端为准覆盖本地状态机（ZSM-528 的 confirm 语义）。
- 追问钩子：支付回调的乱序（先收到成功后收到超时关单事件）用「状态迁移的方向守卫」防御——expired 只能从 awaitingPayment 进入，已 paid 的实例忽略关单事件。

```javascript
import { setup, createActor } from 'xstate'

const orderMachine = setup({
  actors: { pollStatus: fromPromise(({ input }) => api.getOrderStatus(input.orderId)) },
  delays: { payTimeout: 15 * 60 * 1000 },
}).createMachine({
  id: 'order',
  context: ({ input }) => ({ orderId: input.orderId, remaining: 15 * 60, error: null }),
  initial: 'submitting',
  states: {
    submitting: {                       // 锁单：防重复提交
      invoke: { src: 'createOrder', input: ({ context }) => ({ items: context.items }),
        onDone: { target: 'awaitingPayment', actions: assign({ orderId: ({ event }) => event.output.id }) },
        onError: 'createFailed' },
    },
    createFailed: { on: { RETRY: 'submitting' } },
    awaitingPayment: {
      after: { payTimeout: { target: 'expired', guard: ({ context }) => !context.paid } },
      on: { PAY_NOW: 'redirecting', CANCEL: 'cancelled' },
    },
    redirecting: {                      // 跳第三方支付页
      on: { BACK: 'awaitingResult' },   // 返回后必须对账
    },
    awaitingResult: {                   // 轮询服务端拿真实结果
      invoke: { src: 'pollStatus', input: ({ context }) => context,
        onDone: [
          { guard: ({ event }) => event.output.status === 'paid', target: 'paid' },
          { guard: ({ event }) => event.output.status === 'closed', target: 'expired' },
          { target: 'awaitingResult', reenter: true },   // 未定：继续轮询
        ],
        onError: 'pollFailed' },
    },
    pollFailed: { after: { 5000: 'awaitingResult' } },  // 轮询失败退避重试
    paid: { type: 'final' },
    cancelled: { type: 'final' },
    expired: { type: 'final' },         // 三个不可逆终点
  },
})
```
