## ZSM-164：场景：白板/画布编辑器的状态怎么设计？高频拖拽为什么不能用常规 store 逐帧同步？
**答**：
- 三态分离：文档模型（元素树）= 结构化 store（Zustand 归一化）；视口/工具态 = 轻量 store 或 ref；拖拽等高频瞬时值 = ref/动画帧局部变量，**不进响应式系统**（transient update 思路，031 已考 Zustand 版，这里考画布整体）。
- 高频更新的正确姿势：pointermove 里直接改 canvas 引擎（原生对象），requestAnimationFrame 统一提交；结束时才把最终位置 set 进 store 触发一次重渲染 + 写协作历史。逐帧 set 会让 React 每帧 reconciliation，60fps 直接崩。
- 协作（CRDT/yjs）接法：yjs 是真源，y-observer 批量把文档变更映射进 store（或组件直接订阅 yjs 事件绕过 React），撤销栈用 yjs UndoManager。
- 面试要点：说出「React 渲染频率 ≠ 交互频率」的分层思想，瞬态数据用 ref/引擎承载。

```javascript
// 画布三层结构
const useDocStore = create((set) => ({
  shapes: { byId: {}, allIds: [] },               // 文档模型：低频、归一化
  commitShape: (id, patch) => set(s => /* 归一化局部更新 */),
}))
const viewport = { x: 0, y: 0, scale: 1 }         // 视口：ref 命令式，不渲染
const dragging = { id: null, dx: 0, dy: 0 }       // 瞬态：普通对象

canvas.addEventListener('pointermove', (e) => {
  dragging.dx += e.movementX
  engine.move(dragging.id, dragging.dx, dragging.dy)  // 逐帧只进引擎
})
canvas.addEventListener('pointerup', () => {
  useDocStore.getState().commitShape(dragging.id, // 结束时才进 React 世界
    engine.getPos(dragging.id))
  ydoc.transact(() => { /* 同步到协作文档 */ })
})
```
