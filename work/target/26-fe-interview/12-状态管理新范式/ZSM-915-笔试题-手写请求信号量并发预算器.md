## 915：笔试手写：实现预取/请求的并发预算信号量

**答**：实现 Semaphore(n)：run(fn) 返回 promise（fn 结果）；超过 n 个并发排队 FIFO；支持 setLimit(n2) 动态调整（调小时不中断在跑的，只影响新排队）。

```js
class Semaphore {
  constructor(n) { this.limit = n; this.active = 0; this.queue = []; }
  setLimit(n) { this.limit = n; this._drain(); }
  run(fn) {
    return new Promise((resolve, reject) => {
      this.queue.push({ fn, resolve, reject });
      this._drain();
    });
  }
  _drain() {
    while (this.active < this.limit && this.queue.length) {
      const { fn, resolve, reject } = this.queue.shift();
      this.active++;
      fn().then(resolve, reject).finally(() => {   // finally 保证释放
        this.active--;
        this._drain();
      });
    }
  }
}
const sem = new Semaphore(3);
const results = await Promise.all(
  Array.from({ length: 10 }, (_, i) =>
    sem.run(async () => { await sleep(50); return i; })));
console.log(results);  // [0..9]，任意时刻并发 <= 3
```

**评分点**：
- FIFO 队列 + 槽位释放后 _drain 续接（finally 保证异常时也释放——漏 finally 是并发泄漏 bug）
- setLimit 动态调整只影响新调度
- resolve/reject 双通道透传（fn 抛错不吞）
- 能讨论：应用场景（预取预算/上传并发/重试风暴防护）、公平性进阶
