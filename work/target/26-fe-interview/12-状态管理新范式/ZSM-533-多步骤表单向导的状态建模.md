## ZSM-533：多步骤表单向导（分步签核类）的状态建模

**答**：
- 向导本质是线性状态机：`steps: ['basic', 'detail', 'confirm', 'done']`，状态切片 `stepIndex + stepData: Record<stepKey, FormData>`。每个步骤的数据**分 key 存储**——返回上一步不丢前面步骤的数据，最后一步才整体提交。
- 步骤守卫：`canGoNext` 是派生（校验当前 stepData），不是用户点击时才校验——步骤条上的「可点/灰」和下一步按钮共用同一派生，状态一致。
- 跳步语义：允许跳过的步骤（非必填）给 `optional: true`，`skip` 动作把该步骤标记 skipped 而非清空；「已访问过的步骤」单独记录（visitedSteps），决定步骤条上是否显示完成勾。
- 提交失败处理：done 前提交失败回到 confirm 步骤并保留所有数据；只有服务端确认成功才进 done——**done 是服务端事实，不是本地状态**。
- 追问钩子：向导中途刷新/分享链接，用 URL query 存 stepIndex + localStorage 存草稿 stepData 恢复；未提交过的数据不能进 URL（隐私与长度）。

```javascript
const STEPS = ['basic', 'detail', 'confirm', 'done'] as const

const useWizard = create((set, get) => ({
  stepIndex: 0,
  stepData: { basic: {}, detail: {}, confirm: {} },
  visited: new Set(['basic']),
  skipped: new Set(),

  next() {
    const { stepIndex, stepData } = get()
    const key = STEPS[stepIndex]
    if (!validators[key]?.(stepData[key])) return false   // 守卫拒绝
    set((s) => ({
      stepIndex: Math.min(s.stepIndex + 1, STEPS.length - 1),
      visited: new Set([...s.visited, STEPS[s.stepIndex + 1]]),
    }))
    return true
  },
  back: () => set((s) => ({ stepIndex: Math.max(0, s.stepIndex - 1) })),
  skip() {
    const key = STEPS[get().stepIndex]
    if (!OPTIONAL.includes(key)) return false
    set((s) => ({ skipped: new Set([...s.skipped, key]) }))
    return get().next()
  },
  submit: async () => {
    const { stepData } = get()
    try {
      await api.createOrder({ ...stepData.basic, ...stepData.detail })
      set({ stepIndex: STEPS.indexOf('done') })   // 服务端成功才进 done
    } catch {
      set({ stepIndex: STEPS.indexOf('confirm') })  // 失败回 confirm，数据保留
    }
  },
}))

const canGoNext = (s) => validators[STEPS[s.stepIndex]]?.(s.stepData[STEPS[s.stepIndex]]) ?? true
```
