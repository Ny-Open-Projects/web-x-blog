## ZSM-282：应用启动时多个状态源初始化的时序怎么管

**答**:
- 明确依赖图：配置 → 权限/用户 → 业务数据，分层初始化；用「ready 门控」（authReady/configReady）让消费方等待而不是读默认值
- 实现手段：启动 promise 汇聚（Promise.all + 超时兜底）、Query 的 dependent query、或路由 loader 前置初始化（进入页面时数据已就绪）
- 避免「初始化竞态三宗罪」：组件在初始化完成前读了 store 默认值、初始化请求互相依赖但并发发出、初始化失败后静默继续
- 失败策略：关键初始化失败给重试页；非关键降级默认值并上报——初始化也要分层失败

```javascript
const boot = Promise.race([Promise.all([loadConfig(), loadSession()]), timeout(3000)])
export function useBootReady() {
  const [ready, setReady] = useState(false)
  useEffect(() => { boot.then(() => setReady(true)) }, [])
  return ready
}
// 消费：<App gate={useBootReady()}> 未 ready 渲染 Splash，防止读默认值
```
