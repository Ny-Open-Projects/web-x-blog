## ZSM-287：persist 大状态树卡顿怎么优化

**答**:
- 开销三来源：每次 setState 都触发 partialize+JSON.stringify+setItem（同步阻塞主线程）、大字符串在移动端低配机上 10ms+、storage 配额超限抛错
- 优化一：节流写盘（100ms~1s debounce 合并）、只在变更时写（值哈希比较跳过）；优化二：partialize 只存必要子树，砍掉大数组（分页数据不持久化）
- 优化三：换异步存储（IndexedDB），配合「标签页关闭前 flush」；超限处理 try-catch + 淘汰策略（LRU 清旧 key）
- 结构化数据别 stringify 两次：能存原始可序列化对象就直接存，运行时再反序列化校验

```javascript
let timer
const throttledPersist = debounce(() => {
  try { localStorage.setItem(key, JSON.stringify(partialize(getState()))) }
  catch (e) { evictOldKeys() }        // 配额满 → LRU 淘汰
}, 500)
store.subscribe(throttledPersist)     // 节流替代每次写
```
