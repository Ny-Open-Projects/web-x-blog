## ZSM-582：小程序端的状态共享：跨页面、分包与 tabbar 页的特殊性

**答**：
- 小程序没有浏览器环境，跨 tab 方案（BroadcastChannel/storage 事件）不可用；小程序自身是多「页面栈」结构：状态共享靠 **App 实例的 globalData / 模块级单例 store**——多个页面 require 同一个 store 模块天然共享。
- 更新通知问题：模块级 store 是「数据共享」但没有订阅机制，页面 `onShow` 时手动拉取一次（简单但会闪旧值）；进阶做法是给 store 加 mini 订阅器，页面 onLoad 订阅、onUnload 退订，data 更新走 setData。
- **tabbar 页的特殊性**：tabbar 页不销毁，切换 tab 不触发 onLoad，只有 onShow——订阅回调在隐藏期间累积的变更要在 onShow 里 flush（或订阅时立即同步一次），否则切回来数据陈旧。
- 分包的边界：分包页面也能 require 主包的 store（分包依赖主包），但主包不能反向依赖分包——store 定义必须全在主包/公共模块；跨分包的状态通信走主包 store，不要走页面参数传递。
- 追问钩子：跨小程序实例（不同入口/不同 tab 页面的 WebView）与 native 层状态共享走 globalData + 事件总线，或干脆走服务端（同 IM 游标思路）。

```javascript
// 主包 store/store.js：模块级单例 + mini 订阅器
let state = { cartCount: 0, user: null }
const subs = new Set()

module.exports = {
  getState: () => state,
  setState(patch) {
    state = { ...state, ...patch }
    subs.forEach((fn) => fn(state))
  },
  subscribe(fn) { subs.add(fn); return () => subs.delete(fn) },
}

// 页面（含 tabbar 页的 onShow 处理）
const store = require('../store/store.js')
Page({
  data: { cartCount: 0 },
  onLoad() {
    this.unsub = store.subscribe((s) => this.setData({ cartCount: s.cartCount }))
  },
  onShow() {
    // tabbar 页不销毁：隐藏期间的变更用最新值兜底一次
    this.setData({ cartCount: store.getState().cartCount })
  },
  onUnload() {
    this.unsub && this.unsub()   // 页面栈销毁要退订，防泄漏
  },
})

// 加购动作（任意页面/分包调用）
store.setState((s) => ({ cartCount: s.cartCount + 1 }))
```
