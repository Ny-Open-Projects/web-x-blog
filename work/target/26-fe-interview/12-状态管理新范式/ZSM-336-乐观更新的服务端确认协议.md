## ZSM-336：乐观更新提交后服务端确认协议怎么设计

**答**:
- 协议四要素：客户端生成操作 id（幂等键）随提交携带；服务端确认返回「应用后的完整资源」而非 ack（免二次拉取）；确认带版本号供后续冲突检测；失败返回结构化错误码（可重试/需决策）
- 确认落地：确认数据直接 setQueryData 覆盖本地乐观值（以服务端为准收尾），乐观期 UI 标记 pending 状态消除
- 超时语义：确认超时 ≠ 失败——进入「待确认」态轮询结果或由 WS 推送补确认，不立即回滚（避免用户已看到结果又消失）
- 重复提交：同一操作 id 重发服务端幂等返回首次结果，客户端状态机保证单飞

```javascript
const opId = crypto.randomUUID()
onMutate: (vars) => { qc.setQueryData(k, (o) => ({ ...o, ...vars, _opId: opId, _pending: true })) }
onSuccess: (server) => qc.setQueryData(k, { ...server, _pending: false })     // 服务端确认覆盖
onError: (e) => {
  if (e.code === 'TIMEOUT') markAwaitConfirm(opId)       // 待确认：轮询/等推送
  else rollback(opId)
}
```
