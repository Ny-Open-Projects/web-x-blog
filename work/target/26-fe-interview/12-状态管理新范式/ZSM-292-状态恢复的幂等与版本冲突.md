## ZSM-292：从 storage 恢复状态时新旧版本冲突怎么处理

**答**:
- 恢复是「合并」不是「覆盖」：persisted 与代码默认值 merge（persist 默认浅合并），嵌套对象要深合并，数组类字段按业务语义决定（覆盖 or 并集）
- 版本三态：相等 → 直接合并；旧 → migrate 迁移链；新（降级/回滚发版）→ 丢弃并用默认值（向前兼容不可保证时安全丢弃）
- 损坏兜底：JSON.parse try-catch、hash 校验失败即丢弃 + 上报，绝不恢复半截数据
- 冲突可视化：dev 环境打印恢复 diff（默认值 vs 持久化值），帮助发现「以为恢复了实际丢了」的坑

```javascript
function restore(saved, defaults, version) {
  try {
    const data = JSON.parse(saved)
    if (data.version < version) return migrate(data, version)    // 升级迁移
    if (data.version > version) { report('stale_storage'); return defaults }  // 回滚丢弃
    return deepMerge(defaults, data.state)
  } catch { report('corrupt_storage'); return defaults }
}
```
