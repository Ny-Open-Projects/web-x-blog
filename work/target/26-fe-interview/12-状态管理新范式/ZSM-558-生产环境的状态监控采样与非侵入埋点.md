## ZSM-558：生产环境的状态监控：采样与非侵入埋点怎么设计

**答**：
- 生产不能开全量状态日志（体积/PII/性能），监控目标收窄为三类信号：**变更频率异常**（某 store 每秒 >50 次 set）、**重渲热点**（一次变更触发 >30 组件）、**异常链路**（状态不变但 UI 错）。
- 非侵入埋点：只在 store 的 setState 包一层（一个中间件），业务代码零改动；上报内容做白名单裁剪——只报字段名与变更计数，不报值；涉及用户数据的字段做 hash 或脱敏。
- 采样设计：入口按 userId hash 抽样（1%），抽样用户内全量记录，保证「单用户完整会话」可回放；错误发生时强制携带错误前 N 秒的状态事件缓冲（类似 Sentry 的 breadcrumbs 环形缓冲）。
- 上报协议：批量 + 失败丢弃（监控数据不能影响业务网络），Payload 限 32KB，超限只发摘要。会话 ID 贯穿，便于和 RUM/APM 关联。
- 追问钩子：状态监控和 RUM（PerformanceObserver）关联——把「状态变更序列」与「长任务/INP」时间轴对齐，才能定位「状态风暴导致的卡顿」。

```javascript
// 生产监控中间件（非侵入）
function monitorMiddleware({ sampleRate = 0.01, flushMs = 10000, buffer = 50 } = {}) {
  const sampled = Math.random() < sampleRate || MONITOR_FORCE
  const events = []
  return (create) => (set, get, api) =>
    create((...args) => {
      const t0 = performance.now()
      set(...args)
      if (!sampled) return
      const dur = performance.now() - t0
      events.push({ ts: Date.now(), store: api.name ?? 'anon', dur })   // 只记元数据不记值
      if (events.length >= buffer) flush(events.splice(0))
    })
}

function flush(batch) {
  // 批量上报：失败静默丢弃，不阻塞业务
  navigator.sendBeacon?.('/api/rum/state', JSON.stringify({
    sessionId: SESSION_ID,
    batch: batch.slice(0, 100),
  })) || fetch('/api/rum/state', { method: 'POST', body: JSON.stringify({ sessionId: SESSION_ID, batch: batch.slice(0, 100) }), keepalive: true })
    .catch(() => {})
}

// 错误兜底：全局错误时强制上报状态事件缓冲
window.addEventListener('error', () => {
  flush(lastEvents.slice(-20))   // 错误前 20 条状态事件随错误上报
})
```
