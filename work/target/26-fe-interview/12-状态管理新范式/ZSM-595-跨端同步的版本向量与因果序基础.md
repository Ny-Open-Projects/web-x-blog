## ZSM-595：跨端同步的版本向量：怎么判断两个副本谁更新

**答**：
- 版本向量（Version Vector）：每个副本维护 `{ deviceId: counter }` 的映射，记录「我已见过各设备到第几号变更」。比较两个向量：A ≥ B（A 见过 B 的一切）则 A 更新；互不支配则「并发分叉」——需要合并策略。
- 与 Lamport 时钟的区别：Lamport 只给全序（谁的事件先发生）但不能表达「并发」；版本向量能精确区分「先后」与「并发」——这是冲突检测的基础。ZSM-583 的字段 LWW 是「知道并发也硬覆盖」，版本向量是「先识别并发再决定策略」的前置。
- 应用流程：本地写 → 本地向量对应 device 计数 +1 → 广播时附带向量；接收方对比向量决定「直接应用 / 已经有了（幂等） / 并发冲突（走合并）」。
- 持久化与裁剪：向量随状态一起持久化（否则重启后无法判断新旧）；长期运行向量会膨胀，服务端定期 GC（所有副本都确认过的旧 device 条目可移除）。
- 追问钩子：Dotted Version Vectors / Interval Tree Clock 是工程上的精简版；面试时说清「向量膨胀」和「device 离线一年」两个边界即可体现深度。

```javascript
class VersionVector {
  constructor(deviceId, vv = {}) {
    this.deviceId = deviceId
    this.vv = { ...vv, [deviceId]: vv[deviceId] ?? 0 }
  }

  // 本地事件：计数 +1
  tick() {
    this.vv[this.deviceId]++
    return { ...this.vv }
  }

  // 见到远端向量（收到消息时吸收）
  absorb(remote) {
    for (const [d, c] of Object.entries(remote)) {
      this.vv[d] = Math.max(this.vv[d] ?? 0, c)
    }
  }

  // 关系判定：0=相等 1=a更新 -1=b更新 2=并发
  static compare(a, b) {
    let aGreater = false, bGreater = false
    const devices = new Set([...Object.keys(a), ...Object.keys(b)])
    for (const d of devices) {
      const ca = a[d] ?? 0, cb = b[d] ?? 0
      if (ca > cb) aGreater = true
      if (cb > ca) bGreater = true
    }
    if (aGreater && bGreater) return 2
    if (aGreater) return 1
    if (bGreater) return -1
    return 0
  }
}

// 同步决策
function onReceive(local, remoteState) {
  const cmp = VersionVector.compare(local.vv, remoteState.vv)
  switch (cmp) {
    case 1: return 'already-have'   // 本地更新：忽略远端
    case -1: return 'apply-remote'  // 远端更新：直接应用
    case 2: return 'merge'          // 并发分叉：进入冲突合并策略
    default: return 'dedupe'        // 相同：幂等
  }
}
```
