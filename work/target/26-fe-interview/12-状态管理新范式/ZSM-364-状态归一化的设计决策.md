## ZSM-364：什么时候需要归一化，什么时候是过度设计

**答**:
- 需要归一化的信号：同一实体出现在多个响应/多处引用（订单里有用户、评论里有用户）；更新单个实体要遍历多处；实体间关系复杂且频繁变更
- 归一化收益：单点更新（改一处全视图生效）、引用一致（不出现两份不同步的同一实体）、订阅粒度到实体级
- 过度设计的信号：实体只在单一视图使用、列表整体换页（归一化后重组成本反而高）、无跨视图共享——此时嵌套原样存更简单
- 实现选型：手写 pick+Map、RTK Query 的 tag 失效、normalizr 式 schema 归一、或 TanStack Query 的「列表缓存 + 单实体缓存双轨」轻量方案

```javascript
// 双轨轻量归一：列表 + 实体
queryClient.setQueryData(['user', u.id], u)                 // 实体层
queryClient.setQueryData(['order', id], (o) => ({
  ...o, user: u,                                            // 冗余引用，可接受
}))
// 更新用户：两处失效或实体层更新 + 列表 invalidate
```
