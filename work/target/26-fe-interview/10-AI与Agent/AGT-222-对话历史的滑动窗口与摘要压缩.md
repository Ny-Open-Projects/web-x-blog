## AGT-222：几十轮的长对话怎么管理历史——滑动窗口+摘要怎么组合？

**答**:
- 双层结构：近期层（最近 6~10 轮原文保留，保证细节与指代完整）、远期层（更早的对话滚动压缩为摘要——每超阈值就把最旧 N 轮压成一段"对话纪要"，纪要也可再合并成更早的纪要，形成摘要金字塔）。
- 摘要纪律：纪要只保留事实与决策（"用户确认用方案 B，目标延迟 <200ms"），丢弃寒暄与过程；用户画像类信息（偏好/身份）单独存结构化记忆而不是混进纪要。
- 指代风险：压缩后"上面说的那个"可能失锚——关键实体在压缩时保持原名，不代词化；当前层与远期层拼接时在边界加"（以上是早期对话纪要）"提示。
- 成本控制：摘要用便宜模型异步生成（不阻塞主对话），触发阈值按 token 而不是轮数（轮数不均匀）。

```javascript
async function compactHistory(history, budget = 8000) {
  while (tokens(history) > budget) {
    const old = history.slice(0, 5);           // 最旧 5 轮
    const summary = await cheapLLM(`
      压缩为对话纪要：只保留事实、决策、
      用户偏好，保留关键实体原名。`, old);
    history = [{ role: 'system',
      content: '早期对话纪要：' + summary },
      ...history.slice(5)];
  }
  return history;   // 纪要可再合并，形成金字塔
}
```
