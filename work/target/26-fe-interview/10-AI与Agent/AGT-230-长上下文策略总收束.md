## AGT-230：长上下文工程的手段怎么收束成体系？

**答**:
- 四层手段栈：窗口内优化（预算分配/位置工程/前缀缓存）→ 会话内压缩（滑动窗口+摘要金字塔/工具结果结论化）→ 跨会话记忆（工作/情景/语义三层记忆+遗忘）→ 任务级拆分（检索代替通读/子 Agent 隔离/map-reduce）——自下而上成本递增，优先用低层手段。
- 选型判据：信息要在"多长时间"内可用？秒级→窗口内；会话级→压缩；天级以上→记忆库；单次任务但内容海量→拆分与检索——按时长选层，不要为短期需求上重基建。
- 通用红线：任何压缩/摘要都可能失真——关键事实（数字/决策/约束）永远原文保留并可溯源；压缩系统要有忠实性校验。
- 收束心法：上下文是稀缺资源，工程本质是"信息价值的调度"——把注意力预算花在与当前任务最相关、最不可再生的信息上。

```text
长上下文四层手段栈：
L1 窗口内：预算分段 / 关键信息放首尾 /
  前缀缓存降本
L2 会话内：滑动窗口 + 摘要金字塔 /
  工具结果结论化 / 70% 熔断
L3 跨会话：三层记忆（工作/情景/语义）
  + 写入判据 + TTL 遗忘
L4 任务级：检索代替通读 / 子 Agent 隔离
  / map-reduce / RAPTOR 层次索引
选层：按信息有效期；关键事实永远原文
保留可溯源；本质 = 注意力预算调度。
```
