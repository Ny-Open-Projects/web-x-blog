## AGT-277：Agent 循环失控或重试风暴时，预算熔断机制怎么设计？

**答**:
- 四级熔断：步骤级（单任务最大步数，防死循环）、成本级（单任务成本上限，超限强制结束并给出部分结果）、用户级（用户日预算/配额，防滥用）、全局级（总预算水位线，超 80% 降级为只读/小模型模式，超 100% 拒新任务）——从细到粗层层兜底。
- 熔断的体验设计：熔断不是报错甩锅——结束时要给出"已完成的部分+未完成的原因+继续的入口"，用户可以追加预算或简化任务重跑；熔断事件全部记录归因（为什么超限：任务复杂/死循环/重试风暴）。
- 死循环专项：同工具同参数连续出现即判死循环（AGT-253 模式库），强制注入"停止重复，换思路或结束"的指令，再犯直接熔断——循环是最常见的失控形态。
- 与限流的区别：限流防"流量型"超载（QPS），预算熔断防"单任务型"失控——两者都要，Agent 场景后者更重要。

```javascript
class BudgetGuard {
  async step(ctx) {
    if (++ctx.steps > MAX_STEPS) return this.stop('max_steps');
    if (ctx.cost > TASK_CAP) return this.stop('budget');
    if (isLoop(ctx.recentCalls)) {           // 死循环检测
      ctx.inject('停止重复调用，换思路或直接给结论');
      if (++ctx.loopWarn >= 2) return this.stop('loop');
    }
    if (globalPool.usage() > 0.8) ctx.model = CHEAP_MODEL; // 全局降级
  }
  stop(reason) {
    log(reason); return partialResult(ctx, reason); // 部分结果+原因
  }
}
```
