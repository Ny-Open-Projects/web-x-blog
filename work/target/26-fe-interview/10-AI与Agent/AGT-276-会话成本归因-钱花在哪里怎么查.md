## AGT-276：月账单暴涨后，怎么把成本归因到具体环节？

**答**:
- 归因维度设计：每次 LLM 调用记录（trace_id/任务类型/模型/输入输出 token/缓存命中/工具调用链）——成本日志与 trace 体系（AGT-158）打通，才能按任意维度切片：按功能/按用户/按模型/按步骤类型。
- 典型发现模式：某功能的长尾任务吃掉 60% 成本（P95 任务是 P50 的 20 倍——截断/熔断）、某工具的检索 embedding 费超预算（缓存缺失）、重试风暴（某下游故障导致全局重试，成本×5）——归因的价值是找到"结构性浪费"而非普遍省。
- 看板与告警：单位成本看板（每任务/每会话/每 DAU 成本，P50/P95）+ 异常告警（单任务成本超阈值/总量增速异常）；预算硬限（任务级成本熔断：超 X 元强制结束）。
- 归因驱动优化闭环：每个降本项（缓存/分级/压缩）上线后看对应维度的成本变化验证收益——成本工程与性能工程同构，先测量后优化。

```javascript
function costBreakdown(traces) {
  const dims = groupBy(traces, [t => t.feature, t => t.model]);
  return map(dims, (g, k) => ({
    cost: sum(g, t => t.in * p.in + t.out * p.out + t.toolFee),
    p95Task: quantile(g, 'taskCost', 0.95),
    retryWaste: sum(g, t => t.isRetry ? t.cost : 0),
  }));
}
// 任务级熔断：cost > TASK_CAP → 立即结束并降级
```
