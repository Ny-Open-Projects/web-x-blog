## AGT-336：数小时的 Agent 长任务（大型重构/深度调研）怎么设计？

**答**:
- 任务结构化：把长任务拆成可检查点的阶段（AGT-229 断点续跑），每阶段有明确产出物与验收标准——长任务失败的根源是"目标漂移"（几十步后忘了初始目标）：目标锚定（原始目标+关键约束常驻上下文，AGT-288 安全锚同理）+ 阶段产出对齐初始目标。
- 进度与监督：阶段完成即输出进度报告（做了什么/发现什么/下一步）供用户中途纠偏——长任务的信任来自"可见的中间产出"而非黑盒等待；关键决策点人审（方向性选择不自动）。
- 资源管理：成本预算分配到阶段（AGT-277），上下文按阶段滚动压缩（AGT-226），长时工具（编译/爬取）异步化并行。
- 质量收敛：后期阶段做全局一致性检查（前期产出与后期产出是否矛盾——AGT-264 一致性校验），最终产出带"完整证据链"可回溯每一步。

```text
长任务工程四件：
结构：阶段化 + 检查点 + 断点续跑
锚定：目标与约束常驻 + 阶段对齐
  （防目标漂移）
监督：阶段报告 + 关键决策人审 +
  预算分阶段
收敛：全局一致性检查 + 全链证据链。
信任 = 可见的中间产出。
```
