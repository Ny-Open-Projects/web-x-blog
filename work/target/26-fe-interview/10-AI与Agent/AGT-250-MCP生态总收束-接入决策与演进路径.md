## AGT-250：MCP 的适用边界与团队的接入演进路径怎么规划？

**答**:
- 什么场景值得上 MCP：能力要被多个 AI 应用复用（IDE 助手+客服机器人都要查工单）→ 封装成 Server 一次投入多处收益；只有单一应用自己用 → 普通 function calling 更简单，不必为协议而协议。
- 团队演进三阶段：个人工具期（stdio Server 接本地文件/终端，验证价值）→ 团队共享期（远程 HTTP + 统一鉴权审计，做 MCP 网关与工具目录）→ 平台生态期（Server 市场化：注册/评审/版本管理/SLA，业务团队自助发布能力包）。
- 治理要点随阶段升级：个人期无治理；团队期必须有安全评审（AGT-246 的注入/权限）与变更审核；平台期加配额计费、SLA 监控、下线流程。
- 收束心法：MCP 的本质是"Agent 能力的标准化分发"——判断标准始终是复用面与治理需求，工具粒度（AGT-245）与安全（AGT-246）决定 Server 质量，传输与会话（AGT-243/249）决定部署形态。

```text
MCP 接入决策与演进：
单应用自用 → function calling 即可
多应用复用 → 封装 MCP Server
阶段 1：stdio 本地工具（验证价值）
阶段 2：远程 HTTP + 网关
  （鉴权/审计/工具目录/健康熔断）
阶段 3：平台生态（注册评审/版本/SLA/
  配额/业务自助发布）
判断轴：复用面 × 治理需求；
  质量 = 粒度 + 安全；形态 = 传输 + 会话。
```
