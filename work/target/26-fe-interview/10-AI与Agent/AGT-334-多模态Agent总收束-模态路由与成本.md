## AGT-334：多模态 Agent（文/图/语音/视频混合）的架构怎么收束？

**答**:
- 模态路由：输入按模态与任务复杂度路由——文本走便宜通道、图像理解按需 VLM、语音全链路专用管线（AGT-331）、视频两级采样（AGT-333）；多模态联合任务（看图说话）才动用原生多模态大模型——模态路由是成本控制的第一层。
- 统一表示：各模态的输出归一为统一事件/内容结构（文本描述+引用原素材），下游 LLM 统一处理——避免每模态一套业务逻辑；原素材保留引用（溯源到原始帧/音频段）。
- 端侧协同：隐私敏感/低延迟任务（唤醒词/简单 OCR）下沉端侧（WebGPU 端侧模型 AGT-141），云端负责复杂推理——端云分工同时优化隐私与成本。
- 收束心法：多模态 Agent 的工程本质是"模态作为能力插件"——统一的 Agent 内核 + 各模态的感知/生成插件 + 路由与成本治理，而不是为每个模态重建整个 Agent。

```text
多模态架构：
路由：文本→便宜通道；图→按需 VLM；
  语音→专用管线；视频→两级采样
统一表示：各模态 → 结构化事件
  （+原素材引用）→ 统一 LLM 处理
端云：端侧（隐私/低延迟小任务）
  + 云端（复杂推理）
本质：Agent 内核 × 模态插件
  × 路由与成本治理。
```
