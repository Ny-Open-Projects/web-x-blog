## AGT-351：喂给 Agent 的数据管线（采集→清洗→入库→更新）怎么设计？

**答**:
- 管线四段：采集（多源连接器：文件/API/数据库/网页，采集权限合规 AGT-115）、清洗（格式统一/去重/脱敏 PII/语言与编码规范——垃圾进垃圾出）、加工（分块/抽取结构化信息/打元数据与信任标签，AGT-201/287）、入库（向量库+结构库双写，版本化 AGT-215）。
- 质量监控：管线级指标（采集成功率/清洗丢弃率/入库延迟）+ 数据级抽检（分块质量人工抽检、脱敏漏检扫描）——数据管线要有 SRE 同款的监控与告警。
- 更新与失效：增量更新（AGT-215）、过期策略（TTL/降权）、删除权（用户/合规要求删除时同步清除向量与缓存——GDPR 式删除在 RAG 里的实现难点要预设计）。
- 成本控制：清洗加工用规则+小模型（大模型只做必要的高价值加工），批处理通道（AGT-278）——数据管线是持续性成本，架构上就要省钱。

```text
数据管线四段：
采集（合规）→ 清洗（去重/脱敏/统一）
→ 加工（分块/结构化/信任标签）
→ 入库（向量+结构双写/版本化）
监控：管线指标 + 分块抽检 + 脱敏扫描
更新：增量 / TTL / 删除权同步清
  （向量+缓存）。
成本：规则+小模型加工，批量通道。
```
