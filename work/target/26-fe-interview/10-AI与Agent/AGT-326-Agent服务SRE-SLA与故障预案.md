## AGT-326：Agent 服务的 SLA 怎么定义、故障预案怎么做？

**答**:
- SLA 的 AI 特殊性：除可用性/延迟外，要定义质量 SLA（回答可用率=非拒答非错误的比例、幻觉率上限）与成本 SLA（单任务成本上限）——纯 99.9% 可用不能代表 Agent 服务健康，质量与成本也是 SLO。
- 分级降级预案：上游模型故障→切备用模型（AGT-279 冗余）；RAG 索引故障→降级为无检索模式（明确标注"未联网知识，可能过时"）或直接拒答高危类；全链路故障→前端降级为传统流程（AGT-322 总开关）——每层故障有对应降级，预案演练化（AGT-159 混沌工程）。
- 延迟预算分配：首 token 时间（用户感知核心）与总时长分账管理——流式掩盖总延迟但首 token 不能等太久；工具调用的超时预算单独设（AGT-238）。
- 可观测三件套：trace（全链路）、指标（质量/成本/延迟三 SLO 看板）、日志（结构化可回放）——Agent 故障多数是"质量劣化"不是宕机，质量监控要先行。

```text
Agent SRE 三类 SLO：
可用性（常规）+ 质量（回答可用率/
  幻觉率上限）+ 成本（任务成本上限）
降级链：备用模型 → 无检索模式（标注）
  → 非 AI 总开关
延迟：首 token SLO 与总时长分账；
  工具超时单独预算。
预案演练化：混沌测试定期跑。
```
