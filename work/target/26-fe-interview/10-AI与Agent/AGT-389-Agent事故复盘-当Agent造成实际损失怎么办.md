## AGT-389：Agent 造成实际损失（错误操作/资损/泄露）后，处置与复盘怎么做？

**答**:
- 应急处置四步：止损（撤销操作/冻结相关能力/降级到非 AI 流程——AGT-289 应急预案启用）、评估（损失范围量化：影响多少用户/多少钱）、沟通（受影响用户的告知与补偿方案——透明沟通保住信任底线）、归档（全链 trace 固定证据，AGT-289 审计）。
- 复盘差异点（vs 传统事故）：根因往往在"模型判断+流程设计"的组合（为什么 Agent 有权限做这个操作？为什么没有人审？为什么校验没拦住？）——复盘对象包括权限设计而不只是代码 bug；对"模型行为"的归因用 trace 回放+消融（AGT-369）。
- 修复三件套：直接修复（补规则/收权限/加人审点）、回归固化（该 case 进安全回归集与红队用例，AGT-299）、体系检查（同类操作的其他路径是否同样暴露——举一反三排查）。
- 信任重建：对外透明（修复说明+补偿）、对内机制化（事故进培训与评审清单）——Agent 事故的公众敏感度高，处置姿态比技术修复更影响长期信任。

```text
Agent 事故处置：
应急：止损（撤销/冻结/降级）→ 评估
  → 透明沟通与补偿 → trace 取证
复盘：权限设计 + 流程设计 + 模型行为
  （回放+消融）三向归因
修复：直接修复 + 回归固化（安全集）
  + 举一反三排查同类路径。
信任重建 > 技术修复。
```
