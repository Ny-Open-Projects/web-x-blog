## AGT-260：Agent 评测体系怎么收束成完整工程？

**答**:
- 全景四环节：离线评测（四层指标：结果/轨迹/单步/系统，AGT-251~253；judge 校准与数据管理，AGT-254/257）→ 回归门禁（变更必过回归集，AGT-255）→ 影子验证（真实流量零风险对比，AGT-256）→ 在线实验（A/B 统计纪律，AGT-259）——风险逐级递减地放行，每一级都有明确的通过标准。
- 评测的组织属性：评测不是个人行为而是团队基础设施——评测集版本化、结果看板化、badcase 流水线化（线上失败→聚类→回归集）、judge 定期人工校准；没有流程的评测集会迅速腐烂。
- 成本意识：评测本身是开销（judge 调用/影子流量/回归耗时）——分层预算：日常小集快速跑、发版全量集、季度大评测（含挑战集与安全评测），按风险配成本。
- 收束心法：评测体系的成熟度决定 Agent 迭代速度——没有评测的团队只能靠"感觉"改 prompt，有评测的团队才能把 Agent 当真正的软件工程来持续交付。

```text
Agent 评测全景：
离线：四层指标 + rubric judge + 三层评测集
门禁：变更必过回归集，退化超阈值阻断
影子：10% 真实流量零风险对比
在线：A/B（预注册指标/不 peeking/
  长尾分桶）+ 30 天漂移
闭环：线上失败 → 聚类 → 回归集
预算：日常小集 / 发版全量 / 季度大评。
心法：评测成熟度 = 迭代速度上限。
```
