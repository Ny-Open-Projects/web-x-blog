## AGT-385：传统 RPA（流程自动化机器人）与 Agent 怎么融合升级？

**答**:
- RPA 的局限：脚本脆弱（页面结构变就断）、只能处理标准化流程、异常处理靠人工——RPA 擅长"重复稳定路径"，Agent 补"判断与适应"。
- 融合架构：RPA 作为 Agent 的"手"（稳定的操作执行器——页面操作/系统录入由成熟 RPA 组件执行，比让 LLM 直接操作 GUI 稳定），Agent 作为"脑"（理解任务/处理异常/决策分支）——"AI 大脑 + RPA 手脚"是流程自动化的升级形态。
- 升级路径：现有 RPA 流程逐步注入 AI 步骤（异常时 Agent 介入处理而非转人工——AGT-359 增强模式）、非标输入的预处理（LLM 把非结构化输入转成 RPA 可处理的标准化输入）。
- 治理继承：RPA 已有的权限/审计/合规体系延续，Agent 层叠加（AGT-283/289）——融合不是重建而是分层增强。

```text
RPA × Agent 融合：
脑：Agent（理解/异常处理/决策分支）
手：RPA（稳定操作执行/系统录入）
升级：非标输入 → LLM 预处理标准化
  → RPA 执行；异常 → Agent 介入
  而非直接转人工
治理：RPA 权限审计体系延续 +
  Agent 层叠加。
```
