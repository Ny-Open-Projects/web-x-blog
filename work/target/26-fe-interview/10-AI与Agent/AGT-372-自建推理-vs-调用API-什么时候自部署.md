## AGT-372：自建模型推理（开源模型部署）与调用商业 API 的决策框架？

**答**:
- 自建的价值区：数据敏感不能出域（合规硬约束——最常见理由）、超大用量（API 成本 > GPU 成本，通常日调用量千万级 token 才划算）、深度定制需求（模型行为微调+自控版本）、延迟与可控性要求极端。
- 自建的真实成本：GPU 资本与运维（卡/机房/工程师）、模型能力差距（开源与顶级闭源在复杂任务有代差——能力损失要评测量化）、版本演进负担（开源模型迭代快，升级=重新评测）——自建是"买生产能力"不是"省钱魔法"。
- 混合架构（多数企业的答案）：敏感/高频简单任务走自建小模型（AGT-272 分级路由），复杂/低频任务走 API——"自建保底+API 冲高"，供应商治理（AGT-327）覆盖两侧。
- 决策清单：合规约束？用量规模？能力要求（评测集对比开源模型达标吗）？运维能力（有 GPU 运维团队吗）？——四问全 Yes 或前两项 Yes 才值得。

```text
自建 vs API 决策四问：
1 数据不能出域？（最常见硬理由）
2 用量足够大？（API 成本 > GPU 成本）
3 开源模型评测达标？（能力差距量化）
4 有运维能力？（GPU/工程师）
混合架构：自建保底（敏感+高频简单）
  + API 冲高（复杂低频）。
```
