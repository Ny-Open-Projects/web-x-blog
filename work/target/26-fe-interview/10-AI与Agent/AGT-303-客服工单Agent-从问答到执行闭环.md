## AGT-303：客服 Agent 从"能答"到"能办"（改地址/退款/查单）怎么设计？

**答**:
- 能力分层：L1 知识问答（RAG 答政策/流程）、L2 查询执行（调工具查订单/物流——只读自动）、L3 变更执行（退款/改地址——写操作，需身份核验+确认流）、L4 复杂案件（多步/争议→转人工）——分层授权与升级机制是客服 Agent 的骨架。
- 身份与授权：执行操作前身份核验（登录态/二次验证），操作权限对齐该用户的数据（AGT-283）；金额类操作双人规则（Agent 建议+规则引擎审批+超阈值人审）。
- 情绪与升级：情绪识别触发提前转人工（挽回体验），转人工时 Agent 输出"案件摘要"（已确认信息/已尝试操作/用户诉求）——人工接手零重复沟通是关键体验。
- 评测：解决率（无需人工闭环的比例）、转人工率与原因分布、误操作率（错误退款等，零容忍监控）、满意度——客服 Agent 的北极星是"安全地提高解决率"。

```text
客服 Agent 分层：
L1 问答（RAG）→ L2 查询（只读自动）
→ L3 变更（身份核验+确认流+金额规则）
→ L4 转人工（情绪/争议/复杂）
转人工必带案件摘要：已确认信息/
已尝试操作/用户诉求。
评测：解决率 / 转人工原因分布 /
误操作率（零容忍）/ 满意度。
```
