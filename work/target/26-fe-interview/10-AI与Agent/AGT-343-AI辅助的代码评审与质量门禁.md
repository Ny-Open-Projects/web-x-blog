## AGT-343：AI Code Review 怎么用才不沦为噪音生成器？

**答**:
- 定位分工：AI 评审管"确定性检查的深度化"（逻辑漏洞/边界遗漏/安全问题/性能反模式——规则引擎扫不到的语义层），人评审管"设计合理性/业务正确性"——AI 是第一道细筛，人做终审，不是替代。
- 噪音控制：AI 评审的失效模式是"大量正确但无用的建议"——分级输出（blocker/must/should/nit）、只评 diff 上下文（不评审整个文件的历史问题）、低置信发现折叠（"可能有 X 问题，置信度低"）；建议必须附修复建议或反例。
- 上下文注入：给 AI 评审的输入不只 diff——相关模块代码/团队规范文档/历史同类 bug（"这类代码曾出过 X bug"）——上下文决定发现的深度。
- 度量与调优：AI 发现被采纳率、漏报（人发现 AI 没发现的 bug）、噪音率（被忽略的建议比例）——按指标调 prompt 与阈值，AI 评审本身也要迭代。

```text
AI 评审分工：
AI：语义层确定性检查（边界/安全/性能反模式）
人：设计合理性 / 业务正确性
降噪：分级输出 + 只评 diff + 低置信折叠
  + 建议附修法
上下文：相关模块 + 规范 + 历史 bug
度量：采纳率 / 漏报 / 噪音率 → 调优。
```
