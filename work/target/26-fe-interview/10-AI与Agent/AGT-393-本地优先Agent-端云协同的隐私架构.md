## AGT-393：本地优先（local-first）的 Agent 架构怎么设计？

**答**:
- 分级策略：本地执行（隐私最高敏+低延迟小任务：个人笔记问答——端侧小模型 WebGPU AGT-141）、云端执行（复杂推理）、混合（本地脱敏→云端推理→本地还原——脱敏代理的端侧版）——数据分级决定执行位置。
- 端侧能力边界：小模型的意图识别/抽取/改写够用，复杂推理/长上下文不行——本地优先不等于全本地，是"本地处理敏感与高频，云端处理复杂"，路由器按数据分级+任务复杂度双维决策。
- 离线可用性：本地缓存的知识/记忆支持离线问答（降级模式：明确标注"离线模式，仅基于本地知识"）、网络恢复后同步（会话/记忆的冲突解决 AGT-330）。
- 工程现实：端侧模型的设备差异（内存/算力分档——能力探测与降级）、模型分发与更新（按需下载/增量更新）、电量与散热约束——本地优先的工程成本不低，价值锚定在隐私与离线场景。

```text
本地优先分级：
本地：高敏数据 + 低延迟小任务
  （端侧 WebGPU 小模型）
云端：复杂推理（数据可脱敏出域）
混合：本地脱敏 → 云推理 → 本地还原
离线：本地知识降级问答（明确标注）
  + 恢复后同步
现实：设备分档探测 / 模型增量更新 /
  电量散热约束。
```
