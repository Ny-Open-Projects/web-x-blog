## AGT-320：把 Agent 落到具体业务场景，通用方法论是什么？

**答**:
- 方法论五步：能力边界定义（AI 做什么/规则做什么/人做什么——定位先于实现，参照 AGT-307~309 的分层思想）、任务分层（高确定性→规则与固定管线，低确定性→Agent，灰区→Agent+人审）、数据与工具准备（知识库质量/工具权限/实时数据通道——场景 80% 的工作在数据准备）、评测先行（上线前建金标评测集与安全集，AGT-257）、灰度与闭环（影子→小流量→放量，badcase 回流）。
- 场景共性规律：高价值场景都在"数据密集+流程有 SOP+尾部非标"的交集——标准部分规则化、非标部分 AI 化、判断部分人审化，这个"三明治"结构是绝大多数落地形态。
- 失败模式清单：边界不清（AI 越权决策出事故）、数据不备（知识库空转幻觉）、评测缺位（上线即翻车）、闭包缺失（badcase 不回流持续烂）——四个失败模式对应方法论四步，逐项自检。
- 收束心法：业务 Agent 的本质是"把业务 SOP 翻译成 Agent 可执行的契约"——场景工程 = 业务理解 × AI 工程 × 治理工程，三缺一不可。

```text
场景工程五步法：
1 边界：AI / 规则 / 人 三分（先定位）
2 分层：确定性→规则；非标→Agent；
  灰区→Agent+人审（三明治结构）
3 备料：知识库 / 工具权限 / 实时通道
4 评测：金标集 + 安全集先行
5 灰度：影子→小流量→放量→badcase 回流
失败四模式：越权 / 空转 / 无评测 /
  无闭环 —— 逐项自检。
```
