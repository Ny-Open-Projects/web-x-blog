## AGT-298：前端集成 Agent 的工程体系怎么收束？

**答**:
- 全景五层：传输层（SSE 事件信封/续传/打断，AGT-291）→ 状态层（消息状态机/多会话 hub/多端同步，AGT-292/295）→ 渲染层（delta 合帧/结构块分流/组件协议，AGT-296/153）→ 交互层（过程时间线/审批卡/错误引导，AGT-293/297）→ 可靠层（中断恢复/降级轮询/静默失败检测，AGT-294）——每层可独立演进。
- Agent UI 与传统 UI 的本质差异：输出是异步、不确定、渐进的——传统"请求-响应"的组件模型要升级为"事件流+状态机"模型，前端复杂度主要在可靠性（断续/乱序/半成品）而非渲染。
- 体验三支柱：透明（过程可见，AGT-293）、可控（随时打断/审批/撤销）、可恢复（任何中断不丢内容，AGT-294）——信任建立在"用户永远有掌控感"上。
- 收束心法：Agent 前端是"流式应用的完整工程"——把 token 流当视频流对待（缓冲/断连/进度/降级），把 Agent 当协作者对待（过程/确认/反馈），两条线索交织成完整的产品体验。

```text
Agent 前端全景：
传输：SSE 信封 + seq 续传 + cancel
状态：消息状态机 + 会话 hub + 多端同步
渲染：合帧 delta + 结构块白名单组件
交互：时间线 + 审批卡 + 分类错误引导
可靠：落库重放 + 退避重连 + 心跳检测
体验三支柱：透明 / 可控 / 可恢复。
本质：流式应用工程 × 协作式产品体验。
```
