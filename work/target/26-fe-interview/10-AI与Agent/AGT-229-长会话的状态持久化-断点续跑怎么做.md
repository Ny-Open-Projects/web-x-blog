## AGT-229：跑几小时的 Agent 任务中断（崩溃/限流/人工暂停）后怎么恢复？

**答**:
- 持久化的单位：把 Agent 状态外置存储（消息历史/工具结果/当前步骤/中间产物全落库），进程崩溃只是丢内存——恢复 = 从存储重建上下文，从最后完成的步骤继续。
- 步骤幂等是前提：恢复时最后一步可能已执行但未记录（如已下单未写库）——工具调用要带幂等键（step_id），服务端可去重；不可幂等的动作（发邮件）要有"预执行记录"（先写意图再执行）。
- 检查点粒度：每完成一个子任务打 checkpoint（状态快照+版本），长步骤内部用工具级幂等兜底；人工暂停点（审批）天然是检查点。
- 恢复策略：从最近 checkpoint 恢复后先"自检"（重放关键状态校验，如数据是否已写入），再继续；带版本的状态支持回滚到更早 checkpoint（适用于中途决策错误的场景）。

```javascript
async function resumableRun(taskId) {
  const state = await store.load(taskId);     // 重建上下文
  for (let step = state.nextStep; step < plan.length; step++) {
    const key = `${taskId}:${step}`;          // 幂等键
    if (await store.isDone(key)) continue;    // 已完成跳过
    await store.markIntent(key);              // 预执行记录
    const result = await execStep(plan[step], key);
    await store.saveResult(key, result);
    await store.checkpoint(taskId, { nextStep: step + 1,
      context: prune(state.context) });
  }
}
```
