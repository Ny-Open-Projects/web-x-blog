## AGT-289：Agent 系统的审计与合规要留什么痕、防什么责？

**答**:
- 审计留痕清单：决策链（每步的输入/输出/模型版本/prompt 版本——可完整回放）、工具调用（调用/参数/结果/耗时）、人工介入（谁在何时批准/修改了什么）、数据访问（读了/写了什么数据，AGT-285）——审计的目标是"任何一次输出都能还原其产生过程"。
- 责任边界设计：产品侧明示 AI 参与与局限（AI 生成内容标注）、高危决策保留人工终审（Agent 只建议）、免责条款与用户协议覆盖（AI 建议不构成专业意见）；内部侧：Agent 行为的责任归属到流程（谁配置的 prompt/谁批准的上线）——版本化让每个决策可追到人。
- 合规框架：数据（PII 处理与跨境传输合规，AGT-285）、内容（生成内容审核，AI 标识法规）、行业（金融/医疗的额外监管要求）、算法备案与评估（国内监管要求）——合规清单按业务地域与行业定制。
- 应急与演练：事件响应预案（Agent 出现有害输出的处置流程：下线开关/追溯/通知）、定期演练（AGT-159 故障演练思路同样适用于安全事件）。

```text
Agent 审计四类留痕：
决策链：输入/输出/模型版本/prompt 版本
工具调用：参数/结果/耗时
人工介入：审批记录（谁/何时/改了什么）
数据访问：读写的对象与 ACL 校验
责任：AI 标注 + 高危人工终审 +
  prompt 版本化到人；
合规：数据/内容/行业监管/算法备案。
```
