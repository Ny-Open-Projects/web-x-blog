## AGT-226：Agent 连续调用几十次工具后上下文膨胀，怎么控制？

**答**:
- 膨胀来源：工具返回结果（尤其是 search/读文件类）远大于输入，几十轮后历史里堆满了大段无用中间结果——控制重点是"工具结果的生命周期"。
- 控制手段：结果即用即弃（工具结果被下一轮消费后压缩为一句结论）、结果裁剪（工具层先做截断/摘要再返回，search 只返回标题+片段）、分任务清理（子任务完成即把该段压缩为小结，主循环只保留小结）、硬上限熔断（超预算强制触发压缩或结束）。
- 结构设计：把"过程上下文"与"结论上下文"分开——Agent 的决策只依赖结论列表（已确认事实/已完成步骤），过程明细按需回查（工具可重放）。
- 实践参数：单工具结果 ≤2k token、过程结论化每 5~10 轮一次、总上下文超过 70% 预算触发强制压缩——阈值要按模型与任务实测调。

```javascript
function compactToolResults(history) {
  return history.map(m => {
    if (m.role === 'tool' && m.consumed) {
      return { ...m, content: m.takeaway };  // 已消费→结论
    }
    if (m.role === 'tool' && tokens(m.content) > 2000) {
      return { ...m, content: truncate(m.content, 2000) };
    }
    return m;
  });
}
// 每 N 轮：把已完成子任务整段压缩为小结
// 超 70% 预算 → 强制 compact 或熔断
```
