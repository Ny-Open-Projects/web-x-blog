## AGT-390：AI/Agent 浪潮中，前端团队的角色怎么重新定位？

**答**:
- 四个机会角色：Agent UI 专家（流式/状态机/审批交互——AGT-298 的工程体系是前端主场）、AI 产品的前端负责人（AI 功能的产品化呈现：置信度/引用/教育——AGT-378）、应用层 AI 工程师（RAG 管线/编排/MCP 集成——应用层不需要训练模型，前端工程师的工程能力可平移）、效率推进者（团队的 AI 协作规范与工具链，AGT-346）。
- 能力建设路径：从现有优势出发——前端的状态管理/异步流/组件化经验直接迁移到 Agent UI 与编排（DAG 与组件树同构）；补的短板是 AI 应用域知识（RAG/评测/成本——本目录 AGT-201~380 的体系）。
- 组织协作：与算法团队的分工（算法管模型与效果，前端管产品化与体验——AGT-380 转换层的归属）、与后端的接缝（BFF 扩展为 AI 网关：流式聚合/工具代理）。
- 心态建议：不焦虑"被 AI 取代"，焦虑"错失 Agent 工程的先发位"——应用层的工程位刚刚打开，前端团队有独特优势（离用户最近）。

```text
前端团队四角色：
Agent UI 专家（流式/状态机/审批）
AI 产品前端负责人（呈现/教育/置信）
应用层 AI 工程师（RAG/编排/MCP）
效率推进者（团队 AI 规范/工具链）
迁移：状态管理/异步流/组件化 →
  Agent UI 与 DAG 编排；
补：AI 应用域知识（RAG/评测/成本）。
```
