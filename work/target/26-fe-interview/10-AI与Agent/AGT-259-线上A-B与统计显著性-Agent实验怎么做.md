## AGT-259：Agent 功能的线上 A/B 实验怎么设计——避免被随机波动骗？

**答**:
- 实验要素：分流单元（按用户/会话分流——同用户必须进同版本，否则体验割裂且污染数据）、核心指标（北极星：任务完成率/采纳率）+ 护栏指标（成本/延迟/投诉率，防赢了大指标输了系统）、样本量（按最小可检测效应 MDE 反推——Agent 指标方差大，别指望 1% 提升几天测出来）。
- Agent 特有的坑：成本分布长尾（平均成本被少数长任务拉偏——看 P50/P95 与分桶，不只看均值）、学习效应（用户对新界面先不适应）、季节与流量波动（大促周不做实验）、多重比较（测 20 个指标总有"显著"的——预注册指标清单）。
- 判读纪律：实验跑满预定周期（power 计算的时长）才判读，不看中途"显著"（peeking 造假）；结果不显著≠无差异，报告置信区间与 MDE。
- 长期观测：A/B 赢了上线后还要看 30 天漂移（新奇效应消退后可能回落）——上线≠实验结束。

```text
Agent A/B 实验清单：
分流：按用户/会话，同用户同版本
指标：北极星（完成率/采纳率）
  + 护栏（成本 P95 / 延迟 / 负反馈）
样本量：按 MDE 与指标方差反推周期
纪律：预注册指标 / 不 peeking /
  长尾看分位数与分桶 / 避开大促周
上线后：30 天漂移观察，
  新奇效应消退再定论。
```
