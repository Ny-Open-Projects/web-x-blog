## AGT-349：Agent 产品的常见失败模式有哪些——怎么提前规避？

**答**:
- 技术型失败：可靠性不足（90% 成功率的 Agent 在高频使用中"永远会错一次"——用户信任崩塌于第一次大错）、评测缺位（上线靠感觉，badcase 无闭环）、成本失控（单任务成本超用户感知价值）——对应解法：可靠性分层（高危人审）、评测先行（AGT-260）、成本治理（AGT-280）。
- 产品型失败：场景选错（选了高确定性任务——规则就够了，或低价值任务——用户懒得配置）、信任过快（一上来全自动，错一次即流失——应从低授权渐进）、价值可感知性差（后台干活用户看不见——过程透明与进度呈现是产品能力，AGT-340）。
- 组织型失败：无 owner（技术演示没有产品化投入）、数据与工具不备（知识库空转）、合规缺位（高监管领域裸奔）——组织三查在立项期做。
- 规避总纲：立项期"边界+价值+风险"三问（AGT-320 场景工程）、MVP 期评测与灰度、放量期成本与信任管理——失败模式都有对应的前置检查，逐项过。

```text
Agent 产品失败三型：
技术：可靠性/无评测/成本失控
产品：场景错选 / 信任过快 /
  价值不可见
组织：无 owner / 数据不备 / 合规缺位
规避：立项三问（边界/价值/风险）
  → MVP 评测灰度 → 放量期
  成本与信任管理。
关键：90% 成功率 ≠ 可用，
  高危路径必须有人审兜底。
```
