## AGT-360：把 AGT-201~360 的体系收束成一张工程全景图？

**答**:
- 全景五域：数据域（数据管线/知识库/隐私合规，AGT-351/355）、模型与检索域（RAG 管线/长上下文/多模态路由，AGT-201~234）、Agent 运行域（编排/MCP/记忆/各形态，AGT-231~250/331~339）、质量域（评测体系/幻觉治理/红队/反馈闭环，AGT-251~270/299/353）、运营域（成本/安全/SRE/平台化/商业，AGT-271~290/321~328/358）——每个域有独立的技术栈与度量体系，组合成完整工程。
- 域间的关键接口：数据→模型（知识质量决定答案上限）、运行→质量（trace 支撑评测与归因）、质量→运营（评测门禁与成本护栏联动发布）——域解耦但接口契约化。
- 能力建设顺序建议：多数团队的最短路径是"RAG 管线→评测门禁→成本与安全护栏→编排与多 Agent→平台化"——评测门禁优先于多 Agent（没有评测的多 Agent 是灾难放大器）。
- 终章心法：Agent 工程的成熟度不在单点技术（模型/框架会持续换代），而在"可评测、可治理、可复利"的体系——技术会过时，体系资产（评测集/数据飞轮/平台）持续增值。

```text
Agent 工程全景五域：
数据：管线 / 知识库 / 隐私
模型检索：RAG / 长上下文 / 模态路由
运行：编排 / MCP / 记忆 / 专用形态
质量：评测 / 幻觉治理 / 红队 / 反馈
运营：成本 / 安全 / SRE / 平台 / 商业
建设顺序：RAG → 评测门禁 → 护栏
  → 编排 → 平台
终章：体系资产（评测/飞轮/平台）
  比单点技术更保值。
```
