## ALG-344：乐观锁版本号：If-Match/ETag 的前端使用（412 冲突的刷新提示与本地保留）？
**答**：编辑实体的乐观锁：GET 时记录 ETag → PUT 带 If-Match → 412（他人已改）→ 冲突处理：拉最新版展示差异（ALG-265 三方合并）或整页刷新提示——按字段冲突可能性选择。

**思路**：ETag 记录 → If-Match 提交 → 412 时拉新版本 + 本地版本做三方合并（可合并字段自动合并，冲突字段 UI 决策）。

```javascript
async function saveWithOptimisticLock(id, localChanges, etag) {
  const res = await fetch(`/api/doc/${id}`, {
    method: 'PUT',
    headers: { 'If-Match': etag, 'Content-Type': 'application/json' },   // 乐观锁头
    body: JSON.stringify(localChanges),
  });
  if (res.status === 412) {                                // 他人已改：冲突
    const server = await fetch(`/api/doc/${id}`).then((r) => r.json());   // 拉最新
    const merged = threeWayMerge(localChanges.base, localChanges.current, server);   // ALG-265 三方合并
    return { conflict: true, merged, conflicts: merged.conflicts };
  }
  return { etag: res.headers.get('ETag'), ok: res.ok };    // 成功：更新本地 ETag（下次提交用）
}
// 412 语义链：ETag 是内容指纹（服务端变更即变）—— If-Match 精确检测"自上次读取后的任何变更"
// 冲突处理分层：字段级三方合并（ALG-265）自动解决多数冲突 → 真冲突字段 UI 决策 → 全冲突才刷新
// ETag 更新纪律：成功保存后必须更新本地 ETag（旧 ETag 下次必 412——不更新会导致"永久冲突"）
```

**评分点**：
- ETag/If-Match 乐观锁完整流程（记录/提交/412 处理）——本题核心。
- 412 后拉最新做三方合并（ALG-265 联动）而不是直接刷新丢输入。
- 成功后更新本地 ETag 的纪律（防永久冲突）。
- 字段级合并 vs 整页刷新的选择依据。
