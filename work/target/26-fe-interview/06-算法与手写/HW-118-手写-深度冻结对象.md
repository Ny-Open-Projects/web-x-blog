**答**：deepFreeze 递归冻结配置对象（防止运行时意外修改），要点：递归冻结前先检查 isFrozen（幂等）；跳过已冻结；冻结数组同样处理；说明代价——严格模式下写冻结对象抛错（开发期好），但 V8 对冻结对象的属性访问有 deopt 成本（热路径大数据别冻结，配置对象小而无妨）。

```javascript
function deepFreeze(obj) {
  if (obj && typeof obj === 'object' && !Object.isFrozen(obj)) {
    Object.freeze(obj);
    for (const key of Reflect.ownKeys(obj)) {
      const v = obj[key];
      if (v && typeof v === 'object') deepFreeze(v);
    }
  }
  return obj;
}
// 用法：全局配置只读
const CONFIG = deepFreeze({
  api: { base: '/api', timeout: 8000 },
  features: { newCart: true },
});
// CONFIG.api.timeout = 999;  // 严格模式：TypeError；非严格：静默失败
// 性能说明：
// 1. 冻结对象的属性修改会抛错（开发期立即暴露 bug）
// 2. V8 对 frozen 对象的访问有轻微 deopt（hidden class 稳定但写入路径变慢）——
//    配置对象读多写零，冻结零成本；热路径大数据数组不要冻结（React state 更新会卡）
// 3. 配合 TypeScript readonly 类型层 + 运行时 deepFreeze 双保险
```

**评分点**：
- 递归冻结幂等（isFrozen 检查）；数组同样处理。
- 严格模式抛错 vs 非严格静默的语义差异。
- 能说出冻结的性能代价（deopt）与适用边界（小配置对象可、热路径大数据不可）。
- TS readonly + 运行时冻结的双保险意识。
