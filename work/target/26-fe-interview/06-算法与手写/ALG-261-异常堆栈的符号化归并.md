**场景**：线上 minified 堆栈（a.js:1:2345）不可读——按 sourcemap 符号化（源文件:行:列 + 函数名）后聚类：同一错误不同实例（不同用户/不同输入行号）归并为一个错误组，Top 排行驱动修复优先级。

**思路**：指纹设计——符号化后取"错误类型 + 源文件 + 函数名"（忽略行号：同函数内多行抛同一错误归一组）；聚类 Map 计数；行号保留首个样本（定位用）。

```javascript
function errorFingerprint(symbolicated) {
  // symbolicated: [{ fn, file, line, col }] sourcemap 符号化后的帧
  const top = symbolicated[0] ?? {};
  return [                                                // 指纹 = 类型 + 最内层文件 + 函数（忽略行号）
    top.file?.split('/').pop(), top.fn, symbolicated[0]?.type,
  ].filter(Boolean).join('|');
}
class ErrorCluster {
  #clusters = new Map();                                  // 指纹 -> { count, first, sample }
  add(stack, { type } = {}) {
    const fp = errorFingerprint(stack);
    const c = this.#clusters.get(fp) ?? { count: 0, first: Date.now(), sample: stack };
    c.count++;
    this.#clusters.set(fp, c);
  }
  top(n = 10) {
    return [...this.#clusters].map(([fp, c]) => ({ fp, ...c, frames: c.sample.slice(0, 3) }))
      .sort((a, b) => b.count - a.count).slice(0, n);
  }
}
// 指纹粒度权衡：
// 含行号 → 同函数多入口错误被拆散（排行失真）；含函数名 → 聚合合理（同函数 = 同根因大概率）
// 符号化：上报 minified 堆栈 + sourcemap 版本 → 服务端按构建版本查 map 反解（PER-426 版本指纹前提）
// 排行输出：count 排序 × 影响用户数（去重 uid）—— "Top1 错误 1.2 万次/3000 用户"修复优先级
```

**评分点**：
- 指纹粒度权衡（含/不含行号的聚合语义）——本题核心。
- sourcemap 符号化依赖构建版本指纹（PER-426）。
- 排行 = count × 去重用户数（修复优先级的双维度）。
- first/sample 保留（时间线 + 定位样本）。
