## ALG-286：路由切换的数据清理：离开路由时按声明清理（meta.cleanup 声明式资源回收）？
**答**：SPA 路由泄漏（PER-272）：轮询/WS/全局监听/大缓存散落在组件各处，漏一个就泄漏——声明式清理：路由 meta 声明"本页拥有的资源"，路由守卫统一回收（PER-272 的工程化版）。

**思路**：ResourceRegistry（页面级资源注册：轮询/监听/缓存引用）→ 路由 afterEach 按 registry 全量回收 → 泄漏审计（离开后 registry 应为空，非空即泄漏告警）。

```javascript
class PageResources {
  #items = new Set();
  add(cleanup, { label } = {}) { this.#items.add(cleanup); return cleanup; }
  releaseAll() {
    const leaked = [];
    for (const cleanup of this.#items) {
      try { cleanup(); } catch (e) { leaked.push(String(e)); }   // 单清理失败不阻塞其他
    }
    this.#items.clear();
    if (leaked.length) report?.({ type: 'cleanup-error', leaked });
  }
  get size() { return this.#items.size; }                 // 离开路由后 size > 0 = 注册遗漏
}
// 路由集成：
// router.beforeEach((to) => { currentResources?.releaseAll(); });   // 离开统一回收
// 页面 setup：currentResources.add(() => clearInterval(pollTimer), { label: 'order-poll' });
// 泄漏审计：离开路由后 registry.size > 0 → 有资源未注册（漏 add）→ dev 告警
// 语义：声明式（资源在创建时注册清理）—— 比卸载时人肉记忆清理可靠（忘写 = 泄漏，忘注册 = 可检测）
```

**评分点**：
- 声明式资源注册 + 路由守卫统一回收——本题核心（PER-272 工程化）。
- 泄漏审计（registry 非空 = 漏注册，可检测的遗漏）。
- 单清理失败隔离。
- 与框架生命周期清理（onUnmounted）的关系（路由级兜底，覆盖非组件资源）。
