**场景**：埋点 SDK 要去重"同一事件不重复上报"，事件 ID 百万级。用 Set 存 ID 内存爆（百万字符串 ≈ 80MB+）；布隆过滤器：位数组 + k 个哈希，O(1) 时间、几十 KB 内存，代价是有**假阳性**（说"已存在"可能误判，但说"不存在"绝对正确）。

**思路**：add 时 k 个哈希置位；has 时全 1 判存在（可能误阳）、有 0 判不存在（可靠）。误判率公式 m/n·k 决定，前端场景允许 1% 假阳性（多报一条无伤大雅）。

```javascript
class BloomFilter {
  constructor(size = 1 << 20, k = 4) {              // 1M 位 = 128KB
    this.bits = new Uint8Array(Math.ceil(size / 8));
    this.size = size; this.k = k;
  }
  #hashes(str) {
    const out = [];
    for (let i = 0; i < this.k; i++) {
      let h = 2166136261;                            // FNV-1a 变体
      const s = `${str}#${i}`;                       // 盐化出 k 个独立哈希
      for (let j = 0; j < s.length; j++) { h ^= s.charCodeAt(j); h = Math.imul(h, 16777619); }
      out.push((h >>> 0) % this.size);
    }
    return out;
  }
  add(id) { for (const h of this.#hashes(String(id))) this.bits[h >> 3] |= 1 << (h & 7); }
  has(id) { return this.#hashes(String(id)).every((h) => this.bits[h >> 3] & (1 << (h & 7))); }
}
const bf = new BloomFilter();
bf.add('evt-001');
bf.has('evt-001');   // true
bf.has('evt-x');     // 大概率 false（1% 概率误阳 → 重报一条，可接受）
// 内存对比：Set 存 100 万 ID ≈ 80MB；布隆 128KB —— 差 600 倍
// 误判率：n=100 万, m=100 万位, k=4 → 误判率 ≈ (1 - e^(-kn/m))^k ≈ 34%？注意 m 要够大：
// m = 8n（800 万位 = 1MB）时误判率 ≈ 2.1%；m = 12n 时 ≈ 0.3% —— 按业务容忍度选 m
```

**评分点**：
- 布隆语义精确：**不存在绝对可靠，存在可能误阳**——这是核心考点。
- k 个独立哈希（盐化）与位数组实现正确。
- 误判率与 m/n/k 的关系（能算或查公式），并按业务容忍度选参数。
- 适用边界：删除不支持（标准布隆）；需要删除用计数布隆或直接 Set。
