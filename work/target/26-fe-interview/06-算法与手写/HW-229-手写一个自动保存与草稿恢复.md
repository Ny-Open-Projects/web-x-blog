## HW-229：手写一个自动保存与草稿恢复：防抖持久化与版本对比恢复

**答**：
- 需求：实现 AutoSave：onEdit 后防抖 1s 保存（序列化文档+时间戳+选区），IndexedDB 存最近 5 版；恢复流程：启动时检测到未保存草稿 → 提示"恢复/丢弃"，选择恢复后 diff 当前与草稿（若有服务端版本则三选一）。
- 边界：保存失败重试（3 次指数退避）；文档未变更（hash 相同）跳过保存；多标签页冲突（BroadcastChannel 通知互斥保存）。
- 评分点：防抖+hash 去重；版本列表与恢复 UI 数据；多标签互斥。

```javascript
class AutoSave {
  constructor(store, { debounceMs = 1000, keep = 5 } = {}) {
    this.store = store; this.keep = keep; this.t = null; this.lastHash = null;
    this.chan = new BroadcastChannel('autosave');
  }
  onEdit(doc) {
    clearTimeout(this.t);
    this.t = setTimeout(() => this.save(doc), 1000);           // 防抖
  }
  async save(doc) {
    const h = hash(JSON.stringify(doc));
    if (h === this.lastHash) return;                           // 未变更跳过
    const rec = { h, ts: Date.now(), doc, sel: editor.getSelection() };
    try { await this.store.put('draft', rec); this.lastHash = h; await this.trim(); this.chan.postMessage({ saved: h }); }
    catch (e) { retry(() => this.save(doc), 3); }
  }
  async trim() {                                               // 保留最近 keep 版
    const all = await this.store.all('draft');
    const old = all.sort((a, b) => b.ts - a.ts).slice(this.keep);
    for (const o of old) await this.store.del('draft', o.h);
  }
  async recoverCandidates() {                                  // 恢复候选列表
    const all = await this.store.all('draft');
    return all.sort((a, b) => b.ts - a.ts)
      .map(r => ({ ts: r.ts, preview: r.doc.blocks[0]?.text.slice(0, 30),
        size: JSON.stringify(r.doc).length }));
  }
}
function hash(s) { let h = 0; for (const c of s) h = (h * 31 + c.charCodeAt(0)) >>> 0; return h.toString(36); }
function retry(fn, n) { let i = 0; const go = () => fn().catch(() => i++ < n && setTimeout(go, 2 ** i * 500)); go(); }
```

## 补充：评分点与变体

**评分点**：

- 防抖要在 onEdit 里先 clearTimeout 再设新定时器，且定时器回调取的是最新 doc；闭包住首次传入的 doc 会保存过期内容
- hash 去重要在写库之前算，命中相同 hash 直接 return，否则每次编辑都白写一次 IndexedDB
- trim 必须按 ts 倒序 `slice(this.keep)` 取尾部旧记录删除，排序方向写反会把最新版本删掉、直接造成草稿丢失
- 多标签互斥靠 BroadcastChannel 广播已保存的 hash，收到后同步本地 lastHash，否则两个 tab 会互相覆盖同一份 draft

**变体与延伸**：

1. 关闭页面时防抖还没触发 → pagehide 与 visibilitychange 里同步 flush 一次，beforeunload 只做提示不做异步写
2. 大文档序列化卡住输入 → 序列化放进 requestIdleCallback 或 Worker，主线程只传引用
3. 恢复时保留哪一版 → 先按 ts 排序再展示首行预览与体积让用户选；有服务端版本时给三方对比而非二选一
