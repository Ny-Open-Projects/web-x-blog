## ALG-251：提交按钮防重：本地禁用 + 服务端幂等 + 会话锁三层防重的一致性分析？
**答**：提交按钮防重复点击，三层防线各防什么：① 本地禁用（防双击，但刷新/多标签页失效）；② 会话锁（sessionStorage 标记，防同会话刷新重复，但多标签页失效）；③ 服务端幂等键（终极防线，任何路径重复都去重）。分析每层失效场景。

**思路**：本地禁用是 UX 层（秒级）；会话锁是浏览器层（分钟级）；幂等键是业务层（永恒）。前端两层只是体验优化，正确性必须由服务端保证。

```javascript
async function guardedSubmit(payload, { lockKey = 'submit-lock' } = {}) {
  // 层 1：本地禁用（防双击）—— 调用方控制按钮 disabled
  if (sessionStorage.getItem(lockKey)) return { blocked: 'session-lock' };   // 层 2：会话锁
  sessionStorage.setItem(lockKey, '1');
  const key = crypto.randomUUID();                    // 层 3：幂等键
  try {
    return await fetch('/api/order', {
      method: 'POST',
      headers: { 'Idempotency-Key': key, 'Content-Type': 'application/json' },
      body: JSON.stringify(payload),
    }).then(async (r) => {
      const body = await r.json();
      if (r.status === 409) return { duplicate: true, ...body };   // 幂等命中：返回首次结果
      return body;
    }).finally(() => sessionStorage.removeItem(lockKey));
  } catch (e) {
    sessionStorage.removeItem(lockKey);               // 失败释放会话锁（可重试）
    throw e;
  }
}
// 各层失效分析：
// 层 1 失效：双击间隙 < 渲染帧 / 代码未同步 disabled
// 层 2 失效：多标签页（sessionStorage 每标签独立）/ 刷新后手滑
// 层 3 无失效：服务端按键去重 —— 唯一正确性保证
// 结论：前端两层是"减少重复请求到达"，正确性靠服务端幂等（与 HW-100 一致）
```

**评分点**：
- 三层防线各自防什么与失效场景分析——本题核心（正确性必须靠服务端幂等）。
- 会话锁的失败释放（可重试）与多标签页局限。
- 409 幂等命中按成功处理。
- 层级语义清晰：UX 层 / 浏览器层 / 业务层。
