## HW-303：手写一个规则引擎：AND/OR/NOT 条件组合评估

**答**：
- 需求：实现 RuleEngine：规则 {name, condition}，condition 支持嵌套组合 {all: [...]} / {any: [...]} / {not: {...}} / 叶子 {field, op, value}；evaluate(condition, fact) 递归求值；批量规则评估输出命中清单；短路优化（all 遇 false 即停）。
- 边界：op 注册表（eq/gt/in/contains/regex）；叶子字段缺失视为不匹配（fail-closed）；嵌套深度上限。
- 评分点：递归组合求值；短路；op 注册表。

```javascript
const OPS = {
  eq: (a, b) => a === b, gt: (a, b) => a > b, gte: (a, b) => a >= b,
  lt: (a, b) => a < b, in: (a, b) => b.includes(a),
  contains: (a, b) => String(a ?? '').includes(b),
  regex: (a, b) => new RegExp(b).test(String(a ?? '')),
};
function evalCond(cond, fact, depth = 0) {
  if (depth > 20) throw new Error('cond-too-deep');
  if (cond.all) return cond.all.every(c => evalCond(c, fact, depth + 1));      // 短路
  if (cond.any) return cond.any.some(c => evalCond(c, fact, depth + 1));
  if (cond.not) return !evalCond(cond.not, fact, depth + 1);
  const { field, op, value } = cond;
  const fn = OPS[op];
  if (!fn) throw new Error('unknown-op: ' + op);
  const v = fact[field];
  if (v === undefined) return false;                       // fail-closed
  return fn(v, value);
}
class RuleEngine {
  constructor(rules) { this.rules = rules; }
  run(fact) {
    const hit = [];
    for (const r of this.rules)
      if (evalCond(r.condition, fact)) hit.push(r.name);   // 命中清单
    return hit;
  }
}
// 用法：run({age: 20, city: 'BJ'})，规则 {all:[{field:'age',op:'gte',value:18},{any:[...]}]}
```

## 补充：评分点与变体

**评分点**：

- 叶子字段缺失按 fail-closed 处理为不匹配，不能直接拿 undefined 参与比较，否则 `gt` 会因类型转换意外为 true
- 三种短路语义要分清：all 遇 false 即停、any 遇 true 即停、not 只取反不参与短路
- 算子必须走注册表（eq/gt/in/contains/regex）扩展，硬编码 switch 加一个自定义算子就要改核心代码
- regex 算子要有回溯防护，至少限长度或加超时，用户可写的正则能把主线程卡死

**变体与延伸**：

1. 上万条规则怎么批量评估 → 按叶子字段建倒排索引粗筛候选规则，只对候选求值，避免每来一条 fact 全量遍历
2. 需要「首命中即停」与「全命中」两种模式 → run 加 mode 参数，首命中模式命中后 break 并跳过剩余规则
3. 规则热更新时正在求值 → 求值持有版本化规则集快照，更新时整体替换指针，避免读到半新半旧
