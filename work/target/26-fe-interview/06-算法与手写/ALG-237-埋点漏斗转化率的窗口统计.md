**场景**：ALG-215 的进阶：漏斗带窗口约束（view → add_cart 30min 内 → pay 10min 内），每步有自己的时限。校验用户事件序列是否满足全部窗口。

**思路**：顺序扫描记录每步命中时间，命中下一步时校验"与上一步的间隔 ≤ 该步窗口"；不满足则该步作废，继续向后找（同一事件不能重复充当步骤）。

```javascript
function funnelWithWindows(events, steps) {
  // steps: [{ type: 'view', winMs: null }, { type: 'add_cart', winMs: 30*60000 }, ...]
  const hitAt = [];
  let j = 0;
  for (const e of events) {
    const step = steps[j];
    if (!step) break;
    if (e.type !== step.type) continue;
    if (j > 0 && step.winMs != null && e.ts - hitAt[j - 1] > step.winMs) continue;  // 窗口外：此事件不算
    hitAt.push(e.ts);
    j++;
  }
  return { done: j === steps.length, hitAt, lostAtStep: j === steps.length ? null : j };
}
// events: view@0, add_cart@50min, pay@55min, add_cart@10min, pay@12min
// steps: view→add_cart(30m)→pay(10m)
// 扫描：view@0 ✓ → add_cart@50min 超 30m 窗口跳过 → pay@55min 不匹配当前步骤跳过
//       → add_cart@10min ✓（间隔 10m ≤ 30m）→ pay@12min ✓（间隔 2m ≤ 10m）→ done
// 注意：窗口外事件"跳过但不清空前序"（后续事件仍可满足窗口）——语义按业务定
```

**评分点**：
- 每步独立窗口校验（与上一步命中时间的间隔 ≤ 该步 winMs）。
- 窗口外事件跳过但不作废前序（继续向后寻找）的语义明确。
- lostAtStep 流失步输出（支撑流失分析）。
- 事件时间乱序前先排序的边界意识。
