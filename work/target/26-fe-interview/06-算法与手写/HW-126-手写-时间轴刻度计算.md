## HW-126：手写时间轴刻度生成——给定时间范围与目标刻度数，产出"整齐"的刻度（步长取整到 1/2/5×10^n）
**答**：图表时间轴刻度生成：目标 N 个刻度 → 理想步长 = span/N → 步长"取整"到 1/2/5 × 10^n 的漂亮值（人类可读：15 分钟/2 小时/3 天）→ 从对齐起点（如整点/整日）开始产出刻度。

```javascript
function timeTicks(start, end, target = 6) {
  const span = end - start;
  const ideal = span / target;
  // 步长取整到 1/2/5 × 10^n（秒级）
  const pow = 10 ** Math.floor(Math.log10(ideal));
  const nice = [1, 2, 5, 10].map((m) => m * pow).find((v) => v >= ideal) ?? pow * 10;
  // 对齐起点：按步长向下取整（如步长 1h 对齐整点，1d 对齐零点）
  const aligned = Math.floor(start / nice) * nice;
  const ticks = [];
  for (let t = aligned; t <= end; t += nice) {
    if (t >= start) ticks.push(new Date(t));
  }
  return { ticks, stepMs: nice };
}
// timeTicks(10:07, 17:23, 6)：span≈26300s，ideal≈4380s → nice=2*3600=7200（2h）
// 刻度：10:00, 12:00, 14:00, 16:00 —— 人类可读的整齐刻度
// 反例：直接 span/6 均分 → 10:43, 12:19... 不可读
// 标签格式随步长自适应：step<1h → HH:mm；step≥1d → MM-DD
```

**评分点**：
- 步长取整到 1/2/5×10^n 的 nice-number 算法正确。
- 起点对齐（整点/整日）意识——刻度可读性的关键。
- 标签格式随步长自适应。
- 能说出均分刻度不可读的反例。
