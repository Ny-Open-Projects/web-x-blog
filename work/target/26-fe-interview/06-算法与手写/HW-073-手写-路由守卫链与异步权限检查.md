## HW-073：手写路由守卫链——async 权限检查、取消、重定向循环保护
**答**：守卫链 = 前置守卫数组依次执行：返回 false 取消、返回字符串重定向、返回 Promise 等待。关键边界：**重定向循环保护**（to === from 或重定向次数 > 5 直接放行/报错）与并发导航竞态（快速连续跳转只认最后一次，用导航序号丢弃过期 resolve）。

```javascript
class GuardRouter {
  constructor() { this.guards = []; this.seq = 0; this.maxRedirects = 5; }
  beforeEach(g) { this.guards.push(g); }

  async navigate(to, redirects = 0) {
    const mySeq = ++this.seq;
    for (const g of this.guards) {
      let v;
      try { v = await g(to, location.pathname); }
      catch (e) { return console.error('guard error', e), false; }
      if (this.seq !== mySeq) return false;                 // 已有更新的导航，过期结果丢弃
      if (v === false) return false;                        // 取消
      if (typeof v === 'string' && v !== to) {              // 重定向
        if (redirects >= this.maxRedirects) {               // 循环保护
          throw new Error(`重定向循环: ${to} -> ${v}`);
        }
        return this.navigate(v, redirects + 1);
      }
    }
    history.pushState(null, '', to);
    return true;
  }
}
// 用法
const router = new GuardRouter();
router.beforeEach(async (to) => {
  if (to === '/pay' && !(await getUser())) return '/login?next=' + to;  // 异步权限
  if (to === '/login' && (await getUser())) return '/home';             // 已登录跳走
  return true;
});
router.beforeEach((to) => to.startsWith('/vip') ? false : true);          // 直接拦截
```

**评分点**：
- 守卫三种返回值语义完整（false 取消 / 字符串重定向 / true 放行），async await 正确。
- 重定向循环保护（计数上限）——大多数人会漏。
- 并发导航竞态：seq 递增丢弃过期守卫结果。
- 重定向自调用时 to !== v 条件（允许"自我重定向即放行"避免误判循环）。

## 变体与延伸（补充）

**变体与延伸**：

1. 守卫里 throw 了怎么算 → 视为取消并回滚到 from，同时上报错误；async 未 catch 会变成 unhandledRejection，页面停在半导航状态，显式取消应走 next(false)，别靠静默 resolve 蒙混
2. 重定向计数上限设多少、超限怎么办 → 一般 10 次，超限中断并跳错误页；计数须在每次导航开始时重置，否则正常的连续重定向会被误杀；跳错误页也比白屏更可诊断
3. 嵌套路由的守卫顺序 → 按 matched 数组从父到子依次执行 beforeEach，子守卫依赖父级 meta 时必须先父后子，顺序反了读到的是 undefined；父级守卫返回重定向时子级不再执行
