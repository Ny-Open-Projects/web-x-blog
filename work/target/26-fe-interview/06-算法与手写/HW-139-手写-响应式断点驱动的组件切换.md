**答**：桌面/移动渲染不同组件（表格 vs 卡片列表）：matchMedia 监听断点（change 事件，不轮询）；切换抖动消除——断点临界区（±20px）滞回（hysteresis），防窗口拖动时组件反复重挂；切换时状态保留（尺寸筛选等用户状态透传）。

```javascript
function responsiveSwitch(breakpoint = 768) {
  const mq = matchMedia(`(min-width: ${breakpoint}px)`);
  const mqUp = matchMedia(`(min-width: ${breakpoint + 20}px)`);    // 滞回双阈值
  const mqDown = matchMedia(`(min-width: ${breakpoint - 20}px)`);
  const subs = new Set();
  let desktop = mq.matches;
  const onChange = () => {
    // 滞回：向上穿 +20 才切桌面，向下穿 -20 才切移动 —— 临界区不抖动
    const next = desktop ? mqDown.matches : mqUp.matches;
    if (next !== desktop) {
      desktop = next;
      subs.forEach((f) => f(desktop));
    }
  };
  mqUp.addEventListener('change', onChange);
  mqDown.addEventListener('change', onChange);
  return {
    get desktop() { return desktop; },
    subscribe(fn) { subs.add(fn); fn(desktop); return () => subs.delete(fn); },
  };
}
// 用法：
const r = responsiveSwitch(768);
r.subscribe((desktop) => render(desktop ? <DataTable /> : <CardList />));
// 组件切换时用户状态透传：筛选/排序条件放在外部 store，切挂载不丢状态
// 切换成本意识：重挂载组件 = 卸载+重建（状态丢失+闪烁）——能用 CSS 切换显示就不用 JS 重挂
```

**评分点**：
- 滞回双阈值防临界抖动（±20px 穿越才切换）——本题核心。
- matchMedia change 事件（不轮询 resize）。
- 订阅模式 + 状态透传（切换不丢用户输入）。
- 能说出"CSS 能切换就不 JS 重挂"的成本意识。
