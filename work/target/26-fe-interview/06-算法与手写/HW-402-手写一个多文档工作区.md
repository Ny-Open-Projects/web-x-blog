## HW-402：手写一个多文档工作区：打开缓存与脏状态管理

**答**：
- 需求：实现 Workspace：多文档管理（打开列表 + 活跃文档）；打开缓存（LRU 上限 N 个，超出关闭最久未活跃的——关闭前强制保存或提示）；脏状态（dirty 标记 + 关闭前检查）；tab 数据（标题/脏标/图标）输出给 UI；文档切换防抖（快速切换只渲染最后的）。
- 边界：LRU 淘汰的脏文档强制保存（失败则不关闭并提示）；切换防抖（120ms）；活跃文档的输入事件只绑当前；内存约束（文档内容懒加载）。
- 评分点：LRU 脏文档保护；切换防抖；懒加载。

```javascript
class Workspace {
  constructor({ maxOpen = 8, switchDebounce = 120 } = {}) {
    this.open = new Map();                                   // docId -> {doc, dirty, lastActive}
    this.max = maxOpen; this.activeId = null;
    this.switchDebounce = switchDebounce;
    this.switchTimer = null;
  }
  async openDoc(id, loader) {
    if (!this.open.has(id)) {
      if (this.open.size >= this.max) await this.evict();    // LRU 淘汰
      this.open.set(id, { doc: await loader(id), dirty: false, lastActive: Date.now(), loader });
    }
    this.open.get(id).lastActive = Date.now();
    this.scheduleSwitch(id);                                 // 防抖切换
    return this.open.get(id);
  }
  scheduleSwitch(id) {
    clearTimeout(this.switchTimer);
    this.switchTimer = setTimeout(() => { this.activeId = id; this.onChange?.(id); }, this.switchDebounce);
  }
  markDirty(id) { const e = this.open.get(id); if (e) e.dirty = true; }
  async evict() {                                            // LRU 淘汰
    const sorted = [...this.open.entries()].sort((a, b) => a[1].lastActive - b[1].lastActive);
    for (const [id, entry] of sorted) {
      if (id === this.activeId) continue;
      if (entry.dirty) {
        const ok = await autoSave(entry);                    // 脏文档先保存
        if (!ok) { entry.dirty = 'save-failed'; continue; }  // 失败不关闭
      }
      this.open.delete(id);
      return;
    }
  }
  async closeDoc(id, { force = false } = {}) {
    const e = this.open.get(id);
    if (e?.dirty && !force) return { needConfirm: true };    // 关闭前检查
    this.open.delete(id);
    return { closed: true };
  }
  tabs() { return [...this.open.entries()].map(([id, e]) =>
    ({ id, title: e.doc.title, dirty: e.dirty === true, active: id === this.activeId })); }   // tab 数据
}
```

## 补充：评分点与变体

**评分点**：

- LRU 淘汰前必须查 dirty，脏文档先强制保存；保存失败则不关闭并提示，直接淘汰等于丢用户内容
- 切换防抖 120ms 且只渲染最后一次目标，否则快速 Ctrl+Tab 会把中间文档逐个加载一遍
- 输入事件只绑当前活跃文档，切走时解绑，绑错对象会把 A 的输入写进 B
- tabs 是派生数据，脏标记变化只需更新对应项，整体重算会在多标签场景下反复触发渲染

**变体与延伸**：

1. 超出上限但打开的文档全是脏的 → 不允许静默淘汰，提示用户手动关闭或先批量保存
2. 懒加载加 LRU 释放后如何还原现场 → 关闭前记录 scrollTop 与选区，重开时按记录恢复
3. 同一文档在两个窗口打开 → 需跨窗口同步或禁止重复打开，否则后写覆盖先写
