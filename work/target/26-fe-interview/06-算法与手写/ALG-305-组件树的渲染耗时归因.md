**场景**：性能面板只见总时长——"哪个组件慢"需要组件级归因：每个组件记录自身耗时（mount/update，不含子组件），树上卷出"贡献排行"（排除子组件的自耗时 = 真正该优化的组件）。

**思路**：组件计时（mount 前后 performance.now，子组件耗时从父扣除——Self Time 语义）→ 树聚合 Top 排行。

```javascript
class ComponentProfiler {
  #timings = new Map();                                   // 组件名 -> { self, total, count }
  #stack = [];                                            // 渲染栈（父子关系）
  start(name) {
    this.#stack.push({ name, t0: performance.now(), childrenMs: 0 });
  }
  end() {
    const frame = this.#stack.pop();
    const total = performance.now() - frame.t0;
    const self = total - frame.childrenMs;                // Self Time：扣除子组件（PER-298 语义）
    const t = this.#timings.get(frame.name) ?? { self: 0, total: 0, count: 0 };
    t.self += self; t.total += total; t.count++;
    this.#timings.set(frame.name, t);
    const parent = this.#stack.at(-1);
    if (parent) parent.childrenMs += total;               // 子组件耗时累加给父（供父的 self 扣除）
    return self;
  }
  top(n = 10) {
    return [...this.#timings].map(([name, t]) => ({ name, selfAvg: +(t.self / t.count).toFixed(1), ...t }))
      .sort((a, b) => b.self - a.self).slice(0, n);
  }
}
// 用法（React Profiler API 或手写包装）：
// <Profiler id="GoodsList" onRender={() => { p.start('GoodsList'); queueMicrotask(() => p.end()); }} />
// Self Time 排行的意义：total 最大的组件可能是"容器"（子组件贵）—— self 才是"自己贵"（PER-298 双口径）
// 输出：[{ name: 'PriceTable', selfAvg: 8.2, count: 42 }, ...] —— 优化优先级直接可见
```

**评分点**：
- Self Time 语义（父耗时扣除子组件）——本题核心（PER-298 的组件树版）。
- 渲染栈 + childrenMs 累加的排除机制。
- Top 排行按 self 排序（优化优先级）。
- 与 React Profiler/手写包装的落地方式。
