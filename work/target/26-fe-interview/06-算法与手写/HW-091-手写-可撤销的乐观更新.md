**答**：乐观更新三步：快照当前状态 → 应用变更渲染 → 请求成功确认/失败回滚。多次并发操作要栈式管理（回滚要按逆序），且回滚后还要"重放"后续成功操作（A 失败不能把成功的 B 也冲掉）。用版本号做冲突检测。

```javascript
class OptimisticManager {
  constructor(store) { this.store = store; this.ops = new Map(); }  // id -> {snapshot, apply, request}
  async apply(applyFn, request, { id = crypto.randomUUID?.() ?? String(Math.random()) } = {}) {
    const snapshot = structuredClone(this.store.state);             // 快照
    applyFn(this.store.state);                                      // 乐观改
    this.store.notify();
    const op = { snapshot, apply: applyFn, request };
    this.ops.set(id, op);
    try {
      const serverState = await request();
      this.store.state = serverState ?? this.store.state;           // 服务端数据优先（可选）
      this.store.notify();
      this.ops.delete(id);
      return true;
    } catch (e) {
      // 回滚：恢复快照，并重放"比本操作新"的成功操作（简化：恢复快照后通知调用方重放队列）
      this.store.state = snapshot;
      // 重放其他在途成功 op 的 apply（按提交顺序）
      for (const [oid, o] of [...this.ops]) if (oid !== id && o.applied) o.apply(this.store.state);
      this.store.notify();
      this.ops.delete(id);
      return false;                                                 // 调用方提示失败并询问重试
    }
  }
}
// 用法：点赞
const mgr = new OptimisticManager(store);
const ok = await mgr.apply(
  (state) => { item.liked = true; item.likes++; },                  // 乐观 UI
  () => api.post(`/goods/${id}/like`),                              // 真实请求
);
if (!ok) toast('点赞失败，请重试');
// 关键点：快照回滚不是简单 state = snapshot——要考虑并发 op 互相覆盖，故需重放
```

**评分点**：
- 快照回滚语义正确，并能说出"并发操作回滚需重放后续操作"这一坑点。
- 乐观 UI 先行 + 请求结果确认（服务端数据优先）。
- 失败路径给调用方明确结果（不静默）。
- structuredClone 深快照（浅快照回滚会残留内层变更）。
