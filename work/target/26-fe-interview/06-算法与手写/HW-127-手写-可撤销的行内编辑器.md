## HW-127：手写表格行内编辑——Esc 取消还原、Enter 提交校验、失焦策略与并发编辑冲突提示
**答**：行内编辑四要素：① 进入编辑取原值快照（Esc 还原）；② Enter 提交前校验（失败不清编辑态）；③ 失焦策略（失焦即提交 or 失焦取消——按业务定，默认失焦提交 + Esc 取消优先）；④ 并发冲突——提交时带行版本号（updated_at），服务端 409 时提示刷新。

```jsx
function EditableCell({ row, field, onSave }) {
  const [editing, setEditing] = useState(false);
  const [draft, setDraft] = useState('');
  const [conflict, setConflict] = useState(false);
  const snapshot = useRef(null);

  function start() { snapshot.current = row[field]; setDraft(row[field]); setEditing(true); }
  function cancel() { setDraft(snapshot.current); setEditing(false); }       // Esc：还原快照
  async function commit() {
    if (draft === snapshot.current) return setEditing(false);                // 未变更不提交
    const err = validate(field, draft);
    if (err) return;                                                          // 校验失败保持编辑态
    const ok = await onSave(row.id, field, draft, row.updatedAt);            // 带版本号
    if (ok) { setEditing(false); }
    else setConflict(true);                                                    // 409 冲突提示
  }
  if (!editing) return <td onDoubleClick={start}>{row[field]}</td>;
  return (
    <td>
      {conflict ? <span role="alert">已被他人修改，请刷新后重试</span> : (
        <input value={draft} autoFocus
          onChange={(e) => setDraft(e.target.value)}
          onKeyDown={(e) => {
            if (e.key === 'Enter') commit();
            if (e.key === 'Escape') cancel();
          }}
          onBlur={commit} />                                                  {/* 失焦提交 */}
      )}
    </td>
  );
}
// 快照还原（Esc）与"未变更不提交"是最常漏的边界；冲突用行版本号乐观锁
```

**评分点**：
- 快照还原语义（Esc 精确还原进入编辑时的值，不是清空）。
- "未变更不提交"短路；校验失败保持编辑态不清空。
- 失焦策略明确且 Esc 优先级高于失焦。
- 并发冲突乐观锁（行版本号 + 409 提示刷新）。
