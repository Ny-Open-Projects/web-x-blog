## ALG-218：数据同步：接口每次最多返回 limit 条且总数未知，最少请求次数拉完全量（倍增+二分）
**答**：同步 10 万条数据，接口 `GET /list?offset=x&limit=y`（y ≤ 服务端上限 500）。朴素做法固定 limit=500 循环。优化点：① 用 HEAD/响应头拿 total 则精确分片；② total 未知时用"倍增探测"找尾部（指数跳 offset 直到越界，再二分定位总数），总请求数 O(log n) 探测 + O(n/limit) 拉取。

**思路**：探测只做一次；分页拉取不可省（必须每条都拿到）。工程优化是**并行分片**（已知 total 后并发拉，限并发数）。

```javascript
async function fetchAll({ fetchPage, limit = 500, concurrency = 4 }) {
  // 1. 倍增探测 total（total 未知时）：offset=500,1000,2000... 直到空页
  let total = 0;
  for (let probe = limit; ; probe *= 2) {
    const rows = await fetchPage(probe, limit);
    if (rows.length < limit) { total = probe + rows.length; break; }
    total = probe + limit;
  }
  // 2. 并行分片拉取（限并发）
  const pages = Math.ceil(total / limit);
  const result = new Array(total);
  let next = 0, done = 0;
  await Promise.all(Array.from({ length: Math.min(concurrency, pages) }, async () => {
    while (true) {
      const i = next++;
      if (i >= pages) return;
      const rows = await fetchPage(i * limit, limit);
      rows.forEach((r, k) => { result[i * limit + k] = r; });
      done++;
    }
  }));
  return result;
}
// 10 万条、limit=500：探测 ~9 次请求（log2(100000/500)≈8）+ 分页 200 次（并发 4）≈ 209 次
// 对比朴素串行 200 次但无并行 —— 并行分片把墙钟时间除以 concurrency
// 边界：total 变化（同步期间新增数据）→ 以最后探测为准或服务端给 revision 快照
```

**评分点**：
- 倍增探测 total 的正确性（指数跳 + 空页/短页定位），请求次数 O(log n)。
- 并行分片 + 并发上限（worker 池模式），结果按 offset 写回无乱序。
- 能说清"探测次数少但分页次数省不了"的本质（每条数据必须拉一次）。
- 同步期间数据变化的边界意识（revision 快照）。
