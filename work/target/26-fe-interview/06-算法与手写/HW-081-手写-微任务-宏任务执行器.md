**答**：考察对事件循环的掌握：宏任务队列（setTimeout）与微任务队列（Promise.then）优先级——**每执行完一个宏任务，清空全部微任务**（微任务可派生微任务，要循环清空），然后再取下一个宏任务。用两个数组模拟并跑一个 tick 循环验证执行顺序。

```javascript
class MiniEventLoop {
  constructor() { this.macros = []; this.micros = []; this.running = false; }
  macro(fn) { this.macros.push(fn); }
  micro(fn) { this.micros.push(fn); }
  async run() {
    while (this.macros.length) {
      const macro = this.macros.shift();
      macro();                                     // 1. 执行一个宏任务
      while (this.micros.length) {                 // 2. 清空微任务（含派生）
        const micro = this.micros.shift();
        micro();                                   // micro 里 push 的 micro 也会被清空
      }
    }
    if (this.micros.length) {                      // 残余微任务兜底（宏队列空时）
      while (this.micros.length) this.micros.shift()();
    }
  }
}
// 验证经典顺序：
const el = new MiniEventLoop();
const log = [];
el.macro(() => { log.push('macro1'); el.micro(() => log.push('micro1.1')); });
el.micro(() => log.push('micro0'));
el.macro(() => log.push('macro2'));
await el.run();
// log => ['micro0', 'macro1', 'micro1.1', 'macro2']
// 解读：run 前先清一轮微任务（模拟 sync 尾部微任务），然后 macro1 → 它派生的 micro1.1 → macro2
```

**评分点**：
- 顺序规则正确：一个宏任务 → 清空全部微任务（循环含派生）→ 下一个宏任务。
- 微任务可派生微任务的处理（while 循环而非 if）。
- 能解释为什么 Promise.then 比 setTimeout(0) 先执行。
- 初始已有微任务的边界处理。
