**场景**：筛选器连续点击（品牌 A → B → C），三个请求并发返回顺序不定——渲染必须与"最后点击的筛选"一致（HW-117 的列表版 + 快照校验：渲染时比对当前筛选与结果对应的筛选）。

**思路**：双重校验——请求序号（seq 丢弃过期响应）+ 筛选快照绑定（响应携带其请求时的筛选指纹，渲染前比对当前筛选指纹——防"序号对但筛选已被用户再改"的窗口）。

```javascript
class FilterRenderer {
  #seq = 0; #currentFingerprint = '';
  async apply(filters) {
    const seq = ++this.#seq;
    const fingerprint = JSON.stringify(sortEntries(filters));   // 筛选指纹（键序规范化）
    this.#currentFingerprint = fingerprint;
    const rows = await fetchRows(filters);                    // 网络请求
    if (seq !== this.#seq) return;                            // 有更新的请求：丢弃（序号校验）
    if (this.#currentFingerprint !== fingerprint) return;     // 用户又改了筛选：丢弃（快照校验）
    render(rows, filters);                                    // 双校验通过：渲染
  }
}
function sortEntries(obj) {
  return Object.entries(obj).filter(([, v]) => v != null && v !== '')
    .sort(([a], [b]) => a.localeCompare(b));
}
// 双校验缺一不可：
// 只有序号 → 竞态覆盖 OK，但"响应期间用户又改筛选"会渲染错配数据（序号是最新但筛选已变）
// 只有快照 → 并发响应乱序到达仍可能错配
// 指纹 = 键序规范化 JSON（筛选对象顺序无关比较，PER-384 语义）
```

**评分点**：
- 序号 + 快照指纹双校验——本题核心（单靠任一层都有漏网窗口）。
- 指纹的键序规范化。
- 快照校验针对的具体窗口（响应期间用户再改）。
- 与 HW-117 的关系（abort 版 vs 指纹版的适用差异——不可 abort 的场景用指纹）。
