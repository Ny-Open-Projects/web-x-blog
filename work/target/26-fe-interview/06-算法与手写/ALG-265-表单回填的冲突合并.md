**场景**：用户编辑表单期间服务端被他人更新——三方合并（base=打开时快照, draft=本地草稿, server=服务端最新）：字段级判定——draft 改了且 server 没改 → 用 draft；server 改了且 draft 没改 → 用 server；都改且不同 → 冲突（UI 选择）。

**思路**：字段级 diff 三版本 → 三方合并规则表 → 冲突清单输出（字段名/两个值）。

```javascript
function threeWayMerge(base, draft, server) {
  const out = { ...server }, conflicts = [];
  for (const k of new Set([...Object.keys(base), ...Object.keys(draft), ...Object.keys(server)])) {
    const b = base[k], d = draft[k], s = server[k];
    const draftChanged = d !== b, serverChanged = s !== b;
    if (!draftChanged) continue;                          // 本地没动：直接用 server（含 server 修改）
    if (!serverChanged) out[k] = d;                       // server 没动：保留本地修改
    else if (d !== s) conflicts.push({ field: k, mine: d, theirs: s });   // 都改且不同：冲突
    else out[k] = d;                                      // 都改成相同值：无冲突
  }
  return { merged: out, conflicts };                      // conflicts 非空 → UI 逐字段选择
}
// threeWayMerge(
//   { name: 'a', price: 100, note: '' },
//   { name: 'b', price: 100, note: 'x' },   // 本地改 name、加 note
//   { name: 'a', price: 120, note: '' })    // server 改 price
// => merged: { name: 'b', price: 120, note: 'x' }, conflicts: [] —— 各自修改完美合并
// 都改 name（b vs c）→ conflicts: [{ field: 'name', mine: 'b', theirs: 'c' }] → UI 选择
// 三方合并的价值：只冲突"真冲突"字段（双方都改）—— 比整表覆盖/整表拒绝都精准
```

**评分点**：
- 三方合并规则表（字段级四分支）——本题核心。
- "都改成相同值不算冲突"的分支。
- conflicts 输出结构驱动 UI 逐字段选择（mine/theirs 对比）。
- 与整表乐观锁（HW-127 版本号）的粒度对比（字段级更精准）。
