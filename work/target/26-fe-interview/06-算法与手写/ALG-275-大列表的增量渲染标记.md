**场景**：无框架列表（HW-147 手写渲染）：数据更新后全量重渲染 1000 行 vs 增量（脏区间计算）——LCS/前缀对比找"哪些行变了"，只更新变化行（O(diff)）。

**思路**：简化版：按 id 建 Map（旧列表 idx），新列表遍历——旧有且相同位置内容相同 → skip；位置变 → move 标记；新增/删除 → 计算连续脏区间（批量 DOM 操作优于逐行）。

```javascript
function dirtyRanges(oldList, newList) {
  const oldIdx = new Map(oldList.map((x, i) => [x.id, i]));
  const dirty = new Set();
  newList.forEach((item, i) => {
    const prev = oldIdx.get(item.id);
    if (prev == null || oldList[prev] !== item) dirty.add(i);   // 新增或内容变化
  });
  const removed = oldList.filter((x) => !newList.some((y) => y.id === x.id)).length;
  // 合并连续脏行 → 区间（减少 DOM 操作批次）
  const ranges = [];
  let start = null;
  for (let i = 0; i <= newList.length; i++) {
    if (dirty.has(i) && start == null) start = i;
    else if (!dirty.has(i) && start != null) { ranges.push([start, i]); start = null; }
  }
  return { ranges, removed };
}
// 渲染器：
// for (const [s, e] of ranges) rerenderRange(s, e);   // 区间批量更新（一次 reflow per 区间）
// removed > 0 → 尾部裁剪
// 增量收益：1000 行改 10 行 → O(10) DOM 操作 vs O(1000) 全量（快 100 倍）
// 数据结构前提：行内容不可变（引用相等即内容相同——同 ALG-099 结构共享语义）
```

**评分点**：
- id 索引 + 内容引用比较的脏行判定——本题核心。
- 连续脏行合并区间（批量 DOM 操作优于逐行）。
- 不可变数据前提（引用相等 = 内容相同）说明。
- 增量 vs 全量的收益量化。
