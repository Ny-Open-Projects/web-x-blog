**场景**：详情页三接口：先到先渲染（用户尽快看到内容，但布局跳变 CLS）vs 汇合渲染（全部就绪一次渲染，布局稳定但慢）。判定依据：区块间布局依赖——独立区块先到先渲染，耦合区块（价格影响按钮态）汇合。

**思路**：区块依赖声明（independent: true/false）→ 独立块 onEach 即时渲染，耦合块 allSettled 汇合渲染。

```javascript
function renderStrategy(blocks, { onEach, onAll }) {
  const independent = blocks.filter((b) => b.independent);   // 布局独立：先到先渲染
  const coupled = blocks.filter((b) => !b.independent);      // 布局耦合：汇合渲染
  independent.forEach((b) => b.fetch().then((d) => onEach(b, d)));   // 谁先到谁渲染（感知速度）
  Promise.allSettled(coupled.map((b) => b.fetch())).then((rs) => {
    onAll(coupled.map((b, i) => ({ b, data: rs[i].status === 'fulfilled' ? rs[i].value : null })));
  });                                                        // 汇合：一次渲染（布局稳定，含降级 null）
}
// 判定规则：
// 独立区块（评论区/推荐位）：先到先渲染 —— CLS 风险低（区块间无布局耦合）
// 耦合区块（价格+库存+按钮态）：汇合渲染 —— 分开渲染会"按钮先可点后禁用"跳变（交互态打架）
// 混合策略收益：感知速度（独立块即时）+ 布局稳定（耦合块汇合）—— 不是二选一
// 降级：耦合块中某接口失败 → null 传入 onAll（区块显示降级态，不阻塞其他耦合块）
```

**评分点**：
- 区块依赖声明驱动的双策略（独立先到先渲染/耦合汇合）——本题核心。
- 耦合判定理由（交互态跳变 vs 布局位移）。
- allSettled 降级 null（部分失败不阻塞）。
- 混合策略的收益（感知+稳定兼得）。
