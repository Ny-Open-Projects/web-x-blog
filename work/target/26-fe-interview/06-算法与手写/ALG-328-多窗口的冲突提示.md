**场景**：ALG-281 合并的实时版：用户正在编辑"价格"字段时，另一窗口改了价格——当前窗口收到广播，字段旁出现"另一窗口已修改此字段"提示（不打断输入，提交时决策）。

**思路**：BroadcastChannel 广播字段级变更 → 接收方比对"正在编辑的字段集"→ 交集即冲突 → 字段级提示（提交时三选一：用我的/用对方的/对比）。

```javascript
const bc = new BroadcastChannel('doc-edit');
const editing = new Set();                                // 本窗口正在编辑的字段（focus 时加入）

bc.onmessage = ({ data }) => {
  if (data.type === 'field-change') {
    if (editing.has(data.field)) {                        // 正在编辑的字段被别处修改：实时冲突
      markConflict(data.field, data.value);               // 字段旁提示（不覆盖输入框——不打断）
    } else {
      applyRemote(data.field, data.value);                // 未编辑字段：直接同步（无感合并）
    }
  }
};
input.addEventListener('focus', () => editing.add(name));
input.addEventListener('blur', () => { editing.delete(name); resolveConflict(name); });   // blur 时决策
input.addEventListener('input', () => {
  bc.postMessage({ type: 'field-change', field: name, value: input.value, ts: Date.now() });
});
// 分级语义：
// 未编辑字段 → 直接同步（无感合并，多数场景）
// 编辑中字段 → 提示不覆盖（保留用户输入流——打断输入是最差体验）
// blur 时 → 冲突决策（用我的/用对方的）—— 用户主动解决
// 与 ALG-281（提交时合并）的差异：实时冲突提示（编辑过程可感知）—— 协作密度高的场景
```

**评分点**：
- 编辑集（editing Set）与变更广播的交集冲突检测——本题核心。
- 三级处理（未编辑直接同步/编辑中提示不覆盖/blur 决策）。
- 不打断输入流（提示不覆盖输入框）的体验优先级。
- 与 ALG-281 提交时合并的粒度对比。
