**场景**：权限系统推送变更：权限集 500 项、变更通常 1~2 项——全量推送浪费带宽且客户端全量重建；增量推送（added/removed diff）+ 客户端幂等应用。边界：变更密集期增量丢失 → 定期全量校准（心跳快照）。

**思路**：服务端 diff 产出 {added, removed, rev}；客户端按 rev 顺序应用（乱序丢弃/缓存等待）；rev 缺口 → 请求全量快照对齐（gap 检测）。

```javascript
// 服务端：diff 产出
function permissionDiff(oldSet, newSet, rev) {
  const oldS = new Set(oldSet), newS = new Set(newSet);
  return { rev,
    added: [...newS].filter((x) => !oldS.has(x)),
    removed: [...oldS].filter((x) => !newS.has(x)),
  };
}
// 客户端：幂等应用 + gap 检测
class PermissionStore {
  #perms = new Set(); #rev = 0; #pending = new Map();
  apply({ rev, added, removed }) {
    if (rev <= this.#rev) return;                         // 旧变更：幂等丢弃
    if (rev > this.#rev + 1) {                            // 缺口：缓存等待中间变更
      this.#pending.set(rev, { added, removed });
      this.#requestSnapshot();                            // 请求全量对齐（gap 补齐）
      return;
    }
    added.forEach((p) => this.#perms.add(p));
    removed.forEach((p) => this.#perms.delete(p));
    this.#rev = rev;
    this.#drainPending();                                 // 应用缓存的后续变更
  }
  setSnapshot(perms, rev) {                               // 全量对齐
    this.#perms = new Set(perms); this.#rev = rev;
    this.#drainPending();
  }
  #drainPending() {
    for (const [rev, d] of [...this.#pending].sort((a, b) => a[0] - b[0])) {
      if (rev !== this.#rev + 1) break;
      this.apply(d); this.#pending.delete(rev);
    }
  }
}
// 全量 500 项 ≈ 8KB；增量 2 项 ≈ 60B —— 高频变更场景省 99% 带宽
// gap 检测：rev 缺口 → 全量对齐（增量推送的正确性兜底）—— WS 断线重连场景必配
```

**评分点**：
- 增量 diff + rev 顺序应用 + 幂等丢弃——本题核心。
- gap 检测 → 全量快照对齐（增量丢失的正确性兜底）。
- pending 缓存队列按序 drain。
- 带宽量化对比（8KB vs 60B）与心跳全量校准。
