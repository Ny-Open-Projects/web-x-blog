**场景**：万行列表点击：不能遍历找行（O(n)）——事件委托 + dataset.index（O(1) 反查）；嵌套元素（按钮/图标）用 closest 上溯到行容器；虚拟列表下 dataset.index 是数据索引（不是 DOM 序号）。

**思路**：委托容器监听 → closest('[data-index]') → dataset.index 取数据 → 虚拟列表兼容（index 即数据索引，DOM 节点复用不影响）。

```javascript
listEl.addEventListener('click', (e) => {
  const row = e.target.closest('[data-index]');           // 嵌套元素上溯到行（O(depth) 极小）
  if (!row || !listEl.contains(row)) return;              // 点在容器外/行外：忽略
  const idx = +row.dataset.index;                         // O(1) 数据索引（虚拟列表 = 数据索引）
  const item = data[idx];
  handleRowClick(item, idx, e);
});
// 对比：e.target 逐级 parentNode 手写循环（closest 的标准替代）；
// 遍历 rows.find((x) => x.el === e.target)（O(n) —— 万行点击卡顿的根因）
// 虚拟列表兼容：dataset.index 存数据索引（HW-067 渲染时写入）—— DOM 复用后 dataset 随内容更新，永远正确
// dataset 与事件委托的组合是"大列表交互"的标准解：O(1) 定位 + 单监听器
```

**评分点**：
- closest + dataset.index 的 O(1) 反查——本题核心（拒绝 O(n) 遍历）。
- 嵌套元素上溯与 contains 边界（行外点击忽略）。
- 虚拟列表下 dataset.index 语义（数据索引非 DOM 序号）。
- 事件委托单监听器（不逐行绑定，HW-164 泄漏防线）。
