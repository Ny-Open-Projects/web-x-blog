## ALG-332：大数组的内存友好过滤：流式 filter（TypedArray 视图 + 双指针原地压缩，不分配新数组）？
**答**：100 万元素过滤：filter() 分配新数组（8MB 瞬时）+ 旧数组共存 = GC 压力（PER-273）。原地压缩：双指针（读写指针），过滤后截断——零新分配。

**思路**：双指针遍历（读指针扫、写指针收）→ subarray 截断（TypedArray 视图，不拷贝）。

```javascript
function inPlaceFilter(arr, predicate) {
  let write = 0;
  for (let read = 0; read < arr.length; read++) {
    if (predicate(arr[read])) arr[write++] = arr[read];   // 写指针只前移（保留项原地压缩）
  }
  return arr.subarray(0, write);                          // 视图截断（零拷贝，不分配新内存）
}
const data = new Float64Array(1_000_000);                 // 8MB
const filtered = inPlaceFilter(data, (v) => v > 0);       // 原地：GC 零新分配
// 对比 data.filter(...)：分配新 8MB 数组 + 旧 8MB 共存（16MB 峰值 + GC 压力）
// 原地语义：调用方知悉（输入被修改）—— 不可变需求场景（React state）不能用（PER-099 语义冲突）
// 适用：Worker 内数据处理（结果一次性消费）、大报表计算—— 可变管道场景
// subarray 是视图（与原 buffer 共享内存）—— 需要独立副本时 slice（拷贝换隔离，按需选择）
```

**评分点**：
- 双指针原地压缩 + subarray 视图截断（零新分配）——本题核心。
- 与 filter() 的内存对比（16MB 峰值 vs 0）。
- 可变语义边界（不可变场景不适用——React state 冲突）。
- subarray 视图 vs slice 拷贝的取舍。
