## HW-318：手写一个前端限流引擎：令牌桶、漏桶与并发池统一接口

**答**：
- 需求：实现 RateLimiter：三种策略统一 acquire(n) 接口——令牌桶（速率+突发容量）、漏桶（恒定流出速率排队）、并发池（最大并发）；返回 Promise（排队等待或拒绝 fast-fail 可配）；stats（拒绝数/排队数）。
- 边界：令牌桶按时间补充（惰性计算，不用定时器）；漏桶 FIFO 队列；acquire(0) 立即返回。
- 评分点：惰性令牌补充；统一接口；fast-fail 选项。

```javascript
class TokenBucket {
  constructor({ rate, burst, failFast = false }) {
    this.rate = rate; this.tokens = burst; this.burst = burst;
    this.last = Date.now(); this.waiting = []; this.denied = 0;
    this.failFast = failFast;
  }
  refill() {                                                 // 惰性补充
    const now = Date.now();
    this.tokens = Math.min(this.burst, this.tokens + (now - this.last) / 1000 * this.rate);
    this.last = now;
  }
  acquire(n = 1) {
    this.refill();
    if (this.tokens >= n) { this.tokens -= n; return Promise.resolve(); }
    if (this.failFast) { this.denied++; return Promise.reject(new Error('rate-limited')); }
    return new Promise((res, rej) => this.waiting.push({ n, res, rej, t: Date.now() }));
  }
  tick() {                                                   // 定期尝试唤醒等待者
    this.refill();
    const w = this.waiting.shift();
    if (w && this.tokens >= w.n) { this.tokens -= w.n; w.res(); }
    else if (w) this.waiting.unshift(w);
  }
}
class ConcurrencyPool {
  constructor(max) { this.max = max; this.active = 0; this.q = []; }
  acquire() {
    if (this.active < this.max) { this.active++; return Promise.resolve(); }
    return new Promise(res => this.q.push(res));
  }
  release() { this.active--; const next = this.q.shift(); if (next) { this.active++; next(); } }
}
// 统一接口包装：limiter.acquire(n).then(run)
```

## 补充：评分点与变体

**评分点**：

- 令牌桶必须惰性补充 `tokens = min(cap, tokens + (now - last) / rate)` 并更新 last，用 setInterval 补令牌会空转且长时间挂起后漂移
- 漏桶 FIFO 严格保序，acquire(n>1) 要么拆成 n 次入队要么原子占用多个桶位，不能部分占用
- 并发池的 release 放在 finally 里，异常路径不释放会让许可永久泄漏、池最终饿死
- fast-fail 与排队共用同一接口，拒绝时走 reject 而不是静默丢弃，调用方才能感知

**变体与延伸**：

1. 需要多标签页共享限额 → 用 SharedWorker 集中计数，localStorage 事件有延迟不适合高频扣减
2. 排队后用户离开页面要取消 → acquire 返回带 abort 的句柄，出队时检查标记并跳过
3. 多实例部署单机限流不准 → 改中心化令牌（Redis 脚本原子扣减）或按实例数均摊配额
