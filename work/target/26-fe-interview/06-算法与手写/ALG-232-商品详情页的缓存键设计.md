## ALG-232：缓存键设计：商品详情的多维缓存键（id+语言+版本+用户域）与失效联动？
**答**：商品详情缓存键要涵盖所有影响内容的维度——id、语言、客户端版本（不同版本渲染 schema 不同）、价格档（会员价）——漏一个维度就是串数据事故。

**思路**：键 = `d:{id}:{lang}:{vMajor}:{priceTier}`；失效联动：商品更新事件 → 按 id 前缀批量失效（多维度键只删 id 前缀）；用户域数据（浏览历史）绝不混入商品缓存键。

```javascript
function detailKey({ id, lang, appVersion, priceTier }) {
  return `d:${id}:${lang}:${appVersion.split('.')[0]}:${priceTier}`;   // major 版本（渲染 schema 变更才升）
}
// 事故案例：键漏 priceTier → 会员看到普通价缓存（串价事故）；漏 lang → 英文用户看到中文页
// 失效联动：商品更新 → SCAN d:{id}:* → 删除所有维度变体（按前缀批量失效）
async function invalidateGoods(id) {
  const keys = await store.scan(`d:${id}:*`);
  await Promise.all(keys.map((k) => store.del(k)));
  // CDN 层联动：purge /goods/{id} 相关 URL（软失效 SWR 更稳，PER-258）
}
// 版本维度用 major：minor/patch 升级不影响渲染 schema，避免缓存全失效（命中率崩塌）
// 用户域隔离：browse-history:{userId} 独立键空间 —— 永不与商品缓存混键
```

**评分点**：
- 多维键完整性（id/lang/版本/价格档），漏维度的串数据事故意识——本题核心。
- 版本只取 major（避免 minor 升级导致命中率崩塌）的细节。
- 按前缀批量失效的联动（商品更新 → 全维度变体失效）。
- 用户域数据独立键空间（绝不混键）。
