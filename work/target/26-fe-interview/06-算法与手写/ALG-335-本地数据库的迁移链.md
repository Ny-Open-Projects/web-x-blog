**场景**：本地存储 schema 升级（localStorage 结构 v1→v2→v3）：用户可能停在任何版本——链式迁移（按版本逐步执行迁移器），单步失败保留原数据（迁移事务性——失败回退到原版本不破坏）。

**思路**：migrations 注册表（{from, to, migrate}）→ 按版本链执行 → 每步先备份（原版本数据快照）→ 失败回滚到备份并上报。

```javascript
const MIGRATIONS = [
  { from: 1, to: 2, migrate: (d) => ({ ...d, settings: { theme: d.theme ?? 'light' }, theme: undefined }) },
  { from: 2, to: 3, migrate: (d) => ({ ...d, draftV3: d.draft ? normalizeV2Draft(d.draft) : null, draft: undefined }) },
];
function migrateStorage(key, { currentVersion = 1 } = {}) {
  let data = JSON.parse(localStorage.getItem(key) ?? 'null') ?? {};
  let version = data.__version ?? currentVersion;
  for (const m of MIGRATIONS) {
    if (m.from < version || m.to <= version) continue;    // 只跑需要的迁移段
    const backup = JSON.stringify(data);                  // 步前备份（事务性）
    try {
      data = { ...m.migrate(data), __version: m.to };
      localStorage.setItem(key, JSON.stringify(data));
    } catch (e) {
      localStorage.setItem(key, backup);                  // 失败回滚到步前状态
      report?.({ type: 'migration-failed', from: m.from, to: m.to, error: String(e) });
      return { ok: false, version, error: e };            // 停在当前版本（功能降级而不是数据破坏）
    }
    version = m.to;
  }
  return { ok: true, version };
}
// 链式语义：v1 用户跑 1→2→3 两步；v2 用户只跑 2→3 —— 任意版本起点都能到达最新
// 事务性：步前备份 + 失败回滚 —— 迁移失败不破坏用户数据（宁可功能降级）
// 迁移器幂等：__version 判断跳过已迁移段（重复调用安全）
// 与 ALG-309 字段映射的关系：迁移器内部用 rename/drop/default 语义（同一套字段迁移原语）
```

**评分点**：
- 版本链式迁移（任意起点到最新）+ 步前备份回滚——本题核心。
- 迁移器幂等（__version 跳过）。
- 失败降级（停在当前版本不破坏数据）。
- 与 ALG-309 字段迁移原语的组合。
