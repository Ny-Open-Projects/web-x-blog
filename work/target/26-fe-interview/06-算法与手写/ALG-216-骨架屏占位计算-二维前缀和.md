**场景**：瀑布流布局（网格化），懒加载过程中产品要求"视口内已加载比例"实时显示。网格上每个格子是 0/1（已加载/未加载），频繁查询"矩形区域和"。每次矩形遍历 O(area) 慢，二维前缀和预处理 O(n·m)、查询 O(1)。

**思路**：P[i][j] = 从 (0,0) 到 (i,j) 的矩形和；区域和 = P[b][r] - P[t-1][r] - P[b][l-1] + P[t-1][l-1]（容斥）。

```javascript
class GridPrefix2D {
  constructor(grid) {                    // grid: number[][]
    const n = grid.length, m = grid[0].length;
    this.P = Array.from({ length: n + 1 }, () => new Array(m + 1).fill(0));
    for (let i = 1; i <= n; i++)
      for (let j = 1; j <= m; j++)
        this.P[i][j] = grid[i - 1][j - 1] + this.P[i - 1][j] + this.P[i][j - 1] - this.P[i - 1][j - 1];
  }
  sum(t, l, b, r) {                      // 0-based 闭区间矩形 [t..b]×[l..r]
    const P = this.P;
    return P[b + 1][r + 1] - P[t][r + 1] - P[b + 1][l] + P[t][l];
  }
}
const g = new GridPrefix2D([[1,0,1],[1,1,0],[0,1,1]]);
g.sum(0, 0, 1, 1);   // => 4（左上 2x2 区域已加载 4 张）
// 预处理 O(n·m)，查询 O(1)——瀑布流滚动时每帧查视口比例都够快
// 动态更新（新图加载完变 1）：单点更新 + 全量重建 O(n·m) 太慢 → 树状数组二维版 O(log²n)
```

**评分点**：
- 二维前缀和构造（容斥：上+左-左上）与查询公式正确（四个象限加减）。
- 1-based 前缀表与 0-based 输入的换算无 off-by-one。
- 预处理 O(n·m)/查询 O(1) 复杂度标注。
- 单点更新场景的演进方向（二维树状数组）。
