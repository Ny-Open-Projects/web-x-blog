**场景**：实验 A（UI 改版）与实验 B（推荐算法）要同时跑且互不干扰——分层：A 在层 1、B 在层 2，每层 10000 段独立分配（层内互斥），层间正交（B 的效果在 A 实验组/对照组均匀分布——可测 A×B 交互）。

**思路**：bucket(userId, layer, salt)——layer 参与 hash（层独立域）；同层实验共享段位分配表（互斥）；跨层不同 salt（独立随机 = 正交）。

```javascript
function layeredBucket(userId, { layer, experiment, ranges }) {
  // 同层互斥：层内所有实验用同一 base hash（段位不重叠）
  const base = fnv(`${layer}:${userId}`);                 // 层级 + 用户 = 层内确定段位
  const v = base % 10000;
  const hit = ranges.find((r) => v >= r.start && v < r.end);
  return hit?.bucket ?? 'control';
  // 正交验证：layer1 与 layer2 的 hash 输入不同 → B 在 A 各桶中均匀分布（可统计验证）
}
// 互斥：同层实验 A 占 0-999，B 占 1000-2999 —— 用户最多命中同层一个实验
// 正交：跨层 hash 域独立 —— A 实验组里 B 的实验/对照组各 50%（A×B 交互可测）
// 容量规划：每层段位资源（10000）÷ 实验所需比例 = 可并存的实验数 —— 分层的资源管理语义
```

**评分点**：
- 分层正交模型（层内互斥、层间独立域）——本题核心。
- 同层共享 base hash 的互斥实现。
- 正交的可统计验证（A 组内 B 均匀分布）。
- 容量规划语义（每层可并存实验数）。
