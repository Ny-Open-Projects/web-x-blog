## HW-324：手写一个调度引擎：优先级任务队列与截止时间抢占

**答**：
- 需求：实现 Scheduler：schedule(task, {priority, deadline})；执行循环取优先级最高任务；deadline 临近（剩余 < 100ms）的任务抢占提升到最高优先级；超期任务标 expired 直接拒绝（回调通知）；并发上限内运行。
- 边界：同优先级 FIFO；抢占只提升不中断运行中任务；expired 判定在出队时执行（队列中过期在出队时发现）。
- 评分点：deadline 抢占；expired 出队判定；FIFO 平局。

```javascript
class Scheduler {
  constructor({ concurrency = 4, urgentMs = 100 } = {}) {
    this.conc = concurrency; this.urgent = urgentMs;
    this.q = []; this.running = 0; this.seq = 0;
  }
  schedule(task, { priority = 5, deadline } = {}) {
    return new Promise((res, rej) =>
      this.q.push({ task, priority, deadline, seq: this.seq++, res, rej, this: null }));
  }
  pump() {
    while (this.running < this.conc && this.q.length) {
      this.q.sort((a, b) => this.rank(b) - this.rank(a));    // rank 大者优先
      const job = this.q.shift();
      if (job.deadline && Date.now() > job.deadline) {       // 出队时过期判定
        job.rej(Object.assign(new Error('expired'), { expired: true }));
        continue;
      }
      this.running++;
      job.task().then(job.res, job.rej).finally(() => { this.running--; this.pump(); });
    }
  }
  rank(job) {                                                // deadline 抢占
    if (job.deadline && job.deadline - Date.now() < this.urgent)
      return 1e9 + job.seq;                                  // 紧急最高（seq 保 FIFO）
    return job.priority * 1e6 + (1e6 - job.seq);
  }
}
setInterval(() => scheduler.pump?.(), 50);                   // 定期触发（也可在 schedule 内）
```

## 补充：评分点与变体

**评分点**：

- deadline 抢占只在出队时重算 rank，运行中的任务不中断；要中断就得处理半执行状态，属另一层设计
- expired 判定放在出队瞬间，排队期间超时同样算过期；入队时判会漏掉等待中超时的那批
- 同优先级 FIFO 用入队自增序号做次级键，依赖 sort 的稳定性在跨引擎实现里不成立
- 并发上限用运行计数控制，任务正常结束与异常结束都要 decrement，漏一处就少一个并发位

**变体与延伸**：

1. 任务执行远超 deadline → 引入 AbortSignal 超时中断，并区分「未开始即过期」与「已开始但超时」两类统计
2. 同优先级且都带 deadline 怎么排 → 按剩余时间升序（最早截止优先），相同再退回入队序号
3. 任务之间有串行依赖 → 依赖图加就绪队列，前置完成才入调度队列，避免占着并发位空等
