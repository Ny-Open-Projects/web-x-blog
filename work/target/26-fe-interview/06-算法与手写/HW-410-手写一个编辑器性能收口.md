## HW-410：手写一个编辑器性能收口：核心指标清单与长期守护方案

**答**：
- 需求：实现 PerfGuardian：指标清单（大文档打开耗时/输入延迟 p95/滚动 FPS/内存峰值/undo 栈内存）；采集探针（HW-392 复用 + 内存 periodic 采样）；守护机制（CI 门禁 + 线上大盘 + 版本对比基线 + 劣化自动告警）；收口验收（指标达标 + 探针上线 + 值班运行一个迭代）。
- 边界：指标口径文档化（每指标定义/采集方式/预算）；探针自身开销控制（采样率+聚合上报）；长期机制（季度演练 + 新功能预算评审）。
- 评分点：指标口径完整；探针低开销；机制闭环。

```javascript
class PerfGuardian {
  constructor(budgets) { this.budgets = budgets; this.samples = new Map(); }
  metrics() {                                                // 指标清单（口径文档化）
    return {
      'doc-open-ms': { def: '10 万字文档打开到可输入', budget: 800, how: 'kernel.ready 事件' },
      'input-p95-ms': { def: '按键到渲染 p95', budget: 50, how: 'InputProbe' },
      'scroll-fps': { def: '大文档滚动平均帧率', budget: 50, how: 'rAF 计帧', lowerBetter: true },
      'mem-mb': { def: '峰值 JS heap', budget: 150, how: 'performance.memory 采样' },
      'undo-mb': { def: 'undo 栈内存占用', budget: 20, how: '序列化估算' },
    };
  }
  sample(metric, value) {                                    // 采集（聚合不上报原始）
    const arr = this.samples.get(metric) ?? [];
    arr.push(value);
    this.samples.set(metric, arr.length > 500 ? arr.slice(-500) : arr);   // 环形
  }
  report() {
    const pct = (a, p) => [...a].sort((x, y) => x - y)[Math.floor(a.length * p)];
    return Object.fromEntries([...this.samples].map(([k, arr]) => {
      const m = this.metrics()[k];
      const v = m?.lowerBetter ? pct(arr, 0.1) : pct(arr, 0.95);   // FPS 取低分位
      return [k, { value: +v.toFixed(1), budget: m?.budget,
        pass: m ? (m.lowerBetter ? v >= m.budget : v <= m.budget) : true }];
    }));
  }
  guard() {                                                  // 守护机制
    return {
      ci: 'perfGate 断言（HW-398）pre-merge',
      online: '探针聚合上报 → 大盘 → 版本基线 diff → 劣化告警',
      review: '新功能带性能预算评审',
      drill: '季度大文档/弱网演练',
      acceptance: ['指标达标', '探针上线', '值班一迭代', '口径文档归档'],   // 收口四条
    };
  }
}
```

## 补充：评分点与变体

**评分点**：

- 每个指标必须凑齐「定义 + 采集方式 + 预算」三件套，只报数值不给口径，线上对不上账时无法归因
- 分位方向要分开：输入延迟取 p95（越大越差），滚动 FPS 取低分位并配 `lowerBetter` 反向比较，两者不能共用一套判定
- 采样要环形截断（`slice(-500)`）且只上报聚合值，原始样本全量上报会让探针本身成为性能问题
- 守护闭环四段齐全：CI 门禁拦截、线上大盘、版本基线 diff、劣化自动告警，缺任一环只能算「有监控」不算收口

**变体与延伸**：

1. 预算数值怎么定 → 首版取现网 p95 作基线，再乘 1.2 留抖动余量；输入延迟另有产品阈值（超 50ms 用户可感知）
2. 探针自身拖慢指标怎么办 → 采样率降到十分之一、聚合后批量上报、单测里跑空载对照证明开销可忽略
3. 收口后如何防止回退 → 预算写进 PR 模板并让 perfGate 阻断不合规合并，季度做一次大文档演练
