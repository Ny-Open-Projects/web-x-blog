## ALG-270：构建产物循环依赖：chunk 间循环 import 检测（构建图 DFS）与拆包建议？
**答**：拆包后 chunk 间循环依赖（A chunk import B，B 又 import A）——运行时初始化顺序问题（undefined 导入）。构建期检测：模块图 DFS 找环 + 输出拆包建议（把共同依赖抽公共 chunk）。

**思路**：模块图（manifest 依赖边）→ DFS 三色（ALG-203 同构，模块图版）→ 环路径输出 → 建议：环内模块抽到公共 chunk（entry 先行加载）。

```javascript
function detectChunkCycles(manifest) {
  // manifest: { chunkFile: { imports: [chunkFile] } }
  const color = new Map();                                // 0 白 1 灰 2 黑
  const stack = [];
  const cycles = [];
  function dfs(node) {
    color.set(node, 1); stack.push(node);
    for (const dep of manifest[node]?.imports ?? []) {
      const c = color.get(dep) ?? 0;
      if (c === 1) cycles.push(stack.slice(stack.indexOf(dep)).concat(dep));   // 环路径
      else if (c === 0 && dfs(dep)) break;
    }
    color.set(node, 2); stack.pop();
    return cycles.length > 0;
  }
  for (const node of Object.keys(manifest)) if ((color.get(node) ?? 0) === 0) dfs(node);
  return cycles.map((cycle) => ({
    cycle,
    suggestion: `抽出环内共同依赖到 common chunk（entry 预加载）: ${[...new Set(cycle.flat())].join(', ')}`,
  }));
}
// 环的运行时危害：A 初始化时 import B，B 又反向 import A 的变量 → undefined（TDZ/初始化序）
// 拆包建议：环内模块（通常是 utils/config）抽公共 chunk，entry 显式先行 —— 打破环
// 构建期检测（CI 拦截）vs 运行时暴露（线上 undefined 报错难排查）—— 修复成本差 10 倍
```

**评分点**：
- 模块图 DFS 三色找环（ALG-203 同构迁移）——本题核心。
- 拆包建议（公共 chunk 打破环）的可执行性。
- 环的运行时危害机制（初始化序/TDZ）说明。
- 构建期拦截 vs 运行时暴露的成本对比。
