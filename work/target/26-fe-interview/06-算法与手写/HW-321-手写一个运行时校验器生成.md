## HW-321：手写一个运行时校验器生成：从 TS 风格类型描述生成校验函数

**答**：
- 需求：实现 TypeGen：类型描述（字符串 DSL："string" | "number" | "{name: string, age?: number}" | "string[]" | 枚举联合 a/b）；compile 生成校验函数（可选 ? 字段、数组元素递归、枚举联合）；输出错误路径（$.age: expected number）。
- 边界：可选字段 undefined 通过；数组元素错误路径带索引；嵌套对象递归编译；非法 DSL 编译时报错。
- 评分点：DSL 解析；错误路径；递归编译。

```javascript
function compileType(dsl) {
  dsl = dsl.trim();
  if (dsl.endsWith('[]')) {                                  // 数组
    const elem = compileType(dsl.slice(0, -2));
    return (v, path = '$') => {
      if (!Array.isArray(v)) return `${path}: expected array`;
      for (let i = 0; i < v.length; i++) { const e = elem(v[i], `${path}[${i}]`); if (e) return e; }
      return null;
    };
  }
  if (dsl.startsWith('{')) {                                 // 对象
    const fields = dsl.slice(1, -1).split(',').map(s => s.trim()).filter(Boolean)
      .map(f => { const m = f.match(/^(\w+)(\?)?:\s*(.+)$/);
        return { name: m[1], optional: !!m[2], type: compileType(m[3]) }; });
    return (v, path = '$') => {
      if (v == null || typeof v !== 'object') return 'expected object';
      for (const f of fields) {
        if (v[f.name] === undefined) {
          if (f.optional) continue;
          return `${path}.${f.name}: required`;
        }
        const e = f.type(v[f.name], path + '.' + f.name);
        if (e) return e;                                     // 首个错误即返
      }
      return null;
    };
  }
  if (dsl.startsWith("'")) {                                 // 枚举联合
    const opts = dsl.split('|').map(s => s.trim().replace(/'/g, ''));
    return v => opts.includes(v) ? null : `expected one of ${opts.join('/')}`;
  }
  const prim = { string: v => typeof v === 'string', number: v => typeof v === 'number',
    boolean: v => typeof v === 'boolean' }[dsl];
  if (!prim) throw new Error('bad-dsl: ' + dsl);             // 编译期报错
  return (v, path = '$') => prim(v) ? null : `${path}: expected ${dsl}`;
}
// compileType 用法示例: {name: string, age?: number} 对 {name:1} 报 name 字段错误
```

## 补充：评分点与变体

**评分点**：

- DSL 解析要写成递归下降并能处理 `?` 可选标记与嵌套对象，正则一把梭在嵌套层级上必然出错
- 错误路径要拼到字段级且带数组下标（形如 `$.list[2].id`），只抛「校验失败」无法定位问题
- 可选字段遇 undefined 直接通过，不能和类型不匹配共用同一条错误分支，否则前端表单大量误报
- compile 阶段应把解析结果（AST）缓存下来只解析一次，每次 validate 重 parse DSL 会让长表单明显变慢

**变体与延伸**：

1. 联合类型 `a/b` 怎么校验 → 逐分支尝试，全失败时汇总各分支原因或只报「不匹配任何枚举值」避免噪音
2. 递归类型（树节点自引用）怎么办 → 编译期用惰性引用占位，运行时按需展开，并加深度上限防栈溢出
3. 与 zod / ajv 的差距在哪 → 只覆盖子集语法、没有 schema 复用与错误国际化，胜在体积与可控
