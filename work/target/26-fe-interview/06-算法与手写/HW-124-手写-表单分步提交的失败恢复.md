## HW-124：手写分步提交的失败恢复——多接口顺序提交、失败断点续传、已成功步骤不重发（幂等）
**答**：注册流程三步各一个接口，第 3 步失败后重试必须跳过已成功的 1、2 步（断点续传）：步骤状态持久化（localStorage），每步带幂等键（HW-100 思路），恢复时从首个未成功步骤继续；服务端幂等兜底重复请求。

```javascript
async function submitWizard(steps, draftKey = 'wizard-submit') {
  // steps: [{ key, run: (ctx) => Promise, idempotencyKey }]
  const state = JSON.parse(localStorage.getItem(draftKey) || '{"done":{},"ctx":{}}');
  for (const step of steps) {
    if (state.done[step.key]) continue;                       // 已成功：跳过（断点续传）
    try {
      state.ctx = (await step.run({
        ...state.ctx,
        idempotencyKey: step.idempotencyKey ?? crypto.randomUUID(),
      })) ?? state.ctx;
      state.done[step.key] = true;
      localStorage.setItem(draftKey, JSON.stringify(state));   // 每步成功即持久化
    } catch (e) {
      throw Object.assign(e, { failedStep: step.key, recoverable: true });   // 断点信息随错误抛出
    }
  }
  localStorage.removeItem(draftKey);                          // 全部成功清状态
  return state.ctx;
}
// 网络中断后重新调用 submitWizard(steps)：自动从失败步骤继续，1、2 步不重发
// 幂等键保证：即使 done 状态丢失（换设备），服务端按键去重也不会重复执行
// UX：失败提示"第 2 步失败，重试将从第 2 步继续"
```

**评分点**：
- 断点续传语义：已成功步骤跳过（done 状态持久化），失败步骤重试。
- 幂等键贯穿（本地状态丢失也有服务端兜底）——双保险。
- 每步成功即持久化（不是最后一次性写）。
- 错误对象带 failedStep 供 UX 展示"从第 N 步继续"。
