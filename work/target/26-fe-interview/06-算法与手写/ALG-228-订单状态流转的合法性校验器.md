## ALG-228：订单中心：批量校验订单状态流转是否合法（状态机表 + 非法流转统计）
**答**：订单日志里每条是 {orderId, from, to, ts}，要校验每笔订单的状态流转是否符合状态机（pending→paid→shipped→done / paid→refund），输出非法流转清单（审计用）。

**思路**：按 orderId 分组 → 组内按 ts 排序 → 逐对流转查状态机表；非法的收集。注意乱序日志（迟到事件）要先按 ts 排序。

```javascript
const LEGAL = {
  created: ['pending'],
  pending: ['paid', 'cancelled'],
  paid: ['shipped', 'refund'],
  shipped: ['done', 'refund'],
  refund: [],
  done: [], cancelled: [],
};
function auditTransitions(logs) {
  const byOrder = new Map();
  for (const e of logs) (byOrder.get(e.orderId) ?? byOrder.set(e.orderId, []).get(e.orderId)).push(e);
  const illegal = [];
  for (const [orderId, events] of byOrder) {
    events.sort((a, b) => a.ts - b.ts);           // 迟到事件先按时间排
    let cur = 'created';
    for (const e of events) {
      if (!LEGAL[cur]?.includes(e.to)) {
        illegal.push({ orderId, from: cur, to: e.to, ts: e.ts });
        cur = e.to;                               // 继续审计（不中断，收集全部非法点）
      } else cur = e.to;
    }
  }
  return illegal;
}
// 非法输出带 orderId/from/to/ts —— 审计可直接定位
// 扩展：状态机表可配置下发；同一事件重复（网络重试）按幂等键去重后再审计
```

**评分点**：
- 按 orderId 分组 + 组内按 ts 排序（迟到/乱序事件处理）。
- 状态机表驱动（数据不是 if-else）；非法流转继续审计不中断。
- 输出可审计（订单号/流向/时间）。
- 幂等去重意识。
