**场景**：IM 群消息通知：100 条群消息 = 100 个系统通知（灾难）。同类合并：窗口内同类通知合并为"群 A 有 37 条新消息"（计数+可展开明细列表）。

**思路**：同类 key + 窗口计时器 → 窗口内累积（计数+样本）→ 窗口结束发合并通知（或实时更新计数）。

```javascript
class NotifMerger {
  #windows = new Map();                                   // key -> { count, timer, samples: [] }
  constructor({ windowMs = 5 * 60000, maxSamples = 5 } = {}) { Object.assign(this, { windowMs, maxSamples }); }
  push(key, item, show) {
    let w = this.#windows.get(key);
    if (!w) {
      w = { count: 0, samples: [], timer: null, show };
      w.timer = setTimeout(() => {                        // 窗口结束：发合并通知
        this.#windows.delete(key);
        show(key, w.count, w.samples.slice(0, this.maxSamples));
      }, this.windowMs);
      this.#windows.set(key, w);
    }
    w.count++;
    if (w.samples.length < this.maxSamples) w.samples.push(item);   // 明细样本（前 5 条）
    // 实时更新模式（可选）：每次 push 更新系统通知文案（"37 条"递增）—— Notification tag 合并（HW-169）
  }
}
// 合并语义：5 分钟窗口内同类累积 → 一次通知（计数 + 前 5 条明细可展开）
// 实时更新变体：Notification tag 相同 → 系统自动合并替换文案（HW-169 双层去重的系统层）
// 明细上限（5 条）：通知面板空间有限——完整列表进应用内（点通知打开）
// 内存：窗口 Map 有界（窗口结束即清）—— 长会话不涨（ALG-299 同源纪律）
```

**评分点**：
- 窗口合并（计数 + 样本 + 定时发送）——本题核心。
- 系统层 tag 合并与应用层窗口的双层联动（HW-169）。
- 明细上限与"完整列表进应用内"的分层。
- 窗口 Map 有界性。
