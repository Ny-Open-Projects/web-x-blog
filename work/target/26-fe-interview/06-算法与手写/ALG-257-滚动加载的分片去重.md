**场景**：列表混合两种更新（下拉刷新给全量 + 无限滚动给增量页），合并后可能重复（刷新快照与增量页交叠）。要求：id 幂等去重 + 保序（最新全量序优先，增量追加）。

**思路**：合并函数 merge：全量替换模式——以最新全量为基准，增量中不在全量的按序追加；增量模式——Set 去重保序。状态标记（数据源 + 快照版本）决定走哪条路径。

```javascript
function mergeList(current, incoming, mode, seen = new Set(current.map((x) => x.id))) {
  if (mode === 'refresh') {                               // 全量快照：替换 + 增量补遗
    const base = [...incoming];
    const ids = new Set(base.map((x) => x.id));
    const extra = current.filter((x) => !ids.has(x.id));  // 旧数据不在新快照：保留在尾部（防丢失未同步项）
    return [...base, ...extra];
  }
  // mode === 'append'：增量去重保序
  const out = [...current];
  for (const item of incoming) {
    if (!seen.has(item.id)) { out.push(item); seen.add(item.id); }
  }
  return out;
}
// refresh 语义：新快照优先（服务端排序变了以新为准），旧独有项保尾（乐观更新项不丢，HW-091 pending 语义）
// append 语义：Set 保序去重（重复页自然跳过）
// seen 集合跨调用维护（调用方持有）—— O(1) 判重
// 对比：每页独立去重（不维护 seen）—— 页间重叠会漏检；维护全局 seen 才幂等
```

**评分点**：
- refresh/append 双模式语义（快照替换 + 增量保序去重）——本题核心。
- refresh 时旧独有项保尾（乐观更新不丢）。
- 全局 seen 跨调用维护 vs 每页独立去重的差异。
- 幂等验证：同页重复加载列表不变。
