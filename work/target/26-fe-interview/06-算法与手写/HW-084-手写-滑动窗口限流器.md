## HW-084：手写滑动窗口限流器——队列裁剪版，消除固定窗口边界突刺
**答**：固定窗口（1 秒 100 次）在窗口交界处可放过 200 次（突刺）。滑动窗口记录最近 windowMs 内每次请求的时间戳，allow 时先裁剪窗口外旧时间戳再判长度。O(1) 近似版：分桶计数（每桶 windowMs/10），精度换内存。

```javascript
class SlidingWindowLimiter {
  constructor({ limit = 100, windowMs = 1000 } = {}) {
    Object.assign(this, { limit, windowMs, hits: [] });
  }
  allow() {
    const now = Date.now();
    const cut = now - this.windowMs;
    while (this.hits.length && this.hits[0] <= cut) this.hits.shift();  // 裁剪窗口外
    if (this.hits.length >= this.limit) return false;
    this.hits.push(now);
    return true;
  }
}
// 精确版 O(N) 简单；高 QPS 用分桶近似版 O(1)：
class SlidingWindowCounter {
  constructor({ limit = 100, windowMs = 1000, buckets = 10 } = {}) {
    Object.assign(this, { limit, windowMs, buckets, counts: new Map() }); // bucketStart -> count
  }
  allow() {
    const now = Date.now();
    const bucketMs = this.windowMs / this.buckets;
    const cur = Math.floor(now / bucketMs);
    for (const k of [...this.counts.keys()]) if (k < cur - this.buckets + 1) this.counts.delete(k); // 清理旧桶
    let sum = 0;
    for (const [k, v] of this.counts) sum += v;         // 近似：所有活跃桶求和
    if (sum >= this.limit) return false;
    this.counts.set(cur, (this.counts.get(cur) || 0) + 1);
    return true;
  }
}
// 突刺验证：limit=10/1s，固定窗口在 t=0.9s 和 t=1.1s 各放 10 次 => 0.2s 内 20 次；
// 滑动窗口任取 1s 窗口内命中数始终 <= 10
```

**评分点**：
- 精确版裁剪逻辑正确（shift 窗口外旧记录）。
- 能指出固定窗口的边界突刺问题并解释成因。
- 分桶近似版：桶粒度 = windowMs/buckets，旧桶清理、跨桶求和。
- 精度/内存权衡表述（分桶数越多越精确）。

## 变体与延伸（补充）

**变体与延伸**：

1. QPS 很高时时间戳数组会不会爆内存 → 会，每条请求存一个时间戳，单窗口十万条就是十万个数字；改分桶计数或环形桶，只留桶计数不存明细
2. 多实例部署各算各的窗口准不准 → 不准，每台只看到自己那部分流量，总量必然超；要么中心化计数，要么按实例数均摊配额
3. 分桶版桶数怎么选 → 误差上限约为 1/桶数，10 到 60 个桶足够，内存与桶数成正比，不是越多越好
