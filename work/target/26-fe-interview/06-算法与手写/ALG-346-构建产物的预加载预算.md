**场景**：ALG-264 预加载谱系的预算约束：每路由 preload 总量 ≤ 300KB——超预算说明"静态 import 展开过深"（把不该预载的 chunk 拉进来了）——构建期检查并输出超限清单（改动态 import 或拆 chunk）。

**思路**：预加载清单 × 产物大小表 → 每路由求和 → 超预算输出（哪些 chunk 占大头 + 拆包建议）。

```javascript
function checkPreloadBudget(preloadMap, sizes, { budgetKB = 300 } = {}) {
  const violations = [];
  for (const [route, chunks] of Object.entries(preloadMap)) {
    const total = chunks.reduce((s, c) => s + (sizes[c] ?? 0), 0);
    if (total > budgetKB * 1024) {
      const top = chunks.sort((a, b) => (sizes[b] ?? 0) - (sizes[a] ?? 0)).slice(0, 3);
      violations.push({ route, totalKB: +(total / 1024).toFixed(1),
        topChunks: top.map((c) => `${c} (${(sizes[c] / 1024).toFixed(0)}KB)`),
        suggestion: top[0] + ' 改为动态 import 或拆 chunk' });   // 可执行建议
    }
  }
  return violations;                                       // CI 拦截输出（构建期卡口，PER-339）
}
// 预算语义：preload = "用户跳转前就拉"的资源——超预算 = 预加载变预浪费（带宽与首屏争抢）
// 卡口输出可执行建议（哪个 chunk 占大头 + 改法）—— 不是"超了"而是"怎么改"
// 构建期检查（CI 拦截）vs 运行时发现（用户感知慢）：修复成本差 10 倍（ALG-270 同源）
// 与 PER-339 预算体系的关系：路由级 preload 预算是 budgets.json 的细化维度
```

**评分点**：
- 每路由 preload 总量卡口（构建期 CI 拦截）——本题核心。
- 超限输出的可执行建议（top chunk + 改法）。
- "预加载变预浪费"的边界语义（静态展开过深）。
- 与构建期循环依赖检测（ALG-270）的同源纪律。
