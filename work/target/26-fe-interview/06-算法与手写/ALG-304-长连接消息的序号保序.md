**场景**：WS 消息带 seq（服务端单调递增），网络乱序到达——按 seq 保序交付（连续窗口），缺口等待（后续消息补上缺口后连续交付），超时（500ms 缺口未补）跳过并请求补发。

**思路**：pending Map（seq→msg）+ expectNext 指针 → 到达消息 seq === expect 直接交付并 flush 连续段；seq > expect 缓存；定时器（缺口超时 → 跳过 + gap 标记 + 补发请求）。

```javascript
class SeqOrderer {
  #pending = new Map(); #expect = 1; #timer = null;
  constructor(deliver, { gapTimeout = 500, onGap } = {}) { Object.assign(this, { deliver, gapTimeout, onGap }); }
  push(msg) {
    if (msg.seq < this.#expect) return;                   // 重复（重发）：幂等丢弃
    if (msg.seq === this.#expect) {
      this.deliver(msg); this.#expect++;
      while (this.#pending.has(this.#expect)) {           // 连续段 flush（缓存的多条一次交付）
        this.deliver(this.#pending.get(this.#expect));
        this.#pending.delete(this.#expect++);
      }
      this.#clearTimer(); return;
    }
    this.#pending.set(msg.seq, msg);                      // 乱序：缓存等缺口
    this.#timer ??= setTimeout(() => this.#gapTimeout(), this.gapTimeout);
  }
  #gapTimeout() {                                         // 缺口超时：跳过 + 补发请求
    this.#clearTimer();
    if (this.#pending.size) {
      const missing = [];
      for (let s = this.#expect; s < Math.max(...[...this.#pending.keys()]); s++)
        if (!this.#pending.has(s)) missing.push(s);
      this.onGap?.(missing);                              // 补发请求（服务端按 seq 范围回）
      this.#expect = Math.max(...[...this.#pending.keys()]);   // 跳过缺口（不永久卡死）
      while (this.#pending.has(this.#expect)) {
        this.deliver(this.#pending.get(this.#expect)); this.#pending.delete(this.#expect++);
      }
    }
  }
  #clearTimer() { clearTimeout(this.#timer); this.#timer = null; }
}
// 语义：连续交付（期望指针推进）+ 缺口等待（500ms）+ 超时跳过（不永久卡死）+ 补发请求（恢复完整性）
// 重复消息（seq < expect）：幂等丢弃（重发场景）
// flush 连续段：缺口补上后缓存的多条一次交付（保序不牺牲吞吐）
```

**评分点**：
- 连续窗口交付 + 缺口超时跳过 + 补发请求的完整状态机——本题核心。
- 重复消息幂等丢弃。
- 连续段 flush（缺口补齐后一次交付缓存段）。
- 跳过语义（expect 跳到最大缓存 seq——不永久卡死）。
