**答**：场景：详情页要并发拉 5 个接口，要求"谁先回来先渲染谁"，单个失败不阻塞其他，整体给 8s 超时兜底。核心：每个任务包一层"完成即回调"，不阻塞彼此；整体超时用 race 一个 timer promise。

```javascript
function parallelSettle(tasks, { timeout = 8000, onEach } = {}) {
  const timeoutP = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('整体超时')), timeout));
  const run = tasks.map((t, i) =>
    Promise.resolve(t())
      .then((v) => { onEach?.(i, v, null); return v; })
      .catch((e) => { onEach?.(i, null, e); return { __err: e }; }));   // 单失败不炸
  const all = Promise.all(run);          // catch 已内部化，all 不会因单项 reject
  return Promise.race([all, timeoutP]);
}

// 用法：详情页 5 路并发，先到先渲染
await parallelSettle([
  () => fetch('/api/goods/1').then(r => r.json()),   // 主商品
  () => fetch('/api/reviews').then(r => r.json()),   // 评论
  () => fetch('/api/recs').then(r => r.json()),      // 推荐
  () => fetch('/api/stock').then(r => r.json()),
  () => fetch('/api/coupons').then(r => r.json()),
], {
  onEach: (i, data, err) => {
    if (err) return renderSlot(i, fallback(i));      // 失败的槽位给兜底，不阻塞其他
    renderSlot(i, data);                             // 先到先渲染，感知速度最大化
  },
  timeout: 8000,
});
```

**评分点**：
- 单任务失败内部化（catch 返回哨兵），Promise.all 不被单项炸掉。
- onEach 回调实现"先到先渲染"，语义清楚。
- 整体超时用 Promise.race；超时 reject 后已完成的渲染保留。
- 能说明为什么不用 Promise.allSettled（它等全部结束才结算，无法先到先渲染）。
