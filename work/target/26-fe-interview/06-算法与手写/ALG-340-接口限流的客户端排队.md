**场景**：接口返回 429 + Retry-After: 5——不是立即重试也不是固定退避：按服务端指示的恢复时间把请求插回队列（时间排序的等待队列），其他请求照常（只有被限流的 key 排队）。

**思路**：429 处理：Retry-After 解析 → 该 key 的后续请求入等待队列（按恢复时间排序）→ 定时器到点释放。per-key 队列（不同接口独立限流）。

```javascript
class RateLimitQueue {
  #queues = new Map();                                    // key -> [{ run, resolve, reject, at }]
  async fetch(key, url, opts) {
    return new Promise((resolve, reject) => {
      const q = this.#queueFor(key);
      const now = Date.now();
      const readyAt = q.readyAt ?? now;
      if (now >= readyAt && !q.pending) {
        q.pending = true;
        return this.#fire(key, url, opts, resolve, reject);
      }
      q.items.push({ url, opts, resolve, reject });       // 排队（按 readyAt 定时释放）
      q.items.sort((a, b) => a.readyAt - b.readyAt);
    });
  }
  #fire(key, url, opts, resolve, reject) {
    fetch(url, opts).then(async (res) => {
      const q = this.#queues.get(key);
      q.pending = false;
      if (res.status === 429) {
        const ra = +(res.headers.get('Retry-After') ?? 5);
        q.readyAt = Date.now() + ra * 1000;               // 服务端指示的恢复时间
        res.body?.cancel();
        this.#scheduleDrain(key);
        resolve(this.fetch(key, url, opts));              // 本请求转排队（递归入队）
        return;
      }
      resolve(res);
      this.#drain(key);                                   // 释放队列中的后续请求
    }).catch(reject);
  }
  #scheduleDrain(key) {
    const q = this.#queues.get(key);
    setTimeout(() => this.#drain(key), (q.readyAt ?? 0) - Date.now() + 50);
  }
  #drain(key) {
    const q = this.#queues.get(key);
    if (!q || q.pending || Date.now() < (q.readyAt ?? 0)) return;
    const item = q.items.shift();
    if (!item) return;
    q.pending = true;
    this.#fire(key, item.url, item.opts, item.resolve, item.reject);
  }
  #queueFor(key) { return this.#queues.get(key) ?? this.#queues.set(key, { items: [], pending: false, readyAt: 0 }).get(key); }
}
// 语义：
// Retry-After 是服务端的权威指示（比客户端猜退避更准——HW-063 的退避是猜测，Retry-After 是指令）
// per-key 队列：不同接口独立限流（商品限流不影响订单接口）
// 排队请求按恢复时间排序释放（最早恢复的先走）
```

**评分点**：
- Retry-After 解析并按指示排队（服务端指令优先于客户端猜测）——本题核心。
- per-key 独立队列（不同接口限流隔离）。
- 排队请求按恢复时间排序释放。
- 429 请求递归转排队（不丢失）。
