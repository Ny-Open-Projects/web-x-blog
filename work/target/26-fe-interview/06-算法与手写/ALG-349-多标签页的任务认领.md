**场景**：轮询/同步任务多标签页重复执行（每个标签页都跑 = 服务端 3 倍负载 + 数据竞争）——Web Locks 认领（HW-146）+ 持锁心跳 + 崩溃自动转移（浏览器释放锁后其他页 ifAvailable 抢到接管）。

**思路**：锁循环：ifAvailable 抢锁 → 抢到执行任务并周期续期 → 抢不到等待（监听锁释放——locks 事件轮询）→ 崩溃（标签页关）浏览器自动释放 → 其他页下一轮抢到接管。

```javascript
async function claimTask(name, task, { intervalMs = 5000 } = {}) {
  for (;;) {                                              // 认领循环：抢锁→执行→释放→再抢
    const held = await navigator.locks.request(name, { ifAvailable: true }, async (lock) => {
      if (!lock) return false;                            // 别页持有：本轮跳过
      await task();                                       // 执行任务（持锁期间）
      return true;
    });
    if (!held) await sleep(Math.min(intervalMs, 1000));   // 未抢到：短等待再试（快速接管）
    else await sleep(intervalMs);                         // 执行完：按周期再来
  }
}
// 崩溃转移：标签页关闭 → 浏览器自动释放锁 → 其他页下一轮 ifAvailable 抢到接管（无需额外机制）
// 心跳语义：任务执行周期本身就是心跳（锁随任务执行续期——浏览器管理锁生命周期，无自定义心跳）
// 语义保证：任意时刻至多一个标签页执行任务（Locks 互斥）—— 服务端负载 = 单页水平
// 降级：无 Locks API 的浏览器 → BroadcastChannel 选主（PER-321 老方案）或接受重复（低价值任务）
```

**评分点**：
- Locks 认领循环 + 崩溃自动转移（浏览器释放锁）——本题核心。
- 任务执行周期即心跳（无自定义心跳的简化）。
- 服务端负载收敛语义（单页水平）。
- 降级链（无 Locks → BC 选主 → 接受重复）。
