**场景**：跨字段约束（endDate > startDate、max > min）：散落在字段校验器里难维护——集中声明跨字段规则（{fields: [a,b], test}）+ 触发传播（改 a 时重验 b）——ALG-069 deps 的规则引擎化。

**思路**：跨字段规则注册 → 字段变更时找"含该字段的规则"重验 → 规则错误挂到规则的主字段（展示位）。

```javascript
class CrossFieldRules {
  #rules = [];
  add({ id, fields, test, primary }) {                    // test: (values) => true | 错误 key
    this.#rules.push({ id, fields, test, primary: primary ?? fields[0] });
    return this;
  }
  validateField(field, values, rules) {                   // 字段变更：找相关规则重验
    const errors = {};
    for (const r of this.#rules) {
      if (!r.fields.includes(field) && !r.fields.includes(r.primary)) continue;
      const result = r.test(values);
      if (result !== true) errors[r.primary] = result;    // 错误挂主字段（展示位）
      else delete errors[r.primary];
    }
    return errors;
  }
}
// 用法：
// rules.add({ id: 'date-order', fields: ['startDate', 'endDate'], test: (v) =>
//   !v.startDate || !v.endDate || v.endDate > v.startDate || 'err.date-order', primary: 'endDate' });
// setValue('startDate', x) → date-order 重验 → 错误挂 endDate（用户看得到）
// 集中声明价值：跨字段规则一眼全览（散落字段校验器 = 依赖关系不可见）；错误挂主字段（展示策略显式）
// 与 HW-069 的联动：字段级规则（FormEngine）+ 跨字段规则（本类）两层正交
```

**评分点**：
- 跨字段规则集中声明 + 变更触发传播——本题核心（ALG-069 引擎化）。
- 错误挂主字段（primary 展示策略显式）。
- 与字段级校验的正交分层。
- 规则 id 供本地化（错误 key 语义）。
