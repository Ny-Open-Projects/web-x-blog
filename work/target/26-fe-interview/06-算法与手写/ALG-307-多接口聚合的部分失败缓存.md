## ALG-307：聚合接口部分失败缓存：成功的部分缓存 + 失败部分单独重试（部分结果复用）？
**答**：聚合请求（商品+价格+库存）中库存失败——整体重试浪费已成功的两个；部分失败缓存：成功部分入缓存，重试只拉失败部分（HW-174 分片上传的同构思想，接口版）。

**思路**：并行请求 → allSettled → 成功结果入 per-key 缓存 → 失败 keys 收集 → 重试循环只拉失败（缓存命中直接复用）→ 组装完整响应。

```javascript
async function aggregateWithPartialCache(keys, loader, cache) {
  let pending = [...keys];
  const result = {};
  for (let round = 0; round < 2; round++) {               // 最多两轮（首轮 + 失败重试轮）
    const results = await Promise.allSettled(
      pending.map((k) => cache.get(k) ?? loader(k).then((v) => { cache.set(k, v); return v; })));
    pending = [];
    results.forEach((r, i) => {
      if (r.status === 'fulfilled') result[keys.indexOf(pending[i]) ?? i] = r.value ?? (result[keys.indexOf(pending[i])] = r.value);
      else pending.push(keys[keys.indexOf(pending[i])]);
    });
    // 简化写法易错，工程上用明确索引映射：
    if (!pending.length) break;
    await new Promise((r) => setTimeout(r, 500));         // 重试退避
  }
  return { result, failedKeys: pending };                 // 部分失败的 keys（UI 降级展示）
}
// 更清晰的实现（推荐）：
async function aggregate(keys, loader, cache) {
  const out = {}, failed = [];
  const settled = await Promise.allSettled(keys.map(async (k) => [k, await (cache.get(k) ?? loader(k).then((v) => (cache.set(k, v), v)))]));
  settled.forEach((s, i) => s.status === 'fulfilled' ? (out[keys[i]] = s.value[1]) : failed.push(keys[i]));
  return { out, failed };                                  // 成功部分已缓存 —— 下次聚合只拉 failed
}
// 收益：三接口中库存挂 → 商品/价格已缓存（60% 流量省），重试只拉库存
// 降级：failed keys → UI 对应区块显示"暂时不可用"（部分可用优于全部失败）
```

**评分点**：
- 部分失败缓存复用（成功部分缓存、重试只拉失败）——本题核心。
- allSettled 聚合 + failed keys 输出（UI 部分降级）。
- 与 HW-174 分片重试的同构关系。
- 部分可用优于全部失败的降级语义。
