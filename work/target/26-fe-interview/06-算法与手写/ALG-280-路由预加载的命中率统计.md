## ALG-280：预取命中率统计：prefetch 请求与真实消费的关联归因（5min 窗口内命中判定）？
**答**：PER-391 命中率的服务端实现：预取请求（X-Prefetch: 1）与后续真实请求关联——同一会话内同 URL 5min 内出现真实请求 = 命中。流式聚合（Map 窗口 + 过期清理）。

**思路**：预取事件入 pending Map（key=url+sid → at）→ 真实请求到达查 pending → 命中则记录并移除 → 窗口过期清理（定时扫描或惰性）；按策略/页面聚合命中率。

```javascript
class PrefetchStats {
  #pending = new Map();                                   // "sid|url" -> at
  #hits = new Map();                                      // strategy -> { hit, total }
  recordPrefetch(sid, url, strategy) { this.#pending.set(`${sid}|${url}`, { at: Date.now(), strategy }); }
  recordReal(sid, url) {
    const k = `${sid}|${url}`;
    const p = this.#pending.get(k);
    if (p && Date.now() - p.at < 5 * 60000) {             // 5min 窗口内：命中
      const s = this.#hits.get(p.strategy) ?? { hit: 0, total: 0 };
      s.hit++; s.total++; this.#hits.set(p.strategy, s);
      this.#pending.delete(k);
    }
  }
  sweep() {                                               // 惰性清理：过期的 pending = 浪费
    const now = Date.now();
    for (const [k, p] of this.#pending)
      if (now - p.at > 5 * 60000) {
        const s = this.#hits.get(p.strategy) ?? { hit: 0, total: 0 };
        s.total++; this.#hits.set(p.strategy, s);         // 浪费也计数（分母）
        this.#pending.delete(k);
      }
  }
  rates() { return [...this.#hits].map(([k, v]) => ({ strategy: k, rate: +(v.hit / v.total * 100).toFixed(1), ...v })); }
}
// 命中率 < 50% 的策略自动下线（PER-391 闭环）；分策略/页面聚合定位"哪个预取在浪费"
// 浪费计数（total 含未命中）—— 只算命中不算浪费的命中率是自欺
```

**评分点**：
- 预取-真实请求关联归因（sid|url key + 时间窗口）——本题核心。
- 浪费计入分母（命中率诚实）。
- sweep 惰性过期（窗口关闭后补计浪费）。
- 按策略聚合 → 自动下线闭环。
