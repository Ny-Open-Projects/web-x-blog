## HW-391：手写一个内容防丢失体系：多级快照与异常保护

**答**：
- 需求：实现 ContentGuard：三级保护——内存实时态（每次变更）、sessionStorage 高频快照（2s 防抖）、localStorage 低频快照（30s + 关键操作后）；beforeunload 提示（有未保存变更）；崩溃恢复（启动时检测未关闭标记 → 提示恢复到最近快照）；快照版本管理（保留 5 版）。
- 边界：beforeunload 的 returnValue 触发确认；崩溃标记（正常关闭时清除，异常残留即为崩溃证据）；多标签页同文档快照互斥（按 tabId 区分，恢复时取最新非本 tab 的）。
- 评分点：三级频率分层；崩溃标记机制；多 tab 互斥。

```javascript
class ContentGuard {
  constructor(doc, { hotMs = 2000, coldMs = 30000 } = {}) {
    this.doc = doc; this.tabId = 'tab-' + Math.random().toString(36).slice(2);
    localStorage.setItem('doc-alive-' + this.tabId, '1');   // 崩溃标记（必须跨 tab 可见，sessionStorage 是标签页私有的，崩溃即销毁）
    this.hotTimer = debounceSnapshot(() => this.save('hot'), hotMs);
    setInterval(() => this.save('cold'), coldMs);
    addEventListener('beforeunload', e => {                  // 未保存提示
      if (this.dirty) { e.preventDefault(); e.returnValue = ''; }
      localStorage.removeItem('doc-alive-' + this.tabId);  // 正常关清标记
    });
  }
  onChange() { this.dirty = true; this.hotTimer(); }
  save(level) {                                              // 分级快照
    const snap = { ts: Date.now(), tabId: this.tabId, doc: serializeDoc(this.doc) };
    const key = level === 'hot' ? 'doc-snap-hot' : 'doc-snap-cold';
    const list = JSON.parse(localStorage.getItem(key) ?? '[]');
    list.push(snap);
    localStorage.setItem(key, JSON.stringify(list.slice(-5)));   // 保留 5 版
    this.dirty = false;
  }
  async detectCrash() {                                      // 崩溃恢复检测
    const alive = Object.keys(localStorage).filter(k => k.startsWith('doc-alive-'));
    const stale = alive.filter(k => k !== 'doc-alive-' + this.tabId);   // 残留标记=崩溃
    if (!stale.length) return null;
    const snaps = [...Object.keys(localStorage).filter(k => k.startsWith('doc-snap-'))]
      .flatMap(k => JSON.parse(localStorage.getItem(k) ?? '[]'))
      .filter(s => s.tabId !== this.tabId)
      .sort((a, b) => b.ts - a.ts);                          // 取最新非本 tab
    return snaps[0] ?? null;
  }
}
function debounceSnapshot(fn, ms) { let t; return () => { clearTimeout(t); t = setTimeout(fn, ms); }; }
```

## 补充：评分点与变体

**评分点**：

- 三级频率要真分层：内存每次变更、sessionStorage 2s 防抖、localStorage 30s 加关键操作后，全部同一频率等于没分级
- 崩溃标记只能在显式保存成功或正常退出流程中清除，beforeunload 里清会连刷新一起误清，崩溃就再也检测不到
- beforeunload 必须设置 returnValue 才会弹确认，仅 return 字符串在现行浏览器里已被忽略
- 多 tab 快照按 tabId 区分，恢复时取最新且非本 tab 的记录，否则会恢复到自己刚打开的空文档

**变体与延伸**：

1. 存活标记为什么用 localStorage 而不是 sessionStorage → sessionStorage 是标签页私有的，崩溃的标签页一消失标记就跟着销毁，崩溃永远检测不到；localStorage 跨标签页共享，残留标记才能当"崩溃证据"
2. 快照超出 localStorage 5MB → 只存增量 diff 或压缩，仍超限则降级写 IndexedDB
3. 用户点了「丢弃」如何防误恢复 → 打 discarded 标记并保留一段时间，再次进入不再弹窗
