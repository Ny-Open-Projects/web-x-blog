**场景**：表单 schema 升级（字段改名 email→contact，删除 fax，新增 phone 默认值）后旧草稿恢复——字段迁移映射（rename map + defaults + drop list），旧草稿不丢数据（能映射的迁移，不能映射的归档）。

**思路**：迁移器（{renames, drops, defaults}）→ 旧草稿遍历映射 → 未映射字段保留到 `__legacy`（可找回不丢弃）。

```javascript
function migrateDraft(draft, { renames = {}, drops = [], defaults = {} } = {}) {
  const out = { ...defaults };                            // 新字段默认值
  const legacy = {};
  for (const [k, v] of Object.entries(draft)) {
    if (drops.includes(k)) { legacy[k] = v; continue; }   // 删除字段：归档不丢弃
    const nk = renames[k] ?? k;
    if (nk in out && out[nk] !== defaults[nk]) legacy[k] = v;   // 冲突：新字段已有值，旧值归档
    else out[nk] = v;
  }
  return { draft: out, legacy };                          // legacy 提示"以下旧字段已归档"
}
// migrateDraft({ email: 'a@b.c', fax: '010', name: 'x' },
//   { renames: { email: 'contact' }, drops: ['fax'], defaults: { phone: '', contact: '' } })
// => { draft: { phone: '', contact: 'a@b.c', name: 'x' }, legacy: { fax: '010' } }
// 语义：rename 迁移数据、drop 归档、default 填新字段 —— 用户无感升级（数据不丢）
// legacy 归档的信任价值：宁可归档提示也不静默删除（用户填过的东西消失 = 信任损失）
// 版本化：草稿带 schemaVersion —— 迁移器按版本链式执行（v1→v2→v3）
```

**评分点**：
- 迁移器三能力（rename/drop/default）+ legacy 归档——本题核心。
- 冲突分支（新字段已有值时旧值归档不覆盖）。
- schemaVersion 链式迁移。
- "不静默删除"的信任语义。
