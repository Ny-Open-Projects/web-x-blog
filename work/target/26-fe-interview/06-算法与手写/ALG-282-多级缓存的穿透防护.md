**场景**：恶意/异常请求打不存在的 id → 缓存永远 miss → 回源风暴。三层防护：① 负缓存——miss 结果（不存在）也缓存短 TTL（60s）；② 布隆过滤器前置——确定不存在的 id 直接拒绝（ALG-221）；③ 单飞——同 key 并发回源合并为一个请求（HW-079）。

**思路**：get 流程：bloom 检查 → L1（内存）→ L2（IDB）→ 负缓存检查 → 单飞回源 → 写 L1/L2/负缓存。

```javascript
class GuardedCache {
  #l1 = new Map(); #negative = new Map(); #inflight = new Map(); #bloom;
  constructor(loader, { negativeTtl = 60000 } = {}) { Object.assign(this, { loader, negativeTtl }); }
  async get(key) {
    if (this.#bloom && !this.#bloom.has(key)) return null;          // ① 布隆：确定不存在
    const l1 = this.#l1.get(key);
    if (l1 && Date.now() - l1.at < l1.ttl) return l1.value ?? null; // L1 命中（含负缓存值 null）
    if (this.#inflight.has(key)) return this.#inflight.get(key);    // ③ 单飞：在途共享
    const neg = this.#negative.get(key);
    if (neg && Date.now() - neg < this.negativeTtl) return null;    // ② 负缓存：短 TTL 的"不存在"
    const promise = this.loader(key)
      .then((value) => {
        value != null ? this.#l1.set(key, { value, at: Date.now(), ttl: 60000 })
                      : this.#negative.set(key, Date.now());        // miss 也缓存（负缓存）
        this.#inflight.delete(key);
        return value ?? null;
      })
      .catch((e) => { this.#inflight.delete(key); throw e; });
    this.#inflight.set(key, promise);
    return promise;
  }
}
// 三层各自挡什么：
// 布隆挡"绝对不存在的恶意 id"（O(1) 拒绝）；负缓存挡"查询后才确认不存在"的（60s 内不再回源）
// 单飞挡"同 key 并发穿透"（100 个并发 = 1 次回源）
// 组合后穿透回源量 = 理论下限（每 key 每 TTL 至多 1 次）
```

**评分点**：
- 三层防护各自挡的攻击面（布隆/负缓存/单飞）——本题核心。
- 负缓存 TTL 短于正缓存（数据可能晚点存在）。
- 单飞在途 Promise 共享（HW-079 语义）。
- 组合后穿透量理论下限的分析。
