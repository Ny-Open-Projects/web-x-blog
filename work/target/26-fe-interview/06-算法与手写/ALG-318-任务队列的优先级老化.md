**场景**：优先级队列的饿死问题：高优任务源源不断，低优任务永远排队——老化机制：任务等待超 5s 自动提升优先级（每 5s +1），最终必然执行。

**思路**：任务带 effectivePriority（base + age/5s）→ 出队按 effective 排序 → 老化升位； starving 检测（等待 > 30s 强制立即执行）。

```javascript
class AgingQueue {
  #q = []; #active = 0;
  constructor(concurrency = 4, { ageBoostMs = 5000 } = {}) { Object.assign(this, { concurrency, ageBoostMs }); }
  push(task, priority = 0) {
    return new Promise((resolve, reject) => {
      this.#q.push({ task, priority, at: Date.now(), resolve, reject });
      this.#drain();
    });
  }
  #eff(job) {
    const age = Date.now() - job.at;                    // 老化：每 5s 等待 = +1 优先级
    return job.priority + Math.floor(age / this.ageBoostMs);
  }
  #drain() {
    while (this.#active < this.concurrency && this.#q.length) {
      this.#q.sort((a, b) => this.#eff(b) - this.#eff(a));   // 有效优先级（base + 老化）排序
      const job = this.#q.shift();
      this.#active++;
      job.task().then(job.resolve, job.reject).finally(() => { this.#active--; this.#drain(); });
    }
  }
}
// 老化保证：等待 5s 的低优任务 eff = 1，10s = 2…… 最终超过新来的高优任务 —— 零饿死
// 参数权衡：ageBoost 越小低优越快插队（高优延迟增大）；5s 是"低优延迟可控、高优基本不受扰"的平衡
// 对比 HW-066 静态优先级：老化版解决"高优持续洪峰饿死低优"—— 预取类低优任务必备
```

**评分点**：
- 老化机制（effective = base + age/boost）防饿死——本题核心。
- 参数权衡（ageBoost 与高优延迟的 tradeoff）。
- 与静态优先级队列（HW-066）的差异场景。
- 零饿死保证的推理。
