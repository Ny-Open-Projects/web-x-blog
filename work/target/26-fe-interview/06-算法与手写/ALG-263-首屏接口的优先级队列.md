## ALG-263：首屏接口编排：按 LCP 贡献排序的请求优先级（关键路径接口先行，并发上限内调度）？
**答**：首屏 8 个接口，HTTP/1.1 同域并发 6——超出并发的接口排队，排错顺序会拖慢 LCP。按"LCP 贡献"排优先级：主商品(10) > 价格(9) > 库存(8) > 评价(3) > 推荐(1)——队列按优先级出队（HW-066 模式，接口版）。

**思路**：优先级队列 + 并发上限（6）+ fetchpriority 透传（浏览器侧调度配合）+ 依赖感知（评价依赖商品 id——拓扑约束）。

```javascript
class PriorityFetcher {
  constructor(concurrency = 6) { Object.assign(this, { concurrency }); this.active = 0; this.q = []; }
  fetch(url, { priority = 0, deps = [] } = {}) {
    return new Promise((resolve, reject) => {
      this.q.push({ url, priority, deps, resolve, reject });
      this.q.sort((a, b) => b.priority - a.priority);     // 高优先级先出队
      this.#drain();
    });
  }
  #drain() {
    while (this.active < this.concurrency && this.q.length) {
      // 依赖约束：deps 中有未完成的任务跳过（取下一个无依赖的）
      const idx = this.q.findIndex((j) => j.deps.every((d) => this.#done?.has(d)));
      if (idx === -1) break;                              // 全被依赖阻塞：等当前完成
      const job = this.q.splice(idx, 1)[0];
      this.active++;
      fetch(job.url, { priority: job.priority >= 8 ? 'high' : 'auto' })   // fetchpriority 透传
        .then((r) => r.json())
        .then((data) => { (this.#done ??= new Set()).add(job.url); job.resolve(data); })
        .catch(job.reject)
        .finally(() => { this.active--; this.#drain(); });
    }
  }
}
// 用法：
// f.fetch('/api/goods/1', { priority: 10 });
// f.fetch('/api/stock/1', { priority: 8, deps: ['/api/goods/1'] });   // 依赖商品接口（要 id）
// f.fetch('/api/recs', { priority: 1 });
// 效果：并发 6 内，主商品+价格+库存先占槽；评价等依赖满足后插入；推荐最后
// LCP 贡献排序依据：Resource/Server-Timing 聚合（PER-299 接口瀑布分析的数据驱动）
```

**评分点**：
- 优先级出队 + 依赖拓扑约束（deps 未完成跳过取下一个）——本题核心。
- fetchpriority 透传（应用层与浏览器调度双轨）。
- 优先级来自 LCP 贡献数据（PER-299）不是拍脑袋。
- 依赖全阻塞时的防死循环（idx -1 break）。
