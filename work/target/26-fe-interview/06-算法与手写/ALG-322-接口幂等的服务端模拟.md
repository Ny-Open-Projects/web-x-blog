**场景**：前端重试/重放逻辑（HW-063/108）的测试：mock 服务端实现幂等语义（首执行 201/重放 200+首响应/并发 409/过期重执行）——四种分支全覆盖才能验证前端正确性。

**思路**：幂等表（key→{status, response, expiresAt}）+ 请求序互斥（并发同 key：第一个执行其他 409）+ TTL 过期重执行。

```javascript
const idemStore = new Map();                            // key -> { status, response, expiresAt, executing }
async function handleIdempotent(key, handler) {
  const now = Date.now();
  const entry = idemStore.get(key);
  if (entry && entry.expiresAt > now) {
    if (entry.executing) return { status: 409, body: { error: 'in-progress' } };      // 并发同 key：409
    if (entry.status === 'done') return { status: 200, body: entry.response };        // 重放：首次响应
  }
  const e = entry ?? { status: 'executing', response: null, expiresAt: now + 48 * 3600e3, executing: true };
  e.executing = true; idemStore.set(key, e);
  try {
    const response = await handler();                   // 首次执行
    e.status = 'done'; e.response = response; e.executing = false;
    return { status: 201, body: response };
  } catch (err) {
    idemStore.delete(key);                              // 执行失败：清除（下次重执行）
    e.executing = false;
    throw err;
  }
}
// 四分支语义（前端重试/重放逻辑的验证矩阵）：
// 首执行 201 / 重放命中 200+原响应（不是重新执行）/ 并发同 key 409（前端按成功处理）/ TTL 过期重执行（新请求）
// 测试用例映射：
// HW-063 重试（同键两次）→ 断言第二次 200 且副作用一次
// HW-108 断网重放 → 断言重放命中
// 并发双击 → 409 → 前端按成功处理
```

**评分点**：
- 四分支幂等语义（首执行/重放/并发 409/过期）——本题核心（验证矩阵完整）。
- executing 标志的并发互斥。
- 执行失败清 key（下次可重执行）。
- TTL 过期语义（48h 后同键视为新请求）。
