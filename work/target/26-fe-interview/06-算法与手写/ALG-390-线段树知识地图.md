## ALG-390：线段树知识地图：什么时候该想到线段树

**答**：
- 题目：收官题——给出「看到什么需求特征就该上线段树」的判断树与替代方案对照。
- 要点：特征①区间统计查询+单点/区间更新 → 线段树/BIT；特征②统计量满足区间可加性（sum/min/max/gcd 可，众数/中位数不可直接）→ 能合并就能建树；特征③复杂懒标记（赋值+加混合）→ 线段树必备懒标记；特征④稀疏大值域 → 动态开点；特征⑤只读多查询 → 离线排序+BIT；特征⑥静态数组 → ST 表（O(1) 查询）。
- 评分点：可加性判断是核心；各替代方案（BIT/ST/离线/分块）边界；复杂度对照。

## 追问（补充）

**追问**：

1. 为什么 BIT 只能做「可减」的统计量？ → 前缀和相减要求运算存在逆元：sum 有减法，min/max 没有，所以区间最小值必须走线段树或 ST 表；答题时说出「可减性」这个词就是分水岭。
2. 懒标记为什么强调「合并顺序」？ → 赋值与加法不满足交换律（先赋后加 ≠ 先加后赋），必须显式定义标记复合规则（如 set 覆盖 add）；顺序写错的典型症状是「连续两次区间赋值后结果漂移」。
3. 动态开点什么时候反而不划算？ → 每次操作新建 O(log n) 个节点，q 次操作就是 O(q log n) 个指针；值域大但操作集中的场景，指针与 GC 开销会超过静态数组版，不如先离散化。
4. 树链剖分到底在解决什么？ → 把树上「路径」拆成 O(log n) 段在 dfs 序上连续的区间，从而把路径查询/修改转成线段树的区间操作；代价是多一次 LCA 与两次 dfs 预处理。
