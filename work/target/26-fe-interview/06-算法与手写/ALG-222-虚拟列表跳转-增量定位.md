**场景**：10 万条消息的长会话里"定位到某条消息"（搜索/引用跳转）：虚拟列表下不能直接 scrollTo，需要 ① 找到目标 index（Map 索引 O(1)）② 计算其 offset（前缀和）③ 定位虚拟列表渲染窗口（设置 scrollTop 后等渲染再精确对齐）。

**思路**：id→index 哈希索引 + 前缀和 offset + 两阶段定位（粗定位 scrollTop，渲染后微调 scrollTo 精确值）。

```javascript
class MessageLocator {
  constructor(list, virtualList) {
    this.vl = virtualList;
    this.index = new Map();                          // id -> {idx, offset}
    let acc = 0;
    list.forEach((m, i) => { this.index.set(m.id, { idx: i, offset: acc }); acc += m.height; });
  }
  locate(id, { align = 'center' } = {}) {
    const hit = this.index.get(id);
    if (!hit) return false;
    const viewport = this.vl.container.clientHeight;
    // 粗定位：把 scrollTop 设到目标附近（虚拟列表立刻渲染对应窗口）
    this.vl.container.scrollTop = Math.max(0, hit.offset - viewport / 2);
    // 两阶段：等当前帧渲染完成后再精确对齐（元素可能高度与预估不同）
    requestAnimationFrame(() => {
      const el = this.vl.container.querySelector(`[data-id="${id}"]`);
      if (!el) return;
      const delta = align === 'center'
        ? el.offsetTop - this.vl.container.scrollTop - (viewport - el.offsetHeight) / 2
        : el.offsetTop - this.vl.container.scrollTop;
      this.vl.container.scrollTop += delta;          // 微调到精确位置
    });
    return true;
  }
}
// 10 万条里 O(1) 找到目标（Map 索引），定位两阶段解决"动态高度预估不准"问题
// 询优：若列表是动态高度且未渲染，offset 是预估——两阶段定位就是修正预估误差的标准做法
```

**评分点**：
- id→index Map 索引 O(1)（线性 findIndex 10 万条会卡）。
- 两阶段定位（粗 scrollTop → rAF 后精确对齐）解决动态高度预估误差——核心考点。
- align 语义（center/top）。
- 场景对应：虚拟列表内的搜索定位/引用跳转。
