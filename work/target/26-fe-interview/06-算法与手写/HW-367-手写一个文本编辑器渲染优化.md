## HW-367：手写一个文本编辑器渲染优化：分行渲染缓存与失效

**答**：
- 需求：实现 LineRenderCache：每行渲染结果缓存（HTML 字符串 + 版本号）；行编辑时按版本失效（只重渲染脏行）；视口内行渲染（虚拟滚动结合）；语法高亮 token 缓存复用（行未变不重 tokenize）。
- 边界：版本号方案（文档全局 rev + 行局部 rev）；缓存内存上限（视口外 LRU 清理）；粘贴大段文本批量失效。
- 评分点：版本失效精确到行；token 缓存复用；LRU 清理。

```javascript
class LineRenderCache {
  constructor({ cap = 2000 } = {}) { this.cache = new Map(); this.cap = cap; this.docRev = 0; }
  bump() { this.docRev++; }                                  // 文档全局版本
  invalidate(lineIdx) { this.cache.delete(lineIdx); }        // 行局部失效
  invalidateRange(start, end) {                              // 批量失效（粘贴）
    for (let i = start; i <= end; i++) this.cache.delete(i);
  }
  renderLine(idx, text, highlighter) {
    const c = this.cache.get(idx);
    if (c && c.rev === this.docRev && c.text === text) {               // 命中：不重渲染
      this.cache.delete(idx); this.cache.set(idx, c);                  // 命中要移到队尾，否则退化成 FIFO
      return c.html;
    }
    const html = highlighter(text);                          // tokenize + 渲染
    this.cache.set(idx, { html, text, rev: this.docRev });
    if (this.cache.size > this.cap) {                        // LRU 清理视口外
      const keys = [...this.cache.keys()];
      keys.slice(0, this.cache.size - this.cap).forEach(k => this.cache.delete(k));
    }
    return html;
  }
}
```

## 补充：评分点与变体

**评分点**：

- 缓存命中条件要同时校验 `c.rev === this.docRev` 与 `c.text === text`；只比 docRev 会让未改动行在全局版本递增后全部失效
- 粘贴走 `invalidateRange` 逐行 delete，而不是 `cache.clear()`，否则一次粘贴把视口内所有行的渲染结果全丢掉
- LRU 清理放在 set 之后、按 Map 的插入序淘汰最老的键；命中分支要 delete 再 set 才能把该行移到队尾，否则只是 FIFO
- 能讲清两级缓存的层次：行文本未变复用 HTML，行变了但 token 序列相同可只重拼 span 不重 tokenize

**变体与延伸**：

1. 撤销后行内容回到旧值，缓存还能命中吗 → 用内容 hash 作键可跨版本复用，用 docRev 作键则必然重渲染
2. 单行十万字符的超长行怎么处理 → 行内再按可视区切片，token 按段缓存，避免整行重建 DOM
3. 折叠区域的行要不要渲染 → 不进视口就不渲染，但保留缓存条目，避免展开时整段重算
