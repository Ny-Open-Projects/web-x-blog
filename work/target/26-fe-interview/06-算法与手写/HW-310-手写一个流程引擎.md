## HW-310：手写一个流程引擎：顺序、分支与并行节点编排执行

**答**：
- 需求：实现 FlowEngine：节点 [{id, type: task|branch|parallel|end, next/branches/parallel}]；run(ctx) 从 start 逐节点执行：task 调处理器、branch 按 ctx 判定走向、parallel 并行执行子分支（全部完成后汇合到 merge 节点）；执行轨迹记录（供调试）。
- 边界：task 处理器失败可配置 continue-on-error；parallel 分支异常聚合（Promise.allSettled）；环检测（流程图成环报错）。
- 评分点：分支/并行汇合语义；异常策略；环检测。

```javascript
class FlowEngine {
  constructor(nodes, handlers) { this.nodes = new Map(nodes.map(n => [n.id, n])); this.h = handlers; }
  async run(ctx) {
    const trace = [];
    let cur = this.nodes.get('start');
    const seen = new Set();
    while (cur && cur.type !== 'end') {
      if (seen.has(cur.id)) throw new Error('flow-cycle: ' + cur.id);   // 环检测
      seen.add(cur.id);
      trace.push(cur.id);
      if (cur.type === 'task') {
        try { ctx = await this.h[cur.task](ctx); }
        catch (e) { if (!cur.continueOnError) throw e; ctx.error = String(e); }
        cur = this.nodes.get(cur.next);
      } else if (cur.type === 'branch') {
        const target = cur.branches.find(b => b.when(ctx)) ?? cur.default;
        cur = this.nodes.get(target);
      } else if (cur.type === 'parallel') {                  // 并行 + allSettled 汇合
        const results = await Promise.allSettled(
          cur.parallel.map(b => this.h[b.task](structuredClone(ctx))));
        ctx.results = results.map(r => r.status === 'fulfilled' ? r.value : { error: String(r.reason) });
        cur = this.nodes.get(cur.merge);
      }
    }
    return { ctx, trace };                                   // 轨迹供调试
  }
}
```

## 补充：评分点与变体

**评分点**：

- parallel 汇合用 Promise.allSettled 而非 all，单分支 reject 不能让其余分支结果丢失、更不能阻断 merge
- 环检测放在 run 之前用 DFS 三色标记做一遍，靠执行步数上限兜底属于事后补救
- branch 节点判定后必须走到它指向的节点，不能直接跳到 end 绕过 merge，否则汇合逻辑形同虚设
- 轨迹要记 nodeId 与耗时，只记「执行到某步」在排查卡死节点时没有信息量

**变体与延伸**：

1. 分支要人工审批、可能挂几小时 → 节点状态持久化，run 支持从 checkpoint 恢复，不能常驻内存干等
2. 并行分支同时写 ctx 同一字段 → 每分支给 ctx 副本，汇合时按声明的 merge 策略合并，避免后写覆盖先写
3. 开了 continue-on-error 后怎么收尾 → 节点结果标 failed 但流程继续，最终汇总带失败清单供人工复核
