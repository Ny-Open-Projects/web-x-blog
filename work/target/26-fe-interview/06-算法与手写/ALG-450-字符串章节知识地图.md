## ALG-450：字符串章节知识地图：字符串工具选型

**答**：
- 题目：收官题——字符串算法选型判断树。
- 要点：单模式匹配 → KMP（next 数组）；多模式 → AC 自动机；子串比较/判相似 → 哈希（双哈希防碰撞）；重复/周期 → Z 函数；回文 → Manacher；循环同构 → 最小表示法 / t+t；前缀类 → Trie（海量压缩 → 双数组）；编辑距离类 → DP（受限带状优化）；不连续公共 → LCS；子串公共 → 哈希二分。坑点：哈希碰撞、UTF-16 码元 vs 码点、大小写/全角归一化。
- 评分点：按「模式数/查询次数/精度要求」选型；各算法复杂度表；工程坑点清单。

## 补充：评分点与变体

**评分点**：

- 选型要给判据而非名字：模式数（1 个还是多个）、查询次数（一次还是反复）、是否要全部位置，三维一定位基本唯一
- 复杂度要能脱口而出：KMP O(n+m)、AC 建树 O(Σm) 匹配 O(n+z)、Z 函数 O(n)、Manacher O(n)
- 哈希必须双哈希或带校验，单模 1e9+7 在构造数据下可被卡碰撞，这一点是工程与竞赛的分水岭
- 坑点要具体：UTF-16 码元与码点、全角半角、大小写归一化，且顺序必须是先归一化再匹配

**变体与延伸**：

1. 中文与 emoji 为什么不能直接 indexOf → JS 按 UTF-16 码元索引，代理对会被从中间切开，需先转成码点数组
2. 要容忍一个错字的模糊匹配 → 编辑距离 DP 或分段哈希加校验，KMP 的严格前缀性质在这里不适用
3. 流式日志里查敏感词 → AC 自动机逐字符推进、失配走 fail 指针，不能每行重建自动机
