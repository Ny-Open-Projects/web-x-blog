## HW-132：手写重试策略注册表——按接口类型配置不同重试策略（读/写/支付），策略可热更新
**答**：不同接口重试策略不同：读接口（可重试 3 次退避）、写接口（幂等前提下重试 1 次）、支付（永不自动重试——防止重复支付，失败显式确认）。策略注册表：按路由模式匹配策略，服务端可下发热更新（PER-423 配置中心）。

```javascript
const STRATEGIES = new Map([
  ['GET:*',        { retries: 3, backoff: 500, jitter: true, retryOn: [429, 500, 502, 503] }],
  ['POST:/api/like*', { retries: 1, backoff: 1000, retryOn: [500, 503] }],      // 写：幂等键前提
  ['POST:/api/pay*',  { retries: 0, confirmOnFail: true }],                     // 支付：永不自动重试
]);

function matchStrategy(url, method) {
  for (const [pattern, s] of STRATEGIES) {
    const [m, glob] = pattern.split(':');
    if (m !== method && m !== '*') continue;
    const re = new RegExp('^' + glob.replace(/\*/g, '.*') + '$');
    if (re.test(url)) return s;
  }
  return { retries: 1, backoff: 500, retryOn: [503] };      // 兜底默认
}
async function fetchWithStrategy(url, options = {}) {
  const s = matchStrategy(url, options.method ?? 'GET');
  for (let i = 0; ; i++) {
    try {
      const res = await fetch(url, options);
      if (res.ok) return res;
      if (i >= s.retries || !s.retryOn?.includes(res.status)) {
        if (s.confirmOnFail) return { __confirmNeeded: true, status: res.status };   // 支付失败：显式确认
        throw new Error(String(res.status));
      }
    } catch (e) { if (i >= s.retries) throw e; }
    await new Promise((r) => setTimeout(r, s.backoff * 2 ** i * (0.5 + Math.random() / 2)));
  }
}
// 热更新：服务端下发 STRATEGIES 覆盖（配置中心签名校验，PER-423）
// 支付语义：retries=0 + confirmOnFail —— "可能已成功"的失败必须人工确认，绝不自动重发
```

**评分点**：
- 按接口类型分级策略（读多试/写谨慎/支付绝不自动重试）——支付语义是本题核心。
- glob 模式匹配路由；兜底默认策略存在。
- 确认式失败（confirmNeeded）区别于重试失败。
- 策略可热更新（签名 + 缓存回退）。
