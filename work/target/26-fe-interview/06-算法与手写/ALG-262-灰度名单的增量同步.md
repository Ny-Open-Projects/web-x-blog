**场景**：灰度名单 10 万 uid（白名单/黑名单），变更频繁——全量推送 1MB/次不可接受；增量 diff（added/removed）推送 + 客户端 Set 合并；断线重连 gap 检测（ALG-259 同构，名单版）。

**思路**：服务端维护 rev 计数与变更日志（最近 N 条 diff）；客户端 rev 对齐请求 `?since=rev`；压缩：uid 列表差集比全量小 100 倍。

```javascript
// 服务端
class GrayList {
  #set = new Set(); #log = []; #rev = 0;
  update(added, removed) {
    this.#rev++;
    added.forEach((u) => this.#set.add(u));
    removed.forEach((u) => this.#set.delete(u));
    this.#log.push({ rev: this.#rev, added, removed });
    if (this.#log.length > 100) this.#log.shift();        // 日志窗口：超窗只能全量
  }
  since(rev) {
    if (rev === null || this.#rev - rev > this.#log.length) return { full: [...this.#set], rev: this.#rev };
    const added = [], removed = [];
    for (const d of this.#log.filter((x) => x.rev > rev)) {
      added.push(...d.added); removed.push(...d.removed);
    }
    return { added, removed, rev: this.#rev };            // 合并窗口内多条 diff（客户端幂等合并）
  }
}
// 客户端：Set 合并（ALG-259 同构）
// added.forEach(u => set.add(u)); removed.forEach(u => set.delete(u));
// 语义：日志窗口内增量；超窗/首连 → 全量快照 —— 两种响应客户端都幂等（Set 语义天然幂等）
// 带宽：全量 1MB → 增量 ~2KB（百倍）；灰度判定 O(1)（Set.has）
```

**评分点**：
- 变更日志窗口 + since 增量协议（超窗回退全量）——本题核心。
- 合并窗口内多条 diff 的正确性（同 uid added+removed 抵消由 Set 幂等吸收）。
- 断线重连 gap 检测（rev 对齐）。
- 带宽量化与 Set O(1) 判定。
