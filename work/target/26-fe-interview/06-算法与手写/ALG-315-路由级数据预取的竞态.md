**场景**：用户快速点击列表两个商品（两次导航）——第一次的预取/加载还在途，第二次导航开始：第一次的结果必须丢弃（渲染目标已变）；预取的（第一次目标）保留在缓存（用户可能回来）。

**思路**：导航序号（navigation epoch）——渲染前校验 epoch；预取结果按 URL 缓存（与导航无关，按需消费）；真实加载绑定导航。

```javascript
class RouteLoader {
  #epoch = 0; #cache = new Map();                         // 预取缓存（URL 维度，跨导航保留）
  async navigate(path) {
    const epoch = ++this.#epoch;                          // 导航序号
    const cached = this.#cache.get(path);
    if (cached) return this.#renderIfCurrent(path, cached, epoch);   // 预取命中：秒渲染
    const data = await fetchData(path);
    this.#cache.set(path, data);                          // 结果入缓存（后续导航/返回命中）
    return this.#renderIfCurrent(path, data, epoch);      // 渲染前校验：epoch 变了丢弃
  }
  #renderIfCurrent(path, data, epoch) {
    if (epoch !== this.#epoch) return false;              // 已被新导航取代：静默丢弃
    render(path, data);
    return true;
  }
}
// 双层语义：
// 预取缓存按 URL 维度（与导航序无关）—— 第一次导航的预取保留，用户返回时命中（HW-189 语义）
// 真实渲染绑定 epoch —— 过期渲染静默丢弃（不闪旧内容）
// fetch 无 abort 的场景（缓存接口）epoch 校验是唯一防线（PER-328 分层）
```

**评分点**：
- 预取缓存（URL 维度跨导航保留）与渲染 epoch（导航维度校验）的双层语义——本题核心。
- 渲染前校验丢弃过期结果。
- 预取保留的理由（用户返回命中）。
- 与 HW-117 的对照（abort 版 vs epoch+缓存版）。
