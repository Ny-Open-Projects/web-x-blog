**场景**：看板轮询（5s 一次）：全量拉取（1000 行）浪费——增量：`?since=lastRev` 只拉变更（变更日志窗口内）；客户端 rev 对齐（ALG-259/262 同构协议）；日志窗口超界（断线久）→ 全量兜底。

**思路**：轮询器带 rev → 响应含 {changes, rev} 或 {full, rev}（超窗）→ 客户端应用 + 更新 rev；gap（rev 跳变）→ 全量重拉。

```javascript
class IncrementalPoller {
  #rev = null;
  async poll(url, apply) {
    const res = await fetch(`${url}?since=${this.#rev ?? ''}`).then((r) => r.json());
    if (res.full) {                                       // 超窗/首拉：全量
      apply(res.full, 'full');
    } else {
      if (this.#rev != null && res.fromRev !== this.#rev) {
        return this.resync(url, apply);                   // gap：rev 不连续 → 全量重拉
      }
      apply(res.changes, 'delta');                        // 增量应用（added/updated/deleted）
    }
    this.#rev = res.rev;                                  // 游标推进
  }
  async resync(url, apply) {                              // gap 兜底：全量 + 重置游标
    const res = await fetch(url).then((r) => r.json());
    apply(res.full, 'full-resync');
    this.#rev = res.rev;
  }
}
// 增量收益：1000 行全量 80KB → 变更 3 行 1KB（轮询流量 -98%）
// gap 检测：fromRev ≠ 期望 rev → 断线期间的变更丢了 → 全量重拉（正确性兜底）
// 语义统一：full/delta 两种响应客户端都幂等应用（apply 回调内部按模式处理）
// 与 ALG-259/262 的关系：同一套 rev 对齐协议（权限推送/灰度名单/轮询——三场景一套模式）
```

**评分点**：
- since 游标增量 + gap 全量兜底的双模式——本题核心。
- rev 连续性检测（fromRev 校验）。
- 与 ALG-259/262 的协议同构（一套模式三场景）。
- 增量收益量化（-98%）。
