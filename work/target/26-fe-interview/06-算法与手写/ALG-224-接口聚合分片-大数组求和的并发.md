## ALG-224：前端大数组计算的分片并行：1 亿数字求和/最大值，不卡 UI 的分片 + SharedArrayBuffer 并行方案？
**答**：1 亿条数据的前端聚合计算（求和/过滤/统计），主线程一次算会卡 2~5 秒（INP 爆炸）。方案阶梯：① 分片 yield（简单，单线程）；② Worker 多线程并行（Transferable/SharedArrayBuffer 分块）。

**思路**：Worker 并行——数据分 P 块传给 P 个 Worker（transfer 零拷贝），各自求部分和，主线程聚合。注意 1 亿 × 8B = 800MB 本身就是内存问题，实际场景要 TypedArray + 流式。

```javascript
// 主线程：分块并行求和
async function parallelSum(f64buf, workers = 4) {
  const pool = Array.from({ length: workers }, () => new Worker('sum.js'));
  const len = f64buf.byteLength / 8, chunk = Math.ceil(len / workers);
  const results = await Promise.all(pool.map((w, i) => new Promise((resolve, reject) => {
    const start = i * chunk, count = Math.min(chunk, len - start);
    if (count <= 0) return resolve(0);
    // 注意：Transferable 切片不能 transfer 同一个 buffer 的不同区间——
    // 方案 a：slice 拷贝子块（有拷贝成本）；方案 b：SharedArrayBuffer 共享（零拷贝）
    const sub = f64buf.slice(start * 8, (start + count) * 8);
    w.onmessage = (e) => resolve(e.data);
    w.onerror = reject;
    w.postMessage(sub, [sub]);                       // transfer 子块
  })));
  pool.forEach((w) => w.terminate());
  return results.reduce((a, b) => a + b, 0);
}
// sum.js（Worker）：
self.onmessage = ({ data }) => {
  const arr = new Float64Array(data);
  let s = 0;
  for (let i = 0; i < arr.length; i++) s += arr[i];
  self.postMessage(s);
};
// 对比：主线程单线程 1 亿求和 ≈ 300ms~1s（还要 yield 切片防卡顿）；
// 4 Worker 并行 ≈ 80~250ms 且主线程零占用
// 精度提示：浮点求和顺序影响精度，大数场景用 Kahan 补偿或整数化（分单位）
```

**评分点**：
- Transferable 子块分发正确，能指出"同一 buffer 不同区间不能分别 transfer"这个坑（slice 拷贝或 SharedArrayBuffer 两案）。
- 并发 worker 池 + Promise.all 聚合。
- 浮点求和精度意识（Kahan/整数化）。
- 主线程零占用 vs 分片 yield 的取舍说明。
