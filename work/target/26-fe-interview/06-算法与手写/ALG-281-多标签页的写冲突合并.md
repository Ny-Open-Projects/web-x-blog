**场景**：同一文档双标签页编辑：A 改 title、B 改 price——合并应双保留（字段级 LWW）；都改 title → 时间戳新的赢但提示（可感知的覆盖）。合并引擎：操作日志（{field, value, ts, tab}）→ 字段级 LWW + 冲突字段标记。

**思路**：按 field 建 state（{value, ts, tab}）→ 合并两标签页日志 → LWW 应用 + 冲突检测（同 field 双写且值不同 → 冲突列表）。

```javascript
function mergeTabOps(opLogs, currentTab) {
  const state = new Map();                                // field -> { value, ts, tab }
  const conflicts = [];
  for (const op of opLogs.sort((a, b) => a.ts - b.ts)) {  // 时间序应用（LWW 语义）
    const cur = state.get(op.field);
    if (!cur || op.ts >= cur.ts) {
      if (cur && cur.value !== op.value && cur.tab !== op.tab) {
        // 同字段两标签都写：后者覆盖（LWW）但记冲突（UI 提示"B 标签的修改被覆盖"）
        conflicts.push({ field: op.field, winner: op.value, loser: cur.value, loserTab: cur.tab });
      }
      state.set(op.field, op);
    }
  }
  const value = Object.fromEntries([...state].map(([f, o]) => [f, o.value]));
  return { value, conflicts };                            // conflicts → 覆盖提示（可感知 LWW）
}
// 双开场景：A(10:00) 改 title='x'，B(10:05) 改 title='y' → y 赢 + A 收到冲突提示（广播）
// 语义分级：
// 不同字段 → 字段级合并（双保留，无冲突）
// 同字段双写 → LWW + 冲突提示（不是静默覆盖——用户可感知）
// 冲突提示的送达：BroadcastChannel 广播 loser 给对应标签页（该页 toast"您的修改已被另一窗口覆盖"）
```

**评分点**：
- 字段级 LWW + 冲突标记（覆盖可感知）——本题核心。
- 时间序应用（ts 排序保证确定性）。
- 冲突提示送达loser标签页（BroadcastChannel）。
- 与整篇 LWW 的粒度对比（字段级保留更多用户输入）。
