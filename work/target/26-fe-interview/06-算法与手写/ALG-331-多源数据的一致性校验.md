**场景**：同一商品价格来自列表接口、详情接口、缓存——不一致时（列表 99/详情 101/缓存 98）仲裁：按数据时间戳（updatedAt）最新者胜 + 不一致本身上报（缓存失效/主从延迟的信号）。

**思路**：多源合并（带 ts）→ 仲裁（max updatedAt）→ 一致性检测（max-min 差值超阈值告警——数据管线健康度）。

```javascript
function arbitrate(sources, { tolerance = 0.01 } = {}) {
  // sources: [{ source: 'list', value: 99, ts }, { source: 'detail', value: 101, ts }, ...]
  const valid = sources.filter((s) => s.value != null && s.ts);
  if (!valid.length) return null;
  const winner = valid.reduce((a, b) => (b.ts > a.ts ? b : a));   // 时间戳最新仲裁
  const values = valid.map((s) => s.value);
  const spread = Math.max(...values) - Math.min(...values);
  if (spread > winner.value * tolerance) {                // 离散度超容差：跨源不一致告警
    report?.({ type: 'source-inconsistency', key: winner.source,
               sources: valid.map((s) => ({ src: s.source, v: s.value, age: Date.now() - s.ts })) });
  }
  return { value: winner.value, from: winner.source, staleAge: Date.now() - winner.ts };
}
// 仲裁语义：时间戳最新优先（数据新鲜度是唯一可信维度——不是"哪个接口更权威"）
// 告警价值：跨源不一致 = 缓存失效缺失/主从延迟/版本错配（PER-388）—— 数据管线健康信号
// staleAge 输出：用的数据多旧（> 60s 的"最新"也是陈旧——UI 标注）
```

**评分点**：
- 时间戳最新仲裁（不按接口权威性主观指定）——本题核心。
- 离散度容差告警（跨源不一致 = 管线健康信号）。
- staleAge 输出（陈旧标注）。
- 与 PER-388 混版/PER-331 脏读防线的联动。
