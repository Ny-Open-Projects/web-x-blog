## HW-239：手写一个编辑器历史压缩：N 步后合并为快照

**答**：
- 需求：实现 CompressedHistory：最近 N 条保留操作级 undo，更早的历史压缩为快照（文档 JSON + 快照时间）；undo 跨越快照边界时恢复快照再重放之后的操作；内存统计输出（操作栈 vs 快照占用）。
- 边界：快照创建时机（操作数超阈值时异步生成，不阻塞输入）；重放操作要按序且幂等；压缩后 undo 深度仍正确。
- 评分点：快照+重放混合 undo；异步快照；深度正确性。

```javascript
class CompressedHistory {
  constructor({ opLimit = 50 } = {}) {
    this.ops = []; this.snapshot = null; this.limit = opLimit;
    this.afterSnapshot = [];                                   // 快照之后的操作
  }
  push(op) {
    this.ops.push(op);
    if (this.ops.length > this.limit) {                        // 超限：把最旧操作并入快照
      this.ops.splice(0, this.ops.length - this.limit);        // 丢弃最旧 op
      this.afterSnapshot = [];                                 // 快照点之后不留旧 op
      const keep = this.ops.slice();
      for (let i = keep.length - 1; i >= 0; i--) keep[i].inverse();   // 回退到边界状态
      this.snapshot = serializeDoc(currentDoc());              // 快照 = 边界状态
      for (const o of keep) o.after();                         // 重放回当前文档
    }
  }
  undo() {                                                     // 跨快照边界恢复
    if (this.ops.length) { const op = this.ops.pop(); op.inverse(); return 'op'; }
    if (this.snapshot) {
      restoreDoc(this.snapshot);                               // 恢复快照
      for (const op of this.afterSnapshot.slice(0, -1)) op.after();   // 重放到上一条
      const last = this.afterSnapshot.pop();
      this.ops = [...this.afterSnapshot]; this.afterSnapshot = [];
      return 'snapshot';
    }
    return null;                                               // 无可回退
  }
  memory() {                                                   // 占用统计
    const opBytes = this.ops.length * 200;
    const snapBytes = this.snapshot?.length ?? 0;
    return { opBytes, snapBytes, mode: snapBytes > opBytes ? 'snapshot-heavy' : 'op-heavy' };
  }
}
```

## 补充：评分点与变体

**评分点**：

- 快照异步生成且必须绑定生成时刻的操作序号，序号不绑会出现「快照已含新 op 又重放一遍」
- undo 跨快照边界要「恢复快照 + 按序重放其后 op」，重放必须幂等，重复应用不能叠加
- 压缩后 undo 深度按逻辑步计数而非物理条目，否则压缩一次深度凭空缩水
- 内存统计要同时含操作栈与快照体积，只算栈会低估真实占用

**变体与延伸**：

1. 快照生成中用户继续编辑 → 快照取开始时刻的状态并记 op 序号，之后的新 op 不并入
2. 文档 10MB 时快照本身就很大 → 周期全量加中间增量，或对快照做结构化压缩
3. 为什么不能全用快照代替操作栈 → 快照无操作语义，无法做细粒度合并与跨文档重放
