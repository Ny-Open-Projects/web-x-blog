## HW-131：手写乐观列表对账——本地操作序 vs 服务端序的 reconciliation（版本向量 + 冲突合并）
**答**：乐观更新列表（HW-091）的多端一致性：本地按操作序渲染，服务端有全局序——对账（reconciliation）时按 id 合并：本地未确认操作保留在"pending 区"，服务端数据到位后做三方合并（服务端序 + 本地 pending 插入位置 + 冲突检测）。

```javascript
class OptimisticList {
  constructor() { this.server = []; this.pending = new Map(); }   // id -> {op, beforeId|afterId}
  applyLocal(op) {                                                 // 乐观：本地立即变更
    this.pending.set(op.id, op);
    this.#renderMerged();
  }
  reconcile(serverList) {                                          // 服务端数据到达
    this.server = serverList;
    // 冲突检测：pending 操作的锚点（beforeId）在服务端已不存在 → 冲突
    for (const [id, op] of this.pending) {
      if (op.type === 'insert' && op.beforeId && !serverList.some((x) => x.id === op.beforeId)) {
        op.conflict = true;                                        // 标记冲突：UI 提示用户
      }
    }
    this.#renderMerged();
  }
  #renderMerged() {
    const out = [];
    for (const item of this.server) {
      // 服务端条目前插入 pending 中锚点指向它的项
      for (const [, op] of this.pending) if (op.beforeId === item.id) out.push(this.#stub(op));
      out.push(item);
    }
    for (const [, op] of this.pending) if (!op.beforeId) out.push(this.#stub(op));   // 尾部追加
    this.view = out;    // pending 项带"未同步"标记（半透明+icon）
  }
  #stub(op) { return { ...op.data, __pending: true, __conflict: op.conflict }; }
}
// 语义：本地立即见（pending 标记）→ 服务端序到达 → 合并渲染 → 冲突显式提示（不静默覆盖）
// 关键：pending 锚点失效（beforeId 被删）→ conflict 标记，绝不静默丢弃用户操作
```

**评分点**：
- pending 区 + 服务端序的三方合并模型清晰。
- 冲突检测（锚点失效）显式标记给用户，不静默覆盖/丢弃——本题核心。
- pending 项的视觉语义（未同步标记）。
- reconcile 后 pending 清理时机（服务端确认后移出）。
