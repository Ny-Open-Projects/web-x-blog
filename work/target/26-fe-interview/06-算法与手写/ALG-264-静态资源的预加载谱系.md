**场景**：路由级 code splitting 后，跳转路由要二次下载 chunk——构建期分析依赖图生成每路由的 preload 清单（入口 JS/CSS/字体/modulepreload 依赖图），注入 HTML；跳转时浏览器并行预载，零瀑布。

**思路**：构建器读 chunk 依赖图（vite/webpack manifest）→ 对每路由输出 { js, css, imports } → HTML 注入 `<link rel=modulepreload>` 与 preload；路由切换时新路由资源已并行到位。

```javascript
// 构建期插件（伪码）：路由 → 资源清单
function generatePreloadMap(manifest, routeEntries) {
  const map = {};
  for (const [route, entry] of Object.entries(routeEntries)) {
    const deps = new Set();
    (function walk(chunk) {                               // 依赖图遍历：入口 chunk + 静态 import 链
      if (!chunk || deps.has(chunk.file)) return;
      deps.add(chunk.file);
      chunk.imports?.forEach((i) => walk(manifest[i]));
    })(manifest[entry]);
    map[route] = [...deps];                               // 动态 import 不展开（保持懒加载语义）
  }
  return map;
}
// 注入 HTML（SSR 模板）：
// <link rel="modulepreload" href="/chunk-a.8f3.js"> × 每路由清单
// <link rel="preload" as="style" href="/route.css">
// 效果：跳转路由 → chunk 已在 HTTP 缓存/已解析 → 路由切换 < 50ms
// 注意：只展开静态 import（动态 import 保持懒加载——否则首屏把所有路由都拉了，预加载变预浪费）
// CSS 路由样式用 preload as=style（关键 CSS 才 preload，其余 prefetch）
```

**评分点**：
- 依赖图遍历生成每路由清单（静态 import 展开、动态保持懒加载）——本题核心。
- modulepreload vs preload as 的语义区分。
- 预加载谱系与"预浪费"的边界（只展开静态链）。
- 与 HW-088 空闲预取的配合（构建期清单 = 预取的确定性版）。
