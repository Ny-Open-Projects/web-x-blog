**场景**：组件树中部分节点配置了 `stopPropagation: true`，埋点系统要预判"根节点（window 级埋点）是否能收到来自某叶子的事件"——即沿叶子到根路径上是否有拦截节点。

**思路**：从叶子沿 parent 指针向上走，遇 stopPropagation 即被拦截；到根未遇则可达。O(depth)。也可以从树结构预计算每个节点的 "blockedAncestor" 标记（一次 DFS，之后 O(1) 查询）。

```javascript
function eventReachesRoot(node) {              // node: {id, parent, stopPropagation}
  let cur = node;
  while (cur) {
    if (cur.stopPropagation && cur !== node) return false;   // 路径上（不含自身？按业务定义）的拦截
    cur = cur.parent;
  }
  return true;
}
// 进阶：批量查询——一次 DFS 预处理 blocked 状态
function markBlocked(root) {
  const state = new Map();                     // node.id -> 到根是否有拦截（不含自身贡献）
  (function dfs(n, blockedAbove) {
    state.set(n.id, blockedAbove);
    const below = blockedAbove || n.stopPropagation;
    for (const c of n.children ?? []) dfs(c, below);
  })(root, false);
  return state;
}
// markBlocked(root).get('leafX') === false → 该叶子事件不会到根（路径上有拦截）
// 单查 O(depth)；批量预处理 O(N) 后查询 O(1)
```

**评分点**：
- 向上遍历 O(depth) 的直接解正确；"自身是否拦截"的语义边界说清。
- 批量场景的预处理思想（自顶向下传递 blocked 状态），查询 O(1)。
- 树结构的 parent/children 双向导航意识。
- 场景对应：组件树事件可达性预判（埋点/事件委托）。
