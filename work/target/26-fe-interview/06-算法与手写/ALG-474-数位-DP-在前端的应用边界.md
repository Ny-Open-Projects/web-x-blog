## ALG-474：数位 DP 在前端的应用边界：什么时候前端别做数位 DP

**答**：
- 题目：收官判断题——哪些场景该前端做数位 DP，哪些该丢给服务端？
- 要点：前端适合——交互式试算（用户输入区间实时反馈）、号段预览、校验提示（单次查询，位数短）；服务端适合——批量审计、大区间统计、规则频繁变更（服务端统一规则源）、需要持久化的计数。前端做的代价：JS 单线程阻塞风险（位数大时仍 O(位数×状态) 很快，但要防超长输入）。
- 评分点：交互实时性是前端价值；规则单一来源原则；输入防御（长度上限）。

```javascript
const digitDPBoundary = {
  frontend: [
    '交互式试算：用户输入 [a, b] 实时显示可用号数（位数 < 12，单次 < 1ms）',
    '表单校验提示：编号合法性预检',
    '号段预览：剩余可分配数量的近似展示',
  ],
  server: [
    '批量审计统计（百万日志按规则分组计数）',
    '规则频繁变更（规则源统一在服务端）',
    '超大区间 / 超长位数（防御性限制）',
  ],
  frontendGuard: (input) => {
    if (input.length > 20) throw new Error('input too long');   // 输入防御
    return input;
  },
  // 数位 DP 单次查询极快（O(位数×状态×10) ≈ 千级运算）——前端瓶颈在输入而非算法
}
```
