## WCN-867：编译响应式平台的「可观测性」：编译指标如何采集与分析？

**答**：
- 结论先行：编译平台作为基建也要有完整可观测性——采集「编译耗时、缓存命中率、产物体积、错误率、优化效果」等指标，才能回答「编译是否健康、优化是否真的生效、什么时候劣化了」。
- 核心指标：① 编译耗时（分阶段 p50/p95）；② 缓存命中率（失效是否合理）；③ 产物体积与压缩率（tree-shaking 是否有效）；④ 编译错误/警告数与类型；⑤ 优化收益（静态提升数量、消除的副作用、细粒度绑定占比）。
- 采集方式：编译器各阶段埋点输出结构化事件（JSON），本地写日志、CI 汇总上报；用 trace id 串起一次构建的全流程；与构建系统（CI/CD）集成出仪表盘。
- 分析场景：劣化检测（某次提交后编译时间突增）、回归定位（哪个 Pass 变慢）、效果验证（确认产物真的细粒度而非全量 diff）、容量规划（CI 资源需求）。
- 与运行时联动：编译指标 + 运行时性能指标（更新次数、卡顿）关联，才能验证「编译优化是否真的改善用户体验」，否则只是自嗨。
- 追问钩子：面试官会问「指标太多怎么看重点」——答：定义少量「黄金信号」——编译时长、缓存命中率、产物体积、错误率；其余按需下钻，避免指标噪音。

```javascript
// 编译指标采集：埋点 → 结构化事件 → 汇总
function instrument(compileFn) {
  return function (...args) {
    const t0 = performance.now();
    const result = compileFn(...args);
    const event = {
      type: 'compile', ts: Date.now(), duration: +(performance.now() - t0).toFixed(2),
      cacheHit: result.cacheHit ?? false, outputBytes: JSON.stringify(result.code || '').length,
      optimizations: result.optimizations || {},
    };
    (globalThis.__METRICS__ ||= []).push(event);   // 真实环境上报到监控系统
    return result;
  };
}
const compile = instrument((src) => ({ code: src, cacheHit: true, optimizations: { hoisted: 3 } }));
compile('const a=1');
console.log(globalThis.__METRICS__);
```
