## WCN-959：选型论证怎么做「可逆性设计」：组件协议怎么避免被单一框架绑架

**答**：
- 结论先行：可逆性 = 未来换框架/换技术栈时成本可控；核心手段是「把框架相关与框架无关分层」，用稳定协议隔离，避免组件 API 直接暴露框架特性。
- 协议层设计：组件对外只暴露「平台无关」的属性/事件/主题契约（字符串/对象/CustomEvent），不暴露 React hooks、Vue inject 等框架专属概念。
- 适配层薄化：框架绑定放在窄适配层（薄壳），换框架只换壳不动核心；核心组件不 import 任何框架运行时。
- 逃逸口预留：协议允许 extensionslot 或 escape hatch，遇到框架特有能力时局部绕过而不污染主协议（大促临时定制常见）。
- 追问钩子：面试官问「怎么验证可逆性」——答：做「换壳演练」——用一个新框架（或原生）实现薄壳接上现有协议，跑通核心场景即证明解耦有效。

```javascript
// 可逆性：核心不依赖框架，框架绑定放薄壳
// core/ds-button.js —— 框架无关
class DsButton extends HTMLElement {
  connectedCallback() { this.setAttribute('tabindex', '0'); } // 只用 DOM API
}
if (!customElements.get('ds-button')) customElements.define('ds-button', DsButton);
// adapters/react.js —— 薄壳，可替换
const createComponent = (opts) => ({ ...opts, __framework: 'react' });
export const ReactButton = createComponent({ tagName: 'ds-button', react: React });
// adapters/vue.js —— 另一薄壳，core 完全不动
export const VueButton = { tagName: 'ds-button', framework: 'vue' };
// 逃逸口：特殊能力通过 extension slot 局部绕过，不污染主协议
const escapeHatch = { slot: 'advanced', usedBy: ['legacy-page'] };
// 换框架时只重写 adapters/*，core 不动
function swapAdapter(core, oldShell, newShell) {
  return { core, shell: newShell, dropped: oldShell.__framework };
}
// 验证：用 Vue 薄壳接同一 ds-button，跑同样用例
console.log(swapAdapter(DsButton, ReactButton, VueButton));
```
