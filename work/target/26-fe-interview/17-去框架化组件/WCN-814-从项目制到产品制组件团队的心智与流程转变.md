## WCN-814：组件团队从「项目制」转到「产品制」，心智与流程要怎么变？

**答**：
- 结论先行：项目制交付完就结束，产品制要「持续经营」——核心变化是从「按需求排期写代码」转为「对业务结果负责、自己发现并解决问题」。
- 心智变化：从「业务方提什么做什么」到「理解业务目标后主动定义组件路线图」；从「上线即完成」到「上线只是开始，要盯采纳率、满意度、事故」。
- 流程变化：引入产品化三件套——路线图（Roadmap）、需求池（Backlog，按价值排序）、版本节奏（定期发布 + 变更日志）；每个组件有 owner，像 mini-PM 一样经营。
- 能力变化：团队要补「产品感」（懂业务场景、会数据分析）、「运营感」（文档、布道、支持）、「经营感」（成本、SLA、弃用策略）。
- 组织信号：考核指标从「交付了多少组件」变为「平台采纳率/NPS/事故率」，这是产品制真正落地的标志。
- 追问钩子：面试官会问「团队习惯了接需求，怎么过渡」——答：设过渡期双轨——保留少量需求响应，同时给每个成员分配「组件产品线」操作空间，用有限授权培养主人翁意识。

```javascript
// 项目制 vs 产品制的工作重心对比（用于团队共识宣导）
const MODEL = {
  project: { driver: '需求排期', success: '按时上线', owner: '临时', afterLaunch: '交接走人' },
  product: { driver: '路线图+数据', success: '采纳率/NPS', owner: '长期 owner', afterLaunch: '持续运营迭代' },
};
function diff(mode) {
  const m = MODEL[mode];
  return `驱动:${m.driver}｜成功标准:${m.success}｜归属:${m.owner}｜上线后:${m.afterLaunch}`;
}
console.log('项目制 →', diff('project'));
console.log('产品制 →', diff('product'));
```
