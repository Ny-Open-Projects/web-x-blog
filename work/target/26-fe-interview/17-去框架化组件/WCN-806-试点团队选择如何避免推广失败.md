## WCN-806：试点团队选择有什么讲究？怎么避免「试点成功但推广失败」？

**答**：
- 结论先行：试点要选「有代表性但不极端」的团队——太简单的场景证明不了价值，太复杂的场景会被工程细节拖死；关键是试点结论要能「被复制」。
- 选团队三要素：业务有一定复杂度（能暴露真实问题）、团队有意愿且技术能力中上（能配合共创）、场景能代表主流用法（别选独角兽页面）。
- 试点成功 ≠ 可推广：很多试点靠平台团队「贴身支持」才成功，推广时没有这种资源就崩——所以试点期就要把「支持成本」记下来，并要求沉淀成文档/脚手架。
- 推广前置条件：可复制的接入脚手架、自动化门禁、明确的 owner 与 SLA、成功案例的量化数据（省了多少工时）。
- 追问钩子：面试官会问「如果试点团队本身就抵触怎么办」——答：换团队，或者先用「非侵入式」场景（如新页面）证明价值，别在存量核心页面硬推。

```javascript
// 试点团队筛选评分：代表性 × 意愿 × 复杂度适配，并计入贴身支持成本
function pickPilot({ representativeness, willingness, complexity, supportCost }) {
  // complexity 过高（>4）会拖垮试点，过低（<2）证明不了价值 → 用 2~4 的最佳区间
  const fit = 1 - Math.abs(complexity - 3) / 3;
  const score = representativeness * 2 + willingness * 2 + fit * 2 - supportCost;
  return { score: +score.toFixed(2), recommend: score >= 8 && supportCost <= 2 };
}
const teams = [
  { name: '订单中台', representativeness: 5, willingness: 4, complexity: 3, supportCost: 2 },
  { name: '前沿实验', representativeness: 1, willingness: 5, complexity: 5, supportCost: 5 },
];
for (const t of teams) console.log(t.name, pickPilot(t));
```
