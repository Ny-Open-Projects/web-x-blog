## WCN-802：大组织里组件平台的「联邦式治理」和「集中式治理」怎么取舍？

**答**：
- 结论先行：没有纯集中或纯联邦，成熟组织是「集中定标准 + 联邦做实现」的混合制——集中管契约、token、门禁，联邦管业务专属组件与迭代节奏。
- 集中式适合强品牌一致性、合规严格的场景（如金融），好处是体验统一、治理成本低，坏处是成为瓶颈、业务方觉得「慢」。
- 联邦式适合多 BU、多品牌、迭代速度差异大的场景，好处是自治与速度，坏处是容易碎片化、重复造轮子。
- 落地做法：核心组件（按钮/输入/布局）集中团队维护，业务域组件（订单卡片、风控面板）由各域贡献但必须通过统一契约与 a11y/a11y 门禁审查。
- 追问钩子：面试官会追问「怎么防止联邦演进成失控」——答案是设「守门人（guardrails）」：自动化契约校验 + 贡献度看板 + 定期治理审计，自治但不脱管。

```javascript
// 治理模式决策：按品牌一致性要求与组织自治度打分
function chooseGovernance({ brandStrictness, buCount, compliance, speedNeed }) {
  let central = brandStrictness * 2 + compliance * 2;   // 集中倾向
  let federal = buCount + speedNeed;                     // 联邦倾向
  if (central > federal) {
    return '集中式为主：核心组件统一团队维护，业务方按流程提需求';
  }
  if (federal > central) {
    return '联邦式为主：集中管契约/token/门禁，业务域自治实现';
  }
  return '混合制：核心集中 + 业务联邦（最常见）';
}
console.log(chooseGovernance({ brandStrictness: 5, buCount: 3, compliance: 5, speedNeed: 2 }));
// → 集中式为主
console.log(chooseGovernance({ brandStrictness: 2, buCount: 8, compliance: 1, speedNeed: 5 }));
// → 联邦式为主
```
