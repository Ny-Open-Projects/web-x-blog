## WCN-811：采购 vs 自建 vs 开源组件库，企业决策矩阵怎么建？

**答**：
- 结论先行：决策不是比较「哪个技术好」，而是比较「总成本、可控性、差异化价值、风险」四维度——先划红线（如数据合规、品牌强定制）排除选项，再打分。
- 采购（商业组件）：上手快、有供应商支持，但长期授权贵、定制受限、有 vendor lock-in；适合非核心、通用、合规要求高的后台系统。
- 自建：完全可控、贴合业务与品牌、无授权费，但前期投入大、需要持续维护团队；适合核心链路、强品牌、长期战略场景（去框架化 WC 通常属此类）。
- 开源：零授权、社区生态，但需自行承担维护与安全风险，License 合规要审；适合通用能力、有社区维护的基础组件。
- 打分做法：对四个维度按业务实际加权，>=某阈值才选对应方案；并做 3 年 TCO（总拥有成本）测算，而非只看首年报价。
- 追问钩子：面试官会问「什么情况下自建也不够」——答：当组件是核心竞争力且需要跨端（Web/App/小程序）统一，就要上升到「平台化自建 + 长期投入」，把它当产品而非项目。

```javascript
// 决策矩阵：先红线否决，再加权打分
function decide({ complianceRedLine, brandCritical, coreBusiness, budget, teamReady }) {
  if (complianceRedLine) return '排除多数商业/开源方案 → 倾向自建（数据不出域）';
  const score = {
    buy:   2 + (budget ? 2 : 0) - (brandCritical ? 2 : 0) - (coreBusiness ? 2 : 0),
    build: (coreBusiness ? 3 : 0) + (brandCritical ? 3 : 0) + (teamReady ? 2 : 0) - (budget ? 0 : 2),
    oss:   2 + (teamReady ? 1 : 0) - (coreBusiness ? 1 : 0),
  };
  const best = Object.entries(score).sort((a, b) => b[1] - a[1])[0];
  return `推荐 ${best[0]}（得分 ${best[1]}），3年 TCO 需另行测算`;
}
console.log(decide({ complianceRedLine: false, brandCritical: true, coreBusiness: true, budget: true, teamReady: true }));
```
