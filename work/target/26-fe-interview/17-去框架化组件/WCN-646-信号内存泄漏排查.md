## WCN-646：Signal 体系里常见的内存泄漏有哪些？如何系统性排查？

**答**：
- 结论：三类泄漏——effect 未在元素卸载时 dispose、被闭包长期持有的大对象 signal、全局注册表强引用已卸载节点。
- 做法：用 WeakMap/WeakSet 管理注册表；DevTools 堆快照对比挂载前后；给 effect 打标统计存活数；组件卸载钩子统一 dispose。
- 追问钩子：为什么 WeakMap 不是万能的？如果 value 反向强引用 key（如 signal 持有 DOM），仍会泄漏——考察对弱引用边界的理解。

```javascript
// 反例：全局 Map 强引用已卸载元素 → 泄漏
// const registry = new Map(); registry.set(el, effect);
// 正例：WeakMap + 统一 dispose
const registry = new WeakMap();
function bind(el, sig, apply) {
  const dispose = effect(() => apply(sig.get()));
  registry.set(el, dispose);
  return dispose;
}
function unbind(el) {
  registry.get(el)?.();
  registry.delete(el);
}
// 排查：统计存活 effect（dev 模式）
const live = new Set();
function trackedEffect(fn) {
  const d = effect(fn); live.add(d);
  return () => { d(); live.delete(d); };
}
console.log('当前存活 effect 数:', live.size);
```
