## WCN-808：用「绞杀者模式」迁移一个核心交易页面，如何分阶段切流？

**答**：
- 结论先行：绞杀者模式的要义是「渐进替换、随时可退」——在老页面外设一层路由/组件拦截，把流量逐步从 React 组件切到 WC 组件，每个阶段都能秒级回滚。
- 阶段划分：① 影子运行（WC 渲染但不接管交互，比对 DOM/数据一致性）；② 1% 灰度切流（只看错误率、性能、转化）；③ 按用户/地域放大到 10%→50%；④ 全量并下线老代码。
- 关键护栏：功能开关（feature flag）控制切换，灰度期间双跑并做数据对账，任何核心指标（下单成功率、错误率）劣化立即自动回滚。
- 边界处理：表单状态在切换时不能丢、埋点口径要一致、老新组件并存时的样式与 store 隔离要验证。
- 追问钩子：面试官会问「双跑期间用户看到的是哪个」——答：影子期用户只看到老组件、WC 在隐藏容器里渲染做比对；灰度期才真正接管，通过 flag 原子切换，用户无感知。

```javascript
// 绞杀者切流控制器：flag + 指标守卫 + 自动回滚
class Strangler {
  constructor() { this.stage = 'shadow'; this.metrics = { errOld: 0, errNew: 0, orders: 0 }; }
  resolveComponent(flag) {
    switch (this.stage) {
      case 'shadow':  return 'legacy-react';        // WC 影子渲染仅比对
      case 'canary':  return flag % 100 < 1 ? 'wc-new' : 'legacy-react';
      case 'ramp':    return flag % 100 < 50 ? 'wc-new' : 'legacy-react';
      case 'full':    return 'wc-new';
    }
  }
  guard(metric, delta) {
    this.metrics[metric] += delta;
    // 新组件错误率明显高于老组件 → 自动回退到 shadow
    if (this.stage !== 'shadow' && this.metrics.errNew > this.metrics.errOld + 5) {
      this.stage = 'shadow';
      console.warn('指标劣化，已自动回滚到 legacy');
    }
  }
  promote(next) { this.stage = next; }
}
```
