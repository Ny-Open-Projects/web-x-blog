## WCN-825：笔试：手写「组件平台健康预警打分器」（五维信号 → 风险等级）

**题目**：输入平台的五项指标 `{ adoption, quality, satisfaction, busFactor, costTrend }`，每项为 0~100 分（越高越好，其中 `costTrend` 越高代表成本越可控）。要求：① 计算加权总分，权重为 adoption 0.25、quality 0.25、satisfaction 0.2、busFactor 0.15、costTrend 0.15；② 任一项低于 40 分视为「单项红灯」，红灯数 ≥2 时总分强制不超过 59（封顶），防止单项掩盖危机；③ 输出风险等级：≥80 健康、60~79 关注、40~59 预警、<40 危险；④ 返回 `{ total, level, redFlags }`。边界：某项缺失按 0 分处理；分值越界截断到 0~100。

**答**：

```javascript
const WEIGHTS = { adoption: .25, quality: .25, satisfaction: .2, busFactor: .15, costTrend: .15 };

function platformHealth(input = {}) {
  const clamp = v => Math.max(0, Math.min(100, Number(v) || 0));
  let total = 0;
  const redFlags = [];
  for (const [k, w] of Object.entries(WEIGHTS)) {
    const v = clamp(input[k]);                     // 缺失→0，越界截断
    total += v * w;
    if (v < 40) redFlags.push(k);
  }
  total = Math.round(total);
  if (redFlags.length >= 2) total = Math.min(total, 59); // 多项红灯封顶
  const level = total >= 80 ? '健康' : total >= 60 ? '关注' : total >= 40 ? '预警' : '危险';
  return { total, level, redFlags };
}

console.log(platformHealth({ adoption: 90, quality: 85, satisfaction: 80, busFactor: 30, costTrend: 20 }));
// 两项红灯 → 总分封顶 59 → 预警，避免被高分项掩盖
console.log(platformHealth({ adoption: 50, quality: 50, satisfaction: 50, busFactor: 50, costTrend: 50 }));
```

**评分点**：
- 加权求和用 WEIGHTS 表驱动，便于调整，避免硬编码散落（可维护性）。
- 缺失按 0、越界 clamp 到 0~100，防御脏输入（边界处理）。
- 多项红灯强制封顶，体现「短板效应」而非简单平均（业务理解深度）。
- 风险等级分层清晰，输出含 redFlags 便于定位问题（可用性）。
