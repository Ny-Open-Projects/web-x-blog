## WCN-605：同一标签需按业务方声明路由到不同大版本实现，如何实现运行时版本选择器？

**答**：
- 结论：在 connectedCallback 读取 version 声明（属性或最近上下文），动态替换内部渲染实现，而非注册多个全局标签。
- 实现：用策略表 version→render 函数；版本未命中时降级到默认版本并上报，避免页面白屏。
- 追问钩子：版本切换时已绑定事件怎么办？需要 dispose 旧副作用再挂载新实现——引出生命周期清理的必要性。

```javascript
const STRATEGIES = {
  '2.x': (el) => { el.textContent = '[legacy] button'; },
  '3.x': (el) => { el.textContent = '[new] button'; },
};
class VersionRouter extends HTMLElement {
  connectedCallback() {
    const want = this.getAttribute('version') || '3.x';
    const render = STRATEGIES[want] || STRATEGIES['3.x'];
    if (!STRATEGIES[want]) reportFallback(this.tagName, want);
    render(this);
  }
}
customElements.define('ds-smart-button', VersionRouter);
function reportFallback(tag, v) {
  console.warn(`[version] ${tag} 未命中 ${v}，降级默认版本`);
}
// <ds-smart-button version="2.x"> 使用旧渲染
```
