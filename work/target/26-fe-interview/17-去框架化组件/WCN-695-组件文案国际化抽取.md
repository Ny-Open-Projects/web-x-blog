## WCN-695：设计系统组件里的硬编码文案如何抽取为 i18n 资源？

**答**：
- 结论：组件内部文本走 i18n key（t('ds.button.submit')），默认值放组件包内的 locales；业务可覆盖；构建期抽取未国际化的硬编码文案并告警。
- 做法：用 AST 扫描 JSX/模板中的中文字面量；提供 t() 函数与 locale 上下文；抽取工具生成待翻译 JSON。
- 追问钩子：如何处理动态拼接文案？用 {placeholder} 插值而非字符串拼接——考察对「翻译友好写法」的经验。

```javascript
function extractHardcoded(source) {
  const re = /[\u4e00-\u9fa5]+/g;
  return [...new Set(source.match(re) || [])];
}
// 反例：硬编码
const bad = '<button>提交订单</button>';
// 正例：i18n key + 插值
const good = `t('ds.button.submit')`;
console.log(extractHardcoded(bad)); // ['提交订单'] → 需抽取
const messages = { 'ds.button.submit': '提交订单' };
function t(key, vars = {}) {
  return (messages[key] || key).replace(/\{(\w+)\}/g, (_, k) => vars[k] ?? '');
}
console.log(t('ds.button.submit'));
```
