## WCN-671：编译型框架「运行时小、编译产物大」的现象如何权衡？体积如何度量才公平？

**答**：
- 结论：要区分「框架运行时体积」与「业务编译产物体积」——Svelte 运行时小但每个组件编译出独立代码，组件越多总产物可能反超 VDOM 框架。
- 度量：按真实业务场景（组件数量/复用度）测总 gzip；用 bundle analyzer 看重复代码；关注「边际成本」（新增一个组件的体积增量）。
- 追问钩子：为什么微基准不公平？因为它忽略组件复用——考察对「真实场景度量」的坚持。

```javascript
function estimateBundle(framework, components) {
  const runtime = { svelte: 2, react: 45, vue: 35 }[framework]; // KB gzip
  const perComponent = { svelte: 1.2, react: 0.3, vue: 0.4 }[framework];
  return runtime + perComponent * components;
}
[10, 100, 500].forEach(n => {
  console.log(n, '个组件:',
    'svelte', estimateBundle('svelte', n),
    'react', estimateBundle('react', n));
});
// 组件少时 svelte 优；组件极多时 react 运行时被摊薄，可能反超
```
