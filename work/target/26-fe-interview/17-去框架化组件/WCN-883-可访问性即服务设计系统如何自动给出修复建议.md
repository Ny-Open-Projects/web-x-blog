## WCN-883：「可访问性即服务」：设计系统如何自动给出修复建议？

**答**：
- 结论先行：a11y 不该只是「发布前的一道检查」，而要变成「设计系统持续提供的能力」——把检测、诊断、修复建议做成服务和工具链，让业务方随时能得到「哪里不合规、怎么改」的具体指导。
- 检测层：静态扫描（jsx/模板里的 aria 缺失、无键盘事件、裸值颜色对比度）+ 运行时审计（axe-core 扫描 DOM，含 Shadow DOM 穿透）+ 视觉回归（焦点态快照）；集成进 CI 与本地开发。
- 诊断层：不只报「缺 aria-label」，而是解释「为什么需要、违反哪条 WCAG、影响哪些用户」——让开发者理解而非机械修补。
- 修复建议层：提供可复制的修复代码、自动 codemod（如自动补 alt/aria）、组件层面给「安全默认值」（组件默认就带正确 role/键盘支持），从源头减少问题。
- 服务化：提供 a11y 看板（按团队/组件的合规趋势）、咨询渠道、组件 a11y 契约文档；把 a11y 变成平台的「自助服务能力」而非靠专家人肉 review。
- 追问钩子：面试官会问「Shadow DOM 里 axe 扫不到怎么办」——答：用 axe-core 的 `include` 配置或递归遍历 shadowRoot 注入检测；更根本的是组件本身在影子树内就做对 a11y，并通过 ElementInternals 暴露可访问状态给外部审计工具。

```javascript
// a11y 自动诊断 + 修复建议（示意）
function auditA11y(el) {
  const issues = [];
  if (!el.hasAttribute('aria-label') && !el.textContent.trim()) {
    issues.push({ code: 'aria-label-missing', wcag: '4.1.2',
      why: '屏幕阅读器无法识别该控件', fix: "添加 aria-label='描述'" });
  }
  const tabIndex = el.getAttribute('tabindex');
  if (el.tagName === 'DIV' && tabIndex === null && el.onclick) {
    issues.push({ code: 'no-keyboard', wcag: '2.1.1',
      why: '键盘用户无法触发点击', fix: "使用 <button> 或添加 tabindex='0' + keydown" });
  }
  return issues;
}
console.log(auditA11y(Object.assign(document.createElement('div'), { onclick: () => {} })));
```
