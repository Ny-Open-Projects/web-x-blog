## WCN-878：设计系统的「主题市场」：允许第三方主题如何做隔离与治理？

**答**：
- 结论先行：开放第三方主题的前提是「主题只能改 token，不能改组件行为」——用 schema 约束 + 沙箱加载 + 审核门禁，让主题市场既繁荣又不破坏平台一致性。
- 能力边界：明确定义「可主题化清单」（颜色/字体/间距/圆角等 token），第三方只能提供这些 token 的值；禁止注入自定义 CSS 改组件内部结构、禁止 JS 逻辑、禁止覆盖 a11y 相关样式（焦点环、对比度）。
- 技术隔离：主题以数据（token JSON）形式分发而非任意 CSS/JS——加载时按 schema 校验，只生成 CSS 变量注入；用 CSP/沙箱防止注入；版本化避免污染全局。
- 治理机制：主题上架审核（对比度检测、视觉快照、安全检查）、评分与评论、下线机制；官方提供主题脚手架与校验器降低门槛。
- 与 WCN 结合：主题 token 通过 CSS 自定义属性穿透 Shadow DOM；用 `adoptedStyleSheets` 按主题动态切换，保证多主题共存切换不闪烁。
- 追问钩子：面试官会问「第三方主题把对比度做得很低怎么办」——答：schema 校验阶段强制 a11y 门槛（如文本/背景对比度 ≥4.5:1），不达标不予上架；运行时也可做兜底校正，但主要靠上架门禁。

```javascript
// 主题市场校验器：只允许白名单 token + a11y 对比度门槛
const ALLOWED = new Set(['--color-primary', '--color-bg', '--color-text', '--radius']);
function contrast(fg, bg) { // 简化：相对亮度对比（真实需按 WCAG 公式）
  const lum = (hex) => parseInt(hex.slice(1), 16) / 0xffffff;
  const [l1, l2] = [lum(fg), lum(bg)].sort((a, b) => b - a);
  return (l1 + 0.05) / (l2 + 0.05);
}
function validateTheme(tokens) {
  const errors = [];
  for (const k of Object.keys(tokens)) if (!ALLOWED.has(k)) errors.push(`禁止的 token: ${k}`);
  const ratio = contrast(tokens['--color-text'] || '#000', tokens['--color-bg'] || '#fff');
  if (ratio < 4.5) errors.push(`对比度不足 ${ratio.toFixed(2)}:1`);
  return { valid: errors.length === 0, errors };
}
console.log(validateTheme({ '--color-primary': '#06c', '--color-text': '#ccc', '--color-bg': '#fff' }));
```
