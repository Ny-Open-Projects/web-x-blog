## WCN-505：跨应用元素注册的「单例仲裁 + 版本协商」加载器应如何设计？

**答**：
- 结论：加载器维护全局 tag→版本→Promise 表，define 只执行一次，重复请求复用同一 Promise。
- 多版本请求时按宿主声明的 semver 区间仲裁，返回兼容的最高版本。
- 处理竞态：多个子应用同时 require 同一 tag，必须合并为一次脚本加载。
- 追问：如何暴露「当前已注册版本」给监控做盘点？

```javascript
const registry = new Map();  // tag -> { version, promise }
function load(tag, version, url) {
  const cur = registry.get(tag);
  if (cur) {
    if (cur.version === version) return cur.promise;      // 完全复用
    if (compatible(cur.version, version)) return cur.promise; // 兼容提升
    console.warn(`tag ${tag} 版本冲突: ${cur.version} vs ${version}`);
    return cur.promise;
  }
  const p = import(url).then(m => {
    if (!customElements.get(tag)) customElements.define(tag, m.default);
    return m.default;
  });
  registry.set(tag, { version, promise: p });
  return p;
}
function compatible(a, b) { return a.split('.')[0] === b.split('.')[0]; }
function inventory() { return [...registry].map(([t, v]) => `${t}@${v.version}`); }
```
