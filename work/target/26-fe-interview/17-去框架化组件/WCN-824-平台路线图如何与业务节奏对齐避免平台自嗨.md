## WCN-824：平台路线图如何与业务节奏对齐，避免「平台自嗨」？

**答**：
- 结论先行：平台路线图不能闭门造车——必须「自下而上收需求 + 自上而下定方向」，用业务价值排序，每季度校准一次。
- 需求来源分层：业务方痛点（最高优先，来自 NPS/工单/访谈）、平台基建（稳定性/性能，长期必要）、技术趋势（如新平台 API，适度预研但不追新）——按 5:3:2 之类的比例分配人力。
- 对齐机制：季度路线图评审邀请业务方代表参加；重大特性先找「种子业务」验证价值再推广；路线图公开透明，让业务方能提反馈与优先级投票。
- 防止自嗨的检验：每个平台特性都要能回答「解决哪个业务的哪个痛点、预计多少收益」，无法回答的要么砍掉要么降级为预研。
- 留白应对变化：路线图不是合同，预留 20% 机动人力承接突发业务战略调整（如新业务线上线）。
- 追问钩子：面试官会问「业务方要的和平台判断冲突怎么办」——答：用数据与战略对齐度做裁决，并解释平台的技术约束（如某个急需求会破坏契约），必要时提供临时方案而非硬塞进平台。

```javascript
// 路线图优先级排序：价值 × 紧迫度 × 战略对齐，防自嗨
function prioritize(items) {
  return items.map(i => {
    const score = i.businessValue * 2 + i.urgency + i.strategicFit * 2;
    return { ...i, score, justified: !!i.businessPain }; // 无业务痛点 = 可疑
  }).sort((a, b) => b.score - a.score);
}
console.log(prioritize([
  { name: '表格虚拟滚动', businessValue: 5, urgency: 4, strategicFit: 4, businessPain: '大列表卡顿' },
  { name: '追新实验特性', businessValue: 1, urgency: 1, strategicFit: 1, businessPain: '' },
]).map(i => `${i.name}: ${i.score} ${i.justified ? '' : '(自嗨嫌疑)'}`));
```
