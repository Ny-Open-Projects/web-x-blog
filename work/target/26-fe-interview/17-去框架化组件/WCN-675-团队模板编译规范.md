## WCN-675：为团队制定模板编译规范时，你会约束哪些「可编译性」红线？

**答**：
- 结论：红线包括——禁止运行时拼接模板字符串（破坏静态分析）、禁止在模板写复杂语句（保持表达式纯净）、动态 class/style 用约定写法以便 patchFlag 生效。
- 补充：模板与逻辑分离、指令使用受限白名单、复杂的动态逻辑抽成 computed 而非内联表达式。
- 追问钩子：如何自动检查这些红线？用编译期 lint 插件与 CI 门禁——考察「规范→工具化」的落地能力。

```javascript
const LINT_RULES = {
  noRuntimeTemplate: {
    test: (src) => /innerHTML\s*=|new Function/.test(src),
    msg: '禁止运行时拼接模板（破坏静态分析与安全）',
  },
  pureExprOnly: {
    test: (expr) => /;|while\s*\(|for\s*\(/.test(expr),
    msg: '模板表达式应为纯表达式（无语句）',
  },
  dynamicClassPattern: {
    test: (attr) => /^\{.*\}$/.test(attr) || /^:class/.test(attr),
    msg: '动态 class 应使用约定绑定写法',
  },
};
function lint(src) {
  return Object.entries(LINT_RULES)
    .filter(([, r]) => r.test(src)).map(([k, r]) => ({ rule: k, msg: r.msg }));
}
console.log(lint('el.innerHTML = html')); // 命中 noRuntimeTemplate
```
