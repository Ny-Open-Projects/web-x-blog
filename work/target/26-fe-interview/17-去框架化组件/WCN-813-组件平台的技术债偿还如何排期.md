## WCN-813：组件平台的「技术债」如何识别、量化并排期偿还？

**答**：
- 结论先行：技术债不是「想起来就还」，而要像财务债务一样「登记本金、计算利息、按 ROI 排期」——不还的债要付利息（维护成本、事故风险），这才是让管理层买单的语言。
- 识别来源：CI 告警（裸值/a11y 不达标）、已知兼容层（旧 API/旧框架包装）、重复组件、过时依赖、缺失文档与测试的组件。
- 量化：给每笔债估算「本金」（偿还工作量）与「利息」（每月因它多花的维护/排障工时 + 事故概率 × 影响）；利息高的优先还。
- 排期：用固定比例（如每迭代 20% 人力）持续还债，重大债务单独立项；新功能开发时遵循「副作用原则」——碰到债顺手还，不制造新债。
- 追问钩子：面试官会问「和业务抢资源时怎么说」——答：把利息换算成人力成本与线上风险，对比还债与不换债的 3 年总成本，用数据而非「代码不优雅」来说服。

```javascript
// 技术债看板：按利息（月成本）降序排期
const debts = [
  { id: 'legacy-wrapper', principal: 10, monthlyInterest: 4, risk: 0.3 },
  { id: 'bare-values',    principal: 5,  monthlyInterest: 1, risk: 0.1 },
  { id: 'old-token',      principal: 15, monthlyInterest: 6, risk: 0.5 },
];
function prioritize(list, horizon = 12) {
  return list
    .map(d => ({ ...d, cost12m: d.monthlyInterest * horizon + d.risk * d.monthlyInterest * horizon, roi: (d.monthlyInterest * horizon) / d.principal }))
    .sort((a, b) => b.cost12m - a.cost12m);
}
console.log(prioritize(debts).map(d => `${d.id}: 12月成本${d.cost12m}`));
```
