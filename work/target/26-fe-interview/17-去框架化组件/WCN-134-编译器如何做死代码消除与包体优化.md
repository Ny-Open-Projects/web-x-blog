## WCN-134：编译器如何做死代码消除与包体优化？

**答**：
- 模板编译的本质收益：运行时只需要"被模板实际用到的 helper"——编译器知道模板用了 v-if/v-for/transition 中哪些，按需 tree-shake runtime helper（Vue 编译器的 `ssrRenderHelpers`/Svelte 的按需 runtime 导入）。
- 静态内容完全消失：静态子树编译为 HTML 字符串常量（不需要 JS 对象表示）；Svelte 编译产物无"组件运行时"概念，只有实例化函数。
- 死代码消除层次：① 模板层（未用指令不生成代码）；② 组件层（scope hoisting + rollup tree-shaking）；③ 运行时层（helper 按需导入，ESM 具名导出是前提）。
- 对比数字口径：简单组件下 Svelte ~2KB、Vue Vapor ~（runtime 按需 ~10KB 级共享）、React+编译器（runtime ~40KB 共享）——共享运行时被多组件摊薄时差异缩小。
- 权衡：编译产物失去源码可读性，调试依赖 sourcemap；运行时升级不能覆盖已编译产物（需重编译，框架版本锁定）。

```javascript
// 编译器按需 helper 示意（Svelte 产物只 import 用到的）
// 模板用了 v-if 与事件：
import { mount, if_block, event } from 'svelte/internal/client';
// 未用 transition/store → 这两个模块根本不出现在产物里（天然 DCE）
```
