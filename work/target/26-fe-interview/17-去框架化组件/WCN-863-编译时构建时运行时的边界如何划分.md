## WCN-863：「编译时 / 构建时 / 运行时」的边界如何划分？

**答**：
- 结论先行：三者按「信息何时可得」划分——编译时做「与输入无关的静态变换」，构建时做「依赖整个项目/环境的决策」，运行时做「依赖用户数据与交互的动态行为」；把能提前做的尽量前移以省运行时开销。
- 编译时（单文件/单组件级）：语法解析、静态提升、模板编译、依赖标记、常量折叠——信息只来自当前源码，结果可缓存复用。
- 构建时（项目/部署级）：依赖解析、tree-shaking、代码分割、环境变量注入、产物哈希、target 兼容——需要全局依赖图与部署配置。
- 运行时（用户/浏览器级）：响应式更新、事件处理、数据请求、条件渲染的实际分支、水合——依赖只有运行时才有的数据。
- 边界的模糊地带：SSR 把部分渲染前移到「服务端的运行时」（仍是运行时，但在服务器）；AOT 把依赖注入前移到编译期；环境变量在构建时注入而非运行时读取——这些都是「前移」的优化。
- 追问钩子：面试官会问「为什么不能全放编译时」——答：编译时拿不到用户数据与环境差异，强行前移会导致产物爆炸（为所有分支生成代码）或失去动态能力；边界是「信息可得性」与「产物体积」的权衡。

```javascript
// 三阶段分工示意：同一特性在不同阶段的处理
const feature = {
  compile: (componentSource) => {
    // 编译时：静态模板 → 更新函数，标记响应式插值
    return { code: 'bindText(()=>count)', reactiveDeps: ['count'] };
  },
  build: (modules, env) => {
    // 构建时：依赖图 tree-shaking + 环境变量注入
    return { bundle: modules.filter(m => m.used), apiBase: env.API_BASE };
  },
  runtime: (bundle, userData) => {
    // 运行时：真实数据驱动的更新
    return bundle.reactiveDeps.map(d => `更新 ${d}=${userData[d]}`);
  },
};
const c = feature.compile('<span>{{count}}</span>');
const b = feature.build([{ used: true }], { API_BASE: '/api' });
console.log(c, b, feature.runtime(c, { count: 7 }));
```
