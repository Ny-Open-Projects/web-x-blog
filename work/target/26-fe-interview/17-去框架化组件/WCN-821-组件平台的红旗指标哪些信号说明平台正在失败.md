## WCN-821：组件平台的「红旗指标」：哪些信号说明平台正在走向失败？

**答**：
- 结论先行：平台失败很少是突然崩溃，而是慢性失血——要靠一组「领先指标」提前发现，而不是等采纳率崩了才行动。
- 采纳侧红旗：新页面组件覆盖率停滞或下降、业务方开始自研同类组件、平台组件被包装器层层绕过——说明价值主张失效。
- 质量侧红旗：a11y/契约达标率下滑、线上组件事故增多、文档新鲜度下降、bug 修复周期变长——说明平台在透支信誉。
- 组织侧红旗：owner 离职后无人接手（bus factor=1）、路线图长期不更新、NPS 持续走低、平台团队被抽调去做业务——说明投入在撤退。
- 成本侧红旗：单位维护成本上升、长尾组件无人维护、CI 时长失控——说明复杂度在吞噬收益。
- 追问钩子：面试官会问「发现红旗后第一步做什么」——答：先定位是「价值问题」（没人用）还是「能力问题」（用不好）——前者重做价值主张与布道，后者补质量与治理，不要一上来就加功能。

```javascript
// 平台健康预警：任一红灯项触发就要介入
const RED_FLAGS = {
  adoptionFlat:  '连续2季度采纳率不涨',
  shadowRebuild: '业务方自研同类组件数上升',
  busFactorOne:  '核心模块仅1人懂',
  docStale:      '文档新鲜度<70%',
  npsDropping:   'NPS连续两期下降',
};
function check(signals) {
  const fired = Object.keys(RED_FLAGS).filter(k => signals[k]);
  return fired.length ? `预警: ${fired.map(k => RED_FLAGS[k]).join('; ')}` : '健康';
}
console.log(check({ adoptionFlat: true, busFactorOne: true }));
```
