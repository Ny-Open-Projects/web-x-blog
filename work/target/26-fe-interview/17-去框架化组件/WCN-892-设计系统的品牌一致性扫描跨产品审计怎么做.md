## WCN-892：设计系统的「品牌一致性扫描」：跨产品审计怎么做？

**答**：
- 结论先行：品牌一致性扫描要「把品牌规范做成可执行的检查」——自动爬取/接入各产品页面，比对 token 使用与视觉呈现，输出「哪里偏离了品牌规范」的审计报告。
- 扫描维度：① token 合规——页面里是否用了规范的 token（颜色/字体/间距），有无裸值；② 视觉呈现——关键元素（按钮/标题/主色）是否与品牌基线一致（截图 + 视觉比对）；③ 组件版本——是否用了弃用版本；④ 交互一致性——同类交互（如弹窗关闭方式）是否统一。
- 实现方式：静态扫描代码（token/裸值/组件引用）+ 运行时采集（真实页面的计算样式与 DOM）+ 视觉快照比对（关键页面关键元素）；做成定期任务（周/月扫描）与 PR 门禁两层。
- 输出与闭环：按产品/团队出「一致性得分」与具体问题清单，自动建 issue；得分纳入团队健康度；对偏离提供修复建议与 codemod。
- 边界：不是 100% 统一才叫一致——要区分「品牌核心元素」（Logo、主色、字体必须严格）与「可灵活区域」（运营活动页可适度定制）；规则要分级，避免误伤合理创新。
- 追问钩子：面试官会问「运营页想做个特殊风格怎么办」——答：品牌规范分级——核心不可动，运营场景提供「受控的定制 token 子集」或在沙箱内允许例外，并标注为「非标准品牌露出」，既不一刀切也不放任。

```javascript
// 品牌一致性扫描：token 合规 + 裸值检测，输出一致性得分
const BRAND_TOKENS = new Set(['--color-primary', '--font-brand', '--spacing-unit']);
function brandAudit(pages) {
  return pages.map(p => {
    const used = p.tokens || [];
    const bare = (p.rawValues || []).filter(v => /^#|^rgb/.test(v)); // 疑似裸色值
    const offBrand = used.filter(t => !BRAND_TOKENS.has(t));
    const score = Math.max(0, 100 - bare.length * 5 - offBrand.length * 3);
    return { page: p.name, score, bare, offBrand };
  });
}
console.log(brandAudit([
  { name: '首页', tokens: ['--color-primary', '--font-brand'], rawValues: ['#f00'] },
  { name: '活动页', tokens: ['--color-primary', '--custom-x'], rawValues: [] },
]));
```
