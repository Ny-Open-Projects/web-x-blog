## WCN-693：设计系统如何把无障碍（A11Y）做成基线能力而非事后补救？

**答**：
- 结论：A11Y 左移——组件开发阶段就内置语义（role/aria/键盘导航/焦点管理），用自动化 axe 扫描 + 人工读屏双重门禁。
- 做法：组件模板内置 ARIA 与 tabindex；dev 模式自动审计（contrast/aria）；文档标注键盘操作；发版前 axe + VoiceOver 实测。
- 追问钩子：为什么自动化不够？因为 axe 只能查约 30-40% 问题，焦点顺序与语义正确性需人工——考察对「自动化边界」的认知。

```javascript
const A11Y_CHECKS = {
  hasRole: (el) => !!el.getAttribute('role'),
  hasLabel: (el) => !!(el.getAttribute('aria-label') || el.textContent.trim()),
  keyboardFocusable: (el) => el.tabIndex >= 0,
  contrastOk: (fg, bg) => contrastRatio(fg, bg) >= 4.5,
};
function audit(el) {
  return Object.entries(A11Y_CHECKS)
    .filter(([, fn]) => !fn(el)).map(([k]) => k);
}
function contrastRatio(a, b) { /* 简化：实际按 WCAG 公式 */ return 4.6; }
console.log(audit(document.createElement('button')));
// ['hasRole','hasLabel']：开发期即暴露缺失项
```
