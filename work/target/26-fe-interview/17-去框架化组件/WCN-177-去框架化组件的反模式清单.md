## WCN-177：去框架化组件的反模式清单：review 时要拦下来

**答**：
- 反模式一：组件依赖宿主全局变量（window.__APP__）——破坏容器无关性；依赖应显式注入（property/context）。
- 反模式二：每次 attributeChanged 全量重写 shadowRoot.innerHTML——性能黑洞，应细粒度更新或 Signals。
- 反模式三：在 connectedCallback 里 attachShadow / 在 constructor 里读 attribute——生命周期错位。
- 反模式四：自定义事件不 composed / 事件名驼峰——跨影子树收不到、与平台惯例冲突。
- 反模式五：把大对象塞 attribute（JSON 序列化膨胀 + 解析开销）——对象走 property。
- 反模式六：业务代码直接 customElements.define——绕过 registry/加载器，破坏冲突治理与灰度能力。
- 反模式七：影子树内硬编码颜色/字体——绕过 token 契约，多主题失效。
- review 清单落地：把七条做成 PR checklist + ESLint 自定义规则（静态扫描 define/innerHTML/事件名）。

```javascript
// ESLint 自定义规则示意：拦截业务代码直接 define
module.exports.rules = {
  'no-direct-define': {
    create(context) {
      return {
        CallExpression(node) {
          const callee = node.callee;
          const isDefine = callee.object?.property?.name === 'customElements' &&
                           callee.property?.name === 'define';
          const inLib = context.getFilename().includes('packages/core');
          if (isDefine && !inLib) context.report({ node, message: '组件注册必须走 registry/加载器' });
        },
      };
    },
  },
};
```
