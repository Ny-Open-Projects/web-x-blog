## WCN-697：微前端架构下，设计系统如何避免多版本样式与组件冲突？

**答**：
- 结论：设计系统作为「共享基座」由主应用统一下发（单例 token + 单例组件注册），子应用只消费不自带副本；确需隔离用 Shadow DOM + 作用域 token。
- 做法：主应用初始化时 define 全部 WC 并注入 token；子应用 import 类型声明与 API 文档但不重复打包运行时；冲突用版本协商 + 沙箱。
- 追问钩子：子应用想升级组件版本怎么办？走主应用的版本路由与灰度，而非私自打包——考察对「集中治理」的理解。

```javascript
// 主应用：单例初始化设计系统
class DesignSystemHost {
  constructor() { this.loaded = false; }
  bootstrap(tokens) {
    if (this.loaded) return;
    import('@ds/components').then(() => {
      this.applyTokens(tokens);
      this.loaded = true;
    });
  }
  applyTokens(tokens) {
    Object.entries(tokens).forEach(([k, v]) =>
      document.documentElement.style.setProperty(k, v));
  }
}
const host = new DesignSystemHost();
host.bootstrap({ '--ds-primary': '#165DFF' });
// 子应用：只消费，通过 window.__DS_HOST__ 或 module federation 共享
```
