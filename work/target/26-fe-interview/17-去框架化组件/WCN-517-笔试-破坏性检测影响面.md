## WCN-517：元素 API 变更的「破坏性检测 + 消费方影响面分析」怎么做？

**答**：
- 结论：对比新旧 API 描述（属性/事件/slot），按规则判定 breaking 等级，反查登记的消费方。
- 破坏规则：删属性、改类型、事件改名/改 payload、slot 移除均算 breaking；新增算 minor。
- 影响面：遍历消费方依赖区间，标记需升级的仓库与 owner，输出迁移清单。
- 追问：如何避免误报（如内部属性删除）？（答：API 描述只暴露 @public 标记的字段）

```javascript
function diffAPI(oldApi, newApi) {
  const breaks = [];
  for (const p of oldApi.props) {
    if (!newApi.props.some(n => n.name === p.name)) breaks.push(`删除属性 ${p.name}`);
    else if (newApi.props.find(n => n.name === p.name).type !== p.type) breaks.push(`类型变更 ${p.name}`);
  }
  for (const e of oldApi.events) if (!newApi.events.includes(e)) breaks.push(`事件移除 ${e}`);
  for (const s of oldApi.slots) if (!newApi.slots.includes(s)) breaks.push(`slot 移除 ${s}`);
  return { level: breaks.length ? 'major' : 'minor', breaks };
}
function analyze(oldApi, newApi, consumers) {
  const d = diffAPI(oldApi, newApi);
  return { ...d, affected: consumers.filter(c => !c.range.startsWith('^' + newApi.major)) };
}
```
