## WCN-637：上万行列表中，细粒度 Signal 更新为何仍可能卡顿？如何优化？

**答**：
- 结论：细粒度解决了「更新范围」，但上万 effect 的创建/订阅本身有成本，且 DOM 节点过多会拖累布局——需要「虚拟列表 + 行级 signal 复用」。
- 做法：只渲染可视区行（虚拟滚动）；行 DOM 复用，signal 绑定到行实例而非数据项；批量更新用 batch 合并通知。
- 追问钩子：为什么不能每行一个全局 effect？因为 effect 数量与行数线性相关，创建和 GC 开销大——引出「按可视区订阅」的优化。

```javascript
// 虚拟列表：只给可视区行建立 effect
function virtualRows(container, data, rowH = 32) {
  const pool = [];
  function render(scrollTop) {
    const start = Math.floor(scrollTop / rowH);
    const end = start + Math.ceil(container.clientHeight / rowH);
    for (let i = start; i < end; i++) {
      let row = pool[i - start];
      if (!row) { row = document.createElement('div'); pool[i - start] = row; }
      row.textContent = data[i].name; // 复用 DOM，避免重建 effect
      container.appendChild(row);
    }
  }
  container.addEventListener('scroll', e => render(e.target.scrollTop));
  render(0);
}
```
