## WCN-601：已有 React/Vue 体系为何还要引入 Web Components，混合栈如何渐进迁移？

**答**：
- 结论：WC 不是替代框架，而是提供「框架无关的组件交付契约」，解决多技术栈并存下组件重复建设与视觉不一致。
- 渐进路径：先在新模块/跨团队共享组件用 WC，旧模块保留原框架；React/Vue 侧写一层薄 wrapper 消费，属性用 property、事件用 addEventListener 桥接。
- 追问钩子：什么时候不该用 WC？强交互且深度依赖框架状态/路由的业务组件，WC 桥接成本高于收益——面试官想听边界判断而非布道。

```javascript
// 宿主：React 团队 + Vue 团队 + WC 共享组件并存
import React from 'react';
import { createRoot } from 'react-dom/client';

class CartBadge extends HTMLElement {
  static observedAttributes = ['count'];
  connectedCallback() { this.render(); }
  attributeChangedCallback() { this.render(); }
  render() {
    const n = Number(this.getAttribute('count') || 0);
    this.textContent = n > 99 ? '99+' : String(n);
  }
}
customElements.define('cart-badge', CartBadge);

// React 侧薄 wrapper（属性同步）
function ReactCartBadge({ count }) {
  return React.createElement('cart-badge', { count });
}
createRoot(document.getElementById('root'))
  .render(React.createElement(ReactCartBadge, { count: 8 }));
// Vue 侧可直接 <cart-badge :count="n" />：一份实现，零重复建设
```
