## WCN-882：设计系统如何支撑产品的「国际化」平台化？

**答**：
- 结论先行：国际化不是「把文案翻译了」这么简单——设计系统要把「文案、排版、布局方向、格式」做成平台的横切能力，让组件天然适配多语言，而不是业务方各自打补丁。
- 文案层：组件内文案（如「确定/取消」「加载中」）走 i18n key + 默认文案，消费方覆盖 locale；支持复数、占位符、性别等 ICU 语法；提供 locale 切换即时生效（与 Signals 联动）。
- 排版层：不同语言文本长度差异大（德语比中文长很多）——组件布局要有弹性（不写死宽度、支持 truncation/tooltip）；字体栈按语言切换（中日韩字体、阿拉伯字体）。
- 方向层：RTL（阿拉伯/希伯来）支持——用逻辑属性（`margin-inline-start` 而非 `margin-left`）和 `dir` 属性，组件内部避免物理方向硬编码；提供 RTL 自动校验器。
- 格式层：数字/日期/货币/度量单位用 `Intl` API 统一格式化，组件提供 `locale` 属性或走 context。
- 追问钩子：面试官会问「某个组件文案写死中文了怎么办」——答：设计系统层面提供「硬编码文案检测」（静态扫描 + 伪语言测试 pseudolocale），在 CI 拦截；组件 API 设计上把文案做成必填或带默认 i18n key，从源头避免。

```javascript
// WC 组件的 i18n：context 注入 locale + Intl 格式化 + 默认文案兜底
const I18N = {
  'zh-CN': { confirm: '确定', loading: '加载中' },
  'en-US': { confirm: 'OK', loading: 'Loading...' },
};
function t(locale, key) { return I18N[locale]?.[key] || I18N['en-US'][key] || key; }
function formatDate(locale, d) { return new Intl.DateTimeFormat(locale).format(d); }

class I18nButton extends HTMLElement {
  static observedAttributes = ['locale'];
  connectedCallback() {
    const locale = this.getAttribute('locale') || 'zh-CN';
    this.setAttribute('dir', ['ar', 'he'].some(l => locale.startsWith(l)) ? 'rtl' : 'ltr');
    this.innerHTML = `<button>${t(locale, 'confirm')}</button>
      <time>${formatDate(locale, new Date())}</time>`;
  }
}
customElements.define('i18n-button', I18nButton);
```
