## WCN-146：去框架化组件的选型决策树：拿到需求后如何判断该用 WCN 还是框架组件？

**答**：
- 第一问：消费方技术栈是否 ≥2 种或包含"无框架区"（营销页、低代码、第三方站点）？否 → 框架组件。
- 第二问：组件是否稳定（API 迭代频率低）？高频变更的业务组件 → 留在框架层。
- 第三问：是否需要强宿主框架生态（Router context、React Query、Pinia）？是 → 框架组件或"WC 壳 + 依赖注入"。
- 第四问：SSR 要求？全站 SSR → 确认 DSD 管线可用；纯 CSR → 无顾虑。
- 第五问：团队基建（类型生成、Storybook、CI manifest diff）是否就绪？未就绪但方向确定 → 先做 1 个试点组件跑通全链路再扩量。
- 结论输出：决策树走完仍指向 WCN 的典型场景 = 设计系统基础层、跨团队 SDK、嵌入式部件（客服/支付组件）。

```text
决策树（文字版）
跨栈/无框架区? ─否→ 框架组件
  │是
API 稳定? ─否→ 框架组件（或 WC 壳 + 快速迭代区）
  │是
依赖宿主生态? ─是→ WC 壳 + 注入 / 包装层
  │否
SSR 需要 DSD? ─是→ 确认管线 → WCN ✅
  │否 → WCN ✅（先试点一个组件验证链路）
```
