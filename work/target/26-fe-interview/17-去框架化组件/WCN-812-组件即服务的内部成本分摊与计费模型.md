## WCN-812：企业内部「组件即服务」（CaaS）如何做成本分摊与计费？

**答**：
- 结论先行：内部计费的目的不是赚钱，而是「让使用方感知成本、让提供方有投入依据」——通常采用「平台预算兜底 + 按量分摊超额」的混合模式，避免纯粹免费导致滥用或纯粹收费导致不用。
- 成本构成：平台团队人力、CI/存储/CDN 等基建、第三方授权、on-call 成本——先算清总成本，再选分摊口径。
- 分摊口径：按调用量（组件加载次数）、按页面数、按 BU Headcount，或按「治理成本」（不达标组件占用额外审查资源）；选能引导正确行为的口径（如按量能抑制滥用）。
- 计费方式：设「免费额度 + 超额阶梯价」，新业务有起步额度鼓励采纳；账单要透明可查，能下钻到「哪个 BU 用了哪些组件、产生多少成本」。
- 追问钩子：面试官会问「计费会不会让业务方改用自研绕开」——答：所以要配合治理红线（自研组件也需过平台门禁），并让「用平台」的单位成本明显低于「自建+维护」，用经济性引导而非行政命令。

```javascript
// 内部计费：免费额度 + 超额阶梯，账单可下钻
const TIERS = [{ upto: 1e6, price: 0 }, { upto: 5e6, price: 0.5 }, { upto: Infinity, price: 0.3 }];
function bill(usage, tiers = TIERS) {
  let cost = 0, prev = 0;
  for (const t of tiers) {
    if (usage > prev) {
      const chunk = Math.min(usage, t.upto) - prev;
      cost += chunk * t.price / 1e4;
    }
    prev = t.upto;
    if (usage <= t.upto) break;
  }
  return +cost.toFixed(2); // 单位：内部结算币
}
console.log('800k 次:', bill(8e5));  // 0，免费额度内
console.log('3M 次:', bill(3e6));    // 阶梯计费
```
