## WCN-288：编译器响应式的产物审计（确认真的细粒度）如何做？
**答**：
- 对照实验：点击一个按钮，记录触发的 effect 数量（理想 = 1-2 个）。
- 产物检查：编译输出中 effect 覆盖的 DOM 写入数 vs 组件树大小。
- 性能回归：交互 P95 帧预算（细粒度应 < 5ms/交互）。
- 常见退化源：解构 props/大对象信号/数组整体替换——审计定位后重构。

```javascript
// 审计 harness
let effectRuns = 0;
onEffectRun(() => effectRuns++);
button.click();
expect(effectRuns).toBeLessThanOrEqual(2);   // 细粒度审计
```
