## WCN-891：设计系统平台的「数据洞察」：组件使用热力图如何支撑决策？

**答**：
- 结论先行：数据洞察的价值是「用真实使用数据驱动平台的路线与治理」——热力图回答「哪些组件高频用、哪些没人用、哪些被误用」，让资源投放与弃用决策有据可依。
- 数据采集：在组件侧埋点（加载/交互/版本），聚合到「页面 × 组件 × 变体 × 主题」维度；采集要轻量、可采样、注意隐私（不采用户隐私数据）；结合静态扫描（代码里 import 了哪些组件）做交叉验证。
- 热力图呈现：按使用频率给组件着色——高频核心组件（重点保障）、低频长尾（考虑维护或合并）、零使用（弃用候选）；可按 BU/页面/时间下钻。
- 决策支撑：高频组件优先投入质量与性能；发现「某组件总被错误参数调用」→ 改进 API 或文档；发现「某新组件采纳慢」→ 加强布道；发现「重复造轮子」→ 推动收敛。
- 边界：数据要结合定性反馈（NPS、访谈）——高频使用不一定等于体验好，可能是被 KPI 强推；避免只盯数字忽视用户声音。
- 追问钩子：面试官会问「怎么知道业务方自研了同类组件」——答：静态扫描代码库里的相似实现（如 button 类名、相似 DOM 结构）+ 组件清单对账，结合热力图发现「平台组件用得少但同类自研多」的缝隙。

```javascript
// 使用热力图数据聚合：组件 → 使用次数 + 变体分布 + 健康分级
function usageHeatmap(events) {
  const map = new Map();
  for (const e of events) {
    const cur = map.get(e.component) || { count: 0, variants: {}, versions: new Set() };
    cur.count++;
    cur.variants[e.variant] = (cur.variants[e.variant] || 0) + 1;
    cur.versions.add(e.version);
    map.set(e.component, cur);
  }
  return [...map].map(([component, v]) => ({
    component, count: v.count, topVariant: Object.entries(v.variants).sort((a, b) => b[1] - a[1])[0]?.[0],
    versionSpread: v.versions.size,
    level: v.count > 1000 ? '核心' : v.count > 50 ? '常规' : '长尾/弃用候选',
  })).sort((a, b) => b.count - a.count);
}
console.log(usageHeatmap([
  { component: 'ds-button', variant: 'primary', version: '2.1' },
  { component: 'ds-button', variant: 'primary', version: '2.2' },
  { component: 'ds-rare', variant: 'x', version: '1.0' },
]));
```
