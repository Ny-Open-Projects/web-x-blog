## WCN-674：IDE 场景下编译器如何做错误恢复，避免一处语法错误导致全文件失效？

**答**：
- 结论：用「容错解析」——解析出错时跳过非法 token 并构造 ErrorNode 继续解析后续内容，收集多个错误而非首错即停。
- 做法：parser 遇错记录错误并同步到下一个边界（; / } / 标签结束）；AST 保留错误节点带范围；LSP 把所有错误映射回源码位置。
- 追问钩子：为什么容错对 IDE 重要？因为用户输入是中间态（如刚敲 <div），全量失败会导致补全/高亮闪烁——考察对「编辑器体验」的重视。

```javascript
function tolerantParse(tokens) {
  const errors = [], nodes = []; let i = 0;
  while (i < tokens.length) {
    try {
      nodes.push(parseNode(tokens, i));
      i = consumeNode(tokens, i);
    } catch (e) {
      errors.push(e);
      i = sync(tokens, i); // 同步到下一个安全边界
    }
  }
  return { nodes, errors };
}
function sync(tokens, i) {
  while (i < tokens.length && ![';', '}', '>'].includes(tokens[i])) i++;
  return i + 1;
}
function parseNode(t, i) { return { token: t[i] }; }
function consumeNode(t, i) { return i + 1; }
const r = tolerantParse([{ v: '<div' }, { v: '>' }, { v: 'ok' }]);
console.log(r.nodes.length, r.errors.length); // 尽量多产出，少中断
```
