## MFW-574：笔试：手写快照-订阅缝隙补拉

**答**：实现 `createSnapshotStream({ snapshot, subscribe, fetchSince })`。snapshot: `{ data, version }`；subscribe: `(cb) => unsub`（实时事件流 `{ version, data, type: 'upsert'|'delete' }`）；fetchSince: `(version) => Promise<events[]>`（补拉缝隙事件）。规则：1) 订阅先启动（实时事件先进 buffer）；2) fetchSince 补拉缝隙（T0-T1 事件）；3) **合并去重**：buffer 中 version ≤ 补拉最大 version 的事件丢弃（补拉覆盖缝隙）；4) 事件按 version 排序输出到 onEvent；5) 之后实时事件直通。边界：补拉为空（无缝隙）；订阅事件先于补拉返回（乱序合并）；补拉失败 → 降级全量重拉（onReset 通知）。

```javascript
function createSnapshotStream({ snapshot, subscribe, fetchSince, onEvent, onReset = () => {} }) {
  let buffer = [];
  let lastVersion = snapshot.version;
  let ready = false;
  let unsub = subscribe((ev) => {
    if (!ready) { buffer.push(ev); return; }             // 就绪前缓冲
    if (ev.version > lastVersion) { lastVersion = ev.version; onEvent(ev); }
  });
  (async () => {
    try {
      const missed = await fetchSince(snapshot.version); // 缝隙补拉
      // 合并：buffer 中与补拉重叠（version ≤ 补拉最大）的丢弃
      const maxMissed = missed.at(-1)?.version ?? snapshot.version;
      const merged = [...missed,
        ...buffer.filter(e => e.version > maxMissed)]
        .sort((a, b) => a.version - b.version)
        .filter(e => e.version > lastVersion);
      for (const ev of merged) { lastVersion = ev.version; onEvent(ev); }
      ready = true;
    } catch (e) {
      unsub();
      onReset();                                         // 补拉失败：全量重拉
    }
  })();
  return { unsubscribe: unsub };
}

// 自测
const events = []; let unsubbed = false;
const stream = createSnapshotStream({
  snapshot: { data: [1, 2], version: 10 },
  subscribe: (cb) => {
    // 订阅先于补拉返回：实时事件进 buffer
    setTimeout(() => { cb({ version: 11, data: 3, type: 'upsert' });
      cb({ version: 12, data: 4, type: 'upsert' });
      cb({ version: 13, data: 5, type: 'delete' }); }, 0);
    return () => { unsubbed = true; };
  },
  fetchSince: async (v) => {
    await sleep(10);                                     // 补拉慢于订阅
    return [{ version: 11, data: 3, type: 'upsert' }];   // 缝隙事件（与 buffer 重叠 11）
  },
  onEvent: (ev) => events.push(ev),
});
await sleep(30);
console.log(events.map(e => e.version).join(','));       // 11,12,13（无缝隙丢数据）
console.log(events[0].data === 3);                       // 补拉版优先（buffer 的 11 被丢）
console.log(unsubbed === false);                         // 成功不取消订阅（继续实时）

// 补拉失败 → onReset
const resets = [];
createSnapshotStream({
  snapshot: { data: [], version: 1 },
  subscribe: () => () => {},
  fetchSince: async () => { throw new Error('net'); },
  onEvent: () => {}, onReset: () => resets.push(1),
});
await sleep(10);
console.log(resets.length === 1);
```

**评分点**：
- 接缝合并正确：补拉覆盖缝隙、buffer 重叠（version ≤ 补拉最大）丢弃、按 version 排序去重
- 失败降级 onReset（全量重拉——缝隙不可恢复时的正确姿势）；成功不取消订阅（继续实时）
- 就绪前 buffer（订阅先启动不丢实时事件——接缝策略的核心）
- 能说清「快照与订阅的接缝（T0-T1）是实时架构的经典丢数据点——订阅带 since 的补拉是标准解」属于加分
