## MFW-786：笔试：手写渐进增强时序

**答**：实现 `progressiveEnhanceTest(page, { htmlReady, jsReady })`。page: `{ url, formSelector, submitSelector, resultSelector }`。模拟时序：htmlReady（HTML chunk 到达时间 ms）、jsReady（JS 水合完成时间 ms）。规则：1) **JS 前提交**（htmlReady < t < jsReady → 原生提交——整页刷新：URL 变化 + 独立请求）；2) **JS 后提交**（t > jsReady → RSC 提交——软导航：URL 变化 + fetch RSC payload）；3) 断言：两种模式的最终结果一致（搜索结果相同——RBL-667 双包一致性的渐进增强版）；4) 返回 `{ nativePath: { result, mode: 'full-page' }, enhancedPath: { result, mode: 'rsc' }, consistent }`。边界：htmlReady === jsReady（同时到达——JS 前无窗口——native path 不存在）；formSelector 不存在（no-form——跳过）。

```javascript
async function progressiveEnhanceTest(page, { htmlReady = 200, jsReady = 2000, formAction = '/search' } = {}) {
  // 模拟：JS 前提交（原生 POST/GET）
  const nativeResult = await simulateSubmit(page, { disableJs: true, at: htmlReady + 100 });
  // 模拟：JS 后提交（RSC 增强路径）
  const enhancedResult = await simulateSubmit(page, { disableJs: false, at: jsReady + 100 });
  // 结果一致性
  const consistent = nativeResult.data === enhancedResult.data;
  return {
    nativePath: { ...nativeResult, mode: 'full-page' },
    enhancedPath: { ...enhancedResult, mode: 'rsc' },
    consistent,
  };
}
async function simulateSubmit(page, { disableJs, at }) {
  // Playwright：JS 禁用/启用
  const ctx = page.context();
  const newPage = await ctx.browser().newContext({
    javaScriptEnabled: !disableJs,
  }).then(c => c.newPage());
  await sleep(at);
  await newPage.goto(page.url);
  await newPage.fill(page.formSelector, 'laptop');
  await newPage.click(page.submitSelector);
  await newPage.waitForURL(/q=laptop/);
  const data = await newPage.textContent(page.resultSelector);
  await newPage.close();
  return { data };
}
const sleep = (ms) => new Promise(r => setTimeout(r, ms));

// 自测
const page = { url: 'http://localhost:3000/products',
  formSelector: 'input[name="q"]', submitSelector: 'button[type="submit"]',
  resultSelector: '[data-results]' };
// 测试结构验证（mock fetchFn 的集成在 E2E 中验证）
console.log(typeof progressiveEnhanceTest === 'function');
// 一致性断言的核心：
// native: GET /products?q=laptop → SSR HTML → 结果
// enhanced: GET /products?q=laptop (RSC) → Flight payload → 渲染结果
// 两者最终显示的搜索结果一致（服务端逻辑相同——渲染方式不同）
```

**评分点**：
- 双路径测试：JS 前（原生提交）与 JS 后（RSC 增强）——渐进增强的两种路径
- 结果一致性断言（两种模式最终显示相同数据——渲染方式不同但服务端逻辑同）
- 时序模拟（htmlReady/jsReady 的时间窗口——用户在窗口内提交走原生路径）
- 能说清「chunked 流式让渐进增强从理论变实践：HTML 先行的交互窗口是真实用户路径」属于加分
