## MFW-812：笔试：手写幂等记录与业务写入的同事务提交器

**答**：
- 结论：用 DB 原子插入 + 唯一键冲突来「占位」，避免先查后写的 TOCTOU；幂等记录与业务写入同事务提交，保证原子。
- 关键：并发冲突时——已完成(done)回放缓存结果，处理中(pending)返回可重试提示，绝不重复执行业务。
- 追问钩子：Redis SETNX 为什么不够？——跨存储无法与 DB 事务原子提交，占键成功但业务失败会留下「幽灵幂等键」。

```javascript
function createIdempotent(txFactory) {
  return async function withIdempotency(key, fn) {
    const tx = await txFactory();
    try {
      // 原子占位：唯一键冲突代表已在处理/已处理
      const inserted = await tx.insert('idem', { key, state: 'pending' })
                                .onConflict('key').doNothing();
      if (!inserted) {
        const row = await tx.one('SELECT result,state FROM idem WHERE key=?', [key]);
        await tx.commit();
        if (row.state === 'done') return { replay: row.result };
        return { retryAfter: 100 };                 // 处理中，稍后重试
      }
      const result = await fn(tx);                  // 执行业务（同 tx）
      await tx.exec('UPDATE idem SET state=?,result=? WHERE key=?',
                    ['done', JSON.stringify(result), key]);
      await tx.commit();                             // 全部原子落库
      return { result };
    } catch (e) { await tx.rollback(); throw e; }
  };
}

// 自测：内存版 tx 简化验证流程
const store = new Map();
const idem = createIdempotent(async () => ({
  insert: async (t, r) => { if (store.has(r.key)) return false; store.set(r.key, {...r}); return true; },
  one: async (_, k) => store.get(k),
  exec: async (sql, s, k) => { store.get(k).state = s; store.get(k).result = s; },
  commit: async () => {}, rollback: async () => {}
}));
idem('k1', async () => 'ok').then(r => console.log(r));
idem('k1', async () => 'again').then(r => console.log(r)); // replay: ok
```

**评分点**：
- 占位使用 DB 原子插入 + 唯一键冲突（INSERT ON CONFLICT），不是先查后写——避免 TOCTOU 竞态
- 幂等记录与业务写入同事务提交，异常整体回滚
- 并发冲突处理正确：done 回放结果、pending 返回可重试，不重复执行业务
- 能点出 Redis SETNX 方案与 DB 无法原子提交的缺口（加分）
