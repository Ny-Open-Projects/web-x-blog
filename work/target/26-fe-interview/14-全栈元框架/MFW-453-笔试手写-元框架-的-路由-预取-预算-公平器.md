## MFW-453：MFM→453：预取公平器
**答**：实现 `fairPrefetch(tabs)`：1) 场景：用户 20 个 Tab 同站——每 Tab 独立预取=带宽×20；SharedWorker 或 BroadcastChannel 协调全局预算；2) 机制：集中记账（focus Tab 权重 3/背景 1——用户注意力优先）、同 URL 去重（A Tab 预取 B Tab 复用）、全局并发 ≤6；3) 抢占：focus Tab 新意图可挤背景在途（abort 低的）；4. 失效广播：任何 Tab 的 mutation → 全 Tab 缓存失效标记（下次导航重验——跨页签一致性 MFW-276 复用）。

```javascript
// shared-worker 内
const ledger = { inflight: new Map(), byTab: new Map() }
onmessage = ({ data: { kind, tab, url, prio } }) => {
  if (kind === 'want') {
    const my = (ledger.byTab.get (tab)?.n ?? 0) * weightOf(tab)  // focus=3 bg=1
    if (globalInflight () >= 6 && lowestBgAbort()) abortLow()     // focus 抢占 bg
    if (hasOrInflight (url)) return reply(tab, { reuse: true })    // 同 URL 复用
    grant(tab, url)
  }
  if (kind === 'mutated', { domain }) broadcast({ invalidate: domain }))  // 全 Tab 失效
}
function weightOf(t) { return focused === tab ? 3 : 1 }
```
**评分点**：
- 集中记账（SharedWorker——Tab 各自为政是带宽爆炸根因）
- 注意力权重（focus 3:1——预取服务用户当前意图）
- 同 URL 复用 + focus 抢占 bg（预算内价值最大化）
- 失效跨 Tab 广播（多页签数据一致性——常见盲区）
