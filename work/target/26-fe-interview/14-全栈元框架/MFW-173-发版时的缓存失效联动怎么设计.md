## MFW-173：一次发版后缓存失效联动怎么设计（四种缓存一起动）？
**答**：
- 内容发布（如运营改了商品详情）：只 `revalidateTag('product:123')`，Data Cache 与依赖它的 Full Route Cache 一起失效，Client Router Cache 靠重新导航拉新 payload；影响面最小。
- 代码发版（构建产物变了）：Full Route Cache 天然全部作废（构建 ID 变了），但 CDN 上还压着旧 HTML——要把 CDN 缓存清掉或让构建 ID 参与 URL（资产 hash / HTML 带 no-store）。
- Client Router Cache 默认 30s/5min 静态复用：重要页面导航后要拿新数据，可在响应段设置 `staleTimes` 调短，或对敏感数据路由用 `router.refresh()`。
- SSR 内存里的 Request Memoization 只活一个请求，发版不影响；不用管。
- 设计原则：失效粒度从细到粗依次评估——tag → path → 全量清 CDN，能细不粗，并写进发布 checklist 自动执行。

```javascript
// 发布流水线里的失效钩子（发版后自动触发）
async function onDeploy({ changedTags, cdn }) {
  for (const tag of changedTags) {
    revalidateTag(tag); // Data Cache + Full Route Cache 联动失效
  }
  // 构建产物变更时清 CDN 旧 HTML（只清动态页 HTML，静态资产靠 hash 自失效）
  if (changedBuild) await cdn.purge({ prefixes: ['/product/', '/list/'] });
}
```
