## MFW-489：客户端导航最新请求竞态守卫
**答**：实现 `NavigationGuard`：1) `start(href, loader)`：发起新导航时 abort 上一未完成导航的 loader（AbortController 贯穿——快进快出场景旧响应不许落地）；2) 旧导航 abort 后 resolve 也会被丢弃（promise 结果到达先比对 epoch）；3) loader 支持 signal（fetch 透传，服务端不白算）；4) `end()` 提交结果前校验仍是最新 epoch，否则静默丢弃并记 `dropped` 计数（回退按钮 + 快速点击列表是重灾区）。

```javascript
export class NavigationGuard {
  constructor() {
    this.epoch = 0
    this.aborter = null
    this.dropped = 0
  }

  start(href, loader) {
    this.aborter?.abort('superseded')       // 杀上一趟
    this.aborter = new AbortController()
    const my = ++this.epoch
    const signal = this.aborter.signal
    return loader(signal).then(
      result => {
        if (my !== this.epoch || signal.aborted) {
          this.dropped++                     // 旧响应到达即丢弃
          return { committed: false }
        }
        return { committed: true, href, result }
      },
      err => {
        if (signal.aborted) return { committed: false, aborted: true }
        throw err                            // 非竞态错误正常上抛
      })
  }

  get current() { return this.epoch }
}
```

**评分点**：
- epoch 比对守卫 resolve 路径（abort 不一定拦住已 resolve 的 promise——双保险）
- AbortController 透传 loader（服务端/网络层真正取消，不只前端丢弃）
- abort 错误不上抛（被取代是正常路径，不是 error）
- dropped 计数（竞态丢弃可观测，高频增长说明列表页需要防抖）
