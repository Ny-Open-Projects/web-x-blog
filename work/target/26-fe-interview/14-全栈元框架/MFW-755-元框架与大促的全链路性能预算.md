## MFW-755：大促全链路性能预算

**答**:
- 大促的性能预算分配（RBL-934 + RBL-662 的综合应用）：1) **三层预算**：CDN 层（缓存命中延迟 <10ms）、SSR 层（TTFB <300ms——shell 渲染）、client 层（LCP <2.5s、INP <200ms、CLS <0.1）；2) **每层细化**：SSR 的 shell <200ms（build time 静态部分）、动态洞 <500ms（数据 fetch）；client 的 JS <200KB（大促首页——大促 JS 比日常更小（紧急加载最小集））；3) **预算的门禁链**：CI 体积门禁（RBL-662）→ 线上 RUM 门禁（RBL-880）→ 告警（RBL-836）。
- 大促的特殊预算：动态洞的 QPS 预算（优惠券/库存 fetch——每洞的数据源容量 RBL-599）；失效队列预算（失效速率 vs 渲染速率——RBL-600 的加权调度）。
- 追问钩子：为什么「大促的性能预算」比日常更严格？——大促流量 ×10（预算超标的用户影响 ×10——1% 超预算 = 10 倍用户受影响）；预算的「乘数效应」：流量放大时性能问题的商业损失也放大（延迟 1s = 转化率降 7% × 10 倍流量 = 大额营收损失）——「性能预算与商业损失的映射」在大促场景更直接：每 100ms 延迟 = N 元损失——性能预算的商业语言（RBL-944 叙事的数据锚点）。

```typescript
// 大促性能预算（三层）
const PROMO_BUDGET = {
  cdn: { cacheHitLatencyMs: 10, hitRate: 0.95 },        // CDN 层
  ssr: { ttfbMs: 300, shellMs: 200, dynamicHoleMs: 500 },   // SSR 层
  client: { lcpMs: 2500, inpMs: 200, cls: 0.1, jsKB: 200 },   // client 层
  // 大促特殊预算
  invalidation: { regenQpsLimit: 50, priorityTopN: 5000 },
  dynamicHoles: { couponsQps: 5000, stockQps: 10000 },  // 洞的 QPS 预算
};
// 门禁链
// CI: routeProfile → 预算比对（RBL-662）
// 线上: RUM → P75 对比（RBL-880）
// 告警: 超 20% → P1 通知（RBL-836）
// 商业映射
const businessImpact = (latencyIncreaseMs, dailyRevenue) =>
  `延迟 +${latencyIncreaseMs}ms ≈ 转化率 -${(latencyIncreaseMs / 1000 * 7).toFixed(1)}%` +
  ` ≈ 日损失 ¥${(dailyRevenue * latencyIncreaseMs / 1000 * 0.07).toFixed(0)}`;
```
