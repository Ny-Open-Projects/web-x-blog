## MFW-540：水合错误自动化检测：SSR/CSR diff 的 CI 化

**答**:
- 水合 mismatch 的 CI 化检测：1) SSR 渲染 HTML → headless 加载执行水合 → **捕获 hydration error**（React 的 console.error 拦截）→ 存在即 fail；2) **双渲染 diff**（SSR DOM vs 水合后 DOM 的序列化比较——语义指纹 RBL-794）；3) RSC 场景：序列化校验（RBL-779 的 props 可序列化检查前置）。
- 检测的覆盖策略：路由抽样 × 状态注入（cookie/搜索参数的矩阵——不同状态下的 mismatch；locale/设备维度）。
- 生产监控的互补：client 水合错误的 RUM 上报（production 的 hydration error 聚合 RBL-938 指纹——「hydration mismatch」指纹分组）——CI 拦已知、RUM 兜未知（RBL-904 SLO 的正确性 SLI）。
- 追问钩子：为什么「mismatch 在 dev 能看到、上线才爆」是常态？——dev 的 mismatch 警告依赖「相同输入」：dev SSR 与 client 渲染都走 dev 模式（时间/随机/环境一致概率高）；生产差异（缓存命中不同/buildId 差异/用户态数据）——「dev 与 prod 的输入面差异」是 mismatch 检测的核心盲区：CI 的生产构建水合测试（staging 环境）补上这个盲区。

```javascript
// CI 水合检测（Playwright）
test('hydration clean', async ({ page }) => {
  const errors = [];
  page.on('console', (msg) => {
    if (msg.type() === 'error' && /hydrat|did not match/i.test(msg.text()))
      errors.push(msg.text());
  });
  await page.goto('/product/42', { waitUntil: 'networkidle' });
  expect(errors).toEqual([]);
});
// 双渲染语义 diff
test('ssr/csr same fingerprint', async ({ page }) => {
  const ssr = await (await fetch('/product/42')).text();
  await page.goto('/product/42', { waitUntil: 'networkidle' });
  const csr = await page.evaluate(() => document.body.outerHTML);
  expect(semanticFingerprint(ssr)).toEqual(semanticFingerprint(csr));
});
// 状态矩阵：cookie/locale/参数的组合抽样（RBL-794 分层）
const matrix = [['guest', 'user'], ['zh', 'en']].reduce(cartesian);
for (const [role, locale] of matrix) await hydrationClean({ role, locale });
```
