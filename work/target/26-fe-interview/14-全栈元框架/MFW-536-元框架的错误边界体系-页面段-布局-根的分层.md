## MFW-536：错误边界体系：分层的恢复语义

**答**:
- 错误边界的分层：error.tsx 逐段（段级错误只重渲染该段——layout 保持）；global-error.tsx（根级：全页替换——layout 也崩时）；`reset()` 的语义（重试渲染错误段——不是整页刷新）。
- 分层的决定逻辑：错误向上冒泡到最近的 error 边界——「边界的粒度 = 恢复的粒度」：段级 error（侧栏崩正文还在）；layout 的 error.js（整个 layout 崩——布局级恢复）；global（连根 layout 都崩）。
- 恢复语义的三态：自动重试（reset——客户端组件重新渲染错误段）/导航离开（用户自己点）/降级 UI（error 页的 fallback UI + report 按钮）；「错误页不消耗错误」（error.js 自身崩溃 → global-error 兜底）。
- 与 error 元数据的配合：error 页的 SEO（4xx/5xx 状态码的语义——not-found.tsx 是 404 语义、error 是 500——爬虫的状态码正确性）。
- 追问钩子：为什么「错误恢复的粒度」要跟着布局结构走而不是全局统一？——全局兜底 = 任何局部错误整页重载（用户体验断崖：滚动丢失/状态清零）；段级边界 = 错误被围栏在发生地（其他区域无感知）——「故障隔离域」的架构原则与微前端隔离（RBL-766）、SCC 禁拆（RBL-592）同源：边界结构决定故障传播范围。

```tsx
// app/shop/[id]/error.tsx —— 段级（client 组件）
'use client';
export default function ProductError({ error, reset }) {
  return (
    <div role="alert">
      <p>商品加载失败: {error.message}</p>
      <button onClick={reset}>重试</button>              {/* 只重渲染该段 */}
    </div>
  );
}
// app/global-error.tsx —— 根级兜底（连 root layout 都崩）
'use client';
export default function GlobalError({ error, reset }) {
  return (
    <html>                                               {/* 自带 html/body：layout 已崩 */}
      <body><h1>页面出错了</h1><button onClick={reset}>重试</button></body>
    </html>
  );
}
// 恢复链：段 error → reset 重试段 → 仍失败用户导航 → global 兜底
```
