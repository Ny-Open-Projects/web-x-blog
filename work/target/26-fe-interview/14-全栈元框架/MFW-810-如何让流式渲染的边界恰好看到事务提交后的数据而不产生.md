## MFW-810：如何让流式渲染的边界恰好看到事务提交后的数据而不产生快照漂移

**答**：
- 结论：不要在同一请求里协调——把「事务提交」与「渲染刷新」解耦为两个事件：提交后 revalidateTag，渲染由下一次请求触发；单个流只读请求开始时的快照。
- 强行在同一请求等事务会引入「快照漂移」：同一个流前后两块读到不同版本，UI 自相矛盾（价格块旧、库存块新）。
- 追问钩子：那「提交后立即看到结果」怎么保证？——提交响应返回新版本号，客户端据此发起带版本的 refresh，保证读到 ≥ 该版本。

```javascript
// 提交响应携带版本，作为渲染刷新的门控
async function checkout(cart) {
  'use server';
  const { orderId, version } = await db.checkout(cart);
  revalidateTag('cart');
  return { orderId, version };                     // 版本号随响应返回
}

// 客户端：用版本号发起「可见性有保证」的刷新
async function afterCheckout(res) {
  const r = await fetch('/api/snapshot?t=' + res.version, {
    headers: { 'x-min-version': String(res.version) }
  });
  if (r.ok) router.refresh();                      // 读到 >= version 的快照
}

// 服务端读路径：阻塞直到副本追平请求版本（有上限）
async function readAtLeast(version) {
  const v = await replica.version();
  if (v < version) await replica.waitFor(version, { timeout: 500 });
  return replica.find(/* ... */);
}
```
