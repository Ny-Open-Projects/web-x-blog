## MFW-792：笔试：手写双端验证一致性

**答**：实现 `validateDual(schema, formData, { mode })`。schema: zod schema。mode: 'client'（返回字段错误——UI 渲染）| 'server'（返回 { errors } or { data }——action 返回值）。规则：1) safeParse 调用（schema.safeParse(formData)）；2) 成功：client → `{ valid: true }`；server → `{ data: parsed.data }`（通过验证的数据）；3) 失败：client → `{ valid: false, fieldErrors: Record<field, string[]> }`（按字段分组——UI 逐字段显示）；server → `{ errors: fieldErrors }`（同结构——useActionState 消费）；4) fieldErrors 的格式：zod 的 flatten().fieldErrors——`{ name: ['至少2字符'], email: ['邮箱格式错误'] }`。边界：schema 抛错（内部错误——非验证失败）；formData 空（空对象 → schema 验证失败——字段缺失错误）；多字段错误（每个字段的错误数组）。

```javascript
function validateDual(schema, formData, { mode = 'server' } = {}) {
  try {
    const parsed = schema.safeParse(
      formData instanceof FormData ? Object.fromEntries(formData) : formData);
    if (parsed.success) {
      if (mode === 'client') return { valid: true, data: parsed.data };
      return { data: parsed.data };                       // server：通过
    }
    const fieldErrors = parsed.error.flatten().fieldErrors;
    if (mode === 'client')
      return { valid: false, fieldErrors };
    return { errors: fieldErrors };                       // server：返回错误
  } catch (e) {
    return mode === 'client'
      ? { valid: false, fieldErrors: { _schema: ['schema 内部错误'] } }
      : { errors: { _schema: [e.message] } };             // 内部错误——非验证失败
  }
}

// 自测
const ProfileSchema = {
  safeParse(data) {
    const errors = {};
    if (!data.name || data.name.length < 2)
      errors.name = ['名称至少 2 字符'];
    if (!data.email || !data.email.includes('@'))
      errors.email = ['邮箱格式错误'];
    return Object.keys(errors).length
      ? { success: false, error: { flatten: () => ({ fieldErrors: errors }) } }
      : { success: true, data: { ...data } };
  },
};
const fd = { name: 'a', email: 'bad' };
// server 模式
let r = validateDual(ProfileSchema, fd, { mode: 'server' });
console.log(r.errors.name[0] === '名称至少 2 字符');
console.log(r.errors.email[0] === '邮箱格式错误');
console.log(r.data === undefined);                       // 失败时无 data
// client 模式
r = validateDual(ProfileSchema, fd, { mode: 'client' });
console.log(r.valid === false && r.fieldErrors.name[0] === '名称至少 2 字符');
// 成功
r = validateDual(ProfileSchema, { name: 'ab', email: 'a@b.com' }, { mode: 'server' });
console.log(r.data.name === 'ab');                       // 验证通过的数据

// 多字段错误
r = validateDual(ProfileSchema, {}, { mode: 'client' });
console.log(Object.keys(r.fieldErrors).length >= 2);     // name 和 email 都错

// 空 formData
r = validateDual(ProfileSchema, new Map(), { mode: 'server' });
console.log(r.errors !== undefined);                     // 空表单验证失败
```

**评分点**：
- 双模式返回（client valid+fieldErrors / server errors+data——useActionState 的消费格式）
- fieldErrors 按字段分组（UI 逐字段显示）；schema 抛错的内部错误区分（非验证失败）
- 边界（空 formData/多字段错误/成功与失败的互斥结构）；safeParse 的包装
- 能说清「双端验证的分工：client 是 UX（快速反馈）、server 是安全（防绕过）——同一 schema 保证一致性」属于加分
