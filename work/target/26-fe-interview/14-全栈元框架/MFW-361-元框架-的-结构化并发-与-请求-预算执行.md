## MFW-361：结构化并发预算执行

**答**:
- 语义目标：一次请求内的所有子任务生命周期被请求边界约束——请求结束（完成/放弃/断连）所有在途 IO 必须终结（无孤儿查询——RBL-459 AbortScope 的请求级应用）
- 组合实现：`AbortSignal.any([reqSignal, timeout(800), stdLibSignal])`——请求取消/段预算/依赖超时三源合一；并行聚合用 Promise.allSettled + 每支独立 sub-budget（核心 800/非核心 300——MFW-326 分级竞速）
- 框架接点：Next 的请求取消传播到 RSC 树（客户端放弃→render 中断）——自定义数据函数必须接收并透传 signal 才真取消（pg 驱动 cancelAffinity 级）
- 度量闭环：孤儿 IO 检测（请求结束后仍完成的查询计数——应为 0，非 0 即泄漏点清单）

```javascript
async function loadDashboard(id, { reqSignal }) {
  const core = abortableTimeout(800), side = abortableTimeout(300)
  const [price, recs] = await Promise.allSettled([
    fetchWith(`/api/price/${id}', { signal: AbortSignal.any([reqSignal, core]) }),
    fetchWith('/api/rec', { signal: AbortSignal.any([reqSignal, side]) }),   // 非核心独立短预算
  ])
  return { price: unwrapOrStale(price), recs: recs.value ?? REC_FALLBACK }
}
// 孤儿检测：req end 后完成的 DB 查询计数 → 必须为 0
```
