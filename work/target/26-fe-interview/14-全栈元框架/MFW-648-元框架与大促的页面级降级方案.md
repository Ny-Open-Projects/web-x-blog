## MFW-648：大促页面级降级

**答**:
- 大促的页面降级层次（RBL-686 容量的降级面）：1) **功能降级**（实时库存显示 → 关闭（秒级实时→分钟级缓存——DB 压力降级）；个性化推荐 → 通用热门（每用户查询 → 全局缓存）；评论 → 折叠）；2) **数据降级**（页面骨架 + 缓存数据（stale 数据可接受——新鲜度换可用性）；3) **渲染降级**（ISR 页 → 纯静态壳（放弃动态洞——静态兜底）；SSR → CDN 缓存的上次成功快照（RBL-583 降级链）。
- 降级的触发：feature flag（Edge Config RBL-594——运行时切换不改代码）；自动触发（DB 延迟阈值/渲染 QPS 超——指标驱动自动降级 RBL-904 SLO）。
- 降级的恢复：自动恢复（指标回正）vs 人工确认（大促后回全功能——渐进恢复：先恢复低风险功能）。
- 追问钩子：为什么「降级的触发要自动化而不是人工」？——大促峰值时人工来不及（DB 打满到页面 500 = 分钟级；自动降级 = 秒级）；人工判断依赖监控（监控延迟 + 人工反应 = 3-5 分钟——流量已损失）；「自动降级的误触发」成本（提前降级 = 功能体验降）vs「不降级的代价」（服务崩 = 全损）——误触发成本 < 全损成本 → 自动化；降级决策的自动化与 RBL-687 弹性扩容同构（阈值驱动的自动动作）。

```typescript
// 大促降级配置（Edge Config 驱动）
const DEGRADE_LEVELS = [
  { level: 1, trigger: { dbP95: 200 }, action: { stockRealtime: false, cacheTtl: 60 } },
  { level: 2, trigger: { dbP95: 1000 }, action: { stockRealtime: false, recommendations: 'popular', comments: 'collapse' } },
  { level: 3, trigger: { renderQps: 5000 }, action: { page: 'static-shell' } },  // 静态壳兜底
];
// middleware 或 server 组件读降级级别
export async function getDegradeLevel() {
  const level = await edgeConfig.get('degradeLevel') ?? 0;
  return DEGRADE_LEVELS[level];                          // 运行时降级不改代码
}
// RSC 中应用
export default async function ProductPage({ params }) {
  const degrade = await getDegradeLevel();
  return (
    <>
      {degrade?.action.recommendations === 'popular'
        ? <PopularProducts />                            // 通用热门（全局缓存）
        : <PersonalRecs userId={session.id} />}          // 个性化（每用户查询）
      {degrade?.action.page === 'static-shell'
        ? <StaticShell />                                // 静态壳兜底
        : <FullProduct params={params} />}
    </>
  );
}
```
