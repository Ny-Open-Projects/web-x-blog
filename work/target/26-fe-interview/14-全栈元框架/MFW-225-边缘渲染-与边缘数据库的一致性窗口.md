## MFW-225：边缘一致性窗口治理

**答**:
- 窗口来源：边缘副本落后主库 N 秒（复制延迟）——边缘渲染的页面用副本数据 = 可能展示秒级旧值
- 分级策略：强一致读（下单/余额）→ 绕副本直读主（接受 RTT）或写后读走主（read-your-writes 会话粘主）；最终一致读（列表/详情展示）→ 副本
- 会话粘主实现：写操作的响应带「最新时间戳」cookie → 后续 N 秒内该用户读请求路由主库——一致性体验与副本成本的平衡点
- UI 层补偿：可能旧的数据标注「更新于 x 秒前」（期望管理）——比假装强一致诚实

```javascript
// 会话粘主：写后 N 秒读主
setCookie('lwts', Date.now())                          // 写后下发
const usePrimary = Date.now() - +(getCookie('lwts') ?? 0) < 5000
const db = usePrimary ? primaryClient : edgeReplica     // 读路由
```
