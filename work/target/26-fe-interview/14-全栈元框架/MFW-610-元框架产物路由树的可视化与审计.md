## MFW-610：路由树可视化与审计

**答**:
- 路由树 = 文件目录树的编译产物映射（RBL-524）：可视化= 段树（route/layout/page/loading/error 节点标注）；「审计维度」：1) **深嵌套 layout 链**（嵌套 5 层 layout = 每次导航 payload 含 5 层（共享前缀）——合理；但嵌套 loading 叠加 = 流式层级混乱）；2) **孤段**（有 layout 无 page——404 死区）；3) **段级 bundle 的体积分布**（哪个段的 bundle 重——RBL-561 路由画像的段级细分）。
- 审计的自动化：build 产物（routes-manifest + app-paths）→ 段树 JSON → 规则检查（孤段/超深/超大段）。
- 可视化的用途：新人理解路由架构（目录即图）；重构规划（layout 重构的影响面——段的父子关系 RBL-525 diff 的段树基础）。
- 追问钩子：为什么「段树审计」能发现「layout 嵌套过深」的架构问题？——每层 layout 都进 payload/进水合树（深嵌套 = 导航 payload 大 + React 树深渲染慢）；「结构深度 × 每层成本」的乘积——审计的阈值（>4 层 layout 警告）不是风格偏好而是成本约束（每层 layout 的 JS/payload 有实际字节成本）；段树可视化让「结构成本」可见（RBL-553 成本归因的架构维度）。

```javascript
// 段树构建（从 routes manifest）
function buildSegmentTree(manifest) {
  const root = { segment: '/', children: new Map(), node: {} };
  for (const [route, meta] of Object.entries(manifest.routes)) {
    let cur = root;
    for (const seg of route.split('/').filter(Boolean)) {
      if (!cur.children.has(seg)) cur.children.set(seg, { segment: seg, children: new Map(),
        node: { layouts: 0, pages: 0, loading: false, error: false, sizeKB: meta.sizeKB } });
      cur = cur.children.get(seg);
      cur.node.pages += meta.hasPage ? 1 : 0;
      cur.node.layouts += meta.hasLayout ? 1 : 0;
    }
  }
  return root;
}
// 审计规则
function auditSegments(root) {
  const findings = [];
  walk(root, 0, (node, depth) => {
    if (node.layouts > 0 && node.pages === 0 && node.children.size === 0)
      findings.push({ segment: node.segment, issue: 'orphan-layout', detail: '有 layout 无 page——404 死区' });
    if (depth > 4)
      findings.push({ segment: node.segment, issue: 'deep-nesting', detail: `layout 嵌套 ${depth} 层——payload 与水合成本` });
    if (node.sizeKB > 150)
      findings.push({ segment: node.segment, issue: 'heavy-segment', detail: `段 bundle ${node.sizeKB}KB——超段预算` });
  });
  return findings;
}
```
