## MFW-193：笔试：手写拦截路由「软导航弹窗」状态判定器
**答**：App Router 拦截路由的本质是「同一 URL，软导航显示弹窗、硬导航显示整页」。实现判定器 `resolveRoute(pathname, navigationType)`：① 路由表声明每条路径的两种呈现（`modal` 与 `page`），拦截规则支持 `(.)` 同级、`(..)` 父级、`(...) `根匹配（内部实现可简化为「来源路由匹配」）；② 软导航（push/back）命中拦截规则 → 返回 `{ mode: 'modal', render: modal 路由 }`；③ 硬导航（刷新/直链）→ `{ mode: 'page' }`；④ 弹窗打开时 URL 已是目标页，返回上一段用 `router.back()` 而不是 push 回来（要判定「来源在历史中」才用 back，否则 fallback 到 push）；⑤ 关闭弹窗后刷新 → 整页正确渲染。

```ts
type Nav = 'push' | 'back' | 'refresh' | 'direct';
type Rule = { from: RegExp; modal: string; page: string };

const rules: Rule[] = [
  // 列表页点商品 → 弹窗；直接访问 /product/1 → 整页
  { from: /^\/list$/, modal: '/product/:id', page: '/product/:id' },
];

export function resolveRoute(pathname: string, nav: Nav, hasHistory = true) {
  for (const r of rules) {
    if (!matchModal(r, pathname)) continue;
    if (nav === 'refresh' || nav === 'direct') {
      return { mode: 'page', route: r.page }; // ③ 刷新/直链永远整页
    }
    return { mode: 'modal', route: r.modal }; // ② 软导航弹窗
  }
  return { mode: 'page', route: pathname };
}

function matchModal(r: Rule, pathname: string) {
  return r.modal === pathname || pathname.startsWith(r.modal.replace(':id', ''));
}

// ④ 关闭弹窗时的导航决策
export function closeModal(nav: Nav, hasHistory: boolean) {
  if (nav === 'push' && hasHistory) return { action: 'back' }; // 来源在历史栈中，back 回列表
  return { action: 'push', to: '/list' }; // 直链打开的弹窗：back 会离开站点，push 兜底
}
```

**评分点**：
1. 区分呈现层与 URL 层：弹窗和整页是**同一路由的两种渲染形态**，判定依据是导航来源（软/硬），不是 URL 不同。
2. 硬导航（refresh/direct）必须整页——这是拦截路由在真实站点上「可分享、可刷新」的保证，漏掉是核心扣分点。
3. closeModal 的 back/push 分支：直链弹窗直接 back 会把用户弹出站外，要 push fallback（很多实现忽略）。
4. 能说明 Next 里对应目录约定 `(.)`/`(..)`/`(...)@modal/default.js` 的角色，判定器是它的心智简化。
5. 状态恢复：刷新后弹窗内容来自 page 路由的完整数据（数据层不依赖弹窗上下文）。
