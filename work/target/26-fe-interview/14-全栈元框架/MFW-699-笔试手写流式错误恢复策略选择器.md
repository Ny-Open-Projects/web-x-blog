## MFW-699：笔试：手写流式恢复策略选择器

**答**：实现 `recoveryStrategy({ outputType, receivedBytes, totalEstimate, error })`。规则：1) 结构化输出（JSON/XML）→ 'discard'（半截无用——全清 RBL-698）；2) 文本流（LLM 文本）→ receivedBytes ≥ totalEstimate × 0.5 → 'keep-with-error'（过半保留）；< 50% → 'keep-with-error'（也保留——LLM 部分文本仍有价值——但标注「可能不完整」）；3) 二进制（文件流）→ 'discard'（半截文件损坏）；4) error 为 null → 'complete'（正常完成无策略）。返回 `{ strategy: 'keep-with-error'|'discard'|'complete', partial: boolean, hint }`。边界：receivedBytes=0（无内容——discard）；totalEstimate 缺失（保守 keep——文本类）；error 非 Error 实例（字符串包装）。

```javascript
function recoveryStrategy({ outputType = 'text', receivedBytes = 0, totalEstimate, error } = {}) {
  if (!error) return { strategy: 'complete', partial: false, hint: null };
  const msg = error instanceof Error ? error.message : String(error);
  switch (outputType) {
    case 'json': case 'xml':
      return { strategy: 'discard', partial: true,
        hint: `结构化输出不完整——丢弃（已收 ${receivedBytes}B）` };
    case 'binary':
      return { strategy: 'discard', partial: true,
        hint: '二进制流不完整——文件损坏，重新下载' };
    case 'text': default: {
      const ratio = totalEstimate ? +(receivedBytes / totalEstimate).toFixed(2) : null;
      return { strategy: 'keep-with-error', partial: true,
        hint: `文本流中断：保留部分内容${ratio !== null ? `（${Math.round(ratio * 100)}%）` : ''}——标注可能不完整` };
    }
  }
}

// 自测
// 正常完成
console.log(recoveryStrategy({ error: null }).strategy === 'complete');
// LLM 文本：保留
let r = recoveryStrategy({ outputType: 'text', receivedBytes: 500, totalEstimate: 1000,
  error: new Error('stream abort') });
console.log(r.strategy === 'keep-with-error' && r.hint.includes('50%'));
// JSON：丢弃
r = recoveryStrategy({ outputType: 'json', receivedBytes: 500,
  error: new Error('abort') });
console.log(r.strategy === 'discard');
// 二进制：丢弃
r = recoveryStrategy({ outputType: 'binary', receivedBytes: 100, error: 'x' });
console.log(r.strategy === 'discard' && r.hint.includes('损坏'));
// 无 totalEstimate 的文本
r = recoveryStrategy({ outputType: 'text', receivedBytes: 100, error: new Error('x') });
console.log(r.strategy === 'keep-with-error' && !r.hint.includes('%'));
// 零字节文本：也保留（LLM 部分文本——0 字节时 hint 提示）
r = recoveryStrategy({ outputType: 'text', receivedBytes: 0, error: new Error('x') });
console.log(r.strategy === 'keep-with-error');           // 文本类一律保留（策略一致性）
// 字符串 error
r = recoveryStrategy({ outputType: 'text', error: 'timeout' });
console.log(r.strategy === 'keep-with-error');
```

**评分点**：
- 三类输出的恢复策略（文本保留/结构化丢弃/二进制丢弃——部分内容可用性决定）
- 比例提示（receivedBytes/totalEstimate——用户可感知的完成度）；无 estimate 保守保留
- 边界（零字节/字符串 error/正常完成）；hint 的用户可读性
- 能说清「部分内容的价值决定恢复策略：文本保留标注、结构化丢弃——策略由可用性而非技术决定」属于加分
