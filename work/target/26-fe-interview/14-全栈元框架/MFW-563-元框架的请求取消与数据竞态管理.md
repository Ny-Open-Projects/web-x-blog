## MFW-563：软导航竞态：切换时的渲染取消与最后到达优先

**答**:
- 竞态场景：快速连续导航（/a → /b → /c）——三个渲染请求并发：谁的结果显示？——「最后到达优先」原则（c 的结果先到 → 先显示；b 后到 → 丢弃）——路由器维护「当前导航 token」，过期响应丢弃（RBL-640 取消语义的路由版）。
- 服务端取消：client 导航 abort → fetch abort → server 渲染中止（RBL-505：req close → abort 渲染——取消传播全链路：省 server 计算）。
- 竞态的具体形态：导航 A 慢（数据库 3s）、导航 B 快——B 先显示、A 后到覆盖 B？——路由器的导航序号守卫（stale response 丢弃）；「用户看到的页面 = 最后一次导航意图」而非「最后完成请求」。
- prefetch 与竞态：prefetch 的响应也过守卫（prefetch 完成时用户已导航走——结果进缓存无害 RBL-511）。
- 追问钩子：为什么「取消传播到 server」值得做（比仅 client 丢弃复杂得多）？——client 丢弃 = 用户看不到但 server 算完（CPU 白烧）；server 取消 = 数据库查询中止（省 DB/内存——大页面的渲染 3s = DB 查询 2.5s 全省）；「取消的价值 = 省下的可再生计算」（RBL-505 背压原则的取消版）：渲染不可再生（结果丢弃）但 DB 查询可中止——取消传播的深度 = 省的成本深度。

```javascript
// client 路由守卫（概念）
let navToken = 0;
async function navigate(href) {
  const token = ++navToken;
  const controller = new AbortController();
  const res = await fetch(href, { signal: controller.signal,
    headers: { 'rsc': '1' } }).catch(() => null);
  if (token !== navToken) return;                        // 过期导航丢弃
  const payload = await res.text();
  if (token !== navToken) return;                        // 双检（响应后仍可能过期）
  applyPayload(payload);
}
// server 取消传播
req.on('close', () => controller.abort());               // RBL-505
// 数据层：AbortSignal → db 查询中止
async function getProducts(signal) {
  return db.query('...', { signal });                    // pg 支持 signal → 查询取消
}
```
