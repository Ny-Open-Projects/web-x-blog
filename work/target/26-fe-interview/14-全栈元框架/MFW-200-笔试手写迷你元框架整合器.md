## MFW-200：笔试：手写迷你元框架整合器（路由 + 流式 SSR + 复水闭环）
**题目**：综合题。实现一个 200 行以内的迷你元框架核心 `createApp`：① 路由：支持 `/user/:id` 动态段匹配，命中返回 `{ page, data }`；② SSR：`renderRoute` 先跑 `data()`（服务端取数），再用极简渲染函数生成 HTML（页面用 data 渲染，允许 async 段——简化为两个同步段）；③ 脱水：把 `data()` 结果以 `<script type="application/hydration">` 注入（防 XSS 转义）；④ 复水：客户端 `hydrate` 读该 script，交给客户端渲染函数生成 DOM（简化 innerHTML）；⑤ 客户端导航：拦截 `<a data-link>`，fetch 目标路由 JSON（`Accept: application/json` 返回 data 不含 HTML），替换视图且**不重新请求服务端页面**；⑥ 请求并发安全：每请求独立的 data 上下文。

```ts
type Route = { pattern: RegExp; page: (data: any) => string; data: (params: any) => Promise<any> };
type App = { routes: Route[] };

function match(app: App, path: string) {
  for (const r of app.routes) {
    const m = path.match(r.pattern);
    if (m) return { route: r, params: m.groups ?? {} }; // ①
  }
  return null;
}

const esc = (s: string) => s.replace(/</g, '\\u003c').replace(/&/g, '\\u0026'); // ③ 防 XSS

export function createServer(app: App) {
  return async function handle(req: Request): Promise<Response> {
    const url = new URL(req.url);
    const m = match(app, url.pathname);
    if (!m) return new Response('404', { status: 404 });
    const data = await m.route.data(m.params); // ⑥ 每请求独立执行

    if (req.headers.get('accept')?.includes('application/json')) { // ⑤ 客户端导航取数端点
      return Response.json({ path: url.pathname, data });
    }
    const html = `<div id="app">${m.route.page(data)}</div>
<script type="application/hydration">${esc(JSON.stringify(data))}</script>
<script src="/client.js"></script>`;
    return new Response(html, { headers: { 'content-type': 'text/html' } });
  };
}

// client.js —— 客户端复水 + 软导航
export function createClient(app: App, initial: { path: string; data: unknown }) {
  const root = document.getElementById('app')!;
  const mount = (r: Route, data: unknown) => (root.innerHTML = r.page(data)); // ④ 极简复水
  let current = match(app, initial.path);
  mount(current.route, initial.data); // 首屏用脱水数据，不发请求

  document.addEventListener('click', async (e) => {
    const a = (e.target as HTMLElement).closest('a[data-link]');
    if (!a) return;
    e.preventDefault();
    const res = await fetch(a.href, { headers: { accept: 'application/json' } });
    const { data } = await res.json();                 // ⑤ 只取数据
    const m = match(app, new URL(a.href).pathname);
    mount(m.route, data);                              // 软导航不重新拉整页
    history.pushState({}, '', a.href);
  });
  window.addEventListener('popstate', () => location.reload()); // 简化：back 走硬导航
}
```

**评分点**：
1. 闭环完整：路由匹配 → 服务端 data() → HTML 渲染 → 脱水注入 → 客户端复水 → 软导航走 JSON 端点，六环缺一不可。
2. 脱水数据必须 XSS 转义后再进 script 标签（漏了这条是安全直接扣分项）。
3. 软导航与首屏共用同一 page 渲染函数（同一份路由表、同一份数据协议）——保证两端渲染结果一致，这正是元框架「同构」的要点。
4. 客户端导航请求带 `Accept: application/json` 协商，只取数据不拉整页，能说出「同一 URL 两种输出形态」。
5. 主动声明简化点与生产差距：真实框架还要处理布局嵌套、流式分段、错误边界、hydration mismatch 校验。
