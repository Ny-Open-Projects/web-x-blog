## MFW-641：水合优先级策略

**答**:
- 默认水合 = 树根开始（全页面顺序水合）——「交互区域优先」：用户最可能交互的组件先水合（视口内的 header/nav/主按钮）；实现层次：1) **HTML 流序**（交互组件的 chunk 前置——HTML 流内 script 的顺序 = 水合顺序 RBL-506）；2) **选择性水合**（React 18 的 selectHydration 语义：交互事件触发时优先水合目标组件——点击未水合组件 → 优先水合它再派发事件）；3) **Islands 策略**（client:visible/idle RBL-538——水合时机声明化）。
- 优先级的来源：RUM 交互热图（哪些组件被交互最多——优先级数据化 RBL-940 归因）；「交互概率 × 组件成本」的水合排序。
- 追问钩子：为什么「选择性水合」（点击触发优先水合）优于「全页面按序水合」？——全序水合：交互区域的组件排在第 100 位 → 等前面 99 个水合完才响应（INP 崩）；选择性：点击时立即优先水合「被点击的组件」（响应延迟 = 水合该组件的时间而非全页）；React 18 的 hydration priority + 事件重放（点击被缓存、水合后派发）——「用户意图驱动的水合顺序」优于「静态树序」——与 RBL-564 预取的意图分级同构。

```tsx
// 选择性水合语义（React 18.3+ 的 hydration 优化）
// SSR HTML：<button data-hydrate-priority="high">Add</button>
// 水合前点击：React 的全局事件委托捕获 → 优先水合该边界 → 重放事件
// RSC 树中标记优先级（框架实验特性）
// <Suspense fallback={<ButtonSkeleton />} hydrationPriority="high">
//   <AddToCartButton id={id} />
// </Suspense>
// 手动降级方案：原生事件委托（水合前收集、水合后重放）
if (!window.__hydrated) {
  document.addEventListener('click', (e) => {
    (window.__pendingClicks ??= []).push(e.target);      // 收集
  }, true);
}
window.__hydrated = true;
(window.__pendingClicks ?? []).forEach(el => el.click());  // 重放
```
