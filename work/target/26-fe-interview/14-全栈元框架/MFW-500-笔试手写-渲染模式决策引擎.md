## MFW-500：渲染模式决策引擎（500 张收官）
**需求**：实现 `decideRender(profile)`：输入页面画像，输出渲染策略与理由。画像字段：{ traffic(次/分), freshness(数据可容忍秒), personal(是否个人化), seo(是否需 SEO), buildCost(预渲染单页 ms), paths(路径基数, Infinity 表示无限) }。规则：1) personal → SSR（个人化不可缓存）；2) seo && paths ≤ 10000 && freshness ≥ 60 → SSG/ISR（构建成本可控才 SSG，否则 ISR）；3) freshness < 5 → SSR + s-maxage=freshness（短 CDN 缓存兜平峰）；4) 输出 { mode, revalidate, reasons[] }——reasons 每条独立可引用（决策引擎必须可辩护）。

```javascript
export function decideRender(p) {
  const reasons = []
  if (p.personal) {
    reasons.push('per-user content cannot be shared-cached')
    return { mode: 'ssr', revalidate: 0, reasons }
  }
  if (p.freshness < 5) {
    reasons.push(`freshness=${p.freshness}s too tight for ISR; use SSR + short s-maxage`)
    return { mode: 'ssr', revalidate: p.freshness, reasons }
  }
  if (p.seo && p.paths <= 10000) {
    if (p.buildCost * p.paths <= 3_600_000) { // 预渲染总耗时 ≤ 1h 才 SSG
      reasons.push('SEO required, bounded path space, build budget fits')
      return { mode: 'ssg', revalidate: false, reasons }
    }
    reasons.push('SEO required but build budget exceeded; fall back to ISR')
    return { mode: 'isr', revalidate: Math.max(60, p.freshness), reasons }
  }
  reasons.push('no SEO need, shareable content; ISR balances freshness and load')
  return { mode: 'isr', revalidate: Math.max(60, p.freshness), reasons }
}
```

**评分点**：
- 规则短路有序：personal > freshness > seo（个人化一票否决）
- 构建预算总量校验（paths × buildCost，不只看单页——SSG 爆炸的经典原因）
- revalidate 与 freshness 联动（下限 60s 防抖，策略输出可直接落 config）
- reasons 数组（决策可辩护：每个模式切换都有文字依据，不是拍脑袋）
