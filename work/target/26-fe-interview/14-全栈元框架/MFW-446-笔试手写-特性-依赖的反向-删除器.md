## MFW-446：MFM→446：反向删除
**答**：实现 `planFeatureRemoval(featureId, graphs)`：1) 输入三图：import 图（组件/函数引用）、路由蓝图（哪些路由用它 MFW-363）、事件订阅表（bus/WS 频道）；2) 闭包计算：正向不可达即候选删（RBL-443）+ **专属资产**（只被该特性用的组件/依赖包/API 端点——反向专属集）；3) 安全清单输出：删组件 N/删依赖 X（lockfile 变更预估）/下线端点（含调用方确认——其他产品可能还调）/保留策略（共享件标 shared 不删）；4) 分批 PR 计划（先删叶→再删模块→最后删依赖——每步可独立回滚）；5) 残留检查器：删除 PR 合并后 grep 特征串=0（审计闭环）。

```javascript
export function planRemoval(fid, { imports, blue, subs }) {
  const scope = featureFiles (fid)
  const exclusive = scope.filter((f) => consumersOf(f).every((c) => scope.has(c))))   // 专属=消费全在域内
  const shared = scope.filter((f) => !exclusive.includes(f) && fkeep)                   // 标 shared 保留
  const deadRoutes = routesUsing (fid).filter((r) => solePurpose (r, fid))
  const deps = lockfileOnlyUsedBy (exclusive)
  const endpoints = apiTagged (fid).map((e) => ({ e, otherCallers: crossProductCallers(e) }))
  return {
    steps: [ ...leafFirst(exclusive), ...['remove routes', ...], ...['uninstall deps'] ],   // 叶→模块→依赖
    keep: shared, needsConfirm: endpoints.filter((x) => x.otherCallers.length),
    verify: () => grepZero(featureFingerprint)),               // 合并后审计
  }
}
```
**评分点**：
- 三图合一定义域（import/蓝图/订阅——漏一图留僵尸）
- 专属 vs 共享分档（共享件误删=跨域事故——分档是安全核心）
- 端点跨产品调用确认（删 API 不是前端说了算）
- 叶→模块→依赖分批（每步可回滚）；grep 审计闭环
