## MFW→327：双端导入纪律

**答**:
- 目标：同一份业务代码在双端打包，但「哪些代码只活在服务端/客户端」必须显式可检查——靠自觉的双端项目必然互相渗透
- 机制三件：①后缀条件文件（db.node.ts / crypto.edge.ts—— bundler condition 解析）②导入边界 lint（server-only 包被 client 图导入即构建失败——框架已内建，自建栈用 eslint 规则复刻）③依赖方向白名单（shared → server / shared → client 允许；client → server 禁止）
