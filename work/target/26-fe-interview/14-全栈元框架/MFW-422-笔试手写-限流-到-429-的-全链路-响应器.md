## MFW-422：429 全链路
**答**：实现两端协作：①服务端 `rateLimited(res, { retryAfterSec, scope, limit })`——429 + Retry-After + RateLimit-* 三组头 + 结构化 body；②客户端 `with429Backoff(fn)`——读 Retry-After 退避（尊重服务器指令优先于本地指数）、抖动 ±20%、最多服从 2 次后放弃上抛（用户决策而非无限等）、同域 429 计数熔断（连续 5 次 → 全域暂停 30s——相关接口一起歇）。

```javascript
// 服务端
function rateLimitResponse({ retryAfterSec, scope, limit, remaining = 0 }) {
  return new Response(JSON.stringify({ error: { code: 'rate_limited', scope } }), {
    status: 429,
    headers: {
      'Retry-After': String(retryAfterSec),
      'RateLimit-Limit': String(limit), 'RateLimit-Remaining': String(remaining),
      'RateLimit-Reset': String(Math.ceil(Date.now() / 1000) + retryAfterSec),
    },
  })
}
// 客户端
export async function with429(fn, { maxServerWaits = 2, domainPauseMs = 30_000 } = {}) {
  let waits = 0, domain = domainOf(fn.url)
  if (Date.now() < pausedUntil.get(domain) ?? 0)) throw new DomainPaused()
  for (;;) {
    const r = await fn()
    if (r.status !== 429) { failStreak.delete(domain); return r }
    if (++failStreak.get(domain) >= 5) { pausedUntil.set(domain, Date.now() + domainPauseMs) }  // 域级熔断
    if (++waits > maxServerWaits) throw new RateExhausted(r)      // 上抛给用户决策
    const server = +r.headers.get('Retry-After'), local = 500 * 2 ** waits
    await sleep(Math.max(server ?? 0, local) * jitter(0.8, 1.2))  // 服务器指令优先
  }
}
```
**评分点**：
- 三组标准头（Retry-After/RateLimit-Limit-Remaining-Reset——RFC 9330 语义）
- 服务器指令优先退避（不盲指数——服务端知道自己的容量）
- 域级熔断（连续 429 → 相关接口一起歇——单点打满不逐个撞）
- 上抛边界（服从 2 次后交用户——无限礼貌等待是 UX 事故）
