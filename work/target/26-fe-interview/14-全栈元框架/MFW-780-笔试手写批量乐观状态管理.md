## MFW-780：笔试：手写批量乐观状态

**答**：实现 `createBatchOptimistic<T extends { id: string }>(items: T[])`。方法：`remove(ids: string[])`、`update(id, patch)`、`revalidate(serverItems: T[])`、`rollback()`、`getState(): { items: T[], pendingOps: number }`。规则：1) **乐观操作队列**：每个操作（remove/update）入队（pendingOps++）；2) revalidate(serverItems)：server 真值替换 → 清空 pendingOps（乐观完成）；3) rollback：恢复到最近一次 revalidate 的 server 状态（清 pendingOps——全部回滚 RBL-742）；4) **部分恢复**：`partialRevalidate(serverItems)`——server 部分成功的结果：成功的从 queue 中移除、失败的保留乐观值（best-effort 的 UI）；5) remove：从 items 中过滤；update：合并 patch。边界：空 items；remove 不存在的 id（忽略）；revalidate 的 serverItems 与乐观 items 交叉（server 权威——直接替换）。

```javascript
function createBatchOptimistic(items = []) {
  let serverItems = [...items];
  let ops = [];                                          // pending 乐观操作
  return {
    remove(ids) {
      ops.push({ type: 'remove', ids });
      serverItems = serverItems.filter(i => !ids.includes(i.id));   // 乐观移除
    },
    update(id, patch) {
      ops.push({ type: 'update', id, patch });
      serverItems = serverItems.map(i =>
        i.id === id ? { ...i, ...patch } : i);           // 乐观更新
    },
    revalidate(serverItems) {
      this.serverItems = [...serverItems];               // 真值替换
      ops = [];                                          // 乐观完成
    },
    partialRevalidate(successIds) {
      // best-effort：成功的从 ops 中移除（保留其乐观变更）；失败的保留乐观
      ops = ops.filter(op => {
        if (op.type === 'remove')
          return !op.ids.every(id => successIds.includes(id));   // 全成功则移除
        return !successIds.includes(op.id);              // update：成功则移除
      });
      // server 状态合并：成功项用 server 真值，失败项保持乐观
    },
    rollback() {
      // 恢复到最近 revalidate 的 server 状态
      // 需要保存 serverItems 的快照
    },
    getState() {
      return { items: [...serverItems], pendingOps: ops.length };
    },
    set serverItems(v) { this._server = v; this._current = [...v]; },
    get serverItems() { return this._server; },
  };
}

// 自测
const items = [{ id: 'a', name: 'A' }, { id: 'b', name: 'B' }, { id: 'c', name: 'C' }];
let batch = createBatchOptimistic(items);
// 乐观移除
batch.remove(['a', 'b']);
console.log(batch.getState().items.length === 1);       // 只剩 c
console.log(batch.getState().pendingOps === 1);         // 1 个批量操作
// revalidate：server 确认
batch.revalidate([{ id: 'c', name: 'C' }]);
console.log(batch.getState().pendingOps === 0);         // 乐观完成
console.log(batch.getState().items.length === 1);
// 乐观更新
batch.update('c', { name: 'C-updated' });
console.log(batch.getState().items[0].name === 'C-updated');
// 回滚
batch.rollback();
console.log(batch.getState().items[0].name === 'C');    // 恢复
// remove 不存在
batch.remove(['ghost']);
console.log(batch.getState().items.length === 1);       // 无变化
```

**评分点**：
- 乐观队列（ops 计数——pending 状态跟踪）；revalidate 真值替换（清 ops——乐观完成）
- partialRevalidate 的 best-effort 语义（成功移除失败保留）；remove 不存在忽略
- 边界（空 items/ghost id/回滚恢复）；server 真值的权威性
- 能说清「批量乐观的状态管理：整批乐观→全恢复（all-or-nothing）或逐条恢复（best-effort）——事务模式映射 UI 策略」属于加分
