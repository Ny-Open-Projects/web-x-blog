## MFW-224：D1 限制与规避

**答**:
- 硬限制清单：单库容量（GB 级）、单查询行数/时长限制、无长事务（Worker CPU 时间预算内）、写入主区域（单写多读——副本只读）、外键/复杂查询支持子集
- 规避策略：大数据拆库（按租户/时间分片 D1 database）、重查询下沉（聚合物化预计算——边缘只做点查）、事务改批次（batch API + 业务级幂等补偿）
- 适用判定：读多写少 + 点查为主 + 数据可分片 → D1 合适；重分析/大事务 → 留中心 Postgres + Hyperdrive
- 混合架构常态：D1 管边缘热数据（session/配置/计数），中心库管重数据——数据分域比「全上边缘」更现实

```text
D1 适合：点查/读多写少/可分片 GB 级
规避：拆库分片 / 预计算聚合 / batch+幂等替代长事务
混合：边缘热数据（D1）+ 中心重数据（PG+Hyperdrive）
```
