## MFW-707：笔试：手写批量部分成功

**答**：实现 `executeBatch(operations, { mode, chunkSize, retry })`。operations: `{ id, fn: () => Promise }[]`；mode: 'all-or-nothing'（全事务——任一失败全回滚）| 'best-effort'（部分成功——失败的记录继续）。规则：1) all-or-nothing：逐个执行，任一失败 → 返回 `{ committed: 0, failed, error: 第一个错误 }`（全回滚——无部分结果）；2) best-effort：逐个执行，失败记录继续 → `{ committed: number, results: Array<{ id, ok, error? }> }`；3) **重试**：best-effort 模式的失败项重试 retry 次（退避）；4) 分片：chunkSize 限制单批大小（超分）；5) 返回统一的 `{ committed, failed: Array<{ id, error }>, results }`。边界：operations 空（committed 0）；all-or-nothing 首个失败（立即停）；retry 与 all-or-nothing 冲突（忽略 retry）。

```javascript
async function executeBatch(operations = [], { mode = 'best-effort', chunkSize = 100, retry = 0 } = {}) {
  const failed = [], results = []; let committed = 0;
  const chunks = [];
  for (let i = 0; i < operations.length; i += chunkSize)
    chunks.push(operations.slice(i, i + chunkSize));
  for (const chunk of chunks) {
    for (const op of chunk) {
      let attempts = mode === 'best-effort' ? retry + 1 : 1;
      let done = false, lastErr;
      for (let a = 0; a < attempts && !done; a++) {
        try {
          if (a > 0) await sleep(500 * 2 ** (a - 1));    // 退避
          await op.fn();
          results.push({ id: op.id, ok: true });
          committed++; done = true;
        } catch (e) { lastErr = e; }
      }
      if (!done) {
        if (mode === 'all-or-nothing')
          return { committed: 0, failed: [{ id: op.id, error: lastErr?.message }],
            results: [], error: `事务回滚：${op.id} 失败` };
        failed.push({ id: op.id, error: lastErr?.message });
        results.push({ id: op.id, ok: false, error: lastErr?.message });
      }
    }
  }
  return { committed, failed, results };
}
const sleep = (ms) => new Promise(r => setTimeout(r, ms));

// 自测
const ops = [
  { id: 'a', fn: async () => {} },
  { id: 'b', fn: async () => { throw new Error('conflict'); } },
  { id: 'c', fn: async () => {} },
];
// best-effort：b 失败 c 继续
let r = await executeBatch(ops, { mode: 'best-effort', retry: 0 });
console.log(r.committed === 2);
console.log(r.failed[0].id === 'b' && r.failed[0].error === 'conflict');
console.log(r.results.length === 3);                     // 全部有结果

// all-or-nothing：b 失败全回滚
r = await executeBatch(ops, { mode: 'all-or-nothing' });
console.log(r.committed === 0);
console.log(r.error.includes('事务回滚'));
console.log(r.results.length === 0);                     // 无部分结果

// 重试：b 重试后成功
let callCount = 0;
const flakyOps = [{ id: 'flaky', fn: async () => { if (callCount++ < 1) throw new Error('net'); } }];
r = await executeBatch(flakyOps, { mode: 'best-effort', retry: 1 });
console.log(r.committed === 1);                          // 重试成功

// 空
r = await executeBatch([], { mode: 'best-effort' });
console.log(r.committed === 0 && r.failed.length === 0);
```

**评分点**：
- 双模式语义：all-or-nothing 首败即停全回滚（事务语义）/ best-effort 失败记录继续（可用性）
- 重试仅 best-effort 模式生效（all-or-nothing 的重试会破坏事务语义）；分片
- 边界（空/首败/重试成功）；统一返回结构
- 能说清「批量的事务边界是业务决策：库存扣减全事务、日志写入各自事务——原子性与可用性的权衡」属于加分
