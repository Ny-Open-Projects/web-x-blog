## MFW-384：副作用审计

**答**:
- 风险面：顶层副作用（import 时 setInterval/挂全局/打点）让「模块被谁加载」决定行为——tree-shaking 失效、双实例重复注册（部署×实例风暴）、测试污染全由此生
- 审计实现：构建期 AST 扫描模块顶层语句白名单（允许：常量/导出声明/显式注册器调用 `registerX()`——一切行为收敛到注册器，可枚举可禁用）→ 违规清单 PR 门禁
- 收益链：行为全经注册器 → 灰度按注册键禁用（某打点器一键关）→ 测试只注册被测项（隔离）→ SSR/客户端注册表分离（双端差异显式化）
- 迁移：存量逐个「副作用上提」refactor（行为不变测试先行）——与渲染纯度 lint（MFW-364）合成「加载与渲染双纯度」体系

```javascript
// ❌ import 即行为
import './analytics'          // 顶层 setInterval 上报
// ✅ 显式注册
import { registerOnce } from './boot'
registerOnce('analytics', initAnalytics)   // 白名单内；可按键禁用/单测隔离
```
