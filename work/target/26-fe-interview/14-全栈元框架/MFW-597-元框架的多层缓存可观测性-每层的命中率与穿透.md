## MFW-597：多层缓存可观测性

**答**:
- 四层缓存的可观测（RBL-508）：每层独立指标（命中率/延迟/大小）——「分桶维度」：路由 × 层 × 状态（hit/miss/stale）；「CDN 命中率 vs Data Cache 命中率」的差异解读（CDN 命中 = 用户快、Data Cache miss = 回源渲染——CDN 掩盖 Data Cache 问题 RBL-581）。
- 穿透的画像：Data Cache miss（每次回源查 DB）的比率——「miss 率高的 tag」= 失效过频（RBL-577 tag 粒度太粗）或 TTL 太短；「缓存命中率下降」的归因流程（RBL-851 看板 → 分桶 → tag/路由）。
- 观测的注入点：框架内埋点（Next 的 fetch 扩展拦截——cache 状态从响应头/内部状态读取）；「无侵入采样」vs「全量埋点」（开销权衡 RBL-728 采样策略）。
- 追问钩子：为什么「CDN 高命中率」可能是坏消息？——CDN 命中率高 = 大部分请求被 CDN 缓存挡住——但缓存的内容可能是旧的（ISR 未失效/失效管线丢失——RBL-590 死信）；「命中率高 = 缓存工作」与「命中率高 = 失效失效」是同一指标的两种解读——区分依赖「新鲜度 SLI」（RBL-904 抽样校验内容与源数据一致）：命中率 + 新鲜度双指标才是缓存健康。

```typescript
// 缓存可观测的分桶
interface CacheMetrics {
  layer: 'cdn' | 'fullRoute' | 'data' | 'router';
  route: string;
  status: 'hit' | 'miss' | 'stale-revalidated';
  latencyMs: number;
}
function aggregate(metrics: CacheMetrics[]) {
  const byLayer = {};
  for (const m of metrics) {
    const k = `${m.layer}:${m.route}`;
    byLayer[k] = byLayer[k] || { hit: 0, miss: 0, stale: 0, totalLatency: 0 };
    byLayer[k][m.status === 'stale-revalidated' ? 'stale' : m.status]++;
    byLayer[k].totalLatency += m.latencyMs;
  }
  return Object.entries(byLayer).map(([k, v]) => ({
    bucket: k, hitRate: +(v.hit / (v.hit + v.miss + v.stale) * 100).toFixed(1),
    p50: v.totalLatency / (v.hit + v.miss + v.stale),
  })).sort((a, b) => a.hitRate - b.hitRate);             // 命中率最低的桶最值得看
}
// 归因：miss 率高的 tag
// Data Cache miss 率 80% @ tag 'products'
// → RBL-577: tag 粒度太粗（任何变更全失效）？TTL 太短？失效管线风暴？
```
