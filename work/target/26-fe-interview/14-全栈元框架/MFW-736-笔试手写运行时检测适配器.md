## MFW-736：笔试：手写运行时适配器

**答**：实现 `detectRuntime()` 与 `createRuntimeAdapter({ bunImpl, nodeImpl, denoImpl })`。detectRuntime：检测当前运行时（globalThis 探测：Bun/Deno/process）。规则：1) Bun 优先（globalThis.Bun 存在）；2) Deno 次（globalThis.Deno）；3) 默认 node。createRuntimeAdapter：按运行时选择 impl（bunImpl/denoImpl/nodeImpl 的函数——runtime 特化的实现）；**fallback**：未提供当前 runtime 的 impl → 用 nodeImpl（Node 是最大兼容层——Deno/Bun 都兼容 Node API）；全部未提供 → 抛错。返回 adapter 函数（透传参数）。边界：globalThis 无 process（非 Node 环境——Deno 环境测试时 Deno 已检测）；impl 全空。

```javascript
function detectRuntime() {
  if (typeof globalThis.Bun !== 'undefined') return 'bun';
  if (typeof globalThis.Deno !== 'undefined') return 'deno';
  if (typeof process !== 'undefined' && process.versions?.node) return 'node';
  return 'unknown';
}
function createRuntimeAdapter({ bunImpl, nodeImpl, denoImpl } = {}) {
  const runtime = detectRuntime();
  const impls = { bun: bunImpl, deno: denoImpl, node: nodeImpl };
  const selected = impls[runtime] ?? nodeImpl ?? (runtime === 'unknown' ? null : nodeImpl);
  if (!selected)
    throw new Error(`运行时 ${runtime} 无可用实现——请提供至少 nodeImpl`);
  return (...args) => selected(...args);
}

// 自测
// Node 环境
let r = detectRuntime();
console.log(['node', 'bun', 'deno'].includes(r));        // 取决于测试环境

// 适配器选择
const bunImpl = (x) => `bun:${x}`;
const nodeImpl = (x) => `node:${x}`;
const denoImpl = (x) => `deno:${x}`;
// 当前环境是 node → nodeImpl
let adapter = createRuntimeAdapter({ bunImpl, nodeImpl, denoImpl });
console.log(adapter('test').startsWith(process.versions?.bun ? 'bun:' : 'node:'));
// 仅 nodeImpl → bun 环境下也用 nodeImpl（fallback）
adapter = createRuntimeAdapter({ nodeImpl });
console.log(adapter('fallback') === 'node:fallback');

// 全空抛错
e = null; try { createRuntimeAdapter({}); } catch (x) { e = x; }
console.log(/无可用实现/.test(e.message));

// denoImpl 在 deno 环境
// （模拟：无法直接模拟 Deno 全局——测试通过注入）
r = detectRuntime.call({ Bun: {} });
// 实际检测用 globalThis——测试环境不可模拟——检测逻辑按 globalThis 顺序
// bun > deno > node > unknown
```

**评分点**：
- 三级运行时检测（Bun > Deno > Node > unknown——globalThis 探测顺序）；fallback 到 nodeImpl（Node 兼容层）
- 适配器的函数式选择（runtime → impl 映射——特化路径）；全空抛错
- 边界（仅 nodeImpl 的 fallback/unknown）；Web 标准优先的适配哲学
- 能说清「Web 标准 API 是多运行时的最大公约数——适配层用标准 API 写代码即可跨运行时」属于加分
