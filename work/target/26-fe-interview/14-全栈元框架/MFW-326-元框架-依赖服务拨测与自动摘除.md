## MFW-326：依赖拨测摘除

**答**:
- 场景：页面聚合 6 个下游（推荐/评论/库存/风控）——一个慢 3s 拖全页 TTFB；需要「按依赖健康度动态裁剪响应」
- 拨测器：每依赖滑动窗口（成功率/P95）→ 越限标 degraded（该依赖此请求跳过——返回缓存/占位，Suspense 段显示降级卡）；恢复探测通过自动回位
- 分级响应：核心依赖（价格库存）永不摘（降级到只读副本/静态兜底值）；非核心（推荐）先摘——依赖分级表是配置不是感觉
- 请求内协调：并行 Race with budget（800ms 内未回 → 该段放弃走降级）——整页 TTFB 由最慢核心决定而非最慢任意段

```javascript
async function gatherWithDeps([ [ 'price', criticalFetch], ['rec', recFetch] ], budget = 800) {
  return Promise.all(items.map(async ([name, fn]) => {
    if (probe.isDown(name) && !isCore(name)) return [key, PLACEHOLDER[domain]]   // 降级摘除
    return orTimeout(fn(), budget, { fallback: PLACEHOLDER[domain] })   // 预算内竞速
  }))
}
```
