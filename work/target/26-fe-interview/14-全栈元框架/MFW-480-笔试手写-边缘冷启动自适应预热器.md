## MFW-480：边缘冷启动自适应预热器
**需求**：实现 `AdaptiveWarmer`：1) `record(route, ms)` 记录每路由实际延迟（滚动窗口 100 条）；2) `plan()` 生成预热清单：近窗口 p95 延迟 > 200ms 的路由进清单，按 p95 降序，上限 10 条（预热配额有限）；3) 抖动抑制：p95 与 p50 比值 > 3 视为"偶发抖动"不预热（预热解决不了抖动，别浪费配额）；4) `shouldWarm(route)` 幂等：已在当前清单中的路由重复 plan 不重复触发。

```javascript
export class AdaptiveWarmer {
  constructor() { this.win = new Map(); this.list = new Set() }

  record(route, ms) {
    if (!this.win.has(route)) this.win.set(route, [])
    const w = this.win.get(route)
    w.push(ms)
    if (w.length > 100) w.shift()
  }

  p95(a) { const s = [...a].sort((x, y) => x - y); return s[Math.floor(s.length * 0.95) - 1] ?? s[0] }
  p50(a) { const s = [...a].sort((x, y) => x - y); return s[Math.floor(s.length * 0.5)] ?? s[0] }

  plan() {
    const cands = []
    for (const [route, w] of this.win) {
      if (w.length < 10) continue // 样本不足不判断
      const hi = this.p95(w), lo = this.p50(w)
      if (hi <= 200) continue
      if (lo > 0 && hi / lo > 3) continue // 抖动非冷启动
      cands.push({ route, p95: hi })
    }
    this.list = new Set(cands.sort((a, b) => b.p95 - a.p95).slice(0, 10).map(c => c.route))
    return [...this.list]
  }

  shouldWarm(route) { return this.list.has(route) }
}
```

**评分点**：
- p95 分位而非平均（冷启动是尾部现象，均值会掩盖）
- p95/p50 > 3 判抖动（区分"持续慢"与"偶发慢"——预热只治前者）
- 样本量门槛 + 配额截断（小样本误判与无上限清单都是反模式）
- 清单幂等（重复 plan 不重复预热打爆自己）
