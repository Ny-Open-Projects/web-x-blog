## MFW-851：笔试：手写渲染取消信号沿流传播器（断连即停）

**答**：
- 结论：把 AbortSignal 从 HTTP 断连一路传到数据生产端；每次产出前检查 aborted，断开后停止迭代并清理资源。
- 关键：服务端用 res.on(close) 感知断连生成 signal；signal 传入 DB 查询可取消在途请求；finally 释放连接/定时器。
- 追问钩子：不可取消的查询怎么办？——至少停止渲染与输出、释放连接，避免继续占用服务端资源。

```javascript
async function* cancellable(producer, signal) {
  try {
    for await (const chunk of producer(signal)) {
      if (signal.aborted) return;                    // 断连 → 停止产出
      yield chunk;
    }
  } finally {
    // 清理：关闭 DB 游标、清定时器等
  }
}
function attachAbort(res, producer) {
  const ac = new AbortController();
  res.on('close', () => ac.abort());                 // 感知客户端断连
  (async () => {
    for await (const c of cancellable(producer, ac.signal)) res.write(c);
    if (!ac.signal.aborted) res.end();
  })();
  return ac;
}

// 自测：生产者感知 signal 提前停止
const producer = async function* (signal) {
  for (let i = 0; i < 5; i++) {
    if (signal.aborted) return;
    await new Promise(r => setTimeout(r, 10));
    yield 'chunk' + i;
  }
};
const ac = new AbortController();
let out = [];
(async () => { for await (const c of cancellable(producer, ac.signal)) out.push(c); })();
setTimeout(() => ac.abort(), 25);
setTimeout(() => console.log(out.length < 5), 80);   // true
```

**评分点**：
- AbortSignal 从断连传到数据生产端（可取消查询）
- 每次产出前检查 aborted，及时停止迭代
- finally 清理资源（连接/定时器），避免泄漏
- 服务端用 res close 感知断连；res.end 前再校验 aborted
