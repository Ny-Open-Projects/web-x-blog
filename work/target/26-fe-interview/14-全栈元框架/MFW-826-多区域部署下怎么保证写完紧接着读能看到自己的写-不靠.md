## MFW-826：多区域部署下怎么保证写完紧接着读能看到自己的写（不靠读主库）

**答**：
- 结论：用因果令牌：写响应返回该写的版本向量/因果上下文（token），后续读带上它；副本发现自己版本不足以覆盖 token 时，向持有该版本的节点补拉或等待。
- 与「读己之写走主库」不同：令牌让读继续走就近副本，必要时才回源，兼顾延迟与一致性。
- 追问钩子：token 丢失/过期怎么办？——回退读主库或等待窗口上限，语义降级但保证可用。

```javascript
// 写：返回因果令牌（本节点版本向量）
async function write(key, value) {
  const vv = await db.write(key, value);            // 返回版本向量
  return { ok: true, token: encodeVV(vv) };
}

// 读：带 token，副本检查是否覆盖
async function read(key, token) {
  const need = decodeVV(token);
  const node = nearestReplica();
  const local = await node.getVV(key);
  if (!covers(local, need)) {                       // 本地版本不足
    await node.catchUp(need, { timeout: 300 });     // 补拉/等待
  }
  return node.get(key);
}
function covers(have, need) {                      // have 是否覆盖 need
  return Object.keys(need).every(k => (have[k] || 0) >= need[k]);
}
```
