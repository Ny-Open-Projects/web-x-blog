## MFW-855：笔试：手写流式响应可缓存性判定器

**答**：
- 结论：个性化/Set-Cookie/Vary auth 一律不可共享缓存；chunked 且 TTFB 优先 → 不缓存；chunked 可接受缓冲 → 缓冲后缓存。
- 关键：返回清晰的 strategy 供路由配置直接消费；PPR 应拆成壳（缓存）+ 洞（流式私有）分别判定。
- 追问钩子：为什么 Set-Cookie 响应不能共享缓存？——会把 A 用户的会话 Cookie 发给 B 用户。

```javascript
function canCache({ isChunked, hasSetCookie, hasVaryAuth, personalized, ttfbFirst }) {
  if (hasSetCookie || personalized)
    return { cacheable: false, strategy: 'private,no-store', reason: '个性化/Set-Cookie' };
  if (hasVaryAuth)
    return { cacheable: false, strategy: 'private', reason: 'Vary: auth' };
  if (isChunked && ttfbFirst)
    return { cacheable: false, strategy: 'stream-no-store', reason: '边到边流优先 TTFB' };
  if (isChunked)
    return { cacheable: true, strategy: 'buffer-then-cache', reason: '需缓冲完整流' };
  return { cacheable: true, strategy: 'buffer-and-cache', reason: '常规' };
}

// 自测
console.log(canCache({ isChunked: true, ttfbFirst: true }).strategy); // stream-no-store
console.log(canCache({ isChunked: true }).strategy);                  // buffer-then-cache
console.log(canCache({ hasSetCookie: true }).cacheable);              // false
```

**评分点**：
- 个性化/Set-Cookie/Vary auth → 不可共享缓存
- chunked + TTFB 优先 → 不缓存；chunked 可缓冲 → 缓冲后缓存
- 返回清晰 strategy 与 reason，可被路由配置消费
- 能点出 PPR 拆分判定（加分）及 Set-Cookie 共享缓存风险
