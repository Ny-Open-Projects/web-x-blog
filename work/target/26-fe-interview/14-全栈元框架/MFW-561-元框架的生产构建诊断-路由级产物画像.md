## MFW-561：路由级产物画像与超预算路由

**答**:
- next build 的产物画像：每路由输出 First Load JS（共享 JS + 路由专属）——「路由级预算」（RBL-934 分配的落地：entryKB/routeChunksKB 逐路由门禁）；构建输出的路由表（静态/动态/ISR 标记 + First Load JS）。
- 超预算路由的归因流程：路由超预算 → 依赖分析（webpack-bundle-analyzer 的 Next 版/ turbopack 的 trace）→ 区分「共享 JS 膨胀」（所有路由受害——共享 chunk 治理）vs「路由专属膨胀」（该路由引入重依赖——按需化）；「共享 JS 的基线」是关键：共享层膨胀 = 全站路由预算全超（RBL-596 共享 chunk 的治理优先级最高）。
- 构建诊断的 CI 化：build 输出 → 结构化解析（路由/体积/静态标记 JSON）→ 预算比对（RBL-662 门禁）→ 归因报告挂 PR。
- 追问钩子：为什么「路由级预算」比「全站总量预算」更可执行？——全站总量（2MB）超标时不知道「谁的锅」（200 路由分摊）；路由级（每路由 First Load ≤ 200KB）= 责任到路由（超标路由明确——PR 引入该路由的作者自查）；预算的粒度决定责任的可归因性（RBL-855 成本模型的 CI 版）：预算是治理工具不是数字游戏——粒度 = 可行动性。

```javascript
// 构建输出的路由画像解析
// .next/app-path-routes-manifest.json + build manifest → 路由体积
function parseRouteProfile(buildOutput) {
  return Object.entries(buildOutput.pages).map(([route, files]) => ({
    route,
    firstLoadKB: sum(files.map(f => fileSize(f))) / 1024,
    type: buildOutput.staticRoutes.includes(route) ? 'static'
      : buildOutput.isrRoutes.includes(route) ? 'isr' : 'dynamic',
  })).sort((a, b) => b.firstLoadKB - a.firstLoadKB);
}
// 预算门禁（RBL-662 路由级）
const BUDGETS = { '/*': 200, '/dashboard/**': 350 };     // 通用 + 路由覆盖
function gateBudget(profile) {
  return profile
    .map(p => ({ ...p, budget: matchBudget(p.route, BUDGETS) }))
    .filter(p => p.firstLoadKB > p.budget)
    .map(p => ({ route: p.route, over: +(p.firstLoadKB - p.budget).toFixed(1),
      verdict: 'exceeded' }));
}
// 共享 JS 膨胀的识别
const sharedGrew = profile[0].firstLoadKB - profile.at(-1).firstLoadKB;   // 最轻路由的增量 ≈ 共享增量
```
