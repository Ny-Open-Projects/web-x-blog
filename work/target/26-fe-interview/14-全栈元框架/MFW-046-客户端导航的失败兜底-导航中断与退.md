## MFW-046：客户端导航失败（Payload 请求挂了）怎么兜底？
**答**：
- 客户端导航本质是 fetch 目标路由的 RSC Payload；网络失败/服务端 500 时 Next 会**回退为浏览器原生导航**（整页跳转），让服务端重新渲染或返回错误页——自动兜底。
- 若整页导航也失败，进入 error.js 边界或浏览器默认错误页；应用层可再包一层：监听 navigation error 上报并提示重试。
- 慢导航的用户体验：目标路由有 loading.js/Suspense 就会有即时反馈；没有则点击后界面「卡住」——**每个路由都该有 loading** 是基本素养。
- 拦截导航错误：`router.push` 没有回调/Promise，无法直接 try/catch；靠 error 边界 + window.onerror 全局兜底。
- 离线场景：Service Worker 缓存 Payload 实现弱网可用；或对关键导航 `router.push` 前先 navigator.onLine 检查。

```jsx
'use client';
import { useRouter } from 'next/navigation';

// 导航超时兜底：push 后 N 秒未完成（页面未切换）提示并强制整页跳转
function useSafeNavigate() {
  const router = useRouter();
  return (href) => {
    const timeout = setTimeout(() => {
      // Payload 请求迟迟无响应：回退原生导航，让服务端直接渲染
      window.location.href = href;
    }, 8000);
    // 导航成功会卸载当前页面，timeout 自然失效
    router.push(href);
    return () => clearTimeout(timeout);
  };
}

export function NavButton({ href, children }) {
  const nav = useSafeNavigate();
  return <button onClick={() => nav(href)}>{children}</button>;
}
```
