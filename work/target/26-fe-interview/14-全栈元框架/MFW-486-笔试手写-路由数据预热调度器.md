## MFW-486：路由依赖数据预热调度器
**答**：实现 `createWarmupScheduler({ routes, fetch })`：1) routes = [{ path, deps: ['user','products'] }]（构建期从蓝图提取）；2) 启动时对 deps 建倒排（dep -> routes），按"影响路由数"降序预热（影响越大的 dep 越先拉——一次预热救多条路由）；3) 预热调用 fetch 并写入 warm 缓存，同 dep 单飞；4) 失败的 dep 记入 `failed`，不影响其它 dep；预热完成触发 `onReady(pct)` 回调（部署探针依赖此信号）。

```javascript
export function createWarmupScheduler({ routes = [], fetch }) {
  const inverted = new Map()
  for (const r of routes)
    for (const d of r.deps)
      inverted.set(d, (inverted.get(d) || new Set()).add(r.path))

  const warm = new Map(), failed = new Set(), inflight = new Map()

  async function start(onReady) {
    const order = [...inverted.keys()]
      .sort((a, b) => inverted.get(b).size - inverted.get(a).size) // 影响面降序
    let done = 0
    await Promise.allSettled(order.map(async d => {
      if (inflight.has(d)) return inflight.get(d) // 单飞
      const p = fetch(d)
        .then(data => { warm.set(d, data) })
        .catch(() => failed.add(d))
        .finally(() => { inflight.delete(d); if (++done === order.length) onReady?.(done / order.length) })
      inflight.set(d, p)
      return p
    }))
  }

  return { start, get: d => warm.get(d), failed: () => [...failed] }
}
```

**评分点**：
- 倒排索引按影响面排序（预热顺序即收益顺序）
- Promise.allSettled（单 dep 失败不拖垮整批）
- 单飞 + failed 集合（重复触发与可观测缺失都会造成重复浪费）
- onReady 比例回调（健康探针依赖预热完成度信号）
