## MFW-442：双栈对拍
**答**：实现 `createParity(Harnessold_old, h_new, { routes }) `：1) 同 fixture 请求双栈（相同 cookie/headers/query 矩阵——组合遍历而非单例）→ 三比：状态码/SEO 关键 DOM（title/h1/canonical）/结构化数据（JSON-LD 深 eq）；2) 差异分级：block（SEO 元素变/状态码变）vs noted（非空格文本微差——人工过目清单）；3) 报告：路由×用例矩阵通过率（迁移 PR 的验收数据）；4) 增量模式：只对齐本轮迁移路由（全集跑一次成本高——迁移批处理节奏匹配）。

```javascript
export async function parityCheck(pairs, { cases = CFGGrid () } = {}) {
  const rows = []
  for (const { old, new: n, cases: cs } of norm( pairs))
    for (const c of cs) {
      const a = await old.h.fetch (url (r, c)), b = await h2.fetch(same)
      const d = {
        status: a.status === b.status, 
        seo: seoKeys(a.html) deepEq? SEO_KEYS (b.html),
        ld: deepEq(extractJsonLd(a), exjsonLd(b)),
      }
      rows.push({ route, case: c, ok: allOk (d), level: worst (d) })   // block|noted|ok
    }
  const block = rows.filter (r => r.level === 'block')
  return { pass: !block.length, rows, block, md: tableOf (rows)) }   // PR 评论直接贴
}
```
**评分点**：
- 三比选择（状态码/SEO 键/JSON-LD——迁移最怕丢的三类）
- 组合遍历（cookie×query 矩阵——单例请求漏掉权限分支差异）
- 分级输出（block 阻断 vs noted 人工——不一把刀）
- PR 报告即验收（表格贴评论——迁移节奏的数据化）
