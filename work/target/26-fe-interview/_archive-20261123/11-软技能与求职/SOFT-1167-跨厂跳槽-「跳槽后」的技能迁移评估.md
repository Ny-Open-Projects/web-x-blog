## 1167：跳槽前怎么评估「我的技能在新环境能迁移多少」

**答**：
- 技能分类：可迁移层（工程方法论/系统设计/协作能力——到哪都值钱）、半迁移层（框架经验——Vue 到 React 迁移成本低但非零）、不可迁移层（业务领域知识/公司内部系统——归零但通常也不计价）。
- 迁移评估三问：新公司的技术栈与我重合度多少（JD 与技术博客可查）、行业领域差异多大（电商->金融要重学的领域知识量）、我的「不可迁移层」占比多高（资深者常高估自己——50% 经验是领域绑定很常见）。
- 诚实的折价：不可迁移层高的跳槽要接受「能力重估期」（6~12 个月才能恢复原有产出水平）——把它计入跳槽成本（见离职成本卡），别用老环境的产出标准预期新环境。
- 加速迁移：入职前预学新栈核心（30 小时投入减少一半上手期）、入职后主动找「跨栈协作」任务（在协作中迁移最快）。

```text
技能迁移三层：
可迁移（方法论/设计/协作） / 半迁移（框架） / 不可迁移（业务/内部系统）
三问：栈重合度 / 领域差异 / 不可迁移占比
预期：能力重估期 6~12 月计入成本
加速：入职前预学 30h + 跨栈协作任务
```
