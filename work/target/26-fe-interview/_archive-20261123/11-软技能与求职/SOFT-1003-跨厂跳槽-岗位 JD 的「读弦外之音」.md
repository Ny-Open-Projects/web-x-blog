## 1003：JD 怎么读出岗位的真实情况

**答**：
- JD 情报点：「快速迭代」=可能加班多、「跨部门协作」=沟通成本高/扯皮多、「从 0 到 1」=业务不确定/可能被砍、「 mature system 维护」=创新少但稳、「全栈/一专多能」=人力紧张、「抗压能力强」=高压预警。
- 发布时间信号：挂了 3 个月还在招（难填——要么要求太高要么团队差）vs 刚发布（新鲜坑位）；频繁重发同一岗位（留不住人）。
- 要求倒推团队：JD 要求列表的「长度与广度」反映团队人力厚度——要求越全能，越说明人手不够；「精通 X/Y/Z + 加分 A/B/C」超过 10 条的慎入。
- 验证动作：JD 疑点在面试中逐个求证（把这些词变成你的提问清单），别在 offer 后才发现弦外之音。

```text
JD 弦外之音对照：
快速迭代 -> 加班预警 | 从0到1 -> 业务不确定
跨部门协作 -> 沟通成本 | 抗压 -> 高压
全栈 -> 人手紧张 | 挂3个月 -> 难填
要求>10条 -> 团队人力薄
动作：疑点变面试提问清单逐个求证
```
