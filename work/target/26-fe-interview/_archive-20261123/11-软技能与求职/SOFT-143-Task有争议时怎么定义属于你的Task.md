## SOFT-143：STAR 里 Task 归属有争议时（团队目标与个人任务混在一起），怎么定义属于你的 T？

**答**：
- T 必须是"可指认到个人"的任务：格式固定为"在 {团队目标} 下，我个人的任务是 {X}，成功标准是 {Y}"——前半句给上下文，后半句给个人 cut。
- 目标级 T（团队 OKR）不是你的 T；你从目标里领到的 slice 才是。面试官验证的就是这个 slice 是否真实存在且由你扛。
- 有争议的任务（你 claim 的部分别人也参与了）：用"我负责的部分 + 我独有的动作"双重限定，例如"配置层是我从 0 写的，其他人只在上面接业务"。
- T 里必须含成功标准：没有标准的 T 无法验证 R，也会被追问"你怎么知道做成了"。

```text
T 定义公式：
团队目标（1 句）+ 我领到的 slice（1 句）+ 成功标准（1 句）

示例：
"团队 Q3 目标是中台支撑 N 个业务方接入；我领到的
slice 是把表单配置化，标准是新业务表单接入 ≤ 0.5 人日、
零后端排期依赖。"

归属争议限定词：
"我从 0 写的 / 我主导评审定的 / 我负责其中的 X 层"
——避免裸写"我负责 XX 项目"这种可争议粒度。
```
