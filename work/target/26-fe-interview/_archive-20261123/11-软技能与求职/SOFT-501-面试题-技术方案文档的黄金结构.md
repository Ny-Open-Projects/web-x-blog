## SOFT-501：一份技术方案文档的标准结构（背景/目标/方案/风险/里程碑），每部分写到什么深度

**答**：
- 六段结构：背景与问题（为什么做，3 段内）→ 目标与指标（可量化的成功标准）→ 方案设计（含被否掉的备选方案——评审最看重这个）→ 风险与对策 → 里程碑（分阶段可验证）→ 资源与排期。
- 深度原则：背景给"决策者视角"（业务损失/机会成本），方案给"执行者视角"（能照着干活），备选方案给"被否原因"（证明你考虑过，不是只会一条路）。
- 长度纪律：正文控制在评审人 20 分钟能读完（约 2000 字+图），附录放细节。

**可复用模板**（方案文档骨架）：

```text
# XXX 技术方案
1. 背景与问题：现状→痛点（量化：耗时/故障/成本）→ 为什么现在做
2. 目标与指标：目标一句话 + 成功指标（基线→目标值）+ 非目标（明确不做什么）
3. 方案设计：
   3.1 总体架构图（一张图讲清）
   3.2 关键设计点（3~5 个，每个含决策理由）
   3.3 备选方案对比（A/B/C 表格 + 被否原因）
4. 风险与对策：top3 风险 + 触发条件 + 对策 + 兜底
5. 里程碑：阶段划分，每阶段有可验证交付物
6. 资源与排期：人力/依赖方/排期表
```

**反例**：方案文档只有"我们打算用 X 技术因为 X 很先进"，没有备选对比与量化目标——评审第一轮就会被打回。
