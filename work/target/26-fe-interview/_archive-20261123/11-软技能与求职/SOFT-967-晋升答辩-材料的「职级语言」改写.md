## 967：把「干活语言」改写成「职级语言」的要点

**答**：
- 语言层级对照：干活语言（我写了 XX 模块/修了 XX bug）→ 职级语言（我定义了问题/设计了机制/推动了组织采纳）——改写的核心是把「动作」升维成「决策与影响」。
- 高频升维对：修复 bug → 建立防复发机制；做技术选型 → 在 X 约束下的方案权衡与决策记录；带新人 → 建立人才培养机制产出 N 名合格执行者。
- 升维的底线：每个升维都要有证据兜底（说「机制」就要有机制文档与运行数据）——无证据的升维是「注水」，评委一戳就破。
- 自检方法：把材料通读一遍，标记所有「我做了/我负责了」句式，逐句升级为「我判断/我定义/我推动/我沉淀」句式并核对证据。

```text
升维对照表（须有证据兜底）：
修 bug -> 建立防复发机制（有机制文档）
技术选型 -> 约束下的权衡与 ADR（有决策记录）
带新人 -> 培养机制产出 N 名骨干（有成长记录）
自检：标记所有"我做了X" -> 升维 + 证据核对
```
