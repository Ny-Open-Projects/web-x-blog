## SOFT-105：简历深挖的"三连问"——为什么这么设计、有没有别的方案、坑在哪——怎么层层接住？

**答**：
- 三连问的考察逻辑：第一问看决策依据（有无 trade-off 意识），第二问看视野广度（知不知道备选），第三问看实战深度（真做过必有坑）。
- 每个简历技术点提前备好"决策卡"：选了什么、备选是什么、为什么放弃备选、代价是什么——四要素缺一不可。
- "坑"必须讲真实且有细节的坑（报错信息、定位过程），修饰过的完美故事是最大的红旗。
- 如果某问答不上，用"当时我的认知是 X，现在回头看 Y 更好"承认局限，比硬拗可信。

```text
决策卡模板（每个简历技术点一张）：
选型：{如 微前端 qiankun}
备选：{iframe 方案 / module federation}
放弃原因：{iframe 通信与登录态成本高，MF 构建耦合强}
代价（必答）：{qiankun 样式隔离开销 + JS 沙箱兼容成本}
坑与定位：{具体报错/现象 → 排查路径 → 最终修复}

答不上时兜底话术：
"这块当时是团队定的方案，我参与度在执行层；
如果让我现在重新评估，我会关注 {X}。"
```
