## OPS-241：审批流引擎怎么设计？
**答**：
- 审批即数据：审批流（节点/审批人/状态）结构化存储，由发布风险级别（SCN-OPS-202）动态装配——L0 零审批、L3 双人 + 值班。
- 审批节点路由：按角色（owner/平台/值班经理）而非具体人路由（人员变动不断流），代理规则（缺勤自动转交）。
- 超时与升级：审批超时升级（SCN-640 SLA 同手法），卡在审批的发布自动标注在看板（SCN-OPS-207 卡点）。
- 审批有效性：审批人必须能看到发布内容摘要（diff 摘要/影响面）——「盲批」是审批形式主义的标志，摘要生成是引擎的一部分。
- 追问钩子：为什么审批节点要「按角色路由」而不是指定人——指定人会因休假/离职卡死发布流（SCN-ENG-206 bus factor 问题）；角色路由 + 代理规则让审批流对人员变动鲁棒，审批职责随角色而非随个人。

```javascript
function assembleApprovalFlow(riskLevel) {
  const nodes = APPROVAL_TEMPLATES[riskLevel];         // L0 [] / L2 [owner] / L3 [owner, platform, oncall]
  return nodes.map(n => ({
    role: n.role,                                      // 角色路由非指定人
    approver: resolveActiveUser(n.role),               // 含代理规则
    timeout: n.timeout, escalateTo: n.escalateTo,
    brief: buildBrief(publishPlan),                    // 审批摘要（盲批防御）
  }));
}
```
