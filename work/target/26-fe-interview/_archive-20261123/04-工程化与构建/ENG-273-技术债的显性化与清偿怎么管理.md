## ENG-273：技术债怎么管理？
**答**：
- 债台账：每笔债登记（位置/成因/影响面/利息=每次触及相关代码的额外成本/清偿估时）——显性化是治理的前提，隐性的债无法排期。
- 利息优先：清偿排序按「利息 × 剩余寿命」而非「修起来的快感」——高频改动区的债优先（利息高）。
- 债务预算：每迭代固定比例（如 15%）时间偿还债务，债务 Ratchet（总量不增）；新债入账需登记（借钱要有凭证）。
- 反模式：把技术债当道德问题（指责）——债是工程决策的产物，治理靠机制不靠愧疚。
- 追问钩子：为什么「利息」是技术债排序的核心——同是 3 人日的债，在每周都改的支付模块（利息高）和三年没动的工具页（利息≈0）价值完全不同；按清偿快感排序会做一堆「漂亮但无用」的重构。

```javascript
const debtLedger = {
  register: (debt) => ({ ...debt, interest: debt.touchFrequency * debt.extraCost }),
  priority: sortByDesc(debt => debt.interest * debt.remainingLife),
  budget: { perIteration: 0.15, ratchet: 'total debt non-increasing' },
  antiPattern: '道德指责 → 换成台账 + 预算机制',
};
```
