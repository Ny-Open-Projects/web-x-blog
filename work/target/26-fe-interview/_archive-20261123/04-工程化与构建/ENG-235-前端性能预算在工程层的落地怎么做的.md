## ENG-235：性能预算怎么落地？
**答**：
- 预算分层：入口 bundle 预算（per-route）、chunk 预算、Lighthouse 分数门禁、RUM P75 目标——预算绑定到「路由/页面」而非全局总量（全局平均会掩盖烂页）。
- 门禁形态：PR 内 bundle 分析注释（每包增减可视化）+ 超 Ratchet 需评审；Lighthouse CI 对关键页面跑分。
- 预算制定：由「竞品对标 + 用户设备分布」推导而非拍脑袋；预算本身版本化（设备基线更新时调整）。
- 突破通道：确需超预算走「性能豁免审批」（说明理由 + 限期还债），防止一刀切堵死业务。
- 追问钩子：为什么预算要绑到路由级——全局预算下 A 页面超 500KB 被 B 页面省的 100KB「平均」掉；路由级让每个页面的劣化都显形，责任也路由到对应 owner。

```javascript
// lighthouserc.json
{ "ci": { "assert": {
  "assertions": {
    "categories:performance": ["error", { "minScore": 85 }],
    "resource-summary:script:total": ["error", { "maxNumericValue": 300 }]
  } } } }
// PR bundle diff 注释（per-route）
routes.map(r => `| ${r} | ${r.before}KB → ${r.after}KB | ${r.delta > 0 ? '⚠️' : '✅'} |`)
```
