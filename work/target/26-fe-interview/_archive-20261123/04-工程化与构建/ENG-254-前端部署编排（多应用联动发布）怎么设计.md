## ENG-254：多应用部署编排怎么设计？
**答**：
- 部署拓扑：应用间依赖（宿主需新版 SDK/子应用需新协议）显式声明为部署图；编排器按拓扑排序发布（SDK 先于宿主，宿主先于子应用）。
- 发布单元：一次「发布计划」包含多个应用的版本组合——组合整体验证（联调环境跑冒烟）后按序上线，支持整体回滚（按逆序）。
- 兼容窗口：跨应用协议变更走兼容期（新旧协议并存），部署编排里标「先行/滞后」角色。
- 编排可视化：发布计划看板（哪个应用在哪个阶段/卡在哪步），失败自动暂停后续步骤。
- 追问钩子：为什么「SDK 先行」是部署拓扑的第一规则——SDK 是被消费方；SDK 新版本先上，宿主逐步升级，随时可回退 SDK；反过来先发宿主则宿主引用的 SDK 能力不存在，必然报错。

```yaml
# deploy-plan.yaml —— 发布计划
steps:
  - app: @org/sdk, version: 2.0, role: first       # SDK 先行
  - app: host-shell, depends: [@org/sdk@2.0]
  - app: cart-mfe, depends: [host-shell@3.1], compatWindow: true
rollback: reverse-order
gates: [smoke-on-staging, canary-5min]
```
