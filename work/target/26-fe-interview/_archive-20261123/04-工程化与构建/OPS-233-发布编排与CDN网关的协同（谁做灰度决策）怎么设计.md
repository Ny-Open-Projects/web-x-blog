## OPS-233：灰度决策分层怎么设计？
**答**：
- 分层职责：CDN 边缘做「地域/粗粒度」（就近、无会话上下文）；网关做「用户级」（有会话身份，权威分流）；应用内 flag 做「功能级」（细粒度业务开关）——三层各管一段，越细越靠内。
- 决策单源原则：同一维度的决策只在一层做（用户分流只在网关），避免多层决策打架（CDN 说灰度、网关说非灰度）。
- 性能考虑：网关层决策每请求一次哈希（缓存决策结果按会话）；应用层 flag 读本地缓存（不阻塞渲染）。
- 跨层一致性：网关决策结果通过灰度标记传给应用层（SCN-OPS-216），应用层 flag 决策可参考灰度桶但独立计算。
- 追问钩子：为什么「用户级分流」必须放网关而不是 CDN 边缘——CDN 边缘无稳定会话上下文（用户身份 cookie 可能在回源时才可读），且边缘缓存会固化分流结果（同一边缘节点所有用户同一版本）；网关有会话且每请求可算，是用户级分流的唯一权威位置。

```javascript
// 三层分工
edge: { regionGate: true },                            // CDN：地域
gateway: { userSplit: 'authoritative', cacheBySession: true },  // 网关：用户级
app: { featureFlag: 'local-cache-first' },             // 应用：功能级
// 跨层传递：gateway -> X-Gray-Bucket -> app flag 参考
```
