## OPS-234：回滚决策树怎么设计？
**答**：
- 决策树主干：异常确认是本次发布引入？→ 是：① 版本切换类问题（资源/入口）→ 秒级回滚入口；② 代码逻辑问题 → 评估修复时长：修复 < 15min 且有热修通道 → 修复；否则回滚。→ 不是本次引入：转常规故障排查。
- 修复优先的条件：修复时间可预期 + 修复比回滚代价小（回滚会丢失新版本依赖的数据结构）——回滚不是免费的。
- 回滚代价评估项：新版本数据写入量（SCN-OPS-205 兼容成本）、用户已体验的新功能（回退感知）、灰度档位损失（要重新爬）。
- 决策记录：决策树执行的每步（为什么选修复/回滚）记录进发布审计——决策质量的复盘依据。
- 追问钩子：为什么「回滚代价评估」是决策树最容易被忽略的分支——回滚被默认为「免费按钮」，但新版本可能已写入新 schema 数据/用户已依赖新功能；评估代价（数据兼容/用户感知/灰度进度）后才选回滚或修复，是高级发布工程与「出事就回滚」的区别。

```javascript
function rollbackDecisionTree(incident) {
  if (!isIntroducedByRelease(incident)) return 'NORMAL_INCIDENT_FLOW';
  if (incident.type === 'entry/resource') return rollbackEntry();      // 秒级切入口
  const fixEta = estimateFixTime(incident);
  const rollbackCost = assessCost({ dataWrites: true, grayProgress: '50%', userAware: true });
  return fixEta < 15 * 60_000 && hasHotfixChannel()
    ? hotfix(incident)
    : rollbackCost.acceptable ? rollbackEntry() : escalate();          // 代价不可接受→升级
}
```
