## OPS-211：移动端灰度协同怎么做？
**答**：
- 双轨灰度：App 版本灰度（应用商店放量，天级）+ 端内 H5/配置灰度（分钟级）——策略上「Web 先行验证 + App 慢速跟随」，用 Web 灰度数据预判 App 风险。
- 审核窗口管理：App 提审与发布解耦——提审期间 Web 侧继续迭代；审核通过后按商店节奏放量，前端灰度系统识别「App 版本维度」分流。
- 强更与灰度联动：强更（强制升级）是高风险操作——强更开关本身要灰度（先 1% 用户验证强更弹窗体验）。
- 版本兼容矩阵：新版 App × 旧版服务端（及反向）的兼容测试矩阵进发布计划。
- 追问钩子：为什么「Web 先行」是移动端灰度的最佳前哨——Web 发布秒级回滚且流量同等真实；同一功能的 Web 版灰度数据（错误率/转化）可直接预判 App 版风险，把 App 的「不可快速回滚」风险前置到可回滚的 Web 侧消化。

```javascript
const mobileGray = {
  tracks: { web: '先行验证（分钟级回滚）', app: '商店放量（天级）跟随' },
  fleet: { reviewWindow: '提审与发布解耦', versionDim: '灰度按 App 版本分流' },
  forceUpdate: { grayFirst: true, note: '强更开关本身先 1% 灰度' },
  matrix: ['newApp×oldApi', 'oldApp×newApi'],   // 兼容矩阵进发布计划
};
```
