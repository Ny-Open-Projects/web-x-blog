## ENG-245：构建插件开发治理怎么做？
**答**：
- 插件清单治理：仓库内插件注册表（谁写的/作用/性能开销）——插件是构建黑盒化的主因，「幽灵插件」会让构建越来越慢且没人敢删。
- 性能约束：插件必须声明执行阶段与预估开销；新插件进 CI 构建耗时 diff 评审（ENG-221 Ratchet）。
- 编写规范：正确处理 watch 模式（增量/失效）、错误信息可行动、不阻塞主线程（重计算入 worker）。
- 测试：插件用 fixture 工程做快照测试（输入项目 → 产物断言），升级构建工具时插件回归有保障。
- 追问钩子：为什么插件要「fixture 快照测试」——插件逻辑在真实大型项目上难以断言；最小 fixture 工程让插件行为可复现可断言，构建工具大版本升级时插件回归成本可控。

```javascript
// 插件注册表
const plugins = {
  'svg-sprite': { stage: 'transform', cost: 'low', owner: 'infra', fixtures: 'test/fixture-svg' },
};
// 插件快照测试
await build(fixtures('svg-sprite'));
expect(readOutput('sprite.svg')).toMatchSnapshot();
```
