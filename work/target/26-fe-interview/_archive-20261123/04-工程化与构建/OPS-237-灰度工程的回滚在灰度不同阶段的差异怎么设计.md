## OPS-237：分阶段回滚怎么设计？
**答**：
- 阶段语义差异：1% 灰度出问题 → 回滚 = 档位归零（影响极小，直接回）；50% 出问题 → 先降档（50→10）止血再评估全回滚；100% 出问题 → 全量回滚 + 事故流程（SCN-OPS-227 善后）。
- 降档止血优先：降档比回滚温和（已灰度用户保留新版本，不再扩散）——除非问题对新版本用户本身有害。
- 回滚速度分级：1% 回滚 < 1 分钟（切入口）；100% 回滚 < 5 分钟（含验证）——SLO 按阶段设定。
- 阶段记录：每阶段的回滚决策差异记录进预案——值班不用现场判断「该归零还是降档」。
- 追问钩子：为什么 50% 阶段优先「降档」而不是「回滚」——50% 用户已在新版本稳定运行（问题可能只影响特定人群）；降档阻止扩散同时保留对新版本用户的观察窗口，信息价值高于直接回滚——「先止血再诊断」是灰度工程的核心节奏。

```javascript
function stageRollback(stage, incident) {
  if (stage.pct <= 1) return rollbackEntry({ full: true });          // 影响极小直接回
  if (stage.pct <= 50 && !incident.harmsNewUsers)
    return downgrade(stage, { to: 10 });                             // 降档止血保留观察
  return rollbackEntry({ full: true, aftermath: 'SCN-OPS-227' });    // 全量回滚 + 善后
}
// SLO: 1% 回滚 < 1min, 100% 回滚 < 5min
```
