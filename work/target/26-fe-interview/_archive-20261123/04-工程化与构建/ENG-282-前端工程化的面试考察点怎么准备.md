## ENG-282：工程化面试怎么答？
**答**：
- 考察三层：工具使用（用过什么）、机制理解（为什么这么设计）、体系思维（怎么权衡与演进）——高分在二三层。
- 答法框架：场景 → 约束 → 方案与取舍 → 效果数据——「我们 CI P95 从 40 分钟降到 8 分钟，靠 affected 构建与远程缓存，代价是输入声明的治理成本」比「我们用了 Turborepo」高两个档次。
- 高频深挖点：缓存失效的正确性、灰度回滚、依赖治理、monorepo 分工——这些有「错误答案」的题区分度最高。
- 反模式：背工具名/说不出代价与副作用——工程化的每个方案都有代价，能讲代价才证明真做过。
- 追问钩子：为什么面试官总要追问「代价是什么」——只讲收益的方案人人会背；代价（维护成本/迁移成本/失效风险）体现的是真实权衡经验，这是工程化面试的核心区分度。

```javascript
const interviewFramework = {
  structure: ['场景', '约束', '方案+取舍', '效果数据'],
  depthSignals: ['缓存失效正确性', '回滚预案', '治理成本'],
  redFlags: ['只列工具名', '讲不出代价', '度量缺失'],
  sample: 'CI 40min→8min：affected 构建 + 远程缓存；代价 = 输入声明治理 + 缓存污染防护',
};
```
