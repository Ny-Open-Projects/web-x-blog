## ENG-267：构建配置抽象怎么治理？
**答**：
- 抽象层级：preset 包（`@org/vite-preset-react`：完整配置闭包）优先于零散配置片段——preset 是「可版本化的最佳实践」，项目一行引用。
- 抽象的成本边界：preset 暴露 override 入口（项目可覆盖），禁止 preset 内部 if-else 分叉出「魔法行为」——抽象越多调试越黑盒。
- 升级编排：preset 升级 = 全仓配置升级，用 codemod 处理 override 兼容（ENG-207 手法）。
- 度量：配置重复度统计（各项目 vite.config 与 preset 的 diff 行数）——diff 越大说明 preset 覆盖不足或项目特殊需求应回馈 preset。
- 追问钩子：为什么「项目 config 与 preset 的 diff」是抽象健康的温度计——diff 小说明 preset 吸收了共性（抽象有效）；diff 持续增长说明共性没被沉淀回 preset，抽象正在失效，需要把新模式上收。

```typescript
// preset 包：完整闭包 + override 入口
import { defineConfig, presetReact } from '@org/vite-preset';
export default defineConfig({
  extends: presetReact({ ssr: false }),
  override: { server: { port: 3000 } },    // 显式覆盖，可枚举
});
// 健康度
const dupRate = avg(projects.map(p => configDiffLines(p, preset)) );
```
