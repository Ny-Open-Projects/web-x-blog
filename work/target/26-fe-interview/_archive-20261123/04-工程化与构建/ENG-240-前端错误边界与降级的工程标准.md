## ENG-240：错误处理工程标准怎么定？
**答**：
- 错误分级：渲染错误（ErrorBoundary 分区：页面级/模块级/组件级）、请求错误（统一错误模型：可重试性/用户文案/上报级别）、未知错误（全局兜底 + 上报）——每类有标准处理路径而非各写各的。
- 上报标准：错误上报带上下文（buildinfo/路由/用户操作序列/采样决策），错误 fingerprint 聚合（同因合并）——没有聚合的错误上报是噪音洪水。
- 降级标准：每个关键模块声明降级态（错误 UI/缓存数据/隐藏模块），错误不升级为整页白屏。
- 防重复上报：同一错误会话内限频，恢复后重置。
- 追问钩子：为什么错误要带「用户操作序列」——同样一个 undefined 报错，用户刚点了提交和刚进页面含义完全不同；操作序列是复现的最短路径，比堆栈更快定位。

```javascript
// 分区边界标准
<PageBoundary>            // 页面级：整页兜底
  <ModuleBoundary name="checkout" fallback={CachedFallback}>  // 模块级：缓存降级
    <CheckoutForm />
  </ModuleBoundary>
</PageBoundary>
// 统一错误模型
{ code: 'NET_TIMEOUT', retryable: true, userText: '网络不稳，点击重试', reportLevel: 'warn' }
```
