## ENG-238：前端 DI 怎么设计？
**答**：
- 适用场景：多实现切换（支付渠道/存储后端）、测试替换（mock 注入）、平台差异（web/electron 能力层）——DI 的价值是「可替换性」，不是炫技。
- 轻量实现：React 语境下 Context + Provider 已是 DI；复杂域（SDK/服务层）用轻量容器（token 化注册 + 生命周期管理）。
- 生命周期对齐：容器实例与页面/应用生命周期绑定（页面卸载 dispose），防泄漏。
- 可测性收益：服务层构造函数注入依赖，单测直接传 mock——服务层可测性是 DI 的最大回报。
- 追问钩子：为什么前端 DI 常做过度——前端多数「多实现」场景频率低（一年切一次），运行时 DI 容器的复杂度不值；先用「参数化构造 + 模块顶层组合」，真有多环境热切换需求再上容器。

```typescript
// 服务层 DI（token 化轻量容器）
const StorageToken = createToken<Storage>('storage');
container.register(StorageToken, isElectron ? ElectronStorage : IndexedDBStorage);
// 服务层可测性
class SyncService { constructor(private storage: Storage) {} }
// 测试: new SyncService(mockStorage) —— 无需容器
```
