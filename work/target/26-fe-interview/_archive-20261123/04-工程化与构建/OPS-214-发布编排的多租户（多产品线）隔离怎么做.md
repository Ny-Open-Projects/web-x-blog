## OPS-214：多产品线发布隔离怎么做？
**答**：
- 资源隔离：发布基础设施（runner/编排器/CDN 配额）按产品线分池——一条线的发布风暴不阻塞其他线（SCN-ENG-278 配额同源）。
- 窗口隔离：各产品线独立发布窗口（互不冲突），公共依赖（共享 SDK）的发布要协调所有消费线（发布计划聚合视图）。
- 风险隔离：一条线的事故不自动波及其他线（独立域名独立降级矩阵），但共享依赖事故需要全局预案。
- 治理统一：隔离不等于各自为政——发布分级/审批/哨兵标准全局统一，执行按线自治。
- 追问钩子：为什么「标准统一、执行自治」是多租户发布的正确姿势——完全自治会让各线质量水位漂移（A 线有哨兵 B 线没有），标准也失去可比性；统一标准 + 按线执行既保治理一致性又保灵活性，这是平台化治理的通用模式。

```javascript
const multiTenantRelease = {
  isolation: { runner: 'per-tenant-pool', window: 'per-tenant', blastRadius: 'independent-domain' },
  shared: { sdkRelease: 'aggregated-plan-across-consumers' },
  governance: { standards: 'global (分级/审批/哨兵)', execution: 'per-tenant' },
};
```
