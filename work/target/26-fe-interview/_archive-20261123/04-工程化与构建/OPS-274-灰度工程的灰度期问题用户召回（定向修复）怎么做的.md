## OPS-274：问题用户定向处理怎么做的？
**答**：
- 定向修复场景：问题只影响灰度组（版本 bug 但影响面小）——处置选项：定向 push/站内信告知 + 回滚该用户组（组级回滚比全量回滚温和）。
- 组级回滚：灰度引擎支持「按组回滚」（灰度组用户切回旧版本，其他用户不受影响）——灰度不是只有全量/全无。
- 用户数据修复：灰度期写入的脏数据（新版本 bug 产生）——识别（灰度标记关联的数据）+ 修复任务（对账模式，SCN-867 同源）。
- 沟通义务：受影响用户的补偿/说明（体验受损要有交代），客诉话术更新。
- 追问钩子：为什么「组级回滚」是灰度体系必须有的能力——全量回滚对「问题只在灰度组」的情形是过度反应（100% 用户承受回滚代价）；组级回滚把修复的影响面精确到受影响人群，是灰度细粒度控制的终点形态——没有组级回滚的灰度体系，遇到小范围问题只能选择过度回滚或带病运行。

```javascript
async function groupRollback(grayGroup) {
  // 只对该灰度组用户切回旧版本
  grayEngine.setOverride(grayGroup.users, { version: 'stable' });
  notify(grayGroup.users, { template: 'gray-fix' });    // 定向沟通
  scheduleDataRepair(grayGroup.dirtyData);              // 脏数据修复任务
  audit({ action: 'group-rollback', group: grayGroup.id, by: oncall });
}
```
