## OPS-207：发布进度看板怎么搭？
**答**：
- 看板三区：进行中（当前阶段/卡在哪步/谁在操作）、今日发布（全部计划与状态）、风险区（超时未完成的发布/卡住的灰度/待回滚）。
- 实时性：编排器事件流（step-started/step-failed/rollback-started）推送更新看板，发布人不用刷页面盯日志。
- 卡点自动标注：步骤执行超时（如 canary 观察 30min 未动）自动标黄并 @发布人——「卡住但没人发现」是发布事故的常见起点。
- 审计回放：每次发布的事件时间线归档，复盘时回放完整过程（谁/何时/做了什么决策）。
- 追问钩子：为什么看板要「卡点自动标注」而不是只显示状态——状态显示「进行中」无法区分「正常灰度观察」与「卡死了没人管」；超时标注把「时间异常」显性化，这是发布流水线最有价值的自动化之一。

```javascript
const releaseBoard = {
  live: orchestrationEvents.subscribe(),               // 事件流实时
  stuck: (step, now) => step.startedAt + step.timeout < now
    && notify(step.owner, `步骤 ${step.name} 超时未动`),   // 卡点标注
  zones: ['live', 'today', 'risk'],
  audit: '事件时间线归档可回放',
};
```
