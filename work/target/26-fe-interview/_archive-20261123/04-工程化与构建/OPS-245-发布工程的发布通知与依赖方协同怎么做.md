## OPS-245：发布通知怎么协同？
**答**：
- 通知矩阵：发布前（预告：时间/范围/影响面 → 依赖方评估）、发布中（事件流：关键节点状态）、发布后（结果：成功/回滚 + 哨兵摘要）——依赖方（App 团队/后端/客服）按需订阅。
- 依赖方清单管理：哪些系统依赖本次发布（API 变化/协议变化）显式声明在发布计划——通知发「对的人」而非全员广播。
- 通知渠道分级：广播（结果通知）vs 定向（API 变更必须确认收到）——需要 ack 的通知才有约束力。
- 通知静默合并：高频灰度放量不逐次通知（每日摘要合并），关键节点（回滚/熔断）即时通知——降噪与即时性的平衡（SCN-OPS-612 同手法）。
- 追问钩子：为什么「API 变更通知」必须带 ack 而结果通知可以广播——API 变更需要依赖方做适配动作（不改就挂），广播没有确认机制等于没通知；ack 机制把「通知」变成「协议」，未确认前发布门禁可拦截——通知的约束力必须与依赖方的动作成本匹配。

```javascript
const notifyMatrix = {
  pre: { to: dependents(plan), needAck: hasApiChange(plan) },    // API 变更必须确认
  during: { events: orchestrationEvents, channel: 'watch-room' },
  post: { summary: sentinelDigest, broadcast: true },
  noise: { grayAdvances: 'daily-digest', critical: 'immediate' },  // 降噪合并
  gate: !allAcked(dependents) && blockRelease(),       // 未确认不发布
};
```
