## OPS-263：高频发布冲突怎么处理？
**答**：
- 冲突场景：A 的灰度未完成时 B 要发——灰度中的版本是「当前生产版本」，B 的发布必须基于 A 完成后的状态（或显式叠加策略）。
- 发布队列：同应用发布强制串行（互斥锁，SCN-ENG-276 并发安全），队列可视化（谁在等谁）。
- 叠加策略：灰度中可「基于当前灰度版本叠加新变更」重新构建（新 commit 包含 A 的变更）——前提是 A 已 merge 到主干（灰度代码在主干）。
- 插队规则：hotfix 可插队但触发灰度中的版本「快速收口」（全量或回滚）——hotfix 基于旧版本会让灰度版本变成孤儿。
- 追问钩子：为什么 hotfix 插队要「强制收口灰度」——hotfix 通常基于旧版本分支，若灰度版本继续存在，修复后会产生「hotfix 版本」与「灰度版本」两条线（修复可能没进灰度版本）；收口（全量或回滚）让版本线归一，修复的覆盖面才完整。

```javascript
const publishQueue = {
  mutex: 'per-app serial (SCN-ENG-276)',               // 同应用串行
  stackStrategy: 'rebuild-on-top-of-current-gray',     // 灰度代码必须在主干
  hotfix: { jump: true, forceGraySettle: '全量或回滚' },  // 插队先收口
  visibility: queueBoard(),                            // 队列可视化
};
```
