## ENG-229：凭据与敏感配置怎么管理？
**答**：
- 分层原则：前端产物里永远不该有密钥（public 配置白名单化）；服务端凭据走密钥管理服务（KMS/Vault），构建时注入运行时而非打进产物。
- 泄露防线：pre-commit secret 扫描（gitleaks）+ CI 全历史扫描 + 泄露应急（轮换流程 < 1h）——扫描是降低概率，轮换流程是兜底。
- 环境变量治理：.env 模板进仓库（字段名与说明），真实值走密管；CI 变量分级（公开 build 参数 vs secret 引用）。
- 事故复盘：泄露事件必复盘「为什么扫描没拦住」+ 补规则。
- 追问钩子：为什么「构建时注入运行时」优于「打进产物」——打进产物的密钥随 bundle 分发到所有用户浏览器（公开）；运行时注入（SSR 环境变量/配置接口）密钥只存在服务端内存，暴露面差几个数量级。

```bash
# pre-commit secret 扫描
gitleaks protect --staged --redact
# CI 全历史扫描（增量）
gitleaks detect --log-opts="--since=$(last_scan)"
# 泄露应急
rotate-credential --immediate && audit-usage --last-24h
```
