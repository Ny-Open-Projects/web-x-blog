## ENG-233：组件库构建发布怎么设计？
**答**：
- 产物矩阵：ESM/CJS/类型（d.ts）/CSS（vars+components）/源码 map——exports 字段声明清晰（import/require/types 三键），sideEffects 标注让消费方 tree-shake。
- 类型治理：d.ts 用 api-extractor 抑制膨胀 + API report（导出变更进 PR diff，breaking 一眼可见）。
- 发布流程：CI 构建 → 产物 hash 校验 → npm provenance 签名 → 发布 → 接线文档站版本化部署。
- 消费兼容：peer deps 声明 React 版本范围；prepublishOnly 全链校验；dist-tags 策略（next 通道灰度）。
- 追问钩子：为什么 api-extractor 的 API report 值得维护——导出签名变化以 diff 形式出现在 PR 里，评审者不用逐个文件找 breaking；这是「组件库不炸消费方」的最廉价保险。

```jsonc
// package.json exports 矩阵
{ "exports": {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.mjs", "require": "./dist/index.cjs" },
    "./styles.css": "./dist/styles.css" },
  "sideEffects": ["**/*.css"],
  "publishConfig": { "provenance": true } }
```
