## OPS-208：发布演习怎么做的？
**答**：
- 演练矩阵：正常发布走查（新人按 runbook 跑一遍）、失败注入（编排第二步故意失败验证回滚）、超时注入（canary 卡住验证告警）、回滚演习（真实回滚预发到上一版本）。
- 演练判据：每项有预期行为（回滚在 5 分钟内完成/告警 2 分钟内触达），实际差距即改进项。
- 频率与触发：每季度例行 + 重大编排变更后必演；未演练的编排能力视为不存在（SCN-861 同纪律）。
- 演练资产：演练脚本（可重复执行）与结果档案，编排变更的回归依据。
- 追问钩子：为什么「失败注入」是发布演习的核心——正常发布走查只能验证「顺的时候对」；编排的真正价值在「坏的时候不失控」，只有注入失败才能验证回滚/暂停/通知这些异常路径——而它们恰恰是事故时刻唯一能依赖的。

```yaml
# release-drill.yaml
scenarios:
  - name: normal-publish, judge: runbook-complete < 30min
  - name: fail-at-step-2, inject: rollback-trigger
    judge: { rollbackDone: '< 5min', notify: '< 2min' }
  - name: canary-stuck, inject: timeout
    judge: { stuckAlert: true }
schedule: quarterly + on-major-change
```
