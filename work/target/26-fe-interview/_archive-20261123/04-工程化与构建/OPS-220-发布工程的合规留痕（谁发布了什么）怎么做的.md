## OPS-220：发布合规留痕怎么做的？
**答**：
- 留痕要素：每次发布记录（触发人/审批链/发布内容 commit/产物 hash/目标环境/时间）——产物 hash 让「线上 bundle 确实来自该次发布」可验证（SCN-ENG-222 可复现构建联动）。
- 不可篡改：发布日志只追加不可改（append-only），与 CI 系统直连（非手工填写）。
- 查询场景：审计（谁在什么时候发了什么版本）/客户质疑（当时线上是什么版本）/事故回溯（出问题的版本是哪次变更引入）。
- 与变更管理联动：发布记录关联变更单/工单（发布不是孤立的，是变更管理的最后一环）。
- 追问钩子：为什么「产物 hash」是发布留痕的关键要素——commit 只是源码凭证，产物 hash 才是「部署实体」的凭证；有了 hash（配合可复现构建）可以证明「线上这份 bundle 确实由该 commit 构建而来」，审计与事故回溯才闭环。

```javascript
// 发布留痕（append-only）
releaseLog.append({
  by: triggerUser, approvals: chain, commit: sha,
  artifacts: { entry: buildHash, chunks: manifestHash },
  env: 'prod', ts: now(), changeTicket: ticketId,
});
// 查询：谁发了什么
releaseLog.query({ by, range })  // → 审计/事故回溯
```
