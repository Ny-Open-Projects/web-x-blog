## ENG-226：工程化 ROI 怎么评估？
**答**：
- ROI 公式落地：节省工时（构建提速 × 人数 × 频次、事故减少的损失）− 建设与维护成本；用「人时」折算成管理者听得懂的语言。
- 量化基线：建设前采样基线（构建时长/CI 时长/事故率），建设后同口径对比——没有 before 数据的 ROI 都是编的。
- 间接价值显性化：质量门禁拦住的 bug 数（每拦一个 ≈ 线上事故成本）、onboarding 时长缩短 → 折算招聘产能。
- 叙事策略：给管理层讲「风险与产能」（事故率/交付速度），给工程师讲「摩擦消除」——同一套数据两种叙事。
- 追问钩子：为什么「事故减少」比「构建提速」更打动管理层——构建提速省的是小钱（小时级），事故省的是大钱（资损+信任）；ROI 报告要把工程化与风险成本挂钩而不是只讲效率。

```javascript
const roi = {
  savings: {
    build: (savedMin, devs, freq) => savedMin * devs * freq / 60,   // 人时/月
    incidents: (avoided, costPerIncident) => avoided * costPerIncident,
    gate: (caughtBugs) => caughtBugs * bugFixCostOnline,
  },
  costs: { build: engMonths, maintain: engMonthsPerYear },
  before: '必须先采样基线，否则 ROI 无从谈起',
};
```
