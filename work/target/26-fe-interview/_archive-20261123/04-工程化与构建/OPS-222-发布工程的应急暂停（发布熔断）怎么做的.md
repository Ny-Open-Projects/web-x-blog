## OPS-222：发布熔断怎么做的？
**答**：
- 熔断语义：暂停后续放量（冻结当前档位）vs 紧急回滚——两个动作分开（先冻结止血，再判断回滚）；「一键熔断」只做冻结，回滚是独立决策。
- 熔断触发：自动（哨兵超阈值）+ 手动（值班/发布人/值班经理均可触发——触发权限放宽，因为漏触发代价大于误触发）。
- 熔断执行：编排器收到熔断立即暂停 + 通知发布人 + 状态标红；已分发的流量保持当前版本（不再扩散）。
- 解除熔断：需明确解除条件（指标恢复/根因排除），解除也是审计动作。
- 追问钩子：为什么熔断要「冻结不回滚」且触发权限放宽——冻结是低风险动作（阻止爆炸半径扩大，当前版本已稳定运行则维持）；回滚是高风险动作（可能引入新问题）；权限设计让「人人可刹车」但「刹车不等于掉头」，两权分离防止误操作。

```javascript
function circuitBreak({ by, scope = 'current-release' }) {   // 触发权限放宽
  orchestrator.pause(scope);                          // 冻结当前档位（不回滚）
  notify([releaseOwner, oncallMgr], `发布熔断 by ${by}`);
  audit({ action: 'BREAK', by, scope, ts: now() });
  // 回滚是独立决策（rollback 是高风险动作，不与熔断捆绑）
}
function resume({ condition, by }) { require(conditionMet(condition)); audit({ action: 'RESUME', by }); }
```
