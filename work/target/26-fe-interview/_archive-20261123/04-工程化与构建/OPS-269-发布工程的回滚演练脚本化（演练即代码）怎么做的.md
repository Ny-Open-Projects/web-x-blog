## OPS-269：演练即代码怎么做的？
**答**：
- 脚本化：演练场景（故障注入/回滚步骤/判定标准）以代码/配置形式版本管理——演练剧本与 runbook 同源（SCN-OPS-217 预案卡片驱动脚本生成）。
- 自动执行：演练脚本进 CI 定时触发（预发环境），结果自动判定与报告——演练从「人组织」到「系统跑」。
- 剧本与预案一致性校验：预案卡片（人读）与演练脚本（机跑）同步校验（预案更新未同步脚本 = 告警）——两套资产不许漂移。
- 演练债务管理：剧本覆盖的场景清单 vs 故障模式清单（SCN-OPS-217）的差集 = 演练债务（有预案没演练的场景）。
- 追问钩子：为什么「预案与脚本的一致性校验」重要——预案卡片是故障时刻人读的，演练脚本是平时机跑的；两者漂移时（预案改了脚本没改），演练验证的是过时流程，故障时刻按新预案操作却从未被验证过——一致性校验把「演练有效性」从假设变成检查。

```yaml
# drill-scenarios/rollback-entry.yaml —— 脚本即代码
scenario: rollback-entry
inject: { type: 'manifest-corrupt' }
steps: fromPlaybook('card-bundle-404')               # 从预案卡片生成（同源）
assert: { entrySwitched: '< 5min', notify: true }
```
```javascript
// 一致性校验：预案 vs 脚本
const drift = playbookCards().filter(c => !drillScriptFor(c));
if (drift.length) warn(`预案未同步演练脚本: ${drift}`);
const debt = failureModes().filter(m => !drillScriptFor(m));   // 演练债务
```
