## OPS-226：灰度对象怎么选？
**答**：
- 首批对象原则：高容忍度用户（内部员工/种子用户）→ 特征代表性用户（设备/网络分布均衡）→ 随机放量——首批选「愿报问题的人」，中期选「有代表性的人」。
- 避免偏差：首批只给内部员工会让「内部可用≠外部可用」（数据规模/网络环境差异）——内部灰度后必须进入真实用户灰度。
- 排除名单：VIP/付费大户在早期灰度排除（高风险变更不碰核心用户），中后期纳入。
- 灰度名单管理：排除名单时效化（随灰度阶段自动解除），防止「永远不让 VIP 体验新功能」。
- 追问钩子：为什么早期灰度要「排除 VIP」而不是「优先 VIP」——VIP 用户对故障的容忍度最低且影响面最大（客诉升级快）；早期灰度样本应该「报错耐心且影响可控」，VIP 放在中后期（功能已稳定）是风险与反馈价值的平衡。

```javascript
function grayCohort(user, stage) {
  if (stage === 'internal') return user.isEmployee;
  if (stage === 'early') return !user.isVip && tolerantUser(user);   // 排除 VIP
  if (stage === 'mid') return deviceBalanced(user);                  // 特征代表性
  return true;                                                       // full
}
```
