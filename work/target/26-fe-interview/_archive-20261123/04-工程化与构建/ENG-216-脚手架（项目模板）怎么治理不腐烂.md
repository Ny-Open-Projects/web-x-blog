## ENG-216：脚手架治理怎么做？
**答**：
- 腐烂根源：模板生成一次后无人维护，依赖与最佳实践随时间过期——治理核心是「模板即仓库」：模板自身是个可构建可测试的项目，CI 持续验证。
- 同步机制：模板升级向存量项目推送（codemod/diff 提示），存量项目可选择跟进——单向生成必腐，双向同步才有生命。
- 模板最小化：模板只含「必选公共部分」（构建/规范/CI/监控接入），业务结构轻——模板越重，同步成本越高。
- 效果度量：模板版本使用分布（新项目用最新模板的比例）、模板驱动项目与手工项目的 CI 通过率差异。
- 追问钩子：为什么「模板自身过 CI」是防腐关键——模板改动直接在模板仓库验证（构建/测试/规范检查都真实跑），而不是生成后才发现模板本身是坏的；这也是 codemod 能持续提供的前提。

```yaml
# 模板仓库 CI：模板自身就是项目
name: template-validate
on: [push, schedule]
jobs:
  build-template:
    steps:
      - run: pnpm install && pnpm build && pnpm test   # 模板自己能跑
      - run: node scripts/generate-test-project.js && pnpm -C test-project build  # 生成验证
```
