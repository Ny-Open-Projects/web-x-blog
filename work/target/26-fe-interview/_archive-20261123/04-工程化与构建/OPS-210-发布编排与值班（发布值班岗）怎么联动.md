## OPS-210：发布值班岗怎么联动？
**答**：
- 发布盯守要求：灰度期哨兵自动监控 + 发布人在线盯守（大版本发布必须有第二人复核哨兵数据）——哨兵是机器，值守是人对「哨兵看不见的异常」兜底。
- 升级路径：发布人 → 团队负责人 → 值班经理，发布异常 10 分钟无决策自动升级（发布卡死比发布失败更常见）。
- 交接：发布横跨班次时交接清单（当前灰度档位/观察结论/待办动作）——灰度多天跨越多班次必须交接。
- 决策记录：灰度放量/回滚决策带决策人记录——发布决策可追溯是免责与复盘的基础。
- 追问钩子：为什么发布异常要「10 分钟自动升级」——发布期的时间价值极高（每多带病运行一分钟爆炸半径扩大）；发布人容易陷入「再等等看」心态，自动升级强制把决策权上移，打破决策瘫痪。

```javascript
const publishOncall = {
  guard: { sentinel: 'auto', human: 'publisher + reviewer(大版本)' },
  escalation: { timeout: '10min', path: ['publisher', 'team-lead', 'oncall-mgr'] },
  handover: { checklist: ['当前档位', '观察结论', '待办动作'] },   // 跨班次灰度交接
  decisionLog: (decision) => audit({ decision, by: currentUser, ts: now() }),
};
```
