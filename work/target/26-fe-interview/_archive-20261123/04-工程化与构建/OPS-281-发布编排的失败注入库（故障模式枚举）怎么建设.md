## OPS-281：失败注入库怎么建设？
**答**：
- 注入库内容：按失败层枚举——构建层（依赖拉取失败/缓存污染）、部署层（产物不完整/签名失败/CDN 推送超时）、运行层（chunk 404/接口超时/灰度分流失灵）、流程层（审批卡死/哨兵误报/回滚通道损坏）——每项注入器实现「如何制造该故障」。
- 注入器标准：可编程触发（API/定时）、影响范围限定（预发/灰度小流量）、自动清理（注入后恢复现场）、观察指标声明（验证注入生效的信号）。
- 与预案联动：每个注入项关联预案卡片（注入验证预案有效性——SCN-OPS-269 演练即代码的数据源）。
- 注入库治理：注入项随真实事故扩充（新故障模式 → 新注入器）——注入库是事故知识的可执行形式。
- 追问钩子：为什么注入器要「声明观察指标」——注入后必须验证「故障真的发生了」（注入失效的演练是无效演练）；观察指标（如 chunk 404 计数上升）是注入生效的确认信号，也是演练判定的事实基础——注入的可观测性决定演练的可信度。

```javascript
const injectionLibrary = {
  build: ['dep-fetch-fail', 'cache-pollute'],
  deploy: ['partial-artifact', 'sig-fail', 'cdn-push-timeout'],
  runtime: ['chunk-404', 'api-timeout', 'split-skew'],
  process: ['approval-stuck', 'sentinel-fp', 'rollback-channel-broken'],
  standards: { trigger: 'api/schedule', scope: 'staging/gray-small', cleanup: 'auto',
               observe: required },                    // 注入生效信号
  fromIncidents: (incident) => addInjector(incident.failureMode),   // 事故 → 注入器
};
```
