## OPS-276：熔断误触发怎么防？
**答**：
- 误触发来源：哨兵阈值过紧（正常波动触发）/基线失真（业务节奏变化）/指标噪声（采样波动）——每次误触发都消耗「熔断公信力」（狼来了效应）。
- 治理手段：误触发分类统计 → 阈值/基线规则修正；连续误触发的哨兵自动降级为「仅告警不熔断」（哨兵降权）；熔断后的快速恢复通道（误熔断 5 分钟内可恢复，SCN-OPS-222 解除机制）。
- 熔断成本意识：每次熔断都是真实的业务中断（放量停滞）——熔断决策的质量直接影响发布效率。
- 哨兵-熔断分离：告警（观察）与熔断（动作）分级，初期新哨兵只告警累积置信度，达标后接入熔断——新哨兵的试用期制度。
- 追问钩子：为什么新哨兵要「试用期」而不是直接接熔断——新哨兵的误报率未知，直接接熔断等于让未经验证的判定器控制生产动作；试用期只告警积累误报数据，误报率达标（如 <5%）后才授予熔断权——权限跟随可信度，是自动化渐进授权的标准模式。

```javascript
function sentinelTrustLevel(sentinel) {
  const stats = sentinel.history(30);                  // 近 30 天
  const falsePositiveRate = stats.falseAlarms / stats.alarms;
  if (stats.alarms < 10) return 'observe-only';        // 冷启动：仅观察
  return falsePositiveRate < 0.05 ? 'can-break'        // 可信：接入熔断
       : falsePositiveRate < 0.2 ? 'alert-only' : 'demoted';   // 降权
}
```
