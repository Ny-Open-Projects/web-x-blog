## OPS-209：发布期流量峰值怎么配合？
**答**：
- 峰值来源：新版本 HTML 上线瞬间全量用户拉新入口 → 新 chunk 下载风暴；immutable 资源已被 CDN 边缘预热（SCN-ENG-256），真实压力在 HTML 回源与边缘未命中的长尾。
- 预热编排：发布前置资源推送边缘节点（全量 hash 资源先上）→ HTML 切换；发布限速（HTML 切换按地域渐进天然限流）。
- 客户端节流：SW 缓存 + HTTP 缓存让老用户第二次访问零下载；new chunk 下载做并发限制（浏览器默认同域 6 连接已够）。
- 容量演练：发布峰值纳入压测场景（模拟 HTML 切换瞬间的请求模式）——发布期故障多是「没把发布当流量事件」。
- 追问钩子：为什么「资源先上、HTML 后切」是发布流量治理的核心顺序——资源 URL 是 hash 命名（全球 immutable），先预热到边缘后，HTML 切换瞬间用户只会回源一个 HTML 文件；顺序反了（先切 HTML）会让全量用户同时回源拉新资源，制造人工流量风暴。

```yaml
publish_flow:
  1: push-assets-all-edges        # immutable 资源全球预热
  2: switch-html-regional         # HTML 地域渐进切换（天然限流）
  3: monitor-edge-hit-rate        # 边缘命中率哨兵
capacity_drill: '模拟 HTML 切换请求模式压测'
```
