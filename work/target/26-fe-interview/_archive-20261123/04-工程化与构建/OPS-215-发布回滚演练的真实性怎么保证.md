## OPS-215：回滚演练真实性怎么保证？
**答**：
- 真实性三要素：真环境（预发或小流量生产，不是本地模拟）、真数据（带真实用户数据的预发库）、真流程（值班人员按 runbook 执行，发布人旁观不插手）。
- 计时硬指标：从「决定回滚」到「旧版本生效」的总时长（目标 < 5 分钟），各段拆解（决策/执行/生效验证）。
- 盲演：演练内容对执行者保密（值班不知道今天要演回滚）——演练的价值在检验「无准备时的响应」，通知式演练失去意义。
- 演练复盘：时间线对比目标差距，卡点（权限不足/步骤不清）进 runbook 修订。
- 追问钩子：为什么「盲演」比「通知式演练」有价值得多——通知式演练时大家提前准备，验证的是「有准备的表现」；真实事故是突然发生的，盲演检验的是值班体系在无预警状态下的真实响应能力，这才能暴露 runbook 与权限的真实缺陷。

```yaml
rollback_drill:
  authenticity: { env: 'staging-with-prod-data', executor: 'oncall(blind)', observer: 'release-owner' }
  metrics: { total: '< 5min', segments: ['decision', 'exec', 'verify'] },
  blind: true,                                          # 执行者不知情
  review: '时间线对比 → runbook 修订',
  frequency: quarterly,
```
