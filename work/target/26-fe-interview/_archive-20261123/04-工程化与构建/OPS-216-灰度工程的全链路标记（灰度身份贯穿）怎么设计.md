## OPS-216：灰度身份贯穿怎么设计？
**答**：
- 标记传播链：网关判定灰度身份 → HTML 注入灰度标记 → 前端所有 API 请求携带灰度头（X-Gray-Bucket）→ 后端日志/追踪/指标按灰度维度切片。
- 一致性锚点：灰度决策在网关层单源（前端不自判，SCN-ENG-251），标记进 session（同会话稳定）；灰度标记与 traceId 并列贯穿。
- 指标切片价值：错误率/性能/转化全部按灰度桶切片——「灰度组错误率」是唯一有意义的灰度指标口径，没有标记贯穿就只能看全站平均值（混入灰度外的噪声）。
- 标记安全：灰度标记不可被客户端伪造篡改影响分流（网关重写而非透传用户传入值）。
- 追问钩子：为什么灰度标记要「网关重写」而不是信任前端传值——前端传的灰度头可被篡改（用户或脚本自行加标记进入灰度组）；网关根据会话身份重新计算并覆写标记，保证分流的唯一权威性，也让埋点口径可信。

```javascript
// 网关层：重写灰度标记
const bucket = computeGrayBucket(session.userId);      // 网关单源判定
proxy.setHeader('X-Gray-Bucket', bucket);              // 覆写（不信客户端）
// 前端透传到所有 API
api.interceptors.request.use(cfg => { cfg.headers['X-Gray-Bucket'] = window.__GRAY__; return cfg; });
// 指标切片
metrics.sliceBy('grayBucket');   // errorRate / tti / conversion 全部按桶
```
