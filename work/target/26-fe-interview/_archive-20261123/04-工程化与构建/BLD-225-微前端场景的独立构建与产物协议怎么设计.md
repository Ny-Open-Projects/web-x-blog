## BLD-225：微前端构建协议怎么设计？
**答**：
- 产物协议：每个子应用产出标准清单（entry/manifest/依赖声明/版本）——宿主按协议加载，不感知子应用内部构建（SCN-ENG-234 边界）。
- 独立构建要求：子应用构建不依赖宿主产物（无宿主 import）——共享逻辑走独立包（构建时）或 shared（运行时）。
- 版本协商与回滚：清单带版本 + 宿主可指定版本（回滚 = 指向旧清单）。
- 隔离构建的产物一致性：共享依赖版本对齐（依赖治理目录/对齐工具）——各子应用 React 版本不一致是微前端 crash 头号来源。
- 追问钩子：为什么「子应用之间 React 版本对齐」要靠工程约束而不是文档约定——文档约定会漂移（各团队升级节奏不同）；工具强制（CI 校验各子应用 lockfile 的 react 版本一致 + 对齐检查进发布门禁）——约定靠人记住，工具靠门禁执行。

```yaml
# 子应用产物协议
{ name: cart, version: 1.4.0, entry: remoteEntry.js,
  shared: { react: '^19.0.0', 'react-dom': '^19.0.0' } }
# CI 对齐检查
subapps.forEach(app => assert(app.lockfile.react === baseline.react));   // 版本对齐门禁
```
