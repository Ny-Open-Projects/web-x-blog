## OPS-203：灰度指标观测怎么不失真？
**答**：
- 同质对比：灰度组与对照组必须「同质」——分流按用户稳定哈希后，还要校验两组的用户画像/设备分布一致性（SRM 偏斜检测：比例偏离预期即告警）。
- 流量加权：灰度 1% 流量的指标天然噪声大——看「置信区间」而非点值；小流量阶段只看硬指标（错误率/崩溃），软指标（转化）等流量放大再判。
- 时间窗对齐：灰度组与基线在同一时段窗口对比（SCN-ENG-298 哨兵口径），避免「昨天 vs 今天」的环境差异混入。
- 新鲜效应：新版本用户初期行为异常（新奇感/曝光变化）——观察窗口排除首日数据或用留存曲线对比。
- 追问钩子：为什么 SRM（样本比例失配）检测是灰度观测第一哨兵——分流哈希正常时 1% 灰度组用户数应该精确接近 1%；比例失配说明分流实现有 bug（缓存/重试/身份合并），此时所有对比指标都不可信——先修分流再看指标。

```javascript
function srmCheck(treatmentCount, total, expectedPct, { tolerance = 0.02 } = {}) {
  const actual = treatmentCount / total;
  const skew = Math.abs(actual - expectedPct) / expectedPct;
  if (skew > tolerance)
    return { alert: 'SRM', skew, note: '分流比例失配，指标观测暂不可信，先查分流实现' };
  return { ok: true, actual };
}
```
