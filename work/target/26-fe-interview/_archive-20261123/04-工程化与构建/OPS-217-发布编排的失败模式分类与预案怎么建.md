## OPS-217：发布失败模式怎么建？
**答**：
- 失败模式清单：产物缺失（HTML 引用悬空）、灰度分流失灵（SRM）、哨兵误报风暴、回滚卡死、编排器崩溃、缓存未刷新、兼容矩阵漏测——每类有「症状/定位/处置」三段预案。
- 预案形式：预案卡片（一页：症状识别 → 定位命令 → 处置步骤 → 升级条件）嵌入值班工具箱（SCN-OPS-191 联动）——预案在故障时可被 5 分钟内执行。
- 预案保鲜：预案卡片必须被演练触达过（SCN-OPS-208 注入式演练），未演练预案标「未验证」。
- 失败模式沉淀：每次真实发布事故后新增/修订预案卡片——预案库是事故学费的转化器。
- 追问钩子：为什么预案要「一页卡片」而不是长文档——故障时刻的认知带宽极低，长文档没人读完；卡片化（症状→定位→处置→升级）让值班在 3 分钟内定位到正确预案，这是预案可用性的形态要求。

```yaml
# playbook/card-bundle-404.md
症状: 白屏/资源 404，边缘命中率骤降
定位: curl HTML → 检查 manifest 引用 vs CDN 对象
处置: 1) 若悬空→回滚入口 2) 若 CDN 缺失→重新推送 assets
升级: 处置 10min 无效 → 升级值班经理
verified: drill-2026-11
```
