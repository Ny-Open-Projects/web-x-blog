## BLD-289：分片构建怎么做？
**答**：
- 拆分维度：按入口拆（每入口独立构建进程——内存隔离，SCN-BLD-253）、按包拆（monorepo 包级并行——turbo 图调度）、按语言拆（i18n 多语言产物并行）。
- 合并问题：拆分后的产物合并（chunk 依赖跨进程——共享 chunk 的分配需要在拆分前全局规划；或接受每入口独立产物——无跨进程共享）。
- 适用判断：单进程构建慢的原因是「内存/单线程」而非「任务总量」时拆分才有效（SCN-BLD-212 并行的延伸）。
- 追问钩子：为什么分片构建要「先决定共享 chunk 策略再拆」——拆分后各进程看不到彼此的模块图，跨进程共享 chunk 无法自动提取；先规划（共享依赖预构建为独立产物、各分片引用）再拆，否则产物里公共库重复 N 份——拆分的正确顺序是「先分模块图、再分进程」。

```javascript
// 共享前置
await build('vendor-common');                          // 共享 chunk 先独立构建
// 分片并行
await Promise.all(entries.map(e =>
  fork(buildWorker, { entry: e, externals: ['vendor-common'] })));   // 各分片引用共享产物
```
