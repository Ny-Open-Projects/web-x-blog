## ENG-227：工程化路线图怎么定？
**答**：
- 排序原则：先止痛后增值——Top 摩擦点（DevEx 调查 + 客观度量）优先于技术尝鲜；稳定性（防劣化/门禁）优先于提速。
- 一年结构：Q1 稳底座（规范统一/CI 分层/门禁）→ Q2 提效率（缓存/构建提速/CLI）→ Q3 平台化（自服务/度量看板）→ Q4 深水区（AI 工程化/依赖治理收尾）——每季度有可交付里程碑。
- 资源配比：建设人力 ≤ 30%，其余保运维与响应（基建团队常见错误是全投建设欠运维债）。
- 路线的抗变更设计：里程碑绑定「可验证指标」而非「工具名」——工具会换（webpack→rspack），目标（构建 P95 < 3min）不变。
- 追问钩子：为什么里程碑绑指标不绑工具——绑工具的路线图在技术选型变化时整段作废；绑指标（构建时长/事故率）的路线图在任何技术路径下都有效，这是规划的韧性。

```javascript
const roadmap = {
  q1: { goal: '稳定性', kpi: ['门禁覆盖率 100%', '构建 P95 基线建立'] },
  q2: { goal: '效率', kpi: ['CI P50 < 8min', 'HMR < 300ms'] },
  q3: { goal: '平台化', kpi: ['自服务查询类上线', 'DevEx 调查 +20%'] },
  q4: { goal: '深水区', kpi: ['AI 产物采纳率 > 60%', '幽灵依赖清零'] },
  rule: '里程碑绑指标不绑工具名',
  opsRatio: 0.3,
};
```
