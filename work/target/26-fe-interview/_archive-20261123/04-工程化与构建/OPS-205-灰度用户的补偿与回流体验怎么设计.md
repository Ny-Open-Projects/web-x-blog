## OPS-205：灰度期用户数据处理怎么设计？
**答**：
- 数据兼容双向：灰度组可能写新格式数据——回滚后旧版本必须能读（前向兼容读：新字段忽略降级）；灰度版读旧数据同理（向后兼容）——数据 schema 迁移独立于版本灰度。
- 本地状态隔离：新旧版本的 localStorage/schema 版本号隔离，回滚时迁移不破坏（读写版本戳）。
- 用户感知最小化：版本切换（灰度进/出）不应造成页面状态丢失——路由/表单状态在切换时保持或提示保存。
- 灰度退出体验：被移出灰度的用户给「版本回退说明」仅在高风险变更时展示（一般静默）。
- 追问钩子：为什么数据兼容必须「双向」而不是只保证向后兼容——灰度失败回滚时，新版本写的数据已经在库里；旧版本只保证「读旧写旧」会让新数据读不出来（用户数据"消失"）；前向兼容（旧版容忍新数据）是灰度安全的隐形前提。

```javascript
// 数据 schema 版本戳
const data = { v: 2, ...payload };
function readData(raw) {
  if (raw.v > CURRENT_SCHEMA) return degradeRead(raw);   // 前向兼容：新版数据降级读
  if (raw.v < CURRENT_SCHEMA) return migrate(raw);       // 向后兼容：旧数据迁移读
  return raw;
}
```
