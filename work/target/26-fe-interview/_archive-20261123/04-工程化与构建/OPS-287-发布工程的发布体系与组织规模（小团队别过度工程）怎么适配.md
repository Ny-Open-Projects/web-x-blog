## OPS-287：发布体系规模适配怎么做的？
**答**：
- 分规模基线：小团队（<10 人）——CI + 自动部署 + 简单哨兵即可，灰度/审批流程是负担；中团队——加灰度/分级审批/值班；大团队——全套（编排/flag 体系/多环境/合规留痕）。
- 过度工程的信号：流程环节数 > 团队人数的一半（审批链比开发链还长）/发布前置时间 > 开发时间——流程成本超过其防的风险成本。
- 渐进引入触发器：按事故与规模驱动（出过灰度相关事故 → 引入灰度；多人同时发布冲突 → 引入队列）——机制跟着痛点走（SCN-ENG-225 重复请求驱动同构）。
- 降级同样合法：团队缩小后流程要能减配——体系设计预留「减配模式」。
- 追问钩子：为什么「发布前置时间 > 开发时间」是过度工程的明确信号——开发者半天写完的功能要走两天发布流程，流程已经成为交付瓶颈；此时要么简化流程要么增加自动化——度量这个比值是发现「流程税」最直接的指标。

```javascript
function releaseFit(teamSize, incidents) {
  if (teamSize < 10) return { must: ['ci', 'auto-deploy', 'basic-sentinel'],
                              skip: ['multi-env', 'heavy-approval'] };
  if (teamSize < 50) return { add: ['gray', 'risk-leveling', 'oncall'] };
  return { full: ['orchestration', 'flag-system', 'compliance-audit'] };
  // 过度工程信号
  const tax = pipelineLeadTime / devTime;
  if (tax > 2) simplifyFlow();
}
```
