## OPS-246：产物签名怎么做的？
**答**：
- 签名链：构建产物 hash → CI 签名（私钥）→ manifest 携带签名 → 部署端验签（公钥）——防「产物在传输/存储环节被篡改」（供应链攻击的最后一环）。
- SRI 补充：HTML 内联 script/css 的 integrity 属性（浏览器侧校验）——用户端最后防线（CDN 被污染时浏览器拒绝执行）。
- 密钥管理：签名私钥存密管（SCN-ENG-229），CI 专用签名凭据（人员不可直接签名）。
- 验证时机：部署端验签（进 CDN 前）+ 运行时抽检（定时拉产物验 hash）——两端双保险。
- 追问钩子：为什么「部署端验签」和「浏览器 SRI」要双份——部署端验签防「上传环节篡改」（CI 到 CDN 之间），SRI 防「CDN 存储被污染」（用户拿到的是被改过的文件）；两段信任链独立，单点被攻破时另一层仍能拦截——纵深防御在发布链路的直接应用。

```html
<!-- SRI：用户端防线 -->
<script src="/assets/index-abc123.js" integrity="sha384-xyz..." crossorigin="anonymous"></script>
```
```javascript
// 部署端验签：进 CDN 前校验
const sig = verify(prodManifest.signature, PUB_KEY);
if (!sig) throw new Error('产物签名校验失败——疑似篡改');
// 运行时抽检
cron('0 */6 * * *', () => spotCheckProdHash());        // 每 6 小时抽检线上 hash
```
