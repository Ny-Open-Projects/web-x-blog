## OPS-227：回滚善后怎么设计？
**答**：
- 善后清单：回滚后必做——① 确认指标恢复（回滚成功≠问题解决，指标恢复才是）；② 通知用户/客服话术更新；③ 数据清理评估（新版本期间产生的数据兼容处理）；④ 根因分析排期；⑤ 灰度记录关闭与发布计划归档。
- 数据兼容检查：回滚后新版本写入的数据（SCN-OPS-205）由旧版本降级读取——验证一遍真实数据可读。
- 回滚后发布策略：修复后重新发布的准入是「根因明确 + 修复验证」，不是「改完了」——同一问题二次发布的门槛更高。
- 善后跟踪：善后清单进工单跟踪（不是口头记住），未完成项阻塞下一次发布。
- 追问钩子：为什么「指标恢复确认」是回滚善后第一项——回滚只是撤销了变更，如果异常根因不是该变更（外部依赖故障），回滚后指标不会恢复；确认恢复才证明回滚有效，否则立即转向真正的根因排查——这是回滚决策的最快验证闭环。

```javascript
async function postRollback(releaseId) {
  await waitForMetricRecovery(10 * 60_000);            // 1. 指标恢复确认（10min 窗口）
  updateSupportScripts();                              // 2. 客服话术
  auditDataCompat();                                   // 3. 新数据可读性验证
  scheduleRCA(releaseId, { due: '48h' });              // 4. 根因分析排期
  blockNextRelease(until: rcaDone);                    // 5. 未闭环阻塞下次发布
}
```
