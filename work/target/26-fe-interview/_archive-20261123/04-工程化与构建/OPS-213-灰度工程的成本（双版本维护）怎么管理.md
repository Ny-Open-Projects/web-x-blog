## OPS-213：灰度成本怎么管理？
**答**：
- 成本构成：双版本产物存储/边缘缓存、代码内 flag 分支复杂度、观察人力、灰度期 bug 修复要出双份——成本随灰度时长非线性上升。
- 控制手段：灰度时限（7 天内必须全量或回滚，SCN-ENG-251 灰度卫生）、flag 分支复杂度 lint（嵌套 flag 检测）、产物双版本存储按需（只在灰度期保留）。
- 长期灰度例外：企业客户/合规场景的长期灰度（白名单常驻）单独管理，不占常规灰度资源。
- 成本可见：灰度成本报表（双版本存储/人力投入）进发布复盘——成本是灰度策略调整的输入。
- 追问钩子：为什么「灰度时限 7 天」是硬规则而非建议——灰度超过一周，代码里新旧两条路径并存导致修复成本翻倍，且 flag 膨胀固化；时限迫使团队做出「放量或回滚」的明确决策，避免灰度变成永久悬置状态。

```javascript
const grayCost = {
  limit: { maxDuration: '7d', onExpire: '放量或回滚，不允许悬置' },
  lint: { nestedFlags: '嵌套 flag 检测（分支复杂度）' },
  storage: { dualVersion: '仅灰度期保留，结束即清理' },
  report: grayCostReport(),   // 进发布复盘
};
```
