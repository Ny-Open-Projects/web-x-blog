## ENG-214：AI 规则文件怎么治理？
**答**：
- 规则分层：全局规则（语言/风格）→ 包级规则（技术栈约定）→ 场景规则（按任务类型加载），按需注入控制上下文预算。
- 治理机制：规则文件进版本管理 + 变更评审（规则影响所有 AI 产出，等同基建变更）；规则有效性度量（违反规则的 AI 产出占比下降才算规则有效）。
- 膨胀治理：规则数量上限 + 每季度评审——「AI 经常自动遵守的不用写，AI 从来做不到的也别写（改工程约束更有效）」；规则优先级冲突显式声明。
- 从规则到约束的迁移：反复写「不要这样」的规则，直接改成 lint 规则/类型约束——硬约束优于软规则。
- 追问钩子：为什么「做不到的规则要改成工程约束」——AI 依赖概率遵守规则，人也会忘；lint/类型是执行层的确定性约束，把软规则硬化一次，AI 与人都不会再犯。

```
# .ai/rules 分层结构
.ai/
  global.md        # 全局：语言/注释/命名
  packages/ui.md   # 包级：组件 API 约定
  tasks/codemod.md # 场景：codemod 任务专用规则
```
```javascript
// 规则有效性度量
const ruleEffectiveness = (ruleId, before, after) => ({
  violationRate: after / before,          // <1 才算规则有效
  action: after >= 1 ? '考虑迁移为 lint 规则' : '保留',
});
```
