## OPS-223：变更管理闭环怎么打通？
**答**：
- 闭环链路：变更单（需求/工单）→ 代码 PR → 发布计划（关联变更单）→ 发布执行 → 验证关闭——每个变更单可查「我的变更上线上了吗/效果如何」。
- 强关联：发布必须引用变更单（无变更单的发布需豁免审批）——发布是变更管理的执行环节，不是独立行为。
- 冻结期联动：变更冻结（SCN-OPS-181 大促封网）时发布编排器自动拒绝常规发布，紧急通道走独立审批。
- 变更日历：所有变更（发布/配置/数据）进统一变更日历——「同时段谁在改什么」的可视化（变更冲突检测）。
- 追问钩子：为什么「无变更单的发布要豁免审批」而不是直接拒绝——直接拒绝会催生「补填变更单」的形式主义（事后补单）；豁免通道保留灵活性同时留下审计记录，豁免频率数据反过来暴露变更管理的漏洞——治理靠闭环而非靠堵。

```javascript
async function publish(plan) {
  if (!plan.changeTicket && !plan.waiver)
    return requireWaiver(plan);                        // 豁免通道 + 审计
  const conflicts = changeCalendar.conflicts(plan.window);   // 变更冲突检测
  if (conflicts.length && !plan.isHotfix)
    return reject(plan, `同时段变更冲突: ${conflicts}`);
  await orchestrate(plan);
  closeTicket(plan.changeTicket, { evidence: sentinelReport });   // 变更单闭环
}
```
