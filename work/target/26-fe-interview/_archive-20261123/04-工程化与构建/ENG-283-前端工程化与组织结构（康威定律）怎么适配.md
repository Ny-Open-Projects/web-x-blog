## ENG-283：工程化与组织怎么适配？
**答**：
- 康威定律的工程映射：组织怎么沟通，架构就长什么样——平台工具的边界要匹配团队边界（强协作的团队进同一 monorepo 空间，弱协作的用包边界隔离）。
- 所有权即架构：包的归属划分应与业务团队一致（一个团队一个包域），跨团队共享包要有明确的共同治理机制。
- 工程化对组织的反向塑造：门禁/CI 会固化协作方式——引入 merge queue 前先确认组织能承受排队等待。
- 改组织还是改工程：跨团队冲突频发时，先评估是组织边界问题还是工具问题——用工程手段硬解组织问题通常失败。
- 追问钩子：为什么「先评估组织边界再上工程手段」——两个团队冲突频发的根因可能是目标不一致（组织问题）；用 monorepo 强绑定只会放大冲突。工程手段适合解决协作摩擦，不适合解决利益冲突。

```javascript
const conwayFit = {
  mapping: { strongCollab: '同 monorepo 空间', weakCollab: '包边界隔离' },
  ownership: '包域 = 业务团队域',
  reverse: { mergeQueue: '先确认组织能接受排队' },
  decision: (conflict) => isOrgProblem(conflict) ? '改组织' : '用工程手段',
};
```
