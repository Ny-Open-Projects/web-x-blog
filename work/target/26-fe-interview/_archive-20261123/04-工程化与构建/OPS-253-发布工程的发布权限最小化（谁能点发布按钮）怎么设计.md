## OPS-253：发布权限怎么设计？
**答**：
- 权限分层：触发发布（发布工程师/授权开发）vs 批准发布（审批人，SCN-OPS-241）vs 紧急操作（回滚/熔断——值班经理+发布人双权限）——触发/批准/应急三权分离。
- 账号卫生：发布凭据是 CI 服务账号（人员不持发布凭据）；紧急人工通道走个人账号 + 强审计（SCN-OPS-220 留痕）。
- 权限时效：发布权限与值班排班绑定（值班才有应急权限）——权限随职责动态，不终身持有。
- 权限审计：权限变更记录 + 定期权限评审（离职即回收，SCN-ENG-277 危险路径联动）。
- 追问钩子：为什么「触发/批准/应急」三权要分离——一人三权意味着可以「自己批准自己发布再自己回滚」，审批与留痕形同虚设；三权分离让每次发布至少两个角色参与（触发人+批准人），应急操作有独立授权通道——这是职责分离（SoD）在发布工程的应用。

```javascript
const releasePerms = {
  trigger: 'release-engineer / CI-service-account',    // 触发
  approve: 'approval-flow (OPS-241)',                  // 批准（独立角色）
  emergency: ['oncall-mgr', 'release-owner'],          // 回滚/熔断双权限
  hygiene: { creds: 'CI-service', oncall: '权限随排班', audit: 'all-changes', offboard: '即时回收' },
};
```
