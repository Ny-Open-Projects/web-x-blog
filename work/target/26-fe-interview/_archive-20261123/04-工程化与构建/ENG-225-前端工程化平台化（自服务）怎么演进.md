## ENG-225：工程平台化怎么演进？
**答**：
- 演进路径：人肉支持 → 脚本化 → CLI 工具 → 平台（Web 界面 + 自服务 API）——每一步都以「重复请求量」为触发（同问题被问 10 次才值得平台化）。
- 自服务能力优先级：创建应用/查构建状态/看质量门禁/申请资源——先做「查」类（只读风险低），再做「做」类（写操作要权限与审计）。
- 平台团队边界：平台做「共性底座 + 护栏」，业务团队保「灵活性与所有权」——平台包揽业务构建配置会变成单点瓶颈。
- 平台自身健康：平台可用性 SLA/支持请求量趋势/采纳率——平台工具没人用比没平台更糟。
- 追问钩子：为什么平台优先做「查」类能力——查询类无写风险、实现快、立刻降负载（值班答疑占平台团队 30% 时间被工具替代）；写操作引入权限/审计复杂度，放到验证价值之后。

```javascript
const platformRoadmap = {
  trigger: (faq) => faq.repeat >= 10,               // 重复请求驱动平台化
  readOnlyFirst: ['app-status', 'build-logs', 'quality-gate', 'resource-inventory'],
  writeLater: ['create-app', 'request-resource'],   // 带权限审计
  boundary: '底座+护栏归平台，业务配置归业务',
  health: { sla: 0.999, adoption: '团队使用率', supportTrend: down },
};
```
