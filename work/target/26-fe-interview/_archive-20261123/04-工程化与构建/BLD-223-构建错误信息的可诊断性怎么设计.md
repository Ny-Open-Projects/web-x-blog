## BLD-223：构建错误可诊断性怎么设计？
**答**：
- 错误分类：语法错误（位置精确）/解析错误（依赖找不到）/转换错误（loader 抛错）/插件错误（内部异常）——每类有标准定位路径。
- 错误增强：报错附「建议修复」（依赖找不到 → 检查 alias/是否安装/exports 条件）；原始错误保留（堆栈不吞）；相关上下文（importer 链——谁引用了这个坏模块）。
- 输出分层：CI 用机器可解析输出（JSON）/人用友好格式（代码帧+指针）——同一错误两种渲染。
- 追问钩子：为什么「importer 链」是依赖类错误最有用的上下文——「Module not found: xxx」不告诉你谁引用了它；带上 importer 链（A→B→xxx）直接定位是哪个业务模块的 import 写错——这比全局搜索快一个数量级，是打包器错误 UX 的核心改进。

```javascript
// 错误增强示例
{ code: 'MODULE_NOT_FOUND',
  spec: '@/utils/date',
  hint: 'alias "@" 未配置或目标不存在',
  importerChain: ['src/pages/home.tsx', 'src/components/Card.tsx'],
  frame: '1 │ import { formatDate } from "@/utils/date";',
  fix: '在 vite.config resolve.alias 添加 @ → /src' }
```
