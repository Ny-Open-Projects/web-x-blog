## OPS-221：地域灰度怎么做？
**答**：
- 地域灰度策略：按低风险地域先行（小流量市场验证）→ 主要市场；地域维度与用户维度灰度叠加时取「先过地域闸门再用户分流」。
- 时区考虑：发布窗口按目标地域本地时间（凌晨发布要选目标市场夜间，不是自己的夜间）；灰度观察窗口跨时区时注意指标昼夜模式差异。
- CDN 与灰度联动：地域灰度靠 CDN 边缘路由（不同地域返回不同入口），与用户哈希灰度在网关层合并决策。
- 合规差异：不同地域的数据策略/隐私合规差异（如欧盟）可能要求功能差异——灰度维度增加「合规域」。
- 追问钩子：为什么全球产品的发布窗口要「目标市场本地夜间」——夜间流量低（爆炸半径小）且时段一致性使指标对比干净；用「自己的夜间」发布对另一时区可能是高峰期，等于在流量峰值上灰度——时区错误是全球发布最常见的低级失误。

function grayDecision(user, release) {
  const region = edgeRegion();                          // CDN 边缘地域
  if (!release.regionGates.includes(region)) return 'stable';   // 地域闸门先行
  return userSplit(user, release);                      // 再过用户分流
}
const publishWindow = targetLocalNight(release.regions);   // 目标市场本地夜间
