## ENG-277：Monorepo 权限边界怎么设计？
**答**：
- 权限分层：读（全员）/写代码（按 CODEOWNERS 审批）/改构建配置（工程平台团队双审——构建配置影响所有产物）/发布（CI 专用凭据，人员禁发）。
- 危险路径清单：.github workflows/构建 preset/依赖 catalog/CI 脚本——这些路径的 PR 强制平台团队审批（供应链攻击的靶向路径）。
- 最小权限原则：CI token 按流水线细分（构建 token 无发布权），凭据轮换自动化。
- 审计：所有权限变更与危险路径合入进审计日志（谁/何时/改了什么）。
- 追问钩子：为什么「构建配置」的审批级别要高于业务代码——构建配置决定「产物里有什么」：改 preset 可以注入任意代码到所有应用产物；这是供应链攻击的首选靶点，权限必须与代码写权限分离。

```yaml
# 危险路径双审
dangerous_paths:
  - 'tools/preset/**'
  - 'pnpm-workspace.yaml'
  - '.github/workflows/**'
approval: { required: 'infra-team × 2', audit: true }
# CI token 最小权限
tokens: { build: { can: 'build' }, release: { can: 'publish', separate: true } }
```
