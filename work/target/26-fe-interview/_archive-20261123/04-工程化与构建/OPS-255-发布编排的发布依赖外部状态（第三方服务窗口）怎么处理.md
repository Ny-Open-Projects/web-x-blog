## OPS-255：外部依赖窗口怎么处理？
**答**：
- 外部窗口类型：支付渠道维护窗口/第三方 SDK 审核期/应用商店审核/短信通道配额——发布计划必须声明外部依赖与窗口。
- 依赖声明与校验：发布计划的 externalDeps 字段，编排器校验「发布窗口与外部窗口冲突」（如发布窗口撞上支付渠道维护）。
- 外部状态探测：发布前探测外部服务健康（支付渠道可用性探测），不健康则延迟发布——外部故障期的发布是复合故障制造机。
- 降级联动：第三方服务故障时，依赖它的功能发布自动推迟（发布计划与降级矩阵联动，SCN-OPS-861 同源）。
- 追问钩子：为什么「发布前探测外部服务健康」是门禁的一部分——新版本若依赖某个第三方服务，而该服务正在故障，发布后故障归因会混入第三方因素（排障复杂度翻倍）；探测通过才发布，让每次发布的变量集合最小化——这是归因清晰性的前提。

```yaml
external_deps:
  - service: payment-channel
    window: { maintenance: 'Tue 02:00-04:00' }
    healthProbe: required-before-publish
  - service: app-store-review
    leadTime: '24-48h'
orchestrator:
  check: [window-conflict, health-probe]               # 冲突/健康双校验
  defer: third-party-degraded                          # 外部故障自动推迟
```
