## ENG-257：发布哨兵怎么做的？
**答**：
- 三道哨兵：合成监控（发布后定时跑关键旅程 E2E，10 分钟内首轮）、RUM 哨兵（错误率/性能 P75 与上版本对比，5 分钟窗口）、关键指标哨兵（业务漏斗转化，15 分钟窗口）。
- 自动回滚触发：哨兵超阈值自动回滚（可配置人工确认），宁可误回滚不可带病运行——误回滚的代价是灰度重来，带病的代价是事故。
- 哨兵排噪：发布期指标波动正常，哨兵用「与上版本同窗口对比」而非绝对阈值，减少误报。
- 哨兵结果回流：每次发布的哨兵记录归档（发布质量档案），异常发布模式可分析（如周五发布的错误率系统性偏高 → 发布窗口调整）。
- 追问钩子：为什么哨兵要用「版本对比」而不是绝对阈值——绝对阈值受流量/时段/活动影响波动大；同版本前后对比天然剥离环境因素，是发布验证中噪声最低的口径。

const sentinels = [

  { type: 'rum', at: '+5min', metric: ['errorRate', 'ttiP75'], vs: 'prevVersion' },
  { type: 'biz', at: '+15min', metric: 'conversion', vs: 'prevVersion' },
];
if (rum.errorRate > prev.errorRate * 1.5) autoRollback();   // 宁误回滚不带病
