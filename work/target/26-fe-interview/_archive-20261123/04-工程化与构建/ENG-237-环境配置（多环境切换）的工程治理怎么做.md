## ENG-237：多环境配置怎么治理？
**答**：
- 配置分层：构建期常量（构建目标/调试开关）+ 运行时配置（API 地址/功能开关——产物不变环境可切）——运行时配置才是多环境的正解（一次构建多环境部署）。
- 校验门禁：配置 schema 校验（缺字段/类型错启动即失败 fail-fast），敏感字段不入前端（ENG-229）。
- 配置漂移治理：各环境配置 diff 看板（staging 与 prod 差异审计）——「staging 能跑 prod 挂」多为配置漂移。
- 配置变更走发布流程：配置 PR + 评审 + 变更记录，与代码发布同治理。
- 追问钩子：为什么「运行时配置」优于「构建时多环境打包」——构建时打包产生 N 份产物（构建时间×N、产物不一致风险），且「本地用 dev 产物连测试环境」这类错配常见；运行时配置一份产物 + 配置注入，部署灵活且审计清晰。

```javascript
// 运行时配置：一份产物
const config = await fetch('/config.json');   // 部署时注入/网关下发
// schema 校验 fail-fast
const parsed = configSchema.safeParse(config);
if (!parsed.success) throw new Error(`配置校验失败: ${parsed.error}`);
// 漂移看板
const drift = diffConfig(staging, prod);   // 只允许预期差异字段
```
