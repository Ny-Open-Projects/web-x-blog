## OPS-250：灰期客服协同怎么做？
**答**：
- 灰度知情范围：客服知道「存在灰度」但不知道具体谁在灰度（隐私最小化）——用户报问题时客服可查「该用户版本」判断新旧版本问题。
- 话术差异：灰度用户遇到的是新版本问题（可能已知/修复中）——客服话术库按版本维度区分（SCN-OPS-232 版本协商联动）。
- 反馈通道：灰度用户的反馈直通发布团队（不走常规客诉池——时效价值高）；反馈打标（灰度版本）便于归因。
- 运营协同：灰度期不叠加运营活动（多变量干扰灰度判定——SCN-OPS-203 同质原则）；确需叠加则记录为事件（基线排除）。
- 追问钩子：为什么灰度期「不叠加运营活动」是判定有效性的前提——活动会同时改变灰度组与基线组的行为（转化波动），此时指标差异无法归因于版本；确需叠加就必须记录进事件日历（SCN-SLA-708 标注），让基线排除——变量控制是灰度判定的科学底线。

```javascript
const grayOpsCollab = {
  support: { knowsGray: true, knowsWho: false, byVersion: true },   // 版本话术
  feedback: { directToTeam: true, tagged: 'gray-version' },         // 直通+打标
  ops: { noCampaignOverlap: true, ifMust: 'record-as-event' },      // 变量控制
};
```
