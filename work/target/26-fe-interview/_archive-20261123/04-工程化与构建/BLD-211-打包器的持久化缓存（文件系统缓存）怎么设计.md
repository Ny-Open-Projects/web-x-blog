## BLD-211：持久化缓存怎么设计？
**答**：
- 缓存键：模块内容 hash + 转换配置 + 工具版本 + 依赖版本——键完整才能命中正确（SCN-ENG-287 同构）。
- 存储结构：按模块 hash 存转换结果（webpack filesystem cache / vite 依赖缓存），重建时只重转变更模块。
- 失效陷阱：配置读取了 env/文件系统状态（未进键）→ 脏缓存；loader 内部依赖未声明 → 变更不失效。
- 与远程缓存分层：本地持久缓存（单机热启动）→ CI 远程缓存（跨机器，SCN-ENG-205）——键一致才能互通。
- 追问钩子：为什么「切换分支后构建变慢一次又恢复」——持久缓存按模块内容 hash 键控，切分支后大量模块内容变化（缓存 miss），重建后再切回来又命中；这是缓存正确工作的表现而非 bug——但如果切回旧分支仍慢，说明缓存键混入了「非内容因素」（如绝对路径/时间）。

```javascript
// webpack 5
cache: { type: 'filesystem',
  buildDependencies: { config: [__filename], lockfile: ['pnpm-lock.yaml'] },   // 键声明完整
  version: 'preset-v2' };                              // 配置语义变化 → version bump
```
