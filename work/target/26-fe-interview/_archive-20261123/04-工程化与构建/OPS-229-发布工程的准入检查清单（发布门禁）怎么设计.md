## OPS-229：发布门禁怎么设计？
**答**：
- 门禁清单自动化：发布前自动检查——CI 全绿/产物完整性/buildinfo 就位/哨兵配置就绪/回滚演练在有效期内/相关团队知晓（发布公告）——人工 checklist 必然漏项，自动化是唯一可靠形态。
- 门禁分级阻断：硬门禁（CI 红/产物缺失 → 阻断）与软门禁（文档未更新 → 警告放行）——全部阻断会让门禁被豁免滥用。
- 门禁豁免治理：豁免必须带理由与过期（SCN-ENG-281 同源），豁免率是门禁健康度指标。
- 门禁可解释：每项检查输出「为什么检查它」——门禁不是关卡而是风险清单的执行。
- 追问钩子：为什么门禁要分「硬阻断」与「软警告」——全部硬阻断会导致高频豁免（门禁失效），全部软警告等于没有门禁；按风险分级（影响安全的硬、影响体验的软）保持门禁权威性与可执行性的平衡。

```javascript
async function releaseGates(release) {
  const hard = [ciGreen, artifactIntegrity, buildinfoReady, rollbackDrillValid];
  const soft = [changelogUpdated, announcementPosted];
  const hardFails = (await Promise.all(hard)).filter(r => !r.ok);
  if (hardFails.length) return block(hardFails);       // 硬门禁阻断
  const softWarns = (await Promise.all(soft)).filter(r => !r.ok);
  softWarns.forEach(w => warn(w));                     // 软门禁警告放行
  return proceed(release);
}
```
