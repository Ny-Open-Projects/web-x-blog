## OPS-275：发布与业务节奏怎么对齐？
**答**：
- 业务节奏约束：营销活动日（发布避开活动峰值）/财报静默期（界面变更冻结）/大版本业务里程碑（发布对齐业务上线时间）——发布日历与业务日历合并视图。
- 业务方参与：发布计划里标记「业务关键变更」（影响业务指标的），业务方参与验收（SCN-OPS-257 扩展）与放量决策（业务判断）。
- 双向承诺：技术承诺发布质量（灰度/哨兵），业务承诺配合窗口（验收人力/数据解读）——发布协同是双向契约。
- 节奏冲突仲裁：技术窗口与业务窗口冲突时（业务要提前/技术要延后）升级到联合决策——有仲裁机制而不是默认谁强势听谁的。
- 追问钩子：为什么「发布与业务日历合并视图」能预防大多数协同事故——最高频的协同事故是「技术发布撞上业务大促」（发布引发的性能劣化放大了活动影响）；合并视图让冲突在排期阶段就可见，比事故后互相指责便宜得多——日历是最便宜的协同工具。

```javascript
const businessCalendar = mergeCalendars({
  tech: releaseCalendar,                                // 技术发布窗口
  biz: [campaignDays, quietPeriod, milestones],         // 业务节奏
});
conflicts(businessCalendar).forEach(c => escalateArbitration(c));   // 冲突仲裁
plan.bizCritical && acceptBizOwner(plan);              // 业务方参与验收
```
