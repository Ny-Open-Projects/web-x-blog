## OPS-228：配置发布怎么统一？
**答**：
- 统一治理原则：配置变更与代码发布同级（审批/审计/哨兵/回滚全套）——「改个配置」的心态是配置事故的温床。
- 配置发布差异：生效即时（无构建过程）→ 更需要灰度（配置灰度按用户百分比）+ 快照回滚（秒级）；配置哨兵重点看「行为突变」（flag 变化即行为变化）。
- 配置依赖：配置间依赖（flag A 依赖 flag B）显式声明，变更时级联校验。
- 配置快照：每次配置状态全量快照（时间点还原能力），回滚到任意历史快照。
- 追问钩子：为什么配置发布「更需要灰度」——代码发布有构建/灰度/哨兵全套流程缓冲，配置变更往往即时全量生效；一次 flag 改错 = 全量用户立即受影响。给配置套上灰度（按用户比例）把「即时全量」变成「渐进生效」，是配置治理最核心的防线。

```javascript
async function publishConfig(change, { gray = true } = {}) {
  validateSchema(change);
  await approvals(change);                             // 与代码发布同级审批
  if (gray) await grayRollout(change, { stages: [1, 10, 50, 100] });   // 配置灰度
  snapshotConfig();                                    // 快照（可回滚任意历史点）
  watchBehaviorChange();                               // 配置哨兵：行为突变检测
}
```
