## ENG-285：工程化成熟度评估怎么做？
**答**：
- 评估维度：交付（CI/CD 效率）、质量（门禁/测试健康）、治理（依赖/规范/权限）、体验（DevEx/文档/支持）、智能（AI 采纳）——每维 1~5 级评分 + 证据。
- 评估方式：客观指标自动采集（DORA/CI 数据）+ 定性评审（抽样工程实践的实做情况：随机挑 PR 看评审质量）——指标好看但实做烂的情况要靠抽样抓。
- 产出：雷达图 + 每维度短板的改进计划（进下年度路线图，ENG-227）。
- 评估纪律：评估结果面向改进不用于团队排名（ENG-284 反模式防线）。
- 追问钩子：为什么成熟度评估要「抽样实做」而不能只看指标——指标反映「结果」，抽样反映「过程」（评审是否真的在看、门禁是否真的在拦）；指标可被长期优化到失真，过程抽样是对冲，两者结合才是可信评估。

```javascript
const maturityAssess = {
  dims: { delivery: doraScore, quality: gateHealth, governance: depSpecPerm,
          experience: devexSurvey, intelligence: aiAdoption },
  method: { objective: '自动指标', subjective: '随机 PR 过程抽样' },
  output: { radar: true, gaps: '短板改进计划 → 下年路线图' },
  discipline: '改进导向，不排名',
};
```
