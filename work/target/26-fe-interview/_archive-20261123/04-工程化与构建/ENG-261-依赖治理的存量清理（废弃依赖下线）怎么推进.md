## ENG-261：存量依赖清理怎么推进？
**答**：
- 使用面盘点：依赖被哪些包/多少调用点引用（模块图分析），替换成本 = 调用点数 × API 差异——按成本排序清理，先易后难建立势能。
- 替换策略：直接依赖换成新包（同 API 的轻量替代）→ API 适配层（封装差异，调用点改一处）→ codemod 批量迁移（ENG-207 同手法）。
- 治理手段：废弃依赖进「禁用清单」（新代码 import 即 CI 失败），存量调用点数 Ratchet 递减——只减不增的棘轮让清理有终局。
- 收益度量：清理后的 bundle 体积/安装时长/维护面变化，成果公示形成正循环。
- 追问钩子：为什么「禁用清单 + 调用点 Ratchet」优于「一次性大迁移 PR」——大迁移 PR 长期挂着（冲突不断、评审疲劳）且风险集中；棘轮让清理分散在日常 PR 里增量完成，风险面小且进度可见。

```javascript
// 依赖使用面盘点
usageOf('moment')  // -> { packages: 12, callSites: 143, apiDiff: 'small' }
// 棘轮递减
const current = countCallSites('moment');
if (current > budget('moment')) fail(`moment 调用点 ${current} > 预算 ${budget}`);
// 每次清理 PR 后下调预算
```
