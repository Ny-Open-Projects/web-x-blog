## ENG-260：工程度量看板怎么搭？
**答**：
- 核心四指标（DORA）：部署频率/变更前置时间/变更失败率/MTTR——围绕「交付吞吐与稳定性」的闭环。
- 工程健康度补充：CI 通过率与时长/门禁拦截数/flaky 率/依赖新鲜度/技术债 Ratchet——四指标之外的「过程健康」。
- 看板纪律：每个指标有 owner 与行动阈值（超标即触发行动而非只看）；季度评审砍掉「从未触发行动」的指标（SCN-SLA-704 同原则）。
- 团队级而非个人级：所有度量面向团队（反博弈设计，ENG-226 联动）。
- 追问钩子：为什么部署频率提升可能伴随失败率上升而这不是坏事——频率上升意味着部署变小（风险分散），失败率略升但 MTTR 与爆炸半径大幅下降；单独看失败率会误判，四指标必须成组解读。

```javascript
const engBoard = {
  dora: { deployFreq, leadTime, changeFailRate, mttr },   // 成组解读
  health: { ciPassRate, gateCatches, flakyRate, depFreshness, ratchetDebt },
  discipline: { owner: '每个指标必须有', actionThreshold: '超标即行动', quarterlyPrune: true },
  scope: 'team-level-only',
};
```
