## BLD-275：懒编译怎么做？
**答**：
- 动机：超大应用全量构建慢——但首屏只需要部分路由；懒编译 = 只构建当前导航需要的模块，跳转时按需构建（farm/vite 懒编译实验）。
- 实现：模块图懒解析（入口只解析顶层——动态 import 的目标延迟解析）、请求驱动（dev server 收到请求才构建该模块子图）。
- 风险：跳转时的构建延迟（从「全量预付」变「按需后付」）——预取策略平衡（idle 时预构建高频路由）。
- 与预构建的配合：依赖预构建（SCN-BLD-210）解决 node_modules、懒编译解决业务源码——两层按需。
- 追问钩子：为什么懒编译把「构建时长」问题转化为「跳转延迟」问题——总工作量没变，只是支付时点从「启动一次付清」变为「每次导航分期」；如果用户会遍历全部路由，总时长反而更长（每跳都付调度开销）——懒编译适合「路由访问局部性强」的应用（大部分会话只访问少数路由），判断依据是路由访问分布。

```javascript
// 请求驱动构建
devServer.onRequest(path => scheduler.ensureBuilt(path));   // 收到请求才构建
// 预取平衡
router.onNavigate(to => prefetchBuild(likelyRoutes(to)));   // idle 预构建
```
