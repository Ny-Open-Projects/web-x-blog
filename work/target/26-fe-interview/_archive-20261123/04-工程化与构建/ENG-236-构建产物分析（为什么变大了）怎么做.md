## ENG-236：产物分析怎么做？
**答**：
- 分析器三视角：体积构成（哪些模块占了多少）、依赖来源（为什么被引进来——追踪 import 链）、重复打包（同一包多实例）。
- 增量归因：PR 自动 diff 两版 bundle（按模块粒度），「+120KB 来自 lodash 全量引入」直接可读。
- 高频病根：moment/locale 全量、lodash 未按需、双版本共存（幽灵依赖的产物级表现）、polyfill 重复、sourcemap 误传线上。
- 治理输出：分析结果变成规则（bundle analyzer 进 CI 阻断重复打包），而不只是报告。
- 追问钩子：为什么「重复打包」要用 source 追踪而不是看产物名——产物 chunk 名被分割/改名后看不出重复；用模块 id（源文件路径 + 包版本）聚合才能发现 lodash@4 与 lodash@4.17 双实例这类根因。

```javascript
// 产物 diff（按模块）
const diff = bundleDiff(base, current);
diff.topIncreases().forEach(m =>
  console.log(`${m.module}: +${m.delta}KB (via ${m.importChain})`));
// 重复实例检测（按包版本聚合）
const dup = groupBy(modules, m => `${m.package}@${m.version}`)
  .filter(g => g.length > 1);
if (dup.length) fail(`重复打包: ${dup.map(d => d[0].package)}`);
```
