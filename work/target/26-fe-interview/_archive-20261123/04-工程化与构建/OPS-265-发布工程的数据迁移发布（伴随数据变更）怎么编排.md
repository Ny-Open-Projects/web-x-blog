## OPS-265：数据迁移发布怎么编排？
**答**：
- 编排三步：扩展阶段（新旧字段并存，写双读旧）→ 迁移阶段（后台任务刷历史数据）→ 收敛阶段（切读新、删旧）——每步独立发布独立验证，可停可回。
- 前端角色：扩展阶段前端已可用新字段（只读展示），迁移完成才切换写入——UI 的「新数据可见」与「旧数据兼容」分阶段灰度。
- 回滚语义：每步的回滚是「回退到上一步语义」而非回滚数据（数据向前兼容设计，SCN-OPS-205/234）。
- 迁移验证：迁移任务的完成度对账（迁移条数 vs 总条数）、抽样校验（迁移后数据正确性）——迁移没验证完不能进收敛阶段。
- 追问钩子：为什么数据迁移要「扩展→迁移→收敛」三步而不是「一步到位改 schema」——一步到位时新旧代码/数据必须同时切换，任何环节失败都是复合故障；三步让每一步可独立验证可独立回滚，且数据向前兼容（旧代码能读新数据）保证任意时刻回滚安全——这是 expand-contract 模式的标准价值。

```yaml
migration_plan:
  phase1_expand: { write: both, read: old, front: '新字段只读展示' }
  phase2_migrate: { job: 'backfill', verify: 'count-reconcile + sample-check' }
  phase3_contract: { read: new, drop: old, gate: 'phase2-verified' }
rollback: '回退到上一步语义（数据向前兼容）'
```
