## BLD-224：隐藏输入怎么治理？
**答**：
- 隐藏输入清单：未声明的 env、当前时间（Date.now 进产物——版本号戳）、文件系统状态（读取目录列表顺序）、git 状态（脏工作区进产物）——它们让「同 commit 不同产物」（可复现性破坏，SCN-ENG-222）。
- 治理手法：输入显式声明（构建配置声明 env 依赖清单，SCN-ENG-287）、时间固定（SOURCE_DATE_EPOCH）、顺序固定（目录遍历排序）、CI 干净环境。
- 检测工具：双次构建产物 diff（同 commit 同环境）——diff 非空即有隐藏输入。
- 追问钩子：为什么「时间戳进产物」是最常见的隐藏输入——版本标识/构建时间戳看起来无害，但它让每次构建产物必不同（hash 变化）——持久缓存失效 + 可复现性破坏 + CDN 缓存全部失效；解法 SOURCE_DATE_EPOCH 用 commit 时间替代当前时间——确定性时间戳是可复现构建的第一课。

```javascript
// 隐藏输入治理
const BUILD_TIME = process.env.SOURCE_DATE_EPOCH ?? '0';   // 固定时间
const files = fs.readdirSync(dir).sort();                  // 顺序固定
// 检测
buildTwiceAndDiff();   // 同 commit 两次构建产物应逐字节一致
```
