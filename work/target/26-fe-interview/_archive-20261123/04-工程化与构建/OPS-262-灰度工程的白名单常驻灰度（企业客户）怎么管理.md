## OPS-262：常驻灰度怎么管理？
**答**：
- 常驻 vs 常规：常规灰度是「临时手段」（7 天时限），常驻灰度是「产品形态」（企业客户长期用定制版本）——两者的治理模型完全不同，混用是混乱源头。
- 常驻版本管理：定制差异清单化（哪些功能/配置不同）、与主版本的兼容承诺（升级周期/回归范围）、差异代码的合并策略（feature flag 常驻 vs 独立分支——flag 常驻优于分支）。
- 升级协调：主版本升级时常驻客户的回归优先级（付费客户 SLA），升级前通知与窗口协商。
- 成本显性化：常驻差异的维护成本按客户分账——定制差异是有偿服务，成本不可见会导致无限定制。
- 追问钩子：为什么常驻定制「flag 常开」优于「独立分支维护」——独立分支与主版本渐行渐远（合并冲突指数上升，最终无法升级）；flag 常驻让定制差异始终在主代码树上（CI 同套流程验证），升级成本线性可控——长期定制是 flag 体系唯一合理常驻场景。

const standingGray = {
  taxonomy: { regular: '7d-limit', standing: 'product-form' },   // 分类治理

};
