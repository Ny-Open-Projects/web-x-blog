## OPS-273：计划冻结怎么设计？
**答**：
- 分离原则：审批批准的是「计划快照」（planId+版本 hash），执行只能按快照跑——执行时改动计划（加步骤/换版本）= 未审批的发布。
- 计划冻结点：审批通过即冻结；执行期需要变更计划 → 走计划修订流程（重新审批，修订留痕）。
- 紧急修订通道：执行中发现的紧急问题（依赖服务故障需跳过某步）走「执行中豁免」（值班权限 + 事后复审）——豁免留痕。
- 计划与实际的 diff：执行完成后对比「计划 vs 实际执行」（哪些步骤被跳过/重试）——偏差记录是流程改进的输入。
- 追问钩子：为什么执行必须按「审批时的快照」而不是「实时计划」——实时计划意味着审批者批准的内容与实际执行的内容可能不同（执行时加了危险步骤）；快照让「批准 = 授权该确切内容」，任何偏离都需要新的授权——审批的意义由此成立。

```javascript
const planSnapshot = freezePlan(plan);                 // 审批对象：planId+hash
approve(planSnapshot);
// 执行时
const actual = hash(currentPlan);
if (actual !== planSnapshot.hash) requireReApproval(); // 偏离 = 重新审批
// 紧急豁免（值班权限 + 事后复审）
emergencySkip(step, { by: oncall, reviewedAfter: true });
// 执行后 diff
const drift = diffPlan(planSnapshot, executionLog);    // 偏差 → 流程改进
```
