## ENG-222：可复现构建怎么保证？
**答**：
- 非确定源消除：时间戳（用 SOURCE_DATE_EPOCH）、随机顺序（排序模块图）、路径差异（相对路径/统一 root）、环境差异（锁 Node/工具链版本 + 容器化构建）。
- 验证机制：同 commit 双环境（本地/CI）构建 → 产物逐文件 hash 对比，diff 即暴露非确定源——一次校准终身受益。
- 价值：产物 hash 可作为缓存键与审计凭据（「这个线上 bundle 确实来自这个 commit」），供应链审计的基础（SCN-OPS-194 联动）。
- 工具支撑：确定性压缩（固定 gzip 字典参数）、版本 pin、`--frozen-lockfile`。
- 追问钩子：为什么 gzip 也会破坏可复现——gzip 头部带时间戳且压缩级别可能随环境不同；固定压缩参数与头部是构建可复现的隐蔽坑。

```bash
# 可复现性验证脚本
build_and_hash() {
  SOURCE_DATE_EPOCH=$(git log -1 --format=%ct) pnpm build
  find dist -type f -exec sha256sum {} \; | sort > $1
}
build_and_hash /tmp/ci.hash    # CI 环境
build_and_hash /tmp/local.hash # 本地
diff /tmp/ci.hash /tmp/local.hash && echo REPRODUCIBLE
# vite: build.modulePreload / terser 固定参数；gzip: 固定 level 与 mtime=0
```
