## ENG-275：多仓库收编怎么渐进做？
**答**：
- 收编排序：共享工具/组件库先收（协同收益最大、风险最低）→ 活跃业务 app → 低频遗留 app（可最后或永不收）。
- 收编手法：git subtree/filter-repo 保历史迁入 → 临时过渡（原仓库变镜像/废弃指针）→ CI 与发布路由切换。
- 兼容期治理：收编期间双仓库并存要锁死「改哪边」——原仓库归档只读（写操作 CI 拒绝），防止收编期双头修改。
- 验收：收编后跑通「affected 构建 + 统一发布」，与原仓库行为对齐才算完成。
- 追问钩子：为什么共享库先收编——共享库被多个仓库引用，是跨仓依赖地狱的源头；先收编共享库，各业务仓对它的依赖变成 workspace 内引用，后续业务仓收编时依赖面已就绪，风险递减。

```bash
# 保历史迁入
git filter-repo --subdirectory-filter packages/ui
git remote add mono ../mono && git push mono HEAD:import/ui
# 归档防双头写
# 原仓库 CI: [ "$(git log -1 --format=%H)" ] && echo "REPO ARCHIVED - 请在 monorepo 修改" && exit 1
```
