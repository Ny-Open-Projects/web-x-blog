## ENG-228：工程化推广怎么做？
**答**：
- 推广失败主因：只发公告不做迁移支持——正确姿势是「工具 + 迁移器 + 文档 + 冠军用户」四件套：codemod 让迁移成本趋零，样板项目给参照。
- 强制 vs 引导：核心护栏（安全/质量）强制（CI 门禁），效率工具引导（自愿 + 效果数据吸引）——一刀切强制效率工具会催生抵触。
- 冠军用户机制：每个团队 1 名工具 champion（参与设计/反馈/内部答疑），扩散速度远高于官方宣讲。
- 采纳度量与回退承诺：使用率曲线公开；承诺「数据证明无效则回退」——可回退承诺大幅降低采纳阻力。
- 追问钩子：为什么「可回退承诺」是推广关键——新工具的采纳阻力来自「万一不好用被锁死」的恐惧；明确回退路径把采纳风险归零，试用意愿倍增。

```javascript
const rollout = {
  kit: ['tool', 'codemod', 'docs+样板', 'champion-per-team'],
  enforceRule: (tool) => tool.isGuardrail ? 'CI 强制' : '自愿+数据吸引',
  metrics: { adoptionCurve: 'public', satisfaction: '月度调查' },
  rollbackPromise: '采纳率 < 30% 且满意度 < 3/5 → 回退',
};
```
