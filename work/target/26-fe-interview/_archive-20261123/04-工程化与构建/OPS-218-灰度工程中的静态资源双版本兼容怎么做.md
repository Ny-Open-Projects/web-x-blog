## OPS-218：双版本兼容怎么做？
**答**：
- 交叉引用风险：灰度期用户缓存里可能混合两版本的 chunk（v1 入口加载后 lazy chunk 被 v2 替换）——manifest 级隔离（每版本独立 manifest，入口只引用本版本 chunk）+ lazy chunk 保留上一版本（N-1 兼容窗口）。
- 加载失败兜底：chunk 加载失败（已被替换）自动 fallback 到对应版本入口刷新——「加载失败 → 版本对齐刷新」是 SPA 灰度的标准自愈。
- 版本协商：页面持有版本戳，API 响应带服务端期望版本，不匹配提示刷新（非强制）。
- 清理时机：N-1 资源在旧版本全量退出后 24h 清理（用户会话残留）。
- 追问钩子：为什么「chunk 加载失败自动刷新」是灰度期必备自愈——灰度期 lazy chunk 被新版本覆盖是常态（CDN 同路径更新或版本切换），用户手上旧入口请求新 chunk 必然 404；捕获 chunk error → 刷新对齐版本，把用户从「白屏死路」拉回，比任何预防都更兜底。

```javascript
window.addEventListener('error', (e) => {
  if (e.target?.tagName === 'SCRIPT' && /chunk|assets/.test(e.target.src)) {
    report({ type: 'CHUNK_LOAD_FAIL', src: e.target.src, version: window.__BUILD__.version });
    location.reload();                                 // 版本对齐自愈
  }
}, true);
```
