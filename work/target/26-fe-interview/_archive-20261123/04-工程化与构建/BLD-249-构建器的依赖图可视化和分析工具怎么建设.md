## BLD-249：依赖图工具怎么建设？
**答**：
- 三张图：模块依赖图（为什么这个模块被打进来——反向引用链）、chunk 归属图（模块进了哪个 chunk、为什么）、体积构成图（SCN-ENG-236）——三图合一的交互式分析。
- 关键能力：反向查询（「谁引用了 lodash」——从依赖出发查消费方）、假设分析（「如果移除某模块会怎样」——子图体积差）、diff 视图（两次构建的图对比）。
- 数据源：构建器导出的模块图 JSON（stats/manifest），工具独立于构建器消费（SCN-ENG-268 契约）。
- 集成方式：CLI + Web 交互（大图交互必须 Web），CI 注释引用静态视图。
- 追问钩子：为什么「反向查询」是依赖图工具最高频的能力——体积问题的第一问永远是「这个包为什么在产物里」；正向图（A 依赖 B）回答不了它，反向边（谁 import 了 lodash）才能给出引用链——依赖图工具的核心价值是把「引用链查询」做成 O(1)。

```javascript
// 反向查询
graph.reverse('lodash').chain();   // app → dashboard → lodash（引用链）
// 假设分析
graph.remove('lodash').sizeDelta();  // -72KB gzip（如果移除）
// diff 视图
graphDiff(buildA, buildB).addedModules();
```
