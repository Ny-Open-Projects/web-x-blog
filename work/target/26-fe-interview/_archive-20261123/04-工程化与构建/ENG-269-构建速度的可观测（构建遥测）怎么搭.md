## ENG-269：构建遥测怎么搭？
**答**：
- 遥测数据面：每次构建上报（本地/CI 标识/项目/任务/耗时分阶段/缓存命中/机器规格）——构建性能问题要按「谁/在哪/何时」聚类才可诊断。
- 分析视图：P95 按任务类型/机器规格分层；本地 vs CI 差异（本地慢通常是磁盘/杀毒软件）；缓存命中率随时间趋势。
- 告警：某项目构建 P95 劣化 20% 自动开 issue（防劣化的自动哨兵，ENG-221 Ratchet 的动态版）。
- 隐私边界：遥测不含源码内容只含元数据；可退出。
- 追问钩子：为什么「本地 vs CI 差异」值得单独看——同一 commit 两端耗时差 5 倍时，问题多半不在构建配置而在环境（Node 版本/磁盘/依赖安装残留）；分环境聚类让「优化配置」和「修环境」两条路径不再混谈。

```javascript
// 构建遥测上报
telemetry.push({
  scope: 'local|ci', project, task: 'build',
  phases: { resolve, transform, emit }, cacheHit,
  machine: { cpu, mem, diskType },
});
// 自动哨兵
if (p95(project) > baseline * 1.2) autoIssue('build-regression', project);
```
