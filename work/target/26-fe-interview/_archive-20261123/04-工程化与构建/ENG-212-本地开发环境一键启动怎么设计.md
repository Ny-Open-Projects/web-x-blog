## ENG-212：一键启动怎么设计？
**答**：
- 环境即代码：devcontainer/nix flakes 锁定 Node 版本/系统依赖/环境变量模板——「在我机器上是好的」从根上消灭。
- 启动编排：`pnpm setup` 一条命令完成 install/codegen/mock 服务启动/种子数据注入；中间步骤失败给可行动提示（不是报错堆栈）。
- 时间预算：新机器到可开发 ≤ 15 分钟（install 5 + codegen 2 + 启动 1 + 验证 1），超预算即 DevEx 事故进优化清单。
- 外部依赖最小化：本地启动不依赖真实后端（mock server 内置）、不依赖特殊权限（无需 VPN 即可纯前端开发）。
- 追问钩子：为什么 mock server 要内置而不是「连测试环境」——测试环境不稳定/数据脏/需要 VPN；本地 mock 让前端开发零外部依赖，断网也能开发，这才是「一键」的含义。

```yaml
# devcontainer.json —— 环境即代码
{ "image": "mcr.microsoft.com/devcontainers/typescript-node:20",
  "postCreateCommand": "pnpm setup",
  "customizations": { "vscode": { "extensions": ["dbaeumer.vscode-eslint", "esbenp.prettier-vscode"] } } }
```
```jsonc
// package.json —— 编排入口
{ "scripts": {
  "setup": "pnpm install && pnpm codegen && pnpm mock:seed && pnpm verify",
  "verify": "node scripts/verify-env.js"   // 检查并给出可行动提示
} }
```
