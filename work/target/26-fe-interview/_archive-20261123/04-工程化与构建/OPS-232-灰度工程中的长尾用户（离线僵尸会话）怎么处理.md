## OPS-232：长尾用户怎么处理？
**答**：
- 长会话用户：挂机页面（后台 Tab 开几天）一直跑旧版本——发布时旧会话怎么办：旧版本继续跑（本地可用）但 API 响应带版本协商，行为差异提示刷新；不强制刷新（用户可能在做表单）。
- 离线/弱网设备：灰度标记与版本更新延迟到达——SW 缓存的旧版本继续服务，版本对齐在下次在线时完成（最终一致）。
- 长尾监控：旧版本残留率看板（还在报旧 buildinfo 的用户占比）——残留率 > 阈值说明「版本对齐机制失效」（刷新提示没触达）。
- 强制对齐的边界：交易页面不强制刷新（防丢单），内容页面可温和引导。
- 追问钩子：为什么旧版本残留率是灰度收尾的关键指标——全量发布 ≠ 所有用户都用上新版（长会话/离线设备可能拖几天）；残留率高说明「版本对齐通道」失效（chunk 错误自愈/刷新提示没生效），N-1 资源清理和旧版本依赖都要等残留率收敛后再做。

```javascript
// 版本协商：API 响应带服务端期望版本
api.interceptors.response.use(res => {
  if (res.headers['x-expected-version'] !== window.__BUILD__.version)
    showSoftRefreshHint('有新版本可用');               // 温和引导（交易页不强制）
  return res;
});
// 残留率监控
telemetry.push({ type: 'version-report', version: window.__BUILD__.version });
const residueRate = oldVersionUsers / totalUsers;
```
