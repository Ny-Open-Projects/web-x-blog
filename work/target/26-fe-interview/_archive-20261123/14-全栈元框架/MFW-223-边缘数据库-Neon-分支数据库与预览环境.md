## MFW-223：Neon 分支数据库

**答**:
- 机制：copy-on-write 数据库分支（基于存储快照秒级建分支，零拷贝）——git 工作流搬到数据库（每个 PR 一分支）
- 预览环境联动：Vercel PR 预览 → 自动建 DB 分支（带生产快照）→ 预览环境用真实数据形状测试（含迁移验证）→ PR 合并删分支
- 价值场景：①迁移安全验证（migration 先在分支跑）②数据 Bug 复现（用生产快照分支 debug）③多环境成本砍半（分支存储只存增量）
- 边界：写入扩散（分支上大量写 → 存储增长）、敏感数据合规（生产数据进预览分支——脱敏策略要前置）

```text
流程：PR → Neon 分支（COW 快照）→ 预览环境用真实形状 → merge 删分支
价值：迁移预演 / bug 复现 / 存储成本（分支只存增量）
红线：生产数据进预览前脱敏（合规）
```
