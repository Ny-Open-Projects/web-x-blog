## MFW-348：死配置检测

**答**:
- 问题形态：环境配置矩阵（MFW-342）随业务演化遗留死键（没人读了但每个环境都在维护——配置税与心智噪音；更危险的是「以为生效实际没人读」的假开关）
- 检测原理：配置键的消费图 = 代码中对 config.x 的引用集（AST 扫描：直接访问/解构/动态键白名单豁免清单）——引用集 ∪ 动态豁免 ≠ 全键集 → 死键候选
- 分级处置：连续 2 个版本零引用 → deprecated 标记（日志提醒一次）→ 移除 PR（附引用扫描证据——防误删动态键）；假开关（影响行为的键引用为零）优先移除（安全幻觉最危险）
- 预防：新配置键注册制（PR 模板字段：消费者/默认值/清理计划——与 Cookie 矩阵同构治理）

```javascript
// 消费图扫描（简化）
const refs = scanProgram(cfg => cfg.output.locale || destructure('config'))
const dead = allKeys.filter(k => !refs.has(k) && !DYNAMIC_OK.has(k))
// 分级：zeroRef×2 版本 → deprecate warn → remove PR（附证据）
// 假开关（零引用的行为键）→ 最先移除
```
