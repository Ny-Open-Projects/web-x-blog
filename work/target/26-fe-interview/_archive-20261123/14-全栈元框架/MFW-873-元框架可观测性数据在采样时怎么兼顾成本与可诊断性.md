## MFW-873：元框架可观测性数据在采样时怎么兼顾成本与可诊断性

**答**：
- 结论：高频正常流量抽样、低频异常流量全采；错误和慢请求必须保留（可诊断性），海量成功请求按比例抽样（控成本）。
- 落地：按路由基线采样率 + 错误/超时强制采样 + 关键业务全采；采样决策在 trace 根处一次性决定并向下传递。
- 追问钩子：为什么不在采集端二次抽样？——会破坏同一 trace 的完整性（父采子不采）。

```javascript
function shouldSample(trace) {
  if (trace.error || trace.status >= 500) return true;   // 错误全采
  if (trace.duration > 1000) return true;                // 慢请求全采
  const base = SAMPLE_RATE[trace.route] ?? 0.01;         // 路由基线
  return hash(trace.traceId) % 10000 < base * 10000;    // 稳定哈希抽样
}
// 采样决策在入口决定，整条 trace 共享同一标志
const sampled = shouldSample(rootSpan);
ctx.sampled = sampled;                                   // 向下传递
// 导出端只上报 sampled=true 的 trace
```
