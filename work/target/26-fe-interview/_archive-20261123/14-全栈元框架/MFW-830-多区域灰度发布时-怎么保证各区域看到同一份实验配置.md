## MFW-830：多区域灰度发布时，怎么保证各区域看到同一份实验配置

**答**：
- 结论：配置中心推送有延迟，各区版本可能不一致；用「全局配置版本号 + 生效时间戳」：变更带全局递增版本与生效时间，各区按期切换，读取时校验本地版本落后则拉取。
- 兜底：生效时间前到达的请求用旧版本、之后用新版本；短 TTL + 强制刷新把窗口收敛。
- 追问钩子：用户跨区漂移看到不同版本怎么办？——用 cookie 固定实验版本（sticky），保证同一用户体验一致。

```javascript
// 配置带全局版本与生效时间
const config = { version: 42, effectiveAt: 1732400000000, variants: ['A', 'B'] };

async function getVariant(req) {
  // 用户 sticky：cookie 已有版本则沿用，避免跨区漂移
  const sticky = req.cookies.get('exp-version');
  if (sticky) return sticky;
  const cfg = await localConfig.get();               // 本区配置
  let active = cfg;
  if (cfg.version < (await globalConfig.version()))  // 本地落后 → 拉取
    active = await globalConfig.fetch();
  if (Date.now() < active.effectiveAt) active = await globalConfig.previous();
  const v = assign(req.userId, active.variants);
  req.cookies.set('exp-version', v, { maxAge: 86400 });
  return v;
}
function assign(uid, variants) { return variants[fnv(uid) % variants.length]; }
```
