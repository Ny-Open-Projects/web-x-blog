## MFW-357：Feature Store 推送链

**答**:
- 全链设计：管理台变更（审批流）→ 配置中心（版本化/审计）→ 双推（CDN 配置文件版本化 URL + 长轮询/SSE 通知失效）→ 服务端渲染读取（请求时最新已发布版本）+ 客户端热生效（订阅通道）
- 版本与回滚：每次发布 snapshot（immutable 版本文件）→ 回滚=指针回退（秒级）——配置发布用与代码发布同级的原子协议（MFW-295 复用）
- 一致性窗口：客户端热生效与服务端渲染可能短暂分叉（用户看到混合）——可接受域声明（仅 UI 开关类可热混；逻辑类 flag 标「需刷新」强一致）
- 熔断：配置服务不可用 → 各端用最后已知好版本（LKG 快照本地持久化——配置中心不是渲染的前置依赖）

```text
链：审批变更 → 版本化中心 → 双推(文件+通知) → SSR 读已发布版 / 客户端热更
保障：snapshot 回滚指针 / 热混可接受域声明 / LKG 熔断
```
