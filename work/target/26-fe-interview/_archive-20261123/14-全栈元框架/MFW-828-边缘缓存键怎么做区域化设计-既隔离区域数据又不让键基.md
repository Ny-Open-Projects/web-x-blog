## MFW-828：边缘缓存键怎么做区域化设计，既隔离区域数据又不让键基数爆炸

**答**：
- 结论：按「数据是否区域相关」分层——全局共享数据（商品详情）用全局键 + 版本号；区域数据（库存、价格）用 region 前缀键；二者隔离避免跨区缓存污染。
- 反模式：把 userId/sessionId 直接进全局键，导致基数爆炸 + 缓存永不命中。
- 追问钩子：区域键怎么控制基数？——region 只有有限个（几十个 PoP），配合版本号而非用户维度。

```javascript
const REGION_SCOPED = new Set(['/api/price', '/api/stock']);
function buildKey({ path, version, region }) {
  const base = path + '@' + version;                // 版本号进键
  // 区域数据加 region 前缀，全局数据共享同一键
  return REGION_SCOPED.has(path) ? `r:${region}:${base}` : `g:${base}`;
}
console.log(buildKey({ path: '/p/1', version: 7, region: 'cn-east' }));
// g:/p/1@7  —— 全球共享
console.log(buildKey({ path: '/api/stock', version: 7, region: 'cn-east' }));
// r:cn-east:/api/stock@7 —— 区域隔离，避免串区
// ✗ 反模式：g:uid-123:/p/1 —— 每个用户一份，缓存永不命中
```
