## MFW-363：数据蓝图静态分析

**答**:
- 动机：路由的数据依赖（哪些 tag/哪些表/哪些权限点）散落在代码里——构建期静态提取成「路由蓝图」（route → { tags[], tables[], authz[], expectedMs }）成为治理的单一事实源
- 提取实现：编译器插件/AST 走访（Next 的 build 钩子或 SWC transform）——收集 fetch tag 字面量、ORM 模型引用、can() 调用——动态值标 unknown 进人工确认清单
- 三个消费方：①失效对账（MFW-293 注册表自动生成——不再手维护）②容量预算表校验（蓝图 ms vs 声明预算）③权限矩阵导出（安全审计输入）
- CI 守门：蓝图 diff 进 PR 评论（这个 PR 让 /orders 页新增了 payments 表依赖+新权限点——架构评审一目了然）

```javascript
// build 钩子产出 blueprint.json
{ "/orders/:id': { tags: ['order:*', 'user:*'], tables: ['orders','payments'],
    authz: ['order:read'], p95Ms: 420 } }
// CI: blueprint diff → PR 评论；失效注册表/预算表/权限矩阵三处自动同步
```
