## MFW-184：电商大促页、内容站、SaaS 后台、Dashboard 各怎么选框架与渲染模式？
**答**：
- 电商大促页（流量尖峰、SEO 强）：Next/Nuxt 混合渲染——商品详情 ISR + tag 失效，列表 PPR（静态壳 + 动态价格孔），CDN SWR 兜底；写操作走 Server Action；重点防缓存击穿（预热 + 请求合并）。
- 内容站（读多写少、 SEO 绝对主导）：Astro 或 SSG——构建期静态化 + Content Layer，交互很少用 islands 点缀；动态个性化用 Server Islands。框架选 Astro 胜在产出体积与心智简单。
- SaaS 后台（登录态、强交互、SEO 无关）：React Router v7 / TanStack Start 的 SPA 或 SSR-light 模式都行，重点不是渲染模式而是数据层（Query 缓存 + 乐观更新）与类型安全（TanStack Router/RRv7 typegen）。
- 运营 Dashboard/监控（实时数据）：SSR 反而有害（数据秒变），用 SSR 壳 + 客户端订阅（SSE/WebSocket），或 RRv7 SPA 模式 + Suspense 流式首帧。
- 通用决策链：① SEO 需求 → 决定 SSR/SSG 与否；② 个性化占比 → 决定动态孔方案；③ 交互密度 → 决定框架生态（React 全家桶 vs islands）；④ 团队栈 → 决定 Vue/React/Svelte。

```text
SEO 强 + 交互弱 ──> Astro/SSG（内容站）
SEO 强 + 交互强 ──> Next/Nuxt 混合渲染（电商）
SEO 弱 + 交互强 ──> RRv7/TanStack Start SPA（后台）
数据实时 + 全屏 ──> SPA + 订阅（Dashboard），SSR 只做壳
```
