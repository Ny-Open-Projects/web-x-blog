## MFW-220：放弃自建的判断信号

**答**:
- 六个危险信号：①路由/渲染补丁频率上升（每月都在修框架 bug）②新特性需求（PPR/Server Actions/Suspense 数据流）开始排队 ③核心维护者离职风险（bus factor 1）④安全公告需要自己跟进（React 序列化漏洞类——上游框架替你盯）⑤新人 onboarding 时间超过一周（框架学习成本反噬）⑥性能优化停滞（自建优化到顶，而新框架版本性能碾压）
- 灰度回迁路径：自建路由 → 保留（兼容层好写）；数据层 → 回 TanStack Query（接口相似）；渲染 → 回 Next（最大迁移项，按路由分批）
- 决策表格式：每个信号打分（频率×影响），总分超阈值启动回迁评估——「沉没成本」是最大的迁移敌人（已写 3 万行不是继续写的理由）

```text
危险信号记分卡（每月评估）：
框架 bug 修复 PR 数 / 新特性排队数 / bus factor / 安全跟进负担 / onboarding 周期 / 性能差距
≥3 项红灯 → 启动回迁评估（灰度按路由分批回 Next/Start）
```
