## MFW-559：并行路由与拦截路由的产物语义

**答**:
- 并行路由（@slot）：同一路由多槽位渲染（@modal 与 children 并行——每个 slot 独立加载/独立 error/loading）；产物语义：段树多分支（payload 含多 slot）；slot 的独立导航（modal 内容变化不影响 children）。
- 拦截路由 (.)..(..)：同 URL 不同渲染上下文（列表内点击 → modal 内详情（拦截）；直接访问 URL → 全页详情）——「上下文相关的路由」（软导航拦截、硬导航不拦）；产物：拦截段只进 client 导航 payload（直接访问路径不含拦截段）。
- 复杂形态的成本：slot/拦截的排列组合 = 段树爆炸（缓存键/预取范围膨胀）；「复杂路由的产物成本」需要预算（RBL-553 成本归因）。
- 追问钩子：为什么「拦截路由只在软导航生效」是协议设计的关键？——拦截的语义是「用户上下文继承」（在列表页点击 → 用户期望 modal 内展示——上下文 = 当前页面）；直接访问 URL 无上下文（刷新后 modal 里没有列表——回退语义破坏）→ 全页渲染；「URL 的上下文依赖」是 SPA 的经典矛盾（可分享性 vs 上下文连贯）——拦截路由的「软导航才拦截」是折中：URL 可分享（全页）+ 上下文连贯（软导航 modal）。

```tsx
// 并行路由：@modal + children
// app/products/layout.tsx
export default function Layout({ children, modal }: { children: ReactNode; modal: ReactNode }) {
  return <>{children}{modal}</>;                         // 两 slot 并行渲染
}
// app/products/@modal/[id]/page.tsx                      → modal 内详情
// app/products/[id]/page.tsx                             → 全页详情（直接访问）
// app/products/@modal/default.tsx                        → 无 modal 时 null
// 拦截路由：(.)捕获同级、(..)捕获上级、(...)捕获根
// app/products/(.)[id]/page.tsx                          → 软导航拦截为 modal
// 拦截段只在 client 导航 payload；硬导航直接走 /products/[id] 全页
```
