## MFW-889：锁文件和依赖解析的非确定性怎么影响构建复现

**答**：
- 结论：锁文件（package-lock/pnpm-lock）固定依赖树，但不同包管理器的解析算法、peer 依赖处理、可选依赖平台差异会带来非确定性；统一包管理器与锁文件版本是前提。
- 落地：CI 用 frozen-lockfile 安装；提交锁文件；对齐 Node 与包管理器版本；对原生模块按平台锁定。
- 追问钩子：pnpm 比 npm 更确定吗？——pnpm 的内容寻址存储 + 严格锁文件通常更可复现，但仍需 frozen 安装。

```bash
# CI 强制 frozen 安装：锁文件与 package.json 不一致即失败
npm ci                       # npm：按 lock 精确安装
# 或
pnpm install --frozen-lockfile

# 校验：安装后 lock 文件不应被修改
git diff --exit-code pnpm-lock.yaml || echo "锁文件被改动 → 非确定性！"
# 对齐版本
# engines: { node: ">=20.0.0" }, packageManager: "pnpm@9.1.0"

# 对齐工具链版本（版本差异会改变解析结果）
node -v                      # 确认 CI 与本地一致
pnpm -v

# 原生模块按平台锁定 lock（optionalDependencies 含各平台二进制）
# 避免不同机器装到不同平台的包导致产物漂移

# 校验 lock 中的解析版本确实满足 package.json 范围
pnpm install --frozen-lockfile --offline   # 离线：确保不联网拉新版本
```
