## MFW-885：灰度回滚后仍在上报的实验事件怎么处理才不污染数据

**答**：
- 结论：回滚后旧变体代码可能仍在上报事件，需给事件打「配置版本/实验版本」标签，分析时按版本过滤；服务端拒绝已结束实验的上报或标记为无效。
- 落地：事件携带 expVersion，实验结束/回滚后该版本进入终态；分析管道过滤终态版本的迟到事件，或单列观察。
- 追问钩子：为什么不能简单丢弃迟到事件？——可能包含回滚前的真实用户行为，应保留但标记，供审计而非入主指标。

```javascript
function onExperimentEvent(evt) {
  const state = expRegistry.get(evt.expName);        // { version, ended }
  if (state.ended && evt.expVersion === state.version) {
    metrics.inc('exp.late_event', { exp: evt.expName }); // 计数，不入主指标
    store.append({ ...evt, invalid: true });            // 保留供审计
    return;
  }
  store.append({ ...evt, invalid: false });              // 正常入分析
}
// 分析管道：WHERE invalid = false 计算主指标
```
