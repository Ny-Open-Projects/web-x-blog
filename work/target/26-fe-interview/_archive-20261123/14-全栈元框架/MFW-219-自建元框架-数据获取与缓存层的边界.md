## MFW-219：自建的数据层边界

**答**:
- 建议边界：自建「请求级去重 + SSR 预取注入」薄层（几十行：fetch 包装 + per-request Map + 序列化到 HTML），不建缓存语义（staleTime/revalidate/失效协议——这些是 TanStack Query 的核心价值，自建是重复造失效协议的坑）
- 组合模式：自建薄层负责「SSR 预取→注入→客户端复水启动」，之后一切交给 Query（失效/重试/缓存生命周期）
- 需要服务端缓存语义时（Data Cache 类）：显式引入独立缓存组件（Redis 层 API 化）而不是把缓存语义塞进前端 fetch 包装——关注点分离
- 信号：当你开始在自己 fetch 包装里写「tag」「revalidate」——越界了，要么认真建（一年工作量）要么换框架

```javascript
// 自建薄层：仅 SSR 预取 + 注入（~40 行）
const serverCache = new AsyncLocalStorage()      // 每请求去重 Map
export async function fetchCheap(key, fn) {
  const map = serverSeq.getStore()
  if (!map) return clientQuery(client, key, fn)   // 客户端 → Query
  if (!map.has(key)) map.set(key, fn())           // 服务端去重
  return map.get(key)
}
// HTML 注入：<script>window.__PRESET__=...</script> → 客户端 queryClient.setQueryData 复水
```
