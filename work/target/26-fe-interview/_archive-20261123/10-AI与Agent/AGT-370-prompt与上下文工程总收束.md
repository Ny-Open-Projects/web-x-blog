## AGT-370：Prompt 与上下文工程的体系怎么收束？

**答**:
- 体系四层：Prompt 架构（分区/分层/条款化/版本化，AGT-361/321）、上下文装配（预算分配/优先级保留/动态注入，AGT-221/363）、示例工程（动态 few-shot/边界示例，AGT-362）、调试与评测（回放/消融/格式纪律，AGT-369/368）——prompt 工程已从"写好一句话"进化为"信息供给系统工程"。
- 核心认知一：上下文是稀缺资源，工程本质是信息调度（AGT-230）——每一块上下文都要论证"为什么值得占用注意力预算"。
- 核心认知二：上下文问题的占比远大于模型能力问题——badcase 排查先查上下文（AGT-369），大多数"模型不行"是"没喂对"。
- 核心认知三：上下文工程与软件工程同构——版本化/评审/门禁/监控全套适用（AGT-321），prompt 是"用自然语言写的代码"，用管理代码的纪律管理它。

```text
上下文工程四层：
架构：分区 / 三层叠加 / 条款化 / 版本化
装配：预算分段 / 关键项永不摘要 /
  动态注入
示例：动态 few-shot / 边界示例 /
  质量即上限
调试：trace 回放 / 消融实验 /
  注入审计
三认知：信息调度 / 先查上下文再怪模型
  / 用代码纪律管理 prompt。
```
