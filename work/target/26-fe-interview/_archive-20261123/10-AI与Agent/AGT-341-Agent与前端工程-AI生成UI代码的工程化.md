## AGT-341：AI 从设计稿/自然语言生成前端代码，怎么保证工程可维护？

**答**:
- 约束优先于自由生成：给 AI 的不是空白项目而是"带约束的脚手架"——组件库（只用内部组件库不造轮子）、设计 token（颜色/间距走变量）、目录与命名规范——生成代码的质量上限由约束质量决定，裸生成必然风格漂移。
- 管线分层：设计稿→结构化描述（AI 解析设计稿为组件树+token 映射）→代码生成（模板化+组件库调用）→静态校验（lint/类型/可访问性检查，AGT-264 工具化校验）→视觉比对（截图与设计稿 diff）——每层校验把错误挡在合并前。
- 可维护性要求：生成代码进正常 PR 流程（人审+测试），复杂组件拆分为可复用组件而非巨型块；生成物带来源标注（AI 生成段注释，便于后续追踪）。
- 评测：视觉还原度（像素 diff）、代码规范通过率、人审修改量（趋势下降=生成质量在提升）。

```text
AI 生成 UI 管线：
约束：组件库 + 设计 token + 规范
分层：设计稿 → 结构化描述 →
  模板化生成 → lint/类型/a11y 校验
  → 视觉 diff → 人审 PR
可维护：拆组件/带来源标注/
  走正常评审。
评测：还原度 / 规范通过率 / 修改量趋势。
```
