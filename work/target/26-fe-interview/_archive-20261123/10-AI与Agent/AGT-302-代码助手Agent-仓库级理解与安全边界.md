## AGT-302：能读懂整个仓库并修改代码的 Agent 怎么设计？

**答**:
- 仓库理解：代码检索层（符号索引/调用图+embedding 双路，"找实现"用符号索引、"找相似逻辑"用向量）、上下文构造（改一处代码需要相关文件+类型定义+测试——按依赖图拉取上下文而非全仓库塞入，AGT-227）。
- 任务模式：只读问答（解释/评审）直接答；修改任务走"计划→修改→自测→人审"工作流——diff 呈现给人审（AGT-286），测试与 lint 作为自校验（AGT-264 的工具化校验）。
- 安全边界：执行类操作（跑测试/装依赖）在沙箱（AGT-284）；仓库权限按用户 scope（Agent 只能改用户有权限的仓库）；生成的代码进 PR 流程而非直接 push——代码助手的一切产出走人类评审闭环。
- 评测：修复率（真实 issue 能否修好）+ 回归安全率（修改不破坏其他测试）+ diff 质量（人工评审通过率）——代码 Agent 的评测围绕"可合并的 PR"而非"看起来对"。

```text
代码 Agent 设计：
理解：符号索引 + 向量双路检索；
  按依赖图拉上下文
流程：只读→直答；修改→计划→diff
  →沙箱自测（lint/单测）→ 人审 PR
安全：沙箱执行 + 用户 repo scope +
  只出 PR 不直推
评测：修复率 / 回归安全率 / 评审通过率。
```
