## 1074：线上事故怎么高效转化成评测用例

**答**：
- 转化五步：定界（trace 确认失败环节与根因）→ 采样（该事故模式下的同型样本抽 3~5 条）→ 脱敏（PII 处理）→ 建题（query + 期望行为 + 归因标签）→ 入回归集（打 incident 标签，修复验证用）。
- 关键纪律：期望行为写成「行为断言」不只写结果断言（事故常是行为错而结果碰巧对）；事故标签让「同类事故复发率」可统计——这是防复发 KPI。
- 时效要求：事故闭环的最后一环就是用例入库，修复 PR 必须引用回归用例 ID，否则合并被挡。
- 追问钩子：事故太多转不过来怎么办？——按「根因类别」聚合转化（同类事故转一条代表用例 + 标签），单条事故不强制一题，类别覆盖率优先于个案覆盖。

```ts
async function fromIncident(incident) {
  const root = await triage(incident.trace);          // 归因
  const samples = await similarIncidents(root.kind, 3); // 同型样本
  const case_ = await buildCase({ from: incident.id,
    query: samples[0].query, behavior: root.expectedBehavior,
    tags: ['incident', root.kind], pii: sanitize(samples) });
  await evalStore.add(case_, { gate: 'must-fix' });   // 修复 PR 必须引用
  return case_.id;
}
```
