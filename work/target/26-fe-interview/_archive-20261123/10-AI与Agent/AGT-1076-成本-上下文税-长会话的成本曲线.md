## 1076：长会话的成本为什么超线性增长

**答**：
- 超线性根因：每轮都要重发全部历史（无状态 API），第 n 轮成本 ∝ n²（累计历史 × 轮数）；100 轮会话的后期单轮成本是前期的几十倍。
- 治理组合：历史压缩（超阈值滚动摘要）、prompt 前缀缓存（历史稳定部分命中 KV cache，输入成本降一个数量级）、外部记忆（把不常用历史挪到检索库按需召回而不是全量随身携带）。
- 感知设计：会话超长时主动提示「开启新会话并自动带上下文摘要」，比无限续聊省钱且模型表现更好（超长上下文质量下降）。
- 追问钩子：压缩历史会丢信息，怎么权衡？——按「引用频率」决定保留：被后续轮次引用过的内容保留原文，从未引用的进摘要，用数据说话。

```ts
async function turnCostAware(session, input) {
  if (est(session.history) > COMPACT_AT) {
    session.history = await compact(session.history);       // 滚动压缩
  }
  const stablePrefix = hash(session.system + session.summary); // 前缀缓存
  return llm(buildPrompt(session, input), { promptCache: { key: stablePrefix } });
}
```
