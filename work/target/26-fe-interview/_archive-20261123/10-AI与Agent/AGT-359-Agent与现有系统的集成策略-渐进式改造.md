## AGT-359：把 Agent 能力接入存量系统，渐进式改造怎么排？

**答**:
- 集成模式四档：嵌入（现有页面加 AI 卡片：摘要/问答——最低风险）、增强（现有流程插入 AI 步骤：工单自动分类后进人审）、旁路（AI 并行跑同任务对照，验证后切换，AGT-256 影子思路）、重构（AI-native 重做流程——最后才做）——风险与收益递增，按顺序推进不跳级。
- 集成的工程接缝：存量系统的 API 质量决定 Agent 集成难度（无 API 的老系统只能 UI 自动化——脆弱，优先补 API/MCP 出口 AGT-345）；数据出口（现有权限体系与 Agent 的 ACL 对齐，AGT-283）。
- 组织接缝：存量系统的 owner 团队与 AI 团队的协作模式（AI 团队出能力，业务团队出场景与验收——AGT-328 场景包模式）；变更节奏对齐（Agent 上线不改存量系统行为——旁路阶段零侵入）。
- 回滚设计：每档集成都有"退回原流程"的开关——Agent 接入必须可逆，这是存量系统改造的铁律。

```text
集成四档（按序不跳级）：
嵌入：页面加 AI 卡片（低风险）
增强：流程插 AI 步骤（人审兜底）
旁路：AI 并行对照 → 验证后切换（零侵入）
重构：AI-native 重做（最后）
接缝：优先补 API/MCP 出口；
  ACL 对齐；每档有回退开关
  —— 接入必须可逆。
```
