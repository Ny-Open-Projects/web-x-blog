## AGT-294：流式对话中途刷新页面或断网，恢复机制怎么设计？

**答**:
- 服务端为源：Agent 的生成状态持久化在服务端（消息+已产生 delta 落库）——前端任何中断都不丢内容；前端重连后带 `lastSeq` 请求增量（AGT-291 的 Last-Event-ID 续传），服务端从持久化流重放。
- 断网重连策略：指数退避重连 + 重连后先拉"自上次确认点以来的落库内容"再继续流——双保险避免 SSE 重连窗口期丢帧；连续失败转降级（轮询完整消息）。
- 页面刷新场景：进入会话时拉全量消息+检查"进行中任务"（服务端任务状态表）——若有未完成任务，重新挂流而不是重跑任务（幂等：任务 id 关联）。
- 多端一致性：同一账号多标签页/设备同时打开——用任务级订阅（同一任务流多端共享）或后进端显示"在其他设备进行中"的只读状态，避免双流互踩。

```javascript
async function reconnect(convId, lastSeq) {
  const { events, active } = await fetch(
    `/api/conv/${convId}/stream?after=${lastSeq}`);
  replay(events);                                 // 补齐落库帧
  if (active) attachSSE(convId, lastSeq);         // 续流
  else if (pending) poll(convId);                 // 降级轮询
}
// SSE 自动重连带 Last-Event-ID；
// 失败 3 次 → 转轮询完整消息。
```
