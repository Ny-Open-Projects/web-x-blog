## AGT-245：给 Agent 提供工具时，粒度怎么设计——粗粒度还是细粒度？

**答**:
- 两极的失败模式：太细（工具爆炸——几十个原子工具，模型选择困难、上下文塞满 schema、一次任务调用十几轮）；太粗（一个万能工具吃所有参数——schema 巨大且模糊，模型传参错误率高、复用性差）。
- 设计原则：按"模型的一个决策单元"切——一个工具 = 模型一次有意义的决策（`search_flights` 是一个决策单元，`http_request` 太粗，`flight_search_step1` 太细）；高频组合流程可以封装为一个高阶工具（`book_flight = search + hold + pay`），把固定流程固化降低模型负担。
- 数量控制：单 Server 工具数建议 ≤10~15，超出按域拆分 Server 或做工具检索（先按任务匹配相关工具子集再注入）——工具列表本身就是上下文成本。
- 参数设计：必填参数最少化（可选的给默认值），枚举代替自由字符串，参数名自解释——每个参数都是模型出错的机会。

```text
工具粒度设计原则：
一个工具 = 模型一次决策单元
太粗：http_request(url, body) → 传参错误率高
太细：step1_auth step2_search ... → 选择困难
封装：固定流程 → 高阶工具（book_flight
  = search+hold+pay）
数量：≤10~15/Server，超出按域拆
  或动态注入相关子集
参数：必填最少化 / 枚举优于自由文本 /
  名称自解释。
```
