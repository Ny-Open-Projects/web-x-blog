## AGT-330：长期记忆里的冲突与过时信息怎么治理？

**答**:
- 冲突来源：用户偏好变化（去年喜欢 A 今年喜欢 B）、事实变化（项目从 X 迁到 Y）、来源冲突（用户说的与系统记录的不一致）——冲突不处理，记忆越多答案越乱。
- 治理机制：时间戳与版本（每条记忆带时间与来源，新记忆生成时与相关旧记忆比对，冲突显式标记而非覆盖——保留历史便于回溯与用户修正）、置信度衰减（长期未强化的记忆降权）、检索时的冲突消解（新者优先呈现+旧者标注"历史记录"）。
- 主动校准：记忆冲突率高时触发"与用户确认"（"您之前偏好 A，现在按 B 处理对吗？"）——把记忆治理变成一次交互而非静默决策；用户可批量查看/删除自己的记忆（合规+信任）。
- 一致性测试：记忆系统的回归集（跨会话的一致性问答：上周说的本周还记得且不矛盾）——记忆 bug（张冠李戴/穿越）是最伤信任的故障，要有专项测试。

```javascript
async function writeWithConflict(newMem) {
  const olds = await memory.searchRelated(newMem, 5);
  for (const o of olds) {
    if (contradicts(o, newMem))
      await markConflict(o, newMem, { strategy: 'keep-both' });
  }
  await memory.write(newMem, { ts: now(), source: 'dialog' });
}
// 检索：新者优先 + 旧者标"历史"；
// 冲突率高 → 触发用户确认。
```
