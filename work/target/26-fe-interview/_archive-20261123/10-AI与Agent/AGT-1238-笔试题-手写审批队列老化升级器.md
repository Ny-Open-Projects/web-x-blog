## 1238：笔试手写：实现审批队列的 SLA 老化与超时策略

**需求**：实现 ApprovalQueue({ midSlaMs=14400000, timeoutAction='reject' })：push(ticket) 记录入队时间；sweep(now)——超 SLA 的 mid 票按 timeoutAction 处理（'reject' -> 状态 rejected 并出队；'escalate' -> 升级标记不改状态）；返回处理清单 [{ ticket, action }]。

```js
class ApprovalQueue {
  constructor({ midSlaMs = 14400000, timeoutAction = 'reject' } = {}) {
    this.sla = midSlaMs; this.action = timeoutAction; this.tickets = new Map();
  }
  push(ticket) { this.tickets.set(ticket.id, { ...ticket, at: Date.now(), status: 'pending' }); }
  sweep(now = Date.now()) {
    const out = [];
    for (const [id, t] of this.tickets) {
      if (t.status !== 'pending') continue;
      if (now - t.at >= this.sla) {
        if (this.action === 'reject') {
          t.status = 'rejected'; this.tickets.delete(id);
        } else t.status = 'escalated';
        out.push({ ticket: id, action: this.action });
      }
    }
    return out;
  }
}
const q = new ApprovalQueue({ midSlaMs: 100, timeoutAction: 'reject' });
q.push({ id: 'a' });
console.log(q.sweep(Date.now() + 200));   // [{ ticket: 'a', action: 'reject' }]
console.log(q.sweep(Date.now() + 400));   // []（已出队幂等）
```

**评分点**：
- SLA 超时按预设动作处理（reject fail-closed 语义）
- 已处理票的幂等（重复 sweep 不重复动作）
- escalate 模式不改状态只标记（策略可配）
- 能讨论：超时默认拒绝的 fail-closed 理由、老化升级的组织机制
