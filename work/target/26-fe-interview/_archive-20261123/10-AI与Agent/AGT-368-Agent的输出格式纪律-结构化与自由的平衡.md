## AGT-368：Agent 输出的结构化程度怎么按场景设计？

**答**:
- 判据：下游是谁——程序消费（工具传参/数据入库/UI 渲染）必须严格 schema（AGT-269 约束解码）；人消费（对话/报告）用自由文本但骨架约束（章节结构/引用规则）；混合消费（报告+附数据）用"结构外壳+自由正文"。
- Agent 内部通信也按判据：Agent 间传递（任务书/结果）严格 schema（AGT-235），Agent 思考过程自由（CoT 不约束——约束思考反而降低质量）。
- 格式漂移治理：自由输出也会漂移（段落结构跑偏/引用丢失）——轻量校验（结构检查器：章节齐/引用存在）+ 失败重试或降级标注；格式纪律写进 prompt 分区（AGT-361 格式约定区）并配评测样例。
- 一致性收益：输出格式稳定带来的下游红利（前端渲染组件化 AGT-296/评测断言可程序化/用户预期稳定）——格式纪律是 Agent 产品的隐性工程质量。

```text
格式判据：看下游——
程序消费 → 严格 schema + 约束解码
人消费 → 自由文本 + 骨架约束
混合 → 结构外壳 + 自由正文
Agent 间 → schema；思考过程 → 自由
治理：结构检查器 + prompt 格式分区
  + 格式评测样例。
```
