## AGT-318：销售场景的 AI 助手（通话纪要/话术建议/CRM 更新）怎么设计？

**答**:
- 三件套：通话/沟通纪要（AGT-315 管线复用：转写+摘要+承诺事项抽取——"答应下周给方案"这类承诺自动入待办）、话术辅助（基于产品知识库+异议库的实时建议，销售自主采纳——辅助不代打）、CRM 自动更新（沟通内容→结构化字段建议：客户阶段/需求点/下一步，销售确认后写入——写操作确认制）。
- 合规红线：承诺类话术管控（折扣/到货时间等超权限承诺拦截——价格承诺只来自报价系统）、客户数据权限（销售只见自己客户，AGT-283）、录音告知合规。
- 实时性设计：通话中的实时建议延迟要求高（<2s）——小模型+预计算（常见异议的应答预生成），复杂分析会后离线——实时与离线两套延迟预算。
- 度量：纪要采用率、建议采纳率、CRM 字段准确率（销售修改率作为反向指标）、对成单的辅助效应（A/B）——避免"为 AI 而 AI"，看销售效率的真实提升。

```text
销售 Agent 三件套：
纪要：转写+摘要+承诺事项→待办
话术：知识库+异议库实时建议
  （实时 <2s 小模型，复杂离线）
CRM：结构化字段建议→销售确认后写入
合规：超权限承诺拦截 / 客户数据
  按 scope / 录音告知。
度量：采用率 / 字段修改率 / 成单 A/B。
```
