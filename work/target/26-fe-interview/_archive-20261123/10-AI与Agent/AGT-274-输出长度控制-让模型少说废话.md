## AGT-274：输出 token 的成本控制手段有哪些？

**答**:
- prompt 级：明确长度预算（"答案 ≤200 字/要点 ≤5 条"——模型对具体数字服从性好）、要求结构化输出（要点式比散文短且信息密度高）、禁止套话（"好的，我来为您…""希望对您有帮助"这类填充词显式禁止）。
- 参数级：max_tokens 硬上限（防失控长输出）+ 负截断处理（被截断时检测并补全/重试，而不是静默烂尾）。
- 任务级：分步生成分步返回（先给结论要点，用户展开再看细节——按需生成的成本远低于一次性全量）、流式提前可读（用户提前获得信息，感知延迟降，即使总 token 不变）。
- 后处理：输出压缩有风险（改写可能引入错误），优先在生成侧控制；确需压缩时走忠实性校验（AGT-212 红线：数字实体不改）。

```javascript
async function conciseLLM(q, { budget = 200 } = {}) {
  const out = await llm(`${q}\n要求：≤${budget} 字，
    要点式，无客套与重复。`, { max_tokens: budget * 3 });
  if (out.truncated) return await completeTail(out);  // 截断补全
  return out;
}
// 交互设计：先要点后展开（按需生成），
// 长文档"展开全文"再付 token 成本。
```
