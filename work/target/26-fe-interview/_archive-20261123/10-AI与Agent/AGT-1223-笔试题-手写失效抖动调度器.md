## 1223：笔试手写：实现批量失效的抖动下发与优先级

**需求**：实现 JitteredInvalidator(maxDelay=2000)：invalidate(keys, { priority })——high 立即执行、normal 随机 0~maxDelay 延迟、low 随机 maxDelay~2×maxDelay；去重（同 key 在窗口内只调度一次）；pendingCount() 与 flushNow()（清空延迟立即全部执行）。

```js
class JitteredInvalidator {
  constructor(invalidateFn, maxDelay = 2000) {
    this.fn = invalidateFn; this.max = maxDelay;
    this.scheduled = new Map();                // key -> timer（去重）
  }
  invalidate(keys, { priority = 'normal' } = {}) {
    for (const key of keys) {
      if (this.scheduled.has(key)) continue;   // 窗口去重
      const range = priority === 'high' ? [0, 0]
        : priority === 'low' ? [this.max, this.max * 2]
        : [0, this.max];
      const delay = range[0] + Math.random() * (range[1] - range[0]);
      const timer = setTimeout(() => {
        this.scheduled.delete(key);
        this.fn(key);
      }, delay);
      this.scheduled.set(key, timer);
    }
  }
  pendingCount() { return this.scheduled.size; }
  flushNow() {
    for (const [key, timer] of this.scheduled) {
      clearTimeout(timer); this.fn(key);
    }
    const n = this.scheduled.size;
    this.scheduled.clear();
    return n;
  }
}
```

**评分点**：
- 三档优先级的延迟区间（high 即时/normal 抖动/low 后置——优先级语义清晰）
- scheduled Map 去重（窗口内同 key 不重复调度——风暴防护核心）
- flushNow 清理定时器后立即执行（防双执行——漏 clearTimeout 是 bug）
- 能讨论：优先级的判定来源（可见 query 优先——IntersectionObserver 联动）、服务端广播抖动的配合
