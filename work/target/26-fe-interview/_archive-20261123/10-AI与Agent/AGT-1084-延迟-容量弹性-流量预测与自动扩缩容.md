## 1084：Agent 服务的容量弹性怎么做

**答**：
- 扩容维度不同：无状态网关按 CPU/QPS 扩；有状态瓶颈（rerank GPU、向量索引内存）按业务指标扩；模型 API 是外部配额——「扩容」常等于「提前申请配额」。
- 预测式扩容：按流量日曲线预测提前 15 分钟扩容（reactive 扩容追不上 Agent 任务的长时长特性——扩完任务已经超时了）。
- 优雅收缩：缩容前 drain 在途任务（Agent 任务长达分钟级，直接杀等于浪费已花的 token 钱）。
- 追问钩子：为什么 Agent 服务不能照搬普通 Web 的弹性策略？——任务长（分钟级）、成本高（中断即浪费）、有状态（黑板/会话），扩缩容必须「任务感知」而不是「连接感知」。

```ts
const autoscaler = {
  predict: forecastCurve('15m'),             // 预测式提前扩
  scaleUp: c => Math.max(c, forecast.peak * 1.2),
  scaleDown: c => drainFirst(c - 1, {        // 缩容先 drain 在途任务
    waitFor: 'tasks_done', maxWait: '5m' }),
  quotaPrebook: peak => vendor.reserveQuota(peak),  // 模型配额预约
};
```
