## AGT-310：团队 Wiki/文档/代码/工单统一的知识助手怎么建？

**答**:
- 多源索引：Wiki（Confluence/飞书文档）+ 代码库 + 工单（历史故障/决策）+ 消息沉淀（群公告类）统一进索引，按源类型定制解析（代码用符号索引、文档用 RAG 管线）——价值密度最高的是工单与故障复盘（真实问题与答案）。
- 新鲜度机制：文档 TTL 与过期标记（AGT-151 知识新鲜度）、代码答案带"基于哪个 commit"版本标注、过期知识自动降权——研发知识半衰期短，新鲜度是可信度核心。
- 反哺闭环：Agent 答不上来的问题（低置信拒答）生成"知识缺口清单"，定期推给团队补文档——知识库 Agent 同时是文档质量的探测器；高频问题自动生成 FAQ 草稿进审核队列。
- 治理：权限对齐各源系统（不同空间的文档按用户 ACL 过滤），答案强制引用源（跳到原文）——团队信任建立在"每次都能点回去验证"上。

```text
研发知识库 Agent：
源：Wiki + 代码 + 工单/复盘 + 群沉淀
  （工单复盘价值密度最高）
新鲜度：TTL/降权 + commit 版本标注
闭环：拒答 → 知识缺口清单 → 补文档；
  高频问题 → FAQ 草稿审核
治理：各源 ACL 对齐 + 答案强制引用。
```
