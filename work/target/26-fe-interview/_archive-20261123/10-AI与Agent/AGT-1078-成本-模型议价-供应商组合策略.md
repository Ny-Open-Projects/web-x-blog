## 1078：多模型供应商组合怎么降成本提可靠性

**答**：
- 组合逻辑：主备双供应商（互为灾备）+ 按任务分流量（不同供应商在不同任务类上的性价比不同，评估数据决定分配比）。
- 议价筹码：采购量集中度、可迁移性（抽象层让切换成本趋近于零，供应商才知道你有备胎）、批量接口用量承诺。
- 抽象层是议价之本：统一模型调用接口（供应商差异在适配器里），切换只改配置；没有抽象层的系统被单一供应商锁死。
- 追问钩子：多供应商的隐性成本？——评测成本翻倍（每个供应商单独校准）、行为差异处理（同一 prompt 输出风格不同）、质量基线要对齐（不能拿 A 家的 rubric 直接用 B 家）。

```ts
const registry = {
  primary: { vendor: 'A', tasks: ['qa', 'coding'], weight: 0.7 },
  backup: { vendor: 'B', tasks: ['qa'], weight: 0.3 },
};
async function llmCall(task, prompt) {
  const v = registry[task.vendor ?? pickVendor(task)];
  try { return await vendors[v.vendor].chat(prompt); }
  catch (e) { return failover(v, task, prompt); }       // 灾备切换
}
```
