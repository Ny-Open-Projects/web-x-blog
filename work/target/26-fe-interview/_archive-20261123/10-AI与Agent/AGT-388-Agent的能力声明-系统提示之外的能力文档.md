## AGT-388：面向用户/开发者的 Agent 能力声明（说明书）怎么写？

**答**:
- 用户侧说明书：能力清单（能做什么——按任务类型列举带示例）、边界清单（不能做什么/高风险话题——比能力清单更重要，AGT-378）、正确用法（怎么问效果好——示例化）、数据说明（数据怎么被使用/怎么删除——合规透明）。
- 开发者侧文档（如果开放集成）：能力契约（API/工具的 schema 与语义）、限制（限流/配额/超时）、行为规范（幂等性/错误码语义/重试建议）、变更政策（版本兼容承诺/弃用流程）——AGT-345 三层出口的文档化。
- 一致性纪律：说明书承诺与实际行为一致（文档说支持的能力必须真支持，评测覆盖文档声明——"文档即评测范围"）——说明书超卖是信任透支；能力升级时说明书同步更新（版本对应）。
- 呈现策略：用户说明书嵌入产品（AGT-378 能力地图），开发者文档进开发者门户，共同的上游是同一份"能力事实源"（从配置生成文档——避免文档与实现漂移）。

```text
能力说明书双面：
用户：能力清单 + 边界清单（更重要）
  + 正确用法示例 + 数据说明
开发者：schema 契约 / 限流配额 /
  幂等与错误码 / 版本政策
纪律：文档=评测范围（超卖=透支）；
  文档从配置生成（防漂移）；
  能力升级同步更新。
```
