## 1167：检索算力（召回数、精排深度）怎么分配最划算

**答**：
- 原则：把算力花在「排序质量的边际收益」上——召回从 1000 到 2000 边际收益趋零，但精排从 30 到 60 还有收益，所以「召回宽（1000+）、精排精（30~50 条 cross-encoder）」是经典分配。
- 验证方法：画「候选数-质量曲线」（召回数固定扫精排深度、反之亦然），找各段拐点；拐点随语料与查询类型漂移，季度复测。
- 延迟预算联动：精排深度 × 单条耗时 ≤ 精排预算（如 400ms），超预算先优化精排模型（蒸馏/批量）而不是砍深度（砍深度直接掉质量）。
- 追问钩子：为什么召回宁可宽也不能窄？——窄召回是不可逆错误（好文档没进候选，精排再强也无济于事），宽召回的浪费只是精排算力，可逆性决定分配策略。

```ts
async function allocate(q) {
  const recalls = await knn(q, 1000);            // 宽召回（便宜）
  const mid = await cheapRank(q, recalls, 50);   // 粗排收敛
  const budget = Math.floor(RERANK_MS / PER_PAIR_MS);
  return rerank(q, mid.slice(0, Math.min(50, budget)));  // 精排按预算定深度
}
```
