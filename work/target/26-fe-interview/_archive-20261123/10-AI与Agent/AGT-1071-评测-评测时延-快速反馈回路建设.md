## 1071：从改 prompt 到看到分数要多久，怎么压到 10 分钟内

**答**：
- 时延构成：改动生效 + 任务调度 + 并发执行 + 结果聚合；并发是最大杠杆——评估任务天然独立，全并发跑（受供应商 QPS 上限，用批接口）。
- 分级集设计：10 分钟档 = 50 条探针（改 prompt 时自测）、1 小时档 = 200 条核心（MR 门禁）、夜间档 = 全量；反馈越快迭代越密。
- 增量评估：只跑「改动影响面」相关的条目（按标签索引：改了检索就跑检索敏感题），核心集再砍 60%。
- 追问钩子：并发跑会不会因限流导致「分数失真」？——会（限流触发的降级路径与平时不同），并发上限设为「不触发降级的最大值」，且降级触发次数进报告。

```ts
const lanes = {
  fast: { set: 50, timeout: '10m', concurrency: 16, trigger: 'manual' },
  gate: { set: 200, timeout: '1h', concurrency: 32, trigger: 'MR' },
  nightly: { set: 'all', trigger: 'cron' },
};
async function runLane(l) {
  const relevant = l === 'gate' ? impactedItems(changedTags) : sets[l];
  return Promise.all(relevant.map(c => limiter.schedule(() => runCase(c))));
}
```
