## AGT-327：模型/工具供应商的治理（选型、监控、退出）怎么做？

**答**:
- 准入评审：能力评测（自家评测集）、安全合规（数据处理协议/ZDR/合规认证）、稳定性（SLA/限流政策）、价格与商务（量价/退出条款）——准入是四维评审不是只看 demo；供应商变更（模型版本升级）须重新评测（模型静默升级是质量突变源，锁定版本号）。
- 运行监控：供应商健康看板（错误率/延迟/限流事件）自动记录，配额水位与账单异常告警——供应商侧问题要能被第一时间发现并归因（不是自家 bug）。
- 退出预案：回退通道（上一版本模型保留/备用供应商热备，AGT-279）、数据可迁移性（自建索引/记忆的导出能力——避免锁死）、合同终止与数据删除条款。
- 多供应商治理：按任务最优分配（AGT-279）、统一的抽象层版本管理（各家 schema 差异在适配层消化）、年度供应商复评（市场在快速演进，去年的选择未必仍是最优）。

```text
供应商治理四环节：
准入：自家评测 + 安全合规 + SLA + 商务
  （锁定版本号，静默升级须重评）
监控：健康看板 + 配额水位 + 账单告警
退出：热备回退 + 数据可导出 + 合同条款
复评：年度重评 + 抽象层消化 schema 差异。
```
