## 992：多轮会话历史越滚越长，压缩策略怎么设计

**答**：
- 分段处理：近期 N 轮保原文（保证细节准确）、更早的滚动摘要（保留结论/决定/未决事项）、系统级事实（用户偏好等）单独结构化存储不进摘要。
- 摘要时机：不是每轮都摘——token 超过阈值才触发一次「摘要合并」，摘要本身也要控制长度（原文的 20% 以内）。
- 摘要丢失风险：数字、ID、明确承诺类信息摘要易丢——摘要 prompt 强制「保留所有数字与 ID」，并用结构化抽取兜底单独存。
- 追问钩子：摘要后用户引用早期细节怎么办？——摘要条目带「原文指针」（轮次号），需要时按需回捞原始轮次重新注入。

```ts
async function compact(history, threshold) {
  if (est(history) < threshold) return history;
  const recent = history.slice(-6);                       // 近期保原文
  const old = history.slice(0, -6);
  const summary = await llm(`摘要以下对话，保留所有数字/ID/承诺，控制在20%以内：\n${render(old)}`);
  const keyFacts = extractStructured(old);                // 数字/ID 结构化兜底
  return [{ role: 'system', content: `历史摘要：${summary}\n关键事实：${keyFacts}` },
    ...recent];
}
```
