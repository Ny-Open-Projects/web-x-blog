## AGT-651：一个成熟的评测集应该分哪几层（冒烟/回归/深水），各自跑什么频率

**答**：
- 冒烟层（~50 条）：每次提交跑，<5 分钟出结果，拦住"完全跑不通"级别的回归；回归层（~500 条）：PR/每日跑，覆盖主路径与已知 bug 复发；深水层（数千条）：每周/发版前跑，覆盖边界与长尾，代价高但管住尾部风险。
- 分层的意义是「信号时间与成本的平衡」：全量跑一次几小时，没人愿意在改一行提示词后等它——分层让常见迭代有分钟级反馈。
- 层间要有晋升通道：线上新发现的 bug 用例先进冒烟，稳定后下沉回归，极端边界进深水。

```javascript
const TIERS = {
  smoke:   { n: 50,  trigger: 'every-commit', budgetMin: 5 },
  regress: { n: 500, trigger: 'pr-and-daily' },
  deep:    { n: 3000, trigger: 'weekly-and-release' },
};
function promote(caseItem, from, to) {          // 层间晋升通道
  if (!TIERS[to]) throw new Error('BAD_TIER');
  move(caseItem, from, to, { note: caseItem.promoteReason });
}
```
