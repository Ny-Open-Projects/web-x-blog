## AGT-221：长上下文模型的窗口预算怎么分配——不是塞满就最好？

**答**:
- 预算分段：系统提示与工具定义（固定开销，尽量压缩到 2k 内）、对话历史（滑动保留最近 N 轮+更早的摘要）、检索上下文（按相关性分配最大块）、输出预留（模型输出预算要显式留出）——每段设上限，总和 ≤ 窗口的 80%（留安全边际）。
- "lost in the middle"问题：长上下文中部信息召回率显著低于首尾——关键指令放系统提示（开头）、关键证据放检索上下文的开头或结尾，不要埋在中间。
- 塞满的代价：注意力稀释（重要信息被淹没）、成本线性上涨、延迟上升——窗口大≠要用满，按信息密度取舍，宁可多一轮检索也不堆垃圾上下文。
- 动态调度：多轮会话用"预算管理器"统一决策（谁进谁出），进出的优先级 = 最近性 × 重要性 × 任务相关性——把上下文当内存管理，有 LRU 也有 pin。

```javascript
function budgetContext(win = 128000) {
  const budget = { total: win * 0.8,
    system: 4000, history: 20000,
    retrieval: 60000, output: 8000,
    toolResults: 30000 };            // 分段上限
  return {
    fit(items, seg) {                 // 按段装配
      let used = 0;
      return items.filter(it => {
        const t = tokens(it);
        if (used + t <= budget[seg]) { used += t; return true; }
        return false;
      });
    }
  };
}
// 关键证据排首尾，指令固定在 system。
```
