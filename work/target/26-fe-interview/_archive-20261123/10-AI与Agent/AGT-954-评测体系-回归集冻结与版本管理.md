## 954：评测集为什么要冻结？怎么管理版本

**答**：
- 冻结的意义：评估分数只有在「题不变」时才可比；回归集一旦在迭代中被顺手修改，指标就失去了时间轴上的可比性，你会「越测越好」但产品没变好。
- 版本管理：评测集本身进 Git，改动走 PR 审查（谁加的题、为什么、预期难度），每个版本打 tag，评测报告注明「基于 vN」。
- 演进纪律：旧版本永不删（保可比性），新增题目走「增量集」先单独看分数，稳定一个季度后并入回归集并升版本号。
- 追问钩子：题目被产品变化「过期」了怎么办（接口改版导致旧题答案失效）？——标注 deprecated 但保留，替换题进增量集，报告里新旧版本分数分列。

```ts
// evals/ 根目录结构
// regressions.v3.json  <- 冻结，只读
// incoming.v3.json     <- 增量候选
// CHANGELOG.md         <- 每次增删的理由
const report = await runEval([
  { set: 'regressions.v3', required: true },   // 必须不回退
  { set: 'incoming.v3', reportOnly: true },    // 只报告，不卡门禁
]);
```
