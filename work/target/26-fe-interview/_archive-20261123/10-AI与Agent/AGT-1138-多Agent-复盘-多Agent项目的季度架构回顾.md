## 1138：多 Agent 系统的季度架构回顾该看什么

**答**：
- 回顾五问：拓扑健康度（Agent 数量是否失控、孤立 Agent 有没有用）、成本结构变化（最贵环节漂移了吗）、失败模式 top3（结构性问题还是个案）、能力重叠（两个 Agent 干同一件事）、技术债（配置里的逻辑气味、协议版本散乱）。
- 数据先行：回顾会前出数据包（拓扑图 + 成本瀑布 + 失败分类 + 各 Agent 表现趋势），讨论基于数据不基于印象。
- 产出约束：回顾结论必须落到「3 个以内」的架构动作（合并 Agent/下线能力/重构协议），超过 3 个说明没抓重点，季度内也做不完。
- 追问钩子：回顾谁主导？——平台团队主导但必须有业务方参与（成本与质量优先级由业务定），纯技术回顾会漏掉「业务已经不需要这个 Agent」这类最大浪费。

```md
## 季度架构回顾 2026-Q4
数据包：拓扑 7 Agent（2 个零调用）| 成本 top: coder-1 42% | 失败 top: 格式漂移 31%
动作（≤3）：
1. 下线 reviewer-2（与 reviewer-1 能力重叠，季度零增量收益）
2. coder-1 上下文裁剪（成本 -20% 目标）
3. 输出协议统一 v2（格式漂移根因）
```
