## 1174：评测算力有限，端到端和环节评测怎么分配

**答**：
- 分配原则：端到端评测是「体检」（必须常跑但条数可控），环节评测是「诊断」（失败时按需跑）；预算 7:3——日常端到端为主，回归失败时触发环节评测定位。
- 环节评测的触发联动：端到端失败 → 自动归因到环节（检索/生成/后处理）→ 只跑该环节的专项评测集（小而精）→ 定位到参数/组件级。
- 环节评测集的维护成本高（要固定其他环节的 mock），只给「历史上失败最多的环节」建专项集，不为所有环节建。
- 追问钩子：环节评测和端到端结果矛盾（环节全绿但端到端红了）说明什么？——环节接口处的「组合问题」：各环节单独正确但拼起来错（上下文格式不兼容、信息在传递中丢失），专项加「接口契约测试」。

```ts
const evalRouter = {
  daily: () => e2e(coreSet),                        // 体检：7 成预算
  onFail: async r => {                              // 诊断：3 成预算
    const stage = await attribute(r);
    return stageChecks[stage]?.(smallSet(stage)) ?? fullDiagnose(r);
  },
  onMismatch: () => contractTests(stageInterfaces), // 组合问题->契约测试
};
```
