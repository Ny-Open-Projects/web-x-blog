## AGT-220：生产级 RAG 管线由哪些环节组成——全景怎么收束？

**答**:
- 离线层：解析（多格式/表格/图）→ 分块（语义/父子块）→ 嵌入（选型+增量更新）→ 索引（向量+BM25+元数据/ACL）——数据质量决定上限，垃圾索引救不回来。
- 在线层：查询理解（改写/自查询/路由）→ 召回（混合检索）→ 重排（rerank）→ 质量门（CRAG 评估）→ 压缩（截断/抽取/摘要）→ 生成（引用+安全审核）——每一环都可插拔可评测。
- 治理层：评测集与回归基线（AGT-216）、权限与审计（AGT-217）、新鲜度 SLA（AGT-215）、成本归因与缓存——RAG 是系统工程，管线各环节的短板决定整体水位。
- 收束心法：RAG 优化顺序永远是"数据 > 检索 > 生成"——先修分块与索引质量，再调检索策略，最后才轮到 prompt 工程；顺序反了会一直在下游打补丁。

```text
生产 RAG 全景：
离线：解析 → 分块 → 嵌入 → 索引
  （语义分块/父子块/增量/ACL）
在线：改写 → 混合召回 → rerank
  → 质量门(CRAG) → 压缩 → 生成
  （引用溯源/安全审核/拒答兜底）
治理：评测基线 / 权限审计 / 新鲜度
  SLA / 缓存与成本归因
优化顺序：数据 > 检索 > 生成，
  每次变更必须过回归评测集。
```
