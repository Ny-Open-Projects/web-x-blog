## 974：评测体系怎么嵌进双周迭代节奏

**答**：
- 固定节奏：周一规划（从看板取 top 失败类别定本周目标）→ 周中迭代（每改动过核心集）→ 周四评审（全量报告 + 门禁）→ 周五上线灰度 + badcase 回流入库。
- 目标要挂指标：本周目标写成「compare 类误拒率从 8% 降到 5%」而不是「优化检索」——可度量才能验收。
- 迭代纪律：每周最多一条结构性改动（换模型/换分块策略），多改动并发会让归因失效；小调优（prompt 微调）可并行但分开评估。
- 追问钩子：紧急线上事故打断节奏怎么办？——事故修复走单独分支过核心集，不占本周结构性改动名额，复盘产出进回归集。

```ts
// 周迭代看板的数据结构
const board = {
  week: '2026-W47',
  goal: { metric: 'compare.falseReject', from: 0.08, to: 0.05 },
  changes: [ { type: 'structural', desc: 'rerank 阈值调整', eval: 'core+full' },
             { type: 'tweak', desc: '拒答 prompt 微调', eval: 'core' } ],
  review: { day: 'Thu', gate: true },
  retro:  { day: 'Fri', feed: 'badcase -> incoming set' },
};
```
