## AGT-830：平台跑了一年（多租户 20 家），技术债最可能出现在哪、演进优先级怎么排

**答**：
- 高发债区：模型适配层（供应商协议碎片化，适配器烂写）、租户特例逻辑（"就这一个客户要的"散落 if-else）、工具适配器质量参差、记忆/检索的老版本共存。
- 演进优先级判定：看「变更频率×影响面」——模型适配层变更最频繁（供应商月月改）优先重构；租户特例优先抽象成策略配置（而不是代码分支）。
- 演进纪律：每次重构带迁移期与回归评测（平台自身也要评测护航），冻结期制度（大促/续约季冻结大重构）。

```javascript
function debtPrioritize(debts) {
  return debts.map(d => ({ ...d,
    score: d.changeFreq * d.blastRadius })).sort((a, b) => b.score - a.score);
}
// 高频高影响优先：模型适配层抽象成能力声明表驱动
function refactorModelLayer() {
  return capabilityDriven(MODEL_CATALOG, { adapters: 'thin' });
}
```
