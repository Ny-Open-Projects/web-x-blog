## AGT-328：企业级 Agent 平台的分层架构怎么收束？

**答**:
- 五层平台架构：接入层（前端集成/开放 API/MCP 网关）、编排层（Agent 运行时/DAG/多 Agent 协作/人审流）、能力层（模型路由/RAG 管线/工具市场/记忆服务）、治理层（评测平台/prompt 资产/特征开关/成本与配额/安全审计）、运营层（监控/SRE/供应商管理/反馈闭环）——业务 Agent 全部长在平台层上，业务只写"场景配置"。
- 平台化的判断标准：≥3 个业务场景复用同一能力时下沉到平台——过早平台化（只有一个场景就建平台）是过度设计，过晚（N 个场景各自造轮子）是重复浪费。
- 平台与业务的接口：业务侧交付物是"场景包"（知识库+工具配置+prompt+评测集+SOP），平台侧提供全部运行时——场景包的可复用与可审计是平台价值的核心度量。
- 收束心法：平台的目标是把"做 Agent"的门槛降到"配 Agent"——但治理能力（评测/安全/成本）必须平台内置而非业务自配，否则每个业务都会重踩一遍坑。

```text
Agent 平台五层：
接入：前端 / 开放 API / MCP 网关
编排：运行时 / DAG / 多Agent / 人审流
能力：模型路由 / RAG / 工具市场 / 记忆
治理：评测 / prompt 资产 / 开关 /
  成本配额 / 安全审计
运营：监控 SRE / 供应商 / 反馈闭环
业务 = 场景包（知识+工具+prompt+评测
  +SOP）；≥3 场景复用才下沉平台；
  治理能力平台内置。
```
