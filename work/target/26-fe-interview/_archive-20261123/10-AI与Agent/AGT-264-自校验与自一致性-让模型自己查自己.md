## AGT-264：让模型自我校验（self-check）在什么场景有效，什么场景是假把式？

**答**:
- 有效场景：约束校验（输出是否符合格式/是否涵盖要求的要点——模型检查"要求是否被满足"的能力强）、一致性问题（前后文自相矛盾、数字对不上——重读上下文可发现）、推理复核（要求模型重新独立推导并对比，CoT 场景可发现部分逻辑错误）。
- 失效场景：事实性校验（模型检查自己编造的事实，大概率认可自己的幻觉——同一知识源无法自查知识错误）；自证式检查（"你的答案对吗？"→"对的"）是无效动作。
- 工程做法：把校验拆成具体可执行的问题（"输出中的 3 个数字是否都出现在提供的资料中？逐一列出"）而不是笼统"检查正确性"——具体问题+逐项核对才有校验力。
- 替代方案：事实类校验交给外部工具（检索比对/代码执行/规则引擎）——模型自校验负责"结构与一致"，外部工具负责"事实"，分工明确。

```javascript
async function selfCheck(output, context) {
  // 有效：一致性 + 约束校验（逐项、具体）
  const checks = await llm(`逐项核对：
    1. 输出中每个数字是否都在资料中出现过？
    2. 是否存在前后矛盾？3. 是否遗漏要求的要点？
    资料:${context}`, output);
  // 失效做法（不要用）：
  // await llm("你的答案正确吗？", output);
  return checks;
}
// 事实校验 → 外部工具：检索比对/代码执行
```
