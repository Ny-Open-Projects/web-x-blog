## AGT-319：订单履约异常（缺货/延迟/地址错误）的多 Agent 处理怎么编排？

**答**:
- 角色分工：异常识别 Agent（监控事件→判定异常类型）、方案 Agent（按 SOP 生成处理方案：换货/退款/补偿，成本核算）、沟通 Agent（生成用户通知话术）、审批节点（金额超阈值人审）——DAG 编排（AGT-236），每角色权限最小化（AGT-283）。
- SOP 与模型的分工：标准异常走规则引擎（确定性+快），非标异常（复合原因/客户特殊要求）才走 LLM 方案生成——LLM 只接手规则覆盖不了的尾部，成本与风险双降。
- 一致性约束：补偿金额/退款动作受业务规则引擎校验（Agent 建议不越过规则边界——如退款上限），Agent 输出在规则内才执行；用户沟通话术过合规扫描（不乱承诺赔偿）。
- 回放与审计：每个异常案件全链路留痕（识别→方案→审批→执行→通知），可回放复盘；批量异常（大促缺货）的批量决策走灰度抽样人审（AGT-286 批量确认）。

```text
履约异常编排：
识别 → 方案（标准异常=规则引擎；
  非标=LLM 生成+规则校验边界）
→ 审批（超阈值人审）→ 执行 → 沟通
（话术过合规扫描）
每案全链留痕可回放；
批量案件灰度抽样人审。
```
