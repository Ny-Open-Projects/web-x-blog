## AGT-373：Agent 应用的压测与传统应用有什么不同？

**答**:
- 压测对象分层：模型层（供应商限流/并发容量——mock 或真实流量小比例）、Agent 层（编排服务/工具并发——工具下游通常是最先崩的）、前端层（流式连接数/渲染性能——AGT-292 合帧在高并发下的表现）——分层压测定位瓶颈层。
- Agent 特有的压测点：工具下游压测（数据库/内部 API 被并发 Agent 调用打爆——比模型层先崩）、流式连接保持（大量 SSE 长连接的网关承载）、上下文内存（会话状态服务的内存水位）、死循环与重试风暴在高负载下的放大效应（限流引发重试引发更多限流——雪崩）。
- 压测策略：真实流量回放（录制的会话轨迹重放——比脚本压测真实）、影子压测（生产流量镜像加倍）、逐级加压找拐点；熔断验证（AGT-277 预算熔断在压测下是否生效）。
- 产出：容量水位表（各层极限与安全水位）、自动扩缩容策略验证、限流与降级预案的实际有效性报告。

```text
Agent 压测分层：
模型层（供应商限流）→ Agent 层
  （编排/工具并发——最先崩）→ 前端层
  （SSE 连接/渲染）
特有点：工具下游 / 长连接网关 /
  会话内存 / 重试风暴放大
策略：真实轨迹回放 + 逐级加压 +
  熔断预案有效性验证。
产出：容量水位表 + 扩缩容验证。
```
