## AGT-309：风控/信贷类场景里，LLM Agent 与规则引擎怎么分工？

**答**:
- 分工原则：可解释与合规要求高的决策（额度/利率/拒贷）由规则引擎与评分模型做（可审计可监管），LLM 负责非决策层——材料信息抽取（从报表/合同提取结构化数据）、辅助材料分析（异常点提示）、报告撰写、反欺诈线索聚合（多源信息摘要给人审）。
- 可解释性要求：金融决策必须能还原依据（监管要求）——LLM 不直接产出决策因子；如果 LLM 输出参与决策（如非结构化材料的风险标签），该输出要进入决策留痕并可复核。
- 一致性与回归：规则引擎改动走灰度；LLM 环节的输出稳定性要评测（同材料同输出，AGT-255 回归集）——风控场景对"同输入不同输出"零容忍。
- 红线：不给用户"AI 决定额度"的感知；拒贷解释由规则引擎生成（可审计的理由），不用 LLM 即兴解释。

```text
金融风控分工：
决策层（额度/拒贷/利率）：
  规则引擎 + 评分模型（可审计）
LLM 层：材料信息抽取 / 异常点提示 /
  线索聚合给人审 / 报告撰写
约束：LLM 输出参与决策须入留痕可复核；
  拒贷解释由规则生成（非 LLM 即兴）；
  同材料同输出（回归零容忍）。
```
