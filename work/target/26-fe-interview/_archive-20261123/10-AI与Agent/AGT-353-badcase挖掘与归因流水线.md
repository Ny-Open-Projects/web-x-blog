## AGT-353：线上 badcase 怎么系统化挖掘与归因？

**答**:
- 挖掘通道：用户负反馈（点踩/重试/改写——直接信号）、质量抽检异常（judge 打分低的样本 AGT-268）、指标异动定位（某类场景完成率跌——按场景切片找差样本）、主动巡检（高风险场景定期人工巡检）。
- 归因流水线：收集 → 自动分类（失败模式标签：检索缺失/工具错误/逻辑错误/幻觉/格式——用 LLM 分类+人工抽检校准）→ 聚类（同类问题聚合，AGT-157 方法）→ 归因报告（Top 失败模式+根因假设+修复建议+影响面）→ 修复排期。
- 修复与验证：按失败模式选修复手段（检索缺失→补数据；工具错误→修 schema；幻觉→护栏），修复后用该 badcase 簇验证效果并入回归集——badcase 的终点是"变成回归资产"。
- 运营节奏：周级 badcase 例会（Top 问题过目+排期）——挖掘归因是持续运营而非一次性项目。

```text
badcase 流水线：
挖掘：负反馈 / 抽检异常 / 切片异动 /
  主动巡检
归因：LLM 自动分类（校准）+ 聚类
  → Top 失败模式 + 根因 + 影响面
修复：按模式选手段 → 簇级验证
  → 入回归集
节奏：周例会 + 排期，持续运营。
```
