## 1112：给业务团队定一份「Agent 开发安全规范」，该有哪些条款

**答**：
- 规范五部分：数据红线（什么数据不能进 prompt/日志）、权限基线（工具白名单审批流程、高危工具必须走审批门）、内容边界（外部内容必须过消毒、输出必须过 DLP）、发布要求（安全评审清单 + 红队回归）、运营义务（防线告警响应、事故上报时限）。
- 写法要点：每条规范配「反例 + 正确做法」，只写原则不写做法的规范没人执行；条款编号化便于评审引用（「违反 3.2」比「违反内容边界」高效）。
- 落地机制：规范条款尽量「工具化」——能做成 lint/CI 检查的做成检查（数据红线扫描器、权限变更触发评审），靠自觉的条款必然衰减。
- 追问钩子：规范怎么保持不腐？——季度修订（吸收新攻击手法与新防线）+ 每次事故后回查「哪条规范本该拦住」；拦不住的条款要么加强要么承认失效并移除。

```md
## Agent 开发安全规范 v3
3.2 外部内容进上下文前必须过消毒器（sanitizeExternal）。
   反例：爬虫结果直接拼 prompt -> 注入。
   正确：sanitizeExternal() + trust 标记。
5.1 高危工具调用必须经审批门（approval.require）。
   CI 检查：permissions.yml 新增高危工具而无 approval 配置 => 阻止合并。
```
