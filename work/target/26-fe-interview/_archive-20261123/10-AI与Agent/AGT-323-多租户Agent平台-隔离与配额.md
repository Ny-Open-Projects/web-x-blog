## AGT-323：SaaS 化的 Agent 平台，多租户隔离与配额怎么设计？

**答**:
- 隔离三层：数据隔离（向量库/记忆/会话按租户物理或逻辑隔离——逻辑隔离时租户 ID 是所有索引与缓存的强制过滤字段，AGT-217）、配置隔离（每租户独立的 prompt 资产/模型白名单/工具授权）、故障隔离（租户级限流与熔断——一个租户的死循环任务不拖垮平台）。
- 配额体系：三层配额（租户月配额/用户日配额/单任务成本上限）+ 超额策略（软限：降级模型；硬限：暂停并通知升级）——配额同时是商业模式（计费）与安全机制（AGT-300）。
- 计费与归因：按租户精确归因成本（token/工具调用分租户记账），支持按量与包月混合计费——成本归因体系（AGT-276）的租户维度版。
- 噪声租户治理：异常租户（成本突变/滥用特征）自动限流+通知；租户级行为审计供合规审查——平台要能"单个租户出局不影响他人"。

```text
多租户三层隔离：
数据：索引/缓存/记忆强制 tenant_id 过滤
配置：prompt 资产 / 模型白名单 / 工具授权
故障：租户级限流熔断
配额：月租额 / 日用户额 / 任务上限；
  超额先降级后暂停；
  计费归因按租户记账（按量+包月）。
```
