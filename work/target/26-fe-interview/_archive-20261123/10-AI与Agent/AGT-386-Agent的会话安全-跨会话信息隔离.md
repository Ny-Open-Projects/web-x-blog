## AGT-386：多用户 Agent 服务中，跨会话/跨用户的信息隔离怎么保证？

**答**:
- 隔离面清单：上下文隔离（会话上下文绝不跨用户——缓存 key 含用户与权限 AGT-275）、记忆隔离（用户记忆按用户 ID 硬隔离，检索强制 filter AGT-223/323）、共享资源污染（共享知识库的写入校验 AGT-367——一个用户的注入不能变成全局知识）、并发串扰（并发会话的状态串号——会话 ID 贯穿全链路）。
- 典型事故模式：缓存越权（A 的权限下缓存的答案被 B 命中——含 A 可见数据=泄露）、会话粘性错误（负载均衡把会话路由错实例但状态外置修复）、共享事实库无租户过滤。
- 防御验证：隔离性测试集（A 用户写入→B 用户查询的交叉测试进回归 AGT-257）、缓存权限单测、并发压力下的串号检测——隔离 bug 是最严重级别（数据泄露），测试优先级最高。
- 架构原则：默认拒绝——任何共享资源（缓存/事实库/记忆）的访问必须显式携带并校验租户/用户标识，"全局缓存"这类设计在多用户 Agent 服务中默认禁止。

```javascript
function cacheKey(req) {
  return hash(req.user.id, req.user.acl,   // 全因子
    req.tenantId, req.promptVer, req.body);
}
// 共享事实库写入：verify + tenant 过滤；
// 回归：A 写 B 查交叉测试 + 并发串号检测。
// 原则：默认拒绝，共享必须显式校验。
```
