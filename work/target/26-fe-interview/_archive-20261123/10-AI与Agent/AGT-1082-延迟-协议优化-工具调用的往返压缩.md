## 1082：多工具任务的「往返次数」怎么压缩

**答**：
- 往返成本：每轮「模型思考 → 工具执行 → 结果回传」是一个 RTT，5 个独立工具串行就是 5 个 RTT；压缩手段：并行工具调用（模型一次输出多个调用）、批量接口（模型先规划再一次性执行）、服务端循环（把「调用-执行-反馈」循环下沉到服务端代理，客户端只收最终结果）。
- 前提是「依赖分析」正确：工具间有数据依赖的不能并行，让模型在调用时显式声明依赖（结构化并行调用协议）。
- 收益量化：独立工具全并行后，工具阶段时长 = max(单工具耗时)，串行 5 RTT 压成 1 RTT，端到端延迟降 60%+ 是常见水平。
- 追问钩子：并行调用会不会让模型「乱序消费结果」？——结果按调用 ID 对应回传，prompt 组装时保持「调用序 = 结果序」，模型侧不感知乱序。

```ts
// 模型一次输出并行调用计划
const plan = await llm(plannerPrompt, { tools, parallel: true });
// calls: [{ id: 1, tool: 'search', args }, { id: 2, tool: 'profile', deps: [1] }]
const noDep = plan.calls.filter(c => !c.deps?.length);
const rs = await Promise.all(noDep.map(execTool));      // 独立的全并行
return feedBack(plan.calls, rs);                        // 依赖项下一轮
```
