## 973：评测报告怎么写才能真正推动决策

**答**：
- 报告三段式：结论先行（这个版本能不能上、差在哪，一句话）、证据（关键指标对比表 + 3 个代表性 badcase 全文 trace）、建议（明确到改哪个环节、预期收益）。
- badcase 挑「可归因」的：贴完整 trace 让读者自己能看懂失败链，比贴十个「模型答错了」有说服力。
- 报告面向决策者分层：TL;DR 给老板（成本/质量/风险三行），技术细节附录给工程师；不要把原始 JSON 直接甩出去。
- 追问钩子：报告怎么防「报喜不报忧」？——固定模板必填「本周退化项」与「未解决项」，模板强制让坏消息有位置。

```md
## 评测报告 v2.3 (2026-11-17)
**结论**：质量达标（acc 0.88，+0.03），成本超标 15%，暂缓全量，建议先优化执行链上下文。
**证据**：qa 0.90(+0.02) / coding 0.85(+0.05) / cost 6.2k tokens(+15%)；badcase #AC-217（检索空仍硬答）…
**建议**：执行链上下文裁剪（预期 -20% tokens）；补检索空兜底测试 5 条。
**退化项**：compare 类 acc -0.01（回归集 12 条全绿但留出集退化）
**未解决**：多轮会话记忆漂移（已建跟踪 issue #88）
```
