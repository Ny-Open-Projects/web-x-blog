## AGT-240：多 Agent 编排的工程体系怎么收束？

**答**:
- 全景五层：拓扑层（五种模式选型，AGT-231）→ 通信层（类型化消息契约+trace，AGT-235）→ 控制层（DAG 编排/任务分解/人工介入点，AGT-232/236/237）→ 容错层（超时降级/失败传播/断点续跑，AGT-238/229）→ 质量层（结果聚合/冲突仲裁/批判迭代，AGT-239/233）——每层独立可替换，组合成具体系统。
- 中心原则一（契约先行）：Agent 间一切交互走显式契约（任务书/消息 schema/验收标准），"靠 prompt 默契"的多 Agent 系统一定会在规模上崩——契约是分布式的基石。
- 中心原则二（可见性）：每个 Agent 的每一步有 trace、每个决策有依据、每笔成本有归因——多 Agent 的复杂度必须用可观测性对冲，否则调试是黑箱玄学。
- 中心原则三（简单优先）：单 Agent 能解决的不上多 Agent；多 Agent 时拓扑从简；批判/辩论只在高风险输出启用——多 Agent 的默认敌人是自己的复杂度。

```text
多 Agent 编排全景：
拓扑：流水线/中心路由/辩论/黑板/DAG
通信：类型化消息 + schema 校验 + trace
控制：任务分解(DAG) + 任务书契约
  + 人工介入分级
容错：分级处置 + 全链路死线 + 断点续跑
质量：结构化聚合 + 冲突阶梯 + 批判收敛
三原则：契约先行 / 全链可见 / 简单优先。
```
