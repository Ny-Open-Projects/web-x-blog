## PER-914：如何做跨团队的性能规范推动？落地难点在哪

**答**：
- 推动模型：规范文档 + 工具强制（lint/门禁）+ 看板晾晒（团队性能红黑榜）三件套，只发文档没有强制基本无效。
- 切入点选"低成本高收益"：图片规范、路由级代码分割、组件按需加载，先赢几场建立信任。
- 难点一：存量包袱——用"新增拦增量、存量走专项"策略；难点二：跨团队责任模糊——按页面归属定 Owner；难点三：需求压性能——用数据挂钩业务损失争取排期。
- 沉淀机制：每季度性能专项 + 最佳实践模板（脚手架内置），让新项目天生合规。

```javascript
// 脚手架内置规范：新项目默认配置
// vite.config.ts 生成的默认门禁
export default {
  build: { target: 'es2018',
    rollupOptions: { output: { manualChunks(id) {
      if (id.includes('node_modules')) {
        if (id.includes('echarts')) return 'chart';
        if (id.includes('lodash')) return 'lodash';
        return 'vendor';
      }
    } } } } },
  // 配套 size-limit 配置 + CI hook，脚手架创建即生效
};
```
