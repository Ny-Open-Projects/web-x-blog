## PER-1098：如何设计"防重放"的前端请求体系

**答**：
- 手段：时间戳 + nonce + 签名（1088）是基础；幂等键防业务重复；高危操作二次验证。
- nonce 管理服务端成本高（存储与过期），可用时间窗 + 客户端会话密钥简化。
- 与重试的兼容：重试复用同一签名（同 nonce）会失败——重试需重新签名或服务端对同幂等键放行。
- 测试：重放攻击模拟（录制请求重发）验证 100% 被拒。

```javascript
// 重放攻击模拟测试
async function replayTest(signedRequest) {
  const first = await signedRequest();               // 首次正常
  const replay = await signedRequest();              // 原样重发
  return { first: first.status, replay: replay.status,
    pass: first.ok && replay.status === 401 || replay.status === 409 };
}
// 服务端规则：同 nonce+同幂等键且参数一致 -> 幂等返回缓存结果而非 401
// 参数不一致 -> 直接 401 拒绝（签名复用攻击）
```
