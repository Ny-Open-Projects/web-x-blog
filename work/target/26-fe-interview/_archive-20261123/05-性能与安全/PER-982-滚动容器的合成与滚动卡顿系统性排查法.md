## PER-982：滚动容器的合成与"滚动卡顿"系统性排查法

**答**：
- 滚动本身在合成器线程，卡顿来源三类：滚动容器内布局失效（滚动中懒加载/重排）、被动监听的主线程回调、大图片层反复栅格化。
- 排查顺序：Performance 录制滚动 → 看主线程是否有滚动相关任务（脚本）→ 看 Rasterize 是否密集 → 看 Layout 是否被滚动触发。
- 修复对应：懒加载加 rootMargin 预热、监听改 IO/timeline、大图预解码与定尺寸。
- 预防：滚动区域内容统一 contain: paint，图片宽高必填，滚动监听准入走 lint 规则。

```javascript
// 滚动健康自检脚本
function scrollHealth(container) {
  const listeners = getEventListeners?.(container) ?? {};
  const bad = [];
  for (const [type, ls] of Object.entries(listeners)) {
    if (type === 'scroll' && ls.some(l => !l.passive)) bad.push('scroll 非 passive');
    if (type === 'wheel' && ls.some(l => !l.passive)) bad.push('wheel 非 passive');
  }
  const imgs = [...container.querySelectorAll('img')];
  const noSize = imgs.filter(i => !i.width && !i.getAttribute('width')).length;
  return { bad, imgs: imgs.length, noSize,
    verdict: bad.length || noSize ? '存在卡顿风险' : 'ok' };
}
```
