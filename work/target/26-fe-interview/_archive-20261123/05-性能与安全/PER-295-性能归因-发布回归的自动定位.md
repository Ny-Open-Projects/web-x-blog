## PER-295：发版后性能突然恶化，如何自动定位"是哪个版本/哪次提交引入的"？

**答**：
- 前提基建：RUM 上报带版本号（构建时注入 `__BUILD_VERSION__`）与发布时间戳；看板在时间轴上自动标注发版线。没有版本维度就无法定位，这是基建先行项。
- 自动对比：发版后 2 小时自动跑"新旧版本同口径对比"（PER-249 的分组对比）：同页面、同设备切片下，p75 INP/LCP/CLS 与错误率差异，显著恶化即告警并附 diff。
- 定位到提交：版本 diff 只到"两个构建之间"，再往下用产物 diff——CI 里对构建产物做 chunk 体积 diff（哪个包涨了）+ 关键函数耗时快照（如实验室脚本执行 profiler 对比），结合 git log 圈定嫌疑提交。
- 回滚决策：恶化幅度超阈值（如 INP p75 +30%）且影响核心页面时，性能告警应触发"回滚评审"而不是只发通知；灰度发布让这类问题止步于 5% 流量。

```javascript
// 构建时注入版本与产物指纹
// webpack/vite:
// new webpack.DefinePlugin({ __BUILD_VERSION__: JSON.stringify(process.env.GIT_SHA) })
// RUM 上报带版本：
report({ type: 'INP', value: 480, v: __BUILD_VERSION__, page: routeTemplate(location.pathname) });
// 服务端自动对比任务（伪码）：
// for page in topPages:
//   cur  = p75(metric, version=NEW, device=PHONE, last2h)
//   prev = p75(metric, version=OLD, device=PHONE, last2h_before_release)
//   if cur > prev * 1.3 && significant():   # PER-249 bootstrap 显著性
//     alert(owner, `INP +${(cur/prev-1)*100}% 由 ${NEW} 引入`, diffLink(OLD, NEW))
```
