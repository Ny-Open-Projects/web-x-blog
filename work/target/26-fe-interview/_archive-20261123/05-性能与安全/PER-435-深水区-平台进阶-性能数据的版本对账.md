## PER-435：SDK 升级后新旧口径数据的衔接与历史数据可信度维护？

**答**:
- 问题：RUM SDK 升级（采集逻辑变化：LCP 候选策略修正/CLS 窗口修正）后，新旧数据口径不一致——趋势图出现"台阶"，若不处理会被误读为性能突变。这与指标口径变更（PER-419）同类，但发生在 SDK 层。
- 对账机制：① SDK 版本字段必报——每条数据带 sdkVersion，聚合层按版本分组；② 双跑期——新版本灰度期间新旧并存，同会话双上报校验（PER-239 的双跑校验），产出修正系数；③ 历史数据标注——趋势图在 SDK 版本切换点画分界线并标注口径变化，跨版本的对比自动应用修正系数；④ 数据可信度等级——每段历史数据标注采集版本与已知偏差（供两年后复盘时判断数据可靠性）。
- 预防纪律：SDK 升级前跑口径回归基准（固定样本集，新旧实现输出 diff < 阈值才发布）；破坏性采集变更（改口径）按 PER-419 流程走，纯修复变更（修 bug）走快速通道但要说明影响。

```text
SDK 版本对账：
每条数据带 sdkVersion → 聚合层按版本分组
升级流程：固定样本集口径回归基准（diff < 阈值才发布）
  → 双跑期灰度（同会话双上报校验，产出修正系数）
  → 趋势图版本切换点画分界线 + 跨版本对比应用修正系数
数据可信度：每段历史标采集版本与已知偏差
纪律：口径级变更走 PER-419 流程；bug 修复级走快速通道但说明影响
```
