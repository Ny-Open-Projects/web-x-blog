## PER-1187：用户身份与同意的绑定关系设计

**答**：
- 问题：同意挂在设备上还是账号上？换设备/登出后同意状态如何延续。
- 设计：同意记录双键（设备 ID + 账号 ID），登录时合并策略（从严原则：账号级拒绝覆盖设备级同意）。
- 边界：游客模式（无账号）同意只挂设备；账号注销时同意记录随删除（保留审计摘要）。
- 冲突场景：同一账号多设备不同选择——以账号最新为准并全端同步。

```javascript
// 同意合并策略
function mergeConsent(deviceConsent, accountConsent) {
  // 从严：false 优先
  const merged = {};
  for (const k of new Set([...Object.keys(deviceConsent), ...Object.keys(accountConsent)]))
    merged[k] = deviceConsent[k] === false || accountConsent[k] === false ? false
      : (accountConsent[k] ?? deviceConsent[k] ?? false);
  report({ type: 'consent-merge', merged });
  return merged;
}
// 登出：设备恢复设备级同意，不继承账号拒绝（可重新询问）
```
