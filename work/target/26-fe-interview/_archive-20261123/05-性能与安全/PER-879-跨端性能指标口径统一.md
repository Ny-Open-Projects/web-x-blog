## PER-879：跨端性能指标口径统一：H5、RN、小程序与 Native 的秒开与卡顿口径对齐

**答**：
- 问题本质：各端原始指标定义不同（H5 的 FCP / 小程序的首屏 setData 完成 / RN 首帧 / Native 的页面可见），直接对比会得出错误结论（某端"看起来快"只是口径早）。
- 统一原则：以"用户看到核心内容且可交互"为锚（TTI 类），各端映射到统一指标（如 u-second-open）；每端保留原始指标明细，映射规则文档化并可追溯。
- 卡顿口径：Web 用 FPS/长任务、RN 用 JS 线程帧率、Native 用渲染掉帧——统一为"卡顿次数/分钟（>50ms 阻塞）"口径，各端采集方式不同但阈值一致。
- 落地：指标注册表（端 × 原始指标 × 映射规则 × Owner）+ 抽样人工校验（同一页面双端录屏对齐），口径变更走评审。

```javascript
const metricRegistry = {                     // 端 × 原始指标 → 统一口径
  h5: { raw: 'FCP+TTI', map: r => r.tti, uMetric: 'u-second-open' },
  mp: { raw: 'first-setData-done', map: r => r.setDataDone, uMetric: 'u-second-open' },
  rn: { raw: 'first-frame+interactive', map: r => r.interactiveAt, uMetric: 'u-second-open' },
  native: { raw: 'page-render-finished', map: r => r.renderDone, uMetric: 'u-second-open' },
};
function unify(records) {                     // records: {platform, raw, ms}
  return records.map(r => {
    const reg = metricRegistry[r.platform];
    if (!reg) return { ...r, unified: null, note: 'unregistered-platform' };
    return { ...r, unified: reg.uMetric, ms: reg.map(r.rawMs) ?? r.rawMs.ms };
  });
}
// 卡顿统一：>50ms 阻塞次数/分钟
function stallRate(events, minutes) {
  const stalls = events.filter(e => e.blockMs > 50).length;
  return +(stalls / minutes).toFixed(2);      // 各端阈值一致，采集不同
}
```
