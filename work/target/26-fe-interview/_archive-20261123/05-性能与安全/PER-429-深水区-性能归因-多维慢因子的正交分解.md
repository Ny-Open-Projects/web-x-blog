## PER-429：把"页面慢"拆成设备/网络/代码/后端四个可加因子的方法？

**答**:
- 归因的量化目标：p75 LCP = 3.8s，分解出"低端机贡献 0.9s、弱网贡献 1.2s、代码贡献 0.8s、后端贡献 0.9s"——每个因子的量级决定优化优先级与责任归属。
- 分解方法：基于分层切片的加权贡献估计——① 用最佳组合切片（旗舰机+快网）的 p75 作为"代码+后端地板"；② 设备因子 = 中低端机切片与旗舰切片的差（同网络下）；③ 网络因子 = 弱网切片与快网切片的差（同设备下）；④ 后端因子 = Server-Timing 的 P75 直接读出（PER-257）；⑤ 代码因子 = 地板 − 后端 − 基础网络。切片样本不足时用回归模型补（设备档×网络档系数）。
- 有效性约束：切片间要有足够样本（分层采样保尾部）；因子有交互效应（弱网×低端机非线性叠加）——报告时标注"近似可加模型"与误差范围。
- 落地形态：页面健康卡自动输出因子分解（PER-400 扩展），每个因子链接到对应的治理工具箱（设备因子→降级策略、网络因子→CDN、代码因子→bundle、后端因子→接口优化）。

```text
慢因子正交分解（近似可加模型）：
p75 LCP 3.8s = 代码 0.8 + 后端 0.9 + 网络 1.2 + 设备 0.9
  后端因子：Server-Timing p75 直读（权威）
  设备因子：低端机切片 − 旗舰切片（同网络控制）
  网络因子：弱网切片 − 快网切片（同设备控制）
  代码因子：地板(旗舰+快网) − 后端 − 基础网络
约束：切片样本充足（分层采样保尾部）；交互效应标注近似性与误差
输出：因子 → 治理工具箱映射（设备→降级 / 网络→CDN / 代码→bundle / 后端→接口）
```
