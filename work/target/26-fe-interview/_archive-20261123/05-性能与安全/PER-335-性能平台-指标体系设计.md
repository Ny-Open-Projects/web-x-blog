## PER-335：性能平台设计的指标体系怎么搭？北极星、诊断树与业务指标三层怎么分？

**答**：
- 三层结构：① 北极星层——2~4 个全公司对齐的核心指标（CWV 达标率、核心页 p75 LCP/INP），少而稳定，给管理层看趋势与预算达成；② 诊断层——支撑北极星的拆解指标（四段拆解、长任务数、三方阻塞时长、接口 P75），给工程团队定位用，只做下钻不进汇报；③ 业务层——性能与业务的关联指标（弱网转化率、性能与跳出率相关性），给产品/运营说话用。
- 设计纪律：北极星不许频繁改（口径变更要公告+双轨期）；诊断指标可以随工具演进随时增删；每个指标必须有：口径定义（怎么算）、采集点（哪个 API）、责任人、SLO、看板链接——五要素缺一就不是"指标"是"数字"。
- 反模式：指标大杂烩（50 个指标全上汇报页）、无口径文档（每次争论怎么算）、无 owner（发现恶化没人管）、无 SLO（达标与否靠感觉）。
- 平台形态：指标注册中心（定义 YAML 化，口径即代码）+ 统一聚合引擎 + 分层看板 + 告警路由，四个组件把"指标"从口头变成资产。

```yaml
# 指标注册中心示例（YAML 定义口径即代码）
metric: core_lcp_p75
tier: north-star                       # north-star | diagnostic | business
definition: |
  LCP 原始值（Event Timing last candidate），页面导航类型 = navigate，
  按页面模板聚合第 75 分位，单位 ms
source: rum.vitals                    # 采集点
owner: perf-team
slo: { good: 2500, unit: ms, eval: p75 }
dashboard: https://perf.example.com/lcp
alerts: [ { type: threshold, cond: "> 2500 for 2h", route: perf-oncall } ]
```
