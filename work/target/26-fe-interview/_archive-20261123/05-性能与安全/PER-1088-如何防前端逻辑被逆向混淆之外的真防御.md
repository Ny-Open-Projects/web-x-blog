## PER-1088：如何防"前端逻辑被逆向"（混淆之外的真防御）

**答**：
- 认知：前端代码必然可逆向，混淆只是提高成本；真防御是"服务端裁决"——关键逻辑（定价/风控/权限）不下放前端。
- 手段：关键计算放服务端或 WASM + 服务端校验双保险；接口参数签名（时间戳+nonce+HMAC）防重放与篡改；行为风控（操作频率/轨迹）。
- 反调试与完整性检测仅作辅助（检测调试器打开、自校验代码 hash），且要防误伤。
- 风控联动：前端埋点提供设备与行为特征，服务端模型判定，命中即挑战（验证码/限流）。

```javascript
// 接口签名防重放
async function signedFetch(url, body) {
  const ts = Date.now();
  const nonce = crypto.randomUUID();
  const payload = JSON.stringify({ url, body, ts, nonce });
  const key = await sessionKey();               // 派生密钥，不在源码硬编码
  const sig = await hmac(key, payload);
  return fetch(url, { method: 'POST',
    headers: { 'X-Ts': ts, 'X-Nonce': nonce, 'X-Sign': sig },
    body: JSON.stringify(body) });
}
// 服务端：ts 漂移 < 60s、nonce 未见过、签名匹配，三者齐才受理
```
