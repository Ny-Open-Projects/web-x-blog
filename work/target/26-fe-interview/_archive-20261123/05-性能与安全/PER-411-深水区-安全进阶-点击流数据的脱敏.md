## PER-411：行为埋点（点击流）的隐私脱敏：路径数据、输入内容与跨站关联的脱敏规则？

**答**:
- 三类风险源：① 路径数据——URL query 里的 token/手机号/订单号随埋点上报（页面路径要先脱敏再上报：query 白名单化，敏感参数替换为 `[redacted]`）；② 输入内容——表单输入埋点（autocomplete 采集）绝不能带明文，只采"字段名 + 长度 + 是否填写"；③ 跨站关联——referrer 带完整 URL 可能泄漏用户来源页面细节，用 referrer policy 收敛 + 埋点侧解析为来源域名。
- 脱敏管道：SDK 出口统一过滤——URL 规范化（query 白名单）、字符串截断（防大 payload）、字段黑名单（password/idcard 等键名直接丢弃）、PII 模式检测（手机号/身份证正则命中即替换）。
- 制度配套：埋点字段准入清单（新埋点字段走评审，PER-389 管道扩展）；保留期（明细 30 天）；用户删除权（按设备标识的删除接口）。
- 验证：埋点数据抽样审计（自动化 PII 检测器扫上报样本）——上线后持续跑，命中即告警。

```javascript
// 埋点出口脱敏管道
const SENSITIVE_KEYS = /^(password|idcard|phone|token|card)/i;
const PII_PATTERNS = [/1[3-9]\d{9}/, /\d{17}[\dXx]/];     // 手机号/身份证

function sanitize(event) {
  const out = { ...event };
  if (out.page) {                                          // URL 规范化：query 白名单
    const u = new URL(out.page, location.origin);
    const keep = new Set(['id', 'page', 'sort']);
    for (const [k] of u.searchParams) if (!keep.has(k)) u.searchParams.set(k, '[redacted]');
    out.page = u.pathname + u.search;
  }
  for (const [k, v] of Object.entries(out)) {
    if (SENSITIVE_KEYS.test(k)) delete out[k];             // 键名黑名单
    else if (typeof v === 'string' && PII_PATTERNS.some((p) => p.test(v))) out[k] = '[pii]';
  }
  return out;
}
// 通道出口统一过 sanitize（PER-389 管道挂载点）
```
