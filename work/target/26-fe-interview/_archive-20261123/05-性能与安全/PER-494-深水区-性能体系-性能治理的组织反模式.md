## PER-494：性能治理的组织反模式识别与纠偏？

**答**:
- 反模式一：性能警察——平台团队只拦不帮（卡口拦截 + "找平台组"的黑洞），业务方绕过卡口（禁用/造数据）。纠偏：平台团队配服务指标（帮修的工单数/接入支持时长），卡口附带自动修复建议（"超预算 → 这三个文件可以拆"）。
- 反模式二：指标 KPI 化——CWV 达标率进业务 KPI 后出现数据美化（采样调整/口径宽松/只报好看的页面）。纠偏：指标进 OKR 但口径审计独立（PER-419 注册中心口径不可被业务改）；激励与治理指标（复发率/修复率）绑定而非单点达标率。
- 反模式三：平台孤岛——性能平台与监控/发布/工单系统不互通（告警无人认领、发布无性能检查）。纠偏：集成优先于功能（PER-457 API 优先建设）；平台健康度度量里"集成度"是一级指标。
- 识别信号：业务方绕过行为、数据美化投诉、平台使用率下滑——每季度组织健康度评审（PER-343 加议题）。

```text
性能治理组织三反模式：
① 性能警察：只拦不帮 → 纠偏：平台配服务指标 + 卡口带自动修复建议
② 指标 KPI 化：数据美化 → 纠偏：口径审计独立（注册中心）+ 激励绑定复发率而非达标率
③ 平台孤岛：与监控/发布/工单不互通 → 纠偏：API 集成优先（PER-457），集成度为一级健康度指标
识别信号：绕过行为 / 美化投诉 / 使用率下滑 → 季度组织健康度评审
```
