## PER-317：构建产物从 CI 到 CDN 到浏览器，完整性如何逐段审计？

**答**：
- 链路四段各有威胁：CI（依赖投毒改产物）→ 上传管道（中间人/配置错误）→ CDN（缓存污染/被入侵）→ 浏览器（传输劫持）。逐段对策：
- CI 段：构建可复现（同输入同输出，lockfile + 固定基础镜像），产物 hash 进构建日志；构建机最小权限（无外网凭据、产物只写不动依赖）。
- 上传段：manifest（文件→hash 清单）随产物签名（cosign 类制品签名）；上传后探活校验（PER-310 verifyManifest）——CDN 返回字节 hash 必须等于 manifest。
- CDN 段：SRI 让浏览器硬校验（PER-308）；CDN 开启"回源校验"与访问日志审计；跨域资源 crossorigin=anonymous + TLS。
- 浏览器段：CSP script-src 限定 CDN 域（配合 strict-dynamic）；SRI 失败监控上报（区分篡改/缓存/网络）。
- 应急预案：出现篡改迹象的响应清单——下线受影响资源 URL、CDN 回源重推、从 CI 重新发布、排查 CDN 账号权限，全部预演过。

```text
产物完整性审计链：
CI build(可复现) → 产物 hash + manifest 签名
   → upload → probe(hash 对账, PER-310)
   → CDN(独立域 + 访问日志 + 回源校验)
   → browser(SRI 硬校验 + CSP 白名单 + 失败监控上报)
应急：篡改告警 → 下线 URL → CDN 重推 → 重发布 → 账号审计（1 小时内止血）
```
