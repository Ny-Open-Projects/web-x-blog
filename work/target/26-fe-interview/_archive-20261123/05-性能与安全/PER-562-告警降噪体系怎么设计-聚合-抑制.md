## PER-562：告警降噪体系怎么设计？聚合/抑制/静默三级机制分别解决什么问题？

**答**：
- 三级机制各治一种噪声：**聚合**治同一问题重复响"（同一指纹的告警在窗口内合并成一条并累计计数）、**抑制**治连带告警刷屏"（网关挂了导致全站接口告警，只留根因告警，子告警被根因抑制）、**静默**治已知问题打扰"（计划内发版/维护窗口手动静默）。
- 聚合的 key 设计要贴近排障心智：错误指纹 + 路由 + 版本，而不是简单的 URL 全串（参数不同会打散聚合）。
- 抑制的方向是单向的：根因告警出现 -> 抑制其下游依赖的告警，需要依赖拓扑配置；拓扑不准会导致真告警被误抑制，所以抑制规则要可回溯（被抑制的告警在恢复后可见）。
- 效果度量：降噪后 page 量、聚合率（原始告警数/通知数）、漏报复盘数，三个数字每周看板公开。

```javascript

const alertNoiseControl = {
  aggregate: { key: ['errFingerprint', 'route', 'version'], window: '5m',
    action: '合并为一条并累计 count' },
  inhibit: { topo: { 'gateway-down': ['api-5xx-*', 'api-timeout-*'] },
    rule: '根因 active 时子告警转 suppressed，根因恢复后可见可回溯' },
  silence: { scope: ['env=prod', 'version=v2.3.x'], during: '发版窗口 20:00-21:00',
    owner: '值班长审批' },
  metrics: { pagePerWeek: '<10', aggregateRate: '>90%', missRate: '复盘统计，目标 0' },
};
console.log(alertNoiseControl.inhibit.rule);
```
