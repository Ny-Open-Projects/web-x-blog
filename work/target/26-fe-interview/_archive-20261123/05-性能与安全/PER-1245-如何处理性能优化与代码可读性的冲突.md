## PER-1245：如何处理"性能优化与代码可读性"的冲突

**答**：
- 常见冲突：手写优化（内联/展开循环/避免抽象）让代码难维护。
- 决策：默认可读优先；热点路径（profiler 证实）才做底层优化，且优化必须带注释（为什么快/基准数据）。
- 封装：优化逻辑下沉到工具库（fastdom/虚拟列表封装），业务用可读 API。
- 评审标准：反模式修复按库封装实现，禁止业务代码内手写低级优化。

// 优化注释规范
// PERF: 批量读写分离，避免 N 次强制布局
// 基准：优化前 120ms -> 优化后 8ms（1k 行）
// see: fastdom（1225 测试）
function batchedUpdate(items) { /* fastdom read then write */ }
