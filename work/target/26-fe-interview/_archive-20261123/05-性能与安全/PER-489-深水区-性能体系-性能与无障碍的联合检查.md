## PER-489：性能与无障碍的同源问题双视角？

**答**:
- 同源模式盘点：① JS 依赖渲染——慢（首屏等 JS）且不可访问（读屏用户也等）；② 自定义组件无语义——渲染重（div 堆叠）且读屏无法理解（role 缺失）；③ 动画无 prefers-reduced-motion 尊重——性能浪费（用户不需要的动画照跑）+ 前庭问题；④ 巨型 DOM——布局慢 + 读屏遍历慢；⑤ 键盘导航缺失常伴随滚动监听混乱（PER-128 的 roving tabindex 与 ScrollHub 同源治理）。
- 联合检查清单：提测清单合并性能与 a11y 项（一次过两关）；自动化——Lighthouse 同时出 performance 与 accessibility 分数，双低的页面进联合治理清单；组件库默认语义（PER-341：组件自带 role/aria——组件层一次修复双收益）。
- 度量：双低页面占比趋势；组件库 a11y 画像（PER-381 扩展）。

```text
性能 × 无障碍同源模式：
JS 依赖渲染 / 无语义自定义组件 / 动画不尊重 reduced-motion / 巨型 DOM / 键盘导航混乱
联合清单：提测一次过两关；Lighthouse 双分（双低页进联合治理）
组件库默认语义（PER-341）：一次修复双收益
度量：双低页面占比趋势 + 组件 a11y 画像
协同价值：同一反模式的两个受害者视角互为佐证
```
