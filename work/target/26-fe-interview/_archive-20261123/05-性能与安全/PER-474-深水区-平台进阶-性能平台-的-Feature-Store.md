## PER-474：性能平台的能力目录与复用治理？

**答**:
- 场景：平台长大后的重复建设——三个团队各写了一个"慢资源排行看板"、两个采集器都在算 Resource Timing 拆解。能力目录（capability catalog）解决"平台里已经有什么"的可发现性问题。
- 目录设计：能力条目 = { 能力名, 类型（SDK 插件/看板组件/告警动作/API）, owner, 版本, 使用方, 文档链接 }；注册即评审（能力签名：输入输出契约）；使用方登记（谁在用——下线决策的依据）。
- 治理节奏：季度能力盘点——使用方为 0 的能力下线候选；重复能力合并（保留最好的一个）；能力间依赖图（SDK 插件依赖核心版本——升级通知机制）。
- 价值度量：新需求"复用已有能力"的比例（> 60% 说明目录有效）；能力平均使用方数（孤儿能力占比应 < 15%）。

```text
能力目录（capability catalog）：
条目：{ 名, 类型(SDK插件/看板组件/告警动作/API), owner, 版本, 使用方, 契约, 文档 }
流程：注册评审（契约签名）→ 使用方登记 → 季度盘点（0 使用方下线 / 重复能力合并）
依赖图：SDK 插件依赖核心版本 → 升级通知
度量：新需求复用比例 > 60%；孤儿能力 < 15%
价值：治"重复建设"与"平台里有什么没人知道"两大顽疾
```
