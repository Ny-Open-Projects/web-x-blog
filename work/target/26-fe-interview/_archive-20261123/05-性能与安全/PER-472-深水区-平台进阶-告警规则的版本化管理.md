## PER-472：告警规则的版本化管理：变更走评审、可回滚、可追溯？

**答**:
- 现状问题：告警规则散落在监控控制台手动改——谁改的/为什么改/改错了怎么回滚全靠记忆；一次误改（阈值改小 10 倍）能造成告警风暴或静默漏报。
- 工程化方案：规则即代码（YAML 进仓库，PER-337 的规则注册）→ 变更走 PR 评审（影响面声明：哪些页面/哪些路由）→ CI 语法与影响面校验 → 合入自动下发生效 → 每次变更留版本与 diff。回滚 = revert PR（分钟级）。
- 变更纪律：新规则先 warn 模式跑 1 周观察误报率再启用（PER-432 lint 同款纪律）；规则删除必须附"为什么不再需要"的说明（防删除后问题复发无人知）。
- 度量：规则变更频率、回滚率、误报率趋势——规则库的健康度与代码库同标准治理。

```text
告警规则工程化：
规则即代码（YAML 仓库）→ PR 评审（影响面声明）→ CI 校验 → 自动下发 → 版本 diff
回滚 = revert PR（分钟级）；变更留版本与变更人
纪律：新规则 warn 模式跑 1 周再启用；删除规则必须附说明
度量：变更频率 / 回滚率 / 误报率趋势 —— 规则库按代码库标准治理
收益：误改阈值的风暴从"无人知"变"diff 可见 + revert 可回"
```
