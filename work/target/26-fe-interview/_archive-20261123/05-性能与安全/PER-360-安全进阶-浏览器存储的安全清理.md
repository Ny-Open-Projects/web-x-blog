## PER-360：敏感数据在前端存储（token/PII）的安全清理：退出登录的完整擦除清单？

**答**：
- 擦除清单（退出登录/账号切换时）：① localStorage/sessionStorage——同源所有键（或按前缀白名单删除，注意 ITP 下 localStorage 存 token 本身就应避免）；② IndexedDB——用户数据分库逐库 delete 或整库 deleteDatabase；③ Cache API/Service Worker——含用户数据响应的 cache 逐个删除（注意公共静态资源缓存可保留）；④ Cookie——HttpOnly 由服务端 Set-Cookie 过期，JS Cookie 逐个 max-age=0；⑤ 内存——全局状态 store reset、事件总线解绑、闭包引用置空（尽量让对象可 GC）。
- 原则：token 类**不落盘**（内存 + HttpOnly Cookie），PII 尽量不缓存，缓存必带"用户域"前缀便于批量清理（`u:123:*`）；多标签页场景广播登出（BroadcastChannel）同步清理。
- 验证手段：自动化测试——登录写入 → 登出 → 遍历 storage/IDB/cache 断言无用户数据残留。

```javascript
async function wipeUserData({ userId }) {
  localStorage.clear(); sessionStorage.clear();        // 或按 u:123: 前缀删
  const dbs = await indexedDB.databases?.() ?? [];
  for (const { name } of dbs) {
    if (name?.startsWith(`u:${userId}:`)) indexedDB.deleteDatabase(name);   // 用户域分库
  }
  const keys = await caches.keys();
  await Promise.all(keys.filter((k) => k.startsWith(`u:${userId}:`)).map((k) => caches.delete(k)));
  document.cookie.split(';').forEach((c) => {          // JS Cookie 过期
    const name = c.split('=')[0].trim();
    document.cookie = `${name}=;max-age=0;path=/`;
  });
  store.reset();                                       // 全局状态复位
  new BroadcastChannel('auth').postMessage({ type: 'logout' });   // 广播其他标签页同步擦除
}
```
