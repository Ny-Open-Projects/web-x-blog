## PER-867：移动端表单页的性能专项：长表单渲染、分步拆分与校验时机

**答**：
- 长表单（几十个字段）的性能问题：一次性渲染全部字段节点多、每个输入的受控更新触发全表单重渲染、校验逻辑集中阻塞提交。
- 分步拆分：按业务逻辑切成 2~4 步，每步独立挂载（上一步卸载或 keep 状态）；步骤间数据本地暂存（draft），最后统一提交——节点数与重渲染范围都减半以上。
- 校验时机：输入时只做轻校验（必填/长度），blur 做字段级格式校验，提交做全量校验（含异步唯一性检查）；校验函数防抖避免每键触发。
- 性能度量：单字段输入到 UI 回显延迟、切步耗时、提交前校验总耗时；目标输入回显 < 50ms、切步 < 300ms。

```javascript
const formOptimizer = {
  split(steps) {                                               // 分步拆分
    return steps.map((fields, i) => ({
      step: i, fields,
      mount() { return renderFields(fields); },                // 按步挂载
      unmount() { saveDraft(fields); releaseFields(fields); }, // 卸载存草稿
    }));
  },
  validateField(field, value, stage) {                         // 分级校验时机
    if (stage === 'input') return rule.required(value);        // 轻校验
    if (stage === 'blur') return rule.format(field, value);    // 格式
    if (stage === 'submit') return Promise.all([               // 全量含异步
      rule.format(field, value),
      rule.unique(field, value),
    ]);
  },
  metric: { echoMs: '< 50ms 输入回显', stepMs: '< 300ms 切步' },
};
```
