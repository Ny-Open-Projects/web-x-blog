## PER-438：动画中断与恢复：Web Animations API 的正确续播实现？

**答**:
- 场景：抽屉动画播到一半被路由切换中断，回来要"从当前进度续播"而不是重播。WAAPI 的正确做法：读取 `animation.currentTime`（或 effect.getComputedTiming().progress），新动画从该 offset 起播；`fill: 'forwards'` 保持终态但会持有元素（无限 forwards 层不清理会内存滞留）——动画完成后 commitStyles() 固化样式再 cancel()。
- 中断语义：cancel() 会让元素跳回初始状态（fill 不保留）——中断续播必须先读进度再取消；commitStyles 把当前计算样式写成内联样式，避免 forwards 层滞留。
- 续播实现：进度 p = animation.currentTime / effect.getTiming().duration；恢复时 new KeyframeEffect(el, frames, { duration, iterations })，用 `animation.currentTime = p * duration` 起步。
- 性能关联： forwards 填充的动画持续持有合成层（元素不释放层），大量 forwards 动画 = 层滞留（PER-405 层预算）——完成即 commitStyles + cancel 是纪律。

```javascript
// 中断续播模板
function interruptedReplay(el, frames, { duration = 300 } = {}) {
  const savedProgress = el.__savedProgress ?? 0;         // 中断前存的进度 0~1
  const anim = el.animate(frames, { duration, easing: 'ease-out', fill: 'both' });
  anim.currentTime = savedProgress * duration;           // 从进度续播
  return anim.finished.then(() => {
    anim.commitStyles();                                 // 固化终态为内联样式
    anim.cancel();                                       // 释放 forwards 层（防层滞留）
    el.__savedProgress = 1;
  }).catch(() => {
    // 中断：存进度供续播
    el.__savedProgress = anim.effect.getComputedTiming().progress ?? 0;
  });
}
// fill:'forwards' 不清理 = 元素持续占合成层（层内存滞留）；完成即 commitStyles+cancel 是纪律
```
