## PER-453：图标库/字体/配色资产的投毒风险与资产白名单？

**答**:
- 被忽视面：供应链审计常聚焦 npm 包，但静态资产同样有投毒面——图标 SVG 可内嵌 script（SVG 加载进 DOM 可执行）、字体文件可利用解析器漏洞、CDN 上的"免费图标包"被篡改注入。SVG 作为 <img> 不执行脚本但 inline SVG 会。
- 防护清单：① 资产白名单——图标/字体只从受控源（自家 CDN/官方发布通道）引入，CI 扫描资产来源；② SVG 净化——内联 SVG 上线前过 SVG sanitizer（去 script/事件属性/foreignObject）；③ 字体校验——字体文件 hash 入 manifest（PER-310 模式），来源域白名单（PER-316）；④ 撤源审计——第三方"资源聚合站"（免费字体站/图标站）禁止直链，一律官方源。
- 案例：历史上 SVG 注入 XSS（内嵌 <script> + onload 事件）与字体解析 CVE 都真实发生过——"静态资产是安全的"是错误假设。
- 落地：资产清单进 SBOM（PER-315 扩展），巡检覆盖静态资产来源与 hash。

```text
静态资产供应链防护：
风险：SVG 内嵌 script/onload（inline 可执行）、字体解析 CVE、聚合站直链被篡改
防护：
  [ ] 资产白名单：只从官方源/自家 CDN 引入；CI 扫资产来源
  [ ] inline SVG 过 sanitizer（去 script/事件属性/foreignObject）
  [ ] 字体/图标 hash 入 manifest（PER-310）+ 来源域白名单（PER-316）
  [ ] 禁止第三方资源聚合站直链
落地：资产清单进 SBOM；巡检覆盖静态资产（与 npm 审计同等地位）
```
