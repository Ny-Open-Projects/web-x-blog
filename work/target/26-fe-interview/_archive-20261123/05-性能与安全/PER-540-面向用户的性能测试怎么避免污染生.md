## PER-540：面向用户的性能测试怎么避免污染生产数据？压测流量和真实流量的隔离方案有哪些？

**答**：
- 隔离四板斧：**流量打标**（压测请求带 `X-Load-Test` 头，全链路透传到 DB 层写影子表）、**独立账号池**（压测专用账号与真实用户隔离，避免污染推荐画像）、**独立数据域**（压测订单写影子库或打标后由清理任务回收）、**限流豁免与保护**（压测 IP 加白名单防误封，同时真实用户侧加保险限流）。
- 前端职责：打标透传、压测入口隐藏（只有内网域名/特定 query 开启）、压测后验证真实用户数据未被污染（对比压测前后订单量曲线）。
- 事故案例视角：最常见的污染是"压测账号混进推荐系统导致全站用户第二天刷出测试商品"，根因是推荐侧没接打标协议——全链路压测的打标协议必须覆盖所有数据消费方。
- 兜底：压测窗口选低峰 + 一键熔断开关 + 压测后数据核对清单。

```javascript

// 压测标识的统一透传封装：前端只此一处，避免散落
function pressureAwareFetch(input, init = {}) {
  const headers = new Headers(init.headers || {});
  if (window.__PRESSURE__) headers.set('X-Load-Test', '1');   // 全链路打标协议
  return fetch(input, { ...init, headers });
}
// 入口开启：仅内网域名或白名单 query
if (location.hostname.endsWith('.test.internal') ||
    new URLSearchParams(location.search).get('__pt') === '1') {
  window.__PRESSURE__ = true;
}
// 压测后核对：SELECT count(*) FROM orders WHERE is_load_test=1 -> 确认全部落影子表
```
