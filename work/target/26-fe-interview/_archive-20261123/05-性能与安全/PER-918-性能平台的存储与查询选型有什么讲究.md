## PER-918：性能平台的存储与查询选型有什么讲究

**答**：
- 明细数据量大：原始埋点写 Kafka，落对象存储（Parquet）供离线回放；实时聚合走 Flink 写 ClickHouse。
- 查询模式决定引擎：多维下钻聚合→ClickHouse/Doris；单用户会话回放→ES 或对象存储按 uid 索引；趋势看板→预聚合表。
- 成本控制：明细保留 7~30 天、聚合保留 1~2 年；采样降本（明细 10% 采样但 P75 计算需注意偏差，用分层采样保尾部）。
- 读写隔离：看板查询只打预聚合表，禁止即席查询直接扫明细。

```javascript
// 分层采样：保住尾部用户不丢失
function sample(records, rate = 0.1) {
  return records.filter(r => {
    if (r.lcp > 4000) return true;               // 尾部全保留
    return hash(r.uid) % 100 < rate * 100;       // 头部按比例
  });
}
// 注意：采样后 P75 需按层权重还原：
// p75 = mix(headP75, wHead) 与 tailP75 按真实占比加权
```
