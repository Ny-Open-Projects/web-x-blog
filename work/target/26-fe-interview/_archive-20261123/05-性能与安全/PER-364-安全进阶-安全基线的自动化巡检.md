## PER-364：前端安全基线（安全头/CSP/SRI/依赖）如何自动化巡检？巡检项与修复闭环？

**答**：
- 巡检项清单（对每个线上站点周期跑）：① 安全响应头齐全性——CSP、HSTS、X-Content-Type-Options、Referrer-Policy、Permissions-Policy、frame-ancestors；② CSP 强度评分——是否 Report-Only、有无 unsafe-inline/eval、白名单规模；③ SRI 覆盖率——外链 script/style 带 integrity 的比例；④ 依赖审计——npm audit 高危、过期大版本；⑤ 三方脚本清单 diff——新增未评审域；⑥ 传输——TLS 版本、证书到期。
- 实现：巡检脚本（curl 拉头 + 解析 CSP + 对账 SRI 清单 + npm audit + 三方清单 diff），输出评分与 diff 报告；接入 CI（PR 级增量巡检）与定时任务（周级全量巡检）。
- 修复闭环：巡检结果转工单（owner/严重级/deadline）；高危项（反射 Origin、无 CSP）24h 内修；修复验证自动复核（下次巡检绿了才关闭）；分数趋势进性能委员会月会。
- 与性能巡检合并跑：一个巡检平台同时出性能（PER-238 CrUX 巡检）与安全分数，同一工单体系，减少团队负担。

```javascript
// 巡检核心（伪码）
async function auditSite(origin) {
  const res = await fetch(origin);
  const headers = {
    csp: res.headers.get('content-security-policy'),
    hsts: res.headers.get('strict-transport-security'),
    xcto: res.headers.get('x-content-type-options'),
    referrer: res.headers.get('referrer-policy'),
    frame: res.headers.get('content-security-policy')?.includes('frame-ancestors'),
  };
  const cspScore = scoreCsp(headers.csp);           // report-only? unsafe-inline? 白名单数?
  const sriRatio = await sriCoverage(origin);        // 外链脚本 integrity 占比
  const audit = await npmAuditHigh();                // 高危依赖数
  return { headers: missingHeaders(headers), cspScore, sriRatio, audit, score: total() };
}
// 输出：{ score: 78, blockers: ['CSP report-only', 'SRI 40%'], owners: {...} }
// 周级跑全站 → 工单派发 → 自动复核关闭
```
