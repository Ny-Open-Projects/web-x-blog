## PER-400：LCP/INP/CLS/TTFB 四指标联合诊断一个页面的健康画像？

**答**:
- 单指标会骗人：LCP 达标但 TTFB 占比 70% —— "LCP 好"只是因为后续段被压缩，实际是"服务端快、前端烂"；四指标联合才构成健康画像。联动模式（典型组合与诊断）：
- 组合一：TTFB 高 + LCP 高 + INP 低 → 服务端/网络瓶颈，前端还行——查 CDN/回源/BFF（PER-258）。
- 组合二：TTFB 低 + LCP 高 + INP 高 → 前端负载过重（bundle 大/渲染重），典型 CSR 重页——bundle 减量 + 切片。
- 组合三：LCP 快 + INP 快 + CLS 高 → 内容稳定性问题（无尺寸媒体/动态插入），加载快反而放大位移感知——补占位。
- 组合四：全部达标但业务感知慢 → 指标没覆盖真实痛点（如接口瀑布导致"可看不可点"）→ 补自定义指标（业务首屏可交互 PER-231）。
- 联动视图：页面健康卡（四指标雷达图 + 组合诊断标签自动生成），把"逐个看数"升级为"一键画像"。

```text
页面健康卡（联动诊断自动标签）：
/pay:  TTFB 180ms ✓  LCP 2.1s ✓  INP 310ms ✗  CLS 0.02 ✓
自动诊断：组合二倾向 —— TTFB 低 + INP 高 → 前端负载重（bundle 480KB + 三个三方同步加载）
/list:  TTFB 620ms ✗  LCP 3.8s ✗  INP 160ms ✓  CLS 0.09 ✓
自动诊断：组合一 —— 服务端/网络瓶颈（CDN 命中率 58%，回源 P99 1.8s）
/faq:   全达标但"可看不可点"投诉多 → 补自定义指标 biz:faq-ready（PER-231 模式）
视图：雷达图 + 自动组合标签；逐页生成，委员会月会用
```
