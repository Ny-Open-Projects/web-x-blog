## PER-829：移动端触摸响应延迟优化：点击 300ms 的历史、现代方案的响应链路与感知优化

**答**：
- 300ms 延迟的历史：早期移动浏览器等待双击缩放（dblclick zoom）需延迟 click 判定；viewport meta 设 width=device-width 后现代浏览器已取消该延迟，FastClick 类库如今基本不需要。
- 现代响应链路：touchstart → (可能的滚动判定) → touchend → click 合成；延迟主要来自合成 click 的时机与主线程阻塞——touchstart 里做重活会拖慢后续滚动判定。
- 感知优化：视觉反馈先行（touchstart 立即按压态，不等 click），可交互元素 >= 44px 触控目标；关键操作用 touchend + 350ms 防误触代替 click（谨慎，与滚动冲突需位移判定）。
- 度量：从 touchstart 到视觉反馈的耗时、到业务响应的耗时分开测，定位"感觉卡"是渲染慢还是逻辑慢。

```javascript
// 视觉反馈先行 + 慢响应检测
document.addEventListener('touchstart', e => {
  const t = e.target.closest('[data-tappable]');
  if (!t) return;
  t._ts = performance.now();
  t.classList.add('pressed');               // 反馈先行，不等 click
}, { passive: true });
document.addEventListener('touchend', e => {
  const t = e.target.closest('[data-tappable]');
  if (!t) return;
  const latency = performance.now() - t._ts;
  if (latency > 100) report('slow-tap', { sel: t.dataset.tappable, ms: +latency.toFixed(1) });
  requestAnimationFrame(() => t.classList.remove('pressed'));   // 下一帧移除防闪
}, { passive: true });
// 注意：不要在 touchstart 中做重逻辑（会拖慢滚动判定）
```
