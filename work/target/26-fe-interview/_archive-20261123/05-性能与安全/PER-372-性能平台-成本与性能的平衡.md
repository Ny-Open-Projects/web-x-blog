## PER-372：性能优化与云成本的联合优化：CDN 流量/边缘计算/存储怎么一起看账？

**答**：
- 性能优化的成本面：图片转 AVIF（省流量但转码计算贵）、SSR（快但服务器 CPU 贵）、预取/预载（体验好但可能浪费流量）、回源策略（命中率 vs 源站压力）。两边都要进同一张账：**每千次访问成本**（CDN 流量 + 转码 + 计算合计）与性能指标并排看。
- 典型联合优化：图片——AVIF/WebP 省 30~60% 流量（成本与性能双赢，优先做）；预取——预取命中率监控（预取了没用 = 流量白花），按命中率调整预取范围；HTML 缓存——SWR 边缘缓存省回源（成本）且降 TTFB（性能）；SSR——只对"SEO/首屏敏感"页面 SSR，其余 CSR/SSG（计算成本可控）。
- 度量机制：成本看板与性能看板联动（同一页面维度）；优化动作的"双指标验收"（性能改善 + 成本不升或下降）；预取/降级这类"花钱买体验"的措施按 ROI 评审。

```text
联合账本（每千次 PV 成本，示例）：
图片 AVIF 化：流量 -40%（¥X → ¥0.6X）+ 转码成本 +10%  => 净省 30%，LCP -0.6s  双赢
接口预取：流量 +15%，预取命中率 55% => 45% 浪费；命中率 > 70% 才值得扩预取范围
SSR 范围：全站 SSR 月计算成本 ¥Y；砍到 30% 核心页 => 成本 -70%，非核心页 LCP 可接受
原则：性能与成本同一页面看数；双赢动作优先、单赢动作按 ROI 排序、双输动作不做
```
