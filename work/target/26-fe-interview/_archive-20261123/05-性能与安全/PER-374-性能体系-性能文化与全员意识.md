## PER-374：如何让"性能是每个人的事"落地而不只是口号？

**答**：
- 文化落地的四个支点：① 工具门槛低——看板自助可查（不用找平台组拉数）、CI 卡口自动反馈（开发者无感知被守护）、案例库即查即用；② 反馈即时——PR 里 3 分钟内拿到性能 diff（延迟反馈 = 没人看）；③ 责任到人——页面 owner 制 + 告警 MTTA 考核；④ 激励可见——性能达人榜、案例季度评优、优化收益进业务 OKR。
- 机制嵌入日常工作流：需求评审加"性能影响评估"项（新功能对预算的消耗）；代码评审 checklist 有性能项；发版 checklist 有性能验收（PER-248）；复盘会必看性能告警 MTTR。
- 避免形式主义：不搞"性能周打卡"，不为指标而指标（SLO 达标是手段不是目的）；平台组的服务姿态——"帮你更快"而不是"卡你发布"；卡口的豁免机制透明（perf-exception 标签 + 48h 还债）。
- 衡量文化：告警响应不需催、PR 性能讨论成为常态、新项目主动申请性能评审——行为指标比口号更能证明文化成立。

```text
文化落地检查表：
[ ] 任何人 5 分钟内能自助查到自己页面的性能现状（工具门槛）
[ ] PR 性能 diff 3 分钟内自动评论（反馈即时）
[ ] 每个线上页面有唯一 owner，告警 MTTA < 4h（责任到人）
[ ] 季度案例评优 + 优化收益进业务 OKR（激励可见）
[ ] 需求评审/代码评审/发版 checklist 均有性能项（流程嵌入）
[ ] 卡口豁免透明且 48h 还债（不做一刀切）
行为信号：性能讨论在 PR 中自发出现、新项目主动约性能评审 → 文化成立
```
