## PER-245：性能监控发现慢页面后，如何形成"预警→定位→修复→验证"的工单闭环？

**答**：
- 预警：告警消息里必须自带初步归因（哪个页面、哪个指标、环比恶化多少、疑似慢脚本 Top3），并且已按 owner 分好组——没有归因的告警等于转手问题。
- 定位：告警里的深链接直达看板单页视图（直方图 + 发版标注 + LoAF 脚本榜），owner 3 分钟内能看到"谁慢、为什么慢"。
- 修复：工单模板化——问题、SLO 目标值、建议方案（切片/懒加载/降体积）、预期收益；修复必须走正常代码评审，性能修复也有回归风险。
- 验证：合入后看板自动标记该页面的修复时间戳，观察 7 天 p75 回到 SLO 则关闭工单，否则自动重开并升级；CrUX 口径的最终验收等 28 天滚动窗口。
- 制度：闭环指标本身也要考核——告警响应时长、修复率、复发率，防止"告警一直没人认领"。

```text
工单生命周期（与看板联动）：
alert(fire) ──> ticket(create, owner=页面owner, 附归因链接)
   ──> fix(PR 标签 perf-fix) ──> deploy(看板标记时间戳)
   ──> verify(7天 p75 <= SLO ? close : reopen+escalate)
考核指标：MTTA(认领时长) < 4h；周修复率 >= 80%；同页复发率 < 10%
反例：告警进群没人认领 —— MTTA 无考核的必然结果
```
