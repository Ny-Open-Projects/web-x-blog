## PER-559：灰度发布期间的性能对照监控怎么做？灰度组与对照组的性能数据如何设计才公平？

**答**：
- 公平性来自**同条件对比**：灰度组与对照组的对比必须固定设备档位、网络类型、时段（同环比窗口）与人群特征（新老用户占比），任一维度失衡都会把人群差异误读成性能回归。
- 设计要点：分桶维度进上报（`bucket: gray|control` + 设备档 + 网络档），对比口径用 p75 且样本量达标（每组 > 1000 会话）才出结论；灰度前 10 分钟只观察不报警（冷启动噪声）。
- 告警逻辑：灰度组指标劣化超对照组 8% 且连续两个窗口成立才触发，单窗口波动不告警；对照组自己劣化（环境问题）时抑制灰度告警。
- 评分点：分桶维度设计与双窗口确认逻辑。

```javascript

function grayPerfMonitor(graySessions, ctrlSessions, { minSamples = 1000, threshold = 0.08 } = {}) {
  const p75 = (list) => {
    const v = list.map(s => s.lcp).sort((a, b) => a - b);
    return v[Math.floor(v.length * 0.75)] ?? null;
  };
  const stratify = (sessions) => {                       // 按设备档+网络分层
    const m = {};
    sessions.forEach(s => {
      const k = `${s.deviceTier}/${s.net}`;
      (m[k] ??= []).push(s.lcp);
    });
    return m;
  };
  const g = stratify(graySessions), c = stratify(ctrlSessions);
  const verdicts = [];
  for (const [k, gl] of Object.entries(g)) {
    const cl = c[k];
    if (!cl || gl.length < minSamples || cl.length < minSamples) continue; // 样本不足不出结论
    const delta = (p75(gl) - p75(cl)) / p75(cl);
    verdicts.push({ seg: k, delta: +(delta * 100).toFixed(1) + '%',
      alarm: delta > threshold });                        // 分层对比而非总量
  }
  return { verdicts, note: '分层对比 + 样本量门槛，避免人群结构差异误报' };
}
```
