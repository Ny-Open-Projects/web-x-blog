## PER-480：性能平台 API 的分级 SLA 与超时降级？

**答**:
- SLA 分级（按消费方）：发布对照 API（P0，2s 内响应——发布流水线在等）、告警诊断（P1，10s）、看板查询（P2，5s 可重试）、报表聚合（P3，分钟级异步）。每级超时策略不同：P0 超时返回保守 verdict（warn 并提示人工判断——不 block 发布也不盲目放行）；P3 异步化。
- 降级策略：OLAP 过载 → 查询走物化层缓存（PER-414 物化命中率的价值）；对照 API 降级 → 返回最近一次成功对照结论（标注时间戳）——发布流程不断，决策信息打折标注。
- 容量预案：发布高峰（全员同天发版）的对照查询洪峰——队列 + 优先级（核心页面 PR 优先）+ 结果缓存（同版本对短窗内复用）。
- 度量：各 SLA 达标率、降级触发次数/原因分布——SLA 不达标成为平台自身的性能工单（自举闭环）。

```text
平台 API 分级 SLA：
P0 发布对照（2s）：超时 → 保守 verdict（warn + 人工提示），不 block 不盲放
P1 告警诊断（10s）/ P2 看板查询（5s 可重试）/ P3 报表（异步分钟级）
降级：OLAP 过载 → 物化层缓存；对照降级 → 最近成功结论（标注时间戳）
容量：发布洪峰 → 队列 + 核心页优先 + 短窗结果缓存
度量：各 SLA 达标率 + 降级原因分布 → 平台自身性能工单（自举）
```
