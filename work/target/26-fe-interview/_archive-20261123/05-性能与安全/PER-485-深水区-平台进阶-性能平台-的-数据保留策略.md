## PER-485：明细/聚合/回放各自保留多久与依据？

**答**:
- 保留期决策依据（每类数据三问）：它支撑什么决策？决策窗口多长？合规要求多久？——明细（下钻用，7~14 天：两周内的问题才值得下钻，更久的靠聚合）；聚合宽表（趋势/SLO，≥ 2 年：年度对比与季节性分析）；回放（现场复现，7 天：仅超慢样本触发，PER-368）；配置与规则（永久：Git）。
- 保留期 ≠ 删光：过期明细转入冷存储（对象存储 Parquet，成本 1/10）——保留"可重算"能力（PER-455 backfill 依赖），查询走异步。
- 执行机制：TTL 策略代码化（每类数据一条 TTL 规则，进 Git 版本管理）；执行自动化（存储生命周期策略），删除留审计日志（合规要求"删除了什么/何时"可查）。
- 成本联动：保留期调整直接反映在成本看板（PER-418）——季度成本评审时按"决策价值/存储成本"重估每类 TTL。

```text
数据保留精细化：
明细 7~14d（下钻窗口）→ 过期转冷存储（Parquet 1/10 成本，保留可重算能力）
聚合 ≥ 2y（趋势/季节性）；回放 7d（超慢样本触发）；配置规则永久（Git）
依据三问：支撑什么决策 / 决策窗口多长 / 合规要多久
执行：TTL 规则代码化进 Git + 生命周期自动化 + 删除审计日志
联动：季度成本评审按"决策价值/存储成本"重估 TTL（PER-418）
```
