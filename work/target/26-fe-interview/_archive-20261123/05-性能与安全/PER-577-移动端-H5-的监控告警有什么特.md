## PER-577：移动端 H5 的监控告警有什么特殊性？哪些指标和告警逻辑必须区别于桌面端？

**答**：
- 三类特殊性：**网络切换**（WiFi/蜂窝切换导致瞬时超时尖峰，要与真实故障区分，按网络类型分层告警）、**前后台切换**（切后台再回来 LCP/计时类指标异常，visibility 生命周期要正确处理）、**WebView 差异**（不同 App 内核版本行为不同，UA 里的容器版本要进维度）。
- 告警逻辑差异：移动端错误率基线天然更高（低端机 + 弱网），阈值要按设备档分层设，不能一套全局阈值；白屏/容器崩溃是移动端特有告警项。
- 采样差异：移动端流量贵，上报 payload 要压缩（gzip + 字段短名），采样率更低但错误类保真。
- 专项指标：页面被系统杀掉的概率（页面存活时长分布）、内存告警（iOS `performance.memory` 缺失，用自建采样估算）。

```javascript

const mobileAlertPolicy = {
  layers: {   // 按设备档分层阈值，拒绝全局一刀切
    lcpP75: { low: 3500, mid: 2800, flag: 2200 },        // ms
    errorRate: { low: 0.02, mid: 0.015, flag: 0.01 },
  },
  special: {
    netSwitch: '按 netType 分层告警，切换尖峰不 page',
    lifecycle: 'visibility hidden 期间暂停计时类采集',
    webview: '容器版本(UC/X5/WKWebView)作为必备维度',
  },
  payload: { gzip: true, shortKeys: true, errSampleRate: 1.0 },
  extra: ['白屏率', '容器崩溃率', '页面存活时长 p50'],
};
console.log('移动端告警的第一原则：分层，不搞全局阈值');
```
