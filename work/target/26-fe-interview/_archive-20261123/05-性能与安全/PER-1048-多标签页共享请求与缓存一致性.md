## PER-1048：多标签页共享请求与缓存一致性

**答**：
- 场景：同 app 多标签页各自请求同一接口，浪费且可能出现数据不一致（A 页改了 B 页看不到）。
- 方案：BroadcastChannel 广播缓存失效与数据更新；Storage 事件兜底跨标签通信。
- 实现：主标签负责请求（抢锁），其他标签订阅结果；写操作后广播 invalidate 前缀。
- 一致性等级：最终一致（弱数据）vs 强一致（金额类必须服务端为准），设计时明确分级。

```javascript
const bc = new BroadcastChannel('app-cache');
function invalidate(prefix) {
  cache.invalidate(prefix);
  bc.postMessage({ type: 'invalidate', prefix });    // 广播其他标签
}
bc.onmessage = e => {
  if (e.data.type === 'invalidate') cache.invalidate(e.data.prefix);
  if (e.data.type === 'update') cache.set(e.data.key, e.data.value);
};
// 强一致数据（余额）不走前端缓存：
function mustFresh(url) { return fetch(url, { cache: 'no-store' }); }
```
