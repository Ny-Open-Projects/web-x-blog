## PER-378：多页面应用与微前端下如何保证全站性能一致性？

**答**：
- 一致性挑战：MPA 各页面独立构建，团队各自为政——A 页面 LCP 1.8s、B 页面 4.5s；微前端更甚——主子应用重复加载框架、样式与脚本互相干扰、公共依赖多份。
- 基线分发机制：**共享层统一**——框架/工具库/UI 组件库做成共享 bundle（externals + CDN 稳定版本），所有页面引用同一份（浏览器缓存全站复用）；页面只打包业务代码。构建层统一：脚手架（PER-341）+ 统一构建配置（分包策略/preload 策略/图片组件），个性化必须走白名单。
- 微前端专项：依赖共享（qiankun/wujie 的 externals 或 Module Federation 共享单例）、公共样式一次加载、子应用按需加载 + 预加载策略、主子应用之间的性能预算拆分（主应用 ≤ X、每个子应用 ≤ Y）。
- 度量与治理：全站性能大盘按页面排名（PER-343 委员会用），落后页面自动进治理清单；新页面接入基线检查（模板合规即达标）。

```text
全站一致性机制：
共享层：react/vue + ui-lib + utils → externals 稳定版本 CDN（全站一份，缓存复用率最大化）
构建层：统一脚手架模板（分包/preload/图片/字体方案内置），个性化走白名单评审
微前端：Module Federation 共享依赖单例、子应用按需 + idle 预加载、主子预算拆分
治理：全站大盘排名 → 落后页进清单 → owner 跟进；新页面模板合规即出生达标
```
