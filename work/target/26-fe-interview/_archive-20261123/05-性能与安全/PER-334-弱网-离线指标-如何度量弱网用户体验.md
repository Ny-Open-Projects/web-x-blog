## PER-334：如何度量弱网用户的真实体验？弱网切片指标与优化验收怎么定？

**答**：
- 弱网切片定义：RUM 上报带网络信号（connection API 的 effectiveType/rtt + 自建 TTFB 分位），服务端切片"slow"档用户单独看数。CrUX 无法切弱网（维度不够），这正是自建 RUM 的价值（PER-234）。
- 弱网专项指标：① 弱网 p75 LCP/INP（与全量分开验收，目标更宽松但独立追踪）；② 降级触发率（弱网用户中多少走了降级路径）；③ 弱网转化率（性能优化对弱网用户业务价值的直接体现）；④ 弱网错误率（超时/重试占比）。
- 验收方法：实验室侧用 Chrome throttling（Slow 3G + 4x CPU）跑核心路径作为回归基线；线上侧看弱网切片趋势。优化动作的验收=弱网切片指标改善且全量指标不回退。
- 常见误区：只看全量均值——弱网用户占比 15% 但贡献了大部分的 poor 样本，全量 p75 可能达标而弱网体验灾难；切完不行动——弱网报告没有对应降级策略等于白测。

```text
弱网切片看板（自建 RUM）：
切片: connection.effectiveType ∈ {slow-2g, 2g, 3g} 或 自建 TTFB p50 > 1200ms
指标:
  LCP p75 (弱网)     目标 < 5s（全量 2.5s 的弱网放宽档）
  INP p75 (弱网)     目标 < 400ms
  降级触发率         目标 > 90%（弱网就该降级）
  弱网转化率         与全量对比（性能优化业务验收）
  弱网错误率         目标 < 3%（超时重试控制）
验收：弱网切片改善 + 全量不回退，双绿才算过
```
