## PER-406：页面跳转时大对象在页面间传递的内存策略？

**答**：
- 三种传递方式与内存影响：① 序列化传递（URL/sessionStorage）——只适合小状态（筛选条件/滚动位置），大对象写 sessionStorage 会撞配额且序列化耗时；② 共享内存（ BroadcastChannel/SharedWorker/内存型 SPA 状态库）——SPA 内无拷贝但页面卸载即失；③ 重取（到新页面重新请求）——内存最省，代价是再次等待。
- 决策矩阵：数据大小 < 10KB 且是"导航参数" → URL/sessionStorage；10KB~1MB 且目标页立即可用性重要 → SW/IDB 中转（写入带 TTL，目标页读取后删除——中转不是持久存储）；> 1MB → 重新请求（服务端缓存加速，避免本地搬运大对象）；SPA 内部 → 内存状态库 + 路由离开自动清理（PER-272）。
- 内存纪律：中转数据必须带 TTL 与"消费即删"语义——堆在 sessionStorage/IDB 的中转数据是常见泄漏点；URL 传参只传 id 引用不传数据本体（幂等且可分享）。
- 验证：跳转前后的堆快照对比——源页大对象在目标页不应以"第二份拷贝"形式存在（除非必要）。

```javascript
// 大对象中转：SW/IDB 中转站，消费即删 + TTL
const transit = {
  async put(key, data, ttlMs = 60000) {
    await db.put('transit', { data, exp: Date.now() + ttlMs }, key);   // IDB 中转
  },
  async take(key) {
    const item = await db.get('transit', key);
    if (item) await db.delete('transit', key);                          // 消费即删
    return item?.exp > Date.now() ? item.data : null;                   // 过期即弃
  },
};
// 用法：列表页 put('goods-list', bigRows, 30000) → navigate('/detail')
// 详情页 take('goods-list') —— 命中则秒渲染，未命中回退重新请求
// URL 只传引用：/detail?id=88&from=list&anchor=row12 —— 不塞数据本体
```
