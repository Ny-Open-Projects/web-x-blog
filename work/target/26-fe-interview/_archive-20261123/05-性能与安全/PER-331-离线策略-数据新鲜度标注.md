## PER-331：离线时展示缓存数据，如何让用户知道"这是旧数据"？新鲜度标注与脏读防线？

**答**：
- 新鲜度链路：数据入缓存时带上"抓取时间戳 + 版本"，UI 读取时标注"缓存于 X 分钟前"；离线横幅（navigator.onLine + SW 响应头 X-From-Cache 联合判定）；关键数据（价格/库存）标注"以刷新后为准"。
- 脏读防线分级：可容忍旧数据（资讯/历史订单）→ 正常展示加标注；强时效数据（价格/库存/余票）→ 离线时置灰并禁用下单按钮，或下单时强制联网校验；用户生成内容 → 离线可编辑但明确"未同步"状态（乐观更新 + 待同步标记）。
- 恢复时收敛：onLine 恢复后自动刷新（SW network-first 会拿到新数据），标注清除；若离线期间用户做了写操作，恢复后先重放队列再刷新展示（顺序很重要，否则展示的是重放前旧态）。

```javascript
// 数据封装层：读取时计算新鲜度
async function getGoods(id) {
  const res = await fetch(`/api/goods/${id}`);
  if (res.headers.get('X-From-Cache')) {
    const cachedAt = +res.headers.get('X-Cached-At') || 0;
    const ageMin = Math.round((Date.now() - cachedAt) / 60000);
    return { data: await res.json(), stale: true, ageMin,
             buyable: ageMin < 10 };                        // 强时效：>10min 禁买
  }
  return { data: await res.json(), stale: false, buyable: true };
}
// UI：
// stale && 横幅："离线中，当前为 ${ageMin} 分钟前的数据"
// !buyable && 按钮："恢复网络后可下单"（禁用态）
// 恢复：window.addEventListener('online', () => { replayOutbox().then(refreshAll); });
```
