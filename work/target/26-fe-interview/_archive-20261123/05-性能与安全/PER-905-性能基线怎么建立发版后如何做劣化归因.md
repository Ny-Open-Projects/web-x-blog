## PER-905：性能基线怎么建立？发版后如何做劣化归因

**答**：
- 基线 = 上一稳定版本在相同分桶（页面×机型×地域）下的 P75 指标快照，随版本滚动更新。
- 发版后对比当前版本 vs 基线，差异超过阈值（如 LCP +8%）触发劣化事件而非直接告警，避免噪声。
- 归因三步：先看资源维度（新版本多了哪些 JS/CSS、图片是否变大），再看代码维度（diff 中引入的同步阻塞、大组件），最后看流量维度（新地域/新机型占比变化）。
- 归因产出物：劣化报告（指标、差异、嫌疑资源、责任人、修复单链接），挂到发版单上闭环。

```javascript
// 劣化检测核心：对比基线
const REGRESSION_RATE = 0.08;
function detect(regressions, current, baseline) {
  const out = [];
  for (const m of ['lcp', 'inp', 'ttfb']) {
    const diff = (current[m] - baseline[m]) / baseline[m];
    if (diff > REGRESSION_RATE)
      out.push({ metric: m, baseline: baseline[m], current: current[m],
                 delta: +(diff * 100).toFixed(1) + '%' });
  }
  return out;  // 平台据此生成劣化事件并 @ 版本负责人
}
// 资源归因：diff 两版本构建产物 manifest，找新增/增量前 5 的 chunk
```
