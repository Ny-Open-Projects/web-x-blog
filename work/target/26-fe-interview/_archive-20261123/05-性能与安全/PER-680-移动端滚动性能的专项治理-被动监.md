## PER-680：移动端滚动性能的专项治理：被动监听、合成层与滚动容器的常见性能坑

**答**：
- 三个高频坑：**非 passive 的 touch/wheel 监听**（阻止合成器滚动，必须等 JS 执行完才滚，改为 passive 后 JS 无法 preventDefault，要按需处理）、**滚动容器嵌套过深**（每层都建立滚动上下文，滚动重算成本高）、**滚动中触发布局**（scroll 回调里读 offsetTop 触发强制同步布局）。
- 治理清单：滚动相关监听全 passive + 回调节流（rAF 对齐）、滚动容器扁平化（最多两层）、回调里先写后读分离（批量读，批量写）、大列表虚拟化、will-change 只给正在滚动的元素（用完移除，常驻会占内存）。
- 合成层管理：过度提升合成层（大量 will-change/transform）导致层爆炸内存上涨——用 Layers 面板审计，只提升真正动的层。
- 验证方式：滚动帧率探针（679）+ DevTools Performance 录制对比治理前后。

```javascript

// 滚动治理三件套落地
function fixScrollPerf() {
  // 1) passive 化
  document.addEventListener('touchstart', onTouch, { passive: true });
  document.addEventListener('touchmove', onTouch, { passive: false }); // 需要 preventDefault 的才不 passive
  // 2) rAF 对齐节流 + 先读后写
  let ticking = false;
  function onScrollRaw() {
    if (ticking) return; ticking = true;
    requestAnimationFrame(() => {
      const y = readScrollState();                             // 批量读
      applyScrollUI(y);                                        // 批量写
      ticking = false;
    });
  }
  // 3) will-change 用完即撤
  const el = document.querySelector('.dragging-item');
  el.style.willChange = 'transform';
  el.addEventListener('transitionend', () => el.style.willChange = 'auto', { once: true });
}
```
