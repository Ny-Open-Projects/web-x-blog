## PER-794：离线包的安全设计：包体签名校验、防篡改与包加密的取舍

**答**：
- 威胁模型：离线包经下发通道落盘，被中间人替换或本地篡改后，拦截器会把恶意 JS 当本地资源返回——比在线注入更隐蔽。
- 防线一（必做）：整包聚合签名（对 manifest 内所有文件 hash 再做一次 RSA/ECDSA 签名），下载后先验签再落盘；文件级 hash 校验（拦截时逐文件）防本地篡改。
- 取舍：包加密（AES）防的是逆向分析，代价是加解密 CPU 与密钥分发复杂度；一般核心业务包加密、普通包只签名——签名防篡改是底线，加密是加分项。
- 通道：包下发走 HTTPS + 证书校验；紧急止损要有"服务端强制失效"开关（版本黑名单，客户端拉到黑名单立即弃用本地包回在线）。

```javascript
async function verifyBundle(bundleBuf, sigPubKey) {
  const manifest = JSON.parse(unzip(bundleBuf, 'manifest.json'));
  // 1. 聚合签名：对排序后的 文件名:hash 串验签
  const payload = Object.keys(manifest.files).sort()
    .map(k => `${k}:${manifest.files[k]}`).join('
');
  const ok = await crypto.subtle.verify('ECDSA-P256-SHA256', sigPubKey,
    base64ToBuf(manifest.signature), new TextEncoder().encode(payload));
  if (!ok) throw new Error('bundle-signature-invalid');      // 弃包回在线
  // 2. 逐文件 hash 校验在拦截时进行（buildUrlMap.resolve 已含）
  return manifest;
}
```
