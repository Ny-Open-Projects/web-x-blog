## PER-861：移动端页面的预加载体系：数据预取、组件预载与页面预渲染三层如何排布

**答**：
- 三层按"意图强度"排布：低意图（浏览中）→ 数据预取（prefetch 下一跳接口，只花网络）；中意图（悬停/按下）→ 组件预载（import() 组件 chunk）；高意图（明确跳转路径如 banner）→ 页面预渲染（整页后台渲染，点击即显）。
- 成本递增排布的意义：意图越低成本越低，避免"预渲染一堆没人点的页面"白耗内存与流量。
- 协同约束：三层共享预算（并发上限/内存上限），高优先级触发时挤掉低优先级排队项；预取数据要有 TTL（页面到达时已过期则重新请求）。
- 度量收益：每层分开统计命中率（预取被消费占比），命中率持续低于 20% 的预载策略应收缩。

```javascript
const preloadLayers = [
  { level: 1, trigger: 'route-registered', action: 'prefetch-data', cost: 'net' },
  { level: 2, trigger: 'pointerdown-near', action: 'import-component', cost: 'net+cpu' },
  { level: 3, trigger: 'banner-click-intent', action: 'prerender-page', cost: 'net+cpu+mem' },
];
function onIntent(trigger, ctx) {
  const layer = preloadLayers.find(l => l.trigger === trigger);
  if (!layer || !budget.tryOccupy(layer.level)) return;        // 共享预算
  if (layer.level === 1) prefetchData(ctx.nextRoute, { ttl: 10000 });
  if (layer.level === 2) import(ctx.componentPath);
  if (layer.level === 3) prerender(ctx.nextUrl);
}
// 命中反馈收缩：命中率 < 20% 连续 3 天的层自动关闭
function feedback(hitRate) {
  if (hitRate < 0.2) shrinkPreload(layer, reason: 'low-hit');
}
```
