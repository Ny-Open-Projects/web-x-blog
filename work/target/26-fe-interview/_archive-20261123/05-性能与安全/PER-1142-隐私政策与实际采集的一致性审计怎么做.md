## PER-1142：隐私政策与实际采集的"一致性审计"怎么做

**答**：
- 问题：政策写了 10 类采集、实际 SDK 采了 15 类——不一致即违规（透明性）。
- 方法：以字段注册表（1004）为唯一事实源 → 生成政策文本章节（自动渲染）→ 线上实际采集抽样比对（抓包/上报内容 diff）。
- 频率：每次 SDK 发版自动比对 + 季度人工抽查；差异项阻塞发布。
- 版本：政策文本版本号与注册表版本绑定，用户同意记录到具体版本。

```javascript
// 注册表 -> 政策文本一致性
function policyConsistency(registry, policyText) {
  const required = new Set(Object.keys(registry)
    .filter(k => registry[k].disclose !== false));
  const missing = [...required].filter(f => !policyText.includes(f));
  const extra = (policyText.match(/采集字段：([\w_]+)/g) ?? [])
    .map(m => m.split('：')[1]).filter(f => !registry[f]);
  return { missing, extra,
    pass: missing.length === 0 && extra.length === 0,
    action: missing.length ? '政策需补充' : extra.length ? '注册表缺登记' : '一致' };
}
```
