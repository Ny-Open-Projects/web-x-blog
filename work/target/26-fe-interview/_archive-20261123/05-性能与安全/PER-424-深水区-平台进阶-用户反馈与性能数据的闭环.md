## PER-424："感觉卡"的用户反馈如何定位到具体指标与交互？

**答**:
- 主观反馈的定位难点："卡"可能是加载慢（LCP）、交互慢（INP）、滚动掉帧（长帧）、动画卡（合成）——用户的"卡"需要翻译成指标。闭环设计让反馈自带上下文。
- 反馈组件设计：应用内"报告问题"入口采集——用户勾选卡顿场景（加载慢/点击慢/滚动卡/其他）+ 自动附上当前上下文（页面/会话 sid/设备档位/最近 30s 的 LoAF 与长任务摘要）。用户一句话 + 系统自动上下文 = 可定位的工单。
- 数据侧反查：反馈会话的 sid 关联 RUM 明细——该会话的实际指标（哪些交互慢、哪些资源拖后）直接给修复 owner；同时反馈聚合成"主观卡顿热力图"（页面 × 场景 × 频次），与客观数据交叉验证（PER-394）。
- 价值闭环：主观反馈发现"客观数据没覆盖的痛点"（如动画不流畅不在 CWV 口径里）→ 反向驱动指标体系补充（自定义指标）；修复后回访用户验证（反馈 → 修复 → 确认闭环率）。

```javascript
// 问题反馈组件：一句话 + 自动上下文
async function reportProblem(userChoice) {
  const ctx = {
    page: routeTemplate(location.pathname), sid: sessionSid,
    deviceTier: deviceMemory <= 4 ? 'low' : 'high',
    recentLoAF: await getRecentLoAFSummary(30000),      // 最近 30s 慢帧摘要
    recentLongTasks: longTaskCounter.last30s,
  };
  await telemetry.push('feedback', { choice: userChoice, ...ctx });   // 带上下文进管道
}
// 工单侧：sid 反查 RUM 明细 → 该会话实际 INP/LoAF → 直接定位慢函数
// 聚合：反馈热力图（页面×场景×频次）× 客观数据交叉 → 发现 CWV 未覆盖的痛点（如动画卡）
// 闭环率：反馈→修复→用户确认 的比例进平台健康度
```
