## PER-1238：如何设计"性能优化的可回滚性"（每个优化都能安全撤回）

**答**：
- 原则：优化项必须带开关（feature flag），出问题 30s 内切回。
- 清单化：每项优化登记（开关 ID/回滚步骤/风险面），发布单附回滚预案。
- 灰度验证：优化按 5%→50%→100% 灰度，每级观察核心指标 24h。
- 反例：硬编码优化（构建期内联）需走完整发版才能回滚——高风险项禁止。

```javascript
// 优化开关登记
const OPTS = {
  'img-avif': { flag: 'opt-img-avif', rollback: '切回 webp，30s 生效',
    risk: '低端机解码慢' },
  'route-split': { flag: 'opt-route-split', rollback: '关闭按需加载，回全量包',
    risk: '首屏体积增大' },
};
function optToggle(id, on) {
  const o = OPTS[id];
  flags.set(o.flag, on);
  report({ type: 'opt-toggle', id, on, rollback: o.rollback });
}
// 灰度：
function canary(id, pct) { return hash(uid) % 100 < pct; }
```
