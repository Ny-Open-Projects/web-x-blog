## PER-393：每次发布都做性能基线对照的自动化流程？

**答**:
- 流程四步：① 发布前采集基线——CI 对上一版本构建跑实验室基准（固定环境/固定交互脚本），记录 LCP/TBT/体积/请求数入库；② 发布构建的对照——新版本构建跑同一基准，diff 生成"性能变更清单"（哪个 chunk 涨了多少、哪个页面 TBT 变化多少），超预算项标红并阻断或要求豁免；③ 发布后灰度对照——RUM 新旧版本同口径对比（PER-249 bootstrap），2 小时自动产出结论；④ 结论归档——对照结果写进发布记录（版本 → 性能变更 → 线上验证），形成版本性能档案。
- 自动化载体：CI job（实验室部分）+ 定时任务（RUM 对照部分）+ 发布平台 webhook 串联；人工只处理"标红项"的豁免评审。
- 对照的口径纪律：实验室环境固定（浏览器版本/设备档位升级要重跑全量基线）；RUM 对照同页面模板 × 同设备切片；节假日流量异常期对照自动跳过（防误判）。

```text
发布性能基线对照流水线：
PR:  构建 → 实验室基准 → diff 上一版本 → 预算内放行 / 超预算标红（豁免需评审）
发布: 灰度 5% → RUM 新旧版本 bootstrap 对比（2h）→ 显著恶化自动回滚评审
归档: 版本档案 { v3.2.1: LCP +0.1s, vendor +120KB, RUM 验证 PASS }
人工介入点：仅标红项的豁免评审与回滚决策；其余全自动
口径纪律：实验室环境升级 = 重跑全量基线；节假日自动跳过 RUM 对照
```
