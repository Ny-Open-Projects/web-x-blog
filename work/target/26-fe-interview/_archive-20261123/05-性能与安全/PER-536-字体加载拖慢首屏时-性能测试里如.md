## PER-536：字体加载拖慢首屏时，性能测试里如何把字体影响单独隔离出来量化？

**答**：
- 隔离思路是对照实验：同一页面跑两遍，一遍禁用 webfont（只留系统字体）、一遍正常加载，LCP/FCP 的差值就是字体贡献的成本；差值超过 300ms 就该上 `font-display: swap` 与子集化。
- 字体影响路径有三条：阻塞期（`font-display: block` 期间文字不可见，LCP 候选若是文字则被推迟）、交换抖动（swap 后 FOUT 引发 CLS 与 LCP 元素切换）、下载体积本身（WOFF2 全量 vs 子集）。
- 测量细节：LCP 候选可能因字体晚到从图片切换成大标题，要看 LCP entry 的 `element` 字段是否变了，不只看时间。
- 结论落地形式：给设计/业务一个可感知的数字——"这个 380KB 的品牌字体让 75% 用户的首屏慢 400ms"，用数据驱动字体方案决策。

```javascript

async function isolateFontCost(page, url) {
  const run = async (blockFonts) => {
    await page.setRequestInterception(true);
    page.on('request', req => {
      if (blockFonts && req.resourceType() === 'font') req.abort();  // 隔离变量
      else req.continue();
    });
    await page.goto(url, { waitUntil: 'load' });
    return page.evaluate(() => new Promise(res => {
      let lcp = 0, el = '';
      new PerformanceObserver(l => {
        const e = l.getEntries().at(-1);
        lcp = e.startTime; el = e.element?.tagName ?? '';
      }).observe({ type: 'largest-contentful-paint', buffered: true });
      setTimeout(() => res({ lcp, el }), 5000);
    }));
  };
  const withFont = await run(false), noFont = await run(true);
  return {
    fontCost: +(withFont.lcp - noFont.lcp).toFixed(0),   // 字体贡献的首屏成本(ms)
    lcpElementChanged: withFont.el !== noFont.el,        // LCP 候选是否被字体切换
  };
}
// fontCost > 300ms -> 立项做字体子集化 + font-display 调整
```
