## PER-926：性能指标口径变更如何管理？防止历史数据断裂

**答**：
- 口径变更三原则：双写过渡（新旧口径并行采集 ≥ 2 周）、断点标注（看板在切换点画虚线并注明）、迁移文档（定义差异、影响面、换算关系）。
- 版本字段：每条性能记录带 metricSchema 版本号，聚合查询按版本分组，禁止跨版本直接对比。
- 常见触发点：浏览器指标定义更新（如 FID→INP）、采集 SDK 大版本升级、业务改版导致页面含义变化。
- 治理动作：口径变更需要评审 + 通知订阅方，平台维护口径变更日志。

```javascript
// 双写与版本化
let SCHEMA_V = 2;                    // 当前口径版本
function record(m) {
  const v1 = v1Compat(m);            // 旧口径换算
  send({ v: SCHEMA_V, ...m });
  if (TRANSITION) send({ v: 1, ...v1 });   // 过渡期双写
}
// 查询侧：SELECT ... WHERE v = ?，看板切换点画断点标注
```
