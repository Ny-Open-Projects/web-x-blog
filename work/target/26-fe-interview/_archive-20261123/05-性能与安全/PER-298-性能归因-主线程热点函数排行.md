## PER-298：如何建立"主线程热点函数排行榜"？Self Time 与 Total Time 怎么用才不误判？

**答**：
- 两个口径：Self Time（函数自身执行，不含子调用）找"真正烧 CPU 的实现"；Total Time（含子调用）找"该不该被调用的调用链入口"。误判典型：一个 forEach 包装函数 Self Time 很低但被调用百万次——看 Total 排行才能发现；反过来递归函数 Self 高不代表该优化它（可能是被无脑调了 N 次）。
- 采样而非插桩：CPU profiler（Chrome DevTools / node --prof / Perfetto）用采样栈，开销低接近真实；插桩（console.time 到处打）会改变执行时序与优化决策，只做局部精确测量。
- 自动化排行：CI 里跑固定交互脚本 + 采样 profiler，输出函数级 Self Time Top 20 与版本 diff（比上次构建哪些函数变热了）；线上用 LoAF 的 invoker 维度做"脚本级"排行（函数级线上开采样器成本高，仅诊断期开启）。
- 误判防护：排除 GC 与浏览器内部帧；预热后采样（排除 JIT 暖机）；关注分布（p50 vs p95 的热点可能不同）。

```javascript
// CI 热点排行：Node 侧用 inspector 采样，浏览器侧用 CDP Profiler
import inspector from 'node:inspector';
const session = new inspector.Session();
session.connect();
session.post('Profiler.enable');
session.post('Profiler.setSamplingInterval', { interval: 1000 }); // 1ms 采样
session.post('Profiler.start');
await runInteractionScript();                       // 固定操作序列
session.post('Profiler.stop', (err, { profile }) => {
  const self = new Map();
  for (const node of Object.values(profile.nodes)) {
    const d = node.callFrame;
    const key = `${d.functionName || '(anon)'} @ ${d.url.split('/').pop()}:${d.lineNumber}`;
    const t = (profile.timeDeltas[node.hitCount] ?? 0) / 1000;
    self.set(key, (self.get(key) || 0) + node.hitCount);  // hitCount ≈ Self Time
  }
  console.log([...self.entries()].sort((a, b) => b[1] - a[1]).slice(0, 20)); // Top20
});
```
