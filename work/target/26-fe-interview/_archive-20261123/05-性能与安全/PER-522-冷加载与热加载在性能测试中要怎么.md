## PER-522：冷加载与热加载在性能测试中要怎么分开测？混合测量会得出什么错误结论？

**答**：
- 冷加载 = 空缓存首访（新用户/换设备），热加载 = 有缓存回访（老用户二跳），两者瓶颈不同：冷加载瓶颈在资源体积与 RTT，热加载瓶颈在 JS 执行与接口，混测会互相稀释。
- 典型错误结论：加了 Service Worker 后"平均加载时间没变"就认为优化无效——实际上冷载不变、热载大幅变快，平均被流量比例冲掉了；必须分桶对比。
- 测法：冷载用每次清缓存（CDP `Network.setCacheDisabled` + 新 incognito profile）；热载用同一 profile 二次访问并断言 disk cache 命中（看 resource 的 transferSize 为 0）。
- 报告必须分桶：同一指标给冷/热两列，回访率高的站点优化重心在热载路径。

```javascript

const puppeteer = require('puppeteer');
async function measure(url, { cold }) {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();
  if (cold) {
    const cdp = await page.createCDPSession();
    await cdp.send('Network.setCacheDisabled', { cacheDisabled: true });      // 冷载：禁缓存
    await cdp.send('Network.clearBrowserCache');
  } else {
    await page.goto(url, { waitUntil: 'load' });                              // 热载：先预热一次
  }
  await page.goto(url, { waitUntil: 'load' });
  const res = await page.evaluate(() => {
    const entries = performance.getEntriesByType('resource');
    const cached = entries.filter(e => e.transferSize === 0).length;           // 命中缓存的资源数
    const [nav] = performance.getEntriesByType('navigation');
    return { cached, load: nav.loadEventEnd };
  });
  await browser.close();
  return res;
}
(async () => { // 分桶报告，绝不做冷热混合平均
  console.log('cold:', await measure('https://example.com', { cold: true }));
  console.log('warm:', await measure('https://example.com', { cold: false }));
})();
```
