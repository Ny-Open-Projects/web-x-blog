## PER-921：性能平台和错误监控、埋点平台如何协同而不是各建一套

**答**：
- 统一底座：共享同一采集 SDK 骨架、上报通道、用户标识与会话模型，避免三套 SDK 重复消耗与口径冲突。
- 数据打通：性能记录与错误记录共享 traceId/会话 ID，错误激增时能直接看对应时段性能曲线（错误多伴随 INP 劣化）。
- 组织协同：统一数据字典评审，任何新增指标走平台注册，防止同名不同义。
- 成本收益：合并后 SDK 体积下降、上报合并，是新项目接入的最大卖点。

```javascript
// 会话与 traceId 打通
function makeSession() {
  const sid = crypto.randomUUID();
  const ctx = { sid, traceId: null };
  return {
    withTrace(t) { ctx.traceId = t; },           // 请求层注入
    report(type, data) {                          // 统一出口
      navigator.sendBeacon('/collect',
        JSON.stringify({ type, ...data, sid: ctx.sid, trace: ctx.traceId }));
    },
  };
}
// 性能/错误/埋点共用 report()，后端按 type 分表但同会话可关联
```
