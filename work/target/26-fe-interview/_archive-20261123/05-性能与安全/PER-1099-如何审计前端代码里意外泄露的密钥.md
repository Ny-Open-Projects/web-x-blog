## PER-1099：如何审计"前端代码里意外泄露的密钥"

**答**：
- 来源：源码硬编码（API key/第三方 SDK key）、构建环境变量误注入、sourcemap 残留。
- 扫描：构建产物正则规则（AKIA/key=xxx/secret）+ gitleaks 类工具进 CI；三方 SDK key 属公开密钥需在服务端配置来源域名白名单。
- 治理：发现即轮换密钥（不能只删代码，密钥已视为泄露）；服务端补充 referer/域名白名单兜底。
- 预防：密钥分级（公开/私有），私钥永远只在服务端；pre-commit 扫描。

```javascript
// 产物密钥扫描
const PATTERNS = [
  /AKIA[0-9A-Z]{16}/,                                // AWS
  /AIza[0-9A-Za-z_-]{35}/,                           // Google
  /sk-[A-Za-z0-9]{20,}/,                             // OpenAI 风格
  /(secret|private_key|passwd)\s*[:=]\s*['"][^'"]{8,}/i,
];
function scanSecrets(bundleSrc) {
  return PATTERNS.flatMap(p => [...bundleSrc.matchAll(p)].map(m =>
    ({ found: m[0].slice(0, 12) + '...', action: '轮换密钥 + 删除源码' })));
}
// 三方公开 key：确认其控制台已绑定域名白名单再标记为豁免
```
