## PER-436：复杂文字整形（阿拉伯语/泰语/Emoji）对渲染管线的影响？

**答**:
- 整形成本差异：拉丁文每个字形独立映射（整形快）；阿拉伯语连写整形（字形随上下文变化）、泰语组合元音、Emoji 连簇（ZWJ 序列）需要复杂的 shaping——同一段文字在 CJK/阿拉伯语下 Layout 耗时可差 2~5 倍。多语言长文本页面的 Layout 块明显更胖。
- 放大场景：长列表每行都是 RTL 阿拉伯语 → 滚动时 Layout 成本暴涨；动态文本（聊天）高频插入 → 每条消息整形。
- 优化手段：① 长文本分块渲染（整形按块缓存，浏览器按段落整形——避免整段一个 DOM 节点反复整形）；② 列表行固定尺寸契约（行高固定，整形不影响布局高度，Layout 只发生在插入点附近）；③ Emoji 密集内容（聊天）用 text-overflow 截断 + 展开查看；④ 字体子集按语言分包（不加载无关整形表）。
- 度量：分语言的 Layout 耗时对比（Performance 面板 Layout 块），RTL/CJK 页面单独做渲染预算。

```text
整形成本与应对：
拉丁 1x / CJK ~1.5x / 阿拉伯连写 ~2-3x / Emoji ZWJ 簇 ~3-5x
手段：
  长文本分块 DOM（段落级整形缓存）
  列表行高固定契约（Layout 局部化）
  Emoji 密集内容截断 + 展开
  字体子集按语言分包
度量：分语言 Layout 耗时对比；RTL 页面单独渲染预算
```
