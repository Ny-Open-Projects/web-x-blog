## PER-288：防抖、节流、scheduler.yield、Web Worker 四种手段分别在什么场景下用？

**答**：
- 防抖（debounce）：**合并高频事件到最后一刻**——搜索输入、resize 重算。语义是"用户停下来才做"，会牺牲即时性；不适合需要即时反馈的场景。
- 节流（throttle）：**限频不合并**——scroll 监听、拖拽跟随、打点上报。语义是"最多每 N ms 一次"，保证周期性执行，配合 rAF 用（每帧一次）效果最好。
- scheduler.yield：**同一任务内部切片让出**——大计算/大渲染必须马上开始但可以分段。语义是"我在做，但给你插队机会"，不减少总工作量。
- Web Worker：**整块计算移出主线程**——排序、解析、编解码、复杂规则引擎。语义是"这事不归主线程管"，主线程零占用，但有通信成本与无法访问 DOM 的限制。
- 组合使用很常见：输入防抖 300ms → 触发搜索（网络异步）→ 结果大计算进 worker → 渲染切片 yield。选错手段是常见错误：给输入加节流会伤体验，给纯计算加防抖只是延后卡顿。

```javascript
// 组合示例：IM 场景的输入与计算分工
input.addEventListener('input', debounce(async (e) => {      // 防抖：合并输入
  const draft = e.target.value;
  const tokens = await tokenizeInWorker(draft);               // Worker：分词计算
  renderSuggestions(tokens);                                   // 渲染由框架调度
}, 300));
scrollEl.addEventListener('scroll', throttleRaf(() => {       // rAF 节流：每帧一次
  updateScrollShadow();
}, { passive: true }));
// 大首屏数据解析：await scheduler.yield() 切片 + Worker 解析，二者按数据量选择
```
