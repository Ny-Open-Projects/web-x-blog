## PER-468：签名体系的密钥轮换与多密钥共存期平滑切换？

**答**:
- 场景：前端参与的请求签名（防重放/防篡改）密钥要定期轮换——直接换 = 旧客户端签名全部失败。平滑方案：签名带 keyId，服务端按 keyId 查验，新旧密钥共存窗口期。
- 轮换流程：① 配置中心下发新公钥 + keyId（PER-423）；② 客户端用最新密钥签名并带 keyId；③ 服务端双密钥验证窗口（阶段 1 双验证 → 阶段 2 旧 keyId 拒签逼升级 → 阶段 3 旧密钥下线）；④ 客户端密钥缺失降级——拉取重试一次，失败提示刷新。
- 前端要点：密钥派生在 Worker（PER-362）；keyId 与签名关联（X-Key-Id）；签名带时间戳 ± 60s 窗口（设备时钟偏移是常态）。
- 性能注意：签名在请求路径上——WebCrypto Ed25519 微秒级可接受；纯 JS RSA 会明显慢（优先 WebCrypto 原生实现）。

```text
密钥轮换 keyId 机制：
签名头：X-Key-Id + 签名 + 时间戳（± 60s 时钟容忍）
服务端窗口：阶段1 双验证 → 阶段2 旧 keyId 拒签 → 阶段3 下线
客户端：配置中心拉新公钥（PER-423）+ Worker 派生（PER-362）+ 失败重拉一次
性能：WebCrypto 原生优先（Ed25519 µs 级）；纯 JS RSA 慢——别自己实现密码学
```
