## PER-545：性能测试结果如何向业务方汇报？怎么把 LCP 200ms 的改善翻译成业务语言？

**答**：
- 业务方不关心指标名，关心三件事：**多少用户受益**（受影响 PV/UV 占比）、**收益多大**（转化率/留存与性能的弹性系数）、**花了多少**（人力与风险）。
- 翻译链路：LCP p75 从 3.2s 降到 3.0s -> 覆盖 68% 的移动端会话 -> 依据历史性能实验（每快 100ms 转化 +0.1%）估算下单转化 +0.2% -> 折算 GMV 增量区间（给区间不给单点，诚实标注置信度）。
- 汇报结构建议：一页纸——结论（达标/未达标）、业务收益区间、风险项、下一步；原始数据放附录，别让业务方读瀑布图。
- 追问钩子：如果拿不出性能-转化弹性系数怎么办？——先做一次小流量性能实验（延迟注入）建立弹性，再谈收益，这比拍数字可信。

```javascript

function bizTranslate(before, after, model) {
  const delta = before.lcpP75 - after.lcpP75;              // 改善毫秒数
  const affected = after.affectedSessions / after.totalSessions;
  const convGain = delta / 100 * model.convPer100ms;       // 弹性系数来自历史实验
  const gmvLow = convGain * model.gmvPerConv * (1 - model.ci),   // 置信区间下限
        gmvHigh = convGain * model.gmvPerConv * (1 + model.ci);
  return `首屏快 ${Math.round(delta)}ms，覆盖 ${(affected * 100).toFixed(0)}% 会话，` +
         `预计转化 +${(convGain * 100).toFixed(2)}%，GMV 日增量区间 [${Math.round(gmvLow)}, ${Math.round(gmvHigh)}] 元（80% 置信）`;
}
bizTranslate({ lcpP75: 3200 }, { lcpP75: 3000, affectedSessions: 6800, totalSessions: 10000 },
  { convPer100ms: 0.001, gmvPerConv: 150, ci: 0.2 });
```
