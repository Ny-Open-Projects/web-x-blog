## PER-408：长列表数据的分页内存模型：客户端囤积 vs 窗口滑动？

**答**:
- 两种模型：① 囤积式（append-only）——所有已加载页留在内存，实现简单，长会话内存线性增长（1 万条 × 2KB = 20MB 尚可，聊天记录百万条则爆炸）；② 窗口滑动式（只保留可视区 ± N 页）——内存恒定，代价是滚动方向的重新拉取（需要滚动位置预测与双向加载）。
- 折中模型（工程主流）：**锚点窗口**——以当前可视页为中心保留 K 页（如前后各 3 页），离开窗口的数据序列化为轻量引用（id + 摘要）保留可回溯性，回到窗口时按需重取（服务端按 id 范围/offset 批量返回）。聊天场景配合"消息索引表"（id→服务端位置）实现精确回跳。
- 决策因素：单条数据大小（> 5KB 倾向窗口式）、数据可变性（可变数据囤积会陈旧，窗口式天然拿新）、回跳概率（高频回跳 → 保留轻量引用）。
- 配套：窗口滑动必须配合虚拟列表（PER-068）与滚动锚定（PER-397），否则内存省了体验崩了。

```javascript
class WindowedList {
  constructor({ pageSize = 50, keep = 3, fetchPage }) { Object.assign(this, { pageSize, keep, fetchPage });
    this.pages = new Map();                       // pageIndex -> rows
    this.refs = new Map();                        // 离窗页的轻量引用：pageIndex -> {count, firstId}
  }
  async ensure(pageIndex) {
    if (this.pages.has(pageIndex)) return this.pages.get(pageIndex);
    const rows = await this.fetchPage(pageIndex);
    this.pages.set(pageIndex, rows);
    this.#trim(pageIndex);                        // 以当前页为中心保留 keep 页
    return rows;
  }
  #trim(center) {
    for (const [idx] of this.pages) {
      if (Math.abs(idx - center) > this.keep) {
        this.refs.set(idx, { count: this.pages.get(idx).length, firstId: this.pages.get(idx)[0]?.id });
        this.pages.delete(idx);                   // 离窗页：数据释放，引用保留（可回跳）
      }
    }
  }
  size() { return [...this.pages.values()].reduce((s, p) => s + p.length, 0); }   // 内存占用恒定 ≤ (2k+1)×pageSize
}
```
