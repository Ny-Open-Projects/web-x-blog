## PER-487：CSP report 的误报治理：爬虫/插件/劫持噪音过滤？

**答**:
- 噪音源识别：① 爬虫——headless 浏览器访问产生的违规（UA 特征 + 无会话 + 高频同 pattern）；② 浏览器插件——用户装的插件注入脚本被 CSP 拦（source-file 是 chrome-extension:// 或 about:，且与用户域无关）；③ 网络劫持——运营商注入的脚本被 CSP 拦（这其实是 CSP 立功，但要区分"我们的策略挡了好事"还是"真劫持"）；④ 自家配置错误——策略太严挡了自家资源（最高优先修复）。
- 过滤管道：采集端按"来源域类别"分桶（self / trusted-third-party / unknown / extension）→ unknown 类聚合观察（不告警不拦截判断）→ 频次突变的 unknown 域进入人工研判（可能是新攻击面）。
- 治理度量：误报率（非真实威胁/全部违规）、研判响应时长；自家配置错误类必须 24h 修复（影响的是自己的用户）。

```text
CSP report 噪音过滤：
分桶：self(自家误配，24h 必修) / trusted(三方白名单内) / unknown(聚合观察) / extension(插件噪音，丢弃)
unknown 治理：不立即告警；频次突变 → 人工研判（新攻击面 or 劫持——CSP 立功）
爬虫：UA 特征 + 无会话高频 → 过滤桶
度量：误报率 / 研判时长；自家误配优先级最高（影响自己用户）
```
