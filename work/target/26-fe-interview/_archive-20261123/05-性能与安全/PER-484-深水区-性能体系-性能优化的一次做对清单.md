## PER-484：新页面从设计到上线的性能完整性检查清单？

**答**:
- 按阶段分布的检查（事后补 = 3 倍成本）：① 设计阶段——布局尺寸契约（图片比例/卡片高度）、动效方案合成器路径评估（PER-347）、数据量级上限约定（PER-443）；② 开发阶段——组件选择（虚拟列表/图片组件强制）、数据链路（并行化/缓存）、三方接入（统一加载器）；③ 提测阶段——性能自测清单（LHCI 本地跑 + DevTools 弱网过一遍）；④ 上线阶段——灰度 RUM 观察（PER-393 基线对照）+ 回滚预案。
- 清单的使用形态：不是"人肉记"而是工具化——脚手架生成新页面时自动创建 checklist issue，各项带自动化检测（能自动的自动判，不能自动的人工勾选）。
- 度量：清单漏项率（上线后才发现的问题追溯到漏检的项）——驱动清单迭代与自动化覆盖率提升（自动化检测占比 > 70% 为目标）。

```text
"一次做对"清单（按阶段，工具化 issue 跟踪）：
设计：布局尺寸契约 / 动效合成器评估 / 数据量级上限（PER-443/347）
开发：组件强制（虚拟列表/图片）/ 数据链路（并行+缓存）/ 三方统一加载器
提测：LHCI 本地 + DevTools 弱网手测（PER-431 档位）
上线：灰度基线对照（PER-393）+ 回滚预案（PER-248）
度量：漏项率追溯 → 清单迭代 + 自动化占比 > 70%（能自动的不靠人）
原则：事后补 = 3 倍成本 —— 检查前移到设计与开发阶段
```
