## PER-865：混合栈页面切换的性能优化：Native 与 H5 互切的动画、数据预载与栈管理

**答**：
- 混合栈（Native 页与 H5 页混排）切换开销：Native→H5 要创建/复用 WebView（容器段 100~300ms）；H5→Native 要销毁或隐藏 WebView；动画与加载并行是体验关键（切换动画期间后台加载）。
- 优化手段：① WebView 池复用（免创建）；② 切换动画期间并行预热（native 侧提前 loadUrl）；③ 数据预载（H5 数据由 Native 侧转发或页面预取）；④ 栈管理：H5 页面后退用 history.back 而不是关闭容器（免重建）。
- 栈深治理：页面栈过深（>10 层）内存告急，低端机限制栈深并对非活跃 WebView 释放渲染（保留状态快照）。
- 度量：切换分段耗时（容器准备/加载/动画）与切换动画掉帧率，掉帧说明动画与加载抢主线程。

```javascript
const hybridNav = {
  async pushH5(url) {
    const w = pool.acquire() ?? createWebView();               // 池优先
    w.preload(url);                                            // 动画期间并行加载
    await playPushAnimation();                                 // 动画不等待加载完成
    await w.ready({ timeout: 3000 });                          // 超时降级占位
  },
  popH5() { history.length > 1 ? history.back() : pool.release(current); },
  checkStackDepth(depth, tier) {                               // 栈深治理
    if (depth > 10 && tier === 'low') releaseInactive();        // 低端机释放非活跃
    report('stack-depth', { depth, tier });
  },
};
```
