## PER-814：秒开的全链路分段归因：点击、容器、白屏、首屏各段的采集口径与归因方法

**答**：
- 分段定义：① 点击→容器就绪（App 侧路由调度，桥建连）；② 容器→白屏消失（HTML/JS 加载执行，前端可控）；③ 白屏→首屏内容（数据请求+渲染，业务最重的段）；④ 首屏→可交互（事件绑定完成）。
- 采集口径：必须统一时间戳来源（容器 native 时间戳 vs 页面 performance.now 存在偏移），跨端上报时做时钟对齐或以页面时间为准加偏移量字段。
- 归因方法：先看分布（p75 各段占比），超预算段再下钻（段内子埋点）；不能只看均值——移动端长尾用户决定大盘体验。
- 组织约定：每段有 Owner（容器段归 App 团队、加载段归前端、数据段归后端+前端），告警按段路由。

```javascript
// 分段上报与归因
const segments = [
  { name: 'click->container', owner: 'app-team', budget: 150 },
  { name: 'container->blank-gone', owner: 'fe', budget: 500 },
  { name: 'blank->first-screen', owner: 'fe+be', budget: 800 },
  { name: 'first-screen->ready', owner: 'fe', budget: 200 },
];
function attributeSegs(report) {              // report: 分段 p75 数据
  const seg = segments.map(s => ({ ...s, actual: report[s.name]?.p75 ?? null,
    status: (report[s.name]?.p75 ?? Infinity) > s.budget ? 'over' : 'ok' }));
  const worst = seg.filter(s => s.status === 'over')
    .sort((a, b) => b.actual - b.budget - (a.actual - a.budget))[0];
  return { seg, action: worst ? `下钻 ${worst.name}（owner: ${worst.owner}），超预算 ${worst.actual - worst.budget}ms` : '全段达标' };
}
```
