## PER-422：发布平台与性能平台的联动自动化：放行/回滚决策如何自动做出？

**答**:
- 联动协议：发布平台在灰度放量后调用性能平台的"对照 API"（版本对 × 页面 × bootstrap 显著性），性能平台返回结构化结论：{ verdict: 'pass' | 'warn' | 'block', evidence }；发布平台按 verdict 自动执行——pass 放量下一档、warn 保持观察、block 自动回滚并通知。
- 对照 API 的口径约束：灰度组与对照组同页面模板 × 同设备切片；样本下限（每分组 ≥ 200 会话）；等待窗口（放量后 2h 才出结论，避免预热抖动）；节假日自动降级为 warn-only（流量结构异常期不做自动 block）。
- 安全护栏：自动 block 只对"核心页面 + 显著恶化 + 双通道确认（实验室 + RUM）"触发；block 后自动生成诊断包（PER-390）附到回滚通知；自动决策全部留档可追溯（决策日志：输入快照 + 规则版本）。
- 误伤治理：自动回滚的误伤率监控（回滚后人工确认是误伤的比例）> 10% 时收紧规则；规则变更走评审（与告警规则同仓库）。

```text
发布平台 ↔ 性能平台联动协议：
灰度放量 → 调用对照 API（版本对×页面×bootstrap）
返回：{ verdict: pass|warn|block, evidence }
  pass → 自动放量下一档
  warn → 保持观察（人工确认）
  block → 自动回滚 + 诊断包（PER-390）+ 通知
口径约束：同模板×同设备切片；样本 ≥ 200/组；放量后 2h 出结论；节假日 warn-only
护栏：block 需核心页 + 显著恶化 + 双通道确认；决策日志留档（输入快照+规则版本）
误伤率 > 10% → 收紧规则（规则变更走评审）
```
