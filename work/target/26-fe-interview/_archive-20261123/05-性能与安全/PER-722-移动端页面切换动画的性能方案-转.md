## PER-722：移动端页面切换动画的性能方案：转场动画怎么与页面加载并行而不掉帧？

**答**：
- 原则：转场动画（合成器层：transform/opacity）与页面加载（主线程：JS 执行/请求）**必须并行**——动画在合成器跑，新页面数据在主线程加载，互不阻塞；阻塞主线程的初始化要延到转场结束后。
- 实现分工：容器/框架负责转场（Native 转场 or CSS transition），新页面 mount 拆两段——同步最小骨架（< 16ms）+ 异步内容填充（数据回来后渲染）；骨架期间旧页面已隐藏但未销毁（返回快）。
- 冲突点治理：转场期间禁止新页面触发大 layout（先 visibility 占位）；图片解码延到转场后（同步解码 45MB 位图会冻结转场）；转场结束时机用 transitionend 而不是定时器猜测。
- 度量：转场掉帧（rAF gap）与转场后首帧间隔分开统计——转场顺滑但内容白屏 2s 和转场卡顿是两种不同的问题。

```javascript

const transitionParallel = {
  principle: '转场动画走合成器层与页面加载并行：transform/opacity 动画不占主线程预算',
  mount: { sync: '同步最小骨架 < 16ms', async: '数据回来后内容填充' },
  guards: ['转场期禁大 layout（visibility 占位）', '图片解码延到转场后',
    '旧页隐藏不销毁（返回快）', 'transitionend 定终点不用定时器'],
  metrics: { slideJank: 'rAF gap 掉帧', contentGap: '转场结束->首屏内容间隔' },
};
function onEnterTransition() {
  const el = newPageEl;
  el.style.visibility = 'hidden';                               // 占位防大 layout
  el.classList.add('slide-in');                                 // 合成器转场
  el.addEventListener('transitionend', () => {
    el.style.visibility = 'visible';
    requestIdleCallback(() => decodeHeavyImages(el));           // 解码延后
  }, { once: true });
}
```
