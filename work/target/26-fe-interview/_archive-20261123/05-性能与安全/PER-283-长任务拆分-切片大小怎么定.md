## PER-283：拆长任务时切片大小怎么定？切太碎或太粗各有什么代价？

**答**：
- 目标区间：单切片 20~50ms。50ms 是长任务红线，留出事件处理与渲染余量；20ms 下限防止切片成本（调度、上下文切换、闭包状态）占比过高。
- 切太碎（<5ms）的代价：调度开销占大头（yield 本身要一次宏任务循环）、总耗时反而上升、yield 频繁让出给了其他任务插队机会，结果"更卡"。
- 切太粗（>100ms）的代价：等于没拆——单切片本身是长任务，input delay 照旧；用户输入还是在切片内排队。
- 实操：按"每片处理 N 个元素"定片，N 由实测调整（如 1000 行过滤按 200 行一片）；配合时间预算 API（每片结束检查剩余时间），比固定 N 更稳。切片间用 yield 保持优先级。

```javascript
// 时间预算式切片：自适应大小，比固定 N 更稳
async function processAll(items) {
  let i = 0;
  while (i < items.length) {
    const start = performance.now();
    do {
      step(items[i++]);
    } while (i < items.length && performance.now() - start < 30);  // 单片预算 30ms
    await scheduler.yield();                                        // 让出（保优先级）
  }
}
// 自适应效果：快机器单片处理更多元素，慢机器自动少处理——两端都落在预算内
```
