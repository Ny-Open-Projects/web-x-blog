## AV-236：直播连麦混流：服务端合流架构

**答**：
- 连麦混流：两路（或 N 路）流在服务端合成一路（画面布局+音频混音）→ 推 CDN 供观众看——观众端只需拉一路。
- 方案：SFU + ffmpeg/gstreamer 合流（转码 CPU 成本）；或 SFU 直接多流转发（观众端自己合成布局——省服务端但客户端复杂）。
- 前端关注：混流布局指令（服务端 layout API）、混流延迟（+200~500ms）。

```javascript
const mixingArchitectures = {
  serverMix: { desc: 'SFU 转发 + ffmpeg 合流 → RTMP → CDN',
    pros: '观众端简单（一路流）', cons: '转码 CPU 成本 + 300ms 额外延迟',
    layout: '服务端 layout API：{layout: "pip", main: peerA, sub: peerB, position: [x,y,w,h]}' },
  clientCompose: { desc: 'SFU 多流转发，观众端 canvas 合成',
    pros: '无服务端转码、延迟低', cons: '观众端解码 N 路（上限 4~6 路）',
    fit: '小规模连麦（≤4 路）' },
  decision: '观众规模大/布局固定 → serverMix；小规模互动 → clientCompose',
};
// 前端 clientCompose：N 个 video → WebGL canvas 合成（pip 布局）→ 录制/转推走 canvas.captureStream()
```
