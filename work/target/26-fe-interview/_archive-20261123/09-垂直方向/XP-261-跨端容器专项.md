## XP-261：跨端容器专项：容器内存泄漏排查实战（笔试）

**答**：
- 题目：容器页面频繁切换内存涨——排查流程：Heap Snapshot 对比（切换前后）→ 泄漏源定位（未清理监听/闭包持有）→ 修复验证。
- 思路：① 基线 snapshot → 切换 10 次 → 对比 snapshot → 增长对象定位（constructor 分组）；② 常见源：全局事件未清理/定时器/闭包持大对象；③ 修复后对比验证。
- 评分点：snapshot 对比方法；常见泄漏源清单；验证闭环。

```javascript
function diagnoseMemoryLeak(container) {                    // 泄漏排查
  const baseline = container.takeHeapSnapshot();                // 基线
  for (let i = 0; i < 10; i++) container.cyclePage();            // 切换 10 次
  const after = container.takeHeapSnapshot();
  const diff = compareSnapshots(baseline, after);                // 差异
  const leaked = diff.filter(d => d.count > 10 && d.sizeMB > 1);   // 显著增长
  return leaked.map(d => ({
    constructor: d.constructor,                                  // 泄漏对象类型
    growth: `+${d.count} (+${d.sizeMB}MB)`,
    suspects: LEAK_SUSPECTS[d.constructor] ?? '未知——看 retained size 引用链',
  }));
  // 常见泄漏源：EventListener（未 remove）、定时器（未 clear）、闭包（持有大数据）、
  // 全局 Map（只增不删）、Native 引用（View 未释放）
}
```
