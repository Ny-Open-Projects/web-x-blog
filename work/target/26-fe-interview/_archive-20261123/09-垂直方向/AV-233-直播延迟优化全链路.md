## AV-233：直播延迟优化全链路：从 6s 到 1s 的手段

**答**：
- 延迟构成拆解：HLS 切片（3×2s=6s）→ LL-HLS（部分切片 0.5s + 增量拉取 → 2s）；HTTP-FLV（TCP 层 1~3s）；WebRTC（300ms）。
- 优化手段排序：协议升级 > GOP 缩短（首帧快但压缩率降）> 缓冲策略 > 边缘缓存预热。
- 取舍：延迟与卡顿率跷跷板——缓冲越小越延迟低但抗抖动弱。

```javascript
const latencyOptimization = {
  protocol: {
    hls: '6s（3×2s 切片）→ LL-HLS 2s（0.5s 部分切片 + blocking playlist）',
    httpFlv: '1~3s（TCP 流式）',
    webrtc: '300ms（RTP/UDP）',
  },
  gop: 'GOP 从 4s → 1s：首帧快 3s，但压缩率降 20%（码率升）',
  buffer: '播放端 jitter buffer 3s → 1s：延迟降但卡顿率升（需边缘节点质量兜底）',
  decision: '互动直播（连麦/带货）→ WebRTC；常规直播 → HTTP-FLV；点播回放 → HLS',
};
```
