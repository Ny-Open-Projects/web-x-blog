## AV-278：音视频场景专项：多人合唱/合奏低延迟协同

**答**：
- 合唱协同：多人唱歌合流——延迟是死敌（>40ms 无法对齐）。方案：本地节拍器 + 各自录音上传 → 服务端对齐合成（非实时）；或超低延迟专用网络（同城）。
- WebRTC 延迟下限：采集 20ms + 编码 30ms + 网络 RTT/2 + jitter buffer 40ms + 解码 20ms ≈ 100ms+——实时合唱不可行。
- 实时合奏替代：指挥模式（一人节拍广播，各自跟拍）+ 非实时合成。

```javascript
const chorusArchitecture = {
  realtime: { feasible: false,
    reason: 'WebRTC 单向延迟 ~100ms+，人类合唱容差 < 40ms' },
  recording: { desc: '各成员跟节拍器录制 → 上传 → 服务端时间对齐合成',
    alignment: '节拍器时间戳对齐（录音起点打标）+ 波形互相关精调（±10ms）' },
  conducting: { desc: '指挥实时广播节拍（WebRTC datachannel 低延迟），成员各自跟唱录制',
    tolerance: '跟拍偏差 < 80ms 可接受（后期对齐修正）' },
};
// 波形对齐：互相关找最佳偏移——服务端合成时自动对齐各轨
```
