## 1002：微前端的跨应用事件总线设计与陷阱

**答**：
- 总线设计要点：事件命名空间化（域.实体.动作——order.updated）、payload 契约校验（schema 注册）、通配订阅（order.* 订阅域内全部——调试利器）、错误隔离（订阅者故障不影响发布者——allSettled）。
- 陷阱清单：事件风暴（高频实体变更刷屏总线——节流/合并窗口）、循环事件（A 发布 B 订阅处理又发布——事件链要 DAG 化，环检测告警）、监听泄漏（子应用卸载必须退订——生命周期钩子强制清理）。
- 替代方案评估：共享状态库（强耦合不推荐）、CustomEvent（原生但无契约能力）、专有总线（契约/统计/调试能力——微前端规模下值得自建或用成熟库）。
- 追问钩子：为什么「事件链要 DAG 化」？——循环事件（A->B->A）在异步边界下会无限循环（经典线上事故）；发布-订阅的自由度需要「链路规则」约束，环检测是总线的安全网。

```js
class MicroBus {
  publish(event, payload) {
    if (this.detectCycle(event)) { this.warnCycle(event); return; }
    const subs = [...(this.map.get(event) || []),
      ...this.wildcard(event)];                      // order.* 通配
    Promise.allSettled(subs.map(f => f(payload)));
  }
}
```
