## ZSM-343：SaaS 切换租户时状态怎么完整清场

**答**:
- 清场清单四层：内存（queryClient.clear + 各 store 重置到初始态，不是清空而是「恢复出厂」）、持久化（带租户 key 的 storage 全清）、连接（WS/轮询带着旧租户参数在跑的必须断掉重建）、UI 残留（路由回默认页、弹层/草稿关闭）
- 根治方案：租户 id 进所有 key（queryKey/store key/事件命名空间），切换时天然隔离旧数据不匹配新命名空间——比「切换后手动清」可靠
- 灰度风险：切换瞬间在途请求返回旧租户数据写入新状态——请求带租户头 + 响应校验租户 id，不匹配丢弃
- 验收：自动化测试「A 租户操作 20 步 → 切换 B → 断言无 A 残留」，覆盖 localStorage/内存/在途请求三类

```javascript
async function switchTenant(tenantId) {
  abortAllInflight()                          // 1. 断在途
  sockets.forEach((s) => s.close())           // 2. 断连接
  queryClient.clear()                         // 3. 清缓存
  Object.keys(localStorage).filter((k) => k.startsWith('t:')).forEach((k) => localStorage.removeItem(k))
  resetAllStores()                            // 4. 恢复出厂
  bootstrap(tenantId)                         // 5. 重新初始化
}
```
