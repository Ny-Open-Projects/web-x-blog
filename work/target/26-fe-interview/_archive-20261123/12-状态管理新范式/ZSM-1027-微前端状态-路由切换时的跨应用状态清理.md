## 1027：跨应用路由切换时的状态清理边界

**答**：
- 清理边界：应用卸载清理「私有状态」（store/订阅/缓存），保留「共享状态」（主应用的用户态/主题——不属于任何子应用）；清理清单进子应用卸载钩子（强制 checklist）。
- 保留即治理：路由离开「容器化保留」（keep-alive 式——同应用内切回不重载），跨应用切换默认销毁（显式声明可保留的白名单——如大表单草稿）。
- 清理遗漏的典型后果：定时器仍在跑（后台继续请求）、事件订阅累积（总线订阅数随切换增长——泄漏断言卡抓）、缓存陈旧（回来看到旧数据）。
- 追问钩子：为什么「跨应用切换默认销毁、白名单保留」优于「默认保留」？——默认保留要求每个应用正确处理「回来时的状态过期」（漏了就是旧数据事故）；默认销毁把「保留」变成显式决策（声明白名单——罕见且经过评审）。

```ts
// 卸载钩子的清理清单
export function unmount() {
  busUnsubs.forEach(u => u());            // 1. 事件退订
  store.destroy();                        // 2. 私有 store 销毁
  qc.clear();                             // 3. Query 缓存清理
  timers.forEach(clearTimeout);           // 4. 定时器
  // 保留白名单：draftBucket（显式声明）
}
```
