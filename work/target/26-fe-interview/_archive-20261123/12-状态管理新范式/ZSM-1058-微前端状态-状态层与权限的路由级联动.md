## 1058：微前端的路由级权限与状态联动（子应用间跳转守卫）

**答**：
- 跨应用跳转守卫：子应用 A 跳转到 B 的页面（B 的路由）——守卫由 B 自己执行（B 知道自己页面的权限要求），A 只负责导航（A 不该知道 B 的权限规则——关注点分离）。
- 守卫的数据依赖：B 的守卫读「状态门的权限数据」（主应用提供——权威）；守卫失败的跳转目标（无权限页/回退）由 B 决定（通知主应用或自跳）。
- 权限变更的守卫重算：权限实时变更（见权限感知卡）——当前页面所在应用的守卫重算（用户正停留在刚失去权限的页面——踢出或降级展示）。
- 追问钩子：为什么「守卫由目标应用执行」而不是主应用统一守卫？——主应用统一守卫需要主应用知道所有子应用的页面权限规则（主应用变成规则黑洞——每次子应用加页面都要改主应用）；目标应用自治守卫 = 权限规则与页面定义同处一地（内聚）。

```ts
// B 应用注册自己的守卫（自治）
registerRouteGuard('/orders/:id', async params => {
  const order = await deps.gate.getOrder(params.id);
  return order.perm.canView || { redirect: '/no-perm' };
});
// A 应用只导航：navigate('/orders/123') —— 守卫由 B 执行
```
