## ZSM-312：客户端列表的软删除（墓碑）状态怎么设计

**答**:
- 删除交互三态：立即消失（乐观从列表移除，服务端失败回滚）、墓碑态（行变成「已删除，撤销」可恢复）、批量待确认（收集后一次提交）
- 墓碑的价值：可撤销删除（不丢数据）+ 保留布局位置（撤销后回到原位）；实现为 `deleted: true` 标记而非物理移除，渲染层过滤
- 与缓存的配合：墓碑进 store（客户端态），删除提交成功后 invalidate 列表 Query——服务端才是删除真相，墓碑只是过渡 UI
- 陷阱：过滤在渲染层做（不在数据层删），否则撤销无从谈起；分页场景墓碑要按 id 跨页匹配

```javascript
const items = useStore((s) => s.items.filter((i) => !i.deleted))     // 渲染层过滤
function softDelete(id) {
  useStore.setState((s) => ({ items: s.items.map(i => i.id === id ? { ...i, deleted: true } : i) }))
  // 行内「撤销」：deleted: false；提交后 invalidateQueries(['list'])
}
```
