## ZSM-352：页面卸载（导航/关闭）时状态清理的正确时序

**答**:
- SPA 路由卸载：组件 cleanup 里清理「本页私有资源」（订阅/定时器/事件监听），全局 store 不清（跨页共享）；误清全局是跨页状态丢失的主因
- 整页卸载：unload 不可靠（bfcache/移动端），用 pagehide + visibilitychange(hidden) 兜底；同步写 storage 可行，异步请求用 sendBeacon
- 时序陷阱：页面 hide 时异步任务还会跑完一小段——「写库」任务要防重入（幂等键）；abort 策略明确（卸载即 abort 查询，mutation 视业务容忍）
- 清单化：页面级清理做成 hook（usePageCleanup），卸载钩子集中注册，避免散落 useEffect 各自为战漏清

```javascript
// 页面私有资源集中清理
usePageCleanup(() => { unsub(); clearInterval(t); wsChannel.leave(room) })
// 整页卸载兜底
window.addEventListener('pagehide', () => {
  syncWriteDraft()
  navigator.sendBeacon('/api/draft', blob)     // 异步上送的合法通道
})
```
