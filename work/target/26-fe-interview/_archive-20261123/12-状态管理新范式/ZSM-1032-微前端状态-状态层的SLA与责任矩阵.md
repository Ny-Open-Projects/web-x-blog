## 1032：微前端状态层的 SLA 与责任矩阵（谁负责什么）

**答**：
- 责任矩阵：主应用负责「状态门可用性/总线健康/契约校验工具」；子应用负责「自己的生命周期清理/事件契约遵守/私有状态正确性」；共享数据的事故归「权威方」（用户态事故=主应用，业务数据事故=拥有方子应用）。
- SLA 示例：总线事件传播延迟 P95 < 50ms、状态门可用性 99.9%、契约违规 CI 拦截率 100%、泄漏（卸载残留订阅）=0 容忍。
- 争议仲裁：跨应用状态事故的「根因仲裁」按契约（契约没写的盲区 = 平台组补契约——盲区即契约文档的 bug）。
- 追问钩子：为什么责任矩阵必须「书面化」？——跨团队的状态事故第一反应是互相甩锅（A 说 B 的消费错、B 说 A 的发布错）；书面矩阵让仲裁按文档走——矩阵的价值在冲突时刻兑现。

```md
## 状态责任矩阵
| 资产 | 权威方 | SLA |
| 状态门/总线 | 主应用 | 99.9% / P95<50ms |
| user.changed 契约 | user 应用 | CI 拦截率 100% |
| 订单缓存正确性 | order 应用 | 一致性窗口 <2s |
| 泄漏 | 各应用自清 | 卸载残留=0 |
仲裁：契约盲区 = 平台组补契约
```
