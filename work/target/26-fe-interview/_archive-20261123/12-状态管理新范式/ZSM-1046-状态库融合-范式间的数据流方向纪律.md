## 1046：范式组合的数据流方向纪律（防双向纠缠）

**答**：
- 方向纪律：Query -> Zustand 允许（服务端数据落本地副本——单向）、Zustand -> XState 允许（数据作为机器输入）、XState -> Zustand 允许（机器产出写仓库）——禁止的是「任何两层互写」（双向 = 两个真相 + 循环依赖）。
- 反向通道的正规形式：下层变化影响上层时走「事件/回调」（Zustand 变化 -> 显式 send 事件给机器——显式优于自动同步）；自动双向绑定（observer 双写）是范式纠缠的根源。
- 数据流的图：画出全应用的层数据流（单向 DAG——环检测），新范式引入前先看「加进图里是否产生环」。
- 追问钩子：为什么「自动双向绑定」在范式组合里特别危险？——两层数据互相 observer（A 变写 B、B 变写 A）——一次变更级联振荡（经典无限循环）；显式事件让「谁触发谁」可审计，自动绑定让循环无处定位。

```ts
// 方向纪律示例：显式反向通道
useUiStore.subscribe(s => s.mode, mode => {
  if (mode !== actor.getSnapshot().context.mode) {
    actor.send({ type: 'MODE_CHANGED', mode });   // 显式事件，非自动双写
  }
});
// 全局数据流图：单向 DAG，环检测进 CI
```
