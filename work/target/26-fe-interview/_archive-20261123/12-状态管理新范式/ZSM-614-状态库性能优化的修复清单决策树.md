## ZSM-614：状态库性能优化修复清单：从诊断结果到具体动作的决策树

**答**：
- 决策树第一层（变更次数异常）：一次交互 > 5 次 set → 合并写/事务批处理；订阅回调里再 set → 改派生。动作：`setState` 合并、`transact`、级联改派生。
- 第二层（selector 慢）：单次 > 2ms 或放大系数 > 组件数 → 拆标量 selector、memo 记忆化、写时算、worker/服务端迁移（按 ZSM-612 决策链）。
- 第三层（渲染层慢）：单次 commit > 16ms → 订阅粒度拆分、useShallow、组件 memo、列表虚拟化、`useSyncExternalStore` 的 transient 直写。
- 第四层（序列化/初始化慢）：stringify > 5ms → partialize + 节流 + 异步；store 创建 > 5ms → 懒创建 + 异步 hydrate。
- 第五层（内存增长）：订阅不平衡 → 平衡检查器；Map 只增不减 → LRU/TTL；快照/日志无限 → 环形缓冲。
- 顺序原则：**从上往下修**——次数问题不修，单次再优化也是乘法上的浪费；每修一项复测基线（ZSM-601），确认收益再进入下一项。

```javascript
// 修复决策树（可直接落成 CI 建议生成器）
function suggestFixes(prof) {
  const fixes = []
  if (prof.changesPerInteraction > 5) {
    fixes.push({ level: 1, fix: '合并 setState / transact 批处理', why: `${prof.changesPerInteraction} 次 set/交互` })
  }
  if (prof.cascadeDetected) {
    fixes.push({ level: 1, fix: '订阅回调写状态 → 改派生', why: '级联放大' })
  }
  for (const sel of prof.topSelectors) {
    if (sel.avgMs > 2) fixes.push({ level: 2, fix: `优化 selector「${sel.label}」`, why: `avg ${sel.avgMs}ms × ${sel.amplification}x` })
    if (sel.amplification > sel.subscribers) fixes.push({ level: 2, fix: `排查「${sel.label}」重复订阅`, why: `放大系数 ${sel.amplification}` })
  }
  if (prof.maxCommitMs > 16) {
    fixes.push({ level: 3, fix: '订阅粒度拆分 / useShallow / 虚拟化', why: `commit ${prof.maxCommitMs}ms` })
  }
  if (prof.stringifyMs > 5) {
    fixes.push({ level: 4, fix: 'partialize + 节流持久化', why: `stringify ${prof.stringifyMs}ms` })
  }
  if (prof.subImbalance > 0) {
    fixes.push({ level: 5, fix: '退订泄漏修复（平衡检查器定位）', why: `${prof.subImbalance} 个未平衡订阅` })
  }
  return fixes.sort((a, b) => a.level - b.level)   // 从上往下修
}
```
