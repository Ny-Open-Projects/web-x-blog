## 1052：主子应用双向数据编辑的案例（主表单嵌子应用字段）

**答**：
- 场景：主应用的大表单中嵌一个子应用渲染的字段区块（地址编辑器是子应用）——主表单的提交需要拿到子应用字段的数据。
- 交互协议：主应用注入「字段读写接口」与「校验时机」（getFields/setFields/validate——子应用实现，主应用提交时调用）——协议是契约（schema 定义接口签名），子应用换实现主应用无感。
- 校验联动：主应用提交前调用子应用 validate（返回错误集——主表单统一展示错误）；子应用内部编辑不主动上报（受控拉取优于推——主应用需要时才取）。
- 追问钩子：为什么用「受控拉取」而不是「子应用推送变更」？——推送（每击键上报主应用）产生高频耦合与性能开销；拉取（提交时取）只在需要时交互——跨应用边界的交互频率应最小化，拉取模式天然最小化。

```ts
// 契约：地址区块字段接口
export interface AddressBlock {
  getFields(): AddressFields;
  setFields(f: Partial<AddressFields>): void;
  validate(): Promise<{ field: string; msg: string }[]>;
}
// 主应用提交时
const errs = [...await mainValidate(), ...await addressBlock.validate()];
```
