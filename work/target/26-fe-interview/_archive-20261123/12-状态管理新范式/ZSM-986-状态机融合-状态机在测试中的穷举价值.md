## 986：状态机的测试穷举与模型测试

**答**：
- 模型测试：状态机定义本身可被「穷举测试」（每个状态 × 每个事件 = 预期结果表）——XState 的 testModel 或手写遍历：自动生成「所有合法转换」的断言（非法转换必须返回 false/不响应）。
- 穷举的价值：传统单测「测了开发者想到的路径」，模型测试穷举「定义里存在的所有路径」——转换定义新增（新事件）时自动进入测试覆盖（不会漏测）。
- 路径测试：从初始态到终态的所有路径（shortest paths 生成）——关键流程（支付成功/失败路径）的端到端断言自动生成。
- 追问钩子：为什么状态机的测试成本「随状态数线性」而 if/else 实现「随组合指数」？——状态机的合法路径被结构约束（非法组合不可达），测试只需覆盖合法路径；if/else 实现里所有组合都可能发生都得测。

```ts
// 模型测试：穷举每个状态的事件响应
const allStates = ['idle', 'editing', 'saving', 'saved'];
const allEvents = ['EDIT', 'SAVE', 'SAVED', 'FAILED'];
for (const s of allStates) for (const e of allEvents) {
  const a = machineAt(s);
  const r = a.send(e, samplePayload(e));
  expect(r).toBe(EXPECTED_TRANSITIONS[s]?.[e] ?? false);  // 非法转换必须 false
}
```
