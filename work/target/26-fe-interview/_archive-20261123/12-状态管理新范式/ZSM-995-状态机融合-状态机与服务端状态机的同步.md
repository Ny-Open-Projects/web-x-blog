## 995：前端状态机与后端流程状态的同步

**答**：
- 同步问题：后端也有流程状态（订单：待支付/已支付/已发货）——前端状态机必须与后端状态对齐（前端状态超前/落后于后端都会出错）：同步方式为「后端状态推送/轮询 -> 前端机器 send 对应事件」。
- 状态映射表：后端状态 -> 前端事件的映射显式声明（'PAID' -> send('PAID')）——映射表是前后端契约的一部分（后端加状态前端映射表缺失会静默不响应——需监控覆盖）。
- 冲突处理：前端状态超前于后端（乐观「已支付」但服务端实际失败）——机器要有「校准事件」（sync 事件强制对齐后端真相——乐观回滚的机器版本）。
- 追问钩子：为什么不能只信后端状态（前端不建模）？——前端的「过程性状态」（表单填写中/支付中）后端没有；但「终态」必须以后端为准——前端机器管过程、后端管终态，边界清晰。

```ts
// 后端状态推送 -> 前端机器事件映射
const BACKEND_TO_EVENT = {
  PAID: 'PAID', SHIPPED: 'SHIPPED', REFUNDED: 'REFUND',
};
socket.on('order.updated', e => {
  const ev = BACKEND_TO_EVENT[e.status];
  if (ev) actor.send({ type: ev, payload: e });     // 后端真相驱动前端机器
  else monitor.warn('unmapped backend state', e.status);  // 映射缺失监控
});
```
