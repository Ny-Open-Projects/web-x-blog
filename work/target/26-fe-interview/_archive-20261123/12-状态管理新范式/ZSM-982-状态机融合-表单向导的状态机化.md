## 982：多步表单向导的状态机化（含校验守卫）

**答**：
- 建模：每步一个状态（step1/step2/...），「下一步」事件带 guard（该步校验通过才允许前进）——非法前进（未填完跳步）结构上不可能；back 事件自由回退（已访问步骤可回）。
- 校验与数据：每步的表单值存机器 context（assign 更新），guard 校验 context（如 `ctx.email.valid`）；提交事件在最后一步聚合 context 发请求。
- 恢复与放弃：持久化 context（见持久化卡）支持中断恢复；「放弃」事件清 context 并回初始态（确认弹窗在 UI 层，机器只管 reset）。
- 追问钩子：为什么向导的状态机化收益特别明显？——向导是「步骤+校验+跳转」三重逻辑交织的传统重灾区（if/else 地狱）；状态机让三者各归其位（状态=步骤、guard=校验、事件=跳转）。

```ts
const wizard = createMachine({
  initial: 'step1',
  context: { email: '', emailValid: false, address: '' },
  states: {
    step1: { on: { NEXT: { target: 'step2',
      guard: c => c.emailValid,                 // 校验通过才前进
      actions: assign(c => ({ saved1: c.email })) },
      EDIT: { actions: assign((c, e) => ({ email: e.value,
        emailValid: isEmail(e.value) })) } } },
    step2: { on: { NEXT: 'review', BACK: 'step1' } },
    review: { on: { SUBMIT: 'done', BACK: 'step2' } },
    done: { type: 'final' },
  },
});
```
