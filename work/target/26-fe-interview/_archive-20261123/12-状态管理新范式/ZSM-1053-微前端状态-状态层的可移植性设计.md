## 1053：状态层的可移植性（换微前端框架状态层不动）

**答**：
- 可移植性问题：qiankun/wujie/federation 各有自己的通信与生命周期 API——状态层若绑死框架 API（用 qiankun 的 initGlobalState），换框架 = 状态层重写。
- 解耦设计：状态层自建总线/门/SDK（框架无关——纯 JS），框架适配器薄层（qiankunAdapter：把框架的 props/生命周期转接到 SDK）——换框架只换适配器。
- 验证可移植性：状态层单包测试（不依赖任何框架运行——纯 Node 可测）；适配器的表面积极小（<200 行）。
- 追问钩子：为什么「框架无关的状态层」值得投入？——微前端框架的迁移概率高于状态层（框架迭代快/选型摇摆）；状态层承载了最多的业务语义（事件契约/失效逻辑）——最贵的资产必须最可移植。

```ts
// 框架无关核心
export const core = createCore({ bus, gate, lifecycle });   // 纯 JS
// qiankun 适配器（薄层）
export function qiankunAdapter(props) {
  return core.bind({ auth: props.auth, bus: props.bus });
}
// wujie 适配器同理——核心不动
```
