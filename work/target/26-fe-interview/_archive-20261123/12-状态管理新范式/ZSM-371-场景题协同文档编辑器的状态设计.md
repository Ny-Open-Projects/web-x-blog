## ZSM-371：场景题示范：多人协作文档的状态管理

**答**:
- 核心选型：文档内容不用自研 store 硬管——直接用协同引擎的数据结构（Yjs/Y.Map 或 ProseMirror 协同），store 只存「视图与派生」（目录、权限、评论列表进 Query）
- 本地意图与远端事实分离：本地输入即时生效（本地事务），远端事务异步合入；undo 按作者过滤（ZSM-269）
- 在线状态：presence（光标/选区/在线列表）走 ephemeral 通道（Yjs awareness），不进持久状态
- 离线：本地事务缓存 + 重连自动同步（CRDT 天然合并）；崩溃恢复靠本地事务日志
- 面试亮点：说明「为什么不用 Redux 管文档内容」（文本变更频率与 op 语义不匹配自研方案），展示工具选型判断

```javascript
const ydoc = new Y.Doc()
const ytext = ydoc.getText('doc')            // 事实层：协同引擎持有
const provider = new WebsocketProvider(url, room, ydoc)
const awareness = provider.awareness         // presence 层
awareness.setLocalState({ cursor: pos })     // 光标不进持久 store
// 视图层：编辑器订阅 ytext 变化渲染；评论/目录走 Query
```
