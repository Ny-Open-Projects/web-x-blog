## ZSM-254：微前端里用户态（登录态）为什么必须单点化

**答**:
- token 双份/多份必然漂移：各子应用独立刷新会导致「一个刷新一个没刷」的 401 乱舞，以及竞态互踩
- 单点模式：主应用持有 token 与刷新逻辑，子应用通过注入的 request 代理（带最新 token）发请求，自身永不缓存 token
- 下发与仲裁：主应用监听 401 统一处理刷新+失效广播，子应用收到「auth:invalid」事件即清理本地缓存跳登录
- 收益：登出时主应用一次广播即可清理所有子应用状态，避免「登出后残留上一用户数据」的安全问题

```javascript
// 主应用注入请求代理
props.request = async (url, opt) => fetch(url, { ...opt, headers: { ...opt.headers, Authorization: `Bearer ${getToken()}` } })
// 子应用只用自己的 request，不碰 token
// 主应用 401 仲裁后广播
bus.emit('auth:invalid', { reason: 'refresh_failed' })   // 子应用各自清理
```
