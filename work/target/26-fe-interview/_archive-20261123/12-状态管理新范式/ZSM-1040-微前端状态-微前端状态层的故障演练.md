## 1040：微前端状态层的故障演练场景

**答**：
- 演练场景：总线故障（事件不传播——子应用缓存不失效，验证降级快照与用户提示）、状态门不可用（验证子应用只读降级运行）、子应用泄漏（mount/unmount 循环——验证泄漏断言生效）、契约违规事件注入（未注册事件发布——验证拒绝与告警）、灰度回滚（验证双发兼容与状态重置可接受）。
- 演练的预期行为预写：每个场景的「预期降级路径」先写好（演练是验证预案不是发现预案）——预案未覆盖的场景就是演练产出（补预案）。
- 频率与范围：季度全量演练、月度单场景（总线/门轮换）——微前端的状态故障模式跨应用，单体演练方法不完全适用（事件时序类场景是微前端特有）。
- 追问钩子：为什么微前端的状态故障演练比单体重要？——单体的状态故障模式少（单 store 单真相）；微新增了「事件链断裂/跨应用时序/契约漂移」类故障——这些故障模式在单体中不存在，团队没有直觉，必须演练建立。

```txt
演练场景与预期：
1. 总线故障 -> 降级快照 + stale 标识
2. 状态门不可用 -> 子应用只读降级
3. 契约违规注入 -> 拒绝 + 告警
4. 灰度回滚 -> 双发兼容 + 状态重置
原则：预期先写，演练验证；缺口即产出
```
