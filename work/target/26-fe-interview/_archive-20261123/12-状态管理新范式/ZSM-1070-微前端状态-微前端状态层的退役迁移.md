## 1070：子应用下线/合并时状态层的退役迁移

**答**：
- 退役场景：子应用下线（功能废了）或合并（两个小应用合成一个——治理成本）——状态层退役涉及：事件下线（provides 的事件还有订阅者吗——消费量归零才下线）、storage 桶清理（用户端残留数据清除策略）、契约文档标记 deprecated。
- 合并迁移：两个应用的事件合并到新应用（事件名兼容期——旧名发布转新实现），消费方渐进切换（同 API 兼容窗口）。
- 检查清单：消费量归零验证 -> storage 桶清理公告（用户数据删除合规）-> 契约 deprecated 标记 -> 预算监控移除 -> 架构图更新。
- 追问钩子：为什么「事件消费量归零」是下线的前置条件？——直接删事件，隐藏的消费方（未在审计中发现的隐式依赖）静默坏掉——消费量监控是「隐式依赖的最后探测器」（探针漏的它兜住）。

```txt
退役清单：
1. 事件消费量归零验证（最后探测器）
2. storage 桶清理公告（合规）
3. 契约 deprecated 标记 + 文档更新
4. 预算监控/快照接口移除
5. 架构图更新
合并迁移：事件名兼容窗口 + 消费方渐进切换
```
