## 989：状态机的延迟事件（after）与超时治理

**答**：
- 延迟事件：状态机内建超时（saving 状态 after 10s -> timeout 事件——自动迁移到超时分支）——比 useEffect + setTimeout 的手工超时可靠（组件卸载清理/状态变更取消全部内建）。
- 超时治理场景：支付等待超时（转入「支付结果确认中」而不是停在 saving）、重试退避（after 指数延迟重发）、会话超时（idle 30min -> 锁屏事件）。
- 取消语义：状态迁移自动取消未触发的延迟事件（离开 saving 状态，10s 超时自动作废）——手工 setTimeout 的清理遗漏是常见泄漏源。
- 追问钩子：为什么状态机里的超时比组件里的 setTimeout 可靠？——setTimeout 的生命周期绑定组件（组件卸载漏清理=泄漏；状态变化漏取消=误触发），机器的 after 生命周期绑定状态（状态离开自动清理）——所有权清晰。

```ts
const payMachine = createMachine({
  states: {
    waiting: {
      after: { 10000: { target: 'confirming',       // 超时自动迁移
        actions: assign({ timedOut: true }) } },
      on: { PAID: 'done' },
    },
    confirming: { on: { PAID: 'done', CANCEL: 'cancelled' } },
    done: { type: 'final' }, cancelled: {},
  },
});
```
