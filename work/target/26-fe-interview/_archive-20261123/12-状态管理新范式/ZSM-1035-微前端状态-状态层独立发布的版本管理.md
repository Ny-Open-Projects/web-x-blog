## 1035：状态层基座（总线/门/工具）的独立版本发布

**答**：
- 基座独立发布：总线/状态门/调试工具作为独立包（@mf/state-core——semver 发布，各应用按需升级）；基座 API 的兼容承诺（同主版本内不破坏）。
- 升级协调：基座升级的「兼容窗口」（新版本先兼容旧用法——deprecation 警告期一个季度），各子应用自选升级节奏（基座不强推——但安全修复版本强制）。
- 版本探测：运行时版本上报（各应用上报使用的基座版本——版本分布看板，长尾旧版本催促升级）。
- 追问钩子：为什么基座要「兼容窗口期」而不是强推升级？——强推 = 所有子应用同步升级（一次大爆炸，任一未适配即全站故障）；兼容窗口把升级分散到各团队节奏（基座作者的发布压力与使用方的适配压力解耦）。

```ts
// 基座 deprecation 警告（兼容窗口）
export function publish(event, payload) {
  if (isLegacyFormat(payload)) {
    warnOnce(`event ${event} legacy format, migrate before 2027-Q1`);
  }
  return bus.publish(event, payload);
}
// 运行时版本上报
reporter.gauge('mf_core_version', VERSION);
```
