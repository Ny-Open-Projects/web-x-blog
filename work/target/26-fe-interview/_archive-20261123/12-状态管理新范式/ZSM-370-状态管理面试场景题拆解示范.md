## ZSM-370：场景题示范：协作看板的状态管理怎么设计

**答**:
- 分层数据模型：服务端事实（卡片/列/成员）归一化 Map + 列顺序数组；实时层（他人光标/在线状态）独立 ephemeral store（不持久化）；本地层（拖拽影子/选中）组件态
- 更新链路：本地拖拽 → 影子态即时渲染 → drop 后乐观提交（幂等 op）→ 服务端确认/冲突合并（卡片被他人移动时提示）→ 广播给他人（op 流）
- 失效与一致：seq 协议 + 重连快照重建；卡片详情进 Query 缓存（id key）；操作日志可回放
- 面试结构：先分层（30 秒）→ 数据模型（画一下）→ 关键难点（冲突/离线/撤销各一句）→ 取舍说明（为什么不上 CRDT/什么时候上）

```javascript
// 分层示意
const boardAtom = atom({ cards: new Map(), columns: [['todo'], ['doing']] })   // 事实层
const cursorsAtom = atom(new Map())                                            // ephemeral
// 拖拽：影子 → commit
onDrop: (cardId, colIdx) => {
  moveShadow(cardId, colIdx)
  submitOp({ type: 'move', cardId, colIdx, baseVersion })   // 幂等 op + 广播
}
```
