## ZSM-783：状态层的测试金字塔：逻辑测、交互测、契约测三层配比

**答**：
- 状态层的测试金字塔（区别于 UI 金字塔，重心在逻辑）：
- **逻辑测（70%）**——store 的 action/reducer/派生纯逻辑：直接调 action 断言 getState，不渲染组件（跑得飞快，覆盖 ZSM-624 竞态注入 + ZSM-622 显著性基准）。一个 store 的测试文件与源文件同目录。
- **交互测（20%）**——组件与状态的接线：renderHook + userEvent 验证「点击 → action → 渲染更新」链路，重点测投影纪律（aria 与 store 一致 ZSM-708）与 selector 粒度（不测样式细节）。
- **契约测（10%）**——跨模块/跨应用的协议：契约事件总线的 schema 校验（ZSM-779）、API mock 响应与 fixture 工厂（ZSM-710）的一致性、persist migrate 链的版本兼容。
- 配比的依据：状态 bug 的分布（经验）——纯逻辑 60%、接线 30%、协议 10%，测试资源按 bug 分布倾斜。
- 反模式警示：状态层的 E2E 覆盖是伪需求（慢且脆）——E2E 只保关键链路拼装（ZSM-705），状态细节全在下三层。
- 追问钩子：覆盖率的有效口径——不看行覆盖率看「分支语义覆盖率」：守卫的每个拒绝分支、竞态注入的每个时序、迁移链的每个版本都要有用例，这三个维度有洞就是风险。

```javascript
// 三层配比与示例
const TEST_PYRAMID = {
  逻辑测_70: {
    scope: 'action/reducer/派生/守卫/竞态',
    example: 'createReconciler 的回滚/确认/超时（ZSM-528 用例）',
    speed: '< 50ms/用例',
  },
  交互测_20: {
    scope: '组件接线/投影纪律/selector 粒度',
    example: 'renderHook 断言 aria-checked 跟随 store 三态（ZSM-708）',
    speed: '< 500ms/用例',
  },
  契约测_10: {
    scope: '跨模块协议/schema/migrate/fixture 一致性',
    example: 'fixture 工厂双出口一致性断言（ZSM-710）',
    speed: '< 200ms/用例',
  },
}

// 逻辑测示例（无渲染）

  const rc = createReconciler(...)

// 分支语义覆盖检查（自定义指标）
function branchCoverage(machine) {
  // 守卫拒绝分支 / 迁移目标 / 错误路径 逐个检查有用例
  return {
    guardRejects: machine.guards.every((g) => hasTestFor(g)),
    errorPaths: machine.errorStates.every((s) => hasTestFor(s)),
    migrateChain: MIGRATIONS.every((m, v) => hasTestFor(`v${v}->v${v + 1}`)),
  }
}
```
