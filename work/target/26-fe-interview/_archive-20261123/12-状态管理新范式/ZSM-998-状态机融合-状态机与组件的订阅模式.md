## 998：状态机在 React 中的订阅模式（防过度渲染）

**答**：
- 订阅收窄：useSelector(actor, s => s.context.email)——只订阅需要的切片（email 变化不触发整个组件重渲染）；对比 useMachine 的全量订阅（任何状态变化都重渲染——大机器里是性能坑）。
- 选择器纪律：选择器返回原始值或稳定引用（返回新对象 = 每次都变 = 永远重渲染——与 Zustand 的 select 纪律同构）；嵌套字段用多个 useSelector 而非一个大对象。
- 渲染分界：状态机的「状态变化」（matches 变化）通常低频（流程跳转），「context 变化」（表单输入）高频——两类订阅分开（低频组件用状态、高频输入组件只订阅自己的字段）。
- 追问钩子：为什么状态机「低频状态+高频context」的二分要显式设计？——混在一起订阅（useMachine 全量）会让「表单打字」重渲染整个流程 UI——分界设计是性能与正确性的平衡点。

```ts
// 收窄订阅：只订字段
const email = useSelector(actor, s => s.context.email);
const step = useSelector(actor, s => s.value);          // 低频：状态
const canNext = useSelector(actor, s => s.context.emailValid);
// 反例：useMachine 全量订阅 -> 打字重渲染全流程
```
