## ZSM-733：多端消息信令的时序一致性：服务端序 vs 客户端序 vs 混合

**答**：
- 多端显示顺序不一致是 IM 最经典 bug：A 端显示「消息1→消息2」，B 端相反。根因是排序键选择。三种序：1) **客户端时间戳**——时钟漂移必乱序，只能做展示辅助；2) **服务端到达序**（seq）——单会话严格一致，多会话间无全局序；3) **混合**——服务端 seq 做排序权威 + 客户端时间做展示（「显示的是发送时间」），乱序包按 seq 插入。
- 服务端序的实现要求：每会话单调递增 seq（服务端分配），客户端**本地先按「乐观序」渲染**（发出即显示在底部），服务端 ack 后携带正式 seq——与乐观序冲突时（服务端序与本地预期不同）按服务端 seq 重排，用户的「我刚发的」消息可能落在中间——视觉跳动是可接受的代价，或用「pending 区」缓解。
- 乱序到达的插入算法：按 seq 二分插入（消息数组保持 seq 升序）；缺口（seq 跳跃）触发拉取补齐（ZSM-727）而不是假设丢失。
- 系统消息与撤回的序：撤回是「对某 seq 的修改指令」（按 seq 定位而非按列表位置）；系统消息有自己的序空间（混排时同样按 seq），避免「撤回指令比消息先到」——撤回指令必须等目标消息已应用才生效（依赖检查，未到则挂起队列）。
- 追问钩子：跨会话的全局时序（会话列表排序）用「服务端 lastActivityTime」而非客户端时间——多端排序一致的统一原则：**所有跨端一致性的排序键必须来自服务端单一事实源**。

```javascript
// 按服务端 seq 的消息列表管理
class MessageList {
  #messages = []           // seq 升序
  #pending = new Map()     // clientId -> { content, sentAt }（未 ack 乐观区）
  #gapHandler = null

  append(m) {
    if (m.seq == null) {   // 本地乐观消息：无 seq，pending 区
      this.#pending.set(m.clientId, m)
      return { pending: true }
    }
    // 二分插入：按 seq 升序（重复 seq 去重）
    const i = this.#lowerBound(m.seq)
    if (this.#messages[i]?.seq === m.seq) return { dup: true }
    // 缺口检测：seq 跳跃触发补拉
    if (i > 0 && m.seq - this.#messages[i - 1].seq > 1) {
      this.#gapHandler?.(this.#messages[i - 1].seq, m.seq)
    }
    // ack 后从 pending 区移除
    if (m.clientId) this.#pending.delete(m.clientId)
    this.#messages.splice(i, 0, m)
    return { inserted: i }
  }

  #lowerBound(seq) {
    let lo = 0, hi = this.#messages.length
    while (lo < hi) {
      const mid = (lo + hi) >> 1
      if (this.#messages[mid].seq < seq) lo = mid + 1
      else hi = mid
    }
    return lo
  }

  // 撤回：按 seq 定位 + 未到挂起
  #recallQueue = []
  recall(targetSeq) {
    const m = this.#messages.find((x) => x.seq === targetSeq)
    if (m) { m.recalled = true }
    else this.#recallQueue.push(targetSeq)        // 目标未到：挂起
  }
  // append 后处理挂起队列
  #drainRecalls() {
    this.#recallQueue = this.#recallQueue.filter((s) => {
      const m = this.#messages.find((x) => x.seq === s)
      if (m) { m.recalled = true; return false }
      return true
    })
  }

  render() {
    return [...this.#messages, ...this.#pending.values()]   // pending 展示在尾部
  }
}
```
