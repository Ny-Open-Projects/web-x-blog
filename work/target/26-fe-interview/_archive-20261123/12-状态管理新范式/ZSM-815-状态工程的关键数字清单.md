## ZSM-815：状态工程的关键数字清单：面试中脱口而出的度量基准

**答**：
- 面试里「带数字」的表达可信度倍增。状态工程的 20 个关键数字（来源标注，可引用）：
- **帧与预算**：16ms 帧预算 / 8ms 每帧类余量 / INP good ≤ 200ms / 长任务阈值 50ms / TBT 关注点。
- **渲染**：React commit 单次 ≤ 16ms、单次变更重渲组件 ≤ 30（后台类红线 ZSM-755）、虚拟窗口活跃行 ~50。
- **网络**：WS 心跳 25s / 假死判定 40s / 重连退避 cap 30s / 请求并发闸门 50 / 熔断阈值 5 次失败 / 追平缺口分界 50 条。
- **缓存**：gcTime 默认 5min / staleTime 交易类 0 配置类 Infinity / persist 队列上限 2000 op。
- **内存**：JS 堆告警 500MB / 降载阈值 heap ratio 0.8 连续 3 次 / 快照体积红线 100KB。
- **协议**：presence TTL 60s / idle 30s / 通知窗口 5min / 上报去抖 500ms / 已读游标最小值口径。
- 数字的正确用法：**「我们的预算是 X，实测 Y，按 Z 口径」**——只说预算不说实测=背书；只说实测不说口径=不可信。
- 追问钩子：数字的时效声明——「以上是我在上项目的实测口径，换设备档位/网络环境要重测」——数字+口径+时效三要素齐才算专业。
