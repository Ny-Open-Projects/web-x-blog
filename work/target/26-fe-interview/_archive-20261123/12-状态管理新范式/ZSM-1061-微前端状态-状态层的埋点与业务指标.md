## 1061：跨应用状态层的埋点体系（行为指标归因到应用）

**答**：
- 埋点归因：跨应用的用户行为（A 提交订单 -> B 展示结果）需要「全链路行为埋点」——traceId 贯穿（A 的提交事件到 B 的展示事件同一 traceId——转化漏斗跨应用可算）。
- 指标分层：技术指标（事件延迟/缓存失效耗时——平台组）、业务指标（跨应用转化率/状态不一致投诉——业务组）——同一埋点体系两种消费。
- 埋点的标准化：SDK 内置埋点钩子（bus.publish 自动埋事件指标——发布方零成本埋点）+ 业务显式埋点（关键转化动作手动打点）。
- 追问钩子：为什么「traceId 贯穿」是跨应用埋点的核心？——跨应用漏斗（A 提交到 B 展示的转化）若 traceId 断裂，漏斗只能按应用分段统计（转化率算不出来）；traceId 是把「跨应用的异步链」变成「可归因的单条旅程」的唯一线索。

```ts
// SDK 内置埋点
function publish(event, payload) {
  reporter.event(event, { app, traceId: ctx.traceId });   // 自动埋
  return bus.publish(event, payload);
}
// 业务显式埋点：关键转化
reporter.conversion('order.submit_to_display', { traceId });
```
