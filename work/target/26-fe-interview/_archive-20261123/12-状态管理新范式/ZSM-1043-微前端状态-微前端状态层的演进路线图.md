## 1043：微前端状态层的演进路线图（从 MVP 到平台化）

**答**：
- 三阶段路线：MVP（总线+分桶+基础清理——两个应用能协同）、平台化（契约校验/SDK/调试工具——治理成型）、自动化（契约测试/依赖审计/预算监控/故障演练常态化——治理自运转）。
- 每阶段的进入条件：MVP->平台化（子应用 >=3 或发生过 1 次跨应用状态事故）；平台化->自动化（子应用 >=5 或契约变更频率 >2 次/月）——投入与规模匹配。
- 路线的反模式：跳级（MVP 直接上自动化——工具建了没人用/没有事故驱动的问题意识）；停滞（事故频发仍停在 MVP——治理欠债指数增长）。
- 追问钩子：为什么路线图要「事故驱动升级」？——治理投入没有外部评审压力（不像功能有需求方），事故是最诚实的「投入回报证明」——用事故换预算的治理升级是可持续的（无事故的治理预算会被砍）。

```md
## 状态层演进路线
MVP：总线 + 分桶 + 清理清单
  -> 条件：>=3 应用 或 1 次跨应用事故
平台化：契约校验 / SDK / 调试工具
  -> 条件：>=5 应用 或 契约变更 >2 次/月
自动化：契约测试 / 审计 / 预算 / 演练
反模式：跳级 / 停滞（事故频发仍 MVP）
```
