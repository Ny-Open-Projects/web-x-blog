## 1039：子应用权限感知的实时性（权限变更传播）

**答**：
- 权限变更的三种传播时机：下次启动（重启生效——最简单但用户困惑「为什么功能还在」）、实时推送（权限变更事件——子应用即时响应）、页面切换校验（路由守卫每次校验——折中）。
- 实时传播的落地：主应用监听权限变更（自身接口/WebSocket）-> 广播 perm.changed -> 子应用失效权限相关缓存 + 重算 UI（菜单/按钮态）；权限敏感操作（提交前）服务端终校验（前端感知只是体验不是安全）。
- 感知的完整性：子应用「收到事件后做什么」要有标准动作（失效权限域缓存 + 触发 UI 重算——标准动作固化在 SDK 里，各子应用一致）。
- 追问钩子：为什么权限的「前端实时感知」不能替代「服务端校验」？——前端感知控制「界面可见性」（体验），服务端校验控制「操作合法性」（安全）；降权用户的残留前端能力若仅靠前端隐藏拦截，一个内存修改就绕过——安全边界永远在服务端。

```ts
// SDK 标准动作：权限变更处理
bus.subscribe('perm.changed', e => {
  qc.invalidateQueries({ queryKey: ['perms'] });        // 失效权限缓存
  qc.invalidateQueries({ queryKey: ['admin'] });        // 权限敏感域
  recomputeUI();                                        // 标准重算入口
});
// 操作侧：提交前服务端终校验（前端感知仅体验）
await serverGuard.check('order.cancel', orderId);       // 403 则拒绝
```
