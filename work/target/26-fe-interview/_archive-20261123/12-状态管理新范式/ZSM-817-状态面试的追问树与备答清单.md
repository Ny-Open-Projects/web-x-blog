## ZSM-817：状态面试的追问树：每道主题的备答分支清单

**答**:
- 高频主题的追问树（面试官最常延伸的方向 + 各分支的一句备答）：
- **主题「乐观更新」**→ ①失败回滚粒度？（字段级，对账器 528）②服务端合并了他人改动？（confirm 以服务端为准）③超时呢？（timeout 自动 reject + 幂等键沿用 767）④什么场景不能乐观？（资损/不可逆/服务端再加工 538）。
- **主题「大列表性能」**→ ①虚拟滚动怎么做？（窗口三数 547）②不定高呢？（实测+前缀和+锚定补偿）③排序切换？（order 与实体分离，引用稳定 753）④扇出？（observer 通知闸门 643）。
- **主题「多端同步」**→ ①多 tab 一条连接？（leader 选举 577/599）②断线丢消息？（lastSeq 追平三策略 727）③冲突？（按数据性质分层 583/596）④离线？（op 队列 + baseVersion 588）。
- **主题「状态库选型」**→ ①为什么 Zustand？（六维矩阵 788）②什么时候 XState？（流程复杂+可观测要求 507）③能混用吗？（职责分层合法，偏好混用碎片化）④迁移成本？（映射覆盖率预检 788）。
- 追问树的用法：每道主题准备「一主三副」——主答 90 秒骨架 + 三个最可能追问的一句备答；备答不展开只锚定（「字段级——对账器模式」），展开留给面试官点单。
- 追问钩子：追问树的「防逃逸」——备答时主动留钩子（「这里还有个超时场景，感兴趣可以展开」），把追问引向自己准备好的分支。

```javascript
// 高频主题追问树（一主三副）
const FOLLOWUP_TREES = {
  乐观更新: {
    main: '90s 骨架：可乐观三特征 → 三层防线 → 对账闭环',
    branches: {
      回滚粒度: '字段级——对账器模式（528），只还原自己的切片',
      他人合并: 'confirm 以服务端为准，version 裁决（737）',
      超时: 'timeout 自动 reject + 幂等键沿用（767）',
      不能乐观: '资损/不可逆/服务端再加工——悲观+pending态（538）',
    },
    hook: '主动留钩：「超时场景感兴趣可以展开」',
  },
  大列表性能: {
    main: '四段式骨架（801）',
    branches: {
      虚拟滚动: '窗口三数 scrollTop/viewportH/rowH + overscan（547）',
      不定高: '实测前缀和 + 滚动锚定补偿',
      排序切换: 'order 与实体分离，行引用稳定（753）',
      扇出: 'observer 通知闸门 + select 粒度（643）',
    },
  },
  多端同步: {
    main: '协议栈五层（743）',
    branches: {
      多tab: 'leader 选举 WebLocks + 转发聚合（599）',
      断线: 'lastSeq 追平三策略，410 全量兜底（727）',
      冲突: '按数据性质：交易/计数/游标/偏好 分层（583）',
      离线: 'op 队列 + baseVersion 冲突标记（588）',
    },
  },
  选型: {
    main: '六维矩阵 + 迁移触发四条件（788）',
    branches: {
      为什么Zustand: '粒度4/TS5/生态4/成本5/SSR5——加权最高',
      何时XState: '流程复杂+可视化评审需求（507/566）',
      混用: '职责分层合法（服务端态/客户端态/流程态），偏好混用=碎片化',
      迁移成本: 'API 映射覆盖率预检 >90% 才值得',
    },
  },
}
// 用法：一主三副——备答只锚定不展开，留钩子引向准备好的分支
```
