## 1054：跨应用撤销重做（undo/redo）的状态治理

**答**：
- 场景：画布类编辑器跨子应用（图形编辑子应用+属性面板子应用）——撤销重做需要跨应用的操作历史。
- 治理方案：操作历史在「拥有画布的子应用」（undo/redo 栈），跨应用只暴露 undo()/redo() 命令接口（面板调用）；历史栈不跨应用共享（栈的一致性由单点保证）。
- 命令模式：每个操作记录「正向执行+逆向撤销」（command 对象）——撤销重做的本质是命令模式，命令的序列化让历史可持久化（刷新恢复）。
- 追问钩子：为什么 undo 栈「单点持有」而不是分布式（各应用各管各的操作）？——undo 的语义是「全局时间线」（用户视角一个 Ctrl+Z 回退一步——不管这步改了哪个应用）；分布式栈无法合并成全局时间线（顺序/冲突无解）——单点持有是唯一正确解。

```ts
// 命令模式 + 单点历史栈
class CommandStack {
  undo() { const c = this.stack[--this.p]; c?.revert(); }
  redo() { const c = this.stack[this.p++]; c?.apply(); }
  push(c) { this.stack.length = this.p; this.stack.push(c); this.p++; }
}
// 子应用面板：deps.canvas.undo()   // 命令接口，栈在画布应用
```
