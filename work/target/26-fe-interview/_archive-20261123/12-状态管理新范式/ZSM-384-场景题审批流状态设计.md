## ZSM-384：场景题示范：审批流（会签/或签/转交）状态设计

**答**:
- 流程真相在服务端：客户端只渲染「审批快照」（节点状态/当前处理人）+ 本地操作乐观层；审批动作是幂等 mutation（opId + 节点版本）
- 视图派生：节点状态图（待审/通过/驳回/转交）从快照派生渲染，不本地维护「流程推进逻辑」——前端推进流程必然与服务端漂移
- 并发审批（会签）：他人已审节点被本地乐观标记后收到推送覆盖，UI 以推送版本收敛；驳回后未处理节点自动失效（重拉）
- 时间线与附件：审批历史是追加流（分页缓存），附件上传独立 mutation 与审批提交解耦（先传后提，传失败可重试不阻塞驳回）

```javascript
const { data: flow } = useQuery({ queryKey: ['flow', id], queryFn: fetchFlow })   // 服务端快照
const approve = useMutation({
  mutationFn: (node) => api.approve({ flowId: id, nodeId: node.id, opId: uuid(), baseVersion: flow.version }),
  onMutate: optimisticNodeApprove, onError: rollback,
})
const timeline = useInfiniteQuery({ queryKey: ['flow-log', id], queryFn: fetchLog })   // 历史流
```
