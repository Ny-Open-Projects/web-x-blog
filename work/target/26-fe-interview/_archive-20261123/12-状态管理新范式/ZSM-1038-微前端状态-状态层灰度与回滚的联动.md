## 1038：微前端子应用灰度时的状态层联动

**答**：
- 灰度场景：子应用新版本灰度（10% 用户）——新旧版本的子应用同时在线，各自 store/缓存独立（天然隔离），但「事件契约」跨版本（旧版消费方收到新版事件 payload——契约兼容是灰度的前提）。
- 灰度期的状态策略：事件双发（新旧格式都发——兼容窗口）或单发新格式（前提消费方已兼容）；失效联动在灰度期要覆盖「两版本的消费方」（谁在线谁收事件——总线天然做到）。
- 回滚联动：灰度回滚（新版下线）——新版发布的事件残留处理（旧版消费方收到新格式？——兼容窗口内双发解决）；回滚后状态不迁移（旧版从初始态恢复——灰度回滚接受状态重置）。
- 追问钩子：为什么灰度期「事件双发」比「分桶隔离总线」简单？——分桶总线（新旧应用各自总线）需要事件桥接（桥接本身又是 bug 源）；双发在单总线内解决（消费方按版本选择解析）——机制数量最少者优先。

```ts
// 灰度期双发
function publishOrderUpdated(order) {
  bus.publish('order.updated', { v: 1, ...legacyPayload(order) });
  bus.publish('order.updated', { v: 2, ...newPayload(order) });  // 兼容窗口
}
// v1 消费量归零后移除 v1 发布
```
