## ZSM-320：状态层重构上线的运行时 feature flag 怎么设计

**答**:
- 状态层重构（换库/改 key 结构）不能靠「发版即生效」硬切：用 flag 控制「新旧实现」双路径，按用户/流量灰度
- 兼容关键点：持久化 key 命名带版本（cart_v2），新旧实现互不覆盖；灰度期间双写不一致埋点对比
- flag 数据源：启动时拉取（未拿到前用默认保守值），不要让 flag 本身阻塞渲染；flag 变更的热生效范围要明确（大多数 flag 需要刷新生效）
- 收尾纪律：flag 有 owner 与下线日期，全量后删除旧实现与 flag——双路径长期并存是最大债

```javascript
const useNewCart = flags.get('state.cart_v2', false)      // 保守默认
export function useCart() {
  return useNewCart ? useCartV2() : useCartV1()           // 双路径，持久化 key 各自版本化
}
// 灰度观测：对比新旧实现的 action 耗时/错误率，达标后全量删旧
```
