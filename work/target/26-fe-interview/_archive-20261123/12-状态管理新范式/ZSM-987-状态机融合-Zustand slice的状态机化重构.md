## 987：把 Zustand 里的隐式状态机显式化（重构案例）

**答**：
- 重构识别：Zustand store 里发现「status 字段 + 一堆 if(status === ...) 守卫」——这就是隐式状态机（字符串状态 + 手动守卫 = 易漏易错）；重构为显式机器的信号：status 值 >=3 且守卫逻辑分散在多个 action。
- 重构步骤：画当前隐式状态图（从 if/else 反推）-> 定义机器（合法转换固化）-> store 保留数据字段（status 由机器驱动）-> action 改为 send 事件 -> 逐步迁移消费方（selector 从机器读）。
- 重构的验证：迁移前后「行为等价测试」（同样的操作序列产出同样的 store 状态——重构不改行为）+ 非法操作测试（重构前能触发的 bug 场景现在不可触发——显式收益）。
- 追问钩子：为什么「先画图再动码」？——隐式状态机的真实结构（哪些转换实际存在）藏在代码里，反推画图的过程就是「发现 bug 与死代码」的过程（画完图常发现几个从未到达的状态）。

```txt
Zustand 隐式状态机重构路径：
1. 反推：从 if(status === 'x') 守卫画出现状图
2. 定义：合法转换固化成机器（非法不可表示）
3. 分工：机器管 status，store 管数据
4. 迁移：action -> send 事件，消费方渐进
验证：行为等价测试 + 非法操作归零
```
