## 978：状态机的持久化（流程中断恢复）怎么做

**答**：
- 持久化方案：XState 的 persist/state 序列化（机器状态 + context 存 sessionStorage/localStorage）——用户中断流程（关页面/刷新）后恢复到中断点（向导到第 3 步就回第 3 步）。
- 持久化的边界：只持久化「可恢复状态」（表单值/步骤），不持久化「瞬时状态」（loading/错误——恢复后应重置）；敏感数据（支付信息）不持久化。
- 版本兼容：机器定义演进（状态改名/结构变化）后旧持久化数据无法恢复——持久化带 schema 版本，不兼容时降级重置到初始态（而不是崩溃）。
- 追问钩子：为什么「恢复到中断点」的用户价值巨大？——长流程（多步表单/复杂配置）的中断重填是流失主因——状态机持久化把「流程的连续性」变成产品的默认能力。

```ts
// 持久化与恢复
const saved = sessionStorage.getItem('checkout');
const actor = saved
  ? createActor(checkoutMachine).start(JSON.parse(saved).state)  // 版本校验后恢复
  : createActor(checkoutMachine).start();
actor.subscribe(state => {
  if (state.matches('filling') || state.matches('paying')) {
    sessionStorage.setItem('checkout',
      JSON.stringify({ v: SCHEMA_V, state: persist(actor) }));
  }
});
```
