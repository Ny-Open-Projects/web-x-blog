## 1014：微前端状态治理的跨团队协作规范

**答**：
- 规范四件：契约变更流程（manifest/事件 schema 变更需影响方评审——契约是公共资产）、命名规范（事件与 storage key 的命名空间规则——防冲突）、生命周期规范（mount/unmount 的清理义务——泄漏是集体成本）、调试规范（事件录制/快照接口的标准实现——人人可定位跨应用问题）。
- 治理组织：平台组提供总线/契约校验/调试工具（基座），业务组遵守契约（业务）——平台不给工具，规范就是空话。
- 违规治理：CI 契约校验拦截（未声明依赖禁止合入）+ 运行时探针告警——规范靠工具执行不靠自觉。
- 追问钩子：为什么微前端的状态规范必须「工具化」？——跨团队规范靠约定必然衰减（各团队优先级不同）；CI 与运行时探针是「不依赖协作意愿」的执行机制——规范的生命力等于其自动化程度。

```md
## 微前端状态协作规范
1. 契约变更：影响方评审 + manifest 同步
2. 命名：{app}.{entity}.{action} / mf:{app}:{key}
3. 生命周期：unmount 必须清理（CI 泄漏测试）
4. 调试：标准快照接口 + 总线录制器（平台提供）
执行：CI 校验 + 运行时探针
```
