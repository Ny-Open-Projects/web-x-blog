## ZSM-736：多端购物车同步：服务端权威合并与本地未提交项的共存

**答**：
- 购物车是「多端同步 + 交易敏感」双属性：同步策略用**服务端权威**（一端改、服务端合并、全端推送），因为库存/优惠/价格校验只在服务端。本地未提交项（刚点加购、请求在途）单独标记 `pendingAdd`，服务端推送覆盖时保留 pending 项不丢。
- 服务端合并语义（这就是「服务端是权威」的含义）：数量冲突取 max（两端各 +1 → 合并后 2，不是覆盖）、删除与修改冲突以删除胜（删了的商品不该复活）、同商品不同 SKU 分开条目。合并结果带 `version`，客户端 apply 时做版本检查（旧版本推送丢弃）。
- 推送驱动的 apply 三步：1) 版本检查（`msg.version > local.version`）；2) 合并 pending（服务端条目 + 本地 pendingAdd 求并）；3) 派生重算（小计/角标都是派生，不存储）。本地乐观值在推送到达时自动被权威值替换——乐观写、推送覆盖、无显式回滚。
- 离线队列的兼容：离线加购进队列（ZSM-588），联网 flush 时服务端做同样合并；队列 flush 返回的合并结果与 WS 推送是同一数据源（服务端单点合并，双通道只是传输差异）。
- 追问钩子：购物车合并的「用户可感知差异」提示——合并后发现条目被删（另一端删除）时 toast「购物车已在其他设备更新」，不要静默吞掉。

```javascript
// 购物车多端同步引擎
class CartSyncEngine {
  #version = 0
  #items = new Map()          // skuId -> { qty, price, pending? }
  #listeners = new Set()

  // 本地操作：乐观 + 发送
  addItem(sku, qty = 1) {
    const cur = this.#items.get(sku)
    // 乐观：本地立即 +1（pending 标记：未确认）
    this.#items.set(sku, { ...(cur ?? { price: null }), qty: (cur?.qty ?? 0) + qty, pending: true })
    this.#notify()
    api.cart.add({ sku, qty, baseVersion: this.#version })
      .catch(() => { /* 离线：进队列（ZSM-588），flush 时合并 */ })
  }

  // 服务端推送：权威合并结果
  applyRemote({ version, items, changes }) {
    if (version <= this.#version) return              // 旧版本推送丢弃
    const next = new Map()
    for (const it of items) next.set(it.sku, { ...it, pending: false })
    // 保留本地 pending（请求在途的加购不被推送吞掉）
    for (const [sku, it] of this.#items) {
      if (it.pending && !next.has(sku)) next.set(sku, it)
    }
    this.#items = next
    this.#version = version
    // 用户可感知差异提示
    if (changes?.removed?.length) toast.info(`购物车已在其他设备更新（移除 ${changes.removed.length} 件）`)
    this.#notify()
  }

  // 派生：小计/角标不存储
  get subtotal() { return [...this.#items.values()].reduce((a, i) => a + (i.price ?? 0) * i.qty, 0) }
  get count() { return [...this.#items.values()].reduce((a, i) => a + i.qty, 0) }

  #notify() { this.#listeners.forEach((fn) => fn(this.snapshot())) }
  snapshot() { return { items: [...this.#items.values()], version: this.#version, subtotal: this.subtotal, count: this.count } }
}

// 服务端合并语义（对照）
// qty 冲突: max(本地, 远端) —— 各端 +1 都算数
// delete vs edit: delete 胜 —— 删除优先
// pending + remote: 并集保留 —— 本地在途不丢
// version: 单调递增 —— 旧推送丢弃
```
