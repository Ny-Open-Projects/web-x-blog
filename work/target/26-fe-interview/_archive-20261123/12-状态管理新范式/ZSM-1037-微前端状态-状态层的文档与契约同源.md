## 1037：契约文档与运行时校验的同源生成

**答**：
- 同源问题：契约文档（手册写的）与运行时校验（schema 写的）两处维护必然漂移（文档说字段叫 id 实际叫 orderId）——同源生成：schema（单一真相）-> 自动生成「运行时校验器 + 类型 + 文档」。
- schema 形态：JSON Schema / zod（运行时可执行）——文档站从 schema 渲染（字段表/示例/变更历史自动产出）。
- 变更历史：schema 入 Git，PR 即契约变更记录（diff 自动生成变更说明——破坏性变更标红提示评审）。
- 追问钩子：为什么「文档同源」在微前端格外重要？——跨团队的文档与代码分别维护，漂移概率指数级高于单体（没人看得全）；schema 单源让「文档=代码=校验」三合一——漂移在结构上不可能。

```ts
// schema 单源：zod
export const orderUpdated = z.object({
  v: z.literal(1), id: z.string(), status: z.enum(ORDER_STATUSES),
});
// 生成：运行时校验器 / TS 类型 / 文档站（字段表自动渲染）
// PR diff -> 变更历史（破坏性变更标红）
```
