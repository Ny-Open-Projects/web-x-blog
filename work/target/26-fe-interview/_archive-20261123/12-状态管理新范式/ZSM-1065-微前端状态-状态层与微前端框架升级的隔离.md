## 1065：微前端框架升级时状态层的冻结保障

**答**：
- 升级风险：框架升级（qiankun->wujie）时状态层的「隐性框架依赖」暴露（用了框架的 initGlobalState/生命周期钩子细节）——升级 = 状态层重写的灾难。
- 冻结保障：状态层的「框架接触面」收敛到适配器（见可移植性卡）——升级只改适配器；接触面的度量（状态层代码 import 框架包的数量——目标 0，全部经适配器注入）。
- 升级演练：新框架适配器在影子环境跑（同一套契约测试/泄漏测试对适配器跑——状态层行为不变性验证——换框架状态层零改动是验收标准）。
- 追问钩子：为什么「接触面为零」是可度量的冻结保障？——「理论上没依赖」不可验证（隐性依赖总在细节里）；import 计数是可审计的硬指标（0 = 状态层对框架无知）——可度量才能冻结。

```ts
// 接触面度量（CI 守护测试）
it('state-core must not import framework packages', () => {
  const offenders = scan('src/state-core', /from ['"](qiankun|wujie|single-spa)['"]/);
  expect(offenders).toEqual([]);      // 接触面 = 0
});
// 升级验收：同一套契约/泄漏测试对新适配器全绿
```
