## ZSM-316：WS 推送驱动的状态怎么保证一致性（seq/补拉）

**答**:
- 推送不可靠：会丢、会乱序、会断——协议上必须带单调递增 seq，客户端检测到跳号就「补拉快照」，不能默默吞掉空洞
- 一致性基线：重连后先拉当前快照（含最新 seq），再消费新事件；快照与增量用同一 seq 空间
- 应用到状态：事件写 store 用「幂等 upsert」（按 id 覆盖），重复推送天然安全；排序类事件要按 seq 处理
- 兜底：长连接不可用降级轮询（网络层降级链），seq 校验同样适用

```javascript
ws.onmessage = (e) => {
  const { seq, type, data } = JSON.parse(e.data)
  if (seq !== lastSeq + 1) { fetchSnapshot().then(applyFull); lastSeq = snap.seq; return }  // 空洞补拉
  lastSeq = seq
  applyEvent(type, data)          // upsert：按 id 覆盖，天然幂等
}
ws.onclose = () => setTimeout(connect, backoff())   // 指数退避重连 → 重连后先快照
```
