## ZSM-888：状态层的性能红线一页纸：可直接抄进团队规范

**答**：
- 把分散在各卡的性能纪律收敛成「一页纸红线」（可直接进团队规范/PR 模板）——八条红线每条带检测方式：
- **R1 通知纪律**：一次交互 setState ≤ 3 次——检测：探针计数（562）。
- **R2 订阅纪律**：selector 返回对象必须 useShallow/标量——检测：eslint（780）。
- **R3 退订纪律**：subscribe/EventListener 必须在 cleanup——检测：平衡检查器（610）。
- **R4 序列化纪律**：persist 必须 partialize + 节流 ≥1s——检测：lint + stringify 探针（605）。
- **R5 重渲预算**：单次 commit ≤ 16ms、组件 ≤ 30（后台类）——检测：BudgetGate CI（616）。
- **R6 每帧纪律**：动画/拖拽路径禁 setState（transient 强制）——检测：帧循环标记（763）。
- **R7 内存纪律**：缓存 Map 必须有淘汰策略、快照/历史必须有上限——检测：巡检器（565）。
- **R8 竞态纪律**：写操作必须幂等键 + 乐观必须有回滚——检测：审计八问 PR 模板（766）。
- 红线的执行强度分级：R1/R3/R8 违规阻断合并（正确性），R2/R4/R6 lint error，R5/R7 门禁告警（性能预算）。
- 追问钩子：红线的「豁免流程」——超标场景必须走 ADR 豁免（写明原因+限期+补偿措施），无豁免的违规按红线处置——制度要有出口才可持续。

  { id: 'R3', rule: 'subscribe/EventListener 必 cleanup', detect: '平衡检查器(610)', level: '阻断' },
  { id: 'R4', rule: 'persist 必 partialize + 节流≥1s', detect: 'lint + stringify探针(605)', level: 'lint error' },
  { id: 'R5', rule: '单次 commit ≤16ms、组件≤30', detect: 'BudgetGate CI(616)', level: '告警' },
  { id: 'R6', rule: '动画/拖拽路径禁 setState', detect: '帧循环标记(763)', level: 'lint error' },
  { id: 'R7', rule: '缓存Map必有淘汰、快照/历史必有上限', detect: '巡检器(565)', level: '告警' },
  { id: 'R8', rule: '写操作必幂等键、乐观必回滚', detect: '审计八问(766)', level: '阻断' },

// 执行分级：正确性(R1/R3/R8)=阻断 | 纪律(R2/R4/R6)=lint | 预算(R5/R7)=告警
// 豁免流程：超标走 ADR（原因+限期+补偿），无豁免按红线处置
