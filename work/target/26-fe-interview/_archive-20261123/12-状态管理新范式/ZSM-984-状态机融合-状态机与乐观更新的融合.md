## 984：状态机 + 乐观更新的融合（提交过程的防错）

**答**：
- 融合动机：乐观更新的「提交中/成功/失败回滚」三态与 UI 交互交织（提交中禁止编辑、失败回编辑态并提示）——用状态机建模提交过程（editing -> saving -> saved/error），乐观写入在 saving 入口动作、回滚在 error 入口动作。
- 实现要点：mutation 的生命周期映射机器事件（mutate -> SAVE 事件、onSuccess -> SAVED、onError -> FAILED）；乐观值与回滚快照存机器 context（生命周期与数据同源）。
- 收益：提交过程的所有交互规则（可否再点/可否离开/失败后可否重试）由状态图表达——「提交中双击」这类经典 bug 结构性消失。
- 追问钩子：为什么不用 isPending 布尔就够了？——单按钮 isPending 够；但「提交中有未保存编辑/提交失败后部分字段锁定/重试计数」的组合场景，布尔组合会爆炸——状态机是组合复杂度的解法。

```ts
const submitMachine = createMachine({
  initial: 'editing',
  context: { draft: null, snapshot: null, tries: 0 },
  states: {
    editing: { on: { SAVE: { target: 'saving',
      actions: assign(c => ({ snapshot: c.draft, tries: c.tries + 1 })) } } },
    saving: { on: { SAVED: 'saved', FAILED: { target: 'editing',
      actions: assign(c => ({ draft: c.snapshot })) } } },   // 乐观回滚
    saved: { type: 'final' },
  },
});
```
