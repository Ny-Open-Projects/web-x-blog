## ZSM-170：专题总结：状态管理新范式里最典型的 8 个反模式是什么？各自的正解一句话是什么？
**答**：
- ① 接口数据塞全局 store 手动维护 loading/error → 正解：服务端数据交给缓存库，组件只消费状态机。
- ② selector 返回内联新建对象/数组导致死循环重渲染 → 正解：浅比较（useShallow）或拆成原始值 selector（018/039 已考细节，这里考清单化）。
- ③ 一个巨型单 store 无切片无命名空间 → 正解：按域切片、key 工厂、owner 唯一。
- ④ 用缓存库/全局 store 存弹窗开关等瞬态 UI 态 → 正解：useState 或局部 atom，生命周期就近。
- ⑤ 乐观更新无快照无回滚 → 正解：快照 + 回滚 + 对账三件套。
- ⑥ 双 owner（URL 与 store 同存页码）→ 正解：定一个 owner，另一个派生。
- ⑦ mutation 后无差别 invalidate 全库 → 正解：精确 key + 失效清单跟资源定义同文件。
- ⑧ 表单逐键同步进全局 store → 正解：表单库管值，store 只存快照与提交结果。
- 答题技巧：反模式清单要能「对照自己项目各给一个实例」，比背概念高一档。

```javascript
// 快速自检脚本：扫出可疑反模式
// 1) 无 queryFn 的缓存写入（幽灵 key）
const ghostKeys = queryCache.getAll().filter(q => !q.queryFn)
console.warn('幽灵 key:', ghostKeys.map(q => q.queryKey))

// 2) selector 每次渲染返回新引用
const susSelectors = grepInRepo(/create\(\s*\(\)\s*=>\s*\(\{/)   // store 全量解构提示

// 3) store 里出现 loading + saving 双布尔组合
const suspiciousFlags = /loading.*&&.*saving|isLoading.*&&.*isSaving/

// 4) 双 owner 检测：同名字段既在 store 又在 useSearchParams 解构中
const dualOwner = diff(
  Object.keys(useStore.getState()),
  ['page', 'kw', 'sort', 'tab']
)
```
