## 1013：老系统渐进迁移到微前端的状态过渡策略

**答**：
- 过渡期形态：老系统（单体）与新微应用并存——老系统的全局状态（window.xxx/jQuery 时代的全局）与新应用状态共存；策略：适配层（老全局状态的读写代理——新应用通过适配层访问，不动老代码）。
- 数据双源的过渡：老系统与微应用各有用户态（双源）——过渡期以「老系统为权威」（适配层透传），微应用不自持用户态；迁移完成后权威转移（适配层反转为微应用侧）。
- 迁移节奏：按页面切片迁移（一个业务页面 = 一个新微应用）——过渡期路由混合（部分页面单体/部分微前端），状态适配层保证跨页一致性。
- 追问钩子：为什么过渡期「老系统为权威」？——双源并存时权威必须单点（否则两边漂移）；老系统是既成事实（数据流已稳定），新应用适配它成本最低——权威转移是迁移的最后一步不是第一步。

```ts
// 适配层：透传老系统全局状态
export const legacyAdapter = {
  getUser: () => window.__legacy_user || null,       // 老系统权威
  onUserChange: (fn) => legacyBus.subscribe('user.changed', fn),
};
// 微应用只消费适配层，不直接碰 window.__legacy_user
```
