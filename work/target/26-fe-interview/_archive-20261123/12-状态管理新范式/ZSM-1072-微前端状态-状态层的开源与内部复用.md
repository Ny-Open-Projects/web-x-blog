## 1072：状态层基座的开源化或跨项目复用评估

**答**：
- 复用评估：基座（总线/门/SDK）的「通用度」检查——抽掉业务语义（事件名/权限模型）后剩多少（通用核心 vs 业务壳）；通用核心可开源或跨项目复用，业务壳留项目。
- 开源的合规前置：公司开源审批/无业务语义泄漏/文档通用化——收益（社区反馈/品牌）与维护成本（issue 处理）权衡。
- 内部复用的形式：模板仓库（新微前端项目 clone 起步——含 SDK/契约模板/测试基建）比 npm 包更适合内部（模板可整体定制）。
- 追问钩子：为什么「模板仓库」优于「npm 包」做内部复用？——npm 包是黑盒依赖（升级受制于包作者/定制要提 PR）；模板是白盒起点（项目自由演进——代价是无法统一升级）——内部小生态用模板，公共生态用包。

```txt
复用评估：
基座抽业务语义 -> 通用核心（可开源/跨项目）
业务壳留项目
内部形式：模板仓库（clone 起步，自由演进）
> npm 包（黑盒依赖，升级受制）
开源前置：合规审批 / 脱敏 / 通用化文档
```
