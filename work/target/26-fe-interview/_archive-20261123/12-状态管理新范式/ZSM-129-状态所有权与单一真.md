## ZSM-129：「单一数据源」在分层架构里怎么落地？状态所有权冲突怎么裁决？
**答**：
- 落地规则：每个状态有且只有一个「可写 owner」，其他位置只允许「派生读取」——服务端数据 owner 是缓存库、URL 状态 owner 是路由、业务全局 owner 是唯一 store、局部状态 owner 是组件。
- 常见冲突与裁决：页码既在 URL 又在 store → URL 赢，store 派生；用户信息在 Query 缓存又复制进 Zustand → 缓存赢，Zustand 只存「客户端偏好」；表单值既要实时校验又要草稿 → 组件内 reducer 是 owner，草稿层只在失焦时快照。
- 检测方法：grep 全库 set 调用点，同一份数据有多个写入方即违例；code review 时问一句「这个状态的 owner 是谁」。
- 冲突裁决的本质是「生命周期最长者当 owner」：URL 比组件活得久、服务端比客户端活得久。

```javascript
// 冲突案例：页码的 owner 裁决
// ❌ 双 owner：URL 和 store 都写 page，刷新/回退必失同步
const usePageStore = create((set) => ({ page: 1, setPage: (page) => set({ page }) }))

// ✅ URL 是唯一 owner，store 只派生不可写
const params = useSearchParams()
const page = Number(params.get('page') ?? 1)      // 读：从 URL 派生
const setPage = (p) => setSp({ page: String(p) }) // 写：只能写 URL

// 派生读取示例：缓存层服务端数据 + store 派生选中集合
const selectedIds = useSelectionStore(s => s.ids)            // owner: selection store
const { data: goods } = useQuery({ queryKey: ['goods', page],
                                   queryFn: () => api.goods(page) })
const selectedRows = goods?.list.filter(g => selectedIds.has(g.id)) // 派生，不复制
```
