## 1019：微前端场景状态层的性能预算分配

**答**：
- 预算分配：每个子应用的状态层开销（store 创建/订阅/持久化）+ 总线开销（事件分发）+ 主应用状态门开销——总预算按「主 X + 每子 Y」分配（超预算的应用排查——状态层通常是重复订阅/大对象拷贝）。
- 常见超标点：子应用重复订阅同一事件（N 个订阅者各拉全量数据）、store 快照深拷贝（大对象的 structuredClone 高频调用）、事件 payload 过大（全量数据广播——见事件风暴卡）。
- 度量方式：Performance API 打点（store 创建/订阅回调耗时）、内存快照（heap size 按应用标签对比——泄漏应用定位）、事件分发耗时（总线 instrumentation）。
- 追问钩子：为什么微前端的状态层性能问题比单体更隐蔽？——单体里一个 store 的性能一眼可见；微前端里 N 个应用的「各自合理」叠加成整体超标（每个子应用 100 个订阅 × 8 个应用）——预算必须按「全局总量」管理。

```ts
// 性能预算 instrumentation
performance.mark('bus:publish:start');
bus.publish(event, payload);
performance.measure('bus:publish', 'bus:publish:start');
// 每应用上报：subscriptions 数 / store 大小 / 事件耗时
reporter.gauge('mf_state_subs', app, subsCount);
```
