## ZSM-391：场景题示范：内嵌 iframe 支付页与宿主的状态桥

**答**:
- 通道唯一化：宿主与 iframe 只走 postMessage RPC（协议化：ready/pay/result/cancel + 幂等 id + 超时），状态不直接跨域共享（硬隔离）
- 生命周期握手：iframe load → ready 消息 → 宿主下发会话参数（订单号/金额只读锁定）→ 业务交互 → result 上报 → 宿主驱动整页 FSM 转移
- 超时语义：pay 调用超时不等于失败——轮询订单状态接口裁决（支付可能已成功），防止用户被误导重复支付
- 安全面：origin 双校验、金额等关键参数以宿主下发为准（iframe 只回执）、result 消息带订单号校验

```javascript
// 宿主侧
const rpc = createRpc(payIframe.contentWindow, PAY_ORIGIN)
await rpc.call('init', { orderId, amountLocked: true })     // 参数锁定
const res = await rpc.call('pay', {}, 120_000).catch(() => null)
const order = await pollOrder(orderId)                       // 超时后接口裁决
if (order.status === 'PAID') gotoSuccess()
```
