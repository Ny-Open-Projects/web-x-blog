## ZSM-694：在线协作的在场状态（presence）：光标、选区与活跃成员的管理

**答**：
- presence 是「会消失的状态」：光标位置、选区、头像、输入中提示——特点：高频更新、不需要持久化、过期要自动清理。与内容状态（文档数据）严格分通道：presence 走 WS 轻量广播（可丢帧），内容走可靠通道。
- 生命周期设计：`join → active(idle timeout 内有更新) → idle(30s 无更新) → leave(关闭页/WS 断)`。服务端对每个成员维护 lastActive，广播成员列表时带超时信息；客户端本地也要「灰显掉线成员」的降级（WS 心跳丢失 10s 即本地标记 idle，不等服务端确认）。
- 光标节流与合并：光标移动高频（每帧），广播节流到 ~30ms 一次且只发最终位置；接收端合并——同一用户的连续光标更新只保留最后一个（丢弃中间帧），节流渲染（rAF 批量更新 DOM）。
- Ephemeral 状态的正确载体：Yjs Awareness、自建 presence channel——都遵循「本地乐观更新 + 广播 + 过期清理」，不进持久层。
- 追问钩子：presence 泄漏的兜底——页面关闭不一定触发 WS close（断电/杀进程），服务端的 TTL 清理是最终一致性来源；客户端渲染时对「超过 TTL 的 presence」做本地过滤，防僵尸光标。

```javascript
// Presence 引擎（客户端侧）
class PresenceEngine {
  #me = { id, name, color }
  #peers = new Map()          // userId -> { cursor, lastSeen, status }
  #sendThrottle = null

  constructor(ws, { idleMs = 30000, ttlMs = 60000 } = {}) {
    this.idleMs = idleMs
    this.ttlMs = ttlMs
    ws.on('presence', (msg) => this.#onRemote(msg))
    // TTL 清理：僵尸光标过滤
    setInterval(() => {
      const now = Date.now()
      for (const [id, p] of this.#peers) {
        if (now - p.lastSeen > ttlMs) this.#peers.delete(id)      // 超时移除
        else if (p.status !== 'idle' && now - p.lastSeen > idleMs) {
          p.status = 'idle'                                        // 灰显
          this.notify()
        }
      }
    }, 5000)
    window.addEventListener('pagehide', () => this.leave())
  }

  setCursor(cursor) {
    // 节流广播 30ms：只发最终位置
    clearTimeout(this.#sendThrottle)
    this.#sendThrottle = setTimeout(() => {
      this.#me.cursor = cursor
      ws.send({ type: 'presence', user: this.#me, ts: Date.now() })
    }, 30)
  }

  #onRemote({ user, ts }) {
    const p = this.#peers.get(user.id) ?? { status: 'active', lastSeen: 0 }
    // 合并：同用户只保留最新光标
    p.cursor = user.cursor
    p.lastSeen = Math.max(p.lastSeen, ts)
    p.status = 'active'
    this.#peers.set(user.id, p)
    this.notify()
  }

  leave() { ws.send({ type: 'presence-leave', userId: this.#me.id }) }
}
```
