## ZSM-360：状态层的测试金字塔怎么搭（单测到 E2E 比例）

**答**:
- 三层比例：纯逻辑单测 70%（reducer/selector/中间件，毫秒级）→ hook/store 集成 20%（renderHook + MSW）→ 关键流程 E2E 10%（真实 store + 接口 mock 的全链路）
- 单测重点：竞态与幂等（并发事件序列）、失效映射正确性（写操作触发预期失效）、边界（空态/异常响应）——这些 E2E 根本测不到
- 集成重点：订阅时序（setState 后 hook 更新）、Suspense/复水行为、与路由联动
- E2E 只锁「不可再拆的关键路径」：下单/支付全流程——状态错误导致的用户级故障在此兜底
- 反模式：E2E 占比过高（慢且脆）、mock 过深测不到真实行为、只测 happy path

```javascript
// 金字塔示意（一域）
describe('cart domain', () => {
  unit(cartReducer, [/* 表驱动 30 例 */])
  unit(selectors, [/* 派生与边界 20 例 */])
  integration(() => {/* renderHook + MSW 5 例：订阅时序/失效联动 */})
  e2e('下单全流程', 1)      // 全链路唯一一条
})
```
