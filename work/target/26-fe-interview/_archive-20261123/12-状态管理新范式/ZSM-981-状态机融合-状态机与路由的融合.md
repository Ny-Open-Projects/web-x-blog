## 981：路由状态与业务状态机的融合模式

**答**：
- 融合模式：状态机的状态映射路由（machine 状态 -> 路由路径），路由变化作为「事件」发给机器（URL 是状态的序列化形式）——双向同步：机器迁移 -> navigate；URL 变化 -> send 事件。
- 收益：多步骤流程的「每步一个 URL」（可分享/可回退/可刷新恢复）——流程状态不再只存内存（刷新丢流程），URL 即持久化。
- 实现要点：路由跳转触发机器事件时防循环（机器迁移触发 navigate，navigate 触发事件，事件再迁移——同一目标态要幂等跳过）；用「目标态一致性检查」防循环。
- 追问钩子：为什么「URL 即状态」对多步流程这么关键？——用户中途分享给同事（同事直接打开第 3 步）/客服让用户「回到第 2 步」（直接给 URL）——流程的协作与恢复都依赖 URL 化。

```ts
// 双向同步：机器 <-> 路由
actor.subscribe(state => {
  const path = STATE_TO_PATH[state.value];       // 机器 -> URL
  if (location.pathname !== path) history.push(path);
});
window.addEventListener('popstate', () => {
  const ev = PATH_TO_EVENT[location.pathname];   // URL -> 事件
  if (ev && actor.getSnapshot().value !== PATH_TO_STATE[location.pathname]) {
    actor.send(ev);                              // 目标态一致则跳过（防循环）
  }
});
```
