## 1033：微前端状态层的团队知识传递

**答**：
- 上手材料：状态架构总图（主子应用的状态流与事件流——一张图看懂全景）、契约手册（每事件/每注入 API 的语义与示例）、调试手册（快照/录制器/常见问题定位路径）。
- 传递机制：新人先「读契约跑通一个最小子应用」（从 mount 到发布一个事件——闭环体验）再碰业务；老带新时重点传「契约变更流程」与「调试工具用法」（这两样文档学不会）。
- 知识保鲜：契约手册与代码同步 PR、季度架构走查（图与实现偏差校对）——微前端的知识分散在各团队，中心化文档是唯一粘合剂。
- 追问钩子：为什么微前端的知识传递比单体更依赖文档？——单体的知识在同一个代码库里（读代码可懂）；微前端的知识跨 N 个仓库与团队（全读一遍不现实）——中心化的契约手册是跨仓知识的唯一入口。

```md
## 微前端状态上手包
1. 架构总图（状态流+事件流）
2. 契约手册（事件/API 语义与示例）
3. 调试手册（快照/录制器/定位路径）
4. 最小子应用示例（mount -> 发布事件 -> 失效联动）
机制：文档与代码同 PR / 季度走查
```
