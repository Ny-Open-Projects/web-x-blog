## ZSM-609：状态优化的内存维度：五个常见泄漏面与检测方法

**答**：
- 泄漏面一 **订阅未退订**：组件外 subscribe、BroadcastChannel、window 事件在组件卸载/页面关闭后残留。检测：DevTools Memory 快照对比，Detached 节点；或订阅计数探针（add/remove 差值不为零告警）。
- 泄漏面二 **Map 家族只增不减**：atomFamily/缓存 Map 无淘汰策略，长会话无限增长。检测：size() 监控 + 快照 diff；修法：LRU/TTL/setShouldRemove。
- 泄漏面三 **闭包持引用**：订阅回调捕获大对象（整个列表快照），回调存活即大对象存活。检测：Memory 面板的 Retainers 链找「谁拽住了它」。修法：回调只持 id，按需取值。
- 泄漏面四 **历史无限累积**：时间旅行快照、变更日志、undo 栈无上限。检测：长会话内存曲线只升不降。修法：环形缓冲 + 锚点压缩（ZSM-562）。
- 泄漏面五 **事件监听叠加**：StrictMode/热更新下 effect 反复注册（清理函数缺失）。检测：getEventListeners(window)（DevTools console）；修法：effect 必须返回退订。
- 方法论：内存优化是「曲线验证」型工作——录制 10 分钟会话的 heap 曲线，修复后同脚本复测，看锯齿是否回落。

```javascript
// 订阅计数探针：全局泄漏哨兵
const subCounter = (() => {
  let active = 0
  const log = []
  return {
    track(label, subscribeFn) {
      return (...args) => {
        active++
        log.push({ label, op: 'add', active, ts: Date.now() })
        const unsub = subscribeFn(...args)
        return () => {
          unsub()
          active--
          log.push({ label, op: 'remove', active, ts: Date.now() })
        }
      }
    },
    snapshot: () => ({ active, log: log.slice(-20) }),
    assertBalanced: (label) => {
      const adds = log.filter((l) => l.label === label && l.op === 'add').length
      const removes = log.filter((l) => l.label === label && l.op === 'remove').length
      if (adds !== removes) console.warn(`[泄漏] ${label}: add=${adds} remove=${removes}`)
    },
  }
})()

// 用法
const trackSub = subCounter.track('im-session', (id) => useIM.subscribe(() => {}))

// Map 泄漏监控
function watchMapGrowth(map, name, { max = 1000 } = {}) {
  setInterval(() => {
    if (map.size > max) {
      console.warn(`[泄漏] ${name}.size=${map.size} 超阈值，考虑 LRU`)
    }
  }, 30000)
}
```
