## ZSM-256：子应用独立部署时状态契约怎么保证不破坏其他应用

**答**:
- 契约即 API：共享状态的 shape、事件名、payload 结构是跨应用 API，必须版本化（shared-store 的 type 包独立发包，semver 管理）
- 消费者按「宽容读取」写：读字段判空兜底，不假设字段永远存在——新版本加字段不破坏旧消费方（类似 protobuf 演进原则）
- CI 门禁：共享 store 类型包发 minor/breaking 变更时跑全子应用的契约测试（mock 上下游事件验证）
- 运行时自检：dev 环境对 shared state 做 schema 校验，shape 违规直接报错定位到违规应用

```javascript
// shared-state-types 独立包（版本化）
export interface SharedStateV1 { user: UserDTO | null; theme: 'dark' | 'light' }
// 子应用宽容读取
const theme = shared.get()?.theme ?? 'dark'        // 字段缺失兜底
// dev 自检
if (import.meta.env.DEV) assertSchema(shared.get(), sharedSchemaV1)
```
