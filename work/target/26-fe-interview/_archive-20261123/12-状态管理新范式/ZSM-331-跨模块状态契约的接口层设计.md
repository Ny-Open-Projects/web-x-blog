## ZSM-331：多团队共用的状态模块怎么设计契约接口层

**答**:
- 契约层三原则：只暴露稳定 API（读 hook + 动作函数），不暴露原始 setState；类型包独立发版（semver）；破坏性变更加 deprecation 周期（旧 API 保留一个版本并打警告）
- 写路径收敛：外部模块不能直接改内部结构，只能调「意图化动作」（addToCart 而非 setCart），内部结构随意重构不受外部影响
- 读路径稳定：hook 返回的是「视图模型」（已经裁剪/派生），内部数据结构变化不外泄；未消费字段不进类型
- 治理：契约变更走 RFC/评审，CI 做类型兼容检查（ts-bench/api-extractor），消费方升级在 lockfile 可见

```javascript
// cart-contract 包（对外）
export interface CartApi {
  items: () => CartItemVM[]            // 视图模型
  useTotal(): number
  addItem(item: AddItemInput): void    // 意图化动作
  removeItem(id: string): void
}
// 内部实现自由重构，只保证 contract 不变；@deprecated(removed in v3) 管过渡
```
