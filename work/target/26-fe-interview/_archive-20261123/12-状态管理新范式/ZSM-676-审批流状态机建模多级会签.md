## ZSM-676：审批流的状态机建模：多级会签与回退分支怎么表达

**答**：
- 审批流的复杂度在「分支语义」：或签（任一通过即过）、会签（全部通过才算过）、加签（临时插入节点）、回退（退回指定节点重走）——这些用「散装布尔 + if-else」必出错，用状态机表达：每个审批节点是一个状态，迁移由守卫（会签进度判断）驱动。
- 会签建模：节点状态内部记录 `context.signers: Map<uid, 'pending'|'approved'|'rejected'>`，`on: APPROVE` 的守卫是「全部 approved」；或签守卫是「任一 approved」。**节点状态与签署状态分离**——控制流（当前节点）用 finite state，签署集合用 context。
- 回退建模：目标节点是动态的（退到发起人/上一节点/指定节点），用 `send` 带 `target` 参数的事件迁移：`on: REJECT_TO: [{ target: ({ event }) => event.to, actions: resetNode }]`；回退要清理目标节点之后所有节点的签署记录（否则重走时残留旧签）。
- 加签建模：不改状态机拓扑，在 context 的 `signers` 里插入临时签署人并要求新加者通过后回到原守卫判断——「加签是数据变更，不是流程变更」是关键设计判断。
- 追问钩子：审批流的「服务端权威 + 前端投影」——前端状态机做 UI 交互态（防止重复点击/展示当前节点），流程推进由服务端事件驱动（WS 推送节点变更），前端状态机消费事件而非自作主张迁移。

```javascript
import { setup, createActor } from 'xstate'

const approvalMachine = setup({
  guards: {
    counterSignDone: ({ context }) =>
      [...context.signers.values()].every((s) => s === 'approved'),
    anyApproved: ({ context }) =>
      [...context.signers.values()].some((s) => s === 'approved'),
  },
}).createMachine({
  id: 'approval',
  context: ({ input }) => ({
    nodeId: input.nodeId,
    signers: new Map(input.signers.map((u) => [u, 'pending'])),
    history: [],
  }),
  initial: 'pending',
  states: {
    pending: {
      on: {
        SIGN: {
          actions: ({ context, event }) => ({ context: { signers: context.signers.set(event.uid, event.decision) } }),
        },
        // 或签：任一通过 → passed
        NEXT: [
          { guard: 'anyApproved', target: 'passed' },
        ],
        // 会签：全部通过 → passed
        COMPLETE_NODE: [{ guard: 'counterSignDone', target: 'passed' }],
        // 回退：动态目标 + 清理后续签署
        REJECT_TO: {
          target: ({ event }) => event.targetNode,
          actions: ({ context, event }) => ({
            context: {
              ...context,
              signers: new Map(event.targetNode.signers.map((u) => [u, 'pending'])),  // 清残留
              history: [...context.history, { from: context.nodeId, to: event.targetNode.id }],
            },
          }),
        },
      },
    },
    passed: { type: 'final' },
  },
})

// UI 消费：只读当前节点 + 签署集合，推进由服务端事件驱动
const actor = createActor(approvalMachine, { input: { nodeId: 'n1', signers: ['a', 'b'] } })
actor.start()
actor.send({ type: 'SIGN', uid: 'a', decision: 'approved' })
```
