## 1001：微前端主子应用的状态契约怎么设计

**答**：
- 契约三部分：主应用提供的（用户态/权限/主题——通过 props 或专用 API 注入，子应用只读）、子应用发布的（实体变更事件——order.updated 类）、子应用私有的（页面 UI 状态——永不外泄）。
- 注入方式的选择：props 注入（初始化时——适合不变数据）、共享 API（auth.getUser() 函数注入——子应用按需取，主应用控制实现）、事件（变更通知——松耦合）；禁用「子应用直接读主应用的全局变量」（隐式耦合不可控）。
- 契约文档化：每个子应用的 manifest 声明依赖与发布事件（依赖清单+事件清单进 CI 校验——未声明的依赖报错）。
- 追问钩子：为什么「子应用私有状态永不外泄」是契约核心？——外泄的私有状态会被其他子应用依赖（隐式契约），主应用重构/子应用下线时牵一发动全身——契约的价值就是把耦合显式化并最小化。

```ts
// 子应用 manifest（契约声明）
export const manifest = {
  name: 'order-app',
  requires: ['auth', 'theme'],
  provides: ['order.updated', 'order.created'],
};
// 主应用注入：mount(el, { auth, theme, bus })
```
