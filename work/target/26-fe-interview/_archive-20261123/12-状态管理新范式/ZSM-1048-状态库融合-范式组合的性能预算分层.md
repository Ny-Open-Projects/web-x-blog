## 1048：多范式的性能预算分层（各层预算独立）

**答**：
- 分层预算：Query（请求数/缓存体积——见 Query 大盘）、Zustand（订阅数/重渲染率）、XState（实例数/事件处理耗时）、组件（渲染时长）——各层独立预算与看板（跨层问题定位到层）。
- 跨层的复合性能问题：一次状态变更跨层传播（机器事件 -> zustand -> Query 失效 -> refetch -> 组件重渲染）——传播链的端到端耗时拆解（各层耗时打点——链路瓶颈定位）。
- 预算的守门：CI 基准测试（关键操作链路的各层耗时断言——回归拦截）、线上 RUM（真实用户的操作链路耗时采样）。
- 追问钩子：为什么跨层链路要「端到端耗时拆解」？——用户感受到的是「点击后 800ms 才反馈」，但四层各 200ms 的归因需要拆解（没有拆解就不知道优化哪层）——性能优化的第一步永远是归因而非猜测。

```ts
// 跨层链路打点
const t = trace.start('submit_order');
actor.send({ type: 'SUBMIT' });                 // 机器层
trace.mark(t, 'machine');
store.commit();                                  // zustand 层
trace.mark(t, 'store');
qc.invalidateQueries(orderKeys.all);             // Query 层
trace.mark(t, 'query');
trace.end(t);                                    // 端到端 + 分段耗时
```
