## ZSM-392：场景题示范：表格行内编辑并发保存状态

**答**:
- 行级状态机：viewing→editing→saving→done/failed；每行独立互不阻塞；保存中该行锁定（禁再次提交），其他行可继续
- 提交策略：失焦保存（onBlur+值变化判定）或显式保存按钮；同一单元格连续编辑 debounce 合并，避免每键一请求
- 冲突处理：服务端版本比对（baseVersion）失败 409 → 行级冲突标记（黄条 + 「拉取最新」按钮），不打断整表
- 验证与回滚：保存失败恢复原值并标红提示；成功用服务端返回值覆盖（时间戳/审计字段统一）

```javascript
const rowState = useStore((s) => s.rowStates[id])   // per-row FSM
const save = useMutation({
  mutationFn: (patch) => api.updateRow(id, { ...patch, baseVersion: row.version }),
  onMutate: () => setRowState(id, 'saving'),
  onSuccess: (server) => { setRow(id, server); setRowState(id, 'done') },
  onError: (e) => e.status === 409 ? setConflict(id, e.body) : (rollback(id), setRowState(id, 'failed')),
})
```
