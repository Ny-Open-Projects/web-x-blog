## 1021：模块联邦下共享依赖（React/状态库）的版本冲突

**答**：
- 冲突场景：主应用 React 18、子应用 React 17（各自打包自己的 React——双 React 实例 = hooks 失效/context 断裂——状态 Provider 跨应用失效的经典事故）；共享依赖（模块联邦 shared）的版本协商（singleton + requiredVersion——不满足版本时回退各自打包）。
- 状态层的特殊敏感性：状态库实例必须单例（两个 Zustand 实例 = 两份数据；两个 QueryClient = 缓存断裂）——shared 配置里状态库 singleton: true 是硬要求。
- 版本策略：主应用锁定状态库版本（子应用 requiredVersion 匹配——semver 范围），降级链（子应用版本不匹配 -> 警告 + 用主应用版本（若兼容）-> 严重不匹配子应用自带（放弃状态互通））。
- 追问钩子：为什么「双 React 实例」对状态层是致命的？——Context 是按 React 实例隔离的（A 实例的 Provider 在 B 实例的组件里读不到）——QueryClientProvider/Zustand context 全部失效，状态层静默断裂（不报错，数据各自为政）。

```js
// 模块联邦 shared 配置（状态库必须 singleton）
shared: {
  react: { singleton: true, requiredVersion: '^18.0.0' },
  'react-dom': { singleton: true, requiredVersion: '^18.0.0' },
  zustand: { singleton: true },   // 状态库实例必须唯一
}
// 版本不匹配降级链：警告 -> 用主版本 -> 严重不匹配自带
```
