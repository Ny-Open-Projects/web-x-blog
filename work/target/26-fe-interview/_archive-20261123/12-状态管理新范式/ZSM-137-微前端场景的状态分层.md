## ZSM-137：微前端/多团队场景下状态怎么分层？跨应用的缓存与 store 隔离方案是什么？
**答**：
- 隔离原则：每个子应用独立的 QueryClient 与 store 实例（按应用前缀命名空间），杜绝单例串台；跨应用只共享「契约状态」（当前用户、租户、主题），由主应用提供。
- 契约状态用主应用发布的 `sharedStore`（或 CustomEvent 总线）单向分发，子应用只读 + 订阅变更；子应用间禁止直接互写对方 store。
- 服务端缓存隔离时 key 也要加命名空间（`['app-a', 'goods', id]`），避免同 key 不同团队语义冲突；失效广播同样带命名空间过滤。
- 面试要点：说出「微前端状态问题的根源是单例假设被打破」——window 挂载、全局 devtools、单例 store 在多实例下全部失效。

```javascript
// 子应用工厂：独立 QueryClient + 命名空间 key
export function createAppRuntime(appName) {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: 2 } },
  })
  const ns = (key) => [appName, ...(Array.isArray(key) ? key : [key])]
  return { queryClient, ns,
    invalidate: (key) => queryClient.invalidateQueries({ queryKey: ns(key) }) }
}

// 主应用契约：单向分发当前用户
export const sessionBus = new BroadcastChannel('session')
export function publishSession(me) { sessionBus.postMessage({ type: 'session', me }) }
// 子应用侧只订阅不回写：
// sessionBus.onmessage = ({ data }) => localRuntime.onSessionChange(data.me)
```
