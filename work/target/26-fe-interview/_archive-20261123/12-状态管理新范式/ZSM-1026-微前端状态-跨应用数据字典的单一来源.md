## 1026：跨应用数据字典（枚举/配置）的单一来源治理

**答**：
- 问题：订单状态枚举在 3 个子应用各写一份（魔数漂移——A 认为 2 是已支付 B 认为是已发货）——字典必须单一来源：主应用提供字典服务（或共享 npm 包@shared/dictionaries——版本锁定）。
- 共享包 vs 状态门：字典是「低频变化的结构化数据」——共享包更合适（类型安全/离线可用），状态门适合「高频变化的运行时数据」（用户态）；两者不混用。
- 字典的版本与缓存：字典包 semver（枚举值只增不删——删除是破坏性变更），子应用锁定范围版本；运行时字典（CMS 可配）走状态门 + 缓存。
- 追问钩子：为什么枚举漂移是最隐蔽的微前端事故？——魔数比对不报错（2 === 2 各自为真）但语义错位（展示「已发货」实际「已支付」）——业务事故而非技术报错，发现靠用户投诉。

```ts
// 共享字典包 @shared/dictionaries（semver 锁定）
export const ORDER_STATUS = {
  PAID: 2, SHIPPED: 3,   // 只增不删
} as const;
// 子应用 import { ORDER_STATUS } from '@shared/dictionaries';
// 模块联邦 shared: { '@shared/dictionaries': { singleton: true } }
```
