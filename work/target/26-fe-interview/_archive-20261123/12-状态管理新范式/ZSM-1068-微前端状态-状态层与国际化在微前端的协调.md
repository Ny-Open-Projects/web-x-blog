## 1068：微前端多语言的状态协调（语言切换广播与各自加载）

**答**：
- 协调设计：主应用持有当前语言（状态门提供），语言切换 -> 门广播 lang.changed -> 各子应用失效自己的语言包缓存（各自按需加载自己的文案——文案分散在各应用）。
- 各子应用的文案来源两模式：自带文案包（独立——跨应用文案重复但自治）与共享文案包（共享包@shared/i18n——公共术语统一，业务文案各自）——公共术语（按钮/通用词）共享、业务词自治。
- 切换体验：各子应用切换速度不一（语言包大小不同）——主应用切换时显示「应用中」遮罩至所有子应用确认（ready 事件回执）——或乐观切换（各应用各自完成，允许短暂混语言——按体验容忍度选）。
- 追问钩子：为什么「公共术语共享、业务词自治」？——公共术语（「确定/取消/保存」）各应用各译会不一致（用户体验割裂——同一按钮两种叫法）；业务词只有拥有方知道语义（共享会错译）——按「语义所有权」划分共享边界。

```ts
// 主应用：切换广播
gate.setLang(lang);
bus.publish('lang.changed', { lang });
// 子应用：失效 + 各自加载
bus.subscribe('lang.changed', e => {
  qc.invalidateQueries({ queryKey: ['labels', e.lang] });
});
// 共享术语包：@shared/i18n（公共按钮词）+ 各应用业务词包
```
