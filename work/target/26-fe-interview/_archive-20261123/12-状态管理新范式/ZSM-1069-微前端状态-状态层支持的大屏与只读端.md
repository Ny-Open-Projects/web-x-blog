## 1069：大屏/只读端的微前端状态轻量模式

**答**：
- 轻量模式动机：大屏/只读端（监控大屏嵌入多个子应用视图）不需要写路径/编辑锁/完整生命周期——全量 SDK 是过度配置（体积与复杂度）。
- 轻量 SDK：只读门访问 + 订阅（无 publish 权限）+ 无持久化——「能力降级的 SDK」（readonly 模式：publish 抛错/持久化禁用）——同一 SDK 两种模式（配置能力集而非两套代码）。
- 大屏特有：多子应用的数据刷新节奏协调（各子应用轮询独立——大屏的刷新频率由主应用统一下发 refetchInterval——避免各子应用各自高频轮询）。
- 追问钩子：为什么大屏要「主应用统一下发刷新频率」？——各子应用独立轮询（各自 5s）= 总请求频率是 N 倍（大屏长时间驻留放大）；主应用统一下发（一个频率源）——共享端点耗时的场景，频率权必须收口到单点。

```ts
// 只读模式 SDK
const sdk = createAppSdk('screen-app', deps, {
  capabilities: { publish: false, persist: false, editLock: false },
});
sdk.bus.publish('x', {});   // 抛错：readonly 模式无发布权限
// 主应用统一下发轮询
bus.publish('poll.interval', { ms: 10000 });   // 子应用按此设置 refetchInterval
```
