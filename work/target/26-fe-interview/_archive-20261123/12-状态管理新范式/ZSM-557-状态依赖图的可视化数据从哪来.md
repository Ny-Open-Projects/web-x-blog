## ZSM-557：状态依赖图可视化的数据从哪来：三种采集方案对比

**答**：
- 方案一 **运行时读取库内部结构**：Jotai 的 store 里 atomState.d 直接是依赖 Map，读出来就是图。优点零侵入、精确；缺点依赖库内部实现（版本升级会断），且只能看到「已实例化」的边。
- 方案二 **订阅探针**：包一层 `store.sub`/selector 执行记录，统计「谁在订阅谁」和「值变化传播到了谁」。优点反映真实传播路径（含触发频率），能发现高频重渲的图热点；缺点是只有运行过才知道，冷路径缺失。
- 方案三 **静态分析 + 手工标注**：编译期扫代码里的 `atom(get(...))` 调用建静态图。优点完整（含未实例化分支）；缺点条件分支派生的动态边无法静态确定。
- 实践建议：方案一做骨架（节点/静态边）+ 方案二做热力（边上叠加传播次数/耗时），可视化用 D3/Reactflow 渲染，节点大小=订阅者数、边粗细=传播频率。两张图层叠加才能定位「这个高频更新沿着哪条链轰炸了半个页面」。
- 通用数据模型：`{ nodes: [{ id, label, kind }], edges: [{ from, to, weight, version }] }`——与具体库解耦，换状态库图表层不用重写。

```javascript
// 方案二实现骨架：订阅探针
function instrument(store, { emit }) {
  const origSub = store.sub.bind(store)
  const edgeWeight = new Map()   // `a→b` -> count
  const nodes = new Map()

  store.sub = (atom, fn) => {
    nodes.set(atom, { label: atom.debugLabel ?? atom.id, kind: 'atom' })
    return origSub(atom, () => {
      fn()
      emit({ type: 'propagate', atom: atom.debugLabel, ts: performance.now() })
    })
  }
  // 读依赖：包 get 探针（示例性）
  return {
    graph() {
      return {
        nodes: [...nodes.values()],
        edges: [...edgeWeight.entries()].map(([k, weight]) => ({ key: k, weight }))
          .sort((a, b) => b.weight - a.weight),
      }
    },
  }
}

// 数据模型示例（库无关）
const graph = {
  nodes: [
    { id: 'cartItems', label: 'cartItems', kind: 'primitive' },
    { id: 'cartTotal', label: 'cartTotal', kind: 'derived' },
    { id: 'Badge', label: 'Badge', kind: 'component' },
  ],
  edges: [
    { from: 'cartItems', to: 'cartTotal', weight: 342, version: 17 },
    { from: 'cartTotal', to: 'Badge', weight: 342, version: 17 },
  ],
}
// weight 342 次/分钟：一条高频传播链，优化目标
```
