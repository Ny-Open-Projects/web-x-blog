## ZSM-898：状态库选型的成本总账：引入一个库的完整成本模型

**答**：
- 引入任何状态相关库的完整成本（不止 bundle 体积）——五项成本模型：
- 1) **体积成本**：gzip 后 KB + 间接依赖（如 immer 带 Proxy polyfill 评估）。
- 2) **学习成本**：团队 ramp-up 人日（心智模型差异——XState 的 actor 模型 ≈ 3 人日/人）。
- 3) **维护成本**：版本升级跟进、breaking change 应对、安全补丁——按库活跃度估年化人日。
- 4) **迁移成本**：从现有方案迁入的一次性投入（ZSM-714 五步法）+ 迁移期双栈共存体积。
- 5) **风险成本**：库停止维护的退出成本（导出层封装隔离，防止 API 渗透到业务代码——「防腐层」）。
- 总账公式：`年化成本 = 体积成本(固定) + 学习成本(一次性) + 维护成本(年化) + 迁移成本(一次性摊销) + 风险成本(保险费)`——与收益（ZSM-774）对比决定引入。
- 防腐层设计：所有第三方状态库的 API 通过自家薄封装暴露（`ourStore = create()` 内部用 zustand）——换库只改封装层。代价：类型推导链变复杂（ZSM-525 的柯西化被封装打断）——防腐层的取舍要显式决策。
- 追问钩子：「我们为什么不自己写一个」的答案——自研成本 = 上述五项 ×∞（无社区测试/无文档/无生态），自研只在「领域特化」（协同引擎/OJ 判题）时成立。
