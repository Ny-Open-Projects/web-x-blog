## ZSM-706：单元测试的状态隔离：模块级单例 store 的重置三板斧

**答**：
- Zustand/Jotai 的模块级单例在测试里的头号问题：**用例间状态污染**（test A 改了 store，test B 读了脏值）。三板斧：1) `beforeEach` 重置——`store.setState(store.getInitialState())`（ZSM-513 的 getInitialState 用武之地）；2) `vi.resetModules()` + 动态 import——彻底重建模块（store 工厂闭包里有外部状态时用）；3) **依赖注入**——组件接受 store 作为 prop/Context，测试传新实例（架构级解法，从源头避免单例）。
- Jotai 的重置：`createStore()` 每测试新建 + Provider 注入 `<Provider store={freshStore}>`，比「重置 defaultStore」干净——atom 的缓存/派生链随 store 一起重建。
- 派生/异步的隔离坑：mutation/query 的 QueryClient 要每测试新建（缓存污染），mock 的计时器/日期用 fake timers 后必须 restore（`vi.useRealTimers()` 在 afterEach），否则下一个用例的时间断言全错。
- 断言策略：测状态机语义时直接调 action 并断言 getState——不渲染组件（渲染测试交给 Storybook/组件测试）；这样 store 测试与 React 解耦，跑得飞快。
- 追问钩子：「测试要重置什么」的清单化——每个 store 声明 `__resetForTest()`（含持久化清理：localStorage mock 清空、IndexedDB fake 清库），重置遗漏是 flaky test 的最大来源。

```javascript
// 三板斧示例
import { describe, it, expect, beforeEach, vi } from 'vitest'

// 斧1：beforeEach 重置
const useCart = create((set) => ({ items: [], total: 0 }))
describe('cart', () => {
  beforeEach(() => {
    useCart.setState(useCart.getInitialState())
    localStorage.clear()                        // persist 清理
  })
  it('加购累计', () => {
    useCart.getState().add({ id: 'g1', price: 100 })
    useCart.getState().add({ id: 'g2', price: 200 })
    expect(useCart.getState().total).toBe(300)
  })
})

// 斧2：模块重建（工厂闭包有外部状态时）
describe('module isolation', () => {
  beforeEach(async () => {
    vi.resetModules()
    const { createCartStore } = await import('./cart')
    cartStore = createCartStore()               // 全新闭包
  })
})

// 斧3：依赖注入（组件层）
it('组件级注入', () => {
  const fresh = createCartStore()
  render(<CartList store={fresh} />)            // 不碰全局单例
  fireEvent.click(screen.getByRole('button'))
  expect(fresh.getState().items).toHaveLength(1)
})

// Jotai：每测试新 store
it('jotai isolation', () => {
  const freshStore = createStore()
  freshStore.set(countAtom, 5)
  expect(freshStore.get(countAtom)).toBe(5)     // defaultStore 不受影响
})

// QueryClient 每测试新建
beforeEach(() => {
  queryClient = new QueryClient()
  vi.useFakeTimers()
})
afterEach(() => vi.useRealTimers())
```
