## 1022：子应用独立部署时的状态契约兼容策略

**答**：
- 兼容原则：事件与接口「只增不删改」（字段新增可选、语义不变——旧消费者忽略新字段），破坏性变更走版本化（order.updated@2 与 v1 并存过渡）。
- 部署顺序：契约变更的发布顺序是「消费方先兼容 -> 提供方再切换」（B 先支持新事件格式 -> A 再发布新格式——顺序反了 B 收到不认识的数据）；与 API 向后兼容同构。
- 兼容期监控：旧格式消费量监控（v1 事件还有多少订阅者消费——归零才能下线 v1）。
- 追问钩子：为什么「消费方先兼容」的顺序不能反？——提供方先发新格式，旧消费方收到不认识的数据（解析失败/静默错乱）——线上事故；兼容窗口的顺序保证任何时刻在线的组合都能工作。

```txt
契约兼容发布顺序：
1. B（消费方）发布：兼容新旧两种格式
2. A（提供方）发布：切换到新格式
3. 监控：v1 消费量 -> 归零
4. 下线 v1（契约清理）
原则：只增不删改；破坏性变更版本化并存
```
