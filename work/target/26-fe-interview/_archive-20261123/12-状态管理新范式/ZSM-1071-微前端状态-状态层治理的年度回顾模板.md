## 1071：微前端状态治理的年度回顾模板

**答**：
- 回顾五项：事故盘点（状态类事故数与根因分布——治理缺口的证据）、成熟度对比（L1~L5 各项的自评变化——治理投入的产出）、容量变化（应用数/事件数/契约变更频率——治理压力的趋势）、成本核算（治理人力 vs 事故避免的估算损失——ROI）、来年路线（升级目标/合并计划/预算）。
- 事故驱动的回顾：每个事故标注「本可被哪级能力拦住」（L3 契约能拦/L4 监控能拦）——未升级的能力就是下一年的预算申请依据（事故清单 = 治理 ROI 的实证）。
- 回顾的产出纪律：3 个以内的来年动作（与多 Agent 回顾同构——超过 3 个说明没抓重点）。
- 追问钩子：为什么年度回顾必须「量化事故根因分布」？——治理方向的选择靠根因分布（事件类事故多 -> 契约治理加码；泄漏多 -> 生命周期治理加码）——没有分布数据的回顾是感觉驱动（预算争夺战必输）。

```md
## 年度回顾：微前端状态治理
1. 事故：N 起，根因分布（契约 X/泄漏 Y/时序 Z）
2. 成熟度：L2 -> L3（契约 CI 化）
3. 容量：应用 4->6，事件 30->52
4. ROI：治理 Z 人日 vs 避免 loss 估算
5. 来年（<=3）：L4 事件录制 / 合并 A+B / 预算监控
```
