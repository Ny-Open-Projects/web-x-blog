## 1010：微前端的状态隔离与样式隔离的联合治理

**答**：
- 联合问题：样式冲突（全局 CSS 污染）与状态冲突（全局变量/store 污染）是同构问题——都源于「全局命名空间共享」；治理思路同构：命名空间化（样式 scope + 状态分桶）、契约化（CSS 变量注入 + 状态访问器注入）。
- 设计令牌的状态化：主题（design token）作为「主应用注入的共享状态」（CSS variables 注入 + token 订阅更新——子应用跟随主题）——token 是合法共享（契约声明），业务数据不共享。
- 隔离等级：shadow DOM（样式+状态强隔离但成本高——事件冒坑/portal 问题）、scoped CSS（轻量样式隔离）+ 状态分桶——多数团队选择轻量组合。
- 追问钩子：为什么「主题」是合法共享而「业务数据」不共享？——主题是「展示层的横向关注点」（所有应用需要且语义一致——版本演进慢）；业务数据是「领域层的纵向数据」（语义随业务变——共享即耦合）。

```ts
// 主题注入：CSS variables + 订阅
mount(el, {
  theme: {
    get: () => tokenStore.get(),
    subscribe: tokenStore.subscribe,
  },
});
// 子应用：CSS 变量消费主题（var(--primary)）
// token 更新 -> 主应用写 CSS variables -> 子应用样式自动跟随
```
