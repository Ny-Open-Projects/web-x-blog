## 1047：多范式下的调试统一界面（四层状态全景）

**答**：
- 调试痛点：四层范式各有 devtools（Query devtools/Zustand devtools/XState inspector）——问题跨层时来回切换；统一界面：把四层状态聚合到一个调试面板（按实体聚合——「订单」的 Query 缓存+zustand 草稿+机器状态同屏）。
- 聚合实现：按实体 ID 关联（各层状态打 tag——entityId），调试面板按实体检索（一次看全该实体在各层的状态与变更历史）。
- 跨层追踪：一次用户操作（点击提交）在各层的传播（mutation -> 机器事件 -> zustand 写入 -> Query 失效）——操作级 trace 串联（traceId 贯穿四层）。
- 追问钩子：为什么「按实体聚合」优于「按库聚合」？——调试者的心智是「这个订单怎么了」（实体视角），不是「Query 缓存里有什么」（工具视角）——调试界面跟随调试者的心智模型，这是所有 devtools 设计的第一原则。

```ts
// 实体 tag 关联
qc.setQueryData(orderKeys.detail(id), data, { entityId: id });
machine.setContext({ entityId: id });        // 机器 context 带实体 id
zustandStore.entityTag = id;
// 调试面板：按 entityId 检索四层状态与变更历史
```
