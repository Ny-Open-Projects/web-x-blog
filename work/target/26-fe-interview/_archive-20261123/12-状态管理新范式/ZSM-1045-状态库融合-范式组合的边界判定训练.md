## 1045：给数据「选家」的判定流程（范式组合的日常决策）

**答**：
- 判定流程（五问依次）：真相在服务端吗 -> Query；跨路由持久且多组件写吗 -> Zustand；有严格生命周期与转换规则吗 -> XState；只有本组件用且刷新可丢吗 -> useState；跨应用共享吗 -> 微前端契约层。
- 判定的分歧仲裁：「感觉放哪都行」的数据（如购物车）——按「变化频率与失效语义」定（服务端有购物车实体 -> Query 缓存 + 本地乐观副本——混合模式要有 ADR 说明）。
- 迁移自由度：数据搬家是允许的（业务演进——原来 useState 的提升为 Zustand）——搬家要「一次搬干净」（双家并存是双源事故）。
- 追问钩子：为什么「五问有顺序」？——从最客观的（真相来源）到最主观的（生命周期感觉）——顺序保证判定从「事实」开始而不是从「习惯」开始；先问习惯的人永远把东西放进最熟的库。

```txt
数据选家五问（按序）：
1. 真相在服务端？ -> Query
2. 跨路由持久+多组件写？ -> Zustand
3. 严格生命周期/转换规则？ -> XState
4. 本组件瞬时？ -> useState
5. 跨应用共享？ -> 微前端契约
分歧：按失效语义定 + ADR 记录；搬家一次搬净
```
