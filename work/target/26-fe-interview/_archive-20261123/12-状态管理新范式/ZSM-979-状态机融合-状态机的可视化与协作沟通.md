## 979：状态机图在团队协作中的沟通价值

**答**：
- 沟通价值：状态机图（XState visualizer/stately）是「产品经理与工程师的共同语言」——产品确认流程逻辑（「这个状态下点取消去哪」）、QA 按图穷举测试路径（每个状态×事件=测试用例）、新人理解流程不用读代码。
- 图即文档：机器定义就是流程文档的「可执行版本」——代码与文档不会漂移（同一份定义）；对比流程图工具画的图（与代码必然漂移）。
- 评审流程：新流程的评审「先过图再写码」——产品/QA/前端在图上对齐合法路径与异常分支，评审通过后机器定义就是唯一真相。
- 追问钩子：为什么「图与代码同源」这么重要？——传统流程文档与代码的双源漂移是流程 bug 的温床（文档说 A 代码做 B）；状态机让「文档=代码」成为结构事实。

```txt
状态机协作流：
1. 产品/QA/前端 在 stately 上对齐状态图
2. 图评审通过 -> 导出机器定义（唯一真相）
3. QA 按图穷举：状态 x 事件 = 测试矩阵
4. 流程变更 -> 改图 -> 评审 -> 改机器
图与代码同源，零漂移
```
