## 1051：跨应用搜索状态共享的案例（全局搜索与各子应用联动）

**答**：
- 场景：全局搜索框在主应用，搜索结果跨子应用（订单/商品/用户各子应用提供搜索面）——搜索词状态共享与结果聚合。
- 设计：搜索词作为「主应用发布的查询事件」（query.changed 带节流），各子应用订阅并各自查询自己的域（并行返回）——主应用聚合展示（各域结果分区）；搜索词不入子应用缓存 Key 的共享段（各子应用按自己的 Key 结构存）。
- 一致性：搜索词节流（300ms）+ 取消（新搜索取消旧查询——各子应用各自处理竞态）；空态/加载态由各子应用自报（主应用聚合渲染）。
- 追问钩子：为什么搜索词「广播事件」而非「共享状态」？——搜索词是「命令意图」不是「共享数据」（子应用需要「响应搜索」而非「持有搜索词」）；命令走事件、数据走门——通信语义决定通信机制。

```ts
// 主应用：搜索词广播（节流）
const debouncedPublish = debounce(q =>
  bus.publish('query.changed', { q, v: ++seq }), 300);
// 子应用：订阅并各自查询
bus.subscribe('query.changed', e => {
  qc.cancelQueries({ queryKey: ['search'] });
  qc.invalidateQueries({ queryKey: ['search', 'mine'] });  // 各自 Key 结构
  setSearch(e.q);
});
```
