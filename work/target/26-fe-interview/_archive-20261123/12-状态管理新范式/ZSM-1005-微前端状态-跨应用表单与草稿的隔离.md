## 1005：跨应用场景下表单草稿与编辑锁的治理

**答**：
- 隔离原则：编辑类状态（表单草稿/选中项）永远在「拥有该页面的子应用」内部——跨应用传递只在「提交时」（提交事件带最终数据）；草稿不跨应用（A 编辑一半切到 B 再回来——A 的草稿由 A 自己持久化恢复）。
- 编辑锁：同一资源被两个子应用编辑（订单详情在 A、编辑表单在 B）——编辑锁机制（谁在编辑谁持锁，广播 lock.acquired——B 提示「A 正在编辑」）；锁的生命周期与编辑器一致（卸载释放）。
- 提交后的失效联动：B 提交成功 -> 发布 order.updated -> A 失效对应缓存（只失效数据，不碰 A 的草稿——草稿是 A 的私有）。
- 追问钩子：为什么草稿不跨应用同步？——草稿的语义是「某个编辑器实例的私有工作区」（跨应用同步意味着两个编辑器写同一草稿=冲突地狱）；跨应用共享的应该是「已提交的真相」不是「进行中的草稿」。

```ts
// 编辑锁：B 提示"A 正在编辑"
bus.subscribe('edit.locked', e => {
  if (e.resourceId === myResourceId && e.app !== 'B') {
    showBanner('该订单正在其他模块编辑中');
  }
});
// A 提交成功 -> B 失效缓存但不碰草稿
bus.publish('order.updated', { id });
```
