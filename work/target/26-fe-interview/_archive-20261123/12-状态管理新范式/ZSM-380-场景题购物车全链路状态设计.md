## ZSM-380：场景题示范：购物车全链路状态设计

**答**:
- 读写分层：加购/改量是 mutation（乐观更新 + 回滚 + 幂等 opId）；购物车本体是 Query 缓存（列表 key）；角标数从缓存派生不单独存
- 并发与合并：连续改量防抖合并为一次提交（末值提交）；多端同时改（PC+APP）以服务端版本为准，冲突拉最新提示
- 失效网络：下单成功 → invalidate 购物车 + 库存 + 优惠资格（映射表登记）；改量 → 只失效该 sku 相关聚合（价格/优惠）
- 结算一致性：结算页快照（价格/优惠锁定）与购物车缓存分离——结算锁定后购物车可继续变，结算页展示锁定值并标注时效

```javascript
const addCart = useMutation({
  mutationFn: (sku) => api.addCart({ ...sku, opId: crypto.randomUUID() }),   // 幂等
  onMutate: optimisticAdd, onError: rollback, onSuccess: (server) => setCache(server),
})
// 改量防抖合并
const setQty = debounce((skuId, qty) => mutation.mutate({ skuId, qty }), 500)
// 失效映射
checkoutDone: () => invalidate(['cart'], ['stock'], ['promo-elig'])
```
