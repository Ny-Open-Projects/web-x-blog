## ARC-633：风控挑战交互
**答**:
- 挑战协议：服务端风控决策返回挑战（NODE-456 challenge 决策 → 挑战类型 + 参数 + token）——前端渲染挑战组件（注册表：图形验证/滑块/短信/人脸 SDK——类型路由），通过后带凭证重放原请求。
- 挑战组件协议：统一接口（mount(token, params, onDone)/校验回调——各挑战实现注册）、凭证生命周期（挑战通过 token 短时效一次性——失败重新挑战）、重放语义（原请求自动重放——用户无感续流程，ARC-454 验证 token）。
- 体验设计：挑战时机（操作前预判 vs 操作中拦截——预判减少打断）、失败引导（连续失败 → 换验证方式/联系客服——死循环防护）、无障碍（挑战的 a11y：图形验证码替代音频——ARC-577）。
- 安全边界：挑战组件反调试（滑块轨迹采集——防自动化）、挑战数据不上报敏感信息、降级（人脸 SDK 不可用 → 降级短信）。
- 观测：挑战触发率/通过率/放弃率（放弃率高 = 挑战太重——策略调优数据）。
```javascript
// 挑战拦截与重放
api.interceptor(async (req) => {
  const r = await req.send();
  if (r.status === 403 && r.body.challenge) {                    // 风控挑战
    const cred = await ChallengeRunner.run(r.body.challenge);    // 注册表路由渲染
    return req.resend({ 'x-challenge-cred': cred });             // 带凭证重放
  }
  return r;
});
```
