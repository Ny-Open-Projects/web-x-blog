## DP-448：状态库模式对比

**答**：
- 状态库的模式内核差异：Redux（命令+单一 store——dispatch 是命令）、Zustand（观察者+模块化 store——selector 订阅）、MobX（代理+细粒度观察者）、 jotai（原子组合——依赖图）
- 模式视角的选型：需要时间旅行/严格纪律 → Redux（命令日志）；需要细粒度性能 → MobX/zustand（selector）；需要简单 → zustand（样板少）
- 模式的组合成本：Redux 的中间件生态（责任链成熟）vs zustand 的轻量（但 ecosystem 少）——模式成熟度 vs 灵活度
- 深水点：状态库的「撕裂防护」差异——Redux（store 快照天然一致）vs 自研（必须 useSyncExternalStore）——并发渲染对状态库的模式要求

```text
模式内核对比:
  Redux:   命令模式 + 单一状态树 → 时间旅行/强纪律
  Zustand: 观察者 + selector → 细粒度/轻量
  MobX:    代理 + 自动依赖追踪 → 细粒度极致
  Jotai:   原子组合 → 依赖图派生
并发渲染: 均需 useSyncExternalStore 快照化
```
