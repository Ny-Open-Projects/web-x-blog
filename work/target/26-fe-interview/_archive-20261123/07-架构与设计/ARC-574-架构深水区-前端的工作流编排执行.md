## ARC-574：前端工作流编排执行架构
**答**:
- 场景：用户自定义自动化（"每天 9 点拉取报表发我"/"库存低于 10 通知我"）——前端负责编排器 UI（触发器+动作连线 ARC-453），执行在服务端（前端不下发执行逻辑 NODE-453 同理）。
- 编排模型：触发器（定时/事件/数据条件）+ 动作（通知/导出/调接口白名单）+ 条件分支；编排 schema 校验（无环/动作白名单/权限校验）。
- 执行架构：编排保存 → 服务端调度器实例化（NODE-345 定时 + NODE-344 事件订阅）→ 执行记录可查（每次执行的输入输出/失败原因——用户可见执行历史）。
- 前端体验：编排测试运行（发布前单次试跑——用真实数据 dry-run）、执行历史面板、失败通知（连续失败自动暂停工作流 + 通知 owner——防僵尸工作流反复报错）。
- 权限与安全：动作白名单（编排能触发的动作范围受限）、配额（每用户工作流数/执行频次 ARC-439）。
```javascript
// 工作流 schema + 试跑
const wf = {
  trigger: { type: 'schedule', cron: '0 9 * * *' },
  actions: [{ type: 'export-report', params: { range: '1d' } }, { type: 'notify', channel: 'im' }],
  guards: { maxRunsPerDay: 5 }
};
const dryRun = await api.testRun(wf);                            // 单次试跑展示结果
await api.deploy(wf);                                            // 通过后部署
```
