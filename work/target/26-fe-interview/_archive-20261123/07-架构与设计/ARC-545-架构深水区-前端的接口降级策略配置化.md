## ARC-545：接口降级策略配置化
**答**:
- 问题：降级逻辑散落在业务代码 try/catch，无法盘点、无法演练、无法运营期调整。配置化：每个接口声明降级策略（数据源/文案/显隐），请求层统一执行（ARC-390 降级框架前端版）。
- 策略字段：{ fallback: 'cache' | 'static-default' | 'hide' | 'block', maxAge, notice }——cache 用本地缓存（maxAge 内）、static-default 用内置兜底数据、hide 隐藏区块（ARC-469 矩阵）、block 核心接口失败显式报错。
- 执行器：请求失败 → 查策略 → 按类型取 fallback → 结果带 degraded 标记（UI 显"缓存数据"标识）→ 降级事件上报（监控降级率——降级频发即依赖健康问题）。
- 配置来源：与接口元数据同文件维护（schema 内声明降级——改策略不用改逻辑代码），热更新走配置中心（紧急降级秒级生效 ARC-369）。
- 演练：每条降级策略可单独触发演练（NODE-408 思想：mock 注入接口故障验证 fallback 真实可用）。
```javascript
// 接口级降级声明
const api = defineApi({
  'goods.list': { fallback: { type: 'cache', maxAge: 30 * 60e3, notice: '显示缓存数据' } },
  'pay.submit':  { fallback: { type: 'block' } }                 // 核心接口：失败显式报错
});
// 执行器：res = await call(api.goods.list).catch(e => degrade('goods.list', e));
```
