## ARC-523：应用内通知中心架构
**答**:
- 数据流：服务端通知服务（NODE-394）→ 前端通道（WS 实时推 + 拉取兜底分页）→ 通知 store（未读计数/列表/分类过滤）。
- 未读数体系：分类型未读（系统/互动/审批）+ 总未读；本地乐观维护（WS 增量）+ 拉取对账（进入通知中心/定时校准）；多 Tab 一致（ARC-500 广播）。
- 列表体验：虚拟滚动 + 分组（今天/更早）、按类型筛选、批量已读/删除；通知跳转深链（点击直达业务上下文，通知 payload 带路由参数——权限校验后渲染，无权则友好提示）。
- 偏好管理：通知偏好（类型级开关/勿扰时段）与推送通道联动（ARC-474），偏好变更即时生效。
- 清理与沉淀：保留策略（已读 30 天归档）、重要通知（不可删，固定置顶）。
```javascript
// 未读 store + 对账
class NoticeStore {
  unread = new Map();                                            // type -> count
  applyWs(n) { this.unread.inc(n.type); this.list.prepend(n); }  // WS 增量
  async reconcile() {                                            // 进入中心时对账
    const srv = await api.unreadCounts();
    for (const [t, c] of srv) this.unread.set(t, c);             // 服务端权威覆盖
  }
  markRead(ids) { this.list.patch(ids, { read: true }); this.unread.dec(...); }
}
```
