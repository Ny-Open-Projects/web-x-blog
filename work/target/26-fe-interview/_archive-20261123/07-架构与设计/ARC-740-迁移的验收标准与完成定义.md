## ARC-740：迁移验收标准

**答**：
- 验收四层：代码层（老 API 零引用——扫描器验证）、行为层（回归测试全绿+双跑无缺陷）、指标层（性能/错误率不劣化）、体验层（用户无感知或改善）——四层验收缺一不可
- 「完成」的严格定义：老代码删除/依赖移除/文档更新/工具下线——「迁移完但老代码还在」是半成品
- 验收的时点：全量后观察期（2 周）无劣化才宣布完成——「上线即完成」是假完成
- 完成的宣告仪式：迁移总结（收益数据+经验沉淀进知识库）——宣告完成即开始收割收益（团队士气）
- 深水点：验收的「遗留清单」——验收时明确「接受不迁的部分」（写入文档）——不留尾巴不留糊涂账

```text
迁移验收:
  四层: 代码(零引用) / 行为(回归+双跑) / 指标(不劣化) / 体验
  完成: 老代码删+依赖移+文档更+工具下
  时点: 全量后 2 周观察期
  遗留: 接受不迁的部分写入文档
```
