## ARC-397：架构漂移（Drift）如何检测与纠偏？
**答**:
- 漂移形态：分层腐化（view 直调 service、工具里塞业务）、口径分裂（同名工具三处实现）、规范失效（lint 被禁用堆积）、文档失真（文档与真实架构脱节）。
- 检测手段：适应度函数自动卡（ARC-396）+ 季度架构巡检（结构扫描报告：依赖图、重复度、规范豁免清单）+ 代码考古（历史提交里谁在绕过规范）。
- 纠偏机制：漂移项入技术债清单定责定期；高频漂移点反推规范不合理（规范被人反复绕过，先怀疑规范，再怀疑人）；豁免机制给逃生门但留痕过期。
- 文档保真：用代码生成架构文档（依赖图/目录树自动生成），手写文档只写"为什么"不写"是什么"，减少失真面。
- 文化配套：漂移不是追责工具，巡检结果面向改进；纠偏工时纳入排期。
```javascript
// 架构巡检报告（季度）
function auditDrift() {
  return {
    circularDeps: madge(src).circular().length,          // 目标 0
    duplicateUtils: jscpd(src).duplicatedBlocks,          // 重复代码块
    lintDisable: countDisableComments(src),               // eslint-disable 数量趋势
    docFreshness: daysSince(README, lastCommit)           // 文档失真风险
  };
}
```
