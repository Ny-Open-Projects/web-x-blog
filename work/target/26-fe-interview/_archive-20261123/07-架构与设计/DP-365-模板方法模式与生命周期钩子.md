## DP-365：模板方法：骨架与钩子

**答**：
- 模板方法核心：父类定骨架（步骤顺序固定），子类填钩子——前端形态：基类页面的生命周期编排（load → render → track 顺序固定，各步骤细节子类覆写）
- 与钩子（React Hooks）的关系：Hooks 的自定义 Hook 就是「模板方法的函数式形态」（usePageFlow 封装固定编排，参数即钩子）——OO 模板方法在函数式中的演化
- 实战要点：钩子的「默认实现」（钩子可不覆写——空操作默认）；骨架步骤的「不可跳过」（模板方法控制流程，钩子不能改顺序）
- 反模式：钩子过多（子类覆写 8 个钩子——等于没有骨架）——钩子数与抽象层级匹配
- 深水点：模板方法的「测试策略」——骨架本身单测（顺序断言）+ 钩子各自单测（解耦测试）

```javascript
// 函数式模板方法
function usePageFlow({ loadData, onReady, trackPage }) {
  const [data, setData] = useState(null);
  useEffect(() => {
    let alive = true;
    (async () => {
      const d = await loadData();                    // 步骤1: 数据(钩子)
      if (!alive) return;
      setData(d);
      onReady?.(d);                                  // 步骤2: 就绪钩子(默认空)
      trackPage(d);                                  // 步骤3: 埋点(固定)
    })();
    return () => { alive = false; };
  }, []);
  return data;
}
// 骨架固定: load → ready → track; 各页面只填钩子
```
