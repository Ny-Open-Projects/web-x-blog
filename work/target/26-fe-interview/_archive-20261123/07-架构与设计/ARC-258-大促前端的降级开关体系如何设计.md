## ARC-258：大促前端的降级开关体系如何设计？
**答**：
- 开关分级：**功能开关**（砍非核心模块：直播挂件/推荐流）、**数据开关**（缓存数据替代实时接口）、**渲染开关**（整页静态化/简化版页面）。每个开关对应预案，预案必须演练过。
- 开关下发：配置中心长轮询（NODE-150 思路）+ 本地 last-good 兜底；大促期间开关配置本身要"预下发"（提前把可能的预案值缓存到端上，断网也能降级）。
- 设计原则：降级路径的代码是**平时就在跑的代码**（静态化版本每日自动构建、缓存数据每日刷新），而不是大促临时写的 if 分支——没跑过的降级等于没有降级。
- 恢复策略：自动恢复（指标回归即自动关闭降级）+ 人工确认开关，避免抖动反复切换（加冷却期）。

```typescript
// 降级开关消费
const flags = degrade.getFlags();          // 配置中心+端上预下发缓存
if (flags['home:live-widget'] === false) return <Skeleton/>;      // 功能降级
if (flags['home:feed:use-cache'] === true) return <Feed data={cachedFeed()}/>; // 数据降级
// 数据降级的数据源：每天 02:00 拉取快照进 localStorage/端缓存，大促接口抖动时无缝切换
// 自动恢复：metrics.stable(10min) && cooldownElapsed(15min) → degrade.autoRestore(flag)
```
