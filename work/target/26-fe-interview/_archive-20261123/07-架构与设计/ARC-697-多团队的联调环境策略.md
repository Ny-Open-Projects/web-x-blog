## ARC-697：联调环境策略

**答**：
- 环境谱系：本地 dev（mock 自测）→ dev 联调环境（多团队集成）→ staging（准生产验证）→ 生产——各环境「数据隔离与服务版本」策略不同
- 联调环境的冲突治理：多团队共用 dev 环境的「数据打架」——按团队隔离数据（请求头带团队标识路由到各自 mock）或「环境分时预约」
- 特性环境的弹性：按 PR 动态创建特性环境（preview deployment）——「每个 PR 一个环境」的评审体验
- 环境成本：常驻环境 vs 按需创建——低频使用的 staging 按需拉起（成本减半）
- 深水点：联调环境的「版本漂移」——dev 环境后端版本与生产不一致导致「联调通过上线失败」——环境版本与生产对齐（dev 也走版本管理）

```text
联调环境:
  谱系: dev(mock/联调) → staging → 生产
  冲突: 团队隔离路由 / 分时预约
  弹性: PR 级 preview deployment
  成本: 常驻 vs 按需拉起
  漂移: dev 服务版本与生产对齐
```
