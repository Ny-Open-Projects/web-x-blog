## ARC-448：前后端同构代码的架构管理
**答**:
- 同构价值：一份校验 schema/类型定义/枚举常量两端共用，契约漂移在编译期暴露。管理核心是"共享什么、不共享什么"边界清晰。
- 共享清单：类型与 schema（zod/openapi 生成）、枚举与错误码、纯计算函数（价格计算/格式化——注意时区与精度）、文案 key。不共享：UI 组件、依赖 DOM/Node 的逻辑。
- 工程形态：Monorepo shared 包（源码直引或构建产物）、openapi-generator 从契约生成 TS 类型（契约优先）、tRPC 式端到端类型（全栈同一框架时）。
- 运行时校验：共享 schema 在两端各跑一遍——前端做即时提示、后端做安全裁决，同一规则防"前端放行后端拒绝"的体验割裂。
- 版本治理：shared 包 semver 严格化，破坏性变更走迁移指南；两端升级节奏协调（先发后端兼容层再发前端）。
```javascript
// shared/schemas/order.ts 两端共用
import { z } from 'zod';
export const OrderCreateSchema = z.object({
  skuId: z.string(), qty: z.number().int().min(1).max(999),
  couponId: z.string().optional()
});
export type OrderCreate = z.infer<typeof OrderCreateSchema>;
// 前端：OrderCreateSchema.parse(formState) 即时提示
// 后端：同一 schema 裁决，规则永不漂移
```
