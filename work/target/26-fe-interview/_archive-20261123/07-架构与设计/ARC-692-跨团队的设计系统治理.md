## ARC-692：设计系统治理

**答**：
- 治理三角色：设计团队（token/视觉规范）、组件团队（实现）、业务团队（消费与反馈）——三角色的「接口」是 token 规范与组件 API
- token 流转管道：Figma（设计源）→ token JSON → 生成 CSS 变量/组件主题——设计变更的自动化同步（手工同步必漂移）
- 组件准入流程：新组件提案（业务提需求 + ≥2 业务线确认）→ 设计稿 → 实现 → 文档 → 发布——「准入即评审」防组件库膨胀
- 破坏性变更的协调：设计改版（按钮圆角变化）→ token 更新自动生效——「全局视觉变更」的爆炸半径管理（先灰度站点）
- 深水点：设计系统的「一致性 vs 灵活性」——业务定制需求（改按钮颜色）走「语义 token 扩展」不走「样式覆盖」——覆盖是漂移之源

```text
设计系统治理:
  三角色: 设计(token) / 组件(实现) / 业务(消费)
  管道: Figma → token JSON → CSS/主题 (自动同步)
  准入: ≥2 业务线确认
  全局变更: token 灰度生效
  灵活性: 语义 token 扩展 (禁样式覆盖)
```
