## ARC-276：灰度发布平台的前端整体架构如何设计？
**答**：
- 前端灰度的特殊性：静态资源一旦被引用就固化在用户会话里，"灰度比例"实际作用于 **HTML/入口决策**层——按用户特征决定返回哪个版本的 HTML（或指向哪个资源清单）。
- 架构三件套：入口决策服务（HTML 层按分桶返回新/旧版本）、资源共存（新旧产物同时在线，旧不删）、观测对账（分桶打标进监控，指标按版本分桶对比）。
- 决策因子：用户 ID 分桶（稳定）、设备/地区、白名单（内部员工先体验）、回滚指纹（出问题秒切回）。决策必须**确定可复现**——同一用户同请求参数永远同桶，否则功能错乱。
- 与发布流程集成：灰度不是"发一半代码"，而是"新旧两个完整版本共存 + 流量比例渐进"，任何一步可回滚。

```typescript
// 入口决策服务（边缘函数/网关层）
function pickVersion(req) {
  const uid = req.cookies.uid;
  if (whitelist.has(uid)) return 'v2';                       // 内部先体验
  if (req.query.version === 'rollback') return 'v1';         // 指纹回滚
  const bucket = hash(`gray:home:${uid}`) % 100;
  return bucket < grayConfig.ratio ? 'v2' : 'v1';            // 5% → 25% → 100%
}
// 响应：html = fetch(`/builds/${version}/index.html`)；页面内 window.__BUILD__ = version 打标
// 监控按 __BUILD__ 分桶对比：errorRate/LCP/转化 三组对比决定放行
```
