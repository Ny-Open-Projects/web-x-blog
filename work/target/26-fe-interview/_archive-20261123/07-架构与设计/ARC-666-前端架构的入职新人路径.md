## ARC-666：新人 onboarding 路径

**答**：
- 30 分钟上手图：环境搭建一键脚本 → 本地跑起核心应用 → 提交一个测试 PR——「第一天就能改代码」是 onboarding 设计目标
- 分阶段路径：第 1 周（架构总览+规范手册+小 bug 修复）、第 2~3 周（独立小需求+oncall 旁听）、第 1 月（独立负责模块+架构文档通读）——渐进接触复杂度
- 知识结构化：新人最常卡的不是技术而是「暗知识」（为什么这么设计/哪里有坑）——FAQ + ADR 导读是暗知识的外化
- 导师机制：Buddy 制（非 leader——降低心理门槛）+ 每周架构答疑会
- 深水点：onboarding 的度量——新人首个独立 PR 的时间（中位数 <5 天为健康）——时间指标驱动 onboarding 改进

```text
Onboarding 路径:
  D0: 一键环境 + 测试 PR (30min 上手图)
  W1: 架构总览 + 规范 + 小 bug
  W2-3: 独立小需求 + oncall 旁听
  M1: 独立模块 + ADR 通读
暗知识: FAQ + ADR 导读 (为什么这么设计)
度量: 首个独立 PR 中位数 <5 天
```
