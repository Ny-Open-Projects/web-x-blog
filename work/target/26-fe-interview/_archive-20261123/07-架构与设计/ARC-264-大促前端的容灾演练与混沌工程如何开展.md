## ARC-264：大促前端的容灾演练与混沌工程如何开展？
**答**：
- 前端混沌场景清单：CDN 域名劫持/超时、核心接口 5xx、WebSocket 断连、配置中心不可用、第三方 SDK 加载失败（支付/地图）、弱网高延迟。每个场景对应"预期表现"与"实际表现"的 gap 分析。
- 注入方式：测试环境用代理（Whistle/Charles map 故障响应）；线上灰度实验注入（小流量把某接口延迟 3s 观察降级是否生效）——线上注入必须可秒停。
- 演练纪律：先在预发跑通 SOP，再灰度注入；每次演练有中止条件（白屏率超线即停）；演练报告沉淀为预案修订。
- 与预案关系：演练验证的预案才进大促预案库（ARC-256），未演练预案一律视为不存在。

```typescript
// 前端故障注入 SDK（预发/灰度环境）
chaos.inject({
  match: /\/api\/cart/, delay: 3000, failureRate: 0.5,     // 模拟购物车接口劣化
  stop: () => whiteRate > 0.005,                            // 中止条件
});
// 预期：购物车骨架+重试提示，整页可浏览；实际记录 gap → 预案修订
// 第三方 SDK 注入：block(['//pay.example.com/sdk.js']) → 验证支付降级路径（提示+备用支付方式）
```
