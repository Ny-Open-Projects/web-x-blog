## DP-465：React 调度器剖析

**答**：
- Scheduler 的模式分解：优先级队列（小顶堆——expiration 排序）、策略（时间片：5ms 让出——shouldYield）、观察者（MessageChannel 宏任务驱动）、命令（任务可取消——惰性标记）
- 时间片的本质：「协作式调度」——每帧给 React 5ms（剩余留给浏览器渲染）——时间片是「与浏览器协商」的策略
- 优先级映射：lane（React 内部）→ Scheduler priority（Immediate/UserBlocking/Normal）——两套体系的中介转换
- 饿死防护：低优先级任务的 expiration 会「过期」——过期任务升为同步（不死锁）
- 深水点：调度器的「可中断恢复」——workInProgress 游标保存进度（中断后从游标继续——不需要重头）——fiber 树即进度快照

```text
Scheduler 模式分解:
  小顶堆: expiration 排序 → 堆顶执行
  时间片: shouldYield() — 5ms 让出
  MessageChannel: 宏任务驱动 (无 setTimeout 4ms 延迟)
  惰性取消: task.cb = null
  饿死防护: expiration 过期 → 升级
```
