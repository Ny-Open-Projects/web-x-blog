## ARC-691：多团队 API 契约管理

**答**：
- 契约三层：前端↔后端接口契约（OpenAPI + mock server）、组件↔使用方契约（props 类型 + d.ts）、应用↔基座契约（微前端协议）——每层有独立版本管理
- 契约先行流程：接口定义（schema）→ 双方并行开发（前端用 mock）→ 联调——「等后端接口」的串行等待被消解
- 契约变更管理：breaking change 需要新版本号（/v2/xxx）——旧版本保留一个迁移周期；非破坏变更（新增可选字段）同版本演进
- 契约测试：前后端各自跑契约测试（schema 校验）——CI 阶段发现不一致（而非联调发现）
- 深水点：契约的「事实源」管理——OpenAPI 文件放独立仓库（前后端共同 PR）——单边修改必然漂移

```text
契约管理:
  三层: 接口契约 / 组件契约 / 基座契约
  流程: schema 先行 → mock 并行开发 → 契约测试
  变更: breaking 加版本号, 旧版保留迁移期
  事实源: 独立仓库, 前后端共同维护
```
