## ARC-694：多团队 CR 文化

**答**：
- CR 的分层责任：业务 CR（本团队——业务正确性）、架构 CR（跨团队影响面——架构师或模块 owner）、安全 CR（敏感链路——安全团队抽查）——「谁的 PR 谁的责任域」
- CR 的 SLA 与规模：24h 响应 SLA、PR <400 行（大 PR 拆分——review 质量随规模下降）
- 跨团队 CR 的场景：修改公共组件/影响其他应用的行为——强制相关团队 reviewer——「影响面决定 reviewer」
- CR 的自动化前置：lint/类型检查/单测全绿才请求人工 review——人工 review 只看「机器看不到的」（设计/边界/命名）
- 深水点：CR 文化的「度量」——评审响应时长/缺陷拦截率（CR 拦住的 bug 比例）——拦截率低的 CR 流于形式（要反思 review 内容）

```text
CR 文化:
  分层: 业务 CR / 架构 CR / 安全 CR
  规则: PR<400 行 + 自动化全绿前置
  跨团队: 影响面决定 reviewer
  度量: 响应 SLA + 缺陷拦截率
  机器看不了的: 设计/边界/命名
```
