## DP-400：模式面试答题框架

**答**：
- 答题结构四步：意图（解决什么问题——先说场景）→ 实现（核心结构——简洁代码）、取舍（代价与适用边界）、替代（不用模式怎么写/何时不需要）——「替代方案」是最能区分水平的部分
- 常见追问预案：「这个模式会不会过度设计」→ 触发条件（重复出现/变化方向明确）、「和 X 模式的区别」→ 意图差异（代理控制访问 vs 装饰增强行为）、「在 React 里怎么用」→ 范式映射（OO 模式的函数式形态）
- 反模式警示：背诵 23 种模式定义（面试考的是实战不是背书）、无场景堆模式名词
- 深水点：模式面试的「高级信号」——主动谈模式的失效场景与滥用识别、用业务案例而非教科书案例、谈模式在框架中的内化（React 的 Context 就是提供者模式的内置化）

```text
答题四步:
  1. 意图: 什么场景什么痛点
  2. 实现: 核心结构 (20行内)
  3. 取舍: 代价/边界/滥用信号
  4. 替代: 不用模式的写法 + 何时不需要
高级信号: 失效场景 / 业务案例 / 框架内化认知
```
