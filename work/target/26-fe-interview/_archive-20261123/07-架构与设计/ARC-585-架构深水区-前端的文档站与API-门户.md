## ARC-585：文档站与 API 门户
**答**:
- 文档站的失败模式：文档与代码脱节（改了组件没改文档）、搜不到、没示例。建设原则：文档从代码生成（组件 props/类型/默认值自动提取——手写只写"什么时候用什么" ARC-399 原则）、可交互（Playground：改 props 实时看效果 ARC-320）、搜索优先（全文搜索 + 组件意图搜索："表格"能搜到 Table）。
- 内容分层：快速上手（5 分钟能跑通）、组件 API（自动生成 + 使用示例）、最佳实践（模式与反模式：什么时候不用该组件）、迁移指南（版本升级）。
- 门户能力：组件状态搜索（"带校验的表单" → Form 组件 + 示例）、代码片段复制即用、版本切换（多版本文档——老项目还能查旧文档）、示例代码与库版本锁定（示例可运行不腐烂——CI 验证示例编译）。
- 运营：文档使用数据（哪些组件文档访问高/示例复制多）、缺口发现（工单高频问题 → 补文档）、文档 MR 与组件 MR 同流程（改组件必须带文档，CI 强制）。
```yaml
# 文档站流水线
build: [typedoc extract, playground generate, search-index build]
ci:
  - verify-examples   # 示例代码编译 + 渲染冒烟
  - doc-sync-check    # 组件变更 MR 必须含文档变更
deploy: versioned   # v2/v3 文档并存
```
