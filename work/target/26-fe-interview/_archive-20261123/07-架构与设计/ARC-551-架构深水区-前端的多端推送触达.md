## ARC-551：多端推送触达统一架构
**答**:
- 通道矩阵：Web（Web Push ARC-474/站内信）、小程序（订阅消息——一次性授权每条需申请）、App（厂商通道 APNs/FCM/厂商推送）、IM 长连接（在线直推 ARC-416）。统一消息模型（NODE-453 服务端版的前端配合层）：消息 ID/类型/跳转参数标准化，各端渲染器适配。
- 触达策略引擎：按用户在线状态与端选择通道（在线 WS 直推 → 离线 Web Push → 短信兜底，成本递增）；频控与偏好（ARC-523/474）；到达率与打开率统计（端上报）驱动通道权重。
- 授权管理：各端授权状态台账（用户对每端每类型的授权：授权/拒绝/未决）、重新授权引导（拒授权后的恢复路径——价值展示而非骚扰）、授权合规（ARC-154 同意管理）。
- 深链一致性：点击推送跳转的业务上下文统一协议（push deep link → 路由映射 → 权限校验 → 上下文恢复 ARC-389），各端深链格式收口。
- 可靠性闭环：推送到达未打开的召回策略（同消息二次触达冷却期）、推送服务端到端的延迟监控（发送→端上收到）。
```javascript
// 端上推送统一入口
async function handlePush(msg) {                                  // 各端 adapter 调用
  if (!prefAllows(msg.type)) return track('suppressed', msg.id);  // 偏好抑制
  await notifyCenter.apply(msg);                                  // 未读 + 列表 ARC-523
  track('arrived', { id: msg.id, channel: adapter.channel, latency: Date.now() - msg.sentAt });
}
onClick(() => router.handle(msg.deepLink));                       // 统一深链协议
```
