## ARC-481：前端的时区与时间处理架构
**答**:
- 时间架构三原则：传输与存储一律绝对时间（UTC 时间戳或 ISO8601 带偏移）；展示一律本地化（用户时区 Intl 格式化，禁服务端预格式化字符串）；业务时区显式声明（报表"按东八区日切"，用户时区 ≠ 业务时区）。
- 常见事故：后端返回 "2026-11-19 00:00:00" 无时区（浏览器按本地解析，海外用户错一天）；前端 new Date('2026-11-19')（ISO 日期字符串按 UTC 解析，东八区显示前一天 08:00）。解法：解析也收口到时间模块。
- 相对时间与边界：倒计时用服务下发截止时间戳 + 本地钟差校正（ARC-446）；"今天/昨天"语义按用户时区；跨月账单按业务时区。
- 库与收口：日期库统一（date-fns/Dayjs + timezone 插件），所有 new Date/parse/format 禁止绕过封装（lint 禁令）。
- 测试：跨时区用例（UTC-11 与 UTC+14 边界、夏令时切换日）进回归集；伪本地化时区测试（模拟 TZ 环境变量）。
```javascript
// 时间模块收口
export const T = {
  parse: (iso) => new Date(/^\d{4}-\d{2}-\d{2}$/.test(iso) ? `${iso}T00:00:00Z` : iso), // 日期串当 UTC
  fmt: (ts, { tz = Intl.DateTimeFormat().resolvedOptions().timeZone, dateStyle = 'medium', timeStyle = 'short' } = {})
    => new Intl.DateTimeFormat(undefined, { timeZone: tz, dateStyle, timeStyle }).format(new Date(ts)),
  bizDay: (ts, bizTz = 'Asia/Shanghai') => fmtDay(ts, bizTz)          // 业务日切显式时区
};
```
