## DP-357：责任链：中间件管道

**答**：
- 责任链核心：请求沿处理者链传递（每个节点处理或转发）——前端形态是「中间件管道」（fetch 包装/Koa 洋葱模型）
- 实战结构：中间件签名 `(ctx, next) => Promise`——洋葱模型（next 前后各可做事：请求前加 header、响应后打点）
- 管道设计要点：ctx 的结构约定（请求/响应/元数据分区）、短路语义（中间件可不调 next——直接返回缓存）、错误在链中的传播（任一节点抛错向上冒泡）
- 典型管道：鉴权 → 限流 → 缓存 → 重试 → 日志——顺序即语义（缓存应在重试前——重试不该绕过缓存）
- 深水点：next 多次调用的防护（Koa 的 classic bug——一个中间件调两次 next）——compose 实现的 i 指针检查

```javascript
function compose(middlewares) {
  return (ctx) => {
    let i = -1;
    function dispatch(j) {
      if (j <= i) throw new Error('next() called multiple times');   // 防护
      i = j;
      const mw = middlewares[j];
      if (!mw) return Promise.resolve();
      return Promise.resolve(mw(ctx, () => dispatch(j + 1)));
    }
    return dispatch(0);
  };
}
// 用法: request = compose([auth, throttle, cache, retry, log])
// cache 中间件: if (cached) return cached;   ← 短路, 不调 next
```
