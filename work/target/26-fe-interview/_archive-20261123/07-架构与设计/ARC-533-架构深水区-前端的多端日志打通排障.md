## ARC-533：一次会话的前端到服务端排障全景
**答**:
- 目标：用户报障时，用一个 sessionId 拉出全景：用户操作序列（行为日志 ARC-134）→ 前端错误与性能（RUM）→ 每次请求的服务端 trace（ARC-357）→ 相关后端日志。排障不再跨平台人工拼。
- 打通的键：sessionId（会话级）+ reqId/traceId（请求级）+ release（版本级）三级关联键全链路传递；前端诊断包（ARC-465）与服务端 trace 联合检索接口（排障工作台一次输入全量返回）。
- 排障工作台：输入 sessionId → 自动聚合五类数据（行为/错误/请求列表/trace 瀑布/服务端日志摘要）→ 时间线对齐展示（用户点击的时间轴与请求的时间轴对齐）。
- 权限与隐私：排障数据访问权限（工单号关联才可查——防滥用）、PII 脱敏一致（NODE-396 两端同规则）。
- 度量：排障耗时（从报障到定位的时长）趋势，打通前后的对比是基建价值证据。
```javascript
// 排障工作台聚合
async function troubleshoot(sessionId) {
  const [actions, errors, requests] = await feQuery.bySession(sessionId);
  const traces = await traceQuery.byReqIds(requests.map(r => r.reqId));  // ARC-357 关联
  const backendLogs = await logQuery.byTraceIds(traces.map(t => t.traceId));
  return mergeTimeline({ actions, errors, requests, traces, backendLogs }); // 时间线对齐
}
```
