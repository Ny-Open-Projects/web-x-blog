## DP-353：装饰器模式：三种形态

**答**：
- 装饰器的本质：不修改原对象，动态叠加职责——前端三种形态：高阶函数（日志/重试包装函数）、HOC（React 组件增强）、JS 装饰器（类成员注解）
- HOC 的实战规范：透传无关 props（...rest）、 displayName 标注（调试）、不破坏 ref（forwardRef 传递）——破坏性 HOC 是常见事故
- 函数装饰器的实战：重试/缓存/限流的「包装器组合」（compose 装饰）——装饰顺序影响语义（先重试再限流 vs 反之）
- 与继承的对比：装饰器是组合优于继承的实践——运行时可叠加，继承是静态的
- 深水点：装饰器的「叠加顺序陷阱」——@log(@retry(fn)) 与 @retry(@log(fn)) 的日志条数不同（重试产生多次日志）——装饰顺序要文档化

```javascript
// 高阶函数装饰器: 可组合
const withRetry = (fn, n = 3) => async (...a) => {
  for (let i = 0; i < n; i++) { try { return await fn(...a); } catch (e) { if (i === n - 1) throw e; } }
};
const withLog = (fn) => async (...a) => { console.log('start', fn.name); const r = await fn(...a); console.log('end'); return r; };
const withCache = (fn) => { const m = new Map(); return async (...a) => { const k = JSON.stringify(a); if (!m.has(k)) m.set(k, fn(...a)); return m.get(k); }; };
// 组合: withLog(withCache(withRetry(fetchUser))) — 顺序即语义
```
