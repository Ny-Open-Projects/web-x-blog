## ARC-616：Hybrid 混排滚动
**答**:
- 场景：App 内 H5 长页（原生导航栏 + H5 内容 + 原生悬浮按钮）——滚动联动（吸顶导航/标题渐变）跨 H5 与原生边界。
- 协作模式：全 H5 滚动（容器统一——原生只提供 WebView 容器，吸顶等纯 H5 实现：简单但吸顶性能与原生有差）、原生滚动转发（原生滚动 + offset 转发给 H5（JSBridge ARC-112）——原生丝滑但同步协议复杂）、分块混合（顶部原生 Tab + 下方 H5 列表滚动锁定——NestedScroll 协议（Android）与 iOS 的 contentInset 联动）。
- 架构决策：优先全 H5（一致性优先——性能达标的页面不引入桥接复杂度），性能不达标（长列表）再上原生滚动转发；桥接协议标准化（滚动 offset/吸顶状态/下拉刷新三事件——两端实现同一协议）。
- 坑位清单：iOS WebView 滚动惯性/fixed 失效（键盘弹起 ARC-615 联动）、Android 回收机制导致 fixed 抖动、安全区与导航栏高度（原生告诉 H5 insets——启动注入）。
- 验证：混排滚动真机矩阵（关键页面清单——吸顶/回弹/边缘 case）。
```javascript
// 原生滚动转发协议
bridge.on('scroll', ({ y }) => h5sync(y));                        // 原生 offset → H5 同步
bridge.on('topReached', () => h5.pullRefresh());                  // 下拉刷新联动
// insets 注入：bridge.call('getSafeArea') → H5 布局补偿
```
