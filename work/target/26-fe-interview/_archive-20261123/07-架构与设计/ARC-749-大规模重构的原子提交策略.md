## ARC-749：原子提交策略

**答**：
- 大重构的分支困境：长生命周期分支（迁移分支 3 个月）——合并冲突地狱；全量小步提交——主干随时可发布——「原子提交 + 功能开关」优于长分支
- 原子提交的实践：每个提交完成一个完整小步骤（可编译可测试）——「红绿重构」循环（先测试后重构——每步绿灯）
- 功能开关的配合：未完成的新实现藏在开关后（主干上持续集成——用户不可见）——开关让重构与发布解耦
- 长分支的允许场景：迁移初期探索性工作（不确定方向）——探索期短分支、确定后转原子提交
- 深水点：原子提交的「回滚粒度收益」——每提交可回滚（出问题二分定位到具体提交）——git bisect 友好

```text
原子提交:
  优于长分支: 主干持续集成 + 功能开关藏新实现
  实践: 每提交完整小步 (可编译可测试)
  探索期: 允许短分支, 确定后转原子
  收益: 每提交可回滚 + git bisect 友好
```
