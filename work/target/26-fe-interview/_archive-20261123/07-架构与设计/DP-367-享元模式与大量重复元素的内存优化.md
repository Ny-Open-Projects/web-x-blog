## DP-367：享元模式：共享减内存

**答**：
- 享元核心：分离「内部状态（共享）」与「外部状态（独特）」——10000 个相同图标的节点共享同一份图标对象，只差位置（外部状态）
- 前端实战：图标系统（sprite/组件实例共享）、虚拟列表的行组件复用（DOM 节点池——享元的 DOM 形态）、Canvas 粒子系统（粒子状态数组 + 单一绘制逻辑）
- 与对象池的关系：对象池是享元的「生命周期管理」变体（用完归还复用——内存恒定）
- 实战要点：内部状态的识别（什么可共享：样式/图标/模板；什么独特：数据/位置）
- 深水点：享元的「缓存键设计」——key 必须涵盖所有内部状态变体（漏一个维度=错误共享=UI bug）

```javascript
// 图标享元
const iconPool = new Map();
function getIcon(name, size) {
  const key = `${name}:${size}`;                     // key 覆盖全部内部状态!
  if (!iconPool.has(key)) {
    const img = new Image();
    img.src = `/icons/${name}@${size}.png`;
    iconPool.set(key, img);
  }
  return iconPool.get(key);                          // 共享同一 DOM/资源
}
// 10000 处 <Icon name="star" size={16}/> → 1 个实例
```
