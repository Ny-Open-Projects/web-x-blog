## ARC-267：大促结束后的复盘机制与数据沉淀怎么做？
**答**：
- 复盘三层：指标复盘（目标 vs 实际：白屏率/错误率/LCP/转化）、事件复盘（每次告警的 MTTR、根因分类、预案有效性）、资产复盘（哪些预案用上了、哪些演练没白做、哪些代码该下线）。
- 关键产出：问题清单转任务（owner+deadline）、预案库更新（新增/修订/废弃）、下次大促日历初稿。
- 数据沉淀：大促期间的指标快照入库作为**明年基线**（历史同环比的数据基础）；降级代码下线清单（活动代码回收，防常年背着大促包袱）。
- 机制设计：复盘会前数据先行（平台自动生成复盘报告草稿），会上只讨论"为什么"和"改什么"，不念数据。

```typescript
// 自动复盘报告骨架（平台聚合）
const report = {
  sla: compare(actual, target),                       // { whiteRate: [0.08%, 0.1%], pass: true }
  incidents: alerts.map(a => ({ id: a.id, mttr: a.ackTime - a.fireTime, rootCause: a.rootCause,
    planUsed: a.action })),
  plans: planLibrary.usage(),                         // 命中/未命中/无效
  cleanup: chunks.filter(c => c.campaign && c.expireAt < now),   // 待下线资产
};
// → 问题转 Jira 任务、预案库 diff、明年 calendar 草稿，一次产出
```
