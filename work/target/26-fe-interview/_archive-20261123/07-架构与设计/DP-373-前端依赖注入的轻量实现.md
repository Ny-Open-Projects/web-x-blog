## DP-373：依赖注入

**答**：
- 前端 DI 的形态：React Context（Provider 注入）、Vue provide/inject、构造参数注入——目的：依赖可替换（测试/多环境）
- 实战实现：轻量容器（token → factory 的 Map）+ 注入钩子（useInject(token)）——比 DI 框架轻，够用
- DI 的核心收益：测试替身（FakeApi 注入——组件测试不 mock 网络）、多环境切换（存储实现按环境注入）
- 注入的「token 设计」：Symbol token（防冲突）+ 类型关联（TS 泛型——token 携带类型）
- 深水点：DI 的「隐式依赖问题」——inject 看不出依赖来源（比参数注入隐式）——平衡：横切关注用 DI，核心依赖用参数

```javascript
const TOKENS = { Api: Symbol('Api'), Storage: Symbol('Storage') };
class Container {
  #factories = new Map(); #instances = new Map();
  register(token, factory, { singleton = true } = {}) { this.#factories.set(token, { factory, singleton }); }
  resolve(token) {
    const { factory, singleton } = this.#factories.get(token);
    if (singleton && this.#instances.has(token)) return this.#instances.get(token);
    const inst = factory(this);                       // 支持依赖其他 token
    if (singleton) this.#instances.set(token, inst);
    return inst;
  }
}
// 测试: container.register(TOKENS.Api, () => fakeApi) — 组件测试无需 mock 网络
```
