## ARC-275：大促稳定性建设的常态化：如何避免每次运动式保障？
**答**：
- 把大促动作转成日常基建：降级开关体系=配置中心日常能力（ARC-258）、白屏监控=日常 RUM、性能预算=日常 CI 门禁（ARC-262）、预案库=常态化故障演练产物。大促只是"高水位演练场"。
- 差异只留三样：冻结期日历、容量评估、值班编制——其余全部常年在线。
- 度量常态化程度：预案库中"日常可触发演练"的占比、监控大盘日常使用频率、SLO 错误预算是否平时就在烧（说明监控在真实运转）。
- 组织机制：稳定性 owner 制（每核心页面有 owner）、季度容灾演练、复盘任务闭环率考核——人上的机制比工具先失效。

```typescript
// 稳定性常态化检查表（季度审计）
const audit = [
  { item: '预案库', check: (lib) => lib.every(p => p.rehearsedInLast90d) },       // 预案 90 天内演练过
  { item: '降级开关', check: (f) => f.usedInProd30d.length > 0 || f.isDead(f) },  // 开关真被用过
  { item: '监控大盘', check: (m) => m.dailyActive > 0.6 },                        // 日常有人看
  { item: 'SLO 预算', check: (s) => s.consuming },                                // 真在统计
];
// 审计不过 → 季度任务；大促预案库 = 日常审计通过项的超集，大促只加"容量+值班"两层
```
