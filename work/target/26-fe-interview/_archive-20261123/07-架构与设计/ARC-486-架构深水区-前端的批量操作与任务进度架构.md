## ARC-486：批量操作与任务进度架构
**答**:
- 分级策略：≤ 50 条前端并发直接调（并发池 5）；更大规模转服务端异步任务（ARC-382 导出同构）——前端提交任务、轮询/SSE 进度、结果中心查看。
- 任务协议：taskId + 状态机（queued/running/done/partial/failed）+ 进度（done/total + 预估剩余）+ 失败明细（哪些条目失败、原因、可重试子集）。
- 部分成功语义：批量操作一半失败如何展示？——结果明细页（成功/失败分栏）、失败子集一键重试、不可重试项（权限不足）单独标出。禁止"全部成功"笼统提示掩盖部分失败。
- 前端交互：批量选择（当前页/全部结果集的区分——全选语义明确标注范围）、操作确认（影响条数显式展示）、进行中任务的持久化（关页面回来还能看进度）。
- 服务端配合：任务幂等、进度写入可查询、大任务限流（每用户并发 1 任务）。
```javascript
async function batchOp(ids, op) {
  if (ids.length <= 50) return runPool(ids, op, 5);           // 小批量直接跑
  const { taskId } = await api.createBatchTask({ ids, op });  // 大批量转异步
  watchProgress(taskId, (p) => ui.update({ done: p.done, total: p.total }));
  return pollFinal(taskId).then(r => showResult(r));          // partial 展示失败明细
}
```
