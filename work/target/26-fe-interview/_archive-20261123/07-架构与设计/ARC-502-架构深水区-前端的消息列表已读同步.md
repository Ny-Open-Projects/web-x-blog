## ARC-502：IM 消息已读同步与未读数
**答**:
- 已读模型：按会话记录 lastReadSeq（而不是逐条已读标志）；已读上报节流（可见即上报，50ms 合并）；对方已读回执渲染（单聊 seq 对比）。
- 未读数计算：服务端权威（会话 unread 计数，读会话时清零上报）；本地乐观清零 + 服务端对账；总未读 = 会话未读和（本地缓存 + 推送增量维护，ARC-394 通知体系）。
- 多端已读一致：已读位置多端同步（ARC-500 广播/服务端存储，设备维度 lastReadSeq），A 端读过 B 端不重复提醒（取 max）。
- 渲染细节：消息列表虚拟滚动（ARC-442）+ 已读分割线位置随 seq；正在输入、消息撤回、已编辑等状态更新走增量 patch（不重渲染整列表）。
- 可靠性：已读上报丢失的兜底（进入会话强制上报一次，NODE-392 seq 协议服务端兜底）。
```javascript
// 已读上报节流
const markRead = throttle(async (seq) => {
  if (seq <= lastReported) return;
  lastReported = seq;
  await api.readReport({ convId, seq });                         // 服务端权威
  unread.clear(convId);
}, 50);
// 多端同步：bus.on('read', ({ device, seq }) => lastRead = Math.max(lastRead, seq))
```
