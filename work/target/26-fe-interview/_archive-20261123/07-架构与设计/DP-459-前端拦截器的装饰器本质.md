## DP-459：拦截器的装饰器本质

**答**：
- axios 拦截器 = 装饰器管道：请求拦截器（装饰请求）、响应拦截器（装饰响应/捕获错误）——每个拦截器是「不改原函数的增强」
- 拦截器的顺序语义：请求拦截器按注册序执行、响应拦截器按注册逆序（洋葱模型）——「进序出逆」是理解拦截器组合的关键
- 拦截器的典型应用链：token 注入 → 幂等键 → 重试 → 错误转换 → 埋点——每环节独立可测
- 弹出错误的传播：拦截器 reject → 后续拦截器跳过 → 调用方 catch（链式传播）——reject 的「短路」语义
- 深水点：拦截器与中间件的选择——axios 拦截器（request/response 两段）vs fetch 中间件（洋葱模型全链）——洋葱模型能做「响应后还能改请求上下文」的事

```javascript
// axios 拦截器: 进序出逆
axios.interceptors.request.use(addToken);           // 进: 1st
axios.interceptors.request.use(addIdempotencyKey);  // 进: 2nd
axios.interceptors.response.use(unwrap, (e) => {    // 出: 逆序 — 先经过后注册的
  if (e.response?.status === 401) return refreshTokenAndRetry(e.config);
  return Promise.reject(e);
});
```
