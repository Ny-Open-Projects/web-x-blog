## ARC-382：大数据量表格导出架构如何设计？
**答**:
- 容量判断：行数 < 1 万前端导出（SheetJS 一次生成）；更大走服务端异步导出——前端提交导出任务，服务端流式写 Excel，完成后给下载链接。
- 异步导出架构：任务表（状态 pending/running/done/failed）+ 消息队列 + 进度接口轮询/推送 + 对象存储结果 + 过期清理；前端展示"导出中心"任务列表。
- 服务端流式生成：xlsx 的 stream writer（逐行写，不整表驻内存）；百万行用 CSV 或 xlsxwriter 分 sheet；内存与超时预算明确。
- 细节：字段国际化与格式（数字千分位/日期时区）与服务端列配置一致；大数据导出限流（每用户并发 1 任务）防拖垮服务；敏感字段导出权限与审计。
- 失败与重试：任务失败给原因（字段权限/超时），支持重试；结果文件有效期（如 24h）。
```javascript
// 前端导出中心任务流
async function exportRows(query) {
  const { taskId } = await api.createExportTask(query);   // 异步任务
  poll(taskId, { interval: 2000, until: s => s.status !== 'running' })
    .then(s => s.status === 'done'
      ? download(s.fileUrl)                                // OSS 签名链接
      : notify(`导出失败：${s.reason}`));
}
```
