## DP-434：令牌桶限流

**答**：
- 令牌桶 vs 滑动窗口：令牌桶允许突发（桶容量=突发额度）——上报限流（平时匀速+高峰突发）
- 实战实现：时间驱动的令牌累积（不用定时器逐个加——按时间差计算：tokens += elapsed × rate）——无漂移
- 与策略模式组合：限流策略可插拔（令牌桶/滑动窗口/固定窗口——按接口特性选择）
- 请求排队语义：take(n) 不足时等待（Promise 化——令牌够了 resolve）vs 直接拒绝（tryTake——秒杀场景）
- 深水点：限流的「多级组合」——QPS 限流（令牌桶）+ 并发限流（信号量）双层——速率与并发是两个独立维度

```javascript
class TokenBucket {
  #tokens; #last = performance.now();
  constructor({ rate, capacity }) { this.rate = rate; this.capacity = capacity; this.#tokens = capacity; }
  #refill() {
    const now = performance.now();
    this.#tokens = Math.min(this.capacity, this.#tokens + ((now - this.#last) / 1000) * this.rate);
    this.#last = now;
  }
  async take(n = 1) {
    this.#refill();
    if (this.#tokens >= n) { this.#tokens -= n; return; }
    const wait = ((n - this.#tokens) / this.rate) * 1000;
    await new Promise((r) => setTimeout(r, wait));
    this.#refill(); this.#tokens -= n;
  }
}
// 双层: 令牌桶(20/s) × 信号量(并发6) — 埋点上报的组合限流
```
