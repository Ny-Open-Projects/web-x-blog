## ARC-426：前端如何做混沌工程？
**答**:
- 前端混沌的目标：验证降级/重试/超时这些"设计了但从不触发"的路径真实可用。注入手段：网关故障注入（延迟/错误率/断流）、CDN 故障切换、端上网络条件模拟（弱网/断网/高丢包）。
- 端上注入层：请求层内置故障注入开关（测试环境），可模拟慢响应、5xx、超时、断连重连；SW 层模拟缓存失效。
- 演练场景库：接口 500 → 降级缓存数据展示？WS 断连 → 自动重连 + gap 补拉？CDN 切换 → 用户无感？支付回调丢失 → 查单兜底生效？每个场景验证"用户看到什么"而非"代码走了哪行"。
- 度量：韧性指标（MTTR 模拟值、降级触发率、恢复时延）；演练发现的缺陷进入修复队列闭环。
- 安全边界：演练只在灰度名单/测试流量上执行，生产全量注入需审批与一键终止。
```javascript
// 请求层故障注入（仅 test 环境）
function chaos(config) {
  if (!ENV.chaos?.enabled) return config;
  const rule = matchRule(config.url, ENV.chaos.rules);         // {url:/api/goods, delay:3000, rate:0.3}
  if (rule?.delay) config.mockDelay = rule.delay;
  if (rule && Math.random() < rule.rate) config.mockError = rule.status ?? 500;
  return config;
}
// 演练验收：断言降级 UI 出现且核心功能可用
```
