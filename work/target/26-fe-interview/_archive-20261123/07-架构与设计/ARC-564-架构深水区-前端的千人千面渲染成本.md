## ARC-564：个性化渲染的成本架构
**答**:
- 个性化与缓存的矛盾：千人千面 → 每人不同 → 无法用公共缓存 → 每请求全量计算。架构目标：个性化"局部化"——页面骨架公共缓存 + 个性化片段按需。
- 分层方案：骨架静态化（页面结构公共，CDN 缓存 ARC-102）、个性化片段分离（用户专属模块独立请求/ESI 边缘注入 ARC-375）、个性化降档（推荐流首屏公共热门 + 差异化增量——不是全页个性化）。
- 缓存键设计：个性化数据的缓存键 = 用户维度（短 TTL）+ 分层（活跃用户热缓存，长尾冷——ARC-438 热点分片）；推荐结果缓存（同类用户共享——按特征分桶缓存而非逐用户）。
- 性能预算：个性化不影响 LCP（个性化模块异步后置 + 占位 ARC-494）、个性化请求预算独立（ARC-546 分级：个性化属于 normal/lazy）。
- 成本核算：个性化计算成本（推荐服务 QPS 成本）随流量线性涨——降档开关（高峰期统一公共内容，成本与效果平衡）。
```javascript
// 骨架 + 个性化片段
route.get('/', cachedPage(skeletonHtml, { ttl: 300 }));          // 公共骨架 CDN
route.get('/me/fragments', async (ctx) =>                        // 个性化片段独立
  ctx.body = { recommend: await reco.for(ctx.user, { bucketShared: true }) });
// 前端：骨架先渲染（公共缓存秒开），个性化模块并行填充
```
