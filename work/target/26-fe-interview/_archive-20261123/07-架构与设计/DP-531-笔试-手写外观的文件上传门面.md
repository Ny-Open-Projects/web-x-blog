## DP-531：笔试：手写上传门面

**题目**：实现文件上传外观 `uploadFacade.upload(file)`：① 内部编排：校验（魔数/大小）→ 压缩（图片）→ 策略选择（直传/分片）→ 上传（进度）→ 确认（服务端）——五步收拢；② 策略路由：>10MB 分片（断点续传）/小文件直传——按文件特征；③ 进度统一：压缩 0-30% + 上传 30-100%（分段进度合成）；④ 取消：AbortController 贯穿全链（压缩与上传都可取消）；⑤ 产出统一（{ url, fileId }——业务一行调用）。写出实现。

```javascript
class UploadFacade {
  async upload(file, { onProgress, signal } = {}) {
    // 1) 校验
    const type = await sniff(file);
    if (!type) throw new UploadError('unsupported-type');
    // 2) 压缩 (图片)
    onProgress?.({ phase: 'compress', pct: 0 });
    const blob = type.startsWith('image') ? await compress(file, signal) : file;
    onProgress?.({ phase: 'compress', pct: 30 });
    // 3) 策略选择
    const strategy = blob.size > 10 * 1024 * 1024 ? chunkedUpload : directUpload;
    // 4) 上传 (进度 30-100 映射)
    const result = await strategy(blob, {
      signal,
      onProgress: (pct) => onProgress?.({ phase: 'upload', pct: 30 + pct * 0.7 }),
    });
    // 5) 确认
    const confirm = await api.confirmUpload(result.key);
    return { url: confirm.url, fileId: confirm.fileId };   // 统一产出
  }
}
// 业务: await uploadFacade.upload(file, { onProgress }) — 五步一行
// 取消: signal.abort() → 压缩与上传同时中断
```

**评分点**：
- 五步编排收拢（校验→压缩→策略→上传→确认）
- 策略路由（按文件特征直传/分片）
- 分段进度合成（压缩与上传的百分比映射）
- AbortController 全链贯穿（取消语义完整）
