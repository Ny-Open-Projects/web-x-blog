## DP-354：单例模式：合理与反模式

**答**：
- 前端合理单例：WebSocket 连接管理器、全局配置中心、性能监控 SDK、路由实例——「全局唯一且无状态竞争」的资源
- 反模式：把业务状态做成单例（全局可变状态——测试难/并行冲突）——「单例 ≠ 全局变量」
- ES Module 的天然单例：模块加载即单例（import 缓存）——显式单例类在 ESM 下通常不需要（模块级常量即可）
- 单例的测试友好设计：依赖注入入口（构造时传入依赖而非内部 new）+ reset 方法（测试隔离）
- 深水点：React StrictMode 双挂载下单例的「重复初始化」——初始化守卫（if (!instance) create）+ 副作用分离（连接与注册分离）

```javascript
// ESM 模块级单例 (推荐)
class WSManager {
  #ws = null; #refs = 0;
  acquire() { this.#refs++; this.#connect(); return this; }
  release() { if (--this.#refs <= 0) this.#disconnect(); }
  #connect() { if (!this.#ws) this.#ws = new WebSocket(url); }   // 初始化守卫
}
export const ws = new WSManager();
```
