## ARC-546：页面级请求预算分配
**答**:
- 场景：一次页面渲染发起 10+ 请求——无预算管理时互相抢带宽/连接（HTTP/1.1 6 连接限制），慢接口拖死整体。预算制：页面声明请求优先级与超时预算，请求层调度执行。
- 分级：critical（首屏必需：并行全发 + 短超时 2s，失败降级）、normal（首屏次要：critical 后发）、lazy（交互后/空闲 ARC-405）；并发上限（浏览器连接数感知，HTTP/2 下控制多路复用公平性）。
- 超时预算联动（NODE-377 服务端 deadline 传播的前端版）：关键请求预算优先，非关键请求在预算紧张时主动推迟或取消（页面总预算 5s——超时后 lazy 全取消）。
- 取消策略：页面路由切换 → 未完成请求批量取消（AbortController 池 ARC-410），防"切走了还在发请求"浪费与状态错乱。
- 观测：页面请求瀑布（按分级着色的时序图）、预算超标页面上报（新页面偷偷发 20 个请求 → 性能回归拦截 ARC-407）。
```javascript
// 页面请求调度器
const scheduler = createRequestScheduler({ budget: 5000, concurrency: 6 });
scheduler.critical(['goods.list', 'user.profile']);              // 并行短超时
scheduler.normal(['recommend.list'], { after: 'critical' });     // 依赖 critical 完成
scheduler.lazy(['chat.history'], { idle: true });
router.onLeave(() => scheduler.abortAll());                      // 离开批量取消
```
