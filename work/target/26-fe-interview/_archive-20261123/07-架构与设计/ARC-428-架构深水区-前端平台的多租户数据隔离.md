## ARC-428：B 端多租户前端的数据隔离与个性化架构
**答**:
- 租户上下文贯穿：登录时解析租户（域名/路径/header），租户 ID 注入所有请求 header（X-Tenant-Id）、所有监控上报、所有缓存键——缓存键不带租户就是数据串户事故。
- 前端缓存隔离：localStorage/IndexedDB 键加租户前缀；切换租户（同一用户多租户）走"完全重置"（清内存态 + 重载），禁止热切换共享 store。
- 个性化分层：租户级（主题/域名/功能开通）、用户级（角色权限）、实例级（租户自己的配置）；三级配置合并顺序固定，前端只读消费。
- 安全细节：URL 不携带租户密钥；租户功能开关由服务端下发（前端清单仅显隐）；导出/分享链接做租户校验。
- 可观测：按租户切片的错误率/性能（大租户问题不影响全局告警判断），租户级 SLA 报表。
```javascript
// 请求层租户注入与缓存键隔离
axios.interceptors.request.use(c => { c.headers['X-Tenant-Id'] = tenant.current; return c; });
const cacheKey = (k) => `${tenant.current}:${k}`;              // 所有本地缓存统一前缀
function switchTenant(id) {
  tenant.set(id);
  store.reset(); idb.clearNamespace(tenant.previous);          // 内存+持久化双清
  location.assign(buildTenantUrl(id));                          // 重载而非热切换
}
```
