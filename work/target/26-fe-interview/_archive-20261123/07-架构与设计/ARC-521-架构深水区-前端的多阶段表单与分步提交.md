## ARC-521：多阶段提交的一致性架构
**答**:
- 场景：一个业务对象分多次提交完成（先建草稿 → 补充资料 → 提交审核），每步独立接口。核心问题：部分提交的中间态语义清晰、断点可续（ARC-488）、整体一致（最后一步校验全量）。
- 状态机驱动（ARC-451）：阶段状态（draft → partial → submitted → reviewing）服务端权威，前端按状态渲染可编辑性（submitted 后锁字段）。
- 提交协议：每步提交携带 stepId + 阶段快照校验（前序步骤未完成则阻断）；阶段间依赖声明（第 2 步依赖第 1 步的字段，前步变更后步标记重验 ARC-489）。
- 断点续填：阶段进度持久化（服务端 + 本地 ARC-483）、恢复时从最近完成阶段继续、过期策略（草稿 30 天失效提醒）。
- 一致性收尾：最终提交做全量 schema 校验 + 部分提交数据合并校验（分步填的数据组合后可能不满足整体约束——金额分步填但合计超限）。
```javascript
// 分步提交协议
async function submitStage(stageId, data) {
  const st = await api.stageStatus(objId);
  if (!st.completed.includes(stageId - 1)) throw new Error('前序阶段未完成');
  const saved = await api.saveStage({ objId, stageId, data,
    baseVersion: st.version });                                  // 阶段级 CAS
  if (stageId === LAST) await api.finalize(objId);               // 全量校验 + 状态推进
  return saved;
}
```
