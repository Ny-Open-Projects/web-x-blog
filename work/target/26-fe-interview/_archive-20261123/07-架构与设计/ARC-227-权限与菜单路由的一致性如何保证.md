## ARC-227：权限与菜单、路由的一致性如何保证？
**答**：
- 经典 bug：菜单显示了入口但路由 403，或路由能进但菜单没入口。根因是菜单、路由、权限码三份数据各自维护。
- 方案：**单一事实源**——路由配置里声明 `perm: 'order:read'`，菜单由"过滤后的路由表"自动生成，不再单独维护菜单权限。可见性 = 可导航性。
- 层级权限：菜单项可以要求"任一子路由有权即可见"（hasAny），避免父级 perm 写错导致整组消失。
- 一致性测试：CI 里遍历路由表，断言"有 perm 的路由必有菜单可达路径（或显式 hidden）""菜单叶子必对应真实路由"。

```typescript
// 路由即唯一事实源
const routes = [
  { path: '/order', perm: 'order:read', children: [
    { path: 'list',  component: OrderList },
    { path: 'audit', perm: 'order:audit', component: OrderAudit },
  ]},
];
function buildMenu(rs, snap) {                       // 菜单 = 权限过滤后的路由投影
  return rs.filter(r => !r.perm || hasAny(snap, r))  // hasAny：子路由任一有权即可见
    .map(r => ({ title: r.title, path: r.path, children: r.children && buildMenu(r.children, snap) }));
}
// CI 一致性检查：assert every leaf(route with perm) is reachable from menu(snap of each fixture role)
```
