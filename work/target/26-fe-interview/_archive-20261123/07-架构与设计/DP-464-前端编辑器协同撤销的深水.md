## DP-464：协同撤销深水

**答**：
- 协同撤销的难题：撤销「我的删除」但中间有他人插入——直接逆操作会破坏他人内容（变换补偿——OT undo 的核心）
- 变换补偿的原理：撤销操作要「跳过」并发操作的偏移（op 的位置在并发插入后已移动——transform 重定位）
- 实现路径：操作历史按「作者分组」——undo 只处理自己的操作序列 + transform 补偿并发——CRDT 的 undo 是内建的（每个操作有唯一 ID——按作者撤销）
- 深水点：协同撤销的「语义选择」——撤销到最后一个共同状态 vs 精确撤销自己的操作——产品决策（协作文档通常「撤销我的」）

```javascript
// OT 撤销: 我的 op 的逆操作要经过并发操作变换
function undoMine(myOpHistory, concurrentOps) {
  const inverse = invert(myOpHistory.at(-1));
  const transformed = concurrentOps.reduce((op, c) => transform(op, c), inverse);
  apply(transformed);                                // 变换补偿后的撤销
}
// CRDT: 每操作带 actorId — undo 按 actorId 过滤自己的操作链
```
