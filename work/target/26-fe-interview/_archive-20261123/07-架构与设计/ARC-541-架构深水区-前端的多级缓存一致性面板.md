## ARC-541：多级缓存一致性调试工具
**答**:
- 问题（ARC-444 五层缓存）的排障难：用户说"数据不对"，工程师要逐层检查（内存/持久/HTTP/SW/CDN）——做缓存检查器（devtools 面板）：一次展示某数据在各层的版本与时间戳，秒级定位陈旧层。
- 实现要点：各缓存层写入时打标（version/timestamp/source），检查器聚合展示（当前值 + 各层快照对比）；模拟失效操作（逐层 invalidate 按钮——验证失效链路真实生效，ARC-444 级联协议的自检）。
- 场景化检查：怀疑 SW 缓存旧版本 → 一键列出 SW cache keys 与对应 manifest 版本；怀疑 HTTP 层 → 展示响应缓存头（Age/ETag/Cache-Control）解读。
- 自动化：CI 层面缓存一致性回归（写操作 → 断言各层失效，Playwright + SW 检查脚本 ARC-424 思想）。
- 教育价值：检查器同时是新人理解缓存体系的工具（可视化层级与失效路径）。
```javascript
// 缓存检查器（devtools 面板数据源）
async function inspectCache(key) {
  const layers = {
    memory: memCache.inspect(key),                               // {value, version, ts}
    idb: await idbCache.inspect(key),
    http: await fetch(url, { headers: { 'x-cache-inspect': 1 } }).then(r => parseCacheHeaders(r)),
    sw: await swCache.inspect(key)                               // SW 内 RPC 列 cache keys
  };
  return { key, consistent: sameVersion(layers), layers };       // 版本不一致即陈旧层定位
}
```
