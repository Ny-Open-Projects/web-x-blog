## ARC-368：前端基建：从构建到上线的发布编排如何设计？
**答**：
- 前端发布链路：CI 构建 → 产物上传 CDN（immutable 哈希文件名）→ 发布单审批 → HTML/入口更新（原子切换）→ 线上对账。核心原则：入口与产物分离，产物永不覆盖，入口原子更新。
- 原子性：HTML 发布用版本目录 + 索引原子切换（软链/对象存储版本指针），任一时刻线上只有完整版本组合，杜绝新旧资源错配。
- 回滚即切换指针回上一版本，秒级完成；回滚演练纳入例行流程。
- 与灰度联动：入口服务支持按用户特征返回不同版本 HTML（ARC-276），发布编排提供"全量/灰度/指定名单"三种通道。
- 可观测：发布事件自动打标到监控平台，发布后 15 分钟自动对比核心指标（错误率/LCP），异常自动暂停放量。
```javascript
// 入口原子切换（对象存储版本指针）
async function publish(buildId) {
  await uploadAssets(buildId);                 // 1. 产物上传（immutable）
  await verifyAssets(buildId);                 // 2. 线上抽样对账
  await atomicUpdatePointer('current', buildId); // 3. 原子切指针
  await watchMetrics(buildId, { window: '15m', autoPause: true }); // 4. 自动观测
}
```
