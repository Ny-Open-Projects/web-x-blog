## ARC-378：音视频前端架构：播放链路如何设计？
**答**：
- 协议选型：点播 H5 主流 HLS（兼容好、延迟 5~10s）与 MP4（首帧快）；低延迟直播 WebRTC（< 1s）或 LL-HLS（2~5s）；H.265 在 Web 需考虑解码支持矩阵（Safari/MSE 扩展）。
- 播放器分层：源加载器（HLS.js/MSE demux）→ 解码渲染（video 标签/WebCodecs/Canvas）→ 控制层（UI/快捷键）→ 业务层（鉴权/埋点/弹幕）。自研播放器是组装而非全自写。
- 核心指标：首帧时间（起播优化：预加载、探测最优清晰度）、卡顿率（rebuffer/播放时长）、秒开率。清晰度自适应（ABR）按带宽估计切换。
- 架构要点：多实例管理（列表页预览静音懒加载）、内存控制（只保留滑动窗口分片）、错误恢复（解码失败换源、断流重连退避）。
- DRM 与防盗链：token 签名 URL + 有效期、水印（用户 ID 隐写）、HLS 加密密钥鉴权分发。
```javascript
// 播放器组装层
const player = new Player(el, {
  src: signUrl(videoUrl, { exp: 300 }),               // 防盗链签名
  abr: { initial: detectTier() === 'low' ? 480 : 720 },
  onStall: (d) => metrics.stall(d),                    // 卡顿上报
  onError: async (e) => {                              // 恢复链
    if (e.fatal) await player.switchSource(backupUrl); // 换备用源
  }
});
```
