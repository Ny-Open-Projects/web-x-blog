## DP-444：撤销重做边界

**答**：
- 撤销的边界场景：异步命令（图片上传完成才入栈——撤销要等资源就绪）、跨组件撤销（全局命令栈 vs 每组件独立栈——焦点决定撤销目标）、协作撤销（他人操作插入后「撤销我的」的语义——变换补偿）
- 命令的「副作用回滚」：命令的副作用（发请求/通知）无法完美 undo——「补偿而非还原」（撤销删除 = 恢复记录而非恢复删除动作）
- redo 栈的清空时机：新操作清空 redo（git 语义）——分支化（保留 redo 树——复杂度高，产品通常不需要）
- 深水点：撤销的「内存管理」——命令持有大对象（图片数据）——栈上限 + 旧命令的数据瘦身（只留 diff 不留全量）

```javascript
class AsyncCommand {
  constructor(task, inverse) { this.task = task; this.inverse = inverse; this.done = false; }
  async execute() { this.result = await this.task(); this.done = true; }
  async undo() { if (!this.done) await this.task; await this.inverse(this.result); }   // 等任务完成
}
// 大对象瘦身: 命令只存 diff (before/after patch), 不存全量快照
```
