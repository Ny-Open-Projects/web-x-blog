## ARC-390：灰度/AB 数据与业务指标的联动架构如何设计？
**答**:
- AB 有效性的前提是"分桶信息跟随每一条数据"：所有埋点/错误/性能上报自动附加实验维度（experimentId + bucket + 版本），SDK 统一注入，业务无感。
- 数据链路：端上报 → 网关补全维度（登录态/地域）→ 数仓按实验分桶切片 → 指标平台按分桶对比（转化率/GMV/留存）+ 显著性检验。
- 常见错误做法：实验维度只有部分埋点带（漏斗断链）、分桶在渲染时才决定（曝光前已变桶）、分桶写入 cookie 但接口读 header（口径不一）。架构上必须"一次分桶，全程携带"。
- 指标分层：护栏指标（错误率/性能不许劣化）+ 北极星指标（实验目标）；实验评估自动出对比报告。
- 与灰度监控联动（ARC-279）：实验桶错误率超阈值自动熔断该桶。
```javascript
// SDK 层：全局注入实验维度
function report(event, payload) {
  const dims = { ...activeExperiments() };              // {exp1:'A', exp2:'B'}
  send(event, { ...payload, ...dims, release: VERSION });
}
// 分桶只在会话初始化时决定并固化，session 内不变
function activeExperiments() {
  return Object.fromEntries(experiments.map(e => [e.id, bucketOf(userId, e)]));
}
```
