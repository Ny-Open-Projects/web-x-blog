## ARC-613：埋点回归门禁
**答**:
- 问题：改代码顺手改坏埋点（事件漏发/参数错——数据链路静默污染，ARC-424 的门禁化）。
- 门禁实现：埋点快照测试（E2E 关键路径跑一遍 → 断言事件序列与期望一致——操作 X 必产生事件 Y 带参数 Z；事件流快照 diff 审查）、schema 校验（ARC-535 字典约束——类型/必填错误即失败）、覆盖率检查（核心路径的埋点覆盖率——新页面缺关键事件阻断）。
- 用例维护：埋点用例与事件字典同源生成（字典定义触发场景 → 自动生成用例骨架——减少手写腐烂）、字典变更 → 用例自动更新（联动维护）。
- 容错与噪音：快照严格度分级（核心转化事件严格断言、展示类宽松）、flaky 治理（埋点时序抖动——等待策略与重试，flaky 率 > 2% 修用例 ARC-130）。
- 闭环：门禁拦截的缺陷统计（证明价值）、漏网事故复盘补用例（每个埋点事故 = 一条新用例）。
```javascript
// 埋点快照断言
test('下单路径埋点序列', async ({ page }) => {
  await page.addInitScript(sinkHook);                            // 收集事件流
  await buyFlow(page);
  const evs = await page.evaluate(() => window.__events__);
  expect(evs.map(e => e.event)).toEqual(['goods_expose', 'goods_click', 'order_submit', 'pay_launch']);
  expect(evs.find(e => e.event === 'order_submit')).toMatchObject({ goods_id: expect.any(String) });
});
```
