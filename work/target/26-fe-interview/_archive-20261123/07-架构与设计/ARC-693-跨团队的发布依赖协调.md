## ARC-693：发布依赖协调

**答**：
- 依赖类型：组件库新 API（A 团队要 B 团队的组件支持）、后端接口（新字段）、基座能力（微前端新协议）——跨团队依赖是排期最大变数
- 依赖的显式化：需求拆解时标注「外部依赖」+ 依赖负责人 + 需要时间——排期评审检查依赖可行性
- 依赖的解耦策略：适配层（B 团队未就绪时 A 自己包一层临时实现——后续替换）——「不阻塞主流程」的弹性
- 依赖升级窗口：组件库发新版 → 各团队升级排期（一个迁移周期）——「发布即生效」对多团队不现实
- 深水点：依赖的「二段式交付」——组件库先发 API（beta 标记）→ A 团队基于 beta 开发 → 组件库正式发布——并行度最大化

```text
发布依赖:
  显式化: 需求标注依赖+负责人+时间
  解耦: 适配层临时实现 (不阻塞)
  窗口: 新版发布 → 迁移周期
  二段式: beta API 先行 → 正式发布 (并行度最大化)
```
