## DP-480：模式选型决策树

**答**：
- 按问题类型查表：全局状态 → 观察者+备忘录（store）、流程控制 → 状态机+命令、第三方集成 → 适配器+外观、性能隔离 → 代理+享元、可扩展 → 插件+责任链、错误治理 → 边界+空对象、高频事件 → 批处理+限流
- 决策树的三问：问题重复出现吗（Rule of Three）、变化方向明确吗（策略/状态机的时机）、团队理解成本可承受吗——三问过才上模式
- 模式的「组合上限」：一个模块 2~3 个模式（组合爆炸 = 认知过载）
- 深水点：决策树的「动态性」——模式选型随框架演进（React 18 并发让某些防抖模式被 deferredValue 替代）——决策树是活的

```text
模式选型决策树:
  全局状态? → store (观察者+备忘录)
  多步流程? → 状态机 + 命令
  第三方接入? → 适配器 + 外观
  性能问题? → 先 Profiling → 代理/享元/虚拟化
  需要扩展? → 插件 + 责任链
三问: 重复? 变化明确? 成本可承受? → 才上模式
```
