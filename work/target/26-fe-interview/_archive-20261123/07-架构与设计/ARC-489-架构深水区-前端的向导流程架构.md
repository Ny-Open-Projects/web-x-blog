## ARC-489：向导流程（多步表单/引导流）架构
**答**:
- 向导本质是状态机（ARC-451）+ 数据收集器 + 恢复能力（ARC-488）的组合：步骤定义（顺序/分支/跳过条件）+ 步骤间数据契约（每步产出 schema）+ 校验边界（步内校验 vs 提交校验）。
- 分支流程：步骤图支持条件分支（企业用户跳过 X 步）——步骤定义为有向图而非线性数组；回退到分支点要重算后续步骤。
- 数据管理：步骤数据独立分片存储（避免单一大对象），最终提交时合并 schema 校验（ARC-384）；跨步字段依赖（第 3 步用到第 1 步的值）显式声明，修改前步时后续步骤标记"需重新确认"。
- 恢复与放弃：步骤进度 + 数据自动持久化（ARC-483 草稿）；中途放弃给"保存草稿/丢弃"选择。
- 异常边界：某步接口失败允许"跳过稍后补"（非关键步）或卡点重试（关键步）；提交失败的兜底（全量数据已在本地不丢）。
```javascript
const wizard = {
  steps: graph([ 'basic' -> 'verify' | 'skip-verify' -> 'confirm' ]),   // 条件分支
  data: shardByStep(),                                         // 分片存储
  canEnter(step, ctx) { return step.guard?.(ctx) ?? true; },   // 分支守卫
  onPrevChange(changedStep) {                                  // 前步变更 → 后续需重确认
    markStaleAfter(changedStep);
  }
};
```
