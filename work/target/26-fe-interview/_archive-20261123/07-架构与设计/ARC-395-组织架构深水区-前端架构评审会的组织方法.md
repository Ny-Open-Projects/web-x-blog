## ARC-395：架构评审会的组织方法如何设计？
**答**:
- 评审会的三类：方案预审（做不做、方向对不对）、设计评审（怎么做、边界清楚吗）、变更评审（存量架构的重要改动）。各有不同 checklist（ARC-187）。
- 组织规则：材料提前 24h 发（会上只对齐分歧，不从头讲）；决策人明确（谁拍板、谁备案）；记录即时产出（决议/风险/待办三栏）会内成文。
- 防走过场：评审问题必须落到可验证条款（"灰度方案是什么"而不是"再考虑下"）；未通过的方案明确 re-review 条件；通过率不是 KPI（全通过 = 评审失效）。
- 效率控制：小改动走轻量通道（文档评论 + 架构师批注），只有跨团队/不可逆决策进全会。
- 闭环：评审决议编号关联 ADR；后续实际执行与决议的偏差在下一次评审首问。
```javascript
// 评审记录模板
const reviewRecord = {
  decision: '采用 Module Federation 方案，qiankun 仅老应用过渡期使用',
  risks: ['公共依赖升级需联邦协商机制（责任方：平台组，DDL：两周）'],
  todos: [['出灰度与回滚方案', 'appA owner', '本周五']],
  reReviewCondition: null   // 未通过时写明复评条件
};
```
