## DP-374：事件溯源裁剪版

**答**：
- 事件溯源核心：状态 = 事件序列的折叠（fold）——不存状态存操作（操作日志 → 重放得状态）
- 前端裁剪场景：协作编辑（操作日志同步——CRDT 的基础）、画布操作重放（操作序列回放教学）、撤销（事件逆操作）
- 前端的取舍：全量事件溯源成本高（存储/重放性能）——裁剪为「最近 N 条操作 + 快照基线」（快照 + 增量事件——游戏存档模式）
- 实战结构：Event { type, payload, ts, actor } + reducer(events) → state——事件是持久化单元，状态是派生
- 深水点：事件的「不可变与有序」——事件一旦写入不改（修正 = 补偿事件）——与命令模式的区别：命令是意图，事件是事实

```javascript
function createState(events, initial) {
  return events.reduce((state, e) => reducers[e.type](state, e), initial);
}
// 快照 + 增量 (裁剪版):
// { snapshot: state@t100, events: [e101, e102, ...] } — 重放只需增量
// 补偿事件: 删除错误添加的节点 → 添加 { type: 'node:removed' } 而非改历史
```
