## DP-435：组合优于继承

**答**：
- 继承的前端困境：类组件继承链（BasePage → ListPage → XxxPage——改动基类影响全链）、HOC 嵌套地狱（多层包装——调试困难）
- 组合的形态：Hooks（逻辑复用——平行组合）、组件组合（children/slot——结构组合）、mixin→composable（行为组合）
- 继承仍合理的场景：框架基类（ErrorBoundary 必须继承 Component）、模板方法骨架（生命周期编排）——「框架要求继承时才继承」
- 迁移路径：继承链 → 提取 mixin → 转 hooks/composables（每步可验证——渐进迁移）
- 深水点：继承的「脆弱基类问题」——基类改一个钩子顺序，所有子类行为变化且无人察觉——组合的显式依赖让变更影响可见

```javascript
// 继承链 → 组合迁移
// 旧: class ListPage extends BasePage { fetchData() {...} }   ← BasePage 改动影响所有页
// 新: function useListPage() { const data = useFetch(); useTrack('list'); return data; }
//     function ListPage() { const data = useListPage(); ... }  ← 显式依赖, 影响可见
```
