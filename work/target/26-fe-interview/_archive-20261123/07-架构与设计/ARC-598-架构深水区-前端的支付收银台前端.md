## ARC-598：收银台前端架构
**答**:
- 职责：聚合多支付方式（余额/银行卡/第三方渠道）+ 安全展示 + 发起支付 + 结果确认——收银台是独立应用（可嵌入 H5/App/PC 多宿主 ARC-109）。
- 支付方式管理：方式列表服务端下发（可用性/限额/营销标签——服务端裁决可用渠道），前端渲染注册表（每种方式一个适配器：发起协议不同——跳转/JSBridge/原生 SDK）。
- 发起支付协议：统一发起（payToken → 适配器 → 渠道）→ 结果三态确认（成功/失败/未知——unknown 走查单 ARC-418）；中断恢复（收银台刷新/回跳丢失——payToken 重入）。
- 安全红线：金额/商品信息只读展示（服务端下发不可改）、不聚合敏感卡信息（PCI 边界：卡号输入走渠道 SDK/令牌化——收银台不碰卡数据）、防篡改（参数服务端签发）。
- 体验：方式记忆（用户偏好置顶）、失败原因可懂化（渠道错误码转译 ARC-491 思想）、超时与轮询节奏（2s×15 次 ARC-418）。
```javascript
// 支付方式适配器
const payAdapters = { balance: BalanceAdapter, alipay: RedirectAdapter, wechat: JsBridgeAdapter };
async function pay(method) {
  const a = payAdapters[method];                                 // 服务端下发方式列表
  const r = await a.invoke({ payToken });                        // 统一发起
  if (r.state === 'unknown') return pollResult(payToken);        // 查单兜底
  return navigate(r.state === 'success' ? '/success' : `/fail?reason=${r.code}`);
}
```
