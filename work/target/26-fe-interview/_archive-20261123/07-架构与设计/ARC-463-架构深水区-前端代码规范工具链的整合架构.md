## ARC-463：代码规范工具链的整合架构
**答**:
- 打架根源：格式化与 lint 职责重叠（Prettier 与 ESLint 都管格式）。分工原则：Prettier 管格式、ESLint 管代码质量与模式、TypeScript 管类型、各自插件关闭冲突规则（eslint-config-prettier）。
- 分层配置：基础包（preset：团队统一规则）→ 项目继承（extends）→ 项目级例外（允许个别目录放宽，需注释理由）；配置本身版本化、有 changelog。
- 执行位置：编辑器即时（保存格式化 + 实时 lint）、提交钩子（lint-staged 增量）、CI 全量（兜底 + 增量报告）。三层规则集完全一致（同一 preset），防"本地过 CI 挂"。
- 规则分级：error（阻断）、warn（提示）、off（明确关闭并注释）；新规则上线用 warn 观察期 + 自动修复优先（--fix 能解决的直接 error）。
- 演进：规则提案走 RFC；规则效果回看（误报率、autofix 率、绕过数），每季度清理无效规则。
```jsonc
// .eslintrc 继承链
{
  "extends": ["@corp/eslint-config/base", "@corp/eslint-config/react", "prettier"],
  "rules": {
    // 项目级例外：必须注释理由
    "no-restricted-imports": ["error", { "patterns": ["@corp/legacy/*"] }] // 迁移期禁止新引旧库
  }
}
```
