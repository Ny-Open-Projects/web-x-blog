## DP-397：模式的测试策略

**答**：
- 每种模式的测试焦点：策略（每策略单测 + 策略选择逻辑）、状态机（迁移矩阵遍历 + 非法迁移拒绝）、命令（execute/undo 对称性）、观察者（订阅/退订/错误隔离）、装饰器（装饰前后行为对比 + 顺序语义）
- 模式组合的测试：先单元（每模式独立）后集成（组合行为——管道顺序断言）
- 测试替身的运用：DI 注入 Fake（策略可测不需要真网络）、状态机的 Fake 时钟（时间驱动迁移）
- 模式测试的「对称性断言」：undo/redo 后状态应与初始一致（命令模式的黄金断言）；缓存命中与未命中的结果一致（代理模式）
- 深水点：模式的「契约测试」——模式的公共行为约定写成可复用的测试套件（任何实现该模式的类都跑同一套契约测试——策略契约/缓存契约）

```javascript
// 命令模式的对称性黄金断言
function testCommandContract(cmdFactory, getState, setState) {
  const before = structuredClone(getState());
  const cmd = cmdFactory();
  cmd.execute(); cmd.undo();
  expect(getState()).toEqual(before);                  // undo 后状态复原
  cmd.execute(); cmd.undo(); cmd.redo();
  expect(getState()).toEqual(/* execute 后状态 */);
}
// 任何实现命令模式的操作都跑此契约
```
