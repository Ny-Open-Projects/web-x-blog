## ARC-604：表单 schema 版本迁移
**答**:
- 场景：表单 schema 迭代（加字段/改校验/字段更名/拆分合并）后，存量草稿/已提交数据跨版本处理（ARC-449/468 的表单特化）。
- 迁移设计：schema 版本号（数据带 schemaVersion）、迁移器链（v1→v2→v3 逐级——每级纯函数：字段映射/默认值填充/结构转换）、迁移方向原则（向前兼容：新代码读旧数据 OK——迁移在读侧惰性执行 ARC-468 双写协议）、删除字段的兼容（旧字段数据保留至下版本清理——回滚安全 ARC-450）。
- 提交数据的版本处理：历史提交数据只读渲染按其版本 schema（展示层支持多版本渲染——ARC-531 审批实例同思想）；需要编辑旧数据 → 先迁移到当前版本（迁移确认提示用户）。
- 校验变化的影响：新 schema 校验更严 → 旧数据迁移后可能校验不过——迁移器负责修复到合法（默认值/裁剪），修复不了标记"需人工确认"。
- 测试：迁移矩阵（每级迁移的前后数据快照测试 + 迁移幂等性）。
```javascript
const migrations = {
  2: (d) => ({ ...d, phone: d.tel, tel: undefined }),            // 字段更名（旧字段保留防回滚）
  3: (d) => ({ ...d, address: d.province + d.city + d.detail })  // 合并拆分
};
function loadForm(raw) {
  let v = raw.schemaVersion ?? 1;
  while (v < CURRENT) { raw = migrations[++v](raw); }
  return { data: raw, version: CURRENT, needsReview: validateStrict(raw).length > 0 };
}
```
