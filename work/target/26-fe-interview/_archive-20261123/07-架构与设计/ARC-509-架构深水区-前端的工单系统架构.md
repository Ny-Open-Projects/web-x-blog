## ARC-509：工单系统前端状态流架构
**答**:
- 状态模型：工单状态机（服务端权威，前端投影）+ 待办列表（我的待办/已办/抄送）+ 操作权限（当前状态 × 我的角色 → 可执行操作集合 ARC-420）。
- 列表与详情联动：状态变更后列表项失效更新（ARC-386 回写）、待办红点（未读/截止时间排序提醒）。
- 操作流架构：操作 = 状态转移 + 表单提交（转办需选人 + 意见必填）——操作按钮由服务端返回的操作集驱动（前端不硬编码状态判断，服务端下发"当前可做什么"）。
- 实时性：待办推送（ARC-394 通知 + 列表刷新）、SLA 倒计时（临期标红，本地钟差校正 ARC-481）。
- 详情一致性：详情页各区块（表单/流转记录/附件）独立 query 缓存，状态变更统一失效；并发操作冲突（他人已处理）提示最新状态（ARC-483）。
```javascript
// 操作集服务端驱动
const { actions, ticket } = useTicket(id);                       // 服务端返回当前可操作集
// actions: [{ key:'approve', label:'通过', form: ApprovalForm },
//           { key:'transfer', label:'转办', form: TransferForm }]
const act = actions.find(a => a.key === actionKey);
if (act?.form) await openForm(act.form);                         // 表单驱动
await api.runAction(id, actionKey, payload);
queryClient.invalidateQueries(['ticket', id]);                   // 列表与详情失效
```
