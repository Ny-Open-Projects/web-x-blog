## ARC-295：低代码引擎的撤销重做与历史管理如何设计？
**答**：
- 历史模型二选一：全量快照（每次操作存整棵 DSL，简单但内存大）vs **命令/补丁**（存逆操作或 JSON Patch，省内存可协作）。推荐补丁式：每操作产出 forward/backward patch。
- 粒度合并：拖拽产生高频变更——按"语义操作"合并（一次拖拽 = 一条历史），空闲期 flush 或按时间窗合并，否则 Ctrl+Z 一次退 1px。
- 持久化：历史进内存栈（上限 100 步），文档保存时历史可固化（版本时间线），支持"回到 10 分钟前的版本"。
- 协作扩展：补丁式天然适配 OT/CRDT（ARC-058 类思路），单人版先落 patch 模型，多人版再升级并发控制。

```typescript
class History {
  stack: Array<{ fwd: Patch; back: Patch; label: string }> = [];
  idx = -1;
  apply(patch: Patch, label: string) {
    const back = computeBackward(patch);          // 由 patch 逆算
    this.stack.splice(this.idx + 1);              // 丢弃 redo 分支
    this.stack.push({ fwd: patch, back, label });
    if (++this.idx > 100) this.stack.shift();     // 上限
    this.coalesce(label);                         // 相邻同类操作合并（drag/typing）
  }
  undo() { const e = this.stack[this.idx--]; applyPatch(e.back); }
  redo() { const e = this.stack[++this.idx]; applyPatch(e.fwd); }
  coalesce(label: string) { if (this.stack.at(-2)?.label === label) this.mergeLastTwo(); }
}
```
