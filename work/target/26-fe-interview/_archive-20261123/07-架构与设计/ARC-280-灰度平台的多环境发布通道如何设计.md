## ARC-280：灰度平台的多环境发布通道如何设计？
**答**：
- 通道模型：dev（随时部署）→ staging（每日主干构建，内部域名+员工白名单）→ canary（生产 1%~5% 真实流量）→ full（全量）。每条通道有独立准入条件与观测时长。
- staging 关键：必须用**生产同构数据形态**（脱敏快照或影子流量），否则测不出真实问题；灰度平台提供"staging 结果一键晋升 canary"（复用产物不重构建）。
- 环境路由：内部员工按 uid 白名单进 staging 体验新版本（ARC-276 白名单复用）；灰度指纹（版本号+通道）贯穿埋点，保证任何环境的问题可归因到发布通道。
- 回滚矩阵：canary 问题回滚版本指针；full 后发现问题回滚 = 指针回上一版本 + 旧产物保留策略（至少 2 周覆盖）。

```typescript
const channels = {
  staging:  { entry: 'https://stg.example.com', who: 'whitelist', data: 'masked-snapshot', soak: '1d' },
  canary:   { ratio: 0.03, entry: 'https://example.com', soak: '4h', gates: ['errRate', 'LCP', '转化'] },
  full:     { gate: 'canary绿色' },
};
async function promote(from, to) {
  assertGatesPassed(from, channels[to].gates);
  return pointer.set(currentApp, buildId, to);               // 产物复用，仅改指针
}
// 回滚矩阵：pointer.set(currentApp, lastGreenBuild, from) —— 秒级，旧产物保留 14 天
```
