## ARC-539：报表订阅与定时推送
**答**:
- 订阅模型：用户订阅报表（周期/渠道/筛选条件快照）→ 服务端定时生成（ARC-382 异步任务 + NODE-437 编排）→ 推送（IM/邮件/站内信 ARC-394）→ 打开即见与订阅时相同口径的报表（订阅上下文可重放）。
- 前端配合点：订阅配置 UI（周期/渠道/筛选声明）、订阅快照序列化（筛选条件 + 版本入配置——报表 schema 变更后旧订阅的兼容渲染或提示重建）、报告落地页（从推送深链进入，带生成时间与数据时点标注）。
- 一致性：报表生成时间 vs 数据时点显式标注（"数据截至 11-19 08:00"）；订阅版与在线版口径一致（同 query 构建器 ARC-381）。
- 体验：推送卡片预览（关键数字摘要）、打开失败降级（PDF 附件兜底 ARC-496）、取消订阅即时生效。
- 治理：订阅量监控（爆款订阅 → 生成任务容量评估）、僵尸订阅清理（连续未打开 → 询问停订）。
```javascript
// 订阅快照
const subscription = {
  report: 'daily-sales',
  schedule: { cron: '0 8 * * *', tz: 'Asia/Shanghai' },
  context: serialize(filterState()),                             // 筛选条件快照（可重放）
  channels: ['im', 'email'],
  schemaVersion: reportSchema.v3
};
// 服务端：cron → buildReport(subscription.context) → push(channels) + 深链 /report?sub=xx
```
