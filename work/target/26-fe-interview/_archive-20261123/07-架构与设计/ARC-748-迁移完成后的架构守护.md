## ARC-748：迁移后守护

**答**：
- 守护的必要性：迁移成果会被「无意识的回退」侵蚀（新人用老模式/图省事绕过新架构）——守护是迁移的最后一步
- 守护三层：lint 门禁（禁老模式——机械化）、架构测试（依赖规则测试——模块边界不被破坏）、评审卡点（新代码的架构合规）
- 架构测试（ArchUnit 模式）：「UI 层不得直接调接口」「状态必须经 store」——规则的自动化测试——规则写进测试才守得住
- 守护的度量：门禁拦截数趋势（拦截归零后=团队内化了——守护可降级为 lint）
- 深水点：守护的「成本递减设计」——初期人工 review 严格 → 逐步自动化 → 最终规则进 lint——守护强度随内化程度递减

```text
迁移后守护:
  三层: lint 门禁 / 架构测试(依赖规则) / 评审卡点
  架构测试: UI 不直调接口等规则自动化
  度量: 拦截数趋势 → 归零则降级
  递减: 人工严格 → 自动化 → lint 内化
```
