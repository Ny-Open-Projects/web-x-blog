## ARC-357：可观测性深水区：前端与后端链路如何真正打通？
**答**：
- 打通的载体是 W3C Trace Context：前端生成 traceparent（version-traceid-spanid-flags）写入请求头，后端以此为 parent 延续链路。
- 关键细节：前端在 fetch 拦截器统一注入；跨域需服务端暴露 traceparent 响应头（Access-Control-Expose-Headers）才能回读；traceid 同值才可能在后端 APM 中关联。
- 打通的第二层是业务关联键：sessionId/userId/orderId 作为 baggage 或自定义头传递，让"一个用户的一次会话"串起前端行为 + 后端 trace + 日志。
- 排障流程因此改变：从"前端报错截图给后端查日志"变成"拿 traceid 全链路看"，定位时间从小时级到分钟级。
- 落地难点：后端多语言/多团队接入节奏不一——先打通网关层（网关生成/透传 traceparent 兜底），再逐服务深入。
```javascript
// fetch 拦截注入 traceparent
const { traceId, spanId } = startClientSpan();
const tp = `00-${traceId}-${spanId}-01`;
const res = await fetch(url, { headers: { traceparent: tp, 'x-session-id': session.id } });
const respTp = res.headers.get('traceparent');      // 需要 CORS expose
if (respTp) linkToBackendTrace(parseTraceId(respTp)); // 前端错误上报关联后端 trace
```
