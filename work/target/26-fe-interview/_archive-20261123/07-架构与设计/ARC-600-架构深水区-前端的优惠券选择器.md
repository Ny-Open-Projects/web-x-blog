## ARC-600：优惠券选择器架构
**答**:
- 职责边界：券的可用性判断与最优组合计算在服务端（规则复杂且涉资——前端只做选择 UI 与展示），前端职责：券列表分组（可用/不可用/不可叠加）、推荐展示（服务端推荐的"最优组合"）、切换生效（换券 → 结算重算流程 ARC-599 预检）。
- 券状态机：可用/已选/冲突（与已选互斥）/不满足门槛（差 X 元可用——引导凑单是运营抓手）/已过期——状态由服务端判定下发，前端按状态渲染置灰与提示。
- 凑单引导：门槛差值展示（凑单商品推荐接口——凑单商品加入后自动重算）——凑单是券选择器的高价值延伸。
- 交互一致性：选券即时反馈（预计优惠金额更新——乐观展示 + 结算确认兜底）、不可用原因透明（每张不可用券有明确原因文案 ARC-487 文案协议）。
- 性能：券列表懒展开（不可用券折叠）、券规则说明富文本（复杂规则的可读性——条款链接）。
```javascript
// 券选择器状态渲染
const { groups, recommended } = await api.couponOptions(cartSnapshot); // 服务端判定
// groups: { usable: [...], conflicted: [...](with reason), threshold: [...](差 X 元) }
<CouponPicker groups={groups} recommended={recommended.combo}
  onPick={async (id) => { const r = await recompute(id);        // 重算 + 确认
    if (r.ok) applyDiscount(r.breakdown); else showReason(r.reason); }} />
```
