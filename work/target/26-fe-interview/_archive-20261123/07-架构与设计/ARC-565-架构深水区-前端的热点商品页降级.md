## ARC-565：热点商品页降级与扩容
**答**:
- 突发场景：某商品爆红（微博引爆）→ 商品页流量 ×100，全链路（CDN/缓存/DB/下游）逐层承压。架构预案按层准备。
- 前端降级链：静态化加强（热点页提前全静态化 + CDN，ARC-102）、互动功能降级（评论/推荐异步化或关闭——保留购买主链路）、图片降档（ARC-341 低清晰度优先）、请求瘦身（非关键请求全砍 ARC-546）。
- 服务端配合：热点识别（单商品 QPS 突增 → 自动加缓存 TTL/预热点 NODE-438）、页面微缓存（1~3s 全页缓存——牺牲实时性换容量）、库存等强一致数据单独通道（NODE-412 原子扣减，不进页面缓存）。
- 限流排队：超出容量进排队页（ARC-107 秒杀模式），排队时用户可继续浏览其他页。
- 复盘沉淀：热点事件复盘（各层承压数据/降级触发情况）→ 预案更新（下次识别更快、降级更准）。
```javascript
// 热点页降级编排
async function loadGoodsDetail(id) {
  const hot = hotspotDetector.check(id);                         // 服务端热点标记下发
  if (hot) { loadStatic(id); disable('comments'); disable('recommend'); // 降级链
             queueIfBehindCapacity(); }                          // 超容量进排队
  else loadNormal(id);
}
```
