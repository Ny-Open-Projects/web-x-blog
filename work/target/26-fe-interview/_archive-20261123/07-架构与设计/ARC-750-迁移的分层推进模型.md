## ARC-750：分层推进模型

**答**：
- 迁移的分层顺序：底层先（工具/内核/组件库——被依赖的层）→ 中层（状态/业务逻辑）→ 顶层（页面/视图）——「依赖方向决定迁移顺序」
- 分层推进的验证点：每层迁移完成做「层验收」（该层的 API 冻结——上层基于稳定层开发）——层验收是上层开发的起点
- 层间的适配器：下层未迁完时上层已迁移——适配层桥接（上层用新 API 调旧底层实现）——适配层让层间解耦
- 分层的并行度：底层迁移完成 80% 即可启动中层（不追求 100%——长尾并行处理）
- 深水点：分层模型的「倒置场景」——页面驱动的迁移（按页面纵向切）vs 分层横向切——纵向适合页面独立业务、横向适合共享层重构——两种模型可混用

```text
分层推进:
  顺序: 底层 → 中层 → 顶层 (依赖方向)
  验证: 层验收 + API 冻结
  适配: 层间适配器解耦
  并行: 下层 80% 即启动上层
  倒置: 页面纵向切 vs 分层横向切 — 可混用
```
