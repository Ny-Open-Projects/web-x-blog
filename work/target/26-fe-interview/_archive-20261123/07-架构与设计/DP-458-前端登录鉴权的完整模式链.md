## DP-458：鉴权模式链

**答**：
- 鉴权的完整模式链：代理（fetch 包装自动带 token）、状态机（会话状态）、单飞（并发 401 共享刷新）、观察者（token 变更多端广播）、策略（存储策略：内存+refresh cookie）、责任链（守卫链的鉴权节点）
- 每个模式的必要性验证：去掉单飞（并发 401 多次刷新互相覆盖）→ 去掉广播（多 tab 状态漂移）——模式链的「必要性测试」
- 存储策略的安全权衡：localStorage（便利但 XSS 可读）vs memory+refresh cookie（安全但刷新逻辑复杂）——威胁模型驱动选择
- 深水点：鉴权链的「测试矩阵」——正常登录/过期静默续/401 并发/登出广播/多标签并发——每个模式组合场景一条测试

```text
鉴权模式链测试矩阵:
  正常登录 → token 内存 + refresh cookie
  过期 → checkSession → 静默续 (无感)
  并发 401 → 单飞刷新 (一次)
  登出 → 广播所有 tab 清理
  多标签 → BroadcastChannel 一致
```
