## ARC-741：迁移失败原因复盘

**答**：
- 失败原因 Top5：① 动机不足（技术自嗨——业务不支持）② 范围失控（「顺便重构」——迁移变成无限工程）③ 中途换血（核心人员流失+知识断层）④ 双系统烂尾（共存期过长——新系统永远差一点）⑤ 验收不严（半成品宣布完成）
- 预防机制对应：动机→立项时业务价值量化；范围→迁移点清单锁定（新需求走变更流程）；换血→A/B 角+文档；烂尾→强制截止日期；验收→四层验收标准
- 「半途而废」的识别：进度连续落后 + 团队情绪低迷——早识别早止损（回滚或重启）
- 失败的止损方案：保留已迁移部分（不回滚已完成的）+ 暂停推进 + 复盘调整策略——止损不是全部回退
- 深水点：失败的「组织学习」——失败案例进知识库（比成功案例更有教育价值）——复盘要敢写失败

```text
迁移失败 Top5:
  动机不足 / 范围失控 / 中途换血 / 双系统烂尾 / 验收不严
预防: 价值量化 / 清单锁定 / AB角 / 硬截止 / 四层验收
止损: 保留已完成 + 暂停 + 调整策略
组织学习: 失败案例进知识库
```
