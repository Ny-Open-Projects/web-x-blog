## DP-361：备忘录模式：草稿与快照

**答**：
- 备忘录核心：在不破坏封装的前提下捕获状态快照——表单草稿（崩溃恢复）、编辑器版本、审批流快照
- 实战要点：快照的「触发策略」（定时 vs 变更节流 vs 关键节点——输入每键保存是浪费）、存储介质分级（内存 / sessionStorage / IndexedDB / 服务端）
- 快照的结构化：带时间戳与来源（自动保存 vs 手动保存——恢复 UI 区分）；「快照链」（多版本可回溯）
- 恢复的冲突处理：本地草稿与服务端版本冲突（他人已改）——冲突 UI（三路合并或选择版本）
- 深水点：快照的「隐私清理」——草稿含敏感信息（手机号）的存储加密与过期清理——快照也是数据泄漏面

```javascript
class DraftManager {
  #key; #snapshots = [];
  constructor(key, { maxAge = 24 * 3600e3, interval = 30_000 } = {}) {
    this.#key = key;
    setInterval(() => this.#autoSave(), interval);   // 节流触发
    addEventListener('pagehide', () => this.#autoSave());
  }
  #autoSave() {
    if (!this.isDirty()) return;
    const snap = { data: structuredClone(this.getState()), at: Date.now(), source: 'auto' };
    this.#snapshots.push(snap);
    sessionStorage.setItem(this.#key, JSON.stringify(this.#snapshots.slice(-20)));  // 上限20份
  }
  restore(latest = true) {
    const snap = latest ? this.#snapshots.at(-1) : this.#snapshots[0];
    snap && this.setState(snap.data);
  }
}
```
