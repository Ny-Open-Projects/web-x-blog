## ARC-296：低代码平台的权限与协作编辑如何设计？
**答**：
- 权限三层：页面级（谁能编辑哪个页面，RBAC 挂到页面资产上）、组件级（页面里哪些区块锁定，如财务区块只有财务角色可改）、操作级（属性面板某些字段只读，如价格逻辑）。
- 协作编辑：多人同时编辑一个页面——简单方案是**页面级悲观锁**（编辑即加锁，提示他人），成本低；进阶方案 OT/CRDT 实时协同（Yjs），成本高但体验好。按团队规模选型：小团队锁足够。
- 锁的实现：编辑会话心跳持有锁，断线 30s 自动释放；强制解锁走管理员审计。
- 版本管理：保存即版本，发布走"版本 → 发布单"（ARC-099 发布流），协作编辑只作用于草稿版本。

```typescript
// 页面级锁
async function acquireEdit(pageId, user) {
  const lock = await redis.set(`page-lock:${pageId}`, user.id, { nx: true, px: 60_000 });
  if (!lock) { const holder = await redis.get(`page-lock:${pageId}`);
    throw new LockedError(`正在被 ${holder} 编辑`); }
  heartbeat(() => redis.expire(`page-lock:${pageId}`, 60_000));  // 心跳续期
}
// 组件级锁定：dsl.nodes.forEach(n => n.lockedRole && !hasRole(user, n.lockedRole) && freeze(n))
// 冻结节点：画布置灰 + 属性面板只读，保存时校验被冻结节点未被改动（服务端 diff 校验）
```
