## DP-451：响应式模式内核

**答**：
- 响应式的两种模式内核：代理追踪（Vue——Proxy get 拦截自动收集依赖）与显式订阅（Solid signal——读时订阅需要函数调用语义）——「自动收集」vs「显式声明」
- 依赖清理的必要性：分支切换后旧依赖不再读取——effect 重跑时清旧依赖（依赖图动态重连——脏标记 + 清理）
- computed 的链式传播：上游变化 → 标脏 → 下游读时才重算（惰性）——脏标记 + 惰性求值的组合
- 批处理与调度：同一 tick 多次写 → 一次通知（批处理队列）——与 React 的自动批处理同构
- 深水点：响应式的「循环依赖」——effect 读自己写的 signal → 无限循环——循环检测（调用栈/版本号）与开发期告警

```javascript
// 代理追踪内核
let active = null;
function signal(v) {
  const subs = new Set();
  return () => {
    if (active) { subs.add(active); active.deps.add(subs); }   // 读时订阅
    return v;
  };
}
function effect(fn) {
  const e = { deps: new Set(), run() { cleanup(e); stack.push(active); active = e; fn(); active = stack.pop(); } };
  e.run();
}
// cleanup: 分支切换解除旧依赖 — 响应式正确性的关键
```
