## ARC-555：实验结果回读与决策闭环
**答**:
- 前端在实验闭环的职责：数据采集质量（ARC-390 分桶跟随、ARC-535 事件规范）、结果回读展示（实验看板：前端侧指标——错误率/性能/交互指标按桶对比）、决策执行（实验结论 → 全量/放弃的实现落地与开关清理）。
- 结果回读协议：实验平台推送结论（胜出/无显著/负向）→ 前端侧收到后执行：胜出 → 移除开关直接采用新逻辑（代码固化）→ 清理旧分支 + 分桶代码（ARC-288 防开关债务）；无显著 → 回滚开关。
- 固化流程：实验胜出的代码"转正"要走正常评审（实验代码临时分支的质量往往低于主线——转正不是直接删开关完事，要重构到正式实现）、转正后的指标验证（一个周期确认无回归）。
- 知识沉淀：实验档案（假设/数据/结论/学到的）入库——避免同类实验重复做；负向实验的"为什么不行"最值钱。
- 度量：实验转正率、实验后回归事故率（转正质量）、开关清理及时率。
```javascript
// 实验转正流程
experiment.on('concluded', async (exp) => {
  if (exp.winner === 'treatment') {
    await promote(exp.featureKey);                               // 代码固化（重构进主线）
    await removeFlag(exp.featureKey);                            // 开关与分桶代码清理
    scheduleVerify(exp, '14d');                                  // 转正后指标验证
  } else if (exp.winner === 'neutral') await revert(exp.featureKey);
  await archive(exp);                                            // 实验档案
});
```
