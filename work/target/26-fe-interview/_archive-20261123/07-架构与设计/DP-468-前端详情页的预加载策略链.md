## DP-468：预加载策略链

**答**：
- 预加载的策略链：hover 预取（列表项鼠标停留——最高概率）、可见预取（IO——下一屏第一项）、空闲预取（idle callback——低概率兜底）——概率递减的预取链
- 预取的成本控制：预取预算（每页最多 N 个预取请求——防预取风暴）+ 预取缓存 TTL（过期丢弃）
- 预取与正式加载的衔接：预取结果进缓存 → 正式导航命中缓存（零等待）——「预取是缓存的预热」
- 深水点：预取的「命中率度量」——预取后实际访问的比例（<30% = 纯浪费）——预取策略的数据化调优

```javascript
// 预取链: hover > visible > idle
listItem.onMouseEnter = () => prefetch(id);          // hover: 高概率
io.observe(firstItemOfNextScreen);                   // visible
requestIdleCallback(() => prefetch(topN));           // idle 兜底
// prefetch = queryClient.prefetchQuery({ queryKey: ['detail', id] })  → 导航命中缓存
```
