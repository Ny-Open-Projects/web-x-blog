## ARC-482：前端金额与精度处理架构
**答**:
- 金额红线：计算不用浮点（0.1+0.2 问题）——前端展示可乘 100 用整数分计算，或 decimal 库；与服务端金额一致性原则：金额裁决永远在后端，前端只展示与传递。
- 传输协议：金额字段传最小单位整数（分）或字符串 decimal，禁传 float；schema 声明类型防增量误传 number 浮点。
- 展示收口：统一货币格式化模块（Intl.NumberFormat：千分位/小数位/货币符号按 locale），禁手写 toFixed（舍入规则 Rounding 问题）；折扣价/划线价的舍入方向由业务规则显式定义。
- 汇总一致性：列表页合计 = 各行相加，行内展示四舍五入后相加可能与真实合计差 1 分——协议规定"合计以服务端字段为准"，前端行合计只展示"约"。
- 溢出与边界：大额（超过 Number.MAX_SAFE_INTEGER 的分）用 BigInt 或字符串运算；金额输入框防止科学计数法与非法字符。
```javascript
// 金额模块
export const Money = {
  parse: (v) => typeof v === 'string' || Number.isInteger(v) ? v : (() => { throw new Error('金额必须是整数分或字符串'); })(),
  fmt: (cents, currency = 'CNY') => new Intl.NumberFormat(undefined, { style: 'currency', currency })
    .format(cents / 100),
  sum: (centsArr) => centsArr.reduce((a, b) => a + Number(b), 0),   // 整数分安全
  toBigIntSafe: (v) => BigInt(v)                                     // 大额走 BigInt
};
```
