## ARC-213：联邦下的样式与全局状态污染如何治理？
**答**：
- 联邦是"同 DOM 同运行时"集成，没有 qiankun 式的天然沙箱，污染风险更高：全局样式（reset/*）、CSS-in-JS 重复注入、全局事件与定时器。
- 样式方案：子应用样式统一加命名空间前缀（构建期 postcss plugin 加 `.shop-` 前缀）或 CSS Modules/CSS-in-JS 带 scope；主应用 reset 约定唯一来源，子应用不重复注入。
- JS 侧：全局单例（window 上的 SDK、事件总线）由主应用提供并作为 shared 单例注入；子应用禁止 window 域名乱挂，ESLint 规则约束。
- 排查手段：MutationObserver + getComputedStyle 抽样检测异常注入，监控"样式漂移"指标。

```javascript
// 构建期命名空间隔离（postcss 插件示意）
module.exports = ({ prefix }) => ({
  postcssPlugin: 'ns-prefix',
  Rule(rule) {
    if (rule.selector.startsWith('@') || rule.selector.includes(prefix)) return;
    rule.selector = rule.selector.split(',').map(s => `${prefix} ${s.trim()}`).join(',');
  },
});
// 子应用配置：plugins: [postcssPlugin({ prefix: '.shop-scope' })]，挂在子应用根节点 <div class="shop-scope">
// 单例注入：主应用把 bus/sdk 放进 init 的 shareScope 或通过 props 传入，子应用不自己 new EventBus()
```
