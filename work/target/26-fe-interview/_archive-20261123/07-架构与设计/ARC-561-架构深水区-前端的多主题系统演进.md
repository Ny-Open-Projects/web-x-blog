## ARC-561：主题系统长期演进
**答**:
- 演进场景：设计系统改版（token 语义重构：primary → brand-primary）、品牌升级（换整套色板）、新增主题（暗黑/品牌皮肤）。演进失败的常见形态：token 名改了旧引用残留（硬编码绕过了 token——治理失效的前科）。
- 演进机制：token 变更走 RFC（ARC-433 设计系统运营）→ 兼容期双名（新旧 token 同时存在，旧名标记 deprecated → codemod 全量替换 ARC-425 → 移除旧名）→ 视觉回归验证（ARC-319 快照对比变更影响面）。
- 硬编码防御：lint 检查（禁裸色值/裸间距——必须走 token 引用，ARC-533 资产管理）+ 逃逸口（特殊情况豁免留痕）。
- 品牌升级演练：全量页面主题快照（升级前后对比矩阵——按页面类型抽样），渐进切换（新主题灰度 ARC-554）。
- token 源头管理：Figma 变量 → token 管道 → 多端产物（ARC-163）——演进变更从设计源头驱动，代码侧自动同步。
```bash
# token 迁移流水线
npx token-migrate --from primary --to brand-primary   # codemod 全量替换
npm run visual-regression -- --theme light,dark       # 快照对比
# CI: 旧 token 引用 = 0 才允许删除旧定义（lint --check）
```
