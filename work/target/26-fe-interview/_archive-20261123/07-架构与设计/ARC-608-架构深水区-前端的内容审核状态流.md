## ARC-608：内容审核状态流呈现
**答**:
- 状态流：发布 → 机审（通过/疑似/拒绝）→ 人审（队列/通过/拒绝）→ 申诉（复审）——内容可见性按状态分级（全部可见/仅自己可见/审核中占位/不可见）。
- 作者端呈现：审核中内容的呈现协议（"审核中，通过后展示"——自己可见 + 他人不可见 ARC-501 评论审核状态）、被拒呈现（原因 + 修改重发入口——拒绝原因结构化：命中哪类规则，可申诉）、申诉流程（表单 + 进度跟踪 ARC-509）。
- 观众端一致性：审核状态变化时内容可见性切换（通过 → 从"审核中"占位变为正常——列表增量更新 ARC-501）、缓存一致性（审核通过后 CDN/缓存刷新——ARC-507 失效链路）。
- 前端架构：内容状态渲染器（status → 可见性 + 提示组件——统一渲染协议不散写 if）、审核状态推送（作者端 WS 通知审核结果 ARC-416）。
- 合规：审核记录留痕展示（作者可查自己的审核历史）、申诉时效承诺展示。
```javascript
// 内容可见性渲染器
function renderContent(item, viewer) {
  switch (item.audit) {
    case 'pending': return viewer.isAuthor ? <PendingBadge /> : null;      // 审核中仅自己见
    case 'rejected': return viewer.isAuthor ? <RejectedCard reason={item.reason} onAppeal={...} /> : null;
    case 'passed': return <ContentBody item={item} />;
  }
}
```
