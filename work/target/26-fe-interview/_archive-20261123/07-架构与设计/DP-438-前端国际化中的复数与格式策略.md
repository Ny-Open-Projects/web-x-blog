## DP-438：Intl 格式化策略

**答**：
- Intl 的策略封装：DateTimeFormat/NumberFormat/PluralRules/RelativeTimeFormat/ListItem——原生 API 即「策略族」（locale 决定策略）
- 封装的价值：formatter 实例昂贵（创建有成本）——按 locale+options 缓存实例（享元——重复创建是性能坑）
- 统一门面：fmt.date/fmt.number/fmt.relative——业务侧不直接碰 Intl API（换实现/加缓存不动业务）
- 格式化的「一致性挑战」：服务端渲染与客户端格式化结果一致（同 locale 同时区——水合不 mismatch）
- 深水点：RelativeTimeFormat 的「时间流动」——「3 分钟前」随时间失效（需要定时刷新——观察者驱动重算）

```javascript
const formatterCache = new Map();
function getFormatter(locale, type, opts) {
  const key = `${locale}:${type}:${JSON.stringify(opts)}`;
  if (!formatterCache.has(key)) {
    const Ctor = { date: Intl.DateTimeFormat, number: Intl.NumberFormat, relative: Intl.RelativeTimeFormat }[type];
    formatterCache.set(key, new Ctor(locale, opts));   // 享元缓存
  }
  return formatterCache.get(key);
}
export const fmt = {
  date: (ts, locale) => getFormatter(locale, 'date', { dateStyle: 'medium' }).format(ts),
  relative: (ts, locale) => getFormatter(locale, 'relative', { numeric: 'auto' }).format(-3, 'minute'),
};
```
