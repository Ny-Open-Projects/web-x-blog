## ARC-420：复杂权限界面（行列交叉权限）的渲染架构
**答**:
- 场景：表格中"哪些用户对哪些资源有什么操作权"（行 = 资源，列 = 操作，单元格 = 允许/拒绝/继承），权限点数 = 行×列×操作，不能逐个判断渲染。
- 架构：权限判定下沉为纯函数层 can(user, action, resource)，输入是权限快照（位图/集合），输出布尔；UI 组件只消费判定结果。快照一次性拉取 + 变更推送更新，渲染时零请求。
- 位图方案：操作编码为 bit（read=1, write=2, admin=4），资源粒度聚合为数字，判定是位运算（O(1)），存储体积小（ARC-348 DP 系列）。
- 继承与覆盖：权限可继承（部门 → 子部门 → 资源），渲染时解析有效权限（有效 = 直接覆盖 ?? 继承 ?? 默认拒绝）；UI 上区分"显式授予/继承/拒绝"三种展示。
- 性能与安全：大快照分片（按资源域懒加载）；前端判定只做 UI 显隐，最终裁决永远在后端接口（提交时校验）。
```javascript
const OPS = { read: 1, write: 2, approve: 4 };
function effectivePerm(user, resource) {
  return resource.overrides[user.id] ?? inherited(user.dept, resource) ?? 0; // 显式>继承>默认
}
const can = (perm, op) => (perm & OPS[op]) !== 0;
// 渲染：<button disabled={!can(effectivePerm(u, r), 'write')}>
```
