## ARC-683：架构变更的通知与迁移

**答**：
- 变更分级通知：破坏性变更（API 移除/行为变化）——提前 2 周公告+迁移指南+双跑窗口；非破坏性——发布说明即可
- 迁移的支持包：codemod（自动化迁移脚本）+ 迁移期双支持（新旧 API 并存一个版本周期）——「给迁移工具」比「催迁移」有效
- 迁移的进度跟踪：迁移看板（各业务线迁移进度百分比）——落后团队点名+协助
- 强制截止：迁移窗口结束 → 旧 API 移除（硬截止）——无截止的迁移永不完成
- 深水点：变更的「影响面评估」先行——变更前扫描全仓调用点（统计受影响团队数）——影响面决定通知与支持投入

```text
变更通知:
  分级: 破坏性提前 2 周+指南+双跑
  支持: codemod + 新旧并存一版
  跟踪: 迁移看板 (各线进度)
  截止: 硬截止 (旧 API 移除)
  前置: 全仓调用点扫描 → 影响面定投入
```
