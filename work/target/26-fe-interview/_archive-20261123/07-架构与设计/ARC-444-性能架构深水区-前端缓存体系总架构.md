## ARC-444：前端缓存体系总架构：五层协同
**答**:
- 五层缓存：HTTP 层（Cache-Control/ETag，静态资源 immutable + HTML 协商）、SW 层（策略矩阵 ARC-373）、内存层（store 内查询缓存 + SWR）、持久层（IndexedDB 结构化业务数据）、CDN 层（边缘缓存 + 主动刷新）。
- 协同原则：各层职责单一——HTTP 管新鲜度、SW 管可用性（离线）、内存管会话内一致性、持久层管跨会话/离线、CDN 管边缘时延。同一数据多层共存时，失效必须级联（服务端变更 → CDN purge → SW 清缓存 → 内存 tag 失效）。
- 一致性等级：强一致（支付结果：不缓存直查）、会话一致（购物车：写后读本地优先）、最终一致（推荐流：SWR）。按数据类型声明等级，写进接口元数据。
- 失效架构：tag-based 失效（响应带 cache-tag，失效广播清多层）优于全量刷新；版本号贯穿（schema 变更 → 持久层迁移或清空）。
- 度量：命中率分层统计、stale 数据暴露率（用户看到旧数据的投诉归因）。
```javascript
// 多层失效级联
function invalidate(tag) {
  api.purgeCDN(tag);                       // 边缘 purge
  swBroadcast({ type: 'invalidate', tag }); // SW 清匹配缓存
  queryClient.invalidateQueries(tag);       // 内存层 tag 失效
  idb.dropByTag(tag);                       // 持久层
}
// 接口元数据：{ consistency: 'session', tags: ['goods', 'user:42'] }
```
