## DP-431：联动引擎重构

**答**：
- 重构前的问题：300 行 if-else 散落校验/联动/显隐（改一个字段要看全文件）——「逻辑与结构耦合」的典型
- 重构后：联动规则数据化（when/then 声明——中介者消费）、校验规则策略化、显隐声明化——「规则即数据」
- 重构的步骤：先测试护栏（现有行为的快照测试——重构不改行为）→ 规则提取（if-else 逐条转为声明）→ 引擎替换（中介者逐条消费）→ 死代码删除
- 重构的收益量化：新增联动字段从「改 300 行文件」到「加一条规则」（变更局部化）
- 深水点：重构的「行为等价验证」——声明式规则与原 if-else 的执行顺序差异（顺序敏感的联动会 bug）——规则优先级显式化

```text
重构路径:
  1. 快照测试护栏 (行为等价基线)
  2. if-else 逐条提取为 { when, then } 声明
  3. 中介者引擎逐条消费 (顺序显式化)
  4. 死 if-else 删除 + 基线通过
收益: 新增联动 = 加一条规则 (变更局部化)
```
