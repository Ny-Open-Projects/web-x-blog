## ARC-315：组件库的可访问性基线如何工程化保障？
**答**：
- 基线清单（ARC-032 扩展组件库视角）：语义化标签与 ARIA 角色（dialog 的 role/aria-modal、tab 的 keyboard 导航）、焦点管理（焦点陷阱/归还）、键盘操作完整（Esc/箭头键/Tab 序）、对比度（Token 层保证，ARC-029）。
- 工程化：每个交互组件的测试模板内置 a11y 断言（axe-core 跑 Storybook 快照，violation 即 fail）；键盘操作用 Testing Library userEvent 断言；文档标注每个组件的 ARIA 模式。
- CI 门禁：Storybook axe 扫描全量 stories，新增 violation 卡发布；对齐 WCAG 2.1 AA 作为基线级别。
- 组件开发者清单：写组件先查 WAI-ARIA Authoring Practices 对应模式，实现模式而不是自由发挥（Dropdown 键盘交互有标准行为定义）。

```typescript
// Storybook a11y 测试模板
import { axe } from 'jest-axe';
test.each(allStories)('component %s passes axe', async (story) => {
  const { container } = render(story.render());
  expect(await axe(container)).toHaveNoViolations();     // CI 卡点
});
// 焦点管理示例（Modal）：
useEffect(() => {
  const prev = document.activeElement;
  trapFocus(dialogRef.current);                          // Tab 循环限制在对话框内
  return () => prev?.focus();                            // 关闭归还焦点
}, []);
```
