## ARC-260：大促前端的容量评估与压测如何做？
**答**：
- 前端容量三个维度：CDN 带宽与命中率（静态资源 QPS 估算）、接口放大系数（1 次 PV 发多少请求）、弱网环境表现。目标是"预估峰值 PV → 换算资源与接口 QPS → 逐项验证"。
- 压测手段：全链路压测（影子流量标记，服务端配合）验证服务端；CDN 压测验证边缘缓存命中；**前端本地压测**用 Chrome CPU throttling + 弱网模拟验证"最差用户"体验。
- 放大系数治理：合并请求（首屏接口聚合）、取消不必要的轮询、预加载裁剪——压测前先优化，再验证。
- 产出物：容量评估表（维度/假设/结论/责任方），T-7 复测，假设变化（流量翻倍）自动触发重评。

```typescript
// PV → QPS 估算模型
function estimateQps(pvPeak: number, windowSec: number, amplification: Record<string, number>) {
  // 秒杀经验：开抢 1 分钟内完成 30% PV
  const burstPv = pvPeak * 0.3 / 60;                       // 每秒 PV
  return Object.fromEntries(Object.entries(amplification).map(([api, k]) => [api, burstPv * k]));
}
// 例：峰值 PV 2000 万 → burst 10万 PV/s → /seckill/clock 系数 0.5 → 5万 QPS（需 CDN/边缘承接）
// 前端"最差用户"测试：Chrome DevTools CPU 6x slowdown + Fast 3G，核心路径可交互时间 < 5s 达标
```
