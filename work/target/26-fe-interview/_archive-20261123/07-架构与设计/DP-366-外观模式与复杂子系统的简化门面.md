## DP-366：外观模式：简化门面

**答**：
- 外观的价值：复杂子系统（支付：风控+下单+收银台+查单）封装为「一个方法」——业务侧 `pay(orderId)` 一行
- 与适配器的区别：适配器「转换接口」（让不兼容变兼容），外观「简化接口」（让复杂变简单）——支付门面常同时做两者
- 实战结构：Facade 内部编排子系统调用顺序 + 错误处理 + 状态确认——「编排逻辑收拢」业务侧不感知步骤
- 前端典型：支付门面/上传门面（选图→压缩→分片→合并→确认五步封装为 upload(file)）/登录门面
- 深水点：外观的「层级纪律」——业务只调门面不直捣子系统（lint 禁止直接 import 内部模块）——否则门形同虚设

```javascript
// 支付外观
export async function pay(orderId) {
  const params = await risk.check(orderId).then(() => payApi.prepay(orderId));
  try { await wx.requestPayment(params); }
  catch (e) { /* cancel 也继续查单 — 用户可能已付 */ }
  const state = await pollOrder(orderId);
  if (state === 'PAID') return { ok: true };
  if (state === 'PENDING') return { ok: true, pending: true };
  throw new PayError(state);
}
// 业务侧: const r = await pay(orderId) — 五步收拢为一行
// 纪律: 禁止 import payApi (lint 强制走门面)
```
