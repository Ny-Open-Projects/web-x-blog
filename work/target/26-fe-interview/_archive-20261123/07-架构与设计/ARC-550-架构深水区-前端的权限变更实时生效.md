## ARC-550：权限变更实时生效
**答**:
- 生效链路：管理端改权限 → 服务端权限版本号 +1（ARC-383）→ 推送失效（WS/SSE 广播该用户）→ 用户端收到 → 重新拉权限快照 → UI 即时更新；推送失败兜底：下次请求带旧版本号，服务端发现过期返回 426 要求刷新（轮询兜底闭环）。
- UI 反应策略：新增权限（菜单/按钮出现——平滑展示，不闪断）、收回权限（正在使用的页面处理：软失效——当前操作完成后续期失败跳转；硬失效——涉资页面立即退出，ARC-420 权限裁决）。
- 会话与权限解耦：权限变更不踢会话（除非安全要求）——权限快照独立刷新；踢出（ARC-415 会话撤销）单独通道。
- 一致性窗口：推送延迟内用户可能仍用旧权限——服务端裁决兜底（前端显隐是体验，提交时服务端拒绝 ARC-420 红线）。
- 观测：权限变更到生效的延迟指标、失效推送到达率（推送链路健康）。
```javascript
ws.on('perm:invalidate', async () => {
  const fresh = await permStore.refresh();                       // 重拉快照
  router.applyPermRoutes(fresh);                                 // 路由/菜单更新
});
// 兜底：api 拦截器收到 426 Upgrade Required（权限过期）→ permStore.refresh() + 重放请求
```
