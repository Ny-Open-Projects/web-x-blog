## ARC-530：拖拽排序一致性架构
**答**:
- 排序模型：分数排序（相邻分数中点）vs 位置数组 vs 链表——批量移动多选分数区间会耗尽精度（分数排序的经典坑）；推荐"序号 + 批量重排"：移动 = 计算新位置数组提交 diff。
- 乐观更新：拖放结束本地立即重排（UI 不等网络）→ 服务端提交（batch move 原子）→ 失败回滚 + 提示；提交 diff（moved ids + 目标位置）而非全量。
- 并发冲突：两人同时拖——服务端按提交序处理，后提交者收到冲突（基准版本不符）→ 拉最新重放本地操作或提示；协作场景走 op 序列（ARC-379）。
- 批量语义：多选拖拽、跨列表移动（看板：列变更 + 位置变更一个事务 ARC-412）、撤销一笔（ARC-387 merge）。
- 感知细节：拖拽占位（ghost）与实际提交布局一致、自动滚动（ARC-497）、移动端长按阈值。
```javascript
async function onDrop(dragIds, targetList, index) {
  const before = store.snapshot();                               // 乐观
  store.move(dragIds, targetList, index);
  try { await api.reorder({ ids: dragIds, list: targetList, index, baseVersion: ver }); }
  catch (e) { store.restore(before);                             // 回滚
    if (e.conflict) await reloadAndPrompt(); }                   // 冲突重放
}
```
