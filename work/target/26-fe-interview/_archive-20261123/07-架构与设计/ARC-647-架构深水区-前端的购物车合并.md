## ARC-647：购物车合并
**答**:
- 场景：匿名购物车（本地）→ 登录 → 与服务端车合并（同商品数量合并/超限处理）、多端登录合并（手机加的 Web 出现）。
- 合并协议：登录成功 → 合并请求（本地车快照上传）→ 服务端合并策略（同 SKU 数量相加 capped、失效商品保留标记、冲突定价以后来为准）→ 返回合并结果 → 本地覆盖刷新；合并冲突可见（合并报告：新增 X 件/合并 Y 件——用户知情）。
- 匿名车存储：本地持久（IndexedDB——匿名车也是状态需恢复 ARC-434）、匿名 ID 关联（ARC-572 匿名标识——服务端可做"匿名车暂存"实现跨端匿名合并）。
- 一致性：合并是原子事务（服务端——防合并中并发加购丢失）、合并后失效重算（价格/优惠重算 ARC-644）。
- 边界：超大车合并（百 SKU——批量协议分批）、合并失败的降级（保留本地车 + 提示重试——不丢数据优先）。
```javascript
// 登录合并
async function onLogin(uid) {
  const localCart = await idb.get('cart');                       // 匿名车快照
  const { cart, report } = await api.mergeCart(localCart);       // 服务端原子合并
  cartStore.replace(cart); idb.set('cart', cart);
  toast(`已合并 ${report.merged} 件商品`);                        // 合并报告
}
```
