## ARC-292：低代码画布与渲染器分离的编辑态注入怎么做？
**答**：
- 分离原理：渲染器输出组件树，编排器不重写渲染逻辑，而是通过**上下文注入**拿到编辑能力：渲染器在创建组件时调用 `enhance(el, nodeMeta)` 钩子，画布侧实现钩子挂选择框/拖拽手柄。
- 关键机制：节点与 DOM 的映射（每个组件实例挂 data-node-id）→ 点击命中反查 DSL 节点 → 属性面板联动；拖拽时渲染器提供"插入占位"（drop indicator）而不是编排器自己造 DOM。
- 编辑态与运行态隔离：编辑注入的全部代码走单独入口（iframe 内画布或独立 bundle），运行时产物不含任何编排代码——发布产物干净。
- 事件劫持：画布内点击/拖拽要拦截组件默认行为（按钮别真触发提交），渲染器在编辑态把用户事件替换为编排事件。

```tsx
// 渲染器增强钩子
function renderNode(node, ctx) {
  const Comp = materialMap[node.componentName];
  const el = <Comp {...resolveProps(node.props, ctx)}/>;
  if (ctx.mode === 'edit') return (
    <div data-node-id={node.id}
      onClickCapture={e => { e.preventDefault(); e.stopPropagation(); ctx.select(node.id); }}
      className={ctx.selected === node.id ? 'lc-selected' : ''}>{el}</div>
  );
  return el;
}
// 命中反查：click → closest('[data-node-id]') → node.id → 属性面板与大纲树同步选中
```
