## ARC-438：多窗口应用的渲染架构如何设计？
**答**:
- Electron 架构分层：主进程（窗口生命周期/系统 IO/原生菜单）、渲染进程（每窗口独立）、共享进程（UtilityProcess 跑重任务）。多窗口的核心问题是"状态与服务的归属"。
- 状态归属设计：跨窗口共享状态放主进程（单一事实源）或独立后台窗口（hidden window 做服务层），窗口间通过 IPC 请求-响应 + 广播订阅同步；禁止各窗口独立拉数据导致口径分裂。
- IPC 协议：requestId 关联、超时与错误传播、大数据用 MessagePort 或 SharedArrayBuffer 而非序列化 IPC。
- 性能：窗口数量控制（同质窗口用 BrowserView 复用）、隐藏窗口休眠、首窗口启动优化（延迟加载非首窗）。
- 生命周期：窗口崩溃自动重建并恢复状态（状态可序列化快照）；退出前状态持久化。
```javascript
// 主进程：共享状态服务
ipcMain.handle('state:get', (e, key) => sharedState.get(key));
ipcMain.on('state:patch', (e, patch) => {
  sharedState.patch(patch);
  BrowserWindow.getAllWindows().forEach(w =>
    w.webContents.send('state:changed', patch));            // 广播给所有窗口
});
// 渲染进程统一 store 适配 IPC，业务代码无感窗口边界
```
