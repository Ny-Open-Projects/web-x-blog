## ARC-242：多语言文案的翻译生产流水线如何搭建？
**答**：
- 流水线五环：源文案入库（key 进文案平台，代码只引用 key）→ 翻译任务生成（diff 出新增/变更 key）→ 机翻+译员混合（AI 预翻 + 人工校对高价值页面）→ 质检（术语一致性、长度溢出、占位符完整）→ 产物回注（CI 校验 key 覆盖率后才允许发布）。
- 代码侧保障：ESLint 禁止 JSX 里出现裸中文（扫出未国际化文案）；CI 检查"用到的 key 必须在源语言包存在""其他语言缺失时列出清单但可用 fallback"。
- 版本管理：文案包按 app 版本发版，线上按"语言包版本"缓存；回滚文案 = 回滚语言包版本，与代码发布解耦。
- 长度与排版质检：德语/俄语比中文长 30%~100%，CI 里对每个 key 做"容器宽度预估"或截图级视觉回归，提前发现溢出。

```yaml
# CI 文案门禁（示意）
i18n-check:
  - bare-chinese-in-jsx: error            # 未国际化文案
  - key-exists-in-source: error           # 引用了不存在的 key
  - placeholder-integrity: error          # {name} 占位符各语言必须一致
  - missing-langs: warn --allow en        # 缺失语言列出清单
# 文案平台 API：POST /keys/diff?base=main → 新增 key 自动建翻译任务 → 状态机 draft→mt→human→approved
```
