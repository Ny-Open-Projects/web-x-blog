## DP-395：组件库模式应用

**答**：
- 组件库的模式全景：工厂（组件注册）、组合组件（Tabs/Select 的复合 API）、headless（行为与样式分离）、策略（主题 token 切换）、代理（受控/非受控双模）、备忘录（表单组件的内部态）
- 组件 API 设计的模式：受控/非受控混合（value/defaultValue）、组合式（复合子组件）、headless 可选层（提供 useXxx hook 供深度定制）
- 版本演进的约束：组件 API 是契约——breaking change 的成本由所有业务承担——「新 prop 而非改语义」的演进纪律
- 主题系统：token 层（CSS 变量）+ 组件层（var() 消费）——主题切换零组件改动
- 深水点：组件库的「树摇友好」——ESM 导出 + sideEffects 标注（按需加载）—— barrel 文件的副作用陷阱
