## ARC-450：前端的可回滚设计：发布之外的回滚维度
**答**:
- 回滚不止"切回旧版本"：功能开关回滚（新逻辑秒关）、数据回滚（错误配置/错误文案回滚）、缓存回滚（污染的缓存清除）、端上状态回滚（本地升级的 schema 迁移要可逆或向前兼容）。
- 发布回滚（ARC-368）：指针切换秒级；配合"保留 N 个历史版本可用"策略，回滚目标版本必须仍能运行（旧版本 API 兼容窗口）。
- 开关回滚：功能走 flag 包裹（ARC-281），出问题开关关闭即回滚，比发版快 10 分钟；关键新功能默认"暗发布"（上线不开启）。
- 数据与配置回滚：配置中心变更历史快照一键恢复；缓存污染（错误数据大面积缓存）有 purge 协议（ARC-444）。
- 不可回滚操作的防御：本地 schema 迁移设计为向前兼容（新代码读旧数据 OK，回滚后旧代码遇到新数据不崩——未识别字段忽略策略）；支付等强操作不做前端层面回滚，只做补偿流程。
```javascript
// 向前兼容的迁移设计（可回滚前提）
function safeMigrate(old) {
  return { ...old, newField: old.newField ?? DEFAULT };      // 只增不改名
}
// 旧代码读取新数据：忽略未知字段（JSON.parse 天然满足），关键在写入侧：
// 不删除旧字段（双写期），回滚后旧代码仍能工作
```
