## ARC-594：无限滚动位置恢复
**答**:
- 经典难题：无限滚动列表 → 进详情 → 返回，位置必须恢复且数据一致（不能跳回顶部或数据错位 ARC-386/389）。
- 恢复协议：快照三件（滚动位置 + 已加载数据集 + 数据版本）——返回时恢复快照；数据未变 → 直接恢复（虚拟列表定位到 index，高度缓存 ARC-442）；数据已变（刷新/过期）→ 版本比对：尝试锚定（记录锚点元素 id 与偏移，数据刷新后按锚点重定位——ARC-ALG 锚点恢复算法）。
- 分页协议配合：恢复滚动位置需要"已加载 N 页"的数据都在——恢复时按快照 cursor 并行补拉缺失页（双缓冲渲染：恢复完成前显示骨架）。
- 失效降级：锚点元素已删除/数据结构变化 → 降级恢复到相对比例位置（保守）而非强行定位错位。
- 跨端一致：Web（history.scrollRestoration 手动管理 + 自己的快照）、小程序（页面栈天然保留但要处理数据过期）、App（原生复用）——快照协议三端统一。
```javascript
// 滚动恢复协议
function leaveList() { saveSnapshot({ scrollTop, items, version, anchor: visibleFirstItem() }); }
function enterList(snap) {
  if (snap.version === currentVersion) restore(snap);            // 直接恢复
  else refetchFrom(snap.cursor).then(fresh => relocate(snap.anchor, fresh)); // 锚点重定位
}
// relocate：找 anchor.id 新位置 → scrollTop = offsetOf(anchor) + snap.delta
```
