## DP-362：中介者模式：联动解耦

**答**：
- 问题场景：多对象互相引用（字段 A 联动 B，B 联动 C，C 又校验 A——网状依赖）——中介者把「多对多」变「星型」（都跟中介者说）
- 实战形态：表单引擎的中介者（字段间联动规则集中在 engine——字段只发布变更/订阅结果）；微前端的基座（子应用互不认识，通过基座通信）
- 与观察者的分工：观察者是一对多广播；中介者是「多对多的协调中枢」（知道全局规则）
- 实战要点：中介者的规则注册（联动规则数据化：{ when: 'a>10', then: disable('b') }——规则可测可配）
- 深水点：中介者的「膨胀风险」——所有逻辑涌入中介者（上帝对象）——按域拆分中介者（表单联动/页面通信各自中介）

```javascript
class FormMediator {
  #rules = []; #fields = new Map();
  addRule(rule) { this.#rules.push(rule); }          // { when(ctx), effect(ctx) }
  fieldChanged(name, value) {
    this.#fields.set(name, value);
    const ctx = Object.fromEntries(this.#fields);
    for (const rule of this.#rules)
      if (rule.when(ctx)) rule.effect(ctx, this);    // 联动集中处理
  }
}
// 规则: mediator.addRule({ when: (c) => c.type === 'enterprise',
//   effect: (c, m) => m.setFieldRequired('taxId', true) })
// 字段们互不认识, 只跟 mediator 说话 — 网状变星型
```
