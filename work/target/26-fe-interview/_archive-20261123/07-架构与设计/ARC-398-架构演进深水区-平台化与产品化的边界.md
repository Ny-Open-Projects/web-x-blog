## ARC-398：内部平台何时值得产品化？
**答**:
- 判断维度：重复度（同类需求出现次数 ≥ 3 且模式稳定）、标准化程度（协议能写清楚 = 能产品化）、维护意愿（有没有长期 owner）、用户面（覆盖团队数决定摊薄成本是否成立）。
- 阶段模型：脚本/工具（一次性）→ 内部库（团队内复用）→ 平台（跨团队自助服务）→ 产品（对外/商业化）。跳级是常见失败原因——没有内部打磨直接对外必翻车。
- 产品化成本：文档、onboarding、兼容承诺、支持响应、版本化发布——维护成本通常是最初开发的 2~3 倍，评估时按全生命周期算。
- 反产品化信号：需求方只此一家、协议月月变、无人愿意接手维护——保持脚本形态，别建平台。
- 退出机制：平台使用率持续低于阈值 → 冻结新功能 → 归档下线，代码与数据迁移方案先行。
```javascript
// 产品化评估打分
function productizeScore({ reuse, stability, owner, users }) {
  const score = reuse * 3 + stability * 3 + owner * 2 + users * 2;  // 0~10
  if (score >= 8) return '立项产品化';
  if (score >= 6) return '内部库形态，暂不建平台';
  return '维持脚本/工具';
}
```
