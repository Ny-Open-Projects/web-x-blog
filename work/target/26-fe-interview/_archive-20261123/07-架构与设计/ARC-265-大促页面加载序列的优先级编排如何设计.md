## ARC-265：大促页面加载序列的优先级编排如何设计？
**答**：
- 把资源与数据分成四档：P0 关键路径（HTML/CSS/首屏数据）、P1 首屏可交互依赖（核心 JS）、P2 首屏后内容（楼层 2+）、P3 低优（埋点上报/预取/字体）。编排目标：P0 并行、P1 紧随、P2/P3 让路。
- 技术：P0 用 preload/fetchpriority=high；P2 用懒加载 + IntersectionObserver；P3 用 requestIdleCallback + fetchpriority=low；JS 拆 chunk 按档位注入。
- 数据编排：首屏接口聚合成一个"页面快照接口"（BFF 聚合），一次往返；非首屏数据进入视口才请求。避免瀑布（A 等 B 等 C）——依赖图显式化。
- 大促变体：峰值期 P2/P3 直接降档为"不加载"（ARC-258 开关），保护 P0 带宽。

```html
<!-- P0/P1 在 head -->
<link rel="preload" href="/api/page-snapshot" as="fetch" fetchpriority="high">
<link rel="preload" href="/core.a1b2.js" as="script" fetchpriority="high">
```
```typescript
// P2/P3 编排
const io = new IntersectionObserver(loadFloor, { rootMargin: '200px' }); // 楼层进视口前 200px 预载
floors.slice(1).forEach(f => io.observe(f.el));
requestIdleCallback(() => { beacon.flush(); prefetchNextPage(); });      // P3 空闲期
```
