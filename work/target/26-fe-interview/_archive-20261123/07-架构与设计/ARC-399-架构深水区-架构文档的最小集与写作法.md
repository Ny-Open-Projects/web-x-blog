## ARC-399：架构文档的最小集与写作法
**答**:
- 最小集四件：系统概览（一页图：模块与数据流）、关键决策（ADR 列表）、模块指南（每模块职责/边界/入口）、运维手册（发布/回滚/常见故障 Runbook）。超过这四件的部分按需长出，不预写。
- 写作原则：文档回答"为什么"（决策背景与取舍），"是什么"尽量由代码与自动生成图承载（ARC-397 防失真）；每篇文档 3 个月内不更新就归档或删。
- ADR 写法：一行决策 + 背景（为什么现在要决策）+ 备选与放弃原因 + 后果（新约束）；单条 ≤ 100 行，可读性优先于完备性。
- 图的规范：一张图只讲一件事（数据流/依赖/部署分开画）；框图里的每个框都有名字与 owner；禁止装饰性大图。
- 维护机制：文档与代码同仓库同 MR 评审（架构变更必须带文档变更），CI 校验文档中引用路径有效性。
```javascript
// ADR 模板（精简版）
const adr = `# ADR-014: 状态库选用 TanStack Query + Zustand 组合
## 背景：服务端状态与本地状态混在 Redux 导致缓存与失效逻辑膨胀
## 决策：服务端状态走 TanStack Query，本地 UI 状态走 Zustand
## 放弃：Redux Toolkit（缓存与失效仍需自建）、SWR（无 mutation 体系）
## 后果：新约束——禁止把服务端响应复制进全局 store；契约测试覆盖 queryKey`;
```
