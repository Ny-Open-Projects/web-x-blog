## ARC-273：大促期间的客户端缓存策略如何设计？
**答**：
- 分级缓存：静态资源 immutable（hash URL + 1 年）；HTML 短缓存或协商缓存（保证版本及时性）；**数据缓存**分"可陈旧"（商品描述，stale-while-revalidate）与"必须新鲜"（价格/库存，no-store，专用接口）。
- 大促专项预热：活动开始前把商品页静态壳+图片预取进 SW Cache Storage（预热名单下发），峰值时命中本地。
- 缓存失效一致性：价格库存这类"必须新鲜"的数据与可陈旧数据**物理分离**（不同接口、不同缓存策略），可陈旧数据抖动不影响交易正确性。
- 失效兜底：大促改版风险（旧 HTML 引用已删除 chunk）——旧版本 HTML 保留期拉长 + chunk 不删除，或 SW 对缺失资源兜底到旧缓存并上报。

```typescript
// SW 分级路由
self.addEventListener('fetch', (e) => {
  const url = new URL(e.request.url);
  if (url.pathname.startsWith('/api/price/')) return;        // 新鲜数据：直穿网络，不缓存
  if (url.pathname.match(/\.(js|css|png)$/)) {
    e.respondWith(cacheFirst(e.request));                    // immutable 资源：缓存优先
  }
});
// 预热：主线程 postMessage({ type: 'warmup', urls: warmList }) → SW caches.addAll(urls)
// 兜底：cacheFirst catch → caches.match(oldUrl) + report('chunk-missing', url)
```
