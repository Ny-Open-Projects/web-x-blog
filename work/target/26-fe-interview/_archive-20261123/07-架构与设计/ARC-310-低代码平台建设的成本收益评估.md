## ARC-310：低代码平台建设的成本收益评估？
**答**：
- 成本结构：平台研发（引擎+物料+运维，人年级）、物料持续建设（组件生产流水线常年投入）、用户培训与支持（运营/产品使用成本）、迁移与维护（存量页面随引擎升级）。总成本常被低估在"物料持续建设"。
- 收益结构：搭建效率（页面交付时间从周降到天）、专业研发释放（ARC-300 分工）、复用资产沉淀（模板复用次数）。收益要有**对照数据**：同类页面的低代码 vs 手写交付耗时对比。
- 适用边界（ARC-100 风险评估延伸）：高频、模式化的页面（中后台 CRUD/营销页）收益最大；强个性化/高性能场景收益为负。
- 评估节奏：上线 6 个月做 ROI 复盘（ARC-267 复盘机制），不达预期的方向裁撤，避免平台变成"什么都想做"的黑洞。

```typescript
// ROI 模型（半年窗口）
function roi(stats) {
  const savedHours = stats.pagesBuilt * stats.avgManualHours * (1 - stats.lcHoursRatio);
  const devCost = stats.platformPersonMonths * stats.costPerPM;
  const benefit = savedHours * stats.hourlyCost;
  return { roi: (benefit - devCost) / devCost, breakEvenPages: Math.ceil(devCost / (stats.avgManualHours * stats.hourlyCost * 0.7)) };
}
// 例：200 页 × 16h × 60% 节省 × ¥150 = ¥28.8万收益；平台投入 6 人月 × ¥4万 = ¥24万 → ROI ≈ +20%
// 关键：avgManualHours/lcHoursRatio 必须来自对照测量，不是拍脑袋
```
