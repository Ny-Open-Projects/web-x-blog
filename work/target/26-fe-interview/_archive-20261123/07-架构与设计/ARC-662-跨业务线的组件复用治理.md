## ARC-662：组件复用治理

**答**：
- 复用的三个层次：设计 token（全公司统一）、基础组件（平台维护——Button/Table）、业务组件（中台维护——订单卡片/地址选择器）——层次清晰防「什么都往组件库塞」
- 组件入库标准：≥2 个业务线真实使用才进公共库（「预判复用」的组件 80% 死亡）——先复用后入库
- 组件的版本与兼容：semver + 变更日志 + 迁移指南——breaking change 的成本由「业务线升级负担」约束组件库设计（少破坏）
- 组件库的「反模式治理」：巨型组件（什么都配置）、业务耦合组件（接口地址写死）——「组件的 purity」进 review 清单
- 深水点：复用率度量——组件在 N 个应用的引用数（npm 依赖分析）——复用率低的组件进「退役清单」

```text
复用治理:
  层次: token → 基础组件(平台) → 业务组件(中台)
  入库: ≥2 业务线真实使用 (先复用后入库)
  版本: semver + 迁移指南 (少 breaking)
  反模式: 巨型组件/业务耦合 → review 清单
  度量: 引用数 → 低复用进退役清单
```
