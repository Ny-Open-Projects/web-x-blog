## ARC-305：低代码平台如何支持复杂交互逻辑：状态机？
**答**：
- 事件表达式只能表达简单联动；审批流/多步表单这类复杂交互需要**可视化状态机/流程编排**：状态（页面态）+ 事件（触发）+ 动作（副作用）+ 守卫（条件）。
- DSL 设计：页面可挂 flow 定义（节点=状态，边=事件+guard），引擎把 flow 编译成状态机实例（XState 风格），组件 props 可绑定当前状态（`visible: state === 'editing'`）。
- 编排体验：图形化流程编辑器是高级物料（ARC-298 插件），流程变化热生效；流程执行日志可视（哪一步被 guard 拦了）方便低代码用户自排查。
- 与工作流后端结合：跨系统流程（人工审批流转）不前端硬造，对接工作流引擎 API，前端 flow 只管页面态。

```typescript
// flow DSL 与编译
const flow = {
  initial: 'viewing',
  states: { viewing: { on: { EDIT: { target: 'editing', guard: 'canEdit' } } },
            editing: { on: { SAVE: { target: 'viewing', actions: 'submitForm' },
                             CANCEL: 'viewing' } } },
};
const machine = compileFlow(flow, ctx);        // guard 'canEdit' → resolveExpr(ctx.canEdit)
machine.send('EDIT');                          // guard false → 拒绝并记录日志
// 绑定：<Button visible={useFlowState() === 'viewing'} onClick={() => machine.send('EDIT')}>
```
