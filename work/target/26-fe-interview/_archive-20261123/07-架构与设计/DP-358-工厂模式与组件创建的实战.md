## DP-358：工厂模式：创建解耦

**答**：
- 工厂的价值：调用方不关心「怎么创建」（依赖的组装细节）——组件工厂（按 type 渲染不同组件）、服务工厂（按环境创建不同实现）
- 实战形态一：注册表工厂（Map<type, Creator>——动态表单的组件映射，新增类型只注册不改渲染逻辑）
- 实战形态二：抽象工厂（按平台创建整套实现——WebFactory/MobileFactory 各产出 storage/pay/analytics——跨端适配层）
- 工厂 + 依赖注入：工厂产出实例时注入依赖（测试可传 Fake）——「工厂负责组装，DI 负责可测」
- 深水点：工厂的「创建参数校验」——非法 type 抛错并提示可用类型（静默 fallback 会掩盖配置错误）

```javascript
// 注册表工厂
const creators = new Map([
  ['text', () => TextField],
  ['select', (opts) => SelectField(opts.options)],
]);
export function createField(spec) {
  const creator = creators.get(spec.type);
  if (!creator) throw new Error(`unknown type: ${spec.type}, available: ${[...creators.keys()]}`);
  return creator(spec.props);
}
// 跨端抽象工厂
function createServices(platform) {
  const impls = { web: { storage: localStorageAdapter, pay: webPay }, 'mini-app': { storage: wxStorage, pay: wxPay } };
  return impls[platform];     // 调用方: services.pay.order(...) — 不关心端差异
}
```
