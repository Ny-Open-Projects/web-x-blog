## TST-901：大促下单返回 30 个字段只错了 couponAmount，如何让断言失败「一句话定位根因」？
**答**：
- 结论：可诊断断言的黄金结构是「期望值 / 实际值 / 差异路径 / 下一步线索」四件套，而不是 expected true to be false 这种零信息报错。
- 做法：用 toMatchObject / objectContaining 做局部比对，只断言关心的字段，让 diff 只暴露真正不同的路径。
- 进阶：在断言前给失败结果挂业务上下文（订单号、场次、优惠券规则版本），失败日志直接可检索。
- 追问钩子：如果错误字段嵌套在 data.order.items[2].price 里，你怎么让报错直接给出这条路径而不是整棵对象树？

```javascript
// 反例：整对象比对，噪声淹没根因
expect(order).toEqual(expectedOrder); // 30 字段刷屏

// 正解：局部断言 + 显式路径上下文
function assertField(obj, path, expected) {
  const actual = path.split('.').reduce((o, k) => o?.[k], obj);
  if (actual !== expected) {
    throw new Error(
      `[下单断言失败] 路径=${path} 期望=${expected} 实际=${actual} ` +
      `订单号=${obj.orderId} 场次=${obj.sessionId}`
    );
  }
}
assertField(order, 'data.order.items.2.price', 9900);
// 失败输出：路径=data.order.items.2.price 期望=9900 实际=9901 订单号=O123 场次=S9
```
