## TST-299：契约如何演进而不破坏兼容（向后兼容规则）？
**答**：
- 兼容规则固化：新增可选字段=兼容；删除字段/改类型/收紧校验=breaking 需走流程。
- broker 的兼容性检查（pact-flow 系）自动判定 diff 类型，breaking 拒绝合入。
- 多版本过渡：提供者同时支持新旧字段一个版本期（deprecation 标记），消费者迁移完成再删。
- 契约即文档：字段语义/示例/弃用说明写进契约注解，自动生成 API 文档。

```javascript
// 兼容性规则示例
const compatible = (old, next) =>
  Object.keys(old).every(k => k in next) &&          // 不删字段
  Object.entries(old).every(([k, v]) => typeOf(next[k]) === typeOf(v)); // 不改类型
// 新增字段必须 optional（consumer 契约用 like() 才不破）
r
```
