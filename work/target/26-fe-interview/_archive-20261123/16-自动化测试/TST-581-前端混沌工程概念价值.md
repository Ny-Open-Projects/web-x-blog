## TST-581：前端混沌工程是什么，为什么要做

**答**：
- 结论：混沌工程是「主动在受控范围注入故障，验证系统韧性」的实践；前端做混沌是为了暴露「弱网/依赖失败/渲染异常」下的真实用户体验问题，而非等线上事故。
- 价值：验证降级/容错/重试是否真生效，发现隐藏的单点依赖，建立团队对故障的信心与响应能力。
- 追问钩子：前端做混沌和后端有什么不同？——前端更关注「用户可感知体验」（白屏/卡顿/错误提示/降级展示），且受设备/网络/浏览器多样性影响，故障注入多在测试环境的客户端侧。

```javascript
// 前端混沌实验的最小骨架：稳态 → 注入 → 观测 → 恢复
async function chaosExperiment({ steadyCheck, inject, observe, rollback }) {
  const before = await steadyCheck();
  try {
    await inject();
    const during = await observe();
    return { before, during, resilient: during.errorVisible && !during.whiteScreen };
  } finally {
    await rollback(); // 必须恢复，无论成功失败
  }
}
```
