## TST-837：平台化治理：如何防止「平台成了新的单点瓶颈」？
**答**：
- 结论：平台化在收敛重复建设的同时会引入「单点风险」——治理要点是去中心化执行、平台无状态化、有降级与逃生通道。
- 去中心执行：平台只做调度与聚合，实际执行跑在各团队自己的 runner/集群上，平台挂了不阻塞本地测试。
- 无状态化：平台状态外置（DB/队列），可水平扩容与快速重建。
- 逃生通道：保留「脱离平台直接跑」的能力（本地命令直接跑用例），平台故障时团队仍能交付。
- 追问钩子：团队习惯了平台，已经忘了怎么本地直接跑测试——这种「能力退化」如何防范？

```javascript
// 逃生通道：平台不可用时的本地直跑脚本
const runner = {
  async run() {
    try { return await this.viaPlatform(); }
    catch (e) {
      console.warn('平台不可用，降级本地直跑:', e.message);
      return this.viaLocal(); // 保证交付不被平台阻塞
    }
  },
  async viaPlatform() { throw new Error('platform 503'); },
  async viaLocal() { return { passed: true, source: 'local' }; },
};
runner.run().then(console.log); // { passed:true, source:'local' }
```
