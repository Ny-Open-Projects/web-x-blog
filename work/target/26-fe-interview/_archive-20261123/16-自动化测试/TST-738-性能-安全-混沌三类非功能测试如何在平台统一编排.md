## TST-738：性能、安全、混沌三类非功能测试如何在平台统一编排

**答**：
- 结论：三类测试统一为「非功能任务」抽象，共用调度器与结果模型，差异封装在任务类型插件里。
- 统一任务模型：{type, target, params, budget}，调度器只关心资源预算与依赖，不关心具体类型。
- 编排要处理互斥：性能压测与混沌注入不能同时对同一目标跑，用资源锁串行化。
- 追问钩子：混沌实验触发了性能告警，如何区分是预期故障还是真实回归？

```javascript
// 统一非功能任务编排 + 资源互斥锁
class Orchestrator {
  constructor() { this.locks = new Map(); }
  schedule(task) {
    const key = task.target;
    if (this.locks.has(key)) return { ok: false, why: '目标被占用' };
    this.locks.set(key, task.type);
    return { ok: true, run: () => this.locks.delete(key) };
  }
}
const o = new Orchestrator();
const t1 = o.schedule({ type: 'perf', target: 'svcA' });
const t2 = o.schedule({ type: 'chaos', target: 'svcA' }); // 被互斥
console.log(t1.ok, t2.ok); // true false
```
