## TST-923：快照基线能不能像代码一样「版本化 + 回滚」？大促前误更新了怎么办？
**答**：
- 结论：快照文件进 Git 本身就是版本化——关键是「更新与代码同 PR」，回滚时用 git revert 快照文件即可，禁止在发布分支上 -u。
- 实践：大促前冻结快照（只读），任何更新走 hotfix 流程；给 .snap 文件打 release tag 便于回溯。
- 回滚验证：revert 后必须重跑全量快照测试确认绿，不能只 revert 文件不验证。
- 追问钩子：大促当天有人偷偷 -u 更新了 20 个快照并合入，你如何在 10 分钟内判断哪些是真变更、哪些是误更新？

```javascript
// 大促前冻结快照：CI 检测发布分支上的快照变更则拦截
const branch = process.env.GIT_BRANCH;
const snapChanged = execSync('git diff --name-only main -- "*.snap"').toString().trim();
if (/release\//.test(branch) && snapChanged) {
  console.error('发布分支禁止修改快照，请走 hotfix 流程:\n' + snapChanged);
  process.exit(1);
}
// 回滚后验证：revert 指定 commit 的快照文件并重跑
execSync('git revert --no-commit <bad-commit> -- "*.snap"');
execSync('npm test -- --runInBand'); // 必须全绿才算回滚成功
```
