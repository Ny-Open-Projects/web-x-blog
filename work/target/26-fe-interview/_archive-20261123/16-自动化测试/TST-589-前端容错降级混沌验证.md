## TST-589：前端容错与降级能力的混沌验证

**答**：
- 结论：验证「依赖失败时用户仍能完成核心任务」——通过注入接口错误/超时/第三方挂掉，断言降级 UI（骨架/缓存/默认值/友好提示）出现且核心流程可用。
- 做法：列出每个外部依赖的降级策略表（依赖→失败表现→降级行为），逐一注入验证；检查错误边界（Error Boundary）捕获渲染异常，避免整页白屏。
- 追问钩子：降级用了缓存数据，怎么保证不是过期到误导用户？——给缓存数据加时间戳与有效期标识，降级时展示「数据可能不是最新」，并设置缓存刷新策略。

```javascript
// 降级策略表驱动验证
const FALLBACKS = {
  'recommend-api': { onFail: 'show-cache', mustShow: '推荐内容(可能过期)' },
  'pay-sdk':       { onFail: 'disable-button', mustShow: '支付暂不可用' },
  'avatar-cdn':    { onFail: 'default-image', mustShow: '默认头像' },
};
function verifyFallback(dep, response, renderedText) {
  const rule = FALLBACKS[dep];
  if (response.ok) return { pass: true };
  return { pass: renderedText.includes(rule.mustShow), expected: rule.mustShow, rule: rule.onFail };
}
```
