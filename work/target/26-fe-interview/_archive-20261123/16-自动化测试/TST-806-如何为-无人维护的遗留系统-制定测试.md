## TST-806：如何为「无人维护的遗留系统」制定测试接管策略？
**答**：
- 结论：不要试图一开始就补全测试，用「 characterizing tests（特征化测试）」先锁住现有行为，再随重构逐步替换。
- 第一步：对核心链路加「表征测试」——记录当前真实输入输出（哪怕是 bug），形成安全网，先保证不破坏现状。
- 第二步：按「变更热度 × 缺陷密度」排序，只在高频改动区补真正的行为测试，避免在即将下线的模块浪费投入。
- 第三步：引入「测试债」台账，每次改动顺手补一点，配合绞杀者模式逐步迁移，而非停下业务专门补测试。
- 追问钩子：表征测试把一个 bug 也锁住了，后来产品说这个 bug 要修，你如何区分「锁住现状」和「固化错误」？

```javascript
// 表征测试：先记录现状（含已知 bug），作为重构安全网
import { describe, it, expect } from 'vitest';
import { legacyPricing } from './legacy'; // 不敢动的老代码

describe('legacyPricing 表征（锁定当前行为）', () => {
  // 已知 bug：会员折扣叠加顺序错误，但当前线上就是这个行为，先锁住
  it('VIP+优惠券的当前实际结果', () => {
    expect(legacyPricing({ vip: true, coupon: 10, price: 100 })).toBe(81);
  });
  it('边界：空购物车', () => {
    expect(legacyPricing({ vip: false, coupon: 0, price: 0 })).toBe(0);
  });
  // 注释标明：待产品确认后，再修正期望值——避免把 bug 永久固化
});
```
