## TST-924：一个公共组件被 5 条业务线引用，它的快照变更该谁批、怎么避免「一人改全员炸」？
**答**：
- 结论：公共组件快照采用「双层 owner」——组件 owner 主审 + 各消费方代表会签，变更需同步通知所有下游。
- 机制：CODEOWNERS 配置组件 owner；CI 检测公共快照变更自动 @ 全部消费方；提供「影响面清单」（哪些业务用例引用了该快照）。
- 降级：紧急修复允许先合入 + 24h 内补齐会签，但需记录豁免。
- 追问钩子：5 条业务线里有 2 条正处于大促封版，公共快照必须改，你怎么协调？

```javascript
// 影响面分析：哪些业务线的用例引用了公共快照
function impact(snapshotKey, testRegistry) {
  return testRegistry
    .filter(t => t.snapshots.includes(snapshotKey))
    .map(t => ({ team: t.team, line: t.businessLine, frozen: t.freezeUntil > Date.now() }));
}
const affected = impact('Price.snap 1', [
  { team: 'pay', businessLine: '支付', snapshots: ['Price.snap 1'], freezeUntil: 0 },
  { team: 'promo', businessLine: '大促', snapshots: ['Price.snap 1'], freezeUntil: Date.now() + 864e5 },
]);
console.log(affected); // promo.frozen = true → 需协调或走豁免
```
