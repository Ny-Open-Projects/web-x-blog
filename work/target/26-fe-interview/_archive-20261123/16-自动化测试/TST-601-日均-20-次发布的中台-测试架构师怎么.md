## TST-601：日均 20 次发布的中台，测试架构师怎么设计分层与门禁？

**答**：
- 结论先行：按「变更半径 × 反馈速度」切三层——提交级（单测+静态）、合并级（集成+契约）、发布级（E2E+性能+安全），每层独立门禁与时限。
- 提交级必过且 <3 分钟；合并级阻塞但可带 owner 审批豁免；发布级卡关键路径，失败走自动回滚而不是卡死发布。
- 门禁要分层降级：资源紧张时只保留 P0 用例，把完整验证挪到发布后线上探针。
- 追问钩子：业务方要求「先发后测」，你如何用线上探针 + 灰度把门禁右移而不丢质量数据？

```javascript
function planGates(changeScope, budgetMin) {
  const layers = [
    { name: 'commit', kinds: ['unit', 'lint'], limit: 3 },
    { name: 'merge',  kinds: ['integration', 'contract'], limit: 10 },
    { name: 'release',kinds: ['e2e', 'perf', 'security'], limit: 30 },
  ];
  return layers.map(l => {
    const need = l.kinds.filter(k => changeScope.includes(k));
    return { layer: l.name, run: need, blocking: l.limit <= budgetMin,
             timeout: l.limit, degraded: budgetMin < l.limit };
  });
}
console.log(planGates(['unit', 'e2e'], 15).map(g => g.layer + ':' + g.blocking));
```
