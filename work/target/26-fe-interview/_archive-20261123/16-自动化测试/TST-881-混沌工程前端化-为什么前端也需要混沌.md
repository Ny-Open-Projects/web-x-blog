## TST-881：混沌工程前端化：为什么前端也需要混沌测试，与后端混沌有什么差异？
**答**：
- 结论：后端混沌关注「服务不可用/延迟」，前端混沌关注「在依赖异常时用户体验是否可控」——验证降级、兜底、重试、错误边界是否真的生效。
- 差异点：前端是「用户侧最后一公里」，依赖多（API/CDN/第三方 SDK）、网络环境复杂（弱网/离线）、状态在客户端，故障表现更碎片化。
- 前端混沌目标：验证「一个依赖挂了不会整页白屏」「错误有友好提示」「恢复后状态自愈」。
- 手段：故障注入 fetch/CDN/SDK、弱网模拟、随机数据污染、错误边界触发。
- 追问钩子：后端混沌有成熟的稳态假设（SLO），前端「稳态」该怎么定义？

```javascript
// 前端混沌关注点 vs 后端
const comparison = {
  后端: { 目标: '服务可用性/SLO', 手段: '杀进程/限流/网络分区', 稳态: 'QPS/错误率' },
  前端: { 目标: '用户体验可控', 手段: '故障注入/弱网/脏数据', 稳态: '白屏率/可交互/提示友好' },
};
function frontendChaosFocus() {
  return ['API 异常时降级 UI', '第三方 SDK 挂了不阻塞主流程',
    '弱网/离线可恢复', '错误边界兜底不白屏'];
}
console.log(frontendChaosFocus().join(' / '));
```
