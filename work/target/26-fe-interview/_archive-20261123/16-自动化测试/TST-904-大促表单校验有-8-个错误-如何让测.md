## TST-904：大促表单校验有 8 个错误，如何让测试一次跑完并聚合展示而不是报第一个就停？
**答**：
- 结论：用「软断言」模式——把失败收集到数组，用例末尾统一断言 failures 为空，避免白屏式逐条改。
- 工具：Jest/Vitest 可用 expect-soft 或自行维护 failures 数组；Playwright 用 expect.soft。
- 注意：软断言不适合有依赖关系的步骤（如登录失败后不应继续断言购物车），要给硬断言保留位置。
- 追问钩子：8 个错误里有 3 个是同一个根因（接口 500）连锁触发的，聚合后如何帮开发去重而不是刷 8 条？

```javascript
// Playwright 软断言：一次收集所有校验错误
await page.goto('/checkout');
await expect.soft(page.getByText('请选择地址')).toBeVisible();
await expect.soft(page.locator('#coupon-error')).toHaveText('优惠券已过期');
await expect.soft(page.locator('#stock-error')).toHaveText('库存不足');
await expect.soft(page.locator('#agreement')).toBeDisabled();

// 手写版：按错误码去重
const failures = [];
const soft = (cond, msg, code) => { if (!cond) failures.push({ msg, code }); };
soft(price > 0, '价格非法', 'PRICE');
soft(stock > 0, '库存不足', 'STOCK');
const deduped = [...new Map(failures.map(f => [f.code, f])).values()];
expect(deduped).toEqual([]); // 末尾统一断言，失败输出去重后的清单
```
