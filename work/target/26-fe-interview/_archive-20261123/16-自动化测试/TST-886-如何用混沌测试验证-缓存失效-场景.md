## TST-886：如何用混沌测试验证「缓存失效」场景（CDN / 本地缓存打穿）？
**答**：
- 结论：缓存失效演练要「主动让缓存不可用」——清空 CDN/本地缓存、注入穿透流量，验证回源链路与降级策略是否扛得住。
- 演练手段：注入 Cache-Control: no-cache、删除 localStorage/Service Worker 缓存、mock CDN 返回 5xx。
- 验证点：回源后首屏是否仍可接受、是否有「缓存击穿」导致后端雪崩、降级到静态兜底是否生效。
- 护栏：演练限灰度环境，回源流量设上限，避免真的打挂后端。
- 追问钩子：缓存打穿后前端变慢但没崩，如何判断这是「可接受的降级」还是「用户体验不可接受」？

```javascript
// 缓存失效演练：禁用缓存 + 观察回源表现
async function cachePunchTest(page, cdn) {
  await page.evaluate(() => {
    localStorage.clear();
    caches.keys().then(keys => keys.forEach(k => caches.delete(k))); // 清 SW 缓存
  });
  cdn.mockStatus(503); // CDN 不可用，强制回源
  const start = Date.now();
  await page.goto('/product/1', { headers: { 'Cache-Control': 'no-cache' } });
  const metrics = { firstPaintMs: Date.now() - start };
  cdn.restore();
  return { ...metrics, acceptable: metrics.firstPaintMs < 4000 };
}
```
