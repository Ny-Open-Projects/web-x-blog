## TST-801：测试架构师的终局能力模型：从写用例到定标准，你凭什么做架构师？
**答**：
- 结论：架构师的价值不是「写更多用例」，而是定义质量的标准、杠杆与决策框架，让几百人团队的质量水位可复制。
- 三层能力：能写（懂工具与实现）→ 能设计（定分层/门禁/度量）→ 能影响（无职权推动标准落地）。终局看的是第三层。
- 标志性产出物：测试策略文档、质量门禁规范、成熟度模型、工具选型 ADR、质量债路线图——这些是「资产」而非一次性脚本。
- 判断标准：团队离开你之后，质量体系是否还能自转？能自转才算架构，不能自转只是高级个体贡献者。
- 追问钩子：如果我问你「过去一年你做的哪个决定让团队整体少写了 30% 的重复用例」，你能答上来吗？答不上说明还停在写用例层。

```javascript
// 架构师的产出物示例：一份可被团队复用的「质量门禁 ADR」
const adr = {
  id: 'ADR-007', title: 'CI 质量门禁分级',
  status: 'accepted',
  context: '20 条业务线共用一条主干，门禁过松导致缺陷逃逸，过严拖慢交付',
  decision: {
    blocker: ['单测覆盖率 >= 70%', '核心 E2E 通过率 = 100%'],
    warner: ['性能预算增幅 <= 5%', 'flaky 率 <= 1%'],
    bypass: '紧急修复需 tech-lead 双人审批 + 24h 内补测',
  },
  consequences: ['发布前平均多 6 分钟', '线上 P0 下降 40%'],
};
// 价值不在写了这个对象，而在让所有团队按同一份 decision 执行
console.log(adr.decision.blocker.join(' / '));
```
