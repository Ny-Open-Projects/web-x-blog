## TST-302：灰度发布期间新旧契约并存的测试策略？
**答**：
- 灰度期间 provider 同时满足 v1/v2 契约——两套契约都在 broker 验证集合中。
- 灰度分流头（x-beta）驱动：契约测试分别带新旧头验证两条路径。
- 灰度收口：v1 契约归档（标记 deprecated）前的消费者迁移追踪。
- 测试环境复现灰度：按头分流的路由在集成环境可切换。

```javascript
test.each([
  ['v1', {}], ['v2', { 'x-api-version': '2' }],
])('灰度双契约 %s', async (_v, headers) => {
  const res = await provider.verify({ headers });
  expect(res.status).toBe(200);      // 两版本都满足
});
```
