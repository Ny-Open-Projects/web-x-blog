## TST-983：「测得快」和「测得准」冲突时怎么取舍？ Especially 大促封版窗口？
**答**：
- 结论：分阶段取舍——开发期偏快（快速反馈，允许漏），封版/发布前偏准（全量慢测，追求零漏），用「阶段化门禁」承接。
- 手段：快（受影响用例、并行、mock 依赖）与准（全量、真实依赖、多环境）不是同一套配置，按阶段切换。
- 底线：任何阶段都不能牺牲「确定性」——宁可少测，不可测出假绿误导决策。
- 追问钩子：大促封版只剩 2 小时，全量回归要 4 小时，你怎么在 2 小时内给出「可发布」结论且不背锅？

```javascript
function stageStrategy(stage, remainingHours) {
  if (stage === 'dev') return { scope: 'affected', mock: true, gate: '建议级',
    note: '快速反馈，允许少量漏测' };
  if (stage === 'release' && remainingHours >= 4)
    return { scope: 'full', mock: false, gate: '阻塞级', note: '全量真实依赖' };
  if (stage === 'release') return {
    scope: 'critical-path', mock: false, gate: '阻塞级',
    note: '时间不足：只跑 P0 关键路径 + 人工签署风险，禁止降级为真绿',
  };
  return { scope: 'none' };
}
console.log(stageStrategy('release', 2).scope); // 'critical-path'
```
