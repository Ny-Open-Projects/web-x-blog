## TST-812：大规模团队里「测试左移」如何真正落地而不流于口号？
**答**：
- 结论：左移不是「让测试人员早点介入」，而是把质量活动嵌入需求/编码/CI 的每一个环节，让缺陷在成本最低处被发现。
- 需求阶段：验收标准(AC)写成 Given-When-Then 可测语句，测试参与评审并对齐「什么叫完成」。
- 编码阶段：TDD/单测、静态检查、契约测试、组件测试前移到开发本地，IDE 内即可反馈。
- 基建支撑：把左移能力做成默认工具链（pre-commit、CI 模板、MR 门禁），而不是靠个人自觉。
- 追问钩子：左移后测试同学是不是就没事做了？你如何重新定义测试团队的价值定位？

```javascript
// 左移落点矩阵：把质量活动映射到研发阶段
const shiftLeft = {
  '需求': ['AC 可测化', '三方评审（产品/开发/测试）'],
  '设计': ['可测性设计评审', '契约先行'],
  '编码': ['TDD/单测', 'lint', '类型检查'],
  '集成': ['组件测试', 'MSW 接口测试', '契约验证'],
  '提交': ['pre-commit 钩子', 'MR 门禁'],
};
for (const [stage, activities] of Object.entries(shiftLeft)) {
  console.log(`${stage}: ${activities.join(' + ')}`);
}
```
