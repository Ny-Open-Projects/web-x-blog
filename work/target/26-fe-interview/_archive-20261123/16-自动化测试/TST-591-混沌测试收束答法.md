## TST-591：混沌测试与韧性工程的面试收束答法

**答**：
- 结论：答法分四步——先讲「为什么」（主动找脆弱点、验证降级容错），再讲「注入什么」（网络/渲染/数据/依赖四维度），再讲「怎么安全做」（稳态假设+爆炸半径+熔断回滚），最后落到「度量与常态化」（韧性分+故障即代码+文化）。
- 关键判断：混沌的价值不在「实验全过」，而在「发现了多少脆弱点并修复」；安全边界是红线。
- 追问钩子：和传统测试区别是什么？——传统测试验证「期望行为成立」，混沌验证「异常情况下系统仍可接受」；一个测确定性，一个测不确定性下的韧性。

```javascript
// 面试回答的结构化骨架
const answerFrame = {
  why: '主动暴露弱网/依赖失败下的体验问题',
  what: ['network', 'render', 'data', 'dependency'],
  how: ['steady-hypothesis', 'blast-radius', 'circuit-breaker', 'rollback'],
  measure: ['resilience-score', 'chaos-as-code', 'game-day'],
  law: '价值 = 发现的脆弱点，而非实验全过',
};
// 结构化骨架可在面试中按此顺序展开
const speak = () => Object.values(answerFrame).join(' → ');
console.log(speak());
```
