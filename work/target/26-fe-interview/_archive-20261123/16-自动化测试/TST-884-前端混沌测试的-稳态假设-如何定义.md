## TST-884：前端混沌测试的「稳态假设」如何定义（如何判断系统健康）？
**答**：
- 结论：前端稳态假设 = 可观测的用户体验指标阈值——「页面可交互、关键内容可见、错误有提示、无白屏」，注入故障后这些指标不破即为稳态。
- 可观测信号：FCP/可交互时间、错误边界是否触发兜底 UI、关键元素是否渲染、控制台错误率。
- 假设写法：遵循「我们认为，当 X 依赖故障时，系统仍满足 Y（稳态指标）」的句式，可证伪。
- 判定：注入前后对比稳态指标，差异在容忍区间内则假设成立，否则发现脆弱点。
- 追问钩子：稳态指标选「白屏率」还是「用户可完成核心操作」，哪个更能反映真实健康？

```javascript
// 稳态假设的可证伪判定
const steadyState = {
  hypothesis: '当商品详情 API 故障时，页面仍展示骨架屏+友好提示，不白屏',
  indicators: { fcpMs: 1500, errorBoundaryShown: true, whiteScreen: false, actionable: true },
  check(observed) {
    return !observed.whiteScreen &&
      observed.errorBoundaryShown &&
      observed.fcpMs < this.indicators.fcpMs;
  },
};
console.log(steadyState.check({ whiteScreen: false,
  errorBoundaryShown: true, fcpMs: 900 })); // true 稳态保持
```
