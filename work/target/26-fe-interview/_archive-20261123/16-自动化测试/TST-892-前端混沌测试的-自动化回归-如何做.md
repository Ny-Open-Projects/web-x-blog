## TST-892：前端混沌测试的「自动化回归」如何做（不是一次性演练）？
**答**：
- 结论：把混沌演练「用例化 + CI 化」——故障注入写成可重复执行的测试用例，纳入回归套件，每次发布都验证容错能力不退化。
- 用例化：用固定随机种子 + 故障配置，让演练可复现；断言稳态指标（不白屏/有提示/可恢复）。
- CI 化：核心链路的混沌用例进 nightly/发布前套件，而非人工偶尔点一下。
- 瑞典：注入率与范围受控测试环境，演练结果与功能测试一起出报告。
- 追问钩子：混沌用例本身可能 flaky（随机性），如何让它稳定可重复？

```javascript
// 混沌用例化：固定种子 + 稳态断言
import { describe, it, expect } from 'vitest';
describe('混沌回归：商品页依赖故障', () => {
  it('详情 API 失败时不白屏且展示友好提示', async () => {
    const chaos = injectChaos(fetch, {
      rate: 1, weights: { fail: 1 }, seed: 42, // 固定种子，可复现
    });
    render(<ProductPage fetcher={chaos} />);
    await screen.findByText('加载失败，请重试');
    expect(screen.queryByText('白屏')).toBeNull();
  });
});
// 进 nightly CI，保证每次发布容错不退化
```
