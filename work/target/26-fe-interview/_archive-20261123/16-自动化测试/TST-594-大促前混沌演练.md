## TST-594：大促前的混沌演练怎么组织

**答**：
- 结论：大促前按「风险清单 → 场景设计 → 受控演练 → 修复闭环 → 复盘准入」组织，重点验证限流/降级/熔断/扩容在真实压力下是否有效。
- 做法：列出大促核心链路与单点依赖；设计对应的网络/接口/依赖故障场景；在预发做演练（避开生产高峰），记录稳态表现；发现的脆弱点转 backlog，修复后复验作为发布准入。
- 追问钩子：演练发现的问题来不及全修怎么办？——按风险排序，P0 脆弱点必须修复才可准入，其余纳入大促期间的应急预案与 oncall 关注清单。

```javascript
// 大促演练准入：脆弱点分级 + 复验
function drillGate(findings) {
  const p0 = findings.filter(f => f.severity === 'P0');
  const unfixedP0 = p0.filter(f => !f.fixed);
  return { canRelease: unfixedP0.length === 0,
    blockers: unfixedP0.map(f => f.title),
    watchlist: findings.filter(f => f.severity !== 'P0' && !f.fixed).map(f => f.title) };
}
console.log(drillGate([
  { title: '支付降级失效', severity: 'P0', fixed: false },
  { title: '头像加载慢', severity: 'P2', fixed: false },
])); // canRelease=false, blockers=['支付降级失效']
```
