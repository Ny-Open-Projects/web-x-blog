## TST-728：平台如何支撑性能压测的分布式编排与施压端治理

**答**：
- 结论：分布式压测=「中央编排 + 多施压端协同」，关键是时钟同步与负载模型一致，否则结果不可信。
- 编排器统一下发场景与 RPS 曲线，施压端按同一时间轴打流，用 NTP 保证时钟偏差在毫秒级。
- 施压端自身不能成为瓶颈：监控其 CPU/连接数，超过阈值自动扩容或限流。
- 追问钩子：施压端分布在不同地域，如何判断是服务端慢还是施压端网络慢？

```javascript
// 分布式 RPS 分配：按施压端权重拆分
function distributeRps(totalRps, workers) {
  const weightSum = workers.reduce((s, w) => s + w.weight, 0);
  return workers.map(w => ({
    id: w.id,
    rps: Math.round(totalRps * w.weight / weightSum),
  }));
}
console.log(distributeRps(1000, [
  { id: 'w1', weight: 3 }, { id: 'w2', weight: 1 },
])); // w1:750, w2:250
```
