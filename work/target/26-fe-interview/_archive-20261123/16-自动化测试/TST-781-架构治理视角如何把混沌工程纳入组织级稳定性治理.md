## TST-781：架构治理视角：如何把混沌工程纳入组织级「稳定性治理」体系

**答**：
- 结论：混沌工程不是独立活动，而是稳定性治理的一环——与 SLO、故障复盘、容量治理并列，统一到「韧性目标」下管理。
- 治理三件套：统一韧性度量指标、实验准入与审批流程、发现问题的闭环跟踪（从实验到改进项）。
- 架构层提供公共能力（注入平台、稳态基线、熔断），业务只定义场景与假设，降低参与门槛。
- 追问钩子：稳定性治理有 KPI 后，团队开始「刷演练次数」，如何纠偏？

```javascript
// 稳定性治理：韧性目标驱动
function governanceScore(org) {
  const { sloCoverage, chaosRuns, issueClosure, mttrTrend } = org;
  return {
    score: +(sloCoverage * 0.3 + Math.min(chaosRuns, 20) / 20 * 0.2
      + issueClosure * 0.3 + (mttrTrend > 0 ? 0.2 : 0)).toFixed(2),
    note: '演练次数封顶，避免刷量',
  };
}
console.log(governanceScore({ sloCoverage: 0.8, chaosRuns: 50, issueClosure: 0.7, mttrTrend: 1 }));
```
