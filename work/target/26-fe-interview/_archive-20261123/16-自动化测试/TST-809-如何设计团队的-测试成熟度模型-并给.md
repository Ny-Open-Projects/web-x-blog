## TST-809：如何设计团队的「测试成熟度模型」并给出定级方法？
**答**：
- 结论：成熟度模型要可观测、可定级、可演进——每一级都有明确的「证据」，避免凭感觉打星。
- 分级参考：L1 无系统测试 → L2 有零散单测 → L3 分层+CI 门禁 → L4 平台化+度量驱动 → L5 质量自治/预测。
- 定级证据：单测覆盖率、CI 门禁覆盖率、flaky 治理机制、测试平台化程度、质量指标闭环——用数据而非问卷。
- 用法：不是拿来排名羞辱，而是识别「下一级最该补的能力」，给出可执行的升级路径。
- 追问钩子：成熟度模型最容易变成「为评级而评级」的形式主义，你如何防止？

```javascript
// 成熟度定级器：用证据自动定级，避免主观打分
const LEVELS = [
  { level: 1, evidence: c => c.coverage < 0.1 },
  { level: 2, evidence: c => c.coverage >= 0.1 && !c.ciGate },
  { level: 3, evidence: c => c.ciGate && !c.platform },
  { level: 4, evidence: c => c.platform && c.metricsClosedLoop },
  { level: 5, evidence: c => c.predictiveQuality },
];
function grade(ctx) {
  return LEVELS.slice().reverse().find(l => l.evidence(ctx))?.level ?? 1;
}
console.log(grade({ coverage: 0.8, ciGate: true, platform: true,
  metricsClosedLoop: true, predictiveQuality: false })); // 4
```
