## TST-247：复合组件（如 Table 支持列自定义渲染）如何测试扩展点？
**答**：
- 渲染插槽用「探针」断言：传入标记内容验证渲染位置与次数。
- 自定义渲染的异常路径：render 函数抛错时组件的容错行为（不整表崩）。
- 扩展 API 与内部状态的交互：自定义列头带排序/筛选是否正常协作。
- 性能边界：100 行 × 30 列渲染时长断言（防扩展用法拖垮性能）。

```javascript
test('自定义列渲染', () => {
  render(<Table columns={[{ key: 'op', render: (r) => <b data-testid="probe">{r.id}</b> }]} data={[{ id: 1 }]} />);
  expect(screen.getByTestId('probe')).toHaveTextContent('1');
});
test('渲染函数抛错不崩表', () => {
  render(<Table columns={[{ key: 'x', render: () => { throw new Error('boom'); } }]} data={[{}]} />);
  expect(screen.getByRole('table')).toBeInTheDocument(); // 容错
});
```
