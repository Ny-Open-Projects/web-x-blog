## TST-899：混沌与稳定性收官：一次「全链路故障演练」的完整设计？
**答**：
- 结论：全链路演练 = 明确稳态假设 + 选关键故障场景 + 控制爆炸半径 + 全程可观测 + 可回滚 + 无指责复盘，是一次「有剧本的安全演习」。
- 准备：选核心链路（登录→浏览→下单→支付），定义稳态指标，通知相关方，确认 kill switch。
- 执行：在灰度环境注入 1-2 个故障（如支付 API 延迟 + 缓存失效），观察监控/告警/用户体验/降级表现。
- 收尾：验证回滚、汇总隐患、无指责复盘、产出改进项并纳入下一轮迭代。
- 追问钩子：如果演练中不得不提前终止（kill switch 触发），这次演练是成功还是失败？

```javascript
// 全链路演练的剧本结构
const drill = {
  scenario: '支付 API 延迟 + 缓存失效',
  steadyHypothesis: '用户仍可浏览、下单，故障有提示不白屏',
  blastRadius: { env: 'staging', users: 'internal-only' },
  observability: ['RUM', '告警', '错误边界上报'],
  killSwitch: 'seconds',
  steps: ['基线观测', '注入故障', '观测判定', '回滚', '无指责复盘'],
  output: ['隐患清单', '告警盲区', '改进项'],
};
console.log(drill.steps.join(' -> '));
```
