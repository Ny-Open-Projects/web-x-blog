## TST-854：安全测试如何左移到「编码阶段」（前端 SAST / lint 规则）？
**答**：
- 结论：把安全规则写成 lint 与静态检查（SAST），在开发者本地和 MR 阶段就拦截危险模式，比运行时扫描更早、更便宜。
- 规则示例：禁止 innerHTML 直接拼接用户输入、禁止 eval/new Function、禁止 document.write、cookie 必须带 Secure/HttpOnly 提示。
- 工具：ESLint 安全插件（eslint-plugin-security）、semgrep、CodeQL 做数据流分析；自定义规则覆盖业务特有风险。
- 落地：接入 pre-commit 与 MR 门禁，违规必须修复或申请豁免；规则误报要及时调校以免被无视。
- 追问钩子：静态规则误报率高导致开发绕过检查，你如何平衡安全性与开发体验？

```javascript
// 自定义 ESLint 风格规则：禁止危险 sink（示意）
const dangerousSinks = ['innerHTML', 'outerHTML', 'eval', 'new Function'];
function lintSecurity(code) {
  return dangerousSinks
    .filter(sink => code.includes(sink))
    .map(sink => ({ rule: 'no-dangerous-sink', sink,
      advice: `改用 textContent 或安全的 DOM API 替代 ${sink}` }));
}
console.log(lintSecurity('el.innerHTML = userInput; eval(x);'));
// 两条违规 + 可操作建议
```
