## TST-840：平台化收官：从脚本到平台到生态，你如何回答「测试平台的边界在哪」？
**答**：
- 结论：平台的边界是「提供机制不代替决策」——平台负责执行、调度、报告、治理能力，业务线的测试策略、用例设计、质量判断不该被平台接管。
- 该平台做的：runner、CI 集成、分片调度、报告聚合、flaky 治理、数据工厂、配额计量——规模效应强的公共能力。
- 不该平台做的：替业务定义「测什么」、强制统一所有阈值、把用例写成平台 DSL 导致与代码割裂。
- 演进方向：平台→生态是开放扩展点（插件/API），让第三方工具与业务特色能力接入，而非平台大而全。
- 追问钩子：平台团队和业务团队对「边界」理解不一致时，如何用机制（而非争论）达成共识？

```javascript
// 平台边界：机制下沉，策略上浮
const boundary = {
  platformOwns: ['执行引擎', '调度', '报告聚合', 'flaky 治理', '配额计量'],
  businessOwns: ['用例设计', '质量阈值', '发布决策'],
  extensionPoints: ['插件 Executor', '自定义钩子', '开放 API'],
};
function isInPlatformScope(capability) {
  return boundary.platformOwns.some(c => capability.includes(c));
}
console.log(isInPlatformScope('分片调度'), isInPlatformScope('定义发布阈值'));
// true false -> 阈值决策属于业务，平台不越界
```
