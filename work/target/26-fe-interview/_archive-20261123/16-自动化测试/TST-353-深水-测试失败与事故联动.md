## TST-353：线上事故后如何系统性地「测试补位」？
**答**：
- 事故复盘的测试议题：哪层测试缺口（缺用例/断言弱/环境差异）——归因到层。
- 补位用例「先红后绿」验证（在事故前代码上必须复现失败）。
- 同类风险排查：同模式的其他位置批量补测（AI 辅助定位相似代码）。
- 缺口登记：测试缺口清单进迭代排期（不口头承诺）。

```javascript
async function testGapFill(incident) {
  const gap = await classifyGap(incident);     // missing-case / weak-assert / env-diff
  const tc = await genRegressionCase(incident); // 先红后绿
  const similar = await findSimilarCode(incident.pattern);   // 同类批量补测
  return { tc, backlog: similar.map(s => `补测 ${s.file}`) };
}
```
