## TST-823：测试平台的「用例元数据」模型应如何设计？（标签/owner/层级/稳定性）
**答**：
- 结论：用例元数据是平台化的基石——把每条用例当作「可检索、可归属、可度量」的资产，而非散落的脚本。
- 核心字段：id、name、业务线、模块、层级(unit/integration/e2e)、owner、标签、稳定性分、执行时长、最后通过时间。
- 用途：按 owner 派单、按标签筛选回归集、按稳定性分治理 flaky、按时长优化执行顺序（快的先跑）。
- 治理：元数据与代码同源（文件头注释或配置即代码），随 mr 一起变更，避免平台与代码脱节。
- 追问钩子：元数据靠人工维护总会腐化，你如何让它「自动保鲜」？

```javascript
// 用例元数据模型（配置即代码，随用例文件提交）
const testMeta = {
  id: 'E2E-PAY-003', name: '优惠券叠加支付',
  layer: 'e2e', businessLine: 'pay', module: 'checkout',
  owner: 'zhangsan', tags: ['core', 'regression', 'smoke'],
  stability: 0.98, durationMs: 4200, lastPassed: '2026-11-22',
};
// 平台按元数据检索/派单
function pickRegressions(metaList, { tags, owner }) {
  return metaList.filter(m =>
    (!tags || tags.every(t => m.tags.includes(t))) &&
    (!owner || m.owner === owner));
}
console.log(pickRegressions([testMeta], { tags: ['core','smoke'] }).length); // 1
```
