## TST-643：弱网下请求乱序返回引发的竞态怎么测试？

**答**：
- 结论：弱网不只考验「慢」，更考验「乱序」——后发请求先返回时，旧结果不能覆盖新状态。
- 用可控延迟队列手动控制响应顺序，断言最终展示的是最后一次请求的数据。
- 检查三件事：请求取消（AbortController）、序号标记、过期响应丢弃。
- 追问钩子：取消请求后旧响应仍到达，组件已卸载，怎么防内存泄漏？

```javascript
function outOfOrderTest(handler) {
  const pending = [];
  const delayedFetch = (q) => new Promise(res =>
    pending.push(() => res(handler(q))));
  const first = delayedFetch('old');
  const second = delayedFetch('new');
  // 故意让后发请求先返回
  pending[1]();
  pending[0]();
  return Promise.all([first, second]);
}
// 断言：UI 最终状态 = 'new'，且 'old' 的响应被丢弃
```
