## TST-612：测试架构评审机制与红线清单应该怎么建立？

**答**：
- 结论：评审不是开会，而是把红线做成可执行的 CI 检查 + 人工评审清单双轨。
- 红线分三类：安全（禁 eval/innerHTML）、稳定性（禁全局 mock 泄漏）、可维护性（禁无主测试）。
- 每次评审产出 ADR，记录例外与到期时间，避免红线变成一纸空文。
- 追问钩子：业务紧急上线要绕过红线，你的审批与补救流程是什么？

```javascript
const REDLINES = [
  { id: 'SEC-1', re: /eval\(|innerHTML\s*=/, msg: '禁止危险 DOM 写入' },
  { id: 'STB-1', re: /vi\.mock\(.*\)\s*\/\/\s*global/, msg: '禁止全局 mock 泄漏' },
  { id: 'MNT-1', re: /it\.skip/, msg: 'skip 用例必须带 owner 与到期日' },
];
function review(files) {
  return files.flatMap(f => REDLINES
    .filter(r => r.re.test(f.content))
    .map(r => ({ file: f.name, rule: r.id, msg: r.msg })));
}
console.log(review([{ name: 'a.js', content: 'el.innerHTML = x' }]));
```
