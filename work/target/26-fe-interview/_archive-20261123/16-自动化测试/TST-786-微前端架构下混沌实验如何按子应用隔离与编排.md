## TST-786：微前端架构下混沌实验如何按「子应用」隔离与编排

**答**：
- 结论：微前端的隔离性天然适合做「按子应用的故障演练」——注入限定在单个子应用，验证主框架与其他子应用不受影响。
- 注入点：子应用的远程加载失败、资源超时、运行时抛错、共享依赖污染，观察基座是否降级而非整体崩溃。
- 编排要保证「一次只坏一个子应用」，避免多点故障叠加掩盖问题。
- 追问钩子：某子应用故障导致主框架一起挂，说明架构哪里有问题？

```javascript
// 微前端：按子应用注入故障，验证彼此隔离
function injectSubappFault(apps, target, failure) {
  return apps.map(app => app.name === target
    ? { ...app, status: 'failed', error: failure }
    : { ...app, status: 'ok' });
}
const apps = injectSubappFault(
  [{ name: 'header' }, { name: 'checkout' }, { name: 'footer' }],
  'checkout', 'chunk load timeout'
);
console.log(apps.filter(a => a.status === 'failed').map(a => a.name)); // ['checkout']
```
