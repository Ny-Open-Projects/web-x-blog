## TST-615：演进式设计：如何识别测试架构的腐化信号？

**答**：
- 结论：腐化是可度量的——看「修改一处要动几个测试」「新同学多久能写出第一个稳定用例」。
- 信号清单：测试间隐式顺序依赖、mock 层级超过 2 层、fixture 巨型化、门禁例外长期不回收。
- 定期做「架构健康巡检」，把信号转成 backlog 而不是等事故。
- 追问钩子：哪些腐化信号可以自动化检测，哪些只能靠 review？

```javascript
function decaySignals(stats) {
  const out = [];
  if (stats.avgMockDepth > 2) out.push('mock 过深：考虑依赖注入');
  if (stats.orderDependent > 0) out.push('存在顺序依赖用例');
  if (stats.fixtureLines > 300) out.push('巨型 fixture：拆 builder');
  if (stats.expiredWaivers > 0) out.push('过期门禁豁免未回收');
  return out;
}
console.log(decaySignals({ avgMockDepth: 3, orderDependent: 0,
  fixtureLines: 120, expiredWaivers: 2 }));
```
