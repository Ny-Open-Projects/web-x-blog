## TST-933：子应用独立发布（一天 10 次）时，怎么给它的契约变更设「守门」而不拖垮节奏？
**答**：
- 结论：把契约校验做成「子应用自助门禁」——提交时本地跑 schema 校验 + 消费者示例回放，CI 只跑受影响契约，秒级反馈。
- 分级：破坏性变更（删字段/改类型）需消费者会签；兼容变更自动放行。
- 守住底线：无论多快，契约校验不可跳过，紧急发布走「限时豁免 + 事后补测」并留痕。
- 追问钩子：子应用想 5 分钟内上线一个新 props，但契约检查要 10 分钟，你怎么既不阻塞又守住质量？

```javascript
// 按变更影响范围 selective 跑契约测试
const changedFiles = execSync('git diff --name-only HEAD~1').toString().split('\n');
const affectedContracts = changedFiles
  .filter(f => f.includes('/contracts/'))
  .map(f => f.replace('contracts/', '').replace('.schema.json', ''));
if (affectedContracts.length) {
  const isBreaking = checkBreaking(affectedContracts[0]);
  if (isBreaking && !hasConsumerSignoff(affectedContracts[0])) {
    console.error('破坏性契约变更缺少消费者会签'); process.exit(1);
  }
}
function checkBreaking() { /* 对比新旧 schema */ return false; }
function hasConsumerSignoff() { /* 查 PR 审批 */ return true; }
```
