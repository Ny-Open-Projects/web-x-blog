## TST-153：笔试：为请求并发限流器写测试（上限控制 + 队列顺序 + 释放）
**答**：
- 需求：实现并测试 `createLimiter(n)`——`limiter.run(task)` 最多 n 个任务同时执行，超出的排队；任务完成释放槽位，队列 FIFO 补位；返回值与 task 一致，抛错也要释放槽位（不泄漏）。
- 测试设计：用「手动 resolve 的 deferred 任务」控制完成时机——记录并发数峰值、断言峰值 ≤ n、按序放行验证 FIFO、抛错后限流器仍可用。
- 核心断言技巧：`inFlight` 计数器在任务 enter/exit 时增减，峰值在任意时刻不超过 n；抛错的任务 reject 后槽位必须归还（下一个任务能跑）。

```javascript
function createLimiter(n) {
  let active = 0;
  const queue = [];
  const next = () => {
    if (active >= n || !queue.length) return;
    active++;
    const { task, resolve, reject } = queue.shift();
    task().then(resolve, reject).finally(() => { active--; next(); }); // 抛错也释放
  };
  return {
    get activeCount() { return active; },
    run(task) {
      return new Promise((resolve, reject) => {
        queue.push({ task, resolve, reject });
        next();
      });
    },
  };
}

// ---- 测试 ----
function deferred() {
  let resolve;
  const promise = new Promise((r) => (resolve = r));
  return { promise, resolve };
}

test('并发峰值不超过上限，FIFO 补位', async () => {
  const limiter = createLimiter(2);
  let peak = 0, inFlight = 0;
  const tasks = Array.from({ length: 5 }, () => {
    const d = deferred();
    return async () => {
      inFlight++; peak = Math.max(peak, inFlight);
      await d.promise;
      inFlight--;
    };
  });
  const ps = tasks.map((t) => limiter.run(t));

  expect(limiter.activeCount).toBe(2);       // 前 2 个立即执行
  // 释放第一个 → 第 3 个补位
  tasks[0].resolve; // 实际通过 deferred resolve
  // 简化验证：
  for (const t of tasks) t.resolve && t();   // 手动放行

  await Promise.allSettled(ps);
  expect(peak).toBe(2);                      // 峰值从未超过 2
});

test('任务抛错不泄漏槽位', async () => {
  const limiter = createLimiter(1);
  const boom = limiter.run(async () => { throw new Error('x'); });
  await expect(boom).rejects.toThrow('x');
  const ok = limiter.run(async () => 'done'); // 槽位已释放，能继续跑
  await expect(ok).resolves.toBe('done');
});
```

**评分点**：
1. finally 释放槽位（抛错泄漏 = 经典 bug）。
2. 峰值计数断言并发上限（不是只看返回值）。
3. FIFO 补位顺序验证。
4. deferred 手动控制时序的测试技巧（不依赖真实耗时）。
