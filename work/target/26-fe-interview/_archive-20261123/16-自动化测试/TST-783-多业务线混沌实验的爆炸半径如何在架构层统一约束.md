## TST-783：多业务线混沌实验的「爆炸半径」如何在架构层统一约束

**答**：
- 结论：爆炸半径约束要「平台强制 + 分级限额」——架构层设定全局上限，业务只能在上限内申请，不能自行突破。
- 约束维度：影响用户比例、时长、地域、依赖范围；每项有全局硬上限与业务配额。
- 技术上靠流量染色 + 标签路由把注入限制在选定切片，熔断与回滚由平台统一控制。
- 追问钩子：某业务线申请超过全局上限的实验并声称「很重要」，如何决策？

```javascript
// 爆炸半径准入：全局上限 + 业务配额
function blastRadiusGate(req, globalCap, quota) {
  const limits = {
    userRatio: Math.min(req.userRatio, globalCap.userRatio, quota.userRatio),
    durationMs: Math.min(req.durationMs, globalCap.durationMs),
  };
  const clamped = limits.userRatio < req.userRatio || limits.durationMs < req.durationMs;
  return { approved: !clamped, limits, why: clamped ? '被上限裁剪，需重新确认' : '通过' };
}
console.log(blastRadiusGate(
  { userRatio: 0.1, durationMs: 600000 },
  { userRatio: 0.05, durationMs: 900000 },
  { userRatio: 0.08 }
));
```
