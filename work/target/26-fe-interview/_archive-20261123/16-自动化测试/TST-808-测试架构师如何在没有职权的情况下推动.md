## TST-808：测试架构师如何在没有职权的情况下推动质量标准落地？
**答**：
- 结论：靠「机制 + 样板 + 数据」建立影响力，而不是靠发文件；让人「自己想按标准做」而非「被迫按标准做」。
- 做样板间：先在 1-2 个标杆项目跑通标准并拿到可量化收益（缺陷下降、发布提速），用事实说服而非说教。
- 把标准产品化：封装成 lint 规则、CI 模板、脚手架，让「符合标准」成为最省力的默认选项（feature 默认开）。
- 建立社区：测试兴趣小组、内部分享、用例评审轮值，让标准在同伴压力下自然扩散。
- 追问钩子：如果某个业务线负责人就是不接受标准，你有哪些升级路径？什么时候该妥协、什么时候该上报？

```javascript
// 把标准做成「默认即合规」的 CI 模板，降低采纳阻力
const ciTemplate = {
  stages: ['install', 'lint:test-quality', 'unit', 'integration', 'e2e:core', 'gate'],
  // 标准内建：团队无需自己配置，天然合规
  qualityLint: {
    'no-assertion-on-truthy': 'error',   // 禁止 expect(true).toBe(true)
    'require-test-id': 'warn',           // 关键元素需 data-testid
    'max-flaky-rate': 0.01,
  },
  // 一键继承，业务线零成本接入
  extends: '@org/test-baseline',
};
console.log(ciTemplate.stages.join(' -> '));
```
