## TST-711：如何设计可演进的插件协议，避免测试平台被插件版本锁死

**答**：
- 结论：插件协议要「版本协商 + 能力声明 + 向后兼容默认值」三件套，禁止插件直接依赖平台内部类。
- 每次调用带协议版本，平台按版本选适配器；新字段可选、旧字段保留，消除强耦合。
- 插件先声明能力（canParse/canExecute），平台按能力路由，未声明则降级到默认实现。
- 追问钩子：插件作者用了平台未公开的私有 API，如何发现并阻止？

```javascript
// 协议版本协商 + 能力路由
const ADAPTERS = {
  '1': r => ({ id: r.name, ok: r.ok }),
  '2': r => ({ id: r.title ?? r.name, ok: r.status === 'passed' }),
};
function invoke(plugin, raw) {
  const v = plugin.protocol || '1';           // 默认 v1
  const adapter = ADAPTERS[v] || ADAPTERS['1']; // 未知版本降级
  if (!plugin.capabilities.includes('execute')) return { ok: false, reason: '能力未声明' };
  return adapter(raw);
}
console.log(invoke({ protocol: '2', capabilities: ['execute'] },
  { title: 'login', status: 'passed' })); // {id:'login', ok:true}
```
