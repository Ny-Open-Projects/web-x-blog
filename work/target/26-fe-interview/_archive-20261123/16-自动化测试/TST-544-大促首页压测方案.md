## TST-544：大促首页的压测方案怎么设计

**答**：
- 结论：明确压测目标（峰值 QPS/并发用户/响应时间 SLO）→ 构造真实流量模型 → 分级施压（基准→负载→峰值→破坏性）→ 监控与瓶颈定位 → 容量结论。
- 做法：流量模型按用户行为比例混合（浏览/加购/下单）；前端侧关注首屏资源、CDN 命中、长列表渲染；与后端全链路压测联动，注入影子流量避免污染生产数据。
- 追问钩子：前端在压测里只关心加载吗？——不止：高峰下的交互流畅度（INP）、图片懒加载、降级渲染、错误边界都是前端职责，需用真实低端机型测。

```javascript
// 压测阶梯：按阶段递增并发，记录各阶段 SLO 达标情况
const stages = [
  { name: '基准', vus: 100, dur: 60 },
  { name: '负载', vus: 500, dur: 120 },
  { name: '峰值', vus: 2000, dur: 300 },
];
function runStages(stages, slo) {
  return stages.map(s => ({
    name: s.name, vus: s.vus,
    // 伪：实测 p95；这里用模型估算演示
    p95: Math.round(s.vus * 1.2 + 200),
    pass: (s.vus * 1.2 + 200) <= slo.p95,
  }));
}
```
