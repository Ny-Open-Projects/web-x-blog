## TST-579：如何设计人机协同的测试工作流

**答**：
- 结论：明确分工——AI 做「广度生成、重复劳动、初步归因」，人做「风险判断、业务规则、最终决策」；中间用「闸门 + 评审 + 反馈闭环」连接。
- 做法：AI 产出进入待审队列；人评审的采纳/修改结果反哺 Prompt 与规则；记录每次人机协作的耗时与质量，持续优化哪些环节交给 AI。
- 追问钩子：怎么防止人「无脑点通过」？——把评审质量纳入度量（如 AI 用例的逃逸率），抽样复核，并让评审界面展示 AI 置信度与证据降低盲签。

```javascript
// 人机协同队列：AI 产出带置信度，人评审结果反哺
function collaborationQueue(aiOutputs) {
  return aiOutputs.map(o => ({
    ...o,
    priority: o.confidence >= 0.8 ? 'batch-review' : 'careful-review',
    showEvidence: true,           // 展示证据辅助决策
    feedbackKey: `${o.sourceVersion}|${o.id}`,  // 用于追踪采纳/修改
  }));
}
console.log(collaborationQueue([{ id: 1, confidence: 0.9, sourceVersion: 'v2' }]));
```
