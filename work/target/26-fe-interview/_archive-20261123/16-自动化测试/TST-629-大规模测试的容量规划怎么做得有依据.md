## TST-629：大规模测试的容量规划怎么做得有依据？

**答**：
- 结论：用排队论建模——把 CI 当 M/M/c 系统，输入到达率与单任务服务时长，算出所需 worker 数。
- 峰值按发布窗口的到达率 × 安全系数；排队时长超阈值就扩容或降载。
- 容量不是越多越好，要算边际收益：第 n 个 worker 缩短的时间递减。
- 追问钩子：扩容后反而更慢，可能的非线性瓶颈在哪？

```javascript
function capacity(lambda, serviceMs, targetWaitMs, maxWorkers = 64) {
  for (let c = 1; c <= maxWorkers; c++) {
    const rho = lambda * serviceMs / 1000 / c;
    if (rho >= 1) continue;
    const waitMs = (rho / (1 - rho)) * (serviceMs / c);
    if (waitMs <= targetWaitMs) return { workers: c, rho: +rho.toFixed(2), waitMs: +waitMs.toFixed(0) };
  }
  return { workers: maxWorkers, saturated: true };
}
console.log(capacity(2, 5000, 60000));
```
