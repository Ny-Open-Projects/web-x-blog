## TST-997：门禁阈值（覆盖率、通过率）定死了会僵化，怎么让阈值「自适应学习」？
**答**：
- 结论：阈值基于历史基线动态计算（如过去 8 周 P50/P90），而非拍脑袋定值；只升不降的「棘轮机制」防止悄悄退化。
- 做法：覆盖率下限 = 近 8 周中位数，异常周排除；阈值调整需评审且留痕。
- 边界：业务剧烈变化期（重构/大促）暂停自适应，用固定阈值避免误判。
- 追问钩子：某团队历史基线很低（覆盖率 40%），自适应会不会把低标准「合法化」？怎么防止？

```javascript
function adaptThreshold(history, { floor = 0.6, pct = 0.5, weeks = 8 }) {
  const recent = history.slice(-weeks).sort((a, b) => a - b);
  const median = recent[Math.floor(recent.length * pct)] ?? 0;
  return {
    threshold: +Math.max(floor, median).toFixed(2), // 不低于硬下限，防低基线合法化
    raw: +median.toFixed(2),
    note: median < floor ? '历史基线过低，采用硬下限' : '采用历史中位数',
  };
}
console.log(adaptThreshold([0.4, 0.42, 0.45, 0.41, 0.43], { floor: 0.6 }));
// { threshold:0.6, raw:0.42, note:'历史基线过低，采用硬下限' }
```
