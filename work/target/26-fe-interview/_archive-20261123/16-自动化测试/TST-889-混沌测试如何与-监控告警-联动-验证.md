## TST-889：混沌测试如何与「监控告警」联动（验证告警有效性）？
**答**：
- 结论：混沌演练是「告警的体检」——故意制造故障，验证监控能否及时发现、告警是否触达、值班是否能响应，闭环后才算告警有效。
- 联动方式：注入故障时打标记，观察监控指标是否异常、告警是否触发（含延迟），对比预期。
- 验证项：告警漏报（故障了没报）、误报（没故障乱报）、延迟（报得太慢）、可操作性（告警信息能否定位问题）。
- 闭环：演练发现的告警盲区补上规则与看板，形成「演练→发现→修复→再演练」的飞轮。
- 追问钩子：演练中故障发生了但监控没报警，你会从哪几个环节排查？

```javascript
// 告警有效性验证：注入故障 -> 观察告警是否按时触发
async function verifyAlert(injectFault, waitForAlert, expectedMaxDelayMs = 60000) {
  const start = Date.now();
  await injectFault();                          // 注入故障并打标记
  const alert = await waitForAlert(start);      // 等待告警系统触发
  if (!alert) return { effective: false, reason: '漏报：未触发告警' };
  const delay = alert.timestamp - start;
  return {
    effective: delay <= expectedMaxDelayMs,
    delay,
    actionable: Boolean(alert.runbook), // 告警是否带处理指引
  };
}
```
