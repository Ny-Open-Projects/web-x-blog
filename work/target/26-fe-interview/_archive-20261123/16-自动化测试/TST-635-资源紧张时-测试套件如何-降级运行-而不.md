## TST-635：资源紧张时，测试套件如何「降级运行」而不丢核心验证？

**答**：
- 结论：降级不是少跑，而是按风险重排——P0 链路 + 近期变更域必须跑，长尾用例延期。
- 用风险分给用例打标：核心交易/资金相关权重最高，UI 细节最低。
- 被跳过的用例要显式记录并进入下一轮补跑队列，不能默默消失。
- 追问钩子：降级后线上仍出了 P1 缺陷，你如何复盘降级策略？

```javascript
function degrade(cases, budget) {
  const sorted = [...cases].sort((a, b) => b.risk - a.risk);
  const run = [], deferred = [];
  let cost = 0;
  sorted.forEach(c => {
    if (cost + c.estMs <= budget) { run.push(c.id); cost += c.estMs; }
    else deferred.push({ id: c.id, reason: 'budget' });
  });
  return { run, deferred, coverage: +(run.length / cases.length).toFixed(2) };
}
console.log(degrade([{ id: 1, risk: 9, estMs: 4 },
  { id: 2, risk: 2, estMs: 10 }], 6).run);
```
