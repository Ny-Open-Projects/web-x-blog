## TST-586：微前端场景下的混沌测试怎么设计

**答**：
- 结论：重点验证「故障隔离」——某个子应用挂掉/加载失败/响应慢时，主应用与其他子应用不受影响，并有明确的降级展示与错误边界。
- 做法：注入子应用加载失败、JS 异常、接口超时、事件总线消息丢失；断言主框架存活、其他子应用可用、失败子应用显示错误占位而非整页崩溃；验证 mount/unmount 后无状态残留。
- 追问钩子：子应用之间共享依赖（如 React 实例）故障怎么测？——验证共享依赖加载失败时各子应用的降级行为，并检查版本冲突场景下的隔离策略（如 Module Federation 的 singleton 配置）。

```javascript
// 微前端混沌：注入某子应用加载失败，验证其余子应用存活
function microFeFault(apps, failingApp) {
  return apps.map(app => {
    if (app.name === failingApp) return { ...app, status: 'failed', fallback: app.errorBoundary ? 'placeholder' : 'crash' };
    return { ...app, status: 'ok' };
  });
}
const apps = [{ name: 'header' }, { name: 'checkout', errorBoundary: true }, { name: 'footer' }];
console.log(microFeFault(apps, 'checkout')); // checkout -> failed + placeholder，其余 ok
console.log(microFeFault(apps, 'header')); // header 无 errorBoundary -> crash
```
