## TST-831：测试平台如何做「自身的灰度发布」（平台自己的 CI/CD）？
**答**：
- 结论：测试平台也是软件，需要「用自己验证自己」——平台变更先在小流量/影子环境验证，再逐步放量，且要有回滚能力。
- 影子运行：新版本平台与旧版本并行执行同一批用例，对比结果一致性，无差异再放量。
- 分级放量：先内部团队 → 友好业务线 → 全量，每级观察失败率/执行时长是否异常。
- 回滚：平台配置与版本可快速回滚（feature flag），一旦新版本误判立即切回。
- 追问钩子：如果新版本平台「静默地」漏跑了某些用例（结果仍全绿），影子运行如何发现？

```javascript
// 影子运行：新旧版本对比用例集合是否一致
function shadowCompare(oldResult, newResult) {
  const oldIds = new Set(oldResult.caseIds);
  const newIds = new Set(newResult.caseIds);
  const missing = [...oldIds].filter(id => !newIds.has(id));
  const added = [...newIds].filter(id => !oldIds.has(id));
  return {
    consistent: missing.length === 0 && added.length === 0,
    missing, added, // 漏跑的用例必须为零才能放量
  };
}
console.log(shadowCompare(
  { caseIds: ['a','b','c'] }, { caseIds: ['a','b'] })); // missing:['c'] -> 不放量
```
