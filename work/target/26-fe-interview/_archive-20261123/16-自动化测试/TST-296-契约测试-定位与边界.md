## TST-296：契约测试（Pact）在测试体系中的定位与覆盖边界？
**答**：
- 定位：验证「服务间接口预期」——消费者期望与提供者实现匹配，替代大部分重量级联调 E2E。
- 边界：只验证结构与时序语义（状态码/字段/状态处理器），不验证业务正确性（那是提供者自己的单测）。
- 收益：提供者独立发布前就能知道是否破坏消费者——不用等联调。
- 不适用：复杂多步流程（走 E2E）、非契约化内部函数。

// consumer 测试
const provider = new PactV3({ consumer: 'fe-cart', provider: 'order-svc' });
await provider.addInteraction().given('order 1 exists')
  .uponReceiving('get order').withRequest({ method: 'GET', path: '/orders/1' })
  .willRespondWith({ status: 200, body: like({ id: '1', status: 'paid' }) }).executeTest(...);
