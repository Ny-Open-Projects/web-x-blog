## TST-836：如何让测试平台具备「可观测性」（自身的监控/告警/SLO）？
**答**：
- 结论：平台要像业务系统一样被观测——定义 SLO（如用例调度成功率、报告可用性），暴露指标、日志、链路，出问题能快速自愈或告警。
- 指标：调度延迟、执行成功率、队列堆积、flaky 率趋势、平台 API 错误率（RED/USE 方法）。
- 链路：给每次测试执行打 traceId，贯穿「提交→调度→执行→报告」，定位卡在哪一环。
- 告警：SLO SError budget 耗尽才告警，避免噪音；平台自身故障要有降级（呼应 TST-389 容灾）。
- 追问钩子：平台「看起来正常」但用例结果悄悄不准了（如时钟漂移），这类「沉默故障」如何用可观测性发现？

```javascript
// 平台可观测性：SLO + 指标采样
const slo = { name: '调度成功率', target: 0.999, window: '7d' };
function recordSLO(slo, actual) {
  const errorBudget = 1 - slo.target; // 0.001
  const errorRate = 1 - actual;
  return {
    slo: slo.name, actual,
    budgetRemaining: Number((errorBudget - errorRate).toFixed(4)),
    alert: errorRate > errorBudget,
  };
}
console.log(recordSLO(slo, 0.9985)); // errorRate 0.0015 > 0.001 -> alert true
```
