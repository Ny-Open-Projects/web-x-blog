## TST-851：性能测试「基线漂移」如何治理？（环境/数据/缓存导致假警报）
**答**：
- 结论：基线漂移治理的关键是「控制变量 + 相对比较 + 多轮统计」——固定环境/数据/预热策略，用多次中位数而非单次绝对值判定回归。
- 识别根因：机器负载波动、缓存预热与否、数据量变化、依赖服务抖动都会让基线漂移，需逐项排查。
- 控制手段：专用稳定机器、固定数据集与种子、统一预热轮次、关闭无关进程；记录环境指纹与每次结果关联。
- 判定策略：设「噪声区间」（如 ±10% 内不报警），连续多轮超阈值才判回归，避免单点抖动误报。
- 追问钩子：如何区分「真的性能退化」和「测试机今天比较慢」？

```javascript
// 基线判定：多轮中位数 + 噪声区间，抗单点抖动
function detectRegression(baseline, currentSamples, noiseRatio = 0.1) {
  const sorted = [...currentSamples].sort((a, b) => a - b);
  const median = sorted[Math.floor(sorted.length / 2)];
  const delta = (median - baseline) / baseline;
  return {
    median, baseline,
    delta: Number(delta.toFixed(3)),
    regression: delta > noiseRatio,
    note: Math.abs(delta) <= noiseRatio ? '噪声区间内，忽略' : '疑似真实退化',
  };
}
console.log(detectRegression(1000, [1010, 995, 1020, 1005, 1300]));
// 中位数 1010，delta 0.01 -> 噪声内；单次 1300 被中位数抹平
```
