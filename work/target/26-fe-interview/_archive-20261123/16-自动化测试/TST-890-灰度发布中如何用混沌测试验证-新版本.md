## TST-890：灰度发布中如何用混沌测试验证「新版本容错」？
**答**：
- 结论：灰度阶段的混沌测试要「在新版本上注入故障、对比旧版本表现」——验证新版本的降级/重试/容错没有退化，才逐步放量。
- 做法：对灰度流量注入依赖故障，对比灰度组与对照组的错误率/白屏率/恢复时长。
- 关注：新版本是否引入了「故障放大」（如重试风暴、缓存击穿）、降级 UI 是否仍生效。
- 放量门槛：灰度组稳态指标不劣于对照组，才进入下一档放量；否则回滚。
- 追问钩子：灰度组故障表现和对照组一样「正常」，但用户投诉变多了，可能是哪里没测到？

```javascript
// 灰度混沌：对比灰度组 vs 对照组的稳态指标
function compareCanary(canary, control, tolerance = 0.05) {
  const fields = ['errorRate', 'whiteScreenRate', 'recoverMs'];
  const degraded = fields.filter(f =>
    (canary[f] ?? 0) > (control[f] ?? 0) * (1 + tolerance));
  return {
    safe: degraded.length === 0,
    degraded, // 劣化字段 -> 阻止放量
    verdict: degraded.length ? '暂停放量并分析' : '可继续放量',
  };
}
console.log(compareCanary(
  { errorRate: 0.02, whiteScreenRate: 0.001, recoverMs: 800 },
  { errorRate: 0.01, whiteScreenRate: 0.001, recoverMs: 700 })); // degraded:['errorRate']
```
