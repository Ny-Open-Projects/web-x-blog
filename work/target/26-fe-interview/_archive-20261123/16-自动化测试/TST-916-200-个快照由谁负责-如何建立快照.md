## TST-916：200 个快照由谁负责？如何建立快照基线的 review 规范与 owner 制？
**答**：
- 结论：快照不是「测试的事」而是「组件的事」——给每个快照文件绑定 CODEOWNERS，变更必须对应组件 owner review。
- 规范：更新快照的 PR 必须说明「为什么变」，禁止 -u 全量更新；diff 超过 N 行自动打「大改」标签要求截图佐证。
- 治理：定期跑孤儿快照检测（无用例引用的基线）并清理，避免基线库腐化。
- 追问钩子：一个共享组件被 5 个业务线引用，它的快照变更该谁批、谁担责？

```javascript
# .github/CODEOWNERS 片段
/src/components/Price/    @team-pay
/src/components/Coupon/   @team-promo
/__snapshots__/Price.snap @team-pay @qa-infra

// CI 检查：快照 diff 行数阈值
const diffLines = execSync('git diff --numstat -- "*.snap"').toString();
const total = diffLines.split('\n').reduce((n, l) => {
  const [add, del] = l.split('\t').map(Number);
  return n + (add || 0) + (del || 0);
}, 0);
if (total > 200) {
  core.warning(`快照变更 ${total} 行，需附截图说明并 double review`);
}
```
