## TST-162：升级 React/Vitest/组件库大版本时，测试怎么保驾护航？
**答**：
- 升级前：确认测试基线是绿的（基线红 = 无法归因）；盘点升级影响面（React 18 的并发特性影响 act/RTL 行为、组件库大版本破坏 props API）；在分支上先跑一遍全集记录现状。
- 升级中：分两波——第一波只升测试工具链（vitest/RTL），业务代码不动，验证测试基础设施兼容；第二波升业务依赖（React/组件库），逐包升级跑受影响用例。锁定器（lockfile diff review）+ 变更日志里的 Breaking Changes 清单逐条核对。
- 升级后的验证矩阵：单测全绿 → E2E 冒烟 → 每夜全集 + 视觉回归（组件库升级视觉 diff 是重灾区）→ 灰度发布兜底。快照/截图基线需要有意更新（--update-snapshots），但要 review diff 图确认变化符合预期。
- 典型踩坑：React 18+ `act` 环境变量、RTL `render` 的 root API 变化、fake timers 实现从 jest 换 vitest 的行为差异（nextTick/queueMicrotask）、组件库从 uncontrolled 改 controlled。
- 追问钩子：没有测试的遗留库怎么办？——升级前先补「冒烟快照 + 核心交互用例」（特征测试 characterization tests），锁住当前行为再动。

```bash
# 升级操作脚本化（示例）
npm run test:unit -- --changedSince=main    # 升级分支跑受影响用例
npx playwright test --grep @smoke           # 冒烟
npx playwright test --update-snapshots      # 有意更新视觉基线（review diff!）
npx vitest run -u                           # 快照更新同样要 review
```
