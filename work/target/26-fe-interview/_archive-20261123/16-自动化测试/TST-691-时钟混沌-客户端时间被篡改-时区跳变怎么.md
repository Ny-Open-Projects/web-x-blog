## TST-691：时钟混沌：客户端时间被篡改 / 时区跳变怎么测试？

**答**：
- 结论：前端业务逻辑大量依赖本地时间（券有效期/倒计时/活动窗口），必须把「时间不可信」当默认假设。
- 注入场景：系统时间大幅前进/回退、跨时区切换、夏令时跳变。
- 断言：以服务端时间为准、倒计时不出现负数、活动状态不错乱。
- 追问钩子：用户故意改本机时间薅羊毛，前端能防住吗？

```javascript
function timeChaos({ offsetMs = 0, tz = 'Asia/Shanghai' } = {}) {
  const RealDate = Date;
  class FakeDate extends RealDate {
    constructor(...args) {
      super(...(args.length ? args : [RealDate.now() + offsetMs]));
    }
    static now() { return RealDate.now() + offsetMs; }
  }
  window.Date = FakeDate;
  return () => { window.Date = RealDate; };
}
// 场景：时间前进一天，验证优惠券过期逻辑
const restore = timeChaos({ offsetMs: 86400000 });
```
