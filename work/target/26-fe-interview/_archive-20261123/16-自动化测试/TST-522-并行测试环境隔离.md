## TST-522：大规模并行测试如何保证环境隔离

**答**：
- 结论：隔离三要素——数据命名空间、端口/进程、外部依赖 stub。每个 worker 分到唯一 ID，所有共享资源按 ID 加前缀或走独立实例。
- 做法：测试数据用 tenantId/runId 前缀隔离；浏览器 context 每用例独立；后端用容器或 Mock Server 按 worker 路由；用完即清理并登记。
- 追问钩子：第三方共享账号被并行测试改崩怎么办？——把第三方彻底 stub 掉（契约测试保证行为一致），或用账号池 + 租借锁，禁止多 worker 复用同一账号。

```javascript
// 并行隔离：为每个 worker 生成唯一命名空间，所有资源带上前缀
function namespaceFor(runId, workerIdx) {
  const ns = `t_${runId}_w${workerIdx}`;
  return {
    dbSchema: ns,
    email: `${ns}@test.example.com`,
    redisKey: p => `${ns}:${p}`,
    cleanup: keys => keys.forEach(k => console.log('delete', ns + ':' + k)),
  };
}
const ns = namespaceFor('R123', 2);
console.log(ns.redisKey('cart'), ns.email);
```
