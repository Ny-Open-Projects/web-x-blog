## TST-959：同一份数据在开发/测试/预发三套环境脱敏结果不一致，怎么保证「一处脱敏处处一致」？
**答**：
- 结论：把脱敏规则集中成「单一配置源」（版本化的规则文件/中心化服务），各环境引用同一版本，禁止各自硬编码。
- 做法：规则文件进 Git 并打版本；数据管道启动时拉取规则版本并记录；校验三环境对同一输入的脱敏输出一致性。
- 变更：规则升级需评审 + 全环境同步灰度，避免测试环境先变导致联调错乱。
- 追问钩子：测试环境用了新规则、预发还是旧规则，导致同一手机号两处脱敏值不同，你怎么在联调前发现？

```javascript
const RULE_VERSION = 'v3';
const rules = loadRules(RULE_VERSION); // 单一配置源
function mask(value) { return applyRules(value, rules); }
function applyRules() { return 'masked'; }
function loadRules() { return []; }
// 一致性校验：对同一批样本，三环境输出必须相同
function checkConsistency(envOutputs) {
  const base = JSON.stringify(envOutputs.dev);
  const diffs = Object.entries(envOutputs).filter(([, v]) => JSON.stringify(v) !== base);
  return { consistent: diffs.length === 0, diffs: diffs.map(([env]) => env) };
}
console.log(checkConsistency({
  dev: ['m1', 'm2'], test: ['m1', 'm2'], staging: ['m1', 'OLD'],
})); // { consistent:false, diffs:['staging'] } → 联调前拦截
```
