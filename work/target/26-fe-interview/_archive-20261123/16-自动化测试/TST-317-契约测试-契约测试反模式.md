## TST-317：契约测试的常见反模式有哪些？
**答**：
- consumer 契约写得太宽（like 万物）→ 测不出破坏；太严（exact 全字段）→ 脆弱。
- provider states 状态准备造假数据与真实不符 → 验证通过但联调仍崩。
- 契约只测 happy path——错误契约（4xx/5xx）缺失。
- broker 无人维护（契约过期不清理），验证集合越来越脏。

```javascript
// 反例：过宽
.willRespondWith({ body: like({ data: eachLike(anything()) }) })   // 什么都过
// 正例：结构关键 + 值域宽松
.willRespondWith({ body: like({ id: string('o1'), status: regex(/^(paid|pending)$/) }) })
```
