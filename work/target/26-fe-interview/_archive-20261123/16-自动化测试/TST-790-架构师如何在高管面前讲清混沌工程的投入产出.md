## TST-790：架构师如何在高管面前讲清混沌工程的投入产出

**答**：
- 结论：用「风险语言」而非「技术语言」——把混沌工程翻译成「减少故障损失」的保险，用事故成本与避免损失量化 ROI。
- 讲法：过去 N 次演练发现 X 个真实隐患，若发生在生产预计损失 Y，投入为 Z，ROI = (Y-Z)/Z。
- 强调「可控」：说明爆炸半径、熔断、审批机制，打消「引入风险」的顾虑。
- 追问钩子：高管说「直接多买几台服务器不就行了」，如何回应？

```javascript
// 混沌工程 ROI 估算（面向高管的语言）
function chaosROI({ drills, bugsFound, avgLossAvoided, cost }) {
  const avoided = bugsFound * avgLossAvoided;
  const roi = cost > 0 ? +((avoided - cost) / cost * 100).toFixed(0) : 0;
  return {
    drills, bugsFound,
    avoided: `约 ${avoided} 万潜在损失`,
    roi: `${roi}%`,
    pitch: `每次演练平均发现 ${(bugsFound / (drills || 1)).toFixed(1)} 个隐患`,
  };
}
console.log(chaosROI({ drills: 20, bugsFound: 6, avgLossAvoided: 50, cost: 100 }));
```
