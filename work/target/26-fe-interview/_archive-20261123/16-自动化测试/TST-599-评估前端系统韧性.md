## TST-599：如何评估前端系统的整体韧性

**答**：
- 结论：从「抗扰动能力（故障下稳态保持）+ 恢复能力（MTTR）+ 降级体验（核心任务可完成）+ 可观测性（问题可发现）」四方面综合评估，用混沌实验与线上数据共同验证。
- 做法：建立韧性场景矩阵并定期跑，产出韧性分趋势；结合线上真实故障复盘看预案是否有效；把韧性纳入架构评审（如新增依赖需有降级方案）。
- 追问钩子：韧性做得好是否意味着零故障？——不是；韧性承认故障必然发生，目标是「故障时用户可感知影响最小、恢复最快」，而非追求绝对不出错。

```javascript
// 韧性四维评估
function resilienceProfile(m) {
  const dims = {
    resistance: m.steadyHeldRate,                 // 抗扰动
    recovery: Math.max(0, 1 - m.mttrMs / 60000), // 恢复速度
    degradation: m.coreTaskSuccessRate,           // 降级体验
    observable: m.alertCoverage,                  // 可观测
  };
  const overall = +(Object.values(dims).reduce((a, b) => a + b, 0) / 4).toFixed(3);
  return { dims, overall };
}
```
