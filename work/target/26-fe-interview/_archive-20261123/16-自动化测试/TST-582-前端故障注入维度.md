## TST-582：前端故障注入有哪些维度

**答**：
- 结论：四大维度——网络（延迟/丢包/断网/慢 DNS）、渲染与主线程（长任务/内存压力/OOM）、状态与数据（接口 500/脏数据/超时）、依赖（第三方 SDK/CDN/字体失败）。
- 做法：网络用 CDP/Fiddler；渲染用 CPU 节流与脚本阻塞；接口用 Mock 注入错误响应；依赖用拦截请求模拟第三方挂掉。
- 追问钩子：哪些故障不该注入生产？——破坏性故障（删数据/OOM/全断网）只在测试环境；生产只做只读探针或极小爆炸半径的验证，且必须有熔断。

```javascript
// 故障注入类型注册表
const FAULTS = {
  'net-latency': p => ({ latency: p.ms }),
  'net-offline': () => ({ offline: true }),
  'api-500':     () => ({ status: 500 }),
  'cpu-throttle':p => ({ rate: p.rate }),
  'third-party-down': () => ({ block: /cdn\.thirdparty\.com/ }),
};
function injectFault(type, params) {
  const build = FAULTS[type];
  if (!build) throw new Error(`未知故障: ${type}`);
  return build(params);
}
```
