## TST-849：前端依赖供应链安全：如何自动化检测恶意/漏洞依赖？
**答**：
- 结论：供应链安全要「锁版本 + 查漏洞 + 验来源 + 控更新」——用 lockfile 固定依赖，CI 扫描 CVE，限制安装脚本，升级走审查。
- 检测手段：npm audit / osv-scanner 扫 lockfile 中的已知漏洞；检查依赖来源是否为官方 registry；警惕 typosquatting（拼写仿冒包）。
- 安装期防护：禁用/审查 postinstall 脚本（恶意代码高发区），用 --ignore-scripts + 白名单；最小化依赖树。
- 持续监控：Dependabot/Renovate 自动提升级 PR，SLA 内修复高危漏洞；SBOM 记录依赖清单便于追溯。
- 追问钩子：一个「好用但很久没维护」的依赖被报中危漏洞，你如何决策修还是换？

```javascript
// 依赖安全检查：漏洞等级门禁 + 安装脚本审查
function auditDependencies(auditReport, packageJson) {
  const high = (auditReport.vulnerabilities || []).filter(v => v.severity === 'high' || v.severity === 'critical');
  const scripts = packageJson.scripts || {};
  const riskyHooks = ['postinstall', 'preinstall'].filter(h => scripts[h]);
  return {
    blockRelease: high.length > 0,
    highCount: high.length,
    riskyHooks, // 需人工审查
    advice: riskyHooks.length ? '审查安装脚本后再安装' : '无高风险钩子',
  };
}
console.log(auditDependencies({ vulnerabilities: [{ severity: 'critical' }] },
  { scripts: { postinstall: 'node setup.js' } }));
```
