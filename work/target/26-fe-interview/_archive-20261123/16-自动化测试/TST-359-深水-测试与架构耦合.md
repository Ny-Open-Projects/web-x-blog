## TST-359：测试如何反向约束架构（可测性设计）？
**答**：
- 架构规则测试化：分层依赖/模块边界写成测试（arch-test），违规即红——架构约束自动化。
- 可测性设计模式：副作用边界注入（DI）、纯函数核心——测试写不动说明架构有问题。
- 新模块准入：模块模板内置测试骨架（强制可测起点）。
- 架构测试进 CI：eslint-boundaries + 自定义依赖图断言双保险。

```javascript
// 架构规则测试
import { validateDependency } from './arch-rules';
test('分层依赖', () => {
  expect(validateDependency('ui/Price.tsx', 'dal/order.ts')).toBe(false); // ui 不许直连 dal
});
```
