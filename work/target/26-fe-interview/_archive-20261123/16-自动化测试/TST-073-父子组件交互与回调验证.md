## TST-073：父子组件交互怎么测？回调验证与集成粒度怎么把握？
**答**：
- 两种粒度：① 隔离测子组件——mock 回调（vi.fn）断言「事件发生时回调参数正确」，纯契约测试；② 轻集成测父子——父组件传真实现，断言「点击子组件按钮后父组件 UI 发生变化」，验证接线（props 名、事件名）正确。
- 粒度把握：子组件本身有自己的测试文件（回调契约）；父组件测试只关心「接线后的可见结果」，不重复子组件内部行为断言——重复会让重构成本翻倍。
- 回调验证三件套：toHaveBeenCalled、参数结构 toHaveBeenCalledWith、调用次数 toHaveBeenCalledTimes（防重复触发）。
- 反模式：在父组件测试里断言子的内部 state——戳不进去也戳不该戳；用「父组件 UI 结果」作为断言面。

```jsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';
import CartPage from './CartPage';      // 父：持有 count state
import Counter from './Counter';        // 子：+/- 按钮，onChange 回调

describe('Counter 子组件契约（隔离）', () => {
  it('点击 + 时回调 onChange(1)', async () => {
    const user = userEvent.setup();
    const onChange = vi.fn();
    render(<Counter value={0} onChange={onChange} />);
    await user.click(screen.getByRole('button', { name: '+' }));
    expect(onChange).toHaveBeenCalledWith(1);
  });
});

describe('CartPage 接线（轻集成）', () => {
  it('点击子组件 + 后父组件数量文案更新', async () => {
    const user = userEvent.setup();
    render(<CartPage />);              // 父传真实现
    await user.click(screen.getByRole('button', { name: '+' }));
    expect(screen.getByText('数量：1')).toBeInTheDocument();   // 断言父的可见结果
  });
});
```
