## TST-119：常见的测试反模式有哪些？怎么识别和纠正？
**答**：
- 时序类：`sleep(500)` 硬等待（改成条件等待 `findBy`/auto-wait）；依赖执行顺序（每个用例自造数据）；用例间共享可变状态（beforeEach 重置）。
- 实现类：测内部 state/调用次数而非行为（改成断言用户可见结果）；选择器绑死 CSS class（改 getByRole/testid）；过度 mock 连被测逻辑都 mock 掉（mock 收敛到网络/时间/随机三类）。
- 断言类：无断言或 `toBeDefined()` 刷覆盖率（断言具体值）；巨断言一次比 20 个字段（拆成多条、失败信息才可读）；快照滥用不看内容（改关键断言 + 快照兜底）。
- 结构类：巨型 beforeEach 上帝夹具（每个用例只 setup 自己需要的）；复制粘贴测试体（参数化 test.each 或工厂函数）；测试里有 if/try 逻辑（测试代码不该有分支，一个用例一条路径）。
- 识别手段：Code Review 清单 + ESLint 自定义规则（禁 `await sleep`）+ flaky 率榜单 + 变异测试抽查；改测试导致不该挂的挂 = 测了实现。
- 追问钩子：为什么说「测试代码不能有逻辑」？——分支让测试路径不可预测，挂了看不懂；多分支 = 多个用例。

```javascript
// 反模式 → 纠正对照表（白板可写）
const anti = [
  ['await new Promise(r => setTimeout(r, 500))', 'await screen.findByText(...) / expect(...).toHaveText'],
  ['expect(spy).toHaveBeenCalled()',            'expect(result).toEqual(...) // 行为优先'],
  ['.btn-primary.btn-lg:nth-child(2)',          "getByRole('button', { name: '提交' })"],
  ['test 里 if (xxx) { assertA } else { assertB }', '拆成两个 test'],
  ['expect(true).toBe(true) // 凑覆盖率',        '删掉或补真实断言'],
  ['beforeEach: 造 10 个共享对象',               'fixture 工厂按需造、teardown 清理'],
];
```
