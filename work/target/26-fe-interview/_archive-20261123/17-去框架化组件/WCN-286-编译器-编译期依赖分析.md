## WCN-286：编译期响应式依赖分析的能力边界（哪些模式分析不了）？
**答**：
- 能分析：直接调用、属性读取、模板表达式——静态可见的信号读取。
- 分析不了：间接调用（数组 map 里闭包传信号函数）、动态属性访问、跨模块 re-export 的读取。
- 兜底：运行时依赖收集（编译器对「不确定表达式」生成 track 包裹代码）。
- 工程规范：导出响应式值时避免重命名/包装（文档约定），丢响应 lint 提示。

```javascript
// 编译期分析不了的形态
const getters = [() => count()];      // 闭包收集：运行时兜底 track
const { val } = someObj;              // 解构丢响应：编译器警告
function Wrapper(fn) { return fn(); } // 间接调用：黑名单
r
```
