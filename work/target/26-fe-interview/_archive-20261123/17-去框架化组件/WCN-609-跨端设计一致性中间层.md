## WCN-609：Web Components 能否作为 Web/iOS/Android 三端设计一致的中间层？利弊如何？

**答**：
- 结论：WC 适合做「设计语言的 Web 端载体 + 跨端契约源」，但不能直接跑在原生端，需与 React Native/Flutter 共享 token 与组件规范。
- 落地：token 用 JSON 作为单一数据源，Web 端由 WC 消费生成 CSS 变量，原生端由脚本生成对应样式代码；交互规范用文档 + 截图测试对齐。
- 追问钩子：为什么不直接上 Flutter？考察对「团队技术栈现状 + 增量收益」的权衡——原生端改造成本高时，先统一 token 是性价比最高的切入点。

```javascript
// 单一 token 源，驱动多端产出
const tokens = { color: { primary: '#165DFF' }, radius: { md: '8px' } };
function toCssVars(t) {
  return Object.entries(t).flatMap(([g, m]) =>
    Object.entries(m).map(([k, v]) => `--ds-${g}-${k}:${v};`)
  ).join('');
}
function toDart(t) { // 原生端生成（示意）
  return `class DsColor{static const primary=Color(0xFF${t.color.primary.slice(1)});}`;
}
console.log(toCssVars(tokens)); // Web 注入 :root
console.log(toDart(tokens));    // Flutter 端生成常量
```
