## WCN-120：WCN 跨框架复用的成本收益模型是什么？什么情况下不该用？

**答**：
- 成本清单：桥接层（React18 包装/Vue 适配）、类型与文档基建、SSR 管线改造（DSD）、影子树调试成本、团队 WC 认知培训；一次性投入约占组件开发成本的 30~50%。
- 收益条件：复用宿主数 ≥2、组件生命周期长（设计系统级）、跨技术栈分布稳定；此时摊销后净收益为正。
- 不该用的信号：① 只有 1~2 个消费方且同框架（直接源码复用）；② 高频迭代期的业务组件（桥接层拖慢迭代）；③ 深度依赖宿主框架生态（React Query/Router context）的组件——桥接复杂度爆炸。
- 混合策略：设计系统基础层（Button/Table/Icon）用 WCN，业务组合层留在各框架——"去框架化"只做在稳定边界上。
- 度量：以"重复实现数 × 单组件成本"对比"基建投入 + 单 WC 成本"，用真实组件数做敏感性分析，别拍脑袋上。

```text
决策矩阵（示例口径）
┌──────────────┬───────────┬───────────┐
│              │ ≥2 技术栈  │ 单框架     │
├──────────────┼───────────┼───────────┤
│ 设计系统组件  │ WCN ✅     │ 框架组件   │
│ 业务高频迭代  │ WCN ⚠️     │ 源码共享   │
│ 依赖框架生态  │ 包装层复用 │ 源码共享   │
└──────────────┴───────────┴───────────┘
```
