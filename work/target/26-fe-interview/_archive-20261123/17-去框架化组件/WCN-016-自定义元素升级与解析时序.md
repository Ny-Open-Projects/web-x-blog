## WCN-016：什么是自定义元素"升级"（upgrade）？HTML 解析与 define 时序会引发哪些坑？

**答**：
- 升级：`customElements.define` 注册之前文档里已存在的同名元素（unknown element），注册瞬间被逐个替换为元素实例并走完整生命周期，这就是 upgrade。
- 坑一：未升级元素是 `HTMLElement` 实例，读写自定义 property 会先落在普通对象上，升级时浏览器会把这些"early value"搬运到新实例（属性升级机制），但 getter/setter 对象（如复杂对象属性）可能丢失——所以惯例是在 constructor 里定义 property 默认值。
- 坑二：解析 HTML 时，`connectedCallback` 触发时子元素可能尚未解析完（元素先闭合子后到），操作 children 要用微任务/`queueMicrotask` 推迟。
- 坑三：`define` 重复注册同名会抛 NotSupportedError，社区懒加载方案用 `customElements.get()` 判断或 `whenDefined()` 等待。
- 坑四：`document.write`/innerHTML 动态插入后元素立即升级（同步），但 constructor 里的抛错会导致浏览器标记该定义无效并跳过升级。

```javascript
// 坑二示例：connectedCallback 里子节点未就绪
class NavList extends HTMLElement {
  connectedCallback() {
    // 此时 this.children 可能是空的（解析顺序：本标签先出现）
    queueMicrotask(() => {
      const items = this.querySelectorAll('nav-item');
      console.log('子项数量:', items.length); // 稳定正确
      this.#bind(items);
    });
  }
  #bind(items) { /* ... */ }
}
customElements.define('nav-list', NavList);

// 坑三示例：懒 define 守卫
async function lazyDefine(tag, loader) {
  if (!customElements.get(tag)) {
    customElements.define(tag, (await loader()).default);
  }
}
lazyDefine('heavy-chart', () => import('./heavy-chart.js'));
```
