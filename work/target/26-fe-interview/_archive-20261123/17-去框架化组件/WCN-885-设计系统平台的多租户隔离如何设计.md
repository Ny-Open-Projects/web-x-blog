## WCN-885：设计系统平台的「多租户隔离」如何设计？

**答**：
- 结论先行：设计系统作为内部平台服务多个 BU/品牌时，要做到「共享底座 + 隔离定制」——组件实现共享，但 token/主题/品牌配置/数据按租户隔离，避免互相污染。
- 隔离维度：① 主题隔离——每个租户有自己的 token 主题（CSS 变量命名空间/`:root` 作用域），切换不串味；② 数据隔离——租户的组件使用数据、定制配置分开存储；③ 权限隔离——租户只能改自己的主题与配置，不能动平台核心组件。
- 技术实现：token 用命名空间前缀（如 `--tenantA-primary`）或运行时注入到独立 DOM scope；主题样式表用 `adoptedStyleSheets` 按租户管理；构建时可做「按租户的差异化产物」（共享组件 + 租户 token 包）。
- 数据层：多租户数据库加 tenant_id 隔离，查询强制带租户条件；缓存 key 含租户 id，防止跨租户数据泄漏。
- 边界：不是所有东西都要隔离——组件代码、基础 token（如间距刻度）应该共享以获得规模效应；只隔离「品牌相关」与「租户私有」部分。
- 追问钩子：面试官会问「一个租户把主题改崩了会影响别人吗」——答：主题以数据形式隔离注入，且上架/保存时校验（对比度、schema），问题主题只影响该租户；平台可一键回退到默认主题。

```javascript
// 多租户主题隔离：命名空间 token + 按租户注入
function tenantThemeCSS(tenant, tokens) {
  const prefix = `--${tenant}-`;
  return `:root { ${Object.entries(tokens).map(([k, v]) => `${prefix}${k}: ${v};`).join(';')} }`;
}
const themes = {
  tenantA: { primary: '#06c', bg: '#fff' },
  tenantB: { primary: '#e00', bg: '#000' },
};
console.log(tenantThemeCSS('tenantA', themes.tenantA));
// 组件读取时用 var(--tenantA-primary)，由当前上下文的租户决定前缀
```
