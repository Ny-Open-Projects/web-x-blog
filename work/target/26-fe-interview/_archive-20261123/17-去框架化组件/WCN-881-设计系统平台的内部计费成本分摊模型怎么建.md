## WCN-881：设计系统平台的「内部计费 / 成本分摊」模型怎么建？

**答**：
- 结论先行：与通用组件平台类似，设计系统的成本分摊目的是「让使用方感知成本、让平台有投入依据」——但设计系统有独特成本项（设计人力、设计工具许可、视觉回归基建），要单独计量。
- 成本构成：设计师与工程师人力、Figma/设计工具许可、视觉回归与文档基建、a11y 审计、跨品牌主题维护——先算清总成本，再选分摊口径。
- 分摊口径：按消费方「引用的组件数/调用量」、按 BU 规模、按「定制需求量」（提了专属组件/主题定制的业务多分摊）；关键是口径能引导正确行为（如鼓励复用而非重复定制）。
- 计费方式：设「基础额度（平台预算兜底）+ 超额按量」——保证小团队敢用，大用量方多承担；账单透明可下钻到「哪个业务用了哪些组件/定制」。
- 与价值挂钩：计费要和「节省的成本」对照展示——用了平台省了多少重复设计与开发工时，让业务方觉得「花得值」而非「被收费」。
- 追问钩子：面试官会问「计费会不会让业务方绕开平台自己造轮子」——答：配合治理红线（自研组件也要过平台门禁/a11y 审计）和「用平台单价明显低于自建」的经济性，用引导而非强压。

```javascript
// 设计系统成本分摊：基础额度 + 超额按量，并展示节省价值
function allocateCost({ teams, totalCost, freeQuota = 1000 }) {
  const totalUsage = teams.reduce((s, t) => s + t.usage, 0);
  const billable = Math.max(totalUsage - freeQuota * teams.length, 0);
  return teams.map(t => {
    const share = billable ? (t.usage / totalUsage) * totalCost : 0;
    return { team: t.name, usage: t.usage, cost: +share.toFixed(0),
             savedHours: t.usage * 0.5 }; // 每千次调用约省 0.5 工时（示意）
  });
}
console.log(allocateCost({ totalCost: 100000, teams: [
  { name: '交易', usage: 5000 }, { name: '营销', usage: 2000 },
] }));
```
