## WCN-128：编译期响应式与运行时响应式各有什么优劣势？

**答**：
- 编译期路线（Svelte 4 式 invalidate、Astro 模板）：零运行时追踪开销、包体最小、代码即依赖图（可静态分析）；但依赖静态——动态分支/深层数据表达受限，跨模块共享状态难。
- 运行时路线（Solid/Vue/Svelte 5 signals）：依赖动态收集（分支内读取才算）、深层 proxy 响应、跨组件 store 自然；代价是每帧追踪开销与内存（订阅集合）。
- 实际趋同：主流都走"编译器定位更新点 + 运行时信号追踪"的混合（Svelte 5、Vue Vapor、Qwik）——纯编译期已少见。
- 边界判断：更新点是否可以在编译时静态确定？模板（结构稳定）可以；任意 JS 控制流不可以——这就是 JSX（任意表达式）更依赖运行时追踪、模板 DSL 更能编译的原因。
- 对 WCN 的启示：WCN 用 Signals（运行时）最兼容任意实现方式；若选 Lit（运行时模板缓存）还是编译方案（如 Solid 自定义元素）取决于团队工具链。

```javascript
// 边界示例：编译期无法确定依赖
function render(flag) {
  if (flag) show(a()); else show(b());  // a/b 是否是依赖取决于 flag 运行时值
}
// 运行时追踪：走到哪个分支追踪哪个 —— 天然正确
// 编译期 invalidate：只能保守地把 a、b 都标记为潜在依赖（过度失效）
```
