## WCN-859：编译时如何做安全审计：防止模板注入与 XSS？

**答**：
- 结论先行：编译期是拦截 XSS 的最佳时机——编译器知道哪些插值进入「HTML 上下文」、哪些进入「属性上下文」，可以在生成代码时自动插入正确的转义，把安全从「靠开发者记得」变成「默认安全」。
- 上下文感知转义：编译产物根据插入位置选择转义策略——文本节点用文本转义、属性用属性转义、URL 属性（href/src）做协议白名单校验、`style` 属性特殊处理；Vue 的 `v-html`、React 的 `dangerouslySetInnerHTML` 是显式「逃逸舱」，要重点审计。
- 静态分析拦截：识别危险模式——模板里直接拼接用户输入到 `innerHTML`、动态构造脚本、未净化的 `srcdoc`、可执行的 `javascript:` URL；编译期报错或警告。
- 与 Trusted Types/CSP 配合：编译产物统一走 `textContent` 而非 `innerHTML`，配合 Trusted Types 策略与 CSP，形成多层防御。
- 边界：编译期只能审计「静态结构」，运行时拼接的字符串仍需运行时防护（如 DOMPurify）；审计规则要避免误报（合法富文本场景走显式净化流程）。
- 追问钩子：面试官会问「编译期转义会不会双重转义」——答：编译器对每个插值只转义一次并标记「已处理」，上下文明确就不会双重转义；难点在「一个值进入多个上下文」时要分别处理。

```javascript
// 编译期上下文感知转义：生成绑定时按上下文选转义函数
const ESCAPERS = {
  text: (v) => String(v).replace(/[&<>]/g, c => ({ '&':'&amp;', '<':'&lt;', '>':'&gt;' }[c])),
  attr: (v) => String(v).replace(/["&<]/g, c => ({ '"':'&quot;', '&':'&amp;', '<':'&lt;' }[c])),
  url: (v) => /^(https?:|\/|#|mailto:)/i.test(String(v)) ? v : 'about:blank', // 协议白名单
};
function emitBinding(interp) {
  const esc = ESCAPERS[interp.context] || ESCAPERS.text;
  if (interp.rawHtml) return `/* 危险：需 DOMPurify */ sanitize(${interp.expr})`;
  return `setText(${esc.name}, () => ${interp.expr})`; // 生成带转义的绑定代码
}
console.log(emitBinding({ context: 'text', expr: 'userInput' }));
console.log(emitBinding({ context: 'url', expr: 'link' }));
```
