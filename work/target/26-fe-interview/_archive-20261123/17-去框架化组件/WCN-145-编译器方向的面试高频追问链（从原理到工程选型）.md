## WCN-145：编译器方向的面试高频追问链：原理题如何引申到工程选型？

**答**：
- 追问链示例：`Vue 的静态提升是什么` → `block 树为什么把 diff 变成 O(动态节点)` → `Vapor 连 vnode 都不要了，SSR 水合怎么办` → `如果让你给老项目接 Vapor，第一步做什么`（迁移成本评估）→ `编译器 bug 如何兜底`（escape hatch + sourcemap 测试）。
- 回答框架：每层从"机制 → 收益 → 成本 → 工程约束"四点收束，避免只背概念。
- 高频组合题：给出一个渲染性能 Profile（长列表 diff 占 40%），让你选方案——优先判断"更新粒度"还是"diff 跳过"是瓶颈，再对应选 signals（Solid/Vapor）或编译缓存（React Compiler）。
- 反向追问：编译器方案对"动态运行时逻辑"（任意 JS 构造组件树）支持有限——回答要主动暴露限制，显示工程判断力。
- 准备建议：把 WCN-121~144 的 20+ 张卡串成 3 条主线（更新粒度、SSR 成本、工具链成本），每条主线练一版 2 分钟电梯陈述。

```text
面试追问地图（节选）
原理层：静态提升 → patchFlag → block 树 → vapor 无 vnode
成本层：水合成本 → resumability → 切片粒度
工程层：渐进迁移 → 双模式测试 → escape hatch → devtools 适配
```
