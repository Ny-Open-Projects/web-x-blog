## WCN-575：编译响应式性能优化：编译耗时过长（大型项目冷编译 30s+）如何定位与加速？

**答**：
- 结论：先分阶段计时（parse/transform/codegen/minify）定位瓶颈，再针对性优化——多数耗时在 transform 的重复遍历。
- 加速手段：单趟遍历合并多插件、增量编译（只重编变更文件）、缓存 AST 与类型信息、并行编译。
- 持久化缓存跨构建复用（如 turborepo / 自研 cache key = 内容 hash）。
- 追问：如何避免「缓存失效风暴」？（答：细粒度依赖追踪 + 内容寻址，改动一个文件只失效受影响图）

```javascript
function profile(build) {
  const t = {}; let prev = performance.now();
  const mark = name => { const now = performance.now(); t[name] = (t[name] || 0) + now - prev; prev = now; };
  build(mark);
  return t;
}
const costs = profile(mark => {
  mark('start'); parseAll(mark); mark('transform'); generateAll(mark); mark('minify'); mark('end');
});
// 找出最大耗时阶段
const hotspot = Object.entries(costs).sort((a,b)=>b[1]-a[1])[0];
```
