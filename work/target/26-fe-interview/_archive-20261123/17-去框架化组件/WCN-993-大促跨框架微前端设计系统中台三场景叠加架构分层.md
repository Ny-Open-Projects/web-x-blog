## WCN-993：大促 + 跨框架微前端 + 设计系统中台三场景叠加，架构怎么分层

**答**：
- 结论先行：三场景叠加要用「分层 + 边界」降维——把大促（性能/稳定性）、跨框架（复用/隔离）、设计系统（一致/治理）分配到不同架构层，避免相互污染。
- 分层：基座层（宿主/路由/主题 token 下发）→ 组件层（WC 原子 + 框架复合）→ 场景层（大促页按 islands 组织）→ 治理层（性能预算/a11y/灰度监控）。
- 边界：跨框架用 WC 做 DOM 边界、MF 共享依赖、iframe 隔离不可信；大促流量在场景层做降级开关（关非核心岛），不侵入组件层。
- 一致性：token 单一数据源贯穿基座与组件，主题按租户作用域隔离；版本由基座统一协商提升，避免多版本共存冲突。
- 追问钩子：面试官问「三层都要改时怎么排期」——答：先定协议与 token（基座），再组件适配，最后场景接入；协议稳定后各层可并行，避免返工。

```javascript
// 叠加场景的分层配置
const arch = {
  base: { theme: 'tenant-scoped tokens', router: 'host-owned' },
  component: { atoms: 'Web Components', composites: 'framework-native' },
  scene: { '大促页': 'islands + 降级开关', '普通页': '按需水合' },
  governance: { perfBudget: true, a11yGate: true, canary: true },
};
function degradeForPeak(arch) {
  arch.scene['大促页'] = '只水合核心岛，关动画'; // 场景层降级，不动组件层
  return arch.scene['大促页'];
}
console.log(degradeForPeak(arch));
```
