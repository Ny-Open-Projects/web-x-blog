## WCN-877：公司收购合并两个品牌，设计系统如何做「品牌归一」？

**答**：
- 结论先行：品牌归一的本质是把「两套 token + 两套组件」收敛成「一套组件 + 多品牌 token 主题」——先统一组件实现与契约，品牌差异只体现在 token 层，避免维护两套组件代码。
- 阶段一盘点：对比两品牌的 token（颜色/字体/间距/圆角）、组件清单与 API 差异，建立「映射表」——哪些 token 等价、哪些组件功能重叠、哪些是品牌独有。
- 阶段二统一底座：选一套组件实现为标准（或合并优点），把两品牌差异抽象成「主题（theme）」——同一组件在不同主题下换 token 即可；独有组件先作为品牌专属保留。
- 阶段三渐进迁移：按品牌/业务线分批切到新主题，用视觉回归保证一致性；旧品牌主题保留过渡期后下线。
- 组织难点：设计师与业务方对「谁的规范为准」有争议——要靠高层的品牌战略决策 + 数据（哪个品牌是主品牌）定方向，而非技术投票。
- 追问钩子：面试官会问「两个品牌的按钮形状完全不同怎么办」——答：形状是 token 能覆盖的（border-radius 等）；若交互行为都不同（如一个圆形 icon 按钮有不同状态机），就抽象成「组件的 variant/配置」或标记为品牌专属组件，别硬塞进一个组件。

```javascript
// 品牌归一：统一组件 + 多主题 token，差异只在 token 层
const baseComponents = ['button', 'input', 'card', 'table'];
const themeMap = {
  brandA: { '--color-primary': '#06c', '--radius': '4px', '--font': 'Inter' },
  brandB: { '--color-primary': '#e00', '--radius': '20px', '--font': 'Roboto' },
};
function renderTokenCSS(themeName, themes = themeMap) {
  const tokens = themes[themeName];
  if (!tokens) throw new Error(`未知主题 ${themeName}`);
  return `:root { ${Object.entries(tokens).map(([k, v]) => `${k}:${v}`).join(';')} }`;
}
// 同一套组件，注入不同主题即可切换品牌外观
console.log(renderTokenCSS('brandA'));
console.log(renderTokenCSS('brandB'));
```
