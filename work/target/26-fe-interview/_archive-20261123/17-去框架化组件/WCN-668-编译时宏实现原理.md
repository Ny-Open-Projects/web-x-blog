## WCN-668：编译时宏（如 defineProps / defineEmits）是如何工作的？为什么必须在编译期处理？

**答**：
- 结论：宏是「编译器的语法糖指令」——编译器在 AST 阶段识别宏调用，提取信息（props 类型/事件名）并生成对应运行时代码，宏本身不会出现在产物中。
- 为什么编译期：props 类型要在编译期确定才能生成类型声明与运行时校验；宏依赖 SFC 上下文（无法在普通函数运行时获取）。
- 追问钩子：为什么宏不能运行时调用？因为它需要「声明式」信息供类型系统消费——考察对「编译期信息 vs 运行时值」的理解。

```javascript
// 源码 SFC：<script setup> const props = defineProps({ id: Number }) </script>
// 编译器识别 defineProps 调用并提取声明
function compileScript(src) {
  const m = src.match(/defineProps\s*\(([^)]+)\)/);
  if (!m) return src;
  const schema = m[1]; // '{ id: Number }'
  // 生成运行时代码 + 类型信息（供 IDE）
  return `const __propsSchema = ${schema};
const props = __resolveProps(__propsSchema);`;
}
console.log(compileScript('const props = defineProps({ id: Number })'));
// 产物中已无 defineProps 调用 —— 纯编译期展开
```
