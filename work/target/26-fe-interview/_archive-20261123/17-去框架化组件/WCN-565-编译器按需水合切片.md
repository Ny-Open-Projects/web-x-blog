## WCN-565：编译器「按需水合」：如何根据交互优先级把组件拆成不同水合时机的 chunk？

**答**：
- 结论：编译器给每个组件打「交互分」（事件数量、可见性、业务权重），按分档生成不同水合策略。
- 高分（首屏按钮/输入）立即水合；中分（视口内）idle 水合；低分（折叠区/页脚）交互时水合。
- 每个策略对应一个 chunk，配合 islands 边界，避免整页一次性水合。
- 追问：如何避免「用户点了但还没水合」？（答：注册前交互意图暂存，水合后回放——事件代理 + 意图队列）

```javascript
function hydrationRank(comp) {
  const score = comp.events * 3 + (comp.aboveFold ? 5 : 0) + (comp.businessWeight || 0);
  return score >= 10 ? 'eager' : score >= 5 ? 'idle' : 'on-interaction';
}
function planChunks(tree) {
  const groups = { eager: [], idle: [], 'on-interaction': [] };
  walk(tree, c => groups[hydrationRank(c)].push(c.id));
  return Object.fromEntries(Object.entries(groups).map(([k, ids]) => [k, `chunk-${k}.js`]));
}
```
