## WCN-571：编译器「自定义指令 / 宏」的扩展机制：如何让业务方注册编译期转换插件？

**答**：
- 结论：暴露插件 API（visitor 注册 + 顺序执行），插件在 AST 各阶段（parse/transform/generate）插入转换。
- 每个插件声明 name、enforce（pre/normal/post）与 visitor（节点类型 → handler）。
- 执行时按 enforce 排序，插件间通过共享 context 传递元信息，冲突时报错。
- 追问：如何防止插件写出错误 AST？（答：转换后用 schema 校验节点结构，失败回滚该插件）

```javascript
function createCompiler(plugins = []) {
  const sorted = plugins.sort((a, b) => ({pre:0,normal:1,post:2}[a.enforce] - {pre:0,normal:1,post:2}[b.enforce]));
  function transform(ast, ctx) {
    for (const p of sorted) {
      const snapshot = structuredClone(ast);
      try { walk(ast, p.visitor, ctx); }
      catch (e) { console.error(`插件 ${p.name} 失败`, e); ast = snapshot; } // 回滚
    }
    return ast;
  }
  return { transform };
}
```
