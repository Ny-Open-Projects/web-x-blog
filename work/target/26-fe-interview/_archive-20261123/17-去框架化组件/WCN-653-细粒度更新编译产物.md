## WCN-653：Solid 风格「细粒度更新」的编译产物长什么样，相比 VDOM 省在哪？

**答**：
- 结论：编译产物把每个动态节点包进 effect/createEffect，数据变化时只执行对应 DOM 写操作，没有虚拟树创建与 diff。
- 机制：<div>{count()}</div> 编译为 effect(() => el.textContent = count())；静态节点直接创建一次。
- 追问钩子：为什么要 createEffect 包一层？为了把写操作登记为响应式副作用，从而自动追踪依赖——考察对「编译 + 运行时协作」的理解。

```javascript
// 模板： <div><span>静态</span><b>{count()}</b></div>
// 编译后（简化）：
function compiled(props) {
  const div = document.createElement('div');
  const span = document.createElement('span');
  span.textContent = '静态'; // 静态节点：只建一次
  const b = document.createElement('b');
  div.append(span, b);
  createEffect(() => {
    b.textContent = String(props.count()); // 动态节点：精准更新
  });
  return div;
}
// 对比 VDOM：每次 count 变都要重建整棵 vnode 树并 diff
```
