## WCN-147：设计系统去框架化的整体路线图：试点、基建、扩量三阶段怎么规划？

**答**：
- 阶段一（试点，2~4 周）：选 3~5 个无生态依赖组件（Button/Badge/Avatar/Tag），跑通"实现 → 类型生成 → React/Vue 双宿主接入 → SSR DSD → 视觉回归"全链路；产出 = 决策验证 + 基建清单。
- 阶段二（基建，4~8 周）：Monorepo 结构（tokens/core/adapters/docs）、manifest CI、灰度加载器、a11y 门禁；同时沉淀《WC 开发规范》（事件命名、token 契约、生命周期约定）。
- 阶段三（扩量，按季度）：复杂组件（Table/DatePicker）逐个迁移，每迁移一个更新 docs 与迁移指南；存量框架组件通过 adapters 复用 core 实现；建立废弃版本窗口（v1 与 v2 并存一个季度）。
- 度量指标：组件 WC 覆盖率、宿主接入成本（接入一个新项目的人日）、双版本共存期 bug 数、构建产物体积。
- 组织配套：组件平台团队维护 core，业务团队只消费 adapters；RFC 流程管理 API 变更。

```text
里程碑示例
M1（试点完成）：3 组件双宿主可用 + SSR 输出 DSD + CI 全绿
M2（基建完成）：manifest diff 门禁 + 灰度加载器 + 开发规范 v1
M3（扩量 50%）：Top20 组件 WC 化 + 2 个业务线全量接入 + 指标看板
```
