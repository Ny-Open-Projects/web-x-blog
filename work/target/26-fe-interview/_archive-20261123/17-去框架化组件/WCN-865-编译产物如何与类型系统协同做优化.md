## WCN-865：编译产物如何与「类型系统」协同做优化？

**答**：
- 结论先行：类型是编译器的「免费优化信息」——类型系统能告诉编译器变量的确切类型，从而做单态化、内联、去虚化、精确的属性访问，生成更快更小的代码；编译响应式里还能靠类型精确判断依赖。
- 优化场景：① 单态化（monomorphization）——泛型按具体类型生成专用代码，避免运行时装箱；② 去虚化——知道具体类型就把多态调用变成直接调用；③ 常量折叠——类型+字面量推导；④ 属性访问优化——知道对象形状（shape）可生成直接偏移访问；⑤ 死代码消除——类型收窄后某些分支不可能到达。
- 与去框架化场景结合：WC 的 attribute 是字符串，但类型信息能指导「该用哪种反序列化」（number/boolean/JSON）；组件的 property 类型声明能生成类型安全的包装器与校验代码。
- 边界：JS 是动态类型，类型信息可能不准（类型断言、any、外部输入）——优化要保守，运行时仍需兜底校验；过度单态化会导致代码膨胀（每个类型一份），要权衡。
- 追问钩子：面试官会问「类型擦除后运行时还有类型信息吗」——答：默认擦除（TS 类型不进运行时），要利用类型做优化就得让编译器「看着类型生成代码」（如利用类型生成专用绑定/校验），或运行时携带轻量类型标签（如 valibot/zod 的 schema）。

```javascript
// 用类型信息生成专用的 attribute 解析器（类型指导代码生成）
const schema = { count: 'number', disabled: 'boolean', config: 'json' };
function genParser(schema) {
  const lines = Object.entries(schema).map(([key, type]) => {
    const parse = { number: 'Number', boolean: "v => v !== 'false' && v !== null", json: 'JSON.parse' }[type];
    return `${key}: (v) => ${parse}(v)`;
  });
  return `({ ${lines.join(', ')} })`;
}
console.log(genParser(schema));
// 生成: ({ count: (v)=>Number(v), disabled: (v)=>v!=='false'&&v!==null, config: (v)=>JSON.parse(v) })
// 类型信息 → 专用、无运行时判断开销的解析代码
```
