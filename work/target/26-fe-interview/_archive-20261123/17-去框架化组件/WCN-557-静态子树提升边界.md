## WCN-557：编译时「静态子树提升」的边界：含 slot / 动态引用的子树为什么不能 hoist？

**答**：
- 结论：hoist 的前提是子树「完全静态」——无动态插值、无 slot 分发、无副作用引用、无组件实例。
- slot 内容来自父作用域，提升会固化分发结果，导致父更新时子树不更新。
- 动态引用（变量/信号）提升会捕获旧值，产生「卡住」的 bug。
- 追问：如何自动判定？（答：AST 遍历标记「动态锚点」，含锚点的祖先子树一律不 hoist）

```javascript
function canHoist(node) {
  if (node.hasDynamicBinding || node.hasSlot || node.hasComponent || node.hasSideEffect) return false;
  return (node.children || []).every(canHoist);
}
function markHoistable(ast) {
  return walk(ast, n => { n.hoistable = canHoist(n); return n; });
}
// <div>纯文本</div> -> hoistable
// <div>{name()}</div> -> 含动态绑定，不 hoist
// <div><slot/></div>  -> 含 slot，不 hoist
```
