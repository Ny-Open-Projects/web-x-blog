## WCN-572：「编译插件管线」的 AST visitor 注册、顺序执行与冲突检测怎么设计？

**答**：
- 结论：管线按 enforce 排序插件，依次用各自 visitor 遍历 AST；同一节点被多插件改写时检测冲突。
- visitor 用 { enter, leave } 钩子，enter 可改写节点，leave 做收尾。
- 冲突检测：节点记录 lastPlugin，若被不同插件二次改写则告警。
- 追问：插件如何声明式地「只处理某类节点」？（答：visitor 的 key 即节点 type，精确匹配）

```javascript
function runPlugins(ast, plugins, ctx) {
  const sorted = [...plugins].sort((a,b) => (a.enforce||'normal').localeCompare(b.enforce||'normal'));
  function walk(n, plugin) {
    const v = plugin.visitor[n.type];
    if (v?.enter) { if (n.__plugin && n.__plugin !== plugin.name) console.warn('冲突', n.type); v.enter(n, ctx); n.__plugin = plugin.name; }
    for (const c of n.children || []) walk(c, plugin);
    v?.leave?.(n, ctx);
  }
  for (const p of sorted) walk(ast, p);
  return ast;
}
const p1 = { name: 'macro', enforce: 'pre', visitor: { CallExpression: { enter(n) { n.macro = true; } } } };
```
