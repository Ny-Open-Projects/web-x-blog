## WCN-818：跨部门推动 WC 标准时，怎么做「利益相关方管理」？

**答**：
- 结论先行：技术标准推广是「组织问题」——先识别谁受益、谁受损、谁有话语权，再针对性沟通，别指望靠一封邮件统一思想。
- 识别与分类：用「权力-利益矩阵」把干系人分为四类——重点管理（高权力高利益，如架构委员会）、令其满意（高权力低利益，如 VP）、随时告知（低权力高利益，如一线开发）、监督（低权力低利益）；对不同类用不同策略。
- 找到赢家与输家：迁移会「受益」的（平台团队、追求效率的业务）发展为盟友；会「受损」的（维护旧组件库的团队、需要额外工作量的业务）要提前沟通并给补偿或退出路径。
- 争取赞助人（Sponsor）：需要有高层背书，在资源冲突与阻力出现时拍板；没有 Sponsor 的标准化运动基本推不动。
- 建立反馈闭环：让业务方参与标准制定（而非被通知），把他们的诉求纳入路线图，把「被推行者」变成「共建者」。
- 追问钩子：面试官会问「遇到一个实权部门的强烈反对怎么办」——答：先理解其真实顾虑（往往是工作量或话语权），通过让其主导某个子标准、给予署名与资源来转化，而不是硬碰硬或绕过。

```javascript
// 权力-利益矩阵：输出差异化的沟通策略
function stakeholderStrategy(power, interest) {
  if (power && interest) return '重点管理：深度参与决策，定期一对一';
  if (power && !interest) return '令其满意：简报 + 关键节点征询，别过度打扰';
  if (!power && interest) return '随时告知：文档站/Newsletter 保持透明';
  return '监督：最低成本覆盖，留意变化';
}
console.log(stakeholderStrategy(true, true));   // 重点管理
console.log(stakeholderStrategy(true, false));  // 令其满意
```
