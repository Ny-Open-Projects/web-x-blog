## RBL-390：构建系统决策记录（ADR）的实践

**答**:
- ADR 结构：背景（为什么决策）→ 选项对比（各选项利弊）→ 决策与理由 → 后果（代价与风险）→ 状态（proposed/accepted/superseded）——「为什么当时这么选」是新人最需要的信息
- 什么该写 ADR：不可逆/高成本/有争议的决策（工具选型/缓存架构/迁移策略）——写 ADR 有成本，琐碎决策不写
- 生命周期：决策被推翻时新 ADR 标记 superseded 旧 ADR（保留链）——决策历史是组织的记忆
- 位置与检索：ADR 目录（仓库内）+ 索引表 + 标签（工具/缓存/安全）——「这个决策当时怎么考虑的」10 秒内可查

```text
结构：背景 → 选项对比 → 决策+理由 → 后果 → 状态
标准：不可逆/高成本/有争议才写；推翻时 superseded 保留链
```
