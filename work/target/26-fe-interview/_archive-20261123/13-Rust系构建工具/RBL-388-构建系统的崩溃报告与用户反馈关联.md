## RBL-388：构建工具崩溃报告与用户环境的关联分析

**答**:
- 崩溃报告要素：错误类型/堆栈（符号化）+ 环境快照（OS/Node/工具版本/插件清单）+ 触发输入（脱敏的项目特征：模块数/配置摘要）——三要素缺一无法归因
- 聚类分析：崩溃按签名聚类（堆栈指纹）→ top 崩溃簇 → 版本关联（哪个版本引入）→ 修复优先级（影响面排序）
- 用户关联：崩溃 ↔ 用户环境交叉（如「windows+pnpm 用户崩溃率 5x」）——环境组合的系统性 bug 定位
- 反馈闭环：修复版本发布 → 崩溃率监控确认下降 → 用户通知（issue 回连）——闭环才有人愿意继续报

```text
三要素：堆栈符号化 + 环境快照 + 项目特征
分析：签名聚类 → 版本归因 → 环境交叉 → 修复优先级
闭环：修复 → 崩溃率确认 → 回连用户
```
