## RBL-864：场景题：发布前演练——预发环境产物验证与 CDN 预热

**答**:
- 发布前演练（staging）的价值窗口：1) **产物一致性**（staging 与 prod 的构建输入差异——环境变量注入 RBL-760 会让两者产物不同；验证「差异仅限预期环境字段」）；2) **全链路依赖**（staging 的后端 mock/真实依赖组合——mock 环境发现不了的生产 API 契约变化）；3) CDN 预热（RBL-693 预推在 staging 先演练一遍，验证配额与流程）。
- 一致性验证的方法：staging 与 prod 的「差异清单审计」（buildId 不同是必然，逐字段 diff：哪些差异是环境变量导致的预期项、哪些是意外）——意外差异（依赖版本不同：staging 忘了锁版本）是 staging 价值的核心发现。
- 预热的演练价值：CDN 预推脚本在 staging 跑通（配额报错/顺序错误提前暴露）；「预热报告」成为 prod 发布的输入（预热耗时预估发布窗口）。
- 演练的成本控制：staging 不是第二生产环境——「最小真实化」：真实 CDN/真实网关 + mock 后端——演练目标是「部署链路验证」不是「功能测试」（功能测试在 CI/预发功能环境）。
- 追问钩子：为什么「依赖版本锁」在 staging 阶段才暴露问题太晚？——staging 用了浮动版本（^x.y）而 prod 锁定，两者产物行为可能不同——这类差异应该在「构建输入清单」（attestation 的 lockHash RBL-773）就一致；演练阶段发现说明「输入一致性检查」缺失——左移原则：staging 演练是最后一道网而不是唯一一道。

```javascript
// staging/prod 产物差异审计
async function stagingAudit({ staging, prod, expectedEnvVars }) {
  const diffs = diffManifests(staging, prod);
  const unexpected = diffs.filter(d =>
    !(d.field.startsWith('env.') && expectedEnvVars.includes(d.field.split('.')[1])));
  if (unexpected.length)
    fail(`staging 与 prod 存在意外差异: ${unexpected.map(u => u.field)}——检查依赖锁定/配置注入`);
  // 预热演练
  const warmup = await cdn.pushBatch(staging.files, { dryRun: true, quota: 1000 });
  if (warmup.estimatedMinutes > 10)
    warn(`CDN 预热预计 ${warmup.estimatedMinutes} 分钟——prod 发布窗口需预留`);
  return { unexpected, warmup };
}
```
