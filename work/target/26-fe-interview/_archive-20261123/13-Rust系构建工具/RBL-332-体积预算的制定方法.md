## RBL-332：体积预算的制定方法

**答**:
- 预算三来源倒推：性能目标反推（LCP 目标 → 首屏 JS 预算 = 目标加载时间 × 4G 带宽 × 压缩率）、历史数据（当前 P50 体积 + 合理增幅）、竞品对标
- 预算结构：总量预算 + 分项预算（vendor/业务/懒加载 chunk 各自限额）——只有总量会转移矛盾（涨在懒加载 chunk 不报警）
- 维护节奏：预算随业务里程碑调整（大功能上线路径上放行）——预算是协商的契约不是死数字；每次调整带业务背景记录
- 执行：CI 门禁 + 超预算白名单（带 issue 过期日期）——白名单过期自动收紧

```text
预算推导：LCP 3s → 首屏 JS ≤ 170KB gzip → vendor 90KB + 业务 80KB
结构：总量 + 分项（vendor/业务/懒加载） | 维护：里程碑协商 + 白名单过期
```
