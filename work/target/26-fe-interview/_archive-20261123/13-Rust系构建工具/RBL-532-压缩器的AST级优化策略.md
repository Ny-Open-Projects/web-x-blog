## RBL-532：压缩器的 AST 级优化：死代码消除与内联的三级策略

**答**：
- 压缩器（minifier）的优化分三级，成本与收益递增：
- **L1 语法级**（零分析）：空语句删除、常量折叠（`1+2`→`3`）、逗号合并、`if` 无 else 转三元——纯语法变换，安全零风险。
- **L2 作用域级**（作用域分析）：未用变量删除、变量名混淆（mangle）、简单内联（仅字面量赋值：`const a = 5` → 引用处替换 5）——需要作用域图，正确性由词法作用域保证。
- **L3 数据流级**（全程序分析）：跨函数内联、死代码传播（未调用的函数删除——依赖 tree-shaking 标记）、常量传播跨赋值链——需要引用流分析，风险最高（`@__PURE__` 标注缓解误删）。
- 三级的工程取舍：L1/L2 是 minifier 的主体（快且安全），L3 保守启用（只对明确标注 @__PURE__ 的调用内联删除）——误删风险（`sideEffect` 判断错）是压缩器正确性事故的全部来源。
- 压缩正确性的保障：**golden 测试**（压缩前后行为一致——跑测试集）+ 语义保留清单（eval/with/with 语句的变量环境不可混淆）。
- 追问钩子：为什么 terser 慢而 swc 压缩快 10x？——terser 是 JS 多遍 AST 分析，swc 单遍 + Rust——压缩质量差异主要在「激进程度」（terser 的 L3 更激进），速度差异在实现语言与遍数。

```javascript
// 压缩器三级优化
const MINIFIER_LEVELS = {
  L1_语法级: '空语句/常量折叠/逗号合并/三元化——零分析零风险',
  L2_作用域级: '未用变量删除/变量名混淆/字面量内联——作用域图保证',
  L3_数据流级: {
    actions: '跨函数内联/死代码传播/常量传播链',
    risk: '误删副作用——@__PURE__ 标注缓解',
    policy: '保守启用：仅明确标注 @__PURE__ 的调用',
  },
  保障: 'golden 测试（压缩前后行为一致）+ 语义保留清单（eval/with 不可混淆）',
  对比: 'terser 慢（JS 多遍）vs swc 快 10x（Rust 单遍）——质量差在激进度，速度差在实现',
}
```
