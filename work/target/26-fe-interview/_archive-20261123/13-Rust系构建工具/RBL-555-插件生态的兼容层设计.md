## RBL-555：插件生态的兼容层设计：webpack 插件适配器的语义映射

**答**：
- Rspack 兼容 webpack 插件的适配器设计——不是「重实现 webpack」而是「语义映射」：
- 1) **钩子映射表**：webpack compiler/compiler.hooks 的每个钩子 → Rspack 内部事件（`thisCompilation` → 编译开始；`emit` → 产物写出前）——映射表的完整性 = 兼容率。
- 2) **对象形态模拟**：webpack 插件访问的 `compilation.assets`/`chunks` 对象——Rspack 生成「视图对象」（Proxy 或快照）——插件读没问题，**插件写**（修改 assets）要同步回 Rust 侧（双向同步是兼容层的复杂点）。
- 3) **不可兼容清单**：依赖 webpack 内部实现的插件（tapable 细节/隐藏 API）——显式列出不兼容清单 + 替代方案推荐——「诚实的不兼容」好过静默跑错。
- 兼容层的测试策略：**社区 Top100 插件兼容性矩阵**（每版本跑一遍真实插件测试）——兼容率作为发布门禁。
- 追问钩子：兼容层的长期归宿——随着生态迁移，兼容层逐步萎缩（插件原生 Rust 化），但「webpack 插件兼容」是迁移期的生命线（没有它没人敢迁移）——兼容层的存在本身是迁移策略的一部分。

```javascript
// webpack 插件兼容层
const COMPAT_LAYER = {
  钩子映射: 'compiler.hooks 每钩子 → Rspack 内部事件——映射表完整性 = 兼容率',
  对象模拟: {
    read: 'compilation.assets/chunks 生成视图对象（Proxy/快照）——读免费',
    write: '插件修改 assets → 双向同步回 Rust——兼容层的复杂点',
  },
  不可兼容: '依赖 webpack 内部实现的插件——显式清单 + 替代推荐（诚实的不兼容）',
  测试: '社区 Top100 插件兼容矩阵（每版本跑真实插件测试）——兼容率 = 发布门禁',
  长期归宿: '兼容层是迁移期生命线 → 生态原生 Rust 化后逐步萎缩',
}
```
