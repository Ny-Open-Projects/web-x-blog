## RBL-222：增量编译的输入指纹设计与不变量检测

**答**:
- 指纹内容：源文件内容 hash + 配置 hash（resolve/plugins/loader 参数）+ 工具版本 hash——三者任一变化即全量
- 「不变量」思想：把「决定输出的全部输入」显式化，指纹命中 = 输出可复用；漏掉一个输入（如环境变量）就是缓存错误 bug
- 文件依赖指纹的边界：静态 import 可精确追踪；动态 import（变量路径）、fs 读取、worker 引用是指纹盲区——工具用保守策略（视为全局输入）
- 实践：Turborepo/Nx 的 input 声明就是「显式化不变量」——声明不全会导致缓存命中但产物错误（最危险的缓存 bug）

```javascript
// Turborepo turbo.json
{
  "tasks": {
    "build": {
      "inputs": ["src/**", "$TURBO_DEFAULT$"],
      "env": ["API_URL"],          // ← 漏声明的 env 就是缓存错误源
      "outputs": ["dist/**"]
    }
  }
}
```
