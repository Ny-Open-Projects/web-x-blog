## RBL-722：构建器自身的发布工程：版本原子性、渠道（canary/stable）与回滚

**答**:
- 构建器发布的特殊性（RBL-580 平台绑定 + RBL-644 ABI 耦合）决定了发布工程比普通库严格：1) **原子发布**——主包与全部平台 binding 同版本一次发齐（任一平台 CI 失败 → 全体回滚 deprecate）；2) **渠道分层**——canary（每次主干构建，尝鲜用户，无支持承诺）→ beta（功能冻结候选）→ stable（灰度验证后，RBL-705 门禁）；3) dist-tag 管理（latest/next/canary 指向切换，npm deprecate 做撤回提示）。
- 回滚工程：发布后发现问题，回滚不是「重发旧版本」（npm 不允许覆盖）——deprecate 坏版本 + dist-tag latest 指回旧版 + 迁移说明；已锁定坏版本的用户走升级修复（所以构建器用户要锁 minor 而非精确——回滚窗口的平衡）。
- 发布前检查清单自动化：全平台冒烟测试（RBL-563）、插件矩阵抽样（生态 top20 插件 × 新版本）、基准对比（RBL-587 性能门槛）、文档同步（错误码/示例 RBL-590）——全绿才允许打 tag。
- 发布审计：每次发布记录「决策上下文」（谁批准、指标快照、changelog 链接）——出问题时可复盘「当时为什么放行」。
- 追问钩子：为什么 canary 渠道是构建器生态的健康指标？——canary 用户是「真实世界压测机」：他们的仓库多样性（配置/依赖/平台组合）远超内部测试；canary 阶段捕到的兼容性问题数量，直接预测 stable 发布的口碑——维护者要经营的是 canary 反馈回路。

```javascript
// 发布流水线（原子性）
async function release({ version, channel }) {
  const bindings = await buildAllPlatforms();            // 全平台编译
  for (const b of bindings) await smokeTest(b);          // 平台冒烟
  await runPluginMatrix({ top: 20, core: version });     // 生态抽样
  const bench = await runBench();                        // 性能门槛
  if (bench.regression) fail(`性能回归 ${bench.regression}，中止发布`);
  await publishAtomic({ main: version, bindings, tag: channelTag(channel) });
  await recordRelease({ version, channel, approver: CI_ACTOR, bench });
}
const channelTag = (c) => c === 'canary' ? 'canary' : c === 'beta' ? 'next' : 'latest';

// 回滚
async function rollback(badVersion, goodVersion) {
  await npmDeprecate(badVersion, `存在回归，请使用 ${goodVersion}`);
  await retag('latest', goodVersion);                    // dist-tag 指回
  await broadcast({ broken: badVersion, fix: goodVersion });   // 社区公告
}
```
