## RBL-655：构建正确性的测试金字塔：单元 invariant、集成 fixture、端到端行为

**答**:
- 构建器的正确性测试三层：1) **不变量单测**（resolve 幂等、hash 确定性、chunk 引用闭合——每个模块的 invariant 独立验证，跑得快）；2) **fixture 集成**（RBL-585 的最小复现库，覆盖语言特性与依赖形态组合）；3) **端到端行为**（产物在真实环境执行，断言运行结果——唯一能捕获「打包正确但运行时语义错」的层）。
- 不变量（invariant）的价值：构建器的大量正确性可以表述为「性质」而非「用例」——产物引用闭合（每个被引用的 chunk 都产出）、导出可达（入口用到的导出在产物中存在）、语义等价（RBL-546 随机等价测试）；property testing 比 example testing 覆盖面广一个量级。
- 层间配比与失败定位：单测失败定位精确但可能测不到组合效应；E2E 失败定位差但真实——所以失败要在层间下沉（E2E 失败 → 找出最小特征 → 固化成 fixture → 再拆到单测），让每类 bug 最终由最快的层守护。
- 端到端的「行为断言」设计：不只「页面能打开」，而是「页面渲染内容 === 源码语义的期望渲染」——用同一源码的「无构建参考实现」（直接跑源码 via jsc-like）对比产物执行结果，语义等价的运行时版本。
- 追问钩子：为什么构建器的测试金字塔比业务应用更依赖「性质测试」？——业务应用的输入是有限用户操作，构建器的输入是无限代码空间（用户写什么都有）；有限用例永远漏，性质（不变量）是唯一可扩展的正确性描述。

```javascript
// 不变量测试框架（property-based）
function invariant(name, gen, check, { runs = 100 } = {}) {
  for (let i = 0; i < runs; i++) {
    const input = gen();                                 // 随机输入生成器
    try {
      check(input);
    } catch (e) {
      throw new Error(`不变量[${name}]失败 #${i}，反例已保存: ${JSON.stringify(input)}\n${e.message}`);
    }
  }
}
// 引用闭合不变量
invariant('chunk-refs-closed',
  () => randomProject(),                                 // 随机生成项目
  (proj) => {
    const out = buildSync(proj);
    for (const chunk of out.chunks)
      for (const ref of chunk.imports)
        if (!out.chunks.some(c => c.name === ref))
          throw new Error(`chunk ${chunk.name} 引用了未产出的 ${ref}`);
  });

// E2E 行为等价
it('产物行为 === 源码行为', async () => {
  const srcResult = runSource(proj);                     // 参考实现（无构建）
  const builtResult = runInBrowser(buildSync(proj));     // 产物执行
  expect(builtResult).toEqual(srcResult);
});
```
