## RBL-268：构建工具升级的风险评估流程

**答**:
- 升级前评估：changelog 的 breaking 清单核对（逐条找用到没）、实验 API 使用盘点（团队适配层）、插件兼容矩阵
- 升级验证三关：产物一致性 diff（fixture 全量对比）、性能回归（P95 不劣化 10%）、端到端冒烟（dev/构建/预览三态跑通）
- 发布策略：preset 内升级（业务无感）+ 金丝雀项目先行 + 回滚预案（锁版本回退）
- 治理机制：升级窗口期（每季度集中升）、工具版本漂移监控（多仓工具版本不一致告警——monorepo 外的多仓团队常见病）

```text
升级流程：changelog 核对 → 实验面盘点 → fixture diff → 性能回归 → 金丝雀 → 全量 → 锁版本
回滚：git revert 锁版本文件
```
