## RBL-553：WASM 插件的边界与性能：比 JS 快、比 Rust 慢的原因

**答**：
- 插件三档性能阶梯：Rust 内建（最快，零边界）< WASM 插件（中间）< JS 插件（最慢）。WASM 的位置来自两处边界成本：
- 1) **线性内存边界**：WASM 只能访问自己的线性内存——宿主数据（模块内容）每次调用都要**拷贝进 WASM 内存**——大文件插件的拷贝成本显著（SWC WASM 插件的 AST 传递是纯拷贝）。
- 2) **调用粒度**：跨边界调用本身有开销（~微秒级）——「每元素一次调用」（遍历 AST 每节点回调）的模式在 WASM 边界上成本爆炸——正确模式是「粗粒度调用」（一次传入整个 AST/文档，插件内部遍历）。
- WASM 的价值：比 JS 快（无 JIT 预热/GC 抖动）+ 语言无关（Go/C/Rust 都可写插件）+ 沙箱安全（内存隔离，插件崩不崩宿主）——「性能与安全的中间点」。
- 边界的工程优化：**批量数据传递 + 共享内存实验**（WASM memory 与宿主共享——免拷贝但需所有权协议）；SWC 的 WASM 插件接口演进就是从细粒度 visitor 转向粗粒度文档传递。
- 追问钩子：WASM 插件 vs JS 插件的选择矩阵——计算密集（转换/分析）选 WASM；需要 Node 生态（fs/network）选 JS（WASM 无系统访问）；原型期选 JS（迭代快），稳定后移植 WASM。
