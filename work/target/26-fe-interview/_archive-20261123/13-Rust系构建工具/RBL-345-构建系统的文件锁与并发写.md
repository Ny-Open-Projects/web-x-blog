## RBL-345：构建系统的文件锁与并发写保护

**答**:
- 并发场景：两个终端同时 dev（预构建目录并发写）、CI 并行任务写同一缓存——无锁结果是文件互相覆盖/半截读取
- 锁实现：文件锁（O_EXCL 创建 lockfile + 超时抢占——持锁进程死亡锁文件残留，必须带过期时间与 holder pid 检测）、proper-lockfile 类库封装
- 更优解：原子性替代锁——唯一临时文件名 + rename 原子替换（无锁并发安全，最后 rename 者胜）——能绕过锁就绕过
- 分布式锁：远程缓存写入用服务端原子性（S3 key 唯一），不实现分布式文件锁（复杂度不值）

```javascript
// 锁 + 抢占
async function acquire(lockfile, ttl = 30_000) {
  try { fs.writeFileSync(lockfile, String(process.pid), { flag: 'wx' }); return true }
  catch {
    const holder = Number(fs.readFileSync(lockfile, 'utf8'))
    if (Date.now() - fs.statSync(lockfile).mtimeMs > ttl || !pidAlive(holder)) {
      fs.unlinkSync(lockfile); return acquire(lockfile, ttl)   // 抢占死锁
    }
    return false
  }
}
// 更优：临时名 + rename（无锁原子）
```
