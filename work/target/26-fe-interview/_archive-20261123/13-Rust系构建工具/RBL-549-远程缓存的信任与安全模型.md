## RBL-549：远程缓存的信任与安全模型：缓存投毒与完整性校验

**答**：
- 远程缓存（Turbo Remote Cache/GitHub Actions Cache）的信任问题：**从共享存储拉取的产物会被直接使用**——缓存投毒（恶意 PR 上传带后门的产物）是供应链攻击面。
- 安全模型三层：
- 1) **完整性**：产物签名（写缓存方私钥签名，读方验签）或至少「键-值绑定」（key 含输入指纹，值 hash 校验）——防传输损坏。
- 2) **信任分级**：主分支构建的缓存可信（可被所有人复用）；PR 分支缓存只在本 PR 复用（防止恶意 PR 污染主缓存）——Turbo 的签名模式（TEAM 级签名）就是这个语义。
- 3) **产出可审计**：缓存命中也要「可验证」——抽检机制（采样重算比对——LRU 比例验证缓存正确性）。
- 投毒的实际案例模式：PR 构建注入恶意代码 → 产物入共享缓存 → 主分支构建命中缓存使用恶意产物 → 部署。防御：PR 缓存隔离 + 产物签名 + 部署前 SBOM 校验。
- 追问钩子：远程缓存的收益/安全权衡——全团队共享（收益最大）vs 严格隔离（安全最高）——折中：分支级隔离 + 主分支签名复用——「缓存共享半径 = 信任半径」。

```javascript
// 远程缓存安全模型
const REMOTE_CACHE_SECURITY = {
  威胁: '缓存投毒：恶意 PR 产物入共享缓存 → 主分支命中使用 → 部署（供应链攻击面）',
  三层防御: {
    完整性: '产物签名（私钥签/验签）或键-值绑定（key 含指纹，值 hash 校验）',
    信任分级: '主分支缓存全员可复用；PR 缓存仅本 PR（Turbo 签名模式语义）',
    可审计: '抽检重算比对（LRU 采样验证缓存正确性）',
  },
  权衡: '缓存共享半径 = 信任半径——分支隔离 + 主分支签名复用是折中',
  补充: '部署前 SBOM 校验 + 部署产物与缓存产物 hash 比对',
}
```
