## RBL-281：构建遥测：匿名统计与反馈闭环怎么设计

**答**:
- 采集内容：构建耗时分布/工具版本/插件组合/错误类型计数——用于工具方改进优先级（如「错误信息不懂」的量化反馈）
- 隐私设计：默认 opt-out、匿名化（无路径/无业务内容/无源码片段）、collect 清单公开可审计——遥测的信任基础
- 闭环机制：遥测数据 → 工具改进（如高频错误加更好的修复提示）→ changelog 回连数据（「错误 X 的出现率下降 60%」）——证明遥测产生了价值
- 企业内遥测：团队内部构建遥测（私有部署）价值更大——驱动 preset 治理与升级决策

```text
采集：{ tool: 'rspack@1.2', time: '18.2s', plugins: ['html'], errorTypes: ['TS2304'] }
不采：路径 / 业务字段 / 源码
闭环：错误 X 出现率 12% → 修复提示改进 → 降至 4%（changelog 回连）
```
