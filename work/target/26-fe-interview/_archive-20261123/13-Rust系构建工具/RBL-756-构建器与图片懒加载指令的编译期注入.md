## RBL-756：构建器对懒加载指令的编译期注入：loading=lazy、fetchpriority 与 LCP 优化

**答**:
- 图片加载属性的优化是「上下文敏感」的：LCP 图（首屏大图）要 `fetchpriority="high"` + eager + preload；非首屏图要 `loading="lazy" decoding="async"`——构建器可按「位置启发式」注入（首屏组件目录的 img → eager，其余 → lazy），但误判 LCP 图是致命的（延迟首图渲染）。
- 构建器的策略：1) **显式声明优先**（开发者标记 `<Img priority>` → high/eager/preload），构建器只在「无声明」时注入默认值；2) 默认规则保守（只有明显非首屏的才 lazy——组件目录启发式 + 预渲染 HTML 中的位置分析）；3) 注入结果进诊断报告（哪些图被 lazy/eager，供 review）。
- srcset 与 sizes 的自动生成（RBL-719 变体产物联动）：源图有多变体 → 编译期生成 srcset/sizes；sizes 的默认值策略（视口断点）要与设计系统断点一致——配置化而非猜测。
- LCP 预加载清单：构建器从「首屏优先图」生成 preload 提示（RBL-624）——preload 的 URL 是变体 hash（RBL-598 级联），构建器保证 preload 与实际 srcset 选中的 URL 一致（否则双下载——preload 错误 URL 是常见 LCP 退化原因）。
- 追问钩子：为什么「preload 与 srcset 不一致」会导致双下载？——preload 带 imagesrcset 时浏览器按其提示选择，实际 img 的 srcset 可能选了不同候选（视口变化）→ 两个请求；解法是 preload 与 img 的 srcset/sizes 严格同源（构建器从同一变体计划生成两者）。

```javascript
// 编译期图片属性注入
function transformImgTag(tag, ctx) {
  const attrs = parseTag(tag);
  const out = { ...attrs };
  if (attrs.priority) {                                  // 显式声明最高优先
    out.fetchpriority = 'high'; out.loading = 'eager';
    ctx.preloads.push({ url: variantUrl(attrs.src, viewportWidth(ctx)), as: 'image' });
  } else if (ctx.aboveFold(attrs) === false) {           // 明确非首屏才默认 lazy
    out.loading ??= 'lazy';
    out.decoding ??= 'async';
  }
  if (variantsOf(attrs.src).length > 1)
    out.srcset = buildSrcset(attrs.src, ctx.breakpoints); // 变体联动
  return serialize(out);
}
// preload 与 srcset 同源（防双下载）
const buildPreload = (img, breakpoints) => ({
  href: pickVariant(img, defaultViewport),
  imagesrcset: buildSrcset(img, breakpoints),            // 与 img 一致
  imagesizes: img.sizes,
});
```
