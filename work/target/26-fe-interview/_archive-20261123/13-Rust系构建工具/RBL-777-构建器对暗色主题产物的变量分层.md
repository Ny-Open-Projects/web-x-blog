## RBL-777：场景题：暗色主题的产物分层——主题切换的构建期与运行时协作

**答**:
- 暗色主题（乃至多品牌）的产物策略光谱：1) **CSS 变量双层**（`:root` 亮色层 + `.dark` 覆盖层，切换 = 切 class——零体积增量、零延迟，首选）；2) **多主题产物**（每主题独立 CSS 文件，按需加载——主题差异大/品牌完全不同时）；3) **编译期主题**（SCSS 变量时代产物，切主题 = 换产物——已淘汰，切换要重载）。
- 构建器的配套：1) token 编译（RBL-697）产出变量分层 CSS；2) **主题完整性校验**——暗色层必须覆盖全部亮色变量（缺项 = 暗色下白底闪烁——这是暗色主题最常见的线上 bug），缺项诊断精确到变量名；3) 对比度审计双主题都跑（WCAG AA）。
- 切换时序的无闪烁：入口 HTML 内联「初始主题脚本」（读 localStorage/prefers-color-scheme 设置 class）——在 CSS 加载前执行防 FOUC；构建器把这个内联片段注入 entry html。
- 第三方组件的主题适配：变量穿透（组件读全局变量）vs 组件自带主题产物（多份 CSS 变量映射）——构建器提供「变量别名映射」让旧组件接新 token（`--antd-primary` → `--color-primary`）。
- 追问钩子：为什么暗色缺项会导致「白闪」而不仅是样式缺失？——变量缺项时回退到 inherited/默认值（白色背景），暗色模式下页面局部亮块；根因是「覆盖层的完整性没有机械保证」——所以完整性校验必须是构建门禁而非 code review 的人眼检查。

```javascript
// 主题完整性校验
function validateThemeVars(lightVars, darkVars) {
  const missing = Object.keys(lightVars).filter(k => !(k in darkVars));
  if (missing.length)
    return { ok: false, missing,
      detail: `暗色层缺 ${missing.length} 个变量——将产生白底闪烁` };
  // 值相同也告警（未真正适配暗色）
  const unchanged = Object.keys(darkVars).filter(k => darkVars[k] === lightVars[k] && /background|color/.test(k));
  return { ok: true, unchanged };
}
// FOUC 防御内联（构建器注入 entry html <head> 首位）
const themeBoot = `<script>(function(){try{var t=localStorage.theme||'light';
if(t==='auto')t=matchMedia('(prefers-color-scheme: dark)').matches?'dark':'light';
document.documentElement.classList.add(t);}catch(e){}})()</script>`;
```
