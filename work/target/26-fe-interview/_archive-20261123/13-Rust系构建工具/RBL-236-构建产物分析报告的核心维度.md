## RBL-236：构建产物分析报告的核心维度有哪些

**答**:
- 四维度：体积（原始/gzip/brotli 分层统计，按 chunk 与第三方包下钻）、构成（各包占比 treemap，定位「谁吃掉了体积」）、变化（与上一版 diff，涨跌归因到包）、加载影响（关键路径 chunk、并行请求数、首屏 JS 量）
- 深钻链路：总体积涨 → 定位 chunk → chunk 内包占比 → 包内模块占比 → 具体依赖（为什么引了它：grep 调用链）
- 常见发现：moment→dayjs 类替换收益、重复依赖（lodash 两版本并存）、polyfill 重复注入、按需引入失效（import 整包）
- 报告工程化：PR 评论体积 diff（自动）+ 主分支基线看板（趋势）——只在「变化时」报警而非静态阈值

```text
下钻链：+180KB → vendor-charts +180KB → echarts 全量引入 → 改用按需 import → -160KB
```
