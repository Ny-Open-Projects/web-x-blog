## RBL-946：综合深水：全栈类型安全——契约单源的构建管线

**答**:
- 全栈类型安全的管线形态（14 目录衔接）：1) **契约单源**（API schema OpenAPI/GraphQL/tRPC router——前后端类型从单源生成 RBL-741）；2) 构建管线的职责：生成（codegen 幂等校验 RBL-742）、校验（前后端类型一致——「契约漂移」检测：后端 schema 变了前端未重新生成 → CI 红）、注入（client 类型进产物——类型不进 bundle 只进编译期）。
- 全栈类型安全的「构建期事故拦截」：后端改字段名 → 前端编译失败（类型错误阻断构建）——「类型作为编译期测试」：接口变更的成本前置到编译而不是运行时 undefined。
- 管线的集成点：1) codegen 前置（构建前确保类型新鲜 RBL-742 幂等）；2) tRPC 类运行时类型推导（无 codegen——推理链依赖 tsconfig 严格性：构建器的 typecheck 任务配置）；3) 边界校验的运行时互补（类型是编译期的，运行时仍需 zod 校验外部输入——「编译期类型 + 运行时校验」双层）。
- 演进的摩擦：schema 大仓库的 codegen 时长——增量 codegen（RBL-741 难点）或分域 schema。
- 追问钩子：为什么「编译期类型」不能替代「运行时校验」？——类型只约束「编译时已知的调用」，运行时的真实输入（用户提交/API 返回）不在编译期保证内（后端实际返回可能与 schema 漂移/用户输入任意）；边界处（信任边界跨越点）必须运行时校验（zod/guard）——「类型管协作、校验管边界」的双层模型；把类型当运行时保证 = 信任边界的裸奔。

```javascript
// 契约漂移检测（CI）
async function contractDriftCheck({ committedTypes, regenerate }) {
  const fresh = await regenerate();
  if (committedTypes !== fresh)
    fail('契约漂移：后端 schema 已变但前端类型未重新生成——运行 pnpm codegen');
}
// 双层校验模式（边界 + 编译期）
// 编译期：tRPC 推理（router 类型直达 client）
const client = createTRPCClient<AppRouter>();
const user = await client.user.byId.query(id);          // user 类型自动推导
// 运行时：信任边界
```
