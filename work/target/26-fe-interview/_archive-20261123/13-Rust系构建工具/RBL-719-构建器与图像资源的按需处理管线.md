## RBL-719：图像资源的构建管线：格式转换、响应式源集与体积预算的自动执行

**答**:
- 图像资源管线的构建期任务：1) 格式转换（png/jpg → webp/avif，构建时双格式产物 + picture 元素用 webp 优先）；2) 尺寸变体（srcset 生成：320/640/1280 多分辨率，按断点预算裁剪）；3) 质量探测（图片体积超预算自动降质量参数重压——「质量 vs 体积」的自动寻优）；4) LQIP/占位色（平均色或微缩 base64 注入 HTML/CSS）。
- 与构建器集成的形态：资源管线是 transform 插件（import './img.png?width=640&format=webp' 的查询参数语义）或目录级批处理（assets/images/**）。关键是**确定性**：同输入同输出（质量参数显式配置而非探测随机）——产物 hash 稳定（RBL-598）。
- 体积预算的自动执行：每图预算（如 >200KB 警告）+ 总资产预算；超预算的处理不是自动压缩（可能损画质）而是「门禁 + 豁免」（RBL-662 模式）——质量决策留给人，检测自动化。
- 缓存：图像转换是 CPU 重操作（avif 编码秒级），按「源文件 hash + 参数」缓存转换结果（RBL-633 持久缓存）——重复构建零成本。
- 追问钩子：为什么「构建时转格式」优于「CDN 边缘转格式」？——构建时产物确定（可预推 CDN/预缓存 SW）；边缘转换灵活但首次请求慢且不可审计；工程答案常是「构建时主格式 + CDN 兜底动态格式」。

```javascript
// 图像资源插件（查询参数语义）
async function transformImage(id, query) {
  const { width, format = 'webp', quality = 80 } = parseQuery(query);
  const cacheKey = `${sha(file(id))}:${width}:${format}:${quality}`;
  const cached = await imageCache.get(cacheKey);
  if (cached) return cached;                             // 转换结果持久缓存

  const out = await sharp(file(id)).resize(width).toFormat(format, { quality }).toBuffer();
  const result = { code: `export default ${JSON.stringify(assetUrl(out))};`, bytes: out.length };
  await imageCache.set(cacheKey, result);
  if (result.bytes > 200 * 1024) warn(`${id} 超预算 ${kb(result.bytes)}KB——请人工评估质量参数`);
  return result;
}
// 自动生成 srcset（目录级批处理）
// <img srcset="a-320.webp 320w, a-640.webp 640w, a-1280.webp 1280w" sizes="(max-width:600px) 320px, 640px">
```
