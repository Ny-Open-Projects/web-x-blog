## RBL-284：构建工具的错误码体系怎么设计

**答**:
- 结构：`ERR_<域>_<编号>`（ERR_CONFIG_001），错误码 → 文档页（详细原因+修复方案+已知 issue 链接）——错误信息短，详情进文档可热更新
- 编号管理：错误码注册表（单文件集中定义，防重复编号）；废弃码保留别名（用户搜索还能找到）
- 分层：稳定码（用户可搜索的知识库条目）vs 临时码（内部 debug，不承诺稳定）——两类分开命名避免误导
- 消费方：CI bot 用错误码分类聚合（本周 ERR_CONFIG_001 增多 → 文档补 FAQ）；IDE 插件按码给 inline 修复

```javascript
// 错误注册表
const ERRORS = {
  ERR_CONFIG_001: { msg: 'invalid output.target', doc: '/docs/errors/ERR_CONFIG_001' },
  ERR_RESOLVE_003: { msg: 'cannot resolve dynamic import', doc: '/docs/errors/ERR_RESOLVE_003' },
}
throw new BuildError('ERR_CONFIG_001', { got: target, expected: ['web', 'node'] })
```
