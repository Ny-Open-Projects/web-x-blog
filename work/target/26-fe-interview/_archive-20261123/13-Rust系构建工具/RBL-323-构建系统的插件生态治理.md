## RBL-323：团队构建插件生态的治理

**答**:
- 治理问题：同一个功能 5 个团队各写一个插件（重复）、插件无测试无文档无人维护（僵尸）——治理靠「注册制 + 质量门禁 + 生命周期标注」
- 注册制：团队插件进统一 registry（内部 npm scope），注册要求：README + 测试 + 类型 + 版本策略——不做注册制就没有可见性
- 质量分级：verified（平台维护）/ community（团队自维护）——业务选型优先 verified；community 插件加「维护状态」标注（最近发布时间）
- 生命周期：deprecation 政策（映射到替代插件 + 日期）——生态跟 preset 升级联动（preset 只内置 verified 插件）

```text
治理三件：registry 注册制（可见性）→ 质量分级（verified/community）→ deprecation 政策（联动 preset）
```
