## RBL-273：依赖预构建的原理（为什么预打包能加速 dev）

**答**:
- 问题：node_modules 的 ESM 包有大量小文件与裸导入（lodash-es 几百个文件），原生 ESM 逐文件请求会请求风暴
- 预构建：dev 前把依赖包预打包成单文件（esbuild/Rolldown 极快），浏览器只请求打包后的依赖 chunk——请求数从千级降到个位
- 失效条件：lockfile 变/依赖版本变/配置的 optimizeDeps 变——预构建缓存目录带指纹
- 坑：新增依赖（代码里新 import）触发重新预构建导致 dev 全页刷新——避免频繁增删依赖；CJS 互操作（预构建把 CJS 转 ESM 统一处理）

```text
无预构建：页面 → 1000+ 请求（逐模块）
预构建后：页面 → 几个 deps chunk（react.js, lodash.js...）
缓存 key: lockfile hash + optimizeDeps 配置 hash
```
