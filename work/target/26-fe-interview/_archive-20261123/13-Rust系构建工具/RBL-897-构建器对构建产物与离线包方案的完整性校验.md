## RBL-897：场景题：离线包的完整性校验——App 内嵌 H5 离线资源版本对账

**答**:
- 混合 App 的离线包（H5 资源打包进 App 本地，秒开）：1) **版本对账**（离线包版本 vs 服务端最新——App 启动时查询差量更新）；2) 完整性校验（离线包内每个文件的 hash 与清单比对——下载中断/存储损坏的检出）；3) 一致性（离线包的 html 引用的 chunk 全部在包内——离线场景的引用闭合 RBL-656 变体）。
- 构建器的配合：1) 离线包清单生成（RBL-708 SW 清单的同构：文件+hash）；2) 差量包计算（新旧版本 manifest diff → 只含变化文件的差量包 RBL-708 swDiff）；3) 「离线闭包校验」（离线包内页面引用的资源 100% 在包内或显式声明在线 fallback——离线不可达资源必须在清单标注）。
- 更新的原子性：差量包应用（旧版本完整 → 下载差量 → 校验 → 原子替换目录 RBL-583/584）——「半更新的离线包」比无离线包更糟（白屏）。
- 版本对账的灰度兼容：App 版本 × 离线包版本的矩阵（旧 App 只认旧协议离线包）——服务端按 App 版本下发对应格式。
- 追问钩子：为什么「离线闭包校验」比「文件完整性校验」更关键？——完整性只保证「包内文件没坏」，闭包校验保证「页面真的能离线跑」（引用了 CDN 图片 = 离线白屏的静默故障——单文件校验全绿但页面挂）；「页面级可用性」才是离线包的交付单位，文件只是载体——完整性是必要条件，闭包是充分条件，发布门禁要校验交付单位。

```javascript
// 离线包闭包校验
function verifyOfflineClosure(manifest, htmlPages) {
  const inPkg = new Set(manifest.files.map(f => f.name));
  const problems = [];
  for (const page of htmlPages) {
    for (const ref of page.refs) {                       // html 提取的引用（script/css/img）
      const local = ref.replace(/^https?:\/\/[^/]+/, '').replace(/^\//, '');
      if (!inPkg.has(local) && !manifest.onlineFallbacks?.includes(ref))
        problems.push({ page: page.path, ref, detail: '离线不可达且未声明 fallback' });
    }
  }
  return { problems, ok: problems.length === 0 };
}
// 差量包
function deltaPkg(oldM, newM) {
  const { add, update, remove } = swDiff(oldM, newM);    // RBL-708
  return {
    version: newM.version,
    files: [...add, ...update].map(u => ({ url: u, content: newM.content(u) })),
    remove,
    hash: manifestHash(newM),
  };
}
```
