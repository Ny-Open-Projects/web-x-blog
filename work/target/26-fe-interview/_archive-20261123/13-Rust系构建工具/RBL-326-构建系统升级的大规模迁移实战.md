## RBL-326：构建工具大规模迁移的实战流程

**答**:
- 分仓分级：按项目活跃度/复杂度分批迁移（试点 2 个活跃仓 → 梯度推广 → 遗留仓最后或豁免）——不要一把梭
- 迁移自动化：配置 codemod（webpack config → 新工具 config 的映射器）+ 差异人工清单（自动迁移不了的逐仓处理）——迁移工具先行是规模化关键
- 统一基线：迁移后所有仓进统一 preset（借迁移机会收敛配置漂移）——迁移是治理的最佳时机
- 验收与回退：每仓迁移后双跑对比（产物 diff + CI 时长），不达标回退等下批；进度看板跟踪

```text
流程：分级分批 → codemod 自动化 → 统一 preset 收敛 → 双跑验收 → 看板跟踪
试点仓选择：活跃 + 复杂度中等（最有代表性且反馈及时）
```
