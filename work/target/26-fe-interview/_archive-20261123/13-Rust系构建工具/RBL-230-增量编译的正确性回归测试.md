## RBL-230：增量编译的正确性怎么回归测试

**答**:
- 黄金法则：增量结果必须与全量结果 byte-identical——回归测试的断言就是这条
- 测试设计：fixture 工程 + 变更脚本序列（改文件/删文件/改配置/切分支）→ 每步后抓产物快照 → 与「全量重构建快照」对比
- 变更脚本要覆盖边界：新增文件、删除被引用文件（图断裂）、配置热改、依赖升级（lockfile 变）、重命名（delete+add）、无操作（应零重算）
- CI 化：夜间跑全量序列（几分钟），PR 跑子集（1 分钟内）；快照 hash 存基线文件

```javascript
// 增量正确性测试骨架
const cases = [
  { name: 'edit file', act: () => fs.writeFileSync('src/a.ts', 'export const x = 2') },
  { name: 'delete referenced', act: () => fs.rmSync('src/b.ts') },
  { name: 'no-op', act: () => {} },            // 断言零重算
]
for (const c of cases) {
  await incrementalBuild(c.act)
  expect(await buildHash()).toBe(await fullBuildHash())   // 增量 = 全量
}
```
