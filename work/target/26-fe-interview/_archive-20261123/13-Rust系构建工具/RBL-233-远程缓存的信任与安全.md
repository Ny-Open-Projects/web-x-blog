## RBL-233：远程缓存的信任与安全问题

**答**:
- 威胁模型：缓存投毒（恶意产物写入远程缓存，全员命中）→ 缓存条目必须可验证（内容 hash + 签名），恢复后校验
- 访问控制：读全员可读、写限制到 CI 服务账号（本地开发者只读或私空间），避免个人环境污染共享缓存
- 审计与可回溯：条目记录（谁在什么 commit 用什么工具版本产出），出问题可定位污染源头并整体作废（按版本号区间）
- 隐私面：缓存含源码派生物（产物/类型信息），公网缓存服务需评估泄露面；企业内自托管（Turborepo 自托管/Nx cloud 私有部署）更可控

```text
安全基线：内容 hash 校验 + CI-only 写权限 + 条目审计 + 版本区间作废
```
