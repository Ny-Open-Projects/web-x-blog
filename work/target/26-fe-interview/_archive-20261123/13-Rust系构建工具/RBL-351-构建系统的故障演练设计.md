## RBL-351：构建系统的故障演练怎么设计

**答**:
- 演练场景清单：远程缓存断网（验证回退本地）、registry 慢（验证镜像源切换）、磁盘满（验证清理与告警）、内存 OOM（验证任务隔离与重试）、慢文件系统（网络盘模拟）——每个场景对应一个降级路径的验证
- 演练实施：预发环境注入故障（tc/iptables 模拟网络故障、ulimit 模拟资源限制）→ 观测降级行为与恢复时间（MTTR 是演练的核心度量）
- 演练纪律：演练窗口声明（业务团队知情）、一键恢复、演练结果进 Runbook 更新——「发现的每个失效点修一个」
- 成熟度路径：手动演练（脚本化）→ 定时自动演练 → 生产随机演练（构建系统可承受，业务系统谨慎）

```text
场景：缓存断网 / registry 慢 / 磁盘满 / OOM / 慢 IO
度量：降级是否自动 + MTTR + 用户感知面
闭环：演练 → 失效点修复 → Runbook 更新
```
