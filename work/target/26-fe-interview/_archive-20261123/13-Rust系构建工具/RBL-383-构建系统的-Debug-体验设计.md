## RBL-383：构建问题的 Debug 体验设计

**答**:
- 排查难根因：构建是黑盒流水线（错误在多层间传递失真）+ 状态不可复现（缓存/环境差异）——Debug 体验设计要打通「可观测+可复现」
- 可观测三件：分层日志（--verbose 阶段级）、产物溯源（哪个插件/loader 生成了这个输出——source 注释标记）、时序 trace（chrome tracing 格式可视化）
- 可复现三件：最小复现生成器（当前配置+失败模块自动导出可独立运行的 fixture）、环境快照（版本/env/lockfile 一键导出）、确定性重放（禁缓存模式重跑）
- 设计哲学：把「构建问题的排查成本」当作产品指标——好的构建工具 = 快的构建 + 好查的构建

```text
可观测：分层日志 / 产物溯源注释 / trace 可视化
可复现：最小复现生成器 / 环境快照 / 禁缓存重放
哲学：排查成本 = 产品指标
```
