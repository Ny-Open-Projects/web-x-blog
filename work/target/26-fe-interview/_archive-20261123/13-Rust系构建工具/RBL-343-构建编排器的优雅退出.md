## RBL-343：构建编排器的优雅退出

**答**:
- 信号处理链：SIGINT → 编排器捕获 → 通知运行中任务（子进程 SIGTERM）→ 等待清理（限时）→ 超时 SIGKILL → 输出已完成的任务状态（进度不丢失的感知）
- 状态保存：中断时已完成的任务缓存可复用（下次续跑只重跑未完成的）——优雅退出的价值是「续跑无损」
- Windows 差异：无 SIGINT 完整语义（Ctrl-C 行为不同）——跨平台信号库（或轮询 stdin/exit 事件兜底）
- 常见 bug：Ctrl-C 后端口被占（子进程没死）、缓存损坏（写入中断）——写入原子性（临时文件+rename）保护

```javascript
process.on('SIGINT', async () => {
  await Promise.race([cleanupAll(), timeout(3000)])   // 限时清理
  process.kill(-process.pid, 'SIGKILL')               // 兜底
})
// 原子写入保护缓存
tmpWrite(data); fs.renameSync(tmp, final)             // rename 原子
```
