## RBL-293：Rspack 增量模式下 Module Graph 的一致性怎么保证

**答**:
- 一致性问题三面：依赖边更新（import 变化增删边）、删除清理（文件删除后图节点回收）、顺序正确（多文件同时变更的合并处理）
- 实现要点：变更批次化（watch 事件攒批后统一失效+重建，避免逐文件重建）、图操作原子化（一批变更要么全应用要么全回滚）、引用计数清理（无引用模块出图）
- 回归守护：增量结果 = 全量结果的断言测试（fixture 变更序列），是图一致性的最后防线（见 RBL-230 方法论）
- 常见 bug 表现：偶发的「改了 A 但 B 的产物没更新」——依赖边漏更新的典型症状，靠增量回归测试捕获

```text
一致性机制：
变更批处理 → 原子应用 → 引用计数清理
守护：增量=全量 断言（变更序列快照对比）
```
