## RBL-764：场景题：数据报表场景的产物策略——大表格、图表库按需与导出功能的构建配合

**答**:
- 报表场景的构建特征：1) 图表库（echarts 类）全量引入 1MB+——按需注册（构建器 tree shaking + 手动注册图表类型，RBL-594 的副作用声明配合）；2) 表格虚拟化库与导出库（xlsx/pdf 类）是低频重资源——动态 import 边界（RBL-596：导出按钮触发才加载）；3) 主题/语言包按需（echarts locale、antd locale 动态注入）。
- 导出功能的产物策略：xlsx/pdf 生成走 Web Worker（主线程卡死是报表页最大体感问题）——worker chunk（RBL-709）+ Comlink 封装；导出库的 polyfill 兼容（worker 里的 es 目标可以更高——worker 不跑老浏览器）。
- 体积归因驱动（RBL-739）：报表页的「隐性体积」常来自——日期库全 locale、图标库全量、图表渲染器全量；归因报告 + 按需改造的量化收益是治理依据。
- 首屏与报表渲染的分层：首屏只加载「布局 + 数据获取」，表格/图表按路由懒加载——报表页的 TTI 与首屏 TTI 分开度量（交互发生在不同时刻）。
- 追问钩子：为什么「导出走 Worker」比「主线程生成」在报表场景是必选项？——万行 Excel 生成 2-5 秒，主线程冻结期间所有交互失效（用户会重复点击→双击导出→两个 worker 竞争）；Worker 让 UI 保持响应 + 导出可取消（AbortSignal）——这不是优化而是可用性底线。

```javascript
// 报表页构建配置要点
export default {
  manualChunks: { charts: ['echarts/core'] },           // 图表运行时独立 chunk
  plugins: [echartsPlugin({ autoRegister: false })],    // 按需注册
};
// 按需注册（源码侧）
import * as echarts from 'echarts/core';
import { BarChart, LineChart } from 'echarts/charts';
echarts.use([BarChart, LineChart, GridComponent, TooltipComponent]);   // 只打这几个

// 导出走 Worker（Comlink）
const exporter = Comlink.wrap(new Worker(new URL('./export.worker.ts', import.meta.url), { type: 'module' }));
const ctrl = new AbortController();
await exporter.toXlsx(rows, Comlink.proxy(signal => ctrl.signal));     // 可取消
// worker 目标更高（es2019），不参与主包 legacy 降级——构建矩阵区分
```
