## RBL-766：场景题：微前端的样式隔离构建——prefix 改写、layer 分层与运行时兜底

**答**:
- 多应用样式冲突的三层防御：1) **构建期 prefix 改写**（子应用所有选择器加 `.mf-app-a` 前缀——postcss 扫描改写，确定性最强，代价是所有选择器特异性 +1）；2) **@layer 分层**（每个应用样式放独立 layer：`@layer mf-a, mf-b`——声明序即优先级，天然防覆盖）；3) 运行时兜底（shadow DOM 或 scoped 属性）——构建期解决不了的（动态 class 注入的第三方组件）才上运行时。
- 构建期 prefix 的边界情况：keyframes 名也要改（重名动画互相覆盖）、CSS 变量跨应用共享是「故意暴露面」（token 层不改写）、:global 类样式（reset）要显式豁免清单——prefix 改写器的配置就是「隔离策略文档」。
- @layer 的加载语义：layer 声明顺序在**首次出现**时固定——多应用的 layer 声明要集中管理（宿主先声明所有 layer 名，子应用样式包在 layer 内）——构建器给每个子应用产物包 `@layer mf-app-x { ... }`。
- 字体/动画/伪元素等全局副作用的豁免审查：隔离审计器（扫描产物里的全局性选择器 html/body/#root）列出「影响宿主的清单」给评审——隔离是概率问题，审计让残留可见。
- 追问钩子：为什么构建期 prefix 优于 shadow DOM？——shadow DOM 隔离彻底但破坏全局样式约定（主题 token/全局字体无法穿透，需 CSS 自定义属性桥接）、事件重定向带来 a11y 复杂度（RBL- WCN 系列）；prefix 是「够用的隔离」且零运行时成本——多数中后台场景的最优解。

```javascript
// 构建期样式隔离器
function isolateCss(css, { prefix, exemptions = ['.reset', ':root'], layer }) {
  const body = css
    .replace(/@keyframes\s+([\w-]+)/g, (_, n) => `@keyframes ${prefix}-${n}`)      // keyframes 重命名
    .replace(/animation(?:-name)?\s*:\s*([\w-]+)/g, (m, n) =>
      /,|\s/.test(n) ? m : `animation-name: ${prefix}-${n}`.replace('animation-name', m.split(':')[0]))
    .replace(/(^|\n)([^@\n][^{]*?)\{/, ...)  // 略：选择器加前缀，豁免清单跳过
  return layer ? `@layer ${layer} {\n${body}\n}` : body;
}
// 隔离审计：全局性选择器清单
function auditGlobalSelectors(css) {
  return [...css.matchAll(/(^|\n)\s*(html|body|#root|#app)\b[^{]*\{/g)]
    .map(m => m[2].trim());                              // 影响宿主的全局选择器 -> 评审清单
}
// 宿主集中声明 layer（声明序即优先级）
// @layer mf-host, mf-app-a, mf-app-b;   —— 子应用样式构建期包入各自 layer
```
