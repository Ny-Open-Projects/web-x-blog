## RBL-545：构建正确性工程：产物语义等价的验证方法

**答**:
- 构建正确性的最高标准：**产物语义等价**（压缩/降级/摇树后行为一致）——验证方法三层：
- **L1 冒烟**：产物加载无报错（console error 监控 + 页面渲染截图对比）——最粗但必做。
- **L2 行为等价**：golden 测试——对产物跑「源码版相同的功能测试集」——测试跑在产物环境（真实 bundle 加载）而非源码模块。
- **L3 随机等价**：属性测试——生成随机输入对（源码执行 vs 产物执行）输出比对——覆盖测试集外的路径（随机执行器的成本控制：采样）。
- 正确性事故的高频来源排序：1) 压缩误删（@__PURE__ 误标）；2) tree-shaking 误摇（sideEffects 误标）；3) CSS 顺序（异步注入）；4) 循环依赖的执行序（打包后与源码序不同）——前两个靠标注规范，后两个靠产物行为测试。
- 追问钩子：正确性工程的组织保障——「正确性事故必须归因到构建器/标注/依赖三方之一并写复盘」，归因数据驱动标注规范（@__PURE__ 使用指南）的演进——正确性是持续运营不是一次性验收。

```javascript
// 产物语义等价三层验证
const CORRECTNESS = {

  L2_行为等价: 'golden 测试：测试集跑在产物环境（真实 bundle）非源码模块',
  L3_随机等价: '属性测试：随机输入对（源码 vs 产物）输出比对——采样控制成本',
  事故来源: ['压缩误删（@__PURE__ 误标）', '摇树误摇（sideEffects 误标）', 'CSS 顺序', '循环依赖执行序'],
  组织: '事故归因三方（构建器/标注/依赖）→ 复盘驱动标注规范演进——持续运营',
}
```
