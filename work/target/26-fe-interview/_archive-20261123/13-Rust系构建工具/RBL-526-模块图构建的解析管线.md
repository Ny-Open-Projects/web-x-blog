## RBL-526：模块图构建的解析管线：resolve 的四级缓存

**答**：
- `import x from 'pkg'` 的解析（resolve）是构建最频繁的操作——现代打包器的解析管线四级缓存：
- **L1 内存 Map**（specifier+context → resolved）——同进程重复 import 直接命中。
- **L2 包解析缓存**（package.json 的 main/exports 字段缓存）——同包不同 specifier 共享。
- **L3 文件系统探测缓存**（exists 检查结果缓存：.ts/.tsx/.js 后缀尝试序列）——文件系统调用是大头，缓存后 resolve 从毫秒到微秒。
- **L4 持久化**（跨进程：上次构建的 resolve 结果 + 文件 mtime 校验）——冷启动跳过全量解析。
- 解析语义的对齐负担：Node 的 exports/imports 字段条件解析（browser/node/import/require 条件）+ tsconfig paths + symlink 实路径——打包器必须完整实现这套语义，任一偏差都是「能构建但跑错文件」的隐蔽 bug。
- 追问钩子：解析管线的性能特征——「冷启动 80% 时间在 resolve」是常见现象（每个 import 都要探测文件系统）——四级缓存让二次构建 resolve 归零，这也是「持久缓存对冷启动收益最大」的原因。
