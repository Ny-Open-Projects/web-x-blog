## RBL-084：Turbopack 的 dev 为什么快？三个机制讲清
**答**：
- 机制一：函数级增量记忆化（turbo-tasks）——只重算受影响的最小计算链，其余缓存命中；比模块级缓存更细。
- 机制二：惰性按需计算——冷启动只计算浏览器请求的入口模块子图，未引用的模块完全不解析；传统工具启动即全量构建模块图。
- 机制三：Rust 原生 + 零拷贝 AST + 并行线程池——单次计算本身也快（解析/转换无 JS 开销）。
- 综合效果：冷启动（按需）+ 热更新（函数级重算）双快；官方数据大型 monorepo 冷启动从 webpack 的数十秒降到秒级，HMR 毫秒级。
- 代价：架构复杂度高（依赖追踪 overhead）、通用生态受限（webpack 插件不可用）、内存占用偏高（缓存长期驻留）。
- 追问钩子：三个机制里"惰性计算"对 monorepo 冷启动贡献最大（不触达的包不编译），这是与 Rspack 差异最显著的一点。

```text
webpack/Rspack dev 启动：解析全部 entry 可达模块 → 产出 bundle → 可服务
Turbopack dev 启动：    只注册入口 → 浏览器请求时按需编译对应模块子图

首次访问 /page1：只编译 page1 子图（其他 9000 模块未动）
HMR 改 page1 内文件：函数级重算受影响链 → 毫秒级 update
```
