## NODE-647：压测与容量评估怎么做？
**答**：
- 压测目标分层：极限吞吐（找拐点——QPS vs 延迟曲线的膝点）、稳态容量（SLO 延迟下的最大 QPS）、故障注入（依赖故障下的降级验证，SCN-OPS-281）。
- 压测方法：生产影子流量回放（真实请求分布——合成请求覆盖不了长尾）、阶梯加压（找拐点而非一步到位）、多实例验证（集群横向扩展的线性度）。
- 容量模型：实测单实例稳态 QPS × 实例数 × 冗余系数（1.5×）→ 所需实例数；瓶颈定位（CPU/连接池/下游限流——按资源维度拆解，SCN-ENG-270 容量模型联动）。
- 压测数据回流：压测发现的瓶颈（慢查询/连接池/序列化）进优化清单——压测是准入门槛（SCN-NODE 秒杀压测同源）。
- 追问钩子：为什么「影子流量回放」优于「合成压测脚本」——合成脚本通常只覆盖主路径的均匀请求，而真实流量有长尾（参数组合/缓存命中率差异/用户行为分布）；回放脱敏后的生产流量，压测结果与生产容量的换算更可信——压测的可信度取决于「流量代表性」。

```javascript
// autocannon 阶梯加压
for (const qps of [100, 500, 1000, 2000]) {
  const r = await autocannon({ url, connections: qps / 10, duration: 60, rate: qps });
  chart(qps, r.latency.p99);                           // QPS-P99 曲线找膝点
}
// 容量模型
instances = Math.ceil(peakQps * 1.5 / steadyQpsPerInstance);
```
