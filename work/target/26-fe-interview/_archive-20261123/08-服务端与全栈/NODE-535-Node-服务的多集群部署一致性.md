## NODE-535：多集群部署一致性
**答**:
- 场景：服务部署多集群（多机房多活 NODE-459/多环境集群）——配置与版本漂移是多集群的头号事故源（集群 A 有配置 B 没有 = 只有一半用户的新行为）。
- 一致性机制：同版本部署策略（发布流水线按集群顺序同步发布——发布完成定义 = 所有集群同版本 NODE-406）、配置中心按集群命名空间 + 全局配置（跨集群一致的配置单源，集群差异显式声明——ARC-415 环境矩阵的多集群版）、漂移检测（定期比对：各集群版本/配置/副本数/资源——diff 报告 + 漂移告警）。
- 部署编排：集群发布顺序（按重要性：先边缘集群验证再核心——风险分级）、集群故障时的发布降级（某集群不可达——发布跳过并标记，恢复后补齐——补齐任务防遗漏）。
- 数据层一致性：各集群 DB 版本/schema 一致（迁移按集群顺序 NODE-335——schema 漂移检测加入漂移扫描）。
- 度量：集群间漂移事件数（趋零目标）、发布跨集群完成时长（多集群发布的效率）。
```yaml
# 多集群发布编排
release:
  clusters: [edge-1, core-1, core-2]
  order: sequential           # 边缘先行
  drift-scan: daily           # 每日漂移扫描：version/config/schema
  onClusterFail: skip-and-track   # 失败跳过 + 补齐任务（防遗漏）
```
