## NODE-627：MQ 优先级消费
**答**:
- 需求：支付类消息优先于报表类——低优任务积压不能拖慢高优。实现谱系：多队列分档（高/中/低独立队列——消费者按优先级轮询：高优队列非空优先拉，BullMQ priority 支持）、加权消费（高优：低优 = 3:1 轮询配比——防低优完全饿死）、独立 worker 池（高优专用消费者——资源隔离 NODE-418）。
- 优先级语义：任务提交时声明（生产方指定——缺省中优）、优先级反转防护（高优任务依赖低优产出——依赖链优先级继承，复杂场景避免）、抢占（运行中的低优任务不中断（MQ 无抢占——靠队列调度），长任务拆分让出）。
- 延迟与时效：高优延迟 SLO（入队到开始 P95——优先级有效性指标）、低优 ETA（积压预估——透明化）。
- 治理：优先级滥用（全标高优 = 无优先级——生产方审计）、队列健康（各档积压/延迟分层监控——NODE-474 分档版）。
```javascript
// 分档轮询消费
worker.start({ queues: ['high', 'normal', 'low'], strategy: weighted(3, 2, 1) });
// BullMQ: await queue.add('pay', data, { priority: 1 })  // 数字越小越优先
// 隔离：high-queue 专用 worker 池（concurrency 独立）——低优积压不影响支付消息
```
