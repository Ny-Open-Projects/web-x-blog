## NODE-513：代码生成落地
**答**:
- 生成体系：契约单源（proto/OpenAPI）→ 生成矩阵（服务端路由骨架/客户端 SDK/文档/校验 schema——NODE-402/399 的生成层）——生成物一致性由单源保证，杜绝手写漂移。
- 生成器定制：模板定制（生成风格贴合团队规范——错误处理/日志埋点内置）、生成与手写边界（生成路由骨架 + 手写业务实现——生成不覆盖手写区（partial class 模式：生成基类 + 手写子类））。
- CI 集成：契约变更 → 生成 diff → 未更新生成物阻断（NODE-402）、生成物不入库 vs 入库的权衡（入库：review 可见 diff、离线可用——推荐入库 + CI 强制同步）。
- 脚手架：新服务模板（标准目录/配置/可观测三件套/健康检查开箱即用——NODE-435 合规的源头保证）、模板版本化（模板升级 → 存量服务的迁移 PR 自动生成——渐进统一）。
- 度量：生成覆盖率（多少接口走生成——手写接口占比下降趋势）、模板合规率（脚手架新建服务开箱合规率 NODE-435）。
```bash
# 生成流水线
pnpm gen:api        # proto/openapi → 路由骨架 + 客户端 + docs
pnpm gen:check      # CI: 生成物与契约 diff → 不一致阻断
# 目录约定：src/generated/（生成物，禁手改，CI 校验）/ src/modules/（手写区）
```
