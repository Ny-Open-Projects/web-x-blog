## NODE-418：Node 服务的资源隔离与流量分级
**答**:
- 流量分级：核心（支付/下单）、重要（商品/购物车）、边缘（推荐/统计上报/报表导出）。分级目的：资源紧张时边缘先让路，核心永远有资源。
- 隔离手段：实例隔离（边缘流量独立部署组——报表导出 NODE-386 与在线 API 分实例，导出打满 CPU 不影响下单）、线程池/连接池隔离（不同分级用不同 DB 连接池配额）、限流分层（边缘全局限流阈值远低于核心）。
- 进程内优先级：请求队列按分级调度（事件循环无法优先级调度——所以分级靠部署隔离与提前限流，而不是运行时排队）；大任务下沉 worker/MQ（NODE-348）。
- 削峰时序：过载时先限边缘（自动）、再降级非核心功能、最后保护核心（拒绝边缘新请求，核心继续服务）。
- 声明化：每个接口声明分级（路由元数据），限流/隔离/降级策略按分级自动应用（NODE-390 降级框架联动）。
```javascript
const TIERS = { core: { instPool: 'main', dbPool: 'main', limit: 1.0 },
                edge: { instPool: 'edge', dbPool: 'edge', limit: 0.3 } };
router.get('/reports/export', tier('edge'), handler);           // 边缘流量独立实例池
// 过载联动：edge 实例 CPU > 80% → 网关对 edge 路由返回 429，core 不受影响
```
