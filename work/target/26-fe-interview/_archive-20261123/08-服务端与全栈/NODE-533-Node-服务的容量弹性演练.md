## NODE-533：容量弹性演练
**答**:
- 演练目标：大促/突发时"扩容真的来得及"——HPA 配置/镜像预热/依赖容量/下游配额全链路验证（ARC-446 大促容量的常态化验证）。
- 演练内容：扩容速度（从触发到新实例接流的真实耗时：镜像拉取+启动+预热 NODE-526——目标是 < 2min）、扩容上限验证（max 副本扩满时的容量水位 NODE-433）、依赖联动（扩容后 DB 连接总和是否超限 NODE-405——演练即验证）、缩容回收（低谷缩容不影响在途请求——drain 正常 NODE-475）。
- 演练方法：压测到扩容触发（NODE-373 压测联动 HPA——真实触发而非手动 scale）、时间线记录（每阶段耗时：触发/调度/拉镜像/启动/预热/接流——瓶颈定位）、扩容上限演练（模拟 10 倍流量到 max 副本——验证容量公式）。
- 发现问题闭环：清单化修复（镜像太大拉取慢→瘦身 NODE-511；预热太慢→预热清单精简；DB 连接不够→PgBouncer）——修复后复演练。
- 频率：季度 + 大促前必演（与混沌演练 NODE-408 合并节奏）。
```yaml
# 弹性演练检查单
- 触发→接流: < 120s？(record: trigger/schedule/pull/start/warm/ready 各段耗时)
- max 副本容量: 水位 ≥ 1.3？(NODE-433)
- DB 连接: replicas × pool ≤ max？(NODE-405)
- 缩容 drain: 在途请求零失败？
```
