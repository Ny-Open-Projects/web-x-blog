## NODE-580：单元化改造路径
**答**:
- 单元化目标：用户维度分单元（set）——同用户请求闭环在单元内（数据不跨单元写——无分布式事务，容灾按单元切流 ARC-459/460）。
- 改造路径：先评估（业务数据是否可按用户分片——全局数据清单（库存/配置：跨单元数据特殊处理））、路由改造（网关按 uid 路由到归属单元——归属规则中心化 NODE-437）、数据改造（DB 按 uid 分片到单元——分片键选 uid；迁移：双写→切读→切写 NODE-438 灰度）、服务改造（单元内闭环——跨单元调用显式标记（同步调用容忍或异步投递到归属单元））。
- 难点清单：全局强一致数据（库存——单元预分配 ARC-459）、跨单元业务（用户 A 给用户 B 转账——异步化或中心化处理）、单元容量不均（迁移负载均衡——归属重算迁数据）。
- 演进节奏：按域逐步单元化（交易域先行——收益最大）、每步有回滚（单元化是长期工程——半单元化状态要可运行）。
- 验证：单元内闭环率（请求不跨单元的比例——目标 > 99%）、切流演练（单元故障切流真实可用）。
```yaml
# 单元化路由与闭环
routing: { rule: 'unitOf(uid)', units: [set-a, set-b, set-c] }
data: { shardBy: uid, globalData: [stock(预分配), config(单源广播)] }
metrics: { unitClosedRate: '>99%', crossUnitCalls: '仅异步投递' }
```
