## NODE-477：回滚演练常态化
**答**:
- 问题：回滚按钮从没按过 → 故障时不敢按/按了发现问题（回滚目标镜像已清理/迁移不兼容/配置残留）。回滚演练 = 定期真实回滚一次发布，验证整链路。
- 演练内容：回滚目标存在性（保留 N 个历史镜像/制品 ARC-469 滚动保留策略）、回滚速度（从决策到流量切回的实际耗时——MTTR 组成部分）、回滚后功能验证（老版本核心链路 E2E NODE-464）、回滚与迁移兼容（代码回滚 + DB 新 schema 的兼容性 NODE-335 多步迁移保证）。
- 频率与时机：月度（挑非核心服务）、季度（核心服务演练 + 大促前必演）、与混沌演练合并（NODE-408 场景：发布 + 回滚组合）。
- 演练发现的问题闭环：清单化修复（目标镜像清理策略/回滚步骤自动化缺失/验证脚本缺失）→ 修复验证 → 更新预案（NODE-429）。
- 文化：把"回滚"去污名化（回滚是正常操作不是失败——快速回滚的团队比硬扛的团队故障时间短一个量级）。
```yaml
# 回滚演练剧本（月度）
playbook: rollback-drill
steps:
  - deploy: { image: previous-stable }            # 真实回滚一次
  - verify: { e2e: core-flows, metrics: error-rate<0.1%, duration: expect<120s }
  - findings: record → 修复清单（如：镜像保留策略/验证脚本缺失）
cadence: monthly
```
