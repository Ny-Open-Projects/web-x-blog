## FRP-321：框架运行时剖析：组件生命周期模型的对比

**答**：
- 生命周期三模型：React「渲染纯函数 + effect 表达时序」（无生命周期概念，只有提交后的 effect）、Vue「显式生命周期钩子」、Solid「无生命周期（组件函数只跑一次，effect 是唯一时序原语）」
- 心智差异的根源：React 每次渲染重跑组件体（闭包陷阱来源）、Solid 只跑一次（响应式绑定长期存活）、Vue setup 一次 + 响应式（与 Solid 近）
- effect 对齐表：useEffect ≈ onMounted + 依赖追踪 ≈ watchEffect + onCleanup——跨框架迁移时「生命周期映射表」是基建
- StrictMode 双执行的模型差异：React 需要幂等（渲染可丢弃）；Solid/Vue 无此要求——迁移 React 代码到细粒度框架时 StrictMode 依赖会失效
- 迁移陷阱清单：React 的「每次渲染新闭包」假设（事件处理器捕获旧值）在 Solid 是 bug 源（值长期新鲜反而不同）——语义反转的坑

```text
生命周期对齐:
  React useEffect(fn, [])      ≈ Vue onMounted(fn)      ≈ Solid onMount(fn)
  React useEffect(fn, [a])     ≈ Vue watch(a, fn)        ≈ Solid createEffect
  React useEffect(() => cleanup) ≈ onCleanup (Vue/Solid)
模型差异: React 重跑组件体(闭包) vs Solid 一次(新鲜闭包) — 语义反转!
```
