## FRP-351：框架运行时剖析：组合式抽象的演进共识

**答**：
- 演进共识三条：逻辑复用从 mixin/HOC → 组合函数（显式依赖）→ signal/可独立运行的响应式内核——「隐式依赖消灭」是主线
- 各家现状：React hooks（顺序绑定）、Vue composables（作用域绑定）、Solid/Svelte5（signal/runes——无绑定）、Qwik（useTask）——绑定越少可移植性越强
- 新共识「响应式原语独立化」：TC39 Signals 提案 + @vue/reactivity 可独立使用——组合函数的核心（响应式）脱离框架成为标准库
- 对团队的意义：组合函数设计向「内核 + 胶水」演进——useUser 内核（纯状态机）+ 框架绑定层——迁移成本下降
- 面试表达：mixin 命名冲突/HOC 嵌套地狱 → hooks 显式但绑定 → signal 无绑定——用「依赖声明方式」串起演进史

```text
演进主线: 隐式依赖 → 显式依赖 → 无绑定
  mixin:   命名冲突, 来源不明
  hooks:   显式调用顺序绑定 (React)
  signal:  响应式内核独立 (Solid/TC39 提案)
团队策略: 内核(纯状态机) + 胶水(框架绑定) 分层
```
