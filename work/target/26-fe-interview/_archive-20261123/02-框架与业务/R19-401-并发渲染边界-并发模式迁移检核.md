## R19-401：并发模式迁移检核：legacy root 到 concurrent 的行为差异

**答**：
- 差异清单：render 同步→可中断（依赖同步 DOM 读的代码要检查）、setState 批处理范围扩大（原生事件内）、Suspense 语义（不提交变隐藏挂载）、effect 时序（passive 调度）
- 检核方法：concurrent root 灰度跑「全量回归 + 长任务监控」——「同步读 DOM 后 setState」的代码模式全仓扫描（grep flushSync 需求）
- 典型翻车点：拖拽库在 mousemove 里读 DOM + setState 假设同步——并发下读到旧位置；修复「ref 直接操作 DOM + 结束时同步状态」（R19-375 模式）
- createRoot vs hydrateRoot：SSR 场景用 hydrateRoot（并发水合）；错用 createRoot 会导致全树重建
- 收口指标：并发开启前后 INP/长任务数/内存对比——行为差异最终量化到指标

```text
迁移检核清单:
  [ ] 无渲染中同步读 DOM 假设
  [ ] 全部外部订阅已迁移 useSyncExternalStore
  [ ] Suspense fallback 的 UX 重验
  [ ] SSR 用 hydrateRoot
  [ ] INP/长任务前后对比
```
