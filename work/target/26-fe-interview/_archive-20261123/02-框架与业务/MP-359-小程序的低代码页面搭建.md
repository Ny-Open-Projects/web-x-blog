## MP-359：小程序的低代码页面搭建：DSL 与渲染引擎

**答**：
- 低代码两形态：楼层配置化（运营配置预定义组件——MP-357）vs 页面搭建（拖拽生成整页 DSL）——表达力与可控性递增
- DSL 渲染引擎：JSON 树（组件树 + 绑定表达式）→ 渲染层递归模板（通用渲染模板消费 JSON）——「渲染层递归」的深度限制（栈深——树深 <20 层）
- 表达式引擎：DSL 里的绑定表达式（{{ state.count > 3 }}）——安全子集求值（自研表达式解析器，禁 Function/eval——CSP 类安全）
- 事件协议：DSL 声明的事件 → 内核路由到「动作编排」（调接口/跳页/弹层）——低代码的「行为定义」是难点
- 深水点：低代码与代码的混合——「逃生组件」（低代码里嵌自定义组件——注册表协议）——纯低代码表达不了的复杂逻辑的出口

```javascript
// DSL 渲染引擎
function renderNode(node, ctx) {
  const comp = REGISTRY[node.type];                 // 组件注册表
  const props = evalExpr(node.props, ctx);          // 安全表达式求值
  return comp({ ...props, children: node.children?.map((c) => renderNode(c, ctx)) });
}
// 渲染层递归模板 (WXML):
// <template name="node"><block wx:for="{{node.children}}"><template is="node" data="{{node: item}}"/></template></template>
// 深度限制: DSL 校验层限制树深 <20, 避免 WXML 递归栈溢出
```
