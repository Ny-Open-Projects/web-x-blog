## MP-306：小程序组件通信体系：properties/triggerEvent/relations

**答**：
- 组件通信四通道：properties（父→子，类型校验 + observer）、triggerEvent（子→父）、slot/抽象节点（内容分发）、relations（跨层级树关系——父子/祖先关联）
- properties 的 observer 性能：每次 setData 到属性都触发——重逻辑 observer 是性能坑；改用 observers 声明式（多属性合并监听）+ 防抖
- relations 的场景：树形组件（子需要父的 API——form 与 form-item 的经典关系）——跨组件层级（不一定是直接父子）的强关联
- this.selectComponent 的正确用法：父调子方法（命令式逃生口）——滥用会导致耦合（改用事件驱动优先）
- 深水点：虚拟节点（virtualHost: true）——自定义组件不产生真实 DOM 节点（样式穿透/布局类组件必需），selectComponent/类名行为改变

```javascript
Component({
  options: { virtualHost: true },                    // 不生成 wrapper 节点
  properties: { value: { type: String, observer: 'onValueChange' } },
  observers: { 'value, disabled': function (v, d) { /* 多属性合并监听 */ } },
  relations: {
    './form': { type: 'ancestor', linked(t) { this.form = t; } },  // 祖先关联
  },
  methods: {
    onValueChange(v) { /* 轻: 仅同步内部态 */ },
    validate() { return this.form?.rules ?? []; },
  },
});
```
