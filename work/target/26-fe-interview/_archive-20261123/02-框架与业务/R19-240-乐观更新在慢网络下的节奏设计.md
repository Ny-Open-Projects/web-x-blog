## R19-240：慢网络下乐观更新的确认节奏怎么设计？
**答**：
- 超时阈值：action 超过 3s 未确认，乐观 UI 附加「保存中…」微提示（弱化视觉），让用户知道还在等待而非已成功。
- 更长（10s+）：提示「网络缓慢，正在重试」，必要时前端主动断开重试（幂等前提下）。
- 队列积压：连续操作超过 N 条未确认时停止乐观（缓冲上限），防止一次失败回滚一大片。
- 交互兜底：乐观 UI 状态可中断——用户关闭页面时 pending 的 action 结果丢失，重进页面以服务端为准，设计上不允许「本地独有状态」依赖乐观层。
