## FRP-309：框架运行时剖析：各框架的批处理与调度对比

**答**：
- 批处理机制对比：React（自动批处理 + lane 调度，宏任务切片）、Vue（微任务队列 flush，nextTick 边界）、Solid（同步 + transaction 批处理可选）、Svelte5（microtask 批）——批处理边界决定「同一 tick 多次写的渲染次数」
- 可中断性：只有 React 有真正的可中断渲染（时间片）；Vue 的同步 patch 在大树下不可打断——「交互优先」策略的框架差异
- 观测实验：同一 tick 内 N 次状态写 → 各框架渲染次数（React 1/Vue 1/Solid 0~1）——实验化理解比背结论可靠
- 与浏览器帧对齐：React 主动让出（5ms 切片）、Vue 依赖 nextTick 微任务边界、Solid 不让（更新极快无需）——「对帧率的贡献」不同
- 业务含义：高频更新场景（拖拽/实时数据）选型差异——细粒度框架天然无批处理烦恼，VDOM 框架靠批合并

```text
同一 tick 3 次写的渲染次数:
  React 18+: 1 (自动批处理)
  Vue3:     1 (nextTick 微任务 flush)
  Solid:    ~0 额外 (每次写直接定向更新, 无渲染概念)
```
