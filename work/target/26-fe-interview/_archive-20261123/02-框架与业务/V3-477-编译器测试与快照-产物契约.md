## V3-477：编译器测试与快照：产物契约怎么验

**答**：
- 编译器测试三层：快照测试（产物代码字符串快照，改动可见 diff——Vue 仓库维护上千个 __snapshots__）、语义测试（编译产物执行行为断言）、错误用例测试（非法输入报错信息与 loc）
- 快照的价值与陷阱：锁定产物契约（下游 Taro/uni-app fork 依赖产物形状）；但快照会让「无害重构」产生大量 diff 噪音——配合 semver 约束产物稳定性
- 语义测试（端到端）：编译产物在 jsdom 真跑——断言「点击后 emit 正确」「v-for 渲染条数」——只测编译不测行为会漏掉 helper 版本错配
- 自定义编译插件的测试策略：单测 transform 函数（输入 AST 断言输出 AST）+ 快照产物——AST 级断言比字符串快照稳定
- 工程化：编译器升级走「产物 diff 审查」（PR 里展示编译产物变化）——像 review 代码一样 review 编译产物

```javascript
// 语义测试示例
const { code } = compileTemplate({ source: '<button @click="add">{{n}}</button>' });
const render = new Function('Vue', `${code}; return render`)({ ...runtime });
// jsdom 挂载 → 模拟点击 → 断言 n 变化
```
