## FRP-307：框架迁移中的渐进桥接策略

**答**：
- 迁移形态光谱：整页替换（风险大）、路由级共存（新旧框架各管部分路由）、组件级嵌入（新框架组件嵌老页面）——按耦合度递增
- 桥接层设计：共享态（用户/购物车）用框架无关内核 + 双适配器；路由打通（URL 驱动，两边各自解析）；样式互不污染（前缀/scoped）
- 事件与导航统一：导航事件桥（A 框架页面跳到 B 框架路由——统一走 history API + 双方路由监听）
- 数据流打通：API 层共享（请求封装独立包）+ 状态桥（FRP-303 模式）——迁移期「双份请求」的浪费靠共享缓存层解决
- 收口标准：迁移完成 = 桥接层可删——「桥接是脚手架不是永久架构」的心态管理

```text
迁移桥接清单:
  [ ] 状态内核 + 双适配器 (用户/购物车)
  [ ] 路由统一 (history API 驱动)
  [ ] API 层共享包
  [ ] 样式隔离 (前缀/scoped)
  [ ] 事件桥 (CustomEvent 协议)
```
