## MP-336：小程序自定义组件的性能面：生命周期与渲染时机

**答**：
- 生命周期时序：created（实例化，不能 setData）→ attached（可 setData）→ ready（视图层就绪，可查询布局）→ detached——「查询布局必须在 ready 后」是高频 bug
- observers 与 setData 的关系：组件自身 setData 触发 observers（data 驱动）——「observer 里再 setData」的循环风险（条件终止）
- 组件的 setData 频率：组件内部状态更新也是跨线程通信——「列表项组件的高频动画」放 WXS/worklet 而不是组件 data
- lifetime 优化点：detached 清理（IO observer/定时器——组件级泄漏）+ lifetimes 统一写法（lifetimes 字段优先于旧式 attached）
- 深水点：lifetimes.ready 的批量查询——组件树大量 ready 并发 boundingClientRect——合并查询（父组件统一 measure 子树）减少 IPC 次数

```javascript
Component({
  lifetimes: {
    attached() { this._timer = setInterval(this.tick, 1000); },
    ready() { this.createSelectorQuery().select('.inner').boundingClientRect((r) => this.init(r)).exec(); },
    detached() { clearInterval(this._timer); this._io?.disconnect(); },   // 清理防泄漏
  },
  observers: {
    'value'(v) { if (v !== this._last) { this._last = v; this.setData({ inner: v * 2 }); } }   // 条件终止防循环
  },
});
```
