## V3-383：SSR 服务端内存泄漏怎么排查？
**答**：
- 常见来源：模块级缓存无上限（Map 只进不出）、请求上下文挂到全局、定时器/监听器未清理、onServerPrefetch/async setup 内副作用滞留。
- 排查路径：heap snapshot 对比（压测前后 diff，看 Retained Size 最大的构造函数，找 app/组件实例计数不降的）→ 按引用链定位模块 → 修复后压测复验。
- 防护手段：请求级上下文（Nuxt useRequestEvent 作用域）而不是模块级变量；给缓存加 LRU/TTL；定期优雅重启兜底。
- 指标：常驻内存斜率 + GC 后回收率，Prometheus + 压测脚本回归。
- 案例：详情页数据用了模块级 Map 缓存且 key 含用户参数，QPS 高时缓存百万条——改 LRU 1000 条解决。
