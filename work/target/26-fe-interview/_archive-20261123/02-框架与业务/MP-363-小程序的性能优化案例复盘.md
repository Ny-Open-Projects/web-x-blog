## MP-363：小程序性能优化案例复盘：从 4s 到 1.2s 的启动优化

**答**：
- 基线：启动 4s（主包 2.1MB + 全量组件注入 + 首页串行请求）——按链路拆解（下载/注入/执行/渲染四段）
- 第一刀（下载）：主包瘦身 2.1MB→0.9MB（图片出包/死代码清理/分包三业务域）——下载时间 -60%
- 第二刀（注入与执行）：lazyCodeLoading requiredComponents + 首页代码精简（首页依赖组件数 -30%）——注入执行 -40%
- 第三刀（渲染）：initialRenderingCache + 上次数据缓存 + 接口预取并行（login 与 home 接口同时发）——首屏数据等待 -50%
- 结果与方法论：4s→1.2s（P75）——「链路拆解 → 各段击破 → 指标验收」；每刀独立 AB 验证（贡献度归因，防止「都归功于最后一刀」）

```text
优化链路拆解:
  下载 1.8s → 0.7s   (主包瘦身: 2.1MB→0.9MB)
  注入 0.8s → 0.4s   (lazyCodeLoading)
  执行 0.6s → 0.3s   (首页精简)
  渲染 0.8s → 0.2s   (缓存+预渲染+并行请求)
  合计 4.0s → 1.6s → 继续细挖 → 1.2s
每刀: 独立灰度 + AB 归因
```
