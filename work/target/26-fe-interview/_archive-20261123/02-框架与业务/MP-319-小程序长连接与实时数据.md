## MP-319：小程序长连接：WebSocket 与实时数据

**答**：
- wx.connectSocket 约束：并发 5 个、域名白名单、小程序切后台 5s 后断连（iOS）——「后台断连 + 回前台重连」是标准生命周期处理
- 重连设计：指数退避 + onNetworkStatusChange（网络恢复立即重连）+ 心跳（ping/pong 30s——服务端 idle 断连检测）
- 消息补拉：重连后 lastSeq 补拉增量（与 FRP-359 同协议——断线期间消息不丢）——补拉接口（HTTP）与 WS 通道的双轨
- 连接管理单例：App onLaunch 建连、页面共享（监听器注册/注销按页面生命周期）——多页面共用一条连接的引用计数
- 深水点：切后台的消息感知——断连期间的推送进「未读」；onShow 时补拉 + 未读角标——「后台丢失的实时性」用补拉兜底

```javascript
// App onShow 重连
onShow() { ws.ensureConnected(); }   // 内部: 若 socket 已断 → 重连 + afterSeq 补拉
// 页面级监听
onLoad() { this._off = ws.on('msg', (m) => this.append(m)); }
onUnload() { this._off(); }          // 页面卸载注销, 连接保持(App 级)
// 心跳: setInterval(() => ws.send({ type: 'ping' }), 30_000) — onclose 后重连退避
wx.onNetworkStatusChange(({ isConnected }) => isConnected && ws.ensureConnected());
```
