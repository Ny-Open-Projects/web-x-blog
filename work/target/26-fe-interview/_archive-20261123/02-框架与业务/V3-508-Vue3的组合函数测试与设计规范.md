## V3-508：组合函数设计规范：从 useFoo 到可复用资产

**答**：
- 设计规范：入参支持 ref/getter 与原始值（toValue 统一）、返回 refs（对象解构保响应式，storeToRefs 语义）、副作用可清理（onScopeDispose 或返回 stop）——三条是「好的 composable」判据
- 异步 composable 模板：status(data/error/loading) 状态机 + 竞态守卫 + 可选缓存——不要让调用方处理 Promise 内部
- 依赖注入式配置：全局配置用 provide/inject（组件库上下文），composable 内 inject 默认值——可测试性（测试时 provide mock）
- 组合而非堆叠：composable 之间可以互相组合（useUser 内用 useFetch）——但避免深层链（A→B→C→D 调试地狱）；跨层通信显式参数
- 资产化：composables 目录 + 命名规范（use 前缀 + 领域）+ 文档（参数/返回/副作用）——团队复用的最小工程约束

```javascript
export function useUser(getId) {
  const id = computed(() => toValue(getId));
  const state = reactive({ data: null, loading: false, error: null });
  const stop = watch(id, async (v) => {
    state.loading = true;
    try { state.data = await fetchUser(v); state.error = null; }
    catch (e) { state.error = e; }
    state.loading = false;
  }, { immediate: true });
  onScopeDispose?.(stop);            // 自动清理(组件内) || 手动调用返回值
  return { ...toRefs(state), stop };
}
```
