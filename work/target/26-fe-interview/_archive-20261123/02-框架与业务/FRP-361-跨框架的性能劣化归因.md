## FRP-361：跨框架的性能劣化归因

**答**：
- 跨框架特有的劣化源：桥接层高频同步（事件风暴）、内核状态过期重算（订阅链长）、双框架各自批处理边界错位（一帧两次渲染）
- 归因工具链：内核层打点（set/get 计数）→ Performance 面板按「框架渲染任务」分色（React devtools 调试标记）——分清「哪个框架在花时间」
- 典型案例：内核 store 高频写（实时行情）→ 两框架各渲染一次 → 帧超时——修复「内核合帧」（16ms 窗口合并通知）
- 基线管理：单框架版本的性能基线保留——「跨框架化前后」对比是归因的锚点
- 修复优先级：桥接层（架构问题）> 框架内优化（局部问题）——跨框架的劣化多数在边界上

```text
归因链:
  劣化出现 → 内核打点 (set 频率/通知次数)
  → Performance 分色 (React 时间 vs Vue 时间 vs 桥接时间)
  → 定位边界问题: 桥接风暴/批处理错位/订阅链长
  → 修复: 内核合帧 / 事件节流 / selector 细化
```
