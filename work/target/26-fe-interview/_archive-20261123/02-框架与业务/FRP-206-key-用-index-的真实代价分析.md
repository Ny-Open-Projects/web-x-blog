## FRP-206：key 用 index 的真实代价（带案例）？
**答**：
- 案例一：头部插入。index key 让第 0 行复用为「新头部内容」——组件 state（勾选、滚动、输入）全部错位。
- 案例二：排序。反转列表时所有 key 对应内容变化，等价于全量更新 + 所有子组件重渲染，比无 key 更差（还骗了 key 复用检查）。
- 案例三：删除中间项。后面全部错位。
- 何时 index 可接受：列表纯静态展示（渲染后不增删排序）、无子组件 state。
- 正确姿势：稳定业务 id；服务端列表 id 天然可用；临时项用 uuid。
