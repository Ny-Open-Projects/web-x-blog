## R19-404：并发渲染边界：并发特性在 SSR 场景的边界

**答**：
- SSR 侧没有并发渲染：renderToPipeableStream 是流式但不可打断（服务端 CPU 可控）——transition/deferredValue 在服务端渲染时退化为同步
- useDeferredValue 的 SSR 行为：服务端用初始值渲染（initialValue 参数）——水合后客户端才进入两轮渲染
- transition 在水合前的语义：未水合的组件上触发 transition——React 排队到水合完成后执行；「水合前点击」由事件重放机制承接
- Suspense 服务端与客户端的一致性：服务端 boundary 决定「哪部分流式」——客户端 transition 打断只影响 client 子树
- 落地检查：SSR 页面用并发 API 时——验证「服务端输出」「水合后行为」两阶段分别符合预期（快照对比工具）

```text
SSR: 流式不可打断, deferredValue=initialValue, transition 排队
水合: 选择式水合 + 交互重放
水合后: 并发渲染全量生效
检查点: 服务端 HTML 快照 ≠ 客户端可交互行为, 两阶段分别验证
```
