## MP-341：小程序分享与裂变：技术设计要点

**答**：
- 分享三形态：onShareAppMessage（好友/群）、onShareTimeline（朋友圈——静态展示）、小程序码海报（保存图片发圈）——触达面与转化差异
- 分享卡片优化：title 文案 A/B、imageUrl 比例（5:4 最佳展示）、path 参数（落地页 + 归因）——「卡片即广告位」的设计
- 裂变链路：邀请关系绑定（inviter 参数 → 落地解析 → 服务端绑定关系——防刷（同一设备/频率限制））+ 奖励发放（服务端校验）
- 防刷设计：设备指纹（openid + 系统信息弱指纹）、邀请上限、奖励延迟发放（T+1 审核）——裂变活动的风控是技术+产品联合
- 深水点：分享路径的容量限制（path 长度）——参数过多用「分享 id 换参数」（服务端存分享上下文，path 只带 shareId）

```javascript
onShareAppMessage() {
  const shareId = await createShareContext({ act: 42, inviter: this.uid });   // 服务端存上下文
  return {
    title: '帮我砍一刀，立减 50',
    path: `/pages/kill/index?sid=${shareId}`,     // 短参数
    imageUrl: 'https://cdn.example.com/kill-share.jpg',
  };
}
// 落地: onLoad({ sid }) → api.getShareContext(sid) → 归因绑定 + 防刷校验
```
