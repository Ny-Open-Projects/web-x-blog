## V3-507：渲染函数与 h()：什么时候绕过模板

**答**：
- 绕过模板的合法场景：高度动态的组件结构（可视化编辑器画布）、需要程序化生成 vnode（表格列渲染器）、JSX/TSX 团队偏好——模板是默认，render 是逃生口
- h() 与编译产物的对齐：手写 render 没有 patchFlag/静态提升（编译器不接管）——手写 render 的组件天然无编译优化，更新走全量 diff；热点组件慎用
- JSX 生态：@vitejs/plugin-vue-jsx 提供 patchFlags 优化（babel 插件）——TSX 的类型安全与编译优化可兼得
- 函数式组件（无状态）：`(props) => h(...)`——轻量包装（透传插槽/加壳）；没有实例（无 this），响应式依赖在 render 内自动追踪
- 实战建议：动态结构用「模板 + 动态组件」先试；确实需要程序化（树/图渲染递归）才 render——可维护性优先

```javascript
// 函数式组件
const Badge = (props, { slots }) =>
  h('span', { class: ['badge', props.type] }, slots.default?.());
Badge.props = ['type'];
// 程序化: 表格列渲染
function renderCell(col, row) {
  return col.custom ? col.custom(h, row) : h('span', row[col.key]);
}
```
