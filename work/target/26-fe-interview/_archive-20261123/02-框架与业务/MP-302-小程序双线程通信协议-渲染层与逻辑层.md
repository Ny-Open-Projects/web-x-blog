## MP-302：双线程通信协议：渲染层与逻辑层的边界

**答**：
- 双线程模型：逻辑层（JS 在 JSCore/V8，无 DOM）、渲染层（WebView 渲染 WXML）——「逻辑不可碰 DOM」决定了所有交互都要走通信
- 通信协议三条通道：setData（逻辑→渲染，数据）、事件（渲染→逻辑，bindtap 等）、节点查询（SelectorQuery，跨线程异步）——每条都是异步 IPC
- 设计含义：同步 DOM API 全部缺失（offsetWidth 不存在）——布局感知改用「渲染层通知」（bindlayout 不可用，改 WXML 结构反馈或 boundingClientRect 异步）
- 与 Taro3 运行时的关系：Taro 把 vdom 操作「翻译」成 setData——双线程协议是其底座（通信量优化的根因）
- 深水点：渲染层也有 JS（WXS）——高频 UI 逻辑（动画/滚动联动）放 WXS 避免跨线程往返——「WXS 是渲染层的逃生口」

```text
双线程通道:
  逻辑层 --setData(data)--> 渲染层 (JSON 序列化 + diff)
  渲染层 --event(e.g. bindtap)--> 逻辑层
  逻辑层 <--SelectorQuery--> 渲染层 (异步查询)
WXS: 渲染层内 JS, 绕过跨线程 (动画/滚动联动唯一可行方案)
```
