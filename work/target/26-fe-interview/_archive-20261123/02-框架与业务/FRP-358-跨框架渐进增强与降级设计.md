## FRP-358：跨框架渐进增强与降级设计

**答**：
- 渐进增强的分层：HTML 可用（无 JS 表单提交——server action/form 原生）→ 增强交互（JS 挂载）→ 富交互（框架完全接管）——每层可独立工作
- 跨框架的增强一致性：React19 form action 与 Vue 的渐进方案（无 JS 也能提交）——「无 JS 底线」在跨框架页面统一
- 降级设计：JS 失败（chunk 加载失败）→ 静态内容仍可读/表单原生提交——「内容不丢」是底线
- 检测与提示：noscript 层 + JS 错误时的「降级横幅」（重试按钮 reload）——用户体验闭环
- 深水点：增强层与降级层的双实现成本——只对「核心转化路径」（登录/支付）做完整渐进，长尾页面放弃无 JS 支持

```text
渐进分层:
  L0: HTML (表单原生提交, server action) — 无 JS 可用
  L1: +JS (框架水合, 交互增强)
  L2: +增强 (transition/乐观更新)
底线: L0 核心路径不丢; L2 失败降级 L1
```
