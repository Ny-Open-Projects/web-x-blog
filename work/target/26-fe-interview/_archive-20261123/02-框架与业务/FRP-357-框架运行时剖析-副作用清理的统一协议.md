## FRP-357：框架运行时剖析：副作用清理的统一协议

**答**：
- 清理协议设计：资源注册表（register(resource, disposer)）+ scope 语义（tryOnScopeDispose/onCleanup 对齐）——内核层实现，各框架 hook 接入
- 各框架的清理原语映射：React effect cleanup / Vue onScopeDispose / Solid onCleanup——统一协议的 dispose() 由各层翻译
- 清理顺序：注册逆序（后进的先清）+ 依赖顺序（消费者先于生产者）——泄漏与悬挂引用的防护
- 验证手段：清理完整性测试（mount → unmount × N → 断言资源数归零）——「资源计数器」探针
- 与 StrictMode 的关系：双执行要求清理幂等——协议层规定 disposer 必须可重入

```javascript
// 清理协议内核
export function createScope() {
  const disposers = [];
  return {
    register(resource, dispose) {
      disposers.push(dispose);
      return resource;
    },
    listen(el, ev, fn) { el.addEventListener(ev, fn); disposers.push(() => el.removeEventListener(ev, fn)); },
    dispose() { for (const d of disposers.reverse()) try { d(); } catch {} },   // 幂等可重入
  };
}
// 各框架绑定: React useEffect(() => scope.dispose(), []) / Vue onScopeDispose(...)
```
