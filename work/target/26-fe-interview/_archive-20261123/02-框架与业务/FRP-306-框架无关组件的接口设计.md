## FRP-306：框架无关组件的接口设计：以 Web Components 还是包装层

**答**：
- 两条路线：Web Components（真跨框架，但 React/Vue 各自的集成摩擦——属性/事件/样式桥）、多框架包装层（内核逻辑共享 + 每框架薄壳 React/Vue/Solid 各实现渲染）
- WC 的摩擦清单：属性序列化（对象 props 要 JSON attribute 或 property 手桥）、事件自定义（CustomEvent）、样式隔离（shadow 与全局主题的冲突）、SSR（Declarative Shadow DOM 支持度）
- 包装层路线的成本：每个壳的渲染实现 + 状态桥接——组件多时维护翻倍；适合「核心少数组件」（设计系统的 Button/Input）
- 决策公式：组件交互密度（高交互 → WC 桥接成本高）× 框架数量——低交互展示组件 WC、高交互组件「逻辑内核 + 框架壳」
- 类型系统共享：内核 props 类型定义一份，各壳 re-export——接口一致性的工程保障

```javascript
// 内核逻辑(框架无关)
export function useCounterLogic(initial) {
  let n = initial;
  const listeners = new Set();
  return {
    get: () => n,
    inc() { n++; listeners.forEach(f => f(n)); },
    sub(fn) { listeners.add(fn); return () => listeners.delete(fn); },
  };
}
// React 壳: useSyncExternalStore 消费
// Vue 壳: customRef 消费
// WC 壳: attribute + CustomEvent
```
