## MP-332：Taro 编译时 vs 运行时方案的取舍

**答**：
- 编译时方案（Taro1/2）：Babel 把 React/JSX 编译成各端模板代码——性能好（无运行时翻译）但语法受限（静态模板/不能动态组件/受限的条件渲染）
- 运行时方案（Taro3）：完整 React 语义 + 运行时翻译——语法自由（生态兼容）但双层成本（diff+通信）
- uni-app 的中间路线：Vue 模板编译时映射（模板语法天然接近小程序模板）+ 部分运行时——Vue 语法映射成本低于 JSX
- 决策框架：业务复杂度（动态组件/复杂状态 → 运行时）vs 性能敏感度（长列表高频更新 → 编译时或原生）——混用策略（核心性能页原生、业务页 Taro）
- 深水点：编译时方案的「逃逸口」缺失——运行时方案兜底复杂场景；「跨端一致性」的测试成本（编译时方案的端差异 bug 更隐蔽）

```text
取舍矩阵:
  编译时: 性能高 / 语法受限 / 端差异隐蔽
  运行时: 语义完整 / 双层成本 / 一致性易测
  策略: 业务页 Taro3(运行时) + 性能页原生 — 混合架构
```
