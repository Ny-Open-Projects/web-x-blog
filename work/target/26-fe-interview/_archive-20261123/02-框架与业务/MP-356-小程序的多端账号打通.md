## MP-356：多端账号打通：openid/unionid 与账号体系

**答**：
- ID 体系：openid（单 appid 内用户标识）、unionid（同主体多端统一标识——绑定开放平台后）、手机号（跨生态标识）——三层 ID 的打通策略
- unionid 的获取条件：小程序与公众号/其他应用绑定同一开放平台账号——「先绑开放平台再上线」是架构前置决策
- 账号合并场景：用户先用 H5（手机号注册）再用小程序（openid 登录）——服务端按手机号合并账号（合并策略：保留旧号/字段级合并/登录提示选择）
- 换绑与解绑：手机号换绑的安全流程（验证旧手机号）——多端会话的一致失效（换绑后其他端 token 全失效——强制重新登录）
- 深水点：多端登录态的一致性——同账号多端在线的 token 策略（并存 vs 单点踢出）——按业务选择（IM 类单点、内容类并存）

```text
ID 打通:
  openid  (单端标识, 每个小程序不同)
  unionid (同开放平台主体统一)
  phone   (跨生态最终锚点)
合并链路: openid 登录 → 无账号 → 手机号授权 → 匹配已有账号 → 绑定 unionid → 合并
```
