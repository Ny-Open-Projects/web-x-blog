## FRP-326：框架运行时剖析：列表渲染策略的框架差异

**答**：
- key 对齐算法差异：React 两轮遍历（位置→key map），Vue3 双端 + LIS（最小移动），Solid 无 diff（For 组件按引用 track）——同一数据变更的 DOM 移动次数不同
- index key 的行为差异：React/Vue 的 index key 在头部插入时状态错位；Solid 的 <For> 按引用追踪（无 key 概念）天然正确——「key 心智」的框架差异
- 部分更新路径：React 需要父组件重跑 + diff；Vue 细粒度（item 是 reactive，改字段只更新对应绑定）；Solid 直接定向——列表更新成本光谱
- 大列表的统一解：虚拟化（三种框架都靠窗口化解决渲染量）——框架差异被虚拟化掩盖（真正瓶颈是 DOM 量）
- 迁移注意：React 的「key 稳定性」最佳实践在 Solid 反而多余——跨框架团队的规范要按框架分叉

```text
列表更新 1000 项换 1 项:
  React:  父 render + 两轮 diff + 1 处 patch
  Vue3:   双端 diff + LIS (移动最少) + 定向 patch
  Solid:  <For> 引用追踪 → 只动那一项 (无 diff)
共识: >500 项一律虚拟化, 框架差异被窗口化掩盖
```
