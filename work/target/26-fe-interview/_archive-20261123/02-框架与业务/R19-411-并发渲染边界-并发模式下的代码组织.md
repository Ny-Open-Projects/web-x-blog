## R19-411：并发渲染边界：并发模式下的代码组织规范

**答**：
- 状态写入分层：输入类同步（直接 setState）、结果类 transition（startTransition 包裹）、乐观类 optimistic（useOptimistic）——团队规范明确「哪类状态走哪条通道」
- 副作用出口集中：外部订阅统一 useSyncExternalStore、命令式操作统一 ref API——禁止散落的 window/document 直读
- transition 的命名与范围：hook 封装（useNavigatingTransition）而不是裸 startTransition——范围可审计（哪些更新允许被打断）
- lint 规则集：react-hooks（依赖完整性）+ compiler eslint（可缓存性）+ 自定义（禁止渲染中读 window / 禁止 transition 包输入）
- 评审清单：新状态通道正确？副作用有 cleanup？外部源撕裂安全？——并发规范的 CR 化

```text
代码组织规范:
  输入状态 → useState 同步
  计算密集结果 → useDeferredValue / transition
  外部数据 → useSyncExternalStore + selector
  乐观交互 → useOptimistic
  命令式库 → ref + useEffect 桥接
CR 清单: 通道正确 / cleanup / 撕裂安全
```
