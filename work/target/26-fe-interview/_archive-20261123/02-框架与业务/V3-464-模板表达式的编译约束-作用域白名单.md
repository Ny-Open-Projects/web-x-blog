## V3-464：模板表达式的编译约束：作用域白名单与 prefixIdentifiers

**答**：
- 模板表达式不是裸 JS：编译器用 Babel 解析表达式 AST，做 prefixIdentifiers——把 `msg` 加前缀 `_ctx.msg`、`$setup.x`（script setup）、`$slot` 等
- 作用域白名单：已知全局（Math/Date/console 等白名单）不加前缀，未声明变量在 dev 模式编译报错（防止模板里访问未定义变量静默 undefined）——「模板里拼错变量名编译期就报」的价值
- 组件标识符：`<Comp/>` → `_resolveComponent('Comp')`（runtime 自动导入注册组件）或编译期静态导入（script setup 时直接引用变量）——script setup 免去 resolve 的开销
- 表达式内不可以写语句（if/for）、只能单表达式；多语句报错——表达式 AST 校验
- 深水点：with 前缀的 runtime 编译（CDN 模板）与 prefix 编译（构建时）产物差异——`with(this){}` 性能差且禁用于 CSP

```javascript
// {{ msg.toUpperCase() }} 编译产物
_toDisplayString(_ctx.msg.toUpperCase())
// script setup: { { count } } → $setup.count
// runtime 模板(CSP 不友好):
new Function('with(this){ return _renderList(...) }')  // 退化形态
```
