## R19-410：并发渲染边界：并发渲染下的埋点一致性

**答**：
- PV/曝光的歧义：渲染被丢弃重来——「曾渲染过但未提交」的页面/元素算不算曝光？——以「commit 完成」为埋点时机（useEffect 触发），丢弃渲染天然不触发
- 点击归因：Transition 期间的点击（旧 UI 上的）——事件发生在旧内容上但结果提交的是新内容——埋点带「当时上下文」（旧页面 id）而不是最终路由
- 曝光去重的并发影响：同元素因重渲染多次触发 IO 回调——去重键（元素 id + commit 版本）防重复计数
- 性能埋点的口径：组件渲染耗时（Profiler）要与「丢弃渲染」区分（phase: 'mount'/'update'，丢弃的没有 onRender）——Profiler 只报提交的渲染
- 设计原则：埋点在「事实发生层」（DOM/网络）而不是「渲染尝试层」——并发渲染的中间态不是事实

```jsx
useEffect(() => {                     // commit 后才触发 → 丢弃渲染不计
  exposure.track(itemId);
}, [itemId]);
// 点击归因: capture 时的上下文
const onClick = () => track('click', { from: currentRouteId, to: targetId });
```
