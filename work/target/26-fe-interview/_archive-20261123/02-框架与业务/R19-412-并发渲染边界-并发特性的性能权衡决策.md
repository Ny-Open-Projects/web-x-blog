## R19-412：并发渲染边界：并发特性的性能权衡决策框架

**答**：
- 决策维度四问：这个更新能被打断吗（语义上可丢弃）？中断的用户感知是什么（旧内容可接受）？成本（双渲染/内存）收益（输入延迟下降）比？测试与维护成本？
- 适用矩阵：大列表过滤/导航切换（适用 transition）、重计算派生（适用 deferredValue）、实时预览（适用 transition）、支付确认（不适用——不可丢弃）
- 成本模型：transition 双渲染成本 ≈ 2×渲染耗时，换来「输入即时」；小组件不划算（直接同步更快）——量化阈值：渲染 >16ms 才考虑
- 度量驱动决策：INP P75 改善 × 影响 PV → 收益量化；内存增量 → 成本量化——数据决策不是潮流决策
- 回滚预案：并发特性开关（业务层包装），劣化时退同步——决策可逆

```text
决策树:
  更新渲染 >16ms?
    ├─ 否 → 同步 setState (省双渲染)
    └─ 是 → 中断可接受?
        ├─ 是 → transition (输入即时)
        └─ 否 → 同步 + 业务级防抖/虚拟化
```
