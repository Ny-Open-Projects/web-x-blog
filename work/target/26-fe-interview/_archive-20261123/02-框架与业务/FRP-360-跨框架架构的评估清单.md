## FRP-360：跨框架架构的评估清单：什么时候值得上

**答**：
- 值得上跨框架的信号：并购/团队栈分裂（被迫共存）、大型老系统渐进迁移（逐页换）、组件复用跨产品线（设计系统多栈）——「共存现实」驱动而非技术偏好
- 不值得的信号：单团队两框架（维护翻倍无收益）、性能借口（单框架调优空间远大于框架差异）、招聘借口（框架不是招聘瓶颈）
- 成本核算：双 runtime 体积、内核抽象层、双测试矩阵、团队认知负荷——「跨框架税」年化估算
- 决策流程：先尝试「单框架收敛」（迁移计划）→ 收敛不可行（时间/政治约束）才跨框架架构——架构是妥协的产物要诚实
- 落地检查单：内核 API 冻结、桥协议文档化、双壳 CI、性能预算、团队 onboarding 文档——五项齐备才开工

```text
决策树:
  团队栈分裂/并购/渐进迁移?
    ├─ 是 → 跨框架架构 (五项检查单齐备)
    └─ 否 → 单框架收敛 (迁移计划) ← 默认答案
成本: 双 runtime ~80KB + 内核抽象 + 双测试矩阵 + 认知负荷
```
