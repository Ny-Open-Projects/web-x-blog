## FRP-343：框架运行时剖析：并发渲染对数据层的要求

**答**：
- 并发渲染的数据层要求：快照一致（渲染中读到的数据不中途变）、可取消（丢弃渲染时请求可 abort）、渲染与数据解耦（数据层独立于渲染轮次）
- React 数据层的适配：useSyncExternalStore 快照化（撕裂防护）——「数据层必须在渲染期稳定」是硬约束
- 细粒度框架的宽松性：无并发渲染，数据层直接订阅即可——迁移 React→Solid 时数据层约束放松
- 缓存层的轮次语义：请求级缓存（cache()）绑定「渲染轮次」——并发下同轮次共享、跨轮次重新评估——React 19 cache 的设计动机
- 设计清单：数据层 API 不得「渲染中触发副作用」（fetch in render 需缓存）、写操作与渲染轮次解耦（乐观更新协议）

```text
并发渲染 × 数据层:
  要求: 快照一致 / 可取消 / 副作用不在渲染中
  机制: useSyncExternalStore + 请求级 cache + transition 包提交
  细粒度框架: 无此约束 (数据层更简单)
```
