## MP-311：小程序订阅消息：授权时机与触达链路

**答**：
- 订阅消息模型：一次性订阅（一次授权一条消息）vs 长期订阅（特定类目）——「授权一次发一条」的现实约束决定产品策略
- 授权时机设计：在「价值时刻」请求（下单成功时请求发货通知）——首屏弹授权的拒绝率极高；拒绝后引导「设置里开启」（openSetting）是唯一补救
- 链路：前端 wx.requestSubscribeMessage(tmplIds) 拿授权 → 服务端 subscribeMessage.send（带 openid + 模板数据）——授权凭证由前端拿、发送在服务端
- 触达兜底：订阅消息未授权/已消费 → 短信/公众号模板消息兜底——「触达矩阵」按用户授权状态分级
- 深水点：多次授权累积——用户可勾选「总是保持以上选择」→ 长期订阅效果；授权状态的查询（服务端记录发送次数与授权次数对比）

```javascript
// 价值时刻授权: 下单成功后
async function afterOrderCreated(orderId) {
  const res = await wx.requestSubscribeMessage({ tmplIds: [SHIP_TPL, PROMO_TPL] });
  const accepted = res[SHIP_TPL] === 'accept';
  await api.reportSubscribe({ orderId, ship: accepted });   // 服务端记录授权状态 → 触达矩阵
}
// 服务端: wx.requestSubscribeMessage 每次授权可发一条 → 授权计数管理
```
