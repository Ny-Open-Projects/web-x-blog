## R19-409：并发渲染边界：并发特性在移动端的适配

**答**：
- 移动端约束：CPU 弱（时间片 5ms 内完成的渲染更少）——并发切片的价值更大（输入不卡），但单次渲染更慢（切片更多）
- 设备分档降级：低端机关闭 transition（退同步渲染，减少双缓冲内存）——通过 UA/内存 API 检测；React 没有运行时开关，用业务层包装（低端机不包 transition）
- WebView 差异：Android WebView 的 MessageChannel 延迟波动——Scheduler 时间片对齐偏差；实测弱机 P95 帧时间校准业务阈值
- 内存红线：双缓冲 + Activity 隐藏树在低端机 OOM 风险——隐藏实例数上限、大树拆 root
- 评估方法：分档真机矩阵（S/A/B 档）跑核心路径——并发收益（输入延迟）与成本（渲染耗时/内存）分别量化

```text
移动端分档策略:
  S 档: 全并发特性 (transition/activity/deferred)
  A 档: transition + deferred
  B 档: 同步渲染 + 虚拟列表 (省内存)
  依据: navigator.deviceMemory + 真机 P95 帧时间
```
