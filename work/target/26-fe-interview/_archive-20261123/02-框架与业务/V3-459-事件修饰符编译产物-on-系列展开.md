## V3-459：事件修饰符编译产物：.stop/.prevent/.self 系列展开

**答**：
- 修饰符编译为 wrapper 函数链：.stop → withModifiers(..., ['stop']) 内部 e.stopPropagation；.prevent → preventDefault；.passive 标记监听选项；.capture 反转捕获——运行时 withModifiers 一次处理全部修饰符
- 按键修饰符：@keyup.enter → _withKeys(handler, ['enter'])，运行时查 keyCode 表匹配——.exact 精确匹配修饰键组合
- 系统修饰键（.ctrl/.meta）：运行时检查 event 的对应布尔属性——编译层只是把修饰符字符串传给 helper，判断逻辑全在 runtime（这是「编译产出薄、runtime helper 厚」的设计）
- 事件缓存（cacheHandlers）：内联 handler（@click="count++"）被缓存为 _cache[0]，避免每次渲染创建新函数 → 子组件 props 浅比较不被击穿——等价于手写 useCallback
- 深水点：修饰符顺序影响执行顺序（@click.prevent.self 阻止自身触发 vs @click.self.prevent 只在 self 时 prevent）——编译层保留顺序，runtime 按序执行

```javascript
// @click.stop.prevent="onClick" 编译产物
_onClick: _withModifiers(_cache[0] || (_cache[0] = (...args) => _ctx.onClick(...args)),
  ['stop', 'prevent'])
// @keyup.enter → _withKeys(handler, ['enter'])
```
