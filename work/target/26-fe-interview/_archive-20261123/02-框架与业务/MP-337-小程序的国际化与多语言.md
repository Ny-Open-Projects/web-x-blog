## MP-337：小程序的国际化：多语言方案与坑

**答**：
- 方案：语言包 JS 模块（函数 t(key)）+ WXS 内嵌翻译（渲染层直接用——高频列表文案）双层——逻辑层 t() + 渲染层 WXS 版本
- 切换语言：setLocale → 全页面重渲染（遍历页面栈 setData 语言包引用）——「切换即时生效」需要所有活跃页面通知
- WXS 限制：WXS 不能 require 逻辑层模块——语言包要在 WXS 内独立（构建期注入或传参）——双份语言包的一致性（构建期同源生成）
- 布局适配：RTL 小程序支持有限（多数市场是 LTR）——国际化重点是多语言长度（德语长文案）导致的布局弹性（flex 换行预留）
- 深水点：语言包按需加载（分包语言包——用哪个业务加载哪个）+ 缓存（storage 存当前语言包避免重复加载）

```javascript
// 逻辑层 t()
const { t, setLocale } = require('../../i18n/index');
// 渲染层 WXS
// <wxs src="./i18n.wxs" module="i18n" />
// <view>{{i18n.t('buy', langPack)}}</view>   ← langPack 由逻辑层 setData 注入当前语言包
// 切换:
async function switchLang(l) {
  const pack = wx.getStorageSync(`lang:${l}`) || await require(`../../i18n/${l}.js`);
  getApp().globalData.lang = l;
  getCurrentPages().forEach((p) => p.setData({ langPack: pack, locale: l }));  // 全栈通知
}
```
