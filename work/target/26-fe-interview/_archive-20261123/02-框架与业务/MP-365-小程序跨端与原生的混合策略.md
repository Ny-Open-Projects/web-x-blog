## MP-365：小程序跨端与原生的混合策略

**答**：
- 混合动机：Taro 全量方案的「双层成本」在性能敏感页不可接受——「性能页原生、业务页 Taro」的混合拓扑
- 混合的边界：原生页面与 Taro 页面互跳（路由统一——Taro 路由与原生路由的 URL 规范统一）；共享状态（globalData/store 单源）；共享组件（原生组件跨用——Taro 可引用原生组件但样式对齐成本）
- 目录拓扑：src/pages（Taro 业务页）+ native-pages（原生页，构建时合并进 app.json）——构建编排（Taro 构建产物与原生页 json 合并）
- 决策标准：页面交互密度（拖拽/手势/长列表 → 原生）与开发效率（表单/展示 → Taro）——「按页面性能画像」分配
- 深水点：混合的维护成本——两套技术栈的心智与规范——「混合边界文档化」（哪些页面为什么原生）防止边界漂移

```text
混合拓扑:
  Taro 页: 业务表单/展示 (开发效率)
  原生页: 直播间/IM/长列表 (性能上限)
  统一: 路由规范 / globalData store / 主题 token
构建: Taro build + native-pages 合并进 app.json
边界文档: 每个原生页标注「为什么不用 Taro」— 防漂移
```
