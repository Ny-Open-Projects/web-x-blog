## FRP-329：框架运行时剖析：事件系统差异与合成事件

**答**：
- React 合成事件：委托到 root（17+），合成事件对象池化（17 废弃池化）、e.nativeEvent 访问原生——委托带来的「冒泡截断」边界（e.stopPropagation 只在合成层）
- Vue 事件：直接 addEventListener 到元素（无委托统一层）——行为最接近原生；修饰符编译进 handler
- Solid/Svelte：原生事件直绑——事件处理器是编译期确定的
- 跨框架事件桥的根基：React 合成事件不跨 root 冒泡——跨框架通信必须走原生 CustomEvent（FRP-304）
- 性能含义：委托（React）适合大量同类型事件（列表点击）；直绑（Vue/Solid）在少量事件上更省——事件量级的选型因素

```text
事件系统对比:
  React:  root 委托 + 合成事件 (stopPropagation 合成层语义)
  Vue:    元素直绑 + 修饰符编译
  Solid:  元素直绑 (编译期)
跨框架: 合成事件不跨 root → CustomEvent(bubbles+composed) 桥接
```
