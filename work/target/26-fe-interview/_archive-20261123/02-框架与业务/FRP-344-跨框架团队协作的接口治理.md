## FRP-344：跨框架团队协作的接口治理

**答**：
- 接口三件套：组件壳接口（props 协议 + 类型包）、内核 API（状态/服务语义 + 文档）、桥接协议（事件 schema）——每层有 owner 与版本策略
- 版本策略：内核 semver 严格（破坏性变更走迁移指南）、壳层跟随内核 minor、桥协议加版本字段（新消息兼容旧订阅者）
- 变更流程：内核 PR 需要「双框架影响面评估」（两壳是否需要同步改）——CI 跑双壳测试集
- 废弃管理：deprecated API 保留两个 minor + 运行时警告（dev）——跨框架团队的协调成本更高（周期拉长）
- 治理工具：API Extractor 冻结签名（变更 diff 进 PR review）——接口漂移的机械防护

```text
接口治理:
  内核 API: semver 严格 + owner + 迁移指南
  壳层:     跟随内核 minor
  桥协议:   版本字段 + 双向兼容窗口
CI: API 签名 diff 强制 review + 双壳测试集
```
