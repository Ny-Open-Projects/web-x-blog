## MP-324：小程序灰度发布与版本管理

**答**：
- 版本形态：开发版（IDE/预览码）、体验版（审核前内测）、正式版（审核发布）——发布链路「上传 → 提审 → 发布」，审核周期约束节奏
- 灰度能力：发布后的「全量/分阶段放行」（微信后台按比例）——小程序原生灰度比 Web 弱（无路由级灰度），动态化靠配置中心
- 配置中心兜底：小程序内容热更（代码必须发版，但文案/开关/接口地址可远程下发）——「不发版修配置」的能力边界要清楚
- 版本回退：后台支持回退到上一版本（分钟级）——回滚预案比 Web 简单（整包切换）
- 深水点：多版本共存问题——用户停留旧版本（未重启）与新版接口不兼容——「接口向后兼容 1~2 个版本」是小程序 API 设计纪律；体验版与正式版环境隔离（测试数据不进生产）

```text
发布流程:
  IDE 上传(开发版) → 设为体验版(内测) → 提交审核 → 发布(灰度比例)
  回滚: 后台一键回退上一版 (分钟级)
约束: 代码热更不可行 → 配置中心承载开关/文案
纪律: API 向后兼容 2 个小程序版本 (用户升级滞后)
```
