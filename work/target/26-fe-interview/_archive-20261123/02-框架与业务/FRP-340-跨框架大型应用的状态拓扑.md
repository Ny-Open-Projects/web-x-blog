## FRP-340：跨框架大型应用的状态拓扑

**答**：
- 拓扑设计：内核层（会话/权限/全局配置——跨框架共享）+ 域层（各框架页面的业务状态，不跨框架）+ 局部层（组件内）——「共享最小化」原则
- 判定标准：状态被 ≥2 框架消费 → 内核；单框架多页面 → 框架内 store；单页面 → 组件——拓扑自上而下收敛
- 数据流方向：内核单向下发 + 事件上行（内核不改域层状态）——双向依赖是耦合灾难
- 内核的规模控制：内核状态膨胀（业务态混入）→ 退化为全局大 store——定期审计「谁在消费」（订阅者统计）
- 与微前端的配合：内核 = 微前端通信总线的状态面（FRP-317 事件面 + 本卡状态面）——两平面清晰分工

```text
状态拓扑:
  内核层: session / auth / flags / theme   (跨框架共享, 最小集)
  域层:   react-store / vue-store          (框架内)
  局部:   组件 useState / ref
流向: 内核 → 下发; 事件 → 上行; 禁止跨层双向
```
