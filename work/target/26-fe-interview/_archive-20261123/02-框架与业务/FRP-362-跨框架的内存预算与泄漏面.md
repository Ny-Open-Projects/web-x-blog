## FRP-362：跨框架的内存预算与泄漏面

**答**：
- 泄漏面扩展：单框架泄漏面（组件/副作用）+ 桥接泄漏面（总线订阅未清/内核持有的框架对象）+ 微前端泄漏面（子应用卸载残留）
- 内核层的持有关注点：内核 store 不应持有「框架组件实例」（传数据不传实例）——传实例即泄漏（框架卸载后实例被内核挂着）
- 订阅生命周期审计：内核 sub() 的返回清理必须被框架层调用——「谁订阅谁清理」写进协议 + 泄漏检测（sub 计数 vs unsub 计数）
- 检测方法：Heap Snapshot 按「框架内部构造器 × 内核对象」交叉——FiberNode 挂在内核 Map 上就是跨框架泄漏指纹
- 预算分配：内核 <5MB、各框架 <15MB（中型应用）——超预算告警化

```text
泄漏面检查单:
  [ ] 总线 sub/unsub 计数平衡
  [ ] 内核不持有框架实例 (只传数据)
  [ ] 子应用卸载后 bridge 清理 (按 source)
  [ ] snapshot: 内核 Map 无 FiberNode/VNode 引用
预算: 内核 <5MB / 每框架 <15MB
```
