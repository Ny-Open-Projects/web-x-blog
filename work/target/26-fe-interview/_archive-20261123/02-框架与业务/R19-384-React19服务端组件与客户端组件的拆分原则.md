## R19-384：Server/Client 组件拆分原则

**答**：
- 拆分判据：需要交互/浏览器 API/生命周期 → Client；纯数据展示/DB 访问/密钥操作 → Server；「服务端数据 + 本地交互」→ Server 父 + Client 叶（数据作为可序列化 props 下传）
- client 叶子最小化：交互组件只接收「必需 props」（可序列化），重数据留在 server 侧渲染成 HTML——bundle 体积与服务器负载的双赢
- children 穿透模式：Server 组件可以作为 children 传给 Client 组件（`<ClientShell>{<ServerContent/>}</ClientShell>`）——布局 client、内容 server 的经典结构（保留 server 渲染）
- 反模式清单：把整个页面做成 client（回到 SPA）、server 组件里藏交互（跑不起来）、props 传不可序列化对象（构建报错）
- 迁移策略：先全 server（默认），逐个把交互叶子标 'use client'——bundle 增长曲线决定拆分深度

```jsx
// Server
async function Page() {
  const data = await db.query();               // 服务端
  return <Tabs>{data.map(g => <TabPanel key={g.id} content={g.html} />)}</Tabs>;
}
// Client 壳(布局交互), 内容仍是 server children
'use client';
function Tabs({ children }) { /* 切换逻辑 */ return <div>{children}</div>; }
```
