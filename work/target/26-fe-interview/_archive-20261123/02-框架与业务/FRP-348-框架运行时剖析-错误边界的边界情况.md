## FRP-348：框架运行时剖析：错误边界的覆盖盲区与补齐

**答**：
- 双框架的盲区对照：React 边界不捕（事件/异步/setTimeout）；Vue errorHandler 全捕但无「边界恢复」（onErrorCaptured 只拦截不恢复）——语义互补
- 补齐模式：异步错误「同步化」（async 错误手动 throw 进边界/用 use 的 promise）；Vue 的恢复用「key 重挂」模拟 React 边界
- 统一恢复协议：无论框架，恢复 = 「重新执行失败的子任务」——错误对象带「重试闭包」（哪个函数失败了）才能精准恢复
- 全局兜底的一致性：uncaught error → 全局错误页（两框架同策略）——兜底层的 UX 一致性
- 监控口径：边界捕获的错误与全局兜底的错误分开统计——「框架内可控错误」vs「失控错误」的比例是架构健康度指标

```text
边界盲区对照:
  React:  事件/异步/setTimeout 不捕 → 异步错误同步化 (throw promise/use)
  Vue:    errorHandler 全捕但不恢复 → key 重挂恢复
统一协议: error { retry: () => Promise }  — 恢复 = 重执行失败子任务
```
