## FRP-320：跨框架的类型系统共享

**答**：
- 共享三层的类型：领域模型（实体/枚举——最稳定）、API 契约（请求/响应 schema——zod 单源生成）、组件 props（接口层——各框架壳 re-export）
- zod 单源模式：schema 定义一次 → 类型推断（z.infer）+ 运行时校验 + 文档生成——类型与校验永不漂移
- props 类型的框架差异：React 的 FC Props vs Vue 的 defineProps 泛型——内核 props 类型定义一份，壳层适配（Vue 宏的类型生成对齐）
- monorepo 里的类型包：@acme/types（领域）/ @acme/api-schema（契约）——组件包依赖二者，跨框架一致性的编译期保障
- 深水点：跨框架枚举/字面量联合的一致性——「magic string」是跨框架 bug 高发（React 侧 'active' vs Vue 侧 'ACTIVE'）——常量包收敛

```typescript
// zod 单源
export const OrderSchema = z.object({
  id: z.string(), status: z.enum(['pending', 'paid', 'shipped']),
  amount: z.number().int(),
});
export type Order = z.infer<typeof OrderSchema>;   // 类型从 schema 推导
// React 壳: FC<{ order: Order }>
// Vue 壳: defineProps<{ order: Order }>()
```
