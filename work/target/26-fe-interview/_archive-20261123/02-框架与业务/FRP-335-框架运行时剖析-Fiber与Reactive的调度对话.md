## FRP-335：框架运行时剖析：调度系统对话——让出与批处理的哲学

**答**：
- 两种调度哲学：React「抢占式」（时间片内让出，高优可打断——复杂度换体验）、细粒度「协作式」（更新本身够快无需让出——简单换性能）——没有对错只有负载适配
- React 让出的代价：双缓冲内存、丢弃重渲、状态快照复杂度——「让出」不是免费的
- 细粒度不需要让出的原因：单次更新传播路径短（<1ms），渲染队列天然不积压——「快到不需要调度」
- 混合趋势：React Compiler 让 React 更新变快（趋近协作式需求减少）；Vapor 让 Vue 保持批处理但传播更短——殊途同归「更短的更新路径」
- 面试表达：用「队列积压」模型统一解释——调度器解决积压，细粒度消灭积压

```text
积压模型:
  更新速度 < 到达速度 → 队列积压 → 需要调度器 (React)
  更新速度 >> 到达速度 → 无积压 → 无需调度 (Solid)
React Compiler: 降低单次更新耗时 → 让出需求减少
结论: 两条路线都走向「更短的更新路径」
```
