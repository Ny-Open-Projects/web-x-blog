## FRP-311：框架无关的数据获取层设计

**答**：
- 分层：内核（请求执行/缓存/去重/重试——纯 JS）+ 框架绑定（React Query for React、Vue Query、Solid Query——TanStack 全家桶证明「内核 + 多绑定」可行）
- 内核 API 设计：query(key, fetcher, { staleTime, gcTime })——键化缓存 + 订阅通知；mutation 同构
- 绑定层职责：订阅 → 框架响应式（useSyncExternalStore/customRef/signal）+ 生命周期（挂载触发、卸载 GC）
- 设计取舍：自研内核 vs 直接用 TanStack Query（多框架支持）——业务复杂度低用现成，有特殊协议（RPC/GraphQL 订阅）才自研
- 深水点：内核与框架绑定的「快照一致性」——React 绑定必须走 useSyncExternalStore（撕裂防护），不能简单 useState

```javascript
// 内核
class QueryCore {
  #cache = new Map();
  query(key, fetcher, { staleTime = 30_000 } = {}) {
    const e = this.#entry(key);
    if (e.promise) return e.promise;                        // 去重
    if (e.data && Date.now() - e.at < staleTime) return Promise.resolve(e.data);
    e.promise = fetcher().then((d) => { e.data = d; e.at = Date.now(); e.notify(); return d; })
      .finally(() => e.promise = null);
    return e.promise;
  }
}
// 各框架绑定层薄壳(~100行/框架)
```
