## FRP-313：框架性能基准测试方法论

**答**：
- 基准维度五类：创建（首渲染 N 项）、更新（替换/部分更新 N 项）、高频交互（每帧更新）、内存（N 组件实例）、体积（runtime gzip）——js-framework-benchmark 的维度即此
- 方法论红线：预热（JIT）、取中位数不取均值、控制变量（同一数据形态/同 key 策略）、真机矩阵（桌面结论不外推移动端）
- 基准的欺骗性：微基准（单行更新）不代表业务负载；key 策略/渲染粒度的业务差异比框架差异影响更大——「基准赢 ≠ 业务赢」
- 自建基准的姿势：用「自家业务的关键路径」（真实列表形态/真实更新模式）写基准——比通用基准有决策价值
- 汇报规范：给场景化结论（「大列表部分更新 Solid 快 3x」「交互输入 React 19 与 Solid 差距 <20%」）而不是「谁最快」

```text
可信基准检查单:
  [ ] 预热 ≥ 50 次
  [ ] 中位数 + P95 (非均值)
  [ ] key 策略一致 (id vs index)
  [ ] 真机矩阵 (低端安卓必测)
  [ ] 业务形态负载 (非微基准)
```
