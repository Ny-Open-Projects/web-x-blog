## V3-202：Vue 3.5 双向链表依赖结构是怎样组织的？对比 Set 存储优势在哪？
**答**：
- 数据结构：属性 dep 仍是 `Map<target, Map<key, Dep>>`，但 Dep 内部从 `Set<ReactiveEffect>` 变为**双向链表节点**，每个节点持有 `prevSub/nextSub` 指向同一属性的其他订阅者。
- 反向连接：每个 Effect 也持有 `deps` 链表（`deps/depsTail`），与属性的订阅链互指，形成双向图。
- 删除节点 O(1)：cleanup 时通过 `prevSub/nextSub` 直接摘除自己，不用遍历 Set 做 `delete`。
- 增量收集：effect 重新执行时只把**新读到的属性**追加到 deps 链尾部（`link()`），已存在的属性自动跳过，无需删除重加。
- 对比优势：原 Set 方案 cleanup 复杂度 O(所有依赖总数)，新方案只处理"本轮真正新增的依赖"。

```javascript
// 简化的 link/unlink 逻辑（3.5 思想）
function link(dep, sub) {
  // dep（属性侧）与 sub（effect 侧）互相挂到链表上
  const tail = dep.subsTail;
  const node = { dep, sub, prevSub: tail, nextSub: undefined };
  if (tail) tail.nextSub = node; else dep.subs = node;
  dep.subsTail = node;
  // effect 侧同样追加到自己的 deps 链
  const dTail = sub.depsTail;
  if (dTail) { node.prevDep = dTail; dTail.nextDep = node; }
  else sub.deps = node;
  sub.depsTail = node;
}
function unlink(node) { // O(1) 摘除，双向链表优势所在
  const { prevSub, nextSub, dep } = node;
  (prevSub ? prevSub.nextSub = nextSub : dep.subs = nextSub);
  if (!nextSub) dep.subsTail = prevSub;
}
```
