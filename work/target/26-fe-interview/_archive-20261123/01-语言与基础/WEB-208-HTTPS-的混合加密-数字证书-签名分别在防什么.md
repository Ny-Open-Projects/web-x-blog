## WEB-208：HTTPS 的混合加密、数字证书、签名分别在防什么？

**答**：
- 混合加密防窃听：非对称（ECDHE）只用来协商出对称会话密钥，之后全部用对称加密（AES-GCM）传数据——非对称性能差但解决密钥分发，对称快。
- 数字证书防冒充：CA 用自己的私钥给「服务器公钥 + 域名 + 有效期」签签名，浏览器用内置的 CA 根证书逐级验证证书链，确认「这个公钥真的属于这个域名」。
- 签名防篡改：握手参数与证书的签名保证了中间人无法替换公钥或篡改协商参数而不被发现。
- 三者合起来：窃听者看不到明文，中间人换不了公钥，重放/篡改会被 AEAD 校验发现。

```javascript
// 证书链校验示意
// 根 CA（浏览器内置信任）→ 中间 CA（Let's Encrypt R3）→ 站点证书（example.com）
// 校验步骤：
// 1. 用中间 CA 公钥验证站点证书签名
// 2. 用根 CA 公钥验证中间 CA 证书签名
// 3. 检查域名匹配、有效期、吊销状态（OCSP）
// 任一步失败 → 浏览器拦截并提示 NET::ERR_CERT_AUTHORITY_INVALID
```
