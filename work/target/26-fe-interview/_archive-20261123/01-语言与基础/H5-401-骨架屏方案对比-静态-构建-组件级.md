## H5-401：骨架屏方案对比：静态、构建生成与组件级

**答**：
- 三种方案：手写静态骨架（HTML 内联，最可控）、构建期从真实页面截图/结构生成（骨架一致性高、自动化）、组件级 Skeleton 组件（React/Vue 生态，灵活但依赖 JS 执行）
- 时机原则：骨架要「随 HTML 首字节到达」（内联在 HTML 里），JS 执行后才出现的骨架浪费白屏窗口——这是方案选择的硬标准
- 视觉规范：骨架布局必须与真实内容结构一致（否则数据到达后跳动）；用渐变动画（shimmer）传达加载中；暗色模式双套
- 退出时机：数据到达即替换（骨架带 min-display 时间防闪烁，约 200ms）；部分数据先到先渲染（分块替换）
- 陷阱：骨架引发的 CLS（骨架与真实高度不一致）→ 骨架按设计稿真实尺寸出图；过度骨架化（整页都是骨架反而显得慢）

```html
<!-- 内联骨架: 随 HTML 到达 -->
<div class="feed-skeleton">
  <div class="sk-card"><div class="sk-img shimmer"></div><div class="sk-line shimmer"></div></div>
</div>
```

```css
.sk-img { width: 100%; aspect-ratio: 16/9; }   /* 骨架占位=真实尺寸, 防 CLS */
.shimmer {
  background: linear-gradient(90deg, #eee 25%, #f5f5f5 50%, #eee 75%);
  background-size: 200% 100%;
  animation: shimmer 1.2s infinite;
}
@keyframes shimmer { from { background-position: 200% 0; } to { background-position: -200% 0; } }
```
