## H5-278：直播流 H5 播放的延迟与协议选择

**答**：
- 延迟梯度：HLS（6s 片×3 缓冲 ≈ 15~30s）→ LL-HLS/LL-DASH（2~5s）→ HTTP-FLV/MSE（2~3s）→ WebRTC（<1s）
- 选择逻辑：秀场/带货互动用 WebRTC 或 FLV；普通直播 HLS 够用且成本最低；大型赛事 LL-HLS 平衡延迟与 CDN 成本
- H5 实现：HLS 用 hls.js；FLV 用 flv.js（MSE 喂流）；WebRTC 浏览器原生但对 CDN 扩展成本高
- 追帧细节：播放落后于直播边缘时（buffered 末端 - currentTime > 3s），主动倍速追赶或 seek 到边缘，否则延迟越积越大
- 面试话术：先问延迟要求再选协议，是架构题的正确打开方式

```javascript
// flv.js 直播追帧
setInterval(() => {
  const end = video.buffered.at(-1)?.end;
  if (end && end - video.currentTime > 3) video.currentTime = end - 0.5;
}, 5000);
```
