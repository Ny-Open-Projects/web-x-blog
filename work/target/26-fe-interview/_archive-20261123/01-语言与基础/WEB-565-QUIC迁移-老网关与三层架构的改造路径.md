## WEB-565：QUIC 迁移：存量三层架构的改造路径

**答**：
- 改造只发生在接入层：四层 LB 要支持 UDP 443 转发（很多云 LB 默认只转 TCP），七层网关（nginx/envoy）开 QUIC 监听，业务服务零改动
- LB 层检查清单：UDP 健康检查支持、会话保持方式（按 CID 而不是四元组）、UDP 会话超时配置、是否透传客户端 IP
- 网关层：h2/h3 双栈配置、证书双协议同步、Alt-Svc 策略、qlog 采样开关
- 灰度顺序：测试环境 → 静态域名 → 动态 API → 长连接域名；每一步停留一个观察周期
- 老架构阻力点通常不是技术：是「谁签字对 UDP 通路负责」——迁移方案里要写清各层 owner 与回滚开关归属

```text
改造面:
  四层LB: 开 UDP443 转发 + 健康检查 (owner: 运维)
  七层网关: quic listen + Alt-Svc (owner: 网关组)
  CDN: h3 开关按域名灰度 (owner: CDN)
  业务: 无改动
回滚开关: 每层独立, 权限与预案提前写进迁移文档
```
