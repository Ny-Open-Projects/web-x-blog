## WEB-586：多进程模型与内存占用：浏览器怎么平衡

**答**：
- 进程上限控制：Chrome 有进程数量上限（如桌面端几十个渲染进程），超限后同站点/低风险站点开始共享进程——隔离策略是「尽力而为」而非绝对
- 内存压力回收：Windows 有内存不足时挂起后台 tab（保存渲染状态、释放进程），切回时恢复；前端 `document.visibilityState` 变化时丢部分状态配合
- 前端可观测：`performance.memory`（Chrome）看 JS 堆，`chrome://process-internals` 看进程分布；报告「页面占用」时要说清 JS 堆 ≠ 进程总内存
- 页面侧减内存就是减进程压力：iframe 数量、Worker 数量、大对象驻留都是放大器——一个页面开 10 个 Worker 在多进程模型里还叠加线程调度成本
- 移动端差异明显：iOS WKWebView 进程模型更保守（内存限额更低、进程更少），Android Chrome 才有完整站点隔离——跨端测试不能只看桌面

```javascript
// 内存压力配合: 页面被挂起/恢复时的状态管理
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    idbSet('state', snapshotState());     // 挂起前持久化
  } else {
    restoreIfStale();                      // 恢复时检查数据时效
  }
});
```
