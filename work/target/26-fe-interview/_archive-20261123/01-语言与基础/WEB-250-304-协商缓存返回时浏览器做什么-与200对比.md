## WEB-250：304 协商缓存返回时浏览器做什么？与 200 对比

**答**：
- 304 流程：缓存过期 → 浏览器带 If-None-Match（或 If-Modified-Since）发请求 → 服务端校验未变 → 只返回头 → 浏览器更新缓存的元数据（新的过期时间），继续用本地正文。
- 成本对比：304 省了响应体传输（正文不传），但仍有完整 RTT 与头部开销；200 from disk cache 零网络。所以「immutable」方案下连协商都省掉是最优。
- 304 的响应头会刷新 Cache-Control/ETag，相当于续约缓存有效期。
- 常见 bug：服务端 304 响应头里没带新的 Cache-Control，浏览器沿用旧过期时间，可能造成二次过期抖动。

```text
首次: 200 + Cache-Control: max-age=60 + ETag "v1"   （60 秒强缓存）
60s 内: (from disk cache)                            零请求
60s 后: GET If-None-Match: "v1" → 304                刷新有效期
对照: HTML 用 no-cache → 每次都 304 往返（1 RTT），发版即时生效
```
