## JS-353：performance.measureMemory 与内存监控 API

**答**：
- performance.measureMemory()（Chrome）：返回 Promise 的 { bytes, breakdown }——按 URL/JS 运行域聚合的精确内存；非阻塞（异步等 GC 后测量），比 performance.memory 的估计值可靠
- performance.memory（Chrome 老接口）：同步返回 usedJSHeapSize/totalJSHeapSize/jsHeapSizeLimit——值是近似且受 GC 时机影响，趋势监测可用，绝对值别信
- measureMemory 的精度开关：需 COOP/COEP（crossOriginIsolated）才有 breakdown 详情——跨源隔离是精确测量的前提
- 监控策略：定时采样（10s 间隔）+ 页面切换前后采样对比 + 增长率告警（10 分钟持续增长 = 泄漏嫌疑）；iOS 无 API → 只能靠页面崩溃率间接推断
- 汇报口径：内存监控报「趋势与增长率」而不是绝对值；结合 long task/GC 频率关联分析

```javascript
async function memProbe() {
  if (performance.measureMemory) {
    const { bytes, breakdown } = await performance.measureMemory({ detailed: true });
    beacon({ bytes, byUrl: breakdown.map(b => ({ url: b.url, bytes: b.bytes })) });
  } else if (performance.memory) {
    beacon({ used: performance.memory.usedJSHeapSize, trendOnly: true });
  }
}
setInterval(memProbe, 10_000);
```
