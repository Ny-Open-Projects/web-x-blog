## JS-327：分代 GC 细节：Scavenge 与三色标记

**答**：
- Scavenge（新生代）：Cheney 复制算法——From 空间存活对象按广度优先复制到 To 空间，然后空间互换；存活率低时极快，但空间利用率 50%
- 三色标记（老生代）：白（未访问）→灰（已访问未处理引用）→黑（处理完）；标记结束仍白 = 垃圾——配合写屏障（write barrier）在并发标记期间记录 JS 线程的新引用，防止漏标
- 增量/并发策略：增量标记（标记与 JS 交替执行）、并发标记（后台线程标记）、惰性清理（按需清理页面）——Major GC 的停顿被拆到毫秒级
- 晋升条件：对象经历一次 Scavenge 仍存活，或 To 空间已满——短命大对象意外晋升是内存问题常见根源
- 前端可感知现象：Major GC 触发时帧掉落（性能面板有 GC 事件）；「分配越多 GC 越频繁」的本质是新生代半空间耗尽

```text
新生代: From --复制存活--> To (快, <1ms级)
老生代: 白→灰→黑 三色标记 (并发+增量, 停顿拆碎)
写屏障: JS 写入对象引用时记录, 防并发标记漏标
验证: Performance 面板搜 "GC" 事件, 看 Minor/Major GC 耗时
```
