## H5-406：移动端缓存命中率与 CDN 策略

**答**：
- 缓存分层：浏览器（memory/disk）、SW 预缓存/运行时缓存、CDN 边缘、源站——命中率要分层统计（CDN 面板 + 前端 transferSize 判断）
- 静态资源：hash 文件名 + Cache-Control: immutable, max-age=1y——命中即零请求；HTML: no-cache（协商缓存 304）
- 移动端特有：iOS ITP 7 天清理存储（长期不访问的用户 SW 缓存也没了，要评估重装成本）；弱网下 304 仍有 RTT 成本，高频小文件可考虑本地版本号跳过协商
- API 缓存：GET 接口按数据时效分级（配置类 cache-first + 短 TTL、列表 SWR、个人数据 no-store）；私有数据严禁公共 CDN 缓存（Cache-Control: private）
- 缓存污染防护：query 参数规范化（utm 等参数剥离缓存 key）、错误响应短 TTL 防负缓存

```text
策略速查:
  app.[hash].js  → Cache-Control: public, max-age=31536000, immutable
  index.html     → Cache-Control: no-cache (协商)
  /api/config    → s-maxage=60, stale-while-revalidate=300
  /api/me        → Cache-Control: private, no-store
命中率目标: 静态资源 CDN 命中 >95%, HTML 边缘命中 >60%
```
