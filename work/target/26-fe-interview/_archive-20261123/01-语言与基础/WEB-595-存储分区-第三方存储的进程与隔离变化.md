## WEB-595：存储分区（Storage Partitioning）：第三方存储的隔离变化

**答**：
- 存储分区：第三方上下文（跨站 iframe、第三方 worker）的 localStorage/IndexedDB/Cookie/缓存按「顶层站点」分区——同一个第三方站点在 a.com 和 b.com 里是两份存储
- 动机：阻断跨站跟踪（第三方 cookie 被分区后无法用存储指纹串联用户）
- 架构关联：分区后的第三方 iframe 数据按 partition key 隔离，进程分配也倾向按站点组合分——第三方脚本在多个宿主站点的缓存完全独立
- 业务影响：支付/社交等第三方 iframe 内「记住用户」的能力被削弱，第三方 iframe 内登录态要靠 partitioned cookie（`Partitioned` 属性）或自己的会话管理
- 迁移注意：清缓存/统计逻辑要按「站点+分区」维度理解命中率，跨站点共享数据必须走服务器

```text
key 结构: (top-site, iframe-site)
  user 在 a.com 的 cdn-tracker.com iframe 存储 ≠ 在 b.com 的同一 iframe 存储
Cookie: Set-Cookie: sid=xxx; Secure; Partitioned; HttpOnly
  → 分区 cookie, 仅在第一方上下文内有效
```
