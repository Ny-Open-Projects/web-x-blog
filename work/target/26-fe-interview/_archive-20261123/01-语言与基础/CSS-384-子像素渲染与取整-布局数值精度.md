## CSS-384：子像素渲染与取整：布局数值精度问题

**答**：
- 布局精度：现代引擎布局保留小数（getBoundingClientRect 返回小数），但设备像素网格上光栅化会取整——三等分 33.33% 列在物理像素上产生 1px 缝隙/重叠（dpr 非 3 整倍数时）
- 缝隙修复：等分列加背景同色（缝隙隐形）、重叠 1px（负 margin/outline 覆盖）、或用 repeat(auto-fit, minmax(0,1fr)) 让引擎分配而不是手写百分比
- 边框与 1px 问题：dpr=2 下 0.5px 物理边框可行（部分内核）、transform: scaleY(.5) 方案（H5-336）、SVG 线条 width 用对齐像素——「细线」是子像素问题的招牌场景
- 动画中的取整抖动：transform 平移小数在合成器内不做布局取整（浮点合成，平滑）；但 offsetTop/width 动画每帧取整产生「爬行感」——动画用 transform 的又一理由
- 测量一致性：JS 测量（offsetWidth 取整 vs getBoundingClientRect 小数）与 CSS 布局比较时统一口径，否则出现「算出来的和渲染的不一样」

```css
/* 三等分缝隙修复 */
.grid3 { display: grid; grid-template-columns: repeat(3, minmax(0, 1fr)); }
.grid3 > * + * { border-left: 1px solid var(--border); }  /* 边界显式化 */
/* 细线 */
.hairline { height: 1px; transform: scaleY(.5); transform-origin: top; }
```
