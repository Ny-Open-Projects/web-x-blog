## WEB-435：多端登录互踢怎么设计，前端如何感知被踢

**答**：
- 策略光谱：单端互踢（新挤旧）→ 多端共存（上限 N 台）→ 分端共存（Web+App 各一台）；产品决定，技术实现只是承接
- 服务端为每个会话发 sessionId/deviceId，踢线即把目标会话标记失效
- 前端感知三通道：长连接下发 kick 消息（最实时）→ 轮询/接口 401 特殊码 → storage 事件同域多 tab 联动
- 收到踢线后统一动作：清本地 token/Cookie 上下文、断开 WebSocket、跳登录页并提示「您的账号在其他设备登录」
- 细节坑：踢线消息与业务消息共用一条 WS 时要定义清晰的消息 type；多 tab 只有一个 tab 持连接，需广播给其他 tab

```javascript
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type === 'KICKED') {
    localStorage.setItem('kicked', msg.deviceName); // 通知同域其他 tab
    cleanupSession();
    location.href = '/login?reason=kicked';
  }
};
window.addEventListener('storage', (e) => {
  if (e.key === 'kicked') cleanupSession(); // 无连接的 tab 也能退出
});
```
