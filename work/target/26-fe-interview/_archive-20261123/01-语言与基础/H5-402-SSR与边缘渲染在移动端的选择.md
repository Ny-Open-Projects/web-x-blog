## H5-402：SSR 与边缘渲染：移动端首屏的服务端方案选择

**答**：
- 移动端痛点：设备 JS 执行慢 2~5 倍，纯 CSR 的 hydration 成本高——SSR/SSG 把首屏渲染挪到服务端，用户提前看到内容
- 方案谱系：静态 SSG（内容型）→ SSR（动态数据）→ 流式 SSR（首字节先到，逐步补内容）→ 边缘渲染（CDN 边缘节点就近渲染，省 RTT）→ Islands（只 hydrate 交互组件）
- 边缘渲染价值：边缘节点离用户近（省 30~100ms RTT）+ 可做边缘个性化（AB/Geo），移动端弱网收益明显；代价是边缘函数成本与调试复杂度
- 数据注水：SSR 页面数据内联（JSON script 标签）避免二次请求；流式渲染时先骨架后数据逐块填充
- 选型决策：内容为主 → SSG/ISR；强动态 → SSR+缓存分层（边缘缓存 HTML 片段）；重交互 → Islands/选择性 hydration

```text
决策速查:
  营销落地页 → SSG + CDN (零服务端)
  商品详情 → SSR + 边缘缓存 (TTL 60s + stale-while-revalidate)
  强个性化首页 → 流式 SSR (骨架先行, 数据逐块)
  复杂后台 → CSR + 代码分割 (缓存价值低)
```
