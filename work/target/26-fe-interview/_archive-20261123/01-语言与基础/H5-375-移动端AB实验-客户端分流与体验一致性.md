## H5-375：移动端 AB 实验：客户端分流与体验一致性

**答**：
- 分流一致性：同一用户在 H5/Native/小程序多端要落同一实验组——用统一 user-id hash 分层实验框架，端内通过桥同步分组信息
- 分流时机：配置在「首屏渲染前」就绪（启动时同步获取），否则对照组/实验组首屏体验混跑污染数据；页面内动态分组要标记进入时刻
- 效应污染源：iOS/Android 平台差异、机型性能差异——实验报告要分层（平台 × 机型档位 × 网络档）看效应是否稳定，整体均值可能掩盖负向群体
- 周期与样本量：弱网/低频业务效应慢，实验周期至少 1~2 周 + 提前算好 MDE 最小样本量，避免「跑三天看均值下结论」
- 灰度联动：实验与发布灰度叠加时注意分层正交（实验 hash 层与发布层独立），防止同一批用户连续吃多个变量

```javascript
// 分流函数: 分层正交 + 稳定 hash
function bucket(userId, layer, salt) {
  const h = hashCode(`${salt}:${layer}:${userId}`) % 10000;
  return h / 10000;
}
const group = bucket(uid, 'pay-btn', 'exp42') < 0.1 ? 'treatment'
  : bucket(uid, 'pay-btn', 'exp42') < 0.2 ? 'control' : 'none';
beacon({ exp: 'exp42', group, uid: hashUid(uid) }); // 隐私: 上报哈希
```
