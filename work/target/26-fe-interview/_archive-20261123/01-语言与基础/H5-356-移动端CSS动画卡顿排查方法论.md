## H5-356：移动端 CSS 动画卡顿排查方法论

**答**：
- 排查路径四步：现象归因（掉帧/闪烁/内存涨）→ 层级检查（Layers 面板看是否提层、层内存）→ 管线定位（Performance 面板看 layout/paint/composite 哪段超时）→ 属性修正
- 常见卡顿源：动画属性触发 layout（top/left）、未提层的大区域 paint、will-change 滥用层爆炸、动画元素带 filter/blend（合成线程不接管）、z-index 层叠上下文错误导致强制提层
- 闪烁类问题：iOS 提层后纹理上传慢首帧白块（动画前预热：先 opacity 0.01 跑一帧）、will-change 长驻内存、transform 带 3d 引发的文本模糊
- 修复规范：动画只动 transform/opacity；动画开始前提层（will-change 加了就别忘删）；时长与 easing 用 cubic-bezier 而非无限阶梯
- 度量闭环：动画页面上报帧率采样（rAF 间隔分布），P95 帧间隔 > 20ms 告警

```css
/* 修复示例 */
.card { will-change: transform; }        /* 动画前提层 */
.card.animating { transform: translate3d(0, -100px, 0); transition: transform .3s; }
.card.done { will-change: auto; }        /* 结束后释放层 */
/* 反模式: .box { will-change: transform } 全站 300 个元素 → 层爆炸 */
```
