## JS-355：V8 代码缓存与启动优化：冷启动链路

**答**：
- 冷启动链路：下载 → 解析（字节流Scanner）→ 编译（全量/惰性）→ 执行——优化各段：代码分割减下载、预解析降编译、代码缓存免重复编译
- 惰性编译：函数体第一次调用才编译，顶层代码立即编译——大文件里未被调用的导出函数只花预解析成本（wrapper stub）；tree-shaking 后未用代码根本不下载
- 代码缓存（code cache）：Chrome 按 URL 缓存编译产物（第二次访问免解析编译）——条件：脚本加载两次 + 非内联小脚本；`<script>` 带缓存头即可，bundle 拆分影响缓存命中率（拆太碎缓存利用率低）
- 服务端协作：Code Cache API（Node/chrome 的 `v8.serialize` 不同）浏览器自动管理，前端能做的是「稳定 URL + 合理拆分」让缓存命中
- 度量：DevTools Performance 的 Compile 事件耗时对比二次访问；「解析编译占总加载的比重」是优化验证指标

```text
启动优化清单:
  1. 代码分割: 路由级 chunk, 首屏只拉必需
  2. 预解析/预加载: modulepreload
  3. 稳定 hash URL: 触发 code cache
  4. 避免超碎 chunk: 缓存与请求的平衡
  5. 惰性初始化: 重模块首次使用时 import()
```
