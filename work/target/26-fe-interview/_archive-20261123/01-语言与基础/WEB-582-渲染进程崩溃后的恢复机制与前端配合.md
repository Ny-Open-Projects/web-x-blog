## WEB-582：渲染进程崩溃后浏览器怎么恢复，前端能做什么

**答**：
- 渲染进程 OOM/崩溃后：浏览器进程感知到 Mojo 连接断开，tab 显示「喔唷，崩溃啦」，用户手动刷新即重建进程；浏览器进程与网络/GPU 进程不受影响
- 前端感知手段有限：`window.onerror` 无法捕获进程崩溃（进程都没了），可靠信号来自服务端——「会话突然中断 + 无 beforeunload」的上报缺失模式
- 恢复策略靠自建：编辑器/长表单类应用必须持续做本地持久化（localStorage/IndexedDB/草稿接口），崩溃刷新后恢复现场，这是对崩溃唯一有效的产品级防御
- 降低崩溃率的前端手段：控制单页内存峰值（大列表虚拟化、大图分片解码）、避免循环引用堆积（Canvas 离屏、Worker 不释放）
- 上报闭环：崩溃无法上报，但「上次会话异常终止」可以用 IndexedDB 写心跳时间戳，重启后检测心跳断层来统计崩溃率

```javascript
// 崩溃检测: 心跳断层法
setInterval(() => {
  idbSet('hb', { t: Date.now(), url: location.href });
}, 5000);
// 启动时:
const last = await idbGet('hb');
if (last && Date.now() - last.t > 60_000 && !wasCleanUnload()) {
  beacon({ event: 'suspect-crash', gap: Date.now() - last.t, url: last.url });
}
function wasCleanUnload() { return sessionStorage.getItem('clean-exit') === '1'; }
addEventListener('pagehide', () => sessionStorage.setItem('clean-exit', '1'));
```
