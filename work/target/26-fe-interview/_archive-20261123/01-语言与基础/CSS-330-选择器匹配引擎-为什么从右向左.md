## CSS-330：选择器匹配引擎：为什么从右向左匹配

**答**：
- 从右向左的原因：先定位「候选元素」（最右 CompoundSelector 命中的元素集合），再向左验证祖先链——候选集通常远小于全 DOM，避免对每个元素都做完整匹配尝试
- 复合选择器（.a.b）内部按 class/index 匹配很快；复杂选择器（.a .b .c）的代价在祖先回溯，最坏 O(深度^n)，现代引擎用 bloom filter/ancestor cache 剪枝
- 性能含义：`.box *` 这类宽右侧无效——右侧才是先决条件，`.box > li` 优于 `.box li`（子选择器终止回溯）；伪类 :nth-child 在候选阶段也要遍历兄弟
- :has() 的代价：祖先/先前兄弟方向的反向查询（回溯再展开），引擎会做失效标记与限制（不能嵌套 :has），性能敏感页面慎用大范围 :has
- 实战规范：选择器长度适度（2~3 层），避免全页通配与深层嵌套；CSS Modules/原子化天然短选择器受益于此

```css
/* 反例: 右侧通配 → 候选集=全DOM, 每个都要回溯验证祖先 */
.nav * { color: red; }
/* 正解: 右侧具体 → 候选集小 */
.nav > li { color: red; }
/* :has() 反向匹配代价: */
.row:has(.tag-hot) { border-color: red; } /* 每行都可能回溯找 .tag-hot, 列表页慎用 */
```
