## CSS-342：容器查询引擎实现与使用边界

**答**：
- 机制三步：容器声明（container-type: inline-size 建立 containment）→ 后代用 @container 查询该容器尺寸 → 容器尺寸变化时只重查后代匹配（失效范围限容器子树）
- container-type: inline-size 隐含 layout/style containment + 高度仍可由内容决定（size 类型则宽高都冻结）——这就是组件级响应式的成本基础
- 与媒体查询的架构差异：媒体查询绑定视口（全局失效），容器查询绑定组件（局部失效）——组件库适配多布局场景的正确工具；查询条件里还能查容器名（named container）与样式（@container style）
- 性能边界：容器自身尺寸频繁变化（拖拽/动画容器宽度）会级联触发后代重查+重排——不要把动画放在容器宽度的祖先链上；resize 容器要 contain 隔离
- 兼容与降级：不支持的内核按「默认桌面布局」降级（@supports 分支），渐进增强策略

```css
.card-wrap { container-type: inline-size; container-name: card; }
@container card (min-width: 480px) {
  .card { flex-direction: row; }
  .card__thumb { width: 40%; }
}
/* 样式查询: 按容器继承的主题变量分支 */
@container card style(--theme: dark) {
  .card { background: #222; }
}
```
