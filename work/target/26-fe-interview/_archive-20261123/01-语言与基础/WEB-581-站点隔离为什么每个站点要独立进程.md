## WEB-581：站点隔离：为什么跨站 iframe 必须换进程

**答**：
- 站点隔离（Site Isolation）规则：不同站点的文档不共享渲染进程，恶意站点即使被攻破（Spectre 类侧信道），也读不到其他站点进程内存
- 触发点不止 iframe：跨站导航、跨域弹窗打开的文档都会切到独立进程，页面里每个跨站 iframe（即使 0 尺寸）都可能是一个进程
- 代价：进程数膨胀（几十个 tab + 若干跨站 iframe），内存上涨明显；Chrome 用进程合并（同站点多 tab 共享）与内存回收缓解
- 前端关联点：跨站 iframe 每次创建/销毁都伴随进程创建，iframe 动态加载第三方组件时性能成本要计入；`document.domain` 放宽同源策略的站点会破坏隔离（已被 deprecated）
- COOP/COEP 可以强制进一步隔离：带 `Cross-Origin-Opener-Policy` 的页面独立成进程，防跨窗口攻击，同时解锁 SharedArrayBuffer 等高精度计时能力

```text
进程切分示意:
  a.com 主文档        → 进程 P1
  b.com iframe        → 进程 P2 (跨站必须隔离)
  c.com 新开弹窗      → 进程 P3
同站多 tab: a.com/tab1 + a.com/tab2 → 可共享 P1 (进程合并)
Spectre 防线: 恶意站点进程内读不到其他站点内存 → 隔离是安全边界
```
