## SCN-313：电子合同签署（盖章/签名/签署流程）的合规实现？

**答**:
- 签署流程状态机：发起（合同文件+签署区配置）→签署中（多方按序/无序签署）→完成（归档），多方签署的顺序控制（企业章在个人签之后——流程依赖）、催签与过期（签署链接有效期）。
- 签署交互：签名方式（手写板签名 canvas/签名图片/印章（企业章授权使用））、签署区定位（在合同 PDF 上拖放签名位置——坐标锚定按 PDF 页面坐标），意愿认证（签署前短信验证码/人脸核身——合规等级对应的认证方式）。
- 合规红线：合同内容不可篡改（签署前 hash 固化+签署后区块链/时间戳存证）、完整合同视图（签署前强制阅读——滚动到底才能签）、签署证据链（认证记录+签署时间+IP 留痕——司法证据要求）。
- 文件处理：PDF 渲染（分页渲染大合同/签章叠加层）、签署后 PDF 合成（签章图像合成进 PDF——服务端做，前端预览校验）、归档下载（带签章的最终版）。

```javascript
// 签署流程
const sign = await esignApi.create(contract, {
  signers: [{ role: 'personal', auth: 'sms' },
    { role: 'company', after: 'personal' }],  // 顺序依赖
  expireAt: plusDays(7),
});
// 签署面板：PDF 渲染（页坐标）+ 拖放签章区
//   + 意愿认证（sms/face）→ 签署提交
// 合规：阅读到底（scroll 监听）才激活签署按钮；
//   提交带 { contractHash, authRecord, ip, ua } 证据链。
// 归档：signed.pdf（服务端合成）→ 下载+存证编号。
```
