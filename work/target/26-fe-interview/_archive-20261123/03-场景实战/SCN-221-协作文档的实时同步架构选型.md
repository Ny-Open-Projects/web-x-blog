## SCN-221：多人实时协作文档，OT 与 CRDT 怎么选型？

**答**:
- OT（Operational Transformation）：操作经服务器中心化变换（并发操作变换后重放），需要中心服务器仲裁——优点：操作语义清晰、服务端可控制权限与审核；缺点：变换函数实现复杂（正确性难证明）、离线支持弱。
- CRDT（无冲突复制数据类型）：数据结构天然收敛（如 RGA/Yjs 文档模型），无中心仲裁也可合并——优点：离线优先/去中心化/实现生态成熟（Yjs/Automerge）；缺点：元数据开销（每个字符带唯一 ID）、垃圾回收（删除 tombstone 需压缩）。
- 选型决策：中心化协同（类飞书，服务端强管控+权限审核）→ OT 或"CRDT+中心服务器混合"；离线优先/本地优先产品 → CRDT；富文本表格复杂结构 → Yjs（成熟生态）自研 OT 风险高。
- 工程建议：不重复造轮子——CRDT 选 Yjs（Yjs+WebSocket provider+ awareness 状态协议是事实标准），OT 用成熟库（ShareDB）；自研只在协议有特殊需求时做，且要配模糊测试验证收敛性。

```text
OT vs CRDT 决策：
OT：中心仲裁 / 服务端管控强 /
  变换函数复杂 / 离线弱
CRDT：天然收敛 / 离线优先 /
  元数据开销 / 生态成熟（Yjs）
选型：强管控中心化 → OT 或混合；
  离线优先 → CRDT；
  富文本复杂结构 → Yjs 事实标准。
自研底线：模糊测试验证收敛性。
```
