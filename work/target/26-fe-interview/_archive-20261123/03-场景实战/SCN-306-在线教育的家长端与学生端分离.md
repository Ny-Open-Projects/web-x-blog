## SCN-306：教育产品多角色（学生/家长/老师）的账号绑定与信息分离怎么设计？

**答**:
- 账号关系模型：学生账号与家长账号绑定（家长绑多个孩子、一个孩子多家长），角色能力矩阵（学生：学习/作业；家长：查看报告/缴费；老师：批改/学情）——绑定关系服务端为准，前端按角色渲染。
- 信息可见性分离：家长看报告（成绩/时长/报告单）不看学生端交互细节（聊天内容分级可见——青少年模式合规）、学生不感知缴费操作、老师只看班级维度——数据可见性在服务端 API 层裁剪。
- 青少年模式合规：时长限制（未成年人防沉迷：使用时长上限+宵禁——服务端强制，前端到时提醒）、内容过滤（适龄内容池）、消费限制（未成年人充值管控——支付环节年龄校验）。
- 家校沟通：老师↔家长通道（作业通知/成绩单/私聊——IM 协议复用）、通知触达策略（作业截止提醒发家长端而非学生端——按内容类型路由）。

```javascript
function renderByRole(user) {
  const caps = roleCaps(user.role, user.bindings);   // 服务端下发
  return caps.includes('study')
    ? <StudentApp /> : caps.includes('parent')
      ? <ParentApp child={user.children[0]} />
      : <TeacherApp />;
}
// 防沉迷：ws.on('usage_limit') → 全屏提示+锁学习功能（除已约定豁免）
// 绑定：parent.bind(child, { verify: smsOf(child Guardian) })
// 通知路由：notify({ audience: 'parent', type: 'hw_due' })。
```
