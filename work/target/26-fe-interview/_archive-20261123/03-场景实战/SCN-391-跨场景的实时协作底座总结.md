## SCN-391：IM/协作文档/会议/直播四大场景的实时底座怎么抽象统一？

**答**:
- 共用基建识别：连接管理（WS 心跳重连/多端同步——SCN-213/446）、信令通道（QoS 分级消息——SCN-370）、状态广播（awareness presence——SCN-223/232）、洪峰治理（聚合渲染/采样降级——SCN-216/272）、时钟服务（SCN-020）——五件套是所有实时场景的公共底座。
- 场景差异建模：IM=点对点消息+存储会话；协作=文档 CRDT+光标；会议=RTC 媒体+控制信令；直播=单向媒体+弹幕洪峰——差异在数据模型与 QoS 策略，底座协议统一。
- 底座 API 设计：ConnectionManager（连接生命周期）、Channel（QoS 分级的消息通道）、Presence（在线状态）、Clock（时钟服务）、Flood（洪峰治理策略）——场景组装这些原语（组合优于继承）。
- 演进纪律：底座变更全场景回归（底座动一刀全场景受影响——回归测试矩阵）、场景特例不下沉（只有一个场景用的逻辑留场景内——防底座膨胀）。

```text
实时底座五件套：
Connection：心跳/重连/多端同步
Channel：QoS 分级消息通道
Presence：在线状态广播
Clock：服务器时钟服务
Flood：聚合渲染/采样/降级策略
场景差异：数据模型 + QoS 策略，
  底座原语组装（组合优于继承）。
纪律：底座变更全场景回归；
  单场景特例不下沉。
```
