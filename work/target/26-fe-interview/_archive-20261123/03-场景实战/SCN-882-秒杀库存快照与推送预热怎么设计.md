## SCN-882：库存快照与预热推送怎么设计？
**答**：
- 预热快照：活动开始前把「商品快照（价格/图/规则文案）」推送到客户端缓存（App 预拉/H5 SW 缓存）——开抢瞬间零等待渲染商品信息，只等库存接口。
- 快照版本：快照带版本号，活动配置变更（SCN-871）后重新推送；客户端校验版本展示。
- 库存订阅预热：开抢前 5 秒预建立 WS 订阅（连接早建好，开抢只发订阅消息），避免瞬时建连风暴。
- 快照一致性：快照价格与下单接口价格不一致时（配置改了没推送），下单以后端为准 + 前端检测差异刷新快照。
- 追问钩子：为什么快照要版本化推送而不是每次全量拉——秒杀页商品信息大（图文），全量拉在峰值前制造流量洪峰；增量推送 + 版本校验让变更精准生效。

```javascript
const snapshotWarm = {
  push: { timing: 'T-24h & T-1h', transport: 'config-push', cache: 'sw/app-cache' },
  version: { check: 'render-time', mismatch: 'refetch-incremental' },
  wsPreheat: { connectAt: 'start-5s', subscribe: 'on-demand' },   // 连接预热
  priceGuard: { snapshotVsServer: 'diff-detect + refresh' },
};
```
