## SCN-668：大屏可视化技术选型怎么定？
**答**：
- 决策维度：3D 复杂度（美术要求）、实时性要求、团队技术栈、终端硬件、预算。
- 三个档位：① Web 原生（three.js + ECharts）：交互可控、成本低，适合轻中量 3D；② UE/Unity 像素流（服务端渲染推流）：电影级画质，但每路推流占服务端 GPU、并发受限、延迟 100ms+；③ 混合：UE 渲染主场景 + Web 层叠 2D 图表（iframe/WS 数据桥）。
- 硬约束检查：浏览器端 WebGL 对大模型/高贴图有显存上限；推流方案吃服务端成本——两个方向的成本模型完全不同。
- 演进路线：先 Web 原生验证需求，画质/复杂度确实不够再上推流（推流是不可逆重投入）。
- 追问钩子：推流的并发瓶颈怎么算——单 GPU 卡约 3~5 路 1080p 推流，100 大屏要 20+ 卡集群；这直接决定选型经济性。

```javascript
function chooseTech(req) {
  if (req.modelSize < 50 && req.fps > 30 && !req.cinematic)
    return { mode: 'web-gl', stack: ['three.js', 'echarts'], cost: 'low' };
  if (req.cinematic || req.modelSize > 200)
    return { mode: 'pixel-stream', concurrencyPerGPU: 4, latency: '150ms',
             cost: `GPU集群: ${Math.ceil(req.screens / 4)} 卡`, fallback: 'web-gl' };
  return { mode: 'hybrid', note: 'UE 场景 + Web 图表层', bridge: 'ws-data + iframe' };
}
```
