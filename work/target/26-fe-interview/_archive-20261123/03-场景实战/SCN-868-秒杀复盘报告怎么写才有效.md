## SCN-868：复盘报告怎么写才有效？
**答**：
- 结构一页化：结论先行（三句话：达成/事故/改进）→ 数据表 → 事故时间线 → 改进项清单（owner/期限/验证指标）；正文不超过 3 页，附录放明细。
- 改进项质量标准：每条必须「可验证」（下场活动怎么确认做完了）+ 有 owner + 有期限——「加强监控」这种不可验证的表述禁止出现。
- 事故叙述纪律：时间线只陈述事实（几点几分发生了什么），归因放分析节；责任描述用「系统行为」不用「某人失误」（无责文化，聚焦改进）。
- 传播设计：报告核心版发全员（建立认知），技术细节版发相关团队；改进项进追踪系统而非躺在文档里。
- 追问钩子：为什么改进项要「可验证」——不可验证的改进项等于没有（下次复盘无法检查）；验证指标与 SCN-717 闭环追踪一致。

```javascript
const reportTemplate = {
  headline: ['达成结论', '事故结论', '改进结论'],      // 三句话
  timeline: { factsOnly: true, blameless: true },     // 事实+无责
  improvements: (item) => item.owner && item.due && item.verifyMetric
    || reject('改进项必须可验证'),                     // 质量门禁
  distribute: { all: 'core-3page', team: 'tech-detail' },
};
```
