## SCN-222：长篇协作文档（几十万字）的同步，全量传输扛不住怎么办？

**答**:
- 增量同步模型：文档版本向量（每个客户端记录已应用到的操作序号），同步只传缺失操作（客户端上报本地版本→服务端下发增量操作包）；操作按逻辑时钟排序应用。
- 快照机制：定期快照（每 N 次操作或每 5 分钟生成文档快照——新加入者/断线重连者从快照+快照后增量恢复，避免重放全量历史）；快照是恢复锚点也是垃圾回收点（快照前的操作历史可归档）。
- 大文档分层：按章节分区协同（每章节独立同步域，跨章节引用弱耦合）——几百万字的文档只有编辑者所在的分区实时同步，其他分区按需拉取。
- 传输压缩：操作批量打包（10ms 窗口聚合）、二进制编码（Yjs update 是二进制格式，比 JSON 小一个量级）、增量 diff（同版本内容变更只传 diff）。

```javascript
// 基于 Yjs 的增量同步
const doc = new Y.Doc();
doc.on('update', (update, origin) => {
  if (origin !== provider)                 // 本地变更→上报
    ws.send(encode(update));
});
ws.on('message', (update) => {
  Y.applyUpdate(doc, decode(update));      // 增量应用
});
// 快照：Y.encodeStateAsUpdate(doc) 定期存服务端；
// 新客户端：服务端下发 [快照 + 快照后增量包]，
// 客户端 Y.applyUpdate 依次应用即可恢复到最新。
// 大文档：Y.Doc per 章节，分区独立同步。
```
