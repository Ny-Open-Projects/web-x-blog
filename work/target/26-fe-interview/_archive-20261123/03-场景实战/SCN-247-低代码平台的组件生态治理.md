## SCN-247：低代码平台的组件资产（几十个业务组件）怎么治理？

**答**:
- 组件准入：SDK 规范（props 协议/事件协议/schema 描述文件——组件的 schema 元数据决定低代码面板怎么配置它）、准入评审（API 设计/性能/无障碍/主题兼容四查）、沙箱验证（组件在平台 runtime 的兼容性自动测试）。
- 版本治理：组件 semver（ breaking 变更影响存量页面——影响面扫描：哪些 schema 用了旧版本）、兼容策略（旧版本共存期：页面锁定版本，升级走迁移工具）、废弃流程（标记废弃→通知存量页面 owner→下线期限）。
- 质量运营：组件使用统计（热度/错误率——低质组件数据说话）、组件评测基线（每个组件的渲染性能基准）、反馈通道（使用方 issue → 组件 owner）。
- 资产复用：组件市场（搜索/预览/一键引入）、跨平台复用（中后台/移动端组件分层：逻辑层复用+渲染层分端）。

```text
组件生态治理：
准入：SDK 规范（props/事件/schema 元数据）
  + 四查评审 + 沙箱兼容测试
版本：semver + 存量影响面扫描 +
  旧版本共存 + 废弃通知流程
运营：使用统计 / 错误率 / 反馈闭环
复用：市场搜索引入 + 逻辑层跨端复用。
关键：schema 元数据 = 组件与平台的契约。
```
