## SCN-866：客诉与舆情复盘怎么做的？
**答**：
- 客诉分类归因：客诉按技术根因聚类（超时未支付误关单/页面白屏/排队被踢/误杀拦截）——客诉量是技术问题的滞后指标，用于验证「技术问题→用户体验」的传导。
- 舆情监测：社交平台讨论（抢不到/疑似机器人/规则不透明）与客诉交叉验证——舆情热度点常是「规则感知问题」而非技术故障。
- 快速响应机制：活动期客诉突增自动告警值班（分类聚类实时跑），Top 客诉类型 15 分钟内出解释话术下发客服。
- 复盘产出：客诉 Top5 问题 → 技术或产品改进项；「规则不透明」类问题推动规则文案优化（很多客诉源于规则没讲清而非系统故障）。
- 追问钩子：为什么「规则不透明」也是技术问题——规则文案/交互说明是产品技术的一部分；库存规则、优先权规则如果 UI 没讲清，客诉与舆情成本远大于一句文案。

```javascript
const complaintReview = {
  cluster: (complaints) => clusterByRootCause(complaints, {
    dims: ['tech-root', 'rule-perception', 'expectation-gap'] }),
  realtime: { alertThreshold: 'baseline*3', scriptSLA: '15min' },
  output: (top5) => top5.map(c => classify(c) === 'rule-perception'
    ? copyImprovement(c) : techImprovement(c)),       // 规则感知问题→文案优化
};
```
