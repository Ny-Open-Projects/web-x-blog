## SCN-784：审核与举报协同怎么设计？
**答**：
- 举报即提审：用户举报触发内容提审（跳过直放），举报量与举报人信誉加权优先级——高信誉用户举报单条即置顶。
- 举报滥用防御：同一用户高频恶意举报限流；批量举报（水军）按举报人网络聚类识别，聚合为单任务。
- 举报与机审对账：举报内容机审分数低但人审通过的比例（误举报率）反馈给举报排序模型。
- 举报者反馈闭环：举报处理结果推送给举报者（已处置/未违规），提升举报意愿质量。
- 追问钩子：为什么高信誉用户举报要加权——信誉体系（历史举报准确率）让高质量举报信号放大，等同免费质检网络；同时限流防滥用，两边缺一不可。

```javascript
const reportFlow = {
  priority: (report) => base + reporterCred(report.userId) * 10 + report.clusterSize,
  abuseGuard: (userId) => rateLimit(userId, { daily: 20 }) && clusterDetect(userId),
  feedback: (report) => notify(report.userId, report.verdict),   // 结果闭环
  calibrate: (rejected) => trainReportRanker(rejected),          // 误举报回流
};
```
