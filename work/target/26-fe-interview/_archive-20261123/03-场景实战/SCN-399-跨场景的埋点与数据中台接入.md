## SCN-399：多业务线的埋点口径统一与数据中台接入怎么治理？

**答**:
- 口径统一：事件字典（全业务统一事件命名规范：object.action 格式/公共属性集（用户/设备/页面上下文）——SCN 各业务埋点口径篇的统一治理），字典治理流程（新增事件评审/废弃标记/变更通知——SCN-247 资产治理复用）、CI 门禁（埋点 schema 校验：未注册事件拦截上报——质量前置）。
- 接入架构：统一采集 SDK（SCN-211 管道复用全业务）+ 数据中台接入（埋点→清洗→数仓：业务方只管打点，链路统一），实时与离线双链（实时看板+离线分析）。
- 质量治理：埋点覆盖率检测（关键路径埋点自动化校验：冒烟环境跑关键流程比对事件——漏埋检测）、数据质量监控（事件量突降/字段缺失率告警——SCN-278 监控复用）、口径文档（事件字典门户——查询/示例/负责人）。
- 组织机制：埋点 Owner（业务线数据 Owner）、需求流程（数据需求→埋点方案评审→上线验证）、分析自助化（自助查询平台——减少取数人力）。

```text
埋点中台治理：
字典：统一命名 + 公共属性 + 评审流程
  + CI 校验（未注册拦截）
链路：统一 SDK → 中台清洗 → 数仓
  （实时+离线双链）
质量：覆盖率自动校验 + 量级告警
  + 字典门户
组织：业务 Owner + 需求评审 + 自助分析。
心法：字典治理 = 数据可信的地基。
```
