## SCN-770：审核标准变更灰度怎么做的？
**答**：
- 变更流程：标准修订提案 → 影响评估（回放历史数据：新标准下多少存量内容会被判违规）→ 灰度生效（部分审核员/部分品类先行）→ 全量。
- 影响预演：标准变更前用「历史审核数据回放」估算影响面（多少存量视频会被新处置动作波及），影响过大先修标准而不是先上线。
- 灰度观察：灰度期对比新标准组的准确率/申诉率与旧组，申诉率突增说明标准与社区共识冲突，回退。
- 审核员同步：生效前强制学习（标准变更卡片 + 小测），未完成学习不派受影响任务。
- 追问钩子：为什么标准变更要「回放」——处置动作有追溯效应（存量内容也会被新标准处置），不预演就是拿存量创作者做实验。

```javascript
async function grayReleaseStandard(newStd) {
  const impact = await replay(newStd);               // 历史数据回放评估
  if (impact.takedownRate > 0.05)                    // 影响 >5% 存量先修标准
    return { blocked: true, reason: 'impact too large', impact };
  const gray = await enableFor({ auditors: 'beta-group', categories: ['tech'] });
  const monitor = await compareGroups(gray, { window: 7 * 24 * 3600_000 });
  if (monitor.appealRateDelta > 0.5) return rollback(newStd);   // 申诉率突增回退
  return fullRelease(newStd);
}
```
