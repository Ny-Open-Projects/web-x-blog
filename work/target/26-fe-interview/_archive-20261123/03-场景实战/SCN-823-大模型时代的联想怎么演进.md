## SCN-823：大模型时代的联想怎么演进？
**答**：
- 语义联想：从「前缀匹配」到「意图理解」——输入「怎么学 rust」联想「rust 入门路线/rust vs go」，命中语义而非字面；LLM 生成候选 + 传统召回融合。
- 延迟矛盾：LLM 生成慢（500ms+），联想要求 250ms——架构上「传统联想秒出 + 语义联想流式追加」（下拉先出结果，AI 建议渐进补入）。
- 成本控制：语义联想仅对「传统召回不足」的输入触发（LLM 是补充不是替代），并做缓存（同输入复用）。
- 前端呈现：AI 建议分容器展示（带 AI 标识 + 可展开解释），与传统建议视觉区分——用户要知道哪些是生成的。
- 追问钩子：为什么 AI 建议要流式追加而不是等完整——联想的跟手性预算不因 AI 而破坏；先传统后 AI 的渐进呈现保住 250ms 底线同时给语义价值。

```javascript
async function hybridSuggest(q) {
  const classic = await suggest(q);                    // ≤250ms 先出
  render(classic);
  if (classic.weak) {                                  // 传统召回不足才触发 LLM
    const stream = await aiSuggest(q, { stream: true });
    for await (const chunk of stream) appendAISection(chunk, { badge: 'AI' });
  }
}
```
