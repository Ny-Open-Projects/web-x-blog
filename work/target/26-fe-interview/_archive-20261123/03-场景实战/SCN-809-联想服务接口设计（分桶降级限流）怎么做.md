## SCN-809：联想服务接口怎么设计？
**答**：
- 接口契约：GET /suggest?q=&size=&type=；响应分桶（history/hot/entity）+ traceId + 服务端版本号；QPS 极高（每次输入都打）——接口必须轻。
- 性能手段：服务端前缀树 + 热词缓存（Top 前缀预计算）；热点前缀（"iph"）合并缓存；CDN 边缘缓存热门通用联想（非个性化部分）。
- 降级链：联想服务挂 → 前端本地兜底（历史词 + 本地静态热词表）→ 完全无联想（输入框可用）——搜索主流程永不因联想挂掉。
- 限流协同：前端对超短前缀（1 字符）不请求（命中率低噪声大）+ 输入节流；服务端按用户限流防爬。
- 追问钩子：为什么 1 个字符不请求联想——1 字符候选集巨大且区分度低，接口成本高用户价值低；同时它是最容易被爬虫枚举的入口，限流优先卡住。

```javascript
const suggestAPI = {
  contract: 'GET /suggest?q&size&type -> {groups, traceId, version}',
  minQueryLen: 2,                                     // 1 字符不请求
  degrade: async () => localHistorySuggest() ?? staticHotwords(),   // 本地兜底
  edgeCache: { personalized: false, hotPrefixes: true },   // 边缘缓存非个性化部分
  rateLimit: { perUser: 60, perMin: true },
};
```
