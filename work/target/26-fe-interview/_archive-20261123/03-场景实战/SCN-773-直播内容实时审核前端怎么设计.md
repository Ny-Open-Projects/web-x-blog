## SCN-773：直播实时审核怎么设计？
**答**：
- 实时链路：直播流切片（5~10s）→ 机审（画面/语音）→ 实时风险推送；审核端显示「当前风险等级 + 违规时刻倒推片段」，高危可秒级切断（与运营侧切断联动）。
- 延迟匹配：审核端拉流比观众端延迟更低（审核走低延迟流），保证「看到违规时观众也刚看到」——延迟差是实时审核的关键参数。
- 违规定位：直播无「片段回放」语义，违规时刻 + 前后 30s 缓冲录制（服务端滚动录制）供取证与复盘。
- 并发监控：单人监控多路直播（画面墙 + 风险排序），高危直播自动置顶并放大。
- 追问钩子：为什么审核端流要更低延迟——审核响应窗口 = 流延迟差 + 人工反应时间；观众端 10s 延迟而审核端 2s，给了 8s 的切断窗口。

```javascript
const liveAudit = {
  stream: { audit: 'll-hls-2s', audience: 'hls-10s', windowDiff: 8 },   // 切断窗口 8s
  riskPush: (risk) => ({
    level: risk.level, ts: risk.ts,
    evidence: rollingRecord(risk.channelId, risk.ts - 30_000, risk.ts + 30_000),  // 取证缓冲
  }),
  cutSwitch: (channelId) => api.post(`/live/${channelId}/cut`, { level: 'HIGH' }),  // 秒级切断
};
```
