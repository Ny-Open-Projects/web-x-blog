## SCN-834：联想的性能与成本平衡怎么做？
**答**：
- 请求削减三板斧：防抖 150ms（-60% 请求）、1 字符不请求（-30%）、缓存命中零请求（-40%）——叠加后接口 QPS 降一个数量级。
- 响应瘦身：联想响应 ≤ 2KB（分条截断/卡片字段精简）；gzip/brotli + 字典压缩（词表复用）。
- 分级算力：热门前缀走缓存（预计算）不进索引实时查询——80% 流量命中 20% 热门前缀（幂律），缓存层省大头。
- 客户端兜底减负：服务降级时用本地历史替代（用户无感知损失，服务端零成本）。
- 追问钩子：为什么「热门前缀预计算」收益最大——搜索前缀分布高度幂律，Top 前缀预计算成静态缓存后，实时索引查询只剩长尾，算力成本大幅下降。

```javascript
const costOptimization = {
  requestReduction: { debounce: 0.4, minLen2: 0.7, cacheHit: 0.6 },   // 乘法叠加
  responseBudget: '2KB', compression: 'brotli+dict',
  computeTier: { hotPrefix: 'precomputed-cache (80% traffic)', tail: 'index-query (20%)' },
  fallback: 'local-history (zero server cost)',
};
```
