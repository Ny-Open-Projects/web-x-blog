## SCN-530：金融组件可测试性怎么设计？
**答**：
- 纯函数抽离：金额格式化/精度运算/状态映射全部抽成纯函数，单测覆盖边界（0、负数、超大额、多币种、NaN 输入），这是金融 QA 的第一道防线。
- 快照守恒：关键渲染（确认页金额、收款人）用固定 fixture 快照测试 + 变更必须显式 review，防止文案/金额错位静默上线。
- 合约测试：组件对接口字段的依赖写契约（TS 类型 + mock server schema），服务端字段变更 CI 即报错。
- 时间与随机可控：金额动画/水印时间戳注入 clock，测试不 flaky；随机键盘布局可注入固定 seed。
- 追问钩子：为什么金融组件要mutation 测试——验证测试本身有效（改错金额测试必须红）。

```javascript
// amount.spec.js —— 纯函数边界矩阵
const CASES = [
  [0, '¥0.00'], [-12345, '-¥123.45'], [1, '¥0.01'],
  [Number.MAX_SAFE_INTEGER, '¥90,071,992,547,409.91'],
];
test.each(CASES)('fenToYuan(%d) === %s', (fen, exp) => expect(fenToYuan(fen)).toBe(exp));
test('NaN 输入抛错而非渲染 NaN', () => expect(() => fenToYuan(NaN)).toThrow());
// mutation 检查：把 fenToYuan 里 /100 改成 /10，上面用例必须失败（CI 门禁）
```
