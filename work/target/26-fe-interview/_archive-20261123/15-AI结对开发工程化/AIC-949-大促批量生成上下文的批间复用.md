## AIC-949：大促前要批量生成上百个活动页配置，如何让这些任务的上下文「批间复用」而不是每个都重新组装？
**答**：
- 抽取「共享基线上下文」：活动页的公共组件、规则、品牌规范、接口 schema 组装一次并复用（配合 prefix caching），每个任务只追加自己的差异化参数（商品 ID、活动文案）。
- 用「上下文模板 + 参数槽」：模板固化不变部分，槽位填入任务特定数据；结论：批间复用的关键是区分「不变量」与「变量」。
- 注意污染隔离：复用基线时，若某任务产生了新知识（如新踩的坑），要审慎决定是否回写基线——直接回写可能污染其他任务，应走评审。
- 追问钩子：能说出「共享基线要版本化，任务记录自己用的基线版本，便于出问题时定位是哪个基线导致的」的候选人，把复用与可追溯结合了。

```typescript
// 上下文模板 + 参数槽，批间复用基线
const baseline = { // 版本化的共享基线
  version:'base-v3',
  rules:['用设计系统组件','价格用整数分'],
  components:['Banner','CouponCard'],
};
function buildTaskContext(task) {
  return {
    baseVersion: baseline.version,      // 记录用的基线版本（可追溯）
    system: baseline.rules.join('; ') + '\n' + baseline.components.join(','),
    task: `商品:${task.skuId} 文案:${task.copy}`, // 仅变量部分变化
  };
}
console.log(buildTaskContext({skuId:'A001',copy:'限时5折'}));
```
