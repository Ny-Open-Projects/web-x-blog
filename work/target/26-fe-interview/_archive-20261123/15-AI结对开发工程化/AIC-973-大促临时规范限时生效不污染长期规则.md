## AIC-973：大促期间临时加了一条「所有价格改动必须双人复核」的规范，如何让它在限时生效又不污染长期规则库？
**答**：
- 用「带时效的规则」机制：规则带 `effectiveFrom/effectiveTo` 或 `expires` 字段，到期自动失效——结论：临时规范要有明确生命周期，不能混进永久规则。
- 隔离存放：临时规范放在独立的 `campaign-rules` 目录/命名空间，与长期 rules 分开；工具按当前日期动态决定加载哪些，避免硬编码删除。
- 要有「到期复盘」：规则失效前提醒 owner 复盘——是转为长期规范、还是随大促结束移除；避免大量临时规范悄悄变成永久负担。
- 追问钩子：能提出「临时规则要记录引入它的事件与过期原因，到期自动归档并触发复盘通知」的候选人，把规则治理做成了有生命周期的资产。

```typescript
// 带时效的规则 + 到期复盘
const rules = [
  { id:'PRICE-DUAL', text:'价格改动双人复核', from:'2026-11-20', to:'2026-11-30', owner:'p1' },
  { id:'ALWAYS-TS', text:'必须用TypeScript', from:'2026-01-01', to:null, owner:'p2' },
];
function activeRules(rules, today) {
  return rules.filter(r => (!r.from||r.from<=today) && (!r.to||r.to>=today));
}
function expiringSoon(rules, today, days=3) {
  return rules.filter(r=>r.to && r.to>=today && (new Date(r.to)-new Date(today))/864e5<=days);
}
console.log(activeRules(rules,'2026-12-05').map(r=>r.id)); // 仅 ALWAYS-TS，临时规则已失效
console.log(expiringSoon(rules,'2026-11-28').map(r=>r.id)); // 提醒复盘
```
