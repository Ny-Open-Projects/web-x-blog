## AIC-634：大促压测脚本让多个模型交叉验证，怎么落地？

**答**：
- 结论先行：**交叉验证不是「让两个模型各写一版压测脚本再挑一个」，而是「用第二个模型审第一个模型的假设」**——压测脚本最大的风险不是语法错，而是「压错了地方」（假设错了）。
- 落地方式：1) **模型 A 生成脚本**（如基于 k6 的大促场景：登录→浏览商品→加购→下单）；2) **模型 B 审查假设**：检查并发模型是否符合真实大促流量（峰值系数、思考时间、链路比例）、是否漏掉关键路径、mock 数据是否真实（AIC-059 mock 规范）；3) **一致性检查**：两模型对「核心瓶颈在哪」的判断若一致，可信度提升；若分歧，标记为人重点复核。
- 关键验证点：压测脚本容易犯的错——把所有请求打到同一接口（不符合真实流量分布）、忽略思考时间导致压力虚高、没设预热阶段。交叉审查要专门盯这些。
- 人的角色：模型只能验证「脚本逻辑自洽」，验证不了「是否符合真实业务流量」——流量模型必须人来定（AIC-069 Senior 的领域知识）。
- 追问钩子：为什么「审假设」比「审代码」更有价值？——因为压测脚本的代码通常很简单（几十行），错不起大错；但如果流量假设错了（比如少了「秒杀瞬时峰值」），整个压测结论都是无效的，浪费的是整个压测窗口。

```typescript
type PressurePlan = { peakRps: number; thinkTimeMs: number; rampUpSec: number; paths: string[] };

function crossValidate(planA: PressurePlan, planB: PressurePlan): { consistent: boolean; diffs: string[] } {
  const diffs: string[] = [];
  for (const k of ['peakRps', 'thinkTimeMs', 'rampUpSec'] as const) {
    const a = planA[k], b = planB[k];
    if (Math.abs(a - b) / Math.max(a, b, 1) > 0.3) diffs.push(`${k}: ${a} vs ${b}`);
  }
  const pathsA = planA.paths.join(','), pathsB = planB.paths.join(',');
  if (pathsA !== pathsB) diffs.push(`paths: ${pathsA} vs ${pathsB}`);
  return { consistent: diffs.length === 0, diffs };
}

const a: PressurePlan = { peakRps: 5000, thinkTimeMs: 500, rampUpSec: 60, paths: ['login', 'browse', 'cart', 'order'] };
const b: PressurePlan = { peakRps: 5200, thinkTimeMs: 500, rampUpSec: 60, paths: ['login', 'browse', 'cart', 'order'] };
console.log(crossValidate(a, b).consistent); // true（差异 < 30%）
```
