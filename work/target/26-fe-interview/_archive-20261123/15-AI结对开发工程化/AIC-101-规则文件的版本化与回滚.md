## AIC-101：规则文件本身要不要做版本化与回归测试？「规则回归」怎么做？
**答**:
- 要。规则文件决定所有 AI 产出的行为基线，改一条规则等于改全团队的生成器配置——必须和代码同等级别治理：Git 管理、PR review、变更说明。
- 规则回归：维护「规则测试集」——一组固定任务（含必须遵守某条规则的任务）+ 期望行为要点；规则变更后批量跑一遍，确认新规则生效且没误伤其他行为。
- 版本化价值：产出退化时可以定位「是规则变了还是模型变了」——两者都演化，没有版本对照就无法归因。
- 变更节奏：规则变更要小步，一次改一条并记录动机（关联事故/复盘），大重构式改写会让行为漂移无法定位。
- 追问钩子：与 AIC-040（prompt as code）呼应——规则文件是常驻 prompt，治理体系共用。

```javascript
// 规则回归跑批
async function rulesRegression(rulesVersion) {
  const cases = loadCases('rules-cases/');  // [{task, expect: ['不使用 any', '清理副作用']}]
  const results = [];
  for (const c of cases) {
    const output = await runWithRules(c.task, rulesVersion);
    const checks = c.expect.map(e => ({ expect: e, pass: llmJudge(output, e) }));
    results.push({ task: c.task, checks });
  }
  return { pass: results.every(r => r.checks.every(c => c.pass)), detail: results };
}
```
