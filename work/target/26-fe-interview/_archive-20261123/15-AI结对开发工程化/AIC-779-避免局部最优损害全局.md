## AIC-779：如何避免 AI 效能指标导致局部最优损害全局

**答**：
- 结论先行：局部最优 = 某团队/环节为优化自己的指标，牺牲了整体（如测试团队为「测试覆盖率」写大量弱测试，拖慢全局交付）；解法是「端到端指标 + 跨环节制衡」。
- 机制：1) 用全局指标（交付周期、线上质量）作为北极星，局部指标只作诊断；2) 设置跨环节 guardrail（A 团队指标提升不得导致 B 团队负担超标）；3) 定期审视指标间的负相关。
- 文化：鼓励「为整体优化」而非「为指标优化」；发现局部优化行为先质疑指标设计，而不是指责个人。
- 追问钩子：为什么「先质疑指标」而不是「先问责个人」？——人按指标行事是理性的；局部最优通常是指标设计缺陷的信号，问责会掩盖真问题。

```javascript
// 跨环节制衡：局部指标提升不得突破全局 guardrail
function checkLocalOptimization(local, globalGuard) {
  const improved = local.cycle > 0;                 // 本地周期缩短（正向）
  const harmed = globalGuard.downstreamReviewHours > globalGuard.limit; // 下游负担超标
  return {
    realImprovement: improved && !harmed,
    warning: improved && harmed ? '局部提效以损害下游为代价' : null,
  };
}
console.log(checkLocalOptimization(
  { cycle: 0.2 },
  { downstreamReviewHours: 40, limit: 20 }
));
// { realImprovement:false, warning:'局部提效以损害下游为代价' }
```
