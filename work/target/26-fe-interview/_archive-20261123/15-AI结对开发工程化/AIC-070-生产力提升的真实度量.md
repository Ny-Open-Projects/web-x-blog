## AIC-070：「AI 提效 30%」这类数字怎么度量才不是自欺？个人与团队层面的度量有什么不同？
**答**：
- 自欺来源：只测「写代码速度」（接受补全数）不测「返工与维护成本」；试点期是新鲜劲；任务样本偏简单。
- 个人层：同任务前后对比法——选 3~5 个固定基准任务（含一个有坑的存量 bugfix），记录「开始→可合并」总耗时，含测试与 review 返工。
- 团队层：产出口径用「PR 合并周期、返工次数、线上缺陷率、7 天存活率」这类结果指标，而不是过程指标（代码行数毫无意义，AI 时代行数还会虚增）。
- 必须控变量：AI 工具引入期间不要同时换框架/换流程，否则归因不清；观察周期 ≥ 1 个月抹平新鲜感。
- 追问钩子：诚实的结论往往是「简单任务提效明显（40%+），复杂任务接近 0 甚至为负」——能说出这个分布的才是真度量过的人。

```javascript
// 基准任务计时表（度量最小实现）
const baseline = [
  { task: '存量 bugfix（含坑）', before: 210, after: 150 },  // 分钟
  { task: '新 CRUD 页面', before: 240, after: 90 },
  { task: '复杂状态逻辑设计', before: 300, after: 280 },
];
const summary = baseline.map(b => ({
  ...b, delta: (b.before - b.after) / b.before,
  note: b.delta < 0.1 ? '复杂任务：AI 收益有限' : '模式化任务：AI 收益显著',
}));
```
