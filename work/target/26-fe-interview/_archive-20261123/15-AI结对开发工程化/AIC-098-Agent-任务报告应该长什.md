## AIC-098：Agent 完成任务后的「任务报告」应该包含什么？为什么报告质量直接决定验收效率？
**答**：
- 报告要素：做了什么（改动文件清单 + 每个文件一句话意图）、为什么这么做（关键决策与被否方案）、验证结果（测试/类型/构建通过情况）、遗留风险（它自己不确定的点）、复现方式（如何本地验证）。
- 质量关键：报告必须「与 diff 对得上」——说的和改的不一致是 agent 高频问题，报告生成要从 diff 反推而不是让它自由发挥。
- 为什么决定验收效率：人的验收是「读报告 → 抽查报告里宣称的关键点 → 跑验证」，一份可对照的报告让验收从 30 分钟降到 5 分钟；含糊的报告逼人全量读 diff。
- 最有价值的字段是「遗留风险」：agent 主动说「我对 X 不确定」能把人的注意力精准投到最可能出问题的地方。
- 追问钩子：报告也是度量输入——「报告宣称 vs 实际不符」的比率可以用来评估该 agent 配置的可信度。

```javascript
// 任务报告结构（从 diff 反推生成）
const reportTemplate = {
  summary: '改动清单（file → 一句话意图）',
  decisions: [{ choice: '方案B：手动维护索引', rejected: '方案A：建索引表（过重）' }],
  verification: ['vitest 24 passed', 'tsc clean', 'build ok'],
  risks: ['对 Unicode 文件名未测试', '性能未实测，大列表可能需虚拟滚动'],
  howToVerify: 'pnpm --filter goods test，页面路径 /goods/list 拖拽排序',
};
```
