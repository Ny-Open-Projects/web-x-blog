## AIC-100：Agent 如何做跨会话的任务衔接？「交接文件」模式怎么设计？
**答**：
- 问题：长任务跨多个会话/多次人工介入，每次重开会话 agent 都失忆，重复探索浪费时间。
- 交接文件（handoff）模式：任务目录下维护固定结构文件——PLAN.md（拆解的步骤与状态勾选）、DECISIONS.md（已定方案与理由）、NEXT.md（下一步与阻塞点）。每个会话开头先读、结束前必写。
- 设计要点：状态用「机器可判定」的标记（checkbox、状态字段）而不是叙述；决策带理由防止下个会话重新发散；NEXT.md 是入口，永远指向唯一下一步。
- 与 git 的配合：交接文件与代码同仓库提交，会话边界对应绿色快照（AIC-083），回滚时交接文件一并回退保持一致。
- 追问钩子：这个模式的本质是「把 agent 的短期记忆物化到文件系统」——文件就是它的外部海马体，这也是 AIC-082 项目记忆的具体落地。

```markdown
<!-- handoff/PLAN.md 示例 -->
- [x] 1. 抽取 usePagination hook
- [x] 2. goods 列表接入
- [ ] 3. orders 列表接入 ← NEXT
- [ ] 4. 删除旧分页逻辑（依赖 3）
<!-- handoff/DECISIONS.md：选 zustand 而非 context，因为跨 4 层组件且已有先例 -->
```
