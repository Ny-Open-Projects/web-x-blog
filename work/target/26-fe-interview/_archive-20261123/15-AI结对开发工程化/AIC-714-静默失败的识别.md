## AIC-714：结对开发中如何识别 AI 看似完成实则未达标的静默失败

**答**：
- 结论先行：静默失败 = AI 输出「看起来完整、能编译」，但没真正满足需求；识别靠「验收前移」——在生成前定义可机器验证的验收条件，生成后逐条断言，而不是靠肉眼读代码。
- 典型形态：1) 只实现了 happy path；2) 用硬编码/mock 冒充真实逻辑；3) 测试写了但断言是 `expect(true)`；4) 性能/边界被悄悄忽略。
- 防范：让 AI 先输出「实现计划 + 验收清单」，人确认后再生成；生成后跑验收脚本，失败即打回而非「差不多就行」。
- 追问钩子：为什么「能编译」不能作为完成标准？——编译只保证语法，不保证行为正确；静默失败恰恰穿过语法层。

```javascript
// 验收前移：生成前定验收，生成后逐条断言
function acceptOrReject(impl, checks) {
  const results = checks.map(c => ({ name: c.name, pass: c.test(impl) }));
  const failed = results.filter(r => !r.pass).map(r => r.name);
  return failed.length ? { ok: false, failed } : { ok: true };
}
const impl = { login: (u, p) => u && p ? 'ok' : null };
console.log(acceptOrReject(impl, [
  { name: 'happy', test: i => i.login('a', 'b') === 'ok' },
  { name: '空密码拒绝', test: i => i.login('a', '') === null },
  { name: '调用真实接口', test: i => !i.login.toString().includes('mock') },
])); // { ok:false, failed:['调用真实接口'] } —— 识别出 mock 冒充
```
