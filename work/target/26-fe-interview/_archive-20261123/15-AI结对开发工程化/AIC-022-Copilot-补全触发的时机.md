## AIC-022：Copilot 的补全是黑盒触发的，如何写「给补全模型看的代码注释」让建议更准？
**答**：
- 补全模型对紧邻上下文最敏感：光标上方 5~20 行决定建议方向，注释要写在光标附近而不是文件头。
- 三种高效注释：① 签名契约（参数、返回、异常）；② 输入输出示例（一行 in → out 胜过十行描述）；③ 反例声明（「不要用 any」「不要引入新依赖」）。
- 先写类型再写实现：TypeScript 的类型声明本身就是最强 prompt，让模型在强类型约束下补全，幻觉率显著下降。
- 分步续写：复杂函数先让模型补壳（结构 + 注释占位），再逐个函数体补全，比一次生成整个函数可控。
- 追问钩子：能提到「注释里给的名字会被模型直接采用」——命名也是一种提示。

```typescript
// ① 契约 + ② 示例 + ③ 反例 的三合一注释

 *      满减不叠加折扣码时返回原价
 * 注意：全部用分（integer），禁止用浮点数运算金额，返回值必须是整数分
 */
function calcPayable(items: { price: number; qty: number }[], coupon?: string): number {
  // 从这里开始补全：先 sum 原价，再应用 coupon 规则表 COUPON_RULES
```
