## AIC-981：IM 消息模块有一段代码的同一个误报被连报了十几个 PR，如何让 AI Review「记住」并抑制它？
**答**：
- 用「带作用域的抑制规则」：对误报记录 `{ 规则ID, 文件/代码指纹, 原因, 过期时间, 创建人 }`，命中即抑制——结论：抑制要精确绑定到具体位置，不能因一处误报就全局关掉规则。
- 抑制要「有过期与复检」：设置有效期（如 30 天）并到期提醒复检，因为代码 evolves，曾经的误报现在可能是真问题；永久抑制会变成新的盲区。
- 用「代码指纹」而非行号：行号随改动漂移，基于内容哈希/规范化代码片段的指纹才能稳定识别同一处，避免误抑制别处。
- 追问钩子：能提出「抑制数据要可视化并定期审计，防止大量『永久抑制』悄悄把 Review 变成摆设」的候选人理解抑制治理的风险。

```typescript
// 带指纹、过期、作用域的误报抑制
function fingerprint(code){ let h=0; const s=code.replace(/\s+/g,'');
  for(const c of s)h=(Math.imul(h,31)+c.charCodeAt(0))>>>0; return h; }
const suppressions = [
  { rule:'ANY-WARN', fp:fingerprint('const x: any = parse(msg)'), reason:'第三方库无类型', expires:'2026-12-31' },
];
function isSuppressed(rule, code, today) {
  const fp=fingerprint(code);
  return suppressions.some(s=>s.rule===rule && s.fp===fp && s.expires>=today); // 命中且未过期
}
console.log(isSuppressed('ANY-WARN','const x: any = parse(msg)', '2026-11-23')); // true
console.log('到期复检:', suppressions.filter(s=>s.expires<'2027-01-01').length);
```
