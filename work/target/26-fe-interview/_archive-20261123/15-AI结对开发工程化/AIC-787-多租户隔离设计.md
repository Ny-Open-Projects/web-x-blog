## AIC-787：平台化 AI 工具链中多租户隔离如何设计

**答**：
- 结论先行：多租户平台必须保证「租户 A 看不到也用不了租户 B 的数据与额度」；隔离分三层——数据隔离（逻辑/物理）、资源隔离（配额/限流）、权限隔离（鉴权/审计）。
- 数据隔离：上下文、prompt、产出按 tenantId 打标并强制过滤；高敏感客户可选独立端点/独立模型实例（物理隔离）。
- 资源隔离：按租户配额限流与计费，防止一个租户跑满拖垮其他租户（噪声邻居）；权限用 RBAC + 审计日志。
- 追问钩子：为什么「逻辑隔离」必须做到查询层强制带 tenantId？——靠业务代码自觉很容易漏，一旦漏就是跨租户数据泄露；应在数据访问层统一注入租户过滤。

```javascript
// 强制租户过滤：数据访问层统一注入 tenantId
function scopedQuery(tenantId, rows) {
  return rows.filter(r => r.tenantId === tenantId); // 强制过滤，调用方无法绕过
}
const rows = [
  { id: 1, tenantId: 'A', data: 'x' },
  { id: 2, tenantId: 'B', data: 'y' },
];
console.log(scopedQuery('A', rows).map(r => r.id)); // [1]
console.log(scopedQuery('B', rows).map(r => r.id)); // [2]
```
