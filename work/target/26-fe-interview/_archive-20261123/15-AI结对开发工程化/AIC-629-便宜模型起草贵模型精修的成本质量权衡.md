## AIC-629：「便宜模型起草 + 贵模型精修」划算吗？怎么权衡？

**答**：
- 结论先行：**只有当「精修成本 << 从头生成成本」且「贵模型确实能识别便宜模型的错误」时才划算**。否则便宜模型的错误根深蒂固，贵模型精修只是在错误上抛光。
- 划算的条件：1) **任务是「量大、单条价值中等」**——如批量生成 CRUD、mock 数据、i18n 文案，便宜模型快速铺量，贵模型只 review 风险高的；2) **错误易检测**——类型错误、测试失败能被客观发现，贵模型（或编译器）能修；3) **成本差显著**——贵模型单价是便宜模型 10 倍以上时，分层才有意义。
- 不划算的场景：1) 需要深度推理的架构设计——便宜模型的方案方向就错了，精修救不回来；2) 精修要重写 80%——不如一开始就贵模型。
- 量化决策：计算 `总成本 = 便宜模型生成成本 + 贵模型精修成本 + 人工返工成本`，与「全程贵模型」对比；关键是**人工返工成本**——如果便宜模型导致大量返工，省下的 API 费会被人力成本吃掉（AIC-307 成本效能）。
- 追问钩子：为什么「编译器/测试」比「贵模型」更适合做精修环节？——因为编译器和测试是确定性的、免费的、100% 准确的；贵模型精修是概率性的、收费的、可能引入新错。能用工具验证的，就别用模型猜。

```typescript
function shouldLayer(cheapCost: number, expensiveCost: number,
  refineCost: number, reworkRate: number, humanCostPerRework: number): { recommended: boolean; saving: number } {
  const layered = cheapCost + refineCost + reworkRate * humanCostPerRework;
  const allExpensive = expensiveCost;
  return { recommended: layered < allExpensive, saving: allExpensive - layered };
}

// 便宜 1 + 精修 2 + 20%返工×10 = 5；全程贵 = 8 → 分层划算，省 3
console.log(shouldLayer(1, 8, 2, 0.2, 10)); // { recommended: true, saving: 5 }
// 返工率飙到 60% 时分层反亏
console.log(shouldLayer(1, 8, 2, 0.6, 10).recommended); // false（1+2+6=9 > 8）
```
