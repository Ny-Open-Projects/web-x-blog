## AIC-983：大促前最后一版代码 AI Review 报了 80 条警告，时间只够处理几条，如何排优先级？
**答**：
- 按「严重性 × 置信度 × 影响面」三维度排序，而非按报告顺序——结论：先处理高severity、高置信、影响核心链路（价格/库存/支付）的问题。
- 结合「可变性」：能快速修且低风险的先修；耗时高、风险大的（如大改架构）记录为技术债，不阻塞本次上线，但要有 follow-up。
- 用「阻断 vs 提示」分级：只有死锁级问题（如安全漏洞、资金计算错误）阻断上线，其余进队列；避免 80 条全阻断导致无法交付。
- 追问钩子：能提出「紧急期的优先级排序要明确『哪些必须现在修、哪些可以带债上线、谁为带债负责』，本质是风险决策而非技术排序」的候选人懂紧急决策。

```typescript
// 三维度优先级排序
function prioritize(warnings) {
  const sev={critical:4,high:3,medium:2,low:1};
  return warnings.map(w=>({
    ...w,
    priority:+( (sev[w.severity]||1)*w.confidence*(w.corePath?2:1) ).toFixed(2),
  })).sort((a,b)=>b.priority-a.priority);
}
const warnings=[
  {id:1,severity:'low',confidence:0.9,corePath:false},
  {id:2,severity:'critical',confidence:0.8,corePath:true},
  {id:3,severity:'high',confidence:0.6,corePath:false},
];
console.log(prioritize(warnings).map(w=>({id:w.id,p:w.priority}))); // 2 最优先
```
