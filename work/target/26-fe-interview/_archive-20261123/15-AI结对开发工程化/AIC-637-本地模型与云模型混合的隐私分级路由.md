## AIC-637：本地模型+云模型混用，怎么按隐私分级路由？

**答**：
- 结论先行：**隐私分级路由 =「数据敏感度决定模型去向」**：高敏数据只走本地模型或不出网，低敏数据走云模型换更强能力。核心是把「能不能出网」变成路由的硬约束，而非事后脱敏（AIC-321 脱敏层 / AIC-076 数据分级）。
- 分级标准：1) **L3 绝密**（密钥、用户 PII、未公开业务数据）——仅本地模型，且本地也要审计；2) **L2 内部**（业务代码、内部 API）——脱敏后可用云模型，或走企业私有部署；3) **L1 公开**（开源代码、通用算法）——云模型随便用。
- 路由实现：在 LLM 网关层做「敏感度标注 → 路由决策」——请求头带数据分级标签，网关按标签选择模型端点；无法标注时默认按最高敏处理（fail-safe）。
- 关键陷阱：**上下文污染**——同一个会话里先处理了 L3 数据又切到云模型，历史上下文带着敏感信息出网了。所以路由必须按「会话」而非「单请求」隔离，敏感会话全程本地。
- 追问钩子：为什么「事后脱敏」不如「路由隔离」可靠？——因为脱敏靠识别敏感模式（正则/NER），总有漏网之鱼（新型 PII、隐晦的业务代号）；而路由隔离在物理层阻止数据出网，不依赖识别准确性——把「可能漏」换成「根本没机会漏」。

```typescript
type Sensitivity = 'L1'|'L2'|'L3';
type Route = { endpoint: string; sanitize: boolean };

function routeBySensitivity(level: Sensitivity, sessionHasSensitive: boolean): Route {
  // 会话曾含敏感数据 → 全程本地，防止上下文污染
  if (sessionHasSensitive || level === 'L3') {
    return { endpoint: 'local-model', sanitize: false };
  }
  if (level === 'L2') return { endpoint: 'cloud-model', sanitize: true };
  return { endpoint: 'cloud-model', sanitize: false };
}

console.log(routeBySensitivity('L1', false).endpoint);           // cloud-model
console.log(routeBySensitivity('L2', false).sanitize);           // true —— 脱敏后出网
console.log(routeBySensitivity('L1', true).endpoint);            // local —— 会话污染兜底
console.log(routeBySensitivity('L3', false).endpoint);           // local
```
