## AIC-932：一个功能经过 AI 十几轮对话迭代才定稿，如何建立「第几轮产出哪段代码」的轮次—代码映射？
**答**：
- 要求每轮产出都带「轮次号 + 父轮次引用」，形成有向无环图（DAG）而非线性列表——因为对话常有回退与分叉（第 8 轮否定了第 5 轮的方案）。
- 每段最终代码通过「来源指针」链接到产生它的轮次（类似 Git 的每个 blob 记录来源），改动时更新指针；这样反查时能沿指针回溯完整演化链。
- 关键挑战是「覆盖与废弃」：被后续轮次推翻的代码要标记为废弃而非删除，保留演化轨迹供审计——结论：映射是可追溯性的骨架。
- 追问钩子：能提出「用内容寻址（哈希）+ 父指针管理轮次，像 Git 一样对待对话历史」的候选人，把对话管理提升到了版本控制高度。

```typescript
// 轮次 DAG：每轮带父引用，代码段链接到产生它的轮次
const rounds = [
  { id:1, parent:null, code:'v1', status:'obsolete' },
  { id:2, parent:1,    code:'v2', status:'obsolete' },
  { id:3, parent:1,    code:'v2-fork', status:'active' }, // 从1分叉
];
function lineage(rounds, id) { // 回溯某轮的完整演化链
  const map = new Map(rounds.map(r => [r.id, r]));
  const chain = []; let cur = map.get(id);
  while (cur) { chain.push(cur.id); cur = cur.parent ? map.get(cur.parent) : null; }
  return chain.reverse();
}
function codeAt(rounds, id){ return rounds.find(r=>r.id===id)?.code; }
console.log('轮次3链路:', lineage(rounds,3), '最终代码:', codeAt(rounds,3));
```
