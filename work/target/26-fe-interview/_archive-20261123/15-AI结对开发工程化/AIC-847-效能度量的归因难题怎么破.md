## AIC-847：用了 AI 之后交付变快了，凭什么说是 AI 的功劳？
**答**：
- 这是**相关不等于因果**的经典问题：交付变快可能是因为需求变简单、人员变熟练、流程优化，AI 只是同期发生。直接把提升归因给 AI 是自欺欺人。
- 严谨方法：**对照实验**——选相似团队/相似任务，一组用 AI 一组不用，或同一团队分时段 AB；但真实组织里很难严格随机，要诚实说明混杂因素。
- 次优方法：**差分中的差分（DiD）**——比较「采用 AI 的团队」和「未采用的团队」在采用前后的变化差，能部分抵消共同趋势。
- 最实用的是**任务级归因**：在同一需求内对比「AI 辅助部分」和「纯手工部分」的耗时/质量，或用「关闭 AI 一周」的灰度对照（A/B 回滚实验）。同时报告置信区间，样本小就不下强结论。
- 追问钩子：能说出「拿不出对照就诚实说'无法严格归因'，只报告相关性」的候选人，具备科学诚实——这比编造因果更有价值。

```typescript
// 差分中的差分（DiD）：比较采用组与对照组在前后期的变化差
function did(beforeA: number, afterA: number, beforeB: number, afterB: number) {
  const changeA = afterA - beforeA; // 采用 AI 团队的变化
  const changeB = afterB - beforeB; // 对照组的变化（共同趋势）
  const effect = changeA - changeB; // 净效应 ≈ AI 的真实贡献
  return {
    changeA, changeB, effect,
    interpretation: effect > 0 ? `AI 净贡献约 ${effect.toFixed(1)}` : '无显著正向贡献',
  };
}
// 示例：周期从 10 天降到 7 天，但对照组也从 9 降到 8
console.log(did(10, 7, 9, 8)); // changeA -3, changeB -1, effect -2 → AI 净贡献约 2 天
// 注意：仍需检验样本量与置信区间；非随机分组只能作为近似
```
