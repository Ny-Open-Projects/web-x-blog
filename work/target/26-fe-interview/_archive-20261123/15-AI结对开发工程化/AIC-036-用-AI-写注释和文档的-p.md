## AIC-036：用 AI 补写注释和文档的 Prompt 怎么写？为什么「解释这段代码」类任务最容易被低估？
**答**：
- 注释类 prompt 三要素：注释风格约定（JSDoc/中文、写「为什么」不写「是什么」）、目标读者（新人/外部 API 使用者）、禁止改代码本身。
- 低估的原因：解释类任务看似简单，实则是新人和存量代码之间最便宜的桥梁——AI 生成的「模块导读」30 秒能替代 2 小时通读。
- 实战用法：接手陌生模块时先让 AI 输出「数据流摘要 + 关键函数职责表」，再带着摘要读代码，效率远高于直接啃。
- 风险与对策：AI 会「合理化」错误代码（把 bug 解释成 feature），所以解释输出要标注「AI 生成待人工确认」，关键结论回代码里验证。
- 追问钩子：文档生成应挂在 CI 上做增量更新（改了导出签名就重生成对应章节），避免文档腐化。

```javascript
// 模块导读生成 prompt（团队 onboarding 标准动作）
const onboardingPrompt = `
你是模块导读员。阅读 <code> 后输出：
1. 该模块的职责与对外接口（表格：导出名 | 用途 | 被谁引用）
2. 核心数据流（从入口到出口，3 句以内）
3. 你不确定的点（明确列出，不要编造）
约束：不修改代码，不评价代码风格，解释以代码事实为准。
<code>
${moduleCode}
</code>`;
```
