## AIC-721：多模型协作中模型能力画像如何建立与维护

**答**：
- 结论先行：能力画像是「哪个模型擅长哪类任务」的结构化知识，是路由与分派的依据；靠主观印象选模型不可复现，必须用评测集量化每个模型在各任务维度的表现。
- 画像维度：代码正确率、长上下文稳定性、指令遵循度、延迟、单位成本、擅长语言/框架；每个维度用固定评测集跑分，结果版本化。
- 维护机制：模型会更新（静默升级导致行为漂移），画像要定期回归评测，发现分数变化立即更新路由策略（RBL-344 模型行为回归）。
- 追问钩子：为什么模型「无通知升级」会让画像失效？——同一模型名背后权重变了，历史分数不再代表当前行为，必须重跑评测。

```javascript
// 模型能力画像：按任务维度记录跑分与成本
const PROFILE = {
  'model-cheap': { code: 0.72, longCtx: 0.5, latency: 200, cost: 1 },
  'model-strong': { code: 0.93, longCtx: 0.9, latency: 1200, cost: 8 },
};
function pickByProfile(task, maxCost) {
  const need = task.long ? 'longCtx' : 'code';
  const candidates = Object.entries(PROFILE).filter(([, p]) => p.cost <= maxCost);
  return candidates.sort((a, b) => b[1][need] - a[1][need])[0]?.[0];
}
console.log(pickByProfile({ long: false }, 2)); // model-cheap（够用且便宜）
console.log(pickByProfile({ long: true }, 10)); // model-strong（长上下文刚需）
```
