## AIC-060：用 AI 搭项目脚手架和内部工具原型的正确姿势？和正式开发有什么区别？
**答**：
- 脚手架是 AI 的甜点区：需求明确（CRUD/表单/图表面板）、模式固定、容忍度高——一天产出过去一周的内部工具完全现实。
- 姿势：先用一句话+参考截图定页面结构，再让 AI 按「路由→数据层→组件」顺序生成；技术栈锁死在团队熟悉的（出问题会修）。
- 和正式开发的区别：原型追求「走通流程」，允许硬编码数据、无测试、无 i18n；但**转正必须补课**——补类型、补测试、补权限，补课清单在立项时就列好。
- 风险管理：原型代码必须放独立目录并标记 `// AI-PROTOTYPE`，防止直接被 copy 进生产而没人负责质量。
- 追问钩子：转正评审的核心问题是「这段代码里有几处是你能独立讲清楚的」——讲不清的部分就是后续维护的雷。

```javascript
// 脚手架任务描述模板（分阶段生成）
const scaffoldPrompt = [
  { step: 'route', ask: '生成路由表与页面骨架，数据用硬编码常量' },
  { step: 'data', ask: '把数据层抽成 service，类型来自 interface File above' },
  { step: 'polish', ask: '补 loading/空态/错误态，补中文文案' },
].map(s => `## ${s.step}\n${s.ask}`).join('\n');
// 标记原型目录
// .gitattributes: ai-prototype/** linguist-generated
```
