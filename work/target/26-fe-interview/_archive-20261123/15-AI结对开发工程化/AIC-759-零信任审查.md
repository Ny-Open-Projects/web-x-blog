## AIC-759：AI 代码审查中零信任理念如何落地

**答**：
- 结论先行：零信任审查 = 默认不信任任何 AI 输出，每份产出都要经过独立验证才能合入——不是因为 AI 不可靠，而是因为「验证成本 << 出错成本」，尤其在生产关键链路。
- 落地：1) 不复用 AI 自己的「检查通过」结论，用独立工具/模型验证；2) 关键结论必须有外部证据（测试、文档、运行结果）；3) 分层授权——低风险任务可快速通道，高风险任务必须人工签字。
- 与信任分级的关系：零信任不是「一刀切不信任」，而是「验证后才信任」；低风险任务的验证可以自动化且轻量。
- 追问钩子：为什么不能信任 AI 的「自评通过」？——生成与自评来自同一模型/上下文，存在系统性偏差（自己检查自己容易漏），必须用独立信号验证。

```javascript
// 零信任：AI 自评不作为依据，独立验证通过才放行
function zeroTrustReview(aiClaim, verifiers) {
  const results = verifiers.map(v => ({ name: v.name, pass: v.check(aiClaim) }));
  const allPass = results.every(r => r.pass);
  return { trusted: allPass, evidence: results, decision: allPass ? 'merge' : 'block' };
}
const r = zeroTrustReview({ code: 'x/0' }, [
  { name: 'lint', check: c => !c.code.includes('/0') },        // 独立 lint 不通过
  { name: 'test', check: c => true },
]);
console.log(r.trusted === false && r.decision === 'block'); // AI 自评"已检查"不被采信
```
