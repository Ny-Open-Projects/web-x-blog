## AIC-749：AI 生成代码的缺陷逃逸率如何度量与降低

**答**：
- 结论先行：缺陷逃逸率 = 「上线后才发现的缺陷数 / 总缺陷数」；它比「生成时通过率」更能反映真实质量——高通过率但高逃逸率说明审查与测试在「自我验证的闭环」里失效了。
- 度量：给每个线上 bug 打标「是否 AI 生成/辅助」，按周统计逃逸率并按任务类型分层；低逃逸率是目标（<5%）。
- 降低手段：1) 提升验收前移质量；2) 关键路径强制人工验证；3) 把逃逸 bug 转成评测集用例，防止同类复发（RBL-465 失败案例库）。
- 追问钩子：为什么逃逸 bug 必须回灌评测集？——否则同类缺陷会在下一次生成中重现，质量改进无法闭环。

```javascript
// 缺陷逃逸率：按 AI 参与标记统计
function escapeRate(bugs) {
  const ai = bugs.filter(b => b.aiAssisted);
  const escaped = ai.filter(b => b.foundAfterRelease);
  return { rate: ai.length ? escaped.length / ai.length : 0, total: ai.length, escaped: escaped.length };
}
const bugs = [
  { aiAssisted: true, foundAfterRelease: false },
  { aiAssisted: true, foundAfterRelease: true },
  { aiAssisted: false, foundAfterRelease: true },
];
console.log(escapeRate(bugs)); // { rate:0.5, total:2, escaped:1 } —— 非 AI 不计入
```
