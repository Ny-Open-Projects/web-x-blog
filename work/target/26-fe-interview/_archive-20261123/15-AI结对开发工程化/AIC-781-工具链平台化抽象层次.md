## AIC-781：AI 工具链平台化中抽象层次如何划分

**答**：
- 结论先行：平台化本质是分层抽象——「基础设施层（模型/算力）→ 能力层（补全/审查/测试等原子能力）→ 编排层（任务流/多模型协作）→ 接入层（IDE/CI/Web）」；每层只依赖下一层，换模型不动业务。
- 分层价值：1) 隔离变化（模型升级只动基础设施层）；2) 能力复用（各接入方共享原子能力）；3) 职责清晰（平台团队管下两层，业务团队管上层）。
- 反模式：IDE 插件直接调模型 API——换模型要改所有客户端；能力层与编排层耦合——无法组合复用。
- 追问钩子：为什么接入层不应该直接调模型 API？——会造成供应商锁定与 N×M 集成复杂度，平台层存在的意义就是收敛成一处。

```javascript
// 四层架构：上层只依赖下层接口
const LAYERS = {
  infra: ['model-gateway', 'vector-store'],
  capability: ['complete', 'review', 'test-gen'],
  orchestration: ['pair-task-flow', 'multi-model-pipeline'],
  access: ['ide-plugin', 'ci-gate', 'web-console'],
};
function assertDependency(from, to) {
  const order = ['infra', 'capability', 'orchestration', 'access'];
  return order.indexOf(from) > order.indexOf(to); // 只允许上层依赖下层
}
console.log(assertDependency('access', 'capability')); // true（合法）
console.log(assertDependency('capability', 'access')); // false（反向依赖，违规）
```
