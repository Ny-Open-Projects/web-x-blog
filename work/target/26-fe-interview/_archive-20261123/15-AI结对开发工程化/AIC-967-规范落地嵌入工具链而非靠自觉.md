## AIC-967：如何让团队 AI 规范「嵌入工具链」而不是靠大家自觉？举几个具体的嵌入点。
**答**：
- 关键嵌入点：① IDE 层——rules 自动加载、实时提示；② 提交层——pre-commit 校验 commit 规范与 AI trailer；③ CI 层——规范扫描作为必过检查；④ PR 层——模板里带规范 checklist。
- 原则是「在离开发者最近的地方拦截」：越早发现问题（写代码时 > 提交时 > CI 时 > 上线后），修复成本越低——结论：规范要前移到最短反馈环。
- 工具链规范要「同一份规则多端复用」：避免 IDE 和 CI 两套规则不一致；规则单一来源、多端适配（呼应 AIC-968）。
- 追问钩子：能提出「每个嵌入点都要有逃生阀（紧急绕过 + 事后补查），否则工具链会成为交付瓶颈」的候选人懂治理与效率的平衡。

```typescript
// 规范的多点嵌入 + 逃生阀
const checkpoints = [
  { at:'IDE', rule:'实时提示', blocking:false },
  { at:'pre-commit', rule:'commit格式', blocking:true },
  { at:'CI', rule:'规范扫描', blocking:true },
  { at:'PR', rule:'checklist', blocking:false },
];
function runCheckpoint(cp, violation, emergencyBypass) {
  if (violation && cp.blocking && !emergencyBypass) return `${cp.at}: 拦截`;
  if (violation && emergencyBypass) return `${cp.at}: 紧急绕过(需事后补查)`;
  return `${cp.at}: 通过`;
}
console.log(checkpoints.map(c=>runCheckpoint(c, true, false)));
```
