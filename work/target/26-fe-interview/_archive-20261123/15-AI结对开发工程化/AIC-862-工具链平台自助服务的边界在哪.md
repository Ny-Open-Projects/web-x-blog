## AIC-862：工具链平台做「自助服务」的边界在哪？什么都开放行不行？
**答**：
- 不能全开放：**自助的是「受约束的选择」而非无限自由**。平台把安全、合规、成本这些「必须统一」的维度收归平台控制，把业务语义（prompt 模板、评测标准、流程编排）开放给业务自治。
- 划分依据：**变更的影响半径**。影响单团队内部的（改自己的 prompt）自助；影响跨团队/全局的（新增模型供应商、改计费口径、放开工具权限）必须平台审批。
- 手段是**护栏 + 默认安全**：提供「黄金路径」（预置的安全模板，照着用最省事），偏离路径需要申请但可通过；权限用能力令牌按场景授权，高风险操作要二次确认。
- 边界要**可演进**：初期收紧（信任未建立），随着团队成熟度提高逐步下放；下放前要有可观测和回滚能力兜底。
- 追问钩子：能说出「自助是受约束的选择，平台收口影响半径大的变更，开放影响半径小的」的候选人，把握了平台治理的核心原则。

```typescript
type Action = { name: string; scope: 'team' | 'org'; risk: 'low' | 'high' };

// 边界判定：影响半径 × 风险
function canSelfServe(action: Action, teamMaturity: number) {
  if (action.scope === 'org') return { allowed: false, reason: '跨组织变更需平台审批' };
  if (action.risk === 'high' && teamMaturity < 3) {
    return { allowed: false, reason: '团队成熟度不足，高风险操作需审批' };
  }
  return { allowed: true, reason: '黄金路径内，自助完成' };
}
console.log(canSelfServe({ name:'修改本团队 prompt', scope:'team', risk:'low' }, 2));
// { allowed:true, ... }
console.log(canSelfServe({ name:'接入新模型供应商', scope:'org', risk:'high' }, 5));
// { allowed:false, reason:'跨组织变更需平台审批' }
// 团队成熟度提升后，可逐步把 scope=team & risk=high 的操作下放
```
