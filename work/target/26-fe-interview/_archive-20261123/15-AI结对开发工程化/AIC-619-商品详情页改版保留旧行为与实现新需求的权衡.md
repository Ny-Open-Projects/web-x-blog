## AIC-619：商品详情页改版，怎么让 AI 在「保留旧行为」和「实现新需求」间正确权衡？

**答**：
- 结论先行：**关键是把「保留什么」变成可执行的清单喂给 AI，而不是指望它自己推断**。AI 天生倾向「大刀阔斧重写」，因为它看到的是代码而非历史决策——哪些看似丑陋的旧逻辑其实承载着业务规则。
- 建立「行为基线」：改版前先让 AI 生成一份「现有行为清单」（当前组件在哪些场景做什么），人工补充 AI 看不出的潜规则（如「划线价只在特定渠道展示」），这份清单成为新需求的约束（AIC-129 Agent 友好仓库）。
- 用 feature flag 隔离：新需求用开关包裹（AIC-370），旧路径保留不删，灰度验证新路径。这样「保留旧行为」是物理保证而非口头承诺，出问题秒切回。
- 回归测试当护栏：把行为基线里的每条写成测试用例，AI 的新实现必须让这些测试全绿——「不动旧行为」变成可自动验证的条件，而不是靠 AI 自觉遵守。
- 追问钩子：为什么「让 AI 列行为清单」本身也需要人工补充？——因为 AI 只能从代码推断「代码做了什么」，推断不出「为什么这么做」；业务规则、历史坑点、合规要求常以「反直觉的特判」形式存在，这些潜规则只有人知道，不写下来 AI 一定会在重写时抹掉。

```typescript
// 行为基线：改版前后的行为对照，AI 新实现必须通过旧行为断言
type Behavior = { name: string; check: (oldOut: any, newOut: any) => boolean };

const baseline: Behavior[] = [
  { name: '划线价仅特定渠道展示', check: (o, n) => o.strikePrice === n.strikePrice },
  { name: '库存为0显示"到货通知"', check: (o, n) => o.stockLabel === n.stockLabel },
];

function validateRewrite(oldModel: any, newModel: any, baseline: Behavior[]) {
  const passed = baseline.filter(b => b.check(oldModel, newModel)).map(b => b.name);
  const failed = baseline.filter(b => !b.check(oldModel, newModel)).map(b => b.name);
  return { passed, failed, safe: failed.length === 0 };
}

const old = { strikePrice: 99, stockLabel: '到货通知' };
const rewritten = { strikePrice: 99, stockLabel: '暂无库存' }; // 破坏了旧行为
console.log(validateRewrite(old, rewritten, baseline).failed); // ['库存为0显示"到货通知"']
```
