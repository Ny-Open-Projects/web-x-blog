## AIC-709：AI 结对开发中小步快跑的提交粒度如何设计

**答**：
- 结论先行：AI 一次容易产出大块改动，但「大 diff = 难审查 = 高风险」；应把 AI 产出切成语义完整、可独立回滚的小提交，每个提交对应一个可验证的意图。
- 切分原则：1) 按意图切（一个 commit 只做一件事）；2) 按可回滚性切（改动能独立 revert 而不破坏构建）；3) 按验证切（每个 commit 都能跑对应测试）。
- 操作手法：让 AI 按「任务卡」逐张生成，生成一张提交一张；禁止把「重构 + 功能 + 格式化」混在一个 commit。
- 追问钩子：为什么「格式化单独提交」能降低审查成本？——把噪声 diff 从功能 diff 中剥离，审查者只看真正改变行为的行。

```javascript
// 提交粒度检查：一个 commit 只能有一个意图标签
const INTENT = ['feat', 'fix', 'refactor', 'docs', 'style', 'test', 'chore'];
function validateCommit(files, intentTags) {
  const unique = [...new Set(intentTags)];
  if (unique.length !== 1) return { ok: false, reason: '一个提交只能有一个意图' };
  if (!INTENT.includes(unique[0])) return { ok: false, reason: '未知意图' };
  const hasBehavior = files.some(f => f.endsWith('.ts') || f.endsWith('.js'));
  if (unique[0] === 'style' && hasBehavior) return { ok: false, reason: 'style 不应含行为代码' };
  return { ok: true, intent: unique[0] };
}
console.log(validateCommit(['a.ts'], ['feat']));        // ok
console.log(validateCommit(['a.ts'], ['feat', 'style'])); // 多意图
console.log(validateCommit(['a.ts'], ['style']));         // style 含行为
```
