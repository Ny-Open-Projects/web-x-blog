## AIC-723：多模型流水线中模型降级如何触发与恢复

**答**：
- 结论先行：降级不是「出错就换便宜模型」，而是「在质量约束内降级」——先判断任务对质量的敏感度，低敏感任务才允许降级，高敏感任务宁可失败重试也不降级。
- 触发条件：主模型超时、限流、成本超预算、连续两轮质量不达标；按原因选不同降级目标（超时→更快模型，成本→更便宜模型）。
- 恢复机制：降级是临时的，要有「恢复探针」定期探测主模型可用性，恢复后切回并记录本次降级影响（哪些任务用了降级模型）。
- 追问钩子：为什么降级必须记录「哪些任务被降级」？——事后质量回溯需要知道结果出自哪个模型，否则问题无法归因。

```javascript
// 模型降级决策：按原因选择目标，并记录
function degrade(reason, task, budget) {
  const map = { timeout: 'fast-model', rateLimit: 'backup-model', cost: 'cheap-model', quality: null };
  const target = map[reason];
  if (reason === 'quality') return { action: 'retry', model: task.model }; // 质量问题不降级，重试
  if (!budget.allowDegrade || budget.remaining <= 0) return { action: 'fail' };
  return { action: 'degrade', model: target, logged: true };
}
console.log(degrade('timeout', { model: 'main' }, { allowDegrade: true, remaining: 5 }));
console.log(degrade('quality', { model: 'main' }, { allowDegrade: true, remaining: 5 })); // retry
```
