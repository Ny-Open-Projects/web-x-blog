## AIC-030：写 Prompt 时「正向指令」和「负面约束」怎么搭配？为什么「不要做 X」经常失效？
**答**：
- 模型对正向指令的服从度显著高于否定句：「不要用 var」不如「统一使用 const/let，采用块级作用域声明」。
- 失效原因：否定词会被语义里的「var」激活反而提供注意力线索；且模型倾向满足「有具体做法」的指令而非空泛的禁令。
- 搭配原则：**每个负面约束都配一个正向替代**——"不要弹 alert，统一走项目的 notification.showToast"。
- 优先级排序：约束列表按重要度从上往下写（模型对开头结尾更敏感，中段约束最易丢），关键红线放首尾。
- 追问钩子：约束数量控制在一屏内，超过后「规则密度过高」会导致全部约束都打折——这是 AIC-006 规则失效的同款问题。

```javascript
// 负面约束 → 正向约束的改写对照表（可沉淀为团队 prompt lint 规则）
const rewriteRules = [
  { bad: '不要使用 CSS in JS', good: '样式统一用 Tailwind 原子类，复杂动效用 CSS Module' },
  { bad: '不要写 any', good: '所有参数与返回值标注精确类型，泛型不确定时用 unknown + 收窄' },
  { bad: '不要改我贴的代码之外的地方', good: '只输出目标函数的修改，其余文件保持原样并在说明中列出未改动项' },
];
// prompt 组装：把 good 列表作为「约束」段落
const constraints = rewriteRules.map(r => `- ${r.good}`).join('\n');
```
