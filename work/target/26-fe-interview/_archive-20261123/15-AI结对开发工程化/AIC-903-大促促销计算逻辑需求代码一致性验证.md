## AIC-903：大促前 AI 生成的「满减+折扣+优惠券」叠加计算逻辑，如何做「需求—代码」一致性验证？
**答**：
- 先把模糊需求转成「可执行规格」：用真值表/决策表列出各优惠组合的预期结果（如满300减50与9折能否叠加），这是验证的基准。
- 让 AI 生成代码的同时生成「逐条对应规格的测试用例」，评审时人只核对规格表是否覆盖完整，而非逐行读代码。
- 用属性测试补充规格盲区：如「任何情况下实付金额 ≤ 原价」「优惠额度非负」，这些不变量比枚举用例更能抓边界。
- 追问钩子：能强调「先固化需求为机器可读的真值表，再让代码与表对齐」的候选人，懂得验证的锚点是需求而非代码本身。

```typescript
// 需求真值表驱动的一致性验证
const spec = [
  { cart:300, coupon:'MAN300', discount:0.9, expect:225 }, // 满减与折扣叠加
  { cart:299, coupon:'MAN300', discount:1,   expect:299 }, // 未达门槛不减
  { cart:100, coupon:'NONE',   discount:0.9, expect:90  },
];
function calc(cart, coupon, discount) { // AI 生成的实现
  const cut = coupon === 'MAN300' && cart >= 300 ? 50 : 0;
  return Math.max(0, (cart - cut) * discount);
}
const mismatches = spec.filter(s => calc(s.cart, s.coupon, s.discount) !== s.expect);
// 属性测试：不变量——实付永不超过原价且非负
const propertyOk = spec.every(s => { const p = calc(s.cart,s.coupon,s.discount); return p>=0 && p<=s.cart; });
console.log('规格不一致:', mismatches.length, '不变量通过:', propertyOk);
```
