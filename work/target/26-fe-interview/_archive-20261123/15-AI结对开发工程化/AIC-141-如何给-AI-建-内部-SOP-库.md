## AIC-141：如何给 AI 建内部 SOP 库（标准作业流程）？SOP 和 prompt 模板是什么关系？
**答**:
- 关系定义：prompt 模板管「一次任务的输入输出形态」，SOP 管「一类工作的完整流程」（步骤、检查点、异常处理）——SOP 是模板的编排，一个 SOP 内含多个模板调用。
- SOP 结构：适用范围（什么任务走此 SOP）→ 前置条件（需要什么材料）→ 步骤（每步：动作 + 使用的 prompt + 产出物）→ 检查点（人工介入时刻，AIC-088）→ 异常处理（失败怎么办）。
- 建库来源：团队高频流程（发布、hotfix、依赖升级、新人任务）各写一份；从「人做的流程文档」改造而来——把「找某人确认」改写成「检查点：暂停等人工」。
- 治理：SOP 进 Git 走 PR；每个 SOP 标注「最近验证日期」——流程变化后 SOP 不更新就是灾难源。
- 追问钩子：SOP 是 agent 从「单任务」走向「流程级自动化」（L5，AIC-092）的载体——有 SOP 的团队才玩得起流程 agent。

```markdown
<!-- ai/sop/hotfix.md -->
## 适用：生产 hotfix
1. 复现：用 evidencePack 模板（prompts/evidence.md）
2. 定位：诊断 prompt + 依赖图影响面
3. 修复：fix prompt，验收=复现测试转绿
4. 检查点①：人确认根因判断
5. 发布：走 hotfix 分支 + CI
6. 检查点②：人确认发布
异常：修复 3 轮未绿 → 升级人工
```
