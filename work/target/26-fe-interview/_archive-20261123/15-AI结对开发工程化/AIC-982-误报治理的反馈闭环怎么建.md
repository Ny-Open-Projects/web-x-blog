## AIC-982：如何为 AI Review 建立一个「误报治理的反馈闭环」，让系统越用越准而不是越用越烦？
**答**：
- 闭环四步：① 报告带结构化反馈按钮（真问题/误报/建议不当）；② 反馈入库并关联规则/文件/模型版本；③ 定期分析反馈调整规则（降权/加上下文/关闭）；④ 用调整后的效果指标（精确率/处置率）验证改进是否生效。
- 反馈要「低成本」：开发者点一下即可，不要填长表单；低摩擦才有数据，没数据就没优化依据。
- 把「高价值反馈」沉淀进规则：误报案例转成规则的反向样例（不该报的场景），进入规则的回归测试集，防止规则改版后旧误报复发。
- 追问钩子：能强调「闭环的关键是反馈真的驱动了规则变更，并有指标证明变准了——否则只是收集了一堆无人看的抱怨」的候选人懂闭环的实质。

```typescript
// 误报治理闭环：反馈 → 分析 → 调规则 → 验证
function feedbackLoop(feedbacks, rules) {
  const byRule = {};
  for(const f of feedbacks){ byRule[f.rule] ??= {fp:0,tp:0};
    byRule[f.rule][f.label==='falsePositive'?'fp':'tp']++; }
  const updated = rules.map(r=>{
    const s=byRule[r.id]||{fp:0,tp:0}, precision=s.tp/(s.tp+s.fp||1);
    return { ...r, weight: precision<0.3 ? r.weight*0.5 : r.weight }; // 误报多→降权
  });
  return { byRule, updated };
}
console.log(feedbackLoop(
  [{rule:'ANY',label:'falsePositive'},{rule:'ANY',label:'falsePositive'},{rule:'KEY',label:'truePositive'}],
  [{id:'ANY',weight:1},{id:'KEY',weight:1}]).updated);
```
