## AIC-067：团队应该建「AI 知识库」吗？里面放什么、不放什么？和规则文件是什么关系？
**答**：
- 该建，但要分清两层的职责：规则文件（常驻、短、每次任务都注入）管「行为约束」；知识库（按需检索、可长）管「领域事实」。
- 知识库放：术语表与缩写、领域模型图解、核心流程时序、历史事故复盘、API 事实卡片（版本+签名+示例）、prompt 模板库、few-shot 示例库。
- 不放：会腐烂的细节（具体行号、临时方案）、敏感信息（密钥、客户数据）、大段抄来的文档（放链接让 AI 需要时再取）。
- 关系：规则文件里写「遇到 XX 领域问题时先查知识库/ai/domain/*.md」——规则是路由，知识库是内容；两者都进 Git 由 PR 治理。
- 追问钩子：知识库的价值取决于「检索是否顺手」，宁可目录结构简单 + 命名规范，也不要上复杂 RAG 一开始就过度工程。

```
ai/
  AGENTS.md          # 规则：路由层（常驻）
  knowledge/
    glossary.md      # 术语表
    incident-*.md    # 事故复盘（含「AI 使用教训」段）
    fact-*.md        # API 事实卡片
prompts/             # prompt 模板库
```
