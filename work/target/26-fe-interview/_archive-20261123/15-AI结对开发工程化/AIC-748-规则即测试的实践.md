## AIC-748：AI 质量工程中规则即测试的实践如何落地

**答**：
- 结论先行：规则即测试 = 把团队的编码规范/审查意见写成可自动执行的 lint 规则或断言，让「规范」从文档变成门禁——AI 才会真正遵守，因为文档里的规范 AI 容易忽略，可执行的规则无法绕过。
- 落地路径：1) 从高频审查意见提炼规则（RBL-461 评审意见转 lint）；2) 用真实 badcase 做规则的测试用例；3) 规则进 CI 门禁，违规即失败；4) 规则本身版本化并衡量拦截率。
- 与 prompt 约束的关系：prompt 里写规范是「软约束」，可能失效；lint 是「硬约束」，稳定可靠——关键规范必须双保险。
- 追问钩子：为什么高频审查意见最适合转成规则？——高频意味着反复消耗人力且模式稳定，自动化 ROI 最高。

```javascript
// 高频审查意见 → 可执行的 lint 规则
const RULES = [
  { id: 'no-console', test: code => !/\bconsole\.log\b/.test(code), msg: '禁止 console.log' },
  { id: 'no-any', test: code => !/\bany\b/.test(code), msg: '禁止 any 类型' },
];
function lint(code) {
  return RULES.filter(r => !r.test(code)).map(r => r.id + ': ' + r.msg);
}
console.log(lint('const x: any = 1; console.log(x);')); // ['no-console:...', 'no-any:...']
console.log(lint('const x: number = 1;'));             // [] → 通过
```
