## AIC-799：团队从散装 AI 工具迁移到统一平台的策略如何设计

**答**：
- 结论先行：迁移不能「一刀切断旧」——用渐进式策略：先建平台能力并证明更优 → 双轨并行让团队平滑过渡 → 逐步收紧旧工具入口 → 最终下线；每一步都有回退能力。
- 步骤：1) 盘点现有工具与用法，识别高频场景优先覆盖；2) 平台能力对齐（不能比旧工具差）；3) 双跑验证（同一任务旧/新都跑，比质量成本）；4) 迁移激励与培训；5) 旧工具只读冻结后下线。
- 风险：平台能力不齐时强推会导致「用旧的更有效」的倒退；必须诚实评估平台成熟度。
- 追问钩子：为什么双跑阶段不可省略？——它用真实任务证明平台「不比原来差」，是争取团队信任的关键证据。

```javascript
// 迁移阶段门禁：能力对齐才进入下一阶段
function migrationStage(platformReadiness, dualRunDone) {
  if (!platformReadiness) return 'build-capability';           // 先建能力
  if (!dualRunDone) return 'dual-run';                          // 双跑验证
  return 'cutover';                                             // 逐步切换
}
console.log(migrationStage(false, false)); // build-capability
console.log(migrationStage(true, false));  // dual-run
console.log(migrationStage(true, true));   // cutover
```
