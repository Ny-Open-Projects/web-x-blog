## AIC-733：本地模型与云端模型混合协作的架构如何设计

**答**：
- 结论先行：混合架构 = 「敏感/高频/低难度」任务走本地模型（数据不出域、延迟低、成本可控），「高难度/需最新知识」任务走云端模型；核心是分类路由 + 统一接口。
- 架构要点：1) 统一调用接口屏蔽本地/云端差异；2) 路由器按敏感度、难度、成本分类；3) 本地模型做前置过滤（脱敏、分类），云端只接收脱敏后的必要数据。
- 风险：本地模型能力弱，需设置质量兜底——本地输出置信度低时上抛云端，避免「将就用本地弱结果」。
- 追问钩子：为什么混合架构里本地模型适合做「前置脱敏」？——敏感数据在本地完成处理，只把脱敏结果送云端，从源头降低泄露面。

```javascript
// 混合路由：敏感度 + 难度决定本地/云端
function route(task) {
  if (task.sensitive) return { target: 'local', reason: '数据敏感不出域' };
  if (task.difficulty === 'high') return { target: 'cloud', reason: '需强模型' };
  if (task.confidenceLow) return { target: 'cloud', reason: '本地置信低需兜底' };
  return { target: 'local', reason: '本地够用' };
}
console.log(route({ sensitive: true, difficulty: 'high' }));  // local（敏感优先）
console.log(route({ sensitive: false, difficulty: 'low' }));  // local
console.log(route({ sensitive: false, difficulty: 'low', confidenceLow: true })); // cloud 兜底
```
