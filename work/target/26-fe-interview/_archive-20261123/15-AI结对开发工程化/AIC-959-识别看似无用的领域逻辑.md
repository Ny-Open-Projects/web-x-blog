## AIC-959：AI 重构时把一段「看起来没用」的代码删了，结果那是重要的业务领域逻辑，如何避免？
**答**：
- 根因是 AI（和人）容易把「无显式调用」等同于「无用」——结论：删除前必须证明「无副作用且无隐式依赖」，而非仅看静态引用。
- 识别手段：① 查动态调用/反射/字符串拼接调用（如 `obj[methodName]`）；② 查该逻辑与持久化数据/接口契约的关联（可能在校验历史数据格式）；③ 查注释与领域术语，domain 相关代码即使无显式调用也要审慎。
- 组织手段：建立「领域语言清单」——把核心业务概念、规则列为受保护资产，AI 不得擅自删除；删除受保护代码需人工评审签字。
- 追问钩子：能说出「『死代码』的判定需要运行时证据（如采样调用/日志），静态分析只能提示不能定论」的候选人，对删除操作保持敬畏。

```typescript
// 删除前的安全检查：别把领域逻辑当死代码
const PROTECTED_DOMAINS = ['computeDiscount','validateSku','settlePrice']; // 领域语言清单
function canDelete(symbol, { staticRefs, runtimeHits, inDomainList }) {
  const reasons = [];
  if (PROTECTED_DOMAINS.includes(symbol) || inDomainList) reasons.push('领域核心逻辑');
  if (runtimeHits > 0) reasons.push('运行时有调用');
  if (hasDynamicCall(symbol, staticRefs)) reasons.push('可能被动态调用');
  return { safe: reasons.length===0, reasons };
}
function hasDynamicCall(sym, refs){ return refs?.some(r=>r.includes('[') && r.includes(sym)); }
console.log(canDelete('computeDiscount',{ staticRefs:[], runtimeHits:0, inDomainList:true }));
```
