## AIC-757：AI 结对开发中回归检测的分层策略如何设计

**答**：
- 结论先行：AI 改动影响面大，回归要分层——L1 单元测试（快、全量）、L2 集成测试（中、按影响选）、L3 E2E（慢、只跑关键路径），按「改动风险」决定跑到哪一层。
- 分层依据：1) 改动文件的影响半径（依赖图分析）；2) 风险等级（支付/权限等敏感区强制跑 L3）；3) 历史 flaky 情况（避开已知不稳定用例）。
- 与 AI 的结合：让 AI 根据 diff 生成「影响清单」，据此选择回归层与用例，而不是每次全量跑（成本不可接受）。
- 追问钩子：为什么不能每次都跑全量回归？——AI 高频生成下，全量回归的时长会成为瓶颈，拖慢反馈循环，反而降低采纳率。

```javascript
// 分层回归：按风险选层
function chooseRegression(change) {
  if (change.touchesPayment || change.touchesAuth) return { level: 'L3', suites: ['checkout', 'login', 'e2e'] };
  if (change.affects > 5) return { level: 'L2', suites: ['integration'] };
  return { level: 'L1', suites: ['unit'] };
}
console.log(chooseRegression({ touchesPayment: true, affects: 2 }).level); // L3
console.log(chooseRegression({ affects: 10 }).level);                     // L2
console.log(chooseRegression({ affects: 2 }).level);                      // L1
```
