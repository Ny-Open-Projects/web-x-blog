## AIC-715：如何用结对日志复盘 AI 协作中的效率瓶颈

**答**：
- 结论先行：结对日志是「过程数据」，复盘要回答三个问题——时间花在哪、卡点在哪、哪类任务 AI 帮倒忙；没有结构化日志就只能凭感觉优化。
- 记录字段：任务类型、生成耗时、人工返工轮数、采纳率、失败原因；关键是记「返工轮数」而非「生成速度」——高返工说明 prompt 或上下文有问题。
- 复盘产出：把高频返工原因转成规则/技能沉淀（RBL-358），形成「记录→归因→改进→验证」闭环，而不是一次性总结。
- 追问钩子：为什么「生成快」不等于「效率高」？——生成 1 分钟但返工 5 轮，远慢于生成 3 分钟一次过。

```javascript
// 结对日志复盘：按返工归因找瓶颈
function retro(logs) {
  const byCause = {};
  for (const l of logs) {
    if (l.rework > 1) byCause[l.failCause] = (byCause[l.failCause] ?? 0) + l.rework;
  }
  const top = Object.entries(byCause).sort((a, b) => b[1] - a[1])[0];
  return { topCause: top?.[0], waste: top?.[1] ?? 0 };
}
console.log(retro([
  { rework: 3, failCause: '上下文不足' },
  { rework: 4, failCause: '上下文不足' },
  { rework: 2, failCause: 'prompt含糊' },
])); // { topCause:'上下文不足', waste:7 } → 优先改进上下文准备
```
