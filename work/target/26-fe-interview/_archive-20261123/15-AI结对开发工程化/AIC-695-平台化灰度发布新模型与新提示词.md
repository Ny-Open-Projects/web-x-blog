## AIC-695：新模型/新提示词上线，平台怎么做灰度发布？

**答**：
- 结论先行：**AI 能力的灰度比普通功能更需谨慎——模型输出是概率的、可能静默退化，所以必须「小流量 + 对照 + 质量指标达标才放量」（AIC-284 评审金丝雀）**。
- 灰度维度：1) **按流量比例**：1% → 5% → 20% → 100%，每档观察足够样本；2) **按团队/用户**：先内部团队 dogfood，再放量；3) **按任务类型**：先在低风险任务（文案/格式）验证，再上核心任务。
- 放量门槛（每档必须达标才进下一档）：1) **质量指标**：评测集通过率不低于基线 − 容忍度；2) **线上信号**：接受率/存活率/回滚率不劣化；3) **成本与延迟**：不超预算/SLA；4) **无严重事故**：灰度期零 P0/P1。
- 关键机制：1) **A/B 可对照**：灰度组与对照组同条件，才能归因（AIC-670）；2) **快速回滚**：一键切回旧模型/prompt，配置化而非改代码；3) **自动熔断**：灰度组指标超阈值自动停止放量并告警。
- 追问钩子：为什么「评测集通过率」和「线上信号」都要看？——因为评测集是「实验室条件」（固定用例），线上是「真实分布」；评测集过不代表线上好（可能有分布偏移），线上信号滞后（要等采纳/存活数据）；两者互补——评测集快速筛掉明显差的，线上信号确认真实效果。

```typescript
type GrayMetrics = { evalPassRate: number; baselineRate: number; acceptance: number; baselineAccept: number; incidents: number };

function canPromote(m: GrayMetrics, opts = { tolerance: 0.05, acceptDropMax: 0.1 }): boolean {
  const { tolerance = 0.05, acceptDropMax = 0.1 } = opts;
  return m.evalPassRate >= m.baselineRate - tolerance   // 评测不退化
    && m.acceptance >= m.baselineAccept - acceptDropMax  // 线上接受率不崩
    && m.incidents === 0;                                 // 无事故
}

const stage1 = { evalPassRate: 0.88, baselineRate: 0.9, acceptance: 0.7, baselineAccept: 0.72, incidents: 0 };
console.log(canPromote(stage1) === true); // 小幅波动，达标放量
const stage2 = { evalPassRate: 0.75, baselineRate: 0.9, acceptance: 0.6, baselineAccept: 0.72, incidents: 1 };
console.log(canPromote(stage2) === false); // 评测退化+事故，停止
```
