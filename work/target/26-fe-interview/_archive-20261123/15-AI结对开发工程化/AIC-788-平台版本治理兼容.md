## AIC-788：平台化 AI 工具链的版本治理与兼容性如何设计

**答**：
- 结论先行：平台接口一旦被多业务方依赖就成「契约」，版本治理用语义化版本（SemVer）+ 弃用周期——破坏性变更必须升主版本并留迁移期，不能悄悄改。
- 要点：1) SemVer（主/次/补丁）明确变更级别；2) 弃用流程（deprecate → 警告 → 移除，跨多个版本）；3) 兼容层（新版本暂时兼容旧调用）；4) 变更日志与迁移指南。
- 对 AI 的特殊性：模型/prompt 变更也算「行为版本」，要像 API 一样版本化，否则同一接口行为漂移难以追责。
- 追问钩子：为什么 prompt 变更也要版本化？——prompt 是「行为代码」，改动会改变输出；不版本化就无法知道某次质量变化是哪个 prompt 版本导致的。

```javascript
// SemVer 兼容性判断
function compatible(current, required) {
  const [cMaj] = current.split('.').map(Number);
  const [rMaj, rMin] = required.split('.').map(Number);
  return cMaj === rMaj && current.localeCompare(required, undefined, { numeric: true }) >= 0;
}
console.log(compatible('3.2.0', '3.1.0')); // true（同主版本，更高次版本）
console.log(compatible('4.0.0', '3.1.0')); // false（主版本破坏性变更）
console.log(compatible('3.0.0', '3.1.0')); // false（低于要求）
```
