## RBL-319：构建系统支持灰度发布的产物分流

**答**:
- 产物层灰度：同一 commit 构建多套产物（stable/canary 各自 flag 组合）→ 部署到不同目录（/stable/ /canary/）→ 入口分流（cookie/百分比）选产物
- 构建配置：多产物输出的 manifest 命名空间隔离（防 hash 冲突）、canary 产物带版本标记（可观测区分流量桶）
- 一致性保障：canary 与 stable 的公共 chunk 尽量共享（CDN 缓存复用），只有差异部分独立——构建配置的 chunk 策略决定
- 回滚：灰度异常直接切入口指向 stable（秒级），产物不删除（保留 N 版本）

```text
结构：/dist/stable/main.abc.js + /dist/canary/main.def.js
入口分流：cookie=canary → 加载 /canary/index.html
公共 chunk：共享 vendor hash 复用 CDN 缓存
```
