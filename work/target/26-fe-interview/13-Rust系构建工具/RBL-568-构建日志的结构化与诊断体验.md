## RBL-568：构建工具的诊断体验：错误结构化与「可操作的报错」设计

**答**：
- 报错质量是构建工具的第二竞争力——核心是把错误**结构化**（Diagnostic 对象：severity/code/message/span/labels/hints/related），渲染只是最后一步（终端 fancy / CI 纯文本 / IDE JSON 三种渲染器）。
- 好报错的要素：1) 主消息说「什么错了」，label 标到源码具体 span（错误下划线 + 上下文行）；2) hint 给「怎么改」（如「did you mean」、缺失 peer 依赖的安装命令）；3) related spans 解释因果链（「这里 import → 这里 resolve 失败」）；4) 错误码稳定可搜索（E0001 风格），文档可链接。
- 批量错误策略：单模块失败不终止整个构建能收集的更多错误（fail-fast vs collect-all 可配）——但 DCE/压缩阶段的错误常互相依赖，必须 fail-fast；CI 场景默认 collect-all + 上限截断（防止 10 万行刷屏）。
- 错误去重与聚合：同一 resolveId 在 50 个模块被 import → 聚合成一条主错误 + 引用列表，而不是 50 条。
- 追问钩子：sourcemap 与错误定位的关系——压缩产物报错要反解回源码位置（sourcemap 反查），这是构建器提供「runtime error → 源码 span」链路的原因，也是 sourcemap 保留 names 段的价值。

```javascript
// 诊断结构设计示意
class Diagnostic {
  constructor({ severity, code, message }) { this.severity = severity; this.code = code; this.message = message; this.labels = []; this.hints = []; this.related = []; }
  label(span, text) { this.labels.push({ span, text }); return this; }   // span: { file, start, end }
  hint(text) { this.hints.push(text); return this; }
  related(diag) { this.related.push(diag); return this; }
}

// 使用：resolve 失败的可操作报错
function resolveError(id, importer, suggestions) {
  return new Diagnostic({ severity: 'error', code: 'RBL1001', message: `Cannot resolve '${id}' from ${importer}` })
    .label(spanOf(importer, id), `import 语句在这里`)
    .hint(`是否漏装依赖？npm i ${id}`)
    .hint(...suggestions.map(s => `相似包：${s}（did you mean）`))
    .related(new Diagnostic({ severity: 'note', code: 'RBL1001N', message: `同 id 另有 ${refs.length - 1} 处引用已聚合` }));
}
```
