## RBL-861：迁移复盘：十年老仓库的考古式迁移——历史债的考古方法

**答**:
- 老仓库的「活化石」问题：构建配置里有大量「没人知道为什么存在」的配置（2015 年加的 alias、绕过某工具 bug 的 loader hack）——考古方法：1) **git blame 归因**（每条可疑配置的引入 commit + 当时上下文——commit message/关联 issue）；2) 使用面验证（该配置今天还影响构建吗——删除试验：临时移除后构建产物 diff，无差异即可删）；3) 归类（有效逻辑/失效遗留/历史 workaround——workaround 的新工具可能已内置解法）。
- 删除试验的工程化：不是手工逐条——「配置最小化脚本」（自动逐项注释配置 → 构建对比 → 产物一致则标记可删）；二分式收敛（多条可疑配置批量测试）。
- 考古的价值边界：只考古「影响迁移的配置」（会阻塞翻译器的部分），全仓考古是无底洞——考古的投入与迁移阻塞度挂钩（RBL-664 评估中的 configHacks 项）。
- 文化的副产品：考古产出「配置说明文档」（每条配置的存在理由）——比迁移本身更长效的资产（下一个改配置的人不用重新考古）。
- 追问钩子：为什么「删除试验」比「咨询老员工」可靠？——人的记忆失真（记得加过但忘了已删/忘了副作用）；删除试验是行为级证据（产物一致 = 确实无用）；且试验成本低（一次构建几分钟）——「实证优于回忆」是考古方法论的核心，与死代码判定（RBL-814）的「运行时证据」哲学一致。

```javascript
// 配置考古流水线
async function archaeology(config, { build, baseline }) {
  const findings = [];
  const items = flattenConfig(config);                   // 点路径展开每条叶子配置
  for (const item of items.filter(isSuspicious)) {       // hack 特征：alias 环/loader 魔法字符串
    const trial = removeConfig(config, item.path);
    const out = await build(trial);
    const same = semanticEq(baseline, out);
    findings.push({ path: item.path, blame: await gitBlame(item.path),
      verdict: same ? 'removable' : 'load-bearing',
      note: same ? '产物一致——可删除' : '影响产物——迁移时必须翻译' });
  }
  return findings;
}
// 批量二分：多条可疑配置一次试验
async function batchTrial(config, suspects, { build, baseline }) {
  let alive = [...suspects];
  while (alive.length > 1) {
    const half = alive.slice(Math.floor(alive.length / 2));
    const out = await build(removeAll(config, half));
    alive = semanticEq(baseline, out) ? alive.filter(p => !half.includes(p)) : half;
  }
  return alive;                                          // 仍影响产物的最小集合
}
```
