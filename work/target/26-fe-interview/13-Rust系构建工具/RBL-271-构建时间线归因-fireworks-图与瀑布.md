## RBL-271：构建时间线归因（瀑布图与关键路径怎么画）

**答**:
- 数据模型：任务事件流 { task, start, end, deps }——渲染为瀑布图（条形按时间偏移），关键路径 = 依赖图上总时长最长的链（关键路径决定总时长）
- 归因三问：慢在哪一段（阶段分解）、慢的是哪个任务（瀑布定位）、为什么它慢（该任务内部 profile）——逐层下钻
- 并行浪费检测：瀑布图上的「空洞」（有任务可跑但没跑=调度没打满）与「排队等待」（被低优先级占住）——空洞时间就是优化空间
- 可视化实现：Chrome tracing 格式（trace-viewer 可直接开）或自渲染 SVG/gantt；CI 产 trace artifact 供下载

```text
瀑布示例：
core#build   |██████        | 6s     ← 关键路径
ui#build        |████████| 8s      ← 关键路径
app#build              |███| 3s    ← 等 ui 结束（空洞 2s=调度未打满）
关键路径 = max(依赖链总时长) = 6+8+3 = 17s（理论下限）
```
