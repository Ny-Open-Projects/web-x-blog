## RBL-841：笔试：手写分片上传调度器（续传 + 并发 + 重试）

**答**：实现 `upload(chunks, { concurrency, retries, resume, put, complete })`。chunks: `{ i, blob }[]`；resume: `() => Promise<Set<number>>`（已传分片）；put: `(chunk) => Promise`（可失败）；complete: `(doneIdx) => Promise<url>`。规则：1) resume 命中的分片视为已完成；2) 并发 ≤ concurrency 执行 put，单分片失败重试（最多 retries 次，指数退避可省略）；3) 超过重试上限 → 整体 reject（含失败分片列表，已完成的不撤销——断点保留）；4) 全部完成后 complete 返回 url；5) 返回 `{ url }`。边界：chunks 全在 resume（直接 complete）；retries=0（失败即 reject）；concurrency=1。

```javascript
async function upload(chunks, { concurrency = 3, retries = 2, resume, put, complete }) {
  const doneSet = await resume();                        // 断点
  const done = new Set(doneSet);
  const todo = chunks.filter(c => !done.has(c.i));
  const failed = [];
  let active = 0;

  await new Promise((resolveAll, rejectAll) => {
    let cursor = 0;
    const pump = () => {
      if (failed.length) return;
      while (active < concurrency && cursor < todo.length && !failed.length) {
        const chunk = todo[cursor++];
        active++;
        attempt(chunk, retries);
      }
      if (!active && cursor >= todo.length && !failed.length) resolveAll();
    };
    const attempt = async (chunk, left) => {
      try { await put(chunk); done.add(chunk.i); }
      catch (e) {
        if (left > 0) return attempt(chunk, left - 1);   // 重试
        failed.push(chunk.i);
        return rejectAll(new Error(`分片上传失败: ${failed.join(',')}`));
      } finally {
        active--; pump();
      }
    };
    if (todo.length === 0) resolveAll();
    else pump();
  });

  return { url: await complete([...done]) };
}

// 自测
const stored = new Set([0, 1]);                          // 分片 0,1 已传（断点）
const putCalls = [];
let failFirst = new Set([3]);                            // 分片 3 首次失败
const chunks = Array.from({ length: 5 }, (_, i) => ({ i, blob: `c${i}` }));
let r = await upload(chunks, {
  concurrency: 2, retries: 2,
  resume: async () => stored,
  put: async (c) => {
    putCalls.push(c.i);
    if (failFirst.has(c.i) && !putCalls.slice(0, -1).includes(c.i)) {
      failFirst.delete(c.i); throw new Error('net');     // 首次失败，重试成功
    }
  },
  complete: async (done) => `https://f/${[...done].sort().join('')}`,
});
console.log(r.url.includes('01234'));                    // 全部 5 片完成
console.log(putCalls.filter(i => i === 3).length === 2); // 分片 3 重试一次

// 超重试上限
let e; try {
  await upload(chunks, {
    concurrency: 1, retries: 0,
    resume: async () => new Set(),
    put: async () => { throw new Error('always'); },
    complete: async () => '',
  });
} catch (x) { e = x; }
console.log(/分片上传失败/.test(e.message) && e.message.includes('0'));

// 全部命中断点
r = await upload(chunks, {
  concurrency: 3, retries: 1,
  resume: async () => new Set([0, 1, 2, 3, 4]),
  put: async () => { throw new Error('should not run'); },
  complete: async (d) => `ok${d.size}`,
});
console.log(r.url === 'ok5');
```

**评分点**：
- 断点续传正确（resume 命中跳过、失败不撤销已完成分片）；重试上限后整体 reject 带失败清单
- 并发池正确（active 计数 + pump 续跑）；重试在槽位内进行（不占额外并发）
- 边界：全命中断点直接 complete、retries=0、concurrency=1
- 能说清「断点保留是续传的前提，失败清单让用户知道哪些分片要重传」属于加分
