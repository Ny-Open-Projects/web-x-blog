## RBL-461：手写构建平台成本分摊
**答**：实现 `allocateCosts(usage, pricing)`：1) usage：按团队的用量（runner 分钟/缓存 GB·月/带宽 GB）；2) 定价模型：runner 按 tier 单价（自托管 0.5$/h vs 云 1.2$/h 分开计）、缓存按存储月+请求次数、带宽按 GB；3) 分摊规则：固定平台成本（维护人力）按用量比例摊、可变成本直接按量计——两层模型；4) 异常用量标记（环比涨超 50% 的团队——先沟通再收费）；5) 输出按团队账单 + 平台总览（成本结构可视化）。

```javascript
export function allocateCosts(usage /* [{ team, runnerMin, cacheGBMonth, cacheOps, bandwidthGB, tier }] */, pricing) {
  const P = { runnerSelf: 0.5 / 60, runnerCloud: 1.2 / 60, cacheGB: 0.02, cacheOp: 0.000001, bandwidth: 0.05, ...pricing }
  const rows = usage.map((u) => ({
    team: u.team,
    runner: u.runnerMin * (u.tier === 'self' ? P.runnerSelf : P.runnerCloud),
    cache: u.cacheGBMonth * P.cacheGB + u.cacheOps * P.cacheOp,
    bandwidth: u.bandwidthGB * P.bandwidth,
  }))
  // 固定平台成本按可变成本比例摊
  const variablePerTeam = rows.map((r) => r.runner + r.cache + r.bandwidth)
  const totalVariable = variablePerTeam.reduce((a, b) => a + b, 0)
  rows.forEach((r, i) => (r.overhead = pricing.platformOverhead * (variablePerTeam[i] / totalVariable)))
  rows.forEach((r) => (r.total = +(r.runner + r.cache + r.bandwidth + r.overhead).toFixed(2)))
  // 异常用量标记
  const flagged = rows.filter((r) => r.prevTotal && (r.total - r.prevTotal) / r.prevTotal > 0.5)
    .map((r) => r.team)
  return { rows: rows.sort((a, b) => b.total - a.total), total: +rows.reduce((s, r) => s + r.total, 0).toFixed(2),
    flagged, note: '异常涨费团队先沟通后计费（避免误伤正常增长）' }
}
```
**评分点**：
- 分层定价（runner tier 区分自托管/云——同资源不同成本源）
- 两层分摊模型（可变直接计 + 固定按比例摊——平台成本归属的完整模型）
- 异常标记先行（涨费先沟通——成本模型的组织友好性）
- 排序输出（成本榜驱动优化优先级）
