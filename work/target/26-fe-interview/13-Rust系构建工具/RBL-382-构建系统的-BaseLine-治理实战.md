## RBL-382：构建性能基线的治理实战

**答**:
- 基线腐化：基线定于一年前，期间代码增长/依赖增加——门禁阈值失效（全在超限→白名单泛滥→门禁形同虚设）
- 重校准机制：基线与「业务里程碑」联动（大版本发布后重校）+ 自动漂移检测（P50 连续 N 周缓慢上涨告警——腐化早期信号）
- 校准原则：基线反映「当前合理水平」而非「历史最好」——过严基线逼出白名单，过松失去意义；校准幅度记录（每次调整可视化）
- 例外治理：白名单每季度审计（过期清理）——白名单是债务清单不是永久豁免

```text
腐化信号：P50 连续 N 周上涨 / 白名单数量增长
重校：里程碑联动 + 漂移告警；白名单季度审计（过期清理）
原则：基线 = 当前合理水平，调整可追溯
```
