## RBL-944：综合深水：构建体系的一页纸架构叙述——向决策者解释构建投资

**答**:
- 向管理层/非技术决策者解释构建投资的叙事结构：1) **价值语言**（不说「构建快 3 倍」而说「每次需求上线提前 X 小时 + 故障恢复快 Y 分钟 + 释放 Z 人天」——RBL-855 成本核算的语言）；2) **风险语言**（现在的构建状态=三个具体风险：发布事故（半成品产物）、安全合规（审计缺失）、人才瓶颈（单人维护））；3) **投资语言**（一次性投入 N 人月 + 持续运营 M 人/季，回本周期 RBL-851）；4) **里程碑**（阶段化路线 RBL-893——每个里程碑可验收）。
- 一页纸的纪律：一页 = 现状/风险/方案/投资/里程碑 五段 + 一张图（现状→目标的时间线）——技术细节全部进附录（决策者要的是「值得吗」不是「怎么做」）。
- 常见的叙事失败：技术自豪感驱动（罗列 12 个特性——决策者无从判断价值）；无风险锚点（没有「不做会怎样」的对比）；无回本（投资不可比）。
- 叙事的数据锚点：每个论断带一个数字（「上线前置时间从 2 天 → 2 小时」「构建故障月均 3 次 → 0.2 次」）——数据的来源是 SLO/看板（RBL-904/851），叙事与度量体系是同一系统的两面。
- 追问钩子：为什么「技术方案的一页纸」比「技术方案文档」对平台团队更重要？——平台投资是「跨团队的资源再分配」决策，决策者是非技术或半技术；一页纸的叙事质量决定预算申请成败（技术完美但叙事失败的方案拿不到资源）；「翻译能力」是平台工程师的元能力——把工程价值翻译成业务价值，与 RBL-891 的「无感知北极星」互为表里。

```javascript
// 一页纸生成器（从度量体系自动取数）
function onePager({ baseline, current, investment, roadmap }) {
  return {
    现状: `上线前置 ${baseline.leadTimeH}h | 构建故障 ${baseline.failuresMo}/月 | 维护者 ${baseline.busFactor} 人`,
    改善: `→ 上线前置 ${current.leadTimeH}h | 故障 ${current.failuresMo}/月 | 团队自助率 ${current.selfServePct}%`,
    投资: `${investment.personMonths} 人月（回本 ${investment.paybackDays} 天，RBL-851）`,
    里程碑: roadmap.map(r => `${r.name}（${r.doneRate}%）`),
    风险锚点: '不做 = 发布事故率维持 + 审计缺口持续 + 单点风险',
  };
}
// 叙事自检：每个论断必须有数字锚点
function auditNarrative(page) {
  const noNumber = Object.values(page).filter(s => !/\d/.test(String(s)));
  return { ok: noNumber.length === 0, unanchored: noNumber };
}
```
