## RBL-950：综合深水：面试反脆弱——用对抗问题检验知识深度

**答**:
- 高级面试的对抗结构：面试官会攻击你方案的最弱点（「你这个缓存方案在 X 场景会不会错？」「并发拉满内存爆了怎么办？」）——反脆弱准备：1) **每个方案预写攻击面**（方案的失效条件清单 RBL-886 step4 的深版：失效条件 + 触发概率 + 缓解）；2) 「不知道」的正确姿势（承认边界 + 给出排查路径——瞎编是面试死穴）；3) 用不变量接住任意追问（追问到深处都是不变量：并发→失效传播、缓存→键完备性 RBL-850）。
- 对抗问题的三类：**边界攻击**（极端场景：10 万模块/1KB 内存）、**矛盾攻击**（两个你说的原则冲突：确定性 vs 增量速度）、**迁移攻击**（换条件还成立吗：小仓库还要这套吗）。每类的应对模板。
- 「矛盾攻击」的化解：原则的适用域声明（确定性优先于增量——增量建立在确定性缓存键上，不冲突而是分层）——原则冲突的表面性来自「缺适用域声明」。
- 备考的元方法：把自己卡片里的每个方案「自问自答 3 个攻击」——卡片的「追问钩子」字段就是为此设计（每张卡的钩子是面试官视角的预演）。
- 追问钩子：为什么「预写攻击面」比「临场反应」更有效？——临场攻击激活的是防御心理（急于辩护）；预写攻击面让你以「研究过的取舍」回应（「对，这个方案在 X 会失效，我们用 Y 兜底」）——承认失效 + 给缓解 = 顶级信号；对抗准备的实质是把「面试博弈」变成「工程讨论」，与 kill criteria（RBL-842）的诚实文化同源。

```javascript
// 方案攻击面自检表
function attackSurface(plan) {
  return {
    boundary: [`${plan.scaleLimit} 规模上限：超出时的降级路径`],
    contradiction: [`${plan.principles} 原则间的适用域分层`],
    portability: [`${plan.context} 小团队/小仓库还需要吗`],
  };
}
// 对抗应对模板
const RESPONSE_TEMPLATES = {
  boundaryAttack: (q, plan) =>
    `好问题——该方案在 ${q.limit} 时会 ${plan.failure}。我们的缓解是 ${plan.mitigation}；` +
    `再往上就需要 ${plan.escalation}（架构级变化而非参数调整）。`,
  contradictionAttack: (a, b) =>
    `${a} 与 ${b} 的适用域不同：${a} 管 ${aDomain}，${b} 管 ${bDomain}——分层后不冲突。`,
  unknownAttack: () =>
    `这个我没实际处理过。我的排查路径会是：1) ${step1} 2) ${step2}——基于对 ${related} 的理解推断。`,
};
```
