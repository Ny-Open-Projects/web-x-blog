## RBL-957：笔试：手写静默错误防线匹配器（触及 → 防线）

**答**：实现 `reviewGuard(pr, enabled)`。SILENT_MODES: 18 项注册表 `{ id, touch: (pr) => boolean, defense, freq }`（touch 判定 PR 是否触及该模式：如 pr.files 含缓存目录 → cache-poison）。pr: `{ files: string[], ops?: string[] }`；enabled: `Set<defense>`（已开启防线）。规则：1) 触及且防线未开 → risk `{ mode, defense, freq }`（按 freq 排序 high>medium>low）；2) 触及且已开 → ok（静默计数）；3) 返回 `{ risks, guarded: number, ok }`（ok = 无 high 风险）。边界：pr 无文件；全部已开；注册表空。

```javascript
const SILENT_MODES = [
  { id: 'cache-poison', touch: (pr) => pr.files.some(f => f.includes('.cache') || f.includes('cache-key')),
    defense: '签名校验+抽样复算', freq: 'high' },
  { id: 'missed-invalidation', touch: (pr) => pr.files.some(f => f.includes('graph') || f.includes('invalidat')),
    defense: '产物源码hash对账', freq: 'high' },
  { id: 'dual-version', touch: (pr) => pr.files.some(f => f.includes('chunk') || f.includes('manifest')),
    defense: 'entry闭包双版本审计', freq: 'high' },
  { id: 'env-leak', touch: (pr) => pr.files.some(f => f.includes('define') || f.includes('.env')),
    defense: 'define白名单校验', freq: 'medium' },
  { id: 'mock-residue', touch: (pr) => pr.files.some(f => f.includes('mock') || f.includes('fixture')),
    defense: '生产产物mock扫描', freq: 'medium' },
];
const RANK = { high: 0, medium: 1, low: 2 };

function reviewGuard(pr = { files: [] }, enabled = new Set()) {
  const risks = [], guarded = [];
  for (const m of SILENT_MODES) {
    if (!m.touch(pr)) continue;
    if (enabled.has(m.defense)) guarded.push(m.id);
    else risks.push({ mode: m.id, defense: m.defense, freq: m.freq });
  }
  risks.sort((a, b) => RANK[a.freq] - RANK[b.freq]);
  return { risks, guarded, ok: !risks.some(r => r.freq === 'high') };
}

// 自测
const pr = { files: ['src/graph/invalidator.ts', 'config/cache-key.ts'] };
let r = reviewGuard(pr, new Set());
console.log(r.risks.length === 2 && r.risks.every(x => x.freq === 'high'));
console.log(r.ok === false);                             // 双 high 风险

// 部分开启
r = reviewGuard(pr, new Set(['签名校验+抽样复算']));
console.log(r.guarded.join(',') === 'cache-poison');
console.log(r.risks.length === 1 && r.risks[0].mode === 'missed-invalidation');
console.log(r.ok === false);

// 全开
r = reviewGuard(pr, new Set(SILENT_MODES.map(m => m.defense)));
console.log(r.ok === true && r.risks.length === 0 && r.guarded.length === 2);

// 不触及
r = reviewGuard({ files: ['README.md'] }, new Set());
console.log(r.ok === true && r.risks.length === 0 && r.guarded.length === 0);

// medium 不阻断
r = reviewGuard({ files: ['src/mock/data.js'] }, new Set());
console.log(r.risks[0].freq === 'medium' && r.ok === true);
```

**评分点**：
- touch 谓词与防线一一映射（触及模式 → 对应防线要求——RBL-956 清单的操作化）；freq 排序
- ok 语义分级：仅 high 阻断（medium 警示不拦——风险分级的门禁化）；guarded 计数
- 边界：不触及/全开/空注册表
- 能说清「每条静默模式都有『变响』的手段——review 时 PR 触及模式即检查防线开启」属于加分
