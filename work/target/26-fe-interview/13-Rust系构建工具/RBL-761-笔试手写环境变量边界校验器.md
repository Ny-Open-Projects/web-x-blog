## RBL-761：笔试：手写环境变量边界校验器（分层 + 声明完整性 + 泄漏）

**答**：实现 `auditEnv(files, { declared, allowedPrefixes })`。files: `{ path, code, layer: 'client'|'server'|'shared' }[]`。规则：1) client/shared 层引用 `process.env.X` 且 X 非 allowedPrefixes 前缀 → blocker 'client-env'（client 应走 import.meta.env）；2) PRIVATE_/SECRET_ 前缀变量出现在 client/shared → blocker 'secret-leak'；3) 引用但未声明（declared 数组）→ warn 'undeclared'；4) `import.meta.env.X` 只检查声明完整性；5) 返回 `{ blockers, warnings }` 去重排序。边界：无引用文件；声明含 import.meta.env 引用的变量。

```javascript
function auditEnv(files, { declared = [], allowedPrefixes = ['PUBLIC_', 'NEXT_PUBLIC_'] } = {}) {
  const blockers = [], warnings = [];
  const seen = new Set();
  const add = (arr, msg) => { if (!seen.has(msg)) { seen.add(msg); arr.push(msg); } };

  for (const f of files) {
    const refs = [
      ...[...f.code.matchAll(/process\.env\.(\w+)/g)].map(m => m[1]),
      ...[...f.code.matchAll(/import\.meta\.env\.(\w+)/g)].map(m => m[1]),
    ];
    for (const name of [...new Set(refs)]) {
      if (!declared.includes(name)) add(warnings, `undeclared: ${name}（${f.path}）`);
      const isSecret = /^(PRIVATE_|SECRET_)/.test(name);
      const isClientish = f.layer !== 'server';
      if (isSecret && isClientish) add(blockers, `secret-leak: ${name} in ${f.layer}（${f.path}）`);
      else if (f.layer !== 'server' && /process\.env\./.test(f.code) &&
               new RegExp(`process\\.env\\.${name}\\b`).test(f.code) &&
               !allowedPrefixes.some(p => name.startsWith(p)))
        add(blockers, `client-env: process.env.${name} 在 ${f.layer}（${f.path}）——改用 import.meta.env`);
    }
  }
  blockers.sort(); warnings.sort();
  return { blockers, warnings };
}

// 自测
const declared = ['PUBLIC_API', 'PRIVATE_KEY', 'MODE'];
const files = [
  { path: 'a.ts', code: 'fetch(process.env.PUBLIC_API)', layer: 'client' },       // ok（白名单前缀）
  { path: 'b.ts', code: 'const k = process.env.SECRET_KEY;', layer: 'client' },   // leak
  { path: 'c.ts', code: 'const t = process.env.TOKEN;', layer: 'shared' },        // 非白名单 client-env
  { path: 'd.ts', code: 'import.meta.env.MODE; import.meta.env.UNLISTED;', layer: 'client' }, // undeclared
  { path: 'e.ts', code: 'process.env.PRIVATE_KEY;', layer: 'server' },            // ok
];
let r = auditEnv(files, { declared });
console.log(r.blockers.join('|'));
// secret-leak: SECRET_KEY in client（b.ts）|client-env: process.env.TOKEN in shared（c.ts）
console.log(r.warnings.join('|').includes('UNLISTED'));
console.log(r.blockers.length === 2);

console.log(auditEnv([{ path: 'x.ts', code: 'const a = 1;', layer: 'client' }], { declared })).blockers.length === 0;
```

**评分点**：
- 分层规则正确：server 层豁免、client/shared 的 process.env 需白名单前缀
- 泄漏检测优先级高于前缀规则（SECRET_/PRIVATE_ 无论前缀一律 blocker）
- 声明完整性 warn（process.env 与 import.meta.env 都检查）；去重排序输出
- 能说清「环境值随环境变则运行时注入、构建期内联只留静态值」属于加分
