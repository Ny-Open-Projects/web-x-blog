## RBL-893：迁移复盘：从单仓迁移到平台化的十年路线——能力复利

**答**:
- 平台化的能力复利轨迹（本目录卡片的叙事线）：年 1 单仓迁移（学会语义验证 RBL-649）→ 年 2 多仓迁移（迁移平台 RBL-789，验证基建复用）→ 年 3 构建平台（preset/CI 模板/升级日 RBL-852/821）→ 年 4 可观测与治理（预算闭环/审计门禁 RBL-880/661）→ 年 5+ 可替换性与上游协作（RBL-866/783）——每一步的资产都是下一步的杠杆。
- 复利的机制：验证基建（跨工具行为测试）与度量体系（指标看板）是「跨阶段资产」——它们不因工具更换失效（RBL-850 不变量）；阶段化的「一次性投入」（迁移脚本）要尽快资产化（RBL-789 Rule of three）。
- 平台化的反模式：过早平台化（单仓都没迁稳就建平台——抽象没有实例支撑）；平台化不收租（平台组成本无人分摊——治理没有预算闭环）；平台变孤岛（成员团队绕过平台自建——自由度管理失败 RBL-891）。
- 判断「该进入下一阶段」的信号：当前阶段的边际收益递减（迁移第 50 仓的工时已是第 1 仓的 1/5——剩余仓库收益薄）+ 下一阶段的问题开始出现（多仓版本碎片 = 平台化信号）。
- 追问钩子：为什么「验证基建」能跨越所有阶段复利？——语义等价验证的输入是「行为用例」，与工具无关（RBL-655 端到端行为断言）；迁移/升级/重构/任何变更都以它为安全网——「工具可换、验证长存」的资产属性让它的 ROI 随阶段数线性放大；这也是面试中「你迁移最宝贵的产出是什么」的深度答案。

```javascript
// 平台化路线的阶段门禁
const ROADMAP = [
  { stage: 1, name: '单仓迁移', asset: '语义验证基建',
    exit: (s) => s.migratedRepos >= 1 && s.semanticToolReady },
  { stage: 2, name: '多仓迁移', asset: '迁移平台',
    exit: (s) => s.migratedRepos >= 10 && s.platformUsed },
  { stage: 3, name: '构建平台', asset: 'preset + 升级日',
    exit: (s) => s.presetCoverage > 0.8 },
  { stage: 4, name: '治理闭环', asset: '预算闭环 + 审计门禁',
    exit: (s) => s.budgetLoopActive && s.auditGates > 5 },
  { stage: 5, name: '可替换性', asset: '抽象层 + 上游协作',
    exit: (s) => s.replaceabilityScore >= 75 },          // RBL-867
];
function nextStage(state) {
  const cur = ROADMAP.find(r => !r.exit(state));
  return cur ? { enter: cur.name, note: '当前阶段边际收益递减时进入下一阶段' } : { done: true };
}
```
