## RBL-223：持久化缓存的失效与验证策略

**答**:
- 失效层级：版本失效（工具升级，缓存目录带版本号整体作废）、指纹失效（输入变化，单条目作废）、策略失效（磁盘超限 LRU 清理）
- 验证两问：命中是否正确（指纹完整性）与命中是否值得（校验成本 vs 重算成本）——大产物缓存校验用 hash 对比（O(n) 读），小文件直接重算更快
- 错误缓存的自愈：产物内容 hash 进条目键，命中后二次校验；发现不匹配即丢弃缓存回退全量并上报（缓存 bug 可观测）
- 生命周期：缓存目录上限（如 2GB）+ LRU + 版本切换清理旧版本目录

```javascript
// 缓存条目结构
const entry = {
  key: sha(inputFingerprint + toolVersion),   // 指纹
  outputHash: sha(output),                    // 校验
  outputs: [...], createdAt: ts,
}
// 命中流程：key 命中 → 读产物 → 校验 outputHash → 通过才复用
```
