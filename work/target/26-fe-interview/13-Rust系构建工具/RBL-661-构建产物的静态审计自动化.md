## RBL-661：构建产物的静态审计：把「产物检查单」变成 CI 门禁

**答**:
- 产物审计自动化清单：1) 体积预算（每入口/每 chunk 阈值，超标 fail）；2) 引用闭合（RBL-656）；3) 敏感信息扫描（.env 值/内网地址/密钥模式正则）；4) 兼容性（产物语法 vs browserslist 目标——降级遗漏检测）；5) sourcemap 配套完整（每个 js 有 map 或显式声明无）；6) SBOM 与依赖白名单比对。
- 门禁化的意义：这些检查靠人眼 review 是漏的（PR diff 不包含产物）；CI 里自动跑 + 违规即红——把「构建质量约定」从文档变成代码。审计器应作为构建器输出的一部分（builder.audit()），而不是事后独立脚本（拿不到构建期语义）。
- 体积预算的工程细节：绝对阈值（如 200KB）会随业务膨胀而过时——用「相对基线」（与上次 release 比 +10% 警告 +25% 阻塞）+ 绝对上限双轨；豁免机制（某次确实要加体积，PR 里声明 reason 后审计标注通过，记录在案）。
- 兼容性审计的实现：产物 parse 后收集使用的语法特性（optional chaining/spread 等）→ 与 browserslist 目标对比——比跑全量真机便宜得多；特性使用来源可归因到模块（哪个依赖引入了新语法，polyfill 该加在哪）。
- 追问钩子：为什么敏感信息扫描要在「产物层」而不是「源码层」做？——泄漏发生在产物（源码里有 define 注入但产物才暴露值）；且产物是字符串级聚合（多个模块拼起来），源码层扫描看不到拼接后的完整模式（如跨行的密钥拆分）。

```javascript
// 产物审计器
function auditArtifacts(output, { budgets, baseline, browserslist }) {
  const problems = [];
  // 1) 体积预算：相对基线 + 绝对上限
  for (const [entry, { absoluteKB, relativePct }] of Object.entries(budgets)) {
    const size = output.sizeOf(entry);
    if (size > absoluteKB) problems.push({ level: 'error', msg: `${entry} 超绝对预算 ${size}KB > ${absoluteKB}KB` });
    const base = baseline?.sizeOf?.(entry);
    if (base && size > base * (1 + relativePct))
      problems.push({ level: 'error', msg: `${entry} 相对基线增长 ${(size / base - 1) * 100}% 超限（基线 ${base}KB）` });
  }
  // 2) 敏感信息模式
  const SECRET = [/AKIA[0-9A-Z]{16}/, /-----BEGIN (RSA )?PRIVATE KEY-----/, /ghp_[A-Za-z0-9]{36}/];
  for (const f of output.files)
    for (const re of SECRET)
      if (re.test(f.content)) problems.push({ level: 'error', msg: `${f.name} 疑似密钥泄漏` });
  // 3) 兼容性
  for (const f of output.js)
    for (const feat of detectSyntaxFeatures(f.content))
      if (!supportedBy(feat, browserslist)) problems.push({ level: 'error', msg: `${f.name} 使用 ${feat}，目标环境不支持` });
  return problems;                                       // 空 = 门禁通过
}
```
