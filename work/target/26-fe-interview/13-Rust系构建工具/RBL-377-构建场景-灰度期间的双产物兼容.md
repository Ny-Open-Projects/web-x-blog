## RBL-377：灰度期间新旧产物并存的兼容问题

**答**:
- 并存风险面：API 兼容（新前端调旧后端/旧前端调新后端——灰度期内接口双版本）、数据兼容（localStorage schema 新旧互写）、CDN 资源互相引用（新 html 引到旧 chunk 缓存）
- 构建侧保障：接口版本协商（前端产物带 API 版本预期，后端按版本路由）、storage key 版本化（新旧互不覆盖）、产物保留策略（N 版本共存 + 回滚可用）
- 灰度对账：新桶用户的错误率与旧桶对比（灰度产物的问题早发现）——构建产物带灰度标记（可观测区分桶）
- 收尾纪律：灰度结束旧产物删除延迟（回滚窗口）+ 数据迁移脚本（storage schema 升级）

```text
并存四险：API 双版本 / storage schema / 资源引用 / 可观测标记
保障：版本协商 + key 版本化 + 产物保留 N 版 + 桶级错误率对账
```
