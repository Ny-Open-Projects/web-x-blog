## RBL-687：笔试：手写构建池弹性扩容决策器（队列积压 + 延迟双指标 + 冷却期）

**答**：实现 `decideScale(metrics, config, state)`。metrics: `{ queueDepth, waitP95Ms, cpuUtil, errorRate }`；config: `{ minWorkers, maxWorkers, scaleTrigger: { queueDepth, waitP95Ms }, cooldownMs }`；state: `{ current, lastChangeAt }`。决策规则（按序）：1) 错误率 > 0.1 → 'throttle'（先降并发排查，不扩容）；2) queueDepth > 阈值 或 waitP95Ms > 阈值 → 'scale-up'（workers + 4，不超 max）；3) 队列空且 waitP95 低于阈值一半持续（用 metrics.lowLoad 布尔代表持续性）→ 'scale-down'（-2，不低 min）；4) 其余 'hold'。冷却期：距上次变更 < cooldownMs 时扩缩容一律 'hold-cooldown'。返回 `{ action, workers, reason }`。边界：目标值 clamp 在 [min, max]。

```javascript
function decideScale(metrics, config, state) {
  const { minWorkers, maxWorkers, scaleTrigger, cooldownMs } = config;
  const inCooldown = state.lastChangeAt && (metrics.at - state.lastChangeAt) < cooldownMs;
  const clamp = (n) => Math.max(minWorkers, Math.min(maxWorkers, n));

  if (metrics.errorRate > 0.1)
    return { action: 'throttle', workers: Math.max(minWorkers, Math.floor(state.current / 2)), reason: 'error-rate-high' };
  if (inCooldown)
    return { action: 'hold-cooldown', workers: state.current, reason: 'cooldown' };

  const over = metrics.queueDepth > scaleTrigger.queueDepth || metrics.waitP95Ms > scaleTrigger.waitP95Ms;
  if (over) {
    const target = clamp(state.current + 4);
    return { action: target > state.current ? 'scale-up' : 'hold-max',
             workers: target, reason: target > state.current ? 'queue-backlog' : 'already-max' };
  }
  if (metrics.lowLoad && metrics.queueDepth === 0) {
    const target = clamp(state.current - 2);
    return { action: target < state.current ? 'scale-down' : 'hold-min',
             workers: target, reason: target < state.current ? 'low-load' : 'already-min' };
  }
  return { action: 'hold', workers: state.current, reason: 'steady' };
}

// 自测
const cfg = { minWorkers: 4, maxWorkers: 24, scaleTrigger: { queueDepth: 10, waitP95Ms: 30000 }, cooldownMs: 60000 };
const t0 = new Date('2026-11-11T10:00:00');

let r = decideScale({ queueDepth: 15, waitP95Ms: 40000, errorRate: 0.01, at: t0 },
  cfg, { current: 8, lastChangeAt: null });
console.log(r.action === 'scale-up' && r.workers === 12);

// 冷却期
r = decideScale({ queueDepth: 20, waitP95Ms: 50000, errorRate: 0.01, at: new Date(t0.getTime() + 30000) },
  cfg, { current: 12, lastChangeAt: t0 });
console.log(r.action === 'hold-cooldown');

// 已达 max
r = decideScale({ queueDepth: 50, waitP95Ms: 90000, errorRate: 0, at: new Date(t0.getTime() + 120000) },
  cfg, { current: 24, lastChangeAt: t0 });
console.log(r.action === 'hold-max' && r.workers === 24);

// 缩容
r = decideScale({ queueDepth: 0, waitP95Ms: 1000, lowLoad: true, errorRate: 0, at: new Date(t0.getTime() + 120000) },
  cfg, { current: 10, lastChangeAt: t0 });
console.log(r.action === 'scale-down' && r.workers === 8);

// 错误率熔断
r = decideScale({ queueDepth: 99, waitP95Ms: 99999, errorRate: 0.2, at: t0 },
  cfg, { current: 12, lastChangeAt: null });
console.log(r.action === 'throttle' && r.workers === 6);
```

**评分点**：
- 决策优先级正确：错误率熔断 > 冷却期 > 扩容 > 缩容 > hold
- clamp 边界（不超 max、不低 min）与 hold-max/hold-min 区分（动作语义诚实）
- 冷却期只挡扩缩不挡熔断（throttle 不受 cooldown 限制）
- 能说清「缩容要保守（-2 vs +4 非对称）防抖动」属于加分
