## RBL-089：Turbopack 的内存占用问题如何看待与治理？
**答**：
- 为什么占内存：函数级缓存长期驻留（记忆化结果+依赖边全存内存）、大项目 AST 保留、dev server 全生命周期不释放；换来的是毫秒级 HMR。
- 量级：大型 monorepo dev 数 GB 内存不罕见（webpack 也会占到 2-4GB，量级相当或略高）；CI/生产构建因不需要长期驻留，影响较小。
- 治理手段：官方持续优化缓存淘汰（LRU 式驱逐冷任务）；业务侧减少不必要的大依赖进图、拆分应用。
- 对比：Rspack 用持久缓存换内存（可写盘卸载），Turbopack 也在做持久化；方向都是"内存紧张时卸载到磁盘"。
- 监控：dev 内存曲线突变通常对应大文件或依赖图爆点，用构建工具的 trace 定位。
- 追问钩子：内存 vs 速度是缓存体系的核心权衡——面试能主动讲 tradeoff 加分。

```text
内存构成（dev 长驻）
├── 任务结果缓存（记忆化 blob）
├── 依赖边图（追踪开销）
├── AST/源码缓存
└── dev server 运行时
治理：冷任务驱逐 → 持久化卸载 → 拆应用/减依赖
```
