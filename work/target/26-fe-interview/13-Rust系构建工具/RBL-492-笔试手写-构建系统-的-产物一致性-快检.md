## RBL-492：手写产物一致性快检
**答**：实现 `verifyIncrementalEquivalence(incrementalResult, fullResult)`：1) 产物树对比：文件集合相同 + 每文件 hash 相同（byte 级等价）；2) 差异定位：首个不一致文件 + 该文件依赖链（哪个模块的增量编译错了）；3) 差异分级：内容差异（hash 不同——严重）/仅顺序差异（模块顺序—— mild 但要查）；4) 自动归因建议：差异文件的反向依赖闭包（最可能的脏传播源头）；5) 输出 { equivalent, firstDiff, suspectedCause }；6) 快检成本控制：hash 预比较（树 diff 前 O(1) 全量 hash 对比——不同再深入）。

```javascript
export function verifyIncrementalEquivalence(inc, full) {
  // O(1) 预比较：全树汇总 hash
  const treeHash = (files) => Object.keys(files).sort().map((k) => `${k}:${files[k].hash}`).join('|')
  if (treeHash(inc.files) === treeHash(full.files)) return { equivalent: true }

  // 首个差异文件
  const all = new Set([...Object.keys(inc.files), ...Object.keys(full.files)])
  let firstDiff = null
  for (const p of all) {
    const a = inc.files[p]?.hash, b = full.files[p]?.hash
    if (a !== b) { firstDiff = { path: p, incremental: a, full: b,
      kind: a && b ? 'content' : 'missing' }; break }
  }
  // 反向依赖闭包（疑似脏传播源）
  const suspected = firstDiff ? inc.reverseDeps?.(firstDiff.path)?.slice(0, 5) ?? [] : []

  return { equivalent: false, firstDiff, suspectedCause: suspected,
    severity: firstDiff?.kind === 'content' ? 'critical' : 'mild',
    note: '增量 ≠ 全量 是缓存/图一致性 bug 的最终判定标准' }
}
```
**评分点**：
- O(1) 全树 hash 预比较（快检成本控制——不等价才深入）
- 首个差异定位 + kind 分级（missing vs content）
- 反向依赖闭包归因（疑似脏传播源——差异要能定位）
- 断言语义正确（增量=全量是判定标准不是参考）
