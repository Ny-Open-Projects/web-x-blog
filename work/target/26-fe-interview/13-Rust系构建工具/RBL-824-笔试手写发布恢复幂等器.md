## RBL-824：笔试：手写发布恢复幂等器（ledger + 幂等 + 终检）

**答**：实现 `resumeRelease(plan, { registry, notify })`。plan: `{ version, layers: string[][] }`（拓扑分层）；registry 注入：`exists(name, version) -> Promise<boolean>`、`publish(name, version) -> Promise`；notify 注入。规则：1) 逐层逐包：registry.exists 为 true 跳过（幂等续跑）；发布失败记录并 notify（继续发布其他包——不中断）；2) 返回 `{ published: string[], skipped: string[], failed: Array<{ pkg, reason }> }`；3) **一致性终检**：发布结束后，检查每个 failed 包的下游是否声明了其新版本（plan.declaredDeps: `Record<pkg, string[]>`——failed 包被下游引用 → 追加 blocker `deps-inconsistent`，需要 follow-up patch）；4) 全部成功时 ok=true。边界：layers 空；registry.exists 抛错按 failed 处理。

```javascript
async function resumeRelease(plan, { registry, notify = () => {} }) {
  const published = [], skipped = [], failed = [];
  for (const layer of plan.layers ?? []) {
    for (const pkg of layer) {
      try {
        if (await registry.exists(pkg, plan.version)) { skipped.push(pkg); continue; }
        await registry.publish(pkg, plan.version);
        published.push(pkg);
      } catch (e) {
        failed.push({ pkg, reason: e.message });
        notify(`${pkg}@${plan.version} 发布失败: ${e.message}`);
      }
    }
  }
  const blockers = [];
  for (const f of failed)
    for (const [down, deps] of Object.entries(plan.declaredDeps ?? {}))
      if (deps.includes(f.pkg)) blockers.push(`deps-inconsistent: ${down} 引用失败的 ${f.pkg}——需 follow-up patch`);
  return { published, skipped, failed, blockers, ok: failed.length === 0 };
}

// 自测
const publishedSet = new Set(['a@1.1.0']);
const registry = {
  exists: async (name, version) => publishedSet.has(`${name}@${version}`),
  publish: async (name, version) => {
    if (name === 'c') throw new Error('registry-timeout');
    publishedSet.add(`${name}@${version}`);
  },
};
const notifyLog = [];
const plan = { version: '1.1.0', layers: [['a', 'b'], ['c', 'd'], ['e']],
  declaredDeps: { e: ['c'], d: ['b'] } };
let r = await resumeRelease(plan, { registry, notify: (m) => notifyLog.push(m) });
console.log(r.skipped.join(',') === 'a');                // 已发布跳过
console.log(r.published.sort().join(','));               // b,d
console.log(r.failed[0].pkg === 'c' && r.failed[0].reason === 'registry-timeout');
console.log(r.blockers[0].includes('e') && r.blockers[0].includes('c'));  // e 依赖失败的 c
console.log(r.ok === false);
console.log(notifyLog.length === 1);

// 全成功
const r2 = await resumeRelease({ version: '1.0.0', layers: [['x']], declaredDeps: {} },
  { registry: { exists: async () => false, publish: async () => {} } });
console.log(r2.ok === true && r2.published.join(',') === 'x');

console.log((await resumeRelease({ version: '1', layers: [] }, { registry: { exists: async () => false, publish: async () => {} } })).ok === true);
```

**评分点**：
- 幂等语义正确（exists 跳过、失败不中断后续）；failed 记账 + notify（半发布可见性）
- 一致性终检：failed 包被下游引用 → deps-inconsistent blocker（follow-up patch 的触发依据）
- exists 抛错按 failed 处理；空 layers 安全
- 能说清「npm 生态回滚只能向前修正，发布恢复的幂等记账是半发布的解药」属于加分
