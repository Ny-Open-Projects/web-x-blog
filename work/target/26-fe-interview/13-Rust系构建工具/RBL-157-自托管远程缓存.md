## RBL-157：远程缓存怎么自托管？协议与安全要点

**答**：
- 动机：Vercel Remote Cache 绑其平台；公司内网/私有化部署需要自建。协议上是简单 KV：客户端按 hash GET 缓存包（tar 归档），miss 时 PUT 上传。
- Turborepo 兼容协议：配置 TURBO_API 指向服务地址，TURBO_TOKEN 鉴权，服务端实现 /artifacts/{hash} 的 GET/PUT/HEAD 即可（社区有 duckdb/s3 后端的开源实现）。
- 存储：对象存储（S3/OSS/MinIO）放缓存包，索引层记录 hash→object；hash 命名天然幂等，写入可并发。
- 安全要点：1) PUT 必须鉴权（防止污染缓存投毒——命中端会直接信任回放日志）；2) GET 可只读 token；3) 传输层 TLS + hash 校验；4) 缓存内容视为"不可信输入"，回放日志不执行 shell。
- 容量治理：LRU/TTL 淘汰，监控命中率（<50% 说明 key 设计有问题）。
- 追问钩子：缓存投毒是面试区分度点——攻击者拿到写权限可上传与 hash 不对应的恶意产物，所以生产要校验上传者身份与产物签名。

```javascript
// 自托管 remote cache 的核心接口（Express 简版）
import express from 'express';
import { putObject, getObject, hasObject } from './store.js'; // S3/MinIO 封装

const app = express();
app.use(express.raw({ type: '*/*', limit: '2gb' }));

function authWrite(req, res, next) {
  if (req.get('authorization') !== `Bearer ${process.env.WRITE_TOKEN}`)
    return res.status(401).end(); // 写必须鉴权，防缓存投毒
  next();
}

app.head('/artifacts/:hash', async (req, res) => {
  if (await hasObject(req.params.hash)) return res.status(200).end();
  res.status(404).end();
});
app.get('/artifacts/:hash', async (req, res) => {
  const obj = await getObject(req.params.hash);
  if (!obj) return res.status(404).end();
  res.set('Content-Type', 'application/octet-stream');
  res.send(obj);
});
app.put('/artifacts/:hash', authWrite, async (req, res) => {
  await putObject(req.params.hash, req.body);
  res.status(200).end();
});
app.listen(3000);
```
