## RBL-372：低代码平台的动态编译需求

**答**:
- 场景：用户拖拽生成的 DSL → 运行时/准运行时编译成可执行组件——构建层提供「编译即服务」（compiler-as-a-service）：oxc/swc 内嵌（浏览器 wasm 或服务端）按 DSL 生成代码
- 方案谱系：纯运行时解释执行（DSL 不编译，灵活但性能差）→ 运行时编译（DSL→代码→eval/wasm，平衡）→ 发布期编译（DSL 固化为产物，性能最好但迭代慢）
- 构建层职责：DSL → 代码模板的编译器（用 oxc-transform 转译 TS/JSX）、生成代码的校验（AST 白名单防注入）、产物版本管理（每次发布 DSL 快照）
- 安全红线：用户生成代码必须沙箱执行（能力受限）——编译期静态检查 + 运行时沙箱双保险

```text
谱系：解释执行 / 运行时编译 / 发布期编译
构建职责：DSL 编译器 + AST 白名单校验 + DSL 快照版本
安全：静态检查 + 运行时沙箱
```
