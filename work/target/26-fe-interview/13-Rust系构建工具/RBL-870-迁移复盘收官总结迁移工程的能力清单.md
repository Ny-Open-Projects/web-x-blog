## RBL-870：迁移复盘收官：迁移工程师的能力清单——这 300 张卡片的脉络

**答**:
- 迁移工程师的五个能力域（对应本目录 551-870 的脉络）：1) **评估力**（收益成本模型 RBL-664/kill criteria RBL-843——决定做不做）；2) **执行力**（配置翻译/兼容扫描/影子构建 RBL-665/691/667——决定做得快不快）；3) **验证力**（语义 diff/行为测试/双模式对比 RBL-649/585/589——决定做得对不对）；4) **运营力**（灰度/看板/值班 SLA RBL-589/851/853——决定做得稳不稳）；5) **沉淀力**（迁移平台/文档/可替换性 RBL-789/848/866——决定下次成本）。
- 五力的依赖关系：验证力是地基（没有语义验证一切等于赌博）→ 执行力建立在验证上 → 运营力放大执行 → 沉淀力让下一次便宜 → 评估力决定要不要开始。新工程师的学习顺序也应是这个依赖序。
- 能力清单的面试映射：高级面试考「验证力 + 评估力」（判断题：这个迁移该不该做/怎么验证），资深考「运营力 + 沉淀力」（组织题：怎么让 200 仓库迁移可持续）；工具细节（RBL-5xx 原理层）是所有五力的底层语言。
- 复盘的元认知：迁移工程的本质是「在不确定中建立确定性」——用语义验证把行为不确定性消除、用数据把收益不确定性消除、用机制把组织不确定性消除；每个能力的价值都可以用「消除哪类不确定性」来陈述。
- 追问钩子：为什么「沉淀力」最容易被忽视却决定长期 ROI？——单次迁移的成功有运气成分（赶上了好时机/强团队）；沉淀力把运气变成能力（平台/文档/测试基建让第二次迁移成本减半）；组织的构建工具竞争力 = 迁移能力 × 沉淀能力，只算前者会高估团队。

```javascript
// 迁移能力自评（五域雷达）
const CAPABILITY_RUBRIC = {
  assess: { artifacts: ['收益模型', 'kill criteria', '试点报告'], weight: 0.15 },
  execute: { artifacts: ['翻译器', '兼容扫描', '影子构建流水线'], weight: 0.2 },
  verify: { artifacts: ['语义 diff 工具', '行为测试集', '双模式对比'], weight: 0.3 },   // 地基最重
  operate: { artifacts: ['灰度看板', '指标体系', '值班 runbook'], weight: 0.2 },
  sediment: { artifacts: ['迁移平台', '三层文档', '可替换性度量'], weight: 0.15 },
};
function capabilityScore(team) {
  return Object.entries(CAPABILITY_RUBRIC).map(([k, v]) => ({
    domain: k, score: v.artifacts.filter(a => team.has(a)).length / v.artifacts.length,
    weight: v.weight,
  }));
}
// 学习路径：verify -> execute -> operate -> assess -> sediment
```
