## RBL-168：构建可观测：CI 耗时监控与回归告警怎么搭

**答**：
- 采集：CI job 结束时上报数据点（job 名、分支、阶段耗时、缓存命中率、runner 信息、commit）到时序库（Prometheus/自建）；没条件也至少落一份 JSON 供脚本聚合。
- 展示：P50/P95 分支维度趋势图；PR 视图要能对比"这个 PR 相比基线慢了多少"（性能门禁的基础）。
- 告警：回归告警比绝对阈值更有效——某 job P50 连续上升 20% 触发；缓存命中率跌破阈值触发。告警要归因：附上最近变更（lockfile diff、配置 diff）。
- 防噪：统计口径剔除排队时间与偶发 flaky 重试；用窗口中位数而非单次值。
- 追问钩子：可观测是"构建工具链优化"的收尾必做项——没有度量，前面的优化会悄悄退化（依赖膨胀、缓存失效无人察觉）。

```javascript
// scripts/report-ci.js —— 构建结束时上报
import { readFileSync } from 'node:fs';
const stages = JSON.parse(readFileSync('.ci/stage-times.json', 'utf8'));
// stage-times.json 由 timed.js 包装器（RBL-153）累积生成

const point = {
  job: process.env.JOB_NAME,
  branch: process.env.BRANCH,
  commit: process.env.GIT_SHA,
  runner: `${process.env.RUNNER_OS}/${process.env.RUNNER_ARCH}`,
  cacheHit: process.env.CACHE_HIT === '1',
  install_s: stages.install, build_s: stages.build, test_s: stages.test,
  total_s: stages.install + stages.build + stages.test,
};
await fetch(process.env.METRICS_URL, {
  method: 'POST',
  headers: { 'content-type': 'application/json', authorization: `Bearer ${process.env.METRICS_TOKEN}` },
  body: JSON.stringify(point),
});
// 服务端按 branch+job 聚合出 P50/P95，并计算 PR 相对 main 基线的回归比例。
```
