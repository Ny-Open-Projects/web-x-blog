## RBL-926：综合深水：构建缓存的共享与隔离——缓存键作用域

**答**:
- monorepo 缓存的作用域矛盾：1) **跨包共享**（utils 的 transform 产物，app 构建时也要用——共享提升命中率）；2) **隔离需求**（不同包的配置/插件集不同——共享错缓存 = 语义污染：包 A 的 alias 影响 B 的产物）。键的作用域设计：键必须包含「影响产物的全部上下文」——跨包共享的前提是「该阶段的输出与包上下文无关」（纯源码 transform 可共享；resolve 后的产物不可共享 RBL-582 最小完备键的包级扩展）。
- 分层键设计：`transform: { 源码 hash + 语法 target }`（全局共享）→ `resolve: { 上述 + 包 resolve 上下文 hash }`（包内共享）→ `chunk: { 上述 + 包集合 hash }`（全仓唯一）——「阶段的共享域」由语义决定，不是一刀切。
- 隔离的防线：键冲突的检测（同键不同内容的命中 = 键不完备的信号——RBL-543 确定性测试的缓存版）；「包上下文指纹」（resolve 配置/插件集 hash）参与键生成。
- 缓存共享的成本收益核算：共享域大（命中率高但键长/污染风险）vs 小（键短但命中率低）——按阶段风险分级：transform 低风险全共享、chunk 高风险全隔离。
- 追问钩子：为什么「transform 可共享而 resolve 产物不可」？——transform 的输入只有（源码 + 语法目标），与包上下文无关（纯函数）；resolve 产物依赖包的 alias/tsconfig/node_modules 布局（上下文敏感）——共享域由「函数的输入闭包」决定：输入闭包越大键越宽、共享越危险；「纯函数边界」是缓存架构的分析工具（与 RBL-594 副作用判定同构：纯性决定可缓存性）。

```javascript
// 分层缓存键
function cacheKey(stage, ctx, { hash = sha256 } = {}) {
  const layers = {
    transform: [ctx.sourceHash, ctx.target],             // 全局共享：纯函数输入
    resolve: [ctx.sourceHash, ctx.target, ctx.pkgResolveHash],  // 包内共享
    chunk: [ctx.sourceHash, ctx.target, ctx.pkgResolveHash, ctx.pkgSetHash],  // 全仓唯一
  };
  return `${stage}:${hash(layers[stage].join('|'))}`;
}
// 键冲突检测（键不完备的信号）
function detectKeyCollision(cache, { sampleRate = 0.01 } = {}) {
  // 抽样：命中缓存的条目重算一次，对比内容
  const sampled = cache.sample(sampleRate);
  const collisions = sampled.filter(s => s.recomputed !== s.cached);
  if (collisions.length)
    fail(`缓存键冲突: ${collisions.length}/${sampled.length}——键不完备，需补充上下文指纹`);
  return collisions;
}
```
