## RBL-745：构建器与产物组合：多平台产物（web/node/rn）的单源构建矩阵

**答**:
- 一份业务代码跑多平台（web/Node SSR/React Native/小程序）的构建矩阵：平台差异三类——1) 语法目标（rn 用 hermes 兼容子集）；2) 模块解析（平台专属文件 .web.ts/.native.ts 后缀解析）；3) 全局环境（rn 无 DOM/window 有部分 shim）。构建器通过 resolve 的 `platform` 条件 + extensions 优先级实现平台分支。
- 平台后缀解析的规则深度：`.web.ts > .ts > .js` 的优先级顺序、目录级 index 变体、.native.ts 共享逻辑——解析器是「平台差异的第一现场」，构建器缓存键要含平台（RBL-634 的 cache key 加 platform 维度，防缓存串平台）。
- 产物组合的共享面分析：多平台产物共享业务逻辑（80%），平台层差异收敛在 adapter（fetch 存储路由事件）——构建器输出「平台共享度报告」（多少模块跨平台复用/多少平台专属），衡量抽象质量。
- 构建矩阵的 CI 成本：平台数 × 目标组合爆炸——分层构建（共享层构建一次 + 平台层增量）或按需矩阵（PR 只跑主平台、release 跑全矩阵）。
- 追问钩子：为什么平台分支放在「文件后缀」而不是「运行时 if」？——运行时分支把全平台代码打进每个产物（体积翻倍 + 泄漏平台 API）；文件后缀让分支在解析期发生（产物只含本平台代码）——「解析期分支」是多平台构建的第一性原理。

```javascript
// 平台感知解析
function platformExtensions(platform) {
  const base = ['.ts', '.tsx', '.js', '.jsx'];
  const platformExt = { web: '.web', native: '.native', rn: '.native', node: '.node' }[platform];
  return platformExt
    ? [`${platformExt}.ts`, `${platformExt}.tsx`, ...base]     // 平台文件优先
    : base;
}
// 构建矩阵
const MATRIX = [
  { platform: 'web', target: 'es2019', output: { dir: 'dist/web', format: 'es' } },
  { platform: 'node', target: 'node18', output: { dir: 'dist/node', format: 'cjs' } },
  { platform: 'native', target: 'hermes', output: { dir: 'dist/rn', format: 'es' } },
];
async function buildMatrix(src) {
  const outs = await Promise.all(MATRIX.map(m =>
    build({ ...m, input: src, extensions: platformExtensions(m.platform) })));
  return { outs, sharing: sharingReport(outs) };          // 平台共享度报告
}
// 缓存键含平台：cacheKey += platform（RBL-634 扩展）
```
