## RBL-282：构建工具的兼容性测试矩阵怎么建

**答**:
- 矩阵维度：Node 版本（LTS 范围）× OS（win/mac/linux）× 架构（x64/arm64）× 场景（spa/mpa/lib/微前端）——Native 工具必须覆盖矩阵（平台二进制差异）
- 实现成本控制：矩阵按风险分层——发布必测核心格（win-x64/linux-x64/mac-arm × 主场景），夜间跑全矩阵；GitHub Actions matrix 矩阵原生支持
- 平台专项：路径分隔符/大小写敏感（mac vs linux）/换行符——跨平台产物一致性的经典坑（hash 因路径不同而不同）
- 团队侧矩阵：开发者 OS 分布调查 → 把真实使用面纳入必测集

```yaml
matrix:
  os: [ubuntu-latest, macos-14, windows-latest]
  node: [18, 20, 22]
  scenario: [spa, lib]
# 专项断言：跨平台产物 hash 一致（路径归一化后）
```
