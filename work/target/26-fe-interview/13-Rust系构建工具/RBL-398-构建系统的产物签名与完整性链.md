## RBL-398：产物签名与完整性链

**答**:
- 完整性链：CI 构建签名（产物清单 hash + CI 私钥签名）→ 部署验证签名（部署系统校验）→ 浏览器 SRI（每资源 hash）——三层保证「用户运行的产物 = CI 构建的产物」
- 实现要点：签名内容 = manifest（文件+hash 树）而非单文件（链式完整性）、密钥管理（CI 签名私钥 KMS 管理，轮换机制）、SRI 与签名 hash 口径统一
- 价值场景：供应链攻击检测（产物被篡改 → 签名不匹配拒绝部署/运行）、部署事故定位（哪一层 hash 断链）
- 与 RBL-318 指纹对账的区别：指纹对账是「排查工具」（事后），签名链是「防护机制」（事前阻断）

```text
三层链：CI 签名 → 部署校验 → 浏览器 SRI
要点：manifest 签名 / KMS 密钥 / hash 口径统一
价值：供应链攻击阻断 + 分层定位
```
