## RBL-264：构建缓存的多级架构（本地/团队/云端）

**答**:
- 三级：本地磁盘（最快，个人复用）→ 团队共享（S3/NFS，同分支复用）→ 云端全局（跨分支 main 基线）——逐级回退，命中即停
- 优先级策略：main 分支缓存对特性分支只读（防分支污染基线）；团队缓存按「同 fixture + 同工具版本」命名空间隔离
- 一致性：任意层级命中都要过 output hash 校验（防投毒/损坏）；层级间同步策略（CI 产物写团队层，nightly 写云端基线）
- 成本账：缓存存储有生命周期成本——LRU 清理 + 分支命名空间过期（7 天）+ 命中率监控决定层级取舍

```text
查找链：local disk → team S3（同分支命名空间）→ cloud base（main 基线）
写入：CI → team；nightly main → cloud；本地命中即写回本地
校验：每级命中过 output hash
```
