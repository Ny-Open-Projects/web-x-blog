## RBL-891：迁移复盘：组织构建能力的终局——平台组、成员团队与元框架的三分格局

**答**:
- 中大型组织构建职责的终局三分：1) **平台组**（构建器/共享 preset/CI 模板/发布流水线——产品的产品，服务内部客户）；2) **成员团队**（用 preset + 白名单覆盖，只关心业务语义——配置自由度被有意限制）；3) **元框架/上游社区**（vite/rolldown——平台组站在上游肩膀上，upstream-first 协作 RBL-783）。
- 三分格局的耦合契约：平台组对上游（fork 负债管理 RBL-784）、对成员（preset 兼容 semver RBL-651 的内部版 + 升级日 RBL-821）；成员对平台（自检脚本/文档自助 RBL-853）——「契约化」让三方各自演进。
- 小组织的不同形态：无平台组时元框架默认值 + 少量约定（文档）就是「平台」——形态随规模缩放，但「配置自由度收敛」的原则不变（自由度 = 维护成本）。
- 终局的判断依据：构建问题对业务的干扰频率——干扰频繁 → 投入平台组；偶发 → 元框架默认 + 文档；「构建团队的存在理由是让业务团队忘记构建的存在」——平台的北极星是「无感知」。
- 追问钩子：为什么「配置自由度收敛」对成员团队是好事而非限制？——自由度 = 维护成本的分摊：200 个团队各有一份 webpack 配置 = 200 份维护负担 + 0 份共享；收敛到 preset 后维护归平台组（专业化），成员只做语义决策（他们擅长的）——「限制的是选项，解放的是注意力」，这与微前端隔离（RBL-766）的团队边界哲学一致。

```javascript
// 构建职责的三分契约
const CONTRACTS = {
  platform: {
    provides: ['preset + semver', 'CI 模板', '升级日', '值班 SLA（RBL-853）'],
    upstreamPolicy: 'upstream-first，fork 负债季审（RBL-783/784）',
  },
  member: {
    consumes: ['preset', '自检脚本', '文档'],
    duty: ['白名单内覆盖', '业务语义验证（owner 签核 RBL-802）', '跟随升级日'],
  },
  upstream: { consumes: ['bug report', '通用特性 PR'], gives: ['稳定构建器', '生态插件'] },
};
// 平台的北极星度量
const platformNorthStar = {
  metric: '构建相关工单数 / 团队数 / 月',
  target: '下降趋势（终态：业务团队忘记构建的存在）',
  antiMetric: 'preset 覆盖率下降 / fork 行数上升',
};
```
