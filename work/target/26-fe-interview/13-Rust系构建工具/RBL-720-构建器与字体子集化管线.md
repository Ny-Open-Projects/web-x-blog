## RBL-720：字体子集化管线：按需字符集、分片加载与 FOUT 治理

**答**:
- 中文字体的体积问题：全量 CJK 字体 5-10MB——构建期子集化（扫描源码提取实际使用的字符 → fonttools subset）把字体压到几百 KB；难点是「动态内容字符」（用户输入/后端文案不在源码里）→ 分片方案（unicode-range 切片：把字体按常用度切 N 片，浏览器按需加载——Google Fonts 中文的思路）。
- 构建管线：1) 静态字符集提取（源码扫描）；2) 分片计划生成（按 unicode-range 分块 + 频率排序——首屏高频字符进第一片）；3) CSS 生成（@font-face × N 片，unicode-range 声明）；4) 缓存键 = 源字体 hash + 字符集 hash（字符集变了才重切）。
- FOUT 治理的构建配合：font-display: swap 的兜底、preload 第一片（高频字符）、fallback 字体的 metrics 匹配（size-adjust 让回退字体占位宽度接近真字体——减少布局抖动）；构建器输出「字体加载建议清单」。
- 字体许可：子集化/embedding 权限是法律问题——构建管线要有字体许可元数据检查（subset 允许标记），无许可的字体拒绝子集化并告警。
- 追问钩子：为什么「子集化」不能只做静态扫描？——SPA 的动态渲染内容（接口数据/用户输入）字符不可预知；分片 + unicode-range 让「未知字符」也能按需加载，静态子集只优化「确定字符」的命中率——两层组合才是完整方案。

```javascript
// 字体分片计划
function planSubsets(chars, { sliceSize = 500 } = {}) {
  const freq = charFreq(chars);                          // 按源码出现频率
  const sorted = [...chars].sort((a, b) => freq[b] - freq[a]);
  const slices = [];
  for (let i = 0; i < sorted.length; i += sliceSize)
    slices.push(sorted.slice(i, i + sliceSize));
  return { slices, firstSlice: slices[0] };              // 第一片 = 高频（preload）
}
function emitFontCSS(fontFamily, slices) {
  return slices.map((chars, i) => `@font-face {
  font-family: '${fontFamily}';
  src: url('/fonts/${fontFamily}.s${i}.woff2') format('woff2');
  unicode-range: ${toUnicodeRange(chars)};
  font-display: swap;
}`).join('\n');
}
// 许可检查
if (!fontLicense.allowsSubset) fail(`${font} 许可不含子集化/embedding——拒绝处理`);
```
