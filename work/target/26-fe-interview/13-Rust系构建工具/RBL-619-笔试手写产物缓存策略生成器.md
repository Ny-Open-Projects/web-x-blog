## RBL-619：笔试：手写产物缓存策略生成器（角色分类 + immutable 安全检查）

**答**：实现 `cachePolicy(files)`。files: `{ name, role, hash }[]`，role ∈ 'entry-html' | 'service-worker' | 'asset' | 'chunk'。返回 `Map<name, string>` 规则：1) entry-html → `public, max-age=0, must-revalidate`；2) service-worker → `no-cache`；3) 其余：hash 存在 → `public, max-age=31536000, immutable`；无 hash → `public, max-age=0, must-revalidate`（同名覆盖不敢 immutable）。另实现 `auditUnsafe(files)`：找出「无 hash 但被策略标记了 immutable」的矛盾项（防御误配），返回文件名数组。边界：role 缺失按 'asset'；空列表返回空 Map。

```javascript
const POLICY = {
  immutable: 'public, max-age=31536000, immutable',
  negotiated: 'public, max-age=0, must-revalidate',
};

function cachePolicy(files) {
  const out = new Map();
  for (const f of files) {
    const role = f.role ?? 'asset';
    let policy;
    if (role === 'entry-html') policy = POLICY.negotiated;
    else if (role === 'service-worker') policy = 'no-cache';
    else if (role === 'api') policy = 'no-store';
    else policy = f.hash ? POLICY.immutable : POLICY.negotiated;   // 无 hash 不敢 immutable
    out.set(f.name, policy);
  }
  return out;
}

function auditUnsafe(files) {
  const policy = cachePolicy(files);
  return files
    .filter(f => (policy.get(f.name) || '').includes('immutable') && !f.hash)
    .map(f => f.name);                                    // 理论不可达（策略已防），审计兜底
}

// 自测
const files = [
  { name: 'index.html', role: 'entry-html', hash: null },
  { name: 'sw.js', role: 'service-worker', hash: null },
  { name: 'main.abc.js', role: 'chunk', hash: 'abc' },
  { name: 'legacy.js', role: 'chunk', hash: null },        // 同名覆盖模式
  { name: 'logo.png' },                                    // role 缺失
];
const p = cachePolicy(files);
console.log(p.get('index.html') === POLICY.negotiated);
console.log(p.get('sw.js') === 'no-cache');
console.log(p.get('main.abc.js') === POLICY.immutable);
console.log(p.get('legacy.js') === POLICY.negotiated);     // 无 hash 降级
console.log(p.get('logo.png') === POLICY.negotiated);
console.log(auditUnsafe(files).length === 0);
console.log(cachePolicy([]).size === 0);
// 矛盾注入审计（模拟误配）
const bad = files.map(f => ({ ...f, _force: 'immutable' }));
// auditUnsafe 只对策略结果审计——构造策略矛盾场景验证函数本身
console.log(auditUnsafe([{ name: 'x.js', role: 'chunk', hash: null }]).length === 0);
```

**评分点**：
- 角色优先级正确：html/sw 特殊策略先于通用 hash 判断
- 「无 hash 不得 immutable」安全降级实现（同名覆盖发布模式的防线）
- role 缺失按 asset 处理；api 角色可扩展 no-store（架构开放性）
- 能说清「immutable 只与内容寻址文件名组合成立」与「旧版本保留窗口」的关联属于加分
