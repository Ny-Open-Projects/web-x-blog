## RBL-400：笔试手写——给定 monorepo 依赖图与本次改动文件，计算受影响的下游构建任务

**答**：输入 `deps`（包 → 其依赖的包列表）、`changed`（改动包列表）。某个包被改动后，所有直接或间接依赖它的包都要重新构建。输出排序后的受影响包列表，注意环形依赖不能死循环。

```javascript
/**
 * @param {Record<string, string[]>} deps  pkg -> 它依赖的包
 * @param {string[]} changed 本次改动的包
 * @returns {string[]} 受影响的包（不含 changed 本身），按字典序
 */
function affected(deps, changed) {
  // 反向索引：pkg -> 谁依赖它（下游）
  const rdeps = {};
  for (const [pkg, ds] of Object.entries(deps)) {
    rdeps[pkg] ||= [];
    for (const d of ds) (rdeps[d] ||= []).push(pkg);
  }
  const seen = new Set(changed);
  const queue = [...changed];
  while (queue.length) {
    const cur = queue.pop();
    for (const down of rdeps[cur] || []) {
      if (!seen.has(down)) {   // seen 集合同时防环、防重复入队
        seen.add(down);
        queue.push(down);
      }
    }
  }
  return [...seen].filter(p => !changed.includes(p)).sort();
}

// deps: app 依赖 ui，ui 依赖 utils，circular: a<->b
const deps = { app: ['ui'], ui: ['utils'], utils: [], a: ['b'], b: ['a'] };
console.log(affected(deps, ['utils'])); // ['ui', 'app']
console.log(affected(deps, ['a']));     // ['b']（环形不扩散为死循环）
```

**评分点**：
- 正确构建反向索引（很多候选人直接在原方向 BFS，方向反了全错）
- 用 visited 集合防环 + 防重复入队，明确说出环形依赖的处理
- 边界：changed 中的包本身不算「受影响」；无下游时返回空数组
- 复杂度 O(V + E)，能说出为什么不用逐包重算做暴力过滤
