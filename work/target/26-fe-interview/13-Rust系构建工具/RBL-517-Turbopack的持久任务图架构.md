## RBL-517：Turbopack 的持久任务图：函数级缓存为什么可行

**答**:
- Turbopack 的核心架构：**把编译过程编译成任务图**——每个编译单元是一个「任务」（parse file/read dir/resolve/transform），任务有输入指纹与输出缓存；输入不变 → 直接复用输出（跨进程持久化到磁盘）。函数级缓存 = 「任务粒度的 memoization」。
- 可行的前提是**纯函数化**：任务必须是确定性的纯函数（输入指纹相同 → 输出字节相同）——Turbopack 把所有环境依赖（时间/随机/env）收敛为「显式输入」，这是纯函数化的工程难点。
- 与 Rspack 的流派差异：Rspack = 「事件驱动的增量」（变更事件 → 失效传播 → 重算受影响者），Turbopack = 「任务图的持久 memoization」（指纹不变直接跳过）——后者缓存粒度更细（函数级 vs 模块级）但架构约束更严。
- 任务图的执行调度：任务间依赖 = 图拓扑——无依赖任务并行、有依赖按拓扑序；「按需执行」（lazy）是 dev 体验的关键：页面只引用的模块才编译（未被 import 的文件零成本）。
- 追问钩子：持久缓存的失效正确性——指纹要覆盖「任务可见的全部输入」（文件内容+配置+依赖版本+工具版本），漏一项就是脏缓存——指纹设计是持久缓存系统的生命线（RBL-534 缓存键卡同构）。

// Turbopack 持久任务图
const TASK_GRAPH = {
  核心思想: '编译过程编译成任务图：任务 = 函数级缓存单元（输入指纹 → 输出缓存）',
  纯函数化: {
    requirement: '任务确定性：输入指纹相同 → 输出字节相同',
    difficulty: '环境依赖（时间/随机/env）收敛为显式输入——工程难点',
  },
  vs_Rspack: {

  },
  调度: {
    parallel: '无依赖任务并行、有依赖拓扑序',
    lazy: '按需执行——页面只引用的模块才编译（未 import 零成本）',
  },
  生命线: '指纹覆盖任务可见的全部输入（内容+配置+依赖版本+工具版本）——漏一项 = 脏缓存',
}
