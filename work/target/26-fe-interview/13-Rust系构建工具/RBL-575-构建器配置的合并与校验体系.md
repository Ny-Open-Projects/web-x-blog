## RBL-575：构建器配置体系：TS 配置的类型校验、默认值分层与迁移诊断

**答**：
- 构建器配置的复杂度在于三层叠加：用户配置 → profile/环境预设（dev/prod/test）→ 内置默认值；合并顺序必须是「深合并 + 数组替换」明确语义——webpack merge 的历史混乱（数组 concat 还是替换）教训要吸收：rolldown/esbuild 都定为「数组整体替换」，组合用显式 spread。
- 校验两层：**类型层**（TS 类型 + 运行时 schema，Rust 侧入口再验一次——JS 类型只是编译期约束，配置可从 JSON 来）与**语义层**（依赖约束：output.format='iife' 与 codeSplitting=true 冲突；experimental 选项与 stable 选项的组合告警）。
- 错误体验：配置错误给出「字段路径 + 实际值 + 期望 + 修复示例」四元组，而不是把 Rust serde 报错裸抛——serde 的错误信息要映射成面向用户的诊断（见 RBL-568）。
- 迁移诊断（webpack → rolldown 配置迁移）是实战重点：识别 webpack 独有配置（loader/module.rules）→ 给出等价方案或「不支持 + 变通」清单，迁移工具输出 diff 报告而非静默忽略——静默忽略未知字段是大事故源（用户以为生效了）。
- 追问钩子：配置热更新（dev server watch 配置文件）的失效粒度——配置变更通常意味着重建 pipeline（插件集合变了），等价于重启构建器而不是增量失效；设计上要显式标记「可热更子集」（如 sourcemap 开关）与「需重启」。

```javascript
// 配置合并与语义校验
const DEFAULTS = { output: { format: 'es', sourcemap: false }, resolve: { alias: {} } };
const PROFILES = { dev: { output: { sourcemap: true } }, prod: { minify: true } };

function merge(base, ...over) {                 // 数组整体替换语义
  if (Array.isArray(base) || Array.isArray(over[0])) return over[0] ?? base;
  if (typeof base === 'object' && base && typeof over[0] === 'object' && over[0])
    return { ...base, ...Object.fromEntries(Object.keys(over[0])
      .map(k => [k, merge(base[k], over[0][k])])) };
  return over.length ? over[over.length - 1] : base;
}
const config = merge(DEFAULTS, PROFILES.dev, userConfig);

// 语义校验：组合冲突
function validate(c) {
  const errs = [];
  if (c.output.format === 'iife' && c.codeSplitting) errs.push({
    field: 'codeSplitting', value: c.codeSplitting, expect: 'false when format=iife',
    fix: `output: { format: 'es' } 或 codeSplitting: false` });
  for (const key of unknownKeys(c, KNOWN_FIELDS)) errs.push({          // 未知字段显式报错
    field: key, value: 'unknown', expect: 'known option or plugin',
    fix: `webpack 迁移？module.rules 请改用 plugins 里的 transformer（见迁移指南）` });
  return errs;
}
```
