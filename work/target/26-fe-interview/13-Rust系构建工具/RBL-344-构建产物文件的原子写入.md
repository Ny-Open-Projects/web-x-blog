## RBL-344：构建产物与缓存文件的原子写入

**答**:
- 问题：直接写目标文件在崩溃/断电时留下半截内容（产物损坏/缓存损坏）——原子写 = 写临时文件 + fsync + rename（rename 同分区原子）
- 实现细节：临时文件放同目录（跨分区 rename 不原子）、fsync 确保落盘、并发写保护（lock 或唯一临时名：pid+uuid）
- 缓存目录的清理策略：损坏文件（半截 JSON）在读取时检测丢弃——防御性读取（try-catch + schema 校验）+ 写入原子性双保险
- 分布式扩展：远程缓存的原子性由服务端保证（S3 put 原子）——本地实现学 S3 语义（先写完整再可见）

```javascript
function atomicWrite(file, data) {
  const tmp = path.join(path.dirname(file), `.${path.basename(file)}.${process.pid}.${uuid()}`)
  fs.writeFileSync(tmp, data)
  fs.fsyncSync(fs.openSync(tmp, 'r'))
  fs.renameSync(tmp, file)                    // 同目录 → 原子替换
}
// 读取防御：JSON.parse try-catch + schema 校验，损坏即删重算
```
