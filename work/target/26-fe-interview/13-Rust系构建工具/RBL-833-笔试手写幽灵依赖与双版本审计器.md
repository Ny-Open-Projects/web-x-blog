## RBL-833：笔试：手写幽灵依赖与多版本审计器（声明比对 + 双实例）

**答**：实现 `auditDeps(modules, declarations)`。modules: `Array<{ id, owner }>`（id 形如 `node_modules/lodash@4.17.21/lodash.js` 或 `src/a.js`；owner 为所属包名）；declarations: `Record<owner, Set<string>>`（各包声明的直接依赖）。规则：1) 幽灵依赖：id 在 node_modules 下，其顶层包名不在 owner 的声明集 → `{ type: 'phantom', pkg, owner }`（按 pkg+owner 去重）；2) 多版本：同顶层包出现 ≥2 个不同版本 → `{ type: 'multi-version', pkg, versions }`；3) **双实例门禁**：多版本包的模块同时出现在同一 entry 的闭包 → 追加 `{ type: 'dual-instance', pkg }`（entryClosures: `Record<entry, string[]>` 注入）；4) 返回 `{ problems }`（phantom 排序在前）。边界：无 node_modules 模块；声明集缺失视为空。

```javascript
const parse = (id) => {
  const m = /^node_modules\/((?:@[\w-]+\/)?[\w.-]+?)(?:@([\d.]+))?\/(.*)$/.exec(id);
  return m ? { pkg: m[1].replace(/@[\d.]+$/, ''), version: m[2] ?? null, rest: m[3] } : null;
};

function auditDeps(modules, declarations, entryClosures = {}) {
  const phantomSet = new Set();
  const versions = new Map();                            // pkg -> Set<version>
  for (const { id, owner } of modules) {
    const p = parse(id);
    if (!p) continue;
    if (!(declarations[owner] ?? new Set()).has(p.pkg))
      phantomSet.add(JSON.stringify({ type: 'phantom', pkg: p.pkg, owner }));
    if (p.version) {
      versions.get(p.pkg) || versions.set(p.pkg, new Set()).get(p.pkg).add(p.version);
    }
  }
  const problems = [...phantomSet].map(s => JSON.parse(s));
  for (const [pkg, vs] of versions) {
    if (vs.size > 1) {
      problems.push({ type: 'multi-version', pkg, versions: [...vs] });
      for (const [entry, closure] of Object.entries(entryClosures))
        if (closure.some(id => id.includes(pkg)))
          problems.push({ type: 'dual-instance', pkg, entry });   // 简化：闭包含该包即查
    }
  }
  const rank = { phantom: 0, 'dual-instance': 1, 'multi-version': 2 };
  problems.sort((a, b) => rank[a.type] - rank[b.type] ||
    (a.pkg ?? '').localeCompare(b.pkg ?? ''));
  return { problems };
}

// 自测
const modules = [
  { id: 'node_modules/lodash@4.17.21/lodash.js', owner: 'app' },
  { id: 'node_modules/lodash@3.10.1/lodash.js', owner: 'legacy-ui' },
  { id: 'node_modules/moment@2.29.1/moment.js', owner: 'app' },          // app 未声明 moment
  { id: 'src/index.js', owner: 'app' },
];
const declarations = { app: new Set(['lodash', 'react']), 'legacy-ui': new Set(['lodash']) };
let r = auditDeps(modules, declarations, { entry: ['node_modules/lodash@4.17.21/lodash.js', 'node_modules/lodash@3.10.1/lodash.js'] });
console.log(r.problems[0].type === 'phantom' && r.problems[0].pkg === 'moment');
console.log(r.problems.some(p => p.type === 'multi-version' && p.pkg === 'lodash'));
console.log(r.problems.some(p => p.type === 'dual-instance' && p.pkg === 'lodash' && p.entry === 'entry'));
console.log(r.problems[0].type === 'phantom');           // phantom 排序在前
console.log(r.problems.length === 3);

// 无幽灵：声明完整
r = auditDeps([modules[0]], { app: new Set(['lodash']) });
console.log(r.problems.length === 0);
```

**评分点**：
- id 解析兼容 scope 包与 @版本内嵌（lodash@4.17.21）；phantom 按 pkg+owner 去重
- 多版本聚合与双实例门禁（同一 entry 闭包含多版本 = 双实例风险）
- 排序：phantom 优先（发布阻断类）；边界（无 node_modules/声明缺失为空集）
- 能说清「幽灵依赖是开发态与发布态的解析差异，pnpm 隔离是发布态忠实模拟」属于加分
