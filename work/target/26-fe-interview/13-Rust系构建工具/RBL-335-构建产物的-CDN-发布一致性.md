## RBL-335：构建产物在 CDN 的发布一致性

**答**:
- 一致性风险：多 CDN 节点同步延迟（部分节点新部分旧 → 用户拿到混合版本）、上传不完整（部分文件失败）、缓存刷新不彻底
- 保障机制：发布清单驱动（上传完成后逐文件 head 校验）→ 全量就绪才切 html 指针（先传产物后切入口）——「产物先行，入口后切」是发布一致性的核心
- 探测：多地区拨测（各 CDN 节点拉 manifest 比对 hash）——发布完成判定以「全网一致」为准
- 事故预案：半发布状态回滚（入口切回旧 manifest）+ CDN 强刷（ costly，最后手段）

```text
发布序：产物全量上传 → head 校验清单 → 拨测全网一致 → 切 html 指针
回滚：指针切回旧 manifest（产物保留多版本）
```
