## RBL-490：构建系统综合收官（全能力验证）
**需求**：综合运用 401~489 的机制，实现 `createBuildPlatform()` 门面——把分散机制组装成可运行平台骨架（每个子系统一行集成声明 + 组装顺序），作为 500 张卡收官的总装。

```javascript
export function createBuildPlatform({ remoteCache, registry, telemetry, slo }) {
  const layers = {
    L0_core: {
      resolveCache: createResolveCache(resolve),        // 483
      moduleGraph: buildGraph,                          // 416
      profiler: createProfiler(),                       // 405
      abortScope: new AbortScope(),                     // ZSM 侧复用概念
    },
    L1_build: {
      bundler: bundle,                                  // 417
      incremental: createWatcher(graph, opts),          // 418
      manifest: generateManifest,                       // 404
      integrity: validateSourceMap,                     // 407
    },
    L2_orchestration: {
      scheduler: createScheduler,                       // 402
      affected: computeAffected,                        // 401
      workerPool: createWorkerPool,                     // 435
      branchCache: createBranchCache(remoteCache),      // 448
    },
    L3_governance: {
      budget: createBudgetGuard,                        // 406
      diff: diffManifests,                              // 410
      slo, telemetry,                                   // 471/421
      chaos: createChaos,                               // 468
      rollback: createRollback,                         // 440
    },
  }
  // 依赖红线：L3 只读观测；L1 不依赖 L2/L3；失败隔离（治理崩不影响构建）
  return { layers,
    acceptance: ['增量=全量（418/230）', '指纹完整（409）', 'hash 稳定（415）',
      '缓存可校验（403）', '降级链存在（468 验证）', '可回滚（440）'] }
}
```
**评分点**：
- 组装顺序与依赖方向（L0→L1→L2→L3 单向；治理只读）
- 每个子系统标注来源卡号（架构题的机制支撑——不是空谈）
- 验收清单对应机制（每条验收可指向具体实现）
- 失败隔离声明（治理层崩溃不影响业务路径）
