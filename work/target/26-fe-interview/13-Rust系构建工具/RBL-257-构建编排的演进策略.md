## RBL-257：从 npm 脚本拼接到任务编排器的演进策略

**答**:
- 演进阶段：单仓 npm scripts → 手写 shell 串行（慢）→ Lerna/gulp 并行（无缓存）→ Turborepo/Nx（图+缓存+分布式）——按痛点引入，不跳级
- 引入时机信号：全量 CI > 15 分钟、重复构建多（10 包共享依赖全部重 build）、CI 排队严重——三个信号齐备再上编排器
- 迁移步骤：先只接管 build（收益最大风险最小）→ test → lint；保留原脚本为 fallback 双跑一周验证一致
- 反模式：一上来全量接管 + 团队不理解缓存语义——迁移期保留「无缓存模式」逃生门（turbo build --no-cache 排障）

```text
迁移节奏：build（第一周）→ 验证一致 → test（第二周）→ lint → 删旧脚本
逃生门：--no-cache 对比排障
```
