## RBL-190：笔试：手写缓存命中率统计与成本估算器

**答**：写 cache-metrics.mjs：1) 输入 CI 构建记录数组（每条含 job、cacheKey、hit、buildSeconds、machineCostPerMin）；2) 按 job 聚合：请求数、命中数、命中率；3) 估算"缓存节省的机器成本"：hit 构建按其对应 miss 构建耗时的 90% 计节省（命中仍有 restore 开销 10%）；4) 输出表格与 Top 差 job（命中率 < 30%）；5) 命中率时间序列：按 commit 时间排序输出滑动窗口（最近 20 次）命中率，便于看趋势。

```javascript
// cache-metrics.mjs
export function analyze(builds, { restoreOverhead = 0.1, windowSize = 20 } = {}) {
  const byJob = {};
  for (const b of builds) {
    const g = byJob[b.job] ??= { total: 0, hit: 0, saved: 0, missDur: [], hitDur: [] };
    g.total++;
    if (b.hit) {
      g.hit++; g.hitDur.push(b.buildSeconds);
      // 该 job 最近一次 miss 的耗时作为"若 miss 会花多久"的估计
      const est = g.missDur.at(-1) ?? b.buildSeconds;
      g.saved += est * (1 - restoreOverhead) * b.machineCostPerMin / 60;
    } else g.missDur.push(b.buildSeconds);
  }
  const rows = Object.entries(byJob).map(([job, g]) => ({
    job, total: g.total,
    hitRate: +(g.hit / g.total * 100).toFixed(1),
    savedUSD: +g.saved.toFixed(2),
  }));
  const bad = rows.filter(r => r.hitRate < 30).sort((a, b) => a.hitRate - b.hitRate);

  // 时间序列：按 commit 时间升序的滑动窗口命中率
  const sorted = [...builds].sort((a, b) => new Date(a.ts) - new Date(b.ts));
  const series = [];
  for (let i = windowSize; i <= sorted.length; i++) {
    const w = sorted.slice(i - windowSize, i);
    series.push({ at: w.at(-1).ts,
      hitRate: +(w.filter(x => x.hit).length / windowSize * 100).toFixed(1) });
  }
  return { rows, bad, series };
}

// 演示数据
const builds = [
  { job: 'build', cacheKey: 'k1', hit: false, buildSeconds: 600, machineCostPerMin: 0.02, ts: '2026-11-18T01:00:00Z' },
  { job: 'build', cacheKey: 'k1', hit: true, buildSeconds: 90, machineCostPerMin: 0.02, ts: '2026-11-18T02:00:00Z' },
  { job: 'test', cacheKey: 'k2', hit: false, buildSeconds: 900, machineCostPerMin: 0.02, ts: '2026-11-18T02:10:00Z' },
];
console.table(analyze(builds).rows);
console.log('需治理 job:', analyze(builds).bad);
```
**评分点**：
- 命中率与成本节省分维度聚合。
- 节省估算考虑 restore 开销（不是 100% 节省），miss 基线取最近一次真实 miss。
- Top 差 job 排序输出（治理优先级）。
- 滑动窗口趋势可发现"命中率随时间衰减"。
- 能解释命中率下降的可能原因（key 设计、容量淘汰）衔接排查题。
