## RBL-263：多环境构建的配置矩阵管理

**答**:
- 矩阵维度：环境（dev/test/staging/prod）× 变体（平台/租户/AB）——配置爆炸的解法是「基础 + 覆盖层」（base config + env override + variant override，深度合并）
- 环境差异应收敛为「数据」而非「配置」：环境差异点抽成 env 清单（接口域名/开关），构建只管打何种包——避免每个环境一份完整配置漂移
- 校验：构建时校验当前组合的配置合法性（schema），非法组合 fail-fast；环境清单进类型定义（env.d.ts）
- 验收：每环境产物带构建指纹（env 清单 hash 写入版本文件），线上可核对「跑的哪份配置」

```javascript
// base + 覆盖层
const base = { ... }
const envs = { test: { sourcemap: 'all', minify: false }, prod: { minify: true } }
export default merge(base, envs[process.env.NODE_ENV])
// 构建指纹
console.log('envHash:', sha(JSON.stringify(envManifest)))   // 进版本文件
```
