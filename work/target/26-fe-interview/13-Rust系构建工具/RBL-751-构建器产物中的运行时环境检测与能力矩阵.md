## RBL-751：运行时能力矩阵的构建期生成：特性清单驱动的能力检测代码

**答**:
- 构建器扫描产物使用到的「平台能力」（fetch/Worker/WebGL/optional chaining 语法）→ 生成能力清单（capability manifest：每项能力的检测代码 + 被哪些模块使用）——运行时按清单做一次检测（RBL-724 分层加载的依据），比手写散落的特性检测集中且可审计。
- 清单的两类能力：**语法能力**（构建目标已处理的不再列——target es2019 下可选链已转换）与 **API 能力**（运行时探测：IntersectionObserver/fetch）。语法能力来自转换器统计，API 能力来自 AST 扫描全局引用。
- 检测代码的生成规范：每能力一个纯函数（无副作用、可组合），生成的检测文件本身零依赖（可在任何环境跑）——检测文件也要过 RBL-724 core 层预算。
- 能力清单的维护：API 使用变化（新模块用了 Worker）→ 清单自动更新——构建器把「能力」当一等资产（失效传播：清单变化 → 引用清单的 HTML/入口失效）。
- 追问钩子：为什么能力检测要「构建期生成」而不是「运行时库」？——运行时库（modernizr 类）检测全部能力但多数无用；构建期生成的清单只含「你的产物真的用到」的能力（检测项数量从 100+ 降到 5-10），且与产物版本绑定（能力变化即清单 hash 变化）——按需 + 可审计。

```javascript
// 能力清单生成
const API_CAPABILITIES = {
  fetch: 'typeof fetch === "function"',
  worker: 'typeof Worker !== "undefined"',
  webgl: '(() => { try { const c = document.createElement("canvas"); return !!c.getContext("webgl"); } catch { return false; } })()',
  intersectionObserver: 'typeof IntersectionObserver !== "undefined"',
};
function generateCapabilityManifest(chunks, { syntaxTarget }) {
  const used = new Set();
  for (const chunk of chunks)
    for (const api of Object.keys(API_CAPABILITIES))
      if (chunk.code.includes(api)) used.add(api);       // AST 扫描更精确，简化为文本
  const syntax = transformStats(chunks)                  // 转换器统计：被降级的语法
    .filter(s => s.converted).map(s => s.feature);
  return {
    api: [...used].map(name => ({ name, detect: API_CAPABILITIES[name] })),
    syntax,                                              // 语法能力已由 target 处理，列出供审计
  };
}
// 产物：capability.js —— 运行时一次性检测，结果存 sessionStorage 供分层加载决策
```
