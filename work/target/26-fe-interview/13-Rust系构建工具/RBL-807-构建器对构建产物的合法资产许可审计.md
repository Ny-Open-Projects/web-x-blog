## RBL-807：产物资产合规审计：字体/图片许可证与再分发边界的构建门禁

**答**:
- 产物里嵌入的资产有法律边界：1) **字体许可**（RBL-720 提过 subset 权限；还有「web 嵌入权限」——桌面版字体授权不含 web embedding）；2) **图片版权**（unsplash/图库的署名要求）；3) **第三方 CSS/代码**（MIT/BSD 需要保留版权声明——minify 不许删 legal 注释/*! */）。构建器的资产审计：资产清单 × 许可证元数据 → 门禁。
- 许可证元数据的载体：资产注册表（内部：每个字体/图片的 license 字段）或 npm 包的 LICENSE 字段——构建器在产物聚合时生成 THIRD-PARTY-NOTICES（法律要求的声明文件），缺失即门禁失败。
- legal 注释保护：压缩器必须保留 `/*! ... */` 开头的注释（版权/许可声明）——构建器审计「产物中 license 注释存活性」（源码有但产物被剥 = 违规）；配置 contract：terser/esbuild 的 comments 保留规则。
- web 字体的合规要点：woff2 嵌入许可、CDN 分发许可（部分字体许可只允许自托管或只允许特定 CDN）——注册表的 license.scope 字段（self-host/cdn/embed）与产物分发方式比对。
- 追问钩子：为什么 license 注释会被「悄悄剥掉」而没人发现？——压缩器的默认行为是剥全部注释（体积优化），legal 注释靠特殊前缀豁免；迁移/换压缩器时配置丢失，注释消失——没有「产物中 license 存活」的机械检查，违规是静默的；合规审计的价值就是把法律要求变成构建门禁。

```javascript
// 资产许可审计
function auditLicenses(assets, registry, { distMode = 'self-host' } = {}) {
  const problems = [];
  const notices = [];
  for (const a of assets) {
    const lic = registry[a.id];
    if (!lic) { problems.push(`${a.id}: 未注册许可信息`); continue; }
    if (!lic.scope?.includes(distMode))
      problems.push(`${a.id}: 许可不允许 ${distMode} 分发（scope: ${lic.scope}）`);
    if (lic.required && !lic.notice)
      problems.push(`${a.id}: 许可要求署名但缺 notice 文本`);
    if (lic.notice) notices.push(lic.notice);
  }
  return { problems, thirdPartyNotices: notices.join('\n---\n') };
}
// license 注存活检查
function verifyLegalComments(source, minified) {
  const legal = [...source.matchAll(/\/\*!([\s\S]*?)\*\//g)].map(m => m[1].trim().slice(0, 40));
  const missing = legal.filter(l => !minified.includes(l));
  if (missing.length) fail(`许可注释被压缩剥除: ${missing}——压缩器需保留 /*! */ 注释`);
}
```
