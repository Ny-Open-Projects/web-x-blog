## RBL-537：静态资源的资源模块管线：hash 命名、内联阈值与预加载提示

**答**：
- 资源模块（图片/字体/wasm）的管线三决策：
- 1) **hash 命名**：`[name].[contenthash][ext]`——内容 hash（长效缓存的前提）；hash 要**稳定**（同内容同 hash 跨构建）且**抗碰撞**（短 hash 的碰撞概率评估：8 位 hex 的 2^32 空间在万级资源下碰撞概率 ~0.00001%——够用）。
- 2) **内联阈值**：小于阈值（如 4KB）的图片内联 data URL（省请求）——阈值权衡：内联过多撑大 JS/HTML（浏览器解析 data URL 比 http 慢且无法独立缓存）。
- 3) **预加载提示**：关键资源（首屏字体/关键图）生成 `<link rel=preload>`——构建器从「入口依赖分析」推断关键资源；字体 preload 的 crossorigin 坑（必须加否则重复下载）。
- 资源的引用完整性：hash 命名后「引用方同步更新」——CSS url()/JS import 的引用替换是资源管线的正确性关键（漏替换 = 404）——产物一致性校验（RBL-626 正确性工程）覆盖。
- 追问钩子：字体子集化与资源管线的联动——构建期按「页面实际用到的字符」子集化字体（unicode-range 分片）——资源模块管线的增值处理（不只是拷贝）。

```javascript
// 资源模块管线三决策
const ASSET_PIPELINE = {
  hash命名: {
    format: '[name].[contenthash][ext]——内容 hash = 长效缓存前提',
    stability: '同内容同 hash 跨构建稳定',
    collision: '8 位 hex 万级资源碰撞 ~1e-5%——够用',
  },
  内联阈值: {
    default: '<4KB 内联 data URL（省请求）',
    tradeoff: '内联过多撑大 JS/HTML——data URL 无法独立缓存且解析慢',
  },
  preload: {
    infer: '从入口依赖分析推断关键资源 → <link rel=preload>',
    pitfall: '字体 preload 必须 crossorigin 否则重复下载',
  },
  引用完整性: 'hash 命名后引用方同步替换（CSS url/JS import）——漏替换=404；产物一致性校验覆盖',
  增值处理: '构建期字体子集化（unicode-range 分片）——资源管线不止拷贝',
}
```
