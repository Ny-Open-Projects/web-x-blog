## RBL-165：增量构建的输入指纹（hash key）怎么设计才不踩坑

**答**：
- 指纹要覆盖"所有影响产物的输入"：源码（含目标包依赖的包源码）、构建配置、lockfile、环境变量、工具版本、模板/静态资源。少一项 → 缓存命中但产物过期（最危险）；多一项 → 无谓 miss（只是慢）。
- hash 粒度：文件级 hash（内容 sha256）比 mtime 可靠（git clone 后 mtime 全变）；目录树 hash 用"路径+内容"的组合序列化。
- 隐藏输入最难防：环境变量（NEXT_PUBLIC_*）、日期戳（build time 注入产物会让指纹永远变）、随机 ID；处理方式是显式声明白名单、把时间戳排除在指纹外但接受产物 hash 变化。
- 工具内 vs 工具外：Rspack 的持久化缓存管"单次构建内的模块级复用"，turbo/nx 管"跨次构建/跨机器的任务级复用"，两级 key 语义不同别混谈。
- 追问钩子：验证 key 设计靠"反证"——故意改一个应失效的输入看是否 miss，改一个无关文件看是否命中（key 回归测试）。

```javascript
// scripts/build-fingerprint.mjs —— 包级指纹计算
import { createHash } from 'node:crypto';
import { readFileSync, readdirSync, statSync } from 'node:fs';
import { join, relative } from 'node:path';

function treeHash(dir, base, h = createHash('sha256')) {
  for (const e of readdirSync(dir, { withFileTypes: true }).sort((a, b) => a.name.localeCompare(b.name))) {
    const p = join(dir, e.name);
    if (e.isDirectory()) { treeHash(p, base, h); continue; }
    h.update(relative(base, p)); h.update(readFileSync(p)); // 路径 + 内容，排序稳定
  }
  return h;
}
export function fingerprint(pkgDir, { envKeys = [], toolVersion }) {
  const h = treeHash(pkgDir, pkgDir);
  h.update(readFileSync('pnpm-lock.yaml'));            // lockfile 全局影响
  h.update(toolVersion);                                // 构建工具版本
  for (const k of envKeys) h.update(`${k}=${process.env[k] ?? ''}`); // 显式声明的 env
  return h.digest('hex').slice(0, 16);
}
// 排除清单：__tests__/**、*.spec.*、README —— 不影响产物的不进指纹（inputs 负 glob）
```
