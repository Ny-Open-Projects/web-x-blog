## RBL-513：增量编译的三级粒度：文件级、模块级、图级

**答**：
- 增量编译的粒度阶梯（越细越快、正确性越难）：
- **文件级**：变更文件重新读+转换——最粗，实现简单，但下游全量重算。
- **模块级**：变更模块重转换 + **受影响下游失效**（依赖图反向遍历）——Rspack/Turbopack 的主粒度；关键数据结构是「反向依赖索引」（module → importers）。
- **图级**：模块图结构本身的增量更新（节点/边增删不重建图）+ chunk 复用（未变更 chunk 产物直接复用）——最细，Turbopack 的持久化任务图（Turbopack 的核心卖点：函数级持久缓存）。
- 失效传播的正确性难点：**传递性失效**（A 变 → B（import A）失效 → C（import B）失效）——必须沿反向边递归，但「副作用模块」（CSS 全局注入/patch 全局对象）的失效传播语义要保守处理（宁可多失效不可漏）。
- 粒度选择的工程判断：dev 场景追求图级（反馈 <100ms），build 场景用模块级（正确性优先，全量 chunk 重建成本低）。
- 追问钩子：「为什么 Turbopack 的增量可以做到函数级？」——任务级缓存（每个编译函数的输入指纹+输出缓存，输入不变直接复用）——这是「把构建编译成任务图再增量执行」的架构，与 Rspack「增量事件驱动」是两种流派。

```javascript
// 增量编译三级粒度
const INCREMENTAL_GRANULARITY = {
  文件级: '变更文件重读+转换，下游全量——粗但简单',
  模块级: {
    core: '变更模块重转换 + 反向依赖索引失效传播',
    correctness: '传递性失效递归（A→B→C）+ 副作用模块保守多失效',
    users: 'Rspack / Turbopack 主粒度',
  },
  图级: {
    core: '图结构增量更新（节点/边增删）+ chunk 产物复用',
    users: 'Turbopack 持久化任务图（函数级：输入指纹+输出缓存）',
  },
  选择: 'dev 追求图级（反馈<100ms）；build 用模块级（正确性优先）',
  两流派: 'Turbopack「编译成任务图再增量执行」 vs Rspack「增量事件驱动」',
}
```
