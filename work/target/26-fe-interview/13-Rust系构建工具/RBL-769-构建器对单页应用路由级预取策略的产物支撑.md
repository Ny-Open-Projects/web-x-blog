## RBL-769：路由级预取的产物支撑：路由清单、预取预算与空闲调度

**答**:
- 路由级预取（SPA 导航提速）需要构建器提供三样东西：1) **路由 → chunk 映射清单**（路由懒加载的 import 映射，RBL-627 glob 展开的产物化——运行时查表预取）；2) 预取预算（并发上限 + 每会话总预算，防预取挤占当前页带宽）；3) 空闲调度（requestIdleCallback + navigator.connection 判断——弱网/省流模式禁预取）。
- 预取策略分级：hover 意图（鼠标停留 100ms 预取——意图最强）、视口内链接（IntersectionObserver 批量预取）、空闲全量（低优先级）——预算在三级间共享，hover 预取可抢占空闲预取。
- 预取与缓存的配合：预取的 chunk URL 是 hash 产物（RBL-598）——预取结果进入 HTTP 缓存（immutable 长缓存），导航时直接命中；预取失败的静默处理（不打扰用户，导航时正常加载）。
- 数据预取与代码预取的分层：路由的「数据预取」（API 请求提前）比代码预取更值钱（串行时间更长）——但数据预取需要「路由数据需求清单」（框架 loader 元数据），构建器提供 chunk 清单、框架提供数据清单。
- 追问钩子：为什么预取要「预算 + 调度」而不是「能预取就预取」？——无预算预取在移动端造成流量浪费与带宽竞争（预取的 chunk 与当前页交互请求抢带宽，交互延迟反而上升）；「预取的价值 = 概率 × 收益 − 成本」，预算与调度是这个公式的工程化表达。

```javascript
// 路由预取调度器
const ROUTES = window.__ROUTE_MANIFEST__;               // 构建器注入：path -> chunk url[]

function createPrefetcher({ budgetKB = 300, concurrency = 3 } = {}) {
  const used = new Set(); let usedKB = 0; const queue = [];
  const canFetch = () =>
    navigator.connection?.saveData !== true &&
    (navigator.connection?.effectiveType ?? '4g') !== 'slow-2g';

  function prefetch(url, priority) {
    if (used.has(url) || usedKB > budgetKB || !canFetch()) return;
    used.add(url);
    const link = document.createElement('link');
    link.rel = priority === 'hover' ? 'preload' : 'prefetch';   // hover 高优先
    link.href = url; link.as = 'script';
    link.onload = link.onerror = () => {};
    document.head.appendChild(link);
  }
  // hover 意图（100ms 阈值）
  document.addEventListener('mouseover', debounce(e => {
    const route = routeOf(e.target.closest('a'));
    ROUTES[route]?.forEach(u => prefetch(u, 'hover'));
  }, 100));
  // 空闲全量（低优先级）
  requestIdleCallback(() =>
    Object.values(ROUTES).flat().forEach(u => prefetch(u, 'idle')));
  return { prefetch };
}
```
