## RBL-193：笔试：手写缓存预热脚本（main 分支定时构建灌缓存）

**题目**：写 warm-cache.mjs：1) 背景：PR 构建全 miss 很慢，策略是 main 分支每天定时构建一次把 turbo/构建缓存"灌热"；2) 输入：包列表与最近 N 天各包被 PR 触达次数（影响度权重）；3) 只预热影响度 ≥ 阈值的包（冷门包不值得占缓存）；4) 预热执行 = 在 main 最新 commit 上逐包跑 build，吞掉所有错误（预热失败不告警），但统计成功数；5) 输出预热报告并清理超过 TTL 的缓存条目（本地演示为删除目录）。

```javascript
// warm-cache.mjs
import { execSync } from 'node:child_process';
import { readdirSync, rmSync, statSync } from 'node:fs';
import { join } from 'node:path';

export function warmCache(pkgs, { minHits = 3, cacheDir = '.turbo/cache', ttlDays = 14 } = {}) {
  const sorted = [...pkgs].sort((a, b) => b.hits - a.hits);
  const targets = sorted.filter(p => p.hits >= minHits);

  const results = [];
  for (const p of targets) {
    try {
      const t0 = performance.now();
      execSync(`pnpm --filter ${p.name} build`, { stdio: 'ignore' }); // 失败会抛
      results.push({ pkg: p.name, ok: true, ms: Math.round(performance.now() - t0) });
    } catch {
      results.push({ pkg: p.name, ok: false }); // 预热失败静默：main 本身坏了不该由预热报
    }
  }
  // TTL 清理：按目录 mtime，超过 ttlDays 的缓存条目删除，防缓存目录无限膨胀
  let evicted = 0;
  const cutoff = Date.now() - ttlDays * 86_400_000;
  for (const e of readdirSync(cacheDir)) {
    const full = join(cacheDir, e);
    if (statSync(full).mtimeMs < cutoff) { rmSync(full, { recursive: true }); evicted++; }
  }
  const ok = results.filter(r => r.ok);
  return { warmed: ok.length, skipped: pkgs.length - targets.length,
    totalMs: ok.reduce((s, r) => s + r.ms, 0), evicted, results };
}
// 定时触发（GitHub Actions cron）：
// on: { schedule: [{ cron: '0 2 * * *' }] }
// jobs.warm: steps: [checkout main, pnpm install, node warm-cache.mjs]
```
**评分点**：
- 影响度阈值筛选（冷门包不占缓存容量，体现容量意识）。
- 预热失败静默吞错但统计（预热是尽力而为）。
- TTL 按 mtime 淘汰防膨胀。
- 能说明"定时灌缓存"解决的是 PR 首 build 全 miss 的体验问题。
- 与远程缓存配合：预热脚本本身也应走远程缓存（重复预热秒过）。
