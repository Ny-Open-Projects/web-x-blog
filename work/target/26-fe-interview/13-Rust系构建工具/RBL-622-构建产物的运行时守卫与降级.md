## RBL-622：构建产物的运行时守卫：产物自校验与不兼容降级

**答**：
- 产物在浏览器里跑挂的原因常不是代码 bug 而是组合错误：chunk 加载顺序错（旧 html 引新 chunk）、CSP 拦截动态 import、宿主环境不支持某特性（老 WebView 遇 optional chaining）。运行时守卫 = 产物内嵌的自检与降级逻辑。
- 守卫层次：1) **特性探测**（feature detect 而非 UA sniff）：入口处探测关键特性（fetch/IntersectionObserver/ES2020 语法）→ 失败走降级 bundle（构建器产出 legacy 双包 + browserslist 配套）；2) **chunk 完整性**：动态 import 失败时（chunk 404/网络断）触发「版本刷新」提示——检测 import error 是否为 ChunkLoadError 类，自动 location.reload 一次（带防循环标记 sessionStorage）；3) **CSP 守卫**：document CSP 头检测（提前发现会被拦的动态路径）。
- legacy 双包方案的构建器配套：同一入口产 modern + legacy 两份产物（modern: ES2019+，legacy: 经 Babel/降级 + polyfill），html 用 `type="module" nomodule` 双 script 分发——构建器的正确性在于「两份产物的行为一致性」（同一测试集两边都跑）。
- 降级决策的位置哲学：能编译期解决的绝不运行时（编译目标覆盖浏览器矩阵）；运行时守卫只处理「部署组合」类问题（chunk 404/版本错配）——把运行时当兜底而不是万能。
- 追问钩子：ChunkLoadError 的自动 reload 为什么只能一次？——无限 reload 会造成「刷新风暴」（CDN 缓存未更新时所有用户循环刷新）；防循环标记 + 服务端健康检查配合才是完整方案。

```javascript
// 入口守卫模板
(async function boot() {
  // 1) 特性探测：不过关 -> 加载 legacy 包
  if (!('fetch' in window) || typeof IntersectionObserver === 'undefined') {
    loadScript('/legacy-entry.js');                      // nomodule 包
    return;
  }
  // 2) chunk 加载失败：一次性刷新
  window.addEventListener('error', (e) => {
    if (!/ChunkLoadError|Failed to fetch dynamically imported module/.test(e.message)) return;
    const k = 'chunk_reload_' + location.href;
    if (sessionStorage.getItem(k)) return;               // 防循环
    sessionStorage.setItem(k, '1');
    location.reload();
  });
  // 3) 启动主应用（dynamic import 走 chunk 分发）
  import('./main.' + MANIFEST.main + '.js').catch(showFatalPage);
})();

// 构建器双包产出（配置视角）
// target: { modern: 'es2019', legacy: ['defaults', 'not dead'] }
// html 注入：<script type="module" src="modern.js"></script>
//           <script nomodule src="legacy.js"></script>
```
