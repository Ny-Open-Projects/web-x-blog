## RBL-489：手写 CI 失败自动归因
**答**：实现 `attributeFailure(failedRun, history)`：1) 分类决策树：编译错误（代码问题 → 归因到变更 commit）/基础设施（runner OOM/网络——归因到平台）/flaky（重跑通过——归因到测试稳定性）/配置错误（变更 config 的 commit）；2) 证据链：变更 commit 的 diff 与失败输出的关联（改了 X 模块 → X 模块测试失败——直接因果）；3) flaky 判定：重跑策略（同任务重跑 2 次——2 次同失败=真失败，1 过 1 败=flaky）；4) 输出 { category, culprit: commit?, confidence, evidence }；5) 归因准确率追踪（人工确认 vs 自动归因——分类器校准）。

```javascript
export async function attributeFailure(failedRun, history, { rerun = (t) => Promise.resolve('pass') } = {}) {
  const failed = failedRun.failedTasks[0]

  // 1. flaky 判定：重跑
  const reruns = await Promise.all([rerun(failed.task), rerun(failed.task)])
  const flaky = reruns.some((r) => r === 'pass') && reruns.some((r) => r === 'fail')
  if (flaky) return { category: 'flaky', culprit: null, confidence: 0.9,
    evidence: `重跑 ${reruns} —— 测试稳定性问题` }

  // 2. 基础设施特征
  if (/OOM|killed|out of memory/i.test(failedRun.output))
    return { category: 'infra', culprit: null, confidence: 0.85,
      evidence: 'OOM 特征输出 → runner 资源问题' }
  if (/ECONNRESET|ETIMEDOUT|socket hang up/i.test(failedRun.output))
    return { category: 'infra', culprit: null, confidence: 0.8, evidence: '网络错误特征' }

  // 3. 变更关联：变更文件 ∩ 失败任务的输入文件
  const changed = failedRun.commitFiles ?? []
  const overlap = failed.task.inputFiles?.filter((f) => changed.includes(f)) ?? []
  if (overlap.length)
    return { category: 'code', culprit: failedRun.commit, confidence: 0.9,
      evidence: `变更文件与失败输入交集: ${overlap.slice(0, 3)}` }

  // 4. 配置变更
  if (changed.some((f) => /config|\.rc/.test(f)))
    return { category: 'config', culprit: failedRun.commit, confidence: 0.7,
      evidence: '配置文件在变更集内' }

  return { category: 'unknown', culprit: null, confidence: 0.3, evidence: '无明确信号' }
}
```
**评分点**：
- 决策树优先级（flaky 重跑先判——最便宜的判定先做）
- 证据链归因（变更集 ∩ 失败输入——不是猜是证）
- 基础设施特征识别（OOM/网络错误的输出特征）
- 置信度分级 + 准确率校准（归因器自身的可信度追踪）
