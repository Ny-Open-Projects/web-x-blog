## RBL-858：迁移复盘：决策会的组织形式——技术评审会如何避免「嗓门决定论」

**答**:
- 迁移决策会的失效模式：会前无材料（现场讨论变成观点对撞）、权威偏好（资深者的历史经验压倒数据）、群体沉默（反对者不发言事后才爆雷）。结构化改造：1) **会前材料先行**（RFC 文档 + 基准数据提前 3 天发出，会上只讨论异议——「会前沉默 = 默认同意」规则）；2) 证据分级发言（数据 > 复现案例 > 偏好——偏好类发言自动降权记录）；3) 异议登记制（反对意见必须落 RFC 评论，形成 ADR 的否决理由记录 RBL-671）。
- 决策的输出规范：ADR（动机/选项/取舍/决策/否决理由/回访条件）——「回访条件」让决策可逆（触发条件成立时重新评估，而不是一条道走到黑）。
- 会的规模控制：决策会 ≤ 8 人（相关方代表），利益相关者书面参与——大会讨论变表演；「决策者」明确到人（集体决策 = 无人负责）。
- 会后执行的可追溯：决策 → 任务/里程碑（负责人 + 日期），决策会的产出不是「共识的感觉」而是可检查的承诺。
- 追问钩子：为什么「会前材料 + 异议登记」能消解权威偏好？——会前材料给了低资历工程师平等的准备时间（数据在自己的 benchmark 里跑过）；异议登记把「会上不敢说」变成「书面可以说」（书面表达的心理门槛低且留痕）——机制替代了「会议勇气」，这与 RFC 流程（RBL-671）的组织心理学基础相同。

```javascript
// 决策会结构化模板
const RFC_REVIEW = {
  preWork: { rfcDeadline: 'T-3d', commentsRequired: true,
    rule: '会前无异议 = 默认同意（书面留痕）' },
  agenda: ['异议讨论（按证据分级）', '回访条件设定', '决策者拍板', '行动项登记'],
  evidenceRanking: ['benchmark-data', 'repro-case', 'experience', 'preference'],
};
function structureMeeting(rfc) {
  const blockers = rfc.comments.filter(c => c.type === 'objection');
  return {
    canDecide: rfc.comments.length > 0 && rfc.data.attached,   // 有材料 + 有讨论
    objections: blockers.map(b => ({ by: b.author, evidence: b.evidenceLevel })),
    revisitCondition: rfc.revisit ?? '触发 kill criteria 时（RBL-842）',
    actionItems: rfc.nextSteps.map(s => ({ ...s, owner: s.owner ?? 'REQUIRED' })),
  };
}
```
