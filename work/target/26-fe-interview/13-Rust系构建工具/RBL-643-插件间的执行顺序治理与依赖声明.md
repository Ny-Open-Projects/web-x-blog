## RBL-643：插件间执行顺序的治理：enforce 语义、依赖声明与显式拓扑

**答**:
- 插件顺序是语义问题不是注册顺序问题：`@vitejs/plugin-react`（transform）必须在自定义 babel 插件前跑；alias 插件必须在其他 resolve 前。Vite 的方案是 **enforce: 'pre'|'post'** 三段式（pre → 内置核心 → normal → post），rollup 依赖注册序——两者都无法表达「A 必须在 B 前」的精确依赖。
- 精确治理方案：插件声明 `before: ['plugin-b']` / `after: ['plugin-a']`，调度器做**拓扑排序**；声明缺失时按注册序（兼容），冲突时（循环依赖）报错并保持注册序回退。这是把「隐式顺序约定」升级为「显式依赖图」——大团队插件池（几十个插件）的必经之路。
- 顺序契约的可观测：构建日志输出「插件执行顺序表」（每个钩子的最终顺序），让顺序问题可诊断；插件冒烟测试建议：把插件池随机 shuffle 跑十次，产物一致才算「顺序无隐藏依赖」——这是发现隐式顺序依赖的有效手段（类似测试的 property testing）。
- 内置核心的顺序固定点：resolve 内置解析在 pre 之后 normal 之前；virtual 模块协议（\0）优先于一切包解析——这些「硬序」不受用户插件影响，文档要显式列出。
- 追问钩子：为什么「enforce 三段式」不够？——同段内多插件的顺序仍靠注册序（全局状态耦合），A 团队改注册顺序就破坏 B 团件的插件；before/after 声明把耦合局部化到直接相关者，改动的影响面可推导。

```javascript
// 插件顺序：enforce 分段 + before/after 拓扑
function orderPlugins(plugins, { core = [] } = {}) {
  const seg = (p) => p.enforce === 'pre' ? 0 : p.enforce === 'post' ? 2 : 1;
  const groups = [[], [...core], [], []];                // pre, core, normal, post
  for (const p of plugins) groups[seg(p)].push(p);

  const topo = (list) => {                               // 组内拓扑
    const byName = new Map(list.map(p => [p.name, p]));
    const done = new Set(), out = [], visiting = new Set();
    const visit = (p) => {
      if (done.has(p.name)) return;
      if (visiting.has(p.name)) throw new Error(`插件顺序环: ${p.name}`);
      visiting.add(p.name);
      for (const b of p.after || []) if (byName.has(b)) visit(byName.get(b));
      out.push(p); done.add(p.name); visiting.delete(p.name);
      // before 声明：把依赖者排到自己前
    };
    // 简化：只处理 after；before 反向建边等价
    list.forEach(visit);
    return out;
  };

  return [topo(groups[0]), groups[1], topo(groups[2]), topo(groups[3])].flat();
}

// 顺序稳定性验证：shuffle 十次产物一致
async function orderStable(buildFn, plugins) {
  const results = new Set();
  for (let i = 0; i < 10; i++) {
    const shuffled = shuffle(plugins);
    results.add(await buildFn(orderPlugins(shuffled)));
  }
  return results.size === 1;                             // true = 无隐藏顺序依赖
}
```
