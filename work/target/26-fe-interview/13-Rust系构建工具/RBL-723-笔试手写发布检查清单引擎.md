## RBL-723：笔试：手写发布检查清单引擎（前置依赖 + 短路失败 + 汇总报告）

**答**：实现 `runChecklist(checks)`。checks: `{ id, name, run() -> Promise<{ ok, detail? }>, requires?: string[] }[]`（requires 是前置 check id）。规则：1) 前置失败的检查跳过（status 'skipped-by-dep'，注明依赖）；2) 无依赖的检查并行执行、有依赖的等前置完成；3) 任一 'blocking' 检查失败 → 尚未开始的检查不再启动（短路），已开始的等完成；4) 返回 `{ results: Record<id, { status: 'passed'|'failed'|'skipped-by-dep'|'not-started', detail? }>, ok }`（ok = 无 failed）；5) 环形 requires 抛错。

```javascript
function runChecklist(checks) {
  const byId = new Map(checks.map(c => [c.id, c]));
  // 环检测
  const visit = (id, stack) => {
    if (stack.includes(id)) throw new Error('前置环: ' + [...stack, id].join(' -> '));
    for (const r of byId.get(id)?.requires || []) visit(r, [...stack, id]);
  };
  checks.forEach(c => visit(c.id, []));

  const results = {};
  let shortCircuit = false;
  const runOne = async (c) => {
    // 前置
    for (const dep of c.requires || []) {
      const d = results[dep];
      if (!d || d.status !== 'passed') {
        results[c.id] = { status: 'skipped-by-dep', detail: `前置 ${dep} 未通过` };
        return;
      }
    }
    if (shortCircuit) { results[c.id] = { status: 'not-started' }; return; }
    try {
      const r = await c.run();
      results[c.id] = r.ok ? { status: 'passed' } : { status: 'failed', detail: r.detail };
      if (!r.ok && c.blocking) shortCircuit = true;
    } catch (e) {
      results[c.id] = { status: 'failed', detail: e.message };
      if (c.blocking) shortCircuit = true;
    }
  };

  return (async () => {
    // 拓扑分批执行
    let remaining = [...checks];
    while (remaining.length) {
      const ready = remaining.filter(c => (c.requires || []).every(d => results[d]));
      if (!ready.length) break;
      await Promise.all(ready.map(runOne));
      remaining = remaining.filter(c => !ready.includes(c));
    }
    remaining.forEach(c => { if (!results[c.id]) results[c.id] = { status: 'not-started' }; });
    return { results, ok: !Object.values(results).some(r => r.status === 'failed') };
  })();
}

// 自测
const mk = (id, blocking, deps, run) => ({ id, name: id, blocking, requires: deps, run });
const checks = [
  mk('build', true, [], async () => ({ ok: true })),
  mk('test', true, ['build'], async () => ({ ok: false, detail: '2 tests failed' })),
  mk('bench', false, ['build'], async () => ({ ok: true, detail: 'p50 890ms' })),
  mk('docs', false, ['test'], async () => ({ ok: true })),
];
const { results, ok } = await runChecklist(checks);
console.log(results.build.status === 'passed');
console.log(results.test.status === 'failed');
console.log(results.bench.status === 'passed');          // 并行完成
console.log(results.docs.status === 'skipped-by-dep');   // 前置失败跳过
console.log(ok === false);

// 短路：blocking 失败后未开始的不再启动
const c2 = [
  mk('a', true, [], async () => ({ ok: false })),
  mk('b', false, ['a'], async () => ({ ok: true })),
  mk('c', false, [], async () => ({ ok: true })),
];
const r2 = await runChecklist(c2);
console.log(r2.results.c.status === 'passed' || r2.results.c.status === 'failed');
console.log(r2.results.b.status === 'skipped-by-dep');
```

**评分点**：
- 拓扑分批执行正确（无依赖并行、有依赖等前置）；前置失败跳过并注明原因
- blocking 失败短路（未开始的标 not-started，已开始等完成——不悬挂）
- 环检测先行；ok 语义 = 无 failed（skipped 不算失败但阻止 ok 路径下游）
- 能说清「发布门禁的并行执行缩短反馈、短路节省资源」属于加分
