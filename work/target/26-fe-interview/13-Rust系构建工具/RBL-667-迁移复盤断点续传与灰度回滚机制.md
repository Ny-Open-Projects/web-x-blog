## RBL-667：迁移复盘：双构建器的并行期管理、断点续传与灰度回滚

**答**:
- 大迁移不能「一刀切」：并行期（旧构建器与新构建器同时可用）是风险缓冲——dev 用新、CI 用旧（或相反）跑两周，对比产物语义与构建时间后切换；切换用 flag（build-tool=rspack）控制，回滚 = 改回 flag。
- 断点续传：迁移是长周期工程（几周），要拆成可独立合并的小步骤：① 配置翻译 PR；② 插件替换 PR；③ 行为测试补齐；④ CI 切换——每步可回退，迁移中断（人员/优先级变化）时文档记录「下一步」，复活成本低。这与卡片生成的心跳断点同构：长任务必须可恢复。
- 灰度机制：同仓库双配置输出（rspack 输出到 dist-rspack）在预发环境对比验证；全量切前先「影子构建」（CI 同时跑两构建器，产物对比报告挂 PR，构建时间只计入旧工具）。
- 复盘产出：迁移复盘文档四要素——预估成本 vs 实际成本（评分卡校准）、遇到的最大坑（往往是冷门插件）、规则库沉淀（下个仓库复用）、度量改善（构建时间曲线前后对比）。
- 追问钩子：为什么并行期最容易出「双版本差异静默漂移」？——两套配置会被人顺手各自改（修 bug 改旧配置忘了新配置），漂移累积；治理是「配置单一来源」（codemod 从旧配置生成新配置并锁定，或反向）+ 差异看板每日报告。

```javascript
// 影子构建 CI 步骤
steps:
  - run: pnpm build --config webpack      # 旧构建（计时基准）
  - run: pnpm build --config rspack --output dist-rspack   # 影子构建
  - run: node scripts/semantic-diff.js dist dist-rspack > diff.md
  - uses: actions/upload-artifact@v4
    with: { name: migration-diff, path: diff.md }
  # 影子期产物对比挂在每个 PR，差异突增即告警

// 双配置一致性守卫：旧配置变更时强制重跑翻译器
function guardConfigDrift() {
  const webpackHash = hashFile('config/webpack.js');
  const lastTranslated = readCache('config/rspack.translated.json');
  if (lastTranslated.sourceHash !== webpackHash)
    fail('webpack 配置已变更，请重跑 codemod 同步 rspack 配置（防双版本漂移）');
}

// 迁移断点文档模板
// ## 迁移状态 2026-11-22
// 已完成：配置翻译（PR#1）、swc-loader 替换（PR#2）
// 下一步：CSS 插件等价物验证（负责人 @x）
// 回滚方式：build-tool=webpack flag
```
