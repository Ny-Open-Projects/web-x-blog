## RBL-592：循环依赖的产物顺序：强连通分量缩点与初始化顺序决定

**答**:
- 循环依赖产物的核心问题：**模块初始化顺序决定哪个模块拿到「未完成的绑定」**——CommonJS 语义里是拿到 partially filled exports，ESM 语义里是 hoisting + live binding 兜底。打包器必须为环内模块选一个执行顺序，选错就是运行时 undefined。
- 算法框架：1) Tarjan/Kosaraju 求**强连通分量**（SCC）——每个环收缩成一个节点；2) SCC 图是 DAG，可拓扑排序；3) 环内部的顺序策略：按「入口优先」（从非环入口进来的第一个模块先执行）> 按 import 关系尽量满足 > 按 ID 稳定排序兜底（保证确定性，同输入同输出）。
- ESM 的优势能力：import 声明提升 + 函数声明提升，使得环内「先执行者」引用后执行者的函数也能跑（绑定是 live 的）；但**顶层执行的副作用**（模块体直接调用对方导出的函数/读非常量导出）会 undefined——诊断器要专门识别这种模式并告警。
- chunk 分割与环的交互：环内模块如果被拆到不同 chunk，跨 chunk 的加载顺序会引入异步时序——打包器一般**禁止分割 SCC**（环整体进同一 chunk），否则 lazy chunk 间的循环引用会死锁（A 等 B 加载完，B 等 A）。
- 追问钩子：如何向用户报告环？——诊断分级：info（无害环，hoisting 保护住了）/ warn（环内顶层副作用，可能 undefined）/ error（环跨 chunk 且无法保证顺序）；webpack 的 Circular dependency warning 过于粗暴（所有环都报），分类分级是工程改进。

```javascript
// Tarjan SCC + 环内排序（概念实现）
function tarjanSCC(graph) {
  const index = new Map(), low = new Map(), stack = [], onStack = new Set();
  const sccs = []; let idx = 0;
  function dfs(v) {
    index.set(v, idx); low.set(v, idx); idx++;
    stack.push(v); onStack.add(v);
    for (const w of graph.edges(v)) {
      if (!index.has(w)) { dfs(w); low.set(v, Math.min(low.get(v), low.get(w))); }
      else if (onStack.has(w)) low.set(v, Math.min(low.get(v), index.get(w)));
    }
    if (low.get(v) === index.get(v)) {               // 根 -> 弹出一个 SCC
      const c = []; let w;
      do { w = stack.pop(); onStack.delete(w); c.push(w); } while (w !== v);
      sccs.push(c);
    }
  }
  graph.nodes().forEach(v => !index.has(v) && dfs(v));
  return sccs;
}

// chunk 分割禁令
for (const scc of tarjanSCC(graph)) {
  if (scc.length > 1) {
    markIndivisible(scc);                            // 环整体同 chunk
    const order = pickOrder(scc, graph);             // 入口优先 -> import 序 -> id 序
    diagnose(scc, order);                            // 分级报告环风险
  }
}
```
