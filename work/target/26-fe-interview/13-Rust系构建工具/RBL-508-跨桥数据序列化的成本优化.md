## RBL-508：跨桥数据序列化的成本优化：批量、瘦身与零拷贝

**答**：
- napi 桥的三档数据传输成本：1) **JSON 字符串**（两端解析，最贵但通用）；2) **结构化对象逐字段转换**（napi 对象 API，中等）；3) **Buffer/ArrayBuffer 零拷贝**（transferable 内存，最便宜）——构建器产物（AST 不跨桥、只传 code+map 字符串）的选型原则：**大字符串走 Buffer，结构化小对象走 napi 对象**。
- 批量优化：每模块回传（N 次跨桥）→ 攒批回传（1 次）——Rspack 的 HMR 增量回传就是批量（一次传本次变更的模块集合）。
- 瘦身优化：桥上只传必要字段——loader 结果只传「变更内容」（未变更模块传引用标记而非内容）；AST 永不跨桥（Rust 侧消费）。
- 零拷贝边界：Buffer 跨桥是引用共享（同一内存）——**Rust 侧持有期间 JS 侧改写会撕裂**——需要「冻结语义」（copy-on-need 或生命周期约束），这是 napi Buffer 的坑点。
- 追问钩子：为什么 Rspack 最终「dev 产物也留在 Rust 侧内存」而不回传全量？——dev server 直接从 Rust 内存 serve（HTTP 层在 JS），产物回传只发生在需要 JS 消费的场景（如 plugin 钩子）——「数据不落地 JS」是终极瘦身。

```javascript
// 跨桥传输的三档成本与优化
const BRIDGE_COST = {
  三档: {
    JSON字符串: '两端解析，最贵但通用（小对象低频可用）',
    napi对象: '逐字段转换，中等（结构化小对象）',
    Buffer零拷贝: 'transferable 共享内存，最便宜（大字符串：code/map）',
  },
  批量: '每模块回传（N 次跨桥）→ 攒批回传（1 次）——HMR 增量即批量',
  瘦身: [
    'loader 只传变更内容（未变更传引用标记）',
    'AST 永不跨桥（Rust 侧消费）',
    'dev 产物留 Rust 内存，HTTP 层直接 serve——「数据不落地 JS」',
  ],
  零拷贝坑: 'Buffer 引用共享——Rust 持有期间 JS 改写会撕裂，需冻结语义',
}
```
