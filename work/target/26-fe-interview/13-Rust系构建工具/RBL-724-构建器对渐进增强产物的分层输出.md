## RBL-724：构建器对渐进增强的产物分层：核心可用层与增强层的构建策略

**答**:
- 渐进增强的产物分层：1) **核心层**（无 JS 也能用：SSR 渲染的 HTML + 原生表单/链接——es5 兼容、零依赖）；2) **增强层**（现代语法 + 交互增强，动态 import）；3) **体验层**（离线/推送等 PWA 特性，SW 注册）。构建器输出对应的多层产物，HTML 用特性检测渐进加载——分层让「基础可用」不依赖「增强成功」。
- 构建策略：核心层与增强层是不同 entry（不同闭包），核心层显式预算（如 ≤50KB，RBL-662 双轨门禁）；增强层失败不影响核心层（错误边界分层：增强失败静默降级到核心交互）。
- 特性检测的构建期辅助：构建器可生成「能力清单」（各层依赖的特性列表），运行时按清单检测决定加载哪层——清单比逐个探测便宜且可审计。
- 降级路径的测试义务：分层产物要求「每层独立可用」的测试（禁用 JS 的爬虫视角测试核心层、弱网测试增强层降级）——分层是承诺，不是注释。
- 追问钩子：为什么分层与「legacy 双包」（RBL-622）不同？——legacy 双包是同一功能的两种语法（行为一致），分层是功能的两个层次（核心功能 vs 增强功能，语义不同）；分层回答「没有 JS/没有新浏览器时产品还能不能用」，双包回答「老浏览器能不能跑」。

```javascript
// 分层产物构建配置
const LAYERS = [
  { name: 'core', entry: 'src/core.ts', target: 'es5', budgetKB: 50,
    rule: '零依赖 + SSR HTML 可交互（原生表单/锚点）' },
  { name: 'enhanced', entry: 'src/enhanced.ts', target: 'es2019',
    loads: '动态 import（特性检测通过后）' },
  { name: 'pwa', entry: 'src/sw.ts', kind: 'service-worker' },
];

// HTML 分层加载（构建器注入模板）
// <link rel="modulepreload" href="core.js">       核心层预载
// <script>
//   if ('IntersectionObserver' in window) import('/enhanced.js')  // 增强层
//     .then(e => e.enhance())                          // 失败静默：核心层已可用
//     .catch(() => {/* 降级到核心交互 */});
// </script>

// 能力清单（构建器输出）
const CAPABILITIES = {
  enhanced: ['IntersectionObserver', 'fetch', 'ES2019'],
  pwa: ['serviceWorker'],
};
function pickLayer() {
  const ok = (list) => list.every(c => capability(c));
  return ['pwa', 'enhanced', 'core'].find(l => l === 'core' || ok(CAPABILITIES[l]));
}
```
