## RBL-465：手写构建产物风险分级发布
**需求**：实现 `classifyReleaseRisk(diff, history)`：1) 风险要素：变更面（模块数/依赖变更/配置变更/新依赖引入）、历史稳定性（最近 5 次同域发布的事故率）、灰度覆盖度（灰度桶用户量）；2) 分级：low（走快速通道：跳过部分门禁）/medium（标准）/high（全量门禁+双人审+延长灰度观察）；3) 分级依据可解释（每级列出触发因子）；4) 与发布流水线联动：high 级自动插入额外门禁（如真机冒烟）；5) 误判反馈：分级与实际事故对比校准（分级器的准确率追踪）。

```javascript
export function classifyReleaseRisk(diff, history) {
  const factors = []
  let score = 0
  if (diff.modules > 50) { score += 2; factors.push(`大变更面 ${diff.modules} 模块`) }
  if (diff.newDeps > 0) { score += 3; factors.push(`新增依赖 ${diff.newDeps} 个`) }
  if (diff.configChanged) { score += 2; factors.push('构建配置变更') }
  if (diff.securityRelated) { score += 4; factors.push('安全相关变更') }

  const recentIncidents = history.slice(-5).filter((h) => h.incident).length
  if (recentIncidents >= 2) { score += 3; factors.push(`近期同域事故 ${recentIncidents} 次`) }

  const level = score >= 6 ? 'high' : score >= 3 ? 'medium' : 'low'
  const pipeline = {
    low: { gates: ['build', 'smoke'], grayHours: 1 },
    medium: { gates: ['build', 'smoke', 'size-budget'], grayHours: 8 },
    high: { gates: ['build', 'smoke', 'size-budget', 'e2e', 'real-device'], grayHours: 48,
      requires: 'double-approval' },
  }[level]

  return { level, score, factors, pipeline,
    note: '分级因子可解释；分级器准确率用「分级 vs 实际事故」回溯校准' }
}
```
**评分点**：
- 多因子加权（变更面/新依赖/配置/安全/历史事故——风险是多维的）
- 分级与流水线联动（high 自动插入额外门禁与灰度时长——分级要产生行为差异）
- 因子可解释（每级列出触发因子——分级不是黑盒评分）
- 校准闭环（分级 vs 实际事故回溯——分级器自身的准确率治理）
