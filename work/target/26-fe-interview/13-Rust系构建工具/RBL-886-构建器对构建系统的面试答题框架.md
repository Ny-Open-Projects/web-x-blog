## RBL-886：构建系统面试答题框架——用不变量组织 3 分钟深度回答

**答**:
- 深水题的答题结构（以「大仓构建优化」为例）：1) **先定性**（这是哪类不变量问题——失效传播/并行调度/缓存键）；2) 再给框架（分层方案：测量 → 归因 → 定向优化 → 复测——RBL-587 的方法论）；3) 场景翻译（不变量在具体场景的落点）；4) 主动边界（这个方案的失效条件/权衡）——四段结构让回答「有骨架有深度有自知」。
- 「主动边界」是区分高级与初级的信号：初级给方案，高级给方案的适用域——每个方案的失效条件（并发优化的内存上限/缓存的污染风险）是深度讨论的入口，也是面试官追问的预判。
- 场景题的「不变量映射表」：拿到场景先映射「考的是哪个不变量」（上传场景 = 懒加载边界 + Worker 隔离；微前端 = 隔离与共享的权衡；迁移 = 语义等价验证）——映射对了，答题框架自动就位；映射错了（把迁移题答成工具介绍）整题崩塌。
- 反模式清单：背工具文档（「rolldown 是 Rust 写的所以快」——为什么快才是题眼）、罗列没有决策（10 个优化点并列没有优先级）、无数据的断言（「会快很多」）。
- 追问钩子：为什么「先定性再翻译」的顺序不能反？——先说场景细节会让回答发散（面试官跟着细节走）；定性（不变量）让面试官立即校准「你懂原理」，后续场景只是举例——认知框架先行是深度对话的引导术，与 RBL-850「不变量投资」的学习策略同源。

```javascript
// 答题框架模板
const ANSWER_FRAME = {
  step1: (q) => `定性：本题考 ${invariantOf(q)} 不变量`,       // 失效传播/并行/缓存/隔离/语义等价
  step2: () => '框架：测量 → 归因 → 定向优化 → 复测（RBL-587）',
  step3: (q) => `场景落点：${scenarioMapping(q)}`,             // 不变量在场景的具体形态
  step4: (plan) => `边界：${plan.failConditions}`,             // 方案失效条件与权衡
};
const invariantOf = (q) =>
  /增量|热更新|HMR/.test(q) ? '失效传播'
  : /秒开|体积|分包/.test(q) ? 'chunk 分割与缓存粒度'
  : /微前端|隔离/.test(q) ? '隔离与共享权衡'
  : /迁移|升级/.test(q) ? '语义等价验证'
  : '依赖图与并行调度';
// 反模式自检
const ANTI = ['背工具文档', '罗列无决策', '无数据断言', '先讲细节后定性'];
```
