## RBL-901：综合深水：一次完整构建的全链路解剖——从按键到落盘的 12 阶段

**答**:
- 全链路 12 阶段（把本目录知识串成时间线）：1) 配置加载与校验（575/576）；2) 插件池初始化与排序（644）；3) 入口解析与模块图构建（591 BFS 发现）；4) 逐模块 resolve（737 四级缓存）；5) load/transform 管线（610 分层 pass、rayon 并行 560）；6) 语义分析（559 OXC scope/symbol）；7) tree shaking 与 DCE（594）；8) chunk 分割（596/597 + SCC 约束 592）；9) 产物生成与级联 hash（598/599）；10) sourcemap 链合并（608）；11) 原子落盘（583/584）；12) 缓存刷盘与遥测上报（799/679）。
- 每阶段的「失效点」：12 阶段各有代表性故障（配置错误→1 阶段诊断、循环依赖→3 阶段 SCC、语义错→5/7、hash 错→9、半成品→11）——故障定位先按阶段归类再深入（RBL-831 模式化）。
- 阶段间的数据契约：模块图 → chunk 分割 → 级联 hash → 落盘，上一阶段的输出是下一阶段的输入——「跨阶段的数据流」是构建器可观测性 trace（RBL-728 span 树）的结构依据。
- 性能视角的阶段占比：典型大仓 resolve 30-40%、transform 30%、chunk+codegen 20%、IO 10%（RBL-739 归因）——优化按占比排序。
- 追问钩子：为什么「全链路时间线」是构建工程师的心智模型基础？——所有专题知识（缓存/并行/失效）都附着在时间线的某个阶段上；面试深水题（「构建突然慢了怎么排查」）的第一反应就是「哪个阶段慢了」——trace 分阶段计时（RBL-728）是这 12 阶段的仪表化，心智模型与工具互为表里。

```javascript
// 12 阶段的 trace span 结构（RBL-728 应用）
const PIPELINE_SPANS = [
  'config.load', 'plugin.init', 'graph.discover', 'resolve',
  'transform', 'semantic', 'tree-shake', 'chunk.split',
  'codegen+hash', 'sourcemap', 'flush', 'telemetry',
];
function buildTraceRoot(buildId, ctx) {
  return {
    name: 'build', buildId, commit: ctx.commit,
    spans: PIPELINE_SPANS.map(name => ({ name, children: [] })),   // 阶段骨架预建
  };
}
// 故障按阶段归类
const STAGE_FAILURES = {
  'resolve': ['RBL1001', '循环依赖', 'exports 封装'],
  'transform': ['插件抛错', '语法降级失败'],
  'chunk.split': ['SCC 拆散告警', 'TLA 传染'],
  'codegen+hash': ['级联 hash 不确定', '重复 chunk'],
  'flush': ['原子切换失败', '缓存写入失败'],
};
```
