## RBL-551：插件系统的钩子设计与执行模型：Tapable 式 vs trait 式

**答**：
- 插件系统的两个流派：
- **Tapable 式（webpack/Rspack JS 插件）**：钩子是「事件发射器 + 订阅者队列」——`compiler.hooks.emit.tap(plugin, fn)`；支持同步/异步/并行/瀑布（SyncHook/AsyncSeriesWaterfall）等钩子类型；灵活但调度成本高（每钩子一次 JS 调用链）。
- **trait 式（Rust 原生插件）**：插件实现 trait（`trait Plugin { fn transform(&self, ...) }`）——编译期静态分发（零调度开销），但灵活性低（编译时固定）。
- Rspack 的混合：**JS 插件（兼容 webpack）+ Rust 内建插件（高频钩子内建）**——高频钩子（每模块 transform）用 trait 批量处理，低频钩子（构建开始/结束）走 JS。RBL-507 双栈策略在插件层的落地。
- 钩子设计的三原则：1) **钩子数量收敛**（10 个以内高频钩子——每钩子都是维护与兼容负担）；2) **上下文最小化**（钩子参数只给需要的——大 context 的克隆成本）；3) **错误语义明确**（插件抛错 → 构建失败但给出插件名与阶段）。
- 追问钩子：插件钩子的「版本兼容策略」——钩子签名变更 = 插件生态 breaking——策略：钩子只增不改 + deprecated 过渡期 + 语义化版本（插件声明兼容范围）。

```javascript
// 插件系统两流派
const PLUGIN_MODELS = {
  tapable: {
    model: '事件发射器 + 订阅者队列（SyncHook/AsyncSeriesWaterfall 等钩子类型）',
    pros: '灵活（运行时注册/异步）',
    cons: '调度成本（每钩子 JS 调用链）',
  },
  trait: {
    model: 'Rust trait 静态分发',
    pros: '零调度开销',
    cons: '编译期固定，灵活性低',
  },
  rspack混合: '高频钩子（每模块 transform）trait 批量 + 低频钩子（构建开始/结束）JS——507 双栈落地',
  三原则: ['钩子数量收敛（≤10 高频）', '上下文最小化（克隆成本）', '错误语义明确（插件名+阶段）'],
  版本兼容: '钩子只增不改 + deprecated 过渡 + 插件声明兼容范围',
}
```
