## ARC-596：上传队列持久化与恢复
**答**:
- 场景：多文件批量上传（网盘/素材库）跨页面切换/浏览器重启——队列与分片进度不能丢（ARC-377 大文件链路的队列层）。
- 队列模型：任务（文件元数据 + 目标路径 + 状态）→ 分片进度（已传分片索引——IndexedDB 持久化）；恢复（启动时读取未完成任务 → 校验文件仍存在 → 分片续传，服务端分片状态配合 ARC-339）。
- 调度策略：全局并发（同时 2~3 个文件活跃——防互相饿死）、优先级（用户拖动排序/紧急上传置顶）、失败重试（分片级重试退避 → 文件级失败原因归类：配额满/格式拒绝——不无限重试）。
- 生命周期 UI：上传面板（全局浮层：进度/速度/暂停/取消/清已完成——跨页面常驻）、完成通知（ARC-394）。
- 边界：文件修改检测（续传前文件 mtime/size 变了 → 重新哈希整个文件——安全优先）、隐私模式（IndexedDB 不可用的降级：内存队列 + 不恢复提示）。
```javascript
// 队列持久化
async function persistQueue() {                                  // 状态变更即持久化
  await idb.put('uploadQueue', tasks.map(t => ({
    ...t, doneChunks: t.doneChunks, fileSig: { size: t.file.size, mtime: t.file.lastModified } })));
}
async function resume() {
  for (const t of await idb.getAll('uploadQueue').filter(t => t.status !== 'done')) {
    if (await fileChanged(t)) t.doneChunks = [];                 // 文件变了重来
    scheduler.enqueue(t);                                        // 分片续传
  }
}
```
