## ARC-554：灰度名单同步与管理
**答**:
- 名单类型：内部名单（员工先体验 ARC-469）、白名单（定向放量：VIP/内测用户）、黑名单（禁灰度：风控敏感用户）、豁免名单（跳过某功能）。
- 同步架构：名单服务（管理台增删 → 版本号递增）→ 分发（端侧：配置中心下发快照 + 增量；服务端：缓存订阅失效广播 NODE-353）→ 使用（分桶判定时名单优先于比例 ARC-403 顺序）。
- 一致性挑战：名单延迟窗口（服务端已生效端侧未更新 → 前后端分桶错位，实验数据污染 ARC-282/285）——策略：分桶判定尽量收口到一端（服务端判定结果下发，端侧只消费）+ 快照版本比对。
- 治理：名单大小限制（万级名单改为规则化：按标签圈人而非逐 ID——名单爆炸不可维护）、变更审计（谁加谁删 NODE-442）、名单过期机制（临时名单自动失效——防永久白名单堆积 ARC-396 思想）。
- 效率：名单查询性能（bitmap/布隆过滤大名单 ARC-ALG）、命中统计（名单使用率——零命中名单清理）。
```javascript
// 名单服务 + 分桶优先级
function resolve(user, exp) {
  if (exp.whitelist.has(user.id)) return 'treatment';            // 1. 白名单优先
  if (exp.blacklist.has(user.id)) return 'control';              // 2. 黑名单排除
  if (isEmployee(user) && exp.internalFirst) return 'treatment'; // 3. 内部名单
  return hashBucket(user.id, exp.salt, exp.rollout);             // 4. 比例放量
}
```
