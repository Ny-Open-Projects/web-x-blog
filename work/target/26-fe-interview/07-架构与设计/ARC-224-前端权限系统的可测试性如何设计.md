## ARC-224：前端权限系统的可测试性如何设计？
**答**：
- 权限逻辑必须**纯函数化**：`can(user, action, resource) → boolean`，输入快照输出布尔，与 UI、路由解耦，才能低成本覆盖组合场景。
- 测试策略：判定引擎用表驱动单测（角色×操作矩阵全覆盖）；路由守卫用快照注入的集成测试；按钮级用 Testing Library 断言 DOM 不渲染。
- 关键回归场景清单：权限边界（恰好有权/恰好无权）、角色叠加与互斥、权限热更后的已渲染页面、菜单与路由不一致的兜底（手输 URL）。
- E2E 上只测"金路径"（管理员能进、访客进不去），矩阵类组合全部下沉单测，否则 E2E 会爆炸。

```typescript
// 纯函数判定引擎：表驱动可测
export function can(snap: PermSnapshot, action: string, resource: string): boolean {
  return snap.perms.includes(`${resource}:${action}`) || snap.perms.includes(`${resource}:*`);
}
// 表驱动单测
const cases = [
  { perms: ['order:read'], action: 'read',   resource: 'order', want: true },
  { perms: ['order:read'], action: 'edit',   resource: 'order', want: false },
  { perms: ['order:*'],    action: 'delete', resource: 'order', want: true },
];
test.each(cases)('$perms $action $resource → $want', ({ perms, action, resource, want }) => {
  expect(can({ tenantId: 't1', role: 'r', perms }, action, resource)).toBe(want);
});
// 路由守卫测试：注入快照 + 手输 URL /admin → 断言重定向 /403 而非白屏
```
