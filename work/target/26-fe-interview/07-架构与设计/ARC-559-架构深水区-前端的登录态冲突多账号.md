## ARC-559：多账号与账号切换架构
**答**:
- 切换的本质：完全环境切换——不是换 token 那么简单（缓存/连接/订阅/未读全是账号维度的，ARC-428 租户切换同理）。
- 切换协议：切换请求 → 服务端新会话 → 前端"重置宇宙"：清内存 store、断开并重建 WS（订阅的是旧账号频道 ARC-416）、清账号维度缓存（IndexedDB 命名空间）、重载页面（最可靠——SPA 热切换容易漏）。
- 多账号并行需求：隔离上下文（B 端多租户场景：不同浏览器容器/独立 Tab 隔离——BroadcastChannel 按账号命名空间，防 A 账号消息串到 B）。
- 最近账号列表：快捷切换（存最近 N 账号的刷新凭证——refresh token 绑设备，安全性评估：敏感场景不做免密切换）。
- 冲突与安全：同设备多账号的会话隔离（HttpOnly cookie 单账号限制下的方案：域名分片或 token in memory + 切换协议）、切换审计（敏感系统记录账号切换事件）。
```javascript
async function switchAccount(targetUid) {
  const s = await auth.switchSession(targetUid);                 // 服务端新会话
  store.resetAll();                                              // 内存全清
  ws.reconnect({ token: s.token });                              // WS 重建（新订阅）
  await idb.clearNamespace(currentUid);                          // 账号维度缓存清
  location.assign(routeAfterSwitch());                           // 重载兜底
}
```
