## ARC-211：联邦模块的预加载与首屏性能优化？
**答**：
- 联邦首屏三段开销：manifest 请求 → remote entry/chunk 加载 → 共享依赖协商加载，任何一段串行都伤首屏。
- 手段一：manifest 预取——HTML 里 prefetch 子应用 manifest（它是小 JSON），把"发现依赖"提前到页面加载期；2.0 的 manifest 支持 preflight 声明首屏需要的 expose 清单。
- 手段二：SSR 直出联邦组件（ARC-205），首屏不依赖客户端联邦加载，客户端只做水合与懒加载非首屏模块。
- 手段三：共享依赖收敛——高频 shared（react/vue）由主应用作为唯一提供方并 requiredVersion 收紧，避免子应用自带导致重复下载；配合 HTTP 缓存与 chunk hash 稳定化。
- 兜底：给 loadRemote 设 SLO（P90 < 800ms），超时走本地 fallback，性能预算进 CI。

```javascript
// 首屏预取编排
const firstScreen = ['shop/Header', 'shop/UserMenu'];
// 1) HTML 注入 manifest 预取（服务端模板）
function prefetchLinks(routes) {
  return Object.values(routes).map(v => `<link rel="prefetch" href="${v}" as="fetch">`).join('');
}
// 2) 首屏模块并行预载（空闲期），非首屏走 IntersectionObserver 懒载
async function warmup() {
  await Promise.all(firstScreen.map(id => loadRemote(id).catch(() => {}))); // 失败静默，运行时兜底
}
requestIdleCallback(warmup);
// 3) 懒加载：const Cart = lazy(() => import('shop/Cart'))，路由级 + 视口级两级触发
```
