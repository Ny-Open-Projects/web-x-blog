## ARC-353：可观测性深水区：告警疲劳如何治理？
**答**：
- 告警疲劳的本质是"告警 ≠ 行动"：值班对高频低价值告警脱敏，真问题被淹没。治理目标是让每条告警都可执行。
- 分级：P0（电话/IM 强提醒，核心可用性 SLO 燃烧）、P1（工作时间处理）、P2（周会巡检）；每级定义响应时效。
- 收敛手段：同源聚合（同一 release/接口的 50 条错误聚成 1 条）、静默窗口（发布后 15 分钟自动静默已知抖动）、依赖抑制（网关挂了抑制下游全部告警）。
- 生命周期管理：每季度审计——零行动告警直接删除或降级；每条告警必须有 Runbook 链接与 owner。
- 度量告警质量本身：告警确认时长（TTA）、告警→事故转化率、每值班周期告警数，作为可观测性平台的北极星。
```javascript
// 告警聚合与抑制规则（平台侧伪码）
rules.push({
  match: { alert: 'js_error', release: currentRelease },
  groupBy: ['errorFingerprint'],           // 指纹聚合：堆栈归一化后分组
  silence: { after: 'deploy', for: '15m' } // 发布静默窗
});
rules.push({
  match: { alert: 'api_p99', dependsOn: 'gateway_down' },
  suppress: true                            // 上游挂了抑制下游延迟告警
});
```
