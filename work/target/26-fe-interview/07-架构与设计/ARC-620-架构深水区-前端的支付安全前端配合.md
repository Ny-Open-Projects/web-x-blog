## ARC-620：支付安全前端配合
**答**:
- 防篡改：下单参数服务端签发（前端不拼金额——ARC-418 红线）、收银台参数 token 化（ARC-598）、提交数据完整性（服务端二次校验——前端只是第一道）。
- 防劫持：HTTPS 强制 + HSTS（ARC-435 头防线）、页面防 iframe 嵌套（X-Frame-Options/frame-ancestors——防点击劫持改单）、关键操作二次确认（支付前展示订单摘要确认——防静默扣款）、JSBridge 安全（白名单方法/来源校验 ARC-077/112）。
- 防重放：请求幂等键（ARC-418）、时间戳+nonce（开放支付 API NODE-458 同款）、一次性支付 token。
- 环境安全：反调试与混淆的定位（防爬/防注入是纵深一层——不作为唯一防线 ARC-158 分级）、运行环境检测（WebView 注入框架检测上报——风控信号 NODE-456）。
- 体验与安全的平衡：安全措施不显著拖慢支付转化（预检在后台并行、二次确认精简）——安全 UX 双指标评估。
```javascript
// 收银台安全基线
if (window.top !== window.self) top.location = location;         // 防 iframe 嵌套
const order = await api.payToken(goodsId);                       // 服务端签发参数
// 提交：{ payToken, idempotencyKey, nonce, ts } —— 前端不传金额
```
