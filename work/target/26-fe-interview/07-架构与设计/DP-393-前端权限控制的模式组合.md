## DP-393：权限控制组合

**答**：
- 权限的模式组合：策略（判定规则：RBAC/ABAC）、装饰器/指令（v-perm 注入权限检查）、状态（权限集合变更响应）、外观（统一 auth.has API）
- 实战分层：内核（权限点集合+判定纯函数）→ 绑定层（路由守卫/指令/组件）——内核可测，绑定薄
- RBAC vs ABAC：角色到权限点（简单清晰）vs 属性条件（资源属于创建者——动态）——RBAC 为主 ABAC 补充是常见落地
- 前端权限的边界：前端权限是 UX 优化不是安全——服务端才是真权限（前端隐藏按钮≠服务端不放行）
- 深水点：权限的「响应式变更」——权限集变更（切角色）时 UI 自动更新（订阅机制）——静态权限在登出/切换租户时会泄漏

```javascript
// 内核: RBAC + ABAC 混合
function createAuth({ roles, userId }) {
  let perms = expand(roles);                         // 角色→权限点展开
  const subs = new Set();
  return {
    has(perm, resource) {                            // ABAC: resource 属性条件
      return perms.has(perm) && (!resource || resource.ownerId === userId || perms.has(`${perm}:any`));
    },
    setRoles(r) { perms = expand(r); subs.forEach((f) => f()); },   // 响应式变更
  };
}
// v-perm 指令消费 auth.has — 三模式组合
```
