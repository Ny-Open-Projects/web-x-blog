## DP-267：源码识别：低代码表达式引擎源码中的沙箱与缓存？
**答**:
- 解释器+沙箱：表达式编译为 AST 求值（禁止 Function 构造逃逸），作用域是白名单 ctx——ARC-304 的引擎侧实现。
- 备忘录：表达式字符串 → 编译函数缓存（表达式重复执行率高），AST 编译一次多处复用。
- 策略：依赖收集（编译期扫描标识符 → 依赖数据源列表），供精确重渲染（ARC-293 联动）。
- 识别要点：能对比 eval/with/Function/new Proxy 四种沙箱路线的安全性与性能。

```javascript
// 表达式引擎（源码级简化）
const compiled = new Map();                    // 表达式 → 编译产物
function compileExpr(src) {
  if (compiled.has(src)) return compiled.get(src);
  const ast = parser.parse(src);               // 递归下降解析
  const deps = collectIdentifiers(ast, ctxKeys);   // 编译期依赖收集
  const fn = evalAst.bind(null, ast);
  compiled.set(src, { fn, deps });             // memo
  return compiled.get(src);
}
function evalAst(node, ctx) {                  // 解释器：递归求值（无 Function/eval）
  switch (node.type) {
    case 'Identifier': return ctx[node.name];
    case 'Binary': return binop(node.op, evalAst(node.left, ctx), evalAst(node.right, ctx));
    case 'Member': return evalAst(node.object, ctx)?.[evalAst(node.property, ctx)];
    case 'Call': return evalAst(node.callee, ctx)(...node.args.map(a => evalAst(a, ctx)));
  }
}
// 沙箱路线对比：with({}) 最快但逃逸风险 / Proxy has trap 拦截全局 / 递归解释器最安全但慢 5~10 倍（低代码常选）+ 编译缓存补偿
```
