## ARC-383：前端搜索架构如何设计？
**答**：
- 三种路线：纯前端（数据全量在端：MiniSearch/lunr/Fuse，万条内可行，离线可用）、纯服务端（ES/OpenSearch，标准方案）、混合（端上缓存热点索引做即时搜索，长尾走服务端）。
- 混合架构关键：端上索引增量同步（版本号拉差异）+ 查询路由（先查本地，N ms 内无结果或置信度低再查服务端）+ 去重合并。
- 体验层：输入防抖 + 请求取消（AbortController）+ 竞态保护（只采纳最新请求结果）+ 搜索联想（前缀树/ES suggest）。
- 分词与中文：端上中文分词成本高，折中用 n-gram 或按空格/常见词切分；精确匹配需求强的直接服务端。
- 可观测：搜索无结果率（优化词典/同义词）、搜索→点击转化率（相关性指标）。
```javascript
class HybridSearch {
  async search(q) {
    const local = this.mini.search(q);                    // 本地即时结果
    const ctrl = new AbortController();
    this.ctrl?.abort(); this.ctrl = ctrl;                 // 竞态保护
    const remote = await api.search(q, { signal: ctrl.signal }).catch(() => []);
    return mergeByScore(local, remote);                   // 合并去重
  }
  syncIndex() { diffAndMerge(this.indexVersion, await api.indexDiff()); }
}
```
