## ARC-446：大促容量：前端在压测与扩容链路的职责
**答**:
- 前端在容量链路的职责：流量模型输入（用户行为漏斗：PV→点击→下单的转化比，决定各接口 QPS 倍数）、压测配合（影子流量标识、压测数据隔离展示）、前端自身扩容（CDN 带宽预算、静态资源削峰）。
- 流量模型计算：峰值 QPS = 日 PV × 峰值系数 × 行为系数 ÷ 秒；前端提供各页面/各动作的真实埋点占比（哪些接口被触发最频繁），这是压测脚本还原真实流量的依据。
- 前端削峰手段：静态化（ARC-102）、请求合并与节流（倒计时同步用本地时钟不轮询）、接口聚合（BFF 一次返回首屏全集）、随机退避（整点开抢的用户请求打散秒级抖动）。
- 压测验收：前端配合观察压测期间的错误率/性能回归，确认用户侧无感知（压测流量带标识不污染真实数据与监控）。
- 大促后复盘：容量预估 vs 实际流量的偏差分析，修正下次的系数模型。
```javascript
// 流量模型：从埋点推接口 QPS
function estimateQps(dailyPv, peakFactor, actionShare, conversion) {
  const peakPv = dailyPv * peakFactor / 86400;              // 秒均 PV
  const peakAction = peakPv * actionShare * conversion;     // 动作接口 QPS
  return Math.ceil(peakAction * 1.5);                        // 余量 50%
}
// 例：detail 1000万PV × 3 峰值 → 秒均 347，下单按钮 40% × 30% → submit QPS ≈ 42×1.5
```
