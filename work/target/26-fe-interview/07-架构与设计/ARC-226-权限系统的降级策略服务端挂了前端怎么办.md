## ARC-226：权限系统的降级策略：服务端挂了前端怎么办？
**答**：
- 原则：**失败时收紧，不放松**（fail-closed）。权限服务不可用 ≠ 所有人获得权限，而是"只保留上一次快照的最小集"。
- 降级阶梯：权限快照有本地缓存（sessionStorage，仅当前会话）→ 直接用缓存快照渲染，但所有请求标注"基于过期快照"；缓存也没有 → 渲染只读首页，全部写操作禁用。
- 后端兜底才是安全底线：即便前端放行了 UI，接口层鉴权照样拒绝。前端的降级只关乎体验不关乎安全。
- 恢复：权限服务恢复后主动刷新快照并对比 diff，提示用户"权限已刷新"；期间产生的 403 批量补偿上报。

```typescript
async function loadPermSnapshot(): Promise<PermSnapshot> {
  try {
    const snap = await api.get('/me/perm-snapshot', { timeout: 3000 });
    sessionStorage.setItem('perm-snap', JSON.stringify({ snap, ts: Date.now() }));
    return snap;
  } catch {
    const cached = sessionStorage.getItem('perm-snap');   // 会话内缓存（关标签即失效，不落盘）
    if (cached) { markStaleMode(); return JSON.parse(cached).snap; }
    return READONLY_SNAPSHOT;                             // 只读兜底：仅 read:* 权限码
  }
}
// stale 模式：banner 提示"权限校验服务暂不可用，当前按上次权限显示"，写操作按钮禁用并上报
```
