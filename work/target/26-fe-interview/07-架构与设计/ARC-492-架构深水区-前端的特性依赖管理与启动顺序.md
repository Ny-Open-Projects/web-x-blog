## ARC-492：特性依赖管理与启动编排
**答**:
- 启动问题：几十个 SDK/特性初始化（监控/配置/登录/I18n/权限），顺序错（监控后于业务启动 → 首个错误丢失）、阻塞错（配置拉取阻塞渲染）。
- 编排设计：依赖图声明（feature: { init, dependsOn: ['config','auth'] }）→ 拓扑排序执行；阻塞分级：critical（阻塞渲染：配置/登录）、eager（并行尽快：监控/I18n）、lazy（交互后：客服/埋点热力）。
- 失败策略：critical 失败阻断启动（明确报错页）；eager 失败降级继续（监控挂了不影响功能，记录 meta 告警）；lazy 失败静默。
- 启动度量：各阶段打点（bootstrap → config → auth → render → interactive），预算与回归（慢启动归因到具体 init）。
- 幂等与重入：init 可重入（热更新/重试场景），单例守卫防止重复初始化副作用（重复订阅/重复上报）。
```javascript
const features = {
  config: { init: loadConfig, critical: true },
  auth: { init: restoreSession, dependsOn: ['config'], critical: true },
  monitor: { init: initMonitor, dependsOn: ['config'], stage: 'eager' },
  chat: { init: () => {}, stage: 'lazy' }
};
async function bootstrap() {
  const order = topoSort(features);
  for (const f of order.filter(x => x.critical)) await runInit(f);      // 串行关键路径
  await Promise.allSettled(order.filter(x => !x.critical && x.stage === 'eager').map(runInit)); // 并行非关键
  requestIdleCallback(() => order.filter(x => x.stage === 'lazy').forEach(runInit));
}
```
