## ARC-488：中断恢复总览：哪些操作需要可恢复设计
**答**:
- 判断标准：操作耗时长（用户中途离开/刷新概率高）+ 有副作用成本（重做代价大）→ 需要断点恢复。清单：大文件上传（分片续传 ARC-377）、长表单（草稿）、批量任务（ARC-486）、引导流程（向导步骤持久化）、下载大资源（Range 续传）。
- 恢复协议三要素：进度持久化（状态存哪：IndexedDB/服务端任务）、幂等键（恢复后重放不重复）、校验点（部分完成的中间产物有效）。
- UX 协议：恢复入口显式（"继续上次未完成的任务 3/10"）、恢复前校验环境（版本/schema 兼容）、放弃选项（清理残留）。
- 服务端配合：任务状态查询接口、分片幂等、过期策略（3 天未恢复的任务归档）。
- 防滥用：不是一切都要恢复——一次性轻操作（点赞）加恢复机制是过度设计，判断标准里"重做代价大"是硬条件。
```javascript
// 通用恢复管理器
class Resumable {
  async resume(taskId) {
    const st = await api.taskStatus(taskId);
    if (st.expired) return offerRestart(taskId);
    const local = await idb.get('tasks', taskId);              // 本地进度
    await idb.ensureSchemaCompat(st.schemaVersion);            // 版本校验
    return this.continueFrom(st.progress, local);
  }
  static worthResuming(op) { return op.duration > 30e3 && op.redoCost > 'high'; }
}
```
