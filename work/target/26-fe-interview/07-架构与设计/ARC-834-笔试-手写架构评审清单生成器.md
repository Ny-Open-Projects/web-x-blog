## ARC-834：手写评审清单生成

**答**：实现架构评审的「动态清单生成器」`ReviewChecklistGenerator`：① 基于变更特征生成评审清单：变更类型（新增页面/修改共享组件/依赖升级/新端接入）——每种类型有专属检查项；② 风险加权：变更触发的风险项（跨团队→加协作检查项；支付链路→加安全检查项）；③ 历史教训注入：过往评审发现的「高频问题」自动加入清单（故障复盘的教训——同模式变更必查）；④ 清单的执行追踪：每项检查 { item, checker(谁查), result(pass/fail/na), note }——评审记录可追溯；⑤ 评审质量反馈：清单中被查出问题的项（有拦截价值的保留）vs 从未拦截的项（移除——清单瘦身）。写出实现。

```javascript
const TYPE_CHECKS = {
  'new-page': ['路由归属确认', '性能预算评估', '埋点方案确认'],
  'shared-component': ['影响面扫描(使用方清单)', '向后兼容确认', '迁移指南更新'],
  'dep-upgrade': ['生态兼容矩阵', 'codemod 准备', '灰度方案'],
  'new-platform': ['能力矩阵核对', '样式适配方案', '发布节奏'],
};
const RISK_CHECKS = { crossTeam: '接口人确认', authOrPay: '安全评审', largeData: '性能压测' };

class ReviewChecklistGenerator {
  #history = new Map();   // item -> { asked: n, caught: n }
  generate(changeType, risks = []) {
    const items = [...(TYPE_CHECKS[changeType] ?? [])];
    for (const risk of risks)
      if (RISK_CHECKS[risk]) items.push(RISK_CHECKS[risk]);
    // 历史教训注入: 同类型变更的高频问题
    for (const [item, stat] of this.#history)
      if (stat.caught >= 2 && items.includes(item)) items.push(`[历史教训] ${item}`);
    return items.map((item) => ({ item, checker: assignChecker(item), result: null, note: '' }));
  }
  recordResult(checklist) {
    for (const c of checklist) {
      const stat = this.#history.get(c.item) ?? this.#history.set(c.item, { asked: 0, caught: 0 }).get(c.item);
      stat.asked++;
      if (c.result === 'fail') stat.caught++;          // 查出问题 = 有拦截价值
    }
  }
  slim() {                                             // 清单瘦身: 从未拦截的项移除
    return [...this.#history.entries()]
      .filter(([item, s]) => s.asked >= 10 && s.caught === 0)
      .map(([item]) => item);
  }
}
```

**评分点**：
- 按变更类型生成专属清单（非通用模板）
- 风险加权注入（跨团队/支付链路的专项检查项）
- 历史教训注入（故障复盘 → 同模式必查）
- 清单瘦身（从未拦截的项移除——清单防膨胀）
