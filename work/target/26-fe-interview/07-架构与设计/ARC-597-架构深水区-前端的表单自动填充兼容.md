## ARC-597：autofill 兼容架构
**答**:
- 问题：自定义表单组件（受控/虚拟输入/隐藏真实 input）常破坏浏览器 autofill（密码管理器/浏览器填充失效——登录表单最伤）。
- 兼容基线：语义化 name/autocomplete 属性（username/current-password/new-password/tel/email——autofill 靠这些识别，自定义组件也必须保留原生 input 承载）、可见性规则（display:none 的 input 浏览器拒填——用 opacity/位移隐藏而非 display）、iframe 场景（跨域 iframe 内填充策略）。
- 架构落点：表单引擎的字段映射层（schema 字段 → 标准 autocomplete token 映射表——组件库统一处理，业务无感）、密码框专项（登录/注册/改密三类表单的 autocomplete 基线测试进组件库 CI——ARC-577 a11y 同款思路）。
- 状态同步：autofill 触发 change（浏览器填充不总是触发 input/change 事件——组合事件兼容 ARC-528 同源问题）→ 受控状态同步的兜底（轮询读取/autofill 事件探测——Chrome 的 -webkit-autofill 伪类检测）。
- 验证：主流浏览器 + 1Password/Bitwarden 的填充矩阵测试（第三方密码管理器行为差异大——真机矩阵）。
```html
<!-- 组件库基线：自定义样式但保留原生语义 -->
<form>
  <input name="account" autocomplete="username" required>       <!-- 真实 input 承载填充 -->
  <input type="password" name="pwd" autocomplete="current-password">
  <!-- 自定义视觉层覆盖其上（opacity 定位），填充事件同步到受控状态 -->
</form>
```
