## ARC-442：长列表渲染的架构分层
**答**:
- 架构分四层：数据层（分页协议 cursor + 预取下一页）、测量层（高度缓存/估算/修正）、渲染层（虚拟滚动窗口 + 回收复用）、交互层（滚动锚定/键盘导航/选中保持）。
- 数据层设计：无限滚动用 cursor 分页（offset 深翻页性能崩塌）；预取策略（剩余 < 1 屏时拉下一页，双缓冲防跳变）；数据上限治理（10 万条后本地索引或服务端检索切换）。
- 测量与渲染：定高纯计算、动态高估式渲染 + 实测修正（缓存 per-item 高度）；DOM 回收但组件状态外置（选中/展开状态按 id 存 store，滚动回来恢复）。
- 架构决策：什么时候不用虚拟化——条数 < 100 直接渲染（虚拟化的复杂度不值）；筛选/排序频繁变化的列表要把计算放 selector/memo 层。
- 性能预算：滚动帧 < 16ms（滚动期禁用复杂布局）、搜索过滤 P95 < 100ms。
```javascript
// 虚拟列表核心分层（测量层示意）
class HeightCache {
  #heights = new Map(); #default = 48;
  estimate(i) { return this.#heights.get(i) ?? this.#default; }
  measure(i, h) { this.#heights.set(i, h); }                  // 实测修正
  offset(i) { let o = 0; for (let k = 0; k < i; k++) o += this.estimate(k); return o; }
}
// 渲染层：只渲染 [start, end] 窗口，overscan 5 条；状态外置到 store 保证滚动恢复
```
