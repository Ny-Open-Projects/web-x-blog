## ARC-206：联邦架构下的依赖图谱与影响面分析平台怎么做？
**答**：
- 数据源：CI 发布时上传每个应用的 manifest/snapshot 到平台，平台抽实体（应用、版本、expose 模块、shared 依赖）与边（host→remote、模块→依赖），落成有向图存储。
- 三类查询：正向（这个主应用运行时依赖哪些子应用版本——发布前预览）、反向（我要下线/改某 expose，影响哪些主应用——影响面）、冲突（shared 依赖 requiredVersion 交叉校验）。
- 与发布流程集成：子应用发布卡点 = 反向影响的每个主应用 owner 审批或自动跑契约测试（对 expose 模块的 props 类型快照）；影响面为 0 才允许自动发布。
- 可视化只是壳，价值在"反向查询自动化"——没有它，微前端的独立发布就是互相踩踏。

```javascript
// 平台侧核心：用邻接表存图，反向查询 O(出度)
const edges = new Map(); // host@version → Set<remote@version>
function addEdge(hostVer, remoteVer) {
  if (!edges.has(remoteVer)) edges.set(remoteVer, new Set());
  edges.get(remoteVer).add(hostVer);
}
function dependents(remoteApp, remoteVer) {         // 谁在用我
  const out = [];
  for (const hostVer of edges.get(`${remoteApp}@${remoteVer}`) ?? []) out.push(hostVer);
  return out;
}
function canAutoPublish(remoteApp, remoteVer) {
  const deps = dependents(remoteApp, remoteVer);
  return deps.length === 0 || deps.every(h => contractTestPass(h, remoteApp, remoteVer)); // 契约快照全绿
}
// 契约测试：对 expose 模块做 props 类型/渲染快照，主应用侧的 fixture 由平台代跑
```
