## ARC-412：组件树的错误传播与恢复设计
**答**:
- 错误分类决定处理策略：渲染错误（ErrorBoundary 捕获）、异步错误（Promise/onunhandledrejection，需手动接入边界）、事件错误（window error 兜底）、资源错误（window error capture）。架构上建立"错误 → 处理者"的路由表。
- 边界分级（ARC-084 延伸）：边界粒度与爆炸半径对应——区块级边界降级区块、路由级边界降级整页；错误信息带"受影响范围"标签便于监控归类。
- 恢复设计：边界提供三种恢复出口——重试（重新渲染该子树）、重置（清空该子树状态重来）、逃生（跳转备用页面）；自动恢复尝试 1 次，失败转人工兜底，避免无限重渲染循环。
- 错误上下文强制携带：上报必须含路由/组件名/release/用户操作序列（最近 5 个动作），否则排障无从下手。
- 布局稳定性：降级 UI 用同高度占位，防止错误引发页面跳动引发二次错误。
```javascript
class SmartBoundary extends React.Component {
  state = { error: null, retried: false };
  componentDidCatch(err, info) {
    report(err, { boundary: this.props.name, scope: this.props.scope,
      actions: actionHistory.last(5) });                        // 强制上下文
    if (!this.state.retried) this.setState({ retried: true });  // 自动重试一次
  }
  render() {
    if (this.state.error && this.state.retried === true) {
      return this.props.fallback(this.state.error, {           // 三出口
        retry: () => this.setState({ error: null, retried: false }),
        reset: () => { resetSubtree(this.props.scope); this.setState({ error: null }); },
        escape: this.props.escapeTo
      });
    }
    return this.state.error ? null : this.props.children;      // 重试中静默占位
  }
  static getDerivedStateFromError(error) { return { error }; }
}
```
