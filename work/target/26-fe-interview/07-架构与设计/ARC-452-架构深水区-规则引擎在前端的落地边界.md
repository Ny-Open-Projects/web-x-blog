## ARC-452：规则引擎在前端的落地边界
**答**:
- 适用信号：规则高频变更（运营策略/风控阈值）、规则由非开发角色维护、规则间有组合逻辑（且/或/非/优先级）、同一规则多端执行。表单联动/审批条件/营销优惠是典型。
- 架构形态：规则 DSL（JSON 结构：{ fact, op, value, compose }）+ 解释器执行；可视化编辑器（条件树 UI）产出 DSL，存服务端，运行时拉取执行。
- 边界红线：规则引擎不是万能——性能敏感热路径（每帧渲染判断）不进规则引擎；规则数 < 5 且稳定的直接写代码（引擎是维护负担）；安全裁决类规则必须服务端执行副本。
- 落地分层：规则定义（存储/版本/审批）、规则编译（DSL → 可执行闭包，缓存编译结果）、规则执行（沙箱内，超时保护）、规则观测（每条规则命中率，死规则清理）。
- 测试策略：规则集快照测试（固定输入 → 命中输出），变更 diff 自动生成回归用例。
```javascript
// 迷你规则引擎
const compile = (r) => r.compose === 'and'
  ? (ctx) => r.children.every(c => evalRule(c, ctx))
  : (ctx) => r.children.some(c => evalRule(c, ctx));
function evalRule(r, ctx) {
  if (r.children) return compile(r)(ctx);
  const v = ctx[r.fact];
  switch (r.op) {
    case 'eq': return v === r.value;
    case 'gt': return v > r.value;
    case 'in': return r.value.includes(v);
    default: throw new Error(`未知操作符 ${r.op}`);          // fail fast
  }
}
// DSL: { compose:'and', children:[{fact:'vip',op:'eq',value:true},{fact:'price',op:'gt',value:100}] }
```
