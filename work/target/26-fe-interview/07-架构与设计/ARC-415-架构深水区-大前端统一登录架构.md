## ARC-415：多端统一登录架构如何设计？
**答**:
- 统一原则：一次登录多端互信。Web 主域 Cookie（HttpOnly + SameSite）为桌面基线；小程序用自身 session_key 换统一 token；App 用设备信任 + refresh token。
- token 架构：短效 access token（15min）+ 长效 refresh token（端绑定）；token 内嵌设备指纹与端标识，服务端可识别异常端登录（异地/新设备触发二次验证）。
- 互信跳转：H5 在 App 内嵌时通过 JSBridge 透传免登 token；小程序与 App 通过开放平台互跳协议；所有端最终换取同一个统一会话（统一用户中心签发）。
- 会话一致性：单端登出 → 全端踢出策略可配置（强安全场景）；会话撤销用服务端黑名单 + 端上轮询/推送下线。
- 降级与安全：登录链路任何一环失败都要有明确降级（短信验证码兜底）；风控埋点（登录失败率/异地率）进统一监控。
```javascript
// 统一 token 管理器（多端共用逻辑）
class AuthCenter {
  async ensure() {
    if (this.accessToken && !expired(this.accessToken, 60)) return this.accessToken; // 提前 60s 续
    try { return await this.refresh(); }
    catch (e) { if (isRevoked(e)) return this.relogin();        // 被踢出强登
                throw e; }
  }
  async refresh() {
    const res = await api.refresh({ rt: this.refreshToken, device: deviceFingerprint() });
    this.set(res); return res.accessToken;
  }
}
```
