## ARC-304：低代码平台的安全防线如何设计？
**答**：
- 低代码扩大了"能写代码的人"，攻击面同步扩大：表达式注入（DSL 里的 JS 表达式逃逸沙箱）、XSS（用户配置的富文本/URL）、SSRF（数据源 URL 任填）、越权（页面权限配置错误）。
- 防线：表达式**强沙箱**（白名单上下文 + 无 window/document/eval，禁 Function 构造递归）；富文本白名单渲染（ARC-253 转义策略）；数据源 URL 走代理白名单（平台代请求，禁止内网地址）；页面权限默认 deny（ARC-226 fail-closed）。
- 审计增强：低代码变更审计比普通代码更细（谁改了哪个节点的什么属性，ARC-073），高危动作（改权限绑定/数据源）双人复核。
- 平台自身的供应链：物料市场物料上架前扫描（依赖审计 + 行为分析：禁止物料请求非白名单域名）。

```typescript
// 表达式沙箱防线
function evalSandbox(expr, ctx) {
  if (/window|document|globalThis|eval|Function|fetch|XMLHttpRequest/.test(expr)) throw new SandboxError();
  const keys = Object.keys(ctx);              // 白名单上下文
  return new Function(...keys, `"use strict"; return (${expr});`)(...keys.map(k => ctx[k]));
}
// 数据源代理：POST /proxy/ds { url } → 服务端校验 url ∈ allowlist && !isPrivateIp → 平台代请求，端上拿不到任意外联能力
```
