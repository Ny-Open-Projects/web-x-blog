## ARC-801：笔试：手写容量估算模型

**答**：实现前端大促容量估算器 `estimateCapacity(event)`：① 输入：{ expectedPv, peakHourRatio, avgPageSizeKB, resourceCount, publishPerDay, buildMinutes }；② CDN 带宽：峰值带宽 = PV×peakHourRatio / 3600s × pageSize × 资源数——输出 Gbps；③ CI 并发：发布频率 × 构建时长 → 需要的构建并发数；④ BFF QPS：页面 QPS × 接口扇出系数；⑤ 输出估算报告 + 3 倍冗余建议（大促安全水位）+ 各项的「当前容量 vs 需求」缺口对比。写出实现。

```javascript
function estimateCapacity({ expectedPv, peakHourRatio = 0.15, avgPageSizeKB = 120, resourceCount = 25, publishPerDay = 8, buildMinutes = 5, fanout = 3 }) {
  const peakPvPerSec = (expectedPv * peakHourRatio) / 3600;
  // CDN: 每秒峰值请求 × 平均资源大小
  const cdnGbps = +((peakPvPerSec * resourceCount * avgPageSizeKB * 8) / 1e6).toFixed(1);  // KB→Gb
  // CI: 发布窗口 2h 内消化全天发布
  const ciConcurrency = Math.ceil((publishPerDay * buildMinutes) / 120);
  // BFF: 页面 QPS × 扇出
  const bffQps = Math.ceil(peakPvPerSec * fanout);
  const report = {
    peakQps: Math.ceil(peakPvPerSec),
    cdn: { needGbps: cdnGbps, withHeadroom: cdnGbps * 3 },
    ci: { needConcurrency: ciConcurrency, withHeadroom: ciConcurrency * 2 },
    bff: { needQps: bffQps, withHeadroom: bffQps * 3 },
  };
  // 缺口对比: currentCapacity 传入对比
  return {
    ...report,
    gaps: (current) => Object.fromEntries(Object.entries(report).map(([k, v]) =>
      [k, v.withHeadroom > (current[k] ?? 0) ? `缺口: 需 ${v.withHeadroom} 有 ${current[k]}` : 'OK'])),
  };
}
// 用法: estimateCapacity({ expectedPv: 50e6, peakHourRatio: 0.2 })
// → cdn.withHeadroom: XXX Gbps (3 倍冗余), ci.needConcurrency: N
```

**评分点**：
- 峰值换算公式正确（PV×占比/3600s）
- 单位换算（KB→bit→Gbps 的 ×8 处理）
- 三维度输出 + 3 倍冗余安全水位
- 缺口对比函数（当前容量 vs 需求——可行动）
