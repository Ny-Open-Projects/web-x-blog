## DP-386：批处理模式

**答**：
- 批处理核心：高频单件 → 低频批量（合并窗口）——上报合批、DOM 写合帧、请求合并
- 实现协议：缓冲区（queue）+ 触发器（size/time/demand 三选或组合）+ flush（一次性消费缓冲区）
- Vue/React 的批更新就是批处理：同 tick 多次 set → 一次渲染——框架内置，业务层「自己批」的场景是埋点/日志/IM 消息
- 实战要点：缓冲上限（防内存涨——满了强制 flush）、flush 的「pagehide 兜底」（切走前必须发）、批的时序保序（seq）
- 深水点：批处理的「背压联动」——flush 失败重入队（批不丢）vs 丢弃计数（监控不能拖垮业务）——按数据价值选择

```javascript
function createBatcher({ maxSize = 20, windowMs = 3000, flush }) {
  const buf = []; let timer = null;
  function add(item) {
    buf.push(item);
    if (buf.length >= maxSize) return doFlush();
    timer ??= setTimeout(doFlush, windowMs);
  }
  function doFlush() {
    clearTimeout(timer); timer = null;
    if (!buf.length) return;
    flush(buf.splice(0));                            // 一次性消费
  }
  addEventListener('pagehide', doFlush);             // 兜底
  return { add, flush: doFlush };
}
```
