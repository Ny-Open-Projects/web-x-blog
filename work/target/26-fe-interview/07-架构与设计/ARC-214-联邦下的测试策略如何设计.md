## ARC-214：联邦下的测试策略如何设计？
**答**：
- 分层测试金字塔：单测各自跑 → 契约测试（expose 模块 props/渲染快照，平台代跑）→ 集成测试（主应用 mock loader 加载本地 expose 产物）→ E2E 少量真联邦链路。
- 核心是**契约测试**：主应用不依赖子应用完整功能，只依赖 expose 契约；子应用 CI 触发"下游契约回归"，红了就阻断发布。
- 本地联调不必起全套联邦：host 测试时注入 mock loader（依赖倒置 ARC-209），把 loadRemote('shop/X') 换成本地 fixture，秒级反馈。
- E2E 环境稳定性：固定各子应用"测试版本指针"，避免下游随机发布污染 E2E。

```javascript
// 契约测试：对 expose 模块做 props 类型 + 渲染快照
import { render } from '@testing-library/react';
import ShopButton from '../src/exposes/Button'; // 直接测源码入口

test('Button 契约：size/type props 渲染稳定', () => {
  const { asFragment } = render(<ShopButton size="lg" type="primary" onClick={() => {}}>Go</ShopButton>);
  expect(asFragment()).toMatchSnapshot();       // 快照即契约，改动必须显式 review
});
// 平台代跑：子应用发布时把 expose 目录打包上传，平台在各下游主应用仓库的 fixture 里渲染新版快照比对
// host 集成测试注入 mock：
vi.mock('@module-federation/enhanced/runtime', () => ({
  loadRemote: (id) => import(`../fixtures/shop/${id.replace('shop/', '')}.tsx`),
}));
```
