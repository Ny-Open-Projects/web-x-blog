## ARC-588：架构演进路线图制定与执行
**答**:
- 路线图 ≠ 愿望清单：每项演进要"为什么是现在"（业务驱动/债务临界点）、目标态（完成的定义）、路径（分阶段可交付——ARC-425 长跑管理）、依赖与风险。
- 制定方法：输入三源——业务规划（未来半年要做什么业务 → 架构提前备能力）、债务清单（ARC-191 债务定价）、技术趋势（ARC-197 技术雷达——不追热点只挑与业务相关的）；输出季度滚动路线（季度细 + 半年粗——保留调整空间）。
- 执行机制：季度立项评审（ARC-165）→ 里程碑验收（每阶段有可验证产出——"完成 50% 迁移"不是里程碑，"A 模块全量新架构"才是）→ 季度回顾（路线 vs 实际偏差原因——是规划问题还是执行问题）。
- 容量分配：演进投入占比明确（如 20% 工时——没有预留的路线图是空头支票）、与业务排期冲突时的决策规则（ARC-394 向上沟通预先约定）。
- 传播：路线图公开（团队/业务方可见——预期管理 ARC-394）、每季度对外汇报进展（价值证据）。

// 季度滚动路线

    { item: '微前端迁移 A 域', milestone: 'A 域 3 应用全量联邦', capacity: '15%' },

  '2027-H1': ['构建工具升级', '低代码平台二期'],
  review: { deviationRule: '连续两季度未达 → 立项重评（不是硬推）' }
};
