## ARC-218：联邦下多子应用的公共依赖收敛策略？
**答**：
- 收敛目标：同一依赖全页面只加载一份，且版本由"平台统一决定"而不是"谁先加载用谁"。
- 分层策略：框架类（react/vue）——host 提供，singleton，requiredVersion 严格；UI 库/工具类——独立"shared-base"应用集中提供（单例），其他应用只声明不提供；业务组件——不 shared，走 expose 或 npm。
- 平台校验：发布平台对所有应用 manifest 的 shared 段做合并计算，输出"最终生效版本表"，任何子应用声明与表不符直接卡发布（防漂移）。
- 极端兜底：某子应用确实需要不同大版本（如 vue2 遗留）——不进联邦 shared，独立打包（体积换兼容），或该应用退回 qiankun 应用级集成。

```javascript
// shared-base：集中提供公共依赖的应用
exposes: {},
shared: {
  react:   { singleton: true, requiredVersion: '~18.2.0', eager: false },
  'react-dom': { singleton: true, requiredVersion: '~18.2.0' },
  dayjs:   { singleton: true, requiredVersion: '^1.11.0' },
  '@corp/ui': { singleton: true, requiredVersion: '^5.0.0' },
},
// 子应用一律：react: { singleton: true, requiredVersion: '~18.2.0', import: false }  // 只声明不提供
// 平台校验：mergeShared(manifests) → diff 出 requiredVersion 不一致清单 → CI 卡点
```
