## ARC-443：交互密集型应用的帧调度架构
**答**:
- 帧调度模型：每帧预算 16ms 分三段——输入处理（pointer 事件采样合并，跟随 rAF）、状态计算（ dirty 区域最小计算）、渲染提交（transform/opacity 优先，禁 layout 属性动画）。
- 输入优化：高频事件（pointermove/scroll）不做即时计算，存最新值 rAF 里消费（合并多事件为一帧一次）；拖拽用 pointer capture 保证不丢事件。
- 渲染优化：画布类走离屏缓存（静态层缓存位图，只重绘脏区）；DOM 类走 will-change 局部提升 + 内容可见性；重计算（碰撞检测/吸附）下沉 Worker 或 WebGPU compute。
- 状态与渲染解耦：交互状态（拖拽中位置）绕过状态库直接 mutable 更新渲染（避免订阅开销），落定后才提交到正式 store（协议化"瞬时态 vs 提交态"）。
- 度量：帧率分布、长任务数、交互延迟（pointerdown → 首帧响应）；不达标瓶颈用 Performance 面板火焰图定位。
```javascript
// 帧调度循环
const input = { x: 0, y: 0, dirty: false };
canvas.onpointermove = (e) => { input.x = e.clientX; input.y = e.clientY; input.dirty = true; }; // 只存值
function frame() {
  if (input.dirty) {
    const hit = hitTest(input.x, input.y);                    // 每帧一次计算
    renderAt(input.x, input.y, hit);                          // transform-only
    input.dirty = false;
  }
  requestAnimationFrame(frame);
}
```
