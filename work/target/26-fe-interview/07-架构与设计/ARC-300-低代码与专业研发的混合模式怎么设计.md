## ARC-300：低代码与专业研发的混合模式怎么设计？
**答**：
- 混合是常态：低代码页面里一定有"专业代码兜底"的场景（复杂逻辑/个性化 UI）。三种混合形态：自定义组件物料（专业开发 → 物料市场）、表达式/JS 块（逃逸舱 ARC-097）、出码接管（低代码起步 → 出码后专业接手演进）。
- 分工模型：专业研发产出物料与领域模板（质量高复用强），运营/产品用物料搭建页面（ARC-173 营销页链路）；界限是"是否需要新能力"——需要 → 提物料需求。
- 协作流程：物料需求走 RFC（ARC-038）→ 专业开发发布物料 → 搭建侧使用；搭建页面的疑难杂症可"一键转专业开发"（出码 + 交接文档），避免低代码死胡同。
- 治理：逃逸舱代码进审查（表达式长度限制、禁止网络直连外的副作用），出码产物进正常代码仓与 CI。

```typescript
// 逃逸舱 JS 块（受控）
interface JsBlock { name: string; code: string; allowedApis: ['state', 'dataSource', 'utils'] }
function runJsBlock(block, ctx) {
  const scopedCtx = pick(ctx, block.allowedApis);          // 只暴露白名单上下文
  return new Function('ctx', `"use strict"; ${block.code}`)(scopedCtx);   // 平台审查后入 DSL
}
// 一键转专业：export(dsl) → Vue SFC 差异化产物 → git 仓库初始化 → 交接 checklist
```
