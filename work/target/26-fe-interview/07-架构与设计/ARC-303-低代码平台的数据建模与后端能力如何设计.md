## ARC-303：低代码平台的数据建模与后端能力如何设计？
**答**：
- 无后端撑腰的低代码只能搭静态页；完整平台要提供**数据建模**（实体/字段/关系，类似 airtable）+ 自动 CRUD API + 权限联动。
- 模型层：实体定义（字段类型/校验/关联）→ 平台自动生成表结构与 REST/GraphQL API，schema 变更走迁移（破坏性变更提示）；API 直接进页面的数据源编排（ARC-293）。
- 权限联动：实体字段级权限自动映射到页面字段渲染（ARC-228 字段级控制复用）——建模时定义"谁能看薪资字段"，页面自动 masked。
- 边界：低代码建模适合"后台管理/轻业务"，高并发/复杂事务场景明确不适用（出码接管或专业开发），平台要给"能力边界提示"而不是让用户撞墙。

```typescript
// 实体建模 DSL
const Order = defineEntity({
  name: 'Order',
  fields: {
    id: { type: 'id' },
    amount: { type: 'money', perm: { read: ['finance:*'], write: ['finance:edit'] } },  // 字段级权限
    status: { type: 'enum', options: ['pending', 'paid', 'refunded'] },
  },
  relations: { user: { entity: 'User', type: 'belongsTo' } },
});
// 平台自动产出：REST /orders（CRUD+分页+过滤）、zod 校验、字段权限元数据下发前端 → 页面渲染时 masked
```
