## ARC-291：低代码引擎的架构分层如何设计？
**答**：
- 经典五层：**协议层**（物料描述协议/页面 DSL schema，引擎的中立语言）、**渲染层**（DSL → 组件树运行时渲染）、**编排层**（拖拽画布、属性面板、大纲树）、**物料层**（组件+配置描述+setter，低代码的"资产"）、**扩展层**（插件体系：数据源、出码、权限、国际化）。分层讲清"协议先行"是加分点。
- 关键决策：编排器与渲染器**分离**——画布是"带编辑态的渲染器"，通过注入调试信息（选中框/占位）复用同一渲染引擎，保证"所见即所得"。
- 双模式：运行时渲染（JSON 直接驱动，灵活）vs 出码（生成 Vue/React 代码，性能与可维护性好），ARC-092 讲过取舍，引擎层要两者可共存（同一 DSL 两后端）。
- 扩展机制：引擎内核只管渲染与编排，一切领域能力（表单/表格/图表/流程）做成物料+插件，避免内核腐化。

```typescript
// DSL schema（节选）
interface PageDSL {
  version: '1.0';
  components: [{
    id: 'node_1', componentName: 'Button',
    props: { type: 'primary', text: { type: 'i18n', key: 'btn.submit' } },
    events: { onClick: { type: 'js-expression', value: 'this.submit()' } },
    children: [],
  }];
  dataSource: [{ id: 'ds1', type: 'fetch', options: { url: '/api/list' } }];
}
// 渲染器：compile(dsl) → vdom（处理 props 表达式/数据源绑定/i18n）
// 编排器：同一渲染器 + editorEnhancers（点击选中/hover 框/拖拽占位）——代码复用保证所见即所得
```
