## ARC-400：架构判断力：五个经典取舍案例分析
**答**:
- 案例一（过早抽象 vs 重复三遍）：团队协作中允许重复到第二遍，第三遍才抽——错误抽象的改造成本远高于重复代码（ARC-014 延伸）。
- 案例二（微前端 vs 模块化）：单团队 < 20 人用微前端是自找复杂度；先问"要解决的是独立发布还是团队墙"。
- 案例三（SSR vs CSR + 预渲染）：内容时效敏感、SEO 关键 → SSR；营销页 → SSG/预渲染；中后台 → CSR。按页面级混合而非应用级一刀切。
- 案例四（自研平台 vs 开源魔改）：核心差异化能力自研，通用能力开源 + 薄封装；判断标准是"这一层是否构成我们的护城河"。
- 案例五（一刀切规范 vs 分级规范）：新代码严格、存量代码渐进（修复时顺手升级），规范不带迁移路径就会催生豁免泛滥。
- 判断力的底层：每个取舍都回到"这个决策错了的修复成本是多少"——修复成本低就快速决策，成本高才值得花一周评审。
```javascript
// 取舍速查：决策修复成本矩阵
const tradeoffs = {
  '抽象时机': { wrongCost: '高（API 扩散）', rule: '三次法则' },
  '微前端':   { wrongCost: '极高（拆回去更贵）', rule: '先证明团队墙存在' },
  'SSR':      { wrongCost: '中（页面级可回退）', rule: '页面级混合渲染' },
  '自研平台': { wrongCost: '高', rule: '护城河判定' },
  '规范强度': { wrongCost: '低（可分级）', rule: '新严旧宽渐进' }
};
```
