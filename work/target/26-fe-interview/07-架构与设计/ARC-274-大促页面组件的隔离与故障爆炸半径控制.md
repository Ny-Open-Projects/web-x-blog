## ARC-274：大促页面组件的隔离与故障爆炸半径控制？
**答**：
- 爆炸半径原则：任何楼层/挂件的故障不允许阻断页面其余部分与下单链路。手段：每楼层独立 ErrorBoundary + 独立数据源（不共享一个聚合请求）+ 独立降级开关。
- 依赖隔离：楼层组件禁止直接 import 全局单例做互斥（共享 store 单点故障会传染）；楼层间通信走事件且失败静默。
- 第三方组件（直播/客服/优惠计算）作为最高风险源：全部包边界 + 超时 + 静态兜底（图替代挂件），其加载失败永不影响核心楼层。
- 度量：故障演练中验证"拆掉任一楼层，核心路径 LCP 与下单成功率不变"作为架构验收标准。

```tsx
// 楼层容器：边界+数据隔离
function Floor({ floor }) {
  return (
    <ErrorBoundary fallback={floor.fallback} onError={e => degrade(floor.id)}>
      <FloorDataProvider id={floor.id}>          {/* 独立数据源，不共用聚合请求 */}
        <Suspense fallback={<FloorSkeleton/>}>{floor.comp}</Suspense>
      </FloorDataProvider>
    </ErrorBoundary>
  );
}
// degrade(id)：记录到降级注册表 → 大盘可见"某楼层已降级" → 预案可单独摘除该楼层
```
