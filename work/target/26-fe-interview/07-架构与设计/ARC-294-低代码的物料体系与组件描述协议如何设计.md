## ARC-294：低代码的物料体系与组件描述协议如何设计？
**答**：
- 物料 = 组件代码 + 描述协议（metadata）：组件名、props 结构（供属性面板自动生成 setter）、事件、插槽、默认值、缩略图。协议是物料与引擎解耦的关键（业界如阿里 lowcode-engine 的物料协议）。
- setter 体系：属性面板根据 prop 类型自动选择编辑器（文本/枚举/颜色/表达式/数据绑定），复杂场景可自定义 setter 物料——属性面板本身也是低代码可扩展的。
- 物料版本与兼容：物料带版本号，页面 DSL 记录所用物料版本；升级物料要过"快照 diff"（渲染结果对比），破坏性变更走新组件名而不是改旧组件。
- 物料生产流水线：组件库（ARC-028）产出组件 → 物料描述自动生成（从 TS 类型推导）→ 人工补默认值/文档 → 发布到物料市场。

```typescript
// 物料描述协议（节选）
const buttonMeta = {
  componentName: 'Button',
  props: [
    { name: 'type', propType: 'enum', defaultValue: 'default', setter: 'SelectSetter',
      options: ['default', 'primary', 'danger'] },
    { name: 'disabled', propType: 'bool', defaultValue: false },
    { name: 'onClick', propType: 'func', setter: 'ExpressionSetter' },   // 绑定低代码表达式
  ],
  snippets: [{ title: '主按钮', schema: { componentName: 'Button', props: { type: 'primary' } } }],
};
// 描述自动生成：ts-morph 解析 ButtonProps 类型 → 草稿 metadata → 平台补默认值与文案 → 发布
```
