## DP-371：受控/非受控

**答**：
- 受控：值由父管理（props + onChange）——每次输入走父级状态（联动/校验需要）；非受控：组件自持（ref 取值）——性能好（无父级重渲）
- 选择标准：需要「即时联动」用受控；只需要「提交时取值」用非受控（大表单的非受控性能优势明显）
- 混合模式：defaultValue 初始化 + 受控可选（value 缺省时自动降级非受控）——组件库的标准 API 设计
- 受控的性能优化：受控大表单的「字段级状态隔离」（每个字段独立组件——输入只重渲本字段）
- 深水点：受控的「反馈延迟」问题——父级处理慢导致输入卡顿（输入到显示的延迟）——concurrent 特性缓解但本质是「状态所有权」设计问题

```jsx
function Input({ value, defaultValue, onChange }) {
  const [inner, setInner] = useState(defaultValue);
  const controlled = value !== undefined;
  const v = controlled ? value : inner;               // 混合: value 存在则受控
  return <input value={v} onChange={(e) => {
    if (!controlled) setInner(e.target.value);
    onChange?.(e.target.value);
  }} />;
}
// 大表单: 每字段包 Field 组件(内部受控) — 输入只重渲本字段
```
