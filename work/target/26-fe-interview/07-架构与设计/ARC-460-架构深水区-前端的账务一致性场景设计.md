## ARC-460：涉账场景（余额/积分/优惠券）的前端一致性
**答**:
- 原则：涉账数据前端永远"展示后端事实"，不做本地推算（本地余额扣减与服务端并发扣减必然漂移）；所有变更后主动刷新 + 服务端为事实源。
- 乐观更新的边界：非涉账数据（昵称）可乐观；涉账操作（扣积分兑换）必须"请求 → 服务端结果 → 更新"，失败即回显真实值；操作期间按钮锁与防重。
- 并发一致性：同一账户多端操作——关键操作用服务端版本号/幂等键；前端提交携带版本，冲突（版本不符）时拉最新数据重新确认，绝不静默覆盖。
- 对账展示：积分明细列表是用户自查手段——变更必须留流水（时间/类型/数量），前端展示流水与余额来自同一接口防口径分裂。
- 异常路径：余额显示与预期不符的用户投诉，前端要能提供"刷新 + 流水"的自证路径；监控涉账接口的错误率单独建告警。
```javascript
// 涉账操作：服务端事实 + 幂等 + 冲突处理
async function redeemWithPoints(skuId) {
  const lock = acquireUiLock('redeem');                       // 防连点
  try {
    const res = await api.redeem({ skuId, idempotencyKey: genKey(),
      balanceVersion: account.version });                     // 带版本防并发
    if (res.conflict) await refreshAccount();                 // 冲突：拉最新重确认
    else account.update(res.balance, res.flowId);             // 服务端结果落地
  } finally { lock.release(); }
}
```
