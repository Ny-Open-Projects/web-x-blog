## ARC-603：大表单性能优化
**答**:
- 性能病灶：全表单 re-render（一个字段变更整棵表单重渲）、校验风暴（每输入触发全量校验）、联动级联（DAG 传播连锁重算 ARC-506 无批处理）。
- 架构手段：字段级订阅（字段组件只订阅自己的 value/error——细粒度订阅是第一杠杆，react-hook-form/自带字段组件）、校验分层（输入期只校验本字段 + 防抖、提交期全量）、联动批处理（微任务合并传播 ARC-506）、分片渲染（长表单分页/步骤化 + 卸载非当前片——状态保 store 不丢 ARC-489）。
- 深表单：嵌套结构路径优化（扁平化注册 vs 嵌套对象——深层嵌套的不可变更新贵，扁平 key 存 store 映射）、大列表字段（可重复行组：行内虚拟化 + 行级 memo）。
- 初始化性能：大 schema 表单首渲（字段注册懒化/分步挂载）、默认值大量计算（惰性计算 derived 字段）。
- 度量：输入响应延迟（按键到 UI 更新 < 16ms）、校验耗时分布、全表单提交耗时。
```javascript
// 字段级订阅（细粒度）
const Field = memo(({ name }) => {
  const value = useFieldValue(name);                             // 只订阅本字段
  const error = useFieldError(name);
  return <Input value={value} error={error} onChange={v => setFieldValue(name, v)} />;
});
// 批量传播：setField 触发的联动在 microtask 合并一次计算（ARC-506）
```
