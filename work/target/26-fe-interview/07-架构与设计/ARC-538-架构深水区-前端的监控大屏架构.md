## ARC-538：监控大屏/驾驶舱架构
**答**:
- 场景特征：长时间运行（不刷新跑 7×24）、多图表高频更新、多人观看（电视/投影）——架构重点是稳定与自适应而非首屏。
- 数据层：推送订阅（ARC-537 快照+增量）+ 轮询兜底双通道；图表数据按刷新率分级（核心指标 5s、次级 30s、趋势 5min——防全屏高频刷新拖垮后端）。
- 长时运行治理：内存巡防（图表实例重建策略：每天低峰重建防泄漏累积 ARC-445）、WS 断线自动重连与数据校准、浏览器崩溃自愈（看门狗：无响应自动刷新——Electron/安卓盒子上必配）。
- 布局与适配：大屏分辨率适配（设计稿缩放 scale 方案 vs 组件自适应——推荐后者防变形）、多屏分发（不同屏幕不同布局配置）。
- 权威性设计：大屏数据与告警/工作台同源（大屏只是可视化，不做独立计算——口径一致 ARC-381）。
```javascript
// 大屏看门狗 + 分级刷新
setInterval(() => {                                              // 心跳自检
  if (!heartbeatOk()) { location.reload(); }                     // 崩溃自愈（保存布局状态）
}, 30000);
const refreshers = { core: pollOrPush(5000), secondary: pollOrPush(30000), trend: pollOrPush(300000) };
// 重建策略：每天 03:00 低峰整页 reload（防 7×24 内存累积）
```
