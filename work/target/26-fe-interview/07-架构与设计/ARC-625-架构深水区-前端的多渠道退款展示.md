## ARC-625：多渠道退款状态展示
**答**:
- 退款复杂性：一笔订单多支付方式拆分退（组合支付：余额 + 银行卡——退款按原路各自退）、渠道时效不同（余额即时/银行卡 3~7 天）、部分退款（多次退款拆分——每笔退款独立记录）。
- 数据模型：退款单（订单 → 多退款记录：渠道/金额/状态/预计到账时间）——服务端状态机权威（渠道回执驱动），前端展示状态时间线（每笔退款独立进度——渠道到账时效说明）。
- 交互：退款申请（选择退回方式：原路/退余额——可用方式服务端下发）、进度页（轮询/推送 ARC-416）、失败处理（渠道退回失败 → 人工介入通道 + 原因说明）。
- 一致性：退款到账与余额联动（退到余额 → 余额刷新 ARC-460 涉账刷新）、部分退款后的订单状态（已退金额/可退金额展示——服务端计算前端展示）。
- 文案合规：退款时效承诺（"银行卡 3~7 个工作日"——渠道实际时效配置化下发，避免写死）。
```javascript
// 退款状态时间线
const refunds = await api.refundsOf(orderId);                    // [{channel, amount, state, eta}]
refunds.map(r => <RefundTimeline key={r.id} {...r}
  etaText={ETA_TEXT[r.channel]} />);                             // 渠道时效配置化文案
// 退到余额：bus.on('refund.settled', ({ toBalance }) => balanceStore.refresh())
```
