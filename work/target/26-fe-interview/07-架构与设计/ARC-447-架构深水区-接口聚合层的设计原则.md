## ARC-447：接口聚合层的设计原则
**答**:
- 聚合层定位：面向"页面"而非"领域"组装数据——一个首屏接口 = 一次聚合（商品 + 营销 + 用户态），把 N 次串行 RTT 变成 1 次。
- 设计原则：无业务逻辑（只做编排/裁剪/格式适配，业务规则留在领域服务）；无状态（水平扩展）；依赖隔离（单一下游慢/挂不阻塞整体——并行调用 + 分级超时 + 局部降级占位）。
- 数据裁剪协议：下游返回大对象，聚合层按页面 schema 裁剪字段（防过度传输）；多端差异（PC/移动字段集）由同一聚合层参数化。
- 容错设计：调用图并行化、关键/非关键依赖分级（推荐位挂了不影响商品列表）、失败兜底数据（默认值占位）+ 降级标记（前端知道哪块是兜底可提示）。
- 可观测：聚合层是排障关键节点——每次聚合记录下游耗时瀑布，慢因可归到具体下游接口。
```javascript
// BFF 聚合器（并行 + 分级容错）
async function homePageAgg(userId) {
  const [goods, marketing, profile] = await Promise.allSettled([
    call('goods.list', { timeout: 800 }),                    // 关键依赖
    call('marketing.banners', { timeout: 300, fallback: DEFAULT_BANNERS }),
    call('user.profile', { timeout: 200, fallback: GUEST_PROFILE })
  ]);
  return {
    goods: goods.value,                                       // 关键失败则整体 500
    marketing: unwrap(marketing, { degraded: true }),         // 非关键失败给兜底
    profile: unwrap(profile, { degraded: true })
  };
}
```
