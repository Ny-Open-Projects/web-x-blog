## ARC-237：按钮级权限的批量注解方案如何设计？
**答**：
- 散落各处的 `can()` 判断不可维护；目标是一处声明、处处生效：路由表统一声明页面权限码 → 注解/指令消费 → 构建期静态检查漏标。
- 三种形态按语义选：无权隐藏（v-if/指令移除 DOM）、无权置灰（禁用+tooltip 说明）、无权保留但点击拦截（引导申请权限）。**置灰+引导申请**是体验最优解，隐藏让用户不知道功能存在。
- 构建期保障：ESLint 规则扫操作类组件（Button onClick）外层必须包 `<WithPerm>` 或 v-perm，漏标报错；权限码字面量必须来自生成的常量表。
- 申请权限闭环：置灰按钮点击弹出"申请该权限"面板，走审批后自动热更快照（ARC-223）。

```tsx
// 声明式包装组件
function WithPerm({ perm, mode = 'disable', children }) {
  const ok = can(usePermSnap(), perm.action, perm.resource);
  if (ok) return children;
  if (mode === 'hide') return null;
  return (
    <Tooltip title="无权限，点击申请">
      <Button disabled onClick={() => openPermRequest(perm)}>{children}</Button>
    </Tooltip>
  );
}
// 使用：<WithPerm perm={{ action: 'audit', resource: 'order' }}><AuditBtn/></WithPerm>
// ESLint：jsx-a11y 自定义规则，onClick 所在 Button 若无 WithPerm/v-perm 祖先 → warn
```
