## ARC-566：端上消息分发与订阅管理
**答**:
- 架构：一条 WS 连接多逻辑通道（ARC-416 复用）——端上需要"订阅管理器"：组件订阅/退订生命周期管理（引用计数）、消息路由（topic → handlers）、优先级（核心消息不丢、展示类消息可丢）。
- 订阅生命周期：组件挂载 subscribe → 卸载 unsubscribe（自动配对 API + 未配对告警——ARC-466 泄漏防护前端版）；页面级订阅随路由清理；全局订阅（通知）常驻。
- 消息处理模型：串行队列（核心消息按序处理）vs 即时处理（展示类）——处理慢不阻塞接收（接收与处理分离，积压上限丢弃策略）。
- 去重与补拉：seq 去重（ARC-502）+ 断线补拉（lastSeq 请求）——订阅管理器统一处理，组件无感。
- 调试与观测：订阅快照（当前活跃订阅列表——调试"为什么收到不该收的消息"）、消息量统计（按 topic——高频 topic 优化线索）。
```javascript
class SubscriptionHub {
  #subs = new Map();                                             // topic -> {handlers, refCount}
  use(topic, handler) {                                          // React hook 式 API
    useEffect(() => this.subscribe(topic, handler), [topic]);
  }
  dispatch(topic, msg) {
    const s = this.#subs.get(topic);
    if (!s) return track('orphan-msg', topic);                   // 无订阅者消息（异常或可丢弃）
    s.queue.push(msg);                                           // 接收与处理分离
  }
}
```
