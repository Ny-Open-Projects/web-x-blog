## ARC-480：架构升级的传播与采纳
**答**:
- 发布 ≠ 采纳。采纳漏斗：知晓（公告/分享会）→ 首次使用（门槛最小化：一条命令接入）→ 持续使用（迁移旧代码的动力）→ 口碑传播（内部案例）。
- 降门槛设计：接入工具自动化（CLI 一条命令装好并演示效果）、默认配置开箱即用、文档按"5 分钟上手"而非全量手册开头。
- 采纳动力设计：与新需求绑定（新功能必须用新方案）、存量迁移补贴（codemod 自动迁移大部分，剩余手工给排期）、样板案例（第一个迁移的团队公开收益数据）。
- 采纳度量与干预：接入率曲线（周度），停滞超过 2 周做根因访谈（是门槛问题还是价值问题）；硬性 deadline 只用于安全/合规类升级。
- 反面模式：靠行政命令强推但工具难用 → 表面接入实际绕过（逃生舱泛滥）；用 lint 卡死旧路径之前先确保新路径体验更好。
```javascript
// 采纳漏斗看板
const adoption = {
  aware: 40,        // 知晓团队数
  onboarded: 28,    // 完成接入
  active: 22,       // 周活跃使用
  stuck: [ { team: 'teamC', reason: 'codemod 不覆盖路由写法', action: '补规则后重跑' } ]
};
```
