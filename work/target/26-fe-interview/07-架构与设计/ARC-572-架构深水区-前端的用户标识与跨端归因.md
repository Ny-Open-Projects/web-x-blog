## ARC-572：用户标识与跨端归因
**答**:
- 标识层级：匿名 ID（设备指纹/cookie ID——未登录用户）、登录 ID（账号体系）、融合 ID（匿名与登录的关联归因）。标识是分析体系的基石（ARC-134/536 数据链路起点）。
- ID 生成策略：匿名 ID 生成与持久化（localStorage + cookie 双写——任一可用即续）、设备指纹（多信号加权：UA/屏幕/字体——趋势上隐私限制加强，指纹要合规化 ARC-154）、ID 合并（登录瞬间匿名行为归因到账号——merge 事件）。
- 跨端打通：同账号多端（ARC-415 统一登录天然打通）、跨设备归因（登录行为串联——营销归因场景的限制：三方 cookie 退场后的替代方案第一方数据）。
- 合规红线：标识与 PII 关系的分级（匿名 ID 不与明文身份同存于前端）、用户重置权（清 cookie/换设备 = 新匿名 ID——分析口径要理解这个自然流失）、GDPR 意义上的"个人数据"判定。
- 一致性：ID 生成逻辑收口单模块（多 SDK 各自生成 ID 是数据割裂主因）、ID 迁移（ID 方案升级时的历史数据桥接）。
```javascript
// 匿名 ID 双写 + 登录归因
function anonId() {
  return ls.get('aid') ?? cookie.get('aid') ?? create();          // 双存任一续用
}
function onLogin(uid) {
  track('id_merge', { anon_id: anonId(), user_id: uid });         // 归并事件
  ls.set('aid', genAnonId());                                     // 换新匿名 ID（会话隔离）
}
```
