## ARC-429：测试环境治理如何设计？
**答**:
- 问题：多人共用 test 环境互相覆盖；每个 MR 一个环境的成本失控。治理策略三级：固定公共环境（集成验证）、按需弹性环境（MR 级预览环境，自动创建销毁）、本地环境（Mock 兜底）。
- 弹性预览环境：MR 触发自动部署到 preview-{mr} 域名，网关路由 + 后端 mock/stub 池；闲置 24h 自动回收。成本可控的关键是"前端容器 + 后端共享 stub"而非全链路独立。
- 环境元数据：每环境标注 owner/用途/后端版本/数据版本；环境状态页（哪个环境谁在用、当前部署版本）公开可查。
- 数据治理：测试数据集版本化（种子数据脚本），环境重置一键化；敏感数据脱敏进测试库。
- 工具支撑：一键切环境（浏览器插件/URL 规则），环境指纹显示在页面角标（当前环境+版本），防"测了半天在 wrong env"。
```javascript
// MR 预览环境编排（伪 CI）
on: pull_request
jobs:
  preview:
    steps:
      - run: deploy --env preview-${{ github.event.number }} --ttl 24h
      - run: gateway route add preview-${{ number }}.app.com -> this
      - run: comment "预览地址 https://preview-${{ number }}.app.com"
on: pull_request.closed
jobs: [ run: teardown preview-${{ number }} ]                  // 自动回收
```
