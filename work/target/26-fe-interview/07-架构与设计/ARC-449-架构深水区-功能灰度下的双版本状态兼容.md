## ARC-449：灰度下的双版本状态兼容设计
**答**:
- 问题：灰度期间 v1/v2 用户混跑，同一条持久化数据（本地缓存/服务端草稿/协同文档）可能被两个版本的代码读写——v2 写的新结构 v1 读不懂，v1 读后回写会破坏 v2 数据。
- 设计原则：数据 schema 版本化（写入带 version 字段）；读兼容（新版本能读旧版本并惰性迁移）；写保护（旧版本遇到更高 version 数据只读不写，或按字段级合并）。
- 落地手段：迁移器注册表（v1→v2→v3 链式迁移，禁止跳版）；字段级合并协议（协同场景只 merge 自己负责的字段，ARC-379）；灰度分桶时同步数据 schema（同一桶内 schema 一致，跨桶数据由服务端归一化）。
- 服务端数据：API 响应带 schemaVersion，前端按版本选择解析器；前端写回时升版 + 服务端兼容读。
- 测试：跨版本读写矩阵测试（v1 写 → v2 读、v2 写 → v1 读）纳入迁移回归。
```javascript
const migrations = { 1: migrate1to2, 2: migrate2to3 };
function loadDraft(raw) {
  let data = raw, v = raw.schemaVersion ?? 1;
  while (v < CURRENT) { data = migrations[v](data); v++; }   // 链式惰性迁移
  return data;
}
function saveDraft(data) {
  if (data.schemaVersion > CURRENT) return readOnlyMode();   // 高版本数据写保护
  write({ ...data, schemaVersion: CURRENT });
}
```
