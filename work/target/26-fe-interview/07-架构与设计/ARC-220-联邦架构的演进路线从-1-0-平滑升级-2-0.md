## ARC-220：联邦架构的演进路线：从 1.0 平滑升级 2.0？
**答**：
- 升级原则：运行时先行、manifest 渐进、不做大爆炸切换。2.0 运行时兼容 1.0 的 remote entry 协议，可先只升级 host 运行时。
- 四步走：① host 接入 @module-federation/runtime（兼容期，加载协议不变）；② 各子应用构建升级到 enhanced 插件，产出 manifest，但 entry 仍可用；③ 发布平台接入 snapshot 依赖图谱与编排（ARC-206）；④ 切换 remote 指针到 manifest，开启版本协商与 SSR。
- 风险控制：每步独立可回滚，灰度按"应用"粒度推进；兼容期内 shared 协商关闭（行为与 1.0 一致），验证后再开启。
- 验收指标：联邦错误率不升、首屏 P90 不劣化（预加载补偿）、发布编排覆盖率（多少主应用改走 manifest）。

```javascript
// 第①步兼容期配置（host）
new ModuleFederationPlugin({
  name: 'host',
  remotes: { shop: 'shop@https://cdn.example.com/shop/remoteEntry.js' }, // 仍用 1.0 entry
  runtimePlugins: [require('@mf/compat-plugin')],   // 2.0 runtime + 兼容插件：关闭严格协商
}),
// 第④步切换：remotes 改为 manifest 地址 + 开启 strictVersion
// 灰度：按用户分桶让 10% 流量走 manifest 链路，对比两组 mf-error-rate / FCP
```
