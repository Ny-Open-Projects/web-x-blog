## DP-518：笔试：手写支付门面

**答**：实现支付外观 `payFacade.pay(orderId)`：① 内部编排：风控预检 → 服务端 prepay → 唤起收银台（渠道适配）→ 查单确认（服务端为准）；② 渠道适配：微信内 JSAPI / 浏览器 H5 / App 桥——策略按容器选择；③ 异常矩阵：用户取消（查单——可能已付）、超时（pending 态）、渠道失败（降级链）；④ 重复点击防护（paying 锁 + 幂等键）；⑤ 产出统一结果（{ ok, pending }——业务侧单分支处理）。写出实现。

```javascript
class PayFacade {
  #paying = new Set();   // 幂等锁
  async pay(orderId) {
    if (this.#paying.has(orderId)) return { ok: false, reason: 'paying' };
    this.#paying.add(orderId);
    try {
      const params = await api.prepay(orderId, { idempotencyKey: orderId });
      const channel = pickChannel();                   // 策略: 按容器
      try { await channel.invoke(params); }
      catch (e) { if (!e.errMsg?.includes('cancel')) { /* fail 不代表没付 */ } }
      const state = await pollOrderState(orderId);     // 服务端查单为准
      if (state === 'PAID') return { ok: true };
      if (state === 'PENDING') return { ok: true, pending: true };   // 异步确认中
      return { ok: false, state };
    } finally { this.#paying.delete(orderId); }
  }
}
// 业务侧: const r = await payFacade.pay(id); — 五步收拢为一行
// lint: 禁止 import payApi — 强制走门面
```

**评分点**：
- 编排收拢（风控→prepay→收银台→查单——业务一行）
- cancel 分支也查单（用户先付后取消界面的真实场景）
- 幂等锁 + 幂等键（重复点击防护）
- 统一结果结构（业务侧单分支——门面的简化价值）
