## DP-455：配置中心模式

**答**：
- 配置中心的模式分解：观察者（配置变更推送 → 订阅组件热生效）、策略（配置合并策略：全局→区域→站点三层）、代理（flag() 判定封装——业务无感）、备忘录（上次配置缓存——启动兜底）、空对象（配置缺失的默认值——脏配置防御）
- 三源合并的优先级：编译期 < 远程 < 用户级（AB）——合并语义（深合并/覆盖）要显式
- schema 校验：脏配置不能崩页面（类型/范围校验——失败回默认值）
- 深水点：配置的「生效时序」——首屏前就绪（同步注入）vs 热更新（推送）——两条通道的合并（启动快照 + 增量推送）

```javascript
class ConfigCenter {
  #config = {}; #subs = new Set();
  async init() {
    const cached = localStorage.get('cfg');          // 备忘录: 启动兜底
    this.#config = cached ?? DEFAULTS;
    try {
      const fresh = await fetchConfig();
      this.#config = deepMerge(this.#config, fresh); // 三源合并
      if (validate(this.#config)) this.#notify();    // schema 校验通过才生效
    } catch { /* 网络失败: 缓存兜底 */ }
  }
  get(key) { return this.#config[key] ?? DEFAULTS[key]; }   // 空对象: 默认值兜底
  onChange(fn) { this.#subs.add(fn); return () => this.#subs.delete(fn); }
}
```
