## ARC-623：多步支付确认状态协调
**答**:
- 状态协调难点：支付跨页面/跨 App（收银台 → 渠道 App → 回跳）——前端状态机（payToken 生命周期：created → channel-open → awaiting-result → settled）+ 服务端状态同步（查单为事实源 ARC-418/598）。
- 回跳处理：渠道回跳语义（成功回跳 ≠ 支付成功——以查单为准；回跳丢失 → 挂起页重入（payToken 续用））、App 内嵌（JSBridge 回调 + 回跳双通道——先到为准，查单校验）。
- 中断场景：用户中途杀 App（状态丢失 → 恢复入口：订单列表"继续支付"——payToken 幂等重入）、渠道超时（收银台超时 → 查单确认 → 处理中页兜底）。
- 防重复支付：同一订单重复发起（复用支付单号 ARC-418）、渠道侧重复扣（幂等键贯穿）、支付结果页防刷新重复展示（结果幂等渲染）。
- 体验细节：等待态进度（查单轮询中的动画与预计时间——不白等）、跨步状态可见（订单状态页实时更新 ARC-622）。
```javascript
// 支付状态机
const sm = payMachine('created');
sm.on('channel-open', () => startWatchdog());                    // 超时查单
sm.on('return', async () => {                                    // 回跳：查单校验
  const r = await pollResult(payToken);
  sm.to(r.state);                                                // settled/failed/pending
});
// 恢复入口：/pay/resume?payToken=xx → sm.to('awaiting-result')（幂等重入）
```
