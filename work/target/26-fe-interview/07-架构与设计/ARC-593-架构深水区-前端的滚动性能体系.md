## ARC-593：滚动性能体系
**答**:
- 滚动性能三杀手：滚动期布局抖动（scroll handler 里读写布局交替——ARC-443 rAF 合帧）、大面积重绘（滚动内容未合成层化）、嵌套滚动冲突（内层滚动到边界外层继续—— overscroll 行为不一致）。
- 体系方案：滚动事件收口（统一滚动管理器：rAF 节流 + 被动监听 passive: true——业务不自绑 scroll）、合成层策略（sticky/fixed 层化 + will-change 有节制——层爆炸反而耗内存 ARC-445）、嵌套滚动协议（overscroll-behavior 收口 + 虚拟列表与页面滚动的协调 ARC-442）。
- 滚动驱动 UI：scroll-linked 动画走 CSS scroll-timeline 或 rAF 合帧（禁 handler 直接改样式）、吸顶/进度条等高频 UI 用 IntersectionObserver/scrollend 替代轮询。
- 测量体系：滚动帧率采样（真实用户滚动 jank 率）、长任务归因到滚动场景（handler 违规检测 dev-only 警告）。
- 端差异：iOS 弹性滚动（bounce）与 fixed 元素的坑、Android 回弹禁用差异——滚动行为基线按端适配层收口。
```javascript
// 滚动管理器（收口）
const scroll = {
  on(el, fn) {                                                   // rAF 合帧 + passive
    let ticking = false;
    el.addEventListener('scroll', (e) => {
      if (ticking) return; ticking = true;
      requestAnimationFrame(() => { fn(e); ticking = false; });
    }, { passive: true });
  }
};
/* CSS: overscroll-behavior: contain;  内层滚动不外溢 */
```

**追问**：

1. 设了 passive 之后 handler 里 preventDefault 就失效，什么场景必须去掉？ → 需要拦截滚动的场景（下拉刷新、自定义滚动物理）才用非 passive，且 handler 内不许读写布局，否则照样掉帧。
2. 虚拟列表滚到底部快速加载时出现白屏和跳动，怎么治？ → 预留缓冲区、加载占位与原列表项等高、开启滚动锚定，避免新内容插入把视口顶走。
3. 你说要看滚动 jank 率，这个指标在 RUM 里怎么算出来？ → 滚动期间用 rAF 采样帧间隔，超过 50ms 的帧计为 jank，按会话聚合上报分位值，而不是只报平均值。
