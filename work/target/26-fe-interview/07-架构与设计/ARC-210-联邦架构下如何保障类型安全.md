## ARC-210：联邦架构下如何保障类型安全？
**答**：
- 问题本质：remote 模块在主应用里只是 `import('shop/Button')` 的字符串路径，TS 不知道它的类型，改 props 全靠人肉同步。
- 方案一（推荐）：@module-federation/dts-plugin（2.0）——子应用构建时生成远程类型（remote-entry 类型声明 + dts 快照发布到 CDN），主应用构建时自动拉取并映射 `shop/*` 到对应 dts，类型跟随子应用版本自动更新。
- 方案二（轻量）：Monorepo 内维护 @types 契约包，子应用改 props 必须发版契约包并过主应用 CI——版本化但流程重。
- 运行时兜底：类型只能管编译期，跨团队运行时契约用 zod/JSON Schema 在 expose 入口校验 props（开发期不通过直接抛错），配合 ARC-206 的契约测试。

```javascript
// dts-plugin 配置（子应用）
module.exports = {
  plugins: [new ModuleFederationPlugin({
    name: 'shop', exposes: { './Button': './src/Button.tsx' },
    dts: { generateTypes: true },          // 构建时产出远程类型并随 manifest 发布
  })],
};
// 主应用
plugins: [new ModuleFederationPlugin({
  name: 'host', remotes: { shop: 'shop@https://cdn.example.com/shop/mf-manifest.json' },
  dts: { consumeTypes: true },             // import('shop/Button') 自动获得 ButtonProps 类型
})],
// expose 入口的运行时契约：组件内部对关键 props 做 zod 校验并上报，防跨版本错配
```
