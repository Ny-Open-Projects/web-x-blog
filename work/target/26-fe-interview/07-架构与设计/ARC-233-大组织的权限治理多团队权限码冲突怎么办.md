## ARC-233：大组织的权限治理：多团队权限码冲突怎么办？
**答**：
- 冲突根源：权限码无命名空间、各团队自行造码（`order:read` vs `orders:list` 同义不同码），矩阵编辑器里无法合并。
- 治理结构：**注册制**——权限码必须先注册（域归属 + owner + 描述 + 敏感级）才能被引用；注册走平台 PR 式审批；码名强制 `{domain}:{resource}:{action}` 三段式。
- 生命周期：码有 deprecated 状态与替代码字段，删除前必须先标废弃并给迁移期；平台定期扫"零引用码"促清理。
- 敏感分级：高危码（如 `user:export`）注册即标记，引用处自动触发二次审批与审计增强。

```typescript
// 权限码注册表（平台侧）
interface PermDef {
  code: string;          // 必须 ^[a-z]+:[a-z-]+:[a-z-]+$
  owner: string;         // 团队/人，出事找得到
  sensitive: boolean;
  status: 'active' | 'deprecated';
  replacedBy?: string;
}
function lintPermCode(def: PermDef) {
  if (!/^[a-z]+:[a-z-]+:[a-z-]+$/.test(def.code)) throw new Error('权限码命名不规范');
  if (def.status === 'deprecated' && !def.replacedBy) throw new Error('废弃码必须给替代码');
}

```
