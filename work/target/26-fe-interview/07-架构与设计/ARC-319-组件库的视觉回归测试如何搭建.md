## ARC-319：组件库的视觉回归测试如何搭建？
**答**：
- 架构：Storybook stories 全量截图（Playwright 多视口+主题矩阵）→ 与基线 diff（像素/感知哈希）→ 超阈值 MR 卡点。ARC-035 讲过思路，这里讲工程搭建细节。
- 稳定性是难点：动画/字体渲染差异导致 flaky——截图前禁用动画（prefers-reduced-motion + 全局 CSS 动画暂停）、固定时间（日期组件 mock 时间）、字体用内嵌字体保证渲染一致。
- 阈值策略：像素级 diff 容忍率 0.1%（抗噪），大改动走"基线更新"流程（review diff 图后接受新基线，基线变更即设计变更记录）。
- 与主题联动：基线矩阵 = stories × {light, dark} × {sm, lg}，抽核心组件全矩阵、长尾组件默认主题，控制 CI 成本。

```typescript
// Playwright 视觉回归
const themes = ['light', 'dark'];
for (const theme of themes) {
  test(`story ${story.id} [${theme}]`, async ({ page }) => {
    await page.emulateMedia({ reducedMotion: 'reduce' });      // 禁动画
    await page.addStyleTag({ content: '*,*::before,*::after{animation:none!important;transition:none!important}' });
    await page.goto(`iframe.html?id=${story.id}&theme=${theme}&mockDate=2026-01-01`);
    await expect(page.locator('.preview')).toHaveScreenshot(`${story.id}-${theme}.png`,
      { maxDiffPixelRatio: 0.001 });
  });
}
// 基线更新：pnpm vrt:update → diff 图人工 review → 提交新基线（review 记录即设计变更档案）
```
