## ARC-421：前端可复现构建如何实现？
**答**:
- 目标：同源码 + 同工具链在任何机器构建出字节一致的产物。价值：产物可校验（对比哈希即知是否同版本）、缓存可信、供应链可审计。
- 不确定性来源与消除：时间戳（构建时间注入改为固定值或从 git 取 commit 时间）、路径（absolute path 进了 sourcemap/chunk 名 → 统一 root + relative）、随机哈希/顺序（模块遍历顺序依赖文件系统 → 排序）、环境变量注入（同一 CI 环境固化）。
- 工具链锁定：Node 版本、包管理器版本、构建器版本全部锁定（ARC-364）；lockfile 哈希参与产物指纹。
- 校验机制：CI 里连跑两次构建比对哈希（快检）；发布产物哈希存档供事后审计。
- 收益落地：远端缓存命中率随确定性提升（输入相同 → 缓存必然命中），发布对账（ARC-363）有了精确基准。
```javascript
// 构建注入固定时间（消除时间戳不确定性）
// vite.config.ts
export default defineConfig({
  define: {
    __BUILD_TIME__: JSON.stringify(execSync('git log -1 --format=%cI').toString().trim()),
    __COMMIT__: JSON.stringify(execSync('git rev-parse HEAD').toString().trim())
  },
  output: { paths: { root: path.resolve(__dirname) } }          // 相对化路径
});
// CI：build && build 二次 && diff hash —— 不一致即确定性破坏，直接失败
```
