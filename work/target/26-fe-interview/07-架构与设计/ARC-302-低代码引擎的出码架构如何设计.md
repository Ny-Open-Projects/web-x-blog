## ARC-302：低代码引擎的出码架构如何设计？
**答**：
- 出码 = DSL → 框架代码的编译器：管线四步——解析 DSL（AST 化）→ 语义转换（表达式/事件/数据源映射为框架概念）→ 代码生成（模板/AST 打印）→ 后处理（格式化/类型标注/依赖收集）。
- 架构要点：**目标框架作为插件**（Vue/React 生成器各自实现同一下游接口），上游 DSL 协议稳定——出码器是"多后端编译器"。
- 可读性优先：生成的代码要像人写的（语义命名、拆分组件文件、注释保留），因为出码产物会被专业开发者接手维护（ARC-300）——不可读的出码没有价值。
- 转换语义映射表是核心资产：DSL 事件 → emit 回调、数据源 → composable/hook、i18n → t() 调用。映射表版本化，DSL 升级同步更新。

```typescript
// 出码管线
function generate(dsl, target: 'vue' | 'react') {
  const ast = parseDsl(dsl);                       // 1) AST
  const sema = lowerToSemantics(ast);              // 2) 框架无关语义层
  const gen = generators[target];                  // 3) 目标后端插件
  const files = gen(sema);                         //    → [{ path: 'pages/home.vue', code }]
  return postProcess(files, { prettier: true, lint: true, typecheck: true });  // 4)
}
// 语义层节点：{ kind: 'source', id: 'ds1', kind2: 'fetch' } → vue: useFetch() / react: useSWR()
// 质量门禁：出码产物必须过 tsc + eslint + 渲染快照对比（与运行时渲染结果一致性）
```
