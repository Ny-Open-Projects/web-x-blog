## ARC-535：交互埋点协议 schema 体系
**答**:
- 协议分层：事件分类（曝光/点击/输入/提交/停留/错误）、通用属性（session/user/page/release/ab 分桶——SDK 自动注入 ARC-390）、事件特有属性（每类事件的 schema 定义）。
- 命名规范：对象_动作_位置（goods_click_list、order_submit_detail）——可读可聚合；命名注册制（事件字典平台，先注册后埋点，防同名异义）。
- 属性规范：id 类字段命名统一（goods_id 不是 goodsId/gid）、数值单位明确（duration_ms）、枚举值注册（属性字典）——属性可聚合的前提。
- 版本演进：事件 schema 版本化（改属性 = 新版本事件，分析端兼容双版本窗口）；弃用事件标注替代关系。
- 工程化：埋点代码生成（从事件字典生成类型安全的 track 调用——track('goods_click', { goods_id }) 编译期校验参数）、lint 检查未注册事件。
```typescript
// 从事件字典生成的类型安全埋点
import { track, EventMap } from '@corp/track-gen';               // 生成物
track('goods_click', { goods_id: 'g1', from: 'list', position: 3 });
// track('goods_click', { gid: 'g1' })  // TS 报错：参数不符字典
const ev: keyof EventMap = 'goods_click';                        // 只能是注册过的事件
```
