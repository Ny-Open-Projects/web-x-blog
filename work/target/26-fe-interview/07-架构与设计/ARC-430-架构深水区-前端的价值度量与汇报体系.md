## ARC-430：前端架构工作的价值度量与汇报体系
**答**:
- 度量框架三层：效率（构建时长/CI 时长/新人上手天数/需求交付周期）、质量（线上错误率/事故数/逃逸缺陷率）、体验（Web Vitals 达标率/健康分）。每项有基线、有目标、有归因。
- 归因难点：指标变化可能是业务变化导致。解法：控制变量（同口径同比）、配对比较（接入基建的项目 vs 未接入）、事件标注（基建上线时间点在曲线上标记）。
- 汇报设计：季度一本账（投入 X 人日 → 节省 Y 人日/事故 -Z 起/LCP -N%），用业务语言；每月轻量同步（看板 + 异常说明）；年度叙事（基建能力地图演进）。
- 反指标设计：防止度量异化——"构建时长"不鼓励砍必要检查；质量指标不鼓励瞒报。指标成对出现（速度+质量）。
- 输出形态：自动化看板（数据自动采集）为主，人工分析只写"为什么"。
```javascript
// 价值账本（季度汇总）
const valueLedger = {
  quarter: '2026Q1',
  investments: [['构建提速专项', 18], ['监控平台', 25]],        // 人日
  returns: {
    ciTimeSaved: { hoursPerWeek: 42, note: '全团队 CI 缓存 + 分片' },
    incidents: { before: 3, after: 1, attribution: '错误边界 + 灰度门禁' },
    lcp: { before: 3.6, after: 2.4, attribution: 'SSR + 图片治理' }
  }
};
```
