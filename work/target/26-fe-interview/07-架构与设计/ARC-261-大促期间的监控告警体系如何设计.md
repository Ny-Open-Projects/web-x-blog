## ARC-261：大促期间的监控告警体系如何设计？
**答**：
- 大促告警与日常的差异：**基线切换**（大促流量形态不同，用"同时段昨日环比+同环比"而不是绝对阈值）、**分级响应**（P0 呼叫、P5 分钟群播）、**告警降噪**（聚合规则：同页面同错误 5 分钟收敛为一条）。
- 核心指标盘：白屏率、JS 错误率、核心接口成功率/耗时 P95、LCP、下单漏斗转化。每个指标定义 owner、阈值、SOP 链接。
- 告警到响应的闭环：告警消息带"一键执行预案"入口（ARC-258 的预案 ID），值班点击即降级——告警不闭环等于没有告警。
- 复盘沉淀：每次告警的处理时长/根因回写平台，转化为新预案或新规则。

```typescript
// 告警规则配置（平台 DSL 示意）
const rules = [
  { metric: 'whiteScreenRate', window: '5m', cond: 'v > wowSameHour * 3 && v > 0.001', level: 'P0',
    notify: 'call', action: 'EMG-001' },                     // 关联预案
  { metric: 'jsErrorRate', window: '10m', cond: 'v > wowSameHour * 2', level: 'P1', notify: 'group',
    dedupe: 'page+errType:5m' },                             // 聚合降噪
];
// 值班闭环：alert.ack → 执行 action → 填 rootCause → 复盘归档
```
