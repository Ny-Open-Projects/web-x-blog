## ARC-363：前端基建：构建产物完整性校验如何设计？
**答**：
- 目标：保证线上运行的 JS 就是 CI 构建出来的那一份——防 CDN 被篡改、防发布链路注入、防回滚到未知版本。
- 机制一：SRI（Subresource Integrity）——构建时计算资源哈希写入 integrity 属性，浏览器加载时校验；本地静态资源直接可用，CDN 场景需确认 CDN 不重写内容。
- 机制二：产物清单与签名——构建产出 manifest（文件名+哈希），发布时签名存档；运行时灰度抽样比对线上资源哈希与 manifest。
- 机制三：发布对账——部署完成后机器人拉取线上 HTML 与产物，校验资源 URL 与 manifest 一致，防止"发布了但没生效"。
- 供应链纵深：第三方 SDK 引入白名单 + 哈希锁定，动态脚本注入需经 CSP nonce。
```javascript
// 构建后生成 SRI manifest（vite 插件思路）
import { createHash } from 'crypto';
function sriPlugin() {
  return {
    name: 'sri', enforce: 'post',
    transformIndexHtml(html, { bundle }) {
      return html.replace(/<script src="([^"]+)"/g, (m, src) => {
        const code = bundle[src]?.code ?? '';
        const hash = createHash('sha384').update(code).digest('base64');
        return `<script src="${src}" integrity="sha384-${hash}"`;
      });
    }
  };
}
```
