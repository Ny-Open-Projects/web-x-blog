## ARC-232：前后端权限校验的重复建设如何避免？
**答**：
- 先立规矩：前端校验**只为体验**（藏菜单、置灰按钮），后端校验**才是安全**；两者不能互相替代，但可以共享"定义"。
- 共享方式：权限码与资源定义进契约包（OpenAPI 扩展字段或 @types 包），后端在 OpenAPI 的 operation 上标注 requiredPerm，前端代码生成器据此自动生成路由 perm 声明与 TS 类型——定义写一次，两端生成。
- 联调期防漂移：CI 校验"前端用到的权限码必须存在于契约包"，后端删码时 CI 立即发现前端引用。
- 收益量化：重复定义消失、新增接口自动带权限标注、删码/改名即时可发现。

```yaml
# OpenAPI 扩展：后端标注一次
paths:
  /orders/{id}/audit:
    post:
      x-required-perm: order:audit        # 契约即定义
```
```typescript
// 前端代码生成产物（CI 生成，禁止手改）
export const routePerms = {
  '/order/audit': 'order:audit',
} as const;
// 路由守卫直接消费 routePerms，后端 x-required-perm 变更 → 契约包发版 → 前端生成物 diff 被 review
```
