## ARC-392：前后端协作协议如何设计？
**答**:
- 显性协议（接口契约 ARC-162）之外的隐性协作：错误码语义（前端按类处理而非逐码 switch）、时间与时区约定（全部 UTC 传输 + 端上本地化）、枚举字典（服务端维护字典接口）、分页协议统一（cursor 优先）。
- 错误处理协议设计：HTTP 状态 + body 统一结构 { code, message, detail }；前端拦截器按 code 类（鉴权/限流/参数/业务）分流处理；错误码注册表两端共用。
- 联调协议：环境矩阵（dev/test/staging/prod 对应关系）、联调窗口与责任人、契约变更通知（schema diff 自动推送到前端群）。
- 争议裁决：字段命名/结构分歧以契约评审会决议为准，形成先例沉淀（ADR-lite）。
- 工具固化：契约测试（ARC-128）让协议自动执行，不靠自觉。
```javascript
// 统一错误分流拦截器
const CODE_CLASS = { AUTH: redirectLogin, RATE: showBackoff, PARAM: showFormError, BIZ: toastBizMsg };
axios.interceptors.response.use(null, (err) => {
  const { code, message } = err.response?.data ?? {};
  const handler = CODE_CLASS[codeClassOf(code)] ?? toastBizMsg;
  handler(message, err);                                 // 按类处理而非逐码
  return Promise.reject(err);
});
```
