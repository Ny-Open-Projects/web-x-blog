## ARC-309：低代码平台的技术选型：自研还是基于开源引擎？
**答**：
- 决策框架（ARC-001 评估矩阵落地）：看需求偏离度——若需求 = 通用中后台搭建（表单+表格+图表），开源引擎（如 lowcode-engine/ambercat 类）+ 物料定制即可，自研浪费；若核心是垂直场景（营销页/特定行业表单/报表），自研轻引擎反而更小更快。
- 自研的隐藏成本：协议设计、画布细节（拖拽/撤销/命中）、物料生态冷启动——三个都是月级工程。开源的隐藏成本：协议受制于人、深度定制要读改内核、升级断代风险。
- 常见落地路径：基于开源引擎起步 → 摸清协议 → 逐步替换关键模块（渲染器/出码器自研，编排器保留）——ARC-006 渐进演进思想。
- 决策输出：给结论 + 两三个触发重估的条件（如开源引擎停止维护、垂直需求占比 > 50%）。

```typescript
// 选型评估矩阵（评分 1-5，加权）
const matrix = [
  { factor: '需求偏离度', weight: 3, self: 2, oss: 4 },
  { factor: '深度定制需求', weight: 3, self: 5, oss: 2 },
  { factor: '团队投入预算', weight: 2, self: 2, oss: 4 },
  { factor: '生态与物料复用', weight: 2, self: 1, oss: 4 },
];
function score(m, key) { return m.reduce((s, f) => s + f[key] * f.weight, 0); }
// score: self=27 oss=44 → 结论：OSS 起步 + 关键模块渐进替换；重估条件：引擎停维护 / 垂直需求 > 50%
```
