## DP-461：轮询与推送切换

**答**：
- 实时性的策略族：WebSocket（双向全功能）、SSE（单向流+自动重连）、轮询（简单兜底）、长轮询（兼容环境）——策略按「实时性需求 × 环境支持」选择
- 策略切换的实现：统一 RealtimeChannel 接口（subscribe/send）——实现可热切换（WS 失败 → SSE → 轮询降级链）
- 轮询的自适应：间隔随数据变化频率调整（变化密集缩短——自适应轮询）+ jitter（防同时冲击）
- 推送的兜底语义：WS 断连期间的推送丢失 → 重连补拉（lastSeq 游标）——推送的可靠性靠「补拉」闭环
- 深水点：通道的「降级检测」——WS 假活（连接在但消息不通——心跳超时判死）——半开连接的检测是切换触发器

```javascript
class RealtimeChannel {
  #impl; #lastSeq = 0;
  async connect() {
    try { this.#impl = await tryWebSocket(); }       // 首选 WS
    catch { this.#impl = await trySSE(); }           // 降级 SSE
    catch { this.#impl = startPolling(); }           // 兜底轮询
    this.#impl.onMessage((m) => { if (m.seq > this.#lastSeq) { this.#lastSeq = m.seq; this.#emit(m); } });
  }
  reconnect() { /* 重连 + fetch(after=lastSeq) 补拉 */ }
}
```
