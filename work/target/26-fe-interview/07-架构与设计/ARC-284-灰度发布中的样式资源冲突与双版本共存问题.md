## ARC-284：灰度发布中的样式资源冲突与双版本共存问题？
**答**：
- 双版本共存坑：新旧版本同时在线期间，**CSS 全局类名互踩**（v2 改了 `.card` 布局，v1 用户遇到 v2 样式残留）、Service Worker 新旧版本交叉控制页面、localStorage schema 变化。
- 样式隔离：所有样式 scope 化（CSS Modules/命名空间前缀 ARC-213），全局类禁止无前缀；主题/关键 CSS 变量集中管理，双版本共享变量必须兼容（新版本只能加不能改语义）。
- SW 冲突：新版本 SW 安装后旧页面仍在运行——用"等待激活+skipWaiting 策略选择"：灰度期 skipWaiting=false（旧页面用旧资源），版本切换一致性要求高时才 skipWaiting 并刷新。
- 存储兼容：localStorage schema 加版本号，v2 读到旧结构先迁移再写；两个版本轮流写同一 key 要定义写权限（只允许当前生效版本写）。

```typescript
// SW 双版本策略
self.addEventListener('install', () => self.skipWaiting() && clientsClaim()); // 或灰度期注释掉等待
// localStorage schema 迁移
const SCHEMA_V = 2;
function migrate() {
  const cur = Number(localStorage.getItem('__schema') ?? 1);
  if (cur < 2) { localStorage.setItem('cart', JSON.stringify(migrateV1toV2(read('cart')))); }
  localStorage.setItem('__schema', String(SCHEMA_V));
}
// 样式：构建期 classnames 加 build 前缀或 CSS Modules hash —— 全局 .card 不允许出现在源码
```
