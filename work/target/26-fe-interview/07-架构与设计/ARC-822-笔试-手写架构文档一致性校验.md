## ARC-822：手写架构文档校验

**答**：实现「架构文档 vs 实际代码」一致性校验器 `docConsistencyCheck(docs, code)`：① 模块清单校验：文档声明的模块 vs 代码实际目录（缺失/多余标注）；② 依赖声明校验：文档声明的依赖关系 vs 实际 import 关系（文档说 A 不依赖 B 但实际 import 了 → drift）；③ 公共接口校验：文档声明的对外 API vs 实际导出（导出但没文档 = 未登记接口）；④ 输出漂移报告：文档过时项（需更新）/代码越轨项（需修复）/新增未记录项（需补文档）——三类分类；⑤ CI 集成：文档与代码同仓——PR 修改代码时自动检查相关文档是否更新。写出实现。

```javascript
function docConsistencyCheck(docs, code) {
  const drift = { outdatedDocs: [], codeViolations: [], undocumented: [] };

  // 1) 模块清单校验
  for (const docMod of docs.modules)
    if (!code.dirs.includes(docMod.path))
      drift.outdatedDocs.push({ type: 'module-gone', path: docMod.path });
  for (const dir of code.dirs)
    if (!docs.modules.some((m) => m.path === dir))
      drift.undocumented.push({ type: 'module-undocumented', path: dir });

  // 2) 依赖声明 vs 实际 import
  for (const [from, actualDeps] of Object.entries(code.imports)) {
    const docMod = docs.modules.find((m) => m.path === from.split('/')[1]);
    for (const to of actualDeps) {
      const declared = docMod?.dependsOn?.some((d) => to.startsWith(d));
      const allowed = docs.globalRules?.some((r) => r.allows(from, to));
      if (!declared && !allowed)
        drift.codeViolations.push({ type: 'undeclared-dependency', from, to,
          hint: `文档未声明 ${from} → ${to} 的依赖` });
    }
  }
  // 3) 公共接口: 导出但未登记
  for (const [mod, exports] of Object.entries(code.publicExports))
    for (const exp of exports)
      if (!docs.modules.find((m) => m.path === mod)?.publicApi?.includes(exp))
        drift.undocumented.push({ type: 'api-undocumented', mod, exp });
  // CI: drift.codeViolations.length → exit 1
  return drift;
}
```

**评分点**：
- 三类漂移分类（文档过时/代码越轨/新增未记录——各归其主）
- 依赖声明 vs 实际 import 的 diff（架构图保鲜的核心）
- 公共接口登记校验（未登记接口 = 隐形 API）
- PR 联动的文档检查（改代码必须同步文档）
