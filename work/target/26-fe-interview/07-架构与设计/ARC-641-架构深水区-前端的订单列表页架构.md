## ARC-641：订单列表页架构
**答**:
- 状态分区：待支付/待发货/待收货/已完成/售后——Tab 即筛选（状态入 URL ARC-389），每 Tab 独立缓存（ARC-386 回写：详情操作后列表行更新）。
- 列表数据：cursor 分页 + 状态筛选协议（NODE-400）、状态变更驱动（支付成功推送 → 行状态局部更新 + Tab 角标移动——列表与角标同源计算）。
- 行操作集：服务端下发（每订单当前可做什么：支付/取消/确认收货/售后——操作集协议 ARC-509），操作交互（危险操作确认 + 结果刷新——乐观 + 失败回滚 ARC-530）。
- 批量操作：多选批量（发货/打印——批量任务 ARC-486）、全选语义（ARC-602 排除式）。
- 空态与引导：各状态空态差异化（待支付空 → 推荐商品；已完成空 → 引导逛逛）。
- 性能：行组件 memo（状态变更只更新目标行）、图片懒加载、长列表虚拟化（订单多的 B 端商家 ARC-442）。
```javascript
// 订单列表
const { tab } = useListState();                                  // URL 状态
const { items, nextCursor } = useInfiniteQuery(['orders', tab], ({ cursor }) => api.orders({ tab, cursor }));
// 操作集：order.actions = server 下发 → 渲染按钮 → 执行 → setQueryData 回写该行
```
