## DP-513：笔试：手写脚本沙箱

**答**：实现用户脚本的沙箱执行 `runInSandbox(code, allowedApis)`：① 伪 window：Proxy 包装（读取 fallback 真全局、写入落沙箱）——用户脚本不污染真 window；② 能力白名单：allowedApis 之外的 API 不可访问（fetch 不可用时抛错提示）；③ 超时保护：脚本死循环（Promise.race 超时 + 不可中断的说明——同步死循环只能 Worker 隔离）；④ Worker 方案：代码进 Worker 执行（同步死循环可 terminate——真正的隔离）；⑤ 清理：沙箱内注册的定时器/监听器清单——退出清理。写出实现。

```javascript
function runInSandbox(code, allowedApis = {}) {
  const cleanups = [];
  const fakeWindow = new Proxy({}, {
    get(t, k) {
      if (k in allowedApis) return allowedApis[k];
      if (['console', 'Math', 'JSON', 'Date'].includes(k)) return window[k];   // 安全白名单
      throw new Error(`沙箱禁止访问: ${String(k)}`);
    },
    set(t, k, v) { t[k] = v; return true; },          // 写入落沙箱
  });
  const w = new Function('window', 'self', `with(window) { ${code} }`);
  const result = w(fakeWindow, fakeWindow);
  return { result, dispose: () => cleanups.forEach((c) => c()) };
}
// Worker 方案 (真隔离):
// const worker = new Worker(URL.createObjectURL(new Blob([code])));
// setTimeout(() => worker.terminate(), 5000);        // 同步死循环可强杀
```

**评分点**：
- Proxy 伪 window（写落沙箱不污染真全局）
- 能力白名单（显式授权——未授权抛错）
- 同步死循环的边界认知（主线程只能超时提示；Worker 可 terminate）
- 清理协议（沙箱注册的定时器退出清理）

## 变体与延伸（补充）

**变体与延伸**：

1. 这个 Proxy 沙箱能防住 constructor 逃逸吗？→ 不能，原型链逃逸要在 get 里拦危险键，真正的隔离必须靠 Worker 或 iframe，沙箱全局也要用无原型对象承载以减少可达面。
2. Worker 里用户脚本怎么调白名单 API？→ 全部走 postMessage 的 RPC，由主线程按白名单代理真实调用，Worker 内拿不到真实全局，白名单参数本身也要校验，防止借合法 API 越权。
3. 沙箱性能开销怎么评估？→ 看启动延迟与消息往返次数，纯计算脚本用 Worker 更划算，短脚本 Proxy 包装够用，隔离级别要写进接入文档避免误用。
