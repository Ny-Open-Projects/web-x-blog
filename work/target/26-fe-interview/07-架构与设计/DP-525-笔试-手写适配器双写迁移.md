## DP-525：笔试：手写双写适配器

**答**：实现埋点 SDK 迁移的双写适配器 `DualAnalytics`：① 统一接口实现——内部同时调旧 SDK 与新 SDK（迁移期数据校验双跑）；② 数据对比：新旧 SDK 的事件 diff 采样上报（语义映射错误的发现——10% 采样对比）；③ 失败隔离：旧 SDK 失败不影响新 SDK（各自 try/catch）；④ 迁移开关：配置控制流量（10% 用户只走新 SDK——灰度切换）；⑤ 完成 → 移除旧适配器（单写新 SDK——迁移收官）。写出实现。

```javascript
class DualAnalytics {
  constructor(legacy, modern, { sampleRate = 0.1, newOnlyRate = 0 }) {
    Object.assign(this, { legacy, modern, sampleRate, newOnlyRate });
  }
  track(event, props) {
    const roll = Math.random();
    if (roll < this.newOnlyRate) return this.modern.track(event, props);   // 灰度: 只走新
    // 双写: 各自隔离
    const results = [this.legacy, this.modern].map((sdk) => {
      try { return { ok: true, data: sdk.track(event, props) }; }
      catch (e) { return { ok: false, error: String(e), sdk: sdk.name }; }
    });
    // 数据对比采样
    if (roll < this.sampleRate && results[0].ok && results[1].ok) {
      const drift = diffEvent(results[0].data, results[1].data);
      if (drift) reportDrift(event, drift);            // 语义映射错误发现
    }
    return results[1];
  }
}
// 迁移完成: DualAnalytics → new Analytics(newAdapter) — 旧适配器删除
```

**评分点**：
- 双写 + 失败隔离（新旧各自 try/catch——互不影响）
- 数据对比采样（语义映射错误的发现机制）
- 灰度切换（newOnlyRate——流量渐进）
- 迁移收官的路径（双写 → 单写新 → 删旧）
