## ARC-231：权限低代码平台的权限矩阵编辑器如何设计？
**答**：
- 矩阵编辑器 = 角色（行）× 权限码（列）的批量勾选界面，难点不在 UI 而在**语义分组与联动**：权限码按资源域分组、读写 admin 三级联动、套餐限制置灰。
- 关键体验：批量操作（整列/整域授权）、diff 预览（保存前展示"给 3 个角色增加了 5 个权限码"）、冲突检测（互斥/套餐超限）前置到编辑期。
- 数据模型：编辑器操作的是"草稿快照"，保存=提交 diff 给权限中心走审批，不是直接改生效数据——权限变更是高危操作必须有审批链。
- 影响预览：保存前调用平台"影响面接口"，告知这次变更影响多少用户、哪些页面会新增/消失入口。

```typescript
// 矩阵草稿与 diff
function applyToggle(draft, role, perm, on) { draft.set(`${role}|${perm}`, on); }
function diffDraft(draft, base) {
  return [...draft.entries()]
    .filter(([k, v]) => base.get(k) !== v)
    .map(([k, v]) => ({ role: k.split('|')[0], perm: k.split('|')[1], action: v ? 'grant' : 'revoke' }));
}
// 保存前：const impact = await api.post('/perm/impact-preview', diffDraft(...));
// impact = { usersAffected: 128, pagesGained: ['order/audit'], pagesLost: [] } → 展示后走审批提交
```
