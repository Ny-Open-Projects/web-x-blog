## ARC-239：离线与弱网下的权限表现如何设计？
**答**：
- 离线（PWA/端内弱网）时拿不到新快照，用"最后已知快照"渲染 UI；但**写操作必须服务端终审**——离线队列里的操作在恢复联网后可能被 403，前端要预判。
- 预判策略：入队前用本地快照校验操作权限，无权操作直接阻止入队并明确提示；有权操作入队后标注"基于快照 v123"，恢复联网重放时若服务端权限已变更返回 403，做温和的失败处理（ARC-056 同步队列思想）。
- 弱网：快照请求走 stale-while-revalidate（缓存快照立即用，后台刷新）；权限版本号进请求头，服务端发现过期随响应带上新版本触发热更。
- 边界：高危操作（支付/审批）在"快照过期超 TTL"时强制要求联网复核，不允许离线队列。

```typescript
queue.enqueue = (op) => {
  if (!can(store.snap, op.action, op.resource)) throw new PermError('无权限操作，未加入离线队列');
  return persist({ ...op, snapVersion: store.snap.version, risky: isSensitive(op) });
};
function replay(op, res) {
  if (res.status === 403) {                 // 服务端权限已变
    toast(`权限已变更（快照 v${op.snapVersion}），操作未执行`);
    audit.report({ type: 'offline-perm-denied', op });
  }
}
// 高危规则：isSensitive(op) && isStale(store.snap, 10 * 60_000) → 阻止入队，要求联网复核
```
