## ARC-386：列表页与详情页的数据一致性架构如何设计？
**答**:
- 经典场景：列表看到"有货"，详情页"无货"；列表点赞数 12，详情页 11。根因是两个接口的读取时点与缓存策略不同。
- 策略一：详情页作为唯一事实源——进入详情后用详情数据反向更新列表缓存（TanStack Query 的 setQueryData），列表回显一致。
- 策略二：详情页变更事件广播——列表订阅变更消息（相同 tab 内 store 事件或跨 tab BroadcastChannel），局部 patch 对应行。
- 策略三：关键状态字段列表与详情同源同缓存键（如库存直接用 queryKey 共享），非关键展示字段容忍最终一致。
- 缓存失效协议：详情页修改成功后 invalidate 关联列表（tag 失效），但避免全列表 refetch 的闪烁——用乐观 patch 优先，失效兜底。
```javascript
// TanStack Query：详情变更回写列表
const { data: detail } = useQuery(['detail', id]);
const qc = useQueryClient();
async function toggleLike(id) {
  const next = await api.like(id);
  qc.setQueryData(['detail', id], next);                 // 详情更新
  qc.setQueryData(['list'], (list) =>
    list.map(item => item.id === id ? { ...item, likes: next.likes } : item)); // 列表回写
}
```
