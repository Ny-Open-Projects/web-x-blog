## ARC-501：评论系统的前端架构
**答**:
- 数据模型：扁平 + parent 引用（两层楼中楼，主流——无限层级递归渲染与分页都难做）；树渲染扁平化遍历（ARC-485 思想），"查看更多回复"懒加载子楼。
- 发表链路：敏感词前端预检（服务端终审 ARC-158）→ 乐观插入（本地临时 ID）→ 服务端确认替换正式 ID → 失败回滚提示；审核中状态显式（"审核通过后展示"）。
- 实时更新：新评论 WS 推送 → 增量插入（不打断阅读位置：仅顶部提示"有 N 条新评论"点击加载，不自动插入防跳动）。
- 分页与排序：cursor 分页 + 排序切换（热/时间）缓存各排序的游标；已读位置记忆。
- 交互细节：点赞乐观更新与对账（ARC-460）、举报流程、楼中楼折叠、长评折叠展开、删除自己评论的级联显示（"已删除"占位保留结构）。
```javascript
// 乐观发表
async function postComment(content) {
  const tmpId = `tmp_${nanoid()}`;
  store.insert({ id: tmpId, content, status: 'posting' });       // 乐观插入
  try {
    const saved = await api.create({ content, idempotencyKey: tmpId });
    store.replace(tmpId, saved);                                 // 换正式 ID
  } catch (e) {
    store.update(tmpId, { status: 'failed', error: errMsg(e) }); // 就地重试入口
  }
}
```
