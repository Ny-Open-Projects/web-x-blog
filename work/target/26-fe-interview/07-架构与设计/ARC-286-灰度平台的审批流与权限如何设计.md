## ARC-286：灰度平台的审批流与权限如何设计？
**答**：
- 权限模型：发布/灰度动作按"应用+环境"两级授权——开发有 dev 权限、owner 有 staging、灰度放量需要 owner+QA 双签、full 需要 tech lead。用 RBAC（ARC-068/221）落地：权限码形如 `deploy:canary:home-app`。
- 审批流分级：常规灰度（自动审批，gates 全绿即放行）、高风险（涉及交易链路/核心页面，走双人审批）、紧急回滚（免审批，人人可触发——止损优先，事后审计）。
- 审计完整性：每次放量/回滚记录 who/when/build/before-after 比例，不可篡改（append-only），复盘与事故归因的依据。
- 大促联动：日历门禁（ARC-263）作为审批流的前置条件注入，冻结期自动升级审批级别。

```typescript
// 灰度动作权限与审批
async function rampUp(app, from, to, operator) {
  if (!can(operator.perms, 'deploy', `canary:${app}`)) throw new PermError();
  const risky = touchesTradePath(app);
  if (risky && !(await dualApproval(app, from, to))) throw new ApprovalError();
  await pointer.set(app, to, { by: operator.id, prevRatio: from });     // append-only 审计
}
// 紧急回滚免审批：
function rollback(app, operator) {
  if (!onDuty(operator)) audit.flag('unauthorized-rollback');           // 事后审计
  return pointer.set(app, lastGreen(app));                              // 止损优先
}
```
