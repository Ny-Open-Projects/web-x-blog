## ARC-360：可观测性深水区：如何保证监控数据本身可信？
**答**：
- 数据不可信的三类来源：采集缺陷（SDK bug、埋点错位）、传输损耗（丢包/拦截/隐私插件丢弃）、口径漂移（指标定义被悄悄改）。
- 采集侧：SDK 发版前跑一致性测试（模拟场景构造预期事件序列）；双跑期新旧 SDK 数据对账；SDK 自身错误上报（meta-SDK）。
- 传输侧：上报成功率指标化（上报失败也计数，指数退避重试 + 本地兜底队列）、对数校验（上报量 vs PV 的比值监控，比值突变即报警）。
- 口径侧：指标字典统一管理（定义/公式/采集点唯一出处）、口径变更走评审 + 新旧并行两周 + 醒目断点标注。
- 终极校验：三角互证——RUM、拨测、日志三条独立链路对同一 SLI 的估计差异在阈值内才可信。
```javascript
// 数据可信度巡检：比值监控
function checkSanity() {
  const ratio = pvReported / pvServerSide;              // 前端上报 PV / 服务端 PV
  if (ratio < 0.8) alert('上报丢失率异常：可能被拦截或 SDK 故障');
  if (Math.abs(errorRateNow - errorRate7dAvg) > 5 && releaseUnchanged)
    alert('口径或采集疑似漂移，无发布关联');
}
```
