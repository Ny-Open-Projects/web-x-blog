## ARC-216：联邦运行时的内存与实例治理？
**答**：
- 内存三大泄漏源：卸载的页面仍持有 remote 模块引用（模块注册表只增不减）、共享单例上累积监听器、跨应用事件总线挂了没解绑。
- 实例治理：非 singleton 共享会实例化多份（内存膨胀），singleton 会互相影响（版本收敛），策略是"框架类 singleton + 工具类 singleton + 业务组件非共享"。
- 生命周期对齐：给联邦模块注入 unload 钩子（主应用路由卸载时广播），子应用清理自己的监听/定时器；平台监控每个 remote 的引用计数。
- 手段：Chrome Memory 面板按 remote 名做 retainers 分组排查，Heap snapshot diff 对比"进入→退出"联邦页面。

```javascript
// 带卸载通知的联邦模块加载器
const refCount = new Map(); // remote 名 → 引用计数
function useFederated(id) {
  const mod = useMemo(() => loadRemote(id), [id]);
  useEffect(() => {
    refCount.set(id, (refCount.get(id) ?? 0) + 1);
    return () => {
      const n = refCount.get(id) - 1;
      refCount.set(id, n);
      if (n === 0) mod?.__unload?.();                 // 最后一个引用退出 → 通知子应用清理
    };
  }, [id]);
  return mod;
}
// 子应用 expose 侧：export const __unload = () => bus.offNamespace('shop'); // 解绑自己挂的全局监听
```
