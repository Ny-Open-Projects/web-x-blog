## ARC-595：骨架屏体系
**答**:
- 骨架的价值与代价：消除"白屏焦虑"（感知性能 ARC-494），但做不好反而有害（骨架与真实内容尺寸不符 → CLS + 跳变；骨架展示过久比 loading 更糟）。
- 体系化方案：骨架与组件绑定（组件声明自己的骨架形态——不是页面手绘骨架图：Skeleton.Table(rows=10)），尺寸一致性约束（骨架尺寸 ≈ 内容尺寸：同 token 布局——降低 CLS）、超时退化（骨架 > 3s → 换错误态/重试态——骨架不是无限等待的遮羞布）。
- 自动化：组件库内置骨架变体（每个数据组件标配 skeleton 属性——开发零成本获得）、SSR 场景骨架（流式渲染的 placeholder 与骨架统一 ARC-064）。
- 视觉规范：骨架动画统一 token（ shimmer 曲线/速度——禁各组件自定义动画 ARC-471 token）、暗色主题骨架适配（ARC-561）。
- 数据驱动：骨架曝光时长统计（> 2s 的骨架实例数——骨架场景优化的信号：该加速数据而不是美化骨架）。
```tsx
// 组件绑定骨架
<GoodsList skeleton={{ rows: 6 }} data={list} />                 // 组件声明骨架形态
// 超时退化
useSkeletonTimeout(3000, { onTimeout: () => setError('加载超时') }); // 骨架不是无限遮罩
```
