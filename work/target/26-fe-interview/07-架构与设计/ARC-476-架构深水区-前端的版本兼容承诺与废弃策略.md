## ARC-476：版本兼容承诺与废弃策略
**答**:
- 兼容承诺分级：core API（两个大版本兼容，废弃先告警后移除）、实验 API（不承诺，命名 experimental 前缀）、协议类（schema 版本化，长期兼容读）。
- 废弃流程：deprecate（运行时告警 + 文档标注 + 替代方案链接）→ 观察期（使用量监控，降到阈值下）→ 移除（大版本 + codemod 迁移工具）。移除前必须给迁移路径，否则告警无效。
- 使用量驱动：每次运行时告警带调用方标识（应用名+版本）上报，形成"谁还在用"清单——废弃推进对象明确，而不是广而告之等人自觉。
- 多版本共存支持：SDK 多版本共存协议（ARC-417）保证宿主渐进升级期间新旧版本不互相破坏。
- 承诺写入 SLA：平台团队对外发布"兼容政策"（语义化版本 + 支持窗口），违反承诺的事故按平台事故定责。
```javascript
// 运行时废弃告警 + 使用量上报
export function deprecated(fn, { alt, until, name }) {
  return function (...args) {
    reportDeprecation({ api: name, caller: detectApp(), until, seenAt: Date.now() }); // 谁在用
    console.warn(`[deprecated] ${name} 将在 ${until} 移除，请迁移至 ${alt}`);
    return fn.apply(this, args);
  };
}
// 使用量降到阈值（如 30 天零调用）→ 进入移除排期
```
