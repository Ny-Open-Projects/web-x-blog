## ARC-548：第三方脚本治理架构
**答**:
- 三方脚本的问题：体积失控、性能拖累（同步阻塞/长任务）、安全风险（被黑后供应链攻击 ARC-363）、不可控更新（对方改代码你的页面炸）。
- 治理框架：注册制（三方脚本清单：用途/提供方/体积/加载时机/负责人——新脚本进清单走评审，页面禁引清单外脚本，lint/构建扫描）、统一加载器（loadingOrchestrator：延迟加载/交互后加载/按需加载 ARC-405/436，禁同步 script）、隔离（iframe 沙箱/Worker 内运行可行时——重计算三方下沉 Worker）。
- 安全：SRI 锁定版本（ARC-363）+ 版本更新走变更流程（对方升级=你的发布）、CSP 白名单收紧、三方脚本的错误隔离（window.onerror 不被三方污染——错误归属打标）。
- 性能对账：三方脚本资源占比监控（性能面板按脚本 owner 归因）、三方引入的 long task 告警——证据驱动与提供方谈判。
- 退役机制：使用率统计（转化贡献为零的营销脚本下线——多数三方脚本没人记得为什么存在）。
```javascript
// 三方脚本注册与统一加载
const thirdParty = {
  'track-sdk': { src: 'https://cdn.3p.com/t.js', mode: 'idle', sri: 'sha384-...', owner: 'data-team' },
  'cs-widget': { src: '...', mode: 'interaction', owner: 'support-team' }
};
function load3p(key) {
  const c = thirdParty[key];
  verifySri(c);                                                  // SRI 校验
  loader.load(c.src, { mode: c.mode, attrs: { async: true } });  // 统一编排
}
```
