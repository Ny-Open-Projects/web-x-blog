## ARC-394：技术方案如何向上沟通与争取资源？
**答**:
- 管理层语言是"业务影响 + 风险 + 成本"，不是技术名词。结构：现状问题（量化）→ 不做的后果（事故概率/效率损失）→ 方案与投入（人力/周期）→ 里程碑与收益（可验证）。
- 量化技巧：把技术债折算成工时（每周因老架构多花 X 人日）、把性能折算成转化率（加载每慢 1s 转化降 X%）、把稳定性折算成事故成本。
- 争取资源的策略：小切口先要"试点资源"跑出数据，再扩大投入；绑定业务诉求（大促稳定性）搭车推进；分期承诺（每期独立可交付）降低决策压力。
- 向上管理节奏：提前 1~2 个季度预告（给排期留位）、定期同步进展（避免"钱花了没动静"质疑）、坏消息早说（风险暴露越早代价越小）。
- 被拒绝后的路径：降级为最小可行版本先做、纳入下一季度、用复盘中的事故数据再申请。
```javascript
// 向上汇报结构模板
const proposal = {
  problem: '首页 LCP 3.8s，转化率低于竞品 15%（数据来源：RUM + 业务报表）',
  cost: '2 人 × 6 周',
  plan: ['图片与脚本治理', 'SSR 迁移', '监控闭环'],
  benefit: 'LCP 降至 2.5s 内，预估转化 +5%，季度 GMV 增量 X 万',
  milestone: '第 2 周可灰度验证第一阶段效果'
};
```
