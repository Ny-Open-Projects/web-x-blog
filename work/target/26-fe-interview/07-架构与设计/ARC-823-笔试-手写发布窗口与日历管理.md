## ARC-823：手写发布日历

**答**：实现发布日历管理器 `ReleaseCalendar`：① 窗口登记：`register(app, time, scope)`——各应用发布窗口登记；② 冲突检测：同日多应用发布告警（故障归因混乱风险）、共享依赖变更的应用发布重叠（必须错峰）——两级冲突；③ 冻结期管理：大促冻结窗口（24~48h）——冻结期内 release 请求拒绝（bugfix 特批通道）；④ 历史数据：发布-故障相关性分析（过去 N 次故障的发布时间分布——数据校准发布规则）；⑤ 日历视图：周视图（各应用发布排期）+ 冻结期高亮。写出实现。

```javascript
class ReleaseCalendar {
  #windows = []; #frozen = []; #incidents = [];
  register(app, time, { scope = 'normal', sharedDeps = [] } = {}) {
    const sameDay = this.#windows.filter((w) => sameDay(w.time, time) && w.app !== app);
    if (sameDay.length) warn(`同日多应用发布: ${sameDay.map((w) => w.app).join(',')} — 归因风险`);
    // 共享依赖重叠检测
    for (const w of this.#windows) {
      if (sameDay(w.time, time) && sharedDeps.some((d) => w.sharedDeps?.includes(d)))
        throw new Error(`共享依赖 [${sharedDeps}] 与 ${w.app} 发布重叠 — 必须错峰`);
    }
    // 冻结期拦截
    if (this.#frozen.some(([s, e]) => time >= s && time <= e))
      throw new Error('发布窗口在冻结期 (bugfix 走特批)');
    this.#windows.push({ app, time, scope, sharedDeps });
  }
  addFreezeWindow(start, end, reason) { this.#frozen.push([start, end, reason]); }
  emergencyFix(app, reason) {                          // 特批通道
    const inFreeze = this.#frozen.some(([s, e]) => Date.now() >= s && Date.now() <= e);
    if (!inFreeze) throw new Error('非冻结期无需特批');
    return { approved: true, reason, expiresAt: Date.now() + 4 * 3600e3 };   // 特批 4h 有效
  }
  correlate() {                                        // 发布-故障相关性
    const byHour = new Map();
    for (const inc of this.#incidents) {
      const related = this.#windows.filter((w) =>
        w.time < inc.time && inc.time - w.time < 72 * 3600e3);
      for (const w of related)
        byHour.set(w.time.getHours(), (byHour.get(w.time.getHours()) ?? 0) + 1);
    }
    return byHour;                                     // 发布小时 × 故障数 → 数据校准规则
  }
}
```

**评分点**：
- 两级冲突检测（同日多应用告警 / 共享依赖重叠阻断）
- 冻结期拦截 + 特批通道（4h 有效期）
- 发布-故障相关性分析（数据校准发布规则——而非迷信）
- 周视图冻结高亮（可产出但代码体现数据结构）
