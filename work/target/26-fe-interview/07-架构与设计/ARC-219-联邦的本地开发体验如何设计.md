## ARC-219：联邦的本地开发体验如何设计？
**答**：
- 痛点：联调要同时起 N 个子应用，dev server 链路不稳定。方案是**混合模式**：本地只起当前开发的应用，其他依赖走远端 stage/prod 的稳定产物。
- 实现：运行时按环境解析 remote——本地开发时 `shop → stage manifest`，被开发的应用 `shop → localhost:3001/mf-manifest.json`；用环境变量 + 运行时 hook 切换。
- 辅助工具：CLI 一键"拉取远端 expose 清单到本地 stub"（类型提示 + mock 数据）；断点调试远端产物用 sourcemap 映射。
- 红线：本地永远不连 prod 产物（数据安全），stage 产物每日从主干构建保证新鲜。

```javascript
// 按环境解析 remote 地址
function resolveEntry(name) {
  if (process.env.NODE_ENV !== 'development') return prodManifest(name);
  if (process.env.DEV_APPS?.includes(name)) return `http://localhost:${ports[name]}/mf-manifest.json`;
  return stageManifest(name);                                  // 混合模式核心
}
registerRemotes(Object.keys(apps).map(n => ({ name: n, entry: resolveEntry(n) })));
// stub 生成：mf-pull shop --expose ./CartPage  → 生成本地声明 + mock 数据，开发时 import('shop/CartPage') 有类型
// sourcemap：CDN 产物上传 .map，DevTools 里 loadRemote 的模块可直接断点
```
