## ARC-377：大文件与媒体上传架构如何设计？
**答**：
- 主链路：MD5/哈希预检（秒传）→ 申请上传凭证（服务端签发，前端不持密钥）→ 分片直传对象存储（前端→OSS 直传，绕过应用服务器带宽）→ 合并回调 → 服务端校验入库。
- 分片设计：分片大小按网络自适应（弱网 1MB，WiFi 8MB）；并发 3~5 路，失败分片单独重试；分片序号 + 文件哈希作为幂等键。
- 可靠性：断点续传（分片状态持久化到 IndexedDB）；页面关闭前 beforeunload 提示；上传队列优先级与暂停/恢复。
- 安全：文件类型魔数校验（不只看扩展名）、大小限额、病毒扫描钩子、私有读走签名 URL + 过期时间。
- 体验层：进度（分片级）、速度显示、失败原因分类提示、弱网自动降并发。
```javascript
async function upload(file) {
  const hash = await hashFile(file);
  const existed = await api.check(hash);
  if (existed) return { fastUpload: true };          // 秒传
  const { uploadId, urls } = await api.createSession({ hash, size: file.size });
  const chunks = slice(file, adaptiveChunkSize());
  const pool = new ConcurrencyPool(4);
  await pool.all(chunks.map((c, i) => () =>
    retry(() => fetch(urls[i], { method: 'PUT', body: c }), { retries: 3, backoff: 'exp' })
  ));
  return api.complete({ uploadId, hash });           // 合并 + 校验
}
```
