## ARC-301：低代码平台的测试与质量保障如何设计？
**答**：
- 质量对象三层：引擎自身（单元/集成测试，普通前端测试体系）、物料（组件测试+物料快照）、**搭建产物页面**（用户搭出来的页面——最难，平台要替用户兜底质量）。
- 产物页面质量手段：发布前自动检查（渲染无报错冒烟、死链检测、性能基线：节点数/图片体积）、预览环境强制人工过一遍（确认制发布）、高危操作二次确认（删除数据源绑定）。
- 引擎回归：内置"黄金页面集"（典型 DSL 样本），每次引擎发版跑渲染快照 + 性能基准，防引擎升级打挂存量页面——这是低代码平台的生命线。
- 用户侧数据保护：自动保存草稿（每 30s）、操作历史可回滚（ARC-295）、误删恢复（软删除 7 天）。

```typescript
// 引擎黄金页面回归
const goldenPages = loadFixtures('golden/*.dsl.json');
test.each(goldenPages)('render $title stable & performant', async (dsl) => {
  const { html, ms } = await renderToString(compilePage(dsl));
  expect(html).toMatchSnapshot();                                  // 渲染结果快照
  expect(ms).toBeLessThan(perfBudget(dsl.components.length));      // 按节点数分档预算
});
// 发布检查清单：smokeRender ✓ / deadLinks ✓ / perfBaseline ✓ / i18nCoverage ✓ → 人工预览确认 → 发布
```
