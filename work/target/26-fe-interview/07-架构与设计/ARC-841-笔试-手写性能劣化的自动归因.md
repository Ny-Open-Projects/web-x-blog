## ARC-841：手写性能劣化归因

**答**：实现性能劣化的自动归因器 `PerfAttributor`：① 输入：指标劣化（LCP P75 从 2.1s→2.8s）+ 关联上下文（近期发布列表/资源体积变化/依赖变更）；② 假设生成：从上下文产出假设排序（最近发布的变更/资源体积增长/新增依赖的初始化耗时）；③ 假设验证：每个假设的验证查询（该发布版本的 LCP 对比/资源瀑布对比）——验证后排序置信度；④ 输出：归因报告（最可能根因 + 置信度 + 验证数据 + 修复建议）；⑤ 归因的知识沉淀：归因结果入库（同模式劣化的快速归因——模式库）。写出实现。

```javascript
class PerfAttributor {
  #hypothesisGenerators = [
    { name: 'recent-release', gen: (ctx) => ctx.recentReleases.map((r) => ({
        hypothesis: `发布 ${r.version} 引入劣化`,
        verify: async (api) => {
          const before = await api.metricFor(r.previousVersion);
          const after = await api.metricFor(r.version);
          return { confidence: after > before * 1.15 ? 0.8 : 0.2, data: { before, after } };
        } })) },
    { name: 'asset-growth', gen: (ctx) => ctx.assetDelta > 100 * 1024 ? [{
        hypothesis: `资源体积增长 ${(ctx.assetDelta / 1024).toFixed(0)}KB`,
        verify: async () => ({ confidence: 0.6, data: { delta: ctx.assetDelta } }) }] : [] },
  ];
  async attribute(degradation, context, metricApi) {
    const hypotheses = this.#hypothesisGenerators.flatMap((g) => g.gen(context));
    const verified = [];
    for (const h of hypotheses) {
      const result = await h.verify(metricApi);
      verified.push({ hypothesis: h.hypothesis, ...result });
    }
    verified.sort((a, b) => b.confidence - a.confidence);
    const top = verified[0];
    return {
      rootCause: top?.hypothesis ?? '未找到明显根因',
      confidence: top?.confidence ?? 0,
      report: verified, fix: top?.confidence > 0.6 ? '回滚或修复该变更' : '需人工排查',
      patternKey: hash(top?.hypothesis ?? 'unknown'),   // 沉淀模式库
    };
  }
}
```

**评分点**：
- 假设生成器可扩展（发布/资源/依赖多源假设）
- 假设验证的置信度排序（验证后排序——非拍脑袋）
- 修复建议的置信度门槛（0.6 才建议行动）
- 模式库沉淀（同模式劣化快速归因）
