## ARC-589：技术债定价与偿还排期
**答**:
- 债务定价模型：利息（每周因该债务额外消耗的工时：绕行开发/排查耗时/新人理解成本——用数据估：相关工单数 × 平均处理时长）+ 本金（偿还所需工时）+ 风险（引发事故的概率 × 预计损失）。利息高/风险高的债优先还——不是"看起来乱"的优先。
- 债务清单治理：债务登记（每笔债：现象/根因/利息估算/偿还方案/owner）——清单公开透明（团队知道债在哪）、利息复评（业务变化利息会变——半年复评）。
- 偿还策略：专项偿还（利息最高的债立项集中还）、顺手偿还（触碰到债务代码的功能开发要求先还——ARC-562 一致性巡检联动）、结构预防（偿还后防复发：适应度函数 ARC-396 卡住）。
- 排期机制：固定偿还预算（如每迭代 10% 工时——没有预算的偿还计划是空话 ARC-588 联动）、偿还里程碑（可验证：利息工时下降数据）。
- 汇报：债务账本（总利息工时/已还/新增——趋势向好是治理有效的证据 ARC-430）。
```javascript
// 债务定价
const debt = {
  id: 'D-012', desc: 'legacy 表单组件三处复制',
  interest: { hoursPerWeek: 3, evidence: '近 3 月相关工单 14 个' },   // 利息
  principal: 12,                                                    // 本金（人日）
  risk: { incidentProb: 0.1, costIfHappens: 'high' },
  plan: '统一到 FormEngine（schema 复用）', owner: 'app-team', quota: '每迭代 1 人日'
};
```
