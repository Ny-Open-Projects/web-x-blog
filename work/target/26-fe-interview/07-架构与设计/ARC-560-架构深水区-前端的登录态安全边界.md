## ARC-560：登录态浏览器端安全边界
**答**:
- token 存储权衡：HttpOnly Cookie（XSS 拿不到 token，但 CSRF 需防护：SameSite + CSRF token）、localStorage（便捷但 XSS 可读——配合 CSP/Trusted Types 降低 XSS 概率 ARC-435）、内存 + 刷新（最安全：access token 只在内存，refresh 持久——刷新页丢一次会话成本）。
- 协同防线：选 Cookie 路线时把 CSRF 防线做实（SameSite=Lax/Strict + 双提交 cookie 或同步 token）；选 localStorage 路线时 XSS 防线拉满（CSP 严格 + 无 innerHTML + 三方脚本白名单）。
- 最小化原则：token 范围最小（权限窄的 token——不同敏感级操作用不同 scope）、时效短 + 静默刷新、敏感操作不依赖前端 token（二次认证服务端裁决 ARC-454）。
- 会话固定与劫持防护：登录后轮换 session id（防固定）、设备指纹绑定（异常设备使用触发风控 NODE-455）、退出即失效（服务端黑名单，非只删本地）。
- 监控：异常 token 使用模式告警（同 token 多 IP 并发——被盗用特征，NODE-455 联动）。
```javascript
// 双路线选择矩阵
const strategy = {
  cookie: { pros: 'XSS 免疫', cons: 'CSRF 需防护', must: ['SameSite=Lax', 'csrfToken 双提交'] },
  memory: { pros: '页面刷新即失效最安全', cons: '体验（刷新丢会话）', must: ['refresh token HttpOnly', '静默续期'] }
};
// 落地：access token in memory + refresh in HttpOnly Cookie（混合最常见）
```
