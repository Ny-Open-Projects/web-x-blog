## ARC-411：渲染管道架构：从路由切换到像素上屏的全链路如何设计？
**答**:
- 路由切换管道分五段：路由解析与守卫（同步快速）→ 数据预取（并行、超时控制）→ 组件树渲染（Suspense 边界分级）→ 提交与布局（避免强制同步布局）→ 视觉完成（骨架 → 内容 → 图片渐入）。
- 架构设计点：数据预取与代码加载并行发起（路由懒加载 chunk + query 预取同时启动）；Suspense 分级——页面骨架立即出、二级区块各自悬挂；转场动画与数据加载解耦（动画不阻塞交互）。
- 上屏质量度量：从"路由点击"到"可交互"（TTI 局部版）逐段打点（route_start / data_ready / commit / paint / interactive），劣化时能定位到段。
- 管道治理：每段设预算（守卫 < 5ms、预取 < 300ms、渲染 < 16ms×n），预算超标进性能回归门禁。
```javascript
// 路由切换管道（伪码示意）
router.beforeResolve(async (to) => {
  mark('route_start');
  await Promise.all([to.meta.preload?.(), prefetchQueries(to)]);  // 并行
  mark('data_ready');
});
router.afterEach(() => mark('commit'));
onNextPaint(() => mark('paint'));
requestIdleCallback(() => mark('interactive'));                   // 局部可交互
// 管道预算校验：pipelineBudget.check('route_start', 'interactive', 800)
```
