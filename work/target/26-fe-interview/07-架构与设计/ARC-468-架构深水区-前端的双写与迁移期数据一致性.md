## ARC-468：存储迁移期的双写一致性设计
**答**:
- 迁移期场景：端上存储换介质（localStorage → IndexedDB）或换结构（扁平 → 归一化）。风险窗口：新旧读写并存、部分用户数据只在新介质、回滚版本读不到新数据。
- 双写协议：迁移期写操作同时写新（权威）与旧（兼容），读一律读新、新缺失回读旧并回填新；迁移完成标记（版本号写入后停止双写）。
- 迁移执行：启动时检查数据版本 → 未迁移则执行迁移脚本（大数据分批防阻塞主线程）→ 失败可重试（迁移幂等）→ 完成后旧数据保留一个版本周期再清（防回滚）。
- 回滚兼容：旧版本代码读不到新结构时的行为定义——降级到空数据重建（可接受）还是崩溃（不可接受）；迁移脚本向前兼容（ARC-450 只增不改名）。
- 验证：迁移对账（迁移前后记录数一致）、回滚演练（装旧版本读新数据）、中断恢复（迁移中杀进程重启续迁）。
```javascript
async function migrateStorage() {
  if (await meta.get('dataVersion') >= CURRENT) return;       // 已迁移
  const legacy = readLocalStorageAll();
  await idb.bulkPut('main', transform(legacy));               // 幂等迁移
  await meta.set('dataVersion', CURRENT);                     // 原子标记
  scheduleCleanup('legacy', { after: '2 versions' });         // 延迟清理防回滚
}
// 迁移期写：writeBoth(key, v) → idb.put(key, v) && localStorage.setItem(key, v)
```
