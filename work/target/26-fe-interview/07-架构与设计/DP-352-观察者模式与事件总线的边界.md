## DP-352：观察者模式：事件总线的边界

**答**：
- 观察者 vs 发布订阅：观察者是「主体直接通知」（耦合知道彼此），发布订阅是「通过事件中心解耦」——前端常说的「观察者」多为发布订阅
- 适用边界：跨层级的不可预测消费方（埋点/告警/多组件响应同一事件）；不适用：可预测的父子通信（props/emit 更清晰）
- 三大陷阱：订阅泄漏（忘记 off——内存泄漏）、事件风暴（高频事件无节流）、隐式依赖（事件名拼错静默失败）
- 实战防御：命名空间订阅（批量清理）、事件类型常量（防拼错）、dev 模式的事件流日志（可观测）
- 深水点：事件总线与状态管理的边界——「状态」用 store（最新值语义），「事件」用总线（每次发生语义）——混用是混乱之源

```javascript
class EventBus {
  #subs = new Map();
  on(type, fn) {
    const set = this.#subs.get(type) ?? this.#subs.set(type, new Set()).get(type);
    set.add(fn);
    return () => set.delete(fn);          // 返回退订函数 — 防泄漏的标配
  }
  emit(type, payload) {
    for (const fn of [...(this.#subs.get(type) ?? [])]) {
      try { fn(payload); } catch (e) { reportError(e); }   // 错误隔离
    }
  }
}
// 命名空间批量清理:
// const off1 = bus.on('a', f1), off2 = bus.on('b', f2);

```
