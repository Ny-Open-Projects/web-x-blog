## ARC-293：低代码的数据源设计：绑定与依赖追踪？
**答**：
- 数据源模型：声明式数据源（fetch/静态/mock/派生计算），页面 DSL 里组件 props 通过**绑定表达式**引用数据源字段（`{{ds1.data.items}}`），引擎解析表达式建立"组件→数据源"依赖图。
- 依赖追踪与更新：数据源状态变化 → 反查依赖该源的组件 → 精确重渲染（不要整页刷新）。实现上可在编译期静态解析绑定生成依赖表（快、稳），或运行时 Proxy 收集（灵活、容错）。
- 级联数据源：ds2 依赖 ds1 的结果（ds1 加载完自动触发 ds2），引擎要有依赖排序与失败处理（上游失败下游跳过并标记）。
- 安全边界：表达式执行环境受限沙箱（白名单上下文，无 window/document），防低代码用户写出危险表达式。

```typescript
// 编译期依赖提取
function extractDeps(expr: string) {           // "{{ds1.data.items.length}}"
  return [...expr.matchAll(/ds(\w+)\./g)].map(m => `ds${m[1]}`);
}
const deps = new Map();                        // nodeId → Set<dsId>
function bind(node, props) { deps.set(node.id, flatMap(props, p => extractDeps(String(p.value)))); }
function onDsUpdate(dsId) {
  for (const [nodeId, ds] of deps) if (ds.has(dsId)) rerender(nodeId);   // 精确更新
}
// 级联：topoSort(dataSource).forEach(ds => run(ds, resultsOf(upstream(ds))))
// 表达式沙箱：new Function('ctx', `with(ctx) { return (${expr}); }`)，ctx 仅含 dataSources/state/工具函数
```

**追问**：

1. 绑定位写 `{{a ? ds1.x : ds2.y}}` 这类动态引用，正则提依赖会漏，怎么办？ → 正则只能抓字面量，要解析成表达式 AST 收集全部成员访问路径；动态 key 取不到时按保守策略登记全部数据源，宁可多渲染也不能漏更新。
2. 数据源整体变了但组件只用 `items.length`，怎么避免整块重渲染？ → 依赖粒度下沉到字段路径，配合选择器与浅比较，只有该路径的值变化才通知组件。
3. 沙箱用 with 加 new Function 有性能与逃逸风险，怎么加固？ → 生产改用表达式解释器按 AST 求值，或放 iframe 里隔离；至少冻结原型链、封掉 constructor 这类逃逸路径。
