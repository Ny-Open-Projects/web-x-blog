## DP-351：策略模式：表单校验的策略组合

**答**：
- 策略模式的核心：把「变化的算法族」封装为可替换的策略——校验规则（手机号/身份证/自定义）是典型场景
- 实战要点：策略注册表（Map<ruleName, validator>）+ 校验编排（字段的 rules 数组按序执行——短路或聚合两种语义）
- 与硬编码 if-else 的对比：新增校验规则只加策略不改主流程（开闭原则）；测试独立（每个策略单测）
- 组合实战：策略 + 责任链（校验按依赖顺序执行）+ 错误聚合（全部执行收集所有错误 vs 短路返回第一个）
- 深水点：策略的「上下文注入」——校验器需要表单全量数据（跨字段校验）——策略签名设计 `(value, allValues) => error`

```javascript
const strategies = new Map([
  ['required', (v) => (v == null || v === '' ? '必填' : null)],
  ['phone', (v) => (/^1\d{10}$/.test(v) ? null : '手机号格式错误')],
  ['minLength', (n) => (v) => (v.length < n ? `至少 ${n} 字` : null)],
]);

function validateField(value, rules, allValues, { shortCircuit = false } = {}) {
  const errors = [];
  for (const rule of rules) {
    const [name, ...args] = Array.isArray(rule) ? rule : [rule];
    const fn = strategies.get(name);
    if (!fn) throw new Error(`unknown rule: ${name}`);
    const err = fn(...args)(value, allValues);
    if (err) {
      errors.push(err);
      if (shortCircuit) break;
    }
  }
  return errors;
}
// 用法: validateField('138', ['required', 'phone'], formData) → ['手机号格式错误']
// 新增身份证校验: strategies.set('idcard', fn) — 主流程零改动
```

**答**（要点）：策略注册表 + 参数化规则（minLength(n) 是「策略工厂」）；聚合 vs 短路两种语义按 UX 选；跨字段校验靠 allValues 上下文注入。
