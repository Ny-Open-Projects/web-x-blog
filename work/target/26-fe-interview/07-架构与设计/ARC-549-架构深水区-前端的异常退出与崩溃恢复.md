## ARC-549：异常退出与崩溃恢复
**答**:
- 覆盖退出场景：页面刷新/关闭（beforeunload 可拦截但不可依赖——崩溃时不会触发）、浏览器崩溃、Tab 被杀（移动端后台回收）、断电。设计原则：任何时刻崩溃，重启后用户进度不丢（ARC-488 恢复三要素落地到页面级）。
- 持久化节奏：关键状态持续写（storage 事件节流 1s 或关键动作即写——编辑器逐 op、表单逐字段）、会话快照（路径 + 组件状态 + 草稿），恢复时全量还原。
- 崩溃检测：连续异常退出检测（sessionStorage 计数：本次会话无正常 unload 结束 → 标记崩溃恢复，恢复后提示 + 引导 + 崩溃上报——崩溃率统计进监控）。
- 恢复 UX：恢复确认（检测到未完成流程 → "继续上次/重新开始"）——不静默恢复（用户可能想重来）也不丢弃。
- 长流程特化：考试/填写类（ARC-519 答案即存）、支付中断恢复（查单兜底 ARC-418）、向导恢复（ARC-489）。
```javascript
// 会话状态持久化 + 崩溃标记
sessionStorage.setItem('alive', '1');
addEventListener('beforeunload', () => sessionStorage.removeItem('alive'));
// 启动：sessionStorage.getItem('alive') === '1' → 上次未正常退出（崩溃）
if (wasCrashed()) { track('crash-recovered'); offerResume(lastSnapshot()); }
// 持久化：store.subscribe(debounce(s => idb.set('session', snapshot(s)), 1000))
```
