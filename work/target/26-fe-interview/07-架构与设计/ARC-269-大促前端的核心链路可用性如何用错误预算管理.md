## ARC-269：大促前端的核心链路可用性如何用错误预算管理？
**答**：
- SLO 定义（前端口径）：核心页面可用性 = 1 - 白屏率 - 致命 JS 错误率（页面不可交互的报错），下单链路单独定 99.95%。
- 错误预算 = 1 - SLO：预算内可正常发布迭代；预算耗尽（快燃尽）→ 冻结发布，只修稳定性问题——把"稳"与"快"的矛盾变成可计算的规则。
- 预算消耗看板：按天展示燃尽进度与消耗来源（错误类型 Top），大促前燃尽 > 80% 自动升级到技术负责人。
- 与发布管控（ARC-263）联动：预算状态作为发布门禁输入，预算耗尽自动收紧灰度比例。

```typescript
// 错误预算计算（日窗口）
const SLO = 0.9995;
const availability = 1 - (whiteRate + fatalErrRate);       // 前端口径可用性
const budgetTotal = 1 - SLO;                               // 0.0005 = 每天 43s 等效不可用
const budgetLeft = Math.max(0, budgetTotal - (1 - availability));
// 看板：budgetLeft / budgetTotal = 燃尽率；> 80% 消耗 → freezeRelease()
// 来源归因：budget.spend = errors.groupBy(type) → Top 类型转治理任务
```
