## ARC-413：前端多环境配置与密钥管理架构如何设计？
**答**:
- 环境矩阵设计：dev/test/staging/prod 各有独立配置集；配置注入分构建期（VITE_ 环境变量，进产物）与运行时（window.__CONFIG__ 或配置接口，改配置不重新构建）。
- 运行时配置优先：网关地址/开关类配置放运行时（HTML 里注入一次），避免"改个域名要重新发版"；构建期只留编译常量（裁剪代码的 flag）。
- 密钥红线：前端产物中不允许出现任何服务端密钥；"前端 API Key"只做调用方标识不做鉴权，真鉴权走后端代理或签名服务（ARC-156）。
- 环境隔离防线：prod 域名/test 域名硬编码白名单（防配置串环境）；test 环境加显式横幅与 noindex；staging 与 prod 数据库完全隔离。
- 配置校验：启动时 schema 校验配置完整性，缺字段 fail fast 而不是运行中 undefined 事故。
```javascript
// 运行时配置注入 + 校验
const envSchema = z.object({
  API_BASE: z.string().url(), UPLOAD_BASE: z.string().url(), FLAG_X: z.boolean().default(false)
});
const config = envSchema.safeParse(window.__CONFIG__ ?? {});
if (!config.success) throw new Error(`配置缺失: ${config.error.issues.map(i => i.path)}`); // fail fast
export const env = config.data;
```
