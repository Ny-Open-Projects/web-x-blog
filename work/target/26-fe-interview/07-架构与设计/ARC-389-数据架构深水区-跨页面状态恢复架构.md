## ARC-389：跨页面状态恢复架构如何设计？
**答**:
- 三种"丢"场景对应三层方案：返回上一页丢（SPA 内 store 清理/组件卸载）→ keep-alive + 滚动位置 + 筛选条件入 URL；刷新丢 → sessionStorage 快照或 URL 参数重放；跨设备丢 → 服务端草稿（用户维度持久化）。
- URL 即状态：筛选/分页/排序入 query（可分享可回退），用 schema 校验与默认值合成，刷新与分享天然恢复。
- 表单草稿策略：自动保存节流（3s 或字段级 debounce）到 sessionStorage + 服务端草稿双写；恢复时提示"检测到未提交草稿"；提交成功清除。
- 恢复的边界：状态中含敏感数据（token/手机号）不落 URL；含临时数据（防重复提交 ID）不恢复；版本不兼容（schema 变更）快照丢弃降级默认。
- 实现收敛：做成框架级能力（路由守卫统一序列化/恢复），而不是每个页面手写。
```javascript
// 路由状态序列化统一层
const listStateSchema = z.object({ kw: z.string().default(''), page: z.number().int().min(1).default(1), sort: z.enum(['time','price']).default('time') });
function useListState() {
  const params = useSearchParams();
  return listStateSchema.parse(Object.fromEntries(params));  // URL→状态（带默认值）
}
function updateListState(patch) {
  router.setQuery(merge(current, patch), { replace: false });  // 状态→URL（可回退）
}
```
