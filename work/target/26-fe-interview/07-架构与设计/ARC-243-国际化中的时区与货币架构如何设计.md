## ARC-243：国际化中的时区与货币架构如何设计？
**答**：
- 三条铁律：**存储永远 UTC**（DB/API 时间戳带时区）、**展示按时区上下文**（用户时区 > 站点时区）、**换算只做一次**（服务端出 UTC+用户时区元数据，前端只格式化）。
- 时区上下文来源：用户资料显式时区 > Intl.DateTimeFormat().resolvedOptions().timeZone 猜测；跨时区业务（会议/航班）必须双时区展示（出发地+当地时间）。
- 货币：金额存储用**最小单位整数**（分）+ 货币码，展示用 Intl.NumberFormat(currency, locale)；汇率换算发生在服务端（汇率带版本号，前端不换算，防止刷新后金额跳动）。
- DST 陷阱：夏令时切换日的"本地时间"有歧义，比较/排序永远用 UTC 时间戳，展示层才转本地。

```typescript
// 时区感知格式化
const fmt = new Intl.DateTimeFormat(locale, { timeZone: userTz, dateStyle: 'medium', timeStyle: 'short' });
fmt.format(new Date(tsUtc)); // tsUtc 永远是 UTC
// 双时区展示（跨时区业务）
function dualZone(ts: number, fromTz: string, toTz: string) {
  return {
    from: new Intl.DateTimeFormat(locale, { timeZone: fromTz, timeStyle: 'short' }).format(ts),
    to:   new Intl.DateTimeFormat(locale, { timeZone: toTz,   timeStyle: 'short' }).format(ts),
  };
}
// 货币展示：new Intl.NumberFormat(locale, { style: 'currency', currency: amount.currency })
//   .format(amount.minor / 100) —— 换算比例与精度由服务端下发，前端只除以最小单位
```
