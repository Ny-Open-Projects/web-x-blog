## ARC-393：前端架构师的角色定位与决策机制如何设计？
**答**:
- 架构师产出物：决策（ADR）、约束（规范/门禁）、能力（基建/工具）、判断（评审/仲裁）；不是"写最难代码的人"，而是"让团队整体产出更好的人"。
- 决策权设计：决策分级—— reversible 的（组件内部设计）团队自决；hard to reverse 的（状态库选型/微前端引入）架构师主导 + 评审会决策；决策记录公开可追溯。
- 避免两个极端：独裁（团队失去成长，架构师成瓶颈）与放任（口径分裂，架构漂移）。解法是"框定边界内的自由"——规范定死边界，边界内团队自选。
- 架构师的杠杆：做一次能被复用 100 次的事（模板/工具/规范），评审里教方法而非改代码。
- 继任设计：决策文档化 + 轮值评审，保证架构师离岗体系不崩（bus factor）。
```javascript
// 决策分级矩阵
const decisionMatrix = {
  reversible:  { examples: ['组件拆分', '工具函数位置'], owner: '开发自决' },
  consequential: { examples: ['状态库选型', '构建迁移'], owner: '架构师提案 + RFC + 评审会' },
  irreversible: { examples: ['微前端引入', '低代码平台自研'], owner: '架构委员会 + ADR 归档' }
};
```
