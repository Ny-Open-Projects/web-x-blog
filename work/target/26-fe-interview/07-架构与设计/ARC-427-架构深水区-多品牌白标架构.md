## ARC-427：多品牌白标前端架构如何设计？
**答**:
- 白标 = 一套代码多个品牌皮肤与功能子集（不同客户 logo/配色/功能开关/域名）。分层：核心能力层（业务逻辑）+ 品牌适配层（主题 token/资源包/功能清单）+ 构建分发层（每品牌一份产物或运行时切换）。
- 主题适配：Design Token 三层（ARC-029）延伸——品牌 token 包独立仓库，构建时注入；资源（logo/字体/图）走 CDN 按品牌路径，不进主包。
- 功能子集：品牌功能清单（feature manifest）驱动路由与组件显隐，禁止品牌 if-else 散落代码（收敛到配置 + 能力探测）。
- 构建策略权衡：构建期多产物（体积小、隔离好，品牌多时构建慢）vs 运行时加载品牌包（灵活，首屏多一次请求）。混合：构建期定品牌集合、运行时定品牌参数。
- 治理：品牌间差异清单化（diff 报告），新品牌接入预算评估（理想 < 1 人周）。
```javascript
// 品牌包结构与加载
const brands = { acme: { theme: 'theme-acme.json', features: ['pay', 'im'], domain: 'acme.com' } };
function detectBrand(host) { return Object.keys(brands).find(b => brands[b].domain === host); }
// 主题：CSS 变量注入
async function applyBrand(brand) {
  const tokens = await fetchJson(`/brands/${brand}/tokens.json`);
  for (const [k, v] of Object.entries(tokens))
    document.documentElement.style.setProperty(`--${k}`, v);   // 全局变量换肤
}
```
