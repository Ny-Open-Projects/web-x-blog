## ARC-298：低代码引擎的插件体系如何设计？
**答**：
- 插件模型：声明式注册（init/engine/destroy 生命周期 + 可声明消费的引擎 API 面），内核通过依赖顺序初始化插件，插件之间通过事件总线与共享上下文通信，禁止直接 import 别的插件（依赖显式声明）。
- 扩展点设计：画布扩展（选中行为/拖拽规则）、属性面板 setter、数据源类型、导出器（出码/预览/发布）。每个扩展点定义 interface，插件实现接口注册。
- 沙箱与兼容：插件运行出错不能拖垮引擎（try/catch 包 init + 插件健康上报）；插件 API 版本协商（engineVersion 范围声明），不兼容时禁用并提示。
- 与 DP-096 插件化呼应：低代码引擎是插件化的最佳练武场——内核小、扩展点多、生态大。

```typescript
interface LcPlugin {
  name: string;
  engineVersion: '^1.0';
  depends?: string[];
  init(ctx: EngineContext): void;       // 注册扩展点
  destroy?(): void;
}
engine.use([designPlugin, dataSourcePlugin, i18nPlugin]);   // 按依赖拓扑初始化
// 扩展点注册示例（数据源类型插件）
dataSourcePlugin.init = (ctx) => {
  ctx.registerDataSource('graphql', { schema: gqlDsSchema, run: gqlRunner, editor: GqlSetter });
};
// 兼容：engine.use(p) → semver.satisfies(engine.version, p.engineVersion) || disable(p, '版本不兼容')
```
