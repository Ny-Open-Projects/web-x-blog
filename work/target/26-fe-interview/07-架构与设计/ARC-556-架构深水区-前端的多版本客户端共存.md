## ARC-556：多版本客户端共存的服务端支持
**答**:
- 现实：H5 无版本概念（即时更新）但 App/小程序版本碎片（用户不更新）——服务端必须同时服务 v1~vN 客户端。核心纪律：服务端接口变更向前兼容（NODE-335/359 多步迁移）+ 客户端能力协商。
- 能力协商：客户端版本/能力清单随请求上报（header X-Client-Cap: search-v2,captcha3）→ 服务端按能力返回适配内容（新字段只给支持的版本/新交互降级）——比版本号判断更精准（同版本多端能力不同）。
- 强更与灰度：最低支持版本策略（低于 minVersion → 强更页——停服旧版本要公告期）；新版本灰度发布（App 版本发布平台：按百分比放增量包——热更场景）。
- 兼容窗口管理：每个废弃接口记录"仍有哪个版本在调"（NODE-448 调用方画像的客户端版本维度）→ 版本渗透率监控 → 渗透达标才下线接口。
- 测试矩阵：多版本客户端回归（最低支持版本跑核心链路——每次服务端发布前，防"只测了新版"）。
```javascript
// 能力协商
const caps = parseCaps(ctx.get('x-client-cap'));                 // ['search-v2','pay-3ds']
const resp = { ...base };
if (caps.has('search-v2')) resp.newField = computeNew();         // 只给支持的版本
ctx.body = resp;
// minVersion 检查：version < MIN → 426 { action: 'upgrade', url: storeLink }
```
