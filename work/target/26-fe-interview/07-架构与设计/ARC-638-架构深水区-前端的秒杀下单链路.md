## ARC-638：秒杀下单链路
**答**:
- 链路设计：秒杀资格（报名/预约 → 开抢）→ 排队页（资格申请 → 排队结果异步通知——削峰 ARC-107/520）→ 预扣单（资格 + 库存预扣 → 生成限时订单——超时未支付释放）→ 支付（ARC-623 正常支付链路）。
- 前端状态机：idle → queued（排队动画 + 进度反馈——等待体验设计：不确定时长用阶段提示）→ granted（预扣成功 → 跳支付，倒计时提醒）→ released（超时释放 → 可重新排队）；服务端状态权威（排队结果推送/轮询双通道）。
- 体验细节：开抢瞬间（倒计时结束 → 请求随机延迟打散——客户端 jitter + 服务端配额）、排队页行为约束（刷新/返回语义——重新排队 vs 放弃的提示）、失败原因可懂（未抢到/资格不符/库存售罄——不同文案）。
- 防作弊配合：设备指纹/行为采集上报（ARC-158/520）、下单按钮防连点 + 请求签名。
- 性能与降级：秒杀页静态化（活动规则/商品信息——ARC-565）、动态接口降级（排队服务挂 → 公平降级：直接进抢但限流——预案 ARC-545）。
```javascript
// 秒杀状态机
const sm = seckillMachine(activityId);
sm.on('start', () => requestJoin(jitter(0, 200)));               // 随机打散
sm.on('queued', () => pollQueue(sm.id));                          // 排队结果双通道
sm.on('granted', ({ preOrderId, expireAt }) => gotoPay(preOrderId, { expireAt })); // 限时订单
sm.on('released', () => offerRequeue());                          // 超时可重新排队
```
