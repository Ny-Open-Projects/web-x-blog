## ARC-563：多语言文案缺失治理
**答**:
- 缺失形态：新 key 未翻（fallback 显示英文 key 或原文）、机器翻译占位上线、硬编码字符串绕过 i18n。治理是持续运营（ARC-255 国际化综述的执行层）。
- 检测三道：构建期（key 覆盖率检查：代码引用的 key 在所有语言包存在，缺失阻断——CI）、运行期（missing-key 上报 ARC-419 fallback 钩子——真实用户访问时发现漏网之鱼，按 key 聚合统计）、巡检期（伪本地化扫描：伪翻译模式暴露硬编码 ARC-458）。
- 治理流程：缺失事件 → 翻译流水线补录（机翻初稿 + 人工审核 ARC-242）→ 热更新下发（无需发版修复——文案包版本化）→ 覆盖率指标归零确认。
- 质量分级：核心路径文案（支付/订单）翻译质量要求高（人工 + 回译校验）、长尾文案机翻可接受——分级投入。
- 度量：各语言覆盖率（按页面/模块切片）、用户反馈的翻译问题工单趋势。
```javascript
// 运行期缺失上报 + 热修
function t(key, params, locale) {
  const msg = pack[locale]?.[key];
  if (!msg) { reportMissing({ key, locale, page: route }); return fallback(key, locale); }
  return icuFormat(msg, params);
}
// 缺失上报 → 翻译平台工单 → 补录 → 文案包发新版本 → 客户端热更新拉取
```
