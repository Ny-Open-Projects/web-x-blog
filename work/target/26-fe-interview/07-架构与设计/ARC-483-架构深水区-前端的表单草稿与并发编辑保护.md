## ARC-483：表单草稿与并发编辑保护
**答**:
- 草稿体系（ARC-389 延伸）：本地草稿（sessionStorage 即时）+ 服务端草稿（跨设备）；保存策略字段级 debounce + 关键字段即时；恢复时版本与时间展示，用户确认后应用。
- 并发编辑保护三档：乐观（单人场景，最后写入胜）、版本号 CAS（提交带 baseVersion，冲突时 diff 展示双方修改让用户选择）、行级锁（强一致场景：进入编辑先加锁，锁心跳保活，超时自动释放）。
- 冲突 UX：不弹生硬"保存失败"——给三方对比（你的修改 / 线上最新 / 合并结果），字段粒度选择；关键业务字段（金额）冲突必须人工裁决。
- 离开保护：有未保存修改时 beforeunload 提示 + 路由内拦截（未保存确认）；自动保存失败的重试与本地兜底。
- 审计：草稿与覆盖操作留痕（谁在何时覆盖了谁），协同纠纷可追溯。
```javascript
async function saveForm(form, baseVersion) {
  try {
    await api.save({ ...form, baseVersion });                 // CAS 提交
  } catch (e) {
    if (e.code === 'VERSION_CONFLICT') {
      const diff = showConflictDialog({ mine: form, theirs: e.serverVersion }); // 三方对比
      await api.save({ ...await diff.merged(), baseVersion: e.serverVersion.version });
    }
  }
}
// 行级锁：editSession = api.lock(rowId) → 心跳 10s → 提交后 unlock → 30s 超时自动释放
```
