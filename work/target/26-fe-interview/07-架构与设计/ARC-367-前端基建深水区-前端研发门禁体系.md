## ARC-367：前端基建：研发门禁体系（提交到发布全链路卡口）如何设计？
**答**：
- 门禁分层：本地（husky 秒级：lint-staged、type 快检）→ MR（分钟级：完整 lint/单测/构建/依赖审计/包体积 diff）→ 发布（人工审批 + 灰度自动观测）。越靠前越快，越靠后越严。
- 关键设计：本地快检防"提交即失败"浪费 CI；MR 卡口全部自动化且 10 分钟内完成，否则开发者会找绕过方法；包体积/性能预算超标需 owner 显式豁免并留痕。
- 防绕过：分支保护强制 MR + 状态检查；管理员合并也走同一路径；紧急通道（hotfix）简化卡单不简化检查，事后补审。
- 门禁指标自身的运营：卡口平均耗时、误杀率（检查失败但实际没问题）、豁免率——豁免率持续走高说明阈值或检查有问题。
```yaml
# MR 门禁流水线（伪 yaml）
stages:
  - name: lint & typecheck   # < 1min, 缓存命中
  - name: unit tests         # 分片并行, < 3min
  - name: build              # 缓存命中 < 2min
  - name: bundle-size-gate   # diff > 5% 阻断
  - name: dep-audit          # high CVE 阻断
required: [lint, test, build, bundle-size-gate, dep-audit]
```
