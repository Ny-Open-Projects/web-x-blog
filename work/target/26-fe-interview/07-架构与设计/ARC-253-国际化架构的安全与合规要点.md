## ARC-253：国际化架构的安全与合规要点？
**答**：
- 数据出境合规：翻译服务调用（尤其第三方机翻）涉及内容出境——敏感内容（用户隐私字段）不进机翻管道；翻译前做敏感信息脱敏（人名/手机号占位）。
- 本地合规差异：不同法域的文案不同（欧盟 GDPR cookie 提示、巴西 LGPD），语言 ≠ 法域，合规文案按"locale+法域"双维度维护。
- 文案注入风险：插值是纯文本拼接，用户可控的动态内容进文案必须转义（富文案白名单标签），防 XSS（例如 UGC 走 ARC-251 链路时清洗）。
- 语言包供应链：语言包若来自外部/众包翻译，进产物前过敏感词与合规扫描，防夹带。

```typescript
// 机翻脱敏管道
async function translateSafe(text: string, target: string) {
  const { masked, secrets } = maskPII(text);                  // 手机号/身份证 → {{s1}} 占位
  const out = await mtService.translate(masked, target);
  return unmask(out, secrets);                                // 译文还原真实值，PII 不出域
}
// 合规文案按法域：dict key 带 region 维度 gdpr.banner（eu） / privacy.note（br）
// 插值转义：t() 默认 HTML escape；确需富文本走 <Trans> 组件白名单节点（b, br, a[href]）
```
