## ARC-414：前端容灾体系：多级降级链如何设计？
**答**:
- 降级链按"离用户最近的资源最后失效"排列：CDN 静态兜底页 → 缓存版本（上次可用 HTML）→ 本地内置版本（App 内置资源包）→ 极简可服务页（服务端硬编码）。每级触发条件与恢复条件明确。
- 触发机制：健康探测（连续 N 次失败）+ 人工开关 + 自动熔断（错误率超阈值）；降级与恢复都要防抖（防止来回切换抖动）。
- 降级分级：功能降级（砍非核心功能）、数据降级（缓存数据替代实时）、渲染降级（SSR 转 CSR）、整页降级（静态兜底页）。每个核心页面预案明确写"降级后用户看到什么"。
- 演练制度化（ARC-264）：季度容灾演练真实触发降级链，验证每级可用、恢复时长达标。
- 可观测：降级事件自动上报与告警，降级时长统计进可用性报告。
```javascript
// 多级降级调度器
const chain = [
  { name: 'cdn-fallback', probe: () => ping('/fallback/index.html'), use: () => location.replace('/fallback/') },
  { name: 'cached-version', probe: () => caches.has('last-good'), use: () => loadFromCache('last-good') },
  { name: 'csr-degrade', probe: () => true, use: () => renderCSR() }    // 最终兜底
];
async function degrade() {
  for (const level of chain) {
    if (await level.probe()) return level.use();
  }
}
// 恢复防抖：连续 5 次探测成功才退出降级
```
