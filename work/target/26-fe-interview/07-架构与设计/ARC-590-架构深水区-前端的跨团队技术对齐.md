## ARC-590：跨团队技术对齐机制
**答**:
- 对齐对象：前端 ↔ 后端（接口协议 ARC-162/392）、前端 ↔ App/小程序团队（多端一致性 ARC-580）、前端 ↔ 设计（token/规范 ARC-562）、前端 ↔ 平台基建（标准与例外 ARC-435）。
- 机制设计：接口协作走契约流程（自动化 ARC-447 通知）、多端对齐例会（双周：跨端功能排期对齐/能力差异同步——低频轻量）、设计协作走规范流程（token 变更评审/走查机制）、与基建的接口是"标准 + 扩展点"（ARC-370 服务分层）。
- 冲突裁决：有预定义的裁决路径（协议分歧 → 架构评审会 ARC-165；规范分歧 → 设计系统委员会）——冲突不可怕，没裁决机制才可怕。
- 共享资产治理：跨团队共用组件/工具的 owner 与发布节奏（ARC-462 复用策略）、共享依赖升级协同（ARC-164 发布顺序）。
- 度量：对齐成本（跨团队联调耗时/协议冲突次数趋势）、对齐质量（跨端不一致 bug 数）。
```javascript
// 对齐机制清单
const alignment = {
  backend: { flow: 'openapi-diff → ack → sunset', cadence: '事件驱动' },
  multiEnd: { flow: '双周例会 + 能力差异表', artifacts: '端差异台账' },
  design: { flow: 'token RFC + 月度走查', artifacts: 'token 管道' },
  infra: { flow: '标准 + 豁免申请', cadence: '季度标准复审' },
  escalation: '分歧 → 架构评审会（预定义裁决路径）'
};
```
