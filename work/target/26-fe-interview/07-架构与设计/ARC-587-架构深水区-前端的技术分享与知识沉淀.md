## ARC-587：技术分享与知识沉淀
**答**:
- 问题：分享会讲完就散（口头知识蒸发）、踩坑经验散在聊天记录。机制设计：让分享产出"可检索资产"且成本可控。
- 分层机制：轻量（踩坑周报：每周值班/开发踩坑 3 条——模板化 15 分钟产出，持续且低成本）、中量（双周分享会：30 分钟 + 讲稿归档）、重量（专项复盘：大故障/大迁移的深度复盘文档——ARC-407/425 产出物沉淀）。
- 沉淀转化：分享 → 文档（讲稿归档进知识库 + 结构化标签 ARC-517）、经验 → 工具（高频踩坑自动检查化——lint/CI 规则，"讲过的坑"变成"代码防的坑"——最高价值的沉淀形态）、案例 → 培训（新人培训材料迭代 ARC-586）。
- 驱动设计：轮值分享（人人有份不抽血少数人）、分享质量反馈（听完能用上的投票——防形式主义）、沉淀计数纳入团队健康指标（ARC-391）。
- 检索闭环：知识库全文搜索 + AI 辅助问答（新问题先搜沉淀——"这个问题是不是踩过"的入口）。
```javascript
// 知识沉淀流水线
const knowledge = {
  weekly: pitfallReport({ template: '现象/原因/修复/预防', timebox: '15min' }),
  biweekly: techTalk({ archive: 'wiki', tags: auto }),
  transform: { pitfall: '→ lint/CI rule', talk: '→ onboarding material' }
};
// 检索：search('拖拽排序并发冲突') → 命中 2026-Q2 踩坑周报 #12 + 拖拽方案 ADR
```
