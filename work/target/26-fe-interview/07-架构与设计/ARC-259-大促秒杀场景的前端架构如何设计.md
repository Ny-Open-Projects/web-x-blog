## ARC-259：大促秒杀场景的前端架构如何设计？
**答**：
- 秒杀前端三大矛盾：瞬时流量（QPS 百倍）、倒计时一致性（零点开抢）、按钮状态正确（防超卖后的体验崩坏）。
- 页面静态化：秒杀页完全静态（CDN 边缘缓存），商品数据+库存状态走**独立轻接口**轮询/长连接，页面壳与状态分离，动静分离抗流量。
- 倒计时方案：服务端下发**当前服务器时间+开抢时间戳**，客户端只算差值（不做本地时钟对齐）；临近开抢时用 NTP 校准接口二次校正；防提前点：按钮倒计时结束才可点，服务端依然终审。
- 流量治理：客户端随机延迟打散请求（0~500ms 抖动）、点击防抖+一次性 token、失败快速反馈不无限重试（指数退避+封顶）。

```typescript
// 服务端对齐的倒计时
const { serverTime, startAt } = await api.get('/seckill/clock');   // 一次往返拿两个时间
const skew = serverTime - Date.now();                              // 时钟偏差
function remainMs() { return startAt - (Date.now() + skew); }      // 用偏差校正后的本地时间
setInterval(() => setRemain(remainMs()), 250);
// 抢购请求：开抢瞬间 + jitter
setTimeout(submit, Math.random() * 300);                           // 300ms 内打散
async function submit() {
  const r = await api.post('/seckill/order', { sku, onceToken }, { retries: 3, backoff: 'exp' });
  if (r.code === 'SOLD_OUT') setState('已抢完');                    // 快速终态，不再重试
}
```
