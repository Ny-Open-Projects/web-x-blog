## ARC-369：前端基建：多端配置中心架构如何设计？
**答**：
- 配置分类：业务开关（feature flag）、参数调优（阈值/文案）、紧急开关（降级熔断）；不同类别变更频率与审批要求不同，schema 分开管理。
- 端上架构：启动拉取 + 本地缓存兜底（断网可用上次快照）；轮询或长连接推送更新；开关值带版本号与生效时间，支持定时生效与放量比例。
- 一致性：多端（Web/小程序/App）同一开关 ID，各端 SDK 语义一致；分桶逻辑端侧实现时必须与服务端同构（同 hash 算法），否则实验数据错乱。
- 安全与回滚：改配置即改线上行为，走发布级审批；每次变更留快照，一键回滚；高危开关（支付链路）二次确认 + 白名单生效模式。
- 可观测：开关被读取的次数、生效版本分布上报，防止"僵尸开关"堆积。
```javascript
// 配置 SDK 核心
class ConfigSDK {
  async init() {
    this.cache = await storage.get('cfg') || DEFAULTS;
    this.apply(await fetchConfig(this.userId));    // 拉新并写缓存
    subscribePush(cfg => this.apply(cfg));          // 推送更新
  }
  get(key, fallback) {
    const item = this.cache[key];
    if (!item || !inBucket(this.userId, item.rollout)) return fallback;
    track('cfg_read', key, item.version);           // 读取上报
    return item.value;
  }
}
```
