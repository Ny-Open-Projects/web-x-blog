## ARC-207：联邦下的异常隔离与子应用降级如何设计？
**答**：
- 分层隔离：加载层（loadRemote 包超时/重试/降级）、执行层（ErrorBoundary 包每个联邦组件）、共享层（singleton 冲突要有告警而非静默）。
- 降级阶梯：子应用 CDN 不可用 → 用主应用本地预置的 fallback 组件（骨架/静态版）→ 整块功能隐藏并上报。绝不因为一个子应用挂掉白屏整个主应用。
- 健康度驱动：子应用错误率通过监控打分，平台把"不健康版本"从 manifest 指针上摘除（软熔断），流量回退到上一版本。
- 契约兜底：子应用 expose 模块的错误不应是"主应用里的陌生堆栈"，要求子应用在 expose 层自带 ErrorBoundary 与上报上下文（app 名 + 版本）。

```javascript
// 联邦组件加载器：超时 + 降级 + 归因上报
function loadFederated(id, { timeout = 5000, fallback } = {}) {
  return lazy(async () => {
    try {
      return withTimeout(loadRemote(id), timeout, `mf-load-timeout:${id}`);
    } catch (e) {
      report({ type: 'mf-fallback', remote: id, err: String(e) });   // 归因到子应用
      return fallback;                                               // 本地静态版组件
    }
  });
}
// 使用：<Suspense fallback={<Skel/>}><ErrorBoundary app="shop"><FederatedHeader/></ErrorBoundary></Suspense>
// 平台软熔断：errorRate(app, version) > 2% 持续 5 分钟 → routes 指针回退上一版本（见 ARC-202）
```
