## ARC-567：大数据量图表渲染架构
**答**:
- 容量分界：1k 点直接画、1w 点降采样 + 增量、10w+ 必须走 GPU（WebGL：ECharts GL/Deck.gl）或服务端聚合。架构先问"真的需要 10 万点吗"——聚合后 1k 点通常信息等价（ARC-381 降采样）。
- 降采样策略：LTTB（保留视觉特征）、按视口聚合（缩放时动态聚合级别——概览聚合看趋势、放大看细节渐进加载）、分桶统计（heatmap 类按桶聚合）。
- WebGL 路线：数据上传一次常驻 GPU buffer、增量更新（脏区间更新 ARC-376）、拾取（GPU 拾取或空间索引）。
- 交互性能：缩放平移 60fps（transform 不重算数据）、tooltip 采样点查找（空间索引 O(logn)）、图例筛选（GPU 数据重绘 vs 数据集重切——按数据规模选）。
- 内存：大数据集的 typed array（不进 JS 对象数组）、数据集生命周期管理（切页释放）。
```javascript
// 分级渲染策略
function pickRenderer(n) {
  if (n <= 1000) return canvas2dRenderer;                        // 直接画
  if (n <= 20000) return downsampledRenderer(LTTB, 2000);        // 降采样
  return webglRenderer({ capacity: 1e6 });                       // GPU 常驻
}
// 缩放联动：zoomend(level) → level > 5 ? fetchDetail(bbox) : renderAggregated(level)
```
