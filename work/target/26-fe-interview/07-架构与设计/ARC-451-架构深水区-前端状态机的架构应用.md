## ARC-451：前端状态机的架构应用
**答**:
- 判断标准：状态数 ≥ 3 且转移有规则、存在非法转移需要防护（未支付不能发货）、有异步动作伴随状态（请求中/成功/失败重试）的流程值得状态机化——订单流、审批流、表单向导、播放器状态。
- 状态机架构价值：把"散落的 boolean（isLoading+isSuccess+isError）"收敛为单一状态 + 显式转移表，非法组合（loading && success）在结构上不可能存在。
- 实现分层：转移表（纯数据，可可视化可测试）+ 执行器（guard 守卫 / action 副作用 / context 扩展数据）；XState 用于复杂流程，手写 reducer 足够用于简单场景。
- 与后端状态对齐：前端状态机是后端状态机的投影——后端状态变更（推送/轮询）驱动前端转移，前端本地转移（乐观）在后端确认后校正。
- 可视化与测试：状态图直接生成（XState viz），全转移遍历测试替代枚举用例。
```javascript
// 手写状态机（转移表）
const machine = {
  initial: 'idle',
  states: {
    idle:    { submit: { target: 'paying', guard: 'hasItems' } },
    paying:  { paid: 'done', fail: 'failed', cancel: 'idle' },
    failed:  { retry: 'paying' },
    done:    {}
  }
};
function transition(state, event, ctx) {
  const next = machine.states[state][event];
  if (!next) return state;                                   // 非法转移原地不动
  const target = next.target ?? next;
  if (next.guard && !ctx[next.guard]) return state;
  return target;
}
```
