## ARC-840：手写架构评分卡

**答**：实现面向决策的架构评分卡 `ArchScorecard`：① 评分卡面向「变更决策」：评估某变更（引入微前端/换状态库）在当前架构下的适配分；② 评估维度：与现状的兼容性/迁移成本/团队负担/收益预期/风险——每维度 1~5 分 + 理由必填；③ 门槛判定：总分 < 阈值 → 不建议（附理由）；争议维度（团队负担 1 分但收益 5 分）→ 标注「需讨论」；④ 决策记录联动：评分卡通过 → 自动生成 ADR 草稿（评分理由即 ADR 内容）；⑤ 事后校准：决策执行后回填实际分数 vs 预估分数（评分偏差——校准评估能力）。写出实现。

```javascript
class ArchScorecard {
  #criteria = ['compatibility', 'migration-cost', 'team-burden', 'benefit', 'risk'];
  score(proposal, scores) {                            // scores: { dim: { score: 1-5, reason } }
    const missing = this.#criteria.filter((c) => !scores[c]?.reason);
    if (missing.length) throw new Error(`缺少理由: ${missing.join(',')}`);
    const total = this.#criteria.reduce((s, c) => s + scores[c].score, 0);
    const max = this.#criteria.length * 5;
    const contentious = this.#criteria.filter((c) => {
      const s = scores[c].score;
      return s <= 2 || s >= 4;                         // 极端分 = 争议维度
    });
    const verdict = total / max >= 0.7 ? 'recommend' : total / max >= 0.5 ? 'needs-discussion' : 'reject';
    return { proposal, total, max, verdict, contentious,
      adrDraft: this.#toADR(proposal, scores, verdict) };
  }
  #toADR(proposal, scores, verdict) {
    return {
      title: `评估: ${proposal}`,
      context: `评分卡: ${Object.entries(scores).map(([c, s]) => `${c}=${s.score}(${s.reason})`).join('; ')}`,
      decision: verdict,
      alternatives: Object.entries(scores).filter(([, s]) => s.score <= 2).map(([c, s]) => ({ option: c, reason: s.reason })),
    };
  }
  calibrate(proposalId, actualScores) {                // 事后校准
    const predicted = this.#predictions.get(proposalId);
    const drift = this.#criteria.map((c) => ({ dim: c, predicted: predicted[c], actual: actualScores[c] }));
    return { drift, bias: mean(drift.map((d) => Math.abs(d.predicted - d.actual))) };
  }
}
```

**评分点**：
- 理由必填（评分无理由无效——防走过场）
- 争议维度标注（极端分——需讨论项显式化）
- 评分卡 → ADR 自动生成（评估即决策记录）
- 事后校准（预估 vs 实际偏差——评估能力进化）
