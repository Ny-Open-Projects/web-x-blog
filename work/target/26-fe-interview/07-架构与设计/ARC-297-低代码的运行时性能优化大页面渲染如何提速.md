## ARC-297：低代码的运行时性能优化：大页面渲染如何提速？
**答**：
- 大 DSL 的性能问题：千节点页面全量递归渲染慢、表达式重复求值、组件全量挂载。优化三板斧：编译期优化、运行时按需、渲染调度。
- 编译期：DSL 预编译成"渲染函数"（compile 一次缓存，不是每次 render 都解析表达式）；静态 props 提升（不变的属性不参与响应式）；绑定依赖表预生成（ARC-293）。
- 运行时：懒挂载（视口外节点不渲染，IntersectionObserver）、虚拟滚动大列表、组件缓存（同 props 复用 memo）。
- 调度：数据源更新按依赖表批量 flush（一个 tick 内合并），避免级联数据源导致渲染风暴。
- 度量：TTI 按节点数分桶（100/500/1000 节点基准），回归进 CI（低代码引擎自带 benchmark 页面集）。

```typescript
// DSL 预编译
function compilePage(dsl) {
  return memoized(() => dsl.components.map(c => ({
    ...c, compiledProps: Object.fromEntries(
      Object.entries(c.props).map(([k, v]) => [k,
        typeof v?.value === 'string' && v.value.startsWith('{{')
          ? compileExpr(v.value)          // 预编译表达式为函数
          : () => v]),                    // 静态 props 常量函数
    }),
  })));
}
// 懒挂载：visible = useInView(ref, { rootMargin: '300px' }); if (!visible) return <Placeholder height={node.h}/>;
```
