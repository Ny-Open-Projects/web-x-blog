## ARC-424：埋点的测试与数据回归体系
**答**:
- 埋点特殊性：错误不抛异常但直接污染数据（漏报/错报/重复报），发现滞后（业务方用数才发现）。架构上把埋点当"接口"对待——有 schema、有测试、有回归。
- 埋点 schema 化：事件字典（事件名/参数/类型/触发时机）统一注册，SDK 校验上报数据合规（缺字段/错类型拒绝并告警），防脏数据入库。
- 自动化测试：E2E 中挂 mock 上报通道，断言"操作 X 触发事件 Y 且参数 Z"（Playwright + 事件断言）；关键漏斗（曝光→点击→转化）有专项回归用例。
- 双跑对账：新埋点版本上线时新旧并行，自动对比事件量分布，偏差 > 阈值报警。
- 数据侧验收：入库后 T+1 数据对账（上报量 vs 入库量），断链（某事件入库量骤降）自动告警定位到版本。
```javascript
// Playwright 埋点断言
test('商品点击曝光事件', async ({ page }) => {
  const events: any[] = [];
  await page.addInitScript(() => { window.__trackSink__ = (e) => (window.__events__ ??= []).push(e); });
  await page.goto('/list');
  await page.click('[data-testid=goods-1]');
  const ev = await page.evaluate(() => window.__events__);
  expect(ev).toContainEqual(expect.objectContaining({ event: 'goods_click',
    goods_id: expect.any(String) }));                           // schema 断言
});
```
