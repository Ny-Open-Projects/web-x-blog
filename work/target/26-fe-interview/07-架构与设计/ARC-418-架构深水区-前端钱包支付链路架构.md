## ARC-418：支付链路的前端架构如何设计？
**答**:
- 支付前端架构第一原则：任何一步都可能失败或中断，状态机 + 对账是骨架。状态：created → paying（拉起收银台）→ unknown（中断不确定结果）→ success/failed，unknown 必须有主动查询出口。
- 支付编排：下单（服务端生成支付单）→ 唤起收银台（SDK/跳转）→ 回跳/回调 → 主动查单（轮询 2s×N 次退避）→ 结果页。前端不依赖回跳必达（用户可能杀进程），查单是事实源。
- 幂等与防重：支付按钮防连点（loading 锁）；同一订单重复唤起复用支付单号；结果页可刷新可重入。
- 异常路径全覆盖：取消支付、余额不足、渠道超时、回调丢失——每类给出用户可懂的下一步（重试/换渠道/联系客服），并埋点区分失败原因。
- 安全红线：金额与商品信息以后端为准（前端只展示）；签名参数前端不拼装；HTTPS + 防劫持提示。
```javascript
async function pay(orderId) {
  const order = await api.createPayOrder(orderId);            // 幂等：同订单复用单号
  await invokeCashier(order.payParams);                        // 唤起收银台
  const result = await pollPaymentStatus(order.payNo,          // 查单是事实源
    { interval: 2000, maxAttempts: 15 });
  if (result === 'unknown') return showPendingPage(order.payNo); // 挂起页可重入
  navigate(result === 'success' ? '/pay/success' : `/pay/fail?reason=${result}`);
}
```
