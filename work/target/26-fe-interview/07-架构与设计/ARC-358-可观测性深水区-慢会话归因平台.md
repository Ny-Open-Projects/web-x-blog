## ARC-358：可观测性深水区：慢会话归因平台如何设计？
**答**：
- 问题定义：监控只告诉你"LCP 涨了"，平台要回答"为什么涨、谁的锅、怎么修"。归因是把指标劣化拆解到可行动的维度。
- 归因维度：版本（新 release 引入）、地域/运营商（CDN 节点）、设备档位（低端机占比变化）、接口（关键 API P95）、资源（某 JS 包体积/某图片）。
- 方法论：先做一阶差分对比（劣化期 vs 基线期各维度分布），再用贡献度分解（如各维度占比变化 × 权重）排序嫌疑因素；每条归因结论附带样本量与置信度，防小样本误判。
- 平台形态：慢样本聚类（指纹分组）→ 自动维度对比报告 → 一键跳转对应构建 diff / 接口监控 / CDN 看板。
- 长期沉淀：归因结论入知识库，同类特征再次出现时自动提示历史根因。
```javascript
// 维度贡献度分解（简化）
function attribute(slow, base) {
  return Object.keys(slow.byDim).map(dim => {
    const delta = slow.byDim[dim] - base.byDim[dim];      // 占比变化
    const impact = delta * slow.totalCount;               // 影响量
    return { dim, delta, impact, confidence: minSample(slow.n, base.n) };
  }).sort((a, b) => Math.abs(b.impact) - Math.abs(a.impact));
}
// 输出：[{dim:'release:v2.3.0', delta:+0.12, impact:4800, ...}, ...]
```
