## DP-378：重试模式完整协议

**答**：
- 重试协议五要素：重试条件（哪些错误可重——网络/5xx/429，4xx 不重）、退避策略（指数+抖动）、上限（次数/总时长预算）、幂等前提（写操作需幂等键）、钩子（onRetry——埋点/降级通知）
- 与熔断的组合：重试是单请求策略，熔断是服务级策略——连续失败触发熔断（停止重试风暴）
- 实战结构：retry(fn, { attempts, base, maxDelay, budget, shouldRetry, onRetry })——预算制（总时长内才重试）
- 重试的抖动（jitter）：防同步重试风暴（多客户端同时退避到期同时打服务端）——random 0~base
- 深水点：重试的「超时收缩」——总预算 3s，第一次尝试用 1s 失败，第二次超时应为剩余 2s 的合理分配（不是重置 3s）——预算感知重试

```javascript
async function retry(fn, { attempts = 3, base = 200, maxDelay = 5000,
    budget = Infinity, shouldRetry = (e) => !e.status || e.status >= 500, onRetry } = {}) {
  const start = performance.now();
  for (let i = 0; i < attempts; i++) {
    const remain = budget - (performance.now() - start);
    if (remain <= 0) throw new Error('retry budget exhausted');
    try { return await fn(); }
    catch (e) {
      if (!shouldRetry(e) || i === attempts - 1) throw e;
      const delay = Math.min(base * 2 ** i + Math.random() * base, maxDelay, remain);
      onRetry?.(i + 1, delay, e);
      await new Promise((r) => setTimeout(r, delay));
    }
  }
}
```
