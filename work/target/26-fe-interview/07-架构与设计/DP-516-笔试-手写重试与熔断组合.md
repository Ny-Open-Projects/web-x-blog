## DP-516：笔试：手写重试熔断限流管道

**答**：组合三个模式为一个请求管道：① 限流（令牌桶——出站速率限制）→ ② 熔断（依赖健康感知——open 快速失败）→ ③ 重试（退避+预算——单请求策略）；④ 组合顺序的正确性论证：限流在外（保护自己并发）、熔断在中（避免对挂掉服务重试）、重试在内（单请求策略）；⑤ 每层的独立可测（单元测试各自）+ 组合集成测试。写出组合实现。

```javascript
// 管道组合: 限流 → 熔断 → 重试
function makeResilient(fn, { limiter, breaker, retryOpts }) {
  return async (...args) => {
    await limiter.take();                              // 1. 限流: 出站速率
    return breaker.call(() => retry(fn, retryOpts)(...args));   // 2. 熔断包 3. 重试
  };
}
// 层次论证:
// 限流最外: 请求先过速率门 (不管下游死活——保护自己)
// 熔断中间: 重试产生的连续失败被熔断感知 (open 后快速失败, 重试不再发起)
// 重试最内: 单请求的退避策略 (在熔断 closed 态才真正执行)
// 单测: 限流器单测(速率) / 熔断器单测(状态迁移) / 重试单测(退避) 各自独立
// 集成: 模拟下游挂 → 熔断 open → 重试不再发起 → 快速失败
```

**评分点**：
- 组合顺序的正确性论证（限流外/熔断中/重试内——每层职责）
- 熔断感知重试失败（连续失败计数包含重试的）
- 分层单测 + 组合集成测试
- open 态快速失败（重试不再发起——不雪上加霜）
