## DP-517：笔试：手写观察者→响应式迁移层

**答**：实现旧事件总线到新响应式内核的迁移适配层：① 旧 API：bus.on('user:change', fn)——新内核：userStore 的 signal；② 双写期：旧事件 → 内核写入 + 内核变更 → 旧事件广播（双向桥——迁移期两套消费者都活着）；③ 回环防护：桥接层标记来源（bridge 来源的写不再广播——防 A→桥→A 死循环）；④ 迁移进度：旧 API 使用统计（还有多少业务用 bus.on('user:change')——迁移看板数据）；⑤ 双 API 的一致性校验（双跑：两套状态对比——迁移正确性）。写出实现。

```javascript
function bridgeBusToStore(bus, store) {
  const SOURCE = 'bridge';
  // 旧 → 新: 旧事件写入内核
  bus.on('user:change', (user) => store.set(user, SOURCE));
  // 新 → 旧: 内核变更广播旧事件 (bridge 来源跳过 — 防回环)
  store.subscribe((user, meta) => {
    if (meta?.source === SOURCE) return;
    bus.emit('user:change', user);
  });
  // 双跑校验: 每 N 次变更对比两套状态
  let count = 0;
  store.subscribe((user, meta) => {
    if (++count % 100 === 0 && meta?.source !== SOURCE) {
      const legacy = legacyUserCache.get();
      if (!deepEqual(legacy, user)) console.warn('[migration drift]', { legacy, user });
    }
  });
  // 使用统计: 包装 bus.on 统计旧 API 消费者 (迁移看板)
}
```

**评分点**：
- 双向桥（两套消费者都活着——迁移期共存）
- 回环防护（来源标记——bridge 写不再广播）
- 双跑一致性校验（迁移正确性验证）
- 旧 API 使用统计（迁移进度看板）
