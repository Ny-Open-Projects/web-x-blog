## ARC-520：抽奖活动公平性架构
**答**:
- 铁律：抽奖结果服务端裁决，前端只做动画展示——前端"先抽后演"（请求结果 → 播放开奖动画 → 展示结果），结果与动画通过动画 ID 关联（动画可重放）。
- 防刷分层：入口风控（设备指纹/行为验证码 ARC-158）、频次限制（服务端限流 NODE-360）、资格预检（活动资格/库存预扣 NODE-384）；前端配合：按钮防连点、异常快速点击行为上报。
- 概率与库存：奖池库存原子扣减（Redis Lua NODE-412）、谢谢参与兜底（库存空时的降级体验）、概率公示合规（ARC-458）。
- 中奖履约：中奖凭证（唯一券码 + 幂等发放 ARC-381）、发放失败补偿（对账补发 ARC-382）、虚拟/实物奖品流转状态展示。
- 演示细节：开奖动画与结果解耦（动画时长固定，结果提前拿到不剧透——动画期间禁止用户离开导致结果丢失，重进入可查）。
```javascript
async function draw() {
  if (drawing) return;                                           // 防连点
  drawing = true;
  const r = await api.draw({ idempotencyKey: sessionKey });      // 服务端裁决
  await playLotteryAnimation({ duration: 3000, result: r.prize, // 动画与结果解耦
    onDone: () => showResult(r) });
  if (r.prize) ensureTicket(r.ticketId);                         // 中奖凭证持久化展示
}
```
