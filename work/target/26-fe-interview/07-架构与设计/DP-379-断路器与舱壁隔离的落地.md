## DP-379：断路器 + 舱壁

**答**：
- 断路器三态：closed（正常）→ 连续失败开路 open（快速失败）→ half-open（探测恢复）——防止「对已挂服务疯狂重试」拖垮前端
- 舱壁隔离：资源按池隔离（图片请求池与 API 池分开——图片慢不占 API 并发额度）——故障隔离的并发维度
- 组合实战：断路器按「依赖服务」分实例（推荐服务挂了不影响订单服务——各自断路）；舱壁按「资源类型」分池
- 实战要点：half-open 的探测并发限制（1 个探测——防探测风暴）；断路器的指标暴露（open 时长/失败率——可观测）
- 深水点：断路器的「前端特有收益」——不只是保护服务端，更保护「用户等待时间」（快速失败→立即降级 UI，比 30s 超时体验好）

```javascript
class CircuitBreaker {
  #state = 'closed'; #fails = 0; #openedAt = 0;
  async call(fn) {
    if (this.#state === 'open') {
      if (Date.now() - this.#openedAt < this.cooldown) throw new CircuitOpenError();
      this.#state = 'half-open';                     // 探测
    }
    try {
      const r = await fn();
      this.#fails = 0; this.#state = 'closed';
      return r;
    } catch (e) {
      if (++this.#fails >= this.threshold) { this.#state = 'open'; this.#openedAt = Date.now(); }
      throw e;
    }
  }
}
// 舱壁: new Semaphore(4) 给图片, new Semaphore(6) 给 API — 各自独立并发额度
```
