## ARC-422：线上产物的版本指纹与追溯体系
**答**:
- 指纹三件套：构建指纹（commit + 构建时间 + 工具版本，注入全局变量）、运行时指纹（window.__BUILD__ 可查询）、上报指纹（所有监控数据自动携带）。
- 追溯链路：线上报错 → 指纹定位 release → sourcemap 还原堆栈（sourcemap 按版本上传存档，不进 CDN 公网）→ 关联 MR/作者/变更内容。排障从"猜"变成"查表"。
- sourcemap 管理：构建时上传监控平台，按版本索引；生产不发布 .map 文件；过期版本 map 定期清理。
- 版本对账：监控平台的版本分布与发布记录比对——某版本流量占比异常（发了一半没生效/多版本混跑超预期）自动预警。
- 回滚关联：回滚事件也记指纹，避免"回滚后还在收集旧版本数据"的误判。
```javascript
// 构建指纹注入 + sourcemap 上传
window.__BUILD__ = { release: 'v2.3.0+8f3a2c1', builtAt: BUILD_TIME, sdk: 'monitor@3.1' };
// 上报 SDK 统一附加
send({ type: 'error', ...payload, release: window.__BUILD__.release });
// CI 步骤：构建 → 上传 map（curl -F release=$RELEASE -F map=@dist/app.js.map）
```
