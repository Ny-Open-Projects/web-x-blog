## ARC-236：授权页面首次进入的权限就绪时序如何设计？
**答**：
- 时序冲突：路由守卫需要权限 → 权限快照需要请求 → 请求又可能依赖路由。处理不当会出现白屏闪烁/先渲染后消失（"闪权限"）。
- 设计：把快照纳入**首屏关键路径**——app 启动并行发起 `perm-snapshot` 与首屏数据，路由跳转前 await 快照就绪（Promise 缓存复用，多个守卫共享一次请求）。
- 体验层：快照就绪前渲染骨架而非空内容；快照失败走 fail-closed（ARC-226）；刷新页面用 sessionStorage 快照先渲染、后台静默校验版本，把感知延迟降到 0。
- 度量与优化：perm-ready 时间进 RUM；高危页面（财务）可接受阻塞就绪，普通页面宁可先渲染再收敛。

```typescript
let snapshotPromise: Promise<PermSnapshot> | null = null;
function getSnapshot() {                          // 单飞：多守卫共享一次请求
  return snapshotPromise ??= api.get('/me/perm-snapshot')
    .then(s => { store.set('perm', s); return s; })
    .catch(e => { snapshotPromise = null; throw e; });
}
beforeEach(async to => {
  const snap = await getSnapshot();               // 路由前就绪，杜绝闪权限
  if (to.meta.perm && !can(snap, to.meta.perm.action, to.meta.perm.resource))
    return '/403';
});
// 首屏并行：Promise.all([getSnapshot(), prefetchFirstScreen()]) —— 权限不串行阻塞数据
```
