## ARC-356：可观测性平台的成本治理如何设计？
**答**：
- 成本结构：接入流量（上报带宽）+ 存储（时序/日志量）+ 查询算力；前端平台大头通常是日志类存储。
- 端上降本：采样（ARC-351）、聚合上报（端上先聚计数再报增量）、字段裁剪（禁止整包 state 上报）、压缩（gzip + 字典）。
- 存储分层：热数据（7~14 天，SSD 可查询）→ 温数据（90 天，列式压缩）→ 冷归档（对象存储，按需恢复）；错误日志与性能指标保留策略不同。
- 数据分级：核心 SLI 指标永不采样；诊断明细（堆栈、trace）按价值采样；行为日志最激进。
- 成本可观测：按业务域/团队分账（tag 到应用），预算与配额制——没有分账的成本治理必然失效。
```javascript
// 端上聚合上报示例：性能指标先聚再报
const perfCounter = { lcp: { sum: 0, n: 0, buckets: new Array(10).fill(0) } };
onLCP(v => {
  perfCounter.lcp.sum += v; perfCounter.lcp.n++;
  perfCounter.lcp.buckets[Math.min(9, Math.floor(v / 1000))]++;
});
// 30s 或 20 条时上报汇总而非逐条
setInterval(() => send(perfCounter) && reset(perfCounter), 30000);
```
