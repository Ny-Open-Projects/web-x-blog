## ARC-459：前端在多活与异地容灾中的配合
**答**:
- 前端配合点：入口层多活（静态资源多 CDN 多源、HTML 多机房发布）、请求层容灾路由（主机房失败自动切备、域名健康探测切换）、状态层降级（切机房后本地缓存数据可用，登录态跨机房共享）。
- DNS/CDN 层：GeoDNS 按地域调度 + 健康检查自动摘除故障节点；前端不感知细节，但要设计"切换后体验降级"的容忍（缓存数据兜底、部分功能提示暂不可用）。
- 请求层容灾路由：网关域名集合 + 探测器（每 30s 探活），主域名失败切换备用域名（预建连减少切换时延）；切换事件上报便于统计容灾触发率。
- 一致性注意：双机房数据延迟——切活后立即写入可能到旧机房（复制延迟），关键操作（支付）切换后 30s 内提示"处理中"而非立即失败。
- 演练：多活切换演练（ARC-426 混沌延伸）每季度真实切一次，验证前端各层兜底生效。
```javascript
// 前端容灾路由
const endpoints = ['https://api.example.com', 'https://api-bj.example.com'];
let active = 0;
async function fetchFailover(url, init) {
  for (let i = 0; i < endpoints.length; i++) {
    const ep = endpoints[(active + i) % endpoints.length];
    try {
      const res = await fetchWithTimeout(ep + url, init, 3000);
      active = (active + i) % endpoints.length;                // 记住健康节点
      if (i > 0) track('failover', { from: endpoints[0], to: ep });
      return res;
    } catch (e) { continue; }                                  // 下一个端点
  }
  throw new Error('所有机房不可用');
}
```
