## ARC-263：大促前的发布管控与冻结期策略？
**答**：
- 冻结期分级：T-7 冻结"非必要变更"（只允许 fix），T-3 冻结全部常规发布（仅 P0 线上故障修复走特批通道），T-0 当天只允许预案执行（降级开关/回滚），不允许任何新发布。
- 特批通道：审批人（技术负责人+业务方双签）、必跑冒烟用例、发布后 30 分钟观察期值守、一键回滚预演过。
- 灰度收紧：冻结期内灰度比例上限下调（如最高 10%），避免问题扩散面过大；发布系统在大促日历驱动下自动调整这些限制。
- 变更关联：所有发布强制关联"大促组件影响面"（ARC-206 依赖图谱思想），改动碰到大促核心链路自动升级审批级别。

```typescript
// 发布系统的大促日历门禁
const calendar = { freezeFull: ['11-09','11-11'], freezeNonFix: ['11-05','11-08'], event: 'double11' };
function canRelease(mr) {
  const d = today();
  if (calendar.event && d >= calendar.freezeFull[0]) {
    return mr.fixOnly && mr.approvals >= 2 && mr.smokePass && mr.watchScheduled; // 特批通道条件
  }
  return mr.ciPass;
}
// 观察期：release 后 30min 内 autoMonitor('whiteScreenRate') 突增 → autoRollback()
```
