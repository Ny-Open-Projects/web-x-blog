## ARC-543：发布质量门禁清单自动化
**答**:
- 门禁清单分层：构建期（lint/测试/体积预算/依赖审计——ARC-367）、发布前（E2E 冒烟/视觉回归/性能预算/Lighthouse 阈值/契约一致性/埋点 schema 校验）、发布中（灰度自动观测 ARC-475/446）、发布后（对账/版本指纹校验 ARC-363/422）。
- 清单自动化映射：每项检查对应可执行工具（lint→eslint、体积→size-limit、性能→Lighthouse CI、埋点→schema 校验器、契约→openapi diff），CI 编排为阶段流水线；不能自动化的项（业务风险判断）进人工 checklist 附在发布单。
- 阈值治理：门禁阈值版本化（收紧走评审）、豁免流程（超标的显式豁免带有效期 ARC-396）、误杀率监控（门禁失败但实际没问题 → 调阈值）。
- 发布单集成：门禁结果自动汇总到发布单（绿/黄/红 + 证据链接），红项阻断发布；黄项 owner 确认后可放行（留痕）。
- 持续裁剪：季度审计（零作用的检查删除、高频误杀的调阈值——门禁自身也要 DevEx ARC-138）。
```yaml
# 发布门禁流水线（阶段编排）
gates:
  build: [lint, unit, bundle-budget, dep-audit]
  pre-release: [e2e-smoke, visual-regression, lighthouse(lcp<2.5,cls<0.1),
                api-contract-diff, track-schema-check]
  release: [canary-watch(err3x/lcp1.3x), version-fingerprint]
  post: [release-reconcile]
waiver: { owner: required, ttl: '14d' }   # 豁免带过期
```
