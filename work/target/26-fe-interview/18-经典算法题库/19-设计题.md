# 19 设计题（C-361 ~ C-380）

> 设计题是笔试里最像"工程"的一类，也是**区分度最高**的一类：题干往往给一段类的方法签名，让你在 O(1) 或 O(log n) 的约束下实现。它考的不是算法技巧，而是**数据结构选型**——你必须能说出"为什么必须是这两个结构的组合，少一个就退化"。字节、阿里、腾讯的设计题几乎必考 LRU / LFU / Trie 三件套。**识别特征**：看到"O(1) 完成增删查改"就要想到"哈希表定位 + 链表/数组做顺序"；看到"按频次/时间淘汰"就要想到"分层桶 + 最小频次指针"；看到"环形复用固定空间"就要想到"数组 + head + count 取模"；看到"前缀/通配"就要想到 Trie。

## 题型速查

### C-361 LRU 缓存 · 中等 · 字节/阿里/腾讯

**题干**：请你设计并实现一个满足 **LRU（最近最少使用）** 约束的缓存。实现 `LRUCache` 类：`LRUCache(int capacity)` 以正整数容量初始化；`int get(int key)` 若关键字存在则返回其值，否则返回 `-1`；`void put(int key, int value)` 若关键字已存在则变更其值，否则插入。若插入导致容量超出，则**淘汰最久未使用**的关键字。`get` 与 `put` 必须以 **O(1)** 平均时间复杂度运行。

**示例**：
```
LRUCache cache = new LRUCache(2);
cache.put(1, 1); cache.put(2, 2);
cache.get(1);    // 1，key 1 变成最新
cache.put(3, 3); // 容量满，淘汰最久未用的 key 2
cache.get(2);    // -1
```

**思路**：
- 先问"单个结构够不够"。数组：定位 O(n)；链表：定位 O(n)；哈希表：定位 O(1) 但**没有顺序**，无法知道谁是"最久未使用"。所以必须**两结构分工**：哈希表 `key -> 节点引用` 负责 O(1) 定位，双向链表负责维护访问顺序。
- 为什么是**双向**链表：淘汰/刷新时我们要把节点从原位置摘下再挂到头部，摘除需要 `prev`，单链表拿不到前驱，只能 O(n) 重扫——这是设计题最常被追问的一点。
- 约定"头部最新、尾部最旧"：`get` 命中后把节点摘下来挂到头部（这一步最容易漏，**get 也会改变顺序**）；`put` 更新已有 key 同样要刷新位置；新插入后若 `size > capacity`，删尾节点并同步从哈希表移除。
- 工程实现可用 JS `Map` 的插入序：`delete(key)` 后重新 `set(key, val)` 即可把该键移到"最新端"，`map.keys().next().value` 就是最旧键。面试时先给这个 8 行版本，再补手写双向链表版本，能同时展示"懂语言特性"和"懂底层原理"。

**代码**：
```javascript
class LRUCache {
  constructor(capacity) {
    this.cap = capacity;
    this.map = new Map(); // key -> value；Map 天然记住插入顺序
  }
  get(key) {
    if (!this.map.has(key)) return -1;
    const val = this.map.get(key);
    this.map.delete(key);   // 先删后插 => 移到"最新"端
    this.map.set(key, val);
    return val;
  }
  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.cap) {
      // keys() 按插入序迭代，第一个就是最久未使用
      const oldest = this.map.keys().next().value;
      this.map.delete(oldest);
    }
  }
}
```

**复杂度**：`get` / `put` 均摊 O(1)；空间 O(capacity)。

**易错点**：
- **`get` 命中也要刷新顺序**，很多人只写了 `put` 的刷新，用例立刻挂。
- `put` 一个已存在的 key 时，必须**先删再插**，否则 `set` 只覆盖值、不改变插入位置，顺序就错了。
- 容量为 1、`put` 同一个 key 多次这类边界要过一遍；`Map.keys()` 返回的是迭代器，别忘记 `.next().value`。
- 手写链表版一定要用**头尾哨兵**，否则空链表/单节点时全是 `null` 判断，写不完。

**变体与追问**：
- 追问"多线程下怎么办"：哈希表分段加锁 + 每个分段一条链表，或直接用并发安全的 LRU（近似算法如 CLOCK）。
- 追问"如何加 TTL"：节点里存过期时间戳，另开一个最小堆/时间轮做主动清理，`get` 时再惰性判断。
- 变体：LFU（C-362）、LRU-K（多维护一条历史队列）、Redis 的近似 LRU（采样淘汰）。

### C-362 LFU 缓存 · 困难 · 字节/阿里

**题干**：设计并实现最不经常使用（**LFU**）缓存。实现 `LFUCache`：`LFUCache(int capacity)`；`int get(int key)` 存在返回其值，否则 `-1`；`void put(int key, int value)` 存在则修改值，不存在则插入；容量满时淘汰**使用频次最低**的键，若最低频次有多个，淘汰其中**最久未使用**的那个（LRU 作为平局规则）。`get` 与 `put` 要求 **O(1)** 平均时间。

**示例**：
```
LFUCache c = new LFUCache(2);
c.put(1, 1); c.put(2, 2);
c.get(1);       // 1，key1 频次变 2
c.put(3, 3);    // 淘汰频次最低且最久未用的 key2
c.get(2);       // -1
```

**思路**：
- 难点不在"计数"，而在**"怎么 O(1) 找到最低频次那一组里最久未用的元素"**。做法是**分层**：`freq -> 一条双向链表`，同频次的键按访问先后挂在链表中，头新尾旧，淘汰时取该频次链表的尾。
- 还需要 `minFreq` 指针：淘汰时若从 1 遍历找最小频次就退化成 O(n)。维护规则很简单——**只在"最小频次那条链表被删空"时才 `minFreq++`**，新插入元素时 `minFreq` 重置为 1。
- 于是三张表：`key -> 节点`（定位）、`freq -> 链表`（分层）、`minFreq`（淘汰入口）。节点同时携带 `freq`，因为它要在链表之间搬家。这就是"为什么必须三个结构"的完整回答。
- 访问一个键 = 从 `freq` 链表摘下 → `freq+1` → 挂到 `freq+1` 链表头部；若原链表空了且原频次等于 `minFreq`，则 `minFreq++`。

**代码**：
```javascript
class Node {
  constructor(k, v) { this.k = k; this.v = v; this.freq = 1; this.prev = null; this.next = null; }
}
class BucketList {                       // 同频次的双向链表
  constructor() {
    this.head = new Node(0, 0); this.tail = new Node(0, 0);
    this.head.next = this.tail; this.tail.prev = this.head; this.size = 0;
  }
  addFront(n) { n.next = this.head.next; n.prev = this.head; this.head.next.prev = n; this.head.next = n; this.size++; }
  remove(n) { n.prev.next = n.next; n.next.prev = n.prev; this.size--; }
  removeLast() { const n = this.tail.prev; this.remove(n); return n; }
}
class LFUCache {
  constructor(capacity) {
    this.cap = capacity; this.minFreq = 0;
    this.map = new Map();                // key -> Node
    this.buckets = new Map();            // freq -> BucketList
  }
  _touch(node) {                         // 频次 +1，在桶之间搬家
    const f = node.freq, list = this.buckets.get(f);
    list.remove(node);
    if (f === this.minFreq && list.size === 0) this.minFreq++;
    node.freq = f + 1;
    if (!this.buckets.has(node.freq)) this.buckets.set(node.freq, new BucketList());
    this.buckets.get(node.freq).addFront(node);
  }
  get(key) {
    const node = this.map.get(key);
    if (!node) return -1;
    this._touch(node);
    return node.v;
  }
  put(key, value) {
    if (this.cap === 0) return;
    const node = this.map.get(key);
    if (node) { node.v = value; this._touch(node); return; }
    if (this.map.size === this.cap) {    // 淘汰 minFreq 桶的尾部
      const dead = this.buckets.get(this.minFreq).removeLast();
      this.map.delete(dead.k);
    }
    const fresh = new Node(key, value);
    this.map.set(key, fresh);
    if (!this.buckets.has(1)) this.buckets.set(1, new BucketList());
    this.buckets.get(1).addFront(fresh);
    this.minFreq = 1;                    // 新元素频次必为 1
  }
}
```

**复杂度**：`get` / `put` 均摊 O(1)；空间 O(capacity)。

**易错点**：
- **淘汰顺序写反**：平局要淘汰同频次里"最久未使用"，所以链表头放最新、淘汰取 `tail.prev`；头尾搞反就变成淘汰刚访问的。
- `minFreq` 的更新时机只有两个：桶被删空且等于 `minFreq` 时 `++`；插入新键时重置为 1。漏掉前者会导致淘汰时拿到空桶直接崩。
- `put` 已存在的 key 也要 `_touch`（频次 +1），很多人只改了值。
- `capacity === 0` 必须特判，否则 `put` 立刻走到淘汰分支，桶不存在。

**变体与追问**：
- 追问"频次衰减怎么做"（热点会永久霸榜）：定期把所有频次除以 2，或引入时间窗滑动计数。
- 追问"为什么不用堆"：堆的删除是 O(log n)，且要惰性删除，达不到 O(1)；分桶本质是"频次只有整数且相邻"这一额外信息带来的优化。
- 与 LRU 对比作答：LRU 是一维顺序，LFU 是二维（频次 × 时间），所以 LFU 的链表要分层。

### C-363 设计循环队列 · 中等 · 腾讯/美团

**题干**：设计你的循环队列实现。循环队列是一种线性数据结构，其操作基于 FIFO 原则并且队尾被连接在队首之后以形成一个循环。它也被称为"环形缓冲器"。实现 `MyCircularQueue` 类：`MyCircularQueue(k)` 构造长度为 `k` 的队列；`enQueue(value)` 向队尾插入元素，成功返回 `true`；`deQueue()` 从队首删除元素，成功返回 `true`；`Front()` 取队首元素，空则 `-1`；`Rear()` 取队尾元素，空则 `-1`；`isEmpty()`、`isFull()`。

**示例**：
```
MyCircularQueue q = new MyCircularQueue(3);
q.enQueue(1); // true
q.enQueue(2); q.enQueue(3); q.enQueue(4); // 最后一个返回 false，已满
q.Rear();     // 3
q.isFull();   // true
q.deQueue();  // true
q.enQueue(4); // true
q.Rear();     // 4
```

**思路**：
- 用**定长数组**做环形缓冲，`head` 指向队首下标，`count` 记录当前元素个数。入队位置是 `(head + count) % cap`，出队就是 `head = (head + 1) % cap` 且 `count--`。
- **为什么用 `count` 而不是 `head/tail` 两个指针判满**：如果只留 `head` 和 `tail`，空与满时二者都相等，必须**牺牲一个槽位**或者额外加标记位才能区分，代码里到处是 `(tail + 1) % cap === head` 这种易错表达式。用 `count` 后，`isEmpty` 就是 `count === 0`、`isFull` 就是 `count === cap`，判空判满彻底解耦，这是本题的唯一采分核心。
- 取队尾是 `(head + count - 1 + cap) % cap`，**加 `cap` 再取模**是为了处理 `count === 0` 时的负数下标（虽然空队列已被提前返回，但保持写法统一更安全）。
- 所有下标运算都要 `% cap`，JS 的 `%` 对负数返回负值，这是从 C++/Java 转过来最容易踩的坑。

**代码**：
```javascript
class MyCircularQueue {
  constructor(k) {
    this.buf = new Array(k);
    this.cap = k;
    this.head = 0;    // 队首下标
    this.count = 0;   // 当前元素个数：用它同时判空和判满
  }
  enQueue(value) {
    if (this.isFull()) return false;
    this.buf[(this.head + this.count) % this.cap] = value; // 队尾位置
    this.count++;
    return true;
  }
  deQueue() {
    if (this.isEmpty()) return false;
    this.head = (this.head + 1) % this.cap; // 只移动 head，不搬数据
    this.count--;
    return true;
  }
  Front() { return this.isEmpty() ? -1 : this.buf[this.head]; }
  Rear() {
    if (this.isEmpty()) return -1;
    return this.buf[(this.head + this.count - 1) % this.cap];
  }
  isEmpty() { return this.count === 0; }
  isFull() { return this.count === this.cap; }
}
```

**复杂度**：所有操作 O(1)；空间 O(k)。

**易错点**：
- 循环队列的**满/空判定**是本题核心：不要用 `head === tail` 判断任一状态，必须靠 `count`。
- `Rear()` 的下标是 `head + count - 1`，忘了减 1 会取到"下一个空位"。
- 出队只挪 `head`、不清数组元素没问题，但 `count` 必须同步减，否则判满永久为真。
- 空队列时 `Front/Rear` 返回 `-1` 而不是 `undefined`，`new Array(k)` 里是 `undefined`，别直接返回。

**变体与追问**：
- 追问"如何支持动态扩容"：容量翻倍后按顺序把旧数据拷到新数组，重置 `head = 0`，均摊 O(1)。
- 追问"无锁环形队列"：生产者只写 `tail`、消费者只写 `head`，靠原子变量和内存屏障，是 Disruptor 的基础。
- 变体：循环双端队列（C-364），在两端都能进出。

### C-364 设计循环双端队列 · 中等 · 字节/快手

**题干**：设计实现双端队列。实现 `MyCircularDeque` 类：`MyCircularDeque(int k)` 构造大小为 `k` 的双端队列；`insertFront()` 向队首添加一个元素，成功返回 `true`；`insertLast()` 向队尾添加；`deleteFront()` 从队首删除；`deleteLast()` 从队尾删除；`getFront()` 取队首元素，空则 `-1`；`getRear()` 取队尾元素，空则 `-1`；`isEmpty()`、`isFull()`。

**示例**：
```
MyCircularDeque d = new MyCircularDeque(3);
d.insertLast(1); d.insertLast(2); d.insertFront(3); // 都返回 true
d.insertFront(4);  // false，已满
d.getRear();       // 2
d.isFull();        // true
d.deleteLast();    // true
d.insertFront(4);  // true
d.getFront();      // 4
```

**思路**：
- 和循环队列同一套骨架：定长数组 + `head` + `count` + 取模。双端队列只多了一件事——**队首也能插入、队尾也能删除**。
- `insertFront` 的关键是 `head = (head - 1 + cap) % cap`：先把 `head` 往前挪一格再写值。**必须先加 `cap` 再取模**，否则 JS 里 `(0 - 1) % 3 === -1`，直接写到数组外。
- `insertLast` 复用 `(head + count) % cap`；`deleteLast` 只需 `count--`（因为尾元素位置由 `head + count - 1` 推导出来，不需要真的清理）；`getRear` 同理。
- 判空判满仍然交给 `count`：这是从循环队列继承下来、最不该出错的部分。若用 `head/tail` 双指针，双端队列要区分四种状态（空、满、只剩一个、正常），代码量翻倍且极易错。

**代码**：
```javascript
class MyCircularDeque {
  constructor(k) {
    this.buf = new Array(k);
    this.cap = k;
    this.head = 0;
    this.count = 0;
  }
  insertFront(value) {
    if (this.isFull()) return false;
    this.head = (this.head - 1 + this.cap) % this.cap; // 先退一格，避免负数下标
    this.buf[this.head] = value;
    this.count++;
    return true;
  }
  insertLast(value) {
    if (this.isFull()) return false;
    this.buf[(this.head + this.count) % this.cap] = value;
    this.count++;
    return true;
  }
  deleteFront() {
    if (this.isEmpty()) return false;
    this.head = (this.head + 1) % this.cap;
    this.count--;
    return true;
  }
  deleteLast() {
    if (this.isEmpty()) return false;
    this.count--; // 尾元素位置由 head+count-1 推导，无需挪指针
    return true;
  }
  getFront() { return this.isEmpty() ? -1 : this.buf[this.head]; }
  getRear() {
    if (this.isEmpty()) return -1;
    return this.buf[(this.head + this.count - 1 + this.cap) % this.cap];
  }
  isEmpty() { return this.count === 0; }
  isFull() { return this.count === this.cap; }
}
```

**复杂度**：所有操作 O(1)；空间 O(k)。

**易错点**：
- `(head - 1) % cap` 在 `head === 0` 时得到 `-1`，**必须 `+ cap` 再取模**，这是本题第一大坑。
- `deleteLast` 忘了同步 `count--`，会导致 `getRear` 取到已"逻辑删除"的元素。
- `insertLast` 的位置是 `head + count`，不是 `head + count - 1`，减 1 会覆盖队尾元素。
- 容量为 1 时，`insertFront` 与 `insertLast` 写同一个槽，靠 `count` 判满才不会双重写入。

**变体与追问**：
- 追问"用两个栈实现双端队列"：前端栈 + 后端栈，一端空了就把另一端整体倒过来，均摊 O(1)。
- 追问"滑动窗口最大值为什么用双端队列"：单调队列需要在尾部淘汰更小的候选、在头部淘汰过期的下标，正是双端队列的两个操作（对应 C-048）。
- 工程映射：React 的调度队列、浏览器的事件循环任务队列都是这种环形/双端结构的变体。

### C-365 最大栈 · 困难 · 字节/美团

**题干**：设计一个支持 `push`、`pop`、`top` 操作，并能在常数时间内检索到最大元素的栈。实现 `MaxStack` 类：`push(int x)` 压栈；`pop()` 弹出栈顶并返回；`top()` 返回栈顶；`peekMax()` 返回栈中最大元素；`popMax()` 弹出并返回栈中**最大**元素，若有多个最大值，只弹出**最靠近栈顶**的那个。

**示例**：
```
MaxStack stk = new MaxStack();
stk.push(5); stk.push(1); stk.push(5);
stk.top();     // 5
stk.popMax();  // 5，弹出最靠顶的那个 5
stk.top();     // 1
stk.peekMax(); // 5
stk.pop();     // 1
stk.top();     // 5
```

**思路**：
- `push/pop/top/peekMax` 全是 O(1) 好办，靠**辅助栈**：`maxs[i]` 存"主栈前 i+1 个元素的最大值"，`push` 时 `maxs.push(max(prevMax, x))`，两个栈严格同步进出。这是"主结构 + 辅助结构"最经典的形态。
- 真正难的是 `popMax`：最大值可能藏在栈中间，**栈只能从顶部取**。所以必须把顶部元素**临时搬到缓冲区**，直到遇到那个最大值并弹掉，再把缓冲区的元素**按原序压回**。这决定了 `popMax` 最坏 O(n)。
- 缓冲区的还原顺序是关键：弹出的顺序是"顶 → 底"，压回时必须**逆序**（`buf.pop()` 逐个 `push`），否则栈就被倒置了。
- 若要求 `popMax` 也 O(log n)，就要换成**平衡树 / 跳表**（按值索引 + 记录插入序号）或"双向链表 + 有序索引"，这也是常见追问。笔试阶段 O(n) 版本足够，先把"搬栈 + 还原"写对。

**代码**：
```javascript
class MaxStack {
  constructor() {
    this.main = [];   // 主栈
    this.maxs = [];   // maxs[i] = main[0..i] 的最大值，与主栈同步
  }
  push(x) {
    this.main.push(x);
    const prev = this.maxs.length ? this.maxs[this.maxs.length - 1] : -Infinity;
    this.maxs.push(Math.max(prev, x));
  }
  pop() {
    this.maxs.pop();          // 两个栈必须同步弹出
    return this.main.pop();
  }
  top() { return this.main[this.main.length - 1]; }
  peekMax() { return this.maxs[this.maxs.length - 1]; }
  popMax() {
    const target = this.peekMax();
    const buf = [];
    while (this.top() !== target) buf.push(this.pop()); // 顶部不是最大值，暂存
    this.pop();                                        // 弹掉最靠顶的最大值
    while (buf.length) this.push(buf.pop());           // 逆序压回，恢复原栈序
    return target;
  }
}
```

**复杂度**：`push`/`pop`/`top`/`peekMax` O(1)；`popMax` 最坏 O(n)；空间 O(n)。

**易错点**：
- `pop` 时**只弹了主栈忘了弹辅助栈**，之后 `peekMax` 全部错位，这是最高频 bug。
- 缓冲区压回时用 `buf.shift()`（正序）会把栈倒置，必须 `buf.pop()` 逆序。
- 多个相同最大值时题目要求弹"最靠顶"的，`while (top() !== target)` 从顶部开始找，天然满足；若从底找就错了。
- 辅助栈初值用 `-Infinity` 而不是 `0`，否则全负数栈时 `peekMax` 返回 0。

**变体与追问**：
- 追问"如何让 `popMax` 也 O(log n)"：用 `TreeMap<值, 该值的下标栈>`，同时主栈元素带全局自增序号，取最大值对应的最大序号删除。
- 变体：最小栈（155，只有 `getMin`，辅助栈即可）、最大频率栈（895，按频次分层）。
- 追问"两个栈能否合一"：可以存 `[value, curMax]` 二元组，本质还是辅助栈，只是打包进一个数组。
### C-366 常数时间插入、删除和获取随机元素 · 中等 · 字节/腾讯

**题干**：实现 `RandomizedSet` 类：`insert(val)` 当元素 `val` 不存在时插入集合并返回 `true`，否则返回 `false`；`remove(val)` 当元素 `val` 存在时移除并返回 `true`，否则返回 `false`；`getRandom()` 从现有集合中**等概率**随机返回一个元素。每个元素被返回的概率必须相同。要求三个操作的平均时间复杂度都是 **O(1)**。

**示例**：
```
RandomizedSet s = new RandomizedSet();
s.insert(1);   // true
s.remove(2);   // false，不存在
s.insert(2);   // true
s.getRandom(); // 1 或 2，概率各 1/2
s.remove(1);   // true
s.insert(2);   // false，已存在
s.getRandom(); // 2
```

**思路**：
- "等概率随机取一个"只有一条路：**必须用数组**（`Math.random() * len` 取下标）。`Set` 无法按下标随机访问，所以数组是唯一选择。
- 但数组的删除是 O(n)（要搬元素）。于是引入第二张表：`值 -> 下标` 的哈希表。**哈希表给 O(1) 定位，数组给 O(1) 随机**——这就是为什么必须是这两个结构的组合。
- O(1) 删除的技巧是：把**待删元素与末尾元素交换**，然后 `pop()`。交换后要同步更新哈希表里末尾元素的新下标，再删掉待删键。这一步是本题的全部技巧。
- `insert` 要防止重复插入；`remove` 要先查哈希表判断存在性，避免对不存在的键做交换把数组搞乱。

**代码**：
```javascript
class RandomizedSet {
  constructor() {
    this.nums = [];          // 用于 O(1) 随机访问
    this.pos = new Map();    // 值 -> 下标，用于 O(1) 定位
  }
  insert(val) {
    if (this.pos.has(val)) return false;
    this.pos.set(val, this.nums.length);
    this.nums.push(val);
    return true;
  }
  remove(val) {
    if (!this.pos.has(val)) return false;
    const i = this.pos.get(val);
    const last = this.nums[this.nums.length - 1];
    this.nums[i] = last;             // 末尾元素补到被删位置
    this.pos.set(last, i);
    this.nums.pop();                 // 真正删除末尾
    this.pos.delete(val);
    return true;
  }
  getRandom() {
    return this.nums[Math.floor(Math.random() * this.nums.length)];
  }
}
```

**复杂度**：三个操作平均 O(1)；空间 O(n)。

**易错点**：
- 删的是**最后一个元素**时，`this.nums[i] = last` 相当于自己赋值自己，随后 `pop()` 和 `pos.delete(val)` 都正确——但如果不写 `set(last, i)` 的顺序，很容易把刚设置的下标又删掉。
- 忘记同步更新 `pos` 里末尾元素的下标，之后 `remove(last)` 会删错位置。
- `getRandom` 的下标是 `[0, len-1]`，`Math.random()` 不会返回 1，所以 `Math.floor` 直接乘即可，不需要 `+1`。
- `remove` 前必须 `has` 判断，不存在的值取出 `undefined` 当作下标会写入 `nums[undefined]`。

**变体与追问**：
- 变体：允许重复（C-368），哈希表改成 `值 -> 下标集合`。
- 追问"如何按权重随机"：值映射到前缀和数组，随机出 `[0, total)` 的数后二分查找，O(log n)。
- 追问"并发下 getRandom 一致性"：需要快照或读写锁，否则读到"交换了一半"的状态。

### C-367 全 O(1) 的数据结构 · 困难 · 字节/阿里

**题干**：设计一个用于存储字符串计数的数据结构，并能够返回计数最小和最大的字符串。实现 `AllOne` 类：`inc(String key)` 将字符串 `key` 的计数增加 1，若不存在则插入计数为 1；`dec(String key)` 将计数减 1，若计数变为 0 则删除该键（题目保证 `dec` 前 `key` 一定存在）；`getMaxKey()` 返回任意一个计数最大的字符串，没有元素则返回 `""`；`getMinKey()` 返回任意一个计数最小的字符串，没有元素则返回 `""`。四个操作都要求 **O(1)**。

**示例**：
```
AllOne a = new AllOne();
a.inc("hello"); a.inc("hello");
a.getMaxKey(); // "hello"
a.getMinKey(); // "hello"
a.inc("leet");
a.getMaxKey(); // "hello"
a.getMinKey(); // "leet"
```

**思路**：
- 直接 `Map<key, count>` 做不到 O(1) 求最值：`getMaxKey` 每次都要扫全表。瓶颈在于"计数相同的键"没有被组织起来。
- 解法是**按计数分桶 + 桶之间用双向链表串起来**，并且**桶链按 count 严格递增**。这样 `head.next` 就是最小计数的桶、`tail.prev` 就是最大计数的桶，取最值直接 O(1)。
- 每个桶是 `{ count, Set<key> }`。`inc`：若键不存在，看 `head.next` 是不是 count=1 的桶，不是就新建一个插到最前；若存在，则看当前桶的下一个桶是不是 `count+1`，不是就新建。然后把 key 从旧桶的 Set 移到新桶，旧桶空了就摘掉。`dec` 完全对称，往 `count-1` 方向找。
- **为什么这三个结构缺一不可**：`Map<key, bucket>` 给 O(1) 定位；`Set` 让"桶空了要删除"和"随便取一个 key"都是 O(1)；有序双向链表让"找相邻计数的桶"是 O(1)（因为计数每次只变 1，相邻桶必然在前后）。这正是设计题的采分核心。

**代码**：
```javascript
class Bucket {
  constructor(cnt) { this.cnt = cnt; this.keys = new Set(); this.prev = null; this.next = null; }
}
class AllOne {
  constructor() {
    this.map = new Map();              // key -> Bucket
    this.head = new Bucket(0);         // 哨兵，桶链按 cnt 递增
    this.tail = new Bucket(0);
    this.head.next = this.tail; this.tail.prev = this.head;
  }
  _insertAfter(node, cnt) {            // 在 node 后面插一个新桶
    const b = new Bucket(cnt);
    b.next = node.next; b.prev = node;
    node.next.prev = b; node.next = b;
    return b;
  }
  _drop(b) { b.prev.next = b.next; b.next.prev = b.prev; }
  inc(key) {
    let b = this.map.get(key);
    if (!b) {
      let nb = this.head.next;
      if (nb.cnt !== 1) nb = this._insertAfter(this.head, 1); // 没有 cnt=1 的桶就新建
      nb.keys.add(key); this.map.set(key, nb); return;
    }
    let nb = b.next;
    if (nb.cnt !== b.cnt + 1) nb = this._insertAfter(b, b.cnt + 1);
    nb.keys.add(key); this.map.set(key, nb);
    b.keys.delete(key);
    if (b.keys.size === 0) this._drop(b);
  }
  dec(key) {
    const b = this.map.get(key);
    if (b.cnt === 1) {                 // 计数归零，直接删键
      b.keys.delete(key); this.map.delete(key);
      if (b.keys.size === 0) this._drop(b);
      return;
    }
    let pb = b.prev;
    if (pb.cnt !== b.cnt - 1) pb = this._insertAfter(b.prev, b.cnt - 1);
    pb.keys.add(key); this.map.set(key, pb);
    b.keys.delete(key);
    if (b.keys.size === 0) this._drop(b);
  }
  getMaxKey() {
    const b = this.tail.prev;
    return b === this.head ? "" : b.keys.values().next().value;
  }
  getMinKey() {
    const b = this.head.next;
    return b === this.tail ? "" : b.keys.values().next().value;
  }
}
```

**复杂度**：四个操作均摊 O(1)；空间 O(n)。

**易错点**：
- 桶链的哨兵 `head.cnt = 0` 让"第一个桶的 cnt 是否为 1"的判断可以和普通情况统一，但不能直接拿 `head` 当真实桶用。
- `inc` 移动键之后**必须检查旧桶是否变空**，空桶不摘链会让 `getMinKey` 取到空桶的 `undefined`。
- `dec` 到 0 时是"删键"而不是"移到 cnt=0 的桶"，桶链里永远不该存在 cnt=0 的真实桶。
- `keys.values().next().value` 取的是 Set 的第一个元素，空 Set 会返回 `undefined`，所以必须先判断桶是否存在。

**变体与追问**：
- 追问"为什么不用堆"：堆取最值是 O(1)，但 inc/dec 是 O(log n)，达不到题目要求。
- 追问"如果计数不是每次变 1 而是任意加减"：桶链要按 count 有序插入，需要跳表维持 O(log n)；这正是"计数只变 1"这一条件带来的优化空间。
- 工程映射：Redis 的 ZSET 用跳表 + 字典实现"按分值取最值"，是同一思路的工业版。

### C-368 允许重复的常数时间随机集合 · 困难 · 字节/快手

**题干**：设计一个支持在平均时间复杂度 **O(1)** 下执行以下操作的集合（**允许重复元素**）：`insert(val)` 插入 `val`，返回 `true`；`remove(val)` 移除**一个** `val`，若存在返回 `true`，不存在返回 `false`；`getRandom()` 随机返回集合中的一个元素，**每个元素被返回的概率与其出现次数成正比**。

**示例**：
```
RandomizedCollection c = new RandomizedCollection();
c.insert(1);   // true
c.insert(1);   // true
c.insert(2);   // true
c.getRandom(); // 1 的概率 2/3，2 的概率 1/3
c.remove(1);   // true
c.getRandom(); // 1 的概率 1/2，2 的概率 1/2
```

**思路**：
- 和 C-366 同一个骨架：数组做随机访问，哈希表做 O(1) 定位。区别是"一个值可能有多个下标"，所以哈希表的值从 `number` 变成 **`Set<number>`**。
- 删除仍然是"与末尾交换 + pop"。但这里有个细节：被换到前面的是末尾元素，要把它的**旧下标 `lastIdx` 从 Set 里删掉、把新下标 `i` 加进去**；同时从 `val` 的 Set 里删掉 `i`。三个下标更新缺一不可。
- 特殊情形：**当 `val` 恰好就是末尾元素**（`i === lastIdx`），交换是自我赋值，此时不能再 `add(i)`，否则 Set 里凭空多出一个重复下标，之后删除就会错。所以必须用 `if (i !== lastIdx)` 保护。
- `Set` 是"随便取一个下标"的 O(1) 容器：`set.values().next().value` 即可，删任意元素也是 O(1)。这就是为什么哈希表的值要用 Set 而不是数组。

**代码**：
```javascript
class RandomizedCollection {
  constructor() {
    this.nums = [];
    this.pos = new Map();   // 值 -> 该值所有下标组成的 Set
  }
  insert(val) {
    if (!this.pos.has(val)) this.pos.set(val, new Set());
    this.pos.get(val).add(this.nums.length);
    this.nums.push(val);
    return true;
  }
  remove(val) {
    if (!this.pos.has(val)) return false;
    const idxSet = this.pos.get(val);
    const i = idxSet.values().next().value;   // 任取一个该值的下标
    const lastIdx = this.nums.length - 1;
    const lastVal = this.nums[lastIdx];
    this.nums[i] = lastVal;                   // 末尾元素补位
    idxSet.delete(i);
    this.pos.get(lastVal).delete(lastIdx);
    if (i !== lastIdx) this.pos.get(lastVal).add(i); // 同一元素时不能重复加
    this.nums.pop();
    if (idxSet.size === 0) this.pos.delete(val);
    return true;
  }
  getRandom() {
    return this.nums[Math.floor(Math.random() * this.nums.length)];
  }
}
```

**复杂度**：三个操作平均 O(1)；空间 O(n)。

**易错点**：
- `i === lastIdx` 时把 `i` 又加回 Set，是这个题最阴的 bug，表现为"删了几次还能删"。
- 删完 `val` 后要判断 `idxSet.size === 0` 再 `pos.delete(val)`；不删会导致 `pos` 里堆积空 Set，`remove` 时取到 `undefined` 下标。
- 顺序问题：必须**先**把 `lastVal` 的新下标写入，**再** `nums.pop()`；顺序反了会拿到已被 pop 的错误值。
- `getRandom` 概率正比于出现次数，靠"数组里每个副本各占一格"天然满足，不需要额外权重计算。

**变体与追问**：
- 追问"如果要求 O(1) 删除并且不允许重复存储"：就是 C-366；允许重复本质是把"值到下标"的一对一变成一对多。
- 追问"如何按值权重随机"：把所有重复展开成前缀和 + 二分；当权重很大时不适合展开，要用别名法（Alias Method）。
- 追问"内存优化"：`Set<number>` 开销大，可用"链表式下标槽"或分级位图替代。

### C-369 设计 Twitter · 中等 · 字节/阿里

**题干**：设计一个简化版的 Twitter，允许用户发送推文、关注/取关其他用户、查看新闻提要。实现 `Twitter` 类：`postTweet(userId, tweetId)` 用户发布一条推文；`getNewsFeed(userId)` 返回该用户**自己和所关注用户**最近发布的 **10** 条推文 ID，按从新到旧排列；`follow(followerId, followeeId)` 关注；`unfollow(followerId, followeeId)` 取关。

**示例**：
```
Twitter t = new Twitter();
t.postTweet(1, 5);      // 用户1 发推 5
t.getNewsFeed(1);       // [5]
t.follow(1, 2);         // 1 关注 2
t.postTweet(2, 6);      // 用户2 发推 6
t.getNewsFeed(1);       // [6, 5]
t.unfollow(1, 2);
t.getNewsFeed(1);       // [5]
```

**思路**：
- 三个动作的代价不同：`postTweet` / `follow` / `unfollow` 必须是 O(1)，而 `getNewsFeed` 允许多花一点（只取 10 条）。所以设计要"把复杂度压到读的时候去"。
- 结构一：`userId -> 推文数组`，数组里存 `{id, time}`，`time` 是全局自增时间戳——**用时间戳比用数组下标可靠**，因为不同用户的数组长度不同，没法直接比较。
- 结构二：`userId -> Set<followeeId>`，用 Set 让关注/取关 O(1) 且天然去重。别忘了 `getNewsFeed` 要把**自己**也加进去（很多人漏掉"自己的推文也在自己的 feed 里"）。
- 取 10 条的本质是**多路归并**：每个用户的最新一条构成候选集，取出时间戳最大的那条，然后从该用户往前推一格补位。标准实现用**大顶堆**（O(k log F)，k=10，F=关注数）；这里为了代码紧凑用有序数组模拟堆，语义完全一致。

**代码**：
```javascript
class Twitter {
  constructor() {
    this.time = 0;
    this.tweets = new Map();     // userId -> [{ id, t }]，按发布顺序追加
    this.following = new Map();  // userId -> Set<followeeId>
  }
  postTweet(userId, tweetId) {
    if (!this.tweets.has(userId)) this.tweets.set(userId, []);
    this.tweets.get(userId).push({ id: tweetId, t: ++this.time });
  }
  getNewsFeed(userId) {
    const users = new Set([userId, ...(this.following.get(userId) || [])]);
    const heap = [];             // 有序数组模拟大顶堆：[时间戳, 用户, 下标]
    for (const u of users) {
      const arr = this.tweets.get(u);
      if (arr && arr.length) heap.push([arr[arr.length - 1].t, u, arr.length - 1]);
    }
    heap.sort((a, b) => b[0] - a[0]);
    const res = [];
    while (res.length < 10 && heap.length) {
      const [t, u, j] = heap.shift();          // 取全局最新
      const arr = this.tweets.get(u);
      res.push(arr[j].id);
      if (j > 0) {                             // 该用户的下一条补位
        const item = [arr[j - 1].t, u, j - 1];
        let k = 0;
        while (k < heap.length && heap[k][0] > item[0]) k++;
        heap.splice(k, 0, item);               // 插入保持有序
      }
    }
    return res;
  }
  follow(followerId, followeeId) {
    if (followerId === followeeId) return;     // 关注自己无意义
    if (!this.following.has(followerId)) this.following.set(followerId, new Set());
    this.following.get(followerId).add(followeeId);
  }
  unfollow(followerId, followeeId) {
    const s = this.following.get(followerId);
    if (s) s.delete(followeeId);
  }
}
```

**复杂度**：`postTweet`/`follow`/`unfollow` O(1)；`getNewsFeed` O(F log F + 10F)，F 为关注数；空间 O(总推文数 + 关注关系数)。

**易错点**：
- **漏掉把自己放进 feed**：`getNewsFeed` 的候选集合必须包含 `userId` 本身。
- 时间戳必须是全局单调递增的**实例变量**，用每个用户数组的局部下标比较大小会得到错误的顺序。
- `unfollow` 时关注集合可能不存在（从没关注过），必须判空，否则 `undefined.delete` 抛错。
- 取 10 条时某个用户已经取完（`j === 0`）不能再补位，否则下标 -1。

**变体与追问**：
- 追问"关注数上万怎么办"：不能每次读时扫全部关注者，改为**推模式**（发推时写入粉丝的收件箱）或**拉模式 + 缓存**，这就是微博/Twitter 的 fanout 架构取舍。
- 追问"如何分页"：feed 需要游标（时间戳 + 推文 ID）而不是 offset，避免新推文插入导致重复/漏读。
- 追问"大 V 发推风暴"：推拉结合，普通用户走推模式、大 V 走拉模式。

### C-370 设计排行榜 · 中等 · 腾讯/美团

**题干**：设计一个 `Leaderboard` 类，实现三个方法：`addScore(playerId, score)` 根据给定分数更新玩家得分，若玩家不在排行榜中则加入；`top(K)` 返回得分**最高的前 K 名玩家**的得分**总和**；`reset(playerId)` 将指定玩家从排行榜中重置（删除其记录）。初始排行榜为空。

**示例**：
```
Leaderboard l = new Leaderboard();
l.addScore(1, 73);  // 1 号玩家 73 分
l.addScore(2, 56);
l.addScore(3, 39);
l.addScore(4, 51);
l.addScore(5, 4);
l.top(1);           // 73
l.reset(1);
l.reset(2);
l.addScore(2, 51);  // 2 号重新加入
l.top(3);           // 141 = 51 + 51 + 39
```

**思路**：
- 本质是"动态维护 Top K 的和"，数据量小（玩家 ≤ 2×10⁴，操作 ≤ 10³），完全可以直接排序。用 `Map<playerId, score>` 存当前分数，`addScore` 是 O(1) 覆盖更新，`reset` 是 O(1) 删除。
- `top(K)` 时把 `Map` 的 values 取出来降序排序，取前 K 个求和。排序是 O(n log n)，K 只是切片长度，不改变量级。
- **注意 `addScore` 是"累加"而不是"覆盖"**：题目说的是"更新得分"，若玩家已存在要把新分数加到旧分数上，这是本题最常见的读题错误（示例里 2 号 reset 后重新 add 51，若写成覆盖，答案会从 141 变成 91）。
- 如果需要 `top` 也高效（数据量大），就把 `Map` 换成**有序容器**（跳表 / 平衡树 / 分数分桶），`addScore` 变成 O(log n)、`top` 变成 O(K)。但 JS 没有内置 TreeMap，笔试写排序版即可，并在追问时说明优化方向。

**代码**：
```javascript
class Leaderboard {
  constructor() {
    this.scores = new Map();   // playerId -> 累计得分
  }
  addScore(playerId, score) {
    // 已存在则累加，不存在则视为 0 再加
    this.scores.set(playerId, (this.scores.get(playerId) || 0) + score);
  }
  top(K) {
    const all = [...this.scores.values()].sort((a, b) => b - a); // 降序
    let sum = 0;
    for (let i = 0; i < Math.min(K, all.length); i++) sum += all[i];
    return sum;
  }
  reset(playerId) {
    this.scores.delete(playerId);
  }
}

const lb = new Leaderboard();
lb.addScore(1, 73); lb.addScore(2, 56); lb.addScore(3, 39);
console.log(lb.top(2));  // 129
lb.reset(1);
console.log(lb.top(2));  // 95
```

**复杂度**：`addScore`/`reset` O(1)；`top` O(n log n)，n 为当前玩家数；空间 O(n)。

**易错点**：
- `addScore` 是**累加**语义，`get(playerId) || 0` 里的 `|| 0` 不能省，否则第一次 `undefined + score = NaN`。
- `top(K)` 的 K 可能大于当前玩家数，必须 `Math.min`，否则求和里混进 `undefined`。
- `reset` 后再次 `addScore` 应该是"从零开始的新记录"，不能残留旧分数。
- 排序比较器必须写 `(a, b) => b - a`；写成 `sort()` 默认字典序时，`100` 会排在 `9` 前面。

**变体与追问**：
- 追问"实时榜单怎么做"：Redis ZSET（跳表 + 字典），`ZINCRBY` 更新、`ZREVRANGE` 取 Top K，都是 O(log n + K)。
- 追问"分数相同如何排名"：需要并列名次（1,1,3）时用 `ZSET` 的 rank 做去重计数，或额外维护"分数 -> 人数"。
- 追问"如何做周榜/月榜"：按时间分桶，每个周期一个 ZSET，过期自动淘汰。

### C-371 设计浏览器历史记录 · 中等 · 字节/腾讯

**题干**：请你设计一个**只支持单个标签页**的浏览器，最开始浏览的页面是 `homepage`，你可以访问其他的网站 `url`，也可以在浏览历史中后退 `steps` 步或前进 `steps` 步。实现 `BrowserHistory` 类：`BrowserHistory(string homepage)` 初始化；`visit(string url)` 从当前页跳转到 `url`，**执行此操作会清除前进记录**；`string back(int steps)` 后退最多 `steps` 步，返回后退后的当前页；`string forward(int steps)` 前进最多 `steps` 步，返回前进后的当前页。

**示例**：
```
BrowserHistory b = new BrowserHistory("leetcode.com");
b.visit("google.com");      // leetcode -> google
b.visit("facebook.com");    // google -> facebook
b.visit("youtube.com");     // facebook -> youtube
b.back(1);                  // 返回 "facebook.com"
b.back(1);                  // 返回 "google.com"
b.forward(1);               // 返回 "facebook.com"
b.visit("linkedin.com");    // 前进记录被清空
b.forward(2);               // 返回 "linkedin.com"（无路可进）
b.back(2);                  // 返回 "google.com"
```

**思路**：
- 浏览历史就是一条**线性的时间轴**，只有"当前位置"和"两个方向"三个概念。最自然的模型是**数组 + 下标**：`history` 存所有 URL，`cur` 指向当前页。
- `back` / `forward` 只是 `cur` 的加减，再 `clamp` 到 `[0, len-1]`——**用 `Math.max/min` 做边界夹紧**，这是唯一需要注意的点：题目要求"最多 steps 步"，越界时停在端点而不是报错。
- `visit` 是唯一有破坏性的操作：新访问会**丢弃当前页之后的所有记录**（前进历史作废）。所以先 `history.length = cur + 1`（截断），再 `push(url)`。
- 等价实现是**双栈**（后退栈 + 前进栈）：`visit` 时把新 URL 压入后退栈并清空前进栈，`back` 时后退栈弹到前进栈。双栈版本多了 O(n) 的空间碎片，数组+下标更简洁；但面试时说一句"也可以用双栈"能体现你理解了两者的等价性。

**代码**：
```javascript
class BrowserHistory {
  constructor(homepage) {
    this.history = [homepage];
    this.cur = 0;                    // 当前页在数组中的下标
  }
  visit(url) {
    this.history.length = this.cur + 1; // 截断：清空所有"前进"记录
    this.history.push(url);
    this.cur = this.history.length - 1;
  }
  back(steps) {
    this.cur = Math.max(0, this.cur - steps);          // 最多退到首页
    return this.history[this.cur];
  }
  forward(steps) {
    this.cur = Math.min(this.history.length - 1, this.cur + steps); // 最多进到最后一页
    return this.history[this.cur];
  }
}

const bh = new BrowserHistory("leetcode.com");
bh.visit("google.com");
bh.visit("facebook.com");
console.log(bh.back(1));    // google.com
console.log(bh.forward(1)); // facebook.com
```

**复杂度**：`visit` 均摊 O(1)（截断可能触发 O(n) 但总体均摊）；`back`/`forward` O(1)；空间 O(访问过的页数)。

**易错点**：
- `visit` **忘记清空前进记录**，这是本题唯一的业务逻辑陷阱；用 `slice(0, cur+1)` 或 `length = cur+1` 都可以。
- `back` / `forward` 越界时必须**夹紧到端点**，直接 `cur -= steps` 会得到负下标或 `undefined`。
- 返回的是**跳转后的当前页**，不是被跳过的页，读题要看清。
- 用 `slice` 生成新数组虽然对，但每次 `visit` 都是 O(n)，大数据量下不如原地截断 `length`。

**变体与追问**：
- 追问"如何支持多标签页"：每个标签页一个 history 数组，再加一个"标签页栈"，就是 Chrome 的会话恢复模型。
- 追问"如何持久化"：把 `history` + `cur` 序列化进 `sessionStorage`，刷新后恢复；注意版本兼容和容量上限。
- 追问"要不要去重"：真实浏览器访问同一 URL 也会新增一条记录，不去重才对。

### C-372 设计链表 · 中等 · 腾讯/美团

**题干**：设计链表的实现。你可以选择使用单链表或双链表。单链表中的节点应该具有两个属性：`val` 和 `next`。实现 `MyLinkedList` 类：`get(index)` 获取链表中第 `index` 个节点的值，无效则返回 `-1`；`addAtHead(val)` 在头部插入；`addAtTail(val)` 在尾部插入；`addAtIndex(index, val)` 在第 `index` 个节点**之前**插入，若 `index` 等于链表长度则追加到末尾，若 `index` 大于长度则不插入；`deleteAtIndex(index)` 删除第 `index` 个节点（若存在）。

**示例**：
```
MyLinkedList l = new MyLinkedList();
l.addAtHead(1);      // 1
l.addAtTail(3);      // 1 -> 3
l.addAtIndex(1, 2);  // 1 -> 2 -> 3
l.get(1);            // 2
l.deleteAtIndex(1);  // 1 -> 3
l.get(1);            // 3
```

**思路**：
- 本题考的是**链表基本功**，采分点全在"边界处理是否干净"。手写链表最常见的崩溃来源是"删/插头节点时没有前驱"，解决办法是加**哑节点（dummy head）**：`dummy.next` 才是真正的第一个节点，这样"在第 0 个位置插入"和"在中间插入"的代码完全一样。
- 维护一个 `size` 字段，所有下标越界检查都用它完成，不要再靠"走到底看是不是 null"——后者写得出来但极易漏判。
- 插入/删除都要先**走到 index 的前一个节点**，所以循环是 `for (let i = 0; i < index; i++) prev = prev.next`，注意是 `< index` 不是 `<= index`。
- `addAtTail` 不必单独实现，直接复用 `addAtIndex(size, val)`；`addAtHead` 也可以写成 `addAtIndex(0, val)`，能显著减少重复代码和出错面。双链表版本额外维护 `prev`，可以让 `get` 从更近的一端开始走，但代码量翻倍，笔试写单链表足够。

**代码**：
```javascript
class ListNode {
  constructor(val, next = null) { this.val = val; this.next = next; }
}
class MyLinkedList {
  constructor() {
    this.dummy = new ListNode(0); // 哑节点：消除"头节点没有前驱"的特判
    this.size = 0;
  }
  get(index) {
    if (index < 0 || index >= this.size) return -1;
    let p = this.dummy.next;
    while (index--) p = p.next;   // 走 index 步到目标节点
    return p.val;
  }
  addAtHead(val) { this.addAtIndex(0, val); }
  addAtTail(val) { this.addAtIndex(this.size, val); }
  addAtIndex(index, val) {
    if (index > this.size) return;      // 超出长度：不插入
    if (index < 0) index = 0;           // 负数按头部处理
    let prev = this.dummy;
    for (let i = 0; i < index; i++) prev = prev.next; // 停在插入位置的前一个
    prev.next = new ListNode(val, prev.next);
    this.size++;
  }
  deleteAtIndex(index) {
    if (index < 0 || index >= this.size) return;
    let prev = this.dummy;
    for (let i = 0; i < index; i++) prev = prev.next;
    prev.next = prev.next.next;         // 跳过被删节点
    this.size--;
  }
}
```

**复杂度**：`get`/`addAtIndex`/`deleteAtIndex` O(index)；`addAtHead` O(1)；空间 O(n)。

**易错点**：
- 没有哑节点时，`deleteAtIndex(0)` 会丢掉 `head` 引用——这是链表题第一大事故，用 dummy 可以彻底规避。
- `addAtIndex` 的越界规则是"**大于**长度才忽略，等于长度要追加"，写成 `>=` 会漏掉尾插。
- 循环边界 `< index` 与 `<= index` 混淆：插入/删除都要停在前驱，所以是 `<`；`get` 要停在目标节点。
- `size` 忘记同步增减，后续所有越界判断全错。

**变体与追问**：
- 追问"怎么 O(1) 拿到中间节点"：快慢指针；如果要支持"任意位置 O(1) 插入"，换成跳表（C-373）。
- 追问"如何反转链表"：三指针迭代，或用 dummy 头插法逐个搬——后者和本题的 `addAtHead` 是同一套动作。
- 变体：设计双链表、设计 LRU（C-361，就是"哈希表 + 手写双链表"）。

### C-373 设计跳表 · 困难 · 字节/阿里

**题干**：不使用任何库中内置的跳表数据结构，设计并实现一个跳表。跳表在增加、删除、搜索元素方面，都需做到 **O(log n)** 的平均时间复杂度。实现 `Skiplist` 类：`bool search(int target)` 判断 `target` 是否存在；`void add(int num)` 向跳表中插入 `num`（重复元素允许存在，即插入多个相同的值）；`bool erase(int num)` 删除**一个** `num`，存在并删除成功返回 `true`，否则 `false`。

**示例**：
```
Skiplist s = new Skiplist();
s.add(1); s.add(2); s.add(3);
s.search(0);  // false
s.add(4);
s.search(1);  // true
s.erase(0);   // false，不存在
s.erase(1);   // true
s.search(1);  // false
```

**思路**：
- 跳表 = **有序链表 + 多级索引**。最底层是完整链表，每往上一层就随机"提拔"一部分节点做索引，查找时从最高层开始"能往右就往右，不能就往下一层"，期望跳过的节点数让复杂度降到 O(log n)。
- 三个结构决定成败：① 每个节点持有 `next[level]` **数组**（不是单指针），因为一个节点要在多层出现；② `head` 节点的高度取最大值（本实现 32 层），保证高层索引有落脚点；③ 一个 `level` 字段记录当前最高有效层数，查找从这里开始，避免每次都从 32 层空跑。
- `add` 的核心是维护 `update[]` 数组：**自顶向下记录"每层最后一个小于 num 的节点"**，插入时把新节点接在它们后面，这才是 O(log n) 而不是每次重扫。
- 随机层数用**几何分布**（`while (Math.random() < 0.25)`），期望层数 O(1)，整体空间 O(n)。`erase` 同样是先求 `update[]`，再逐层改指针；删完若最高层空了，`level--`。

**代码**：
```javascript
const MAX_LEVEL = 32, P = 0.25;
class SkipNode {
  constructor(val) { this.val = val; this.next = new Array(MAX_LEVEL).fill(null); }
}
class Skiplist {
  constructor() { this.head = new SkipNode(-1); this.level = 1; }
  _randomLevel() { let l = 1; while (Math.random() < P && l < MAX_LEVEL) l++; return l; }
  search(target) {
    let p = this.head;
    for (let i = this.level - 1; i >= 0; i--) {
      while (p.next[i] && p.next[i].val < target) p = p.next[i]; // 同层向右贪心
    }
    return p.next[0] !== null && p.next[0].val === target;
  }
  add(num) {
    const update = new Array(MAX_LEVEL).fill(this.head); // 每层的前驱
    let p = this.head;
    for (let i = this.level - 1; i >= 0; i--) {
      while (p.next[i] && p.next[i].val < num) p = p.next[i];
      update[i] = p;
    }
    const lv = this._randomLevel();
    this.level = Math.max(this.level, lv);   // 可能拔高整体层数
    const node = new SkipNode(num);
    for (let i = 0; i < lv; i++) {           // 只在 lv 层内建立链接
      node.next[i] = update[i].next[i];
      update[i].next[i] = node;
    }
  }
  erase(num) {
    const update = new Array(MAX_LEVEL).fill(null);
    let p = this.head;
    for (let i = this.level - 1; i >= 0; i--) {
      while (p.next[i] && p.next[i].val < num) p = p.next[i];
      update[i] = p;
    }
    const target = p.next[0];
    if (!target || target.val !== num) return false;
    for (let i = 0; i < this.level; i++) {
      if (update[i].next[i] === target) update[i].next[i] = target.next[i];
    }
    while (this.level > 1 && this.head.next[this.level - 1] === null) this.level--;
    return true;
  }
}
```

**复杂度**：`search`/`add`/`erase` 平均 O(log n)，最坏 O(n)；空间 O(n)。

**易错点**：
- `add` 时**只更新到 `lv` 层**，却在更高层也改了 `update[]`，会导致高层指针指向不存在的层——循环必须是 `i < lv`。
- `erase` 里 `update[i].next[i] === target` 的判断不能省：高于目标节点层数的那些 `update[i]` 并不指向它，直接改会把别人的链接切断。
- `Math.random() < P` 的 `P` 取 0.25 或 0.5 都行，但**必须小于 1**，否则层数无限增长直接崩。
- `MAX_LEVEL` 要按数据规模取：10⁵ 个元素时 32 层已经绰绰有余（0.25³² 极小），取 16 可能不够。

**变体与追问**：
- 追问"跳表 vs 平衡树"：跳表实现简单、范围查询友好、并发插入只需局部锁；Redis 的 ZSET 就是跳表 + 字典。
- 追问"如何支持按排名查询"：每个节点额外存 `span`（到下一个节点的跨度），`ZRANK` 就是沿路累加 span。
- 追问"为什么随机化能保证 O(log n)"：层数服从几何分布，第 k 层节点数期望是 n·(1/4)^k，总期望比较次数 O(log n)。

### C-374 实现 Trie（前缀树） · 中等 · 字节/阿里/腾讯

**题干**：Trie（发音类似 "try"）或者说**前缀树**，是一种树形数据结构，用于高效地存储和检索字符串数据集中的键。这一数据结构有相当多的应用情景，例如自动补全和拼写检查。实现 `Trie` 类：`Trie()` 初始化；`insert(String word)` 插入字符串；`search(String word)` 如果字符串在树中返回 `true`；`startsWith(String prefix)` 如果之前插入过某个字符串是该前缀返回 `true`。

**示例**：
```
Trie t = new Trie();
t.insert("apple");
t.search("apple");   // true
t.search("app");     // false，只存了 apple
t.startsWith("app"); // true，app 是 apple 的前缀
t.insert("app");
t.search("app");     // true
```

**思路**：
- Trie 的本质是**用"字符路径"代替"整串哈希"**：从根走到某个节点，路径上拼起来就是一个前缀。这样"查前缀"和"查整词"走的是同一条路，只差最后看一眼 `isEnd` 标记——这是哈希表做不到的（哈希表只能判等，判前缀必须枚举所有 key）。
- 每个节点需要两个字段：`children`（子节点集合，用 `Map` 或定长 26 数组）和 `isEnd`（是否有单词在此结束）。用 `Map` 更省空间且支持任意字符，用数组访问更快、适合只有小写字母的笔试题。
- `insert` 就是沿路径"没有就建"，最后把 `isEnd = true`；`search` 沿路径走，**走完且 `isEnd` 为真**才返回 true；`startsWith` 沿路径走，**走得通就算 true**，不看 `isEnd`。
- 三个方法可以抽出一个共用的 `_find(word)`：返回"路径尽头的节点或 null"，`search` 再叠加 `isEnd` 判断。这样写既短又不容易出错，也是面试官想看到的抽象能力。

**代码**：
```javascript
class TrieNode {
  constructor() {
    this.children = new Map();  // 字符 -> 子节点
    this.isEnd = false;         // 是否有单词在此结束
  }
}
class Trie {
  constructor() { this.root = new TrieNode(); }
  insert(word) {
    let p = this.root;
    for (const ch of word) {
      if (!p.children.has(ch)) p.children.set(ch, new TrieNode());
      p = p.children.get(ch);
    }
    p.isEnd = true;             // 整词结束标记
  }
  _find(word) {                 // 公共逻辑：走到路径尽头
    let p = this.root;
    for (const ch of word) {
      p = p.children.get(ch);
      if (!p) return null;      // 路径断了
    }
    return p;
  }
  search(word) {
    const p = this._find(word);
    return p !== null && p.isEnd;      // 必须是某个单词的结尾
  }
  startsWith(prefix) {
    return this._find(prefix) !== null; // 走得通即可，不看 isEnd
  }
}
```

**复杂度**：`insert`/`search`/`startsWith` 均 O(L)，L 为字符串长度；空间 O(总字符数 × 字符集)，最坏 O(N·L)。

**易错点**：
- `search` 与 `startsWith` 的唯一区别就是**要不要判 `isEnd`**，写反了用例全挂。
- 空串 `""` 的处理：`_find("")` 返回根节点，若曾有单词是空串则 `isEnd` 为真——通常题目不测，但逻辑上要自洽。
- 用定长数组 `new Array(26)` 时要记得 `ch.charCodeAt(0) - 97`，且只适用于小写字母；出现大写/数字就会越界或串味。
- 节点里存 `isEnd` 不要存"单词本身"，否则重复插入同一个词会浪费空间，且不好支持删除。

**变体与追问**：
- 追问"如何删除单词"：沿路径递归回溯，`isEnd = false` 后若 `children` 为空就逐层删节点；注意不能误删仍是其他词前缀的节点。
- 追问"如何做自动补全"：在目标前缀节点上 DFS 收集所有 `isEnd` 的路径，配合优先队列取 Top K（C-384）。
- 追问"Trie vs 哈希表"：哈希表 O(1) 判等但无法判前缀、无法做有序遍历；Trie 的代价是空间和常数。
- 变体：通配符匹配（C-375）、单词搜索 II（C-381）。

### C-375 添加与搜索单词（通配符） · 中等 · 字节/美团

**题干**：请你设计一个数据结构，支持**添加新单词**和**查找字符串是否与任何先前添加的字符串匹配**。实现 `WordDictionary` 类：`addWord(String word)` 添加单词；`search(String word)` 如果数据结构中存在与 `word` 匹配的字符串则返回 `true`。`word` 中可能包含点号 `'.'`，点号可以匹配**任意一个字母**。

**示例**：
```
WordDictionary d = new WordDictionary();
d.addWord("bad"); d.addWord("dad"); d.addWord("mad");
d.search("pad");  // false
d.search("bad");  // true
d.search(".ad");  // true，首字母任意
d.search("b..");  // true
```

**思路**：
- 底层仍然是 Trie（C-374）：`addWord` 完全等同于 Trie 的 `insert`，因为存的是"字符路径"，天然支持前缀与逐字符匹配。
- 区别在 `search`：遇到 `'.'` 时不能确定走哪条边，必须**枚举当前节点的所有子节点并递归尝试**，任意一条成功就返回 true。这是"Trie + 回溯"的标准组合。
- 回溯的两个终止条件要写全：`node` 为空直接 false；`i === word.length` 时返回 `node.isEnd`（匹配完整词，而不是匹配前缀）。
- 复杂度分析要分层说清：无通配符时是 O(L)；最坏情况（全是 `'.'`）要枚举整棵子树，是 O(26^L)，这也是为什么工程上通配查询要限制长度或加剪枝（比如记录子树最大剩余深度）。

**代码**：
```javascript
class TrieNode {
  constructor() { this.children = new Map(); this.isEnd = false; }
}
class WordDictionary {
  constructor() { this.root = new TrieNode(); }
  addWord(word) {
    let p = this.root;
    for (const ch of word) {
      if (!p.children.has(ch)) p.children.set(ch, new TrieNode());
      p = p.children.get(ch);
    }
    p.isEnd = true;
  }
  search(word) {
    const dfs = (node, i) => {
      if (!node) return false;                 // 路径断了
      if (i === word.length) return node.isEnd; // 必须正好是词尾
      const ch = word[i];
      if (ch !== '.') return dfs(node.children.get(ch), i + 1);
      for (const next of node.children.values()) {
        if (dfs(next, i + 1)) return true;     // 任一分支成功即可
      }
      return false;
    };
    return dfs(this.root, 0);
  }
}
```

**复杂度**：`addWord` O(L)；`search` 平均 O(L)，含 `k` 个通配符时最坏 O(26^k · L)；空间 O(总字符数)。

**易错点**：
- `i === word.length` 时**必须判 `isEnd`**，否则"存了 bad，查 ba"会误判为 true。
- 递归里 `node.children.get(ch)` 可能返回 `undefined`，要在函数入口用 `if (!node) return false` 兜住，别在取子节点前就 `.has`。
- `'.'` 分支遍历的是 `children.values()`（节点），不是 `keys()`（字符），类型搞错会直接崩。
- 全通配符 `"..."` 会退化成暴力枚举，笔试题数据量小可以接受，但要能说出优化方向（剪枝 / 按长度分组）。

**变体与追问**：
- 追问"如何优化全通配符"：在节点上维护"子树最大剩余深度"，长度不匹配就剪枝；或按单词长度分桶存储。
- 追问"支持 `*`（匹配任意多个字符）"：就变成正则匹配 DP，Trie 上的递归要加"跳过任意长度"的分支。
- 变体：单词搜索 II（C-381，棋盘上搜单词，Trie 剪枝 + 回溯）、前缀和后缀搜索（C-382）。

### C-376 设计一个验证系统 · 中等 · 字节/腾讯

**题干**：你需要设计一个验证系统，用于管理众多用户的验证令牌（token）。实现 `AuthenticationManager` 类：`AuthenticationManager(int timeToLive)` 构造，`timeToLive` 表示令牌的**有效期**；`generate(string tokenId, int currentTime)` 在 `currentTime` 时刻生成一个令牌 `tokenId`；`renew(string tokenId, int currentTime)` 在 `currentTime` 时刻**更新**一个未过期的令牌的有效期，若令牌不存在或已过期则忽略；`countUnexpiredTokens(int currentTime)` 返回在 `currentTime` 时刻**未过期**的令牌数量。**同一时刻不会生成两个相同 tokenId 的令牌。**

**示例**：
```
AuthenticationManager m = new AuthenticationManager(5);
m.renew("aaa", 1);              // 令牌不存在，忽略
m.generate("aaa", 2);           // aaa 有效到 7
m.countUnexpiredTokens(6);      // 1
m.generate("bbb", 7);
m.renew("aaa", 8);              // aaa 已过期，忽略
m.renew("bbb", 10);             // bbb 续期到 15
m.countUnexpiredTokens(15);     // 0，15 时刻 bbb 已过期
```

**思路**：
- 题目只有"写入"和"全局计数"两类操作，没有"按时间逐个取出"的需求，所以**一个 `Map<tokenId, expireAt>` 就够了**——不需要堆、不需要有序结构。这是设计题里典型的"先判断需不需要复杂结构"。
- 过期判断的口径是**严格大于**：有效期 5、在 2 时刻生成，则 `expireAt = 7`，`currentTime = 7` 时已经过期（示例里 15 时刻的 bbb 返回 0 就是证明）。写成 `>=` 会错。
- `renew` 必须**先判断旧令牌是否仍在有效期内**，再续期：`expireAt > currentTime` 才更新，否则忽略。用"是否存在于 Map"来判断是不够的——过期的键还留在 Map 里。
- `countUnexpiredTokens` 需要遍历所有令牌，单次 O(n)。题目给的调用次数有限，可以接受；若要 O(log n)，就把 `Map` 换成按 `expireAt` 排序的 `TreeMap` / 小顶堆，计数时惰性清理。这是本题最重要的追问方向。

**代码**：
```javascript
class AuthenticationManager {
  constructor(timeToLive) {
    this.ttl = timeToLive;
    this.tokens = new Map();   // tokenId -> 过期时刻
  }
  generate(tokenId, currentTime) {
    this.tokens.set(tokenId, currentTime + this.ttl);  // 记录绝对过期时刻
  }
  renew(tokenId, currentTime) {
    const expireAt = this.tokens.get(tokenId);
    if (expireAt !== undefined && expireAt > currentTime) {
      this.tokens.set(tokenId, currentTime + this.ttl); // 只有未过期才续期
    }
  }
  countUnexpiredTokens(currentTime) {
    let cnt = 0;
    for (const expireAt of this.tokens.values()) {
      if (expireAt > currentTime) cnt++;   // 严格大于才算有效
    }
    return cnt;
  }
}
```

**复杂度**：`generate`/`renew` O(1)；`countUnexpiredTokens` O(n)；空间 O(n)。

**易错点**：
- 过期判定用 `>` 而不是 `>=`；`currentTime` 恰好等于过期时刻即为过期。
- `renew` 前必须判断 `expireAt > currentTime`，只看 `has(tokenId)` 会把过期令牌"续活",与题意不符。
- 存的是**绝对过期时刻**（`生成时刻 + ttl`），不是"剩余时间"，否则每次查询都要做减法且容易算错边界。
- 用 `Map` 存过期键不会自动清理，长时间运行会内存泄漏——真实系统要配合定时清理或惰性删除。

**变体与追问**：
- 追问"如何把 count 降到 O(log n)"：用按过期时间排序的结构（小顶堆 / 跳表），计数时先把 `expireAt <= currentTime` 的弹出，剩下的就是有效数。
- 追问"令牌能否重复生成"：题目保证同一时刻不重复，但不同时刻可能重复；若允许覆盖，`set` 语义天然处理。
- 工程映射：这就是 JWT / session token 的 `exp` + 滑动续期模型。

### C-377 设计前中后队列 · 中等 · 阿里/快手

**题干**：请你设计一个队列，支持在前、中、后三个位置添加元素，并且支持从前、中、后三个位置删除元素。实现 `FrontMiddleBackQueue` 类：`pushFront(val)`、`pushMiddle(val)`、`pushBack(val)` 分别在队首、队中、队尾添加；`popFront()`、`popMiddle()`、`popBack()` 分别删除并返回对应位置的元素，若队列为空返回 `-1`。**当队列长度为偶数时，中间位置取靠前的那个**（即下标 `n/2 - 1`）。

**示例**：
```
FrontMiddleBackQueue q = new FrontMiddleBackQueue();
q.pushFront(1);   // [1]
q.pushBack(2);    // [1,2]
q.pushMiddle(3);  // [1,4?] -> [1,3,2]
q.pushMiddle(4);  // [1,4,3,2]
q.popFront();     // 1，剩 [4,3,2]
q.popMiddle();    // 3，剩 [4,2]
q.popMiddle();    // 4，剩 [2]
q.popBack();      // 2，剩 []
q.popFront();     // -1，空
```

**思路**：
- 用一个大数组 `splice` 也能做，但每次 O(n)，面试官会追问"能不能 O(1)"。正解是**拆成两个双端队列**：`left` 和 `right`，并维护不变式 **`right.length === left.length` 或 `right.length === left.length + 1`**。
- 在这个不变式下，"中位元素"永远是 **`right[0]`**（前缀左半 + 右半的第一个）。用长度验证一下：n=1 时 left=[]、right=[x]；n=2 时 left=[a]、right=[b]；n=3 时 left=[a]、right=[b,c]——三种情况下 `right[0]` 都是题目定义的"靠前的中位"。
- 有了不变式，六个操作都变成"改一端 + 调平衡"：`pushFront` 塞 `left` 头部、`pushBack` 塞 `right` 尾部、`pushMiddle` 塞 `right` 头部；三个 `pop` 分别从 `left` 头、`right` 头、`right` 尾取。每次操作后调用 `_balance()` 恢复不变式即可。
- **为什么这个拆分是唯一漂亮解**：单一双端队列无法 O(1) 定位中点；两个队列把"中点"转化成了"某个队列的端点"，端点操作天然 O(1)。这就是设计题要讲清的"结构为什么这样选"。

**代码**：
```javascript
class FrontMiddleBackQueue {
  constructor() {
    this.left = [];    // 左半段
    this.right = [];   // 右半段，长度 = left 或 left+1
  }
  _balance() {
    while (this.right.length > this.left.length + 1) this.left.push(this.right.shift());
    while (this.left.length > this.right.length) this.right.unshift(this.left.pop());
  }
  pushFront(val) { this.left.unshift(val); this._balance(); }
  pushMiddle(val) { this.right.unshift(val); this._balance(); }
  pushBack(val) { this.right.push(val); this._balance(); }
  popFront() {
    if (!this.right.length) return -1;              // 不变式：right 空则整体空
    const v = this.left.length ? this.left.shift() : this.right.shift();
    this._balance();
    return v;
  }
  popMiddle() {
    if (!this.right.length) return -1;
    const v = this.right.shift();                   // 中位永远是 right[0]
    this._balance();
    return v;
  }
  popBack() {
    if (!this.right.length) return -1;
    const v = this.right.pop();
    this._balance();
    return v;
  }
}
```

**复杂度**：六个操作均摊 O(1)（`shift/unshift` 在 V8 中对小数组是快的，严格 O(1) 需手写双端队列）；空间 O(n)。

**易错点**：
- **不变式写反**：必须是 `right` 更长或相等，这样中位落在 `right[0]`；若让 `left` 更长，偶数长度时中位会取到后面那个，与题意相反。
- 空队列判断只需看 `right`：不变式保证 `right` 空当且仅当两个都空，用 `left.length` 判断会漏。
- `popFront` 要判断 `left` 是否为空（可能在调平衡后全部落在 right），空则从 `right` 头取。
- `pushMiddle` 直接 `right.unshift` 再平衡，不要手动算下标，否则偶数/奇数切换时容易错位。

**变体与追问**：
- 追问"严格 O(1) 怎么做"：用链表或环形数组实现双端队列，`shift/unshift` 变成指针移动。
- 追问"如果要支持按下标随机访问"：两个队列改成两个可扩容环形缓冲区，并可二分确定元素在哪一段。
- 变体：双端队列（C-364）、滑动窗口最大值（单调双端队列）。

### C-378 设计食物评分系统 · 中等 · 美团/拼多多

**题干**：设计一个支持以下操作的餐厅评分系统。实现 `FoodRatings` 类：`FoodRatings(String[] foods, String[] cuisines, int[] ratings)` 初始化，第 `i` 个食物属于 `cuisines[i]` 菜系、评分为 `ratings[i]`；`changeRating(String food, int newRating)` 修改某个食物的评分；`String highestRated(String cuisine)` 返回指定菜系中**评分最高**的食物名，评分相同则返回**字典序最小**的名字。

**示例**：
```
FoodRatings f = new FoodRatings(
  ["kimchi","miso","sushi","moussaka","ramen","bulgogi"],
  ["korean","japanese","japanese","greek","japanese","korean"],
  [9, 12, 8, 15, 14, 7]);
f.highestRated("korean");   // "kimchi"
f.highestRated("japanese"); // "ramen"
f.changeRating("sushi", 16);
f.highestRated("japanese"); // "sushi"
f.changeRating("ramen", 16);
f.highestRated("japanese"); // "ramen"，同分取字典序小的
```

**思路**：
- 需要同时回答两个问题：① 某个食物属于哪个菜系、当前多少分（**按名字查**）；② 某个菜系里谁的分最高（**按菜系查**）。这是两个不同维度的索引，所以**必须两张表**：`food -> {cuisine, rating}` 和 `cuisine -> 有序集合`。
- 若只有第一张表，`highestRated` 要扫全部食物，O(n)；若只有第二张表，`changeRating` 找不到食物的旧记录，无法删除。这就是"为什么必须拆成两张表"。
- 第二张表要能"快速取最值"且"支持删除旧分数"。标准做法是**每个菜系一个大顶堆 + 惰性删除**（弹出时比对 `food -> rating` 是否仍是当前值，过期就丢）。JS 无内置堆，笔试里用"数组 + 每次变更后重排"更稳，跑得过题且逻辑透明。
- 排序规则要**一次性编码进比较器**：`b.rating - a.rating || (a.name < b.name ? -1 : 1)`。同分比名字，名字用字符串比较，不能减。

**代码**：
```javascript
class FoodRatings {
  constructor(foods, cuisines, ratings) {
    this.info = new Map();      // food -> { cuisine, rating }
    this.groups = new Map();    // cuisine -> [[rating, food], ...] 有序
    for (let i = 0; i < foods.length; i++) {
      this.info.set(foods[i], { cuisine: cuisines[i], rating: ratings[i] });
      if (!this.groups.has(cuisines[i])) this.groups.set(cuisines[i], []);
      this.groups.get(cuisines[i]).push([ratings[i], foods[i]]);
    }
    for (const arr of this.groups.values()) this._sort(arr);
  }
  _sort(arr) {
    arr.sort((a, b) => b[0] - a[0] || (a[1] < b[1] ? -1 : 1)); // 分降序，同分名字升序
  }
  changeRating(food, newRating) {
    const item = this.info.get(food);
    item.rating = newRating;                          // 更新元信息
    const arr = this.groups.get(item.cuisine);
    const idx = arr.findIndex(([, name]) => name === food);
    arr[idx][0] = newRating;                          // 同步到该菜系的有序表
    this._sort(arr);
  }
  highestRated(cuisine) {
    return this.groups.get(cuisine)[0][1];            // 有序表头部即答案
  }
}
```

**复杂度**：初始化 O(n log n)；`changeRating` O(k log k)，k 为该菜系食物数；`highestRated` O(1)；空间 O(n)。

**易错点**：
- 同分时的**字典序方向**：升序（小的优先），写成 `a[1] > b[1] ? -1 : 1` 就把字典序大的排前面，答案反了。
- 字符串比较**不能相减**，`a[1] - b[1]` 得到 `NaN`，排序结果未定义。
- `changeRating` 必须同时更新 `info` 和 `groups`，只改一处会让下一次同分比较用到旧分数。
- 用堆 + 惰性删除时，弹出前要校验 `info.get(food).rating === heapTop.rating`，否则会返回已被改分的旧记录。

**变体与追问**：
- 追问"数据量大时如何优化"：每个菜系一个堆，`changeRating` 只 push 新记录并标记旧记录失效，`highestRated` 时惰性弹出，均摊 O(log n)。
- 追问"如果要返回 Top K"：堆取 K 次，或维护一个大小为 K 的小顶堆。
- 工程映射：电商的"店铺-商品"多维榜单、Redis ZSET 的 `ZREVRANGE`。

### C-379 设计一个文本编辑器 · 困难 · 字节/腾讯

**题干**：请你设计一个文本编辑器，初始时文本为空，光标在文本起始位置。实现 `TextEditor` 类：`addText(String text)` 在光标处插入 `text`，光标移到插入文本之后；`deleteText(int k)` 删除光标左侧最多 `k` 个字符，返回实际删除的字符数；`cursorLeft(int k)` 光标左移最多 `k` 步，返回光标左侧最多 **10** 个字符；`cursorRight(int k)` 光标右移最多 `k` 步，返回光标左侧最多 10 个字符。

**示例**：
```
TextEditor e = new TextEditor();
e.addText("leetcode");     // "leetcode|"
e.deleteText(4);           // 删除 4 个，剩 "leet|"，返回 4
e.addText("practice");     // "leetpractice|"
e.cursorRight(3);          // 光标右移 3，"leetprac|tice"，返回 "etpractice"
e.cursorLeft(8);           // 返回 "leet"
e.deleteText(10);          // 返回 4，剩 "|practice"
```

**思路**：
- 文本编辑器的最小模型是 **"一个字符串 + 一个光标下标"**：插入 = `s.slice(0, cur) + text + s.slice(cur)`，删除 = 从 `cur` 往前截掉 `min(k, cur)` 个，移动 = 对 `cur` 做 `clamp`。四个操作全部围绕 `cur`，没有第二种状态。
- **为什么不用双栈**：双栈（左栈 + 右栈）能让插入/删除变成 O(1) 的 `push/pop`，光标移动也只是在两栈间搬元素；但"返回光标左侧最多 10 个字符"需要从左栈取尾部 10 个，双栈要额外拼字符串。字符串方案赢在**代码量和可读性**，且题目数据规模允许 O(n) 的 `slice`。
- 关键细节是**返回值口径统一**：`cursorLeft/cursorRight` 都返回"光标左侧最多 10 个字符"，所以右移之后也要往左看，不是往右看。
- 若面试官要求 O(1) 增删，就换成**双向链表存字符 + 光标指向节点**（或 rope / piece table），这也正是 VS Code、Vim 的真实做法。答题时说清"字符串版适合笔试，工程用 piece table"是加分项。

**代码**：
```javascript
class TextEditor {
  constructor() {
    this.s = "";
    this.cur = 0;              // 光标位置：s[0..cur-1] 在光标左侧
  }
  addText(text) {
    this.s = this.s.slice(0, this.cur) + text + this.s.slice(this.cur);
    this.cur += text.length;   // 光标落到插入内容之后
  }
  deleteText(k) {
    const del = Math.min(k, this.cur);          // 最多删到行首
    this.s = this.s.slice(0, this.cur - del) + this.s.slice(this.cur);
    this.cur -= del;
    return del;
  }
  cursorLeft(k) {
    this.cur = Math.max(0, this.cur - k);
    return this.s.slice(Math.max(0, this.cur - 10), this.cur); // 左侧最多 10 个
  }
  cursorRight(k) {
    this.cur = Math.min(this.s.length, this.cur + k);
    return this.s.slice(Math.max(0, this.cur - 10), this.cur); // 仍是看左侧
  }
}
```

**复杂度**：`addText`/`deleteText` O(n)，`cursorLeft`/`cursorRight` O(1)（返回字符串本身的 O(10) 可忽略）；空间 O(n)。

**易错点**：
- `deleteText` 要删的是**光标左侧** `min(k, cur)` 个，删多了会越过光标切到右侧内容。
- `cursorRight` 的返回值是**光标左侧** 10 个字符，不是右侧；这是最容易读反的一处。
- `cursorLeft` 返回时 `slice` 的起点要 `Math.max(0, cur - 10)`，否则负数起点会被当成从末尾算。
- 光标 `cur` 必须始终在 `[0, s.length]` 内，右移要 `clamp` 到 `s.length`（不是 `s.length - 1`），因为光标可以在末尾。

**变体与追问**：
- 追问"如何做到 O(1) 插入删除"：双向链表 / piece table（记录原文片段引用，编辑只改索引表），这是 VS Code 的方案。
- 追问"如何支持撤销重做"：命令模式 + 双栈，每个操作记录反向操作。
- 追问"超大文件怎么办"：rope（平衡树存子串长度），按字符下标查找是 O(log n)。

### C-380 设计 Excel 求和公式 · 困难 · 阿里/字节

**题干**：请你设计一个能够支持求和公式的 Excel 表格。实现 `Excel` 类：`Excel(int height, int width)` 构造一个 `height × width` 的表格，初始全为 0；`void set(int row, int col, int val)` 将 `(row, col)` 单元格的值设为 `val`；`int get(int row, int col)` 返回该单元格的值；`int sum(int row, int col, String[] numbers)` 将单元格设为公式，`numbers` 中每项是单个单元格（如 `"A1"`）或矩形区域（如 `"A1:B2"`），该单元格的值等于这些单元格之和。公式中的单元格若也是公式，要**递归求值**。

**示例**：
```
Excel e = new Excel(3, "C");   // 3 行 3 列
e.set(1, "A", 2);              // A2 = 2
e.sum(3, "C", ["A1", "A1:B2"]); // C3 = A1 + (A1+A2+B1+B2) = 0 + (0+2+0+0) = 2
e.get(3, "C");                 // 2
e.set(2, "B", 2);              // B2 = 2
e.get(3, "C");                 // 4，公式动态重算
```

**思路**：
- 表格里有两类内容：**常量**和**公式**。所以第一张表 `formula: "r,c" -> 值或公式串`，"没记录"就代表 0。这是本题的唯一存储核心。
- `get` 不能"存什么返回什么"——公式要**现场求值**。做法是 `_eval(r, c)` 递归：常量直接返回，公式则展开每一项、递归累加。**必须递归而不是缓存**，因为被引用的单元格随时会被 `set` 改掉（示例里 `set(2,"B",2)` 之后 C3 从 2 变 4）。
- 公式里的引用有两种粒度：单个格子 `A1` 和矩形 `A1:B2`。统一处理方式是"先按 `:` 拆分，拿两个角点，再双重循环遍历矩形"，单格就是"左上角等于右下角"的退化情形。**用同一段代码处理两种情况**，代码短且不易错。
- 难点是**循环引用**：A1 引用了 B1、B1 又引用 A1，递归会栈溢出。解法是 `busy` 集合做"正在计算"标记：进入 `_eval` 时加入，退出时删除，若再次遇到同一格就返回 0（题目保证不会出现非法引用，但防御性处理是加分项）。

**代码**：
```javascript
class Excel {
  constructor(height, width) {
    this.h = height; this.w = width;
    this.cells = new Map();   // "r,c" -> 数字（常量）或 { sum: [...] }（公式）
    this.busy = new Set();    // 循环引用检测
  }
  _key(r, c) { return r + ',' + c; }
  set(row, col, val) { this.cells.set(this._key(row, col), val); }
  get(row, col) { return this._eval(row, col); }
  sum(row, col, numbers) { this.cells.set(this._key(row, col), { sum: numbers }); }
  _parse(ref) {                       // "A1" -> [行, 列]（都转 0-based）
    return [parseInt(ref.slice(1), 10) - 1, ref.charCodeAt(0) - 65];
  }
  _eval(r, c) {
    const key = this._key(r, c);
    const v = this.cells.get(key);
    if (v === undefined) return 0;    // 空格视为 0
    if (typeof v === 'number') return v;
    if (this.busy.has(key)) return 0; // 循环引用：按 0 兜底
    this.busy.add(key);
    let total = 0;
    for (const item of v.sum) {
      const [a, b] = item.split(':');
      const [r1, c1] = this._parse(a);
      const [r2, c2] = b ? this._parse(b) : [r1, c1];  // 单格退化为同一点
      for (let i = Math.min(r1, r2); i <= Math.max(r1, r2); i++) {
        for (let j = Math.min(c1, c2); j <= Math.max(c1, c2); j++) total += this._eval(i, j);
      }
    }
    this.busy.delete(key);
    return total;
  }
}
```

**复杂度**：`set`/`sum` O(1)；`get` 最坏 O(单元格总数)（每次递归展开全部引用）；空间 O(单元格数 + 递归深度)。

**易错点**：
- **公式不能缓存成值**：被引用的格子改了之后必须重算，缓存会让示例里的第二次 `get(3,"C")` 仍返回 2。
- 引用是 **1-based 行列 + 字母列**，`row/col` 参数是 **0-based 数字**，两套坐标系必须在 `_parse` 里一次性转换干净。
- 矩形区域的左上/右下不保证有序（`B2:A1` 也合法），循环边界要 `Math.min / Math.max` 而不是直接 `for (i = r1; i <= r2; i++)`。
- `busy` 必须在**所有返回路径**上清理；只写在末尾的话，抛错或提前 return 会让该格永久锁死。

**变体与追问**：
- 追问"如何避免每次 get 都全量重算"：建**反向依赖图**（被引用格 -> 引用者），`set` 时拓扑排序失效缓存；或做记忆化 + 版本号。
- 追问"循环引用如何报错"：把 `busy` 路径记下来，检测到环时抛出并高亮环上的所有格子，这正是 Excel 的 `#REF!` 提示。
- 追问"公式里出现 SUM(A1:A3) 这种函数嵌套"：解析器要分层（词法 → 语法树 → 求值），本质是写一个小型表达式解释器。
