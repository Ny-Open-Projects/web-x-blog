# 15 动态规划：线性与序列（C-281 ~ C-300）

> 线性 DP 是大厂笔试的"主战场"：题干只要出现**方案数、最值、能不能凑成、两个字符串比对**，几乎都是它。真正的分水岭不是写出转移方程，而是能否讲清**状态为什么这样定义、初始化代表什么、遍历顺序为什么不能反**。**识别特征**：看到"到第 i 个位置的最优解"想到一维线性 DP；看到"两个串的公共/编辑/匹配"想到双序列 DP；看到"连续区间上的最优决策"想到区间 DP。

## 题型速查

| 子类型 | 核心手法 | 代表题 |
|---|---|---|
| 一维线性递推 | 只依赖前 1~2 项，滚动变量降维 | C-281 C-282 C-283 C-299 |
| 环形 / 多状态 | 拆环为线性，或用 hold/cash 状态机 | C-284 C-295 C-296 C-297 C-298 |
| 序列 + 二分 | tails 数组维护"最小结尾" | C-285 C-287 |
| 双序列匹配 | 二维 dp，按相等/不等分流 | C-288 C-290 C-291 C-292 C-293 C-294 |
| 区间 DP（回文） | 由内向外扩，倒序枚举左端点 | C-289 |
| 贪心 + DP 对照 | 能贪心则贪心，否则 DP | C-300 |

### C-281 爬楼梯 · 简单 · 字节/阿里/腾讯

**题干**：假设你正在爬楼梯，需要 `n` 阶才能到达楼顶。每次你可以爬 **1 或 2** 个台阶，问有多少种不同的方法可以爬到楼顶。`1 <= n <= 45`，结果保证在 32 位整数范围内。

**示例**：`输入: n = 3` → `输出: 3`（1+1+1、1+2、2+1）

**思路**：
- 状态定义：`dp[i]` = 爬到第 `i` 阶的方法总数。之所以"以阶数为状态"，是因为**到达第 i 阶的最后一步是确定的**，只可能是从 `i-1` 跨 1 阶或从 `i-2` 跨 2 阶，历史路径被完全压缩进这两个状态里，无需知道具体怎么走的。
- 转移方程：`dp[i] = dp[i-1] + dp[i-2]`——按最后一步分类，两类互斥且完备。
- 初始化：`dp[1] = 1`（只有 1 阶一种），`dp[2] = 2`（1+1 或 2）。
- 遍历顺序：`i` 从 3 到 `n` 严格递增，因为 `dp[i]` 依赖更小的下标，顺序不能反。
- 本质是带初值的斐波那契递推，面试常追问「n 很大时如何取模」以及「步长集合变化后能否用矩阵快速幂加速」。

**代码**：
```javascript
/**
 * 爬楼梯：每次走 1 或 2 阶，求到第 n 阶的方案数
 * @param {number} n
 * @returns {number}
 */
function climbStairs(n) {
  if (n <= 2) return n;        // n=1 返回 1，n=2 返回 2
  let prev2 = 1;               // dp[i-2]，初始为 dp[1]
  let prev1 = 2;               // dp[i-1]，初始为 dp[2]
  for (let i = 3; i <= n; i++) {
    const cur = prev1 + prev2; // dp[i] = dp[i-1] + dp[i-2]
    prev2 = prev1;             // 滚动：旧 prev1 降级为 prev2
    prev1 = cur;               // 当前值成为下一轮的 prev1
  }
  return prev1;
}

console.log(climbStairs(3)); // 3
console.log(climbStairs(5)); // 8
```

**复杂度**：时间 O(n) ／ 空间 O(1)（滚动变量后不再需要数组）。

**易错点**：
- 忘记 `n <= 2` 的边界，导致 `prev1` 初值错位。
- 误用递归朴素实现，`n = 45` 会指数级爆炸且栈溢出。
- 滚动时先更新 `prev2` 再算 `cur`，顺序颠倒会污染依赖值。
- 本题本质是斐波那契数列，但不要写成 `dp[0]=0, dp[1]=1` 的斐波那契初值，台阶语义不同。

**变体与追问**：
- 每次可走 1~m 阶：`dp[i] = sum(dp[i-1..i-m])`，用前缀和或滑动窗口把 O(nm) 降到 O(n)。
- 不能连续走两阶：增加一维状态记录"上一步走了几阶"。
- 带障碍（某些台阶不能踩）：遇到障碍令 `dp[i] = 0` 即可，思路同 C-316。

### C-282 使用最小花费爬楼梯 · 简单 · 腾讯/美团

**题干**：给你一个整数数组 `cost`，其中 `cost[i]` 是从第 `i` 个台阶向上爬需要支付的费用。一旦支付该费用，你可以选择爬 1 或 2 个台阶。你可以从下标 0 或 1 的台阶开始，返回爬到楼顶（下标 `n`，即越过最后一个台阶）的最小花费。`2 <= cost.length <= 1000`。

**示例**：`输入: cost = [10,15,20]` → `输出: 15`（从 1 出发付 15 直接到顶）

**思路**：
- 状态定义：`dp[i]` = **到达**第 `i` 阶的最小花费（站在第 i 阶上，但还没支付 `cost[i]`）。把状态定在"到达"而非"离开"，是因为费用发生在起跳时，到达时不应计入当前台阶费用，语义更干净。
- 转移方程：`dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`——到达 i 只能从 i-1 或 i-2 起跳，起跳前必须先支付那一阶的费用。
- 初始化：`dp[0] = 0, dp[1] = 0`——题目允许直接从 0 或 1 起步，起步本身不花钱。
- 遍历顺序：`i` 从 2 递增到 `n`，答案取 `dp[n]`（楼顶在 n，不需要支付费用）。
- 两种理解方式（到达 vs 离开）只差一个下标偏移，但混用会让初始化和返回值同时出错，选定一种就全程贯彻。

**代码**：
```javascript
/**
 * 最小花费爬楼梯：dp[i] 为到达第 i 阶的最小花费
 * @param {number[]} cost
 * @returns {number}
 */
function minCostClimbingStairs(cost) {
  const n = cost.length;
  let prev2 = 0; // dp[0]：从 0 起步花费 0
  let prev1 = 0; // dp[1]：从 1 起步花费 0
  for (let i = 2; i <= n; i++) {
    // 从 i-1 起跳要付 cost[i-1]，从 i-2 起跳要付 cost[i-2]
    const cur = Math.min(prev1 + cost[i - 1], prev2 + cost[i - 2]);
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1; // 即 dp[n]
}

console.log(minCostClimbingStairs([10, 15, 20]));      // 15
console.log(minCostClimbingStairs([1, 100, 1, 1, 1, 100, 1, 1, 100, 1])); // 6
```

**复杂度**：时间 O(n) ／ 空间 O(1)。

**易错点**：
- 把 `dp[i]` 定义成"离开第 i 阶的最小花费"，导致初始化与答案下标全部错位。
- 答案返回 `dp[n-1]`：楼顶在 n，最后一阶也要能被跨过，必须返回 `dp[n]`。
- 初始化写成 `dp[0]=cost[0]`：起步不收费，这是与 C-283 打家劫舍最大的语义差别。
- 数组至少两个元素，不需要额外处理 `n=1`。

**变体与追问**：
- 每次最多跨 3 阶：转移式扩展到三项取 min。
- 输出具体路径：额外用 `from[i]` 记录最优来源，最后回溯。
- 若必须从第 0 阶起步：初始化改为 `dp[0]=0, dp[1]=cost[0]`，其余不变。

### C-283 打家劫舍 · 中等 · 字节/美团/快手

**题干**：你是一个专业小偷，计划偷窃沿街的房屋。每间房内都藏有一定的现金 `nums[i]`，相邻的房屋装有相互连通的防盗系统，**如果两间相邻的房屋在同一晚上被闯入，系统会自动报警**。给定非负整数数组 `nums`，求在不触动警报的情况下，一夜之内能够偷窃到的最高金额。`1 <= nums.length <= 100`。

**示例**：`输入: nums = [2,7,9,3,1]` → `输出: 12`（偷 2+9+1）

**思路**：
- 状态定义：`dp[i]` = 考虑前 `i+1` 间房（下标 0..i）能偷到的最大金额。状态定在"前缀"上，是因为相邻约束是**局部**的，只要保证"第 i 间偷或不偷"与前一位相关，更早的决策已被最优值吸收。
- 转移方程：`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`——第 i 间不偷，答案继承 `dp[i-1]`；偷第 i 间，则第 i-1 间必不能偷，只能接 `dp[i-2]`。
- 初始化：`dp[0] = nums[0]`，`dp[1] = max(nums[0], nums[1])`。
- 遍历顺序：`i` 从 2 递增，依赖 `i-1`、`i-2` 两个更小下标。
- 这类「相邻不能同选」的约束在环形、树形、网格上反复出现，本质都是「当前选不选」影响邻居，用状态把影响显式化即可。

**代码**：
```javascript
/**
 * 打家劫舍：不能偷相邻房屋，求最大金额
 * @param {number[]} nums
 * @returns {number}
 */
function rob(nums) {
  const n = nums.length;
  if (n === 0) return 0;
  if (n === 1) return nums[0];
  let prev2 = nums[0];                        // dp[0]
  let prev1 = Math.max(nums[0], nums[1]);     // dp[1]
  for (let i = 2; i < n; i++) {
    // 不偷 i：prev1；偷 i：prev2 + nums[i]
    const cur = Math.max(prev1, prev2 + nums[i]);
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}

console.log(rob([2, 7, 9, 3, 1])); // 12
console.log(rob([1, 2, 3, 1]));    // 4
```

**复杂度**：时间 O(n) ／ 空间 O(1)。

**易错点**：
- `dp[1]` 忘记取 `max`，直接写 `nums[1]`，当 `nums[0] > nums[1]` 时出错。
- 把转移写成 `dp[i-2] + nums[i]` 却不和 `dp[i-1]` 取 max，漏掉"不偷"分支。
- 金额非负但可能为 0，不能用 0 当 `-Infinity` 的哨兵来判断无解。
- 空间压缩时必须先保存旧 `prev1`，否则 `prev2` 被覆盖后算错。

**变体与追问**：
- 房屋围成环（LC 213）：见 C-284，拆成两段线性。
- 房屋是二叉树（LC 337）：树形 DP，每个节点返回"偷/不偷"两个值。
- 要求输出方案：保留 `dp` 数组并反向判断 `dp[i] === dp[i-1]` 决定是否偷。

### C-284 打家劫舍 II · 中等 · 字节/阿里

**题干**：你是一个专业小偷，沿街的房屋**围成一圈**，这意味着第一间房和最后一间房是相邻的。每间房内有一定现金 `nums[i]`，相邻房屋被盗会触发报警。给定非负整数数组 `nums`，求今晚能偷到的最高金额。`1 <= nums.length <= 100`。

**示例**：`输入: nums = [2,3,2]` → `输出: 3`（不能同时偷首尾，只能偷中间那间 3）

**思路**：
- 核心是把**环拆成两条链**：首尾不能同时偷，于是最优解要么"不偷第 0 间"（等价于在 `[1, n-1]` 上做线性打家劫舍），要么"不偷第 n-1 间"（在 `[0, n-2]` 上做）。两种情况取较大值即可覆盖全部合法解。
- 状态定义：沿用 C-283 的 `dp[i]` = 区间内考虑前若干间的最大金额，只是作用域被限制在子区间。
- 转移方程：`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`。
- 初始化：子区间 DP 用 `prev2 = 0, prev1 = 0` 作为哨兵（相当于 `dp[-1]=dp[-2]=0`），可统一处理任意起点。
- 遍历顺序：子区间内从左到右递增。

**代码**：
```javascript
/**
 * 在闭区间 [start, end] 上做线性打家劫舍
 */
function robRange(nums, start, end) {
  let prev2 = 0; // dp[i-2]
  let prev1 = 0; // dp[i-1]
  for (let i = start; i <= end; i++) {
    const cur = Math.max(prev1, prev2 + nums[i]);
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}

/**
 * 打家劫舍 II：房屋围成环
 * @param {number[]} nums
 * @returns {number}
 */
function rob2(nums) {
  const n = nums.length;
  if (n === 1) return nums[0];
  if (n === 2) return Math.max(nums[0], nums[1]);
  // 情况一：不偷最后一间；情况二：不偷第一间
  return Math.max(robRange(nums, 0, n - 2), robRange(nums, 1, n - 1));
}

console.log(rob2([2, 3, 2]));       // 3
console.log(rob2([1, 2, 3, 1]));    // 4
console.log(rob2([1, 2, 3]));       // 3
```

**复杂度**：时间 O(n) ／ 空间 O(1)。

**易错点**：
- 只做一次线性 DP 然后特殊处理首尾，逻辑极易写错；拆两段是最稳的写法。
- `n = 1`、`n = 2` 必须单独返回，否则子区间会变成非法区间。
- 两段区间的边界写成 `[0, n-1]`，等于没拆环。
- `robRange` 的哨兵必须是 0 而非 `-Infinity`，因为金额非负，空区间贡献为 0。

**变体与追问**：
- 房屋排成矩阵/网格：相邻约束变成二维，状态要带方向。
- 若允许偷首尾但不能同时偷"首、尾、次尾"：需要增加状态维度记录边界选择。
- 若金额可能为负：哨兵要改成 `-Infinity`，且语义变为"必须偷"还是"可不偷"要重新定义。

### C-285 最长递增子序列 · 中等 · 字节/腾讯/美团

**题干**：给你一个整数数组 `nums`，找到其中**最长严格递增子序列**的长度。子序列由删除（或不删除）数组元素而不改变其余元素顺序得到。`1 <= nums.length <= 2500`，`-10^4 <= nums[i] <= 10^4`。要求 O(n log n) 更佳。

**示例**：`输入: nums = [10,9,2,5,3,7,101,18]` → `输出: 4`（如 2,3,7,101）

**思路**：
- 状态定义（朴素）：`dp[i]` = 以 `nums[i]` **结尾**的 LIS 长度。状态必须"以 i 结尾"，否则无法判断新元素能否接续。
- 转移方程（朴素）：`dp[i] = max(dp[j]) + 1`，其中 `j < i` 且 `nums[j] < nums[i]`，复杂度 O(n²)。
- 最优解法（贪心 + 二分）：维护 `tails[k]` = 所有长度为 `k+1` 的递增子序列中，**结尾元素的最小值**。这个定义的关键在于：结尾越小，后续越容易接上，因此只需保留每个长度下的最小结尾。`tails` 天然严格递增，可用二分查找。
- 初始化：`tails` 为空。
- 遍历顺序：从左到右扫 `nums`，对每个 `x` 二分找第一个 `>= x` 的位置并替换；若都比 `x` 小则追加，长度加一。

**代码**：
```javascript
/**
 * 最长严格递增子序列：贪心 + 二分，O(n log n)
 * @param {number[]} nums
 * @returns {number}
 */
function lengthOfLIS(nums) {
  const tails = []; // tails[k] = 长度 k+1 的 LIS 的最小结尾
  for (const x of nums) {
    // 找第一个 >= x 的位置（lower_bound）
    let lo = 0;
    let hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = x; // 替换（让结尾更小）或追加（变长）
  }
  return tails.length;
}

console.log(lengthOfLIS([10, 9, 2, 5, 3, 7, 101, 18])); // 4
console.log(lengthOfLIS([0, 1, 0, 3, 2, 3]));           // 4
console.log(lengthOfLIS([7, 7, 7, 7]));                 // 1
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)。

**易错点**：
- `tails` 里存的**不是**真实的 LIS，只是每个长度的最小结尾，不能用它还原序列（要还原需额外记录前驱）。
- 严格递增用 `lower_bound`（第一个 `>= x`）；非严格递增（允许相等）要用 `upper_bound`（第一个 `> x`）。
- 二分写成 `<=` 会把相等元素错误替换，导致非严格场景结果偏大。
- 朴素 DP 的 `dp` 初值全为 1，答案要取 `max(dp)` 而不是 `dp[n-1]`。

**变体与追问**：
- 最长递增子序列的个数（LC 673）：见 C-286，需要额外计数数组。
- 二维信封嵌套（LC 354）：见 C-287，排序后转一维 LIS。
- 最长**非递减**子序列：二分条件改为 `upper_bound`。
- 还原具体序列：朴素 DP 记录 `pre[i]`，最后从最大 `dp` 处回溯。

### C-286 最长递增子序列的个数 · 中等 · 字节/腾讯

**题干**：给定一个未排序的整数数组 `nums`，返回最长递增子序列的**个数**。注意递增子序列必须是**严格递增**的。`1 <= nums.length <= 2000`，答案保证在 32 位整数范围内。

**示例**：`输入: nums = [1,3,5,4,7]` → `输出: 2`（1,3,4,7 与 1,3,5,7）

**思路**：
- 状态定义需要**两个数组**：`len[i]` = 以 `nums[i]` 结尾的 LIS 长度；`cnt[i]` = 以 `nums[i]` 结尾且达到该长度的不同方案数。单个长度数组无法统计"有多少条"，必须额外记数。
- 转移方程：对每个 `j < i` 且 `nums[j] < nums[i]`，若 `len[j] + 1 > len[i]`，说明找到了更长的方案，`len[i] = len[j] + 1` 并将 `cnt[i]` **重置**为 `cnt[j]`；若 `len[j] + 1 === len[i]`，说明找到了等长的新方案，`cnt[i] += cnt[j]`。
- 初始化：`len[i] = 1`、`cnt[i] = 1`（每个元素自身构成一条长度 1 的序列）。
- 遍历顺序：外层 `i` 递增，内层 `j` 从 0 到 `i-1`，因为只依赖左侧已算好的结果。最后再扫一遍，把所有 `len[i] === maxLen` 的 `cnt[i]` 相加（注意不是只取某一个，最大长度可能在多个位置结尾）。

**代码**：
```javascript
/**
 * 最长递增子序列的个数（严格递增）
 * @param {number[]} nums
 * @returns {number}
 */
function findNumberOfLIS(nums) {
  const n = nums.length;
  const len = new Array(n).fill(1); // 以 i 结尾的 LIS 长度
  const cnt = new Array(n).fill(1); // 以 i 结尾的 LIS 方案数
  let maxLen = 1;

  for (let i = 0; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        if (len[j] + 1 > len[i]) {
          len[i] = len[j] + 1;  // 找到更长：继承方案数并覆盖
          cnt[i] = cnt[j];
        } else if (len[j] + 1 === len[i]) {
          cnt[i] += cnt[j];     // 等长：累加方案数
        }
      }
    }
    maxLen = Math.max(maxLen, len[i]);
  }

  let ans = 0;
  for (let i = 0; i < n; i++) {
    if (len[i] === maxLen) ans += cnt[i];
  }
  return ans;
}

console.log(findNumberOfLIS([1, 3, 5, 4, 7])); // 2
console.log(findNumberOfLIS([2, 2, 2, 2, 2])); // 5
```

**复杂度**：时间 O(n²) ／ 空间 O(n)。

**易错点**：
- 找到更长方案时写成 `cnt[i] += cnt[j]`，正确做法是 `cnt[i] = cnt[j]`（旧方案已不是最长，必须丢弃）。
- 最后只取 `cnt[argmax(len)]`，漏掉其他同样达到 `maxLen` 的结尾位置。
- 判断用 `nums[j] < nums[i]`；若写成 `<=` 会把相等元素算作递增，与"严格递增"矛盾。
- `cnt` 初值忘了设 1，导致单个元素的方案数变成 0。

**变体与追问**：
- O(n log n) 版本需要树状数组/线段树维护"长度 → 方案数"的前缀聚合，实现复杂度高，笔试通常接受 O(n²)。
- 若求"最长非递减子序列的个数"，比较条件改为 `<=`，并注意去重语义。
- 若只要长度不要个数，回到 C-285。

### C-287 俄罗斯套娃信封问题 · 困难 · 字节/腾讯

**题干**：给你一个二维整数数组 `envelopes`，其中 `envelopes[i] = [wi, hi]` 表示第 `i` 个信封的宽度和高度。当另一个信封的宽度和高度**都比**这个信封大时，这个信封就可以放进另一个信封里（不能旋转）。请计算最多能有多少个信封组成一组"俄罗斯套娃"信封。`1 <= envelopes.length <= 10^5`。

**示例**：`输入: envelopes = [[5,4],[6,4],[6,7],[2,3]]` → `输出: 3`（[2,3] → [5,4] → [6,7]）

**思路**：
- 这是"二维 LIS"：要求同时满足 `w` 和 `h` 都严格递增。关键技巧是**排序降维**：先按宽度升序，宽度**相同**时按高度**降序**。
- 为什么同宽要降序？因为同宽的两个信封不能互相嵌套，降序排列后，它们的高度在序列中呈递减，一维 LIS（严格递增）绝不会同时选中它们，天然排除了"同宽嵌套"的非法情况。若同宽也升序，就会被错误地串起来。
- 状态定义：排序后只取高度序列，问题变为在高度上求**严格递增子序列**的最大长度；`tails[k]` 表示长度 `k+1` 的递增子序列的最小结尾高度。
- 转移方程：对每个高度 `h`，二分找到第一个 `>= h` 的位置并用 `h` 替换；若所有结尾都小于 `h` 则追加，等价于 LIS 的贪心转移。
- 初始化：`tails` 为空。
- 遍历顺序：按排序后的信封顺序从左到右处理，此时宽度已满足递增，只需在高度上找 LIS。

**代码**：
```javascript
/**
 * 俄罗斯套娃信封：排序降维 + 一维 LIS
 * @param {number[][]} envelopes
 * @returns {number}
 */
function maxEnvelopes(envelopes) {
  // 宽升序；宽相同时高降序，避免同宽被串成链
  envelopes.sort((a, b) => (a[0] === b[0] ? b[1] - a[1] : a[0] - b[0]));

  const tails = []; // 高度序列上每个 LIS 长度的最小结尾高度
  for (const [, h] of envelopes) {
    let lo = 0;
    let hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < h) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = h;
  }
  return tails.length;
}

console.log(maxEnvelopes([[5, 4], [6, 4], [6, 7], [2, 3]])); // 3
console.log(maxEnvelopes([[1, 1], [1, 1], [1, 1]]));          // 1
```

**复杂度**：时间 O(n log n)（排序 O(n log n) + n 次二分）／ 空间 O(n)。

**易错点**：
- 同宽时也用升序排序，会把宽度相同的信封错误嵌套，答案偏大。
- 排序比较器写成 `a[0] - b[0] || a[1] - b[1]`，这正是错误写法。
- 高度 LIS 用 `lower_bound`（严格递增），若改成 `upper_bound` 会允许等高嵌套。
- `envelopes` 可能为空或长度为 1，代码本身能处理，但要在题干约束外做好防御。

**变体与追问**：
- 三维套娃（长宽高）：需要 CDQ 分治或树套树，属于竞赛难度。
- 允许旋转信封：宽高可交换，先对每个信封归一化（`w <= h`）再套。
- 若求"最多能套多少个"并输出方案：`tails` 需改为记录前驱。

### C-288 最长公共子序列 · 中等 · 字节/阿里/美团

**题干**：给定两个字符串 `text1` 和 `text2`，返回这两个字符串的**最长公共子序列**的长度。若不存在公共子序列，返回 0。子序列是指在不改变字符相对顺序的前提下删除若干字符得到的新字符串。`1 <= text1.length, text2.length <= 1000`。

**示例**：`输入: text1 = "abcde", text2 = "ace"` → `输出: 3`（"ace"）

**思路**：
- 状态定义：`dp[i][j]` = `text1` 的前 `i` 个字符与 `text2` 的前 `j` 个字符的 LCS 长度。用"前 i 个"而不用"以 i 结尾"，是因为 LCS 不要求连续，前缀状态能自然承接所有历史最优。
- 转移方程：若 `text1[i-1] === text2[j-1]`，这个字符一定能贡献进 LCS，`dp[i][j] = dp[i-1][j-1] + 1`；否则两个末尾字符至少有一个不在 LCS 中，`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`。
- 初始化：`dp[0][*] = dp[*][0] = 0`，任一空串与任何串的 LCS 都是 0。
- 遍历顺序：`i` 从 1 到 m、`j` 从 1 到 n **都正序**，因为依赖左、上、左上三个已计算格子。字符串 DP 的下标偏移体现在：第 `i` 个字符对应 `text1[i-1]`，写错会整体错位。
- LCS 是所有双序列问题的母题：编辑距离、删除操作、最短公共超序列都能由它变形得到，务必吃透。

**代码**：
```javascript
/**
 * 最长公共子序列（不要求连续）
 * @param {string} text1
 * @param {string} text2
 * @returns {number}
 */
function longestCommonSubsequence(text1, text2) {
  const m = text1.length;
  const n = text2.length;
  // dp[i][j] = text1 前 i 个 与 text2 前 j 个 的 LCS
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (text1[i - 1] === text2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1; // 该字符纳入公共子序列
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]); // 舍弃一侧
      }
    }
  }
  return dp[m][n];
}

console.log(longestCommonSubsequence("abcde", "ace")); // 3
console.log(longestCommonSubsequence("abc", "def"));   // 0
```

**复杂度**：时间 O(mn) ／ 空间 O(mn)，可用滚动数组压到 O(n)。

**易错点**：
- 字符下标写成 `text1[i]` / `text2[j]`，导致越界或错位；正确是 `i-1` / `j-1`。
- 相等时错误地取 `max(dp[i-1][j], dp[i][j-1]) + 1`，会重复计数，正确只用左上角 `+1`。
- 一维优化时忘记保存 `dp[j-1]` 的旧值（左上角），必须用 `prev` 变量暂存。
- 把"子序列"误解为"子串"（连续），那是 C-311/C-312，转移完全不同。

**变体与追问**：
- 求具体 LCS 字符串：从 `dp[m][n]` 反向回溯，相等取字符并向左上走，否则向值大的一侧走。
- 最短公共超序列（LC 1092）：长度 = `m + n - LCS`。
- 两个字符串的删除操作（LC 583）：见 C-291，答案同为 `m + n - 2*LCS`。

### C-289 最长回文子序列 · 中等 · 腾讯/快手

**题干**：给你一个字符串 `s`，找出其中最长的**回文子序列**的长度。子序列不要求连续，但必须保持字符相对顺序。`1 <= s.length <= 1000`，`s` 仅由小写英文字母组成。

**示例**：`输入: s = "bbbab"` → `输出: 4`（"bbbb"）

**思路**：
- 状态定义：`dp[i][j]` = 子串 `s[i..j]` 内最长回文子序列的长度。回文结构天然是"两端向中间收缩"，所以必须用**区间**作状态，一维前缀无法表达"两端同时去掉"。
- 转移方程：若 `s[i] === s[j]`，两端可以同时纳入，`dp[i][j] = dp[i+1][j-1] + 2`；若不相等，至少有一端不在回文中，`dp[i][j] = max(dp[i+1][j], dp[i][j-1])`。
- 初始化：`dp[i][i] = 1`（单字符是长度 1 的回文）；长度 2 的区间由通式自然得到（`dp[i+1][i]` 视作空区间 0，代码中 `dp` 全 0 即可）。
- 遍历顺序：**`i` 必须从 n-1 递减到 0，`j` 从 i+1 递增到 n-1**。因为 `dp[i][j]` 依赖 `dp[i+1][*]`（更大的 i，必须先算）和 `dp[*][j-1]`（更小的 j）。若 i 正序，`dp[i+1][j-1]` 还没算，结果错误。
- 区间 DP 的通用套路是：先定端点、再按长度递推、最后枚举分割点或收缩方式，回文题只是收缩方式固定为「两端比较」。

**代码**：
```javascript
/**
 * 最长回文子序列：区间 DP
 * @param {string} s
 * @returns {number}
 */
function longestPalindromeSubseq(s) {
  const n = s.length;
  if (n === 0) return 0;
  const dp = Array.from({ length: n }, () => new Array(n).fill(0));
  for (let i = 0; i < n; i++) dp[i][i] = 1; // 单字符回文

  // i 必须倒序：dp[i][j] 依赖 dp[i+1][j-1]（下一行）
  for (let i = n - 1; i >= 0; i--) {
    for (let j = i + 1; j < n; j++) {
      if (s[i] === s[j]) {
        dp[i][j] = dp[i + 1][j - 1] + 2; // 两端都能用上
      } else {
        dp[i][j] = Math.max(dp[i + 1][j], dp[i][j - 1]); // 舍弃一端
      }
    }
  }
  return dp[0][n - 1];
}

console.log(longestPalindromeSubseq("bbbab")); // 4
console.log(longestPalindromeSubseq("cbbd"));  // 2
```

**复杂度**：时间 O(n²) ／ 空间 O(n²)，可压到 O(n)。

**易错点**：
- 外层 `i` 写成 0→n-1 正序，访问到未计算的 `dp[i+1][j-1]`，答案偏小。
- 内层 `j` 从 i 开始，`j === i` 时会把 `dp[i][i]` 再算一遍并可能覆盖成 0。
- 相等时写成 `dp[i+1][j-1] + 1`，回文是两端各加一个字符，应为 `+2`。
- 与"最长回文子串"混淆：子串必须连续，转移不同（C-312 类）。

**变体与追问**：
- 最长回文子串：状态改为"以 i、j 为端点是否回文"，或中心扩展 O(n²)/Manacher O(n)。
- 最少插入次数使字符串回文（LC 1312）：答案 = `n - 最长回文子序列长度`。
- 一维空间优化：`dp[j]` 需保存上一行旧值，务必用临时变量防止覆盖。

### C-290 编辑距离 · 困难 · 字节/阿里/腾讯

**题干**：给你两个单词 `word1` 和 `word2`，请返回将 `word1` 转换成 `word2` 所使用的**最少操作数**。你可以对一个单词进行三种操作：插入一个字符、删除一个字符、替换一个字符。`0 <= word1.length, word2.length <= 500`。

**示例**：`输入: word1 = "horse", word2 = "ros"` → `输出: 3`（horse→rorse→rose→ros）

**思路**：
- 状态定义：`dp[i][j]` = 把 `word1` 前 `i` 个字符变成 `word2` 前 `j` 个字符的最少操作数。用前缀而不是整串，是因为一次操作只影响末尾，前缀子问题可复用（最优子结构）。
- 转移方程：若 `word1[i-1] === word2[j-1]`，末字符已匹配，`dp[i][j] = dp[i-1][j-1]`；否则三选一取最小再加 1：
  - 删除：`dp[i-1][j] + 1`（丢掉 word1 末字符）
  - 插入：`dp[i][j-1] + 1`（给 word1 补上 word2 末字符）
  - 替换：`dp[i-1][j-1] + 1`（把末字符改成目标）
- 初始化：`dp[i][0] = i`（删光 i 个），`dp[0][j] = j`（插入 j 个）。
- 遍历顺序：`i`、`j` 均正序，依赖左上、上、左三个方向。
- 三种操作的取舍体现了编辑距离的核心：匹配就跳过、不匹配就付出一次代价，代价模型换成权重后仍是同一套骨架。

**代码**：
```javascript
/**
 * 编辑距离：插入/删除/替换三种操作
 * @param {string} word1
 * @param {string} word2
 * @returns {number}
 */
function minDistance(word1, word2) {
  const m = word1.length;
  const n = word2.length;
  // dp[i][j]：word1 前 i 个 → word2 前 j 个 的最少操作数
  const dp = Array.from({ length: m + 1 }, (_, i) =>
    Array.from({ length: n + 1 }, (_, j) => (i === 0 ? j : j === 0 ? i : 0))
  );

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1];          // 末字符相同，无需操作
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i - 1][j],    // 删除 word1 末字符
          dp[i][j - 1],    // 插入 word2 末字符
          dp[i - 1][j - 1] // 替换
        );
      }
    }
  }
  return dp[m][n];
}

console.log(minDistance("horse", "ros"));        // 3
console.log(minDistance("intention", "execution")); // 5
```

**复杂度**：时间 O(mn) ／ 空间 O(mn)，可滚动到 O(n)。

**易错点**：
- 初始化只设了 `dp[0][0]=0`，忘记第一行/第一列，导致边界全错。
- 相等分支仍加 `Math.min(...)+1`，白白多算一次操作。
- 三个来源写混：删除是 `dp[i-1][j]`、插入是 `dp[i][j-1]`，方向记反是最常见 bug。
- 一维优化时 `dp[j-1]` 已被本轮覆盖，必须先存 `prev`（左上角旧值）。

**变体与追问**：
- 只有删除和插入（无替换）：LC 583，答案 = `m + n - 2*LCS`（见 C-291）。
- 操作带不同代价：把 `+1` 换成对应代价，结构不变。
- 求具体编辑步骤：保留完整 `dp` 表反向回溯每一步选择了哪种操作。

### C-291 两个字符串的删除操作 · 中等 · 美团/腾讯

**题干**：给定两个单词 `word1` 和 `word2`，返回使得 `word1` 和 `word2` **相同**所需的最小步数。每步可以删除任意一个字符串中的一个字符。`1 <= word1.length, word2.length <= 500`。

**示例**：`输入: word1 = "sea", word2 = "eat"` → `输出: 2`（删 s、删 t，剩 "ea"）

**思路**：
- 本题本质是"留下最长公共子序列，其余全删"。设 LCS 长度为 `L`，则 `word1` 要删 `m - L` 个、`word2` 要删 `n - L` 个，总步数 `m + n - 2L`。因此只需先求 LCS。
- 正确性：保留下来的字符必须同时是两个串的子序列，要让删除数最少就等价于让保留数最多，而最多能同时保留的正是最长公共子序列 LCS 的长度。
- 状态定义：`dp[i][j]` = `word1` 前 `i` 个与 `word2` 前 `j` 个的 LCS 长度，与 C-288 完全一致。
- 转移方程：相等 `dp[i][j] = dp[i-1][j-1] + 1`；不等 `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`。
- 初始化：`dp` 首行首列全 0。
- 遍历顺序：`i`、`j` 均正序。
- 另一种直接 DP 写法（不借用 LCS）：`dp[i][j]` = 使两前缀相同的最少删除数，相等时 `dp[i-1][j-1]`，不等时 `min(dp[i-1][j], dp[i][j-1]) + 1`，二者等价。
- 注意区分「删除」和「替换」：删除只能减少字符，替换能直接改写，两者可达的终态不同，答案自然不同。

**代码**：
```javascript
/**
 * 两个字符串的删除操作：m + n - 2 * LCS
 * @param {string} word1
 * @param {string} word2
 * @returns {number}
 */
function minDistance2(word1, word2) {
  const m = word1.length;
  const n = word2.length;
  // dp[i][j] = 两前缀的 LCS 长度
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1;
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }

  const lcs = dp[m][n];
  return m + n - 2 * lcs; // 除了 LCS 的字符，其余都要删
}

console.log(minDistance2("sea", "eat"));   // 2
console.log(minDistance2("leetcode", "etco")); // 4
```

**复杂度**：时间 O(mn) ／ 空间 O(mn)。

**易错点**：
- 忘记乘 2，写成 `m + n - lcs`，漏掉两个串各删一遍。
- 直接用编辑距离（C-290）套本题，多算了"替换"操作，结果偏小。
- 相等分支仍取 `max`，会丢掉 `+1` 的收益。
- 本题允许删任意一侧，因此答案是 `m+n-2L`；若只允许删 `word1`，答案才是 `m - L`。

**变体与追问**：
- 只允许删除 word1 的字符使二者相等：答案是 `m - LCS`。
- 允许替换（LC 72 编辑距离）：见 C-290。
- 要求输出被删除的字符序列：在 `dp` 表上回溯即可。

### C-292 不同的子序列 · 困难 · 字节/腾讯

**题干**：给你两个字符串 `s` 和 `t`，统计在 `s` 的**子序列**中出现的 `t` 的个数。`0 <= s.length, t.length <= 1000`，答案保证符合 32 位整数范围。

**示例**：`输入: s = "rabbbit", t = "rabbit"` → `输出: 3`（三种删掉一个 b 的方式）

**思路**：
- 状态定义：`dp[i][j]` = 在 `s` 的前 `i` 个字符中，能选出 `t` 的前 `j` 个字符的**方案数**。这是"计数型"双序列 DP，状态语义是方案数而非长度。
- 转移方程：若 `s[i-1] === t[j-1]`，有两种选择——用这个字符匹配（方案 `dp[i-1][j-1]`）或不用它（方案 `dp[i-1][j]`），两者相加；若不相等，只能用之前的结果 `dp[i-1][j]`。
- 初始化：`dp[i][0] = 1` 对所有 `i`——空串是任何串的子序列，只有"全不选"一种方案；`dp[0][j] = 0 (j>0)`——空串选不出非空串。
- 遍历顺序：`i`、`j` 均正序，依赖上方与左上。
- 计数型 DP 的关键是「分类不重不漏」：相同字符时把「用/不用」两种选择相加，正是组合计数的标准拆分。

**代码**：
```javascript
/**
 * 不同的子序列：统计 s 的子序列中等于 t 的个数
 * @param {string} s
 * @param {string} t
 * @returns {number}
 */
function numDistinct(s, t) {
  const m = s.length;
  const n = t.length;
  // dp[i][j] = s 前 i 个中选出 t 前 j 个的方案数
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));

  for (let i = 0; i <= m; i++) dp[i][0] = 1; // 空串恒为一种方案

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (s[i - 1] === t[j - 1]) {
        // 用当前字符匹配 + 不用当前字符
        dp[i][j] = dp[i - 1][j - 1] + dp[i - 1][j];
      } else {
        dp[i][j] = dp[i - 1][j]; // 只能用之前的字符
      }
    }
  }
  return dp[m][n];
}

console.log(numDistinct("rabbbit", "rabbit")); // 3
console.log(numDistinct("babgbag", "bag"));    // 5
```

**复杂度**：时间 O(mn) ／ 空间 O(mn)。

**易错点**：
- 相等时只写 `dp[i-1][j-1]`，漏掉"不用当前字符"的 `dp[i-1][j]`，导致重复字符场景少算。
- 初始化 `dp[i][0]` 写成 0，导致所有答案归零（空串必须是 1 种方案）。
- 把 `dp[i][0]` 和 `dp[0][j]` 弄反：`dp[0][j>0]` 才是 0。
- 一维优化时必须**逆序**遍历 `j`，因为 `dp[j-1]` 要用上一行的旧值。

**变体与追问**：
- 若 `s` 很长（1e5）而 `t` 很短：可对 `s` 做字符位置表 + 记忆化搜索，复杂度与匹配数相关。
- 求"最少删除多少字符使 t 成为 s 的子序列"：在本题基础上找最短可行前缀。
- 若允许重复使用 `s` 的字符（变成完全背包式计数）：转移改为 `dp[i][j-1] + ...`，需重新推导。

### C-293 通配符匹配 · 困难 · 字节/阿里

**题干**：给你一个输入字符串 `s` 和一个模式串 `p`，实现通配符匹配，支持 `'?'` 匹配任意**单个**字符、`'*'` 匹配任意**字符序列（包括空序列）**。匹配必须覆盖整个字符串。`0 <= s.length, p.length <= 2000`。

**示例**：`输入: s = "adceb", p = "*a*b"` → `输出: true`

**思路**：
- 状态定义：`dp[i][j]` = `s` 的前 `i` 个字符能否被 `p` 的前 `j` 个字符匹配。布尔型双序列 DP。
- 为什么用 DP 而非贪心：`*` 可以吞任意长度，贪心地"尽量多吞"在 `*a*b` 这类模式下需要回溯，DP 把所有前缀匹配状态都枚举，稳妥且可证。
- 转移方程分三类：
  - `p[j-1] === '*'`：`*` 可以匹配空（`dp[i][j-1]`）或再吞一个 `s` 的字符（`dp[i-1][j]`），故 `dp[i][j] = dp[i-1][j] || dp[i][j-1]`。
  - `p[j-1] === '?'` 或 `p[j-1] === s[i-1]`：只能一对一匹配，`dp[i][j] = dp[i-1][j-1]`。
  - 其他：`false`。
- 初始化：`dp[0][0] = true`；`dp[0][j]` 仅当 `p` 前 `j` 个全是 `*` 时为 true（`dp[0][j] = dp[0][j-1] && p[j-1]==='*'`）；`dp[i][0] = false (i>0)`。
- 遍历顺序：`i`、`j` 均正序，`*` 依赖上方和左方。
- 布尔 DP 的状态只有真/假，转移时把「或」和「与」用对即可，难点全在 `*` 的两种展开方式。

**代码**：
```javascript
/**
 * 通配符匹配：'?' 匹配单字符，'*' 匹配任意序列
 * @param {string} s
 * @param {string} p
 * @returns {boolean}
 */
function isMatch(s, p) {
  const m = s.length;
  const n = p.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(false));
  dp[0][0] = true;

  // 空串只能被全 '*' 的前缀匹配
  for (let j = 1; j <= n; j++) {
    if (p[j - 1] === '*') dp[0][j] = dp[0][j - 1];
  }

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      const pc = p[j - 1];
      if (pc === '*') {
        // '*' 匹配空（左）或吞掉 s[i-1]（上）
        dp[i][j] = dp[i - 1][j] || dp[i][j - 1];
      } else if (pc === '?' || pc === s[i - 1]) {
        dp[i][j] = dp[i - 1][j - 1];
      }
      // 其余情况保持 false
    }
  }
  return dp[m][n];
}

console.log(isMatch("adceb", "*a*b"));   // true
console.log(isMatch("acdcb", "a*c?b"));  // false
console.log(isMatch("", "*"));           // true
```

**复杂度**：时间 O(mn) ／ 空间 O(mn)，可压到 O(n)。

**易错点**：
- `*` 的转移只写 `dp[i][j-1]`（匹配空）或只写 `dp[i-1][j]`（吞字符），都会漏解。必须两者取或。
- 初始化漏掉"空串 vs 全星号"这一行，`s=""` 的用例全错。
- 把 `*` 当成"匹配一段固定长度"或"只匹配一个字符"，那是 `?` 的语义。
- 连续多个 `*` 未折叠，虽不影响正确性但会拖慢；可先预处理合并。

**变体与追问**：
- 正则表达式匹配（LC 10）：`*` 是"前一个字符重复 0 次或多次"，语义完全不同，见 C-294。
- 贪心 + 双指针回溯可做到 O(m+n) 均摊，但边界处理极易出错，面试建议先写 DP。
- 若要求返回所有匹配方案，需要 DFS + 记忆化。

### C-294 正则表达式匹配 · 困难 · 字节/腾讯/阿里

**题干**：给你一个字符串 `s` 和一个字符规律 `p`，实现支持 `'.'` 和 `'*'` 的正则表达式匹配。`'.'` 匹配任意单个字符；`'*'` 匹配**零个或多个前面的那一个元素**。匹配必须覆盖整个字符串 `s`。`1 <= s.length <= 20`，`1 <= p.length <= 30`。

**示例**：`输入: s = "aab", p = "c*a*b"` → `输出: true`（c 出现 0 次，a 出现 2 次）

**思路**：
- 状态定义：`dp[i][j]` = `s` 的前 `i` 个字符能否被 `p` 的前 `j` 个字符匹配。与通配符匹配结构相同，但 `*` 的语义不同：它修饰的是**前一个字符**，且可以出现 0 次。
- 转移方程：
  - 若 `p[j-1] === '*'`，考察 `p[j-2]`（被修饰字符）：
    - 不用这个组合（出现 0 次）：`dp[i][j-2]`；
    - 若 `p[j-2]` 能匹配 `s[i-1]`（`p[j-2]==='.'` 或相等），则 `*` 还能多吞一个：`dp[i-1][j]`。
    - 合并：`dp[i][j] = dp[i][j-2] || (match && dp[i-1][j])`。
  - 否则若 `p[j-1]==='.'` 或 `p[j-1]===s[i-1]`：`dp[i][j] = dp[i-1][j-1]`。
- 初始化：`dp[0][0]=true`；`dp[0][j]` 仅当 `p` 从 `j-1` 往前能由 `x*` 组合清空时成立，即 `p[j-1]==='*' && dp[0][j-2]`。
- 遍历顺序：`i`、`j` 正序；`*` 依赖 `j-2`（左二）和 `i-1`（上）。
- 与通配符最大的差异是 `*` 绑定前一个字符，因此循环里必须回看 `j-2`，并单独处理「前一字符能否匹配」。

**代码**：
```javascript
/**
 * 正则表达式匹配：'.' 任意单字符，'*' 重复前一元素零次或多次
 * @param {string} s
 * @param {string} p
 * @returns {boolean}
 */
function isMatchRe(s, p) {
  const m = s.length;
  const n = p.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(false));
  dp[0][0] = true;

  // 空串：只有形如 a*b*c* 的模式能匹配（每个 * 让前一字符出现 0 次）
  for (let j = 2; j <= n; j++) {
    if (p[j - 1] === '*') dp[0][j] = dp[0][j - 2];
  }

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (p[j - 1] === '*') {
        const prev = p[j - 2]; // 被 '*' 修饰的字符
        const canMatch = prev === '.' || prev === s[i - 1];
        // 出现 0 次（跳过 x*） 或 再吞一个字符
        dp[i][j] = dp[i][j - 2] || (canMatch && dp[i - 1][j]);
      } else if (p[j - 1] === '.' || p[j - 1] === s[i - 1]) {
        dp[i][j] = dp[i - 1][j - 1];
      }
    }
  }
  return dp[m][n];
}

console.log(isMatchRe("aab", "c*a*b")); // true
console.log(isMatchRe("mississippi", "mis*is*p*.")); // false
```

**复杂度**：时间 O(mn) ／ 空间 O(mn)。

**易错点**：
- 把 `*` 当成通配符的"任意序列"（C-293），语义错误。这里的 `*` 只修饰前一个字符。
- `*` 的"吞字符"分支写成 `dp[i-1][j-1]`，正确是 `dp[i-1][j]`（保持模式位置不动，继续用同一个 `x*`）。
- 初始化 `dp[0][j]` 写成 `p[j-1]==='*'`，漏掉 `dp[0][j-2]` 的递推，`"a*b*"` 之类会判错。
- `p[j-2]` 越界：`j` 从 1 开始，但只有 `p[j-1]==='*'` 时才会访问 `j-2`，此时 `j>=2`，安全。

**变体与追问**：
- 通配符匹配（LC 44）：见 C-293，`*` 语义不同，对比记忆。
- 支持 `+`（至少一次）：把"0 次"分支去掉即可。
- 若要返回匹配到的子串而非整体匹配：改为在 `dp` 表上找最长的可行区间。

### C-295 买卖股票的最佳时机 · 简单 · 字节/美团/拼多多

**题干**：给定一个数组 `prices`，它的第 `i` 个元素 `prices[i]` 表示一支给定股票第 `i` 天的价格。你只能选择**某一天买入**这只股票，并在**未来的某一个不同的日子卖出**。设计算法计算你所能获取的最大利润。若不能获取利润，返回 0。`1 <= prices.length <= 10^5`。

**示例**：`输入: prices = [7,1,5,3,6,4]` → `输出: 5`（第 2 天买 1，第 5 天卖 6）

**思路**：
- 状态定义：`hold` = 当前持有股票时的最大收益（买入即负收益），`cash` = 当前不持有时的最大收益。
- 转移方程：`hold = max(hold, -prices[i])`（本题只允许买一次，买入成本直接是 `-price`）；`cash = max(cash, hold + prices[i])`（在持有基础上卖出）。
- 更简洁的等价写法：维护"历史最低价" `minPrice`，答案 `max(prices[i] - minPrice)`。这就是 DP 压缩后的形态。
- 初始化：`minPrice = Infinity`，`ans = 0`（不允许亏损，故下界为 0）。
- 遍历顺序：从左到右单遍扫描，因为卖出必须在买入之后，顺序天然保证"先买后卖"。
- 股票系列共六道题，全部围绕 buy/sell 状态机展开，先把「一次交易」的状态图画清楚，其余变体只是加维度。

**代码**：
```javascript
/**
 * 买卖股票的最佳时机：只允许一次交易
 * @param {number[]} prices
 * @returns {number}
 */
function maxProfit(prices) {
  let minPrice = Infinity; // 至今出现过的最低买入价
  let ans = 0;             // 最大利润，初始 0 表示可以不交易
  for (const p of prices) {
    // 先更新最低价（相当于"今天买入"），再算今天卖出的利润
    minPrice = Math.min(minPrice, p);
    ans = Math.max(ans, p - minPrice);
  }
  return ans;
}

console.log(maxProfit([7, 1, 5, 3, 6, 4])); // 5
console.log(maxProfit([7, 6, 4, 3, 1]));    // 0
```

**复杂度**：时间 O(n) ／ 空间 O(1)。

**易错点**：
- 先算 `p - minPrice` 再更新 `minPrice`，会把"今天买今天卖"算进去（利润 0，不致命），但若顺序反了且要求严格未来交易日，语义要小心。
- 初始化 `ans = -Infinity`，遇到单调下跌数组会返回负数，与"可以不交易返回 0"矛盾。
- 用双重循环 O(n²)，`n=1e5` 会超时。
- 把"最多一次"写成"必须一次"，空数组/单元素时出错。

**变体与追问**：
- 允许多次交易（LC 122）：见 C-296，`hold = max(hold, cash - p)`。
- 含冷冻期（LC 309）：见 C-297。
- 最多 k 次（LC 188）：见 C-298。
- 允许做空：增加 `short` 状态，收益符号翻转。

### C-296 买卖股票的最佳时机 II · 中等 · 字节/快手/拼多多

**题干**：给你一个整数数组 `prices`，其中 `prices[i]` 表示某支股票第 `i` 天的价格。在每一天，你可以决定是否购买和/或出售股票。你在任何时候**最多只能持有一股**股票，但可以在同一天先卖出再买入。返回你能获得的最大利润。`1 <= prices.length <= 3*10^4`。

**示例**：`输入: prices = [7,1,5,3,6,4]` → `输出: 7`（1 买 5 卖，3 买 6 卖）

**思路**：
- 状态定义：`hold` = 第 `i` 天结束时**持有**股票的最大收益；`cash` = 第 `i` 天结束时**不持有**的最大收益。用"结束时"定义状态，是为了让每天买卖动作有明确的先后顺序。
- 转移方程：
  - `hold = max(hold, cash - prices[i])`：要么继续持有，要么用之前的现金在今天买入（注意是 `cash` 而非 `-price`，因为可以反复交易）。
  - `cash = max(cash, hold + prices[i])`：要么继续空仓，要么把持有的股票今天卖掉。
- 初始化：`hold = -Infinity`（第 0 天前不可能持有），`cash = 0`。
- 遍历顺序：从左到右单遍，且更新 `cash` 时必须用**昨天**的 `hold`（先存 `prevHold`），否则会用到今天刚更新的值，等价于当天买入又卖出。
- 贪心等价：所有相邻上涨段 `prices[i] - prices[i-1] > 0` 累加，答案相同，因为无限次交易下每段上涨都能吃到。

**代码**：
```javascript
/**
 * 买卖股票的最佳时机 II：可无限次交易
 * @param {number[]} prices
 * @returns {number}
 */
function maxProfitII(prices) {
  let hold = -Infinity; // 持有股票的最大收益
  let cash = 0;         // 空仓时的最大收益
  for (const p of prices) {
    const prevHold = hold;              // 保存昨天持有状态
    hold = Math.max(hold, cash - p);    // 继续持有 或 今天买入
    cash = Math.max(cash, prevHold + p); // 继续空仓 或 今天卖出
  }
  return cash;
}

console.log(maxProfitII([7, 1, 5, 3, 6, 4])); // 7
console.log(maxProfitII([1, 2, 3, 4, 5]));    // 4
```

**复杂度**：时间 O(n) ／ 空间 O(1)。

**易错点**：
- `cash` 更新时用本轮已更新的 `hold`，等价于当天买当天卖，虽不致命但逻辑不严谨；应保存 `prevHold`。
- `hold` 初始化写成 0，导致第一天就能"免费持有"，收益虚高。
- 与 C-295 的唯一区别：买入项从 `-p` 变成 `cash - p`，别写混。
- 贪心写法漏掉"只累加正收益"，遇到下跌段仍加负值。

**变体与追问**：
- 只允许一次交易：见 C-295。
- 含冷冻期：见 C-297，卖出后一天不能买。
- 含手续费：`cash = max(cash, hold + p - fee)`，在卖出时扣手续费。
- 最多 k 次：见 C-298，需要二维状态。

### C-297 买卖股票的最佳时机含冷冻期 · 中等 · 字节/阿里

**题干**：给定一个整数数组 `prices`，其中 `prices[i]` 表示第 `i` 天的股票价格。设计算法计算出最大利润。在满足以下约束条件下，你可以尽可能地完成更多的交易：卖出股票后，你**无法在第二天买入股票**（即冷冻期为 1 天）。`1 <= prices.length <= 5000`。

**示例**：`输入: prices = [1,2,3,0,2]` → `输出: 3`（买 1 卖 3，冷冻一天，买 0 卖 2）

**思路**：
- 状态定义：冷冻期意味着"卖出"和"买入"之间必须隔一天，因此需要把"不持有"再细分为两个状态，共三个：
  - `hold`：今天结束时持有股票的最大收益；
  - `sold`：今天**刚卖出**（进入冷冻期）的最大收益；
  - `rest`：不持有且**不在冷冻期**（可随时买入）的最大收益。
- 转移方程：
  - `hold = max(hold, rest - prices[i])`——只能从 `rest` 买入，不能从 `sold` 买（冷冻期限制）。
  - `sold = hold(昨天) + prices[i]`——今天卖出，昨天必须持有。
  - `rest = max(rest, sold(昨天))`——冷冻期结束转为可买入状态。
- 初始化：`hold = -prices[0]`，`sold = 0`，`rest = 0`。
- 遍历顺序：从左到右；三个式子必须用**昨天的旧值**同步更新，故先缓存 `prevHold/prevSold/prevRest`。

**代码**：
```javascript
/**
 * 买卖股票含冷冻期：卖出后隔一天才能买
 * @param {number[]} prices
 * @returns {number}
 */
function maxProfitCool(prices) {
  const n = prices.length;
  if (n < 2) return 0;

  let hold = -prices[0]; // 持有
  let sold = 0;          // 今天刚卖出（冷冻中）
  let rest = 0;          // 空仓且可买

  for (let i = 1; i < n; i++) {
    const prevHold = hold, prevSold = sold, prevRest = rest;
    hold = Math.max(prevHold, prevRest - prices[i]); // 只能从 rest 买入
    sold = prevHold + prices[i];                     // 昨天持有，今天卖
    rest = Math.max(prevRest, prevSold);             // 冷冻结束
  }
  return Math.max(sold, rest); // 最后一天持有无意义
}

console.log(maxProfitCool([1, 2, 3, 0, 2])); // 3
console.log(maxProfitCool([1]));             // 0
```

**复杂度**：时间 O(n) ／ 空间 O(1)。

**易错点**：
- 只用一个 `cash` 状态，无法表达"冷冻期"，会退化成 C-296 的无限交易。
- `hold` 从 `sold` 买入，违反冷冻期约束；必须从 `rest` 买入。
- 三个状态更新时没有缓存旧值，导致同一天内状态互相污染。
- 返回值写成 `hold`，最后一天还持有股票不应计入收益。

**变体与追问**：
- 冷冻期为 k 天：需要队列保存最近 k 天的 `sold`，或用长度为 k 的滚动数组。
- 含手续费 + 冷冻期：在 `sold` 处再减 `fee`。
- 若允许卖空：增加 `short` 状态，注意与冷冻期的交互。

### C-298 买卖股票的最佳时机 IV · 困难 · 字节/腾讯

**题干**：给你一个整数数组 `prices` 和一个整数 `k`，其中 `prices[i]` 是某支股票第 `i` 天的价格。设计算法计算你所能获取的最大利润，你**最多**可以完成 `k` 笔交易（一次买入和一次卖出为一笔）。注意你不能同时参与多笔交易。`1 <= k <= 100`，`1 <= prices.length <= 1000`。

**示例**：`输入: k = 2, prices = [2,4,1]` → `输出: 2`（第 1 天买 2、第 2 天卖 4）

**思路**：
- 状态定义：`buy[j]` = 已完成 `j` 笔交易且**当前持有**股票的最大收益；`sell[j]` = 已完成 `j` 笔交易且**空仓**的最大收益。交易次数是必须显式建模的维度。
- 转移方程（对每天、每个 `j`）：
  - `buy[j] = max(buy[j], sell[j-1] - p)`——第 `j` 笔的买入，必须建立在完成 `j-1` 笔的基础上。
  - `sell[j] = max(sell[j], buy[j] + p)`——在第 `j` 笔买入后卖出。
- 初始化：`buy[*] = -Infinity`（不可能一上来就持有这么多笔的仓位），`sell[*] = 0`（0 笔交易收益为 0）。
- 遍历顺序：外层遍历每天，内层 `j` 从 1 到 `k` **正序**。因为 `buy[j]` 依赖 `sell[j-1]`，而 `sell[j-1]` 在本轮已更新表示"今天可以连着做第 j-1 笔再开第 j 笔"，同一天连续交易不亏，顺序正确。
- 剪枝：`k` 超过 `n/2` 时等价于无限次交易，可直接用 C-296，避免无效维度。

**代码**：
```javascript
/**
 * 买卖股票的最佳时机 IV：最多 k 笔交易
 * @param {number} k
 * @param {number[]} prices
 * @returns {number}
 */
function maxProfitIV(k, prices) {
  const n = prices.length;
  if (n === 0 || k === 0) return 0;
  k = Math.min(k, Math.floor(n / 2)); // 有效交易次数上限

  const buy = new Array(k + 1).fill(-Infinity); // 持有状态
  const sell = new Array(k + 1).fill(0);        // 空仓状态

  for (const p of prices) {
    for (let j = 1; j <= k; j++) {
      // 第 j 笔买入：承接第 j-1 笔的卖出收益
      buy[j] = Math.max(buy[j], sell[j - 1] - p);
      // 第 j 笔卖出：在持有基础上兑现
      sell[j] = Math.max(sell[j], buy[j] + p);
    }
  }
  return sell[k];
}

console.log(maxProfitIV(2, [2, 4, 1]));          // 2
console.log(maxProfitIV(2, [3, 2, 6, 5, 0, 3])); // 7
```

**复杂度**：时间 O(nk) ／ 空间 O(k)。

**易错点**：
- 不剪枝 `k`，当 `k` 很大且 `n` 很小时浪费；`k > n/2` 应退化为无限交易。
- `buy` 初始化成 0，导致第一天就"白得"持仓，收益虚高。必须是 `-Infinity`。
- 内层 `j` 逆序写，会让 `sell[j-1]` 用不到当天的更新，少算同日多笔的衔接（虽然同日多笔可合并，但逆序逻辑不自洽）。
- 把 `buy[j]` 的买入基准写成 `sell[j] - p`（同一笔里反复买），交易次数语义错乱。

**变体与追问**：
- `k = 1`：退化为 C-295；`k = ∞`：退化为 C-296。
- 含冷冻期且限 k 笔：在状态里再加"冷冻"维度，变成 3×k。
- 若允许同时持有多笔（不限制），问题变成"选 k 段最大子段和"，可用堆或 DP 求解。

### C-299 解码方法 · 中等 · 字节/美团

**题干**：一条包含字母 `A-Z` 的消息通过以下映射进行了编码：`'A' -> "1"`, `'B' -> "2"`, …, `'Z' -> "26"`。要解码已编码的消息，所有数字必须基于上述映射的方法反向映射回字母（可能有多种方法）。给你一个只含数字的非空字符串 `s`，请计算并返回**解码方法的总数**。`1 <= s.length <= 100`。

**示例**：`输入: s = "226"` → `输出: 3`（"BZ"、"VF"、"BBF"）

**思路**：
- 状态定义：`dp[i]` = 字符串前 `i` 个字符的解码方法数。按"最后一步取 1 位还是 2 位"划分，与爬楼梯同构。
- 转移方程：
  - 若 `s[i-1]` 单独可解码（`'1'~'9'`），`dp[i] += dp[i-1]`；
  - 若 `s[i-2..i-1]` 两位可解码（`10~26`），`dp[i] += dp[i-2]`。
- 初始化：`dp[0] = 1`（空串算 1 种，作为乘法基准），`dp[1] = s[0] === '0' ? 0 : 1`。
- 遍历顺序：`i` 从 2 递增，依赖前两项。若首位是 `'0'`，整串无法解码，直接返回 0。
- 关键：`'0'` 只能作为 `10` 或 `20` 的第二位出现，不能单独解码，这是本题最容易漏的分支。
- 解码与爬楼梯同构，区别在于每一步是否「合法」需要额外判断，非法转移直接不加即可，无需特判整串。

**代码**：
```javascript
/**
 * 解码方法：'A'-'Z' 映射到 "1"-"26"
 * @param {string} s
 * @returns {number}
 */
function numDecodings(s) {
  const n = s.length;
  if (n === 0 || s[0] === '0') return 0; // 首位 0 无法解码

  let prev2 = 1; // dp[0]：空串 1 种
  let prev1 = 1; // dp[1]：首字符非 0，1 种
  for (let i = 2; i <= n; i++) {
    let cur = 0;
    const one = Number(s[i - 1]);          // 取 1 位
    const two = Number(s.slice(i - 2, i)); // 取 2 位
    if (one >= 1 && one <= 9) cur += prev1;     // 单独解码
    if (two >= 10 && two <= 26) cur += prev2;   // 两位解码
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}

console.log(numDecodings("226"));  // 3
console.log(numDecodings("06"));   // 0
console.log(numDecodings("10"));   // 1
```

**复杂度**：时间 O(n) ／ 空间 O(1)。

**易错点**：
- 允许 `"0"` 单独解码，导致 `"06"`、`"100"` 之类错判。
- 两位判断用 `two <= 26` 却忘了 `two >= 10`，`"05"` 会被当成 5 解码。
- `dp[0]` 初始化成 0 而不是 1，导致首位两位组合 `"12"` 少算。
- `s.slice(i-2, i)` 在 `i=1` 时越界；循环从 2 开始即可避免。

**变体与追问**：
- 数字可映射到 `1-9` 单字符（无 10-26）：退化为"每步走 1 格"，答案恒为 1（只要无 0）。
- 要求输出所有解码结果：DFS + 回溯，注意处理 `0`。
- 若映射表可自定义（如 `1-99`）：转移扩展到取 1~2 位，判断区间相应变化。

### C-300 最长数对链 · 中等 · 腾讯/快手

**题干**：给你一个由 `n` 个数对组成的数组 `pairs`，其中 `pairs[i] = [left_i, right_i]`，且 `left_i < right_i`。如果满足 `b < c`，则数对 `(c, d)` 可以跟在 `(a, b)` 后面，形成数对链。请找出能形成数对链的**最长长度**。你不需要使用所有数对，可以按任意顺序选择。`1 <= pairs.length <= 1000`。

**示例**：`输入: pairs = [[1,2],[2,3],[3,4]]` → `输出: 2`（[1,2] → [3,4]）

**思路**：
- 这是"区间调度"的变体：要求前一个的右端点严格小于后一个的左端点。可用 DP，也可用贪心。
- 状态定义（DP 解法，与 LIS 同构）：先按左端点升序排序，令 `dp[i]` = 以第 `i` 个数对结尾的最长链长度。状态"以 i 结尾"是因为需要知道最后一个区间的右端点才能判断能否接续。
- 转移方程：`dp[i] = max(dp[j] + 1)`，其中 `j < i` 且 `pairs[j][1] < pairs[i][0]`。
- 初始化：`dp[i] = 1`（每个数对自身是一条长度 1 的链）。
- 遍历顺序：`i` 升序、`j` 从 0 到 `i-1`，保证只依赖已算好的前缀。
- 贪心解法：按**右端点升序**排序，顺序扫描，若当前左端点大于上一个选中的右端点就选它。这是区间调度的经典结论——右端点越小，留给后面的空间越大，因此贪心最优，O(n log n)。

**代码**：
```javascript
/**
 * 最长数对链：DP 解法（与 LIS 同构）
 * @param {number[][]} pairs
 * @returns {number}
 */
function findLongestChain(pairs) {
  // 按左端点升序，便于后续只往右接
  pairs.sort((a, b) => a[0] - b[0]);
  const n = pairs.length;
  const dp = new Array(n).fill(1); // 每个数对自身长度为 1

  for (let i = 0; i < n; i++) {
    for (let j = 0; j < i; j++) {
      // 严格 b < c 才能接在后面
      if (pairs[j][1] < pairs[i][0]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }
  return Math.max(...dp);
}

console.log(findLongestChain([[1, 2], [2, 3], [3, 4]])); // 2
console.log(findLongestChain([[1, 2], [7, 8], [4, 5]])); // 3
```

**复杂度**：DP 时间 O(n²)、空间 O(n)；贪心时间 O(n log n)、空间 O(1)。

**易错点**：
- 条件写成 `pairs[j][1] <= pairs[i][0]`，题目要求严格 `b < c`，等号会多接一段。
- 忘记按左端点排序，`j < i` 的顺序没有意义。
- 贪心解法按左端点排序（而非右端点），会得到错误答案。
- 返回 `dp[n-1]`，最长链未必以最后一个数对结尾，必须取 `max`。

**变体与追问**：
- 若允许 `b <= c`（闭区间相接）：条件改为 `<=`，且贪心排序的稳定性要注意。
- 加权版本（每个数对有权重，求最大权链）：DP + 二分查找右端点，O(n log n)。
- 无重叠区间（LC 435）：求"最少删除多少个区间使互不重叠"，答案 = `n - 最长链`。
