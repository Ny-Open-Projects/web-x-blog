# 14 排序与分治（C-261 ~ C-280）

> 排序模板是笔试的"地基题"，分治统计是区分度题：模板写不对直接挂，逆序对/翻转对不会写就拿不到大厂的中高难度分。**识别特征**：看到"逆序对 / 右侧比它小的个数 / 区间和落在某范围 / 数组小和"就要想到**在归并的合并阶段顺带计数**；看到"第 k 大 / 最大间距 / 按名次"就要想到**堆、桶、计数排序**绕开比较下界。

## 题型速查

| 子类型 | 核心手法 | 代表题 |

### C-261 排序数组（快排 / 归并 / 堆排 三解法）· 中等 · 字节/阿里/腾讯

**题干**：给定整数数组 `nums`，将该数组升序排列并返回。要求不使用 `Array.prototype.sort`，并分别用归并、快排、堆排实现，说清三者的稳定性与空间开销差异。

**示例**：`输入: nums = [5,2,3,1]` → `输出: [1,2,3,5]`；`nums = [5,1,1,2,0,0]` → `输出: [0,0,1,1,2,5]`

**思路**：
- 归并：把数组对半分，各自排好再合并。合并时 `L[i] <= R[j]` 取左边，这个 `<=` 决定了**稳定性**；代价是需要 O(n) 辅助空间。
- 快排：选基准分区后递归左右。基准必须**随机化**，否则对已排序数组每次只砍掉 1 个元素，退化成 O(n²)；分区后基准归位，所以空间只要递归栈 O(log n)。
- 堆排：先自底向上下沉建出大顶堆（从 `n/2-1` 开始，因为叶子天然是堆），再反复把堆顶换到末尾、缩小堆范围并下沉修复。建堆是 O(n) 而不是 O(n log n)，这是最常被追问的点。
- 三者时间都是 O(n log n)（快排指平均），差异在稳定性与空间：归并稳定但费空间，快排不稳定但原地，堆排不稳定且常数大但空间 O(1)。

**代码**：
```javascript
// ① 归并：稳定，最坏 O(n log n)
function mergeSort(a) {
  if (a.length < 2) return a;
  const m = a.length >> 1, L = mergeSort(a.slice(0, m)), R = mergeSort(a.slice(m)), out = [];
  let i = 0, j = 0;
  while (i < L.length && j < R.length) out.push(L[i] <= R[j] ? L[i++] : R[j++]); // <= 保证稳定
  return out.concat(L.slice(i), R.slice(j));
}
// ② 快排：随机基准，避免有序输入退化为 O(n²)
function quickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;
  const p = a[lo + ((Math.random() * (hi - lo + 1)) | 0)];
  let i = lo, j = hi;
  while (i <= j) {
    while (a[i] < p) i++;
    while (a[j] > p) j--;
    if (i <= j) { [a[i], a[j]] = [a[j], a[i]]; i++; j--; } // 交换后双指针各自内收
  }
  quickSort(a, lo, j); quickSort(a, i, hi);
  return a;
}
// ③ 堆排：大顶堆，原地 O(1) 额外空间
function heapSort(a) {
  const down = (i, n) => {
    while (2 * i + 1 < n) {
      let c = 2 * i + 1;
      if (c + 1 < n && a[c + 1] > a[c]) c++; // 选较大的孩子
      if (a[i] >= a[c]) break;
      [a[i], a[c]] = [a[c], a[i]]; i = c;
    }
  };
  for (let i = (a.length >> 1) - 1; i >= 0; i--) down(i, a.length); // 建堆 O(n)
  for (let i = a.length - 1; i > 0; i--) { [a[0], a[i]] = [a[i], a[0]]; down(0, i); } // 弹出堆顶
  return a;
}
const t = [5, 2, 3, 1];
console.log(mergeSort([...t]).join(), quickSort([...t]).join(), heapSort([...t]).join()); // 1,2,3,5 三次
```

**复杂度**：归并 O(n log n)/O(n)；快排 平均 O(n log n)、最坏 O(n²)/O(log n)；堆排 O(n log n)/O(1)

**易错点**：
- 快排分区里 `if (i <= j)` 写成 `if (i < j)`，`i == j` 时两指针不动，死循环；
- 快排递归写成 `quickSort(a, lo, i)`：正确边界是左段到 `j`、右段从 `i` 开始，因为 `i > j` 才退出；
- 堆排建堆从 `n-1` 开始：叶子不需要下沉，浪费一半时间，应从 `n/2-1` 开始；
- 归并的 `<=` 写成 `<`：相等元素来自右段时先被取走，稳定性被破坏。

**变体与追问**：
- 要求稳定 + O(1) 空间：理论上比较排序做不到（需 O(n) 额外空间或 O(n log²n) 的原地归并），要能说出这个结论；
- 链表排序：归并是唯一自然的选择（快排也可，堆排难以随机访问）；
- 数据近乎有序：插入排序 O(n) 最快，工业库常用"归并 + 小区间插入排序"的混合策略（见 C-263）。

### C-262 数组中的逆序对 · 困难 · 字节/腾讯/美团

**题干**：在数组中的两个数字，如果前面一个数字大于后面的数字，则这两个数字组成一个逆序对。给定数组 `nums`，返回逆序对的总数。结果可能很大，用 JS number（安全整数范围内）返回即可。

**示例**：`输入: nums = [7,5,6,4]` → `输出: 5`（逆序对为 (7,5)(7,6)(7,4)(5,4)(6,4)）

**思路**：
- 暴力：双重循环 O(n²)，`n = 1e5` 时必超时。
- 分治：把数组分成左右两半，逆序对 = 左半内部 + 右半内部 + **跨左右**。前两项递归，第三项在归并的"合并"阶段顺带统计。
- 为什么合并时能 O(1) 算出跨区间对数？因为此时左右两半都已各自有序。当 `nums[i] <= nums[j]` 时取左段元素，它比右段已取走的元素都大，却比 `nums[j..hi]` 都小或等——反之，当取右段元素 `nums[j]` 时，左段剩下的 `mid - i + 1` 个元素**全部大于** `nums[j]`，一次性贡献这么多逆序对。
- 用 `<=` 取左段可以保证计数不重不漏：相等时不构成逆序对（题目要求严格大于），所以相等应取左边。

**代码**：
```javascript
function reversePairs(nums) {
  let cnt = 0;
  const tmp = new Array(nums.length);
  const merge = (lo, hi) => {
    if (lo >= hi) return;
    const mid = (lo + hi) >> 1;
    merge(lo, mid); merge(mid + 1, hi);
    let i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
      if (nums[i] <= nums[j]) {
        tmp[k++] = nums[i++];        // 相等取左边，不构成逆序对
      } else {
        tmp[k++] = nums[j++];
        cnt += mid - i + 1;          // 左段剩余元素都比 nums[j] 大
      }
    }
    while (i <= mid) tmp[k++] = nums[i++];
    while (j <= hi) tmp[k++] = nums[j++];
    for (let p = lo; p <= hi; p++) nums[p] = tmp[p]; // 回写，供上层使用
  };
  merge(0, nums.length - 1);
  return cnt;
}

console.log(reversePairs([7, 5, 6, 4])); // 5
console.log(reversePairs([1, 2, 3, 4])); // 0
console.log(reversePairs([4, 3, 2, 1])); // 6
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)

**易错点**：
- `cnt += mid - i + 1` 写成 `j - mid`，统计的是右段已取出的个数，方向反了；
- 忘记把 `tmp` 回写 `nums`：本层统计正确，但上层 `nums` 不是有序的，跨层统计全错；
- 相等时取右段（用 `<` 而非 `<=`），会把相等元素算成逆序对，答案偏大；
- `cnt` 放到函数外层做全局变量，多次调用要重置——写成闭包内变量更安全。

**变体与追问**：
- 换成"计算右侧小于当前元素的个数"：需要返回每个位置的答案，合并时要靠**下标数组**追踪（见 C-266）；
- 换成"翻转对（`nums[i] > 2*nums[j]`）"：合并时不能用同一套比较，需先单独用双指针统计再合并（见 C-267）；
- 若要求 O(n log n) 但数据规模 1e6：递归层数深，注意 JS 栈深度，可改迭代式自底向上归并。

### C-263 归并排序模板 · 中等 · 字节/腾讯

**题干**：请手写一份可直接用于笔试的归并排序模板，要求：对 `[lo, hi]` 闭区间原地排序、复用同一块辅助数组、对小区间切换插入排序以降低递归常数，并说明为什么这样做不影响复杂度。

**示例**：`输入: [38,27,43,3,9,82,10]` → `输出: [3,9,10,27,38,43,82]`

**思路**：
- 标准归并是"分到单个元素再合并"，递归到长度 1 时函数调用与数组拷贝的开销占比很高。工业实现（Java `Arrays.sort`、V8 的 TimSort）都会在长度小于阈值（常用 16/32）时改用插入排序——插入排序常数小，且对近乎有序的小段近乎线性。
- 阈值不影响渐进复杂度：只剩 O(log(n/16)) 层归并，每层 O(n)，仍是 O(n log n)。
- 辅助数组 `tmp` 通过参数传入而不是每层 `new Array`，避免 O(n log n) 次分配；合并完必须回写原数组，否则上层拿到的是未排序数据。
- 合并时用 `a[i] <= a[j]` 取左侧，保持稳定；这是归并相对快排的核心优势。

**代码**：
```javascript
function mergeSort(a, lo = 0, hi = a.length - 1, tmp = new Array(a.length)) {
  if (hi - lo + 1 <= 16) { // 小区间插入排序，降低递归常数
    for (let i = lo + 1; i <= hi; i++) {
      const v = a[i];
      let j = i - 1;
      while (j >= lo && a[j] > v) { a[j + 1] = a[j]; j--; }
      a[j + 1] = v;
    }
    return a;
  }
  const mid = (lo + hi) >> 1;
  mergeSort(a, lo, mid, tmp);
  mergeSort(a, mid + 1, hi, tmp);
  let i = lo, j = mid + 1, k = lo;
  while (i <= mid && j <= hi) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++]; // <= 保证稳定
  while (i <= mid) tmp[k++] = a[i++];
  while (j <= hi) tmp[k++] = a[j++];
  for (let p = lo; p <= hi; p++) a[p] = tmp[p]; // 回写，否则上层数据未排序
  return a;
}

console.log(mergeSort([38, 27, 43, 3, 9, 82, 10])); // [3,9,10,27,38,43,82]
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)（辅助数组）+ O(log n)（递归栈）

**易错点**：
- 插入排序的 `while (j >= lo ...)` 边界写成 `j > 0`，会越过本段左界去改写别的段；
- 合并后不回写，只在最外层返回 `tmp`，导致递归中间层的 `a` 始终无序；
- `tmp` 每层新建 `new Array`，空间变 O(n log n)（虽然会被 GC 回收，但分配压力大）；
- 递归终止条件写 `lo > hi`，长度 1 的段还会继续分，`mid` 计算后无限递归。

**变体与追问**：
- 自底向上归并（迭代版）：`for (size = 1; size < n; size *= 2)`，无递归栈，适合超深数组；
- 原地归并：用"旋转"或"块交换"，时间退化到 O(n log²n)，面试只需说清 trade-off；
- 外部排序：数据大于内存时，先分块排序写磁盘再 k 路归并，这是 MapReduce 的雏形。

### C-264 快速排序模板 · 中等 · 字节/阿里

**题干**：请手写一份快速排序模板，要求：能正确处理**大量重复元素**（例如全数组相同）、使用随机基准避免有序输入退化，并说明三路划分相比两路划分的优势。

**示例**：`输入: [3,1,4,1,5,9,2,6,5,3,5]` → `输出: [1,1,2,3,3,4,5,5,5,6,9]`

**思路**：
- 两路划分在"全相同元素"时会退化：每次只能把基准放到中间，其余元素全落到一侧，递归深度 O(n)，时间 O(n²)。
- 三路划分（荷兰国旗问题）把区间分成 `< pivot`、`== pivot`、`> pivot` 三段，相等的元素一次性归位、不参与后续递归。这对重复率高的数据（如按状态码排序的日志）效果显著。
- 三个指针的语义：`[lo, lt)` 是小于区、`[lt, i)` 是等于区、`(gt, hi]` 是大于区、`[i, gt]` 是待处理区。遇到小于就交换到小于区尾部，遇到大于就交换到大于区头部（此时 `i` **不前进**，因为换过来的是未检查元素）。
- 基准随机化是为了让"划分不平衡"的概率极低，把期望时间锁死在 O(n log n)；即便三路划分，有序输入仍需随机化才能避免"每次只切掉 1 个"。

**代码**：
```javascript
function quickSort(a, lo = 0, hi = a.length - 1) {
  if (lo >= hi) return a;
  const p = a[lo + ((Math.random() * (hi - lo + 1)) | 0)]; // 随机基准
  let lt = lo, i = lo, gt = hi;
  // [lo,lt) < p；[lt,i) == p；(gt,hi] > p；[i,gt] 待处理
  while (i <= gt) {
    if (a[i] < p) {
      [a[lt], a[i]] = [a[i], a[lt]]; lt++; i++;
    } else if (a[i] > p) {
      [a[i], a[gt]] = [a[gt], a[i]]; gt--; // 换过来的元素未检查，i 不动
    } else {
      i++; // 等于基准，留在中间区
    }
  }
  quickSort(a, lo, lt - 1); // 只递归严格小于/大于两段
  quickSort(a, gt + 1, hi);
  return a;
}

console.log(quickSort([3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5])); // [1,1,2,3,3,4,5,5,5,6,9]
console.log(quickSort(new Array(5).fill(7)));             // [7,7,7,7,7]
```

**复杂度**：平均 O(n log n)，最坏 O(n²) ／ 空间 O(log n)（递归栈）

**易错点**：
- `a[i] > p` 分支里也 `i++`，跳过了刚从 `gt` 换过来的未检查元素，结果错乱；
- 递归区间写成 `quickSort(a, lo, lt)` / `quickSort(a, gt, hi)`，把等于区又递归进去，全相同元素时死循环；
- 基准取 `a[lo]` 而不随机：已排序输入每次只切掉一个，`n = 1e5` 直接栈溢出；
- 认为三路划分让最坏复杂度变成 O(n log n)——最坏仍是 O(n²)，只是重复元素场景不再触发。

**变体与追问**：
- 求数组第 k 大的元素（快速选择）：三路划分后只看目标落在哪一段，平均 O(n)，最坏 O(n²)；
- 快排 vs 归并的选择：内存敏感选快排，要求稳定选归并，工业界常用"内省排序"（快排 + 深度超限转堆排）；
- 基准选"三数取中"：比随机更工程化，避免 `Math.random` 的开销。

### C-265 堆排序模板 · 中等 · 阿里/快手

**题干**：请手写一份堆排序模板，要求：说明"建堆为什么是 O(n) 而不是 O(n log n)"，并给出用最小堆求数组中第 k 大元素的复用方式。

**示例**：`输入: [4,10,3,5,1]` → `输出: [1,3,4,5,10]`

**思路**：
- 堆本质是完全二叉树，用数组存储时下标 `i` 的孩子是 `2i+1`、`2i+2`，父节点是 `(i-1)/2`，不需要指针。
- 建堆要从最后一个非叶节点 `n/2-1` 开始**自底向上下沉**。为什么不从 0 开始上浮？因为自底向上时每层的下沉深度是"到叶子的距离"，总代价 `Σ (n/2^k)·k = O(n)`（等比级数收敛）；而逐个插入式上浮是 `Σ log k = O(n log n)`。
- 排序阶段每次把堆顶（当前最大值）与末尾交换，堆范围减 1，再对新堆顶下沉修复。共 n-1 次，每次 O(log n)，所以排序部分才是 O(n log n)。
- 复用：把 `down` 的比较方向反过来就是最小堆；维护大小为 k 的最小堆，堆顶即第 k 大元素，时间 O(n log k)。

**代码**：
```javascript
function heapSort(a) {
  const down = (i, n) => {          // 下沉：维护 [0, n) 范围内的大顶堆
    while (2 * i + 1 < n) {
      let c = 2 * i + 1;
      if (c + 1 < n && a[c + 1] > a[c]) c++; // 取较大的孩子
      if (a[i] >= a[c]) break;               // 已满足堆性质
      [a[i], a[c]] = [a[c], a[i]];
      i = c;
    }
  };
  for (let i = (a.length >> 1) - 1; i >= 0; i--) down(i, a.length); // 建堆 O(n)
  for (let i = a.length - 1; i > 0; i--) { // 堆顶（最大）换到已排序区前端
    [a[0], a[i]] = [a[i], a[0]]; down(0, i); // 堆范围缩小到 [0, i)
  }
  return a;
}

// 复用：小顶堆求第 k 大
function kthLargest(a, k) {
  const heap = a.slice(0, k);
  const down = (i) => {
    while (2 * i + 1 < heap.length) {
      let c = 2 * i + 1;
      if (c + 1 < heap.length && heap[c + 1] < heap[c]) c++;
      if (heap[i] <= heap[c]) break;
      [heap[i], heap[c]] = [heap[c], heap[i]]; i = c;
    }
  };
  for (let i = (k >> 1) - 1; i >= 0; i--) down(i);
  for (let i = k; i < a.length; i++) {
    if (a[i] > heap[0]) { heap[0] = a[i]; down(0); } // 只保留最大的 k 个
  }
  return heap[0];
}

console.log(heapSort([4, 10, 3, 5, 1])); // [1,3,4,5,10]
console.log(kthLargest([3, 2, 1, 5, 6, 4], 2)); // 5
```

**复杂度**：时间 O(n log n)（建堆 O(n) + 排序 O(n log n)） ／ 空间 O(1)

**易错点**：
- 建堆起始下标写成 `n-1`：叶子下沉是空操作，浪费一半时间（复杂度仍对，但被问"为什么从 n/2-1 开始"要答得出）；
- 下沉循环条件写成 `2*i < n`：`2i+1` 已是左孩子，`2i < n` 会漏掉最后一个孩子；
- 排序阶段 `down(0, i)` 里传 `n` 而不是 `i`，刚换到末尾的最大值被重新卷进堆，结果错乱；
- 认为"堆排稳定"：交换会跨越大量元素，堆排不稳定。

**变体与追问**：
- TopK 问题：求最大 k 个用**小顶堆**（堆顶是这 k 个里最小的，新元素更大才替换），求最小 k 个用大顶堆，方向别反；
- 数据流中位数：一个大顶堆 + 一个小顶堆，保持两堆大小差不超过 1；
- 建堆的 O(n) 证明要能写出 `Σ_{h=0}^{log n} (n/2^{h+1})·h = O(n)`。

### C-266 计算右侧小于当前元素的个数 · 困难 · 字节/美团

**题干**：给定整数数组 `nums`，返回数组 `counts`，其中 `counts[i]` 是 `nums[i]` 右侧小于 `nums[i]` 的元素个数。

**示例**：`输入: nums = [5,2,6,1]` → `输出: [2,1,1,0]`（5 右侧有 2、1；2 右侧有 1；6 右侧有 1；1 右侧没有）

**思路**：
- 暴力：对每个 `i` 向右扫，O(n²)。
- 与 C-262 的差别：那题只求总数，这题要求**每个位置各自的答案**，所以合并时元素的位置不能被"打乱丢失"。解决办法是对**下标数组**做归并排序（比较时看 `nums[idx[i]]`），这样每个下标始终知道自己对应哪个原值。
- 计数时机：合并两段有序区间时，若从右段取 `idx[j]`，说明它比左段剩下的元素都小——但我们要统计的是"每个元素右侧比它小的个数"，方向正好相反。所以应该在**从左段取元素**时结算：此时右段已被取走 `j - (mid+1)` 个，它们全部小于（或等于）当前左段元素，正好是 `counts[idx[i]]` 的增量。
- 左段剩余元素同理：循环结束后未取完的左段元素，其右侧小于它的个数就是右段全部长度。

**代码**：
```javascript
function countSmaller(nums) {
  const n = nums.length;
  const idx = [...Array(n).keys()];       // 只对下标排序，保住原位置
  const res = new Array(n).fill(0);
  const tmp = new Array(n);
  const merge = (lo, hi) => {
    if (lo >= hi) return;
    const mid = (lo + hi) >> 1;
    merge(lo, mid); merge(mid + 1, hi);
    let i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
      if (nums[idx[i]] <= nums[idx[j]]) {
        res[idx[i]] += j - (mid + 1);     // 右段已并入的都更小
        tmp[k++] = idx[i++];
      } else {
        tmp[k++] = idx[j++];
      }
    }
    while (i <= mid) { res[idx[i]] += j - (mid + 1); tmp[k++] = idx[i++]; }
    while (j <= hi) tmp[k++] = idx[j++];
    for (let p = lo; p <= hi; p++) idx[p] = tmp[p]; // 回写下标顺序
  };
  merge(0, n - 1);
  return res;
}

console.log(countSmaller([5, 2, 6, 1])); // [2,1,1,0]
console.log(countSmaller([-1, -1]));     // [0,0]
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)

**易错点**：
- 直接对 `nums` 归并，值被换了位置，`res` 下标对不上原数组；
- 在"取右段"时累加，得到的是"左侧比自己大的个数"，方向反了；
- `res[idx[i]] += j - (mid + 1)` 里的 `mid + 1` 写成 `mid`，多算一个；
- 忘记处理循环结束后左段剩余元素，尾部会漏统计。

**变体与追问**：
- 若改为"右侧大于等于"：把 `<=` 改成 `<`，并把 `j - (mid+1)` 换成统计"右侧未取走的个数"；
- 也可用树状数组（离散化后从右往左更新），时间 O(n log n) 常数更小，面试可作第二种解法加分；
- 与 C-262 的关系：C-262 是本题所有 `res` 求和，可用来交叉验证。

### C-267 翻转对 · 困难 · 字节/腾讯

**题干**：给定数组 `nums`，若 `i < j` 且 `nums[i] > 2 * nums[j]`，则称 `(i, j)` 是一个重要翻转对。返回重要翻转对的数量。

**示例**：`输入: nums = [1,3,2,3,1]` → `输出: 2`；`nums = [2,4,3,5,1]` → `输出: 3`

**思路**：
- 与逆序对同属"归并统计"，但判定条件变成 `nums[i] > 2 * nums[j]`，这个 2 倍关系破坏了"合并时顺带计数"的直接性：合并的比较是 `nums[i] <= nums[j]`，与 `> 2*nums[j]` 不是同一个关系，不能用一个分支同时完成"排序"和"计数"。
- 正确做法是**先统计、后合并**：在左右两段已经各自有序（递归返回后）但尚未合并时，用一个不回退的指针 `j` 划出"满足 `nums[i] > 2*nums[j]` 的右段前缀"，`j - (mid+1)` 就是该 `i` 的贡献。因为左段递增，`nums[i]` 变大时 `j` 只会右移，总移动 O(n)，本层统计 O(n)。
- 统计完再做标准的归并合并。这个"两遍扫描"结构是本题与 C-262 最大的区别，也是面试区分点：能不能意识到"比较关系不同，必须拆成两步"。

**代码**：
```javascript
function reversePairs(nums) {
  let cnt = 0;
  const tmp = new Array(nums.length);
  const merge = (lo, hi) => {
    if (lo >= hi) return;
    const mid = (lo + hi) >> 1;
    merge(lo, mid); merge(mid + 1, hi);
    // 第一步：两段各自有序，用不回退的指针统计 nums[i] > 2 * nums[j]
    let j = mid + 1;
    for (let i = lo; i <= mid; i++) {
      while (j <= hi && nums[i] > 2 * nums[j]) j++; // 右段越大越容易满足
      cnt += j - (mid + 1); // 右段前 j-(mid+1) 个都满足严格大于
    }
    // 第二步：标准归并，与计数完全解耦
    let i = lo, k = lo; j = mid + 1;
    while (i <= mid && j <= hi) tmp[k++] = nums[i] <= nums[j] ? nums[i++] : nums[j++];
    while (i <= mid) tmp[k++] = nums[i++];
    while (j <= hi) tmp[k++] = nums[j++];
    for (let p = lo; p <= hi; p++) nums[p] = tmp[p];
  };
  merge(0, nums.length - 1);
  return cnt;
}

console.log(reversePairs([1, 3, 2, 3, 1])); // 2
console.log(reversePairs([2, 4, 3, 5, 1])); // 3
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)

**易错点**：
- 把统计塞进合并的 `if/else` 里，因为两个比较关系不一致，结果会随机错；
- 比较写成 `nums[i] >= 2 * nums[j]`，把等号算进去，答案偏大（本题要求严格大于）；
- 指针 `j` 在 `for` 循环里重置为 `mid + 1`：左段递增，重置会让复杂度退化为 O(n²)；
- 用 `nums[l] * 2` 时数据接近 2^31，JS 安全但强类型语言会溢出，面试提一句"用除法或 long"。

**变体与追问**：
- 若条件是 `nums[i] > nums[j] + k`：同样是"先统计后合并"，只需换掉指针推进条件；
- 若要求返回具体下标对：需要像 C-266 那样维护下标数组；
- 与逆序对的关系：把 2 倍去掉，本题退化成 C-262，但"先统计后合并"的写法仍然正确（只是多一遍扫描）。

### C-268 最大子数组和（分治解法）· 中等 · 字节/阿里/腾讯

**题干**：给定整数数组 `nums`，找到一个具有最大和的**连续子数组**（至少含一个元素），返回其最大和。要求用**分治**实现（不能用 Kadane 的一维 DP）。

**示例**：`输入: nums = [-2,1,-3,4,-1,2,1,-5,4]` → `输出: 6`（子数组 `[4,-1,2,1]`）

**思路**：
- 分治的核心是"跨中点的子数组怎么合并"。把区间 `[lo, hi]` 从中点切开，最大子数组只有三种可能：完全在左半、完全在右半、**跨过中点**。前两种递归，第三种必须能 O(len) 算出来。
- 跨中点时，子数组 = 以 `mid` 结尾向左延伸的一段 + 以 `mid+1` 开头向右延伸的一段。向左的最大和只依赖"从 `mid` 往左累加"，向右同理。因此每层只需返回 4 个信息：以左端开头的最大和、以右端结尾的最大和、区间内最大和、区间总和。
- 合并公式：`跨中点 = 左段的"右端结尾最大和" + 右段的"左端开头最大和"`。四个值互相依赖，这也是分治的"信息合并"范式，和线段树维护区间信息是同一个思路。
- 为什么不能只返回"区间最大和"？因为上层的跨中点计算需要子区间的"边界前缀/后缀和"，信息不够就无法合并。

**代码**：
```javascript
function maxSubArray(nums) {
  // 返回 [左端起最大和, 右端止最大和, 区间最大子段和, 区间总和]
  const solve = (lo, hi) => {
    if (lo === hi) return [nums[lo], nums[lo], nums[lo], nums[lo]];
    const mid = (lo + hi) >> 1;
    const [lL, lR, lM, lS] = solve(lo, mid);
    const [rL, rR, rM, rS] = solve(mid + 1, hi);
    return [
      Math.max(lL, lS + rL),     // 左端起：不跨界，或整段左 + 右段的左端起
      Math.max(rR, rS + lR),     // 右端止：对称
      Math.max(lM, rM, lR + rL), // 最大子段：左 / 右 / 跨中点
      lS + rS,                   // 总和
    ];
  };
  return solve(0, nums.length - 1)[2];
}

console.log(maxSubArray([-2, 1, -3, 4, -1, 2, 1, -5, 4])); // 6
console.log(maxSubArray([-1]));                            // -1
console.log(maxSubArray([5, -10, 3]));                     // 5
```

**复杂度**：时间 O(n log n) ／ 空间 O(log n)（递归栈）

**易错点**：
- 只返回区间最大和，合并时无法算跨中点，只能退化成 O(n log n) 内再 O(n) 暴力（变成 O(n² log n)）；
- `lS + rL` 写成 `lL + rL`：左端起必须包含整个左段才能跨到右段；
- 全负数数组时把初值设成 0，答案错成 0（子数组至少含一个元素）；
- 认为分治是本题最优：Kadane 是 O(n)/O(1)，分治的意义在于"可回答任意区间的最大子段和"（线段树/ST 表），要能说出这个动机。

**变体与追问**：
- 允许子数组为空（和至少为 0）：把 `Math.max(..., 0)` 加进三个结果里；
- 带长度限制（长度不超过 k）：分治不再是首选，改用单调队列 + 前缀和；
- 区间查询任意 `[l, r]` 的最大子段和：把这四个信息放进线段树，合并函数与本题完全一致。

### C-269 区间和的个数 · 困难 · 字节/美团

**题干**：给定整数数组 `nums` 和两个整数 `lower`、`upper`，返回满足 `lower <= sum(i..j) <= upper` 的下标对 `(i, j)`（`i <= j`）的个数。

**示例**：`输入: nums = [-2,5,-1], lower = -2, upper = 2` → `输出: 3`（区间 `[0,0]`、`[2,2]`、`[0,2]`）

**思路**：
- 区间和立刻转**前缀和**：`sum(i..j) = pre[j+1] - pre[i]`，问题变成"数有多少对 `i < j` 满足 `lower <= pre[j] - pre[i] <= upper`"，这就是前缀和数组上的"逆序对加强版"。
- 用归并在**有序的两段**上统计：左段下标都小于右段（因为归并排序保序地合并下标区间），对每个左段元素 `pre[i]`，右段需要满足 `pre[i] + lower <= pre[j] <= pre[i] + upper`。由于右段有序，用两个不回退的指针 `l`、`r` 分别找下界与上界，`r - l` 即该 `i` 的贡献。
- 为什么指针不回退？左段递增，`pre[i]` 单调增，所以 `pre[i] + lower` 与 `pre[i] + upper` 也单调增，右段的边界只会右移，总移动 O(len)，本层 O(n)。
- 统计完再合并，与 C-267 结构相同；但这里区间是双边界（`lower` 和 `upper` 两个 `while`），比翻转对更典型。

**代码**：
```javascript
function countRangeSum(nums, lower, upper) {
  const n = nums.length;
  const pre = new Array(n + 1).fill(0);
  for (let i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i]; // 前缀和
  let cnt = 0;
  const tmp = new Array(n + 1);
  const merge = (lo, hi) => {
    if (lo >= hi) return;
    const mid = (lo + hi) >> 1;
    merge(lo, mid); merge(mid + 1, hi);
    // 在 pre[lo..mid] 与 pre[mid+1..hi] 这两段有序数组上双指针统计
    let l = mid + 1, r = mid + 1;
    for (let i = lo; i <= mid; i++) {
      while (l <= hi && pre[l] - pre[i] < lower) l++;   // 下界
      while (r <= hi && pre[r] - pre[i] <= upper) r++;  // 上界
      cnt += r - l;
    }
    let i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) tmp[k++] = pre[i] <= pre[j] ? pre[i++] : pre[j++];
    while (i <= mid) tmp[k++] = pre[i++];
    while (j <= hi) tmp[k++] = pre[j++];
    for (let p = lo; p <= hi; p++) pre[p] = tmp[p];
  };
  merge(0, n);
  return cnt;
}

console.log(countRangeSum([-2, 5, -1], -2, 2)); // 3
console.log(countRangeSum([0], 0, 0));          // 1
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)

**易错点**：
- 前缀和长度写成 `n`，`i == j` 的单元素区间需要 `pre[j+1]`，少一位会漏掉所有 `j = n-1` 的区间；
- `l`、`r` 的初始值写成 `lo`，跨段统计与左段自身混淆，必须从 `mid + 1` 开始；
- 边界条件写成 `pre[l] - pre[i] <= lower`，`lower` 侧也要严格取 `<` 才能"停在第一个满足的位置"；
- 每轮重置 `l`、`r`，复杂度退化成 O(n²)，`n = 1e5` 超时。

**变体与追问**：
- 用树状数组替代归并：离散化前缀和后从右往左查询区间计数，O(n log n) 常数更小；
- 要求返回具体区间而不只是个数：归并过程中记录 `(i, j)`，输出规模可能 O(n²)，需注意空间；
- 与 C-267 对比：翻转对是单边界（`nums[i] > 2*nums[j]`），本题是双边界，但双指针框架完全一致。

### C-270 最大间距 · 困难 · 字节/腾讯

**题干**：给定无序数组 `nums`，返回数组在排序之后，相邻元素之间的最大差值。若数组元素少于 2 个，返回 0。要求**线性时间**与线性空间。

**示例**：`输入: nums = [3,6,9,1]` → `输出: 3`（排序后 `[1,3,6,9]`，最大差 `9-6=3`）；`nums = [10]` → `输出: 0`

**思路**：
- 直接排序是 O(n log n)，题目要求线性时间，暗示**不能做比较排序**，要用"桶 + 鸽巢原理"。
- 关键洞察：`n` 个数放在值域 `[min, max]` 上，若分成 `n-1` 个等宽的桶，由鸽巢原理，**至少有一个桶是空的**；而最大间距一定出现在"某个非空桶的 max"与"下一个非空桶的 min"之间，绝不会在同一桶内部（桶内最大跨度 < 桶宽 <= 全局最大间距）。
- 因此只需记录每个桶的 `min/max`，然后扫一遍桶，用"当前桶 min - 上一个非空桶 max"更新答案。空桶直接跳过。
- 桶宽取 `ceil((max - min) / (n - 1))`，保证最极端情况（min 和 max）不会挤在同一个桶里导致找不到间距。

**代码**：
```javascript
function maximumGap(nums) {
  const n = nums.length;
  if (n < 2) return 0;
  const min = Math.min(...nums), max = Math.max(...nums);
  if (min === max) return 0; // 全部相同，间距为 0
  const size = Math.ceil((max - min) / (n - 1)); // 桶宽
  const bMin = new Array(n).fill(Infinity);
  const bMax = new Array(n).fill(-Infinity);
  for (const v of nums) {
    const id = Math.floor((v - min) / size); // 落在哪个桶
    bMin[id] = Math.min(bMin[id], v);
    bMax[id] = Math.max(bMax[id], v);
  }
  let ans = 0, prev = min; // prev 是上一个非空桶的最大值
  for (let i = 0; i < n; i++) {
    if (bMin[i] === Infinity) continue;      // 空桶跳过
    ans = Math.max(ans, bMin[i] - prev);     // 跨桶间距
    prev = bMax[i];
  }
  return ans;
}

console.log(maximumGap([3, 6, 9, 1])); // 3
console.log(maximumGap([10]));         // 0
console.log(maximumGap([1, 10000000])); // 9999999
```

**复杂度**：时间 O(n) ／ 空间 O(n)

**易错点**：
- 桶内也参与比较：桶内元素差必然小于桶宽，不可能超过跨桶间距，多算只会让答案偏小的概率变化（实际是浪费时间），理解不清就会被追问倒；
- `size` 用 `Math.floor`，`(max-min)/(n-1)` 不是整数时桶数不够，min 与 max 挤进同一个桶，答案错成桶内差；
- 空桶没跳过，`bMin` 的 `Infinity` 参与减法得到 `-Infinity`，`Math.max` 后答案不变但 `prev` 被污染成 `-Infinity`；
- `n = 2` 时 `n-1 = 1`，`size = max-min`，两个元素分别在桶 0、桶 1，正确；但若先做 `min === max` 判断就无此分支。

**变体与追问**：
- 基数排序后扫一遍：同样 O(n)（按 32 位分两轮，每轮 8 位），更容易写但有常数开销；
- 若要求 O(1) 空间：桶排序做不到，只能上基数排序（原地版）或承认无法线性；
- 与"最大间距变体：允许重复元素"的区别：重复时 `min === max` 需返回 0，否则会除以 0 得到 `NaN`。

### C-271 数组的相对排序 · 简单 · 字节/腾讯

**题干**：给定两个数组 `arr1` 和 `arr2`，`arr2` 中各元素互不相同且都出现在 `arr1` 中。对 `arr1` 排序，使 `arr1` 中元素的相对顺序与 `arr2` 一致；未在 `arr2` 中出现的元素按**升序**放在末尾。

**示例**：`输入: arr1 = [2,3,1,3,2,4,6,7,9,2,19], arr2 = [2,1,4,3,9,6]` → `输出: [2,2,2,1,4,3,3,9,6,7,19]`

**思路**：
- 直观做法是给每个值定一个"排序权重"：在 `arr2` 中出现的位置作为第一关键字，没出现的按值本身排在后面，然后调 `sort`。这样是 O(n log n)，但比较器里要反复查表，代码也不够直白。
- 更贴合题意的做法是**计数排序**：元素值域有界（`0 <= arr1[i] <= 1000`），开一个计数数组，先扫 `arr1` 统计频次；再按 `arr2` 的顺序把对应值按频次吐出来（这正好满足"相对顺序一致"）；最后从 0 到最大值扫一遍，把剩余值按升序补齐。
- 计数排序不受 O(n log n) 下界约束，因为它没有做元素间比较，而是用值作为下标直接定位，时间 O(n + m + V)，`V` 是值域大小。
- 这也是"值域小就用桶/计数"这一判断的典型场景，与 C-270 的桶排序、C-272 的排序索引是同一族思想。

**代码**：
```javascript
function relativeSortArray(arr1, arr2) {
  const max = Math.max(...arr1);
  const cnt = new Array(max + 1).fill(0);
  for (const v of arr1) cnt[v]++;   // 值域有界，用计数代替比较
  const res = [];
  for (const v of arr2) {           // 第一优先级：arr2 中的相对顺序
    while (cnt[v] > 0) { res.push(v); cnt[v]--; }
  }
  for (let v = 0; v <= max; v++) {  // 第二优先级：未出现的按值升序
    while (cnt[v] > 0) { res.push(v); cnt[v]--; }
  }
  return res;
}

console.log(relativeSortArray(
  [2, 3, 1, 3, 2, 4, 6, 7, 9, 2, 19],
  [2, 1, 4, 3, 9, 6]
)); // [2,2,2,1,4,3,3,9,6,7,19]
```

**复杂度**：时间 O(n + m + maxVal) ／ 空间 O(maxVal)

**易错点**：
- 按 `arr2` 顺序输出后忘记补剩余元素，`7`、`19` 直接丢失；
- 补剩余元素时从 0 扫到 `max`，但 `arr1` 可能有负数（本题约束为非负，若放开需要偏移量）；
- 用 `cnt[v]--` 而不判断 `> 0`，会输出负频次导致死循环；
- 值域很大（如 1e9）时计数数组爆炸，此时应退回"排序权重 + sort"的 O(n log n) 方案。

**变体与追问**：
- `arr2` 中可能有 `arr1` 里没有的元素：计数为 0，`while` 自然跳过，无需特判；
- 要求"未出现的元素也按 `arr1` 中原顺序"：第二段改成遍历 `arr1` 输出未标记过的元素，稳定性更好；
- 与 C-270 的桶排序对比：本题桶宽为 1（每个值一个桶），C-270 是按值域均分的区间桶。

### C-272 相对名次 · 简单 · 阿里/美团

**题干**：给定长度为 `n` 的数组 `score`，`score[i]` 是第 `i` 位运动员的成绩，所有成绩互不相同。返回排名数组：第 1 名 `"Gold Medal"`，第 2 名 `"Silver Medal"`，第 3 名 `"Bronze Medal"`，其余为名次数字的字符串。

**示例**：`输入: score = [5,4,3,2,1]` → `输出: ["Gold Medal","Silver Medal","Bronze Medal","4","5"]`

**思路**：
- 排名本质是"每个元素在降序排列中的位置"，所以先复制一份降序排序，再用哈希表把"成绩 → 名次"记下来，最后按原顺序映射回去。这一步是 O(n log n) 排序 + O(n) 查表。
- 为什么不能直接对原数组排序？排名必须按原下标输出，排序会破坏位置；用"值 → 名次"的映射把两件事解耦，是这类"排序但不改原序"问题的通用套路（与 C-266 保留下标的思路互为表里）。
- 前三名用数组查表比 `if/else` 链更简洁；名次从 0 开始计数时，`i < 3` 对应前三，`String(i + 1)` 对应第 4 名之后。
- 题目保证成绩互不相同，所以哈希不会冲突；若有并列，需要额外定义"并列名次"规则（如 `1,2,2,4` 的跳跃式排名）。

**代码**：
```javascript
function findRelativeRanks(score) {
  const sorted = [...score].sort((a, b) => b - a); // 降序，下标即名次
  const medal = ['Gold Medal', 'Silver Medal', 'Bronze Medal'];
  const rankOf = new Map();
  sorted.forEach((s, i) => rankOf.set(s, i));       // 成绩 -> 名次
  return score.map((s) => {
    const r = rankOf.get(s);
    return r < 3 ? medal[r] : String(r + 1);        // 前3名发奖牌
  });
}

console.log(findRelativeRanks([5, 4, 3, 2, 1]));
// ["Gold Medal","Silver Medal","Bronze Medal","4","5"]
console.log(findRelativeRanks([10, 3, 8, 9, 4]));
// ["Gold Medal","5","Bronze Medal","Silver Medal","4"]
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)

**易错点**：
- 直接对 `score` 排序后返回，结果顺序与原下标错位；
- `String(r)` 而不是 `String(r + 1)`，第 4 名输出成 `"3"`；
- 用对象 `{}` 做映射时，数字键会被转成字符串，虽能工作但不如 `Map` 明确（也避免原型链污染）；
- 前三名的判断用 `r <= 3`，第 4 名也会拿到奖牌。

**变体与追问**：
- 有并列成绩时用"标准竞赛排名"（`1,2,2,4`）：排序后遇到相同成绩沿用上一个名次，并记录"下一个名次 = 当前位置 + 1"；
- 要求 O(n) 且成绩范围小（如 0~1000）：用计数数组从高到低扫，名次即累加计数；
- 与 C-271 的关系：都是"按外部给定的顺序/名次重排"，区别是本题用排序，那题用计数。

### C-273 有效三角形的个数 · 中等 · 字节/腾讯/快手

**题干**：给定非负整数数组 `nums`，返回其中可以组成三角形三条边的三元组个数。三条边能组成三角形的充要条件是**任意两边之和大于第三边**。

**示例**：`输入: nums = [2,2,3,4]` → `输出: 3`（组合为 `(2,2,3)`、`(2,3,4)`、`(2,3,4)`）；`nums = [4,2,3,4]` → `输出: 4`

**思路**：
- 暴力：三重循环判断 O(n³)，`n = 1000` 时 1e9 必超时。
- 关键简化：排序后只需检查**最小的两边之和大于最大边**。因为排序后 `a <= b <= c`，若 `a + b > c`，则 `a + c > b`、`b + c > a` 自动成立，三个不等式退化成一个。
- 于是枚举最大边 `nums[k]`，在 `[0, k-1]` 内用**双指针**数出满足 `nums[i] + nums[j] > nums[k]` 的对数：`i` 从 0、`j` 从 `k-1` 开始。若 `nums[i] + nums[j] > nums[k]`，则 `i` 到 `j-1` 的所有位置与 `j` 组合都成立（因为 `nums[i..j-1] >= nums[i]`），一次性加 `j - i` 后 `j--`；否则说明 `nums[i]` 太小，`i++`。
- 每个 `k` 的双指针是 O(k)，总计 O(n²)；比三重循环省一个数量级，是"排序把无序枚举变成有序单调"的经典收益。

**代码**：
```javascript
function triangleNumber(nums) {
  nums.sort((a, b) => a - b); // 排序后只需比较最小两边与最大边
  let ans = 0;
  for (let k = nums.length - 1; k >= 2; k--) {
    let i = 0, j = k - 1;
    while (i < j) {
      if (nums[i] + nums[j] > nums[k]) {
        ans += j - i; // i..j-1 与 j、k 都能组成三角形
        j--;          // 缩小最大候选边，继续找更小的组合
      } else {
        i++;          // 和小了，只能增大较小边
      }
    }
  }
  return ans;
}

console.log(triangleNumber([2, 2, 3, 4])); // 3
console.log(triangleNumber([4, 2, 3, 4])); // 4
console.log(triangleNumber([0, 0, 0]));    // 0（边长为 0 不构成三角形）
```

**复杂度**：时间 O(n²) ／ 空间 O(1)（排序栈忽略）

**易错点**：
- `ans += j - i` 写成 `ans += j - i + 1`，把 `j` 自己也算进去，答案偏大；
- 判定写成 `>=`，退化三角形（两边之和等于第三边）被错误计入；
- 忘记 `i < j` 的边界，`i == j` 时自己和自己组三角形；
- 不排序直接三重循环，虽然逻辑正确但超时；排序是 O(n²) 的前提。

**变体与追问**：
- 若要求返回具体三元组（去重）：需要额外用 `Set` 存排序后的三元组字符串，且跳过相同元素；
- 若边长可达 `1e9`：`nums[i] + nums[j]` 在 32 位语言会溢出，需用 long；
- 与"两数之和"的关系：固定 `k` 后的双指针计数是"两数之和小于某值"的计数版，模板可迁移。

### C-274 计算数组的小和 · 中等 · 字节/美团

**题干**：定义数组的小和为：对每个 `i`，累加 `nums[i]` 左侧所有**小于等于** `nums[i]` 的元素之和；把所有 `i` 的结果再累加即为小和。给定数组，返回小和。

**示例**：`输入: nums = [1,3,5,2,4,6]` → `输出: 27`（各位置贡献 0、1、4、1、6、15）

**思路**：
- 暴力：对每个 `i` 向左扫，O(n²)。
- 归并：与逆序对完全同构，只是把"计数"换成"求和"。合并两段有序区间时，若 `nums[i] <= nums[j]`，那么 `nums[i]` 会小于等于右段从 `j` 到 `hi` 的**所有**元素（因为右段有序），所以它对小和的贡献是 `nums[i] * (hi - j + 1)`，一次乘加搞定。
- 这个乘法的正确性依赖"右段有序"：右段是递归排好序的，`nums[j..hi]` 全部 `>= nums[j] >= nums[i]`，所以个数就是区间长度。
- 与 C-262 的差别只在统计表达式：逆序对加"个数"（`mid - i + 1`），小和加"值 × 个数"。理解这一点，这一族题就只剩下"合并时怎么数"的换壳。

**代码**：
```javascript
function smallSum(nums) {
  let sum = 0;
  const tmp = new Array(nums.length);
  const merge = (lo, hi) => {
    if (lo >= hi) return;
    const mid = (lo + hi) >> 1;
    merge(lo, mid); merge(mid + 1, hi);
    let i = lo, j = mid + 1, k = lo;
    while (i <= mid && j <= hi) {
      if (nums[i] <= nums[j]) {
        // 右段 [j, hi] 全部 >= nums[i]，共 hi-j+1 个
        sum += nums[i] * (hi - j + 1);
        tmp[k++] = nums[i++];
      } else {
        tmp[k++] = nums[j++];
      }
    }
    while (i <= mid) tmp[k++] = nums[i++]; // 右段已空，不再有小和贡献
    while (j <= hi) tmp[k++] = nums[j++];
    for (let p = lo; p <= hi; p++) nums[p] = tmp[p];
  };
  merge(0, nums.length - 1);
  return sum;
}

console.log(smallSum([1, 3, 5, 2, 4, 6])); // 27
console.log(smallSum([1, 2, 3, 4]));       // 10
```

**复杂度**：时间 O(n log n) ／ 空间 O(n)

**易错点**：
- 乘数写成 `hi - j`，少算 `j` 自身（差一错误，本题最易错处）；
- 用 `<` 而非 `<=`，相等元素不被计入，答案偏小（题目要求"小于等于"）；
- 循环结束后对左段剩余元素继续累加，但此时右段已空，贡献应为 0，多写反而错；
- `sum` 放在外层用全局变量，多次调用忘记清零。

**变体与追问**：
- 改为"左侧严格小于"：把 `<=` 换成 `<` 即可；
- 改为"右侧大于当前元素的和"：归并方向反着数，或把数组翻转后套本题；
- 与树状数组解法对比：离散化后从右往左查询前缀和，O(n log n) 但在线，适合流式数据。

### C-275 数组中两元素的最大乘积 · 简单 · 腾讯

**题干**：给定整数数组 `nums`，选择两个**不同下标**的元素 `nums[i]` 和 `nums[j]`，返回 `(nums[i] - 1) * (nums[j] - 1)` 的最大值。

**示例**：`输入: nums = [3,4,5,2]` → `输出: 12`（选 5 和 4：`(5-1)*(4-1) = 12`）

**思路**：
- 目标函数 `(a-1)(b-1)` 关于 `a`、`b` 各自单调递增（在 `a, b >= 1` 的前提下），所以要使乘积最大，只需取数组中**最大的两个元素**，与它们的位置无关。
- 因此不需要排序：一次遍历维护"最大值"和"次大值"两个变量即可，O(n) 时间、O(1) 空间，比 `sort` 的 O(n log n) 更优，也更能体现"看到目标函数单调就直接维护极值"的思维。
- 更新顺序很关键：新元素比 `max1` 大时，要先把旧 `max1` 降级为 `max2`，再更新 `max1`；否则会丢掉真正的次大值。若只比 `max2` 大，直接更新 `max2`。
- 初值取 0 而不是 `-Infinity`：本题约束 `nums[i] >= 1`，取 0 等价于"尚未赋值"，逻辑更简洁；若允许负数则必须用 `-Infinity`。

**代码**：
```javascript
function maxProduct(nums) {
  let max1 = 0, max2 = 0; // 最大值、次大值
  for (const v of nums) {
    if (v > max1) {
      max2 = max1; // 旧的最大值降级为次大值
      max1 = v;
    } else if (v > max2) {
      max2 = v;
    }
  }
  return (max1 - 1) * (max2 - 1);
}

console.log(maxProduct([3, 4, 5, 2]));       // 12
console.log(maxProduct([1, 5, 4, 5]));       // 16（两个 5 下标不同，合法）
console.log(maxProduct([10, 2, 5, 2]));      // 36
```

**复杂度**：时间 O(n) ／ 空间 O(1)

**易错点**：
- 更新 `max1` 时忘了把旧值赋给 `max2`，次大值丢失（如 `[3,4,5,2]` 会得到 `max2 = 0`）；
- 用 `else if (v > max2)` 时把条件写成 `v >= max2`，相等元素被重复计入同一个下标（本题重复值下标不同是合法的，但语义上要清楚）；
- 先 `sort` 再取最后两个：正确但 O(n log n)，面试官会追问能否 O(n)；
- 认为"必须选不同的值"：题意是不同**下标**，相同值可以选两次，`[1,5,4,5]` 应返回 16。

**变体与追问**：
- 改为 `(nums[i]-1)*(nums[j]-1)*...*(nums[k]-1)` 取 k 个：需要维护前 k 大，用小顶堆 O(n log k)；
- 允许负数：目标函数不再单调，需要同时维护最大值与最小值（因为负负得正）；
- 若要求返回下标：维护极值的同时记录下标，注意不能选中同一个位置。

### C-276 把数组排成最小的数 · 中等 · 字节/腾讯

**题干**：输入一个非负整数数组，把数组里所有数字拼接起来排成一个数，打印能拼接出的所有数字中**最小的一个**。输出为字符串形式（数字可能超出安全整数范围）。

**示例**：`输入: nums = [10,2]` → `输出: "102"`；`nums = [3,30,34,5,9]` → `输出: "3033459"`

**思路**：
- 直觉上"按字典序排"或"按数值排"都不对：`[3,30]` 若按值排得到 `"330"`，正确答案是 `"303"`，说明比较规则必须与**拼接结果**绑定。
- 定义偏序：`a` 排在 `b` 前面当且仅当 `a + b < b + a`（字符串拼接后比较）。把 `sort` 的比较器换成这个规则，得到的序列就是拼接最小的序列。
- 为什么这个比较器可以交给 `sort`？因为它满足**传递性**（可以证明：若 `ab <= ba` 且 `bc <= cb`，则 `ac <= ca`），这是 `sort` 能正确工作的前提。面试被问"为什么这样排是对的"时，这一句是标准答案。
- 比较用字符串而不是数值：`"30" + "3" = "303"`，长度相同的两个拼接串做字典序比较等价于数值比较，但不受精度限制，`nums` 达 1e9 时依然安全。

**代码**：
```javascript
function minNumber(nums) {
  const strs = nums.map(String);
  // 拼接后更小的排在前面；相等时返回 0 保持稳定
  strs.sort((a, b) => {
    const ab = a + b, ba = b + a;
    return ab < ba ? -1 : ab > ba ? 1 : 0;
  });
  const res = strs.join('');
  return res === '' ? '' : res.replace(/^0+(?=\d)/, ''); // 处理前导零
}

console.log(minNumber([10, 2]));          // "102"
console.log(minNumber([3, 30, 34, 5, 9])); // "3033459"
console.log(minNumber([0, 0]));            // "0"
```

**复杂度**：时间 O(n log n · L)（`L` 为拼接串长度） ／ 空间 O(n · L)

**易错点**：
- 比较器写成 `(a, b) => a - b` 或 `a.localeCompare(b)`，`[3,30]` 会得到 `"330"`；
- 比较器返回布尔值（`return a + b < b + a`），`sort` 需要数字，`true/false` 会被转成 `1/0`，`-1` 缺失导致顺序错乱；
- 全 0 数组返回 `"00"`，`[0,0]` 应返回 `"0"`（用正则去掉前导零，但要保留单个 0）；
- 用 `Number(a + b) - Number(b + a)` 比较：数字超出 2^53 后精度丢失，比较结果不可靠。

**变体与追问**：
- 求拼接出的**最大**数：比较器反过来（`b + a` 与 `a + b` 换位）；
- 若数组含负数：需按符号分组，负数段按"绝对值大的在前"排，正数段按本题规则排，中间处理 0；
- 与 C-272 的关系：都是自定义比较器，区别是那题按外部名次、本题按拼接结果。

### C-277 找到数组的中间位置 · 简单 · 阿里/美团

**题干**：给定整数数组 `nums`，找到最左边的"中间位置" `i`，满足 `i` 左侧所有元素之和等于 `i` 右侧所有元素之和。若 `i` 在最左端则左侧和为 0，最右端同理。不存在返回 `-1`。

**示例**：`输入: nums = [2,3,-1,8,4]` → `输出: 3`（左侧 `2+3-1=4`，右侧 `4`）；`nums = [1,-1,4]` → `输出: 2`；`nums = [2,5]` → `输出: -1`

**思路**：
- 暴力：对每个 `i` 分别求和左右两侧，O(n²)。
- 前缀和：先求总和 `total`，从左往右扫并维护 `left`（`i` 之前元素之和）。位置 `i` 的右侧和可以用 `total - left - nums[i]` O(1) 得到，判断 `left === total - left - nums[i]` 即可。整体 O(n)、O(1) 额外空间。
- 关键点是"右侧和"不要重新累加，而是用总和减去左侧和与当前元素；这个"总和 - 已知部分"的技巧在数组划分、平衡点类问题里通用。
- 由于是"最左边"的中间位置，从左往右第一个满足条件的位置直接返回即可，无需继续扫描。

**代码**：
```javascript
function findMiddleIndex(nums) {
  const total = nums.reduce((a, b) => a + b, 0);
  let left = 0; // i 左侧元素之和
  for (let i = 0; i < nums.length; i++) {
    const right = total - left - nums[i]; // 右侧和 = 总和 - 左侧 - 当前
    if (left === right) return i;         // 第一个满足即最左
    left += nums[i];
  }
  return -1;
}

console.log(findMiddleIndex([2, 3, -1, 8, 4])); // 3
console.log(findMiddleIndex([1, -1, 4]));       // 2
console.log(findMiddleIndex([2, 5]));           // -1
```

**复杂度**：时间 O(n) ／ 空间 O(1)

**易错点**：
- `right` 写成 `total - left`，把当前元素算进了右侧，`[1,-1,4]` 会返回 0 而不是 2；
- 先 `left += nums[i]` 再比较，左右边界全错一位；
- 用 `if (left === right) ans = i` 继续循环，返回的是最右边的中间位置，与题意相反；
- `nums` 含负数时仍要用 `===` 而不是大小比较，前缀和不再单调，不能用二分。

**变体与追问**：
- 返回所有中间位置（数组）：去掉 `return`，把可行下标推入结果；
- 要求 O(log n)：只有当数组全为非负数（前缀和单调）时才能二分，含负数必须 O(n)；
- 二维版本（矩阵的平衡线）：先按行/列求前缀和，再逐行判断，仍可做到 O(mn)。

### C-278 使数组唯一的最小增量 · 中等 · 字节/快手

**题干**：给定整数数组 `nums`，每次操作可以选择一个元素并将其**增加 1**。返回使数组中每个值都唯一所需的最少操作次数。

**示例**：`输入: nums = [1,2,2]` → `输出: 1`（变成 `[1,2,3]`）；`nums = [3,2,1,2,1,7]` → `输出: 6`

**思路**：
- 先排序。排序后相同或冲突的元素必然相邻，处理顺序就从"任意位置"变成"从左往右一次扫描"。
- 贪心策略：维护 `prev` = 上一个元素最终被放到的值。对当前元素 `v`，它至少要被提升到 `prev + 1` 才能与前面所有元素不同，所以最终值 `cur = max(v, prev + 1)`，本次操作数 `cur - v`。
- 为什么贪心最优？因为只能加不能减，若把 `v` 抬到比 `prev + 1` 更大，后续元素只会被抬得更高，总代价只会增加。这就是"局部最小即全局最小"的交换论证，面试要能说出来。
- 排序后冲突只可能发生在"当前值 <= 前一个最终值"的情况，一次扫描 O(n)（排序 O(n log n) 主导）。

**代码**：
```javascript
function minIncrementForUnique(nums) {
  nums.sort((a, b) => a - b); // 排序后冲突必然相邻
  let ans = 0, prev = -1;     // prev 为上一个元素最终落到的值
  for (const v of nums) {
    const cur = Math.max(v, prev + 1); // 至少要比前一个大 1
    ans += cur - v;                    // 抬高的步数
    prev = cur;
  }
  return ans;
}

console.log(minIncrementForUnique([1, 2, 2]));          // 1
console.log(minIncrementForUnique([3, 2, 1, 2, 1, 7])); // 6
console.log(minIncrementForUnique([0, 2, 2]));          // 1
```

**复杂度**：时间 O(n log n) ／ 空间 O(1)（忽略排序栈）

**易错点**：
- `prev` 初值写 0，`nums` 含 0 时第一个元素被错误抬高（本题元素可为 0，初值应为 `-1` 或 `-Infinity`）；
- `cur = prev + 1` 而不取 `max`，会把本来就大的元素**缩小**（逻辑上不允许减操作）；
- `ans += cur` 而不是 `cur - v`，多算了原始值；
- 用哈希表逐个探测空位（`while (set.has(v)) v++`），最坏 O(n²)，`n = 1e5` 超时。

**变体与追问**：
- 允许加也允许减：问题变成"使数组严格递增的最小调整代价"，需要 DP 或带绝对值的中位数技巧（LC 2263 的简化版）；
- 值域很小（`<= 1e5`）：可用"并查集找下一个空位"，接近 O(n α(n))；
- 若要求最终数组元素仍在原范围内：可能无解，需先判断 `max - min + 1 >= n`。

### C-279 按递增顺序显示卡牌 · 中等 · 腾讯/拼多多

**题干**：牌组中的每张卡牌都有一个唯一的整数。按以下规则展示：取出牌堆顶的牌展示，若牌堆还有牌，把下一张牌移到牌堆底；重复直到展示完所有牌。返回能使牌以**递增顺序**展示的初始牌堆顺序。

**示例**：`输入: deck = [17,13,11,2,3,5,7]` → `输出: [2,13,3,11,5,17,7]`

**思路**：
- 正向模拟很难：展示顺序由初始排列决定，正向是"排列 → 顺序"，需要反解。
- 反过来做"逆过程"：准备一个下标队列 `[0, 1, ..., n-1]`，把排好序的牌从小到大依次放入队列头部指向的位置，然后**模拟一次"移牌到底"**（把队首元素移到队尾）。这样构造出的位置序列，正好使正向过程按升序揭牌。
- 为什么逆过程等于正向？因为正向操作是"揭牌（队首出队）+ 移牌（队首移到队尾）"，逆过程的每一步恰好把一张已知牌放到"当前会被揭牌的位置"，再复现"移牌"这个动作，保证下一次落点一致。
- 用下标队列而不是真的搬牌：牌的大小排列是已知的（升序），只需要确定"哪张牌放在哪个下标"，队列只负责算出下标顺序。

**代码**：
```javascript
function deckRevealedIncreasing(deck) {
  deck.sort((a, b) => a - b);          // 揭牌顺序就是升序
  const q = [...deck.keys()];          // 下标队列，模拟牌堆的位置变化
  const res = new Array(deck.length);
  // 逆过程：每放一张牌，就复现一次"揭牌 + 移牌到底部"
  for (const card of deck) {
    res[q.shift()] = card;             // 队首下标放当前最小的牌
    if (q.length) q.push(q.shift());   // 复现"把下一张移到底部"
  }
  return res;
}

console.log(deckRevealedIncreasing([17, 13, 11, 2, 3, 5, 7])); // [2,13,3,11,5,17,7]
console.log(deckRevealedIncreasing([1, 1000]));               // [1,1000]
```

**复杂度**：时间 O(n log n)（排序） ／ 空间 O(n)

**易错点**：
- 逆过程里先"移牌"再"放牌"，顺序反了，构造出的排列对应的是另一种揭牌规则；
- 最后一次不需要移牌（堆里只剩一张），漏判 `q.length` 会把空队列的元素 `undefined` 移到队尾；
- 用 `q.shift()` 实现队列：数组 `shift` 是 O(n)，总体退化 O(n²)，大数据应改用头指针或双端队列；
- 混淆"牌堆顶"与"牌堆底"：揭牌取的是队首，移走的是新的队首。

**变体与追问**：
- 若规则改为"移牌后再揭牌"：逆过程相应变成"先移牌再放牌"；
- 若牌可以重复（同一数值多张）：排序后仍按下标队列放置，数值重复不影响位置推导；
- 正向验证：写一个 `reveal` 函数跑一遍结果，是面试时自测的好习惯（也是单元测试的写法）。

### C-280 煎饼排序 · 中等 · 字节/阿里

**题干**：给定数组 `arr`，你可以执行"煎饼翻转"：选择整数 `k`，将 `arr[0..k]`（下标 0 到 k，共 k+1 个元素）整体翻转。返回能使数组有序的翻转序列（`k` 的序列，`1 <= k <= n`），要求翻转次数在 `10 * arr.length` 以内。

**示例**：`输入: arr = [3,2,4,1]` → `输出: [3,4,2,3,2]`（翻转 3 得 `[4,2,3,1]`，翻转 4 得 `[1,3,2,4]`，翻转 2 得 `[3,1,2,4]`，翻转 3 得 `[2,1,3,4]`，翻转 2 得 `[1,2,3,4]`；答案不唯一）

**思路**：
- 煎饼排序的经典策略是"**每次把当前最大的元素归位到末尾**"，最多用 2 次翻转完成一个元素：先把最大值翻到队首（翻转 `maxIdx + 1`），再翻到它该在的位置（翻转 `size`）。
- 为什么这样可行？第一次翻转后最大值在 `arr[0]`；第二次翻转 `[0, size-1]` 会把它送到 `arr[size-1]`，而其余元素的相对顺序翻转两次后恢复原样，所以不会破坏已经归位的后缀。
- 已经是最大且在末尾时跳过（0 次翻转），这保证了翻转次数不超过 `2(n-1)`，满足题目"翻转次数在 10n 以内"的要求。
- 复杂度 O(n²)：每轮找最大值 O(size)，共 n 轮；虽然慢，但这是本题的标准答案，面试重点在"能否用两次翻转把一个元素归位"的构造。

**代码**：
```javascript
function pancakeSort(arr) {
  const res = [];
  const reverse = (i, j) => {
    while (i < j) { [arr[i], arr[j]] = [arr[j], arr[i]]; i++; j--; }
  };
  for (let size = arr.length; size > 1; size--) {
    let maxIdx = 0;
    for (let i = 1; i < size; i++) if (arr[i] > arr[maxIdx]) maxIdx = i;
    if (maxIdx === size - 1) continue;                    // 已归位，不用翻转
    if (maxIdx > 0) { reverse(0, maxIdx); res.push(maxIdx + 1); } // 最大值翻到队首
    reverse(0, size - 1); res.push(size);                 // 再翻到末尾
  }
  return res;
}

const a = [3, 2, 4, 1];
const ops = pancakeSort(a);
console.log(ops, a); // 翻转后 a 有序：[1,2,3,4]
```

**复杂度**：时间 O(n²) ／ 空间 O(1)（不计结果数组）

**易错点**：
- 翻转区间是 `[0, k]`（共 `k+1` 个元素），返回的 `k` 要写成 `maxIdx + 1` 而不是 `maxIdx`；
- 忘记 `maxIdx === size - 1` 的跳过分支，最大值已在末尾还翻两次，把它翻走了；
- `maxIdx === 0` 时仍翻转 1 个元素，多做一次无效操作（虽不影响正确性，但会被问"能否更少"）；
- 翻转后 `size` 没有递减，仍然在已排序的后缀里找最大值，死循环。

**变体与追问**：
- 要求最少翻转次数：本题的最优解是 NP-hard，只能求近似（每次归位一个元素已是 2n-3 上界）；
- 只允许"翻转前 k 个"且要求最终降序：把比较改成找最小值即可；
- 与选择排序的关系：本质是"选择排序 + 两次翻转代替一次交换"，可以借此向面试官说明你对排序不变量的理解。
