# 17 贪心（C-321 ~ C-340）

> 贪心在大厂笔试里从不单独出现，它总裹着"区间""排队""分配""覆盖"的外衣：题目看着像 DP，其实排序一次 + 线性扫一遍就完了。它真正的门槛不是写代码，而是**你得能证明"局部最优推得出全局最优"**——写不出交换论证的贪心，面试官追问两句就崩。**识别特征**：看到"最多/最少 + 区间互不重叠"想到按右端点排序；看到"资源分给需求"想到双指针排序；看到"每步能到的最远位置"想到维护边界；看到"相邻比较"想到左右各扫一遍取 max。

## 题型速查

| 子类型 | 核心手法 | 代表题 |
|---|---|---|
| 排序 + 双指针分配 | 小需求配小资源，不浪费 | C-321 C-330 |
| 区间调度 | 按右端点升序，能选就选 | C-325 C-326 C-337 |
| 覆盖范围贪心 | 维护当前可达的最远边界 | C-322 C-323 C-324 |
| 左右各扫一遍 | 分别满足左约束与右约束后取 max | C-331 C-332 |
| 从后往前回退修正 | 发现逆序就借位，把尾巴填满 | C-333 C-336 |
| 树形状态贪心 | 后序遍历，按子树状态决定父节点 | C-329 |
| 前缀和 + 哈希 / 构造比较 | 模意义下的最短子数组、字典序贪心 | C-338 C-339 C-340 |

### C-321 分发饼干 · 简单 · 阿里/美团

**题干**：假设你是一位很棒的家长，想给孩子们分小饼干。每个孩子最多只能拿一块饼干。对每个孩子 `i` 有一个胃口值 `g[i]`，这是能满足该孩子胃口的最小饼干尺寸；每块饼干 `j` 有一个尺寸 `s[j]`。若 `s[j] >= g[i]`，就能把饼干 `j` 分给孩子 `i` 并让他满足。求最多能满足多少个孩子。

**示例**：`输入: g = [1,2,3], s = [1,1]` → `输出: 1`

**思路**：
- 两个数组各自升序排序，`i` 指向最小胃口、`j` 指向最小饼干。若 `s[j] >= g[i]` 就投喂并双指针前进；否则这块饼干连最小的胃口都满足不了，对谁都没用，直接 `j++` 丢弃。
- **为什么贪心成立（交换论证）**：考察当前最小胃口的孩子 `g[i]`。设存在一个最优解，该孩子要么没饼干、要么拿了某块饼干 `c`。贪心给出的 `c'` 是"能满足 `g[i]` 的最小饼干"，因为 `c` 也满足 `g[i]`，所以必有 `c' <= c`。把最优解里给这个孩子的 `c` 换成 `c'`：`c'` 本身满足要求，被释放的 `c` 又能顶替 `c'` 原本能顶替的任何位置（`c >= c'`，能装下 `c'` 的胃口一定装得下 `c`）。交换后满足人数不减少。
- 对孩子数做归纳：每一步贪心都不使最优解变差，故最终答案最优。

**代码**：
```javascript
/**
 * 分发饼干：小饼干喂小胃口
 * @param {number[]} g 每个孩子的胃口值
 * @param {number[]} s 每块饼干的尺寸
 * @returns {number} 最多能满足的孩子数
 */
function findContentChildren(g, s) {
  g.sort((a, b) => a - b);          // 升序：胃口从小到大
  s.sort((a, b) => a - b);          // 升序：饼干从小到大
  let child = 0;                    // 已满足孩子数，同时是胃口指针
  let cookie = 0;                   // 饼干指针
  while (child < g.length && cookie < s.length) {
    if (s[cookie] >= g[child]) {
      child++;                      // 这块饼干能喂饱，孩子和饼干都前进
      cookie++;
    } else {
      cookie++;                     // 饼干太小，对任何孩子都无用，丢弃
    }
  }
  return child;
}

console.log(findContentChildren([1, 2, 3], [1, 1]));            // 1
console.log(findContentChildren([1, 2], [1, 2, 3]));            // 2
console.log(findContentChildren([10, 9, 8, 7], [5, 6, 7, 8]));  // 2
```

**复杂度**：时间 O(n log n + m log m)（排序主导）／ 空间 O(1)（不计排序栈）。

**易错点**：
- `sort()` 不传比较函数会按**字符串**排序，`[10, 9, 8]` 会排成 `[10, 8, 9]`，这是 JS 头号坑。
- 循环条件必须同时判 `child < g.length`，否则饼干多时会读到 `undefined`，比较结果恒为 `false`，静默算错。
- 别写成"每块饼干都从最小孩子重新找"，那是 O(nm)；双指针的关键是 `child` 只增不减。
- `>=` 的等号不能漏，否则胃口正好等于饼干的孩子会被判为不满足。

**变体与追问**：
- 若饼干可以掰开喂多个孩子：答案变成"排序后累加满足前缀"，贪心不变但判定改为前缀和。
- 若要求"满足孩子胃口总和最大"：退化为 0/1 背包，贪心失效，必须 DP。
- 若每个孩子最多拿 k 块：贪心不再直接成立，需重新论证或换 DP。

### C-322 跳跃游戏 · 中等 · 字节/腾讯

**题干**：给定一个非负整数数组 `nums`，你最初位于数组的第一个下标。数组中的每个元素代表你在该位置可以跳跃的最大长度。判断你是否能够到达最后一个下标。

**示例**：`输入: nums = [2,3,1,1,4]` → `输出: true`；`输入: nums = [3,2,1,0,4]` → `输出: false`

**思路**：
- 只维护一个变量 `reach`：扫描过的最远覆盖下标。遍历到 `i` 时若 `i > reach`，说明 `i` 根本到不了，其右侧更到不了，直接失败；否则用 `i + nums[i]` 更新 `reach`。
- **为什么贪心成立（反证）**：`reach` 的含义是"下标 `0..i` 中所有点能覆盖到的最远位置"，这些点本身都可达（前缀连续）。假设存在 `k > reach` 事实可达，那么它的最后一步必由某个 `j <= reach` 起跳，且 `j + nums[j] >= k > reach`，与 `reach` 是最大值矛盾。
- 本质结论：**可达集合在数轴上是前缀封闭的**，因此只需保证"扫描不掉队"，一次线性扫描即完备，无需枚举路径。

**代码**：
```javascript
/**
 * 跳跃游戏：只关心"最远能覆盖到哪"
 * @param {number[]} nums 每个位置的最大跳跃长度
 * @returns {boolean} 能否到达最后一个下标
 */
function canJump(nums) {
  const last = nums.length - 1;
  let reach = 0;                        // 能覆盖到的最远下标
  for (let i = 0; i <= reach && i < nums.length; i++) {
    reach = Math.max(reach, i + nums[i]);  // 从 i 起跳能到的更远处
    if (reach >= last) return true;        // 已覆盖终点，提前返回
  }
  return false;
}

console.log(canJump([2, 3, 1, 1, 4]));  // true
console.log(canJump([3, 2, 1, 0, 4]));  // false
console.log(canJump([0]));              // true
```

**复杂度**：时间 O(n)／空间 O(1)。

**易错点**：
- 循环写成 `i < nums.length` 却没在循环内判 `i > reach`，会把不可达点的跳跃能力也算进去，得到假 `true`。
- `nums = [0]` 时首元素就是终点，必须返回 `true`，别被 `reach === 0` 误导。
- 有 0 不等于必败，只有"0 落在断层上"才失败。
- 别用 DFS/BFS 枚举跳跃方案，方案数指数级。

**变体与追问**：
- 求最少跳跃次数（LC 45）：见 C-323。
- 若允许向后跳（元素可为负）：贪心失效，需建图或 DP。
- 若要求输出一条可行路径：需要 `from` 数组记录前驱，贪心只保可达性、不保路径。

### C-323 跳跃游戏 II · 中等 · 字节/快手

**题干**：给定长度为 `n` 的 0 索引整数数组 `nums`，`nums[i]` 表示从下标 `i` 向前跳的最大长度。你从下标 `0` 出发，返回到达 `n - 1` 的最小跳跃次数。题目保证可以到达 `n - 1`。

**示例**：`输入: nums = [2,3,1,1,4]` → `输出: 2`（先跳到下标 1，再跳 3 步到末尾）

**思路**：
- 把"跳 k 次能到达的点集"看成分层：第 0 层 `{0}`，第 k 层是 `(end_{k-1}, farthest_k]`。"最少次数"就是 BFS 的层数。
- 实现上不用队列：`end` 是当前层右边界，`farthest` 是下一层右边界。走到 `i === end` 表示当前层耗尽，必须再跳一次，`steps++` 并把 `end` 推到 `farthest`。
- **为什么贪心成立（BFS 最优性）**：同层内所有点耗费的跳跃次数相同，从它们出发一步能覆盖的并集恰好是连续前缀 `(end, farthest]`。既然同层代价一致，选哪个点等价，只需保留"最远"。所以"每层尽量跳最远"不改变层数，而 BFS 保证层数最小。
- 循环只到 `n - 2`：到达终点后无需再跳，遍历到 `n - 1` 会多算一步。

**代码**：
```javascript
/**
 * 跳跃游戏 II：隐式 BFS 分层，求最少跳数
 * @param {number[]} nums 每个位置的最大跳跃长度
 * @returns {number} 到达末尾的最少跳跃次数
 */
function jump(nums) {
  const n = nums.length;
  if (n <= 1) return 0;
  let steps = 0;        // 已跳次数（BFS 层数）
  let end = 0;          // 当前层能覆盖的右边界
  let farthest = 0;     // 下一层能覆盖的右边界
  for (let i = 0; i < n - 1; i++) {   // 关键：不遍历最后一个位置
    farthest = Math.max(farthest, i + nums[i]);
    if (i === end) {                  // 当前层走完，必须再跳一次
      steps++;
      end = farthest;
      if (end >= n - 1) break;        // 已能一步到终点，提前收敛
    }
  }
  return steps;
}

console.log(jump([2, 3, 1, 1, 4]));   // 2
console.log(jump([2, 3, 0, 1, 4]));   // 2
console.log(jump([1, 1, 1, 1]));      // 3
```

**复杂度**：时间 O(n)／空间 O(1)。

**易错点**：
- 循环上界必须是 `n - 1`；站在最后一格还 `steps++` 会多算 1 次，本题最高频 WA。
- `end` 与 `farthest` 混用：`end` 只在层耗尽时更新，提前更新会少算层数。
- 漏判 `n <= 1` 时 `[0]` 会返回 1。
- 别用"每次跳当前最远"的朴素贪心，`[3,100,1,1]` 类数据会错，必须按层推进。

**变体与追问**：
- 求最少跳数的具体路径：记录每次换层时选中的"桥点"。
- 若要求"跳数最少前提下总代价最小"：先 BFS 求层数，再在层内做 DP。
- 反向从终点 BFS 到起点，答案相同，可用于对拍验证。

### C-324 加油站 · 中等 · 美团/字节

**题干**：在一条环路上有 `n` 个加油站，第 `i` 个加油站有 `gas[i]` 升汽油。你有一辆油箱容量无限大的汽车，从第 `i` 个加油站开往第 `i+1` 个加油站需要消耗 `cost[i]` 升汽油。你从某个加油站出发（初始油箱为空），若能绕环路行驶一周则返回出发站编号，否则返回 `-1`。若存在解，保证唯一。

**示例**：`输入: gas = [1,2,3,4,5], cost = [3,4,5,1,2]` → `输出: 3`

**思路**：
- 先算总账：`sum(gas) < sum(cost)` 必然无解，返回 `-1`；否则必有解且唯一。
- 一次遍历，`cur` 记录"从当前候选起点出发的累计净油量"。若某站 `i` 使 `cur` 变负，则候选起点到 `i` 之间**任何一点**都不能当起点，起点直接跳到 `i + 1`，`cur` 清零。
- **为什么整段可跳过（反证）**：设起点 `s` 到 `i` 时累计为负，即 `sum(gas[s..i]) < sum(cost[s..i])`。取中间点 `k ∈ (s, i]`，它到 `i` 的净收益 = 总净收益(负) − 前半段净收益。而能从 `s` 走到 `k-1` 说明前半段净收益 `>= 0`，故 `k` 到 `i` 的净收益 `< 0`，`k` 也到不了 `i` 之后。整段排除不漏解。
- 剩下的起点必然可行：总账非负，所有负前缀段都被跳过，剩下那个点出发的任意前缀和都非负。

**代码**：
```javascript
/**
 * 加油站：一次遍历，失败段整段跳过
 * @param {number[]} gas 每站可加油量
 * @param {number[]} cost 到下一站的耗油
 * @returns {number} 可行的出发站下标，无解返回 -1
 */
function canCompleteCircuit(gas, cost) {
  let total = 0;     // 全局净收益
  let cur = 0;       // 从 start 出发的累计净收益
  let start = 0;     // 当前候选起点
  for (let i = 0; i < gas.length; i++) {
    const diff = gas[i] - cost[i];
    total += diff;
    cur += diff;
    if (cur < 0) {          // 从 start 到 i 走不通
      start = i + 1;        // start..i 全段排除
      cur = 0;              // 新起点重新计数
    }
  }
  return total >= 0 ? start : -1;   // 总账为负才是真无解
}

console.log(canCompleteCircuit([1, 2, 3, 4, 5], [3, 4, 5, 1, 2])); // 3
console.log(canCompleteCircuit([2, 3, 4], [3, 4, 3]));             // -1
console.log(canCompleteCircuit([5, 1, 2, 3, 4], [4, 4, 1, 5, 1])); // 4
```

**复杂度**：时间 O(n)／空间 O(1)。

**易错点**：
- 只在 `cur < 0` 时重置；在 `cur === 0` 时重置会跳过合法起点。
- 最后必须用 `total >= 0` 兜底，只看 `start` 会把无解误判为有解。
- `start` 可能等于 `n`（走到最后才失败），此时 `total < 0` 返回 `-1`，无需额外特判（也别去取模，会错）。
- 别从每个点模拟一圈，那是 O(n²)，1e5 数据必超时。

**变体与追问**：
- 若油箱有容量上限：需维护油量的上下界，一次扫描的贪心不再够用。
- 若允许中途换车/多次出发：变成前缀和 + 单调队列问题。
- 追问"为什么解唯一"：两可行起点间的环段净收益必为 0，配合"唯一解"条件即得唯一。

### C-325 无重叠区间 · 中等 · 腾讯/美团

**题干**：给定区间集合 `intervals`，其中 `intervals[i] = [start_i, end_i]`。返回需要移除区间的最小数量，使剩余区间互不重叠。区间 `[1,2]` 与 `[2,3]` 端点相接视为**不重叠**。

**示例**：`输入: intervals = [[1,2],[2,3],[3,4],[1,3]]` → `输出: 1`（移除 `[1,3]`）

**思路**：
- "最少移除"等价于"最多保留多少个互不重叠区间"，即经典区间调度。按**右端点升序**排序，能选就选。
- **为什么按右端点排（交换论证）**：设排序后第一个区间为 `I1`（右端点最小）。任取最优解，其第一个区间为 `J`，有 `J.end >= I1.end`。把 `J` 换成 `I1`：`I1` 与最优解中第二个区间仍不冲突（右端点更靠左，只会给后续留更多空间），故存在包含 `I1` 的最优解。归纳即得最优。
- 直观上，右端点越靠左"占用的未来"越少，这是唯一需要压榨的量；按左端点排则会让长区间把后面全堵死。
- 答案 = 区间总数 − 最多保留数。

**代码**：
```javascript
/**
 * 无重叠区间：按右端点排序的区间调度
 * @param {number[][]} intervals 区间列表 [start, end]
 * @returns {number} 最少需要移除的区间数
 */
function eraseOverlapIntervals(intervals) {
  const n = intervals.length;
  if (n <= 1) return 0;
  intervals.sort((a, b) => a[1] - b[1]);  // 关键：按右端点升序
  let kept = 1;                           // 至少保留一个
  let end = intervals[0][1];              // 上一个保留区间的右端点
  for (let i = 1; i < n; i++) {
    if (intervals[i][0] >= end) {         // 端点相接算不重叠
      kept++;
      end = intervals[i][1];              // 只有保留时才更新边界
    }
  }
  return n - kept;
}

console.log(eraseOverlapIntervals([[1, 2], [2, 3], [3, 4], [1, 3]])); // 1
console.log(eraseOverlapIntervals([[1, 2], [1, 2], [1, 2]]));         // 2
console.log(eraseOverlapIntervals([[1, 2], [2, 3]]));                 // 0
```

**复杂度**：时间 O(n log n)／空间 O(1)。

**易错点**：
- 排序键写成 `a[0] - b[0]`：本题第一大坑，`[[1,100],[2,3],[3,4]]` 会算成 2（正确 1）——长区间 `[1,100]` 把后面全堵死，右端点排序才能识别出"删掉它最划算"。
- 边界必须 `>=`：端点相接不算重叠，写成 `>` 会把 `[1,2],[2,3]` 判为冲突而多删。
- 冲突时不要更新 `end`，否则长区间也被"保留"了。
- 返回"移除数"而非"保留数"，两者差一个 `n`。

**变体与追问**：
- 用最少箭引爆气球（LC 452）：同套排序，但判定改成 `start > end` 才加箭（端点可共用一支箭）。见 C-326。
- 会议室 II（LC 253，求最少会议室）：那是"最大重叠数"，用最小堆或差分，不能用这个贪心。
- 加权区间调度（区间带收益求最大权和）：贪心失效，改 DP + 二分。

### C-326 用最少数量的箭引爆气球 · 中等 · 字节/美团

**题干**：在二维空间中有许多球形气球，对于一个气球，提供水平方向上直径的起点和终点，即 `points[i] = [x_start, x_end]`。一支弓箭可以沿 `x` 轴从不同点完全垂直射出，若满足 `x_start <= x <= x_end`，该气球会被引爆。求引爆所有气球所必须射出的**最小**弓箭数。

**示例**：`输入: points = [[10,16],[2,8],[1,6],[7,12]]` → `输出: 2`

**思路**：
- 与 C-325 同一血脉：按**右端点升序**排序，箭头固定在上一个气球的右端点。若下一个气球左端点 `> 箭头位置`，说明射不到，必须补一支箭。
- **为什么把箭放在右端点最优（交换论证）**：设第一个气球为 `[s1, e1]`。任何能引爆它的箭位置 `x` 必满足 `x <= e1`。把箭从 `x` 移到 `e1`，能引爆的气球集合只会变大（凡是区间包含 `x` 且 `x < e1` 的，若 `e1` 不在区间内，则该区间右端点 `< e1`，与 `e1` 是"最靠左右端点"矛盾）。所以取 `e1` 不劣于任何选择，可归纳到剩余气球。
- 注意与 C-325 的差别：这里**端点相接可以被同一支箭射穿**，所以判定用 `start > pos` 而不是 `>=`，这正是两题最容易混淆的地方。

**代码**：
```javascript
/**
 * 最少箭引爆气球：按右端点排序，箭钉在最靠左的右端点上
 * @param {number[][]} points 每个气球 [x_start, x_end]
 * @returns {number} 最少箭数
 */
function findMinArrowShots(points) {
  if (points.length === 0) return 0;
  points.sort((a, b) => a[1] - b[1]);   // 右端点升序
  let arrows = 1;                        // 至少一支
  let pos = points[0][1];                // 当前箭的位置 = 最靠左的右端点
  for (let i = 1; i < points.length; i++) {
    if (points[i][0] > pos) {            // 严格大于才射不到（端点可共用）
      arrows++;
      pos = points[i][1];                // 新箭钉在新气球的右端点
    }
  }
  return arrows;
}

console.log(findMinArrowShots([[10, 16], [2, 8], [1, 6], [7, 12]])); // 2
console.log(findMinArrowShots([[1, 2], [3, 4], [5, 6], [7, 8]]));    // 4
console.log(findMinArrowShots([[1, 2], [2, 3], [3, 4], [4, 5]]));    // 2
```

**复杂度**：时间 O(n log n)／空间 O(1)。

**易错点**：
- 判定写成 `>=` 就变成"端点相接要两支箭"，比正确答案多；用 `>` 才对。
- 空数组要返回 0，直接 `points[0][1]` 会抛错。
- 箭的位置只在"需要新箭"时更新，不需要每轮都改。
- 若按**左端点**排序，`[[1,10],[2,3],[4,5]]` 会先拿 `[1,10]` 把箭钉在 10，误判 1 支就够（正确答案 2）；坚持按右端点。

**变体与追问**：
- 若气球是三维球体（区间变超矩形）：问题变成集合覆盖，NP-hard。
- 若问"每支箭必须有不同位置"：答案不变（右端点必互不相同或可微调）。
- 若同时求箭的具体位置：记录每次 `pos` 的取值即可。

### C-327 划分字母区间 · 中等 · 阿里/快手

**题干**：字符串 `S` 由小写字母组成。要把这个字符串划分成尽可能多的片段，同一字母最多出现在一个片段中。返回一个表示每个字符串片段长度的列表。

**示例**：`输入: S = "ababcbacadefegdehijhklij"` → `输出: [9,7,8]`

**思路**：
- 先扫一遍记录每个字母**最后出现的位置** `last[c]`。再扫第二遍，维护当前片段的右边界 `end = max(end, last[c])`。当 `i === end` 说明片段内所有字母都不会再出现在后面，此处必须切分——切完 `start = i + 1` 继续。
- **为什么贪心成立（最早切分必最优）**：设当前片段起点为 `start`，那么任何合法片段的右端点都不可能小于 `max(last[c] for c in 片段)`，否则某个字母会跨片段出现。因此上述 `end` 是**最小的合法切点**。切得越早，剩余部分越长，而"片段数最多"正是把问题切成更多独立子问题，故每次取最小合法切点不会让最优解变差（标准的最早切分贪心，归纳可证：任何最优解的第一个片段右端点 `>= end`，截断到 `end` 后剩余部分仍是原问题的一个后缀子问题，片段数不减）。
- 一旦切分，两段中不存在共同字母，子问题完全独立，这就是贪心能"局部决定、全局累加"的根本原因。

**代码**：
```javascript
/**
 * 划分字母区间：先记最后位置，再贪心扩右界
 * @param {string} s 仅含小写字母
 * @returns {number[]} 每个片段的长度
 */
function partitionLabels(s) {
  const last = new Array(26).fill(-1);
  for (let i = 0; i < s.length; i++) {
    last[s.charCodeAt(i) - 97] = i;      // 记录每个字母最后一次出现的位置
  }
  const res = [];
  let start = 0;                          // 当前片段起点
  let end = 0;                            // 当前片段右边界
  for (let i = 0; i < s.length; i++) {
    end = Math.max(end, last[s.charCodeAt(i) - 97]);  // 扩到片段内最远
    if (i === end) {                      // 片段内字母不会再出现在后面
      res.push(end - start + 1);
      start = i + 1;                      // 切分，开新片段
    }
  }
  return res;
}

console.log(partitionLabels("ababcbacadefegdehijhklij")); // [9, 7, 8]
console.log(partitionLabels("eccbbbbdec"));              // [10]
console.log(partitionLabels("ab"));                      // [1, 1]
```

**复杂度**：时间 O(n)／空间 O(1)（26 个字母的定长表）。

**易错点**：
- 用 `charCodeAt(i) - 97` 做下标，忘了减 97 会越界或错位（大写字母要减 65）。
- 必须"先扫一遍求 last，再扫一遍切分"；边扫边更新 `last` 会把后面的出现漏掉。
- 片段长度是 `end - start + 1`，漏 `+1` 会少 1。
- 切分后 `start` 要更新为 `i + 1`，不更新会算出重复长度。

**变体与追问**：
- 若要求"片段数固定为 k"：变成带约束的划分，贪心不再适用，需 DP。
- 若允许同一字母出现在两个片段（不再是硬约束）：问题退化为任意划分，答案无意义。
- 若字符串含大写与数字：把 `26` 扩成 ASCII 128 或改用 Map 存 `last`。

### C-328 根据身高重建队列 · 中等 · 字节

**题干**：假设有打乱顺序的一群人站成一个队列，数组 `people` 表示队列中人的属性，`people[i] = [h_i, k_i]`，`h_i` 是第 `i` 个人的身高，`k_i` 是排在这个人前面且身高**大于或等于** `h_i` 的人数。请重新构造并返回这个队列（答案可能不唯一，返回任一合法队列即可）。

**示例**：`输入: people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]` → `输出: [[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]`

**思路**：
- 排序规则：**身高降序；身高相同则 `k` 升序**。然后按顺序把每个人 `splice(k, 0, person)` 插入到下标 `k`。
- **为什么贪心成立（归纳）**：先处理高个子。此时队伍里全是身高 `>=` 当前人的人，把当前人插到下标 `k`，他前面恰好有 `k` 个人且都比它高，`k` 的要求被精确满足。关键在"矮个子插进来不破坏高个子的 `k`"：矮个子插到某个高个子前面会使高个子的下标 +1，但矮个子身高 `<` 高个子，不计入"身高 `>=`"的统计，所以高个子的 `k` 值不变。
- 身高相同时按 `k` 升序是必须的：`k` 小的人应先就位，否则 `k` 大的插在前面会把 `k` 小的挤到后面，`k` 小的那个人的前置数量就错了。这是本排序规则"第二关键字"的来由。
- 每一步插入后，已处理部分都是合法的，归纳到全部处理完即得合法队列。

**代码**：
```javascript
/**
 * 按身高重建队列：高个子先站，矮个子按 k 插入
 * @param {number[][]} people [h, k] 数组
 * @returns {number[][]} 重建后的队列
 */
function reconstructQueue(people) {
  // 身高降序；同身高时 k 小的在前
  people.sort((a, b) => (a[0] === b[0] ? a[1] - b[1] : b[0] - a[0]));
  const res = [];
  for (const p of people) {
    res.splice(p[1], 0, p);   // 插到下标 k：前面正好 k 个不低于他的人
  }
  return res;
}

console.log(JSON.stringify(reconstructQueue([[7, 0], [4, 4], [7, 1], [5, 0], [6, 1], [5, 2]])));
// [[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]
console.log(JSON.stringify(reconstructQueue([[6, 0], [5, 0], [4, 0], [3, 2], [2, 2], [1, 4]])));
// [[4,0],[5,0],[2,2],[3,2],[1,4],[6,0]] 之类合法解
```

**复杂度**：时间 O(n²)（`splice` 是 O(n)）／空间 O(n)。

**易错点**：
- 同身高按 `k` **降序**排序会出错：`[[7,1],[7,0]]` 会先插 `k=1` 导致越界或顺序错乱。
- 排序方向写反（升序处理）则整个贪心的前提"队伍里全是高个子"不成立。
- `splice(k, 0, p)` 的第二个参数是删除个数，必须是 0；写成 `splice(k, p)` 会删人。
- 直接改传入数组会污染入参，工程代码里应先 `slice()` 拷贝。

**变体与追问**：
- 若 `k` 定义为"前面严格更高的人数"（`>` 而非 `>=`）：排序第二关键字要改成同身高按 `k` 升序仍然成立，但插入位置要减去同身高已插入的人数。
- 若要求 O(n log n)：把数组换成"树状数组/平衡树 + 逆序定位置"（从矮到高，用 BIT 找第 `k+1` 个空位）。
- 若问"合法队列是否唯一"：不唯一，同身高的人可互换。

### C-329 监控二叉树 · 困难 · 拼多多/字节

**题干**：给定一个二叉树，我们在树的节点上安装摄像头。节点上的每个摄像头可以监视它的父节点、自身及其直接子节点。计算监控树的所有节点所需的最小摄像头数量。

**示例**：`输入: [0,0,null,0,0]` → `输出: 1`（摄像头放在根节点的左孩子上）

**思路**：
- 后序遍历 + 三态：`0 = 未被覆盖`、`1 = 已被覆盖但无摄像头`、`2 = 该节点有摄像头`。空节点返回"已覆盖"，避免叶子被迫装摄像头。
- 决策规则（自底向上）：只要有一个孩子"未被覆盖"，当前节点**必须**装摄像头（唯一能覆盖那个孩子的就是它爹）；否则若有一个孩子有摄像头，当前节点被覆盖；否则当前节点"未覆盖"，交给父节点处理。
- **为什么贪心成立（支配关系 + 归纳）**：对一个叶子节点，能覆盖它的位置只有自己和父节点。选父节点的覆盖集**严格包含**选自己的覆盖集（父节点还能覆盖兄弟、父节点自身），所以在父节点装是弱支配的策略，永远不会更差。推广到任意子树：若子树的根"未覆盖"，能覆盖它的只剩父节点（子树内部已无更优点），因此必须由父节点装摄像头，这就是贪心的必然性。归纳自底向上，每步都取弱支配方案，总摄像头数最小。
- 最后根节点若仍"未覆盖"，只能自己装一个（没有父节点了）。

**代码**：
```javascript
function TreeNode(val, left, right) {
  this.val = val === undefined ? 0 : val;
  this.left = left === undefined ? null : left;
  this.right = right === undefined ? null : right;
}

/**
 * 监控二叉树：后序遍历 + 三态贪心
 * @param {TreeNode} root
 * @returns {number} 最少摄像头数
 */
function minCameraCover(root) {
  const UNCOVERED = 0, COVERED = 1, CAMERA = 2;
  let cameras = 0;

  function dfs(node) {
    if (!node) return COVERED;          // 空节点已"覆盖"，别让叶子装摄像头
    const left = dfs(node.left);
    const right = dfs(node.right);
    if (left === UNCOVERED || right === UNCOVERED) {
      cameras++;                        // 有孩子没被覆盖，当前节点必须装
      return CAMERA;
    }
    if (left === CAMERA || right === CAMERA) return COVERED; // 被孩子照到
    return UNCOVERED;                   // 孩子都被覆盖但都没摄像头，交给父节点
  }

  if (dfs(root) === UNCOVERED) cameras++;  // 根节点没有父节点，只能自救
  return cameras;
}

// 构造 [0,0,null,0,0] 并验证
const root = new TreeNode(0, new TreeNode(0, new TreeNode(0), new TreeNode(0)), null);
console.log(minCameraCover(root));   // 1
console.log(minCameraCover(new TreeNode(0)));  // 1
```

**复杂度**：时间 O(n)／空间 O(h)（递归栈，h 为树高）。

**易错点**：
- 空节点返回 `UNCOVERED` 会导致每个叶子都装摄像头，答案偏大；必须返回 `COVERED`。
- 三种状态的语义容易写串，尤其是"有摄像头"与"被覆盖"要分开，否则无法判断父节点是否需要装。
- 忘记根节点兜底：`dfs(root) === UNCOVERED` 时 `cameras++`，漏了会少 1。
- 递归写法在退化树（链）上栈深 O(n)，1e5 节点可能爆栈，工程上要改迭代后序。

**变体与追问**：
- 若摄像头能监视距离 2 的节点：状态要多一维（剩余监视半径），贪心规则更难，一般改树形 DP。
- 若每个节点装摄像头有不同代价：贪心失效，改树形 DP `dp[u][0/1/2]`。
- 若问"是否能把树删点使每个保留点都被覆盖"：变成最小支配集，同一套后序贪心思路。

### C-330 柠檬水找零 · 简单 · 美团/腾讯

**题干**：在柠檬水摊上，每一杯柠檬水的售价为 5 美元。顾客排队购买（按账单 `bills` 的顺序），每位顾客只买一杯，且分别向你付 5 美元、10 美元或 20 美元。你必须给每位顾客正确找零，即净交易是每位顾客付给你 5 美元。注意一开始你手头没有任何零钱。如果你能给每位顾客正确找零，返回 `true`，否则返回 `false`。

**示例**：`输入: bills = [5,5,5,10,20]` → `输出: true`；`输入: bills = [5,5,10,10,20]` → `输出: false`

**思路**：
- 只需维护 `five` 和 `ten` 两个计数（20 美元找不出零，收进来也没用）。
- 收 5：`five++`。收 10：必须找回 5，`five--`、`ten++`。收 20：找 15，**优先用 10+5**，没有再考虑 5+5+5。
- **为什么优先消耗 10（交换论证 / 通用性）**：5 美元是"硬通货"——它既能给 10 找零，也能给 20 找零；10 美元只能给 20 找零。为了未来留出最大灵活性，应当优先消耗通用性差的 10。若某最优策略在用 5+5+5 找零时手里其实有 10，把它换成 10+5 后找零金额不变、5 的数量反而多 2 个，对后续任何情形都不劣——故优先用 10 是弱支配策略。
- 反过来若手里只有两张 5 而需要给 10 找零，必须用掉一个 5，这是唯一的局部最优。

**代码**：
```javascript
/**
 * 柠檬水找零：优先花掉通用性差的 10 美元
 * @param {number[]} bills 顾客付款序列，只含 5/10/20
 * @returns {boolean} 能否全部正确找零
 */
function lemonadeChange(bills) {
  let five = 0;      // 5 美元张数
  let ten = 0;       // 10 美元张数
  for (const bill of bills) {
    if (bill === 5) {
      five++;
    } else if (bill === 10) {
      if (five === 0) return false;   // 找不出 5
      five--;
      ten++;
    } else {                          // 收到 20，需找 15
      if (ten > 0 && five > 0) {      // 优先 10 + 5
        ten--;
        five--;
      } else if (five >= 3) {         // 只能三张 5
        five -= 3;
      } else {
        return false;
      }
    }
  }
  return true;
}

console.log(lemonadeChange([5, 5, 5, 10, 20]));  // true
console.log(lemonadeChange([5, 5, 10, 10, 20])); // false
console.log(lemonadeChange([5, 5, 10]));         // true
```

**复杂度**：时间 O(n)／空间 O(1)。

**易错点**：
- 20 美元找零时先用 `five -= 3` 再判 `ten`，会漏掉"有 10 但 5 不够 3 张"的情形（`[5,5,10,10,20]` 就该 false，用错顺序会误判）。
- 只统计 5 和 10 的钱数，别把 20 也算进可用零钱（20 找不开）。
- 收到 10 时若 `five === 0` 必须立刻返回 false，不能"等后面收 5 再补"。
- 找零判断顺序必须是"先 10+5，再 5×3"，调换顺序会错。

**变体与追问**：
- 若面额改为 5/10/20/50：贪心规则变复杂，但"优先消耗通用性差的面额"原则仍成立。
- 若问"最少需要准备多少初始零钱"：变成前缀最小值问题，扫一遍取 `-min(prefix deficit)`。
- 若顾客可以不按顺序（可调度）：需要判断"是否存在排列使全部成功"，是另一类贪心/搜索题。

### C-331 分发糖果 · 困难 · 字节/腾讯

**题干**：`n` 个孩子站成一排，每个孩子有一个评分 `ratings[i]`。你需要给每个孩子至少 1 颗糖果，并满足：相邻两个孩子中评分更高的那个必须获得更多的糖果。求最少需要准备多少颗糖果。

**示例**：`输入: ratings = [1,0,2]` → `输出: 5`（分配 `[2,1,2]`）

**思路**：
- 一次遍历无法同时兼顾左右两侧，于是拆成两个独立方向：从左到右保证"右 > 左时，右边比左边多 1"；从右到左保证"左 > 右时，左边比右边多 1"。两遍结果对每个位置取 `max`，再求和。
- **为什么取 max 就是最优（差分约束视角）**：把每个孩子看成一个变量 `c[i] >= 1`，约束形如 `c[i] >= c[i-1] + 1`（当 `ratings[i] > ratings[i-1]`）。这是一个**差分约束系统**，所有约束都是"下界"，因此对每个变量取"各条链给出的下界的最大值"就是最小可行解：既满足所有约束（因为不小于每个下界），又不可能再小（因为再小就违反某条约束）。两遍扫描分别求出了左侧链与右侧链的下界，`max` 即两条链下界的合并。
- 注意 `ratings[i] === ratings[i-1]` 时不加约束，此时两边可以都是 1，不需要 `+1`。

**代码**：
```javascript
/**
 * 分发糖果：左右各扫一遍，取两侧下界的最大值
 * @param {number[]} ratings 每个孩子的评分
 * @returns {number} 最少糖果总数
 */
function candy(ratings) {
  const n = ratings.length;
  if (n === 0) return 0;
  const c = new Array(n).fill(1);        // 每人至少 1 颗
  // 左 → 右：保证右比左高时糖果更多
  for (let i = 1; i < n; i++) {
    if (ratings[i] > ratings[i - 1]) c[i] = c[i - 1] + 1;
  }
  // 右 → 左：保证左比右高时糖果更多，取 max 保留两个方向的下界
  for (let i = n - 2; i >= 0; i--) {
    if (ratings[i] > ratings[i + 1]) {
      c[i] = Math.max(c[i], c[i + 1] + 1);
    }
  }
  let sum = 0;
  for (const x of c) sum += x;
  return sum;
}

console.log(candy([1, 0, 2]));                 // 5
console.log(candy([1, 2, 2]));                 // 4
console.log(candy([1, 3, 2, 2, 1]));           // 7
```

**复杂度**：时间 O(n)／空间 O(n)。

**易错点**：
- 第二遍忘了取 `Math.max`，直接 `c[i] = c[i+1] + 1` 会把第一遍算大的值覆盖掉，`[1,2,3,1]` 类数据必错。
- 相等时也 `+1`，会让 `[1,2,2]` 的输出从 4 变成 6。
- 只做单方向一遍是最常见的错误：`[1,2,3,4,5]` 单向左扫是对的，但 `[5,4,3,2,1]` 会全变 1。
- 求和时用 `reduce` 别忘了初始值 0，空数组会抛错。

**变体与追问**：
- 若孩子站成环形（首尾相邻也需满足）：先处理成"断开最低点"，或做两次线性 + 特判首尾。
- 若每条约束允许"多给"而不必恰好差 1：最优解不变（多给只会增加总数）。
- 若要输出具体分配方案：直接返回 `c` 数组即可，注意可能有多个最优解。

### C-332 摆动序列 · 中等 · 快手/美团

**题干**：如果连续数字之间的差严格地在正数和负数之间交替，则数字序列称为摆动序列。第一个差（如果存在）可以是正数或负数，仅有一个元素或含两个不等元素的序列也视作摆动序列。子序列可以通过删除原序列中的一些元素（也可不删除）得到。返回 `nums` 中作为摆动序列的最长子序列的长度。

**示例**：`输入: nums = [1,7,4,9,2,5]` → `输出: 6`（整段都是摆动序列）

**思路**：
- 观察：一段单调递增/递减的"中间点"删掉不会影响摆动性——只保留**拐点**（局部极大、局部极小）即可。于是只需数"方向发生变化的次数 + 1"。
- 用 `up` 表示"以当前元素结尾、最后一步为上升的摆动序列最长长度"，`down` 同理。遇到 `nums[i] > nums[i-1]` 时 `up = down + 1`（在任意一个下降结尾的序列后再接一个上升）；反之 `down = up + 1`。相等则两个都不动（平段不改变方向）。
- **为什么贪心成立（删除中间点不劣）**：设存在连续三段同向 `a < b < c`。把 `b` 删除仍是合法摆动（`a` 到 `c` 仍是一个"上升"），且不影响 `b` 前后已有的拐点，故删掉中间元素不会让答案变小。反复删除后，剩下的就是所有极值点，长度即答案。这等价于"只保留波峰波谷"的贪心，而 `up/down` 递推正是它在 O(n) 下的实现。
- 序列长度 = `max(up, down)`。

**代码**：
```javascript
/**
 * 摆动序列：数拐点，等价于只保留波峰波谷
 * @param {number[]} nums
 * @returns {number} 最长摆动子序列长度
 */
function wiggleMaxLength(nums) {
  const n = nums.length;
  if (n < 2) return n;           // 空 / 单元素
  let up = 1;                    // 以 i 结尾、最后方向向上的最长长度
  let down = 1;                  // 以 i 结尾、最后方向向下的最长长度
  for (let i = 1; i < n; i++) {
    if (nums[i] > nums[i - 1]) {
      up = down + 1;             // 接在某个下降序列后面形成波谷→波峰
    } else if (nums[i] < nums[i - 1]) {
      down = up + 1;             // 接在某个上升序列后面形成波峰→波谷
    }
    // 相等时两个都不变：平段不产生新拐点
  }
  return Math.max(up, down);
}

console.log(wiggleMaxLength([1, 7, 4, 9, 2, 5]));   // 6
console.log(wiggleMaxLength([1, 17, 5, 10, 13, 15, 10, 5, 16, 8])); // 7
console.log(wiggleMaxLength([1, 2, 3, 4, 5, 6, 7, 8, 9]));          // 2
```

**复杂度**：时间 O(n)／空间 O(1)。

**易错点**：
- 初始化 `up = down = 1` 而非 0；设 0 会让全等数组返回 0（应为 1）。
- 用 `>=` / `<=` 判断会把平段当成方向变化，`[3,3,3,2,5]` 会算多。
- 若用"贪心跳跃"写法（跳过同向连续段），要小心首尾指针越界；`up/down` 递推更不容易写错。
- 返回 `Math.max(up, down)`，不是 `up + down`。

**变体与追问**：
- 求最长摆动**子数组**（必须连续）：改成滑动窗口/双指针。
- 求"最长交替子序列"且允许相等也算一次摆动：约束放松，需改状态定义。
- 若要求输出具体序列：`up/down` 需同时记录前驱下标，再回溯。

### C-333 单调递增的数字 · 中等 · 阿里/字节

**题干**：给定一个整数 `n`，返回小于或等于 `n` 的最大整数，且该整数满足各位数字是**单调递增**的（即每一位数字都不大于其右侧相邻的数字，例如 `1234`、`1123`）。`n` 的范围是 `[0, 10^9]`。

**示例**：`输入: n = 332` → `输出: 299`；`输入: n = 1234` → `输出: 1234`

**思路**：
- 从右往左找**第一个下降点**：若 `a[i-1] > a[i]`，说明前缀被 `a[i-1]` 卡住了，把它减 1，并把从 `i` 开始的所有位改成 9（后缀取最大）。
- 为什么只需改这一位：前缀 `a[0..i-2]` 已经单调递增，若把 `a[i-1]` 减 1，可能与 `a[i-2]` 形成新的下降，所以要从右往左**连续回退**（循环里继续 `i--` 修正），直到前缀重新单调。
- **为什么贪心成立（前缀最大化 + 后缀最大化的字典序论证）**：要"不超过 n 的最大数"，应尽可能保留与 n 相同的前缀。第一个下降点之后无论怎么填都不可能再保持前缀相等（因为 `a[i-1] > a[i]` 本身就违反递增），必须牺牲 `a[i-1]`：减 1 是最小的牺牲。牺牲后为了让数最大，后缀每一位都应填 9（这是该位置上能取的最大值，且 9 一定能让后缀单调）。字典序比较下，"保留最长相同前缀 + 最小牺牲 + 后缀全 9"是最大解，故贪心最优。
- 特判：`n < 10` 时直接返回 `n`（本身单调）。

**代码**：
```javascript
/**
 * 单调递增的数字：找第一个下降点，前一位借位，后缀全 9
 * @param {number} n
 * @returns {number} 不大于 n 的最大单调递增整数
 */
function monotoneIncreasingDigits(n) {
  if (n < 10) return n;
  const a = String(n).split('').map(Number);
  let start = a.length;                 // 从 start 开始全部填 9
  for (let i = a.length - 1; i > 0; i--) {
    if (a[i - 1] > a[i]) {
      a[i - 1] -= 1;                    // 借位：前一位减 1
      start = i;                        // 后缀从 i 起全变 9
    }
  }
  for (let i = start; i < a.length; i++) a[i] = 9;
  return Number(a.join(''));
}

console.log(monotoneIncreasingDigits(332));   // 299
console.log(monotoneIncreasingDigits(1234));  // 1234
console.log(monotoneIncreasingDigits(10));    // 9
console.log(monotoneIncreasingDigits(120));   // 119
```

**复杂度**：时间 O(log n)（位数）／空间 O(log n)。

**易错点**：
- 只处理一处下降就停下：`332` 需要连续回退两次（`3,3,2` → `3,2,9`? 实际是 `2,9,9`），必须让循环自然往回走。
- 没有下降点时 `start` 保持为 `length`，后缀循环不执行，才能返回 `1234` 本身；若把 `start` 初始化为 0 会把整个数变成 999……
- 前导零问题：`10` → `09` → `Number("09")` 得 9，正确；但若用字符串返回会得到 `"09"`。
- 直接用数值取模 `/10` 拆位在负数上会出错，本题 `n >= 0` 才安全。

**变体与追问**：
- 若要求"小于 n 的最大单调递增数"：在结果上再减一位处理（或把 `<=` 改 `<` 后重新借位）。
- 若要求"严格递增"（各位互不相同）：贪心规则变为借位后填 `9,8,7,...`。
- 若 `n` 可达 `10^18`：JS 的 Number 精度不够，必须用 `BigInt` 或字符串比较。

### C-334 种花问题 · 简单 · 美团/阿里

**题干**：假设有一个很长的花坛，一部分地块种植了花，另一部分却没有。花不能种植在相邻的地块上，否则它们会争夺水源而双双死去。给定一个整数数组 `flowerbed` 表示花坛（`0` 表示没种花，`1` 表示种了花）和一个整数 `n`，能否在不打破规则的情况下种入 `n` 朵花？能则返回 `true`。

**示例**：`输入: flowerbed = [1,0,0,0,1], n = 1` → `输出: true`；`输入: flowerbed = [1,0,0,0,1], n = 2` → `输出: false`

**思路**：
- 从左到右扫，若 `i` 位置为空且左右邻居都为空（边界外视为空），就在 `i` 种一朵并把它标记为 1，继续往后。种满 `n` 朵即可提前返回。
- **为什么"能种就种"最优（交换论证）**：设当前位置 `i` 可以合法种植。若某个最优解在 `i` 不种，那么 `i` 之后的位置最多只能种到与贪心相同数量——把最优解中 `i+2` 及之后的第一朵花挪到 `i`，合法性不受影响（`i` 的左右都空），且挪走后 `i+2` 周围更空，不会让后续变差。故存在一个"在 `i` 种"的最优解。
- 换句话说：种在 `i` 只会"占用" `i-1, i, i+1` 三个位置，而种在更右侧占用的区间是它的平移，右端点更靠右、对未来更不利。左端尽量靠左种，是区间调度式的标准贪心。
- 边界处理：`i === 0` 只需看右边，`i === len-1` 只需看左边。

**代码**：
```javascript
/**
 * 种花问题：从左往右，能种就种
 * @param {number[]} flowerbed 0 空 1 有花
 * @param {number} n 需要种的花数
 * @returns {boolean} 能否种下 n 朵
 */
function canPlaceFlowers(flowerbed, n) {
  const f = flowerbed.slice();          // 不污染入参
  let planted = 0;
  for (let i = 0; i < f.length; i++) {
    if (f[i] !== 0) continue;           // 已有花，跳过
    const leftOk = i === 0 || f[i - 1] === 0;          // 左邻居空（或边界）
    const rightOk = i === f.length - 1 || f[i + 1] === 0; // 右邻居空（或边界）
    if (leftOk && rightOk) {
      f[i] = 1;                         // 就地种下，供后面判断
      planted++;
      if (planted >= n) return true;     // 提前收敛
    }
  }
  return planted >= n;
}

console.log(canPlaceFlowers([1, 0, 0, 0, 1], 1));  // true
console.log(canPlaceFlowers([1, 0, 0, 0, 1], 2));  // false
console.log(canPlaceFlowers([0, 0, 1, 0, 0], 2));  // true
```

**复杂度**：时间 O(n)／空间 O(n)（拷贝数组；原地改则 O(1)）。

**易错点**：
- 忘了把已种的位置置 1，后面会重复利用同一块地。
- 边界判据必须带短路：`i === 0 || f[i - 1] === 0`。若只写 `f[i - 1] === 0`，`f[-1]` 是 `undefined`，`undefined === 0` 为 `false`，首元素永远种不上。
- 把"右邻居"写成 `f[i+1] !== 1`，`undefined !== 1` 为 true，边界上会侥幸通过，但语义是错的——用显式的 `i === len-1` 判断更稳。
- `n = 0` 应直接返回 true（循环里最后 `0 >= 0` 也成立，但要确保不会因空数组出错）。

**变体与追问**：
- 若花坛是环形的（首尾相接）：特判首尾不能同时种，分别假设"第一块种/不种"跑两遍。
- 若问"最多能种几朵"：去掉 `n`，返回 `planted`。
- 若允许间隔为 `k`（相邻 `k` 格内不能有花）：把邻居判断扩成窗口最大值。

### C-335 提莫攻击 · 简单 · 字节/美团

**题干**：在《英雄联盟》中，提莫的攻击会让敌人中毒。给定提莫攻击的时间序列 `timeSeries`（**非递减**）和中毒持续时间 `duration`，若提莫在 `t` 时刻攻击，敌人将在 `[t, t + duration - 1]` 处于中毒状态；若在中毒结束前再次攻击，中毒计时器会**重置**。求敌人处于中毒状态的总时间。

**示例**：`输入: timeSeries = [1,4], duration = 2` → `输出: 4`

**思路**：
- 最终中毒时间是若干区间的**并集长度**。由于 `timeSeries` 非递减，区间只可能"重叠"或"分离"。
- 对第 `i` 次攻击，它的有效贡献是 `min(duration, timeSeries[i+1] - timeSeries[i])`：若下次攻击来得晚（间隔 ≥ duration），本次完整贡献 `duration`；若来得早，本次只贡献到下次攻击开始那一刻，后面被重置覆盖。最后一次攻击贡献完整的 `duration`。
- **为什么这是贪心/正确**：区间按起点升序排列且起点就是攻击时间，因此并集长度 = 首区间起点到末区间终点的总跨度 − 被覆盖的部分，逐段累加 `min` 正好等于并集长度。等价于"每次只补贴被前一次覆盖之后新增的部分"，每个时间点只被计入一次，不重不漏。
- 换个角度：总时长 = 最后一次攻击时间 + duration − 第一次攻击时间 − 中间的所有"空档"，而 `min` 的写法自动处理了空档与重叠。

**代码**：
```javascript
/**
 * 提莫攻击：中毒区间求并集长度
 * @param {number[]} timeSeries 非递减的攻击时刻
 * @param {number} duration 单次中毒持续时长
 * @returns {number} 总中毒时间
 */
function findPoisonedDuration(timeSeries, duration) {
  const n = timeSeries.length;
  if (n === 0) return 0;
  let total = 0;
  for (let i = 0; i < n - 1; i++) {
    const gap = timeSeries[i + 1] - timeSeries[i];  // 两次攻击的间隔
    total += Math.min(gap, duration);               // 重叠则只算到下次攻击
  }
  total += duration;                                // 最后一次完整计入
  return total;
}

console.log(findPoisonedDuration([1, 4], 2));        // 4
console.log(findPoisonedDuration([1, 2], 2));        // 3
console.log(findPoisonedDuration([1, 2, 3, 4, 5], 5)); // 9
console.log(findPoisonedDuration([], 3));            // 0
```

**复杂度**：时间 O(n)／空间 O(1)。

**易错点**：
- 把最后一次也放进 `Math.min` 循环（访问 `timeSeries[n]` 得 `undefined`），结果是 `NaN`，非常隐蔽。
- 空数组必须返回 0，否则 `total += duration` 会凭空多算一次。
- 间隔恰好等于 `duration` 时既不算重叠也不算空档，`min` 取到 `duration`，正确；不能写成 `gap > duration` 的特判。
- 认为 `timeSeries` 有序就一定是严格递增：题目允许相等（同一时刻多次攻击），此时 `gap = 0`，贡献 0，逻辑仍成立。

**变体与追问**：
- 若攻击时刻无序：先排序，O(n log n)，思路不变。
- 若每次攻击的 `duration` 不同（数组形式）：仍按 `min(duration[i], gap)` 累加，最后一次加 `duration[n-1]`。
- 若求"中毒状态的总段数"（不重叠区间的个数）：用 C-325 的区间合并计数即可。

### C-336 最大交换 · 中等 · 腾讯/快手

**题干**：给定一个非负整数，你**至多**可以交换数字中的任意两位一次。返回你能得到的最大值。

**示例**：`输入: 2736` → `输出: 7236`；`输入: 9973` → `输出: 9973`（已最大，无需交换）

**思路**：
- 记录每个数字 `0~9` **最后出现**的下标。从左往右扫，对每一位尝试把 9 到 `a[i]+1` 的数字换到这一位（若该数字在后面出现过），一旦成功立刻返回。
- **为什么贪心成立（数位权重支配 + 交换论证）**：十进制数的字典序由高位决定，第 `i` 位差 1 相当于 `10^(len-1-i)`，而所有低位加起来最多 `10^(len-1-i) - 1`，所以**能提升最高位就一定优于提升任何低位**。因此从左往右找第一个"后面存在更大数字"的位置是必须的。
- 换入什么：要让结果最大，这一位换入的数字越大越好，所以从 9 往下试。若有多个相同的最大数字，选**最靠右**的那个——把更靠左的那个留在原位，能让后面的高位（相对更靠左）保持较大值。例如 `1993`，两个 9 分别在下标 1、2，选下标 2 的 9 换到下标 0 得 `9913`；若选下标 1 得 `9193`，更小。
- 一次交换足矣，交换两次不会更优（任何两次交换可分解为更多逆序，高位只会变差）。

**代码**：
```javascript
/**
 * 最大交换：从左找第一个可提升位，换入最靠右的最大数字
 * @param {number} num 非负整数
 * @returns {number} 至多交换一次后的最大值
 */
function maximumSwap(num) {
  const a = String(num).split('');
  const last = new Array(10).fill(-1);   // 每个数字最后出现的下标
  for (let i = 0; i < a.length; i++) last[Number(a[i])] = i;

  for (let i = 0; i < a.length; i++) {
    for (let d = 9; d > Number(a[i]); d--) {   // 从大到小找可换入的数字
      if (last[d] > i) {                        // 且必须出现在右侧
        const j = last[d];
        [a[i], a[j]] = [a[j], a[i]];            // 交换后立即返回
        return Number(a.join(''));
      }
    }
  }
  return num;                            // 本身已最大
}

console.log(maximumSwap(2736));   // 7236
console.log(maximumSwap(9973));   // 9973
console.log(maximumSwap(1993));   // 9913
console.log(maximumSwap(98368));  // 98863
```

**复杂度**：时间 O(len × 10) ≈ O(len)／空间 O(len)。

**易错点**：
- 记录"第一次出现"而不是"最后一次"，`1993` 会得到 `9193`，少 720。
- 内层循环方向写反（从 `a[i]+1` 到 9），会把较小数字换到高位。
- 找到更大的数字就立刻换，但没检查它是否在当前位右侧，可能把数字换小。
- `Number(a[i])` 用 `+a[i]` 也行，但别写成 `a[i]` 直接比较字符串，`'9' > '10'` 为真会出错。

**变体与追问**：
- 若允许交换**恰好** `k` 次：变成"字典序最大化的 k 次交换"，贪心要按位补足，且 `k` 次用不完时需要用重复数字消耗。
- 若允许任意重排：直接降序排列。
- 若要求"交换后能被 3 整除且最大"：在贪心基础上加整除约束。

### C-337 删除被覆盖区间 · 中等 · 阿里/字节

**题干**：给你一个区间列表 `intervals`，请你删除列表中被其他区间所覆盖的区间。区间 `[a, b)` 被区间 `[c, d)` 覆盖，当且仅当 `c <= a` 且 `b <= d`。对所有的区间执行完删除操作后，返回列表中剩余区间的数目。

**示例**：`输入: intervals = [[1,4],[3,6],[2,8]]` → `输出: 2`（`[3,6]` 被 `[2,8]` 覆盖）

**思路**：
- 排序：**左端点升序；左端点相同时右端点降序**。这样"可能覆盖当前区间的区间"一定排在前面。
- 维护 `end = 之前所有区间的最大右端点`。遍历时若 `r > end`，说明当前区间的右端点比之前所有区间都大，不可能被覆盖，`count++` 并更新 `end = r`；否则 `r <= end` 且 `l >= 之前某区间的左端点`，必然被覆盖，直接跳过。
- **为什么贪心成立（排序后单次扫描即完备）**：设当前区间 `I = [l, r]`。要覆盖它需要存在 `J = [l', r']` 满足 `l' <= l` 且 `r' >= r`。排序保证了所有已扫描区间的 `l' <= l`，所以只需判断"是否存在 `r' >= r`"，而这正是 `end` 的定义。因此判定是**充要**的，不会漏删也不会误删。
- 同左端点时右端点降序的原因：同 `l` 下右端点最大的那个区间能覆盖其余所有同左端点区间，先扫到它就能一次性把 `end` 提到最大，后面的同左端点区间被判为"被覆盖"，符合题意。

**代码**：
```javascript
/**
 * 删除被覆盖区间：按左升右降排序 + 维护最大右端点
 * @param {number[][]} intervals
 * @returns {number} 剩余区间数
 */
function removeCoveredIntervals(intervals) {
  // 左端点升序；左端点相同时右端点降序（大区间优先）
  intervals.sort((a, b) => (a[0] === b[0] ? b[1] - a[1] : a[0] - b[0]));
  let count = 0;          // 剩余区间数
  let end = -Infinity;    // 已扫描区间的最大右端点
  for (const [l, r] of intervals) {
    if (r > end) {        // 右端点突破历史最大值 → 不可能被覆盖
      count++;
      end = r;
    }
    // 否则 r <= end 且 l >= 某区间左端点 → 被覆盖，跳过
  }
  return count;
}

console.log(removeCoveredIntervals([[1, 4], [3, 6], [2, 8]]));   // 2
console.log(removeCoveredIntervals([[1, 4], [2, 3]]));          // 1
console.log(removeCoveredIntervals([[0, 10], [5, 12]]));        // 2
```

**复杂度**：时间 O(n log n)／空间 O(1)。

**易错点**：
- 同左端点时若按右端点**升序**排，`[[1,3],[1,4]]` 会先判 `[1,3]` 为剩余，`count` 多算 1；必须降序。
- `end` 初始值设为 0 而非 `-Infinity`，若区间含负数（`[-5,-1]`）会判错。
- 判定写成 `r >= end` 会把两个完全相同的区间也当作"未被覆盖"而重复计数；题意下相同的区间只留一个，必须用严格 `>`。
- 覆盖判定是"左端点更小或相等"且"右端点更大或相等"，别把两个条件弄反。

**变体与追问**：
- 若求"被删掉的区间个数"：`n - count`。
- 若改求"区间合并后的段数"（相交即合并）：见 C-325 的兄弟题 LC 56，判定条件换成 `l > end`。
- 若区间是开区间 `(a, b)`：端点相接不再算相交，边界判断从 `<=` 改 `<`。

### C-338 使数组和能被 P 整除 · 中等 · 字节

**题干**：给你一个正整数数组 `nums`，请你移除**最短**子数组（可以为空），使得剩余元素的和能被 `p` 整除。不允许将整个数组都移除。返回需要移除的最短子数组长度，如果无法完成请返回 `-1`。子数组定义为原数组中的一个连续子序列。

**示例**：`输入: nums = [3,1,4,2], p = 6` → `输出: 1`（移除 `[4]`，剩余和为 6）

**思路**：
- 设总和 `S`，令 `need = S mod p`。若 `need === 0`，不用删，返回 0。否则要删的子数组 `[i+1, j]` 必须满足"它的和 `mod p === need`"（这样剩下来才能被整除）。
- 用前缀和取模：`pre[j]` 表示前 `j` 个元素的和对 `p` 取模。子数组 `[i+1, j]` 的和取模 = `(pre[j] - pre[i]) mod p`。要求它等于 `need`，即 `pre[i] = (pre[j] - need) mod p`。
- **为什么存"最近一次"出现的位置**：固定右端点 `j` 时，左端点越靠右，子数组越短（长度 `j - i`），所以每遇到一个前缀模值都**覆盖写入**，让表里永远是最大下标。这是"贪心取最优匹配"的体现：对同一个 `j`，更靠右的 `i` 严格更优，保留更早的下标只会算出更长的答案，甚至漏解。
- 例：`nums = [6,3,5,2], p = 9` 时 `pre = [0,6,0,5,7]`，若只保留 `0` 第一次出现的 `-1`，会把整个数组当成候选（非法），答案退化成 `-1`；保留最新的 `1` 才能得到 `[5,2]` 这个长度 2 的解。
- `(x - need + p) % p` 处理负数取模（JS 的 `%` 对负数返回负值，这是 C++/Python 背景的人最常踩的坑）。

**代码**：
```javascript
/**
 * 使数组和能被 P 整除：前缀和取模 + 哈希表存最近下标
 * @param {number[]} nums
 * @param {number} p
 * @returns {number} 最短需移除子数组长度，-1 表示无解
 */
function minSubarray(nums, p) {
  let total = 0;
  for (const x of nums) total = (total + x) % p;
  const need = total % p;
  if (need === 0) return 0;              // 已经能整除

  const pos = new Map();                 // 模值 → 最近一次出现的下标
  pos.set(0, -1);                        // 空前缀，下标记作 -1
  let prefix = 0;
  let ans = nums.length;                 // 等价于"删整个数组"，最后要排除
  for (let j = 0; j < nums.length; j++) {
    prefix = (prefix + nums[j]) % p;
    const target = (prefix - need + p) % p;        // 需要的历史前缀模值
    if (pos.has(target)) {
      ans = Math.min(ans, j - pos.get(target));    // 子数组为 (i, j]
    }
    pos.set(prefix, j);                  // 关键：覆盖写入，保留最新下标
  }
  return ans < nums.length ? ans : -1;   // 不能删掉整个数组
}

console.log(minSubarray([3, 1, 4, 2], 6));          // 1
console.log(minSubarray([6, 3, 5, 2], 9));          // 2
console.log(minSubarray([1, 2, 3], 3));             // 0
```

**复杂度**：时间 O(n)／空间 O(min(n, p))。

**易错点**：
- `(prefix - need) % p` 在 JS 里可能是负数（如 `-3 % 6 = -3`），必须 `+ p` 再取模。
- 哈希表写成 `if (!pos.has(prefix))` 只保留最早下标，会算出更长的子数组甚至误判无解（见上面 `[6,3,5,2], p=9` 的例子）。
- `ans` 初值取 `nums.length`，最后必须用 `ans < nums.length` 过滤掉"删整个数组"这一非法方案。
- `total` 累加时就取模，避免 `1e5 × 1e9 = 1e14` 仍在安全整数内但习惯上应取模。

**变体与追问**：
- 若不限定"连续子数组"（可删任意元素）：变成子序列问题，贪心失效，需背包/枚举模值。
- 若要求"移除最长子数组"：贪心方向反转，改为找最靠右的左端点。
- 若同时求"移除方案"：哈希表存下标即可回溯出区间。

### C-339 构造字典序最大的合并字符串 · 中等 · 腾讯

**题干**：给你两个字符串 `word1` 和 `word2`。需要按下面方式构造字符串 `merge`：当 `word1` 或 `word2` 非空时，选择：

- 若 `word1` 非空，从 `word1` 中取出第一个字符加入 `merge` 末尾，并从 `word1` 中删除该字符。
- 若 `word2` 非空，从 `word2` 中取出第一个字符加入 `merge` 末尾，并从 `word2` 中删除该字符。

返回你能构造出的字典序最大的 `merge` 字符串。

**示例**：`输入: word1 = "cabaa", word2 = "bcaaa"` → `输出: "cbcabaaaaa"`

**思路**：
- 每一步都面临二选一：取 `word1` 的首字符还是 `word2` 的首字符。若首字符不同，显然取大的那个。若相同，则要比较**剩余后缀**的字典序，谁的后缀大就先取谁。
- **为什么贪心成立（反证 + 后缀比较）**：设 `word1[i:] > word2[j:]`。假设最优解此刻取了 `word2[j]`，那么 `merge` 以 `word2[j]` 开头；而取 `word1[i]` 的方案以 `word1[i]` 开头。由于 `word1[i:] > word2[j:]`，两者的首位关系决定了整体字典序：若 `word1[i] > word2[j]`，直接更大；若相等，则比较后缀，仍由 `word1[i+1:] > word2[j+1:]` 递归保证更大。故取 `word1[i]` 不劣，贪心正确。
- 直观：每一步都在"消耗"某一方的首位，只要保证当前前缀字典序最大，后续无论怎么取都不会逆转（字典序由首个不同位置决定），所以局部最优即全局最优。
- 实现上用 `slice` 比较后缀（长度最多 1e5 × 1e3，`slice` 比较是 O(n)，整体 O(n²)，对 3000 长度的数据足够；更大规模需后缀数组或 Z 函数）。

**代码**：
```javascript
/**
 * 字典序最大的合并：每次比较剩余后缀，取较大者首字符
 * @param {string} word1
 * @param {string} word2
 * @returns {string} 字典序最大的合并串
 */
function largestMerge(word1, word2) {
  let i = 0;
  let j = 0;
  const parts = [];
  while (i < word1.length && j < word2.length) {
    // 比较剩余后缀的字典序，谁大取谁的首字符
    if (word1.slice(i) > word2.slice(j)) {
      parts.push(word1[i++]);
    } else {
      parts.push(word2[j++]);
    }
  }
  parts.push(word1.slice(i));   // 一方耗尽后整段拼上
  parts.push(word2.slice(j));
  return parts.join('');
}

console.log(largestMerge("cabaa", "bcaaa"));  // cbcabaaaaa
console.log(largestMerge("abcabc", "abdcaba")); // abdcabcabcaba
console.log(largestMerge("a", "b"));            // ba
```

**复杂度**：时间 O((n + m) × min(n, m))（每步一次后缀比较）／空间 O(n + m)。

**易错点**：
- 只比较 `word1[i]` 与 `word2[j]` 两个字符，相等时随便取 → 本题第一大坑，`"cabaa"` / `"bcaaa"` 类数据必错。
- 用 `slice` 比较时忘了它会复制字符串，大规模数据下内存和时间都会爆；面试可主动提后缀数组优化。
- `parts.push` 后用 `join('')`，别用 `+=` 在循环里拼（V8 虽优化，但链表式拼接更稳）。
- 一方耗尽后直接拼接剩余部分即可，不需要继续逐字符比较。

**变体与追问**：
- 若要求 O(n log n)：用后缀数组 + 拼接串 `word1 + '$' + word2` 比较 `rank`。
- 若改成"字典序最小"：整个比较方向反转。
- 若三方合并（三个字符串）：仍是后缀比较，取最大后缀的首字符，多路归并。

### C-340 装包裹的最小浪费空间 · 困难 · 拼多多/字节

**题干**：给你 `n` 个包裹，第 `i` 个包裹的尺寸为 `packages[i]`。同时给你 `m` 个供应商，第 `j` 个供应商提供的所有箱子尺寸由 `boxes[j]` 给出（`boxes[j]` 是一个尺寸数组，每个尺寸都有无限个）。每个箱子**只能装一个包裹**，且箱子尺寸必须**大于等于**包裹尺寸。如果你选择使用第 `j` 个供应商提供的箱子，你必须**只使用这一家**。浪费空间 = 所有箱子尺寸之和 − 所有包裹尺寸之和。返回最小浪费空间，若无法装下所有包裹则返回 `-1`。

**示例**：`输入: packages = [2,3,5], boxes = [[4,8],[2,8]]` → `输出: 6`（用第一个供应商：`4+4+8 - 10 = 6`）

**思路**：
- 每个箱子只装一个包裹，所以问题解耦：**对每个包裹，选"能装下它的最小尺寸箱子"**，浪费最小，且箱子之间无容量竞争（无限供应），因此这个贪心是**全局最优且无需证明的**（每个包裹独立取 `min{s ≥ p}`）。
- 对单个供应商：把它的尺寸排序去重，包裹排序后，尺寸 `s` 负责"比上一个尺寸大、且 ≤ s"的那批包裹。用前缀和一次算出这批包裹总和，`浪费 = s × 个数 − 总和`。
- **为什么按尺寸升序分段（区间划分的正确性）**：尺寸升序后，`(prev, s]` 范围内的包裹只能由 `s` 或更大的箱子装；而更大的箱子只会更浪费，所以这批包裹必须由 `s` 装，划分唯一且最优。
- 多个供应商取 `min`。若某供应商最大箱子 < 最大包裹，该供应商直接不可用。

**代码**：
```javascript
/**
 * 装包裹的最小浪费空间：包裹排序 + 前缀和 + 按箱尺寸分段
 * @param {number[]} packages 包裹尺寸
 * @param {number[][]} boxes 每个供应商可用的箱子尺寸列表
 * @returns {number} 最小浪费空间，无解返回 -1
 */
function minWastedSpace(packages, boxes) {
  packages.sort((a, b) => a - b);
  const n = packages.length;
  const pre = new Array(n + 1).fill(0);
  for (let i = 0; i < n; i++) pre[i + 1] = pre[i] + packages[i];
  let ans = Infinity;
  for (const batch of boxes) {
    const sizes = batch.slice().sort((a, b) => a - b);
    if (sizes[sizes.length - 1] < packages[n - 1]) continue;  // 最大箱子装不下
    let waste = 0, done = 0;            // done：已装箱的包裹数
    for (const s of sizes) {
      if (done === n) break;            // 全部装完，提前退出
      let lo = done, hi = n;            // 二分：最后一个 <= s 的包裹
      while (lo < hi) {
        const mid = (lo + hi) >> 1;
        if (packages[mid] <= s) lo = mid + 1;
        else hi = mid;
      }
      if (lo > done) {                 // (done, lo] 这批包裹只能由 s 装
        waste += s * (lo - done) - (pre[lo] - pre[done]);
        done = lo;
      }
    }
    if (done === n) ans = Math.min(ans, waste);
  }
  return ans === Infinity ? -1 : ans;
}
console.log(minWastedSpace([2, 3, 5], [[4, 8], [2, 8]]));  // 6
console.log(minWastedSpace([2, 3, 5], [[1, 4]]));           // -1
```

**复杂度**：时间 O(n log n + Σ(m_j log m_j))（另有每个供应商 O(n log m_j) 的二分，同阶）／空间 O(n)。

**易错点**：
- 误以为箱子有容量上限、一个箱子能装多个包裹（想成装箱问题）。题目明确"每个箱子只能装一个包裹"，否则变成 NP-hard 的 bin packing。
- `waste` 用 `Number` 累加没问题（最大约 `1e5 × 1e9 = 1e14 < 2^53`），但若题目放宽到 `1e9` 个包裹就必须 `BigInt`。
- 忘记跳过"最大箱子仍小于最大包裹"的供应商，会在二分后 `done < n` 却没报错，最后被 `if (done === n)` 过滤掉，逻辑侥幸正确但白跑一轮。
- 前缀和数组长度是 `n + 1`，`pre[lo] - pre[done]` 中 `lo` 是**开区间右端**，差一个 1 是经典错位。
- 直接对 `batch` 原地 `sort` 会污染入参，力扣多组用例共享数据时会出错。

**变体与追问**：
- 若一个箱子可以装多个包裹（体积约束）：贪心失效，变成 bin packing（NP-hard），只能近似或小数据搜索。
- 若供应商有"起送量/固定成本"：变成带固定费用的选择问题，贪心需加成本维度。
- 若箱子尺寸只有有限个（有库存）：需排序后双指针匹配，贪心仍成立但要考虑库存耗尽。

---
