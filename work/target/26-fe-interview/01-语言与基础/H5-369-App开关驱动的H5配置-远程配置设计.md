## H5-369：App 开关驱动的 H5 配置：远程配置设计

**答**：
- 配置分级：静态编译期（构建注入）、远程下发（运营开关：功能开关/参数/灰度名单）、用户级（AB 实验分组）——三个来源的优先级与合并规则要在 SDK 里定死
- 获取时机：启动时同步拉取（阻塞可接受 <100ms，走离线缓存兜底）+ 推送通道热更新（开关变更实时生效，不用重启页面）
- 可靠性：远程配置失败必须有内置默认值兜底；配置 schema 校验（类型/范围），脏配置不能导致页面 crash——「配置即代码」要有测试
- 生效与回滚：开关变更有审计与一键回滚；高危开关（支付通道）变更需审批流程
- 与 Hybrid 联动：Native 与 H5 共用同一配置中心，App 版本约束（minAppVersion）在服务端过滤，H5 侧按容器版本分支执行

```javascript
const config = mergeDefaults({
  static: window.__BUILD_CONFIG__,      // 编译期
  remote: await fetchRemoteConfig(),     // 远程下发(带缓存兜底)
  user: window.__AB_FLAGS__,             // AB 分组
});
// schema 校验
function validate(cfg, schema) {
  for (const [k, t] of Object.entries(schema)) {
    if (typeof cfg[k] !== t) { report('bad-config', { k, got: typeof cfg[k] }); return false; }
  }
  return true;
}
if (validate(config, { payChannel: 'string', maxRetries: 'number' })) applyConfig(config);
```
