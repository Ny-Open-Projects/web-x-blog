## JS-377：消息队列应用：前端组件间解耦

**答**：
- 什么时候用消息队列：跨层级通信（深层组件 → 全局）、生命周期解耦（发送方不关心谁听）、事件溯源（消息留痕可重放）——父子通信用 props，兄弟近距用状态提升，全局横切才用总线
- 前端 MQ 模式：进程内总线（EventEmitter）+ 持久化队列（IndexedDB，离线消息）+ 重放（新订阅者补拉历史）——「新页面打开后能看到之前的事件」需要持久化与重放
- 消息设计：类型化消息（discriminated union）、schema 校验（脏消息不进系统）、版本兼容（新增字段不破坏旧订阅者）
- 背压与限流：广播型消息消费慢会堆积——每个订阅者独立队列（消费互不影响）或直接用快照（状态消息覆盖式，只有最新值有意义）
- 与状态管理的关系：状态消息（最新值有意义）用 store 订阅，事件消息（每次发生有意义）用总线——「状态与事件分离」是解耦的关键判断

```javascript
class ReplayableBus {
  #subs = new Map(); #history = new Map();   // event → 最近事件缓存(状态型)
  constructor(maxHistory = 50) { this.max = maxHistory; }
  emit(type, payload, { replay = false } = {}) {
    if (replay) {
      const h = this.#history.get(type) || [];
      h.push({ payload, t: Date.now() });
      this.#history.set(type, h.slice(-this.max));
    }
    this.#subs.get(type)?.forEach(fn => fn(payload));
  }
  subscribe(type, fn, { withHistory = false } = {}) {
    (this.#subs.get(type) ||= new Set()).add(fn);
    if (withHistory) this.#history.get(type)?.forEach(h => fn(h.payload)); // 新订阅补历史
    return () => this.#subs.get(type)?.delete(fn);
  }
}
```
