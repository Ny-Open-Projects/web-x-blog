## H5-341：移动端推送：H5 在 App 内外的推送困境与方案

**答**：
- 纯浏览器 H5：Web Push（VAPID + SW showNotification）在 iOS 16.4+/Android Chrome 可用，但要求「添加到主屏幕」且依赖用户授权率——国内厂商推送通道才是主流
- App 内 H5：推送由 Native 承担（厂商通道+自有长连接），H5 只负责「点击通知后落地页」与「页面内实时消息」
- 页面内实时：WebSocket/SSE 长连接接收消息，配合 Notification API 在前台弹通知；注意 H5 通知在 App 内 WebView 通常不生效，要走桥让 Native 弹
- 离线消息补拉：H5 无推送时用「打开时拉取增量」兜底（last_msg_id 游标），消息可靠性靠服务端存储不依赖推送
- 授权策略：通知授权率是核心指标——在「用户产生价值时刻」申请（如订阅了主播），不要首屏弹授权

```javascript
// 页面内实时消息 + 离线增量补拉
const es = new EventSource('/api/msg/stream?token=...');
es.onmessage = (e) => { render(JSON.parse(e.data)); saveLastMsgId(JSON.parse(e.data).id); };

async function syncMissed() {
  const last = await idb.get('lastMsgId') || 0;
  const missed = await api.get(`/api/msg/missed?after=${last}`);
  missed.forEach(render);                       // 打开页面先补拉
}
// 前台通知走桥(Hybrid)或 Notification API(浏览器)
if (Notification.permission === 'granted' && !isHybrid()) {
  new Notification('新消息', { body: msg.text, tag: msg.id }); // tag 防重复堆叠
}
```
