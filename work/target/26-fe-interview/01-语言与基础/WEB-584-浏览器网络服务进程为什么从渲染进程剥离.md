## WEB-584：网络服务进程：为什么网络栈要独立成进程

**答**：
- 网络栈（HTTP/缓存/DNS/socket）从渲染进程剥离成独立 network service 进程：① 安全（网络栈解析不可信网络数据，崩溃/漏洞不影响渲染）；② 共享（全浏览器一个 socket 池/缓存/连接复用）；③ 稳定（网络库崩溃不杀页面）
- 对前端的意义：不同 tab 请求共享同一 HTTP 缓存与连接池——h2/h3 连接复用是全浏览器维度而不是 tab 维度
- 网络进程与渲染进程通过 Mojo IPC 传输响应体，超大响应体（大文件下载/流式响应）会经过 IPC 通道，`ReadableStream` 直通（streaming 到 JS）能减少一次中间缓冲
- 崩溃自愈：network service 崩溃后自动重启，正在加载的请求失败，页面表现为「ERR_ 网络错误」，刷新恢复
- Service Worker 的 fetch 走渲染进程 SW → network service 两跳，SW 里 `respondWith` 直接透传 Response 可避免反序列化开销

```javascript
// SW 中透传 Response, 避免 body 反序列化副本
self.addEventListener('fetch', (e) => {
  e.respondWith(fetch(e.request)); // 直接透传原 Response
});
// 反例: await res.text() 再 new Response(text) 会多两次拷贝, 大响应显著变慢
```
