## WEB-592：浏览器扩展与页面：进程与执行环境的边界

**答**：
- 扩展由多部分组成：background/service worker（扩展进程/独立世界）、content script（注入页面渲染进程但运行在隔离世界）、扩展页面（独立 origin）
- content script 与页面 JS 同进程不同世界：共享 DOM 但不共享 JS 对象——页面脚本看不到 content script 变量，这就是 MV3 隔离世界的安全设计
- 通信链路：content script ↔ background 走扩展消息（跨世界 IPC），background ↔ 页面不能直接碰，需要 content script 中转或 externally_connectable
- Manifest V3 变化：background 换成 service worker（事件驱动、可被杀），意味着扩展也要做「冷启动恢复」——与 SW 站点同样的事件模型
- 性能与安全影响：content script 能碰 DOM，权限高的扩展是 XSS 之外的第二条注入路径；企业环境对扩展白名单管控的理由即在此

```javascript
// MV3 content script ↔ background
// content.js
chrome.runtime.sendMessage({ type: 'get-settings' }, (s) => applySettings(s));
// background (service worker)
chrome.runtime.onMessage.addListener((msg, sender, reply) => {
  if (msg.type === 'get-settings') { loadSettings().then(reply); return true; } // 异步需 return true
});
// 注意: background SW 可被随时终止, 设置要缓存到 chrome.storage
```
