## JS-318：笔试：串行异步任务队列

**题目**：实现 `SerialQueue`：add(task) 返回该任务的 Promise；任务按添加顺序串行执行（前一个 settle 才跑下一个）；失败不阻塞后续（可配置 stopOnError）；支持 clear 清空未执行任务。

**答**：
```javascript
class SerialQueue {
  #chain = Promise.resolve();   // 队尾 promise：新任务接在其后
  #pending = [];                // 未开始的任务（可 clear）

  add(task, { stopOnError = false } = {}) {
    return new Promise((resolve, reject) => {
      const entry = { task, resolve, reject, stopOnError };
      this.#pending.push(entry);
      this.#chain = this.#chain.then(() => this.#run(entry));
    });
  }
  async #run(entry) {
    const idx = this.#pending.indexOf(entry);
    if (idx === -1) return; // 已被 clear 移除
    this.#pending.splice(idx, 1);
    try {
      entry.resolve(await entry.task());
    } catch (e) {
      entry.reject(e);
      if (entry.stopOnError) throw e; // 抛出会污染链，需重置
    }
  }
  clear() {
    this.#pending.forEach(e => e.reject(new Error('cleared')));
    this.#pending = [];
  }
}

const q = new SerialQueue();
q.add(async () => { await sleep(100); return 1; }).then(console.log); // 1（100ms）
q.add(() => { throw new Error('x'); }).catch(console.error);          // 不阻塞下一个
q.add(() => 3).then(console.log);                                     // 3（120ms，紧随其后）
```

**评分点**：
- 「链式 then 排队」实现串行（#chain 接力）——核心模型
- 失败默认不阻塞（catch 吞掉链上错误）；stopOnError 需防链断裂
- clear 对未开始任务的 reject 与移除
- 顺序保证与并发为 0 的语义说明

## 变体与延伸（补充）

**变体与延伸**：

1. stopOnError 抛错为什么会让整个队列停摆？ → 抛出的 rejection 会污染 #chain，后续 then 全走 rejected 分支不再执行；需在链上 catch 后把 #chain 重置为 resolved。
2. clear 之后正在执行的任务会怎样？ → 已经开始的任务无法中断，只能 reject 未开始的；运行中的任务完成时仍会 settle 自己的 promise，run 里需判断是否已被移除。
3. 串行队列与 p-limit 这类并发池的区别？ → 串行是并发 1 且严格保序，适合有状态依赖的任务链；p-limit 是并发 N、完成顺序不定，只控总量不保证顺序。
