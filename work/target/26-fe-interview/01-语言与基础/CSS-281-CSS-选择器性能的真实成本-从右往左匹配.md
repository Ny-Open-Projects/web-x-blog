## CSS-281：CSS 选择器性能的真实成本：从右往左匹配

**答**：
- 浏览器匹配规则：先确定「候选元素」（最右选择器命中者），再向上验证祖先链——`div .item a` 中先找所有 a 再回溯
- 指导意义：最右选择器尽量具体（类/ID 而非 *）；祖先链越短越好——通配前缀（* html）代价高
- 现实校准：现代引擎样式计算极快，选择器写法性能差异通常微秒级——可读性优先，除非实测 Recalculate Style 热点
- 真正的性能大头：选择器「数量」（全站样式表规模）与「强制同步布局」——优化顺序是先减少样式总量
- 面试话术：先讲原理（从右往左），再主动校准「现代引擎下别过度优化」，判断力加分

```css
/* 避免：右侧太宽泛 + 深祖先链 */
div div div ul li a span { color: red; }
/* 推荐：类锚点 */
.nav-link { color: red; }
```
