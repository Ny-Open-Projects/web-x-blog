## H5-035：前端如何实现"复制到剪贴板"？
**答**：
- 首选异步 Clipboard API：`navigator.clipboard.writeText/readText`，需 HTTPS + 安全上下文，writeText 可在用户手势外由页面主动调用（部分浏览器仍要求手势）。
- 兜底：`document.execCommand('copy')` 已废弃但仍是最广的兼容方案，配合隐藏 textarea。
- `readText` 读取剪贴板权限控制更严，需要用户手势与权限授予。
- 复制成功要给 toast 反馈；富文本复制用 `clipboard.write` 传 ClipboardItem。

```javascript
// 复制工具函数：Clipboard API 优先，execCommand 兜底
async function copyText(text) {
  if (navigator.clipboard?.writeText) {
    try {
      await navigator.clipboard.writeText(text);
      return true;
    } catch (e) {
      // 权限被拒或环境不支持，走兜底
    }
  }
  // 兜底方案：隐藏 textarea + execCommand
  const ta = document.createElement('textarea');
  ta.value = text;
  ta.style.position = 'fixed';
  ta.style.opacity = '0';
  document.body.appendChild(ta);
  ta.select();
  const ok = document.execCommand('copy');
  ta.remove();
  return ok;
}

button.addEventListener('click', async () => {
  const ok = await copyText('https://example.com/invite/123');
  toast(ok ? '复制成功' : '复制失败，请手动复制');
});
```

**追问**：

1. 页面不在焦点（在 iframe 里或切了 tab）时 `writeText` 会怎样？ → 抛 `NotAllowedError`（Document is not focused），需要先让文档获得焦点，或退回到用户点击同步栈里的 execCommand。
2. execCommand 兜底在 iOS 上经常失败，原因是什么？ → iOS 要求 textarea 有值、用 `setSelectionRange` 建立选区，且必须在用户手势的同步调用栈内；`await` 之后再执行就已经失去手势上下文。
3. 要复制图片或带格式的富文本怎么办？ → 用 `clipboard.write([new ClipboardItem({...})])` 同时提供 `text/html` 与 `image/png`，但 Safari 支持的类型有限，失败要回落到纯文本。
