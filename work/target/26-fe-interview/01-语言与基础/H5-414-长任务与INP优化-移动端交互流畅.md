## H5-414：长任务与 INP 优化：移动端交互流畅性

**答**：
- INP 定义：用户交互（点击/键盘）到下一次视觉响应的延迟，取会话内最差值；移动端 P75 目标 <200ms，差交互通常来自「点击后同步执行的长任务」
- 长任务治理：PerformanceObserver longtask 监控 >50ms 任务；优化三板斧——切片（yield 到主线程 scheduler.yield/ setTimeout）、下放 Worker、延迟非关键更新（先视觉反馈后数据）
- 立即反馈原则：点击后第一帧必须有响应（按钮态/骨架），重逻辑异步跟进；「先乐观 UI 后确认」模式
- 事件处理器瘦身：handler 里只做状态分发，重计算交给异步；避免在 input/change 里做同步昂贵校验
- 移动端特有：触摸合成开销、滚动中的事件处理节流——交互期间停止非必要后台任务（visibility + isInteracting 标记）

```javascript
// 长任务监控 + 切片执行
new PerformanceObserver((l) => {
  for (const e of l.getEntries()) beacon({ longtask: e.duration, start: e.startTime });
}).observe({ type: 'longtask', buffered: true });

async function processList(items) {
  for (let i = 0; i < items.length; i++) {
    handle(items[i]);
    if (i % 100 === 0) await scheduler?.yield?.() ?? new Promise(r => setTimeout(r)); // 每100条让出主线程
  }
}
```
