## H5-348：移动端内存优化：大图与泄漏排查

**答**：
- 移动端内存红线：iOS WebView 数百 MB 就会被系统杀进程，大图是头号杀手——一张 4000×3000 解码后位图约 48MB，多张轮播图就超预算
- 图片内存策略：按显示尺寸缩放后解码（createImageBitmap resize / CDN 缩放）、超出视口的图及时 src 置空或对象 URL revoke、轮播只保留相邻 3 张解码位图
- 常见泄漏清单：未清理的定时器/监听器、闭包持有大对象、Video/Audio 未释放、ImageData/Canvas 未复用（每帧 new）、SW 缓存无上限
- 排查手段：Chrome DevTools Memory 快照对比（三快照法）、Allocation timeline 定位分配热点；真机用 Safari 远程调试 iOS、chrome://inspect 安卓
- 压测验证：模拟「反复进入退出页面 50 次」脚本（Puppeteer 控制真机/模拟器），观察堆增长曲线是否收敛

```javascript
// 图片内存受控加载
async function loadThumb(src, w, h) {
  const bmp = await createImageBitmap(await (await fetch(src)).blob(), {
    resizeWidth: w, resizeHeight: h, resizeQuality: 'low', // 解码即缩放, 省内存
  });
  return bmp; // 用完 bmp.close() 释放解码位图
}
// 对象 URL 泄漏防护
const url = URL.createObjectURL(blob);
img.onload = () => { URL.revokeObjectURL(url); };   // 用完必回收
```
