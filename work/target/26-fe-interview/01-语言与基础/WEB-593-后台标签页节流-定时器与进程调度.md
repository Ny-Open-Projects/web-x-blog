## WEB-593：后台标签页节流：定时器降级与进程调度

**答**：
- 后台 tab 的节流链条：rAF 直接暂停 → setTimeout/setInterval 最小间隔 1s → 链式（嵌套>5 层）定时器进一步降到 1 分钟级（intensive throttling）→ 久了整个 tab 被冻结/挂起
- 对前端的直接后果：后台轮询、心跳、倒计时全部漂移——任何依赖后台精确定时的设计都是错的，改用服务端时间戳校准
- 与多进程联动：后台 tab 先节流，内存压力下整进程挂起（状态保存），恢复时 JS 时间线跳变（Date.now 大幅前进）
- 正确姿势：后台任务的「续跑」用 Page Lifecycle API（freeze/resume 事件）+ 离开前台时的持久化；真正需要后台执行的工作放 SW/系统通知
- 音频/RTC 例外：播放音频、活跃 WebRTC 会话可豁免节流，这是「后台音乐不被冻结」的原因

```javascript
// 后台倒计时漂移修复: 用绝对时间而不是累加
let endAt = Date.now() + 90_000;
function tick() {
  const left = Math.max(0, endAt - Date.now());
  render(left);
  if (left > 0) setTimeout(tick, 1000); // 后台被节流也没关系, 恢复前台算的是绝对差值
}
tick();
document.addEventListener('resume', () => tick(), { once: true }); // Lifecycle API
```
