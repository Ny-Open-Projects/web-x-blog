## JS-218：正则的回溯灾难（catastrophic backtracking）

**答**：
- 机制：回溯 = 匹配失败后「退回上一步换个分支重试」；嵌套量词让分支数指数级增长——30 个字符可能要尝试百万次
- 高危模式：`(a+)+`、`(a|a)*`、`(.*a){20}`——「量词套量词」且内外都能匹配同一字符
- 触发条件：接近成功但最终失败的输入（中间态回溯最多）——「用户名带个感叹号」就能打崩服务
- 防御三招：改写为单层量词（`(a+)+` → `a+`）、改用等价但不共享字符的结构（如用否定字符类切分）、输入长度上限；注意 JS **没有**原子组 `(?>...)` 与占有量词 `a*+`（那是 PCRE/Java 语法），关不掉回溯，只能改写模式
- 检测：node --stack-size 下跑长输入计时；用 safe-regex 静态扫描

```javascript
// 灾难正则：输入 "aaaaaaaaaaaaaaaaaaaaaaaa!" 秒变分钟级
const evil = /^(a+)+$/;
const safe = /^a+$/;          // 等价改写：单层量词，回溯退化线性
// JS 没有原子组 (?>...) 和占有量词 a*+（PCRE/Java 才有），
// ES2024 的 v flag 是 unicodeSets，也不提供原子组——不存在"加个符号关掉回溯"的写法
// 保险丝：先限长度
function check(s) { return s.length <= 64 && safe.test(s); }
```
