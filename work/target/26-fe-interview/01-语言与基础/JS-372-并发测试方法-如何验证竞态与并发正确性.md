## JS-372：并发测试方法：如何验证竞态与并发正确性

**答**：
- 竞态测试核心：控制时序制造交错——fake timers 精确推进、手动 resolve 的 deferred（按任意顺序完成）、mock fetch 延迟参数化——「让旧请求后完成」复现竞态
- 输出顺序断言：Promise 执行顺序用事件记录数组断言（['a-start','b-start','a-end','b-end']）——比测结果更早发现时序回归
- 压力式验证：同一操作并发触发 N 次（rapid clicks / 输入连打），断言最终态与请求次数——去重/互斥逻辑的回归测试
- 属性测试（property-based）：fast-check 生成随机输入验证不变量（如「重试函数最终返回或抛特定错误」「缓存命中数 ≤ 调用数」）
- CI 中的现实约束：竞态测试会偶发失败（flaky）——失败重跑 + 关键竞态用确定性时序（fake timers 全控），线上再靠监控兜底

```javascript
// 竞态回归测试示例 (vitest)
it('旧响应不覆盖新结果', async () => {
  const d1 = deferred(), d2 = deferred();
  const fetchMock = vi.fn().mockReturnValueOnce(d1.p).mockReturnValueOnce(d2.p);
  const r1 = search('a', fetchMock);      // 第一次请求(慢)
  const r2 = search('ab', fetchMock);     // 第二次(快)
  d2.resolve(['ab']); d1.resolve(['a']);  // 旧的后到
  await Promise.all([r1, r2]);
  expect(renderedResults).toEqual(['ab']); // 断言最终渲染是新结果
});
```
