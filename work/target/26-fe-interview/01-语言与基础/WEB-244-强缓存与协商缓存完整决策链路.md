## WEB-244：强缓存与协商缓存的完整决策链路

**答**：
- 决策顺序：浏览器先查本地缓存副本 → 有强缓存（Cache-Control/Expires 未过期）→ 直接用，不发请求（200 from disk/memory cache）→ 过期则带 If-None-Match/If-Modified-Since 发协商请求 → 服务器比对 ETag/Last-Modified，未变回 304（只返回头），变了回 200 + 新资源。
- 强缓存优先级：Cache-Control > Expires（绝对时间受本地时钟影响）。
- 协商优先级：ETag/If-None-Match > Last-Modified/If-Modified-Since（ETag 解决秒级修改检测与内容不变但 mtime 变的问题）。
- 工程策略：带 hash 的静态文件 `max-age=31536000, immutable`；HTML 用 `no-cache`（每次协商）。
- 注意：磁盘缓存优先于 Service Worker 之下的 HTTP cache，SW 存在时的缓存行为要单独设计。

```http
# 响应头组合
# 静态资源（首次）
HTTP/1.1 200
Cache-Control: max-age=31536000, immutable
ETag: "abc123"
# 一年后过期，浏览器发协商请求
If-None-Match: "abc123"
# 内容没变
HTTP/1.1 304 Not Modified
```
