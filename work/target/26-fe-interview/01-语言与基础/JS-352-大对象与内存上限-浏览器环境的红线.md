## JS-352：大对象与内存上限：浏览器环境的红线

**答**：
- 上限差异：桌面 Chrome 单 tab 数 GB 级、iOS Safari/WKWebView 数百 MB 级（系统 jetsam）、Android WebView 由设备决定——「桌面跑得动」不等于移动端跑得动
- 大对象阈值：V8 中 >256KB 对象进大对象空间，字符串 >~256MB 直接抛 Invalid string length（实际 ~512MB 视平台）；数组上限 ~4G 元素（32 位索引）
- 超限表现：RangeError（数组/字符串分配失败）、直接页面崩溃（移动端 OOM 被系统杀，无 JS 错误）——移动端白屏崩溃常是内存而非 JS 异常
- 流式处理是唯一出路：大文件（CSV/日志）不能整读进内存——File.stream()/ReadableStream 分块 + 游标聚合；服务器数据分页拉取
- 预算思维：给单页设内存预算（如 <300MB），大图分片、列表虚拟化、及时 revoke objectURL——预算进 code review 意识

```javascript
// 大 CSV 流式处理
async function processCsv(file) {
  const reader = file.stream().pipeThrough(new TextDecoderStream());
  let header, count = 0;
  for await (const chunk of reader) {          // 逐块, 内存占用恒定
    for (const line of chunk.split('\n')) {
      if (!header) { header = line; continue; }
      handleRow(line); count++;
    }
  }
  return count;                                 // 不曾整读文件
}
```
