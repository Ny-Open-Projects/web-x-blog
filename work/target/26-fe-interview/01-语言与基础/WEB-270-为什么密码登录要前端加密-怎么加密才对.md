## WEB-270：为什么密码登录要前端加密？怎么加密才对？

**答**：
- HTTPS 下传输已加密，前端加密不是为了防网络窃听，而是防「日志/代理层明文落盘」——网关日志、错误上报、第三方统计里 accidentally 打印请求体时密码不裸奔。
- 错误做法：前端 MD5 一遍——彩虹表直接破；用固定 key 的 AES——key 在 JS 里等于明文。
- 正确姿势：服务端下发一次性 RSA 公钥（或 SRP 协议），前端用公钥加密密码原文，服务端私钥解密后再做慢哈希（bcrypt/argon2）加盐存储；配合验证码/风控防暴力破解。
- 底线认知：前端加密只能提高门槛，绝不能作为唯一防线；服务端存储必须慢哈希 + 唯一盐。

```javascript
// 服务端先发一次性公钥
const { pubKey } = await fetch('/auth/pubkey').then(r => r.json());
const enc = await crypto.subtle.encrypt(
  { name: 'RSA-OAEP' }, await importRsaKey(pubKey),
  new TextEncoder().encode(password));
await fetch('/auth/login', { method: 'POST',
  body: JSON.stringify({ user, password: btoa(String.fromCharCode(...new Uint8Array(enc))) }) });
// 服务端: RSA-OAEP 私钥解密 → bcrypt(cost=12) 存储
```
