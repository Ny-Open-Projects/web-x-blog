## WEB-569：笔试：手写网络切换与连接存活监控器

**答**：实现 `NetSwitchMonitor`：① 监听 Network Information API 的 `change` 事件记录每次网络切换（from→to）；② 切换后 500ms 内发起轻量探测（fetch HEAD /api/ping, no-store）验证业务链路存活；③ 探测成功/失败各上报一条事件（含切换前后网络类型、探测耗时）；④ 连续 3 次失败标记 `suspect-broken` 并触发回调 `onBroken`。防抖处理：1s 内多次 change 只处理最后一次。

```javascript
class NetSwitchMonitor {
  constructor({ probeUrl, onBroken }) {
    this.probeUrl = probeUrl;
    this.onBroken = onBroken;
    this.lastType = navigator.connection?.effectiveType || 'unknown';
    this.failStreak = 0;
    this.timer = null;
    navigator.connection?.addEventListener('change', () => this._schedule());
  }
  _schedule() {
    clearTimeout(this.timer);
    this.timer = setTimeout(() => this._check(), 1000); // 防抖 1s
  }
  async _check() {
    const to = navigator.connection?.effectiveType || 'unknown';
    const from = this.lastType;
    this.lastType = to;
    const t0 = performance.now();
    try {
      await fetch(this.probeUrl, { method: 'HEAD', cache: 'no-store' });
      this.failStreak = 0;
      this._report({ event: 'net-switch-ok', from, to, ms: performance.now() - t0 });
    } catch {
      this.failStreak++;
      this._report({ event: 'net-switch-fail', from, to, streak: this.failStreak });
      if (this.failStreak >= 3) this.onBroken?.({ from, to });
    }
  }
  _report(data) { navigator.sendBeacon('/api/mon/netswitch', JSON.stringify(data)); }
}
```

**评分点**：
- change 事件防抖（网络切换常触发连续事件），避免探测风暴
- 探测请求 no-store + HEAD，保证真实测到网络通路
- 失败连续计数与阈值回调，能驱动上层重连逻辑
- 上报携带 from/to 网络类型与耗时，支撑按网络类型分析迁移收益

## 变体与延伸（补充）

**变体与延伸**：

1. change 事件为什么必须防抖？ → 一次切换 effectiveType 可能连跳 4g→3g→2g，每条都探测会造成探测风暴，1s 防抖只保留最终稳定态。
2. Network Information API 的兼容性限制是什么？ → 仅 Chromium 系实现 navigator.connection，Safari 与 Firefox 没有，需特性检测后用 online/offline 事件兜底。
3. 探测成功是否等价于业务链路可用？ → 不等价，HEAD 200 只证明网络与 DNS 通，鉴权失效或后端 5xx 仍会失败，需结合业务接口成功率与错误码归因。
