## H5-371：移动端埋点 SDK 设计：采集、缓存与上报

**答**：
- 采集层：声明式埋点（data-track 属性 + 事件委托）覆盖 80% 场景，代码埋点 track() 补充关键业务事件；PV/停留/曝光（IntersectionObserver 曝光去重）自动采集
- 传输层设计三原则：批量（队列 + 定时/满量双触发）、可靠（pagehide 用 sendBeacon；失败落 IndexedDB 补传）、有损可控（队列上限丢弃策略 + 丢弃率上报）
- 移动端特有：后台节流期间暂停定时上报（用 visibility 感知）；桥场景走 Native 上报通道（更可靠，进程不死的通道）
- 时序与去重：事件带本地时间戳 + 序号，服务端按 seq 去重；曝光类事件带 slot 去重避免重复计费
- 采样与治理：全量埋点分级（P0 全量/P1 采样），SDK 支持动态采样率下发；埋点验收用「事件回放工具」抽查数据完整性

```javascript
class Tracker {
  constructor({ url, max = 200, flushMs = 15000 }) {
    this.q = []; this.max = max; this.seq = 0; this.dropped = 0;
    setInterval(() => this.flush(), flushMs);
    addEventListener('pagehide', () => this.flush(true));
    document.addEventListener('visibilitychange', () =>
      document.visibilityState === 'hidden' && this.flush(true));
  }
  track(evt) {
    if (this.q.length >= this.max) { this.dropped++; this.q.shift(); }
    this.q.push({ ...evt, t: Date.now(), seq: ++this.seq });
    if (this.q.length >= 20) this.flush();
  }
  flush(urgent) {
    if (!this.q.length) return;
    const batch = this.q.splice(0);
    urgent ? navigator.sendBeacon(this.url, JSON.stringify(batch))
           : fetch(this.url, { method: 'POST', body: JSON.stringify(batch), keepalive: true }).catch(() => idbAppend(batch));
  }
}
```

## 追问（补充）

**追问**：

1. pagehide 与 beforeunload 该用哪个？ → 优先 pagehide，它在移动端与 bfcache 进出时都会触发；beforeunload 在 iOS Safari 常不触发，不能作为唯一兜底。
2. 上报失败为什么落 IndexedDB 而不是 localStorage？ → IndexedDB 容量大且异步不阻塞主线程，localStorage 是同步写入会卡 UI、只有约 5MB，且无事务。
3. 后台定时器被节流导致上报延迟怎么补救？ → 监听 visibilitychange，页面回到前台立即补一次 flush，并靠 seq 连续性让服务端识别缺口主动索要。
