## WEB-355：发布上线后怎么让用户尽快用上新版本？缓存刷新预案怎么设计？
**答**：
- 常规链路：新 URL(hash) + HTML no-cache 已解决 95%；CDN 对 HTML 的缓存要么关要么配置主动 purge。
- 应急预案：检测版本接口（前端定时或 SW 更新时比对 buildId）→ 提示刷新 / SW 立即 skipWaiting+clients.claim 自动接管。
- 兜底：灰度期间监控"旧版本报错率"，出问题时可通过配置中心下发"强制刷新"标记，前端收到后 location.reload(true) 类方案+清 SW 缓存。

```javascript
// SW 更新自动接管
self.addEventListener('install', e => self.skipWaiting());
self.addEventListener('activate', e => e.waitUntil(clients.claim()));
// 页面检测新版本
setInterval(async () => {
  const v = await (await fetch('/version.json')).json();
  if (v.build !== BUILD_ID) registration.update();
}, 5 * 60 * 1000);
console.log('版本检测 + skipWaiting + 缓存版本化 = 刷新预案');
```
