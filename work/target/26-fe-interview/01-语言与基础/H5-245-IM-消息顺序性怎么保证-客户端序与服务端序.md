## H5-245：IM 消息顺序性怎么保证：客户端序与服务端序

**答**：
- 服务端序是权威：每条消息入会话时分配单调递增 seq，客户端渲染与同步都以 seq 为准——并发发送/多端同步全靠它
- 客户端序的问题：A、B 同时发消息，客户端时间戳可能乱序；「我先发的排在后面」用户体验差，所以显示顺序必须用服务端序
- 本地回显：发送瞬间先渲染「发送中」占位（本地临时 ID），ACK 后替换为正式消息（服务端 seq + ID），失败标红可重发——三态流转
- 断线续传：客户端记录每会话已收最大 seq，重连后带 seq 拉增量
- 拉推结合：推送可能丢（半开连接），定期（切前台、每小时）全量校对一次拉取

```javascript
function onNewMessage(msg) {
  if (msg.seq <= state.maxSeq[msg.conversationId]) return; // 去重
  state.maxSeq[msg.conversationId] = msg.seq;
  insertSorted(state.messages, msg); // 按 seq 有序插入
}
async function sendMessage(text) {
  const localId = crypto.randomUUID();
  render({ localId, status: 'sending', text });
  const { msgId, seq } = await sendAndAck({ text, localId });
  patchMessage(localId, { msgId, seq, status: 'sent' });
}
```
