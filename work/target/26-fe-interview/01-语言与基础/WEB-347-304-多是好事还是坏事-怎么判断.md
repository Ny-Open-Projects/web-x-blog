## WEB-347：304 多是好事还是坏事？怎么判断？
**答**：
- 对静态资源：304 多说明协商缓存生效，省流量；但每个 304 仍要一次完整往返，弱网下不如长 max-age 直接免请求。
- 对 HTML/接口：适度 304 合理；但对指纹文件出现大量 304 是配置错误（应该 immutable 免验证）。
- 判断维度：看 304 对象类型与 TTFB；指纹资源高 304 率 → 改成强缓存；接口高频轮询 → 考虑 ETag 精度或推送。

```javascript
const analyze = (reqs) => {
  const s304 = reqs.filter(r => r.status === 304);
  const bad = s304.filter(r => r.url.includes('.js') && /\[a-f0-9]{8}\]/.test(r.url));
  return bad.length ? '指纹文件走协商=配置错误' : '健康';
};
console.log(analyze([{ status: 304, url: '/app.9f2c1.js' }]));
```
