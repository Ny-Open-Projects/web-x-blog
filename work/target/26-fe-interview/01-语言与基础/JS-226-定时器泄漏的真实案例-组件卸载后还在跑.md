## JS-226：定时器泄漏的真实案例

**答**：
- 案例链路：组件内 setInterval 每 5s 拉数据 → 组件销毁但定时器没清 → 闭包持有组件 state 与回调 → 每 5s 触发已销毁组件的 setState → 内存涨 + 控制台报警告
- 为什么 GC 救不了：定时器回调被浏览器定时器队列持有，队列是根——整条闭包链永远可达
- 同族泄漏：addEventListener 没解绑、rAF 循环没停、Observer 没 disconnect、promise 里 setState
- 系统性防法：组件级「注册-清理」中心（useEffect 返回清理函数 / 自研 TimerManager）、封装 hook 强制成对
- 检测工具：Chrome Memory 快照对比 Detached DOM / 定时器数量；开发期监听 unmount 时 report 未清理项

```javascript
useEffect(() => {
  const t = setInterval(refresh, 5000);
  return () => clearInterval(t); // 必须成对——漏这行就是泄漏
}, []);
```
