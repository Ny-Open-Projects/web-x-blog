## JS-360：轮询调度深水：自适应间隔与增量拉取

**答**：
- 自适应轮询：间隔随「数据变化频率」调整——变化密集期缩短（3s）、平静期拉长（30s），用滑动窗口统计变化率驱动间隔；比固定间隔省 80% 请求
- 增量拉取：游标（lastId/updated_since）替代全量——服务端支持游标是前提；不支持时用 ETag/If-None-Match 让 304 免 payload
- 页面状态联动：前台 3s、后台 60s（H5-406 已有）——加上「网络档位」三态联动；指数退避在连续失败时兜底
- 抖动（jitter）：多客户端同时轮询会同步冲击服务端——启动时间随机偏移（±20%）打散
- 终止与让位：有 WebSocket/SSE 可用后轮询只做兜底（长连接断开期间）；两者互斥切换要有状态机

```javascript
class AdaptivePoller {
  constructor(fetcher, { min = 3000, max = 30_000 } = {}) {
    this.fetcher = fetcher; this.min = min; this.max = max;
    this.changes = [];           // 近10次变化记录
    this.cursor = null;
    this.timer = null;
  }
  async tick() {
    const { items, changed } = await this.fetcher(this.cursor);   // 增量
    if (changed) { this.cursor = items.at(-1)?.id; this.changes.push(Date.now()); }
    this.changes = this.changes.filter(t => Date.now() - t < 60_000);
    const rate = this.changes.length / 60;                        // 次/秒
    const interval = rate > 0.2 ? this.min : this.min + (this.max - this.min) * (1 - Math.min(rate / 0.2, 1));
    this.timer = setTimeout(() => this.tick(), interval * (0.9 + Math.random() * 0.2)); // jitter
  }
  start() { this.tick(); }
  stop() { clearTimeout(this.timer); }
}
```
