## JS-343：防抖节流深水：语义差异与边界场景

**答**：
- 语义精确化：debounce（最后一次事件后 N ms 执行，连续事件不断顺延）有 leading/trailing 选项；throttle（保证每 N ms 最多一次，leading+trailing 组合）——「立即执行首尾、丢弃中间」是常见需求组合
- 边界场景一：debounce 等待中组件卸载/页面隐藏 → timer 要可取消（返回 cancel/flush 方法）——flush 立即执行挂起调用（pagehide 前必须 flush 埋点）
- 边界场景二：throttle 的尾调用（trailing）保证「最后一次事件不丢」——搜索输入停止后必须补一次执行，leading-only 会丢最后输入
- 现代替代视角：rAF 合帧替代高频 throttle（滚动）；scheduler.postTask 优先级调度替代粗粒度节流——知道何时不用防抖节流比会写更重要
- 测试要点：用 vi.useFakeTimers 验证 leading/trailing/flush/cancel 四种行为——手写题考察完整 API 面

```javascript
function debounce(fn, ms, { leading = false } = {}) {
  let t = null, canLead = true;
  const wrapped = (...args) => {
    if (leading && canLead) { fn(...args); canLead = false; }
    clearTimeout(t);
    t = setTimeout(() => { fn(...args); canLead = true; }, ms);
  };
  wrapped.cancel = () => clearTimeout(t);
  wrapped.flush = (...args) => { clearTimeout(t); fn(...args); canLead = true; };
  return wrapped;
}
// 页面隐藏时 flush 埋点
addEventListener('pagehide', () => track.flush());
```
