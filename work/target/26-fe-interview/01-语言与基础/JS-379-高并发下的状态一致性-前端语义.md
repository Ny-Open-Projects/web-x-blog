## JS-379：高并发下的状态一致性：前端语义

**答**：
- 前端一致性问题清单：乐观更新交错、轮询与推送并发到达、多请求乱序返回、缓存与真实态漂移——共同本质是「多个异步源写同一状态」
- 版本号方案：状态带 version/revision，写操作带预期版本（CAS），版本不符拒绝（提示刷新）——适合编辑器/表单类；配合服务端 If-Match
- 时间线仲裁：请求带发起时间戳/序号，状态更新只接受「最新时间线」的写入——解决乱序返回；实现要「单调递增判定」而不是简单覆盖
- 单一写入源：能收敛的收敛——所有写操作过统一的 store.dispatch（串行队列），绕过直接 setState——「一个口子写入」比「到处修补一致」更可维护
- 与服务端协同：最终一致靠服务端（前端缓存只是视图），前端一致性策略的目标是「不展示错误状态 + 不发起错误请求」——认清边界，别追求分布式共识

```javascript
// 时间线仲裁 store
function createStore(initial) {
  let state = initial, timeline = 0;
  return {
    get: () => state,
    apply(data, fromTimeline) {
      if (fromTimeline < timeline) return false;      // 旧时间线丢弃
      timeline = fromTimeline ?? ++timeline;
      state = data; return true;
    },
    nextTimeline() { return ++timeline; },            // 本地乐观更新占用新时间线
  };
}
// 请求响应带 timeline 标记, 过期响应自动失效
```
