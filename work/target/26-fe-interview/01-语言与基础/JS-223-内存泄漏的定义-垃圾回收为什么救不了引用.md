## JS-223：内存泄漏的定义：垃圾回收为什么救不了引用

**答**：
- GC 的判定标准是「可达性」：从根（全局、调用栈）出发沿引用链能到达的对象不会被回收
- 泄漏的本质：对象已经「逻辑上无用」，但仍有引用链连到根——GC 认为它可达，不会回收；引用不清，回收不至
- 常见漏点：全局变量累积、被闭包捕获的大对象、挂在已销毁组件上的定时器/监听器、Map 键持有 DOM
- 判断泄漏标准：不是「内存占用大」（那是使用量大），而是「操作重复执行、内存阶梯式只涨不跌」
- 面试话术：GC 管可达不管有用——「有用与可达的差集」就是泄漏

```javascript
let cache = []; // 挂在全局：永远可达
function handle(item) {
  cache.push(item);           // 只进不出 = 泄漏
  // 修复：LRU/上限清理，或 WeakMap 存键引用
}
```
