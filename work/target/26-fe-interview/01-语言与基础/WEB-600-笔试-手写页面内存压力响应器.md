## WEB-600：笔试：手写页面内存压力响应器

**答**：实现 `MemoryGuard`：① 定时采样 `performance.memory`（usedJSHeapSize），计算 1 分钟滑动均值；② 均值超过 `highWater`（如 350MB）或增幅 30s 内超 50% 时进入 pressure 状态，触发注册的回调列表（按优先级执行：先清缓存、再缩列表、最后放弃草稿）；③ 释放后均值回落到 lowWater 以下退出 pressure（迟滞区间防抖）；④ iOS/无 performance.memory 环境降级为「visibilitychange 时主动执行一级回调」。写出核心实现。

```javascript
class MemoryGuard {
  constructor({ highWater, lowWater, intervalMs = 10_000 } = {}) {
    this.high = highWater ?? 350 * 1024 * 1024;
    this.low = lowWater ?? 250 * 1024 * 1024;
    this.inPressure = false;
    this.hist = [];           // { ts, heap }
    this.hooks = [];          // [{ fn, priority }]
    if (performance.memory) setInterval(() => this._sample(), intervalMs);
    else document.addEventListener('visibilitychange', () => {
      if (document.visibilityState === 'hidden') this.hooks[0]?.fn('lowmem-env');
    });
  }
  on(fn, priority = 0) { this.hooks.push({ fn, priority }); this.hooks.sort((a, b) => a.priority - b.priority); }
  _sample() {
    const now = Date.now(), heap = performance.memory.usedJSHeapSize;
    this.hist.push({ ts: now, heap });
    while (this.hist.length && now - this.hist[0].ts > 60_000) this.hist.shift();
    const avg = this.hist.reduce((s, x) => s + x.heap, 0) / this.hist.length;
    const spike = this.hist.length > 1 && heap - this.hist[0].heap > this.hist[0].heap * 0.5
      && now - this.hist[0].ts < 30_000;
    if (!this.inPressure && (avg > this.high || spike)) {
      this.inPressure = true;
      for (const h of this.hooks) h.fn('pressure');
    } else if (this.inPressure && avg < this.low) {
      this.inPressure = false; // 迟滞退出
    }
  }
}
```

**评分点**：
- 滑动均值 + 双水位迟滞（high 触发/low 退出）防抖
- 增速检测（30s 内 +50%）能抓「快速泄漏」场景
- 回调按优先级有序执行（先轻后重）
- 无 performance.memory 环境（iOS/火狐）有降级路径

## 变体与延伸（补充）

**变体与延伸**：

1. performance.memory 为什么只有 Chromium 能用？ → 非标准 API 且暴露堆信息存在指纹风险，Safari 与 Firefox 未实现，只能改用 measureUserAgentSpecificMemory 或走降级路径。
2. 为什么要 high/low 双水位迟滞而不是单阈值？ → 单阈值在临界点会反复进入退出 pressure，导致清理回调被高频重复触发，迟滞区间让状态切换稳定。
3. 回调按优先级执行有什么隐患？ → 清理动作本身也分配内存，缩列表这类重操作可能加剧卡顿，需异步分批执行并在每步后重新采样决定是否继续。
