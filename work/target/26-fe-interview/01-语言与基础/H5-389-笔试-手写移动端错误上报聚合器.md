## H5-389：笔试：手写移动端错误聚合上报器

**答**：实现 `ErrorAggregator`：① 收集 js/resource/promise/bridge 四类错误，按 fingerprint 聚合（同 fingerprint 计数、只保留首条 stack）；② fingerprint 规则：js/promise 用「文件名 + 行号附近函数名」hash，resource 用域名+类型，bridge 用 module.action；③ 现场信息：最近 20 条用户行为轨迹（注册的 action log），错误时附带；④ 上报节流：同 fingerprint 1 分钟内只上报一次（计数后续补报），队列满 50 丢弃计数；⑤ release 版本号注入。写出核心实现。

```javascript
class ErrorAggregator {
  constructor(release, actionLog) {
    this.release = release; this.log = actionLog;   // 行为轨迹数组(≤20)
    this.map = new Map(); this.lastSent = new Map();
  }
  capture(type, data) {
    const fp = this._fp(type, data);
    const item = this.map.get(fp) || { type, fp, count: 0, first: data, ts: Date.now() };
    item.count++;
    this.map.set(fp, item);
    if (Date.now() - (this.lastSent.get(fp) || 0) > 60_000) {
      this.lastSent.set(fp, Date.now());
      this._send(item);
    }
  }
  _fp(type, { msg, stack, src, module, action }) {
    let key;
    if (type === 'js' || type === 'promise') {
      const m = (stack || '').match(/(?:https?:\/\/[^)\s]+\/)([^)\s]+):(\d+):\d+/);
      key = m ? `${m[1]}:${m[2]}` : (msg || 'unknown').slice(0, 80);
    } else if (type === 'resource') {
      key = new URL(src, location.href).host + ':' + type;
    } else key = `${module}.${action}`;
    return `${type}|${key}`;
  }
  _send(item) {
    const payload = {
      release: this.release, type: item.type, fp: item.fp, count: item.count,
      stack: item.first.stack?.slice(0, 2000), trail: this.log.slice(-20),
      ua: navigator.userAgent, t: Date.now(),
    };
    navigator.sendBeacon('/api/mon/error', JSON.stringify(payload));
  }
}
```

**评分点**：
- 四类错误统一入口 + 分类 fingerprint 规则明确
- 同 fingerprint 节流（1 分钟）+ 计数补报语义
- 行为轨迹附带（≤20 条）定位复现路径
- stack 截断与 release 版本注入，防上报体过大

## 变体与延伸（补充）

**变体与延伸**：

1. fingerprint 用「文件名+行号」有什么缺陷？ → 构建压缩后行号漂移、hash 文件名随版本变化，跨版本永远聚不到一起，应先 sourcemap 还原或改用函数名加消息归一化。
2. 为什么同一 fingerprint 只保留首条 stack？ → 聚合目的是计数降噪，首条 stack 已足够定位，全量堆栈会让上报体膨胀甚至超过 sendBeacon 的 64KB 限制。
3. 节流窗口内的计数怎么补报？ → count 持续累加在 map 里，下个窗口打开时把累计 count 一起带上，实现「首次即时、后续合并」的上报语义。
