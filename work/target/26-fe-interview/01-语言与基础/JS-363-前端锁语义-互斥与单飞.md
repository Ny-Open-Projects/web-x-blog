## JS-363：前端锁语义：互斥、单飞与租约

**答**：
- 单线程里的「锁」是逻辑锁：防的不是线程竞争而是「重复触发」——互斥锁（Mutex：异步任务执行期间拒绝重入）、单飞（singleflight：重入者共享首次结果）
- Mutex 实现：Promise 链队列——`this.queue = this.queue.then(run)` 串行化；支持可重入（同 key 递归调用直接复用）与超时释放（防死锁：任务悬挂时锁永不释放）
- 租约（lease）：锁带 TTL——前端场景「刷新 token 的锁」：拿到锁的页面刷新 token，其他页面等待广播结果；锁持有者崩溃（页面关闭）时 TTL 过期自动放行
- 跨 tab 锁：Web Locks API（navigator.locks）——浏览器原生跨标签互斥，PWA/多 tab 场景的正解；降级 localStorage 竞争（写入测试）但不可靠
- 使用原则：锁是「最后手段」——能用 in-flight 合并（共享结果）就不用互斥（排队等待）；单飞优于互斥

```javascript
// 互斥 + 超时释放
class Mutex {
  #tail = Promise.resolve();
  async run(fn, { timeout = 30_000 } = {}) {
    const release = this.#withTimeout(timeout);
    return this.#tail = this.#tail.then(fn).finally(release);
  }
  #withTimeout(ms) {
    let released = false;
    const t = setTimeout(() => { if (!released) released = true; }, ms); // 超时兜底放行
    return () => { clearTimeout(t); released = true; };
  }
}
const tokenMutex = new Mutex();
async function refreshToken() {
  return tokenMutex.run(async () => {
    if (Date.now() - lastRefresh < 60_000) return cachedToken; // 双检
    return cachedToken = await api.refresh();
  }, { timeout: 10_000 });
}
// 跨 tab: await navigator.locks.request('token', async () => { ... });
```

## 追问（补充）

**追问**：

1. 单线程的前端为什么还需要互斥锁？ → 防的不是线程竞争而是异步任务重复触发，比如两个组件同时发现 token 过期而并发刷新，逻辑锁把第二次调用串行化。
2. 单飞与互斥的本质区别在哪？ → 互斥让后来者排队各自执行，单飞让后来者直接共享首次结果；能用单飞就不用互斥，省一次请求也省等待。
3. navigator.locks 在页面崩溃时锁怎么释放？ → 锁绑定在 document 生命周期上，页面关闭或崩溃由浏览器自动释放，不需要应用层 TTL 兜底。
