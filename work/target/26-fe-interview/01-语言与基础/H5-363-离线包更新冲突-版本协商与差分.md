## H5-363：离线包更新冲突：版本协商与差分更新

**答**：
- 版本协商协议：客户端上报当前包版本 → 服务端返回「目标版本 + 差分包（base→target）或全量包」→ 客户端校验后应用；多版本差分链（v1→v3 缺 v2 中间包）要走「就近差分」策略
- 冲突场景一：下载完成但版本已更新（连续发版）——应用前校验目标版本仍是最新，否则丢弃重下；版本记录原子写入
- 冲突场景二：H5 页面在线上发版瞬间，离线包 HTML 引用的线上 JS/CSS hash 失配——发布平台要「离线包版本与线上资源同步发布」，HTML 入口校验资源可用性
- 差分实现：文件级 diff（bsdiff/zsync）或分块 hash（rsync 语义），移动网络下增量通常 <10% 全量
- 灰度与回滚：按用户百分比放量，异常（包内页面 crash 率）自动暂停放量并回滚到上一版本清单

```javascript
async function applyUpdate(curVer) {
  const plan = await api.get(`/offline/plan?cur=${curVer}`); // { target, patchUrl, fullUrl, md5 }
  const isFull = !plan.patchCompatible.includes(curVer);
  const data = isFull ? await download(plan.fullUrl) : await applyPatch(plan.patchUrl);
  if (md5(data) !== plan.md5) return retry();          // 校验失败重下
  const stillLatest = await api.get(`/offline/latest`);
  if (stillLatest.target !== plan.target) return applyUpdate(curVer); // 版本已变, 重走
  await atomicInstall(data, plan.target);               // 原子切换版本记录
}
```
