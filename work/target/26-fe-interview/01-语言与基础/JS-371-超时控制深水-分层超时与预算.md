## JS-371：超时控制深水：分层超时与预算

**答**：
- 分层超时模型：单请求超时（快速失败）→ 关键路径预算（首屏整链 deadline）→ 全局 deadline（页面会话）——上层超时不等于下层都加时，「预算分配」才是正确抽象
- AbortSignal.timeout 与手写 race：timeout 信号只取消请求本身；「业务超时」（拿到响应但渲染超预算）要用 race 检测——两类超时语义不同
- 超时后的策略分级：关键路径超时 → 降级渲染（缓存/骨架）；非关键 → 静默丢弃；可重试 → 立即重试一次（不是所有超时都重试，重试会放大延迟）
- 与重试的预算耦合：总预算 3s 内做 2 次重试——每次超时要「剩余预算感知」（第一次 1s 失败剩 2s，重试超时设 1.5s 而不是重来 3s）
- 实现纪律：超时常量集中配置（按接口分级），禁止散落魔法数；超时事件埋点（区分网络慢还是服务慢）

```javascript
async function withBudget(tasks, totalBudget) {
  const start = performance.now();
  const results = {};
  for (const [name, task] of Object.entries(tasks)) {
    const remain = totalBudget - (performance.now() - start);
    if (remain <= 0) { results[name] = { timeout: true }; continue; }   // 预算耗尽
    results[name] = await Promise.race([
      task().then(v => ({ v })),
      new Promise(r => setTimeout(() => r({ timeout: true }), remain)), // 剩余预算感知
    ]);
  }
  return results;
}
// 用法: 首屏接口组共享 3s 预算, 先到先得
```
