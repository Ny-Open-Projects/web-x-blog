## WEB-263：前端灰度发布有哪些实现方式？

**答**：
- 按用户分流：登录态 UID 取模/白名单，后端在返回 HTML 或配置接口时决定版本。
- 按流量百分比：CDN/网关层按请求 hash 随机分桶，A/B 两套静态资源目录。
- 按维度：地域（分机房）、渠道（App 内 WebView 传 channel）、设备（UA/OS 版本）。
- 配置驱动：版本号下发在配置中心，前端启动时拉配置决定加载哪个 bundle（最灵活，支持热切换）。
- 观测与决策：灰度组与对照组的报错率/核心指标对比，达标后逐步放量；一键回滚 = 切回旧版本配置。

```javascript
// 配置驱动灰度
const cfg = await fetch('/config', { credentials: 'include' }).then(r => r.json());
const bucket = hash(userId) % 100 < cfg.newVersionPercent ? 'v2' : 'v1';
import(`/assets/${bucket}/app.js`);  // 动态加载对应版本
// 回滚只需后台把 newVersionPercent 调回 0
```
