## JS-364：幂等键设计：客户端如何防重复提交

**答**：
- 重复提交三来源：用户双击/网络重试/离线重放——按钮 loading 只防第一种，幂等键是唯一完备方案（服务端按键去重）
- 键生成策略：业务自然键（订单号/消息 ID）> UUID（crypto.randomUUID）> 内容哈希（相同内容视为同操作）——自然键最稳，UUID 兜底
- 键生命周期：与「操作意图」绑定而不是请求绑定——用户明确重试同一操作复用同键（服务端返回首次结果），新建操作换新键；本地 pending 表记录键与状态
- 请求层封装：fetch 包装自动注入 Idempotency-Key 头 + 本地去重缓存（键 → 响应，TTL 5min）——重试与重放透明化
- 体验配合：提交后按钮禁用 + 结果可查（订单详情），幂等冲突（409 已存在）引导查看而不是报错

```javascript
const keyCache = new Map();   // 幂等键 → 响应缓存

async function idempotentPost(url, body) {
  const key = body.orderId ?? crypto.randomUUID();       // 自然键优先
  const hit = keyCache.get(key);
  if (hit) return hit;
  const res = await fetch(url, {
    method: 'POST',
    headers: { 'Idempotency-Key': key, 'Content-Type': 'application/json' },
    body: JSON.stringify({ ...body, idempotencyKey: key }),
  });
  if (res.status === 409) {          // 已存在: 取回原结果
    const origin = await fetch(`${url}/${key}`);
    return origin.json();
  }
  const data = await res.json();
  keyCache.set(key, data);
  setTimeout(() => keyCache.delete(key), 5 * 60_000);
  return data;
}
```
