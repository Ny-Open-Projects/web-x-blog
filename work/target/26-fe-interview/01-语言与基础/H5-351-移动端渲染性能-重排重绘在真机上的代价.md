## H5-351：移动端渲染性能：重排重绘在真机上的代价

**答**：
- 移动端 CPU/GPU 弱于桌面一个量级：桌面无感的重排（如批量改样式触发布局）在中低端安卓是掉帧主因——优化以「少 layout」为纲
- Layout/Composite 属性清单：改 transform/opacity 只走合成；改 width/margin/font-size 触发 layout；改 color/background 触发 paint——写样式前先问落在哪条管线
- 批量读写分离：循环里交替读 offsetTop/写 style 会强制同步 layout（layout thrashing）；FastDOM 类方案或先读后写分两轮
- 合成层管理：will-change/3d transform 提层有收益也有内存代价，层爆炸（数百层）反而慢——用 Layers 面板查层数与内存
- 真机验证：桌面 DevTools 模拟不可信，中低端安卓真机 + Performance 面板录 trace，看 scripting/rendering/painting 三段占比

```javascript
// 反例: layout thrashing
els.forEach(el => { el.style.height = el.offsetHeight + 10 + 'px'; }); // 每次读写交替

// 正解: 先批量读, 后批量写
const heights = els.map(el => el.offsetHeight);     // 读
els.forEach((el, i) => { el.style.height = heights[i] + 10 + 'px'; }); // 写
// 滚动场景: 布局读放 rAF 首步, 写放同帧后续, 保证一帧最多一次 layout
```
