## WEB-530：静态资源 404 的排查 SOP（发布窗口）

**答**：
- 典型事故：发布瞬间旧 HTML 引用的旧 chunk 被删，或新 HTML 先于资源上传（HTML 与资源不同步）——用户恰在窗口期访问即白屏
- 排查顺序：404 资源的 referer（来自旧 HTML 还是新 HTML）→ 对比发布时间轴 → 确认删除策略与缓存头
- 根治一：资源目录只增不删（保留 N 个历史版本），异步清理任务在发布 24h 后执行
- 根治二：HTML 与资源原子发布（先传资源、校验齐全、再切 HTML）；CDN 缓存 HTML 短 TTL 或不缓存
- 运行时兜底：chunk 加载失败时 reload 一次（带防循环），触发拉取新 HTML

```javascript
window.addEventListener('error', (e) => {
  if (/Loading chunk \d+ failed/.test(e.message) && !sessionStorage.getItem('chunkReloaded')) {
    sessionStorage.setItem('chunkReloaded', '1');
    location.reload(); // 旧 chunk 404 的运行时兜底
  }
}, true);
```
