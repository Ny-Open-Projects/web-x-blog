## H5-330：移动端触摸事件体系：点透与延迟的经典问题

**答**：
- 300ms 延迟根源：浏览器等待双击缩放判定；现代浏览器 viewport meta `width=device-width` 或 touch-action: manipulation 后即消除，老内核需 FastClick 类方案
- 点透机制：touchstart 触发上层元素消失（如关闭弹层），随后浏览器补发的 click 落到下层元素触发误操作——根因是 touch 与 click 两套事件混用
- 解决规范：统一只用 click（现代内核延迟已消）；或统一只用 touch 体系（touchstart/touchend）并 preventDefault 阻止合成 click；遮罩层用 touchend 延迟 300ms 销毁是旧内核兜底
- 事件流差异：touch 系列有 targetTouches/touches 多点信息、passive 默认行为（touchmove 监听默认 passive 不可 preventDefault，要显式声明）
- 手势库自建要点：swipe 判定（位移阈值 + 时长）、长按（定时器 + move 取消）、双击（两次 tap 间隔阈值），这些在移动端面试常考

```javascript
// 点透防御: 遮罩销毁用 touchend + 延迟, 或统一 click
overlay.addEventListener('touchend', (e) => {
  e.preventDefault();               // 阻止合成 click, 防点透
  requestAnimationFrame(() => overlay.remove());
}, { passive: false });

// swipe 手势判定
let sx, sy, st;
el.addEventListener('touchstart', (e) => { const t = e.touches[0]; sx = t.clientX; sy = t.clientY; st = Date.now(); }, { passive: true });
el.addEventListener('touchend', (e) => {
  const t = e.changedTouches[0];
  const dx = t.clientX - sx, dy = t.clientY - sy, dt = Date.now() - st;
  if (dt < 500 && Math.abs(dx) > 40 && Math.abs(dx) > Math.abs(dy) * 2)
    onSwipe(dx > 0 ? 'right' : 'left');
}, { passive: true });
```
