## JS-373：死锁与活锁：前端异步的反模式

**答**：
- 前端死锁形态：互斥锁未释放（任务异常跳过 release）+ 循环等待（A 等 B 的结果、B 等 A 的锁）；单线程下表现为「功能永久转圈」而不是进程卡死
- 死锁预防：锁必须超时释放（租约）、finally 保证释放、锁粒度最小化、避免「锁内发起新的锁请求」（同一把锁可重入需显式支持）
- 活锁：两个操作互相重试撞车（A 重试触发 B 重试触发 A……）——加随机抖动退避打破对称；重试上限熔断
- 饥饿：低优先级任务永远轮不到——优先级老化（等待超时自动升级）；任务队列要有「最大等待时间」断言
- 诊断方法：任务挂起超时埋点（任务 started 未 finished > N 分钟告警）、锁持有时间统计——「转圈不止」的页面先查未释放锁

```javascript
// 死锁修复模式: finally 释放 + 超时
async function safeWithLock(mutex, key, fn) {
  let release;
  const timeout = setTimeout(() => release?.(), 30_000);   // 租约超时
  try {
    release = await mutex.acquire(key);
    clearTimeout(timeout);
    return await fn();
  } finally {
    clearTimeout(timeout);
    release?.();                                            // 任何路径都释放
  }
}
```
