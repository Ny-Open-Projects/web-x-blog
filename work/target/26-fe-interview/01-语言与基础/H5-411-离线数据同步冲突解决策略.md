## H5-411：离线数据同步：冲突解决策略设计

**答**：
- 冲突场景：离线期间本地改了 A，服务端也被别人改了——重放时 409 Conflict；方案三档：LWW（last-write-wins，简单但丢更新）、字段级合并（按字段时间戳/向量）、CRDT（复杂最终一致）
- 业务化选择：表单类用「服务端版本号 + 拒绝过期写」（乐观锁，前端提示冲突让用户合并）；收藏/设置类 LWW；协同编辑类才上 CRDT/OT
- 同步协议设计：本地操作日志（op log：opId/时间戳/实体版本）→ 重放时按 opId 幂等；服务端返回「已应用/冲突+最新数据」两种结果
- 冲突 UI：不要静默覆盖——展示双版本 diff 让用户选，或自动合并无冲突字段；冲突率监控（>1% 说明协议有问题）
- 时间不可信：移动端时钟漂移，时间戳比较用服务端时间；排序用逻辑时钟（版本号递增）

```javascript
// 乐观锁同步
async function syncOps(ops) {
  for (const op of ops) {                                 // 按序重放
    const res = await api.put(`/entity/${op.id}`, op.data, {
      headers: { 'If-Match': op.baseVersion },            // 乐观锁
      idempotencyKey: op.opId,                            // 幂等
    });
    if (res.status === 409) {
      const { data: server } = await api.get(`/entity/${op.id}`);
      const merged = mergeNonConflict(op.data, server);   // 无冲突字段自动合并
      await showConflictDialog(op, server, merged);       // 冲突字段用户裁决
    }
  }
  await idb.clear('oplog');
}
```
