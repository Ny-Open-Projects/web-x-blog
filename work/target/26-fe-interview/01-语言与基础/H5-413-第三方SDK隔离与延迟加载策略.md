## H5-413：第三方 SDK 隔离与延迟加载策略

**答**：
- 第三方 SDK 的三宗罪：阻塞渲染（同步 script）、吞带宽（占并发窗口）、崩溃连带（他们挂你也挂）——治理从「能否砍掉」开始
- 隔离手段：async/defer + 动态注入（idle 时加载）、沙箱 iframe 加载重型 SDK（广告，故障与主页面隔离）、服务端代理（自建埋点网关收数据再转发，去掉页面直连）
- 加载分级：关键业务 SDK（支付）随包、统计 SDK idle 后加载、广告/推荐 SDK 按需（进入相关场景才加载）+ 失败超时熔断
- 熔断器：SDK 加载超时/连续报错 N 次后本会话禁用并上报，防止第三方故障放大成自己页面故障
- 审计机制：季度盘点第三方清单（体积/阻塞时间/错误率），砍掉无 ROI 的 SDK——第三方数量是性能债的直接来源

```javascript
// 带熔断的第三方加载器
async function load3p(name, src, { timeout = 5000 } = {}) {
  if (sessionStorage.getItem(`p3p-off:${name}`)) return false;   // 熔断
  try {
    await new Promise((resolve, reject) => {
      const s = document.createElement('script');
      s.src = src; s.async = true;
      s.onload = resolve; s.onerror = reject;
      document.head.appendChild(s);
      setTimeout(() => reject(new Error('timeout')), timeout);
    });
    return true;
  } catch (e) {
    sessionStorage.setItem(`p3p-off:${name}`, '1');              // 本会话熔断
    beacon({ p3pFail: name, msg: String(e) });
    return false;
  }
}
// idle 时机加载
requestIdleCallback(() => load3p('analytics', 'https://analytics.example.com/sa.js'));
```

## 追问（补充）

**追问**：

1. async 与 defer 该怎么选？ → async 下载完立即执行且顺序不定，适合独立无依赖的统计脚本；defer 在 DOM 解析后按顺序执行，有依赖关系的 SDK 用 defer。
2. 用 iframe 沙箱隔离第三方换来什么代价？ → 独立源与进程，崩溃和内存泄漏不波及主页面，但通信只能走 postMessage，且 iframe 内拿不到主页面上下文与 Cookie 便利性。
3. 熔断为什么按会话而不是永久？ → 第三方故障多为临时性，永久禁用会误伤恢复后的能力，按会话或带退避的短期禁用，下个会话重新探测。
