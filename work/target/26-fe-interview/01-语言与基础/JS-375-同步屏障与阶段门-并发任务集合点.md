## JS-375：同步屏障与阶段门：并发任务的集合点

**答**：
- 屏障语义：N 个并发任务在集合点等待全部到达（Promise.all 是最简单屏障）——动态屏障（任务数量未知，动态加入）需要手写 CountDownLatch
- 动态屏障实现：计数器 + deferred——register() 计数、done() 递减到 0 时 resolve；支持超时（屏障永远等不齐时的兜底）
- 阶段门（分阶段流水线）：阶段 1 全完成才开阶段 2——多阶段用「链式屏障」（每阶段一个 latch）；分步表单向导并行校验后统一提交是这个模式
- 应用场景：多模型投票（全部返回才出结论）、并行预取后统一渲染、灰度双跑对比（新旧逻辑都完成才出报告）
- 反模式提醒：屏障内任务失败会永远阻塞——屏障要带失败策略（任一失败即 abort all 或降级）；超时是必备参数

```javascript
class Latch {
  #n; #d = deferred(); #t;
  constructor(n, timeout) {
    this.#n = n;
    if (timeout) this.#t = setTimeout(() => this.#d.reject(new Error('latch timeout')), timeout);
  }
  register(k = 1) { this.#n += k; }                 // 动态加任务
  done() {
    if (--this.#n <= 0) { clearTimeout(this.#t); this.#d.resolve(); }
  }
  wait() { return this.#d.p; }
}
// 场景: 3 个模型投票
const latch = new Latch(3, 8000);
const votes = [];
models.forEach(m => m.predict(input)
  .then(v => { votes.push(v); })
  .finally(() => latch.done()));
await latch.wait();
return majority(votes);
```

**追问**：

1. 屏障里某个任务永远不 resolve，只加超时够吗？ → 不够，超时只解锁等待方，泄漏的 Promise 及其持有的连接、定时器仍在；要配合 AbortController 取消并做任务级清理。
2. `register()` 在计数已经归零之后调用会发生什么？ → 计数从 0 变 1，但 deferred 早已 resolve，新任务等于不存在，屏障语义被破坏；register 必须发生在 wait 之前，或用「代数」重置计数器。
3. 直接用 `Promise.all` 当屏障，一个 reject 会怎样？ → all 立即 reject，其余任务仍在后台跑但结果被丢弃且无法停止；要真停必须逐个 abort，或用 allSettled 收齐后再判断。
