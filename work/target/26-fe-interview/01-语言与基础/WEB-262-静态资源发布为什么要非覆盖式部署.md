## WEB-262：静态资源发布为什么要非覆盖式部署？

**答**：
- 覆盖式发布的问题：HTML 引用 `app.js`，新版本覆盖同名文件——但旧 HTML 已被用户缓存/CDN 边缘仍持旧内容，引用到「已被覆盖」的新文件或「已删掉」的旧文件，内容与代码不匹配报错。
- 非覆盖式：每次构建产出 `app.<hash>.js`，新文件与旧文件并存；发布顺序铁律——先传静态资源（新旧共存），再更新 HTML，最后刷新 HTML 缓存。
- hash 选择：contenthash 保证内容不变 URL 不变（缓存命中）；回滚 = HTML 指回旧 hash，秒级完成。
- 配套：旧资源保留至少 1~2 个发布周期（覆盖住还在用旧 HTML 的用户）；HTML 本身 no-cache。

```bash
# 发布顺序脚本
rsync dist/assets/  cdn:/assets/          # 1. 静态资源新文件先上线（不删旧的）
curl -X POST cdn/refresh -d 'url=/index.html'  # 2. HTML 引用新 hash 后刷新其缓存
# 回滚: git revert HTML 引用即可，旧 hash 文件仍在线上
```
