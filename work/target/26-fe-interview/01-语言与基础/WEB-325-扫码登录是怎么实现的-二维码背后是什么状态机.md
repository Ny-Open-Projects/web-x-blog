## WEB-325：扫码登录是怎么实现的？二维码背后是什么状态机？
**答**：
- 二维码内容是服务端生成的临时票据 qid（或带签名 URL），网页端持 qid 长轮询/WS 等待状态。
- 状态机：待扫描 → 已扫描（手机确认了身份，网页显示"已扫码，请在手机确认"）→ 已确认（发授权，网页登录成功）/ 已过期 / 已取消。
- 安全性：qid 短时效（约2分钟）一次性；手机端确认时带自己的登录态换取授权，网页端全程拿不到手机凭证。

```javascript
const qr = { status: 'created', qid: 'q_abc' };
const poll = () => setInterval(async () => {
  const s = await fetch('/qr/status?qid=' + qr.qid);
  if (s.status === 'scanned') show('请在手机确认');
  if (s.status === 'confirmed') login(await s.token);
  if (s.status === 'expired') regenerate();
}, 1500);
// 手机端: POST /qr/confirm { qid, 手机token } → 服务端置 confirmed 并发授权
console.log('qid 一次性 + 短时效 + 手机端凭证不落地网页');
```

**评分点**：
- 结论先行，能一句话说清核心机制
- 要点覆盖主流程与关键分支（异常/并发/边界）
- 代码可运行且体现安全或性能意识
- 能主动说出"工程上怎么选"与常见坑
