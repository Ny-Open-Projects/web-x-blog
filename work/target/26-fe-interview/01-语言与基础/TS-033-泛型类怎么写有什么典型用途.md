## TS-033：泛型类怎么写？有什么典型用途？
**答**：
- 类名后声明类型参数，成员属性、方法都可以使用，实例化时确定具体类型。
- 典型用途：容器/集合类，如 Queue、Stack、缓存 Map 封装。
- 静态成员不能使用类的类型参数（静态上下文没有实例信息）。
- 泛型类配合约束可以实现强类型的事件发射器等。

```typescript
class Queue<T> {
  private items: T[] = [];

  enqueue(item: T): void {
    this.items.push(item);
  }

  dequeue(): T | undefined {
    return this.items.shift();
  }

  get size(): number {
    return this.items.length;
  }
}

const q = new Queue<number>();
q.enqueue(1);
q.enqueue(2);
const head = q.dequeue(); // number | undefined
// q.enqueue("x"); // 报错：只能入队 number
```

**边界与易错**：

- 无参构造的泛型类 `new Queue()` 推断不出 T，会落到 `unknown`，`enqueue(1)` 反而不报错（任何值都能赋给 unknown），但 `q.dequeue()` 的类型是 `unknown`，取用结果时才报错——无参泛型类应配工厂函数 `createQueue<T>()` 或显式标注类型实参。
- 静态成员里写 `static create(): Queue<T>` 会报「找不到 T」，静态上下文拿不到类的类型参数；只能改成 `static create<U>(): Queue<U>` 自己声明。
- 泛型参数在运行时被完全擦除，`q instanceof Queue` 无法区分 `Queue<number>` 与 `Queue<string>`，要做运行时校验得自己存一个标记字段。

**追问**：

1. 泛型类能不能约束 T 必须有某个属性？ → 可以，`class Box<T extends { length: number }>`，或用条件类型在方法签名上收窄。
2. 容器类做成泛型类还是泛型函数更好？ → 有跨方法共享状态（队列、缓存）用类；一次性转换或组合用泛型函数，避免为了用类而建类。
3. 泛型类的子类怎么继承类型参数？ → `class Deque<T> extends Queue<T>`，子类也可新增参数 `class Pair<A, B> extends Box<[A, B]>`，父类实参必须写全。
