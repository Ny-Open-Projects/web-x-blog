## WEB-531：接口灰度不一致问题排查（缓存+CDN）

**答**：
- 现象：灰度桶 A 用户拿到旧接口响应，或同一用户一会儿新一会儿旧——灰度标识在链路某处被「吃掉」
- 常见根因：① CDN 把带灰度参数的请求当同一 URL 缓存（Vary 或 cache key 未含灰度头）② 网关未透传灰度 header 到下游 ③ 客户端缓存（Service Worker/内存缓存）没有按灰度版本分 key
- 排查顺序：curl 带/不带灰度头直打源站 → 过网关 → 过 CDN 逐层对比，锁定哪一层开始「漂移」
- 设计规范：灰度标识进 cache key 或干脆对灰度接口禁缓存；客户端请求带版本头并上报，便于归因
- 收尾：灰度问题八成是「某层没把标识传下去」，把「全链路透传清单」写进灰度方案评审

```bash
# 逐层对比灰度头是否生效
curl -s -H 'X-Gray: b' https://edge.example.com/api/x | jq .version   # CDN 层
curl -s -H 'X-Gray: b' https://gateway.example.com/api/x | jq .version
```
