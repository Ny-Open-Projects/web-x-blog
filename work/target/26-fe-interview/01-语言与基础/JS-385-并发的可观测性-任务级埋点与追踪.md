## JS-385：并发的可观测性：任务级埋点与追踪

**答**：
- 追踪模型：给每个异步任务注入 trace context（traceId/spanId/父子关系）——页面加载 = 一个 trace，各请求/计算是 span，能还原「时间花在哪」的树
- 前端实现层级：轻量自研（任务包装器记录 start/end/状态）、W3C Trace Context（traceparent 头贯穿前后端）、OpenTelemetry JS SDK（完整方案，体积成本评估）——按成熟度选
- 并发可视化：任务时间线（甘特图式）暴露「并发度随时间曲线」「排队等待 vs 执行耗时」——排队占比高说明并发上限该调
- 关键指标：任务 P50/P95 耗时、排队时长占比、并发峰值、失败率按任务类型分布——四指标定位「慢在计算还是等待」
- 采样与开销：全量追踪有内存/CPU 开销（每任务对象）——头部采样（10% 会话全量）+ 错误任务强制保留；长任务自动升采样

```javascript
function traced(name, fn) {
  const traceId = sessionTraceId, spanId = crypto.randomUUID().slice(0, 8);
  const t0 = performance.now();
  const span = { name, traceId, spanId, t0, queuedMs: queueWait, status: 'running' };
  activeSpans.set(spanId, span);
  return fn().finally(() => {
    span.status = 'done'; span.dur = performance.now() - t0;
    activeSpans.delete(spanId);
    beacon(span);                                  // span 上报
  });
}
// 页面加载全景: loadTrace = traced('page-load', () => Promise.all([...]))
```
