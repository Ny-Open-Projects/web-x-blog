## JS-357：合帧批处理：把高频事件压到每帧一次

**答**：
- 合帧模型：同一帧内的多次事件合并为一次处理——实现「pending 标记 + rAF flush」：事件只记数据，rAF 回调统一消费
- 与 throttle 的差异：throttle 按时间节流（可能掉在两帧之间引发抖动），合帧严格对齐渲染节拍（每帧最多一次）——滚动/拖拽/鼠标移动的视觉同步场景合帧更优
- 批量语义：合帧还要「批」——一帧内 N 次 input 合成一个 batch（如撤销栈合并、上报合并），回调收到数组而不是单值
- 实现细节：rAF 取消（下一帧无 pending 不排）、卸载清理、值保留策略（保留最后值 vs 全部事件）
- 场景：滚动视差、拖拽跟随、富文本输入合并撤销、埋点批量——「视觉相关用 rAF 合帧，数据相关用 throttle，批处理加 batch」

```javascript
function frameBatch(handler, { keepAll = false } = {}) {
  let pending = [], raf = 0;
  return (...args) => {
    pending.push(args);
    if (!raf) raf = requestAnimationFrame(() => {
      raf = 0;
      const batch = pending; pending = [];
      keepAll ? handler(batch) : handler(batch.at(-1));  // 批处理或只取最后
    });
  };
}
// 用法: 鼠标移动一帧只处理一次
const onMove = frameBatch(({ x, y }) => cursor.style.transform = `translate(${x}px,${y}px)`);
document.addEventListener('mousemove', (e) => onMove(e.clientX, e.clientY));
```
