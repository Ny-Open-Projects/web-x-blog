## JS-401：笔试：手写串行执行队列

**答**：实现 `SerialQueue`：① `enqueue(fn)`：任务按提交顺序串行执行（前一个完成后才下一个），返回该任务的 Promise；② 任一任务失败不阻塞后续（失败跳过继续）；③ 提供 clear（清空未执行任务并 reject 它们）；④ flush()：等待全部已入队任务完成（含失败）；⑤ 统计：pending/done/failed。写出实现。

```javascript
class SerialQueue {
  #chain = Promise.resolve();
  #pending = [];
  stats = { done: 0, failed: 0, pending: 0 };
  enqueue(fn) {
    const task = { fn };
    const p = new Promise((resolve, reject) => Object.assign(task, { resolve, reject }));
    this.#pending.push(task);
    this.stats.pending = this.#pending.length;
    this.#chain = this.#chain.then(async () => {
      const next = this.#pending[0];
      if (next !== task) return;   // 已被 clear 清出队列，跳过执行
      this.#pending.shift();
      try {
        task.resolve(await fn());
        this.stats.done++;
      } catch (e) {
        this.stats.failed++;
        task.reject(e);                        // 任务自身失败, 链继续
      } finally {
        this.stats.pending = this.#pending.length;
      }
    }).catch(() => {});                        // 吞链级错误(任务错误已定向到各自 promise)
    return p;
  }
  clear(reason = 'cleared') {
    for (const t of this.#pending.splice(0)) t.reject(new Error(reason));
    this.stats.pending = 0;
  }
  flush() { return this.#chain.then(() => this.stats); }
}
// 用法: 数据写入必须按序落库
const q = new SerialQueue();
q.enqueue(() => db.insert(a));   // 按序
q.enqueue(() => db.insert(b));   // a 失败不影响 b 执行
```

**评分点**：
- Promise 链实现串行（#chain 递进）且链级错误被吞、任务错误定向回各自 promise
- 失败不阻塞后续（finally + 链 catch）
- clear reject 未执行任务并同步统计
- flush 返回统计（等待自然完成）

## 变体与延伸（补充）

**变体与延伸**：

1. 任务失败为什么要定向 reject 而不是让链 rejected？ → 直接抛会把 #chain 变成 rejected，后续 then 全部跳过导致队列停摆，必须把错误交给任务自身 promise 再在链上 catch 吞掉。
2. clear 之后链上已排队的 then 会不会错位？ → 会，被清空的任务仍在链上占位，执行时 shift 可能拿到别的任务，需按 task 身份校验而不是依赖数组位置。
3. flush 在 clear 之后还有什么语义？ → 只等待链走完，不保证 done+failed 等于入队数，被 clear 的任务已 reject 且不计入统计，调用方需自行区分。
