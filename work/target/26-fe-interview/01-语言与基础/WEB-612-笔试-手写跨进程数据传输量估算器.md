## WEB-612：笔试：手写跨进程传输成本估算器

**答**：实现 `TransferCostEstimator`：① 对一个响应流分别测「整体 await 后处理」与「chunk 流式处理」两种模式的峰值内存与首字节处理延迟；② `measure(url, mode)`：mode='buffered' 用 res.arrayBuffer() 后统计；mode='stream' 用 res.body.getReader() 逐 chunk 处理（chunk 计数与峰值累计）；③ 输出 `{ totalBytes, chunks, firstChunkMs, peakBufferedBytes }`；④ 结论函数 `verdict(m1, m2)`：大响应（>5MB）推荐 stream。写出实现。

```javascript
async function measure(url, mode) {
  const t0 = performance.now();
  const res = await fetch(url);
  const firstChunkMs = performance.now() - t0;
  let totalBytes = 0, chunks = 0, peak = 0;
  if (mode === 'buffered') {
    const buf = await res.arrayBuffer();
    totalBytes = buf.byteLength; peak = buf.byteLength; chunks = 1;
  } else {
    const reader = res.body.getReader();
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      totalBytes += value.byteLength; chunks++;
      peak += value.byteLength; // 流式: 处理后释放, 峰值≈chunk 累计(实际同时只驻留一块)
      await processChunk(value); // 业务处理
      peak -= value.byteLength;  // 释放后回落, 记录最大瞬时
    }
  }
  return { totalBytes, chunks, firstChunkMs, peak };
}
let peakMax = 0;
function processChunk(v) { peakMax = Math.max(peakMax, v.byteLength); }
function verdict(b, s) {
  if (b.totalBytes > 5 * 1024 * 1024 && s.chunks > 1)
    return `推荐 stream: 峰值内存 ${b.peak}→${s.peak}, 首字节处理提前 ${b.firstChunkMs - s.firstChunkMs}ms`;
  return '差异不大, 保持现有模式';
}
```

**评分点**：
- 双模式对照测量框架完整（buffered vs stream）
- 理解核心结论：大响应 buffered 模式整包驻留内存 + 跨进程整块拷贝，stream 降低峰值且首字节提前
- chunk 计数与峰值统计口径自洽
- verdict 阈值判断合理（大文件才值得流式复杂度）
