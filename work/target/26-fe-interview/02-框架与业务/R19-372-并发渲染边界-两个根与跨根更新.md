## R19-372：并发渲染边界：多个 root 与跨根协调

**答**：
- 多 root 场景：微前端子应用各自 createRoot、portal 到不同容器、组件库在非 React 页面挂多个小 root——每个 root 独立调度互不感知
- 跨根问题：A root 更新触发 B root 更新（事件总线桥接）——两个 root 的渲染不原子（B 可能先提交），出现「短暂不一致」；缓解：B 的更新也放 transition，让两树在同一时间窗口提交
- flushSync 跨 root：强制同步提交让两个 root 接近同时 commit——但破坏并发收益，只用于「必须一致」的少数场景
- root 挂载与 StrictMode：每个 root 独立配置（并发特性逐 root 开启）——迁移期「老 root legacy / 新 root concurrent」共存
- 性能面：多 root 意味着多份 reconciler 工作（不共享调度堆）——子应用数量与性能的权衡，微前端架构设计输入

```jsx
// 微前端子应用
function mountApp(el, props) {
  const root = createRoot(el);
  root.render(<SubApp {...props} />);
  return () => root.unmount();
}
// 跨根同步: 事件桥 + transition 双侧包裹
bus.on('user-change', (u) => {
  startTransition(() => setUser(u));   // B root 侧低优
});
```
