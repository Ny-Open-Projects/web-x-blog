## R19-043：错误边界捕获不到哪些错误？分别怎么兜底？
**答**：
- 事件处理器中的错误：不走 React 渲染流程，用 try/catch 包住处理。
- 异步回调（setTimeout、Promise）、Server Component、错误边界自身的错误：同样捕获不到。
- SSR 服务端渲染错误：需要在服务端框架层兜底。
- 全局兜底配合 window.addEventListener 的 error 与 unhandledrejection 上报。

```jsx
function Buttons() {
  // 事件处理器内的错误不会触发错误边界，必须 try/catch
  function handleClick() {
    try {
      riskyOperation();
    } catch (err) {
      reportError(err); // 上报或提示
    }
  }

  useEffect(() => {
    // 异步错误同样要自己接住
    const controller = new AbortController();
    fetchData(controller.signal).catch((err) => reportError(err));
    return () => controller.abort();
  }, []);

  // 全局兜底：main.jsx 中注册
  // window.addEventListener('error', reportError);
  // window.addEventListener('unhandledrejection', reportError);

  return <button onClick={handleClick}>执行</button>;
}
```

## 补充：边界与追问

**边界与易错**：

1. 误以为 effect 里 throw 会被边界接住：effect 在 commit 后执行，抛错直接冒到 window，必须自己 try/catch。
2. 边界自己 render 抛错不会兜住自己：错误继续向上冒泡到父边界，`getDerivedStateFromError` 里不能有副作用。

**追问**：

1. `unhandledrejection` 能兜住所有异步错误吗？→ 只兜未被 catch 的 promise，被 try/catch 吞掉的看不到，且拿不到组件栈。
2. `onUncaughtError` 和 `window.onerror` 谁先拿到？→ root 钩子先拿到并带组件栈，window 只做最后兜底，两边要按错误 ID 去重。
3. 事件处理器为什么不走边界？→ 事件回调不参与渲染流程，React 无法用渲染栈判断归属，只能手动 catch。
