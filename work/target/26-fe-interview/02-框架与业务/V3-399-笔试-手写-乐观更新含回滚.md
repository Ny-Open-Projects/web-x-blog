## V3-399：笔试：手写乐观更新（含失败回滚与冲突提示）
**题**：实现 `optimisticUpdate(listRef, item, apiCall)`：先把本地列表更新为乐观值；请求成功用服务端返回值覆盖（可能带 version）；失败回滚到原值并 toast 提示；连续操作要按序应用（后发先至防护）。

```javascript
const pending = new Map()
async function optimisticUpdate(listRef, item, apiCall) {
  const key = item.id
  const snapshot = structuredClone(toRaw(listRef.value.find(x => x.id === key)))
  // 本地立即更新
  const idx = listRef.value.findIndex(x => x.id === key)
  listRef.value[idx] = { ...item, __optimistic: true }
  const seq = (pending.get(key) ?? 0) + 1
  pending.set(key, seq)
  try {
    const server = await apiCall(item)
    if (pending.get(key) !== seq) return // 过期响应丢弃
    listRef.value[idx] = server          // 服务端值覆盖（含 version）
    if (server.version !== snapshot.version + 1) toast('数据已被他人修改，已同步最新')
  } catch (e) {
    if (pending.get(key) !== seq) return
    listRef.value[idx] = snapshot        // 回滚
    toast.error('保存失败，已恢复原状态')
  } finally {
    if (pending.get(key) === seq) pending.delete(key)
  }
}
```
**评分点**：
- 快照回滚（structuredClone/toRaw，不是引用）。
- 序号防「后发先至」覆盖（核心）。
- 成功后用服务端值而非保留乐观值（含 version 冲突检测）。
- 失败提示 + __optimistic 标记可用于 UI 弱化展示。
