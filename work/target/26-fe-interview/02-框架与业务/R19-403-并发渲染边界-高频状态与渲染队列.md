## R19-403：并发渲染边界：高频状态源与渲染队列治理

**答**：
- 高频源清单：WebSocket 推送行情、鼠标移动、进度条更新——每条都 setState 会淹没渲染队列
- 治理模式一（外部直写）：动画值/位置走 ref+DOM 直写，React 状态只在「节流点」同步——R19-375 模式的推广
- 治理模式二（合帧 store）：store 层合并（16ms 窗口内取最新值再通知订阅）——订阅端渲染频率上限锁死
- 治理模式三（选择性渲染）：数据全量进 store，组件用 selector 订阅「自己关心的切片」——无关更新不触发渲染
- 指标验收：高频场景下「渲染次数/秒」与「输入延迟」——渲染 ≤ 屏幕帧率（60/次每秒），输入 <100ms

```javascript
// 合帧 store
class ThrottledStore {
  #dirty = false;
  update(v) {
    this.value = v;
    if (this.#dirty) return;
    this.#dirty = true;
    requestAnimationFrame(() => {
      this.#dirty = false;
      this.notify();                    // 每帧最多一次通知 → 每帧最多一次渲染
    });
  }
}
```
