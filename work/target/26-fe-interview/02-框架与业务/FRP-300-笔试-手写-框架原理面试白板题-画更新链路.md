## FRP-300：白板画「Vue vs React 更新链路」完整图并标注开销点
**题**：白板/文字画出两种框架「改一个状态 → 屏幕更新」的完整链路，标注每步的开销性质（JS 计算/DOM/GC），并回答：哪一步是可优化焦点？

```
Vue（模板编译优化后）:
  数据变更 → Proxy set → trigger（依赖链表，O(订阅者)）
    → 组件 render effect 入队（微任务批量）
    → render 执行（block 动态点收集，JS，O(动态点)）
    → patch（patchFlag 定位，JS+DOM，O(动态点)）
    → DOM 写（真实开销）

React:
  setState → lane 入队（位运算 O(1)）
    → 调度（时间切片，宏任务）
    → render 阶段（fiber 遍历 reconcile，JS，O(子树)，可中断）
    → commit（DOM 写，同步）
    → useEffect（paint 后）

可优化焦点：Vue = render+patch 的动态点数量（编译优化）；React = reconcile 范围（memo/Compiler/虚拟化）。
```
**评分点**：
- 链路完整无缺步（尤其调度/批量环节）。
- 每步标注开销性质（JS vs DOM vs GC）。
- 优化焦点落到「动态点/reconcile 范围」而不是泛泛「性能优化」。
- 能口头补充：两链路的可中断性差异（render 可中断 vs Vue 同步批处理）。
