## MP-375：笔试：手写跟手拖拽

**答**：实现跟手拖拽的两个版本：① WXS 版（真实方案）：drag.wxs 的 touchmove 直接返回 transform——渲染层同线程（写出 WXS 代码）；② JS 版（对比理解）：bindtouchmove → setData——说明为什么卡（跨线程 16ms+ 序列化）与最小可用优化（16ms 节流 + 只传位移值）；③ 惯性：touchend 速度追踪（最近两次 move 差分）+ 松手动画（CSS transition 替代逐帧）；④ 边界钳制；⑤ 双版本的性能对比结论。写出实现。

```javascript
Page({
  onTouchMove(e) {
    const y = e.touches[0].clientY;
    if (!this._lastT || Date.now() - this._lastT >= 16) {   // 16ms 节流
      this._lastT = Date.now();
      this.setData({ offset: Math.max(0, Math.min(MAX, y - this._startY)) });   // 只传位移值
    }
  },
  onTouchEnd() { this.setData({ inertial: true }); },  // 松手切 CSS transition 类
});
// 结论: 跟手场景 setData 必卡 (每帧一次 IPC+序列化); WXS/worklet 是唯一解
```

**评分点**：
- WXS 版的同线程语义（ins.selectComponent 直接操作渲染层）
- JS 版卡顿根因的准确表述（跨线程 IPC + 序列化 vs 每帧）
- 惯性用 CSS transition 收尾（不逐帧 setData）
- 边界钳制与 return false 阻止默认滚动

## 变体与延伸（补充）

**变体与延伸**：

1. 不用 WXS，Skyline 下有没有别的解？ → worklet 里跑手势与动画（同在渲染线程），或者用 setData 只传位移并前置 CSS transition 缓解；但都只是逼近，真跟手仍要求手势计算与样式写入发生在渲染层同线程。
2. 松手后撞到边界怎么处理回弹？ → 松手时按速度算出目标位移并 clamp 到 [0, MAX]，越界改用 cubic-bezier 缓动回弹；不要逐帧 setData 追位置，否则松手瞬间就掉帧。
3. 多指同时拖两张卡片会怎样？ → WXS 里必须按 touch identifier 分开维护各自的 startY/lastY/offset，共用一个变量会互相覆盖；JS 版则要在 setData 的 key 上带卡片 id。
