## FRP-352：跨框架的状态机内核

**答**：
- 状态机内核的价值：复杂交互（订单流转/向导/审批流）的状态迁移逻辑框架无关——「非法迁移不可能发生」由内核保证
- 最小实现：states（含 guards/actions）、transition(event)（guard 校验 → action 执行 → 状态变更 → 通知）、history（撤销/恢复）
- 与 XState 的关系：生产直接用 XState（actor 模型/可视化/并发状态成熟）；自研只在「极简场景或特殊协议」——内核抽象的学习成本要算
- 框架绑定层：状态机作为 store（订阅通知）——React useSyncExternalStore / Vue customRef——组件只读 state + dispatch
- 调试增强：迁移日志（每次 transition 的 from/event/to）+ 可视化（状态图生成）——复杂状态机的可观测性基建

```javascript
export function createMachine({ states, initial }) {
  let current = initial;
  const subs = new Set();
  return {
    get state() { return current; },
    send(event, payload) {
      const node = states[current];
      const t = node.on?.[event];
      if (!t) return false;                            // 非法迁移: 拒绝
      if (t.guard && !t.guard(payload, current)) return false;
      const prev = current;
      current = t.target;
      t.action?.(payload, prev);
      logTransition({ from: prev, event, to: current });
      subs.forEach((f) => f(current, prev));
      return true;
    },
    sub(fn) { subs.add(fn); return () => subs.delete(fn); },
  };
}
```
