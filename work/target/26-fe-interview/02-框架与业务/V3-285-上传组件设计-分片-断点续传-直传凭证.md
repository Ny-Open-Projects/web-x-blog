## V3-285：上传组件设计：分片、断点续传与直传凭证怎么实现？
**答**：
- 大文件分片：按 5~10MB 切片，`File.slice` 生成 Blob，逐片或并发 2~3 片上传；每片带 hash（秒传判断：文件级 hash 存在即秒传，或抽样 hash 兼顾性能）。
- 断点续传：上传前 `POST /upload/init` 返回已存在分片列表，只传缺失分片；进度 = (已传分片字节 + 当前片进度) / 总字节。
- 直传凭证：后端签发 OSS 临时凭证（STS 或预签名 URL），前端直传对象存储，回调后端合并（`merge` 接口），避免流量过业务服务器。
- 并发与失败控制：并发窗口 2~3，单片失败重试 2 次指数退避；整体失败保留已传分片状态供续传。
- 边界：文件唯一性（hash 冲突校验大小+最后修改时间）、秒传的权限校验（防止凭 hash 引用他人私有文件）、上传取消与浏览器关闭恢复。

```typescript
async function upload(file, onProgress) {
  const hash = await sampleHash(file);                      // 抽样 hash：首尾+中间块
  const init = await api.post('/upload/init', { name: file.name, size: file.size, hash });
  if (init.exists) return onProgress(1);                    // 秒传
  const done = new Set(init.uploaded);                      // 断点续传：已传分片
  let uploadedCount = 0;   // 本轮会话内已上传的分片数
  const chunks = Math.ceil(file.size / CHUNK);
  const queue = [...Array(chunks).keys()].filter((i) => !done.has(i));
  const workers = Array.from({ length: 3 }, () => worker());
  async function worker() {
    while (queue.length) {
      const i = queue.shift();
      const blob = file.slice(i * CHUNK, (i + 1) * CHUNK);
      await withRetry(() => api.put(init.partUrl(i), blob)); // 单片重试
      onProgress((++uploadedCount + done.size) / chunks);
    }
  }
  await Promise.all(workers);
  await api.post('/upload/merge', { uploadId: init.id });    // 合并
}
```

## 追问（补充）

**追问**：

1. 抽样 hash 判断秒传会不会误判成别人的文件？ → 会。抽样只覆盖首尾与中间固定块，必须补文件大小与 lastModified 一起校验，并且秒传必须做权限校验，否则拿到 hash 就能引用他人私有对象。
2. 分片并发传完后文件损坏，怎么定位是哪个环节？ → merge 时按 partNumber 升序拼接并校验每片 Content-MD5 与总字节数；前端 `slice(i*CHUNK,(i+1)*CHUNK)` 的边界要用整数算，浮点乘会在超大文件上偏一字节。
3. 用户中途取消或直接关页面，已传分片白费吗？ → 不白费。分片状态按 uploadId 落在服务端，下次 init 返回 uploaded 列表直接续传；本地要 abort 在途请求并在 beforeunload 提示，避免连接被浏览器强断留下脏片。
