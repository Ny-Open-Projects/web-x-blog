## MP-235：登录态同步与失效处理？
**答**：
- 存储：token 存 storage + 内存双份（内存读快、storage 兜底重启）；登出双清。
- 请求层：统一 request 封装——401/业务码过期触发「静默重登队列」（并发请求等待同一 promise 重登完成再重放）。
- 防重放风暴：重登加锁（单飞）+ 上限次数，失败跳登录页。
- 多页面同步：store（Pinia/自研）管理 user 状态，页面订阅；退出登录全局事件通知各页清理用户态。
- 边界：token 失效但页面正在提交的表单——先暂存本地，重登后恢复提交。
