## V3-209：Vue 3.5 响应式重构对依赖清理策略做了什么改变？
**答**：
- 旧策略"全清重建"：effect 重跑前把所有旧依赖 unlink（O(总依赖数)），跑完再重新 track 收集，存在大量无效操作。
- 新策略"增量收集 + 精准摘除"：重跑前把旧依赖链从头到尾按序遍历，重新 track 时**复用相同依赖**（链表尾追加判定），只摘除本轮未再触达的节点。
- 实现要点：track 时如果当前 dep 已在 effect 的 deps 链中（通过 `dep.version` 或扫描尾部判断），直接跳过。
- 收益场景：分支切换 `v-if` + 大依赖集时，只有真正移除的分支依赖被摘除；热点 effect（每帧动画）不再有重建开销。
- 追问钩子：为什么不能完全不做 cleanup？——条件分支仍会改变依赖集合，不清理会保留幽灵依赖导致误更新。

```javascript
// 增量收集的核心判定（示意）
function track(dep, sub) {
  // 若 dep 已经是 sub 当前轮收集的尾部依赖，直接复用，不重复建链
  if (sub.depsTail && sub.depsTail.dep === dep) return;
  // 旧依赖链中存在该 dep（本轮再次触达）→ 移动/复用节点，避免 unlink 后重 link
  if (isTrackedThisRound(sub, dep)) return;
  link(dep, sub);
}
function runEffect(sub) {
  sub.depsTail = null;          // 重置本轮收集游标
  sub.fn();                     // 执行，期间 track 复用或新建链节点
  pruneUnusedDeps(sub);         // 从 depsTail 之后截断：未被触达的旧依赖一次性摘除
}
```
