## FRP-303：跨框架状态桥接：桥接层设计模式

**答**：
- 桥接需求场景：微前端共享用户态、渐进迁移（新旧页面共享购物车）、设计系统跨框架分发
- 桥接三层设计：状态内核（框架无关的 plain store + 订阅协议）、框架适配器（React 用 useSyncExternalStore、Vue 用 customRef/computed、Solid 用 signal）、序列化边界（跨 iframe/postMessage）
- React 侧适配：`useStore(store, selector)` 包 useSyncExternalStore——快照语义防撕裂；Vue 侧：customRef 订阅 store——写时通知、读时 track
- 双向桥：A 框架写 → 内核 → B 框架订阅更新——「单一真源 + 两个视图」而不是「两个状态互相同步」（同步是死循环之源）
- 生命周期：桥接的订阅必须随组件卸载清理（两框架各自的清理钩子）——泄漏排查点

```javascript
// 框架无关内核
function createStore(initial) {
  let s = initial;
  const subs = new Set();
  return {
    get: () => s,
    set(v) { s = v; subs.forEach(fn => fn(s)); },
    sub(fn) { subs.add(fn); return () => subs.delete(fn); },
  };
}
// React 适配
function useStore(store, sel) {
  return useSyncExternalStore(store.sub, () => sel(store.get()));
}
// Vue 适配
function useStoreVue(store) {
  return customRef((track, trigger) => ({
    get() { track(); return store.get(); },
    set(v) { store.set(v); trigger(); },
  }));
}
```

**追问**：

1. `useSyncExternalStore` 的 `getSnapshot` 里直接用 selector 会出什么问题？→ 每次返回新对象会让 React 认为快照一直在变，报 "getSnapshot should be cached" 并进入无限重渲染，必须缓存结果或改用 `useSyncExternalStoreWithSelector` 做等值比较。
2. 两个框架互相写同一个 store，怎么避免回调互相触发形成死循环？→ 写入方带上来源标记，内核在派发时跳过自己；同 tick 多次写入还要做事务批处理，只广播最终快照。
3. 跨 iframe 桥接为什么不能直接传 Proxy 或函数？→ `postMessage` 走 structured clone，函数、Proxy、Symbol 都不可克隆，只能传序列化快照加版本号，并用递增序号处理异步投递的乱序。
