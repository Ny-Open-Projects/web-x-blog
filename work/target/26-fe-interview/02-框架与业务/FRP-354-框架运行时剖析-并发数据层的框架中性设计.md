## FRP-354：框架运行时剖析：并发数据层的框架中性设计

**答**：
- 框架中性数据层的三个抽象：请求执行（fetch 包装：重试/取消/幂等——纯 JS）、缓存内核（键化 + TTL + 失效订阅）、绑定协议（订阅通知接口——各框架实现）
- 并发语义的中性化：竞态守卫（seq）在内核实现——「各框架自己处理竞态」的反模式（不一致且重复代码）
- 与 React 并发渲染的对接：绑定层负责「快照化」（useSyncExternalStore）——内核不知道并发渲染存在（分层清晰）
- 乐观更新协议：内核 mutate(event) 返回 { rollback } ——乐观值管理在内核（跨框架一致的回滚语义）
- 与 TanStack 的关系：其核心层已是框架中性（query-core）——学习其分层而不是重造

```javascript
// 中性数据层
class DataKernel {
  async mutate(key, fn, { optimistic }) {
    const prev = this.get(key);
    optimistic && this.set(key, optimistic);          // 乐观写
    try {
      const result = await fn();
      this.set(key, result);
      return { result };
    } catch (e) {
      this.set(key, prev);                            // 内核层回滚
      throw e;
    }
  }
}
// 绑定层: React 加快照化, Vue 加 customRef — 内核无感知并发渲染
```
