## V3-307：Vue 3.5 的响应式 Props 解构是怎么实现「解构后仍响应」的？
**答**：
- 编译器把 `const { title = 'x' } = defineProps<{title: string}>()` 中的解构**编译成 `props.title` 的访问表达式**，默认值编译为空值合并。
- 响应性来源不变：`props` 本身是响应式代理，只要在 effect/render 上下文里读取 `props.title`，就会正确收集依赖——解构只是语法糖，不是拷贝。
- 与旧版区别：3.4 之前顶层解构会丢失响应性（拿到的是当时的值快照），需要 `toRefs(props)`；3.5 起在 `<script setup>` 中默认支持直接解构。
- 可配合解构默认值 `const { page = 1 } = defineProps(...)`，编译成 `props.page ?? 1`；如果需要严格响应式判断要避免用 `||` 语义。
- 边界：在普通函数（非响应式上下文）里读解构变量仍是普通求值；跨组件传给子组件时保持响应式没问题，因为最终都收敛为对 props 的依赖收集。
```javascript
// <script setup lang="ts">
const { title = '默认标题', page = 1 } = defineProps<{ title?: string; page?: number }>()
// 编译产物 ≈
// const title = props.title ?? '默认标题'
// const page = props.page ?? 1  （在 render/effect 内每次重新求值）
```
