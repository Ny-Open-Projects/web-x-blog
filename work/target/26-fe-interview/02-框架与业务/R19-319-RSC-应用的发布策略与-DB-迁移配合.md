## R19-319：RSC 发布与 DB 迁移怎么配合？
**答**：
- 顺序：先跑兼容性 DB 迁移（加列/默认值，不删不破坏）→ 部署新代码 → 确认稳定 → 清理迁移（删旧列）。
- RSC 特有：revalidateTag 在迁移期间的大量失效可能打穿缓存——迁移窗口预热关键页。
- Action 兼容：新旧 action id 并存一个版本周期（发版错峰）。
- 回滚预案：代码回滚 + 迁移可逆（保留旧列数据），监控 error rate 与业务指标双绿灯。
- 灰度：按流量百分比切流（边缘分流）观察，异常即回。
