## MP-355：小程序安全体系：接口签名、防重放与风控

**答**：
- 安全分层：传输安全（HTTPS 强制——域名白名单体系天然保障）、身份安全（code2session 链路的 token）、接口安全（签名/防重放/限流）、业务安全（裂变防刷/黄牛）
- 接口签名设计：业务请求带 timestamp + nonce + sign（HMAC(token+params+ts)）——服务端校验时间窗（±60s）+ nonce 去重（Redis）——防重放的标准组合
- 密钥管理的边界：前端没有任何「绝对秘密」（代码包可被反编译）——签名密钥用 token 派生（会话级）而不是硬编码 secret；真正的安全边界在服务端校验
- 风控接入：行为风控（下单频率/设备指纹）——前端采集弱指纹（系统信息+行为特征）只是参考，服务端风控为准
- 深水点：代码包反编译的风险认知——「前端隐藏功能」（隐藏入口/价格逻辑）不构成安全——所有业务规则服务端裁决

```javascript
// 请求签名
function signRequest(params, token) {
  const ts = Date.now(), nonce = crypto.randomUUID();
  const sign = hmacSHA256(`${token}|${ts}|${nonce}|${sortedQS(params)}`);
  return { ...params, ts, nonce, sign };
}
// 服务端: |ts-now| < 60s → Redis SETNX(nonce) 防重放 → 验签 → 业务
// 原则: 前端无秘密, 服务端全量校验; 前端签名只是提高攻击成本
```
