## V3-211：Vue 3.5 响应式性能基准怎么测？重构收益如何量化？
**答**：
- 基准维度：创建（reactive 10w 对象）、读写（百万次 track/trigger）、computed 链、大数组 splice、真实组件树更新。
- 官方数据：内存占用 -56%（组件树场景），`array clone/splice` 类操作显著提升；SSR 场景 `createSSRContext` 优化。
- 工具：`@vue/reactivity` 自带 benchmark 脚本（repo 下 `benchmarks/`），或 performance.now 打点 + 内存用 `performance.measureUserAgentSpecificMemory`。
- 业务化测量：对真实页面用 Performance 面板录制交互（滚动/批量勾选），对比 3.4/3.5 的 Scripting 时间与堆内存。
- 汇报口径：给面试官讲"什么场景受益最大"——依赖数量多、分支切换频繁、大数组操作的页面；简单页面差异不可感。

```javascript
// 简易响应式基准
import { reactive, computed } from 'vue';
function bench(name, fn) {
  const t0 = performance.now();
  fn();
  console.log(name, (performance.now() - t0).toFixed(1), 'ms');
}
const state = reactive(Array.from({ length: 100000 }, (_, i) => ({ v: i })));
bench('bulk write', () => state.forEach((o, i) => { o.v = i * 2 }));
const total = computed(() => state.reduce((s, o) => s + o.v, 0));
bench('computed chain x1000', () => {
  for (let i = 0; i < 1000; i++) total.value; // 未变更时 3.5 直接走版本号快路径
});
bench('splice', () => state.splice(50000, 1000));
```
