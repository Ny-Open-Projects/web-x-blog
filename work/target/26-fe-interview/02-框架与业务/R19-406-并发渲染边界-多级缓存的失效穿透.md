## R19-406：并发渲染边界：多级缓存的失效穿透

**答**：
- 多级缓存栈：请求级 cache() → 路由级 router cache → 客户端 store（React Query）→ 浏览器 HTTP 缓存——失效要「穿透」到底否则 UI 显示旧数据
- 穿透路径：server fn 内 revalidateTag → 服务端缓存失效 → 返回的 Flight 流带新数据 → client store 更新（setQueryData / invalidateQueries 主动触发）——每一跳都要写代码，没有自动全链路失效
- 常见断点：server 缓存已失效但 client Query 缓存 TTL 未到——「重新进入页面看到旧数据」；修复：server 响应带版本号，client 收到即 invalidate 对应 query
- 版本戳方案：全局数据版本（updated_at）作为 queryKey 的一部分——版本变化 = key 变化 = 自然失效
- 深水点：乐观更新与失效的时序——乐观 UI 提交 → server revalidate → 新数据回流——「回流快于 transition 完成」时 UI 闪烁；用 useOptimistic 的 pending 标记压制

```javascript
// server fn
'use server';
await db.update(...);
revalidateTag('orders');
return { version: Date.now() };
// client 提交后
const { version } = await createOrder(fd);
queryClient.invalidateQueries({ queryKey: ['orders'] });  // 主动穿透到 client 层
```
