## V3-302：Vue 3.5 版本计数（version counting）如何避免依赖的级联重复计算？
**答**：
- 全局 `globalVersion` 在每次 trigger 时自增；每个 dep、每个 effect 各自记一个 `version`。
- effect 重新运行前把自己的 version 同步为 globalVersion；若期间某依赖被触发过，依赖节点 version > effect version，才判定为脏、需要重跑。
- computed 采用同样机制：读 computed 时比较其 dep 的 version 与订阅者记录的 version，不同才执行 getter，相同直接返回缓存值。
- 收益：一条链上 A→B→C，A 变了但 B 的计算结果恰好没变时，C 不会因为 B 的「身份变化」而重算——按值版本判断而非引用判断。
- 对比旧方案：旧版靠 `dirty` 布尔标记 + 链式手动传播，需要层层手动置脏；版本计数把「是否变化」判断下沉到数据结构本身。
```javascript
// 简化模型
let globalVersion = 0
class Dep { version = 0; subs = null }
function trigger(dep) {
  dep.version = ++globalVersion   // 只打版本号，不主动刷新订阅者
  notify(dep)                      // 通知头节点 effect 标脏调度
}
```
