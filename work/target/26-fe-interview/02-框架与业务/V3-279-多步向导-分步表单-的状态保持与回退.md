## V3-279：多步向导（分步表单）的状态保持与回退校验怎么设计？
**答**：
- 状态模型：单一 `wizardModel`（全量字段扁平存储）+ `currentStep`；每步组件只声明自己负责的字段路径，切步不销毁模型。
- 步骤切换：前进校验当前步字段子集（descriptor 按 step 切片）；后退不校验（保留现场）；跳步需补全中间步校验。
- 草稿持久化：wizardModel 变更防抖写 localStorage/sessionStorage（区分匿名草稿与登录态），恢复时版本兼容（schema 版本号不匹配丢弃）。
- 步骤可见性：某些步骤条件出现（选择企业账户才出现发票步）——步骤数组动态生成，索引语义改为 step id，避免动态增删后索引错位。
- 服务端草稿：关键流程（贷款申请）每步完成即异步暂存到服务端，支持跨设备续填。

```typescript
const steps = ['base', 'enterprise', 'invoice', 'confirm'] as const;
const current = ref('base');
const model = reactive({ base: {}, enterprise: {}, invoice: {} });
function next() {
  const fields = stepFields[current.value];        // 当前步字段子集
  validate(model, fields).then(() => {
    const idx = steps.indexOf(current.value);
    current.value = steps[idx + 1];
    saveDraft(model);                              // 草稿：每步前进即存
  });
}
// 条件步骤：动态数组 + id 导航
const activeSteps = computed(() =>
  model.enterprise.type === 'company' ? steps : steps.filter((s) => s !== 'invoice'));
// 恢复草稿（版本不兼容丢弃）
const saved = localStorage.getItem('wizard-draft');
if (saved && JSON.parse(saved).v === SCHEMA_VERSION) Object.assign(model, JSON.parse(saved).data);
```
