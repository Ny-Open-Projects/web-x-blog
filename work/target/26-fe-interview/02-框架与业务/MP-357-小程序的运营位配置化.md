## MP-357：小程序的运营位配置化：CMS 驱动的页面能力

**答**：
- 配置化动机：运营活动高频变更——「代码发版」节奏跟不上（审核周期）；「运营位 CMS 化」让素材/开关/排序远程下发
- 楼层化架构：首页按「楼层组件」组合（banner/金刚区/秒杀楼层/推荐流）——楼层注册表 + 服务端配置（楼层列表 + 每楼层数据）驱动渲染
- 楼层协议：{ type, payload, style }——type 对应组件、payload 是数据、style 是布局参数——「楼层组件的开发规范」（props 契约 + 埋点统一）
- 容错设计：未知楼层类型跳过 + 配置错误不白屏（楼层级 error boundary——每个楼层组件 try/catch 降级）——配置驱动的健壮性
- 深水点：配置下发的时机与缓存——冷启动先渲染缓存的配置（上次楼层列表）+ 静默刷新——配置变更的「热生效」体验

```javascript
// 楼层注册表
const FLOORS = { banner: BannerFloor, kingkong: KingKongFloor, seckill: SeckillFloor };
// 页面渲染
async function loadFloors() {
  const cached = wx.getStorageSync('floors') || [];
  this.setData({ floors: cached });                 // 缓存先渲染
  const fresh = await api.floors({ page: 'home' });
  this.setData({ floors: fresh.filter((f) => FLOORS[f.type]) });   // 未知楼层过滤
  wx.setStorageSync('floors', fresh);
}
// WXML: <block wx:for="{{floors}}"><component-skeleton wx:if="{{item.type==='banner'}}" data="{{item.payload}}"/></block>
// 组件内: try/catch 数据异常 → 降级占位 (楼层级容错)
```
