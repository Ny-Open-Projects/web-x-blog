## R19-395：并发渲染边界：列表 key 与重排序动画的并发适配

**答**：
- 重排序动画的冲突：FLIP 动画需要「旧位置快照 → DOM 移动 → 反向播放」——并发渲染的 DOM 移动在 commit 内完成，动画库（react-flip-toolkit）读「commit 前后」的时机在并发下不稳定
- React 生态解法：LayoutGroup/layout 动画库（framer-motion 的 layoutId）在 React 语义内实现（监听 layout effect）——与并发兼容；自己写 FLIP 在 useLayoutEffect 里（同步 commit 内）也可
- key 稳定性的并发影响：渲染被丢弃重来时，「不稳定 key」会让动画/输入状态在两轮渲染间错乱——动画场景 key 纪律更严格
- React 19 View Transitions（实验）：`<ViewTransition>` 组件——并发渲染与转场的官方结合点，重排序动画声明式化
- 性能：动画只动 transform；重排序 + 动画在 500+ 项列表用虚拟列表（动画范围缩到可见区）

```jsx
// framer-motion 与并发兼容的 layout 动画
<motion.li layout key={item.id}>   {/* 稳定 key */}
// React 19 实验:
<ViewTransition>
  <ul>{items.map(i => <li key={i.id}>{i.text}</li>)}</ul>
</ViewTransition>
```
