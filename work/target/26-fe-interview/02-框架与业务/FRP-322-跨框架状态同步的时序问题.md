## FRP-322：跨框架状态同步的时序问题

**答**：
- 时序问题三源：批处理边界不同（React 自动批 vs Vue 微任务 flush vs Solid 同步）、订阅触发时机（渲染前/后）、写回环（A 写 → B 订阅更新 → B 写回 A）
- 回环防护：桥接层「来源标记」（消息带 source）+ 环检测（A→B→A 拒绝）——双向桥的死循环是跨框架头号 bug
- 同步点的选择：关键状态（登录态）在「事件源头立即写内核」（同步，无批处理差异）；UI 派生状态容忍一帧差异——「容忍延迟」的分级
- 调试手段：内核层打点（每次 set 记录 source/timeline）——跨框架时序问题必须在内核层观测（框架层各说各话）
- 与浏览器调度的关系：两侧最终都收敛到「微任务/宏任务」——批处理差异在微任务边界内可观测（rAF 内一致）

```javascript
// 桥接层防回环
function bridgedStore(store, from) {
  return {
    set(v, source) {
      if (source === 'bridge') return store.set(v);   // 桥来的更新不再回写
      store.set(v);
      bridge.notify(from, v);                          // 只通知对端
    },
  };
}
// 时序打点: kernel.set 记录 { source, t, value } — 跨框架时序问题的唯一观测点
```
