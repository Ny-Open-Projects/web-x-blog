## MP-361：小程序的客服与工单体系

**答**：
- 客服三通道：官方客服（button open-type="contact"——微信客服/客服消息）、自建 IM（WebSocket 会话）、电话（makePhoneCall）——触达与人力成本的权衡
- 客服消息能力：用户发消息后 48h 内可回复（模板/图文）——「被动触达窗口」的运营节奏
- 工单体系集成：页面内问题反馈表单 → 工单系统（带上下文：页面路径/设备/最近操作日志——「自动附上下文」提升排查效率）
- 会话上下文收集：进入客服前收集「用户最近行为轨迹」（路由栈/接口失败记录/报错）——「用户说不清楚问题」的技术补偿
- 深水点：官方客服与自建的选择——官方（零开发但能力受限）vs 自建（可控但要人力）——混合：先官方兜底 + 高价值场景自建

```javascript
// 上下文收集 + 转工单
async function openTicket(issue) {
  const trace = {
    route: getCurrentPages().map((p) => p.route).join(' → '),
    recentErrors: errorBuffer.last(5),               // 环形缓冲的最近错误
    device: wx.getDeviceInfo(),
  };
  await api.createTicket({ ...issue, trace });       // 工单自动带现场
}
// 官方客服入口: <button open-type="contact" session-from="{{traceJson}}">联系客服</button>
// session-from 携带上下文 → 客服侧可见
```
