## R19-233：服务端确认值与乐观值不一致怎么处理？
**答**：
- 服务端真值优先：action 返回服务端 state（或 revalidate 后重新拉取），乐观层清空后 UI 跳到真值——「以服务端为准」是底线。
- 跳变体验优化：差异大时用 toast/横幅说明（「下单成功但库存调整为 2」），而不是静默跳变让用户困惑。
- 部分成功：一次 action 改多项，服务端返回每项结果，前端按项合并（成功的更新、失败的回滚）——需要自定义 merge 而非整个 action 回滚。
- 设计启示：乐观 UI 适合「高成功率、低冲突」操作；强竞争场景（秒杀）乐观展示要弱化（按钮 loading 即可，不乐观改数字）。
