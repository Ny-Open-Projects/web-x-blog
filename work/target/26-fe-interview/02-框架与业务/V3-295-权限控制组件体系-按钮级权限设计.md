## V3-295：权限控制组件体系：按钮级权限怎么设计？
**答**：
- 权限模型：RBAC（角色→权限点）或 ABAC（属性规则）；前端持"权限点集合"（登录后接口下发），UI 控制按权限点判断。
- 三种控制形态：指令 `v-permission="'order:delete'"`（无权限移除 DOM）、组件 `<Auth code="order:edit">`（可传 fallback UI）、组合式 `const can = usePermission()`（逻辑判断，如路由守卫）。
- 指令 vs 组件取舍：指令干净但拿不到 fallback；组件可包含"无权限提示"插槽；逻辑判断适合超链接/异步分支。
- 语义选择：控制"可见性"还是"可操作性"——安全关键操作（删除/支付）必须**服务端鉴权**，前端控制只是体验优化。
- 权限缓存与刷新：权限点变化（角色切换）时全局刷新路由与界面，用事件或响应式 store 驱动。

```typescript
// 指令
export const vPermission: Directive = {
  mounted(el, { value }) { if (!can(value)) el.parentNode?.removeChild(el); },
};
// 组件 + 组合式
export function usePermission() {
  const userStore = useUserStore();
  return (code: string) => userStore.permissions.includes(code); // O(1) Set
}
const can = usePermission();
// 组件形态（带 fallback）
const Auth = defineComponent({
  props: { code: String },
  setup(props, { slots }) {
    return () => can(props.code)
      ? slots.default?.()
      : slots.fallback?.() ?? null;
  },
});
// ⚠️ 前端隐藏按钮 ≠ 安全：后端 DELETE /orders/:id 仍需鉴权中间件
```
