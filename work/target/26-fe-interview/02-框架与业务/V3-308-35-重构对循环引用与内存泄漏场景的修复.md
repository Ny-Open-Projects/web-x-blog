## V3-308：Vue 3.5 响应式重构对循环引用与内存泄漏场景做了哪些修复？
**答**：
- 旧版 effect 的 `deps` 数组与 dep 的 Set 双向持有，组件销毁要靠 `stop()` 遍历两边手动断链，遗漏路径（如 computed 被外部持有）会导致 dep 无法回收。
- 新版把订阅关系收敛为单一链表，dep 的头指针是唯一入口，effect 通过 `deps` 链表自清理，链表节点在断链后立即变成可回收的短命对象。
- 对 computed 的依赖同样按链表管理：computed 不再被订阅时会被标记并允许 GC，避免「计算过一次就常驻」的隐性泄漏。
- 大对象场景：旧版 cleanup 全量清空 Set 会产生大量中间对象；新版摘链式清理减少 GC 峰值。
- 排查手段：3.5 下仍建议用 EffectScope 组织非组件级副作用，`scope.stop()` 一键断链；用 heap snapshot 对比 effect/dep 数量验证。
```javascript
const scope = effectScope()
scope.run(() => { watch(data, render) })
// 组件销毁时
scope.stop() // 链表统一断链，无残留引用
```
