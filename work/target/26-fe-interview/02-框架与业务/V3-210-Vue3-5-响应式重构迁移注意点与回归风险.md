## V3-210：从 3.4 升级到 3.5 响应式重构有哪些迁移注意点与回归风险？
**答**：
- 无 API 破坏：官方承诺零 breaking change，风险集中在**依赖触发时序的边缘行为**，重点回归测试 watch/computed。
- 重点回归 1：依赖数组的边缘 case（`watch(() => arr[i])` 索引监听、`deep` 数组新语义误用）。
- 重点回归 2：computed 链的重算时机——3.5 中"没变的 computed 不再重跑 getter"，若 getter 里有副作用（不推荐写法）行为会变。
- 重点回归 3：使用内部私有 API（如直接 import reactivity 内部模块的库）需要同步升级版本。
- 工程手段：灰度发版 + watch 触发次数埋点对比 + 性能基准脚本（升级前后同页面 FP/交互耗时对比）。

```javascript
// 升级前自检脚本：getter 副作用会因重算次数变化而出问题
const count = ref(0);
const buggy = computed(() => {
  log.push('run');        // 副作用！3.5 中可能少跑，依赖此行为的逻辑需改造
  return count.value * 2;
});
// 回归测试建议（vitest 断言触发次数）
import { nextTick } from 'vue';
test('watch 触发次数', async () => {
  let n = 0;
  watch(count, () => n++);
  count.value = 1; count.value = 2; // 同 tick 批量
  await nextTick();
  expect(n).toBe(1); // 批量合并语义不变
});
```
