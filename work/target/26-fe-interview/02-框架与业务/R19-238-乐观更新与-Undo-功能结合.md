## R19-238：乐观更新怎么与撤销（Undo）结合？
**答**：
- 乐观 UI 天然适合「操作已生效」的心智：删除一条待办 → 立即消失 + 底部 Undo 条（5s 倒计时）。
- Undo 的实现不是「回滚乐观层」，而是发起一次反向 action（恢复记录）——乐观删除已经确认，撤销是新的写操作。
- 时序：确认窗口内（倒计时未结束）点 Undo → 取消尚未发出的删除 action 或调用恢复 action；窗口过了 → 服务端已删，恢复走「回收站/软删除」。
- 实现要点：软删除（deleted_at 字段）优于物理删除，撤销成本低；倒计时组件与 action 解耦。
- 面试表达：区分「乐观回滚」与「业务撤销」两个概念——前者是技术机制，后者是产品功能。
