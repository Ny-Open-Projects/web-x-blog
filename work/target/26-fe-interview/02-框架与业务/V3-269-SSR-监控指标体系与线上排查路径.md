## V3-269：SSR 监控指标体系与线上排查路径是怎样的？
**答**：
- 服务端指标：SSR 渲染耗时（P95）、渲染失败率/降级率、上游接口耗时与熔断触发次数、进程 RSS/事件循环延迟。
- 客户端指标：hydration 耗时、hydration mismatch 数、TTI/LCP、payload 体积。
- 桥接指标：SSR 降级为 CSR 的比例（响应头标记 + RUM 上报）；mismatch 会拖慢水合并触发整树重渲染，必须清零治理。
- 排查路径：慢渲染 → 先分"接口聚合慢"还是"组件渲染慢"（打点分层）→ 接口慢看熔断/并行化 → 组件慢看组件级缓存命中率。
- 工具：Nitro 的 performance hooks、Node clinic flame、OpenTelemetry trace 串联服务端到客户端。

```typescript
// 渲染分阶段打点
const timings = { fetch: 0, render: 0, serialize: 0 };
t.start('fetch'); const data = await gatherData(url); timings.fetch = t.end('fetch');
t.start('render'); const html = await renderToString(app, ctx); timings.render = t.end('render');
report({ url, ...timings, fallback: false });       // 上报 P95 与降级标记
// 客户端 hydration 计时
performance.mark('hydr-start');
app.mount('#app');
performance.mark('hydr-end');
performance.measure('hydration', 'hydr-start', 'hydr-end'); // RUM 上报
```
