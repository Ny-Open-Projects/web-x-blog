## FRP-317：跨框架微前端的通信总线

**答**：
- 总线设计原则：类型化消息（schema 校验）、发布/订阅 + 请求/响应双模式、消息溯源（source 标识）——防止「谁发的都不知道」的调试地狱
- 与全局状态的分工：总线传「事件」（发生的事），共享内核 store 传「状态」——混用导致时序 bug（事件先到还是状态先变）
- 生命周期对齐：子应用卸载时 unsubscribe 清理（总线侧按 source 批量清理）——僵尸订阅是微前端内存泄漏主因
- 请求/响应模式：总线 request(type, payload) → Promise（按 requestId 匹配）——跨框架调用（React 调 Vue 的服务）的同步语义
- 版本兼容：消息 schema 版本号 + 兼容层（新字段可选）——多团队独立发版的前提

```javascript
class MicroBus {
  #subs = new Map(); #reqs = new Map();
  emit(type, payload, source) {                       // 事件
    schemaCheck(type, payload);
    this.#subs.get(type)?.forEach((fn) => fn({ payload, source }));
  }
  request(type, payload, { timeout = 5000 } = {}) {   // 请求/响应
    const id = crypto.randomUUID();
    return new Promise((resolve, reject) => {
      this.#reqs.set(id, { resolve, reject });
      this.emit(`${type}:request`, { id, payload }, 'self');
      setTimeout(() => { if (this.#reqs.has(id)) { this.#reqs.delete(id); reject(new Error('timeout')); } }, timeout);
    });
  }
}
```
