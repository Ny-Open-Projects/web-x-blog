## R19-393：并发渲染边界：外部系统（Canvas/WebGL/第三方库）同步

**答**：
- 三方库与并发的冲突面：库在内部 setState（事件回调）——React 18+ 自动批处理覆盖；库直接操作 React 管理的 DOM——并发渲染的「可丢弃渲染」会让 DOM 回退，冲突
- 正确模式：三方库渲染到「React 树外」的容器（ref 挂载的独立 DOM/ECharts 实例），React 只管「数据 → 实例 API 调用」——单向数据流给命令式库
- useImperativeHandle 桥接：暴露命令式 API 给外部（播放器/地图）；外部事件 → React 状态用「回调 ref + useSyncExternalStore」保证撕裂安全
- 并发渲染下的 library 死锁：库 expect 「setState 立即生效」（同步读 DOM）——并发下 useEffect 后 DOM 才更新——提供「flushSync 逃生口」给不可改的库（最后手段）
- 检查清单：库的 DOM 是否在 React 树内、库的事件是否需要同步读布局、库是否有内部缓存依赖 DOM 状态——三条决定集成模式

```jsx
function Chart({ data }) {
  const ref = useRef(null);
  const inst = useRef(null);
  useEffect(() => {
    inst.current ??= echarts.init(ref.current);   // 库容器在 React 树内但 React 不管理其子 DOM
    inst.current.setOption({ series: [{ data }] }); // 数据→API 单向
  }, [data]);
  return <div ref={ref} style={{ height: 300 }} />;
}
```
