## FRP-310：跨框架的路由集成：单页多框架的导航统一

**答**：
- 统一原则：URL 是唯一真源——各框架路由都只是「URL 的视图」，跨框架导航一律走 history.pushState + 双方监听 popstate/pushState 拦截
- history 拦截方案：patch pushState/replaceState（派发自定义事件）——各框架路由器监听统一事件做同步；或用 single-spa 类「路由注册表」
- 嵌套路由边界：主框架管一级路由、子框架管二级——base 前缀约定 + 边界路由（子框架挂载/卸载由一级路由触发）
- 过渡与状态：路由切换的过渡动画跨框架（CSS view transition 统一）——框架各自的 transition 组件不跨界
- 深水点：路由参数与查询串的共享（跨框架页面传参）——URL query 是桥（可序列化天然安全），内存态传递不可靠

```javascript
// history patch: 统一导航事件
['pushState', 'replaceState'].forEach((m) => {
  const orig = history[m];
  history[m] = function (...args) {
    orig.apply(this, args);
    dispatchEvent(new CustomEvent('navigate', { detail: { url: location.href, method: m } }));
  };
});
// 双框架各自订阅:
addEventListener('navigate', (e) => router.sync(e.detail.url));
```
