## MP-312：小程序支付链路：从下单到结果确认

**答**：
- 支付链路：前端提交订单 → 服务端统一下单（预支付交易会话标识 prepay_id）→ 返回签名参数 → 前端 wx.requestPayment（timeStamp/nonceStr/package/signType/paySign）→ 回调
- 结果确认铁律：requestPayment 的 success/fail 不可信（用户支付中断/网络断）——「服务端查单为准」：支付后轮询订单状态接口 + 服务端接收微信异步回调双通道
- 签名安全：paySign 由服务端生成（前端只透传）——「前端参与签名」是安全漏洞（secret 暴露）
- 异常矩阵：用户取消（fail cancel）、支付超时、重复支付（服务端幂等：同一订单只生成一次预支付）、余额不足——每种异常的 UX（重试入口保留）
- 深水点：支付结果页的「等待确认」态——requestPayment 返回后先展示「处理中」，查单接口确认后跳成功页（防「支付成功但页面失败」的客诉）

```javascript
async function pay(orderId) {
  const params = await api.prepay(orderId);          // 服务端统一下单+签名
  try {
    await wx.requestPayment(params);                 // 唤起收银台
  } catch (e) {
    if (e.errMsg?.includes('cancel')) return toast('已取消支付');
    // 其他 fail: 不代表失败 — 继续查单
  }
  await pollOrderState(orderId);                     // 服务端查单为准
}
async function pollOrderState(orderId, tries = 10) {
  for (let i = 0; i < tries; i++) {
    const s = await api.orderState(orderId);
    if (s === 'PAID') return goSuccess(orderId);
    await sleep(1500);
  }
  goPending(orderId);                                // 「处理中」态兜底
}
```
