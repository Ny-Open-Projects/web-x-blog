## V3-460：编译期静态优化边界：静态提升、预字符串化与常量折叠

**答**：
- 静态提升（hoistStatic）：连续 ≥20 个静态节点被合并提升为常量；静态 vnode 提升到 render 函数外（只创建一次）——更新时直接复用引用，patch 跳过
- 预字符串化（stringifyStatic）：大量连续纯静态内容（如静态列表 >20 项）编译为 innerHTML 字符串一次性插入——省掉上千个 vnode 创建；代价是失去逐节点更新能力（纯静态无所谓）
- 静态判定边界：带绑定就不静态（哪怕是常量绑定 :class="'a'"？编译器识别「表达式恒定」才提升——变量访问一定不静态）；含 slot 内容的组件不提升
- 常量折叠：编译器对纯字面量表达式做求值折叠（{{ 'a'+'b' }} → 文本 'ab'）——与 Babel 的常量折叠同思路但范围更保守
- 深水点：静态提升与 SSR 交互——SSR 产物里静态内容也提升（作为字符串常量拼接），hydration 时跳过 diff

```javascript
// 编译前: <div><span>静态A</span><span>静态B</span>...20个</div>
// 编译后:
const _hoisted_1 = /* @__PURE__*/ _createElementVNode('span', null, '静态A')
// 20+ 连续静态 → 预字符串化
const _hoisted_2 = /* @__PURE__*/ _createElementVNode('div', { innerHTML: '<span>静态A</span>...' }, null, 1)
```
