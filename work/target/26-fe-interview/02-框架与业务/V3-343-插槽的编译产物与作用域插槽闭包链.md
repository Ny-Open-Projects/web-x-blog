## V3-343：插槽的编译产物与作用域插槽的闭包链是怎么走的？
**答**：
- 具名/默认插槽编译为 `createSlots(baseVnode, { header: () => [children], default: ({ item }) => [...] })`，每个插槽是「返回子 vnode 的函数」。
- 作用域插槽把插槽内容编译成带参数的函数：子组件渲染时传入数据 `slot({ item })`，函数体里引用父组件作用域变量——靠闭包而非传值。
- 响应性关键：插槽函数在**子组件渲染上下文**中被调用，但其中对父组件数据的依赖收集发生在调用时刻，所以父数据变化能触发子组件内该插槽区域更新。
- 与 2.x 区别：3.x 普通插槽与作用域插槽统一为函数；编译器对「不含动态内容」的插槽会跳过 createSlots 优化（static slots）。
- 坑：插槽函数内解构 props（`({ item }) => item.name`）丢响应性时（旧版本），需 `() => item.name` 保持 ref 访问；3.5 解构语义已修正。
