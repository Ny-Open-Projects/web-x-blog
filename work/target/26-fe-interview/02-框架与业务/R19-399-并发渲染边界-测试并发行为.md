## R19-399：并发渲染边界：如何测试并发行为

**答**：
- 测试工具链：testing-library 的 act()（flush 渲染）、fake timers + 手动推进（time切片）、`@testing-library/react` v16 的并发特性支持（wrap act 处理 transitions）
- 竞态测试模式：两个 promise 手动控制 resolve 顺序（deferred）——断言「旧请求结果不覆盖新状态」；Transition 打断测试（act 内触发更高优先级更新）
- StrictMode 测试：开发环境强制双执行——CI 跑 StrictMode 覆盖的组件测试（暴露 cleanup 缺失）
- 视觉回归的并发影响：渲染被丢弃重来的动画帧——视觉快照要固定「最终提交态」（等 transition 完成再截图）
- E2E 层：真实并发场景（快速点击/输入连打）的 Playwright 脚本——断言最终一致而不是中间态

```javascript
it('transition 被打断后最终一致', async () => {
  render(<Search />);
  await act(async () => { fireEvent.change(input, { target: { value: 'a' } }); });
  await act(async () => { fireEvent.change(input, { target: { value: 'ab' } }); });
  // 中途状态不确定, 只断言最终
  expect(await screen.findByText('ab results')).toBeInTheDocument();
});
```
