## FRP-359：跨框架的国际时间与本地化一致性

**答**：
- 时间一致性协议：内部 UTC（Date.now/ISO 串）、展示层本地化（Intl.DateTimeFormat 按用户时区）——「存储与展示分离」跨框架统一
- 时区来源：服务端下发（用户设置）> 浏览器推断——React/Vue 页面的时区必须同源（内核注入），否则跨框架时间显示不一致
- 水合一致：SSR 的时间字符串 vs 客户端格式化——服务端按「同一时区/语言」格式化（进入 HTML），客户端水合用相同配置（防 mismatch）
- 相对时间（x 分钟前）：内核实现（timestamp → 相对文案 + 定时刷新）——刷新调度在内核（各框架共享一个 ticker）
- 日历边界：Intl 的 locale 语义（周起始日/月名）——跨框架一致因为都走 Intl——自研格式化是反模式

```javascript
export function createI18nTime({ timezone, locale }) {
  const fmt = new Intl.DateTimeFormat(locale, { timeZone: timezone, dateStyle: 'medium', timeStyle: 'short' });
  return {
    format: (ts) => fmt.format(new Date(ts)),
    relative: (() => {
      const rtf = new Intl.RelativeTimeFormat(locale);
      return (ts) => {
        const diff = (ts - Date.now()) / 1000;
        const units = [['day', 86400], ['hour', 3600], ['minute', 60]];
        for (const [u, s] of units) if (Math.abs(diff) >= s || u === 'minute')
          return rtf.format(Math.round(diff / s), u);
      };
    })(),
  };
}
// 内核注入 (时区单源) → React/Vue 页面共享同一 formatter
```

**追问**：

1. SSR 水合时报时间文本不一致，怎么定位？→ 先比对服务端与客户端 formatter 的 `timeZone`、`locale` 是否同源，再看是否一端用了 `toLocaleString` 默认值；根因基本都是配置没从服务端注入，落到浏览器时区推断上。
2. 小程序或旧环境没有完整 Intl 怎么办？→ 需要 `@formatjs` 这类 polyfill，但它要带 full-icu 时区数据、体积很大；更实际的做法是服务端格式化好字符串下发，客户端只做相对时间的轻量计算。
3. 「x 分钟前」的定时刷新为什么会漂移或泄漏？→ 每个组件各自起 `setInterval` 会重复计时，页面隐藏时定时器被节流导致文案滞后；应统一到内核的单 ticker，并在 `visibilitychange` 回来时补算一次。
