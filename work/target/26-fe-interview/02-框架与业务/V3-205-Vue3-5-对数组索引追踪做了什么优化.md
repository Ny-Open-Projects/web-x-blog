## V3-205：Vue 3.5 对数组索引追踪做了什么优化？splice 场景为何变快？
**答**：
- 索引级 dep：对数组 `arr[i]` 的读取按**索引粒度**建立独立依赖，写 `arr[2]` 只触发依赖索引 2 的订阅者。
- 旧实现：数组用 length 作为聚合 dep + 修改方法重写，一次 push/splice 触发所有读数组的 effect。
- splice 优化：splice 触发时只对"被移动/删除区间"的索引 dep 做精准失效，配合 3.5 的增量 cleanup，成本从 O(n) 降到 O(变更区间)。
- length 依赖：读取 `arr.length` 时额外收集 length 的 dep，写入改变长度时触发它，语义更正确。
- 追问钩子：为什么数组不直接用 Proxy 全代理？代理已经全代理了，难点在于**重建/移动元素时的依赖迁移**，3.5 把迁移做到了链表级。

```javascript
// 索引级追踪效果演示
const arr = reactive([1, 2, 3, 4, 5]);
watchEffect(() => console.log('item0:', arr[0])); // 只依赖索引 0
watchEffect(() => console.log('len:', arr.length)); // 依赖 length
arr[1] = 99;      // 只触发"读 arr[1]"的 effect，item0/len 均不触发
arr.push(6);      // 触发 len 的 effect；item0 不触发
arr.splice(1, 1); // 索引 1~4 的 dep 迁移 + len 触发；读 arr[0] 的 effect 依然不动
```
