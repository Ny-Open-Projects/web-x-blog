## AIC-014：什么是 Vibe Coding？它和严肃工程化使用 AI 的边界在哪里？
**答**：
- Vibe Coding 指全靠自然语言对话驱动、不看代码细节、出了问题把报错原样丢回给 AI 的开发方式，适合原型与一次性脚本。
- 边界判断标准：代码要不要被长期维护、出错的代价多大。原型/demo 可以 vibe，生产代码必须有审查、测试与版本管理。
- Vibe Coding 在原型场景是生产力解放：半天出可点击 demo 给产品确认，砍掉的是「注定被推翻的精细化实现」。
- 生产化的迁移路径：原型验证通过后，AI 辅助重构 + 补测试 + 过 code review，转正不是「直接合并」而是「按正常门禁再走一遍」。
- 追问钩子：面试官常追「你怎么识别同事交付了 vibe 产物」——无测试、无错误处理、依赖堆砌、命名随性都是信号。

```text
同一个购物车需求的两种模式：

Vibe Coding（原型日）：
「帮我做个购物车页面，能加商品、能算总价就行」→ 直接跑起来给产品看 → 推翻 3 次
价值：1 天出 3 版交互原型，验证方向

工程化（转正日）：
需求文档 → 拆任务 → AI 生成 + 人审查（逐 diff）→ 补单测/边界用例 → CI 门禁 → PR 评审
禁止：把原型代码直接 merge 进 main
```
