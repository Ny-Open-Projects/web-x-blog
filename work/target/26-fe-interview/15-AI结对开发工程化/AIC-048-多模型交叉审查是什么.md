## AIC-048：什么是「多模型交叉审查」？什么场景值得花双倍成本用两个模型互相挑错？
**答**：
- 做法：模型 A 生成/初审，模型 B 以独立评审身份再审同一产物，意见冲突处交人工仲裁——用模型差异打破单一模型的盲区与偏好。
- 价值场景：核心支付/权限/数据迁移等高危改动、算法实现类代码（单一模型容易集体犯同一类错）、安全敏感逻辑。
- 不值得的场景：样式微调、文案改动、普通 UI 迭代——双倍成本买不来双倍价值。
- 工程要点：两个模型的 prompt 应**不同**（B 要带 A 的产出做对抗审查），且 B 不知道 A 的结论以防锚定；意见去重后分级输出。
- 追问钩子：仲裁记录本身是宝贵数据——冲突类型统计能定位两个模型的能力差异，反哺选型（呼应 AIC-024）。

```javascript
// 交叉审查编排
async function crossReview(diff, context) {
  const gen = await callModel('A', `实现：${diff}`);
  const reviewA = await callModel('A', reviewPrompt(gen, context));
  const reviewB = await callModel('B', reviewPrompt(gen, context)); // B 不看 A 的意见
  const conflicts = diffFindings(reviewA, reviewB);
  return { agreed: intersectFindings(reviewA, reviewB), conflicts, humanArbitration: conflicts.length > 0 };
}
```
