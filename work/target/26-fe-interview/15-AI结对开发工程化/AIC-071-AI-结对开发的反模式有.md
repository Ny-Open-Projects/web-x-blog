## AIC-071：AI 结对开发的常见反模式有哪些？「prompt 打补丁循环」为什么最危险？
**答**：
- 反模式清单：① prompt 打补丁循环 ② 无验收直接要代码 ③ 把 AI 的话当文档读（幻觉当事实）④ 一个会话塞十件事 ⑤ AI 改 A 破坏 B 不看关联 diff ⑥ 复制粘贴式 review（一眼不改直接合）。
- 打补丁循环：改不好就加一句"再改下 X"，十几轮后 prompt 变成补丁摞补丁的谜语，AI 在互相矛盾的指令里打转——比重新起一个结构化 prompt 更慢。
- 危险性：循环中人会「沉没成本化」，越改越不肯重来；同时每轮补丁都稀释早期约束，最后产出看起来能跑但已偏离需求。
- 解法：设「补丁上限」（如 3 轮），超过就回到任务描述层重新结构化；把失败轮次记入失败样本库。
- 追问钩子：反模式的共同根因是「把 AI 当黑盒许愿机」，解法的共同点是「把任务定义权收回到人手里」。

```javascript
// 补丁上限看门狗（会话治理小工具）
function patchGuard(maxPatches = 3) {
  let count = 0;
  return {
    patch() {
      if (++count > maxPatches) {
        throw new Error('补丁超限：请停止增量修补，重新结构化任务描述');
      }
    },
  };
}
```
