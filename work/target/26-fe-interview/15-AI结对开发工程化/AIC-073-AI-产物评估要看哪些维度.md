## AIC-073：评估 AI 代码产物质量要看哪些维度？和评估人类代码的评审标准有什么不同？
**答**：
- AI 特有维度：① 正确性幻觉率（编造 API/行为）② 风格一致性（是否贴合项目规范，AI 常带训练数据风格）③ 过度工程度（无中生有的抽象、多余防御代码）④ 安全性（默认凭据、宽松校验）⑤ 可理解性（注释与代码是否相符，AI 注释常「美化现实」）。
- 与人评不同点：人评审主要看「意图是否合理」，AI 产物意图来自 prompt，评审重点变成「实现是否忠于需求 + 有没有夹带私货」；夹带私货（顺手重构、加了没要的功能）是 AI 高频问题。
- 度量方式：抽样深评（每 PR 抽 1~2 个文件按五维度打分）+ 结果追踪（7 天存活率、回滚率）结合，别只看当下。
- 分任务评估：模式化任务看「一次通过率」，设计类任务看「方案采纳率」，两类指标不可混用。
- 追问钩子：评估结果要闭环到 prompt/规则迭代（AIC-038），单打分不改进等于白评。

```javascript
// AI 产物五维评分卡
const scoreCard = (code, ctx) => ({
  correctness: score(code, '无幻觉 API、逻辑忠于需求'),      // 1-5
  consistency: score(code, '符合项目风格与既定抽象层级'),
  simplicity: score(code, '无过度工程与夹带功能'),
  security: score(code, '无默认凭据/宽松校验/注入面'),
  clarity: score(code, '注释与实现相符、命名贴合领域语言'),
  verdict: () => '总分 < 18 → 打回重生成并记录失败样本',
});
```
