## AIC-179：笔试：实现一个日志脱敏器：多层规则（密钥/PII/内网）、路径感知白名单与审计计数？
**需求**：实现 `LogMasker`：
- `mask(text, { source })`：按规则替换敏感信息为占位符；source（如 'trace'/'audit'）可声明额外白名单；
- 规则有序：先高置信（sk- 密钥）后低置信（数字串），低置信规则在已替换文本上运行时必须跳过占位符；
- `audit()` 返回各规则命中计数（合规审计需要）；
- 幂等：对已脱敏文本再次 mask 不产生二次破坏。

```javascript
class LogMasker {
  #rules = [
    { id: 'key', re: /\b(?:sk-|ghp_)[A-Za-z0-9]{16,}\b/g, to: '[KEY]' },
    { id: 'jwt', re: /\beyJ[\w-]+\.[\w-]+\.[\w-]+\b/g, to: '[JWT]' },
    { id: 'phone', re: /1[3-9]\d{9}/g, to: '[PHONE]' },
    { id: 'intranet', re: /\b(?:10|192\.168)\.\d{1,3}\.\d{1,3}\b/g, to: '[IP]' },
  ];
  #hits = new Map();
  #sourceAllow = { trace: [], audit: ['[PHONE]'] }; // audit 场景手机号占位符已合规

  mask(text, { source = 'trace' } = {}) {
    let out = text;
    const allowed = this.#sourceAllow[source] ?? [];
    for (const r of this.#rules) {
      if (allowed.includes(r.to)) continue;          // source 级白名单
      const placeholder = `\u0000${r.id}\u0000`;     // 防后续规则误伤占位符
      out = out.replace(r.re, (m) => {
        this.#hits.set(r.id, (this.#hits.get(r.id) ?? 0) + 1);
        return placeholder;
      });
    }
    // 最后统一还原占位符为目标占位文本（幂等：再次进入时无原始匹配）
    for (const r of this.#rules) {
      out = out.replaceAll(`\u0000${r.id}\u0000`, r.to);
    }
    return out;
  }
  audit() {
    return Object.fromEntries([...this.#hits.entries()].sort((a, b) => b[1] - a[1]));
  }
}

// 测试
const lm = new LogMasker();
const raw = '用户 13812345678 调用失败，key=sk-abcdefghij12345678，来自 10.0.1.5';
console.log(lm.mask(raw));
// 用户 [PHONE] 调用失败，key=[KEY]，来自 [IP]
console.log(lm.mask(lm.mask(raw)));  // 幂等，结果一致
console.log(lm.audit());             // { key: 1, phone: 1, intranet: 1 }
```

**评分点**：
1. 规则顺序：高置信先跑，防止数字类规则（手机号/ID）把密钥片段提前打碎；
2. 幂等性处理：占位符被后续规则误伤是常见 bug（如 [IP] 里没有数字但 [PHONE] 数字形态可能被内网规则匹配），两阶段替换是标准解法；
3. source 级白名单：不同日志通道合规等级不同；
4. audit 计数是合规举证的硬要求（AIC-130）；
5. 追问：真实场景应支持自定义规则热加载与规则命中采样上报。
