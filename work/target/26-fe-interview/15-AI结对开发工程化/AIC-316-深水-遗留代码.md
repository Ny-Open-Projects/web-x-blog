## AIC-316：在遗留代码（无测试无文档）上用 AI 开发，策略是什么？
**答**：
- 先包再改：让 AI 给改动区域补「特征测试」（characterization tests）锁定现状行为，再动刀。
- 改动策略：新逻辑外置（新增文件/包装层）优先于就地修改老代码。
- 文档自举：AI 边改边产出「模块现状说明」，为下次任务积累上下文。
- 风险隔离：遗留区改动要求更高的评审档位 + 更全的回归验证。

```javascript
// 特征测试：锁定遗留行为（哪怕是怪行为）
it('遗留规则：订单金额 0.01 以下按 0 处理（历史怪癖）', () => {
  expect(legacyCalc(0.005)).toBe(0); // 先记录现状，重构后才允许讨论是否修
});
```
