## AIC-383：300 个依赖的治理（升级/淘汰/替换），如何让 AI 变成持续工作？
**答**：
- 依赖画像：AI 生成每个依赖的画像（维护活跃度/issue 响应/替代品/仓库内使用面）。
- 风险队列：按「维护停滞 × 使用面广」排优先级，AI 输出替换方案（含迁移成本估计）。
- 渐进替换：AI 生成适配层（新依赖 API 包装成旧接口），逐步迁移调用点。
- 新增守门：新增依赖必须过「画像检查」（活跃度/license/体积/重复功能），AI 自动出评估。

```javascript
const depGovernance = {
  profile: 'AI 生成：活跃度/替代品/使用面',
  queue: '停滞 × 广使用 → 优先替换（附迁移成本）',
  strategy: '适配层渐进替换调用点',
  intake: '新依赖 → 自动画像评估 → 审批',
};
```
