## AIC-102：如何给 Agent 写一份好的「任务卡」？和 AIC-019 的好任务描述有什么升级？
**答**:
- AIC-019 讲的是「一句话任务怎么描述清楚」，任务卡是 agent 时代的完整升级版：描述 + 上下文指引 + 约束 + 验收 + 边界 + 回滚说明，六段结构。
- 上下文指引比堆代码更省窗口：不贴文件全文，写「先读 packages/goods/hooks/usePagination.ts，理解现有分页协议」——让 agent 自己按地图（AIC-093）取上下文。
- 边界段专治「夹带私货」：显式写「允许改动的文件白名单」「禁止顺手重构无关代码」。
- 回滚说明：任务独立分支命名约定、commit 格式（AIC-097），让产出天然可回滚。
- 追问钩子：任务卡模板应该存进规则文件体系，agent 遇到描述不合格的任务卡时应该「反问补全」而不是硬猜——这本身可以写成规则。

```markdown
<!-- 任务卡模板（ai/templates/task-card.md） -->
# 任务：{一句话}
## 上下文指引：先读 {files}，理解 {protocol}
## 约束：只允许改 {whitelist}；禁止 {forbidden}
## 验收：{测试命令 + 行为清单}
## 边界：遇到不确定时停下来提问，禁止猜测性实现
## 交付：分支 agent/{id}，commit 格式见 CODEMAP
```
