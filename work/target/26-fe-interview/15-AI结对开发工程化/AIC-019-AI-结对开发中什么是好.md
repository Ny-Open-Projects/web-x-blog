## AIC-019：AI 结对开发中，什么是一个「好任务描述」？给出可复用的描述模板。
**答**：
- 好描述四要素：目标（做什么）、上下文（相关文件与约束）、验收（怎么算对）、边界（不许做什么）。
- 常见坏描述是只有目标：「加个搜索功能」——AI 会在搜索策略、防抖时机、UI 形态上全部自行假设。
- 约束要写「可判定」的：禁止用「注意性能」这种模糊词，写「接口数据超过 100 条时分页，禁止一次性渲染」。
- 任务间要声明依赖：「基于上一步生成的 useCart」防止 AI 重新发明一套。
- 追问钩子：可对比写 PRD 的能力，说明「描述任务的能力」成了新核心技能。

```markdown
<!-- 任务描述模板 -->
# 目标
在商品列表页新增关键字搜索，仅搜当前页前端缓存的 200 条数据。
# 上下文
- 页面：src/pages/goods/List.tsx
- 数据源：useGoodsList() 返回 { list, loading }（见 @src/hooks/useGoodsList.ts）
# 验收
- 输入去抖 300ms，空关键字恢复全量
- 不区分大小写，命中字段：name、skuId
- 现有单测全绿，并新增至少 3 个搜索用例
# 边界
- 禁止修改 useGoodsList 与后端接口
- 禁止引入搜索类新依赖
```
