## AIC-301：衡量「AI 结对开发团队提效」的北极星指标应该选什么？为什么不是代码行数？
**答**：
- 候选北极星：「变更前置时间（PR open→merge）」或「人均每周有效交付的用户价值单元」——端到端周期最能反映提效。
- 代码行数是反指标：AI 让行数膨胀但价值不变，行数激励产生垃圾代码。
- 配二级指标构成指标树：质量（缺陷率/返工率）、采纳（AI 建议采纳率）、周期（TTM）。
- 先建基线再上工具：没有基线的提效宣传都是自说自话。

```javascript
const metricTree = {
  north: 'PR cycle time（open→merge 中位数）',
  children: {
    quality: ['bug escape rate', 'reworkRatio(AI 产出返工比例)'],
    adoption: ['aiAcceptRate', 'aiTaskShare'],
    speed: ['ttm', 'leadTimeToFix'],
  },
  anti: 'loc / commits（行数激励产出膨胀）',
};
```
