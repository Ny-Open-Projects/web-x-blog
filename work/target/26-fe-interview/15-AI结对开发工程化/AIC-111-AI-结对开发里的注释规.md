## AIC-111：AI 结对开发里注释规范有什么新要求？「给 AI 看的注释」和「给人看的注释」要分吗？
**答**：
- 新要求一：注释成为「AI 的上下文资产」——结构化注释（JSDoc 类型、意图说明、TODO 的边界条件）直接影响补全与生成质量（AIC-022 已讲触发技巧，本条讲团队规范层面）。
- 新要求二：注释真实性审查——AI 会生成「看似解释代码实则美化」的注释（AIC-073 的可理解性维度），review 时要验证注释描述与行为一致。
- 要不要分？不分的理由：维护两套注释成本高且会漂移。实践折中：一套注释两种读者都要照顾——写「意图与约束」（人和 AI 都需要），不写「复述代码」（AI 自己看得懂代码，写了纯属噪音）。
- 规范条目：公共 API 必须有意图注释 + 不变量说明；hack 类代码必须写「为什么 hack + 何时可以移除」——这类注释是 AI 后续修改时不破坏意图的关键。
- 追问钩子：注释也是规则失效的排查点——AI 违反约定时先检查相关注释是否存在（缺注释的意图 AI 只能猜）。

```javascript
/**
 * 计算优惠券可用金额（意图：与后端营销服务保持同一口径）
 * 不变量：结果永远 >= 0；多券叠加时只取最优，不做叠加计算
 * HACK: 临时对 giftCard 返回 0（营销侧口径未定），2026 Q2 移除
 */
export function calcDiscount(cart, coupons) { /* ... */ }
```
