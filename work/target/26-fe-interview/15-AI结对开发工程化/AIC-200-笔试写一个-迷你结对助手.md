## AIC-200：笔试：实现一个迷你结对助手：串联模板渲染→上下文预算→调用→校验→重试→报告的完整管线？
**需求**：实现 `PairAssistant.run(task)`，把本专题各笔试模块串成管线：
1. 模板渲染（AIC-145）渲染任务 prompt；2. 上下文预算裁剪（AIC-148 思路）；3. 调用 LLM（带重试，AIC-161 思路）；4. 输出校验（AIC-146 JSON 校验）；5. 校验失败带修复提示重试（≤2 次）；6. 输出任务报告（宣称 vs 实际、耗时、tokens）；
- 任何一步抛错都要产出失败报告而非裸异常；
- 全程 trace id 贯穿。

```javascript
import { randomUUID } from 'crypto';

class PairAssistant {
  constructor({ llm, deps }) { this.llm = llm; this.deps = deps; } // deps: render/fitContext/parseAiJson

  async run(task) {
    const traceId = randomUUID().slice(0, 8);
    const t0 = Date.now();
    const report = { traceId, steps: [], ok: false };

    try {
      // 1. 渲染
      const prompt = this.deps.render(task.template, task.vars);
      this.#log(report, 'render', { len: prompt.length });

      // 2. 预算裁剪（简化：按优先级保留）
      const ctx = this.deps.fitContext(task.context ?? [], 6000);
      this.#log(report, 'context', { kept: ctx.kept.length, dropped: ctx.dropped.length });

      // 3-5. 调用 + 校验 + 修复重试
      let messages = [{ role: 'user', content: prompt + '\n' + ctx.kept.map(k => k.content).join('\n') }];
      let parsed = null, lastErr = null;
      for (let attempt = 0; attempt < 3; attempt++) {
        const res = await this.llm(messages, { temperature: 0 });
        report.tokens = res.usage;
        parsed = this.deps.parseAiJson(res.text, task.schema);
        if (parsed.ok) { this.#log(report, 'validate', { attempt, pass: true }); break; }
        this.#log(report, 'validate', { attempt, pass: false });
        messages.push({ role: 'assistant', content: res.text });
        messages.push({ role: 'user', content: parsed.repairPrompt });  // 修复提示回喂
        lastErr = parsed;
      }
      if (!parsed?.ok) {
        report.ok = false; report.reason = '校验 3 轮未过';
        report.repairHints = lastErr?.repairPrompt;
        return report;
      }

      // 6. 成功报告：宣称 vs 实际
      report.ok = true;
      report.data = parsed.data;
      report.claimsMatched = (parsed.data.changedFiles ?? [])
        .every(f => ctx.kept.some(k => k.key === f) || true); // 简化：真实场景对照 diff
      report.durationMs = Date.now() - t0;
      return report;
    } catch (e) {
      report.ok = false; report.reason = String(e);
      report.durationMs = Date.now() - t0;
      return report; // 失败也产出报告，不裸抛
    }
  }
  #log(report, step, detail) { report.steps.push({ step, detail, at: Date.now() }); }
}

// 测试：模拟 llm 第一轮坏 JSON、第二轮好 JSON
const deps = {
  render: (t, v) => t.replace('{{task}}', v.task),
  fitContext: (items, budget) => ({ kept: items, dropped: [] }),
  parseAiJson: (text, schema) => text.startsWith('{') && JSON.parse(text)
    ? { ok: true, data: JSON.parse(text) }
    : { ok: false, repairPrompt: '请输出合法 JSON' },
};
let call = 0;
const llm = async () => ++call === 1
  ? { text: '我觉得大概是好的', usage: 100 }
  : { text: '{"changedFiles": ["a.ts"]}', usage: 200 };
new PairAssistant({ llm, deps }).run({
  template: '任务：{{task}}', vars: { task: '修 bug' },
  context: [{ key: 'a.ts', content: 'code' }],
  schema: { changedFiles: { type: 'array' } },
}).then(r => console.log(r.ok, r.steps.map(s => s.step)));
// true: ['render','context','validate','validate']
```

**评分点**：
1. 管线各环节职责清晰且可替换（deps 注入）——这是对整专题架构能力的综合考察；
2. 校验失败走「修复提示回喂」而非直接重新生成（增量修复省 token）；
3. 失败也产出结构化报告（trace/steps/reason）——失败报告驱动人工接管（AIC-083/098）；
4. trace id 贯穿全程（可观测性）；
5. 宣称 vs 实际的对账意识（claimsMatched）：AI 报告不可盲信，与 AIC-098 呼应；答辩时能画出管线图并说出每步的失败出口即满分。
