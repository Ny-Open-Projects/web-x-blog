## AIC-025：什么是结构化 Prompt？给 AI 写代码任务时为什么推荐「角色 + 约束 + 输入 + 输出格式」四段式？
**答**：
- 结构化 Prompt 是把需求拆成固定段落（角色/目标/约束/输入/输出格式），让模型按「槽位」理解任务，而不是靠一段自然语言猜重点。
- 四段式各有作用：角色定能力域（你是资深 React 工程师）、约束定红线（不改公共 API、TypeScript strict）、输入定事实（贴相关代码）、输出定验收（只输出 diff 或完整文件 + 说明）。
- 最大的收益是**可复用与可对比**：把变量抽出来就是模板，能版本化、能 A/B，出问题时能定位是哪一段没写清。
- 输出格式段尤其关键：明确「先给方案要点，再给代码，不要复述需求」，可显著减少模型的废话和漏改。
- 追问钩子：结构化过度也会失效——约束超过 10 条模型会丢，应按优先级排列并定期裁剪（呼应规则文件精简原则）。

```javascript
// 一个可复用的四段式任务模板（团队存进 repo，prompt 也进版本管理）
const taskTemplate = `
# 角色
你是资深前端工程师，熟悉 {{stack}}。

# 约束
- TypeScript strict，禁止 any
- 只改 {{scope}} 内文件，不引入新依赖
- 保留既有注释与导出签名

# 输入
<code>
{{relatedCode}}
</code>
需求：{{requirement}}

# 输出
1. 修改要点（3 条以内）
2. 完整修改后的文件内容
`;
```
