## AIC-113：给 AI 用的「依赖图」怎么生成与消费？比代码地图更细一层的信息怎么组织？
**答**：
- 生成：确定性工具产出——madge/dependency-cruiser 扫 import 关系，输出 JSON；消费时按任务裁剪（目标文件的 2 度邻居以内），不要整图灌入。
- 内容增强：原始依赖图只有「谁引用谁」，要叠加 AI 需要的语义——边的类型（runtime/type-only/样式）、节点的变更风险等级（核心/边缘）、模块的稳定性承诺（公共 API or 内部实现）。
- 消费场景：改公共模块时自动拉取「调用方清单」进上下文（AIC-046 的工程化）；评估影响面时输出「改这个文件会影响 N 个调用点，其中 M 个是核心路径」。
- 更新机制：CI 上每次合并重扫，依赖图是产物不是手写文档——手写的会腐烂，扫出来的永远新鲜。
- 追问钩子：依赖图 + 变更风险标注 = 「AI 改动的爆炸半径计算」，这是 AIC-187（笔试变更影响分析器）的原型。

```javascript
// 依赖图消费：变更影响面查询
const depGraph = loadJson('dep-graph.json'); // CI 产出
function blastRadius(file, { depth = 2 } = {}) {
  const seen = new Set([file]);
  let frontier = [file], callers = [];
  for (let d = 0; d < depth; d++) {
    const next = [];
    for (const f of frontier) {
      for (const c of depGraph.reverse[f] ?? []) {
        if (!seen.has(c)) { seen.add(c); next.push(c); callers.push(c); }
      }
    }
    frontier = next;
  }
  const core = callers.filter(c => depGraph.risk[c] === 'core');
  return { total: callers.length, core, verdict: core.length ? 'NEED_EXTRA_REVIEW' : 'OK' };
}
```
