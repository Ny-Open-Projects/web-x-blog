## AIC-140：AI 产出的功能上线，灰度验证流程和人工功能有区别吗？「AI 特有的灰度指标」有哪些？
**答**:
- 流程相同：按比例放量、观察指标、可回滚——灰度工程不因代码来源而变。
- AI 特有指标：① 错误模式分布——AI 产出的报错聚类（它常犯的错和人不完全一样，如幻觉 API 的运行时 undefined）② 性能特征——AI 倾向过度渲染/多余轮询，监控渲染次数与网络请求量 ③ 边界数据暴露率——AI 对极端输入的遗漏，要在灰度期加大脏数据注入。
- 观察期策略：AI 产出的功能灰度期加倍（人工功能 1 周的话给 2 周），回滚触发阈值收紧——因为「AI 产出的长尾风险」分布尚未有团队经验数据。
- 回滚预案差异：AI 产出必须可精确回滚到任务前快照（AIC-097），人工功能通常不需要这么细。
- 追问钩子：核心观点是「灰度是给未知分布买保险」——人工功能的故障分布团队有直觉，AI 产出的分布是新的，所以要更多观察、更严阈值。

```javascript
// AI 产出的灰度监控指标组
const aiGrayMetrics = {
  errorCluster: '错误日志按 agent 任务聚合聚类',      // 错误模式分布
  renderCount: '核心页面渲染次数 p95',                // 过度渲染检测
  polling: '每分钟网络请求数 p95',                     // 多余轮询检测
  edgeError: '边界数据用例的报错率',                  // 边界遗漏
  rollbackThreshold: { human: 'err>1%', ai: 'err>0.5%' }, // 阈值收紧
};
```
