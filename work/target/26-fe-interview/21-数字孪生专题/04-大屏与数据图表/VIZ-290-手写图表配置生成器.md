## VIZ-290：手写图表配置生成器：从交互操作反推配置代码

**答**：
- 「图表编辑器」场景：用户拖拽配置（选字段/改类型/调样式）→ 实时生成可复制的配置代码（声明式 option）。
- 实现：内部状态（声明式 option）为唯一真源 → 渲染与代码生成双输出（同一 option 序列化为代码字符串）。
- 价值：低代码搭图表——用户操作即配置，配置可保存复用。

```javascript
class ChartConfigBuilder {
  constructor() { this.option = { series: [], axes: {} }; }
  setSeries(type, field, style) {                           // 用户拖拽 → 更新 option
    this.option.series.push({ type, field, ...style });
    return this;
  }
  setAxis(axis, cfg) { this.option.axes[axis] = cfg; return this; }
  toOption() { return structuredClone(this.option); }       // 数据输出
  toCode() {                                                // 代码生成
    return `createChart({
  series: ${JSON.stringify(this.option.series, null, 2)},
  axes: ${JSON.stringify(this.option.axes, null, 2)},
})`;
  }
  render(renderer) { return renderer.paint(this.option); }   // 渲染输出（同一 option）
}
// 双输出一致性：代码可执行复现当前图表——「所见即所得」的配置编辑器
```

**追问**：

1. 生成的配置里有函数（formatter、tooltip），JSON 序列化会把函数丢掉，怎么处理？ → 数据配置走序列化，函数类配置走命名映射表，代码里输出成引用预置函数的字符串，而不是把函数体内联进去。
2. option 是唯一真源，但用户在代码编辑器里手改了代码，怎么反向同步回 UI？ → 要么解析代码成 AST 再做双向绑定，要么明确单向：代码只读导出，改配置只能回到 UI，别做半吊子双向。
3. 大屏图表数据几万行，生成代码动辄上千行，可读性怎么保证？ → 数据与配置分离，代码里引用数据集 id 或变量，不内联全量数据，配置只留结构。
