## SCN-653：数字孪生大屏整体架构怎么设计？
**答**：
- 四层链路：数据接入层（IoT 消息/业务库 → 时序数据库）→ 数据服务层（聚合/降采样/推送网关）→ 渲染层（3D 场景引擎 + 2D 图表）→ 交互层（告警联动/下钻）。前端主战场在后两层。
- 渲染选型：3D 场景用 three.js/UE 推流（重场景推流、轻场景 WebGL），2D 图表 ECharts，两者通过「设备 ID」做联动桥。
- 数据契约：设备状态统一事件模型（deviceId/type/value/ts/quality），渲染层只认契约不认识具体业务。
- 分辨率适配：设计稿分辨率（如 3840×2160）等比缩放适配，图表重排与 3D 视角分离处理。
- 追问钩子：为什么数据服务层必须做降采样——大屏 60fps 渲染，设备万级时全量推送会把前端打爆，推送侧就要聚合。

```javascript
// 统一事件契约
interface TwinEvent {
  deviceId: string;
  type: 'state' | 'metric' | 'alarm';
  value: number | string | object;
  ts: number;
  quality: 'good' | 'stale' | 'offline';   // 数据质量标注（陈旧数据变灰）
}
// 渲染层订阅
gateway.subscribe(['metric.temperature', 'alarm.*'], (events) => {
  batchRender(events);                     // 批量合帧渲染，见 SCN-655
});
```
