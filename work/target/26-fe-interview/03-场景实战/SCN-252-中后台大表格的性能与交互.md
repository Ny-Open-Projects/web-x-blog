## SCN-252：中后台万行大表格（排序/筛选/行内编辑），性能怎么保障？

**答**:
- 数据策略：服务端分页/排序/筛选（万行数据不过前端——默认原则）、全量场景（导出/分析场景才前端全量，用 Web Worker 排序筛选不卡 UI）、增量更新（轮询/WebSocket 只更新变化行）。
- 渲染优化：虚拟滚动（行虚拟化+列虚拟化，万行×50 列）、行 memo（行数据引用不变不重渲——注意不可变更新）、单元格渲染瘦身（重单元格懒渲染：进入视口才渲染富内容）。
- 行内编辑：编辑态局部化（只有编辑行是受控输入，其他行静态渲染）、校验即时性（单元格 blur 校验+行级聚合校验）、批量编辑（勾选行→批量修改面板，避免逐行编辑）、脏数据管理（未保存变更集合+离开提示）。
- 交互完整性：排序筛选状态与 URL 同步（可分享/刷新保持）、列宽/列序用户自定义持久化、键盘导航（Excel 式方向键，SCN 已有则引用）。

```javascript
// 虚拟化 + 行 memo
const Row = memo(({ row, columns }) => (
  <tr>{columns.map(c => <Cell key={c.key}
    value={row[c.key]} editable={c.editable} />)}</tr>
), (a, b) => a.row === b.row && a.columns === b.columns);
// 编辑态局部化：
// <EditableRow row={editingRow}/>（受控）
// <Row row={row}/>（静态，其余行）
// Web Worker 全量排序（导出场景）：
// worker.postMessage({ data, sortKey }) → 有序索引回传。
// 脏数据：dirtyRows: Map<rowId, patch>，
//   beforeunload → confirm 提示。
```
