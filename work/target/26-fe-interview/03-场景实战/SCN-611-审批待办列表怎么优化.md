## SCN-611：审批待办列表怎么优化？
**答**：
- 服务端排序分页：待办量大（管理者数千条），排序/过滤全在服务端，前端虚拟滚动 + 游标分页；默认排序按「超时风险 + 到达时间」。
- 红点与计数：待办总数走轻量计数接口（低频轮询或推送），列表数据懒加载——红点数字更新不等列表。
- 批量操作：多选批量同意/转交/导出，批量操作进度条 + 失败项明细（部分成功是常态，逐项幂等）。
- 实时性：新待办 WS 推送插头（带「N 条新待办」提示，不打断当前操作）；处理完成后本地移除 + 计数 -1。
- 追问钩子：批量同意中一条被别人先处理了怎么办——乐观锁（version）逐条提交，冲突项跳过并在结果里标注「已被处理」。

```javascript
async function batchApprove(ids) {
  const results = { ok: [], conflict: [], failed: [] };
  for (const id of ids) {                          // 逐条幂等提交（服务端要求）
    const item = store.get(id);
    try {
      await api.post(`/approve/${id}`, { version: item.version });
      results.ok.push(id);
    } catch (e) {
      if (e.code === 'VERSION_CONFLICT') results.conflict.push(id);   // 已被处理
      else results.failed.push(id);
    }
    updateProgress(results.ok.length + results.conflict.length + results.failed.length);
  }
  showResult(results);                             // 部分成功明细
}
```
