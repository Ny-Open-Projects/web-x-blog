## SCN-768：审核队列实时性怎么设计？
**答**：
- 推拉结合：新任务进队推送「信号」（队列数 +1，类型），审核员领取时才拉内容；列表数据不随每条新任务全量刷新。
- 积压看板联动：队列深度推送更新团队积压大屏；个人视图只推「分配给我技能组」的变化。
- 派单竞态：领取是服务端原子操作，前端领取失败（被抢）自动领取下一条并提示。
- 离线容忍：审核工作不依赖实时推送（领取拉模式），推送只做效率增强——推送挂了不影响审核主流程。
- 追问钩子：为什么领取用「主动拉」而不是服务端「推任务」——主动领取天然解决竞态（原子弹出）、尊重个人节奏、断线可重试；强推需要复杂的任务重分配机制。

```javascript
function queueChannel(ws) {
  ws.on('queue-update', ({ category, depth }) => {
    updateBadge(category, depth);                    // 只更新角标
    if (depth > 0 && idle()) toast('队列有新任务');
  });
  async function claim() {
    const item = await api.post('/queue/claim', { category: currentCategory() })
      .catch(() => claimRetry());                    // 被抢占自动重试下一条
    if (item) loadWorkbench(item);
  }
}
```

## 追问（补充）

**边界与易错**：

- `claim()` 返回 409/410 表示已被抢占，必须继续拉下一条，直接 `loadWorkbench(null)` 会把正在看的工作台清空。
- `ws.on('queue-update')` 只更新角标 `depth`，不能在回调里顺带 `reloadList()`，否则每条新任务都触发一次全量刷新。
- 断线重连后必须补拉一次 `GET /queue/summary`，WebSocket 断开期间的推送全部丢失，角标会长期失真。

**追问**：

1. 推送通道抖动，审核员一直显示空闲却看不到任务怎么办 → 拉模式兜底：空闲超过 N 秒或点击角标时主动拉 summary，推送只做提速不做唯一数据源。
2. 同一任务被两人同时领取，怎么保证只有一个成功 → 领取走 `UPDATE ... WHERE status='pending'` 带乐观锁，影响行数为 0 即抢占失败，前端静默重试下一条。
3. 大促积压到十万条，工作台怎么不卡 → 列表用游标分页 + 虚拟滚动只渲染可视区；积压大屏走独立聚合接口按分钟刷新，不与审核员工作台共享查询。
