## SCN-626：流程调试与沙箱怎么做？
**答**：
- 模拟运行：发布前用测试数据（不同金额/部门）跑沙箱实例，预演实际路径与审批人解析结果——设计器内置「试跑」按钮，不产生真实待办。
- 调试信息：试跑结果逐步展示（每节点命中哪个条件/审批人解析出谁/超时策略是什么），错误（审批人解析为空）直接标在节点上。
- 边界覆盖：试跑面板提供「边界用例集」（最小金额/最大金额/无部门/离职审批人），一键批量试跑并汇总结果矩阵。
- 灰度发布：新流程定义先对指定部门生效（灰度），观察一段无异常后全量；回滚到上一版本一键完成。
- 追问钩子：审批人解析为空为什么要在设计器期暴露——运行期才发现「找不到审批人」会导致流程卡死，属于设计器必须拦截的高危错误。

```javascript
async function sandboxRun(flowId, cases) {
  const matrix = await Promise.all(cases.map(c =>
    api.post(`/flow/${flowId}/sandbox`, { formData: c, dryRun: true })
      .then(r => ({ case: c, ok: true, path: r.path }))
      .catch(e => ({ case: c, ok: false, error: e.code }))));
  const failures = matrix.filter(m => !m.ok);
  highlightDesignErrors(failures);                 // 错误标在节点上
  return { matrix, pass: failures.length === 0 };
}
const BOUNDARY_CASES = [
  { amount: 0 }, { amount: 999999999 },            // 最小/最大
  { dept: null },                                  // 无部门
  { forceVacantApprover: true },                   // 审批人缺勤/离职
];
```
