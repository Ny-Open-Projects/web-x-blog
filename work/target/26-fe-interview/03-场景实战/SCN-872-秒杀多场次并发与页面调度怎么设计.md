## SCN-872：多场次并发怎么设计？
**答**：
- 场次时间线：一页多场次（Tab/时间轴切换），未开始场次显示预告（可订阅提醒），进行中场次可抢，结束场次显示结果——状态由统一时钟管理器驱动（SCN-856）。
- 资源错峰：相邻场次开抢间隔 ≥ 5 分钟（系统喘息）；前端在两场间隙预取下一场数据（闲时预热）。
- 状态切换：场次切换时不整页刷新——切换数据源（新场次配置/库存订阅），复用页面骨架。
- 提醒体系：开抢前提醒（订阅推送/日历），提醒率与到场率关联复盘（提醒太早忘/太晚赶不上）。
- 追问钩子：为什么相邻场次要留 5 分钟间隔——上一场的支付/回流/降级余波需要时间消化；背靠背开抢等于两场洪峰叠加，容量按单场规划必崩。

```javascript
function multiSession(sessions) {
  const clock = createCountdowns(serverOffsetMs);      // 统一时钟
  sessions.forEach(s => clock.register(s.id, s.startTs, () => activate(s)));
  // 场次间隙预取下一场
  clock.onIdleBetween(sessions, (next) => prefetchSession(next));
  return sessions.map(s => ({
    ...s, state: s.startTs > now() ? 'UPCOMING' : s.endTs > now() ? 'LIVE' : 'ENDED',
    subscribe: () => notifyAt(s.startTs - 5 * 60_000),  // 提前 5 分钟提醒
  }));
}
```
