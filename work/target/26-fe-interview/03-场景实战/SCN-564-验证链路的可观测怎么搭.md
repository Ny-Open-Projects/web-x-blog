## SCN-564：验证链路可观测性与排障怎么做？
**答**：
- 三层数据：客户端埋点（每步耗时/失败原因）、服务端日志（判定结果与理由）、中间链路 trace（验证接口的 traceId 与业务接口打通）。
- 排障路径：用户投诉 → 按设备号/手机号查客户端事件流（曝光→尝试→失败原因）→ 对照服务端判定日志 → 定位是轨迹模型误伤还是网络/SDK 故障。
- 误伤修复闭环：误伤样本回流给风控模型团队调参，前端提供「用户操作录像回放」（脱敏轨迹回放）作为证据。
- 告警：验证通过率骤降、某机型通过率异常、SDK JS 错误率超阈值三类告警。
- 追问钩子：为什么 traceId 要贯穿——没有统一 trace，客户端日志与服务端判定对不上，排障靠猜。

```javascript
async function guardedVerify(scene) {
  const traceId = currentTraceId();               // 与业务请求同源
  const span = tracer.startSpan('verify', { tags: { scene, traceId } });
  try {
    const step = (name, extra) => reporter.push({ scene, traceId, step: name, ...extra });
    step('expose');
    const r = await runVerify(scene);
    step(r.pass ? 'pass' : 'fail', { reason: r.reason, cost: span.cost() });
    return r;
  } finally { span.end(); }
}
// 客服查询：GET /debug/verify?device=xxx&hours=24 → 事件时间线 + 服务端判定对照
```
