## SCN-498：手写竞态请求管理器：AbortController 取消过期、最新序保护、缓存配合

**需求与边界**：
- 输入：请求序列（同 key 连续触发）；输出：只有最新请求的结果被采纳。
- 边界要求：① 发起新请求取消旧请求（AbortController）；② 已发出无法取消的响应按序号丢弃（晚到旧响应不覆盖）；③ 缓存命中优先返回再请求（stale-while-revalidate）；④ 错误处理（AbortError 分流）。

**答**：
```javascript
class RequestManager {
  constructor() { this.seq = 0; this.inflight = new Map(); }
  async run(key, fn, { cache } = {}) {
    const cached = cache?.get(key);
    if (cached) emit(key, cached);             // 缓存先返回
    const seq = ++this.seq;
    this.inflight.get(key)?.ac.abort();        // 取消旧请求
    const ac = new AbortController();
    this.inflight.set(key, { seq, ac });
    try {
      const r = await fn({ signal: ac.signal });
      if (this.inflight.get(key)?.seq !== seq)
        return null;                           // 已被更新序取代→丢弃
      cache?.set(key, r);
      emit(key, r);                            // 最新生效
      return r;
    } catch (e) {
      if (e.name === 'AbortError') return null; // 取消静默
      if (this.inflight.get(key)?.seq === seq)
        emitError(key, e);                     // 最新序的错误才呈现
      throw e;
    } finally {
      if (this.inflight.get(key)?.seq === seq)
        this.inflight.delete(key);
    }
  }
}
// 场景：搜索框连续输入（SCN-285）/仪表盘切换（SCN-430）
// 核心：取消（省资源）+ 序号保护（无法取消的也正确）双保险。
```

**评分点**:
- AbortController 取消旧请求 + seq 序号保护双保险（无法取消的响应也正确丢弃）。
- 缓存先返回再请求（stale-while-revalidate）。
- AbortError 与真实错误分流（取消静默不报错）。
- inflight 清理（finally）。
