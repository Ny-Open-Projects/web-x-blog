## SCN-815：历史/热词本地缓存怎么设计？
**答**：
- 历史词存储：localStorage 容量小（5MB）且同步——历史词存 IndexedDB（异步大容量），数量上限 100 条 LRU；未输入任何字符时展示历史 + 热词。
- 热词更新：静态热词表（构建时打包 + SW 缓存）兜底 + 运行时热词接口（定时刷新，TTL 10 分钟）——断网时静态表可用。
- 一致性：历史词与账号绑定（多设备同步走服务端历史服务，本地做缓存）；登出清本地历史。
- 敏感时效：历史词展示前过滤已下架/敏感内容（本地标记后过滤，不重复展示）。
- 追问钩子：为什么历史词用 IndexedDB 而 localStorage 只做标记——历史词列表可能几百条含元数据（时间/类目），localStorage 同步序列化阻塞主线程；IndexedDB 异步且容量充足。

```javascript
const historyStore = {
  db: 'search-history', store: 'queries', cap: 100,       // LRU 上限
  add: (q) => idb.put({ q, ts: Date.now() }),
  list: () => idb.all().then(rows => rows
    .filter(r => !r.removed)                              // 本地标记过滤
    .sort((a, b) => b.ts - a.ts).slice(0, 100)),
  clear: () => idb.clear(),
};
// 热词双层
const hotwords = { static: BUILD_HOTWORDS, runtime: { api: '/hotwords', ttl: 600_000 } };
```
