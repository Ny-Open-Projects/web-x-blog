## SCN-284：订单评价（星级/图文/视频/追评）怎么实现？

**答**:
- 评价表单：星级+标签快捷评价（"物流快/质量好"预置标签点选——降低评价成本提升评价率）、图文上传（多图压缩上传/视频转码）、匿名选项、默认好评的合规边界（默认勾选好评是违规——必须用户主动）。
- 评价内容处理：敏感词过滤（前端快筛+服务端终审）、图片审核（先发后审 vs 先审后发的策略：评分高默认展示、低分内容先审）、追评（收货 N 天后开放追评入口，追评独立展示位）。
- 展示与激励：评价列表（标签聚合统计："98% 好评"）、评价有礼（晒图返券——合规声明）、评价率优化（订单完成触达时机/简化表单）。
- 数据链路：评价提交幂等（一单一评）、评价修改期（N 天内可修改）、评价曝光数据回流（浏览量/有用数）。

```javascript
async function submitReview({ order, stars, tags, images, anonymous, text }) {
  const clean = await prefilter(text);       // 本地敏感词快筛
  const r = await reviewApi.create({ orderId: order.id,
    stars, tags, content: clean,
    images: await uploadAll(images, { compress: true }),
    anonymous, idempotencyKey: `review:${order.id}` },  // 幂等
  );
  return r;
}
// 追评：Date.now() - order.finishAt > 7d → showEntry()
// 标签聚合：tags 统计 → "质量好 (1.2k)" 快捷筛选。
```

**边界与易错**：

1. 幂等键写成 `review:${order.id}` 后，用户修改评价若复用同一 key，服务端会把「修改」当成重复提单直接返回旧评价——改评必须走 update 接口或把 key 换成带 version 的新值。
2. 图片上传与评价创建是两个事务：图片传完但 create 失败会留下孤儿文件，上传时要带 `bizId` 让服务端能对账清理；先审后发时 create 返回的是「审核中」，不能直接当已发布渲染。
3. 追评入口写成 `now - finishAt > 7d` 只是「满 7 天」，若规则是最长 30 天内可追，必须同时判 `< 30d`，否则入口永久不消失。

**追问**：

1. 敏感词前端快筛被改字、拼音、图片藏字绕过怎么办？ → 前端只降延迟，服务端终审才是准入口，并统计前端命中率反推词库是否滞后。
2. 高分先发后审、低分先审后发，会不会被刷分绕过？ → 权限分层要叠加用户信用与历史违规率，新号与异常设备一律先审，不单看星级。
3. 提交成功但列表仍是旧数据怎么排查？ → 检查是否命中列表缓存 key，提交后用返回对象本地插入首条并失效缓存，再对齐服务端游标。
