## SCN-778：审核处置与下游联动怎么设计？
**答**：
- 处置扇出：下架动作扇出到推荐池剔除/搜索索引删除/CDN 缓存刷新/外链失效——每路独立执行独立确认，扇出结果聚合呈现（推荐已剔除 ✓ 搜索已删除 ✓ CDN 刷新中…）。
- 一致性窗口：CDN 刷新有延迟（分钟级），下架后内容可能短暂可达——前端呈现「已下架（缓存刷新中，预计 5 分钟）」管理预期。
- 恢复对称：申诉翻案恢复时反向扇出（重新入库/恢复索引），同样聚合确认。
- 联动失败重试：扇出各路失败进重试队列 + 对账兜底，最终一致。
- 追问钩子：为什么每路独立确认而不是「下架=成功」——下架指令成功 ≠ 所有下游生效；创作者举报「还能搜到」时需要精确定位哪一路没执行。

```javascript
async function takedown(videoId) {
  const results = await Promise.allSettled([
    recommend.remove(videoId), search.deleteIndex(videoId),
    cdn.purge(videoId), shortLink.disable(videoId),
  ]);
  return results.map((r, i) => ({
    channel: ['recommend', 'search', 'cdn', 'link'][i],
    status: r.status === 'fulfilled' ? 'DONE' : 'RETRY_QUEUED',
  }));   // 前端聚合呈现各路状态
}
```
