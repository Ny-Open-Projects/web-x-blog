## SCN-344：多人协同编辑时，Ctrl+Z 撤销怎么不撤销别人的内容？

**答**:
- 撤销语义：协同环境下撤销只撤"自己的操作"（UndoManager 按 author 过滤——SCN-294 同源），撤销的是自己的变更链（即使中途别人插入了内容——撤销自己的插入不影响他人内容位置，CRDT 相对引用保证）。
- 实现机制：本地操作记录（transaction 元数据带 author），undo 生成反向操作（CRDT 下删除插入的反转），redo 栈（撤销后新操作清除 redo——传统语义保留）、批量事务（一次粘贴=一个事务整体撤销）。
- 边界与冲突：撤销与他人并发（我撤销删除的同时别人在该处插入——CRDT 自动合并语义（恢复的文本与插入共存——语义可能需人工确认 SCN-224）、撤销跨会话（重进文档后撤销栈是否保留——策略：会话级撤销栈）。
- 深度与性能：撤销栈深度上限（内存控制）、长事务拆分（宏操作可拆步撤销）。

```javascript
const undoManager = new Y.UndoManager(ytext, {
  trackedOrigins: [myOrigin],               // 只跟踪自己的 origin
});
editor.on('undo', () => undoManager.undo()); // 只撤自己的
editor.on('redo', () => undoManager.redo());
// 批量事务：ydoc.transact(() => { 粘贴内容 }, myOrigin)
//   → 一次 undo 全撤。
// 并发：撤销的反向操作进 CRDT → 与他人操作自动合并；
//   语义冲突 → detectConflicts 提示（SCN-224）。
// 栈深度：undoManager.trackedOrigins + captureTimeout
//   控制，内存超限丢弃最旧。
```
