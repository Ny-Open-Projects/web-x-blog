## SCN-405：手写未读数管理：本地实时增量、进入会话清零上报、服务端校正

**需求与边界**：
- 输入：推送事件、会话切换事件；输出：未读数状态管理。
- 边界要求：① 推送到达本地 +1（实时性）；② 进入会话清零并上报读游标（seq）；③ 多端读游标广播同步（其他端清零）；④ 重连/进列表页全量校正（本地漂移修复）。

**答**：
```javascript
class UnreadManager {
  constructor({ api, myDevice }) {
    this.unread = new Map(); this.api = api;
    this.myDevice = myDevice;
  }
  onIncoming(msg) {                            // 推送到达
    this.unread.set(msg.convId,
      (this.unread.get(msg.convId) ?? 0) + 1); // 实时 +1
  }
  async enter(convId, lastSeq) {               // 进入会话
    const n = this.unread.get(convId) ?? 0;
    this.unread.set(convId, 0);
    await this.api.reportRead(convId, lastSeq);// 上报游标
    return { cleared: n };
  }
  onRemoteRead(e) {                            // 其他端已读
    if (e.device === this.myDevice) return;
    this.unread.set(e.convId, 0);              // 多端同步清零
  }
  async fullSync() {                           // 全量校正
    const server = await this.api.unreadSummary();
    this.unread = new Map(Object.entries(server));
    return this.unread;                        // 修正本地漂移
  }
  total() { return [...this.unread.values()]
    .reduce((a, b) => a + b, 0); }             // 总角标
}
// 读游标服务端为事实源：本地计数只是缓存；
// 广播：reportRead 后服务端推 read_cursor 到其他端。
```

**评分点**:
- 双机制正确：本地增量（实时）+服务端游标（事实源）分工明确。
- 进入会话即清零并上报游标；其他端收到广播同步清零。
- fullSync 校正本地漂移（重连/进列表触发）。
- total 聚合总角标（跨会话汇总）。
