## SCN-392：电商/社交/教育/协作多业务线的内容审核怎么统一成中台？

**答**:
- 中台抽象：统一审核接入 SDK（业务方声明内容类型与策略——策略模板：电商商品/社交动态/教育评论各有默认策略集），统一三级分流（SCN-314 机器分流/人审/申诉——全业务复用），统一审核工作台（多业务线队列聚合——审核员按技能组分单）。
- 策略差异管理：业务线策略包（各业务的规则集/阈值/人审比例——配置化），策略版本（审核规则变更走评审+灰度——SCN-322 开关复用），行业合规差异（教育未成年人/社交尺度/电商广告法——策略包隔离）。
- 统一数据：审核记录（跨业务统一 schema——SCN-421 审计复用）、审核员质量（跨业务一致率考核）、badcase 流水（跨业务归因——AGT-353 复用）。
- 接入体验：业务方接入成本（SDK 一行接入+策略包选择）、审核结果回调协议（状态机回调：通过/驳回/人审中）、审核看板业务隔离（各业务看自己数据——数据权限）。

```text
审核中台抽象：
接入：SDK + 策略包（业务声明内容类型）
分流：三级分流全业务复用（SCN-314）
策略：业务线策略包 + 版本灰度 +
  行业合规隔离
数据：统一 schema + 审核员考核 +
  badcase 流水
接入成本：一行 SDK + 回调协议。
```
