## SCN-513：账户总览页的数据聚合与缓存怎么做？
**答**：
- 聚合在服务端：总览卡片走一个聚合接口（资产/负债/收益快照），前端不并发拉 N 个账户接口再求和——口径一致且省请求。
- 缓存分层：SWR 策略——先展示上次快照（带「截至 hh:mm」时间戳），后台 revalidate；数字变动用 diff 动画而非整块替换。
- 按资产类型 TTL：活期余额短 TTL（秒级推送），理财估值中 TTL（分钟），历史收益长 TTL（小时），避免无效刷新。
- 失效时机：交易完成推送、下拉刷新、切回前台三类事件主动失效对应 key。
- 追问钩子：多个模块都要余额怎么办——全局唯一 BalanceStore（SCN-504），UI 订阅，不各自拉接口。

```javascript
const overviewKeys = {
  deposit:  { ttl: 5_000,  push: true  },   // 活期：推送驱动
  wealth:   { ttl: 60_000, push: false },   // 估值：分钟级
  history:  { ttl: 600_000, push: false },
};
function useOverview() {
  const { data } = useSWR('overview', fetchOverview, {
    fallbackData: lastSnapshot,             // 上次快照先展示
    refreshInterval: (d) => minTtl(d.dirtyParts),
    revalidateOnFocus: true,
  });
  return useMemo(() => ({ ...data, staleText: `截至 ${fmtTime(data.ts)}` }), [data]);
}
```
