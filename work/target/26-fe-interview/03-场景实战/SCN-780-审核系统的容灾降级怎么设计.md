## SCN-780：审核系统容灾降级怎么设计？
**答**：
- 机审故障降级：机审不可用时全量进人审（queue 容量会击穿）——同时启动「限流投稿」（新投稿排队发布）保护审核容量，宁可发布延迟不可漏审。
- 积压雪崩预案：积压超阈值分级响应——加开临时人力/提高直放阈值（高危品类不放宽）/暂停低优先级品类审核（先保高危）。
- 处置链路降级：处置扇出下游（CDN/推荐）故障时处置指令排队重试，保证最终一致；前端显示处置延迟状态。
- 降级决策自动化：按容量模型（人审 throughput × 在岗人数 vs 进审速率）自动计算并建议降级档位，值班确认执行。
- 追问钩子：为什么降级首选「限流投稿」而不是放宽标准——放宽标准牺牲内容安全（不可逆风险），限流牺牲时效（可恢复）；安全红线优先。

```javascript
const degradeLadder = [
  { trigger: 'machineDown', action: 'all-to-human + throttle-upload' },
  { trigger: 'backlog>4h', action: 'open-temp-staff + raise-direct-threshold(lowrisk-only)' },
  { trigger: 'backlog>8h', action: 'pause-low-priority-categories' },
];
function autoSuggest() {
  const capacity = staffRate() * auditorCount();
  const inflow = uploadRate();
  return capacity < inflow ? degradeLadder.find(l => fits(l)) : null;   // 值班确认执行
}
```
