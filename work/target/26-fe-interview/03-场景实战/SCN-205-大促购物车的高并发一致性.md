## SCN-205：大促期间购物车商品"加购时库存充足、结算时已售罄"，前端怎么处理？

**答**:
- 状态分层：购物车条目三态（可结算/库存紧张/已失效），加购时不锁库存（展示"充足"但标注非承诺），结算页才是库存校验点——前端如实呈现"最终以结算为准"，避免强承诺导致的客诉。
- 结算校验失败的处理流：失效项置灰并可勾选移除，其余项继续结算（部分成功优于全部失败）；每个失效项给替代推荐（同款/相似商品入口）——把售罄转化为引导而非死路。
- 库存紧张态的交互：库存 <N 显示"仅剩 X 件"（服务端下发阈值，前端不猜测）、抢购模式商品显示"排队中"而非直接失败（SCN-203 排队机制复用）。
- 数据一致性：购物车本地与服务端冲突合并（SCN-大促离线加购已有，复用时间戳合并策略），结算前的全量刷新（进入结算页拉最新状态，不用购物车页的陈旧数据）。

```javascript
async function enterCheckout(cart) {
  const fresh = await cartApi.refresh(cart.items.map(i => i.id)); // 结算前全量刷新
  const invalid = cart.items.filter(i =>
    fresh.find(f => f.id === i.id)?.stock === 0);
  if (invalid.length) {
    markUnavailable(invalid);               // 置灰+可移除
    showAlternatives(invalid);              // 替代推荐
    if (invalid.length === cart.items.length)
      return toast('所购商品均已售罄');
    toast(`${invalid.length} 件商品已售罄，其余可继续结算`);
  }
  const stock = fresh.filter(f => f.stock > 0 && f.stock <= f.threshold);
  stock.forEach(s => markLowStock(s));      // 仅剩X件（服务端阈值）
  return proceed(cart.items.filter(i => !invalid.includes(i)));
}
```
