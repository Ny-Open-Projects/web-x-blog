## SCN-225：协作文档的权限分级（只读/评论/编辑）怎么落地？

**答**:
- 权限模型：角色三+一（owner/editor/commenter/viewer + 匿名链接访问），权限项矩阵（编辑内容/编辑结构/评论/导出/分享/管理），继承与覆盖（文件夹继承+单文档覆盖）。
- 前端落地：能力对象注入（页面全局 capability 判断，UI 按能力渲染——编辑器只读态/评论态/编辑态三种模式），服务端强制（每个操作带权限校验，前端隐藏只是体验不是防线——API 层拒绝越权）。
- 协同通道的权限：只读用户不订阅文档写通道（只收内容不收操作权）、评论者不能进编辑会话（awareness 只含评论光标）——权限前置到连接建立时（连接即授权，不给无权连接）。
- 动态权限变更：编辑中权限被收回（owner 移除某人编辑权）→ 实时踢出编辑态（通知→编辑器切换只读→未保存内容本地保留提示复制）。

```javascript
function docCapabilities(user, doc) {
  const role = doc.acl[user.id] ?? doc.publicAccess;
  return {
    canEdit: role === 'owner' || role === 'editor',
    canComment: ['owner','editor','commenter'].includes(role),
    canExport: role !== 'viewer' || doc.allowExport,
    canShare: role === 'owner',
  };
}
// UI：canEdit ? <Editor/> : <ReadonlyView comments={canComment}/>;
// 服务端：每个 WS 消息带 token，服务端校验操作权限；
// 无权连接：握手阶段直接拒绝订阅写通道。
// 权限回收：ws.on('kick', () => editor.toReadonly()
//   && backupLocalEdits());   // 本地未同步内容提示保存
```
