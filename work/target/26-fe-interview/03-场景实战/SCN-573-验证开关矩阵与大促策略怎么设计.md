## SCN-573：验证开关矩阵怎么设计？
**答**：
- 矩阵维度：场景 × 验证器 × 生效范围（全量/白名单/灰度），运营后台配置，配置中心秒级下发（长轮询推送失效）。
- 预设预案：大促档（收紧：支付全量滑块）、攻击应急档（极严：可疑流量直接答题）、恢复档（回默认）——预案一键切换并留审计。
- 生效安全：配置变更需双人审批；前端只执行不校验，但配置带签名防篡改下发。
- 生效观察：切换后 5 分钟看板自动对比（通过率/拦截量/客诉量），异常自动回滚提示。
- 追问钩子：配置下发生效延迟怎么办——验证决策在服务端实时读配置，前端配置只影响 UI 展示，延迟不产生安全洞。

```javascript
// 配置结构（服务端为准）
const matrix = {
  scene: 'pay', verifier: 'slider',
  scope: { type: 'percent', value: 100 },          // 或 { type: 'whitelist', uids: [] }
  effectiveAt: 1700000000, signature: '...',
};
async function fetchMatrix() {                      // 前端长轮询或 SSE 接收
  const { data, version } = await api.get('/risk/matrix', { params: { since: localVersion } });
  if (data) applyMatrix(data);                      // 更新本地验证器挂载策略
}
```

## 追问（补充）

**边界与易错**：

- `scope.type === 'percent'` 时 `value` 必须是 0~100 整数，`effectiveAt` 为未来时间时 `applyMatrix` 要挂定时器而非立即生效。
- 版本比较只看服务端返回的 `version` 单调递增，收到更旧 version 必须直接丢弃，否则灰度回滚会把已下线的严格档重新捞回来。
- `applyMatrix` 必须先挂新验证器再卸旧的，顺序反过来会出现几百毫秒「无验证」窗口。

**追问**：

1. 配置中心挂了、SSE 断开，前端还按旧矩阵渲染怎么办 → 前端只决定 UI 展示，真正判定在服务端实时读配置，最坏是展示错而不是放过风险流量；本地矩阵带 `expiresAt`，过期自动回落最严档。
2. 大促零点流量涨 50 倍，矩阵下发 QPS 也跟着涨怎么办 → 矩阵是版本化快照不是逐用户下发，走 CDN/边缘缓存加 ETag，客户端只在 `version` 变化时拉全量。
3. 一键切错档位（严格档误切回默认）怎么止损 → 变更双人审批 + 切前 dry-run 预估影响面 + 切后 5 分钟自动对比通过率与拦截量，越界自动回滚并告警。
