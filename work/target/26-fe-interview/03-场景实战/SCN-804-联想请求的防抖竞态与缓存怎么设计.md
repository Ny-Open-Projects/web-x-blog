## SCN-804：联想请求防抖/竞态/缓存进阶怎么设计？
**答**：
- 请求策略：输入 150ms 防抖 + 「前缀收敛」（同前缀的更长输入可复用父结果做本地过滤预展示，同时仍发请求校正）——打字过程中用户永远有内容看。
- 竞态守卫：请求带输入序号（seq），响应只采纳最新 seq；更快返回的旧响应直接丢弃——不能用「后发先至」假设（网络乱序）。
- 缓存层次：内存 LRU（前缀→结果，TTL 30s）+ 会话缓存（已输入过的前缀回退时零请求）；缓存键含个性化开关（登录态变化失效）。
- 取消策略：切换输入时 abort 上一个请求（省带宽），但注意 abort 后响应处理要幂等。
- 追问钩子：为什么用 seq 而不是「丢弃非当前输入的结果」——abort 可能失败或响应已在途中，seq 判定是最后一道防线，二者叠加才可靠。

```javascript
function createSuggester(api) {
  const cache = new Map();                           // prefix -> {data, ts}
  let seq = 0, ctrl = null;
  async function suggest(prefix) {
    const hit = cache.get(prefix);
    if (hit && Date.now() - hit.ts < 30_000) return hit.data;
    ctrl?.abort();
    ctrl = new AbortController();
    const my = ++seq;
    const res = await api.get('/suggest', { params: { q: prefix }, signal: ctrl.signal });
    if (my !== seq) return null;                     // 竞态守卫：只采纳最新
    cache.set(prefix, { data: res, ts: Date.now() });
    return res;
  }
}
```
