## SCN-267：路线规划（多方案/实时路况/导航态）的交互怎么设计？

**答**:
- 方案展示：多方案并行请求（驾车/打车/公交多策略），方案卡片列表（时间/距离/红绿灯/价格对比），选中方案高亮路线（其他方案灰化细线）——路线几何数据缓存（缩放拖动不重新请求）。
- 实时路况：路况图层（红黄绿着色线路段），路况刷新（导航态 30s 刷新，浏览态不自动刷）、拥堵变更提示（导航中前方拥堵→重新规划提示）。
- 导航态：视角锁定（跟随模式：marker 居中+俯仰旋转，可手动拖动查看——拖动后暂停跟随+N 秒回跟，SCN-234 同源）、转向提示（下一转向大字卡+语音播报钩子）、偏航处理（偏离路线检测→重新规划）。
- 弱网与降级：路线请求失败重试+缓存上次方案、导航中 GPS 丢失→惯性推算（按速度方向推演位置）+信号弱提示。

```javascript
async function planRoutes(from, to) {
  const [drive, taxi, transit] = await Promise.allSettled([
    routeApi.drive(from, to), routeApi.taxi(from, to),
    routeApi.transit(from, to)]);
  renderCards(compactOk([drive, taxi, transit]));   // 方案对比卡
}
// 导航态：
nav.on('position', throttle((p) => {
  if (offRoute(p, currentRoute)) replan(p);  // 偏航重规划
  map.setCenter(p);                          // 跟随
}, 1000));
// 路况刷新 30s：trafficLayer.reload();
// 拖动地图 → follow = false；10s 无操作 → follow = true。
```

**边界与易错**：

1. `Promise.allSettled` 后直接渲染，某个方案 rejected 时会被过滤，但卡片顺序会错位——要按固定策略位回填空槽，不能拿数组下标当方案类型。
2. 偏航判断 `offRoute(p)` 阈值太小，GPS 抖动就会在直路上反复触发重规划，需加距离阈值与持续时间双条件。
3. 拖动后 10s 回跟，但每个 position 都调 `setCenter` 会与手势打架，回跟要等手势结束并重置计时器。

**追问**：

1. 导航中 GPS 丢失做惯性推算，推久了会不会越推越偏？ → 限定时长（如 30s）与误差半径，超时降级为「信号弱」并停止绘制移动轨迹。
2. 30s 刷新路况时用户正在看别的方案，会不会打断？ → 只刷新当前高亮方案的图层，其他方案缓存不动，避免视觉跳变。
3. 多方案并行请求，弱网下三个都超时怎么办？ → 单方案独立超时，先到先渲染，其余继续等待，别让一个慢接口拖住整页。
