## SCN-300：协同办公套件（文档/表格/IM/日历/任务）的前端工程怎么总收束？

**答**:
- 全景五模块：协作文档（SCN-221~229）、多维表格与看板（292/294）、IM（SCN-213~220）与客服、日历任务（293 纪要/295 日历）、平台层（291 列表/296 统一搜索/297 离线/298 桌面同构/299 管理后台）——办公套件是"多应用×统一底座"的架构。
- 统一底座资产：账号与权限（RBAC/组织架构全链路共享）、实时基建（WS/CRDT/awareness 全应用复用）、搜索与通知（统一索引/统一通知中心）、离线框架（分级矩阵全应用一致）、审计与合规（全操作留痕）——底座质量决定各应用的上限。
- 跨应用协同场景：文档@任务（提及即创建联动）、会议→纪要→任务的一键流转（293 链路）、消息转文档（IM 内容沉淀）——应用间通过统一实体协议（实体引用：type+id）互相引用。
- 收束心法：办公套件的竞争力在"底座的一致性"——用户跨应用感受到统一的权限/搜索/通知/离线体验；工程上是"多应用复用统一基建+应用间实体协议互通"的架构，避免每个应用各自造轮子。

```text
办公套件全景：
应用：文档 / 多维表格 / IM / 日历任务
底座：账号权限 / 实时基建（WS+CRDT）
  / 统一搜索 / 通知中心 / 离线框架
  / 审计合规 —— 全应用复用
协同：实体引用协议（type:id）互通，
  会议→纪要→任务一键流转。
心法：底座一致性 = 产品竞争力；
  统一基建 + 实体协议互通。
```
