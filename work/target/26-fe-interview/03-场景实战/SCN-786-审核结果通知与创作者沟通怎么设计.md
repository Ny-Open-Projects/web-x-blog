## SCN-786：审核结果通知怎么设计？
**答**：
- 状态透明：创作者端实时展示审核状态（审核中/预计时间/通过/驳回+原因），驳回原因结构化（引用标准条目 + 违规时刻截图）——减少无效申诉。
- 通知分级：通过静默（不打扰）或轻提示；驳回强通知（站内信 + 推送），附申诉入口与标准原文链接。
- 预期管理：机审直放的内容若后续抽检翻案（回溯处置），通知说明「事后复核发现」并给申诉通道——回溯处置的沟通成本最高，必须解释机制。
- 敏感驳回的人工通道：涉驳回争议大的品类提供人工咨询入口（减少情绪化申诉）。
- 追问钩子：为什么驳回原因要给「违规时刻截图」——「内容违规」四个字让创作者无从修改；具体到帧的证据让驳回可理解、申诉有依据、改进可执行。

```javascript
function notifyCreator(video, verdict) {
  if (verdict.pass) return silentLog(video.id);      // 通过不打扰
  return push(video.creatorId, {
    title: '内容未通过审核',
    evidence: verdict.marks.map(m => ({ ts: m.startTs, shot: m.screenshotUrl })),
    standardRef: verdict.standardRefs,               // 标准原文链接
    appeal: `/appeal/new?videoId=${video.id}`,
    note: verdict.retrospective ? '本次为事后复核处置，如有疑问可申诉' : null,
  });
}
```
