## SCN-623：审批状态实时推送怎么设计？
**答**：
- 推送粒度：订阅型推送（用户订阅自己的待办变更/被催办事件），不广播全部流程；消息体带 instanceId + 事件类型，详情数据由前端按需拉取（推信号拉数据）。
- 多端同步：PC 处理了审批，手机待办列表实时移除——以事件版本号（seq）单调同步，多端各持游标，断线重连补增量。
- 页面内一致性：正在看详情时实例被别人处理，收到推送后顶栏提示「该单已被 X 处理」+ 一键刷新，不强制打断阅读。
- 兜底轮询：WS 断连退化为待办计数轮询（30s），恢复后补拉。
- 追问钩子：推送风暴（批量审批导入产生千条待办）怎么削峰——服务端聚合窗口 + 客户端合并渲染（一次刷新代替千次）。

```javascript
function approvalChannel(ws, store) {
  ws.on('approval', ({ seq, events }) => {
    if (seq <= store.cursor) return;               // 旧事件
    store.cursor = seq;
    const detailOpen = currentDetailId();
    for (const e of events) {
      if (e.type === 'DONE' && e.instanceId === detailOpen)
        toast('该单已被他人处理', { action: '刷新', onClick: reloadDetail });
      else
        store.todoDelta(e);                        // 待办列表增量
    }
  });
  ws.on('down', () => startPolling('/todo/count', 30_000));   // 降级轮询计数
  ws.on('reopen', () => ws.send({ resumeFrom: store.cursor })); // 补增量
}
```
