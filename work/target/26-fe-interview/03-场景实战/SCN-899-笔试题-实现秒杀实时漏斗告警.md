## SCN-899：手写实时漏斗告警

**需求与边界**：
- 需求：分钟窗口聚合漏斗各步计数；步间转化率相对上一窗口下降 > 30% 触发告警；告警带步骤定位与当前值/基线值；告警去抖（连续 2 个窗口下降才触发）。
- 边界：① 活动开始前 5 分钟窗口样本少不告警（预热期）；② 全量步（支付）与采样步（曝光）分开判定阈值；③ 告警恢复也通知（问题解除）。

**答**：
```javascript
function funnelAlert({ dropThreshold = 0.3, warmupMin = 5 } = {}) {
  const windows = [];
  let firing = new Set();
  function onWindow(win, { activityMin } = {}) {
    windows.push(win);
    if (windows.length > 10) windows.shift();
    if (activityMin < warmupMin) return;               // 预热期不告警
    const prev = windows.at(-2), cur = windows.at(-1);
    for (const step of Object.keys(cur)) {
      const rate = stepRate(cur, step), base = stepRate(prev, step);
      const threshold = ALL_VOLUME_STEPS.has(step) ? dropThreshold * 0.5 : dropThreshold;  // 全量步更敏感
      const dropped = base > 0 && (base - rate) / base > threshold;
      if (dropped) confirmFire(step, { rate, base });  // 连续 2 窗口才触发
      else { pending.delete(step);                     // 未下降：连续链断，计数清零
        if (firing.has(step)) { firing.delete(step); notifyRecovered(step); } }
    }
  }
  const pending = new Map();
  function confirmFire(step, ctx) {
    const n = (pending.get(step) || 0) + 1;
    pending.set(step, n);
    if (n >= 2 && !firing.has(step)) {
      firing.add(step);
      pending.delete(step);                          // 触发后清零，恢复后单次下降不复报
      alert({ level: 'P1', step, ...ctx, note: `步骤 ${step} 转化率骤降` });
    }
  }
  return { onWindow };
}
```

**评分点**:
- 步降检测（步间转化率 vs 上窗口）+ 步骤定位。
- 预热期静默（样本少不误报）。
- 全量/采样步差异化阈值（支付步更敏感）。
- 连续 2 窗口确认去抖 + 恢复通知。

## 变体与延伸（补充）

**变体与延伸**：

1. 曝光量本身波动大，固定 30% 阈值会不会天天误报 → 应按同比同刻或 3σ 动态化阈值，固定阈值只留给支付这类低方差全量步。
2. 某步骤计数延迟上报，当前窗口数据不全怎么办 → 窗口带「未完结」标记，延迟窗口只更新不判定，等水位线补齐后再算。
3. 恢复通知发太多造成告警疲劳怎么处理 → 恢复只在同步骤 P1 未确认时发一次，并做告警聚合，同批次合并成一条摘要。
