## SCN-559：验证组件多场景复用怎么设计？
**答**：
- 场景注册表：每个业务场景（scene）声明安全等级、允许的验证器集合、文案与皮肤；配置由服务端运营后台下发，前端不发版即可调整验证强度——这是对抗黑产的核心灵活性。
- 组件无关业务：验证器只输出「通过 token」，不感知支付/登录语义；业务方通过 Promise/回调接入。
- 样式体系：验证器支持主题注入（尺寸/圆角/品牌色），保证嵌入不同产品视觉一致。
- 度量内建：每个场景的验证曝光/通过率/平均耗时自动埋点，运营可看各场景被攻击强度。
- 追问钩子：场景配置热更新怎么生效——配置带版本号，SDK 每次挂载前拉取，旧场景实例完成后新实例用新配置。

```javascript
// 服务端下发的场景配置
const sceneConfig = await api.get('/risk/config');
// { pay: { level: 3, verifiers: ['slider', 'face'], theme: 'pay-dark', copy: {...} },
//   coupon: { level: 1, verifiers: ['slider'], theme: 'light' } }
function mountVerifier(scene, { onPass, onFail }) {
  const cfg = sceneConfig[scene];
  if (!cfg) throw new Error(`未知场景 ${scene}`);
  const track = metrics.track(scene);            // 内建埋点
  const [first, ...rest] = cfg.verifiers;
  runChain(first, rest, cfg).then(r => {
    track.done(r.pass, r.cost);
    r.pass ? onPass(r.token) : onFail(r.reason);
  });
  return { unmount() { /* 清理 DOM/监听 */ }, updateConfig: (c) => Object.assign(cfg, c) };
}
```
