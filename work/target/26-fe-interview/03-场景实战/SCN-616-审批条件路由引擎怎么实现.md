## SCN-616：审批条件路由怎么实现？怎么让用户提交前预演流程？
**答**：
- 路由规则：条件表达式（amount > 10000 → 总监线；amount > 100000 → 加财务线）由服务端定义与求值，前端提交后服务端决定实际路径。
- 前端预演：提供「预计审批路径」接口（dry-run 求值当前表单数据），表单填写实时预演高亮将走的分支——用户提交前知道会到谁手里，减少撤回。
- 预演与真实一致性：预演用同一份规则引擎（同一接口），仅标记 dryRun；提交后真实路径与预演不同（数据被改）时给出提示。
- 边界提示：条件含动态因子（如「本月累计金额」）时预演标注「基于当前填写值估算」。
- 追问钩子：预演要不要把未来审批人名字展示出来——展示岗位而非具体人（人员可变），避免用户找人打招呼。

```javascript
async function previewRoute(form, flowId) {
  const { path, conditions } = await api.post(`/flow/${flowId}/preview`, {
    formData: form, dryRun: true,
  });
  return path.map(node => ({
    ...node,
    hint: node.dynamicCondition
      ? `${node.expr}（基于当前填写值估算）`
      : node.expr,                     // "amount > 10000"
    assigneeRole: node.role,           // 展示岗位不展示具体人
  }));
}
// 表单 watch: form.onChange -> debounce(previewRoute) -> 流程图预览高亮
```

## 边界与易错（补充）

**边界与易错**：

- 规则求值只能有一处实现。前端再写一套 `amount > 10000` 做兜底判断，规则一改两边立刻不一致，预演就开始骗人。
- 预演请求必须防抖且可取消。每次输入都打 dry-run 会打爆接口，且乱序返回会让高亮跳回旧分支——用请求序号或 AbortController 丢弃过期响应。
- 「本月累计金额」这类动态因子，预演时用的是快照值。用户改单后可能跨过阈值，提交成功页必须回显最终路径，而不是把预演路径当结果。
