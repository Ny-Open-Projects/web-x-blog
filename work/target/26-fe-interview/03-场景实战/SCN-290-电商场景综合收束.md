## SCN-290：电商场景（大促+客服+售后+会员+裂变）怎么综合收束？

**答**:
- 全景链路：流量入口（搜索 285/裂变 289/会场 207）→ 交易（详情预载 210/购物车凑单 286/优惠 206/支付 209）→ 履约（物流 287/地址 283）→ 服务（客服 IM 281/售后 282/评价 284）→ 用户体系（会员 288）——电商前端是"最长业务链路"的场景集合。
- 跨场景复用资产：状态机引擎（订单/售后/活动共用）、倒计时校准（秒杀/优惠券过期/会员到期）、幂等请求封装（下单/助力/评价）、分摊计算引擎（优惠/运费/退款金额）——资产化让新场景快速拼装。
- 体验与合规双线：合规是电商前端的一等约束（价格规范/好评合规/隐私脱敏/广告法词库），体验设计在合规框架内优化——合规检查清单进发布流程。
- 收束心法：电商前端工程的成熟度=资产复用度×合规完备度×峰值预案度；场景题千变万化，底层是"状态机+幂等+计算引擎+合规"四件套的组合。

```text
电商综合全景：
入口：搜索联想 / 裂变活动 / 会场楼层
交易：预载矩阵 / 凑单引擎 / 优惠计算 /
  支付三通道
履约：地址解析 / 物流归一融合
服务：客服卡片 / 售后状态机 / 评价合规
用户：会员成长 / 权益联动
资产：状态机 / 倒计时校准 / 幂等封装 /
  分摊引擎 —— 跨场景复用。
心法：资产复用 × 合规完备 × 峰值预案。
```
