## SCN-897：手写对账差异仲裁

**需求与边界**：
- 需求：订单表 vs 支付表差异分类（丢单/重复支付/超时未关）；有争议订单用客户端事件流旁证（用户是否真的提交过）辅助仲裁；输出仲裁结论与置信度。
- 边界：① 旁证匹配规则：客户端有 submit 事件 + 服务端无单 = 高概率网络丢单；② 客户端无事件 + 服务端有单 = 埋点丢失（可信服务端）；③ 双无 = 未知待人工。

**答**：
```javascript
function arbitrate(diff, clientEvidence) {             // diff: { orderId, side }
  const ev = clientEvidence(diff.orderId);
  const hasSubmit = ev?.submitted, hasServer = diff.inOrderTable || diff.inPaymentTable;
  if (hasSubmit && !hasServer)
    return { verdict: 'LOST_IN_TRANSIT', confidence: 0.9,
             action: '补单或引导用户重下', evidence: ev };
  if (!hasSubmit && hasServer)
    return { verdict: 'TRACKING_LOSS', confidence: 0.8,
             action: '以服务端为准，修复埋点', evidence: ev };
  if (hasSubmit && hasServer && diff.type === 'DUP')
    return { verdict: 'DUPLICATE_PAY', confidence: 0.95, action: '退款流程' };
  return { verdict: 'UNKNOWN', confidence: 0.3, action: '人工复核队列' };
}
// 客户端旁证数据结构
const evidence = (orderId) => ({
  submitted: submitEvents.has(orderId),
  submitTs: submitEvents.get(orderId)?.ts,
  idempotencyKey: submitEvents.get(orderId)?.key,      // 幂等键可与服务端日志对齐
});
```

**评分点**:
- 三分类仲裁规则清晰（网络丢单/埋点丢失/重复支付）。
- 旁证可信度分层（有幂等键可与服务端日志精确对齐）。
- 置信度量化（人工队列只收低置信）。
- UNKNOWN 兜底不强行归因。
