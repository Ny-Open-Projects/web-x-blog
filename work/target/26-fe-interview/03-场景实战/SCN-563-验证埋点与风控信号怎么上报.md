## SCN-563：验证埋点与风控信号上报怎么设计？
**答**：
- 上报通道：独立埋点域名（防业务接口限流牵连）+ sendBeacon 优先（页面卸载不丢）+ fetch keepalive 兜底。
- 批量与节流：内存队列 + 满 20 条或 5 秒批量上报；高危信号（疑似机器）立即单独上报不合并。
- 可靠性：上报失败进持久队列（IndexedDB），下次启动重放；带 sessionId 与序号，服务端按序去重。
- 脱敏与采样：正常信号采样上报（10%），异常/风控事件全量；字段白名单，轨迹等大对象压缩。
- 追问钩子：sendBeacon 的局限——无响应回调、体积限制 64KB，重要信号不能只靠它，需要持久队列补偿。

```javascript
class SignalReporter {
  queue = []; seq = 0;
  constructor() { this.flush = throttle(this.flushNow, 5000); }
  push(event, { urgent = false } = {}) {
    this.queue.push({ ...event, seq: ++this.seq, sid: sessionId });
    urgent ? this.flushNow() : this.flush();
    if (this.queue.length >= 20) this.flushNow();
  }
  flushNow() {
    const batch = this.queue.splice(0, 50);
    if (!batch.length) return;
    const body = JSON.stringify(compress(batch));
    navigator.sendBeacon?.('/collect', body)
      ?? fetch('/collect', { method: 'POST', body, keepalive: true })
          .catch(() => persistQueue(batch));       // 失败落 IndexedDB 补偿
  }
}
```
