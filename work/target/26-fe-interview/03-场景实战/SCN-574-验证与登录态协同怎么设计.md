## SCN-574：验证与登录态协同怎么设计？
**答**：
- 依赖声明：验证接口区分「需登录态」与「匿名可用」（登录前的验证本身匿名）；SDK 挂载前检查当前会话有效性，过期先静默续期再验证。
- 中断接续：支付前验证进行到一半会话过期——保留验证上下文（challengeId），续期成功后继续；不可续则完整重来并告知原因。
- 踢下线处理：验证过程收到 401（被踢/他端登录），立即终止验证并展示登录页，提交的中间数据丢弃。
- 多端一致：验证 token 不跨端通用（App 验过的 token H5 不可用），除非显式「信任本设备 7 天」开关。
- 追问钩子：验证与登录循环依赖怎么破——登录页验证用匿名 challenge，成功后再建立会话。

```javascript
async function guardThenVerify(scene) {
  let session = await auth.ensure();               // 静默续期
  if (!session) return redirectToLogin(scene);     // 记录 returnUrl 验后接续
  try {
    return await runVerify(scene);
  } catch (e) {
    if (e.code === 'SESSION_EXPIRED') {            // 验证中途过期
      session = await auth.relogin({ returnUrl: location.href });
      return runVerify(scene);                     // 完整重来（challenge 已作废）
    }
    throw e;
  }
}
```
