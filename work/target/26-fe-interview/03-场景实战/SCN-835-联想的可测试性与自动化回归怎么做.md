## SCN-835：联想可测试性怎么做？
**答**：
- 数据层单测：seq 竞态（注入可控延迟的 mock api 断言只采纳最新）、缓存 TTL（注入时钟）、防抖（fake timers）——纯逻辑可全自动化。
- IME 回归：composition 事件序列模拟（compositionstart → input → compositionend）自动化测试——中文输入场景手测覆盖率低，必须自动化。
- 交互 E2E：键盘导航/无障碍 aria 状态/直达卡点击跳转——Playwright 驱动。
- 契约测试：联想响应结构（groups/items/offsets）契约固定，服务端变更 CI 即报。
- 追问钩子：为什么 IME 序列要专门自动化——composition 事件的时序组合（fast typing/composing 中断/上屏后立即 Enter）手测很难稳定复现，却是中文联想 bug 高发区。

```javascript
test('seq 竞态：慢的旧响应被丢弃', async () => {
  const api = mockApi({ 'a': { delay: 100 }, 'ap': { delay: 10 } });
  const p1 = suggester.suggest('a');                  // 慢
  const p2 = suggester.suggest('ap');                 // 快
  await Promise.all([p1, p2]);
  expect(rendered).toMatch('ap-result');              // 旧响应未覆盖
});
test('composition 期间不请求', () => {
  fireEvent.compositionStart(input);
  fireEvent.input(input, { data: 'zh' });
  expect(apiMock.calls).toHaveLength(0);              // composing 不请求
  fireEvent.compositionEnd(input);
  expect(apiMock.calls).toHaveLength(1);
});
```
