## SCN-409：手写订单状态机：合法迁移表、乱序推送校正、事件留痕

**需求与边界**：
- 输入：订单初始状态、状态事件流（可能乱序/重复）；输出：最终状态与校正记录。
- 边界要求：① 迁移表驱动（非法迁移拒绝并留痕）；② 乱序（旧状态后到）触发全量校正拉取；③ 重复事件幂等；④ 每次变更记录 {from, to, ts, source}。

**答**：
```javascript
const FLOW = ['created', 'paid', 'shipped', 'delivered', 'done'];
const TRANS = {
  created: ['paid', 'cancelled'],
  paid: ['shipped', 'refunding'],
  shipped: ['delivered'],
  delivered: ['done'],
};
class OrderFSM {
  constructor(orderId, init) {
    this.id = orderId; this.state = init;
    this.log = [{ to: init, ts: 0, source: 'init' }];
  }
  apply(to, { ts, source }) {
    // 1. 重复/已到状态：幂等忽略
    if (to === this.state) return { dup: true };
    // 2. 旧事件（回退状态）→ 触发全量校正
    if (FLOW.indexOf(to) < FLOW.indexOf(this.state))
      return { resync: true };                 // 乱序：拉服务端最新
    // 3. 合法迁移校验
    if (!TRANS[this.state]?.includes(to)) {
      this.log.push({ from: this.state, to, rejected: true,
        ts, source });
      return { resync: true };                 // 非法迁移也校正
    }
    this.log.push({ from: this.state, to, ts, source });
    this.state = to;
    return { ok: true, state: to };
  }
  history() { return this.log; }               // 审计留痕
}
// resync 处理：fetchOrder(orderId) 全量校正本地状态，
//   校正结果同样入 log（source: 'server_sync'）。
```

**评分点**:
- 迁移表驱动 + 非法迁移拒绝并留痕。
- 乱序（回退状态）触发 resync 全量校正而非本地硬回退。
- 重复事件幂等；每次变更（含拒绝）记录 from/to/ts/source 可审计。
- FLOW 线性序辅助快速判断旧事件。
