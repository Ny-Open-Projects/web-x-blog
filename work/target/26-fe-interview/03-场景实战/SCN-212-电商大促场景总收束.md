## SCN-212：电商大促场景的前端工程怎么总收束？

**答**:
- 全景五域：秒杀抢购（SCN-203 三态+排队）、流量洪峰（204 静态化+降级三级）、交易一致性（205 库存/206 优惠引擎/208 状态聚合/209 支付回跳）、体验性能（210 预载矩阵）、可观测（211 埋点治理）——大促前端是"高并发+高波动+高敏感"三高工程。
- 时间线管理：大促前 T-2 周（压测/降级演练/预算确认）→ T-1 周（冻结发布/预发验证/开关预配）→ 大促日（值班盯盘/降级按预案执行/紧急修复走绿色通道）→ 大促后（复盘/恢复常规配置）——大促是项目制工程，时间线即纪律。
- 降级体系总纲：所有降级预配置+演练过+触发条件明确+恢复路径明确——临时想出来的降级方案在大促日不可信。
- 收束心法：大促前端的本质是"确定性工程"——用确定性（缓存/静态化/预载/降级预案）对冲流量不确定性；工程师的价值在事前预案，不在事中救火。

```text
大促全景五域：
抢购：三态机 + 排队轮询（203）
洪峰：CDN 静态化 + 接口合并 + 降级三级（204）
交易：库存校验点 / 优惠引擎分摊 /
  状态中心 / 支付三通道（205-209）
体验：预载矩阵 + 秒开（210）
观测：埋点分级采样 + 自保护（211）
时间线：T-2 周演练 → T-1 周冻结 →
  大促日值班预案 → 复盘恢复。
总纲：用确定性对冲不确定性，
  价值在事前预案。
```
