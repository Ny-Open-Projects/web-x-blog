## SCN-578：多端验证一致性怎么保证？
**答**：
- 协议统一：三端 SDK 对接同一套决策协议（challenge/verify/token 结构一致），服务端不区分端逻辑（只把端作为信号）。
- 能力差异抽象：App 有硬件级指纹与安全键盘、H5 有 Canvas 指纹、小程序有 getSystemInfo——统一 SignalProvider 接口，各端各自实现，缺失信号标注 null 而非伪造。
- 体验一致性：同一场景三端验证强度策略一致（同一份矩阵配置），UI 差异只允许皮肤级。
- 端内降级链各自实现但顺序一致（slider → sms → email），监控分端统计成功率。
- 追问钩子：为什么小程序验证常用「图文点选」而非滑块——小程序 canvas 手势与滚动冲突问题，端差异要在协议层吸收而不是业务层感知。

```javascript
// 统一信号接口：三端各自实现
const SignalProvider = {
  async snapshot() {
    return {
      device: await this.device(),       // H5: 指纹 / App: 硬件标识 / 小程序: systemInfo
      behavior: this.behavior?.() ?? null,   // 缺失能力返回 null，不伪造
      env: this.env(),
    };
  },
};
// 注册表
registry.set('signals', isApp ? appSignals : isMini ? miniSignals : h5Signals);
```
