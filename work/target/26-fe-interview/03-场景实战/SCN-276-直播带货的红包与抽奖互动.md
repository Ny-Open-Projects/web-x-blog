## SCN-276：直播红包雨与整点抽奖，前端怎么实现公平与流畅？

**答**:
- 红包雨：动画性能（红包下落用 CSS transform/canvas 粒子——不用 JS 逐帧改 top）、点击判定（命中检测：红包 DOM 层+点击区域）、数量洪峰（每秒几十个红包的渲染上限与合并）、领取流程（点击→领取请求幂等→结果弹窗；未抢到→"手慢了"提示+下次预告）。
- 抽奖公平性：开奖以服务端为准（前端只展示动画）、抽奖资格校验（关注/评论条件服务端裁决）、防重复（一个活动一人一次，幂等键）、开奖延迟（服务端开奖→信令通知→前端动画——动画期间结果已定）。
- 全端同步：红包雨开始/结束信令同步（所有观众同时开始——信令带服务器时间戳）、动画起播对齐（以收到信令时间起播，误差可接受）。
- 防作弊：连点脚本（点击频率风控上报）、结果不可预测（前端不预知中奖者——防抓包提前知道）。

```javascript
ws.on('redpacket_start', ({ endAt, count }) => {
  startRain({ endAt, pool: spawnPool(count),  // 对象池
    renderer: canvasRain });                  // canvas 粒子
});
canvasRain.on('hit', async (packet) => {
  const r = await withIdempotency(() =>
    redpacketApi.grab(packet.id), packet.id);
  showResult(r);                             // 中/未中弹窗
});
// 开奖：ws.on('lottery_result', (winners) => playAnimation())
//   —— 前端不预知结果，动画只在收到信令后播放。
// 性能：>30 个/秒 → 合并 spawn + 采样展示。
```
