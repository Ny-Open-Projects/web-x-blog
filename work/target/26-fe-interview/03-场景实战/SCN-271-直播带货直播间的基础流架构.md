## SCN-271：直播带货间进入要秒开直播画面，拉流与首帧怎么优化？

**答**:
- 协议选择：移动端 HLS（兼容好但延迟高 5~20s）vs FLV/HTTP-FLV（延迟 2~5s，需 MSE）vs WebRTC（<1s，成本高）——带货场景通常 HTTP-FLV/HLS 混合（app 内 FLV 低延迟、H5 兜底 HLS），按端选择。
- 首帧优化：预连接（列表曝光即预建连接+预载首帧——进入直播间时已缓冲）、秒开缓冲策略（buffer 目标调低 0.5s 快速起播 vs 流畅优先）、多码率起播（先低清秒开→无缝切高清）、CDN 调度（就近边缘节点，预取推流数据的 GOP 缓存）。
- 播放器健壮性：断流重连（指数退避+换备用拉流域名/线路）、卡顿监控（stall 事件+卡顿率埋点）、延迟控制（追帧：缓冲超阈值时倍速追帧保持低延迟——直播不能攒缓冲）。
- 资源与降级：后台/锁屏暂停拉流（省流量电量）、后台仅音频模式（继续听）、拉流失败降级（封面图+重试按钮，不放黑屏）。

```javascript
const player = createPlayer({
  type: 'flv', url: pickLine(room.streamLines),  // 多线路
  lowLatency: true, bufferHint: 0.5,             // 快速起播
});
player.on('stall', () => monitor.stall(roomId));   // 卡顿埋点
player.on('error', async () => {
  const next = nextLine(room.streamLines);       // 换线路重连
  backoff(player, next);
});
document.addEventListener('visibilitychange', () => {
  document.hidden ? player.pauseAudioOnly()     // 后台仅音频
                  || player.pause()
                  : player.resume();
});
// 追帧：buffered > 3s → playbackRate = 1.5 追到 1s 内
// 预载：listView.on('expose', (room) => warmup(room.streamLines))
```
