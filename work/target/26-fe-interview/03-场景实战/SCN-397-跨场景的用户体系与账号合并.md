## SCN-397：多业务线用户身份统一（账号合并/多端身份/隐私）怎么实现？

**答**:
- 身份统一：统一 ID 体系（OneID：跨业务唯一身份——业务侧 UID 映射到 OneID），账号合并（同人多账号合并场景：手机号关联合并——合并确认流程：数据归属确认+不可逆警示），多端身份（SCN-446 多端同步复用）。
- 前端体验：跨业务登录态（SSO——SCN-318 复用），统一个人中心（跨业务资产聚合：订单+会员+券——SCN-393 收银台同源），身份变更广播（改手机号/注销→全业务同步——SCN-318 登出广播复用）。
- 隐私与合规：统一隐私设置（隐私中心：授权管理/数据导出/注销——SCN-440 导出删除权复用全业务）、跨业务数据共享的授权边界（业务间数据不默认互通——最小化原则）、注销的全业务贯穿（SCN-440 删除链全业务版）。
- 合并的工程风险：合并的数据冲突（订单/积分/等级合并规则——业务定序），合并后的服务端路由（OneID 路由层——老 UID 重定向），合并通知（各业务端同步刷新）。

```javascript
// 账号合并流程
async function mergeAccounts(primary, secondary) {
  const impact = await api.mergePreview(primary, secondary);
  const ok = await modal.confirm(impact, { irreversible: true,  // 不可逆警示（业务 Modal，返回 Promise）
    detail: '订单/积分/会员等级按规则合并' });
  if (!ok) return;                           // 用户取消：不合并
  await api.merge(primary, secondary);
  broadcast('identity_merged', { primary }); // 全业务刷新
  relogin(primary);                          // 统一登录态
}
// OneID 路由：旧 UID → OneID → 业务数据
// 注销：purgeAll(oneId)（SCN-440 全业务贯穿）
// 隐私中心：统一授权/导出/删除入口。
```

**追问**：

1. 合并后老 UID 的订单链接还有效吗？ → OneID 路由层做老 UID 到 OneID 的重定向并保留跳转，不能直接 404。
2. 两个账号都有会员等级，合并按「取高」还是「叠加」谁定？ → 业务规则定序并写进 mergePreview 明确告知用户，前端只呈现不可自行决定。
3. 合并不可逆，用户误操作怎么给后悔药？ → 合并前做完整影响预览与二次确认，合并后保留短期内可申诉回滚的服务端快照。
