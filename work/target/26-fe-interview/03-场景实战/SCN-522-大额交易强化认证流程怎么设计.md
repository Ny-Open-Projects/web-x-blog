## SCN-522：大额交易强化认证流程怎么设计？
**答**：
- 风险分级触发：服务端按金额/环境/行为评分返回 requiredAuthLevels（如 ["sms","face","paypwd"]），前端按序渲染认证器队列，不做本地判断阈值。
- 认证器可插拔：统一 Authenticator 接口（verify() → token），新认证方式（刷脸/声纹）零改表单接入。
- 中断续接：认证中途切后台/失败，challengId 保持有效期内可续；过期重新发起并提示原因。
- 结果传递：认证 token 只进交易接口，不进 URL/日志；全流程埋点记录各认证器耗时与失败率，供风控调参。
- 追问钩子：多认证器串行太慢怎么办——支持并行采集（人脸+密码同时输入）后一次性提交校验。

```javascript
const AUTHENTICATORS = {
  sms: (ch) => smsForm(ch), face: (ch) => faceCapture(ch), paypwd: () => secureKeypad(),
};
async function stepUp(levels, bizPayload) {
  const { challengeId, expiresAt } = await api.post('/auth/challenge', { levels, bizPayload });
  const tokens = [];
  for (const lv of levels) {                     // 按服务端给定顺序
    const t = await AUTHENTICATORS[lv]({ challengeId, expiresAt });
    tokens.push({ level: lv, token: t });
  }
  return api.post('/auth/verify', { challengeId, tokens }); // 换交易凭证
}
```
