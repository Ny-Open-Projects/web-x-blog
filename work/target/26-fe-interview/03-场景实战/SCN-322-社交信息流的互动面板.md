## SCN-322：信息流互动（点赞/评论/转发）的乐观更新与一致性怎么处理？

**答**:
- 乐观更新：点赞立即上屏（本地状态翻转+动画）+后台同步，失败回滚（toast 提示）——互动是高频低价值操作，乐观是体验基线；连点合并（狂点点赞合并为一次请求+动画节流）。
- 计数一致性：展示计数与真实计数的服务端校正（重连/页面回前台校正——本地漂移容忍）、大数缩写（1.2w）与精度（本地计数误差可接受范围）、点赞取消竞态（连点+取消的请求序——按操作时间戳服务端定序，前端防抖）。
- 评论区：评论输入与发表（乐观上屏：自己的评论立即显示）、评论分页（楼层加载/热门评论置顶）、回复嵌套（两层结构：评论+回复扁平化渲染）、删除与审核态（自己可见"审核中"他人不可见——可见性分端）。
- 转发链路：转发到会话/朋友圈的分享卡片（OG 元数据/小程序卡），转发计数乐观更新。

```javascript
async function like(post) {
  post.liked = !post.liked;                  // 乐观翻转
  post.likes += post.liked ? 1 : -1;
  animate(post);
  try { await api.like(post.id, post.liked,
    { idempotencyKey: likeKey(post) }); }
  catch { revert(post); toast('操作失败，请重试'); }  // 回滚
}
// 连点合并：300ms 窗口内合并状态，只发最终态
// 计数校正：onVisible → api.refreshCounts(post.id)
// 评论可见性：mine && pending → '审核中' 仅自己可见。
```
