## SCN-209：支付从第三方 App 回跳后，结果确认的可靠流程怎么设计？

**答**:
- 回跳三通道冗余：URL 参数（渠道回传凭据，仅作参考不作为最终态）、主动查询（回跳后调支付结果接口，带重试）、推送/WebSocket（服务端异步通知）——三通道任一确认即更新，URL 与查询冲突时以查询为准。
- 确认流程：回跳后立即进入"确认中"态（轮询 3 次 ×2s 间隔），确认成功→结果页；超时未确认→"处理中"页+后台继续轮询（最长 2 分钟），期间用户可离开（结果落地后通知/订单列表可见）——绝不把"未确认"当"失败"。
- 防重复：支付单号幂等（同一支付单的确认请求幂等）、结果页防回退重复支付（已支付订单入口置灰）、客户端发起支付前查单（未支付才发起）。
- 异常兜底：查询接口失败→展示订单号与"稍后在订单列表查看"引导（用户有确定出口）、渠道回调丢失（用户已扣款但状态未更）→客服通道与申诉入口显性给出。

```javascript
async function onPayReturn(payNo) {
  setState('confirming');
  for (let i = 0; i < 3; i++) {
    const r = await payApi.status(payNo);
    if (r.status === 'paid') return showSuccess(r);
    if (r.status === 'failed') return showFail(r);
    await sleep(2000);
  }
  setState('processing');                    // 超时：处理中而非失败
  backgroundPoll(payNo, { maxMs: 120e3, onPaid: showSuccess,
    onFail: showFail, onTimeout: () => showGuide(payNo) });
}
function backgroundPoll(payNo, o) {
  const start = Date.now();
  const timer = setInterval(async () => {
    if (Date.now() - start > o.maxMs) { clearInterval(timer);
      return o.onTimeout(); }
    const r = await payApi.status(payNo).catch(() => null);
    if (r?.status === 'paid') { clearInterval(timer); o.onPaid(r); }
    if (r?.status === 'failed') { clearInterval(timer); o.onFail(r); }
  }, 3000);
}
```

**追问**：

1. 回跳 URL 带 `status=success` 但主动查询仍 pending，界面怎么定？ → 一律以查询结果为准进「处理中」，URL 参数只用于触发查询，绝不直接渲染成功。
2. 后台轮询到 maxMs 用户已经关页走了，结果怎么送达？ → 确认结果落库后靠推送、短信或订单列表红点兜底，客户端不承担「必须在线确认」。
3. 用户回跳后连点重新支付造成重复扣款，除了置灰还要做什么？ → 发起前先查单，服务端对同订单支付单做唯一约束，已重复支付的走自动退款。
