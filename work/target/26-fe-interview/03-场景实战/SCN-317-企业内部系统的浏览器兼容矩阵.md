## SCN-317：企业内部系统要兼容老浏览器/内网特殊环境，策略怎么定？

**答**:
- 兼容矩阵管理：浏览器支持声明（支持/兼容/不支持三级：支持=全功能验证、兼容=可用不保证体验、不支持=引导升级），UA 探测与引导（不支持浏览器→明确引导页：升级链接/用支持的浏览器打开），矩阵进 CI（目标浏览器集合驱动构建 target 与 polyfill 策略）。
- 老内核策略：降级方案（新功能在老浏览器降级为简化版——功能可用性优先于一致性）、Polyfill 预算（polyfill 体积成本——按需注入）、渐进增强（核心流程所有浏览器可用，增强体验渐进）。
- 内网特殊环境：内网 CDN 与依赖自托管（公共 CDN 不可达——npm 依赖全部自托管 SC 内网 npm 复用）、代理与证书（内网 HTTPS 证书链问题）、客户端环境固化（企业统一浏览器版本——按该版本做兼容基线反而简化）。
- 推动升级：数据驱动升级（老浏览器使用率统计→推动 IT 部门统一升级——工程沟通数据说话）、升级过渡期双轨（新旧版本按 UA 分流，设截止日期）。

```text
兼容策略：
声明：支持/兼容/不支持 三级 + 引导页
CI：target 浏览器集合 → 构建 target/polyfill
老内核：功能降级简化版 + 按需 polyfill
内网：依赖全自托管 + 证书链处理
固化：企业统一浏览器版本 = 兼容基线
升级：使用率数据 → 推动 IT 统一升级
  → 双轨过渡 + 截止日期。
```
