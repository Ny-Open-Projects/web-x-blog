## SCN-238：课堂秩序管理（禁言/点名/一键锁屏）的功能与实现？

**答**:
- 禁言体系：全员禁言（聊天通道关闭，信令广播）/单人禁言（定时可选）、禁言的呈现（被禁言者输入框禁用+提示原因与时长）、禁言豁免（老师/助教不受限）。
- 点名功能：随机点名（服务端随机选定，全端同步高亮该学生）、应答流程（被点名者上台连麦 SCN-235/文字应答）、点名历史（防重复点同一人可配置）。
- 锁屏与专注模式：老师端"锁定学生端课件页"（学生端禁止切走：检测切屏并提示+记录，无法真正强制——浏览器边界，教育场景靠约定+记录）、专注度面板（老师看每个学生的切屏次数/在线状态聚合）。
- 信令优先级：秩序类信令（禁言/下台/锁屏）最高优先级即时生效，普通消息排队——课堂控制权是体验底线。

```javascript
ws.on('mute', ({ target, duration }) => {
  if (target === me) { chat.disable(duration); 
    toast(`已被禁言 ${duration / 60} 分钟`); }
  else roster.update(target, { muted: true });
});
// 随机点名（服务端定序公平）
ws.on('rollcall', ({ studentId }) => {
  highlight(studentId);
  if (studentId === me) promptAnswer();      // 应答提示
});
// 专注模式：切屏记录（SCN-236 monitor 复用）
// 老师面板：focusPanel = roster.map(s => ({
//   status: s.presence.status,
//   blurCount: focusStats[s.id]?.blurCount ?? 0 }))
```

**边界与易错**：

1. 禁言只在前端 `chat.disable()`，学生刷新或换端就恢复——禁言态必须服务端下发并在拉取会话信息时带回，前端只负责呈现。
2. `duration` 传 0 或负数表示「永久禁言」还是「立即解禁」要显式约定，否则 `duration/60` 会显示「禁言 0 分钟」。
3. 锁屏靠 `blur` 检测切屏，但切标签、弹输入法都会触发 blur，不做过滤会把正常操作记成违规。

**追问**：

1. 服务端随机点名怎么既防重复又不失公平？ → 服务端维护本轮已点集合，点完一轮再重置，前端不要自己 random。
2. 网络抖动导致禁言信令丢失，被禁言者还能发言怎么办？ → 发言请求由服务端鉴权兜底拒绝，信令只负责即时 UI，不能当唯一闸门。
3. 锁屏「无法真正强制」这个边界，产品上怎么交代？ → 明确只做检测、记录与提示，把约束力放在「切屏次数上报老师」而非技术封锁。
