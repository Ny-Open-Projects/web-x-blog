## SCN-226：版本历史回滚（恢复到昨天版本）时怎么不覆盖他人今天的编辑？

**答**:
- 回滚语义设计：协作文档的"回滚"不是覆盖（覆盖会丢他人编辑），而是"反向操作"（生成一个撤销补丁：把目标版本之后的变更反转应用）——回滚本身也是一次协作操作，进 seq 流水。
- 实现方式：CRDT 下回滚=diff 两版本生成反向 update（Yjs 的 Y.diffApi/自研 diff：字符级 diff 生成删除+插入操作），以当前用户身份提交——他人的并行编辑在 diff 范围外则保留。
- 版本快照体系：自动快照（定时+里程碑：标题变更/字数突变）、手动版本（用户命名保存）、快照元数据（作者/时间/字数/diff 摘要）——快照用于浏览与 diff，反向补丁用于恢复。
- 浏览器体验：版本时间线（滑块选择任意版本对比当前）、双栏 diff（所选版本 vs 当前，高亮差异）、"恢复此版本"按钮→确认弹窗说明影响（"将撤销 X 处变更，他人的 N 处编辑将保留"）。

```javascript
async function restoreVersion(versionId) {
  const snapshot = await api.getVersion(versionId);
  // diff 快照与当前文档 → 反向补丁
  const patch = diffDocs(currentDoc(), snapshot);
  // patch = [{op:'delete', range}, {op:'insert', text}, ...]
  // 以协作操作形式提交（进 seq 流水，他人编辑保留）
  ydoc.transact(() => {
    applyPatch(patch);
  });
  history.push({ type: 'restore',
    from: versionId, patchSummary: summarize(patch) });
}
// UI：时间线滑块 → 双栏 diff → 确认弹窗
// （"撤销 N 处变更，保留他人 M 处编辑"）→ applyPatch。
```
