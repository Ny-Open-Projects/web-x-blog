## SCN-605：会签/或签/并行分支怎么设计？
**答**：
- 三种模式渲染：会签（全同意才过）节点展示各签署人状态列表，或签（一人同意即过）展示「首个通过者」，并行分支画两条并行泳道汇入汇聚节点。
- 意见聚合：同节点多人意见按时间轴聚合，同意见（都同意）折叠为「3 人已同意」+展开明细；驳回意见永不折叠（重要信息）。
- 状态推导：节点状态由服务端计算下发（PASSING/PASSED/REJECTED），前端不自己算会签结果——多人并发签署的中间态服务端才有一致视图。
- 提醒机制：会签未完成时向未签署人催办按钮（有权限控制）；展示已完成 N/共 M 进度。
- 追问钩子：会签中一人驳回，其他人已填的意见怎么办——节点整体 REJECTED，意见保留但标灰为「流程已终止」，保留审计价值。

```javascript
function coSignView(node) {
  if (node.mode === 'COUNTERSIGN') {                 // 会签
    const done = node.signers.filter(s => s.signed);
    return {
      progress: `${done.length}/${node.signers.length}`,
      status: node.status,                           // 服务端下发，不算
      items: node.signers.map(s => ({
        ...s, collapsed: s.signed && s.opinion === 'agree',   // 同意折叠，驳回保留
      })),
      canUrge: node.status === 'PASSING' && hasUrgePerm(node),
    };
  }
  if (node.mode === 'ANY_SIGN') {                    // 或签
    const winner = node.signers.find(s => s.signed);
    return { winner, others: node.signers.filter(s => s !== winner && !s.signed) };
  }
}
```
