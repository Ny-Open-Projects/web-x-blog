## SCN-272：直播弹幕每秒几千条，渲染与发送怎么做？

**答**:
- 接收聚合：弹幕消息批量接收（服务端聚合包：100ms 一批 N 条）+ 客户端聚合渲染（rAF 批量 flush）、洪峰采样（>500 条/秒时服务端抽样下发或前端丢弃非关键弹幕——展示采样不影响语义）、礼物/系统消息优先级高（不可丢弃）。
- 渲染方案：弹幕池复用（DOM 弹幕对象池：固定 N 个轨道对象循环使用——不频繁创建销毁）、canvas 弹幕（万级用 canvas 轨道渲染）、滚动列表弹幕（聊天式：虚拟列表+聚合批 append+自动滚动到底（用户上滑查看历史时暂停自动滚动+回到底部按钮））。
- 发送侧：发送限频（1 条/秒）、发送失败重试（会话级队列）、敏感词前端预检（本地词库快筛+服务端终审）。
- 性能护栏：弹幕开关（用户可关弹幕省性能）、低端机降级（弹幕密度减半/纯礼物特效关闭）、内存巡检（长时直播的内存泄漏防护——弹幕对象池即为此设计）。

```javascript
ws.on('danmaku_batch', (batch) => {          // 100ms 一批
  const kept = floodControl(batch);          // 洪峰采样
  rafQueue.push(...kept);
});
function rafFlush() {                        // rAF 批量渲染
  const batch = rafQueue.splice(0, 30);
  batch.forEach(d => pool.fire(d));          // 对象池复用
  if (rafQueue.length) requestAnimationFrame(rafFlush);
}
// 对象池：10 轨道 × 每轨 3 个弹幕 DOM 循环使用；
// 礼物消息走独立高优通道不参与采样。
// 用户上滑 → autoScroll=false + 回到底部按钮。
```

**边界与易错**：

1. 对象池「10 轨 × 每轨 3 个」是硬上限，洪峰时 `pool.fire` 取不到空闲对象若直接丢弃，礼物消息也会被误丢——礼物必须走独立通道。
2. rAF flush 里固定 `splice(0,30)`，队列持续增长时每帧只出 30 条会越积越多，应按「帧时间预算」而非固定条数控制。
3. 用户上滑设 `autoScroll=false`，但新消息仍 append 会让 scrollTop 漂移，必须记录「距底部距离」并在回底时恢复。

**追问**：

1. 前端丢弃「非关键弹幕」做采样，用户自己发的弹幕会不会被丢？ → 自己发的走本地回流必显，采样只针对他人消息。
2. canvas 弹幕和 DOM 对象池怎么选？ → 千级以下 DOM 池足够且可交互，万级或复杂样式才上 canvas，而 canvas 会失去文本选中与无障碍。
3. 长时直播内存持续上涨，除了对象池还要查什么？ → 查 ws 监听是否重复注册、图片与礼物资源是否无上限缓存。
