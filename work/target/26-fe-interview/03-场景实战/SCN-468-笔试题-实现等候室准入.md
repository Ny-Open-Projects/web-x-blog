## SCN-468：手写等候室：等待态呈现、准入信令+轮询兜底、批量准入

**需求与边界**：
- 输入：入会请求被锁会拦截；输出：等候室状态管理。
- 边界要求：① 等待态呈现（主持人会很快让您进入）；② 准入信令优先+轮询兜底（信令丢失也能入会）；③ 主持人端批量准入/逐个；④ 等候室列表实时（主持人视图）。

**答**：
```javascript
// 参会者端
class WaitingRoom {
  async enter(meetingId) {
    const r = await api.joinRequest(meetingId);   // 请求入会
    if (r.admitted) return join();
    this.waiting = true;
    ws.on(`admit:${meetingId}`, () => join());    // 信令优先
    this.poll = setInterval(async () => {         // 轮询兜底
      const s = await api.joinStatus(meetingId);
      if (s.admitted) { clearInterval(this.poll); join(); }
    }, 3000);
  }
}
// 主持人端：waitingList 实时（信令推送新请求）
//   → admit(ids) 批量 / admitOne(id) / deny(id)
//   → deny 提示原因可写（"会议已结束"）。
// 信令与轮询双通道去重（join 幂等——已入会重复调用无效）。
```

**评分点**:
- 信令优先+轮询兜底双通道（准入不丢）。
- join 幂等（双通道同时触发的去重）。
- 主持人批量/逐个准入+拒绝原因。
- 等待态体验（预期管理文案）。
