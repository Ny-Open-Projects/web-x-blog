## SCN-553：风控验证前端整体架构与 SDK 分层怎么设计？
**答**：
- 分层设计：采集层（行为/设备信号被动收集）→ 决策代理层（服务端评分返回验证等级）→ 渲染层（按等级挂载对应验证器：无感/滑块/答题/人脸）→ 上报层（验证结果与耗时埋点）。前端不做风控决策，只做采集与执行。
- SDK 形态：独立 npm 包 + 版本化发布，业务方声明式接入 `riskGuard.mount({ scene: 'pay', onPass, onFail })`；验证器插件注册（新验证方式不改主流程）。
- 降级链：风控接口超时 → 降级为本地基础校验 + 事后补验；SDK 加载失败 → 业务流程不阻断但打标。
- 隐私边界：采集字段白名单化、声明用途、敏感字段（精确位置/通讯录）绝不采集。
- 追问钩子：为什么决策必须服务端——前端任何评分都可被篡改，前端只提供「更难伪造的信号」。

```javascript
// 风控验证 SDK 主流程
const registry = new Map();                       // 验证器插件注册
function registerVerifier(name, impl) { registry.set(name, impl); }
async function riskGuard({ scene, onPass, onFail }) {
  let decision;
  try {
    decision = await api.post('/risk/challenge', {
      scene, signals: collector.snapshot(),       // 采集层信号快照
    }, { timeout: 3000 });
  } catch {
    decision = { level: 'BASIC' };                // 降级：本地基础校验
  }
  if (decision.level === 'NONE') return onPass();  // 服务端判定无需验证
  const verifier = registry.get(decision.verifier);
  if (!verifier)                                  // 拿不到/不认识验证器：不能静默放行
    return localFallback(scene, onPass, onFail);  // 降级本地基础校验，仍失败则走 onFail
  const result = await verifier.run(decision);    // 渲染层执行
  result.pass ? onPass(result.token) : onFail(result.reason);
}
```
