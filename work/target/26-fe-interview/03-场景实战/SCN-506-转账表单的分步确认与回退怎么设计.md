## SCN-506：转账表单的分步确认与回退怎么设计？
**答**：
- 分步状态机：填写 → 风险揭示 → 强认证 → 确认 → 结果，每步只进不退敏感步骤（确认后不可回退改金额），可退步骤用本地快照恢复。
- 服务端预检：每步提交生成 stepToken，最终下单携带全链 stepToken，服务端校验「用户确认的金额 = 提交的金额」，前端状态不可信。
- 回退安全：返回上一步要重新拉取对手方信息与限额，不缓存可能过期的风控结论（如收款人黑名单状态）。
- 中断恢复：填写的非敏感草稿本地加密暂存；敏感字段（密码/验证码）永不落盘，恢复后重新输入。
- 追问钩子：确认页停留 10 分钟后提交——服务端有效期校验 + 前端倒计时提示重新确认。

```javascript
const transferFlow = {
  state: 'fill', stepToken: null,
  async submit(step, data) {
    const res = await api.post(`/transfer/step/${step}`, { ...data, prev: this.stepToken });
    this.stepToken = res.token;                 // 链式 token，服务端校验顺序
    this.state = res.next;                      // fill -> risk -> auth -> confirm
    if (this.state === 'confirm') this.startCountdown(600); // 10 分钟有效
  },
  back(to) {
    if (['confirm', 'result'].includes(this.state)) throw new Error('不可回退');
    this.state = to;
    this.refreshCounterparty();                 // 重新拉风控结论，不用缓存
  },
};
```
