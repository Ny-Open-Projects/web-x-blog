## SCN-244：低代码产出的页面与手写代码页面要长期共存，怎么设计？

**答**:
- 共存三模式：嵌入（手写页面里嵌低代码区块：活动楼层/运营配置区）、引用（低代码页面里嵌手写自定义组件——组件注册进平台白名单）、同应用混合路由（低代码页与手写页同 SPA 共存，统一鉴权/主题/埋点）——按场景选模式而非二选一。
- 边界契约：设计 token 共享（主题变量同一来源）、组件契约（低代码用的自定义组件按平台 SDK 规范开发：props 协议/事件协议/数据协议）、路由与登录态统一（宿主提供 runtime：路由/鉴权/请求封装注入低代码运行时）。
- 演进路径：低代码页面复杂度超阈值→"导出代码"逃生舱（schema→代码生成一次性导出，转手写维护——单向门，导出后不再回低代码）；手写组件沉淀→注册进低代码组件库（反向增益）。
- 治理：低代码页面也走发布流程（版本/灰度/回滚）、权限隔离（低代码编辑权限与代码仓库权限分离）、质量基线（低代码页面的性能预算与手写一致——SCN 性能预算同源）。

```text
共存三模式：
嵌入：手写页嵌低代码区块（运营区）
引用：低代码嵌手写组件（SDK 规范）
混合路由：统一 runtime（鉴权/主题/埋点）
边界契约：设计 token 同源 / 组件 SDK 协议 /
  runtime 注入
逃生舱：复杂页导出代码转手写（单向门）
治理：低代码页同走发布/灰度/回滚，
  性能预算与手写一致。
```
