## SCN-579：验证配置中心怎么设计？
**答**：
- 配置分层：全局默认 → 场景覆盖 → 用户群覆盖（新设备/高危地区），生效时逐层 merge；每层带 schema 校验。
- 防爆炸半径：配置变更灰度（按流量/白名单）+ 自动快照回滚（新配置导致通过率异常自动回退）+ 变更审计（谁改的/何时/diff）。
- 客户端容错：配置解析失败用上次成功缓存（localStorage 版本化），绝不因坏配置阻断全部验证。
- 审计与演练：季度演练「配置错误→自动回滚」链路；schema 用 JSON Schema 校验在提交时拦截。
- 追问钩子：为什么客户端要缓存上次配置——CDN/配置服务故障时保持可用性，坏配置的最坏后果只是「沿用旧策略」。

```javascript
function resolveConfig(layers) {                    // [global, scene, cohort]
  return layers.reduce((acc, l) => {
    validate(l, RiskSchema);                        // 提交时已校验，运行时防御
    return { ...acc, ...l.overrides };
  }, {});
}
function loadClientConfig() {
  try {
    const cfg = resolveConfig(fetchRemote());
    localStorage.setItem('risk_cfg_v' + version, JSON.stringify(cfg));
    return cfg;
  } catch {
    return JSON.parse(localStorage.getItem('risk_cfg_v' + lastGoodVersion)); // 回退缓存
  }
}
```
