## SCN-607：撤回/加签/回退怎么设计？
**答**：
- 能力下发：每个审批实例给当前用户返回 allowedOperations（withdraw/addSign/return/reject...），前端只渲染允许的操作——规则在服务端（涉及流程引擎语义），前端不自推。
- 影响提示：每个操作带影响说明（撤回：流程终止，已产生的意见保留；回退到发起人：需重新提交），确认弹窗动态渲染。
- 加签语义：在当前节点前/后插入审批人（前加签=新增会签人，后加签=通过后追加节点），UI 上要在流程图中直观标出插入位置。
- 状态一致：操作后全量刷新实例（含流程图/表单/时间线），不局部 patch——流程引擎状态复杂，局部更新易不一致。
- 追问钩子：为什么撤回后不能直接重新提交——撤回可能伴随表单修改，服务端要求重新走完整校验链。

```javascript
const OP_TEXT = {
  withdraw: { label: '撤回', impact: '流程将终止，已产生的审批意见保留存档' },
  addSign:  { label: '加签', impact: '在当前节点新增会签人，需所有会签人通过后继续' },
  return:   { label: '退回发起人', impact: '退回后需修改并重新提交，原审批意见保留' },
};
function OperationBar({ instance }) {
  return instance.allowedOperations.map(op => (
    <button key={op}
      onClick={() => confirmDialog({
        title: OP_TEXT[op].label,
        content: OP_TEXT[op].impact,             // 动态影响说明
        onOk: () => doOperation(instance.id, op).then(refetchAll),   // 全量刷新
      })}>{OP_TEXT[op].label}</button>
  ));
}
```
