## SCN-609：审批权限矩阵怎么设计？
**答**：
- 四类权限：VIEW（可见实例范围：本部门/全部/仅自己发起）、OPERATE（可审哪些节点）、ADMIN（改流程定义/代批）、AUDIT（只读审计）。权限点按「角色 × 场景 × 动作」矩阵管理。
- 数据权限下推：列表查询由服务端按权限过滤返回，前端不做权限过滤——前端权限只控制 UI 显隐（防误操作），不作为安全边界。
- 矩阵可视化：权限配置页用矩阵表格（行=角色，列=动作，勾选交叉点），变更留审计并支持导出评审。
- 前后端一致性：前端 UI 判断与后端校验用同一份权限字典（接口下发 permCode 集合），不一致时以后端为准并上报差异。
- 追问钩子：代理审批（委托）怎么进权限模型——委托是「操作人≠审批人」的特殊授权，操作记录里 both 字段都要落。

```javascript
const PERM_MATRIX = {
  approver: { view: 'dept', operate: ['approve', 'reject', 'return'], admin: false, audit: false },
  admin:    { view: 'all',  operate: ['*'], admin: true, audit: true },
  auditor:  { view: 'all',  operate: [], admin: false, audit: true },   // 只读
};
function can(user, action, ctx) {
  const role = resolveRole(user, ctx);            // 可能是委托链：主审批人缺勤时代理
  const p = PERM_MATRIX[role];
  return p?.operate.includes('*') || p?.operate.includes(action) || false;
}
// 前端 UI 显隐用 can()；真实提交后端二次校验（前端权限不是安全边界）
```
