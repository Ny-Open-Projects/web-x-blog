## SCN-585：验证服务限流时前端怎么配合？
**答**：
- 感知信号：响应头/体带限流等级（QPS 超标），前端进入「节流模式」——合并信号上报、暂停非必要行为采集、延长决策缓存。
- 客户端排队：本地令牌桶限制验证发起频率（超并发时排队并提示），避免用户狂点加剧过载。
- 分级让路：按场景优先级让路（支付验证 > 领券验证），低优先级场景暂用更轻验证器。
- 恢复探测：限流解除由服务端推送/前端低频探测（指数退避），恢复后逐级放开而非瞬时全量。
- 追问钩子：为什么前端不能「默默重试」——重试风暴会拖垮过载服务，必须配合退避与排队。

```javascript
function adaptiveThrottle(feedback) {
  if (feedback.level === 'OVERLOAD') {
    reporter.mode = 'minimal';                     // 只上报关键信号
    collector.pause?.();                           // 暂停行为采集
    return {
      gate: tokenBucket({ rate: 0.2 }),            // 验证发起频率降到 20%
      retry: backoff(2, 30_000),                   // 指数退避探测恢复
    };
  }
  if (feedback.level === 'RECOVERING') {
    reporter.mode = 'normal';
    return { gate: tokenBucket({ rate: 0.6 }), retry: null };  // 逐级放开
  }
}
```
