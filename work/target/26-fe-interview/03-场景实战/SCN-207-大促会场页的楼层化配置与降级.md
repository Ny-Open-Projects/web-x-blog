## SCN-207：大促会场页由运营配置楼层拼装，性能与降级怎么设计？

**答**:
- 楼层协议：楼层 schema（type/props/dataSource/priority），渲染注册表（type→组件，白名单注册），数据源声明（独立接口/SSR 内联/静态）——楼层化让运营拼装与前端组件解耦。
- 渲染策略：首屏楼层 SSR 直出（前 3 楼层关键路径），非首屏楼层懒加载+骨架屏；楼层间错误隔离（单楼层渲染异常→该楼层降级隐藏，不拖垮整页——ErrorBoundary per 楼层）。
- 数据源降级：楼层接口失败→楼层缓存（上次成功数据，本地+CDN 双份）→静态兜底楼层（运营预配置的通用楼层）——每楼层独立降级，整页不死。
- 发布安全：楼层配置版本化（活动开始前锁定，改配置走审核）、配置校验（发布前 schema 校验+预览验证）、紧急下线开关（单楼层 kill switch，运营可自助操作）。

```javascript
const registry = { banner: BannerF, flash: FlashF,
  goods: GoodsF, live: LiveF };          // 白名单注册
function renderFloors(configs) {
  return configs.sort((a, b) => a.priority - b.priority)
    .map(c => {
      const Comp = registry[c.type];
      if (!Comp) return null;                    // 未知类型跳过
      return (
        <FloorErrorBoundary key={c.id}
          fallback={c.fallbackStatic ?? null}>   {/* 楼层兜底 */}
          <Suspense fallback={<FloorSkeleton />}>
            <Comp {...c.props} source={c.dataSource} />
          </Suspense>
        </FloorErrorBoundary>);
    });
}
// 数据源：ssr（首屏）/ api（懒加载）/ static（兜底）
// 楼层配置版本化 + 发布前校验 + 单楼层 kill switch。
```
