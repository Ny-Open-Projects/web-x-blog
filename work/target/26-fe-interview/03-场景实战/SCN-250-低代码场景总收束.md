## SCN-250：低代码平台的前端工程怎么总收束？

**答**:
- 全景五模块：渲染引擎（241 schema 协议/沙箱表达式）、编辑器（242 画布交互/Command 撤销）、数据逻辑（243 数据源/动作编排/逃生舱）、平台治理（244 共存/245 版本回滚/247 组件生态/249 协作权限）、多端（248 逻辑渲染分离）——低代码是"平台产品"，工程重心在协议与治理。
- 核心协议三件：schema 协议（节点树+绑定+事件，版本化演进）、组件 SDK 协议（组件与平台的契约）、动作协议（事件的编排语义）——协议稳定是生态繁荣的前提。
- 能力边界管理：低代码的目标用户（运营/轻定制）与能力上限明确（复杂逻辑→代码逃生舱）、平台复杂度自律（功能蔓延会让编辑器不可用）、度量（搭建时长/一次通过率/导出代码率——逃生舱率升高说明平台能力不足）。
- 收束心法：低代码的本质是"把前端工程能力产品化"——组件注册表=组件库管理、Command 撤销=编辑器工程、schema 校验=发布流水线、权限协作=协作工程；做低代码是用工程方法降低他人的工程门槛，自身的工程质量要求反而更高。

```text
低代码全景：
渲染：schema 协议 + 白名单 + 表达式沙箱
编辑：画布 + Command 撤销 + 撤销栈
数据：数据源抽象 + 动作编排 + 逃生舱
治理：版本/回滚/灰度 + 组件生态 +
  权限协作 + 与手写共存
多端：逻辑渲染分离 + 分端注册表
度量：搭建时长 / 一次通过率 / 导出率。
心法：把前端工程能力产品化，
  平台自身工程要求更高。
```
