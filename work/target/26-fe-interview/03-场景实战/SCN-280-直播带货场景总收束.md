## SCN-280：直播带货全链路的前端工程怎么总收束？

**答**:
- 全景六域：流媒体（271 拉流秒开/275 连麦）、互动洪峰（272 弹幕/276 红包抽奖/277 礼物）、交易联动（273 商品卡片/274 秒杀）、质量保障（278 监控兜底）、主播端（279 中控）、基础设施（信令分级/对象池/动效资源管理）。
- 通道架构总纲：直播间内四类通道分离——媒体流（FLV/RTC）、信令（商品切换/状态广播：高优低频）、弹幕互动（高频可采样）、操作（主播控制：幂等可靠）——通道职责分离让洪峰治理可分而治之。
- 洪峰哲学：直播是"持续洪峰"场景（几小时的高频消息流），所有渲染必须对象池化+聚合批处理+可采样降级——内存与 CPU 的长时稳定比峰值更重要（长时直播内存泄漏是必修题）。
- 收束心法：直播带货 = 流媒体工程 × 实时互动 × 电商交易的交叉——播放器兜底保障"看得见"、信令分级保障"控得住"、购买闭环保障"买得顺"；三者互相独立又要在同一个页面内存里共存，资源管理是隐性的核心难点。

```text
直播带货全景：
流：FLV/HLS 分端 + 秒开预连 + 追帧 + 多线路兜底
互动：弹幕聚合采样 + 礼物队列 + 红包 canvas
交易：商品池预载 + 讲解信令 + 站内闭环下单
质量：卡顿率/黑屏检测 + 自动换线 reload
主播：中控幂等 + 推流监控 + 断网缓冲
通道：媒体/信令/弹幕/操作 四通道分离。
心法：长时洪峰，对象池+聚合+降级保稳定。
```
