## SCN-641：手写加签插队算法

**需求与边界**：
- 语义：前加签（在当前节点前插入会签组，新组通过后回到原节点）、后加签（原节点通过后追加节点再继续）；加签节点携带发起人与理由。
- 要求：① 修改流程实例的运行时节点序列（不改定义）；② 前加签后原节点的已签意见保留；③ 加签记录进审计；④ 校验循环加签（同一节点最多加签 2 次）。

**答**：
```javascript
function addSign(instance, currentNodeId, newSigner, { position, reason, operator }) {
  const chain = instance.runtimeChain;               // 运行时节点链（数组）
  const idx = chain.findIndex(n => n.id === currentNodeId);
  if (idx < 0) throw new Error('NODE_NOT_FOUND');
  const node = chain[idx];
  const addTimes = (node.addSignCount ?? 0) + 1;
  if (addTimes > 2) throw new Error('ADD_SIGN_LIMIT');   // 防循环加签
  const addNode = {
    id: `add_${instance.id}_${addTimes}`,
    type: 'ADDED_COSIGN', signers: [newSigner],
    reason, createdBy: operator, createdAt: Date.now(),
  };
  if (position === 'before') {
    // 前加签：插入当前节点之前；当前节点已签意见保留（idx 不动）
    chain.splice(idx, 0, addNode);
  } else {
    // 后加签：当前节点之后
    chain.splice(idx + 1, 0, addNode);
  }
  node.addSignCount = addTimes;
  instance.audit.push({ op: 'ADD_SIGN', nodeId: currentNodeId, position,
                        signer: newSigner, reason, operator, ts: Date.now() });
  return { chain, current: position === 'before' ? addNode.id : currentNodeId };
}
// 前加签后回原节点：运行时引擎按链顺序推进，ADDED_COSIGN 通过后下一节点即原节点（意见仍在其上）
```

**评分点**:
- 运行时链修改不污染流程定义。
- 前加签保留原节点已签意见（idx 不动，语义正确）。
- 加签次数上限（防循环加签）。
- 审计记录完整（op/position/reason/operator/ts）。
