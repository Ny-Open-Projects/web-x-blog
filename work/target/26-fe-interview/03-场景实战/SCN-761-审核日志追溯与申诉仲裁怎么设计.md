## SCN-761：审核日志与申诉仲裁怎么设计？
**答**：
- 全链路日志：机审分数 → 分发 → 人审意见 → 处置 → 申诉 → 仲裁 → 终局，每步带操作者/时间/所用标准版本——申诉仲裁时完整还原决策链。
- 申诉流程：创作者提交申诉（必填理由 + 可选补充材料）→ 仲裁队列（原审核员回避）→ 结果（维持/撤销 + 说明）；撤销的处置自动恢复内容并补偿信誉分。
- 仲裁工具：仲裁页同屏展示原审核意见/证据/申诉理由/标准条目，仲裁员按标准逐条比对；高频申诉原因自动聚类（标准模糊信号）。
- 时效 SLA：申诉 48h 内必须响应，超时自动升级；申诉量异常（某标准突增）反馈标准团队。
- 追问钩子：为什么仲裁员要回避原审核——避免「维护自己结论」的确认偏误；回避规则在派单层强制（同团队回避可配置）。

```javascript
const appealFlow = {
  submit: (videoId, reason, materials) =>
    api.post('/appeal', { videoId, reason, materials, priorChain: auditChain(videoId) }),
  arbitrate: async (appealId, arbitrator) => {
    if (arbitrator.id === appeal.originalAuditor) throw new Error('RECUSE');   // 回避
    return api.post(`/appeal/${appealId}/verdict`, {
      uphold: bool, evidence: arbitrateEvidence, standardRefs });
  },
  slaCheck: (appeal) => Date.now() - appeal.submitTs > 48 * 3600_000
    && escalate(appeal),
};
```
