## SCN-282：售后流程（申请→审核→寄回→退款）的状态编排怎么设计？

**答**:
- 售后状态机：申请中→商家审核→买家寄回→商家收货→退款中→完成/拒绝，每态对应界面动作（填写物流单号/查看退款进度），非法态操作禁用（状态机驱动 UI）。
- 进度可视化：步骤条时间线（每节点时间+说明）、拒绝原因显性呈现（附重新申请入口）、退款到账预估与实际到账通知（支付渠道退款时效声明——管理预期）。
- 凭证上传：退货凭证（照片/视频压缩上传，断点续传大视频）、物流单号填写（自动识别快递公司）、上传失败重试。
- 多售后单管理：同一订单多商品分别售后（售后单列表）、售后中禁止重复申请（幂等防护）、取消售后（可撤销态限定）。

```javascript
const AFTERSALE_FLOW = ['applied','approved','shipped',
  'received','refunding','done'];
const ACTIONS = { applied: ['cancel'],
  approved: ['fillLogistics'], received: [], refunding: [] };
function AfterSaleDetail({ as }) {
  const idx = AFTERSALE_FLOW.indexOf(as.status);
  return <>
    <Steps current={idx}>
      {AFTERSALE_FLOW.map(s => <Step key={s} title={LABELS[s]} />)}
    </Steps>
    {as.rejected && <RejectPanel reason={as.rejectReason}
      onReapply={reapply} />}
    {/* 状态机驱动操作区 */}
    {(ACTIONS[as.status] ?? []).includes('fillLogistics') &&
      <LogisticsForm onSubmit={fillLogistics} />}
  </>;
}
// 到账：退款中 → 支付渠道时效声明（1-7 天），
//   done → 通知"已到账 X 元"。
```

**追问**：

1. 状态机按下标推进度条，遇到「拒绝」这种分支态怎么显示？ → 拒绝不是线性下一态，要单独渲染终止分支，不能塞进 AFTERSALE_FLOW。
2. 用户填了物流单号但请求失败，界面已进入下一态怎么办？ → 以服务端返回状态为准回滚，本地只做乐观提示，失败要撤回步骤条。
3. 同一订单多商品售后，某个商品退款完成整单状态怎么算？ → 订单态由子售后单聚合，全部完成才置「已完成」，部分完成要显示「部分退款」。
