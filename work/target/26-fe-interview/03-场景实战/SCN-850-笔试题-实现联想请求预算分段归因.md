## SCN-850：手写延迟分段归因

**需求与边界**：
- 需求：input-to-suggest 全链路计时拆三段：keydown→fire（防抖段）、fire→response（网络段）、response→paint（渲染段）；P95 超预算上报最慢段。
- 边界：① 渲染段用 performance.now() 与 requestAnimationFrame 边界测（真实 paint 前的 JS 耗时）；② 缓存命中跳过网络段（标记 cached）；③ 分段数据进直方图聚合上报。

**答**：
```javascript
function latencyProfiler({ budget = 250 } = {}) {
  let t0, tFire, tResp;
  function markInput() { t0 = performance.now(); }
  function markFire() { tFire = performance.now(); }   // 防抖结束发请求
  async function markResponse(promise, { cached = false } = {}) {
    const res = await promise;
    tResp = performance.now();
    const paint = await new Promise(r => requestAnimationFrame(() =>
      requestAnimationFrame(r)));                      // 双 rAF 逼近 paint
    const segs = {
      debounce: tFire - t0,
      network: cached ? 0 : tResp - tFire,
      render: paint - tResp,
      cached,
    };
    const total = paint - t0;
    if (total > budget) report({ type: 'SUG_SLOW', total,
      slowest: Object.entries(segs).filter(([k]) => k !== 'cached')
        .sort((a, b) => b[1] - a[1])[0][0], segs });
    return segs;
  }
  return { markInput, markFire, markResponse };
}
```

**评分点**:
- 三段拆解边界清晰（markInput/markFire/markResponse）。
- 双 rAF 逼近真实 paint 时机。
- 缓存命中路径特殊处理（network=0 标记）。
- 超预算上报 slowest 段（直接可行动的归因）。
