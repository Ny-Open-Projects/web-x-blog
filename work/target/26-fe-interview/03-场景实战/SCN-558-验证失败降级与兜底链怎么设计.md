## SCN-558：验证组件失败降级与兜底链怎么设计？
**答**：
- 降级矩阵：滑块服务挂 → 退短信验证码 → 退邮箱验证 → 都不可用则限制高危操作放行低危操作（白名单场景矩阵）；每一级降级自动上报并告警。
- 超时定义：验证器加载超时（3s）/ 执行超时（60s）/ 服务端判定超时（5s）分别处理；加载失败自动尝试下一个验证器。
- 失败原因区分：用户答错（可重试）/ 系统故障（降级）/ 风控拒绝（终止 + 客服引导）三类走不同分支，绝不把「风控拒绝」降级放行。
- 状态恢复：降级链执行后恢复原流程上下文（回到用户正在做的支付步骤）。
- 追问钩子：降级放行的操作事后怎么补——记补验队列，服务恢复后批量补人审/复核。

```javascript
const FALLBACK_CHAIN = ['slider', 'sms', 'email'];
async function runVerify(scene, levels) {
  for (const v of levels.length ? levels : FALLBACK_CHAIN) {
    const impl = registry.get(v);
    if (!impl?.available()) continue;             // 组件不可用跳到下一级
    try {
      return await withTimeout(impl.run(scene), impl.timeout ?? 60_000);
    } catch (e) {
      if (e.code === 'RISK_REJECT') throw e;      // 风控拒绝：终止不降级
      report({ type: 'VERIFY_FALLBACK', from: v, err: e });   // 系统故障降级
    }
  }
  throw new Error('ALL_VERIFIERS_DOWN');          // 上层决定限流放行或阻断
}
```
