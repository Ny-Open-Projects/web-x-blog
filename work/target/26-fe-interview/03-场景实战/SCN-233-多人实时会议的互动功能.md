## SCN-233：会议互动功能（举手/表情/投票）怎么做到低延迟全员同步？

**答**:
- 通道设计：互动信令走轻量通道（WS 信令而非媒体通道——举手/表情是控制消息，几十字节毫秒级），与音视频数据通道分离；信令风暴控制（表情雨限频：每人 1 次/秒，服务端聚合广播）。
- 状态模型：举手队列（服务端排序，主持人可静音/下麦）、表情反应（瞬时展示+聚合计数，不进历史）、投票（状态机：发起→投票中→公布，票数实时聚合广播）。
- 同步语义：互动消息不保证全局有序（举手先后服务端定序，表情无需定序）、最终一致即可（短暂不一致 <200ms 无感知）；主持人控制信令优先级最高（静音/踢人立即生效）。
- 性能与降级：大会议（>500 人）表情聚合广播（只广播计数与抽样头像）、举手列表虚拟渲染、互动面板按需渲染（不开面板不订阅表情流）。

```javascript
ws.on('reaction', throttleSend((emoji) =>
  ws.send({ type: 'reaction', emoji }), 1000)); // 限频 1s
ws.on('reaction_bulk', ({ emoji, count, sample }) => {
  flyAnimation(emoji, sample);               // 大会聚合：计数+抽样头像
  counters[emoji] += count;
});
// 举手：服务端定序队列
ws.on('hands', ({ queue }) => renderHandQueue(queue));
// 投票：{type:'vote_state', poll: {phase, options, tallies}}
// 大会聚合：>500 人表情只广播 count + 抽样 5 头像。
```
