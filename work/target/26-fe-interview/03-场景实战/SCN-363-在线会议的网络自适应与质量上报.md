## SCN-363：会议弱网环境（音视频质量降级/自动重连）怎么设计？

**答**:
- 质量监测：RTC 统计（RTT/丢包率/抖动/码率——getStats 轮询），质量分模型（多维指标→质量等级），弱网识别（连续降级判定防抖动——单次抖动不切）。
- 降级链：视频降级顺序（分辨率降→帧率降→关视频保音频——音频优先级最高）、发送与接收独立降级（上行差降发送质量/下行差请求更低订阅）、 simulcast（多流发送——接收端按带宽选流）。
- 重连机制：ICE 重启（网络切换快速恢复）、完整重连（信令+媒体全重连，指数退避）、重连状态呈现（"连接中断，正在重连"——与会者知道原因而非神秘消失）、重连后状态恢复（麦克风/共享状态恢复）。
- 体验兜底：音频兜底策略（视频全断时保音频通话）、降级告知（"当前网络较差，已切换为音频优先"）、端内诊断（参会者可查自己的网络质量面板——自助排障）。

```javascript
// 质量监测与降级
setInterval(async () => {
  const s = await pc.getStats();
  const q = qualityScore(s);                 // rtt/loss/jitter
  if (q.degrading && stable(q)) {            // 防抖确认
    downgradeChain.next();                   // 分辨率→帧率→关视频
    notify('网络较差，已降低画质');
  }
}, 3000);
// 降级链：1080p→720p→360p→audioOnly（音频最后才关）
// 重连：pc.oniceconnectionstatechange → failed →
//   iceRestart() → fail → fullReconnect(backoff)。
// 恢复：麦克风/共享状态快照 → 重连后 restore。
```
