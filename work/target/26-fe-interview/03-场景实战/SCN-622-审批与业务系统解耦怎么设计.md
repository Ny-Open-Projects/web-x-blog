## SCN-622：审批系统与业务系统解耦怎么设计？
**答**：
- 解耦原则：审批引擎不认识业务语义（不知道「报销单」），业务系统提交「抽象审批单」(标题/金额/附件/回调地址)；结果通过回调/事件回流。
- 回调协议：事件类型（PASS/REJECT/CANCEL/节点变化）+ 幂等键（instanceId + eventId），业务端幂等处理（重复回调不重复入账）；前端对回调失败不重试风暴（业务侧确认）。
- 前端接续体验：审批通过回调里带业务跳转链接，通知卡片点击直达业务结果页；审批系统内嵌业务表单用 iframe/schema 渲染两种模式，优先 schema（安全可控）。
- 通用组件复用：待办列表/详情框架/时间线是审批域组件，业务表单是业务域组件，通过「表单渲染器 + 数据适配器」组合。
- 追问钩子：回调丢失怎么办——业务侧定期对账拉取终态（审批状态查询接口），补偿机制而非只靠回调。

```javascript
// 审批回调协议（业务侧接收）
app.post('/flow/callback', (req, res) => {
  const { eventType, instanceId, eventId, result, bizRef } = req.body;
  if (!idempotent.tryLock(eventId)) return res.ok();  // 幂等：重复回调直接 ack
  switch (eventType) {
    case 'PASS':   bizService.complete(bizRef, result); break;
    case 'REJECT': bizService.rollback(bizRef, result.opinion); break;
  }
  res.ok();                                          // 先 ack 再异步处理防超时
});
```
