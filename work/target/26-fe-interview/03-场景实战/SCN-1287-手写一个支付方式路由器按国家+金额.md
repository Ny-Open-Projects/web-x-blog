## SCN-1287：手写一个支付方式路由器（按国家+金额）

**答**：
- 需求：implement PayRouter(matrix)。options(country, amount) 返回可用支付方式（按国家矩阵+限额过滤），排序（默认方式优先/费率低的先）；sca(country, method) 判断 3DS 要求；输出列表含 sca 标记。
- 边界：matrix 无该国家回退 card；amount 超 method 限额过滤；排序稳定（同费率按名称）。
- 评分点：国家矩阵；限额过滤；SCA 标记；稳定排序

```javascript
class PayRouter {
  constructor(matrix, limits) { this.matrix = matrix; this.limits = limits; }
  options(country, amount) {
    const list = this.matrix[country] ?? ['card'];
    return list.filter(m => {
      const limit = this.limits[m];
      return !limit || amount <= limit;
    }).map(m => ({ method: m,
      sca: EU_SCA.has(country) && m === 'card' ? '3DS' : null,
      default: m === list[0] }))
      .sort((a, b) => (b.default ? 1 : 0) - (a.default ? 1 : 0) ||
        a.method.localeCompare(b.method));
  }
}
const EU_SCA = new Set(['DE', 'FR', 'NL']);
const matrix = { DE: ['paypal', 'card', 'klarna'], JP: ['card', 'konbini'] };
const limits = { card: 50_000 };
```

## 追问（补充）

**追问**：

1. 限额比较为什么容易在边界上出错？ → `amount <= limit` 与 `< limit` 差一个金额，但各家通道口径不同（含上限/不含上限），应把限额建模成 `{max, inclusive}` 而不是裸数字，否则「刚好 50000 刷不过」这类投诉会反复出现。
2. 多币种怎么比限额？ → 先按结算币种换算再比，且金额用最小货币单位的整数（分）存储；直接用浮点比会因 0.1+0.2 这类精度问题误判，换汇还需固定汇率快照，否则前后端判级不一致。
3. 排序为什么不能直接按费率写死？ → 费率是商务配置、随时会变，且 A/B 实验要换策略。应注入 `rank(method, ctx)` 并保留次级排序键（同费率按名称），保证结果稳定可复现。
4. 如果 matrix 里配了服务端不认识的 method？ → 启动时做白名单自查并告警；运行时静默过滤的后果是「某国家少了一个支付方式」，这种故障没人报障，只能靠监控发现。
