## SCN-629：审批超时自动升级怎么设计？
**答**：
- 升级链定义：节点配置 escalatePolicy（超时 N 小时 → 升级到上级；再超时 → 跳过该节点直送下节点 或 终止），策略由流程定义声明、服务端执行。
- 可视化：流程图上节点显示升级标记（如「超 24h 升级至总监」）；实际发生升级时时间线插入系统事件，节点状态标「已升级」。
- 升级通知：被升级人收到「因 X 未及时处理，该单升级至你」的说明性通知（含原处理人），减少误会；原处理人收到超时通知与积压统计。
- 降级出口：升级不无限循环——超过最大升级层数走兜底（终止/人工介入池），前端展示兜底原因。
- 追问钩子：升级到上级后原审批人补处理了怎么办——先到先得（幂等），时间线记录双方操作与升级事件，不做二次冲突处理。

```javascript
const ESCALATE_POLICY = {
  hours: 24, action: 'escalate', to: 'parent_role',     // 超时升级
  maxLevel: 3,                                           // 最多升 3 层
  fallback: 'manual_pool',                               // 兜底：人工介入池
};
function escalateNode(node, instance) {
  let level = 0;
  return {
    next: () => {
      if (++level > ESCALATE_POLICY.maxLevel)
        return manualPool(instance);                     // 兜底
      const approver = resolveRole(node.assignee, { level });
      timeline.push({ type: 'ESCALATE', level, approver, from: node.id });
      notify(approver, `因上级未及时处理升级至你`);
      return approver;
    },
  };
}
```
