## SCN-398：超级 App（多业务容器）的插件化架构怎么设计？

**答**:
- 容器与插件分层：容器（壳：登录/支付/IM/地图/推送/埋点——SCN 底座五件套复用）+ 插件（业务模块：商城/出行/外卖动态化）——容器提供能力 API，插件声明依赖。
- 插件协议：插件生命周期（load/mount/unmount——资源守卫 AGT-499 复用）、能力接口（容器 API：导航/支付/用户——插件只依赖接口不依赖实现）、路由注册（插件路由注入主路由表）、版本与兼容（插件版本与容器 API 版本协商——向下兼容窗口）。
- 动态化：插件动态下发（bundle 动态加载：业务不发版更新——包体管控：按需下载+缓存版本管理），灰度与回滚（插件级灰度——SCN-322 复用、插件回滚独立）。
- 治理：插件准入（SDK 规范/性能预算/包体限制——SCN-247 组件治理复用）、容器稳定性（插件崩溃隔离——插件沙箱：崩溃不影响容器与其他插件）、跨插件通信（事件总线+实体引用——SCN-300 协议复用）。

```javascript
// 插件协议
container.register({
  id: 'mall', version: '3.2.0',
  requires: { containerApi: '>=2.0' },
  routes: mallRoutes,
  onMount(ctx) { ... },          // ctx: 容器能力注入
  onUnmount() { guard.endTask(this.id); },  // 资源回收
});
// 动态：bundleLoader.load('mall', { version, gray })
//   （按需下载+缓存版本管理）
// 崩溃隔离：sandbox.run(plugin) → crash →
//   unload(plugin) + 容器存活 + 告警。
// 通信：bus + entityRef（SCN-300）。
```
