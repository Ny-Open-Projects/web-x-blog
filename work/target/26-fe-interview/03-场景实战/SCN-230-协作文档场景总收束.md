## SCN-230：协作文档场景的前端工程怎么总收束？

**答**:
- 全景六域：同步架构（221 OT/CRDT 选型+222 增量快照）、协作呈现（223 多光标/224 冲突提示/228 批注/229 表格）、权限体系（225 分级+通道授权）、版本体系（226 回滚=反向补丁）、离线能力（227 本地优先）、性能工程（增量同步/视口加载/awareness 节流）——协作的核心命题是"正确的并发语义+无感的实时体验"。
- 基础设施分层：数据层（Y.Doc 本地+服务端事实源）、传输层（WS 内容通道+awareness 状态通道分离）、呈现层（编辑器/光标层/批注层分离）、权限层（连接即授权）——分层清晰才可维护。
- 体验铁律：本地操作零延迟（乐观渲染，CRDT 本地即时）、他人操作平滑可见（节流+插值）、异常可恢复（离线不丢/合并自动/冲突精准提示）——协作产品的信任来自"我的编辑永远不会丢"。
- 收束心法：协作文档工程 = 并发算法（CRDT）× 编辑器工程（富文本/表格）× 实时系统（WS/awareness）的交叉领域，复用成熟生态（Yjs）比自己发明协议更专业。

```text
协作文档全景：
同步：CRDT（Yjs）+ 增量 + 快照恢复
呈现：相对锚光标 / 冲突语义提示 /
  批注锚跟随 / 表格单元格 CRDT
权限：连接即授权 + 能力对象驱动 UI
版本：回滚=反向补丁进流水
离线：本地优先 IndexedDB + 自动合并
铁律：本地零延迟 / 他人平滑可见 /
  编辑永不丢。
```
