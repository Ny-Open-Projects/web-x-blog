## OPS-254：功能分片渐进怎么做的？
**答**：
- 分片维度：大功能不按「全有全无」发布——按子能力拆片（新结算页的「新UI」「新计算引擎」「新支付通道」各自独立开关），按风险递增顺序开启。
- 分片依赖：片间依赖显式（支付通道依赖计算引擎），依赖未开启的片置灰——分片不是随意组合。
- 分片灰度：每片独立灰度节奏（低风险片快速全量，高风险片慢），全功能就绪 = 所有片完成。
- 收敛纪律：分片功能全部就绪后必须清理分片 flag（SCN-OPS-224 代码化）——分片是发布手段不是永久状态。
- 追问钩子：为什么大功能要「按风险递增开启分片」而不是按开发完成度——先开低风险片（如新 UI）积累真实环境信心，再开高风险片（支付通道）；若按开发完成度随机开，可能第一天就暴露最高风险片——分片顺序本身就是风险控制策略。

```javascript
const featureSlices = {
  slices: [
    { id: 'new-ui', risk: 'low', depends: [] },
    { id: 'calc-engine', risk: 'mid', depends: ['new-ui'] },
    { id: 'pay-channel', risk: 'high', depends: ['calc-engine'] },
  ],
  order: 'risk-ascending',                             // 风险递增开启
  gray: 'per-slice',                                   // 每片独立灰度
  cleanup: 'all-ready-then-codify (OPS-224)',
};
```
