## BLD-238：构建配置测试怎么做？
**答**：
- 测什么：产物结构快照（入口/清单/schema）、特定行为的断言（该摇的摇掉了/该拆的拆了）、错误路径（错误配置产生可读错误）——构建配置是代码，代码就要测试。
- 怎么测：fixture 工程（最小项目矩阵）+ 构建执行 + 产物断言——preset 的每个特性一个 fixture（SCN-ENG-245 同源）。
- 回归价值：升级构建工具版本时，fixture 矩阵跑一遍即知兼容性（SCN-BLD-244 迁移验证的基础设施）。
- 成本控制：fixture 按需触发（改动 preset 才跑相关 fixture——affected 思想下沉到测试）。
- 追问钩子：为什么「产物结构快照」比「构建成功与否」更有价值——构建成功不代表产物正确（splitting 失效/摇树丢失都构建成功）；快照断言 chunk 数量/模块归属/导出面，让「产物语义」回归可见——构建配置的测试对象是产物语义而非过程。

```javascript
// fixture 测试
for (const fixture of ['basic', 'splitting', 'tree-shake', 'worker']) {
  const out = await build(fixtureProject(fixture));
  expect(out.chunks).toMatchSnapshot(`chunks-${fixture}`);        // 结构快照
  if (fixture === 'tree-shake')
    expect(out.modules).not.toContain('unused-module');          // 行为断言
}
```
