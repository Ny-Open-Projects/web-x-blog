## OPS-288：发布系统压测怎么做的？
**答**：
- 发布风暴场景：多团队同时发布（季度末/大促前发布高峰）——编排器/审批流/flag 服务/哨兵的并发承载。
- 压测项：并发发布数上限、审批流吞吐（审批通知风暴）、flag 配置下发并发、哨兵指标写入吞吐、事件溯源存储写入速率。
- 资源隔离验证：一个团队的发布风暴不影响其他团队（SCN-OPS-214 多租户隔离的实测）。
- 降级预案：超载时的排队与限流（发布 API 429）、关键路径优先（回滚/熔断动作不受排队影响——应急通道永不排队）。
- 追问钩子：为什么「应急通道永不排队」是压测必须验证的底线——发布风暴时若回滚请求也在排队，等于故障时刻安全带失灵；压测专门验证「熔断/回滚 API 在系统满载时的响应时间」——应急通道的资源优先级是发布系统设计的第一约束。

```javascript
const stormTest = {
  scenario: '50 并发发布 + 审批风暴 + flag 下发峰值',
  asserts: {
    concurrent: maxConcurrentReleases(),
    approvalThroughput: true,
    emergencyLane: { rollbackP95UnderLoad: '< 5s', note: '应急通道永不排队' },
    tenantIsolation: 'teamA-storm not affect teamB',
  },
  degrade: { overload: '429 + queue', emergencyBypass: 'always' },
};
```
