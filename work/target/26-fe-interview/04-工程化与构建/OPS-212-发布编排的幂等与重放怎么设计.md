## OPS-212：编排器幂等与重放怎么设计？
**答**：
- 状态外置：编排器每步执行前持久化状态（step 状态 + plan 版本 + 执行上下文），崩溃恢复时从台账继续（幂等步骤可重放）。
- 步骤幂等键：每个部署步骤带幂等键（planId+stepId），重复执行服务端去重——重放不会重复发布。
- 危险步骤的确认语义：回滚等不可幂等操作标记为「需人工确认重放」（重放前人工核对状态）。
- 台账与实际对账：恢复时先对账（台账说 DONE 的步骤实际产物是否就位），不一致以实际为准修正台账。
- 追问钩子：为什么恢复时要「对账」而不是直接信台账——编排器崩溃可能发生在「步骤已执行但状态未写」的窗口；直接信台账会跳过已执行的步骤或重复执行未完成的，对账（查询产物实际状态）是唯一可靠的事实来源。

```javascript
async function resumeOrchestration(planId) {
  const state = await loadState(planId);             // 台账
  for (const step of plan.steps) {
    const actual = await checkArtifact(step);        // 对账：实际产物状态
    if (actual.done && state[step.id] !== 'DONE')
      state[step.id] = 'DONE';                       // 台账修正
    if (!actual.done && state[step.id] === 'DONE')
      state[step.id] = 'STALE';                      // 台账虚报
    if (state[step.id] !== 'DONE') await execStep(step, { idempotent: true });   // 幂等重放
  }
}
```
