## OPS-259：自愈发布怎么做的？
**答**：
- 自愈范围：已知、可确定性判定的故障模式自动处置——chunk 404 → 自动版本对齐刷新（SCN-OPS-218）；SRM 检测异常 → 自动暂停放量；CDN 命中率骤降 → 自动预热重推。
- 自愈边界：自动处置只做「可逆、低风险、模式明确」的动作；需要判断的（回滚决策）仍走人工+决策树（SCN-OPS-234）——自愈是执行自动化，不是决策自动化。
- 自愈记录：每次自愈动作记录（触发模式/执行动作/结果），自愈频率异常告警（自愈频繁=系统性问题）。
- 预案转化：预案卡片（SCN-OPS-217）中「确定性处置」逐步转化为自动自愈——人工预案的自动化演进。
- 追问钩子：为什么自愈要严格限定「可逆低风险」动作——自愈的失败模式是「自动做了错误的事」：把有判断价值的回滚也自动化，一次误判回滚的损失可能远超人工响应延迟；自愈先做「明确收益、有限损失」的，是渐进式自动化的安全边界。

```javascript
const selfHealing = {
  rules: [
    { pattern: 'chunk-404', action: 'version-align-refresh' },        // OPS-218
    { pattern: 'srm-skew', action: 'pause-ramp' },                    // OPS-203
    { pattern: 'cdn-hit-drop', action: 're-push-assets' },            // OPS-209
  ],
  boundary: 'reversible + low-risk + deterministic only',            // 回滚仍走人工决策树
  audit: logHealingActions(),
  alert: healRateHigh() && flagSystematicIssue(),
};
```
