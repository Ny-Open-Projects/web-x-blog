## OPS-257：人工验收怎么工程化？
**答**：
- 验收清单生成：从变更 diff 自动生成验收清单（改了什么就验什么——变更影响面映射到验收项，SCN-ENG-203 联动）——通读式验收必然漏。
- 验收环境真实化：验收在灰度环境用灰度账号（真实数据形态）——测试环境验收覆盖不了数据边界。
- 验收结果结构化：每项验收记录（通过/失败/截图），失败项自动阻断放量——验收结果是放量门禁的输入而非参考。
- 验收时效：灰度观察期内完成（验收慢于放量节奏时先降档）——验收速度跟不上时宁可慢放。
- 追问钩子：为什么验收清单要「从 diff 自动生成」——人工写的通用清单（登录/下单/支付）每次都一样，对本次变更的特有风险没有针对性；diff 驱动的清单确保「改了什么验什么」，把验收从仪式变成靶向检查。

```javascript
function acceptanceChecklist(diff) {
  const impacted = affectedPages(diff);                // 变更影响面 → 页面
  return impacted.flatMap(page => ({
    page, items: [
      ...page.coreJourneys,                            // 页面固有旅程
      ...diffSpecificChecks(diff, page),               // 本次变更特有项
    ],
  }));
}
// 结构化结果 → 放量门禁
acceptance.result.filter(r => !r.pass).length && blockRamp();
```
