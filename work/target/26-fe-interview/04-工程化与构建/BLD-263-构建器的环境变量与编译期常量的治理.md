## BLD-263：编译期常量治理怎么做？
**答**：
- 治理目标：常量清单显式化（哪些 Define/哪些 env 进产物）、类型安全（TS 类型声明对应）、字面量约束（SCN-BLD-229 DCE 协作）、值来源可审计（哪个 env 注入了什么——SCN-ENG-229 凭据红线）。
- 清单治理：常量注册表（name/type/来源/用途/是否进产物）——buildinfo 关联（SCN-ENG-309），产物内常量与注册表 diff（未注册的常量进产物 = 漏洞）。
- 类型集成：env 类型自动生成（schema → ts 类型——process.env.XXX 有类型）。
- 泄露防线：常量注册表标记 secret 类（进产物前扫描阻断）。
- 追问钩子：为什么「产物内常量与注册表 diff」能防泄露——开发者随手 Define 一个含 token 的常量不会登记注册表；构建后扫描产物中的常量与注册表比对，出现未注册值即告警——把「凭据不进产物」从纪律变成机器校验（SCN-ENG-229 的工程化落地）。

```javascript
// 常量注册表
{ __API_HOST__: { type: 'string', source: 'env:API_HOST', secret: false },
  __BUILD__: { type: 'object', source: 'generated' } }
// 产物扫描比对
const inBundle = extractDefines(bundle);
const unregistered = inBundle.filter(c => !registry[c.name]);
if (unregistered.length || registry.filter(r => r.secret && inBundle.has(r.name)).length)
  fail('产物含未注册/敏感常量');
```
