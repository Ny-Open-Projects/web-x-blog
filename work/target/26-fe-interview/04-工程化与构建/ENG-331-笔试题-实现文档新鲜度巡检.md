## ENG-331：手写文档新鲜度巡检

**需求与边界**：
- 需求：巡检文档目录——① 最后验证时间超期（>180 天）标记 stale；② 文档引用的代码符号不存在（文档里的示例 API 已删除）= 内容性过期；③ 输出巡检报告（stale 清单/失效引用/建议归档清单——长期无人看的文档）。
- 边界：① 验证时间从 frontmatter 或 git last-commit 取（标记优先）；② 符号校验只查显式代码块（import 路径存在性 + 导出存在性）；③ 归档建议基于访问统计而非仅时间。

**答**：
```javascript
async function docFreshness(docs, { staleDays = 180 } = {}) {
  const stale = [], brokenRefs = [], archiveCandidates = [];
  for (const doc of docs) {
    const verifiedAt = doc.frontmatter?.verifiedAt ?? gitLastCommit(doc.path);
    const age = daysSince(verifiedAt);
    if (age > staleDays && doc.accessCount < 5)          // 过期且没人看 → 归档
      archiveCandidates.push({ path: doc.path, age, accessCount: doc.accessCount });
    else if (age > staleDays) stale.push({ path: doc.path, age,
      fix: `复审并更新 verifiedAt（近 90 天被查看 ${doc.accessCount} 次，值得维护）` });
    for (const code of doc.codeBlocks ?? []) {
      const mod = resolveModule(code.importPath);
      if (!mod) { brokenRefs.push({ path: doc.path, import: code.importPath,
        fix: '模块已删除/改名，更新示例或归档文档' }); continue; }
      for (const sym of code.usedExports ?? [])
        if (!exportsOf(mod).has(sym))
          brokenRefs.push({ path: doc.path, symbol: sym, fix: `导出 ${sym} 已不存在` });   // 内容性过期
    }
  }
  return { stale, brokenRefs, archiveCandidates };       // 三类输出：复审/修复/归档
}
```

**评分点**:
- 三态输出（stale 复审/失效引用修复/归档候选——ENG-220 保鲜机制）。
- 内容性过期（符号不存在）比时间性过期更准（文档里 API 已删才算真过期）。
- 归档建议结合访问统计（时间+流量双信号，ENG-284 防误杀）。
- 每项带 fix（可行动）。
