## OPS-313：手写规模适配

**需求与边界**：
- 需求：按团队规模/事故历史推荐发布体系组件（SCN-OPS-287）；检测「流程税」（发布前置时间 / 开发时间 > 2 = 过度工程信号）；输出「简化建议」（哪些环节可自动化或删除）。
- 边界：① 流程税分位计算（P50 与 P90 分别算——均值掩盖长尾）；② 简化建议区分「自动化」与「删除」（删审批 ≠ 自动审批）；③ 事故驱动的加码优先于规模推荐（出过事先补短板）。

**答**：
```javascript
function releaseFit(teams, metrics, incidents) {
  const { teamSize, pipelineLeadP50, devTimeP50 } = metrics;
  const flowTax = pipelineLeadP50 / devTimeP50;
  const recommendations = [];
  // 事故驱动加码优先
  if (incidents.some(i => i.category === 'no-gray'))
    recommendations.push({ add: 'gray-rollout', why: '曾因无灰度出事故' });
  if (incidents.some(i => i.category === 'approval-missing'))
    recommendations.push({ add: 'risk-leveling', why: '审批缺失事故' });
  // 规模基线
  if (teamSize < 10 && hasHeavyApproval(metrics))
    recommendations.push({ simplify: 'cut-approval-to-auto', why: '小团队重审批 = 流程税' });
  // 流程税检测（分位）
  const taxP90 = metrics.pipelineLeadP90 / metrics.devTimeP90;
  if (flowTax > 2 || taxP90 > 3)
    recommendations.push({ simplify: pipelineLeadP50 > devTimeP50 * 2
      ? 'automate-approval / remove-redundant-gates' : null,
      why: `流程税 ${flowTax.toFixed(1)}×（P90 ${taxP90.toFixed(1)}×）` });
  return { flowTax, taxP90, recommendations };
}
```

**评分点**:
- 事故驱动加码优先于规模推荐（痛点先于理论——SCN-OPS-287）。
- 流程税分位计算（P50/P90——均值掩盖长尾）。
- 简化区分自动化与删除（审批自动化 ≠ 删审批）。
- 输出带 why（建议可解释）。
