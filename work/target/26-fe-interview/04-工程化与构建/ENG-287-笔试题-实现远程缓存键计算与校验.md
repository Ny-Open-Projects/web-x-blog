## ENG-287：手写构建缓存键计算

**需求与边界**：
- 需求：缓存键 = hash(任务声明输入)：源文件集 + 外部依赖版本 + 声明的 env + 任务定义版本；命中校验：键一致且产物清单 hash 匹配。
- 边界：① env 只取「声明的变量」（未声明的 env 变化不影响键——但必须声明完整）；② 文件集排序后 hash（顺序无关）；③ 产物校验：逐文件 sha256 与 manifest 对比，缺失即 miss。

**答**：
```javascript
import { createHash } from 'crypto';
function cacheKey(task, { files, deps, env, taskDef }) {
  const h = createHash('sha256');
  h.update('taskdef:v' + taskDef.version);                     // 任务定义版本
  h.update(files.map(f => `${f.path}:${f.hash}`).sort().join('\n'));  // 排序稳定
  h.update(Object.entries(deps).sort().map(([n, v]) => `${n}@${v}`).join('\n'));
  for (const name of task.envDeclared.sort())                  // 只取声明 env
    h.update(`${name}=${process.env[name] ?? ''}`);
  return h.digest('hex');
}
function verifyHit(key, manifest, artifactDir) {
  const cached = remoteCache.get(key);
  if (!cached) return { hit: false };
  for (const [file, expected] of Object.entries(cached.manifest)) {
    const actual = sha256File(path.join(artifactDir, file));
    if (actual !== expected) return { hit: false, reason: 'CORRUPT', file };   // 产物损坏
  }
  return { hit: true, manifest: cached.manifest };
}
```

**评分点**:
- 键输入四要素完整（任务定义版本是漏报主因）。
- env 只取声明集（未声明变化不影响命中）+ 排序稳定 hash。
- 命中后产物逐文件校验（脏缓存/损坏防护）。
- CORRUPT 带文件定位（缓存治理可行动）。

## 变体与延伸（补充）

**变体与延伸**：

1. 缓存键该包含哪些输入？ → 源码与依赖内容哈希、工具链版本、构建参数，外加影响产物的环境变量白名单，缺一项都会出现错误命中。
2. 环境变量怎么处理才不漏？ → 白名单显式纳入参与 hash，未列入的不参与，但要在构建期断言代码没有读取未登记变量。
3. 命中率突然下降怎么查？ → 打印 key 的组成逐项 diff，先排除无关的工具版本升级，再看 lockfile 是否被间接依赖带动。
