## BLD-266：增量正确性怎么验证？
**答**：
- 核心不变式：增量构建产物 ≡ 全量构建产物——验证方法：增量序列（改文件 A→B→C）后与同终态全量构建 diff。
- 自动化验证：CI 增量一致性测试（随机变更序列 + 全量对照）——增量算法的回归测试（SCN-ENG-266 失效图完整性的实证）。
- 常见破坏点：失效传播漏边（动态依赖/插件产物依赖）、缓存键漏因素、模块 ID 不稳定——每类对应一个测试用例。
- 追问钩子：为什么增量验证要「随机变更序列」而不是固定用例——固定用例只覆盖已知失效边（写测试时想到的）；随机序列能撞出「未预期的失效传播路径」（如插件缓存与模块失效的交互）——property-based 思想在构建正确性上的应用（SCN-BLD-254 同源）。

```javascript
// 增量一致性随机测试
for (let i = 0; i < 20; i++) {
  const seq = randomChangeSequence();                  // 随机变更序列
  const incremental = await buildIncremental(seq);
  const full = await buildFull(finalState(seq));
  expect(hash(incremental)).toBe(hash(full));          // 不变式：增量 ≡ 全量
}
// 已知破坏点的定向用例
await changeFile('a.ts'); await changePluginOutput(); // 插件产物依赖失效
```
