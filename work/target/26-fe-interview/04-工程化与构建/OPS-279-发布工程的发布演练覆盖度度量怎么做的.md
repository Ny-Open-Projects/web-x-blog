## OPS-279：演练覆盖度怎么度量？
**答**：
- 覆盖度三层：场景覆盖（故障模式清单被演练的比例）/流程覆盖（runbook 步骤被演练触达的比例）/角色覆盖（各值班角色参与演练的比例）——三层合成演练健康分。
- 覆盖度腐化检测：新增故障模式/新 runbook 步骤/新值班成员都会让覆盖度下降——覆盖度按月计算（滚动），下降即告警。
- 与真实事故对齐：真实事故中「演练覆盖过的模式处置更顺利」（时间线对比）——覆盖度的价值验证。
- 演练优先级：覆盖度缺口 × 场景风险 = 演练排期依据（ENG-327 利息模型同构）。
- 追问钩子：为什么覆盖度要「按月滚动计算」——覆盖度是衰减量：新故障模式加入、runbook 更新、值班换人都在稀释覆盖；固定时点的覆盖度（如年度评估）会高估实际健康度，滚动计算让「腐化」及时可见——这是所有「健康度」指标的通用设计。

```javascript
function drillCoverage(months = 1) {
  const modes = failureModes();                        // 全部故障模式
  const drilled = modes.filter(m => drilledIn(m, months));
  const runbookSteps = allRunbookSteps();
  const touched = runbookSteps.filter(s => exercisedIn(s, months));
  const roles = oncallRoles().filter(r => participatedIn(r, months));
  return {
    scenario: drilled.length / modes.length,
    process: touched.length / runbookSteps.length,
    role: roles.length / oncallRoles().length,
    debt: modes.filter(m => !drilledIn(m, months)),    // 演练债务（排期依据）
    decay: 'rolling-monthly',                          // 按月滚动防高估
  };
}
```
