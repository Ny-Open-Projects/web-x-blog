## BLD-315：手写预算反推

**需求与边界**：
- 需求：从性能目标反推 JS 预算（SCN-BLD-265）——① 输入 TTI 目标/网络条件分布（RUM）/设备解析速度分布；② 输出预算矩阵（网络 × 设备的组合——各分位）；③ 最严格预算取「p75 网络 × p75 设备」（覆盖大多数用户）；④ 输出与现状的差距（优化空间量化）。
- 边界：① 网络耗时模型（RTT × 请求数 + 传输时间——依赖请求数）；② 解析时间与体积线性近似（移动端 ~1MB/s）；③ 预算分配（入口 JS vs 异步 chunk——首屏只算同步）。

**答**：
```javascript
function budgetCalc({ ttiTarget = 2500, rumNetwork, rumDevice, requestCount = 6 }) {
  // 网络分位（p75：RTT 与带宽）
  const net = quantile(rumNetwork.map(n => n.rtt), 0.75);
  const bandwidth = quantile(rumNetwork.map(n => n.downKbps), 0.75);
  const deviceSpeed = quantile(rumDevice.map(d => d.jsParseKbPerSec), 0.75);   // 设备解析分位
  // 预算 = TTI − 网络 − 解析
  const networkMs = requestCount * net + t => t;       // RTT × 请求数 + 传输（函数）
  const budgetFor = (jsKb) => networkMs(jsKb, bandwidth) + (jsKb / deviceSpeed) * 1000;
  // 二分求解：budgetFor(budgetKb) === ttiTarget
  const budgetKb = solveBinary(budgetFor, ttiTarget, { lo: 50, hi: 2000 });
  return {
    budgetKb: Math.round(budgetKb),
    assumptions: { net: `${net}ms rtt / ${bandwidth}kbps`, device: `${deviceSpeed}kb/s 解析`, requests: requestCount },
    current: currentEntryGzip(), gap: currentEntryGzip() - budgetKb,
    note: currentEntryGzip() > budgetKb
      ? `超预算 ${currentEntryGzip() - budgetKb}KB——分割/摇树优化空间（SCN-BLD-220 来源清单）`
      : '在预算内',
  };
}
```

**评分点**:
- 双分布分位（网络 p75 × 设备 p75——覆盖大多数用户）。
- 耗时模型（RTT×请求数 + 传输 + 解析）与二分求解。
- 假设条件显式输出（预算可解释可审计）。
- 与现状 gap 量化（优化空间——SCN-BLD-265 反推意义）。
