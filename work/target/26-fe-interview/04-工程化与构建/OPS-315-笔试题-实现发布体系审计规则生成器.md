## OPS-315：手写审计规则生成

**需求与边界**：
- 需求：事故复盘产出自动转化为审计规则——① 事故根因分类映射审计项（如「无灰度发布」→ 检查 bypass 记录完整性）；② 规则去重（同类事故不重复生成）；③ 规则有效性回看（该审计项是否再拦截过同类问题——没拦截过考虑移除，SCN-OPS-289）。
- 边界：① 根因分类到审计项的映射表可扩展；② 规则带 owner 与生效日期；③ 有效性回看阈值（12 个月零拦截 → 降级为抽查项）。

**答**：
```javascript
const ROOT_CAUSE_MAP = {
  'no-gray': { audit: 'bypass-completeness', check: '每笔发布检查灰度豁免记录' },
  'approval-missing': { audit: 'approval-chain', check: '审批链与风险级别匹配' },
  'artifact-tamper': { audit: 'signature-chain', check: '产物签名与 CDN hash 一致' },
};
function auditRulesFromIncidents(incidents, existingRules) {
  const added = [];
  for (const inc of incidents) {
    const mapping = ROOT_CAUSE_MAP[inc.rootCause];
    if (!mapping) continue;
    if (existingRules.some(r => r.audit === mapping.audit)) continue;   // 去重
    added.push({ ...mapping, owner: inc.owner, since: Date.now(),
      source: inc.id });                               // 事故溯源
  }
  // 有效性回看
  const stale = existingRules.filter(r =>
    monthsSince(r.since) > 12 && r.catches === 0)      // 12 个月零拦截
    .map(r => ({ rule: r.audit, action: '降级为抽查项' }));
  return { added, stale };
}
```

**评分点**:
- 根因 → 审计项映射表（可扩展——SCN-OPS-289 事故来源）。
- 规则去重（同类事故不重复生成）。
- 12 个月零拦截降级抽查（审计规则自身的有效性治理）。
- 规则带 owner 与事故溯源（责任与依据）。
