## OPS-289：发布体系审计怎么做的？
**答**：
- 审计问题集：合规审查的固定问题——每个线上版本能追溯到发布记录吗（SCN-OPS-220）/审批链完整吗/灰度有绕过吗（bypass 记录）/产物签名链完整吗/事故处置留痕吗——审计是拿这些问题跑数据而不是访谈。
- 审计自动化：定期跑审计脚本（留痕完整性/审批链校验/绕过统计），输出合规报告——人工审计是抽样，自动审计是全量。
- 审计发现闭环：审计发现的制度漏洞（绕过通道无审批）进流程修订——审计的价值在改进不在报告。
- 审计与事故联动：每次事故的审计复盘（该环节留痕缺失吗/审批走没走）——事故是审计规则的最佳来源。
- 追问钩子：为什么审计要「跑数据」而不是「访谈」——访谈得到的是「应该怎么做」（制度文本），数据得到的是「实际怎么做」（真实行为）；合规的实质是行为合规——留痕完整性、审批实际执行率这些只能从数据验证，访谈会被准备过的答案污染。

```javascript
async function releaseAudit() {
  const report = {
    traceability: allReleases().every(r => r.log.complete),          // 留痕完整性
    approvalChains: allReleases().map(r => validateChain(r)),        // 审批链
    bypasses: grayBypasses({ withWaiver: true }),                    // 绕过统计（豁免合规）
    signatureChain: verifyAllSignatures(),
  };
  findingsToFlowFix(report.gaps);                                    // 发现 → 流程修订
  scheduleAudit({ cron: 'monthly', fromIncidents: true });           // 事故 → 审计规则
}
```
