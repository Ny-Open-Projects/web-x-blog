## BLD-277：模块归因怎么回答？
**答**：
- 归因链构建：从产物模块回溯引用链（SCN-BLD-249 反向查询）——模块 X 在产物里因为 A→B→X 的 import 链。
- 归因类型分类：直接引用（业务代码 import）/依赖传递（依赖的依赖）/入口副作用（被 side-effect import 拉入）/动态引用（context module 打包）/摇树失败（SCN-BLD-276）——每类对应不同修复路径。
- 归因工具的接口设计：`why(modulePath)` 返回多条引用链（最短优先）+ 每条链的类型标注。
- 追问钩子：为什么归因要区分「引用类型」而不是只给链路——「lodash 在产物里」的修复动作取决于类型：直接引用→改 import 方式；传递→改中间依赖（可选依赖/替换）；副作用→修 sideEffects 声明；动态→缩 glob 范围——链路只是「在哪」，类型才是「怎么办」。

```javascript
// 归因接口
graph.why('lodash/lodash.js');
// → [{ chain: ['app.ts', 'dashboard.ts', 'lodash'], type: 'direct' },
//    { chain: ['app.ts', 'legacy.ts', 'lodash'], type: 'side-effect' }]
// 每类归因的修复映射
const FIX = { direct: '按需 import', transitive: '替换中间依赖',
  'side-effect': 'sideEffects 声明', dynamic: '缩 glob 范围' };
```
