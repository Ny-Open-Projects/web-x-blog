## BLD-324：手写关键路径

**需求与边界**：
- 需求：任务依赖图的关键路径（SCN-BLD-272）——① 最长链计算（图 DP：每任务最早开始时间 = max(前置完成)）；② 总时长下限 = 关键路径长度（并行再多也压不掉）；③ 优化建议（关键路径上的任务可拆分/缓存命中剪枝——对总时长影响最大）。
- 边界：① 缓存命中的任务时长按 0 计（剪枝后再算关键路径——命中后路径变短）；② 任务耗时数据来源（遥测历史 P50）；③ 环检测前置。

**答**：
```javascript
function criticalPath(tasks, { cacheHits } = {}) {
  assertNoCycle(tasks);                                // 环前置
  const dur = (t) => cacheHits?.has(t.id) ? 0 : t.etaP50 ?? t.eta;   // 缓存命中零成本
  const earliest = {};                                 // 图 DP：最早开始
  const topo = topologicalOrder(tasks);
  let total = 0, endTask = null;
  for (const t of topo) {
    const start = Math.max(0, ...(t.depends ?? []).map(d => earliest[d].end));
    earliest[t.id] = { start, end: start + dur(t) };
    if (earliest[t.id].end > total) { total = earliest[t.id].end; endTask = t.id; }
  }
  // 回溯关键路径
  const path = [];
  let cur = endTask;
  while (cur) { path.unshift(cur); cur = predecessorOnCritical(cur, earliest); }
  const parallelGain = sum(allEta) - total;            // 并行化收益（vs 串行）
  return {
    total, path,                                       // 总时长下限 + 关键链
    optimize: path.filter(t => !cacheHits?.has(t))
      .map(t => `${t}（缓存命中可减 ${dur(tasks.find(x => x.id === t))}s）`),   // 优化建议
    parallelGain,
  };
}
```

**评分点**:
- 图 DP 最早开始/最早结束（关键路径标准算法）。
- 缓存命中剪枝（命中零成本后路径重算——SCN-BLD-272）。
- 关键路径回溯（输出链——优化目标明确）。
- 并行化收益量化（串行 vs 并行差值）。

## 变体与延伸（补充）

**变体与延伸**：

1. 关键路径和实际耗时对不上？ → 关键路径是并行度充足时的理论下界，实际还受 worker 数、内存与 IO 争抢影响，差距大说明并行没吃满。
2. 有环时怎么处理？ → 先报错阻断并打印环上的节点，无法消除时退化为最长链近似，同时显式标注结果不可信。
3. 算出来怎么用？ → 优先拆关键路径上的长任务，非关键链继续加并行收益很小，压缩与转译通常是最该动的两段。
