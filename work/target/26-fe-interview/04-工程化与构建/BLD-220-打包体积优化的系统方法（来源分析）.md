## BLD-220：体积优化系统方法有哪些？
**答**：
- 按来源归类治理：① 依赖级（大依赖替换：moment→dayjs、lodash 全量→按需；tree-shake 失效修复，SCN-BLD-203）；② 重复级（多版本共存——依赖树 diff，SCN-ENG-293）；③ polyfill 级（目标浏览器重算，SCN-ENG-324）；④ 业务级（死代码——unused exports 扫描/图片格式升级 webp/avif）；⑤ 压缩级（mangle/brotli，SCN-BLD-213）。
- 治理顺序：重复与失效（结构性，一次治理永久收益）> 依赖替换 > polyfill > 压缩调参。
- 防劣化：体积 Ratchet（SCN-ENG-291）+ PR bundle diff（SCN-ENG-290）——优化不防劣化等于白做。
- 度量口径：gzip 后传输体积（用户视角）而非 raw。
- 追问钩子：为什么「重复打包」要最先治理——一个包双实例不仅体积翻倍，还会造成运行时单例失效（instanceof/hooks 报错）——它是体积与正确性的双重问题；且治理是结构性的（alias/resolve 统一），一次修复所有入口受益。

```javascript
// 来源清单 → 治理映射
{ dependencies: 'moment→dayjs / lodash-es',
  duplicates: 'lodash@4.17.15 + 4.17.21 → resolve.alias 统一',
  polyfill: 'core-js 按目标重算（ENG-324）',
  business: 'unused exports + 图片格式',
  compression: 'passes/mangle 调参（BLD-213）' }
```
