## BLD-216：模块联邦细节与坑？
**答**：
- 机制：宿主 remote 清单（远程模块地址）+ shared 协商（版本比对 + 优先用已加载实例）——shared 的 singleton/requiredVersion 决定单例语义。
- 坑一：shared 版本不兼容的 fallback——协商失败时异步下载声明版本（loading 状态与失败处理要接住）。
- 坑二：React 双实例——singleton: true 未设置或第三方包内部 require('react') 绕过共享（hooks 报错「Invalid hook call」）。
- 坑三：远程不可用——宿主加载 remote 失败要有降级（错误边界 + 本地兜底模块）。
- 构建时 vs 运行时：联邦是运行时集成，与 monorepo 内包引用（构建时）的边界要清晰（SCN-ENG-234）。
- 追问钩子：为什么联邦下「Invalid hook call」的头号原因是 shared 协商漏网——组件包内部直接 import('react') 若不走联邦的 shared 通道（如包被打成独立 bundle 内嵌了 react 副本），运行时就有两个 React 实例；解法是把所有含 react 依赖的包都纳入 shared 且 singleton——共享的完备性比配置本身更重要。

```javascript
new ModuleFederationPlugin({
  name: 'host',
  remotes: { cart: 'cart@/remote/cart/remoteEntry.js' },
  shared: {
    react: { singleton: true, requiredVersion: deps.react, strictVersion: true },   // strictVersion 版本不符即报错
    'react-dom': { singleton: true },
  },
});
```
