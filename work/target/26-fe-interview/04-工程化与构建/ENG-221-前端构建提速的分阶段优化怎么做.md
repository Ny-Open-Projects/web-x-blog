## ENG-221：构建提速分阶段优化怎么做？
**答**：
- 先测量再优化：构建耗时拆段（resolve/transform/emit/插件），用 speed-measure 或构建工具自带 profile 找大头——常见的头号原因是「一个慢插件/全量 babel」而非整体。
- 常见优化矩阵：缓存（持久化缓存/远程缓存）、并行（多进程 transform）、范围收窄（include/exclude、按需 polyfill）、替代（babel→swc/esbuild）、产物检查（是否多打包了重复依赖）。
- 防劣化基线：构建时长进 CI 指标（P95 基线 + Ratchet），新增慢依赖在 PR 里可见（bundle/耗时 diff）——没有防劣化，优化成果两个月就回吐。
- 分支治理：构建配置本身要有版本化与灰度（新构建配置先在影子分支验证产物一致性）。
- 追问钩子：为什么「防劣化基线」比单次优化更重要——构建时长是典型的棘轮劣化（每次加个插件慢一点没人察觉）；Ratchet 机制让劣化必须显式评审，优化才可持续。

```javascript
// 构建分段诊断
const profile = await build({ profile: true });
profile.topPlugins();        // [{ name: 'babel-loader', ms: 32000 }, ...]
// CI Ratchet 门禁
const buildMs = timer.end();
const budget = await ratchet.get('build-ms-p95');
if (buildMs > budget * 1.05) fail(`构建劣化 ${buildMs}ms > 基线 ${budget}ms`);
```
