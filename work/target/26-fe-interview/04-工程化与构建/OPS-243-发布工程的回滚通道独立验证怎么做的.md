## OPS-243：回滚通道独立验证怎么做的？
**答**：
- 独立性：回滚通道不依赖新版本基础设施——回滚用的是「上一版本入口切换」，但切换通道本身（网关配置/manifest 存储）若与新版本发布共用组件，新版本故障可能连回滚通道一起打挂。
- 独立验证项：回滚入口文件可达/旧版本资源仍在 CDN（N-1 清理没误删）/网关切换 API 可用/回滚权限有效——发布时同步自检。
- 版本保留策略：至少保留 2 个历史版本资源（N 与 N-1），清理必须验证「无流量」后执行（SCN-OPS-218 时序）。
- 验证自动化：发布哨兵顺带跑「回滚通道自检」（轻量探活）——通道坏了在发布时就发现，而不是回滚时。
- 追问钩子：为什么回滚通道要「与新版本发布解耦验证」——最危险的情形是新版本发布故障同时摧毁了回滚通道（比如 manifest 存储被新版本逻辑破坏）；发布时把「回滚是否可用」作为独立探活项，等于给安全网装上警报，事故时刻才不至于发现保险箱是空的。

```javascript
async function verifyRollbackChannel(newRelease) {
  const prev = releases.previous();
  const checks = [
    entryReachable(prev.entry),                        // 旧入口可达
    assetsExist(prev.manifest),                        // N-1 资源未被清理
    gatewaySwitchApiHealthy(),                         // 切换 API 可用
    rollbackPermValid(oncallRole),                     // 回滚权限有效
  ];
  const fails = (await Promise.all(checks)).filter(c => !c.ok);
  if (fails.length) blockRelease(newRelease, `回滚通道异常: ${fails.map(f => f.name)}`);
}
```
