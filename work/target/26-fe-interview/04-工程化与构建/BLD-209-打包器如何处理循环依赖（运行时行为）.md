## BLD-209：循环依赖的运行时行为？
**答**：
- CJS 循环：模块执行到 require 对方时返回「未完成 exports 的部分对象」（引用已存在的缓存）——拿到 undefined 或半初始化对象，取决于执行顺序。
- ESM 循环（live binding）：导入的是绑定引用，函数声明提升可用，const/let 在初始化前访问抛 TDZ 错误——ESM 循环比 CJS 更可预测但也会报错。
- 打包器的处理：保持模块执行顺序（图的后序），循环处按「入口侧先执行」打破——不同入口顺序不同，循环行为可能不一致（同一代码不同入口表现不同）。
- 治理：打包时警告（circular dependency 插件）+ 分层规则（SCN-ENG-202）——循环依赖的正确解法是消除而非依赖打包器行为。
- 追问钩子：为什么循环依赖「有时候能跑有时候报错」——CJS 循环返回的是「执行到一半的 exports」，能否工作取决于访问的是函数（提升可用）还是常量（未初始化）；而入口不同导致模块首次执行顺序不同——同一份循环代码在不同入口下行为不同，这种不确定性就是必须消除循环的工程理由。

```javascript
// a.js: import { b } from './b'; export const a = () => b();
// b.js: import { a } from './a'; export const b = () => a();
// ESM: 函数提升 → 能跑；const a = ... 在 b 初始化前访问 → TDZ ReferenceError
```
