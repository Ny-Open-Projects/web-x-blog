## OPS-266：分流正确性怎么做的？
**答**：
- 三个正确性维度：均匀性（哈希分布均匀——大样本桶分布检验）、稳定性（同用户跨时间/跨端分配一致——sticky 语义验证）、独立性（层间正交——分层盐验证）。
- 自动化验证：分流单元测试（固定输入固定输出——回归保护）、分布监控（线上桶分布实时检验，SRM 是运行时版本）、性质测试（property-based：任意用户序列满足稳定与正交性质）。
- 正确性事故的代价：分流 bug 使实验结论错误（错误的产品决策）——比可用性事故更隐蔽更贵。
- 分流变更的灰度：分流算法本身的变更（换哈希函数）也要灰度——新算法上线先影子运行对比分配结果。
- 追问钩子：为什么「分流 bug 使实验结论错误」比可用性事故更贵——可用性事故影响是即时的（马上发现马上修）；分流偏差让「实验组恰好偏年轻」这类偏差静默扭曲结论，错误的产品决策基于错误数据持续数月——科学性的隐性成本远高于可用性的显性成本。

```javascript
// 性质测试（property-based）
test('稳定性：同用户同层永远同桶', () => {
  for (let i = 0; i < 10000; i++)
    expect(assign(`user${i}`, 'layer1')).toBe(assign(`user${i}`, 'layer1'));
});
test('独立性：层间分布独立', () => {
  const joint = chiSquareIndependence(layer1Buckets, layer2Buckets);
  expect(joint.pValue).toBeGreaterThan(0.01);
});
// 分流算法变更灰度
shadowRun(newHashFn, { compareWith: currentHashFn, duration: '7d' });
```
