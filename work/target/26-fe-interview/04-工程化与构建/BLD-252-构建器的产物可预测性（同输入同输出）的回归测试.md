## BLD-252：可预测性回归怎么做？
**答**：
- 回归场景：构建器升级/配置变更/插件增删——产物语义不应意外变化。
- 测试形态：golden 产物集（代表性项目的基线产物）——升级后新产物与 golden diff，差异逐项解释（SCN-BLD-244 六步法的自动化版）。
- diff 的解释粒度：文件级 hash 变化（可接受）→ 模块级集合变化（必须解释）→ 语义级变化（导出/结构——高危）。
- 差异的可解释性：diff 报告自动分类（hash-only/collection/semantic）——只要求人工解释后两类。
- 追问钩子：为什么 diff 自动分类「只强制解释语义级变化」——hash 变化是工具升级的必然（压缩器版本不同字节不同），逐个解释不现实；模块集合变化影响加载行为（新增 chunk 改变请求模式）；语义变化影响运行时正确性——把人工注意力集中在高危层，是大规模迁移验证的可行设计。

```javascript
// golden 产物回归
const diff = artifactDiff(golden, current);
const classified = classify(diff);   // hash-only | collection | semantic
if (classified.semantic.length || classified.collection.length)
  fail(`需解释的产物变化:\n${[...classified.collection, ...classified.semantic]}`);
// hash-only 自动放行
```
