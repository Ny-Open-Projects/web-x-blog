## OPS-277：回滚数据一致性怎么做的？
**答**：
- 验证对象：回滚后旧版本处理「新版本期间写入的数据」的正确性——数据兼容不是声明了就有效，要实测验证。
- 验证方法：回滚后立即对「新版本写入的真实数据样本」跑旧版本的读写路径（读出/展示/下单链路）——真实数据实测优于 schema 检查（schema 兼容但业务逻辑不兼容的情况抓不住）。
- 一致性哨兵：回滚后 24h 内对关键数据指标（订单创建率/支付成功率）加强监控——数据问题的显性化通常滞后。
- 修复与补偿：发现不兼容数据 → 修复任务（批量迁移/人工修复清单）+ 用户补偿评估（数据丢失的用户）。
- 追问钩子：为什么要用「真实数据跑旧版本读写路径」而不是只做 schema 兼容检查——schema 兼容只保证「字段能读出来」，不保证「业务逻辑能处理」（如新版本写入的状态值旧版本不认识）；真实数据实测把「逻辑级兼容」也验证了——这是回滚验证与常规测试的深度差异。

```javascript
async function verifyDataCompatAfterRollback(writtenByNew) {
  const sample = sampleOf(writtenByNew, 100);          // 新版本写入的真实数据
  const results = await Promise.all(sample.map(d =>
    oldVersionReadWrite(d)));                          // 旧版本真实读写路径
  const failures = results.filter(r => !r.ok);
  if (failures.length) {
    scheduleRepair(failures);                          // 修复任务
    assessCompensation(failures);                      // 用户补偿评估
    alert({ type: 'DATA_INCOMPAT', count: failures.length });
  }
}
```
