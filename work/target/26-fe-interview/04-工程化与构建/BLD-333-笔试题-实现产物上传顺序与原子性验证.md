## BLD-333：手写发布顺序验证

**需求与边界**：
- 需求：发布流程的顺序与原子性验证（SCN-BLD-247）——① 顺序校验（资源先于 HTML——发布过程事件序列断言）；② 原子性验证（中途失败后线上无感——旧 HTML 仍引用旧资源且全可达）；③ 回滚完整性（回滚后旧资源全可达——N-1 未清理验证，SCN-OPS-243）。
- 边界：① 事件序列从发布编排器取（不是日志猜测）；② 原子性测试的故障注入（上传中途 kill——注入点，SCN-OPS-281）；③ 验证进 CI 定期跑（发布流程的回归）。

**答**：
```javascript
async function verifyPublishOrdering(releaseId, orchestrationEvents, cdn) {
  const seq = orchestrationEvents.filter(e => e.releaseId === releaseId);
  // 1. 顺序断言：assets-push 全部完成 → html-switch
  const assetsDone = seq.filter(e => e.type === 'asset-pushed');
  const htmlSwitch = seq.find(e => e.type === 'html-switched');
  const ordering = htmlSwitch && assetsDone.length &&
    assetsDone.every(a => a.ts <= htmlSwitch.ts);      // 资源先于 HTML
  // 2. 原子性验证（故障注入：上传中途 kill）
  const atomicity = await injectAndVerify({
    inject: () => killMidUpload(releaseId),            // 中途 kill（SCN-OPS-281 注入器）
    verify: async () => {                              // 线上无感验证
      const html = await cdn.get('/index.html');
      const refs = extractRefs(html);
      return allReachable(refs, cdn);                  // 旧 HTML 引用的资源全可达
    },
  });
  // 3. 回滚完整性（N-1 资源未清理）
  const prev = releases.previous(releaseId);
  const rollbackOk = prev && allReachable(prev.manifest.allFiles(), cdn);
  return { ordering, atomicity, rollbackOk,
    verdict: ordering && atomicity && rollbackOk ? 'PASS' : 'FAIL' };
}
```

**评分点**:
- 顺序断言（事件序列资源→HTML——SCN-OPS-209 流量顺序）。
- 原子性故障注入（中途 kill 后线上无感——SCN-OPS-281 注入器）。
- 回滚完整性（N-1 资源可达——SCN-OPS-243 联动）。
- 定期 CI 回归（发布流程的演练即代码）。
