## ENG-327：手写技术债台账

**需求与边界**：
- 需求：债务条目（位置/成因/额外成本/触及频率/清偿估时）；利息 = 触及频率 × 额外成本；清偿优先级 = 利息 × 剩余寿命 / 清偿估时（性价比）；债务总量 Ratchet（总量不增）。
- 边界：① 触及频率来自 git 历史统计（文件近 90 天变更次数）而非拍脑袋；② 剩余寿命 = 预期存活月数（计划下线的模块利息 ×0）；③ 新债登记强制字段校验。

**答**：
```javascript
function debtLedger(debts, gitHistory, { iterationBudget = 0.15 } = {}) {
  return debts.map(d => {
    const touchFreq = gitHistory.touchCount(d.path, 90) / 90;   // 次/天（git 数据驱动）
    const interest = touchFreq * d.extraCostHours;
    const remainingLife = d.plannedEol ? Math.max(0, monthsUntil(d.plannedEol)) : 24;   // 默认 24 月
    return {
      ...d, interest, remainingLife,
      payoffScore: remainingLife === 0 ? -1 : interest * remainingLife / d.effortDays,   // 性价比
    };
  }).sort((a, b) => b.payoffScore - a.payoffScore);    // 计划下线的债沉底
}
function debtRatchet(current, budget) {
  const total = current.reduce((s, d) => s + d.effortDays, 0);
  if (total > budget) fail(`技术债总量 ${total} 人日超预算 ${budget}——新债必须配套清偿`);
  return { total, perIterationDays: total * iterationBudget };   // 每迭代 15% 清偿配额
}
```

**评分点**:
- 利息 = 触及频率 × 额外成本（git 历史数据驱动，ENG-273）。
- 性价比 = 利息×寿命/清偿估时（排序可解释）。
- 计划下线模块利息归零（不修快死的代码）。
- 总量 Ratchet + 迭代清偿配额（棘轮机制复用）。
