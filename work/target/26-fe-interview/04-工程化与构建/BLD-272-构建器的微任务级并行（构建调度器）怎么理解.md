## BLD-272：构建调度器怎么理解？
**答**：
- 调度问题：构建任务是依赖图（包 A 依赖 B 先建 B）+ 资源约束（CPU 核数/内存）——调度器决定「什么时刻跑什么任务」（最大并行度 + 关键路径优先）。
- 关键路径：依赖图的最长链决定总时长——调度器优先跑关键路径上的任务（ turborepo 的调度决策）。
- 资源感知调度：任务声明资源需求（内存重的构建任务错峰——SCN-BLD-253 内存治理的调度层解法）。
- 缓存感知：命中缓存的任务零成本跳过——调度器根据缓存状态动态剪枝。
- 追问钩子：为什么「关键路径优先」是构建调度的第一原则——并行度再高，总时长 ≥ 最长依赖链（关键路径）；把关键路径上的任务先跑起来（哪怕它与其他任务抢资源），否则 CPU 空等关键任务的依赖——调度优化的目标函数是「缩短最长链」而非「最大化 CPU 占用」。

```javascript
// 关键路径调度
const criticalPath = longestChain(taskGraph);         // A→C→F 链
schedule(criticalPath.first);                         // 优先启动关键任务
// 资源感知
taskGraph.tasks.forEach(t => scheduler.enqueue(t, { mem: t.memNeeds }));
// 缓存剪枝
if (cacheHit(t)) scheduler.skip(t);                   // 零成本跳过
```
