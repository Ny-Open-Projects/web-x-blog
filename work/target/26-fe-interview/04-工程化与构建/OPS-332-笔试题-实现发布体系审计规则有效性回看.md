## OPS-332：手写审计有效性回看

**需求与边界**：
- 需求：审计规则的生命周期治理（SCN-OPS-315 扩展）——① 12 个月零拦截的规则降级为抽查；② 拦截率异常高的规则复核（可能规则过紧或流程普遍违规）；③ 规则升级（抽查项发现系统性违规 → 升级为全量门禁）；④ 规则变更留痕。
- 边界：① 「拦截」定义明确（规则触发且确认是真实违规）；② 降级不是删除（抽查保留覆盖）；③ 升级需平台团队批准（门禁变更影响所有人）。

**答**：
```javascript
function auditRuleLifecycle(rules, { fullGateMonths = 12, spotMonths = 6 } = {}) {
  return rules.map(r => {
    const catches = r.history.filter(h => h.confirmedViolation);   // 确认违规才算拦截
    const months = monthsSince(r.since);
    if (r.level === 'full-gate' && months > fullGateMonths && catches.length === 0)
      return { ...r, action: 'DEMOTE_TO_SPOT', note: `${months} 月零拦截，降级抽查（非删除）` };
    if (r.level === 'spot' && months > spotMonths && catches.length >= 3)
      return { ...r, action: 'PROMOTE_CANDIDATE',
        note: `抽查发现 ${catches.length} 次系统性违规，建议升级全量门禁（需平台批准）` };
    if (catches.length / r.history.length > 0.3)
      return { ...r, action: 'REVIEW_THRESHOLD',
        note: '拦截率 30%+——规则过紧或流程普遍违规，人工复核' };
    return r;
  }).map(r => r.action ? auditRuleChange(r) : r);      // 变更留痕
}
```

**评分点**:
- 双向治理（降级零拦截 + 升级高频拦截——SCN-OPS-315 扩展）。
- 「确认违规才算拦截」（误报不计数——判定诚实）。
- 拦截率异常复核（规则过紧 vs 流程违规两种归因）。
- 升级需平台批准（门禁变更的权限治理）。
