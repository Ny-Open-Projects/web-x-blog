## OPS-248：发布知识回流怎么做的？
**答**：
- 回流内容：每次非平凡发布（出过问题/特殊决策）生成案例条目——症状/根因/处置/预防改动，与预案卡片（SCN-OPS-217）联动更新。
- 案例结构化：案例带标签（失败模式分类）与「检测方式」（哨兵发现/用户反馈/值班发现）——检测方式的分布暴露观测盲区（全靠用户反馈发现 = 哨兵缺失）。
- 消费场景：新发布计划评审时自动关联相似历史案例（同类型变更出过什么事）；值班排障时检索。
- 回流机制：发布复盘会产出自动转化为案例（模板化，SCN-OPS-248 与复盘体系联动）——知识生产的成本低于不生产的成本。
- 追问钩子：为什么案例要带「检测方式」标签——统计发现 80% 的事故由用户反馈先发现而非哨兵，说明观测体系有盲区（用户感知到的错误哨兵看不见）；检测方式分布是观测体系健康度最直接的度量——案例库不只是记故事，更是观测盲区的探测器。

```javascript
function publishCase(release, incident) {
  return archive({
    symptom: incident.symptom, rootCause: incident.rca,
    resolution: incident.actions, prevention: incident.preventiveChanges,
    detectChannel: incident.detectedBy,                // sentinel/user-report/oncall
    tags: incident.failureMode,
  });
  // 观测盲区分析
  const blind = groupBy(allCases, 'detectChannel');
  if (blind['user-report'] > blind['sentinel']) suggestObservabilityGap();
}
```
