## BLD-264：构建失败降级怎么设计？
**答**：
- 失败分级：源码错误（必须修——不能降级放行）/基础设施失败（CI runner 挂/缓存服务挂/依赖源挂——可降级重试或本地构建）/配置错误（快速回滚配置）。
- 降级路径：CI 不可用 → 本地构建脚本（SCN-ENG-279，日常演练保鲜）→ 紧急发布走人工 runbook（产物本地构建 + 手动上传 + 事后补 CI 记录）。
- 重试策略：基础设施失败自动重试（区分幂等性——依赖安装可重试，代码错误重试无意义）。
- 降级的审计：降级发布的标记（非标准通道发布）——事后补验与审计（SCN-OPS-220 留痕不因降级缺失）。
- 追问钩子：为什么「源码错误不能降级放行」而「基础设施失败可以」——降级的本质是「跳过验证」，源码错误跳过验证 = 未验证代码上线（违背发布底线）；基础设施失败时代码本身已被验证过（本地可跑测试）——降级的合法性取决于「被跳过的环节是什么」，这是分级的核心依据。

```javascript
function buildFailureHandling(err) {
  if (err.category === 'SOURCE') return block();       // 源码错误：阻断不放行
  if (err.category === 'INFRA') {
    return retryOrFallback({
      retry: err.retryable,                            // 幂等失败重试
      fallback: 'local-build + manual-publish runbook', // 降级路径（保鲜演练）
      audit: { degraded: true, reason: err.message },  // 降级留痕
    });
  }
}
```
