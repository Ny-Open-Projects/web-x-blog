## BLD-256：联邦协商与降级怎么做？
**答**：
- 协商流程：宿主加载 remoteEntry → remote 的 shared 清单与宿主比对 → 版本兼容者复用宿主实例 → 不兼容 remote 自带版本异步下载 → singleton 冲突报错（strictVersion）。
- 降级链：remote 不可达 → 本地兜底组件（降级 UI）/错误边界捕获 + 重试其他 CDN 源——远程模块的可用性设计（SCN-BLD-216 坑三的工程化）。
- 协商可观测：shared 协商结果上报（哪个 remote 用了宿主版本/哪个自带）——「双 React 实例」类问题的运行时探测。
- 追问钩子：为什么协商结果的「运行时上报」很重要——构建期 shared 配置正确不代表运行时协商正确（宿主与 remote 的实际版本组合取决于发布顺序）；运行时上报协商结果（实例数/版本）能在「Invalid hook call」发生前发现双实例——把联邦从「配置正确」验证升级到「运行时正确」验证。

```javascript
// 协商后上报
__webpack_share_scopes__.default.__usage = {
  react: { version: React.version, singleton: true, instances: 1 },
};
telemetry.push({ type: 'federation-shared', usage: getShareUsage() });
// remote 不可达降级
loadRemote('cart').catch(() => renderFallback(CartFallback));   // 降级 UI
```
