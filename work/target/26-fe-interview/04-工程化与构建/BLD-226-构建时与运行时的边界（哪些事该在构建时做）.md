## BLD-226：构建时/运行时边界怎么划？
**答**：
- 构建时优先清单：常量内联（Define）、路由表静态生成、i18n 资源按语言拆分、图标 sprite 合成、依赖预构建、类型校验——「能确定就提前算」，运行时零成本。
- 必须运行时的：依赖用户/环境的值（灰度决策/用户偏好）、动态数据（接口数据）、跨发布可变的配置（SCN-ENG-237 运行时配置）。
- 判断准则：值的「变更频率」——发布级别不变 → 构建时；用户级别不变 → 运行时静态（CDN）；请求级变化 → 服务端。
- 边界错配的代价：该构建时做放运行时（体积+性能损失）、该运行时做放构建时（灵活性丧失——改文案要发版）。
- 追问钩子：为什么「变更频率」是划分构建/运行时的第一准则——构建时产物 immutable（SCN-ENG-241 强缓存），变更频率与产物 hash 变化频率一致；文案/feature flag 这类高频变更的东西打进产物会让每次文案修改都是一次全量发布——把高频变更的值留在运行时层（配置/接口），发布只承载低频结构。

```javascript
// 变更频率三分法
buildTime:  { define: '__API_HOST__', routes: staticRoutes },   // 发布级
runtimeStatic: { config: '/config.json', flags: flagSnapshot }, // 用户级/环境级
serverSide: { userData: api },                                     // 请求级
```
