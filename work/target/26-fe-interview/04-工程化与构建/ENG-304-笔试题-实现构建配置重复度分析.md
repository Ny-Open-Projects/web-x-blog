## ENG-304：手写配置重复度分析

**需求与边界**：
- 需求：对比各项目 vite.config 与 preset 的 AST/键结构差异——① 计算每项目与 preset 的 diff 行数/比例；② 跨项目重复模式检测（≥3 个项目有相同 override 应上收到 preset）；③ 输出「上收建议清单」。
- 边界：① 只比较语义键（忽略注释/顺序）；② override 嵌套按路径归一（server.port vs server{port}）；③ 上收建议带涉及项目列表（便于评审影响面）。

**答**：
```javascript
function configDuplication(projects, preset, { threshold = 3 } = {}) {
  const normalized = projects.map(p => ({
    name: p.name, keys: normalizeKeys(parseConfig(p.config)),    // 语义键归一
  }));
  const presetKeys = new Set(normalizeKeys(parseConfig(preset)));
  const report = normalized.map(p => ({        // 注意遍历归一化结果，原始 projects 上没有 keys
    name: p.name,
    diffRatio: p.keys.filter(k => !presetKeys.has(k)).length / (p.keys.length || 1),
  }));
  // 跨项目重复 override 模式
  const patternCount = new Map();
  for (const p of normalized)
    for (const k of p.keys)
      if (!presetKeys.has(k))
        patternCount.set(k, [...(patternCount.get(k) ?? []), p.name]);
  const promote = [...patternCount.entries()]
    .filter(([k, names]) => names.length >= threshold)   // ≥3 项目重复 → 上收建议
    .map(([k, names]) => ({ path: k, projects: names }));
  return {
    perProject: report.sort((a, b) => b.diffRatio - a.diffRatio),
    promote,                                            // preset 上收建议
    health: report.every(r => r.diffRatio < 0.3) ? 'OK' : 'PRESET_DRIFTING',
  };
}
```

**评分点**:
- 语义键归一（忽略顺序/注释，嵌套路径统一）。
- 跨项目重复模式检测（≥3 上收——ENG-267 温度计）。
- 上收建议带项目列表（影响面评审）。
- preset 漂移健康判定（diffRatio 超标告警）。

## 变体与延伸（补充）

**变体与延伸**：

1. 配置重复度怎么量化？ → 配置归一化后按键路径求相似度，或用 AST 子树哈希统计共现次数，两者结合看结构重复与值重复。
2. 抽 preset 的边界在哪？ → 只抽稳定且高频的公共项，项目差异保留为 override，否则 preset 会退化成堆满开关的巨型配置。
3. 怎么防止过度抽象？ → 看变更频率是否共现，长期一起改的才合并，频繁分叉的说明抽象放错了层。
