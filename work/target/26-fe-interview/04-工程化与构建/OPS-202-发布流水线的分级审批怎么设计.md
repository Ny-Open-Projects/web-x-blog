## OPS-202：分级审批怎么设计？
**答**：
- 风险自动分级：变更大小（diff 行数）× 触及路径（危险配置？）× 是否灰度 × 发布窗口——分级器输出 L0~L3，审批强度随级别递增（L0 自动放行、L3 双人审批 + 值班确认）。
- 分级透明：PR 上显示「为什么我被判为 L2」（触发因素列表）——黑盒分级引发博弈与不信任。
- 豁免与申诉：分级不合理可申诉改级（评审记录），但滥用申诉（频繁改级）回流出分级规则优化。
- 审批时效：审批 SLA（2 小时响应）与升级路径，防止发布卡在审批环节——审批也是要被治理的流程。
- 追问钩子：为什么分级依据要「显式列出触发因素」——隐式分级让团队开始猜测和博弈规则（拆小 PR 绕过）；显式因素让分级可预期、可申诉、可改进，审批才成为风险管理而非障碍。

```javascript
function riskLevel(pr, ctx) {
  const factors = [];
  if (pr.diffLines > 500) factors.push('大变更');
  if (pr.paths.some(p => isDangerousPath(p))) factors.push('危险路径');
  if (!pr.hasCanaryPlan) factors.push('无灰度计划');
  if (isFridayAfternoon(ctx.ts)) factors.push('高危窗口');
  const level = factors.length >= 3 ? 'L3' : factors.length === 2 ? 'L2'
    : factors.length === 1 ? 'L1' : 'L0';
  return { level, factors, approval: APPROVAL_MAP[level] };   // L0 auto / L3 双人+值班
}
```
