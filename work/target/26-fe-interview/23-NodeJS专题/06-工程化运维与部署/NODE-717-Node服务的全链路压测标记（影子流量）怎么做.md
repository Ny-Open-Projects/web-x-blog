## NODE-717：全链路压测标记怎么做？
**答**：
- 标记贯穿：压测流量全链标记（header x-loadtest——SCN-NODE-670 灰度标记同构贯穿）→ 每个服务识别 → 影子资源路由（影子 DB 表/影子队列/影子下游——压测流量不写生产数据，SCN-联想-885 隔离语义）。
- 影子资源方案：影子表（同库影子表——t_order_shadow）或影子库（独立实例——隔离彻底）；影子队列（同 MQ 集群影子 topic）。
- 数据脱敏：压测流量来源（生产流量脱敏回放——隐私红线，SCN-联想-584 合规）；影子数据清理（压测后清理——影子表增长治理）。
- 遗漏防御：新服务/新存储接入必须实现标记路由（接入检查清单——未接入 = 压测污染生产，SCN-联想-719 环境隔离同源）。
- 追问钩子：为什么「新服务接入必须实现影子路由」是全链路压测的最大风险点——老服务都实现了标记路由，新服务（或新加的存储）没实现——压测流量直写生产表（污染生产数据——资损级事故）；接入清单进发布门禁（新服务上线前验证影子路由——SCN-联想-885 门禁语义），把风险从压测时刻前移到上线时刻。

```javascript
// 影子路由中间件
app.use((req, res, next) => {
  if (req.headers['x-loadtest']) {
    req.isShadow = true;
    db.routeToShadow();                                // 影子表路由
    mq.topicSuffix = '_shadow';                        // 影子队列
  }
  next();
});
// 接入检查（发布门禁）
verifyShadowRouting(newService);                       // 未接入阻断上线
```
