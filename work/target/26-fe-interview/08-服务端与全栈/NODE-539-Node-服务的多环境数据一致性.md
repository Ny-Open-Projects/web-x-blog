## NODE-539：测试与生产数据隔离加固
**答**:
- 串环境事故形态：测试代码连生产库（配置错误 NODE-413）、测试数据污染生产（共库不隔离）、生产数据被测试操作修改（测试账号误用生产数据）。加固多层防线。
- 网络层：环境网络隔离（测试环境默认连不到生产 DB——网络策略硬隔离，配置错误也连不上——最强防线）、生产 DB 访问白名单（只有生产集群 IP 段可连——NODE-435）。
- 配置层：数据源配置 fail-safe（生产配置缺省拒绝启动而非默认连本地——防"本地兜底连到生产"）、连接串审计（启动日志打脱敏连接串——人眼可确认环境）、环境标识贯穿（连接后校验 DB 内环境标记——`select env from meta` 不匹配即拒绝服务 NODE-413 自检）。
- 数据层：测试数据标识（测试账号/数据专用前缀——生产报表可过滤）、生产数据脱敏导入测试库（NODE-463——测试库禁止用生产明文）。
- 演练：串环境攻击演练（故意配错连接串——验证各层拦截真实生效 NODE-408）。
```javascript
// 环境自检（连接后校验）
const env = await db.query('select env from meta');
if (env !== expectedEnv) throw new EnvMismatch(`连到 ${env}，期望 ${expectedEnv}`); // 拒绝启动
```
