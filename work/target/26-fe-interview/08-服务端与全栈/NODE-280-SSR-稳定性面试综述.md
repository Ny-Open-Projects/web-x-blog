## NODE-280：SSR 稳定性面试综述？
**答**:
- 综述框架：挑战（NODE-271）→ 过载保护（272 队列+降级）→ 缓存策略（273 ISR/277 CDN/345 SWR）→ 正确性（274 水合）→ 容量（279）→ 泄漏防护（278）。
- 答题模板："SSR 稳定性 = 把渲染当 CPU 密集任务管理"——容量按 CPU 算、过载按队列控、失败按降级走、泄漏按快照查。
- 高频追问："SSR 页面 5xx 率怎么降"→ 超时兜底 CSR + 下游预算 + 流式分段；"大促 SSR 怎么扛"→ 预生成+CDN+降级开关。
- 收束金句："SSR 的稳定性本质是成本问题——每一次'每请求渲染'都要问：能不能缓存？能不能流式？能不能降级？"

// 一页纸
// 1) 渲染 = CPU 任务：concurrency 信号量 + 队列上限 + 快速降级
// 2) 缓存三层：组件级 memo → 页面 ISR/SWR → CDN s-maxage
// 3) 数据：AbortSignal.any 预算 + Suspense 分段流式（慢块不阻塞 TTFB）
// 4) 正确性：SSR/CSR 同渲染函数 + 稳定 seed + chunk 兜底
// 5) 容量：单实例基线实测 × 实例数 × 水位线 70%；大促预热 + HPA
