## NODE-469：渐进式发布的用户无感设计
**答**:
- 无感要素：会话粘性（同一用户在灰度期间稳定在同一版本——避免"刚才功能有现在没了"的体验混乱，分桶结果持久化 ARC-390）、长连接不中断（灰度实例滚动重启时 WS 优雅迁移 NODE-346）、事务连续性（用户操作中途切版本——请求级粘性 + 中断重试协议）。
- 版本差异的用户感知控制：UI 变更（文案/布局差异）在灰度期间是"正常产品变化"——但核心流程状态（订单状态语义）跨版本必须兼容（ARC-449 双版本数据兼容）。
- 灰度名单的用户体验：被选中的用户可能遇到 bug——高危功能灰度前先内部名单验证（dogfooding 两周）再外部灰度。
- 灰度期间的客服支持：客服侧标注用户版本（报障时知道用户在哪个版本——按版本分类处理），已知灰度问题的自动话术。
- 发布可观测的用户视角：真实用户监控按版本切片（ARC-422 指纹体系）——"金丝雀用户体验分 vs 全量用户"对比是灰度质量的直接证据。
```javascript
// 会话粘性 + 版本标注
function resolveVersion(user) {
  return sticky(user, releases);                                 // 分桶结果持久化（cookie/db）
}
// 客服工单携带版本：ticket.create({ ..., release: userRelease(uid) })
// 内部名单先行：gray.whitelist = employees(两周) → 外部 1% → 5% → 25% → 100%
```
