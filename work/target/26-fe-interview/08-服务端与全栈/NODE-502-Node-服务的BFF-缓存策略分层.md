## NODE-502：BFF 缓存策略分层
**答**:
- 三层缓存：页面级（聚合结果整页缓存：key = route + 关键 cookie 维度——TTL 秒级微缓存削峰 ARC-367）、片段级（聚合内子模块缓存：推荐位/公告位各自 TTL——页面部分新鲜）、数据级（下游响应缓存：读接口 short TTL——下游压力转移 NODE-353）。
- 分层选择原则：页面级适合个性化弱+变更频率低的页面；片段级适合"大部分稳定少部分动态"（首屏骨架稳定 + 推荐动态）；数据级是兜底（所有下游读的通用加速）。
- key 设计：页面级 key 要含所有影响输出的维度（route+uid 群组+灰度标签 NODE-497——漏维度 = 数据串户）、片段 key 按模块独立维度、数据 key 按请求参数规范化。
- 失效：TTL 为主（BFF 层避免复杂主动失效——依赖下游失效事件太重）、tag 失效（关键数据：价格变更事件失效相关页面缓存——ARC-444 级联的服务端节点）。
- 观测：分层命中率/缓存体积/陈旧度（用户看到数据的最大延迟——业务可接受度校准）。
```javascript
// 片段级缓存示例
const fragments = {
  banner: { ttl: 60, key: () => 'frag:banner' },                 // 全用户相同
  recommend: { ttl: 30, key: (u) => `frag:rec:${cohort(u)}` },   // 按群组分桶缓存
  balance: null                                                  // 个性化强不缓存
};
// 页面装配：稳定片段读缓存 + 动态片段实时——命中率 85%+ 为健康线
```
