## AV-439：手写一个播放器事件去抖统计器

**答**：
- 需求：implement PlayerStats(video)。聚合 seek/qualityChange/pause 事件：seek 统计次数与平均跳转距离；qualityChange 记录方向（升/降）；输出 { seeks: { count, avgJumpMs }, quality: { up, down } }。
- 边界：seek 距离 = |target - currentTime|；quality 变化从 video.videoHeight 判断；flush 清空计数。
- 评分点：事件聚合；跳转距离；质量方向；清空机制

```javascript
class PlayerStats {
  constructor(video) {
    this.seeks = []; this.q = { up: 0, down: 0 };
    this._lastH = video.videoHeight;
    this._lastT = video.currentTime;
    video.addEventListener('timeupdate', () => { this._lastT = video.currentTime; });
    video.addEventListener('seeking', e => {
      this.seeks.push({ from: this._lastT, to: video.currentTime });
    });
    video.addEventListener('loadedmetadata', () => {
      if (this._lastH && video.videoHeight !== this._lastH)
        this.q[video.videoHeight > this._lastH ? 'up' : 'down']++;
      this._lastH = video.videoHeight;
    });
  }
  report() {
    const jumps = this.seeks.map(s => Math.abs(s.to - s.from) * 1000);
    return { seeks: { count: this.seeks.length,
        avgJumpMs: jumps.length
          ? Math.round(jumps.reduce((s, v) => s + v, 0) / jumps.length) : 0 },
      quality: this.q };
  }
}
```

## 补充：评分点与变体

**评分点**：

- seeking 时 currentTime 已是目标值，距离要用 seeked 或缓存上次位置计算（给分）；直接拿同一个 currentTime 相减得到 0（扣分）。
- qualityChange 用 videoHeight 前后比较判断升降并分别计数（给分）；用事件次数或 currentTime 判断方向（扣分）。
- report 与 flush 能清空计数，二次调用结果互相独立（给分）；只累加不清零、多次 flush 数值翻倍（扣分）。
- destroy 时解绑事件监听，重复初始化不会重复计数（给分）；监听器泄漏、同一事件被统计两遍（扣分）。

**变体与延伸**：

1. 频繁 seek 时怎么避免统计被异常值污染 → 距离为 0 或小于 1s 的 seek 不计入主指标，单独统计无效 seek 次数。
2. 要顺带统计卡顿而不只是 seek，怎么扩展 → 监听 waiting 记开始、playing 记结束，累加超过 200ms 的等待为卡顿次数与总时长。
