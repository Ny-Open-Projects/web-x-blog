### 精讲 1 · [HW-016] 手写深拷贝

**为什么考这个**：它是一道「能无限加深」的题——从 10 行到 60 行，面试官靠它判断你的深度。写出来只是及格，能不能主动报出边界才是分水岭。几乎所有「拷贝后数据串了」的线上 bug 都能追溯到这道题的某个分支。

**标准实现（面试够用版）**：

```javascript
function deepClone(input, seen = new WeakMap()) {
  // 1. 原始值与函数：直接返回（函数不做深拷贝，保留引用即可）
  if (input === null || typeof input !== 'object') return input;
  // 2. 命中缓存：说明这个对象正在/已经被拷贝，直接返回半成品，循环引用在此断开
  if (seen.has(input)) return seen.get(input);
  // 3. 内置对象必须专属构造：直接递归会得到空壳
  if (input instanceof Date) return new Date(input.getTime());
  if (input instanceof RegExp) return new RegExp(input.source, input.flags);

  // 4. 先建壳再填肉：数组用 []，普通对象保留原型（class 实例不丢方法）
  const clone = Array.isArray(input) ? [] : Object.create(Object.getPrototypeOf(input));
  seen.set(input, clone); // 必须在递归前写入，否则环回时拿不到半成品

  // 5. Reflect.ownKeys 覆盖字符串键 + Symbol 键；跳过不可枚举（如数组 length）
  for (const key of Reflect.ownKeys(input)) {
    const desc = Object.getOwnPropertyDescriptor(input, key);
    if (!desc || !desc.enumerable) continue;
    clone[key] = deepClone(input[key], seen);
  }
  return clone;
}
```

**必须覆盖的边界**：

- 循环引用 → `WeakMap` 记录「原对象 → 克隆对象」，注意 `seen.set` 必须在递归子属性之前。
- Date / RegExp → 各自的构造器；RegExp 还要带 `flags`，进阶版要带 `lastIndex`。
- Map / Set → 不能靠 `Reflect.ownKeys`（内部槽不可枚举），必须 `forEach` 逐项克隆。
- Symbol 键 → `Object.keys` 会漏，用 `Reflect.ownKeys`。
- 不可枚举属性 → 默认不拷（与 lodash 默认行为一致），但要能说清这是「选择」而非「遗漏」。
- 函数 → 直接返回引用，深拷函数既无意义也会破坏闭包。
- 原型链 → `Object.create(Object.getPrototypeOf(obj))`，否则 class 实例会退化成普通对象。

**追问链**：

1. `structuredClone` 能替代手写吗？→ 大多数场景能，且原生支持循环引用、Map/Set、Date、TypedArray；但不支持函数、DOM 节点、Symbol 键，也会丢失自定义类原型（结果是普通对象）。
2. `JSON.parse(JSON.stringify())` 的五个坑？→ Date 变 ISO 字符串、`undefined`/函数/`Symbol` 值被丢弃、`NaN`/`Infinity` 变 `null`、循环引用直接抛错、RegExp/Map/Set 变空对象。
3. 深拷贝的性能代价？→ O(n) 全量遍历且必然打断引用相等，React 里更常见的是结构共享（只克隆变更路径）而不是全量深拷。
4. WeakMap 为什么不用 Map？→ 用 Map 会在拷贝结束后仍持有源对象引用，阻止 GC；WeakMap 弱引用，且键必须是对象。

### 精讲 2 · [HW-097] 深克隆进阶：特殊对象与丢失原型的兜底

**为什么考这个**：基础版只覆盖了「纯 JSON」世界。真实业务里有 `File` 上传、`Blob` 预览、`Map` 缓存、`ArrayBuffer` 二进制，这些对象用 `Reflect.ownKeys` 拷出来全是空壳——`.size` 是 `undefined`，`byteLength` 是 0。能写出这一版，说明你踩过坑。

**标准实现**：

```javascript
function cloneDeep(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value; // 原始值 + 函数
  if (seen.has(value)) return seen.get(value);                   // 循环引用

  if (value instanceof Date) return new Date(value.getTime());
  if (value instanceof RegExp) {
    const re = new RegExp(value.source, value.flags);
    re.lastIndex = value.lastIndex;                              // 保留 /g 匹配位置
    return re;
  }
  if (value instanceof Map) {
    const out = new Map();
    seen.set(value, out);                                        // 先登记再递归，环安全
    for (const [k, v] of value) out.set(cloneDeep(k, seen), cloneDeep(v, seen));
    return out;
  }
  if (value instanceof Set) {
    const out = new Set();
    seen.set(value, out);
    for (const v of value) out.add(cloneDeep(v, seen));
    return out;
  }
  if (value instanceof ArrayBuffer) return value.slice(0);       // 二进制按字节复制
  if (ArrayBuffer.isView(value)) {                               // TypedArray / DataView
    const buf = value.buffer.slice(value.byteOffset, value.byteOffset + value.byteLength);
    return new value.constructor(buf);                            // 注意别共享同一块 buffer
  }
  if (typeof Blob !== 'undefined' && value instanceof Blob) {
    return value.slice(0, value.size, value.type);                // Blob 不可变，slice 即新实例
  }
  if (typeof File !== 'undefined' && value instanceof File) {
    return new File([value], value.name, { type: value.type, lastModified: value.lastModified });
  }

  // 普通对象 / 数组：保留原型，逐属性用 defineProperty 保留描述符
  const out = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  seen.set(value, out);
  for (const key of Reflect.ownKeys(value)) {
    const desc = Object.getOwnPropertyDescriptor(value, key);
    if (!desc) continue;
    if (key === 'length' && Array.isArray(value)) continue;       // length 自动维护
    if (desc.get || desc.set) { Object.defineProperty(out, key, desc); continue; } // 访问器原样搬
    Object.defineProperty(out, key, {
      value: cloneDeep(desc.value, seen),
      enumerable: desc.enumerable,
      writable: true,
      configurable: true,
    });
  }
  return out;
}
```

**必须覆盖的边界**：

- `Map` 的键也要深拷（对象键是最容易漏的一处），否则克隆出来的 Map 与源共享键对象。
- `Set`/`Map` 内部元素同样可能成环，必须先把空容器 `seen.set` 进去。
- TypedArray：`value.slice()` 只拷视图不拷 buffer 语义要分清；跨 buffer 复制用 `buffer.slice(byteOffset, ...)`。
- `File` 是 `Blob` 子类，判断顺序必须先 `File` 后 `Blob`，否则 File 会被降级成 Blob、丢 `name`。
- 访问器属性（getter）不能直接读值，否则会触发副作用且丢失 getter 语义。
- 函数、DOM 节点、Promise、WeakMap 一律返回引用——它们要么无法拷贝，要么拷贝没有意义。

**追问链**：

1. `File` 和 `Blob` 什么关系？→ `File extends Blob`，多出 `name`/`lastModified`；所以 `instanceof Blob` 的判断要放在 `File` 之后。
2. 为什么用 `defineProperty` 而不是 `clone[key] = ...`？→ 前者能保留 `enumerable/writable/configurable`，也避免 setter 被触发；后者在只读属性上会静默失败（严格模式抛错）。
3. 克隆后 `instanceof` 还成立吗？→ 普通对象成立（保留了原型）；Date/Map/Set 是新建实例，成立；自定义 class 的私有字段（`#x`）无法复制，只能靠类提供 `clone()`。
4. 什么时候干脆不拷贝、直接用 `structuredClone`？→ 数据结构纯 JSON + 二进制 + Map/Set，且不需要保留 class 行为时。

### 精讲 3 · [HW-099] 路径式不可变更新：setIn / getIn / updateIn

**为什么考这个**：Redux、Immer、React 状态更新的本质都是「不可变 + 结构共享」。手写这题能证明你理解「为什么 React.memo 依赖引用相等」，而不是只会 `{...state}` 一层浅拷贝——浅拷贝在嵌套状态下会让所有子组件都重渲染。

**标准实现**：

```javascript
const isObjLike = v => v !== null && typeof v === 'object';

function getIn(obj, path, fallback) {
  let cur = obj;
  for (const key of path) {
    if (!isObjLike(cur)) return fallback;   // 中途断链立即短路，不抛 TypeError
    cur = cur[key];
  }
  return cur === undefined ? fallback : cur;
}

function setIn(obj, path, value) {
  if (path.length === 0) return value;             // 路径耗尽：直接替换当前层
  const [head, ...rest] = path;
  // 当前层不存在时按下一层 key 的类型决定建对象还是建数组
  const base = isObjLike(obj) ? obj : typeof head === 'number' ? [] : {};
  const clone = Array.isArray(base) ? base.slice() : { ...base };  // 只浅拷贝当前层
  clone[head] = setIn(base[head], rest, value);    // 只递归目标分支，兄弟分支保持原引用
  return clone;
}

function updateIn(obj, path, updater) {
  return setIn(obj, path, updater(getIn(obj, path)));
}

// 结构共享验证
const state = { a: { b: { c: 1 } }, d: { e: 2 } };
const next = setIn(state, ['a', 'b', 'c'], 9);
next.a.b.c;            // 9
state.a.b.c;           // 1        ← 源对象未被修改
next.d === state.d;    // true     ← 兄弟分支共享引用（memo 不会重渲染）
next.a === state.a;    // false    ← 变更路径上的每一层都是新对象
```

**必须覆盖的边界**：

- 路径为空数组 → 返回 `value` 本身（整棵树替换）。
- 中间层缺失（`setIn({}, ['a', 0, 'b'], 1)`）→ 按下一个 key 是否为数字自动建数组/对象。
- 原数组的 `slice()`、原对象的 `{...}` 都是浅拷贝，必须保证「每层只拷一次」，不能整体深拷（否则结构共享失效）。
- `getIn` 对 `0`/`''`/`false` 这类假值不能误判为「取不到」，只判断 `=== undefined`。
- 想支持 `Map`/`Set` 需要单独分派，`{...map}` 会得到空对象。

**追问链**：

1. 为什么不直接 `deepClone` 再改？→ 全量深拷 O(n) 且让所有引用失效，所有 memo 组件都会重渲染；结构共享只克隆 O(depth) 个节点。
2. 三元组 `[state, setIn]` 手写和 Immer 的取舍？→ Immer 用 Proxy 支持「可变写法 + 自动产出新树」，开发体验好；手写 setIn 无依赖、可预测，适合极小状态或需要序列化路径（协同编辑、undo 栈）。
3. undo/redo 怎么接？→ 每次 `setIn` 得到的新树天然是不可变快照，把根引用 push 进栈即可，无需深拷贝。
4. 数组 push 怎么做不可变？→ `setIn(state, ['list', state.list.length], item)`，或封装 `pushIn = (arr, v) => [...arr, v]`。

### 精讲 4 · [HW-056] FlattenDeep：为什么这题要写迭代版

**为什么考这个**：递归版三行写完，人人都会；面试官问的是「10 万层嵌套怎么办」。这是从「会写」到「知道运行时限制」的分界线——JS 引擎的调用栈通常一万多层就 `RangeError`，而显式栈在堆上，只受内存限制。

**标准实现（显式栈，保序，O(n)）**：

```javascript
function flattenDeep(input) {
  if (!Array.isArray(input)) throw new TypeError('input must be an array');
  const out = [];
  // 每帧记录「当前数组 + 走到第几个」，比整体 pop 再 reverse 更省内存也更保序
  const stack = [{ arr: input, i: 0 }];

  while (stack.length) {
    const frame = stack[stack.length - 1];
    if (frame.i >= frame.arr.length) {   // 这一层走完，出栈回到上一层
      stack.pop();
      continue;
    }
    const v = frame.arr[frame.i++];      // 取一个元素并把游标前移
    if (Array.isArray(v)) stack.push({ arr: v, i: 0 }); // 遇到数组：压栈下钻
    else out.push(v);                    // 叶子：直接收集
  }
  return out;
}

// flattenDeep([1, [2, [3, [4]]]]) → [1, 2, 3, 4]
```

**必须覆盖的边界**：

- 保序：用 `pop` + `reverse` 的写法容易写反，游标帧天然按原序访问。
- 空数组与空嵌套 `[[], [[]]]` → 返回 `[]`，不应产出空占位。
- 稀疏数组：`forEach`/`for...of` 会把 `hole` 当 `undefined`，需要说清「按 undefined 处理」还是「跳过」。
- 超深嵌套：迭代版跑 10 万层不炸栈（递归版直接 `Maximum call stack size exceeded`）。
- 非数组入参：抛 `TypeError`，而不是静默返回 `[]`（静默会掩盖上游 bug）。
- 复杂度：每个元素最多进栈一次、出栈一次，O(n)；空间 O(深度 + 结果长度)。

**追问链**：

1. 和 `flat(Infinity)` 的差别？→ 原生会跳过空槽（sparse hole 被移除）、不处理类数组；手写版按需定义。原生在 V8 里也是迭代实现，不会爆栈。
2. 为什么要记录 `{arr, i}` 而不是只压元素？→ 只压元素需要倒序 push，会多一次 O(n) 拷贝，且大数组内存翻倍。
3. 递归版什么时候可以用？→ 层级已知且浅（配置树、AST 通常 < 100 层），可读性更好。
4. 能流式处理吗？→ 能，改成生成器 `function*`，`yield` 叶子，配合 `for...of` 增量消费。

### 精讲 5 · [HW-025] 对象深层取值：路径解析与短路

**为什么考这个**：业务代码里 `a && a.b && a.b.c` 的防御式取值满地都是。这题考的是「路径表达式解析」这个正则小技巧，以及「默认值到底什么时候生效」的语义边界——后者是面试官最爱的追问。

**标准实现**：

```javascript
function deepGet(obj, path, defaultValue) {
  // 'a.b[0].c'      → ['a','b','0','c']
  // "a['b-c'].d"    → ['a','b-c','d']  （带引号的中括号也要支持）
  const keys = Array.isArray(path)
    ? path
    : path
        .replace(/\[["']?([^"'\]]+)["']?\]/g, '.$1') // 中括号统一成点号
        .split('.')
        .filter(Boolean);                            // 去掉空段（如 'a..b'）

  let cur = obj;
  for (const key of keys) {
    if (cur === null || cur === undefined) return defaultValue; // 中途断链短路
    cur = cur[key];
  }
  return cur === undefined ? defaultValue : cur;    // 只把 undefined 视为「取不到」
}

// deepGet({ a: { b: [0, { c: 1 }] } }, 'a.b[1].c')  → 1
// deepGet({ a: null }, 'a.b.c', 'x')                → 'x'
// deepGet({ a: 0 }, 'a', 'x')                       → 0   ← 假值不被吞
```

**必须覆盖的边界**：

- 中途 `null`/`undefined` 必须短路，绝不能让它变成 `TypeError: Cannot read properties of null`。
- 默认值只在结果为 `undefined` 时生效；`0`、`''`、`false`、`null` 都是合法值，不能返回默认值。
- 路径数组与字符串两种签名都要支持（lodash `get` 的兼容点）。
- 中括号里是字符串键（`a['b-c']`）或数字（`a[0]`）都要能解析。
- 键名本身含点号（`{'a.b': 1}`）无法用字符串路径表达，要提示改用数组路径——这是这个 API 的固有局限。

**追问链**：

1. `cur?.[key]` 可选链能替代吗？→ 只能替代取值，替代不了「路径字符串解析」和「默认值统一出口」；而且可选链在 `a?.b.c` 中只保护了 `a` 这一层。
2. 为什么不用 `eval`/`new Function` 解析路径？→ 有注入风险（路径来自用户输入时）、CSP 下被禁、性能也未必更好。
3. 数组越界返回什么？→ `undefined` → 触发默认值，这是符合直觉的；若业务要区分「越界」和「值为 undefined」，要返回 `{found, value}` 结构。
4. 深层 set 怎么配合？→ 见 [HW-099] 的 `setIn`，两者路径解析可以共用同一个 `toPath` 工具。

### 精讲 6 · [HW-120] 循环安全遍历器：WeakSet 栈式防环

**为什么考这个**：只要写过「把整个 state 树打平做埋点/日志/校验」就会遇到环。多数人第一反应是「用 Set 记住访问过的对象」，但那是**全局去重**语义，会让「同一个对象在两个分支出现」只被访问一次——数据统计就错了。正确做法是「栈式防环 + 回溯弹出」。

**标准实现**：

```javascript
function walkSafe(root, { visit = () => {}, maxDepth = Infinity } = {}) {
  const onStack = new WeakSet();                 // 只记录「当前 DFS 路径上」的对象
  const stats = { nodes: 0, maxDepth: 0, circular: 0 };

  function dfs(value, path, depth) {
    stats.nodes++;
    stats.maxDepth = Math.max(stats.maxDepth, depth);
    visit(value, path, depth);

    // 叶子 / 超过深度限制：不再下钻
    if (value === null || typeof value !== 'object' || depth >= maxDepth) return;

    if (onStack.has(value)) {                    // 在当前路径上又遇到自己 → 成环
      stats.circular++;
      visit(value, `${path} <circular>`, depth); // 显式标记，便于排查
      return;                                    // 关键：return，不继续下钻
    }

    onStack.add(value);
    try {
      if (Array.isArray(value)) {
        value.forEach((v, i) => dfs(v, `${path}[${i}]`, depth + 1));
      } else {
        for (const [k, v] of Object.entries(value)) {
          dfs(v, path ? `${path}.${k}` : k, depth + 1);
        }
      }
    } finally {
      onStack.delete(value);                     // 回溯：出栈，允许其他分支再次访问
    }
  }

  dfs(root, '', 0);
  return stats;
}
```

**必须覆盖的边界**：

- `onStack.delete` 必须放在 `finally` 里，否则 `visit` 抛错会让后续兄弟分支被误判成环。
- 环的判定要在「下钻前」做，且命中环后必须 `return`，否则无限递归。
- 深度限制与环检测是两个独立开关：`maxDepth` 用于截断超深树（如 DOM 式结构）。
- 访问路径拼接要区分数组下标 `[0]` 与对象键 `.k`，否则日志无法直接复制成 JS 表达式。
- `WeakSet` 只能存对象，原始值要先做类型判断再 `has`，否则会抛错。

**追问链**：

1. 用 `WeakSet` 而不是 `Set` 的理由？→ 遍历结束后不阻止对象被 GC；遍历大对象图时不会造成内存泄漏。
2. 全局 `visited` 和「栈上」有什么区别？→ 全局是「每个节点访问一次」（图遍历），栈上是「每条路径不重复」（树遍历）。JSON 深拷贝要的是后者，结构统计/去重可能要前者。
3. 环在 JSON 里长什么样？→ JSON 无法表示环，`JSON.stringify` 会抛 `Converting circular structure to JSON`；必须靠 `replacer` 里的 `WeakSet` 手动替换成 `"[Circular]"`。
4. 如何只遍历不递归（超大对象）？→ 把 `dfs` 改成显式栈 + 迭代，同时 `onStack` 要换成「进入/离开」两个事件，或改用全局 `visited` 做图遍历。

### [HW-017] 浅比较

```javascript
function shallowEqual(a, b) {
  if (Object.is(a, b)) return true;                       // 同引用；顺带处理 NaN 与 ±0
  if (a === null || b === null) return false;
  if (typeof a !== 'object' || typeof b !== 'object') return false;
  const ka = Object.keys(a), kb = Object.keys(b);
  if (ka.length !== kb.length) return false;              // 数量不同直接剪枝
  return ka.every(k => Object.hasOwn(b, k) && Object.is(a[k], b[k]));
}
```

边界：只比第一层，嵌套对象引用不同即 `false`——这正是 `PureComponent` 的语义，也是「不可变更新」必须存在的原因。用 `Object.is` 而非 `===`，是为了让 `NaN` 相等、`+0/-0` 不等。

### [HW-021] LRU 缓存

```javascript
class LRUCache {
  constructor(capacity) {
    if (!Number.isInteger(capacity) || capacity < 1) throw new RangeError('capacity >= 1');
    this.capacity = capacity;
    this.map = new Map();                 // Map 保持插入顺序，队头 = 最久未使用
  }
  get(key) {
    if (!this.map.has(key)) return -1;
    const val = this.map.get(key);
    this.map.delete(key);                 // 删了再插 = 移到队尾（最新）
    this.map.set(key, val);
    return val;
  }
  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    else if (this.map.size >= this.capacity) {
      this.map.delete(this.map.keys().next().value); // 淘汰队头
    }
    this.map.set(key, value);
  }
}
```

边界：`get`/`put` 都必须是 O(1)；`put` 已存在的 key 也要「刷新热度」，不能只更新值。追问「不用 Map 怎么写」→ 哈希表 + 双向链表哨兵，命中摘节点挂尾，淘汰删 `head.next`。

### [HW-023] 数组扁平化（带 depth）

```javascript
function flatten(arr, depth = Infinity) {
  if (depth <= 0) return arr.slice();                     // 用尽深度：返回副本，不污染入参
  return arr.reduce(
    (acc, v) => acc.concat(Array.isArray(v) ? flatten(v, depth - 1) : v),
    []
  );
}
```

边界：`depth` 语义是「展开几层」，`flatten([[1]], 1)` → `[1]`；深度用尽时必须 `slice()` 拷贝，否则返回原引用会被调用方误改。

### [HW-024] 多维去重（保留嵌套结构）

```javascript
function dedupDeep(arr) {
  const primitives = new Set();     // 基础值判重（SameValueZero：NaN 相等）
  const objects = new Set();        // 对象按「序列化 + 类型」判重
  const walk = list => {
    const out = [];
    for (const item of list) {
      if (Array.isArray(item)) {
        const inner = walk(item);
        if (inner.length) out.push(inner);   // 全被去光的空组直接丢弃
        continue;
      }
      const isObj = item !== null && typeof item === 'object';
      const key = isObj ? `obj:${JSON.stringify(item)}` : `prim:${typeof item}:${item}`;
      const bucket = isObj ? objects : primitives;
      if (bucket.has(key)) continue;
      bucket.add(key);
      out.push(item);
    }
    return out;
  };
  return walk(arr);
}
```

边界：`Set` 对对象是引用比较，两个内容相同的对象不会去重，所以对象要走序列化；序列化的坑是「键顺序不同则不等」「无法处理循环引用」「`undefined`/函数会被丢」。面试时主动说出这三条，比代码本身加分。

### [HW-026] 两数组合并有序

```javascript
function mergeSorted(a, b, compare = (x, y) => x - y) {
  const out = [];
  let i = 0, j = 0;
  while (i < a.length && j < b.length) {
    if (compare(a[i], b[j]) <= 0) out.push(a[i++]);  // <= 保证稳定性：相等取前者
    else out.push(b[j++]);
  }
  return out.concat(a.slice(i), b.slice(j));         // 收尾：把没走完的整段接上
}
```

边界：`O(m+n)`；漏掉尾部拼接是最高频错误。LeetCode 88 变体（`nums1` 尾部预留空间）要从后往前双指针原地写，避免覆盖未比较元素。

### [HW-029] 洗牌（Fisher-Yates）

```javascript
function shuffle(arr) {
  const a = arr.slice();                          // 不改入参
  for (let i = a.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1)); // 0..i，含 i 自身交换
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a;
}
```

边界：每个排列等概率 `1/n!`；必须能指出 `sort(() => Math.random() - 0.5)` 是错的——比较函数不满足传递性，分布依赖具体排序实现，V8 上明显不均。

### [HW-053] chunk 分组

```javascript
function chunk(arr, size = 1) {
  if (!Number.isInteger(size) || size < 1) throw new RangeError('size must be positive integer');
  const out = [];
  for (let i = 0; i < arr.length; i += size) out.push(arr.slice(i, i + size));
  return out;                                     // 最后一组自动截短
}
```

边界：`size = 0` 会死循环，必须拦截；空数组返回 `[]`；`size > length` 返回单组。追问「大数组流式」→ 生成器 `function*` 逐组 `yield`，避免一次性复制。

### [HW-054] 对象深层合并

```javascript
const isPlainObject = v =>
  v !== null && typeof v === 'object' && !Array.isArray(v) &&
  (Object.getPrototypeOf(v) === Object.prototype || Object.getPrototypeOf(v) === null);

function deepMerge(target, ...sources) {
  const out = { ...target };                      // 不修改 target
  for (const src of sources) {
    if (!isPlainObject(src)) continue;
    for (const key of Object.keys(src)) {
      const sv = src[key];
      if (sv === undefined) continue;             // 约定：undefined 不覆盖（可配置）
      out[key] = isPlainObject(sv) && isPlainObject(out[key])
        ? deepMerge(out[key], sv)                 // 两边都是纯对象：递归
        : sv;                                     // 数组/原始值：直接覆盖
    }
  }
  return out;
}
```

边界：数组默认整体覆盖（lodash `merge` 会按下标合并，语义不同，要先声明约定）；只对「纯对象」递归，`Date`/`Map`/class 实例不能被拆成普通对象；`__proto__` 键要做防护，避免原型污染。

### [HW-118] deepFreeze

```javascript
function deepFreeze(obj) {
  if (obj === null || typeof obj !== 'object' || Object.isFrozen(obj)) return obj;
  Object.freeze(obj);                                   // 先冻结自己（幂等，可提前退出）
  for (const key of Reflect.ownKeys(obj)) {
    deepFreeze(obj[key]);                               // 再递归子属性
  }
  return obj;
}
```

边界：`Object.isFrozen` 检查让重复调用变 O(1) 且防重复遍历；只冻结「可写」对象，`Map`/`Set` 的内部内容 `freeze` 管不住（要额外包一层 proxy 或约定只读）。性能代价：冻结后写入抛错（严格模式）便于开发期暴露 bug，但 V8 对冻结对象有 deopt 成本，热路径上的大数组不要冻。

## 常见扣分点

| 扣分点 | 后果 | 正确做法 |
|---|---|---|
| 深拷贝不处理循环引用 | 栈溢出 / 死循环 | `WeakMap` 记录，且 `set` 在递归之前 |
| `seen.set` 放在 `for` 循环之后 | 自引用属性仍然爆栈 | 建完壳立刻登记 |
| 用 `Object.keys` 遍历 | 漏 `Symbol` 键、漏不可枚举属性 | `Reflect.ownKeys` + 描述符判断 |
| `Map`/`Set` 当普通对象拷 | 拷出空容器，`size` 为 0 | 单独 `instanceof` 分派 |
| `JSON.stringify` 判等对象 | 键顺序敏感、环抛错、`undefined` 丢失 | 排序键或改用稳定序列化 |
| `setIn` 里做全量深拷 | 结构共享失效，memo 全失效 | 每层只 `slice()` / `{...}` 一次 |
| `flatten` 递归处理未知深度 | 深嵌套栈溢出 | 显式栈（游标帧）迭代 |
| `shuffle` 用 `sort(random)` | 分布不均，洗牌有偏 | Fisher-Yates，`j ∈ [0, i]` |
| `chunk` 不校验 `size` | `size=0` 死循环卡死页面 | 抛 `RangeError` |
| `deepMerge` 允许 `__proto__` 键 | 原型污染（安全漏洞） | 跳过 `__proto__`/`constructor`/`prototype` |
| 深拷贝函数 | 闭包被复制，行为诡异 | 返回原引用 |
| `deepGet` 用 `!cur` 判断 | `0`/`''`/`false` 被当成取不到 | 只判 `=== undefined` |
