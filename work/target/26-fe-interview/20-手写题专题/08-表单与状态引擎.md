# 08 表单与状态引擎

> 表单题是「业务深度」的照妖镜。**能力分层**：L1 能写规则 → L2 能写联动与异步 → L3 能把表单抽象成引擎。

表单看起来是 CRUD 里最简单的一环，实际上是前端最难的几块交集：**校验的异步性、字段间的依赖、用户输入的时序、草稿与服务器版本的一致性**。面试官出这类题，通常不是要你写一个能跑的 `validate()`，而是要看你有没有被真实表单坑过——「异步校验回来的顺序反了」「联动把用户刚填的值清空了」「恢复草稿覆盖了服务端更新的内容」，这三句话能接上，基本就过关了。

本专题按「规则 → 引擎 → 图」的递进组织：先能写声明式规则，再能调度异步与联动，最后能把它抽象成由 schema 驱动的引擎。

## 能力分层

## 精讲（6 题）

### 精讲 1 · [HW-069] 声明式表单校验引擎

**为什么考这个**：这是表单题的母题。`if (!value) return '必填'` 是写业务，声明式规则 + 联动 + 异步去抖是写引擎。面试官追问「异步校验回来的顺序反了怎么办」，就是要看你有没有竞态意识。

**标准实现**：
```javascript
class FormEngine {
  constructor(rules, { debounce = 300 } = {}) {
    this.rules = rules;        // { field: [{ test, message, deps?, async?, when? }] }
    this.values = {};
    this.errors = {};          // field -> message
    this.seq = new Map();      // field -> 异步校验序号（竞态丢弃）
    this.timers = new Map();
    this.pending = new Map();  // field -> 在途异步校验
    this.debounce = debounce;
    this.listeners = new Set();
  }

  subscribe(fn) { this.listeners.add(fn); return () => this.listeners.delete(fn); }
  #notify() { for (const fn of this.listeners) fn({ ...this.errors }); }

  setValue(field, value) {
    this.values[field] = value;
    this.validateField(field);                        // 改谁校验谁
    for (const dep of this.#dependentsOf(field)) {    // 联动：依赖它的字段一起重校验
      if (dep !== field) this.validateField(dep);
    }
  }

  #dependentsOf(changed) {
    return Object.keys(this.rules).filter((f) =>
      (this.rules[f] || []).some((r) => r.deps?.includes(changed)));
  }

  validateField(field, { immediate = false } = {}) {
    const list = this.rules[field] || [];
    for (const r of list) {                  // ① 同步规则全过，才轮到异步
      if (r.async) continue;
      if (r.when && !r.when(this.values)) continue;    // 条件规则
      const out = r.test(this.values[field], this.values);  // 传全量 values = 天然支持联动
      if (out !== true) {
        this.#setError(field, typeof out === 'string' ? out : r.message);
        return false;
      }
    }
    this.#clearError(field);

    const asyncRules = list.filter((r) => r.async && (!r.when || r.when(this.values)));
    if (asyncRules.length) this.#runAsync(field, asyncRules, immediate);
    return true;
  }

  #runAsync(field, rules, immediate) {
    clearTimeout(this.timers.get(field));
    const seq = (this.seq.get(field) || 0) + 1;
    this.seq.set(field, seq);
    const run = async () => {
      for (const r of rules) {
        const ok = await r.test(this.values[field], this.values);
        if (this.seq.get(field) !== seq) return;       // 过期响应直接丢（竞态）
        if (!ok) { this.#setError(field, r.message); return; }
      }
      if (this.seq.get(field) === seq) this.#clearError(field);
    };
    const p = immediate ? run() : new Promise((resolve) => {
      this.timers.set(field, setTimeout(() => {
        this.timers.delete(field);
        run().then(resolve);
      }, this.debounce));
    });
    this.pending.set(field, p);
  }

  async validateAll() {                      // 提交：全量校验 + 聚合 + 定位首个错误
    const fields = Object.keys(this.rules);
    for (const f of fields) this.validateField(f, { immediate: true });
    await Promise.all([...this.pending.values()]);
    const invalid = fields.filter((f) => this.errors[f]);
    return { valid: invalid.length === 0, errors: { ...this.errors }, focusField: invalid[0] ?? null };
  }

  #setError(field, msg) {
    if (this.errors[field] === msg) return;
    this.errors[field] = msg; this.#notify();
  }
  #clearError(field) {
    if (!(field in this.errors)) return;
    delete this.errors[field]; this.#notify();
  }
}

// ===== 可运行验证：联动 + 异步唯一性 =====
(async () => {
  const engine = new FormEngine({
    username: [{ async: true, message: '用户名已存在',
      test: async (v) => { await new Promise((r) => setTimeout(r, 5)); return v !== 'admin'; } }],
    password: [{ message: '密码至少 6 位',
      test: (v) => (typeof v === 'string' && v.length >= 6) || '密码至少 6 位' }],
    confirm: [{ deps: ['password'], message: '两次不一致',
      test: (v, all) => v === all.password || '两次不一致' }],
  }, { debounce: 0 });

  engine.setValue('password', '123456');        // 触发 confirm 重校验（confirm 还是空）
  console.log('联动后 confirm:', engine.errors.confirm);   // 两次不一致
  engine.setValue('confirm', '123456');
  console.log('修正后 confirm:', engine.errors.confirm);   // undefined

  engine.setValue('username', 'admin');
  console.log(await engine.validateAll());
  // { valid: false, errors: { username: '用户名已存在' }, focusField: 'username' }
})();
```

**必须覆盖的边界**：

- **同步先于异步**：格式都不对就别发唯一性请求，否则浪费一次网络；同步全过才进异步校验。
- **异步竞态**：快速输入 `a`→`ab` 时 `a` 的响应可能后到，必须用序号丢弃，否则新值被旧错误覆盖。
- **异步去抖**：每敲一个字符发一次唯一性校验，等于自己给自己做压测；默认 300ms 去抖。
- **联动重校验**：改 `password` 必须重校验 `confirm`，靠 `deps` 声明反查依赖方，而不是硬编码字段名。
- **提交时聚合**：`validateAll` 必须等所有异步完成，并返回首个错误字段用于聚焦。
- **规则异常**：`test` 抛错时不能整张表单崩掉，要兜成「校验失败」而不是白屏。

**追问链**：

1. **为什么规则要拿到全量 `values`？** → 「确认密码」这类规则本质是跨字段谓词，只给单值就写不了；传全量还让「条件规则（when）」成为可能。
2. **错误消息存哪？** → 引擎里存 `field -> message` 的扁平表，UI 层按字段订阅；不要存在 values 里，否则提交时会把错误一起发给后端。
3. **异步校验结果要不要缓存？** → 同一值重复校验可缓存（值变了才失效），否则用户来回切焦点会重复打接口。
4. **和 UI 框架怎么解耦？** → 引擎只管值、规则、错误和订阅；React 侧用 `useSyncExternalStore` 订阅，Vue 侧把 errors 包成 reactive，引擎本身不依赖框架。

### 精讲 2 · [HW-070] 迷你 JSON Schema 校验器

**为什么考这个**：它考的是**递归 + 错误路径**。看起来简单，但「类型错时该不该继续往下校验」「数组下标怎么拼路径」「可选字段缺失要不要报错」这三处，能立刻分出写过和没写过的人。

**标准实现**：
```javascript
const TYPES = {
  string: (v) => typeof v === 'string',
  number: (v) => typeof v === 'number' && Number.isFinite(v),
  integer: (v) => Number.isInteger(v),
  boolean: (v) => typeof v === 'boolean',
  object: (v) => v !== null && typeof v === 'object' && !Array.isArray(v),
  array: (v) => Array.isArray(v),
  null: (v) => v === null,
};

function validate(value, schema, path = '#') {
  const errors = [];
  const types = schema.type ? [].concat(schema.type) : [];

  if (types.length && !types.some((t) => TYPES[t]?.(value))) {
    // 类型不符直接返回：避免 string 规则吃到 number 报出莫名其妙的错
    const actual = value === null ? 'null' : Array.isArray(value) ? 'array' : typeof value;
    return [`${path} 期望 ${types.join('|')}，实际 ${actual}`];
  }
  if (schema.enum && !schema.enum.includes(value)) errors.push(`${path} 不在枚举内`);

  if (typeof value === 'string') {
    if (schema.minLength != null && value.length < schema.minLength) errors.push(`${path} 长度不足 ${schema.minLength}`);
    if (schema.maxLength != null && value.length > schema.maxLength) errors.push(`${path} 长度超过 ${schema.maxLength}`);
    if (schema.pattern && !schema.pattern.test(value)) errors.push(`${path} 不匹配 ${schema.pattern}`);
  }
  if (typeof value === 'number') {
    if (schema.minimum != null && value < schema.minimum) errors.push(`${path} 小于 ${schema.minimum}`);
    if (schema.maximum != null && value > schema.maximum) errors.push(`${path} 大于 ${schema.maximum}`);
  }
  if (TYPES.array(value)) {
    if (schema.minItems != null && value.length < schema.minItems) errors.push(`${path} 元素少于 ${schema.minItems}`);
    if (schema.items) value.forEach((item, i) => errors.push(...validate(item, schema.items, `${path}[${i}]`)));
  }
  if (TYPES.object(value)) {
    for (const key of schema.required ?? []) {
      if (!(key in value)) errors.push(`${path}.${key} 缺少必填`);
    }
    for (const [key, sub] of Object.entries(schema.properties ?? {})) {
      if (!(key in value)) continue;          // 可选字段缺失跳过，required 已单独处理
      errors.push(...validate(value[key], sub, `${path}.${key}`));
    }
    if (schema.additionalProperties === false) {
      const allowed = new Set(Object.keys(schema.properties ?? {}));
      for (const key of Object.keys(value)) if (!allowed.has(key)) errors.push(`${path}.${key} 不允许的字段`);
    }
  }
  return errors;
}

// ===== 可运行验证 =====
const userSchema = {
  type: 'object',
  required: ['name', 'tags'],
  properties: {
    name: { type: 'string', minLength: 2 },
    age: { type: 'integer', minimum: 0, maximum: 150 },
    tags: { type: 'array', minItems: 1, items: { type: 'string', minLength: 1 } },
    profile: { type: ['object', 'null'], properties: { city: { type: 'string' } } },
  },
};
console.log(validate({ name: 'A', age: 200, tags: ['ok', ''], profile: null }, userSchema));
// [ '#.name 长度不足 2', '#.age 大于 150', '#.tags[1] 长度不足 1' ]
```

**必须覆盖的边界**：

- **类型不符立即返回**：继续往下跑会得到「长度不足」这种误导性错误，用户改不动。
- **`null` 不是 object**：`typeof null === 'object'` 是 JS 的著名坑，`TYPES.object` 必须显式排除。
- **`NaN/Infinity` 不算 number**：`typeof NaN === 'number'`，必须用 `Number.isFinite` 兜。
- **数组路径带下标**：`#.tags[1]` 才能定位到具体元素，UI 才能高亮那一行。
- **`required` 与 `properties` 分离**：required 只检查「存在」，类型规则只检查「存在时的合法性」，否则必填字段会报两条。
- **多类型**：`type: ['object','null']` 要 some 匹配，不能只取第一个。

**追问链**：

1. **递归的终止条件是什么？** → 没有 `properties` / `items` 时自然终止；再加一条「类型不符立即返回」，避免对错误类型的值继续递归。
2. **怎么支持 `$ref` 复用 schema？** → 先建 `definitions` 表，遇到 `$ref` 时查表替换，并用 visited 集合防循环引用。
3. **错误信息要不要国际化？** → 校验器只产出结构化错误 `{ path, rule, params }`，文案在 UI 层用 i18n 渲染，否则引擎无法复用。
4. **性能瓶颈在哪？** → 深层嵌套 + 大数组的 `forEach` 递归；表单场景一般没压力，接口返回值校验才需要抖一层缓存。

### 精讲 3 · [HW-104] 草稿自动保存（防抖 + 脏检查 + 版本恢复）

**为什么考这个**：这是「用户价值」最直接的题——写了两千字的长文，刷新一下没了。面试官想听的不是 `localStorage.setItem`，而是「多久存一次、存不存得下、恢复时怎么不覆盖新数据」。

**标准实现**：
```javascript
function createDraftStore({ storage, key = 'draft', debounceMs = 1000, versions = 5 } = {}) {
  const histKey = `${key}:history`;
  let timer = null;
  let lastSaved = storage.get(key) ?? null;    // 脏检查基线

  const serialize = (values) => JSON.stringify(values);

  function saveNow(values, { history = false } = {}) {
    const cur = serialize(values);
    if (cur === lastSaved) return false;               // 脏检查：没变不写，省配额省 IO
    if (history) {
      const hist = JSON.parse(storage.get(histKey) ?? '[]');
      hist.push({ at: Date.now(), data: cur });
      storage.set(histKey, JSON.stringify(hist.slice(-versions)));   // 只留最近 N 份
    }
    storage.set(key, cur);
    lastSaved = cur;
    return true;
  }

  return {
    schedule(values) {                     // 输入时调用：防抖落盘
      clearTimeout(timer);
      timer = setTimeout(() => { timer = null; saveNow(values); }, debounceMs);
    },
    flush(values) {                        // 提交前/卸载前：立刻落盘并留历史
      if (timer) { clearTimeout(timer); timer = null; }
      return saveNow(values, { history: true });
    },
    restore() {                            // 恢复：只返回数据，是否覆盖由调用方决定
      const raw = storage.get(key);
      return raw ? JSON.parse(raw) : null;
    },
    history() { return JSON.parse(storage.get(histKey) ?? '[]'); },
    clear() { storage.delete(key); storage.delete(histKey); lastSaved = null; },
    get pending() { return timer !== null; },
  };
}

// ===== 可运行验证（用 Map 代替 localStorage）=====
(async () => {
  const storage = new Map();
  const drafts = createDraftStore({ storage, key: 'draft:order', debounceMs: 20, versions: 3 });

  drafts.schedule({ remark: 'a' });
  drafts.schedule({ remark: 'ab' });          // 20ms 内多次修改只落最后一次
  await new Promise((r) => setTimeout(r, 40));
  console.log('落盘', storage.get('draft:order'));            // {"remark":"ab"}

  console.log('无变化再存', drafts.flush({ remark: 'ab' }));   // false（脏检查生效）
  console.log('有变化再存', drafts.flush({ remark: 'abc' }));  // true
  drafts.flush({ remark: 'abcd' });                            // 再进一条历史
  console.log('历史条数', drafts.history().length);            // 2
  console.log('恢复', drafts.restore());                       // { remark: 'abcd' }
  drafts.clear();
  console.log('清空后', drafts.restore());                     // null
})();
```

**必须覆盖的边界**：

- **防抖而非节流**：输入过程中连续写 localStorage 会阻塞主线程（同步 IO），防抖保证停顿 1s 才写一次。
- **脏检查**：序列化后与上次比对，无变化直接返回；否则打开页面什么都不做也在狂写配额。
- **卸载兜底**：`beforeunload` / `pagehide` 时 `flush`，浏览器可能不给异步时间，必须同步写。
- **配额**：localStorage 只有 5MB 左右，大文本应降级到 IndexedDB（HW-107/335），并做 `QuotaExceededError` 捕获。
- **多标签冲突**：两个 tab 编辑同一表单会互相覆盖，需要 `storage` 事件或版本号比对。
- **恢复不自动覆盖**：服务端 `updated_at` 比草稿新时，必须让用户二选一（本地草稿 / 服务器版本），静默覆盖是数据事故。

**追问链**：

1. **为什么用 localStorage 不用 sessionStorage？** → sessionStorage 关标签即失，草稿的语义是「跨会话恢复」；但草稿含敏感信息时应用 sessionStorage 或加密后再落盘。
2. **防抖 1s 会不会丢数据？** → 极端情况（写完立刻崩溃）会丢最后 1s；所以还要在 `pagehide` 做同步 flush，两者互补。
3. **版本栈怎么用？** → 用户点「恢复上一版」时按历史逐条回填；注意历史条目要带时间戳，否无法让用户判断选哪个。
4. **怎么和服务端草稿同步？** → 本地为快，服务端为准；提交时先拉服务端版本号比对，冲突则弹选择框，不能直接后写覆盖。

### 精讲 4 · [HW-119] Proxy 表单字段代理（脏标记 + 嵌套路径）

**为什么考这个**：`useState` 管一个字段还行，二十个字段就是二十个 `onChange`。Proxy 表单考的是「你懂不懂把重复劳动下沉到语言能力上」，同时顺带考 `Proxy` 的 `get/set` 陷阱——尤其嵌套对象和数组。

**标准实现**：
```javascript
const getPath = (obj, path) =>
  path.split('.').reduce((o, k) => (o == null ? o : o[k]), obj);

function reactiveForm(initial, { onChange } = {}) {
  const snapshot = structuredClone(initial);   // 初始快照，reset 用
  const dirty = new Set();                     // 脏字段路径
  const visited = new Set();                   // 被读过的路径（按字段订阅/重渲染）
  const cache = new WeakMap();                 // 同一对象复用同一 Proxy：身份稳定

  const wrap = (obj, path = '') => {
    if (obj === null || typeof obj !== 'object') return obj;
    if (cache.has(obj)) return cache.get(obj);

    const proxy = new Proxy(obj, {
      get(target, key) {
        if (typeof key === 'symbol') return target[key];      // 放过 Symbol（迭代器）
        const full = path ? `${path}.${key}` : String(key);
        visited.add(full);
        return wrap(target[key], full);                       // 惰性递归代理
      },
      set(target, key, value) {
        const isArr = Array.isArray(target);
        // 数组的 push/splice 会写下标和 length：统一归一化到数组字段本身
        const full = isArr ? path : path ? `${path}.${key}` : String(key);
        if (!isArr && Object.is(target[key], value)) return true;  // 同值不算脏
        target[key] = value;
        // 一次 push 会先写 index 再写 length，按路径去重后只通知一次
        if (!dirty.has(full)) {
          dirty.add(full);
          onChange?.(full, value, [...dirty]);
        }
        return true;
      },
      deleteProperty(target, key) {
        dirty.add(path ? `${path}.${key}` : String(key));
        return delete target[key];
      },
    });
    cache.set(obj, proxy);
    return proxy;
  };

  const state = wrap(initial);

  return {
    state,
    get dirty() { return [...dirty]; },
    get visited() { return [...visited]; },
    diff() {                                   // 只提交脏字段（扁平路径），省流量
      return Object.fromEntries([...dirty].map((p) => [p, getPath(initial, p)]));
    },
    reset() {
      for (const k of Object.keys(initial)) delete initial[k];
      Object.assign(initial, structuredClone(snapshot));
      dirty.clear(); visited.clear();
    },
  };
}

// ===== 可运行验证 =====
const form = reactiveForm({ user: { name: '', tags: [] }, agree: false },
  { onChange: (p) => console.log('脏 ->', p) });

form.state.user.name = 'Ada';        // 嵌套写入
form.state.agree = true;
form.state.agree = true;             // 同值不脏
form.state.user.tags.push('vip');    // 数组变更归一化到 user.tags
console.log('dirty', form.dirty);    // [ 'user.name', 'agree', 'user.tags' ]
console.log('diff', form.diff());    // { 'user.name': 'Ada', agree: true, 'user.tags': [ 'vip' ] }
form.reset();
console.log('reset 后', form.state.user.name, form.dirty);   // reset 后  []
```

**必须覆盖的边界**：

- **嵌套要递归代理**：只代理顶层对象时，`state.user.name = 'x'` 完全绕过 set 陷阱，脏标记全丢。
- **Proxy 要缓存**：每次 get 都 new 一个 Proxy，`state.user === state.user` 为 false，React 里会无限重渲染。
- **数组的 push/splice**：会写 `0` 和 `length` 两个键，不归一化会得到 `user.tags.0`、`user.tags.length` 这类垃圾路径。
- **同值不脏**：`Object.is` 比较，否则输入框把光标移到末尾再回来也会标脏。
- **通知要按路径去重**：一次 `push` 会触发 index 和 length 两次 set，不去重的话订阅者会被连打两枪。
- **Symbol 键**：`get(Symbol.iterator)` 也要代理会让 `for...of`/展开爆栈，直接透传。
- **reset 的语义**：恢复初始快照并清空脏集合，否则用户点「重置」后表单仍是脏的，提交按钮还亮着。

**追问链**：

1. **Proxy 与 Vue3 reactive 有什么差别？** → 思路相同，Vue 多了依赖收集（effect 级订阅）、`Reflect` 转发和数组/Map/Set 的特殊处理；这道题只需要「脏标记 + 通知」。
2. **为什么 `visited` 有用？** → 记录渲染期读过的字段，可做「按字段重渲染」；读得少说明渲染开销小，也是排查性能的抓手。
3. **`diff()` 为什么不用深比较？** → 写入时就记了脏路径，O(1) 收集；深比较是 O(n)，大表单上每次提交都做不起。
4. **能直接 `JSON.stringify(state)` 吗？** → 可以，Proxy 透传读写；但会触发所有字段的 get，把 visited 全污染，调试时注意。

### 精讲 5 · [HW-123] 多字段联动校验图（拓扑排序 + 环检测）

**为什么考这个**：当「B 的校验依赖 A 的值」这种关系有十几条时，手写调用顺序必然出错。这题考的是**依赖图**思维：拓扑分层、同层并行、环即配置错误。

**标准实现**：
```javascript
function buildGraph(fields) {
  const rev = new Map();                        // 依赖 -> 依赖它的字段（反向边）
  for (const [name, cfg] of Object.entries(fields)) {
    for (const dep of cfg.dependsOn ?? []) {
      if (!rev.has(dep)) rev.set(dep, []);
      rev.get(dep).push(name);
    }
  }
  return rev;
}

function topoLayers(fields) {                   // Kahn 分层：返回 [[层1], [层2], ...]
  const rev = buildGraph(fields);
  const indeg = new Map(Object.entries(fields).map(
    ([k, v]) => [k, (v.dependsOn ?? []).length]));
  let layer = [...indeg.keys()].filter((f) => indeg.get(f) === 0);
  const layers = [];
  let visited = 0;

  while (layer.length) {
    layers.push(layer);
    visited += layer.length;
    const next = [];
    for (const f of layer) {
      for (const d of rev.get(f) ?? []) {
        indeg.set(d, indeg.get(d) - 1);
        if (indeg.get(d) === 0) next.push(d);
      }
    }
    layer = next;
  }
  if (visited !== indeg.size) {                 // 有环：剩余入度不为 0 的就是环上节点
    const cyclic = [...indeg.keys()].filter((f) => indeg.get(f) > 0);
    throw new Error(`依赖成环: ${cyclic.join(', ')}`);
  }
  return layers;
}

async function validateByDAG(fields, values) {
  const layers = topoLayers(fields);
  const errors = {};
  for (const layer of layers) {                 // 逐层串行，层内并行
    await Promise.all(layer.map(async (name) => {
      const cfg = fields[name];
      if (cfg.when && !cfg.when(values)) return;          // 隐藏字段不校验
      const msg = await cfg.validate(values[name], values);
      if (msg) errors[name] = msg;
    }));
  }
  return { valid: Object.keys(errors).length === 0, errors };
}

// ===== 可运行验证 =====
(async () => {
  const fields = {
    password: { validate: (v) => (typeof v === 'string' && v.length >= 6 ? null : '密码至少 6 位') },
    confirm: { dependsOn: ['password'],
      validate: (v, all) => (v === all.password ? null : '两次不一致') },
    email: { dependsOn: ['confirm'],
      validate: async (v) => { await new Promise((r) => setTimeout(r, 2));
        return String(v).includes('@') ? null : '邮箱格式错误'; } },
  };
  console.log(await validateByDAG(fields, { password: '123456', confirm: '123456', email: 'a@b.c' }));
  // { valid: true, errors: {} }
  console.log(await validateByDAG(fields, { password: '123', confirm: '12', email: 'nope' }));
  // { valid: false, errors: { password: '密码至少 6 位', confirm: '两次不一致', email: '邮箱格式错误' } }

  try {
    topoLayers({ a: { dependsOn: ['b'] }, b: { dependsOn: ['a'] } });
  } catch (e) { console.log(e.message); }       // 依赖成环: a, b
})();
```

**必须覆盖的边界**：

- **拓扑序保证缓存正确**：`confirm` 必须在 `password` 校验完之后才读它的值，否则读到的是「上次的值」，校验结论不可信。
- **同层并行**：层与层之间必须串行（有依赖），层内无依赖可 `Promise.all`，这是性能关键。
- **环检测**：`visited < 总数` 说明有环，必须抛配置错误而不是死循环；报错要带出具体字段名。
- **依赖不存在的字段**：`dependsOn: ['nope']` 会让 `nope` 入度永远不进 0，结果被判成环——要先校验依赖名存在。
- **隐藏字段**：`when` 为假时跳过校验，但值仍保留在 values 里（提交时再 strip）。
- **层内异步失败**：`Promise.all` 遇一个 reject 会中断整层，规则内部要把异常兜成错误消息。

**追问链**：

1. **为什么不直接用 DFS 递归？** → DFS 也能算顺序，但难以做到「同层并行」；Kahn 分层天然给出并发批次，且环检测是副产品。
2. **复杂度多少？** → O(V+E)，每个字段的依赖边只扫一次；相比每次敲键全量重算，局部重算的收益在 50+ 字段的表单上非常明显。
3. **和 HW-281 的联动 DAG 有什么不同？** → 这题图的是「校验顺序」，281 图的是「值/可见性的传播」；同一个思想，两种用途。
4. **依赖成环能自动解开吗？** → 不能。环是配置错误（A 依赖 B 且 B 依赖 A），唯一正确做法是抛错让人改配置，自动截断会掩盖业务 bug。

### 精讲 6 · [HW-313] 表单校验引擎（规则注册表 + 异步去重 + abortEarly）

**为什么考这个**：前三题都在「实现一个点」，这题考「设计一套可扩展的校验器」。规则注册表让你加规则不改引擎，异步去重让同一值的并发校验只打一次接口——这两点直接对应生产可用性。

**标准实现**：
```javascript
const RULES = {
  required: (v) => v !== undefined && v !== null && v !== '',
  minLength: (v, { min }) => typeof v === 'string' && v.length >= min,
  pattern: (v, { re }) => re.test(v),
  sameAs: (v, { field }, ctx) => v === ctx[field],      // 依赖 context 里的其它字段
};

class Validator {
  constructor(schema) {
    this.schema = schema;        // { field: [{ type, params, message }] }
    this.inflight = new Map();   // field:value -> Promise（同值并发去重）
  }

  validateField(field, value, ctx = {}, { dedupe = true, abortEarly = true } = {}) {
    const key = `${field}:${JSON.stringify(value)}`;
    if (dedupe && this.inflight.has(key)) return this.inflight.get(key);   // 共享在途

    const p = this.#run(this.schema[field] ?? [], value, ctx, abortEarly)
      .finally(() => this.inflight.delete(key));       // 结束后清理，允许下次重校验
    if (dedupe) this.inflight.set(key, p);
    return p;
  }

  async #run(rules, value, ctx, abortEarly) {
    const errors = [];
    for (const r of rules) {
      const fn = RULES[r.type];
      const ok = await fn(value, r.params ?? {}, ctx);   // 规则可同步可异步
      if (!ok) {
        errors.push(r.message ?? `${r.type} 校验失败`);
        if (abortEarly) break;                           // 首错即停：blur 场景够用
      }
    }
    return { valid: errors.length === 0, errors };
  }

  async validateAll(values, { abortEarly = false } = {}) {
    const results = await Promise.all(Object.keys(this.schema).map((f) =>
      this.validateField(f, values[f], values, { abortEarly }).then((r) => [f, r])));
    const errors = {};
    for (const [f, r] of results) if (!r.valid) errors[f] = r.errors;
    return { valid: Object.keys(errors).length === 0, errors };
  }
}

// ===== 可运行验证 =====
(async () => {
  const v = new Validator({
    password: [{ type: 'required', message: '密码必填' },
               { type: 'minLength', params: { min: 6 }, message: '至少 6 位' }],
    confirm: [{ type: 'required', message: '请再输入一次' },
              { type: 'sameAs', params: { field: 'password' }, message: '两次不一致' }],
  });

  // 同字段同值并发：应共享同一个 Promise
  const [r1, r2] = await Promise.all([
    v.validateField('password', '123', {}),
    v.validateField('password', '123', {}),
  ]);
  console.log('是否同一结果', r1 === r2, r1.errors);       // true [ '至少 6 位' ]

  console.log(await v.validateAll({ password: '123456', confirm: '123456' }));
  // { valid: true, errors: {} }
  console.log(await v.validateAll({ password: '123456', confirm: 'x' }));
  // { valid: false, errors: { confirm: [ '两次不一致' ] } }
})();
```

**必须覆盖的边界**：

- **去重键必须含值**：只按字段去重，值变了还复用旧结果，会把「可用」误报成「已存在」。
- **去重必须清理**：`finally` 里删 key，否则这个值永久返回旧 Promise，用户改了再改回来也拿不到新结果。
- **abortEarly 分级**：blur 时首错即停（反馈快），submit 时全量收集（一次告诉用户所有问题）。
- **context 传递**：`sameAs` 需要读 `password`，所以必须把整份 values 作为 ctx 传下去。
- **规则缺失**：`RULES[r.type]` 未注册时要给出可读错误，不能 `undefined is not a function`。
- **异步规则超时**：唯一性接口卡住会拖住整个 validateAll，外层要配 `AbortSignal.timeout`。

**追问链**：

1. **为什么用注册表而不是 if/else？** → 加规则（手机号、身份证、异步唯一性）只注册函数，引擎零改动；也让规则可被业务方按需扩展。
2. **去重会不会掩盖错误？** → 不会，去重的是「同一个值」的重复计算；值变即新 key，语义安全。
3. **`abortEarly` 与全量校验怎么选？** → 交互态用 true（少打接口、快反馈），提交态用 false（一次给全）。
4. **怎么接进 UI？** → 引擎返回 `{ valid, errors }`，errors 按字段分组直接映射到表单项；不要返回扁平字符串数组，否则 UI 无法定位。

### 三类「表单题」的边界划分

面试时最容易混的是这三题，说清区别本身就是加分项：

| 题目 | 图什么 | 输出 | 关键风险 |
|---|---|---|---|
| HW-069 校验引擎 | 规则 + 依赖重校验 | 错误表 | 异步竞态、联动漏校验 |
| HW-123 校验图 | 校验的**执行顺序** | 分层后的错误表 | 依赖成环、层内串行化 |
| HW-281 联动引擎 | 值/可见性的**传播** | 新的 values 与可见集合 | 传播不收敛、清空用户输入 |

## 常见扣分点

| 扣分点 | 后果 | 正确做法 |
|---|---|---|
| 异步校验不做序号丢弃 | 旧值的结果覆盖新值，错误提示错乱 | 每字段维护 seq，回包比对 |
| 每个字段一个 `onChange` 手写 | 20 字段 20 份重复逻辑，联动全靠人记 | Proxy 代理 + deps 声明 |
| 校验规则里硬编码字段名 | 表单加字段就要改引擎 | 规则拿全量 values/ctx |
| 不做脏检查直接写 localStorage | 打开页面就狂写，配额很快耗尽 | 序列化比对后再写 |
| 草稿恢复静默覆盖表单 | 覆盖服务端新数据，用户白填 | 比对版本，让用户二选一 |
| Proxy 每次 get 都新建 | 引用不稳定，触发无限重渲染 | WeakMap 缓存 proxy |
| 拓扑排序不做环检测 | 循环依赖时死循环或漏校验 | Kahn 后校验 visited 数 |
| 数组变更记成 `tags.0` | 脏路径碎片化，diff 无法提交 | 归一化到数组字段本身 |
| 校验错误塞进 values | 错误随提交发给后端 | errors 单独一张表 |
| 隐藏字段仍参与校验 | 用户看不到错误却提交不了 | 可见性先算，再校验可见字段 |
