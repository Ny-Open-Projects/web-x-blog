# 手写题模拟卷（3 套）

> **用法**：一套卷 45 分钟，**白板（或纯文本编辑器，关掉补全）**写完。写完先自己报边界，再看评分表。
> **为什么要有手写模拟卷**：手写题的失分不是"不会写"，是"**来不及**"——20 分钟里想、写、报边界三件事挤在一起，练过和没练过差一倍时间。

## 评分口径（通用）

| 维度 | 权重 | 采分点 |
|---|---|---|
| 正确性 | 40% | 核心逻辑对，小例子能走通 |
| 边界覆盖 | 25% | 主动报出边界，不是等追问 |
| 代码质量 | 15% | 命名清晰、无冗余分支、`this`/`arguments` 处理对 |
| 追问应对 | 20% | 能答上 2 层追问，能说替代方案 |

**过关线**：4 题中 3 题"正确性 + 边界覆盖"双绿。**全部写完但边界一个没报 = 不通过。**

## 套卷一 · 基础必会（45 分钟）

### 第 1 题（10 min）· 手写 `Promise.all`

**必答边界**（写完主动说）：
- 空数组 → 立即 `resolve([])`
- 非 Promise 值 → 原样进入结果
- **结果按入参顺序，不是完成顺序**
- 任一 reject → 立即 reject，但其他请求不会被取消（要说明这点）

**参考骨架**：
```javascript
function myAll(promises) {
  return new Promise((resolve, reject) => {
    const arr = Array.from(promises);
    if (arr.length === 0) return resolve([]);
    const results = new Array(arr.length);
    let count = 0;
    arr.forEach((p, i) => {
      Promise.resolve(p).then((v) => {
        results[i] = v;                       // 按索引放
        if (++count === arr.length) resolve(results);
      }, reject);
    });
  });
}
```

**追问链**：
1. 要"任一失败也等其他完成"？→ `allSettled`，结果元素是 `{status, value/reason}`
2. 100 个请求限并发 5？→ `p-limit`，**完成一个补一个**，不是分批跑

**关联原卡**：[HW-002](../06-算法与手写/HW-002-手写-Promiseall.md)、[HW-004](../06-算法与手写/HW-004-手写-PromiseallSettled.md)

### 第 2 题（12 min）· 手写防抖（完整版）

**要求**：支持 `leading` / `trailing` / `cancel` / `flush`，`this` 与参数透传。

**必答边界**：
- 重复调用清旧 timer
- `leading` 只在本轮首次生效
- `cancel` 后不残留、不误触发
- `this` 与 `arguments` 要透传（不能用箭头函数接）

**追问链**：
1. 为什么不能用箭头函数？→ 没有自己的 `this`，拿不到调用方上下文
2. 防抖能返回结果吗？→ 异步无法同步返回，要 `flush()` 或改成返回 Promise
3. 滚动场景用防抖还是节流？→ 节流（要持续响应），输入框用防抖

**关联原卡**：[HW-014](../06-算法与手写/HW-014-手写防抖-含-immediate---cance.md)、[HW-115](../06-算法与手写/HW-115-手写-防抖的-Edge-Case-大合集.md)

### 第 3 题（13 min）· 手写深拷贝

**要求**：支持循环引用、`Date` / `RegExp` / `Map` / `Set`、`Symbol` 键、保留原型。

**必答边界**：
- 循环引用 → `WeakMap` 缓存
- 函数 → 不深拷，返回引用
- `Symbol` 键 → `Reflect.ownKeys`
- 原型链 → `Object.create(Object.getPrototypeOf(obj))`

**追问链**：
1. `structuredClone` 能替代吗？→ 能，但不支持函数、DOM 节点、自定义类原型、Symbol 键
2. `JSON.parse(JSON.stringify())` 五个坑？→ Date 变字符串 / `undefined`+函数丢失 / `NaN`→`null` / 循环引用抛错 / RegExp 变空对象
3. 性能代价？→ O(n) 全遍历；React 里用结构共享替代

**关联原卡**：[HW-016](../06-算法与手写/HW-016-手写深拷贝.md)、[HW-097](../06-算法与手写/HW-097-手写-深克隆升级版-循环引用与特殊对象.md)

---

### 第 4 题（10 min）· 手写 `p-limit`

**要求**：并发上限 5，任务完成立刻补位。

**必答边界**：
- **"完成一个补一个"，不是"分批跑"**（分批会让长任务拖慢整批）
- 任务抛错不能阻塞队列
- 无任务时不能空转

**追问**：如果任务有优先级？→ 队列改成小顶堆，取任务时按优先级取；注意"插队"只在有空位时生效。

**关联原卡**：[HW-007](../06-算法与手写/HW-007-手写-plimit-并发控制.md)、[HW-066](../06-算法与手写/HW-066-手写-优先级任务队列.md)

## 套卷二 · 工程实战（45 分钟）

### 第 1 题（10 min）· 手写 `EventEmitter`

**要求**：`on` / `once` / `off` / `emit`，支持链式。

**必答边界**：
- `emit` 时**拷贝监听器数组**（否则回调里 `off` 会让遍历错位）
- `once` 执行后自删
- 同名多次注册的处理（删一个还是全删？先问）
- 空监听时 `emit` 返回 `false`

**追问**：
1. Node 的 `error` 事件为什么特殊？→ 无监听时会直接抛错，防止被吞
2. 怎么支持通配符订阅 `on('user.*')`？→ 按 `.` 分段建树，或正则匹配（性能差）

**关联原卡**：[HW-020](../06-算法与手写/HW-020-手写-EventEmitter.md)、[HW-315](../06-算法与手写/HW-315-手写一个增强事件总线.md)

### 第 2 题（13 min）· 手写令牌桶限流器

**要求**：容量 10、每秒补 2 个，支持突发。

**必答边界**：
- **惰性补桶**（取令牌时按时间差补，不用 `setInterval`）
- 首次调用 `lastRefill` 初始化
- 桶满不溢出

**追问**：
1. 令牌桶 vs 漏桶？→ 前者允许突发（桶里攒着），后者输出恒定速率
2. 分布式怎么限流？→ 单机内存不行，要 Redis + Lua 保证原子性
3. 固定窗口的边界突刺怎么产生？→ 窗口交界处可能放过 2 倍流量

**关联原卡**：[HW-064](../06-算法与手写/HW-064-手写-令牌桶限流器.md)、[HW-084](../06-算法与手写/HW-084-手写-滑动窗口限流器.md)

---

### 第 3 题（12 min）· 手写 LRU

**要求**：`get` / `put` 均 O(1)。

**必答边界**：
- `get` 命中也要刷新顺序（这是最常漏的一步）
- 容量为 1、重复 `put` 同一个 key
- `put` 已存在的 key 要先删再插

**追问**：
1. 为什么必须双向链表？→ 删除任意节点要拿到前驱，单链表是 O(n)
2. `Map` 版为什么天然满足？→ 内部是哈希 + 插入序链表，`delete` + `set` 等于移到末尾
3. 要带 TTL 怎么办？→ 每个节点存过期时间，`get` 时惰性判断；或加一个按过期时间排序的最小堆

**关联原卡**：[HW-021](../06-算法与手写/HW-021-手写-LRU-缓存.md)、[HW-078](../06-算法与手写/HW-078-手写-TTL-惰性过期缓存.md)

### 第 4 题（10 min）· 手写请求去重合并器

**要求**：同 key 的并发请求共享同一个 Promise；请求结束后清理。

**必答边界**：
- **`finally` 里删除**，否则失败后永久缓存了 rejected Promise
- 并发 N 个请求只发 1 个
- 是否需要"微任务窗口内合批"（同一 tick 的请求合并）

**追问**：
1. 如果要做 SWR（先返回旧数据再后台刷新）？→ 缓存加时间戳，过期后返回旧值同时触发刷新
2. 取消怎么办？→ 引用计数，最后一个消费者取消时才真正 abort

**关联原卡**：[HW-079](../06-算法与手写/HW-079-手写-请求去重合并器.md)、[HW-087](../06-算法与手写/HW-087-手写-带缓存的异步函数.md)

## 套卷三 · 原理与设计（45 分钟）

### 第 1 题（10 min）· 手写 `useState`

**必答边界**：
- 用**调用顺序（下标）**定位状态
- 每次渲染前重置 `hookIndex`
- 相同值不触发渲染（`Object.is`）
- 支持函数式更新

**追问**：
1. 为什么 hook 不能写在条件/循环里？→ 顺序会错位，状态串位
2. 闭包陷阱怎么产生？→ `setState` 捕获了旧的 state 值，要用函数式更新 `setX(v => v + 1)`
3. `useEffect` 的依赖数组怎么比较？→ 浅比较（`Object.is` 逐项）

**关联原卡**：[HW-040](../06-算法与手写/HW-040-手写-React-useState.md)、[HW-042](../06-算法与手写/HW-042-手写-useEffect-简版.md)

---

### 第 2 题（15 min）· 手写 Vue reactive 核心

**要求**：`reactive` / `effect` / `track` / `trigger`。

**必答边界**：
- 嵌套对象 → `get` 时**惰性**代理
- 依赖存储三层结构：`Map<target, Map<key, Set<effect>>>`
- 用 `Set` 去重 effect（同一 effect 多次读同一属性）
- 用 `Reflect` 保证 receiver 正确

**追问**：
1. Proxy vs `defineProperty`？→ 前者能拦截新增/删除/数组索引；后者只能劫持已存在属性
2. 为什么需要 `Reflect`？→ 保证 `receiver` 正确、返回值语义一致
3. 循环依赖/递归触发怎么办？→ 加 `isRunning` 标记防重入

**关联原卡**：[HW-038](../06-算法与手写/HW-038-手写-Vue-reactive-核心.md)、[HW-039](../06-算法与手写/HW-039-手写-Vue-双向绑定-vmodel-简版.md)

### 第 3 题（10 min）· 手写定高虚拟列表

**必答边界**：
- 只渲染可视区 + 缓冲区
- 滚动用 `rAF` 合帧，一帧只算一次
- 用**占位撑开总高度**，否则滚动条长度不对
- 偏移用 `transform` 而不是 `top`（走合成层，不触发重排）

**追问**：
1. 快速滚动白屏怎么办？→ 锚点定位 + 双向缓冲 + 跳过中间渲染
2. 不定高怎么办？→ 预估 + 实测修正 + 缓存已测高度
3. 怎么验证不卡？→ Long Task 观测、掉帧率、Performance 面板

**关联原卡**：[HW-037](../06-算法与手写/HW-037-手写虚拟列表核心-定高.md)、[HW-067](../06-算法与手写/HW-067-手写-虚拟列表-滚动补偿与锚点.md)

### 第 4 题（10 min）· 设计表单校验引擎（讲接口，不写全）

**要求**：说清接口设计即可，不需要写完。

**采分核心**：
- 声明式规则：`{ required, min, max, pattern, validator }`
- 异步校验：去抖 + 竞态丢弃
- 联动校验：字段依赖图（A 变了要重校验 B）
- 错误聚合：`{ field: [errors] }`，全局 `isValid`

**参考接口**：
```javascript
const engine = createValidator({
  username: [
    { required: true, message: '必填' },
    { min: 3, max: 20, message: '3~20 字符' },
    { validator: checkUnique, debounce: 300, message: '已存在' },
  ],
  confirm: [
    { required: true },
    { validator: (v, all) => v === all.password || '两次密码不一致', deps: ['password'] },
  ],
});

await engine.validateField('username');
engine.validateAll();          // → { valid, errors }
```

**追问**：
1. 异步校验乱序返回怎么办？→ 每次校验带序号，只接受最新序号的结果
2. 依赖成环怎么办？→ 建图时做环检测，报配置错误
3. 大表单性能？→ 只校验变更字段 + 依赖链下游

**关联原卡**：[HW-069](../06-算法与手写/HW-069-手写-表单校验引擎-声明式规则.md)、[HW-123](../06-算法与手写/HW-123-手写-可控的多字段联动校验图.md)
