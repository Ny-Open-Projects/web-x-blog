## AGT-278：批处理 API（batch API）适合什么任务，怎么设计接入？

**答**:
- 批处理的价值：供应商提供非实时通道（24h 内完成）通常 5 折——适合一切"不急"的任务：离线评测（AGT-254 judge 批量跑）、索引与摘要生成、数据清洗、回归测试、夜间报表——把非实时任务迁到批处理通道是零质量损失的直接降本。
- 接入设计：任务队列区分实时/批量两类；批量任务拆分为独立请求（无相互依赖）打包提交，轮询或回调取结果；失败请求重提（批处理失败率略高，需幂等重试）。
- 混合场景：交互链路中的"可延后步骤"异步化——如答案生成实时（用户等着）、但答案的摘要存档/标签提取批量走（不阻塞用户）——同一功能内分通道。
- 成本核算：批处理省的钱 vs 队列基础设施与运维复杂度——量小（每天几百次）不值得建队列，量大（每天百万级）收益显著。

```javascript
// 批处理接入
async function enqueueBatch(jobs) {          // jobs: 离线任务
  const reqs = jobs.map(j => ({
    custom_id: j.id,                          // 幂等标识
    body: { model: j.model, messages: j.messages },
  }));
  const batch = await provider.batch.create({ requests: reqs });
  await db.save({ batchId: batch.id, jobIds: jobs.map(j => j.id) });
}
// 回调/轮询结果 → 按 custom_id 分发 → 失败重提（幂等）
```
