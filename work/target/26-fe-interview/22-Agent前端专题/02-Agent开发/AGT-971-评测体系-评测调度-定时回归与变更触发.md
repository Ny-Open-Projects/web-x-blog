## 971：评测什么时候跑：定时、变更触发怎么排

**答**：
- 触发三类：变更触发（prompt/模型/检索配置改动必跑核心集，卡门禁）、定时回归（每日夜间跑全量，抓「环境漂移」类退化——模型供应商悄悄更新也会退化）、事故触发（线上事故复盘后跑对应场景集验证修复）。
- 分级门禁：核心集（200 条，5 分钟）阻塞合并；全量集不阻塞只报告 + 周报汇总趋势。
- 评测排队与缓存：相同 (模型版本, 评测集版本, 配置 hash) 的结果缓存，避免重复跑浪费预算。
- 追问钩子：夜间全量挂了一直红怎么办？——区分「门禁红」（阻塞）与「观测红」（只告警），全量集挂了先看是不是环境问题（网络、配额）再定性为回归。

```ts
const triggers = {
  onChange: { files: ['prompts/**', 'retrieval.yml'], set: 'core', gate: true },
  nightly:  { cron: '0 3 * * *', set: 'full', gate: false },
  onIncident: { set: 'incident/<id>', gate: true },
};
async function scheduleEval(ev) {
  const key = hash([modelVer, evalVer(ev.set), configHash]);
  if (await cache.get(key)) return cache.get(key);   // 相同组合直接复用
  const r = await runEval(ev);
  await cache.set(key, r, '24h');
  return r;
}
```
