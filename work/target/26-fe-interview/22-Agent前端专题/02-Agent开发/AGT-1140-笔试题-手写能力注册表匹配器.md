## 1140：笔试手写：实现能力注册表的选择器（数据驱动）

**答**：实现 select(registry, cap, ctx)：registry 为 { [cap]: [{ name, status, stats: { passRate, costMs } }] }。规则：只考虑 status==='ok' 的实现；默认按 passRate 降序取第一；ctx.costSensitive 为 true 时按 passRate/costMs 综合分降序；无可实现抛 Error('no impl')；并列分数按名称字典序稳定。返回实现对象。

```js
function select(registry, cap, ctx = {}) {
  const impls = (registry[cap] || []).filter(i => i.status === 'ok');
  if (!impls.length) throw new Error('no impl: ' + cap);
  const score = ctx.costSensitive
    ? i => i.stats.passRate / i.stats.costMs
    : i => i.stats.passRate;
  return [...impls].sort((a, b) =>
    score(b) - score(a) || (a.name < b.name ? -1 : 1))[0]; // 稳定排序
}
const reg = { search: [
  { name: 'es', status: 'ok', stats: { passRate: 0.9, costMs: 100 } },
  { name: 'vec', status: 'ok', stats: { passRate: 0.95, costMs: 400 } },
  { name: 'old', status: 'degraded', stats: { passRate: 0.99, costMs: 10 } },
]};
console.log(select(reg, 'search').name);                          // 'vec'
console.log(select(reg, 'search', { costSensitive: true }).name); // 'es'
```

**评分点**：
- status 过滤在评分之前（degraded 不参选，即使 passRate 最高）
- 成本敏感的综合分公式正确（passRate / cost）
- 空实现抛错（fail-fast）与并列稳定排序
- 能讨论：表现数据的滞后风险（灰度提权而非直接切换）、注册表与配置中心的关系
