## AGT-678：评测用例越写越乱（格式不一/判据含糊），用例结构如何设计才可长期维护

**答**：
- 用例是结构化对象不是文本堆：`{ id, cap, diff, input(parts), golden(可判形式), rubric(判据引用), meta(来源/创建人/关联bug) }`；判据引用共享 rubric 库而非每条自带——rubric 改一处全局生效。
- golden 尽量「可程序判定」：结构化期望（字段/正则/引用列表）优先，judge 判据兜底；每条用例标注「判定方式」，执行器按判定方式路由。
- 生命周期字段：active/retired/quarantined + 退役原因，评审式变更（PR 改用例），防止悄悄删失败用例。

```javascript
const caseSchema = {
  id: 'C-1024', cap: 'tool_use', diff: 'hard',
  input: [{ type: 'text', value: '查上季度华东区退款率并对比环比' }],
  golden: { kind: 'structured',                  // 可程序判定优先
    mustHave: ['tool:sql_query', '环比计算'],
    format: { type: 'table', cols: ['region', 'rate', 'qoq'] } },
  rubric: 'R-退款分析',                           // 共享判据引用
  meta: { source: 'online-reflux', bug: 'BUG-231' },
  status: 'active',
};
function judgeRoute(c, output) {
  return c.golden.kind === 'structured'
    ? programmaticJudge(c.golden, output)        // 程序判定
    : llmJudge(c.rubric, c.input, output);       // judge兜底
}
```
