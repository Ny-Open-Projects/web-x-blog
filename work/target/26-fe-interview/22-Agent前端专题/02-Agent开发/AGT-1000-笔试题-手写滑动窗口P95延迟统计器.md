## 1000：笔试手写：实现流式 P95 延迟统计（内存受限）

**答**：实现 LatencyTracker(maxSamples=1000)：observe(ms) 记录样本，超 maxSamples 时淘汰最老样本（滑动窗口）；p95() 返回当前窗口 P95；窗口不足 100 样本返回 null（样本不足不可信）。要求 p95 计算不必全排序（可讨论优化），复杂度可接受。

```js
class LatencyTracker {
  constructor(maxSamples = 1000) {
    this.cap = maxSamples; this.buf = []; // 环形缓冲
    this.sorted = [];                     // 有序副本加速 p95
  }
  observe(ms) {
    if (this.buf.length >= this.cap) {
      const old = this.buf.shift();
      const i = lowerBound(this.sorted, old);
      this.sorted.splice(i, 1);           // 有序数组同步删除
    }
    this.buf.push(ms);
    this.sorted.splice(lowerBound(this.sorted, ms), 0, ms); // 二分插入
  }
  p95() {
    if (this.buf.length < 100) return null;      // 样本不足不可信
    const idx = Math.ceil(this.sorted.length * 0.95) - 1;
    return this.sorted[idx];
  }
}
function lowerBound(a, x) {
  let lo = 0, hi = a.length;
  while (lo < hi) { const m = (lo + hi) >> 1;
    if (a[m] < x) lo = m + 1; else hi = m; }
  return lo;
}
const t = new LatencyTracker();
for (let i = 1; i <= 100; i++) t.observe(i);
console.log(t.p95()); // 95
```

**评分点**：
- 滑动窗口淘汰最老样本时同步维护有序数组（漏删会导致 P95 失真，高频扣分点）
- P95 索引语义：ceil(n*0.95)-1 与团队口径一致即可，能说出不同实现差异
- 样本不足返回 null 而不是给出误导值
- 复杂度讨论：二分插入 O(log n)+O(n) 挪移，比每次全排序 O(n log n) 优；更大量可用 t-digest 近似
