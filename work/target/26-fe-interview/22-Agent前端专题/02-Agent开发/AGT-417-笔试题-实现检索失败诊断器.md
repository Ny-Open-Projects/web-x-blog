## AGT-417：手写检索诊断：金标块定位、过滤复现、上下文层检查

**需求与边界**：
- 输入：query、金标块 id、检索函数（可传 filter 开关）；输出：诊断结论（索引缺失/过滤错杀/相关性弱/生成层问题）。
- 边界要求：① 无过滤重查判断"是否被 filter 杀掉"；② 大 k 重查判断"相关性排名"；③ 索引存在性单独确认（按 id 直查）；④ 各结论附修复建议。

**答**：
```javascript
async function diagnose(query, goldId, { search, getById }) {
  // 1. 索引存在性：按 id 直查
  const gold = await getById(goldId);
  if (!gold) return { level: 'index', fix: '金标块未入库：检查采集/分块管线' };
  // 2. 无过滤大 k：判断相关性上限
  const raw = await search(query, { k: 100, filter: null });
  const rank = raw.findIndex(d => d.id === goldId);
  if (rank === -1)
    return { level: 'relevance', fix:
      'embedding 相关性弱：考虑 rerank / 换模型 / 查询改写' };
  // 3. 带过滤常规查询：判断过滤是否错杀
  const filtered = await search(query, { k: 20, filter: DEFAULT_FILTER });
  if (!filtered.some(d => d.id === goldId))
    return { level: 'filter', fix:
      `filter 错杀：检查过滤条件，rank(无过滤)=${rank}`,
      evidence: { rankRaw: rank } };
  // 4. 已召回但靠后（rank >= 20）
  if (rank >= 20)
    return { level: 'ranking', fix: '候选太浅或 rerank 缺失：调大 k / 加 rerank' };
  // 5. 检索正常 → 生成层
  return { level: 'generation', fix:
    '检索正常：检查上下文装配位置 / prompt / 摘要是否丢块' };
}
```

**评分点**:
- 五级诊断完整：索引缺失→相关性弱→过滤错杀→排名靠后→生成层，顺序合理（上游优先）。
- 每级结论附可执行修复建议，带证据（rank 数值）。
- 控制变量清晰：无过滤大 k 与带过滤常规查询对比定位过滤问题。
- 能说明"检索正常再查生成层"的分层归因思想。
