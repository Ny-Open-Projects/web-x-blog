## 1036：笔试手写：实现父子块（parent-child）检索逻辑

**答**：实现 parentChildSearch(children, query, { topK=3, parentMax=2000 })：children 为 { id, parentId, text, score }[]（已按 score 降序）。取分数前 topK 的子块，按 parentId 去重收集对应父块全文；父块超 parentMax 时替换为「首段 + ... + 尾段」（各保留 parentMax/2）；返回按「最高子块分数」排序的父块列表。

```js
function parentChildSearch(children, { topK = 3, parentMax = 2000 } = {}) {
  const seen = new Map();                            // parentId -> 最高分
  for (const c of children.slice(0, topK)) {
    if (!seen.has(c.parentId) || seen.get(c.parentId) < c.score) {
      seen.set(c.parentId, c.score);
    }
  }
  return [...seen.entries()]
    .sort((a, b) => b[1] - a[1])
    .map(([pid]) => {
      const p = parents[pid];
      if (p.text.length <= parentMax) return p;
      const half = parentMax / 2;
      return { id: pid, score: seen.get(pid),
        text: p.text.slice(0, half) + '\n...\n' + p.text.slice(-half) }; // 首尾保留
    });
}
const parents = { p1: { id: 'p1', text: 'A'.repeat(3000) } };
const children = [{ id: 'c1', parentId: 'p1', text: '...', score: 0.9 }];
console.log(parentChildSearch(children)[0].text.length); // 2001（1000+...+1000）
```

**评分点**：
- parentId 去重语义正确：多个子块命中同一父块只保留一次、分数取最高
- 父块截断策略「首尾各半」保住文档头（往往含标题/定义）与结论
- 排序依据是子块最高分而非父块自身
- 能讨论：为什么不用「直接检索大块」？——小块向量语义更聚焦（召回准），大块上下文完整（生成好），父子块兼顾两头
