## 1230：笔试手写：实现流程状态机的快照保存与恢复校验

**答**：改为笔试题。**需求**：实现 snapshot(actor) -> { state, ctx, ver }；restore(def, snap, SCHEMA_V)——ver 不匹配当前 SCHEMA_V 返回 { ok: false, reason: 'version' }（降级重置）；状态不在 def.states 返回 { ok: false, reason: 'unknown-state' }；合法则恢复 { ok: true, actor }（actor 状态与 ctx 与快照一致）。context 深拷贝防共享。

```js
function snapshot(actor, ver) {
  const s = actor.getState();
  return { state: s.state, ctx: structuredClone(s.ctx), ver };
}
function restore(def, snap, SCHEMA_V) {
  if (snap.ver !== SCHEMA_V) return { ok: false, reason: 'version' };
  if (!(snap.state in def.states)) return { ok: false, reason: 'unknown-state' };
  const actor = createMachine({ ...def, context: structuredClone(snap.ctx) }).start();
  // 迷你机：直接以快照状态为初始（生产用 XState 的 hydrate）
  return { ok: true, actor, state: snap.state };
}
// 用例：保存 -> 恢复 -> send 继续流程；改 SCHEMA_V -> 降级重置
```

**评分点**：
- 版本校验先行（不兼容降级重置而非崩溃）
- 未知状态防御（机器定义演进后旧快照的防御）
- structuredClone 防共享（恢复的 actor 与历史快照隔离）
- 能讨论：XState 的 persist/hydrate、快照中瞬时状态的剔除（loading 不持久化）
