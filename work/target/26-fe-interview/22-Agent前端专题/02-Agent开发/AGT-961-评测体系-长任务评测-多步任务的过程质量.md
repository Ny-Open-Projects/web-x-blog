## 961：多步长任务（10+ 轮工具调用）怎么评

**答**：
- 长任务的失败多是「过程性」的：中途丢失目标、重复劳动、在某一步陷入循环——只评最终产物会漏掉这些，所以要加过程断言（每步的中间产物快照）。
- 检查点评测：把长任务拆成 N 个里程碑（如「已完成需求分析」「代码可编译」），逐里程碑打分，定位是哪一步开始崩的。
- 预算效率也评：同样完成，用了 8 步和 30 步不是一个水平；「步数效率」= 基准步数 / 实际步数。
- 追问钩子：里程碑标注成本太高怎么办？——只对失败 case 要求人工标里程碑（归因用），成功 case 只评端点，人工量可控。

```ts
const milestones = [
  { id: 'm1', check: t => t.files.includes('plan.md') },
  { id: 'm2', check: t => t.build === 'ok' },
  { id: 'm3', check: t => t.tests.allPass },
];
function evalLong(trace, base) {
  const reached = milestones.findIndex(m => !m.check(trace));
  return { score: (reached === -1 ? milestones.length : reached) / milestones.length,
    stepsEff: base / trace.steps,
    firstFailAt: reached === -1 ? null : milestones[reached].id };
}
```
