## AGT-258：Agent 的工具调用能力（选对工具、传对参数）怎么单独评测？

**答**:
- 评测三层：选择层（给定任务与工具列表，模型是否选了正确的工具——含"应该拒绝调用"的反例，测误调用率）、参数层（schema 合规率+语义正确率：参数值是否符合任务意图，如查的是"上周"不是"上个月"）、时序层（多工具任务的调用顺序是否符合依赖）。
- 构造方法：静态集（任务+mock 工具环境，模型输出调用计划与真实计划比对——便宜可回归）、动态集（真实执行看结果断言——更真实但环境噪声大）；两者结合，静态做回归、动态做验收。
- 参数正确性判定：结构校验程序化（schema validate），语义校验用 judge（参数值是否符合意图）+ 模糊匹配（日期/ID 类给容差）——把"程序能判的"与"需要判断的"分开。
- 归因输出：错误分类（选错工具/参数缺漏/参数幻觉[编造不存在的 ID]/顺序错误）——不同错误对应不同修复（工具描述改进/参数 schema 改进/上下文注入改进）。

```javascript
async function evalToolUse(cases) {
  const stat = { select: 0, param: 0, order: 0 };
  for (const c of cases) {
    const plan = await agent.plan(c.task, mockTools(c.tools));
    stat.select += plan.tool === c.gold.tool;
    const pv = schemaValid(plan.args, c.gold.tool.schema)
      && (await semanticMatch(plan.args, c.gold.args, { fuzz: ['date','id'] }));
    stat.param += pv;
    stat.order += orderMatch(plan.seq, c.gold.seq);
  }
  return normalize(stat, cases.length);
  // 错误归因：选错→改描述；幻觉参数→加校验提示；
  // 顺序错→依赖声明强化。
}
```
