## 991：「先给快的再给深的」分级响应怎么设计

**答**：
- 分级响应：先流式给出「快速层」结果（缓存/轻量检索 + 小模型，1s 内），同时后台跑深度层（全量检索 + 大模型），完成后以「深度回答已生成」追加呈现，用户可选切换。
- 适用判断：问答类（时效敏感）适合分级；事务类（下单、审批）不适合——快速层给错答案代价太大，宁可等深度层。
- 一致性风险：快速层与深度层答案矛盾时用户困惑——深度层完成后做 diff，显著矛盾时明确标注「深度分析修正了初步结论」而不是悄悄替换。
- 追问钩子：深度层跑了但用户已离开页面怎么办？——结果落库 + 通知（站内信/邮件可选），这是分级响应的产品闭环，否则白烧算力。

```ts
async function graded(q, sse) {
  const fast = await quickLayer(q);        // 缓存 + 小模型，目标 < 1s
  sse.send('answer', { tier: 'fast', text: fast });
  deepLayer(q).then(async deep => {
    const conflict = await judge.diff(fast, deep);
    sse.send('answer', { tier: 'deep', text: deep,
      note: conflict ? '深度分析修正了初步结论' : null });
    await persist(q, deep);                // 用户离开也能收到通知
  });                                       // 不 await：后台继续
}
```
