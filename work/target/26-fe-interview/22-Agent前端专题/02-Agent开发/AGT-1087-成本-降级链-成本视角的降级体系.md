## 1087：从成本视角，降级链应该按什么顺序设计

**答**：
- 降级链按「成本递减」排：全量 RAG + rerank + 大模型 → 砍 rerank → 缓存/快照答案 → 小模型直答 → 静态话术；每级成本差 3~10 倍，可用性换成本。
- 触发器分两类：质量触发（降级后质量指标跌破红线要能自动回升）与成本触发（预算烧到 80% 自动降一档）；两套触发器独立，不能混。
- 降级透明化：降级响应带标记（用户可见「精简模式」），既管理预期也为质量归因留数据——悄悄降级会让 badcase 归因全乱。
- 追问钩子：降级链的「回升」怎么做？——恢复条件预定义（预算恢复/高峰过去）+ 灰度回升（先回 10% 流量验证质量再全量），避免「降下去升不回来」。

```ts
const LADDER = [
  { level: 'full', cost: 1.0 },
  { level: 'no_rerank', cost: 0.4 },
  { level: 'snapshot', cost: 0.1, mark: '数据非实时' },
  { level: 'small_model', cost: 0.05, mark: '精简模式' },
];
function pick(budgetLeft, load) {
  if (budgetLeft < budget.total * 0.2) return LADDER[LADDER.length - 2]; // 成本触发
  if (load > HIGH) return LADDER[1];                          // 容量触发
  return LADDER[0];
}
```
