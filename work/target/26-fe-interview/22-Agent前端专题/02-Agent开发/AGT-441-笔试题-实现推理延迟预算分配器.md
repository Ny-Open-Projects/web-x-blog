## AGT-441：手写延迟预算分配：首 token SLO、各段预算、超支监测与降级

**需求与边界**：
- 输入：总 SLO（首 token 1.5s / 总时长 30s）、各阶段历史耗时分布；输出：分配方案+监测点。
- 边界要求：① TTFT 预算优先保护（用户感知核心）；② 各段预算按历史 P95 分配且留缓冲；③ 运行时超支检测（某段超预算触发降级：砍检索深度/换快模型）；④ 记录实际分布反哺预算调整。

**答**：
```javascript
class LatencyBudget {
  constructor({ ttftSlo = 1500, totalSlo = 30000, history }) {
    this.slo = { ttft: ttftSlo, total: totalSlo };
    // 按 P95 历史分配 TTFT 预算（首 token 优先）
    const p95 = (k) => history.percentile(k, 0.95);
    this.ttftPlan = {
      preproc: p95('preproc') * 1.2,       // 预处理缓冲 20%
      retrieval: Math.min(p95('retrieval'), 400),
      firstToken: 0,                        // 差额即模型 TTFT 余量
    };
    const used = Object.values(this.ttftPlan).reduce((a,b)=>a+b,0);
    this.ttftPlan.firstToken = ttftSlo - used;
    if (this.ttftPlan.firstToken < 200)
      throw new Error('TTFT 预算不足：压缩检索段或调 SLO');
  }
  // 运行时监测：阶段超支触发降级
  watch(stage) {
    const start = performance.now();
    return { stop: () => {
      const used = performance.now() - start;
      const planned = this.ttftPlan[stage];
      return { used, over: used > planned,
        action: used > planned * 1.5 ? 'degrade' : 'ok' };
    }};
  }
  // 降级策略（按超支阶段选）
  degrade(stage) {
    return stage === 'retrieval'
      ? { action: 'reduce_k', k: 10, note: '砍检索深度' }
      : { action: 'switch_model', model: FASTER_MODEL,
          note: '换快模型，质量降级标注' };
  }
  record(stage, used) {                    // 实际分布回填
    history.push(stage, used);             // 反哺下一轮预算分配
  }
}
```

**评分点**:
- TTFT 优先：首 token 预算 = SLO 扣除各段（含 20% 缓冲），不足直接报错（不静默劣化）。
- 运行时 watch 返回超支判定与降级动作，按阶段选策略（检索砍深度/模型换快）。
- record 回填实际分布形成预算闭环（P95 动态调整）。
- 质量降级需标注（换快模型时）的用户知情意识。
