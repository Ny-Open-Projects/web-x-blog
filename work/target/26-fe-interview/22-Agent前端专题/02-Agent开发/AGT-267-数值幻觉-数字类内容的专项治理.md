## AGT-267：数字类幻觉（金额/比例/日期）为什么最危险，专项怎么治理？

**答**:
- 高危原因：数字的错误是硬错误（用户无法"部分信任"），且 LLM 的算术与记忆都不可靠（训练数据中数字噪声大、算术运算依赖 token 概率）——涉及金额/统计/日期的输出必须走确定性管道。
- 治理原则一：计算不给模型——加减乘除/汇总/换算交给代码执行或查询引擎（AGT-213 表格问答原则），模型只负责理解意图与组织语言；强制数字必须来自工具结果或原文引用。
- 治理原则二：程序化比对——输出中的每个数字回查其来源（原文/工具结果），不在来源中的数字即幻觉，直接拦截；单位与量级也要校验（"万元/元"错位是常见事故）。
- 治理原则三：日期与时效——"最新/去年"等相对时间必须由系统解析为绝对日期再进 prompt（模型不知道今天几号），时效敏感数字带"截至日期"标注。

```javascript
async function numericSafeAnswer(q) {
  const plan = await llm(`若需计算，生成可执行表达式`, q);
  const facts = plan.needsCalc
    ? await codeExec(plan.expr, await retrieve(q))   // 引擎算
    : await retrieve(q);
  const out = await llm(`数字只能来自给定数据`, { q, facts });
  const nums = extractNumbers(out);
  const ok = nums.every(n => sourceContains(facts, n.value, n.unit));
  return ok ? stampAsOf(out, now()) : rejectNumeric(out); // 拦截
}
```
