## 1055：怎么知道 Agent 的工具集「够不够用」

**答**：
- 工具覆盖审计：跑一遍评估集统计「模型想调但工具集里没有」的次数（需求缺口）、以及「有工具但从不被用」的次数（冗余工具）——两个数字直接指导工具集增删。
- 需求缺口的抓取：模型在工具不足时的行为是「硬编答案」（幻觉）或「说做不到」，两类都要识别；「说做不到」的聚合就是工具集改进清单。
- 工具间冲突检测：功能重叠的工具（两个搜索）会让模型选择摇摆，统计「同类工具被交替调用」的频率，过高说明该合并或明确分工描述。
- 追问钩子：工具越多越好吗？——不是，工具超 20 个后选择准确率下降（上下文稀释），定期裁剪零调用工具比加工具更重要。

```ts
async function toolAudit(evalSet, registry) {
  const gaps = new Set(), unused = new Set(registry.keys()), alternate = 0;
  for (const c of evalSet) {
    const tr = await runWithTrace(c, registry);
    tr.wants.forEach(w => { if (!registry.has(w)) gaps.add(w); }); // 需求缺口
    tr.used.forEach(u => unused.delete(u));
    if (hasAlternating(tr.used, sameCategory)) alternate++;
  }
  return { gaps: [...gaps], unused: [...unused], alternateRate: alternate / evalSet.length };
}
```
