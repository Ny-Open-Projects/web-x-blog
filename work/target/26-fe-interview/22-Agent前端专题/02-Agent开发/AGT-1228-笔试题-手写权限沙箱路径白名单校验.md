## 1228：笔试手写：实现 Agent 工具的路径白名单校验（含 realpath 语义）

**答**：实现 checkAccess(cap, op, path, resolve)：cap = { read: string[], write: string[] }（前缀白名单）。规则：op 限 read/write；path 先经 resolve（模拟 realpath——注入函数，测试中恒等或做 ../ 解析）归一化，再前缀匹配（目录边界：/data 不匹配 /data2）。返回 { ok, normalized }。

```js
function checkAccess(cap, op, path, resolve = p => p) {
  if (op !== 'read' && op !== 'write') return { ok: false, normalized: path,
    reason: 'bad op' };
  const norm = resolve(path);
  const prefixes = cap[op] || [];
  const ok = prefixes.some(pre => {
    const base = pre.endsWith('/') ? pre : pre + '/';
    return norm === pre || norm.startsWith(base);   // 目录边界防 /data2 误配
  });
  return { ok, normalized: norm };
}
const cap = { read: ['/data'], write: ['/workspace/out/'] };
console.log(checkAccess(cap, 'read', '/data/sub/f.txt'));         // ok true
console.log(checkAccess(cap, 'read', '/database/x'));             // ok false（边界）
console.log(checkAccess(cap, 'write', '/workspace/out/../out/a')); // 依赖 resolve
```

**评分点**：
- 目录边界匹配（补 / 后 startsWith——/data2 经典误配 bug）
- resolve 注入（realpath 语义——符号链接的最终真相）
- op 白名单校验先行
- 能讨论：realpath 的必要性（软链接逃逸）、Windows 大小写与分隔符的进阶
