## AGT-537：手写请求级配额守卫：预估消耗、余量校验、限流重试倒计时、降级建议

**需求与边界**：
- 输入：配额状态（remaining/rateLimited/retryAfter/resetAt）与预估函数 est(req)；输出守卫函数 guard(req, action)。
- 边界要求：① 余量不足返回升级引导；② 限流时按 retryAfter 排队自动重试；③ 大消耗（>30% 余量）需确认；④ 重试次数上限防死循环。

**答**：
```javascript
function createQuotaGuard(quota, ui) {
  let retryCount = 0;
  return async function guard(req, action, est = estimate) {
    const cost = await est(req);
    if (quota.remaining < cost)
      return ui.upgrade({ need: cost, have: quota.remaining,
        resetAt: quota.resetAt });                     // 配额不足
    if (quota.rateLimited) {
      if (++retryCount > 3) { retryCount = 0;
        return ui.error('多次限流，请稍后再试'); }        // 重试上限
      return ui.wait(quota.retryAfter).then(() =>       // 倒计时后重试
        guard(req, action, est));
    }
    if (cost > quota.remaining * 0.3) {
      const ok = await ui.confirm(`预计消耗 ${cost}，剩余 ${quota.remaining}，继续？`);
      if (!ok) return null;                             // 用户取消
    }
    retryCount = 0;
    const res = await action(req);
    quota.remaining -= res.usage?.totalTokens ?? cost;  // 用实际消耗回写
    return res;
  };
}
```

**评分点**:
- 三分支语义正确：配额不足→升级、限流→倒计时重试、大消耗→确认。
- 重试计数上限防死循环；成功后用实际 usage 回写余量而非预估值。
- est 支持异步注入（预估也可调服务端）。
