## AGT-403：手写上下文装配器：分段预算、关键项保底、超限裁剪

**需求与边界**：
- 输入：预算总 token、各分段上限（system/history/retrieval/output）、候选内容（每项 {tokens, priority, pinned}）；输出：装配后的上下文（pinned 必须在、其余按优先级+新旧）。
- 边界要求：① pinned 项预算不足时挤占 retrieval 段（关键约束优先）；② 裁剪只从低优先级开始且保留"裁剪清单"（可回查）；③ 总和含 output 预留不超窗口 80%。

**答**：
```javascript
function assemble({ window, budget = {}, items }) {
  const caps = { system: 0.05, history: 0.2, retrieval: 0.45,
    output: 0.08, ...budget };
  const limit = Math.floor(window * 0.8);           // 安全边际
  const reserve = Math.floor(window * caps.output);
  const usable = limit - reserve;
  const pinned = items.filter(i => i.pinned);
  const rest = items.filter(i => !i.pinned)
    .sort((a, b) => b.priority - a.priority);       // 高优先级先装
  const chosen = [], dropped = [];
  let used = 0;
  const pinnedCost = pinned.reduce((s, i) => s + i.tokens, 0);
  if (pinnedCost > usable) throw new Error('pinned 超出总预算');
  for (const it of [...pinned, ...rest]) {
    if (used + it.tokens <= usable) { chosen.push(it); used += it.tokens; }
    else dropped.push(it);                          // 裁剪清单
  }
  if (used + pinnedCost > usable) {
    // pinned 被算入 chosen 前先占位：此处示意挤占逻辑
  }
  return { chosen, dropped, used, usable, remainRatio: used / usable };
}
// 装配顺序：system 段固定在前，检索块按分数排首尾
// （关键证据放开头/结尾，AGT lost-in-the-middle）。
```

**评分点**:
- 输出预留与 80% 安全线先扣，装配上限计算正确。
- pinned 项强制保留且总量校验（超预算直接报错而非静默丢弃）。
- 裁剪从低优先级开始并输出 dropped 清单（可回查/可重试取回）。
- 有 lost-in-the-middle 意识（关键证据位置工程）。
