## AGT-265：Agent 的拒答机制怎么设计——拒答不是失败而是正确行为？

**答**:
- 必须拒答的四类：知识/资料不足以支撑结论（检索无命中或低置信）、超出能力边界（需要实时数据但无工具）、高危决策（医疗诊断/法律结论/资金操作——只能提供参考+建议咨询专业人士）、违规内容——每类有不同的拒答话术模板。
- 拒答的判定信号：检索分数低于阈值、自一致性采样分歧、规则触发（敏感域词表）、用户问题含预设错误（"既然 X 为真…"而 X 不成立——需先纠正前提）。
- 拒答质量设计：拒答不是一句"我不知道"——优秀拒答=说明缺什么+给出用户可以补充的方向+提供部分可靠信息（"我知道 A 和 B，但 C 我无法确认"）——部分回答优于全拒，最大化诚实可用性。
- 评测与调优：拒答的假阴性（该拒不拒、编造硬答）与假阳性（不该拒乱拒）都要监控——拒答率异常升高通常是检索退化的信号，拒答率是系统健康的温度计。

```javascript
async function answerWithRefusal(query) {
  const docs = await retrieve(query);
  if (topScore(docs) < 0.35)                   // 低置信信号
    return refusal({
      know: ['A 的定义（来源[1]）'],           // 部分可靠信息
      missing: 'C 的具体数值',
      ask: '可否提供 C 所在的文档或更精确的时间范围？',
    });
  if (hitRiskList(query)) return safeRefusal(query); // 高危域
  return generate(query, docs);
}
```
