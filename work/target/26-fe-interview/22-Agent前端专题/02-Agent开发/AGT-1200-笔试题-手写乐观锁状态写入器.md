## 1200：笔试手写：实现任务状态的乐观锁写入（CAS）

**答**：实现 StateStore：get(taskId) 返回 { data, ver }；cas(taskId, patch, expectVer)：版本匹配则写入（patch 浅合并到 data）并 ver+1，返回 { ok: true, ver }；不匹配返回 { ok: false, ver: 当前 }（调用方重读重试）；另实现 casRetry(store, taskId, patchFn, tries=3)：每次基于最新数据重新生成 patch 重试，指数退避，重试耗尽抛错。

```js
class StateStore {
  constructor() { this.st = new Map(); }
  get(taskId) {
    const s = this.st.get(taskId) ?? { data: {}, ver: 0 };
    return { data: { ...s.data }, ver: s.ver };
  }
  cas(taskId, patch, expectVer) {
    const s = this.st.get(taskId) ?? { data: {}, ver: 0 };
    if (s.ver !== expectVer) return { ok: false, ver: s.ver };  // 版本不符
    this.st.set(taskId, { data: { ...s.data, ...patch }, ver: s.ver + 1 });
    return { ok: true, ver: s.ver + 1 };
  }
}
async function casRetry(store, taskId, patchFn, tries = 3) {
  for (let i = 0; i < tries; i++) {
    const { data, ver } = store.get(taskId);
    const r = store.cas(taskId, patchFn(data), ver);   // 基于最新数据生成 patch
    if (r.ok) return r;
    await sleep(2 ** i * 10);                          // 指数退避重试
  }
  throw new Error('cas contention: ' + taskId);
}
const s = new StateStore();
console.log(s.cas('t1', { a: 1 }, 0));   // { ok: true, ver: 1 }
console.log(s.cas('t1', { b: 2 }, 0));   // { ok: false, ver: 1 }
```

**评分点**：
- CAS 语义正确：版本匹配才写、不匹配返回当前版本（调用方可重试）
- 浅合并语义明确（patch 覆盖同名字段）
- casRetry 基于最新数据重新生成 patch（不是盲重试旧 patch——这是关键区别）
- 能讨论：真实系统的并发来源（多实例接管同任务）、Redis WATCH/MULTI 或 Lua 实现原子 CAS、重试上限后应升级人工/告警
