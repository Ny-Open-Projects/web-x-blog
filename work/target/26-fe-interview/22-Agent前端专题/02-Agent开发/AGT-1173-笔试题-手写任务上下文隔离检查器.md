## 1173：笔试手写：实现「缓存 key 必含任务维度」的静态检查

**答**：实现 lintCacheKeys(code)：扫描代码中 cache.set(k, ...) / cache.get(k) 调用，检查 key 表达式是否引用了任务上下文变量（ctx.taskId / task.id / taskId 任一）。字符串字面量 key 直接违规；无任务维度的 key 报 { line, reason }。返回违规列表。

```js
function lintCacheKeys(code) {
  const lines = code.split('\n');
  const violations = [];
  lines.forEach((line, idx) => {
    if (!/cache\.(set|get)\s*\(/.test(line)) return;
    if (/(ctx\.taskId|task\.id|taskId)/.test(line)) return;  // 含任务维度
    violations.push({ line: idx + 1,
      reason: /'|"|`/.test(line.match(/cache\.(?:set|get)\s*\(([^,]+)/)?.[1] || '')
        ? 'literal key without task scope' : 'key missing task dimension' });
  });
  return violations;
}
const code = [
  "cache.set('result:' + q, r);",        // 违规：无任务维度
  "cache.get(ctx.taskId + ':' + q);",    // OK
].join('\n');
console.log(lintCacheKeys(code));
// [{ line: 1, reason: 'key missing task dimension' }]
```

**评分点**：
- 识别 cache.set/get 调用 + 任务维度变量检查
- 字面量 key 与动态 key 的违规原因区分
- 行号定位正确
- 能讨论：lint 只是静态防线，运行时还要「状态泄漏探针」（产物元数据校验）双保险；更彻底的方案是上下文对象封装，cache API 强制从 ctx 派生 key
