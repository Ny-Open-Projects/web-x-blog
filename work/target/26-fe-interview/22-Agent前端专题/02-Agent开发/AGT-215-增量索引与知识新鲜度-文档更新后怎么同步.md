## AGT-215：文档经常更新/删除，RAG 索引怎么增量同步？

**答**:
- 全量重建不可持续：知识库每天变更时，全量重嵌入既贵又慢（小时级延迟）——增量索引的关键是内容寻址与版本化。
- 增量流水线：文档内容 hash 变化才处理（跳过未变文档）、块级 diff（新文档分块后与旧块 hash 对比，只嵌入新增/变更块）、删除块按版本下线（软删除+灰度切换，保证检索与索引一致）、失败块可重试幂等。
- 一致性风险：检索缓存与索引版本错位（缓存命中旧块）——缓存 key 带文档版本号，索引切换用"双写+切流"或即时生效的 upsert。
- 新鲜度语义：部分业务要求"改完立即可查"（同步更新+写路径阻塞可接受），部分可容忍 T+1（异步队列）——按业务定义 SLA 而不是无脑实时。

```javascript
async function incrementalIndex(doc) {
  const ver = await getCurrentVersion(doc.id);
  if (ver?.hash === doc.hash) return { skipped: true };   // 未变跳过
  const newChunks = chunk(doc).map(c => ({ ...c, hash: md5(c.text) }));
  const oldChunks = ver?.chunks || [];
  const changed = diffByHash(oldChunks, newChunks);
  await Promise.all(changed.added.map(upsert));           // 幂等 upsert
  await Promise.all(changed.removed.map(c => softDelete(c.id)));
  await publishVersion(doc.id, doc.hash);                 // 缓存 key 含版本
}
```
