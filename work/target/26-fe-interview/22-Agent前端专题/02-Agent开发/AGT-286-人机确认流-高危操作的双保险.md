## AGT-286：Agent 执行高危操作前的用户确认，怎么设计才既安全又不烦人？

**答**:
- 确认分级：读操作免确认；写操作单次确认（展示 diff：改了什么）；不可逆/高价值操作（删除/支付/外发）强确认（二次确认+冷静期或批量限额）；批量操作按批次确认+抽样明细（不是逐条点 500 次确认）。
- 确认卡的信息设计：让人能快速决策——做什么（动作+影响范围）、为什么（Agent 的依据摘要）、改什么（具体 diff/参数）、风险是什么（一句话）——"确认疲劳"的根源是信息过载的确认卡，设计目标是 10 秒可决策。
- 疲劳防御：同模式操作支持"记住本次选择"（同参数白名单化+后续静默执行+事后可撤销——撤销比确认更符合人性）、异常偏离时重新确认（参数偏离白名单模式即升级确认）。
- 闭环：确认决策进审计与评测（用户拒绝的操作是重要信号——为什么 Agent 要这么做？反馈回 prompt/规则）。

```javascript
async function riskyOp(op) {
  const card = { action: op.describe(), diff: op.diff(),
    reason: op.brief, risk: op.riskLine() };
  if (whitelisted(op) && !op.deviate()) {     // 记住的选择
    scheduleUndoable(op); return;
  }
  const d = await confirm(card, { level: op.irreversible
    ? 'strong' : 'normal' });                 // 分级确认
  if (d.rejected) feedbackLoop(op, d.reason); // 负反馈闭环
  return executeWithUndo(op);                 // 可撤销优先
}
```
