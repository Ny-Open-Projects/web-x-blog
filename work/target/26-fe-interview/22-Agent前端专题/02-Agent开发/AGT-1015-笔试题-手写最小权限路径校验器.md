## 1015：笔试手写：实现工具调用的路径白名单校验

**答**：实现 checkPath(cap, op, path)：cap = { read: [prefix], write: [prefix] }。规则：op 为 read/write 必须命中对应前缀列表之一；path 归一化（解析 ./ 和 ../）后再校验（防止 /a/b/../../etc/passwd 绕过）；绝对路径与相对路径都要支持（相对路径基于 cwd）；目录穿越后仍越界则拒绝。返回 { ok, normalized }。

```js
const path = require('path');
function checkPath(cap, op, p, cwd = '/workspace') {
  const norm = path.posix.normalize(path.posix.isAbsolute(p) ? p : path.posix.join(cwd, p));
  const prefixes = cap[op] || [];
  const ok = prefixes.some(pre => norm === pre || norm.startsWith(pre.endsWith('/') ? pre : pre + '/'));
  return { ok, normalized: norm };    // 归一化后再前缀匹配，防 ../ 穿越
}
const cap = { read: ['/data'], write: ['/workspace/out/'] };
console.log(checkPath(cap, 'write', '/workspace/out/../out/f.txt').ok);  // true（归一化后仍界内）
console.log(checkPath(cap, 'write', '/workspace/out/../../etc/pw').ok);  // false（穿越出界）
```

**评分点**：
- 归一化必须发生在前缀匹配之前（先匹配后归一化是错的，经典绕过）
- 前缀匹配的边界：/data2 不能匹配 /data 前缀（补 / 的细节）
- 相对路径基于 cwd 解析，绝对路径直接归一化
- 能讨论：Windows 反斜杠、符号链接（realpath 才是最终真相）、大小写不敏感文件系统的额外边界
