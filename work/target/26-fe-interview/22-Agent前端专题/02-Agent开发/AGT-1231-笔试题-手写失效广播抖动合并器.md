## 1231：笔试手写：实现服务端失效广播的合并与抖动下发

**答**：实现 BroadcastScheduler(tickMs=2000)：schedule(userId, keys)——同一用户 tick 内的 keys 合并（一次下发去重后的并集）；flush(tick) 处理该 tick 的全部批次，返回 { userId, keys }[]。跨 tick 不合并。测试：两批同用户同 tick 合并为一次下发。

```js
class BroadcastScheduler {
  constructor(tickMs = 2000) { this.tickMs = tickMs; this.buf = new Map(); }
  schedule(userId, keys) {
    const cur = this.buf.get(userId) ?? new Set();
    keys.forEach(k => cur.add(JSON.stringify(k)));   // Set 去重（序列化 key）
    this.buf.set(userId, cur);
  }
  flush() {
    const out = [];
    for (const [uid, set] of this.buf) {
      out.push({ userId: uid, keys: [...set].map(s => JSON.parse(s)) });
    }
    this.buf.clear();                                // 跨 tick 不合并
    return out;
  }
}
const s = new BroadcastScheduler();
s.schedule('u1', [['order', 1]]);
s.schedule('u1', [['order', 2], ['order', 1]]);     // 同 tick 合并去重
console.log(s.flush());
// [{ userId: 'u1', keys: [['order',1],['order',2]] }]
```

**评分点**：
- Set + JSON 序列化去重（Key 数组的稳定去重）
- flush 清空缓冲（跨 tick 边界语义）
- 顺带可加抖动（下发时 random delay——讨论项）
- 能讨论：tick 与推送通道的配合（batch 广播摊平请求风暴）、内存上界（tick 内用户数）
