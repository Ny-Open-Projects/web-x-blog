## 989：Agent 网关层有哪些容易被忽略的延迟优化点

**答**：
- 连接复用：与模型供应商/检索引擎的 HTTP 连接池常驻（keep-alive + 连接数预热），冷启动握手每次多 50~200ms，高 QPS 下这是白白浪费。
- 序列化开销：大 prompt 组装避免多次字符串拼接拷贝（用数组 join）；响应解析流式处理（边收边解析 SSE），不要等完整响应再 JSON.parse。
- 中间件瘦身：网关链上的鉴权/日志/限流中间件，任何同步阻塞（如同步读配置）都会加到每个请求上；日志改异步批量落盘。
- 追问钩子：怎么证明优化有效？——网关层加「自耗时」打点（扣除下游耗时后自身开销），优化前后对比，拒绝拍脑袋说「感觉快了」。

```ts
const pool = new ConnectionPool({ keepAlive: true, max: 64, warmup: 16 }); // 常驻+预热
async function handler(req) {
  const t0 = performance.now();
  const parts = [system, tools, history, req.input];   // 数组拼接，避免串拷贝
  const stream = await pool.request('llm', { prompt: parts.join('\n') });
  const tUpstream = performance.now() - t0;
  const res = await pipeStream(stream, parseSSEIncrementally); // 流式解析
  metrics.observe('gateway_self', performance.now() - t0 - tUpstream); // 自耗时
  return res;
}
```
