## AIC-632：模型悄悄「变笨」了，怎么持续监测并调整路由？

**答**：
- 结论先行：**模型供应商会静默更新模型，能力会漂移；必须用「固定评测集 + 持续跑分」监测，用「动态路由权重」响应**。「上次好用」不代表现在好用。
- 监测机制：1) **黄金评测集**：一组固定的代表性任务（含边界用例），定期（如每周/每次供应商更新后）跑各模型，记录通过率、延迟、成本（AIC-288 内部基准）；2) **线上质量信号**：接受率、返工率、回滚率按模型分组统计——某模型这些指标恶化就是漂移信号（AIC-516 接受率）；3) **漂移告警**：跑分下降超过阈值（如 10%）自动告警。
- 路由调整：把「任务→模型」的路由从硬编码改成**基于能力档案的动态权重**（AIC-274 能力档案）——跑分高的模型分到更多高价值任务；漂移的模型自动降权，但不完全下线（留作对照）。
- 关键原则：**不要凭单次 Bad Case 下结论**——单任务失败可能是 prompt 问题；要看统计趋势。同时保留旧版本模型对照，避免「新模型全面变差却没人发现」。
- 追问钩子：为什么「线上质量信号」比「定期跑分」更早发现漂移？——因为跑集是周期性的（一周一次），而线上信号是实时的；接受率的连续下滑能在几分钟内暴露问题，跑分要等到下次执行。两者互补：线上信号发现「有事」，黄金评测集确认「确实变差」。

```typescript
type Score = { model: string; passRate: number; week: string };

function detectDrift(scores: Score[], threshold = 0.1): string[] {
  const byModel = new Map<string, Score[]>();
  for (const s of scores) {
    if (!byModel.has(s.model)) byModel.set(s.model, []);
    byModel.get(s.model).push(s);
  }
  const drifted: string[] = [];
  for (const [model, arr] of byModel) {
    arr.sort((a, b) => a.week.localeCompare(b.week));
    if (arr.length < 2) continue;
    const latest = arr[arr.length - 1].passRate;
    const prev = arr[arr.length - 2].passRate;
    if (prev - latest > threshold) drifted.push(model); // 下降超阈值
  }
  return drifted;
}

const scores = [
  { model: 'A', passRate: 0.9, week: 'w1' }, { model: 'A', passRate: 0.75, week: 'w2' },
  { model: 'B', passRate: 0.8, week: 'w1' }, { model: 'B', passRate: 0.82, week: 'w2' },
];
console.log(detectDrift(scores)); // ['A'] —— 下降 15% 触发漂移
```
