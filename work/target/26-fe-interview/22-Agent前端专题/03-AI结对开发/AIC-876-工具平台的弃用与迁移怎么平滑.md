## AIC-876：工具平台要下线一个旧能力，怎么让几百个调用方平滑迁移？
**答**：
- 迁移的本质是**降低调用方的行动成本**：光发公告没用，要给「一键迁移」能力——codemod 自动改代码、兼容层先顶着、清晰的逐步骤文档、迁移前后的行为对照测试。
- 分阶段：**① 标记弃用**（日志警告 + 文档标注 + 调用点扫描出受影响仓库清单）；**② 双跑期**（新旧能力同时可用，用影子流量验证新能力等价，AIC-809）；**③ 定向推动**（按调用量从大到小逐个团队协助迁移，先拿下头部）；**④ 兼容层兜底**（旧接口转发到新实现，给长尾团队缓冲）；**⑤ 到期删除**（明确日期，到期后旧接口返回清晰错误+迁移链接，而非静默失败）。
- 数据驱动：用调用日志确认「真的没人用了」再删，不靠感觉；删除前发最后通牒并留一个可快速恢复的开关。
- 沟通：提前一个季度通知，提供迁移办公室时间（office hour）；对迁移中被发现的 bug 优先修复，别让团队「迁移完反而出问题」。
- 追问钩子：能说出「用调用日志确认无人使用才删，且删除前留可恢复开关」的候选人，把迁移当成有回滚能力的项目而非一次性爆破。

```typescript
// 迁移状态机：按调用量确定迁移优先级，兼容层兜底
type Consumer = { repo: string; callsPerDay: number; migrated: boolean };

function migrationPlan(consumers: Consumer[]) {
  const sorted = [...consumers].sort((a, b) => b.callsPerDay - a.callsPerDay);
  return {
    priority: sorted.filter(c => !c.migrated).slice(0, 5).map(c => c.repo), // 头部优先
    canRemove: consumers.every(c => c.migrated), // 全部迁移才进入删除阶段
    steps: [
      '1. 标记 deprecated + 日志警告',
      '2. 影子流量双跑验证等价',
      '3. 头部团队定向迁移 + codemod',
      '4. 兼容层转发兜底长尾',
      '5. 调用量归零后删除（保留恢复开关）',
    ],
  };
}
console.log(migrationPlan([
  { repo:'A', callsPerDay:5000, migrated:false },
  { repo:'B', callsPerDay:100, migrated:true },
])); // priority:['A'], canRemove:false
```
