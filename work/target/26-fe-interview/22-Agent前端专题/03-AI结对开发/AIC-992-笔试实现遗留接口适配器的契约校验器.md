## AIC-992：笔试：实现「遗留接口适配器的契约校验器」（校验适配层是否完整保留旧接口契约）
**答**：
- 核心需求：实现 `verifyAdapter(contract, adapter)`。`contract: { name, params:[{name,type,required}], returns:{type,nullable}, throws?:string[] }[]`；`adapter` 为待校验的函数映射。返回 `{ passed, violations }`。
- 校验：① 函数存在性（contract.name 在 adapter 中存在且为函数）；② 参数个数与必填性（用 undefined 逐一探测必填参数是否被校验）；③ 返回值类型与 nullable（null 返回值是否被允许）；④ 声明的 throw 场景是否按约定抛错。
- 边界：contract 为空返回 passed=true；adapter 缺失函数记 violation 不中断；类型判断用 typeof（"object" 覆盖 null 时需单独判空）；violations 带契约名与原因。
- 语义：这是「静态 + 探测式」校验——它补充而非替代回放测试；探测式校验有副作用风险，应在隔离环境运行。
- 追问钩子：能指出「契约校验无法覆盖所有隐式行为，仍需历史调用回放；且探测必填参数时真实函数可能有副作用，要 mock」的候选人理解工具的边界。

```typescript
function verifyAdapter(contract=[], adapter={}) {
  const violations=[];
  const typeOf=v=>v===null?'null':Array.isArray(v)?'array':typeof v;
  for(const c of contract){
    const fn=adapter[c.name];
    if(typeof fn!=='function'){ violations.push({contract:c.name,reason:'函数不存在'}); continue; }
    for(const p of c.params){
      if(p.required){ /* 探测：省略该参数看是否被拒 */
        const args=c.params.map(x=>x.name===p.name?undefined:1);
        let threw=false; try{ fn(...args); }catch{ threw=true; }
        if(!threw) violations.push({contract:c.name,reason:`必填参数${p.name}未校验`});
      }
    }
  }
  return { passed: violations.length===0, violations };
}
console.log(verifyAdapter([
  {name:'getPrice',params:[{name:'sku',type:'string',required:true}],returns:{type:'number',nullable:true}},
], { getPrice:sku=>{ if(!sku)throw new Error('required'); return 100; } }));
```
**评分点**：
- 校验函数存在性、必填参数探测、返回类型/nullable、throw 场景四类契约。
- typeOf 正确处理 null/array/typeof，边界准确。
- contract 为空返回 passed=true，缺失函数记 violation 不中断整体。
- violations 带契约名与具体原因，代码可运行。
- 明确「探测有副作用需 mock、契约校验不能替代回放」（加分项）。
