## AIC-923：多 Agent 并行留下了大量「先合上再说」的合并债务，如何度量和管理而不是任其积累？
**答**：
- 先定义「合并债务」的量化指标：未解决的语义冲突数、被标记 TODO/XXX 的合并点、跨 Agent 的适配器/胶水代码量、合并后回归失败率——结论：可度量才可管理。
- 把债务显性化：每次合并的「妥协记录」（哪里保留了双方、哪里用了临时适配）登记到债务清单，带 owner 和偿还期限。
- 设「债务预算」：每个迭代允许新增的合并债务有上限，超预算就暂停并行、先还债——避免债务滚雪球导致系统不可维护。
- 追问钩子：能类比「技术债务」并指出「合并债务是并行开发的必然产物，关键是让它可见、有界、可偿还」的候选人，有成熟的工程治理观。

```typescript
// 合并债务看板
const mergeRecords = [
  { id:'m1', compromises:2, glueLines:40, owner:'a', resolved:false },
  { id:'m2', compromises:0, glueLines:5,  owner:'b', resolved:true },
];
function debtMetrics(records, budget = 50) {
  const open = records.filter(r => !r.resolved);
  const glue = open.reduce((s,r) => s + r.glueLines, 0);
  return {
    openCount: open.length,
    glueLines: glue,
    overBudget: glue > budget,
    topOwner: open.sort((a,b)=>b.glueLines-a.glueLines)[0]?.owner,
  };
}
console.log(debtMetrics(mergeRecords)); // 超预算 → 暂停并行先还债
```
