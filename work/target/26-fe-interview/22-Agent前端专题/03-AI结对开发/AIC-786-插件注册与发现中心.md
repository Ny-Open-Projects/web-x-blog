## AIC-786：笔试：实现插件化工具链的注册与发现中心

**需求**：实现 `createRegistry()`，返回对象含 `register(plugin)`、`discover(query)`、`enable(name)`、`disable(name)`。`plugin`: `{ name, capabilities: string[], apiVersion, enabled? }`。规则：1) register：若 name 已存在则更新覆盖；2) discover：`query` 为 `{ capability?, enabledOnly? }`，按 capabilities 含 capability 过滤，enabledOnly=true 时只返回已启用；返回按 name 字典序；3) enable/disable：改变 enabled 状态，不存在则抛 NOT_FOUND；4) register 时 apiVersion 主版本不等于 '3' 抛 INCOMPATIBLE（平台主版本 3）。边界：discover 无匹配返回 []；query 空返回全部。

**答**：
- 结论先行：注册中心是插件化架构的「单一事实来源」——所有发现、启停都通过它，避免各处维护插件状态导致不一致。
- 发现接口要支持「按能力检索」，让业务方「我要审查能力」而非「我要 reviewer 插件」，实现能力导向的解耦。
- 追问钩子：为什么 register 要支持覆盖更新？——插件升级后重新注册应能替换旧版本，而不是要求先手动删除。

```javascript
function createRegistry() {
  const store = {};
  return {
    register(p) {
      if (String(p.apiVersion).split('.')[0] !== '3') throw { code: 'INCOMPATIBLE' };
      store[p.name] = { ...p, enabled: p.enabled ?? false };
    },
    discover(query = {}) {
      return Object.values(store)
        .filter(p => !query.capability || p.capabilities.includes(query.capability))
        .filter(p => !query.enabledOnly || p.enabled)
        .sort((a, b) => a.name.localeCompare(b.name));
    },
    enable(n) { if (!store[n]) throw { code: 'NOT_FOUND' }; store[n].enabled = true; },
    disable(n) { if (!store[n]) throw { code: 'NOT_FOUND' }; store[n].enabled = false; },
  };
}
const reg = createRegistry();
reg.register({ name: 'z-review', capabilities: ['review'], apiVersion: '3.1' });
reg.register({ name: 'a-test', capabilities: ['test', 'review'], apiVersion: '3.0' });
reg.enable('z-review');
console.log(reg.discover({ capability: 'review', enabledOnly: true }).map(p => p.name)); // ['z-review']
console.log(reg.discover().length === 2);
try { reg.register({ name: 'old', apiVersion: '1.0' }); } catch (e) { console.log(e.code); } // INCOMPATIBLE
```


**评分点**：
- register 覆盖更新、apiVersion 主版本校验
- discover 按能力过滤 + enabledOnly + 字典序
- enable/disable 不存在抛 NOT_FOUND
- 返回浅拷贝隔离、边界无匹配
