## AIC-608：AI 连续三轮都没改对，怎么判断该回滚还是继续？

**答**：
- 结论先行：**判断依据是「是否收敛」而非「试了几次」**。如果每轮 diff 在变小、错误在收敛，继续；如果 diff 在原地打转或越来越大（发散），立即回滚止损（AIC-165 无进展检测 / AIC-557 迭代收敛）。
- 继续的信号：1) 错误描述逐轮具体化（从「不对」到「第 3 个 case 边界错了」）；2) diff 范围逐轮缩小；3) AI 能定位到新的根因。此时应继续，通常是上下文还差一块。
- 回滚的信号：1) 同一段代码被反复改回改去（AIC-430 循环检测）；2) 引入的新错误多于修复的；3) AI 开始「幻觉式自信」否认明显事实。此时继续只会累积「解释性债务」。
- 回滚的正确姿势：**回到最近一个「已知良好」的 commit，而不是逐条撤销 AI 的改动**；同时保留失败尝试的记录作为下一轮 prompt 的「负面示例」（告诉 AI 哪些路走不通）。
- 追问钩子：为什么「回滚到 commit」优于「让 AI 自己撤销」？——因为 AI 撤销时可能再次引入新错误，形成「修-坏-修」循环；git 回滚是确定性的，把不确定性排除在恢复路径之外。

```typescript
type Round = { diffSize: number; newBugs: number; fixedBugs: number; rootCause?: string };

function shouldRollback(rounds: Round[]): { action: 'continue' | 'rollback'; reason: string } {
  if (rounds.length < 2) return { action: 'continue', reason: '样本不足' };
  const last = rounds[rounds.length - 1];
  const prev = rounds[rounds.length - 2];
  // 发散：diff 变大且新增 bug 多于修复
  if (last.diffSize > prev.diffSize * 1.5 && last.newBugs > last.fixedBugs) {
    return { action: 'rollback', reason: '改动发散，新增多于修复' };
  }
  // 原地打转：连续两轮 diff 相同且无新根因
  if (last.diffSize === prev.diffSize && !last.rootCause) {
    return { action: 'rollback', reason: '原地打转，无新根因' };
  }
  // 收敛：diff 变小且有新根因
  if (last.diffSize < prev.diffSize && last.rootCause) {
    return { action: 'continue', reason: '错误在收敛' };
  }
  return { action: 'continue', reason: '暂无回滚信号' };
}
```
