## AIC-921：笔试：实现「三方合并的意图保护器」（基于语义块而非行，保留各 Agent 改动意图）
**答**：
- 核心需求：实现 `intentMerge(base, changes)`。`base` 为基础代码字符串，`changes: { agent, blocks: { id, content }[] }[]` 为各 Agent 的改动块（id 标识语义块）。返回 `{ code, conflicts }`。
- 合并规则：① 不同 id 的块直接拼接（按 id 在 base 中的位置排序）；② 同一 id 被多个 agent 改动 → 若 content 相同则合并为一块，不同则记入 conflicts 并保留 base 原块（保守策略）；③ 未改动的块保持 base。
- 边界：changes 为空返回 base；块 id 在 base 中不存在则忽略并记录；保持代码顺序确定性（按 id 字典序或 base 出现顺序）。
- 语义：这是「保守型合并」——冲突时不猜测，而是保留原状并上报，让人/上层决策；比逐行合并更能保住改动的整体意图。
- 追问钩子：能指出「语义块划分的质量决定合并效果，需要 Agent 在产出时主动标注块边界」的候选人理解该方案的前提条件。

```typescript
function intentMerge(base, changes = []) {
  const blocks = new Map(); // id -> { content, agents:Set }
  const order = [];
  // 用 /* @block:id */ 注释在 base 中标记语义块边界
  const parts = base.split(/(\/\* @block:[^ ]+ \*\/)/);
  for (const p of parts) {
    const m = p && p.match(/@block:([^ ]+)/);
    if (m) { order.push(m[1]); blocks.set(m[1], { content:'', agents:new Set() }); }
  }
  for (const ch of changes) for (const b of ch.blocks) {
    if (!blocks.has(b.id)) continue;
    const cur = blocks.get(b.id);
    cur.agents.add(ch.agent);
    if (!cur.content) cur.content = b.content;
    else if (cur.content !== b.content) cur.agents.add('CONFLICT:' + b.id);
  }
  const conflicts = [...blocks.entries()].filter(([,v]) => [...v.agents].some(a => a.startsWith('CONFLICT:'))).map(([k])=>k);
  return { code: order.map(id => blocks.get(id).content).join('\n'), conflicts };
}
console.log(intentMerge('/* @block:price */old', [{agent:'A',blocks:[{id:'price',content:'new'}]}]));
```
**评分点**：
- 按语义块 id 合并，不同 id 直接拼接且保持 base 顺序（确定性）。
- 同 id 多 agent：content 相同合并、不同记入 conflicts 并保留 base（保守策略）。
- base 中不存在的 id 被忽略，changes 为空返回 base，边界完整。
- 返回 code + conflicts，冲突上报而非擅自取舍。
- 能说明块划分质量是前提、需 Agent 主动标注语义块（加分项）。
