## AIC-707：结对长会话中上下文腐烂的识别与重置时机如何把握

**答**：
- 结论先行：上下文腐烂指「会话越长，早期错误/无关信息越积累，AI 输出质量反而下降」；识别信号包括重复提问、引用已废弃的变量、遗漏早已确认的约束；一旦出现就应重置而非继续对话。
- 识别信号：1) AI 反复询问已经回答过的问题；2) 输出中出现已被删除/改名的符号；3) 新代码与既定约束冲突；4) 摘要比原文还长（压缩失效）。
- 重置策略：不是清空，而是「结构化续接」——把已确认的决策、文件状态、待办写成新会话的种子 prompt，丢弃过程性废话。
- 追问钩子：为什么「压缩上下文」有时反而加速腐烂？——压缩会丢失细节约束，把「近似正确」变成「自信错误」；关键约束必须原样保留。

```javascript
// 上下文腐烂检测：重复提问率 + 陈旧符号引用
function rotSignals(messages) {
  const asked = new Map(), stale = [];
  let repeats = 0;
  for (const m of messages) {
    const q = m.text.trim();
    asked.set(q, (asked.get(q) ?? 0) + 1);
    if (asked.get(q) > 1) repeats++;
    if (m.removedSymbols?.some(s => m.text.includes(s))) stale.push(q);
  }
  const repeatRate = messages.length ? repeats / messages.length : 0;
  return { repeatRate, staleCount: stale.length, shouldReset: repeatRate > 0.3 || stale.length > 2 };
}
console.log(rotSignals([
  { text: '用 redux?', removedSymbols: [] },
  { text: '用 redux?', removedSymbols: [] },
  { text: '改用 mobx 但还在用 store', removedSymbols: ['store'] },
])); // shouldReset: true
```
