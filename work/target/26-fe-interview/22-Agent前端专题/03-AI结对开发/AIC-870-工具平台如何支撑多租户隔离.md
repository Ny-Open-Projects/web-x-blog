## AIC-870：AI 工具平台如何支撑多租户隔离，让各团队互不干扰？
**答**：
- 隔离分三个层面：**数据隔离**（一个团队的 prompt、评测集、调用日志不能被另一团队看到）、**资源隔离**（配额/并发互不挤占，AIC-813）、**配置隔离**（各团队用自己的模型供应商、密钥、规则，互不覆盖）。
- 实现：请求全链路携带 `tenantId`，所有存储查询强制带租户过滤（最好在数据访问层强制注入，而非靠业务记得写 where——漏写就是数据泄露）；密钥按租户托管，不共享。
- 逻辑隔离 vs 物理隔离：普通团队用逻辑隔离（同一套服务 + 租户标记），高敏感团队（法务、金融）用物理隔离（独立实例/独立模型端点）；成本与安全的权衡。
- 审计：跨租户访问一律拒绝并记录告警；提供「租户健康度」视图（各团队的用量、成本、配额、是否触及隔离边界）。
- 追问钩子：能说出「租户过滤要在数据访问层强制注入，不能靠每个业务记得写 where」的候选人，理解隔离最容易在「忘了写」处失守。

```typescript
// 租户上下文：所有数据访问强制带 tenantId
type Ctx = { tenantId: string; userId: string };

class TenantStore {
  // 数据访问层强制注入租户条件，业务无法绕过
  async query(ctx: Ctx, table: string, where: Record<string, any> = {}) {
    if (!ctx.tenantId) throw new Error('tenant context required');
    const scoped = { ...where, tenantId: ctx.tenantId }; // 强制拼接
    console.log(`SELECT * FROM ${table} WHERE`, scoped);
    return db.query(table, scoped);
  }
  // 跨租户访问显式拒绝并告警
  async assertTenant(ctx: Ctx, resourceTenant: string) {
    if (ctx.tenantId !== resourceTenant) {
      audit.alert('cross-tenant access attempt', { ctx, resourceTenant });
      throw new Error('cross-tenant access denied');
    }
  }
}
const store = new TenantStore();
store.query({ tenantId:'team-a', userId:'u1' }, 'prompts', { status:'active' });
// WHERE { status:'active', tenantId:'team-a' } —— 隔离自动生效
```
