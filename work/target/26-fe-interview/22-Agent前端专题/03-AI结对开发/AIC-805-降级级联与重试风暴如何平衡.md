## AIC-805：模型降级级联时，如何避免「重试风暴」把备用模型也打挂？
**答**：
- 重试风暴的根因：主模型超时 → 全量请求同一时刻涌向备模型 → 备模型过载 → 继续降级，形成雪崩。核心对策是**指数退避 + 随机抖动（jitter）**，把重试时刻打散。
- 级联要有**熔断**：对每条模型链路独立维护circuit breaker，连续失败达到阈值后直接短路（快速失败），隔一段时间半开探测恢复，避免反复打挂。
- 配合**并发上限与请求排队**：每个模型设独立信号量，超出上限的请求进入有限队列或直接降级到更便宜的模型，而不是无限排队放大延迟。
- 可加**对冲请求（hedged request）**：主模型延迟超过 P95 时并发发一份到备模型，取先返回者——但要对冲比例设上限，防止流量翻倍。
- 追问钩子：能说出「jitter 打散 + 每链路独立熔断 + 并发闸门」三件套，并提到「降级要有降级终点（兜底模型/缓存）」的候选人，是踩过线上雪崩的。

```typescript
const sleep = (ms: number) => new Promise(r => setTimeout(r, ms));

class Breaker {
  private fails = 0;
  private state: 'closed' | 'open' | 'half' = 'closed';
  async call<T>(fn: () => Promise<T>): Promise<T> {
    if (this.state === 'open') throw new Error('circuit open');
    try {
      const res = await fn();
      if (this.state === 'half') this.state = 'closed';
      this.fails = 0;
      return res;
    } catch (e) {
      if (++this.fails >= 5) {
        this.state = 'open';
        setTimeout(() => (this.state = 'half'), 10_000); // 半开探测
      }
      throw e;
    }
  }
}

async function cascade<T>(req: any, chain: Array<{ call: () => Promise<T> }>): Promise<T> {
  const breakers = chain.map(() => new Breaker());
  for (let i = 0; i < chain.length; i++) {
    try {
      return await breakers[i].call(chain[i].call);
    } catch {
      const backoff = Math.min(100 * 2 ** i, 2000);
      await sleep(backoff + Math.random() * backoff); // 指数退避 + jitter 打散
    }
  }
  throw new Error('all models exhausted'); // 必须有降级终点
}
```
