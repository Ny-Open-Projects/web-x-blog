## AIC-820：多模型平台如何做到「一次接入、多处消费」？
**答**：
- 核心是把能力沉淀为**平台服务**而非散落在业务里：统一网关暴露标准 API（chat / stream / embed / evaluate），上层应用、内部工具、CI 门禁、IDE 插件都从同一入口消费，模型变更只改平台一处。
- 分层：`接入层（适配器）→ 能力层（注册/协商/编排）→ 服务层（统一 API + 配额 + 血缘）→ 消费层（Web/IDE/CI/机器人）`。每层只对下一层负责，避免消费方直连模型厂商。
- 多消费形态要统一语义：流式/非流式、同步/异步任务、批处理的接口要共享同一份 `Request/Response` schema（可用 protobuf / JSON Schema 定义），保证「换一个消费端不改调用逻辑」。
- 平台要提供**自助能力**：文档、SDK、沙箱、示例 prompt 模板，让业务团队自助接入，平台团队不做"人肉转发器"——否则平台成为瓶颈（呼应 AIC-879）。
- 追问钩子：追问「不同消费方对延迟容忍不同怎么办」——能答出「在服务层用 SLA 分层 + 优先级队列，而非给每个消费方单独部署一套」的候选人具备平台复用思维。

```typescript
// 统一服务层：所有消费方共享一个入口与 schema
type Req = { prompt: string; capability: string; tenant: string;
  mode?: 'sync' | 'stream' | 'batch'; priority?: 'high' | 'low' };

class AIPlatform {
  constructor(private registry: any, private quota: any, private tracer: any) {}

  async consume(req: Req) {
    const root = this.tracer.startRoot({ tenant: req.tenant, capability: req.capability });
    if (!await this.quota.acquire(req.tenant, req.priority ?? 'low')) {
      throw new Error('quota exceeded — retry later');
    }
    try {
      const candidates = this.registry.find(req.capability);
      const chosen = candidates[0];                 // 协商（简化）
      const adapter = getAdapter(chosen.modelId);
      const span = this.tracer.span(root, 'call', { modelId: chosen.modelId });
      const res = await adapter.chat({ prompt: req.prompt });
      this.tracer.finish(span);
      return res;
    } finally {
      this.quota.release(req.tenant);
      this.tracer.finish(root);
    }
  }
}
// Web、IDE 插件、CI 门禁都调用 platform.consume(req)，模型升级对它们透明
```
