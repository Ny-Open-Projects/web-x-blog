## AIC-747：笔试：实现 AI 质量门禁的多级阈值校验器

**需求**：实现 `qualityGate(metrics, policy)`。`metrics`: `{ coverage,复杂度, security, review }`（各 0-100）；`policy`: `{ levels: [{ name, min: Record<dim, number> }] }`（从宽松到严格排序）。规则：1) 从最严格级别开始向下找第一个满足所有维度 `metrics[d] >= min[d]` 的级别；2) 全不满足返回 `{ level:'block', failed: ... }`，failed 列出最严格级别中未达标的维度；3) 命中某级别返回 `{ level, gaps: {} }`；4) 维度值非数字按 0 处理。边界：metrics 空（全 0 → block）；policy.levels 空（block）。

**答**：
- 结论先行：多级门禁比单一阈值更实用——「允许带条件合并」比「一刀切阻断」更贴合工程现实；从严到宽找第一个可达级别，能给出最接近的质量档位。
- failed 要基于「最严格级别」计算，让开发者知道「要达到最高标准还差什么」，这是改进方向。
- 追问钩子：为什么命中较低级别时仍要记录 gap？——gap 反映与更高标准的距离，是持续改进的输入，而非一次性放行。

```javascript
function qualityGate(metrics = {}, policy = {}) {
  const levels = policy.levels ?? [];
  const num = v => (typeof v === 'number' && v >= 0 ? v : 0);
  const sorted = [...levels].sort((a, b) =>
    Object.values(b.min ?? {}).reduce((s, x) => s + x, 0) - Object.values(a.min ?? {}).reduce((s, x) => s + x, 0));
  for (const lv of sorted) {
    const gaps = {};
    for (const [d, min] of Object.entries(lv.min ?? {})) {
      if (num(metrics[d]) < min) gaps[d] = min - num(metrics[d]);
    }
    if (!Object.keys(gaps).length) return { level: lv.name, gaps };
  }
  const strictest = sorted[sorted.length - 1];
  const failed = strictest ? Object.keys(strictest.min ?? {}).filter(d => num(metrics[d]) < strictest.min[d]) : [];
  return { level: 'block', failed };
}
const policy = { levels: [
  { name: 'strict', min: { coverage: 90, security: 95 } },
  { name: 'basic', min: { coverage: 60, security: 70 } },
] };
console.log(qualityGate({ coverage: 75, security: 80 }, policy).level);     // basic
console.log(qualityGate({ coverage: 95, security: 96 }, policy).level);     // strict
console.log(qualityGate({ coverage: 50, security: 50 }, policy).level);     // block
console.log(qualityGate({}, policy).failed);                                // ['coverage','security']
```


**评分点**：
- 从最严格级别向下找首个全部达标级别
- failed 基于最严格级别列未达标维度
- 非数字按 0、阈值含等号
- 能解释「多级门禁优于一刀切」属加分
