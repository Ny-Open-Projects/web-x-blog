## AIC-809：用「影子流量」验证新模型版本，具体怎么做才不影响线上？
**答**：
- 影子流量 = 线上请求的副本同时发给**候选模型**，但候选结果**不返回给用户**、不写业务库，只落到旁路存储用于对比。用户路径完全不受影响。
- 关键实现：在网关层克隆请求（注意脱敏），给主/影子请求打同一个 `shadowId`；影子调用设**独立超时与并发上限**，绝不能因为影子慢而拖慢主链路——最好异步 fire-and-forget。
- 对比维度：答案质量（自动裁判/规则）、延迟 P95、成本、错误率；按任务类型分层统计，避免整体均值掩盖局部退化。
- 采样策略：不必 100% 镜像，按 5%~20% 采样即可；灰度期逐步提升采样率，累积足够样本再决策。
- 追问钩子：追问「影子请求有副作用怎么办」——能说出「候选模型若带工具调用权限必须隔离在沙箱，绝不能真的发邮件/下单」的候选人，对 AI 时代的安全边界很敏感。

```typescript
async function handleRequest(req: any, main: any, shadow?: any) {
  const shadowId = crypto.randomUUID();
  // 主链路：同步等待，决定用户看到的响应
  const mainRes = await main.chat(req);

  if (shadow && shouldMirror(req)) {           // 采样 10%
    // 影子链路：异步、独立超时，失败静默，绝不影响主链路
    void Promise.race([
      shadow.chat({ ...req, metadata: { shadowId } })
        .then(res => storeComparison({ shadowId, res, mainRes: mainRes.text }))
        .catch(err => logShadowError(shadowId, err)),
      new Promise((_, rej) => setTimeout(() => rej(new Error('shadow timeout')), 3000)),
    ]).catch(() => {}); // 吞掉所有影子错误
  }
  return mainRes; // 用户永远只看到主模型结果
}

function shouldMirror(req: any) {
  return Math.random() < 0.1 && !req.containsPII; // PII 请求不镜像
}
```
