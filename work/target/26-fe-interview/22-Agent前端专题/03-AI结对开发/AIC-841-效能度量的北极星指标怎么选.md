## AIC-841：AI 时代研发效能的「北极星指标」该怎么选？
**答**：
- 北极星指标要同时满足：**反映真实业务价值**（不是活动量）、**可归因于 AI**（能看出 AI 带来的增量）、**难以被刷**（不易操纵）、**团队可行动**（能通过行为改善）。
- 候选指标对比：代码行数（易刷、与价值无关）、采纳率（只说明用了，不说明有用）、**AI 代码存活率**（AI 生成代码在 N 天后仍未被改掉的比例，兼顾质量与真实采纳）、**需求交付周期**（业务价值直接体现但受多因素影响）、**逃逸缺陷数**（质量护栏）。
- 推荐组合而非单一：一个「价值指标」（交付周期/吞吐量）+ 一个「质量护栏」（逃逸缺陷/存活率）+ 一组「诊断指标」（采纳率、接受率、重试率）。单一指标必然被优化到失真（古德哈特定律，AIC-860）。
- 指标要**分层归因**：团队级看趋势，个人级只用于自我改进不用于考核——否则会引发刷指标和抵触。
- 追问钩子：能说出「存活率优于采纳率，因为它把质量和采纳合二为一」的候选人，理解指标设计的底层逻辑。

```typescript
type DevEvent = { dev: string; aiLines: number; keptAfter30d: number; reverted: number; escapedBugs: number };

function northStar(events: DevEvent[]) {
  const sum = events.reduce((a, e) => ({
    ai: a.ai + e.aiLines,
    kept: a.kept + e.keptAfter30d,
    reverted: a.reverted + e.reverted,
    bugs: a.bugs + e.escapedBugs,
  }), { ai: 0, kept: 0, reverted: 0, bugs: 0 });
  return {
    survivalRate: sum.ai ? +(sum.kept / sum.ai).toFixed(3) : 0, // 北极星：存活率
    qualityGuard: sum.bugs,                                     // 护栏：逃逸缺陷
    adoptionRaw: sum.ai,                                        // 诊断：原始采用量（不单独考核）
    verdict: sum.ai && sum.kept / sum.ai >= 0.7 && sum.bugs <= 3 ? 'healthy' : 'investigate',
  };
}
console.log(northStar([
  { dev:'a', aiLines:1000, keptAfter30d:800, reverted:50, escapedBugs:1 },
  { dev:'b', aiLines:500,  keptAfter30d:200, reverted:200, escapedBugs:3 },
])); // survivalRate 0.667 → investigate
```
