## AIC-931：AI 产出的审计链记了半年已经上千万条，查询慢、存储贵，如何做冷热分层而不丢可举证能力？
**答**：
- 按「热/温/冷」分层：热数据（近 30 天）存可查询库支撑日常检索；温数据（30~180 天）压缩归档到对象存储、建索引支持按需加载；冷数据（>180 天）只保留哈希摘要与索引指纹，不存全文。
- 关键是「摘要链」不丢：冷数据虽然删了明细，但保留每条的哈希与链式指针，仍可验证「某条记录曾存在且未被改」——结论：分层丢的是可检索性，不丢完整性证据。
- 按需回放：需要举证时，通过索引定位温/冷层，把对应记录重新载入验证哈希链，形成「低成本存储 + 按需举证」的组合。
- 追问钩子：能区分「查询性能」与「法律效力」两个维度，并强调哈希摘要保住法律效力、分层只优化查询的候选人，理解合规存储的精髓。

```typescript
// 审计数据分层：保留哈希摘要链，明细按温度迁移
const tiers = { hot:30, warm:180 }; // 天
function classify(ageDays) {
  if (ageDays <= tiers.hot) return 'hot';
  if (ageDays <= tiers.warm) return 'warm';
  return 'cold';
}
function archive(record, tier) {
  return tier === 'cold'
    ? { hash:record.hash, prev:record.prev, at:record.at, detailDropped:true }
    : record; // 热/温保留明细
}
function verifySummaryChain(summaries) { // 即使明细已删，链仍可验证
  return summaries.every((s,i) => i===0 || s.prev === summaries[i-1].hash);
}
console.log(classify(200)); // 'cold' → 只留哈希摘要
```
