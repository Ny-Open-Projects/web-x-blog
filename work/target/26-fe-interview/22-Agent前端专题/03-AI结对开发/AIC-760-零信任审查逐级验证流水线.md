## AIC-760：笔试：实现零信任审查的逐级验证流水线

**需求**：实现 `zeroTrustPipeline(artifact, stages)`。`artifact`: 任意产出对象；`stages`: `Array<{ name, check: (a)=>{pass:boolean, evidence?:string}, blocking: boolean }>`（按顺序执行）。规则：1) 顺序执行每个 stage 的 check，收集 `{ name, pass, blocking, evidence }`；2) 若某 blocking stage 失败，立即停止（短路），结果 `decision='block'`；3) 非 blocking stage 失败只记录不阻断；4) 全部通过 `decision='pass'`；5) 返回 `{ results, decision, stoppedAt? }`。边界：stages 空（results=[]、decision='pass'）；check 抛异常视为失败（evidence 记错误信息）；blocking 缺省视为 true。

**答**：
- 结论先行：零信任流水线 = 多道独立验证 + 阻塞短路 + 证据留痕；「阻塞失败立即停」避免浪费后续验证资源，也防止错误产出继续流动。
- 非阻塞阶段失败要保留记录（软告警），它是质量改进的线索，但不应阻断交付；异常要被捕获为失败，不能让流水线崩溃。
- 追问钩子：为什么每级都要记录 evidence？——事后审计与事故归因需要知道「当时是哪道验证放的行」，无证据的通过等于没验证。

```javascript
function zeroTrustPipeline(artifact, stages = []) {
  const results = [], blockedBy = [];
  for (const s of stages) {
    let out;
    try { out = s.check(artifact) ?? { pass: false }; }
    catch (e) { out = { pass: false, evidence: 'error: ' + e.message }; }
    const blocking = s.blocking !== false;
    results.push({ name: s.name, pass: !!out.pass, blocking, evidence: out.evidence });
    if (!out.pass && blocking) return { results, decision: 'block', stoppedAt: s.name };
  }
  return { results, decision: 'pass' };
}
const r = zeroTrustPipeline({ x: 1 }, [
  { name: 'lint', check: () => ({ pass: true, evidence: 'ok' }) },
  { name: 'security', check: () => ({ pass: false, evidence: '高危漏洞' }) }, // 阻塞
  { name: 'style', check: () => ({ pass: true }) },                          // 不执行
]);
console.log(r.decision === 'block' && r.stoppedAt === 'security');
console.log(r.results.length === 2); // 短路，第三级未执行
console.log(zeroTrustPipeline({}, []).decision === 'pass'); // 边界
```


**评分点**：
- 顺序执行 + 阻塞失败立即短路
- 非阻塞失败只记录不阻断
- check 异常捕获为失败、evidence 留痕
- 边界（空 stages）处理
