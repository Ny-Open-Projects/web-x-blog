## AIC-974：两条规范冲突了：「安全要求所有依赖升级走完整评审」vs「大促前速度优先允许快速合并」，如何仲裁？
**答**：
- 先「定优先级原则」：安全/合规类规范是底线，通常高于效率类；但底线也可在「有等价补偿控制」时豁免（如快速合并但加更严的运行时监控）——结论：仲裁要有原则而非临时拍脑袋。
- 建立「仲裁机制」：明确谁有权裁决（如架构委员会/安全 owner）、裁决要记录理由与有效期、争议大时升级；避免一线人员各自解读。
- 让规则本身「少冲突」：把「速度优先」写成「在满足安全底线前提下的加速通道」，从规则设计上消除对立，而非靠事后仲裁。
- 追问钩子：能提出「规则冲突暴露的是规则设计问题，应回到源头用『底线 + 条件分支』表达，而不是留一个靠人拍板的灰色地带」的候选人，具备治理设计能力。

```typescript
// 规则优先级 + 补偿控制仲裁
const rules = [
  { id:'SEC-REVIEW', kind:'security', priority:100 },
  { id:'SPEED', kind:'efficiency', priority:30 },
];
function arbitrate(conflict, context) {
  const sorted = conflict.slice().sort((a,b)=>b.priority-a.priority);
  // 安全底线不可直接被效率规则推翻，但可用补偿控制有条件豁免
  const canWaive = context.compensatingControl === 'enhanced-monitoring' && context.approvedBy;
  return {
    winner: canWaive ? 'SPEED(有条件)' : sorted[0].id,
    conditions: canWaive ? ['加强运行时监控','安全owner审批','限时48h'] : [],
  };
}
console.log(arbitrate(rules, { compensatingControl:'enhanced-monitoring', approvedBy:'sec-lead' }));
```
