## AIC-842：都说不能用代码行数衡量效能，AI 时代为什么更不能？
**答**：
- AI 让代码生成的边际成本趋近于零：一天能产出过去一周的行数，行数与价值彻底脱钩——「生成 5000 行又删掉 4000 行」在行数上是赢家，在价值上是灾难。
- 行数会激励错误行为：拆分函数凑行、复制粘贴、拒绝重构（重构减少行数）、把简单问题复杂化。AI 时代这些行为可以**自动批量制造**。
- 更好的代理指标：**AI 代码存活率**（生成的代码 N 天后还在）、**净增有效代码量**（考虑删除与重构）、**变更前置时间**（commit 到上线的时长）、**需求吞吐**（完成的故事点/需求数）。
- 即便用行数也要配合质量护栏：逃逸缺陷率、回滚率、review 返工率——单看任何正面指标都会被刷。
- 追问钩子：能说出「AI 时代代码是消耗品，衡量的是留下来的价值而不是生产量」的候选人，把握了范式转变的本质。

```typescript
// 同样是 1000 行生成代码，真实价值天差地别
type Dev = { generated: number; deleted: number; survived: number; bugs: number; features: number };

function realValue(d: Dev) {
  const net = d.generated - d.deleted;       // 净留存（仍不完美，但比毛生成好）
  const survival = d.generated ? d.survived / d.generated : 0;
  return {
    rawLines: d.generated,                   // 好看但无意义的数字
    netLines: net,
    survival: +survival.toFixed(2),
    bugsPerFeature: d.features ? +(d.bugs / d.features).toFixed(2) : 0,
    // 综合：净留存 × 存活率 ÷ 缺陷，比单纯行数接近价值
    valueScore: +(net * survival / (1 + d.bugs)).toFixed(0),
  };
}
console.log(realValue({ generated: 5000, deleted: 4000, survived: 300, bugs: 5, features: 1 }));
// rawLines 5000 很唬人，valueScore 却很低 —— 这就是为什么不能看行数
console.log(realValue({ generated: 300, deleted: 50, survived: 280, bugs: 0, features: 3 }));
```
