## AIC-987：笔试：实现「评审规则效果评估器」（计算精确率/召回率/F1 并给出治理建议）
**答**：
- 核心需求：实现 `evalRules(results, opts)`。`results: { rule, reported:boolean, actualIssue:boolean }[]`（reported=规则是否报告，actualIssue=是否真的有问题）。返回按 rule 聚合的 `{ precision, recall, f1, verdict }` 及 overall。
- 指标：TP=reported且actualIssue，FP=reported且非issue，FN=未reported但是issue；precision=TP/(TP+FP)，recall=TP/(TP+FN)，F1=2PR/(P+R)（分母 0 记 0）。
- verdict 建议：precision<0.5 → "降误报(加上下文/降权)"；recall<0.5 → "补漏报(提敏感/加规则)"；两者都≥0.7 → "健康"；否则 "观察"。opts 可配置阈值。
- 边界：results 为空返回空 map 与 overall 全 0；各指标保留 2 位小数；按 rule 名排序确定性。
- 语义：这是规则治理的「体检工具」——用标注数据量化每条规则的健康度，指导优化方向；标注质量决定结论可信度。
- 追问钩子：能指出「召回率需要一个『所有真问题』的标注集，而这在现实中往往不全，所以 recall 常被低估——评估要说明分母来源」的候选人懂评估的局限性。

```typescript
function evalRules(results=[], opts={}) {
  const pTh=opts.precisionThreshold??0.5, rTh=opts.recallThreshold??0.5;
  const groups=new Map();
  for(const r of results){ if(!groups.has(r.rule))groups.set(r.rule,[]); groups.get(r.rule).push(r); }
  const calc=(evs)=>{
    const tp=evs.filter(e=>e.reported&&e.actualIssue).length;
    const fp=evs.filter(e=>e.reported&&!e.actualIssue).length;
    const fn=evs.filter(e=>!e.reported&&e.actualIssue).length;
    const p=tp/(tp+fp||1), r=tp/(tp+fn||1), f1=2*p*r/(p+r||1);
    const verdict=p<pTh?'降误报':r<rTh?'补漏报':p>=0.7&&r>=0.7?'健康':'观察';
    return { precision:+p.toFixed(2), recall:+r.toFixed(2), f1:+f1.toFixed(2), verdict };
  };
  const byRule=Object.fromEntries([...groups.entries()].sort((a,b)=>a[0].localeCompare(b[0]))
    .map(([k,v])=>[k,calc(v)]));
  return { byRule, overall:calc(results) };
}
console.log(evalRules([
  {rule:'R',reported:true,actualIssue:true},{rule:'R',reported:true,actualIssue:false},
  {rule:'R',reported:false,actualIssue:true},
]).byRule.R); // precision .5 recall .5
```
**评分点**：
- TP/FP/FN 统计正确，precision/recall/F1 计算与除零处理正确。
- verdict 四档建议（降误报/补漏报/健康/观察）逻辑正确且阈值可配。
- 按 rule 分组聚合、按名排序确定性、指标保留 2 位小数。
- 空 results 边界处理，overall 聚合全体，代码可运行。
- 明确「recall 分母来源影响结论可信度」（加分项）。
