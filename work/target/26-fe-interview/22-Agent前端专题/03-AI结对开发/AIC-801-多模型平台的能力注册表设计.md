## AIC-801：多模型平台的「能力注册表」该怎么设计，才能做到一次接入处处可用？
**答**：
- 能力注册表是「模型能力的单一事实源」：把模型抽象为一组可声明的能力（code-gen、long-context、vision、tool-call、json-mode），业务侧不再硬编码模型名，只声明所需能力。
- 结构要带版本与约束：`{ modelId, provider, capabilities: [{ name, version, maxTokens, costPer1k, latencyP50, constraints }], lifecycle: stable|beta|deprecated }`。只写「支持 vision」不够，必须写清「支持 vision 但不支持流式」这类边界。
- 发现机制：任务侧给出「能力 + 预算 + 延迟」三元组，注册中心做匹配并排序（配合 AIC-803 的匹配器）——这是「协商」而不是「路由表 if-else」。
- 热更新：注册项由配置中心下发，监听变更事件；新模型只需注册 + 通过契约测试即可上线，调用方零改动。
- 追问钩子：能说出「注册表（描述）→ 协商（选择）→ 适配器（执行）」三层解耦的候选人，是真做过平台化而非只调过 API。

```typescript
type Capability = {
  name: string; version: string; maxTokens: number;
  costPer1k: number; latencyP50: number; constraints: string[];
};
type ModelEntry = {
  modelId: string; provider: string;
  capabilities: Capability[];
  lifecycle: 'stable' | 'beta' | 'deprecated';
};

class CapabilityRegistry {
  private models = new Map<string, ModelEntry>();

  register(entry: ModelEntry) {
    if (this.models.has(entry.modelId)) throw new Error('duplicate modelId');
    this.models.set(entry.modelId, entry);
  }

  find(cap: string, budget: number): ModelEntry[] {
    return [...this.models.values()]
      .filter(m => m.lifecycle === 'stable')
      .filter(m => m.capabilities.some(c =>
        c.name === cap && c.costPer1k <= budget))
      .sort((a, b) => this.cost(a, cap) - this.cost(b, cap));
  }

  private cost(m: ModelEntry, cap: string) {
    return m.capabilities.find(c => c.name === cap)!.costPer1k;
  }
}
// 新模型接入 = register 一条元数据，业务代码不动
```
