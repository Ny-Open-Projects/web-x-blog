## AIC-878：AI 工具平台的「开放扩展点」如何设计，既灵活又不失控？
**答**：
- 扩展点是平台预留的、允许业务注入自定义逻辑的位置（如自定义模型适配器、自定义评测器、自定义审批策略）。设计原则是**稳定内核 + 窄接口 + 明确契约**：扩展点接口要小而稳定（一次定义多年不变），复杂逻辑放在扩展实现里而不是塞进平台。
- 典型模式：插件/钩子（生命周期 hook，如 `beforeCall`、`afterEval`）、策略注入（把「选谁/能否放行」交给业务策略函数）、适配器接口（接新模型/新工具）。每个扩展点要定义清晰的输入输出与错误语义。
- 防失控：扩展运行在沙箱里（AIC-866）、有超时与资源限制、可观测（扩展调用也埋点）、可降级（扩展挂了平台走默认行为而非整体崩）。**扩展永远不能绕过平台的安全与合规底线**。
- 契约测试：平台提供扩展的测试套件（conformance test），第三方扩展必须通过才能注册——这是「开放但不失控」的关键闸门。
- 追问钩子：能说出「扩展点接口要小而稳定、扩展要过契约测试且挂了能降级到平台默认行为」的候选人，理解开放性与稳定性的平衡靠机制而非自觉。

```typescript
// 平台定义窄接口 + 默认行为，业务通过注册扩展注入
type Hook = { name: string; run: (ctx: any) => Promise<any> };

class Platform {
  private hooks = new Map<string, Hook>();
  registerHook(h: Hook) {
    // 注册时跑契约校验，不合规拒绝
    if (typeof h.run !== 'function') throw new Error('invalid hook');
    this.hooks.set(h.name, h);
  }
  async beforeCall(ctx: any) {
    const h = this.hooks.get('beforeCall');
    if (!h) return ctx;
    try {
      return await withTimeout(h.run(ctx), 1000); // 沙箱 + 超时
    } catch {
      return ctx; // 扩展挂了 → 降级到默认行为，平台不崩
    }
  }
}
const p = new Platform();
p.registerHook({ name:'beforeCall', run: async (ctx) => ({ ...ctx, tenant:'verified' }) });
// 扩展只能增强 ctx，不能绕过平台安全检查（平台在 hook 之后仍做自己的校验）
```
