## AIC-822：「黄金评测集」如何治理才不会变成过期资产？
**答**：
- 评测集要有**分层结构**：按任务类型、难度、场景标签分层，每层有最小样本量；避免全是简单题导致「通过率 95% 但线上翻车」。
- 来源多元：历史 bug 转化（最有价值）、真实线上请求脱敏采样、人工构造边界用例；纯合成数据会与真实分布脱节，要标注来源比例。
- 生命周期治理：每条用例有 owner、创建时间、最后命中时间；定期清理「模型早就稳定通过」的用例（降低权重），补充新出现的失败模式。**评测集要像代码一样 review 和版本化**。
- 防污染：评测集不能进模型训练/prompt few-shot，不能被模型看到，否则指标虚高；开放集与封闭集分开，定期用「新题」测泛化。
- 追问钩子：能说出「评测集本身需要版本化 + 防数据污染 + 随模型能力演进淘汰旧题」的候选人，理解评测集是活资产而非一次性交付物。

```typescript
type Case = {
  id: string; prompt: string; expectation: string;
  tags: string[]; source: 'bug' | 'online' | 'synthetic';
  owner: string; createdAt: number; lastHitAt: number;
  passRate: number; // 最近 N 次评测的通过率
};

// 评测集健康度治理：淘汰过易/过期用例，标记覆盖缺口
function auditSet(cases: Case[], now = Date.now()) {
  const stale = cases.filter(c =>
    c.passRate >= 0.99 && now - c.lastHitAt > 90 * 864e5); // 早就会且长期没区分度
  const coverage = new Map<string, number>();
  for (const c of cases) for (const t of c.tags)
    coverage.set(t, (coverage.get(t) ?? 0) + 1);
  const gaps = ['boundary', 'multilingual', 'tool-call'].filter(t => (coverage.get(t) ?? 0) < 10);
  return {
    retire: stale.map(c => c.id),          // 降权或归档
    gaps,                                   // 需要补题的维度
    syntheticRatio: cases.filter(c => c.source === 'synthetic').length / cases.length,
  };
}
// 经验：syntheticRatio 建议 < 0.5，否则与真实分布脱节
```
