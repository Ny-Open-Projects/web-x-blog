## AIC-853：效能平台的数据管道，如何兼顾实时性和准确性？
**答**：
- 这是个经典权衡：实时口径（流处理）快但易受乱序/迟到数据影响而不准；批口径准确但 T+1。解法是 **Lambda/Kappa 分层**：热路径用流处理给「近实时粗指标」，冷路径用批处理给「T+1 精确指标」，同一套语义定义。
- 关键统一手段：用**事件时间（event time）而非处理时间**聚合，配合 watermark 处理迟到数据；迟到的数据触发「回补修正」，看板标明「数据仍在回填」。
- 语义层要单一：指标定义（如「存活率」的计算口径）在一处声明，流批共用，避免实时和离线算出两个数互相打架——这是最常见的信任崩塌点。
- 准确性校验：定期对账流处理与批处理结果，差异超阈值告警；对缺失数据（埋点挂了）要有显式标记而非当成 0，避免指标假跌。
- 追问钩子：能说出「流批指标必须用同一套语义定义、差异要可解释」的候选人，处理过真实数据平台的信任问题。

```typescript
// 事件时间聚合 + watermark 处理迟到数据
type Event = { ts: number; type: string; session: string };

function aggregateWithWatermark(events: Event[], watermarkMs = 5000) {
  const maxTs = Math.max(...events.map(e => e.ts), 0);
  const cutoff = maxTs - watermarkMs;
  const onTime = events.filter(e => e.ts >= cutoff);  // 准点数据 → 实时口径
  const late = events.filter(e => e.ts < cutoff);     // 迟到数据 → 回填修正
  return {
    realtime: onTime.length,
    lateArrivals: late.length,
    note: late.length ? `${late.length} 条迟到数据待回填修正` : '数据完整',
  };
}
console.log(aggregateWithWatermark([
  { ts: 1000, type:'accept', session:'s1' },
  { ts: 9000, type:'accept', session:'s2' },
  { ts: 2000, type:'reject', session:'s3' }, // 迟到
], 3000)); // realtime 2, lateArrivals 1
```
