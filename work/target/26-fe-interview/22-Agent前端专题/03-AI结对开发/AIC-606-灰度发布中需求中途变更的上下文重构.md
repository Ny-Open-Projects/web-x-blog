## AIC-606：商品列表灰度发布做到一半需求改了，AI 结对怎么重构上下文？

**答**：
- 结论先行：**需求中途变更时不要在原会话里继续追加 prompt，而应「冻结旧会话 + 开新会话 + 迁移未变更的上下文资产」**。在原会话里改需求会让 AI 把废弃决策当事实，越聊越乱（AIC-013 长会话越聊越糊）。
- 三步重构：1) **标记废弃点**：把旧需求产生的代码/决策标记为 deprecated，明确告诉 AI「这些是旧方案，不要参考」；2) **保留有效资产**：保留与变更无关的部分（组件结构、工具函数、测试基建）作为新会话的种子上下文；3) **重写任务卡**（AIC-102）：用新需求重新写一份完整任务卡，而不是在原任务卡上打补丁。
- 变更影响面评估：先让 AI 输出「需求变更影响清单」——哪些文件/接口/测试受影响，人工确认后再开工，避免 AI 把整个模块重写。
- 追问钩子：为什么「开新会话」优于「在原会话里纠正」？——因为 LLM 的注意力对早期 token 存在锚定效应，废弃信息会持续污染后续生成；新会话相当于「清空工作记忆」，代价是迁移成本，收益是决策干净。

```typescript
type ContextAsset = { kind: 'code'|'decision'|'test'; path: string; content: string };

// 需求变更时：迁移未受影响的资产到新会话种子
function migrateContext(
  assets: ContextAsset[],
  changedPaths: Set<string>,
): { seed: ContextAsset[]; deprecated: ContextAsset[] } {
  const seed = assets.filter(a => !changedPaths.has(a.path));
  const deprecated = assets.filter(a => changedPaths.has(a.path));
  return { seed, deprecated };
}

// 新会话开头显式声明废弃项，防止 AI 复用旧决策
function buildNewSessionPrompt(seed: ContextAsset[], deprecated: ContextAsset[], newReq: string) {
  const seedText = seed.map(a => `[保留] ${a.path}:
${a.content}`).join('
');
  const depText = deprecated.map(a => `[废弃-勿参考] ${a.path}`).join('
');
  return `需求已变更，以下是保留资产与废弃项。
${depText}
${seedText}

新需求：${newReq}`;
}
```
