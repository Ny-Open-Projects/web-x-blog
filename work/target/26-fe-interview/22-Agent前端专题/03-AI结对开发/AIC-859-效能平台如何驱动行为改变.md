## AIC-859：效能看板上线半年没人改变行为，平台怎么真正驱动改进？
**答**：
- 根因是「**看见 ≠ 改变**」：看板只呈现数据，没有把洞察送到决策点。开发者不会每天主动打开看板，就像体检报告不解读就等于没体检。
- 把反馈嵌入工作流：在 PR 页面直接显示「本次 AI 建议存活情况」、在 IDE 里给「这类任务换个提示词模板效果更好」的即时建议——**在行为发生的时刻给反馈**，而不是事后看板。
- 把数据变成**可执行的实验**：平台不只说「存活率低」，还要给出假设与行动（「试试分段提示词」）并支持验证（改进后自动对比前后数据）——形成「洞察→行动→验证」闭环。
- 激励与氛围： celebrated 改进案例（谁的方法把存活率从 50% 提到 80%），用同伴影响代替自上而下的考核；把「使用 AI 的好实践」沉淀进团队规则文件与模板，让改进可复制。
- 追问钩子：能说出「反馈要送到行为发生的时刻（PR/IDE），并形成洞察-行动-验证闭环」的候选人，理解数据产品的最后一公里是行为设计。

```typescript
type Insight = { metric: string; gap: number; suggestion: string; experimentId: string };

// 不只是展示，而是生成可执行实验并跟踪验证
function driveChange(team: any, templates: any[]) {
  const insights: Insight[] = [];
  if (team.longDocSurvival < 0.6) {
    insights.push({
      metric: 'longDocSurvival', gap: 0.6 - team.longDocSurvival,
      suggestion: '将长文档任务改为"先分段后汇总"的提示词模板',
      experimentId: 'EXP-SEGMENT-001',
    });
  }
  return insights.map(i => ({
    ...i,
    // 闭环：改进后对比实验组 vs 基线的存活率
    verify: (after: number, baseline: number) => ({
      improved: after - baseline > 0.1,
      delta: +(after - baseline).toFixed(3),
    }),
  }));
}
console.log(driveChange({ longDocSurvival:0.45 }, []));
// 给出具体建议 + 实验 ID，改进后自动验证，形成闭环
```
