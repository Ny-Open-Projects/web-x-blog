## AIC-850：同一套效能数据，如何同时服务一线开发和管理层？
**答**：
- 核心矛盾：开发想看「我自己用得顺不顺、哪里能改进」，管理层要「团队趋势、投入产出、要不要继续投」。一份大屏服务不了两种诉求，必须**同数据源、多视图**。
- 三层视图：**个人层**（仅本人可见，展示采纳/存活/返工与改进建议，绝不用于排名）；**团队层**（聚合趋势、瓶颈环节、与基线对比，供团队复盘）；**组织层**（跨团队趋势、ROI、资源决策，只看聚合不看个人）。
- 个人层要「可行动」：不是给个分数，而是告诉「你的存活率低于团队均值，主要原因是 X 类任务提示词不清，建议试试 Y 模板」——数据要变成改进建议。
- 管理层视图要带**上下文注释**：指标突变的月份发生了什么（模型升级、新团队加入），否则容易被误读；同时展示置信区间，避免对噪声做决策。
- 追问钩子：能说出「个人层只反馈给本人、不进管理者视野，是数据能被执行层信任的前提」的候选人，理解信息权限设计对数据体系成败的影响。

```typescript
type Metric = { name: string; value: number; teamAvg: number; advice?: string };

function renderView(role: 'individual' | 'team' | 'org', metrics: Metric[]) {
  if (role === 'individual') {
    return metrics.map(m => ({
      name: m.name, value: m.value,
      gap: +(m.value - m.teamAvg).toFixed(2),
      advice: m.value < m.teamAvg
        ? (m.advice ?? `你的 ${m.name} 低于团队均值，建议复盘近期任务`)
        : '表现良好，可沉淀经验分享给团队',
    })); // 只返回给本人，含行动建议
  }
  if (role === 'team') {
    const avg = (k: keyof Metric) => 0; // 聚合逻辑省略
    return { trend: metrics.map(m => m.value), baseline: metrics.map(m => m.teamAvg) };
  }
  return { orgTrend: metrics.reduce((s, m) => s + m.value, 0) / metrics.length,
    note: '仅聚合数据，不下钻到个人' };
}
const metrics = [{ name:'survival', value:0.55, teamAvg:0.72, advice:'长文档任务先分段再交给 AI' }];
console.log(renderView('individual', metrics)); // 带 advice，驱动改进
console.log(renderView('org', metrics));         // 只有聚合趋势
```
