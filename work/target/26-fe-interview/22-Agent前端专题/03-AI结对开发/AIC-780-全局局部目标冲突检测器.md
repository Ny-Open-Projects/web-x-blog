## AIC-780：笔试：实现全局-局部目标冲突检测器

**需求**：实现 `detectConflict(units)`。`units`: `Array<{ team, localGain, globalImpact: { cycle, quality, downstreamCost } }>`（`localGain`: 本团队指标提升比例；globalImpact 为对全局的影响，负向值表示恶化）。规则：1) 计算全局净效应 `net = Σ(globalImpact.cycle * 0.4 + globalImpact.quality * 0.3 - globalImpact.downstreamCost * 0.3)`；2) 对每个 unit，若 `localGain > 0` 但其 `contribution = cycle*0.4 + quality*0.3 - downstreamCost*0.3 < 0`，标记 `conflict`（局部提升但损害全局）；3) 返回 `{ net, conflicts: Array<{team, contribution}>, overall: net > 0 ? 'win-win' : 'tradeoff' }`。边界：units 空（net=0、overall='tradeoff'）；缺字段按 0。

**答**：
- 结论先行：冲突检测 = 比较「局部收益方向」与「全局贡献方向」；局部涨、全局跌就是典型的指标博弈信号，应触发指标 redesign。
- 全局净效用加权求和，但每个 unit 的贡献要单独看——整体为正也可能掩盖个别团队的破坏性优化。
- 追问钩子：为什么整体为正也要看个体贡献？——一个团队的严重局部优化可能被其他团队的收益抵消，但破坏性行为本身必须被纠正。

```javascript
function detectConflict(units = []) {
  const contrib = u => {
    const g = u.globalImpact ?? {};
    return (g.cycle ?? 0) * 0.4 + (g.quality ?? 0) * 0.3 - (g.downstreamCost ?? 0) * 0.3;
  };
  const net = units.reduce((s, u) => s + contrib(u), 0);
  const conflicts = units
    .filter(u => (u.localGain ?? 0) > 0 && contrib(u) < 0)
    .map(u => ({ team: u.team, contribution: +contrib(u).toFixed(2) }));
  return {
    net: +net.toFixed(2), conflicts,
    overall: net > 0 ? 'win-win' : 'tradeoff',
  };
}
const r = detectConflict([
  { team: 'A', localGain: 0.3, globalImpact: { cycle: 0.2, quality: 0.1, downstreamCost: 0 } },
  { team: 'B', localGain: 0.2, globalImpact: { cycle: 0.1, quality: -0.1, downstreamCost: 0.5 } }, // 局部涨全局跌
]);
console.log(r.conflicts.length === 1 && r.conflicts[0].team === 'B');
console.log(r.overall === 'win-win'); // 整体仍为正，但 B 的破坏需纠正
console.log(detectConflict([]).net === 0); // 边界
```


**评分点**：
- 全局净效应加权求和正确
- 逐 unit 判「局部涨但贡献负」为 conflict
- overall 判定与空 units 边界
- 能说明「整体为正仍需纠正个别破坏」属加分
