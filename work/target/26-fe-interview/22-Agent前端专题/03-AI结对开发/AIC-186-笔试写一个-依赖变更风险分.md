## AIC-186：笔试：实现一个依赖变更风险分级器：semver 跳版检测、直接/间接依赖与破坏性 API 扫描？
**答**：实现 `assessDeps(before, after, deprecatedApis)`：
- before/after: `{pkg: version}` 锁定文件快照；输出新增/删除/升级清单；
- 风险分级：major 升级 high / minor medium / patch low；新增包 medium（供应链面）；删除 low；
- 扫描代码中对被升级包 deprecatedApis 的引用（命中则风险 +1 级）；
- 输出排序后的风险清单与总计分级。

```javascript
function semverDiff(a, b) {
  const pa = a.split('.').map(Number), pb = b.split('.').map(Number);
  if (pb[0] !== pa[0]) return 'major';
  if (pb[1] !== pa[1]) return 'minor';
  return 'patch';
}
const W = { major: 3, minor: 2, patch: 1 };
const LEVEL = { 1: 'low', 2: 'medium', 3: 'high', 4: 'critical' };

function assessDeps(before, after, codeUsage = {}) {
  const changes = [];
  const pkgs = new Set([...Object.keys(before), ...Object.keys(after)]);
  for (const pkg of pkgs) {
    const b = before[pkg], a = after[pkg];
    if (b && a && b !== a) {
      const diff = semverDiff(b, a);
      let score = W[diff];
      const hits = (codeUsage[pkg] ?? []).filter(api =>
        (codeUsage.deprecated?.[pkg] ?? []).includes(api));
      if (hits.length) score += 1;
      changes.push({ pkg, from: b, to: a, diff, hits, score,
        level: LEVEL[Math.min(score, 4)],
        note: hits.length ? `使用了已废弃 API: ${hits.join(', ')} 升级前必须迁移` : '' });
    } else if (!b && a) changes.push({ pkg, diff: 'new', score: 2, level: 'medium', note: '新依赖：审查维护状态与许可' });
    else if (b && !a) changes.push({ pkg, diff: 'removed', score: 1, level: 'low', note: '' });
  }
  changes.sort((x, y) => y.score - x.score);
  return {
    changes,
    overall: LEVEL[Math.min(Math.max(...changes.map(c => c.score), 0), 4)],
    blocking: changes.filter(c => c.level === 'critical' || c.level === 'high'),
  };
}

// 测试
console.log(assessDeps(
  { react: '18.2.0', lodash: '4.17.20' },
  { react: '19.0.0', lodash: '4.17.21', zod: '3.22.0' },
  { react: ['useState'], deprecated: { react: ['useSWRGlobal'] }, 'react-dom': [] }));
// react major → high；zod new → medium；lodash patch → low；overall high
```

**评分点**：
1. semver 三段比较顺序正确（major→minor→patch）；
2. 废弃 API 引用扫描联动升级风险（用了废弃 API 的 major 升级直接 critical）；
3. 新增/删除包的风险语义（供应链 vs 清理）不同，不是只有升级；
4. 清单按风险降序 + overall 与 blocking 分组——报告可直接进升级决策会；
5. 追问：peer dependency 冲突检测与 lockfile 深度对比（传递依赖变化）是进阶。
