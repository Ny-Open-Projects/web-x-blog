## AIC-972：笔试：实现「规范采纳度分析器」（从提交/Agent 日志计算多维采纳指标）
**答**：
- 核心需求：实现 `analyzeAdoption(events, opts)`。`events: { actor, kind, rule, passed, source }[]`；kind 取值 check/bypass/violation；source 取值 human/ci/ide/agent。返回 `{ byActor, byRule, overall }`。
- 指标：对每个 actor/rule 计算 `passRate=passed数/check数`（无 check 记 0）、`activeRate=source=human或agent的check数/check数`、`bypassCount`、`violationCount`。
- 聚合：overall 为全体指标（按同样公式在全部事件上算）；byActor 为按人聚合的 map；byRule 为按规则聚合的 map。
- 边界：空 events 返回全空且 passRate=0；分母为 0 时比率记 0；结果按 key 排序保证确定性。
- 语义：这是「度量工具」——指标用于发现推广 Obstacles 与博弈迹象，不用于个人绩效考核（否则会被博弈扭曲，呼应 AIC-848）。
- 追问钩子：能指出「采纳指标一旦与个人 KPI 挂钩就会失真（刷通过率），所以它应是团队改进信号而非考核工具」的候选人理解指标治理的红线。

```typescript
function metrics(evs){
  const checks=evs.filter(e=>e.kind==='check');
  const passed=checks.filter(e=>e.passed).length;
  const active=checks.filter(e=>e.source==='human'||e.source==='agent').length;
  const denom=checks.length||1;
  return { passRate:+(passed/denom).toFixed(2), activeRate:+(active/denom).toFixed(2),
    bypassCount:evs.filter(e=>e.kind==='bypass').length,
    violationCount:evs.filter(e=>e.kind==='violation').length };
}
function analyzeAdoption(events=[], opts={}) {
  const group = key => {
    const m=new Map();
    for(const e of events){ const k=e[key]; if(!m.has(k))m.set(k,[]); m.get(k).push(e); }
    return Object.fromEntries([...m.entries()].sort((a,b)=>String(a[0]).localeCompare(String(b[0])))
      .map(([k,v])=>[k,metrics(v)]));
  };
  return { byActor:group('actor'), byRule:group('rule'), overall:metrics(events) };
}
console.log(analyzeAdoption([{actor:'a',kind:'check',rule:'R1',passed:true,source:'human'}]).overall);
```
**评分点**：
- metrics 正确计算 passRate/activeRate/bypassCount/violationCount，分母 0 记 0。
- byActor/byRule 按 key 分组聚合且 key 排序确定性，overall 全体聚合。
- 空 events 边界处理，返回结构完整。
- activeRate 区分 human/agent 主动与 ci/ide 被动来源。
- 明确「指标用于团队改进非个人考核」（加分项）。
