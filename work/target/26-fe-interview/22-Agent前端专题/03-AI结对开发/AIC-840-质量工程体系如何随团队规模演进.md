## AIC-840：质量工程体系如何随团队规模从 5 人演进到 500 人？
**答**：
- **5 人（生存期）**：不需要平台，靠纪律即可——每人写几条核心评测用例，PR 时跑一遍，发现问题就补。重点是别让评测完全缺失，而非追求体系完整。
- **50 人（规模期）**：出现重复建设，需要**标准化**——统一的评测框架、共享 golden 集、CI 门禁模板；设立「质量守护者」轮值，负责评测集治理。此时工具比流程更重要。
- **500 人（平台期）**：标准化不够了，需要**平台化 + 分层治理**——自助评测平台（团队自助接入，平台团队只做底座）、分层质量门禁、按域自治（每个业务域有自己的评测 owner 和标准）、统一的质量数据看板。平台团队从「执行者」变「赋能者」。
- 贯穿始终的原则：**体系要与组织沟通结构匹配**（康威定律）；每次演进解决当前的真实痛点，不要为 500 人的问题在 5 人时过度建设。
- 追问钩子：能说出「不同阶段该痛的问题不同，过早平台化会变成无人用的基建」的候选人，具备务实的演进观而非教条。

```typescript
type Stage = { size: number; name: string; priority: string; tooling: string };

const stages: Stage[] = [
  { size: 5,   name: '生存期', priority: '别让评测缺失', tooling: '脚本 + 共享文档' },
  { size: 50,  name: '规模期', priority: '消除重复建设', tooling: '统一框架 + CI 门禁模板' },
  { size: 500, name: '平台期', priority: '自助化 + 域自治', tooling: '评测平台 + 数据看板' },
];

function recommend(size: number) {
  const stage = stages.find(s => size <= s.size) ?? stages[stages.length - 1];
  return {
    stage: stage.name,
    focus: stage.priority,
    avoid: size < 20 ? '不要建平台团队，先靠纪律' :
           size < 200 ? '不要过度分层治理，先统一工具' : '不要靠人肉 review 兜底，必须自助化',
  };
}
console.log(recommend(8));   // 生存期，别建平台
console.log(recommend(300)); // 平台期，必须自助化
```
