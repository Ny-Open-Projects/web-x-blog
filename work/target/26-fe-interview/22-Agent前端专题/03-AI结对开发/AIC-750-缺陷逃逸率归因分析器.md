## AIC-750：笔试：实现缺陷逃逸率的归因分析器

**需求**：实现 `attributeEscapes(bugs)`。`bugs`: `Array<{ id, aiAssisted, foundAfterRelease, stage?, cause? }>`（`stage`: 发现阶段；`cause`: 归因类别）。只统计 `aiAssisted===true` 的缺陷。规则：1) `rate = escaped / total`（escaped = foundAfterRelease）；2) 按 `cause` 分组统计逃逸缺陷数，取 top 原因；3) `byStage`: 记录各发现阶段的缺陷数（含非逃逸）；4) 返回 `{ rate, total, escaped, topCause, byStage }`。边界：无 AI 缺陷（rate=0、topCause=null）；cause 缺失归入 'unknown'；stage 缺失归入 'unknown'。

**答**：
- 结论先行：归因的价值在「找出逃逸缺陷的集中原因」——把 top cause 转成评测集用例或质量规则，才能形成改进闭环。
- 分母只算 AI 参与的缺陷，避免把人工缺陷混进来稀释归因结论。
- 追问钩子：为什么 byStage 要含非逃逸缺陷？——它能显示「多数缺陷在哪个阶段被拦截」，帮助判断哪道防线最有效。

```javascript
function attributeEscapes(bugs = []) {
  const ai = bugs.filter(b => b.aiAssisted === true);
  const escaped = ai.filter(b => b.foundAfterRelease === true);
  const causes = {};
  for (const b of escaped) { const c = b.cause ?? 'unknown'; causes[c] = (causes[c] ?? 0) + 1; }
  const top = Object.entries(causes).sort((a, b) => b[1] - a[1])[0];
  const byStage = {};
  for (const b of ai) { const s = b.stage ?? 'unknown'; byStage[s] = (byStage[s] ?? 0) + 1; }
  return {
    rate: ai.length ? escaped.length / ai.length : 0,
    total: ai.length, escaped: escaped.length,
    topCause: top?.[0] ?? null, byStage,
  };
}
const r = attributeEscapes([
  { id: 1, aiAssisted: true, foundAfterRelease: false, stage: 'review' },
  { id: 2, aiAssisted: true, foundAfterRelease: true, cause: '边界遗漏', stage: 'prod' },
  { id: 3, aiAssisted: true, foundAfterRelease: true, cause: '边界遗漏', stage: 'prod' },
  { id: 4, aiAssisted: false, foundAfterRelease: true, cause: '其他' },
]);
console.log(r.rate === 2 / 3);          // 分母只算 AI 缺陷
console.log(r.topCause === '边界遗漏'); // 改进重点
console.log(attributeEscapes([]).topCause === null); // 边界
```


**评分点**：
- 分母只算 AI 参与的缺陷
- top cause 统计与 byStage 含非逃逸缺陷
- 缺失字段归入 unknown
- 能说明「逃逸缺陷回灌评测集形成闭环」属加分
