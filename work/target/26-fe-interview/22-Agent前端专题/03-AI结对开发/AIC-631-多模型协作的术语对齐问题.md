## AIC-631：多模型混用时代码术语对不齐怎么办？

**答**：
- 结论先行：**术语对齐靠「单一术语词典 + 生成后归一键词」**。不同模型对同一概念有不同偏好（getUser / fetchUser / queryUser），混用后代码像「拼凑乐高」——功能对但读起来割裂（AIC-273 风格统一）。
- 预防为主：1) **术语表进 rules**：在 Cursor rules / copilot-instructions 里写明「用户数据获取统一用 `fetchXxx`，禁用 get/query 前缀」，所有模型读同一份；2) **类型/接口先行**：先定义好类型与函数签名（人写或强模型写），让编码模型「填空」而非「自由命名」；3) **few-shot 示例**：给模型看团队风格的代码片段，比抽象规则更有效（AIC-026 示例质量）。
- 兜底治理：生成后跑一个「术语归一器」——扫描代码里的约定别名，统一替换（如把所有 `getUser` 改成 `fetchUser`），配合 ESLint 规则固化。
- 注意边界：术语替换要基于 AST 或精确匹配，别用全局字符串替换（会把 `getUserById` 误改、注释里的词也改掉）。
- 追问钩子：为什么「类型/接口先行」比「在 prompt 里反复强调命名」更有效？——因为 prompt 强调是「软约束」，模型可能忽略；而类型签名是「硬约束」，编码模型必须按既有签名实现，命名自由被结构性限制——约束从「请求」升级为「环境」。

```typescript
// 术语归一：把别名映射到规范名，仅替换独立的标识符（词边界）
const TERM_MAP: Record<string, string> = {
  getUser: 'fetchUser',
  queryUser: 'fetchUser',
  getUserById: 'fetchUserById', // 长名优先
};

function normalizeTerms(code: string): string {
  // 按 key 长度降序，避免 getUser 先替换掉 getUserById
  const keys = Object.keys(TERM_MAP).sort((a, b) => b.length - a.length);
  let out = code;
  for (const from of keys) {
    const re = new RegExp(`\b${from}\b`, 'g');
    out = out.replace(re, TERM_MAP[from]);
  }
  return out;
}

console.log(normalizeTerms('const u = getUser(1); const v = getUserById(2);'));
// const u = fetchUser(1); const v = fetchUserById(2);
```
