## AIC-764：笔试：实现效能指标的防刷异常检测与修正器

**需求**：实现 `antiGaming(records, opts)`。`records`: `Array<{ user, day, metric, quality }>`；`opts.floor`（质量红线，默认 0.8）、`zThreshold`（突增倍数，默认 3）。规则：1) 按 user 分组，计算每个用户各日 metric 的个人基线（其历史中位数）；2) 若某日 metric > 基线*zThreshold 且 quality < floor，标记 `suspicious`（疑似刷量）；3) 对 suspicious 记录，metric 修正为 `基线`（截回基线）；4) 返回 `{ adjusted: records', suspicious: Array<{user, day}> }`。边界：无历史基线（首条记录不判异常）；records 空（全空）；中位数用排序取中间（偶数取上中位数）。

**答**：
- 结论先行：防刷 = 「异常突增 + 质量下降」双信号联合判定；单看突增可能是真实进步，单看低质量可能是任务难，两者同时出现才高度可疑。
- 用个人历史中位数做基线（抗离群），而非全团队均值（会误伤进步快的个人）。
- 追问钩子：为什么修正要「截回基线」而不是直接置零？——完全置零过于激进，可能误伤真实进步；截回基线是保守修正。

```javascript
function antiGaming(records = [], opts = {}) {
  const floor = opts.floor ?? 0.8;
  const z = opts.zThreshold ?? 3;
  const adjusted = records.map(r => ({ ...r }));
  const byUser = {};
  adjusted.forEach((r, i) => (byUser[r.user] ??= []).push(i));
  const suspicious = [];
  for (const [user, idxs] of Object.entries(byUser)) {
    const sorted = idxs.map(i => adjusted[i].metric).sort((a, b) => a - b);
    const median = sorted[Math.floor(sorted.length / 2)];
    const firstDay = adjusted[idxs[0]].day;
    for (const i of idxs) {
      const r = adjusted[i];
      if (r.day === firstDay) continue;                 // 首条无基线
      if (median > 0 && r.metric > median * z && r.quality < floor) {
        suspicious.push({ user, day: r.day });
        r.metric = median;                              // 截回基线
      }
    }
  }
  return { adjusted, suspicious };
}
const r = antiGaming([
  { user: 'u1', day: 1, metric: 10, quality: 0.9 },
  { user: 'u1', day: 2, metric: 50, quality: 0.5 },      // 突增 5 倍 + 低质量 → 可疑
]);
console.log(r.suspicious.length === 1 && r.adjusted[1].metric === 10); // true
console.log(antiGaming([]).suspicious.length === 0); // 边界
```


**评分点**：
- 以个人历史中位数为基线
- 突增 且 低质量 双信号联合判定
- 截回基线（非置零）的保守修正
- 首条记录无基线跳过、空记录边界
