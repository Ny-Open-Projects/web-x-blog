## AIC-941：塞给 AI 的上下文超预算了，「该裁哪些、留哪些」应该如何决策而不是拍脑袋删？
**答**：
- 按「重要性 × 相关性」双维度打分：重要性是内容本身的价值（安全约束、接口契约 > 旧代码 > 闲聊），相关性是与当前任务的匹配度；优先裁掉双低的。
- 设「不可裁剪白名单」：系统提示、安全/合规约束、正在修改文件的当前内容、接口契约——这些是硬约束，任何预算下都不能丢，否则 AI 会违规。
- 裁剪要「留结构、去细节」：对长文件可只保留函数签名/类结构/关键注释，而非整段实现；结论：裁剪是信息压缩，不是简单截断。
- 追问钩子：能提出「裁剪后要能验证关键约束仍在（如裁剪结果里必须含所有白名单项）」的候选人，把裁剪变成了可验证的工程步骤。

```typescript
// 上下文裁剪：重要性 × 相关性打分 + 白名单
const WHITELIST = ['system','constraint','current-file'];
function score(ctx) {
  const importance = { constraint:10, contract:8, 'current-file':9, history:3, chat:1 }[ctx.kind] ?? 5;
  const relevance = ctx.relevantToTask ? 1.5 : 1;
  return importance * relevance;
}
function trimContexts(contexts, budget, task) {
  const kept = contexts.filter(c => WHITELIST.includes(c.kind)); // 白名单必留
  let used = kept.reduce((s,c)=>s+c.tokens,0);
  const rest = contexts.filter(c => !WHITELIST.includes(c.kind))
    .map(c => ({ c, s:score({...c, relevantToTask: c.tags?.includes(task)}) }))
    .sort((a,b)=>b.s-a.s);
  for (const {c} of rest) { if (used + c.tokens <= budget) { kept.push(c); used += c.tokens; } }
  return kept;
}
console.log(trimContexts([
  {kind:'constraint',tokens:100},{kind:'history',tokens:500,tags:['price']},
], 300, 'price').map(c=>c.kind)); // 白名单留下，history 超预算被裁
```
