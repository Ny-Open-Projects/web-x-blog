## AIC-839：评测标注时两个人意见相反，这种「标注者分歧」怎么处理？
**答**：
- 分歧是**信号而非噪声**：它往往说明评测标准定义不清，或任务本身有主观性。第一反应不该是「找第三人投票」，而是「为什么分歧」。
- 先量化一致性：用 Cohen's Kappa（两人）或 Krippendorff's Alpha（多人），考虑偶然一致的影响，比裸「一致率」更可信；Kappa < 0.6 说明标准有问题，先修标准。
- 处理流程：① 消除歧义——把模糊标准写成可操作的判断准则（附正例/反例）；② 对分歧样本做**对齐会**讨论，形成裁决先例；③ 仍无法一致的标记为「争议样本」，从计分中剔除但保留用于讨论，不强行打标。
- 裁判模型同样有分歧：多裁判不一致时看一致性分数，低于阈值升级人工（AIC-819）。**不要假设模型裁判天然中立**。
- 追问钩子：能说出「Kappa 低先修标准而不是先换人」的候选人，理解评测体系的根本问题是定义而非执行。

```typescript
// Cohen's Kappa：考虑偶然一致的一致性度量
function cohensKappa(a: string[], b: string[]) {
  if (a.length !== b.length || !a.length) return 0;
  const labels = [...new Set([...a, ...b])];
  const n = a.length;
  const agree = a.filter((x, i) => x === b[i]).length / n;
  const pa: Record<string, number> = {}, pb: Record<string, number> = {};
  for (const l of labels) {
    pa[l] = a.filter(x => x === l).length / n;
    pb[l] = b.filter(x => x === l).length / n;
  }
  const expected = labels.reduce((s, l) => s + pa[l] * pb[l], 0);
  if (expected >= 1) return 1;
  return +((agree - expected) / (1 - expected)).toFixed(3);
}
const alice = ['pass','pass','fail','pass','fail'];
const bob   = ['pass','fail','fail','pass','fail'];
const k = cohensKappa(alice, bob);
console.log('Kappa =', k, k < 0.6 ? '标准不清，先对齐规则' : '一致性可接受');
// 经验：>0.8 高度一致，0.6~0.8 中等，<0.6 需修订标准
```
