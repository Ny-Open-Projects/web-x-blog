## AIC-718：笔试：实现异步结对的变更交接摘要生成器

**需求**：实现 `handoffSummary(diff, decisions)`。`diff`: `Array<{ file, added, removed }>`；`decisions`: `Array<{ topic, choice, owner, resolved }>`。规则：1) 统计每个文件的增删行数，按 `added+removed` 降序排列；2) 未解决决策（`resolved===false`）单列为 `pending`，其余进 `settled`；3) 生成 `risk`：若任一未解决决策的 `topic` 含「安全/权限/支付」关键词，风险为 high，否则 low；4) 返回 `{ files, settled, pending, risk }`。边界：diff 空（files=[]）；decisions 空（settled/pending=[]、risk=low）；added/removed 非数字按 0 处理。

**答**：
- 结论先行：交接摘要的价值在「未决事项」而非「改了什么」——异步场景下，接手人最需要知道「还有哪些问题没拍板」。
- 风险判定用关键词扫描未决决策的 topic，把高危主题显式标红，避免接手人忽略。
- 追问钩子：为什么未解决决策要和已解决分开？——混在一起会让接手人误以为所有决策都已定稿，直接沿用错误假设。

```javascript
function handoffSummary(diff = [], decisions = []) {
  const num = v => (typeof v === 'number' && v >= 0 ? v : 0);
  const files = diff.map(d => ({ file: d.file, churn: num(d.added) + num(d.removed) }))
                    .sort((a, b) => b.churn - a.churn);
  const pending = decisions.filter(d => d.resolved === false);
  const settled = decisions.filter(d => d.resolved !== false);
  const danger = /安全|权限|支付/;
  const risk = pending.some(d => danger.test(d.topic ?? '')) ? 'high' : 'low';
  return { files, settled, pending, risk };
}
const r = handoffSummary(
  [{ file: 'List.tsx', added: 10, removed: 2 }, { file: 'api.ts', added: 1, removed: 0 }],
  [{ topic: '按钮颜色', choice: '蓝', owner: 'A', resolved: true },
   { topic: '支付回调权限', choice: '', owner: 'B', resolved: false }]
);
console.log(r.files[0].file === 'List.tsx'); // 按改动量降序
console.log(r.risk === 'high');              // 未决含「支付/权限」
console.log(r.pending.length === 1);
console.log(handoffSummary([], []).risk === 'low'); // 边界
```


**评分点**：
- 文件按 churn 降序、非数字归 0
- 未决决策单列 pending、已决进 settled
- 风险关键词扫描（安全/权限/支付）判 high
- 边界（diff/decisions 空）；未决事项优先意识属加分
