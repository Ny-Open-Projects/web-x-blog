## AIC-936：出线上事故时审计链有几千万条，如何快速「裁剪」出与这次事故相关的证据，而不是全量翻找？
**答**：
- 先确定「裁剪维度」：时间窗口（事故前后 N 小时）、影响文件（出错模块）、任务/会话 ID、模型版本——结论：多维索引是快速裁剪的前提。
- 沿「因果链」而非「时间线」裁剪：从出问题的代码行出发，顺血缘找到生成它的会话轮次，再向前找该会话依赖的上游产出，形成最小充分证据集。
- 裁剪结果要「可验证完整」：附带证据集的哈希摘要，证明「这就是当时的全部相关记录，未被挑选性删减」——避免举证时被质疑选择性呈现。
- 追问钩子：能说出「裁剪是检索问题 + 完整性证明问题的组合，既快又要能证明没动手脚」的候选人，兼顾了效率与合规。

```typescript
// 多维过滤 + 血缘扩展裁剪最小证据集
function cutEvidence(records, { window, files, session }) {
  return records.filter(r =>
    r.at >= window[0] && r.at <= window[1] &&
    (!files || files.includes(r.file)) &&
    (!session || r.session === session));
}
function extendByBlood(evidence, lineageMap) { // 沿血缘补上游产出
  const ids = new Set(evidence.flatMap(e => lineageMap[e.id] || []));
  return [...evidence, ...evidence.filter(e=>ids.has(e.id))];
}
function digest(set){ return set.map(e=>e.hash).join('|'); }
const ev = cutEvidence([
  {id:1,at:100,file:'price.ts',session:'s1',hash:'a'},
  {id:2,at:999,file:'other.ts',session:'s2',hash:'b'},
], { window:[0,200], files:['price.ts'] });
console.log(ev, '摘要:', digest(ev));
```
