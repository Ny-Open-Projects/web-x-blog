## AIC-621：AI 结对做跨天任务，怎么「断点续作」不丢上下文？

**答**：
- 结论先行：**不能用「昨天的聊天记录」续作，要用「结构化交接文件」续作**（AIC-100 交接文件模式）。聊天记录是过程，充满废弃尝试；交接文件是结论，只保留当前有效状态。
- 交接文件五段式：1) **目标与验收**（原始锚点 AIC-618）；2) **已完成**（含 commit hash、哪些文件改了）；3) **进行中**（卡在哪、下一步是什么）；4) **已知坑**（试过什么不行、别再踩）；5) **上下文索引**（关键文件路径、相关规则、决策记录 ADR）。
- 恢复流程：新会话开头只读交接文件（不读旧聊天），让 AI 复述「当前状态 + 下一步」，人确认无误后继续。相当于给 AI 装了「持久记忆」，但记忆是人工浓缩过的。
- 自动化辅助：用 AI 从聊天记录自动生成交接草稿（AIC-429 交接摘要），但必须人工审——AI 会漏掉「为什么放弃某方案」这类关键负面信息。
- 追问钩子：为什么「已知坑」比「已完成」更重要？——因为已完成的事有代码和 commit 可查，而「试过某方案不行」只存在于人的记忆里；不写下来，第二天 AI 会把同一个坑再踩一遍，这就是为什么跨天任务经常「原地打转」。

```typescript
type Handoff = {
  goal: string;
  done: { commit: string; files: string[] }[];
  inProgress: { blocker: string; next: string };
  knownPitfalls: string[];
  contextIndex: string[];
};

function renderResumePrompt(h: Handoff): string {
  return [
    '## 任务目标', h.goal,
    '## 已完成（勿重做）', ...h.done.map(d => `${d.commit}: ${d.files.join(', ')}`),
    '## 当前状态', `卡点：${h.inProgress.blocker}`,
    '## 下一步', h.inProgress.next,
    '## 已知坑（勿再踩）', ...h.knownPitfalls.map(p => `- ${p}`),
    '## 上下文文件', h.contextIndex.join('
'),
    '
请先复述当前状态与下一步，确认后再动手。',
  ].join('
');
}

const handoff: Handoff = {
  goal: '商品列表虚拟滚动改造',
  done: [{ commit: 'a1b2c', files: ['list.tsx'] }],
  inProgress: { blocker: '虚拟滚动下筛选后滚动位置未重置', next: '在 filter 变更时调用 scrollTo(0)' },
  knownPitfalls: ['试过用 key 强制重挂载，会导致图片重复加载'],
  contextIndex: ['src/list.tsx', 'rules/fe.md'],
};
console.log(renderResumePrompt(handoff).includes('勿再踩')); // true
```
