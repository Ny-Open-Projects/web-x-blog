## AIC-160：笔试：实现一个多模型路由器，按任务类型/成本/健康度选择模型，支持故障自动切换？
**答**：实现 `route(task, providers)`：
- providers: `[{name, models: [{id, cost, speed}], healthy, failureStreak}]`；
- 路由策略：先按任务类型过滤（task.kind 映射候选模型档位），再在健康供应商中按「成本 × 熔断惩罚」选最低分；
- 连续失败 ≥ 3 的供应商熔断 60s（记录熔断时间）；全部不可用时返回降级方案 `degraded: true`；
- 选择结果要记录理由（audit），便于成本复盘。

```javascript
const KIND_MODEL = {
  bugfix: 'high', refactor: 'high', doc: 'cheap', naming: 'cheap', jsonOutput: 'high',
};
const BREAK_MS = 60_000, FAIL_LIMIT = 3;

function route(task, providers, now = Date.now()) {
  const tier = KIND_MODEL[task.kind];
  const candidates = [];
  for (const p of providers) {
    if (p.breakUntil && now < p.breakUntil) continue;         // 熔断中
    for (const m of p.models) {
      if (m.tier !== tier) continue;
      const penalty = 1 + p.failureStreak * 0.1;               // 失败越多越不倾向
      candidates.push({ provider: p, model: m, score: m.cost * penalty, penalty });
    }
  }
  if (!candidates.length) {
    // 降级：允许跨档位找最便宜健康模型
    const any = providers.filter(p => !(p.breakUntil && now < p.breakUntil))
      .flatMap(p => p.models.map(m => ({ provider: p, model: m, score: m.cost })));
    if (!any.length) return { degraded: true, reason: '所有供应商不可用' };
    any.sort((a, b) => a.score - b.score);
    return { ...pick(any[0]), degraded: true, reason: '同档位无可用，降级到任意健康模型' };
  }
  candidates.sort((a, b) => a.score - b.score);
  return { ...pick(candidates[0]), degraded: false };
}
function pick(c) {
  return { provider: c.provider.name, model: c.model.id,
    audit: `tier=${c.model.tier} cost=${c.model.cost} penalty=${c.penalty ?? 1}` };
}

// 熔断记录器（调用失败时）
function onProviderFailure(p, now = Date.now()) {
  p.failureStreak++;
  if (p.failureStreak >= FAIL_LIMIT) p.breakUntil = now + BREAK_MS; // 熔断 60s
}
function onProviderSuccess(p) { p.failureStreak = 0; delete p.breakUntil; }

// 测试
const providers = [
  { name: 'A', failureStreak: 0, models: [{ id: 'A-hi', tier: 'high', cost: 10 }, { id: 'A-cheap', tier: 'cheap', cost: 2 }] },
  { name: 'B', failureStreak: 2, models: [{ id: 'B-hi', tier: 'high', cost: 8 }] },
];
console.log(route({ kind: 'bugfix' }, providers).model); // A-hi（B 因熔断惩罚分数高）
```

**评分点**：
1. 路由决策依据是「成本 × 熔断惩罚」而非纯成本——避免把流量持续打给半坏供应商；
2. 熔断三要素（连续失败阈值、熔断窗口、恢复清零）齐备；
3. 全挂时必须显式 degraded 而非抛错——上游可走确定性兜底（AIC-053 的降级策略）；
4. audit 理由字段：路由决策可复盘是生产级意识；
5. 降级允许跨档位（宁可便宜模型也不拒绝服务）的策略取舍说明。
