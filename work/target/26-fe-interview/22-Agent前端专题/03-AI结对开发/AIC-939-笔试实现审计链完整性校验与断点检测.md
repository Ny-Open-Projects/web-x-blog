## AIC-939：笔试：实现「审计链完整性校验与断点检测」（支持局部校验与断点定位、容忍归档分段）
**答**：
- 核心需求：实现 `verifyChain(records, opts)`，基于每条记录的 `{ seq, prev, hash, payload }`，返回 `{ ok, breaks:[{index,reason}], checked }`。opts.from/to 支持只校验某一段。
- 校验规则：① 重算 hash（payload+prev+seq 稳定序列化）与记录 hash 一致；② prev 等于前一记录 hash；③ seq 连续（允许 opts.allowSeqGap=true 时容忍归档造成的序号缺口，但仍要求 prev 链连续）。
- 断点定位：遇到不一致记录记入 breaks（reason 区分 hash_mismatch / prev_mismatch / seq_gap），后续记录继续校验而非提前退出，收集全部断点。
- 边界：空 records 返回 ok=true；from/to 裁剪到 [0,len]；局部校验时「前一条」取 from-1 的记录（若存在）作为 prev 基准。
- 语义：这是「完整性验证」工具——只报告断点不修复；断点需结合归档策略判断是篡改还是正常的分段归档。
- 追问钩子：能指出「允许 seq 缺口但不允许 prev 断链，是因为归档会跳号但不会断哈希」的候选人理解了归档与篡改的本质区别。

```typescript
function stable(o){ if(o===null||typeof o!=='object')return JSON.stringify(o);
  if(Array.isArray(o))return '['+o.map(stable).join(',')+']';
  return '{'+Object.keys(o).sort().map(k=>JSON.stringify(k)+':'+stable(o[k])).join(',')+'}'; }
function H(s){ let h=0; for(const c of s)h=(Math.imul(h,31)+c.charCodeAt(0))>>>0; return h; }
function verifyChain(records = [], opts = {}) {
  const from=Math.max(0,opts.from??0), to=Math.min(records.length,opts.to??records.length);
  const breaks=[];
  for(let i=from;i<to;i++){
    const r=records[i];
    if(H(stable({payload:r.payload,prev:r.prev,seq:r.seq}))!==r.hash) breaks.push({index:i,reason:'hash_mismatch'});
    const prevRec = i>0 ? records[i-1] : null;
    if(i>0 && prevRec && r.prev!==prevRec.hash) breaks.push({index:i,reason:'prev_mismatch'});
    if(i>from && prevRec && r.seq!==prevRec.seq+1 && !opts.allowSeqGap) breaks.push({index:i,reason:'seq_gap'});
  }
  return { ok:breaks.length===0, breaks, checked:to-from };
}
const gen=(seq,prev,payload)=>({seq,prev,payload,hash:H(stable({payload,prev,seq}))});
const chain=[gen(0,0,{a:1}),gen(1,111,{a:2})];
console.log(verifyChain(chain)); // ok=false, prev_mismatch
```
**评分点**：
- 重算 hash（payload+prev+seq 稳定序列化）校验一致，stable 键排序。
- prev 链连续校验、seq 连续性校验（allowSeqGap 容忍归档跳号）。
- 收集全部断点不提前退出，reason 区分类别，局部校验基准正确。
- 空链、from/to 裁剪边界处理，返回结构完整。
- 区分「seq 可跳、prev 不可断」的归档语义（加分项）。
