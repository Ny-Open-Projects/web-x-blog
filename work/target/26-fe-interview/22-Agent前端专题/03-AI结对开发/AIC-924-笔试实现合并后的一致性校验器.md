## AIC-924：笔试：实现「合并后一致性校验器」（跨文件契约/类型/导入一致性检查）
**答**：
- 核心需求：实现 `checkConsistency(files, contracts)`。`files: {path, content}[]`；`contracts: { name, pattern:RegExp|string, fileGlob }[]` 定义某契约应出现在哪些文件。返回 `{ ok, violations }`。
- 检查三类一致性：① 导入一致性——import 的路径必须存在对应文件；② 契约一致性——声明了 contract 的文件必须匹配 pattern；③ 导出一致性——被 import 的符号必须在目标文件 export。
- 边界：空文件集返回 ok=true；正则 pattern 用字符串时按字面量包含匹配；glob 用简单 `*`/`**`；报告要带文件路径与具体违规原因。
- 语义：这是合并后的「集成检查」，专门抓写集隔离与文本合并无法发现的跨文件语义断裂——检查失败应阻断合并。
- 追问钩子：能指出「一致性校验是合并门禁的最后一道网，但只能检查已声明的契约，未声明的隐式约定仍是盲区」的候选人理解其能力边界。

```typescript
function checkConsistency(files, contracts = []) {
  const paths = new Set(files.map(f => f.path));
  const violations = [];
  const byPath = new Map(files.map(f => [f.path, f.content]));
  for (const f of files) {
    // ① 导入路径存在性（仅相对路径）
    for (const m of f.content.matchAll(/from\s+['"](\.[^'"]+)['"]/g)) {
      const target = m[1] + '.ts';
      if (![...paths].some(p => p.endsWith(target)))
        violations.push({ file:f.path, reason:`导入不存在: ${m[1]}` });
    }
  }
  for (const c of contracts) {
    for (const f of files) {
      if (!c.fileGlob || globMatch(f.path, c.fileGlob)) {
        const ok = typeof c.pattern === 'string' ? f.content.includes(c.pattern) : c.pattern.test(f.content);
        if (!ok) violations.push({ file:f.path, reason:`契约缺失: ${c.name}` });
      }
    }
  }
  return { ok: violations.length === 0, violations };
}
function globMatch(p, g){ return new RegExp('^'+g.replace(/\*\*/g,'.*').replace(/\*/g,'[^/]*').replace(/\./g,'\\.')+'$').test(p); }
console.log(checkConsistency([{path:'a.ts',content:'import x from "./missing"'}], []));
```
**评分点**：
- 导入路径存在性、契约出现、导出符号三类一致性检查实现正确。
- glob 匹配 ** 与 * 处理正确，字符串/正则 pattern 均支持。
- 空文件集返回 ok=true，违规报告带文件与原因。
- 结果可用于阻断合并（门禁语义），代码可运行。
- 能说明只检查已声明契约、隐式约定仍是盲区（加分项）。
