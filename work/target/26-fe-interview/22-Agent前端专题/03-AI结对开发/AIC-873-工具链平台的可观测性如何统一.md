## AIC-873：工具链平台的可观测性怎么统一，避免每接一个工具就要配一套监控？
**答**：
- 统一的关键是**统一语义约定（semantic conventions）**：所有工具/模型/插件上报同一套指标（调用次数、延迟分位数、错误率、token 成本、缓存命中）、同一套 trace 结构、同一套日志字段。新接入工具只要遵循约定就自动进入现有看板与告警。
- 统一埋点放在**平台层而非工具里**：在 SDK / 网关 / 编排器里做无侵入埋点（AOP/中间件），业务和工具作者无需自己写监控代码——这是「统一」能落地的工程前提。
- AI 特有维度必须进标签：`modelVersion`、`promptVersion`、`toolName`、`tenantId`、`decisionId`。没有这些标签，出问题时无法按 AI 特有的变量切片分析（呼应 AIC-810/834）。
- 统一不等于一个大日志池：要有分级（指标/追踪/日志）、采样策略（高成本请求全采）、成本标签（观测本身也花钱，链路太多要采样）。
- 追问钩子：能说出「埋点放在平台层做无侵入采集 + 统一语义约定含 modelVersion/promptVersion」的候选人，理解可观测性是平台能力而非每个工具的自扫门前雪。

```typescript
// 平台层统一埋点中间件：工具作者无需关心
function withObservability(toolName: string, fn: (...a: any[]) => Promise<any>) {
  return async (args: any, ctx: any) => {
    const start = Date.now();
    const tags = {
      toolName,
      modelVersion: ctx.modelVersion,    // AI 特有维度
      promptVersion: ctx.promptVersion,
      tenantId: ctx.tenantId,
      decisionId: ctx.decisionId,
    };
    try {
      const res = await fn(args, ctx);
      meter.incr('tool.calls', { ...tags, status:'ok' });
      meter.histogram('tool.latency', Date.now() - start, tags);
      return res;
    } catch (e) {
      meter.incr('tool.calls', { ...tags, status:'error' });
      throw e;
    }
  };
}
// 任何工具用 withObservability 包装后，自动进入统一看板
const wrapped = withObservability('goods-search', searchGoods);
```
