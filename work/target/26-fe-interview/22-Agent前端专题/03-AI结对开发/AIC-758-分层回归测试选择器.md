## AIC-758：笔试：实现分层回归测试选择器

**需求**：实现 `selectTests(change, testMap)`。`change`: `{ files: string[], risk: 'low'|'mid'|'high' }`；`testMap`: `Record<file, Array<{ id, level: 'L1'|'L2'|'L3' }>>`（文件到关联测试的映射）。规则：1) 由 change.files 收集所有关联测试并按 id 去重；2) 按 risk 决定最高允许层级：low→L1、mid→L2、high→L3（层序 L1<L2<L3）；3) 过滤掉层级高于允许层级的测试；4) 按 level 升序、id 字典序排列返回 id 列表；5) 返回 `{ ids, byLevel }`。边界：files 空（ids=[]）；testMap 无匹配（ids=[]）；未知 level 视为 L3（最保守）。

**答**：
- 结论先行：选择器 = 影响面收集（哪些测试关联到改动文件）+ 风险剪枝（按风险砍掉过重的测试）+ 稳定排序（结果可复现）；三者缺一不可。
- 未知 level 当 L3 处理是「安全侧保守」——宁可多跑也别漏掉重型验证。
- 追问钩子：为什么按 id 去重而非按对象引用？——同一测试可能被多个改动文件关联，按 id 去重才不会重复执行。

```javascript
function selectTests(change = {}, testMap = {}) {
  const rank = { L1: 1, L2: 2, L3: 3 };
  const maxRank = { low: 1, mid: 2, high: 3 }[change.risk] ?? 1;
  const seen = new Set(), picked = [];
  for (const f of change.files ?? []) {
    for (const t of testMap[f] ?? []) {
      if (seen.has(t.id)) continue;
      seen.add(t.id);
      const r = rank[t.level] ?? 3;
      if (r <= maxRank) picked.push(t);
    }
  }
  picked.sort((a, b) => (rank[a.level] ?? 3) - (rank[b.level] ?? 3) || String(a.id).localeCompare(String(b.id)));
  const byLevel = {};
  picked.forEach(t => byLevel[t.level] = (byLevel[t.level] ?? 0) + 1);
  return { ids: picked.map(t => t.id), byLevel };
}
const tm = {
  'a.ts': [{ id: 'u1', level: 'L1' }, { id: 'e2e', level: 'L3' }],
  'b.ts': [{ id: 'u1', level: 'L1' }, { id: 'i1', level: 'L2' }],
};
const r = selectTests({ files: ['a.ts', 'b.ts'], risk: 'mid' }, tm);
console.log(r.ids); // ['u1', 'i1'] —— e2e(L3) 被风险剪枝，u1 去重
console.log(selectTests({ files: [] }, tm).ids.length === 0); // 边界
```


**评分点**：
- 关联测试收集 + 按 id 去重
- 风险剪枝（low/mid/high → L1/L2/L3）
- 未知 level 当 L3 保守处理
- level 升序 + id 字典序稳定输出
