## AIC-943：笔试：实现「上下文预算分配器」（按优先级/相关性分层裁剪，保证关键段不被丢弃）
**答**：
- 核心需求：实现 `allocateBudget(segments, budget, opts)`。`segments: { id, tokens, priority, kind, relevant }[]`；`budget` 为 token 上限。返回 `{ kept, dropped, used }`。
- 规则：① `kind` 在 opts.pinned（默认 ["system","constraint"]）中的段必留；② 其余按 `score = priority * (1 + (relevant?0.5:0))` 降序贪心装入，装不下就 dropped；③ 同分按 id 字典序保证确定性。
- 边界：budget ≤ 0 时只保留 pinned（若 pinned 也超预算则按 priority 截断到能放下的，但至少留一个）；tokens 非法（≤0/NaN）按 1 处理；空 segments 返回空结果。
- 语义：这是「有损但可控」的分配——白名单段绝对保留，其余按价值排序；输出 dropped 让人知道丢了什么，便于审计。
- 追问钩子：能指出「贪心不保证全局最优（背包问题），但工程上够用且确定性好；关键是白名单绝不能被优化掉」的候选人懂取舍。

```typescript
function allocateBudget(segments = [], budget = 0, opts = {}) {
  const pinned = opts.pinned ?? ['system','constraint'];
  const tok = s => Number.isFinite(s.tokens) && s.tokens > 0 ? s.tokens : 1;
  const isPinned = s => pinned.includes(s.kind);
  const sorted = segments.slice().sort((a,b) =>
    (isPinned(b)-isPinned(a)) ||
    ((b.priority*(1+(b.relevant?0.5:0))) - (a.priority*(1+(a.relevant?0.5:0)))) ||
    String(a.id).localeCompare(String(b.id)));
  const kept=[], dropped=[]; let used=0;
  for (const s of sorted) {
    if (isPinned(s) || used + tok(s) <= budget) { kept.push(s.id); used += tok(s); }
    else dropped.push(s.id);
  }
  return { kept, dropped, used };
}
console.log(allocateBudget([
  {id:'sys',tokens:100,priority:1,kind:'system'},
  {id:'hist',tokens:500,priority:2,kind:'history',relevant:false},
], 200)); // sys 必留，hist dropped
```
**评分点**：
- pinned 白名单段无条件保留，其余按 score 降序贪心装入。
- score = priority × (1 + relevant 加成)，同分按 id 字典序确定性排序。
- tokens 非法按 1、budget≤0 等边界处理，空 segments 返回空结果。
- 返回 kept/dropped/used，dropped 可审计「丢了什么」。
- 能说明贪心非全局最优但白名单绝对保留（加分项）。
