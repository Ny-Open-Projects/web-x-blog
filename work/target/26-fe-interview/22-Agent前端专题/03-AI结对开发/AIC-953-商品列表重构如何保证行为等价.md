## AIC-953：让 AI 重构商品列表组件（Class→Hooks），如何保证重构前后「行为等价」而不是改完看着差不多？
**答**：
- 行为等价的锚点是「可观察行为」：相同输入（props/state）→ 相同输出（渲染结果/副作用/回调），因此要对同一组输入做重构前后差分对比。
- 建立「特征化测试（characterization test）」：在重构前先给旧代码写测试锁住当前行为（包括一些「意外的行为」，因为它们可能是隐含需求），重构后用同一套测试验证。
- 覆盖副作用与时序：渲染结果一致不代表一致——要对比 useEffect 触发时机、请求次数、回调调用顺序，这类是重构翻车高发区。
- 追问钩子：能说出「特征化测试锁住的是『现状』而非『理想』，重构阶段先求等价、优化另开一轮，两件事分开做」的候选人懂重构纪律。

```typescript
// 特征化测试：同一输入对比重构前后行为
function characterize(oldImpl, newImpl, cases) {
  return cases.map(input => {
    const render = fn => snapshot(fn(input)); // 渲染快照
    const a = render(oldImpl), b = render(newImpl);
    return { input, equal: JSON.stringify(a) === JSON.stringify(b), a, b };
  });
}
function snapshot(v){ return { props:v.props, items:v.items?.length, effects:v.effects||[] }; }
const cases = [
  { props:{category:'digital'}, items:[1,2,3], effects:['fetch'] },
  { props:{category:'empty'}, items:[], effects:[] },
];
const oldRender = x => x, newRender = x => ({...x});
console.log(characterize(oldRender, newRender, cases).every(c=>c.equal));
```
