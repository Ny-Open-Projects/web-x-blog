## AIC-618：什么是 AI 结对的「意图锚点」，怎么防止长会话目标偏移？

**答**：
- 结论先行：**意图锚点 = 在会话开头写下一段不可协商的「目标+约束+验收标准」，并在每轮结束时让 AI 回念一遍**。它对抗的是长会话中目标被逐步替换的现象——AI 为了迎合最新一句 prompt，悄悄偏离最初需求。
- 锚点三要素：1) **目标句**（一句话说清要什么，如「把商品列表改成虚拟滚动，保持筛选/排序行为不变」）；2) **约束清单**（不可做的事，如「不改 API 契约、不引入新依赖」）；3) **验收标准**（可测条件，如「1 万条数据首屏 < 1s、现有 20 个单测全绿」）。
- 锚定机制：每轮 prompt 开头带上锚点摘要（不用全文，省 token），每轮 AI 输出后让它回答「本轮改动是否仍满足锚点？」，把目标检查变成固定仪式（AIC-343 意图追溯 / AIC-538 意图漂移）。一旦 AI 回答「否」或含糊，立即人工介入。
- 锚点也要版本化：需求真变更时，显式「更新锚点」并保留旧版本，而不是让锚点悄悄失效——否则锚点就成了摆设。
- 追问钩子：为什么「让 AI 每轮回念锚点」比「人自己记得盯着」有效？——因为人在长会话中也会认知疲劳而忘记初衷；把检查固化成 AI 必须回答的问题，等于给会话装了一个不会忘的看门狗，把「依赖人的记忆」变成「依赖流程机制」。

```typescript
type Anchor = { goal: string; constraints: string[]; acceptance: string[] };

function checkAnchor(anchor: Anchor, change: { files: string[]; addedDeps: string[]; testsPass: boolean }) {
  const violations: string[] = [];
  if (change.addedDeps.length) violations.push('引入了新依赖（违反约束）');
  if (!change.testsPass) violations.push('现有测试未全绿（违反验收）');
  // 约束里禁止改的文件若被改动
  for (const c of anchor.constraints) {
    const m = c.match(/不改\s+(\S+)/);
    if (m && change.files.includes(m[1])) violations.push(`改动了禁止文件 ${m[1]}`);
  }
  return { onTrack: violations.length === 0, violations };
}

const anchor: Anchor = {
  goal: '商品列表改虚拟滚动，保持筛选排序不变',
  constraints: ['不改 API 契约', '不引入新依赖'],
  acceptance: ['1万条首屏<1s', '20个单测全绿'],
};
console.log(checkAnchor(anchor, { files: ['list.tsx'], addedDeps: ['react-window'], testsPass: true }).onTrack); // false
```
