## AIC-593：笔试：手写命名评估

**答**：实现 `assessNaming(code)`。规则：1) 泛型命名：`data/result/item/value/temp/obj/res/ret/info` 作为变量名 → 'generic-name'（每个出现位置报告）；2) 匈牙利命名：`strXxx/intXxx/boolXxx/arrXxx` → 'hungarian'；3) 过度缩写：`usr/prd/cfg/cnt/idx` → 'over-abbreviated'；4) 返回 `{ issues: Array<{ name, type, line }>, score: 0~100, ok }`（score = 100 − issues × 10，clamp 0）。边界：空 code（score 100）；仅函数参数中的泛型名（也算——函数参数 `function f(data)` → data 是泛型）；大写开头的泛型（`Data` → 也算——类/组件名不算，只算变量）。边界补充：`const data = ...` 与 `function f(data)` 都检测。

```javascript
function assessNaming(code = '') {
  const GENERIC = new Set(['data', 'result', 'item', 'value', 'temp', 'obj', 'res', 'ret', 'info']);
  const issues: { name: string; type: string; line: number }[] = [];
  code.split('\n').forEach((line, i) => {
    // 泛型变量名（const/let/var/function 参数）
    for (const m of line.matchAll(/(?:const|let|var)\s+(\w+)\s*[=;]/g)) {
      if (GENERIC.has(m[1].toLowerCase()))
        issues.push({ name: m[1], type: 'generic-name', line: i + 1 });
    }
    for (const m of line.matchAll(/function\s+\w+\s*\(([^)]*)\)/g)) {
      for (const p of m[1].split(',')) {
        const name = p.trim().split(/[:=]/)[0].trim();
        if (GENERIC.has(name.toLowerCase()))
          issues.push({ name, type: 'generic-name', line: i + 1 });
      }
    }
    // 匈牙利
    for (const m of line.matchAll(/\b(?:str|int|bool|arr)[A-Z]\w*/g))
      issues.push({ name: m[0], type: 'hungarian', line: i + 1 });
    // 过度缩写
    for (const m of line.matchAll(/\b(?:usr|prd|cfg|cnt|idx)\b/g))
      issues.push({ name: m[0], type: 'over-abbreviated', line: i + 1 });
  });
  const score = Math.max(0, 100 - issues.length * 10);
  return { issues, score, ok: issues.length === 0 };
}

// 自测
// 泛型命名
const code1 = `const data = fetch();`;
let r = assessNaming(code1);
console.log(r.issues[0].type === 'generic-name' && r.issues[0].name === 'data');
console.log(r.score === 90);
// 函数参数中的泛型
const code2 = `function process(data) { return data; }`;
r = assessNaming(code2);
console.log(r.issues.some(i => i.name === 'data' && i.type === 'generic-name'));
// 匈牙利
r = assessNaming('const strName = "x";');
console.log(r.issues[0].type === 'hungarian' && r.issues[0].name === 'strName');
// 缩写
r = assessNaming('const usr = getUser();');
console.log(r.issues[0].type === 'over-abbreviated');
// 好命名
r = assessNaming('const userProfile = getUser();');
console.log(r.issues.length === 0 && r.score === 100);
// 多问题
const badCode = 'const data = 1;\nlet temp = 2;\nconst strVal = "x";';
r = assessNaming(badCode);
console.log(r.issues.length === 3);                      // data + temp + strVal
console.log(r.score === 70);
// 空
console.log(assessNaming('').score === 100);
```

**评分点**：
- 三类命名问题：generic-name（data/result/item）/ hungarian（strXxx）/ over-abbreviated（usr/cfg）
- 函数参数中的泛型检测（`function f(data)` → data 也是泛型——不仅是赋值语句）；score 线性递减
- 边界（空 code/好命名 100/多问题累减/函数参数检测）；score clamp 到 0
- 能说清「AI 的泛型命名（data/result）比人的泛型更有害——AI 无上下文，人至少知道自己指什么——命名是 AI 代码可读性的第一道关」属于加分
