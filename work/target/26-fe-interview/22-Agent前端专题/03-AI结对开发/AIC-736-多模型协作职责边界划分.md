## AIC-736：多模型协作中职责边界如何划分以避免互相干扰

**答**：
- 结论先行：职责边界要按「单一职责 + 明确契约」划——每个模型只负责一类子任务，输入输出有结构化契约，禁止一个模型既生成又审查自己（避免自我确认偏差）。
- 划分原则：1) 按能力匹配（擅长的做擅长的）；2) 生成与验证分离（不同模型）；3) 状态隔离（各模型只看到自己该看的上下文）；4) 单一写入者（同一文件只有一个模型能改，避免冲突）。
- 反模式：多模型同时改同一文件、生成模型兼做裁判、共享全部上下文导致互相污染。
- 追问钩子：为什么「单一写入者」原则重要？——多模型并发写同一文件会产生不可预测的覆盖与冲突，且难以定位是谁引入的问题。

```javascript
// 职责边界检查：同一文件只能有一个写入者
function checkBoundaries(assignments) {
  const writers = new Map();
  const violations = [];
  for (const a of assignments) {
    if (a.action === 'write') {
      if (writers.has(a.file) && writers.get(a.file) !== a.model)
        violations.push({ file: a.file, models: [writers.get(a.file), a.model] });
      else writers.set(a.file, a.model);
    }
  }
  return { ok: violations.length === 0, violations };
}
console.log(checkBoundaries([
  { model: 'A', file: 'a.ts', action: 'write' },
  { model: 'B', file: 'a.ts', action: 'write' }, // 冲突
  { model: 'B', file: 'b.ts', action: 'write' },
]).violations.length); // 1
```
