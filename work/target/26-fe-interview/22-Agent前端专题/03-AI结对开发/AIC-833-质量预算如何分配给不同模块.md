## AIC-833：团队质量预算有限，如何决定把评测精力投到哪些模块？
**答**：
- 质量预算分配本质是**风险驱动**：`优先级 = 影响面 × 出错概率 × 检测难度`。支付/权限/数据删除这类「高影响」模块，即使出错概率低也要重点投入；纯展示文案可以低成本覆盖。
- 用**分层策略**：核心链路做深度评测（golden 集 + 变异测试 + 人工复核 + 灰度），中间层做常规评测（golden 集 + 自动裁判），边缘层只做冒烟。不要平均用力。
- 预算要动态：根据线上问题和评测发现持续调整——某模块连续出问题就加预算，长期稳定就降预算把资源腾给新风险点。
- 要算投入产出：每千行核心代码配多少评测用例、每次发布评测耗时占比、评测发现的问题数 vs 逃逸到线上的问题数（**逃逸率**是最有说服力的指标）。
- 追问钩子：能说出「按逃逸率而非覆盖率调整预算分配」的候选人，把质量投资和真实风险挂钩了，而不是做数字游戏。

```typescript
type Module = {
  name: string; impact: 1|2|3|4|5; failureProb: number; // 0~1
  detectionDifficulty: 1|2|3; escapedBugs: number;      // 近期逃逸到线上的问题数
};

function allocateBudget(modules: Module[], totalHours = 100) {
  const scored = modules.map(m => ({
    ...m,
    risk: m.impact * m.failureProb * m.detectionDifficulty * (1 + m.escapedBugs),
  }));
  const sum = scored.reduce((s, m) => s + m.risk, 0) || 1;
  return scored.map(m => ({
    module: m.name,
    hours: Math.round(totalHours * m.risk / sum),
    tier: m.risk / sum > 0.25 ? 'deep' : m.risk / sum > 0.08 ? 'standard' : 'smoke',
  }));
}
console.log(allocateBudget([
  { name: 'payment', impact: 5, failureProb: 0.3, detectionDifficulty: 3, escapedBugs: 2 },
  { name: 'profile-ui', impact: 1, failureProb: 0.2, detectionDifficulty: 1, escapedBugs: 0 },
]));
// payment 获得大部分预算且 tier='deep'
```
