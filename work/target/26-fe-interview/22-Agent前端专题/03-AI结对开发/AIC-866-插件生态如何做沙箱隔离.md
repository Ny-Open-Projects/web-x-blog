## AIC-866：AI 工具平台的插件生态，如何做沙箱隔离防止恶意插件？
**答**：
- 插件（尤其 AI 生成的）是**不可信代码**：可能读环境变量拿密钥、发外网请求、写任意文件。最小权限是基础——插件只能在注册时声明的权限范围内运行（读哪个目录、访问哪个域名、调用哪个 API），默认全拒绝。
- 隔离层次：**进程/容器隔离**（最强，用独立进程或容器，限制 CPU/内存/文件/网络）、**能力令牌**（插件拿到的凭证是短期、最小权限、可吊销的，绝不把主服务的密钥给它）、**网络白名单**（只允许访问声明的域名）。
- 对 AI 生成插件要额外做**静态扫描 + 人工审核上架**：扫描危险调用（`eval`、子进程、`fetch` 到未知域名）；上架后行为监控，异常自动熔断下架。
- **审计与可追溯**：插件每次调用记录身份与参数；高风险操作（发消息、下单）要二次确认。沙箱不是一次性的，要能快速吊销与下线。
- 追问钩子：能说出「插件凭证必须短期最小权限且可吊销，绝不共享主服务密钥」的候选人，理解 AI 时代供应链安全的新边界。

```typescript
type PluginPerms = { allowNetwork?: string[]; allowRead?: string[]; allowWrite?: string[]; maxMs?: number };

// 权限校验：默认拒绝，只放行显式声明
function checkPermission(perm: PluginPerms, action: { type: string; target: string }) {
  const map: Record<string, string[] | undefined> = {
    network: perm.allowNetwork, read: perm.allowRead, write: perm.allowWrite,
  };
  const allowed = map[action.type];
  if (!allowed?.some(p => action.target.startsWith(p))) {
    throw new Error(`denied: ${action.type} → ${action.target} (not in whitelist)`);
  }
  return true;
}
const perms: PluginPerms = { allowNetwork: ['api.example.com'], allowRead: ['/data/public'], maxMs: 2000 };
checkPermission(perms, { type:'network', target:'api.example.com/items' }); // ok
// checkPermission(perms, { type:'network', target:'evil.com' }); // throw —— 默认拒绝
// 工程中还要配合：容器隔离 + 短期凭证 + 行为审计 + 异常熔断
```
