## AIC-999：笔试：实现「迁移回滚影响面评估器」（评估回滚某个迁移步骤会影响哪些已迁移模块）
**答**：
- 核心需求：实现 `assessRollback(steps, targetId)`。`steps: { id, migratedAt, dependsOn:[], rolledBack:boolean }[]`（dependsOn 为前置步骤 id）。返回 `{ target, affected, cascade, feasible, reasons }`。
- affected = 直接依赖 target 的未回滚步骤；cascade = 递归的传递依赖（回滚 target 会导致这些也必须回滚），用 Set 防环；已 rolledBack 的步骤不计入。
- feasible 判定：若 cascade 中存在「已对外发布/不可逆」的步骤（用 opts.irreversible 集合标注）则不可行——结论：不可逆步骤让回滚链断裂。
- 边界：target 不存在返回 feasible=false/reasons=["目标不存在"]；空 dependsOn 正常；cascade 按 migratedAt 降序（后迁移的先回滚）返回。
- 语义：迁移回滚不是单步操作，而是沿依赖图的级联——评估器给出「要回滚就得连这些一起回滚」的完整清单与可行性。
- 追问钩子：能指出「回滚可行性还取决于『是否已产生外部副作用』（如已发消息、已写外部库），这类不可逆操作无法靠代码回滚，需业务补偿」的候选人理解回滚的真实边界。

```typescript
function assessRollback(steps=[], targetId, opts={}) {
  const map=new Map(steps.map(s=>[s.id,s]));
  const irreversible=new Set(opts.irreversible||[]);
  const reasons=[];
  if(!map.has(targetId)) return { target:targetId,affected:[],cascade:[],feasible:false,reasons:['目标不存在'] };
  const affected=new Set(), cascade=new Set();
  const queue=[targetId];
  while(queue.length){
    const cur=queue.shift();
    for(const s of steps){
      if((s.dependsOn||[]).includes(cur)&&!s.rolledBack&&!cascade.has(s.id)){
        cascade.add(s.id); affected.add(s.id); queue.push(s.id);
      }
    }
  }
  const blocked=[...cascade].filter(id=>irreversible.has(id));
  if(blocked.length) reasons.push('不可逆步骤阻断回滚: '+blocked.join(','));
  const ordered=[...cascade].sort((a,b)=>(map.get(b).migratedAt||0)-(map.get(a).migratedAt||0));
  return { target:targetId,affected:[...affected],cascade:ordered,feasible:!blocked.length,reasons };
}
console.log(assessRollback([
  {id:1,migratedAt:1,dependsOn:[],rolledBack:false},
  {id:2,migratedAt:2,dependsOn:[1],rolledBack:false},
],1));
```
**评分点**：
- affected/cascade 沿依赖图递归计算，用 Set 防环，已回滚步骤不计入。
- feasible 考虑不可逆步骤阻断，reasons 说明原因。
- target 不存在、空 dependsOn 等边界处理正确。
- cascade 按 migratedAt 降序（后迁移先回滚）返回，代码可运行。
- 明确「外部副作用不可逆需业务补偿」（加分项）。
