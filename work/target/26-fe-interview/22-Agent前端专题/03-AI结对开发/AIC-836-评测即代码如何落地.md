## AIC-836：「评测即代码」（Evaluation as Code）如何落地？
**答**：
- 核心思想：评测用例、评测逻辑、通过标准都像代码一样**进版本库、走 code review、可复现、可回滚**，而不是散落在某个平台的数据库里靠点击配置。
- 落地形态：仓库里放 `evals/` 目录——用例用 YAML/JSON 声明（`prompt + expectation + tags`），评测器用代码写（`scorer.ts`），CI 配置声明何时跑（PR 时跑冒烟、每日跑全量）。变更评测集就是一次 PR。
- 好处：可 diff（谁把通过标准从 0.8 改成 0.6 一眼可见）、可复现（任何人在任何环境跑同样结果）、可回滚（评测误判可 revert）。
- 难点与对策：用例含敏感数据要脱敏入库；大规模评测耗时要用缓存与增量执行；评测器自身变更要单独 review（防止「改评测器让指标变绿」）。
- 追问钩子：能说出「评测器和阈值变更要当作高优先级 PR 审查，防止指标被'调参'修饰」的候选人，理解评测即代码也带来新的作弊面。

```typescript
// evals/summary.ts —— 用例与标准随代码版本化（也可用 YAML/JSON 声明）
const suite = {
  name: 'summary-quality',
  cases: [{ id:'sum-001',
    prompt:'用一句话总结：AI 编码工具提升效率但需人工把关',
    expectation:"必须同时包含'效率'与'把关'两个要点", tags:['summary','chinese'] }],
  threshold: { passRate:0.9, p10:0.6 },
  scorer: './scorers/summary.ts',
};
// CI 中读取声明，执行评测并对照阈值
async function runEvalSuite(s: typeof suite) {
  const scorer = await import(s.scorer);
  const scores = await Promise.all(s.cases.map((c: any) =>
    scorer.score(await model.chat(c.prompt), c.expectation)));
  const passRate = scores.filter((x: number) => x >= 0.8).length / scores.length;
  const pass = passRate >= s.threshold.passRate;
  console.log({ suite:s.name, passRate, pass });
  if (!pass) process.exit(1); // 失败则阻断 PR
}
```
