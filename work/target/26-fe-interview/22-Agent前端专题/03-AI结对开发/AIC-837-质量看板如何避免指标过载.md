## AIC-837：质量看板堆了几十个指标，为什么没人看？该怎么设计？
**答**：
- 指标过载的根因是「什么都想看」但没有**决策上下文**：看板不告诉用户「现在该做什么」。好的看板是决策工具，不是数据陈列柜。
- 分层设计：北极星指标（1~2 个，如 AI 代码存活率、线上逃逸缺陷数）放首屏；诊断指标按「人-机-模型-流程」分组折叠；明细数据按需下钻。不同角色看不同视图（一线开发看自己 PR 的 review 意见，管理者看趋势）。
- 每个指标要配**基线、目标、趋势、异常标注**，且回答「恶化了怎么办」——没有行动项的指标应该删掉。
- 减少噪声：合并重复指标（5 种「采纳率」其实是一回事）、固定刷新节奏、异常才推送而不是每天发日报；看板要能记录「为什么这个月指标变了」的事件注释（发布/模型切换）。
- 追问钩子：能说出「看板的价值是驱动行动，驱动不了行动的指标就删掉」的候选人，具备产品化思维而非堆砌数据。

```typescript
type Metric = {
  id: string; value: number; baseline: number; target: number;
  trend: number[]; owner?: string; action?: string;
};

// 看板裁剪：只保留「能驱动行动」的指标进入首屏
function buildDashboard(metrics: Metric[]) {
  const hero = metrics.filter(m =>
    m.action &&                                   // 有明确行动项
    (m.value < m.target * 0.9 || m.value > m.baseline * 1.1)); // 偏离目标/基线
  return {
    hero: hero.map(m => ({
      id: m.id, value: m.value, gap: +(m.value - m.target).toFixed(2),
      action: m.action, owner: m.owner ?? 'unassigned',
    })),
    hiddenCount: metrics.length - hero.length,     // 其余折叠，需要时下钻
  };
}
console.log(buildDashboard([
  { id:'escape-bugs', value:8, baseline:3, target:2, trend:[3,4,5,8],
    action:'加强 payment 模块评测', owner:'qa-lead' },
  { id:'total-prompts', value:1000, baseline:900, target:2000, trend:[], action:'' },
])); // 首屏只显示 escape-bugs，带行动项与 owner
```
