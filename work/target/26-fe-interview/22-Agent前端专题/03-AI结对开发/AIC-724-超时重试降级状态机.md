## AIC-724：笔试：实现多模型流水线的超时-重试-降级状态机

**需求**：实现 `pipelineState(events, opts)`。`events`: `Array<{ type: 'timeout'|'error'|'success', model: string }>`；`opts`: `{ maxRetry, fallbackModel }`。规则：1) 初始状态 `{ state:'calling', retries:0, model:events[0]?.model }`；2) timeout 或 error：若 `retries < maxRetry` 则 `retries++`、状态回 `calling`（重试同模型）；否则切到 `fallbackModel`、状态 `degraded`、`retries` 归零；3) success：状态 `done`；4) degraded 后再出错则状态 `failed`。边界：events 空（返回初始 calling、retries 0）；success 后事件忽略（终态）；maxRetry 默认 2。返回最终状态对象。

**答**：
- 结论先行：状态机把「重试/降级/成功/失败」显式化，避免散落的 if-else；关键是「降级后再失败=终态 failed」，不能无限重试。
- 终态（done/failed）后事件要忽略，否则成功后的迟到 timeout 会把状态改坏。
- 追问钩子：为什么降级后 retries 要归零？——降级模型是新的尝试主体，应给它独立的重试预算，而不是继承主模型的失败计数。

```javascript
function pipelineState(events = [], opts = {}) {
  const maxRetry = opts.maxRetry ?? 2;
  const fallback = opts.fallbackModel ?? 'fallback';
  let st = { state: 'calling', retries: 0, model: events[0]?.model ?? 'main' };
  const terminal = s => s.state === 'done' || s.state === 'failed';
  for (const e of events) {
    if (terminal(st)) break;                       // 终态忽略后续事件
    if (e.type === 'success') { st.state = 'done'; continue; }
    if (e.type === 'timeout' || e.type === 'error') {
      if (st.state === 'degraded') { st.state = 'failed'; break; }
      if (st.retries < maxRetry) { st.retries++; continue; }        // 重试
      st = { state: 'degraded', retries: 0, model: fallback };      // 降级
    }
  }
  return st;
}
console.log(pipelineState([{ type: 'timeout' }, { type: 'timeout' }], { maxRetry: 2 }).state); // degraded
console.log(pipelineState([{ type: 'success' }, { type: 'error' }]).state); // done（终态忽略）
console.log(pipelineState([]).state); // calling（边界）
console.log(pipelineState([{ type: 'timeout' }, { type: 'timeout' }, { type: 'timeout' }, { type: 'error' }], { maxRetry: 1 }).state); // failed
```


**评分点**：
- 重试预算（retries < maxRetry）与降级切换正确
- 降级后 retries 归零、降级再失败进 failed 终态
- 终态事件忽略（done 后不被迟到事件改坏）
- 边界（空 events）处理
