## AIC-963：笔试：实现「重构变更的风险评分器」（综合影响面/测试覆盖/变更类型给出风险分与流程建议）
**答**：
- 核心需求：实现 `scoreRefactor(change, context)`。`change: { files, linesChanged, type, hasTests, touchesContract, flags }[]`；`context: { impactCount, coverage, isPeakSeason }`。返回 `{ score, level, advice }`。
- 评分维度（各 0~N 累加）：① 影响面 impactCount（每 5 个 +1）；② 变更类型（contract/删除 +3，纯重命名 +0）；③ 测试缺口（hasTests=false +2，coverage<0.6 +2）；④ 封版期 isPeakSeason +2；⑤ 大文件改动 linesChanged>300 +1。
- 等级与建议：score≤2 低风险（自动流程）、3~5 中风险（人工 review）、>5 高风险（强制灰度 + 回滚预案 + 专家评审）。
- 边界：change 为空返回 score=0/低风险；各字段缺失用默认值；score 封顶 10。
- 语义：这是「决策辅助」——评分帮助选择合适流程，不替代人判断；评分规则要可解释、可调整。
- 追问钩子：能指出「风险分要让团队共同校准规则，且高风险不是禁止重构而是要求更强流程」的候选人理解评分的治理价值。

```typescript
function scoreRefactor(changes=[], context={}) {
  let score=0;
  for(const c of changes){
    score += Math.floor((context.impactCount||0)/5);
    score += ['contract','delete'].includes(c.type)?3:0;
    score += c.hasTests===false?2:0;
    score += (context.coverage??1)<0.6?2:0;
    score += context.isPeakSeason?2:0;
    score += (c.linesChanged||0)>300?1:0;
  }
  score=Math.min(10,score);
  const level = score<=2?'低':score<=5?'中':'高';
  const advice = level==='低'?'自动流程':level==='中'?'人工 review':'强制灰度+回滚预案+专家评审';
  return { score, level, advice };
}
console.log(scoreRefactor([{type:'contract',hasTests:false,linesChanged:400}],
  {impactCount:12,coverage:0.5,isPeakSeason:true})); // 高风险
```
**评分点**：
- 评分覆盖影响面/变更类型/测试缺口/封版期/大文件多维度，累加逻辑正确。
- 等级分层与对应流程建议（低/中/高）合理、可执行。
- change 为空、字段缺失默认值、score 封顶 10 等边界处理完整。
- 返回 score/level/advice 结构完整，代码可运行。
- 明确「决策辅助、规则可校准、高风险≠禁止」（加分项）。
