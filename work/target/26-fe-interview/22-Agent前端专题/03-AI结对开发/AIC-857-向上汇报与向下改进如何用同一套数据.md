## AIC-857：给老板汇报的数字和给团队复盘的数字，怎么做到同源又不打架？
**答**：
- 打架的根源是两套口径：汇报时挑好看的指标（采纳率 90%），复盘时看真实问题（存活率 40%）。解决是**单一数据源 + 单一指标定义层**，所有视图从同一语义层出数，口径不一致在技术上就不可能。
- 但**呈现要分层**：向上汇报强调「结论 + 趋势 + 业务影响 + 需要的决策」，不需要过程细节；向下复盘强调「明细 + 归因 + 改进行动」，要能看到问题发生在哪。
- 诚实呈现是底线：汇报不能只报喜——同时展示护栏指标（逃逸缺陷、回滚率）和置信区间，让读者看到全貌；否则一旦被追问就露馅，反而损害信任。
- 让数据驱动决策而非表演：汇报的结尾要有「基于数据我们建议做什么」，复盘的结尾要有「下次怎么验证改进有效」——两手都要落到行动。
- 追问钩子：能说出「同源不同粒度，向上给结论向下给明细，但都必须带护栏指标」的候选人，具备数据沟通的专业性。

```typescript
// 单一语义层：所有视图共用同一份指标定义与计算
const metricDefs = {
  adoption: (d: any) => d.accepted / (d.suggestions || 1),
  survival:  (d: any) => d.survived / (d.accepted || 1),
  escaped:   (d: any) => d.escapedBugs,
};
function compute(defs: any, data: any) {
  return Object.fromEntries(Object.entries(defs).map(([k, fn]: any) => [k, fn(data)]));
}

// 向上：结论 + 护栏，隐藏明细
function execReport(m: any) {
  return { headline: `AI 采纳率 ${(m.adoption*100).toFixed(0)}%`,
    guardrails: { survival: m.survival, escaped: m.escaped },
    ask: '建议继续投入，重点提升长文档质量' };
}
// 向下：明细 + 行动
function retroReport(m: any, details: any[]) {
  return { metrics: m, worstCases: details.slice(0, 3),
    action: '针对长文档任务补充分段提示词模板，下次复盘验证存活率' };
}
const data = { suggestions:1000, accepted:900, survived:360, escapedBugs:2 };
const m = compute(metricDefs, data);
console.log(execReport(m)); // 同时展示采纳与护栏，不报喜不报忧
```
