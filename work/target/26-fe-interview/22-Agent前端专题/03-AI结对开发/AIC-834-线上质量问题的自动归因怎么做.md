## AIC-834：线上出现一个 AI 质量问题，如何自动定位是哪个环节引入的？
**答**：
- AI 链路比传统系统多几个「嫌疑变量」：代码版本、**模型版本**、**prompt 版本**、RAG 语料版本、参数配置。归因就是在这几个维度上做「差异定位」。
- 前提是**全量打标**：每个请求记录上述版本信息（血缘 AIC-810），并关联到结果质量信号（用户反馈/自动评测分）。没有数据就无法归因。
- 归因方法：① **对照组分析**——对比出问题请求与正常请求在各版本维度的分布，找显著偏斜的维度（卡方检验）；② **二分回放**——用历史版本重放问题请求，看换成哪个版本问题消失；③ **变更关联**——把问题时间窗与发布/配置变更时间轴对齐。
- 自动归因给出「嫌疑排序 + 证据」，最终由人确认；不要自动回滚——多变量同时变化时自动决策风险高。
- 追问钩子：能说出「模型版本/prompt 版本必须像代码版本一样进血缘，否则无法归因」的候选人，抓住 AI 系统可观测性的核心差异。

```typescript
type Req = {
  id: string; ok: boolean;
  versions: { code: string; model: string; prompt: string; rag: string };
};

// 找与质量问题最相关的版本维度：某取值在失败组中占比显著高于整体
function attribute(requests: Req[]) {
  const failed = requests.filter(r => !r.ok);
  const dims = ['code', 'model', 'prompt', 'rag'] as const;
  const suspects: Array<{ dim: string; value: string; lift: number }> = [];
  for (const dim of dims) {
    const overall = new Map<string, number>(), bad = new Map<string, number>();
    for (const r of requests) overall.set(r.versions[dim], (overall.get(r.versions[dim]) ?? 0) + 1);
    for (const r of failed)   bad.set(r.versions[dim], (bad.get(r.versions[dim]) ?? 0) + 1);
    for (const [v, n] of bad) {
      const badRate = n / failed.length;
      const baseRate = (overall.get(v) ?? 0) / requests.length;
      suspects.push({ dim, value: v, lift: +(badRate / (baseRate || 1e-9)).toFixed(2) });
    }
  }
  return suspects.sort((a, b) => b.lift - a.lift).slice(0, 3); // 嫌疑排序
}
console.log(attribute([
  { id:'1', ok:true,  versions:{ code:'c1', model:'m1', prompt:'p1', rag:'r1' } },
  { id:'2', ok:true,  versions:{ code:'c1', model:'m1', prompt:'p1', rag:'r1' } },
  { id:'3', ok:false, versions:{ code:'c1', model:'m2', prompt:'p1', rag:'r1' } },
])); // model=m2 lift 最高 → 首要嫌疑
```
