## AIC-681：AI 效能度量怎么形成「闭环」而不是只出报表？

**答**：
- 结论先行：**度量的终点不是「出报表」，而是「驱动改进并验证改进有效」——没有闭环的度量是纯成本**。闭环 = 观察指标 → 定位问题 → 采取干预 → 验证效果。
- 闭环四步：1) **观察**：看板看趋势与分层，发现退化指标（AIC-672）；2) **归因**：把指标退化定位到具体环节——接受率低是 prompt 问题还是模型选错？逃逸率高是审查失效还是上下文不足？3) **干预**：针对性调整（改 rules/换模型/加强审查/重构任务模板）；4) **验证**：下个周期看同一指标是否改善——不改善就说明归因错了，重新分析。
- 机制保障：1) **固定复盘节奏**（如双周会），把看板作为会议输入；2) **每个干预记录假设**——「我们改了 X，预期 Y 指标提升 Z」，便于事后核对；3) **A/B 验证重要干预**（AIC-670），避免「改了之后指标涨了」的虚假归因（可能只是季节波动）。
- 避免的坑：只跟踪「提升」不跟踪「退化」；指标涨了就停止改进（应该问「还能更好吗」）；把度量变成考核（AIC-676）。
- 追问钩子：为什么「记录干预假设」是闭环的关键？——因为没有假设，事后无法判断「指标变化是不是因为我们的干预」；记录了「预期 Y 提升 Z」，就能核对——对不上就说明归因错误或有混淆变量，这是让度量从「讲故事」变成「可证伪实验」的关键。

```typescript
type Cycle = { metric: string; before: number; after: number; hypothesis: string; target: number };

function closeTheLoop(c: Cycle): { effective: boolean; verdict: string } {
  const actualChange = c.after - c.before;
  const expectedChange = c.target - c.before;
  // 实际变化达到预期的 70% 以上视为干预有效
  const effective = expectedChange > 0 ? actualChange >= expectedChange * 0.7 : actualChange <= expectedChange * 0.7;
  return {
    effective,
    verdict: effective
      ? `验证通过：${c.metric} 按假设 ${c.hypothesis} 改善`
      : `验证失败：归因可能有误，需重新分析（预期 ${expectedChange.toFixed(1)}，实际 ${actualChange.toFixed(1)}）`,
  };
}

const cycle: Cycle = {
  metric: 'AI代码逃逸率', before: 0.2, after: 0.12,
  hypothesis: '加强属性测试覆盖边界', target: 0.1,
};
console.log(closeTheLoop(cycle).effective === true); // 0.08 改善 >= 0.1*0.7
console.log(closeTheLoop({ ...cycle, after: 0.19 }).effective === false);
```
