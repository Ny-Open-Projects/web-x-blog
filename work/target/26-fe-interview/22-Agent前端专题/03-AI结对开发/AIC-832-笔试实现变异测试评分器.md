## AIC-832：笔试：实现变异测试评分器，统计杀死率与存活变异体
**答**：
- 核心需求：实现 `mutationTest(source, mutantSpecs, testRunner)`。`mutantSpecs: { id, find: string|RegExp, replace: string }[]`；对每个 spec 生成变异源码（只替换第一处），调用 `testRunner(mutatedSrc)` 返回 `boolean`（true=测试通过）。测试通过说明变异存活（测试没抓到 bug），测试失败说明变异被杀死。返回 `{ score, killed, survived, invalid }`。
- 边界：`find` 未在源码中出现 → 归入 invalid（变异未生效，不计入分母）；`testRunner` 抛异常视为测试失败（变异被杀死）；原始源码本身测试必须能通过，否则报错（基线不成立）。
- 语义：score = killed / (killed + survived)，invalid 不计入；survived 列表要给出 id 与替换内容便于人工补测试。
- 追问钩子：追问「变异测试成本高，怎么在实践中用」——能答出「只对核心模块 / 增量代码跑，或离线定时跑，不进每次 PR 门禁」的候选人懂成本权衡。

```typescript
type Spec = { id: string; find: string; replace: string };

function mutationTest(
  source: string,
  specs: Spec[],
  testRunner: (src: string) => boolean
) {
  if (!testRunner(source)) throw new Error('baseline test must pass');

  const killed: string[] = [], survived: string[] = [], invalid: string[] = [];
  for (const spec of specs ?? []) {
    if (!source.includes(spec.find)) { invalid.push(spec.id); continue; }
    const mutated = source.replace(spec.find, spec.replace); // 只替换第一处
    let testPassed = true;
    try { testPassed = testRunner(mutated); } catch { testPassed = false; }
    if (testPassed) survived.push(`${spec.id}: ${spec.find} → ${spec.replace}`);
    else killed.push(spec.id);
  }
  const denom = killed.length + survived.length;
  return {
    score: denom ? +(killed.length / denom).toFixed(2) : 0,
    killed, survived, invalid,
  };
}

// 模拟：测试只有断言 total > 0
const src = 'function total(a,b){ return a + b; }';
const specs: Spec[] = [
  { id: 'plus-to-minus', find: 'a + b', replace: 'a - b' }, // 测试若只查 >0 可能存活
  { id: 'drop-b', find: 'a + b', replace: 'a' },
  { id: 'not-found', find: 'xyz', replace: 'abc' },          // invalid
];
const test = (s: string) => {
  // 用 eval 简化演示：真实场景应沙箱执行
  const fn = new Function(s + '; return total(5,3);')();
  return fn > 0;
};
console.log(mutationTest(src, specs, test));
// 暴露测试盲区：plus-to-minus 等变异未被杀死
```
**评分点**：
- 基线校验：原始源码测试必须通过，否则抛错，避免无效评估。
- `find` 不存在归入 invalid 且不计入分母，避免虚高/虚低。
- testRunner 抛异常视为「测试失败 = 变异被杀死」，语义正确。
- `String.replace` 只替换首处，符合「单点变异」原则。
- survived 带可读描述，能定位测试盲区（工程可用性）。
