## AIC-643：多模型协作链路挂了一个模型，怎么优雅降级？

**答**：
- 结论先行：**降级的原则是「丢能力不丢底线」——多模型协作的额外价值（交叉验证/精修）可以丢，但「产出可用代码 + 基本验证」的底线不能丢**（AIC-421 门禁降级 / AIC-161 重试降级）。
- 分级降级：1) **审查模型挂**：跳过交叉审查，但保留该 PR 的「人工 review 强制」标记——把机器防线降级为人防线，不直接放行；2) **规划模型挂**：降级为「人写任务卡 + 编码模型执行」——规划能力由人补上；3) **主编码模型挂**：切换到备用模型重跑（AIC-160 多模型路由器故障切换）；全部模型挂：任务入队等待，不返回半成品。
- 关键设计：1) **降级要显式记录**：产出里标注「本次未经交叉审查」，让 review 者知道风险等级；2) **降级可恢复**：模型恢复后，降级期间的任务进入「补审队列」——不是不了了之；3) **熔断防雪崩**：某模型连续失败就熔断，避免所有任务都卡在等它超时。
- 追问钩子：为什么「降级期间的任务要补审」而不是「算了」？——因为降级只是延迟验证不是取消验证；如果不补审，这些任务就成了「永远没被交叉验证」的漏网之鱼，风险悄悄积累，下次事故就出在这里。

```typescript
type Stage = { name: string; essential: boolean; available: boolean };
type DegradeResult = { runStages: string[]; flags: string[]; needReaudit: boolean };

function degrade(stages: Stage[]): DegradeResult {
  const runStages: string[] = [], flags: string[] = [];
  for (const s of stages) {
    if (s.available) runStages.push(s.name);
    else if (s.essential) return { runStages: [], flags: ['critical-stage-down'], needReaudit: true };
    else flags.push(`skipped:${s.name}`); // 非关键阶段跳过，显式标记
  }
  return { runStages, flags, needReaudit: flags.length > 0 };
}

const stages = [
  { name: 'plan', essential: true, available: true },
  { name: 'code', essential: true, available: true },
  { name: 'cross-review', essential: false, available: false }, // 审查模型挂了
];
const r = degrade(stages);
console.log(r.runStages.join(',') === 'plan,code');
console.log(r.needReaudit && r.flags.includes('skipped:cross-review')); // 降级但标记补审
console.log(degrade([{ name: 'code', essential: true, available: false }]).flags); // ['critical-stage-down']
```
