## AIC-986：降低 AI Review 误报的同时可能漏掉真问题（漏报），这对矛盾如何平衡？
**答**：
- 先承认「误报与漏报是此消彼长的」（阈值移动）——结论：不存在两者都最优的点，要根据场景选偏向：安全/资金类宁可误报（高召回），风格类宁可漏报（高精确）。
- 用「分层阈值」代替全局阈值：对高风险规则（密钥泄露、资金计算）保持高敏感，对低风险建议类规则提高门槛减少骚扰。
- 用「互补手段」补漏报：静态分析、测试、人工 review 各抓不同问题，AI Review 不必追求全包；明确它「主攻什么、放过什么」，用其他层兜底。
- 追问钩子：能说出「平衡的本质是风险偏好与成本分配——把有限的注意力放在代价最高的错误类型上」的候选人，把技术问题上升到了决策层面。

```typescript
// 分层阈值：高风险高召回，低风险高精确
const rules = [
  { id:'SECRET', kind:'security', threshold:0.3 }, // 低门槛，宁可误报
  { id:'STYLE', kind:'style', threshold:0.85 },    // 高门槛，宁可漏报
];
function shouldReport(rule, confidence) {
  return confidence >= rule.threshold;
}
// 互补手段兜底：AI 漏掉的高风险问题由静态分析/测试补
function complementaryCheck(code, aiResult) {
  const secrets = /secret\s*=\s*['"][^'"]+/.test(code);
  return {
    aiReported: aiResult,
    staticCaught: secrets && !aiResult ? '密钥泄露(AI漏报)' : null,
  };
}
console.log(rules.map(r=>({id:r.id, reportLowConf:shouldReport(r,0.5)})));
console.log(complementaryCheck('const secret = "abc"', false)); // 静态分析补漏报
```
