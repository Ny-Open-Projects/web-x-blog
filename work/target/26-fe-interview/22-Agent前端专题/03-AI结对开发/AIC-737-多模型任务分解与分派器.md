## AIC-737：笔试：实现多模型任务分解与分派器

**需求**：实现 `dispatch(tasks, models)`。`tasks`: `Array<{ id, kind, dependOn? }>`（`kind`: 'plan'|'code'|'review'|'test'）；`models`: `Array<{ name, skills: string[], load: number }>`。规则：1) 按 skills 匹配 kind（model.skills 含 kind 才能接）；2) 在无依赖冲突的前提下，选「匹配且 load 最小」的模型；3) 有 `dependOn` 的任务必须排在被依赖任务之后（拓扑序）；4) 分派后对应 model.load++；5) 返回 `{ order: string[]（任务 id）, assign: Record<id, modelName>, unassigned: string[] }`。边界：无匹配模型的任务进 unassigned；tasks 空（全空）；依赖成环的任务也进 unassigned（用访问标记检测）。

**答**：
- 结论先行：分派 = 拓扑排序（保证依赖顺序）+ 贪心负载均衡（选当前最闲的可用模型）；两者结合既满足先后约束又避免单点过载。
- 环检测必须做，否则拓扑排序死循环；成环任务无法执行，应显式标为 unassigned 而非静默丢弃。
- 追问钩子：为什么「先拓扑后分派」而不是「边排边分」？——先把依赖关系解开，分派时只需看可用性，逻辑更清晰且不易出错。

```javascript
function dispatch(tasks = [], models = []) {
  const state = new Map(); // 0未访问 1访问中 2完成
  const order = [], assign = {}, unassigned = [];
  const map = new Map(tasks.map(t => [t.id, t]));
  function visit(id, stack = new Set()) {
    if (state.get(id) === 2) return true;
    if (state.get(id) === 1 || stack.has(id)) return false; // 环
    state.set(id, 1); stack.add(id);
    const t = map.get(id);
    if (t?.dependOn && !visit(t.dependOn, stack)) return false;
    stack.delete(id); state.set(id, 2); order.push(id); return true;
  }
  for (const t of tasks) {
    if (!visit(t.id)) { unassigned.push(t.id); continue; }
    const cand = models.filter(m => m.skills.includes(t.kind)).sort((a, b) => a.load - b.load)[0];
    if (cand) { assign[t.id] = cand.name; cand.load++; }
    else unassigned.push(t.id);
  }
  return { order, assign, unassigned };
}
const r = dispatch(
  [{ id: 't1', kind: 'plan' }, { id: 't2', kind: 'code', dependOn: 't1' }, { id: 't3', kind: 'review' }],
  [{ name: 'A', skills: ['plan', 'code'], load: 0 }, { name: 'B', skills: ['review'], load: 0 }]
);
console.log(r.order.indexOf('t1') < r.order.indexOf('t2')); // 依赖顺序
console.log(r.assign.t1 === 'A' && r.assign.t3 === 'B');
console.log(r.unassigned.length === 0);
```


**评分点**：
- 拓扑排序保证依赖顺序
- 环检测（visit 状态标记）防死循环
- 贪心选最闲可用模型并 load++、无匹配进 unassigned
- 边界（空 tasks）处理
