## AIC-800：笔试：实现 AI 工具链平台迁移的双跑校验器

**需求**：实现 `dualRunCheck(legacyResults, platformResults, opts)`。两个数组元素为 `{ taskId, quality, costMs, ok }`；`opts.qualityTolerance`（默认 0.05）、`costTolerance`（默认 1.3，平台成本倍数上限）。规则：1) 按 taskId 配对，只校验两边都有的任务；2) 平台质量不得低于 legacy 质量超过 tolerance（`platform.quality >= legacy.quality - tolerance`），否则记 `qualityRegress`；3) 平台成本不得高于 legacy 的 costTolerance 倍（`platform.costMs <= legacy.costMs * costTolerance`），否则记 `costRegress`；4) 平台 ok=false 而 legacy ok=true 记 `failRegress`；5) 返回 `{ pairs, issues: Array<{taskId, type}>, ready: boolean }`（ready=issues 空）。边界：任一边空（pairs=0、issues=[]、ready=true 但标注 noData=true）；单边独有 taskId 忽略。

**答**：
- 结论先行：双跑校验是迁移的「信任闸门」——用真实任务证明平台「不更差」，三类回归（质量/成本/可用性）任一出现都阻断切换。
- 配对只校验共有任务是「公平比较」的前提；单边任务无对照，不能据此判断优劣。
- 追问钩子：为什么成本允许一定 tolerance（如 1.3 倍）？——迁移期平台可能有额外开销（适配、双写），小幅成本上升可接受，但要有上限防止失控。

```javascript
function dualRunCheck(legacy = [], platform = [], opts = {}) {
  const qt = opts.qualityTolerance ?? 0.05;
  const ct = opts.costTolerance ?? 1.3;
  const pMap = new Map(platform.map(p => [p.taskId, p]));
  const issues = [];
  let pairs = 0;
  for (const l of legacy) {
    const p = pMap.get(l.taskId);
    if (!p) continue;                                  // 单边任务忽略
    pairs++;
    if (p.quality < l.quality - qt) issues.push({ taskId: l.taskId, type: 'qualityRegress' });
    if (p.costMs > l.costMs * ct) issues.push({ taskId: l.taskId, type: 'costRegress' });
    if (l.ok && !p.ok) issues.push({ taskId: l.taskId, type: 'failRegress' });
  }
  return { pairs, issues, ready: issues.length === 0, noData: pairs === 0 };
}
const legacy = [
  { taskId: 't1', quality: 0.9, costMs: 100, ok: true },
  { taskId: 't2', quality: 0.8, costMs: 200, ok: true },
];
const platform = [
  { taskId: 't1', quality: 0.88, costMs: 120, ok: true },  // 可接受
  { taskId: 't2', quality: 0.6, costMs: 500, ok: false },  // 三类全中
];
const r = dualRunCheck(legacy, platform);
console.log(r.ready === false && r.issues.length === 3);
console.log(dualRunCheck([], platform).noData === true); // 边界
```


**评分点**：
- 按 taskId 配对、只校验共有任务
- 质量/成本/可用性三类回归判定
- tolerance 含边界、ready = issues 为空
- 边界（单边空 noData）
