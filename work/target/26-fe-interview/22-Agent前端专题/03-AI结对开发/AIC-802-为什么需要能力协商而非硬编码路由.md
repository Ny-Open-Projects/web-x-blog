## AIC-802：为什么多模型平台需要「能力协商」而不是硬编码路由表？
**答**：
- 硬编码路由（`if task==='code' use modelA`）把「任务语义」和「具体模型」焊死：模型下架、涨价、能力升级都要改代码发版，平台失去弹性。
- 协商是双向的：任务侧声明**必需能力 / 禁止项 / 预算 / 延迟上限**，模型侧声明**能力清单 / 约束 / 价格 / 生命周期**，由协商器求交集并按策略排序。它把「选谁」从编码期推迟到运行期。
- 协商要支持「降级链」：首选不满足预算时自动落到次优模型，而不是直接失败；同时要能表达「硬约束」（如合规要求模型必须境内），软约束（成本）可妥协。
- 可观测性：每次协商产出 `decisionLog`（候选集、淘汰原因、最终选择），这是事后归因与 A/B 分析的依据。
- 追问钩子：追问「硬约束和软约束怎么表达」——能答出 `must / should` 分层并把淘汰原因结构化的候选人，说明考虑过真实治理成本。

```typescript
type Requirement = {
  must: string[];            // 硬约束：必须具备的能力
  forbidden?: string[];      // 硬约束：禁止项（如境外节点）
  should?: { maxCost: number; maxLatency: number }; // 软约束
};
type Decision = { modelId: string; candidates: string[]; rejected: Record<string, string> };

function negotiate(req: Requirement, models: any[]): Decision {
  const rejected: Record<string, string> = {};
  let pool = models.filter(m => {
    if (req.forbidden?.some(f => m.constraints?.includes(f))) {
      rejected[m.modelId] = 'forbidden constraint'; return false;
    }
    if (!req.must.every(c => m.capabilities?.includes(c))) {
      rejected[m.modelId] = 'missing must capability'; return false;
    }
    return true;
  });
  if (req.should) {
    const soft = pool.filter(m =>
      m.costPer1k <= req.should!.maxCost && m.latency <= req.should!.maxLatency);
    if (soft.length) pool = soft; // 软约束满足则收敛，否则保留全集降级
  }
  const picked = pool.sort((a, b) => a.costPer1k - b.costPer1k)[0];
  if (!picked) throw new Error('no model satisfies hard constraints');
  return { modelId: picked.modelId, candidates: pool.map(m => m.modelId), rejected };
}

```
