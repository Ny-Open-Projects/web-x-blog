## AIC-706：如何让 AI 扮演红队与蓝队做对抗式代码审查

**答**：
- 结论先行：单模型「自我审查」容易顺着自己的思路走；用「红队找茬 + 蓝队辩护」的双角色对抗，能暴露单点审查漏掉的缺陷——本质是引入视角多样性而非重复同一判断。
- 落地方式：同一份 diff 给两个独立会话，一个 prompt 要求「尽可能挑出 bug / 安全 / 边界问题」，另一个要求「论证这段代码为何正确并给出证据」；人做裁判，对比两边分歧点。
- 关键：两角色必须隔离上下文（互不看对方输出），否则会被「锚定」到同一结论；分歧点才是审查重点。
- 追问钩子：对抗审查与多模型投票有何不同？——投票追求「一致性」，对抗追求「暴露分歧」，后者更利于发现罕见缺陷。

```javascript
// 对抗式审查：红蓝隔离，只把分歧点交给人
function adversarialReview(diff, redFn, blueFn) {
  const red = redFn(diff);   // 独立会话：只找问题
  const blue = blueFn(diff); // 独立会话：只证正确
  const redIssues = new Set(red.issues.map(i => i.line));
  const blueOk = new Set(blue.proofs.map(p => p.line));
  return {
    agreed: [...redIssues].filter(l => blueOk.has(l)), // 双方都提到→重点复核
    disputes: [...redIssues].filter(l => !blueOk.has(l)), // 仅红队提出→人工裁决
  };
}
const diff = { id: 1 };
console.log(adversarialReview(diff,
  () => ({ issues: [{ line: 5 }, { line: 9 }] }),
  () => ({ proofs: [{ line: 5 }] })));
// disputes: [9] —— 红队指出但蓝队未辩护，正是可疑点
```
