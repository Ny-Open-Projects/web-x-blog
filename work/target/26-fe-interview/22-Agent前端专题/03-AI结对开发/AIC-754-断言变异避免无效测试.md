## AIC-754：AI 测试生成中如何通过断言变异避免测试通过但无效

**答**：
- 结论先行：断言变异 = 故意把实现改错（改一个常量、反转一个条件），看测试是否失败；如果不失败，说明测试断言太弱（形同虚设）——这是检验「测试有效性」的黄金方法，比覆盖率更靠谱。
- 做法：对源码做一批自动变异（如 `>` 改成 `>=`、`+` 改成 `-`），逐个跑测试；杀死变异体的比例即「变异分数」，低分数说明断言弱。
- 与覆盖率的区别：覆盖率高只表示代码被执行到，不表示断言在验证行为；变异分数直接衡量「测试能否发现错误」。
- 追问钩子：为什么 AI 生成的测试常断言弱？——AI 倾向写「能跑通」的测试（如 `expect(result).toBeDefined()`），而非「能证伪」的强断言。

```javascript
// 变异测试：改错实现，看测试是否失败
function mutationScore(source, mutants, runTests) {
  let killed = 0;
  for (const m of mutants) {
    const ok = runTests(m.code);        // 用变异代码跑测试
    if (!ok) killed++;                  // 测试失败 = 杀死了变异体
  }
  return { score: mutants.length ? killed / mutants.length : 0, killed, total: mutants.length };
}
const mutants = [
  { code: 'a > b' },   // 原: a >= b
  { code: 'a - b' },   // 原: a + b
];
console.log(mutationScore('', mutants, code => code === 'a >= b' ? false : true));
// { score:0.5, killed:1, total:2 } —— 只杀死 1 个，断言偏弱
```
