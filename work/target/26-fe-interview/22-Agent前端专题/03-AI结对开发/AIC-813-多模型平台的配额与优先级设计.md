## AIC-813：多模型平台的「配额与优先级」怎么设计，防止一个团队打爆全局？
**答**：
- 配额分三维：**并发数**（同时在跑的请求）、**速率**（QPS/分钟）、**预算**（日/月成本上限）。单一维度不够——限了 QPS 但长请求仍可占满连接。
- 租户隔离：每个 `tenantId/appId` 独立配额桶，互不挤占；同时设一个全局兜底桶防止总量失控。用令牌桶 + 信号量分别管速率与并发。
- 优先级：请求带 `priority`（如 interactive > batch），高优先级可抢占或优先排队；批量任务必须低优先级且可延迟，避免和在线请求抢资源。
- 配额耗尽的处理要分级：先降级到便宜模型或排队，再限流返回 429 + `Retry-After`，不能静默丢弃；要把「谁被打爆、因何被限」记录进可观测体系。
- 追问钩子：能说出「配额是分层令牌桶（租户 + 全局两级）且 batch 任务必须可抢占」的候选人，对多租户平台资源治理有真实理解。

```typescript
class TokenBucket {
  private tokens: number;
  private last = Date.now();
  constructor(private capacity: number, private refillPerSec: number) {
    this.tokens = capacity;
  }
  take(n = 1): boolean {
    const now = Date.now();
    this.tokens = Math.min(this.capacity,
      this.tokens + (now - this.last) / 1000 * this.refillPerSec);
    this.last = now;
    if (this.tokens < n) return false;
    this.tokens -= n;
    return true;
  }
}

class QuotaManager {
  private buckets = new Map<string, TokenBucket>();
  private semaphores = new Map<string, number>();
  constructor(private perTenant: TokenBucket, private globalBucket: TokenBucket) {}

  async acquire(tenant: string, priority: 'interactive' | 'batch'): Promise<boolean> {
    if (priority === 'batch' && !this.globalBucket.take()) return false;
    const b = this.buckets.get(tenant) ?? this.perTenant;
    if (!b.take()) return false;
    const inFlight = this.semaphores.get(tenant) ?? 0;
    if (inFlight >= 20) return false;          // 并发上限
    this.semaphores.set(tenant, inFlight + 1);
    return true;
  }
  release(tenant: string) {
    this.semaphores.set(tenant, (this.semaphores.get(tenant) ?? 1) - 1);
  }
}
```
