## AIC-810：一次请求经过多个模型，平台如何贯穿「请求血缘」？
**答**：
- 请求血缘 = 一个用户请求扇出到「路由 → 主模型 → 裁判模型 → 工具调用 → 缓存」全链路的可追溯关系。没有它，出问题无法回答「这次错误答案是谁产生的、用了哪个模型版本」。
- 实现上用**分布式追踪**：入口生成 `traceId`，每个模型/工具调用生成一个 `span`，透传 `traceparent`（W3C 标准）；span 上打属性：`modelId`、`modelVersion`、`promptVersion`、`cost`、`decisionId`。
- 血缘要**双向可查**：从 traceId 查完整调用树（正向排障），从模型版本反查受影响的所有请求（模型回滚时的影响面）。后者需要按 `modelVersion` 建索引。
- 采样要权衡：全量记录成本高，可对成功请求低采样、错误/高成本请求强制采样；血缘数据保留期与隐私策略对齐（prompt 可能含 PII）。
- 追问钩子：能说出「span 属性里必须带 modelVersion 和 promptVersion」的候选人，说明理解 AI 系统排障区别于传统微服务的特殊性——代码没变但模型/提示词变了也会出问题。

```typescript
type Span = { traceId: string; spanId: string; parentId?: string; attrs: Record<string, any> };

class LineageTracer {
  start(traceId: string, attrs: Record<string, any>): Span {
    const span: Span = { traceId, spanId: crypto.randomUUID(), attrs };
    this.store(span);
    return span;
  }
  child(parent: Span, name: string, attrs: Record<string, any>): Span {
    return this.start(parent.traceId, {
      ...attrs, name, parentId: parent.spanId,
    });
  }
  private store(span: Span) {

const tracer = new LineageTracer();
const root = tracer.start('trace-1', { name: 'user-request' });
const main = tracer.child(root, 'model:main', { modelId: 'gpt-x', modelVersion: 'v2', promptVersion: 'p7' });
const judge = tracer.child(main, 'model:judge', { modelId: 'judge-y', cost: 0.02 });
```
