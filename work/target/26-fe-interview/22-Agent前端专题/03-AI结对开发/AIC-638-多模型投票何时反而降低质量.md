## AIC-638：多模型投票什么时候反而降低质量？

**答**：
- 结论先行：**投票的前提是「错误不相关」；当多个模型同质化地犯同一个错时，投票只是把同一个错误票决成「共识」**——这叫「群体思维」，比单模型更危险因为它给了虚假的确定感（AIC-563 投票器）。
- 投票失效的场景：1) **同源模型**：同一厂商的不同版本、用相似数据训练的模型，盲点高度重叠；2) **prompt 引导一致**：给所有模型相同的（有缺陷的）前提，它们会一致地得出错误结论；3) **多数即正确的错觉**：3 个模型 2 个错 1 个对，投票选错——正确性不取决于票数。
- 什么时候投票有效：模型确实异质（不同厂商/架构）、错误模式独立、且问题是「有唯一正确答案」的客观题（如类型判断）。主观设计题投票意义不大。
- 更好的做法：**「投票 + 多样性度量」**——先算模型间的分歧度（AIC-639），分歧太低（都答一样）时不增加可信度反而降低（可能是共同盲点）；分歧高时人工重点复核那个「少数派答案」，它可能是对的。
- 追问钩子：为什么「少数派答案」值得特别关注？——因为如果多数模型共享一个训练数据里的错误模式，少数派反而可能是唯一发现真相的；投票机制会系统性地埋没它，所以要看少数派而不是无条件服从多数。

```typescript
function voteWithDiversity(answers: { model: string; answer: string }[]) {
  const counts = new Map<string, number>();
  for (const a of answers) counts.set(a.answer, (counts.get(a.answer) || 0) + 1);
  const total = answers.length;
  const sorted = [...counts.entries()].sort((a, b) => b[1] - a[1]);
  const [winner, winnerVotes] = sorted[0];
  const consensus = winnerVotes / total;
  // 高度一致（>0.9）不一定是好事：可能是共同盲点
  return {
    winner,
    consensus,
    suspicious: consensus > 0.9 && total > 1,
    minority: sorted.slice(1).map(([ans]) => ans), // 少数派：重点复核
  };
}

console.log(voteWithDiversity([
  { model: 'A', answer: 'X' }, { model: 'B', answer: 'X' }, { model: 'C', answer: 'Y' },
]).minority); // ['Y'] —— 少数派值得看
console.log(voteWithDiversity([
  { model: 'A', answer: 'X' }, { model: 'B', answer: 'X' }, { model: 'C', answer: 'X' },
]).suspicious); // true —— 全票一致反而可疑
```
