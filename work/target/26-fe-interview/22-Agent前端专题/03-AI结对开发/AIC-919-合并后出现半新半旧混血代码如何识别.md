## AIC-919：多 Agent 合并后，商品列表代码出现「半新半旧」的混血实现（一半用旧 API 一半用新 API），如何识别与清理？
**答**：
- 混血代码的特征是「同一概念存在多套实现」：新旧 API 混用、同一数据结构两种形状、命名风格分裂——识别手段是扫描「不应共存的成对模式」。
- 建立「迁移规则清单」：如「用了 newFetch 的文件不得再出现 axios」「用了 v2 类型不得引用 v1 类型」，用静态扫描自动发现违规文件。
- 用依赖图找「边界文件」：同时被新旧实现引用的适配器文件是混血高发区，应重点审查并明确其去留。
- 追问钩子：能提出「把迁移规则写成可执行的 lint 规则并进 CI，让混血代码无法长期存活」的候选人，用机制而非一次性清理解决问题。

```typescript
// 混血检测：不应共存的成对模式扫描
const rules = [
  { name:'新旧请求库混用', a:/newFetch/, b:/axios/ },
  { name:'v1/v2类型混用', a:/PriceV2/, b:/PriceV1/ },
];
function findHybrid(files) { // files: {path, content}[]
  const hits = [];
  for (const f of files) for (const r of rules)
    if (r.a.test(f.content) && r.b.test(f.content)) hits.push({ file:f.path, rule:r.name });
  return hits;
}
console.log(findHybrid([
  { path:'ProductList.tsx', content:'import newFetch; const p = await axios.get(...)' },
  { path:'Clean.tsx', content:'import newFetch; await newFetch(...)' },
])); // 标记 ProductList.tsx 混血
```
