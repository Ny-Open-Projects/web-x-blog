## AIC-808：多模型平台如何做到供应商「热插拔」，接入新厂商不改业务代码？
**答**：
- 关键是**统一适配器接口**：定义 `ProviderAdapter`（`chat()、stream()、embeddings()、health()`），每个供应商实现一个适配器，把各自的请求/响应/错误码翻译成平台统一模型——业务只见统一模型。
- 能力**归一化**：字段差异（如 `finish_reason` vs `stop_reason`）、错误码、流式事件格式在适配器内收敛；无法归一化的差异写入 `capabilities.constraints` 由协商器处理（AIC-801）。
- 配置驱动 + 依赖注入：模型 id 映射到哪个适配器由配置决定，运行时可切换；新供应商上线 = 新增适配器包 + 注册配置 + 跑**契约测试**。
- 契约测试是热插拔的安全带：用同一组 golden 用例跑所有适配器，断言输出结构一致；未通过契约测试的适配器不允许注册进生产。
- 追问钩子：追问「适配器里要不要做重试和降级」——能答出「不，那是协商/编排层的职责，适配器只做纯粹协议转换（单一职责）」的候选人架构分层很清晰。

```typescript
interface UnifiedRequest { prompt: string; maxTokens?: number; stream?: boolean }
interface UnifiedResponse { text: string; finishReason: 'stop' | 'length' | 'error'; usage: { tokens: number } }
interface ProviderAdapter {
  name: string;
  chat(req: UnifiedRequest): Promise<UnifiedResponse>;
  health(): Promise<boolean>;
}

// 供应商 A 的适配器：把厂商特有字段翻译成统一模型
class ProviderA implements ProviderAdapter {
  name = 'vendor-a';
  async chat(req: UnifiedRequest): Promise<UnifiedResponse> {
    const raw = await vendorA.complete({ input: req.prompt, n: req.maxTokens });
    return {
      text: raw.output.text,
      finishReason: raw.stop_reason === 'end' ? 'stop' : 'length',
      usage: { tokens: raw.meta.total_tokens },
    };
  }
  async health() { return (await vendorA.ping()).ok; }
}

// 工厂按配置选择适配器，业务代码与供应商解耦
const adapters = new Map<string, ProviderAdapter>([['vendor-a', new ProviderA()]]);
export function getAdapter(id: string) {
  const a = adapters.get(id);
  if (!a) throw new Error(`no adapter registered: ${id}`);
  return a;
}
```
