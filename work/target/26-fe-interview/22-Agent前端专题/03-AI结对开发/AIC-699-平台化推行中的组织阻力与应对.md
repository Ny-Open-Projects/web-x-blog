## AIC-699：推行 AI 平台化遇到组织阻力，怎么应对？

**答**：
- 结论先行：**阻力主要来自三点——「习惯惯性」（各人用各的更自在）、「自主权丧失感」（平台统一规范像被管束）、「信任不足」（不信平台能力比自己顺手的工具好）**。应对靠「价值证明 + 渐进推广 + 参与共建」，而非行政强制。
- 针对性应对：1) **习惯惯性**：不禁止现有工具，用「更好用」吸引——门户里让新平台接入成本低于自建（AIC-698）；2) **自主权丧失感**：让一线参与规则制定（rules 共建），平台提供「默认值 + 可覆盖」而非一刀切——保留团队调整空间；3) **信任不足**：用数据说话——先在小团队试点，展示提效/降本数据（AIC-394 ROI 复盘），让结果自己说话。
- 推广策略：**小步灰度而非一刀切**（AIC-122）——先找「愿意尝鲜的团队」做种子，形成成功案例和内部布道者，再逐步扩展；避免「强制全员切换」引发反弹。
- 高层支持与节奏：需要管理层明确方向与资源投入，但落地节奏要给团队适应期——「方向坚定、节奏柔性」。
- 追问钩子：为什么「强制一刀切」在平台化推行中常常适得其反？——因为强制会激发逆反，团队表面服从实际绕过平台（shadow IT），反而造成「平台是一套、实际用另一套」的分裂——治理失效比不治理更糟；渐进推广让平台在竞争中胜出， adopters 是真心认同而非被迫，体系才稳固。

```typescript
type Resistance = { type: 'habit'|'autonomy'|'trust'; severity: number };

function addressResistance(r: Resistance): string {
  const playbook = {
    habit: '提供更低接入成本的门户，用体验吸引而非禁止',
    autonomy: '默认值+可覆盖，邀请一线参与规则共建',
    trust: '小团队试点+数据说话，让成功案例成为布道者',
  };
  return playbook[r.type];
}

const resistances: Resistance[] = [
  { type: 'habit', severity: 3 },
  { type: 'autonomy', severity: 5 },
  { type: 'trust', severity: 4 },
];
resistances.sort((a, b) => b.severity - a.severity);
console.log(addressResistance(resistances[0]).includes('共建')); // 最严重的自主权问题优先处理
```
