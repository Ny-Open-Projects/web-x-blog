## AIC-828：AI 质量门禁里，「阻断」和「告警」如何分级才不阻塞交付？
**答**：
- 全量阻断会让开发绕过门禁（「AI review 太烦，加个 skip」），全量告警等于没有门禁。分级依据是**风险 × 确定性**：确定性高且风险高的规则才阻断。
- 三级模型：**Block**（硬红线，如密钥泄露、许可证违规、已知安全漏洞）——必须修；**Warn**（质量建议，如风格不一致、可优化）——展示但不阻断；**Inform**（统计信息，如 AI 代码占比）——只记录。
- 分级要**可演进**：新规则先 Inform 收集数据，误报率降到阈值以下再升 Warn，稳定后再升 Block；任何 Block 规则都要有豁免流程（owner 审批 + 有效期 + 事后补债）。
- 区分改动范围：全量仓库扫描结果只告警，只对**增量 diff**做阻断，避免历史遗留问题让新代码无法上线。
- 追问钩子：能说出「Block 规则必须有豁免与到期机制，否则团队会集体绕过门禁」的候选人，理解门禁是工程与社会系统的结合。

```typescript
type Level = 'block' | 'warn' | 'inform';
type Finding = { rule: string; level: Level; message: string; confidence: number };

function gateDecide(findings: Finding[], opts: { incrementalOnly: boolean }) {
  const actionable = opts.incrementalOnly
    ? findings.filter(f => f.inFileDiff)          // 只看增量
    : findings;
  const blockers = actionable.filter(f => f.level === 'block' && f.confidence >= 0.9);
  const warnings = actionable.filter(f => f.level === 'warn');
  // 有豁免且在有效期内则不阻断
  const effective = blockers.filter(f => !isWaived(f.rule));
  return {
    pass: effective.length === 0,
    blockers: effective,
    warnings,
    waived: blockers.filter(f => isWaived(f.rule)),
  };
}
function isWaived(rule: string) {
  const w = waivers[rule];
  return !!w && w.expiresAt > Date.now();
}
const waivers: Record<string, { expiresAt: number }> = {
  'no-hardcoded-key': { expiresAt: Date.now() + 7 * 864e5 }, // 7 天有效
};
```
