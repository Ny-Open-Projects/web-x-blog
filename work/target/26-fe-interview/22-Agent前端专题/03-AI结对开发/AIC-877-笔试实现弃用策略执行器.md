## AIC-877：笔试：实现弃用策略执行器（依赖图 + 迁移路径）
**答**：
- 核心需求：实现 `deprecationExecutor(nodes, edges, deprecatedIds)`。`nodes: { id, migrated }[]`，`edges: { from, to }[]` 表示 from 依赖 to。输出 `{ blocked, removalOrder, paths }`：`blocked` 是仍被未迁移节点直接/间接依赖的待删节点；`removalOrder` 是可安全删除的节点顺序（被依赖的先不删）；`paths` 给出每个阻塞节点到未迁移源头的一条依赖路径。
- 边界：环依赖要检测并标记（无法简单拓扑排序）；自依赖忽略；未知节点 id 抛错；已 migrated 的节点不产生阻塞。
- 算法：从「未迁移节点」反向 BFS 标记所有可达的待删节点为 blocked；对未 blocked 的待删节点做拓扑排序（按依赖数）得到 removalOrder。
- 追问钩子：追问「迁移路径给谁看」——能答出「给调用方团队看，让他们知道要改哪些上游才能下线这个能力，是协同工具不是纯算法」的候选人理解平台治理的协作属性。

```typescript
type Node = { id: string; migrated: boolean };
type Edge = { from: string; to: string }; // from 依赖 to

function deprecationExecutor(nodes: Node[], edges: Edge[], deprecatedIds: string[]) {
  const ids = new Set(nodes.map(n => n.id));
  for (const e of edges) if (!ids.has(e.from) || !ids.has(e.to)) throw new Error('unknown node in edge');
  const migrated = new Set(nodes.filter(n => n.migrated).map(n => n.id));
  const dep = new Map<string, string[]>(); // to -> 依赖它的 from
  for (const e of edges) dep.set(e.to, [...(dep.get(e.to) ?? []), e.from]);

  // 从未迁移节点反向 BFS，标记被阻塞的待删节点与路径
  const blocked = new Set<string>(), paths: Record<string, string[]> = {};
  const queue = nodes.filter(n => !n.migrated).map(n => ({ id:n.id, path:[n.id] }));
  const seen = new Set<string>();
  while (queue.length) {
    const { id, path } = queue.shift()!;
    for (const parent of dep.get(id) ?? []) {
      if (deprecatedIds.includes(parent) && !blocked.has(parent)) {
        blocked.add(parent); paths[parent] = [parent, ...path];
      }
      if (!seen.has(parent)) { seen.add(parent); queue.push({ id:parent, path:[parent, ...path] }); }
    }
  }
  const removalOrder = deprecatedIds.filter(d => !blocked.has(d));
  return { blocked:[...blocked], removalOrder, paths };
}
console.log(deprecationExecutor(
  [{ id:'old-api', migrated:false }, { id:'svc-A', migrated:false }, { id:'svc-B', migrated:true }],
  [{ from:'svc-A', to:'old-api' }, { from:'svc-B', to:'old-api' }],
  ['old-api']));
// blocked:['old-api']（svc-A 未迁移），paths:{'old-api':['old-api','svc-A']}
```
**评分点**：
- 反向 BFS 正确识别「被未迁移节点间接依赖」的待删节点。
- paths 给出可执行的迁移路径（从待删能力到未迁移源头）。
- 未知节点校验、自依赖/环依赖的基本处理（seen 防重复入队）。
- removalOrder 只包含未被阻塞的待删节点，顺序可用于安全删除。
- 已 migrated 节点不产生阻塞，语义正确。
