## TST-608：什么是测试的「可测试性设计」？架构层面有哪些规范？

**答**：
- 结论：可测试性是架构属性而非测试技巧——代码天生好测，测试才稳定便宜。
- 六条规范：依赖可注入、副作用可隔离、时间与随机可替换、状态可观测、错误可枚举、外部接口可 mock。
- 落地手段：构造函数注入 clock/random、纯函数抽离业务逻辑、事件溯源记录状态变更。
- 追问钩子：遗留代码全不满足这些规范，先重构还是先补测试？

```javascript
// 差：直接依赖全局时间，测试只能 sleep
// const now = Date.now();

// 好：时间作为依赖注入，测试可精确控制
class CouponService {
  constructor(clock, random) {
    this.clock = clock; this.random = random;
  }
  isValid(coupon) {
    const now = this.clock.now();
    return coupon.expireAt > now && this.random() > 0.01;
  }
}
const fakeClock = { now: () => new Date('2026-11-23T00:00:00Z') };
console.log(new CouponService(fakeClock, () => 0.5)
  .isValid({ expireAt: Date.parse('2026-12-01') }));
```
