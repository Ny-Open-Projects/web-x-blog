## TST-155：笔试：手写响应序列注入器（按次序返回不同响应，测重试与降级）
**答**：
- 需求：实现 `useResponses(seq)`——mock 接口按**调用次序**依次返回预设响应（失败→失败→成功），用完序列后停留在最后一个或走 fallback。用于测「重试逻辑」「缓存降级」「断线重连后恢复」这类多阶段场景。
- 与固定 mock 的区别：状态机式 mock——第一次 500、第二次 200，测试能精确驱动「第一次失败重试第二次成功」的完整路径，而不是只测单次成功。
- 设计：支持 `{ status, body, delay }` 三元组；`seq: [500, 500, 'ok']` 简写；`calls` 记录每次请求的入参供断言；`reset()` 复位序列。

```javascript
function useResponses(urlPattern, seq, { fallback = 'last' } = {}) {
  const calls = [];
  let idx = 0;
  const normalize = (s) =>
    typeof s === 'number' ? { status: s, body: {} } :
    s === 'ok' ? { status: 200, body: { ok: true } } : s;

  const handler = async (req) => {
    calls.push({ url: req.url, body: await req.clone().json().catch(() => null) });
    const item = normalize(seq[Math.min(idx, seq.length - (fallback === 'last' ? 1 : 0))] ?? { status: 200, body: {} });
    idx++;
    if (item.delay) await new Promise((r) => setTimeout(r, item.delay));
    return new Response(JSON.stringify(item.body), { status: item.status });
  };
  return {
    calls,
    get index() { return idx; },
    reset() { idx = 0; calls.length = 0; },
    route: () => [urlPattern, handler],   // 适配 MSW: server.use(http.get(...))
  };
}

// ---- 测试：重试两次后成功 ----
test('接口前两次 500，第三次成功 → 重试机制生效', async () => {
  const mock = useResponses('/api/submit', [
    { status: 500, body: { msg: 'db error' } },
    { status: 502, body: { msg: 'gateway' } },
    { status: 200, body: { orderId: 'ORD-1' } },
  ]);
  server.use(http.post('/api/submit', mock.route()[1]));

  render(<SubmitOrder />);
  const user = userEvent.setup();
  await user.click(screen.getByRole('button', { name: '提交' }));
  await screen.findByText('提交失败，重试中…');      // 第 1 次失败
  await user.click(screen.getByRole('button', { name: '重试' }));
  await screen.findByText('提交失败，重试中…');      // 第 2 次失败
  await user.click(screen.getByRole('button', { name: '重试' }));
  await screen.findByText('订单 ORD-1');             // 第 3 次成功

  expect(mock.calls).toHaveLength(3);
  expect(mock.calls.every((c) => c.body.skuId === 'SKU-001')).toBe(true); // 每次请求参数一致
});
```

**评分点**：
1. 按调用次序消费响应序列（状态机 mock 的核心）。
2. 序列耗尽后的语义明确（停留/循环）。
3. 每次调用的入参记录，可断言「重试参数一致」。
4. reset 支持用例复用与隔离。
