## TST-605：多业务线共用测试基建，如何设计「平台 + 插件」架构避免互相绑架？

**答**：
- 结论：平台只做稳定内核（调度/报告/权限/资源），业务差异以插件声明式接入。
- 插件通过 capability 声明依赖与扩展点，平台按能力路由，禁止插件直接写内核状态。
- 版本用语义化，平台维护插件兼容矩阵；不兼容插件走沙箱或隔离进程。
- 追问钩子：一个插件把平台 CPU 打满了，你怎么做到不影响其他业务线？

```javascript
class Platform {
  constructor() { this.plugins = new Map(); }
  register(p) {
    if (!p.capabilities || !Array.isArray(p.capabilities))
      throw new Error('插件必须声明 capabilities');
    for (const c of p.capabilities) {
      const bucket = this.plugins.get(c) || [];
      bucket.push({ name: p.name, version: p.version, run: p.run });
      this.plugins.set(c, bucket);
    }
  }
  async dispatch(cap, payload, { timeout = 3000 } = {}) {
    const list = this.plugins.get(cap) || [];
    return Promise.race([
      Promise.all(list.map(p => p.run(payload))),
      new Promise((_, rej) => setTimeout(() => rej(new Error(cap + ' timeout')), timeout)),
    ]);
  }
}
```
