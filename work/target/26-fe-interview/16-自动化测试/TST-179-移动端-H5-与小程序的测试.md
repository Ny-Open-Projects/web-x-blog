## TST-179：移动端 H5 与小程序的自动化测试怎么做？
**答**：
- H5：逻辑层与普通 Web 一致（Vitest + RTL）；真机特性层用 Playwright 的设备模拟（viewport/touch/UA）覆盖主流分辨率，再用云真机（BrowserStack / 自建 ADB 设备池）跑核心链路冒烟——模拟器测交互、真机测性能与兼容。
- 移动特有断言：触摸事件（tap vs click 300ms 延迟历史坑）、软键盘弹起遮挡输入框、安全区（notch）适配、横竖屏、弱网降级（Playwright 网络节流模拟 3G）。
- 小程序（微信）：工具链与 Web 完全不同——官方 miniprogram-simulate（组件级，JSDOM 类环境）做单测；自动化用 automator SDK（`mini-program-automator`）连微信开发者工具，API 类似 Playwright（page.element/scroll/调用 wx API mock）。云真机走 WeTest / 小程序自动化平台。
- 小程序测试要点：wx API 的 mock（wx.request/getStorageSync/setNavigationBarTitle）注入到测试环境；分包/ tabBar 导航链路 E2E；代码保护/压缩后的回归（真机包 vs 开发版行为差异）。
- 追问钩子：跨端框架（Taro/uni-app）怎么测？——业务逻辑抽到与端无关的纯 TS 层单测（一次写多端跑），端侧只测适配层（薄）。

```javascript
// 小程序自动化：mini-program-automator
import automator from 'miniprogram-automator';

test('下单链路', async () => {
  const mini = await automator.launch({ projectPath: './dist' });
  const page = await mini.reLaunch('/pages/goods/index');
  await page.waitFor(500);
  await page.$('.buy-btn').then((el) => el.tap());
  const toast = await page.waitFor('.order-toast');
  expect(await toast.text()).toContain('下单成功');
  // wx API 已在测试入口被 mock：wx.request → 固定响应
  await mini.close();
});
```
