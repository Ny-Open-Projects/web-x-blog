## TST-323：发现测试金字塔失衡（E2E 堆积、单测稀薄），治理路径？
**答**：
- 测量先行：分层用例数/耗时/缺陷发现率统计，找出「性价比最差层」。
- E2E 减量：每条 E2E 评估下沉可行性（可单测/组件测覆盖的下沉）。
- 冻结新增：失衡层暂停新增用例，新需求强制先写低层测试。
- 迁移专项：把 E2E 中「数据构造 + 断言」逻辑抽成接口测试，UI 只留交互验证。

```javascript
const audit = {
  unit: { count: 300, defectRate: 0.9 },      // 缺陷发现率高性价比好
  e2e: { count: 500, defectRate: 0.2, time: '90min' },  // 失衡点
  plan: 'E2E 冻结新增 + 每迭代下沉 10 条',
};
```
