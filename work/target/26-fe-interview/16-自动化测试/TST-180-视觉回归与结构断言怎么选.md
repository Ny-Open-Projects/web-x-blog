## TST-180：视觉回归和结构断言怎么选？什么页面值得做截图对比？
**答**：
- 本质区别：结构断言验证「DOM 上有什么、行为对不对」（role/文本/交互）；视觉回归验证「看起来对不对」（布局溢出、颜色、间距、字体渲染）。两者覆盖的正交——DOM 正确但样式炸了，结构断言全绿。
- 值得做视觉回归的：设计系统组件库（每个 story 一个基线）、营销/品牌页（视觉即业务）、强排版页面（报表、卡片流）、跨端一致性（暗色模式/RTL/i18n 长文案）。
- 不值得的：高频改版的活动页（基线天天变）、后台 CRUD 表单（结构断言性价比高 10 倍）、依赖后端数据的动态页面（要么 mock 数据要么 mask 掉）。
- 组合策略：组件级视觉回归（Storybook + Playwright，小而稳定）+ 页面级关键区域截图（局部 selector 而非整页）+ 结构断言打底。整页截图只留给核心交易链路的每夜回归。
- 工程化红线：视觉回归必须有 review 流程（diff 图进 PR）、mask 动态区域、固定环境（Docker）跑，否则误报会让团队把它静音。

```javascript
// 选型速查
const strategy = {
  '组件库/设计系统': 'Storybook story 每个状态截图 + review',
  '营销页': '页面级整页截图，mask 轮播/计数器',
  '后台表单': '结构断言为主，提交后跳转 waitForURL',
  '报表页': '关键卡片局部截图 + 数据格式正则断言',
  '活动页（周更）': '不做视觉回归，人工验收',
};
// 基线 review 流程：diff 图作为 PR artifact，reviewer 看图放行
```
