## TST-512：如何推动研发自测而不是把锅甩给测试

**答**：
- 结论：靠机制而非口号——把自测证据作为提测/合入的硬性输入（单测通过率、增量覆盖率、本地 E2E 截图），测试从「兜底」转为「验收与赋能」。
- 抓手：① 提供一键本地测试脚本与模板，降低自测成本；② CI 卡点只认证据不认口头承诺；③ 把线上逃逸缺陷按「本可自测拦截」归因，反馈到团队度量。
- 追问钩子：研发抵触说「没时间写单测」怎么破？——用数据：展示一个逃逸缺陷的修复成本 vs 写单测成本，并把自测纳入研发 Definition of Done。

```javascript
// 提测门禁：必须携带自测证据，否则拒绝
function acceptForQA(submission) {
  const required = ['unitPass', 'incCoverage', 'localE2eSnapshot'];
  const missing = required.filter(k => !submission.evidence?.[k]);
  const coverageOk = (submission.evidence?.incCoverage ?? 0) >= 0.7;
  if (missing.length || !coverageOk) {
    return { accepted: false, missing, advice: '补齐自测证据后再提测' };
  }
  return { accepted: true };
}
console.log(acceptForQA({ evidence: { unitPass: 1, incCoverage: 0.5 } }));
```
