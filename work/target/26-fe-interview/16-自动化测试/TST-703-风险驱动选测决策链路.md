## TST-703：风险驱动选测的决策链路怎么从信号走到用例集

**答**：
- 结论：链路是「风险信号 → 风险打分 → 用例打标 → 集合求解 → 门禁决策」五段，每段都可解释、可回溯。
- 信号来源：改动文件热度、历史缺陷密度、业务等级、依赖变更；用加权模型打分而非拍脑袋。
- 用例预打标（模块/业务/风险等级）是前提，选测本质是标签匹配 + 依赖闭包。
- 追问钩子：选出来的集合为空（风险高但无用例）时，平台应该怎么处理？

```javascript
// 风险打分 → 选测集合
function selectTests(change, caseTags, threshold) {
  const score = 0.4 * change.hotspot + 0.3 * change.bugDensity +
                0.2 * change.bizLevel + 0.1 * change.depImpact;
  if (score < threshold) return { score, cases: [] };
  const hit = caseTags.filter(c =>
    c.risk >= Math.ceil(score * 5) || c.modules.some(m => change.files.includes(m))
  ).map(c => c.id);
  return { score: +score.toFixed(2), cases: [...new Set(hit)] };
}
console.log(selectTests(
  { hotspot: 0.9, bugDensity: 0.8, bizLevel: 1, depImpact: 0.5, files: ['cart'] },
  [{ id: 'c1', risk: 4, modules: ['cart'] }, { id: 'c2', risk: 1, modules: ['ui'] }],
  0.5
));
```
