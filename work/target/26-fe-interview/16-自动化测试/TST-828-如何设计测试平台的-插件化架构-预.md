## TST-828：如何设计测试平台的「插件化架构」（预置/自定义 executor）？
**答**：
- 结论：平台只定义「执行协议」（输入用例+配置，输出统一结果），具体 runner 以插件形式接入，让单元/E2E/性能/安全测试都能被统一编排。
- 协议层：统一 Executor 接口（name、capabilities、execute(context)→Result），平台不关心插件内部用什么工具。
- 扩展点：生命周期钩子（beforeAll/afterAll）、报告适配器、环境提供者都做成可插拔。
- 隔离：插件沙箱运行，限制权限与资源，防止一个插件崩溃拖垮平台。
- 追问钩子：插件版本升级导致结果格式不兼容，平台如何做到平滑过渡？

```javascript
// 插件化 Executor：平台只认协议
class ExecutorRegistry {
  constructor() { this.map = new Map(); }
  register(plugin) {
    if (!plugin.execute || !plugin.name) throw new Error('非法插件');
    this.map.set(plugin.name, plugin);
  }
  async run(name, context) {
    const p = this.map.get(name);
    if (!p) throw new Error(`未注册: ${name}`);
    return p.execute(context); // 统一返回 { passed, details }
  }
}
const registry = new ExecutorRegistry();
registry.register({ name: 'vitest', execute: async () => ({ passed: true }) });
registry.register({ name: 'lighthouse', execute: async () => ({ passed: true, score: 92 }) });
registry.run('lighthouse', {}).then(console.log);
```
