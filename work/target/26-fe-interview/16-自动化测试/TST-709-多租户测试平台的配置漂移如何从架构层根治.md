## TST-709：多租户测试平台的「配置漂移」如何从架构层根治

**答**：
- 结论：漂移根因是「配置散落在代码、环境变量、数据库、控制台多处」，根治手段是单一事实源 + 版本化 + 声明式下发。
- 用中心化配置中心统一托管，所有环境从同一版本拉取，禁止运行时手改。
- 配置变更走 GitOps：变更即提交、可 diff、可回滚，平台定期巡检实际态与期望态差异并自愈。
- 追问钩子：租户 A 需要临时特殊配置做灰度，如何不破坏「单一事实源」原则？

```javascript
// 期望态 vs 实际态漂移检测
function detectDrift(desired, actual) {
  const diffs = [];
  for (const [k, v] of Object.entries(desired)) {
    if (actual[k] !== v) diffs.push({ key: k, desired: v, actual: actual[k] });
  }
  for (const k of Object.keys(actual)) if (!(k in desired)) {
    diffs.push({ key: k, desired: undefined, actual: actual[k] });
  }
  return diffs;
}
console.log(detectDrift(
  { timeout: 5000, retries: 2 },
  { timeout: 5000, retries: 3, debug: true }
));
```
