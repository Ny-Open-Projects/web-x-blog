## TST-166：可访问性（a11y）自动化测试怎么做？哪些能自动、哪些不能？
**答**：
- 能自动化的：规则可判定的部分——axe-core 覆盖 WCAG 大约 30~50% 的规则：图片缺 alt、label 缺失、对比度不足（真实浏览器）、ARIA 属性非法、颜色仅靠传达信息、tab 顺序。工具：jest-axe（单测）、@axe-core/playwright（E2E 每页扫）、eslint-plugin-jsx-a11y（编码期，最早）。
- 三个时机左移：写代码时（lint 插件实时提示）→ 组件测试（jest-axe 常驻）→ E2E 页面级扫描（每夜，critical/serious 阻断）。
- 不能自动化的（要人测/用例测）：键盘操作流是否顺畅（自动化只能查 tabindex，测不了「焦点逻辑是否合理」）、屏幕阅读器朗读顺序与语感、认知层面（文案是否易懂）、复杂交互（拖拽/画布）的替代操作。
- 键盘测试自动化补充：对核心组件（Tab、Dialog、Menu）写显式键盘用例（箭头/Escape/Enter 行为，见 TST-138），把「不能自动」里最机械的部分自动化掉。
- 落地建议：a11y 门禁只卡新增代码（豁免清单 + 期限），不要一上来全站阻断——存量 a11y 债通常很大，一刀切会让团队放弃。

```javascript
// E2E：每页 axe 扫描（Playwright + axe-core）
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

for (const path of ['/', '/goods', '/cart', '/checkout']) {
  test(`a11y: ${path}`, async ({ page }) => {
    await page.goto(path);
    const results = await new AxeBuilder({ page })
      .withTags(['wcag2a', 'wcag2aa'])          // 按 WCAG 级别过滤
      .analyze();
    const blocking = results.violations.filter((v) =>
      ['critical', 'serious'].includes(v.impact));
    expect(blocking).toEqual([]);               // 失败输出含节点与修复链接
  });
}
```
