## TST-181：录制回放（codegen / rrweb）类测试工具怎么用？价值与局限？
**答**：
- 两类工具两种用途：① Playwright codegen——录制用户操作生成测试代码骨架，价值是「零基础起步」和「复杂操作的参数参考」（拖拽坐标、键盘序列），生成的是可维护的 locator 代码；② rrweb（DOM 快照录制）——录线上真实用户会话，用于「问题复现」（用户操作序列在测试环境回放）和「从真实行为挖掘 E2E 场景」。
- 局限（必须会讲）：录制回放本质是「录下的实现轨迹」，脆且不含断言——录的 class/坐标一改就断，没人维护录制产物会变成死资产。所以 codegen 产物只当草稿，必须人工改造成 role/testid + 行为断言的正式用例。
- 正确工作流：codegen 起步 → 人工重构定位器与断言 → 进套件维护；rrweb 线上会话 → 筛选错误会话 → 转成 E2E 复现场景（用户点了什么、什么环境），闭环进缺陷用例。
- 平台化方向：录制产物结构化（步骤 + 语义操作）后可存测试平台做「低代码用例」，配合 AI 把操作轨迹翻译成断言——但断言正确性仍需人审。
- 追问钩子：为什么「纯录制回放」平台常被弃用？——维护成本转移而不是消失，缺乏断言的回放只能验证「不崩」，验证不了「正确」。

```bash
# Playwright codegen：录制生成草稿
npx playwright codegen --load-storage=auth.json https://shop.example.com
# 生成代码示例（草稿）→ 人工改造后入库：
test('下单', async ({ page }) => {
  await page.goto('https://shop.example.com/goods/1');
  await page.getByRole('button', { name: '加入购物车' }).click();  // 录制的是 testid，人工换成 role
  await expect(page.getByText('已加入')).toBeVisible();            // 断言是人工补的
});
```
