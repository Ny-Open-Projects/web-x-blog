## TST-532：测试用例的生命周期如何管理（新增/老化/淘汰）

**答**：
- 结论：用例是资产，需全生命周期治理——新增有评审、存活看价值（命中缺陷/覆盖关键路径）、老化降级、无效淘汰，避免套件无节制膨胀。
- 做法：给每个用例打「最近发现缺陷时间/执行频率/覆盖模块」标签；长期从不失败且覆盖低价值的标记待审；淘汰需 owner 确认，删除留痕。
- 追问钩子：怎么判断一个用例「没价值」？——从不失败 ≠ 没价值（可能是守护者），要结合「覆盖的代码是否仍变更」与「变异测试中是否捕获突变」综合判断。

```javascript
// 用例健康度评分：决定保留/降级/淘汰
function caseHealth(t) {
  let score = 0;
  if (t.lastCaughtDays <= 90) score += 3;        // 近期抓到过缺陷
  if (t.coversChangedModule) score += 2;          // 覆盖仍在变更的模块
  if (t.killedMutant) score += 2;                 // 变异测试中杀死突变
  if (t.execCount > 100 && !t.lastCaughtDays) score -= 2; // 长期空跑
  return { name: t.name, score,
    action: score >= 4 ? 'keep' : score >= 2 ? 'review' : 'retire' };
}
```
