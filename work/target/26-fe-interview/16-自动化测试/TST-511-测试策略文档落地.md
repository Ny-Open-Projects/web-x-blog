## TST-511：测试策略文档应该怎么写才不沦为摆设

**答**：
- 结论：策略文档要「短、可执行、可验证」——一页纸说明测什么、不测什么、各层责任、门槛阈值，并与 CI 配置直接关联。
- 做法：用「测试策略金字塔图 + 分层职责表 + 风险清单 + 退出标准」四块组成；每条策略都能映射到一条 CI 规则，文档更新触发配置审查。
- 追问钩子：文档与代码脱节怎么办？——把策略中的阈值写成配置文件（gate.config），文档由配置生成，保证「文档即配置」。

```javascript
// 策略文档中的「退出标准」直接落地为可执行配置
const testStrategy = {
  layers: [
    { name: 'unit',   scope: '纯函数/reducer/tool', must: true,  gate: { coverage: 0.8 } },
    { name: 'contract',scope: '跨服务接口',        must: true,  gate: { contractPass: 1 } },
    { name: 'e2e',    scope: '核心用户旅程',      must: true,  gate: { criticalPass: 1 } },
    { name: 'visual', scope: 'UI 组件库',         must: false, gate: { diffRatio: 0.01 } },
  ],
  outOfScope: ['一次性运营页', '第三方 SDK 内部'],
};
function exitCriteria(strategy) {
  return strategy.layers.filter(l => l.must).map(l => l.gate);
}
```
