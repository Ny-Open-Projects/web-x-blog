## TST-717：如何评估测试平台的「可迁移性」，避免供应商锁定

**答**：
- 结论：可迁移性 = 数据与用例能否用开放格式完整导出 + 核心能力是否依赖专有 runtime；评估要看「退出成本」而非「进入便利」。
- 三问：用例能否导出为标准格式（如 Markdown/YAML）？结果模型是否可移植？触发器是否绑定私有 SDK？
- 架构上把「平台特有能力」隔离在适配层，核心逻辑用开放协议，定期做迁移演练验证。
- 追问钩子：平台用了专有断言库，如何降低迁移成本？

```javascript
// 可迁移性评分：开放格式占比 + 适配层隔离度
function portability(cases, adapters) {
  const open = cases.filter(c => ['yaml', 'md', 'json'].includes(c.format)).length;
  const ratio = cases.length ? open / cases.length : 1;
  const isolated = adapters.every(a => a.hasFallback);
  return {
    openRatio: +ratio.toFixed(2),
    isolated,
    score: +(ratio * 0.6 + (isolated ? 0.4 : 0)).toFixed(2),
  };
}
console.log(portability(
  [{ format: 'yaml' }, { format: 'proprietary' }],
  [{ hasFallback: true }]
));
```
