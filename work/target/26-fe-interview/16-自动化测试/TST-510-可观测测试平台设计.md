## TST-510：如何设计一个可观测的测试平台

**答**：
- 结论：可观测 = 指标(Metrics) + 日志(Logs) + 追踪(Traces) 三支柱在测试域的落地。核心是让「一次测试运行」像一次线上请求一样可被端到端追踪。
- 落地：给每次 run 打唯一 traceId，贯穿调度→执行→断言→报告；指标看 通过率/flaky率/时长P95/资源成本；日志结构化并关联 runId，失败自动聚合证据链。
- 追问钩子：海量测试日志怎么存不爆？——分级：通过用例只存摘要，失败用例存全量 trace/截图，配合 TTL 生命周期（见前面产物治理）冷热分层。

```javascript
// 测试运行的可观测上下文：一个 runId 贯穿全生命周期
function tracedRun(runId, steps, collector) {
  const span = (name, fn) => async (...args) => {
    const t0 = Date.now();
    collector.log({ runId, event: 'start', name });
    try {
      const res = await fn(...args);
      collector.metric('step.ms', Date.now() - t0, { runId, name });
      return res;
    } catch (e) {
      collector.log({ runId, event: 'error', name, err: String(e) });
      throw e;
    }
  };
  return async () => {
    for (const s of steps) await span(s.name, s.exec)();
    collector.metric('run.total', 1, { runId });
  };
}
```
