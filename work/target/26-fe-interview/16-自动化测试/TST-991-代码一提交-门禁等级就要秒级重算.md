## TST-991：代码一提交，门禁等级就要秒级重算——实时信号驱动的门禁架构怎么搭？
**答**：
- 结论：用「事件驱动 + 增量计算」——提交/合并事件触发门禁服务，拉取变更指纹与质量信号，增量重算等级并回写 PR 状态。
- 要点：信号采集要快（变更文件、覆盖率增量、历史缺陷密度本地缓存），慢信号（全量回归）异步回填并可升级等级。
- 幂等与可解释：同一 commit 重算结果一致，并在 PR 上展示「为什么是这个等级」的信号明细。
- 追问钩子：全量回归还没跑完，但 PR 已合入主干，你的实时门禁怎么避免「先放行后出问题」？

```javascript
async function onPush(event) {
  const signals = await Promise.all([
    getChangeScope(event.sha),          // 快信号
    getDiffCoverage(event.sha),         // 快信号
    getHistoricalDensity(event.files),  // 缓存信号
  ]);
  const level = grade(signals);
  await setCommitStatus(event.sha, level); // 秒级回写 PR
  // 慢信号异步回填：若升级则回滚合并
  runFullRegression(event.sha).then(result => {
    if (gradeUp(result) > level) rollbackMerge(event.sha, '慢信号升级门禁');
  });
}
function grade() { return 'medium'; }
function gradeUp() { return 'high'; }
function rollbackMerge() {}
```
