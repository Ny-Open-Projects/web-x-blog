## TST-857：性能压测：前端如何模拟「大量用户 + 弱网」的叠加场景？
**答**：
- 结论：前端压测分两层——用 k6/Playwright 模拟并发用户给后端施压，用 CDP/Network Throttling 给每个会话叠加弱网，观察前端在双重压力下的表现。
- 并发模拟：k6 脚本起 VU（虚拟用户）访问页面并触发关键交互，观察后端响应与前端渲染的叠加影响。
- 弱网叠加：Playwright 用 context.setOffline / CDP emulateNetworkConditions 注入延迟/丢包/低带宽。
- 关注指标：弱网下首屏时长、交互响应、错误率、后端 P95 延迟，找出「高并发+弱网」放大效应。
- 追问钩子：弱网 + 高并发下前端出现大量超时重试，形成「重试风暴」，你如何测试并缓解？

```javascript
// Playwright + CDP 叠加弱网
async function stressWithWeakNetwork(context, page) {
  const client = await context.newCDPSession(page);
  await client.send('Network.enable');
  await client.send('Network.emulateNetworkConditions', {
    offline: false,
    latency: 300,          // 300ms 延迟
    downloadThroughput: 50 * 1024, // 50KB/s
    uploadThroughput: 20 * 1024,
  });
  const start = Date.now();
  await page.goto('/checkout');
  await page.getByText('提交订单').click();
  return { elapsed: Date.now() - start }; // 弱网+高并发下的关键路径耗时
}
// 配合 k6 起多 VU 打后端，前端侧观察渲染/错误率
```
