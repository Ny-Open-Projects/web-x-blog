## TST-598：笔试：笔试：降级策略决策器

**题目**：实现 decideFallback(dep, health, config)。health={errorRate, latencyMs, available}；config={ deps:{ depName: { degradeOn:'errorRate'|'latency'|'unavailable', threshold:number, fallback:'cache'|'placeholder'|'disable' } } }。要求：① 根据 dep 的配置与实时 health 判断是否触发降级；② degradeOn='unavailable' 时 available=false 触发；'errorRate' 时 errorRate>threshold 触发；'latency' 时 latencyMs>threshold 触发；③ 触发返回 {degrade:true, action:fallback}，否则 {degrade:false, action:null}；④ 未配置的 dep 不降级；⑤ 边界：health 字段缺失按安全默认值（available=false 视为不可用）。

**答**：
- 结论：按依赖配置的触发条件匹配实时健康指标，命中则返回对应降级动作。
- 实现要点：取 config.deps[dep]，无则直接不降级；用 switch 按 degradeOn 判断；health 缺失给安全默认（available 缺失视为 false 会触发 unavailable 降级，符合保守原则）。
- 追问钩子：为什么缺失 health 默认视为不可用？——保守降级优于带病服务；宁可展示兜底也别在未知状态下给用户错误结果。

```javascript
function decideFallback(dep, health = {}, config = {}) {
  const rule = config.deps?.[dep];
  if (!rule) return { degrade: false, action: null };
  const { available = false, errorRate = 0, latencyMs = 0 } = health;
  let hit = false;
  if (rule.degradeOn === 'unavailable') hit = !available;
  if (rule.degradeOn === 'errorRate') hit = errorRate > rule.threshold;
  if (rule.degradeOn === 'latency') hit = latencyMs > rule.threshold;
  return hit ? { degrade: true, action: rule.fallback } : { degrade: false, action: null };
}
```

**评分点**：
- 按 degradeOn 三种条件正确匹配 health 指标。
- 未配置 dep 不降级，返回结构正确。
- health 缺失给安全默认值（available 缺失视为不可用）。
- 返回 {degrade, action} 清晰可断言。
