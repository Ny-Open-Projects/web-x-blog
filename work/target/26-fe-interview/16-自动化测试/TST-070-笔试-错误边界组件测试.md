## TST-070：笔试：为 ErrorBoundary 写测试（捕获渲染错误与降级 UI）
**答**：
- 需求：`<ErrorBoundary fallback>` 包裹抛错的子组件时应显示 fallback 而不是崩溃；恢复场景（子组件换回正常组件）应重新渲染 children；未抛错时正常渲染。
- 要点：子组件抛错会污染 console.error（React 必打日志），spyOn console.error 压噪；抛错组件内直接 throw；断言 fallback 文案与「重试」回调。
- 边界：React 19 下错误冒泡到 window.onerror 的行为变化要注意；catchError 回调（onError prop）应收到 Error 实例。

```jsx
import { render, screen } from '@testing-library/react';
import { describe, it, expect, vi, afterEach } from 'vitest';
import ErrorBoundary from './ErrorBoundary';

function Boom() { throw new Error('render boom'); }   // 渲染期抛错的子组件

afterEach(() => vi.restoreAllMocks());

describe('ErrorBoundary', () => {
  it('正常子组件直接渲染', () => {
    render(<ErrorBoundary fallback={<div>出错了</div>}><div>正常内容</div></ErrorBoundary>);
    expect(screen.getByText('正常内容')).toBeInTheDocument();
  });

  it('渲染错误时显示 fallback 并回调 onError', () => {
    const onError = vi.fn();
    vi.spyOn(console, 'error').mockImplementation(() => {});  // 压掉 React 报错日志
    render(
      <ErrorBoundary fallback={<div>商品信息加载失败</div>} onError={onError}>
        <Boom />
      </ErrorBoundary>
    );
    expect(screen.getByText('商品信息加载失败')).toBeInTheDocument();
    expect(onError).toHaveBeenCalledTimes(1);
    expect(onError.mock.calls[0][0]).toBeInstanceOf(Error);
    expect(onError.mock.calls[0][0].message).toBe('render boom');
  });

  it('捕获后替换子组件可恢复渲染', () => {
    vi.spyOn(console, 'error').mockImplementation(() => {});
    const { rerender } = render(
      <ErrorBoundary fallback={<div>出错了</div>}><Boom /></ErrorBoundary>
    );
    expect(screen.getByText('出错了')).toBeInTheDocument();
    rerender(<ErrorBoundary fallback={<div>出错了</div>}><div>恢复内容</div></ErrorBoundary>);
    expect(screen.getByText('恢复内容')).toBeInTheDocument();
  });
});
```
**评分点**：
- 压噪 spyOn console.error 且 afterEach restore。
- onError 回调收到 Error 实例并断言 message。
- 恢复场景 rerender 覆盖（boundary 有 key/重置语义时是常见 bug 源）。
- 知道渲染期 throw 与事件回调 throw 的区别（后者 ErrorBoundary 捕不到）。
