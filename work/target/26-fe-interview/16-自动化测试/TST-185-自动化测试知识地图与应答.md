## TST-185：自动化测试面试的知识地图：考点分布与应答优先级
**答**：
- 八大考点域：① Vitest/Jest 基础与原理（mock 提升、fake timers）② 单测设计方法论（测什么/不测什么/AAA）③ Testing Library 组件测试 ④ Playwright/E2E（自动等待、拦截、视觉回归）⑤ 测试策略与金字塔 ⑥ MSW/网络 mock ⑦ 覆盖率与门禁 ⑧ 工程化（CI 编排/flaky/反模式治理）。
- 高频优先级：初级到中级必问——mock 与 spyOn 区别、fake timers、getBy/findBy/queryBy 区别、测试金字塔；高级岗侧重——测试策略取舍、flaky 治理、覆盖率门禁设计、「从 0 到 1 体系建设」。
- 笔试高频题型：手写测试框架（describe/it/钩子）、手写断言库、mock 函数实现、防 flaky 重试器、fake timers 测防抖、为具体组件写测试（竞态/防抖/取消）、写覆盖率脚本。
- 应答原则：每题「结论先行 + 场景化举例 + 权衡（trade-off）」；测试题几乎没有唯一答案，面试官考察的是你的判断力——主动说出「什么时候不该这么做」是加分项。
- 反问环节加分：问团队「测试怎么分工、flaky 率多少、有没有测试基建」——显示你是体系化思考者。

## 追问（补充）

**追问**：

1. 被问到不熟的测试工具细节怎么答 → 先给结论与设计取舍，坦白具体 API 要查文档，再把话题拉回原理，例如 fake timers 与微任务的执行顺序。
2. 覆盖率很高但线上 bug 多，怎么向面试官解释 → 覆盖率衡量的是行被执行，不是行为被验证；缺的是断言质量与分支组合，补变异测试和变更覆盖率才有意义。
3. 团队没有测试基建，从 0 到 1 先做什么 → 先卡 CI 门禁与核心链路冒烟（投入产出最高），再补组件测试，最后才是全量 E2E。
