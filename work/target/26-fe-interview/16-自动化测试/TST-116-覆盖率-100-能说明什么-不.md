## TST-116：覆盖率 100% 能说明测试有效吗？什么是变异测试？
**答**：
- 不能。覆盖率只回答「代码被执行过」，不回答「行为被验证过」。经典反例：`expect(result).toBeDefined()` 走遍全代码拿满覆盖率，但任何回归错误都能通过。
- 变异测试（mutation testing）：自动往源码注入变异体（`>` 改 `>=`、`+` 改 `-`、删 await、翻转条件），每个变异体跑一遍测试——测试挂了 = 变异被「杀死」说明测试有效；测试仍绿 = 变异「存活」= 测试有洞。**mutation score（杀死率）比覆盖率真实得多**。
- 前端工具：StrykerJS（支持 Vitest/Jest/Mocha，plugin: @stryker-mutator/vitest-runner）；因为全量变异慢，通常只对核心逻辑模块（金额计算、状态机、diff 算法）抽样开启，不进主干门禁、进每日定时任务。
- 实战结论：覆盖率 70% + mutation score 60% 的项目，比覆盖率 100% + score 30% 的可信；两者结合用——覆盖率找盲区，变异找假测试。
- 追问钩子：等价变异（mutant 与原代码行为一致，永远杀不死）怎么处理？——忽略清单/人工标记，成本太高所以变异测试只对关键模块做。

```javascript
// 变异示例：测试有洞的样子
function discount(price, vip) {
  return vip ? price * 0.9 : price;   // 变异体: 0.9 → 0.1
}
test('低质量测试', () => {
  expect(discount(100, true)).toBeDefined(); // 没断言数值！变异存活
});

// Stryker 配置：只对核心模块做
// stryker.conf.json
{
  "testRunner": "vitest",
  "mutate": ["src/utils/pricing/**/*.ts"],   // 金额计算必须变异验证
  "thresholds": { "high": 80, "low": 60, "break": 50 }, // 低于 50 CI 失败
  "concurrency": 4,
  "timeoutMS": 5000
}
```
