## TST-502：测试左移在需求评审阶段怎么落地

**答**：
- 结论：左移不是「早点写用例」，而是把质量活动前置到需求可验证——评审时产出验收标准（AC）与可测性检查表，把歧义在编码前暴露。
- 三个抓手：① 用 Given/When/Then 把用户故事改写成可验收断言；② 检查可测性（是否有唯一 ID、时间是否可注入、状态是否可观）；③ 识别边界与异常分支，提前登记为测试点。
- 追问钩子：开发说「需求还没定没法测」怎么答？——先把已确定的部分写成「假设驱动」的探索清单，需求变更时同步更新，测试资产随需求演进而非等冻结。

```javascript
// 需求可测性检查器（评审阶段自动扫描 AC 文本）
const CHECKS = [
  { id: 'given-when-then', test: s => /given/i.test(s) && /when/i.test(s) && /then/i.test(s) },
  { id: 'has-metric',      test: s => /\d+\s*(ms|%|秒|条)/.test(s) },     // 是否有可量化指标
  { id: 'no-vague',        test: s => !/(较快|良好|友好|适当)/.test(s) },   // 杜绝模糊词
];
function reviewAcceptance(ac) {
  const gaps = CHECKS.filter(c => !c.test(ac)).map(c => c.id);
  return { pass: gaps.length === 0, gaps, advice: {
    'has-metric': '补充可量化的性能/数量指标',
    'no-vague': '把模糊形容词替换为可判定的阈值',
    'given-when-then': '用 Given/When/Then 重写为可验收断言',
  }};
}
console.log(reviewAcceptance('Given 登录 When 输错密码 Then 提示错误'));
```
