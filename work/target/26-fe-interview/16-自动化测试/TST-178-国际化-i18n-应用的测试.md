## TST-178：国际化（i18n）应用的测试策略？怎么防翻译回归？
**答**：
- 静态层（见 TST-154 的笔试实现）：key 完整性、占位符一致、t() 引用合法——CI 必跑，防「上线显示 raw key」「变量拼错」。
- 渲染层：组件测试里显式设置 locale 断言文案（`renderWithProviders(ui, { locale: 'ja' })`）；数字/日期格式断言用 `Intl`（价格千分位、日历顺序）——这些是 i18n 真正容易翻车的部分。
- 布局层（伪本地化）：用伪翻译文案（字符加长 40% + 重音符号 like ï18ñ、或德语这种长文案）跑视觉回归，防「英文正常、德语溢出」；RTL 语言（阿拉伯语）单独视觉基线 + `dir=rtl` 断言。
- E2E 层：核心链路用 2~3 个语言跑冒烟（en/ja），不全语言跑（成本）；关键断言用 `getByRole(name)` 时注意 name 也会变——断言用 data-testid 或 role 不带 name。
- 追问钩子：翻译文案经常改，测试怎么不天天挂？——测试断言「key 存在于渲染结果」或断言格式模式（正则），不断言具体译文；具体译文的正确性交给翻译平台 + 文案 review。

```javascript
// i18n 组件测试：格式化与切换
import { renderWithProviders } from '@/test-utils';

test('价格格式随 locale 变化', () => {
  const { getByText } = renderWithProviders(<Price value={1234567.89} />, { locale: 'en-US' });
  expect(getByText('$1,234,567.89')).toBeInTheDocument();

  const ja = renderWithProviders(<Price value={1234567.89} />, { locale: 'ja-JP' });
  expect(ja.getByText('¥1,234,568')).toBeInTheDocument();  // 无小数（JPY）
});

test('阿拉伯语 RTL 方向正确', () => {
  const ar = renderWithProviders(<GoodsList />, { locale: 'ar' });
  expect(ar.container.querySelector('[dir="rtl"]')).toBeInTheDocument();
});
```
