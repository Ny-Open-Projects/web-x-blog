## TST-653：性能回归失败后怎么快速归因到具体变更？

**答**：
- 结论：性能数字变差不等于定位完成——要做「变更 → 指标」的因果关联。
- 把每次提交的 bundle diff、依赖变化、资源请求数与性能采样绑定，按相关性排序嫌疑变更。
- 用二分回退（bisect）在受控环境验证真凶，避免凭直觉甩锅。
- 追问钩子：相关性最高的变更其实是无辜的，你怎么排除混杂因素？

```javascript
function suspectRank(changes, delta) {
  return changes.map(c => ({
    commit: c.id,
    score: Math.abs(c.bundleDelta) * 0.5
      + Math.abs(c.requestDelta) * 0.3
      + (c.touchCriticalPath ? 2 : 0),
  })).sort((a, b) => b.score - a.score).slice(0, 5);
}
// 再用 bisect 验证排名第一的 commit
function bisectVerify(commits, bad, run) {
  let lo = 0, hi = commits.length - 1;
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (run(commits[mid]) <= bad) lo = mid + 1; else hi = mid;
  }
  return commits[lo];
}
```
