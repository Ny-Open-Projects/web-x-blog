## TST-515：「测试即文档」在前端怎么实践

**答**：
- 结论：用可执行的规格（Given/When/Then 风格用例 + 组件测试的渲染快照）替代静态文档，让「文档」随代码运行而自动保鲜。
- 做法：组件测试描述交互契约（点击角标+1），API 测试描述契约（字段/状态），用 describe/it 的文案组织成可读规格；配合 Storybook 做可视化文档。
- 追问钩子：测试文案写成「test1/test2」怎么治理？——把用例命名纳入 CR 检查，要求「行为描述句式」，并对模糊命名给 lint 提示。

```javascript
// 用可执行的规格描述组件契约（测试即文档）
describe('购物车角标', () => {
  it('加入商品后角标数量 +1', () => {
    const cart = createCart();
    cart.add({ id: 'sku-1', qty: 1 });
    expect(cart.badge()).toBe(1);   // 这一行就是「文档」
  });
  it('同商品再次加入应累加数量而非新增条目', () => {
    const cart = createCart();
    cart.add({ id: 'sku-1', qty: 1 });
    cart.add({ id: 'sku-1', qty: 2 });
    expect(cart.items()).toHaveLength(1);
    expect(cart.badge()).toBe(3);
  });
});
```
