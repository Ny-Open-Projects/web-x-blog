## TST-523：分布式测试调度架构怎么设计

**答**：
- 结论：中心调度器 + 执行节点（worker）架构。调度器负责分片、分发、超时与重试；worker 无状态、可执行任意分片，结果回传聚合。
- 关键设计：任务队列（带优先级/幂等键）、worker 心跳与故障转移、结果幂等写入、分片粒度与负载均衡。调度器本身需高可用，状态外置（Redis/DB）。
- 追问钩子：worker 跑到一半挂了怎么办？——任务设 lease（租约），超时未续约则重新入队；分片需幂等（同 runId+shardId 结果覆盖写），避免重复计费。

```javascript
// 带租约的任务领取：防止 worker 挂掉导致任务永久卡住
function claimTask(queue, workerId, leaseMs = 60000) {
  const now = Date.now();
  const task = queue.find(t => t.status === 'pending' ||
    (t.status === 'running' && t.leaseUntil < now)); // 租约过期可抢占
  if (!task) return null;
  task.status = 'running'; task.worker = workerId;
  task.leaseUntil = now + leaseMs;
  return task;
}
const queue = [{ id: 1, status: 'running', leaseUntil: Date.now() - 1 }];
console.log(claimTask(queue, 'w-2')?.worker); // 'w-2' 抢占过期任务
```
