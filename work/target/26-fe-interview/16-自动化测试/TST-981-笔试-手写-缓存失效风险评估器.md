## TST-981：笔试：手写「缓存失效风险评估器」——判断本次构建能否安全复用上次缓存
**答**：
- 需求：实现 cacheRisk(current, cached)，两者均为 { gitSha, depsHash, envHash, dataHash, testHash }。
- 规则：逐项比对，差异项计入 riskFactors；gitSha/depsHash/testHash 任一变化判为高风险（必须重跑）；仅 envHash/dataHash 变化判为中风险（需冒烟）；全同低风险。
- 边界：缺失字段视为变化；返回 { level, riskFactors, action }。

```javascript
function cacheRisk(current, cached) {
  const keys = ['gitSha', 'depsHash', 'envHash', 'dataHash', 'testHash'];
  const riskFactors = keys.filter(k => current[k] !== cached[k]);
  const hard = ['gitSha', 'depsHash', 'testHash'];
  const level = riskFactors.some(k => hard.includes(k)) ? 'high'
    : riskFactors.length ? 'medium' : 'low';
  const action = { high: '必须全量重跑', medium: '命中缓存 + 冒烟验证', low: '安全复用缓存' }[level];
  return { level, riskFactors, action };
}
console.log(cacheRisk(
  { gitSha: 'a', depsHash: 'd', envHash: 'old', dataHash: 'x', testHash: 't' },
  { gitSha: 'a', depsHash: 'd', envHash: 'new', dataHash: 'x', testHash: 't' }
)); // { level:'medium', riskFactors:['envHash'], action:'命中缓存 + 冒烟验证' }
```
**评分点**：
- 逐项识别差异，gitSha/depsHash/testHash 变化判高风险。
- 仅 envHash/dataHash 变化判中风险，全同判低风险。
- 缺失字段按变化处理，边界完整。
- 输出 level/riskFactors/action，可直接指导缓存策略。
