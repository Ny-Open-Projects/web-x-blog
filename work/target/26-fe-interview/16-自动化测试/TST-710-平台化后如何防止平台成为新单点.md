## TST-710：平台化后如何防止「平台成为新的单点故障」

**答**：
- 结论：统一平台提升效率但引入集中风险，治理思路是「控制面集中、执行面分布式」，平台挂了执行节点仍能跑完已下发任务。
- 关键：任务下发与执行解耦，执行器本地缓存任务，断联时按最后指令继续；结果先本地落盘再异步上报。
- 平台自身做多活与降级：核心是「能降级为离线 CLI」，让业务在平台不可用时仍有兜底。
- 追问钩子：平台与执行器断联期间代码版本更新了，结果如何保证可信？

```javascript
// 执行器断联续跑：本地缓存 + 结果缓冲
class Runner {
  constructor(store) { this.store = store; this.buffer = []; }
  run(task) {
    this.store.save(task.id, task);      // 任务落本地
    const result = this.execute(task);
    this.buffer.push(result);            // 结果先本地缓冲
    return result;
  }
  flush(upload) {
    const pending = [...this.buffer];
    this.buffer = [];
    return upload(pending).then(() => this.store.clear(pending.map(r => r.id)));
  }
  execute(t) { return { id: t.id, ok: true }; }
}
const r = new Runner({ save() {}, clear() {} });
console.log(r.run({ id: 't1' })); // {id:'t1', ok:true}
```
