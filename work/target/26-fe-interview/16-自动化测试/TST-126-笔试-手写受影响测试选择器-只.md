## TST-126：笔试：手写受影响测试选择器（改动文件 → 只跑相关用例）
**答**：
- 需求：实现 `pickAffectedTests(changedFiles, testRoot)`——输入本次 PR 改动的源文件列表，输出应运行的测试文件列表。规则：① 改动测试文件自身 → 直接收录；② 改动源文件 → 收录「import 了它的测试」；③ 依赖闭包：A 被 B import、B 被测试 import，改 A 也要跑该测试（沿 import 图反向传播）。
- 核心：用 es-module-lexer/正则扫 import 建正向依赖图 `dep -> [importers]`，从改动文件出发 BFS 收集所有「可达测试文件」。
- 边界：循环依赖要标记 visited 防死循环；相对路径与 `@/` 别名都要归一化到绝对路径；找不到任何相关测试时可配置为「全跑」或「跳过」。

```javascript
import { readFileSync, readdirSync, statSync } from 'node:fs';
import { join, resolve, dirname } from 'node:path';

function walk(dir) {
  return readdirSync(dir).flatMap((n) => {
    const p = join(dir, n);
    return statSync(p).isDirectory() ? walk(p) : p;
  });
}
const IMPORT_RE = /(?:from|require\()\s*['"]([^'"]+)['"]/g;

function buildGraph(files, root) {
  const graph = new Map(); // file -> Set(importers)
  const norm = (spec, from) =>
    spec.startsWith('.') ? resolve(dirname(from), spec) : resolve(root, spec.replace(/^@\//, 'src/'));
  for (const f of files) {
    const src = readFileSync(f, 'utf8');
    for (const m of src.matchAll(IMPORT_RE)) {
      const dep = norm(m[1], f);
      if (!graph.has(dep)) graph.set(dep, new Set());
      graph.get(dep).add(f); // 正向：dep 的 importer
    }
  }
  return graph;
}

function pickAffectedTests(changedFiles, testRoot) {
  const allTests = walk(testRoot).filter((f) => /\.(test|spec)\.[jt]sx?$/.test(f));
  const graph = buildGraph([...allTests, ...walk('src')], process.cwd());
  const affected = new Set(), visited = new Set();
  const queue = [...changedFiles];
  while (queue.length) {
    const cur = queue.pop();
    if (visited.has(cur)) continue;              // 循环依赖防护
    visited.add(cur);
    if (allTests.includes(cur)) affected.add(cur);
    for (const importer of graph.get(cur) ?? []) queue.push(importer); // 反向传播
  }
  return [...affected];
}
// git diff --name-only origin/main...HEAD | xargs node pick.js
// 输出: ['src/utils/pricing.spec.ts'] → npx vitest run <files>
```

**评分点**：
1. import 图建模 + 反向 BFS 传播闭包是否正确。
2. visited 防循环依赖、路径别名归一化这两个工程细节。
3. 「改动测试文件自身」与「间接依赖」两类情况都覆盖。
4. 输出可直接拼进 vitest run 命令（工程落地意识）。
