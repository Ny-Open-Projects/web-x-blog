## TST-813：测试架构师评估「引入一个新测试工具」时，如何识别隐性成本？
**答**：
- 结论：工具的显性成本是 license/学习曲线，隐性成本才是杀手——迁移工期、插件缺口、与 CI 的耦合、社区维护风险。
- 评估清单：现有用例迁移成本、团队再培训成本、CI 集成改造、生态插件是否齐全、是否有厂商锁定。
- 用「试点 + 度量」：先在单个项目跑 2 周，量化反馈速度、flaky 率、维护工时，与现状对比再决定推广。
- 退出成本：提前想好「如果不好用怎么退回」，保留旧工具并行期，避免单边下注。
- 追问钩子：一个工具在试点项目效果很好，但推广到 20 条业务线就崩了，可能是什么原因？

```javascript
// 工具评估的隐性成本清单
function evaluateTool(tool) {
  const hidden = [];
  if (tool.migrationEffortWeeks > 4) hidden.push('迁移工期过长');
  if (!tool.pluginCoverage.includes('snapshot')) hidden.push('缺快照插件');
  if (tool.ciCoupling === 'tight') hidden.push('与 CI 强耦合，替换成本高');
  if (tool.maintainerActivity === 'low') hidden.push('社区维护风险');
  return {
    tool: tool.name,
    totalCostWeeks: tool.migrationEffortWeeks + tool.trainingWeeks,
    hidden,
    verdict: hidden.length >= 2 ? '谨慎引入，先试点' : '可试点',
  };
}
console.log(evaluateTool({ name: 'NewRunner', migrationEffortWeeks: 6,
  trainingWeeks: 1, pluginCoverage: ['unit'], ciCoupling: 'tight',
  maintainerActivity: 'low' }));
```
