## TST-140：笔试：测试请求竞态——过期响应到达时必须被丢弃
**答**：
- 场景：列表页关键词筛选——每次搜索条件变化发起新请求，网络慢时旧请求可能后返回，若不处理会把新结果覆盖回旧数据（线上经典 bug）。测试要验证组件「最后一次请求胜出」。
- 测试设计：让「请求 A 慢、请求 B 快」，断言 A 迟到后 UI 仍显示 B 的结果。用 MSW 的 delay 按参数差异化延迟；组件侧用 requestId/AbortController 丢弃过期响应。
- 验证层次：① 最终 UI 正确（用户视角）；② 若组件用 abort，还可断言 abort 被调用（实现细节，作为补充断言可选）；③ setState 在卸载后不触发（React 18 安全，但 abort 未做时 act 警告是线索）。

```jsx
// SearchResults.tsx 组件应实现 requestId 守卫：
// const idRef = useRef(0);
// async function load(q) { const id = ++idRef.current; const r = await api(q);
//   if (id !== idRef.current) return;  // 过期丢弃
//   setList(r); }

import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { http, HttpResponse, delay } from 'msw';
import { server } from '@/mocks/server';
import SearchResults from './SearchResults';

test('迟到的旧响应被丢弃，显示最后一次查询结果', async () => {
  server.use(
    http.get('/api/search', ({ request }) => {
      const q = new URL(request.url).searchParams.get('q');
      // 旧关键词 "a" 慢 800ms，新关键词 "ab" 快 50ms
      return delay(q === 'a' ? 800 : 50).then(() =>
        HttpResponse.json({ list: [{ id: 1, name: `结果-${q}` }] }));
    }),
  );

  render(<SearchResults />);
  const user = userEvent.setup();
  const input = screen.getByRole('searchbox');

  await user.type(input, 'a');           // 请求 A（慢）
  await user.type(input, 'ab');          // 请求 B（快）

  await screen.findByText('结果-ab');    // B 先返回并渲染
  // 等待 A 迟到返回（800ms 后）——注意要真实等过这个窗口
  await vi.waitFor(
    () => { /* A 已返回 */ },
    { timeout: 1000 },
  );
  expect(screen.queryByText('结果-a')).toBeNull();   // 过期结果没进来
  expect(screen.getByText('结果-ab')).toBeInTheDocument();
});
```

**评分点**：
1. 慢旧快新的延迟设计正确（A 必须比 B 晚返回）。
2. 等待迟到响应的窗口（waitFor timeout > 慢延迟）——没等就断言是假绿。
3. 断言用户视角最终态（queryByText 为 null）而非内部 state。
4. 能说出组件侧防御手段：requestId 计数、AbortController、防抖兜底。
