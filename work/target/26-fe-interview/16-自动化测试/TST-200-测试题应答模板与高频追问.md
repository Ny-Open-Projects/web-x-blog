## TST-200：收官：测试面试的应答模板与高频追问清单
**答**：
- 通用应答框架（任何测试题）：结论先行（1 句）→ 原理/方案展开（3 点）→ 示例代码或场景（1 段）→ 权衡与边界（1 句：「但要注意…」「如果反过来…」）。测试题的区分度在权衡，不在背诵。
- 高频追问清单（按追问概率排序）：① 覆盖率多少、怎么定门禁？（TST-114/115/117）② flaky 怎么治理？（TST-108）③ mock 什么不 mock 什么？（TST-055/120）④ E2E 该 mock 后端吗？（TST-107）⑤ 怎么测异步/竞态？（TST-140/141）⑥ 快照测试怎么看？（TST-011/191）⑦ 测试谁写怎么推？（TST-174/183）⑧ 单测设计怎么答？（TST-053~060）。
- 笔试题准备优先级：手写 describe/it 框架、手写 mock 函数与断言库、fake timers 测防抖、为真实组件（搜索框/购物车/上传）写测试、手写 waitFor——这五类覆盖 90% 的现场编码（TST-036~052/121~155）。
- 反问建议：团队的测试分工、flaky 率、测试基建成熟度——既是信息收集也是能力信号。
- 收官一句话：「测试的本质是用可执行的方式描述行为契约，工具只是手段；面试里展示你对行为、成本、权衡的判断力，比展示工具熟练度高一档。」

```javascript
// 30 秒应答模板（背结构不背稿）
function answer(question) {
  return [
    `结论：${question.oneLineAnswer}`,                    // 1 句定调
    `原理：${question.keyPoints.join('；')}`,             // 3 个要点
    `示例：${question.minimalCode}`,                      // 10 行内代码
    `权衡：${question.tradeOff}（何时该反着做）`,          // 加分句
    `实战：${question.realCase}`,                         // 1 个真实案例
  ];
}
// 例：mock 什么不 mock？
// 结论：只 mock 不可控边界（网络/时间/随机/三方），自己写的模块真跑。
// 权衡：能 MSW 就别 vi.mock 模块——网络层 mock 语义最真、漂移风险最小。
```
