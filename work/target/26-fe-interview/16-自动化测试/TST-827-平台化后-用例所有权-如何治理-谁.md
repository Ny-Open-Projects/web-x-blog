## TST-827：平台化后「用例所有权」如何治理？（谁建谁维护、腐化用例下线）
**答**：
- 结论：用例必须「有主」——每条用例绑定 owner 与业务线，无人维护的腐化用例要能自动识别并下线，避免平台变成用例垃圾场。
- 所有权：owner 随代码归属（CODEOWNERS），离职/转岗自动触发用例转派，避免孤儿用例。
- 腐化信号：长期 flaky、连续多次 skip、超过 N 天无有效失败（疑似恒真断言）、owner 已离职——进入「待下线」队列。
- 下线机制：先标记 deprecated 观察一个周期，无异议再删除；保留删除审计记录。
- 追问钩子：一条用例没人维护但从没报错（因为在测一个已下线功能），你如何识别这种「僵尸用例」？

```javascript
// 腐化用例识别：多信号加权
function detectZombie(meta) {
  const signals = [];
  if (meta.flakyRate > 0.1) signals.push('长期 flaky');
  if (meta.skipDays > 30) signals.push('长期 skip');
  if (meta.daysWithoutFailure > 180) signals.push('疑似恒真/功能已下线');
  if (!meta.ownerActive) signals.push('owner 离职/转岗');
  return {
    id: meta.id,
    zombie: signals.length >= 2,
    signals,
    action: signals.length >= 2 ? '进入待下线队列' : '保留',
  };
}
console.log(detectZombie({ id: 'E2E-OLD', flakyRate: 0.2,
  skipDays: 45, daysWithoutFailure: 300, ownerActive: false }));
```
