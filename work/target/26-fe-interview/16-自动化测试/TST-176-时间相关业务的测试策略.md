## TST-176：时间相关业务（日历/会员过期/活动截止）的测试策略？
**答**：
- 核心原则：业务代码不要直接 `new Date()`，注入时间源（clock/nowFn）——测试才有抓手。注入方式三种：参数传 now、DI 容器、测试时 fake timers + `setSystemTime`（见 TST-050 Stub Clock）。
- 三类典型场景：① 倒计时/截止判断——fake timers 推进到临界点验证状态翻转（含 0/负数边界）；② 日历跨月/闰年/月末——参数化传固定日期（2024-02-29、1月31日 +1 月、跨时区），别用「今天」；③ 会员过期——传相对时间（now + 3天）而非绝对时间戳，防止测试跑在过期之后。
- 时区陷阱：用 `Intl`/`Date` 序列化的场景，CI 机器时区可能和你不同——测试里显式固定时区（`TZ=UTC` 跑 CI 或 fake timers 带 timezone），日期字符串解析统一 ISO + 显式时区偏移，禁 `new Date('2026-1-1')` 这类区域格式。
- 真实时间 vs 快进：验证「实时刷新」（倒计时跳秒）用 fake timers 推进；验证「等待真实网络」的场景才允许真时间，且绝不 sleep 固定毫秒。
- 追问钩子：线上「凌晨 0 点活动提前结束」类 bug 怎么防？——把「跨日边界」显式列为测试用例（23:59:59.999 → 00:00:00），并把时区固定进 CI 环境。

```javascript
// 可注入时间源的业务代码（可测性设计）
export function createActivityGate({ now = Date.now, startAt, endAt }) {
  return {
    get status() {
      const t = now();
      if (t < startAt) return 'upcoming';
      if (t >= endAt) return 'ended';          // >= 防止边界闪断
      return 'active';
    },
  };
}

// 测试：fake timers 固定「现在」
vi.useFakeTimers();
vi.setSystemTime(new Date('2026-11-11T23:59:59'));
const gate = createActivityGate({
  startAt: Date.parse('2026-11-11T00:00:00'),
  endAt: Date.parse('2026-11-12T00:00:00'),
});
expect(gate.status).toBe('active');
vi.setSystemTime(new Date('2026-11-12T00:00:00'));   // 跨日边界
expect(gate.status).toBe('ended');
```
