## TST-508：跨端（Web/小程序/App）测试架构如何统一

**答**：
- 结论：统一的是「测试协议与资产」，不是「执行器」。用一层抽象描述用例（页面/操作/断言），各端用不同 adapter 落地执行。
- 做法：用例用平台无关 DSL 描述；断言抽象成语义级（可见/可点/文本），由 adapter 映射到 Playwright/小程序自动化/Appium；数据与契约层完全复用。
- 追问钩子：三端差异大，统一抽象会不会过度设计？——分层：底层能力（数据工厂、契约、断言语义）必须统一，交互细节允许 adapter 内分叉，用「契约测试」保证各端对同一接口理解一致。

```javascript
// 平台无关的用例描述 + 各端 adapter
const caseDef = {
  id: 'add-to-cart',
  steps: [
    { act: 'open', target: '商品详情' },
    { act: 'tap', target: '加入购物车' },
    { act: 'assert', kind: 'visible', target: '购物车角标' },
  ],
};
const adapters = {
  web: a => `page.locator('${a.target}').${a.act === 'tap' ? 'click' : 'waitFor'}()`,
  mini: a => `mini.${a.act}('${a.target}')`,
  app: a => `app.find('${a.target}').${a.act}()`,
};
function compile(caseDef, platform) {
  return caseDef.steps.map(s =>
    s.act === 'assert' ? `expect(${adapters[platform]({ act: 'visible', target: s.target })})`
                       : adapters[platform](s));
}
console.log(compile(caseDef, 'web'));
```
