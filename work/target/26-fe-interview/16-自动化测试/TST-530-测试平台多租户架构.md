## TST-530：测试平台的多租户架构如何设计

**答**：
- 结论：租户隔离（数据/资源/权限）+ 共享引擎。数据按 tenantId 分区或行级隔离；资源按配额与队列隔离；权限 RBAC 控制可见范围。
- 做法：所有资源带 tenantId，查询强制注入（防越权）；执行队列按租户配额 + 公平调度（防一个大户占满）；审计日志记录跨租户操作。
- 追问钩子：如何防止租户 A 越权看到 B 的数据？——数据访问层统一强制 tenantId 过滤（不可绕过），并加自动化越权测试用例持续验证。

```javascript
// 多租户数据访问：强制注入 tenantId 过滤，防止越权
function scopedQuery(tenantId, table, filters = {}) {
  return { sql: `SELECT * FROM ${table} WHERE tenant_id = ? AND ${Object.keys(filters)
    .map(k => `${k} = ?`).join(' AND ')}`,
    params: [tenantId, ...Object.values(filters)] };
}
// 配额检查：单租户并发不得超过配额
function canRun(usage, tenant, quota = { max: 20 }) {
  return (usage[tenant] || 0) < quota.max;
}
console.log(scopedQuery('team-a', 'runs', { status: 'fail' }));
```
