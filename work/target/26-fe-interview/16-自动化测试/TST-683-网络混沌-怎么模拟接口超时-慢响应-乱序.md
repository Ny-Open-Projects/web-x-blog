## TST-683：网络混沌：怎么模拟接口超时 / 慢响应 / 乱序 / 部分失败并验证降级？

**答**：
- 结论：用请求代理层按 URL/方法注入策略——延迟、错误码、乱序、断连，而不是全站限速。
- 验证重点：降级 UI 是否出现、重试是否退避、超时后是否有明确提示。
- 部分失败按百分比注入，模拟长尾接口抖动而非全挂。
- 追问钩子：注入超时后前端重试把后端打挂了，这是前端的锅吗？

```javascript
function networkChaos(handler, rules = []) {
  return async (req) => {
    const rule = rules.find(r => r.match(req.url));
    if (!rule) return handler(req);
    if (Math.random() < (rule.errorRate || 0))
      throw Object.assign(new Error('chaos'), { code: 503 });
    if (rule.delayMs)
      await new Promise(r => setTimeout(r, rule.delayMs));
    return handler(req);
  };
}
const fetch2 = networkChaos(fetch, [
  { match: u => u.includes('/pay'), delayMs: 3000, errorRate: 0.3 },
]);
fetch2('/pay').catch(e => console.log('降级:', e.code));
```
