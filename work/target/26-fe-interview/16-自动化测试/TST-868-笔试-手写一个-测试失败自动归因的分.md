## TST-868：笔试：手写一个「测试失败自动归因的分类器」（规则 + AI 混合）
**答**：
- 需求：实现 classifyFailure(failure) —— 先规则匹配（超时/断言失败/环境问题），规则不确定时交给 AI 分类器（mock 函数）。
- 规则：message 含 timeout → 'flaky/timeout'；含 'Expected' → 'assertion'；含 'ECONNREFUSED' → 'environment'。
- 边界：AI 分类返回置信度 < 0.7 时归为 'needs-human'；未知异常不抛错，转人工。

```javascript
function classifyFailure(failure, aiClassify = () => ({ category: 'unknown', confidence: 0 })) {
  const msg = failure.message || '';
  // 1. 规则优先（确定性强、零成本）
  if (/timeout|exceeded/i.test(msg)) return { category: 'flaky/timeout', source: 'rule', confidence: 1 };
  if (/Expected|toBe|toEqual/i.test(msg)) return { category: 'assertion', source: 'rule', confidence: 1 };
  if (/ECONNREFUSED|getaddrinfo/i.test(msg)) return { category: 'environment', source: 'rule', confidence: 1 };
  // 2. 规则不确定 -> AI 分类
  const ai = aiClassify(msg);
  if (ai.confidence < 0.7) return { category: 'needs-human', source: 'ai-low-confidence' };
  return { category: ai.category, source: 'ai', confidence: ai.confidence };
}
console.log(classifyFailure({ message: 'Test timeout 5000ms exceeded' }));
console.log(classifyFailure({ message: 'weird crash' })); // needs-human

// AI 高置信度返回时采纳其分类
console.log(classifyFailure({ message: 'render crashed' },
  () => ({ category: 'runtime-error', confidence: 0.92 }))); // source:'ai'

// 混合策略价值：规则覆盖高频确定场景（零成本、可解释）
// AI 处理长尾未知异常；两者都不确定时转人工，避免误判
```
**评分点**：
- 规则优先 + AI 兜底的混合策略，先确定性后概率性。
- 置信度阈值 < 0.7 转人工，体现 AI 不确定时的保守设计。
- 未知异常不抛错，归 needs-human，边界健壮。
- 能点出「规则可解释且零成本，AI 处理长尾」这一混合架构思想。
