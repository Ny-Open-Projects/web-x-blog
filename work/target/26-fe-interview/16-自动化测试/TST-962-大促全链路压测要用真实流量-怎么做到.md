## TST-962：大促全链路压测要用真实流量，怎么做到「脱敏回放」又不把真实用户写进压测库？
**答**：
- 结论：用「影子表 + 流量脱敏回放」——录制线上流量后脱敏，回放时写入影子库/影子表，与真实库物理隔离。
- 要点：回放前对 userId/phone/token 做令牌化映射；压测请求带影子标识，中间件路由到影子数据源；压测结束销毁影子数据。
- 红线：禁止压测链路直连生产库写操作；支付/短信等副作用必须 mock。
- 追问钩子：压测流量里混进了一条未脱敏的手机号并触发了短信，你如何在事后审计中发现并止损？

```javascript
function shadowReplay(recordedFlows) {
  const tokenMap = new Map();
  return recordedFlows.map(flow => {
    const tokenize = v => {
      if (!tokenMap.has(v)) tokenMap.set(v, `TK_${tokenMap.size + 1}`);
      return tokenMap.get(v);
    };
    return {
      ...flow,
      headers: { ...flow.headers, 'X-Shadow': 'true', token: tokenize(flow.headers.token) },
      body: { ...flow.body, phone: tokenize(flow.body.phone) },
      sideEffects: ['sms', 'pay'].filter(k => flow.sideEffects?.[k]), // 必须 mock
    };
  });
}
const flows = shadowReplay([{ headers: { token: 't1' }, body: { phone: '13800000000' },
  sideEffects: { sms: true } }]);
console.log(flows[0].body.phone, flows[0].sideEffects); // 'TK_2' , ['sms'] → 需 mock
```
