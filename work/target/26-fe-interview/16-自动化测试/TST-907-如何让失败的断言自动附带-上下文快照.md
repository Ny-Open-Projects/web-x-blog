## TST-907：如何让失败的断言自动附带「上下文快照」（DOM/接口响应/ localStorage）？
**答**：
- 结论：失败时的现场比断言本身更值钱——在断言前用 fixture 捕获最小上下文，失败时一并写入报告。
- Playwright：on('page') 里监听 test 失败，自动保存 page.screenshot + page.content() + 最近 N 条请求响应。
- 体积控制：上下文要「最小化 + 脱敏」，只截视口、只留相关字段，避免报告膨胀和 PII 泄漏。
- 追问钩子：偶发失败你在 CI 上复现不了，但报告里有当时的接口响和 DOM 快照，你会怎么定位是前端渲染还是后端数据问题？

```javascript
test.beforeEach(async ({ page }, testInfo) => {
  const responses = [];
  page.on('response', async r => {
    if (/\/api\//.test(r.url())) responses.push({ url: r.url(), status: r.status() });
  });
  testInfo.__ctx = { responses, page };
});
test.afterEach(async ({}, testInfo) => {
  if (testInfo.status !== 'passed') {
    const { responses, page } = testInfo.__ctx;
    await page.screenshot({ path: `fail-${testInfo.title}.png`, fullPage: false });
    const dom = (await page.content()).slice(0, 5000); // 截断防膨胀
    await testInfo.attach('diagnostic', {
      body: JSON.stringify({ dom, responses: responses.slice(-10) }, null, 2),
      contentType: 'application/json',
    });
  }
});
```
