## TST-597：前端缓存与离线的混沌验证

**答**：
- 结论：验证「网络不可用时缓存是否可用且不过期误导」——注入断网，断言页面从缓存/Service Worker 渲染、展示离线提示、数据带时间戳、重连后能刷新。
- 做法：用离线模式加载页面看是否可访问；断言缓存数据有过期标识；重连后自动重新拉取并更新；验证缓存容量与淘汰策略不会撑爆存储。
- 追问钩子：缓存了过期价格导致用户误解怎么办？——对时效性数据（价格/库存）禁用长期缓存，降级时明确标注「数据可能过时」并提供刷新入口。

```javascript
// 离线降级：判断是否可用缓存及是否需标注过期
function offlineRender(cacheEntry, now = Date.now()) {
  if (!cacheEntry) return { ok: false, ui: 'offline-placeholder' };
  const ageMin = (now - cacheEntry.ts) / 60000;
  return { ok: true, ui: ageMin > 30 ? 'stale-banner' : 'normal',
    stale: ageMin > 30, fromCache: true };
}
// 重连后刷新策略：时效数据强制拉取，非时效数据可延后
async function onReconnect(cacheEntry, fetcher, now = Date.now()) {
  const rendered = offlineRender(cacheEntry, now);
  if (!rendered.ok || rendered.stale) {
    const fresh = await fetcher();       // 重新拉取
    return { source: 'network', fresh, clearedStale: rendered.stale };
  }
  return { source: 'cache', fresh: cacheEntry.data, clearedStale: false };
}
console.log(offlineRender({ ts: Date.now() - 40 * 60000, data: {} })); // stale-banner
```
