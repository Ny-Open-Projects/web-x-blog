## TST-583：笔试：笔试：网络故障注入器（延迟/丢包/断网）

**题目**：实现 NetworkChaos，模拟网络故障并记录拦截统计。接口：apply(profile) 设置当前故障 profile={latency:ms, lossRate:0~1, offline:boolean}；send(req) 模拟一次请求：若 offline 返回 {ok:false,error:'offline'}；否则按 lossRate 随机丢包（可用注入的 rand 函数便于单测），丢包返回 {ok:false,error:'packet-loss'}；未丢包则延迟 latency 后（实际实现可用伪延迟：记录 plannedLatency 而不真的 sleep，便于测试）返回 {ok:true, req, latency}；stats() 返回 {sent, dropped, offlineBlocked, avgLatency}。要求边界、统计正确，rand 可通过构造函数注入。

**答**：
- 结论：用注入的 rand 做确定性丢包判定，统计各类结果；offline 优先于丢包。
- 实现要点：构造注入 rand=Math.random 便于测试；send 先判 offline，再 rand()<lossRate 判丢包；统计 sent/dropped/offlineBlocked 与成功延迟均值。
- 追问钩子：为什么要注入 rand？——让丢包行为可预测（测试传固定 rand=0/0.99），否则网络混沌本身变成 flaky 源。

```javascript
class NetworkChaos {
  constructor(rand = Math.random) { this.rand = rand; this.profile = {}; this.c = { sent: 0, dropped: 0, offlineBlocked: 0, latencySum: 0, ok: 0 }; }
  apply(profile = {}) { this.profile = profile; return this; }
  send(req) {
    const s = this.c; s.sent++;
    const { latency = 0, lossRate = 0, offline = false } = this.profile;
    if (offline) { s.offlineBlocked++; return { ok: false, error: 'offline' }; }
    if (this.rand() < lossRate) { s.dropped++; return { ok: false, error: 'packet-loss' }; }
    s.ok++; s.latencySum += latency;
    return { ok: true, req, latency }; // 伪延迟，记录而不真 sleep
  }
  stats() { return { ...this.c, avgLatency: this.c.ok ? +(this.c.latencySum / this.c.ok).toFixed(1) : 0 }; }
}
const chaos = new NetworkChaos(() => 0.5).apply({ latency: 100, lossRate: 0.8 });
console.log(chaos.send('/api').ok, chaos.stats());
```

**评分点**：
- offline 优先于丢包判定，逻辑顺序正确。
- rand 可注入，丢包判定用 rand()<lossRate 可预测。
- stats 统计 sent/dropped/offlineBlocked/avgLatency 准确。
- 边界（全离线、lossRate=0/1、无成功样本 avgLatency）处理到位。
