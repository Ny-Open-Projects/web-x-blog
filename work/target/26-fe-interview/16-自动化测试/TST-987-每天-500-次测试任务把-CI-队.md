## TST-987：每天 500 次测试任务把 CI 队列打满，怎么「削峰填谷」又不拖慢关键发布？
**答**：
- 结论：给任务分优先级——发布相关任务高优立即跑，普通回归进队列按资源水位调度；用「令牌桶/漏桶」控制并发峰值。
- 做法：夜间低峰跑全量回归，白天只跑受影响用例；高优任务可抢占低优资源。
- 度量：队列等待时长 P95、发布任务从提交到反馈的时长，作为优化目标。
- 追问钩子：大促当天所有团队都触发全量回归，队列爆炸，你怎么保证发布任务不被淹没？

```javascript
class TokenBucket {
  constructor(capacity, refillPerSec) {
    this.capacity = capacity; this.tokens = capacity; this.refill = refillPerSec;
    this.last = Date.now();
  }
  take(n = 1) {
    const now = Date.now();
    this.tokens = Math.min(this.capacity,
      this.tokens + (now - this.last) / 1000 * this.refill);
    this.last = now;
    if (this.tokens >= n) { this.tokens -= n; return true; }
    return false; // 排队等待
  }
}
const bucket = new TokenBucket(10, 2);
function dispatch(task) {
  if (task.priority === 'release' || bucket.take()) return 'run-now';
  return 'queue'; // 普通任务超出令牌则排队
}
console.log(dispatch({ priority: 'normal' }), dispatch({ priority: 'release' }));
```
