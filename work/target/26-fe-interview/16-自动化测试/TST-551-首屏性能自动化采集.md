## TST-551：首屏加载性能如何自动化采集与断言

**答**：
- 结论：用 Performance API/Lighthouse 在受控环境采集 FCP/LCP/资源瀑布，结合代码注入的自定义打点（业务首屏就绪点），作为可失败的断言。
- 做法：固定网络节流与 CPU 降速，冷启动多次取中位数；断言 LCP 预算 + 关键资源数量/体积上限；用 performance.mark/measure 标记「业务可用时刻」而非仅浏览器指标。
- 追问钩子：浏览器 LCP 早于真实数据就绪怎么办？——补一个「数据渲染完成」的自定义打点，把业务首屏纳入断言，避免指标达标但用户看到骨架屏。

```javascript
// 自定义业务首屏打点：数据渲染完成才 mark ready
async function renderFirstScreen(data) {
  performance.mark('fs-start');
  await fetchData(data);
  render(data);
  performance.mark('fs-ready');
  performance.measure('first-screen-ready', 'fs-start', 'fs-ready');
  const ms = performance.getEntriesByName('first-screen-ready')[0].duration;
  return { readyMs: ms, pass: ms <= 2500 };
}
// 测试中断言：await expect(renderFirstScreen(input)).resolves.toMatchObject({ pass: true })
```
