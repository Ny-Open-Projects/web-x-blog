## TST-380：跨团队依赖变更时测试门禁的协同（谁的门禁说了算）？
**答**：
- 接口契约是唯一协同点：契约验证通过 = 允许集成，不依赖「口头确认」。
- 发布窗口协同：依赖方（后端）先发，前端跟随——集成门禁自动检测依赖版本就绪。
- 冲突升级：门禁互卡时由集成 owner 仲裁（数据说话：契约/测试结果）。
- 跨团队 E2E：集成环境的联合冒烟由平台团队维护，结果共享。

const coordination = {
  gate: 'contract verification = integration permission',
  order: 'provider deploy → contract check → consumer follow',
  arbiter: 'integration owner（依据契约与测试数据）',
};
