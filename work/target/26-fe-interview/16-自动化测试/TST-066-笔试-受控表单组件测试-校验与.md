## TST-066：笔试：为受控表单组件写完整测试（校验/提交/受控回显）
**答**：
- 需求：`<AddressForm value onChange onSubmit />` 受控组件——输入同步 onChange、必填校验文案、合法提交携带结构化数据、外部 value 变化回显。
- 要点：受控组件测试用 rerender 模拟父级 setState（外部值变化回显）；提交断言回调参数的结构化对象而非内部 state；校验文案断言用 text 查询。
- 边界：连续输入用 user.type（逐字符触发 onChange，防抖逻辑顺带被覆盖）；空值提交断言 onSubmit 未被调用且出现错误提示。

```jsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';
import AddressForm from './AddressForm';

describe('AddressForm 受控组件', () => {
  it('输入逐字符同步 onChange', async () => {
    const user = userEvent.setup();
    const onChange = vi.fn();
    render(<AddressForm value={{ city: '' }} onChange={onChange} />);
    await user.type(screen.getByLabelText('城市'), '杭');
    expect(onChange).toHaveBeenLastCalledWith({ city: '杭' });
  });

  it('城市为空时提交显示错误且不回调 onSubmit', async () => {
    const user = userEvent.setup();
    const onSubmit = vi.fn();
    render(<AddressForm value={{ city: '' }} onChange={vi.fn()} onSubmit={onSubmit} />);
    await user.click(screen.getByRole('button', { name: '保存' }));
    expect(screen.getByText('城市必填')).toBeInTheDocument();
    expect(onSubmit).not.toHaveBeenCalled();
  });

  it('外部 value 更新后输入框回显（受控）', () => {
    const { rerender } = render(<AddressForm value={{ city: '' }} onChange={vi.fn()} />);
    rerender(<AddressForm value={{ city: '上海' }} onChange={vi.fn()} />);
    expect(screen.getByLabelText('城市')).toHaveValue('上海');   // jest-dom toHaveValue
  });

  it('合法提交携带结构化数据', async () => {
    const user = userEvent.setup();
    const onSubmit = vi.fn();
    render(<AddressForm value={{ city: '杭州' }} onChange={vi.fn()} onSubmit={onSubmit} />);
    await user.click(screen.getByRole('button', { name: '保存' }));
    expect(onSubmit).toHaveBeenCalledWith({ city: '杭州' });
  });
});
```
**评分点**：
- 受控回显用 rerender 而不是 userEvent（外部驱动）。
- 提交断言回调参数结构，不戳内部 state。
- 禁止提交路径断言「错误文案 + 未回调」两点。
- jest-dom 的 toHaveValue/toBeInTheDocument 使用得当。
