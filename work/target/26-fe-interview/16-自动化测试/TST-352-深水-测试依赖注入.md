## TST-352：测试中的依赖注入（DI）如何提升可测性？
**答**：
- 副作用（fetch/存储/时钟）通过参数/context 注入，测试传入 fake 实现而非 monkey-patch。
- fake 实现语义完整（如 fakeStorage 支持跨页面持久），不是空壳。
- DI 容器测试模式：生产绑定与测试绑定集中声明，避免散落 mock。
- 反模式警示：直接 jest.mock 全局模块导致实现耦合——优先参数注入。

```javascript
// 生产
export const deps = { clock: () => Date.now(), storage: localStorage };
// 测试
render(<App deps={{ clock: () => FIXED, storage: fakeStorage }} />);
// fake 语义完整：fakeStorage.get/set/clear 与真实一致
r
```
