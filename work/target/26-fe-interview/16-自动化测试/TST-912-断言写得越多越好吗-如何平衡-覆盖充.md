## TST-912：断言写得越多越好吗？如何平衡「覆盖充分」与「失败噪声淹没根因」？
**答**：
- 结论：断言要「少而准」——一个用例聚焦一个行为，断言数量与失败噪声正相关，根因被掩盖的概率随断言数上升。
- 经验：单测 3~5 个内聚断言；E2E 关键路径 1~2 个业务结果断言 + 必要的软断言；其余交给快照兜底。
- 诊断：用「断言有效率」= 发现过真实缺陷的断言 / 总断言数，定期删掉从未失败的「空气断言」。
- 追问钩子：一个用例有 30 个断言，其中 29 个从不失败，你如何识别并清理这些零价值断言？

```javascript
// 断言有效性追踪：给每个断言打标签，记录是否曾捕获缺陷
const ledger = new Map();
function trackedAssert(id, cond) {
  const rec = ledger.get(id) || { runs: 0, fails: 0 };
  rec.runs++;
  if (!cond) { rec.fails++; throw new Error(`断言 ${id} 失败`); }
  ledger.set(id, rec);
}
// 定期报告：从未失败且运行 > 100 次的断言 = 清理候选
function staleAssertions() {
  return [...ledger.entries()]
    .filter(([, r]) => r.runs > 100 && r.fails === 0)
    .map(([id]) => id);
}
trackedAssert('price>0', price > 0);
trackedAssert('status=PAID', status === 'PAID');
console.log(staleAssertions()); // ['price>0'] → 考虑删除或加变异测试验证其有效性
```
