## TST-821：万级用例规模下，测试报告如何聚合与降噪，避免「报告爆炸」？
**答**：
- 结论：报告要分层聚合——顶部看趋势与门禁结论，中部按业务线/模块聚合，底部才下钻到单用例，让不同角色各取所需。
- 降噪手段：相同失败堆栈聚类（同一根因只报一次）、flaky 用例单独分区、成功用例默认折叠、只展示本次「新增失败」。
- 分级通知：门禁失败才 @人，warner 只进看板；避免每次构建都推送几百条失败造成「告警疲劳」。
- 可检索：报告带标签（业务线/模块/等级），支持按 owner 过滤，失败可直接跳转 trace/视频。
- 追问钩子：聚合后如何避免「把两个不同根因的错误因为堆栈相似而错误合并」？

```javascript
// 报告降噪：按根因聚合失败
function aggregateFailures(failures) {
  const groups = new Map();
  for (const f of failures) {
    const key = f.stackTop || f.message; // 栈顶作为根因指纹
    if (!groups.has(key)) groups.set(key, { reason: key, count: 0, cases: [] });
    groups.get(key).count++;
    groups.get(key).cases.push(f.caseName);
  }
  return [...groups.values()]
    .sort((a, b) => b.count - a.count)
    .map(g => ({ ...g, sample: g.cases.slice(0, 3) })); // 每类只展示 3 个样本
}
console.log(aggregateFailures([
  { caseName: 'A', stackTop: 'Cannot read undefined' },
  { caseName: 'B', stackTop: 'Cannot read undefined' },
  { caseName: 'C', stackTop: 'timeout 3000ms' },
])); // 2 类根因，而非 3 条原始失败
```
