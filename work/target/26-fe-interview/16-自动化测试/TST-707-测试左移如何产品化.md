## TST-707：测试左移如何「产品化」：给业务方的自助测试能力设计

**答**：
- 结论：左移产品化的关键是「让开发在提交前就能自助拿到质量反馈」，把测试能力封装成 IDE 插件 / CLI / MR 评论而非文档。
- 自助能力要有「默认值」：零配置即可跑核心检查，进阶再开放配置，降低使用门槛。
- 反馈要落到开发的工作流（MR 评论、本地 pre-commit），而非另开平台让他主动查。
- 追问钩子：自助能力被滥用来「刷过门禁」，如何在产品层面反制？

```javascript
// 左移门禁：MR 评论机器人决策
function mrGate(checks) {
  const blockers = checks.filter(c => !c.passed && c.severity === 'block');
  const warns = checks.filter(c => !c.passed && c.severity === 'warn');
  return {
    mergeable: blockers.length === 0,
    comment: blockers.length
      ? `阻断：${blockers.map(b => b.name).join(', ')}`
      : warns.length ? `提示：${warns.map(w => w.name).join(', ')}` : '可合并',
  };
}
console.log(mrGate([
  { name: '单测', passed: true, severity: 'block' },
  { name: '安全扫描', passed: false, severity: 'block' },
]).mergeable); // false
```
