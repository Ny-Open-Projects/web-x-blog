## TST-293：测试数据清理（teardown）策略的选型与坑？
**答**：
- 命名空间隔离 + 定时清空 > 逐条清理（逐条慢且失败残留），测试库按运行批次整批重建。
- 共享环境（staging）则必须逐条清理 + 登记表兜底（孤儿数据巡检）。
- 清理失败要告警（残留数据累积会导致后续用例受污染）。
- 快照对比验证清理完整性：运行前后实体计数一致。

```javascript
// 命名空间整批重建（专用测试库）
afterAll(async () => { await db.truncateSchema(`ns_${RUN_ID}`); });
// 共享环境：登记表兜底巡检
cron: SELECT entity FROM registry WHERE created_at < now()-7d AND alive=true; -- 告警
r
```
