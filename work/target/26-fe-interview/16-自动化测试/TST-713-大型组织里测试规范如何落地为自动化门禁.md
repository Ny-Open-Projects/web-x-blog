## TST-713：大型组织里测试规范如何落地为自动化门禁而非文档

**答**：
- 结论：规范可信度 = 是否可执行；能把规范写成门禁的就写成门禁，写不成的才留文档，且文档要能一键生成检查脚本。
- 门禁分层：提交前（快、轻）、MR 阶段（全量单测/规范检查）、发布前（E2E/性能/安全），避免一刀切拖慢开发。
- 每条门禁可豁免但需审批与到期时间，防止「为了过门禁而造轮子」。
- 追问钩子：门禁误拦了紧急发布，如何设计既保质量又不阻塞业务的机制？

```javascript
// 门禁分级与紧急豁免
function runGates(ctx) {
  const gates = [
    { name: 'lint', stage: 'commit', ms: 2000 },
    { name: 'unit', stage: 'mr', ms: 60000 },
    { name: 'e2e', stage: 'release', ms: 600000 },
  ];
  const applicable = gates.filter(g => g.stage === ctx.stage);
  const skip = ctx.emergency && ctx.approved;
  return {
    executed: skip ? [] : applicable.map(g => g.name),
    bypassed: skip ? applicable.map(g => g.name) : [],
  };
}
console.log(runGates({ stage: 'mr', emergency: true, approved: true }).bypassed);
```
