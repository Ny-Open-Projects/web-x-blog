## TST-893：如何度量混沌测试的价值（发现了多少真实隐患）？
**答**：
- 结论：混沌价值用「隐患发现数 + 修复闭环率 + 事故预防数」度量，而非「注入了多少次故障」——衡量的是「避免了多少潜在事故」。
- 发现指标：每次演练发现的新隐患数（按严重度分级）、重复发现（老问题复发）。
- 闭环指标：隐患修复率、MTTR（从发现到修复）、修复后回归验证通过率。
- 价值证明：对比演练前后的线上事故数，把「提前发现的隐患」折算成避免的事故损失。
- 追问钩子：连续 3 个月演练「零发现」，说明体系很稳还是演练没效果？如何区分？

```javascript
// 混沌价值度量
function chaosValue(findings, incidents) {
  const fixed = findings.filter(f => f.fixed);
  const critical = findings.filter(f => f.severity === 'critical');
  return {
    发现隐患数: findings.length,
    高危隐患: critical.length,
    修复闭环率: Number((fixed.length / findings.length).toFixed(2)),
    事故下降: incidents.before - incidents.after,
    zeroFindingNote: findings.length === 0 ? '需检查注入是否真的生效' : '正常',
  };
}
console.log(chaosValue([
  { severity: 'critical', fixed: true }, { severity: 'low', fixed: false },
], { before: 8, after: 3 }));
```
