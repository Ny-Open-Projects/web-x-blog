## TST-501：电商大促场景如何设计分层测试策略

**答**：
- 结论：采用「金字塔 + 风险加权」分层。底层单测/组件测保业务逻辑与渲染，中层契约测保服务间约定，顶层少量 E2E 保核心链路；大促前再叠加全链路压测与故障注入。
- 大促特殊动作：先做容量评估与基准压测，再对「下单/支付/库存扣减」核心链路做全链路压测 + 混沌；回归阶段用风险模型抽取冒烟子集，而非全量。
- 追问钩子：若单测覆盖率 90% 大促仍出 P0，说明哪层缺位？——多半是契约测试与场景化 E2E 缺位：单测测不出跨服务时序、库存超卖这类系统性问题。

```javascript
// 分层测试策略配置：风险等级决定各层的投入权重
const LAYER_WEIGHT = {
  unit:     { low: 0.6, mid: 0.5, high: 0.4 }, // 高风险时单测占比下降
  contract: { low: 0.1, mid: 0.2, high: 0.25 },
  component:{ low: 0.2, mid: 0.2, high: 0.2 },
  e2e:      { low: 0.1, mid: 0.1, high: 0.15 },
};
function strategyFor(modules) {
  return modules.map(m => {
    const w = LAYER_WEIGHT[m.risk];
    return { name: m.name, budget: Object.fromEntries(
      Object.entries(w).map(([k, v]) => [k, Math.round(v * m.cases)])) };
  });
}
console.log(strategyFor([
  { name: '下单', risk: 'high', cases: 100 },
  { name: '帮助中心', risk: 'low', cases: 100 },
]));
```

## 追问（补充）

**追问**：

1. 全链路压测流量怎么造，能直接打生产吗 → 不能，压测流量打染色标识别到影子库与影子链路，写操作全落影子表，严禁直压核心库。
2. 压测通过了大促还是雪崩，最可能漏了什么 → 漏了下游依赖的容量与限流：缓存击穿、DB 连接池、第三方支付限流，压测必须带降级开关一起验证。
3. 故障注入在生产做还是预发做 → 破坏性注入放预发，生产只做低频、可秒级回滚的演练（如单实例摘除），且熔断与回滚预案必须已在手。
