## TST-539：大规模测试的稳定性治理体系怎么建

**答**：
- 结论：稳定性治理 = 预防（确定性设计）+ 检测（flaky/失败率监控）+ 响应（隔离/重试/告警）+ 改进（根因库）。四环节闭环。
- 做法：预防用可控时钟/数据工厂/禁随机；检测设 flaky 率与失败率 SLO；响应有 quarantine 与指数退避重试；改进把每次根因沉淀进知识库并避免复发。
- 追问钩子：SLO 定多少合适？——从历史基线出发（如 flaky<1%），逐季收紧；关键链路更严，边缘模块放宽，避免一刀切导致治理疲劳。

```javascript
// 稳定性健康度：综合 flaky/失败/重试率给套件打分
function stabilityScore(m) {
  const s = 100 - m.flakyRate * 1000 - m.failRate * 200 - m.retryRate * 50;
  return { score: +Math.max(0, Math.min(100, s)).toFixed(1),
    healthy: m.flakyRate < 0.01 && m.failRate < 0.05 };
}
// 治理闭环：按健康度把套件分配到不同响应策略
function governancePolicy(suites) {
  return suites.map(s => {
    const h = stabilityScore(s.metrics);
    const action = h.healthy ? 'keep-monitoring'
      : s.metrics.flakyRate >= 0.05 ? 'quarantine-and-fix' : 'investigate';
    return { name: s.name, ...h, action };
  });
}
const suites = [
  { name: 'checkout', metrics: { flakyRate: 0.005, failRate: 0.02, retryRate: 0.03 } },
  { name: 'legacy',   metrics: { flakyRate: 0.08,  failRate: 0.1,  retryRate: 0.2  } },
];
console.log(governancePolicy(suites)); // legacy 被隔离修复，checkout 持续监控
```
