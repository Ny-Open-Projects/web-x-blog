## TST-934：微前端跨应用路由跳转（主→子→子）的参数怎么定义契约并验证？
**答**：
- 结论：路由参数是「隐式接口」——要把 query/path 参数纳入 schema 定义（名称、类型、必填、枚举），跳转前后双端校验。
- 风险：主应用传 ?orderId=123，子应用读 ?id=，参数名不一致导致白屏，且 E2E 不一定覆盖所有跳转路径。
- 测法：生成「参数矩阵」测试——对每个子应用入口用合法/非法/缺失参数各跳一次，断言渲染结果与降级文案。
- 追问钩子：大促会场有 30 个跳转入口，你怎么保证新增一个入口时不会漏掉参数契约校验？

```javascript
const routeContracts = {
  '/detail': { required: ['skuId'], types: { skuId: 'string', from: 'string' } },
  '/checkout': { required: ['skuId', 'qty'], types: { qty: 'number' } },
};
function validateRoute(path, query) {
  const c = routeContracts[path];
  if (!c) throw new Error(`未登记路由契约 ${path}`);
  for (const k of c.required) if (!(k in query)) throw new Error(`${path} 缺少参数 ${k}`);
  for (const [k, t] of Object.entries(c.types))
    if (k in query && typeof query[k] !== t) throw new Error(`${path}.${k} 类型应为 ${t}`);
  return true;
}
test.each([
  ['/detail', { skuId: 's1' }],
  ['/checkout', { skuId: 's1', qty: 2 }],
])('路由参数合法 %s', (p, q) => expect(validateRoute(p, q)).toBe(true));
```
