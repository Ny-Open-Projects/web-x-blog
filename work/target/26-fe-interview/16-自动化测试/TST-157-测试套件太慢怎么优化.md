## TST-157：测试套件太慢怎么优化？从分钟级到秒级的手段清单
**答**：
- 先度量再优化：`vitest --reporter=json` 或 `test.each` 挂耗时插件，产出最慢用例 Top20。常见结论：慢的不是业务断言，而是 setup（重复 import、真实模块加载）与 E2E 的启动/等待。
- 单测层：① 环境按需——不需要 DOM 的测试指定 `environment: 'node'`（jsdom 慢数倍）；② 收敛 setup——`setupFiles` 只放必需全局，重初始化放 `beforeAll`；③ mock 边界上移——把慢的第三方（日期库 locale 加载、加密）mock 掉；④ 按项目拆分 vitest workspace，前端/node 环境并行跑。
- 组件/E2E 层：① 复用浏览器实例（Playwright context 池）；② 拦掉无关资源（route abort 埋点/字体）；③ storageState 跳过登录；④ networkidle 改条件等待；⑤ 并行分片 + 受影响用例选择器；⑥ 「重」数据用 API 造不用 UI 造。
- 结构性手段：受影响测试选择器（diff 驱动）、PR 只跑冒烟、全集每夜；建立「测试耗时」预算（PR 总时长 < 10min）并监控回归。
- 追问钩子：并行化为什么经常踩坑？——共享资源（数据库/端口/文件系统）没隔离，提速用例一多就互相踩，先隔离再并行。

```javascript
// vitest 慢用例定位 + 分项目提速
export default defineConfig({
  test: {
    environmentMatchGlobs: [            // 纯逻辑不加载 jsdom
      ['src/utils/**', 'node'],
      ['src/hooks/**', 'node'],
      ['src/components/**', 'jsdom'],
    ],
    // 报告：npx vitest run --reporter=json | node scripts/slow-tests.mjs
  },
});

// scripts/slow-tests.mjs：输出最慢 20 个用例
const r = JSON.parse(require('fs').readFileSync('/dev/stdin', 'utf8'));
const rows = (r.testResults ?? []).flatMap((f) => f.assertionResults ?? [])
  .map((a) => ({ name: a.fullName, ms: (a.duration ?? 0) }))
  .sort((a, b) => b.ms - a.ms).slice(0, 20);
console.table(rows);
```
