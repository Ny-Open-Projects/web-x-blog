## TST-187：为什么说测试是重构的安全网？怎么为「马上要重构」的代码建网？
**答**：
- 价值定义：重构的定义是「不改行为的改进」——没有行为锁定的手段，你无法证明「没改行为」。测试就是行为的可执行规格书：重构前后同一套测试全绿，行为等价得证。这也是「遗留代码没有测试 = 拆弹没有图纸」的原因。
- 给遗留代码建网：写特征测试（characterization test）——不写「应该怎样」，只记录「现在怎样」：跑一遍现有行为，把输出钉进断言（快照/黄金文件），先锁定现状再动刀。此时不评判行为对错，锁住是第一目的。
- 分步节奏：建网（特征测试 + 核心路径用例）→ 小步重构（每次一个语义动作，跑受影响测试）→ 绿了再下一步 → 全部完成后把特征测试升级为「表达意图的规格测试」。中间任何一步红了都能立刻定位是重构引入的。
- 安全网的质量要求：网眼要密但不能是死网——断言要针对行为（输入→输出），不能断言实现细节，否则重构必然「误报」逼你改测试，安全网反成枷锁（见 TST-057）。
- 追问钩子：测试也需要重构吗？——是，测试代码是资产要同标准维护；重构实现时同步审视测试表达的是「行为」还是「旧实现」。

```javascript
// 特征测试示例：锁定现有输出（先不判断对错）
test('[特征测试] 现有金额格式化行为', () => {
  // 记录现状：负数显示成 ¥-10.00（历史行为，暂不评判）
  expect(formatMoney(-10)).toBe('¥-10.00');
  expect(formatMoney(0)).toBe('¥0.00');
  expect(formatMoney(1234.567)).toBe('¥1,234.57');
});
// 重构后全绿 → 行为未变
// 然后升级为规格测试（带判断）：
test('负数金额应显示 -¥10.00（JIRA-2345）', () => {
  expect(formatMoney(-10)).toBe('-¥10.00');   // 修复历史行为，单独 PR
});
```
