## TST-318：如何让性能预算成为团队文化而不是形式？
**答**：
- 预算由业务共同制定（体验目标 → 指标预算），不是前端自嗨数字。
- 透明看板：每版本性能分与预算达成度全员可见，劣化归因到 PR。
- 激励对齐：性能回归修复纳入迭代正常工作量（不是「额外要求」）。
- 例外流程：预算调整 = 架构决策（owner 审批 + 记录理由），防私自放水。

const culture = {
  budget: '业务体验目标推导（转化率 ↔ LCP）',
  visible: '全员看板 + PR 归因',
  workflow: '性能修复计入迭代工作量',
  change: '预算调整 = 架构决策 + 审批',
};
