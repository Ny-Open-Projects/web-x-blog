## TST-834：测试平台多租户的「配额与成本分摊」怎么做？
**答**：
- 结论：多租户平台必须「可计量、可限额、可分摊」——按团队统计用量（机时/并发数/存储），设配额防抢占，再按用量分摊成本。
- 计量：every 执行记录打上 tenant/team 标签，统计 CPU-时长、并发槽位占用、报告存储量。
- 限额：按团队设并发上限与月配额，超出排队或降级，避免单一团队跑满集群。
- 分摊：按用量生成账单（呼应 TST-481 按团队出账），推动团队优化低效用例（长耗时/反复重跑）。
- 追问钩子：某团队通过「疯狂重跑」刷高用量导致账单爆炸，你如何用机制而非口头约束？

```javascript
// 配额控制：按团队限并发 + 计量
class QuotaManager {
  constructor(quotas) { this.quotas = quotas; this.usage = new Map(); }
  canRun(team) {
    const q = this.quotas[team] || { concurrency: 2, monthlyMinutes: 600 };
    const u = this.usage.get(team) || { active: 0, minutes: 0 };
    return u.active < q.concurrency && u.minutes < q.monthlyMinutes;
  }
  consume(team, minutes) {
    const u = this.usage.get(team) || { active: 0, minutes: 0 };
    u.minutes += minutes; this.usage.set(team, u);
  }
}
const qm = new QuotaManager({ pay: { concurrency: 8, monthlyMinutes: 5000 } });
console.log(qm.canRun('pay'), qm.canRun('unknown')); // true true(默认配额)
```
