## TST-989：发布门禁要「动态分级」，它的信号源应该有哪些？如何避免被单一指标误导？
**答**：
- 结论：信号源要多维且正交——代码风险（变更范围/关键路径）、质量信号（测试通过率/flaky/覆盖率增量）、业务上下文（大促/故障期）、历史数据（该模块缺陷密度）。
- 去偏：单一指标（如覆盖率）易被 gaming，用多信号交叉验证；给每个信号设权重与置信度。
- 实时性：信号需近实时采集（提交时即算），否则门禁滞后于决策。
- 追问钩子：覆盖率 95% 但改动落在历史高频故障模块，门禁该怎么定级？

```javascript
const SIGNALS = {
  codeRisk: { changeScope: 0.3, touchesCriticalPath: 0.4 },
  quality: { passRate: 0.3, flakeRate: 0.2, diffCoverage: 0.2 },
  context: { promoFreeze: 0.5, recentIncident: 0.5 },
  history: { moduleBugDensity: 0.3 },
};
function computeRiskLevel(signals) {
  let score = 0;
  score += (signals.changeScope || 0) * SIGNALS.codeRisk.changeScope;
  score += (signals.touchesCriticalPath ? 1 : 0) * SIGNALS.codeRisk.touchesCriticalPath;
  score += (1 - (signals.passRate ?? 1)) * SIGNALS.quality.passRate;
  score += (signals.flakeRate || 0) * SIGNALS.quality.flakeRate;
  score += (signals.promoFreeze ? 1 : 0) * SIGNALS.context.promoFreeze;
  score += (signals.moduleBugDensity || 0) * SIGNALS.history.moduleBugDensity;
  return score >= 0.6 ? 'high' : score >= 0.3 ? 'medium' : 'low';
}
console.log(computeRiskLevel({ changeScope: 0.8, touchesCriticalPath: true,
  passRate: 0.99, promoFreeze: false, moduleBugDensity: 0.9 }));
// 'high' → 覆盖率再高也因关键路径+高频故障模块升级门禁
```
