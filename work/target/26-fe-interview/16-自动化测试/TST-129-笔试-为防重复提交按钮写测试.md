## TST-129：笔试：为「防重复提交」按钮写测试（连点 + 网络慢场景）
**答**：
- 场景：下单按钮在请求返回前要禁用（loading 态），防止用户连点产生重复订单。测试要覆盖：① 请求进行中连点只发一次请求；② 成功后按钮恢复可点；③ 失败后恢复可点可重试；④ 请求 pending 期间 UI 显示 loading。
- 测试要点：用 MSW 的 `delay` 把响应拖慢，才能在请求飞行中做连点断言——这是本题核心技巧（没有慢响应窗口，防重逻辑测不到中间态）。请求次数断言用 MSW 捕获或 spy fetch。
- 边界：双击间隔极短（连续两次 click 事件）也要只发一次；组件卸载后 setState 要安全（act 警告排查点）。

```jsx
// CartButton.tsx 被测组件（供理解场景）
// 点击 → setSubmitting(true) + fetch；返回后 setSubmitting(false)

import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { http, HttpResponse, delay } from 'msw';
import { server } from '@/mocks/server';

test('请求飞行中连点，只提交一次', async () => {
  const submitted = [];
  server.use(
    http.post('/api/order', async ({ request }) => {
      submitted.push(await request.json());
      await delay(300); // 拉出网络窗口：关键！
      return HttpResponse.json({ ok: true });
    }),
  );

  render(<CheckoutButton />);
  const btn = screen.getByRole('button', { name: '提交订单' });

  const user = userEvent.setup();
  await user.click(btn);
  await user.click(btn); // 第二次点击在 pending 期间
  await user.click(btn);

  expect(submitted).toHaveLength(1);              // 核心断言：只发一次
  expect(btn).toBeDisabled();                     // 飞行中禁用
  await screen.findByText('提交成功');
  expect(btn).toBeEnabled();                      // 完成后恢复
});

test('失败后可重试', async () => {
  server.use(http.post('/api/order', () => HttpResponse.error(), { once: true }));
  render(<CheckoutButton />);
  const user = userEvent.setup();
  await user.click(screen.getByRole('button', { name: '提交订单' }));
  await screen.findByText('网络异常，请重试');
  expect(screen.getByRole('button', { name: '提交订单' })).toBeEnabled();
});
```

**评分点**：
1. 是否用 delay 造出 pending 窗口（连点才能落在飞行期）。
2. 请求次数断言方式（捕获数组/spy）而非只断言 UI。
3. 覆盖成功/失败/恢复三态，不只 happy path。
4. userEvent 而非 fireEvent.click（真实事件序列）。
