## TST-918：快照文件越攒越大、几百个基线没人敢删，如何治理「快照膨胀」？
**答**：
- 结论：快照膨胀的本质是「无人认领」——先做全量盘点分类（活跃/孤儿/过期），再建立定期清理机制。
- 三类：活跃（有用例引用且近期变更）、孤儿（无用例引用，删）、过期（对应用例已废弃/重构，删）。
- 机制：CI 加「孤儿快照检测」卡点；每季度 snapshot review day；删除需 owner 确认但不需要改业务代码。
- 追问钩子：删了 50 个孤儿快照后覆盖率没变、测试全绿，你如何向团队证明这次清理是安全的？

```javascript
// 孤儿快照检测：扫描用例中 toMatchSnapshot 的键与快照文件键
function findOrphanSnapshots(snapshotKeys, referencedKeys) {
  const ref = new Set(referencedKeys);
  return [...snapshotKeys].filter(k => !ref.has(k));
}
// 统计：哪些快照 90 天未被更新（疑似过期）
function staleSnapshots(gitLogByKey) {
  const cutoff = Date.now() - 90 * 864e5;
  return Object.entries(gitLogByKey)
    .filter(([, lastTouched]) => lastTouched < cutoff)
    .map(([key]) => key);
}
const orphans = findOrphanSnapshots(
  ['sum 1', 'tax 1', 'legacy 1'], ['sum 1', 'tax 1']
);
console.log(orphans); // ['legacy 1'] → 删除候选
```
