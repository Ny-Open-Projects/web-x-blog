## TST-054：「纯函数优先、副作用隔离」在单测设计里怎么落地？
**答**：
- 原理：可测性差的根源是逻辑与副作用（IO/时间/随机/全局状态）缠绕。重构方向是把「决策」提为纯函数、把「执行」留在边缘——决策层随便测，执行层薄到不值得测或通过接口 mock。
- 落地手法：① 参数注入（now/random/fetch 作为参数）；② 拆函数——`process(data) -> plan`（纯）与 `apply(plan)`（副作用）分离；③ 收集器模式——副作用先收集成副作用列表，主流程结束后统一 flush。
- 收益：纯函数部分用例无需 mock 框架、跑得快、永不 flaky；副作用的测试面收敛到薄薄一层。
- 判断标准：一个函数如果「需要 mock 才能测」，先问能不能重构让它不需要 mock。
- 追问钩子：Redux 的 reducer 是这套思想的工业化样本——reducer 纯函数 + effect 在中间件层。

```typescript
// 重构前：逻辑与副作用缠绕，必须 mock Date + fetch 才能测
// export async function refreshCoupon() {
//   if (Date.now() > coupon.expireAt && !fetched) { await fetch('/api/coupon'); fetched = true; }
// }

// 重构后：决策纯函数 + 副作用薄层
export function couponPlan(coupon, now, fetched) {   // 纯：好测
  return coupon.expireAt < now && !fetched ? 'REFETCH' : 'KEEP';
}
export async function refreshCoupon({ coupon, now = Date.now(), fetched, doFetch = fetch }) {
  const plan = couponPlan(coupon, now, fetched);     // 决策与执行分离
  if (plan === 'REFETCH') await doFetch('/api/coupon');
}
// 测试：couponPlan 无任何 mock；refreshCoupon 注入 doFetch 假实现
```
