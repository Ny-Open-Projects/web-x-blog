## TST-136：笔试：为无限滚动列表写测试（IntersectionObserver mock + 分页续传）
**答**：
- 场景：列表滚到底部哨兵元素时加载下一页；测试要覆盖：首屏加载、滚动触发第二页、重复触发去重（加载中不重复请求）、没有更多页停止监听。
- 核心技巧：jsdom 没有 IntersectionObserver，需要 stub——捕获 callback，测试里手动触发 `callback([{ isIntersecting: true }])` 模拟滚动进入视口；jsdom 里 getBoundingClientRect 恒 0 反而让哨兵「天然相交」，所以 stub 必须可控。
- 去重断言：请求飞行中连续触发两次相交回调，只发一次请求（配合 MSW delay + 捕获数组）。

```jsx
// 测试 setup：可控的 IO stub
class IOStub {
  static instances = [];
  constructor(callback) { this.callback = callback; IOStub.instances.push(this); }
  observe(el) { this.el = el; }
  disconnect() {}
  trigger(isIntersecting) { this.callback([{ isIntersecting, target: this.el }]); }
}
beforeAll(() => { global.IntersectionObserver = IOStub; });
afterEach(() => { IOStub.instances = []; server.resetHandlers(); });

test('滚动加载第二页，加载中不重复请求', async () => {
  const requests = [];
  server.use(http.get('/api/goods', ({ request }) => {
    const page = new URL(request.url).searchParams.get('page');
    requests.push(page);
    return delay(100).then(() => HttpResponse.json({
      list: [{ id: page, name: `商品${page}` }],
      hasMore: page < 2,
    }));
  }));

  render(<InfiniteList />);
  await screen.findByText('商品1');                  // 首屏

  const io = IOStub.instances.at(-1);
  io.trigger(true);                                  // 进入视口 → 第二页
  io.trigger(true);                                  // 加载中再触发 → 应被去重
  await screen.findByText('商品2');
  expect(requests).toEqual(['1', '2']);              // 没有重复的 page=2

  io.trigger(true);                                  // hasMore=false 后再滚
  await vi.waitFor(() => expect(requests).toHaveLength(2)); // 不再请求
  expect(screen.getByText('没有更多了')).toBeInTheDocument();
});
```

**评分点**：
1. IO stub 设计：捕获 callback + 手动 trigger，测试可控（不是伪造恒相交）。
2. 覆盖去重（loading 中不重复请求）与 hasMore 终止两处边界。
3. 请求参数断言（page 序列）验证分页逻辑而非只看 UI。
4. stub 的 restore 不污染其他用例（beforeAll/afterEach 配对）。
