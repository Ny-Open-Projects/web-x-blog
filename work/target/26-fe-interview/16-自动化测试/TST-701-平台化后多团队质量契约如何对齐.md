## TST-701：平台化后多团队「质量契约」如何对齐：接口契约与质量 SLA 双轨制

**答**：
- 结论：平台化后要把「接口契约」（字段/结构/错误码）和「质量契约」（覆盖率、P95 反馈时长、误报率上限）分开定义，前者靠 schema，后者靠平台 SLA，双轨独立演进。
- 契约必须机器可读并存版本，CI 用 can-i-deploy 思路做兼容性判定，不靠口头约定。
- 跨团队冲突用「消费者驱动」解决：上游按下游用例集验证，避免各自为政。
- 追问钩子：下游团队 upgrade 了契约但上游还没发布，平台该放行还是卡住，谁说了算？

```javascript
// 双轨契约校验：结构契约 + 质量契约
function checkContract(actual, schema, quality, sla) {
  const missing = schema.required.filter(k => !(k in actual));
  const covOk = quality.coverage >= sla.minCoverage;
  const p95Ok = quality.p95Ms <= sla.maxP95Ms;
  return {
    schemaOk: missing.length === 0,
    qualityOk: covOk && p95Ok,
    deployable: missing.length === 0 && covOk && p95Ok,
  };
}
console.log(checkContract(
  { id: 1, name: 'a' },
  { required: ['id', 'name', 'price'] },
  { coverage: 0.82, p95Ms: 430 },
  { minCoverage: 0.8, maxP95Ms: 500 }
).deployable); // false：缺 price 字段
```
