## TST-059：遗留代码没有测试，怎么安全地补测试？
**答**：
- 先定性：遗留代码改不动往往因为「没测试 → 不敢改 → 更烂」，补测试是打破循环的起点，但目标是给「即将要改的部分」补，不是全量补。
- 步骤（Working Effectively with Legacy Code 的接缝思路）：① 找到本次要动的函数/模块；② 识别依赖副作用（网络/时间/全局变量）；③ 在「接缝」处提取接口或用 vi.mock 隔离外部依赖；④ 写特征测试（characterization test）：先断言「现状行为」锁住，不判断对错；⑤ 改代码后行为 diff 立刻可见。
- 手法：不能直接实例化的大泥球，先抽函数提为可导出单元（纯函数化），测试就有了落点；快照/特征测试做安全网，再逐步换成行为断言。
- 度量与门禁：新改动代码必须带测试（变更覆盖率门禁），存量豁免——让覆盖率随改动自然上涨而不是一次性刷数。
- 追问钩子：特征测试的坑——它会把 bug 也锁进快照，所以发现明显 bug 要先修再锁。

```javascript
// 遗留函数：副作用缠绕，没法直接测
// function submitOrder(form) {
//   if (Date.now() > window.PROMO_END) form.amount += window.LEGACY_FEE;
//   return http.post('/order', form);
// }

// 第 1 步：接缝提取——副作用全部变参数
export function calcOrderAmount(amount, { now = Date.now(), promoEnd = window?.PROMO_END ?? 0, fee = window?.LEGACY_FEE ?? 0 } = {}) {
  return now > promoEnd ? amount + fee : amount;   // 纯函数，可测
}

// 第 2 步：特征测试锁现状（不管对错，先锁住）
it('特征测试：活动结束后加旧手续费（现状行为）', () => {
  expect(calcOrderAmount(100, { now: 2000, promoEnd: 1000, fee: 5 })).toBe(105);
});
// 安全网建立后，才安全地重构（比如把 LEGACY_FEE 下线）——diff 会立刻暴露行为变化。
```
