## TST-163：微前端（qiankun/wujie）场景下测试怎么做？
**答**：
- 分层各管各的：子应用内部逻辑/组件 → 各仓库自己的单测（与普通应用无异）；主子应用之间的「契约」→ 集成测试管：生命周期挂载/卸载、全局状态共享、路由同步、公共依赖版本。
- 契约测试是核心：主应用假设子应用导出 `bootstrap/mount/unmount`、依赖共享的 `globalState` schema——写一份契约测试在子应用仓库跑（schema 校验 + 生命周期 mock 调用），主应用升级协议时契约测试第一时间暴露。
- E2E 层：整箱测试跑在「主应用 + 全部子应用」的真实组合上，验证跨应用链路（A 应用下单 → B 应用支付页）；痛点是环境编排成本（多个子应用要一起起）——用统一测试环境部署 or 本地 compose 脚本，Playwright 一个 entry 跑全链路。
- 特有坑：子应用 CSS 隔离（shadow DOM）影响选择器 → 用 Playwright 的穿透定位；qiankun 的沙箱导致 `window` 代理，测试里 stub 全局 API 时要打到对应沙箱；JS 沙箱下 localStorage 共享策略影响登录态复用。
- 追问钩子：子应用独立开发时怎么验证「装进主应用也能跑」？——契约测试 + 每夜整箱冒烟（standalone 模式测不了协议层）。

```javascript
// 子应用仓库：契约测试（每夜/主应用协议升级时跑）
import { schema } from '@org/qiankun-contract';

test('导出符合主应用契约', async () => {
  const app = await import('./main.ts');
  expect(Object.keys(app)).toEqual(
    expect.arrayContaining(['bootstrap', 'mount', 'unmount']));
  // 生命周期可被 mock 容器调用
  await app.bootstrap({ container: document.createElement('div') });
  await app.mount({ container: document.body, props: { token: 'x' } });
  await app.unmount();
});

test('共享状态 schema 兼容', () => {
  expect(() => schema.parse({ theme: 'dark', user: { id: 1 } })).not.toThrow();
});
```
