## TST-057：「测行为不测实现」具体怎么判断一条测试是否踩线？
**答**：
- 核心检验法：假设保持外部行为不变重写实现（换状态管理、改 DOM 结构、合并两个函数），这条测试还能全绿吗？不能 → 测了实现。
- 行为的定义：从「调用方/用户」视角可观察的东西——函数返回值、抛出的错误、页面显示的文案、点击后的可见变化、对外事件的参数。
- 实现细节的定义：内部函数调用顺序、私有方法、内部 state 命名、DOM 类名结构、渲染次数——这些用户不可见，也不在承诺范围。
- 例外：交互测试里「spy 回调被调用」算行为（回调就是对外契约）；但 spy「内部某个工具被调用」就是实现。
- 追问钩子：踩线的典型信号——mock 的东西是「自己写的模块」、断言对象是「内部 store 的中间字段」、重构后测试必改。

```javascript
// 检验示例：登录逻辑重构（fetch 改为 SDK），行为不变
// ❌ 实现级：测了内部方法与顺序
// expect(spyOn(auth, 'hashPassword')).toHaveBeenCalledBefore(spyOn(auth, 'requestToken'));

// ✅ 行为级：只断言对外契约
test('正确凭证 → 登录成功并携带用户信息', async () => {
  vi.mocked(api.login).mockResolvedValue({ token: 't', user: { name: '张三' } });
  render(<LoginPage />);
  await userEvent.type(screen.getByLabelText('账号'), 'a@b.c');
  await userEvent.type(screen.getByLabelText('密码'), 'pw');
  await userEvent.click(screen.getByRole('button', { name: '登录' }));

  expect(await screen.findByText('欢迎，张三')).toBeInTheDocument();
  expect(onLoginSuccess).toHaveBeenCalledWith('t');   // 对外回调 = 契约
});
// 现在把 fetch 换成任何 SDK，这条测试不需要动。
```
