## TST-197：大促/重大版本上线前的专项测试怎么组织？
**答**：
- 前提：日常门禁全绿只是及格线，大促要加四个专项——全链路演练、性能压测、弱网与故障注入、降级预案验证。
- 全链路演练：把「浏览→加购→支付→回调→履约」在预发环境按生产量级数据跑一遍 E2E 全集 + 真实账号人工走查；重点验证**跨服务边界**（支付回调、库存扣减、消息推送），这些是单测/E2E 日常覆盖最薄的。
- 故障注入（混沌思路）：用 page.route / 后端工具模拟——支付网关超时 30s、库存接口 500、WebSocket 断连、CDN 图片加载失败，验证每个故障都有对应降级 UI 和重试路径而不是白屏。预案「写在文档里」不算数，必须演练触发过。
- 性能专项：大促页（会场页）Lighthouse + 真机性能预算核验；图片按需加载、首屏接口并行度、长列表虚拟化在峰值数据量（1 万条）下的表现——用造数工具灌入极限数据跑断言。
- 时间维度的专项：活动开始/结束临界点（TST-176 的边界用例）、倒计时与服务端时钟对齐、跨日库存重置。
- 收口：演练问题清单 → 按风险分级 → 高风险阻塞上线，中风险配预案 + 监控告警 → 上线后灰度观察指标对齐预案。

```javascript
// 故障注入用例模板（大促专项）
const chaosScenarios = [
  ['支付网关超时', '**/api/pay', { delayMs: 30000 }, '支付处理中，请稍后查看订单'],
  ['库存接口 500', '**/api/stock', { status: 500 }, '库存查询失败，请重试'],
  ['WebSocket 断连', 'wss://im', { close: true }, '消息通道已断开，自动重连中'],
  ['CDN 图片失败', '**/img/**', { abort: true }, null], // 占位图兜底即可
];
for (const [name, pattern, inject, fallbackText] of chaosScenarios) {
  test(`故障演练: ${name}`, async ({ page }) => {
    await injectFault(page, pattern, inject);
    await page.goto('/seckill');
    if (fallbackText) await expect(page.getByText(fallbackText)).toBeVisible();
    await expect(page.locator('body')).not.toContainText('undefined'); // 无白屏
  });
}
```
