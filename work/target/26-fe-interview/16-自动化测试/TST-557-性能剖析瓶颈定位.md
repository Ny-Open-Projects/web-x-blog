## TST-557：性能剖析与瓶颈定位的方法论

**答**：
- 结论：先量化再优化——用 Performance 面板/火焰图定位「时间花在哪」，区分网络/脚本/渲染/布局，按影响面排序优化。
- 做法：录制性能 trace 找长任务与强制同步布局；用 Chrome DevTools Coverage 找未使用代码；bundle 分析（webpack-bundle-analyzer）找大依赖；优化后回归验证，避免凭直觉优化。
- 追问钩子：优化后指标没变怎么办？——可能优化了非瓶颈环节；回到火焰图确认该路径是否真的在主线程关键链路上，并用 A/B 对比验证。

```javascript
// 从性能条目中找耗时 Top N 的任务，聚焦优化目标
function topTasks(entries, n = 5) {
  return entries.filter(e => e.duration)
    .sort((a, b) => b.duration - a.duration)
    .slice(0, n)
    .map(e => ({ name: e.name || e.type, ms: Math.round(e.duration) }));
}
// 配合 PerformanceObserver 收集 longtask / measure 后调用
console.log(topTasks([{ name: 'render', duration: 120 }, { name: 'idle', duration: 5 }]));
console.log(topTasks([{ type: 'longtask', duration: 200 }, { name: 'x', duration: 80 }], 1)); // 只取最重的一个
```
