## TST-716：测试平台的高可用架构如何设计：从单机到多活

**答**：
- 结论：演进路径是「单机 → 主备 → 异地多活」，核心是把无状态控制面与有状态执行面分离，状态外置到共享存储。
- 控制面（API/调度）无状态可水平扩；执行面按地域就近调度，结果写共享对象存储。
- 多活要解决冲突：用租约（lease）保证同一任务只被一个执行器领取，避免重复跑。
- 追问钩子：多活切换时两个地域都认为自己是主，如何避免脑裂？

```javascript
// 基于租约的任务领取，防止多活重复执行
class LeaseQueue {
  constructor() { this.leases = new Map(); }
  claim(taskId, worker, now, ttl) {
    const cur = this.leases.get(taskId);
    if (cur && cur.until > now && cur.worker !== worker) return false;
    this.leases.set(taskId, { worker, until: now + ttl });
    return true;
  }
  renew(taskId, worker, now, ttl) {
    const cur = this.leases.get(taskId);
    if (!cur || cur.worker !== worker) return false;
    cur.until = now + ttl;
    return true;
  }
}
const q = new LeaseQueue();
console.log(q.claim('t1', 'w1', 0, 5000));   // true
console.log(q.claim('t1', 'w2', 100, 5000)); // false，租约未过期
```
