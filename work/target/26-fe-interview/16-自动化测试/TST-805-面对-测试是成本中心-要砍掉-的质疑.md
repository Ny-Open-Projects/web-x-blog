## TST-805：面对「测试是成本中心，要砍掉」的质疑，测试架构师如何用数据反驳？
**答**：
- 结论：不要用「覆盖率 85%」防守，要用「缺陷逃逸率、变更失败率、线上事故损失」把质量翻译成钱和风险。
- 把测试价值货币化：一次 P0 逃逸事故的平均损失 × 减少的事故数 = 测试避免的损失，与测试人力成本做 ROI 对比（呼应 ROI 模型）。
- 用反事实实验：选两个相似业务线，一个加强测试一个不加强，对比线上缺陷密度，用数据而非口号说话。
- 姿态：承认测试确实有成本，主动优化「低效用例/重复执行」，用「花得更省」换取「砍得更少」的信任。
- 追问钩子：如果 CFO 坚持「线上事故损失是估算的，不可信」，你退一步该拿什么硬指标继续沟通？

```javascript
// 把质量翻译成钱：一次反驳发言的数据骨架
const makeBusinessCase = ({ testCost, escapesBefore, escapesAfter, p0Loss }) => {
  const reduced = escapesBefore - escapesAfter;
  const saved = reduced * p0Loss;
  return {
    测试年成本: testCost,
    减少的P0事故: reduced,
    避免损失: saved,
    ROI: Number(((saved - testCost) / testCost).toFixed(2)),
    结论: saved > testCost ? '测试是利润中心而非成本中心' : '需先优化测试效率',
  };
};
console.log(makeBusinessCase({
  testCost: 1_500_000, escapesBefore: 12, escapesAfter: 4, p0Loss: 400_000
})); // 避免 320 万，ROI ≈ 1.13
```
