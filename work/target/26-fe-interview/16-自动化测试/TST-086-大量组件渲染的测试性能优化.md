## TST-086：组件测试跑得慢怎么优化？
**答**：
- 找瓶颈先看三类：环境创建（每个文件新建 jsdom）、转换编译、用例内重渲染。用 `vitest --reporter=verbose` 看文件级耗时分布。
- 环境层：纯逻辑测试文件降级 node 环境（environmentMatchGlobs）；pool 选 threads（CPU 密集）或 forks（更稳）；限制 maxWorkers 避免超额订阅。
- 用例层：砍掉「渲染巨型组件只为断言一个小文案」的用例，下沉为纯函数测试；列表测试数据从 1000 行砍到 3 行（行为等价）；避免不必要的 rerender 链。
- 工程层：CI 缓存 Vite transform 缓存（node_modules/.vite 缓存目录）；`--changed` 只跑受影响文件；sharding 分片并行。
- 追问钩子：先测再优——多数「测试慢」根因是把本该单测的逻辑写成了全组件渲染集成测试。

```typescript
// vitest.config.ts 性能相关配置
export default defineConfig({
  test: {
    pool: 'threads',
    maxWorkers: '50%',
    environmentMatchGlobs: [
      ['**/utils/**/*.test.ts', 'node'],    // 纯逻辑不开 jsdom
    ],
    css: false,                             // 跳过 CSS 解析
  },
});
// CI：npx vitest run --changed=origin/main  # 只跑受影响测试
```
