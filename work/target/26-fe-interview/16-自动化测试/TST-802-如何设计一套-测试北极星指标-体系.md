## TST-802：如何设计一套「测试北极星指标」体系，避免团队陷入唯覆盖率论？
**答**：
- 结论：覆盖率是「手段指标」，北极星应是「单位时间内流向用户的缺陷数」这类结果指标，覆盖率只做诊断不做考核。
- 北极星候选：缺陷逃逸率（线上缺陷/总缺陷）、变更失败率、平均恢复时间(MTTR)、测试反馈时长——直接对齐业务质量结果。
- 配套护栏指标：覆盖率、flaky 率、用例有效率（发现缺陷的用例占比）作为过程诊断，防止为覆盖率写「断言空气」的假测试。
- 反模式：把覆盖率当 KPI 会导致「为覆盖而覆盖」——大量 expect(true).toBe(true) 式用例，数字好看但零价值。
- 追问钩子：如果产品说「这个季度覆盖率从 70% 涨到 90% 但线上 bug 没少」，你如何解释这组矛盾数据？

```javascript
// 北极星指标看板的数据聚合（示意）
const buildQualityDashboard = (bugs, changes, tests) => ({
  northStar: {
    escapeRate: bugs.prod / (bugs.prod + bugs.test),      // 缺陷逃逸率
    changeFailRate: changes.failed / changes.total,       // 变更失败率
  },
  guardrails: {
    coverage: tests.coveredLines / tests.totalLines,      // 仅诊断，不考核
    flakyRate: tests.flaky / tests.total,
    effectiveRate: tests.caughtBugs / tests.total,        // 用例有效率
  },
});
const d = buildQualityDashboard(
  { prod: 5, test: 95 }, { failed: 3, total: 100 },
  { coveredLines: 9000, totalLines: 10000, flaky: 12, total: 1200, caughtBugs: 60 }
);
console.log(d.northStar.escapeRate, d.guardrails.coverage); // 0.05 0.9
```
