## TST-980：缓存能大幅提速测试，但缓存失效带来的「假绿」怎么防？
**答**：
- 结论：缓存键必须包含「影响结果的所有输入」——代码版本、依赖版本、环境变量、测试数据版本，缺一项就可能用旧结果骗过本次构建。
- 做法：用内容哈希（git sha + lockfile hash + env hash）做 key；命中缓存仍跑「冒烟子集」验证缓存有效性。
- 分层：依赖安装可安全缓存，测试结果缓存需谨慎（只缓存稳定通过的纯函数测试）。
- 追问钩子：CI 命中缓存后测试全绿，但线上出现回归，你怀疑缓存用了旧结果，怎么快速验证？

```javascript
import { createHash } from 'crypto';
function cacheKey({ gitSha, lockHash, envHash, testContentHash }) {
  return createHash('sha256')
    .update([gitSha, lockHash, envHash, testContentHash].join('|'))
    .digest('hex').slice(0, 16);
}
const key = cacheKey({
  gitSha: 'abc123', lockHash: 'lock-v2', envHash: 'env-prod',
  testContentHash: 't-hash',
});
// 命中缓存后：仍跑冒烟子集验证
async function useCacheWithSmoke(cache, key, smokeTests) {
  if (cache.has(key)) {
    const smoke = await Promise.all(smokeTests.map(t => t()));
    if (smoke.every(Boolean)) return { fromCache: true, verified: true };
    cache.delete(key); // 冒烟失败 → 缓存失效，重跑
  }
  return { fromCache: false };
}
```
