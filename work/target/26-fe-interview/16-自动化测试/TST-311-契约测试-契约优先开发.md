## TST-311：「契约优先」开发流程如何落地？
**答**：
- 先评审契约 PR（schema 变更）→ 双端从契约生成代码/类型/mock → 并行开发 → 契约验证收口。
- 前端不等后端：契约 mock server 先行开发与测试。
- 后端 TDD 对齐：schema 即验收标准（provider 测试直接消费契约）。
- 流程卡点：PR 模板要求「变更先过契约 PR 链接」。

```javascript
契约 PR → schema 合并 → 生成: 前端类型+mock server / 后端接口骨架
  → 并行开发 → 双端契约验证 → can-i-deploy → 发布
r
```
