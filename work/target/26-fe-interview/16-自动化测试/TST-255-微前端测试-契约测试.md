## TST-255：微应用间「共享状态/API」如何用契约测试守住？
**答**：
- 共享契约显式化：跨应用调用的接口/事件/存储 key 定义为 contract 包，双方依赖同一定义。
- 消费者驱动：子应用测试验证「我按契约调」，主应用 provider 测试验证「我按契约供」。
- Pact/broker 集中校验：发布前验证 provider 满足所有 consumer 期望。
- 契约变更流程：先改契约包发新版本 → 双方适配 → 集成套件验证 → 灰度。

```javascript
// 契约定义（双方共享）
export interface TradeContract {
  getOrder(id: string): Promise<{ id: string; status: 'paid' | 'pending' }>;
  onOrderPaid(cb: (id: string) => void): () => void;
}
// provider 测试：主应用实现满足契约
expectTypeOf(mainApp satisfies TradeContract);
```
