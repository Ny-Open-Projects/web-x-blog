## TST-088：虚拟列表（虚拟滚动）组件怎么测？
**答**：
- 特殊性：DOM 只渲染可视区条目——「第 100 项」根本不在 DOM 里，按全量列表的思路测必然失败；且可视区高度依赖 getBoundingClientRect，jsdom 全是 0，需要 mock。
- 分层测：① 虚拟化逻辑单独抽成纯函数/ hook（visibleRange(scrollTop, itemH, viewport)）单测——这是核心可测资产；② 组件层 mock 尺寸（getBoundingClientRect/spyOn offsetHeight），断言「只渲染了 N 条」；③ 行为测滚动到底触发加载（IntersectionObserver mock 回调）。
- 断言面：初始渲染条数 = ceil(viewport/itemH)；scrollTop 变化后窗口滑动；overscan 余量。
- 追问钩子：jsdom 没有布局引擎，一切依赖真实尺寸的行为都必须 mock 或下沉到纯函数——这决定虚拟列表测试的设计。

```jsx
// ① 核心逻辑抽纯函数（最值得测的部分）
export function visibleRange({ scrollTop, viewportH, itemH, count, overscan = 3 }) {
  const start = Math.max(0, Math.floor(scrollTop / itemH) - overscan);
  const end = Math.min(count, Math.ceil((scrollTop + viewportH) / itemH) + overscan);
  return { start, end };
}
test('滚动到 1000px 视口 500px 行高 50px', () => {
  expect(visibleRange({ scrollTop: 1000, viewportH: 500, itemH: 50, count: 1000 }))
    .toEqual({ start: 17, end: 33 });   // 20-3 ~ 30+3
});

// ② 组件层 mock 尺寸
beforeEach(() => {
  vi.spyOn(HTMLElement.prototype, 'getBoundingClientRect').mockReturnValue({ height: 500, ... } as any);
});
test('只渲染可视区条目', () => {
  render(<VirtualList count={1000} itemHeight={50} viewportHeight={500} />);
  expect(screen.getAllByRole('listitem').length).toBeLessThan(40);
});
```
