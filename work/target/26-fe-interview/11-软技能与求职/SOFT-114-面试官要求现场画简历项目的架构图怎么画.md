## SOFT-114：面试官说"把这个项目架构画一下"，现场怎么画才像真正做过的人？

**答**：
- 先问清粒度（"您想看整体部署架构还是前端内部模块？"），答非所问的图等于没画。
- 画图顺序即思维展示：从请求链路画起（用户 → CDN → 网关 → BFF → 服务），再补前端内部分层，最后标注你负责的边界——虚线框住自己的地盘。
- 图上必须出现"痛点标注"：在真实踩坑的位置画个标记（"这里曾出过 XX 问题"），真做过的人图上全是伤疤。
- 一边画一边解说，沉默画 3 分钟是大忌；画完主动问"这个视角 OK 吗，还是想看 XX 部分？"

```text
现场画图三段式（以中台前端为例）：
第 1 层 接入：CDN → Nginx → 网关（标注：鉴权在这里，
       曾出过 token 续期并发问题 ←痛点标记）
第 2 层 应用：BFF(Node) ←标注我负责→ 微应用×3（qiankun）
       （标注：样式隔离曾踩坑 ←痛点标记）
第 3 层 数据：服务端 API / WS 推送
边界标注：虚线框住"前端侧，3 人，我负责 BFF + 主应用"

解说词节奏：每层 30~45 秒，先说"这层解决什么问题"
再说"怎么实现的"，最后抛痛点钩子。
```
