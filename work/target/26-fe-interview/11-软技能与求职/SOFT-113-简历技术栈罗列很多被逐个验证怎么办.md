## SOFT-113：简历技能栏罗列了十几个技术栈，被逐个验证怎么避免"广度翻车"？

**答**：
- 技能栏只写三类：生产环境用过（可写）、系统学过并有 side project（可写但要标注）、只看过文档（不写）——第三类写了就是送人头。
- 用"熟练度分级"给面试官引导：精通/熟悉/了解分层罗列，并在"了解"类主动降预期。
- 被问到"了解"级别的技术时，答"原理层的理解 + 我没在生产用过"即可，主动圈定边界比装熟安全。
- 精简版技能栏（8~12 项）比大而全（20+ 项）通过率高：每一项都可能变成深挖入口，入口越多破绽越多。

```text
技能栏分级模板：
精通：{Vue3 / TypeScript / Webpack}（生产 2 年+，可讲原理）
熟悉：{React / Node / Docker}（生产用过，原理层可答）
了解：{Rust / WebGL}（side project 级别，无生产经验）

被问到"了解"级技术：
"这个我在 {side project} 里用过，工程上 {细节}；
但生产场景的坑我还没踩过，原理层面我可以聊聊 {X}。"

红线：任何"精通"标签 = 面试官有权利问到底层原理。
不准备被问到底的，写"熟悉"。
```
