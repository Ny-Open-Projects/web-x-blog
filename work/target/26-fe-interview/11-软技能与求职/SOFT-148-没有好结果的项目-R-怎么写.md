## SOFT-148：项目没有拿得出手的结果，STAR 的 R 怎么写？

**答**:
- R 不只有"业务成功"一种：过程性结果（交付了可复用资产）、验证性结果（证伪了一条路，避免更大浪费）、能力性结果（团队获得了什么机制）都是合法 R。
- 结果降级路线：核心指标没动 → 看过程指标（效率/质量/稳定性）；过程指标也没有 → 看资产沉淀（代码/文档/工具被后续使用）；还没有 → 讲教训型 R（配 STARL）。
- 诚实红线：不能把团队其他线的成果挪来凑 R；面试官一句"这个数字和你 action 的因果关系是什么"就穿了。
- R 的底线要求：必须有至少一个"如果没有你这件事，就不会有 X"的陈述——因果句是 R 的灵魂。

```text
R 降级路线（逐级往下找）：
L1 业务指标：{转化率/留存/收入}——没有
L2 过程指标：{开发工时/bug 率/接入成本}——找这个
L3 资产沉淀：{可复用模块被 N 个项目引用/文档被采纳为准}
L4 教训资产：{证伪 X 方案，后续项目避开了，
   配 Learning 讲}

因果句模板（必须）：
"如果没有 {我的 action：统一配置协议}，
就不会有 {L3 结果：新业务接入从 3 人日降到 0.5 人日}。"
```
