## SOFT-346：Code Review 礼仪——意见表达与被 review 的心态？

**答**:
- 提意见三原则：对代码不对人（"这里可能有 X 问题"不是"你怎么又犯这个错"）、给理由或链接（规范/文档/案例）、分优先级（"必须改"vs"建议"vs"个人偏好"标清楚——把偏好说成必须是最伤协作的行为）。
- 被 review 的心态：别人花时间看你的代码是免费咨询——快速回应、有分歧展开讨论而不是防御、改完致谢——review 循环的速度决定团队代码质量。
- review 的范围纪律：只看该看的（逻辑/边界/可维护性），不借 review 推销个人风格偏好——风格统一交给 lint 工具管。
- 借力技巧：大型设计问题提前私聊（SOFT-344 会前预沟通），不要让人在 review 里第一次看到你的架构决策。

```text
CR 三原则：
1 对代码不对人
2 意见带理由/链接
3 分优先级：必须改 / 建议 / 个人偏好
  （偏好说成必须 = 最伤协作）
被 review：快回应 / 分歧展开不防御 /
  改完致谢——review 循环速度 = 代码质量。
范围：逻辑/边界/可维护性；
  风格交给 lint。
大改先私聊，别让人在 CR 首见架构。
```
