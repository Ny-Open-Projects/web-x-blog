## SOFT-138：跨团队协作项目被深挖"协作摩擦怎么处理的"，怎么讲？

**答**：
- 摩擦叙事三要素：具体摩擦源（接口变更无通知、优先级冲突、标准不一致）+ 机制化解决（不是靠吵架）+ 关系未受损的收尾——展示的是"建机制"能力。
- 解决方案升级序：先沟通对齐 → 沟通无效上机制（契约文档、联合 review、同步会议）→ 机制再无效升级到共同上级——逐级升级是有分寸感的标志。
- 讲清摩擦里"我方的问题"：跨团队矛盾单方叙事必被怀疑，主动认领自己一侧的改进（"我们接口文档滞后也是原因"）。
- 收尾量化协作改进：如"接口变更提前率从 30% 到 95%，联调期缩短一半"。

```text
摩擦叙事模板：
摩擦源：{后端团队接口变更不通知，前端 3 次返工}
我方认领："我们文档滞后、没有订阅机制，各占一半责任。"
解决升级：
  1v1 对齐 → 没根治
  → 机制：接口契约入 git，变更走 PR + @前端 reviewer
  → 效果：变更提前率 30%→95%
关系收尾："后来他们主动拉我们评审他们的 API 设计，
  摩擦变成了例行协作。"

红线：不指名道姓骂对方团队；
不讲"最后领导拍板"式的上交矛盾（除非真是终局手段）。
```
