## SOFT-499：手写三分钟口头汇报脚本——完整版 + 30 秒被打断降级版？

**需求与边界**：
- 场景：会上被点名汇报项目进展，可能被打断（"说重点"）。
- 边界要求：① 完整版三段（结论 30s/细节 90s/风险需求 60s）；② 必须内置 30 秒降级版（结论+风险+需求一句话）；③ 全部用数字不用形容词。

**答**（汇报脚本）:
```javascript
function buildReport(p) {
  const full = [
    // 30s 结论：进展+风险总述
    `项目 __ 目前完成 ${p.percent}%，` +
    `${p.risk ? `有一个风险：${p.risk.brief}` : '无风险'}。`,
    // 90s 细节：数字优先 ×2~3
    `已上线 __（指标 __）；联调剩 ${p.days} 天；` +
    `bug ${p.bugs} 个已清零。`,
    // 60s 风险+需求+下一步（风险永远带方案）
    p.risk ? `风险 ${p.risk.desc}，我的方案是 ${p.risk.plan}，` +
      `需要 ${p.risk.support}。下一步 ${p.next}。`
      : `下一步 ${p.next}。`,
  ].join('');
  // 30s 降级版：被打断时一句话收束
  const brief = `${p.percent}%，` +
    `${p.risk ? `风险 ${p.risk.brief}，方案 ${p.risk.plan}，` : '无风险，'}` +
    `需要 ${p.risk?.support || '无'}。细节会后书发群里。`;
  return { full, brief };
}
// 自检：percent/days/bugs 为数字类型（禁形容词）；
// risk 必须同时带 plan 与 support（只抛问题=扣分项）；
// 降级版保结论+风险+需求三要素，即被中途打断也完成有效汇报。
```

**评分点**:
- 完整版三段时长结构正确（30/90/60），结论先行且风险带方案与需求。
- 内置 30 秒降级版，被打断仍能完成有效汇报（保三要素：进展/风险/需求）。
- 数字化纪律落实（percent 为数字而非形容词），报告可被上层转述。
- "细节会后书发群里"的兜底动作，体现书面留痕意识。
