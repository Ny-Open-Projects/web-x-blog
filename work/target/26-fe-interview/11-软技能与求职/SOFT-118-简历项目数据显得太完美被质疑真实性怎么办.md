## SOFT-118：简历上项目成果"每项都成功、数据都漂亮"，被质疑"太顺利了吧"怎么破？

**答**：
- 全绿简历本身就是减分项：真实的工程必然有失败与返工，主动在叙述里放一个"搞砸后修复"的故事，可信度反而暴涨。
- 被问"太顺利了吧"时的正确反应：承认 + 补充挫折面："指标达成用了两轮，第一版方案 {X} 上线后反弹，后来定位到 {原因} 才改稳。"
- 数据里掺入"负向数据"：如"崩溃率降到 0.1%，但为此放弃了 XX 特性"，有取舍的数据比单向胜利的数据真实十倍。
- 面试前为每个王牌项目准备一条"失败线"：一次事故、一次返工、一次被否的方案——深挖时按需释放。

```text
挫折线素材卡（每个王牌项目备一条）：
事故：{上线当天 XX 报错率飙升}
定位：{怎么发现的 → 排查了哪些假设 → 真因是什么}
修复：{止血动作 + 根治动作 + 耗时}
沉淀：{后来加了什么机制防复发}

"太顺利"应答模板：
"没有很顺利，{核心指标} 第一轮只到 {a}，我们发现
{问题}，回滚后改成 {方案} 第二轮才达标。
过程中最大的一次 {事故/返工} 是 {素材卡摘要}。"
```

**边界与易错**：

- 主动讲失败要有分寸：讲成"失败也很成功"的凡尔赛式反思比不讲更糟，失败必须真有代价。
- 负向数据不能编，为了显得真实随手造一个"放弃了某个特性"，被追问取舍原因就崩。
- 不是每个项目都要配失败线，王牌项目一两条足够，讲太多失败会让人怀疑你的基本判断力。

**追问**：

1. 你说第一版方案失败了，当时为什么没人提前发现，你的判断力体现在哪？ → 要讲清当时的信息局限与决策依据，再给出"现在会怎么更早验证"的具体动作，比如先灰度一城、先挂指标看板。
2. 如果面试官顺着失败故事质疑你的技术判断，你怎么接？ → 区分"当时约束下的最优解"和"现在的最优解"，承认局限但不否定当时的决策逻辑，也别急着甩锅给他人。
3. 在强势的面试官面前暴露挫折，会不会变成把柄？ → 会，所以失败故事只选结果可控、后来确实解决的，还在悬着的坑别拿去讲。
