## SOFT-134：简历项目被问"你走了谁接得住"，考察可持续性的问题怎么答？

**答**：
- 这题考的是"你 build 的是系统还是个人英雄主义"：核心答案是有无"离开你也转得动"的机制——文档、模块化、梯队、自动化。
- 讲交接资产四件套：架构文档（决策记录 ADR）、代码可读性（命名/注释/目录约定）、on-call 手册（常见故障与排查路径）、梯队（至少一人能独立处理 P1 问题）。
- 讲一个真实交接案例最有力：你离职/轮岗/休假期间项目怎么运转的，暴露过什么坑、后来补了什么。
- 红线："项目离了我不行"——听起来是炫耀，实际是架构与管理双不合格。

```text
可持续性资产清单（逐条对照自己的项目）：
[ ] ADR：关键决策有"为什么"记录，不只是"是什么"
[ ] 上手路径：新人 3 天能本地跑起 + 发第一个改动
[ ] 故障手册：Top10 常见问题有排查路径
[ ] 梯队：{同事 X} 能独立处理 P1/P2 故障
[ ] 关键配置/权限：不止我一个人有

交接案例话术：
"我休假两周时项目由 {X} 值守，期间 {事故} 他自己
按手册定位到 {层}——暴露的问题是 {手册缺了 XX}，
回来我补了。这算一次免费的演练。"
```
