## SOFT-430：出了线上故障后怎么处理协作关系——不甩锅的复盘姿态？

**答**:
- 止血优先：故障期只做止血与同步（谁在修/预计时间/影响面），责任讨论留到复盘会——故障现场争"是谁的锅"只会拖慢恢复。
- 复盘姿态：对自己环节的问题主动认领（"我的变更没考虑 __ 场景"），对流程问题提机制改进（加卡点/加监控/改流程）而不是对人指责——好的复盘产出物是流程改进项，不是责任认定书。
- 修复信任的三个动作：48 小时内给出改进项落地进度、主动同步修复验证结果、下次同类变更带着新卡点上线——信任靠动作重建不靠道歉。
- 面试转化：故障经历是高分素材（SOFT-021 失败题），按"影响→止血→根因→机制改进→结果"讲，展示的是工程成熟度。

```text
故障协作 SOP：
现场：止血 + 每 30min 同步进展
  （"已定位到 __，预计 __ 恢复"）
复盘会：时间线 → 根因 → 改进项
  改进项格式：动作 + 负责人 + DDL
  红线：只对流程不对人
信任修复：48h 内改进项落地进度同步
  → 修复验证结果 → 下次变更带新卡点
面试叙事：影响 → 止血 → 根因 →
  机制改进 → 后续 0 复发。
```
