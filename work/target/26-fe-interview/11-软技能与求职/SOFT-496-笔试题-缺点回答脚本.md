## SOFT-496：手写"你最大的缺点是什么"回答脚本——真实、有改进闭环、有防御？

**需求与边界**：
- 场景：技术面/HR 面被问最大缺点，以及追问"这个缺点影响过工作吗""改进了吗"。
- 边界要求：① 缺点必须真实（伪缺点"太追求完美"直接减分）；② 不能是岗位核心能力（投前端不能说"写代码慢"）；③ 必须带改进机制与阶段性证据。

**答**（缺点回答脚本）:
```javascript
const weaknessScript = {
  pick: // 选点：真实 + 非核心能力 + 与岗位兼容
    { weakness: '当众表达的紧张感',
      whySafe: '前端岗核心是工程与协作，表达是加分项非生死项',
      whyReal: '真实存在：第一次跨团队评审时我讲方案超过时长且被打断两次' },
  script: // 三段式：承认 + 具体事例 + 改进闭环
    `我的缺点是当众表达容易紧张。具体例子：__（真实事件）。` +
    `我意识到后做了两件事：一是每次重要汇报前写逐字稿并计时彩排；` +
    `二是主动申请了 __ 次内部分享练手感。现在 __（阶段性证据：` +
    `最近一次述职正常完成/反馈 __）。还在继续练，但已经有可控的进步。`,
  defense: {
    q1_impact: '影响过 __（小场景），通过 __ 方式绕开/缓解了',
    q2_fixed: '不会完全消失但已可控，证据是 __——我看重的是趋势',
  },
  ban: // 红线
    ['伪缺点（追求完美/太拼）', '岗位核心能力（写码慢/不爱学新东西）',
     '无改进闭环的裸缺点', '人格化缺点（情绪化/不靠谱）'],
};
// 自检：真实事例+改进机制+阶段证据三要素齐；
// 缺点与岗位兼容；两个追问有防御。
```

**评分点**:
- 三段式结构完整：承认+真实事例+改进闭环，符合"缺点要有证据链"的考察逻辑。
- 缺点选点安全：真实但非岗位核心能力，附 whySafe 说明。
- 两个追问方向（影响/改进效果）都有防御答法，且有阶段性证据而非空头承诺。
- 红线清单完整：识别伪缺点、核心能力缺点、人格化缺点三大雷区。
