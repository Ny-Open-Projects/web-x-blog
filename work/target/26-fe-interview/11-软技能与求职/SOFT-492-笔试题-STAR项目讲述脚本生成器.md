## SOFT-492：手写一个 STAR 项目讲述脚本——60 秒版 + 追问防御点？

**需求与边界**：
- 输入：一个真实项目的 STAR 四要素；输出：60 秒口播脚本 + 每个要素标注"面试官最可能追问的方向及防御答法"。
- 边界要求：① S 必须含可量化影响（影响多少用户/多少收入）；② R 必须有数字且有归因说明（哪些是自己的贡献）；③ 全程不出现"我们团队"糊掉个人贡献。

**答**（讲述脚本 + 追问防御）:
```javascript
/**
 * STAR 项目讲述脚本生成器
 */
function buildSTAR(p) {
  // S：背景+量化影响（10s）
  const S = `当时${p.context}，业务上${p.impact}`;   // impact 例：日活 50w 的下单转化掉到 __%
  // T：我的目标与约束（10s）
  const T = `我负责${p.task}，约束是${p.constraint}`; // 约束例：不能停服、两周内交付
  // A：关键动作×2 + 取舍（25s）——讲决策不讲流水账
  const A = `我做了两件事：一是${p.action1}（因为${p.reason1}）；` +
    `二是${p.action2}（对比过${p.alternative}，选它的原因是${p.reason2}）`;
  // R：量化结果+个人归因（15s）
  const R = `最终${p.result}，其中${p.myPart}是我直接负责的部分`;
  return { script: [S, T, A, R].join('。') + '。', defense: {
    S: '为什么指标掉？→ 准备根因一句话',
    A: '为什么不用别的方案？→ alternative 与 reason2 已备',
    R: '这数字怎么归因到你？→ myPart 明确切分个人贡献',
  }};
}
// 自检：60s 内可讲完；每个追问方向有书面防御答法；
// R 的数字附归因切分，不贪功不虚报。
```

**评分点**:
- STAR 四段时长分配合理（10/10/25/15），A 段讲决策与取舍而非流水账。
- S 有量化影响、R 有数字且带个人贡献归因切分，符合诚信与表达双重要求。
- 附有三个方向的追问防御答法，脚本经得起深挖。
- 全程无"都是我们做的"式模糊归因，也无贬低协作方的表述。
