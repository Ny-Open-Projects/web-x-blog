## SOFT-448：PR 卡在 Code Review 没人理怎么推进——异步评审的规则？

**答**:
- 自查先行：卡 review 先自查 PR 质量（小步提交/描述含测试方式/自测已过/关联需求链接）——大多数"没人理"的 PR 是大而难读，评审成本过高被无限延后。
- 推进阶梯：24h 无响应群里礼貌提醒 → 指定人定向请求（找业务相关者而非随便抓人）→ 超两天影响联调则升级 leader 协调——推进有梯度，不越级抱怨。
- 评审规则共建：推动团队约定 SLA（如 24h 内给首次反馈）与大小上限（单 PR ≤400 行），机制解决比人催人可持续。
- 意见处理：意见分歧点到为止（各自书面陈述一次），争而不决线下 15 分钟或拉架构师裁决，PR 不无限拉锯。

```text
PR 卡关推进阶梯：
自查：≤400 行？描述含测试方式？
  自测过？关联需求链接？→ 补齐再催
24h 无响应 → 群里提醒（贴 PR 链接）
48h → 定向 @ 业务相关者
影响联调 → 升级 leader 协调
团队机制：review SLA 24h + PR 大小上限
分歧：书面各陈一次 → 线下 15min
  或拉架构师裁决，不无限拉锯。
```
