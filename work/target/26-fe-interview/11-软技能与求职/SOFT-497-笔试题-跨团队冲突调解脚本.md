## SOFT-497：手写一份跨团队冲突调解脚本——从立场对抗走到利益共识？

**需求与边界**：
- 场景：前端与后端就"接口是否提前两天交付"僵持，影响联调窗口；脚本需覆盖：开场、立场转利益、选项提案、升级裁决四个阶段。
- 边界要求：① 全程基于事实与数据，无指责性语言；② 给出 ≥2 个可选项（让对方有选择空间）；③ 明确升级条件与升级方式。

**答**（调解脚本）:
```javascript
const mediateScript = {
  facts: // 事实底账（先备后谈）
    { timeline: '接口原定 __ 日', dependency: '前端联调窗口 __ 日-__ 日',
      history: '近 3 次压缩联调各产生 __ 个线上问题（数据筹码）' },
  steps: [
    { stage: '开场（私下）', say:
      '想跟你对齐下 __ 的排期，两边都有压力，先看看有没有双赢的走法。' }, // 不定罪
    { stage: '立场转利益', say:
      '我的核心诉求是联调窗口不被压缩（否则上线质量风险 __）；' +
      '你们的约束是什么？也许我们的约束不冲突。' }, // 把对抗变互探
    { stage: '选项提案', say:
      '几个选项：A 接口提前 2 天，我们配合先做单侧自测回报你们 bug；' +
      'B 接口按时，我们先用契约 mock 联调，__ 日再切真；' +
      'C 砍掉本期 __ 功能，减小依赖面。你看哪个可行？' },
    { stage: '升级裁决', when: '两轮无进展且 deadline 逼近', say:
      '我建议把这个同步给双方 leader（只摆事实和选项，不带立场），' +
      '让他们排优先级——我们的分歧其实是优先级问题。' },
  ],
  bans: ['当面指责', '群发施压', '不带事实的情绪表达'],
};
// 自检：四阶段齐；≥2 选项；升级有条件有方式；
// 全程事实化，无"你们后端总是"式指责。
```

**评分点**:
- 四阶段完整（开场→利益→选项→升级），立场转利益的表述正确（"我的约束是什么/你们的呢"）。
- 选项式提案 ≥2 且含降级方案（契约 mock/砍功能），给对方真实选择空间。
- 升级有明确触发条件（两轮无进展+deadline 逼近）与升级方式（摆事实不带立场）。
- 事实底账前置（时间线+历史数据筹码），全程无指责性语言，冲突不升级为人际对立。
