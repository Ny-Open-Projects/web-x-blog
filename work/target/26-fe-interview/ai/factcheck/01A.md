| JS-092-什么是微任务风暴无限-then-链为什么会饿死渲.md | `processInChunks(Array(1e6).keys(), (i) =>` | `Array(1e6).keys()` 返回的是 **Array Iterator**，没有 `length`/`slice`。`for (let i = 0; i < list.length; ...)` 中 `i < undefined` 恒为 false，循环体一次都不执行，示例静默失效（切片分片完全没跑）。 | 改为 `processInChunks([...Array(1e6).keys()], (i) => { /* 重计算 */ }, 10000);` |
| JS-345-Promise实现原理-then链与状态机.md | `const adopt = (x) => x instanceof MyPromise` | `resolve` 里定义了 `adopt` 却**从未调用**，函数体结束后直接闭合。结果 `resolve(v)` 是空操作：promise 永远不会 fulfilled，`then` 注册的回调永不执行，整个 MyPromise 无法工作。 | 在该箭头函数赋值语句后补一行调用：`const adopt = (x) => ...; adopt(v);`（即 `...this.#flush());` 之后、`};` 之前加 `adopt(v);`） |
| JS-374-可暂停Promise与生成器调度.md | `resume() { const p = gate; gate = Promise.resolve();` | `resume()` 把 gate 换成**已 resolve** 的 Promise，恢复后再次 `await g.wait()` 会直接穿过，暂停点永久失效——正是本卡追问 1 所说的错误（"否则恢复后马上再进 wait() 会 await 已 resolve 的旧 Promise 直接穿过去"）。代码与追问自相矛盾。 | `wait()` 每次新建 gate，`resume()` 只释放旧 gate：<br>`async wait() { gate = new Promise(r => (release = r)); await gate; },`<br>`resume() { release(); },`<br>`pause() { /* wait 已重建 gate，无需额外处理 */ },` |
| H5-371-移动端埋点SDK设计-采集-缓存-上报.md | `seq: ++this.seq` | 构造函数只初始化了 `q` 和 `max`，没有 `this.seq`/`this.dropped`。`++undefined` → `NaN`：**每条事件的 seq 都是 NaN**，服务端按 seq 去重、以及追问 3 说的"seq 连续性识别缺口"全部失效；`this.dropped++` 也是 NaN，丢弃率永远统计不到。 | 构造函数内补两行：`this.seq = 0; this.dropped = 0;`（放在 `this.q = [];` 同一行后） |
| TS-033-泛型类怎么写有什么典型用途.md | 随后 `enqueue(1)` 直接报错 | 事实错误。`new Queue()` 不传实参时 T 被推断为 `unknown`（TS 3.5+，此前是 `{}`），而**任何值都可赋给 `unknown`**，`q.enqueue(1)` 不会报错；真正出问题的是 `q.dequeue()` 返回 `unknown`，后续访问其属性/方法才报错。 | 改为："会落到 `unknown`，`enqueue(1)` 反而不报错（任何值都能赋给 unknown），但 `q.dequeue()` 的类型变成 `unknown`，取用结果时才会报错" |
| WEB-257-线上报错监控方案-window-onerror-到-SourceMap-还原.md | `lineno: err.lineno, colno: err.colno,` | 原生 `Error` 实例**没有** `lineno`/`colno` 属性（这两个字段只存在于 `ErrorEvent` 上），经 `reportError(e.error \|\| e, ...)` 传入后行列号恒为 `undefined`，与要点"上报内容：…行号列号"矛盾。 | 改为从事件取：`reportError(e.error \|\| e, { type: 'runtime', lineno: e.lineno, colno: e.colno, file: e.filename });`，同时把 `reportError` 里的 `lineno/colno` 两行删掉（统一由 `extra` 传入） |
| JS-370-流式响应处理-ReadableStream消费与背压.md | `await reader.releaseLock();` | 代码先 `getReader()`、`releaseLock()` 再 `pipeTo()`，而追问 1 明确说"不能，…pipeTo 会抛 TypeError…正确做法是二选一"，同一张卡前后冲突；且 `reader` 从未 `read()` 过，这两行纯属多余。（`releaseLock()` 已解除锁定后 pipeTo 并不因 locked 抛错，追问里"抛 TypeError"的说法本身也不严谨） | 删掉 `const reader = res.body.getReader();` 与 `await reader.releaseLock();` 两行，直接 `await res.body.pipeTo(sink);`；并把追问 1 改为："**未 releaseLock 时**流处于 locked 状态，pipeTo 会抛 TypeError；一旦用 getReader 手动读了，就不能再 pipeTo，只能二选一（本例不需要 reader）" |
| JS-196-设计一个乐观更新工具回滚与冲突检测怎么实现.md | `locks.set(key, chain.finally(() => {` | 清理判断 `if (locks.get(key) === chain)` 永远为假：存进 Map 的是 `chain.finally(...)` 返回的**新 Promise**，与被比较的 `chain` 不是同一对象。于是 key 永不删除，`locks` 随不同 key 单调增长（长期驻留的页面即内存泄漏）。 | 改为：<br>`const entry = chain.finally(() => { if (locks.get(key) === entry) locks.delete(key); });`<br>`locks.set(key, entry);`<br>`return chain;` |

## 存疑（不自动改，供人工判断）

| 文件 | 原文片段 | 疑点 |
|---|---|---|
| JS-363-前端锁语义-互斥与单飞.md | `const t = setTimeout(() => { if (!released) released = true; }, ms);` | 声称"超时兜底放行"，但定时器只翻转局部布尔，既不中断 `fn` 也不推进 `this.#tail`——任务悬挂时锁仍永不释放，与要点"超时释放（防死锁）"不符。另：`this.#tail = this.#tail.then(fn).finally(release)` 一旦某个 `fn` reject，`#tail` 变 rejected，后续 `run()` 会直接拿到旧错误而**不执行 fn**，队列被永久污染。修法是设计级改动（`Promise.race` + `catch(() => {})` 隔离），故不列入需修。 |
| JS-336-长任务拆分-时间切片的正确姿势.md | `else if (performance.now() % 1000 >= deadline)` | 主体示例的预算判断是错的（取模得到毫秒低位，与切片起点无关），虽然追问 1 已明确自纠为"不对，应记录 sliceStart"，但正文代码仍是可复制的错误写法，建议正文改成 `if (performance.now() - sliceStart >= deadline)`。 |
| JS-356-事件总线实现-订阅泄漏与通配符.md | `set.add({ fn, ns });` | 要点称"Set 保证同 handler 不重复注册"，但每次 `on()` 都 `add` 一个**新的对象字面量**，对象身份不同 → 同一个 fn 重复注册会产生两份订阅、触发两次回调，与要点矛盾。需改成按 fn 去重（如 `Map<fn, ns>` 或先查后 add）。 |
