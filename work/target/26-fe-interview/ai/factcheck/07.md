# 07 核查结果（38 张）

## 需修（置信度高）
| 文件 | 原文片段（≤30字，要能 grep 到） | 问题 | 精确改法 |
|---|---|---|---|
| DP-121 | `React 18 的 use()` | 事实错误+自相矛盾：`use()` 是 React 19 才稳定的 API，React 18 没有它；同卡追问 3 也写"React 19 的 use()"，前后冲突 | 要点改为 `React 19 的 use() / 框架级 suspense 数据源已内置该机制` |
| DP-418 | `this.#hooks.set(hookName, [])).push(fn)` | 代码逻辑错：`Map.set()` 返回 Map 本身而非新建数组，首次注册某钩子时会对 Map 调 `.push` 直接抛 TypeError，插件永远注册不上 | 改为 `if (!this.#hooks.has(hookName)) this.#hooks.set(hookName, []); this.#hooks.get(hookName)!.push(fn)` |
| ARC-332 | `cur.filter(c => !c.key.startsWith('.'))` | 代码逻辑错：`matchPaths` 拼出的路径 key 恒以 `.` 开头（初始 key 为空串、每段拼 `${key}.${p}`），该 filter 把所有结果滤掉，`matchPaths` 恒返回 `[]`，validate 从不校验任何字段 | 删除该 filter（保留 `.map(c => c.key.slice(1))`），或改为过滤 `c.value === undefined` 的项 |
| ARC-075 | `navigator.sendBeacon?.(this.ctx.config.dsn, body)` | 代码逻辑错：`??` 只在 null/undefined 时回退，而 `sendBeacon` 失败时返回 `false`，fetch+keepalive 兜底永远不会执行，失败批次被静默丢弃（与注释"页面卸载也不丢"矛盾） | 改为 `if (!navigator.sendBeacon?.(dsn, body)) fetch(dsn, { method: 'POST', body, keepalive: true })` |

## 存疑
| 文件 | 原文片段 | 疑点 |
|---|---|---|
| ARC-124 | `defineWorkspace` | Vitest 3 起已弃用 `workspace` 配置文件与 `defineWorkspace`，官方推荐根配置的 `projects` 选项；以 2026-11 为基准，示例仍以 `vitest.workspace.ts` 为推荐做法偏过时。未查证当前版本是否已移除该 API，故不判需修 |
| ARC-075 | `for (const hook of this.hooks)` | `Monitor` 类只声明了 `buffer`，`hooks` 字段从未定义/初始化，`capture` 首次执行即对 undefined 做 for-of 抛错；可能是示意省略，但按 TS 示例标准是硬伤 |
| ARC-813 | `JSON.parse/Function 构造替代` | 将 `Function` 构造器列为 eval 的"安全"替代方案有误导性：`new Function` 与 eval 同等危险（ESLint `no-new-func` 同级禁用），照此修改并不消除 reason 所述的安全风险 |
| ARC-323 | `useState({ start: 0, end: 0 })` | 初始 range 为 `{start:0,end:0}` 且区间只在 `onScroll` 里计算，首屏未滚动时渲染 0 行（空白列表），与评分点"可视区间计算正确"不符；疑为示意省略，未判需修 |
