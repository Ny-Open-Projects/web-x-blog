# 05 核查结果（40 张）

## 需修（置信度高）

| 文件 | 原文片段（≤30字，要能 grep 到） | 问题 | 精确改法 |
|---|---|---|---|
| PER-554-手写一个页面加载-LCP-归因报.md | `advice: r.loadPhaseMs > 1500` | `r` 是 `page.evaluate` 返回的对象，只有 startTime/url/tag/size/id/ttfb，没有 `loadPhaseMs` 属性；`undefined > 1500` 恒为 false，导致 advice 永远输出「当前 LCP 达标」，慢页面也判达标，规则映射这一评分点实际失效 | 把 `advice: r.loadPhaseMs > 1500 ? adv : ['当前 LCP 达标'],` 改为 `advice: (r.startTime - r.ttfb) > 1500 ? adv : ['当前 LCP 达标'],` |
| PER-554-手写一个页面加载-LCP-归因报.md | `size=${Math.round(r.size / 1024)}KB` | LCP entry 的 `size` 是元素的**像素面积**（intrinsic size，px），不是字节数；除以 1024 再标 KB 属于口径错误，会让人把「面积大」误读为「图片文件大」 | 改为 `element: \`${r.tag}#${r.id \|\| ''} area=${Math.round(r.size)}px²\`,`（如需文件体积，应另从 `PerformanceResourceTiming.transferSize/encodedBodySize` 取） |
| PER-583-监控-SDK-的初始化时序问题.md | `布局偏移序列、错误堆栈、慢交互细节**没有浏览器缓冲` | `layout-shift` 是**支持** `buffered: true` 的 entry 类型（web-vitals 的 onCLS 正是靠它补历史），本卡下方自己的代码也写着 `.observe({ type: 'layout-shift', buffered: true })`，前后矛盾 | 整句改为：`` `buffered: true` 虽能补回 paint/LCP/布局偏移的历史 entry，但**错误堆栈、交互事件明细（event-timing 之外的 handler 内部耗时）、已丢失的慢任务归属**没有浏览器缓冲，错过了就永久丢失`` |
| PER-220-手写响应式图片组件保证占位比.md | `img.dataset.src = src; img.src = 'data:image/svg+xml` | 上方已设 `img.srcset`，而 `srcset`（带 w 描述符 + sizes）存在时 `src` 会被忽略，占位 data URI 不生效，降级分支实际立即加载真图，「手动 IntersectionObserver 懒加载」完全失效 | 降级分支改为：`img.dataset.srcset = img.srcset; img.removeAttribute('srcset'); img.dataset.src = src; img.src = 'data:image/svg+xml,...';`，并在 IO 回调里写 `img.srcset = img.dataset.srcset; img.src = img.dataset.src; io.disconnect();` |
| OPT-192-白屏率专项治理的全景方案-从检测到自愈.md | `if (performance.now() > 8000) return { type: 'load_slow'` | `performance.now()` 是页面加载至今的时长；`whiteScreenGuard` 在 `setTimeout(..., 8000)` 里调用，此刻必然 > 8000，于是所有「非 JS 报错」的白屏都被判成加载型，后面的 `data_abnormal`（有壳无内容）分支在 SPA 复查路径下也几乎不可达，分型治理结论会全错 | 改为按「有无内容」判定加载型，并把有壳无内容前置：`if (root && root.childElementCount > 0) return { type: 'data_abnormal' };` `if (!root \|\| root.childElementCount === 0) return { type: 'load_slow', ttfb: getTTFB() };`（顺序放在 `jsErrors` 判定之后） |

## 存疑

| 文件 | 原文片段 | 疑点 |
|---|---|---|
| PER-197-边缘计算-Edge-SSR-边缘函数-如何改变前.md | `let res = await cache.match(request);` | 缓存在用户态判定之前命中，且缓存键只用 URL：登录用户访问同一路径会拿到匿名骨架缓存（内容错误）；虽在追问 2 里承认，但代码层面应改 `cache.match` 时拼上 `Vary: Cookie` 或对带 Cookie 请求直接跳过缓存查询 |
| PER-1279-手写一个性能数据脱敏导出器.md | `uid -> 不可逆哈希` | 实现是 32 位无符号滚动哈希（`h*31+code`），对自增 uid/手机号这类低熵输入可秒级枚举还原，「不可逆」表述过强；追问 2 只提到加盐，未指出该哈希碰撞与空间过小 |
| PER-546-手写一个-CLS-回归测试-自动.md | `pass: cls < 0.1` | 实现是「把所有 layout-shift 的 value 直接求和」再比 0.1，而 CLS 口径是**会话窗口最大累计值**（间隔 <1s、窗口 ≤5s）；跨多秒的多次偏移会被累加成远超真实 CLS 的值，阈值含义与 CWV 0.1 不等价（偏严，易误报） |
