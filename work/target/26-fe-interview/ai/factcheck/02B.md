## 存疑（不自动改，供人工判断）

| 文件 | 原文片段 | 疑点 |

| 02-框架与业务/FRP-060-静态提升-hoistStatic-的判定条件是什.md | `0 非静态 / 1 **可提升的字符串**` | Vue 源码 `ConstantTypes` 实为 0=NOT_CONSTANT、1=CAN_SKIP_PATCH、2=CAN_HOIST、3=CAN_STRINGIFY；文本节点是 CAN_STRINGIFY(3) 而非 1。分档编号与 `if (ct < type)` 的比较方向都建立在错误的编号上，属"简化模型"还是"编号写错"需人工定 |
| 02-框架与业务/V3-230-手写-v-memo-的跳过-diff-机制.md | `cacheIndexOf(parent, slot)` | 该函数全文未定义（引用即 ReferenceError）；且 Vue 的 withMemo 只 `return ret`（ret.memo = memo.slice()，存 cache[index]），不应自己调 `mount(vnode,...)`，否则会重复挂载。缓存结构 `[deps..., vnode]` 与源码 `vnode.memo` 也不一致 |
| 02-框架与业务/V3-250-手写-Suspense-结合错误边界的完整兜底方案.md | `2 ** errors.value * 500` | 注释写"500ms/1s"，但先自增再计算，实际是 1000ms/2000ms；另外 `onErrorCaptured`、`resolveComponent` 未 import（其余 API 都 import 了），照抄运行会报未定义 |
| 02-框架与业务/FRP-328-框架无关的存储与缓存层.md | `async get(key) {` | 入参 `ttl` 从未参与过期判断，`at` 只写不读，内存/IDB 缓存永不过期，与"TTL + 显式失效"的表述不符 |
| 02-框架与业务/MP-376-笔试-手写globalData响应式store.md | `const subs = new Map();` | `subs` 没有任何注册入口（无 subscribe API），set trap 只通知空集合；页面侧靠 `getApp().event` 桥接，但写入时从未派发该事件 → "订阅推送"通道实际不生效，只剩 sync 一次 |
| 02-框架与业务/R19-014-函数组件和-class-组件的区别.md | `class 的 this.state 在回调里读到的已合并结果` | class 里同一事件中 setState 后立刻读 `this.state` 同样是旧值，与函数组件并无"已合并"差异（除非特指 setState 回调/lifecycle，表述易误导） |
| 02-框架与业务/FRP-292-笔试-手写-响应式粒度对比实验.md | `A: renderCount 0→1` | 方案 A 代码没有任何订阅机制，`updateCell` 不会让 ComponentLevelGrid 重跑，renderCount 无法由 0 变 1，与断言注释不符（缺一次显式 `ComponentLevelGrid()` 调用或订阅触发） |
| 02-框架与业务/V3-120-流式-SSR-如何与-Suspense-配合.md | `import { renderToNodeStream }` | 官方文档注明该方法在 `vue/server-renderer` 的 ESM 构建中不可用，ESM/Vite 环境应改用 `pipeToNodeWritable`；此处示例为 CJS Express 写法，未标注该限制 |
