# 03 核查结果（35 张）

## 需修（置信度高）

| 文件 | 原文片段（≤30字，要能 grep 到） | 问题 | 精确改法 |
|---|---|---|---|
| SCN-284-电商评价系统的图文评价.md | `const clean = await prefilter(text);` | 函数入参解构为 `{ order, stars, tags, images, anonymous }`，没有 `text`，`prefilter(text)` 取到 undefined，敏感词快筛实际跑的是空值（且真实内容从未进 `text`） | 解构补 `text`（`{ order, stars, tags, images, anonymous, text }`），或改为 `prefilter(arguments.content)`；正文示例调用 `submitReview({..., content})` 时字段名要一致 |
| SCN-209-大促支付回跳与状态同步.md | `if (Date.now() - start > o.maxMs)` | `backgroundPoll` 内 `start` 未定义（既未从 `o` 传入也未在函数内赋值），比较恒为 false，`maxMs: 120e3` 的兜底超时永远不触发，`onTimeout` 永不执行 | 在 `setInterval` 之前加 `const start = Date.now();`，或由调用方传入 `o.start` |
| SCN-206-电商大促优惠券与满减的前端计算引擎.md | `- assigned + total` | 尾差行公式写成 `share - assigned + total`，多加了一次 `total`，最后一行优惠≈自身应摊额的两倍，各行 discount 之和大于总优惠，等于凭空多减钱 | 改为 `discount: total - assigned`（`toFen(...)` 只用于非尾差行的取整） |
| SCN-397-跨场景的用户体系与账号合并.md | `confirm(impact, { irreversible: true,` | 不可逆的账号合并没有判断 `confirm` 的返回值，用户点「取消」后代码继续执行 `api.merge`，直接造成误合并（前端示例里最危险的一处） | `const ok = await confirm(...); if (!ok) return;` 再调 `api.merge`；`confirm` 是原生同步函数，勿传对象，需换成业务 Modal 的 Promise 版本 |
| SCN-553-风控验证的前端整体架构怎么设计.md | `if (!verifier) return onPass();` | 与上文「风控接口超时 → 降级为本地基础校验」自相矛盾：catch 分支只给 `{ level: 'BASIC' }`，没有 `verifier` 字段，于是直接 `onPass()`，风控接口一挂即全量放行；服务端拼错验证器名同样静默放行（fail-open） | 显式区分「服务端判定无需验证」（如 `decision.challenge === false`）与「拿不到/不认识验证器」；后者走本地基础校验，无法降级时 `onFail`，不要一律 `onPass` |
| SCN-799-笔试题-实现相似内容指纹聚合.md | `汉明距离 ≤ 6 必有一段完全相同` | 鸽巢原理用错：切 4 段时只有距离 ≤ 3 才保证至少一段完全相同；≤6 时差值可分布为 2+2+1+1，四段全不同，候选集漏检，本该聚到一起的图聚不上 | 改为「切 ≥7 段时距离 ≤6 必有一段相同」，或保留 4 段并把阈值降到 3；也可多轮换段（按位取模再切）降低漏检率并注明是近似 |
| SCN-899-笔试题-实现秒杀实时漏斗告警.md | `pending.set(step, n);` | 「连续 2 个窗口下降才触发」的去抖没有实现：`pending` 只在下降时自增，未下降的窗口不清零也不衰减，两个相隔很远的孤立抖动能累加到 2 而误报；告警恢复后 `pending` 亦不清零，再次单次下降会立刻复报 | 在 `else` 分支（未判定下降）里 `pending.delete(step)`；`firing` 触发后与恢复后同时清 `pending`，并把 `n >= 2` 的判断放在「上一窗口也下降」的前提下 |
| SCN-1278-手写一个地址表单-schema-适配.md | `f === 'postal' && !this.s.zip.test(v)` | US schema 的邮编字段名是 `zip` 而不是 `postal`，`f === 'postal'` 永不成立，美国地址的邮编正则形同虚设（任何字符串都通过）；卡片还把这一点写成「评分点」 | schema 显式声明 `postalField: 'zip' / 'postal'`，校验时用 `f === this.s.postalField`；或统一字段名为 `postal` 并把 US 的 zip 改名为 postal |

## 存疑

| 文件 | 原文片段 | 疑点 |
|---|---|---|
| SCN-048-团队-Code-Review-流于形式-如何建立.md | `timer = window.setTimeout(() => doSearch(kw.value), 300);` | 示例自称是「CR 高频问题样本」，但 `watch` 回调里没先 `clearTimeout(timer)`，防抖实际不生效（每次输入都发一次搜索），同时也放大了它自己列出的「缺陷2 竞态」。属于第四类遗漏缺陷，也可能只是省略 |
| SCN-1287-手写一个支付方式路由器按国家+金额.md | `default: m === list[0]` | 需求写明要实现 `sca(country, method)` 方法，代码里没有独立 `sca()`，只在 `options` 内联；另外 `default` 用过滤前的 `list[0]`，当默认方式被限额过滤掉时整列无默认项，排序退化为纯按名称 |
| SCN-304-在线教育的课程销售转化页.md | `t === promo.triggerSec` | `timeupdate` 给的是带小数的浮点秒（约 4Hz），严格 `===` 基本命中不了整数秒，弹出时机不可靠；应改为跨阈判断（上一帧 < N 且当前帧 ≥ N） |
