## 需修（置信度高）

| 文件 | 原文片段（≤30字，要能 grep 到） | 问题 | 精确改法 |
|---|---|---|---|
| HW-321-手写一个运行时校验器生成.md | `Array.isArray(v) ? null` | 数组分支三元条件写反：v 是数组时直接返回 null，元素校验永不执行；非数组走 `v.flatMap?.(...)` 得 undefined 再 `?? 'expected array'`。实测 `compileType('string[]')([1,2,3])` 返回 null（应报错）。且 `flatMap` 结果为 `[]` 时 `?? ` 不触发、`[]` 又是 truthy，即使条件改对也会被上层 `if (e) return e` 当成错误返回 `[]`。 | 该行连同下一行整体替换为：<br>`return (v, path = '$') => {`<br>`  if (!Array.isArray(v)) return `${path}: expected array`;`<br>`  for (let i = 0; i < v.length; i++) { const e = elem(v[i], `${path}[${i}]`); if (e) return e; }`<br>`  return null;`<br>`};` |
| HW-229-手写一个自动保存与草稿恢复.md | `this.lastHash = h;` | 在写库**之前**就置 lastHash，`store.put` 失败后 catch 里的 `retry(() => this.save(doc))` 一进来就命中 `h === this.lastHash` 直接 return，重试实际一次都不会发（实测 attempts 恒为 1）。「保存失败重试（3 次指数退避）」完全失效，且草稿已丢。 | 删除现在这行，把赋值挪到写库成功之后：<br>`try { await this.store.put('draft', rec); this.lastHash = h; await this.trim(); this.chan.postMessage({ saved: h }); }` |
| HW-260-手写一个操作去抖与合批.md | `undoBase: this.buf.length` | 上一行刚执行 `this.buf = []`，这里读到的长度恒为 0，undoBase 永远是 0，与「undo 粒度本地保留」的说法不符（实测 2 条 op 合批后 undoBase=0）。 | 在 `const merged = mergeOps(this.buf);` 前加 `const n = this.buf.length;`，发送改为 `send({ compound: merged, undoBase: n });` |
| ALG-413-手写-BIT-持久化思想.md | `this.log.findIndex(e => e.t > snap.t)` | 快照已是最新时 findIndex 返回 -1，`Math.max(0, -1)` 变成 0，于是从第 0 条日志全量重放并叠加到快照状态上，结果翻倍。实测 100 次 +1 后 `queryAt(100,1)` 返回 200（应为 100）。 | 改为：`const idx = snap ? this.log.findIndex(e => e.t > snap.t) : 0; const from = idx < 0 ? this.log.length : idx;` 再把下面 `this.log.slice(Math.max(0, from))` 改为 `this.log.slice(from)` |
| ALG-413-手写-BIT-持久化思想.md | `for (j++; j > 0; j -= j & -j)` | 索引基准不一致：`applyBIT` 直接用 i（1-based）写 `this.base`，而重放用的 `bsum`/`badd` 先 `j++` 当 0-based，快照状态下整体错位一位。实测 `queryAt(101,2)` 返回 107（应为 7）。 | 把 `bsum` 与 `badd` 的 `j++` 去掉，统一按 1-based：<br>`const bsum = j => { let s = 0; for (; j > 0; j -= j & -j) s += bitArr[j]; return s; };`<br>`const badd = (j, v) => { for (; j <= this.n; j += j & -j) bitArr[j] += v; };` |
| ALG-370-区间统计的复杂度推导.md | `// 方案 C：最近 W 秒峰值——单调队列 O(1) 摊还` | 复杂度标注错：`recentPeak` 每次调用都 `new MonotonicQueue(this.buckets, W)` 并把最近 W 个元素全量扫一遍，单次查询是 O(W)，不存在摊还 O(1)；W 大可到几十万。 | 注释与正文同步改为「单次 O(W)」；若要 claim O(1) 摊还，须把队列提成实例字段，`record` 时增量 push、出窗时 shift，`recentPeak` 只读队首。 |
| HW-235-手写一个编辑器大文档优化.md | `const c = this.chunks.get(k);` | `edit` 假设 chunk 已在内存，未加载时 `c` 为 undefined，`c[blockIdx % this.size] = block` 直接 TypeError（实测编辑首个 chunk 与跨 chunk 编辑都抛 `Cannot set properties of undefined`）。与边界「跨 chunk 编辑触发双 chunk 加载」矛盾。 | 改为先确保加载：<br>`edit(blockIdx, block) {`<br>`  const k = this.chunkOf(blockIdx);`<br>`  const c = this.chunks.get(k);`<br>`  if (!c) return this.get(blockIdx).then(() => this.edit(blockIdx, block));`<br>`  c[blockIdx % this.size] = block; this.dirty.add(k);`<br>`}` |
| HW-367-手写一个文本编辑器渲染优化.md | `if (c && c.rev === this.docRev && c.text === text) return c.html;` | 命中分支不刷新 Map 顺序，淘汰时按插入序删最老的键，实际是 FIFO 而非需求声明的「视口外 LRU 清理」（卡片自己的评分点也写了「命中分支要 delete 再 set 才能把该行移到队尾」）。热行会先被淘汰，反复重渲染。 | 改为：`if (c && c.rev === this.docRev && c.text === text) { this.cache.delete(idx); this.cache.set(idx, c); return c.html; }` |
| HW-391-手写一个内容防丢失体系.md | `sessionStorage.setItem('doc-alive-' + this.tabId, '1');` | 崩溃标记放 sessionStorage，而 sessionStorage 是标签页私有的：本 tab 的 `Object.keys(sessionStorage)` 只含自己的键，`stale` 过滤后恒为空，`detectCrash` 永远返回 null，崩溃恢复从不触发（崩溃的 tab 消失后其 sessionStorage 也随之销毁）。 | 存活标记改走 localStorage：`localStorage.setItem('doc-alive-' + this.tabId, '1');`；`detectCrash` 里改为 `Object.keys(localStorage).filter(k => k.startsWith('doc-alive-'))`；beforeunload 里相应改 `localStorage.removeItem(...)` |
| HW-056-手写-FlattenDeep.md | `flat` 保留空洞、map 会跳过空洞 | 事实写反：`Array.prototype.flat` **剔除**空位（`[1,,3].flat()` → `[1,3]`），`map` 是保留空位、只跳过回调（长度仍是 3）。连带上面代码注释「稀疏空位在解构时已变 undefined，行为与 flat 对齐」也错：`[...arr]` 把空位变 undefined，结果数组里会多出 undefined，与 flat 不等价。 | 评分点改为：`flat` 剔除空位、`map` 保留空位但不调用回调，`[...arr]` 把空位变 undefined 二者不等价；代码注释改为「spread 会把空位变成 undefined，与 flat 不一致；要等价需 `if (i in arr)` 过滤空位」 |

## 存疑

| 文件 | 原文片段 | 疑点 |
|---|---|---|
| HW-229-手写一个自动保存与草稿恢复.md | `this.t = setTimeout(() => this.save(doc), 1000);` | 构造函数收了 `debounceMs` 却没用，硬编码 1000，改这个选项不生效（默认值恰好一致，故不算行为错，但选项是死的）。 |
| HW-353-手写一个图层管理器.md | `const hit = layer.hit?.(px, py);` | `hitTest`/`renderAll` 都不递归进分组子节点：组节点自身调 `n.draw(ctx)`（可能未定义，组无 draw 会 TypeError），组内的子图层也永远命中不到。与「组节点递归管理子节点」的设计不一致。 |
| HW-318-手写一个前端限流引擎.md | `tokens + (now - last) / rate` | 评分点里的补充公式量纲错：代码是 `(now - last) / 1000 * rate`（秒 × 速率），写成 `/ rate` 会越补越少；这里只是口径描述与代码不一致。 |
| HW-369-手写一个错误标记层.md | `Math.floor(py / this.lineH)` | `this.lineH` 从未赋值（构造函数没有、`render` 用的是入参 `lineHeight`），`at()` 里除 undefined 得 NaN，命中判断恒失败。若依赖外部赋值则应在构造函数里声明。 |
| ALG-318-任务队列的优先级老化.md | `starving 检测（等待 > 30s 强制立即执行）` | 思路写了 starving 检测与 30s 强制执行，代码里没有任何对应分支（只有 eff 排序），属声明与实现不对应。 |
| HW-363-手写一个流程图自动布局.md | `arr.sort((a, b) => avgUpstreamPos(a) - avgUpstreamPos(b));` | `avgUpstreamPos` 只读 `n.upstreamAvgY ?? 0`，全流程没有任何地方计算该值，排序键恒为 0、等于没排序；「两轮迭代减少交叉」未实现。 |
| HW-391-手写一个内容防丢失体系.md | `const key = level === 'hot' ? 'doc-snap-hot' : 'doc-snap-cold';` | 需求写的是「sessionStorage 高频快照 / localStorage 低频」，但两级快照都写进 localStorage，三级保护实际只有两级存储。 |
| ALG-370-区间统计的复杂度推导.md | `this.tree ??= buildMaxTree(this.buckets);` | 线段树只懒建一次，`record` 之后不再重建也不增量更新，`peak()` 返回的是首次建树时的旧值；另外环形缓冲下 `lo % keep > hi % keep` 的跨环窗口会查到空区间。 |
