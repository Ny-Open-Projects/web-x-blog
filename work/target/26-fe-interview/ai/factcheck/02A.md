## 存疑（不自动改，供人工判断）

| 文件 | 原文片段 | 疑点 |
|---|---|---|
| FRP-004-shallowRef-为什么快triggerRe.md | 10 万条列表数据初始化要做 10 万次代理 | Vue3 的 `reactive` 是惰性代理：`reactive(bigArray)` 初始化只建根 Proxy，逐项代理发生在首次访问（渲染）时，不是初始化。数字量级结论可用，"初始化"这个时机描述不准确 |
| FRP-046-Vue-与-React-的响应式驱动更新模型有什.md | 省的是 patch 而不是 render | `memo` 命中 bailout 时省掉的恰恰是子树那次 render（beginWork 早退），DOM patch 也一并省。同卡第 13/47 行都说 memo 让子组件"不重算"，此句与之相反 |
| FRP-049-SSR-的-hydration-注水-原理是什么.md | 为什么 hydration 期间写 useLayoutEffect 会报警告 | 这条警告（"useLayoutEffect does nothing on the server"）来自 SSR 渲染（react-dom/server），不是 hydration 期；水合 commit 阶段 layout effect 是正常执行的，"React 不走 layout 插入流程"的机制解释站不住。同答"19 允许它在 hydrate 完成后补跑"也需复核 |
| FRP-124-ref-跨组件传递时的自动解包规则与边界有哪些.md | 子组件在 props 里拿到的是 ref **对象本身** | 只在"ref 未经解包直接作为 prop 值"（h/render、v-bind 对象展开）时成立。常见写法 `:count="countRef"` 会在父模板层先解包，子组件 `props.count` 是普通值，此时按本卡示例加 `.value` 反而得到 NaN。此条建议加限定条件 |
| FRP-160-用-key-重置组件状态的所有用法与底层原理是什.md | （子先父后） | React 删除子树时 `commitDeletionEffectsOnFiber` 先对本 fiber 跑 destroy 再递归子节点，是**父先子后**；另外 `useEffect` 的清理与新建都发生在 passive flush（paint 之后），并非"都在 commit 内完成" |
| V3-274-可编辑表格的单元格状态与脏数据管理.md | 只订阅一次 size 变化 | Vue 的 collection handler 里 `Symbol.iterator`/`entries` track 的是 `ITERATE_KEY`，`Map.set` 新键走 ADD 分支会 trigger `ITERATE_KEY`（`keys()` 才只 track `MAP_KEY_ITERATE_KEY`），"新增键不触发旧迭代"的说法与原实现不符。version 计数兜底本身无害 |
| R19-085-如何实现分步向导状态机与草稿持久化怎么做.md | 不能写进 useReducer 初始值 | 写进惰性初始化反而能正确恢复草稿（初始 state 就是草稿，写回 effect 不会覆盖），"每次刷新都覆盖用户草稿"的理由不成立；用 effect 恢复的真实动因是 SSR 下 `localStorage` 不可用/避免首帧写入时序 |
| R19-407-并发渲染边界-并发渲染下的错误恢复.md | （React 19 experimental） | `onUncaughtError` 是 React 19 正式文档化的 root 选项（与 `onCaughtError`/`onRecoverableError` 并列），标成 experimental 会让人误以为是不稳定 API |
| R19-407-并发渲染边界-并发渲染下的错误恢复.md | `fallbackRender={({ error }) => { setError(error); ...` | 在 `fallbackRender`（ErrorBoundary 的渲染期）里 set 父组件 state，属于"A 组件渲染期更新 B 组件"，React 会告警且易引发多余渲染/不一致；改用 `onError={e => setError(e)}` 更稳妥 |
| V3-285-上传组件设计-分片-断点续传-直传凭证.md | 浮点乘会在超大文件上偏一字节 | JS 的 number 在 2^53 以内整数运算精确，`i * CHUNK` 不会产生 1 字节偏差（需要文件超过 9PB 才谈得上）；该"坑"实际不存在，真正的边界是分片边界要按字节对齐 |
