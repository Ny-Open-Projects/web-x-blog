# 05 动态规划与贪心（ALG-074~087 / 204 / 213 / 481~500）

前端业务里真正会写成 DP 的地方，往往不是"求最长回文串"，而是**凑单、切词、diff、档期排期、任务编排**这些"要在有限预算里做最优选择"的场景。它们的共同点是：暴力枚举的组合数随规模指数爆炸，但每一步的决策只依赖少数几个"已经算好的子问题"。**识别特征**：看到「最多 / 最少 / 能否 / 方案数」+ 可拆子问题 → DP；看到「区间不重叠」「按某个维度排序后一次扫描就最优」→ 贪心。

面试官问这类题的真正意图通常有三层：你能不能把业务描述翻译成状态定义；你写不写得对边界（空输入、无解、重复使用）；你能不能说清"为什么不能贪心"或"贪心为什么对"。第三层是区分度最高的一层——很多人能背出零钱兑换的代码，却说不清为什么面额 `[1,3,4]` 凑 6 时贪心会错。

## 场景范式

**1. 先判"最优子结构"，再判"贪心选择性质"。** 如果答案能从"规模更小的同类问题的最优解"拼出来，就是 DP；如果每一步都能证明"选当前看起来最好的那个，不会让后面变差"，才是贪心。贪心写起来只有十行，但它错的时候也只在第 100 个用例上错，所以面试时要主动说"我能给出交换论证"，或者说"这里贪心不成立，我退回 DP"。

**2. 状态定义决定一切，优先试三种措辞。** 「以 i 结尾」（适合连续子数组、LIS）、「前 i 个」（适合序列比对、背包）、「凑出 i / 达到 i」（适合金额、容量）。同一道题换个定义，转移方程可能从两行变成十行。写完定义先自检：这个状态能不能推出答案？转移需要的子状态在不在表里？

**3. 遍历顺序由状态依赖方向决定，背包题尤其容易错。** 完全背包（物品可重复用）：容量从小到大正序，因为 `dp[i]` 依赖同一轮的 `dp[i-c]`；0/1 背包（每件只用一次）：容量从大到小倒序，避免同一件被二次使用。这一点答错，代码能跑但对不上答案。

**4. 二维表的优化路径是固定的：先写二维，再看能不能滚一维。** 转移只依赖"上一行"就能滚成一行；如果还要回溯出方案（LCS、凑单组合），就别急着压空间，或者额外存一份 `choice` 数组。

**5. 贪心的三件套：排序键、每次取什么、正确性证明。** 排序键选错是最高频错误（区间调度按 start 排就错）；证明手段只有三种——交换论证（把最优解的第一个决策换成贪心的，证明不变差）、反证（假设存在更优解，推出与贪心不变式矛盾）、归纳（第 k 步之后贪心仍不劣）。答不出证明就说明你还没想清楚，这时候 DP 更安全。

## 精讲（6 题）

### 精讲 1 · [ALG-077] 满减凑单：恰好凑到目标金额的最少商品数

**场景**：购物车差 3 元才到 199 减 30 的门槛，商品可重复加购（同一 SKU 加多次），要求加购件数最少——每多一件就多一次点击，用户体验最差的是"加 20 件 1 元的小样"。

**问法**：给定面额数组 `coins` 和目标金额 `amount`，每种面额可用无限次，求凑出 `amount` 的最少件数；无解返回 -1。

**状态定义**：`dp[i]` = 凑出金额 `i` 所需的最少件数。之所以用"凑出金额 i"而不是"考虑前 i 个面额"，是因为本题面额可重复使用，物品维度没有意义，金额本身就是完整的子问题描述。

**转移方程**：`dp[i] = min(dp[i - c] + 1)`，对所有满足 `c <= i` 的面额 `c`。含义是"最后一件选 c"，那么前面必须凑出 `i - c`。

**初始化**：`dp[0] = 0`（凑 0 元需要 0 件），其余为 `Infinity`（暂时不可达）。用 `Infinity` 而不是 -1，是为了让 `min` 运算自然跳过不可达状态。

**遍历顺序**：外层金额 `i` 从 1 到 `amount` 正序，内层面额任意。正序保证了 `dp[i-c]`（更小的金额）在同一轮里已经算好，这正是"完全背包"的标志。如果内层改成从大到小，就退化成每件只能用一次的 0/1 背包。

**为什么不能贪心**：直觉是"每次拿最大的面额"，但面额 `[1, 3, 4]` 凑 6 时，贪心拿 4 后只能 `4+1+1` 共 3 件，而最优是 `3+3` 共 2 件。大面额会破坏剩余金额的可组合性，这个反例面试时要能立刻举出来。

```javascript
function minCoins(coins, amount) {
  if (amount === 0) return { count: 0, plan: [] };
  const dp = new Array(amount + 1).fill(Infinity);
  const from = new Array(amount + 1).fill(-1); // 记录最后用的面额，用于回溯方案
  dp[0] = 0;
  for (let i = 1; i <= amount; i++) {          // 正序 = 完全背包
    for (const c of coins) {
      if (c <= i && dp[i - c] + 1 < dp[i]) {
        dp[i] = dp[i - c] + 1;
        from[i] = c;
      }
    }
  }
  if (dp[amount] === Infinity) return { count: -1, plan: [] };
  const plan = [];
  for (let i = amount; i > 0; i -= from[i]) plan.push(from[i]);
  return { count: dp[amount], plan };
}
```

**边界与追问**：`amount = 0` 直接返回 0（不要进循环，否则空面额数组也会返回 Infinity）；面额含 0 要预先过滤，否则 `dp[i-0]+1` 会自我更新并让回溯死循环；金额过大（比如 10 万）时 O(amount) 内存吃不消，实际业务会先用最大面额做贪心近似 + 小范围 DP 修正。追问"如果要求券数最少但金额可以超出"——把状态从"恰好"改成"至少"，答案取 `min(dp[amount..amount + maxCoin])`。

### 精讲 2 · [ALG-204] 优惠券各用一次：凑出恰好门槛的组合与回溯

**场景**：结算页给了用户 4 张券（面额 10 / 20 / 5 / 30），每张最多用一次，要凑出恰好等于运费门槛的金额以触发免运费，并把用了哪几张告诉用户。

**问法**：`subsetSum(coupons, target)`，返回任一和恰好为 `target` 的下标组合，无解返回 `null`。

**状态定义**：`dp[j]` = 布尔值，表示"用当前已考虑过的券，能否凑出金额 j"。这里物品维度被压进了外层循环，一维数组就够，因为每件物品只用一次。

**转移方程**：对每张面额 `v`，`dp[j] = dp[j] || dp[j - v]`。同时用 `from[j]` 记录"达成 j 时用的是哪张券的下标"，这是回溯方案的关键——只存布尔值只能回答"能不能"，回答不了"用哪几张"。

**初始化**：`dp[0] = true`（不用任何券就能凑 0），其余 false；`from` 全部 -1。

**遍历顺序**：外层物品正序，内层金额**从 target 倒序到 v**。倒序是 0/1 背包的灵魂：如果正序，`dp[j-v]` 可能在本轮已经被这张券更新过，同一张券会被用两次。

**为什么不用暴力枚举**：4 张券是 2⁴，但真实的券包有 30 张，2³⁰ 直接爆炸；DP 是 `O(n·target)`，30 × 20000 也就 60 万次。

```javascript
function subsetSum(coupons, target) {
  const dp = new Array(target + 1).fill(false);
  const from = new Array(target + 1).fill(-1); // from[j] = 凑出 j 时最后加的券下标
  dp[0] = true;
  for (let i = 0; i < coupons.length; i++) {
    const v = coupons[i];
    if (v <= 0) continue;                       // 防御 0 / 负面额
    for (let j = target; j >= v; j--) {         // 倒序 = 0/1 背包
      if (!dp[j] && dp[j - v]) {
        dp[j] = true;
        from[j] = i;
      }
    }
  }
  if (!dp[target]) return null;
  const picked = [];
  for (let j = target; j > 0 && from[j] !== -1; j -= coupons[from[j]]) {
    picked.push(from[j]);                       // 记录下标，前端可直接高亮这几张券
  }
  return picked;
}
```

**边界与追问**：`target = 0` 返回空数组（空集合法）；回溯循环要带 `from[j] !== -1` 守卫，否则一旦链路断裂会拿到 `undefined` 面额；多解时 DP 只给"物品序最早"的一种，若要"面额最大 / 张数最少"的最优解，把 `dp` 从布尔改成数值（记录最大抵扣或最少张数）再改写转移。追问"券可叠加但有门槛条件"——这就从子集和变成了带约束的背包，通常只能回溯 + 剪枝（见 ALG-213）。

### 精讲 3 · [ALG-078] Vue3 diff 的 LIS：为什么"不动的节点"要最长递增

**场景**：`patchKeyedChildren` 处理完头尾对比后，中间剩下一段乱序节点，它们都复用了旧的真实 DOM。逐个 `insertBefore` 会把所有节点都搬一遍，代价是 O(n) 次 DOM 操作；找出"相对顺序本来就正确"的最长子集，只移动剩下的那几个，移动次数最少。

**问法**：给定新序列各节点在旧序列中的下标数组（如 `[3, 1, 2, 0]`），返回一组递增下标，使得对应节点无需移动。

**状态定义（贪心 + 二分版）**：`result[k]` 存"长度为 k+1 的递增子序列中，结尾最小的那个元素在数组中的**下标**"。注意存下标而不是值，因为 Vue 最后要的是"哪些位置不用动"。`p[i]` 存 `i` 的前驱下标，用于回溯出真实序列。

**转移（贪心）**：遍历 `arr[i]`：若它比当前最长序列的尾巴还大，直接接上；否则用二分找到第一个 `>= arr[i]` 的位置并替换。替换不会让长度变短，只会让"同样长度的结尾更小"，给后面留更多空间——这就是 LIS 能用二分的正确性来源。

**初始化**：`result = [0]`，`p = arr.slice()`（前驱初始指向自己）。

**遍历顺序**：从左到右一次扫描，`O(n log n)`。最后从 `result` 的最后一个下标沿 `p` 回溯，得到真正的最长递增下标序列（**不能直接返回 `result`**，它只是"每个长度的最小结尾"，元素顺序不保证递增，这是手写 LIS 最经典的坑）。

**为什么要跳过 0**：Vue3 用 `0` 标记"这个位置是新增节点，旧序列里没有"，它不参与最长递增，否则会破坏下标的语义。

```javascript
function getSequence(arr) {
  const p = arr.slice();          // 前驱下标，用于回溯
  const result = [0];             // 存的是下标，不是值
  for (let i = 0; i < arr.length; i++) {
    const arrI = arr[i];
    if (arrI === 0) continue;     // 0 = 新增节点，跳过
    const last = result[result.length - 1];
    if (arr[last] < arrI) {       // 比尾巴大，直接接上
      p[i] = last;
      result.push(i);
      continue;
    }
    let lo = 0, hi = result.length - 1;
    while (lo < hi) {             // 找第一个 >= arrI 的位置
      const mid = (lo + hi) >> 1;
      if (arr[result[mid]] < arrI) lo = mid + 1;
      else hi = mid;
    }
    if (arrI < arr[result[lo]]) {
      if (lo > 0) p[i] = result[lo - 1];
      result[lo] = i;             // 替换成更小的结尾，不影响长度
    }
  }
  let len = result.length;
  let cur = result[len - 1];
  const seq = new Array(len);
  while (len-- > 0) {             // 回溯出真实下标序列
    seq[len] = cur;
    cur = p[cur];
  }
  return seq;
}
```

**边界与追问**：空数组返回 `[]`；全为 0（全是新增）时返回 `[0]`，调用方应据此判断"没有可复用的稳定节点"；`p` 用 `arr.slice()` 初始化是 Vue 的写法，保证回溯到第一个元素时 `p[0] === 0` 能终止。追问"为什么不用 LCS 做 diff"——文本 diff 用 LCS/Myers 因为元素可能重复；DOM 子节点有唯一 key，等价于"排列"，用 LIS 从 O(n²) 降到 O(n log n)。追问"移动策略"——从后往前遍历新序列，遇到不在 LIS 里的节点就 `insertBefore` 到后一个已处理节点之前。

### 精讲 4 · [ALG-079] 编辑距离：给"您是不是想找"打分

**场景**：用户输入 `recieve`，词表里有 `receive`，要把距离最近的候选词排到最前面。搜索纠错、命令面板的模糊匹配、脏词近似检测，底层都是编辑距离。

**问法**：给定两个字符串 a、b，返回把 a 变成 b 的最少操作数（插入、删除、替换各算 1 次）。

**状态定义**：`dp[i][j]` = a 的前 i 个字符变成 b 的前 j 个字符的最小编辑距离。用"前 i 个"而不是"以 i 结尾"，因为编辑操作会改变串的长度，只有前缀长度是稳定的子问题边界。

**转移方程**：若 `a[i-1] === b[j-1]`，`dp[i][j] = dp[i-1][j-1]`（末尾相同，不用动）；否则 `dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])`，三者分别对应"删掉 a 的末字符"、"在 a 末尾插入 b 的末字符"、"把 a 的末字符改成 b 的末字符"。

**初始化**：`dp[i][0] = i`（a 的前 i 个全删掉），`dp[0][j] = j`（从空串插 j 个）。这两行不是可有可无的边界，它们是转移的基石，很多人的实现错就错在这里没填。

**遍历顺序**：i、j 都正序。因为 `dp[i][j]` 依赖左上、上、左三个格子，正序扫描保证三者都已计算。空间可以滚动成一维，但需要额外变量暂存左上角（会被覆盖的 `dp[j-1]` 旧值）。

**复杂度**：时间 O(m·n)，空间 O(n)。业务上还有一个关键优化：如果 `|m - n| > 阈值`，直接判定"不相似"跳过，因为编辑距离不可能小于长度差——这就是搜索联想能对 10 万词表实时打分的原因。

```javascript
function editDistance(a, b) {
  const m = a.length, n = b.length;
  if (m === 0) return n;
  if (n === 0) return m;
  let prev = new Array(n + 1);
  let cur = new Array(n + 1);
  for (let j = 0; j <= n; j++) prev[j] = j;  // 初始化第 0 行
  for (let i = 1; i <= m; i++) {
    cur[0] = i;                              // 初始化第 0 列
    for (let j = 1; j <= n; j++) {
      if (a[i - 1] === b[j - 1]) {
        cur[j] = prev[j - 1];                // 末尾相同，继承左上
      } else {
        cur[j] = 1 + Math.min(
          prev[j],                            // 删除 a[i-1]
          cur[j - 1],                         // 插入 b[j-1]
          prev[j - 1]                         // 替换
        );
      }
    }
    const t = prev; prev = cur; cur = t;     // 滚动，复用旧数组避免反复分配
  }
  return prev[n];
}
```

**边界与追问**：任一串为空时答案就是另一串长度；两个空串返回 0。追问"如何拿到具体的编辑路径"——保留完整的二维表，从 `(m,n)` 反向走，每步判断当初选了哪个分支，就能输出"把第 5 个字符 e 改成 i"，产品上可以直接展示"你是不是想输入 receive"。追问"只允许插入和删除（不允许替换）"——去掉 `dp[i-1][j-1]` 分支，距离变成 `m + n - 2·LCS`，跟 06 篇的 LCS 打通了。追问性能——超长文本先按词切分，只在候选词数量少时逐字算，或用 BK 树做索引剪枝。

### 精讲 5 · [ALG-081] LCS：文件 diff 凭什么知道"哪几行没变"

**场景**：代码 diff 工具把两个版本按行比较，行数可能上千。要先求出"最长公共行序列"，公共行标绿不动，其余按位置标红（删除）和标绿（新增）。

**问法**：给定两个字符串/行数组，返回最长公共子序列的长度，以及可选的公共序列本身。

**状态定义**：`dp[i][j]` = a 前 i 个与 b 前 j 个的 LCS 长度。注意是"子序列"不是"子串"——不要求连续，因为 diff 里公共行之间可以夹着新增行。

**转移方程**：若 `a[i-1] === b[j-1]`，`dp[i][j] = dp[i-1][j-1] + 1`（这个字符一定在某个最优解里，可以贪心地收下）；否则 `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`（至少有一边的末字符用不上，丢掉它）。

**初始化**：第 0 行、第 0 列全 0（任一序列为空则公共长度为 0）。

**遍历顺序**：i 从 1 到 m、j 从 1 到 n 正序。要求长度可以只留两行，但**要还原具体哪几行相同就必须保留整张表**（或额外存方向标记），因为回溯要走回头路。

**为什么是对的**：这是"最优子结构 + 无后效性"的标准形态——两个前缀的 LCS 只由更短前缀的 LCS 决定，与更早的选择无关。等号时收下字符不会丢解：任何以这两个相同字符结尾的匹配都可以前移到最后，不影响最优性。

```javascript
function lcs(a, b) {
  const m = a.length, n = b.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      dp[i][j] = a[i - 1] === b[j - 1]
        ? dp[i - 1][j - 1] + 1
        : Math.max(dp[i - 1][j], dp[i][j - 1]);
    }
  }
  // 回溯还原公共序列（也等价于产出 diff 的编辑脚本）
  const common = [];
  let i = m, j = n;
  while (i > 0 && j > 0) {
    if (a[i - 1] === b[j - 1]) {
      common.push(a[i - 1]);        // 该行未变
      i--; j--;
    } else if (dp[i - 1][j] >= dp[i][j - 1]) {
      i--;                          // a[i-1] 是删除行
    } else {
      j--;                          // b[j-1] 是新增行
    }
  }
  return { length: dp[m][n], common: common.reverse() };
}
```

**边界与追问**：任一为空返回长度 0、序列空；完全相同的两串，回溯会走对角线，`common` 就是原串。风险点是**内存**：1 万行 × 1 万行的二维表是 10⁸ 个格子，浏览器直接 OOM——真实 diff 用 Myers 算法（O(ND)，D 是差异数），差异小时接近线性；或者先按行哈希做滚动哈希，把"相同行"折叠掉再用 LCS。追问"如何标出新增/删除的位置"——回溯时三个分支就是三种操作，把它们按顺序收集起来就是标准的 unified diff 脚本。

### 精讲 6 · [ALG-082] 区间调度：为什么"按结束时间排序"是对的

**场景**：轮播图后台有一批投放档期 `[start, end]`，同一个位置同一时间只能投一个素材，要求选出数量最多的互不冲突档期。

**问法**：给定区间数组，返回最多能选多少个互不重叠的区间。

**算法**：按 `end` 升序排序；维护 `lastEnd = -Infinity`；依次扫描，若 `start >= lastEnd` 就选中它并更新 `lastEnd = end`。

**正确性证明（交换论证）**：设最优解为 O = {o₁, o₂, …}，按结束时间升序。贪心第一步选的 g₁ 是所有区间中 `end` 最小的。因为 `end(g₁) <= end(o₁)`，把 O 中的 o₁ 换成 g₁ 后：g₁ 与 o₂ 不冲突（`start(o₂) >= end(o₁) >= end(g₁)`），所以 O' = {g₁, o₂, …} 仍是合法解，数量不变。于是"存在一个以 g₁ 开头的最优解"。对剩下的区间（起点 >= end(g₁)）归纳使用同一论证，贪心每一步都能替换成最优解的一步，最终贪心解与最优解数量相同。

**为什么按 start 排序是错的**：反例 `[[0,100], [1,2], [3,4]]`。按 start 排会先选 `[0,100]`，后面全被挡住，只选 1 个；正确答案是 2 个。按 start 排序时"早开始"和"早结束"没有关系，长区间会堵死后面所有机会。

**为什么按长度排序也是错的**：`[[0,3], [1,2], [2,4]]`，最短的 `[1,2]` 一选，另外两个都冲突，只能选 1 个——这个例子说明"短"不等于"留出更多空间"，只有"早结束"才等价于"给后面留最多空间"。

```javascript
function maxIntervals(intervals) {
  if (!intervals.length) return { count: 0, picked: [] };
  // 拷贝后排序，避免污染入参（React 里直接 sort props 是经典 bug）
  const sorted = intervals
    .map((it, idx) => ({ start: it.start, end: it.end, idx }))
    .sort((x, y) => x.end - y.end || x.start - y.start);
  let lastEnd = -Infinity;
  const picked = [];
  for (const it of sorted) {
    if (it.start >= lastEnd) {   // 闭区间用 >=；开区间改 >
      picked.push(it.idx);
      lastEnd = it.end;
    }
  }
  return { count: picked.length, picked };
}
```

**边界与追问**：空数组返回 0；单区间直接返回 1；区间端点相接算不算冲突要先问清楚（`[1,2]` 与 `[2,3]` 在时间语义上通常不冲突，用 `>=`；如果是"同一时刻只能有一场"，则要 `>`）。追问"最多能覆盖多长总时长"——贪心失效，必须 DP（按结束时间排序后 `dp[i] = max(dp[i-1], dp[p(i)] + len_i)`，`p(i)` 是最后一个不冲突的区间，用二分找）。追问"删掉最少几个区间让剩下的不重叠"（ALG-496）——答案就是 `n - 最多可选数`，一步转化。
