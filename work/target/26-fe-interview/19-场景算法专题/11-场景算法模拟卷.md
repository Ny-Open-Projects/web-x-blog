# 场景算法模拟卷（3 套）

> **用法**：一套卷限时做完，全程**口述 + 白板**，不查资料。场景题不是笔试作答，是面试对话——所以要练"边说边设计"。
> **为什么要有场景模拟卷**：LeetCode 题做多了会养成"看到题就想模板"的习惯，而场景题恰恰相反，**要想清楚再动手**。这两种节奏必须分开练。

## 评分口径（通用）

| 维度 | 权重 | 采分点 |
|---|---|---|
| 需求澄清 | 20% | 是否主动问数据量、触发频率、并发 |
| 结构选型 | 30% | 选对数据结构，并能说出"为什么不用另一个" |
| 方案完整 | 25% | 核心逻辑正确，边界不遗漏 |
| 复杂度与取舍 | 15% | 能说清瓶颈，能给替代方案 |
| 表达 | 10% | 讲得让人听懂，不闷头写 |

**过关线**：3 题中 2 题达到"结构选型 + 方案完整"双绿；4 题全绿 = 优秀。

## 套卷一 · 电商大促（90 分钟）

### 第 1 题（20 min）· 商品列表多维筛选 + 多字段排序

**场景**：商品列表页，用户可勾选品牌、价格区间、颜色，并点击表头按「销量 / 价格 / 上架时间」排序，要求**同值项保持原有相对顺序**（否则翻页会看到重复商品）。

**你要先问的**：单页多少条？筛选是前端做还是后端做？总数据量多少？

**采分点**：
- 知道多字段排序要用**比较器链**（先比第一关键字，相等再比第二关键字），而不是多次 `sort`
- 知道 `Array.prototype.sort` 在 V8 里是稳定排序（TimSort），但**不能依赖**——跨引擎不保证，要自己带原始索引兜底
- 筛选 + 排序的复杂度：筛选 O(n)，排序 O(m log m)，能说出"如果 m 很大要先在后端过滤"

**参考方案要点**：
```javascript
// 带原始索引的稳定排序（不依赖引擎实现）
function stableSort(list, comparators) {
  return list
    .map((item, i) => ({ item, i }))
    .sort((a, b) => {
      for (const cmp of comparators) {
        const r = cmp(a.item, b.item);
        if (r !== 0) return r;
      }
      return a.i - b.i;              // 全部相等时按原序
    })
    .map((x) => x.item);
}
```

**关联原卡**：[ALG-004](../06-算法与手写/ALG-004-商品列表表格支持点击表头多列排序-先按分类升序.md)、[ALG-225](../06-算法与手写/ALG-225-表格多列排序的稳定实现.md)

**追问**："如果 10 万条数据在前端排，会卡吗？"→ 会，O(n log n) 在 10 万量级约 50~100ms，要放 Worker，或用虚拟列表只排可见部分（但排序语义就不对了，所以要后端排）。

### 第 2 题（25 min）· 凑单最少件数

**场景**：购物车「满 200 减 30」，用户想用**最少件数**的商品凑到门槛，帮他决定加购哪些。

**你要先问的**：商品能重复选吗（不限量 vs 库存 1 件）？商品数量级？

**采分点**：
- 能识别这是**完全背包**（不限量）还是 **0-1 背包**（库存 1 件），两者遍历顺序相反
- 能说清 `dp[j]` 的语义：容量 j 时最少件数，初值 `Infinity` 而不是 0
- 能说明为什么不能贪心（先挑贵的）——给反例

**参考方案要点**：
```javascript
// 完全背包求最少件数；dp[j] = 凑出金额 j 的最少件数
function minItems(prices, target) {
  const dp = new Array(target + 1).fill(Infinity);
  dp[0] = 0;
  for (let j = 1; j <= target; j++) {
    for (const p of prices) {
      if (p <= j && dp[j - p] + 1 < dp[j]) dp[j] = dp[j - p] + 1;
    }
  }
  return dp[target] === Infinity ? -1 : dp[target];
}
```

**追问**：
1. 如果要返回具体选了哪些商品？→ 加 `choice[]` 记录转移来源，回溯
2. 如果商品有库存限制？→ 换成 0-1 背包 + 逆序，或加一维物品数
3. 如果金额很大（百万级）？→ DP 数组开不下，改用「按价格排序 + 二分 + 贪心近似」并说明不保证最优

**关联原卡**：[ALG-077](../06-算法与手写/ALG-077-满减凑单要选最少数量的商品价格组合恰好凑到目标金.md)、[ALG-204](../06-算法与手写/ALG-204-优惠券组合凑满减-DP.md)

### 第 3 题（25 min）· 秒杀按钮本地预扣 + 对账

**场景**：秒杀商品库存 100 件，用户点按钮要立刻看到"抢到了"，但 1000 人同时点，绝大部分会失败。要求前端有反馈，且**绝不能出现超卖或重复扣减**。

**你要先问的**：允许前端"假装成功"吗？失败后怎么补偿？

**采分点**：
- 明确说「前端不能做库存权威」——本地预扣只是**体验优化**，最终以服务端为准
- 说清三层防护：按钮禁用（体验）→ 幂等键（防重）→ 服务端库存原子扣减（正确性）
- 失败回滚：乐观更新 + 失败时回滚 UI + 提示

**参考方案要点**：
```javascript
// 三层防重：本地锁 → 幂等键 → 服务端
let submitting = false;
async function grab(itemId) {
  if (submitting) return;                    // 1. 本地锁
  submitting = true;
  const idemKey = `${itemId}:${userId}:${Date.now()}`;   // 2. 幂等键
  try {
    const res = await fetch('/api/seckill', {
      method: 'POST',
      headers: { 'Idempotency-Key': idemKey },
      body: JSON.stringify({ itemId }),
    });
    if (!res.ok) throw new Error('failed');
  } finally {
    submitting = false;                      // 3. 无论成败都释放
  }
}
```

**追问**：
1. 用户连点 10 次怎么办？→ 本地锁 + 按钮禁用 + 幂等键三重
2. 网络超时（不知道成功没成功）？→ 拿幂等键去**查询**结果，而不是重试
3. 前端预扣的数量什么时候清？→ 收到服务端结果就清，或超时后自动清

**关联原卡**：[ALG-238](../06-算法与手写/ALG-238-库存秒杀的本地预扣与对账.md)、[ALG-251](../06-算法与手写/ALG-251-表单提交防重的分布式语义.md)、[ALG-163](../06-算法与手写/ALG-163-弱网下用户连点提交订单-重试请求到达两次-后端创.md)

## 套卷二 · 后台管理系统（90 分钟）

### 第 1 题（25 min）· 权限树级联勾选与半选

**场景**：给角色分配权限，勾选父节点自动选中所有子节点；取消一个子节点，父节点显示半选；无权限的叶子节点要隐藏，因它变空的父节点也要级联隐藏。

**你要先问的**：树有多少节点？勾选要不要立即提交？

**采分点**：
- 知道要用**后序 DFS**，一次遍历算出 `全部选中 / 部分选中`，避免每次勾选都全树重算
- 能说清"隐藏空父节点"必须**自底向上**判断（父节点是否为空取决于子节点处理后的结果）
- 能说出优化：维护 `checkedCount`，勾选时只沿父链向上传播，O(depth) 而非 O(n)

**参考方案要点**：
```javascript
// 后序：返回 { all, some }，顺带剪掉空父节点
function computeState(node, hasPermission) {
  const kids = (node.children || []).filter((c) => computeState(c, hasPermission));
  node.children = kids;                          // 已剪枝的子节点

  if (kids.length === 0) {
    const selfChecked = !!node.checked && hasPermission(node);
    return { all: selfChecked, some: false };
  }
  const all = kids.every((c) => c._state.all);
  const some = kids.some((c) => c._state.all || c._state.some);
  node._state = { all, some };
  if (!all && !some) return { all: false, some: false };   // 整个子树无权限 → 剪掉
  node.checked = all;
  node.indeterminate = !all && some;
  return { all, some };
}
```

**追问**：
1. 一次勾选要重算全树吗？→ 不需要，只沿父链传播，O(depth)
2. 如果树叶子上万怎么办？→ 懒加载子节点，半选状态由服务端聚合数给出（不能靠本地未加载数据判断）
3. 反选（全不选）怎么写？→ 同样是后序，或先前序清空再后序回填

**关联原卡**：[ALG-197](../06-算法与手写/ALG-197-权限管理页勾选某个部门后其所有子部门自动选中勾掉.md)、[ALG-223](../06-算法与手写/ALG-223-权限树勾选-受控级联优化.md)、[ALG-341](../06-算法与手写/ALG-341-树形勾选的懒加载半选.md)

### 第 2 题（20 min）· 组织架构树懒加载增量合并

**场景**：组织架构树按需展开，每次展开请求一层子节点。用户展开 A、收起、再展开，或两个分支先后来数据，要求**不重复、不丢数据、保持顺序**。

**采分点**：
- 用 `Map<id, node>` 做**幂等合并**（同一 id 重复返回只保留一份）
- 合并要保留已加载的子树（不能整体替换，否则之前加载的子节点全丢）
- 能说出"顺序"的处理：按服务端返回顺序追加，已存在的不动

**参考方案要点**：
```javascript
function mergeChildren(parent, incoming) {
  const existed = new Map(parent.children.map((c) => [c.id, c]));
  for (const item of incoming) {
    const old = existed.get(item.id);
    if (old) {
      // 幂等：保留已加载的子树，只更新标量字段
      Object.assign(old, { name: item.name, count: item.count });
    } else {
      parent.children.push({ ...item, children: [], loaded: false });
    }
  }
  parent.loaded = true;
}
```

**追问**：并发两次请求同一个节点怎么防？→ 节点上挂 `loadingPromise`（单飞），一样的 key 复用同一个 Promise。

**关联原卡**：[ALG-233](../06-算法与手写/ALG-233-导航菜单的树形懒加载合并.md)、[ALG-341](../06-算法与手写/ALG-341-树形勾选的懒加载半选.md)

### 第 3 题（20 min）· 10 万行日志不卡主线程

**场景**：运维后台要展示 10 万条日志，直接 `appendChild` 会卡死十几秒，还要支持关键词搜索。

**采分点**：
- 三件事必须都说：**虚拟列表**（只渲染可视区）、**分片插入**（`DocumentFragment` + 时间切片）、**搜索放 Worker**
- 能说清"为什么 `DocumentFragment` 有用"——一次重排而不是 10 万次
- 能给出指标：首屏 < 1s，滚动 60fps，搜索 < 300ms

**参考方案要点**：
```javascript
// 分片插入：每片 200 条，让出主线程
function chunkedAppend(container, nodes, chunkSize = 200) {
  let i = 0;
  (function next() {
    const frag = document.createDocumentFragment();
    const end = Math.min(i + chunkSize, nodes.length);
    for (; i < end; i++) frag.appendChild(nodes[i]);
    container.appendChild(frag);              // 一次重排
    if (i < nodes.length) setTimeout(next, 0); // 让出主线程
  })();
}
```

**追问**：搜索 10 万条怎么做到 300ms 内？→ 预建小写索引数组 + `includes` 线性扫（V8 很快），或用 Worker 分片并行；正则要考虑 ReDoS。

**关联原卡**：[ALG-149](../06-算法与手写/ALG-149-运营后台要一次性渲染-10-万条日志-直接-ap.md)、[ALG-169](../06-算法与手写/ALG-169-批量处理-5-万条数据-逐条计算--写缓存-单次.md)、[ALG-189](../06-算法与手写/ALG-189-运营报表要导出-100-万行表格为-CSV-一次.md)

## 套卷三 · IM 与协同（90 分钟）

### 第 1 题（25 min）· 多设备消息合并最近 N 条

**场景**：同一会话在多台设备上各有按时间有序的消息列表，要合并出最近 100 条，且不能有空洞。

**采分点**：
- 识别为**多路归并**：小顶堆（按时间戳）或直接归并两个有序数组
- 能说清"最近 N 条"要从**尾部**开始，或先归并再 slice（注意内存）
- 去重：同一 `msgId` 在多设备都可能出现

**参考方案要点**：
```javascript
// 两路归并取最近 N 条（k 路就用小顶堆）
function mergeRecent(a, b, n) {
  const out = [];
  let i = a.length - 1, j = b.length - 1;
  let lastId = null;
  while (out.length < n && (i >= 0 || j >= 0)) {
    const pickA = j < 0 || (i >= 0 && a[i].ts >= b[j].ts);
    const msg = pickA ? a[i--] : b[j--];
    if (msg.id !== lastId) { out.push(msg); lastId = msg.id; }   // 相邻去重
  }
  return out.reverse();
}
```

**追问**：k 路怎么办？→ 小顶堆存每路当前元素，取最小后推进该路，O(N log k)。**为什么不用全量排序**：全量是 O(M log M)，M 可能是 N 的百倍。

**关联原卡**：[ALG-207](../06-算法与手写/ALG-207-IM-消息合并-堆-多路归并.md)、[ALG-042](../06-算法与手写/ALG-042-两个埋点-SDK-各自按时间升序产出日志链表-要.md)

### 第 2 题（25 min）· 弱网重连与心跳

**场景**：WebSocket 长连接在弱网下会"半开"（TCP 没断但收不到数据）。要求能检测到假死、自动重连、恢复后补拉消息。

**采分点**：
- 心跳用**应用层 ping/pong** + 超时判定（TCP keepalive 太慢，默认 2 小时）
- 重连用**指数退避 + 抖动**，避免全员同时重连打垮服务
- 恢复后按**最后消息序号**补拉，而不是全量重拉
- 能说清"重连上限"和"降级到轮询"

**参考方案要点**：
```javascript
function createHeartbeat(ws, { interval = 15000, timeout = 5000, onDead }) {
  let timer = null, pongTimer = null;

  const ping = () => {
    ws.send(JSON.stringify({ type: 'ping' }));
    pongTimer = setTimeout(() => onDead(), timeout);   // 超时未 pong → 判定假死
  };

  ws.addEventListener('message', (e) => {
    if (JSON.parse(e.data).type === 'pong') {
      clearTimeout(pongTimer);
      pongTimer = null;
    }
  });

  timer = setInterval(ping, interval);
  return () => { clearInterval(timer); clearTimeout(pongTimer); };
}
```

**追问**：
1. 页面切后台心跳会停吗？→ 会，浏览器对后台定时器有节流，所以**恢复前台时要立刻 ping 一次**，别等下一个周期
2. 断线期间用户发的消息怎么办？→ 本地队列 + 幂等键，重连后按序补发
3. 多个标签页都建连接？→ 用 `BroadcastChannel` 选主，只让一个标签页持有连接

**关联原卡**：[ALG-191](../06-算法与手写/ALG-191-WebSocket-长连接在弱网下会半开-TCP.md)、[ALG-157](../06-算法与手写/ALG-157-大促限流后前端集体重试-形成重试风暴把刚恢复的服.md)、[ALG-304](../06-算法与手写/ALG-304-长连接消息的序号保序.md)

### 第 3 题（25 min）· 两人同时编辑同一单元格

**场景**：协同表格，A 和 B 同时改同一格，简单的"最后写入胜出"会丢数据；同时改不同格又不能互相覆盖。

**采分点**：
- 能区分粒度：**单元格级 LWW** 足够，不需要全文 OT/CRDT
- 版本号机制：客户端带 `baseVersion`，服务端冲突返回 409，客户端提示而非静默覆盖
- 能说清"为什么字段级并发写适合 LWW"——粒度小、冲突概率低、语义简单

**追问**：
1. 如果冲突了怎么办？→ 提示用户"该单元格已被修改"，给「覆盖 / 保留我的 / 查看差异」三选
2. 什么时候必须上 OT/CRDT？→ 同一段文本的**字符级**并发插入，LWW 会丢字
3. 离线编辑怎么合？→ 本地操作队列 + 上线重放 + 冲突检测

**关联原卡**：[ALG-162](../06-算法与手写/ALG-162-协同文档两人同时基于-v3-保存-后到的会静默覆.md)、[ALG-281](../06-算法与手写/ALG-281-多标签页的写冲突合并.md)、[ALG-257](../06-算法与手写/ALG-257-滚动加载的分片去重.md)
