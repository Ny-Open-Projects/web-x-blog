# 02 树形数据与级联（ALG-021~034 / 197~198 / 223 / 291 / 321 / 327）

后台系统的骨架就是树：菜单、组织架构、权限点、目录、组件树，全部是"父子关系 + 状态（展开 / 勾选 / 高亮）"。这类题看着花样多，其实只有三个变量：**数据是扁平的还是嵌套的**、**操作改的是结构还是状态**、**能不能一次遍历解决**。把这三点问清楚，90% 的树题都会退化成同一个后序遍历或一次 DFS。**识别特征**：需求里出现「父子 / 层级 / 展开 / 勾选 / 面包屑 / 祖先」时，先画一遍数据形状，再决定用递归还是显式栈。

## 场景 → 算法 映射

## 场景范式

**1. 先问"能不能一次后序遍历解决"。** 剪枝、求深度、算半选、判断子树是否含命中，这些需求的共同形状是「先知道子树的结果，才能决定自己怎么办」。写不出这个后序结构，就会掉进"先递归改一遍、再递归检查一遍"的多次遍历，节点上万时性能直接翻几倍。

**2. 建索引再挂载，是树题最通用的加速器。** `id -> node` 的 Map 一旦建好，扁平转树、O(1) 定位、找父节点、路径回溯全都变成查表。很多"树题很难"的错觉，本质是没建索引，只能一遍遍线性搜索，把 O(n) 写成 O(n²)。

**3. 把"结构操作"和"状态操作"分开。** 增删节点改的是结构，必须重建（不可变）或小心地原地改；展开、勾选、高亮改的是状态，最合适的载体是一个独立于数据的 `Set` / `Map`，按 id 存。混在一起写，就会出现"刷新数据后展开状态丢了""删除节点后勾选集合里残留脏 id"这类问题。

**4. 递归的风险是深度，不是逻辑。** 菜单层级一般不超过十层，递归最直观；但组织架构、评论盖楼、不可信数据可能上千层，会爆栈，这时要换显式栈。另外要留意"共享子树"（同一节点被多个父引用）——它会让朴素递归的复杂度从线性变成指数，需要 memo 或按引用去重。

**5. 搜索过滤的铁律：先判断子树有没有命中，再决定留不留。** 很多人写成"先 filter 掉不匹配的节点，再补祖先"，结果要么祖先找不到、要么把兄弟节点的路径也带进来。正确的是 DFS 返回布尔值：子节点有命中或自己命中，就保留自己，并把过滤后的子节点挂回去；否则返回 null。这一条同时解决了"命中节点子树整体保留"和"兄弟折叠"。

## 精讲（6 题）

### 精讲 1 · [ALG-021] 扁平 `{id, pid}` 转树

**场景**：侧边栏接口返回扁平数组 `[{ id, pid, name }]`，前端要渲染成嵌套的 `children` 结构。

**问法**：为什么很多人写成 O(n²)？数据乱序、父节点不在本批数据里怎么办？

**思路**：朴素写法是对每个节点再去全表找父节点，n² 在几十项菜单上看不出来，但菜单上千项、且每次路由切换都重建时就会卡。正确做法两趟：第一趟建 `id -> 节点` 索引，第二趟把每个节点挂到父节点的 `children` 上，总 O(n)。关键细节是索引里存的必须是**最终要输出的那个对象引用**——如果第一趟存副本、第二趟又新建对象，挂载就挂到了不会被返回的孤儿上，这是最隐蔽的 bug。乱序不是问题，因为两趟都在全量数据上做；真正的问题是"父节点不在本批数据里"（分页、权限裁剪），这时要么当根、要么丢弃，必须显式决定并写进注释，否则会出现"接口有 20 条，页面只显示 3 条"的诡异现象。什么时候不成立：数据量极大且只渲染局部时，不必全量建树，按需向下请求更省内存。

**代码**：

```javascript
// 扁平数组转树：先建索引，再挂载，两趟线性扫描
function listToTree(list, rootPid = null) {
  const map = new Map(); // id -> 节点（含 children 容器），只建一次
  for (const item of list) map.set(item.id, { ...item, children: [] });
  const roots = [];
  for (const item of list) {
    const node = map.get(item.id);      // 用索引里的同一份引用，子节点才能挂上去
    const parent = map.get(item.pid);
    if (item.pid === rootPid || !parent) {
      // pid 是根标记，或父节点不在本批数据里（分页/被裁剪），都当根处理
      roots.push(node);
    } else {
      parent.children.push(node);
    }
  }
  return roots;
}

const flat = [
  { id: 3, pid: 2, name: '详情' },   // 故意乱序：子节点先出现
  { id: 1, pid: null, name: '首页' },
  { id: 2, pid: 1, name: '看板' },
];
console.log(JSON.stringify(listToTree(flat), null, 2));
// [{id:1, name:'首页', children:[{id:2, name:'看板', children:[{id:3, ...}]}]}]
```

**边界与追问**：
- `pid` 为 `0` 和 `null` 的语义可能不同（0 是顶级部门 id，null 才是根），要按接口文档区分。
- 环状数据（a 的父是 b、b 的父是 a）会生成不可达节点，连根都挂不上，需要额外检测并告警。
- `children` 为空时要删掉字段，否则 UI 会画出空箭头、或多渲染一层空容器。

### 精讲 2 · [ALG-026] 权限树级联剪枝

**场景**：后台权限树要求无权限的叶子节点隐藏，因它变空的父节点也级联隐藏。

**问法**：为什么不能一次 `filter` 递归搞定？父节点自己没权限、但有存活子节点时留不留？

**思路**：这是标准后序遍历：先处理完所有子节点，拿到"剪完之后的 children"，再决定自己留不留。判断规则必须写清楚——叶子看自身权限；非叶子只要还有存活子节点就必须保留，因为它成了通往子节点的路径，哪怕它自己没有直接权限。这条就是"隐藏空父级"和"误删整条路径"的分界线，很多实现把两者混在一起，导致有权限的三级菜单整条消失，用户投诉"我明明有权限但看不到入口"。用返回 `null` 表示删除，比返回空对象好，因为空对象会让上层误以为"这个孩子还在"，等到渲染时才发现没有内容。另一个决策是原地改还是返回新树：React 场景返回新树才触发重渲染，但节点多时全量复制有成本，可以只复制被改动的路径（结构共享）。什么时候不成立：剪枝规则依赖"兄弟节点的状态"（比如"同级只剩一个就提升为父级"），那就不是单纯后序，需要额外一趟。

**代码**：

```javascript
// 后序剪枝：先剪子树，再决定自己是否保留；返回 null 表示整棵删除
function pruneTree(node, canKeep) {
  if (!node) return null;
  const children = (node.children || [])
    .map(child => pruneTree(child, canKeep))
    .filter(Boolean); // 丢掉被剪掉的子树
  // 叶子靠权限判断；非叶子只要还有存活子节点，就必须留下当路径
  if (!canKeep(node) && children.length === 0) return null;
  return { ...node, children }; // 返回新对象，保持不可变，便于 React 比对
}

const tree = {
  id: 1, name: '权限管理',
  children: [
    { id: 2, name: '只看', children: [] },
    { id: 3, name: '删除', children: [{ id: 4, name: '批量删除', children: [] }] },
  ],
};
const allowed = new Set([1, 2, 4]); // 3 自己无权限，但 4 有
console.log(JSON.stringify(pruneTree(tree, n => allowed.has(n.id)), null, 2));
// 3 被保留为路径节点，children 只剩 4
```

**边界与追问**：
- 权限可能来自"自身拥有"或"角色继承"，`canKeep` 要把两种来源合并后再判断。
- 搜索结果高亮要求保留命中节点的全部祖先，规则与剪枝不同（祖先不要求有权限），不能复用同一个函数。
- 追问"如何只重渲染变化的分支"：在剪枝时记录哪些 id 的结构变了，只更新对应子树。

### 精讲 3 · [ALG-197] 权限树级联勾选（全选 / 半选）

**场景**：勾选某个部门，所有子部门自动选中；勾掉一个子部门，父部门显示半选（横杠）。

**问法**：为什么布尔值表达不了？每次勾选都全树重算 O(n) 可以接受吗？

**思路**：三态（0 未选 / 1 半选 / 2 全选）是必须的，布尔量表达不了"部分选中"，而半选恰恰是用户判断"我到底授了多少权"的唯一线索。计算方向是自底向上：叶子由勾选集合决定，父节点由子节点汇总——全部子节点为 2 才是 2，有一个非 0 就是 1。勾选动作则是自顶向下：勾一个节点要把整棵子树都塞进 `checkedSet`，取消则整棵移除。两个方向分开写，逻辑就不会互相污染。至于"每次全树重算慢不慢"：1000 个节点一次 DFS 只有几毫秒，真正的瓶颈是"勾选一次触发多次 setState、整页重渲染"，那应该用一次批量更新或 memo 化子树解决，不必为了性能把算法改复杂。什么时候不成立：懒加载树只有部分子节点在内存里，半选不能靠已加载子节点算，必须让后端返回聚合状态。

**代码**：

```javascript
// 三态：0 未选 / 1 半选 / 2 全选；后序汇总，一次 DFS 得到全树状态
function calcState(node, checkedSet) {
  const kids = node.children || [];
  if (kids.length === 0) return checkedSet.has(node.id) ? 2 : 0; // 叶子看勾选集合
  let all = true, some = false;
  for (const child of kids) {
    const s = calcState(child, checkedSet);
    if (s === 0) all = false;
    if (s !== 0) some = true;
  }
  return all ? 2 : some ? 1 : 0; // 全选 / 半选 / 未选
}

// 前序下发：勾选某节点时，整棵子树一起加入或移除
function toggleSubtree(node, checkedSet, checked) {
  const method = checked ? 'add' : 'delete';
  checkedSet[method](node.id);
  for (const child of node.children || []) toggleSubtree(child, checkedSet, checked);
}

const tree = {
  id: 'dept', children: [
    { id: 'a', children: [] },
    { id: 'b', children: [] },
  ],
};
const checked = new Set();
toggleSubtree(tree.children[0], checked, true); // 只勾了 a
console.log(calcState(tree, checked));          // 1（半选）
toggleSubtree(tree.children[1], checked, true); // 再勾 b
console.log(calcState(tree, checked));          // 2（全选）
```

**边界与追问**：
- 父子同时被勾选时以谁为准？"只勾父不勾子"通常表示只授父级菜单权限，回填时要能区分。
- 回填只回填叶子，还是把半选父节点也放进集合，会影响再次提交时的权限集合，必须和后端对齐。
- 追问"如何只更新受影响的节点"：沿被勾节点的父链向上重算，O(depth)，其余子树状态不变。

### 精讲 4 · [ALG-022] 树转扁平并携带根路径

**场景**：面包屑组件要把菜单树还原成扁平列表，每项带上从根到自己的路径 `['首页', '设置', '安全']`。

**问法**：为什么 `path` 数组必须复制一份？不用递归怎么写？

**思路**：DFS 时维护一个 `path` 栈，进入节点 `push`、离开 `pop`，栈里的内容天然就是"根到当前"的路径，不需要每层都传一个新数组，空间是 O(depth) 而不是 O(n·depth)。最易错的地方是把 `path` 直接引用存进结果：后续的 `push` / `pop` 会改掉已经存下来的路径，最后所有条目都指向同一条（通常是最后访问的那条）路径——这种 bug 在小数据下看着对，数据一多就全错。要么每次 `path.slice()`，要么先存 `path.length` 快照、最后统一物化。用显式栈也能做，但要手动记录"何时回溯"，代码更长且容易漏，节点层级一般不超过几十层，递归完全够用。什么时候不成立：需要按"层"而不是按"路径"输出时（每层一个分组），BFS 更自然。

**代码**：

```javascript
// 树转扁平 + 根路径：DFS 用数组当栈，进出各一次，避免层层复制
function flattenWithPath(roots) {
  const out = [];
  const path = []; // 当前递归栈 = 根 -> 当前节点
  const dfs = (node) => {
    path.push({ id: node.id, name: node.name });
    out.push({
      id: node.id,
      name: node.name,
      depth: path.length - 1,
      path: path.map(p => p.name),  // 复制：不复制会被后续 pop 改掉
      pathIds: path.map(p => p.id),
    });
    for (const child of node.children || []) dfs(child);
    path.pop(); // 回溯：兄弟分支不会带错路径
  };
  for (const root of roots) dfs(root);
  return out;
}

const tree = [{
  id: 1, name: '首页', children: [
    { id: 2, name: '设置', children: [{ id: 3, name: '安全', children: [] }] },
    { id: 4, name: '报表', children: [] },
  ],
}];
const rows = flattenWithPath(tree);
console.log(rows.find(r => r.id === 3).path); // ['首页','设置','安全']
console.log(rows.find(r => r.id === 4).path); // ['首页','报表'] —— 没有残留
```

**边界与追问**：
- 根节点的 `path` 是 `[root]` 还是 `[]`，前端和设计稿要对齐，否则面包屑会少一级或多一级。
- 同名节点必须用 `pathIds` 判断唯一位置，用名称拼字符串会撞车。
- 大树上 `map` 复制是 O(n·depth) 的额外分配，可以改成只在需要展示时才物化路径。

### 精讲 5 · [ALG-031] 多叉树序列化与还原

**场景**：在线画布要把节点树存成字符串（localStorage / URL / 协同消息），刷新后原样还原。

**问法**：既然有 `JSON.stringify`，为什么还要手写？分隔符出现在节点内容里怎么办？

**思路**：树本身无环，`JSON.stringify` 完全能存，但很多场景需要更紧凑、可跨语言、可校验的格式——比如塞进 URL 参数、塞进配额紧张的 storage 键、或者要和后端/C++ 端交换。手写时选"前序 + 每个节点的子节点数"这种自描述格式：读到一个 token 就知道后面要消费几个孩子，反序列化可以纯递归，不需要额外括号配对，也不会因为少一个分隔符而整体错位。内容里的分隔符必须转义，用 `encodeURIComponent` 最省事，比自定义转义表不容易漏（自己写经常漏 `%`、`,`、`|`）。JSON 的优势是可读、有现成解析器；自定义格式的优势是体积小、键顺序固定（方便做 diff 或签名）。什么时候不成立：节点带有函数、Date、Map 等非 JSON 类型时，得先约定类型标记，否则还原出来是字符串。

**代码**：

```javascript
// 前序序列化：每个节点编码为 "名称|子节点数"，名称用 encodeURIComponent 转义
function serialize(root) {
  const parts = [];
  const walk = (node) => {
    if (!node) return;
    const kids = node.children || [];
    parts.push(`${encodeURIComponent(node.name)}|${kids.length}`); // 自描述：知道要读几个孩子
    for (const child of kids) walk(child);
  };
  walk(root);
  return parts.join(','); // 逗号分隔 token，内容里的逗号已被转义
}

function deserialize(str) {
  if (!str) return null;
  const tokens = str.split(',');
  let i = 0;
  const build = () => {
    const [name, count] = tokens[i++].split('|'); // 前序：先取自己，再依次取孩子
    const node = { name: decodeURIComponent(name), children: [] };
    for (let k = 0; k < Number(count); k++) node.children.push(build());
    return node;
  };
  const root = build();
  return i === tokens.length ? root : root; // 生产环境可校验是否恰好消费完
}

const canvas = { name: '页面', children: [{ name: '头部, 标题', children: [] }] };
const s = serialize(canvas);
console.log(s);                                  // %E9%A1%B5%E9%9D%A2|1,%E5%A4%B4%E9%83%A8%2C%20%E6%A0%87%E9%A2%98|0
console.log(JSON.stringify(deserialize(s)));     // 原样还原，逗号没被切断
```

**边界与追问**：
- 特殊字符（逗号、竖线、emoji 代理对）必须做一次"序列化→反序列化"往返测试，尤其是 `%` 本身。
- 超深树递归会爆栈，改成显式栈 + 待消费计数；格式要带 `version` 字段，否则老数据打不开。
- 追问"如何支持协同编辑"：节点需要稳定 id，序列化只传 id 和字段增量，不要传整棵树。

### 精讲 6 · [ALG-321] URL 直达深层节点

**场景**：分享链接带 `?path=1/5/23`，打开后要逐级展开到该节点并滚动定位、高亮。

**问法**：路径里某一级 id 已被删除怎么办？同步调用 `scrollIntoView` 为什么滚不准？

**思路**：要做三件事——把 id 链解析成数组、把祖先链变成展开集合、定位目标节点。展开集合要包含"祖先 + 自己"：只有父节点展开，子节点才可见；目标节点本身也要展开，否则它的子节点（如果还要继续定位）看不见。实现上先建 `id -> node` 和 `id -> parentId` 两张索引，再沿目标节点向上走，O(depth) 就得到展开集合，比从根往下递归找路径更稳（不依赖树是否完整、不会因为某层被剪枝而中断）。滚动定位必须等展开后的 DOM 渲染完成，同步调用 `scrollIntoView` 拿到的是旧布局，会滚到错误位置——这是这类需求最常见的"偶现滚偏"。什么时候不成立：如果路径是"名称路径"而不是 id 路径，改名就会失效，只能作为降级手段。

**代码**：

```javascript
// ?path=1/5/23 直达：解析 id 链 -> 祖先展开集合 -> 定位目标
function buildExpandState(roots, idPath) {
  const nodeOf = new Map();
  const parentOf = new Map();
  const walk = (node, parentId) => {
    nodeOf.set(node.id, node);
    parentOf.set(node.id, parentId);       // 父指针比反复搜树更可靠
    for (const child of node.children || []) walk(child, node.id);
  };
  for (const root of roots) walk(root, null);

  const expanded = new Set();
  let cur = idPath[idPath.length - 1];
  while (cur != null) {
    expanded.add(cur);                     // 祖先 + 自己都要展开
    cur = parentOf.get(cur);
  }
  // 数据被删/被裁剪时降级：只保留仍然存在的前缀，不要整页报错
  const validPath = idPath.filter(id => nodeOf.has(id));
  return { expanded, validPath, target: nodeOf.get(idPath[idPath.length - 1]) || null };
}

const tree = [{ id: 1, children: [{ id: 5, children: [{ id: 23, children: [] }] }] }];
const { expanded, target } = buildExpandState(tree, [1, 5, 23]);
console.log([...expanded], target?.id);  // [23, 5, 1] 23
// 真实场景：setExpanded(expanded) 后，在 useEffect / requestAnimationFrame 里再 scrollIntoView
```

**边界与追问**：
- 路径非法时降级到最长合法前缀，并给一个"该内容已删除"的提示，比白屏友好。
- 同一 URL 反复直达要幂等：先重置再合并展开集合，避免上一次的展开残留。
- 浏览器前进/后退只改 query 时组件不会重挂载，必须在 query 变化时重新计算，而不是只在 `mounted` 里读一次。
