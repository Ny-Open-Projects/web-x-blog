# 06 图与并查集（ALG-088~095 / 203 / 226 / 270）

图论在前端最常见的形态不是"求最短路"，而是**依赖与关系**：组件互相引用、构建任务互相等待、好友互相连通、推荐位互相冲突、请求区间互相重叠。这些需求的口语版本都很朴素——"能不能一起加载""分几组""先跑谁""谁和谁是一伙的"——但落到代码上就是建图 + 一次遍历。**识别特征**：出现「依赖 / 引用 / 连通 / 分组 / 冲突 / 最短 / 环」这七个词中的任意一个，先想图；出现「关系可以传递」且要反复查询，先想并查集。

图题最容易翻车的不是算法，而是三个工程细节：**建图方向**（谁指向谁决定了拓扑序和入度）、**去重与自环**（重复边会让入度算错）、**递归深度**（网格 DFS 在超大画布上直接爆栈）。面试时把这三点点出来，比背出 Dijkstra 更能体现你在真实项目里踩过坑。

## 场景范式

**1. 建图三选一，先问"边有多少"。** 稀疏图（依赖关系，通常 E ≈ V）用邻接表 `Map<id, id[]>`；稠密图或需要 O(1) 判边用邻接矩阵；网格 / 棋盘这类"位置即节点、相邻即边"的题不建图，直接在遍历时算四个方向，省一半内存。前端业务 95% 是邻接表。

**2. 连通性问题的选型口诀：静态一次 → DFS/BFS；动态加边 + 反复查询 → 并查集。** 岛屿数量只算一次，DFS 沉岛最快；好友关系会不断新增（"加好友"接口持续来），每次加完都要回答"这两个人是不是一伙的"，并查集的近似 O(1) 才有意义。用 DFS 做动态连通，每次查询都要重扫，复杂度直接劣化一个量级。

**3. 有向图先想拓扑，环检测看两个信号。** Kahn 算法里"最终出队数 < 节点数"就说明有环；DFS 三色法里"遇到灰色节点"就说明回到了当前递归栈上。前者顺手给出执行顺序，后者顺手给出环上的具体路径——要"报错信息友好"就用 DFS，要"排执行计划"就用 Kahn。

**4. 最短路按边权选算法。** 无权（每跳成本一样）用 BFS，一层层扩散；非负权用 Dijkstra；有负权才需要 Bellman-Ford / SPFA。前端场景（路由跳转成本、加载耗时）全是非负的，Dijkstra + 小顶堆足够了，别上来就写 Floyd。

**5. 二分图 = "能否分成互不冲突的两组"。** BFS 染色，邻居必须反色，发现邻居和自己同色就失败。它和"区间调度"看起来都是分组，但二分图判的是**冲突关系**（边表示不能同组），区间调度判的是**资源占用**（重叠表示不能同时），别混。

## 精讲（6 题）

### 精讲 1 · [ALG-088] 深拷贝带循环引用的组件图

**场景**：低代码平台的组件关系图里，父组件持有子组件引用，子组件又通过 `parent` 指回父组件。`JSON.parse(JSON.stringify())` 直接抛 `Converting circular structure to JSON`，普通递归深拷贝会无限递归直到栈溢出。

**问法**：克隆一个可能带环的对象图，要求新图与原图结构同构、且不与原图共享任何引用。

**思路**：递归本身没问题，问题在于"同一个节点被访问第二次时该怎么办"。引入 `Map<原节点, 克隆节点>`，并且**在递归子节点之前**就把克隆体注册进 Map。这一步顺序是关键：如果先递归再注册，遇到环时子节点又会去克隆父节点，环断不开；先注册"占位"，第二次遇到同一节点时直接返回已存在的克隆体，环自然被接上。

**为什么用 Map 而不是数组**：键是对象引用，`WeakMap` 还能在源对象被回收后自动释放，长生命周期的编辑器更适合 `WeakMap`。用 `JSON` 序列化做 key 不行——循环引用正是它处理不了的。

**遍历方式**：DFS 递归最直观；图很深（组件嵌套上千层）时改成显式栈 BFS，避免爆栈。

```javascript
function cloneGraph(node, map = new Map()) {
  if (node === null || typeof node !== 'object') return node; // 原始值直接返回
  if (map.has(node)) return map.get(node);                    // 环：已克隆过，直接复用
  const copy = Array.isArray(node) ? [] : {};
  map.set(node, copy);        // 关键：先注册占位，再递归子节点
  for (const key of Object.keys(node)) {
    copy[key] = cloneGraph(node[key], map); // 自引用会命中 map，返回 copy 本身
  }
  return copy;
}
```

**边界与追问**：`Date` / `RegExp` / `Map` / `Set` / `ArrayBuffer` 不是普通对象，需要按类型分支处理，否则会被拍成空对象；原型链要不要保留（`Object.create(Object.getPrototypeOf(node))`）取决于是否保留类方法；函数无法克隆，通常直接共享引用并在注释里写明。追问"环上的两个节点克隆后还指向彼此吗"——是，这正是先注册占位的目的，可以现场用 `copy.a.b === copy` 验证。

### 精讲 2 · [ALG-089] 画布重叠格子：合并后有几个独立区域

**场景**：白板上散落着一些占位格子（`1` 表示被占用），上下左右相邻的算同一块。用户问"这块画布上到底有几处独立的图形"，用于批量操作与统计。

**问法**：给定 0/1 二维网格，返回四连通块的个数。

**思路（沉岛法）**：外层双循环扫描，每遇到一个 `1`，计数器 +1，然后从这个格子开始 DFS，把能走到的所有 `1` 全部改成 `0`。这样同一块区域只会在"第一个被扫到的格子"上计一次数，后续扫描不会再重复计数。本质是"用染色代替 visited 数组"，省一份 O(rows×cols) 的内存。

**为什么四连通而不是八连通**：斜对角相邻算不算同一块是业务定义，图像处理常按八连通，UI 布局按四连通。面试时先问一句"斜着挨着算不算一块"，是加分项。

**复杂度**：时间 O(rows×cols)（每个格子最多被访问常数次），空间 O(rows×cols)（递归栈最坏退化成一条蛇形路径）。

**递归的风险**：1000×1000 全是 `1` 的网格，DFS 深度可达 10⁶，浏览器直接 `Maximum call stack size exceeded`。工程上换 BFS（显式队列）或并查集，这一点必须主动说。

```javascript
function countIslands(grid) {
  if (!grid.length || !grid[0].length) return 0;
  const rows = grid.length, cols = grid[0].length;
  let count = 0;
  const dfs = (r, c) => {
    if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] !== 1) return;
    grid[r][c] = 0;              // 沉岛：标记已访问，避免重复计数
    dfs(r + 1, c); dfs(r - 1, c);
    dfs(r, c + 1); dfs(r, c - 1);
  };
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === 1) { count++; dfs(r, c); }
    }
  }
  return count;
}
```

**边界与追问**：空网格返回 0；单行 / 单列是一条线性链，DFS 深度 = 长度，最容易爆栈。追问"不能修改入参怎么办"——用 `Set<string>` 存 `r*cols+c` 或单独开 `visited` 数组。追问"要返回每块的面积 / 边界框"——DFS 时累计计数与 min/max 坐标即可。追问"动态增删格子后实时查询块数"——换并查集，加格子时 union 四个邻居，删格子则只能重算（并查集不支持删除，这说明选型要跟着操作类型走）。

### 精讲 3 · [ALG-091] 好友传递性归组：并查集

**场景**：社交功能要展示"你可能认识的人"和"好友圈子"。A 与 B 是好友、B 与 C 是好友，则 A、B、C 属于同一个圈子（关系可传递）。好友关系会持续新增，页面随时要问"这两个人是不是一个圈子"以及"一共几个圈子"。

**问法**：实现 `union(a,b)` / `find(x)` / `count()`，支持动态加边与实时查询。

**思路**：每个元素维护一个父指针，初始指向自己。`find` 沿父指针一直走到根（根的特征是 `parent[x] === x`），根相同的两个元素就在同一组。`union` 把两个根连起来，组数减一。

**两个优化（必须都讲）**：路径压缩——`find` 时把沿途节点直接挂到根上，让树变扁，下次查询 O(1)；按秩 / 按大小合并——把矮树挂到高树下，避免退化成链表。两者叠加后单次操作摊还 O(α(n))，α 是反阿克曼函数，对任何现实输入都小于 5，可以认为常数。

**为什么不用 DFS 求连通块**：静态图用 DFS 完全够，但这里是"边一条条加、查询随时来"。DFS 每次都 O(V+E)，加 1 万条边就是 1 万次全图扫描；并查集每次 union 几乎 O(1)。

```javascript
class UnionFind {
  constructor(n) {
    this.parent = Array.from({ length: n }, (_, i) => i);
    this.size = new Array(n).fill(1); // 按集合大小合并
    this.count = n;                   // 当前组数
  }
  find(x) {
    while (this.parent[x] !== x) {
      this.parent[x] = this.parent[this.parent[x]]; // 路径压缩（隔代指向）
      x = this.parent[x];
    }
    return x;
  }
  union(a, b) {
    const ra = this.find(a), rb = this.find(b);
    if (ra === rb) return false;      // 已同组，重复边不入账
    if (this.size[ra] < this.size[rb]) { this.parent[ra] = rb; this.size[rb] += this.size[ra]; }
    else { this.parent[rb] = ra; this.size[ra] += this.size[rb]; }
    this.count--;                     // 合并成功才减组数
    return true;
  }
}
```

**边界与追问**：`n = 0` 时 `count` 为 0，别把 `new Array(0)` 当成错误；自环 `union(a,a)` 返回 false 且不减 count，这是判重的关键；重复边同理不会让组数变负。追问"要返回每个圈子的成员列表"——遍历所有元素按 `find(i)` 分桶。追问"朋友圈要支持删好友"——并查集不支持拆分，只能对删边后的图重建，或者改成"离线倒序加边"（把删除操作逆序变成加边），这是进阶考点。

### 精讲 4 · [ALG-092] 页面跳转最短路径：Dijkstra

**场景**：后台权限页之间的跳转有成本（有的要跨模块、有的要二次鉴权），产品要求算出"从首页到任意页面最少要点几下 / 最少耗时"，用于优化导航层级。

**问法**：给定带非负权的有向图与起点，返回起点到所有节点的最短距离。

**思路**：维护 `dist` 表（起点 0，其余 Infinity）与"已确定"集合。每轮从未确定的节点中取 `dist` 最小的 `cur`，它的最短距离此刻已经确定（因为其他路径都要经过距离更大的点，不可能更短），然后用它去松弛邻居：`dist[cur] + w < dist[v]` 就更新。重复 V 轮。

**为什么不能有负权**：上面"取最小即确定"的论证依赖"绕路只会更长"。有负边时，一条更长的路径加一段负边可能反而更短，贪心地"确定"就错了——这时候要用 Bellman-Ford。

**复杂度**：线性扫最小是 O(V²)；用小顶堆（优先队列）维护候选，每条边最多入堆一次，降到 O((V+E)logV)。前端图规模小（几百个页面），O(V²) 反而更快，因为没堆的常数开销，这一点可以主动提。

```javascript
// graph: { A: [['B', 2], ['C', 5]], B: [['C', 1]] } —— 邻接表，边权非负
function dijkstra(graph, start) {
  const nodes = Object.keys(graph);
  const dist = {}, visited = {};
  for (const v of nodes) dist[v] = Infinity;
  dist[start] = 0;
  for (let k = 0; k < nodes.length; k++) {
    let cur = null;
    for (const v of nodes) {                       // 线性选最小（小图更快）
      if (!visited[v] && (cur === null || dist[v] < dist[cur])) cur = v;
    }
    if (cur === null || dist[cur] === Infinity) break; // 剩余节点不可达
    visited[cur] = true;                           // 此刻 dist[cur] 已是最优
    for (const [next, w] of graph[cur] || []) {
      if (dist[cur] + w < dist[next]) dist[next] = dist[cur] + w;
    }
  }
  return dist;
}
```

**边界与追问**：起点不在图里时返回全 Infinity，要显式报错而不是静默；邻居节点未在 `graph` 里声明（只有入边没有出边）时 `dist[next]` 是 `undefined`，比较会失败，所以建图时要把所有出现过的节点都补成空数组。追问"要还原路径"——额外存 `prev[v] = cur`，最后从终点倒推。追问"要多个起点"——加一个虚拟源点连所有起点、边权 0，或者初始 `dist` 全设 0。

### 精讲 5 · [ALG-093] 竞品推荐位分两组：二分图染色

**场景**：活动页要把推荐位分成 A/B 两组轮播，互为竞品的两个推荐位不能同组（避免同类商品撞车）。产品问"能不能分"，运营问"分不出来是哪两个位冲突"。

**问法**：给定无向冲突边，判断图是否二分；能分则返回每个节点的组别，不能分则返回一条冲突边。

**思路**：对每个未染色的连通分量，任取一点染 1，BFS 扩散时邻居必须染 `-1`（反色）；如果邻居已经染色且颜色与自己相同，说明出现了奇环，无法二分（奇环上绕一圈会要求首尾异色，矛盾），立即返回冲突边。**必须遍历所有连通分量**，只从一个点出发会漏掉不连通的子图，这是本题最常见的失分点。

**复杂度**：O(V+E)，每条边访问两次。

**为什么是"奇环"**：二分图等价于"不含奇环"。三角形（3 个互相冲突的推荐位）就是最小反例——三选二必须有一对同组，而它们又互相冲突，无解。运营听到这个解释比听"奇环"更容易接受。

```javascript
function twoColor(n, edges) {
  const adj = Array.from({ length: n }, () => []);
  for (const [a, b] of edges) { adj[a].push(b); adj[b].push(a); }
  const color = new Array(n).fill(0);   // 0 未染色，1 / -1 两组
  for (let s = 0; s < n; s++) {         // 关键：每个连通分量都要处理
    if (color[s] !== 0) continue;
    color[s] = 1;
    const queue = [s];
    for (let head = 0; head < queue.length; head++) {
      const u = queue[head];
      for (const v of adj[u]) {
        if (color[v] === 0) {           // 未染色 → 染反色并入队
          color[v] = -color[u];
          queue.push(v);
        } else if (color[v] === color[u]) {
          return { ok: false, conflict: [u, v] }; // 同色相邻 = 奇环
        }
      }
    }
  }
  return { ok: true, color };
}
```

**边界与追问**：无边图（全是孤立点）一定可以二分，每个点随便分；自环 `[a,a]` 一定失败，要在建图时先拦掉并给出"这个推荐位和自己冲突"的友好报错。追问"要分得尽量均衡"——二分图染色只保证合法，不保证均衡；均衡分组是 NP-hard 的（等价于最小割的近似），实际业务会用贪心：按度数从大到小依次放到当前人少的一组。追问"三个组怎么办"——三染色是 NP-complete，不能套这个模板，要如实说。

### 精讲 6 · [ALG-095] 构建流水线：拓扑排序 + Promise 并行

**场景**：构建平台里任务有依赖（`a` 完成后才能跑 `b`），无依赖的任务应该立刻并行，某任务的所有依赖完成后立刻解锁。串行执行浪费几分钟，全并行又会因为依赖未就绪而失败。

**问法**：给定 `tasks = { id: { deps: [...], run: async () => {} } }`，按依赖顺序执行，同层并行，返回执行顺序；有环则抛错。

**思路**：先建两张表——`indeg[id]`（还差几个依赖）和 `children[id]`（我完成后能解锁谁）。入度为 0 的进"就绪层"，用 `Promise.all` 整层并行跑；一层结束后，把这一层所有节点的孩子的入度减 1，减到 0 的组成下一层。循环直到就绪层为空。最后检查已完成节点数是否等于总数：不等说明剩下的节点互相等待，即存在循环依赖，直接抛错而不是静默死等——这是工程上最重要的一句。

**为什么分层而不是"完成一个立刻解锁一个"**：分层实现最简单、可预测；"完成即解锁"（事件驱动）吞吐更高但代码复杂。面试先给分层版，再说明可以改成"每个任务完成后触发一次 `check`"。

**复杂度**：O(V+E) 建图 + 实际执行时间；轮数最多 V 层。

```javascript
async function runPipeline(tasks) {
  const indeg = {}, children = {};
  for (const id in tasks) { indeg[id] = 0; children[id] = []; }
  for (const id in tasks) {
    for (const dep of tasks[id].deps) {
      if (!(dep in tasks)) throw new Error(`依赖不存在: ${dep}`);
      indeg[id]++;                 // 注意方向：dep → id
      children[dep].push(id);
    }
  }
  let ready = Object.keys(tasks).filter(id => indeg[id] === 0);
  const order = [];
  while (ready.length > 0) {
    const layer = ready;
    await Promise.all(layer.map(id => tasks[id].run())); // 同层并行
    for (const id of layer) order.push(id);
    const next = [];
    for (const id of layer) {
      for (const child of children[id]) {
        if (--indeg[child] === 0) next.push(child);      // 全部依赖就绪才解锁
      }
    }
    ready = next;
  }
  if (order.length !== Object.keys(tasks).length) {
    throw new Error('存在循环依赖，流水线无法启动');
  }
  return order;
}
```

**边界与追问**：空任务表返回空数组；某个 `run` reject 时 `Promise.all` 会立即失败，但同层其他任务仍在跑（无法真正取消 Promise），要配合 `AbortController` 或让任务自己检查取消信号；重复依赖（`deps: ['a','a']`）会让入度多算一次导致永远无法归零，建图时用 `Set` 去重。追问"要限制并发数"——分层内部再加一个信号量池，每层最多 4 个同时跑。追问"如何指出环上的节点"——Kahn 只能告诉你"有环"，要给出路径得换成 DFS 三色法（见 ALG-203）。
