# 场景算法专题 · 总索引

> **10 个专题 · 精讲 60 题 · 550 张原卡全覆盖 · 3 套模拟卷**

> 与 `18-经典算法题库` 的分工：18 练**手法**（模板怎么写），19 练**选型**（什么需求用什么结构）。

## 先读这个

## 每个专题的信息结构

| 板块 | 作用 |

| **[12-原卡全量索引](12-原卡全量索引.md)** | 550 张卡一张不漏，按「归属专题」筛选即可捞出本专题的其余原卡 |

## 怎么用（推荐顺序）

```
第 1 步 读 _prep/10-场景算法冲刺手册 的第 2 节（映射总表）
第 2 步 按专题顺序做：01 → 02 → 03 → 04 → 05，每专题读范式 + 手写 2 道精讲
第 3 步 做 11-场景算法模拟卷 的第一套，限时 90 分钟，全程口述
第 4 步 对答案，把"卡在哪一步"填进复盘表
第 5 步 针对性补：选型错 → 回看映射表；写不出 → 回 18 目录补模板
```

## 与「经典算法」的配合

| 知道用什么方法但写不出来 | `18` 对应题型文件，手写 3 遍 |
| 写得出但不知道真实场景怎么用 | **本目录**，重点看"场景 → 算法映射"和范式 |
| 面试被问"你的方案有什么问题" | **本目录**的"边界与追问" + `_prep/10` 第 5 节五个错 |

## 常见误区

1. **把场景题当 LeetCode 做** —— 上来就写代码，不问数据量。数据量决定复杂度上限，**不问就是错的**。
2. **过度设计** —— 几百条数据上线段树。正确说法是"当前量级哈希就够，到百万级再换"。
3. **只给一种解法** —— 场景题没有唯一解，只给一种显得没想过替代方案。
4. **忽略真实约束** —— 只说算法不说内存、首屏、交互体验。
5. **答完就停** —— 不主动说"如果数据翻 100 倍怎么办"。
