# 10 高级数据结构专项（ALG-351 ~ ALG-550）

> 线段树、树状数组、KMP/AC 自动机、数位 DP、贪心体系——这五类东西在前端面试里从来不是"必考"，而是**加分项**。它们真正考察的不是你能不能默写模板（模板一周不写就忘），而是：拿到一句业务描述，你能不能在 30 秒内判断"这题该不该上重结构"。看见"任意区间求和 + 单点会变"就想到树状数组，看见"区间赋值 + 查询最值"就知道 BIT 干不了，看见"两万敏感词"就知道逐词 `indexOf` 是灾难——这个判断力才是可迁移的。所以本文的组织方式是 **数据结构 → 适用场景 → 复杂度 → 代表原卡**，六道精讲只用来把判断力落到代码上，剩下 194 张卡按族归档，供你按需回查。

## 一、先回答一个问题：这条需求值不值得上数据结构

上重结构之前，先过四道闸门，任何一道能过，就可以省掉一整棵树：

1. **操作数够不够多？** 1000 个元素、每次渲染查 5 次，直接 `arr.slice(l, r).reduce()` 就够了，O(n) 的常数极小。真正需要 O(log n) 的量级是"查询 10⁴~10⁶ 次、数据还在变"。
2. **能不能离线？** 所有查询一次性给齐，就可以排序 + 扫描线 + 前缀和，不需要在线结构。前端大多数报表都是离线的，别上来就写线段树。
3. **合并运算可不可逆？** 求和可逆（前缀和相减），最值、最长连续段、GCD 不可逆——可逆的用前缀和/差分降级到 O(1)，不可逆的才需要树。
4. **数据是在线到达的吗？** 流式数据（埋点、弹幕、行情）只能增量维护，这是 BIT / 线段树 / 堆的主场；批量数据永远先想排序。

这四问答完，方案基本就定了。面试时把这四问说出来，比直接写代码更能证明你在做工程判断，而不是在背题。

## 二、数据结构选型表（核心）

| 需求信号（你会听到的话） | 首选结构 | 单次操作 | 不该用的信号 | 代表原卡 |
|---|---|---|---|---|
| "数组不变，反复查区间和" | 前缀和 | O(1) 查询 / O(n) 预处理 | 数据会改 → 别用，改一次 O(n) | ALG-351 |
| "单点会改，反复查区间和" | 树状数组 BIT | O(log n) | 需要区间赋值/最值 → BIT 干不了 | ALG-391 |
| "区间批量加，最后查每个点" | 差分数组 | O(1) 改 / O(n) 收口 | 要在线查中间态 → 用 BIT 差分 | ALG-392 / 540 |
| "区间批量加，还要查区间和" | 双 BIT 或懒标记线段树 | O(log n) | 只要单点查 → 单 BIT 就够 | ALG-393 / 352 |
| "区间整体赋值/覆盖，再查最值" | 懒标记线段树（可覆盖标记） | O(log n) | 用 BIT 会算错，赋值不可差分 | ALG-355 |
| "区间最值 + 单点修改" | 线段树 | O(log n) | 完全静态 → ST 表 O(1) 更划算 | ALG-353 |
| "固定窗口滑动求最值" | 单调队列 | 摊还 O(1) | 窗口长度不固定 → 线段树/稀疏表 | ALG-386 / 525 |
| "区间内最长连续 / 最大子段和" | 区间合并线段树（pre/suf/best） | O(log n) | 前缀和无法表达跨段拼接 | ALG-357 / 383 |
| "动态第 k 小 / 实时中位数" | 权值线段树或 BIT 上二分 | O(log V) | 数据静态 → 排序后直接取下标 | ALG-360 / 397 |
| "值域 10⁹ 但只出现几千个" | 动态开点 / 离散化 / Map 版 BIT | O(log n) | 直接开 10⁹ 数组会 OOM | ALG-359 / 363 / 414 |

| "多个矩形求并集面积" | 扫描线 + 线段树（cover 计数） | O(n log n) | 矩形很少（< 100）→ 暴力枚举 | ALG-358 |
| "在长文本里找一个模式串" | KMP | O(n + m) | 只找一次且文本短 → indexOf 更快 | ALG-421 / 422 |
| "一次扫描匹配几千个敏感词" | AC 自动机（Trie + fail） | O(文本长 + 命中数) | 词库只有几个 → 逐个 indexOf | ALG-423 / 424 |
| "多次判断两段子串是否相等" | 字符串哈希（+ 二分） | O(1) 比较 | 有碰撞要求绝对正确 → 后缀数组 | ALG-427 / 429 |
| "最长回文子串" | Manacher | O(n) | 只需判整体回文 → 双指针 O(n) | ALG-430 |
| "前缀统计 / 联想词" | Trie | O(词长) | 只需要精确匹配 → Set 足够 | ALG-433 |
| "统计 [1, N] 里满足数位条件的数" | 数位 DP | O(位数 × 状态) | N < 10⁵ → 直接暴力枚举 | ALG-451 |
| "求第 N 个合法编号" | 数位 DP + 计数二分 | O(位数 × 状态 × log N) | 只要计数 → 普通数位 DP | ALG-461 |

| "选了之后发现更优要能换掉" | 反悔贪心（堆） | O(n log n) | 有后效性 → 只能 DP | ALG-483 / 511 |

这张表最该背的是**第三列**：面试官问"为什么这里用线段树不用 BIT"，标准答案是"因为我要维护区间最长连续 1，这个信息不可差分，BIT 只能维护可减的聚合"——一句话就分清了你和背模板的人。

## 三、场景范式（五条）

**范式 1：把"操作数 × 单次成本"算出来再选型。** 10⁵ 次查询 × O(n)=10¹⁰，必然超时；O(log n) 是 1.7×10⁶，随便跑。前端还要乘一个渲染帧预算：一帧 16ms 内能做的循环大约是 10⁶ 次简单运算，超过就得挪到 Worker 或预计算。

**范式 2：结构的形状由"合并律"决定。** 只要聚合函数满足结合律（和、max、gcd、矩阵乘），就能用线段树；再满足**可逆**（有逆元），才能用 BIT 或前缀和。所以"区间加 + 区间求和"两种都能做，"区间赋值 + 区间最值"只能线段树，"区间众数"两者都不行（不可合并），只能分块近似。

**范式 3：在线与离线是两条完全不同的路。** 离线可以排序、可以按右端点扫描、可以把查询挂到时间轴上（ALG-398 的"区间不同数个数"就是经典离线题）；在线必须增量维护。面试里先问一句"查询是一次性给齐还是随时来"，方案立刻清晰。

**范式 4：值域结构和下标结构要分清。** 线段树的下标是"位置"，权值线段树的下标是"值"，两者代码几乎一样但语义完全不同——这是最高频的概念混淆点。判断方法：你要查的东西是"第几个"还是"多大"。

**范式 5：永远给一个退化方案。** n 很小用暴力、只需要一次用排序、离线用前缀和。能在答案末尾补一句"如果 QPS 只有几十，我会直接用暴力 + 缓存，不上树"，说明你知道复杂度是为了解决问题，不是为了炫技。

## 四、精讲（6 题）

### 精讲 1 · [ALG-352] 懒标记线段树：区间加 + 区间求和

**场景**：弹幕频道按小时段管理配额，运营一次操作把 [10:00, 12:00] 的所有小时段各加 100，同时看板要随时展示任意时段的配额总和。区间改、区间查，两个都发生几十万次。

**问法**：为什么不能每次区间加都逐个点更新？懒标记到底"懒"在哪里？标记什么时候下推？

**思路**：逐个点更新是 O(区间长)，最坏退化成 O(n)。懒标记的核心是**先记账，不结账**：当一个节点管辖的区间被完全覆盖时，我直接把 `sum += v × 区间长度` 记在这个节点上，并给它打一个 `lazy += v` 的标记，**不往下递归**；只有当后续操作真的需要进入子区间时，才把标记下推一层。这样每次修改只触碰 O(log n) 个节点。三个必须写对的细节：① 下推时机——**先 push 再递归**，否则子节点的旧值会被覆盖；② 标记可合并——多次区间加可以累加成 `lazy += v`，不需要队列；③ 完全覆盖直接返回，不要"递归到底再更新"，那样懒标记就白设计了。为什么不用 BIT？区间加 + 区间和用双 BIT 也能做（ALG-393），但一旦操作变成"区间赋值 + 区间最值"，BIT 的差分思想就失效了，线段树是更通用的底座。

**代码**：

```javascript
class LazySegTree {
  constructor(arr) {
    this.n = arr.length;
    this.sum = new Float64Array(this.n * 4);
    this.lazy = new Float64Array(this.n * 4);
    this.build(1, 0, this.n - 1, arr);
  }
  build(o, l, r, a) {
    if (l === r) { this.sum[o] = a[l]; return; }
    const m = (l + r) >> 1;
    this.build(o << 1, l, m, a);
    this.build(o << 1 | 1, m + 1, r, a);
    this.sum[o] = this.sum[o << 1] + this.sum[o << 1 | 1];
  }
  apply(o, l, r, v) { this.sum[o] += v * (r - l + 1); this.lazy[o] += v; }
  push(o, l, r) {                                  // 只在需要进子区间时才下推
    if (!this.lazy[o] || l === r) return;
    const m = (l + r) >> 1;
    this.apply(o << 1, l, m, this.lazy[o]);
    this.apply(o << 1 | 1, m + 1, r, this.lazy[o]);
    this.lazy[o] = 0;
  }
  add(ql, qr, v, o = 1, l = 0, r = this.n - 1) {
    if (ql <= l && r <= qr) return this.apply(o, l, r, v);   // 完全覆盖：只记账
    this.push(o, l, r);                                       // 先下推再递归
    const m = (l + r) >> 1;
    if (ql <= m) this.add(ql, qr, v, o << 1, l, m);
    if (qr > m) this.add(ql, qr, v, o << 1 | 1, m + 1, r);
    this.sum[o] = this.sum[o << 1] + this.sum[o << 1 | 1];
  }
  query(ql, qr, o = 1, l = 0, r = this.n - 1) {
    if (ql <= l && r <= qr) return this.sum[o];
    this.push(o, l, r);
    const m = (l + r) >> 1;
    let res = 0;
    if (ql <= m) res += this.query(ql, qr, o << 1, l, m);
    if (qr > m) res += this.query(ql, qr, o << 1 | 1, m + 1, r);
    return res;
  }
}

const seg = new LazySegTree([0, 0, 0, 0, 0, 0]);
seg.add(1, 3, 100);                                  // [1,3] 各加 100
console.log(seg.query(0, 5), seg.query(1, 3));       // 300 300
```

**边界与追问**：① `push` 里判断 `l === r` 很关键，叶子节点没有子节点，下推会越界写坏数组；② 标记类型决定合并方式：加法可累加，赋值必须覆盖（后写的赢），乘法加法混合要注意顺序（先乘后加）；③ 追问"能不能只写懒标记不更新 sum"——不行，查询完全覆盖时直接返回 `sum[o]`，所以 `sum` 必须同步维护；④ 追问"数组开多大"——`4n` 是安全上界，`2n` 需要按满二叉树编号分布；⑤ 追问"递归深度会不会爆栈"——n=10⁶ 时深度约 20，安全。

### 精讲 2 · [ALG-357] 区间合并线段树：最长连续签到天数

**场景**：用户签到表是 0/1 数组（按天），要查"任意时间段内最长连续签到天数"，同时支持补签（单点把 0 改成 1）。这是区间合并线段树的标准形态。

**问法**：为什么前缀和/普通求和线段树做不了？三个字段怎么定义？跨区间怎么拼？

**思路**：求和线段树只能回答"这段里有几个 1"，而"最长连续"是**跨越区间边界的结构信息**——左半段的末尾连续 1 和右半段开头的连续 1 能拼成更长的段，这个信息必须随节点一起存。所以每个节点维护四个量：`width`（区间长度）、`pre`（从头开始连续 1 的长度）、`suf`（到尾部连续 1 的长度）、`best`（区间内最长连续 1）。合并时三条公式：`best = max(左best, 右best, 左suf + 右pre)`；`pre = 左pre === 左width ? 左width + 右pre : 左pre`（只有左边整段都是 1，前缀才能延伸）；`suf` 对称。查询时如果区间横跨中点，**必须把左右两个结果合并**，而不是简单取 max——这正是"不可差分"的体现，也是 BIT 完全做不了这类题的原因。

**代码**：

```javascript
function buildSeg(arr) {
  const n = arr.length, S = n * 4;
  const pre = new Int32Array(S), suf = new Int32Array(S);
  const best = new Int32Array(S), width = new Int32Array(S);

  function pull(o) {
    const L = o << 1, R = L | 1;
    pre[o] = pre[L] === width[L] ? width[L] + pre[R] : pre[L];
    suf[o] = suf[R] === width[R] ? width[R] + suf[L] : suf[R];
    best[o] = Math.max(best[L], best[R], suf[L] + pre[R]);
  }
  function build(o, l, r) {
    width[o] = r - l + 1;
    if (l === r) { pre[o] = suf[o] = best[o] = arr[l] ? 1 : 0; return; }
    const m = (l + r) >> 1;
    build(o << 1, l, m); build(o << 1 | 1, m + 1, r);
    pull(o);
  }
  function update(i, v, o = 1, l = 0, r = n - 1) {
    if (l === r) { pre[o] = suf[o] = best[o] = v ? 1 : 0; return; }
    const m = (l + r) >> 1;
    if (i <= m) update(i, v, o << 1, l, m);
    else update(i, v, o << 1 | 1, m + 1, r);
    pull(o);
  }
  const merge = (a, b) => ({
    width: a.width + b.width,
    pre: a.pre === a.width ? a.width + b.pre : a.pre,
    suf: b.suf === b.width ? b.width + a.suf : b.suf,
    best: Math.max(a.best, b.best, a.suf + b.pre),
  });
  function query(ql, qr, o = 1, l = 0, r = n - 1) {
    if (ql <= l && r <= qr) return { width: width[o], pre: pre[o], suf: suf[o], best: best[o] };
    const m = (l + r) >> 1;
    if (qr <= m) return query(ql, qr, o << 1, l, m);
    if (ql > m) return query(ql, qr, o << 1 | 1, m + 1, r);
    return merge(query(ql, qr, o << 1, l, m), query(ql, qr, o << 1 | 1, m + 1, r));
  }
  build(1, 0, n - 1);
  return { update, query };
}

const t = buildSeg([1, 1, 0, 1, 1, 1, 0]);
console.log(t.query(0, 6).best);   // 3
t.update(2, 1);                     // 补签
console.log(t.query(0, 6).best);   // 6
```

**边界与追问**：① 空区间要返回单位元（`width=0, pre=suf=best=0`），否则 merge 会算错；② 查询必须走 merge，不能 `Math.max(左, 右)`；③ 同类题只要换字段：最大子段和用 `sum/pre/suf/best`，括号匹配用 `未匹配左括号/右括号/best`；④ 追问"能不能用分块"——可以，`√n` 分块也能做，代码更短但复杂度差一个量级；⑤ 追问"和 ALG-383"——同一套合并思想，只是字段多了 `sum`。

### 精讲 3 · [ALG-391] 树状数组：单点更新 + 前缀和（含逆序对与第 k 小）

**场景**：投票系统里候选人票数实时变化，要查"前 k 个投票站的累计票数"，还要算"当前榜单相对初始榜单的逆序对数"、定位"第 k 个空余名额"。这三个需求共用一套 BIT。

**问法**：`lowbit` 是什么？为什么 BIT 只能维护可减的运算？第 k 小怎么在树上二分？

**思路**：BIT 用 `i & -i` 取出最低位的 1，把下标 i 的管辖范围定为 `[i - lowbit + 1, i]`。单点加时沿 `i += lowbit` 往上走，前缀和时沿 `i -= lowbit` 往下跳，两条路径长度都是 O(log n)。它比线段树少一半常数、少一半代码，代价是**只能维护可减的聚合**（和、异或、计数）：因为区间和是用两个前缀和相减得到的，最大值没法"相减"。逆序对的经典做法是**从右往左扫**，对每个元素查"右边有多少个比它小"，离散化后 `sum(rank-1)` 就是答案。第 k 小利用"前缀和单调"的性质，在 BIT 上做倍增式二分：从高位 lowbit 开始尝试跳，若 `tree[pos + step] < k` 就跳过去并扣减 k，最后 `pos + 1` 就是答案——复杂度 O(log n)，比"二分 + 前缀和"的 O(log²n) 更优。

**代码**：

```javascript
class BIT {
  constructor(n) { this.n = n; this.t = new Int32Array(n + 1); }
  add(i, v) { for (; i <= this.n; i += i & -i) this.t[i] += v; }
  sum(i) { let s = 0; for (; i > 0; i -= i & -i) s += this.t[i]; return s; }
  range(l, r) { return this.sum(r) - this.sum(l - 1); }   // 只能做可减的聚合

  kth(k) {                                                 // 第 k 小（1-indexed）
    let pos = 0;
    for (let step = 1 << (31 - Math.clz32(this.n)); step > 0; step >>= 1) {
      if (pos + step <= this.n && this.t[pos + step] < k) {
        pos += step;
        k -= this.t[pos];                                  // 扣掉跨过的整块
      }
    }
    return pos + 1;
  }
}

function countInversions(a) {                              // 逆序对：从右往左扫
  const sorted = [...new Set(a)].sort((x, y) => x - y);
  const rank = new Map(sorted.map((v, i) => [v, i + 1]));
  const bit = new BIT(sorted.length);
  let cnt = 0;
  for (let i = a.length - 1; i >= 0; i--) {
    const r = rank.get(a[i]);
    cnt += bit.sum(r - 1);                                 // 右边比它小的个数
    bit.add(r, 1);
  }
  return cnt;
}

console.log(countInversions([3, 1, 2]));                   // 2
const bit = new BIT(10);
[2, 5, 7].forEach(i => bit.add(i, 1));
console.log(bit.kth(2), bit.range(1, 6));                  // 5  2
```

**边界与追问**：① 下标必须从 1 开始，`i > 0` 是循环终止条件，用 0 会死循环；② `kth` 的起点是**不大于 n 的最大 2 的幂**，写死 `1 << 20` 也能过但要保证不越界；③ 逆序对必须离散化，原值 10⁹ 开不了数组；重复元素用 `sum(rank-1)` 严格小于，若要求"小于等于"就换 `sum(rank)`；④ 追问 BIT 与线段树怎么选——单点改 + 前缀/区间和选 BIT（快、短），涉及区间赋值、最值、合并信息选线段树；⑤ 追问"BIT 能求区间最大值吗"——不能直接做，见 ALG-400 的局限分析。

### 精讲 4 · [ALG-421] KMP：线性时间模式匹配

**场景**：审计日志流里要实时找 `ERROR:timeout` 出现的所有位置，日志是几十 MB 的连续文本，且同一个模式串会被复用于每一次新到的日志块。

**问法**：为什么不能直接用 `indexOf`？next 数组到底表示什么？失配时为什么跳到 `next[k-1]` 而不是从头开始？

**思路**：暴力匹配在失配时把文本指针回退到 `i - k + 1`，最坏 O(n×m)（比如 `aaaaab` 里找 `aaab`）。KMP 的关键洞察是：**已经匹配成功的那一段前缀里，含有可以复用的信息**——如果模式串的前 k 个字符的后缀，恰好等于它的前缀，那么失配后不必从头比，直接把这个"最长公共前后缀"的长度当作新的已匹配长度即可。`next[i]` 就定义为 `p[0..i]` 的最长公共前后缀长度（不含自身）。因为文本指针永不回退，总复杂度 O(n+m)。对前端更实际的价值是：`next` 只跟模式串有关，可以**预计算一次、复用于所有日志块**，而 `indexOf` 每次调用都要重新做预处理（引擎内部虽有针对短模式的优化，但跨块匹配仍需处理边界）。写的时候注意 `next[0] = 0`，以及匹配成功后 `k = next[k-1]` 继续找重叠出现。

**代码**：

```javascript
function buildNext(p) {
  const next = new Int32Array(p.length);      // next[i] = p[0..i] 的最长公共前后缀长度
  for (let i = 1, k = 0; i < p.length; i++) {
    while (k > 0 && p[i] !== p[k]) k = next[k - 1];   // 失配就沿前缀链回退
    if (p[i] === p[k]) k++;
    next[i] = k;
  }
  return next;
}

function kmpSearch(text, pattern) {
  if (!pattern) return [];
  const next = buildNext(pattern);
  const hits = [];
  for (let i = 0, k = 0; i < text.length; i++) {
    while (k > 0 && text[i] !== pattern[k]) k = next[k - 1];
    if (text[i] === pattern[k]) k++;
    if (k === pattern.length) {
      hits.push(i - k + 1);                   // 命中起点
      k = next[k - 1];                        // 继续找重叠出现
    }
  }
  return hits;
}

const log = 'boot ok; ERROR:timeout at 12; ERROR:timeout at 30';
console.log(buildNext('ababaca'));            // 0 0 1 2 3 0 1
console.log(kmpSearch(log, 'ERROR:timeout')); // [9, 30]
```

**边界与追问**：① 模式串为空要单独处理，否则 `pattern[0]` 是 `undefined`，会匹配出诡异结果；② `next` 用 `Int32Array` 而不是普通数组，长度 10⁶ 时内存差 4 倍；③ 追问"多模式怎么办"——那就是 AC 自动机（ALG-423），把 next 的思想搬到 Trie 的 fail 指针上；④ 追问"KMP 和字符串哈希怎么选"——哈希写起来短、支持 O(1) 比较任意子串，但有碰撞（可用双模数降低）；KMP 无碰撞、适合流式；⑤ 追问"日志跨块切断了模式串"——保留最后 `m-1` 个字符做重叠，这是工程上最常见的坑。

### 精讲 5 · [ALG-451] 数位 DP：统计区间内满足数位条件的数

**场景**：号码池 [1, 10⁹] 里"包含数字 7"的号码要隔离（风控/合规），要统计总数。类似的还有"不含连续相同数字""数位和能被 3 整除""不含前导零影响"等变体，都是同一套骨架。

**问法**：为什么不能遍历？状态怎么设计？为什么记忆化只能记 `!tight` 的状态？

**思路**：10⁹ 遍历不可能，但**数的每一位只有 10 种取值**，从高位到低位逐位决策，状态数只有"位数 × 约束状态"。三个关键标志位：`pos`（当前第几位）、`tight`（是否贴着上界，贴边时这一位最多只能取到 `digits[pos]`，否则 0~9 随便取）、`started`（是否已经开始，用来处理前导零——前导零不算"出现了 7"）。答案用**减法原理**：`count(r) - count(l-1)`，把区间查询变成两次前缀查询，这是数位 DP 的标准套路（ALG-472 专门讲这个视角）。为什么只记忆化 `!tight`？因为 `tight` 的状态在整个搜索中只出现在一条路径上（唯一），记了也用不上；而 `!tight` 的状态会被不同分支反复访问，才是记忆化的收益来源。这个细节是面试里区分"背过模板"和"真懂"的关键点。

**代码**：

```javascript
function countContaining(n, target = 7) {        // 统计 [1, n] 中含 target 数字的个数
  if (n <= 0) return 0;
  const digits = String(n).split('').map(Number);
  const memo = new Map();

  // pos 位置 / tight 是否贴上限 / has 是否已出现 target / started 是否已开始
  function dfs(pos, tight, has, started) {
    if (pos === digits.length) return has ? 1 : 0;
    const key = pos + ',' + has + ',' + started;   // 只缓存 !tight 的状态
    if (!tight && memo.has(key)) return memo.get(key);

    const up = tight ? digits[pos] : 9;
    let res = 0;
    for (let x = 0; x <= up; x++) {
      const nextStarted = started || x !== 0;
      const nextHas = has || (nextStarted && x === target);  // 前导零不算
      res += dfs(pos + 1, tight && x === up, nextHas, nextStarted);
    }
    if (!tight) memo.set(key, res);
    return res;
  }

  return dfs(0, true, false, false);
}

const inRange = (l, r, t = 7) => countContaining(r, t) - countContaining(l - 1, t);
console.log(countContaining(100));     // 19：个位 10 个 + 十位 10 个 - 77 重复
console.log(inRange(1, 20));           // 2：7 和 17
```

**边界与追问**：① 状态里必须带 `has`/`started`，漏一个就会把前导零算成 0 或把"未开始"当成"已含"；② memo 的 key 不要包含 `tight`，否则命中率极低（写了也对，只是没意义）；③ 数的范围超过 `Number.MAX_SAFE_INTEGER` 时要用字符串 + 大数处理（ALG-459）；④ 追问"求第 N 个合法编号"——不能直接 DP，要**按位试填 + 计数**：每一位从 0 试到 9，用 DP 算"填了这个数字后还剩多少合法数"，不够就跳过，够了就定下来（ALG-461）；⑤ 追问"前端真的会用到吗"——用得少，但"权限码/券码校验规则"这类需求出现时，暴力枚举就是事故，判断力在这里体现（ALG-474 专门讨论边界）。

### 精讲 6 · [ALG-498] 贪心 + 二分：最大化最小值

**场景**：把 n 个连续分片切成 m 份（每份必须是连续段），要求"最小的一份尽量大"（分片均衡）。也常见于"最小化最大负载""最大化最小间隔"。

**问法**：为什么不能直接贪心？为什么可以二分？判定函数怎么写才线性？

**思路**：直接贪心没有明确的"每份切多大"的抓手——你不知道目标值，就没法决定什么时候切。这类"最大化最小值 / 最小化最大值"问题的通用解法是**二分答案**：把"求最优值"转成"判定某个值 x 是否可行"。可行性的单调性是关键：如果最小份能做到 14，那 13、12 一定也能（约束更松），所以 `feasible(x)` 关于 x 单调递减，可以二分。判定本身用贪心：从左往右累加，一旦累计和 ≥ x 就切一刀、清零重来，最后看切出的份数是否 ≥ m——**能切出至少 m 份，就说明存在一种切法让每份都 ≥ x**（多出来的份可以合并到最后一份）。整体复杂度 O(n log Σ)，比 DP 的 O(n²m) 快得多。注意二分写法：求最大可行值要用 `mid = ceil((lo+hi)/2)` 配 `lo = mid`，否则会死循环。

**代码**：

```javascript
function maxMinSegment(nums, m) {
  if (m > nums.length) return -1;                 // 份数多于元素，无解
  let lo = Math.min(...nums);
  let hi = nums.reduce((a, b) => a + b, 0);

  // 贪心判定：每份累加到 >= mid 就切一刀，看能否切出至少 m 份
  const feasible = mid => {
    let cuts = 0, acc = 0;
    for (const v of nums) {
      acc += v;
      if (acc >= mid) { cuts++; acc = 0; }
    }
    return cuts >= m;
  };

  while (lo < hi) {
    const mid = Math.ceil((lo + hi) / 2);         // 上取整，配合 lo = mid 防死循环
    if (feasible(mid)) lo = mid;
    else hi = mid - 1;
  }
  return lo;
}

console.log(maxMinSegment([7, 2, 5, 10, 8], 2));  // 14: [7,2,5] 与 [10,8]
console.log(maxMinSegment([1, 2, 3, 4, 5], 2));   // 9
console.log(maxMinSegment([5], 3));               // -1
```

**边界与追问**：① 二分的下界别写 0（会多做 log 次无效判定），用 `min(nums)` 或 `ceil(sum/m)` 更紧；② `feasible` 必须是 O(n) 的贪心，若写成 DP 就退化成 O(n² log Σ)；③ 追问"如果每份不要求连续"——那就是排序 + 二分，判定变成"能否凑出 m 组和 ≥ x"，思路仍是二分答案；④ 追问"和 ALG-504 的区别"——504 是最大化平均值，判定函数换成"减去 mid 后能否切出正贡献"，骨架完全一样；⑤ 追问"为什么贪心判定是对的"——因为每份越早切越不亏（剩余元素更少，不会让后面的份更难满足），这是典型的交换论证。

## 六、这份清单怎么用（比刷完 200 题更重要）

**第一遍，只做判断。** 遮住考点列，看题目只回答三个问题：数据会不会变？要查的是区间还是单点？聚合可不可逆？答完再对照选型表。200 道题全部过一遍判断，比精做 20 道更划算——因为面试考的就是这个判断。

**第二遍，只写四类模板。** 线段树（含懒标记）、BIT（含第 k 小）、KMP、区间合并。这四类能覆盖清单里 80% 的「手写」需求，其余多为变体或思想演示（可持久化、珂朵莉树、树链剖分在前端面试里基本只问思路）。

**第三遍，练退化方案。** 每道题都补一句「如果 n 只有 1000 我会怎么写」。这一步是把「会写模板」变成「会做工程决策」的分水岭，也是面试官最想听到的那句话。

最后提醒一句：ALG-351 ~ 550 里至少有三分之一是**思想题**（知识地图、选型对比、复杂度论证、对拍），它们不会出现在笔试里，但会以「你为什么不用 XX」的形式出现在面试追问里。别跳过它们。
