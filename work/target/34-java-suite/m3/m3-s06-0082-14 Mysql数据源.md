# 用 JDBC 把 MySQL 表读成 Flink Table：JDBCInputFormat 读数、注册、查询一条龙

> 🔒 安全提示：文中示例的口令/密钥均为课程教学环境演示口径，生产环境的安全要求见《安全与合规须知》。

前面注册成表的数据都来自内存集合，真实业务里数据多半躺在关系库中。冷链监控平台这类系统更是典型：实时明细落 MySQL，统计分析要周期性回读。让 Flink 直接把一张 MySQL 表读成 DataSet、注册成 Table 再用 SQL 查询，需要补两支依赖，走批的环境，四步就能跑通。读入侧的另一头是写出：同一个数据库，写出去靠 RichSinkFunction 里手写 JDBC，读进来则由 JDBCInputFormat 替你封装了大半工作，两头对照着看印象更深。

## 先给结论

- MySQL 表数据是有界数据，走批处理：ExecutionEnvironment 配 BatchTableEnvironment。
- 依赖两支：flink-jdbc 连接器（JDBCInputFormat 所在包）与 mysql-connector-java 驱动，课程环境驱动用 5.1.48。
- 读数四步：TypeInformation 数组声明字段类型、buildJDBCInputFormat 配齐连接参数、env.createInput 得到 DataSet、registerDataSet 注册成表。
- 注册成 mTable 后 sqlQuery 查询，toDataSet 取回 Row 集合，print 输出即查询结果。
- 读入与写出对称：读入由 InputFormat 封装连接与取数，写出要自己在 RichSinkFunction 的 open 与 invoke 里管理连接和更新。

## 一、补依赖：连接器与驱动

JDBCInputFormat 不在 flink-java 里，属于 JDBC 连接器，同时 MySQL 的驱动 jar 也必须进 classpath，pom 里补上这两支：

```xml
<!-- Flink JDBC 连接器：JDBCInputFormat 所在包，版本需与集群 Flink 版本对齐 -->
<dependency>
    <groupId>org.apache.flink</groupId>
    <artifactId>flink-jdbc_${scala.binary.version}</artifactId>
    <version>1.9.1</version>
</dependency>
<!-- MySQL 驱动 -->
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <version>5.1.48</version>
</dependency>
```

连接器的版本要与集群的 Flink 版本对齐，课程演示环境取 1.9.1；驱动 5.1.48 对应 MySQL 5.x 系列的库。两支依赖少一支都会在运行期报类找不到，而不是编译期，这也是 JDBC 接入问题最常被忽略的原因。

## 二、环境与字段类型：有界数据走批

动手前先回答一个问题：MySQL 表的数据是有界的还是无界的？表里就是一批有限的行，天然有界，所以执行环境用批的 ExecutionEnvironment，表环境用 BatchTableEnvironment。课程环境里准备的是 test01 库的 users 表，字段很简单：id 整型、userName 字符串、age 整型。

读数前要告诉 Flink 每个字段是什么类型，靠的是 TypeInformation 数组：

```java
// 字段类型：id int、userName string、age int
TypeInformation[] fieldTypes = new TypeInformation[] {
        BasicTypeInfo.INT_TYPE_INFO,
        BasicTypeInfo.STRING_TYPE_INFO,
        BasicTypeInfo.INT_TYPE_INFO
};
RowTypeInfo rowTypeInfo = new RowTypeInfo(fieldTypes);
```

BasicTypeInfo 里预置了 INT、STRING、LONG、DATE 等常用类型常量，按 users 表的列顺序装进数组，再用 RowTypeInfo 包起来，作为查询结果的行类型说明。

## 三、JDBCInputFormat 四步读数并注册成表

主程序把建参数、读数据、注册、查询四步连成一条线，类名沿用课程的 TableJob：

```java
package com.study.coldchain.table;

// import 从略：ExecutionEnvironment、BatchTableEnvironment、Table、DataSet、
// JDBCInputFormat、RowTypeInfo、BasicTypeInfo、TypeInformation、Row

public class TableJob {

    public static void main(String[] args) throws Exception {
        // 1. 批环境与批 Table 环境：MySQL 表是有界数据
        ExecutionEnvironment env = ExecutionEnvironment.getExecutionEnvironment();
        BatchTableEnvironment batchTableEnvironment = BatchTableEnvironment.create(env);

        // 2. 字段类型与行类型
        TypeInformation[] fieldTypes = new TypeInformation[] {
                BasicTypeInfo.INT_TYPE_INFO,
                BasicTypeInfo.STRING_TYPE_INFO,
                BasicTypeInfo.INT_TYPE_INFO
        };
        RowTypeInfo rowTypeInfo = new RowTypeInfo(fieldTypes);

        // 3. JDBC 参数：地址、账号、密码、查询语句、返回行类型
        JDBCInputFormat jdbcInputFormat = JDBCInputFormat.buildJDBCInputFormat()
                .setDBUrl("jdbc:mysql://172.17.0.143:3306/test01?characterEncoding=utf8")
                .setUserName("root")
                .setPassword("123456")
                .setQuery("select * from users")
                .setRowTypeInfo(rowTypeInfo)
                .finish();

        // 4. 读成 DataSet 并注册成表
        DataSource<Row> source = env.createInput(jdbcInputFormat);
        batchTableEnvironment.registerDataSet("mTable", source);

        // 5. SQL 查询并取回结果
        Table table = batchTableEnvironment.sqlQuery("select * from mTable");
        DataSet<Row> result = batchTableEnvironment.toDataSet(table, Row.class);
        result.print();
    }
}
```

构建器链式配参的过程与手写 JDBC 的套路一一对应：setDBUrl 是连接串，库里是 test01，URL 上带 characterEncoding=utf8 保证中文不乱码；setUserName 与 setPassword 是账号密码，课程环境是 root 与 123456；setQuery 是要执行的查询，select * from users；setRowTypeInfo 把第 2 步的行类型挂上；finish 收尾。整体是一个典型的构建器模式，配完的 JDBCInputFormat 交给 env.createInput，得到一个装着 Row 的 DataSource，随后 registerDataSet 注册成 mTable。

注册之后查询有个容易忽略的细节：sqlQuery 查的是 mTable，也就是刚注册进表环境的那张表，而不是直接连 MySQL。先把 MySQL 数据读进来注册成 Flink 表，再在表环境里查询，这是两件独立的事。toDataSet 把查询结果变回 DataSet，元素类型 Row，按位置取字段即可；print 在批处理里立即触发执行，输出就是 users 表的查询结果。整条链路一张图：

```mermaid
flowchart LR
    M["MySQL test01 库 users 表"] --> J["JDBCInputFormat：URL 账号 查询 行类型"]
    J --> I["env.createInput 得到 DataSet"]
    I --> R["registerDataSet 注册成 mTable"]
    R --> Q["sqlQuery 在表环境里查询"]
    Q --> T["toDataSet 取回 Row 结果"]
    T --> P["print 输出并触发执行"]
```

从图上能看出职责边界：JDBCInputFormat 只负责「把表读进来」，注册与查询全在 Flink 表环境里完成，MySQL 对 Flink 来说只是一次有界输入。

## 四、与写出对照：SinkToMySQL 的手写 JDBC

读入侧的封装度高，写出侧则要亲手管理连接生命周期。项目工程里往 MySQL 写实时明细的 SinkToMySQL 就是模板：继承 RichSinkFunction，open 里建连接，invoke 里绑定参数并执行更新：

```java
package com.study.coldchain.flink;

// import 从略：RichSinkFunction、Configuration、Connection、DriverManager、PreparedStatement

public class SinkToMySQL extends RichSinkFunction<MessageEntity> {
    private String driverName = "com.mysql.jdbc.Driver";
    private String DBUrl = "jdbc:mysql://172.17.0.143:3306/cold?useSSL=false&characterEncoding=UTF-8";
    private Connection connection;
    private PreparedStatement preparedStatement;

    @Override
    public void open(Configuration parameters) throws Exception {
        Class.forName(driverName);
        connection = DriverManager.getConnection(DBUrl, "cold", "cold123");
        preparedStatement = connection.prepareStatement(replaceSql());
    }

    @Override
    public void invoke(MessageEntity value, Context context) throws Exception {
        // 按占位符顺序绑定各字段后执行更新
        preparedStatement.executeUpdate();
    }
}
```

对照之下分工很清楚：读入用 JDBCInputFormat，连接、查询、结果映射都由格式类封装，你只配参数；写出用 RichSinkFunction，open 建连接、invoke 逐条 executeUpdate、close 释放资源，全要自己管。连接放在 open 而不是 invoke 里建，是因为每个并行子任务只建一次连接，避免逐条数据反复握手。

顺带一提，不写 Java 代码也有提交 SQL 的路子：Flink 提供 SQL Client 这类命令行入口，直接对注册好的表发查询，本课的程序内嵌写法与它共享同一套解析优化执行链路。

到这里 day5 的主线收官：Table 执行过程的六个阶段、执行计划的查看与分析、与 DataStream 和 DataSet 的双向集成、MySQL 数据源接入，从写查询、看计划到接数据拼成了最小闭环，后续冷链监控平台的实时统计任务就建在这套底座上。

## 常见误区

- **以为 MySQL 数据要走流处理。** 错例：开了 StreamExecutionEnvironment 去接表数据。正解：表数据有界，走 ExecutionEnvironment 加 BatchTableEnvironment，与 DataSet 同族。
- **连接器与驱动只装一支。** 错例：只加 flink-jdbc，运行时抛 ClassNotFoundException: com.mysql.jdbc.Driver。正解：flink-jdbc 提供 InputFormat，MySQL 协议靠驱动 jar，两支都要进 classpath。
- **RowTypeInfo 与查询列对不上。** 错例：select * 返回三列，类型数组只给了两项。正解：类型数组的长度与顺序必须和查询结果的列一一对应，改查询就要同步改类型。
- **print 之后又补 execute。** 错例：result.print() 后再调 env.execute()，抛 No new data sinks have been defined。正解：批处理的 print 立即触发执行，与 execute 二选一。
- **URL 不带 characterEncoding。** 错例：userName 里的中文读出来是问号。正解：连接串加 characterEncoding=utf8。

## 面试可能被问到的问题

1. 面试官追问：「Flink 怎么把一张 MySQL 表读进来？」
   答：用 JDBCInputFormat 构建器配置连接串、账号密码、查询语句与 RowTypeInfo，env.createInput 得到 DataSet，再 registerDataSet 注册成表，之后就能 sqlQuery 查询。
2. 面试官追问：「需要哪些依赖？」
   答：两支，flink-jdbc 连接器提供 JDBCInputFormat，mysql-connector-java 提供 MySQL 协议驱动；版本分别要跟集群 Flink 版本与 MySQL 版本对齐。
3. 面试官追问：「为什么读 MySQL 要用批环境？」
   答：表数据是有界数据，一次查询返回有限的行，与文件、集合同属有界输入，天然匹配 ExecutionEnvironment 与 DataSet 体系。
4. 面试官追问：「读 MySQL 与写 MySQL 的实现有什么差别？」
   答：读入由 JDBCInputFormat 封装连接、查询与结果映射，只需配参数；写出要继承 RichSinkFunction，自己在 open 建连接、invoke 里绑定占位符并 executeUpdate、close 释放，连接按并行子任务复用。
5. 面试官追问：「查询结果里的 Row 怎么取字段？」
   答：Row 按位置存值，用 getField(0)、getField(1) 这类索引访问，顺序与 RowTypeInfo 里声明的字段类型数组一致。
6. 面试官追问：「sqlQuery 查的表是 MySQL 里的表吗？」
   答：不是，查的是注册进 Flink 表环境的那张表。MySQL 数据先经 JDBCInputFormat 读成 DataSet 并注册，SQL 查询发生在 Flink 表环境内部，与数据库不再交互。
