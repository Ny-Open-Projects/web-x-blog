# 仓库湿度预警柱状图：换个图表类型，复盘 Superset 报表生产线

温度预警折线图已经把「配置出图、iframe 嵌回前端」整条链路走通，湿度预警柱状图在流程上没有任何新东西，价值在于补三块拼图：图表类型怎么挑、告警口径怎么随字段切换、Superset 出图的边界在哪。把这张图做完，day8 的图表实战就齐了。

## 先给结论

- 需求是按仓库、按天看湿度预警数量：分组字段 housename，时间粒度 1 天，指标 count。
- 图表类型选 Time-series Bar Chart，按时间先后顺序展现的柱状图，适合「每天一根柱子」这类离散时段的数量对比。
- 告警字段从 temalert 换成 humalert，语义同构：1 高湿预警、-1 低湿预警、0 正常，过滤条件仍然是不等于 0。
- 出图后在 Visual Properties 里调配色与图例，标题定为「仓库湿度预警」，拷贝 iframe（宽 1000 高 400）嵌入前端，Vue dev server 自动编译后页面即见。
- 报表生产线套路固定：数据源、类型、粒度、指标、过滤、分组六项定完即出图；业务人员无代码自助，深度定制样式才需要开发人员对 Superset 二次开发。

## 一、需求与口径：换字段不换套路

「按仓库每天的湿度预警数量」这句话与温度版一字之差：告警字段从 temalert 换成 humalert，时间粒度从小时换成天。humalert 的取值语义与 temalert 同构，都是实时计算链路写好的标记：0 正常、1 高湿预警、-1 低湿预警。对应的统计口径（示例按本课写法补全）：

```sql
-- 仓库维度、按天粒度的湿度预警计数
SELECT TIME_FLOOR(__time, 'P1D') AS day_bucket,
       housename,
       COUNT(*)                AS alert_count
FROM all_device_message
WHERE humalert <> 0
GROUP BY TIME_FLOOR(__time, 'P1D'), housename
```

同一份数据，只换过滤字段与粒度，就长出一张新图，这正是维度与指标拆法的复利：口径清楚，图表向导里每一项都有据可依。

## 二、图表类型怎么挑：看时间是不是主角

Superset 的可视化类型面板是一长串列表：Area Chart、Time-series Bar Chart、Line Chart 等等，每种类型应对一类场景。选型只需要回答一个问题：这份数据的主角是不是时间。

数据按时间先后排列、要体现变化趋势，选时序类图表；其中对比各时段的数量多少，柱状图比折线图更直观，每天一根柱子，高矮一目了然，所以湿度预警按天统计选 Time-series Bar Chart。不看时间维度、只看构成占比（比如故障设备的分布），选饼状图；连续数值看走势，折线图合适。选错类型的典型症状是图能画出来但读不出结论，此时先回头核需求，再换类型，不要先调样式。

## 三、配置、样式与嵌入

新建图表：Charts 页点加号，数据源选 all_device_message（day7 接入的 Druid 数据源），可视化类型选 Time-series Bar Chart，点 create new chart 进入配置。六项依次落定：时间粒度选一天，时间范围选 No filter，指标选 count，过滤条件 subject 选 humalert、operator 选不等于、comparator 填 0，分组字段选 housename，然后 run query，各仓库每天的湿度预警柱子当场画出来。

```mermaid
flowchart LR
    A["添加数据源 all_device_message"] --> B["新建 chart 选 Time-series Bar Chart"]
    B --> C["粒度 1 天 范围 No filter"]
    C --> D["指标 count"]
    D --> E["过滤 humalert 不等于 0"]
    E --> F["分组 housename"]
    F --> G["run query 出图"]
    G --> H["Visual Properties 调样式"]
    H --> I["保存标题 仓库湿度预警"]
    I --> J["拷贝 iframe 宽 1000"]
    J --> K["贴进前端工程自动编译"]
```

样式在 Visual Properties 选项卡里调：Color Scheme 换配色方案，Legend 控制图例显隐，Show Range 等属性按页面观感微调。调整到满意后给图表起标题「仓库湿度预警」保存，点嵌入按钮拷贝 iframe 代码，宽度设为 1000，贴进前端工程对应的湿度预警区域。保存文件，Vue dev server 自动编译，浏览器刷新，统计页面的湿度预警板块就有图了。

真实工程里这块图最终落地的配置可以直接对照。cold-chain-ui 统计报表页（`src/views/Statistics/index.vue`）里「湿度预警/每小时/仓库」这一块 iframe 的 form_data 参数解码出来是这样的：

```json
{
  "datasource": "1__druid",
  "viz_type": "bar",
  "granularity": "PT1H",
  "time_range": "No filter",
  "metrics": ["count"],
  "adhoc_filters": [
    { "subject": "humalert", "operator": "!=", "comparator": "0" }
  ],
  "groupby": ["housename"],
  "bar_stacked": true
}
```

与演示口径相比只有粒度不同：工程里按每小时（PT1H）刷新，供运营实时盯告警处置；日报视角用按天。粒度是需求决定项，没有对错，改完粒度记得重新拷贝 iframe，因为 iframe 里的 form_data 就是这份配置的序列化。

## 四、报表生产线与它的边界

把两张告警图、工作台的趋势图与故障设备饼图放在一起看，生产线是同一条：添加数据源（Druid），新建报表时选数据源与图表类型（饼状图、柱状图、折线图都能选），再配时间、指标、过滤与分组，报表即生成。整个过程不写代码，没有开发经验的业务人员也能快速把自己要的维度与指标变成报表，这是 Superset 这类 BI 平台最大的价值。

边界也要说清楚。界面能调的样式有限：配色方案、图例、坐标轴这些有现成开关，但整套视觉风格与预期不一致时，界面上调不出来，需要对 Superset 做二次开发，定制报表的样式与颜色，这部分是专业开发人员的活。所以平台落地通常是双轨：常规报表业务自助，品牌化、深度定制的少数图表由开发兜底。

## 常见误区

- **告警标记当数值聚合。** 错例：指标选 SUM(humalert)，高湿加低湿正负抵消。正解：标记字段配 count 指标加不等于 0 的过滤，计数才有业务含义。
- **类型跟着感觉选。** 错例：按天对比的数量用饼图，占比关系根本不存在。正解：时间对比用柱状、趋势用折线、占比用饼图，先问「主角是不是时间」。
- **改了粒度不改前端。** 错例：Superset 里把按天改成按小时，页面还是旧口径。正解：iframe 的 form_data 是配置快照，配置变更后重新拷贝覆盖。
- **样式在界面里死磕。** 错例：配色怎么调都不像设计稿，反复试参数。正解：界面上调不出的部分明确走二次开发排期，别把配置界面当设计工具。

## 面试可能被问到的问题

1. 面试官追问：「湿度预警这张图的维度、指标、过滤分别是什么？」
   答：维度是仓库名 housename 加按天的时间粒度，指标是 count 计数，过滤是 humalert 不等于 0，把高湿（1）与低湿（-1）两类告警都统计进来。对应的 SQL 是按天截断时间、按仓库分组计数。
2. 面试官追问：「Time-series Bar Chart 和普通柱状图怎么选？」
   答：数据带时间轴、要体现先后顺序与时段对比就用时序柱状图；分类之间静态对比（没有时间维度）用普通柱状图。判断标准是时间是不是这份数据的主角。
3. 面试官追问：「用 Superset 从零出一张报表的完整流程？」
   答：五步：接入数据源，新建图表时选数据源与可视化类型，配置时间粒度与时间范围，配置指标、过滤条件与分组字段，run query 预览后调样式、起标题保存，需要的话拷贝 iframe 嵌入业务前端。全程配置化，不写代码。
4. 面试官追问：「Superset 的优点与局限分别是什么？」
   答：优点是零代码出图、业务人员可自助、需求变化即改即生效；局限是样式定制能力有限，视觉风格与设计稿差距大时需要二次开发，且分析深度受限于数据集的维度指标定义。落地常采用业务自助加开发兜底的双轨。
5. 面试官追问：「iframe 嵌进去之后，图的数据怎么保持最新？」
   答：iframe 指向 explore 页，每次加载按 form_data 配置向 Superset 现查现画，Druid 侧数据更新后刷新页面即见新数据；配置变更（如换粒度、换分组）才需要重新拷贝 iframe 覆盖。
