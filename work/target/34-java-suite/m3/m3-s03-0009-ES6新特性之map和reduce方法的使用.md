# map 与 reduce：数组的映射与聚合两种思维

从输入框、接口里拿到的数字常常是一排字符串，比如 `['1', '20', '-5', '3']`，得先逐个转成数字才能计算；转完之后又往往要把一整列数揉成一个结果，比如求和。ES6 为数组新增的 map 和 reduce 正好对应这两步：map 负责逐个加工并生成新数组，reduce 负责从左到右聚合出一个值。这两个方法在后续数据处理里出场率极高，map 尤其频繁。

## 先给结论

- map 接收一个函数，把原数组每个元素用这个函数处理一遍，结果放进新数组返回，原数组不动。
- reduce 接收一个函数和一个初始值：函数必须，初始值可选。
- reduce 的回调固定两个参数：第一个是上一次 reduce 处理的结果，第二个是数组中要处理的下一个元素。
- 不给初始值时，第一轮用数组的前两个元素；给了初始值，第一轮用初始值和第一个元素。
- 两个方法的回调都既可以用传统 `function`，也可以用箭头函数，逻辑完全等价。

## 一、map：一进一出，整列加工

课件的定义：map() 接收一个函数，将原数组中的所有元素用这个函数处理后放入新数组返回。

```javascript
let arr = ['1', '20', '-5', '3'];
console.log(arr);   // ["1", "20", "-5", "3"]
let newArr = arr.map(s => parseInt(s));
console.log(newArr);   // [1, 20, -5, 3]
```

map 的回调会对每个元素调用一次，参数 `s` 是当前元素，`parseInt(s)` 的返回值进入新数组的同一位置。四个字符串进，四个数字出：元素个数不变，类型被加工。看不懂箭头写法的话，传统 `function` 版本一字不差地表达同一件事：

```javascript
let newArr2 = arr.map(function (a) {
    return parseInt(a);
});
console.log(newArr2);   // [1, 20, -5, 3]
```

对比可见，箭头函数只是把 `function`、大括号和 `return` 压成一个表达式，映射逻辑没有任何变化。

## 二、reduce：从一列数到一个值

课件的定义：reduce() 接收一个函数（必须）和一个初始值（可选），该函数接收两个参数，第一个参数是上一次 reduce 处理的结果，第二个参数是数组中要处理的下一个元素。reduce 从左到右依次把数组元素交给这个函数，并把每一轮的结果作为下一轮的第一个参数。

```javascript
const arr = [1, 20, -5, 3];
let result = arr.reduce((a, b) => {
    return a + b;
});
console.log(result);   // 19
```

没有传初始值，第一轮直接用数组的前两个元素。完整推演：

| 轮次 | a（上一次的结果） | b（下一个元素） | 返回值 |
|---|---|---|---|
| 1 | 1 | 20 | 21 |
| 2 | 21 | -5 | 16 |
| 3 | 16 | 3 | 19 |

```mermaid
flowchart LR
    A["数组元素 1 与 20"] -->|"第 1 轮 a=1 b=20"| B["返回 21"]
    B -->|"第 2 轮 a=21 b=-5"| C["返回 16"]
    C -->|"第 3 轮 a=16 b=3"| D["最终结果 19"]
```

图里最关键的是箭头上的传递：每一轮的返回值在下一轮变成 `a`，这就是课件那句「把处理的结果作为下次 reduce 的第一个参数」的含义。

## 三、初始值：改写第一轮

课件原文：如果是第一次，会把两个元素作为计算参数，或者把用户指定的初始值作为起始参数。给同一个求和加上初始值 1：

```javascript
let result2 = arr.reduce((a, b) => {
    return a + b;
}, 1);
console.log(result2);   // 20
```

初始值把第一轮的 `a` 顶掉了：第一轮 `a` 是初始值 1、`b` 是第一个元素 1，算出 2；第二轮 `a` 是 2、`b` 是 20，算出 22；第三轮 22 与 -5 得 17；第四轮 17 与 3 得 20。数组被完整走了四轮，比无初始值多出一轮，最终结果多出来的正好是那个初始值 1。

初始值还有一层实际意义：空数组调用 reduce 又不给初始值会直接抛 `TypeError`，给了初始值则返回初始值本身。聚合之前先想清楚「空集合应该是什么结果」，答案通常就是该传的那个初始值。

## 常见误区

- **以为 map 会改原数组。** map 返回新数组，原 `arr` 还是四个字符串，不接住返回值，加工结果就丢了。
- **箭头函数加大括号却忘写 return。** `arr.map(s => { parseInt(s); })` 的回调返回 `undefined`，新数组变成一排 `undefined`。单表达式省大括号，写了大括号就必须显式 `return`。
- **把 parseInt 直接塞给 map。** `arr.map(parseInt)` 的回调会收到两个参数（元素和索引），索引被当成 `parseInt` 的进制参数，结果变成 `[1, NaN, NaN, NaN]`。中间包一层 `s => parseInt(s)` 才安全。
- **给 reduce 的回调只写一个参数。** 只接收一个参数的回调拿不到「下一个元素」，聚合逻辑无法成立，reduce 回调签名固定是「上一次结果、当前元素」两个位。

## 面试可能被问到的问题

1. 面试官追问：「map 和 forEach 有什么区别？」
   答：forEach 执行回调后返回 `undefined`，用于带副作用的遍历；map 对每个元素做映射并返回等长的新数组，用于数据变换。需要拿到加工结果就用 map，只需要逐个处理不需要结果就用 forEach。

2. 面试官追问：「reduce 不传初始值时第一轮怎么走？」
   答：回调第一轮收到数组前两个元素，`a` 是第一个元素，`b` 是第二个元素，从第三个元素开始才轮到「上一次的结果」。数组只有一个元素时直接返回它；空数组且无初始值会抛 `TypeError`。

3. 面试官追问：「arr.map(parseInt) 为什么结果是 [1, NaN, NaN, NaN]？」
   答：map 会把元素值和索引一起传给回调，`parseInt` 的第二个参数是进制基数，索引 1 被当成按一进制解析直接 `NaN`，索引 2、3 也因进制参数异常失败。正确写法是包一层 `s => parseInt(s)`，或改用 `Number`。

4. 面试官追问：「map 的回调一定要 return 吗？」
   答：不一定写 `return`，但一定要产生返回值。单表达式箭头函数隐式返回表达式的值；一旦写成带大括号的语句块，就必须显式 `return`，否则新数组的对应位置是 `undefined`。

5. 面试官追问：「reduce 除了求和还能干什么？」
   答：任何「多归一」的聚合都行：求数组最大值、按 key 分组、统计出现次数、把数组叠成对象，甚至可以用它实现 map 和 filter。核心都是维护一个累加结果逐轮传递。
