# Java 面试术语白话注解

> 本表是「阶段七 面试专题」256 篇博客的配套速查词典。
> 写法是「一句话白话 + 稍详解释」，目标是让**初学者和通用型读者**不用先读其他博客也能看懂正文里的黑话。
> 用法：正文里遇到看不懂的缩写或黑话，直接按域名翻到这里查；表里标 **（正文已展开）** 的是博客里讲得更细、建议配合看的。

## 一、JVM 与内存结构

### JVM（Java 虚拟机）
一句话白话：Java 程序的"运行容器"，你写的 `.java` 最终在它里面跑。
稍详：它把字节码翻译成机器指令执行，负责内存管理和垃圾回收，所以 Java 能"一次编译、到处运行"。

### 字节码（Bytecode）
一句话白话：`.java` 编译后生成的 `.class` 里的指令，不是机器码，是给 JVM 看的"中间语言"。
稍详：因为不直接是某 CPU 的机器码，所以任何装了 JVM 的系统都能跑同一份字节码。

### JIT（即时编译器）
一句话白话：JVM 里的"加速引擎"，把跑得最勤的字节码直接编译成本地机器码。
稍详：第一次跑是解释执行（慢），热点代码被 JIT 编译后就能当原生程序跑（快）。

### 堆（Heap）
一句话白话：所有 `new` 出来的对象都住这儿，大家共用，也是垃圾回收的主战场。
稍详：线程共享；空间不够会 OOM；GC 主要就是回收堆里没人用的对象。

### 栈 / 虚拟机栈（Stack / VM Stack）
一句话白话：每个线程自己的一摞"便签纸"，记着当前方法调到了哪、局部变量是啥。
稍详：线程私有；方法调用压栈、返回出栈；局部变量在栈里，递归太深会栈溢出（StackOverflowError）。

### 方法区 / 元空间（Method Area / Metaspace）
一句话白话：存"类的户口本"的地方——类信息、常量、静态变量。
稍详：JDK 8 之前叫永久代（在堆里），JDK 8 起改成元空间，**用本地内存**，默认不限大小（靠 `-XX:MaxMetaspaceSize` 限制）。

### 程序计数器（Program Counter）
一句话白话：每个线程的"书签"，记着自己执行到哪条字节码指令了。
稍详：线程私有；唯一不会 OOM 的区域； native 方法时值为 undefined。

### 本地方法栈（Native Method Stack）
一句话白话：给 C/C++ 写的 `native` 方法用的栈。
稍详：和虚拟机栈类似，只不过服务的是非 Java 代码。

### 引用类型（强 / 软 / 弱 / 虚引用）
一句话白话：Java 给对象"被引用的强度"分了四档，越弱越容易被 GC 收走。
稍详：强引用（`new` 出来的，绝不回收）最常见；软引用（内存不够才回收，适合做缓存）；弱引用（下次 GC 必回收，ThreadLocal 的 key 就是它）；虚引用（只用来跟踪对象被回收的时机）。

### 序列化（Serialization / Serializable）
一句话白话：把内存里的对象"拍平"成字节流存盘或传网络，反序列化再拼回对象。
稍详：实现 `Serializable` 接口即可；单例模式要防序列化破坏（重写 `readResolve`）；RPC、缓存、深拷贝都用到它。

## 二、垃圾回收（GC）

### GC（Garbage Collection）
一句话白话：自动打扫内存的清洁工，把没人用的对象占的空间收回来。
稍详：程序员不用手动 free，JVM 在后台判断哪些对象"死了"并回收，降低内存泄漏风险。

### 可达性分析（Reachability Analysis）
一句话白话：从一群"根对象"出发顺藤摸瓜，摸不到的对象就是垃圾。 **（正文已展开）**
稍详：根对象（GC Roots）包括栈里的局部变量、静态变量、常量等；从它们出发引用链走不到的对象，判定为可回收。

### 引用计数（Reference Counting）
一句话白话：给对象记"被几个人指着"，为 0 就回收。
稍详：简单但 Java 没把它当主算法——因为两个对象互相指着（循环引用）时计数永远不为 0，会漏回收。

### 标记-清除（Mark-Sweep）
一句话白话：先给存活对象打勾，再清掉没打勾的。
稍详：实现简单，但清完内存会碎成一块块，后面想分配大对象可能找不到连续空间。

### 标记-整理（Mark-Compact）
一句话白话：打勾之后，把活着的都挪到一边排整齐，空出一大片连续空间。
稍详：解决了碎片问题，但移动对象有开销，适合老年代。

### 复制算法（Copying）
一句话白话：把活着的对象整批搬到另一块空地上，原来的地全部清空。
稍详：没有碎片、效率高，但浪费一半空间；新生代（存活率低）用它最划算。

### 分代收集（Generational Collection）
一句话白话：按"年纪"把对象分开管——年轻的用快但费空间的算法，年老的用稳的算法。 **（正文已展开）**
稍详：依据是"弱分代假说"：绝大多数对象活不过第一轮 GC。

### 年轻代 / 老年代（Young / Old Generation）
一句话白话：新 `new` 的对象先在年轻代，活得够久就"晋升"到老年代。
稍详：年轻代又分 Eden + 两个 Survivor；老年代放长命对象和大对象。

### STW（Stop-The-World）
一句话白话：GC 干活时，先把你所有业务线程"按暂停键"。
稍详：暂停期间用户请求不处理；好的收集器目标是把 STW 时间压到最短。

### 安全点（Safepoint）
一句话白话：代码里一些"可以安全喊停"的检查点，线程跑到这儿才允许被暂停做 GC。
稍详：循环开头、方法返回等位置；GC 要等所有线程都跑到安全点才 STW。

### 垃圾回收器（Collector）
一句话白话：具体干 GC 这活的"清洁工型号"，各有各的取舍。 **（正文已展开）**
稍详：Serial（单线程）、Parallel（吞吐优先）、CMS（停顿短）、G1（可预测停顿）、ZGC（亚毫秒停顿）等。

### 逃逸分析（Escape Analysis）
一句话白话：JVM 分析一个对象是不是"出门"了（被别的线程/方法拿到）。
稍详：没逃逸的对象可以栈上分配（不用进堆）、可以锁消除、标量替换，减轻 GC 压力。

## 三、并发与锁

### 线程 / 进程（Thread / Process）
一句话白话：进程是"一个工厂"，线程是工厂里的"一条生产线"，同厂的生产线共用原料（内存）。
稍详：进程间内存隔离，线程间共享堆；多线程能充分利用多核，但要处理竞态。

### synchronized
一句话白话：Java 自带的"门锁"，同一时刻只放一个线程进被它锁住的代码。 **（正文已展开）**
稍详：可锁方法或代码块；底层靠对象头的监视器锁（monitor）；1.6 后做了锁升级优化。

### 偏向锁 / 轻量级锁 / 重量级锁
一句话白话：synchronized 的三档"门锁形态"，没人抢时用最轻的，抢得凶才升级到最重的。
稍详：偏向锁=单线程直接进；轻量级锁=多线程自旋 CAS 抢；重量级锁=抢不到的线程进操作系统等待队列（阻塞）。

### 锁升级（Lock Escalation）
一句话白话：锁从"无锁→偏向→轻量→重量"一路变重的过程，只能升不能降。
稍详：为了在大多数情况下（单线程/低竞争）尽量别付出重锁的代价。

### CAS（Compare-And-Swap）
一句话白话：一句话："我以为你是 A，如果你是 A 我就改成 B，否则不动"——整个过程不可打断。 **（正文已展开）**
稍详：靠 CPU 原子指令实现无锁并发；缺点是会有 ABA 问题（值被改回原样看不出来）。

### AQS（AbstractQueuedSynchronizer）
一句话白话：Java 并发锁的"底盘框架"，ReentrantLock、Semaphore 都站在它肩上。
稍详：用一个 volatile 状态量 + 一个 FIFO 等待队列，实现加锁/释放/阻塞唤醒。

### volatile
一句话白话：给变量贴"即时广播"标签——一个线程改了，其他线程立刻看得见；也禁止指令重排。 **（正文已展开）**
稍详：它**不保证原子性**（比如 `i++` 不是原子的），只解决可见性和有序性。

### 原子性 / 可见性 / 有序性（并发三大特性）
一句话白话：原子性=操作不可中断；可见性=改了别人立刻看得到；有序性=代码顺序不被乱 reorder。
稍详：volatile 管可见+有序，synchronized/锁管三大特性，CAS 靠硬件保证原子。

### 原子类（AtomicXxx）
一句话白话：天生线程安全的计数器/变量，比如 `AtomicInteger`，底层靠 CAS。
稍详：比 `synchronized` 轻，适合简单计数、累加等场景。

### 线程池（ThreadPool）
一句话白话：预先雇好一批线程"待命"，任务来了直接派活，干完不解散、接着等下个任务。 **（正文已展开）**
稍详：避免频繁创建销毁线程的开销；核心参数有核心线程数、最大线程数、队列、拒绝策略。

### ThreadLocal
一句话白话：每个线程自己独享的小抽屉，往里放的东西别的线程翻不到。 **（正文已展开）**
稍详：常用于存"当前用户/数据库连接"等上下文；用完要 `remove()`，否则线程复用会串数据、还可能内存泄漏。

### 死锁（Deadlock）
一句话白话：A 拿着锁等 B 的锁，B 拿着锁等 A 的锁，俩人互相干等、谁都动不了。
稍详：四个必要条件（互斥、占有且等待、不可抢占、循环等待）；破坏任一即可避免。

### happens-before（先行发生）
一句话白话：JMM 里的一条"可见性规矩"：如果 A happens-before B，那 A 的改动对 B 一定可见。
稍详：比如线程启动、解锁-加锁、volatile 写-读，都构成 happens-before 关系。

### 内存屏障（Memory Barrier）
一句话白话：编译器和 CPU 的"停止重排"指令，保证屏障前后的读写顺序不乱。
稍详：volatile 的可见性和有序性底层就是靠它（以及缓存一致性协议）实现的。

### 并发工具类（CountDownLatch / Semaphore / CompletableFuture）
一句话白话：JDK 自带的"线程协作小工具"：倒计时门闩、信号量、异步编排。
稍详：CountDownLatch 等一组线程都就绪再统一放行；Semaphore 限制同时能通过的线程数；CompletableFuture 编排多步异步任务并组合结果。

## 四、集合与数据结构

### HashMap
一句话白话：用"数组+链表/红黑树"实现的键值对表，按 key 的哈希找位置，查得快。 **（正文已展开）**
稍详：JDK 8 里数组（桶）默认 16，冲突多时链表转红黑树；不保证顺序、非线程安全。

### 红黑树（Red-Black Tree）
一句话白话：一种"永远大致平衡"的二叉查找树，保证最坏查找也只要 log n 步。
稍详：靠颜色+旋转维持平衡，比纯二叉搜索树不会因为数据有序而退化成链表。

### 负载因子（Load Factor）
一句话白话：哈希表"塞多满就该扩容"的阈值，默认 0.75。 **（正文已展开）**
稍详：元素数 / 桶数 超过它就扩容（翻倍+重哈希）；调高省空间但冲突多、调低反之。

### 哈希冲突 / 二次哈希
一句话白话：不同 key 算出了同一个桶位，HashMap 用"扰动函数 + 再哈希"让分布更散。
稍详：JDK 8 的 `hash()` 把高 16 位异或低 16 位，减少碰撞；冲突后用链表/树串起来。

### ConcurrentHashMap
一句话白话：线程安全的 HashMap，高并发下也能稳稳读写。 **（正文已展开）**
稍详：JDK 8 用"数组+链表/红黑树 + CAS + 锁单个桶"实现，读基本无锁。

### ArrayList / LinkedList
一句话白话：一个是"会自己长大的数组"（查快改慢），一个是"双向链表"（改快查慢）。 **（正文已展开）**
稍详：随机访问多用 ArrayList；频繁中间增删用 LinkedList；后者其实日常用得少。

### fail-fast（快速失败）
一句话白话：一边遍历集合一边被人改了，立刻抛异常提醒你"别这么干"。
稍详：迭代器靠 `modCount` 计数发现结构变更，抛出 `ConcurrentModificationException`。

### 分段锁（Segment Lock）
一句话白话：把一把大锁拆成若干小锁，谁改哪一段就只锁那一段，其余段照样能进。
稍详：JDK 7 的 ConcurrentHashMap 把数据分成 16 段、每段一把锁；JDK 8 改成只锁单个桶（更细粒度），并发度更高。

## 五、Spring 框架

### IOC（控制反转）
一句话白话：以前你 `new` 对象，现在把"造对象、管对象"的活交给 Spring 容器。
稍详：对象的所有权反转给了容器，你只管用；降低耦合。

### DI（依赖注入）
一句话白话：IOC 的具体手段——容器把你需要的依赖"塞"给你，你不用自己找。
稍详：常见 `@Autowired` 按类型注入、 `@Resource` 按名称注入。

### AOP（面向切面编程）
一句话白话：把"日志、事务、鉴权"这些到处都有的横切逻辑，统一织入到业务方法周围。
稍详：底层是动态代理；让你专注写业务，重复代码不散落各处。

### Bean
一句话白话：被 Spring 容器接生并管理的对象，就是 Spring 眼里的"零件"。
稍详：默认单例；生命周期由容器托管。

### 生命周期（Bean Lifecycle）
一句话白话：Bean 从"生"（实例化）→"填属性"→"初始化"→"用"→"死（销毁）"的全过程。 **（正文已展开）**
稍详：中间有各种后置处理器（`BeanPostProcessor`）可插手。

### 循环依赖（Circular Dependency）
一句话白话：A 要 B、B 要 A，俩人互相掐着脖子谁也生不出来。 **（正文已展开）**
稍详：Spring 用"三级缓存"解决单例 + setter/字段注入的场景；构造器注入的循环依赖解决不了。

### 三级缓存（Three-level Cache）
一句话白话：Spring 解决循环依赖的"三张抽屉"：成品 / 半成品 / 工厂。
稍详：singletonObjects（成品）、earlySingletonObjects（早期引用）、singletonFactories（能造早期引用的工厂）。

### 动态代理（Dynamic Proxy）
一句话白话：运行时凭空"变"出一个代理类，在不改原代码的前提下包一层逻辑。 **（正文已展开）**
稍详：JDK 动态代理（要求有接口）和 CGLIB（继承子类，无需接口）；AOP、事务都靠它。

### 注解（Annotation）
一句话白话：贴在类/方法/字段上的"小标签"，给编译器或框架传达元数据。 **（正文已展开）**
稍详：如 `@Component`、`@Service`、`@Autowired`、`@Transactional`；可运行时反射读取。

### 自动配置（Auto-configuration）
一句话白话：Spring Boot 看你的 classpath 里有什么，就自动帮你把对应的 Bean 配好。
稍详：核心是 `@EnableAutoConfiguration` + `META-INF/spring.factories`（或 `AutoConfiguration.imports`）。

### 事务（Transaction）
一句话白话：把一串数据库操作打包成"要么全成、要么全不成"的一笔账。 **（正文已展开）**
稍详：`@Transactional` 声明式事务靠 AOP 代理，在方法前后自动提交/回滚。

### 事务传播行为（Propagation）
一句话白话：一个事务方法里又调用另一个事务方法时，"新开事务还是加入已有事务"的规则。
稍详：`REQUIRED`（默认，加入已有事务）、`REQUIRES_NEW`（挂起旧的、开新的）、`NESTED`（嵌套子事务）等；面试常问方法互相调用时回滚怎么互相影响。

### 设计模式三剑客（单例 / 工厂 / 代理）
一句话白话：面试最常考的三个套路：全局只留一个实例、把"造对象"包一层、不改原代码前提外包一层。
稍详：单例（见 254/255 专篇）；工厂（按条件产出不同对象，解耦调用方与实现）；代理（静态/动态代理，AOP、RPC 都靠它，动态代理已单列）。

## 六、数据库 MySQL

### 索引（Index）
一句话白话：书的目录，让数据库不用翻整本书就能定位数据。 **（正文已展开）**
稍详：本质是排好序的数据结构，最常见是 B+树；代价是占空间、拖慢写。

### B+树（B+ Tree）
一句话白话：多叉平衡树，所有数据都在叶子节点，叶子之间还用链表串起来。
稍详：矮胖（层级少、IO 少）、适合磁盘；范围查询顺着叶子链表走即可。

### 聚簇索引（Clustered Index）
一句话白话：InnoDB 的主键索引，叶子节点直接放整行数据，"索引即数据"。
稍详：一张表只有一个聚簇索引（就是主键）；没有主键会挑唯一键或隐式生成。

### 回表（Back to Table）
一句话白话：用二级索引查到主键后，还得再拿主键去聚簇索引把整行捞出来。
稍详：多一次 IO；想避免就看下一条"覆盖索引"。

### 覆盖索引（Covering Index）
一句话白话：要查的字段刚好都在索引里，不用回表，一步到位。
稍详：写 SQL 时尽量只 `SELECT` 索引覆盖的列，能明显提速。

### 最左前缀（Leftmost Prefix）
一句话白话：联合索引 `(a,b,c)` 像电话号，必须从最左列 a 开始才能用上，跳着用就断了。
稍详：`WHERE a=1 AND b=2` 能用，`WHERE b=2` 用不上。

### 缓冲池（Buffer Pool）
一句话白话：InnoDB 把磁盘页缓存在内存里的"热数据区"，读写先走它。
稍详：命中缓存就免了磁盘 IO；是 MySQL 性能的关键。

### 隔离级别（Isolation Level）
一句话白话：数据库允许多个事务"互不干扰"到什么程度，四档越来越严。 **（正文已展开）**
稍详：读未提交 < 读已提交 < 可重复读（MySQL 默认）< 串行化。

### 脏读 / 不可重复读 / 幻读
一句话白话：脏读=读到别人没提交的；不可重复读=同一条反复读结果变了；幻读=查一批，再查多了/少了行。
稍详：分别靠提高隔离级别 + MVCC 解决。

### MVCC（多版本并发控制）
一句话白话：给数据留"多个历史版本"，读的人看自己那个时间点的快照，不用加锁等。 **（正文已展开）**
稍详：靠 undo log 版本链 + ReadView（读视图）实现"快照读"。

### undo log / redo log / binlog
一句话白话：undo=回滚用的历史；redo=崩溃后重做的"保险"；binlog=给主从同步/备份用的总账本。
稍详：三者配合保证 MySQL 的原子性、持久性和主从一致。

### 分库分表（Sharding）
一句话白话：一张表太大装不下/查不动，就按规则拆成多张表甚至多个库。
稍详：水平分（按行切）和垂直分（按列切）；引入后跨分片查询、分布式事务变复杂。

### ACID（事务四特性）
一句话白话：数据库事务该有的四个保证：原子、一致、隔离、持久。
稍详：A 原子性（全成或全败，靠 undo log 回滚）、C 一致性（业务规则不被破坏）、I 隔离性（靠隔离级别+锁+MVCC）、D 持久性（靠 redo log，提交后不丢）。

## 七、Redis 与缓存

### Redis
一句话白话：把数据放内存里的键值数据库，快到飞起，常用来做缓存/计数器/排行榜。
稍详：单线程处理命令（6.0 后网络 IO 多线程）；支持多种数据结构（string/hash/list/set/zset）。

### 缓存穿透（Cache Penetration）
一句话白话：老有人查"根本不存在"的数据，缓存没有、每次都穿透到数据库。
稍详：解法：缓存空值、或用布隆过滤器挡在前面。

### 缓存击穿（Cache Breakdown）
一句话白话：某个超热 key 刚好过期那一瞬间，海量请求同时砸向数据库。
稍详：解法：热点 key 不过期、或加互斥锁只放一个请求去查 DB。

### 缓存雪崩（Cache Avalanche）
一句话白话：一大批 key 同时过期，或 Redis 直接挂了，数据库被瞬间打死。 **（正文已展开）**
稍详：解法：过期时间加随机抖动、Redis 高可用（集群）、限流降级。

### 布隆过滤器（Bloom Filter）
一句话白话：一个"省空间的概率筛子"，能断定"这东西一定不在"或"可能在"。
稍详：位数组 + 多个哈希；误判只会在"说存在其实没有"，不会漏掉真正存在的。

### 持久化 RDB / AOF
一句话白话：RDB=定时给内存拍个快照存盘；AOF=把每条写命令记进日志，重启重放。
稍详：RDB 恢复快但可能丢一段时间数据；AOF 更稳但文件大；常混合用。

### 主从复制 / 哨兵 / 集群
一句话白话：主从=一个主库写、多个从库读（读写分离）；哨兵=盯着主库挂没挂、自动切换；集群=数据分片扛海量。
稍详：三者是 Redis 高可用的三件套，逐层递进。

### 读写分离（Read-Write Splitting）
一句话白话：写操作走主库，读操作分摊到从库，分摊压力。
稍详：注意主从有延迟，刚写进去立马读可能读不到（延迟问题）。

## 八、分布式

### 分布式事务（Distributed Transaction）
一句话白话：一个业务横跨多个服务/数据库，要保证"要么都成、要么都回"。 **（正文已展开）**
稍详：单机的事务靠数据库，跨服务就得上 2PC/TCC/消息队列等方案。

### 2PC（两阶段提交）
一句话白话：先问大家"能提交吗"（准备阶段），都 OK 再喊"正式提交"（提交阶段）。
稍详：协调者 + 参与者；缺点是准备阶段资源被锁住、协调者挂了会阻塞。

### TCC（Try-Confirm-Cancel）
一句话白话：业务层面的三步走：先占坑（Try）、都成了确认（Confirm）、有一个不行就回滚补偿（Cancel）。
稍详：不依赖数据库锁，靠写补偿代码；侵入性强但灵活、性能好。

### 最终一致性（Eventual Consistency）
一句话白话：不要求这一秒就一致，过一会儿大家自然会达成一致。
稍详：和"强一致"相对；很多分布式系统用消息队列 + 重试达成它。

### 消息队列（Message Queue）
一句话白话：一个"异步传话筒"，A 把消息丢进去就走，B 按自己节奏来取。 **（正文已展开）**
稍详：用于解耦、削峰、异步；配合重试实现最终一致性。

### 幂等（Idempotent）
一句话白话：同一个请求你发 N 次，结果跟发 1 次一样，不会因为重复而多扣钱。
稍详：常见做法：唯一订单号 + 去重表、令牌机制、状态机。

### CAP（CAP Theorem）
一句话白话：一致、可用、分区容错，三者最多同时拿俩。
稍详：网络分区不可避免，所以实际是在"CP（保一致）"和"AP（保可用）"之间取舍。

### BASE
一句话白话：退而求其次的柔性理论：基本可用、软状态、最终一致。
稍详：是 CAP 里 AP 方向的落地哲学，常见于互联网高并发系统。

### 一致性哈希（Consistent Hashing）
一句话白话：把节点和数据都摆在一个"环"上，节点增减时只挪动环上相邻的一小段数据。
稍详：相比普通哈希取模，加机器时不必全量重分布，缓存命中率更稳。

### 限流 / 熔断 / 降级（三板斧）
一句话白话：限流=拦住超额请求；熔断=下游挂了就别再傻调、直接失败；降级=扛不住时关掉非核心功能保主流程。
稍详：保护系统不被流量冲垮的三件套，常配 Sentinel/Hystrix 使用。

### 分布式锁（Distributed Lock）
一句话白话：跨多个进程/机器也能"同一时刻只一个人干活"的锁，常用 Redis 或 ZooKeeper 实现。 **（正文已展开）**
稍详：要处理好过期时间、误删别人锁、锁续期等问题（Redisson 的看门狗就干这个）。
