# 6. Embedding 是什么、为何重要与怎么炼成（BERT / MLM / NSP）

## 纲要

- **Embedding 定义**：把文本 / 音频 / 视频等数据对象映射到「固定大小、连续的一维数值向量」（维度通常几百到几千）；向量数值非随机，承载语义。
- **核心性质**：语义相似的对象在向量空间中距离更近，不相似的更远——这是向量模型的学习目标，也是 RAG 检索的几何基础。
- **在 RAG 中的关键作用**：RAG 通过计算「问题 embedding」与「文档 embedding」的相似度来挑选相关上下文；embedding 质量直接决定能否选对相关上下文，引入不相关上下文会干扰 LLM 回答。
- **主流架构**：基于 Transformer 编码器的 BERT（Google 2018），用双向注意力提取语义。
- **训练两阶段**：① 完形填空（Masked LM，MLM）——随机 mask 掉 token 让模型预测，任意文本即可训练，无需人工标注；② 预测下一句（NSP）——二分类判断两序列是否语义连续，用 CLS + SEP 构造，亦无需人工标注。两阶段使每个 token 的 embedding 同时包含上下文语义与句间语义。
- 本章按课程口径重构；产品 / 框架名已规范化（BERT / Transformer / MTEB / GTE / BGE）；剥离营销与课程群引流。

## 一、什么是 Embedding

- 将数据对象（文本最常见）映射为固定维度的连续向量；维度代表某种语义或属性。
- **几何意义**：同类语义（如「天气」相关词）在向量空间彼此靠近，远离不相关类（如「水果」）。从向量位置关系即可判断语义相关性。

## 二、Embedding 在 RAG 中为什么关键

- RAG 检索的本质：计算问题向量与候选文档向量的相似度，挑最相似的文档作为上下文。
- **质量决定上限**：embedding 不好 → 选错上下文 → 噪声干扰 LLM → 回答质量下降。因此「为 RAG 挑选合适的 embedding 模型」是核心选型环节。

## 三、Embedding 模型是怎么炼成的

- **架构基石 BERT**：Transformer 编码器部分，双向注意力更好提取文本语义（2018 Google 提出）。
- **训练任务一 · 完形填空（MLM）**：随机用 `[MASK]` 遮住一个 token，模型预测被遮 token；任意网络文本都能构造训练对，无需人工标注，数据越多越好。
- **训练任务二 · 预测下一句（NSP）**：判断输入的两个序列是否语义连续（二分类）；用特殊 token `CLS`（分类）与 `SEP`（分隔）构造，连续样本取自同文档相邻句、不连续样本跨文档抽取，同样无需人工标注。
- **产出**：每个输入 token 得到一个 embedding 向量，既含该 token 的上下文语义，也含句子间语义关联。

## 四、FAQ

**Q1：embedding 向量维度越高越好吗？**
不一定。维度高可捕捉更复杂语义，但存储与计算成本上升；常见取 512 或 1024 折中。

**Q2：为什么 RAG 特别依赖 embedding 质量？**
RAG 靠向量相似度召回上下文，召回错了就给 LLM 喂噪声，直接拉低回答质量。

**Q3：BERT 训练为什么不需要人工标注？**
MLM 用任意文本 mask 自监督，NSP 用同/跨文档自动构造正负样本，二者皆自监督。

**Q4：embedding 的几何意义是什么？**
语义相近的对象向量距离近、不相近的距离远，这一性质支撑了向量检索。

## 五、面试高频问答

**1. 用一句话解释 embedding。**
将离散数据对象映射为连续低维向量，使语义相似者在向量空间距离更近。

**2. BERT 预训练的两个任务？**
MLM（完形填空，mask 预测）+ NSP（判断两句是否连续）。

**3. 为什么 embedding 是 RAG 检索的基础？**
RAG 通过问题向量与文档向量的相似度召回相关上下文，向量质量决定召回质量。

**4. embedding 维度与最大 token 数有何工程影响？**
维度影响语义容量与存储/算力；最大 token 数决定单条输入上限，超出会被截断，直接影响 RAG 文本分块策略。

## 六、ops 提示（增效）

> **检索靠向量**：RAG 召回质量 ≈ embedding 质量，选型要把 embedding 当一等公民。
>
> **自监督红利**：BERT 类训练无需人工标注，可借海量无标注语料练基础语义。
>
> **截断红线**：embedding 最大 token 数限制会截断长文本，分块时务必留余量。
