# 31. Gradio 界面开发基础与项目部署

## 纲要

- **Gradio 是什么**：强大的 Python 库，**几行代码**快速构建简单直观的 Web 界面，最初为方便与机器学习模型交互。封装了 HTML/CSS/JS，免前端开发，内置丰富组件（文本/图像/视频/音频）。
- **核心概念 Blocks**：用 `Blocks` 创建应用，所有组件放入其中。
- **事件机制（重点）**：按钮等事件的**输入/输出是组件对象**，但真正传入事件处理函数的是**组件的值**（如文本框传文本、复选框传状态、图片传二维数组）。
- **布局**：用**行（Row）+ 列（Column）**布局，列可设长度比例（`scale`，如 1:4）。
- **Chatbot 组件**：问答界面用 `Chatbot` 渲染；其**值是 QA 组合的列表**（`[[query,answer],...]`），多轮对话即多个 QA 列表。
- **系统界面设计（erag 企业员工助手）**：左右布局，左列=运行状态+参考信息（上下文，含表格），右列=Chatbot 聊天+输入框+重置/清除按钮；起名 **erag**（企业的 RAG 服务）。
- **部署**：用 **uvicorn** 部署；步骤① 把 Gradio 应用 `mount` 到 **FastAPI** 应用（子路径）；② 用 uvicorn 启 FastAPI 应用，指定入口/App/Host/Port/进程数（支持多并发）。
- 本章按课程口径重构；代码为知识重构（外部代码卷未挂载）；产品名已规范（Gradio / FastAPI / uvicorn / erag）。

## 一、Gradio 快速入门

Gradio 让你用纯 Python 构建美观 Web 应用，无需写前端。典型步骤：
1. `Blocks` 创建应用；
2. 声明组件（文本框、复选框、按钮等）；
3. 为按钮绑定点击事件处理函数；
4. `launch()` 启动，通过 URL 访问页面。

**事件处理关键**：点击事件声明时输入/输出是**组件**，但执行函数时传入的是**组件的值**。例：文本框组件的值是其文本内容，复选框的值是是否被选中状态，图片组件的值是二维数组。

## 二、布局与组件

- **行/列布局**：通过 Row + Column 组织，列可用 `scale` 设宽度比（如两列 1:4，第二列宽四倍）。行列可交错嵌套出复杂结构。
- **Chatbot 组件**：问答界面用 `Chatbot` 渲染；**其值格式为 QA 列表**——`[[query1,answer1],[query2,answer2],...]`，理解这个值格式是后续开发关键。

## 三、erag 系统界面设计

把制度问答 RAG、金融智库 Graph RAG、RAG Router 三模块整合，用 Gradio 提供对外界面，命名 **erag**（企业 RAG 服务）：

- **左列**：① 运行状态文本框（初始「准备就绪」，不可交互，仅展示）；② 参考信息文本框（展示本次回答的检索上下文）+ 表格信息（HTML 渲染）。
- **右列**：① `Chatbot`（问答展示，含气泡样式/复制按钮/双方图标）；② 问题输入框（多模态 Textbox，可文本可上传，自动聚焦）；③ 按钮行（隐藏左列 / 撤销 undo / 清除 clear / 重置 reset 等）。
- 总体左右列宽度比 **1:3**。

> 用户在右列输入问题 → 答案展示在 Chatbot → 所依据的上下文显示在左列参考信息（含表格单独展示），让用户看到回答依据。

## 四、项目部署（FastAPI + uvicorn）

- **为什么用 uvicorn**：基于异步库、轻量高效，适合高性能异步请求，支持多进程并发。
- **两步部署**：
 1. **封装 FastAPI**：声明 FastAPI 应用，用 Gradio 的 `mount` 函数把 Gradio 应用绑定到 FastAPI 子路径。
 2. **uvicorn 启动**：`uvicorn 入口:app --host --port --workers N`，指定入口文件、FastAPI App 名、IP、端口、进程数（如 4 进程支持 4 路并发）。
- 通过 `http://ip:port/子路径` 访问 Gradio 应用，支持多路并发。

## 五、FAQ

**Q1：Gradio 为什么要封装成 FastAPI 再部署？**
直接用 `launch()` 是单进程；封装成 FastAPI 后用 uvicorn 可多进程部署、支持并发，更贴近生产。

**Q2：事件处理函数的输入是组件还是值？**
声明时是组件，调用时传的是组件的值（文本/状态/数组），这是 Gradio 机制重点。

**Q3：Chatbot 组件的值是什么？**
QA 组合列表 `[[q,a],...]`，多轮即多个 QA 元素。

**Q4：左右布局比例怎么设？**
用 Row/Column + `scale`，如左:右=1:3。

## 七、ops 提示（增效）

> **原型用 launch()，生产用 FastAPI+uvicorn**：需要并发就别裸 launch，封装 FastAPI 设 workers 才能扛量。
>
> **Chatbot 值是列表**：做撤销/清除时操作的是 `[[q,a],...]` 列表，清空即设为空列表，别当字符串处理。
>
> **上下文可视化增强可信度**：把检索到的上下文与表格单独展示在左列，用户能看到回答依据，比纯黑盒回答更易被接受。
