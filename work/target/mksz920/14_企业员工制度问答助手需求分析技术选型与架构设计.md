# 14. 企业员工制度问答助手：需求分析、技术选型与架构设计

## 纲要

- **本章目标**：把前几章组件（LLM / embedding / 向量库 / 数据处理）串成一条「制度问答 RAG」基线，按软件流程走：需求分析 → 技术选型 → 架构设计 → 开发实战 → 测试 → 总结。
- **痛点与功能（需求）**：企业制度繁杂、散落多系统、搜索低效、常问 HR 增加沟通成本；差旅报销标准按职级 / 地区 / 旺季节异，易误报多报。助手整合多平台制度文件与差旅资料，帮员工快速定位、减轻 HR 负担。
- **依赖数据**：员工手册（PDF，含病假发放标准表格）、差旅报销标准（PDF，含表格）、住宿明细 Excel（含合并单元格，需特殊处理）。
- **技术选型**：embedding = BGE-M3（1024 维、8k 输入、约 2G 内存、5.6 亿参数，MTEB 检索榜单前列，先用基础版）；向量库 = Chroma（文档少、无强扩展需求）；LLM = 优先最强（开源 Qwen2-72B 验有效性，亦可闭源）；解析分块 = RAGFlow deepDOC + LangChain 分块；框架 = LangChain + gradio 前端。选型可迭代调整。
- **架构两大部分**：① 知识库构建（读取解析 → 分块 → embedding 向量化 → 入向量库）；② 检索生成 pipeline（问题 → 向量检索 → 相关文档作上下文 + 问题拼入 prompt → LLM 生成，上下文作参考展示前端以增强可解释性）。
- 本章按课程口径重构；产品 / 框架名已规范化（BGE-M3 / Qwen2-72B / Chroma / RAGFlow / LangChain / gradio）；剥离营销与课程群引流。

## 一、需求分析：痛点与功能

- **痛点**：制度多、分布散、检索慢；员工常直接问 HR，增加沟通成本；差旅报销按职级 / 地区 / 旺季标准复杂，易误报多报。
- **功能**：整合公司多平台规章制度与差旅报销资料，让员工快速定位所需制度，降低 HR 工作量。
- **依赖数据**：员工手册 PDF（含病假发放标准表）、差旅报销标准 PDF（含表）、住宿明细 Excel（含合并单元格，须特殊解析）。

## 二、技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| Embedding | BGE-M3 | 1024 维、8k 输入、约 2G 内存、5.6 亿参数，MTEB 检索榜前列 |
| 向量库 | Chroma | 文档量小、无强扩展需求，足够 |
| LLM | Qwen2-72B（优先最强，亦可闭源） | 先用最强验证系统有效性 |
| 解析+分块 | RAGFlow deepDOC + LangChain 分块 | 含表格 / 复杂版式 |
| 框架 | LangChain + gradio | 应用框架 + 前端 |

- 强调：初步选型可在项目执行中持续调整。

## 三、架构设计

- **知识库构建链路**：文档读取解析 → 文本分块 → embedding 向量化 → 存入向量库。
- **检索生成链路**：用户问题 → 向量检索 → 取相关文档 → 与问题合并进 prompt → LLM 生成答案；**相关上下文同时作为参考展示在前端**，增强结果可解释性。

## 四、FAQ

**Q1：为什么向量库选 Chroma 而非 Milvus？**
本助手文档量小、无强扩展需求，Chroma 易上手即可；中大型再换 Milvus。

**Q2：embedding 为什么选 BGE-M3？**
检索榜单前列、1024 维、支持 8k 输入、内存占用可控，综合能力好。

**Q3：架构为什么要展示上下文来源？**
让答案「有据可查」，提升可解释性与员工信任。

**Q4：技术选型定了就不能改吗？**
否，初步选型应随项目推进迭代调整。

## 五、面试高频问答

**1. 制度问答助手解决哪些痛点？**
制度分散难检索、问 HR 沟通成本高、差旅报销标准复杂易误报。

**2. 该项目的技术选型要点？**
BGE-M3 作 embedding、Chroma 作向量库、Qwen2-72B 验系统、deepDOC+LangChain 解析分块、LangChain+gradio 框架。

**3. RAG 架构的两大链路？**
知识库构建链路（解析→分块→向量化→入库）与检索生成链路（问题→检索→拼 prompt→LLM 生成）。

**4. 为什么前端要展示检索到的上下文？**
增强答案可解释性，让用户看到依据、提升信任。

## 六、ops 提示（增效）

> **小项目用 Chroma**：文档少、无分布式需求，别一上来堆 Milvus。
>
> **上下文可解释**：RAG 答案务必附来源，既是合规也是信任建设。
>
> **选型可演进**：baseline 阶段选最简可行组合，后续按瓶颈替换。
