# 27. 普通 RAG vs Graph RAG 与 Graph RAG 实战 Pipeline

## 纲要

- **普通 RAG vs Graph RAG 五大维度对比**：
 - 知识表达：平面文档 vs 图结构（天生隐含语义关系）；
 - 检索机制：向量相似度搜索 vs 图遍历（沿边找节点）；
 - 上下文理解：多步关系有局限 vs 可溯很长链条捕多步关系；
 - 推理能力：有限 vs 支持深入复杂关联推理；
 - 擅长查询：**多跳关系 / 语义关联 / 知识推理 / 聚合统计 / 时序关联**。
- **Graph RAG 构建三步骤**：① 用 LLM 从问题提取关键词；② 用关键词去图库检索实体及关系；③ 整合检索信息作上下文送 LLM 生成答案。
- **关键词提取**：LLM + 提示词（限定数量、用分隔符单行输出），解析成列表；关键词不准 → 后续全错。
- **文本自动提三元组**（原始数据非结构化时）：LLM + 提示词从文本识别实体与关系，输出「实体-关系-实体」三元组（Graph RAG 热门研究方向）。
- **实战 Pipeline（py2neo + LangChain）**：`pass_query`（提取关键词）→ `get_node`（关键词匹配节点类型，返回 name）→ `get_context`（按节点查关系，支持 query_level 降级）→ `graphRAG_pipeline`（合并上下文 + LLM 生成）。
- **自我学习方法（总结赠礼）**：新领域入门 3 步（综述找关键词→AI/搜索弄清含义→读 3-5 本经典书/论文→跟专家观点复述）；跟进前沿（渠道订阅+由粗到细读论文+结合代码佐证+定期综述+写博客/笔记费曼输出）。
- 本章按课程口径重构；代码为知识重构（外部代码卷未挂载），演示基于 `py2neo` + LangChain LLM；产品名已规范（Neo4j / LangChain / OpenKG）。

## 一、普通 RAG 与 Graph RAG 核心区别

| 维度 | 普通 RAG | Graph RAG |
| --- | --- | --- |
| 知识表达 | 平面文档（文本块，无显式结构） | 图结构（节点+边，天生隐含语义关系） |
| 检索机制 | 向量相似度搜索 | 图遍历（沿边从一节点到另一节点） |
| 多步关系理解 | 有局限，关系隐含在文本中易忽略 | 可溯很长链条，捕复杂多步关系 |
| 推理能力 | 有限（内容堆在一块文本） | 支持深入复杂关联推理 |
| 擅长查询 | 关键词/语义近似匹配 | 多跳关系、语义关联、知识推理、聚合统计、时序关联 |

**典型对比例**：手机知识图谱中「还有哪些采用超感光摄影的手机」——Graph RAG 沿节点关系轻松回答；普通 RAG 若无明确文本块匹配则答不出。又如「最近几年高端智能手机整体趋势」——Graph RAG 先沿关系收集多品牌调研报告再让 LLM 综合；普通 RAG 易返回片段化、难全局串联。

## 二、构建 Graph RAG 的三步骤

1. **提取关键词**：用 LLM 从用户问题中提取关键实体/关系词（最重要，错则全链错）。
2. **图库检索**：用关键词生成 Cypher，查相关实体及它们的关系。
3. **整合生成**：把实体信息 + 关系属性整合为上下文，送 LLM 生成答案。

> 例：问「总结哪些公司进行了企业转型」→ 提取关键词「公司/企业转型」→ 以「企业转型」为事件类型查发生该事件的公司及投资者 → 整合上下文 → LLM 生成列表。

**关键词提取提示词要点**：给定查询 + 提取 N 个关键词 + 考虑大小写/复述/常见表达 + 用分隔符单行输出 → 解析为列表。

**文本自动提三元组**（非结构化原始数据）：LLM 提示词「根据文本提取实体-关系-实体三元组，避免虚词，只输出三元组」；可从一个文本提多个（如「阿里巴巴是马云1999创立的公司」→ 公司/创始人/时间三个三元组）。这是 Graph RAG 重要研究方向。

## 三、实战 Pipeline 拆解

### 1. pass_query（提关键词）
用 LLM + 提示词模板，输入 query 与关键词数量，输出用分隔符单行；解析取首元素 + 按分隔符拆成列表返回。

### 2. get_node（关键词→节点）
连 Neo4j，对每类节点（投资者/公司/事件类型）写 `MATCH (n:标签) WHERE n.name CONTAINS '关键词' RETURN n.name`；匹配则返回节点名，否则返回空。例：关键词「比亚迪」→ 公司节点命中「比亚迪股份有限公司」，事件/投资者节点为空。

### 3. get_context（节点→关系上下文）
- 据 get_node 结果拼查询条件（投资者/公司/事件类型三类）；
- `MATCH` 获取投资者-公司-事件类型全关系及属性，拼成文本（如「投资者 X 投资了公司 Y」「公司 Z 发生了事件 E + 属性」）；
- **query_level 降级**：level=1 查全关系（含投资+事件）；若返回空（如该公司无投资者），自动 level=2 仅查「公司-事件」关系，避免空上下文；
- `include_content` 开关：报道 content 很长，可排除只留 title，防止上下文爆炸。

### 4. graphRAG_pipeline（合并生成）
遍历关键词列表 → 逐个 get_context 拼接 → 过滤无意义停用词 → 用提示词模板把 query+context 送 LLM（支持流式）。

**实测效果**：
- 问企业转型 → 命中事件类型节点 → 反推发生该事件的公司及投资者 → LLM 列出转型公司；
- 问瑞幸咖啡 → 命中公司节点 → 查其事件（股价异常跌89%、造假欺诈等）→ LLM 总结；
- 问「中立深圳投资了什么公司」 → 命中投资者 → 多跳查其投资的科大讯飞及事件（2019裁员、股份解禁）→ LLM 总结。

## 四、自我学习方法（章节赠礼）

**新领域快速入门 3 步**：
1. 从综述文章找高频关键词，弄清领域最重要概念；

## 五、FAQ

**Q1：Graph RAG 比普通 RAG 强在哪？**
图结构天生表达关系，擅长多跳/语义关联/推理/聚合统计，普通 RAG 平面文本难捕隐含关系。

**Q2：关键词提取为什么最关键？**
它决定后续图检索命中什么节点；提取错了，检索与生成全错。

**Q3：get_context 的 query_level 降级是什么？**
level=1 查全关系（投资+事件），为空则 level=2 仅查公司-事件，保证总有上下文返回。

**Q4：原始文本怎么变图谱？**
用 LLM 提示词从文本自动抽取「实体-关系-实体」三元组，是 Graph RAG 热门方向。

## 六、面试高频问答

**1. 普通 RAG 与 Graph RAG 区别（列三点）？**
知识表达（平面文档 vs 图结构）、检索（向量 vs 图遍历）、擅长（近似匹配 vs 多跳/推理/聚合）。

**2. Graph RAG 构建三步骤？**
提取关键词 → 图库检索实体关系 → 整合上下文送 LLM 生成。

**3. Graph RAG 擅长哪些查询？**
多跳关系、语义关联、知识推理、聚合统计、时序关联。

**4. 文本变图谱怎么做？**
LLM 提示词抽取三元组（实体-关系-实体），再入库建图。

## 七、ops 提示（增效）

> **Graph RAG 不是替代向量 RAG，而是补位**：多跳/关系/聚合类问题才上图谱，纯语义问答仍用向量库，混合最稳。
>
> **关键词提取要带兜底**：提取失败或为空时，pipeline 应有默认降级（如退回全文/向量检索），别让图查询空跑。
>
> **context 长度管控**：报道 content 极长，默认排除只留 title+核心属性，确需细节再开 `include_content`，防 LLM 上下文溢出。
