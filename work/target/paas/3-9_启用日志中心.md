# Go PaaS 平台开发: go-micro v3 启用日志中心

## 纲要

- 微服务日志分散在各节点，ELK（Elasticsearch + Logstash + Kibana）提供集中收集与检索能力。
- 采集链路：应用写日志文件 → Filebeat 采集 → Logstash 过滤 → Elasticsearch 存储 → Kibana 展示。
- 用 docker-compose 单独部署 ELK（资源占用高，建议与业务中间件分开启动）。
- 代码中通过统一日志公共包把日志写入 `micro.log` 文件，再由 Filebeat 上报。

## ELK 整体架构

```mermaid
flowchart LR
    App[应用] -->|写入文件| Log[micro.log]
    Log -->|Filebeat 采集| LS[Logstash :5044]
    LS -->|过滤后写入| ES[Elasticsearch]
    ES -->|查询展示| Kibana[Kibana :5601]
```

每条日志先落盘到本地文件，Filebeat 作为守护进程持续读取并推送到 Logstash；Logstash 按规则过滤（不符合格式的直接丢弃），再写入 Elasticsearch，最终在 Kibana 看板检索分析。

## 关键端口

| 端口 | 作用 |
| --- | --- |
| 5601 | Kibana Web UI |
| 5044 | Logstash 接收 Filebeat 数据（Beats 输入） |
| 9200 | Elasticsearch HTTP API |
| 9300 | Elasticsearch 节点间通信 |

## Demo 示例

### docker-compose 部署 ELK

ELK 对内存/CPU 要求较高，建议单独一个 compose 文件启动，避免与其他中间件争抢资源：

```yaml
version: "3.8"

services:
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:7.17.10
    container_name: elasticsearch
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - ES_JAVA_OPTS=-Xms1g -Xmx1g
    ports:
      - "9200:9200"

  logstash:
    image: docker.elastic.co/logstash/logstash:7.17.10
    container_name: logstash
    depends_on:
      - elasticsearch
    ports:
      - "5044:5044"
    volumes:
      - ./logstash.conf:/usr/share/logstash/pipeline/logstash.conf:ro

  kibana:
    image: docker.elastic.co/kibana/kibana:7.17.10
    container_name: kibana
    depends_on:
      - elasticsearch
    ports:
      - "5601:5601"
```

`logstash.conf` 示例（Beats 输入 + 输出到 ES）：

```ruby
input {
  beats { port => 5044 }
}
output {
  elasticsearch {
    hosts => ["http://elasticsearch:9200"]
    index => "micro-log-%{+YYYY.MM.dd}"
  }
}
```

### 应用侧：统一日志公共包

把日志写入本地文件，便于 Filebeat 采集。公共包示例（节选）：

```go
package logutil

import (
	"log"
	"os"
)

// NewLogger 返回一个写入 micro.log 的日志器，按大小滚动、启用压缩
func NewLogger() *log.Logger {
	f, err := os.OpenFile("micro.log",
		os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0644)
	if err != nil {
		panic(err)
	}
	return log.New(f, "[paas] ", log.LstdFlags|log.Lshortfile)
}
```

在业务代码中替换原来的 `log.Printf`：

```go
logger := logutil.NewLogger()
// 原本的 log.Printf("connect mysql failed: %v", err)
// 改为：
logger.Printf("connect mysql failed: %v", err)
```

### Filebeat 配置

Filebeat 读取根目录下所有 `*.log` 并上报到 Logstash：

```yaml
filebeat.inputs:
  - type: log
    paths:
      - "*.log"

output.logstash:
  hosts: ["127.0.0.1:5044"]
```

启动命令：

```bash
filebeat -c filebeat.yml
```

> 说明：Filebeat 需根据操作系统下载对应版本，启动后日志即从 `micro.log` 流向 ELK。

### 运行说明

1. 资源充足时：`docker compose -f elk.yaml up -d`；机器紧张时先停掉 Consul/Jaeger/MySQL 再单独起 ELK。
2. 等待约 2~3 分钟，访问 `http://127.0.0.1:5601`，能看到 Kibana 看板即说明 ES 正常。
3. 启动 Filebeat，运行业务服务产生日志。
4. 在 Kibana 创建索引 `micro-log-*`，即可检索 `micro.log` 中的报错与运行信息。

### 技术点总结

- 日志先落盘再采集，Filebeat 是轻量守护进程，比让应用直连 ES 更稳。
- Logstash 的过滤规则决定哪些日志进 ES，可在此丢弃噪声。
- 统一日志公共包让所有模块写同一文件、同一格式，是接入 ELK 的前置条件。
- 后续日志中心稳定后，可把 3-7 中的 `log.Printf` 全部替换为该公共包。
