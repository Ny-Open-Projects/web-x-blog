# Go PaaS 平台开发: 服务管理前端展示与删除接口完善

## 纲要

- 前端页面通过 `svcApi` 的 HTTP 接口完成 Service 的创建、列表、删除
- 启动依赖：需同时拉起 `podApi` / `pod` / `service` / `svcApi` / `cap-api-gateway` 五个服务
- 用 `kubectl get svc` + `endpoints` 验证 Service 与 Pod 绑定成功
- 删除接口完善：删除 Service 的同时清理关联的 Pod 记录，使用事务 + 回滚保证一致
- 优化点：关联 Pod 的端口 / 协议应从前端的"应用"下拉获取

## 前端如何调用后端

平台提供了现成的前端页面（HTML），通过 `fetch` / `ajax` 方式调用 `svcApi` 暴露的接口：

- `index` 页面：刷新时请求 `svcApi`（查所有），把返回的服务列表渲染成表格。
- `create` 表单页：填写服务名、命名空间、关联 Pod 名称、端口、目标端口、协议、团队 ID，提交到 `svcApi/AddSvc`。
- `detail` 页：用 `get` 方式拉取单个服务，回填到表单。

## 启动与服务注册验证

演示前需启动五个服务，在注册中心（Consul）看到绿色勾号即表示全部就绪：

- 上章开发的两个：`podApi`、`pod`（service 端）。
- 本章开发的两个：`svcApi`、`service`（svc 端）。
- 网关：`cap-api-gateway`。

访问 `2080` 端口（网关地址）下的 `svcApi` 路径即可调用接口。创建成功后再查数据库或访问 `svcApi` 列表，能看到新服务说明接口打通。

## 验证 Service 与 Pod 的绑定

创建 `nginx-service`（命名空间 `default`，目标 `nginx` Pod，端口 `80` → `8080`，协议 `TCP`）后，用命令确认绑定：

```bash
kubectl get svc
kubectl describe svc nginx-service
kubectl get endpoints nginx-service -o yaml
```

关键点与第 6.1 节呼应：

- `Type` 为 `ClusterIP`。
- `Selector` 为 `app-name=nginx`（与 Pod 上的 `app-name` 标签一致），K8s 据此选中后端 Pod。
- `endpoints` 实时列出 Pod 的运行 IP（如 `11.1.1.5:8080`、`11.1.1.6:8080`），证明 Service 已成功绑定到后端 Pod。

## 删除接口完善（事务 + 回滚）

最初版本的删除只从数据库删除了 `Svc` 记录，关联 Pod 的垃圾数据没清。需要在删除 K8s 中 Service 成功后，一并把关联的 Pod 记录删除，并用事务保证两端一致：

1. 开启事务。
2. 调用 `DeleteFromK8s` 删除 K8s 中 Service；有错误则 `rollback` 并返回。
3. 删除关联的 Pod 记录（按 `SvcID` 关联）；有错误则 `rollback`。
4. 全部成功则 `commit`。

下面是根据讲稿逻辑补充的事务版删除代码：

```go
func (u *SvcDataService) DeleteFromK8sWithPod(svc *model.Svc, podRepo repository.IPodRepository) (err error) {
	tx := u.DB.Begin()
	defer func() {
		if err != nil {
			tx.Rollback()
		}
	}()
	// 1. 删除 K8s 中的 Service
	if err = u.K8sClientSet.CoreV1().Services(svc.SvcNamespace).Delete(
		context.TODO(), svc.SvcName, v12.DeleteOptions{}); err != nil {
		common.Error(err)
		return err
	}
	// 2. 删除数据库中的 Svc 记录
	if err = u.DeleteSvc(svc.ID); err != nil {
		common.Error(err)
		return err
	}
	// 3. 删除关联的 Pod 垃圾数据（按 SvcID 关联）
	if err = podRepo.DeletePodBySvcID(svc.ID); err != nil {
		common.Error(err)
		return err
	}
	tx.Commit()
	common.Info("删除Service及关联Pod成功，ID：" + strconv.FormatInt(svc.ID, 10))
	return nil
}
```

> 说明：上述代码片段为根据讲稿删除逻辑补充，演示了事务 + 回滚的结构；正式工程应复用 `repository` 的事务接口。
