# Go PaaS 平台开发: 用户中心角色数据层开发

## 纲要

- 角色数据层 `RoleRepository` 负责角色与角色—权限关联表的数据库读写。
- 角色与用户通过中间表 `user_role` 关联；角色与权限通过中间表 `role_permission` 关联。
- 除基础 CRUD 外，角色仓库需要补充四个常用接口：
  - `FindAllByIDs`：根据角色 ID 切片查出全部角色（供用户侧匹配使用）。
  - `AddPermission`：为角色添加权限。
  - `UpdatePermission`：更新角色权限（先删后插）。
  - `DeletePermission`：删除角色权限。
- `UpdatePermission` 的语义特殊：不是「覆盖差值」，而是先删除原有权限，再把当前权限整体重新插入。
- 本章仓库代码由模板生成，基础 CRUD 已就绪，开发者在模板上补充上述接口即可。

## 为什么角色要独立成库

用户、角色、权限是三个独立的聚合，各自对应一张主表，并通过中间表互相关联。用户与角色的关系通过 `user_role` 关联表表达，角色与权限的关系通过 `role_permission` 关联表表达。把角色单独抽出一个 repository，可以让「针对角色的增删改查」与「针对用户、权限的读写」相互隔离，避免把所有 SQL 堆在一个文件里。

角色仓库首先由模板生成（与 `UserRepository` 类似），模板已经提供了最基础的 CRUD。课程在这里要求大家在模板基础上再补充四个最常用的方法。

## 根据 ID 切片查询角色

用户侧在鉴权或展示时需要「拿到这个用户拥有的全部角色」，而用户模型里存的是角色 ID 切片。因此仓库提供一个按 ID 切片批量查询的接口：

```go
package repository

import (
	"usercenter/model"
	"xorm.io/xorm"
)

// RoleRepository 角色数据层
type RoleRepository struct {
	engine *xorm.Engine
}

// NewRoleRepository 构造角色仓库
func NewRoleRepository(engine *xorm.Engine) *RoleRepository {
	return &RoleRepository{engine: engine}
}

// FindAllByIDs 根据角色 ID 切片查出所有角色，ID 为切片类型，供用户侧匹配使用
func (r *RoleRepository) FindAllByIDs(ids []int64) ([]*model.Role, error) {
	if len(ids) == 0 {
		return []*model.Role{}, nil
	}
	roles := make([]*model.Role, 0, len(ids))
	if err := r.engine.In("id", ids).Find(&roles); err != nil {
		return nil, err
	}
	return roles, nil
}
```

`In("id", ids)` 是 XORM 的批量 IN 查询，直接把 ID 切片转换为 `WHERE id IN (?, ?, ...)`，比循环单查高效得多。

## 为角色添加权限

添加权限就是把若干 `Permission` 记录插入 `role_permission` 中间表（XORM 的 `Insert` 在 `manytomany` 关联上会自动维护中间表）：

```go
// AddPermission 为指定角色追加权限
func (r *RoleRepository) AddPermission(roleID int64, perms []*model.Permission) error {
	role := &model.Role{ID: roleID}
	// XORM 通过 manytomany(role_permission) 自动维护中间表
	_, err := r.engine.Insert(role, perms)
	return err
}
```

## 更新角色权限（先删后插）

`UpdatePermission` 的语义与直觉不同：它并不是「增量合并」，而是先把该角色原有的权限全部删除，再把传入的权限整体重新写入。相当于在更新前先执行一次删除，再执行一次添加。

```go
// UpdatePermission 更新角色权限：先删除原有权限，再整体重新插入
func (r *RoleRepository) UpdatePermission(roleID int64, perms []*model.Permission) error {
	session := r.engine.NewSession()
	defer session.Close()
	if err := session.Begin(); err != nil {
		return err
	}

	// 1. 删除该角色在中间表里的全部原有权限
	if _, err := session.Exec(
		"DELETE FROM role_permission WHERE role_id = ?", roleID,
	); err != nil {
		_ = session.Rollback()
		return err
	}

	// 2. 把当前权限整体重新插入
	role := &model.Role{ID: roleID}
	if _, err := session.Insert(role, perms); err != nil {
		_ = session.Rollback()
		return err
	}

	return session.Commit()
}
```

> 说明：生产环境中删除操作前后通常还会有前置校验（如「角色至少保留一个权限」），本章为了突出主干逻辑做了最简实现，业务可按需在 session 里补充这些校验。

## 删除角色权限

删除权限就是移除中间表里的对应记录，逻辑与上面删除分支一致：

```go
// DeletePermission 删除角色的部分权限
func (r *RoleRepository) DeletePermission(roleID int64, perms []*model.Permission) error {
	session := r.engine.NewSession()
	defer session.Close()
	if err := session.Begin(); err != nil {
		return err
	}
	for _, p := range perms {
		if _, err := session.Exec(
			"DELETE FROM role_permission WHERE role_id = ? AND permission_id = ?",
			roleID, p.ID,
		); err != nil {
			_ = session.Rollback()
			return err
		}
	}
	return session.Commit()
}
```

## 基础 CRUD 与模板生成

除上述四个补充接口外，角色的增、删、改、查由模板自动生成，例如：

```go
// 模板生成的基础方法（示意）
func (r *RoleRepository) Insert(role *model.Role) (int64, error) {
	return r.engine.Insert(role)
}
func (r *RoleRepository) FindByID(id int64) (*model.Role, error) {
	role := &model.Role{ID: id}
	has, err := r.engine.Get(role)
	if err != nil {
		return nil, err
	}
	if !has {
		return nil, nil
	}
	return role, nil
}
func (r *RoleRepository) Update(role *model.Role) error {
	_, err := r.engine.ID(role.ID).Update(role)
	return err
}
func (r *RoleRepository) Delete(id int64) error {
	_, err := r.engine.ID(id).Delete(new(model.Role))
	return err
}
```
