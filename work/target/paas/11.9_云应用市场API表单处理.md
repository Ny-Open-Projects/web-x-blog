# Go PaaS 平台开发: 云应用市场 API 表单处理研发

## 纲要

- 添加应用（AddAppStore）的「表单」即对外暴露的 Proto 请求 `AppStoreInfo`，它承载了主表字段与五类关联子表（图片、Pod、中间件、存储、评论）。
- 表单到领域模型的转换复用通用工具 `common.SwapTo`：基于 JSON Tag 做结构体拷贝，无需为每个字段手写赋值。
- 关联资源采用「模板 ID 引用」策略：应用市场只记录 Pod 模板、中间件模板、存储模板的 ID，模板本身在之前已创建好，避免在应用层重复创建。
- 表单处理中需要处理「排除逻辑」：应用自身及其依赖关系通过一份排除列表（Exclude List）跳过映射，仅对需要处理的字段做类型转换，防止出现类型不匹配错误。
- 提供两个常用辅助能力：判断字符串是否在某数组内（用于按应用名梳理字段）、按结构体标签把结果内容转换到 App 端。

## API 表单的设计背景

云应用市场的前端页面在「添加应用」时提交的数据量较大：除了应用标题、SKU、描述、详情、价格等主表字段，还包含多张图片、Pod 模板、中间件、存储模板、评论等关联数据。我们在 Proto 中把这一切统一抽象成 `AppStoreInfo` 消息：

```go
message AppStoreInfo {
    int64 id = 1;
    string app_sku = 2;
    string app_title = 3;
    string app_describe = 4;
    string app_detail = 5;
    float app_price = 6;
    int64 app_install = 7;
    int64 app_views = 8;
    bool app_check = 9;
    int64 app_category_id = 10;
    int64 app_isv_id = 11;
    repeated AppImage app_image = 12;
    repeated AppPod app_pod = 13;
    repeated AppMiddle app_middle = 14;
    repeated AppVolume app_volume = 15;
    repeated AppComment app_comment = 16;
}
```

表单处理的核心难点在于：**主表是一组简单字段，而子表是数组形式的关联实体**。如果为每个字段手写映射，既冗长又易错。因此我们复用已有的「表单转换」逻辑，把 `AppStoreInfo` 直接转换为 `model.AppStore`。

## 表单到模型的通用转换：SwapTo

整个表单处理的第一环，就是调用 `common.SwapTo` 把请求 Proto 拷贝到领域模型。其实现非常轻量——利用 JSON 序列化/反序列化，依据 JSON Tag 完成字段对齐：

```go
package common

import "encoding/json"

// 通过 json tag 进行结构体赋值
func SwapTo(request, target interface{}) (err error) {
    dataByte, err := json.Marshal(request)
    if err != nil {
        return
    }
    err = json.Unmarshal(dataByte, target)
    return
}
```

在 Handler 的 `AddAppStore` 中，表单处理的第一步就是这行转换：

```go
func (e *AppStoreHandler) AddAppStore(ctx context.Context, info *appStore.AppStoreInfo, rsp *appStore.Response) error {
    appStoreModel := &model.AppStore{}
    if err := common.SwapTo(info, appStoreModel); err != nil {
        common.Error(err)
        rsp.Msg = err.Error()
        return err
    }
    // ... 关联子表 ID 的二次填充见后续小节
    appStoreID, err := e.AppStoreDataService.AddAppStore(appStoreModel)
    // ...
}
```

`SwapTo` 能工作的前提是：Proto 生成结构体的 JSON Tag 与 `model.AppStore` 的 JSON Tag 命名一致（如 `app_sku`、`app_title`）。这也解释了为什么 `appStore.proto` 中字段统一采用 `app_xxx` 风格，而 GORM 模型同样使用 `json:"app_xxx"`。

## 关联数据的「排除列表」策略

表单里并非所有字段都能直接 `SwapTo` 映射。应用本身及其依赖关系（如模板 ID、外部服务引用）需要单独处理，于是我们维护一份「排除列表」，在表单转换时跳过这些字段，只对需要处理的普通字段做类型转换：

```go
// 伪代码：表单转换时的排除逻辑（依据讲稿中的排除列表思路整理）
var excludeList = []string{
    "app_image",      // 图片：单独处理
    "app_pod",        // Pod 模板：按模板 ID 引用
    "app_middle",     // 中间件：按模板 ID 引用
    "app_volume",     // 存储：按模板 ID 引用
    "app_comment",    // 评论：详情页单独写入
}

// 判断字符串是否在数组内：表单处理中按字段名梳理是否需要跳过
func inArray(target string, list []string) bool {
    for _, v := range list {
        if v == target {
            return true
        }
    }
    return false
}
```

若字段不在排除列表中，就走通用映射；若在列表中，则进入对应的专门处理函数（如 `setImage`、`setPod`、`setMiddle`、`setVolume`），把模板 ID 绑定到主模型上。这样可以避免「字段类型不匹配导致的序列化错误」。

## 关联资源为何只记录模板 ID

表单中 Pod 组合、中间件、存储三者，课程里都以「模板 ID」的方式记录，而不是在应用市场里重新创建一套 Pod/中间件/存储。原因是：

- 模板（如某个规格的 MySQL、某规格的磁盘）在前面章节已经创建好；应用市场只负责「引用」它们。
- 安装应用时不要求使用者手填内存、存储大小等变量，这些默认值由模板初始化，体验更接近手机应用商店「一键安装」。
- 因此 `AppPod`、`AppMiddle`、`AppVolume` 三个子表都只存 `app_id` + 对应的模板 `id`：

```go
type AppPod struct {
    ID       int64 `gorm:"primary_key;not_null;auto_increment"`
    AppID    int64 `json:"app_id"`
    AppPodID int64 `json:"app_pod_id"` // 引用的 Pod 模板 ID
}
```

## Demo 示例

**运行说明**：下面的示例演示 `SwapTo` 如何利用 JSON Tag 完成 Proto 风格结构体到领域模型的拷贝，可直接 `go run` 运行。

**代码说明**：`AppStoreInfoDTO` 模拟 Proto 请求（JSON Tag 为 `app_xxx`），`AppStore` 为领域模型（JSON Tag 一致），通过 `SwapTo` 完成转换。

**技术点总结**：表单处理的核心不是为每个字段手写赋值，而是统一约定 JSON Tag 后用 `SwapTo` 批量拷贝；对关联实体用排除列表分流到专门处理函数，并以模板 ID 引用降低冗余。

```go
package main

import (
    "encoding/json"
    "fmt"
)

// SwapTo 与课程 common 包一致：基于 JSON Tag 拷贝字段
func SwapTo(request, target interface{}) error {
    b, err := json.Marshal(request)
    if err != nil {
        return err
    }
    return json.Unmarshal(b, target)
}

// AppStoreInfoDTO 模拟 Proto 请求体
type AppStoreInfoDTO struct {
    AppSku        string `json:"app_sku"`
    AppTitle      string `json:"app_title"`
    AppDescribe   string `json:"app_describe"`
    AppCategoryID int64  `json:"app_category_id"`
}

// AppStore 模拟领域模型
type AppStore struct {
    AppSku        string `json:"app_sku"`
    AppTitle      string `json:"app_title"`
    AppDescribe   string `json:"app_describe"`
    AppCategoryID int64  `json:"app_category_id"`
}

func main() {
    dto := AppStoreInfoDTO{
        AppSku:        "SKU-1001",
        AppTitle:      "MySQL 高可用模板",
        AppDescribe:   "一键安装的主从 MySQL",
        AppCategoryID: 3,
    }
    model := &AppStore{}
    if err := SwapTo(dto, model); err != nil {
        panic(err)
    }
    fmt.Printf("表单转换结果: %+v\n", model)
}
```
