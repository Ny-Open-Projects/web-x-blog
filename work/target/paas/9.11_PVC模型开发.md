# Go PaaS 平台开发: PVC 模型开发

## 纲要

- PVC 模型核心属性：存储名称、类型、命名空间、容量大小、访问模式、StorageClass、存储介质类型
- 访问模式三种：ReadWriteOnce（单节点读写）、ReadOnlyMany（多节点只读）、ReadWriteMany（多节点读写），可共存，至少标记一种
- StorageClass 必须指定，否则 PVC 无法自动绑定 PV，状态停留在 Pending
- 请求容量用 float 类型（单位 GB），可结合业务逻辑做费用计算与配额拦截
- 存储介质类型：block（块存储）与 filesystem（文件系统）两种
- 表单入参结构体（VolumeInput）映射到模型，便于参数校验与入库

## 模型字段设计

每个存储资源对象都包含以下属性，需要在模型中清晰定义：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| Name | string | 存储名称 |
| Namespace | string | 命名空间 |
| Size | float64 | 请求容量，单位 GB |
| AccessMode | string | 访问模式，至少标记一种 |
| StorageClass | string | 必须显式指定 |
| VolumeType | string | block 或 filesystem |
| Status | string | 绑定状态（Pending / Bound 等） |

### 访问模式

访问模式分为三种，可共存，但至少标记一种：

- `ReadWriteOnce`：可读可写，仅单节点挂载
- `ReadOnlyMany`：只读，多节点挂载
- `ReadWriteMany`：可读可写，多节点挂载

### StorageClass 与容量

- `StorageClass` 表示使用哪个存储类创建 PV，**必须指定**。若不指定，PVC 虽能创建但不会采用默认 StorageClass 创建 PV，导致状态为 `Pending` 无法绑定
- 请求容量（Size）用于告知程序要划分的空间大小，采用 float 类型。可结合业务逻辑做费用计算：例如请求 20G 时按规则计费，超过 30G 则拦截创建

### 存储介质类型

当前支持的存储类型有两种：`block`（块存储）与 `filesystem`（文件系统）。

## Demo 示例

### 代码说明

`model/pvc.go` —— PVC 模型：

```go
package model

// PVC 持久化卷声明模型
type PVC struct {
	ID           uint    `json:"id" gorm:"primaryKey"`
	Name         string  `json:"name"`         // 存储名称
	Namespace    string  `json:"namespace"`    // 命名空间
	Size         float64 `json:"size"`         // 请求容量，单位 GB
	AccessMode   string  `json:"accessMode"`   // ReadWriteOnce / ReadOnlyMany / ReadWriteMany
	StorageClass string  `json:"storageClass"` // 必须指定
	VolumeType   string  `json:"volumeType"`   // block / filesystem
	Status       string  `json:"status"`       // 绑定状态
}
```

`model/volume_input.go` —— 表单入参：

```go
package model

// VolumeInput 创建存储时的表单入参，映射到 PVC 模型
type VolumeInput struct {
	Name         string  `json:"name"`         // 存储名称
	Namespace    string  `json:"namespace"`    // 命名空间
	Size         float64 `json:"size"`         // 请求容量（GB）
	AccessMode   string  `json:"accessMode"`   // 访问模式
	StorageClass string  `json:"storageClass"` // 存储类
	VolumeType   string  `json:"volumeType"`   // block / filesystem
}
```

### 技术点总结

- 模型字段与 K8s PVC Spec 一一对应，入库后可在创建时按 Size 做费用与配额控制
- `Size` 使用 float 便于做阈值判断（如超过 30G 拦截）
- 表单结构体（VolumeInput）与持久化模型（PVC）分离，便于参数校验与层级转换
- 下一节将跳过 repository 层，直接在 Service 中操作 K8s 完成 PVC 的创建
