# Go PaaS 平台开发: 云应用市场开发介绍

## 纲要

- 云应用市场的定位：把单个应用及其依赖的中间件统一打包成一个「云应用」，作为商品在 PaaS 平台内流通
- 解决的问题：此前各个模块都是单体形态，应用只能被单一服务商内部使用，缺少应用分发与复用能力
- 本章开发主线，分为三块：
  - 云应用市场服务端（后端微服务的核心业务逻辑）
  - 云应用市场 API（对外暴露的 HTTP/网关接口）
  - 前端表单提交：前端把应用信息以表单形式提交，服务端接收后写入数据库
- 核心价值：将应用「上架」为可浏览、可安装的商品，显著提升应用的安装率与复用效率

## 为什么要做云应用市场

在 PaaS 平台里，前面章节陆续开发了镜像、Pod、存储、服务、路由等基础能力。这些能力本身是「零件」，通常由平台内部或单一服务商自己使用。当我们需要把做好的应用交付给其他用户使用时，仅靠单体模块是无法完成的——用户没有渠道去浏览、选择并一键安装一个已经配置好的应用。

云应用市场正是用来解决这一类问题的产品方案：

1. 把应用本身，以及它关联的中间件（数据库、缓存、消息队列等），统一打包成一个「云应用」。
2. 在云应用上标记价格、展示标题、详情、截图等商品信息。
3. 把云应用当成一种商品，在 PaaS 平台中供其他用户浏览、安装。

通过这种「应用即商品」的思路，平台上的优质应用可以被反复安装，极大降低了使用门槛。

## 本章内容规划

本章以开发为主，重点落在业务逻辑的实现，整体分为三个层次：

云市场服务端开发
- 这是核心，包含领域模型（Model）、数据访问（Repository）、业务编排（Service）以及与 gRPC 对接的 Handler 层。
- 围绕「云应用」这一聚合根，设计它的属性：唯一标识、标题、描述、价格、安装次数、访问次数、审核状态、分类、服务商，以及它所关联的图片、Pod 模板、中间件模板、存储模板和评论。

云市场 API 开发
- 在服务端之上，再生成并完善一层对外 API。
- 除了基础的增删改查，还会补充运营侧高频使用的统计接口：安装量统计、浏览量统计等。

前端表单落库
- 结合前端页面，提供一个表单用于录入云应用信息。
- 服务端接收表单数据后，将完整数据写入数据库（关系型存储）。
- 课程中的前端页面只实现了基础表单，后续可结合前面章节学到的列表页、详情页做出更美观的页面。

## 小结

云应用市场把 PaaS 平台从「基础设施供给」推进到「应用交付」阶段。它让平台上沉淀的应用能够像商品一样被分发，是平台商业化闭环中非常关键的一环。接下来的小节会逐步落地：先定义领域模型，再实现数据访问与业务服务，最后通过 API 与前端表单把整个链路打通。
