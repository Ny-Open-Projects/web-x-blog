# Go PaaS 平台开发: 中间件前端页面与核心 API 开发（上）

## 纲要

- 对外通过 `middlewareApi` 这一 API 网关服务把内部 RPC 暴露成 HTTP 接口，路径形如 `/middlewareApi/AddMiddleware`。
- API Handler 的核心工作是：把前端表单的散列字段解析成结构化的 `MiddlewareInfo`，再调用内部 `middleware` 服务。
- 端口、环境变量、存储盘等「可多值」字段，前端用「序号后缀」命名（`middle_port`、`middle_env.key.1`、`middle_storage.name.1`…），后端按序号循环解析。
- 类型差异在后端体现：仅 `MYSQL` 类型需要解析 root 账号、普通账号、预置数据库等配置字段。
- 前端 `middleware-create.html` 提供中间件卡片入口，`middleware-create-mysql.html` 提供动态表单（MySQL 专属字段 + 通用字段）。

## API 服务的 Proto 定义

`middlewareApi` 服务采用通用的 `Request` / `Response` 包裹结构，便于透传 HTTP 的 header、get、post、body：

```proto
service MiddlewareApi {
    rpc FindMiddlewareById(Request) returns (Response){}
	rpc AddMiddleware(Request) returns (Response){}
	rpc DeleteMiddlewareById(Request) returns (Response){}
	rpc UpdateMiddleware(Request) returns (Response){}
	rpc FindAllMiddlewareByTypeId(Request) returns (Response){}
	rpc FindMiddleTypeById(Request) returns (Response){}
	rpc AddMiddleType(Request) returns (Response){}
	rpc DeleteMiddleTypeById(Request) returns (Response){}
	rpc UpdateMiddleType(Request) returns (Response){}
	rpc FindAllMiddleType(Request) returns (Response){}
}

message Pair {
	string key = 1;
	repeated string values = 2;
}
message Request {
	string method = 1;
	string path = 2;
	map<string, Pair> header = 3;
	map<string, Pair> get = 4;
	map<string, Pair> post = 5;
	string body = 6;
	string url = 7;
}
message Response {
	int32 statusCode = 1;
	map<string, Pair> header = 2;
	string body = 3;
}
```

## API Handler 的添加流程

`AddMiddleware` 把请求拆分给多个 `set*` 函数，分别构造端口、环境变量、存储盘、配置，最后统一调用内部 `MiddlewareService`：

```go
func (e *MiddlewareApi) AddMiddleware(ctx context.Context, req *middlewareApi.Request, rsp *middlewareApi.Response) error {
	log.Info("Received middlewareApi.AddMiddleware request")
	addMiddleInfo := &middleware.MiddlewareInfo{}
	// 设置端口
	port, err := e.setMiddlePort(req)
	if err != nil {
		common.Error(err)
		return err
	}
	addMiddleInfo.MiddlePort = port
	// 设置环境变量
	addMiddleInfo.MiddleEnv = e.setMiddleEnv(req)
	// 设置存储
	addMiddleInfo.MiddleStorage = e.setMiddleStorage(req)
	// 获取类型
	middleTypeInfo := e.getMiddleType(req)
	// 判断不同的类型设置不同的值
	switch middleTypeInfo.MiddleTypeName {
	case "MYSQL":
		middleConfig := e.setMiddleConfig(req)
		addMiddleInfo.MiddleConfig = &middleConfig
	}
	// 处理其余表单字段
	form.FormToMiddlewareStruct(req.Post, addMiddleInfo)
	// 调用后端服务添加数据
	response, err := e.MiddlewareService.AddMiddleware(ctx, addMiddleInfo)
	if err != nil {
		common.Error(err)
		return err
	}
	rsp.StatusCode = 200
	b, _ := json.Marshal(response)
	rsp.Body = string(b)
	return nil
}
```

## 多值字段的解析

端口、环境变量、存储都是「一对多」，后端用 `for` 循环按序号从 `req.Post` 中取值，遇到缺失即停止：

```go
// 设置端口
func (e *MiddlewareApi) setMiddlePort(req *middlewareApi.Request) ([]*middleware.MiddlePort, error) {
	dataSlice, ok := req.Post["middle_port"]
	if ok {
		middlePortSlice := []*middleware.MiddlePort{}
		for _, v := range dataSlice.Values {
			i, err := strconv.ParseInt(v, 10, 64)
			if err != nil {
				common.Error(err)
			}
			port := &middleware.MiddlePort{
				MiddlePort:     int32(i),
				MiddleProtocol: "TCP",
			}
			middlePortSlice = append(middlePortSlice, port)
		}
		return middlePortSlice, nil
	}
	return nil, errors.New("无端口")
}

// 设置中间件环境变量
func (e *MiddlewareApi) setMiddleEnv(req *middlewareApi.Request) []*middleware.MiddleEnv {
	envSlice := []*middleware.MiddleEnv{}
	i := 1
	for {
		tag := "middle_env.key." + strconv.Itoa(i)
		valueTag := "middle_env.value." + strconv.Itoa(i)
		key, ok := req.Post[tag]
		if ok {
			env := &middleware.MiddleEnv{
				EnvKey:   key.Values[0],
				EnvValue: req.Post[valueTag].Values[0],
			}
			envSlice = append(envSlice, env)
		} else {
			break
		}
		i++
	}
	return envSlice
}

// 设置中间件的存储
func (e *MiddlewareApi) setMiddleStorage(req *middlewareApi.Request) []*middleware.MiddleStorage {
	storageSlice := []*middleware.MiddleStorage{}
	i := 1
	for {
		nameTag := "middle_storage.name." + strconv.Itoa(i)
		sizeTag := "middle_storage.size." + strconv.Itoa(i)
		pathTag := "middle_storage.path." + strconv.Itoa(i)
		key, ok := req.Post[nameTag]
		if ok {
			sizeValue, _ := strconv.ParseFloat(req.Post[sizeTag].Values[0], 32)
			storage := &middleware.MiddleStorage{
				MiddleStorageName:       key.Values[0],
				MiddleStorageSize:       float32(sizeValue),
				MiddleStoragePath:       req.Post[pathTag].Values[0],
				MiddleStorageClass:      "csi-rbd-sc",
				MiddleStorageAccessMode: "ReadWriteOnce",
			}
			storageSlice = append(storageSlice, storage)
		} else {
			break
		}
		i++
	}
	return storageSlice
}
```

## 类型分支与配置解析

```go
func (e *MiddlewareApi) getMiddleType(req *middlewareApi.Request) (middleTypeInfo middleware.MiddleTypeInfo) {
	typeValue, ok := req.Post["middle_type_id"]
	if ok {
		typeId, err := strconv.ParseInt(typeValue.Values[0], 10, 64)
		if err != nil {
			common.Error(err)
			return
		}
		typeInfo, err := e.MiddlewareService.FindMiddleTypeByID(context.TODO(), &middleware.MiddleTypeId{Id: typeId})
		if err != nil {
			common.Error(err)
			return
		}
		middleTypeInfo = *typeInfo
	}
	return
}

func (e *MiddlewareApi) setMiddleConfig(req *middlewareApi.Request) (middleConfig middleware.MiddleConfig) {
	middleConfig.MiddleConfigRootUser = e.getValue(req, "middle_config_root_user")
	middleConfig.MiddleConfigRootPwd = e.getValue(req, "middle_config_root_pwd")
	middleConfig.MiddleConfigUser = e.getValue(req, "middle_config_user")
	middleConfig.MiddleConfigPwd = e.getValue(req, "middle_config_pwd")
	middleConfig.MiddleConfigDataBase = e.getValue(req, "middle_config_data_base")
	return
}

func (e *MiddlewareApi) getValue(req *middlewareApi.Request, key string) string {
	value, ok := req.Post[key]
	if ok {
		return value.Values[0]
	}
	return ""
}
```

## 前端创建表单

前端用纯 HTML 表单提交到 `http://localhost:8080/middlewareApi/AddMiddleware`，字段命名与后端解析规则严格对应。以 MySQL 为例，除通用字段外还有专属配置字段：

```html
<form action="http://localhost:8080/middlewareApi/AddMiddleware" method="post">
  <!-- 通用字段 -->
  <input type="text" name="middle_name" required>
  <input type="text" name="middle_namespace" value="default">
  <input type="text" name="middle_type_id" required>
  <input type="text" name="middle_version_id" required>

  <!-- 多端口：同名 middle_port 多个 input -->
  <input type="text" name="middle_port">
  <input type="text" name="middle_port">
  <input type="text" name="middle_port">

  <!-- 环境变量：序号后缀 -->
  key1:<input type="text" name="middle_env.key.1">
  value1:<input type="text" name="middle_env.value.1">
  key2:<input type="text" name="middle_env.key.2">
  value2:<input type="text" name="middle_env.value.2">

  <!-- 资源与副本 -->
  <input type="text" name="middle_replicas" value="1">
  <input type="text" name="middle_cpu">
  <input type="text" name="middle_memory">

  <!-- 存储盘：序号后缀 -->
  存储名称:<input type="text" name="middle_storage.name.1">
  存储大小:<input type="text" name="middle_storage.size.1">
  挂载目录:<input type="text" name="middle_storage.path.1">

  <!-- MySQL 专属配置 -->
  <input type="text" name="middle_config_root_user" value="root">
  <input type="text" name="middle_config_root_pwd" value="123456">
  <input type="text" name="middle_config_user" value="caplost">
  <input type="text" name="middle_config_pwd" value="caplost">
  <input type="text" name="middle_config_data_base" value="imooc">

  <button type="submit">创建 Mysql 中间件</button>
</form>
```

> 表单命名约定：多值字段用「基准名 + `.序号`」的方式（如 `middle_env.key.1` / `middle_env.value.1`），后端据此循环解析；生产若使用其它前端框架，只需保证提交字段同名即可。

## Demo 示例

以「创建 MySQL 中间件」为例，浏览器提交表单后，请求等价于：

```bash
curl -X POST http://localhost:8080/middlewareApi/AddMiddleware \
  -d "middle_name=mysql-demo" \
  -d "middle_namespace=default" \
  -d "middle_type_id=1" \
  -d "middle_version_id=2" \
  -d "middle_port=3306" \
  -d "middle_env.key.1=MYSQL_ROOT_HOST" \
  -d "middle_env.value.1=%" \
  -d "middle_replicas=1" \
  -d "middle_cpu=0.5" \
  -d "middle_memory=0.5" \
  -d "middle_storage.name.1=mysql-data" \
  -d "middle_storage.size.1=10" \
  -d "middle_storage.path.1=/var/lib/mysql" \
  -d "middle_config_root_user=root" \
  -d "middle_config_root_pwd=123456" \
  -d "middle_config_data_base=imooc"
```

运行说明：需先启动 `consul`、`MySQL`（配置中心存放连接信息）、`middleware` 内部服务，再启动 `middlewareApi` 网关；前端页面经 `filebeat` 收集日志，访问 `http://localhost:8080/middlewareApi/` 可探测服务。

技术点总结：
- API 层与内部 RPC 层解耦，前端只认 HTTP 表单，后端负责字段重组。
- 多值字段用「序号后缀」约定，避免为每种数量预定义结构。
- 类型分支让 MySQL 比 Consul / Redis 多出账号与数据库初始化能力。
