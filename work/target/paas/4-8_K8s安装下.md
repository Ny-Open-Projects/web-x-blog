# Go PaaS 平台开发: K8s 安装（下）

## 纲要

- Master 初始化：设置环境变量（MASTER_IP / APISERVER_NAME / POD_SUBNET），执行 `install_master.sh`
- `install_master.sh` 内部生成 `kubeadm-config.yaml` 并调用 `kubeadm init`
- 安装 Flannel 网络插件，使 Pod 跨节点互通
- Worker 节点通过 `kubeadm join` 加入集群（token 有效期 2 小时）
- 验证：`kubectl get nodes` 查看节点状态均为 Ready

> 本篇承接上篇的基础环境，完成 Master 初始化、网络插件安装与 Worker 加入，最终得到一个可运行的单 Master + 单 Worker 集群。

## Step 1：初始化 Master 节点

先在 Master 节点上设置环境变量（注意 `export` 仅对当前 shell 有效，新开窗口需重设）：

```bash
# 只在 master 节点执行
# 替换为 master 节点的实际内网 IP
export MASTER_IP=192.168.0.10
# 替换为期望的 apiserver 域名
export APISERVER_NAME=apiserver.caplost.com
# K8s 容器组所在网段（安装后由 K8s 自动创建，物理网络中本不存在）
export POD_SUBNET=10.100.0.1/16

echo "${MASTER_IP}    ${APISERVER_NAME}" >> /etc/hosts
```

然后执行 `install_master.sh`，它会生成 `kubeadm-config.yaml` 并初始化集群：

```bash
# 只在 master 节点执行
chmod +x install_master.sh
./install_master.sh 1.21.5
```

脚本核心逻辑如下（节选自 `install_master.sh`）：

```bash
# 生成 kubeadm 配置文件
cat <<EOF > ./kubeadm-config.yaml
---
apiVersion: kubeadm.k8s.io/v1beta2
kind: ClusterConfiguration
kubernetesVersion: v${1}
imageRepository: registry.cn-shanghai.aliyuncs.com/cap1573
controlPlaneEndpoint: "${APISERVER_NAME}:6443"
networking:
  serviceSubnet: "10.96.0.0/16"
  podSubnet: "${POD_SUBNET}"
  dnsDomain: "cluster.local"
dns:
  type: CoreDNS
  imageRepository: registry.cn-shanghai.aliyuncs.com/cap1573
  imageTag: 1.8.0
---
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
cgroupDriver: systemd
EOF

# 拉取镜像并初始化 master
kubeadm config images pull --config=kubeadm-config.yaml
kubeadm init --config=kubeadm-config.yaml --upload-certs

# 配置 kubectl
mkdir -p /root/.kube/
cp -i /etc/kubernetes/admin.conf /root/.kube/config
```

初始化完成后，执行以下命令等待 3–10 分钟，直到所有系统 Pod 进入 `Running` 状态：

```bash
# 只在 master 节点执行
watch kubectl get pod -n kube-system -o wide
kubectl get nodes -o wide
```

## Step 2：安装 Flannel 网络插件

Flannel 负责为 Pod 分配跨节点可达的 IP。先把 Pod 网段写入配置并应用：

```bash
# 只在 master 节点执行
export POD_SUBNET=10.100.0.0/16
sed -i "s#10.244.0.0/16#${POD_SUBNET}#" flannel-v0.14.0.yaml
kubectl apply -f ./flannel-v0.14.0.yaml
```

`flannel-v0.14.0.yaml` 中以 DaemonSet 形式在每个节点部署 `kube-flannel-ds`，并通过 ConfigMap `kube-flannel-cfg` 定义网络（`Network: 10.244.0.0/16`，后端使用 vxlan）。应用后稍等片刻，网络组件就绪。

## Step 3：初始化 Worker 节点并加入集群

先在 Master 上生成 join 命令（token 有效期 2 小时，过期可重新执行）：

```bash
# 只在 master 节点执行
kubeadm token create --print-join-command
# 输出形如：
# kubeadm join apiserver.caplost.com:6443 --token xxxx \
#   --discovery-token-ca-cert-hash sha256:xxxxxxxxxxxxxxxx
```

在 Worker 节点上设置与 Master 一致的解析变量，并执行上面打印出的 join 命令：

```bash
# 只在 worker 节点执行
export MASTER_IP=192.168.0.10
export APISERVER_NAME=apiserver.caplost.com
echo "${MASTER_IP}    ${APISERVER_NAME}" >> /etc/hosts

# 替换为 master 上 kubeadm token create 命令的输出
kubeadm join apiserver.caplost.com:6443 --token xxxx \
  --discovery-token-ca-cert-hash sha256:xxxxxxxxxxxxxxxx
```

若 join 的 token 已过期，回到 Master 重新执行 `kubeadm token create --print-join-command`，再用新 token 在 Worker 上重新 join 即可。

## Step 4：验证集群

回到 Master 节点查看节点状态：

```bash
# 只在 master 节点执行
kubectl get nodes -o wide
```

当列出的 master 与 worker 节点状态均为 `Ready` 时，说明集群已顺利安装完成。此时你已经具备一个可用的 K8s 集群，可以基于此继续后续的 PaaS 平台开发。

> 提示：若某些系统 Pod 仍显示未就绪，属正常现象，等待几分钟即可自动恢复。
