# Go PaaS 平台开发: go-micro v3 框架快速入门概览

## 纲要

- 本章目标：在动手开发 PaaS 平台之前，先用最短的路径掌握 go-micro v3 微服务框架及其周边技术栈。
- 核心议题：
  - go-micro v3 与 micro v3 的定位与关系
  - go-micro v3 的整体架构与核心组件
  - 用 Consul 搭建集群版注册中心与配置中心
  - 通过配置中心连接 MySQL
  - 链路追踪（Jaeger）、日志中心（ELK + Filebeat）、监控中心（Prometheus + Grafana）
- 学习建议：即使学过 go-micro v2，也建议完整跟完本章，因为 v3 在组件拆分、插件引用方式、配置中心形态上都有变化。

## 本章在 PaaS 平台中的位置

PaaS 平台本质上是一组微服务：用户中心、应用管理、路由管理、后台监控等模块彼此独立部署、独立伸缩。go-micro v3 提供了一整套开发微服务的抽象能力——服务注册发现、负载均衡、消息通信、配置、链路追踪等，使我们能专注于业务逻辑，而把基础设施交给框架与中间件。

本章不深入讲解每一个中间件的内部原理，而是以"可运行"为目标，把下列技术栈逐一接入 go-micro v3：

- 注册中心 / 配置中心：Consul
- 关系型存储：MySQL（经由配置中心动态获取连接参数）
- 链路追踪：Jaeger
- 日志收集：ELK（Elasticsearch + Logstash + Kibana）+ Filebeat
- 指标监控：Prometheus + Grafana

## 与 go-micro v2 的差异提示

- v3 将大量通用能力拆成了独立插件仓库（以 `github.com/asim/go-micro/plugins/...` 形式引用），引入方式与原生 `go-micro/v3` 不同。
- 配置中心从单机文件演进为基于 Consul 的集群版，支持动态读取与热更新。
- 链路追踪、监控等组件在 v3 中的包装器（Wrapper）注册方式有所调整。
