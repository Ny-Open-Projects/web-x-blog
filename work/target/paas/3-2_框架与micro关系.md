# Go PaaS 平台开发: go-micro v3 框架与 micro v3 的关系

## 纲要

- go-micro 是一个 Go 语言微服务开发框架，类比其他语言中的 Spring（Java）、Iris（Go Web）等。
- go-micro v3 与 micro v3 名字相近但职责不同：一个偏"开发框架"，一个偏"基础设施抽象/平台工具"。
- v2 时代二者耦合较紧，v3 时代已经各司其职、明显分化。
- 本课程选择 go-micro v3，目的是为了完全掌控框架与中间件，而不是被平台强绑定。

## go-micro 是什么

go-micro 是一套用于快速开发微服务的 Go 框架。它把服务开发过程中大量底层、复杂且重复的工作（如服务注册、服务间通信、编解码、消息发布订阅等）封装进框架，使开发者只需关注业务 Handler 的实现。

借助其多语言客户端设计，使用 go-micro 编写的服务端，也可以被其他语言的客户端调用，因此微服务之间不必与某一种语言强绑定。

## go-micro v3 与 micro v3 的关系

| 维度 | go-micro v3 | micro v3 |
| --- | --- | --- |
| 角色 | 微服务开发框架 | 基础设施抽象 / 平台工具 |
| 关注点 | 提供完整的微服务开发能力，自由度高 | 把中间件、追踪等基础设施抽象到云端，开发者只写业务代码 |
| 与平台绑定 | 不强绑定，可自由替换中间件 | 与官方平台绑定较多 |
| 适用场景 | 希望深度掌握并自定义微服务技术栈 | 希望尽量不关心底层基础设施 |

在 v2 时代，go-micro 与 micro 之间工具与框架的关系较为紧密；到了 v3，两者分裂为各自独立的定位：go-micro v3 继续作为"开发框架"提供从注册发现到通信的完整能力，而 micro v3 更接近于一套把基础设施抽象出来、由云端提供能力的运行/管理平台。

## 为什么本课程选择 go-micro v3

- 自由度更高：可以自行选择并替换注册中心（Consul、etcd 等）、配置中心、数据库、追踪系统等，便于讲解每个组件的原理。
- 可深入掌控：本章会演示如何引用成熟中间件、如何替换中间件，以及这些中间件背后的关键原理，帮助建立对微服务整体技术栈的完整认知。
- 与官方平台解耦：micro v3 与官方平台绑定较多，而我们更希望对 go-micro 框架本身有充分掌握，因此采用 go-micro v3。
