## 本章回顾

本章围绕 Go PaaS 平台的分布式存储管理功能展开，整体脉络如下：

1. **基础概念**：理解 Ceph 的特性、三种存储类型（块 / 文件 / 对象）与核心组件（OSD / MON / MDS），以及基于 RADOS 的整体架构。
2. **集群安装**：用 cephadm 引导基础集群，扩展节点并添加 OSD，进而安装 RGW、CephFS、iSCSI 等核心组件。
3. **接入 K8s**：通过官方推荐的 CSI 模式，把外部 Ceph 集群接入 PaaS 平台运行的 K8s，实现按需动态供给存储卷（StorageClass + PVC）。
4. **后端开发**：基于 client-go 用 Go 封装存储 Service，自动创建 / 删除 PVC，并与平台业务记录关联，对外提供「云盘」开通能力。

## 生产实践经验

在真实使用 Ceph 作为 PaaS 平台存储底座时，以下几点尤为重要：

- **PG 数量要提前规划**：PG 是 Ceph 数据分布与调度的基本单位。若在集群扩容后才频繁调整 PG 数量，调度过程会大量占用网络带宽，导致集群变慢。应在使用前就根据容量与节点规模规划好。
- **副本数至少保留 3 份**：为保障单节点宕机时数据不丢失、且存储能继续对外服务，建议除主数据外至少再保留 2 个副本（共 3 份）。这样节点故障时可临时启用副本，保障业务不中断。
- **维护前打快照**：在对 Ceph 存储做维护（尤其是 MySQL 数据维护）之前，先对对应存储打一份快照。相比用备份工具逐文件回滚，快照回滚速度更快，能在操作异常时快速恢复。
