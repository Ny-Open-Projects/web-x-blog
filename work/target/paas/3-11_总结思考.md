# Go PaaS 平台开发: go-micro v3 框架快速入门总结思考

## 纲要

- 回顾本章主线：go-micro v3 架构与定位、Consul 集群版、配置中心、MySQL 接入、链路追踪、日志中心、监控中心。
- 技术栈全景：注册/配置（Consul）、存储（MySQL）、追踪（Jaeger）、日志（ELK + Filebeat）、监控（Prometheus + Grafana）。
- 与 go-micro v2 的迁移注意点：插件拆分、配置中心形态、包装器注册方式。
- 课后练习建议与下一阶段预告：正式进入 PaaS 平台模块开发，并深入 Kubernetes。

## 本章回顾

本章用最短路径把 go-micro v3 及其周边技术栈打通，目标是让后续 PaaS 平台开发"站在框架肩膀上"：

1. **框架与定位**：厘清 go-micro v3（开发框架）与 micro v3（平台/工具）的关系，明确本课程选择 go-micro v3 以获得更高自由度。
2. **整体架构**：掌握 Registry / Selector / Transport / Broker / Server / Client 等核心组件与通信模型。
3. **注册与配置**：用 Consul 集群版同时承担注册中心与配置中心，服务高可用、配置集中化。
4. **存储接入**：通过配置中心动态获取参数并连接 MySQL（GORM）。
5. **可观测性三件套**：
   - 链路追踪 Jaeger：还原跨服务调用链与耗时。
   - 日志中心 ELK + Filebeat：集中收集、检索日志。
   - 监控中心 Prometheus + Grafana：观测 GC、goroutine、内存等运行时指标。

## 与 go-micro v2 的差异

- 组件拆分为独立插件仓库（`github.com/asim/go-micro/plugins/...`），引入方式变化。
- 配置中心从单机文件演进为基于 Consul 的集群版，支持集中管理与动态读取。
- 链路追踪、监控等包装器在 v3 中的注册方式（`/v3` 后缀）与 v2 不兼容，混用会编译报错。
