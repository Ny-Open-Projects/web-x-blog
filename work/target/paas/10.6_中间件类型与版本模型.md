# Go PaaS 平台开发: 中间件类型与版本模型 MiddleType / MiddleVersion

## 纲要

- `MiddleType` 与 `MiddleVersion` 拥有独立于 `Middleware` 的生命周期
- 一个类型包含多个版本，二者是一对多关系
- 版本的「镜像地址 + 版本号」组合成完整镜像引用 `image:tag`
- 类型与版本单独建表、单独仓储、单独服务，与中间件实例解耦

## 为什么类型和版本要独立建模

在平台里，「中间件类型」（MySQL、Redis…）和「中间件版本」（MySQL 5.7、MySQL 8.0…）是相对固定的「目录数据」，而「中间件实例」（用户真正创建出来的那个 MySQL）则是易变业务数据。

用户创建实例时依赖类型与版本的 ID，但类型与版本自身可以独立管理：运维可以下架某个版本、新增镜像，而不影响已创建的中间件实例。因此本章把 `MiddleType` 与 `MiddleVersion` 设计成独立于 `Middleware` 的两个模型，并配套独立的仓储与服务。

```go
package model

// 中间件类型
type MiddleType struct {
	ID int64 `gorm:"primary_key;not_null;auto_increment" json:"id"`
	// 中间件类型名称
	MiddleTypeName string `json:"middle_type_name"`
	// 中间件图片地址
	MiddleTypeImageSrc string `json:"middle_type_image_src"`
	// 中间件的版本
	MiddleVersion []MiddleVersion `gorm:"ForeignKey:MiddleTypeID" json:"middle_version"`
}

type MiddleVersion struct {
	ID int64 `gorm:"primary_key;not_null;auto_increment" json:"id"`
	MiddleTypeID int64 `json:"middle_type_id"`
	// 镜像地址
	MiddleDockerImage string `json:"middle_docker_image"`
	// 镜像版本
	MiddleVS string `json:"middle_vs"`
}
```

## 字段说明

| 模型 | 字段 | 类型 | 含义 |
| --- | --- | --- | --- |
| `MiddleType` | `ID` | `int64` | 类型主键 |
| `MiddleType` | `MiddleTypeName` | `string` | 类型名称，如 `mysql` |
| `MiddleType` | `MiddleTypeImageSrc` | `string` | 前端展示用的图标地址 |
| `MiddleType` | `MiddleVersion` | `[]MiddleVersion` | 该类型下的版本列表 |
| `MiddleVersion` | `ID` | `int64` | 版本主键 |
| `MiddleVersion` | `MiddleTypeID` | `int64` | 所属类型 ID |
| `MiddleVersion` | `MiddleDockerImage` | `string` | 镜像地址 |
| `MiddleVersion` | `MiddleVS` | `string` | 镜像版本（tag） |

## 设计要点

- **一对多关联**：`MiddleType` 通过 `MiddleVersion []MiddleVersion` + `gorm:"ForeignKey:MiddleTypeID"` 关联；查询类型时可用 `Preload("MiddleVersion")` 一次性加载其全部版本（见 10.8 仓储层）。
- **镜像引用组合**：完整的镜像引用由 `MiddleDockerImage` 与 `MiddleVS` 拼接而成，格式为 `镜像地址:版本号`（例如 `mysql:8.0`）。平台创建实例时正是通过版本 ID 反查出这一组合，再交给 Kubernetes 拉取镜像。
- **私有镜像扩展**：若使用私有仓库，可在此模型上追加 Secret 相关字段，按需扩展，不影响现有结构。
- **与实例解耦**：`Middleware` 只持有 `MiddleTypeID` 与 `MiddleVersionID` 两个外键，不直接内嵌类型/版本数据，保证目录数据与业务实例互不干扰。

## API 速览

类型与版本相关操作由独立的 `MiddleTypeDataService` 提供，关键方法有：

- `FindMiddleTypeByID(id)`：返回类型并 `Preload` 其所有版本（前端下拉框数据源）
- `FindAllVersionByTypeID(typeID)`：按类型查询全部版本
- `FindImageVersionByID(versionID)`：返回 `镜像地址:版本号` 字符串，供创建实例时使用

```go
// 根据版本 ID 拼出完整镜像引用
func (u *MiddleTypeDataService) FindImageVersionByID(middleVersionID int64) (string, error) {
	version, err := u.MiddleTypeRepository.FindVersionByID(middleVersionID)
	if err != nil {
		return "", err
	}
	return version.MiddleDockerImage + ":" + version.MiddleVS, nil
}
```
