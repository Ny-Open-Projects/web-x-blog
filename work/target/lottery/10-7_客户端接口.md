# Go 企业级抽奖项目: 实现 Thrift 客户端接口

## 纲要

- 客户端只需引入对应语言的 Thrift 类库 + 生成代码，即可像本地调用一样使用远程接口
- PHP 客户端示例：加载 Thrift 类库、建立 HTTP 连接、调用 `DoLucky` / `MyPrizeList`
- Go 客户端示例：基于自动生成的 `goclient_main.go` 命令行工具调用服务端
- 不同语言客户端的“连接 + 协议”部分完全通用，差异只在参数构造与返回值处理
- 实际联调验证：服务端启动后，PHP 与 Go 客户端均可正常调用

## 客户端的总体思路

Thrift 客户端比服务端简单得多，因为它只“消费”接口。无论哪种语言，步骤都一样：

1. 引入 Thrift 运行时类库（来自 Thrift 源码 `lib` 目录下对应语言的部分）和生成的代码（`Types.php` / `LuckyService.php`，或 Go 的 `rpc` 包）。
2. 建立一个到服务端的连接，设置传输协议（Transport）与序列化协议（Protocol）。
3. 用生成代码里提供的 Client 对象直接调用远程方法。

## PHP 客户端实现

PHP 客户端需要把 Thrift 源码 `lib/php` 下的 `Thrift` 类库目录复制进项目（即 `php_client/lib/Thrift`），再 `require` 进来。下面是课程里的 `php_client.php`（精简展示关键逻辑）：

```php
<?php
error_reporting(E_ALL);
require_once __DIR__.'/lib/Thrift/ClassLoader/ThriftClassLoader.php';
use Thrift\ClassLoader\ThriftClassLoader;

// 引入 Thrift 生成的代码
$GEN_DIR = realpath(dirname(__FILE__)).'/../../';
include $GEN_DIR . "Types.php";
include $GEN_DIR . "LuckyService.php";

$loader = new ThriftClassLoader();
$loader->registerNamespace('Thrift', __DIR__.'/lib');
$loader->registerDefinition('rpc', $GEN_DIR);
$loader->register();

use Thrift\Protocol\TJSONProtocol;
use Thrift\Transport\TSocket;
use Thrift\Transport\THttpClient;
use Thrift\Transport\TBufferedTransport;

// 得到 thrift 客户端连接对象
function getClient() {
    // 通过 HTTP 连接到 Go 服务端的 /rpc
    $socket = new THttpClient('localhost', 8080, '/rpc', 'http');
    $transport = new TBufferedTransport($socket, 1024, 1024);
    $protocol  = new TJSONProtocol($transport);
    $client    = new \rpc\LuckyServiceClient($protocol);
    $transport->open();
    return $client;
}

$client = getClient();

$uid = 20; $username = "admin"; $ip = "127.0.0.1";
$now = time(); $app = "web";
$sign = md5("0123456789abcdefuid=$uid&username=$username&ip=$ip&now=$now&app=$app");

// 调用抽奖
$rs = $client->DoLucky($uid, $username, $ip, $now, $app, $sign);
var_dump($rs);

// 调用中奖列表
$rs = $client->MyPrizeList($uid, $username, $ip, $now, $app, $sign);
var_dump($rs);
```

前面这些“建立连接、选择 TJSONProtocol、创建 Client”的代码在所有 Thrift RPC 调用里都是一模一样的通用模板，真正随接口变化的只有最后调用的方法与参数。

### 运行结果

服务端启动后，进入 PHP 客户端目录直接执行：

```bash
php php_client.php
```

可以看到 `MyPrizeList` 返回了该用户的 5 条中奖记录，而 `DoLucky` 首次返回“今日的抽奖次数已用完”，换成 uid=20 后则返回了成功中奖的信息——说明 PHP 客户端已能正常与 Go 服务端通信。

## Go 客户端实现

Go 客户端就是 Thrift 自动生成的 `goclient_main.go`（位于 `rpc/lucky_service-remote/go_client`）。它本质是一个命令行工具：解析 `-h host:port`、`-u url`、`-framed` 以及协议参数，再根据子命令 `DoLucky` / `MyPrizeList` 和参数发起调用。核心片段如下：

```go
func main() {
	// ...解析 host/port/url/protocol...
	var protocolFactory thrift.TProtocolFactory
	switch protocol {
	case "json":
		protocolFactory = thrift.NewTJSONProtocolFactory()
	case "binary", "":
		protocolFactory = thrift.NewTBinaryProtocolFactoryDefault()
	// 还支持 compact / simplejson
	}
	iprot := protocolFactory.GetProtocol(trans)
	oprot := protocolFactory.GetProtocol(trans)

	// 用生成的客户端发起调用
	client := rpc.NewLuckyServiceClient(thrift.NewTStandardClient(iprot, oprot))
	if err := trans.Open(); err != nil {
		fmt.Fprintln(os.Stderr, "Error opening socket:", err)
		os.Exit(1)
	}
	defer trans.Close()

	// 构造签名
	now := time.Now().UnixNano()
	str := fmt.Sprintf("uid=%d&username=%s&ip=%s&now=%d&app=%s", uid, username, ip, now, app)
	sign := comm.CreateSign(str)

	rs, _ := client.DoLucky(context.Background(), uid, username, ip, now, app, sign)
	fmt.Println(rs)
}
```

编译并运行：

```bash
go build -o lucky_service-remote rpc/lucky_service-remote/go_client
./lucky_service-remote -u http://localhost:8080/rpc DoLucky 1 admin 127.0.0.1 1710000000 web <sign>
```

如果签名参数不正确，会直接被服务端的 `checkParams` 拦住——这说明请求确实已经走到了服务端的校验环节。在调试阶段可以临时关闭服务端的签名校验（`return nil`）来快速打通链路，连通后再恢复。

## 多语言客户端的共性

除了 PHP 和 Go，还可以有 Java、Python 等客户端，思路完全一致：

- 各自引入本语言的 Thrift 类库；
- 用统一的 `lucky.thrift` 生成对应代码；
- 建立 Socket/HTTP 连接、选用序列化协议；
- 通过生成的 Client 调用方法。

客户端之间唯一不同的，只是参数构造与返回值的本地处理。
