# Go 企业级抽奖项目: 年会抽奖需求分析与并发安全考量

## 纲要

- 年会抽奖的两个基本功能：一次性导入全员名单、每次随机抽取一名中奖者
- 奖项既包含固定等级（一/二等奖），也允许领导临时追加，但抽奖算法保持一致
- 业务上由单人操作、不存在真实并发；程序以 Web 接口形式提供，仍须考虑并发安全
- 本章将以 Iris 框架把六种抽奖活动逐一编码实现，年会抽奖为开篇，引出贯穿全课程的"并发安全"问题

## 需求梳理

本章进入实战，选取六种典型抽奖活动并用代码模拟实现。第一种是年会抽奖，需求非常朴素：

- **导入名单**：一次性导入全公司员工名单，作为可参与抽奖的用户池。
- **抽奖**：每次随机抽取一名用户，被抽中者即为当期中奖人。
- **奖项**：可能包含固定的一等奖、二等奖，也常有领导临时追加的奖品。无论奖项如何变化，抽奖的算法本身是不变的，否则就不属于同一种抽奖玩法。

## 并发安全的必要性

年会是领导在台上操作、念出中奖者名字，现场只有一个人操作，并不具备真实并发。但我们编写的抽奖程序是以 Web 应用形式对外提供接口的，任何客户端都可能高频、并发地访问它。从工程角度，必须考虑并发安全性——尤其在共享数据（如参与名单切片）被并发读写时，否则可能出现数据错乱，落到"在年会上被叫上台 review 代码"的尴尬境地。

## 本章路线

后续会基于 Iris 框架（Go 语言的 Web 框架）把六种抽奖活动全部实现。年会抽奖作为开篇，重点不在于业务多复杂，而在于引出 **"共享变量在并发读写下的安全性"** 这一贯穿全课程的核心问题，后续的彩票、摇一摇、抢红包等活动都会反复触及它。
