# Go 企业级抽奖项目: 支付宝集福卡抽奖实现

## 纲要

- 集福卡活动与微信摇一摇高度相似，可直接复用之前的控制器、日志、抽奖码生成等代码。
- 福卡奖品数量固定为五张（富强福、和谐福、友善福、爱国福、敬业福），使用结构体数组而非切片，无需库存概念。
- 中奖概率不是运营后台静态配置，而是由请求参数 `rate` 动态传入（如 `4,3,2,1,0`），解析后生成概率区间。
- 提供两个接口：首页返回福卡列表与对应概率；抽奖接口根据抽奖码匹配区间命中福卡。
- 每次请求都会重新生成一份独立的 `giftList`，不存在共享变量，因此天然没有并发安全性问题，可水平扩展部署多台服务器。

## 活动特点与数据建模

集福卡的核心差异在于：**奖品固定且数量有限（五张福字）**，不存在库存扣减，也没有"剩余数量"字段。因此数据结构比微信摇一摇更简单——用结构体数组即可，初始化时用 `new`/字面量而非 `make`。

五张福卡的名称固定，概率初始值统一为 0，真正的权重来自外部传入的 `rate` 参数。这样设计的好处是运营无需改代码，只需在请求里带上不同的 `rate` 即可改变各个福卡的产出概率。

## 动态概率与区间生成

`rate` 参数是逗号分隔的字符串（例如 `4,3,2,1,0`），依次对应五张福卡的概率权重。解析时需要做兼容性处理：如果传入的个数少于福卡数量，缺失的部分概率置 0。

```go
package main

import (
	"fmt"
	"strconv"
	"strings"
)

// Gift 福卡定义，数量固定，使用结构体数组而非切片
type Gift struct {
	ID      int
	Name    string // 富强福、和谐福、友善福、爱国福、敬业福
	Rate    int    // 概率权重（来自 rate 参数，百分比）
	RateMin int    // 概率区间下界（含）
	RateMax int    // 概率区间上界（不含）
}

// giftList 固定的五张福卡，无库存概念
var giftList = [5]Gift{
	{ID: 1, Name: "富强福"},
	{ID: 2, Name: "和谐福"},
	{ID: 3, Name: "友善福"},
	{ID: 4, Name: "爱国福"},
	{ID: 5, Name: "敬业福"},
}

// BuildGiftList 依据 rate 参数（如 "4,3,2,1,0"）动态设置概率并生成区间
func BuildGiftList(rate string) [5]Gift {
	list := giftList
	parts := strings.Split(rate, ",")
	for i := range list {
		if i < len(parts) {
			if v, err := strconv.Atoi(strings.TrimSpace(parts[i])); err == nil {
				list[i].Rate = v
			}
		}
		// 越界或未提供则保持默认 0
	}
	// 生成连续概率区间
	min := 0
	for i := range list {
		max := min + list[i].Rate
		list[i].RateMin = min
		list[i].RateMax = max
		min = max
	}
	return list
}

func main() {
	list := BuildGiftList("4,3,2,1,0")
	for _, g := range list {
		fmt.Printf("%s 概率=%d%% 区间=[%d,%d)\n", g.Name, g.Rate, g.RateMin, g.RateMax)
	}
}
```

## 抽奖接口

首页接口把生成后的福卡列表与概率直接返回，便于调试；抽奖接口复用之前封装的"抽奖码"生成方法，再根据抽奖码落在哪个区间来判定命中的福卡。由于每张福卡命中即发放，无需再判断剩余数量。

```go
// GetLucky 抽奖：每次请求重建 giftList，无共享状态，天然无线程安全问题
func GetLucky(rate string, code int) string {
	list := BuildGiftList(rate)
	for _, g := range list {
		if code >= g.RateMin && code < g.RateMax {
			return g.Name // 命中即发福卡
		}
	}
	return "" // 未命中任何福卡
}
```

示例请求：访问首页查看区间后，按 `rate=4,3,2,1,0` 刷新即可看到不同福卡的返回结果；由于敬业福概率为 0，永远不会被刷出。

## 并发安全性分析

集福卡程序之所以没有并发安全问题，关键在于 **`giftList` 不是公共变量**：每个请求进来都重新生成一份独立数据，请求之间没有任何共享状态，也不存在库存扣减。因此这种活动可以部署任意多台服务器，在当前程序模型下没有并发瓶颈。

只有当后端引入了持久化存储（如数据库记录已集福卡用户）时，才需要额外考虑存储层的并发。这也是它与微信摇一摇、大转盘这类"有库存、有共享状态"的活动的本质区别。

## API 速览

- `BuildGiftList(rate string) [5]Gift`：解析概率参数并生成五张福卡的概率区间，返回结构体数组。
- `GetLucky(rate string, code int) string`：传入概率参数与抽奖码，返回命中的福卡名称，未命中返回空串。
- 首页接口（GET）：返回当前福卡列表及概率，支持 `rate` 查询参数，默认 `0,0,0,0,0`。
- 抽奖接口（GET）：复用抽奖码生成与区间匹配逻辑，命中即返回对应福卡。
