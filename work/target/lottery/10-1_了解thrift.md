# Go 企业级抽奖项目: 了解 Thrift 框架与 RPC 选型

## 纲要

- RPC 框架的核心价值：把数据序列化/反序列化、传输协议封装到底层，让跨语言调用远程接口像调用本地方法一样简单
- 主流 RPC 方案横向对比：gRPC、REST/HTTP、Protobuf，理解各自的适用边界
- 为什么本课程选择 Thrift 作为抽奖系统的 RPC 框架
- Thrift 开发环境安装：Go 依赖包与 `thrift` 编译器本体
- Thrift 的类型体系：基础类型（bool、i32、i64、double、binary、string）与复合类型（struct、list、map、set）

## RPC 框架解决了什么问题

在抽奖系统里，抽奖接口最初是放在 Web 站点（Iris）里通过 HTTP 提供的。随着业务增长，我们往往需要用其他编程语言（例如 PHP 客户端、Java 后台）去调用这套抽奖逻辑。如果每次都手工拼装 JSON、自己处理网络收发和字段映射，不仅繁琐，而且不同调用方很容易出现协议不一致的问题。

RPC（Remote Procedure Call，远程过程调用）框架的出现就是为了解决这件事。它主要做两件事：

1. 封装数据的序列化与反序列化，让结构体可以在不同语言之间被正确转换。
2. 封装底层传输协议（TCP、HTTP 等），调用方无需关心网络细节。

最终效果是：客户端用自己语言的方法签名去调用，框架在背后把参数序列化、通过网络发给服务端、再把返回值反序列化回来——对开发者而言，调用远程方法几乎和调用本地方法一致。

## 与 gRPC 的对比

gRPC 是 Google 在 2015 年发起的开源 RPC 框架，相对年轻。它的特点是：

- 数据模型与序列化基于 Protobuf（Protocol Buffers）。
- 传输协议使用 HTTP/2。
- 在规范化和标准化方面做得很好，没有在核心点上重复造轮子。

gRPC 的优势是设计更现代，新项目采用得越来越多。但它有一个现实短板：生态积累时间短，大量存量系统仍然跑在 Thrift 上。存量系统从 Thrift 迁移到 gRPC，意味着服务端、客户端接口和全部调用代码都要重写，迁移成本极高。因此只要老系统还在用 Thrift，就大概率会继续维护下去，gRPC 很难在短期内完全替代它。

## 与 REST/HTTP 接口的对比

传统的 REST 接口、HTTP 接口通常使用短连接，数据以文本（如 JSON）形式传输，序列化效率偏低。更重要的是，调用方需要手动完成请求体的拼装和服务端返回值的解析，哪怕这些转换只是简单的序列化/反序列化，依然要开发者自己处理。

除了性能偏弱，程序调用的严谨性也不如 RPC：REST 接口传递的是松散的 JSON 文本，而不是在代码中严格定义好的方法参数和数据模型，类型安全和契约约束都弱一些。

## 与 Protobuf 的对比

Protobuf 同样来自 Google，也非常成熟，支持多种编程语言。但它只解决了“数据模型的定义与序列化/反序列化”这一件事，缺少 Thrift 底层那一层通信封装。正因为一个完整的 RPC 框架离不开通信协议封装，Google 才在 Protobuf 之上又做了 gRPC。换句话说，Protobuf 是 Thrift 的子集能力，单靠它无法独立构成一套可用的 RPC 通信方案。

## 为什么选择 Thrift

综合以上对比，Thrift 作为比较早的 RPC 开源项目，在性能、易用性和功能完整性上都非常优秀，至今仍有大量系统在使用。它能让我们用一份 IDL（接口定义文件）生成多种编程语言的代码，既快速创建服务端接口，又方便生成和开发各类语言的客户端。

本课程的 Go 抽奖系统就使用 Thrift 来构建抽奖接口：Go 作为服务端，PHP、Java 等作为客户端，统一契约、减少异构系统联调成本。

## 安装 Thrift 开发环境

要使用 Thrift，需要完成两个层面的安装。

第一步，在 Go 项目中引入 Thrift 的 Go 语言包，这样我们才能在 Go 代码里使用 Thrift 开发：

```bash
go get git.apache.org/thrift.git/lib/go/thrift
```

第二步，安装 `thrift` 编译器本体。服务端和客户端都会用到它来生成公共代码（类型定义与服务接口）。不同系统的安装方式：

```bash
# macOS，使用 Homebrew
brew install thrift

# Linux，使用 yum
yum install thrift

# Windows，前往 Apache Thrift 官网的 download 页面下载对应版本源码编译安装
```

在下载的 Thrift 源码里，`lib` 目录下包含了各种编程语言的类库源码。本课程用到的是 Go 类库（`lib/go/thrift`），其他语言（PHP、Java 等）的类库也都在这里可以找到，客户端开发时需要把它们引入到对应语言的工程里。

## Thrift 的类型体系

编写 Thrift 定义文件时，需要了解它支持的类型。

基础类型：

| 类型 | 含义 |
| --- | --- |
| `bool` | 布尔型 |
| `byte` | 8 位有符号整数 |
| `i16` | 16 位整数 |
| `i32` | 32 位整数 |
| `i64` | 64 位整数 |
| `double` | 双精度浮点数 |
| `string` | 字符串 |
| `binary` | 二进制数据 |

复合类型：

- `struct`：结构体，作用与 Go 里的 `struct` 完全一致，内部可包含多个不同类型的字段。
- `list<T>`：列表/数组，对应 Go 的切片（slice）。
- `map<K,V>`：哈希表，对应 Go 的 `map`。
- `set<T>`：集合。

接下来的一讲，我们就用这些类型把抽奖系统的 Thrift 定义文件写出来。

## 总结

本章从概念层面认识了 Thrift：它是一个成熟的 RPC 框架，核心价值在于封装序列化协议与传输协议，使跨语言远程调用像本地调用一样简单。通过和 gRPC、REST/HTTP、Protobuf 的对比，我们明确了在存量系统主导的场景下选择 Thrift 的合理性，并完成了 Thrift 编译器与 Go 依赖包的安装准备。
