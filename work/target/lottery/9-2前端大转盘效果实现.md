# Go 企业级抽奖项目: 前端大转盘效果实现

## 纲要

- 静态页面 `lucky.html`：基于 Bootstrap + jQuery + 旋转动画，导航栏从 `public/index.html` 复用（登录/退出）
- 流式布局双转盘：左半区「转盘旋转」，右半区「指针旋转」，视觉表现不同但数据一致
- 奖品角度映射 `items`：`key` 为奖项，`value` 为 `[起始角度, 结束角度]`；以 12 点钟为 0°，顺时针递增
- `lucky.js` 核心：页面加载初始化控件、`click` 事件触发 `luckyDo`、`loadCallback` 停止回调 `luckyShow`
- `luckyDo`：AJAX 调用 `/lucky`，按 `data.code` 决定转盘停在哪个奖项；成功时取 `gift.displayOrder` 与附加数据 `gdata`
- 演示验证：登录态抽奖、库存耗尽转「幸运奖」、发券码用尽转无奖状态

## 页面结构

`lucky.html` 是一个静态页面，从 GitHub 开源项目中取来的转盘效果。头部引入了 Bootstrap 样式表、GitHub 相关样式、jQuery，以及旋转动画所需的脚本与 Bootstrap 的 JS 文件；转盘的动态旋转效果由 jQuery 相关插件提供，我们自定义的逻辑放在 `lucky.js` 中。

页面主体采用 `container-fluid` 流式布局（占满屏幕宽度），在大屏下分成左右各 50% 的两块（Bootstrap 12 栏中每半边占 6 栏 `col-md-6`）。两块各放一个转盘，区别仅在于：左侧转盘整体旋转，右侧指针旋转。

顶部导航直接从 `public/index.html` 复制而来，具备登录 / 退出功能。页面底部还会检查 `cookie` 中的用户 ID、用户名，判断登录态后在「登录区块」与「退出区块」之间切换显隐。

## 奖品角度映射

转盘的奖品由 `items` 配置，结构为 `key => [起始角度, 结束角度]`。角度约定：指针指向 12 点钟为 0°，3 点钟为 90°，6 点钟为 180°，9 点钟为 270°，转满一圈回到 360°。

例如四个奖项：一等奖、二等奖、三等奖、幸运奖，对应 `items` 大致如下（角度需与后台奖品顺序及背景图严格对应）：

```js
// lucky.js 中的奖品角度定义（根据讲稿逻辑整理）
const items = {
  1: [220, 310], // 一等奖区间 220°~310°
  2: [311, 400], // 二等奖（400° 即 360°+40°，跨圈）
  3: [41, 128],  // 三等奖
  4: [129, 219], // 幸运奖
};
// 指针初始角度（落在 270°，即一等奖区间内）
const pointerDeg = 270;
```

> 关键点：`items` 的奖品顺序与角度区间，必须和后台设置的奖品 `displayOrder`、背景图一一对应。一旦更换背景图或调整奖品顺序，角度要重新计算，否则指针停下的位置会与真实奖品错位。

## 转盘初始化与事件

页面 `DOM ready` 后初始化两个转盘控件。两个控件元素基本相同（背景图、指针、按钮一致），差异只在旋转方式：左侧 `realcontainer` 用 `w`（转盘转），右侧 `realcontainto` 用 `p`（指针转）。

```js
// lucky.js 初始化逻辑（根据讲稿逻辑补充，示意）
$(function () {
  // 转盘一：转盘整体旋转
  const turntable1 = new Turntable({
    container: '#realcontainer',
    items: items,
    pointerDeg: pointerDeg,
    spin: 'w',            // w: 转盘转, p: 指针转
    onClick: luckyDo,     // 点击开始抽奖
    onStop: luckyShow,    // 停下回调
  });
  // 转盘二：指针旋转
  const turntable2 = new Turntable({
    container: '#realcontainto',
    items: items,
    pointerDeg: pointerDeg,
    spin: 'p',
    onClick: luckyDo,
    onStop: luckyShow,
  });
  turntable1.build();
  turntable2.build();
});
```

## 抽奖请求与结果处理

点击抽奖时执行 `luckyDo`：发起 AJAX 请求 `/lucky`，不缓存，返回类型 JSON，超时 1000ms。根据 `data.code` 决定转盘停在哪：

- `code === 0`：中奖，停在 `gift.displayOrder` 对应奖项位置；若奖品带附加数据 `gdata`（如虚拟币数量、优惠券编码），一并拼进提示文案。
- `code === 101`：未登录，引导去登录页。
- `code < 200`：其他限制（如超出今日抽奖次数），转盘转到「幸运奖」（标签 4）位置停下。

奖项标签映射：一等奖=1，二等奖=2，三等奖=3，幸运奖=4。

```js
// lucky.js 核心：luckyDo（根据讲稿逻辑补充，示意）
function luckyDo(view) {
  $.ajax({
    url: '/lucky',
    cache: false,
    dataType: 'json',
    timeout: 1000,
    success: function (data) {
      if (data.code === 0) {
        // 中奖：停在奖品展示顺序位
        const order = data.gift.displayOrder;
        const extra = data.gift.gdata ? '，编码：' + data.gift.gdata : '';
        view.spinTo(order, '恭喜你中奖了：' + data.gift.title + extra);
      } else if (data.code === 101) {
        // 未登录
        view.spinTo(4, '请先登录再来抽奖');
        location.href = '/';
      } else {
        // 受限（如超次）：停在幸运奖
        view.spinTo(4, '今日机会已用完，谢谢参与');
      }
    },
    error: function (err) {
      console.error('抽奖请求失败', err);
      view.spinTo(4, '网络异常，谢谢参与');
    },
  });
}

// 转盘停下后弹窗提示
function luckyShow(view) {
  alert(view.luckyMessage);
}
```

## Demo 示例

下面给出可直接运行的极简演示页面，复现「转盘旋转 + 调用 /lucky + 按 code 停位」的核心逻辑。请将 `/lucky` 替换为你的真实接口地址。

运行说明：用任意静态服务器打开 `lucky.html`（如 `python3 -m http.server`），点击按钮即可观察旋转与结果提示。

代码说明：示例中 `Turntable` 为简化封装，用 CSS `transform: rotate` 实现旋转；`luckyDo` 用 `fetch` 调用后端，按 `data.code` 计算目标角度。技术点集中在「前后端约定 code 语义」与「角度与奖品顺序对齐」。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>抽奖大转盘 Demo</title>
  <style>
    .wheel { width: 240px; height: 240px; border-radius: 50%;
             background: conic-gradient(#f96 0 25%, #9cf 0 50%, #fc9 0 75%, #9f9 0);
             transition: transform 4s ease-out; position: relative; }
    .pointer { position: absolute; top: -10px; left: 50%; transform: translateX(-50%);
               border: 10px solid transparent; border-bottom-color: #333; }
    button { margin-top: 16px; }
  </style>
</head>
<body>
  <div class="wheel" id="wheel"><div class="pointer"></div></div>
  <button onclick="draw()">开始抽奖</button>
  <script>
    // 一等奖0°~90°, 二等奖90°~180°, 三等奖180°~270°, 幸运奖270°~360°
    const items = { 1:[0,90], 2:[90,180], 3:[180,270], 4:[270,360] };
    let current = 0;
    async function draw() {
      const res = await fetch('/lucky', { cache: 'no-store' });
      const data = await res.json();
      let target;
      if (data.code === 0) target = items[data.gift.displayOrder];
      else target = items[4]; // 未登录/受限 -> 幸运奖
      const mid = (target[0] + target[1]) / 2 + 360 * 5; // 多转几圈后停在中点
      current = mid;
      document.getElementById('wheel').style.transform = `rotate(${current}deg)`;
      setTimeout(() => alert(data.code === 0 ? '恭喜：' + data.gift.title : '谢谢参与'), 4100);
    }
  </script>
</body>
</html>
```

技术点总结：

- 转盘动画本质是 CSS 旋转，角度计算必须与后台奖品顺序（`displayOrder`）一致。
- 后端通过 `code` 统一表达「中奖 / 未登录 / 受限 / 未中奖（如库存或券码耗尽）」，前端只负责表现。
- `gdata` 承载奖品附加信息（虚拟币数量、优惠券编码），需在提示中透出，否则用户看不到具体奖励。

## 演示中的关键现象

- 未登录点击抽奖：接口返回 `code=101`，前端提示先登录。
- 登录后抽奖：返回 `code=0`，按 `displayOrder` 停在对应奖项；如三等奖优惠券会带出券码（如 234567）。
- 一等奖库存耗尽：本应中一等奖但发不出奖，后端返回无奖状态（演示中记为 206），前端落到「幸运奖」位置。
- 优惠券码发完：中到三等奖但券码已用尽，同样落为无奖状态（演示中记为 208）。

这说明发奖环节的健壮性直接影响前端表现：发不出奖时要能优雅降级为「谢谢参与」，而不是卡住或报错。
