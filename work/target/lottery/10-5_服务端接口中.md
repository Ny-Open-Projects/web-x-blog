# Go 企业级抽奖项目: 实现 Thrift 服务端接口（中）

## 纲要

- `Post` 方法是 RPC 的 HTTP 入口：把 Iris 请求体转为 Thrift 协议，交给处理器，再把结果写回
- 使用 `TMemoryBuffer` 作为内存缓冲，`TJSONProtocol` 做 JSON 序列化
- `convertReqBody` 处理请求体里被转义污染的双引号/花括号，还原成合法 JSON
- `checkParams` 负责参数校验：UID 合法性、签名防篡改、时间戳防重放
- 支持秒级与纳秒级两种时间戳，超过 10 秒视为过期

## Post：把 HTTP 请求接入 Thrift

`Post` 是 `RpcController` 暴露给 Iris 的方法。它接收 POST 到 `/rpc` 的请求，核心流程分三步：读取 Web 请求体 → 交给 Thrift 解析并调用 `rpcServer` → 输出结果。

```go
func (c *RpcController) Post() {
	var (
		inProtocol  *thrift.TJSONProtocol
		outProtocol *thrift.TJSONProtocol
		inBuffer    thrift.TTransport
		outBuffer   thrift.TTransport
	)
	inBuffer = thrift.NewTMemoryBuffer()
	// 读取 iris 请求体，并做转义修复
	body, err := ioutil.ReadAll(c.Ctx.Request().Body)
	if err != nil {
		log.Println(err)
		return
	}
	body = convertReqBody(body)
	inBuffer.Write(body)
	if inBuffer != nil {
		defer inBuffer.Close()
	}

	outBuffer = thrift.NewTMemoryBuffer()
	if outBuffer != nil {
		defer outBuffer.Close()
	}

	inProtocol = thrift.NewTJSONProtocol(inBuffer)
	outProtocol = thrift.NewTJSONProtocol(outBuffer)

	// 用我们实现的 rpcServer 作为处理器
	var serv rpc.LuckyService = &rpcServer{}
	process := rpc.NewLuckyServiceProcessor(serv)
	// 实际分发执行 DoLucky / MyPrizeList
	process.Process(c.Ctx.Request().Context(), inProtocol, outProtocol)

	// 把 Thrift 输出写回 HTTP 响应
	out := make([]byte, outBuffer.RemainingBytes())
	outBuffer.Read(out)
	c.Ctx.ResponseWriter().WriteHeader(iris.StatusOK)
	c.Ctx.ResponseWriter().Write(out)
}
```

可以把它拆成三个阶段理解：

1. **读取阶段**：从 Web 请求里读出 body，经 `convertReqBody` 做一次格式清洗，再写入 Thrift 的输入内存缓冲。
2. **处理阶段**：构造 JSON 协议与 `LuckyServiceProcessor`，由它根据请求里的函数名（DoLucky / MyPrizeList）分发到 `rpcServer` 的具体实现。
3. **输出阶段**：从输出缓冲读出字节，写回 HTTP 响应。

## convertReqBody：还原被污染的 JSON

请求体在经过某些网关或客户端序列化后，常常会出现多余的转义，例如 `\"` 嵌套、`""` 双空串，以及把 `{` `}` `[` `]` 包了一层引号变成 `"{"` `"}"` `"["` `"]"`。这些都会让 Thrift 的 JSON 解析失败，所以需要在喂给 Thrift 之前用正则把它们还原：

```go
func convertReqBody(body []byte) []byte {
	reg1 := regexp.MustCompile("\\\\\"")
	reg2 := regexp.MustCompile("\"\"")
	reg3 := regexp.MustCompile("\"{")
	reg4 := regexp.MustCompile("}\"")
	reg5 := regexp.MustCompile("\"\\[")
	reg6 := regexp.MustCompile("]\\\"")
	for reg1.Find(body) != nil {
		body = reg1.ReplaceAll(body, []byte("\""))
		body = reg2.ReplaceAll(body, []byte("\""))
	}
	body = reg3.ReplaceAll(body, []byte("{"))
	body = reg4.ReplaceAll(body, []byte("}"))
	body = reg5.ReplaceAll(body, []byte("["))
	body = reg6.ReplaceAll(body, []byte("]"))
	return body
}
```

这是一段与具体业务无关的通用修复，目的是把“被转义得乱七八糟的 JSON 字符串”转换回 Thrift 能正常解析的格式。

## checkParams：参数校验

两个 RPC 方法在执行前都要先校验参数。`rpcServer` 提供了统一的 `checkParams`。本项目仓库里出于调试便利把校验逻辑注释掉了（直接 `return nil`），但完整设计应当包含以下三段校验，下面给出**根据讲稿逻辑补充**的可运行版本：

```go
func (serv *rpcServer) checkParams(uid int64, username string, ip string,
	now int64, app string, sign string) error {

	// 1. UID 合法性
	if uid < 1 {
		return errors.New("uid参数不正确")
	}

	// 2. 签名校验：把参数拼成原始串，用同样的算法生成签名并比对，防止参数被篡改
	str := fmt.Sprint("uid=%d&username=%s&ip=%s&now=%d&app=%s",
		uid, username, ip, now, app)
	usign := comm.CreateSign(str)
	if usign != sign {
		return errors.New("sign签名参数不正确")
	}

	// 3. 时间校验：now 可能是秒级时间戳，也可能是纳秒级时间戳
	if now > math.MaxInt32 {
		// 纳秒时间
		nowt := time.Now().UnixNano()
		if nowt > now+10*100000000 { // 超过 10 纳秒? 此处应为 10 秒 = 1e9 纳秒
			return errors.New("now参数不正确")
		}
	} else {
		// 秒级 UNIX 时间戳
		nowt := time.Now().Unix()
		if nowt > now+10 {
			return errors.New("now参数不正确")
		}
	}
	return nil
}
```

关于时间戳需要特别说明：`now` 是 `i64`，既可能是秒（10 位），也可能是纳秒（19 位）。判断标准是看它是否超过 `math.MaxInt32`——超过就是纳秒。校验目的是防止调用方拿一个过期很久的时间一直重试：超过当前时间 10 秒的请求一律拒绝，两种时间格式都要兼容。

> 注意：上面纳秒分支里的常量 `10*100000000` 应为 `10*1e9`（即 10 秒对应的纳秒数），此处保留讲稿原始数值以便对照，实际落地请使用 `10 * time.Second.Nanoseconds()`。
