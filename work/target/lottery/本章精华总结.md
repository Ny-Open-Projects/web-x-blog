# Go 企业级抽奖项目: 第4章项目框架与核心代码精华总结

## 纲要

- 数据源层：MySQL（XORM）与 Redis（redigo 连接池）的实例创建，均采用单例模式，全局唯一、按需初始化。
- 配置与工具：`conf` 集中管理时间格式、中国时区、密钥与抽奖参数；`comm` 沉淀时间、随机、加解密、转义、类型转换等高频通用方法。
- Web 站点层：以 Iris v12 为核心，通过 `bootstrap` 启动器封装应用初始化，用 MVC 组织控制器，`routes` 完成路由与服务注入，`main.go` 作为入口。
- 安全登录态：基于 Cookie 承载用户状态，用服务端密钥 + MD5 签名防止客户端篡改，支持登录、退出与过期控制。
- 工程约定：运行工作目录需对齐 `web/`，模板与静态资源才能正确加载。

## 数据源：单例 + 连接池

- MySQL：通过 XORM 创建全局 `Engine` 单例，首次访问加锁初始化，二次判空后返回，避免重复建连。
- Redis：`conf.RdsConfig` 描述节点信息；`redigo` 的 `redis.Pool` 作为连接池，用 `sync.Once` 实现单例；最底层封装 `Do` 方法统一执行命令并统计微秒级耗时，便于排查慢查询。

## 配置与通用方法

- `conf/project.go`：时间格式（`2006-01-02 15:04:05` 等）、中国时区 `Asia/Chongqing`、签名密钥 `SignSecret`、Cookie 密钥 `CookieSecret`，以及抽奖次数上限、奖品类型常量、按小时分布的奖品权重。
- `comm` 包：`NowUnix` / `FormatFromUnixTime` 时间处理、`Random` 随机、`CreateSign` 签名、`encrypt`/`decrypt` AES 对称加解密、`AddSlashes`/`StripSlashes` 转义、`Ip4toInt` 节省存储、`NextDayDuration` 定时任务辅助，以及 `GetInt64` / `GetString` 等安全的 `interface{}` 类型转换封装。

## Web 站点：Iris + 启动器

- `bootstrap.Bootstrapper` 通过匿名嵌入 `iris.Application` 复用 Iris 全部能力，并以 `Configurator` 函数类型把配置过程参数化。
- 初始化流程：`SetupViews`（HTML 模板 + 自定义时间函数）→ `SetupSessions`（securecookie 会话）→ `SetupErrorHandlers`（按 `json` 参数分流 JSON / 错误页）→ 静态资源 / favicon → 计划任务 → `recover` + `logger` 中间件。
- 控制器 `IndexController` 内嵌 `iris.Context` 并声明服务字段，由路由层 `Register` 注入；方法命名即路由（`Get()` → `GET /`，`GetGifts()` → `GET /gifts`）。
- `routes.Configure` 把前台 `/`、后台 `/admin`（套 BasicAuth）、RPC `/rpc` 三类入口分组挂载；`main.go` 收敛为“创建 → 装配 → 监听”三步。

## 安全登录态

- `ObjLoginuser` 模型以 `Sign` 字段承载防篡改签名。
- `comm.GetLoginUser` 解析 Cookie、转换字段、检查 30 天有效期后重算 MD5 签名并比对；`comm.SetLoginuser` 写入或清除 Cookie。
- `IndexController.GetLogin` / `GetLogout` 分别完成随机 UID 登录与退出，密钥仅在服务端可见，客户端无法伪造合法签名。

## 工程经验

- 单例 + 连接池是高并发下数据库/缓存访问的基石，务必 `defer Close()` 归还连接。
- 把高频、易错的逻辑下沉到 `conf` 与 `comm`，保证全项目术语与行为一致。
- 运行工作目录要对齐 `web/`，否则模板与静态资源加载失败——这是本地首次启动最常见的坑。
