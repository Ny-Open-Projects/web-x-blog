# Go 企业级抽奖项目: 奖品管理实现（上）

## 纲要

- `AdminGiftController` 由 `AdminController` 派生，复用后台布局与鉴权。
- 页面动作：列表页 `Get()`、编辑页 `GetEdit()`、保存 `PostSave()`、删除 `GetDelete()`、恢复 `GetReset()`。
- 列表页数据：`GiftList`（奖品切片）与 `GiftTotal`（总数）注入模板。
- 编辑页数据：依据 URL 的 `id` 参数取单条 `GiftInfo`；无 `id` 则使用空值（新增）。
- 保存与状态动作返回 `mvc.Response` 做跳转，而非渲染模板。
- 路由：以 `admin.Party("/gift")` 挂载，自动继承 `/admin` 的鉴权中间件，仅注册 `GiftService`。

## 控制器骨架

奖品管理是后台第一个完整模块，因此先把控制器的全部动作定义出来，再逐个填充业务逻辑。

```go
package controllers

import (
    "github.com/kataras/iris/v12/mvc"
    "github.com/kataras/iris/v12"

    "lottery/services"
    "lottery/models"
    "lottery/viewmodels"
)

// AdminGiftController 奖品管理后台
type AdminGiftController struct {
    mvc.Controller
    GiftService services.GiftService
}

// Get 奖品列表页
func (c *AdminGiftController) Get() mvc.Result {
    return mvc.View{
        Name: "admin/gift.html",
        Data: iris.Map{
            "Title":    "奖品管理",
            "Channel":  "gift",
            "GiftList": []models.LtGift{}, // 实际数据在下一讲填充
            "GiftTotal": 0,
        },
        Layout: "shared/layout.html",
    }
}

// GetEdit 新增/编辑页
func (c *AdminGiftController) GetEdit() mvc.Result {
    giftInfo := viewmodels.ViewGift{} // 默认空值=新增
    return mvc.View{
        Name: "admin/giftedit.html",
        Data: iris.Map{
            "Title":    "奖品编辑",
            "Channel":  "gift",
            "GiftInfo": giftInfo,
        },
        Layout: "shared/layout.html",
    }
}

// PostSave 保存（新增或更新）
func (c *AdminGiftController) PostSave() mvc.Result {
    // 业务逻辑在 5-5 填充
    return mvc.Response{
        Path: "/admin/gift", // 保存后跳回列表页
    }
}

// GetDelete 删除（状态置 1）
func (c *AdminGiftController) GetDelete() mvc.Result {
    return mvc.Response{Path: "/admin/gift"}
}

// GetReset 恢复（状态置 0）
func (c *AdminGiftController) GetReset() mvc.Result {
    return mvc.Response{Path: "/admin/gift"}
}
```

## 路由注册

通过 `admin.Party("/gift")` 挂载，既继承了 `/admin` 的 BasicAuth 中间件，又复用了 `/admin` 的路径前缀；由于只涉及奖品，仅需注册 `GiftService`。

```go
// 在 main.go 的 newApp 中补充
admin.Party("/gift").Get("/", new(controllers.AdminGiftController))
// 子动作由 Iris 按方法名自动映射：GetEdit->/gift/edit，PostSave->/gift/save 等
```

> 说明：`AdminGiftController` 直接挂在 `admin.Party("/gift")` 上，而非从 `mvc` 重新派生，因此可以自动继承父级 Party 的路径前缀与中间件，权限校验随之复用。

## API 速览

| 动作 | HTTP | 映射路径 | 返回 |
| --- | --- | --- | --- |
| `Get` | GET | `/admin/gift` | 模板 `gift.html` |
| `GetEdit` | GET | `/admin/gift/edit` | 模板 `giftedit.html` |
| `PostSave` | POST | `/admin/gift/save` | 跳转响应 |
| `GetDelete` | GET | `/admin/gift/delete` | 跳转响应 |
| `GetReset` | GET | `/admin/gift/reset` | 跳转响应 |

运行说明：将本讲的 `AdminGiftController` 与上讲 `main.go` 的 `/admin` 路由结合，为 `admin.Party("/gift")` 注册控制器并注入 `GiftService` 即可运行。访问 `/admin/gift` 看到空列表，访问 `/admin/gift/edit` 看到新增表单。

代码说明：骨架阶段列表数据为空切片、编辑数据为零值 `ViewGift`，仅用于验证路由与模板渲染是否正常；真正的查询、转换、保存逻辑在后续两讲补全。

技术点总结：

- 后台控制器沿用一个统一骨架：列表 + 编辑 + 保存 + 删除/恢复。
- 查询类动作返回 `mvc.View`，写操作类动作返回 `mvc.Response{Path: ...}` 做重定向。
- `Party` 分组让鉴权与路径前缀自动向下继承，新增模块几乎零成本接入。
