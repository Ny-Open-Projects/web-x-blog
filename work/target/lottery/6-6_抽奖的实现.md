# Go 企业级抽奖项目: 抽奖的实现

## 纲要

- 抽奖环节核心是"随机编码 + 区间匹配"：生成 0~9999 的随机数作为抽奖编码，落到某个奖品的中奖区间即中奖。
- 抽奖编码范围用 10000 表示最高精度"万分之一"；普通活动精确到百分之一已足够。
- 奖品有顺序，必须避免编码区间出现"包含关系"（如前一个 `0-5000` 会拦截后一个 `1000-5000`）。
- 返回给用户的中奖信息用独立的 `ObjGiftPrize` 结构（json 标签），屏蔽库存等敏感字段。
- 有效奖品列表 `GetAllUse`：DAO 层过滤"有数量限制 / 状态正常 / 在时间窗内"，按 `gtype DESC, displayorder ASC` 排序；Service 层把 `prize_code` 字符串 `"a-b"` 拆成 `PrizeCodeA/B` 整型。
- 匹配方法 `prize`：遍历有效奖品，判断 `PrizeCodeA <= code <= PrizeCodeB`，并结合 `limitBlack` 限制实物大奖。

## 抽奖编码与中奖区间

随机生成一个四位数编码 `prizeCode = comm.Random(10000)`，范围 `[0, 9999]`。每个奖品在后台配置一个"中奖编码区间"，如 `0-9999` 表示 100% 中奖，`0-0` 表示万分之一。编码落在区间内即中奖。

为什么用 10000 这个量级？因为可设置的最精确中奖概率是"万分之一"；若觉得不够，可以把范围改成十万或百万。大部分活动能精确到百分之一就够用了。

> 注意：奖品是有序的，且**必须避免区间包含关系**。例如奖品 A 区间 `0-5000`、奖品 B 区间 `1000-5000`，B 会被 A 完全拦截，导致 B 几乎无法被匹配到。后台配置顺序与区间时要规避这种重叠。

## 有效奖品列表：GetAllUse

匹配前需拿到"当前可参与抽奖"的奖品集合。DAO 层 `GiftDao.GetAllUse` 用 XORM 做过滤与排序（`dao/gift_dao.go`）：

```go
// 获取到当前可以获取的奖品列表
// 有奖品限定(prize_num>=0)，状态正常(sys_status=0)，时间期间内
// gtype倒序，displayorder正序
func (d *GiftDao) GetAllUse() []models.LtGift {
	now := comm.NowUnix()
	datalist := make([]models.LtGift, 0)
	err := d.engine.
		Cols("id", "title", "prize_num", "left_num", "prize_code",
			"prize_time", "img", "displayorder", "gtype", "gdata").
		Desc("gtype").
		Asc("displayorder").
		Where("prize_num>=?", 0).
		Where("sys_status=?", 0).
		Where("time_begin<=?", now).
		Where("time_end>=?", now).
		Find(&datalist)
	if err != nil {
		log.Println("gift_dao.GetAllUse error=", err)
	}
	return datalist
}
```

Service 层 `GiftService.GetAllUse` 把 `lt_gift.prize_code`（形如 `"1000-5000"`）拆成两个整数，构造出对外的 `ObjGiftPrize`（`services/gift_service.go`）：

```go
func (s *giftService) GetAllUse(useCache bool) []models.ObjGiftPrize {
	list := make([]models.LtGift, 0)
	list = s.dao.GetAllUse() // 简化：不走缓存时直接读库
	if list != nil {
		gifts := make([]models.ObjGiftPrize, 0)
		for _, gift := range list {
			codes := strings.Split(gift.PrizeCode, "-")
			if len(codes) == 2 {
				a, e1 := strconv.Atoi(codes[0])
				b, e2 := strconv.Atoi(codes[1])
				// 校验区间合法性：b>=a>=0 且 b<10000
				if e1 == nil && e2 == nil && b >= a && a >= 0 && b < 10000 {
					gifts = append(gifts, models.ObjGiftPrize{
						Id:           gift.Id,
						Title:        gift.Title,
						PrizeNum:     gift.PrizeNum,
						LeftNum:      gift.LeftNum,
						PrizeCodeA:   a,
						PrizeCodeB:   b,
						Img:          gift.Img,
						Displayorder: gift.Displayorder,
						Gtype:        gift.Gtype,
						Gdata:        gift.Gdata,
					})
				}
			}
		}
		return gifts
	}
	return []models.ObjGiftPrize{}
}
```

`ObjGiftPrize` 是单独定义的返回对象（`models/obj_gift_prize.go`），用 json 标签、屏蔽库存等不可见字段，专门用于序列化返回给前端：

```go
type ObjGiftPrize struct {
	Id           int    `json:"id"`
	Title        string `json:"title"`
	PrizeNum     int    `json:"-"`
	LeftNum      int    `json:"-"`
	PrizeCodeA   int    `json:"-"`
	PrizeCodeB   int    `json:"-"`
	Img          string `json:"img"`
	Displayorder int    `json:"displayorder"`
	Gtype        int    `json:"gtype"`
	Gdata        string `json:"gdata"`
}
```

## 匹配方法 prize

拿到有效奖品列表后，遍历并用区间比较。`limitBlack` 为 `true` 时，仅允许匹配 `Gtype < GtypeGiftSmall` 的非实物大奖（`web/controllers/index_lucky_9prize.go`）：

```go
func (api *LuckyApi) prize(prizeCode int, limitBlack bool) *models.ObjGiftPrize {
	var prizeGift *models.ObjGiftPrize
	giftList := services.NewGiftService().GetAllUse(true)
	for _, gift := range giftList {
		if gift.PrizeCodeA <= prizeCode &&
			gift.PrizeCodeB >= prizeCode {
			// 中奖编码区间满足条件，说明可以中奖
			if !limitBlack || gift.Gtype < conf.GtypeGiftSmall {
				prizeGift = &gift
				break
			}
		}
	}
	return prizeGift
}
```

## 主流程中的收口判断

`luckyDo` 在拿到 `prizeGift` 后，还要排除"无奖品 / 限量但库存不足"的情况：

```go
prizeGift := api.prize(prizeCode, limitBlack)
if prizeGift == nil ||
	prizeGift.PrizeNum < 0 ||
	(prizeGift.PrizeNum > 0 && prizeGift.LeftNum <= 0) {
	return 205, "很遗憾，没有中奖，请下次再试", nil
}
```
