# Go 企业级抽奖项目: 优惠券全量缓存实现（上）

## 纲要

- 在 `web/utils/prizedata.go` 中落地优惠券缓存的四个方法：`ImportCacheCodes`、`RecacheCodes`、`GetCacheCodeNum`、`prizeServCodeDiff`。
- 缓存结构：每个奖品的券编码存于 Redis Set，key 形如 `gift_code_{id}`。
- 关键技巧：`RecacheCodes` 先写入临时 key `tmp_gift_code_{id}`，再用 `RENAME` 原子覆盖正式 key，避免脏数据残留。
- 发奖升级：新增 `prizeServCodeDiff` 用 `SPOP` 从缓存弹券，替代原 MySQL 取券逻辑。

## 文本修正与整合

这一节把上一节规划的方法全部落地。我们逐个来看实现要点。

**导入单个券 `ImportCacheCodes`**：最简单，直接 `SADD gift_code_{id} code`，返回是否成功。运营在后台导入一批编码时，每成功写入数据库一条，就同时写入缓存一条。

**重建缓存 `RecacheCodes`**：先用 `codeService.Search(id)` 取出该奖品全部券，过滤出状态正常的（`SysStatus == 0`），逐个 `SADD` 到临时 key `tmp_gift_code_{id}`，统计成功/失败数；全部导完后用 `RENAME tmp_gift_code_{id} gift_code_{id}` 覆盖正式 key。这样即便数据库里手动删除了某些编码，重建后的缓存也不会残留它们。

**统计 `GetCacheCodeNum`**：分别统计数据库有效编码数（`codeService.Search` 后过滤 `SysStatus == 0`）与缓存剩余数（`SCARD gift_code_{id}`），都返回给后台展示，便于人工核对两者是否一致。

**发券 `prizeServCodeDiff`**：用 `SPOP gift_code_{id}` 弹出一个编码，若拿到非空编码，就把数据库里该编码状态更新为"已发放"（`SysStatus = 2`），再返回编码。这一步替代了原来"查数据库找可用券、再更新"的实现。

## 项目代码实现

以下代码来自项目 `web/utils/prizedata.go`（已精简注释、统一风格）：

```go
package utils

import (
	"fmt"
	"log"

	"imooc.com/lottery/comm"
	"imooc.com/lottery/datasource"
	"imooc.com/lottery/models"
	"imooc.com/lottery/services"
)

// 导入新的优惠券编码到缓存
func ImportCacheCodes(id int, code string) bool {
	key := fmt.Sprintf("gift_code_%d", id)
	cacheObj := datasource.InstanceCache()
	_, err := cacheObj.Do("SADD", key, code)
	if err != nil {
		log.Println("prizedata.ImportCacheCodes SADD error=", err)
		return false
	}
	return true
}

// 重新整理（重建）优惠券编码缓存，返回成功数、失败数
func RecacheCodes(id int, codeService services.CodeService) (sucNum, errNum int) {
	list := codeService.Search(id)
	if list == nil || len(list) <= 0 {
		return 0, 0
	}
	key := fmt.Sprintf("gift_code_%d", id)
	tmpKey := "tmp_" + key
	cacheObj := datasource.InstanceCache()
	for _, data := range list {
		if data.SysStatus == 0 { // 只导入正常状态的编码
			_, err := cacheObj.Do("SADD", tmpKey, data.Code)
			if err != nil {
				log.Println("prizedata.RecacheCodes SADD error=", err)
				errNum++
			} else {
				sucNum++
			}
		}
	}
	// 用临时 key 原子覆盖正式 key
	_, err := cacheObj.Do("RENAME", tmpKey, key)
	if err != nil {
		log.Println("prizedata.RecacheCodes RENAME error=", err)
	}
	return sucNum, errNum
}

// 获取缓存中编码数量：返回（数据库有效数, 缓存剩余数）
func GetCacheCodeNum(id int, codeService services.CodeService) (int, int) {
	num := 0
	cacheNum := 0
	list := codeService.Search(id)
	if len(list) > 0 {
		for _, data := range list {
			if data.SysStatus == 0 {
				num++
			}
		}
	}
	key := fmt.Sprintf("gift_code_%d", id)
	cacheObj := datasource.InstanceCache()
	rs, err := cacheObj.Do("SCARD", key)
	if err != nil {
		log.Println("prizedata.GetCacheCodeNum SCARD error=", err)
	} else {
		cacheNum = int(comm.GetInt64(rs, 0))
	}
	return num, cacheNum
}

// 优惠券发放：从 Redis 缓存弹出一个编码并发放
func prizeServCodeDiff(id int, codeService services.CodeService) string {
	key := fmt.Sprintf("gift_code_%d", id)
	cacheObj := datasource.InstanceCache()
	rs, err := cacheObj.Do("SPOP", key)
	if err != nil {
		log.Println("prizedata.prizeServCodeDiff error=", err)
		return ""
	}
	code := comm.GetString(rs, "")
	if code == "" {
		log.Printf("prizedata.prizeServCodeDiff rs=%s", rs)
		return ""
	}
	// 更新数据库中该编码为已发放
	codeService.UpdateByCode(&models.LtCode{
		Code:       code,
		SysStatus:  2,
		SysUpdated: comm.NowUnix(),
	}, nil)
	return code
}
```

## API 速览

| Redis 命令 | 作用 | 本项目封装 |
| --- | --- | --- |
| `SADD gift_code_{id} code` | 导入一个券编码 | `ImportCacheCodes(id, code)` |
| `SADD tmp_key code` + `RENAME tmp_key gift_code_{id}` | 重建缓存并原子覆盖 | `RecacheCodes(id, svc)` |
| `SCARD gift_code_{id}` | 统计缓存剩余编码数 | `GetCacheCodeNum(id, svc)` |
| `SPOP gift_code_{id}` | 弹出一个编码用于发奖 | `prizeServCodeDiff(id, svc)` |

## Demo 示例

运行说明：本地启动 Redis，安装 `github.com/gomodule/redigo/redis`，`go run main.go`。

代码说明：模拟"导入 3 个券 → 统计 → 发奖弹出 1 个 → 再统计"的过程。

```go
package main

import (
	"fmt"
	"log"

	"github.com/gomodule/redigo/redis"
)

func main() {
	conn, err := redis.Dial("tcp", "127.0.0.1:6379")
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()

	id := 20
	key := fmt.Sprintf("gift_code_%d", id)

	// 导入 3 个券
	for _, c := range []string{"CODE-A", "CODE-B", "CODE-C"} {
		conn.Do("SADD", key, c)
	}
	fmt.Println("已导入 3 个券编码")

	// 统计缓存数量
	n, _ := redis.Int(conn.Do("SCARD", key))
	fmt.Printf("缓存剩余券数: %d\n", n)

	// 发奖弹出一个
	code, _ := redis.String(conn.Do("SPOP", key))
	fmt.Printf("本次发奖编码: %s\n", code)

	// 再次统计
	n, _ = redis.Int(conn.Do("SCARD", key))
	fmt.Printf("发奖后缓存剩余券数: %d\n", n)

	// 重建缓存演示：先写临时 key，再 RENAME 覆盖
	tmpKey := "tmp_" + key
	conn.Do("DEL", tmpKey)
	conn.Do("SADD", tmpKey, "CODE-X", "CODE-Y")
	conn.Do("RENAME", tmpKey, key)
	n, _ = redis.Int(conn.Do("SCARD", key))
	fmt.Printf("重建后缓存剩余券数: %d\n", n)
}
```

技术点总结：

- Set 结构天然去重、无序，完美匹配"唯一券编码"的存储与弹出场景。
- `RENAME` 是原子操作，用它覆盖正式 key 可避免"部分更新"期间读到脏数据。
- 发奖用 `SPOP` 直接出队，天然避免并发重复发同一个编码；拿到编码后立即更新数据库状态，保证最终一致。
- `GetCacheCodeNum` 把"数据库数 vs 缓存数"同时暴露给后台，是发现不一致的第一道人工防线。
