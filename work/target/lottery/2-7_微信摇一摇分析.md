# Go 企业级抽奖项目: 微信摇一摇需求分析

## 纲要

- 摇一摇分三种内容类型：人、歌曲、电视，每次随机返回其中之一
- 奖品/内容种类多、数量大，且包含广告
- 奖品分虚拟币、虚拟券、实物小奖/大奖，发奖规则各异
- 海量用户并发摇奖时，更新库存必须处理并发安全（超发风险）

## 业务特点

第三种抽奖活动是微信摇一摇。与年会抽奖（抽人）、彩票（随机匹配）不同，摇一摇引入了**多种类型、有数量限制的奖品**，技术实现上更复杂：

- **内容类型**：分为人、歌曲、电视三种，每次摇一摇随机返回一条内容。
- **奖品多样**：奖品既可以是虚拟币、虚拟券，也可以是实物小奖（如小礼品）、实物大奖（如手机），甚至包含广告。种类多、数量大。

## 工程难点

摇一摇的关键不在"随机返回"，而在"中奖之后"：

1. **随机匹配奖品**：需要根据配置的概率，从奖品池中匹配出用户本次摇到的奖品。
2. **差异化发奖**：虚拟币、固定券、动态券、实物各自的发放规则不同（例如动态券每个用户拿到的编码不同）。
3. **库存扣减与记录**：很多奖品有数量上限，中奖后必须扣减库存、生成记录并提示用户。
4. **并发安全**：海量用户同时摇奖，对库存数量的并发更新若不加以保护，就会出现"超发"——明明只有 2 部手机，却发出去 3 部甚至更多。这是摇一摇区别于彩票类玩法的核心风险点。
