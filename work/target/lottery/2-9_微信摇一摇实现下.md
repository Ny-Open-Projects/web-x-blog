# Go 企业级抽奖项目: 微信摇一摇服务端实现（下）

## 纲要

- `/lucky` 接口返回 `map`，含 `success` 与中奖信息
- 抽奖阶段与发奖阶段分离：抽中未必能发出（库存不足）
- 按奖品类型分别实现发奖：虚拟币、固定券、动态券、实物
- 中奖后记录日志（`saveLuckyData`），真实项目应落库

## 抽奖主流程

`GetLucky`（对应 `GET /lucky`）是摇一摇的核心接口，返回 `map[string]interface{}`：

1. 为本次请求生成随机码 `code`（`[0, 10000)` 的整数）。
2. 遍历 `giftList`，跳过未启用或已无库存的奖品。
3. 若 `code` 落在某奖品的 `[RateMin, RateMax)` 区间内，即视为中奖，调用对应发奖函数。
4. 发奖成功则回填 `gift_id`、`gift_name`、`send_data` 等信息并记录；发奖失败（如库存真的耗尽）则该次不中奖。

注意：**抽奖阶段**只负责"命中奖品"，**发奖阶段**才真正扣库存并发放。两步分离意味着"抽中了"和"发出去"不是一回事——这正是高并发下超发风险的根源，也是后续要加锁保护的点。

## 差异化发奖

不同奖品类型的发放规则各异，但结构高度相似，都遵循"不限量直接发 / 有限量则先判断剩余再扣减"的范式：

- **虚拟币 `sendCoin`**：不限量直接返回 `Data`；有限量则 `Left--` 后返回。
- **固定券 `sendCouponFix`**：所有用户拿到同一编码，逻辑同虚拟币。
- **动态券 `sendCouponDiff`**：从 `DataList` 中按剩余数取下一张编码，需校验切片长度。
- **实物 `sendReal`**：判断总数与剩余数后扣减。

```go
// GET /lucky 抽奖接口
func (c *lotteryController) GetLucky() map[string]interface{} {
	code := luckyCode()
	result := map[string]interface{}{"success": true, "message": "ok"}
	mu.Lock()
	defer mu.Unlock()
	for i := range giftList {
		g := &giftList[i]
		if !g.Useful || (g.Total > 0 && g.Left <= 0) {
			continue
		}
		if code >= g.RateMin && code < g.RateMax {
			ok, sendData := sendGift(g)
			if ok {
				result["gift_id"] = g.Id
				result["gift_name"] = g.Name
				result["send_data"] = sendData
				saveLuckyData(code, g, sendData)
			}
			break
		}
	}
	return result
}

func luckyCode() int32 {
	seed := time.Now().UnixNano()
	return rand.New(rand.NewSource(seed)).Int31n(10000)
}

// 按奖品类型分发发奖逻辑
func sendGift(g *Gift) (bool, string) {
	switch g.Type {
	case giftTypeCoin:
		return sendCoin(g)
	case giftTypeCouponFix:
		return sendCouponFix(g)
	case giftTypeCouponDiff:
		return sendCouponDiff(g)
	default:
		return sendReal(g)
	}
}

func sendCoin(g *Gift) (bool, string) {
	if g.Total == 0 {
		return true, g.Data
	}
	if g.Left > 0 {
		g.Left--
		return true, g.Data
	}
	return false, "奖品已发完"
}

func sendCouponFix(g *Gift) (bool, string) {
	if g.Total == 0 {
		return true, g.Data
	}
	if g.Left > 0 {
		g.Left--
		return true, g.Data
	}
	return false, "奖品已发完"
}

func sendCouponDiff(g *Gift) (bool, string) {
	// 关键校验：剩余数不能超过切片长度，否则取下一张编码会越界
	if g.Left > 0 && len(g.DataList) >= g.Left {
		g.Left--
		return true, g.DataList[g.Left]
	}
	return false, "奖品已发完"
}

func sendReal(g *Gift) (bool, string) {
	if g.Total == 0 {
		return true, g.Name
	}
	if g.Left > 0 {
		g.Left--
		return true, g.Name
	}
	return false, "奖品已发完"
}

// 演示中以日志代替落库；真实项目应写入数据库
func saveLuckyData(code int32, g *Gift, sendData string) {
	fmt.Printf("中奖: code=%d, giftId=%d, name=%s, data=%s, left=%d\n",
		code, g.Id, g.Name, sendData, g.Left)
}
```

技术点总结：

- 抽奖码落在累计区间内即命中，`break` 保证一次只中一个奖品。
- 发奖函数统一返回 `(bool, string)`，便于上层区分"抽中但发不出"的情况。
- `sendCouponDiff` 取券前必须校验 `len(g.DataList) >= g.Left`，否则会发生数组越界（下一节详述该 Bug）。
- 本示例用全局互斥锁 `mu` 保护 `giftList` 的库存扣减，避免并发超发；真实项目可结合 Redis 等做更细粒度控制。
