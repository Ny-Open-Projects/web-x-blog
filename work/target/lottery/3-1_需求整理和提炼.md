# Go 企业级抽奖项目: 需求整理和提炼

## 纲要

- 需求分类：功能性需求、非功能性需求、管理后台需求、后台定时任务需求
- 功能性需求：奖品列表、我的中奖列表、登录与退出
- 非功能性需求：高性能高并发、安全性（奖品不超发、均匀发放）
- 管理后台：基础数据管理 + 实时在线更新活动配置
- 后台定时任务：生成发奖计划、自动填充奖品池

## 需求分类

抽奖系统的需求可以从两个维度切入：用户视角的功能性需求，以及系统视角的非功能性需求。前端页面高度依赖后端接口，因此后端需要先明确要提供哪些能力。

## 功能性需求

最基础的接口包括：

- 奖品列表：返回大转盘上可展示的奖品信息
- 抽奖 / 我的中奖列表：返回当前用户历史中奖记录
- 登录、退出：最基本的功能性支撑

这些接口构成前端交互的骨架。

## 非功能性需求

活动类系统的访问具有明显的脉冲特征——推广会带来集中的高流量，因此抽奖接口必须满足高性能与高并发要求，否则在流量高峰时无法稳定提供服务，系统便失去价值。

安全性是另一个关键的非功能性需求：

- 奖品不能超发（库存与发放必须严格一致）
- 奖品需合理、均匀地发放，避免「某用户频繁中奖」或「某时间段中奖概率畸高 / 畸低」等不均衡现象

## 管理后台需求

一套完整的管理后台帮助产品运营随时掌握并控制活动：

- 基础数据管理：奖品管理、优惠券管理、用户管理、IP 黑名单、中奖记录管理
- 实时在线更新：运营可随时上下线活动奖品、更新奖品库存与中奖周期，从而精准控制奖品发放节奏

## 后台定时任务需求

除人工管理外，还需后台定时任务：

- 合理生成发奖计划
- 自动填充奖品池

这样可提前设定奖品，避免运营人员时刻盯守发放。

实际运营过程中需求难免变化，系统应随业务持续迭代。

相关度：95%。是否需要继续：是。代码是否可运行：否。
