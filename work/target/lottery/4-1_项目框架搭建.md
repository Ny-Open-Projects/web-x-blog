# Go 企业级抽奖项目: 项目框架搭建

## 纲要

- 抽奖系统的代码目录规划，按职责拆分公共模块、配置、数据访问、Web 站点等
- 核心目录：`bootstrap`、`common`、`conf`、`dao`、`datasource`、`cronjob`、`web`、`thrift`、`models`、`viewmodels`
- Web 站点目录进一步细分：`controllers`、`public`、`middleware`、`views`（后台模板与公共模板）
- 启动入口 `main.go` 放在 `web` 目录之下
- 数据模型通过 XORM 工具根据已设计的数据表自动生成，拷贝进 `models` 目录

## 目录结构设计

进入系统实现阶段，第一步是把抽奖项目的整体框架与核心代码落地。框架本身决定了后续所有代码如何组织、如何维护，因此先规划好目录结构至关重要。整个项目约定如下目录：

```dir
lottery/
├── bootstrap/        # 启动环节：配置初始化、数据源初始化、日志、模板、权限、路由注册、计划任务启动
├── common/           # 公共函数：与业务无关的通用工具（如时间、字符串、加密等）
├── conf/             # 配置：项目配置、数据库配置、Redis 配置
├── dao/              # 数据库操作类（Data Access Object）
├── datasource/       # 数据源：XORM 引擎、Redis 连接的单例创建
├── cronjob/          # 计划任务（定时任务）服务
├── thrift/           # RPC 定义文件（IDL）及生成代码，后续引入 Thrift 框架时使用
├── models/           # 数据模型，由 XORM 依据数据表自动生成
├── viewmodels/       # 视图模型，模板渲染时使用的数据结构
├── web/              # Web 站点
│   ├── controllers/  # 控制器（Controller），业务逻辑处理
│   ├── public/       # 对外网暴露的静态文件
│   ├── middleware/   # 中间件，例如后台身份认证的 auth
│   ├── views/        # 模板文件，细分 admin（后台）与 shared（公共）模板
│   └── main.go       # 站点启动入口
└── main application  # 可独立运行的 Application 入口
```

这些目录的划分可复用到任何 Go Web 项目：凡是数据相关的放 `dao`/`datasource`/`models`，配置相关的放 `conf`，公共工具放 `common`，站点相关的放 `web`。

## 各目录职责说明

`bootstrap` 负责把应用启动要做的杂活统一收口：项目配置初始化、数据源（数据库与缓存）初始化、日志与模板加载、权限处理、路由注册，以及 `cronjob` 中计划任务的拉起。把这些放到启动阶段，业务代码就能直接注入已经就绪的依赖。

`common` 提供与具体业务耦合度很低的公共函数，例如字符串处理、时间转换、加密校验等。它们在本系统可用，在其他系统同样可直接复用。

`conf` 保存项目的配置信息。本轮先建数据库与 Redis 两类配置（详见 `4-6 定义数据库和redis配置信息`）。

`dao` 是面向数据库的操作类，使用 XORM 引擎完成增删改查；其数据源来自 `datasource`。

`web` 是站点的核心：控制器写在 `controllers`，对外静态资源放 `public`，路由与中间件（如后台身份认证的 `auth`）在 `web` 内组织，模板文件放 `views`。其中 `views` 再细分为后台模板与公共模板。站点主程序 `main.go` 也放在 `web` 目录下。

`models` 与 `viewmodels`：`models` 由讲稿中已设计好的五六张数据表经 XORM 自动生成；`viewmodels` 用于在模板渲染时做一层数据转换，直接基于模型做转换会更简洁高效。
