# Go 企业级抽奖项目: 用户IP黑名单的处理

## 纲要

- 黑名单限制的意义：被拉黑的用户 / IP 不允许获取实物大奖，主要为了安全与公平。
- 安全：避免同一 IP 批量注册用户来"刷奖"。
- 公平：已中过大奖的用户运气已用尽，一段时间内让出机会给其他用户。
- 判定方式：查询 `lt_blackip` / 用户表里的黑名单数据，判断是否存在且 `Blacktime` 仍在有效期内。
- IP 维度还有一个"软规则"：今日参与次数超过 `conf.IpPrizeMax` 即视为疑似黑名单（`limitBlack`）。
- 实现入口：`api.checkBlackip(ip)` 与 `api.checkBlackUser(uid)`，均返回 `(bool, *模型)`。

## 为什么还要黑名单

系统已经有了中奖概率限制，又有发奖环节的库存保证，为什么还要黑名单？两个考虑：

1. **安全性**：避免同一 IP 下大量用户批量刷奖。若有人批量注册活动用户，就能利用这批号来刷实物奖品，IP 黑名单针对性地抬高了这种刷奖难度。
2. **公平性**：中过实物大奖的用户运气已经太好，系统让其"关一段小黑屋"，把机会让给其他人。

验证方法本质上就是：判断黑名单数据表中该用户 / IP 的记录是否存在，并且还在限制时间（`Blacktime`）内。

## IP 黑名单校验

`checkBlackip` 通过 `BlackipService.GetByIp(ip)` 查 `lt_blackip` 表（DAO 用 `ip` 条件 + `DESC id` + `LIMIT 1`）。记录不存在，或 `Blacktime` 已过期，都算校验通过（`web/controllers/index_lucky_4check_blackip.go`，与讲稿逻辑一致）：

```go
// 验证当前用户的IP是否存在黑名单限制
func (c *IndexController) checkBlackip(ip string) (bool, *models.LtBlackip) {
	info := c.ServiceBlackip.GetByIp(ip)
	if info == nil || info.Ip == "" {
		return true, nil
	}
	if info.Blacktime > int(time.Now().Unix()) {
		// IP黑名单存在，而且没有过期
		return false, info
	}
	return true, info
}
```

`lt_blackip` 表结构（`models/lt_blackip.go`）：

```go
type LtBlackip struct {
	Id         int    `xorm:"not null pk autoincr INT(10)"`
	Ip         string `xorm:"not null default '' comment('IP地址') VARCHAR(50)"`
	Blacktime  int    `xorm:"not null default 0 comment('黑名单限制到期时间') INT(10)"`
	SysCreated int    `xorm:"not null default 0 comment('创建时间') INT(10)"`
	SysUpdated int    `xorm:"not null default 0 comment('修改时间') INT(10)"`
}
```

## 用户黑名单校验

用户黑名单记录在 `lt_user` 表的 `Blacktime` 字段上。逻辑与 IP 几乎一致：查到且未过期则校验失败（`web/controllers/index_lucky_5check_blackuser.go`）：

```go
func (api *LuckyApi) checkBlackUser(uid int) (bool, *models.LtUser) {
	info := services.NewUserService().Get(uid)
	if info != nil && info.Blacktime > int(time.Now().Unix()) {
		// 黑名单存在并且有效
		return false, info
	}
	return true, info
}
```

## limitBlack：IP 次数联动的软黑名单

在 `luckyDo` 中，`limitBlack` 是一个贯穿后续匹配环节的开关。它由 IP 今日次数直接联动：

```go
limitBlack := false
if ipDayNum > conf.IpPrizeMax {
	// 今日 IP 参与次数超过软阈值，视为疑似黑名单
	limitBlack = true
}
// 验证IP黑名单
if !limitBlack {
	ok, blackipInfo = api.checkBlackip(ip)
	if !ok {
		fmt.Println("黑名单中的IP", ip, limitBlack)
		limitBlack = true
	}
}
// 验证用户黑名单
if !limitBlack {
	ok, userInfo = api.checkBlackUser(uid)
	if !ok {
		limitBlack = true
	}
}
```

也就是说，黑名单有两条来源：

1. IP 今日次数 `> IpPrizeMax`（软阈值）直接置位。
2. 查表发现 IP / 用户处于有效黑名单期。

置位后，`limitBlack=true` 会在 6-6 的 `prize` 匹配中限制该用户只能中"非实物大奖"（即 `Gtype < GtypeGiftSmall`）。

## API 速览

| 方法 / 常量 | 包 | 说明 |
| --- | --- | --- |
| `checkBlackip(ip string) (bool, *LtBlackip)` | `web/controllers` | 查 `lt_blackip`，存在且未过期则 `false` |
| `checkBlackUser(uid int) (bool, *LtUser)` | `web/controllers` | 查用户表 `Blacktime`，有效则 `false` |
| `BlackipService.GetByIp(ip)` | `services` | DAO 层按 IP 取最新一条黑名单 |
| `conf.IpPrizeMax` | `conf` | IP 每日软阈值（默认 30000），超则疑似黑名单 |
