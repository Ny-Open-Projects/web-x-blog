# Go 企业级抽奖项目: 实现发奖计划（上）

## 纲要

- 在 `web/utils/prizedata.go` 中封装 `ResetGiftPrizeData`，用于根据奖品总数与发奖周期重新计算发奖计划。
- 入参为 `*models.LtGift` 与 `services.GiftService`，无返回值。
- 先对参数与状态做校验：状态异常、时间区间不对、剩余数或总数不足时清空旧计划并退出。
- 未设置发奖周期（`PrizeTime<=0`）时，直接把全部剩余数量写入奖品池，不做计划控制。
- 重算前先把奖品池清空，再按「每天平均值 + 剩余随机分配」算出每天数量。
- 用三层结构 `map[int]map[int][60]int` 暂存「天/小时/分钟」的奖品数，最终格式化为 `[][2]int` 并序列化进数据库。

## ResetGiftPrizeData 的整体结构

项目源码（`web/utils/prizedata.go`）：

```go
// 重置一个奖品的发奖周期信息
// 奖品剩余数量也会重新设置为当前奖品数量
// 奖品的奖品池有效数量则会设置为空
// 奖品数量、发放周期等设置有修改的时候，也需要重置
func ResetGiftPrizeData(giftInfo *models.LtGift, giftService services.GiftService) {
	if giftInfo == nil || giftInfo.Id < 1 {
		return
	}
	id := giftInfo.Id
	nowTime := comm.NowUnix()
	// 不能发奖，不需要设置发奖周期
	if giftInfo.SysStatus == 1 || // 状态不对
		giftInfo.TimeBegin >= nowTime || // 开始时间不对
		giftInfo.TimeEnd <= nowTime || // 结束时间不对
		giftInfo.LeftNum <= 0 || // 剩余数不足
		giftInfo.PrizeNum <= 0 { // 总数不限制
		if giftInfo.PrizeData != "" {
			clearGiftPrizeData(giftInfo, giftService)
		}
		return
	}
	// 不限制发奖周期，直接把奖品数量全部设置上
	dayNum := giftInfo.PrizeTime
	if dayNum <= 0 {
		setGiftPool(id, giftInfo.LeftNum)
		return
	}

	// 重新计算出来合适的奖品发放节奏
	// 奖品池的剩余数先设置为空
	setGiftPool(id, 0)
	// ... 后续计算见下文
}
```

## 参数与状态校验

校验分两层：

1. 最基本的防御：`giftInfo == nil` 或 `Id < 1` 直接返回。
2. 业务校验：如果奖品处于删除状态（`SysStatus==1`）、活动未开始或已结束、剩余数量 `LeftNum<=0`、或者总数量 `PrizeNum<=0`（不限量/无奖品），这种情况下都不应该发奖。若原奖品表里的 `PrizeData` 不为空，先调用 `clearGiftPrizeData` 把旧发奖计划清空，然后 `return`。

## 未设置周期的快捷通道

如果 `PrizeTime <= 0`，说明运营没有给这个奖品设置发奖周期，那么所有剩余数量一次性放入奖品池即可，不需要发奖计划来控制节奏：

```go
dayNum := giftInfo.PrizeTime
if dayNum <= 0 {
	setGiftPool(id, giftInfo.LeftNum)
	return
}
```

## 重算前先清空奖品池

进入正式计算前，先把当前奖品的奖品池库存设为 0（`setGiftPool(id, 0)`）。因为上一期的计划可能已经往池子里放过一些库存，现在要开启一个全新的发奖周期，必须先把旧库存清零，等新的计划算完之后，再由填充服务重新往池子里放。

## 按天分配：平均值 + 剩余随机

核心算法是先算「每天平均发多少」，再把除不尽的余数随机撒到任意一天：

```go
prizeNum := giftInfo.PrizeNum
avgNum := prizeNum / dayNum

// 每天可以分配到的奖品数量
dayPrizeNum := make(map[int]int)
// 平均分配，每天分到的奖品数量做分布
if avgNum >= 1 && dayNum > 0 {
	for day := 0; day < dayNum; day++ {
		dayPrizeNum[day] = avgNum
	}
}
// 剩下的随机分配到任意哪天
prizeNum -= dayNum * avgNum
for prizeNum > 0 {
	prizeNum--
	day := comm.Random(dayNum)
	_, ok := dayPrizeNum[day]
	if !ok {
		dayPrizeNum[day] = 1
	} else {
		dayPrizeNum[day] += 1
	}
}
```

注意：只有当 `avgNum >= 1`（平均一天至少能摊到一个）时才做基础平均分配；否则整批奖品都走下面的随机分配。`comm.Random(dayNum)` 返回一个 `[0, dayNum)` 区间内的随机整数，把余数逐一把「某一天 +1」。

## 临时数据结构与最终格式化

算完每天数量后，进入「每天 → 每小时 → 每分钟」的三层结构：

```go
// 每天的map，每小时的map，60分钟的数组，奖品数量
prizeData := make(map[int]map[int][60]int)
for day, num := range dayPrizeNum {
	dayPrizeData := getGiftPrizeDataOneDay(num)
	prizeData[day] = dayPrizeData
}
// 将周期内每天、每小时、每分钟的数据 prizeData 格式化，再序列化保存到数据表
datalist := formatGiftPrizeData(nowTime, dayNum, prizeData)
str, err := json.Marshal(datalist)
```

这个三层结构（`map[int]map[int][60]int`）在 Go 里操作起来略繁琐（读 map 要先判断 key 是否存在），而且直接存库后做增量更新会很复杂。所以最终会用 `formatGiftPrizeData` 把它「拍平」成一个更简单的结构：`[][2]int`，即 `[时间, 数量]` 的有序数组。

## 序列化并写回数据库

拍平、序列化后，更新到奖品表：

```go
info := &models.LtGift{
	Id:         giftInfo.Id,
	LeftNum:    giftInfo.PrizeNum, // 剩余数量重置为总数
	PrizeData:  string(str),       // 发奖计划
	PrizeBegin: nowTime,           // 本周期开始 = 当前时间
	PrizeEnd:   nowTime + dayNum*86400, // 本周期结束
	SysUpdated: nowTime,
}
err := giftService.Update(info, nil)
```

这里有两个关键写入：

- `LeftNum` 重置为 `PrizeNum`：每次重算都把剩余数归位到总数。
- `PrizeBegin` / `PrizeEnd`：记录本发奖周期的时间边界，后续填充服务到期了就能据此自动开启新周期。
