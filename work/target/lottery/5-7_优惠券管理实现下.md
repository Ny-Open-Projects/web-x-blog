# Go 企业级抽奖项目: 优惠券管理实现（下）

## 纲要

- 导入动作 `PostImport()`：以 POST 提交大文本（可含上万条券码），按行拆分后逐条入库。
- 前置校验：必须指定 `giftId`，且对应奖品类型为「差异化虚拟券」（gtype=2），否则返回错误。
- 文本处理：按换行符 `Split`，逐条 `TrimSpace` 过滤空行与首尾空白，再构造 `LtCode` 入库。
- 结果统计：分别计数导入成功数与失败数，最终回写成功提示与 `giftId` 以便返回原页。
- 预留 TODO：导入完成后需同步写入 Redis 缓存（见第7章），本讲仅落库。

## 导入动作 PostImport

```go
package controllers

import (
    "strings"
    "time"

    "github.com/kataras/iris/v12/mvc"

    "lottery/models"
    "lottery/services"
)

// PostImport 批量导入优惠券
func (c *AdminCodeController) PostImport() mvc.Result {
    giftId := c.Ctx.URLParamIntDefault("gift_id", 0)
    if giftId < 1 {
        return mvc.Response{Text: "未指定产品ID，无法进行导入"}
    }

    gift := c.GiftService.Get(giftId)
    if gift == nil || gift.Gtype != 2 {
        return mvc.Response{Text: "商品信息不存在或商品类型不是差异化优惠券，无法进行导入"}
    }

    // 读取待导入的券码大文本
    raw := c.Ctx.PostValue("codes")
    lines := strings.Split(raw, "\n")

    var success, fail int
    now := int(time.Now().Unix())

    for _, line := range lines {
        code := strings.TrimSpace(line)
        if code == "" {
            continue // 过滤空行与纯空白行
        }
        entity := &models.LtCode{
            GiftId:    giftId,
            Code:      code,
            SysStatus: 0,
            SysCreated: now,
            SysUpdated: now,
        }
        if err := c.CodeService.Create(entity); err != nil {
            fail++
        } else {
            success++
        }
    }

    // TODO: 成功入库后同步写入 Redis 缓存（见第7章优化）
    msg := "成功导入 " + itoa(success) + " 条，失败 " + itoa(fail) + " 条"
    return mvc.Response{
        Text: msg,
        // 如有 giftId 可带回到原页面
    }
}

func itoa(v int) string {
    return strconvItoa(v)
}
```

> 说明：`giftId` 既作为查询参数又作为返回参数，使导入后页面能停留在同一奖品上下文。文本拆分后务必做 `TrimSpace` 与空串过滤，避免把换行符、首尾空格当作无效券码写入。

## 删除与恢复（差异点）

优惠券的删除/恢复与奖品管理逻辑一致，但额外读取 `Refer` 头，将用户带回来源页，减少一次跳转：

```go
// GetDelete 删除优惠券
func (c *AdminCodeController) GetDelete() mvc.Result {
    id, _ := c.Ctx.URLParamInt("id")
    if id > 0 {
        c.CodeService.Update(&models.LtCode{Id: id, SysStatus: 1}, "sys_status")
    }
    return c.backToReferer()
}

// GetReset 恢复优惠券
func (c *AdminCodeController) GetReset() mvc.Result {
    id, _ := c.Ctx.URLParamInt("id")
    if id > 0 {
        c.CodeService.Update(&models.LtCode{Id: id, SysStatus: 0}, "sys_status")
    }
    return c.backToReferer()
}

// backToReferer 优先返回来源页，缺失则回列表
func (c *AdminCodeController) backToReferer() mvc.Response {
    ref := c.Ctx.GetReferer()
    if ref == "" {
        ref = "/admin/code"
    }
    return mvc.Response{Path: ref}
}
```

## API 速览

| 方法 | 说明 |
| --- | --- |
| `Ctx.PostValue(key)` | 读取 POST 表单字段（大文本券码） |
| `strings.Split(s, "\n")` | 按换行切分多行券码 |
| `strings.TrimSpace(s)` | 去除首尾空白，过滤脏数据 |
| `Ctx.GetReferer()` | 获取 `Referer` 请求头，用于回跳来源页 |

## Demo 示例

代码说明：导入是「参数校验 → 文本拆分 → 过滤 → 逐条入库 → 统计」的线性流程；类型校验保证优惠券只能挂到差异化虚拟券类奖品下。

技术点总结：

- 批量导入用 POST 承接大文本，按行拆分 + 过滤是通用范式。
- 业务前置校验（归属奖品、类型）应在入库前完成，避免脏数据。
- `Referer` 回跳让后台操作体验更连贯，是列表类操作的常见优化。
