# Go 企业级抽奖项目: 验证用户IP今日参与次数（上）

## 纲要

- 本章分上下两篇，讲"用户 / IP 今日参与次数"的校验。上篇聚焦**用户维度**。
- 每个用户每天的抽奖次数单独计数，达到上限后当天不能再参与，提示"明天再来"。
- 次数计数需要**原子递增**，避免并发下计数不准确。
- 用户今日次数同时落两处：Redis 缓存（快速递增，见 6-4 的 IP 思路同源）与 MySQL 表 `lt_userday`（持久化、可查询）。
- 实现入口：`api.checkUserday(uid, num)` → `UserdayService.GetUserToday` → `UserdayDao.Search`，存在则 `Num++` 后 `Update`，不存在则 `Create`。

## 校验规则

今日参与次数针对"同一用户"独立计数。达到上限（`conf.UserPrizeMax`，工程默认 3000）后，该用户当天不能再抽，返回错误码 `103` 与提示"今日的抽奖次数已用完，明天再来吧"。

并发下要保证计数递增的**原子性**，因此不能在应用内存里先读再加再写，而是借助数据库 / 缓存的原子自增能力。

## 用户今日次数的持久化：lt_userday 表

表结构（`models/lt_userday.go`）：

```go
type LtUserday struct {
	Id         int `xorm:"not null pk autoincr INT(10)"`
	Uid        int `xorm:"not null default 0 comment('用户ID') INT(10)"`
	Day        int `xorm:"not null default 0 comment('日期，如：20180725') INT(10)"`
	Num        int `xorm:"not null default 0 comment('次数') INT(10)"`
	SysCreated int `xorm:"not null default 0 comment('创建时间') INT(10)"`
	SysUpdated int `xorm:"not null default 0 comment('修改时间') INT(10)"`
}
```

DAO 中用联合条件 `uid + day` 查询当天记录（`dao/userday_dao.go`）：

```go
func (d *UserdayDao) Search(uid, day int) []models.LtUserday {
	datalist := make([]models.LtUserday, 0)
	err := d.engine.
		Where("uid=?", uid).
		Where("day=?", day).
		Desc("id").
		Find(&datalist)
	if err != nil {
		return datalist
	}
	return datalist
}
```

Service 层封装"读取今天记录"：

```go
func (s *userdayService) GetUserToday(uid int) *models.LtUserday {
	y, m, d := time.Now().Date()
	strDay := fmt.Sprintf("%d%02d%02d", y, m, d)
	day, _ := strconv.Atoi(strDay)
	list := s.dao.Search(uid, day)
	if list != nil && len(list) > 0 {
		return &list[0]
	}
	return nil
}
```

## 核心校验方法 checkUserday

逻辑非常清晰：今天已有记录就 `Num++` 后更新；没有记录就创建一条 `Num=1` 的新记录（`web/controllers/index_lucky_3check_userday.go`，与讲稿逻辑一致）：

```go
func (api *LuckyApi) checkUserday(uid int, num int64) bool {
	userdayService := services.NewUserdayService()
	userdayInfo := userdayService.GetUserToday(uid)
	if userdayInfo != nil && userdayInfo.Uid == uid {
		// 今天已存在抽奖记录
		if userdayInfo.Num >= conf.UserPrizeMax {
			// 已达上限，必要时把缓存计数同步回数据库值
			if int(num) < userdayInfo.Num {
				utils.InitUserLuckyNum(uid, int64(userdayInfo.Num))
			}
			return false
		}
		userdayInfo.Num++
		if int(num) < userdayInfo.Num {
			utils.InitUserLuckyNum(uid, int64(userdayInfo.Num))
		}
		if err := userdayService.Update(userdayInfo, nil); err != nil {
			log.Println("checkUserday Update err=", err)
		}
	} else {
		// 今天第一次参与，创建记录
		y, m, d := time.Now().Date()
		strDay := fmt.Sprintf("%d%02d%02d", y, m, d)
		day, _ := strconv.Atoi(strDay)
		userdayInfo = &models.LtUserday{
			Uid:        uid,
			Day:        day,
			Num:        1,
			SysCreated: int(time.Now().Unix()),
		}
		if err := userdayService.Create(userdayInfo); err != nil {
			log.Println("checkUserday Create err=", err)
		}
		utils.InitUserLuckyNum(uid, 1)
	}
	return true
}
```

要点：

- `Day` 由 `年(4位) + 月(2位) + 日(2位)` 拼成整型（如 `20180725`），保证两位补零。
- `Update(userdayInfo, nil)` 中 `columns` 传 `nil`，表示更新所有非空字段；XORM 里 `MustCols` 配合可确保 `Num` 被写回。
- `utils.InitUserLuckyNum` 用于把数据库中的准确计数同步到 Redis 缓存，保证缓存与数据库一致（缓存递增方案详见下篇 6-4）。
