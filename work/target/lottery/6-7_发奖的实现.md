# Go 企业级抽奖项目: 发奖的实现

## 纲要

- 不限量奖品无需处理库存；只有**有限量奖品**才需要保证"剩余数量递减"的原子性。
- 库存递减放在数据库层完成：`GiftDao.DecrLeftNum` 用 `Decr("left_num", num)` 并附加 `WHERE left_num >= num`，靠数据库自身锁保证原子、避免超发。
- 配套提供 `IncrLeftNum`（`Incr` + 无条件），用于回补等场景。
- 不同编码的优惠券发放更复杂：需先找到下一个可用编码 → 改状态为"已发放" → 再给中奖信息，全过程用分布式锁保证线程安全。
- 优惠券查找 `CodeDao.NextUsingCode`：按 `gift_id`、`sys_status=0`、`id>上次codeId` 升序取第一条。
- 锁的 key 用"负 UID"（如 `0 - 奖品ID - 常量`）保证不与正常用户锁冲突。

## 有限奖品的库存递减

在基础 MySQL 版本里，"发奖"的本质就是把奖品的剩余库存减去 1，并且必须原子、不能超发。

DAO 层 `GiftDao.DecrLeftNum`（`dao/gift_dao.go`）通过 XORM 的 `Decr` 表达式 + `WHERE left_num >= num` 实现：

```go
// 递减奖品的剩余数量，只有剩余 >= num 时才减，避免减成负数（超发）
func (d *GiftDao) DecrLeftNum(id, num int) (int64, error) {
	r, err := d.engine.Id(id).
		Decr("left_num", num).
		Where("left_num>=?", num).
		Update(&models.LtGift{Id: id})
	return r, err
}

// 配套的递增操作（无需条件，一直往上加）
func (d *GiftDao) IncrLeftNum(id, num int) (int64, error) {
	r, err := d.engine.Id(id).
		Incr("left_num", num).
		Update(&models.LtGift{Id: id})
	return r, err
}
```

说明：

- `Decr("left_num", num)` 等价于 SQL 的 `left_num = left_num - num`，是在数据库内完成的表达式更新。
- `WHERE left_num >= num` 是防超发的关键约束：若剩余不足，更新影响行数为 0，上层据此判定发奖失败。
- 数据库自身的事务 / 行锁保证了该操作的原子性，所以我们"依靠数据库来做库存递减"是安全可靠的。

Service 层只是透传（`services/gift_service.go`）：

```go
func (s *giftService) DecrLeftNum(id, num int) (int64, error) {
	return s.dao.DecrLeftNum(id, num)
}
```

主流程里（`luckyDo`），匹配到有限量奖品后调用：

```go
// 步骤9：有限制奖品发放
if prizeGift.PrizeNum > 0 {
	ok = utils.PrizeGift(prizeGift.Id, prizeGift.LeftNum)
	if !ok {
		return 207, "很遗憾，没有中奖，请下次再试", nil
	}
}
```

其中 `utils.PrizeGift`（基础版本）本质上就是对 `GiftService.DecrLeftNum(id, 1)` 的封装，递减失败即返回 `false`。

## 不同编码优惠券的发放

优惠券（`Gtype == conf.GtypeCodeDiff`）发放与普通限量奖品不同：不能只减库存，而要从编码池里"拿一个唯一码"给用户，并把该码状态置为已发放。

核心难点在于"找下一个可用码 → 改状态 → 回写"是多步操作，需要**分布式锁**保证线程安全。锁的 key 不能和正常用户锁冲突，于是用一个"负 UID"：

```go
// 用负数 UID 作为锁 key，避免与正常用户(uid>0)的锁冲突
lockUid := 0 - prizeGift.Id - 100000
utils.LockLucky(lockUid)
defer utils.UnlockLucky(lockUid)
```

### 查找下一个可用编码

`CodeDao.NextUsingCode`（`dao/code_dao.go`）按条件升序取第一条：

```go
// 找到下一个可用的最小优惠券（sys_status=0 表示有效）
func (d *CodeDao) NextUsingCode(giftId, codeId int) *models.LtCode {
	datalist := make([]models.LtCode, 0)
	err := d.engine.Where("gift_id=?", giftId).
		Where("sys_status=?", 0).
		Where("id>?", codeId).
		Asc("id").Limit(1).
		Find(&datalist)
	if err != nil || len(datalist) < 1 {
		return nil
	}
	return &datalist[0]
}
```

`lt_code` 表结构（`models/lt_code.go`）：

```go
type LtCode struct {
	Id         int    `xorm:"not null pk autoincr INT(10)"`
	GiftId     int    `xorm:"not null default 0 comment('奖品ID') INT(10)"`
	Code       string `xorm:"not null default '' comment('虚拟券编码') VARCHAR(255)"`
	SysCreated int    `xorm:"not null default 0 comment('创建时间') INT(10)"`
	SysUpdated int    `xorm:"not null default 0 comment('更新时间') INT(10)"`
	SysStatus  int    `xorm:"not null default 0 comment('状态，0正常，1作废，2已发放') SMALLINT(5)"`
}
```

### 发放的完整逻辑（按讲稿逻辑补充）

```go
// 不同编码优惠券发放：返回可用的唯一码，找不到返回空串
func prizeCodeDiff(giftId int, codeService services.CodeService) string {
	// 用负数 UID 作为锁 key，避免与正常用户锁冲突
	lockUid := 0 - giftId - 100000
	utils.LockLucky(lockUid)
	defer utils.UnlockLucky(lockUid)

	// 1. 找下一个可用编码（首次从上次 codeId=0 开始）
	codeInfo := codeService.NextUsingCode(giftId, 0)
	if codeInfo == nil || codeInfo.Id <= 0 {
		log.Println("prizeCodeDiff: 无可用编码, giftId=", giftId)
		return ""
	}
	// 2. 把状态改为"已发放"(2)，并更新时间
	codeInfo.SysStatus = 2
	codeInfo.SysUpdated = comm.NowUnix()
	if err := codeService.Update(codeInfo, nil); err != nil {
		log.Println("prizeCodeDiff Update err=", err)
		return ""
	}
	// 3. 返回该唯一编码，由上层写入中奖信息的 Gdata
	return codeInfo.Code
}
```

主流程中：

```go
// 步骤10：不同编码的优惠券发放

```
