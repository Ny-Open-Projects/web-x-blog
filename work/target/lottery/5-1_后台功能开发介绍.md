# Go 企业级抽奖项目: 后台功能开发介绍

## 纲要

- 后台管理模块整体定位：与抽奖业务同构，核心都是对各类数据的「增、删、改、查」。
- 本章覆盖范围：奖品管理、优惠券管理、中奖记录管理、用户管理、IP 黑名单管理五个后台模块。
- 开发策略：第一个模块（奖品管理）逐行精讲，后续模块只讲解与前文存在差异的部分，以加快进度。
- 通用技术栈：Iris 框架的 MVC 模式 + XORM 持久层 + 模板渲染，配合 BasicAuth 中间件做后台鉴权。
- 后台与抽奖核心接口的关系：后台负责数据的录入、维护与查询，抽奖接口（下一章）完全依赖这些后台数据。

## 后台模块的整体设计

后台功能开发与第一章介绍的六种抽奖玩法在业务方向上高度相似——本质都是围绕某一类数据的增删改查。因此本章采用「先细讲、后复用」的方式推进：

- 以「奖品管理」作为样板，把模板、控制器、路由、模型转换等环节完整实现一遍；
- 后续的优惠券、中奖记录、用户、IP 黑名单管理，功能结构与奖品管理同源，只需要在骨架基础上替换数据对象与少量差异逻辑，无需重复造轮子。

## 五个后台子模块

| 模块 | 页面 | 核心动作 | 差异点 |
| --- | --- | --- | --- |
| 奖品管理 | 列表页 + 编辑页 | 新增、保存、删除、恢复 | 含发奖计划（时间+数量数组）的序列化转换 |
| 优惠券管理 | 列表页（无编辑页） | 导入、删除、恢复 | 优惠券不可修改；支持批量导入与分页 |
| 中奖记录管理 | 列表页 | 删除、恢复、标记作弊 | 数据来自抽奖接口，无新增入口 |
| 用户管理 | 列表页 | 设置/解除黑名单（按周/月/年） | 仅维护黑名单时间字段 |
| IP 黑名单管理 | 列表页 | 设置/解除黑名单（按周/月/年） | 操作对象由用户改为 IP |

## 统一的工程结构

后台模块在项目中的落位如下（以 Iris 的 MVC 分层组织）：

```dir
web/
├── main.go                 # 站点初始化、路由注册
├── middleware/
│   └── basicauth.go         # 后台 BasicAuth 鉴权中间件
├── controllers/
│   ├── admin_controller.go       # 后台默认首页
│   ├── admin_gift_controller.go   # 奖品管理
│   ├── admin_code_controller.go   # 优惠券管理
│   ├── admin_result_controller.go # 中奖记录管理
│   ├── admin_user_controller.go   # 用户管理
│   └── admin_blackip_controller.go# IP 黑名单管理
└── views/
    ├── shared/layout.html   # 后台布局模板
    └── admin/               # 各后台页面模板
```

后台数据全部来源于管理操作，抽奖核心接口（下一章实现）在运行时直接消费这些已维护好的数据，因此后台是整套系统数据正确性的第一道闸门。
