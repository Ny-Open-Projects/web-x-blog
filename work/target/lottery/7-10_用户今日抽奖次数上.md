# Go 企业级抽奖项目: 用户今日抽奖次数缓存封装（上）

## 纲要

- 目标：把"用户今日参与抽奖次数"从数据库校验迁移到 Redis，降低 MySQL 压力。
- 缓存结构：每个用户的当日次数存放在 Redis 的 Hash 结构中，key 形如 `day_users_{i}`（i = uid % 分片数），field 为 uid，value 为当日已参与次数。
- 核心封装：
  - `IncrUserLuckyNum(uid)`：原子递增，返回递增后的次数。
  - `InitUserLuckyNum(uid, num)`：以数据库为准，把当前次数写回缓存（解决缓存重启后数据丢失导致不一致的问题）。
  - `resetGroupUserList()`：删除所有分片 key，实现"零点归零"。
- 生命周期：程序启动时执行一次 `resetGroupUserList`，并通过 `time.AfterFunc` 注册到次日零点的定时器，保证每日自动清零。

## 文本修正与整合

在抽奖接口里，用户"今日参与次数"原本每次都要去数据库里查、再比对上限。高并发下这会成为 MySQL 的明显负担。我们把这个计数放到 Redis 中，用 Hash 结构按用户分片存储。

为什么用 Hash 而不是直接给每个用户一个 String key？一方面是避免产生海量 key（key 过多会拖慢 Redis 的过期扫描与内存管理），另一方面是对同一类数据做逻辑聚合，便于统一清零。

封装要点如下：

- 分片：`userFrameSize` 控制分片数量，用 `uid % userFrameSize` 计算分片索引 `i`，key 即为 `day_users_i`。分片可以分散热点、减少单个大 Hash 的写入竞争。
- 递增：用 `HINCRBY key uid 1` 原子自增，返回自增后的结果，直接在业务逻辑里判断是否超过上限。
- 初始化：当缓存因为 Redis 重启、清空而丢失时，所有用户的 `HINCRBY` 都会从 0 变成 1，这显然和数据库里已存在的次数不一致。此时需要 `InitUserLuckyNum` 用数据库的真实次数把缓存补回来。
- 归零：提供 `resetGroupUserList`，遍历所有分片 `DEL` 掉对应 key；程序启动时调用一次，并用定时器在零点再次调用。

## 项目代码实现

下面是项目 `web/utils/user_day_lucky.go` 中的核心实现（基于 `github.com/gomodule/redigo/redis`，通过 `datasource.InstanceCache()` 获取连接池封装对象，`Do` 方法执行命令）：

```go
package utils

import (
	"fmt"
	"log"
	"math"
	"time"

	"imooc.com/lottery/comm"
	"imooc.com/lottery/datasource"
)

// 用户当日抽奖次数缓存的分片数量
const userFrameSize = 2

func init() {
	// 本地开发测试时，每次启动先把当日计数归零
	resetGroupUserList()
}

// 整点（次日零点）重置所有用户的当日抽奖次数
func resetGroupUserList() {
	log.Println("user_day_lucky.resetGroupUserList start")
	cacheObj := datasource.InstanceCache()
	for i := 0; i < userFrameSize; i++ {
		key := fmt.Sprintf("day_users_%d", i)
		cacheObj.Do("DEL", key)
	}
	log.Println("user_day_lucky.resetGroupUserList stop")
	// 注册到次日零点的定时器，循环归零
	duration := comm.NextDayDuration()
	time.AfterFunc(duration, resetGroupUserList)
}

// 今天的用户抽奖次数递增，返回递增后的数值
func IncrUserLuckyNum(uid int) int64 {
	i := uid % userFrameSize
	return incrServUserLucyNum(i, uid)
}

func incrServUserLucyNum(i, uid int) int64 {
	key := fmt.Sprintf("day_users_%d", i)
	cacheObj := datasource.InstanceCache()
	rs, err := cacheObj.Do("HINCRBY", key, uid, 1)
	if err != nil {
		log.Println("user_day_lucky redis HINCRBY key=", key,
			", uid=", uid, ", err=", err)
		return math.MaxInt32
	}
	return rs.(int64)
}

// 以数据库为准，直接初始化用户的当日参与次数
func InitUserLuckyNum(uid int, num int64) {
	if num <= 1 {
		return
	}
	i := uid % userFrameSize
	initServUserLuckyNum(i, uid, num)
}

func initServUserLuckyNum(i, uid int, num int64) {
	key := fmt.Sprintf("day_users_%d", i)
	cacheObj := datasource.InstanceCache()
	_, err := cacheObj.Do("HSET", key, uid, num)
	if err != nil {
		log.Println("user_day_lucky redis HSET key=", key,
			", uid=", uid, ", err=", err)
	}
}
```

`datasource.InstanceCache()` 返回的是一个对 `redis.Pool` 的封装（`*RedisConn`），其 `Do(commandName string, args ...interface{})` 方法从连接池取连接、执行命令并归还，错误处理统一打印日志，便于排查。

`comm.NextDayDuration()` 计算"当前时间到次日零点"的 `time.Duration`，用于 `time.AfterFunc` 注册一次性定时器，到点执行归零后会再次注册下一个零点，形成每日循环的清零机制。

## API 速览

| 命令 | 作用 | 本项目封装 |
| --- | --- | --- |
| `HINCRBY key field increment` | 对 Hash 中 field 的值原子自增 | `IncrUserLuckyNum(uid)` → `incrServUserLucyNum` |
| `HSET key field value` | 设置 Hash 中 field 的值 | `InitUserLuckyNum(uid, num)` → `initServUserLuckyNum` |
| `DEL key` | 删除整个 key（清零） | `resetGroupUserList()` |
| `time.AfterFunc` | Go 标准库定时器 | 注册零点归零 |

go-redis/v9 等价写法（如后续迁移到 `github.com/redis/go-redis/v9`）：

```go
// HINCRBY 等价
n, err := rdb.HIncrBy(ctx, fmt.Sprintf("day_users_%d", uid%2), strconv.Itoa(uid), 1).Result()
// HSET 等价
rdb.HSet(ctx, key, uid, num)
// DEL 等价
rdb.Del(ctx, key)
```

## Demo 示例

运行说明：本地启动一个 Redis（`127.0.0.1:6379`），安装依赖 `go get github.com/gomodule/redigo/redis`，然后 `go run main.go`。

代码说明：下面的示例完整演示"递增当日次数、读取、以数据库为准初始化、零点清零"四个动作。

```go
package main

import (
	"fmt"
	"log"
	"time"

	"github.com/gomodule/redigo/redis"
)

const userFrameSize = 2

func main() {
	conn, err := redis.Dial("tcp", "127.0.0.1:6379")
	if err != nil {
		log.Fatal(err)
	}
	defer conn.Close()

	uid := 1001
	key := fmt.Sprintf("day_users_%d", uid%userFrameSize)

	// 1) 原子递增当日参与次数
	n, err := redis.Int64(conn.Do("HINCRBY", key, uid, 1))
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("uid=%d 今日第 %d 次参与\n", uid, n)

	// 2) 读取当前次数
	cur, _ := redis.Int64(conn.Do("HGET", key, uid))
	fmt.Printf("从缓存读到 uid=%d 次数=%d\n", uid, cur)

	// 3) 假设数据库里该用户已有 5 次，以 DB 为准回写缓存
	_, err = conn.Do("HSET", key, uid, 5)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("已用数据库真实值初始化缓存")

	// 4) 零点归零（删除整个分片 key）
	_, err = conn.Do("DEL", key)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("已归零，新的一天重新开始计数")

	_ = time.Now
}
```

技术点总结：

- 用 `HINCRBY` 做原子计数，避免"先读后写"的并发竞态。
- 分片 Hash 降低单 key 写入热点，也避免产生海量独立 key。
- 缓存与数据库一致性：Redis 重启后用 `InitUserLuckyNum` 以 DB 为准补数。
- 定时器 `time.AfterFunc` + `NextDayDuration` 实现每日零点自动清零。
