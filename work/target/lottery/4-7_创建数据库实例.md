# Go 企业级抽奖项目: 创建数据库实例及其要点

## 纲要

- `datasource` 包负责创建并持有全局唯一的 XORM 引擎（数据库实例）
- `InstanceDbMaster()` 用**双重检查锁**实现单例，保证整个进程只有一个主库引擎
- 连接串 `dataSourceName` 由 `conf.DbMaster` 的 User/Pwd/Host/Port/Database 拼出：`user:pwd@tcp(host:port)/db?charset=utf8`
- `xorm.NewEngine` 失败则 `log.Fatal` 直接退出——连不上库整个应用应崩溃
- `ShowSQL(true)` 用于本地调试，可打印每条 SQL 与执行耗时；线上应关闭
- 必须匿名引入 MySQL 驱动 `_ "github.com/go-sql-driver/mysql"`，否则 XORM 找不到驱动

## 单例入口 InstanceDbMaster

`datasource` 包对外提供 `InstanceDbMaster()`，返回一个 `*xorm.Engine`。整个系统会不断调用它做数据库操作，因此希望全程只实例化一次——这就是典型的单例需求。

下面是项目 `datasource/dbhelper.go` 的真实实现：

```go
var dbLock sync.Mutex
var masterInstance *xorm.Engine

// 得到唯一的主库实例
func InstanceDbMaster() *xorm.Engine {
	if masterInstance != nil {
		return masterInstance
	}
	dbLock.Lock()
	defer dbLock.Unlock()

	if masterInstance != nil {
		return masterInstance
	}
	return NewDbMaster()
}
```

## 为什么需要双重检查锁

朴素写法是“判断为空就加锁创建”，但高并发下会有问题：

1. 第一次 `if masterInstance != nil` 不加锁，多个协程可能同时通过；
2. 进入临界区后只加锁创建，但锁释放后排队的两个协程会**再次进入并重复实例化**，单例就失效了。

正确做法是在 `Lock` 之后**再判断一次** `masterInstance != nil`（双重检查）：

- 已存在 → 直接返回，无需再加锁；
- 不存在 → 加锁后再次确认仍为空才真正创建。

这正是代码里“先 `if` 后 `Lock` 再 `if`”的结构。`sync.Mutex` 保证同一时刻只有一个协程进入创建分支。

## 构造连接串与引擎

`NewDbMaster()` 负责拼连接串并创建引擎：

```go
func NewDbMaster() *xorm.Engine {
	sourcename := fmt.Sprintf("%s:%s@tcp(%s:%d)/%s?charset=utf8",
		conf.DbMaster.User,
		conf.DbMaster.Pwd,
		conf.DbMaster.Host,
		conf.DbMaster.Port,
		conf.DbMaster.Database)

	instance, err := xorm.NewEngine(conf.DriverName, sourcename)
	if err != nil {
		log.Fatal("dbhelper.InstanceDbMaster NewEngine error ", err)
		return nil
	}
	instance.ShowSQL(true)
	//instance.ShowSQL(false)
	masterInstance = instance
	return masterInstance
}
```

连接串结构：`用户名:密码@tcp(IP:端口)/数据库名?charset=utf8`。`xorm.NewEngine` 的第一个参数是驱动类型（来自 `conf.DriverName`，值为 `mysql`）。

## 失败即退出与调试开关

如果 `NewEngine` 返回错误，说明连不上数据库——这种致命错误下整个应用无法正常工作，因此直接用 `log.Fatal` 让程序崩溃退出，而不是带着一个空引擎继续跑。

`instance.ShowSQL(true)` 是 XORM 的调试特性：会在日志中打印每一条执行的 SQL 语句及其执行时间（`ShowSQL` / `ShowExecTime`）。本地调试时打开很方便，线上环境应改为 `false` 以免日志噪音与性能损耗。

## 别忘了引入 MySQL 驱动

XORM 通过驱动名 `mysql` 工作，但驱动包本身在代码里没有被直接调用。必须匿名引入，让它随程序加载：

```go
import (
	_ "github.com/go-sql-driver/mysql"
	"github.com/go-xorm/xorm"
)
```

`_` 下划线把驱动包匿名化（隐藏其导出符号），但副作用是注册了 MySQL 驱动。如果不加这一行，运行时会因找不到驱动而报错。Redis 连接同理，在使用 `github.com/gomodule/redigo/redis` 时也要确保驱动被引入。

## API 速览

- `datasource.InstanceDbMaster() *xorm.Engine`：获取全局唯一主库引擎（双重检查锁单例）
- `datasource.NewDbMaster() *xorm.Engine`：真正创建引擎（拼连接串 + `xorm.NewEngine`）
- `xorm.NewEngine(driverName, dataSourceName string) (*xorm.Engine, error)`：创建引擎
- `(*xorm.Engine).ShowSQL(bool)`：开启/关闭 SQL 调试日志

## Demo 示例

下面给出一个可运行的最小单例示例（简化版，演示双重检查锁与连接串拼接，依赖 `xorm` 与 MySQL 驱动）：

```go
package main

import (
	"fmt"
	"sync"

	"github.com/go-xorm/xorm"
	_ "github.com/go-sql-driver/mysql"
)

var dbLock sync.Mutex
var masterInstance *xorm.Engine

func InstanceDbMaster() *xorm.Engine {
	if masterInstance != nil {
		return masterInstance
	}
	dbLock.Lock()
	defer dbLock.Unlock()
	if masterInstance != nil {
		return masterInstance
	}
	src := fmt.Sprintf("%s:%s@tcp(%s:%d)/%s?charset=utf8",
		"root", "password", "127.0.0.1", 3306, "lottery")
	engine, err := xorm.NewEngine("mysql", src)
	if err != nil {
		panic(err)
	}
	masterInstance = engine
	return masterInstance
}

func main() {
	e1 := InstanceDbMaster()
	e2 := InstanceDbMaster()
	fmt.Println("same instance:", e1 == e2)
}
```

运行说明：需本地有可连接的 MySQL，安装 `go-xorm/xorm` 与 `go-sql-driver/mysql` 后 `go run main.go`。

代码说明：示例完整呈现了“先判空 → 加锁 → 再判空 → 创建”的双重检查锁单例，与项目 `dbhelper.go` 一致；真实项目里连接参数来自 `conf.DbMaster`，失败用 `log.Fatal` 退出。

技术点总结：数据库实例用双重检查锁保证进程内唯一；连接串按 `user:pwd@tcp(host:port)/db?charset=utf8` 拼接；连库失败应直接崩溃；`ShowSQL` 仅本地调试开启；必须匿名引入 MySQL 驱动包，否则引擎找不到驱动。
