### Q5515 · 代理链路实现与超时分层

> 难度:★★★ | 标签:代理, 超时, 网络

**问**：走 HTTP CONNECT 代理和 SOCKS5 代理，Python 层各自怎么建立隧道？「连接超时 5s、读超时 30s、总预算 60s」在代理链路上怎么落地——为什么 requests 一个 `timeout=5` 会埋雷？

**答**：① HTTP CONNECT：向代理发 `CONNECT host:port HTTP/1.1`，收到 `200 Connection established` 后这条 TCP 就变成到目标的透明管道（TLS 在管道内与真实目标握手——证书校验对象是目标域名，不是代理）；② SOCKS5：握手二进制协商（版本 0x05 → 无认证 0x00 → CONNECT 命令 → 绑定地址），Python 标准库不含，手写或 PySocks。③ 超时分层是面试核心：**连接超时**（TCP/隧道建立）、**TLS 握手超时**（代理链路上经常被漏掉）、**读超时**（两次数据之间，不是总时长！）、**总预算**（deadline 覆盖全程）。requests 的 `timeout=(5, 30)` 只有连接/读两层且读超时可无限续期（每收到一个字节就重置）——慢速响应可以合法拖 30s×∞，必须外层再包总 deadline。

```python
# 全部标准库；本机起一个假 CONNECT 代理演示隧道建立与超时分层
import socket, time

def connect_via_http_proxy(proxy_host, proxy_port, target_host, target_port,
                           connect_timeout=5, handshake_timeout=5):
    """HTTP CONNECT 隧道：超时分三层（TCP/CONNECT 响应/隧道内 TLS）。"""
    sock = socket.create_connection((proxy_host, proxy_port), timeout=connect_timeout)  # 层1 TCP
    sock.settimeout(handshake_timeout)                                                  # 层2 隧道协商
    req = f"CONNECT {target_host}:{target_port} HTTP/1.1\r\nHost: {target_host}:{target_port}\r\n\r\n"
    sock.sendall(req.encode())
    resp = b""
    while b"\r\n\r\n" not in resp:
        resp += sock.recv(1024)
    status = resp.split(b"\r\n", 1)[0]
    if b" 200 " not in status:
        raise ConnectionError(f"代理拒绝: {status!r}")
    sock.settimeout(30)                  # 层3：隧道内读超时（此后 sock 是透明管道）
    return sock                          # 接下来可与目标 TLS 握手（证书校验目标是 target_host）

def fake_proxy():
    srv = socket.socket(); srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    srv.bind(("127.0.0.1", 0)); srv.listen(1)
    port = srv.getsockname()[1]
    def run():
        conn, _ = srv.accept()
        req = conn.recv(1024).decode()
        conn.sendall(b"HTTP/1.1 200 Connection established\r\n\r\n")
        conn.sendall(b"echo-back: " + req.split("CONNECT")[1].encode())
        conn.close()
    threading.Thread(target=run, daemon=True).start()
    return port

import threading
if __name__ == "__main__":
    port = fake_proxy()
    s = connect_via_http_proxy("127.0.0.1", port, "api.example.com", 443)
    print("隧道建立 OK，代理回执:", s.recv(200)[:60], b"...")
    s.close()
    # 超时预算模板（面试要能背出分工）：
    # TCP/代理连接 5s < TLS 握手 5s < 读超时 30s（每次 read 之间）<< 总 deadline 60s（外层强制）
    # requests timeout=(5,30) 只覆盖层1+层3，读超时会随每个字节重置 → 必须外层 deadline。
```

**追问**：1) 代理会不会看到 TLS 内容？——CONNECT 隧道只转发字节流，TLS 在隧道内端到端，代理只见 SNI 与 IP（SNI 明文，ECH 可加密）；SOCKS5 同理，除非装了企业级 MITM 证书。2) 为什么 TLS 握手超时经常被漏？——框架把「连接」定义为 TCP 建立完成，TLS 属于「第一次请求」的一部分，走读超时——代理链路上 TLS 慢握手表现为「请求慢」而不是「连接慢」，定位方向就错了。3) SOCKS5 需要认证时握手变什么？——方法协商阶段服务端回 0x02 要求用户名/密码，客户端发子协商块；UDP ASSOCIATE 是另一命令字，Q635 类网络题常考。

## 背诵要点
1. CONNECT 隧道 = `CONNECT host:port` → `200` 后变透明管道，TLS 在管道内、证书校验目标是真实域名。
2. 超时四层：TCP/隧道连接、TLS 握手（最常漏）、读超时（每次 read 重置，可无限续期）、总 deadline。
3. requests `timeout=(5,30)` 是两层口径：读超时可被慢速响应合法拖穿，必须外层包 deadline。
