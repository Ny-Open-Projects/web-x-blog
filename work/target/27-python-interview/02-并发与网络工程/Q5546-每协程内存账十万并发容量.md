### Q5546 · 每协程内存账与十万并发容量规划

> 难度:★★★☆ | 标签:asyncio, 容量规划, 内存, 协程

**问**："一个协程只占几 KB 所以能开百万并发"这句话怎么验证、哪里会翻车？给"10 万并发长连接网关"做内存容量规划，协程之外还有哪些隐性内存项？怎么用 tracemalloc 把每任务成本实测出来？

**答**：单 Task 的固定成本构成：Task 对象 + 协程帧（局部变量随业务涨）+ `coro.cr_frame` + callback 与 loop 调度开销，裸任务实测约 2-6 KB；翻车点在于**"每任务"不止一个 Task**——每连接通常还有：socket 与缓冲区（读 buffer 4-64KB，Q5530 的复用能省）、每连接的上下文对象（用户会话、trace 上下文）、待发送队列、以及 fire-and-forget 的辅助任务（心跳/超时定时器 handle，Q5533）。所以容量公式是：`总内存 ≈ 连接数 × (Task 固定成本 + 业务态 + socket 缓冲) + loop 全局开销`，10 万连接 × ~10KB 起步 ≈ 1 GB 量级，再叠加 Python 解释器与模块基础 RSS。实测法（关键技巧）：tracemalloc 打快照 → 建 N 个真实形态的空转任务 → diff 快照 → 除以 N 得每任务均值；再用 `snapshot.statistics('lineno')` 找意外大头（通常发现业务 dict 才是真正的内存黑洞，而不是 Task 本身）。告警水位设计：按连接数分档（如 5 万/8 万/10 万）对应内存水位与熔断阈值，连接风暴时先拒新保存量。

```python
# file: code/02_并发与网络工程/q5546_task_memory.py
import asyncio
import tracemalloc
import sys

N = 20_000

async def idle_conn():
    """模拟一个连接协程的最小形态: 挂起等待 + 少量业务态"""
    session = {"uid": None, "ts": 0.0}          # 每连接业务态
    await asyncio.sleep(3600)                   # 长连接挂起

async def main():
    tracemalloc.start()
    snap0 = tracemalloc.take_snapshot()

    tasks = [asyncio.create_task(idle_conn()) for _ in range(N)]
    await asyncio.sleep(0.2)                    # 等全部进入挂起态

    snap1 = tracemalloc.take_snapshot()
    cur, peak = tracemalloc.get_traced_memory()
    # 用快照 diff 统计整组增量(比 getsizeof 精确, 含帧与业务态)
    diff = snap1.compare_to(snap0, "lineno")
    grown = sum(s.size_diff for s in diff if s.size_diff > 0)
    print(f"python {sys.version_info[:2]} | {N} 个挂起 Task 增量 ≈ {grown/1e6:.1f} MB "
          f"-> 每任务 {grown/N/1024:.1f} KB")
    print(f"推算 10 万连接: {grown/N*100_000/1e9:.2f} GB(仅 Task+帧+session)")

    # 内存大头归因: 行号级统计
    for s in diff[:3]:
        if s.size_diff > 0:
            print("大头:", str(s).split("::")[0], f"+{s.size_diff/1e3:.0f} KB")

    for t in tasks:
        t.cancel()
    await asyncio.gather(*tasks, return_exceptions=True)
    tracemalloc.stop()

if __name__ == "__main__":
    asyncio.run(main())
```

**追问**：1) 为什么实测"每任务内存"不能只 `sys.getsizeof(task)`？——Task 只是冰山一角：协程帧、引用的 session、闭包变量都不计入浅大小（Q556），必须用快照 diff 拿"整组增量"。2) 10 万连接下 loop 自身的调度成本（每次 epoll 返回的就绪集合、回调队列）有什么量级？——每秒事件吞吐而非静态内存是下一个瓶颈：每连接心跳 30s 时约 3.3K 定时器事件/秒，Python 回调处理 ~微秒级，单核可扛但 CPU 成本随连接数线性涨（Q5537/Q5524）。3) reduce 手段排序？——buffer 复用 > session 精简（字段瘦身/序列化冷数据）> 连接分进程（REUSEPORT 分摊）> 换 sub-interpreter/多核并行。

## 背诵要点
- 裸 Task 固定成本 2-6 KB，但每连接真实成本 = Task + 帧 + 业务态 + socket 缓冲，10KB 起步。
- 实测方法：tracemalloc 双快照 diff ÷ N；行号统计归因，大头常是业务对象而非 Task。
- 容量规划 = 连接数 × 每连接成本 + loop 全局开销；按连接分档设内存水位与熔断。

## 复盘追问
