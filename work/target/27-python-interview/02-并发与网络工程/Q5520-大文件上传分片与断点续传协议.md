### Q5520 · 大文件上传分片协议

> 难度:★★☆ | 标签:分片上传, 断点续传

**问**：上传 10GB 文件，直传单请求有什么问题？分片协议要设计哪些接口——「断点续传」靠什么信息恢复进度，分片完整性怎么校验，秒传和并发上传冲突怎么处理？

**答**：直传问题：请求超时/连接中断即全部重来、内存无法整体装载、无法利用并发带宽。分片协议五件套：① **init**：客户端算整文件 SHA-256 申请 upload_id——服务器查指纹，已存在即**秒传**（直接关联引用）；② **chunk PUT**：分片号+offset+内容，服务器按分片落盘并记录已收清单（断点续传的真相源）；③ **status**：客户端断点重连时先查清单，只传缺的分片；④ **complete**：提交 upload_id，服务器按号拼接 + **逐片哈希比对 + 整体指纹复核**，不匹配的片名单回给客户端重传；⑤ **abort/过期清理**：孤儿分片 TTL 回收。并发冲突：同指纹多 upload_id 并行上传 = 幂等写分片（按 offset 覆盖写）+ complete 时引用计数合并，谁先 complete 谁生效，后者返回已有 file_id（幂等完成）。

```python
# 全部标准库；demo 实现 5MB 分片的完整协议骨架（内存模拟存储）
import hashlib, os, time, tempfile

CHUNK = 5 * 1024 * 1024
STORE: dict[str, dict] = {}                # upload_id -> {"chunks": {no: (sha, path)}, "sha": ...}
FILES: dict[str, str] = {}                 # 整文件 sha -> 落盘路径（秒传表）

def upload_init(data_sha: str) -> tuple[str, bool]:
    """返回 (upload_id, 已秒传?)；已存在的指纹直接秒传。"""
    if data_sha in FILES:
        return "instant", True
    uid = os.urandom(8).hex()
    STORE[uid] = {"sha": data_sha, "chunks": {}, "created": time.time()}
    return uid, False

def upload_chunk(uid: str, no: int, blob: bytes) -> bool:
    sha = hashlib.sha256(blob).hexdigest()
    path = os.path.join(tempfile.gettempdir(), f"{uid}.{no}")
    with open(path, "wb") as f:
        f.write(blob)
    STORE[uid]["chunks"][no] = (sha, path)   # 幂等：同号覆盖写
    return True

def upload_status(uid: str) -> list[int]:
    """断点续传：客户端只补缺的分片。"""
    return sorted(STORE[uid]["chunks"])

def upload_complete(uid: str, total: int) -> tuple[bool, list[int] | str]:
    entry = STORE[uid]
    if len(entry["chunks"]) < total:
        return False, [n for n in range(total) if n not in entry["chunks"]]
    out = tempfile.NamedTemporaryFile(delete=False, suffix=".bin")
    for n in range(total):
        sha, path = entry["chunks"][n]
        with open(path, "rb") as f:          # 拼接时逐片复核哈希
            blob = f.read()
        if hashlib.sha256(blob).hexdigest() != sha:
            return False, [n]
        out.write(blob)
    out.close()
    digest = hashlib.sha256(open(out.name, "rb").read()).hexdigest()
    if digest != entry["sha"]:
        return False, "整体指纹不匹配"
    FILES[digest] = out.name                 # 进秒传表
    del STORE[uid]
    return True, digest

if __name__ == "__main__":
    data = os.urandom(CHUNK * 3 + 1024)      # 3.0000.. 个分片
    sha = hashlib.sha256(data).hexdigest()
    uid, instant = upload_init(sha)
    assert instant is False
    blobs = [data[i*CHUNK:(i+1)*CHUNK] for i in range((len(data)+CHUNK-1)//CHUNK)]
    for i, b in enumerate(blobs[:-1]):       # 模拟中断：少传最后一片
        upload_chunk(uid, i, b)
    ok, missing = upload_complete(uid, len(blobs))
    assert ok is False and missing == [len(blobs)-1]   # 断点：缺片清单
    print("缺片清单:", missing)
    upload_chunk(uid, len(blobs)-1, blobs[-1])         # 断点续传补片
    ok, result = upload_complete(uid, len(blobs))
    assert ok and result == sha
    print("拼接完成，整体指纹一致 ✅")
    uid2, instant = upload_init(sha)                   # 秒传
    assert instant, "同指纹应秒传"
    print("秒传 ✅")
```

**追问**：1) 分片顺序号和 offset 为什么要都有？——顺序号定位「第几片」，offset 定位「全局字节位」；乱序上传/并行上传时只靠序号无法对齐，只靠 offset 无法判缺失。2) 分片多大合适？——带宽×单片上传时长（≈5-10s）反推，太大失败重传代价高、太小请求数爆炸；常见 5-20MB。3) 服务端怎么防止伪造指纹绕过秒传？——秒传命中后要求客户端证明持有内容（挑战-响应：返回随机 offset 段让客户端回传，或直接要求完整重传首尾片段校验）。

## 背诵要点
1. 五接口：init（指纹+秒传）/ chunk（幂等覆盖写）/ status（断点清单）/ complete（逐片+整体哈希复核）/ abort（TTL 回收孤儿片）。
2. 断点续传真相源 = 服务端已收分片清单；缺片清单由 complete 时比对得出。
3. 并发冲突解法：幂等分片写 + 秒传表引用合并，先 complete 生效、后 complete 幂等返回。

## 复盘追问
1. 秒传的隐私风险是什么？（提示：知道指纹即宣告拥有内容——网盘秒传曾被用于传播盗版资源；需权限/配额校验）
2. 上传服务怎么限速单用户？（提示：init 时分配配额令牌 + 分片请求扣减，或网关按用户限流）
