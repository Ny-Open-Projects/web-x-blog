### Q5519 · 异步 DNS 解析陷阱

> 难度:★★☆ | 标签:DNS, asyncio, 阻塞

**问**：asyncio 服务里「为什么偶发全服务卡 5 秒」——`socket.getaddrinfo` 在事件循环里的位置是什么？`dns.lookup` vs `dns.resolve` 的线程池区别在哪？DNS 缓存策略怎么配才不会「故障切换时缓存钉死旧 IP」？

**答**：三连：① `socket.getaddrinfo`（一切高层连接的底层，包括 `asyncio.open_connection` 的默认解析）是**阻塞系统调用**，asyncio 里直接调 = 整个事件循环冻结（所有任务停摆，直到解析返回或超时）——「偶发卡 5s」的典型元凶就是某次 DNS 慢查询阻塞了 loop；② 默认路径下 asyncio 把 getaddrinfo 扔进**默认线程池执行器**（`loop.getaddrinfo` → executor），单次调用不阻塞 loop 但**占用线程池槽**，线程池被别的任务占满时 DNS 排队同样表现为延迟毛刺；`dns.resolve` 类操作（如 `aiodns` 走 c-ares 库）是真异步非阻塞；③ 缓存：OS/`nscd`/框架层各有缓存，TTL 尊重不足 → 故障切换时钉死旧 IP；TTL 缓存太短 → QPS 高时 DNS 查询风暴。正确配置：应用层短 TTL 缓存（几秒~几十秒，遵守记录 TTL）+ 连接池按「DNS 变化」失效 + 健康检查主动刷新。

```python
# 全部标准库（aiodns 为可选优化，缺库降级已写明）
import asyncio, socket, time

def measure_blocking_dns():
    """证明 getaddrinfo 的阻塞性：主线程解析时事件循环被冻结。"""
    import threading
    ticks = []
    stop = threading.Event()
    def ticker():
        while not stop.is_set():
            ticks.append(time.monotonic()); time.sleep(0.001)
    th = threading.Thread(target=ticker, daemon=True); th.start()
    time.sleep(0.05)
    socket.getaddrinfo("www.python.org", 443)     # 阻塞调用（同步线程里）
    stop.set(); time.sleep(0.05)
    gaps = [b - a for a, b in zip(ticks, ticks[1:])]
    print(f"同步线程内 getaddrinfo 期间最大间隔: {max(gaps)*1000:.1f}ms（>1ms 即有冻结段）")

async def async_dns_correct():
    """正确姿势：asyncio.get_running_loop().getaddrinfo → 进线程池，loop 不冻结。"""
    loop = asyncio.get_running_loop()
    t0 = time.monotonic()
    infos = await loop.getaddrinfo("www.python.org", 443,
                                   family=socket.AF_INET, type=socket.SOCK_STREAM)
    print(f"异步解析 {time.monotonic()-t0:.2f}s，首个: {infos[0][4]}")
    return infos

async def resolver_with_cache(ttl=10):
    """应用层短 TTL 缓存：故障切换时不钉死旧 IP，高 QPS 不查风暴。"""
    cache: dict[tuple, tuple[float, list]] = {}
    async def resolve(host, port):
        key = (host, port)
        now = time.monotonic()
        if key in cache and now - cache[key][0] < ttl:
            return cache[key][1]
        loop = asyncio.get_running_loop()
        infos = await loop.getaddrinfo(host, port, family=socket.AF_INET, type=socket.SOCK_STREAM)
        cache[key] = (now, infos)
        return infos
    return resolve

if __name__ == "__main__":
    measure_blocking_dns()
    asyncio.run(async_dns_correct())
    resolve = asyncio.run(resolver_with_cache())
    asyncio.run(resolve("www.python.org", 443))
    print("TTL 缓存 OK")
    # 缺库降级说明：aiodns（c-ares）可替代线程池路径实现真异步解析，
    # 但 getaddrinfo 的服务/套接字语义更全；两者按「量大用 aiodns、语义全用 getaddrinfo」选。
```

**追问**：1) 怎么定位「偶发卡 5s」就是 DNS？——py-spy dump 看 main 线程是否停在 `getaddrinfo` 栈帧；或 strace 观测 `connect` 到 DNS 服务器（UDP 53）的耗时。2) 连接池会缓存已解析连接，DNS 变化怎么感知？——池按存活时间淘汰 + 定期解析比对 IP（漂移则驱逐旧连接）；LB 场景靠健康检查兜底。3) 为什么要 family/type 限定？——不带限定时 getaddrinfo 返回 IPv4+IPv6 全家桶并按 RFC 6724 排序，`happy eyeballs` 试连延迟可能翻倍；显式限定减少解析体积与尝试成本。

## 背诵要点
1. `getaddrinfo` 是阻塞系统调用：直接在事件循环调 = 全 loop 冻结，这是「偶发卡 5s」的常见元凶。
2. asyncio 默认把它扔线程池（不冻结但占槽）；真异步用 aiodns/c-ares。
3. DNS 缓存双刃：TTL 太长钉死旧 IP（故障切换失效）、太短查询风暴；应用层短 TTL + 连接池失效联动。
