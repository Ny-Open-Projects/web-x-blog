### Q5517 · 并发队列选型矩阵

> 难度:★★☆ | 标签:队列, 并发原语

**问**：`queue.Queue`、`asyncio.Queue`、`collections.deque`、`multiprocessing.Queue` 四个「队列」分别解决什么问题？误用最狠的三种事故——线程池里用 asyncio.Queue、deque 当线程安全队列、multiprocessing.Queue 在 fork 后清理——各错在哪？

**答**：选型一句话：**线程间**用 `queue.Queue`（锁 + 条件变量，天然阻塞式生产者-消费者）；**协程间**用 `asyncio.Queue`（await 阻塞，绝不能跨线程共享——它不是线程安全的）；**进程间**用 `multiprocessing.Queue`（底层 pickle + 管道，对象要可序列化）；`deque` 只是**线程安全的双端数组**，`append/popleft` 单操作原子（靠 GIL），但它**没有阻塞语义**——消费者没有 wait/notify，轮询拿空就空转。三大事故：① 在线程池里调 `asyncio.Queue.put_nowait` 后没人在跑 loop，元素永远没人消费；② 用 `deque` + `while not d` 轮询 = CPU 空转 + 延迟抖动，正确做法换 queue.Queue 或加 Condition；③ `multiprocessing.Queue` 在 `fork` 后子进程退出时残留 feeder 线程缓冲区——子进程写队列后立刻退出，数据可能还在 feeder 缓冲里没 flush（经典「子进程数据丢了」），要 `join_thread()` 或显式 flush。

```python
# 全部标准库；三段 demo 各自验证语义
import threading, time, multiprocessing, collections

# ① queue.Queue：阻塞语义让消费者休眠等待（零 CPU）
q: "queue.Queue[int]" = __import__("queue").Queue(maxsize=3)
def consumer():
    while True:
        item = q.get()                # 阻塞等待，无轮询
        if item is None: break
        time.sleep(0.01)
        q.task_done()
t = threading.Thread(target=consumer, daemon=True); t.start()
for i in range(10): q.put(i)
q.put(None); q.join()
print("queue.Queue 生产-消费同步 OK")

# ② deque 的原子边界：append/popleft 原子，但「取不到就睡 1ms」是轮询
d = collections.deque()
def poller():
    got = 0
    while got < 100:
        if d:
            d.popleft(); got += 1
        else:
            time.sleep(0.001)         # 这就是 deque 当队列的代价：忙等/轮询
p = threading.Thread(target=poller, daemon=True); p.start()
for i in range(100): d.append(i)
p.join(timeout=5)
print("deque 可用但无阻塞语义（延迟=轮询间隔）")

# ③ multiprocessing.Queue：fork 后 feeder 缓冲丢失演示（spawn 下更明显）
def child(q):
    q.put("important-data")           # 子进程写完立刻退出
if __name__ == "__main__":
    mp_q = multiprocessing.Queue()
    p = multiprocessing.Process(target=child, args=(mp_q,))
    p.start(); p.join()               # 子进程退出，但 feeder 线程可能未 flush
    time.sleep(0.2)
    try:
        print("读到:", mp_q.get(timeout=1))
        mp_q.close(); mp_q.join_thread()   # 正确收尾：等 feeder flush 完
    except Exception as e:
        print("可能读到空（feeder 缓冲丢失竞态）:", e)
```

**追问**：1) `queue.Queue` 的 `task_done/join` 语义解决什么？——批次完成的 join 点：生产者知道「全部处理完」而不仅是「全部入队」，缺它就只能靠计数器 hacks。2) `asyncio.Queue` 为什么故意不做线程安全？——设计上跨线程协调要走 `loop.call_soon_threadsafe` 或 janus 这类桥接库；隐藏跨线程共享只会造成静默消费丢失。3) 无界队列的共同风险？——`queue.Queue()`/`asyncio.Queue()` 默认无界：生产快于消费时内存爆，maxsize + 满时阻塞/丢弃策略是标配。

## 背诵要点
1. 线程=queue.Queue、协程=asyncio.Queue（非线程安全）、进程=multiprocessing.Queue、deque 无阻塞语义。
2. deque 单操作原子但不阻塞，当队列必轮询；跨线程用 asyncio.Queue = 消费丢失。
3. mp.Queue 子进程退出前 feeder 未 flush = 数据丢失竞态，收尾要 join_thread。
