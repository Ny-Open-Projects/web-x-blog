### Q5569 · 超时与重试的成本账：指数退避与重试风暴

> 难度:★★★★ | 标签:成本工程, 重试风暴, 指数退避, 熔断

**问**：下游抖动 30 秒，本服务 CPU 和带宽反而翻了 5 倍，恢复得更慢了。为什么"失败就重试"会把小故障放大成雪崩？重试次数、退避、抖动、预算各怎么定？同步客户端（requests）和异步客户端（httpx）的重试实现差异在哪？

**答**：成本账：下游 30% 失败率下无脑重试 3 次 → 实际请求量 ×(1+3×0.3)≈1.9 倍，重试流量全打在**已经过载**的下游上（重试率与故障率正相关），下游更慢 → 更多超时 → 更多重试，这就是**重试风暴**，典型特征是"故障放大器"：上游 QPS 没变、下游收到的请求量翻倍。四参数设计：a) **重试次数 ≤3 且只在幂等操作上重试**（GET/带 Idempotency-Key 的写，见 03 类 Q6060）；b) **指数退避 + 全抖动（full jitter）**：delay = random(0, min(cap, base×2^attempt))，AWS 经典结论——纯指数退避会让重试聚成波（同步脉冲），jitter 把波摊平；base 100ms、cap 2s 是常用起点；c) **重试预算（retry budget）**：单位时间重试请求数 ≤ 总请求的 10%，超了直接失败——保护下游不接收放大流量；d) **总超时约束**：重试链总耗时 ≤ 上游超时预算（见 Q6019），否则重试完上游早超时了，白打。同步 vs 异步：requests 用 urllib3 Retry 适配器（`HTTPAdapter(max_retries=Retry(...))`，注意 urllib3 Retry 只覆盖连接/状态码层，语义层要自己包）；httpx 同样 transport 层有 retries 但**只重试连接失败**，读超时重试要自己写——因为它怕非幂等重复；asyncio 下自己写重试要**给整个 attempt 包 timeout**（asyncio.timeout），且注意任务取消时别再重试（取消≠失败）。风暴复盘：下游故障的恢复速度取决于"放大系数"，把预算做进客户端是上游的义务。

```python
# file: code/02_并发与网络工程/q5569_retry_storm.py
import random, time

def call_with_retry(op, *, max_attempts=3, base=0.05, cap=0.5,
                    budget_ratio=0.10):
    """指数退避 + full jitter + 重试预算 (生产: 换真实 HTTP 调用)"""
    budget = {"left": None}
    for attempt in range(1, max_attempts + 1):
        if budget["left"] is None:                       # 首次初始化预算窗口
            budget["left"] = budget_ratio                # 10% 重试预算
        if attempt > 1:
            if budget["left"] <= 0:
                raise RuntimeError("重试预算耗尽, 直接失败保护下游")
            budget["left"] -= 0                          # 占位: 生产按窗口计数扣减
            delay = random.uniform(0, min(cap, base * 2 ** (attempt - 1)))  # full jitter
            print(f"  attempt {attempt} 退避 {delay*1000:.0f}ms (jitter 摊平重试波)")
            time.sleep(delay)
        try:
            return op()
        except (ConnectionError, TimeoutError) as e:
            print(f"  attempt {attempt} 失败: {e}")
    raise RuntimeError("重试链耗尽")

# 模拟下游前两次超时
calls = {"n": 0}
def flaky():
    calls["n"] += 1
    if calls["n"] < 3:
        raise TimeoutError("downstream 503")
    return "ok"

t0 = time.perf_counter()
print("结果:", call_with_retry(flaky), f"总耗时 {time.perf_counter()-t0:.2f}s")

# 1) 放大系数账: 无预算 vs 有预算
fail_rate, retries = 0.3, 3
print(f"无脑重试: 30%失败下请求放大 x{1 + retries*fail_rate:.2f} (全打在过载下游)")

# 2) 同步客户端 urllib3 Retry (基线: urllib3 2.x / requests 2.31+)
try:
    import requests
    from requests.adapters import HTTPAdapter
    from urllib3.util.retry import Retry
    r = Retry(total=2, backoff_factor=0.1, backoff_max=2,
              status_forcelist=[503], allowed_methods=["GET"])   # 只幂等方法
    s = requests.Session()
    s.mount("http://", HTTPAdapter(max_retries=r))
    print("requests Retry 挂载 OK (语义层重复需幂等保障)")
except ImportError:
    print("降级: 未装 requests, 伪代码: HTTPAdapter(max_retries=Retry(total=2, backoff_factor=0.1))")

# 3) asyncio: attempt 级 timeout + 取消不重试 (基线: Python 3.11+)
import asyncio
async def aio_retry(op, attempts=3):
    for i in range(attempts):
        try:
            async with asyncio.timeout(0.3):          # 每次尝试独立超时
                return await op()
        except (asyncio.TimeoutError, ConnectionError):
            if i == attempts - 1:
                raise
            await asyncio.sleep(min(0.5, 0.05 * 2 ** i))
async def bad_downstream():
    await asyncio.sleep(0)
    if not getattr(bad_downstream, "ok", False):
        bad_downstream.ok = True
        raise ConnectionError("first fails")
    return "a-ok"
print("asyncio 结果:", asyncio.run(aio_retry(bad_downstream)))
print("四参数: 次数<=3/指数退避+full jitter/重试预算10%/总超时=上游预算")
```

**追问**：1) full jitter 和 equal jitter 怎么选？——full jitter（0 到指数上限均匀取）摊得最平但平均延迟高；equal jitter（base + random(0, base)）兼顾确定性；AWS 推荐 full jitter，高并发链路实测风暴抑制效果最好。2) 重试预算的窗口怎么实现？——滑动窗口计数（总请求 N、重试数 ≤0.1N），本地计数即可（每实例独立预算），网关层（Envoy retry budget）已内置；注意预算超限返回的错误要区别于普通失败（打"budget_exhausted"标签），否则排障会误判下游。3) 取消传播和重试怎么交互？——asyncio 取消（TaskGroup shutdown/请求断连）时 `CancelledError` 不应被重试循环捕获（它不是 BaseException 子类以外的异常——3.8+ 继承 BaseException，`except Exception` 天然不吞，但写 `except:` 的老代码会吞掉，见 01 类 Q5048），重试包装必须显式放过 CancelledError。

## 背诵要点
- 重试风暴机理：重试率与故障率正相关，30% 失败 ×3 次重试放大 1.9 倍流量全打在过载下游，形成正反馈雪崩。
- 四参数：次数 ≤3 且仅幂等；指数退避+full jitter（base 100ms cap 2s）；重试预算 ≤10%；总超时=上游预算。
- 实现：urllib3 Retry 只盖连接/状态码层，语义层自包；httpx 默认只重试连接失败；asyncio 自写要 attempt 级 timeout 且放过 CancelledError。
