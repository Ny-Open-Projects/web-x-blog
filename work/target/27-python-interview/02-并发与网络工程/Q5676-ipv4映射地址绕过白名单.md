### Q5676 · IPv4-mapped 地址与文本 IP 规范化绕过白名单

难度：P6-P7 ｜ 标签：IPv6、IPv4-mapped、ipaddress、白名单、SSRF

**问**：管理端做 IP 白名单，配置里写 `127.0.0.1`，代码用字符串比较 `client_ip in ALLOWED`。为什么 IPv6 双栈监听时本机请求被拒绝，而攻击者用 `::ffff:127.0.0.1` 却能命中"看起来只允许内网"的逻辑？`socket.inet_aton("127.1")` 为什么返回 `127.0.0.1`，而 `ipaddress.ip_address("127.1")` 直接报错？文本 IP 到底该在哪一层规范化？

**答**：
结论：IPv4 和 IPv6 在文本层有多种合法写法：IPv4 有 `127.0.0.1`、`127.1`、`0177.0.0.1`、整数 `2130706433`；IPv6 有压缩、大小写、以及 **IPv4-mapped** `::ffff:127.0.0.1`（`::ffff:0:0/96` 网段，`IPv6Address.ipv4_mapped` 可取出内嵌 IPv4）。字符串比较 `==` 只能匹配"完全相同的文本"，`::ffff:127.0.0.1` 与 `127.0.0.1` 不相等，`::1` 与 `127.0.0.1` 也不相等；反过来，如果下游把 `::ffff:127.0.0.1` 规范化成 `127.0.0.1`，白名单又可能被"看起来是 IPv6"的输入绕过。正确做法是用 `ipaddress` 解析成对象/网段比较，并把 mapped 地址归一成 IPv4，绝不比较字符串。

取舍：`ipaddress.ip_address` 默认 strict，拒绝 `127.1` 这类历史写法；`socket.inet_aton` 接受它们——如果校验层用 `ipaddress`、连接层用 `socket`，就会出现"校验拒绝、连接仍可"或反之的语义裂缝。边界上应统一用 `ipaddress` 做唯一事实源：解析失败直接拒绝，解析成功再按 `IPv4Network/IPv6Network` 做 `in` 判断；对 `X-Forwarded-For` 这类多值头，取"最右侧可信代理之前"的那一段，再逐跳规范化，别拿整串做字符串匹配。

实战：事故形态是"内网白名单只写 IPv4，双栈 LB 把来源呈现为 `::ffff:10.0.0.5`，全部 403；运维临时加 `::ffff:10.0.0.0/104`，又因为文本写法不统一漏掉一部分"。下面展示：字符串比较失败、解析后也不相等（v6 vs v4）、`canonical()` 把 mapped 归一后成功；以及 `inet_aton` 与 `ipaddress` 对 `127.1` 的分歧。

```python
import ipaddress
import socket

raw = "::ffff:127.0.0.1"
addr = ipaddress.ip_address(raw)
print("原始:", raw, " version:", addr.version, " ipv4_mapped:", addr.ipv4_mapped)

allow_text = {"127.0.0.1"}
print("字符串比较放行:", raw in allow_text)
print("解析后比较放行:", addr in {ipaddress.ip_address(x) for x in allow_text})


def canonical(text):
    ip = ipaddress.ip_address(text)
    if isinstance(ip, ipaddress.IPv6Address) and ip.ipv4_mapped is not None:
        return ip.ipv4_mapped
    return ip


print("规范化后:", canonical(raw), " 放行:", canonical(raw) in {ipaddress.ip_address(x) for x in allow_text})
print("socket.inet_aton('127.1') =", socket.inet_aton("127.1"))
try:
    ipaddress.ip_address("127.1")
except ValueError as e:
    print("ipaddress 拒绝缩写形式:", e)
```

**追问一**：`::1` 和 `127.0.0.1` 是同一个地址吗？需要互相放行吗？——不是同一个地址：`::1` 是 IPv6 loopback，`127.0.0.1` 是 IPv4 loopback，二者在不同协议栈；双栈监听时客户端连 `::1` 就呈现 `::1`，连 `127.0.0.1` 就呈现 `127.0.0.1`（或 mapped 形式，取决于 socket 选项和内核）。白名单要分别列出，或者用"同时接受 v4/v6 loopback"的显式集合；不要假设一个能代表另一个。

**追问二**：为什么 `inet_aton` 接受 `127.1` 而 `ipaddress` 拒绝？——`inet_aton` 沿用历史 inet 解析规则，允许省略段、八进制/十六进制、单整数形式；`ipaddress` 按现代严格文本表示解析，只接受四段十进制（IPv4）或标准 IPv6。安全边界应该用严格解析并在入口拒绝歧义写法，否则"校验层认为不是 IP、连接层却能解析"就是 SSRF/白名单绕过；如果必须兼容旧格式，也要在规范化后再做一次严格校验。

## 背诵要点
- 文本 IP 有多种合法写法：`127.1`、整数、`::ffff:127.0.0.1`；字符串 `==` 不能做白名单。
- 用 `ipaddress` 解析成对象/网段比较；mapped 地址用 `ipv4_mapped` 归一成 IPv4。
- `inet_aton` 宽松、`ipaddress` 严格；校验层与连接层必须统一，否则白名单/SSRF 绕过。
