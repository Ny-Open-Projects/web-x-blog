### Q5567 · 进程池的孤儿与僵尸进程治理

> 难度:★★★★ | 标签:事故复盘, multiprocessing, 孤儿进程, 僵尸进程

**问**：kill 主进程后任务"还活着"继续写库，另一场景 ps 里一堆 `[python] <defunct>` 堆积到几百个。孤儿进程和僵尸进程的成因分别是什么？multiprocessing Pool 与 subprocess 各自的退出行为怎么管？优雅停机怎么做才不留尾巴？

**答**：两个概念相反方向：a) **孤儿**：子进程还活着、父进程先死（父进程未终止子进程树），子进程被 init/PID1 收养继续跑——事故形态是"kill -9 主服务后后台任务仍在写库"；容器里 PID1 不转发信号（见既有 Q5552 SIGTERM 治理）时更糟，整个进程树成了僵尸树。b) **僵尸**：子进程已退出但退出状态没被父进程 `wait()` 收尸，ps 显示 `<defunct>`——multiprocessing 的 Process 对象不 join 就堆僵尸；Pool 的 worker 由 Pool 内部管理收尸，但**主进程异常退出（kill -9）时 worker 会被 Python 的 _exit_function 处理**——Pool 默认等任务结束才退（所以 kill -TERM 会卡在等待），要 `pool.terminate()`。multiprocessing 3.7+ 有 `Process.daemon=True`（父退出时 terminate 子进程，但不能有自己的子进程）与 `close()/join(timeout)`；subprocess 侧用 `Popen.wait(timeout)` + 超时 `kill()`，还有 `start_new_session=True` 的坑：脱离进程组后父进程 kill 进程组收不到它，变成真孤儿。优雅停机清单：①注册 SIGTERM → `pool.close(); pool.join(timeout)` → 超时 `terminate()` → 极限 `kill()`；②subprocess 记账（字典存 Popen），停机时逐个 terminate+wait；③容器里显式 `tini/init: true` 转发信号；④告警监控：`ps defunct 计数` 与"父进程已死但子进程存在"检测。

```python
# file: code/02_并发与网络工程/q5567_orphan_zombie.py
import multiprocessing as mp, os, subprocess, time, signal

def worker(n):
    time.sleep(0.05)
    return n * 2

if __name__ == "__main__":          # macOS spawn 必须守卫
    # 1) 僵尸复现: 不 join 不收尸
    p = mp.Process(target=worker, args=(1,))
    p.start()
    time.sleep(0.2)                 # 子进程已退出
    print("join 前 zombie 状态:", p.is_alive(), "(子已死但状态未收 -> defunct)")
    p.join()                        # 收尸
    print("join 后 exitcode:", p.exitcode)

    # 2) 优雅停机模板: close -> join(timeout) -> terminate -> kill
    pool = mp.Pool(2)
    pending = [pool.apply_async(worker, (i,)) for i in range(8)]
    pool.close()                    # 不再接新任务
    dl = time.monotonic() + 2       # 手动超时等待 (Pool.join 无 timeout 参数)
    while time.monotonic() < dl and not pool._state == mp.pool.RUN:
        if all(h.ready() for h in pending):
            break
        time.sleep(0.02)
    pool.terminate()                # 超时强杀
    print("pool 停机完成")

    # 3) subprocess 记账 + 超时收尸
    children = {}
    pr = subprocess.Popen(["sleep", "10"])
    children[pr.pid] = pr
    try:
        rc = pr.wait(timeout=0.2)
    except subprocess.TimeoutExpired:
        pr.terminate()              # SIGTERM
        try:
            rc = pr.wait(timeout=1)
        except subprocess.TimeoutExpired:
            pr.kill()               # SIGKILL 兜底
            rc = pr.wait()
        print("超时链: terminate->wait->kill, rc =", rc)
    children.pop(pr.pid)
    print("停机时 children 账本清零:", not children)

    # 4) daemon=True: 父退出自动 terminate 子进程
    d = mp.Process(target=worker, args=(9,), daemon=True)
    d.start()
    d.join(timeout=1)
    print("daemon 子进程随父退出被杀:", not d.is_alive())
    print("容器铁律: PID1 用 tini 转发信号; start_new_session=True 会脱离进程组变孤儿")
```

**追问**：1) Pool 的 terminate 和 close 区别？——close 拒绝新任务但等存量跑完（优雅），terminate 立刻杀 worker（任务可能丢一半）；join 在 close 后调用等收尾，terminate 后调用防句柄残留；kill -9 主进程时 worker 收不到任何信号成为孤儿——所以"重启脚本"要连带清理子进程（pkill -P 或进程组 kill）。2) 僵尸堆积的根因除了忘 join 还有什么？——用 `subprocess` 管道读但没 wait（读 EOF 后子进程退出但状态挂着）、库内部起的线程没清理、`os.fork` 裸用没收尸；系统性解法是统一进程管理器（集中 spawn/记账/wait），禁止散落 Popen。3) 容器 PID1 的信号问题？——Python 做 PID1 默认不转发 SIGTERM 给子进程、不 reap 孤儿子进程（init 系统职责），僵尸会无限堆积；要么 tini/--init，要么 Python 里注册信号转发 + 循环 `os.waitpid(-1, WNOHANG)` 收尸。

## 背诵要点
- 孤儿=父死子活（被 PID1 收养继续干活，kill -9 主服务后任务仍写库）；僵尸=子死状态未收（不 join/Popen 不 wait 堆 `<defunct>`）。
- Pool：close 等存量 / terminate 强杀 / join 收尾；subprocess 记账 + terminate→wait→kill 超时链；daemon=True 随父退出。
- 容器 PID1 必须 tini 转发信号并收尸；start_new_session=True 脱离进程组会成为 kill 不到的孤儿；监控 defunct 计数。
