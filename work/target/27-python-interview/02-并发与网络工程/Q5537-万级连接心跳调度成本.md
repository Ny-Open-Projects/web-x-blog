### Q5537 · 万级连接的心跳调度成本：每连接任务 vs 单轮询表

> 难度:★★★★ | 标签:容量规划, 心跳, 调度成本, asyncio

**问**：10 万条长连接，每条一个心跳协程 vs 一个全局轮询表，成本差多少量级？心跳间隔怎么定？连接抖动大时（每秒几千次建立/断开）调度器还会遇到什么新问题？

**答**：两模型的成本账：**每连接任务**——每连接一个协程 + 一个 `TimerHandle`（asyncio.sleep 本质是 call_later），10 万连接 = 10 万协程（每协程约 1-2KB，Task 成本账 Q2678）+ 10 万堆条目，每秒固定 10 万次堆操作进出（O(log n)），且每次连接断开要走取消传播。**单轮询表**——一个调度任务维护 `dict[conn, next_deadline]`，每秒扫一遍到期项（桶按秒分片则每次只扫当前桶），CPU 与连接数解耦，内存一条 dict 记录（约 100B）远小于协程帧。10 万级时两模型都能活，但**抖动风暴**（重连风暴后连接数瞬时翻倍）下每连接任务的取消/新建协程开销变成毛刺源。心跳间隔的账：间隔 = 检测延迟与开销的杠杆——TCP keepalive 底层参数（Q5512）与应用层 ping 二选一或分层；应用层间隔通常 30-60s（NAT 超时普遍 ≥60s，太短纯浪费），轮询表按秒分桶。设计结论：**万级以下用每连接任务（简单），十万级或高抖动用分桶轮询表（成本可控）**；折中方案是"惰性心跳"——读事件顺便刷新 deadline，无流量才真发 ping（省 90% 心跳包）。

```python
# file: code/02_并发与网络工程/q5537_heartbeat_scale.py
"""心跳调度两模型的成本建模与分桶轮询表实现."""
import asyncio
import random
import time

# --- 模型 A: 每连接任务(简单, 万级以下首选) ---
async def per_conn_heartbeat(conn_id: int, interval: float, on_ping) -> None:
    try:
        while True:
            await asyncio.sleep(interval)          # 每连接一个 TimerHandle
            on_ping(conn_id)
    except asyncio.CancelledError:
        raise                                       # 断开时取消传播(Q589)

# --- 模型 B: 分桶轮询表(十万级/高抖动) ---
class BucketHeartbeat:
    """按秒分桶的惰性心跳: 读事件刷新 deadline, 只有到期且无读才发 ping."""

    def __init__(self, interval: float = 45.0, buckets: int = 64) -> None:
        self.interval = interval
        self.buckets = buckets                       # 桶数=扫粒度
        self.table: dict[int, float] = {}            # conn_id -> next_deadline
        self.last_seen: dict[int, float] = {}        # conn_id -> 最近读事件
        self.pings = 0

    def register(self, conn_id: int) -> None:
        now = time.monotonic()
        self.table[conn_id] = now + self.interval
        self.last_seen[conn_id] = now

    def touch(self, conn_id: int) -> None:           # 读事件顺便刷新(惰性核心)
        self.last_seen[conn_id] = time.monotonic()

    def unregister(self, conn_id: int) -> None:
        self.table.pop(conn_id, None)
        self.last_seen.pop(conn_id, None)

    async def run(self) -> None:                     # 单任务轮询: 成本与连接数解耦
        step = self.interval / self.buckets
        while True:
            await asyncio.sleep(step)
            now = time.monotonic()
            due = [cid for cid, dl in self.table.items() if dl <= now]
            for cid in due:
                idle = now - self.last_seen.get(cid, 0)
                if idle >= self.interval:            # 无读流量才真发 ping
                    self.pings += 1
                self.table[cid] = now + self.interval

def cost_model(n: int) -> None:
    per_conn_kb = 1.5                                 # 协程+Task 近似
    table_b = 120                                     # dict 两行记录
    print(f"连接数={n:>7,}: 模型A 协程内存≈{n*per_conn_kb/1024:,.0f}MB + "
          f"{n:,} 堆条目 | 模型B ≈{n*table_b/1024/1024:.1f}MB + 1 任务")

if __name__ == "__main__":
    pinged = []
    async def demo() -> None:
        hb = BucketHeartbeat(interval=0.5, buckets=8)
        for i in range(1000):
            hb.register(i)
        task = asyncio.create_task(hb.run())
        await asyncio.sleep(0.05)
        for i in range(0, 1000, 2):                   # 一半连接有读流量
            hb.touch(i)
        await asyncio.sleep(0.6)
        task.cancel()
        print(f"惰性心跳: 1000 连接 0.6s 实发 ping={hb.pings} "
              f"(无流量的那半才会真发)")

    asyncio.run(demo())
    for n in (1_000, 10_000, 100_000):
        cost_model(n)
    print("结论: <1万 用每连接任务; 十万级/高抖动 用分桶轮询表+惰性心跳")
```

**追问**：1) 惰性心跳为什么能省 90% 包？——活跃连接本来就在收数据，其"存活"已被读事件证明；只有静默连接才需要显式 ping，而静默连接通常占少数。2) 轮询表的 O(n) 扫描在高抖动下会不会退化？——按桶分片后每次只处理到期桶，平均 O(到期数)；但 `dict.items()` 遍历期间注册/注销要小心（用收集后处理的快照模式，避免迭代中改字典 Q2076）。3) keepalive 参数和应用层心跳怎么分层？——内核 keepalive（tcp_keepalive_time 等）检测传输层死亡（兜底，分钟级），应用层心跳检测"进程活着但卡死"（业务层，秒级），两层检测对象不同不可互相替代（Q5512）。

## 背诵要点
- 每连接任务=协程+TimerHandle × N，1 万以下简单直接；十万级/高抖动用分桶轮询表，成本与连接数解耦。
- 心跳间隔 30-60s 起步（NAT 超时约束）；惰性心跳（读事件刷 deadline）省 90% 包。
- 内核 keepalive 查传输死、应用心跳查进程卡死，分层不可互替。
