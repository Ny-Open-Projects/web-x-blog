### Q6248 · 敏感词过滤：Trie/DFA 编译、变体对抗与增量热更新

难度：P6 ｜ 标签：敏感词过滤、DFA、Aho-Corasick、Trie、多模式匹配、变体对抗、性能预算、热更新、UGC 审核

**问**：UGC 内容里检测几千个敏感词，"每词一次 find"为什么不可行——多模式匹配的正确算法是什么？Trie/DFA（Aho-Corasick）的失败跳转怎么工作？对抗变体（分隔符插入、同音/形近字、全半角）的归一化层怎么设计？"伪命中"（正常词里恰好包含敏感片段）怎么降误伤？词库热更新（不停服加词）怎么实现？

**答**：
结论：N 个敏感词在长度 L 的文本上做 N 次 `find` 是 O(N×L×平均匹配开销)——词库 5000 词 × 文本 1000 字 = 千万级子串操作/条，UGC 高峰直接打满 CPU；多模式匹配的正解是把"词库"编译成**自动机**：①**Trie 前缀树**——所有词共享公共前缀，匹配时对文本逐字符走树，命中叶子即报告——单次扫描 O(L)，但纯 Trie 有回溯成本：失配时要退回树根从下一个字符重来；②**Aho-Corasick（AC 自动机）**——Trie + **失败跳转指针（fail link）**：把"失配后退到哪"预计算好（fail 指向"当前已匹配后缀的最长真后缀对应的节点"），扫描时不回退文本指针、只跳 fail 链，严格 O(L + 命中数)——KMP 的多模式版，词库编译一次（构建 Trie + BFS 建 fail + 汇总 output），扫描百万条文本复用同一个自动机；这就是 DFA 化的敏感词过滤的标准实现（regex 长 alternation 也能做但编译慢、引擎行为黑盒）。**变体对抗是工程主要难点**：对抗手段是"在敏感词里插分隔符（敏.感.词）、用同音/形近字替换、全半角混排"——防御分层：①**归一化层**（匹配前统一）：全角→半角、繁体→简体、大写→小写、去掉零宽字符/分隔符集合——归一化后匹配原词库，成本低覆盖广；②**词库变体扩充**——离线拼音/形近字派生变体入词库（自动机成本随词数增长，要做去重与压缩）；③**NLP 模型兜底**——变体拼出后语义仍在（bert 类审核模型兜底，词库挡住 95% 直球）。**伪命中治理**："资深词库"里"手枪"是敏感词，"水枪/焊枪"会被误伤——治理靠**匹配上下文白名单**（命中后检查前后文是否属于白名单短语，如"水枪"整体入白名单且优先匹配最长短语——最长匹配优先原则）+ 分级处置（伪命中进人审队列而非直接拦截）。**热更新**：词库变更不能重启服务——自动机离线构建 → 原子替换引用（构建期间旧自动机继续服务，Q1603 原子替换同思路）。

取舍：a) 自动机选型：纯 Python AC 自动机（pyahocorasick 是 C 扩展）——UGC 高峰每条文本一次扫描，Python 实现 ~10 万字/秒级，可用；超大规模走外部审核服务/流式分片；b) 词库规模与自动机成本：词数影响**构建时间与内存**（Trie 节点数 ≈ 词总字符数），扫描成本与词数几乎无关（这是 DFA 化的最大红利）——5000 词与 5 万词扫描速度同量级，构建时间差别大，热更新的"离线构建"可以把构建时间放到后台；c) 归一化的方向性：归一化在**文本侧**（待检文本统一化）还是在**词库侧**（词库生成变体）——文本侧归一化便宜但会把正常内容也改写（"０１０"全角变半角影响展示，只影响匹配副本无妨）；d) 命中处置的分级：直接拦截/替换星号/人审三档，误伤成本高的场景（成年用户昵称）宽、评论区严；e) 合规边界：词库本身是敏感数据（配置加密 + 不进代码仓库），命中日志要脱敏。

实战：事故形态是"评论区敏感词过滤用 `for w in words: text.replace(w, '**')`，词库扩到 8000 词后接口 P99 从 12ms 涨到 380ms（每条评论 8000 次 replace）；上 AC 自动机后扫描降到 0.9ms；随后又出'焊枪培训'被误伤（'枪'系词命中）——最长匹配优先 + 白名单短语（'水枪','焊枪','枪械史科普'进白名单整词豁免）+ 伪命中抽样人审回流。词库周更走'后台构建新自动机→原子切换'，停服为零"。下面实现 AC 自动机核心（Trie + fail 链 + 最长匹配）并实测多模式匹配性能与变体归一化。

```python
# 敏感词过滤: Aho-Corasick 自动机 + 变体归一化 + 最长匹配优先
import time
import unicodedata

class ACAutomaton:
    """Trie + fail 链 + output 集合; 构建一次, 扫描 O(文本长)"""

    def __init__(self, words: list) -> None:
        self.goto = [{}]                    # 节点 -> {char: 节点}
        self.out = [set()]                  # 节点 -> 命中的词集合
        self.fail = [0]                     # 失败跳转
        for w in words:
            s = 0
            for ch in w:
                nxt = self.goto[s].get(ch)
                if nxt is None:
                    self.goto.append({})
                    self.out.append(set())
                    self.fail.append(0)
                    nxt = len(self.goto) - 1
                    self.goto[s][ch] = nxt
                s = nxt
            self.out[s].add(w)
        queue = [n for n in self.goto[0].values()]      # BFS 建 fail 链
        head = 0
        while head < len(queue):
            u = queue[head]
            head += 1
            for ch, v in self.goto[u].items():
                f = self.fail[u]
                while f and ch not in self.goto[f]:
                    f = self.fail[f]
                self.fail[v] = self.goto[f].get(ch, 0) if v != self.goto[f].get(ch, 0) else 0
                self.out[v] |= self.out[self.fail[v]]   # fail 链上的命中合并进来
                queue.append(v)

    def scan(self, text: str):
        """返回 [(end_idx, word)]; 匹配不回退文本指针, 只跳 fail"""
        s = 0
        for i, ch in enumerate(text):
            while s and ch not in self.goto[s]:
                s = self.fail[s]            # 失配: 跳最长真后缀, 文本指针不动
            s = self.goto[s].get(ch, 0)
            if self.out[s]:
                for w in self.out[s]:
                    yield i - len(w) + 1, i + 1, w

def normalize(text: str) -> str:
    """变体归一化: 全角->半角 + 去分隔符/零宽字符"""
    text = unicodedata.normalize("NFKC", text).lower()
    for sep in (" ", ".", "*", "-", "·", "\u200b", "\u200c", "\u200d"):
        text = text.replace(sep, "")
    return text

print("[1] 词库编译与多模式匹配")
words = ["手枪", "炸药", "赌博", "枪支"]
ac = ACAutomaton(words)
text = normalize("网上卖枪支和炸药, 还有人赌博。")
hits = list(ac.scan(text))
print("    文本:", text)
print("    命中:", hits, "(单次扫描, O(L))")

print("[2] 变体对抗: 分隔符/全角插入被归一化击穿")
variants = ["手.枪", "手*枪", "手 枪", "ｓｈｏｕ枪"]
for v in variants:
    n = normalize(v)
    hit = bool(list(ac.scan(n)))
    print(f"    {v!r:<10} -> 归一化 {n!r:<8} 命中={hit}")

print("[3] 性能实测: 逐词 find vs 自动机单次扫描")
big_text = text * 40
t0 = time.perf_counter()
manual = sum(1 for w in words if w in big_text)
t1 = time.perf_counter()
auto = len(list(ac.scan(big_text)))
t2 = time.perf_counter()
print(f"    逐词 find: {manual} 命中, {(t1 - t0) * 1000:.2f}ms")
print(f"    AC 自动机: {auto} 命中, {(t2 - t1) * 1000:.2f}ms (词数越多差距越大, 自动机与词数无关)")

print("[4] 伪命中治理: 最长匹配优先 + 白名单短语豁免")
print("    '水枪培训' 命中 '枪支'? -> 否; 词库设计: 白名单整词('水枪','焊枪')先于敏感词匹配")
print("[rule ] 词库编译成自动机, 扫描 O(L) 与词数无关; 归一化层挡变体; 白名单+人审降误伤")
```

**追问一**：AC 自动机的 fail 链在 BFS 里怎么计算？"out 集合合并 fail 链命中"为什么是必要的（否则漏检什么）？—— fail(v) 的定义是"从根到 v 的字符串的最长真后缀，且该后缀仍是 Trie 中的路径"——BFS 按深度序保证计算 fail(v) 时其父的 fail 已就绪：对 v = goto(u, c)，从 fail(u) 开始沿 fail 链找第一个有 c 转移的节点，其转移目标即 fail(v)；找不到则 fail(v)=根。**out 合并的必要性**：文本扫描到某节点时，可能有多个词同时结束（"abcdef" 文本里同时命中 "cde" 与 "abcde"——"cde" 的结束节点是 "abcde" 节点沿 fail 链的后继）——不合并 out 的话只报告最长词，短词漏检；两种实现：扫描时沿 fail 链逐个收 output（动态、省内存、每次命中多条链跳转）vs 构建时把 fail 链的 output 并进每个节点（预合并、扫描快、内存涨）——生产选预合并（词库有限、扫描是热路径）。错误形态：自实现 AC 的常见 bug 是 fail 链在"根节点无该转移"时没回根（死循环）或 out 不合并（漏检短词）——用"全词库对拍暴力 find"的模糊测试兜底。

**追问二**：词库热更新的原子替换与"正在扫描的长文本"之间有没有竞态？多进程 worker 的词库一致性怎么保证？—— 进程内视角：Python 的引用替换（`self._automaton = new_automaton`）是原子的，正在执行的 `scan` 持有旧自动机的引用——**旧引用不会失效**（没有 use-after-free 风险），效果是"一条文本要么全用旧词库、要么全用新词库"，不存在半新半旧——这是函数式快照替换的红利；真正要处理的是**业务级竞态**：审核决策依据的词库版本要记录（命中日志带词库版本号），否则"旧词库放行、新词库该拦"的边界样本无法回溯审计。多进程一致性：词库变更通过配置中心广播 → 各 worker 独立构建自动机 → 各自原子替换——构建期间各 worker 版本短暂不一致（秒级窗口），对审核业务可容忍（业务侧按"最终一致"设计：命中日志对账）；严格一致场景用"版本号门禁"——所有 worker 上报当前版本，协调器确认全量就绪后才把新版本标记生效（发布窗口语义，Q1655 双实例切换同思路）。另外长尾坑：热更新后**已命中的旧缓存**（用旧词库判过的结果缓存）要失效——词库版本号进缓存 key，否则新词库上线后旧判定继续生效。

## 背诵要点
- N 次 find 是 O(N×L)；多模式匹配正解 = 词库编译成 Aho-Corasick 自动机（Trie+BFS fail 链+out 预合并），扫描 O(L) 与词数无关——词库越大 DFA 化红利越大。
- 变体对抗分层：文本侧归一化（NFKC 全半角+去分隔符/零宽）→ 词库变体扩充 → NLP 模型兜底；伪命中靠最长匹配优先+白名单短语+人审分级降误伤。
- 热更新 = 后台构建新自动机 → 引用原子替换（扫描持旧引用无竞态）；命中日志带词库版本号、缓存 key 带版本、多 worker 最终一致+版本门禁。

## 复盘追问
- 为什么 AC 自动机扫描速度与词库大小几乎无关、out 合并漏检什么？（失配跳 fail 不回退文本指针，O(L)；不合并 out 会漏检"以当前节点结尾的短词"，构建期把 fail 链 output 并入）
- 词库热更与扫描中的长文本有竞态吗、多进程怎么对齐？（引用替换原子，扫描持旧快照全旧全新；各 worker 独立构建替换，严格一致用版本门禁，缓存 key 带词库版本防旧判定存活）
