### Q6102 · 缓存 key 缺租户维度导致越权事故复盘

> 难度:★★★★☆ | 标签:事故复盘, 多租户, 缓存

**问**:租户 A 的用户看到租户 B 的仪表盘数据，链路上哪一环丢了租户身份？

**答**:结论：多租户越权最常见的洞不在 SQL，而在缓存 key——SQL 层有 `tenant_id` 过滤，缓存层却用 `dashboard:{user_id}` 或 `dashboard:{path}` 这类"缺租户维度的 key"，两个租户同 id/同 path 直接命中同一份缓存（Q6014 只讲了隔离模式，没讲缓存维度的坑）。事故三要素：key 设计缺维度、回填逻辑信任了"查得到就是对的"、监控只有命中率没有串号告警。修复：① key 强制携带租户维度（`t:{tenant}:dashboard:{user}`），把它做成框架级约定而不是业务自觉；② 读路径的租户上下文从可靠来源取（JWT/会话，经 contextvars 传播，Q5561），**绝不信缓存里的身份**；③ 上线串号检测：抽样对比缓存值里的 tenant 与请求上下文 tenant，不一致即告警+失效。复盘要点：越权事故必须先回答"还有多少 key 存在同样问题"，做全 key 前缀审计。

```python
# key 设计层修复：把租户维度做成构造器的强制参数
def ck(tenant: str, *parts: str) -> str:
    assert tenant, "tenant 不可为空（编译期性质的强约束）"
    return "t:" + tenant + ":" + ":".join(parts)

# 事故前后对比
VULN_KEY = f"dashboard:{123}"                 # 缺租户：A/B 两租户撞 key
print("事故 key:", VULN_KEY)
print("修复 key:", ck("acme", "dashboard", "123"), "|", ck("beta", "dashboard", "123"))

# 串号检测：缓存值自带身份戳，读回时校验
def cache_get(key: str, payload: dict, ctx_tenant: str) -> dict | None:
    if payload.get("tenant") != ctx_tenant:
        print("串号告警! 缓存租户", payload.get("tenant"), "≠ 上下文租户", ctx_tenant)
        return None                            # 视为未命中，强制回源
    return payload

print(cache_get(ck("acme", "d", "1"), {"tenant": "beta", "data": 1}, "acme"))
print(cache_get(ck("beta", "d", "1"), {"tenant": "beta", "data": 1}, "beta"))
```

**追问一层**:租户上下文经 async 调用链传播，为什么 contextvars 是正确载体而 threading.local 不是？
**追二层**:历史脏缓存如何做一次性清理？只删已知前缀够吗？

**背诵要点**
- 缓存 key 必须带租户维度，做成构造器强制参数而非业务自觉。
- 缓存值内嵌身份戳，读回时与上下文比对，不一致即失效回源。
- 越权复盘先做全 key 前缀审计，再谈单点修复。

**复盘追问**
- 混合部署（共享实例+独立实例）下 key 约定如何统一？提示：租户路由层与 key 构造层解耦。
- 这类串号如何在灰度阶段就暴露？提示：影子流量双租户抽样比对。
