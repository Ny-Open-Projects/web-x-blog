### Q6016 · 后台任务编排：状态机与可观测的长任务

> 难度:★★☆ | 标签:任务编排, 状态机, Celery

**问**：异步导出/批量处理这类「分钟级后台任务」，API 层怎么设计——任务状态机有哪几个合法状态与转移？为什么「pending→running→done/failed」不够用，进度上报与取消、僵尸任务回收怎么实现？

**答**：状态机升级版：`queued → started → progress → done | failed | canceled`，关键增量：① **progress 是一等状态**（带百分比/已处理数），因为分钟级任务「没进度=没信心」，用户与管理员都需要可观测；② **canceled 与 failed 分离**：用户主动取消是业务事件不是异常，清理路径不同（canceled 不告警、可半退款）；③ **终态不可逆**：done 后不能变 failed（补偿走新任务），防止状态漂移事故。取消实现：协作式取消——任务内定期检查取消标记（DB flag 或 Celery revoke + `soft_time_limit`），**取消必须幂等**（取消已达 done 的任务返回 done 而不是报错）。僵尸回收：worker 崩溃后任务卡 running——心跳字段（`heartbeat_at`）+ 回收扫描把超时 running 重置回 queued（同 A104 租约思路），重置次数上限防「永远重跑的毒任务」。

```python
# 全部标准库；demo 实现带进度/取消/租约回收的状态机
import enum, time

class St(enum.Enum):
    QUEUED = "queued"; STARTED = "started"; PROGRESS = "progress"
    DONE = "done"; FAILED = "failed"; CANCELED = "canceled"

TERMINAL = {St.DONE, St.FAILED, St.CANCELED}
LEGAL = {
    St.QUEUED: {St.STARTED, St.CANCELED},
    St.STARTED: {St.PROGRESS, St.DONE, St.FAILED, St.CANCELED},
    St.PROGRESS: {St.PROGRESS, St.DONE, St.FAILED, St.CANCELED},
}
LEGAL[St.DONE] = set(); LEGAL[St.FAILED] = set(); LEGAL[St.CANCELED] = set()

class Task:
    def __init__(self, tid):
        self.tid, self.state = tid, St.QUEUED
        self.heartbeat = time.monotonic()      # 租约心跳
        self.cancel_requested = False
        self.requeues = 0
    def transition(self, to: St):
        if self.state in TERMINAL:
            if to is St.CANCELED and self.state is St.DONE:
                return "already-done"          # 取消终态任务的幂等响应
            raise ValueError(f"终态 {self.state} 不可再转移")
        if to not in LEGAL[self.state]:
            raise ValueError(f"非法转移 {self.state}→{to}")
        self.state = to
        self.heartbeat = time.monotonic()
        return self.state
    def tick(self, done: int, total: int):
        """任务内协作式取消检查 + 进度上报，是长任务的标准内循环。"""
        if self.cancel_requested:
            self.transition(St.CANCELED)
            raise InterruptedError("canceled")
        self.transition(St.PROGRESS)
        self.heartbeat = time.monotonic()
        return done / total

def reclaim(tasks, idle_sec: float = 10):
    """僵尸回收：心跳超时的 running 任务重置回 queued（同 A104 租约思路）。"""
    now = time.monotonic()
    for t in tasks:
        if t.state in (St.STARTED, St.PROGRESS) and now - t.heartbeat > idle_sec:
            if t.requeues >= 2:
                t.transition(St.FAILED)        # 毒任务上限：防永远重跑
            else:
                t.state = St.QUEUED; t.requeues += 1

if __name__ == "__main__":
    t = Task("job-1")
    t.transition(St.STARTED)
    for i in range(3):
        t.tick(i, 3)
    t.transition(St.DONE)
    assert t.transition(St.CANCELED) == "already-done"   # 取消 done 任务幂等 ✅
    print("done 任务被取消:", "already-done（幂等）")
    z = Task("job-2"); z.state = St.PROGRESS; z.heartbeat -= 999   # 模拟 worker 崩溃
    reclaim([z])
    assert z.state is St.QUEUED and z.requeues == 1
    print("僵尸任务回收 → queued，重试次数:", z.requeues)
```

**追问**：1) 为什么不用 Celery 自带状态就够了？——Celery 的 PENDING/STARTED/SUCCESS/FAILURE 缺 progress 粒度与租约语义：worker 崩溃后任务在 Celery 里永远 PENDING/STARTED，僵尸回收要自己加心跳字段；自带状态是骨架不是方案。2) 进度上报的存储选型？——高频 tick 写 Redis（TTL 短键），低频里程碑写 DB；两者分开，避免 DB 被进度写打满。3) API 怎么暴露长任务？——`202 Accepted` + 任务资源 URL（`/jobs/{id}`）轮询，或 SSE 推进度；`202` 语义（已受理未完成）比 `200` 诚实。

## 背诵要点
1. 状态机：queued→started→progress→done/failed/canceled；progress 一等公民、canceled 与 failed 分离、终态不可逆。
2. 取消是协作式的：任务内 tick 检查 + 取消 done 任务返回 already-done（幂等）。
3. 僵尸回收 = 心跳租约 + 超时重置 queued + 重跑次数上限（毒任务防重复执行风暴）。

## 复盘追问
