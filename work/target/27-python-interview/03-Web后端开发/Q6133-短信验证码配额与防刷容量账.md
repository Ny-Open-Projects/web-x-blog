### Q6133 · 短信验证码发送的配额与防刷容量账

难度：P6 | 标签：验证码、防刷、限流、容量规划

**问**：登录页的"发送验证码"接口被刷：一晚上发出 40 万条短信，账单直接五位数。请设计一套分层的验证码防刷方案：各层的限流键、配额怎么定？验证码本身的存储与校验有哪些安全参数？被刷之后的账单止血怎么做？

**答**：

**结论**：防刷是分层漏斗，配额从宽到紧：(1) 人机层——图形验证码/行为验证前置，拦截脚本流量；(2) 号码维度——同一手机号 1 条/分钟、5 条/天，防骚扰与轰炸；(3) IP/设备维度——同 IP 20 条/天（移动网络 NAT 下放宽），防脚本批量；(4) 全局维度——全站每日总配额（如 10 万条）+ 实时消耗告警，防"慢速分散攻击"绕过前两层；(5) 业务维度——未注册号码/异常归属（虚拟号段）策略。验证码安全参数：6 位数字、有效期 5 分钟、单验证码校验失败 5 次即作废（防枚举）、校验成功立即失效、存储带 TTL（Redis `SET key value EX 300`）。成本账：短信单价约 0.04-0.05 元，40 万条即 1.6-2 万元——所以全局配额与告警阈值要按"财务可承受"反推，而不是按技术容量。

**取舍**：限流存储用 Redis 计数器（INCR+EXPIRE 或滑动窗口 Lua），本地限流在多 worker 下会被放大 N 倍。验证码服务商侧再要一层：余额告警、按模板限频、夜间发送阈值。止血动作顺序：先关接口（feature flag）→ 复盘消耗构成 → 补配额层 → 供应商侧拉黑异常号段 → 追回部分成本（与供应商谈刷量减免）。

**实战**：示例给出 Redis 计数限流器的最小实现与各层配额常量；把"发送成功率、拦截率、账单日耗"做成日报指标，刷量事件应能在 1 小时内由全局告警发现。

```python
# 依赖基线：redis>=5 客户端；缺库时降级为内存版（单进程演示）
import time, random

try:
    import redis
    r = redis.Redis(host="localhost", port=6379, decode_responses=True)
    r.ping()
    BACKEND = "redis"
except Exception:
    r = None
    BACKEND = "memory"

_mem = {}

def hit(key, limit, window):
    """滑动计数限流：window 秒内最多 limit 次。"""
    now = int(time.time())
    if BACKEND == "redis":
        pipe = r.pipeline()
        pipe.incr(key)
        pipe.expire(key, window)
        count = pipe.execute()[0]
    else:
        rec = [t for t in _mem.get(key, []) if now - t < window]
        rec.append(now)
        _mem[key] = rec
        count = len(rec)
    return count <= limit, count

QUOTA_PHONE_MIN, QUOTA_PHONE_DAY = 1, 5
QUOTA_IP_DAY = 20
QUOTA_GLOBAL_DAY = 100_000

def send_sms(phone: str, ip: str) -> bool:
    today = time.strftime("%Y%m%d%H")            # 演示用小时键，实际按天
    for key, limit in [
        (f"sms:phone:{phone}:{today}", QUOTA_PHONE_MIN),
        (f"sms:ip:{ip}:{today}", QUOTA_IP_DAY),
        (f"sms:global:{today}", QUOTA_GLOBAL_DAY),
    ]:
        ok, cnt = hit(key, limit, 3600)
        if not ok:
            print(f"blocked at {key} (count={cnt})")
            return False
    code = f"{random.randint(0, 999999):06d}"
    # 存储：TTL 300s + 校验失败计数在另一 key（略）
    print(f"sent code {code} to {phone}")
    return True

if __name__ == "__main__":
    for i in range(8):
        send_sms("13800000000", "1.2.3.4")       # 第 2 次起被号码维度拦截
```

**追问 1**：为什么验证码要"失败 5 次作废"？
答：6 位码空间 100 万，5 分钟窗口内不设失败上限时攻击者可高频提交枚举（接口 QPS 1000 时 5 分钟 30 万次尝试，命中率可观）；作废把枚举收益压到零，代价是用户体验（输错重发），5 次是平衡值。

**追问 2**：攻击者分散在秒拨 IP 池怎么办？
答：IP 维度失效后靠"全局配额 + 号段/归属策略 + 行为特征"（同 UA 指纹、发送间隔方差、注册→验证转化率）；本质是把对抗从"键限流"升级到"统计异常检测"。

**追问 3**：语音验证码（打电话念码）要不要同样限？
答：要，且单价更高（约 0.1 元/通），配额应独立且更紧；攻击者会在短信被限后切语音通道，通道间共享"号码日配额"这个总闸。

## 背诵要点

- 分层漏斗：人机验证 → 号码（1/分、5/天）→ IP（20/天）→ 全局总配额（财务反推）→ 号段策略。
- 验证码参数：6 位、5 分钟 TTL、失败 5 次作废、成功即失效；Redis INCR+EXPIRE 计数限流。
- 止血顺序：关接口→复盘消耗→补配额→供应商拉黑；全局日耗告警必须做到 1 小时内发现。
