### Q6056 · 静态文件伺服的成本与 CDN/nginx 卸载

> 难度:★★★ | 标签:静态文件, sendfile, X-Accel-Redirect, CDN, 成本工程

**问**：一个 8MB 的下载文件走 Python worker 伺服，高峰期 worker 全忙、带宽打满。Python 发静态文件的真实成本是什么？os.sendfile 省了哪次拷贝？"nginx 卸载/X-Accel-Redirect/预签名 URL"三种卸载姿势怎么选？

**答**：成本三层：a) **worker 占用**：线程/协程被 8MB×若干秒的传输钉住，吞吐按"并发槽 × 带宽"塌缩——Python 进程的下载 QPS 上限低得惊人；b) **拷贝税**：普通 read+send 路径是 磁盘→内核缓冲→用户态→socket 缓冲→网卡 四跳两次用户态拷贝，`os.sendfile()` 在内核态直连文件到 socket，用户态零拷贝零调度，实测 8MB 一跳 8ms 级；c) **带宽竞争**：静态大流量和动态 API 抢同一容器网络配额，动静分离不是洁癖是容量账。卸载三式：**nginx 直接伺服**（root/alias 静态目录，sendfile on）最简单，适合本地静态资源；**X-Accel-Redirect**（Python 只做鉴权/计数，响应头 `X-Accel-Redirect: /protected/xxx`，nginx 接管文件传输）适合"要鉴权的私有文件"，Python 成本降为一次轻响应；**预签名 URL**（对象存储直签，302 给客户端直连 OSS/S3）适合云上大文件，Python 彻底不碰流量，但要管好签名有效期与防盗链。选型顺序一句话：**能直连存储就直连，要鉴权用 X-Accel，纯公开小静态才让 Python 碰**——Flask/FastAPI 的 StaticFiles 只该出现在开发环境。

```python
# file: code/03_Web后端开发/q6056_static_cost.py
import os, socket, tempfile, threading

path = tempfile.mkstemp(suffix=".bin")[1]
with open(path, "wb") as f:
    f.write(os.urandom(8 * 1024 * 1024))     # 8MB 文件

a, b = socket.socketpair()
received = [0]
def drain():                                  # 接收端持续排空, 否则缓冲满会阻塞发送
    while True:
        data = a.recv(1024 * 1024)
        if not data:
            break
        received[0] += len(data)
threading.Thread(target=drain, daemon=True).start()

sent = 0
with open(path, "rb") as f:
    t0 = os.times()
    try:
        while True:
            n = os.sendfile(b.fileno(), f.fileno(), sent, 1024 * 1024)  # 内核态直传
            if n == 0:
                break
            sent += n
    except OSError:                           # 平台不支持时降级: 用户态分块拷贝
        while True:
            chunk = f.read(1024 * 1024)
            if not chunk: break
            b.sendall(chunk); sent += len(chunk)
b.shutdown(socket.SHUT_WR)
print(f"sendfile 传 {sent/1024/1024:.0f}MB / 对端收 {received[0]/1024/1024:.0f}MB: 数据不进用户态")
os.unlink(path)

print("成本: worker 被传输钉住 + 用户态拷贝税 + 带宽竞争 -> 动静分离是容量账")
print("卸载: nginx root(公开) / X-Accel-Redirect(鉴权) / 预签名URL 302(云存储大文件)")
```

**追问**：1) X-Accel-Redirect 的响应里 Python 还该带什么头？——鉴权后由 nginx 补 Content-Type/Content-Disposition；Python 侧注意 body 必须为空、`X-Accel-Buffering` 等头影响 nginx 行为；另外 nginx 的 `internal` location 是安全边界，必须配，否则外部可直接访问 /protected。2) sendfile 在 TLS 终结在应用层时还有效吗？——无效：TLS 记录层要加密数据必然进用户态，sendfile 只对"明文直发 socket"有效；HTTPS 卸载给 nginx/CDN 后，回源的 TLS 流量才可能享受零拷贝路径。3) 对象存储直签 URL 的有效期怎么定？——按"最慢客户端完成下载的时间"上浮（默认 15-60 分钟），配合短效签名 + 服务端记录签发做审计；过期即 403 由存储侧兜底，不占 Python 资源。

## 背诵要点
- Python 伺服静态文件三重税：worker 被传输钉住、用户态拷贝（read+send 四跳）、与动态 API 抢带宽；sendfile 内核态直传用户态零拷贝。
- 卸载三式：nginx root（公开）、X-Accel-Redirect（鉴权私有文件，Python 只发头）、预签名 URL 302（云存储大文件）。
- TLS 终结在应用层时 sendfile 失效（必须加密进用户态）；X-Accel 目标 location 必须 internal。
