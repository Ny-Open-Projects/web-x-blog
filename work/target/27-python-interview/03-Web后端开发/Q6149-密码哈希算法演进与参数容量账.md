### Q6149 · 密码哈希算法演进与参数容量账

难度：P6 ｜ 标签：密码哈希、PBKDF2、bcrypt、Argon2、成本工程

**问**：老系统用 `hashlib.sha256(password + salt)` 存密码，安全审计要求整改。为什么普通 SHA-256 不能存密码？PBKDF2/bcrypt/Argon2 的演进逻辑与参数怎么定？哈希耗时（如 250ms）与登录接口的容量账如何平衡？

**答**：
结论：SHA-256 每秒可算数十亿次（GPU），泄露库后弱口令秒破；密码哈希必须是**故意慢 + 盐 + 可调成本**的 KDF。演进线：PBKDF2-HMAC（纯 CPU 迭代，FIPS 合规、抗 GPU 能力弱）→ bcrypt（基于 Blowfish、自带盐与 cost 因子、抗 GPU 更好但内存占用固定）→ Argon2id（内存硬函数，GPU/ASIC 并行破解性价比被内存量拉垮，2015 密码哈希竞赛冠军，当前首选）。Python 标准库只内置 PBKDF2（`hashlib.pbkdf2_hmac`，与 Q5097 的 FIPS 语境衔接）；bcrypt/Argon2 需第三方（`bcrypt`、`argon2-cffi`），缺库降级路径 = PBKDF2 + 足够迭代（OWASP 当前建议 ≥600,000 次 SHA-256 迭代）。

参数与容量账：单次哈希 250ms 是"登录请求"的合理预算（用户感知 0.3~0.5s 可接受），但这直接吃掉吞吐——单 worker 每秒最多 ~4 次登录，CPU limit 1 核 4 worker 也只有 ~16 登录 QPS，**登录接口要按"哈希耗时×峰值登录 QPS"单独定容**，配限流防刷（与 Q6133 短信配额同构）。参数上调（cost+1 ≈ 耗时×2）必须走灰度，且存哈希时带参数头（bcrypt `$2b$12$...` / Argon2 的 PHC 字符串）以便逐用户升级。

实战：迁移路径——新密码直接 Argon2id（memory=64MB, iterations=3, parallelism 可按容器 CPU 定）；存量 SHA-256 哈希无法"解出"重哈希，用**下次登录时透明重哈希**（登录成功即用新算法重存）+ 时间表强制过期。验证基准：上线前对本机跑一次 `pbkdf2_hmac` 计时，把"目标 250ms"换算成迭代数并写进配置评审。

```python
import hashlib
import os
import time
import secrets

def pbkdf2_hash(password: str, iterations: int = 600_000) -> str:
    salt = secrets.token_bytes(16)
    dk = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, iterations)
    return f"pbkdf2_sha256${iterations}${salt.hex()}${dk.hex()}"

def pbkdf2_verify(password: str, stored: str, iterations_hint: int = 600_000) -> bool:
    scheme, iters, salt_hex, dk_hex = stored.split("$")
    dk = hashlib.pbkdf2_hmac("sha256", password.encode(),
                             bytes.fromhex(salt_hex), int(iters))
    return secrets.compare_digest(dk.hex(), dk_hex)   # 恒时比较

t0 = time.perf_counter()
h = pbkdf2_hash("correct-horse-battery")
dt = (time.perf_counter() - t0) * 1000
print(f"hash cost: {dt:.0f}ms (target ~250ms)")
print("stored format:", h[:40] + "...")               # 参数内嵌，可逐用户升级
print("verify ok:", pbkdf2_verify("correct-horse-battery", h))
print("verify bad:", pbkdf2_verify("wrong", h))

# 容量账：登录 QPS 上限 = 并发槽 / 单次耗时
workers, cpu_per_worker = 4, 1
qps_cap = workers * cpu_per_worker / (dt / 1000)
print(f"login QPS ceiling ≈ {qps_cap:.0f} (4 workers @ {dt:.0f}ms/hash)")

# 第三方库（缺库降级已在上方用标准库 PBKDF2 覆盖）
try:
    import argon2                                     # argon2-cffi 基线 23.x
    ph = argon2.PasswordHasher(time_cost=3, memory_cost=64 * 1024)
    ah = ph.hash("correct-horse-battery")
    t0 = time.perf_counter()
    ph.verify(ah, "correct-horse-battery")
    print(f"argon2id verify: {(time.perf_counter()-t0)*1000:.0f}ms, needs_rehash:",
          ph.check_needs_rehash(ah))
except ImportError:
    print("argon2-cffi 未安装：标准库 PBKDF2 为降级基线")

# 反例（审计红线）：裸 SHA-256 + 固定盐
t0 = time.perf_counter()
bad = hashlib.sha256(b"password123" + b"fixedsalt").hexdigest()
print(f"sha256 cost: {(time.perf_counter()-t0)*1000:.3f}ms  <- billions of guesses/sec")
```

**追问一**：为什么内存硬（Argon2）能对抗 GPU 而迭代型不能？——GPU 算力强但显存带宽与容量受限，Argon2 填充 64MB 内存使单核心破解内存受限，并行度随内存成线性成本；bcrypt 介于两者（4KB Blowfish 状态），PBKDF2 无内存约束最弱。

**追问二**：恒时比较在什么位置还会被忽略？——除 verify 外，"重置 token 比对、API key 查找（应先做哈希再按主键查，而不是按 key 明文查询）"同样是时序面；明文 key 直接查 DB 既有时序差异又有日志泄露风险。

**追问三**：登录接口按哈希耗时定容后，"忘记密码重置"接口要不要同样的预算？——重置链接的 token 验证若也走 KDF 则同预算；生产做法是 reset token 用一次性随机 token（`secrets` + 短 TTL 存储），不进 KDF，只有新密码入库时才付一次哈希成本。

## 背诵要点
- 普通哈希秒级十亿次猜测 = 等于明文；密码 KDF 必须"慢 + 盐 + 可调成本"，标准库兜底 `pbkdf2_hmac`（SHA-256 ≥600k 迭代）。
- 演进：PBKDF2（FIPS 合规）→ bcrypt → Argon2id（内存硬，首选）；哈希串内嵌参数头支持逐用户升级。
- 容量账：登录 QPS ≈ worker 数 / 单次哈希秒数；250ms 哈希 4 worker ≈ 16 QPS，必须配限流与灰度调参。

## 复盘追问
