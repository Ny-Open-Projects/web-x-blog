### Q6135 · SSR 动态渲染、缓存化与预渲染的成本账

难度：P6 | 标签：SSR、页面缓存、预渲染、成本工程

**问**：营销页用 Python 模板动态渲染，每请求都查库+渲染，QPS 300 时要 8 个 worker。同样内容 95% 的请求返回完全相同 HTML。请算一笔账：动态渲染、页面级缓存（整页缓存）、构建期预渲染三种形态的成本差异与各自的失效策略如何设计？

**答**：

**结论**：成本模型（单页 P95 渲染 30ms、CPU 成本 ~10ms 核时）：动态 SSR 每请求都要模板引擎+DB 查询，成本线性于 QPS，300 QPS ≈ 3 核常态占用；整页缓存（页面 key=路径+关键查询参数，存 Redis/内存，TTL 60s）把"查库+渲染"降为"取缓存"，单请求成本降一个数量级，回源率 = 1/(TTL×QPS)（低流量页反而回源率高）；构建期预渲染（SSG，部署时生成 HTML 推到 CDN）把运行时成本压到零，请求只走静态分发，CDN 带宽成本比 worker 成本低两个数量级。失效策略差异：SSR 缓存用"事件失效"（内容变更主动 purge key）或短 TTL 混合；SSG 用"重新构建+原子切换"，变更延迟 = 构建时长（分钟级），不适合秒级时效内容。

**取舍**：选型的三个维度——内容时效（秒级→SSR、分钟级→整页缓存、小时级以上→SSG）、个性化占比（每用户不同→只能片段缓存）、变更频率与构建时长比（高频变更+长构建→SSG 不划算）。混合方案 ISR（增量静态再生）：SSG + 过期后台重渲染，兼得两者，但 Python 生态要自己实现"过期标记 + 后台任务重建"。

**实战**：账要算给业务方看：300 QPS 营销页从动态 SSR 改 SSG，8 worker 降到 1 worker + CDN，月成本差 ≈ 7 核×24h×30d；同时把"页面指纹"（内容 hash）纳入发布校验，防止预渲染出旧数据。

```python
import time, hashlib, functools

def render_dynamic(page_id: str) -> str:
    time.sleep(0.01)                       # 模拟 DB+模板 10ms
    return f"<html>{page_id}@{time.time()}</html>"

# 1) 整页缓存：TTL + 事件失效双通道
class PageCache:
    def __init__(self, ttl=60):
        self.store, self.ttl = {}, ttl
    def get(self, key):
        item = self.store.get(key)
        if item and item[0] > time.time():
            return item[1], "hit"
        return None, "miss"
    def put(self, key, html):
        self.store[key] = (time.time() + self.ttl, html)
    def purge(self, key):
        self.store.pop(key, None)

cache = PageCache(ttl=2)

def render_cached(page_id):
    html, status = cache.get(page_id)
    if status == "hit":
        return html, status
    html = render_dynamic(page_id)
    cache.put(page_id, html)
    return html, status

for _ in range(3):
    _, st = render_cached("home")
    print("cache status ->", st)

# 2) 预渲染：构建期生成 + 内容指纹校验
pages = {pid: render_dynamic(pid) for pid in ["home", "pricing", "about"]}
fingerprints = {pid: hashlib.sha256(h.encode()).hexdigest()[:12]
                for pid, h in pages.items()}
print("预渲染产物指纹 ->", fingerprints)

# 3) 回源率账：TTL 内回源率 = 1/(TTL * QPS)
qps = 300
print(f"TTL=60s QPS=300 时回源率 ≈ {1/(60*qps)*100:.3f}%")
print(f"SSG 运行时 worker 成本 = 0；CDN 承接全部 {qps} QPS")
```

**追问 1**：整页缓存的 key 设计有哪些坑？
答：必须含所有影响输出的维度（路径、语言、设备、A/B 分桶、登录态粗分）；漏一个维度就出现串页事故（把用户 A 的个性化内容给 B）——这也是"个性化内容禁整页缓存"的红线由来。

**追问 2**：ISR 的后台重渲染如何防缓存击穿？
答：过期后第一个请求触发重建但**先返回旧值**（stale-while-revalidate 语义），重建完成原子替换；否则过期瞬间并发回源打爆源站——与缓存雪崩同理，只是粒度是页面。

**追问 3**：CDN 缓存与源站整页缓存怎么分工？
答：CDN 承接公共 GET 页（Cache-Control s-maxage + 主动 purge API），源站缓存兜底非 CDN 可缓存的维度（Cookie 差异）；命中顺序上让 CDN 先挡，源站缓存只接 CDN 回源与长尾。

## 背诵要点

- 成本阶梯：动态 SSR 线性于 QPS → 整页缓存降一个量级（回源率=1/(TTL×QPS)）→ SSG 运行时成本归零走 CDN。
- 选型三维度：内容时效、个性化占比、变更频率×构建时长；个性化内容禁整页缓存（串页事故）。
- ISR/SWR 语义：过期先返回旧值再后台重建，防击穿；页面指纹纳入发布校验。
