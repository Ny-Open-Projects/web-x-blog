### Q6054 · WebSocket/SSE 长连接的每实例容量账

> 难度:★★★★ | 标签:WebSocket, SSE, 长连接, 容量规划, asyncio

**问**：把一个轮询接口改成 WebSocket 推送，预估 10 万在线。单实例能扛多少连接？这笔容量账有哪几项？连接对象怎么写才不虚胖？

**答**：长连接容量账是四项取最小：a) **fd**：每连接 1 个 fd（WebSocket 升级后仍是 TCP），受 RLIMIT_NOFILE 与反代上限约束；b) **内存**：每连接 = socket 缓冲（内核侧各几十 KB）+ 用户态对象（连接状态、收发缓冲、task）——最小化对象（`__slots__` + 512B 级缓冲）实测 1 万条仅约 6MB 业务内存，但加协议栈/SSL buffer/每连接 task 后，综合按 10-50KB/连接估，2GB 容器保守规划 1-5 万；c) **CPU**：事件循环单核，心跳与推送包的处理都在一条循环上——10 万连接 × 每秒一次心跳 = 单核 10 万事件/秒起，就是 Q5537 的心跳风暴题，扇出广播是更大的 CPU 项；d) **架构上限**：实例间"谁在线"的扇出需要外部注册表（Redis pub/sub），单实例广播出不了实例边界。优化顺序：先压缩每连接对象（slots、复用缓冲、避免每连接独立大 task），再压心跳（多连接合并定时器、心跳间隔协商），最后才横向扩。另外 SSE 比 WebSocket 便宜得多（纯 HTTP 半双工、无协议帧解析），单向推送场景优先 SSE。

```python
# file: code/03_Web后端开发/q6054_ws_capacity.py
import tracemalloc

class Conn:
    __slots__ = ("sid", "buf")       # slots: 砍掉 per-instance dict
    def __init__(self, sid):
        self.sid = sid
        self.buf = bytearray(512)    # 最小收发缓冲

tracemalloc.start()
conns = [Conn(i) for i in range(10_000)]
cur, peak = tracemalloc.get_traced_memory()
print(f"1 万条最小化连接对象 ≈ {cur/1024/1024:.1f}MB (仅业务侧)")
print("综合口径: + socket 缓冲/task/SSL buffer -> 按 10-50KB/连接估")
print(f"2GB 容器保守规划: {int(2*1024*1024/50)} ~ {int(2*1024*1024/10)} 条连接")

# 容量账四项取最小
print("账面: min(fd 上限, 内存/每连接, 心跳+推送 CPU, 扇出架构)")
print("CPU 项示例: 10万连接 × 1次/秒心跳 = 单核 10w 事件/秒起, 广播扇出另计")
print("选型: 单向推送优先 SSE(纯HTTP半双工, 无帧解析); 双向才 WebSocket")
```

**追问**：1) 为什么"每连接一个 asyncio task"会成为内存与调度负担？——task+coroutine+栈帧合计数 KB 且参与事件循环调度；万级连接的正确形态是"注册表 + 少量共享任务（按需唤醒）"，每连接独立大 task（如独立心跳循环）是 Q5537 心暴风暴的根源。2) 反代层（Nginx）对长连接要配什么？——`proxy_read_timeout` 大于心跳间隔（否则被反代掐死）、`proxy_http_version 1.1` + `Connection ""`（避免连接被关闭）、WebSocket 要 Upgrade 头透传；容量账里反代连接数也要算。3) 节点扩容后长连接怎么迁移？——连接是有状态资源，扩缩容不迁移只靠重连：发布时先摘流量→广播 close（带重连提示）→ 客户端指数退避重连到新实例；这决定了"优雅停机 drain"对长连接服务的意义。

## 背诵要点
- 长连接容量 = min(fd 上限, 内存/每连接 10-50KB 综合估, 心跳+推送 CPU，扇出架构)；单实例 2GB 保守 1-5 万连接。
- 最小化每连接对象：`__slots__` + 小缓冲 + 注册表模式，避免每连接独立 task；1 万最小化连接业务内存仅约 6MB。
- 单向推送优先 SSE；反代要配 read_timeout>心跳间隔；扩缩容靠"摘流量→close→退避重连"不迁移连接。

## 复盘追问
