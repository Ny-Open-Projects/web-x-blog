### Q6131 · 文件下载接口路径穿越事故复盘

难度：P6 | 标签：路径穿越、secure_filename、权限设计、事故复盘

**问**：一个下载接口用 `open(f"/data/files/{name}")` 返回文件，渗透测试用 `..%2f..%2fetc%2fpasswd`、`....//`、绝对路径 `/etc/passwd` 三种载荷都读到了越权文件。请解释路径穿越在各层（URL 解码、拼接、open）分别怎么发生，为什么"过滤 `..`"不够，正确的工程方案是什么？

**答**：

**结论**：穿越链条分三层：网关/WAF 可能先做一次 URL 解码（`%2f`→`/`）但应用又解一次造成绕过；`os.path.join("/data/files", "/etc/passwd")` 遇到绝对路径参数会**直接丢弃前缀**（join 语义），一个参数就完成穿越；`open` 与 OS 层不认识"逻辑约束"，只认物理路径。过滤黑名单（`..`、斜杠）是打地鼠：编码变体、Windows 反斜杠、符号链接都能绕。正确方案是白名单式定位：把用户输入映射为"存储键"而不是"路径段"——用 ID 查数据库得到服务端持有的一级目录与文件名，或 `os.path.realpath` 后**强制验证前缀**（realpath 解析符号链接后的物理路径必须落在受控根目录内），再叠加下载目录与 Web 进程的系统权限隔离（专用只读用户）。

**取舍**：`realpath + startswith` 校验要小心 `startswith(base)` 的前缀巧合（`/data/files2` 匹配 `/data/files`），必须比较 `os.path.commonpath` 或加 `os.sep`；另一条路线是完全不让用户输入进路径：文件表主键 + 服务端拼接，穿透面归零。静态资源交给 Nginx/OSS 时，签名 URL 也要防止路径参数被替换（签名覆盖完整 key）。

**实战**：代码演示三个载荷在 join/realpath 下的行为与正确校验器；事故复盘时用"输入→解码→拼接→校验→打开"五段日志还原攻击路径，并补上"文件访问审计日志"（谁、何时、哪个 key）。

```python
import os

BASE = "/data/files"

# 1) 三个载荷的真实行为
payloads = ["..%2f..%2fetc%2fpasswd"   # 应用层解码后变 ../../etc/passwd
            .replace("%2f", "/"),
            "....//....//etc/passwd",  # 过滤一个 ../ 后残片重组
            "/etc/passwd"]             # 绝对路径
for p in payloads:
    joined = os.path.join(BASE, p)
    print(f"join({p!r}) -> {joined}")   # 绝对路径直接丢前缀！

# 2) 黑名单过滤被绕过：剥掉 ../ 后仍可能穿越
def naive_filter(name):
    return name.replace("../", "")      # ....// -> 过滤后重新出现 ../

print("naive_filter('....//etc/passwd') =", naive_filter("....//etc/passwd"))

# 3) 正确方案：realpath + commonpath 前缀验证
def safe_resolve(user_input):
    candidate = os.path.realpath(os.path.join(BASE, user_input))
    base = os.path.realpath(BASE)
    if os.path.commonpath([candidate, base]) != base:
        raise PermissionError("path traversal blocked")
    return candidate

for p in payloads:
    try:
        safe_resolve(p)
    except (PermissionError, ValueError) as e:
        print("blocked ->", p[:20], type(e).__name__)
```

**追问 1**：符号链接如何绕过"目录内白名单"？如何防？
答：受控目录里被写入一个指向 /etc 的软链接（或上传压缩包带 symlink entry），join 在目录内、realpath 后跳出；防法就是 realpath 后验证 + 解压时拒绝 symlink entry（zipfile 的 extractall 要自检）。

**追问 2**：为什么说"用户输入只进数据库不进路径"是更强设计？边界在哪？
答：文件元数据（存储 key）由服务端生成（uuid），用户只提交文件 ID，路径构造全程服务端；边界是批量下载/自定义导出名仍需要名字输入——那些只影响 Content-Disposition，不进磁盘路径。

**追问 3**：网关侧还能加哪道防线？
答：WAF/网关对归一化后的 URI 做穿越检测（重复解码后匹配 `../` 模式）作为纵深防御，但不能替代应用层校验——网关与应用解码次数不一致正是绕过来源。

## 背诵要点

- 穿越三层：URL 重复解码、join 遇绝对路径丢前缀、OS 只认物理路径；黑名单过滤会被重组/编码绕过。
- 正确方案：输入映射为服务端 ID/存储键，或 realpath+commonpath 强前缀校验 + 解压拒 symlink。
- 纵深：专用只读权限用户 + 审计日志 + 网关归一化检测，缺一层就少一道防线。
