### Q6028 · CSV 导出的公式注入防护：=cmd 的教训

> 难度:★★★☆ | 标签:CSV, 注入, 安全

**问**：导出 Excel 能正常打开的 CSV 为什么是安全事件高发地？"CSV 公式注入"的攻击原理是什么——用户昵称里存个 `=HYPERLINK(...)` 会发生什么？转义策略（前缀撇号/制表符/空格）怎么选，对"合法的负数/求和数据"怎么放行？

**答**：原理：CSV 只是文本，**公式在 Excel 打开时求值**——用户控制的字段（昵称、备注、反馈文本）若以 `=`、`+`、`-`、`@`、Tab/回车开头，Excel/LibreOffice/Numbers 会把它当公式执行：`@SUM(...)` 外发数据、`HYPERLINK` 钓鱼、旧版 DDE（`=cmd|'/c ...'!A0`）甚至命令执行。受害者是**打开导出文件的人**（运营/财务），所以攻击面是"数据入库在注册环节，引爆在导出环节"的延迟注入，与 XSS 同构。转义策略：1) **前缀单引号 `'`**——Excel 把 `'=SUM(1)'` 显示为文本 `=SUM(1)`，最通用；缺点是 LibreOffice 对前导 `'` 显示行为有差异、且"看起来"多了字符；2) **前缀制表符或空格**——同样破坏公式解析，但会带进字段可见空白；3) 通用做法是按前缀集合 `("=", "+", "-", "@", "\t", "\r")` 触发转义，**对合法数值开白名单**：整串匹配 `-?\d+(\.\d+)?` 的放行（负数与科学计数是真实业务数据），其余命中前缀即转义。另外三条配套：导出统一 `\r\n` + `utf-8-sig` BOM（Q2924）；字段内换行先压平（防行结构破坏与表格劫持）；高危导出（财务/运营全量）考虑直接产出 xlsx 并强制单元格类型为文本，从根上不进公式引擎。

```python
# file: code/03_Web后端开发/q6028_csv_injection.py
import csv, io, re

RISKY_PREFIX = ("=", "+", "-", "@", "\t", "\r")
NUMBERISH = re.compile(r"^-?\d+(\.\d+)?([eE][+-]?\d+)?$")   # 合法数值白名单

def sanitize_cell(value: str) -> str:
    v = value.replace("\r", " ").replace("\n", " ")         # 压平换行
    if v.startswith(RISKY_PREFIX) and not NUMBERISH.match(v):
        return "'" + v           # 前缀撇号: Excel 按文本处理,不进公式引擎
    return v

def export(rows) -> str:
    buf = io.StringIO()
    writer = csv.writer(buf, lineterminator="\r\n")
    for row in rows:
        writer.writerow([sanitize_cell(str(c)) for c in row])
    return buf.getvalue()

rows = [
    ["name", "note", "delta"],
    ["ann", '=HYPERLINK("http://evil", "点我领奖")', "-12.5"],
    ["bob", "@SUM(A1:A9)", "+8613800138000"],
    ["carl", "正常文本", "3.2e-5"],
]
out = export(rows)
print(out)

back = list(csv.reader(io.StringIO(out)))
print("公式字段已转义:", back[1][1].startswith("'="))
print("负数放行:", back[1][2] == "-12.5", "| 电话被转义(含+非纯数值):", back[2][2].startswith("'+"))
print("正常数值不动:", back[3][2] == "3.2e-5")
```

**追问**：1) 为什么"+"和"-"也要转义？——Excel 把 `+SUM(...)`、`-1+cmd` 同样当公式求值；但负数/带区号电话是真实数据，所以白名单先行、转义兜底。2) 前缀撇号在 LibreOffice/Numbers 的兼容性问题？——LibreOffice 显示时会吞掉撇号（行为恰好正确），Numbers 对 CSV 的公式求值策略更保守；跨端一致性最好用 xlsx 显式文本类型。3) 服务端转义 vs 客户端打开时防御？——必须在服务端转义（出口唯一可信点），"让用户开公式确认"是控件不是防线；同时录入侧限制首字符是纵深而非主防线（存量脏数据仍会导出）。

## 背诵要点
1. CSV 公式注入 = 延迟注入：入库存文本、Excel 打开才求值，受害者是下载者。
2. 危险前缀 `= + - @ \t \r` 触发转义；合法数值白名单（负数/科学计数）先放行。
3. 配套：\r\n + utf-8-sig（Q2924）、字段内换行压平；高危导出直接 xlsx 文本单元格。

## 复盘追问
