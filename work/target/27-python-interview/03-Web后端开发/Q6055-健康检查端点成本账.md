### Q6055 · 健康检查端点（liveness/readiness）的成本工程

> 难度:★★★ | 标签:k8s 探针, liveness, readiness, 成本工程, 事故复盘

**问**：readiness 探针里直查了一次数据库，50 个实例上线后 DB 监控多出 14 万次/天的"神秘查询"，DBA 找上门。探针的成本模型是什么？liveness 和 readiness 的职责该怎么分？探针设计有哪些红线？

**答**：成本账：k8s 默认每实例每秒级探测，50 实例 × 2 类探针 × 86400s/周期——readiness 里每一次"真查 DB"都是恒定负载，且故障时会**放大**：DB 抖动 → 全实例 readiness 连查 → 雪上加霜。职责分界：**liveness 只回答"进程活着"**——读内存标志位，零依赖零 IO，挂了重启进程；**readiness 回答"能不能接流量"**——允许查依赖，但结果必须缓存（1-5s TTL）或用"本地状态位 + 后台探活协程"模式：真正的依赖检查在后台任务里周期跑，探针端点只读结果，探针本身永远便宜。红线清单：a) 探针里不做认证（探针走不到 Cookie/Token）；b) 不做重逻辑（不初始化连接池、不跑迁移）；c) 不复用业务路径（超时预算独立，业务 5s、探针 1s）；d) liveness 检查依赖会自杀（依赖抖动→全实例被重启→真宕机）；e) 启动期用 startupProbe 托底，避免慢启动被 liveness 误杀。成本敏感的形态：健康信息也可以从 /metrics 端口顺带暴露一个 gauge，让抓取端合并判断，进一步省专用端点。

```python
# file: code/03_Web后端开发/q6055_probes.py
import threading, time

calls = {"liveness": 0, "readiness": 0, "db": 0}

def liveness():
    calls["liveness"] += 1
    return 200                       # 只读内存标志: 零依赖, 零 IO

# 后台探活协程: 真正的依赖检查, 周期 5s
_ready = {"db": False}
def background_probe():
    while True:
        calls["db"] += 1             # 每 5s 一次, 不是每探针一次
        _ready["db"] = True          # 真查 DB(此处模拟成功)
        time.sleep(5)

def readiness():
    calls["readiness"] += 1
    return 200 if _ready["db"] else 503   # 只读本地状态位, 恒定便宜

threading.Thread(target=background_probe, daemon=True).start()

# 成本账: k8s 探针频率 × 实例数 vs 后台探活频率
instances, probes_per_min = 50, 2
print(f"反例: readiness 直查 DB -> {instances * probes_per_min * 60 * 24} 次/天 打在 DB")
print(f"正解: 后台探活 5s 一次 -> {instances * 12 * 24} 次/天, 且探针端点零依赖")
print("红线: liveness 不查依赖(防自杀); 探针无认证/无重逻辑/独立超时; startupProbe 托慢启动")
```

**追问**：1) readiness 返回 503 后流量怎么走？——Service Endpoints 摘除该 Pod，流量分到其余实例；所以 readiness 的判断必须是"实例级可服务性"，短暂依赖抖动配合缓存 TTL 能防抖动式摘除风暴。2) 为什么 liveness 误杀比不配更糟？——依赖抖动 → 全实例 liveness 失败 → kubelet 集体重启 → 服务真宕机；liveness 只该检查"进程死锁/事件循环卡死"，实践中常用"心跳时间戳超龄"判断而非外部依赖。3) 探针超时和业务超时的关系？——独立且更短（1-2s）：探针挂住会占 kubelet 侧资源并拖慢故障感知；绝不复用业务 client 的默认超时。

## 背诵要点
- 成本账：探针频率×实例数×24h；readiness 直查 DB 50 实例 = 14 万次/天，故障时还放大雪崩。
- 分工：liveness 只读内存标志零依赖；readiness 读本地状态位，真依赖检查放后台探活（5s 级）+ 缓存。
- 红线：探针无认证、无重逻辑、独立短超时；liveness 查依赖=自杀；startupProbe 托慢启动。
