### Q6106 · 单请求成本拆解（FinOps 视角）

> 难度:★★★★☆ | 标签:成本工程, FinOps, 容量

**问**:"每个请求到底花多少钱？"——如何把云账单拆到单请求粒度并找到优化杠杆？

**答**:结论：单请求成本 = 该实例小时价 × 实例数 ÷ 期间请求总数，再叠加按量计费的旁路（出网流量、日志存储、DB IOPS、第三方调用）。工程做法分四步：① 归集——把账单按资源打标（service/env 标签体系，FinOps 的地基）；② 分摊——CPU/内存类按请求占比分摊，流量/存储类按直接归因；③ 建立"单位经济"指标——每千次请求成本（CPK）随版本跟踪；④ 找杠杆——排序取 top：序列化/压缩等 CPU 段（Q6076/Q6094）、出网流量（CDN 卸载 Q6056）、日志量（Q6047 采样）、下游调用次数（合并/N+1）。取舍：不是所有成本都要拆到请求级——固定成本（控制面、监控）按预算封顶即可，拆解粒度只到能指导决策为止，否则度量本身成为成本。实测锚点：QPS 翻倍但 CPK 下降 20%，才是健康的扩容。

```python
# 单请求成本模型：固定实例成本 + 按量旁路
def cost_per_1k(inst_price_h, inst_count, req_month, egress_gb=0, egress_usd=0.09,
                log_gb=0, log_usd=0.5):
    fix = inst_price_h * inst_count * 24 * 30                       # 月实例成本
    var = egress_gb * egress_usd + log_gb * log_usd
    return (fix + var) / (req_month / 1000)

base = cost_per_1k(0.12, 8, 300e6, egress_gb=2000, log_gb=400)
opt = cost_per_1k(0.12, 6, 300e6, egress_gb=600, log_gb=80)          # CDN 卸载 + 日志采样
print(f"当前每千次请求 ${base*1000:.2f} 优化后 ${opt*1000:.2f}（省 {(1-opt/base)*100:.0f}%）")

# 杠杆优先级：按可归因旁路排序
levers = [
    ("出网流量→CDN 卸载", 2000 * 0.09),
    ("日志全量→采样", 400 * 0.5),
    ("CPU 段→中间件/压缩", 0.12 * 2 * 24 * 30 * 0.25),
]
for name, usd_month in sorted(levers, key=lambda x: -x[1]):
    print(f"{name}: ≈${usd_month:.0f}/月")
```

**追问一层**:实例成本按 CPU 时间分摊与按请求数均摊，什么场景差异巨大？提示：长尾重请求 vs 均匀流量。
**追二维**:CPK 指标如何接入发布流程（防止"功能上线、成本翻倍"）？提示：压测口径 + 成本回归门禁。

**背诵要点**
- 单请求成本=实例价×实例数÷请求量+按量旁路；打标归集是地基。
- 单位经济用 CPK 跟踪；优化杠杆按金额排序：流量、日志、CPU。
- 拆解粒度到能指导决策为止，度量本身别变成成本。

**复盘追问**
- QPS 涨 3 倍、账单涨 5 倍，怎么定位非线性来源？提示：旁路项与序列化/下游放大（Q6022）。
- 固定成本项的治理与请求级治理为什么必须分开？提示：预算封顶 vs 单位经济两条线。
