### Q6064 · 对象存储预签名直传的成本账与卸载路径

> 难度:★★★☆ | 标签:成本工程, 对象存储, 预签名, 上传卸载

**问**：客户端上传 100MB 文件走"API 服务器中转"，带宽、内存、延迟三头吃亏（对照 Q6051 OOM）。预签名直传的成本账怎么算？服务端流程（签名→回调→校验）怎么设计才不被绕过？直传模式下恶意文件怎么拦？

**答**：中转模式的账：100MB 文件 × 1000 并发上传 = API 带宽 100GB 级瞬时需求（与下载流量抢池子）、每请求占 worker 一次 body 缓冲（Q6051 的 OOM 源头）、上传时间全程占用 worker 并发槽（Little's Law 的 W 被拉大，Q6063 容量直接缩水）。**预签名直传**把字节流卸载到对象存储：客户端拿签名 URL 直传 S3/OSS，API 只处理"元信息"。成本账对比：API 侧带宽/内存/并发占用 → 接近零（每请求只剩几百字节 JSON）；代价是流程从 1 步变 3 步（签名、上传、回调确认），客户端要改。防绕过四道闸：a) **签名限定**：Presigned URL 只放 PUT 指定 key（`uploads/{user_id}/{uuid}` 目录钉死，防越权覆盖他人文件）、过期时间短（5 分钟）、content-length-range 条件限制大小（AWS policy）；b) **回调确认**：直传成功后客户端调 `POST /files/{id}/complete`，服务端 HEAD 对象核对 size/etag 与申请一致、改状态机 UPLOADED→READY，未 confirm 的对象按生命周期规则清理；c) **校验后置**：直传的对象默认不可公网读（私有桶+服务端代理读），恶意文件（病毒/超大/类型伪装）在 confirm 或首次读取时用异步任务扫描+MIME 嗅探（magic bytes 不信扩展名），不合格删除并封路径；d) **下载也走预签名**（读卸载，静态文件 CDN 卸载见 Q6056 的区分是"公共静态走 CDN、私有文件走预签名"）。版本基线：boto3（s3 `generate_presigned_url`）、oss2 aliyun（`sign_url`），缺库降级提示写在卡内。

```python
# file: code/03_Web后端开发/q6064_presigned_upload.py
import hashlib, hmac, json, time, uuid

SECRET = b"demo-signing-key"

def presign(user_id, size_limit=100 * 1024 * 1024, ttl=300):
    """服务端签发上传凭证: 钉死 key 目录 + 限长 + 短 TTL"""
    file_id = uuid.uuid4().hex
    key = f"uploads/{user_id}/{file_id}"          # 目录钉死防越权覆盖
    expires = int(time.time()) + ttl
    payload = {"key": key, "method": "PUT", "max_size": size_limit, "exp": expires}
    sig = hmac.new(SECRET, json.dumps(payload, sort_keys=True).encode(),
                   hashlib.sha256).hexdigest()
    return {"url": f"https://oss.demo/{key}", "headers": {"X-Amz-Signature": sig},
            "policy": payload}

def confirm(upload_meta, obj_meta):
    """回调确认: 服务端 HEAD 核对, 状态机推进"""
    if upload_meta["key"] != obj_meta["key"]:
        return "reject", "key 不匹配"
    if int(obj_meta["size"]) > upload_meta["max_size"]:
        return "reject", "超限"
    if time.time() > upload_meta["exp"]:
        return "reject", "签名过期"
    # 异步任务: MIME 嗅探(magic bytes)+病毒扫描后才 READY; 演示直接通过
    return "ready", {"etag": obj_meta["etag"], "scan": "queued"}

# 1) 正常流程
meta = presign(user_id=42)
print("签发:", meta["policy"])
state, info = confirm(meta["policy"], {"key": meta["policy"]["key"],
                        "size": 1024 * 1024, "etag": "abc"})
print("确认:", state, info)

# 2) 越权覆盖他人文件: key 目录不匹配 -> 拒
meta2 = presign(user_id=42)
state, why = confirm(meta2["policy"], {"key": "uploads/43/hack", "size": 1, "etag": "x"})
print("越权覆盖:", state, why)

# 3) 超限: policy 的 max_size 闸
state, why = confirm(meta["policy"], {"key": meta["policy"]["key"],
                     "size": 200 * 1024 * 1024, "etag": "y"})
print("超限拦截:", state, why)

# 4) 过期签名
old = presign(user_id=42, ttl=-1)
state, why = confirm(old["policy"], {"key": old["policy"]["key"], "size": 1, "etag": "z"})
print("过期拦截:", state, why)

# 5) 成本账对照
print("中转: 100MB x 1000并发 = API 带宽/内存/并发槽全占")
print("直传: API 只剩几百字节签名+确认 JSON, W 缩回正常, 容量恢复")
print("基线: boto3 generate_presigned_url / oss2 sign_url; 未装库时按本卡 HMAC 结构自签")
```

**追问**：1) 客户端不调 confirm 直接用 URL 下载怎么办？——对象桶私有，读必须服务端签发下载 URL 且校验"对象状态=READY（扫描通过）"，未确认对象无下载路径；生命周期规则把"无 confirm 记录且超过 1 天"的对象自动清掉，堵资源泄漏。2) 直传的分片续传怎么做？——大文件用 multipart upload：服务端签发 `create_multipart_upload` 后逐分片 presign（`partNumber` 限定），客户端断网后 `list_parts` 续传，complete 时服务端聚合 etag 校验——和 Q5520 的自研分片协议对比，对象存储的 multipart 是现成方案，自研只剩"元信息管理"。3) MIME 伪装怎么识别？——信 magic bytes（`python-magic`/前几个字节）不信扩展名和 Content-Type 头；图片服务用 PIL 重编码（解耦元数据注入），视频抽帧校验；扫描不过的对象隔离到 quarantine 前缀并告警。

## 背诵要点
- 中转上传三头亏：API 带宽、worker body 内存（OOM 源）、并发槽被 W 拉大；预签名直传把字节流卸载到对象存储。
- 防绕过四闸：签名钉死 key 目录+content-length-range+短 TTL；confirm 时 HEAD 核对推进状态机；私有桶+异步扫描（magic bytes）；无 confirm 对象生命周期清理。
- 下载同样预签名（私有文件）与 CDN（公共静态）分工；大文件走 multipart 逐分片 presign 支持续传。
