### Q7585 · 长期记忆污染与遗忘策略的事故复盘

难度：P7 ｜ 标签：Agent 记忆 / 事故复盘 / 上下文工程

**问**：个人助手 Agent 运行数月后开始答非所问：它把用户某次纠正前的旧偏好当成了"事实"，还反复自我强化一个错误结论。记忆系统是怎么被污染的？怎么修？

**答**：
- **结论**：污染的三条路径：① 写入侧——把"会话中用户纠正前的话"或模型自己的总结直接固化成长期记忆（错误信息随摘要入库）；② 强化侧——检索命中会提升记忆权重（或被再次复述进上下文），错误记忆每次被引用都变"更可信"，形成自我强化回路；③ 冲突侧——新旧记忆矛盾时按时间或相似度取舍没有明确规则，旧记忆常胜出。遗忘缺失是放大器：只写不删使错误记忆永久存在。修复原则：记忆必须是"可修订的数据"而不是"追加式日志"。
- **取舍**：记忆管理三种范式的取舍：① 纯摘要滚动（简单但错误会传染所有后续摘要）；② 结构化事实库（每条记忆带来源、置信度、时间戳、版本，可修订可撤销——推荐主线）；③ 检索式不固化（每次从原始对话检索，无污染但成本高、跨会话一致性差）。置信度更新规则：用户显式纠正 > 新事实时间戳 > 隐式重复。
- **实战**：治理四件：① 记忆条目带元数据（source_turn、confidence、created_at、superseded_by），写入走"提取-校验-入库"流水线，用户纠正类语句必须产生"旧记忆失效"操作；② 检索时同主题冲突记忆只进上下文最高置信一条，并标注"可能过时"；③ 定期"记忆审计"任务：用近期对话回放检验记忆有效性，低置信且未命中的记忆降权/淘汰；④ 事故恢复：污染记忆的清除要走"影子重放"——用干净记忆库重放近期会话验证行为恢复后再上线。

```python
# 结构化记忆库：置信度更新与冲突裁决（纯标准库）
# 基线：Python 3.9+

from dataclasses import dataclass, field


@dataclass
class Memory:
    topic: str
    fact: str
    confidence: float
    created_at: int          # 时间戳序号
    superseded_by: str | None = None
    source: str = "conversation"


class MemoryStore:
    def __init__(self) -> None:
        self.items: dict[str, list[Memory]] = {}

    def write(self, m: Memory) -> None:
        self.items.setdefault(m.topic, []).append(m)

    def supersede(self, topic: str, old_fact: str, new: Memory) -> None:
        for m in self.items.get(topic, []):
            if m.fact == old_fact:
                m.superseded_by = new.fact
        self.write(new)

    def recall(self, topic: str) -> Memory | None:
        live = [m for m in self.items.get(topic, [])
                if m.superseded_by is None]
        if not live:
            return None
        return max(live, key=lambda m: (m.confidence, m.created_at))


def main() -> None:
    store = MemoryStore()
    store.write(Memory("coffee", "用户喜欢加糖", 0.6, 1))
    # 用户显式纠正：置信度 0.95，旧记忆失效
    store.supersede("coffee", "用户喜欢加糖",
                    Memory("coffee", "用户改喝无糖", 0.95, 2, source="user_correction"))
    got = store.recall("coffee")
    print("召回:", got.fact)
    assert got.fact == "用户改喝无糖"
    # 低置信 + 被取代的旧记忆不进入上下文
    all_m = store.items["coffee"]
    assert all(m.superseded_by is not None or m.confidence >= 0.9
               for m in all_m if m.superseded_by is None)


if __name__ == "__main__":
    main()
```

**追问 1**：为什么"把模型摘要直接固化"特别危险？
→ 一句话提示：摘要会混入模型推断与幻觉，固化的错误成为后续所有推理的前提，且摘要的摘要逐层放大偏差——写入必须保留对原始 turn 的溯源。

**追问 2**：记忆的"自我强化回路"怎么从数据上检测？
→ 一句话提示：监控单条记忆的"被引用次数/置信度增量"与用户纠正率的相关性——被频繁引用但经常被纠正的记忆就是污染候选，自动降权进审计队列。

## 背诵要点
- 污染三路径：纠正前信息入库、检索命中自我强化、新旧冲突无裁决规则；只写不删是放大器。
- 正确形态：结构化事实库（来源/置信度/时间戳/superseded_by），用户显式纠正触发旧记忆失效。
- 检索守则：同主题冲突只进最高置信一条；审计任务回放校验，低置信未命中降权淘汰。

## 复盘追问
- 记忆系统为什么要像"数据库"而不是"日志"设计？提示：日志追加不可改，错误不可撤销；数据可 update/软删除，才有修复污染的能力。
- 如何在不打断用户的前提下降低污染率？提示：写入前用规则+模型双检（纠正语气识别），高影响记忆（健康/财务）入库前请求用户确认一次。
