### Q7749 · 枚举值被模型「美化」：In Progress 落库失败，改成包含匹配又把 not done 判成 done

难度：P6 ｜ 标签：LLM、结构化输出、enum、规范化、fail-closed

基线：Python 3.12；JSON Schema 的 `enum` 校验 + 别名表 + 一次修复重试。

**问**：工单抽取要求 `status ∈ {"in_progress","done","failed","canceled"}`。模型经常输出 `"In Progress"`、`"in-progress"`、`"进行中"`，严格校验全挂；有人写了"字符串包含即匹配"的兜底，`"not done"` 被映射成 `"done"`，一批未完成的单子被自动关单。枚举到底该怎么收敛？

**答**：
- **结论**：模型会把枚举值当"自然语言"处理：改大小写、加空格/连字符、翻译成中文、把状态描述成一句话（`"failed (timeout)"`）。严格校验会大量失败；而**子串匹配是危险的**——`"not done"` 包含 `"done"`，`"undone"` 也包含，语义被直接反转。枚举收敛需要"显式别名表 + 归一化 + 失败即重试"，而不是模糊匹配。
- **取舍**：① **归一化**只做无损变换：`strip`、`lower`、把空格/连字符/下划线统一（`In Progress` → `in_progress`）；② **别名表**由业务维护，只收"语义确定"的写法（`进行中`→`in_progress`、`completed`→`done`），未知值一律拒绝；③ 拒绝时把**允许值列表**回灌给模型做一次修复重试（温度调低、缩短输出）；④ 仍失败就 fail-closed：落 `unknown` + 进人工队列，绝不替模型猜。否定语义（`not done`）必须显式建模成另一个枚举值，而不是靠字符串。
- **实战**：① `enum` 用稳定的机器码（`in_progress`）而不是展示名（`进行中`），展示名放在映射表里由前端渲染；② 埋点统计"归一化命中/别名命中/拒绝"三类比例，别名表膨胀说明提示词或 schema 描述有问题；③ 单测覆盖否定、带括号的解释、中文、全角字符；④ 下游状态机只接受白名单值，任何"猜出来的"值都不能触发不可逆动作（关单、退款）。

```python
"""枚举收敛：归一化 + 显式别名 + fail-closed；子串匹配会反转语义。"""
import re

ALLOWED = ["in_progress", "done", "failed", "canceled"]
ALIASES = {
    "in progress": "in_progress",
    "进行中": "in_progress",
    "处理中": "in_progress",
    "completed": "done",
    "complete": "done",
    "完成": "done",
    "failure": "failed",
    "error": "failed",
    "失败": "failed",
    "cancelled": "canceled",
    "已取消": "canceled",
}


def normalize(raw: str) -> str:
    s = raw.strip().lower().replace("　", " ")          # 全角空格
    s = re.sub(r"[\s\-]+", "_", s)                     # 空格/连字符 -> 下划线
    return s


def strict(raw: str) -> str:
    if raw in ALLOWED:
        return raw
    raise ValueError(f"enum mismatch: {raw!r}")


def safe(raw: str) -> str:
    key = normalize(raw)
    if key in ALLOWED:
        return key
    spaced = key.replace("_", " ")
    if spaced in ALIASES:
        return ALIASES[spaced]
    raise ValueError(f"unknown enum: {raw!r}; allowed={ALLOWED}")


def naive_contains(raw: str) -> str | None:
    s = normalize(raw)
    for cand in ALLOWED:
        if cand in s:                                  # 子串匹配：危险
            return cand
    return None


SAMPLES = ["in_progress", "In Progress", "in-progress", "进行中",
           "failed (timeout)", "not done", "cancelled", "DONE ", "取消"]

if __name__ == "__main__":
    print(f"{'原始值':<20}{'strict':<14}{'safe':<16}{'contains'}")
    stats = {"strict": 0, "safe": 0, "naive": 0, "wrong": 0}
    for raw in SAMPLES:
        try:
            s1 = strict(raw); stats["strict"] += 1
        except ValueError:
            s1 = "拒绝"
        try:
            s2 = safe(raw); stats["safe"] += 1
        except ValueError:
            s2 = "拒绝"
        s3 = naive_contains(raw)
        if s3: stats["naive"] += 1
        if raw == "not done" and s3 == "done":
            stats["wrong"] += 1
        print(f"{raw!r:<20}{s1:<14}{s2:<16}{s3}")

    print("\n覆盖统计:", stats)
    print("-> 'not done' 被 contains 判成 done：语义反转，且不会报错")

    # 拒绝时把允许值回灌，让模型修一次
    def repair_prompt(raw: str) -> str:
        return (f"你的输出 {raw!r} 不在允许值 {ALLOWED} 中。"
                f"请只输出其中一个值，不要解释。")

    unknown = "failed (timeout)"
    print("\n修复提示:", repair_prompt(unknown))
    print("修复后若仍失败 -> 落 unknown + 人工队列，禁止猜测")
    print("\n结论：枚举只做归一化与显式别名；未知值 fail-closed，绝不子串匹配")
```

**追问一**：为什么不让模型直接输出中文展示名（"进行中"）？

→ 解析：展示名会随产品文案变（"处理中"→"处理中(待审核)"），一改文案所有历史数据与下游判断都错；而且中文更容易被模型"意译"（"正在处理中"、"处理中…"），别名表会无限膨胀。稳定做法是"机器码 + 展示映射"：模型只输出 `in_progress` 这类不可变的 code，前端/报表再映射成人话。这也让日志、埋点、状态机共享同一套值域。

**追问二**：状态值有 20 多个时，别名校验还撑得住吗？

→ 解析：撑不住，别名表的组合会爆炸，模型也容易选错相邻状态。这时要做**分层**：先让模型选大类（`open / closed / error`），再在类内选子状态（两级枚举），每级值域不超过 7±2；或者先做"分类"再做"抽取"。另外用 schema 的 `enum` + `description` 给每个值一句判据（"failed=执行失败且不可重试；canceled=用户主动取消"），边界案例写进 few-shot，比事后加别名更有效。
