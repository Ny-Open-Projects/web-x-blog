### Q7533 · 事故复盘：离线评估涨 3 个点，上线后在线指标反跌

> 难度:★★★★ | 标签:评估, 事故复盘, offline-online gap

**问**：检索新版离线评估提升 3 个点，全量上线后核心业务指标不涨反跌。offline-online gap 的来源有哪些？评测集为什么要按线上流量重采样？影子评估和"离线-在线校准曲线"分别解决什么？

**答**：结论：gap 有四大来源——① **分布漂移**（评测集是历史精选数据，线上是新分布含长尾）；② **指标错位**（离线优化 hit@k，业务在乎转化/留存）；③ **条件错位**（离线没有真实上下文：多轮历史、用户状态、实时数据）；④ **评测集过拟合**（反复按评测集调参，评测集事实上变成了训练集）。修复优先级：先把评测集分布校准到线上（分层重采样），再用影子评估与校准曲线建立"离线提升 → 在线提升"的映射。

机理与实战：
- **分布漂移最隐蔽**：评测集为了"可人工校验"往往以高频头部 query 为主，而线上流量长尾占大头——新版在头部赢 4 个点、长尾输 10 个点，离线加权后是赢，线上加权后是输。修法：评测集按线上 query 分布（频次分层）重采样，并定期滚动重采（分布会漂）。
- **影子评估**：新系统与线上系统并行打分但不生效，按 query 配对比较——零风险地拿到"与线上同分布同条件"的离线结论；代价是双倍推理成本或抽样影子（5-10% 流量）。
- **校准曲线**：积累历史"离线提升 pt → 在线提升 pt"的配对数据（每次上线记录两点），得到转换系数——决策从"离线涨 3 点就上"变成"离线涨 3 点 ≈ 在线 1.5 点，值不值得上"。这个系数本身就是组织级的评估质量度量。
- **指标错位检查**：上线评审强制问一句"离线指标与本次业务目标的因果链是什么"——hit@k 涨不一定转化涨；要求离线评估至少包含一个业务代理指标。

```python
# 基线:Python 3.10+;纯标准库模拟离线在线评估 gap(分布漂移)与重采样校准
# 真实场景:评测集按线上流量分层重采样 + 影子评估校准离线在线映射
from __future__ import annotations
from dataclasses import dataclass


@dataclass
class Retriever:
    name: str
    head_score: float            # 高频头部 query 的命中率
    tail_score: float            # 长尾 query 的命中率


def offline_eval(r: Retriever, eval_set: dict[str, float]) -> float:
    """离线评估:按评测集内 query 分布加权。"""
    return r.head_score * eval_set["head"] + r.tail_score * eval_set["tail"]


def online_effect(r: Retriever, traffic: dict[str, float]) -> float:
    """线上效果:按真实流量分布加权(含长尾)。"""
    return r.head_score * traffic["head"] + r.tail_score * traffic["tail"]


def demo() -> None:
    a = Retriever("现行 A", head_score=0.80, tail_score=0.55)
    b = Retriever("新版 B", head_score=0.84, tail_score=0.45)   # 头部强长尾弱

    # 事故现场:评测集是历史精选,头部占比 85%(线上实际 20%)
    stale_eval = {"head": 0.85, "tail": 0.15}
    traffic = {"head": 0.20, "tail": 0.80}
    off_a, off_b = offline_eval(a, stale_eval), offline_eval(b, stale_eval)
    on_a, on_b = online_effect(a, traffic), online_effect(b, traffic)
    print(f"离线评估:B {off_b:.1%} > A {off_a:.1%}(提升 {(off_b - off_a) * 100:.1f}pt) -> 上线!")
    print(f"线上真实:B {on_b:.1%} < A {on_a:.1%}(倒退 {(on_a - on_b) * 100:.1f}pt) ✅ 事故")
    assert off_b > off_a and on_b < on_a

    # 修复一:评测集按线上流量分层重采样
    fresh_eval = {"head": 0.20, "tail": 0.80}
    off_a2, off_b2 = offline_eval(a, fresh_eval), offline_eval(b, fresh_eval)
    print(f"重采样后离线:B {off_b2:.1%} < A {off_a2:.1%} -> 与线上结论一致 ✅")
    assert (off_b2 > off_a2) == (on_b > on_a)

    # 修复二:影子评估建立"离线提升 -> 在线提升"校准曲线(历史配对)
    calibrations = [(0.5, 0.2), (1.0, 0.5), (2.0, 1.1)]      # (离线pt, 在线pt) 历史对
    ratio = sum(o / f for f, o in calibrations) / len(calibrations)
    print(f"校准曲线:离线 1pt ≈ 在线 {ratio:.2f}pt -> 决策不再裸信离线点数 ✅")


if __name__ == "__main__":
    demo()
```

**追问一**：评测集重采样后，长尾 query 的标注质量怎么保？
答：长尾标注贵且噪声大——用分层策略：头部高频全量人工标注，长尾抽样标注 + LLM-as-judge 初筛（Q7501）+ 人工抽检校准；并接受长尾指标有更宽的置信区间，决策看"头部精确 + 长尾区间估计"两层数据。

**追问二**：怎么发现团队在"过拟合评测集"？
答：三个信号：评测集分数持续涨但线上影子不涨；新版本在评测集上的提升幅度越来越大而改动越来越小（刷点）；同一批人对评测集样本做过针对性 fix。处置：评测集滚动重采 + 保留"封存盲测集"（一年只解封一次用于终验）。

## 背诵要点
- gap 四源：分布漂移、指标错位、条件错位、评测集过拟合；分布漂移最隐蔽（评测集头部偏重 vs 线上长尾权重）。
- 修复顺序：评测集按线上流量分层重采样（定期滚动）→ 影子评估配对比较 → 离线-在线校准曲线做决策映射。
- 上线评审必须问"离线指标与业务目标的因果链"；过拟合信号 = 离线持续涨而影子不涨。
