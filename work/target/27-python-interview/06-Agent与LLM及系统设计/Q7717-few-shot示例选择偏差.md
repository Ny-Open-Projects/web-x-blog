### Q7717 · few-shot 示例选择：固定示例与动态检索的偏差

难度：P6 ｜ 标签：few-shot、示例选择、分布漂移、评测

基线：Python 3.12；纯 Python 模拟固定/相似度/分层示例策略的准确率。

**问**：分类 prompt 里固定放了 3 条 few-shot 示例，上线三个月后新意图占比升高，整体准确率从 91% 掉到 78%。改成"按相似度动态检索 3 条示例"后，老意图掉了 5 个点，新意图也没救回来。示例到底该怎么选？

**答**：
- **结论**：示例是**隐式的训练集**，它决定了模型对标签空间、输出格式和边界 case 的理解。固定示例覆盖不到新意图（模型没见过该标签的示范）；纯相似度检索会偏向"和输入最像"的样本，容易选到同类但标签噪声大的例子，且丢掉标签空间的多样性。正确做法是**分层 + 相似度 + 去重**：先按意图/标签分层保证每类都有代表，再在层内选与输入最相似的，最后去重并校验标签。
- **取舍**：固定示例稳定、可缓存（前缀缓存命中高）、易评测；动态示例适应分布变化，但增加检索依赖、延迟与不确定性，且示例顺序会影响输出（近因偏差）。示例越多越好吗？不，示例占 token、可能引入冲突，3-5 条高质量示例通常优于 10 条噪声示例。
- **实战**：① 示例库按标签打标、定期清洗，禁止把模型生成的低质样本直接回流；② 选择策略按意图分层，每类至少 1 条，再补相似样本；③ 固定顺序（同类聚在一起、标签均衡）减少顺序偏差；④ 评测按意图分组，别只看总体准确率。

```python
INTENTS = ["退款", "物流", "发票", "账号", "其他"]


def accuracy(policy: str, dist: dict[str, float], noise: float = 0.2) -> float:
    if policy == "fixed":
        covered = {"退款", "物流", "发票"}
        return sum(p * (0.92 if i in covered else 0.55) for i, p in dist.items())
    if policy == "similarity":
        # 覆盖全部意图，但会选到部分标签噪声样本
        return sum(p * (0.90 * (1 - noise) + 0.55 * noise) for p in dist.values())
    # stratified：分层覆盖 + 相似度，噪声更低
    return sum(p * 0.90 for p in dist.values())


if __name__ == "__main__":
    old = {"退款": 0.5, "物流": 0.3, "发票": 0.15, "账号": 0.03, "其他": 0.02}
    new = {"退款": 0.3, "物流": 0.2, "发票": 0.1, "账号": 0.25, "其他": 0.15}
    for dist_name, dist in (("旧分布", old), ("新分布", new)):
        print(dist_name, {p: round(accuracy(p, dist), 3) for p in
                          ("fixed", "similarity", "stratified")})
    print("结论：固定示例怕分布漂移，纯相似度怕标签噪声，分层+相似度更稳")
```

**追问一**：为什么"示例顺序"会影响分类结果？
→ 解析：模型对上下文末尾更敏感（近因效应），最后一条示例的标签/格式会被过度模仿；同类示例连续出现也会强化某种输出模式。固定且均衡的顺序能减少这种偏差，动态打乱顺序会让评测不可复现。

**追问二**：动态示例和 prompt 前缀缓存冲突吗？
→ 解析：冲突。前缀缓存要求请求开头完全相同，动态示例每次都在变，缓存命中率会掉到 0，成本和首 token 延迟上升。折中是把"稳定指令 + 固定示例"放前缀，动态示例放后面，或按意图分组做多套固定模板。
