### Q7521 · LLM 语义缓存

> 难度:★★★ | 标签:语义缓存, 成本工程, RAG

**问**：「今天天气怎么样」和「现在天气如何」答案相同但字面不同——语义缓存（embedding 相似度命中）怎么实现？误命中（相似但答案不同：改了参数的两个问题）怎么防，缓存与上下文（多轮对话/RAG）怎么兼容——带完整上下文的请求还能缓存吗？

**答**：① 实现：查询 embedding → 向量库 ANN 检索相似历史查询 → 相似度 ≥ 阈值直接返回缓存答案（跳过模型调用）。成本收益巨大（重复类问答占比常 30%+，每次命中省一次强模型调用），但误命中的代价也大——**答错比答慢更糟**。② 防误命中四闸：**阈值保守**（0.92+ 而非 0.85——语义缓存宁可漏不可错，与检索场景阈值完全不同）；**实体等价校验**（关键实体必须一致：两查询提到的城市/产品 ID 不同则绝不命中——embedding 相似但实体不同是最大误命中源）；**时间敏感类禁缓存**（天气/价格/库存类查询带时效，缓存 TTL 极短或直接 bypass）；**答案条件核对**（缓存答案生成时的上下文指纹与当前请求匹配——RAG 检索到的文档集不同则答案可能不同，缓存键要含检索结果指纹）。③ 上下文兼容：多轮对话中「它多少钱」（指代上文）不能独立缓存——缓存键必须是**完整语义请求**（展开指代后的规范化查询），或对话级缓存（整轮上下文哈希）粒度。

```python
# 全部标准库；demo 实现语义缓存（阈值+实体校验+时效 bypass+RAG 指纹）
import hashlib, time, re

STOP = {"的", "吗", "呢", "怎么", "什么", "如何", "现在", "今天"}
def normalize(q: str) -> str:
    return "".join(w for w in re.findall(r"\w+", q.lower()) if w not in STOP)

class SemanticCache:
    def __init__(self, threshold: float = 0.92, entity_strict: bool = True):
        self.store: list[tuple[str, str, float, str]] = []   # (norm_q, answer, ts, rag_fp)
        self.threshold, self.entity_strict = threshold, entity_strict
    @staticmethod
    def sim(a: str, b: str) -> float:
        """简化相似度（真实 = embedding 余弦；演示用字符 Jaccard）。"""
        sa, sb = set(a), set(b)
        return len(sa & sb) / max(len(sa | sb), 1)
    def entities(self, q: str) -> set[str]:
        return set(re.findall(r"[A-Za-z0-9]+", q)) | {"beijing", "shanghai"} & set(q.split())
    def get(self, q: str, rag_fp: str = "", time_sensitive: bool = False) -> str | None:
        if time_sensitive:
            return None                                     # 闸③：时效类 bypass
        nq = normalize(q)
        for nq2, ans, ts, fp in self.store:
            if time.time() - ts > 3600:                     # TTL 1h
                continue
            if rag_fp and fp and rag_fp != fp:              # 闸④：RAG 指纹不同不命中
                continue
            if self.entity_strict and self.entities(q) != self.entities(q2 := nq2):
                continue                                    # 闸②：实体不一致不命中
            if self.sim(nq, nq2) >= self.threshold:         # 闸①：保守阈值
                return ans
        return None
    def put(self, q: str, answer: str, rag_fp: str = ""):
        self.store.append((normalize(q), answer, time.time(), rag_fp))

if __name__ == "__main__":
    cache = SemanticCache(threshold=0.9)
    cache.put("北京今天天气怎么样", "北京晴，25 度")
    hit = cache.get("现在北京天气如何")
    assert hit == "北京晴，25 度"
    print("同义改写命中 ✅:", hit)
    miss1 = cache.get("上海今天天气怎么样")                 # 实体不同 → 不得命中
    assert miss1 is None, "实体校验应拦截跨城市误命中"
    print("实体校验拦截跨城市误命中 ✅")
    miss2 = cache.get("北京今天天气怎么样", time_sensitive=True)  # 强时效 bypass
    assert miss2 is None
    print("时效类 bypass ✅")
    cache.put("这个方案的成本多少", "总成本 50 万", rag_fp="docs-v1")
    miss3 = cache.get("这个方案的成本多少", rag_fp="docs-v2")
    assert miss3 is None, "RAG 指纹不同不得命中"
    print("RAG 指纹闸 ✅（检索内容变了答案可能变）")
    # 成本口径：命中率高（重复咨询 30%+）时语义缓存是最便宜的「模型」；
    # 误命中一次 = 用户拿到错答案 + 信任损失——阈值宁可保守。
```

**追问**：1) embedding 相似度和字符 Jaccard 的差距在哪类查询上最大？——同义换词（「投诉」vs「不满意」embedding 高 Jaccard 零）与跨语言（中英混合）——生产必须 embedding，Jaccard 只能做快速预筛。2) 缓存答案的「生成条件」还要记哪些？——模型版本、prompt 版本（Q7519）、温度参数——任一变化旧答案语义漂移，缓存键/校验带版本指纹，版本切换时清空或分区缓存。3) 为什么说语义缓存是「最便宜但最危险」的优化？——收益线性（每命中省一次调用），风险是错误答案的直接暴露（无模型兜底）；纪律：阈值保守 + 实体闸 + 监控命中率与投诉率的相关性。

## 背诵要点
1. 语义缓存四闸：保守阈值（0.92+）、实体等价校验、时效类 bypass、RAG 指纹匹配。
2. 缓存键必须是完整语义请求（展开指代）或含 RAG 结果指纹——上下文变化答案可能变。
3. 误命中比未命中更糟：宁漏不错；版本切换（模型/prompt）清空或分区缓存。

## 复盘追问
1. 命中率监控显示 60% 但用户投诉翻倍，先查什么？（提示：阈值过松的误命中——抽样人工核对命中对（query, cached answer），阈值回调 + 实体闸收紧）
2. 多租户下语义缓存怎么隔离？（提示：缓存键含 tenant_id（不同租户数据/权限不同答案），或分租户命名空间——跨租户命中是权限泄漏事故）
