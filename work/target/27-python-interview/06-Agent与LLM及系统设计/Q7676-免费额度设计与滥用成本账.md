### Q7676 · 免费额度设计与滥用成本账：羊毛党的账怎么算

难度：P6/P7 ｜ 标签：成本工程、风控、多租户

**问**：产品提供免费试用额度（每天 N 次对话），上线一个月后免费用户消耗了 35% 的模型预算，其中有批量注册的滥用流量。免费额度的成本账怎么算？防滥用的策略如何与成本联动？

**答**：**结论**：免费额度的本质是**获客成本（CAC）的一部分**，账要算成"每个激活付费用户的免费补贴"：`免费总成本 / 转化付费数 = 有效 CAC`。当滥用比例上升，有效 CAC 被稀释——设滥用占比 f，真实获客成本被放大 1/(1-f)。设计上两条铁律：① 免费额度的**单位成本封顶**（用低成本模型/短上下文/限输出长度，把免费会话的单次成本压到付费的 1/5~1/10）；② 额度必须有**速率与总量双约束**（Q1779 双窗口），单纯"每天 N 次"挡不住并发薅。

**取舍**：防滥用手段的成本与误伤：设备指纹/手机验证提高批量注册成本（转化率会掉一点）；免费层用小模型（体验下降可能影响转化）——这两条都是"用一点转化率换大量成本"。更精细的路线：**动态额度**（行为正常的用户给标准额度，可疑特征用户降到 20% 并要求验证），误伤可控且不需要一刀切。

**实战**：三个监控口径：免费成本的日环比（异常天通常是滥用爆发）、免费→付费转化率、滥用特征命中率（同 IP 段会话数、注册-使用间隔、请求节奏的机器特征）。成本账月度复盘一次，把"免费预算占比"与"转化率"画在同一张图上找拐点。

```python
# 免费额度成本账：CAC 稀释与封顶设计（标准库可运行）
def free_tier_economics(
    free_users: int,
    cost_per_free_session: float,   # 免费会话单次成本（元）
    sessions_per_free_user: float,
    conversions: int,               # 转化付费用户数
    abuse_ratio: float = 0.0,       # 滥用流量占比
) -> dict:
    abused = free_users * abuse_ratio
    real_users = free_users - abused
    total_cost = free_users * sessions_per_free_user * cost_per_free_session
    cac = total_cost / conversions if conversions else float("inf")
    # 滥用稀释：真实获客成本 = 总成本/真实转化贡献
    real_cac = total_cost / (conversions * (real_users / free_users)) \
        if conversions else float("inf")
    return {"total_cost": round(total_cost),
            "cac": round(cac, 1), "real_cac": round(real_cac, 1),
            "dilution": f"滥用 {abuse_ratio:.0%} 使 CAC 放大 "
                        f"x{real_cac / cac:.2f}" if cac else ""}

print(free_tier_economics(50_000, 0.10, 20, 500, abuse_ratio=0.3))
# 30% 滥用让有效 CAC 从 20 元变 28.6 元

# 封顶设计：免费层单次成本压到付费的十分之一
def capped_session_cost(paid_cost: float) -> dict:
    return {"模型": "小模型（1/5 价）",
            "上下文": "裁剪到 2K（1/3 token）",
            "输出": "max_tokens 减半",
            "估算成本": round(paid_cost * 0.2 * 0.33 * 0.5, 4),
            "倍差": f"{paid_cost / (paid_cost * 0.2 * 0.33 * 0.5):.1f}x"}
print(capped_session_cost(0.10))

# 动态额度：可疑特征用户降配
def dynamic_quota(base_daily: int, signals: dict) -> int:
    """signals: {same_ip_sessions, signup_to_use_hours, burst_score}"""
    suspicious = (signals.get("same_ip_sessions", 0) > 5
                  or signals.get("signup_to_use_hours", 99) < 1
                  or signals.get("burst_score", 0) > 0.8)
    return base_daily // 5 if suspicious else base_daily

print("正常用户额度:", dynamic_quota(50, {"same_ip_sessions": 1}))
print("可疑用户额度:", dynamic_quota(50, {"same_ip_sessions": 9,
                                          "burst_score": 0.9}))
```

**追问 1**：为什么免费层直接用小模型可能反噬转化率？
提示：免费用户用小模型得到差回答，会低估产品真实能力，影响付费决策；更优解是"首几次用大模型建立认知、之后降小模型"，把降配藏到体验形成之后。

**追问 2**：滥用识别的误伤（把真人当机器人）怎么度量与补救？
提示：对被降配用户做申诉通道 + 特征回溯；离线用付费转化用户的历史行为回测特征阈值——误伤率的账是"流失的潜在付费用户 × LTV"，通常远大于省下的模型成本，阈值宁松勿紧。

**追问 3**：如果滥用是竞争对手在刷接口（而非羊毛党），账有什么不同？
提示：这不是 CAC 问题而是攻击成本问题：按请求计费的成本可预测，对策转向 API key 治理 + 签名 + 按指纹封禁，并把免费预算与生产预算物理隔离（免费池打满不影响付费）。

## 背诵要点
1. 免费额度 = CAC 的一部分：滥用占比 f 使有效 CAC 放大 1/(1-f)，月账必算 real_cac。
2. 封顶三板斧：免费层小模型 + 短上下文 + 限输出，单次成本压到付费 1/5~1/10。
3. 动态额度优于一刀切：可疑特征降配到 20%，误伤的 LTV 代价通常大于省下的成本。
