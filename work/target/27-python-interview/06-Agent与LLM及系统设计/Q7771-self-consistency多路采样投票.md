### Q7771 · 单次回答忽对忽错：self-consistency 多路采样投票的收益边界

难度：P6 ｜ 标签：self-consistency、采样投票、推理时算力、准确率、成本账

基线：Python 3.12；模拟单次采样（70% 正确率）与 5 路多数投票的对比实验（2000 次蒙特卡洛），量化投票的准确率收益与成本倍数，全标准库实跑。

**问**：同一个数学应用题，模型这次答对下次答错——温度采样的方差没法接受。self-consistency（采样 N 次取多数）是怎么把准确率拉上去的？收益和单次正确率是什么关系？什么任务上投票无效甚至更差？成本怎么算账？

**答**：
- **结论**：self-consistency 的原理：推理路径是**分布**而非单点——同一道题存在多条能到达正确答案的推理链，而错误的路径彼此**分散**（错法千奇百怪）。采样 N 次 + 多数投票，相当于用"正确路径的集中性"对抗"错误路径的分散性"：本卡模拟单次 70% 正确率，5 路投票后 91.9%——错误率从 30% 降到 8%，收益远超线性。投票收益的数学直觉：若错误答案均匀散布在 B/C/D 三个候选上（各 ~10%），投票后单一错误候选聚集 ≤14% 的票，几乎不可能过半。**收益边界**：① 单次正确率太低（<40%）时错误也可能集中，投票拉不动；② 模型**系统性错误**（稳定地错同一个答案——知识缺口）投票无效：5 次都错成同一个 B，投票选出的还是 B——投票治方差不治偏倚；③ 任务答案空间连续（长文写作）没有"多数"概念，只能用 rubric 评分聚合。
- **取舍**：① N 的选择：收益递减明显，3→5 的增益大于 5→10；成本线性增长，N=5 是常见拐点（本卡 5x 成本换错误率减半以上）；② 采样温度：投票要求温度 > 0（温度 0 时 N 次全同，白花 5 倍钱）——**这和"低温度更稳"的直觉相反**：投票架构下要故意调高温度增加路径多样性；③ 答案抽取的可靠性：投票的对象是"抽取后的最终答案"（如 JSON 的 answer 字段），抽取失败率会吃掉投票收益；④ 与 CoT 组合：投票对多步推理任务收益最大（本卡场景），对单步检索类任务几乎无增益。
- **实战**：① 按错误成本分级用投票：内部草稿单次采样，对外交付/资金相关用 N=5~7；② 观察投票分散度作为不确定性信号：5 票全同 vs 3:2 分裂，后者自动触发人工复核或升级大模型（Q7776 级联的天然衔接）；③ 压测前先量化"错误候选的分散度"——分布集中（偏倚型）的任务别浪费投票预算，去补知识/改提示；④ 投票与缓存冲突：同一 query 的投票结果缓存键要带 N 与温度参数（Q1778 同 query 合并要区分采样配置）。

```python
"""Q7771 self-consistency 多路采样投票: 单次采样不稳, N 路投票显著降低错答率。"""
import random

random.seed(11)

# 任务: 多步算术应用题。模型单次采样正确率 70%(温度>0 的分布)
SINGLE_ACC = 0.70
N_SAMPLES = 5


def sample_once(rng: random.Random) -> str:
    """单次采样: 70% 正确答案 A, 否则从错误候选里出一个."""
    if rng.random() < SINGLE_ACC:
        return "A"
    return rng.choice(["B", "C", "D"])


def single_run(rng: random.Random) -> bool:
    return sample_once(rng) == "A"


def vote_run(rng: random.Random) -> bool:
    votes: dict[str, int] = {}
    for _ in range(N_SAMPLES):
        ans = sample_once(rng)
        votes[ans] = votes.get(ans, 0) + 1
    best = max(votes, key=votes.get)
    return best == "A"


if __name__ == "__main__":
    trials = 2000
    single_acc = sum(single_run(random.Random(trials + i)) for i in range(trials)) / trials
    vote_acc = sum(vote_run(random.Random(trials + i)) for i in range(trials)) / trials
    cost_ratio = N_SAMPLES
    print(f"单次采样正确率  : {single_acc:.1%}")
    print(f"{N_SAMPLES} 路投票正确率 : {vote_acc:.1%}")
    print(f"成本倍数: {cost_ratio}x (推理费用线性涨, 换取错误率减半以上)")
    ok = vote_acc > single_acc + 0.15
    print(f"校验: 投票显著优于单次 -> {'通过' if ok else '异常'}")
    print("结论：self-consistency 用推理时算力换准确率, 对有多步推理的任务收益最大;")
    print("      错误候选越分散投票越有效, 若模型稳定地错同一个答案, 投票救不了(知识缺口)")
```

**追问一**：为什么投票架构下要"故意调高温度"？温度 0 + 投票 N 次会发生什么？

→ 解析：温度 0 时模型输出近似确定性（贪心解码），N 次采样得到 N 个几乎相同的答案，投票等于花 5 倍钱买 1 次的结果——**多样性是投票的原材料，温度 0 把原材料抽干了**。投票架构的正确配置：温度调高（0.7~1.0）让推理路径充分分散，错误路径散开、正确路径收敛，然后靠聚合去噪。这与单次调用"低温度更稳"的经验完全相反——因为两者对抗的是不同的敌人：单次调用怕输出漂移（低温度压方差），投票架构怕路径同质化（高温度保多样性）。工程上的注意：温度高会让单条路径的格式错误率上升（JSON 崩坏），所以答案抽取层要更健壮（抽取失败的重采样，而不是计为废票——废票过多投票基数缩水）。

**追问二**：怎么区分"方差型错误"和"偏倚型错误"？判出来之后各自怎么办？

→ 解析：判别方法就是 self-consistency 本身：对失败样本重复采样 N 次，看答案分布。**方差型**（同一题多次采样答案不同，正确答案常出现）：投票/重试有效，本质是采样噪声；**偏倚型**（N 次采样答案高度一致且都错）：这是知识缺口或理解错误，投票把错误放大成"高置信错误"——5 票一致地投给错误答案，比单次错误更难被发现（自洽性伪装成了正确性）。对策分叉：方差型 → 投票/升级大模型/提高预算；偏倚型 → 补知识（检索注入、few-shot、文档更新 Q1504）、改问题分解（把一步推理拆成可验证的子步）、或引入外部校验（代码执行、单位检查）——**验证器比生成器便宜**。监控口径上，两种错误要分开统计：投票通过率下降说明方差变大（模型或提示回归），"投票一致但人工复核判错率"上升说明偏倚积累（知识/口径过期），归因方向完全不同。
