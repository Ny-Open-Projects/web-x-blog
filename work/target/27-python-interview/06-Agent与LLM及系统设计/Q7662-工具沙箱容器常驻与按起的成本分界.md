### Q7662 · 工具沙箱容器常驻与按起的成本分界账

难度：P6-P7 | 标签：成本工程、沙箱、Agent 工具执行

**问**：Agent 需要在隔离沙箱里执行用户提交的 Python 代码（数据分析工具）。两种方案：A) 每个会话常驻一个沙箱容器；B) 每次工具调用冷起一个容器（firecracker/docker run）。这笔成本账怎么算？分界点在哪？

**答**：结论：账的三个变量是**会话时长、调用频率、冷起延迟成本**。常驻成本 = 容器内存 × 会话时长 × 单价，即使闲着也在烧钱；按起成本 = 冷起时间（镜像拉取 + 启动 0.5-15s）× 用户等待折损 + 短生命周期资源费。分界式：当 `调用间隔均值 < 冷起时间 × 等待敏感系数` 时常驻划算（频繁调用），调用稀疏（间隔 > 分钟级）则按起。中间态是**池化**：预热容器池按需借用归还，兼顾冷启动与闲置成本——生产大多落在这里。

取舍与实战：
1. 成本账口径：常驻还要算"闲置率"——会话平均活跃调用时间通常 <5%，常驻方案 95% 的钱是闲置费；池化把闲置率压到 20-40%。镜像大小直接决定冷起：预装依赖的 2GB 镜像冷起 10s+，精简基础镜像 + 依赖分层缓存可到 1-2s。
2. 延迟成本折算：冷起 3s 对交互式 Agent 的用户体感损失要折成钱（留存/满意度），公式化进分界式；后台批处理任务延迟敏感系数≈0，几乎总选按起。
3. 回收策略是隐性成本：常驻容器要配 idle timeout 回收（否则泄漏式增长，Q7135 僵尸资源清扫），池化要配最大借用时长与强制回收——两种方案的运维成本都别漏记。
4. 安全约束一致：无论常驻还是按起，网络隔离、文件系统只读、CPU/内存配额（cgroup）不变；常驻容器跨调用保留文件状态是功能也是风险（会话间泄漏要清理）。

```python
"""沙箱成本分界：常驻 vs 按起 vs 池化的月成本模型（标准库，可运行）"""

def sandbox_cost(
    sessions: int, calls_per_session: int,
    call_interval_s: float,        # 会话内调用平均间隔
    session_minutes: float,
    container_mem_gb: float, mem_price_per_gb_h: float,
    cold_start_s: float, wait_penalty_per_call: float,  # 冷起等待折损
) -> dict:
    resident_h = sessions * session_minutes / 60
    resident = resident_h * container_mem_gb * mem_price_per_gb_h
    ondemand = sessions * calls_per_session * (
        container_mem_gb * mem_price_per_gb_h * cold_start_s / 3600 * 3  # 3s 计费粒度
        + wait_penalty_per_call)
    # 池化：P 个预热容器承接峰值并发，闲置率假设 30%
    import math
    pool_size = max(1, math.ceil(sessions * calls_per_session / max(session_minutes * 60 / max(call_interval_s, 0.1), 1) / 3600 * 0.5))
    pooled = pool_size * 730 * container_mem_gb * mem_price_per_gb_h * 1.3 + ondemand * 0.2
    return {"常驻": round(resident), "按起": round(ondemand),
            "池化(估算)": round(pooled),
            "建议": "常驻" if resident < ondemand else ("池化" if abs(call_interval_s) < 60 else "按起")}

r = sandbox_cost(sessions=5000, calls_per_session=8, call_interval_s=25,
                 session_minutes=12, container_mem_gb=1,
                 mem_price_per_gb_h=0.00012, cold_start_s=4,
                 wait_penalty_per_call=0.01)
for k, v in r.items():
    print(f"{k}: {v}")
```

**追问 1**：为什么镜像分层缓存对"按起"方案是最大的降本杠杆？
**提示**：冷起时间被镜像下载/解压主导；基础镜像常驻节点 + 依赖层缓存命中后，冷起只剩应用层挂载，从 10s 降到 1-2s——延迟折损与计费粒度双降，比调资源单价有效得多。

**追问 2**：池化方案的"池大小"怎么定才不是拍脑袋？
**提示**：按会话到达的峰值并发（泊松近似 × P99 系数）定池上界，按调用间隔定预热数量；池太小退化为排队（等效冷起），太大闲置费回升——用池命中率与借用等待 P99 两个指标动态调。

## 背诵要点
- 分界式：调用间隔 < 冷起 × 敏感系数 → 常驻；稀疏调用按起；生产主流是预热池化。
- 常驻的隐性账：闲置率常 >95%（活跃调用占比极低）+ idle 回收运维；按起的账在冷起延迟折损。
- 最大杠杆是镜像分层缓存（冷起 10s→1-2s），池大小按峰值并发 × P99 系数定。
