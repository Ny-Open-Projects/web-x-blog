### Q7583 · 影子流量与 A/B 评测的成本账

难度：P6/P7 ｜ 标签：LLM 评测 / 成本工程 / 实验设计

**问**：团队想给 Agent 的每个 Prompt 改动都跑 A/B 或影子评测，但评测 token 费用已经接近生产推理费用。影子流量和评测的成本怎么建模、怎么控制？

**答**：
- **结论**：成本模型：`评测月成本 = 触发次数 × 每次评测的样本量 × 每样本 token 单价 × 候选版本数`。四个因子都是治理对象：① 触发策略——每次改动全量评测 vs 门禁触发（改动超过阈值/触及核心 prompt 才跑），后者可省 70%+；② 样本量——统计功效下限之外不多花，用固定核心集（500-1000 条）+ 分层抽样，不做随机大样本；③ 候选数——影子跑多候选是双倍成本，先离线小样本筛选再单候选 A/B；④ 模型档位——judge/评测模型用低价位模型，只有争议样本升级到旗舰模型仲裁（分层仲裁）。
- **取舍**：影子流量（shadow）与在线 A/B 的取舍：影子不作用户流量、无风险，但它测的是"回放样本上的质量"，与真实分布有偏（新 case 缺失）；A/B 统计有效但影响用户与收入指标。惯例是两级：影子做"准入判定"（质量显著回退直接否决），A/B 做"效果度量"（只对影子胜出的候选跑，缩小样本量与时长）。
- **实战**：预算护栏：① 评测预算独立科目（不与生产混），月预算 = 生产费用的 10-20% 封顶；② 每次 run 落成本标签（prompt 版本、触发原因、样本量），出"每单位质量提升的成本"报表；③ 评测集复用与缓存：相同样本+相同模型版本的结果直接复用（确定性温度 0），重复 run 只算增量；④ 告警：单次评测 run 超预算 20% 需审批。

```python
# 评测成本建模与门禁触发策略对比（纯标准库）
# 基线：Python 3.9+


def eval_cost(runs: int, samples: int, tokens_per_sample: int,
              price_per_m: float, candidates: int = 1) -> float:
    return runs * samples * tokens_per_sample / 1e6 * price_per_m * candidates


def gate_triggered(diff_lines: int, touches_core: bool) -> bool:
    """门禁触发策略：核心 prompt 或大改动才全量评"""
    return touches_core or diff_lines > 50


def main() -> None:
    sample, tokens, price = 800, 3000, 3.0  # judge 模型 $3/M
    full_month = eval_cost(runs=40, samples=sample, tokens_per_sample=tokens,
                           price_per_m=price, candidates=2)
    gated = sum(eval_cost(1, sample, tokens, price, 1)
                for diff, core in [(5, False), (80, False), (3, True), (10, False)])
    print(f"每改必评×2候选: ${full_month:,.0f} vs 门禁+单候选: ${gated:,.0f}")
    assert gated < full_month / 4  # 门禁策略省 75%+
    # 分层仲裁：90% 低价 judge + 10% 旗舰仲裁
    cost_tiered = eval_cost(1, sample, tokens, price) * 0.9 + \
        eval_cost(1, sample * 0.1, tokens * 2, 60.0)
    print(f"分层仲裁单次: ${cost_tiered:,.2f} vs 全旗舰: ${eval_cost(1, sample, tokens, 60.0):,.2f}")
    assert cost_tiered < eval_cost(1, sample, tokens, 60.0)


if __name__ == "__main__":
    main()
```

**追问 1**：为什么"温度 0 也可能不复现结果"，缓存复用要怎么设计？
→ 一句话提示：供应商侧批量路由与硬件差异使温度 0 不完全确定，缓存 key 要含 prompt 版本+模型版本+采样参数，并把缓存命中标记进报表，避免把缓存当真实评测。

**追问 2**：影子评测与线上分布偏差怎么补偿？
→ 一句话提示：影子集定期从生产流量重新采样刷新（防旧分布），加"新 case 覆盖率"指标，低于阈值触发采样更新。

## 背诵要点
- 成本模型四因子：触发次数、样本量、候选数、judge 单价；门禁触发 + 单候选可省 75%+。
- 两级实验：影子做准入（回放分布有偏），A/B 只对影子胜者跑（省样本量与时长）。
- 护栏：评测预算 ≤ 生产 10-20%，分层仲裁（低价 judge + 旗舰仲裁争议样本），缓存 key 含版本三元组。

## 复盘追问
- 为什么评测费失控常发生在"每次改都跑全量"的团队？提示：触发策略没有分级，把"回归保险"用成了"每次改动的仪式"，必须把触发条件写进 CI 门禁。
- 如何证明评测投入的 ROI？提示：报表"每单位质量提升的成本"——用 A/B 胜率与线上 badcase 下降换算成业务收益对比评测支出。
