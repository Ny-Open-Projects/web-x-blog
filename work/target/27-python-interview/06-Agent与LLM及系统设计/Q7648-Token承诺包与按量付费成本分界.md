### Q7648 · Token 承诺包与按量付费的成本分界

难度：P6 ｜ 标签：成本工程 / 采购策略 / LLM

**问**：LLM 用量稳定增长后，厂商销售来推"承诺用量包"（承诺月度 token 量换 20-40% 折扣，未用完作废或部分结转）。团队用量有增长趋势但也有新功能上线的波动。承诺多少合适？和数据库预留实例（Q6637）的决策逻辑有什么异同？

**答**：
- **结论**：逻辑同源、参数不同。同源部分：保本利用率 = 折扣率 r（承诺包价/按量价），用量预测的"下限"决定承诺额度——只对"高置信度的基线用量"承诺，波动层留按量。LLM 场景的三个特殊性让决策更保守：① **用量方差更大**：新功能/营销活动/Agent 循环深度变化（Q7600 重试放大）都能让月用量 ±50%，而数据库负载相对平稳——预测分位数要取 P30-P40 而不是数据库的"最低利用率"；② **模型迭代改变单价结构**：承诺往往绑定模型版本，新模型上线迁移后承诺包作废（沉没），这是 LLM 独有的"技术过期货"；③ **替代弹性高**：Prompt 缓存、小模型路由（Q1159）、批处理 API 都能降低同业务的 token 消耗——承诺前先做优化（省 30% 用量比拿 20% 折扣更值），承诺一个"未优化"的用量等于锁定浪费。实操公式：`承诺额度 = 过去 3 个月用量均值 × 0.8`（保守覆盖），超出部分按量；月度对账偏差 > 15% 触发额度调整，合同尽量谈**阶梯承诺**（多档承诺，用量增长自动升档）与**结转条款**（未用完延到下月），这两个条款的价值不亚于折扣率本身。
- **取舍**：承诺省的折扣（20-40%）vs 过期作废风险与锁定单价（新模型降价时承诺价反而变贵）——LLM 行业单价趋势是快速下降，长周期承诺要谈判"新模型等效价"条款；短周期（月度滚动承诺）损失一点折扣换灵活性，多数团队更优。多供应商策略下承诺还会削弱议价与迁移能力（Q7646 容灾），承诺额度要留给"必须用主供应商"的部分。
- **实战**：① 建用量预测的三条线（均值/P30/P90），承诺只在 P30 之上谈；② 对账脚本按"承诺内单价/超量单价/浪费（未用完作废）"三列输出，浪费列连续两月 > 10% 即额度虚高；③ 承诺谈判清单：折扣率、阶梯、结转、新模型等效价、可否拆模型家族共享额度。

```python
# 承诺包 vs 按量的保本模型 (LLM 特化: 高方差 + 技术过期货)
# 基线: Python 3.9+ 标准库 (价格单位: 元/百万token)
from dataclasses import dataclass


@dataclass
class CommitAccount:
    ondemand_price: float      # 按量单价
    r: float                   # 承诺折扣率 (0.6 = 六折)
    months_usage: list[int]    # 过去 N 月用量 (百万 token)

    def commit_quota(self, coverage: float = 0.8) -> float:
        """保守承诺 = 均值 x coverage (波动留按量)。"""
        avg = sum(self.months_usage) / len(self.months_usage)
        return avg * coverage

    def monthly_cost(self, usage: float, quota: float) -> dict:
        # 承诺包是预付制: 无论用没用完, 承诺额度的钱都付
        inside = min(usage, quota)
        outside = max(0.0, usage - quota)
        wasted = quota - inside               # 未用完部分 (可结转则为0)
        return {
            "cost": quota * self.ondemand_price * self.r
            + outside * self.ondemand_price,
            "wasted": wasted,
        }


def main() -> None:
    acct = CommitAccount(ondemand_price=10.0, r=0.6,
                         months_usage=[900, 1100, 1000])   # 均值 1000
    quota = acct.commit_quota()
    assert quota == 800.0                                  # 保守 0.8
    # 场景1: 用量 1000 -> 成本 800*6 + 200*10 = 6800 vs 全按量 10000
    c1 = acct.monthly_cost(1000, quota)
    assert abs(c1["cost"] - 6800) < 1e-6 and c1["wasted"] == 0
    # 场景2: 用量暴跌 600 -> 承诺 800 作废 200, 成本 4800 vs 按量 6000
    c2 = acct.monthly_cost(600, quota)
    assert c2["wasted"] == 200.0 and abs(c2["cost"] - 4800) < 1e-6
    # 保本: 用量 >= quota 时承诺必优于按量 (利用率=承诺全额>=r)
    assert acct.monthly_cost(800, quota)["cost"] == 800 * 6.0 < 8000
    # 先优化再承诺: 用量降 30% -> 承诺 560, 省的钱 > 折扣
    optimized = [u * 0.7 for u in acct.months_usage]
    q2 = sum(optimized) / 3 * 0.8
    assert q2 == 560.0
    print(f"承诺额度 {quota} (均值x0.8); 用量1000时 {c1['cost']} 元 vs 按量 10000")
    print("OK: 只承诺 P30 之上的基线; 先优化用量再谈折扣; 谈阶梯+结转条款")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么 LLM 的承诺额度取"均值 × 0.8"而数据库预留取"最低利用率"？
→ 一句话提示：数据库负载平稳（min_util 代表全时段下限）；LLM 用量方差大且承诺作废制，取均值会常态化浪费——用较低分位数（P30-P40 等效于均值×0.8）保"几乎每月都用得完"。

**追问 2**："新模型等效价"条款为什么值钱？
→ 一句话提示：LLM 单价趋势快速下降，长承诺锁旧模型价会越锁越贵；等效价条款让承诺额度可迁移到新模型按新价折算，把"技术过期货"风险转回供应商。

## 背诵要点
- 保本逻辑同数据库预留（利用率 ≥ 折扣率才省），但 LLM 特化三条：用量方差大（承诺只覆盖基线，均值×0.8）、模型迭代 = 技术过期货、优化弹性高（先省用量再谈折扣）。
- 谈判清单价值排序：阶梯承诺与结转条款 ≈ 折扣率；加"新模型等效价"条款锁通胀风险。
- 月度对账三列（承诺内/超量/作废浪费），浪费连续两月 >10% = 额度虚高，立即下调。

## 复盘追问
- 承诺额度和多供应商容灾（Q7646）怎么共存？提示：承诺只覆盖"必须走主供应商的基线流量"，容灾切换的超额部分按量承担；切备方触发的承诺作废要在合同里谈豁免条款。
- Prompt 缓存/小模型路由上线后承诺包怎么处理？提示：优化降低用量会让承诺利用率跌破保本——谈判"可下调条款"或把节省的用量转投更贵的旗舰模型（同额度内），对账脚本提前预警。
