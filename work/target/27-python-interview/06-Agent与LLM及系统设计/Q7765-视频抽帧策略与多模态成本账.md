### Q7765 · 十分钟视频丢给模型 token 爆炸：视频抽帧策略与成本账

难度：P6 ｜ 标签：多模态、视频理解、抽帧策略、token 成本、场景检测

基线：Python 3.12；模拟均匀抽帧与场景切换检测两种策略，输出帧数×单帧 token 的成本对比与关键事件召回率，全标准库实跑。

**问**：产品要求"上传会议录像，AI 总结要点"。10 分钟视频按 1 帧/秒全抽是 600 帧，按视觉 token 计价直接爆炸，还可能超请求上限。视频理解怎么抽帧？固定间隔抽和按场景切换抽各适合什么任务？抽帧会漏掉什么信息——怎么评测"抽帧策略够不够用"？

**答**：
- **结论**：视频理解的成本主角是**帧数 × 单帧 token**（Q7681 计价），抽帧策略是成本与信息保留的核心旋钮：① **固定间隔抽帧**（每 N 秒一帧）：实现简单、时间覆盖均匀，适合"内容分布均匀"的视频（讲座、监控）——但运动场景会大量重复帧（静止画面浪费），快速变化场景会漏关键帧；② **场景切换检测抽帧**：计算相邻帧差异（直方图差/特征差），变化超过阈值才抽——动画/转场多的视频帧数砍 70%+ 且信息密度高，缺点是静止长镜头可能一帧不抽（还是要有最小保底频率）；③ **混合策略**是工程默认值：场景检测为主 + 最大间隔保底（超过 30 秒必抽一帧）+ 全局帧数上限（超上限按重要性降采样）。另一个常被忽略的账：**音频轨道优先**——会议录像的 80% 信息在语音里，先转文字（token 便宜）再配少量关键帧，比狂抽视频帧便宜一个数量级（Q7677 语音链路）。抽帧质量要评测：任务级召回（关键事件被抽到帧的比例）与定位精度（时间戳误差），不是"看起来合理"。
- **取舍**：① 分辨率与 token 的二次方账：降分辨率省 token 但 OCR/小字幕失效——按任务定下限（含文字内容不低于可读分辨率）；② 帧数上限与上下文预算联动：视频帧预算占上下文的比例要显式分配（Q7764 分层预算的多模态版）；③ 场景检测的阈值是内容相关的：监控流与快剪视频的最优阈值差几倍，阈值做成任务配置而不是全局常量；④ 处理时延：抽帧+检测在应用侧做（ffmpeg/帧差计算），不让模型自己去"看"整段视频——即不支持整视频输入的模型更是如此。
- **实战**：① 抽帧策略参数化（间隔/阈值/上限/分辨率）进任务配置，按内容类型路由（会议/监控/短视频）；② 成本仪表：每次任务的帧数、token、费用记账（Q7604 用量对账的视频维度）；③ 抽帧质量回归集：标注 20 个"关键事件时间点"，每次调策略跑一遍召回率；④ 长视频走分段流水线（分段抽帧→分段摘要→合并），分段间保上下文衔接帧。

```python
"""视频抽帧策略: 均匀抽帧 vs 场景检测 + 关键事件召回评测。"""
import random


def detect_scenes(frame_diffs: list[float], threshold: float) -> list[int]:
    """场景切换检测: 相邻帧差异超阈值 -> 抽该帧。"""
    return [i for i, d in enumerate(frame_diffs) if d > threshold]


def uniform_sample(n: int, interval: int) -> list[int]:
    return list(range(0, n, interval))


def hybrid_scenes(frame_diffs: list[float], threshold: float,
                  max_gap: int = 30, hard_cap: int = 80) -> list[int]:
    """混合: 场景检测 + 最大间隔保底 + 总量上限。"""
    picked = set(detect_scenes(frame_diffs, threshold))
    last = -max_gap
    for i in range(len(frame_diffs)):
        if i - last >= max_gap:              # 静止长镜头保底
            picked.add(i)
            last = i
        if i in picked:
            last = i
    picked = sorted(picked)
    if len(picked) > hard_cap:               # 超上限均匀降采样
        step = len(picked) / hard_cap
        picked = [picked[int(i * step)] for i in range(hard_cap)]
    return picked


def eval_strategy(picked: list[int], key_events: list[int], tolerance: int = 3) -> float:
    """任务级召回: 关键事件附近(±tolerance 秒)有被抽到的帧才算命中。"""
    hits = 0
    for ev in key_events:
        if any(abs(p - ev) <= tolerance for p in picked):
            hits += 1
    return hits / len(key_events)


if __name__ == "__main__":
    rng = random.Random(42)
    N = 600                                   # 10 分钟, 1fps
    # 帧差异: 会议录像 5 个话题切换点 + 静止背景
    key_events = [80, 210, 340, 470, 560]
    diffs = [rng.uniform(0.01, 0.05) for _ in range(N)]
    for ev in key_events:
        diffs[ev] = rng.uniform(0.30, 0.45)   # 切换点差异大
        for k in (-1, 1):
            if 0 <= ev + k < N:
                diffs[ev + k] = rng.uniform(0.20, 0.30)

    TOKEN_PER_FRAME = 300                     # 视觉 token 每帧
    u = uniform_sample(N, 10)                 # 每 10 秒一帧
    h = hybrid_scenes(diffs, threshold=0.15)

    print(f"均匀抽帧(每10秒): {len(u)} 帧 -> {len(u) * TOKEN_PER_FRAME} token")
    print(f"  关键事件召回: {eval_strategy(u, key_events):.0%}")
    print(f"混合策略(检测+保底+上限): {len(h)} 帧 -> {len(h) * TOKEN_PER_FRAME} token")
    print(f"  关键事件召回: {eval_strategy(h, key_events):.0%}")
    print(f"  成本比: 混合/均匀 = {len(h) / len(u):.0%}")

    # 阈值敏感性: 阈值过高漏召回
    h_tight = hybrid_scenes(diffs, threshold=0.40)
    print(f"阈值 0.40 过严: {len(h_tight)} 帧, 召回 {eval_strategy(h_tight, key_events):.0%} "
          f"-> 切换点漏检")
    ok = len(h) < len(u) and eval_strategy(h, key_events) >= eval_strategy(u, key_events)
    print(f"校验: 混合策略更省且召回不降 -> {'通过' if ok else '异常'}")
    print("\n结论：抽帧=信息保留与 token 成本的核心旋钮; 场景检测+保底+上限;")
    print("      音频优先: 会议录像 80% 信息在语音里, 转文字比抽帧便宜一个量级")
```

**追问一**：抽帧策略怎么评测才算"够用"，不能只看 token 省了多少吧？

→ 解析：对，成本只是半边，另一半是**任务级质量回归**。三层评测：① **事件召回**：标注关键事件的时间点（谁开始发言、屏幕共享开始），策略抽到的帧覆盖这些点的比例——本卡代码的 eval_strategy；② **任务端到端**：同一任务（视频摘要/质检）在两种策略下生成，人工或 LLM-judge 对比要点覆盖度（Q7501 judge 校准）；③ **定位精度**：要求时间戳的应用（"第 3 分 20 秒发生了什么"）测抽帧的时间对齐误差。三个都要进抽帧策略的回归集，调阈值/间隔时跑一遍。常见误区是只测"抽到的帧好不好"，不测"漏掉的帧里有什么"——抽帧的失败是静默的（模型不知道自己没看到），所以评测必须从**事件侧**定义而不是从帧侧定义。

**追问二**：长视频（2 小时培训录像）超出单次上下文怎么办？

→ 解析：**分段流水线**：把视频按语义段（场景检测切分 + 每段最长 N 分钟）切成 K 段，每段独立走"抽帧→音频转写→分段摘要"，再合并层汇总。三个关键设计：① **段间衔接**：每段的输入附加前一段摘要的尾部（滚动上下文，Q2025 增量摘要思想），保证跨段引用（"刚才提到的方案"）不断链；② **成本结构**：K 段串行的总 token ≈ 全视频内容 + K 份衔接摘要，比"一口气塞"可行得多，比"全量文本"省——关键帧只在段级用；③ **失败隔离**：单段处理失败重试该段而不是全部（Q1791 分片认领思想），长任务加断点（段级 manifest，Q2010）。另外两小时录像的音频转写本身就是长任务，按段转写 + 段级时间戳对齐，让摘要的时间引用回到全局时间轴。
