### Q7555 · 评测的 Token 成本账与分层抽样策略

难度：P6 | 标签：LLM 评测、成本工程、分层抽样、回归检测

**问**：评测集 2000 条，团队想在每次 PR 都跑全量回归——一算每月烧 1650 美元模型费。评测的 Token 成本怎么建模？"跑得多"和"测得住"是什么关系？分层抽样怎么省 90% 预算还不漏回归？

**答**：
- **结论**：评测成本 = 用例数 × (输入 token + 输出 token) × 单价 × 触发频率——触发频率是指数级的杠杆：PR 级触发一天 5 次、夜级一天 1 次、周级一月 4 次，同一批用例的成本差 100 倍。省钱的正解是分层而非砍集：golden 固定集（50 条历史 bug 与核心路径）每次 PR 跑——防"历史 bug 复发"，回归检测力主要来自它的稳定性；分层抽样（按类别×难度分层，200 条）每晚跑保分布；全量 2000 条只在周级与发版前兜底。三层月成本 $146 vs 全量随 PR 的 $1650，省 91%。
- **取舍**：抽样会漏"低频新类别"的回归——缓解手段是新类别用例自动进 golden 集（新 bug 一旦发现即固化为回归用例），golden 集随事故增长，比全量跑更聚焦。另一个方向是评测缓存：输入前缀相同的用例共享 KV 缓存，成本再降 30-50%，但要把缓存键按 prompt 版本隔离防止口径漂移。
- **实战**：落地清单：① 每层标注触发时机与预算，进 CI 配置；② 评测账本按层记账，月度复盘"每层成本 vs 拦截的回归数"——投入产出比决定预算再分配；③ 发版前全量是硬门槛，PR 级只允许 golden——把"跑得多"换成"跑得准"。

```python
"""评测的 Token 成本账：全量回归 vs 分层抽样的预算与覆盖权衡。"""
from dataclasses import dataclass

@dataclass
class EvalTier:
    name: str
    cases: int
    trigger: str                     # 触发时机
    input_tokens: int = 2000         # 每用例平均输入
    output_tokens: int = 500

    def cost(self, price_per_m: float = 3.0) -> float:
        """美元成本（输入/输出同价简化）。"""
        tokens = self.cases * (self.input_tokens + self.output_tokens)
        return tokens / 1e6 * price_per_m

TIERS = [
    EvalTier("golden 冒烟", 50, "每次 PR（每开发者每天约 4 次）"),
    EvalTier("分层抽样", 200, "每晚全量跑一次"),
    EvalTier("全量回归", 2000, "每周一次 + 发版前"),
]

def monthly_cost(commits_per_day: int = 5, workdays: int = 22) -> float:
    """三层的月度总成本：PR 级按提交频率、夜级按 30 天、周级按 4 次。"""
    return (TIERS[0].cost() * commits_per_day * workdays
            + TIERS[1].cost() * 30
            + TIERS[2].cost() * 4)

full_only = EvalTier("全量", 2000, "若每次 PR 都全量").cost() * 5 * 22
tiered = monthly_cost()
print(f"{'层':<12}{'用例数':>6}  触发时机")
for t in TIERS:
    print(f"{t.name:<12}{t.cases:>6}  {t.trigger}（单次 ${t.cost():.2f}）")
print(f"\n每次 PR 全量回归月成本 ≈ ${full_only:,.0f}")
print(f"三层抽样方案月成本   ≈ ${tiered:,.0f}（省 {(1 - tiered / full_only):.0%}）")
print("覆盖设计：golden 固定集防'历史 bug 复发'；分层按'类别×难度'抽样保分布；"
      "全量只在发版前兜底——回归检测力来自固定集的稳定性，不来自用例总数")
```

**追问链**：
1. 追问一层：为什么"回归检测力来自固定集的稳定性，不来自用例总数"？——回归的发现依赖"旧用例对新代码的断言稳定可用"；2000 条新抽的用例每轮都变（抽样抖动），分数噪声比回归信号还大，跑得越多越难比。固定集分数可逐条 diff，50 条的回归检出能力反而强于 2000 条的噪声基线。
2. 追问二层：分层抽样的层怎么划才科学？——按"意图类别 × 难度 × 历史失败率"三维分层，每层按比例抽样并保证每层最小样本量（防小层被抽没）；历史失败率高的层超配（回归更容易藏在难点里）。分层方案每年复审一次，随业务分布演化重新划分。

**背诵要点**：
1. 评测成本 = 用例数 × token × 单价 × 触发频率；触发频率是最强杠杆。
2. 三层结构：golden 每 PR（防复发）、分层抽样每夜（保分布）、全量周级/发版前（兜底）。
3. 回归检测力来自固定集稳定性；新 bug 固化进 golden 集，让保护网随事故生长。

**复盘追问**：
1. 为什么"每次 PR 跑全量"的团队最后反而砍掉了回归测试？（预算爆炸 → 被迫降频 → 信号被噪声淹没 → 失去信任；分层化是唯一可持续路径，成本模型先行）
2. 评测用了模型缓存，分数却和上次不一样了，查什么？（缓存键没按 prompt/评测版本隔离——复用了旧版 prompt 的输出；缓存键必须含 prompt 版本与评测集版本）
