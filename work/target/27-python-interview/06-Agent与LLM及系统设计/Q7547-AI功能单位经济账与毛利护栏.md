### Q7547 · 成本工程：一个 AI 功能"看起来免费"，为什么一算账是亏的？

> 难度:★★★★ | 标签:成本工程, 单位经济, 毛利护栏

**问**：产品上线的 AI 助手对用户免费开放，半年后月账单 80 万，团队才发现每个活跃用户的单均成本已超订阅收入。单位经济账怎么算？"每千次调用成本"为什么不够用？毛利护栏（margin guardrail）应该设在哪些环节？

**答**：结论：单位经济账 = **每会话全成本 ÷ 会话数**，全成本不只是模型 token——要加上检索（embedding+向量库查询）、工具调用、重试与失败浪费、评测与回归（Q7555）、存储与日志。账要按"会话"算而不是按"调用"算，因为一次会话包含多次调用，模型 token 只占全成本的 50-70%。毛利护栏设在三处：**功能开关层的每用户预算上限、路由层的成本分级（免费用户降档）、产品层的用量配额**——护栏要在产品设计期就进需求，而不是事故后补。

机理与实战：
- **成本结构拆解**：一个典型 RAG 会话：模型输出 4000 tok ≈ 0.02-0.2 元（按模型档）、检索 3 次 embedding+查询 ≈ 0.005 元、工具调用与重试浪费 ≈ 20-30% 加成、评测/监控分摊 ≈ 10%。看似"一次几分钱"，乘上"活跃用户 × 日均会话 × 10 轮"就是月度 6-7 位数——单位经济的杀手是**频次不是单价**。
- **成本可归因设计**：每个会话从入口注入 `session_id + user_tier + scenario`，全链路（网关、检索、工具）按此打标签，月末账单按 (tier, scenario) 聚合——没有归因标签的 AI 功能等于"无主成本"，永远算不清盈亏。
- **毛利护栏三环**：① 入口环：免费 tier 用户走降档模型+限轮次（如 5 轮/会话），超限提示升级；② 配额环：每用户每日 token 预算，预算耗尽降级到"纯检索无生成"模式；③ 电路环：单会话成本超阈值（如 2 元）熔断并记 badcase——三环都要"软降级"而非硬报错，体验曲线平滑。
- **定价联动**：单位经济账反过来指导定价：订阅价 = 目标毛利（如 60%）反推允许的每用户月成本，倒逼成本工程目标（上下文裁剪、缓存、分级）量化成"每会话成本从 0.8 元降到 0.3 元"的工程任务。

```python
# 基线:Python 3.10+;纯标准库,会话单位经济账与毛利护栏模拟
from __future__ import annotations
from dataclasses import dataclass, field


@dataclass
class SessionCost:
    model_tokens_in: int
    model_tokens_out: int
    retrieval_calls: int
    tool_calls: int
    retries: int = 0

    PRICE_IN = 8.0    # 元/百万输入 tok
    PRICE_OUT = 24.0  # 元/百万输出 tok
    RETRIEVE = 0.002  # 元/次检索
    TOOL = 0.001      # 元/次工具
    OVERHEAD = 1.25   # 重试/失败浪费 25% 加成


def session_cost(s: SessionCost) -> float:
    llm = s.model_tokens_in / 1e6 * s.PRICE_IN + s.model_tokens_out / 1e6 * s.PRICE_OUT
    aux = s.retrieval_calls * s.RETRIEVE + s.tool_calls * s.TOOL
    return (llm + aux) * s.OVERHEAD


@dataclass
class MarginGuard:
    per_session_cap: float = 2.0      # 单会话熔断阈值
    daily_user_budget: float = 1.0    # 每用户日预算
    spent: dict[str, float] = field(default_factory=dict)

    def guard(self, user: str, session_spent: float) -> str:
        if session_spent > self.per_session_cap:
            return "circuit-break"          # 会话熔断,记 badcase
        if self.spent.get(user, 0) + session_spent > self.daily_user_budget:
            return "degrade"                # 降级:纯检索无生成
        self.spent[user] = self.spent.get(user, 0) + session_spent
        return "ok"


def demo() -> None:
    # 免费用户典型会话:10 轮对话
    heavy = SessionCost(model_tokens_in=40_000, model_tokens_out=8_000,
                        retrieval_calls=10, tool_calls=6, retries=4)
    cost = session_cost(heavy)
    print(f"重度会话成本: {cost:.3f} 元/次")
    assert 0.3 < cost < 0.8
    # 月账单推演:5 万活跃用户 × 日 2 次
    monthly = cost * 50_000 * 2 * 30
    print(f"月账单推演: {monthly:,.0f} 元")
    assert monthly > 500_000          # 频次杀手:单价低 × 频次高
    g = MarginGuard(daily_user_budget=1.0)
    assert g.guard("u1", 0.6) == "ok"       # 第 1 次会话放行
    assert g.guard("u1", 0.6) == "degrade"  # 第 2 次超日预算,降级
    assert g.guard("u2", 2.5) == "circuit-break"  # 单会话超 2 元熔断
    # 降档模型后的对比
    heavy_cheap = SessionCost(model_tokens_in=40_000, model_tokens_out=8_000,
                              retrieval_calls=10, tool_calls=6, retries=2)
    SessionCost.PRICE_IN, SessionCost.PRICE_OUT = 1.0, 4.0   # 换轻量模型
    c2 = session_cost(heavy_cheap)
    print(f"降档+减重试后: {c2:.3f} 元/次 (省 {(1 - c2 / cost):.0%})")
    assert c2 < cost * 0.5
    print("单位经济:按会话算全成本,护栏三环=入口降档/日预算降级/单会话熔断 ✅")


if __name__ == "__main__":
    demo()
```

**追问一**：为什么"每千次调用成本"指标在管理层汇报里是误导？
答：调用次数不可比——一次调用可能是 200 tok 的分类任务，也可能是 20k tok 的多轮 Agent 步骤；按调用平均会把结构差异抹平，出现"千次成本降了、总账单涨了"的悖论（调用结构向重型漂移）。正确指标是按 (scenario, tier) 的**每会话成本**与**总成本增长率 vs 业务量增长率**的比值——单位经济是否恶化看后者。

**追问二**：免费用户的护栏设太严会伤增长，怎么定这个度？
答：护栏是产品决策不是纯成本决策：① 用历史数据分段——90% 用户月用量 < 预算的 20%，收紧护栏只影响头部 5% 高消耗用户（往往是爬虫/批量滥用），对增长无伤；② 降级路径要保留价值感（降档模型仍可用，只是变慢/变浅）；③ 护栏参数 A/B 实验——两档护栏跑两周对比留存与成本，用数据定档而不是拍脑袋。

## 背诵要点
- 单位经济按会话算全成本：模型 token 只占 50-70%，加检索/工具/重试浪费（20-30% 加成）/评测分摊；杀手是频次不是单价（单价几分钱 × 月度高频 = 六位数账单）。
- 归因先行：session_id+user_tier+scenario 全链路打标签，账单按 (tier, scenario) 聚合；无标签 = 无主成本。
- 护栏三环：入口降档限轮次（免费 tier）→ 每用户日预算耗尽降级"纯检索"→ 单会话超阈值熔断记 badcase；全部软降级不硬报错。

## 复盘追问
- 为什么半年没人发现这个功能在亏钱？（提示：AI 成本记在"云服务"大项里没有按功能归因，且免费功能没有收入对冲信号；治理起点是给每个 AI 功能立成本科目+月度单位经济报表，异常环比自动触发评审）
- 护栏上线后某企业客户投诉"功能变浅了"，护栏与商业承诺冲突怎么解？（提示：护栏按 tier 分层设计——企业 tier 的预算与档位单独配置并写进 SLA；个人护栏误伤企业用户说明 tier 标签没有在入口正确传递，先修归因再调参数）
