### Q7567 · 向量距离度量与归一化实测选型

难度：P6 | 标签：embedding、距离度量、归一化、检索

**问**：建向量索引时 metric 选 cosine、内积（dot）还是 L2？为什么说"归一化"是度量选型的前提？选错了排序会怎么错？

**答**：
- **结论**：三者关系：向量归一化后，内积 ≡ 余弦（排序完全一致），且 L2 与余弦单调等价——归一化世界里三选一只是性能差异。未归一化时差异致命：内积偏向模长大的向量（长文本 embedding 模长天然大，"话痨文档"永远排前面），L2 同时考虑方向与模长，与余弦排序可能不同。实践基线：先归一化，metric 选内积（计算最快、主流索引 HNSW/IVF 对内积优化最好）；除非业务确实需要"模长即信息"（如 TF-IDF 词向量的绝对强度），才考虑 L2/未归一化。
- **取舍**：归一化的代价：丢失模长信息——某些模型（如 CLIP 类多模态）训练目标依赖未归一化的内积，强行归一化会伤效果；选型前查模型文档（检索模型通常明确要求归一化+余弦/内积）。索引侧：pgvector 里 vector_ops.ops 的操作符类与 metric 绑定，建索引后换 metric = 全量重建。
- **实战**：选型验证方法：抽样 1000 个真实 query，分别用三种 metric 取 top-10，计算与人工标注相关的 recall 差异；差异应接近零（归一化后），不为零说明数据没归一化或有 bug。另一个实测点：量化（int8）后再比 metric 的排序漂移——量化与度量组合会互相影响。

```python
"""向量距离度量选型实测：归一化后内积≈余弦；未归一化时排序会漂移。"""
import math

def dot(a, b): return sum(x * y for x, y in zip(a, b))
def norm(a): return math.sqrt(dot(a, a))
def cosine(a, b): return dot(a, b) / (norm(a) * norm(b) + 1e-9)
def l2(a, b): return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

q = [0.9, 0.1]
docs = {"A_同向长文档": [3.0, 0.3], "B_近似方向短文档": [0.5, 0.4]}

for name, d in docs.items():
    print(f"{name}: dot={dot(q,d):.2f} cos={cosine(q,d):.3f} l2={l2(q,d):.2f}")

qa, A = [0.9, 0.1], [3.0, 0.3]
print("归一化后 dot == cos:", abs(dot([x/norm(qa) for x in qa], [x/norm(A) for x in A]) - cosine(qa, A)) < 1e-9)
print("要点：归一化是度量选型的前提；未归一化时内积偏向长向量，L2 兼顾方向与模长")
```

**追问链**：
1. 追问一层：为什么归一化后 L2 与余弦单调等价？（||a-b||² = 2 - 2·cosθ（单位向量），L2 最小 ⟺ 余弦最大；所以排序一致，选哪个只看索引实现效率）
2. 追问二层：换 metric 为什么要重建索引？（HNSW/IVF 的图/聚类按建索引时的距离构建，换 metric 等于换空间几何，旧索引结构失效）

**背诵要点**：
1. 归一化前提下内积≡余弦、L2 单调等价，选型只看索引效率。
2. 未归一化用内积会偏向长向量——"长文档霸榜"的经典 bug。
3. 模型文档可能要求特定 metric；换 metric 必须重建索引。

**复盘追问**：
1. 检索结果里某类文档永远排最前，为什么先查归一化？（长向量在内积下占优——度量与数据预处理不匹配）
2. 为什么"抽样 query 对比三种 metric 的 recall"是必要的验证？（度量选型的正确性只能用真实分布验证，理论等价的前提可能不成立）
