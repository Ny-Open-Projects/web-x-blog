### Q7767 · .png 实为脚本：多模态输入的魔数校验与伪装文件拦截

难度：P6 ｜ 标签：文件校验、魔数、MIME 白名单、polyglot、多模态安全

基线：Python 3.12；实现基于文件头魔数的类型校验器与白名单门禁，演示伪装文件与 polyglot 文件的拦截，全标准库实跑。

**问**：Agent 的图片分析工具接收用户上传文件，按扩展名分发处理。安全扫描发现有人把 Python 脚本改名成 `invoice.png` 上传——扩展名校验形同虚设。文件类型的可信校验怎么做？什么是 polyglot 文件（同时是合法的两种格式）？拦下伪装文件后，给模型的错误信息该怎么写？

**答**：
- **结论**：文件类型的可信来源只有**内容本身**：读取文件头魔数（magic bytes）与声明格式比对——PNG 固定头 `\x89PNG\r\n\x1a\n`、JPEG `FF D8 FF`、PDF `%PDF-`、ZIP `PK\x03\x04`。门禁三步：① **魔数校验**：前 16 字节比对魔数表，不匹配即拒绝；② **白名单**：按工具声明可接受的格式集合（图片分析只收 PNG/JPEG/WebP），白名单外的格式拒绝，而不是黑名单"封杀已知危险格式"——黑名单永远漏（Q1015 暴露面收敛思想）；③ **尺寸与深度前置**：文件大小上限（Q7763 体积门禁）与解压炸弹防护（ZIP 内文件数/解压后大小上限）在魔数校验同层完成。**Polyglot** 是进阶威胁：一个文件同时满足两种格式的结构（比如 ZIP+JPEG 的拼接体，JPEG 查看器看是图、解压是 ZIP）——防御是"按声明的唯一格式解析，解析器拒绝尾部多余数据"（PNG 解码器遇到 PNG 结束标记后还有内容即拒绝），而不是"能解析出什么就用什么"。
- **取舍**：① 魔数表的自维护 vs 引入库：核心格式（十来种）手写魔数表够用且零依赖，冷门格式（Office 的 OLE 头、TTNF）用 `python-magic` 类库——面试手写魔数表展示原理，生产用库+魔数表兜底；② 拒绝时的错误信息要**可行动**：给模型的信息含"检测到的实际类型 + 建议动作"（"该文件实际是文本/脚本，图片分析不可用；如需处理请改用 code_interpreter 工具"），驱动模型换路径而不是重试上传（Q7524 自愈循环的输入）；③ 校验的位置：上传入口统一做（一次校验处处可信），工具侧不再重复——但要防"旁路上传"（对象存储直传 URL 绕过入口，Q6064 预签名直传的扫描钩子）；④ 魔数校验不是杀毒：恶意内容的深度扫描（EICAR 测试串、隐写载荷）是另一个层面，别把两类防护混为一谈。
- **实战**：① 上传管线的校验顺序固定：大小→魔数→白名单→（可选）病毒扫描→入库；② 校验结果与实际类型写进附件元数据，下游工具按"验证过的类型"路由而不是按扩展名；③ 拦截事件计数进监控：伪装文件突增可能是攻击探测（Q1126 安全审计的输入源）；④ 评测集加伪装样本（改名的脚本、polyglot 文件），门禁的拦截率是回归项。

```python
"""文件魔数校验: 魔数表 + 白名单门禁 + polyglot 尾部检查。"""
import binascii

MAGIC = {
    b"\x89PNG\r\n\x1a\n": "png",
    b"\xff\xd8\xff": "jpeg",
    b"%PDF-": "pdf",
    b"PK\x03\x04": "zip",
}

ALLOWED = {"png", "jpeg"}          # 图片分析工具的白名单
MAX_SIZE = 5 * 1024 * 1024


def sniff(head16: bytes) -> str | None:
    for magic, fmt in MAGIC.items():
        if head16.startswith(magic):
            return fmt
    return None


def guard_upload(filename: str, size: int, head16: bytes,
                 tail: bytes = b"") -> tuple[bool, str]:
    """上传门禁: 大小 -> 魔数 -> 白名单 -> (png) 尾部多余数据检查。"""
    if size > MAX_SIZE:
        return False, f"文件 {size / 1e6:.1f}MB 超过 5MB 上限"
    real = sniff(head16)
    if real is None:
        return False, ("无法识别文件类型 (魔数不匹配任何已知格式)。"
                       "请上传真实格式的图片文件")
    if real not in ALLOWED:
        return False, (f"文件实际类型 {real} 不在图片分析白名单内; "
                       f"如需处理请改用对应工具")
    if real == "png":
        # polyglot 防御: PNG 数据块结束后 (IEND) 不允许再有数据
        if b"IEND" in head16 + tail and tail:
            return False, ("PNG 结束标记后存在多余数据, 疑似拼接文件, 已拒绝")
    return True, f"校验通过: 声明 {filename.split('.')[-1]}, 实际 {real}"


def make_file(head: bytes, tail: bytes = b"") -> tuple[int, bytes]:
    return len(head) + len(tail), head + tail


if __name__ == "__main__":
    # 合法 PNG
    png_head = b"\x89PNG\r\n\x1a\n" + b"\x00" * 8
    ok, msg = guard_upload("invoice.png", *make_file(png_head))
    print(f"合法 PNG:    {ok} -> {msg}")

    # 伪装: 脚本改名 .png (魔数是 Python 文本)
    script = b"#!/usr/bin/env python3\nimport os\nos.system('id')\n"
    ok2, msg2 = guard_upload("invoice.png", *make_file(script[:16]))
    print(f"伪装脚本:    {ok2} -> {msg2}")

    # PDF 冒充图片
    ok3, msg3 = guard_upload("photo.png", *make_file(b"%PDF-1.7\n"))
    print(f"PDF 冒充:    {ok3} -> {msg3}")

    # polyglot: 合法 PNG 头 + IEND 后拼 ZIP (解压炸弹/夹带)
    poly_head = b"\x89PNG\r\n\x1a\n" + b"IEND" + b"\xaeB`\x82"
    poly_tail = b"PK\x03\x04" + b"\x00" * 8          # IEND 之后藏 ZIP
    ok4, msg4 = guard_upload("trap.png", len(poly_head) + len(poly_tail),
                             poly_head[:16], poly_tail)
    print(f"polyglot:    {ok4} -> {msg4}")

    ok_all = ok and not ok2 and not ok3 and not ok4
    print(f"\n校验: 白名单放行 + 三类伪装全拦截 -> {'通过' if ok_all else '异常'}")
    print("\n结论：类型只信内容魔数不信扩展名; 白名单拒黑名单;")
    print("      polyglot 用'声明的唯一格式解析+拒绝尾部多余数据'防御")
```

**追问一**：为什么白名单优于黑名单，polyglot 为什么不能靠"多格式都校验一遍"解决？

→ 解析：黑名单是"已知威胁清单"，永远滞后于新威胁——今天封了 `.exe/.sh/.php`，明天来个 `.wasm` 或自定义格式，黑名单就是漏的。白名单把默认状态设为拒绝，新格式必须经评审显式加入——暴露面收敛的通用原则（Q1015 ACL、Q2011 许可证 deny/allow 清单同一思想）。polyglot 靠"每种格式都校验"无解，因为 polyglot 的定义就是**在每种声称的格式下都合法**——JPEG 校验器看它是合法 JPEG，ZIP 校验器看它是合法 ZIP，都通过。真正的防御是**单一格式契约**：声明为 PNG 就只允许 PNG 解码器解析，解码器在结构结束标记（IEND）后遇到任何剩余字节即报错拒绝——合法的 PNG 数据流在 IEND 就结束了，后面的"额外内容"必然不是图片本身。这把校验从"这是什么"升级为"它是不是**只有**它声称的东西"。

**追问二**：拦下伪装文件后，错误信息怎么写才能让 Agent 正确自愈？

→ 解析：错误信息是给模型看的 API 契约，写法决定自愈成败。三个要素：① **事实**：检测到的实际类型（"实际为文本/脚本，魔数不匹配任何图片格式"）——模型据此知道不是网络问题或格式转换问题；② **边界**：明确这个工具处理不了（"图片分析工具仅接受 PNG/JPEG/WebP"）——防止模型重试同样的调用；③ **出口**：可行动的替代路径（"如需分析该文件内容，请改用代码执行工具或文档问答工具"）。反例是裸返回"Invalid file"：模型会反复重试、换参数瞎试，烧掉步数预算（Q7511）。另外拦截事件要**结构化上报**（事件类型=伪装文件，实际类型，来源用户），而不只是返回给模型——监控上伪装文件的来源聚集（同一会话/同一用户反复尝试）是攻击探测信号，这个信号只有在统一拦截层记录才能聚合出来。
