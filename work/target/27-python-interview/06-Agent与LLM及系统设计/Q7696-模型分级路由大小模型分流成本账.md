### Q7696 · 模型分级路由：大小模型分流的成本账

难度：P6 ｜ 标签：成本工程、模型路由、分级降级、质量分层

基线：Python 3.9+；多档模型（旗舰/中档/小型）价格梯度约 20x/5x/1x；路由分类器（小模型或规则）。

**问**：所有请求都在打旗舰模型，月费 20 万。业务分析说 70% 的请求其实"很简单"（改写、分类、抽取）。做"大小模型分流"这笔账怎么算？路由错了怎么办？什么请求永远不该降级？

**答**：
- **结论**：分流账 = Σ(每档请求量 × 该档单价) + 路由器成本 + 纠错成本。关键参数是**路由准确率与错误的代价不对称性**：把"难请求"错分到小模型 → 质量下降（需重试/升级补一次旗舰调用，成本反而 ×1.2）；把"易请求"错分到旗舰 → 只是没省钱。所以路由器设计要"宁可保守"：置信度不够就走旗舰。价格梯度 20x 意味着哪怕路由器只把 50% 的真·简单请求分出去，也砍掉近一半账单。
- **取舍**：路由器本身三选一：规则（便宜、糙）、小模型分类（准、有成本）、让小模型先答 + 置信度低再升级旗舰（cascade，成本最优但延迟翻倍）。什么不该降级：强推理/长上下文/安全敏感场景直接白名单走旗舰；新流量模板未经验证的也先全走旗舰，攒了分流评测再放开。
- **实战**：落地三步——(1) 离线评测：抽样请求同时跑两档模型，用 judge/人工标出"小模型等效"的比例与场景特征；(2) 路由器上线带灰度：先 10% 流量，对比质量指标（CSAT/任务完成率）与成本曲线；(3) 全链路记账：按"请求特征→路由档位→质量结果"建报表，路由策略季度复盘调参。

```python
# 分级路由成本账与灰度收益模拟（标准库可运行）。
def route_cost(monthly_reqs: int, simple_ratio: float, route_acc: float,
               price_flagship: float, price_small: float,
               escalate_cost: float = 1.2) -> dict:
    """simple_ratio: 真·简单请求比例；route_acc: 路由准确率(双向)。
    错分难请求到小模型 -> 升级重试成本 escalate_cost × 旗舰价。"""
    simple = monthly_reqs * simple_ratio
    hard = monthly_reqs - simple
    to_small = simple * route_acc                      # 正确分流
    misrouted_hard = hard * (1 - route_acc)            # 难请求被误降级
    cost = (monthly_reqs - to_small - misrouted_hard) * price_flagship \
         + to_small * price_small \
         + misrouted_hard * price_flagship * escalate_cost
    baseline = monthly_reqs * price_flagship
    return {"月费": round(cost), "全旗舰月费": round(baseline),
            "节省": f"{(1 - cost / baseline):.0%}",
            "误降级请求": int(misrouted_hard)}

if __name__ == "__main__":
    r = route_cost(monthly_reqs=1_000_000, simple_ratio=0.7, route_acc=0.9,
                   price_flagship=0.02, price_small=0.001)
    for k, v in r.items():
        print(f"{k}: {v}")
    # 全旗舰 20000 元 -> 分流后 8150 元，省 59%；误降级 3 万难请求要 1.2 倍补救。
    # route_acc 掉到 0.7 时误降级涨到 9 万 -> 路由器质量是命门，宁可保守。
```

**追问**：
- 一层：为什么 cascade（小模型先答）比前置分类器更省但延迟更差？→ 提示：cascade 每个请求都先付一次小模型调用（含延迟），只有置信度低的才二次付费；对延迟敏感场景不适用。
- 二层：路由准确率怎么持续保证不漂移？→ 提示：流量分布会变（新功能、新话术），定期抽样重评 + 路由器版本与分流策略一起灰度；监控"升级重试率"上升即路由劣化信号。

**背诵要点**：
1. 分流账 = 各档请求量×单价 + 路由成本 + 纠错成本；价格梯度 20x 下分出 50% 简单请求就砍半账单。
2. 错误代价不对称：难请求误降级要 1.2 倍旗舰费补救，路由器宁可保守（低置信走旗舰）。
3. 不降级白名单：强推理/长上下文/安全敏感 + 未验证新流量；上线必灰度，看升级重试率。

**复盘追问**：
1. 为什么当初全走旗舰没人提分流？提示：缺"请求难度分布"数据；应先建按特征的成本报表再谈优化。
2. 如果分流后客诉变多但成本降了 60%，怎么决策？提示：把客诉成本折算进账（人力/流失），质量红线优先于成本。
