### Q7651 · 会话恢复重放工具副作用复盘

难度：P6-P7 | 标签：Agent 可靠性、幂等、事故复盘

**问**：Agent 长任务中途进程崩溃，恢复时从检查点重放，结果"发邮件"工具被执行了两次，客户收到两封重复邮件。重放为什么有副作用？恢复语义该怎么设计？

**答**：结论：检查点通常只保存**对话状态**，不保存"工具是否已在真实世界生效"——重放对话到中断点时，未落检查点的工具调用会再次执行。正确恢复语义是两层：① 检查点粒度对齐副作用：每次工具调用完成后先记"已执行回执"再继续，恢复时对照回执跳过已完成步骤；② 副作用工具全部幂等化：客户端生成幂等键随调用传入，服务端按键去重（Q6644 幂等表同款机制）。取舍：回执记录增加检查点写频率，但换来"恢复即精确续跑"。

实战要点：
1. 副作用分级：只读工具（查询）重放无害直接重跑；写工具（发信、下单、退款）必须幂等键+回执。
2. 幂等键来源用"步骤 ID"（检查点里的 step 序号），不要用请求参数哈希——参数相同不代表意图相同。
3. 恢复后先做一致性巡检：比对回执表与外部系统（邮件已发列表），缺口补跑、冲突报警。

```python
"""检查点回执 + 幂等键的重放控制（标准库，可运行）"""
from dataclasses import dataclass, field


@dataclass
class SideEffectLog:
    """服务端视角的幂等去重表"""
    done: set[str] = field(default_factory=set)

    def execute(self, idem_key: str, fn, *args) -> str:
        if idem_key in self.done:
            return f"dedup: {idem_key} already executed"
        self.done.add(idem_key)
        return fn(*args)


@dataclass
class Checkpoint:
    steps: list[dict] = field(default_factory=list)

    def record_done(self, step_id: str, result: str) -> None:
        self.steps.append({"step": step_id, "result": result,
                           "done": True})


def send_email(to: str) -> str:
    # 真实世界副作用（演示中只是打印）
    print(f"[真实副作用] 邮件已发 -> {to}")
    return f"sent to {to}"


def resume(cp: Checkpoint, world: SideEffectLog) -> None:
    plan = [("s1", ("send_email", "a@x.com")),
            ("s2", ("send_email", "b@x.com"))]
    for step_id, (tool, to) in plan:
        already = any(s["step"] == step_id for s in cp.steps)
        if already:
            print(f"{step_id}: 回执存在，跳过重放")
            continue
        result = world.execute(step_id, send_email, to)  # 幂等键=step_id
        cp.record_done(step_id, result)


# 第一次崩溃前：s1 已完成并落回执
cp = Checkpoint()
world = SideEffectLog()
resume(cp, world)
print("--- crash, resume ---")
resume(cp, world)  # s1 跳过，s2 幂等执行
```

**追问 1**：如果工具是第三方 API、不支持幂等键，怎么办？
**提示**：在应用侧做前置登记（发前先写"待执行"记录，成功后更新），恢复时发现"待执行未确认"先查证再补发，等价于自建 outbox。

**追问 2**：回执与对话状态的原子性怎么保证？
**提示**：同一事务/同一写批次落库；只落对话不落回执，恢复时仍可能重放——这正是事故的成因。

## 背诵要点
- 检查点只存对话状态救不了副作用；恢复要靠"步骤回执 + 幂等键"两层。
- 幂等键用步骤 ID 而非参数哈希；写工具前置 outbox 登记可兜第三方无幂等。
- 恢复后先比对回执与外部系统做一致性巡检，再继续跑。
