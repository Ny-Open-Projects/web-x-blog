### Q7818 · 输出格式漂移检测：契约校验、窗口违约率与熔断自愈

难度：P6 ｜ 标签：格式漂移、输出契约、JSON 校验、违约率、熔断、few-shot 降级、归因

基线：库外知识卡，代码用标准库模拟契约校验与违约率窗口监控，不调用外部 API。

**问**：让模型输出 JSON 的功能上线三个月后突然大面积解析失败，开发说"没人改过东西"。检查发现模型输出开始带口语前缀（"好的，结果如下：{...}"），有时干脆全散文。格式契约怎么设计校验？违约率怎么监控？突然漂移怎么自愈与归因？

**答**：

- **结论**：格式契约的校验要**分层统计而不是一刀切拒绝**：第一层解析成功性（裸 JSON 可解析 / 剥离包围文本后可解析 / 完全不可解析），第二层字段契约（必需字段存在性 + 类型正确性），第三层值域（enum/范围）。每层的违规计数进**时间窗违约率**（如每千次请求的违约数），违约率上升是"格式契约正在被破坏"的早期信号——它不是异常告警而是趋势告警。违约率超过阈值触发**熔断自愈**：自动切换到强约束模式（few-shot 示例引导、lower temperature、失败重试），而不是继续裸奔让下游解析错误堆积。漂移的归因三问：换模型了？改提示词了？升温了？——变更时间线与违约率上升时间对齐即可定位；三者都没变，则怀疑上游服务行为变化或流量分布变化（新话题域触发新失败模式）。
- **取舍**：校验的宽严要按下游消费方式定：下游机器消费（API 响应、入库）必须严契约（第一层都过不了直接重试）；下游是人或后处理解析器，可容忍剥离包围文本（宽松解析 + 违约计数）。熔断的代价与收益也要算：few-shot 每请求多几百 token，只有违约率高的窗口才值得开启，恢复后自动回落——这是"契约值守卫 + 自愈降级"的闭环。另一个关键取舍：**重试 vs 修复**——格式失败重试（原样再问）成功率不高（模型往往重复同样错误），带反馈的重试（把解析错误的具体信息回传："confidence 应为数字，收到字符串"）成功率显著提升，每次重试预算 2 次。漂移监控最大的坑是只统计"解析失败率"不统计"字段类型漂移"——后者（confidence 变字符串）能通过宽松解析悄悄进入下游，造成静默错误。
- **实战**：一次"没人改过东西"的漂移事故：JSON 输出违约率从 0.2% 爬到 19%。归因时间线对上了两周前的一次"无害"提示词微调（改了一个形容词）——该词让模型更倾向于"解释性回答"，进而带出口语前缀。短期：熔断开启 few-shot + 带反馈重试，违约率回落 0.4%；长期：提示词变更纳入评审（凡影响输出契约的措辞必须跑格式回归评测集），宽松解析（剥前缀）保留但计独立违约指标。另外补了一条监控：**字段类型漂移单独计数**——评审时发现 confidence 字符串化在事故前两周就有 0.3% 的苗头，只是没被监控。规范沉淀：契约分层校验 + 分层计数 + 时间窗趋势，缺一层就少一个早期信号。

下面模拟契约分层校验、违约率窗口与熔断自愈。

```python
# Q7818 输出格式漂移检测: 契约校验 / 漂移趋势 / 阈值熔断
import json, re

def parse_json_loose(text):
    try:
        return json.loads(text), None
    except json.JSONDecodeError as e:
        m = re.search(r"\{.*\}", text, re.S)
        if m:
            try:
                return json.loads(m.group(0)), f"包围文本剥离后可解析 ({e.msg})"
            except json.JSONDecodeError:
                pass
        return None, str(e)

CONTRACT = {"action": str, "confidence": (int, float), "items": list}

def check_contract(obj):
    if obj is None:
        return ["parse_failed"]
    errs = []
    for k, tp in CONTRACT.items():
        if k not in obj:
            errs.append(f"missing:{k}")
        elif not isinstance(obj[k], tp):
            errs.append(f"type:{k}")
    return errs

# [1] 契约校验: 好输出/坏输出/包文本输出
samples = [
    '{"action": "reply", "confidence": 0.9, "items": [1]}',
    '{"action": "reply", "confidence": "0.9", "items": [1]}',          # 类型漂移
    '好的, 结果如下: {"action": "reply", "confidence": 0.8, "items": []} 希望有帮助',  # 包文本
    '直接回答: 不需要工具。',                                           # 完全脱格式
]
for s in samples:
    obj, note = parse_json_loose(s)
    errs = check_contract(obj)
    print(f"[1] {s[:24]!r:<28} → {'OK' if not errs else errs} {note or ''}")

# [2] 漂移率按时间窗统计: 合同违约率上升 = 模型/提示/温度变化的早期信号
def drift_rate(batch):
    bad = sum(1 for s in batch if check_contract(parse_json_loose(s)[0]))
    return bad / len(batch)

d1 = drift_rate(samples[:1] * 10)      # 早期: 0%
d2 = drift_rate([samples[3]] * 3 + samples[:1] * 7)   # 现在: 30%
print(f"[2] 漂移率: 早期 {d1:.0%} → 当前 {d2:.0%} (上升 = 格式契约正在被破坏)")
assert d1 == 0 and d2 > 0

# [3] 熔断与自愈: 违约率超阈值 → 切换强约束(示例引导/重试)而不是继续裸奔
THRESHOLD = 0.2
def gate(rate, strategy):
    if rate <= THRESHOLD:
        return strategy
    return strategy + "+few-shot+重试"     # 降级到强约束

print(f"[3] 熔断: {d2:.0%} > {THRESHOLD:.0%} → 切换为 '{gate(d2, 'json-mode')}'")
assert d2 > THRESHOLD

# [4] 归因三问: 换模型了? 改提示了? 升温了? 漂移不是玄学是变更
changes = {"model": "v2", "prompt": "v7", "temperature": 0.7}
print(f"[4] 归因检查点: model={changes['model']}, prompt={changes['prompt']}, temperature={changes['temperature']} — 与违约率上升时间对齐")
assert True
print("    → 实测 格式漂移要按窗口监控违约率: 上升→熔断到强约束模式→对齐变更时间线找根因")
```

**追问一**：为什么"字段类型漂移"比"解析失败"更危险？—— 解析失败是显性错误：下游立刻报错、告警响起、可以重试。类型漂移（confidence 变字符串、items 变字符串）在宽松解析下"成功"进入下游：字符串 confidence 参与 `if conf > 0.8` 会 TypeError（显性），但 Python 的真值比较或 JS 的弱类型会让它静默通过——"0.9" > 0.8 在 JS 里为 false（字符串比较），业务判断悄悄错掉。所以校验分层里类型检查必须独立计数、独立告警，宽松解析（剥前缀）只能救"包围文本"不能放过类型错误。这也是"解析成功 ≠ 契约满足"的核心：解析层和契约层必须两把尺子。

**追问二**：带反馈的重试为什么比原样重试有效？预算怎么定？—— 原样重试是把同样的输入再发一遍，模型大概率重复同样的格式错误（同分布采样）；带反馈重试把解析器报错的具体信息（"confidence 应为数字，收到 '0.9'"）拼进重试提示，模型有明确的修复目标，成功率实测从 ~40% 提升到 ~90%。预算定为 2 次：第一次失败多为偶发（温度抖动），反馈修复一次基本解决；连续两次失败说明系统性漂移（提示/模型变更），重试已无意义，该走熔断链路（few-shot 引导）而不是继续烧。预算内失败要计数上报——它是违约率的组成部分，不能因为"重试成功了"就当无事发生。

## 背诵要点

- 契约分层校验：解析成功性 → 字段存在/类型 → 值域；每层独立计数进时间窗违约率，违约率是趋势告警不是异常告警。
- 解析成功 ≠ 契约满足：类型漂移（"0.9" 字符串化）在宽松解析下静默进下游，比解析失败更危险，必须独立监控。
- 违约超阈值熔断到强约束（few-shot + 带反馈重试，预算 2 次）；归因三问：模型/提示词/温度与违约上升时间线对齐。

## 复盘追问

- "没人改过东西"但违约率从 0.2% 爬到 19%，你怎么定位到两周前的一次提示词微调？（变更日志与违约率时间线对齐；提示词 A/B 重放旧流量验证该词确实引出口语前缀——归因要复现而不是猜测）
- 为什么宽松解析（剥前缀）要保留但单独计数？（业务可用性与健康度分离：剥前缀让下游不中断，但计数暴露"契约正在松动"，是升级到强约束模式的触发信号）
