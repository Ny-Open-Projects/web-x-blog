### Q7782 · 出了事查不到谁按的按钮：工具调用链的安全审计日志

难度：P6 ｜ 标签：审计日志、工具调用链、防篡改、脱敏、哈希链

基线：Python 3.12；实现工具调用的审计事件模型（调用 ID 串联链路、敏感字段脱敏、哈希链防篡改），对比 trace 可观测性与审计合规的边界，全标准库实跑。

**问**：Agent 执行了一串工具调用，误删了线上配置——事后要回答"是谁、在哪个会话、用了什么参数、结果是什么"，trace 系统里居然拼不出来。审计日志与 trace/observability 的区别在哪？审计事件要记录哪些字段？审计日志自身怎么防篡改？

**答**：
- **结论**：trace 与审计回答两个问题：trace 回答"**这次执行是怎么发生的**"（性能、路径、归因，Q7519），审计回答"**谁在什么时候对什么做了什么，结果如何**"（合规、追责、回放）——审计的核心属性是**不可抵赖与不可篡改**，trace 的采样/过期策略对审计不适用。工具调用审计事件的最小字段集：`audit_id`（全局唯一）、`trace_id`（与观测系统关联的桥）、`principal`（触发者：用户 ID/服务身份，**服务端注入不许模型填**，Q2831 身份字段注入的同族纪律）、`session_id`、`tool` 与参数（脱敏后）、`decision`（授权结果）、`result` 摘要（不存全量返回体）、时间与顺序号。防篡改的工程栈：**追加写**（audit-only，无更新无删除）+ **哈希链**（每条记录 hash(prev_hash + payload)，链头定期锚定到外部不可变存储——WORM 存储/另一系统的日志）+ 访问控制（审计系统本身只有追加与只读权限）。脱敏的两难：审计要"够用的真相"，脱敏过度等于没审计（查不出误删时传了什么参数），脱敏不足是二次泄漏（Q1169 合规日志的同族取舍）——正确粒度是**参数结构保留、敏感值掩码 + 单向引用**（存参数指纹，原文放加密的独立存储，授权后可解密回查）。
- **取舍**：① 审计与业务同库同事务 vs 异步旁路：同事务保证"操作没落库审计必落库"（Q2761 审计表事务同框），但拖慢主链路；异步旁路有"操作成功审计丢失"的窗口——高风险工具（写/删/支付）必须同步同事务，只读工具可异步；② 全量记录参数与返回 vs 摘要：全量是回放能力的基础，但大返回体（列表结果几 MB）让审计库膨胀——参数全量+结果摘要+引用指针是折中；③ 模型生成内容的审计地位：模型的中间决策（选了哪个工具、为什么）是排查 Agent 事故的关键证据，进 trace 即可；**外部副作用**（工具对真实世界的改变）才必须进审计——分界线是"是否影响真实世界状态"；④ 审计日志的保留期：合规要求（等保/审计规范）与存储成本的平衡，高风险事件长保留、低风险滚动清理，保留策略本身要写进审计（改保留期也是被审计行为）。
- **实战**：① 事件模型先立 schema：工具上线 checklist 加"审计字段完整"项，缺 principal/参数的工具调用直接拒绝执行——审计是执行的前置不是后补；② 定期对账：审计链校验任务每天跑一遍哈希链验证（断链即高优告警），并把链头哈希与外部锚点比对；③ 演练：每季度做一次"审计回放演练"——用审计日志重建某次事故的完整时间线，拼不出来就是审计缺口（Q1966 备份演练的审计版）；④ 脱敏字段的回查权限走独立审批流（谁授权、看了什么，本身也进审计——审计的审计）。

```python
"""Q7782 工具调用审计: 事件模型+脱敏掩码+哈希链防篡改+断链检测。"""
import hashlib
import json


def mask(value: str, keep: int = 2) -> str:
    """敏感值掩码: 保留头尾, 中间打码(结构与长度可见)."""
    if len(value) <= keep * 2:
        return "*" * len(value)
    return value[:keep] + "*" * (len(value) - keep * 2) + value[-keep:]


SENSITIVE = {"token", "api_key", "phone", "id_card"}


def sanitize(params: dict) -> dict:
    out = {}
    for k, v in params.items():
        out[k] = mask(str(v)) if k in SENSITIVE else v
    return out


def hash_chain(prev_hash: str, payload: dict) -> str:
    body = json.dumps(payload, sort_keys=True, ensure_ascii=False)
    return hashlib.sha256((prev_hash + body).encode()).hexdigest()


class AuditLog:
    def __init__(self):
        self.events: list[dict] = []
        self.head = "GENESIS"

    def append(self, principal: str, tool: str, params: dict, decision: str) -> dict:
        ev = {"seq": len(self.events) + 1, "principal": principal,
              "tool": tool, "params": sanitize(params), "decision": decision}
        ev["hash"] = self.head = hash_chain(self.head, ev)
        self.events.append(ev)
        return ev

    def verify(self, tamper_seq: int | None = None) -> bool:
        """全链校验: 任一条被篡改, 从该条起哈希链断裂."""
        head = "GENESIS"
        for i, ev in enumerate(self.events, 1):
            body = {k: v for k, v in ev.items() if k != "hash"}
            if tamper_seq == i:
                body["tool"] = "TOOL-HACKED"      # 模拟事后篡改
            head = hash_chain(head, body)
            if head != ev["hash"]:
                return False
        return True


if __name__ == "__main__":
    log = AuditLog()
    log.append("u_9527", "config.update",
               {"key": "pay.timeout", "token": "sk-live-abcdef123456",
                "old": 30, "new": 300}, "DENIED")      # 高危操作+敏感参数
    log.append("svc_bot", "config.read", {"key": "pay.timeout"}, "ALLOWED")
    log.append("svc_bot", "config.delete", {"key": "pay.timeout"}, "DENIED")
    print(f"审计 3 条, 敏感字段已掩码: token={log.events[0]['params']['token']}")
    print(f"调用 ID 桥接 trace_id 之外的完整链路: 谁(u_9527)->什么(config.update)->裁决(DENIED)")
    print(f"全链校验(未篡改): {log.verify()}")
    tampered = log.verify(tamper_seq=1)
    print(f"全链校验(第1条被改): {tampered}  <- 哈希链当场断裂")
    ok = (log.verify() and not tampered
          and log.events[0]["params"]["token"] != "sk-live-abcdef123456")
    print(f"校验: 掩码 + 链验证 + 篡改可检测 -> {'通过' if ok else '异常'}")
    print("结论：审计答'谁何时对什么做了什么', 与 trace 分工不混用;")
    print("      追加写+哈希链+外部锚定防篡改; 脱敏=结构保留+值掩码+引用可回查")
```

**追问一**：审计日志要求"操作与审计同事务落库"，但 Agent 工具调用很多是外部副作用（调第三方 API）——没法同事务怎么办？两阶段与补偿怎么设计？

→ 解析：外部副作用的审计一致性要靠**意图先行 + 结果回填**两段式：① **意图记录**（pre-audit）：工具执行前先把"将要做什么"（principal、tool、参数、授权裁决）写入审计并拿到 audit_id——这一步与授权检查同事务，"没拿到 audit_id 就不执行"是硬闸门；② **执行**：拿到审计凭证后调用外部工具；③ **结果回填**（post-audit）：把执行结果（成功/失败/耗时/结果摘要）按 audit_id 回填。两段之间的**悬挂态**（执行了但回填失败：进程崩、回调丢）是关键风险，对账机制兜底：审计表里 pre-audit 无 post-audit 的记录定期扫描（悬账清单 Q2824 元数据体检同族），与外部系统的调用流水（第三方 API 通常有自己的调用记录）交叉对账，差异项人工裁决。与 SAGA 补偿（Q7509）的衔接：如果工具本身有补偿动作（config.update 的回滚），审计链要记录补偿意图与补偿结果——审计不只记录"做了什么"，还要记录"撤销了什么"；回放事故时间线时能看到完整的"动作-撤销"对。核心设计判断：**外部副作用的审计永远做不到"同事务原子"，能做的是把原子性要求转化为"凭证先行 + 悬账对账"的最终一致——先让每个动作有'出场票'，再让每张票有'下场记录'，缺口可发现可追。**

**追问二**：审计系统自身被攻破（攻击者拿到审计库写权限，篡改历史并重算整条哈希链）怎么办？哈希链的信任根在哪里？

→ 解析：哈希链防的是"单点篡改"，防不了"掌握全链的攻击者重算"——信任根必须放在**链外**。加固层次：① **外部锚定**：链头哈希定期（每分钟/每 N 条）写入攻击者不可达的存储——WORM 对象存储（一次写入多次读、对象锁 retention 策略）、另一独立系统的日志、甚至公证服务/区块链锚点；重算历史链的攻击者无法伪造锚点时间点之前的哈希，篡改在第 N 分钟后的校验中暴露（`compare with anchor`）；② **分权隔离**：审计库的写权限只给"审计服务"这一个身份（应用侧无直写权限，全部走审计服务的追加 API），审计服务账号与业务数据库账号分属不同凭证体系——攻破业务服务拿不到审计写权限；③ **只读副本异地**：审计库的准实时只读副本推到独立网段（ SOC/风控系统），主库被清空后副本仍在；④ **签名链升级**：哈希链换 HMAC（密钥在 HSM/KMS，应用侧拿不到）或每条记录独立签名——攻击者即使拿到库也拿不到签名密钥，重算链无法通过签名校验；⑤ **审计的审计**：对审计库自身的访问（谁查询过、谁导出过）记录在**另一个独立系统**——攻击者要同时篡改两套体系。现实取舍：小团队做到"外部锚定 + 分权"两层已能挡住绝大多数内部误操作与一般攻击；全部五层是大厂合规岗的配置。原则：**审计的信任根必须独立于被审计系统——任何"自己验证自己"的防篡改在对抗视角下都是自证清白。**
