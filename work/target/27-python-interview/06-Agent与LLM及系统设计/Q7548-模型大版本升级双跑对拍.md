### Q7548 · 版本演进：GPT 换代 / 新模型上线，怎么从"听说更强"走到"灰度切换"？

> 难度:★★★★ | 标签:版本演进, 双跑对拍, 模型迁移

**问**：供应商发布新一代模型（更便宜且宣称更强），业务怎么决定切不切、什么时候切？"跑一遍评测集"为什么不够？双跑对拍（parallel run）的流程与对拍指标怎么设计？切换后的回滚条件怎么定？

**答**：结论：模型升级的验证分三层：**静态评测集**（能力基线，防退化）、**双跑对拍**（真实流量上新旧模型并行，按业务指标 diff）、**灰度放量**（按流量比例逐步切换+护栏）。"跑一遍评测"不够是因为评测集覆盖不了真实流量的长尾分布（prompt 形态、工具组合、用户语言），且静态分数与业务指标（任务完成率、人工采纳率）经常不一致。回滚条件要在切换前写死成数字（如"任务完成率跌破基线 3 个标准误即回滚"），不能等出事再讨论。

机理与实战：
- **双跑架构**：同一请求镜像发给新旧两个模型（shadow 模式，旧模型出正式答案、新模型答案只记录不展示），全量跑 1-2 周收集对拍数据；成本翻倍但可控（shadow 只在采样比例上做，如 10% 流量全双跑）。对拍指标三组：① 业务指标（任务完成率、工具调用成功率）；② 质量代理（人工抽评或 judge 模型打分）；③ 成本与延迟（token 用量、TTFT）。
- **对拍的统计纪律**：diff 要有置信区间（按场景分层，样本不足的场景不下结论）；质量代理（judge 模型）与人工评审做一致性校验（Q7501 的 LLM-as-judge 校准思路）；注意"新模型在评测集上训练过/过拟合"的可能性，评测集要换版本。
- **灰度放量**：按场景分批（低风险场景先切）而非按用户比例盲切；每批观察 48h、达标进下一批；工具调用类变化最危险（新模型的工具选择倾向不同，可能改变调用序列），所以工具链路要单独做轨迹对比。
- **Prompt 迁移**：为旧模型调优的 prompt（few-shot 数量、指令措辞、JSON 格式约束）在新模型上往往需要重调——双跑阶段同时做 prompt 变体实验，切换时带走的是"新模型最优 prompt"，不是旧 prompt 原样迁移。

```python
# 基线:Python 3.10+;纯标准库,双跑对拍的 diff 统计与灰度切换门禁
from __future__ import annotations
import math
from dataclasses import dataclass, field


@dataclass
class PairResult:
    scenario: str
    old_ok: bool          # 旧模型任务完成
    new_ok: bool
    old_cost: float
    new_cost: float


@dataclass
class ParallelRun:
    results: list[PairResult] = field(default_factory=list)

    def compare(self, min_n: int = 30) -> dict[str, dict]:
        """按场景分层对拍:完成率 diff + Wilson 置信区间。"""
        out: dict[str, dict] = {}
        groups: dict[str, list[PairResult]] = {}
        for r in self.results:
            groups.setdefault(r.scenario, []).append(r)
        for sc, rs in groups.items():
            n = len(rs)
            p_old = sum(r.old_ok for r in rs) / n
            p_new = sum(r.new_ok for r in rs) / n
            # Wilson 区间半径(近似,95%)
            se = math.sqrt(max(p_new * (1 - p_new), 1 / (n + 1)) / n) * 1.96
            cost_ratio = sum(r.new_cost for r in rs) / max(sum(r.old_cost for r in rs), 1e-9)
            out[sc] = {"n": n, "old": p_old, "new": p_new,
                       "ci_low": p_new - se, "ci_high": p_new + se,
                       "cost_ratio": cost_ratio,
                       "conclusive": n >= min_n}
        return out


def promote_gate(cmp: dict[str, dict], drop_threshold: float = 0.02) -> tuple[bool, list[str]]:
    """切换门禁:样本足 & 新模型下界不低于旧值-阈值 & 成本不升。"""
    blockers: list[str] = []
    for sc, s in cmp.items():
        if not s["conclusive"]:
            blockers.append(f"{sc}: 样本 {s['n']} 不足,不下结论")
        elif s["ci_low"] < s["old"] - drop_threshold:
            blockers.append(f"{sc}: 新模型下界 {s['ci_low']:.3f} 低于基线 {s['old']:.3f}")
        elif s["cost_ratio"] > 1.1:
            blockers.append(f"{sc}: 成本上升 {(s['cost_ratio'] - 1):.0%}")
    return not blockers, blockers


def demo() -> None:
    run = ParallelRun()
    # 场景 A:新模型略优(80%->85%,n=200);场景 B:样本不足;场景 C:新模型显著退化
    for i in range(200):
        run.results.append(PairResult("qa", old_ok=i % 5 < 4,
                                      new_ok=i % 20 < 17,
                                      old_cost=0.01, new_cost=0.006))
    for _ in range(10):
        run.results.append(PairResult("codegen", old_ok=True, new_ok=True,
                                      old_cost=0.02, new_cost=0.01))
    for i in range(50):
        run.results.append(PairResult("tooluse", old_ok=i % 20 < 17,
                                      new_ok=i % 5 < 3,
                                      old_cost=0.01, new_cost=0.008))
    cmp = run.compare(min_n=30)
    ok, blockers = promote_gate(cmp)
    print(f"切换决定: {'放行' if ok else '阻断'}")
    for b in blockers:
        print(f"  - {b}")
    assert not ok
    assert any("codegen" in b and "样本" in b for b in blockers)
    assert any("tooluse" in b for b in blockers)
    # 去掉退化场景后 qa 可放行
    run.results = [r for r in run.results if r.scenario != "tooluse"]
    cmp2 = run.compare(min_n=30)
    blockers2 = [b for b in promote_gate(cmp2)[1] if "codegen" not in b]
    assert not blockers2
    print("双跑对拍:分层 Wilson 区间 + 样本量门槛 + 成本约束,门禁前置于灰度 ✅")


if __name__ == "__main__":
    demo()
```

**追问一**：为什么工具调用类场景的轨迹对比比最终答案对比更重要？
答：工具场景的失败常是"路径对了结果错"或"结果对了路径危险"——最终答案一样但调用序列不同（多调用、错工具、参数漂移），意味着新模型的行为分布变了，可能引发配额/成本/权限的新问题；轨迹对比（工具序列、调用次数、失败重试分布）能在业务指标恶化前暴露行为漂移，这是 Agent 场景区别于纯问答的验证重点。

**追问二**：切换后监控期发现"长尾场景完成率缓降"，回滚还是修 prompt？
答：先看下降是否超出切换前设定的回滚阈值与统计噪声——超阈值先回滚（可用性好恢复：路由层把流量切回旧模型是配置变更，分钟级）；未超阈值则采样长尾 badcase 分析：若是 prompt 适配问题（新模型对旧指令格式不敏感），修 prompt 比回滚更有长期价值。回滚成本低是灰度架构的前提——路由层必须保留新旧模型并存的能力直到监控期结束。

## 背诵要点
- 模型升级三层验证：静态评测集（防退化）→ 双跑对拍（真实流量 shadow，按业务指标分层 diff）→ 灰度放量（按场景分批，每批 48h）；评测集分数与业务指标经常不一致。
- 对拍纪律：Wilson/标准误置信区间、样本量门槛（n≥30/场景）、judge 与人工一致性校验、评测集换版本防过拟合；工具场景要做轨迹对比。
- 回滚条件切换前写死成数字（下界跌破基线-2 个标准误即回滚）；路由层保留新旧并存到监控期结束，prompt 要随新模型重调而非原样迁移。
