### Q7540 · 语料涨到亿级：向量索引全量进内存撑不住怎么办？

> 难度:★★★★ | 标签:RAG, 索引分层, 容量规划

**问**：RAG 语料从百万涨到亿级 chunk，完整 HNSW 图的内存账爆炸。冷热分层怎么设计（热层常驻、冷层按需）？分层依据是什么？热层容量怎么定？容量缩过头会发生什么？语料更新时分层怎么维护？

**答**：结论：检索请求高度集中（头部 20% 语料承载约 80% 查询），冷热分层把"完整图索引 + 原文"只对热层常驻内存，冷层用低内存索引（IVF 类粗索引/磁盘索引）按需服务长尾，命中后回填热层。热层容量按"命中率-内存"曲线定价：以 95% 命中率为目标反推容量；容量缩过头会触发 LRU 抖动（miss 风暴），延迟反而远差于全量冷层。

机理与实战：
- **分层依据是热度统计**：按 chunk 的检索命中频次做周级聚合，划热层（top-N）与冷层；升降层走统计驱动而非人工指定——业务节奏变化（新活动带火新语料）时自动迁移。
- **两层的索引选型不同**：热层用 HNSW（低延迟高内存），冷层用 IVF/diskANN 类（低内存高延迟）——查询路径先热层 ANN，不足再冷层粗筛回填；两级一致性靠增量索引（Q1198）而不是整层重建。
- **回填风暴**：冷启动/热点迁移时热层集中 miss，冷层取数形成风暴——回填要限速 + 批量预取（把同分区候选一起拉），预热脚本在发布/迁移后主动把预期热集灌入热层（Q6020 预热思路）。
- **缓存一致性**：语料更新后热层旧块失效——失效广播（Q6531 同机制）或按语料版本戳比对回填；否则"检索到的旧内容"是 RAG 最常见的静默事故。

```python
# 基线:Python 3.10+;纯标准库模拟 RAG 向量索引的冷热分层(热层常驻内存/冷层按需加载)
# 真实场景:检索热点集中(头部 20% 语料占 80% 查询);分层省内存保延迟,冷层回填热层
from __future__ import annotations
from collections import OrderedDict


class HotTier:
    """热层:内存常驻(完整 HNSW 图),容量有限 LRU 淘汰。"""

    def __init__(self, capacity: int) -> None:
        self.cap = capacity
        self.chunks: OrderedDict[str, str] = OrderedDict()   # chunk_id -> text
        self.hits = self.misses = 0

    def get(self, cid: str) -> str | None:
        if cid in self.chunks:
            self.hits += 1
            self.chunks.move_to_end(cid)
            return self.chunks[cid]
        self.misses += 1
        return None

    def put(self, cid: str, text: str) -> None:
        self.chunks.pop(cid, None)
        if len(self.chunks) >= self.cap:
            self.chunks.popitem(last=False)                  # 淘汰最冷块
        self.chunks[cid] = text


class ColdTier:
    """冷层:磁盘/远端索引(IVF 类粗索引),按需回填热层。"""

    def __init__(self, chunks: dict[str, str]) -> None:
        self.chunks = dict(chunks)
        self.fetches = 0

    def fetch(self, cid: str) -> str | None:
        self.fetches += 1
        return self.chunks.get(cid)


class TieredIndex:
    def __init__(self, hot: HotTier, cold: ColdTier) -> None:
        self.hot, self.cold = hot, cold

    def search(self, matched_ids: list[str]) -> list[str]:
        out = []
        for cid in matched_ids:
            text = self.hot.get(cid)
            if text is None:                                 # 热层 miss -> 冷层回填
                text = self.cold.fetch(cid)
                if text is not None:
                    self.hot.put(cid, text)
            if text is not None:
                out.append(text)
        return out


def demo() -> None:
    corpus = {f"c{i}": f"chunk-{i}-content" for i in range(1000)}
    # 请求分布:头部 200 块占 80% 请求(zip 型分布)
    request_ids = [f"c{i % 200}" if i % 5 else f"c{200 + (i * 7) % 800}"
                   for i in range(4000)]
    hot, cold = HotTier(capacity=250), ColdTier(corpus)
    idx = TieredIndex(hot, cold)
    for cid in request_ids:
        idx.search([cid])

    hit_ratio = hot.hits / (hot.hits + hot.misses)
    print(f"热层容量 250/全库 1000:命中率 {hit_ratio:.0%}"
          f"(头部 20% 语料承载 80% 请求) ✅")
    assert hit_ratio > 0.75
    print(f"冷层按需取 {cold.fetches} 次 -> 磁盘/远端只服务长尾,内存只驻留热图 ✅")

    # 容量敏感性:热层过小则 LRU 抖动
    small = TieredIndex(HotTier(100), ColdTier(corpus))
    for cid in request_ids:
        small.search([cid])
    r_small = small.hot.hits / (small.hot.hits + small.hot.misses)
    print(f"热层缩到 100:命中率 {r_small:.0%}(冷层取 {small.cold.fetches} 次,"
          "延迟劣化) ✅")
    assert r_small < hit_ratio

    print("纪律:热度统计驱动升降层(周级聚合);语料更新走增量索引不整层重建 ✅")


if __name__ == "__main__":
    demo()
```

**追问一**：为什么热层"完整 HNSW 图"与冷层"IVF 粗索引"可以共存查询？
答：两层是"候选集生产者"不同——热层图索引直接给近邻，冷层 IVF 给粗候选再精排；查询合并两路候选去重后统一 rerank。工程关键在两层的向量版本一致（同一 embedding 模型与维度），版本升级走 Q7518 双写迁移，不允许两层各升各的。

**追问二**：热度统计显示"头部 20%"但热层命中率只有 60%，可能原因？
答：① 请求分布漂移（新活动让长尾语料变热，周级统计滞后）；② 热层被长尾回填污染（单次 miss 的冷块挤掉真热块——回填要设"二次命中才入层"门槛）；③ 会话内局部性（同一文档多块连查）没被利用——按文档粒度批量回填。

## 背诵要点
- 分层依据：头部 20% 语料承载约 80% 请求；热层 HNSW 常驻、冷层 IVF/diskANN 按需，回填限速+批量预取。
- 热层容量按"命中率-内存"曲线定目标（如 95% 命中）；容量过小触发 LRU 抖动，miss 风暴比全冷层更慢。
- 升降层走周级热度统计自动化；语料更新走增量索引 + 失效广播，两层向量版本必须一致。

## 复盘追问
- 亿级语料迁移日，冷启动热层全空怎么保 P99？（提示：预热脚本按历史热度 TopN 灌层 + 灰度放量（先 5% 流量探测回填风暴）+ 临时放宽延迟 SLO）
- 检索偶尔返回已删除文档的内容，是分层引入的吗？（提示：查失效路径——热层旧块未随语料删除失效（版本戳比对缺失），与分层无关但被分层放大；修复靠语料版本对账）
