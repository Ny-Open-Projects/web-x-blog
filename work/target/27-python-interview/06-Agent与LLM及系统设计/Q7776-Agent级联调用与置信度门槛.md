### Q7776 · 每次都调大模型太烧钱：Agent 级联调用与置信度门槛

难度：P6 ｜ 标签：级联调用、模型分级、置信度校准、成本优化、路由降级

基线：Python 3.12；蒙特卡洛模拟"小模型先行 + 低置信升级大模型"的级联架构，对比全量大模型的成本与质量（3000 次试验），全标准库实跑。

**问**：Agent 每一步都调旗舰模型，成本是收益的十倍——但直接换小模型质量又崩。级联调用（cascade）是怎么设计的？置信度门槛怎么定？为什么说"置信度校准是级联的地基"，小模型不知道自己不知道时会发生什么？

**答**：
- **结论**：级联的架构：**请求先到便宜的小模型，小模型自报置信度，置信度 ≥ 门槛直接交付；低于门槛升级大模型重做**。收益来自两段分布的错位：小模型在"简单请求"上正确率接近大模型（本卡：高置信时 95% 实际正确率），只有"困难请求"才显著掉队——用置信度把这两段分开，简单请求以 1x 成本交付，困难请求以 13x 成本保质量。本卡 3000 次蒙特卡洛：级联平均成本 4.9 vs 全量大模型 12.0（省 59%），正确率 98.9% vs 96.9%（反而更高——升级机制让困难请求多了一层检查）。**置信度校准是地基**：级联的全部价值押注在"小模型自报的置信度与真实正确率相关"上——校准良好（高置信≈高正确率）时级联是套利；校准崩坏（小模型不知道自己不知道，错的也报 0.9）时级联退化为"纯小模型"——成本是省了，质量按小模型的原地崩塌。
- **取舍**：① 门槛值的定法：不是拍脑袋，画"门槛-成本-质量"曲线找拐点——门槛高省得少质量高，门槛低反之；本卡 0.65 是质量损失 <1% 下的最大节省点；② 置信度来源：让模型自报（prompt 要求输出 confidence 字段）最便宜但最不准；用**自洽性信号**（N 次采样投票分散度，Q7771）或**验证器通过率**更可靠但更贵——分级用：自报做初筛，分散度做确认；③ 任务分层不混淆：简单分类/抽取类适合级联，长程推理类小模型正确率全段崩，级联无意义——先按任务画像分池，池内再级联；④ 升级路径的一致性：小模型和大模型的输出 schema/工具协议必须一致，否则升级重做时 Agent 状态要迁移。
- **实战**：① 上线前跑"分级评测"：同一评测集分别测小模型、大模型、级联三档，按任务类型出对比矩阵——级联决策是数据决策不是架构直觉；② 监控升级率：升级率设计预期 20%，实测 50% 说明门槛或小模型配置错了（成本账全变）；升级率骤降且质量下降说明小模型过度自信（校准漂移，换模型/版本后必现，Q7548 双跑对拍要覆盖置信度字段）；③ 成本归因按"级联层"拆分（Q1780 token 分账）：小模型省了什么、大模型兜了什么，账目清楚才能继续优化；④ 降级预案：大模型配额耗尽时级联自动退化为"全小模型 + 高风险任务标记"，是降级预案里的质量底线设计。

```python
"""Q7776 Agent 级联调用: 小模型先行, 低置信度升级大模型, 成本与质量的平衡账。"""
import random

random.seed(3)

# 小模型: 80% 任务答对, 答错时"置信度"通常也低; 高置信度时 95% 真的对
SMALL_CORRECT = 0.80
COST_SMALL, COST_BIG = 1, 12   # 相对成本


def small_model(rng: random.Random) -> tuple[bool, float]:
    correct = rng.random() < SMALL_CORRECT
    # 答对时倾向高置信, 答错时倾向低置信(带噪声)
    conf = rng.random() * 0.35 + (0.6 if correct else 0.0)
    return correct, min(conf, 0.95)


def big_model(rng: random.Random) -> bool:
    return rng.random() < 0.97


def cascade(rng: random.Random, threshold: float = 0.65) -> tuple[bool, int]:
    ok, conf = small_model(rng)
    if conf >= threshold:
        return ok, COST_SMALL            # 高置信: 小模型直接交付
    big_ok = big_model(rng)
    return big_ok, COST_SMALL + COST_BIG  # 升级: 双倍成本但质量拉满


if __name__ == "__main__":
    trials = 3000
    rng0 = random.Random(trials)
    acc_c = cost_c = acc_b = cost_b = 0
    for _ in range(trials):
        ok1, c1 = cascade(rng0)
        acc_c += ok1
        cost_c += c1
        ok2 = big_model(rng0)
        acc_b += ok2
        cost_b += COST_BIG
    print(f"级联   : 正确率 {acc_c / trials:.1%}, 平均成本 {cost_c / trials:.1f}")
    print(f"全大模型: 正确率 {acc_b / trials:.1%}, 平均成本 {cost_b / trials:.1f}")
    saved = 1 - (cost_c / trials) / (cost_b / trials)
    print(f"成本节省: {saved:.0%}, 质量差: {(acc_b - acc_c) / trials:+.1%}")
    ok = (cost_c / trials) < (cost_b / trials) * 0.5 and acc_c >= acc_b - 0.03
    print(f"校验: 成本省半且质量接近 -> {'通过' if ok else '异常'}")
    print("结论：级联的价值全在'置信度门槛'上——门槛高则省得少质量高, 门槛低反之;")
    print("      置信度校准是级联的地基: 小模型不知道自己不知道, 级联就变成纯降级")
```

**追问一**：小模型"不知道自己不知道"的具体表现是什么？校准漂移怎么发现？

→ 解析：过度自信的三种表现：① **错误答案配高置信**：事实性幻觉（编造 API 名、编造日期）常带流畅的长推理，自报置信 0.9——它把"生成的流畅度"当成了"正确性"的证据；② **分布外输入不降置信**：训练分布外的任务（新业务域、新语言）照常输出高置信答案，因为模型没有"我不认识这个领域"的元认知；③ **格式自信掩盖语义错误**：JSON 输出格式完美（格式是学的），内容错误（语义没懂）——用格式指标当质量指标时完全隐身。校准漂移的发现机制：**持续抽样人工复核按置信度分层统计**——"置信度 0.9+ 的样本实际正确率"是最关键的单指标，它的周环比下降就是校准漂移的直接证据（换模型版本、改提示、扩工具集后必须重测本指标，Q7548 对拍评测要包含 confidence 字段的校准曲线）。补救手段按成本递增：温度/提示校准（便宜、效果有限）→ 置信度后校准（把自报分数按历史正确率重新映射成校准分，推荐）→ 换置信信号（分散度、验证器，贵但真）。

**追问二**：级联与"意图分级路由"（Q2855）是什么关系？两者能不能互相替代？

→ 解析：不能替代，它们在不同维度切分流量。**意图路由**在**请求入口**按任务类型分池：事实问答走检索管线、总结走短上下文管线、代码走工具密集管线——每池选择"适合该类任务的默认模型"，路由错误 = 走错管线（召回差、工具缺）；**级联**在**管线内部**按难度分档：同一条管线里简单请求小模型交付、困难请求升级——升级错误 = 同管线内质量成本失衡。组合关系是两层楼：路由先分池（决定管线与提示模板），池内级联分档（决定模型档位）；路由依赖请求特征（可预测、可缓存），级联依赖运行时信号（置信度、验证器，必须实算）。只做路由不做级联：池内困难请求浪费大模型预算；只做级联不做路由：检索密集型任务被丢给小模型 + 大模型也救不回（没有检索管线，升级只是换了个同样没工具的模型）。监控上两者分开看：路由准确率（抽样判"该不该走这条管线"）与级联升级率/质量差（池内账）——两个指标恶化时的修复手段完全不同，混在一起会把"路由错了"当成"门槛错了"来调。
