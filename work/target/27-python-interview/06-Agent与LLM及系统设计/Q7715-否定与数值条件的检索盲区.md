### Q7715 · 否定与数值条件：向量检索的结构性盲区

难度：P6 ｜ 标签：RAG、否定查询、数值过滤、混合检索

基线：Python 3.12；dense embedding / BM25 / metadata filter 概念对照；纯 Python 模拟打分。

**问**：用户问"不含糖的饮料"和"价格低于 50 元的套餐"，向量检索召回的却全是含糖饮料和高价套餐。换成 BM25 也没好转："不含糖"里的"糖"和含糖文档高度共现，否定词本身又不出现。为什么常规检索对否定和数值这么弱？该怎么补？

**答**：
- **结论**：dense embedding 编码的是**主题语义**，"含糖"和"不含糖"共享"糖/饮料"主题，向量非常接近，否定差异被淹没；BM25 依赖词共现，否定词（不、无）在文档里往往不出现，反而"糖"把含糖文档打高分。数值比较（<50）也不是语义相似度能表达的关系。它们擅长"找相关主题"，不擅长"执行逻辑/范围约束"。
- **取舍**：补法有三层：① **查询理解**——用 LLM/规则把查询解析成结构化条件（`sugar=false`、`price<50`），走 metadata filter 或 SQL/范围索引；② **混合检索**——dense 召回 + 关键词/同义词扩展（"不含糖"扩展为"无糖/零糖/0 糖"）+ 过滤；③ **重排**——用 cross-encoder 或规则校验否定/数值条件。过滤会提升精确率但可能降低召回（metadata 缺失时全被滤掉），需要覆盖率监控。
- **实战**：① 把"可过滤字段"（价格、含糖、地区、时间）建成结构化 metadata，别只存文本；② 否定查询优先走排除过滤，而不是指望向量；③ 对数值范围做范围索引/分区，不要用 top-k 近似；④ 评估集单列"否定/数值"子集，否则总体指标会掩盖这类失败。

```python
docs = [
    {"id": "d1", "text": "含糖 碳酸 饮料 可乐", "sugar": True, "price": 5},
    {"id": "d2", "text": "无糖 零糖 气泡 水", "sugar": False, "price": 6},
    {"id": "d3", "text": "鲜榨 果汁 含糖", "sugar": True, "price": 18},
]


def dense_score(query: str, text: str) -> float:
    """示意：按词重叠打分，否定词不参与，故含糖/无糖得分接近。"""
    q = set(query.replace("不含", "").replace("低于", "").split())
    return len(q & set(text.split())) / (len(q) or 1)


def search(query: str, k: int) -> list[str]:
    return [d["id"] for d in sorted(docs, key=lambda d: -dense_score(query, d["text"]))[:k]]


def filtered_search(query: str, sugar: bool | None, max_price: float | None) -> list[str]:
    out = []
    for d in docs:
        if sugar is not None and d["sugar"] != sugar:
            continue
        if max_price is not None and d["price"] >= max_price:
            continue
        out.append(d["id"])
    return out


if __name__ == "__main__":
    print("向量 top2:", search("不含糖 饮料", 2))
    print("结构化过滤:", filtered_search("不含糖 饮料", sugar=False, max_price=None))
    print("数值过滤:", filtered_search("低价 套餐", sugar=None, max_price=10))
    print("结论：否定/数值应转成过滤条件，向量只负责主题召回")
```

**追问一**：为什么把"不含糖"改写成"无糖 零糖"能提升召回？
→ 解析：文档里通常写"无糖/零糖/0 糖"，而不是"不含糖"；改写把否定的**语义等价正例**补进查询，让关键词与向量都能匹配到真实表述。但改写可能引入"低糖"等近似词，需要配合过滤兜底。

**追问二**：metadata filter 先过滤再召回，和先召回再过滤，有什么区别？
→ 解析：先过滤（pre-filter）在候选集上做 ANN，能保证结果都满足条件，但过滤很严时可能候选不足、召回下降；后过滤（post-filter）先取 top-k 再筛，可能筛完不够 k 条，甚至全被筛掉。正确做法是 pre-filter + 扩大候选集 + 监控过滤后的召回率。
