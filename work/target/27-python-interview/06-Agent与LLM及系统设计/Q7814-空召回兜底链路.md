### Q7814 · 空召回兜底：改写、宽召回与拒答的降级链路

难度：P6 ｜ 标签：空召回、兜底、查询改写、拒答、阈值过滤、低分命中、RAG

基线：库外知识卡，代码用标准库模拟空召回的四层兜底链路，不调用外部 API。

**问**：RAG 系统里用户问"公司注册在月球怎么办"，向量检索返回空（或全是 0.3 分的弱相关），上下文直接为空塞给模型——模型开始一本正经地编造注册流程。空召回的兜底链路应该有几层？每层解决什么？为什么说"拒答比编造便宜一百倍"？

**答**：

- **结论**：空召回兜底是一条**四层降级链**，每层独立可开关：① **原查询检索**（正常路径）；② **查询改写**——口语化/超具体的问题改写为知识库用语（"月球注册怎么办"→"境外主体注册流程"），重新检索；③ **宽召回**——放宽阈值或切换到通用 FAQ 索引，宁可给弱相关也强于空；④ **拒答**——明确输出"知识库未找到相关内容，请转人工/换种问法"，绝不把空上下文静默塞给模型。同时要区分两种"空"：**真空**（索引里确实没有）与**低分命中**（有结果但 score < 阈值被过滤）——后者是阈值问题，前者是覆盖问题，兜底策略不同：低分命中先怀疑阈值与 embedding 质量，真空才走改写与拒答。每层的尝试都要**显式声明策略**（回答里标注来自哪层），拒答率与各层命中率是核心监控指标。
- **取舍**：链路越深延迟与成本越高，所以要按"答错成本"分配：客服 FAQ 类答错成本低，改写+宽召回即可；医疗/金融类答错成本高，宁可第一层没过阈值就直接拒答（不要宽召回拿弱相关凑数——弱相关上下文诱导模型编出"看起来有依据"的答案，比纯空更危险）。改写的实现两档：规则改写（同义词表、槽位替换，便宜可控）与 LLM 改写（每查询多一次调用，改写本身也可能引入歧义）——规则先行，LLM 改写只用于规则覆盖不了的长尾。宽召回要限定"兜底语料"是经过审核的通用内容，不能把低质文档放进来凑数。拒答话术要给出口（"试试这样问/转人工"），生硬的"我不知道"会拉高转人工率的观感成本。
- **实战**：企业知识库问答上线后 6% 的查询产生幻觉回答，溯源发现全是"空上下文静默进模型"：检索层 score < 0.35 过滤后为空，组装层没做空判断直接拼 prompt。修复四层链路 + 监控面板：拒答率 4.2%（健康，长尾问题确实不在库内）、改写救回 1.8%、宽召回救回 1.1%、真无资料 1.3%。配套动作：每周把拒答 top100 拉出来人工归类——发现"期权行权"类问题集中缺文档，补文档后拒答率降到 1.9%。规范沉淀：**空召回不是异常是常态信号，拒答率是知识库覆盖度的体检指标；兜底链救回的每层都要埋点归因**。

下面模拟四层兜底链路的完整行为。

```python
# Q7814 空召回兜底: 检索为空/低分时的降级链路
def retrieve(query, index):
    """模拟向量检索: score < 0.5 的视为无效命中"""
    hits = index.get(query, [])
    return [h for h in hits if h["score"] >= 0.5]

INDEX = {
    "退款政策": [{"doc": "doc-1 退款政策", "score": 0.82}],
    "冷门问题": [{"doc": "doc-9 弱相关", "score": 0.31}],
}

# [1] 无兜底: 空召回直接把空上下文塞给模型 → 模型开始编造
def answer_nofallback(query):
    hits = retrieve(query, INDEX)
    return f"根据资料: {hits[0]['doc'] if hits else '(无)'} —— 模型开始自由发挥"

r = answer_nofallback("公司注册在月球怎么办")
print(f"[1] 无兜底: {r}")
assert "(无)" in r

# [2] 兜底链路: 重写查询 → 换检索 → 关键词 → 兜底话术, 每层独立可关
def answer_with_fallback(query, index, allow_rewrite=True, allow_broad=True):
    hits = retrieve(query, index)                       # ① 原查询
    strategy = "vector"
    if not hits and allow_rewrite:
        alt = query.replace("怎么办", "流程")           # ② 查询改写
        hits = retrieve(alt, index)
        strategy = "rewrite"
    if not hits and allow_broad:
        hits = [{"doc": "通用 FAQ 索引命中", "score": 0.55}]   # ③ 宽召回
        strategy = "broad"
    if not hits:
        return "抱歉, 知识库没有找到相关内容, 请转人工", "none"  # ④ 明说无资料
    return f"[{strategy}] 依据 {hits[0]['doc']} 回答", strategy

for q in ("退款政策", "冷门问题", "公司注册在月球怎么办"):
    ans, st = answer_with_fallback(q, INDEX)
    print(f"[2] {q!r} → 策略={st}: {ans[:50]}")

# [3] 空召回必须显式声明, 而不是静默让模型自由发挥 (关掉宽召回后, 无资料就是无资料)
ans, st = answer_with_fallback("月球注册", INDEX, allow_broad=False)
assert st == "none" and "转人工" in ans
print("[3] 无资料时输出『未找到』话术 — 拒答比编造便宜一百倍; 宽召回是否兜底是策略开关, 也要显式")

# [4] 低分命中 vs 空召回: 阈值以下等于空, 但要留审计痕迹
hits = retrieve("冷门问题", INDEX)
print(f"[4] '冷门问题' 原始命中 score=0.31 < 0.5 → 过滤后 {len(hits)} 条, 走改写/宽召回兜底")
assert len(hits) == 0
print("    → 实测 兜底链: 改写→宽召回→拒答转人工; 空上下文静默进模型 = 编造事故的标准起点")
```

**追问一**：低分命中和空召回为什么必须分开治理？—— 空召回说明知识库**覆盖**不到该问题，治理靠补文档或改写换路；低分命中说明文档**在库里但向量没对齐**，治理靠检查 embedding 模型与语料域差（术语不一致、语种混杂）、chunk 质量或阈值本身设错。把两者混在"返回空"里处理，会出现"调阈值掩盖覆盖缺口"的错药：阈值降到 0.2，弱相关上下文大量涌入，幻觉反而恶化。工程实现上：过滤层区分 `空` 与 `被阈值过滤`，两条计数分开上报；阈值调整必须配合评测集（阈值扫频看拒答率与幻觉率的双曲线找拐点），不能拍脑袋。

**追问二**：拒答率的"健康区间"怎么定？太高太低分别说明什么？—— 没有普适数，但有结构性判断法：拒答率 ≈ 知识库覆盖不到的提问占比。太高（>10%）通常意味着长尾问题多而文档少——先看 top 拒答问题的聚类，多数可补文档解决；太低（<0.5%）反而要警惕——可能阈值过松、宽召回兜底过硬，弱相关上下文在给幻觉铺路，此时抽样人工核验回答正确率。健康的形态是：拒答率随文档建设缓慢下降，宽召回救回率稳定，真无资料占比可控。把这三个数连成趋势看，比看绝对值更能发现系统性问题。

## 背诵要点

- 四层兜底链：原查询 → 改写 → 宽召回（限审核过的兜底语料）→ 拒答转人工；每层显式声明策略并埋点归因。
- 空召回（覆盖缺口）与低分命中（向量对齐/阈值问题）分开治理；混治会错调阈值放大幻觉。
- 拒答率是覆盖度体检指标：过高补文档、过低警惕阈值过松；拒答话术要给出路，答错成本高的领域宁可早拒答。

## 复盘追问

- 空上下文静默进模型造成 6% 幻觉，为什么这比"检索失败报错"更危险？（静默 = 无告警无痕迹，用户拿到的是自信的编造；报错至少暴露了故障面，幻觉要靠人工发现，发现成本差一个量级）
- 改写层用 LLM 改写时怎么防止"改写本身引入歧义"？（改写结果也过阈值校验：改写后若命中分数反而下降则回退原查询；规则先行，LLM 改写只接长尾，且保留原查询审计对照）
