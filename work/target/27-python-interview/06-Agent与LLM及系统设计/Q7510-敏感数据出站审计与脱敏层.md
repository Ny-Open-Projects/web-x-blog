### Q7510 · 敏感数据出站审计:工具调用白名单 + 脱敏中间层

> 难度:★★★ | 标签:安全, 合规, Agent

**问**：合规要求：Agent 的工具调用不允许把用户敏感数据（手机号、身份证、内部接口地址）发到外部 LLM 或第三方工具。出站审计这条链路该怎么设计？白名单和脱敏中间层各防什么、防不住什么？

**答**：结论：防线要建在**出站边界的统一收口处**（LLM 网关与工具网关），而不是各业务自查。架构是两层串联：**脱敏中间层**（对出站 payload 做识别-替换-映射，敏感值换 token，回站时反解）+ **白名单审计**（工具 × 目标域名 × 数据分级的三维 allowlist，不在名单即拦截并告警）。脱敏防"数据内容泄露"，白名单防"数据流向泄露"，两者互补但都不防"模型从记忆里吐出敏感信息"——那要靠输入侧不出站敏感数据 + 输出侧泄露检测双保险。

设计与实战：
- 脱敏中间层的工程要点：识别用"规则（正则/格式校验）+ NER 兜底"而非只靠正则；**可逆映射表只存服务端内存/加密存储， TTL 与会话绑定**（session 结束即废弃，防止映射表本身成为泄露源）；格式保留（手机号脱成 `138****5678`）用于展示，token 化（`{{TOK_1}}`）用于必须反解的链路，两者用途别混。
- 白名单的三维设计：工具维度（该 Agent 可调哪些工具）、目标维度（该工具可访问哪些域名/表）、数据分级维度（内部数据只能进"已签署数据处理协议"的供应商路由）。三维都要匹配才放行，任何一维越界即拦截 + 打审计事件。
- 事故复盘：某 Agent 把含用户手机号的工单原文发给外部搜索工具做"摘要"，审计层没有出站检查所以无告警，被安全巡检发现。修复：工具网关强制出站 payload 过脱敏层（手机号命中即 token 化）+ 该工具的目标域白名单收紧 + 审计事件接入安全告警。复盘要点：**出站检查必须是架构强制的，"业务自觉"等于没有防线**。

```python
# 基线:Python 3.9+ 标准库;出站收口:脱敏映射 + 三维白名单(可运行)
import re, uuid

PHONE = re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")

class OutboundGate:
    def __init__(self) -> None:
        self.map: dict[str, str] = {}          # token -> 原值(服务端持有,TTL 绑会话)
    def sanitize(self, text: str) -> str:
        def sub(m: re.Match) -> str:
            tok = f"{{{{TOK_{uuid.uuid4().hex[:6]}}}}}"
            self.map[tok] = m.group(0)
            return tok
        return PHONE.sub(sub, text)            # 生产:规则 + NER 兜底 + 更多类别
    def restore(self, text: str) -> str:
        for tok, raw in self.map.items():
            text = text.replace(tok, raw)      # 回站反解;会话结束清空映射表
        return text

ALLOWLIST = {("web_search", "api.search.vendor.com"), ("sql", "dw.internal")}

def audit(tool: str, target: str, data_class: str = "internal") -> tuple[bool, str]:
    """三维校验:工具 × 目标 × 数据分级。"""
    if (tool, target) not in ALLOWLIST:
        return False, "blocked: 工具/目标越界,已产生审计事件"
    if data_class == "secret":
        return False, "blocked: secret 级数据禁止出站"
    return True, "allowed"

if __name__ == "__main__":
    gate = OutboundGate()
    out = gate.sanitize("联系 13812345678 处理工单")
    print("出站:", out)                          # 联系 {{TOK_xxx}} 处理工单
    print(audit("web_search", "api.search.vendor.com"))
    print(audit("web_search", "evil.com"))
    print("回站:", gate.restore(out))
```

**追问**：
- 一层追问：LLM 上下文里已混入的敏感数据，出站时怎么兜住？——三道：出站 payload 统一过脱敏层（不管来源）、模型响应出站前跑泄露检测（对响应做敏感模式扫描）、以及源头治理（进 LLM 前就脱敏——最便宜也最可靠，出站检查是兜底不是首防）。
- 二层追问：token 化破坏了语义，模型答不准怎么办？——这是精度与合规的权衡：敏感值换保留格式的掩码（`138****5678`）保语义但不反解；或只把"任务必需字段"出站（最小化原则），让脱敏层按工具声明"需要哪些字段"做字段级裁剪，而不是全文过滤。
- 三层追问：审计事件怎么设计才不是事后摆设？——事件要结构化（谁、哪个工具、目标、数据分级、动作、命中规则），实时接安全告警（拦截即报警而非日终汇总），并定期用审计数据做策略回测（拦截中有多少误拦），否则白名单会越收越死、业务开始绕路。
