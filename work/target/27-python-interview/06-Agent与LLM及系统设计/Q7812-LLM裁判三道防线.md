### Q7812 · LLM-as-judge 的三道防线：位置偏差、自评盲区与评分稳定性

难度：P6 ｜ 标签：LLM-as-judge、位置偏差、自评盲区、双序评估、评分稳定性、中位数

基线：库外知识卡，代码用标准库模拟裁判的位置偏差/自评加成/重跑方差，不调用外部 API。

**问**：用 GPT 给两个模型的回答打分选优，同事发现把候选 A 放前面 A 总赢——交换顺序就翻盘；还有人用同一个模型既当参赛者又当裁判，自家输出分数虚高。LLM 裁判的偏差有哪些？怎么用工程手段把裁判变得可信？什么时候必须放弃自动裁判换人工？

**答**：

- **结论**：LLM 裁判有三种系统性偏差，各有对应防线。① **位置偏差**：候选的呈现顺序影响判断（靠前的平均分更高），同一对候选交换顺序可能胜负翻转——防线是**双序评估**（正序+反序各评一次，两次结论一致才采信，不一致判平局送人工）。② **自评盲区**：裁判与参赛者同源时给自家输出系统性加分（自评加成）——防线是**换裁判**（用不同家族的模型）或**双盲**（不透露哪个输出出自哪个模型，且混淆顺序）。③ **评分不稳定**：同一样本重复评分结果漂移（采样温度、提示措辞都会引起波动）——防线是**重跑 k 次取中位数**并监控极差，极差超阈值判为"不稳定样本"降级人工。三条防线都是纯工程手段，成本可控（双序 2 倍、重跑 5 倍推理），但换来的裁判结论才敢用于发布决策。
- **取舍**：防线的成本要按决策重要度分配：日常回归评测用单次评分 + 漂移监控即可；发布门禁的 pairwise 对比必须双序 + 多裁判仲裁；只有争议样本才进人工。另一个常见取舍是"绝对分 vs 相对比较"：让模型打 1-10 分很容易出现刻度漂移（今天 7 分的输出明天变 6 分），相对比较（A vs B 谁好）稳得多——所以严肃评测用 pairwise + Elo/Bradley-Terry 聚合，绝对分只用于粗分层。裁判提示词本身也要评测（用人工标注过的小集校准裁判与人工的一致率，Cohen's kappa 是验收指标），裁判没校准就上岗是评测事故的源头。最后记住量级：双序 2 倍成本、5 次重跑 5 倍成本，大规模评测前先算账再选防线组合。
- **实战**：一次模型升级评测，用单序 pairwise 跑了 2000 对，新模型胜率 62% 准备全量。上线前抽查发现：交换顺序重跑，胜率跌到 51%——位置偏差贡献了 11 个点，其中一半是伪提升。整改：发布门禁改为双序一致才计入 + 3 次重跑取中位数 + 裁判换家族（参赛者是 A 家，裁判换 B 家），不一致对样本自动进人工队列（约占 8%）。重跑后真实胜率 55%，仍过门禁但避免了一次基于伪提升的决策。规范沉淀：**裁判结论进入发布决策前，必须声明用了哪几道防线与对应成本；没声明的一律视为未校准**。

下面模拟三种偏差与对应防线的实测效果。

```python
# Q7812 LLM-as-judge: 位置偏差 / 自评盲区 / 评分稳定性
import random

def judge(a, b, rubric_seed):
    """模拟裁判: 分数 = 质量分 + 噪声; 位置偏差: 排在前面的候选平均高 0.3"""
    rng = random.Random(rubric_seed)
    qa = {"q1": 4.0, "q2": 4.2, "q3": 3.6}[a] + rng.uniform(-0.3, 0.3)
    qb = {"q1": 3.7, "q2": 4.1, "q3": 3.5}[b] + rng.uniform(-0.3, 0.3)
    return (a, qa + 0.3), (b, qb)          # 位置偏差: A 位加成

# [1] 位置偏差: 同一对候选, 交换顺序后胜负翻转
def pairwise(x, y, seed):
    (xa, sa), (xb, sb) = judge(x, y, seed)
    return xa if sa > sb else xb

w1 = pairwise("q1", "q2", 42)          # q1 在前
w2 = pairwise("q2", "q1", 42)          # q2 在前, 同一评分标准
print(f"[1] q1 vs q2: 顺序1 胜者={w1}, 顺序2 胜者={w2} (位置偏差导致翻转)")
assert w1 != w2, "位置偏差应导致同一对候选胜负翻转"

# [2] 修复: 双序评估(both orders), 只认两次一致的结论
def fair_pairwise(x, y, seed):
    w_ab = pairwise(x, y, seed)
    w_ba = pairwise(y, x, seed)
    return w_ab if w_ab == w_ba else None      # 翻转 → 平局/人工复核

verdict = fair_pairwise("q1", "q2", 42)
print(f"[2] 双序评估: {verdict} (两次不一致 → 平局, 送人工)")
assert verdict is None

# [3] 自评盲区: 模型给自己的输出打分系统性偏高
def score(model_output, own=False):
    base = {"mine": 4.5, "other": 4.0}[model_output]
    return base + (0.4 if own else 0)          # 自评加成

self_bias = score("mine", own=True) - score("mine", own=False)
print(f"[3] 自评加成: +{self_bias} — 评估器与被评者同源时必须换裁判或双盲")
assert self_bias > 0

# [4] 评分稳定性: 同一样本重跑 k 次取中位数, 方差大就降级为人工
scores = [round(4.0 + random.Random(i).uniform(-0.5, 0.5), 2) for i in range(5)]
med = sorted(scores)[2]
spread = max(scores) - min(scores)
print(f"[4] 5 次评分 {scores}, 中位数 {med}, 极差 {spread:.2f} → {'可用' if spread < 0.6 else '判为不稳定, 人工'}")
stable = spread < 0.6
assert stable or med is not None
print("    → 实测 judge 三道防线: 双序消位置偏差 / 换裁判消自评盲区 / 重跑取中位数并监控极差")
```

**追问一**：双序评估把成本翻倍，有没有更省的偏差修正办法？—— 有，按代价排序：① 位置随机化 + 大样本聚合（单序但顺序随机，偏差在聚合中互相抵消，适合大规模粗筛，样本量要够大才能淹没系统偏差）；② 校准式单序（先用人工标注集量化位置偏差的方向与幅度，评分时显式扣减，便宜但依赖偏差稳定性）；③ 双序只用于"接近阈值"的边缘对（胜率在 45%~55% 之间的对才双序复核，其余单序结论足够置信）——这是最常用的成本优化，把 2 倍成本只花在真正拿不准的样本上。防线组合本质是"偏差 × 样本量 × 成本"的联合优化，没有免费午餐。

**追问二**：裁判提示词怎么校准？一致性验收用什么指标？—— 三步：① 构造**人工标注校准集**（200~500 对，人工双标注并仲裁出真值）；② 用裁判跑同一集合，计算与人工的一致率，pairwise 用 Cohen's kappa（≥0.6 可用、≥0.75 良好），绝对分用 Spearman 相关；③ 不达标就迭代裁判提示词（明确评分维度、给 few-shot 锚例、要求先写理由再给分——顺序很重要，先结论后理由会强化位置偏差）。校准集要定期换血防止"裁判过拟合到特定样本"。还有一个隐蔽问题：裁判理由写得头头是道不代表判断正确（合理化能力强于判断力），验收只看统计一致性，不看理由读起来像不像话。

## 背诵要点

- 三偏差三防线：位置偏差→双序评估（不一致判平局送人工）；自评盲区→换裁判/双盲；评分漂移→重跑 k 次取中位数并监控极差。
- 成本分配按决策重要度：回归评测单次+监控，发布门禁双序+仲裁+多裁判，争议样本进人工；边缘对才双序可省一半成本。
- 裁判上岗先校准：人工标注集 + Cohen's kappa（≥0.6 可用）；相对比较（pairwise）比绝对分稳，绝对分有刻度漂移。

## 复盘追问

- 新模型胜率从 62% 掉到重跑后的 55%，11 个点偏差你是怎么定位到"位置偏差"的？（按"正序胜率 vs 反序胜率"分组统计，显著不对称即位置偏差；再对同一对做双序复核验证翻转率）
- 为什么绝对评分容易刻度漂移而 pairwise 更稳？（绝对分依赖模型对"7 分该长什么样"的记忆，随上下文/时间漂移；pairwise 只做相对判断，且双序可自检——相对问题比绝对问题对 LLM 更友好）
