### Q7750 · 报价 1998 变成 2000：模型转述工具结果时的数值篡改与回抄校验

难度：P6 ｜ 标签：LLM、工具结果转述、数值保真、回抄校验、fail-closed

基线：Python 3.12；模拟工具返回数值 → 模型"转述"环节的常见失真（取整/单位换算/千分位丢失）→ 回抄校验拦截。

**问**：工具查到商品库存价 1998 元，模型的回复里写成"约 2000 元"；对账系统从模型回复里抽取金额，和工具结果对不上，月度差了几十万。模型不是故意说谎，转述为什么总会漂？关键数值到底怎么从"模型嘴"里安全地走到用户和下游系统？

**答**：
- **结论**：模型转述数值时有三类系统性失真：① **取整/约化**——"约 2000 元""近 30%"，对可读性友好、对数值致命；② **格式变形**——千分位、单位换算、币种混写（¥1998 / 1998 元 / 1998 RMB）；③ **张冠李戴**——多字段场景把 A 商品的值接到 B 商品上。根因是模型在做"复述"任务时，语言流畅目标压过数值保真目标。工程解法是**回抄校验（echo-back validation）**：关键数值不信任转述文本，从回复里正则抽取数值，与工具结果精确比对，不一致要么打回重生成、要么在展示层用"数值由系统注入"的模板兜底。
- **取舍**：① 全部数值都校验成本高，按字段分级：金额、库存、日期等"会触发下游动作"的字段强制回抄，描述性数值（百分比、评分）宽松；② 修复方式选"系统注入"优于"让模型重写"——把工具数值渲染成固定模板（表格/代码块），模型只负责周围的叙述文字，数值压根不经它的手；③ 失败策略 fail-closed：校验不过就把数值位置替换为"[见上方数据卡]"，绝不展示错误数字。
- **实战**：① 回抄校验做成输出管线的独立层（Q1145 输出校验器管线的思路），与 schema 校验并列；② 埋点统计"回抄不一致率"，按工具/字段分组看，不一致率高的工具说明其返回格式对模型不友好（嵌套太深、字段名歧义）；③ 单测覆盖千分位、单位、多字段张冠李戴三类样本。

```python
"""回抄校验：从转述文本抽取数值与工具结果精确比对，失败 fail-closed。"""
import re

TOOL_RESULT = {"price": 1998, "stock": 30, "sku": "SKU-88"}

MONEY_PAT = re.compile(r"(\d[\d,]*(?:\.\d+)?)\s*(?:元|¥|RMB)?")


def extract_money(text: str) -> list[float]:
    """从转述文本抽取所有候选金额（去千分位）。"""
    return [float(m.replace(",", "")) for m in MONEY_PAT.findall(text)]


def echo_check(tool: dict, reply: str, strict_fields: tuple[str, ...]
               ) -> tuple[bool, list[str]]:
    problems = []
    for field in strict_fields:
        want = float(tool[field])
        got = extract_money(reply)
        if not any(abs(g - want) < 1e-9 for g in got):
            problems.append(f"{field}: 工具值 {want} 未在回复中精确出现"
                            f"(候选 {got[:3]})")
    return not problems, problems


def safe_render(tool: dict, narrative: str) -> str:
    """系统注入兜底：数值渲染成数据卡，叙述文字里的数字被占位符替换。"""
    scrubbed = MONEY_PAT.sub("[见数据卡]", narrative)
    card = " | ".join(f"{k}={v}" for k, v in tool.items())
    return f"[数据卡] {card}\n{narrative if not problems_check(narrative, tool) else scrubbed}"


def problems_check(narrative: str, tool: dict) -> bool:
    ok, _ = echo_check(tool, narrative, ("price", "stock"))
    return ok


if __name__ == "__main__":
    bad_reply = "该商品价格约 2000 元，当前库存大概 30 件，欢迎选购。"
    ok, probs = echo_check(TOOL_RESULT, bad_reply, ("price", "stock"))
    print("转述:", bad_reply)
    print("回抄校验:", "通过" if ok else f"拦截 -> {probs}")

    good_reply = "该商品价格为 1998 元，当前库存 30 件，欢迎选购。"
    ok2, _ = echo_check(TOOL_RESULT, good_reply, ("price", "stock"))
    print("修正后:", "通过" if ok2 else "仍拦截")

    print("\nsafe_render 输出:")
    print(safe_render(TOOL_RESULT, bad_reply))
    print("\n结论：关键数值不过模型的手——回抄拦截 + 数据卡注入，两者缺一不可")
```

**追问一**：为什么不直接让模型"务必精确复现数字"来修复？

→ 解析：提示词能降低失真率，但失真是采样过程的概率行为，压不到零——金额场景一次失真就是一次资损。分层防线里提示词只是第一层；第二层是校验拦截（回抄）；第三层是**结构性规避**：把数值从"模型输出文本"里挪出去，改成展示层模板注入（数据卡/表格由系统渲染，模型文字环绕其外）。三层成本递增但可靠性递增，金额、库存这类触发下游动作的字段必须到第三层。

**追问二**：多字段场景的"张冠李戴"怎么校验出来？

→ 解析：回抄校验按字段维度做"值-主体"配对检查：从回复里同时抽取数值与其邻近的主体名（SKU/商品名），比对 (主体, 字段, 值) 三元组与工具结果是否一致——只查"数值出现过"查不出 A 的价格安到 B 头上。工程上更稳的做法同样是结构性规避：多对象场景直接渲染成表格（每行一个对象、每列一个字段），模型只写总结句，不写逐对象数值句；或者强制模型输出结构化 JSON（Q7517 约束解码），渲染交给前端，转述自由度归零。
