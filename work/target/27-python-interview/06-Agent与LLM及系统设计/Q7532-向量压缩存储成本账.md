### Q7532 · 一亿条 1536 维向量要多少内存？压缩的召回代价怎么算？

> 难度:★★★★ | 标签:向量检索, 量化, 成本工程

**问**：一亿条 1536 维 float32 向量的存储与内存账怎么算？标量量化（int8）、PQ（乘积量化）、降维各自的压缩倍数与召回代价？为什么 PQ 必须配精排？什么情况下不值得做压缩？

**答**：结论：原始向量 = 1 亿 × 1536 × 4B ≈ **629GB（单副本，另加索引开销）**。压缩选项按"压缩倍数换召回损失"排序：int8 标量量化 4 倍（损失约 1-2%，通常可接受）、PQ 16B/条约 38 倍（损失 3-8%，必须配原始向量精排）、二值量化最高 48 倍（损失大，重打分不可省）。压缩后**必须跑黄金集召回回归**，损失超阈值触发 rerank 补偿或回退。

机理与实战：
- **三份账一起算**：① 磁盘存储（可压缩）；② 内存常驻（HNSW 图索引要热，内存 = 向量 + 邻接表 M×2×4B/条）；③ 重建成本（PQ 码本要训练、换维要重嵌入 Q7518 的迁移路线）——很多团队只算了磁盘账。
- **PQ 粗排 + 原始精排是标准组合**：PQ 用压缩距离快速筛出候选集（几百条），再用原始 float32 向量精排——压缩损失被精排兜住；只换 PQ 不排的召回率不可接受。
- **什么时候不压缩**：千万级以下、内存充裕——压缩的工程复杂度（码本训练、双索引维护、精排延迟）超过内存收益；先算账再动手，别为省 200GB 内存引入一整套量化管线。
- **降维是另一个维度**：1536→512 用 Matryoshka 模型或 PCA，压缩 3 倍且可能提升密度，但需要重嵌入——归到模型迁移路线（Q7518）而不是存储优化。

```python
# 基线:Python 3.10+;纯标准库模拟向量存储账与标量量化的召回损失
# 真实场景:pgvector/qdrant;float32 -> int8 标量量化 + PQ 粗排精排组合
from __future__ import annotations
import math
import random


def storage_gb(n: int, dim: int, dtype_bytes: float, index_overhead: float = 0.1) -> float:
    raw = n * dim * dtype_bytes
    return (raw * (1 + index_overhead)) / 1024 ** 3


def scalar_quantize(v: list[float], bits: int = 8) -> list[float]:
    """标量量化:min-max 映射到 2^bits 档(存档位,读时反解)。"""
    lo, hi = min(v), max(v)
    steps = 2 ** bits - 1
    return [round((x - lo) / (hi - lo or 1) * steps) / steps * (hi - lo) + lo
            for x in v]


def cosine(a: list[float], b: list[float]) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(x * x for x in b))
    return dot / (na * nb or 1)


def recall_overlap(dim: int, k: int = 10, n_cand: int = 300,
                   seed: int = 7, bits: int = 8) -> float:
    """随机向量上模拟:量化噪声导致的 top-k 重合率(召回近似)。"""
    rng = random.Random(seed)
    noise_scale = 1.0 / math.sqrt(dim)                   # 量化噪声与维度相关
    doc = [[rng.gauss(0, 1) for _ in range(dim)] for _ in range(n_cand)]
    q = [rng.gauss(0, 1) for _ in range(dim)]

    def top_k(vecs: list[list[float]]) -> set[int]:
        scored = sorted(range(n_cand), key=lambda i: -cosine(q, vecs[i]))
        return set(scored[:k])

    orig = top_k(doc)
    quant = top_k([scalar_quantize([x + rng.gauss(0, noise_scale) for x in v],
                                   bits=bits) for v in doc])
    return len(orig & quant) / k


def demo() -> None:
    n, dim = 100_000_000, 1536
    print(f"存储账(1 亿 x 1536 维):float32 {storage_gb(n, dim, 4):.0f}GB / "
          f"int8 {storage_gb(n, dim, 1):.0f}GB(4x) / "
          f"PQ(16B/条)≈{storage_gb(n, 16, 1):.2f}GB(38x) ✅")
    assert storage_gb(n, dim, 4) > storage_gb(n, dim, 1) * 3.9
    print("折中:int8 保召回,PQ 省存储;生产常用 PQ 粗排 + 原始向量精排的组合")

    for bits in (8, 4):
        r = recall_overlap(1536, bits=bits)
        print(f"{bits}bit 标量量化 top-10 重合率: {r:.0%} "
              f"({'损失可接受' if r >= 0.9 else '需 rerank 补偿'}) ✅")
    print("纪律:量化/降维后必须跑黄金集回归,召回损失 >2% 触发 rerank 补偿或回退 ✅")


if __name__ == "__main__":
    demo()
```

**追问一**：HNSW 的内存开销怎么估？为什么内存比磁盘更早成为瓶颈？
答：HNSW 邻接表每向量约 M×2×4B（M=16 时 128B）加上层结构，1 亿条约 12-20GB——必须常驻内存才有效能；而向量本体可以压缩放磁盘（diskann 思路）。所以内存账 = 图索引（不可压缩）+ 热向量缓存，比磁盘账先爆。

**追问二**：压缩方案上线后发现长尾 query 召回差、头部 query 正常，为什么？
答：量化误差对"接近边界的相似度对"影响最大——头部 query 与文档差异大、排序稳健；长尾 query 常在阈值边缘，噪声直接翻转排序。这决定了评估集必须覆盖长尾（按 query 频次分层抽样），不能只用头部高频对验证。

## 背诵要点
- 1 亿×1536 维 float32 ≈ 629GB + 索引开销；int8 4 倍（损失 1-2%）、PQ 38 倍（3-8%，必配精排）、二值 48 倍（重打分不可省）。
- 三份账：磁盘、内存（HNSW 图不可压缩、先爆）、重建（码本训练/重嵌入）。
- 压缩后黄金集召回回归是硬门禁（损失 >2% 触发 rerank 或回退）；评估集要覆盖长尾 query。
