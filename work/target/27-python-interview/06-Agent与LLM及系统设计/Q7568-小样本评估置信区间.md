### Q7568 · 小样本评估集的置信区间与决策规则

难度：P6 | 标签：评估、统计、置信区间、bootstrap

**问**：评估集只有 20 条，改 prompt 后分数从 0.80 涨到 0.82，能上线吗？"点估计"在决策里为什么不可靠？工程上用什么决策规则替代"涨了就上"？

**答**：
- **结论**：小样本分数有显著噪声：20 条评估、每条对错二值，0.82 与 0.80 的差异完全可能在噪声区间内——点估计决策等于掷硬币。工程规则：对评估分数算置信区间（bootstrap 重采样最省事：对评估集有放回抽样 N 次算均值分布，取 95% 区间），决策看区间而非点：区间下限 > 基线才上线；区间上限 ≤ 基线则拒绝；区间跨基线 → 扩样本再决策。样本量预估：要分辨 2 个点的差异，二值指标大约需要每侧数百条——20 条只能分辨 15+ 个点的差异。
- **取舍**：bootstrap vs 参数法（正态近似）：bootstrap 不假设分布、实现 10 行，小样本下更稳；代价是计算量（2000 次重采样毫秒级，无所谓）。扩样本 vs 提效：评估跑一次有成本，"分层抽样"（把变化大的维度分层各抽固定条数）比无脑堆样本更省。
- **实战**：落地为上线门禁：CI/发布流程里评估分数必须带 CI 输出，决策规则代码化（`lower > baseline → go`），禁止人工看眼估。同类场景都适用：LLM judge 打分（连续值）、检索 recall、任务成功率——只要样本小，都要区间化。

```python
"""小样本评估集的分数噪声：bootstrap 置信区间与上线决策规则。"""
import random

scores = [0.82, 0.79, 0.85, 0.71, 0.88, 0.80, 0.75, 0.84]   # 8 次评估：均值 0.805
BASELINE = 0.80

def bootstrap_ci(xs, iters=2000, ci=0.95):
    rng = random.Random(7)
    means = []
    n = len(xs)
    for _ in range(iters):
        sample = [rng.choice(xs) for _ in range(n)]
        means.append(sum(sample) / n)
    means.sort()
    lo = means[int((1 - ci) / 2 * iters)]
    hi = means[int((1 + ci) / 2 * iters) - 1]
    return lo, hi

lo, hi = bootstrap_ci(scores)
print(f"均值 {sum(scores)/len(scores):.3f}，95% CI [{lo:.3f}, {hi:.3f}]")

def decide(lo, hi, baseline):
    if lo > baseline:
        return "上线（下限仍高于基线）"
    if hi <= baseline:
        return "不上线（上限都打不过基线）"
    return "样本不足：扩评估集再决策"

print("决策:", decide(lo, hi, BASELINE))
print("要点：评估集小则分数有噪声；决策规则看置信区间下限而非点估计，区间跨基线时扩样本")
```

**追问链**：
1. 追问一层：为什么 bootstrap 在小样本下仍可用？它有什么前提？（前提是样本对总体有代表性且各条独立；不依赖正态假设；样本有聚类/相关性时 bootstrap 会低估方差——评估集要独立采样）
2. 追问二层：judge 打分是 1-5 连续值，决策规则要改什么？（噪声更大，CI 更宽；可配对设计——同一题新旧 prompt 都打分，做差值的配对 bootstrap，方差显著缩小）

**背诵要点**：
1. 小样本点估计决策=掷硬币；用 bootstrap 95% CI 包住均值。
2. 规则：下限>基线才上线，跨基线扩样本；二值指标分辨 2 个点需数百样本。
3. 配对设计（同题新旧对比）能大幅缩窄区间。

**复盘追问**：
1. 评估涨了 2 个点且 CI 下限刚好过基线，上线后线上指标没动，复盘查什么？（评估集与线上分布的偏差——CI 只保证统计显著，不保证分布代表性）
2. 为什么"每条评估独立"是 bootstrap 的前提？（评估题间相关（同一文档衍生）会低估方差，区间虚窄，决策虚假自信）
