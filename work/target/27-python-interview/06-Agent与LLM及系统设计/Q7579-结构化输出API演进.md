### Q7579 · 结构化输出 API 演进：JSON Mode 到 Schema 约束解码

难度：P6 ｜ 标签：版本演进 / structured outputs / JSON Schema / 兼容性

**问**：结构化输出三年间从"prompt 里求模型输出 JSON"演进到 API 级 JSON Schema 约束（structured outputs）。老代码怎么分级迁移？各层可靠性差异是什么？

**答**：

**结论**：四代方案可靠性递增：① prompt 约定 + 容错解析（失败率 5-15%，靠 retry 兜）；② JSON mode（保证合法 JSON 但不保证 schema，字段缺失/类型错仍常见）；③ API 级 Schema 约束（服务端约束解码，schema 遵循近乎 100%，但 schema 子集受限——不支持部分关键字、有 token 预算限制、复杂 schema 被 400 拒绝）；④ 自托管约束解码（outlines/xgrammar 级，本地 lexer 级强制，灵活性最高但要自己维护 grammar 兼容）。迁移策略按依赖层级：定义处统一用 Pydantic 模型 → 各代方案从同一个模型派生（prompt 时代生成 schema 描述、API 时代直接传 model_json_schema()）——定义只写一次，切换只换执行层。

**取舍**：API 约束解码不是免费午餐：① schema 表达力受限（复杂 oneOf/递归引用常被拒，要简化 schema）；② 约束可能影响生成质量——模型被迫在非法分支里选词，长枚举约束下质量下降；③ 严格 schema 拒答行为不同（不满足时 API 报错 vs 静默修补），错误处理路径要按供应商核对。与 retry 的关系：约束解码消灭"格式错误重试"，消灭不了"语义错误重试"（值对但业务错），别指望迁约束解码后重试层下岗。

**实战**：迁移落地：Pydantic v2 的 `model_json_schema()` 直接喂 API（注意 schema 白名单差异，`additionalProperties: false` 等要求显式声明）；自托管走 outlines（>=0.1）/xgrammar，标注 Python 3.10+ 基线。降级链：API 约束不可用（schema 被拒）→ JSON mode → prompt + 解析重试，每层带监控计数，让"降级率"成为可见指标。

```python
# 结构化输出分级执行器：同一 Pydantic 定义，四代方案可切换（标准库模拟）
# 仅标准库，Python 3.9+；生产用 pydantic>=2 / outlines>=0.1
from __future__ import annotations

import json
import re

# 实际项目用 pydantic>=2 定义模型并派生 model_json_schema()
SCHEMA = {
    "type": "object",
    "properties": {"city": {"type": "string"}, "days": {"type": "integer"}},
    "required": ["city", "days"],
    "additionalProperties": False,
}


def run_level(model_out: str, level: str) -> dict:
    """level: prompt / json_mode / api_schema / local_grammar"""
    if level == "prompt":
        # prompt 约定：模型可能输出带前导文字的 JSON
        m = re.search(r"\{.*\}", model_out, re.S)
        if not m:
            raise ValueError("parse fail")
        return json.loads(m.group(0))
    if level == "json_mode":
        data = json.loads(model_out)  # 保证合法 JSON，但 schema 不保
        if "city" not in data:
            raise KeyError("schema drift")
        return data
    if level == "api_schema":
        # 服务端约束解码保证语法；应用层仍需 schema/语义校验
        assert SCHEMA["additionalProperties"] is False
        data = json.loads(model_out)
        for k in SCHEMA["required"]:
            if k not in data:
                raise KeyError(k)
        return data
    if level == "local_grammar":
        return json.loads(model_out)  # 本地 grammar 强制
    raise ValueError(level)


def fallback_chain(model_out: str) -> tuple[dict, str]:
    """降级链：api_schema → json_mode → prompt，返回(结果, 实际层级)。"""
    for lv in ("api_schema", "json_mode", "prompt"):
        try:
            return run_level(model_out, lv), lv
        except Exception:
            continue
    raise ValueError("all levels failed")


def main() -> None:
    good = '{"city": "Tokyo", "days": 3}'
    noisy = '好的，结果如下：{"city": "Osaka", "days": 2}'
    missing = '{"days": 4}'

    assert run_level(good, "api_schema") == {"city": "Tokyo", "days": 3}
    assert run_level(noisy, "prompt")["city"] == "Osaka"  # prompt 层容错解析
    try:
        run_level(missing, "json_mode")
        raise SystemExit("不应到达")
    except KeyError:
        pass  # json_mode 保证 JSON 但不保 schema

    # 降级链：带前导文字的输出 → api_schema/json_mode 层解析失败 → prompt 层容错成功
    res, lv = fallback_chain(noisy)
    print("降级链结果:", res, "实际层级:", lv)
    assert lv == "prompt"
    assert res["city"] == "Osaka"
    print("结论：定义一次（Pydantic），执行层四级可切换，降级率必须监控")


if __name__ == "__main__":
    main()
```

**追问链**：

- 追问 1：为什么"API 级约束"仍会输出业务上错的数据？——约束解码只约束语法（schema 合法），不约束值语义（days=-5 合法但错误）；语义校验属于应用层 validator（Pydantic 的 field validator / 业务规则），两层不能互相替代。
- 追问 1.1：复杂 schema 被 API 400 拒绝时怎么简化？——常见手法：递归/深嵌套拍平成中间层、oneOf 改为带 type 判别字段的扁平结构、去 unsupported 关键字（如部分 pattern 约束）；简化后要在 prompt 里补回语义约束，等价性用评测集回归验证。
- 追问 2：约束解码对生成质量的影响怎么度量？——对照实验：同一评测集，约束开/关比任务指标（抽取 F1、代码可执行率）；重点盯长枚举与强格式场景（约束把模型逼到低概率 token 上）；若质量损失 >2% 而 parse 失败率只省 5%，可能不值得全局开。

**背诵要点**：

1. 四代可靠性递增：prompt+容错解析 → JSON mode（保 JSON 不保 schema）→ API Schema 约束（语法 100% 但 schema 子集受限）→ 本地 grammar 约束。
2. 定义只写一次：Pydantic 模型派生各层输入（model_json_schema()）；降级链 api→json_mode→prompt，降级率做监控指标。
3. 约束解码消灭语法重试、消灭不了语义校验；复杂 schema 要拍平简化，质量影响用对照评测集度量。
