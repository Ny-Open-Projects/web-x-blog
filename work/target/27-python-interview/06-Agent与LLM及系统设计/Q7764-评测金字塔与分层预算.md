### Q7764 · 全量评测一次 300 美元不敢天天跑：评测金字塔与分层预算

难度：P6 ｜ 标签：LLM 评测、评测分层、成本预算、门禁、冒烟测试

基线：Python 3.12；实现评测分层预算分配器（门禁层/夜间层/周度层），按变更影响面选层并估算成本，全标准库实跑。

**问**：评测集 2000 条，全量跑一次调 2000 次模型 API 花 300 美元、40 分钟。结果就是没人日常跑评测——"等大版本上线前跑一次"成了唯一仪式，回归问题全靠用户反馈。工程化的做法是把评测像测试金字塔一样分层：每层跑什么、什么时候跑、预算怎么分？提示词改动和模型升级分别触发哪层？

**答**：
- **结论**：评测金字塔三层，**越往上越贵越准、触发频率越低**：① **门禁层（L1）**：50~100 条分层抽样（覆盖能力维度：抽取/推理/拒答/格式），每次 PR 秒级到分钟级跑完，当"冒烟测试"用——拦结构性回归（格式崩了、拒答率飙升）；② **夜间层（L2）**：全量或大子集，每晚对 main 分支自动跑，产出带置信区间的分数（Q7759 方差治理），拦"缓慢劣化"；③ **周度层（L3）**：人工评审级——badcase 深审、困难子集专攻、与生产流量对拍（Q7529 trace 采样回流），发现"评测集没覆盖的新失败模式"。**触发策略与变更类型绑定**：提示词小改→L1；提示词大改/换检索组件→L1+L2；模型升级/架构变更→L1+L2+双跑对拍（Q7548）。预算的杠杆在于 L1 的样本选择：分层抽样保证"少量样本覆盖全部失败模式"，比随机 100 条的拦截力高得多（Q7555 分层抽样思想的前置化）。
- **取舍**：① L1 快与准的矛盾：50 条能拦"灾难级回归"，拦不住 2~3pp 的质量漂移——所以 L1 的门禁规则只设"红线"（拒答率、格式合法率），质量分数不看 L1 看 L2（Q1164 分数卡点的分层版）；② 夜间全量的成本摊薄：夜间容量错峰（Q7631），供应商批处理接口再省一半（Q7685 Batch API）；③ L3 的人工预算最稀缺：限定在"分数没掉但用户反馈掉了"的排查与新增能力维度建设，别用来重复跑数；④ 层间的一致性：三层用同一评测框架与指标定义（Q7255 口径字典思想），否则 L1 过 L2 挂的归因会变成三层实现打架。
- **实战**：① CI 集成 L1（PR 门禁），调度器挂 L2（夜间），日历挂 L3（周会）；② 每层输出固定报告：L1 红线通过/失败、L2 分数区间+环比、L3 结论与行动项；③ 评测预算看板：本周各层花费与拦截数——评测的价值要用"拦住的回归"证明，不是跑了多少次；④ L1 样本集季度轮换防过拟合（Q7539 防泄漏的常态化版本）。

```python
"""评测分层预算: 三层金字塔 + 按变更类型选层 + 成本估算。"""
from dataclasses import dataclass


@dataclass
class EvalLayer:
    name: str
    samples: int
    cost_per_call: float      # 单次调用成本(元)
    duration_min: float       # 单线程时长(分钟), 并行度外部处理
    trigger: str


LAYERS = [
    EvalLayer("L1 门禁", 80, 0.15, 2, "每次 PR"),
    EvalLayer("L2 夜间全量", 2000, 0.15, 50, "每晚"),
    EvalLayer("L3 人工评审", 100, 0.50, 60, "每周"),
]


def plan_for_change(change: str) -> dict:
    """按变更类型选层: 提示词小改/大改/模型升级 三档。"""
    if change == "prompt_minor":
        selected = ["L1 门禁"]
    elif change == "prompt_major":
        selected = ["L1 门禁", "L2 夜间全量"]
    elif change == "model_upgrade":
        selected = ["L1 门禁", "L2 夜间全量", "L3 人工评审"]
    else:
        selected = ["L1 门禁"]
    plan = [l for l in LAYERS if l.name in selected]
    cost = sum(l.samples * l.cost_per_call for l in plan)
    duration = sum(l.duration_min for l in plan)
    return {"change": change, "layers": [l.name for l in plan],
            "cost": cost, "duration_min": duration}


def l1_sample_plan(fullset: list[dict], per_bucket: int = 10) -> dict:
    """L1 分层抽样: 按能力维度配额抽, 而不是随机。"""
    buckets: dict[str, list] = {}
    for item in fullset:
        buckets.setdefault(item["capability"], []).append(item)
    plan = {}
    for cap, items in buckets.items():
        # 均匀步长抽样保证覆盖难度梯度
        step = max(1, len(items) // per_bucket)
        plan[cap] = [i["id"] for i in items[::step][:per_bucket]]
    return plan


if __name__ == "__main__":
    for change in ("prompt_minor", "prompt_major", "model_upgrade"):
        p = plan_for_change(change)
        print(f"{change:>13}: 层={p['layers']} 成本={p['cost']:.0f}元 时长={p['duration_min']:.0f}分钟")

    print("\nL1 分层抽样 (每能力维度配额):")
    fullset = ([{"id": f"ext{i}", "capability": "抽取"} for i in range(400)] +
               [{"id": f"rea{i}", "capability": "推理"} for i in range(700)] +
               [{"id": f"ref{i}", "capability": "拒答"} for i in range(300)] +
               [{"id": f"fmt{i}", "capability": "格式"} for i in range(600)])
    plan = l1_sample_plan(fullset, per_bucket=5)
    for cap, ids in plan.items():
        print(f"  {cap}: 抽 {len(ids)}/{sum(1 for i in fullset if i['capability'] == cap)} 条 {ids[:3]}...")
    total_l1 = sum(len(v) for v in plan.values())
    print(f"  L1 总量 {total_l1} 条 vs 全量 {len(fullset)} 条 -> 成本 {total_l1 * 0.15:.0f}元/次")

    ok = plan_for_change("model_upgrade")["cost"] > plan_for_change("prompt_minor")["cost"] * 20
    print(f"校验: 模型升级的评测预算远大于小改 -> {'通过' if ok else '异常'}")
    print("\n结论：评测金字塔按'贵度与频率反比'分层; L1 分层抽样是预算杠杆,")
    print("      触发策略与变更类型绑定, 评测价值用拦截数证明")
```

**追问一**：L1 只有 80 条，怎么保证它"拦得住"该拦的？

→ 解析：L1 的定位是红线监测不是质量评估，有效性靠三件事：① **样本分层**：按能力维度×难度配额抽样，每个失败模式至少有 5 条代表（上面代码的 l1_sample_plan），随机抽样会让某类失败模式整层缺席；② **红线指标的选择**：只设"结构性可判定"的规则——JSON 可解析率、必含字段出现率、拒答率、工具调用成功率，这些在 80 条上的波动小（二项比例的区间可控，Q7759），而"语义质量分"在 80 条上方差太大不适合做门禁；③ **失败即阻断**：L1 红线挂了 PR 不准合，逼着作者本地补测；"挂了但人工豁免"要走豁免登记（记录谁豁免的、为什么），豁免率本身进周报——豁免常态化说明红线选错了。L1 拦不住的（2~3pp 漂移）明确交给 L2 的区间判断，两层职责不重叠。

**追问二**：夜间全量挂了，怎么快速归因到是哪个变更？

→ 解析：归因靠**变更登记与差异分解**。① 评测框架对每个 case 记录"本次得分 vs 昨日得分"的 case 级 diff（Q7570 分层漏斗回归思想），聚合出"恶化最集中的能力维度与样本簇"；② 与变更登记表对时间窗：夜里挂了，查当天合入的所有 PR——提示词 diff、检索配置 diff、依赖 diff 各归各的；③ **二分回放**：怀疑某 PR 时，checkout 到它之前的状态在同样样本上重跑（成本几百次调用），分数恢复则锁定。④ 结构化输出的 diff 尤其快：JSON 解析失败率突升通常是格式约束丢失，定位到提示词或工具 schema 的一行改动。预防比归因便宜：每个 PR 合入前 L1 过红线 + 变更登记必填"影响的能力维度"，夜间报告按维度聚合，归因从"考古"变成"查表"。
