### Q7703 · 模型蒸馏与微调的质量-成本分界

难度：P7 ｜ 标签：容量成本账、模型优化、蒸馏、微调

基线：Python 3.12；纯 Python 建质量-成本决策模型。

**问**：大模型 API 账单太高，团队想"用蒸馏的小模型替代"。模型分级路由（大小模型分流）已经做过，蒸馏/微调又和它有什么不同？什么情况下值得做，什么情况下是浪费？

**答**：
- **结论**：三者是不同的杠杆——分级路由是**按请求难度分流**（简单请求走小模型），不改变模型本身；**蒸馏**是用大模型输出当教师信号训练小模型，把能力压缩进小模型（一次训练、长期低推理成本）；**微调**是用领域数据继续训练（改变模型的领域适配，不一定变小）。蒸馏/微调的收益只有在**高频、稳定、任务边界清晰**的场景才回本——前期数据构造、训练、评测、迭代都是固定成本，摊到海量请求才划算。
- **取舍**：蒸馏小模型在分布内任务上接近大模型，但**泛化变窄**，遇到分布外请求质量断崖；且要持续维护训练数据（大模型升级、业务变化）。API 模型和开源模型差价、请求量、质量容忍度共同决定分界点：低频/多变需求直接用 API 更灵活。
- **实战**：先算账——固定成本（数据+训练+评测+运维）vs 每次调用节省 × 请求量，求回本量级；用大模型输出做教师数据时要有质量过滤（否则把幻觉也蒸进去）；建立回归评测集，蒸馏后逐版本对比质量，设质量红线；保留大模型作为兜底路由。

```python
def break_even_requests(fixed_cost: float, api_cost: float, local_cost: float) -> float:
    """回本请求量：固定成本 / 每次节省。"""
    saving = api_cost - local_cost
    if saving <= 0:
        return float("inf")
    return fixed_cost / saving


if __name__ == "__main__":
    fixed = 50_000.0       # 数据/训练/评测/运维固定成本
    api, local = 0.02, 0.002  # 单次调用成本
    n = break_even_requests(fixed, api, local)
    print(f"回本请求量≈{n:.0f} 次")
    print("低于此量级用 API 更划算，高于才值得蒸馏/微调")
```

**追问一**：蒸馏小模型什么情况下质量会断崖？
→ 解析：遇到训练数据分布之外的请求（新领域、新格式、复杂推理）时，小模型缺乏大模型的泛化能力，质量骤降。所以要保留大模型兜底路由，并用 OOD（分布外）样本做回归评测。

**追问二**：用大模型输出做教师数据有什么风险？
→ 解析：会把大模型的幻觉、偏见、错误一并"蒸"进小模型，而且小模型无法纠错。必须做教师输出的质量过滤与人工抽检，必要时用真实标注数据校正。
