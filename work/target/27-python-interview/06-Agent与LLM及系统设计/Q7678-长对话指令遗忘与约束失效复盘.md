### Q7678 · 长对话指令遗忘与约束失效：复盘

难度：P6/P7 ｜ 标签：事故复盘、上下文管理、Agent
基线：通用 LLM 行为（各供应商一致存在的注意力衰减现象）；代码为标准库模拟。

**问**：客服 Agent 在长对话（40+ 轮）后开始违反系统约束——回答超出业务范围、承诺退款、编造政策。单轮测试全部通过。这类"指令遗忘"的机制是什么？如何用工程手段守住约束？

**答**：**结论**：机制是**注意力稀释 + 位置偏置**：约束写在 system prompt 开头，随着对话变长，中间插入了大量工具结果与闲聊，开头的约束在注意力分布里权重衰减；而"临场指令"（用户最近几条消息）权重最高——模型并不是"忘了"，是**近因压过了远因**。所以长对话后违反的是低频约束（业务边界），却仍能遵守高频规范（语气礼貌）：两者在上下文里的出现频率不同。

**取舍**：四条工程防线（按成本递增）：① **约束重申**——每 N 轮把关键约束重新注入（作为 system 消息更新或紧邻最新用户消息的高优先级提醒），位置比重复次数更重要（近因位置最有效）；② **上下文压缩时保留约束段**——摘要永远不动 system 约束，只压历史（与 Q7645 裁剪的成本工程配合：裁剪保约束不保闲聊）；③ **输出侧校验**——约束可判定的部分（退款承诺、越界话题）用规则/分类器对输出做闸，拦截比防止幻觉更可靠；④ **硬约束下沉到工具层**——"能不能退款"不由模型决定，退款工具在服务端校验资格，模型的越界承诺根本无法兑现。

**实战**：上线前用"长对话压力测试集"验收：固定 40-80 轮脚本对话，在第 20/40/60 轮插入诱导违规的用户消息（"你们说了可以全额退款"），统计违规率随轮次的曲线；这既是约束防线的验收指标，也是版本回归的行为基线。

```python
# 指令遗忘的机制模拟与四道防线（标准库可运行）
from dataclasses import dataclass, field

@dataclass
class Session:
    system_rules: tuple[str, ...]        # 关键约束（低频、远因）
    messages: list[tuple[str, str]] = field(default_factory=list)

    def reinject_rules_if_due(self, every_n: int = 10):
        """防线 1：约束重申——注入位置紧跟最新消息（近因位置）。"""
        if len(self.messages) % every_n == 0 and self.messages:
            self.messages.append(
                ("system", "【重申】务必遵守： " +
                 "；".join(self.system_rules)))

    def compact_history(self, keep_last: int = 6) -> None:
        """防线 2：压缩只压闲聊历史，system 约束永不进摘要。"""
        if len(self.messages) > keep_last:
            self.messages = self.messages[-keep_last:]

    def context_for_llm(self) -> list[str]:
        """近因偏置模拟：越靠后的消息权重越高（示意）。"""
        n = len(self.messages)
        weights = [1 / (n - i) for i in range(n)]      # 位置权重递增
        rules_weight = 1 / n                            # 开头约束被稀释
        return ([f"开头约束权重≈{rules_weight:.2f}",
                 f"末条消息权重≈{weights[-1]:.2f}"]
                + [f"{r}: {m}" for r, m in self.messages[-2:]])

# 模拟 40 轮后：开头约束权重被稀释到 1/40
sess = Session(system_rules=("不承诺退款", "不答非客服话题"))
for i in range(40):
    sess.messages.append(("user", f"第{i}轮消息"))
    sess.messages.append(("assistant", "回复"))
print(*sess.context_for_llm()[:2], sep="\n")

# 防线 3：输出侧规则闸（可判定的约束用规则拦）
import re
def output_gate(reply: str) -> tuple[bool, str]:
    if re.search(r"(全额退款|马上退款|承诺.*退款)", reply):
        return False, "命中退款承诺约束 -> 拦截并改写"
    if "竞品" in reply:
        return False, "越界话题拦截"
    return True, "通过"

print(output_gate("好的，我们马上为您全额退款！"))
print(output_gate("根据政策，退款需走审核流程，预计3个工作日。"))

# 防线 4：硬约束下沉工具层——模型的越界承诺无法兑现
def refund_tool(user_id: str, amount: float) -> dict:
    eligible = user_id.startswith("vip") and amount <= 500
    return {"approved": eligible,
            "note": "资格由服务端校验，模型口头承诺不产生效果"}
print(refund_tool("user_123", 300))
```

**追问 1**：为什么"把约束重复写在 system prompt 十遍"不如"每 10 轮重新注入一次"？
提示：重复在开头只增加远因位置的内容量，稀释照样发生；重申发生在近因位置，权重高。上下文优化的本质是"位置工程"而不是"字数工程"。

**追问 2**：约束重申会不会引入新问题（模型过度保守）？
提示：会——频繁重申安全类约束会提升拒答率，业务回答变保守；重申文案要写"边界内可以做什么"而不仅是"不许做什么"，并用压力测试集观察违规率与拒答率两个指标的平衡。

**追问 3**：摘要压缩历史时，怎么避免把"用户已表达的关键意图"压掉？
提示：意图与约束分开处理——关键意图（订单号、诉求）提取为结构化状态卡（始终保留全文），闲聊走摘要；摘要质量用"恢复任务"评估（从摘要能否还原关键事实）。

## 背诵要点
1. 指令遗忘机制：注意力稀释 + 近因偏置，开头约束权重随轮次按 1/n 衰减，低频约束先失效。
2. 四道防线按成本递增：近因位置重申约束 → 压缩保约束 → 输出规则闸 → 硬约束下沉工具层。
3. 验收靠长对话压力测试集（40-80 轮插入诱导消息），同时盯违规率与拒答率两个指标。
