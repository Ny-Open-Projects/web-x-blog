### Q7672 · 双供应商冗余的成本溢价账：热备的代价怎么算

难度：P6/P7 ｜ 标签：成本工程、高可用、多供应商

**问**：业务对模型可用性敏感，架构评审提出"接第二家供应商做冗余"。双供应商的成本溢价怎么算？热备、温备、冷备的成本与恢复时间如何取舍？

**答**：**结论**：冗余溢价 = 第二供应商的**最小可运行成本** + 适配层维护成本 + 灰度验证成本，关键是它随冗余等级非线性变化：**热备**（双活分流，随时可接 100% 流量）溢价 ≈ 100% 流量成本 + 路由层开发；**温备**（低水位保活 + 定期真实调用验证）溢价 ≈ 10-20% 流量成本，恢复时间 5-15 分钟；**冷备**（只有适配层与协议适配，不付费）溢价 ≈ 0，但恢复要跑通"账号、配额、评测、灰度"全流程，实际 MTTR 以天计。事故概率视角：单供应商年可用性 99.5%，双供应商独立故障下可用性 ≈ 1-(1-a)²，但**共同故障面**（同一上游芯片紧缺、同一区域网络）会吃掉理论收益。

**取舍**：多数业务的正确答案是**温备**：每天用 5% 真实流量在 B 供应商上跑影子请求（不对外服务），保持配额活跃、评测分数新鲜、适配层有真实流量验证；故障时切流只改路由权重。纯冷备的隐藏成本是"切换演练缺失"——没验证过的灾备等于没有灾备。

**实战**：溢价账里要列入三项易漏成本：① 评测成本——B 供应商上每月跑回归评测的 token（Q7555 模型）；② 数据重放/回填成本——切换期会话与缓存失效（语义缓存按供应商隔离）；③ 折价谈判空间——承诺最低用量可换折扣，温备水位正好可以拿来谈价。

```python
# 双供应商冗余的溢价模型与可用性收益
def redundancy_premium(
    monthly_spend: float,       # 主供应商月成本
    tier: str,                  # hot / warm / cold
) -> dict:
    cfg = {
        # 溢价系数 = 第二供应商花费占主流量的比例
        "hot":  {"spend_ratio": 1.0, "mttr_min": 1,
                 "extra": monthly_spend * 0.05},   # 路由层开发分摊
        "warm": {"spend_ratio": 0.15, "mttr_min": 10,
                 "extra": monthly_spend * 0.05},
        "cold": {"spend_ratio": 0.0, "mttr_min": 60 * 24 * 2,
                 "extra": monthly_spend * 0.02},   # 只有适配层维护
    }[tier]
    spend = monthly_spend * cfg["spend_ratio"] + cfg["extra"]
    return {"tier": tier, "monthly_premium": round(spend),
            "mttr_minutes": cfg["mttr_min"]}

for tier in ("hot", "warm", "cold"):
    r = redundancy_premium(100_000, tier)
    print(r)

# 可用性收益：独立故障假设 vs 共同故障面修正
def availability(a_primary: float, a_backup: float,
                 correlated_factor: float = 0.0) -> float:
    """correlated_factor: 共同故障面占比（0-1），按比例削弱冗余收益。"""
    indep = 1 - (1 - a_primary) * (1 - a_backup)
    # 共同故障面把备份的可用性按比例向主库"绑定"
    a_backup_eff = a_backup + (a_primary - a_backup) * correlated_factor
    return max(1 - (1 - a_primary) * (1 - a_backup_eff), a_primary)

print("独立故障:", availability(0.995, 0.995, 0))       # ≈0.999975
print("30% 共同面:", availability(0.995, 0.995, 0.3))   # 收益缩水
# 温备的可用性还要打"切换成功率"折扣：99.9% → 真实收益再降

# 决策：预期损失 vs 溢价
downtime_loss_per_min = 3000     # 每分钟停机损失（元）
for tier in ("hot", "warm", "cold"):
    r = redundancy_premium(100_000, tier)
    saved = downtime_loss_per_min * (r["mttr_minutes"] - 1)
    print(tier, "预期止损收益≈", round(saved), "溢价", r["monthly_premium"])
```

**追问 1**：为什么"没演练过的灾备等于没有灾备"？演练成本怎么算进账？
提示：切换涉及配额激活、评测基线、语义缓存重建、路由配置——每个环节都可能失败；演练 = 每季度一次真实切流，其 token 与人力成本应计入冗余溢价，否则 MTTR 数字是纸面的。

**追问 2**：语义缓存在双供应商下为什么必须按供应商隔离？
提示：两家的 token 计费、缓存命中行为、模型输出分布都不同；共用缓存会带来"缓存了 A 的回答按 B 计费/失效规则不对"的双重错账，隔离是最便宜的正确做法。

**追问 3**：如果预算只够热备一半流量，怎么设计？
提示：按流量分层冗余——高价值租户/核心功能双供应商热备，长尾单供应商 + 快速降级；冗余粒度从"全站"细化到"请求等级"，溢价随分位数下降。

## 背诵要点
1. 冗余溢价随等级非线性：热备 ≈ 100% 流量成本，温备 ≈ 15%，冷备 ≈ 0 但 MTTR 以天计。
2. 可用性收益 1-(1-a)² 会被共同故障面吃掉一块，温备还要打"切换成功率"折扣。
3. 温备 = 影子流量保配额与评测新鲜度，是多数业务的最优点；没演练过的灾备不算灾备。
