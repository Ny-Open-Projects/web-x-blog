### Q7778 · 会话重启后答非所问：持久化恢复的上下文重建与摘要压缩

难度：P6 ｜ 标签：会话持久化、上下文重建、摘要压缩、工具对完整性、恢复一致性

基线：Python 3.12；实现会话恢复算法（预算内重建：老轮次摘要压缩 + 尾部完整 + 工具对对齐），全标准库实跑。

**问**：服务重启或长会话超出上下文窗口后，恢复的会话开始答非所问——"刚才提交的退款呢？"模型一脸茫然。会话恢复的一致性指的是什么？"逐字恢复所有消息"为什么不可行？摘要压缩该怎么压、压什么、绝不能压什么？

**答**：
- **结论**：恢复一致性是**状态等价**而非消息逐字等价：恢复后模型对"用户是谁、聊到哪、欠了什么承诺、哪些工具已执行"的认知与中断前一致。逐字全量恢复不可行——长会话超出上下文窗口，恢复算法必须做预算内的取舍，本卡实现标准方案：① **老轮次摘要压缩**：把窗口外的历史压成事实摘要（工具调用与结果、达成的结论、未决问题——事实密度高的话留，寒暄与过程性输出删）；② **近期轮次完整保留**：尾部 K 条逐字保留（细节最相关）；③ **工具对对齐**：tool_call 与 tool 结果必须成对出现在上下文里——**拆散工具对是最常见的恢复 bug**：assistant 发起的 tool_call 留下了、对应的 tool 结果被裁掉，模型看到"调用悬空"产生幻觉补全；反过来结果留下、调用被裁，模型看到来路不明的数据。本卡演示：14 条会话压进 10 条预算，摘要接尾部 8 条，尾部自然包含完整的"申请退款"工具对。
- **取舍**：① 摘要的生成时机：**会话进行中滚动摘要**（每 N 轮把最老段摘要化）优于恢复时一次性摘要——恢复时摘要要付一次生成延迟（秒级），进行中滚动把成本摊进正常轮次；② 摘要者与被摘要者同模型的问题：自己总结自己的话会放大同一偏差，摘要提示词要独立设计（"提取事实清单，忽略语气"）；③ 状态不止消息：会话绑定的工具授权、用户偏好、未完成的后台任务——这些在"消息流"之外，持久化要单独存（结构化状态与消息日志双轨，Q7745 并发推进的状态机版本）；④ 恢复后首轮的锚定：摘要放在 system 位置 + 显式声明"以下是历史摘要"，模型对摘要的信任度与对普通对话不同，锚定减少幻觉补全。
- **实战**：① 持久化格式带版本号（Q2574 导入校验），恢复时按版本迁移；② 恢复质量有评测：构造"中断点 → 恢复 → 追问关键事实"的回归集，恢复成功率是上线指标不是感觉；③ 摘要内容进会话审计：模型引用了摘要里的错误事实时能回溯是压缩丢了信息还是原对话就错；④ 长会话的计费视角：滚动摘要让单轮上下文恒定，token 成本曲线从线性变常数——这是会话产品的成本护城河。

```python
"""Q7778 会话持久化与恢复: 预算内重建上下文, 老轮次摘要压缩, 工具对保持完整。"""
MAX_CTX = 10                  # 上下文预算(条数)
SESSION = [                   # 已持久化的会话 (role, content)
    ("user", "帮我查订单 O1 的物流"),
    ("assistant", "[tool_call: query_logistics(O1)]"),
    ("tool", "O1: 已发货, 预计 11-26 送达"),
    ("assistant", "您的订单 O1 已发货, 预计 11-26 送达。"),
    ("user", "顺便看下 O2"),
    ("assistant", "[tool_call: query_logistics(O2)]"),
    ("tool", "O2: 运输中"),
    ("assistant", "订单 O2 运输中。"),
    ("user", "O2 的退款政策是什么?"),
    ("assistant", "O2 下单 7 天内可无理由退款。"),
    ("user", "那帮我申请 O2 退款"),
    ("assistant", "[tool_call: apply_refund(O2)]"),
    ("tool", "O2: 退款申请已提交, 预计 3 个工作日到账"),
    ("assistant", "已为 O2 提交退款申请, 预计 3 个工作日到账。"),
]


def summarize_old(msgs: list[tuple[str, str]]) -> str:
    """确定性摘要: 保留关键事实(订单号/结果)压缩老轮次."""
    facts = [c for r, c in msgs if r == "tool"]
    return "[摘要] 历史操作: " + "; ".join(facts) if facts else "[摘要] 无历史操作"


def rebuild(session: list[tuple[str, str]], budget: int) -> list[tuple[str, str]]:
    """恢复算法: 预算够 -> 原样; 不够 -> 老轮次压摘要, 近期轮次 + 成对工具保持完整."""
    if len(session) <= budget:
        return list(session)
    keep = budget - 2                                  # 留摘要 + 安全余量
    tail = list(session[-keep:])
    # 成对完整性: 尾部若切开 tool_call/tool 结果, 向前扩到对齐
    while any(r == "tool" for r, _ in tail) and tail[0][0] == "tool":
        keep += 1
        tail = list(session[-keep:])
    head = session[:-keep]
    summary = summarize_old(head)
    return [("system", summary)] + tail


if __name__ == "__main__":
    rebuilt = rebuild(SESSION, MAX_CTX)
    print(f"会话 {len(SESSION)} 条, 预算 {MAX_CTX} -> 重建后 {len(rebuilt)} 条")
    print(f"开头: {rebuilt[0][0]}: {rebuilt[0][1][:60]}...")
    print(f"结尾: {rebuilt[-1][0]}: {rebuilt[-1][1]}")
    # 校验: 最近工具对完整 (tool_call 与 tool 结果都在尾部)
    has_refund_pair = any("[tool_call: apply_refund" in c for _, c in rebuilt[1:]) \
        and any("退款申请已提交" in c for _, c in rebuilt[1:])
    ok = len(rebuilt) <= MAX_CTX and rebuilt[0][0] == "system" and has_refund_pair
    print(f"校验: 预算内重建 + 摘要压缩 + 工具对完整 -> {'通过' if ok else '异常'}")
    print("结论：恢复一致性 = 状态等价而非消息逐字等价;")
    print("      摘要压老轮次保事实, 尾部保成对工具调用——拆散成对是恢复最常见的 bug")
```

**追问一**：摘要该保留什么、删除什么？"事实"的判定标准是什么？

→ 解析：保留三类：① **承诺与义务**（"我会把报表发你"——删了它恢复后模型忘记欠账，用户体感最差）；② **工具执行结果**（退款单号、查询结论——模型后续推理的硬依据，本卡摘要只留 tool 结果正是这个逻辑）；③ **用户显式约束**（"不要用英文""金额保留两位"——指导后续所有轮次的行为，丢失即行为回退，Q7758 历史残留指令的反向问题）。删除三类：过程性输出（模型的中间推理、被推翻的草稿）、重复信息（后续轮次已澄清的旧表述）、社交填充（道歉、寒暄）。判定标准一句话：**这段话删除后，模型对"接下来该做什么"的判断会变吗**？会变就必须留。工程落地：摘要提示词按这三类列检查清单，摘要产出再过一遍"关键事实覆盖率"自动校验（抽查 N 个会话，人工标注事实点，统计摘要命中率）——摘要质量是可评测的，别凭感觉调。

**追问二**：恢复后模型"幻觉补全"摘要里没有的细节怎么办？锚定之外还有什么结构性防御？

→ 解析：幻觉补全的机制：恢复后的上下文里有空洞（摘要之间有跳跃），模型的"补全本能"会用编造填充——用户问"那个退款单号"，摘要没存单号，模型编一个格式正确的。结构性防御分三层：① **摘要的缺口显式化**：摘要里对"知道发生过但没存细节"的事项写明"[细节未保留：退款单号需查工具]"——把空洞从隐式变显式，模型的补全倾向显著下降（它知道该去调工具而不是编）；② **恢复后第一轮禁答细节**：系统提示注入"恢复后的首轮回答涉及历史细节时，必须先调用查询工具核实，不得凭上下文直接回答"——把幻觉风险转移成工具调用成本；③ **关键状态结构化**：退款单号、订单状态这类**强结构事实**不走摘要（摘要是有损的），存进会话的结构化状态字段（双轨持久化），恢复时直接注入上下文——摘要管叙事、结构化状态管事实，分工明确。判断防御是否到位的验收：恢复回归集里"追问历史细节"类用例的幻觉率——它比"恢复后能否继续对话"更能暴露压缩方案的漏洞，前者考的是记忆的**准确性**，后者只考连贯性。
