### Q7594 · 上下文窗口预算工程

> 长对话 Agent 跑 20 轮后越来越慢越来越贵——上下文预算怎么分配（系统提示/历史/检索内容/输出各占多少），截断、压缩（摘要）、外部记忆三策略怎么选，上下文裁剪会不会「剪掉关键事实」导致模型失忆？

**问**：**答**：① **预算分配比例**（128K 窗口的经验配比）：系统提示+工具定义（固定，~10%）、检索内容（RAG 注入，~40%， Quality > 数量：相关性过滤后注入）、对话历史（~30%）、**输出预留**（~20%，输出被挤没会截断回答——最常见事故）。② 三策略光谱：**截断**（丢最旧轮次）最便宜但丢事实；**摘要压缩**（把 N 轮历史压成要点，LLM 自压缩或规则压缩）保留语义丢细节——关键事实（用户名/约束条件）要**抽取成结构化状态**单独保留，不参与压缩；**外部记忆**（向量库/KV 存储按需检索）可无限扩但每次检索有延迟与相关噪声。③ 「剪掉关键事实」的防御：压缩前做**事实抽取**（约束/实体/决策入结构化 memo，永不压缩）；压缩后跑「记忆回归测试」（关键问题探针：压缩后的上下文还能答对「用户预算是多少吗」）；分位数监控（压缩比 vs 回答质量的相关性）。

```python
# 全部标准库；demo 实现上下文预算分配器 + 事实抽取记忆 + 压缩探针
import json, time

class ContextBudget:
    """窗口预算：四段配比 + 超限压缩流水线。"""
    def __init__(self, total_tokens: int = 32000):
        self.total = total_tokens
        self.ratios = {"system": 0.10, "retrieval": 0.40, "history": 0.30, "output": 0.20}
        self.cap = {k: int(total * v) for k, v in self.ratios.items()}
        self.history: list[dict] = []
        self.facts: dict[str, str] = {}        # 结构化事实：永不压缩
    def fits(self, section: str, tokens: int) -> bool:
        return tokens <= self.cap[section]
    def add_turn(self, role: str, text: str, tok: int):
        self.history.append({"role": role, "text": text, "tok": tok})
        while sum(h["tok"] for h in self.history) > self.cap["history"]:
            self._compress()
    def _compress(self):
        """压缩最旧一半：事实先抽取，摘要替换原轮次。"""
        half = len(self.history) // 2
        for h in self.history[:half]:
            for fact in extract_facts(h["text"]):
                self.facts[fact[0]] = fact[1]   # 关键事实入 memo（永不压缩）
        digest = "; ".join(h["text"][:20] for h in self.history[:half])
        tok_saved = sum(h["tok"] for h in self.history[:half]) - max(1, len(digest) // 4)
        self.history = [{"role": "summary", "text": digest, "tok": max(1, len(digest) // 4)}] \
                       + self.history[half:]
        print(f"压缩: 释放 {tok_saved} tokens，事实表 {len(self.facts)} 条")

def extract_facts(text: str) -> list[tuple[str, str]]:
    """事实抽取（规则演示）：预算/人名/截止时间类关键词入 memo。"""
    facts = []
    if "预算" in text:
        import re
        m = re.search(r"预算[:：]?\s*(\d+万?)", text)
        if m: facts.append(("budget", m.group(1)))
    if "截止" in text:
        import re
        m = re.search(r"截止[:：]?\s*(\S+)", text)
        if m: facts.append(("deadline", m.group(1)))
    return facts

def memory_probe(budget: ContextBudget) -> bool:
    """记忆回归探针：压缩后关键问题还能答对吗。"""
    return budget.facts.get("budget") == "50万"

if __name__ == "__main__":
    cb = ContextBudget(total_tokens=1000)          # 小窗口演示压缩
    cb.facts["budget"] = "50万"                     # 第 1 轮用户说的预算
    for i in range(20):
        cb.add_turn("user", f"预算:50万 请处理任务{i}" if i == 0 else f"任务{i}的上下文" * 10, 80)
    print("事实表:", cb.facts)
    assert memory_probe(cb), "压缩后关键事实必须保留"
    print("记忆探针：预算 50万 仍在 ✅")
    print("预算配比:", {k: f"{v}tok" for k, v in cb.cap.items()})
    # 口径：输出段被挤没 = 回答截断事故；压缩前先抽事实；探针测试进 CI。
```

**追问**：1) 为什么输出预留 20% 是最常见事故点？——预算分配忘算输出：输入塞满窗口 → 模型只有几十 token 生成空间 → 回答截断或 API 报 `max_tokens` 超限；生成参数 max_tokens 必须先于上下文填充确定。2) 摘要压缩的「摘要者」是谁？——自压缩（同模型调一次「总结以上对话」）成本可控但有信息损耗；规则压缩（截断+保留首尾）更便宜但语义差；生产常用「低档模型做摘要」降成本。3) 检索内容 40% 怎么动态分配？——按查询相关性排序注入 top-k，k 由「剩余预算」动态决定而不是固定 k=5——预算驱动检索深度（Q7504 rerank 成本分层联动）。

## 背诵要点
1. 四段配比 10/40/30/20：输出预留 20% 先定（max_tokens 先于填充确定），否则回答截断。
2. 三策略：截断丢事实、摘要丢细节、外部记忆可扩——**关键事实先抽取入结构化 memo（永不压缩）**。
3. 压缩质量验收 = 记忆回归探针（关键问题压缩后还能答对），探针进 CI。

## 复盘追问
1. 用户中途改了预算（50 万→80 万），事实表怎么更新不冲突？（提示：事实带版本与来源轮次，新值覆盖旧值并记录变更链——摘要压缩后冲突可追溯）
2. 20 轮对话每轮都全量注入历史，成本怎么估？（提示：token 成本 ∝ 轮数平方（每轮重发全历史），长对话必须压缩/外存，这正是本卡的动机）
