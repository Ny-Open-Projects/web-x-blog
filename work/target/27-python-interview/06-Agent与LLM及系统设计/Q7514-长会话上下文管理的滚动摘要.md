### Q7514 · 长会话上下文管理

> 难度:★★☆ | 标签:上下文, 摘要, Agent

**问**：Agent 会话超过上下文窗口——「直接砍掉最老的 N 条」会破坏什么（引用/承诺丢失），滚动摘要的正确做法是什么（什么时机摘要、摘要保留什么丢什么），「用户 20 分钟前说过的一个约束」怎么不丢（锚定机制）？

**答**：① 砍尾的破坏：对话里的**约束与承诺**（「不要用 MySQL」「之前已创建的表名是 X」）通常出现在早期——砍尾后模型忘约束直接违反，且引用早期实体（变量名/文件名）时幻觉编造。② 滚动摘要：**接近窗口阈值时**（如 80%）触发，把「最老 50% 对话」压成结构化摘要（决策/约束/关键实体三节），摘要替换原文占位——保留近期完整对话保证细节，摘要素养在「保留什么」：**决策与约束全保、过程性讨论丢弃、实体名全保**（表名/函数名/ID 是后续引用的锚）。③ 锚定机制：约束类信息不进摘要也不进对话流，而是**独立的结构化存储**（会话 KV：`constraints: [...]`、`entities: {...}`），每轮注入 system 提示——「用户唯一约束」用 KV 锚定，摘要怎么滚都不丢。④ 摘要生成注意：用小模型即可（省成本）、摘要本身要校验（实体名必须出现在原文——防摘要幻觉）。

```python
# 全部标准库；demo 实现滚动摘要 + KV 锚定 + 摘要幻觉校验
import re

class Session:
    def __init__(self, max_msgs: int = 10, summarize_at: float = 0.8):
        self.messages: list[dict] = []
        self.summary: str = ""
        self.kv: dict[str, list] = {"constraints": [], "entities": []}   # 锚定层
        self.max, self.at = max_msgs, summarize_at
    def add(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})
        for m in re.findall(r"不要?用\s*(\w+)|不要\s*(\w+)", content):   # 约束抽取（规则级）
            c = next(g for g in m if g)
            if c not in self.kv["constraints"]:
                self.kv["constraints"].append(c)
        for ent in re.findall(r"表[名]?\s*[：:]\s*(\w+)", content):      # 实体抽取
            if ent not in self.kv["entities"]:
                self.kv["entities"].append(ent)
        self._maybe_summarize()
    def _maybe_summarize(self):
        if len(self.messages) < self.max * self.at:
            return
        old = self.messages[: len(self.messages) // 2]
        self.summary = self._summarize(old)      # 生产：小模型生成 + 校验
        self.messages = self.messages[len(self.messages) // 2:]
    def _summarize(self, old: list[dict]) -> str:
        ents = sorted({w for m in old for w in re.findall(r"[A-Za-z_]{4,}", m["content"])})
        # 校验：摘要里的实体必须出现在原文（防摘要幻觉）
        assert all(any(e in m["content"] for m in old) for e in ents)
        return f"[摘要] 决策与约束见锚定层；关键实体: {', '.join(ents[:8])}"
    def build_prompt(self) -> str:
        parts = []
        if self.summary:
            parts.append(self.summary)
        parts.append("[约束] " + ", ".join(self.kv["constraints"]))
        parts.append("[实体] " + ", ".join(self.kv["entities"]))
        parts += [f"{m['role']}: {m['content']}" for m in self.messages]
        return "\n".join(parts)

if __name__ == "__main__":
    s = Session(max_msgs=6)
    s.add("user", "不要用 MySQL，我们只有 Postgres；表名：orders_v2")
    s.add("assistant", "好的，将使用 Postgres 创建 orders_v2")
    for i in range(6):                          # 撑爆窗口触发滚动摘要
        s.add("user", f"继续讨论技术细节 {i} " + "long discussion " * 5)
        s.add("assistant", f"detail {i}")
    p = s.build_prompt()
    assert "Postgres" in p and "orders_v2" in p, "约束与实体必须存活"
    assert "[摘要]" in p                        # 滚动摘要生效
    print("滚动摘要 + KV 锚定：早期约束在窗口滚动后仍然存活 ✅")
    print(p[:200] + "...")
```

**追问**：1) 为什么约束进 KV 而不是只在摘要里？——摘要是「有损压缩+可能幻觉」，约束错一个字就是事故（不要 MySQL 摘成别用数据库）；KV 是无损精确层，规则/小模型抽取 + 用户确认后固化。2) 摘要时机为什么选 80% 而不是满了再摘？——满了再摘当轮已经超窗报错；80% 留出摘要生成与注入的余量，且摘要写入也要窗口。3) 多会话共享实体（跨会话记忆）怎么设计？——会话内 KV → 会话结束把「确认过的约束/实体」晋升到用户级长期记忆（带来源与置信度），下会话注入——避免把一次性的会话细节污染长期记忆。

## 背诵要点
1. 砍尾丢失约束与实体引用——摘要必须保留：决策约束全保、过程讨论丢、实体名全保。
2. 三层结构：滚动摘要（近期完整对话 + 老对话结构化压缩）、KV 锚定层（约束/实体无损精确）、system 注入。
3. 摘要幻觉防线：摘要里的实体必须能在原文验证；摘要用小模型省成本，80% 阈值触发。

## 复盘追问
1. 约束抽取错了（「不要用 MySQL」抽取成「用 MySQL」），怎么防？（提示：规则抽取 + LLM 二次确认 + 用户可见的约束清单（UI 展示可修正）——约束层必须可审计可人工干预）
2. 会话特别长（几百轮）摘要链会退化吗？（提示：摘要的摘要会级联失真——重要节点（决策）单独持久化成时间线，摘要只压过程性内容）
