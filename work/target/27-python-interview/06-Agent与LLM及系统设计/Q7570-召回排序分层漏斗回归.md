### Q7570 · 召回与排序的分层漏斗回归

难度：P6 | 标签：RAG、分层指标、漏斗、回归

**问**：端到端评估分数从 0.81 掉到 0.76，但没人知道是检索坏了还是生成坏了。"分层漏斗"怎么把整体退化归因到具体层？每层的回归阈值怎么定？

**答**：
- **结论**：分层漏斗：固定金标（相关文档集合），对每个 query 记录"召回层命中数/金标数 → rerank 后保留数/召回命中数 → 端到端答案正确性"。每层的"保留率"单独算指标、单独设回归阈值——换分块策略只可能伤召回层、换 rerank 模型只可能伤排序层，分层指标让"整体降了"变成"哪层降了"。实践：召回层看 recall@k，排序层看"金标在 rerank 后 top-3 的保留率"，两层都要有独立基线与阈值（如 -2 个点阻断）。
- **取舍**：分层评估的成本：每层都要金标（召回金标与答案金标可以同源：答案引用的文档即召回金标）；漏斗层数越多，评估流水线越复杂——3 层（召回/排序/生成）是性价比拐点。阈值定多少：按历史波动定（该层指标的历史标准差 × 2），拍脑袋的 1% 要么误报要么漏报。
- **实战**：归因流程：端到端分数降 → 看漏斗哪层超阈值 → 召回层超则 diff 分块/向量配置变更 → 排序层超则查 rerank 模型/候选数 → 都没超则是生成层或数据本身变了（金标过时）。注意分层指标要按 query 分位数看，均值掩盖长尾退化。

```python
"""召回/排序分层漏斗：每层都算保留率，回归时定位坏层。"""
GOLD = {"d1", "d2", "d3"}

def funnel(gold, recalled, reranked):
    def stage(name, got):
        kept = got & gold
        return (name, len(kept), len(kept) / len(gold))
    return [stage("recall", set(recalled)), stage("rerank", set(reranked))]

baseline = funnel(GOLD, {"d1", "d2", "d3", "d9"}, {"d1", "d3"})
candidate = funnel(GOLD, {"d1", "d9", "d8"}, {"d1", "d3"})   # 召回换了分块策略
print("baseline:", baseline)
print("candidate:", candidate)
for (n1, _k1, r1), (n2, _k2, r2) in zip(baseline, candidate):
    delta = r2 - r1
    flag = " <-- 坏层" if delta < -0.05 else ""
    print(f"{n1}: {r1:.2f} -> {r2:.2f} ({delta:+.2f}){flag}")
print("要点：分层保留率把'整体分数降了'归因到具体层；各层指标分别设回归阈值")
```

**追问链**：
1. 追问一层：为什么召回层的金标可以复用答案引用？（端到端答对时引用的文档大概率是必要证据；人工确认后即召回金标——分层评估的标注成本因此大幅降低）
2. 追问二层：两层指标都正常但端到端降了，还有什么可能？（生成层退化（模型/上下文裁剪变更）、金标过时（数据更新）、或评估集与线上分布漂移——分层漏斗排除法后要回到分布层检查）

**背诵要点**：
1. 漏斗三层：recall@k → rerank 保留率 → 端到端正确性，分层设阈值。
2. 阈值按该层历史标准差定，别拍脑袋；均值要看分位数补长尾。
3. 端到端降了先看漏斗超阈值层，全正常则查生成层与金标时效。

**复盘追问**：
1. 换了 rerank 模型后召回层指标没变但端到端降了，可能是什么？（rerank 候选数变化导致进入生成的上下文不同——层间接口的参数也在漏斗里）
2. 为什么每层阈值独立而不是只守端到端阈值？（端到端噪声大、归因慢；分层阈值把回归拦截在更靠近根因的位置）
