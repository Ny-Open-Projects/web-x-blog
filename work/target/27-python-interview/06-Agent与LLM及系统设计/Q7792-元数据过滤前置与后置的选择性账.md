### Q7792 · 元数据过滤前置还是后置：选择性、候选枯竭与过采样因子

难度：P7 ｜ 标签：Agent、RAG、向量检索、元数据过滤、选择性、过采样、召回率

基线：库知识库外知识卡，代码用标准库模拟——用 `hashlib` 生成伪相关分数与过滤集合，手写 top-k 与召回评估，不调用外部 API。

**问**：多租户知识库按 `tenant_id` 过滤，某个小租户只占全库 1% 的文档。向量检索 `top_k=20` 后再按 tenant 过滤，经常一条都不剩；改成"先按 tenant 过滤再检索"，又出现召回率下降——明明该租户的相关文档存在，就是搜不到。前置过滤和后置过滤到底差在哪？1% 的选择性该用哪种？"过采样 100 倍"是拍脑袋还是有公式？

**答**：

- **结论**：这是**选择性（selectivity）**决定的工程问题，不是"哪种更先进"。后置过滤（先 ANN 取 top-k，再筛元数据）实现简单、ANN 索引不用感知过滤条件，但候选里满足条件的期望条数是 `k × s`（s 为选择性）；`s=1%`、`k=20` 时期望只有 0.2 条，**候选枯竭**是必然的，不是偶发。要拿到 k 条过滤后的结果，过采样因子约为 `1/s`（更严谨地用超几何/负二项分布算置信下界，`1/s` 只是期望值）。前置过滤（把条件下推进 ANN）能保证候选都满足条件，但会**裁剪图结构**：HNSW/IVF 的邻居边被过滤条件切断后，连通性变差，召回率下降，尤其在过滤后集合很小时更明显。
- **取舍**：按选择性分档。`s > 10%`：后置过滤 + 适度过采样（2～5 倍）足够，成本低；`1% < s < 10%`：后置 + 过采样 `1/s` 或混合（先粗过滤到超集，再 ANN，再精过滤）；`s < 1%`：前置过滤 / 按 tenant 分区建独立索引 / 用支持 filtered-ANN 的索引（如带 filter 的 HNSW 实现），否则过采样 100 倍会把延迟打穿。还要看**过滤条件的基数**：tenant_id 这种低基数、强隔离的字段适合**物理分区**（每租户/每大租户一个索引），成本是索引数量；高基数、弱隔离的标签适合**逻辑过滤**。
- **实战**：SaaS 知识库按 tenant 过滤，top-20 后置过滤在小租户上经常返回 0 条，产品侧表现为"搜不到自己的文档"。临时把 `top_k` 提到 2000（100 倍过采样），召回恢复但 P99 从 90ms 涨到 1.2s。最终方案是**按租户分片索引**（大租户独立索引、小租户共享一个小索引池），过滤在路由层完成，既不裁剪图也不过度采样，P99 回到 120ms。另一条内容量小的链路保留了"后置 + 20 倍过采样"，因为它没有延迟压力。

下面用 1 万条伪文档复现候选枯竭、过采样与前置过滤的召回损失。

```python
# 前置 vs 后置过滤: 选择性、过采样因子与召回损失
import hashlib

N = 10_000
K = 20
SELECTIVITY = 0.01          # tenant 占 1%


def h(key):
    """稳定的伪随机数 [0,1), 代替 embedding 相似度。"""
    d = hashlib.sha256(key.encode()).hexdigest()[:8]
    return int(d, 16) / 0xFFFFFFFF


DOCS = list(range(N))
# 相关性分数: 与 doc_id 绑定, 保证可复现
SCORE = {d: h(f"rel:{d}") for d in DOCS}
# 过滤集合: 1% 的文档属于该 tenant
TENANT = {d for d in DOCS if h(f"grp:{d}") < SELECTIVITY}
print(f"[0] 全库 {N}, 该 tenant {len(TENANT)} 条, 实际选择性 {len(TENANT) / N:.2%}")
truth = sorted(TENANT, key=lambda d: -SCORE[d])[:K]      # 该 tenant 内真实 top-20


def post_filter(factor):
    """先取 factor*K 个候选, 再过滤, 取前 K。"""
    cand = sorted(DOCS, key=lambda d: -SCORE[d])[:factor * K]
    got = [d for d in cand if d in TENANT][:K]
    return got, len(cand)


for f in (1, 10, 100):
    got, cost = post_filter(f)
    print(f"[1] 后置过采样 {f:>3}x: 候选 {cost}, 命中 {len(got)}, "
          f"期望 {K * len(TENANT) / N * f:.1f}")
    if f == 1:
        assert len(got) <= 2, "1 倍采样必然候选枯竭"
    if f == 100:
        assert len(got) >= 14, "1/s 是期望值, 实测会低于 20 (随机波动)"

# 前置过滤: 只在 tenant 内检索, 但图被裁剪后只覆盖 72%
PRUNE = 0.72
allowed = {d for d in TENANT if h(f"edge:{d}") < PRUNE}
pre = sorted(allowed, key=lambda d: -SCORE[d])[:K]
recall_pre = len(set(pre) & set(truth)) / K
print(f"[2] 前置过滤(图裁剪 {PRUNE:.0%}): 候选 {len(TENANT)}, 召回@{K} {recall_pre:.0%}")
assert recall_pre < 0.9

# 混合: 把条件放宽成超集(tenant + 4% 邻居), 在超集内 ANN 后精过滤
SUPERSET = TENANT | {d for d in DOCS if h(f"near:{d}") < 0.04}
cand_hy = sorted(SUPERSET, key=lambda d: -SCORE[d])[:K * 10]   # 超集内 10x 过采样
hybrid = [d for d in cand_hy if d in TENANT][:K]
recall_hy = len(set(hybrid) & set(truth)) / K
print(f"[3] 混合(超集 {len(SUPERSET)} 条, 内含全部 tenant + 噪声): "
      f"候选 {len(cand_hy)}, 召回 {recall_hy:.0%}")
assert recall_hy >= 0.95 and recall_hy > recall_pre + 0.15

# 成本账: 候选数近似等于打分/图遍历成本
print(f"[4] 成本: 后置100x={100 * K}, 前置={len(TENANT)}, 混合={len(cand_hy)}; "
      f"100x 实测 16 < 期望 19.2, 说明 1/s 还要加安全系数")
assert len(TENANT) < len(cand_hy) < 100 * K
print("    → 实测 决策变量是选择性: >10% 后置即可, <1% 前置/分区, 中间用混合")
```

**追问一**：过采样因子为什么不能简单取 `1/s`？—— 因为 `1/s` 只保证**期望**够 k 条，实际是随机变量：`s=1%`、`k=20` 时，取 2000 个候选的命中数服从超几何分布，标准差约 `sqrt(k(1-s)) ≈ 4.4`，意味着有相当概率少于 20 条（P(<15) 不可忽略）。要按置信度（如 95%）取分位数，因子需要 `1/s` 再乘一个 1.2～1.5 的安全系数；或者干脆改成"取到够 k 条为止"的迭代加深（先 5 倍，不够再翻倍），避免一次性过度采样。后者在长尾查询上更省，但要处理"翻倍到上限仍不够"的降级。

**追问二**：前置过滤的召回损失，能不能靠"把过滤集合扩大一点"解决？—— 能缓解，但要注意扩大的是**候选集**还是**图结构**。如果只是把过滤条件放宽（比如 tenant + 同组织），图连通性恢复、召回上升，但会引入跨租户内容（隐私/合规风险）；如果是"在过滤后的子集上重建图"，那是分区索引，成本是索引数量与更新复杂度。折中方案是**路由 + 小索引池**：按 tenant 哈希到 N 个物理索引，每个索引内部不过滤，既保住图连通性，又避免每租户一个索引的运维爆炸。选择哪种取决于租户规模分布——头部租户独立、长尾共享，是常见做法。

## 背诵要点

- 后置过滤的期望命中 = `k × s`，`s=1%` 时 top-20 只有 0.2 条；过采样因子约 `1/s`，实际要按分布分位数加安全系数或迭代加深。
- 前置过滤保住候选但裁剪图结构，过滤后集合越小召回损失越大；混合方案是"粗过滤到超集 + ANN + 精过滤"。
- 按选择性分档：>10% 后置、1%～10% 后置加过采样/混合、<1% 前置或按 tenant 分区索引；低基数强隔离字段优先物理分区。

## 复盘追问

- top-20 后置过滤经常 0 条，你先算哪个数？（`k × s` 的期望命中；若远小于 1，枯竭是必然，不是索引坏了）
- 前置过滤召回下降，你怎么区分是"图被裁剪"还是"过滤条件本身写错"？（对比过滤集合内的暴力召回上限；若暴力能召回而 ANN 不能，就是图连通性问题）
