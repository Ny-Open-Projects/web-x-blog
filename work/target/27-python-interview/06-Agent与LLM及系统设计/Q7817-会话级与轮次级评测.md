### Q7817 · 会话级与轮次级评测：双口径指标与下钻归因

难度：P6 ｜ 标签：评测单元、会话级指标、轮次级指标、任务完成率、均值掩盖、下钻归因

基线：库外知识卡，代码用标准库模拟双口径聚合与下钻归因，不调用外部 API。

**问**：多轮 Agent 的评测报告写"平均得分 0.78"，团队很满意——上线后投诉不断：用户的任务常常在第三四轮烂尾。轮次分数都没错，错的是口径：把所有轮次拉平平均，"中途垮掉"的会话被前几轮高分平均掉了。会话级与轮次级指标各自管什么？为什么缺一不可？指标下降时怎么下钻定位？

**答**：

- **结论**：评测单元的选择决定你能看见什么。① **轮次级口径**（所有轮次拉平统计）：样本量大、粒度细，适合回归测试与 A/B（每轮是独立样本，统计功效高），能定位"哪一轮哪种失败"；缺陷是掩盖会话动态——一个 0.9→0.9→0.2 的会话与三个 0.6 的会话在均值里没有区别，而前者是灾难。② **会话级口径**（先会话内聚合、再会话间统计）：贴近真实用户任务——用户关心的是"我的问题解决了吗"而不是"每一轮的均值"；核心指标是**任务完成率**（终态是否达成，与过程分无关）、会话轮数（成本与耐心）、中途放弃率。s3 的 1.0→0.2→0.2→0.2 在轮次均值里被稀释，在完成率里直接计为失败。双口径缺一不可：轮次级管诊断与优化，会话级管真实价值与发布决策——**只用轮次均值的评测报告，会把'中途崩'平均成'还行'**。
- **取舍**：会话级指标的难点是"任务完成"怎么判定：规则判定（最后一轮是否包含承诺的交付物、会话是否以确认语结束）便宜但粗糙；人工判定准但贵；LLM 判定居中但要校准（见 Q7812）。工程折衷是"关键路径规则判定 + 抽样 LLM/人工复核"。另一个取舍是聚合顺序的统计效应：会话长短差异大时，先会话均值再平均（每会话等权）会放大短会话的话语权，轮次拉平（每轮等权）则被长会话主导——报告必须声明口径，跨版本对比必须同口径，否则指标跳变只是口径假象。还有成本维度：会话级指标需要完整会话数据（采集与存储更重），轮次级可以流式统计——采集链路的设计要兼容两种口径，不要等要做会话分析时才发现日志只存了单轮。
- **实战**：一个多轮排查助手，评测报告轮次均值 0.78 看着健康，上线后会话完成率只有 54%。下钻归因：把未完成会话按"失败发生的轮位"聚类，62% 集中在第 3 轮——恰好是"工具返回多文件结果"的轮位，模型在这一轮开始答非所问（上下文里早期指令被工具结果稀释）。修复（工具结果句柄化 + 第 3 轮前置引导提示）后完成率 81%，轮次均值几乎没变（0.78→0.80）——这个案例是"轮次均值掩盖会话失败"的实证：不看会话级指标，这个问题根本不会进视野。规范沉淀：**评测面板固定双口径：轮次均值管回归，会话完成率/放弃率管发布；两个口径各自设阈值**。

下面模拟双口径聚合的差值与下钻归因。

```python
# Q7817 会话级 vs 轮次级评测单元: 指标口径 / 归因 / 组合优化
SESSIONS = [
    # 一个会话 3 轮: 轮次分 [0.9, 0.5, 0.8]
    {"sid": "s1", "turn_scores": [0.9, 0.5, 0.8]},
    {"sid": "s2", "turn_scores": [0.8, 0.8, 0.8]},
    {"sid": "s3", "turn_scores": [1.0, 0.2, 0.2, 0.2]},
]

# [1] 轮次级口径: 所有轮次拉平算均值 — s3 的高开低走被均值掩盖
all_turns = [s for sess in SESSIONS for s in sess["turn_scores"]]
turn_mean = sum(all_turns) / len(all_turns)
print(f"[1] 轮次级均值: {turn_mean:.3f} ({len(all_turns)} 轮拉平)")

# [2] 会话级口径: 先会话内聚合再会话间平均 — 口径不同结论不同
sess_means = [sum(s["turn_scores"]) / len(s["turn_scores"]) for s in SESSIONS]
sess_mean = sum(sess_means) / len(sess_means)
print(f"[2] 会话级均值: {sess_mean:.3f} (先每会话均值再平均)")
print(f"    s1 会话内波动 0.9→0.5→0.8: 轮次口径看不到『中途垮掉』, 会话口径能看到")
assert abs(sess_mean - turn_mean) > 1e-9

# [3] 任务完成率(会话级硬指标): 会话终态是否达成, 与轮次分无关
def task_done(sess):
    # 约定: 最后一轮分 >= 0.6 视为完成
    return sess["turn_scores"][-1] >= 0.6

done = sum(1 for s in SESSIONS if task_done(s))
print(f"[3] 任务完成率: {done}/{len(SESSIONS)} = {done/len(SESSIONS):.0%} (s3 前面再高, 终态崩=未完成)")
assert done == 2

# [4] 归因: 会话级指标掉了, 必须能下钻到轮次级定位是第几轮哪种失败
def drill_down(sess):
    worst = min(range(len(sess["turn_scores"])), key=lambda i: sess["turn_scores"][i])
    return worst + 1, sess["turn_scores"][worst]

for s in SESSIONS:
    tr, sc = drill_down(s)
    print(f"[4] {s['sid']}: 最差轮=第 {tr} 轮({sc}) → 归因到具体轮次")
assert drill_down(SESSIONS[2]) == (2, 0.2)
print("    → 实测 双口径缺一不可: 轮次级管诊断与回归, 会话级管真实任务达成; 只看轮次均值会把『中途崩』平均掉")
```

**追问一**：会话完成率的"完成"判定，规则法与 LLM 判定法怎么组合？—— 组合方式：**规则判定为主、抽样复核为辅**。规则判定用会话的结构特征（终态是否含交付物标记、是否走了预期的终止路径、用户最后一条是否为新问题而非追问），便宜、确定、可回归；但它对"变相完成"（用户自己绕过去了）与"变相失败"（以礼貌用语收尾但没解决）盲区。抽样 5~10% 用 LLM judge 或人工对照复核，估计规则判定的错误率，超阈值就修规则。不要全量 LLM 判定（成本与判定的不稳定性），也不要全信规则（盲区静默）。判定口径本身要版本化——判定规则一变，历史完成率不可比，报告必须标注判定版本。

**追问二**：为什么说"口径声明"是评测报告的合规底线？—— 同一批数据在不同口径下能得出相反结论：轮次拉平 0.78 vs 会话等权 0.65 vs 终态完成率 67%——三个都是"对的"，回答的问题不同。不声明口径的对比（本次 0.78 vs 上次 0.65）可能只是口径变化，会被误读为模型退化/进步，进而触发错误的发布决策。实践规范：评测报告的每个数字必须带四元组标注（数据范围 / 聚合口径 / 判定方法版本 / 时间窗），跨报告对比前先做口径对齐。这与 Q7533 离线在线一致性是同一族问题——**评测数字脱离口径就没有意义**。

## 背诵要点

- 双口径分工：轮次级（拉平）样本多、可下钻，管回归与 A/B；会话级（先会话内再会话间）贴用户价值，管发布决策。
- 会话级硬指标是任务完成率（终态判定，与过程分无关）；轮次均值会把"高开低走"平均掉——s3 案例：1.0→0.2×3 完成率 0%。
- 报告数字必须带口径四元组（范围/口径/判定版本/时间窗）；跨版本对比先对齐口径，否则指标跳变只是口径假象。

## 复盘追问

- 完成率 54% 但轮次均值 0.78，你怎么定位到"第 3 轮工具结果稀释"这个根因？（未完成会话按失败轮位聚类，62% 集中在第 3 轮；轮位与工具形态对应，复现实验证实修复有效——下钻是把会话级告警翻译成轮次级工程动作）
- 为什么"先会话均值再平均"会放大短会话话语权？（每会话等权时 1 轮会话与 10 轮会话权重相同，而真实 token 成本与用户投入由长会话主导；报告要同时给两种加权结果并声明）
