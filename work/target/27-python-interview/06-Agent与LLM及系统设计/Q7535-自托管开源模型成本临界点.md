### Q7535 · 什么时候值得自托管开源模型？临界点怎么算？

> 难度:★★★★ | 标签:成本工程, vLLM, 容量规划

**问**：API 按量计费 vs 自托管开源模型（vLLM + A100），怎么算临界点？自托管的"真实成本"包含哪些隐性项？为什么"理论吞吐"和"有效吞吐"差这么多？什么规模的流量才值得自托管？能不能混合？

**答**：结论：临界点 = **固定月成本（GPU 租金 + 运维人力）÷ API 单价**得到的月 token 量——月用量超过它才划算。自托管真实成本 = GPU 月租（8×A100 量级 $10-15k）+ 运维人力（0.5-2 人力）+ N+1 容灾冗余 + 升级/容灾/冷启动的隐性风险；单位成本对**利用率极其敏感**（80% → 35% 时 $/Mtoken 翻一倍以上），而利用率由流量波动决定——经验上稳定大流量（月 10B+ token 量级）才值得，波动大/多模型/低 QPS 用 API。可混合：基线流量自托管 + 突发溢出 API。

机理与实战：
- **理论吞吐 vs 有效吞吐**：理论值来自压测满载（continuous batching 高并发），生产里受流量峰谷、batch 效率随并发衰减、长输出占比、维护窗口拖累——利用率 60-70% 已是优等生，容量账必须按有效吞吐算，且峰值按 P95 流量而非均值。
- **隐性成本清单**：模型升级的质量回归（每次换版本全量评估）、供应商中断时的容灾演练、GPU 供货与配额、推理框架调参人力（continuous batching/量化/KV cache 配置）——这些不体现在单价里，但决定总拥有成本。
- **混合分层的路由条件**：按"流量可预测性 + 模型"分流——基线可预测流量走自托管（保障延迟与成本），突发与长尾模型走 API；自托管过载溢出到 API 要有自动降级，且两边质量基线对齐（同模型版本，评估集验证）。
- **决策纪律**：算临界点必须用"自家流量的 P95 形状"代入，不能拿厂商 benchmark；先跑影子双算（同一批流量在两边各算一次成本与延迟）再立项。

```python
# 基线:Python 3.10+;纯标准库模拟自托管开源模型 vs API 计费的临界点模型
# 真实场景:vLLM 部署;GPU 月成本/有效吞吐/运维冗余 vs API 单价的 breakeven
from __future__ import annotations


def selfhost_cost_per_mtok(gpu_month_cost: float, theoretical_tok_s: float,
                           utilization: float, ops_month: float = 0.0,
                           redundancy: float = 1.0) -> tuple[float, float]:
    """自托管单位成本:含运维与 N+1 冗余;返回($/Mtok, 月token产能)。"""
    eff_tok_s = theoretical_tok_s * utilization
    monthly_tokens = eff_tok_s * 86400 * 30
    total_month = (gpu_month_cost + ops_month) * redundancy
    return total_month / monthly_tokens * 1e6, monthly_tokens


def breakeven(api_price: float, fixed_month: float) -> float:
    """月 token 临界量 = 固定成本 / API单价($/Mtok)。"""
    return fixed_month / api_price * 1e6


def demo() -> None:
    gpu_month, tok_s, ops = 12000.0, 2500.0, 4000.0     # 8xA100 租金,理论吞吐,运维
    for util in (0.8, 0.6, 0.35):
        unit, capacity = selfhost_cost_per_mtok(gpu_month, tok_s, util, ops)
        print(f"利用率 {util:.0%}:自托管 ${unit:.2f}/Mtok(月产能 "
              f"{capacity / 1e9:.1f}B token)")
        assert unit > 0

    api_price = 3.0                                     # $3/Mtok
    fixed = gpu_month + ops
    be = breakeven(api_price, fixed)
    print(f"临界点:月用量 > {be / 1e9:.1f}B token 才值得自托管 ✅")
    assert be > 3e9

    print("敏感性:利用率 80%→35%,单位成本 $"
          f"{selfhost_cost_per_mtok(gpu_month, tok_s, 0.8, ops)[0]:.2f} -> "
          f"${selfhost_cost_per_mtok(gpu_month, tok_s, 0.35, ops)[0]:.2f}/Mtok"
          " -> 低利用率自托管反而贵于 API ✅")
    print("混合策略:基线流量自托管 + 突发溢出 API;路由带降级与质量对齐")


if __name__ == "__main__":
    demo()
```

**追问一**：GPU 采购 vs 租用的决策差在哪？
答：采购把"月租金"变成资本摊销（3 年）+ 闲置风险——利用率高且稳定（常年 >70%）时采购省 30-50%；租用保留弹性（随时换卡型/缩容）适合探索期。中间态是竞价实例/预留实例混合：基线用预留、峰谷用按量。

**追问二**：自托管后怎么保证质量不劣于 API 版本？
答：三方对齐——模型版本锁定（同一 checkpoint）、推理参数对齐（温度/top-p/上下文窗口一致）、评估集双跑对比（Q7533 的影子方法）；量化版（int8/AWQ）单独过黄金集，损失超标不上线。版本漂移是自托管最大的质量事故源，发布流程要像 API 供应商换模型一样严格。

## 背诵要点
- 临界点 = 固定月成本（GPU+运维）÷ API 单价；经验月用量 10B+ token 级才值得自托管。
- 单位成本对利用率极敏感（80%→35% 翻倍以上）；容量账按有效吞吐与 P95 流量，不按理论吞吐。
- 混合分层：基线自托管+突发溢出 API，路由带自动降级；质量对齐靠版本锁定+评估集双跑。

## 复盘追问
- 业务方要求"敏感数据不出内网"但流量只有 200M token/月，怎么权衡？（提示：成本不是唯一维度——合规刚性需求可用小模型自托管做前置过滤（Q1159 分级路由），重活走脱敏+API，或专用小集群）
- 自托管集群利用率常年 30%，是缩容还是接业务？（提示：先看流量形状是否可错峰填充（离线批任务/评测跑批），再谈缩容；空闲 GPU 转做 embedding/batch 推理是常见填充手段）
