### Q7680 · 供应商"悄悄升级模型"之后：默认参数漂移事故复盘

难度：P6 ｜ 标签：事故复盘、模型升级、参数漂移
基线：LLM API 通用行为（供应商可改默认 temperature/max 输出/系统提示注入）；openai 1.x。

**问**：供应商把默认模型从 4o-2024-08 切到 4o-2025-05，代码一行没改，一周后客服反馈"回复变得又长又啰嗦"、token 账单涨了 35%、部分下游 JSON 解析失败率上升。这种"没改代码的行为突变"怎么复盘？参数漂移的防线怎么建？

**答**：**结论**：根因是**默认参数属于供应商的实现细节**，不属于你的代码契约：新模型默认 temperature 采样风格、默认输出长度、是否自动补 markdown 代码围栏都可能变。三条防线：① **显式化一切采样参数**——temperature、max_tokens、response_format 全部写进自己的配置并随请求发送，不依赖供应商默认值；② **输出契约校验**——结构化输出用 response_format(json_schema) 或本地 schema 校验 + 截断防护，不靠"模型恰好输出合法 JSON"；③ **升级前影子评测**——新版本模型在评测集上跑回归（分数卡点 + 长度分布对比），长度分布漂移是最容易被忽略的成本信号。复盘时还要把"供应商切换默认模型"加进**变更感知**：订阅 changelog、对响应里的 `model` 字段做监控——它是免费的漂移探测器。

**取舍**：锁死 `model` 版本字符串能挡住"默认切换"，但代价是旧版本退役后强制迁移（见退役窗口题）——所以版本策略是"锁小版本 + 定期主动升级"，把升级节奏从被动变主动。影子评测的成本是评测集跑批费用（每个候选版本几千到几万 token 量级），对比线上事故的排障与返工成本通常值得；但评测集要覆盖"长度敏感、格式敏感"的用例，纯正确性指标测不出啰嗦漂移。

**实战**：参数显式化 + 漂移探测（标准库模拟，无网络依赖）：

```python
# 默认参数显式化 + 响应漂移探测（标准库演示）
from dataclasses import dataclass, field

@dataclass
class RequestProfile:
    """所有采样参数显式声明，禁止依赖供应商默认值。"""
    temperature: float = 0.2
    max_output: int = 800
    response_format: str = "json_schema"   # 或 text
    model_pin: str = "gpt-4o-2024-08-06"

def build_request(profile: RequestProfile, prompt: str) -> dict:
    return {
        "model": profile.model_pin,          # 锁小版本
        "temperature": profile.temperature,  # 显式传，不取默认
        "max_output_tokens": profile.max_output,
        "response_format": {"type": profile.response_format},
        "input": prompt,
    }

print(build_request(RequestProfile(), "总结这批工单")["model"])

# 漂移探测器：监控响应里的 model 字段 + 输出长度分布
import statistics

@dataclass
class DriftSentinel:
    seen_models: set = field(default_factory=set)
    lengths: list = field(default_factory=list)

    def observe(self, model: str, output_len: int) -> list[str]:
        alerts = []
        if model not in self.seen_models:
            if self.seen_models:
                alerts.append(f"MODEL DRIFT: 默认模型变化 {model}")
            self.seen_models.add(model)
        self.lengths.append(output_len)
        if len(self.lengths) >= 50 and len(self.lengths) % 50 == 0:
            base = statistics.mean(self.lengths[:50])
            now = statistics.mean(self.lengths[-50:])
            if now > base * 1.3:
                alerts.append(f"LENGTH DRIFT: 输出均值 {base:.0f}->{now:.0f} (+{(now/base-1)*100:.0f}%)")
        return alerts

s = DriftSentinel()
for _ in range(100):                      # 模拟升级后输出变长
    s.seen_models.add("old"); s.lengths.extend([200] * 99 + [340])
alerts = s.observe("gpt-4o-2025-05", 340)
print("告警:", alerts)

# 成本账：长度漂移 35% 对账单的影响
daily_cost, ratio = 8000, 0.35
print(f"未察觉漂移 30 天多付: {daily_cost*30*ratio:,.0f} 元 —— 探测器上线回本")
```

**追问 1**：`response_format=json_schema` 为什么能挡住"JSON 解析失败率上升"？
提示：服务端受 schema 约束生成（constrained decoding），结构合法性由供应商保证；但 schema 只管结构不管语义，语义回归仍要靠评测集。

**追问 2**：输出长度分布漂移为什么是独立于"正确率"的必测指标？
提示：正确率评分对啰嗦不敏感，但长度直接影响成本、延迟与下游截断；评测集里放长度上限断言（P95 长度 ≤ 预算）作为卡点。

**追问 3**：如果供应商不给 pinned 版本的可用性承诺（退役快），锁版本策略怎么调整？
提示：缩短锁定期（月级而非年）、双版本兼容层（请求体按版本特性分支）、退役窗口预案（见退役迁移题）；监控 `model` 字段变化作为最后防线。

## 背诵要点
1. 默认参数是供应商实现细节：temperature/max_tokens/response_format 全部显式随请求发送，model 锁小版本。
2. 漂移探测器零成本：监控响应 model 字段变化 + 输出长度分布（50 样本滑窗均值 ±30% 告警）。
3. 升级前影子评测必须含长度分布卡点——纯正确率指标测不出"变啰嗦"这类成本漂移。
