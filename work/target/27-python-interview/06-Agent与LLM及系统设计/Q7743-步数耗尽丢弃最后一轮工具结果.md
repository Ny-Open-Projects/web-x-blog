### Q7743 · 步数预算耗尽时，最后一轮工具结果还没进模型就返回了

难度：P7 ｜ 标签：Agent、max_iterations、预算、终止语义

基线：Python 3.12；用"假模型 + 工具注册表"模拟 ReAct 循环的步数与终止。

**问**：Agent 循环写成 `for step in range(max_steps): action = llm(...); if tool: result = run(tool); continue; else: return answer`，`max_steps=6` 防死循环。线上有约 3% 的请求返回"我再确认一下折扣"这类半句话，用户看到的答案里没有最终金额。日志显示模型确实调了折扣工具、工具也返回了，但就是没生成最终答案。为什么？

**答**：
- **结论**：循环在"调用工具 → 追加结果 → 下一轮"的**中途**被 `range` 截断：最后一轮只完成了"工具执行"，没有机会把结果喂回模型再生成答案。于是要么返回 `None`，要么返回上一轮的 `assistant` 文本（通常是一句过渡话）。本质是**预算单位没把"收尾"算进去**：`max_steps` 计的是"工具轮次"，但生成最终答案也需要一次模型调用。
- **取舍**：三种修法：① **预留收尾步**：工具轮最多 `max_steps - 1` 次，最后强制一次"基于已有信息作答"的调用（可带 `tool_choice="none"`，禁止再调工具）；② 预算耗尽时不返回历史文本，而是返回结构化的"部分结果 + 缺失项"（对用户诚实，便于重试）；③ 用"token 预算 + 步数预算"双约束，并在接近上限时提前注入"请尽快收尾"的提示。
- **实战**：① 终止条件要区分三种：**正常完成**、**预算耗尽**、**工具失败**，返回值里带 `finish_reason`，不要都塞成"答案"；② 对"预算耗尽"的比例做监控（超过 1% 就该调大预算或优化工具链）；③ 单测覆盖"最后一步刚好是工具调用"的边界（`max_steps` 取 1、2、3 各跑一遍）；④ 收尾调用不要再给工具，否则又可能进入下一轮。

```python
"""max_steps 把收尾吃掉：最后一轮工具结果进了上下文，却没人读它。"""
TOOLS = {"get_price": 99.0, "get_discount": 0.8}


class FakeLLM:
    def __init__(self) -> None:
        self.turn = 0

    def act(self, ctx: dict, allow_tools: bool = True) -> dict:
        self.turn += 1
        if allow_tools and "price" not in ctx:
            return {"type": "tool", "name": "get_price", "text": "我先查一下价格。"}
        if allow_tools and "discount" not in ctx:
            return {"type": "tool", "name": "get_discount", "text": "再看看有没有折扣。"}
        price = ctx.get("price")
        discount = ctx.get("discount")
        if price is None:
            return {"type": "answer", "text": "暂时拿不到价格，请稍后再试。"}
        if discount is None:
            return {"type": "answer", "text": f"价格 {price:.1f} 元（折扣信息缺失）"}
        return {"type": "answer", "text": f"最终价格 {price * discount:.1f} 元"}


def run(max_steps: int, reserve_final: bool = False) -> dict:
    """max_steps 是总步数；reserve_final 表示最后一步留给"生成答案"。"""
    llm = FakeLLM()
    ctx: dict[str, float] = {}
    said: list[str] = []
    tool_rounds = max_steps - 1 if reserve_final else max_steps

    for _ in range(tool_rounds):
        action = llm.act(ctx, allow_tools=True)
        if action["type"] == "answer":
            return {"finish": "answer", "text": action["text"], "said": said}
        said.append(action["text"])
        ctx[action["name"].replace("get_", "")] = TOOLS[action["name"]]

    if reserve_final:
        action = llm.act(ctx, allow_tools=False)   # 禁止再调工具，只生成答案
        return {"finish": "answer", "text": action["text"], "said": said}

    return {"finish": "budget_exhausted",
            "text": said[-1] if said else None, "said": said}


if __name__ == "__main__":
    bad = run(max_steps=2)
    print("预算=2（无预留）:")
    print("  finish:", bad["finish"], "| 返回给用户的文本:", bad["text"])
    print("  已经说过的话:", bad["said"])

    good = run(max_steps=3, reserve_final=True)
    print("\n预算=3（2 轮工具 + 1 次收尾）:")
    print("  finish:", good["finish"], "| 答案:", good["text"])

    # 预算更紧时，收尾也要给出"部分结果"而不是历史闲聊
    partial = run(max_steps=2, reserve_final=True)
    print("\n预算=2（1 轮工具 + 1 次收尾）:")
    print("  finish:", partial["finish"], "| 答案:", partial["text"])
    print("  -> 明确说明缺什么，而不是把过渡话当答案")

    print("\n结论：max_steps 要包含收尾调用；预算耗尽要返回结构化 finish_reason")
```

**追问一**：为什么"预算耗尽"不应该直接抛异常或返回 500？

→ 解析：这时工具**已经执行**（可能已经下单、发短信），抛异常会让调用方不知道副作用是否发生，重试还可能重复执行。正确做法是返回结构化的部分结果：`finish_reason="budget_exhausted"`、已完成的动作清单、缺失的信息、以及"可安全重试/不可重试"的标记。让上层决定是展示部分结果、转人工，还是在幂等前提下重跑。

**追问二**：`max_steps` 和 token 预算，哪个先触发更常见？

→ 解析：取决于工具形态。高频小工具（每次几百 token）通常先撞步数；一次返回大结果（检索 20 个 chunk、读整张表）通常先撞 token。两者要同时记，并且**分别埋点**：`exhausted_by=steps|tokens|timeout`。只埋一个总"失败率"会导致调参时拍脑袋——看到步数耗尽就调大 `max_steps`，结果 token 又爆，来回震荡。更稳的是"预算分配"：给每类工具设单次结果上限（截断/摘要），让步数成为主要约束。
