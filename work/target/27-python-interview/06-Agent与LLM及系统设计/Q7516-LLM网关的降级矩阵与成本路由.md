### Q7516 · LLM 网关与降级矩阵

> 难度:★★★ | 标签:LLM 网关, 降级, 路由

**问**：应用同时接 3 家模型供应商——「简单任务用便宜模型、复杂任务用强模型」的路由怎么实现（提前分类 vs 试错切换）？供应商 429/超时时的降级链路（换供应商 → 降参 → 缓存兜底 → 排队）怎么编排，降级后「输出风格变了」怎么让业务无感？

**答**：① 路由两路线：**预分类**（小模型/规则先判任务复杂度，路由到对应档位——加一次便宜调用的延迟换整体成本；分类器本身要定期校准防「全路由到贵模型」）；**试错切换**（先便宜模型跑，质量探针不达标升级重试——简单任务零浪费，复杂任务多一次延迟）。生产常用混合：任务类型静态路由 + 边缘 case 试错。② 降级链路（按优先级）：换供应商（同档位模型，prompt 兼容）→ 降参数（max_tokens/上下文裁剪，牺牲质量保可用）→ **缓存兜底**（相似请求历史答案 + 明确标注「缓存结果」）→ 排队（预算恢复后处理，配合幂等）。③ 风格无感：响应层**归一化中间件**（统一输出 schema、截断风格、错误码映射），prompt 层做供应商适配（同一语义多模板）；关键：降级后响应打 `degraded: true` 标记，下游业务可感知但用户无感。

```python
# 全部标准库；demo 实现「路由器 + 降级链 + 输出归一化」
import time, random, hashlib

MODEL_TIERS = {                    # 供应商档位表（成本/能力）
    "cheap":  {"cost_per_k": 0.002, "quality": 0.7, "vendors": ["v-a", "v-b"]},
    "strong": {"cost_per_k": 0.02,  "quality": 0.95, "vendors": ["v-c"]},
}

class Gateway:
    def __init__(self):
        self.cache: dict[str, str] = {}
        self.vendor_health: dict[str, float] = {v: 1.0 for t in MODEL_TIERS.values()
                                                 for v in t["vendors"]}
    def route(self, complexity: float) -> str:
        """复杂度路由：阈值静态分类。"""
        return "strong" if complexity > 0.6 else "cheap"
    def invoke(self, tier: str, prompt: str) -> dict:
        """降级链：同档换供应商 → 降参 → 缓存 → 排队。"""
        chain = []
        for vendor in MODEL_TIERS[tier]["vendors"]:       # 步骤1：同档供应商轮换
            if self.vendor_health[vendor] > 0.5:
                chain.append(f"vendor={vendor}")
                return self._normalize({"text": f"answer({prompt[:10]})",
                                        "vendor": vendor, "degraded": False}, chain)
            chain.append(f"vendor={vendor} 跳过(429)")
        h = hashlib.md5(prompt.encode()).hexdigest()[:8]  # 步骤3：缓存兜底
        if h in self.cache:
            chain.append("cache")
            return self._normalize({"text": self.cache[h], "vendor": "cache",
                                    "degraded": True}, chain)
        chain.append("queued")                            # 步骤4：排队
        return self._normalize({"text": "", "vendor": None, "degraded": True,
                                "queued": True}, chain)
    def _normalize(self, resp: dict, chain: list) -> dict:
        """输出归一化：统一 schema + 降级标记（业务可感知、用户无感）。"""
        return {"text": resp["text"], "degraded": resp.get("degraded", False),
                "fallback_chain": chain, "usage": {"prompt_tokens": 100,
                "completion_tokens": 50,
                "cost": MODEL_TIERS.get("cheap", {"cost_per_k": 0})["cost_per_k"]}}

if __name__ == "__main__":
    random.seed(1)
    gw = Gateway()
    gw.vendor_health["v-a"] = 0.0                # 模拟主供应商 429
    r = gw.invoke("cheap", "写一份周报")
    print("降级链:", r["fallback_chain"], "| degraded:", r["degraded"])
    assert r["fallback_chain"][0].endswith("跳过(429)")
    gw.cache[hashlib.md5("写一份周报".encode()).hexdigest()[:8]] = "历史缓存答案"
    r2 = gw.invoke("cheap", "写一份周报")
    assert r2["text"] == "历史缓存答案" and r2["degraded"]
    print("缓存兜底:", r2["fallback_chain"], "✅")
    print("路由演示:", gw.route(0.9), "/", gw.route(0.3))
    # 口径：降级标记 degraded 必须传递（下游可感知）；缓存答案要过期时间与相似度阈值。
```

**追问**：1) 为什么「同档位换供应商」排在降参前？——用户感知：换供应商（同能力档）质量基本不变，降参（砍上下文/长度）质量确定下降——降级顺序按「质量损失从小到大」排。2) 质量探针怎么设计？——轻量评估（规则/小模型打分）在响应层跑，不达标触发升级重试；探针本身的成本要计入路由决策（探针贵过差价就不划算）。3) 供应商健康度怎么维护？——滑动窗口错误率/延迟（A106 熔断复用），半开探测恢复；LLM 网关本质是「针对 LLM 特性（慢/贵/非确定）特化的 API 网关 + 预算管理」。

## 背诵要点
1. 路由两路线：预分类（省成本）+ 试错切换（保质量），生产混合；探针成本计入决策。
2. 降级链按质量损失排序：同档换供应商 → 降参 → 缓存兜底（标注 degraded）→ 排队。
3. 输出归一化中间件统一 schema/错误码，降级标记 degraded 让业务可感知用户无感。

## 复盘追问
1. 降级期间「缓存答案」过期了但没人发现，业务事故形态？（提示：过期缓存被当新鲜答案使用——缓存必须带 TTL 与数据日期标注，degraded 聚合监控要有专门面板）
2. 三家供应商同时 429（大模型限流风暴），网关的最终防线？（提示：排队 + 客户端友好错误（预估恢复时间）+ 任务优先级抢占（贵任务先跑），参考 A101/A106 联动）
