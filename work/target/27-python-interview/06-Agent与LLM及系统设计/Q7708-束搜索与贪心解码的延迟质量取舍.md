### Q7708 · 束搜索与贪心解码的延迟-质量取舍

难度：P6 ｜ 标签：容量成本账、解码策略、beam search、延迟

基线：Python 3.12；纯 Python 模拟 beam width 与成本/质量关系。

**问**：同一个推理服务，有的请求用贪心解码（temperature=0），有的用 beam search（beam=4）。为什么后者的延迟和成本明显更高，但某些任务质量更好、某些反而更差？怎么按任务选？

**答**：
- **结论**：贪心每步只保留概率最高的 1 条路径（beam=1），计算量最小、延迟最低、确定性强；beam search 每步保留 beam 条候选路径，成本约随 beam 线性增长，能通过全局搜索避免贪心"局部最优"的坑，在机器翻译、摘要等有明确整体目标的任务上质量更好。但在**开放域对话/创意写作**里，beam search 容易产出保守、重复、安全但无趣的答案（"beam search 诅咒"），采样反而更自然。
- **取舍**：beam 越大成本越高、延迟越长，边际收益递减；API 场景多数只提供采样/temperature，不暴露 beam（自托管推理框架才有）。温度采样（temperature/top_p）是另一种"用随机性换多样性"的杠杆，和 beam 属于不同维度。
- **实战**：按任务定解码策略——确定性结构化抽取用贪心/低温度；翻译/摘要用 beam；对话/创意用采样；给 beam width 设上限并监控 P99 延迟；别在高并发在线服务上默认开大 beam，成本会随并发放大。

```python
def beam_cost(beam: int, steps: int) -> int:
    """近似：每步维护 beam 条候选，成本随 beam 与步数增长。"""
    return beam * steps


if __name__ == "__main__":
    steps = 100
    for beam in (1, 2, 4, 8):
        cost = beam_cost(beam, steps)
        print(f"beam={beam}: 相对成本 {cost}, "
              f"{'贪心/最低延迟' if beam == 1 else '搜索更强但更慢'}")
    # beam 越大边际收益递减、延迟线性上升，按任务设上限。
```

**追问一**：为什么 beam search 在开放域对话里反而更差？
→ 解析：beam search 优化的是整体概率最大，倾向于高频、安全、通用的表达，导致输出重复、缺乏多样性（"beam search 诅咒"）；对话/创意任务需要多样性，采样更合适。

**追问二**：temperature=0 等于 beam=1 吗？
→ 解析：近似但不等价。temperature=0 是贪心采样（每步取最大概率 token， beam=1）；beam search 即使 beam>1 也是确定性的概率搜索。核心差别是"是否保留多条候选路径"，而 temperature 控制的是采样分布的尖锐程度，属于不同维度。
