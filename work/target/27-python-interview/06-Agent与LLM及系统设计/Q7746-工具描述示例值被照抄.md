### Q7746 · 工具描述里写了「示例：北京」，模型对任何城市都传北京

难度：P6 ｜ 标签：function calling、工具描述、few-shot 泄漏、参数校验

基线：Python 3.12；用"有槽位就填、没有就抄示例"的规则模型复现参数照抄。

**问**：天气工具的描述写成"查询城市天气。参数示例：`{"city": "北京", "date": "2026-11-24"}`"。上线后用户问"明天天气怎么样"（没说城市），助手直接返回北京的天气；问"上海呢"，日期又变成了示例里的 2026-11-24。模型是"看懂"了描述还是"抄"了示例？工具描述该怎么写？

**答**：
- **结论**：模型对工具描述里的**字面值**极其敏感：示例中的具体值会被当成"默认值/候选值"照抄，尤其是在用户没提供该槽位时。这不是"理解错误"，而是示例在上下文里起到了 few-shot 的作用——它告诉模型"这个字段长这样"，模型就把样例值当成了合理填充。日期这类"看起来像当前时间"的示例危害更大：模型无法感知真实时间，会把示例日期当成事实。
- **取舍**：① 示例用**占位符**而不是真实值（`city` 描述为"城市名，如用户提到的城市；未提到则不要填"），或者干脆不给示例，只给类型与约束；② 每个参数写清"何时必须填、何时留空、留空时工具会怎样"；③ 服务端做参数校验：必填缺失就返回结构化错误让模型追问用户，而不是用默认值兜底；④ 需要 few-shot 时，把示例放在**系统提示的独立区**并明确"以下仅为格式示意，值不代表真实数据"。
- **实战**：① 工具 schema 的 `description` 与 `required` 是契约的一部分，改动要走评审与回归（用固定评测集测调用正确率）；② 对"用户未提供"的槽位，宁可让模型发起澄清提问，也不要猜；③ 日期/时间这类字段由服务端注入当前时间，不要依赖模型；④ 埋点统计"参数等于示例值"的比例——异常高就是照抄信号。

```python
"""工具描述里的示例值被照抄：占位符 + 必填校验才是正解。"""
import re

CITY_RE = re.compile(r"(北京|上海|广州|深圳|杭州|成都)")

DESC_WITH_EXAMPLE = (
    '查询城市天气。参数示例：{"city": "北京", "date": "2026-11-24"}'
)
DESC_WITH_PLACEHOLDER = (
    "查询用户明确提到的城市的天气。"
    "city：必填，只能取用户原话中出现的城市名；用户未提及则不要调用本工具，先反问。"
    "date：可选，格式 YYYY-MM-DD；未提及则由服务端按当天填充，不要自行猜测。"
)


def fake_model(query: str, description: str) -> dict:
    """规则模型：能从 query 抽到城市就填，抽不到就抄描述里的示例值。"""
    city = CITY_RE.search(query)
    if city:
        return {"city": city.group(1)}
    example = re.search(r'"city":\s*"([^"]+)"', description)
    if example:
        return {"city": example.group(1)}          # 照抄示例
    return {}                                       # 占位符描述：不猜


def validate(args: dict) -> tuple[bool, str]:
    if "city" not in args:
        return False, "missing required field: city -> 应向用户澄清"
    if not CITY_RE.fullmatch(args["city"]):
        return False, f"invalid city: {args['city']!r}"
    return True, "ok"


if __name__ == "__main__":
    for q in ("明天天气怎么样", "上海明天天气", "北京呢"):
        got = fake_model(q, DESC_WITH_EXAMPLE)
        ok, msg = validate(got)
        print(f"示例描述 | {q!r:<12} -> {got} | {msg}")

    print()
    for q in ("明天天气怎么样", "上海明天天气"):
        got = fake_model(q, DESC_WITH_PLACEHOLDER)
        ok, msg = validate(got)
        print(f"占位描述 | {q!r:<12} -> {got} | {msg}")

    print("\n日期同理：描述里写死 2026-11-24，模型会把它当成'今天'")
    print("结论：描述里不要放真实值；缺失槽位让模型反问，服务端强校验")
```

**追问一**：为什么模型更愿意"抄示例"而不是"遵守规则"？

→ 解析：示例是**具体的 token 序列**，与最终输出的分布最接近，模型在生成参数时是"续写"而不是"推理规则"；抽象规则（"未提及就不要填"）需要模型先判断"是否提及"再决定"不填"，多了一步反事实推理，概率上更容易被示例的强先验压过。工程上的对策不是"把规则写得更严厉"，而是**消除误导性示例**：没有具体值可抄，模型就只能按规则走。

**追问二**：把 `city` 改成 `enum`（限定城市列表）能解决问题吗？

→ 解析：能解决"抄错城市"的一部分（只能从列表里选），但解决不了"用户没说城市却硬选一个"——它会在 enum 里挑一个最像的，错误从"照抄示例"变成"强行匹配"。而且 enum 会限制扩展（新城市要改 schema），长列表本身还占 token。更稳的是：`enum` + `required` + "缺失时不要调用"的明确指令 + 服务端校验，三层一起；枚举值用稳定的 code（`shanghai`）而不是展示名（`上海`），避免模型在城市别名上做"翻译"。
