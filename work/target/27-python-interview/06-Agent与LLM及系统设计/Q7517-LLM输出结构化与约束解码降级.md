### Q7517 · 结构化输出与校验重试

> 难度:★★★ | 标签:结构化输出, JSON, 重试

**问**：让 LLM 返回 JSON（如订单抽取）——「prompt 里说请返回 JSON」为什么不够？json_schema 约束解码（grammar/structured output）的原理与局限（嵌套太深/枚举太大怎么办），校验失败的重试设计（带错误反馈的二次请求）怎么写才有效，什么时候该放弃解析走兜底？

**答**：① 「请返回 JSON」的失败模式：模型在 JSON 里混 markdown 围栏/注释/尾逗号/单引号——采样是逐 token 的，没有硬约束时非法组合概率累积。约束解码：服务端在每步采样时**用 grammar mask 屏蔽非法 token**（OpenAI structured outputs / vLLM outlines 类），输出 100% 语法合法——但**语义仍可能错**（字段值不符合业务规则：金额为负、日期乱写），schema 合法 ≠ 语义正确，业务校验层必须独立存在。② 局限：深层嵌套/超大枚举导致 grammar 状态机爆炸（首 token 延迟飙升）；`additionalProperties` 类宽松语义各家支持不一。③ 重试设计：失败反馈要**精准具体**（「字段 `amount`: 期望 number 得到 string；行 3」），把原输出和错误一起回喂——比「请重新输出 JSON」有效一个量级；重试带指数退避 + 换 prompt 策略（2 次同错说明 prompt 有歧义，改示例）。④ 放弃条件：重试 2-3 次仍失败 → 结构性 prompt 问题或输入本身歧义，走兜底（降级正则抽取关键字段 / 转人工 / 拒绝并记录），**不要在重试里无限烧钱**。

```python
# 全部标准库；demo 实现「校验 + 精准错误反馈 + 重试预算 + 兜底」
import json, re

SCHEMA = {"type": "object", "required": ["order_id", "amount", "items"],
          "props": {"order_id": str, "amount": float, "items": list}}

def validate(out: dict) -> list[str]:
    """schema 合法性 + 业务语义双层校验，错误要具体到字段。"""
    errs = []
    for k in SCHEMA["required"]:
        if k not in out:
            errs.append(f"字段缺失: {k}")
    if "amount" in out:
        if isinstance(out["amount"], str):
            errs.append(f"字段 amount: 期望 number，得到 string '{out['amount']}'")
        elif out["amount"] <= 0:
            errs.append(f"业务规则: amount 必须为正，得到 {out['amount']}")   # 语义层
    if "items" in out and not out["items"]:
        errs.append("业务规则: items 不能为空")
    return errs

def extract_json(text: str) -> dict | None:
    """宽松解析：剥围栏、找首个平衡大括号。"""
    FENCE = chr(96) * 3                       # 避免 markdown 解析截断
    text = re.sub(rf"^{FENCE}(json)?|{FENCE}$", "", text.strip(), flags=re.M).strip()
    start = text.find("{")
    depth = 0
    for i, ch in enumerate(text[start:], start):
        depth += (ch == "{") - (ch == "}")
        if depth == 0:
            try:
                return json.loads(text[start:i+1])
            except json.JSONDecodeError:
                return None
    return None

def pipeline(attempts: list[str], max_retry: int = 2):
    """重试主循环：校验 → 精准反馈回喂 → 预算耗尽兜底。"""
    log = []
    for i, raw in enumerate(attempts):
        out = extract_json(raw)
        if out is None:
            feedback = "输出无法解析为 JSON：剥除围栏后仍无平衡大括号"
        else:
            errs = validate(out)
            if not errs:
                return {"ok": out, "attempts": i + 1}
            feedback = "JSON 语法合法但校验失败：\n" + "\n".join(f"- {e}" for e in errs)
        log.append(f"attempt{i+1}: {feedback}")
        if i + 1 > max_retry:
            break
    # 兜底：正则抽取关键字段（降级不放弃）
    fallback = {}
    m = re.search(r"order_id[\"':\s]+(\w+)", attempts[-1])
    if m: fallback["order_id"] = m.group(1)
    return {"fallback": fallback, "log": log}

if __name__ == "__main__":
    F = chr(96) * 3
    bad1 = F + 'json\n{"order_id": "A1", "amount": "9.9", "items": []}\n' + F
    good = '{"order_id": "A2", "amount": 9.9, "items": ["x"]}'
    r = pipeline([bad1, good])
    assert "ok" in r and r["attempts"] == 2
    print("第 2 次成功（精准错误反馈后）:", r["ok"])
    r2 = pipeline(['{"amount": -5, "items": []}'] * 3)       # 三次同错
    assert "fallback" in r2
    print("重试预算耗尽 → 兜底:", r2["fallback"])
    print(r2["log"][0])
    # 口径：约束解码管语法、业务校验管语义（两层都要）；反馈具体到字段；
    # 重试 ≤2-3 次，同错 2 次改 prompt 而非重试；兜底永远在场。
```

**追问**：1) 约束解码为什么慢在首 token？——grammar 状态机要在每步对全词表算合法掩码，深 schema 的状态空间大；优化： grammar 编译缓存、字段级分步生成、简化 schema（拍平嵌套）。2) 「业务校验放 prompt 里让模型自查」行不行？——不可靠：模型自查即自评，同一偏差源（自评偏差，Q7501）；校验必须是**代码**（确定性），模型输出只当数据。3) 兜底的「正则抽取」为什么值得保留？——结构化失败 ≠ 全部信息丢失：正则能捞 80% 关键字段打标低置信度，下游按置信度分路（低置信走人工），比全量拒绝的吞吐高一档。

## 背诵要点
1. 约束解码管语法合法（grammar mask 屏蔽非法 token），业务校验管语义合法（代码层，不靠模型自查）。
2. 重试反馈必须具体到字段与期望值；同错 2 次 = prompt 问题，改示例不改重试次数。
3. 重试预算 2-3 次 + 兜底（正则捞字段打低置信标签）永远在场，不无限烧钱。
