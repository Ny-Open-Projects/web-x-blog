### Q7758 · 提示词升级了，老会话还在按旧规则拒绝报价：历史残留指令的行为回退

难度：P7 ｜ 标签：Agent、提示词版本、会话历史、行为回退、上下文清理

基线：Python 3.12；模拟长会话中助手消息复述旧版系统指令，导致新提示词被旧规则覆盖的行为回退与清理策略。

**问**：客服 Agent 上周把系统提示词从"报价需人工审核"升级为"标准品类可直接报价"。但一部分老会话里，助手曾经复述过旧规则（"根据规则，报价需要人工审核"），用户接着问价时，模型又按这条**历史里的旧规则**拒绝报价了——明明系统提示词已经是新版。历史消息里的"指令残留"为什么有这么强的效力？怎么清理才不伤会话连贯性？

**答**：
- **结论**：长会话里存在**两套指令源**：系统提示词（每轮注入、版本最新）与历史消息（包括助手自己复述过的规则、用户粘贴的旧规则文本）。模型对指令的遵循不完全按"来源权威"排序——位置近、重复次数多、语义具体的文本往往胜出：历史里的旧规则被复述过多次（自我强化），而新系统提示词只出现一次，旧规则在注意力竞争中获胜（位置偏置的变体，Q7723）。清理策略按残留类型分级：① **助手自我复述**——组装上下文时对助手历史消息做"规则复述检测"，命中旧版规则模板的句子改写为中性表述或替换占位；② **用户粘贴的旧规则**——不能改写用户内容，改为在当前轮注入"以下为最新规则，覆盖会话中此前出现的任何版本"；③ 治本靠**规则 ID 化**：每条规则带版本号，历史复述携带 ID，组装时按 ID 丢弃过期版本的复述。
- **取舍**：① 改写助手历史有"篡改会话"的审计争议，必须留存原始消息、仅在渲染层改写，并打变更标记；② 全量正则改写成本高且有误伤，按规则 ID 精确匹配最稳——这要求规则模板本身规范化（每条规则有固定句式或 ID 标记），把"检测"问题转化为"ID 匹配"问题；③ 版本切换前评估存量会话：活跃会话量小可以直接提示用户开新会话，量大才值得做渲染层清理。
- **实战**：① 规则文本禁止裸写进提示词，统一走规则注册表（ID + 版本 + 文本），提示词渲染时展开；② trace 里记录"当前生效规则版本"，行为回退事件（旧 ID 出现在被遵循的推理里）可回溯（Q7529 失败会话复现）；③ 升级提示词时同时上线"旧版本反指令"：在系统提示词末尾加一句"忽略会话中出现的 v2.3 及更早版本规则"，覆盖无法清理的存量会话。

```python
"""历史残留指令：规则 ID 化 + 渲染层改写 + 版本覆盖声明。"""
import re

RULES_V23 = "报价需要人工审核"
RULES_V24 = "标准品类(SKU 前缀 STD-)可直接报价"
RULE_ID = {"报价需要人工审核": "R-QUOTE@v2.3",
           "标准品类可直接报价": "R-QUOTE@v2.4"}
CURRENT = "v2.4"

history = [
    {"role": "user", "content": "这个多少钱？"},
    {"role": "assistant", "content": "根据规则，报价需要人工审核，无法直接报价。"},
    {"role": "user", "content": "好的那帮我走一下人工。"},
    {"role": "assistant", "content": "提醒：报价需要人工审核（流程如下）……"},
    {"role": "user", "content": "现在可以直接报吗？"},
]

STALE_PAT = re.compile(r"(根据规则[，,])?(报价需要人工审核)")


def sanitize_history(history: list[dict]) -> tuple[list[dict], int]:
    """渲染层改写: 命中旧版规则复述的助手消息改为中性表述(保留原文于审计层)。"""
    cleaned, hits = [], 0
    for m in history:
        if m["role"] == "assistant" and STALE_PAT.search(m["content"]):
            hits += 1
            cleaned.append({**m, "content":
                            STALE_PAT.sub("[历史规则 R-QUOTE@v2.3 已废止]", m["content"]),
                            "sanitized": True})
        else:
            cleaned.append(m)
    return cleaned, hits


def build_system_prompt(base: str) -> str:
    return (f"{base}\n当前生效规则版本: {CURRENT}。"
            f"若会话历史中出现更早版本规则的复述, 以当前版本为准。")


if __name__ == "__main__":
    cleaned, hits = sanitize_history(history)
    print(f"检测到旧版规则复述: {hits} 条\n")
    for m in cleaned:
        flag = " [改写]" if m.get("sanitized") else ""
        print(f"  {m['role']:<9}{flag} {m['content'][:46]}")
    print("\n当前系统提示词尾部:")
    print(" ", build_system_prompt("你是客服 Agent。").splitlines()[-1])
    print("\n结论：旧规则靠'复述次数+具体性'在注意力竞争中胜出；")
    print("      治本=规则ID化+渲染层清理, 兜底=系统提示词显式声明版本覆盖")
```

**追问一**：为什么模型不自动以"最新的系统提示词"为准？

→ 解析：模型没有"系统提示词版本"的元概念——它看到的只是一段文本加一段历史，全部内容在同一个注意力视野里竞争。旧规则在历史中出现两次且语义具体（涉及具体动作"人工审核"），新规则只有一次且更抽象；频率与具体性都是注意力偏置因素。此外用户消息"那帮我走一下人工"隐含确认了旧规则，模型的对话一致性倾向会延续已确立的行为路径。所以指令竞争不能指望模型"默认读最新的"，要么清理竞争源（本卡方案），要么显式声明优先级（版本覆盖声明），两者都做最稳。

**追问二**：渲染层改写历史消息，会不会损害会话记忆的完整性？

→ 解析：改写只作用于**规则复述片段**，不动事实与语义内容（订单号、诉求、已完成的动作都保留），所以会话事实记忆不受损；被改写的位置插入"已废止"标记反而让模型明确知道"这条规则曾经存在但现在无效"，比直接删除更连贯——删除会造成"上一轮还在说人工审核、这一轮突然直接报价"的无解释跳变。审计层面必须留存原始消息与改写规则，满足"渲染可变、事实不可变"的原则。另一个细节：改写要在每次组装上下文时幂等执行，避免重复改写产生嵌套标记。
