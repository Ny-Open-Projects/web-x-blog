### Q7690 · 上下文超窗截断丢指令事故复盘

难度：P6 ｜ 标签：事故复盘、上下文窗口、截断策略、长会话

基线：Python 3.9+；OpenAI/Anthropic 兼容 SDK 1.x；token 估算 tiktoken（基线 0.7+）。

**问**：一个多轮对话助手上线后偶发"忘记系统提示里的输出格式要求"，输出开始乱编；排查发现是长会话把上下文顶到了窗口上限，SDK/网关做了静默截断。为什么截断会丢指令而不是丢历史？正确处理是什么？

**答**：
- **结论**：常见客户端截断策略是"保尾部"——从消息队列头部丢弃最老的消息，但**系统提示（system）往往拼在最前面**，跟着历史一起被丢掉，于是格式要求、安全约束、人设全没了；工具定义则可能在另一端被截。正确处理是**预算化组装**：把上下文按优先级分区（system+关键约束 > 最近 N 轮对话 > 工具结果 > 更早历史），先算 token 预算再填充，超限走"压缩/摘要"而不是静默丢弃；并且在组装层做硬校验——超窗直接报错，绝不交给框架默认行为。
- **取舍**：摘要压缩有信息损失（数字、ID、否定句最易丢），所以关键事实要"结构化留存"（把 must-know 写进 system 或注入的 state 卡片），历史只负责语气与上下文；同时摘要本身要花一次调用，成本与延迟要入账。
- **实战**：防线清单——(1) 组装函数显式接收 `budget_tokens`，分区裁剪并记录"丢掉了什么"；(2) 对 `context_length_exceeded` 类错误做重试路径（压缩后重试），不裸抛；(3) 监控"组装后实际 token / 上限"水位线，>85% 告警；(4) 系统提示加自检：要求模型复述关键约束做金丝雀验证。

```python
# 上下文预算化组装器：分区裁剪 + 丢包审计（标准库可运行；token 用字符近似）。
def approx_tokens(msgs: list[dict]) -> int:
    # 演示口径：中文约 1 token/字，英文 4 字符/token；生产用 tiktoken 精算
    return sum(int(len(m["content"]) * (1.0 if _zh_ratio(m) else 0.25))
               for m in msgs)

def _zh_ratio(m: dict) -> float:
    c = m["content"]
    return sum(1 for ch in c if ord(ch) > 0x2E80) / max(len(c), 1) > 0.3

def assemble(system: str, history: list[dict], window: int,
             keep_recent: int = 6) -> tuple[list[dict], list[str]]:
    """优先级分区：system 永不裁；最近 keep_recent 轮保留；更早的走摘要占位。"""
    audit: list[str] = []
    budget = window - approx_tokens([{"role": "system", "content": system}])
    if budget <= 0:
        raise ValueError("system 提示本身超过窗口，配置错误")
    recent = history[-keep_recent:]
    older = history[:-keep_recent]
    recent_cost = approx_tokens(recent)
    if recent_cost > budget:
        audit.append(f"最近 {keep_recent} 轮超预算 {recent_cost - budget} tok，"
                     f"需压缩，不允许静默丢 system")
        while recent and approx_tokens(recent) > budget:
            dropped, recent = recent[0], recent[1:]
            audit.append(f"丢弃最旧一条: {dropped['content'][:20]}...")
    parts = [{"role": "system", "content": system}]
    if older:
        parts.append({"role": "system",
                      "content": f"[历史摘要占位：前 {len(older)} 轮已压缩]"})
    parts += recent
    return parts, audit

if __name__ == "__main__":
    history = [{"role": "role", "content": f"第{i}轮对话内容" * 20}
               for i in range(30)]
    msgs, audit = assemble(system="你是客服助手，必须按 JSON 格式输出。",
                           history=history, window=600, keep_recent=6)
    print(f"组装 {len(msgs)} 条消息，约 {approx_tokens(msgs)} tok / 600")
    for line in audit:
        print("-", line)
    # 组装 5 条消息，约 519 tok / 600
    # - 最近 6 轮超预算 381 tok，需压缩，不允许静默丢 system
    # - 丢弃最旧一条: 第24轮对话内容第24轮对话内容第24轮...（逐条裁剪并审计）
```

**追问**：
- 一层：为什么"摘要压缩"对数字/ID 特别危险？→ 提示：摘要模型倾向语义化改写，精确 token（订单号、金额、否定句）最容易变形；关键事实走结构化 state 注入。
- 二层：工具结果占大量上下文时怎么省？→ 提示：工具结果落盘 + 引用句柄（把 3000 行 JSON 换成"结果存于 id=xx"），需要时再拉取；配合 prompt 缓存把稳定前缀固定。

**背诵要点**：
1. 截断事故根因：保尾部策略连 system 一起丢；组装必须预算化分区（system>近期对话>工具结果>历史）。
2. 超窗处理链：组装层硬校验报错 → 压缩/摘要重试 → 水位线 85% 告警；绝不依赖框架静默截断。
3. 摘要有损：数字/ID/否定句最易丢，关键事实结构化注入，历史只保语境。

**复盘追问**：
1. 为什么事故是"偶发"而非必现？提示：只有长会话触发截断，短会话测试全绿——测试集要包含超窗用例。
2. 如果必须支持 10 万 token 会话怎么办？提示：分层记忆（摘要+检索）或换长窗模型，账要算价格与延迟差。
