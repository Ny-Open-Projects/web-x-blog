### Q7512 · RAG 分块的版式感知策略

> 难度:★★★ | 标签:RAG, 分块, 文档解析

**问**：固定 512 token 切块对什么文档会切坏——表格、代码、法律条款各坏在哪？版式感知分块（按结构元素：标题/表格/段落）怎么做，表格怎么块化才能被检索命中（「按行切块」还是「整表+摘要」），块边界信息（前置标题链）为什么重要？

**答**：固定切块的三类破坏：① **表格**：行被拦腰切开，半张表既没有表头（列语义丢失）也没有完整行；② **代码**：函数体内切块，上下文（签名/缩进语义）丢失，检索命中碎片代码无使用价值；③ **法律/条款**：引用关系（「如上文第 3 条」）被切散。版式感知分块：解析器输出结构树（标题层级/表格/代码块/段落），按**结构元素为最小切分单元**，超长元素再内部切（表格按行组+复制表头）。表格策略：小表（≤N 行）整表一块 + 首行转文字摘要；大表按行组切但**每块复制表头**，并可加「列名→值」的文字化描述行（检索器是文本匹配，语义化行命中率远高于裸数字）。块边界：每块携带**前置标题链**（`ch2.3 > 退款规则 > 特殊商品`）拼进正文或 metadata——检索命中碎片时 LLM 仍知道它属于哪节，消歧关键。

```python
# 全部标准库；demo 实现版式感知分块器（标题树/表格行组+表头复制）
import re, hashlib

FENCE = chr(96) * 3            # markdown 代码栅栏（避免裸写导致解析截断）

def parse_structure(doc: str) -> list[tuple[str, str]]:
    """解析 markdown 结构：返回 [(类型, 内容)]。"""
    elements = []
    for para in doc.split("\n\n"):
        para = para.strip()
        if not para: continue
        if para.startswith("#"):
            elements.append(("header", para.lstrip("#").strip()))
        elif para.startswith("|"):
            elements.append(("table", para))
        elif para.startswith(FENCE):
            elements.append(("code", para))
        else:
            elements.append(("para", para))
    return elements

def chunk_semantic(doc: str, max_tokens: int = 200, table_rows: int = 3) -> list[dict]:
    """版式感知分块：结构元素为单元，表格行组切块+表头复制，块带标题链。"""
    elements = parse_structure(doc)
    chunks, h1 = [], ""
    for kind, content in elements:
        if kind == "header":
            h1 = content if content.count(".") <= 1 else h1
            continue
        if kind == "table":
            rows = [r for r in content.splitlines() if r.strip().startswith("|")]
            header_row, body = rows[0], rows[1:]
            for i in range(0, len(body), table_rows):          # 表格：行组切块
                part = "\n".join([header_row] + body[i:i+table_rows])  # 每块复制表头
                chunks.append({"type": "table", "text": f"[表: {h1}]\n{part}",
                               "heading_path": h1})
        else:
            prefix = f"[{h1}]\n" if h1 else ""
            chunks.append({"type": kind, "text": prefix + content,
                           "heading_path": h1})
    return chunks

DOC = """# 2.3 退款规则
普通商品支持 7 天无理由退款。
| 商品 | 退款期限 | 条件 |
|------|---------|------|
| 生鲜 | 24小时 | 未食用 |
| 电子产品 | 15天 | 包装完好 |
| 定制商品 | 不支持 | - |
| 图书 | 7天 | 无划线 |
详细流程见上文第 2.1 节申请入口。"""

if __name__ == "__main__":
    chunks = chunk_semantic(DOC, table_rows=2)
    table_chunks = [c for c in chunks if c["type"] == "table"]
    assert len(table_chunks) == 2 and table_chunks[1]["text"].startswith("[表: 2.3 退款规则]")
    assert "| 商品 |" in table_chunks[1]["text"]           # 第二块也复制了表头 ✅
    for c in chunks:
        print(f"[{c['type']}] {c['text'][:50]}...")
    print(f"共 {len(chunks)} 块；表格按行组切块且每块带表头与标题链 ✅")
    # 检索口径：大表额外生成「列名:值」文字化摘要块（语义化命中）；
    # 块 ID = hash(heading_path + 正文)，重解析文档时块稳定性可审计。
```

**追问**：1) 为什么「每块复制表头」比「整表一块」对大表更好？——整表超 embedding 窗口被截断（后行的列语义丢失）；行组+表头每块自包含语义完整，检索任意行都带列名；代价是表头 token 重复（可接受）。2) 标题链放正文还是 metadata？——进正文（embedding 能看见，检索「退款」时标题语义加权）优于纯 metadata（metadata 只能过滤不能参与相似度）；两者都存（正文加权 + metadata 过滤）。3) 代码块切分？——按函数/类边界切（AST/正则），每块带签名行；更优的是「代码 + 所在文件路径 + 周边注释」组合块，检索「怎么调用」类问题命中率才高。

## 背诵要点
1. 固定切块破坏表格（丢表头）/代码（丢签名）/条款（丢引用）——版式感知按结构元素切块。
2. 表格：小表整块+摘要，大表行组切块**每块复制表头**，另生成「列名:值」文字化摘要块。
3. 块必须带前置标题链：进正文（参与 embedding）+ 存 metadata（可过滤），检索碎片时消歧。
