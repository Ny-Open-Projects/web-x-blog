### Q7589 · 消息顺序配对破坏事故复盘：tool 消息与 tool_call 断裂

难度：P6/P7 ｜ 标签：事故复盘 / 上下文管理 / 原理深挖

**问**：Agent 上线历史裁剪（超长会话只保留最近 N 条）后，部分请求开始返回 400（如 OpenAI 报 "An assistant message with 'tool_calls' must be followed by tool messages"），另一些会话模型行为错乱、幻觉工具结果。这类"消息顺序配对破坏"事故的根因是什么？怎么系统化防住？

**答**：
- **结论**：根因是违反了工具调用消息的**配对不变量**：`assistant(tool_calls=[...])` 必须紧跟与每个 `tool_call_id` 一一对应的 `tool` 消息，三者是一个不可分割的原子单元。两类典型破坏：① 裁剪/摘要"按条裁"切进配对中间——留了 tool 结果却删了它的 tool_call（provider 直接 400），或反之留 tool_call 删了结果（模型把编造的执行结果当真，产生幻觉）；② 并发写历史交错——两个异步步骤各自 append，tool 结果插进了别的轮次中间。多轮迭代裁剪、上下文压缩、会话迁移都可能触发，而且只在"会话里出现过工具调用"的流量上炸，灰度时容易漏。
- **取舍**：修复方案的取舍：① 裁剪粒度从"条"改成"配对单元"（以 tool_call 为锚点，连同其后所有匹配 tool 消息一起裁），实现简单，覆盖 90% 场景；② 摘要化历史时把已完成的工具轮折叠成一条摘要消息（丢弃 id，只留结论），语义安全但丢失细节；③ 发送前跑不变量校验器（配对完整性 + 顺序合法性），违规即拒发或自动修复——这是兜底闸门，必须有。自动修复有损：补一条占位 tool 消息（"已省略"）能让请求合法，但模型拿到的是假结果，宁可整体回退到更早的安全断点。
- **实战**：落地三件事：① 会话存储按"轮（turn）"而非"条（message）"组织，一轮含 assistant + 其全部 tool 结果，裁剪/迁移以轮为单位；② 发送前校验器常驻网关层，校验失败打点告警而不是静默修复，先止血再查根因；③ 回归测试覆盖三类裁剪场景（纯文本会话、单工具轮、并行多工具轮）各裁到不同深度，断言每个 `tool_call_id` 恰好有一个匹配 tool 消息且位置紧跟。

```python
# 工具调用消息配对不变量：校验 + 按轮裁剪（纯标准库）
# 基线：Python 3.9+（用 list[dict] 泛型需 3.9+）

Msg = dict


def validate(messages: list[Msg]) -> list[str]:
    """返回违规列表；空列表 = 合法。规则：
    1) assistant(tool_calls) 后必须紧跟所有对应 tool 消息
    2) tool 消息前必须是其所属 assistant(tool_calls)
    """
    errs: list[str] = []
    i = 0
    while i < len(messages):
        m = messages[i]
        if m["role"] == "assistant" and m.get("tool_calls"):
            ids = {tc["id"] for tc in m["tool_calls"]}
            j = i + 1
            seen: set[str] = set()
            while j < len(messages) and messages[j]["role"] == "tool":
                tid = messages[j].get("tool_call_id")
                if tid not in ids:
                    errs.append(f"idx{j}: tool 消息 tool_call_id={tid} 无主")
                else:
                    seen.add(tid)
                j += 1
                i = j
            missing = ids - seen
            if missing:
                errs.append(f"idx{i - 1}: tool_call 缺结果 {missing}")
            continue
        if m["role"] == "tool":
            errs.append(f"idx{i}: 孤儿 tool 消息（前面无 tool_call）")
        i += 1
    return errs


def turn_boundaries(messages: list[Msg]) -> list[int]:
    """按'轮'切分：一轮 = assistant(tool_calls) + 其全部 tool 结果，或单条普通消息。
    返回每轮起始下标。"""
    bounds, i, n = [], 0, len(messages)
    while i < n:
        bounds.append(i)
        if messages[i]["role"] == "assistant" and messages[i].get("tool_calls"):
            i += 1
            while i < n and messages[i]["role"] == "tool":
                i += 1
        else:
            i += 1
    return bounds


def trim_to_budget(messages: list[Msg], keep_turns: int) -> list[Msg]:
    """按轮裁剪，保留最近 keep_turns 轮——永不切破配对。"""
    bounds = turn_boundaries(messages)
    safe = bounds[max(0, len(bounds) - keep_turns):][0]
    return messages[safe:]


def main() -> None:
    history = [
        {"role": "user", "content": "查订单"},
        {"role": "assistant", "content": None, "tool_calls":
            [{"id": "c1", "type": "function",
              "function": {"name": "query_order", "arguments": "{}"}}]},
        {"role": "tool", "tool_call_id": "c1", "content": "已发货"},
        {"role": "assistant", "content": "订单已发货"},
        {"role": "user", "content": "再查物流"},
    ]
    assert validate(history) == []

    # 事故场景①：按条裁剪切进配对中间 -> 违规
    bad = history[2:]  # 砍掉了 assistant(tool_calls) 但留下了它的 tool 结果
    errs = validate(bad)
    assert any("孤儿 tool 消息" in e for e in errs), errs

    # 事故场景②：并行双工具只回了一个结果
    bad2 = [
        {"role": "assistant", "tool_calls": [
            {"id": "a", "type": "function", "function": {"name": "f1", "arguments": "{}"}},
            {"id": "b", "type": "function", "function": {"name": "f2", "arguments": "{}"}}]},
        {"role": "tool", "tool_call_id": "a", "content": "ok"},
    ]
    assert any("缺结果" in e for e in validate(bad2))

    # 修复：按轮裁剪，配对完整
    trimmed = trim_to_budget(history, keep_turns=1)
    assert validate(trimmed) == []
    assert trimmed[0]["role"] == "user" and trimmed[0]["content"] == "再查物流"
    print("OK: 校验器 + 按轮裁剪全部通过")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么"补占位 tool 消息"自动修复是有损的？正确的降级姿势是什么？
→ 一句话提示：模型会把占位内容当成真实执行结果继续推理（幻觉源头）；正确做法是校验失败即回退到最近一个合法断点重放，并把违规样本回流到告警，而不是静默编结果。

**追问 2**：并行多工具调用（一次返回多个 tool_call）时，配对不变量比串行多了什么约束？
→ 一句话提示：所有 tool 结果必须紧跟在同一个 assistant 之后连续出现，且每个 tool_call_id 恰好一条——部分供应商还要求 id 顺序无额外要求但绝不允许穿插普通 assistant 消息。

**背诵要点**：
1. 配对不变量：assistant(tool_calls) 与其后所有按 tool_call_id 匹配的 tool 消息构成原子单元，裁剪必须以轮为单位。
2. 破坏后果两极：断在"缺 tool_call"侧 provider 直接 400，断在"缺结果"侧模型编造结果产生幻觉。
3. 防线三层：存储按轮组织 + 发送前校验器（告警不静默）+ 回归测试覆盖单/并行工具轮裁剪。

**复盘追问**：
1. 这起事故为什么灰度没拦住？——提示：只有带工具调用的长会话触发，灰度流量配比不足；裁剪开关要按会话长度分层放量。
2. 校验器放在客户端 SDK 还是网关？——提示：网关层兜底覆盖所有客户端，SDK 层尽早失败省重试成本，双层最稳。
