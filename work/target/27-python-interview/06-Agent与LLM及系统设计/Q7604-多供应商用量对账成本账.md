### Q7604 · 多供应商 LLM 用量对账与计费差异成本账

难度：P6 ｜ 标签：LLM 网关 / 对账 / 成本工程

**问**：平台接了三家模型供应商，月底账单总和比自己按 usage 记录估算的多了 18%。除了"用多了"，差额可能来自哪里？一套可运营的对账体系长什么样？

**答**：
- **结论**：估算与账单的差额来源分四类：① **口径差**——供应商计费的 token 数与自己 tokenizer 估算不同（不同模型不同 tokenizer、缓存 token 单独计价、图像按面积折算 token、思考 token 计入 output）；② **隐藏项**——出网/入网流量费、按并发或优先级计费的加价、SLA 附加费、按请求计的固定费；③ **失败计费**——流式中断但 input token 已计费、超时请求已产出的部分计费；④ **时段与折扣**——批量价（batch 半价）、缓存命中折扣、合约折扣没在估算里体现。对账体系的目标不是"算平"，而是把差额定位到可解释项并限额：月度差额 > 5% 必须归因到具体条目，否则当作计费异常申诉。
- **取舍**：自建计量 vs 供应商 usage API：usage API 是权威但滞后（小时/天级）且有配额，自建计量（网关侧按响应 usage 字段记账）实时但可能与供应商口径漂移——正确组合是自建实时记（预算控制）+ 供应商账单月度对齐（审计），两者差值即口径差系数，按供应商/模型维护一个"口径系数"表用于预算换算。batch 价与实时价混用时，账单粒度必须能区分流量类型，否则对账永远糊。
- **实战**：步骤：① 网关侧按"供应商/模型/流量类型（实时/batch/缓存）/租户"四维记账；② 每月拉供应商 usage API 与账单，按四维分解差额，未归因项进申诉清单；③ 供应商引入/退出前跑"小流量计量校准"（同一测试集在两家打分对比口径）；④ 复盘项：把口径系数表纳入预算模型，避免每个季度重新踩一遍坑。

```python
# 多供应商对账分解器（纯标准库）
# 基线：Python 3.9+


def reconcile(
    self_usage: dict[str, float],     # 自建计量: {model: est_usd}
    vendor_usage: dict[str, float],   # 供应商 usage API: {model: usd}
    vendor_bill: float,               # 供应商最终账单
    calibration: dict[str, float] | None = None,  # 口径系数
) -> dict:
    calib = calibration or {}
    usage_diff, est_total, ven_total = [], 0.0, 0.0
    for m in sorted(set(self_usage) | set(vendor_usage)):
        factor = calib.get(m, 1.0)
        mine = self_usage.get(m, 0.0) * factor
        theirs = vendor_usage.get(m, 0.0)
        est_total += mine
        ven_total += theirs
        if abs(theirs - mine) / max(1e-9, theirs) > 0.05:
            usage_diff.append(f"{m}: 自估{mine:.2f} vs 供应商{theirs:.2f}")
    hidden = vendor_bill - ven_total
    return {"unexplained_model_diff": usage_diff,
            "hidden_fees": round(hidden, 2),
            "total_gap_pct": round(
                (vendor_bill - est_total) / max(1e-9, est_total) * 100, 1)}


def main() -> None:
    mine = {"gpt-x": 1000.0, "glm-x": 500.0}
    vendor = {"gpt-x": 1080.0, "glm-x": 520.0}   # 口径差 8%/4%
    bill = 1720.0                                # 1600 usage + 120 隐藏费
    r = reconcile(mine, vendor, bill,
                  calibration={"gpt-x": 1.08, "glm-x": 1.04})
    print(r)
    # 校准后模型级差额消除，只剩隐藏费
    assert r["unexplained_model_diff"] == []
    assert r["hidden_fees"] == 120.0
    # (1720-1600)/1600 = 7.5%
    assert r["total_gap_pct"] == 7.5
    # 无校准时模型级差额会被暴露
    r2 = reconcile(mine, vendor, bill)
    assert len(r2["unexplained_model_diff"]) == 1
    print("OK: 差额归因到口径差与隐藏费两类")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么"缓存 token"是对账里最容易漏的口径项？
→ 一句话提示：缓存命中部分按折扣价（常 1/10）计费，但 usage 记录与账单的缓存命中统计口径可能不同（是否含缓存写入加价），漏拆会让同模型两份记录差出两位数百分比。

**追问 2**：租户级计费拆分（内部成本分摊）用什么记账键最稳？
→ 一句话提示：网关侧在请求入口注入的 trace/tenant id 必须贯穿到 usage 记账与供应商请求 metadata（若支持）；供应商侧无法回填租户的流量，用"请求序号对账"兜底——记账键设计在接入时决定，事后补很痛苦。

## 背诵要点
- 差额四类：口径差（tokenizer/缓存/图像折算/思考 token）、隐藏费（流量/加价/固定费）、失败计费（流中断 input 已计）、折扣项（batch/缓存）漏算。
- 双轨计量：网关实时记（预算控制）+ 供应商账单月度对齐（审计），差值维护为按模型的"口径系数表"。
- 月度差额 >5% 必须逐条归因，未归因项进申诉；新供应商接入先跑计量校准。

## 复盘追问
- 为什么预算控制要用"口径系数换算后的自建计量"而不是供应商 usage？提示：usage 滞后数小时到数天，预算熔断要实时；系数换算把自建口径对齐到计费口径，熔断阈值才有意义。
- batch 半价流量混在实时账单里会怎样扭曲对账？提示：两档单价差一倍，混合占比变化会伪装成"用量暴涨/暴跌"；流量类型必须作为独立维度记账，占比本身也是一个要监控的成本指标。
