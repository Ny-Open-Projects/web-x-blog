### Q7693 · 长会话压缩与上下文窗口容量账

难度：P6 ｜ 标签：容量规划、上下文窗口、会话压缩、prompt 成本

基线：Python 3.9+；主流窗口 128k~200k token；计费按输入+输出 token。

**问**：客服 agent 支持不限轮次长对话，运营一周后发现大模型费用是预估的 4 倍。拆账发现：每次请求都携带全量历史，第 50 轮时单请求输入已经 6 万 token。这笔"历史膨胀账"怎么算？压缩策略怎么设计才不伤质量？

**答**：
- **结论**：LLM 对话的费用不是"每轮一次问答"，而是**每轮都重付全部历史的输入费**——n 轮会话的累计输入 ≈ Σ(第 i 轮的历史长度)，是 O(n²) 增长。50 轮 × 平均 2 万历史 = 百万 token 级别，这就是 4 倍账单的来源。容量账三个数：单会话成本上限、并发会话数 × 单会话峰值（决定吞吐与配额）、压缩触发点。压缩策略分层：**超过阈值（如窗口 40%）时把"最近 N 轮"之外的历史摘要成卡片**，且摘要用便宜模型跑；工具结果落盘引用句柄（另一卡详述）。
- **取舍**：压缩省的是输入费，花的是"摘要调用费 + 信息损失风险"，所以触发点不能太早（频繁摘要反而更贵也不能太晚（逼近窗口直接截断丢信息）。摘要要用便宜模型（如小模型 1/10 价格），质量靠"结构化模板"兜底：固定字段（用户目标/已确认事实/未决问题），而不是自由摘要。
- **实战**：算式——压缩后单轮输入 = system + 摘要卡片 + 最近 N 轮 ≈ 恒定值（如 4k），会话成本从 O(n²) 变 O(n)；再叠加 prompt 缓存把稳定前缀（system+摘要）的价格打到 1/10（命中时）。

```python
# 会话成本账：全量历史 vs 分层压缩（标准库可运行）。
def session_cost(rounds: int, per_round_tok: int, sys_tok: int,
                 price_in: float) -> float:
    """全量历史：第 i 轮输入 = sys + i*per_round。返回累计输入 token 费。"""
    total_tok = sum(sys_tok + i * per_round_tok for i in range(1, rounds + 1))
    return total_tok * price_in

def session_cost_compressed(rounds: int, per_round_tok: int, sys_tok: int,
                            price_in: float, price_summarize: float,
                            compact_at: int = 12, recent: int = 6) -> float:
    """分层压缩：超过 compact_at 轮时摘要一次（每 10 轮一次），
    之后每轮输入 = sys + 摘要卡片 + 最近 recent 轮，近似恒定。"""
    cost = 0.0
    history = 0
    for i in range(1, rounds + 1):
        if i <= compact_at:
            hist = history
        else:
            hist = recent * per_round_tok
        cost += (sys_tok + hist + per_round_tok) * price_in
        history += per_round_tok
        if i % 10 == 0 and i >= compact_at:
            cost += (history - recent * per_round_tok) * price_summarize
    return cost

if __name__ == "__main__":
    pin, psum = 3.0 / 1e6, 0.6 / 1e6   # 每输入/摘要 token 单价（示意）
    a = session_cost(50, 2000, 800, pin)
    b = session_cost_compressed(50, 2000, 800, pin, psum)
    print(f"全量历史: {a:.3f} 元/会话")
    print(f"分层压缩: {b:.3f} 元/会话  (省 {(1 - b / a):.0%})")
    # 全量: 7.77 元/会话；压缩: 2.32 元/会话（省 70%），
    # 轮数越长差距越大：O(n^2) -> O(n)。
```

**追问**：
- 一层：为什么压缩触发点选"窗口 40%"而不是更早？→ 提示：摘要调用本身有成本，触发太频繁净省为负；且近期对话对质量贡献最大，压缩对象只应是远期历史。
- 二层：prompt 缓存与压缩怎么配合？→ 提示：稳定前缀（system+摘要卡片）保持字节级一致才命中缓存，摘要卡片更新要控制频率（攒批更新），否则缓存命中率归零反而更贵。

**背诵要点**：
1. 长会话费用 O(n²)：每轮重付全部历史输入费；50 轮全量历史是预算 4 倍事故的典型来源。
2. 分层压缩：超阈值把远期历史摘要成结构化卡片（便宜模型），单轮输入近似恒定，O(n²)→O(n)。
3. 触发点权衡：太早摘要费 > 省的钱，太晚逼近截断；配合 prompt 缓存需稳定前缀。

**复盘追问**：
1. 为什么预估差 4 倍没人发现？提示：预估按"单轮成本"而不是"会话累计成本"建模；费控要有按会话的维度。
2. 如果摘要丢了关键事实引发客诉怎么办？提示：关键事实结构化留存（确认订单/金额进卡片字段），摘要只管语境。
