### Q7640 · 幻觉返工与人工兜底的单位成本账

难度：P6 ｜ 标签：成本工程 / 质量工程 / LLM 应用

**问**：LLM 应用做"单位经济账"时，团队只算 token 费，忽略了幻觉带来的隐性成本：错误的输出被客户发现 → 返工 → 人工兜底 → 信任损耗。怎么把"幻觉的下游成本"算进单位经济模型？质量投入（护栏/评测/RAG）的 ROI 怎么算？

**答**：
- **结论**：单位成本要从"token 成本"升级为"**全生命周期质量成本**"：`单位成本 = token成本 + 人工审核摊销 + 幻觉返工成本 + 商誉损失估计`。幻觉返工成本 = `错误率 × 每错误的发现与修复成本（人时 × 时薪 + 延误业务损失）`，这个数字通常比 token 贵 1-2 个数量级（一次 token 调用几分钱，一次返工几十分钟人力）。由此推出质量投入 ROI 的判据：**只要护栏/评测的边际成本 < 它消除的返工成本，就值得投**——典型账：把错误率从 5% 降到 1% 花费"每请求加 0.01 元的 RAG+校验"，而每次返工 20 元，则每千次请求省 800 元、花 10 元，ROI 80 倍。但要警惕两点：① 错误率与错误**代价**要分开——低频高代价错误（合同金额）和高频低代价错误（摘要措辞）需要不同护栏；② 人工兜底本身会形成成本陷阱：兜底比例 30% 意味着自动化只省了 70% 的人力，账里要用"净节省 = 全人工成本 - (自动化成本 + 兜底成本)"，且兜底比例是回归指标——质量退化时兜底比例悄悄上涨吃掉毛利（Q7547 毛利护栏的延伸）。
- **取舍**：护栏加多少层？每层护栏都有成本（延迟、token、误拒率）——误拒（把对的判为错的转人工）也是隐性成本，账要双边算：`护栏净收益 = 拦截的返工成本 - 护栏运行成本 - 误拒增加的人工量`。引用溯源/拒答（Q7523/Q7527）是低成本的"减少高代价幻觉"手段，优先于昂贵的重排/大模型复核。
- **实战**：① 建立"错误登记表"：每个出错的输出记录发现环节（客户/审核/无）、修复人时、延误损失，月度汇总出真实错误成本；② 单位经济报表按"token 成本 vs 兜底成本"分列，兜底占比上涨即质量回归告警；③ 高代价字段（金额/日期/法条）强制结构化校验或人工确认，低代价文本靠抽样质检。

```python
# 幻觉质量成本模型: token 成本 vs 返工成本 vs 护栏 ROI
# 基线: Python 3.9+ 标准库 (数值为演示口径, 元)
from dataclasses import dataclass


@dataclass
class QualityAccount:
    requests_per_month: int
    token_cost_per_req: float
    error_rate: float              # 未护栏错误率
    rework_cost_per_error: float   # 每次返工成本(人时+延误)
    guard_cost_per_req: float      # 护栏(RAG+校验)边际成本
    guard_residual_rate: float     # 护栏后残余错误率

    def monthly(self, with_guard: bool) -> dict:
        err = self.guard_residual_rate if with_guard else self.error_rate
        return {
            "token": self.requests_per_month * self.token_cost_per_req,
            "rework": self.requests_per_month * err
            * self.rework_cost_per_error,
            "guard": self.requests_per_month * self.guard_cost_per_req
            if with_guard else 0.0,
        }

    def guard_roi(self) -> float:
        base = self.monthly(False)
        withg = self.monthly(True)
        saved = base["rework"] - withg["rework"]
        spent = withg["guard"]
        return (saved - spent) / spent


def main() -> None:
    acct = QualityAccount(50_000, 0.02, 0.05, 20.0, 0.01, 0.01)
    base = acct.monthly(False)
    withg = acct.monthly(True)
    assert base["token"] == 1_000 and base["rework"] == 50_000   # 返工是 token 的 50 倍
    assert withg["rework"] == 10_000 and withg["guard"] == 500
    roi = acct.guard_roi()
    assert roi > 50, roi                      # (40000-500)/500 = 79
    # 兜底陷阱: 自动化后 30% 仍转人工 -> 净节省打折
    full_manual = 50_000 * 1.0                # 全人工每请求 1 元
    auto_cost = base["token"] + withg["guard"] + 0.3 * 50_000 * 1.0
    net = full_manual - auto_cost
    assert 0 < net < full_manual              # 兜底比例吃掉部分收益
    print(f"返工成本是 token 的 {base['rework']/base['token']:.0f} 倍; "
          f"护栏 ROI x{roi:.0f}; 兜底30%后净省 {net:.0f}/月")
    print("OK: 单位成本 = token + 返工 + 护栏; 高代价字段强制校验")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么错误率和错误代价必须分开建模？
→ 一句话提示：ROI 由"错误率 × 单次代价"驱动，降高频低代价错误的护栏投资回收慢，降低频高代价错误的护栏哪怕只拦住一单都回本——护栏设计跟随代价分布而非错误率排名。

**追问 2**：误拒（把正确输出转人工）的成本怎么进模型？
→ 一句话提示：护栏净收益 = 拦截返工收益 - 运行成本 - 误拒率 × 人工处理成本；误拒率随护栏阈值收紧而升，最优阈值在边际收益 = 边际误拒成本处。

## 背诵要点
- 单位成本 = token + 人工审核摊销 + 幻觉返工 + 商誉损失；返工成本通常比 token 贵 1-2 个数量级。
- 质量投入判据：护栏边际成本 < 消除的返工成本即投；双边账要含误拒成本，最优阈值在边际收益 = 边际误拒成本。
- 兜底比例是质量回归的先行指标：净节省 = 全人工 - (自动化 + 兜底)，兜底占比上涨吃毛利，做进毛利护栏。

## 复盘追问
- 错误登记表如何设计才能支撑这个模型？提示：字段含发现环节/修复人时/业务延误/字段代价级别，按月汇总出分层的"单错误成本"，才能回答该给哪类错误上护栏。
- 为什么引用溯源/拒答优先于重型护栏？提示：它们针对"高代价编造"（无依据的事实陈述）且成本近零——先消灭最贵的错误类型，再考虑重排/大模型复核等每请求加钱手段。
