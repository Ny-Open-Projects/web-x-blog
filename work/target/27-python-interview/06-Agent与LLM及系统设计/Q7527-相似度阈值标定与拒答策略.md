### Q7527 · RAG 相似度阈值怎么定？低于阈值拒答还是照样生成？

> 难度:★★★★ | 标签:RAG, 评估, 拒答

**问**：RAG 检索得分低于多少算"没找到相关内容"？阈值拍脑袋定 0.75 之后，要么大量误杀（明明有答案却被拒答），要么放进来一堆无关块让模型瞎编。阈值怎么科学标定？

**答**：结论：阈值必须从**标注分布**里标定，不能拍脑袋。方法：抽 300-500 条真实查询，人工标注"证据是否在库"，看命中与不命中两组的检索得分分布——两个分布的交叠区就是"不确定带"，阈值定在"高召回但误杀可控"的分位（先保召回，靠后置 NLI/生成层兜底）。比单阈值更好的是**分级策略**：得分带内"高分直答、中分生成+引用强制、低分拒答或转人工"，因为相似度分数跨查询不可比（不同查询的分布中心不同），固定一刀切必然两头翻车。

机理与实战：
- 分数不可比的根源：embedding 相似度是查询相关而非绝对相关——长查询普遍低分、短语普遍高分。修正手段：per-query 归一（本次 top1 与 top-k 分差、与历史查询分布的分位数对比），把绝对分数变成"相对置信"。z-score/min-max 归一在本库多路召回里已有基础，这里同理。
- 分级阈值工程：`高分(≥P85 of 命中分布) → 直答；中分 → 生成但强制引用 + NLI 校验；低分(≤P30) → 拒答/澄清提问`。拒答时最好给"澄清式"输出（"知识库只有 XX 方面的资料，你问的是这个吗"），把拒答变成交互而不是死胡同。
- 阈值会过期：换 embedding 模型、语料结构变化后分布整体漂移，标定必须可重复——把标注集 + 标定脚本（算分位阈值）做成流水线任务，模型换版时重跑。这是 Q7518 embedding 迁移路线的一环。

```python
# 基线:Python 3.9+ 纯标准库 ;演示分布标定与分级策略
import random
from bisect import bisect_left


def percentile(sorted_vals: list[float], p: float) -> float:
    """线性插值分位数。"""
    if not sorted_vals:
        return 0.0
    k = (len(sorted_vals) - 1) * p
    f, c = int(k), min(int(k) + 1, len(sorted_vals) - 1)
    return sorted_vals[f] + (sorted_vals[c] - sorted_vals[f]) * (k - f)


def calibrate(hit_scores: list[float], miss_scores: list[float]):
    """从标注分布标定分级阈值:低分线=miss 的 P70,高分线=hit 的 P15。"""
    h, m = sorted(hit_scores), sorted(miss_scores)
    return {
        "reject_below": percentile(m, 0.70),   # miss 分布上 30% 与 hit 重叠带以下
        "confident_above": percentile(h, 0.15),
    }


def route(score: float, th: dict) -> str:
    if score >= th["confident_above"]:
        return "直答(高分)"
    if score <= th["reject_below"]:
        return "拒答/澄清提问"
    return "生成+强制引用+NLI 校验"


def main() -> None:
    random.seed(7)
    # 模拟标注结果:命中查询分数高且离散,未命中分数低但有重叠尾部
    hits = [random.gauss(0.85, 0.06) for _ in range(400)]
    miss = [random.gauss(0.55, 0.10) for _ in range(400)]
    th = calibrate(hits, miss)
    print(f"标定阈值: 拒答线 {th['reject_below']:.2f} / 高分线 {th['confident_above']:.2f}")
    for s in (0.90, 0.72, 0.40):
        print(f"得分 {s:.2f} -> {route(s, th)}")


if __name__ == "__main__":
    main()
```

**追问一**：为什么不用 top1 与其他候选的分差（margin）替代绝对阈值？
答：margin 反映"查询意图的尖锐程度"——top1 明显领先说明意图明确，全体分数平坦说明查询含糊或库里没对口内容。实践常用组合特征（绝对分位 + margin + 命中数），比单一绝对阈值稳健得多；再往上就是训一个轻量的"可回答性"分类器（特征即这些检索信号）。

**追问二**：标定集的 500 条怎么维护？
答：从线上查询按周期抽样 + badcase 回流补充（被拒答但用户明确说"库里有"的案例是标定集里最值钱的负样本）。标定集要冻结标注口径（"证据在库"的定义），两人独立标注做一致性检查（kappa），否则阈值随标注者漂移。

**背诵要点**：
- 阈值来自标注分布的分位（命中/未命中分布的交叠带），不是拍脑袋数字。
- 相似度分数跨查询不可比，分级策略 + margin/分位组合优于单阈值。
- 换 embedding 模型/语料变更后必须重跑标定流水线，阈值会过期。
