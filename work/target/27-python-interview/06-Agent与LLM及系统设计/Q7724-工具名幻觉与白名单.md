### Q7724 · 模型调了一个不存在的工具：白名单与纠错边界

难度：P6 ｜ 标签：function calling、工具名幻觉、白名单

基线：Python 3.12；OpenAI/Anthropic tool use；纯 Python 模拟注册表与路由。

**问**：Agent 注册了 40 多个工具，偶发模型返回 `tool_calls` 里 `name="get_weather_forecast"`，而注册表里只有 `get_weather`，直接 `dispatch` 抛 `KeyError`，整轮任务失败。有时名字只差一个字母，模糊匹配能"猜"对；有时却猜到了另一个高危工具。工具名幻觉该怎么防？能不能自动纠错？

**答**：
- **结论**：模型输出的是**自由文本里的工具名**，即使 API 层把工具名做成枚举，模型仍可能拼错、缩写、编造相似名（工具越多、名字越像，概率越高）。正确做法是**白名单硬校验**：`name not in registry` 一律不执行，把"未知工具 + 可用工具列表"作为错误结果回给模型，让它重试或改走已知工具。模糊纠错只能用于**低风险、只读、参数可验证**的工具，且必须记录纠正事件。
- **取舍**：严格拒绝最安全，但会增加一轮重试、拉高延迟；自动纠错体验好，却可能把 `delete_user` 猜到 `delete_users`（批量删除）这类高危变体，造成越权/误删。折中：只读工具允许"唯一候选 + 相似度阈值"纠正；写操作/高权限工具绝不自动纠正，必须显式确认。
- **实战**：① 工具名用**命名空间前缀**（`crm_get_user`、`billing_refund`）降低相似度；② 注册表按租户/场景裁剪，别一次暴露 40 个工具；③ 校验失败返回结构化错误（`unknown_tool` + `available_tools`），让模型自我修正；④ 监控"未知工具率"，突增说明 prompt/schema 或模型版本有问题。

```python
"""工具名白名单：精确匹配、候选提示、只读工具的唯一模糊纠正。"""
from difflib import get_close_matches


READ_ONLY = {"get_weather", "search_docs", "get_user"}
WRITE = {"refund_order", "delete_user"}


def dispatch(name: str, args: dict, registry: dict) -> dict:
    if name in registry:
        return {"ok": True, "tool": name, "result": registry[name](**args)}

    candidates = get_close_matches(name, registry.keys(), n=2, cutoff=0.8)
    # 只有"只读 + 唯一候选"才允许纠正
    if len(candidates) == 1 and candidates[0] in READ_ONLY:
        target = candidates[0]
        return {"ok": True, "tool": target, "corrected_from": name,
                "result": registry[target](**args)}

    return {"ok": False, "error": "unknown_tool", "requested": name,
            "candidates": candidates, "available": sorted(registry)}


if __name__ == "__main__":
    registry = {
        "get_weather": lambda city: f"{city}: 晴 26C",
        "search_docs": lambda q: f"docs about {q}",
        "refund_order": lambda order_id: f"refunded {order_id}",
    }

    print(dispatch("get_weather", {"city": "上海"}, registry))
    print(dispatch("get_wether", {"city": "上海"}, registry))       # 只读，可纠正
    print(dispatch("refund_ordre", {"order_id": "A1"}, registry))   # 写操作，拒绝纠正
    print(dispatch("delete_user", {"user_id": 1}, registry))        # 不存在，拒绝
    print("结论：未知工具一律不执行；写操作不做模糊纠错")
```

**追问一**：为什么模型会"编造"工具名，而不是直接用注册表里的？
→ 解析：模型看到的是 prompt 里的工具描述文本，不是强类型枚举；当工具数量多、名字相似、描述重叠时，它会把训练中见过的通用名（`get_weather_forecast`）和当前工具混淆。工具描述太长被截断、schema 与自然语言指令冲突也会提高幻觉率。

**追问二**：把工具名做成 JSON Schema 的 `enum` 能彻底解决吗？
→ 解析：能降低概率但不能根治。部分 provider 的 strict 模式会约束输出结构，但模型仍可能在 `name` 字段填一个"看起来合法"的值；不同 provider/版本对 enum 的强制程度不一致，流式拼接也可能产生半截名字。服务端白名单校验仍是最后一道闸，不能省。
