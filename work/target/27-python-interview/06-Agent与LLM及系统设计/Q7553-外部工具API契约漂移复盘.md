### Q7553 · 外部工具 API 契约漂移的事故复盘

难度：P6 | 标签：工具调用、契约漂移、容错解析、熔断

**问**：天气查询工具的供应商某天改了返回结构（`temp_c` 变成 `current.temp`），Agent 一夜之间从"报天气"变成"编天气"。契约漂移为什么会让 LLM 幻觉？容错解析和熔断怎么设计？

**答**：
- **结论**：契约漂移的杀伤链是：解析层 KeyError → 工具层返回错误信息 → 模型把"解析失败的空结果"当成"工具说没有数据"，用参数知识编一个温度——错误的根因在解析层，症状却是幻觉。三层防御：① 容错解析（adapter 链）：按已知形态逐个尝试，覆盖 v1/v2 结构，未知形态显式抛"schema drifted"而不是裸 KeyError；② 违约计数熔断：未知形态出现率突增（如 10 分钟内 3 次）即熔断该工具并告警——先钉住旧版本/切备用供应商，别让模型继续在未知结构上裸奔；③ 契约回归：录制供应商真实响应做固定样例集，每次发版前重放。
- **取舍**：adapter 链会积累"历史形态兼容代码"，正确的退出机制是供应商提供 schema 版本头（响应里带 `schema_version`）→ 按版本路由 adapter → 旧版本下线后删对应 adapter。没有版本头的供应商，就用"探测 + 记账"的容错解析顶着，同时把"供应商必须带版本头"写进采购要求。
- **实战**：落地清单：① 每个外部工具定义响应 schema（pydantic/json schema）与两种以上已知形态的 adapter；② 解析失败进入"违约账本"（时间、原始响应样本），供复盘取证；③ 熔断后工具返回结构化错误给模型："该工具暂不可用"，禁止模型自由发挥。

```python
"""外部工具 API 契约漂移事故：返回结构静默变化、容错解析与违约熔断。"""
from dataclasses import dataclass, field

def tool_v1(city: str) -> dict:
    return {"temp_c": 28.5, "city": city}                 # 老契约

def tool_v2(city: str) -> dict:                           # 供应商静默改版
    return {"current": {"temp": 28.5, "unit": "C"}, "city": city}

def strict_parse(resp: dict) -> float:
    return resp["temp_c"]                                  # 契约漂移后 KeyError

@dataclass
class TolerantParser:
    violations: int = 0
    trip_at: int = 3
    adapters: tuple = field(default=(
        lambda r: float(r["temp_c"]),
        lambda r: float(r["current"]["temp"]),
    ))

    def parse(self, resp: dict) -> float:
        for a in self.adapters:                            # 逐个适配已知形态
            try:
                return a(resp)
            except (KeyError, TypeError, ValueError):
                continue
        self.violations += 1                               # 未知形态：记账
        raise ValueError("tool response schema drifted")

parser = TolerantParser()
print("严格解析 v2 响应：", end="")
try:
    strict_parse(tool_v2("hangzhou"))
except KeyError as e:
    print(f"KeyError: {e} —— agent 循环拿不到温度，开始幻觉编数")

print(f"容错解析 v1: {parser.parse(tool_v1('hangzhou'))}°C, "
      f"v2: {parser.parse(tool_v2('hangzhou'))}°C")
print(f"契约校验失败计数 = {parser.violations}（熔断阈值 {parser.trip_at}）")
print("治理：录制契约样例做固定回归；响应带 schema 版本头；"
      "违约率突增触发熔断+告警，先钉版本再排迁移，绝不让模型裸奔在未知结构上")
```

**追问链**：
1. 追问一层：为什么模型会把解析失败"翻译"成幻觉？——工具返回的错误文本（"KeyError: temp_c"）对模型是上下文的一部分；多数模型会把"工具没给出数据"理解为"数据不存在"，于是用先验知识补全。对策除了容错解析，还包括给模型的结构化错误语义（"工具不可用，请告知用户稍后再试"），把失败意图显式化。
2. 追问二层：熔断后"拒绝服务"与"降级到缓存数据"怎么选？——天气这类时效数据，降级给缓存等于给模型喂假数据（昨天的温度当今天的报），比拒绝更危险；可缓存的低时效工具（文档检索）才允许降级。原则：数据时效性决定熔断后的策略。

**背诵要点**：
1. 契约漂移的杀伤链：解析 KeyError → 模型把"无数据"编成幻觉——根因在解析层。
2. 防御三件套：adapter 链容错解析 + 违约计数熔断 + 录制样例契约回归。
3. 熔断后策略按时效性定：高时效工具拒绝服务，低时效才可降级缓存。

**复盘追问**：
1. 为什么这类事故总是用户先发现？（解析失败被静默吞掉、模型输出了"看起来合理"的编造值，链路指标全绿；幻觉检测和黄金集回归才能发现语义层损坏）
2. 复盘时怎么证明是契约漂移而不是模型退化？（违约账本里的原始响应样本与旧契约 diff——根因取证在数据层，不在模型层；这也是"解析失败必须留样"的理由）
