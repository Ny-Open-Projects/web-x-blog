### Q7650 · 工具调用参数幻觉（编造 ID）复盘

难度：P6-P7 | 标签：Function Calling、事故复盘、参数校验

**问**：Agent 在查订单工具时，模型编造了一个不存在的 `order_id`，下游返回空结果，Agent 又基于空结果编了结论回复用户。参数幻觉为什么发生？如何在执行前拦截、执行后纠正？

**答**：结论：参数幻觉的根源是模型把"生成一个格式正确的 ID"当成任务目标，而不是"取一个真实存在的 ID"——ID 类参数对模型是**必须从上下文引用的实体**，上下文里没有它就靠先验拼一个。拦截与纠正要形成闭环：① 工具 schema 上把 ID 声明为受约束来源（enum 或引用前序工具输出的字段），② 执行前做**存在性校验**（查库/查缓存），失败时把校验错误结构化喂回去让模型重新选参，③ 空结果不算答案——工具结果为空必须显式声明"未找到"，禁止模型补全。

实战要点：
1. 上下文里放"候选实体列表"：会话中先跑一次轻量检索把真实 ID 列表注入上下文，模型从中选而不是凭空生成。
2. 校验失败回环要限次：同一参数幻觉重试 ≤2 次，超限转人工/降级，防止 Q7618 式循环消耗。
3. 观测：按工具维度统计"参数校验失败率"，突增通常意味着上下文窗口被裁剪掉了实体列表（Q7645）。

```python
"""参数幻觉拦截闭环：存在性校验 + 结构化纠错（标准库，可运行）"""
from dataclasses import dataclass, field

KNOWN_ORDER_IDS = {"ORD-1001", "ORD-1002", "ORD-1007"}
MAX_PARAM_RETRIES = 2


@dataclass
class ToolCall:
    name: str
    args: dict


@dataclass
class AgentLoop:
    retries: int = 0
    history: list[str] = field(default_factory=list)

    def validate(self, call: ToolCall) -> str | None:
        """返回纠错信息，None 表示通过"""
        oid = call.args.get("order_id", "")
        if not oid.startswith("ORD-"):
            return "order_id 格式非法，必须以 ORD- 开头"
        if oid not in KNOWN_ORDER_IDS:
            self.retries += 1
            if self.retries > MAX_PARAM_RETRIES:
                return "HUMAN_HANDOFF"  # 超限转人工
            return (f"order_id {oid} 不存在。可用 ID: "
                    f"{sorted(KNOWN_ORDER_IDS)}，请重新选择")
        return None

    def run(self, call: ToolCall) -> str:
        err = self.validate(call)
        if err:
            self.history.append(f"rejected: {err}")
            if err == "HUMAN_HANDOFF":
                return err
            return f"model re-choose params (retry {self.retries})"
        return f"executed {call.name} -> found order"


loop = AgentLoop()
print(loop.run(ToolCall("get_order", {"order_id": "ORD-9999"})))
print(loop.run(ToolCall("get_order", {"order_id": "ORD-1002"})))

def summarize(tool_result: list[dict]) -> str:
    if not tool_result:
        return "查询无结果：未找到该订单（不编造结论）"
    return f"共 {len(tool_result)} 条结果"

print(summarize([]))
```

**追问 1**：为什么"返回空结果让模型自己判断"不够？
**提示**：模型倾向对空结果脑补解释（"可能已删除"），把空当结论；必须由框架强制"空=未找到"语义并阻断结论生成。

**追问 2**：enum 全集太大（百万订单 ID）没法枚举怎么办？
**提示**：改两段式——先搜后取：第一步工具返回 top-K 候选（分页），第二步只在候选内取，等于把校验前移进检索层。

## 背诵要点
- ID 类参数是"上下文引用"不是"格式生成"，无候选列表必幻觉。
- 闭环三件套：schema 约束来源、执行前存在性校验、校验错误结构化回喂，限次 ≤2 后转人工。
- 工具空结果必须映射为"未找到"，禁止模型补全结论。
