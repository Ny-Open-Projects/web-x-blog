### Q7801 · ANN 召回率评测：为什么用索引自己的结果当基准会虚高

难度：P7 ｜ 标签：RAG、ANN、recall@k、ground truth、向量索引评测

基线：库知识库外知识卡，用纯 Python 的暴力 kNN 与"候选裁剪"模拟 HNSW/IVF 的近似检索，计算真实 recall@10 与自参照评测的差异。

**问**：团队给向量索引做评测，HNSW 配置 A 的 recall@10 是 0.98，配置 B 是 0.96，于是选了 A。上线后用户投诉"明明有答案却搜不到"，人工抽了 200 条 query，发现 A 的真实召回只有 0.71。0.98 是怎么算出来的？为什么"用 A 的结果当基准"会得到接近 1 的召回？评测集和 ground truth 到底该怎么建？

**答**：

- **结论**：那 0.98 很可能是**自参照评测**：把索引 A 返回的 top-10 存成"标准答案"，再拿 A 去比，重合率当然接近 1；或者用另一个近似索引 B 的结果当基准，两个索引共享同样的漏召回模式，互相"对答案"也会虚高。**ANN 的 recall@k 必须相对暴力检索（exact kNN）计算**：`|ANN_topk ∩ brute_topk| / k`。没有精确基准，任何"召回率"都只是两个近似器之间的一致性。
- **取舍**：① 全量暴力基准：最准，但 1200 万 × 1200 万不可行，通常只对**评测集的 query** 做暴力检索（query 数量有限，可承受）；② 采样基准：对每个 query 在候选池内暴力，候选池要足够大且不含索引剪枝偏差；③ 跨索引对比：A vs B 的重合率只能说明"两者像不像"，不能说明"谁更接近真实"；④ 人工标注：成本最高，适合校准小样本，但不能替代 recall 的几何定义。
- **实战**：① 评测流水线固定"暴力 kNN 生成 ground truth"这一步，索引参数只影响被测侧；② 评测集按 query 类型分层（短查询/长查询/多语言/带过滤），分别算 recall；③ 同时看 recall@10 与 recall@100，前者影响答案，后者影响 rerank 候选；④ 每次改索引参数/embedding 版本都重跑同一套 ground truth，避免"基准随模型漂移"。

下面用 400 个 6 维点：暴力 kNN 作为真值，候选裁剪模拟 ANN，比较真实召回与自参照召回。

```python
# ANN recall 必须相对暴力 kNN; 自参照评测恒为 1.0
import math
import random


random.seed(0)
N, DIM, K = 400, 6, 10
pts = [[random.gauss(0, 1) for _ in range(DIM)] for _ in range(N)]


def dist(a, b):
    return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))


def brute_knn(i, k=K):
    order = sorted((j for j in range(N) if j != i), key=lambda j: dist(pts[i], pts[j]))
    return order[:k]


def ann_knn(i, k=K, keep=0.55):
    # 模拟图/倒排只访问一部分候选, 其余被剪枝
    cand = [j for j in range(N) if j != i and (j * 37 + i * 11) % 100 < keep * 100]
    cand.sort(key=lambda j: dist(pts[i], pts[j]))
    return cand[:k]


truth = {i: brute_knn(i) for i in range(N)}
pred = {i: ann_knn(i) for i in range(N)}

true_recall = sum(len(set(truth[i]) & set(pred[i])) / K for i in range(N)) / N
self_recall = sum(len(set(pred[i]) & set(pred[i])) / K for i in range(N)) / N
print(f"[1] 真实 recall@10 (相对暴力)={true_recall:.2f}")
print(f"[2] 自参照 recall@10 (相对自己)={self_recall:.2f}")
assert 0.4 < true_recall < 0.8
assert self_recall == 1.0
print("    → 实测 自参照评测恒为 1.0, 不能反映漏召回")

# 两个近似索引互相对答案: 重合率高但不代表接近真值
def ann_b(i, k=K, keep=0.55):
    cand = [j for j in range(N) if j != i and (j * 37 + i * 11) % 100 < keep * 100]
    cand.sort(key=lambda j: dist(pts[i], pts[j]))
    return cand[:k]


cross = sum(len(set(pred[i]) & set(ann_b(i))) / K for i in range(N)) / N
print(f"[3] A vs B 的重合率={cross:.2f} (同一个剪枝模式, 互相印证但都漏)")
assert cross == 1.0

# rerank 候选窗(100)的召回也要单独看, 不能只报 top-10
def recall_at(kk, keep):
    t = {i: brute_knn(i, kk) for i in range(N)}
    p = {i: ann_knn(i, kk, keep) for i in range(N)}
    return sum(len(set(t[i]) & set(p[i])) / kk for i in range(N)) / N


r10, r100 = recall_at(10, 0.55), recall_at(100, 0.55)
print(f"[4] recall@10={r10:.2f}, recall@100={r100:.2f}")
assert abs(r10 - r100) < 0.15
print("    → 实测 rerank 候选窗(100)的召回也要单独看, 不能只报 top-10")
```

**追问一**：评测集只有 500 条 query，暴力检索够吗？—— 够。暴力检索的复杂度是 `O(Q × N × d)`，500 × 1200 万 × 768 在 GPU/多线程下可接受（分钟级），而且只需离线跑一次。真正不可行的是"对所有可能的 query"做暴力，不是对固定的评测集。把 ground truth 缓存下来，后续只跑被测索引。

**追问二**：为什么 recall@10 和 recall@100 要分开看？—— top-10 决定最终给 LLM 的上下文，recall@10 低直接导致"答案不在上下文"；top-100 是 rerank 的候选池，recall@100 低意味着 rerank 再强也救不回来。两者优化手段不同：前者调 `ef_search`/`nprobe`，后者调候选窗大小与索引类型。

## 背诵要点

- ANN 的 recall@k 必须相对**暴力 kNN** 计算：`|ANN ∩ brute| / k`；自参照或 ANN 对 ANN 都会虚高。
- ground truth 只需对固定评测集暴力跑一次并缓存；query 分层、recall@10 与 recall@100 分开报。
- 改索引参数/embedding 版本要重跑同一套 ground truth，否则基准漂移。
