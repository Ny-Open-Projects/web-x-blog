### Q7607 · 评测集泄漏与指标虚高事故复盘

难度：P7 ｜ 标签：Agent 评估 / 数据泄漏 / 事故复盘

**问**：RAG 系统迭代半年，评测集上的准确率从 62% 一路涨到 91%，上线后用户满意度却没变，甚至有指标回归的投诉。排查发现：内部评测集的很多问题就是从真实用户 FAQ 里抽的，而这些 FAQ 原文全在被检索的文档库里。指标是怎么虚高的？怎么重建可信评测？

**答**：
- **结论**：这是评测集污染（contamination）的经典形态：评测问题的答案文本与检索语料逐字重合，检索器只要"背出原文"就能命中，评测测的是"语料里有没有这段文字"，不是"系统会不会回答"。泄漏路径通常有三条：① 评测集直接从被索引文档生成/抽取；② 迭代过程中用评测集调优（试 prompt、调分块参数都是隐性训练）；③ 评测集长期不更新，被历次迭代"耗尽"。指标虚高的识别信号：线上指标与评测指标背离、评测分数对分块/prompt 参数异常敏感（说明在过拟合评测集）、同一模型在评测集上的表现远超人工抽检结果。
- **取舍**：重建评测的三层设计：① **隔离**——评测问题人工改写（不与语料逐字重合），或从"语料发布之后新增的用户问题"里收集（时间切分天然防泄漏）；② **分层**—— held-out 集只用于最终验收、调优集可日常使用、冒烟集进 CI，三者不重叠；③ **换血**——评测集按月轮换 20-30%，旧题退役（防耗尽）。另一个取舍：完全人工标注贵、合成评测便宜但自带分布偏差——合成题必须经过"去重合改写 + 人工抽检"两道工序才可用。
- **实战**：事故剧本：① 量化污染：对每道评测题计算与语料的 n-gram 重合率，重合率高的题剔除；② 重建分层评测集并冻结 held-out 集（只做季度验收）；③ 建立评测指标与线上指标的"背离告警"（评测涨而线上 NPS/采纳率不动即触发审查）；④ 复盘项：把"评测集管理"（来源、改写工序、轮换节奏）写成文档并纳入评审，评测集本身就是需要治理的数据资产。

```python
# 评测集污染度检测器（纯标准库）
# 基线：Python 3.9+


def ngrams(text: str, n: int = 8) -> set[str]:
    """字符级 n-gram（中文场景实用；生产可用词级/jieba 分词）"""
    text = "".join(text.split())
    return {text[i:i + n] for i in range(max(0, len(text) - n + 1))}


def contamination_rate(question: str, corpus: list[str],
                       n: int = 8) -> float:
    """问题 n-gram 在语料中的命中率 = 污染度"""
    qg = ngrams(question, n)
    if not qg:
        return 0.0
    hit = set()
    for doc in corpus:
        dg = ngrams(doc, n)
        hit |= qg & dg
    return len(hit) / len(qg)


def audit(questions: list[str], corpus: list[str],
          threshold: float = 0.5) -> dict:
    """返回污染题清单与整体污染占比"""
    contaminated = []
    for q in questions:
        rate = contamination_rate(q, corpus)
        if rate >= threshold:
            contaminated.append((q[:20], round(rate, 2)))
    return {"contaminated": contaminated,
            "pct": round(len(contaminated) / len(questions) * 100, 1)}


def main() -> None:
    corpus = [
        "退款政策：购买后 7 天内未使用可全额退款，需在订单详情页申请。",
        "会员权益：黄金会员每月赠送 5 张加速券。",
    ]
    # 污染题：逐字抄语料（含长片段重合）
    leaked = "请问7天内未使用可全额退款，需在订单详情页申请，对吗？"
    # 干净题：人工改写，无长片段重合
    clean = "我买完东西后悔了，钱怎么退回来？"
    leaked_rate = contamination_rate(leaked, corpus)
    clean_rate = contamination_rate(clean, corpus)
    print(f"污染题重合率 {leaked_rate:.2f} / 干净题 {clean_rate:.2f}")
    assert leaked_rate >= 0.5
    assert clean_rate < 0.5
    print("OK: n-gram 重合率可定位逐字泄漏题")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么"用评测集调参"算隐性训练，边界怎么划？
→ 一句话提示：任何"看了评测分数后修改系统并保留改动"的循环都在向评测集过拟合；边界是——调优集可以随便看，held-out 集只在最终验收时解锁且不可基于其结果回改系统，解锁后该集退役换新。

**追问 2**：LLM 合成评测题有哪些系统性偏差？
→ 一句话提示：合成题偏向模型已掌握的表述方式与事实（自我同构）、难度分布中庸、覆盖长尾不足；且与训练分布重合会造成"模型自己考自己"的虚高——合成必须配合人工改写与抽检。

## 背诵要点
- 泄漏三路径：评测题源自被索引语料、用评测集迭代调参、评测集长期不换血；污染度可用 n-gram 重合率量化。
- 重建三层：隔离（改写/时间切分）、分层（调优集/冒烟集/held-out 三分离）、换血（月轮换 20-30%）。
- 背离告警：评测涨而线上采纳率/NPS 不动即审查；评测集是需要治理的数据资产，要有来源与轮换文档。

## 复盘追问
- 为什么 held-out 集解锁一次就要退役？提示：一次解锁的信息就永久进入团队决策记忆，无法"遗忘"，复用必然带偏；-heldout 是消耗品，稀缺性才是它的价值。
- 检索评测（命中率）和端到端评测（答案正确率）哪个更容易被污染掩盖？提示：检索评测最容易被逐字重合刷高（背原文即命中），端到端评测因要经过生成环节反而能暴露部分污染；但只有线上指标才能定案——三层都要有，单层不可信。
