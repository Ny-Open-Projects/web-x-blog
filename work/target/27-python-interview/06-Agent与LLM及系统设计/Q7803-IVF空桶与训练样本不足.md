### Q7803 · IVF 的空桶：训练样本不足为什么让召回塌掉

难度：P7 ｜ 标签：RAG、IVF、nlist、nprobe、聚类、召回率

基线：库知识库外知识卡，用纯 Python 的 k-means 聚类模拟 IVF 的倒排桶与 nprobe 探测，统计桶倾斜与 recall@10。

**问**：1200 万条向量建 IVF 索引，`nlist=4096`，但训练时只采样了 2 万条（不到 0.2%）。上线后 recall@10 只有 0.52，把 `nprobe` 从 8 调到 64 才回到 0.88，延迟翻了 7 倍。训练样本不足为什么会影响查询召回？`nlist` 和 `nprobe` 该怎么定？桶倾斜（一个桶几十万条、另一个桶几百条）是怎么来的？

**答**：

- **结论**：IVF 先用 k-means 把向量空间切成 `nlist` 个桶，查询时只探测离 query 最近的 `nprobe` 个桶。**桶的质量取决于训练样本**：样本太少/不代表性时，k-means 只能粗略划分，出现大量空桶和少数巨型桶；查询落在一个"边界模糊"的区域时，真实近邻可能被分到相邻桶，而 `nprobe` 不够就漏掉。表现是召回低、把 `nprobe` 调大才恢复，但延迟线性上升。经验规则：训练样本至少 `几十 × nlist`（常见 30~100 倍），且要覆盖真实分布（不能只采热门类目）。
- **取舍**：① 增大训练样本：召回更稳，代价是建索引时间/内存；② 减小 `nlist`：每桶更大、边界更少，`nprobe` 小也能覆盖，但单桶扫描变慢；③ 增大 `nprobe`：直接提召回，代价是延迟线性增长；④ 换 HNSW：对训练样本不敏感，但内存/构建成本更高；⑤ 分片/多索引：按租户/类目切，降低单索引的分布复杂度。
- **实战**：① 训练样本按 `30 × nlist` 起步（如 4096 桶 → 12 万+），并从全量随机采样而非只取最近数据；② 建完索引统计桶大小分布，`max/median > 10` 或空桶 > 5% 就要重训；③ `nprobe` 用评测集画"召回-延迟"曲线，取拐点而不是拍脑袋；④ 监控查询落在空桶/巨型桶的比例，作为索引健康度指标。

下面用 k-means 模拟：少量训练样本导致空桶，nprobe=1 与 nprobe=4 的召回差异。

```python
# IVF: k-means 分桶 + 只探测最近 nprobe 个桶
import math
import random


random.seed(3)
DIM, K, PER = 2, 8, 60
centers = [(10 * math.cos(2 * math.pi * i / K), 10 * math.sin(2 * math.pi * i / K))
           for i in range(K)]
points = [(cx + random.gauss(0, 1.2), cy + random.gauss(0, 1.2))
          for cx, cy in centers for _ in range(PER)]


def dist(a, b):
    return math.hypot(a[0] - b[0], a[1] - b[1])


def kmeans(data, k, iters=20):
    cents = [random.choice(data)]
    while len(cents) < k:                     # k-means++ 初始化
        d2 = [min(dist(p, c) ** 2 for c in cents) for p in data]
        total = sum(d2)
        if total == 0:
            cents.append(random.choice(data))
            continue
        r, acc = random.random() * total, 0.0
        for p, w in zip(data, d2):
            acc += w
            if acc >= r:
                cents.append(p)
                break
    for _ in range(iters):
        buckets = [[] for _ in range(k)]
        for p in data:
            idx = min(range(k), key=lambda i: dist(p, cents[i]))
            buckets[idx].append(p)
        for i, b in enumerate(buckets):
            if b:
                cents[i] = (sum(p[0] for p in b) / len(b), sum(p[1] for p in b) / len(b))
    return cents


# 1) 训练样本不足: 64 个桶只给 20 个样本
tiny = random.sample(points, 20)
cents_tiny = kmeans(tiny, 64, iters=3)
counts = [0] * 64
for p in tiny:
    counts[min(range(64), key=lambda i: dist(p, cents_tiny[i]))] += 1
empty = sum(1 for c in counts if c == 0)
print(f"[1] nlist=64, 训练样本=20: 空桶={empty}")
assert empty >= 44
print("    → 实测 样本少于桶数, 大量桶没有中心, 查询只能落到少数巨型桶")

# 2) 充足样本: 8 个桶用 480 个点训练
cents = kmeans(points, K)
assign, sizes = [], [0] * K
for p in points:
    idx = min(range(K), key=lambda i: dist(p, cents[i]))
    assign.append(idx)
    sizes[idx] += 1
print(f"[2] nlist=8, 充足样本: 桶大小={sizes}, max/min={max(sizes) / max(1, min(sizes)):.1f}")
assert max(sizes) / min(sizes) < 1.5


# 3) nprobe 对边界查询的影响
def brute_query(q, k=10):
    order = sorted(range(len(points)), key=lambda j: dist(q, points[j]))
    return set(order[:k])


def ivf_query(q, nprobe, k=10):
    buckets = sorted(range(K), key=lambda c: dist(q, cents[c]))[:nprobe]
    cand = [j for j in range(len(points)) if assign[j] in buckets]
    cand.sort(key=lambda j: dist(q, points[j]))
    return set(cand[:k])


boundary = [((centers[i][0] + centers[(i + 1) % K][0]) / 2,
             (centers[i][1] + centers[(i + 1) % K][1]) / 2) for i in range(K)]
res = {}
for np in (1, 2, 4):
    res[np] = sum(len(brute_query(q) & ivf_query(q, np)) / 10 for q in boundary) / len(boundary)
    print(f"[3] nprobe={np}: 边界 query recall@10={res[np]:.2f}")
assert res[1] < res[4]
print("    → 实测 nprobe 从 1 提到 4, 召回上升; 但延迟也随探测桶数线性增加")
```

**追问一**：`nlist` 越大越好吗？—— 不是。`nlist` 大意味着桶更细、理论上候选更少、扫描更快，但每个桶的训练样本更少、边界更多，`nprobe` 必须跟着增大才能保住召回，延迟未必降。经验上 `nlist ≈ sqrt(N)` 起步（1200 万 → 约 3500），再用评测调 `nprobe`；桶太小还会让倒排元数据占比上升。

**追问二**：为什么"训练样本只取最近 30 天"会伤召回？—— IVF 的桶是**全局空间划分**，只取最近数据会让老数据/长尾类目落在未训练的空白区域，查询这些区域时最近桶可能完全不相邻。采样要覆盖全量分布（按类目/租户分层），而不是按时间便利采样。冷启动阶段尤其容易犯这个错。

## 背诵要点

- IVF 的桶由 k-means 训练样本决定；样本不足会产生大量空桶/巨型桶，真实近邻被分到未探测的桶，召回塌掉。
- 训练样本按 `30~100 × nlist` 起步、分层覆盖真实分布；`nlist ≈ sqrt(N)` 起步，`nprobe` 用召回-延迟曲线取拐点。
- 健康度：空桶 >5%、`max/median >10` 就要重训；监控查询落在空桶/巨型桶的比例。
