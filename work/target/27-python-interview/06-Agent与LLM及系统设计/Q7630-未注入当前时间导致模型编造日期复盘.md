### Q7630 · 未注入当前时间导致模型凭训练记忆编造日期的事故复盘

难度：P6 ｜ 标签：事故复盘 / 上下文工程 / 时效性

**问**：客服助手被问"我的账单什么时候出"，回答了三周前的一个日期（模型训练截止期附近的旧日期）；"今天天气"类问题答案也带着旧日期。为什么模型会"自信地编造当前日期"？时间类上下文应该怎么注入、有哪些容易漏的角落？

**答**：
- **结论**：机制是**模型没有时钟**：训练数据里带着大量带日期的文本，模型对"今天/最近/下周"类词的最优猜测就是训练语料分布里的常见日期——不是幻觉缺陷，是上下文缺失下的合理外推。防法是**把时间作为一等上下文注入**，且要注入完整元组：当前日期 + 时区 + 星期（周末口径）+ 用户的本地时区偏移，格式用机器可解析形式（ISO8601）+ 一句自然语言，并注明"若用户未指定时区，按此时间回答"。容易漏的四个角落：① **多轮长会话**——首条注入了时间，两天后的续传会话还在用旧时间戳（会话恢复时刷新）；② **工具返回值里的时间**——查询 API 返回的相对描述（"上月"）被模型按错误基准换算；③ **缓存命中**——prompt 前缀缓存（Q7580/Q7574）让"动态时间"与"静态前缀"互相打架，时间放错位置（前缀中间）会打爆缓存命中率，放在消息尾部又怕被长上下文稀释；工程折中是时间放 system 末尾独立段落并接受该段缓存失效，或粒度降到"日期级"（日期变了才失效）。④ **推理模型**——思考链里模型自己推算日期可能覆盖注入值，指令要显式声明"以此时间为准，禁止自行推算当前日期"。
- **取舍**：时间注入的粒度：精确到秒会破坏前缀缓存（每请求都变），只注入日期在跨日边界（深夜会话）有口径漂移。折中方案：system 段注入日期+时区（缓存按日失效），请求级精确时间只在涉及时效计算的任务（如"还剩几天"）以 user/tool 消息附加——两个位置、两种粒度、各管各的。
- **实战**：① 上下文组装器有固定"时间槽"（system 末段），模板化生成；② 会话恢复（Q1157）时刷新时间槽；③ 工具结果中的日期强制 ISO 化，禁止"上月/最近"相对词进上下文；④ 评测集加时效用例（问日期/倒计时/相对换算），这类回归不进集就一直复发；⑤ 时间相关 badcase 归因模板：注入缺失/缓存错位/模型忽略三级分类。

```python
# 时间槽注入: system 末段日期级(缓存按日失效) + 任务级精确时间
# 基线: Python 3.9+ 标准库
from dataclasses import dataclass
from datetime import datetime, timezone, timedelta


@dataclass
class TimeSlot:
    now: datetime
    tz_name: str

    def system_line(self) -> str:
        """日期级注入: 缓存前缀按日失效, 不含秒级抖动。"""
        d = self.now.astimezone(timezone(timedelta(hours=8)))
        return (f"[当前时间] {d:%Y-%m-%d}({d:%A}), 时区 Asia/Shanghai. "
                f"以此为准回答时间问题, 禁止自行推算当前日期.")

    def task_line(self, deadline: datetime) -> str:
        """任务级精确时间: 仅时效计算任务, 走 user/tool 消息。"""
        delta = deadline - self.now
        return f"[精确时间] {self.now.isoformat()}; 截止 {deadline.isoformat()} " \
               f"(剩余 {delta.days} 天)"


def cache_key_parts(slot: TimeSlot) -> tuple:
    """缓存粒度=用户本地时区的日期: 同日请求共享前缀。"""
    local = slot.now.astimezone(timezone(timedelta(hours=8)))
    return (local.date(), slot.tz_name)


def main() -> None:
    now = datetime(2026, 11, 21, 23, 30, tzinfo=timezone.utc)
    slot = TimeSlot(now, "Asia/Shanghai")
    line = slot.system_line()
    assert "2026-11-22" in line            # UTC 23:30 -> 上海 11-22, 时区正确
    assert "禁止自行推算" in line
    assert cache_key_parts(slot) == (now.astimezone(
        timezone(timedelta(hours=8))).date(), "Asia/Shanghai")
    dl = datetime(2026, 12, 1, tzinfo=timezone.utc)
    assert "剩余" in slot.task_line(dl) and "9" in slot.task_line(dl)
    print(line[:50], "...")
    print("OK: 日期级进 system(按日缓存), 秒级只进时效任务消息; 会话恢复要刷新")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么时间注入的"位置"影响前缀缓存命中率？折中方案是什么？
→ 一句话提示：前缀缓存按公共前缀命中，秒级时间戳放在前缀中间会让其后所有内容缓存失效；折中 = 日期级放 system 末段（按日失效，代价小），精确时间作为消息级附加不进缓存前缀。

**追问 2**：工具返回"上月订单数 1200"时，风险在哪、怎么修？
→ 一句话提示：模型的"上月"基准取决于它以为的当前时间，注入缺失时按训练记忆换算；修法 = 工具侧把相对描述解析成显式区间再返回（如"2026-10-01..2026-10-31: 1200"），让上下文里没有任何需要模型推算的时间基准。

## 背诵要点
- 模型无时钟：时间词缺失上下文时按训练语料分布外推 = "自信编造日期"，防法是把时间作为一等上下文注入（ISO8601 + 时区 + 星期 + 禁止自行推算指令）。
- 两个位置两种粒度：日期级进 system 末段（前缀缓存按日失效），秒级只进时效任务消息；长会话恢复必须刷新时间槽。
- 易漏角落：会话续传旧时间戳、工具结果相对词（"上月"）、缓存错位、推理模型思考链自算——时间 badcase 三级归因（缺注入/缓存错位/模型忽略）。

## 复盘追问
- 为什么这类事故反复出现在"看起来最简单"的问题上？提示：时间注入属于"没有也不报错的静默退化"，测试用例通常不涉及时效——所以它必须以评测用例形式固化（问日期/倒计时/相对换算），靠人记得靠不住。
- 时区错误的"UTC 23:30 变次日"和日期编造是两类问题吗？提示：是——前者是注入值错了（工程 bug，日志可查），后者是根本没注入（上下文缺失）；归因模板先分这两类，修复路径完全不同。
