### Q7581 · 文档权限与 RAG 索引不同步的越权召回事故复盘

难度：P7 ｜ 标签：RAG / 权限 / 事故复盘

**问**：RAG 助手上线三个月后，用户通过提问召回了他本无权访问的内部文档（源文档权限后来收紧了，但索引没跟上）。事故链是什么？如何系统性防住？

**答**：
- **结论**：事故根因是"索引层与权限层是两个独立系统，生命周期不同步"：文档入库时做了权限过滤，但之后源系统的 ACL 收紧/文档删除/用户调岗，向量索引里的 chunk 及其权限元数据仍是旧快照，检索时按旧 ACL 过滤（或根本没过滤）就漏了密。第二个放大器：权限过滤若做在"检索后"（召回 top-k 再过滤），被过滤掉的 chunk 占据了 top-k 名额，既泄密又降质量。
- **取舍**：权限落点的三种方案取舍：① 检索时带 ACL 过滤（过滤表达式进向量库查询，如 pgvector WHERE 子句）——正确默认，要求索引里的权限元数据实时同步；② 按用户分区索引（每权限组独立 namespace）——隔离彻底但索引数量爆炸；③ 检索后过滤——只适合 ACL 极少变化的公开/内部二级场景，严禁用于机密级。同步机制取舍：CDC 监听源系统 ACL 变更事件（准实时）vs 定时全量对账（兜底），两者都要。
- **实战**：防复发四件：① 索引 chunk 冗余存储 ACL 快照 + 版本号，检索前先过"ACL 版本新鲜度"检查，过期 chunk 不召回；② 源系统权限变更事件接 CDC 管道（webhook/消息队列），驱动索引增量更新；③ 每日全量对账任务（源 ACL vs 索引元数据 diff，差异清零）；④ 安全回归测试：把"权限收紧后不可召回"做成评测用例进 CI。

```python
# 检索时 ACL 过滤 + 版本新鲜度检查（纯标准库模拟）
# 基线：Python 3.9+

from dataclasses import dataclass, field


@dataclass
class Chunk:
    doc_id: str
    acl_version: int
    acls: frozenset[str]


def retrieve(chunks: list[Chunk], user_groups: frozenset[str],
             source_acl_version: dict[str, int], top_k: int = 3) -> list[Chunk]:
    out = []
    for c in chunks:  # 实际为向量库查询，这里模拟过滤条件
        # ① 检索时 ACL 过滤  ② 索引 ACL 版本必须与源一致，过期不召回
        if c.acls & user_groups and source_acl_version.get(c.doc_id) == c.acl_version:
            out.append(c)
    return out[:top_k]


def main() -> None:
    chunks = [
        Chunk("d1", 3, frozenset({"eng"})),
        Chunk("d2", 1, frozenset({"eng"})),   # 源已升到 2，索引过期
    ]
    source = {"d1": 3, "d2": 2}  # d2 权限收紧后版本升级
    got = retrieve(chunks, frozenset({"eng"}), source)
    print("召回:", [c.doc_id for c in got])
    assert [c.doc_id for c in got] == ["d1"]  # 过期索引 chunk 不召回
    # 对账：索引版本 vs 源版本 diff
    stale = [d for d, v in source.items()
             if any(c.doc_id == d and c.acl_version != v for c in chunks)]
    print("对账过期清单:", stale)
    assert stale == ["d2"]


if __name__ == "__main__":
    main()
```

**追问 1**：为什么"检索后过滤"在机密场景不可接受？
→ 一句话提示：它已经把密文 chunk 送进了上下文/日志/缓存链路，即使最终不返回，trace、语义缓存、LLM 供应商侧都可能留下内容，泄露面不可控。

**追问 2**：ACL 快照冗余在 chunk 里如何控制存储成本？
→ 一句话提示：chunk 存 ACL 组 ID 集合而非完整 ACL 明细，组变更走统一版本号失效；或只存文档级 ACL 版本号，chunk 按 doc_id 关联校验。

## 背诵要点
- 根因：索引 ACL 是入库时快照，源系统收紧后不同步即越权；过滤要落在检索时（进查询条件）而非检索后。
- 双保险机制：CDC 事件驱动增量更新 + 每日全量对账 diff 清零；过期版本 chunk 一律不召回。
- 把"权限收紧后不可召回"做成安全评测用例进 CI，权限回归与质量回归同等级。

## 复盘追问
- 为什么这类事故往往三个月后才被发现？提示：越权召回是低频、无报错的行为，只有用户偶然提到敏感内容才暴露，必须靠主动对账与安全用例发现。
- 若源系统不支持权限变更事件，怎么兜底？提示：降低对账周期 + 监控"源 ACL 变更审计日志"变化速率触发对账，宁可多扫不可漏同步。
