### Q7655 · 批量推理 API（Batch）与在线 API 成本分界

难度：P6-P7 | 标签：成本工程、Batch API、推理

**问**：供应商的 Batch API 半价，但完成时限 24 小时且不支持流式。哪些负载该切 Batch、哪些必须留在线？切换的成本账与工程改造怎么算？

**答**：结论：分界线是**"结果时效"与"交互性"**：离线吞吐型（评测跑批、回填 embedding、历史文档摘要、内容审核复盘）切 Batch 半价省 30-50%；交互型（对话、Agent 工具循环、依赖即时反馈的流程）必须在线——Agent 每步要拿结果才能定下一步，Batch 的异步 24h 时限在逻辑上不可用。第二分界是**重试语义**：Batch 任务失败批量退回，错误处理是"结果集级"而非"请求级"，要有对账与补跑设计。

实战要点：
1. 流量画像先分类：把所有 LLM 调用点打标（interactive/batch），batch 化改造的收益 = batch 化调用量 × 单价 × 50%，通常评测与数据管道占大头。
2. 伪在线技巧：对"允许 1-5 分钟延迟"的场景（报告生成、批量问答），可用 Batch 的高优先级档或自建队列攒批+多模型并发，不必用真在线 API。
3. 工程改造三件：请求打包（jsonl 批文件）、结果对账（提交/完成/失败三态拉取）、失败补跑队列——改造一次摊给所有 batch 场景。

```python
"""调用点画像分类与 Batch 节省账（标准库，可运行）"""
from dataclasses import dataclass


@dataclass
class CallSite:
    name: str
    kind: str            # interactive | batch | nearline
    monthly_tokens: int
    price_per_m: float   # 在线单价/百万token


@dataclass
class BatchLedger:
    sites: list[CallSite]
    discount: float = 0.5

    def savings(self) -> tuple[float, float]:
        save = nearline_extra = 0.0
        for s in self.sites:
            if s.kind == "batch":
                save += s.monthly_tokens / 1e6 * s.price_per_m * self.discount
            elif s.kind == "nearline":
                # nearline 也可攒批，但需改造与容忍分钟级延迟
                nearline_extra += s.monthly_tokens / 1e6 * s.price_per_m
        return save, nearline_extra


sites = [
    CallSite("对话客服", "interactive", 40_000_000, 3.0),
    CallSite("评测跑批", "batch", 120_000_000, 3.0),
    CallSite("embedding回填", "batch", 200_000_000, 0.15),
    CallSite("日报摘要", "nearline", 30_000_000, 3.0),
]
led = BatchLedger(sites)
save, nearline = led.savings()
print(f"确定性 Batch 月省: {save:,.0f} 元")
print(f"nearline 攒批潜在节省: {nearline * 0.5:,.0f} 元（需容忍分钟级延迟）")
# Agent 工具循环必须在线：每步依赖上一步结果，Batch 时限逻辑上不可用
```

**追问 1**：Batch API 的"半价"有没有对冲成本？
**提示**：有——24h 时限迫使任务提前排期、失败批量退回需对账补跑、以及"结果晚到导致下游等待"的隐性人力；净节省要扣这些。

**追问 2**：评测跑批切 Batch 后，评测结论的时效性风险是什么？
**提示**：回归评测从"小时级反馈"变"次日"，迭代节奏变慢；核心 P0 用例保留小规模在线快评，全量走 Batch 的混合模式。

## 背诵要点
- 分界线=结果时效与交互性：交互/Agent 循环在线，评测回填等离线吞吐切 Batch 半价。
- nearline（分钟级可容忍）可攒批改造，是第二收获区；净节省要扣对账补跑的工程成本。
- 改造三件套：批文件打包、三态对账、失败补跑，一次改造摊给所有场景。
