### Q7201 · 列式读取零拷贝与内存账

难度：P6 ｜ 标签：容量成本账、Arrow、列式存储、零拷贝

基线：Python 3.12；pyarrow 14+ / Parquet；memoryview 标准库演示零拷贝概念。

**问**：千万行数据用 pandas 读进来再 `df[df.col > 0]` 过滤，内存峰值很高。同事说换成 Arrow 列式 + `pyarrow.compute` 能"零拷贝过滤"。省在哪？零拷贝是不是等于不占内存？

**答**：
- **结论**：pandas 默认行式/块式内存，过滤会构造布尔掩码、中间布尔索引和新 DataFrame，产生多份数据拷贝；Arrow 列式布局把每列存成连续 buffer，`pyarrow.compute` 在 C++ 层向量化计算，`pc.filter` 返回的是**引用原 buffer 的视图**（ChunkedArray），不复制底层数据——这是"零拷贝"的真实含义：省的是**重复拷贝**，不是不占内存。跨进程/跨语言边界（IPC、Parquet mmap）也能保持零拷贝，这是它比 pandas 更适合大数据管道的原因。
- **取舍**：从 pandas 转成 Arrow 有一次转换成本（内存里短暂共存两份），且 Arrow dtype 语义与 pandas 有差异（null 表达、字符串类型）；零拷贝视图会**钉住原 buffer**——只要视图还活着，原数据就不能释放，所以"零拷贝"有时反而延长了内存生命周期。
- **实战**：算内存账要分清"原始一次 + 视图数 × 引用"而非"每步都全量拷贝"；用 `mmap` 读 Parquet 避免整文件入内存；过滤后只 `select` 需要的列（列裁剪），配合行组（row group）把工作集限制在单组；注意视图钉住问题，及时释放不再用的父 buffer。

```python
def zero_copy_view(data: bytearray) -> memoryview:
    return memoryview(data)[:4]  # 视图：共享底层字节，不拷贝


def copy_slice(data: bytearray) -> bytes:
    return bytes(data[:4])  # 拷贝：独立副本


if __name__ == "__main__":
    data = bytearray(b"abcdefgh")
    view = zero_copy_view(data)
    data[0] = ord("Z")
    print("视图随源变化:", bytes(view))
    snap = copy_slice(data)
    data[1] = ord("Y")
    print("拷贝不随源变化:", bytes(snap))
    # 零拷贝省的是重复拷贝；视图仍占用（钉住）原 buffer。
```

**追问一**：零拷贝视图"钉住"原 buffer 是什么意思？
→ 解析：视图只是对原内存的引用，只要视图还被引用，Python/Arrow 就不能释放原 buffer，即使原变量已删除。所以零拷贝不等于零内存，反而可能延长大对象的存活时间。

**追问二**：列式读取为什么配合列裁剪/行组能进一步省内存？
→ 解析：列式存储按列连续存放，只读需要的列就不加载其他列；行组把数据分段，每次只解压/处理一个行组，工作集从"全表"降为"单行组"，峰值内存显著下降。
