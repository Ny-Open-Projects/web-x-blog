### Q7037 · 多环境防呆：为什么"提醒别连生产库"没用？

> 难度:★★★ | 标签:环境隔离, 数据安全, 防呆设计

**问**：工程师本地调试脚本误连生产库跑了 UPDATE；定时任务配置写错环境把测试数据灌进生产。这类"连错库"事故的完整防呆体系怎么设计？为什么靠"提醒"和"code review"不够？只读账号在本地开发时挡住联调怎么办？

**答**：结论：连错库的防呆必须**结构性隔离**——让错误动作"做不出来"，而不是"提醒别做"。四道防线：① 凭证隔离（本地环境根本拿不到生产凭证）；② DSN 环境标识 + 配置中心按环境命名空间下发（连错一眼可见）；③ 账号权限（本地/CI 用只读账号，生产写账号只存在于生产运行时）；④ 运行时护栏（危险 SQL 门禁 + 写操作影响面熔断 + 修数走工单）。

机理与实战：
- **为什么提醒没用**：事故都发生在疲劳/紧急/复制粘贴时，人的可靠性是常数；防呆设计（poka-yoke）的原则是"把错误状态变成不可构造的状态"——本地没有生产凭证，任何脚本都连不上，这比十个 review 评论都可靠。
- **凭证分发模型**：生产凭证只存在生产环境的密钥服务（Vault/KMS/配置中心 prod 命名空间）；本地 `.env` 只允许 local/staging 值；CI 用临时短时凭证。事故里的"debug 配置残留"在这一层直接消失。
- **环境标识进连接串**：DSN 含 env 标签，应用启动时打印连接 banner 并写审计日志；任务平台下发配置时校验"任务声明的环境 == DSN 环境"，不匹配拒绝启动——防"测试任务带生产配置"。
- **修数纪律**：一切生产写操作走工单（SQL 门禁 Q6540 + 备份点 + 窗口）；紧急修复也要事后补工单，把"绕过"变成"例外留痕"。
- **本地联调数据**：需要生产数据形态时用脱敏快照（Q7012）灌开发库；需要实时形态时用只读副本 + 查询审计，绝不直连主库。

```python
# 基线:Python 3.10+;纯标准库模拟多环境数据源防呆(凭证隔离+环境标识+运行时护栏)
# 真实场景:配置中心按环境命名空间下发 DSN;只读账号;危险操作熔断
from __future__ import annotations
from dataclasses import dataclass


@dataclass
class Dsn:
    env: str                     # local / staging / prod
    host: str
    database: str

    def label(self) -> str:
        return f"[{self.env}] {self.host}/{self.database}"


class CredentialStore:
    """凭证库:结构性隔离——本地环境根本拿不到生产凭证。"""

    def __init__(self) -> None:
        self.secrets: dict[tuple[str, str], str] = {}    # (env, user) -> password

    def register(self, env: str, user: str, password: str) -> None:
        self.secrets[(env, user)] = password

    def fetch(self, current_env: str, target_env: str, user: str) -> str | None:
        if current_env != target_env:
            return None                              # 跨环境取凭证:直接拿不到
        return self.secrets.get((target_env, user))


@dataclass
class Account:
    user: str
    readonly: bool


def guard_execute(sql: str, account: Account, est_rows: int,
                  fuse_rows: int = 1000) -> None:
    """运行时护栏:只读拒绝写;写影响面超限熔断(需工单)。"""
    head = sql.strip().split()[0].upper()
    if account.readonly and head in ("UPDATE", "DELETE", "INSERT", "ALTER", "DROP"):
        raise PermissionError(f"[防呆] {account.user} 为只读账号,拒绝 {head}")
    if head in ("UPDATE", "DELETE") and est_rows > fuse_rows:
        raise PermissionError(f"[熔断] 预估影响 {est_rows} 行 > {fuse_rows},"
                              "需修数工单+备份点后执行")


def demo() -> None:
    store = CredentialStore()
    store.register("prod", "svc_write", "prod-secret")
    store.register("prod", "ro_report", "prod-ro")
    store.register("local", "dev", "local-secret")

    # 防线一:本地脚本想连生产 -> 凭证结构性拿不到(而不是"提醒别用")
    pw = store.fetch(current_env="local", target_env="prod", user="svc_write")
    assert pw is None
    print("本地环境取生产凭证 -> None ✅(错误连接在生产环境外不可构造)")

    # 防线二:环境标识进 DSN,配置中心按环境命名空间下发
    prod_dsn = Dsn("prod", "pg-prod-1.internal", "billing")
    stg_dsn = Dsn("staging", "pg-stg.internal", "billing")
    print(f"DSN 带环境标识:{prod_dsn.label()} / {stg_dsn.label()} ✅"
          "(启动时打印 banner,连错一眼可见)")

    # 防线三:只读账号挡住本地调试脚本的误写
    ro = Account("ro_report", readonly=True)
    try:
        guard_execute("UPDATE orders SET status = 1 WHERE id = 1", ro, est_rows=1)
    except PermissionError as e:
        print(e, "✅")

    # 防线四:写账号 + 影响面熔断
    writer = Account("svc_write", readonly=False)
    guard_execute("DELETE FROM logs WHERE day = '2026-01-01'", writer, est_rows=800)
    print("正常小批量删除放行 ✅")
    try:
        guard_execute("DELETE FROM logs WHERE 1=1", writer, est_rows=80_000_000)
    except PermissionError as e:
        print(e, "✅")


if __name__ == "__main__":
    demo()
```

**追问一**：配置中心按环境下发后，"任务声明的环境"和"DSN 环境"不一致怎么防？
答：下发时做原子绑定——任务清单里声明的 env 与配置项的 env 由调度器校验，不一致拒绝启动并告警；再加一层运行时自证：进程启动打印 DSN banner 到审计日志，事后可按 banner 追溯"谁在什么时候连了什么环境"。

**追问二**：生产只读账号被用来跑重型分析查询拖垮副本，权限体系怎么补？
答：权限解决"能不能写"，管不了"写得多重"——要叠加资源治理：只读账号挂独立副本 + 查询超时（statement_timeout）+ 并发上限 + 按账号的查询审计与成本账；重型分析引导到数据仓库，副本只服务轻量业务读。

## 背诵要点
- 防呆=结构性隔离：本地拿不到生产凭证（错误状态不可构造），提醒/review 只是补充而非防线。
- 四道防线：凭证按环境隔离、DSN 环境标识+启动 banner、账号权限（本地只读/CI 临时凭证）、运行时护栏（SQL 门禁+影响面熔断）。
- 生产修数必须工单化（门禁+备份点+窗口）；本地要生产形态用脱敏快照，要实时形态用只读副本+审计。
