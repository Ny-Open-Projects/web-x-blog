### Q7059 · 上游空跑事故：数据量守门与空表阻断

难度：P6 | 标签：数据质量、空跑、守门、事故复盘

**问**：上游采集服务半夜静默故障，产出 0 行分区数据，但任务退出码是 0——下游 12 个任务全部"成功"，第二天业务方发现报表是空的。为什么"行数为 0 的成功"比"任务失败"更危险？量级守门怎么设计？

**答**：
- **结论**：空跑比失败危险在于"静默传播"：失败会触发重试与告警，空跑的退出码是绿的、行数没人看，坏数据（空数据）一路流到报表，由业务方发现——事故发现时间从分钟级劣化到天级。量级守门是第一跳的硬闸门：① 地板行数（该分区配置的期望最小值，低于即标红阻断）；② 环比骤降（较 7 日中位数下降超 90% 即疑似断流）；③ 双阈值才放行（行数与关键列非空率一起看）。守门的意义是把"下游 12 个任务白跑"压缩成"第一跳阻断 + 告警"，等待上游恢复后重跑。
- **取舍**：守门误报的代价是"健康数据被拦"（大促后回落日、节假日低谷会被地板阈值误伤）——所以地板值按分区历史分布配置（P1 分位而非拍脑袋），环比骤降阈值避免绝对值；阻断是"不推进"而不是"任务失败"，上游恢复后自动续跑，比失败重试语义更准确。
- **实战**：落地分层：地板行数是第一层（配置态）；环比骤降是第二层（统计态，防"合法但异常"）；下游就绪探测（SLA 检查"终点表当日分区行数 > 0 且更新时间新鲜"）是第三层兜底。三层各司其职，全部绿灯才算"数据可用"。

```python
"""上游空跑事故：任务"成功"但分区为空，下游整条链产出空报表；量级守门如何拦截。"""
from dataclasses import dataclass

@dataclass
class PartitionTask:
    day: str
    rows: int
    expected_min: int = 1000    # 该分区行数地板

def last7_median(counts: list[int]) -> int:
    hist = sorted(counts)[-7:]
    return hist[len(hist) // 2]

def gate(rows: int, expected_min: int, history: list[int]) -> str:
    if rows < expected_min:
        return f"阻断：{rows} 行低于地板 {expected_min}，任务标红并告警"
    drop = 1 - rows / max(last7_median(history), 1)
    if drop > 0.9:
        return f"阻断：较 7 日中位数骤降 {drop:.0%}，疑似上游断流"
    return "通过"

days = ["d1", "d2", "d3", "d4", "d5", "d6", "d7", "d8"]
rows_hist = [120000, 118000, 122500, 119800, 121300, 120400, 119500]
# d8：上游采集服务静默故障，产出 0 行但任务退出码 0
upstream_rows = dict(zip(days, rows_hist + [0]))

print("无守门（行数不校验）：")
for d, r in upstream_rows.items():
    print(f"  {d}: 上游 {r} 行 -> 任务成功 -> 下游聚合/报表全部照跑"
          + ("（报表全空，业务方先发现）" if r == 0 else ""))
print("\n有量级守门：")
for i, (d, r) in enumerate(upstream_rows.items()):
    verdict = gate(r, 1000, rows_hist[:i] or rows_hist)
    print(f"  {d}: 上游 {r} 行 -> {verdict}")
    if r == 0:
        break
print("守门分层：地板行数（配置）+ 环比骤降（统计）+ 下游就绪探测（SLA）")
```

**追问链**：
1. 追问一层：为什么用"7 日中位数"而不是"昨日行数"做环比基线？——单日基线受周期性影响（周末低谷、大促峰值），昨日值可能本身就异常；中位数对单点异常稳健，骤降判断"相对正常水位"的变化，减少节假日误报。
2. 追问二层：守门拦截后，下游任务应该"失败重试"还是"挂起等待"？——挂起等待（hold）语义更对：上游恢复重跑后，下游自动续跑；失败重试会立刻再撞一次门并刷屏告警。这也是"数据 SLA 就绪探测"与"任务重试"的分工：重试解决偶发失败，就绪探测解决"等上游"的依赖语义。

**背诵要点**：
1. 空跑比失败危险：退出码全绿、静默传播到报表，发现时间从分钟级劣化到天级。
2. 量级守门三件套：地板行数（P1 分位配置）+ 7 日中位数环比骤降 + 下游就绪探测。
3. 阻断语义是"不推进、等续跑"，不是失败重试——上游恢复后自动接续。

**复盘追问**：
1. 为什么这类事故的业务方总比数据组先发现？（管道监控盯退出码与时长，没人盯行数；把"行数守门"做成第一跳的硬失败，才能让数据组比业务方先知道）
2. 大促后流量回落日被地板阈值误拦，怎么调？（地板值不拍脑袋：按分区历史分布的 P1 分位动态生成 + 节假日日历修正；误报记录回流调参，而不是遇到误报就关守门）
