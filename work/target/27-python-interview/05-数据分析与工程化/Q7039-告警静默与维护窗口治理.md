### Q7039 · 告警静默与维护窗口

> 难度:★★☆ | 标签:告警, 运维, SLO

**问**：计划内维护（升级 DB 2 小时）会触发 50 条告警——静默（silence）怎么配置才不会「静默掉了不该静的」（维护真的失败怎么办），告警降噪的层级（抑制/静默/聚合）各解决什么，「告警疲劳」（每天 200 条没人看）的系统性解法是什么？

**答**：① 三层降噪语义：**抑制**（inhibition）：告警 A（DB 宕机）存在时抑制其衍生告警 B（DB 上的服务全挂）——因果链降噪；**静默**（silence）：时间窗口内对指定标签集合的告警不发送（计划内维护）——**必须带过期时间**（忘记恢复的静默是漏报大杀器）；**聚合**（grouping）：同标签的 N 条合并成 1 条通知。② 安全静默的设计：静默按**具体实例/服务**标签而非全局（DB 升级只静 db 相关，别的告警照发）；静默期间维护验证告警**降级为记录**（不发通知但落日志——维护失败有迹可查）；静默创建要审批留痕（谁、为什么、多久）。③ 告警疲劳系统性解法：**按响应动作分级**（需要人立即动的 = page，可等的 = ticket，纯记录 = log——每条告警必须回答「收到后做什么」，答不出就降级）；已知噪声修根因或阈值，不做「静默了事」（静默清单也是债务台账，Q118 同构）。

```python
# 全部标准库；demo 实现「抑制/静默/聚合三层降噪 + 过期强制」
import time

class AlertRouter:
    def __init__(self):
        self.silences: list[dict] = []         # {matchers, until, note, creator}
        self.inhibit = [                       # 抑制规则：A 存在则抑制 B
            {"if": "db_down", "suppress": "service_on_db"}]
        self.groups: dict[str, list] = {}
        self.logged: list[dict] = []
    def add_silence(self, matchers: dict, minutes: float, note: str, creator: str):
        self.silences.append({"matchers": matchers, "until": time.monotonic() + minutes * 60,
                              "note": note, "creator": creator})
    def _silenced(self, alert: dict) -> bool:
        now = time.monotonic()
        self.silences = [s for s in self.silences if s["until"] > now]  # 过期强制清除
        return any(all(alert.get(k) == v for k, v in s["matchers"].items())
                   for s in self.silences)
    def _inhibited(self, alert: dict) -> bool:
        for rule in self.inhibit:
            if rule["suppress"] in str(alert.get("labels")) and \
               any(a["name"] == rule["if"] for a in self._active):
                return True
        return False
    def fire(self, alerts: list[dict]) -> dict:
        self._active = alerts
        sent, grouped = [], {}
        for a in alerts:
            if self._inhibited(a):                     # 层1 抑制：因果降噪
                self.logged.append({**a, "fate": "inhibited"}); continue
            if self._silenced(a):                      # 层2 静默：计划内维护
                self.logged.append({**a, "fate": "silenced"}); continue
            grouped.setdefault((a["severity"], a.get("service")), []).append(a)
        for key, items in grouped.items():             # 层3 聚合：同标签合并
            sent.append({"key": key, "count": len(items)})
        return {"sent": sent, "log": self.logged}

if __name__ == "__main__":
    r = AlertRouter()
    r.add_silence({"service": "db"}, minutes=120, note="DB 升级窗口", creator="ops1")
    alerts = [
        {"name": "db_down", "severity": "critical", "service": "db"},
        {"name": "service_on_db", "severity": "critical", "service": "api"},
        {"name": "high_latency", "severity": "warning", "service": "db"},   # 被静默
        {"name": "http_500", "severity": "critical", "service": "web"},     # 与 DB 无关，照发
    ]
    out = r.fire(alerts)
    fates = {a["name"]: a["fate"] for a in out["log"]}
    assert fates["service_on_db"] == "inhibited"           # 因果抑制 ✅
    assert fates["high_latency"] == "silenced"             # 计划静默 ✅
    assert any(s["key"][1] == "web" for s in out["sent"])  # 无关服务不静默 ✅
    print("三层降噪: db_down 保留 + 因果抑制 + 计划静默 + 无关告警照发 ✅")
    assert all(s["until"] > time.monotonic() for s in r.silences)
    print("静默带过期时间（忘恢复自动失效）✅ 创建人 ops1 留痕")
```

**追问**：1) 为什么静默必须带过期时间？——忘恢复的静默 = 该告警永久失聪（DB 真挂了没人知道）；过期强制清除让最坏情况是「维护中噪音回来一下」而非「漏报一晚」——不对称风险选漏报成本低的。2) 抑制链的环路怎么办？——A 抑制 B、B 又抑制 A = 互相吞；抑制规则必须 DAG（同 Q7513），配置时校验。3) 「告警必须带响应动作」怎么落地？——告警模板强制 `runbook` 字段（链接到处置手册），没写 runbook 的告警规则 CI 拒绝合入——把纪律固化进流水线。

## 背诵要点
1. 三层降噪：抑制（因果链）/ 静默（时间窗+标签，带过期）/ 聚合（同标签合并）——语义各不同。
2. 安静静默三条件：按具体标签非全局、维护验证告警降级为记录、创建留痕；过期强制清除防永久失聪。
3. 告警疲劳根治：按响应动作分级（page/ticket/log），每条告警必须回答「收到后做什么」。

## 复盘追问
1. 大促期间要不要静默全部告警？（提示：绝不全静——大促正是故障高发期；只静计划内变更相关，业务指标告警加强而不是静默）
2. 静默清单本身怎么审计？（提示：静默创建/过期全量日志 + 每周静默时长报表（静默时间占比是运维健康度反向指标））
