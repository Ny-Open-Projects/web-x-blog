### Q7184 · 本地能过 CI 挂：环境路径污染事故复盘

难度：P6 ｜ 标签：事故复盘、环境隔离、sys.path、可复现测试

基线：Python 3.9+；venv / pytest / tox 或 uv run。

**问**：一个同事本地 pytest 全绿，合并后 CI 却报 `ModuleNotFoundError` 和诡异的"旧版函数签名"错误；更糟的是另一个项目 `import utils` 竟然 import 到了不相关的模块。这类"环境路径污染"是怎么发生的？怎么系统性防住？

**答**：
- **结论**：三个经典根因叠加：(1) **没进虚拟环境**——本地用全局 Python 装了所有项目的包，CI 是干净环境，行为天然不同；(2) **CWD 即 sys.path**——pytest/脚本从项目根运行时根目录进 `sys.path[0]`，若目录里有个 `utils.py`/`email.py` 与标准库或第三方包重名，就会遮蔽真包（shadowing）；(3) **stale 产物**——本地残留旧 `.pyc`/`__pycache__`/已安装的旧版自身包（`pip install -e` 的旧 egg-link），CI 没有。本质都是"本地环境是脏的、CI 是净的，两边从未对齐"。
- **取舍**：根治不是"每次手动重建"，而是把环境变成代码：`uv run`/`tox`/`nox` 一条命令从 lock 创建一次性环境跑测试，本地与 CI 用同一个入口；import 遮蔽用"包内绝对导入 + 顶层目录只放包不放散装模块 + CI 加 shadowing 检查"三招。
- **实战**：快速自检命令——`python -I -c "import x; print(x.__file__)"`（-I 隔离模式排除 CWD）看真包在哪；`pytest -p no:cacheprovider` 排除缓存干扰；CI 加一步 `python -c "import proj; print(proj.__file__)"` 断言路径。

```python
# 模块遮蔽检测器：发现 import 结果与预期来源不符（标准库可运行）。
import importlib.util
import sys

STDLIB = set(sys.stdlib_module_names) if hasattr(sys, "stdlib_module_names") else {
    "json", "email", "utils", "types"}

def check_shadowing(module_name: str, expect_path_contains: str) -> str:
    spec = importlib.util.find_spec(module_name)
    if spec is None or spec.origin is None:
        return f"{module_name}: 找不到，先查环境是否装对"
    origin = spec.origin
    if module_name in STDLIB and "python" not in origin.lower() \
            and "lib/python" not in origin:
        return f"{module_name}: 被 {origin} 遮蔽（标准库被同名模块顶掉）"
    if expect_path_contains and expect_path_contains not in origin:
        return f"{module_name}: 来源 {origin} 不在预期路径 {expect_path_contains}"
    return f"{module_name}: OK ({origin})"

if __name__ == "__main__":
    # 1) 真·标准库 json 应来自 Python 安装目录
    print(check_shadowing("json", "python"))
    # 2) 业务包应来自当前仓库（模拟 CI 断言）
    print(check_shadowing("dataclasses", "python"))
    # 若项目里有人写了 dataclasses.py，第二行会报遮蔽。
```

**追问**：
- 一层：`python -I` 和 `python -S` 的区别？→ 提示：-I 隔离（忽略 CWD/PYTHONPATH/用户 site），-S 只是跳过 site 导入；查遮蔽用 -I 更干净。
- 二层：为什么 pytest 比 python -m 更容易触发遮蔽？→ 提示：rootdir 插入 sys.path 的时机与 conftest 收集机制有关，用 `python -m pytest` 强制 CWD 进 path 反而更可控。

**背诵要点**：
1. 本地过/CI 挂三根因：全局环境未隔离、CWD 遮蔽同名模块、stale 缓存与旧安装残留。
2. 根治：环境即代码（uv run/tox 统一本地与 CI 入口）+ shadowing 检查进 CI。
3. 排障武器：`python -I -c "import x; print(x.__file__)"` 与 `sys.stdlib_module_names` 判标准库。

**复盘追问**：
1. 为什么事故发生前没人发现 import 到了旧版本？提示：错误消息来自"旧签名"，但没人检查过 `mod.__file__`。
2. monorepo 里多个同名顶层包怎么治理？提示：统一用命名空间包（PEP 420）或包前缀，禁止散装 utils.py。
