### Q7149 · 告警通知通道（短信/电话）费用成本账

难度：P6-P7 | 标签：成本工程、告警、oncall

**问**：一年告警短信 8 万条、电话外呼 3 千次，账单远超监控平台本身。通知通道的成本账怎么算？哪些工程手段能把费用压下来而不牺牲 P0 响应？

**答**：结论：通知通道是**按次计费的稀缺资源**，费用 ≈ 条数 × 单价，而条数由"告警质量"决定——费用高通常不是通道贵，而是噪音多。压费用的正确路径是降噪而不是换便宜通道：① 分级路由（P0 电话、P1 群消息、P2 静默入面板），② 聚合窗口（同一告警指纹 N 分钟合并成一条），③ 升级链兜底（Q2284：未确认才电话）。注意红线：省钱不能砍 P0 通道，电话是最后防线，其他级别才谈聚合与降级。

实战要点：
1. 按指纹聚合：`alert_id + 环境维度` 做合并键，5 分钟窗口内同指纹只发首条+尾条（恢复）。
2. 每月出"通道账单×来源告警"报表：哪条规则贡献了 60% 短信，就治哪条规则——费用报表是告警治理的抓手（Q7039 静默治理）。
3. 时段分级：夜间 P2 不打扰（值班睡眠 > 次要告警），工作时段合并成日报摘要。

```python
"""告警通道分级路由与聚合成本账（标准库，可运行）"""
from collections import defaultdict
from dataclasses import dataclass


@dataclass
class Channel:
    name: str
    unit_price: float  # 元/次


SMS, PHONE, IM = Channel("短信", 0.09), Channel("电话", 0.50), Channel("IM", 0.0)

ROUTE = {0: (PHONE,), 1: (IM,), 2: (IM,)}


def route_cost(events: list[tuple[int, str]]) -> float:
    """events: (priority, fingerprint) 未聚合"""
    return sum(ROUTE[p][0].unit_price for p, _ in events)


def route_cost_aggregated(events: list[tuple[int, str]],
                          window_minutes: int = 5) -> float:
    """同指纹窗口内聚合：只发首条"""
    seen: dict[str, bool] = defaultdict(bool)
    cost = 0.0
    for p, fp in events:
        if seen[fp]:
            continue
        seen[fp] = True
        cost += ROUTE[p][0].unit_price
    return cost


events = [(2, f"cpu-high{i % 5}") for i in range(1000)]  # P2 噪音 1000 条
print("未聚合成本:", route_cost(events), "元（若走短信通道）")
print("聚合后成本:", route_cost_aggregated(events), "元")

# 月账单×来源规则：找出贡献最大的规则
bills = defaultdict(float)
for p, fp in events:
    bills[fp.split(str(0))[0][:6] or "cpu-high"] += ROUTE[p][0].unit_price
top = sorted(bills.items(), key=lambda kv: -kv[1])[:3]
print("TOP 费用来源:", top)
```

**追问 1**：为什么"把短信单价砍半的供应商换掉"通常解决不了费用问题？
**提示**：条数是指数级主导项；噪音告警的量级放大远超单价差异，先治因再谈价。

**追问 2**：聚合窗口设多长会开始伤害响应？
**提示**：窗口只在同指纹上生效，不同指纹不受影响；窗口>响应 SLO 或覆盖了"恢复又复发"节奏时才有害，恢复通知必须独立发。

## 背诵要点
- 通道费=条数×单价，条数由告警噪音决定；先降噪再谈换供应商。
- 分级路由：P0 电话、P1/P2 IM 与面板；电话只留给未确认升级。
- 聚合按指纹+窗口，恢复通知独立发送；月度"账单×规则"报表是治理抓手。
