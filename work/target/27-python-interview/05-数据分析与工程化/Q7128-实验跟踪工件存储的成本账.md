### Q7128 · 机器学习实验跟踪工件（模型/数据集快照）存储的成本账

难度：P6 ｜ 标签：成本工程 / MLOps / 工件存储

**问**：团队接入实验跟踪平台（MLflow/W&B）后，每次实验自动保存模型权重、数据集快照、环境快照，三个月对象存储账单涨了 4 倍。为什么实验工件的存储会失控？工件该存什么、留多久、怎么引用？

**答**：
- **结论**：失控机制是**每个工件都是"不可变快照"且默认全量**：模型权重 GB 级、数据集快照 10GB 级、每次 run 都存一份，且实验跟踪的价值主张就是"任何时候可回放"——没人敢删，于是存储 = run 数 × 全量工件 × 无限保留。控制结构三步：① **工件分级**——指标/参数/环境清单（KB 级文本）全量长存；模型权重按里程碑存（best/checkpoint 各留 N 版）；数据集快照不存本体存**指纹**（内容哈希 + 存储指针，数据本体在数据版本库去重）；② **保留策略**——生产模型的工件保留与模型生命周期绑定，实验 run 30/90 天后工件降冷（转归档存储）或只剩指针；③ **去重引用**——环境快照（pip freeze/镜像 hash）与代码 commit hash 是 KB 级引用，同一数据集哈希只存一次。成本公式：`月成本 = Σ(级工件体积 × 保留月数 × 单价)`，把"不设保留"改成"分级保留"通常降 60-80%。
- **取舍**：工件去引用（只存 hash，需要时从数据源重建）还是去实体（存本体）？重建依赖上游数据源存活且可复现——回放实验的置信度高但时间成本大（数小时）；存本体回放快但存储贵。决策变量是"回放频率与数据源稳定性"：高频调参期存小工件+指针、发版前里程碑 run 存全量。另一个常见误区：把"删工件"当降本，其实指标/参数是 KB 级，真正贵的是权重与数据快照——先分清账再删，误删指标等于毁掉实验历史。
- **实战**：① 平台侧设工件 TTL 策略（run 状态驱动：abandoned run 7 天清权重留指标）；② 数据集快照强制走内容寻址（hash 命名），天然去重；③ 大工件上传前算账：`频率 × 单件体积 × 保留` 过一个门禁，超预算要评审；④ 降冷用生命周期规则（30 天转 IA/归档）而不是人工清理。

```python
# 工件成本账: 分级保留 vs 全量无限; 数据集存指纹引用, 权重按里程碑
# 基线: Python 3.9+ 标准库
from dataclasses import dataclass
from hashlib import sha1


@dataclass
class Artifact:
    kind: str          # metric | model | dataset
    size_gb: float
    retention_months: int

    def cost(self, per_gb_month: float) -> float:
        return self.size_gb * self.retention_months * per_gb_month


def dataset_pointer(dataset_bytes: bytes) -> str:
    """内容寻址指纹: 同一数据集全库只存一份实体。"""
    return sha1(dataset_bytes).hexdigest()[:16]


def main() -> None:
    per = 0.02   # $/GB/月
    # 全量失控: 每 run 存 模型2GB+数据集10GB, 100 run, 12 月
    reckless = [Artifact("model", 2.0, 12) for _ in range(100)] + \
               [Artifact("dataset", 10.0, 12) for _ in range(100)]
    cost_reckless = sum(a.cost(per) for a in reckless)          # $288/月
    assert abs(cost_reckless - 288.0) < 1e-9
    # 分级: 指标全存(KB忽略), 权重留 5 个里程碑, 数据集 1 份指纹+本体
    tiered = [Artifact("model", 2.0, 12) for _ in range(5)] + \
             [Artifact("dataset", 10.0, 6)]
    cost_tiered = sum(a.cost(per) for a in tiered)              # $3.6/月
    assert cost_tiered / cost_reckless < 0.02                   # 降 ~99%
    ptr = dataset_pointer(b"train-v3")
    assert len(ptr) == 16
    print(f"全量 ${cost_reckless:,.0f}/月 -> 分级 ${cost_tiered:.2f}/月")
    print(f"OK: 指标/参数KB级全存; 权重里程碑化; 数据集内容寻址去重({ptr})")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么数据集快照用"指纹+指针"而不是每 run 一份实体？
→ 一句话提示：实验 90% 的 run 用的是同一批数据集版本，内容寻址后 100 份引用共享 1 份实体，存储从 O(run) 降到 O(版本)；指纹同时充当完整性校验，回放时可验证数据没变。

**追问 2**：把"实验 run"降冷到归档存储前，需要先确认什么？
→ 一句话提示：回放需求的真实频率与归档取回费/延迟的平衡——归档取回要付解冻费和小时级延迟，若该 run 还在被调参引用，降冷反而更贵；TTL 策略要按 run 状态而不是按时间一刀切。

## 背诵要点
- 失控 = run 数 × 全量工件 × 无限保留；降本三板斧：工件分级（指标全存/权重里程碑/数据集指纹引用）+ 状态驱动 TTL + 内容寻址去重，通常降 60-80%。
- 成本公式 = Σ(级工件体积 × 保留月数 × 单价)；真正贵的是权重与数据快照，指标/参数是 KB 级，删除要分清账。
- 数据集指针 = 内容哈希，O(版本) 存储 + 完整性校验；降冷按 run 状态驱动，归档取回费与延迟进决策。

## 复盘追问
- 为什么"实验可回放"的价值主张会变成存储失控的保护伞？提示：没人敢删是因为没人定义"回放到什么粒度"——分级保留策略本质上就是把回放承诺写清楚：指标永远可查、权重里程碑可复现、数据版本可寻址。
- 工件上传门禁怎么设计才不拖慢迭代？提示：门禁只拦超预算大件（GB 级），KB 级指标直传；门禁输出是"这份工件的月成本"数字，让作者自己权衡而不是平台一刀切。
