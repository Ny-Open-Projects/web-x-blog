### Q7063 · 变更影响分析与定向测试

难度：P6 | 标签：CI、定向测试、影响分析、成本工程

**问**：单测从 20 分钟涨到 50 分钟，每次提 PR 全量跑。除了加机器，怎么把"跑哪些测试"变成可以推导的问题？定向测试的安全边界在哪？

**答**：
- **结论**：影响分析 = 变更集 × 反向依赖闭包。拿到本次 diff 触达的模块，沿"测试 → 触达模块"的映射选测试子集；映射的生成两条路：静态（import 扫描建模块依赖图）或动态（coverage 数据：上次全量跑时记录每个用例触达的代码行）。定向后单 PR 只跑命中子集 + 永远的冒烟集。
- **取舍**：静态映射便宜但偏保守（import 到就是"可能触达"），动态映射准但依赖一次全量基线且对新测试失效；工程上常两者叠加：coverage 做主映射，import 图兜底新测试。风险边界：配置变更、全局 monkeypatch、共享 fixture 的修改无法被模块级映射捕获——所以冒烟集必须无条件跑，并且映射粒度到模块而非文件路径。
- **实战**：成本账：全量 50 分钟 × 每天 200 个 PR = 166 小时 CI 时长；定向到 5 分钟后降到 17 小时，省的是钱更是反馈速度——工程师等 CI 的每分钟都在中断心流。实现顺序：先做按目录分片（低技术含量但立竿见影），再上 coverage 映射，最后才考虑分布式缓存。

```python
"""变更影响分析与定向测试：改动模块 -> 反向依赖 -> 测试子集。"""

# 测试 -> 触达模块映射（生产上由 coverage 数据或 import 扫描生成）
tests_to_modules = {
    "test_order_api": ["service/order", "models/order", "utils/money"],
    "test_user_api": ["service/user", "models/user"],
    "test_money": ["utils/money"],
    "test_e2e_smoke": ["*"],                       # 冒烟永远跑
}

def select_tests(changed):
    changed = set(changed)
    return sorted(
        name for name, mods in tests_to_modules.items()
        if "*" in mods or changed & set(mods)
    )

picked = select_tests(["models/order", "utils/money"])
print("改动 models/order + utils/money 后要跑:", picked)
print("只改 docs:", select_tests(["docs/deploy"]))
assert select_tests(["models/order"]) == ["test_e2e_smoke", "test_order_api"]
print("结论：定向测试把 50 分钟回归压到分钟级；冒烟集兜住映射捕获不到的意外影响")
```

**追问链**：
1. 追问一层：为什么映射要靠"测试触达的代码行"而不是"测试文件 import 的模块"？——pytest fixture/conftest、运行时动态导入会绕开静态 import；coverage 的行级数据能覆盖间接触达，代价是需要基线与失效管理。
2. 追问二层：哪些变更必须强制全量跑？（全局配置/依赖版本/共享 fixture/入口代码改动，这些的影响面超出模块映射）

**背诵要点**：
1. 定向测试 = diff 触达模块 × 反向依赖闭包，coverage 动态映射为主。
2. 冒烟集无条件跑，配置/依赖/共享 fixture 类变更强制全量。
3. 成本账按"CI 时长 × PR 数"算，先目录分片再 coverage 映射。

**复盘追问**：
1. 定向后漏掉了一个本该跑的用例导致线上事故，怎么补机制？（映射错就记录事故样本扩基线；冒烟集补上该场景）
2. coverage 基线多久失效一次，失效时的兜底是什么？（新测试/重构后重跑基线，兜底是 import 图 + 定期全量）
