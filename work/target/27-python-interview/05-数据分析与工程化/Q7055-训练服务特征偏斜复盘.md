### Q7055 · 训练-服务特征偏斜的复盘与对账

难度：P6 | 标签：特征工程、训练服务偏斜、PSI、复盘

**问**：模型离线评估 AUC 0.85，上线后转化率反而掉了。查了三天发现训练特征做了 `log1p`、线上打分忘了。为什么"同一列特征"两端不一致会静默地毁掉模型？怎么建立对账机制让这类偏斜活不过一周？

**答**：
- **结论**：训练服务偏斜（train/serve skew）的本质是"模型学到的是 A 分布，吃到的是 B 分布"——log1p 丢失后金额特征放大了几个数量级，模型输出整体漂移，AUC 不会报错（评估用的是训练管道自己的数据）。它静默的原因：偏斜发生在特征变换层，不发生在代码报错层。对账机制三件套：① 特征变换收敛到公共特征库（同一函数两端 import，禁止复制粘贴）；② 线上打分时落特征日志（把真实喂给模型的值记下来）；③ 离线例行跑 PSI 对账（训练样本分布 vs 特征日志分布，PSI>0.25 阻断发布）。
- **取舍**：特征日志有存储成本（每条打分多几 KB），可以对高价值模型全量、长尾模型采样 1%；公共特征库要防"过度抽象"——特征定义随模型实验快速变化，库的版本要跟模型版本绑定发布，否则又会出现"库更新了线上没更新"的新偏斜。
- **实战**：复盘路径：先看线上特征日志的分布直方图 vs 训练样本直方图（肉眼可见量级差）→ 沿特征名 diff 两端的变换代码 → 收敛到公共包。预防靠 PSI 常态化 + "特征字段注册表"（每个特征的变换函数、owner、版本），让"这列怎么算出来的"有唯一答案。

```python
"""训练-服务特征偏斜：两端变换不一致的复盘与 PSI-lite 对账。"""
import math

def bucketize(v: float) -> int:
    """金额分箱：0-10 / 10-100 / 100-1k / 1k+（对变换后的值）。"""
    for i, edge in enumerate((10, 100, 1000)):
        if v <= edge:
            return i
    return 3

def psi_lite(train: list[float], serving: list[float]) -> float:
    """PSI 简化版：sum((p_serving - p_train) * ln(p_serving / p_train))。"""
    n_t, n_s = len(train), len(serving)
    total = 0.0
    for b in range(4):
        pt = sum(1 for v in train if bucketize(v) == b) / n_t
        ps = sum(1 for v in serving if bucketize(v) == b) / n_s
        pt = pt or 1e-6
        ps = ps or 1e-6
        total += (ps - pt) * math.log(ps / pt)
    return total

# 同一批订单：训练侧做了 log1p，线上打分侧忘了（原值直进模型）
amounts = [10, 50, 80, 200, 500, 1200, 3000] * 40
train_feats = [math.log1p(a) for a in amounts]
serving_feats = [float(a) for a in amounts]        # 偏斜：变换丢失
score_psi = psi_lite(train_feats, serving_feats)
print(f"训练 vs 线上特征 PSI = {score_psi:.3f}（阈值 0.25） -> "
      f"{'报警：两端变换不一致' if score_psi > 0.25 else '正常'}")

# 修复后：两端共用同一特征模块 + 特征日志留痕对账
def featurize(amount: float) -> float:
    return math.log1p(amount)                      # 单一事实源的特征函数

serving_fixed = [featurize(a) for a in amounts]
fixed_psi = psi_lite(train_feats, serving_fixed)
print(f"共用特征模块后 PSI = {fixed_psi:.4f} -> 正常")
print("治理：特征变换收敛到公共包并在打分时落特征日志，"
      "离线定期拿'特征日志 vs 训练样本'对账，PSI 超阈值即阻断发布")
```

**追问链**：
1. 追问一层：为什么 AUC 评估没拦住这个偏斜？——离线评估复用的是训练管道的特征（已经 log1p），模型与特征自洽；偏斜发生在"线上打分时的特征生产"，评估管道看不到线上。所以评估指标永远对不上"线上效果"，对账必须在线上特征日志与训练分布之间做。
2. 追问二层：PSI 漂移还有别的原因（人群变化、季节性），怎么区分"偏斜"与"漂移"？——偏斜是系统性的两端不一致：PSI 持续高且复现稳定，回滚到旧特征模块 PSI 归零；漂移随时间缓慢变化且两端一致。定位手段是"同一批请求分别用新旧特征函数算 PSI"，归零即偏斜、不变即分布漂移。

**背诵要点**：
1. 偏斜静默毁模型：评估用训练管道看不到线上特征，AUC 高不等于线上对。
2. 三件套：公共特征库（禁复制粘贴）+ 线上特征日志 + PSI 例行对账阻断发布。
3. PSI 区分偏斜与漂移：回滚归零是偏斜（代码 bug），缓慢变化是漂移（分布变化）。

**复盘追问**：
1. 为什么"特征变换写在两个仓库"这类事故会反复出现？（变换逻辑没有单一事实源，靠人肉同步；评审只看 diff 看不到"另一份拷贝的存在"，根治是收敛公共包 + 注册表）
2. 特征日志该记原始值还是变换后的值？（记变换后并附特征版本——对账要对的是"模型实际吃到什么"；原始值可以另外采样留存用于重算，但主账本是变换后）
