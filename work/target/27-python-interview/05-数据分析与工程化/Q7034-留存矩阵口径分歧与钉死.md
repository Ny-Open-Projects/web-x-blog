### Q7034 · 留存矩阵：为什么产品线和数据团队算出来的留存差 5 个点？

> 难度:★★★ | 标签:留存分析, 指标口径, 数据分析

**问**：留存率公式看着很简单（首日后第 N 天活跃 / 首日用户），为什么不同团队算出来的数字能差好几个点？口径的分歧点有哪几个？"第 N 日"用日历日还是滚动 24 小时窗口，差别有多大？历史口径变更怎么处理？

**答**：结论：留存的争议几乎全部来自**四个口径没对齐**：① 分母（首日新增账号 vs 首日活跃 vs 去重设备）；② 第 N 日定义（日历日差 N vs 首次行为后滚动 24h×N 窗口）；③ 行为定义（打开/登录/核心行为）；④ 时区日界（UTC vs 本地，把日末用户切给不同首日）。矩阵计算本身是集合运算（首日集合 ∩ 第 N 日活跃集合 ÷ 首日集合），难的是口径文档化、版本化与全量重算。

机理与实战：
- **日历 vs 滚动的分歧是结论级的**：首行为在深夜 23 点的用户，次日清晨 4 点回来——日历口径算"第 1 日留存"，滚动窗口口径算"第 0 窗口内活跃"，第 1 窗口判定为未留存。同一个用户、同一次行为，两种口径结论相反，两条曲线不可混排。
- **时区漂移**：23:30 新装的用户在 UTC 日界下归次日首日集合——首日集合本身都不同，分母漂移让所有百分比失去可比性。口径文档必须写明日界与数据入库时区。
- **工程纪律**：① 口径文档四要素（分母/第 N 日/行为/时区）+ 口径版本号；② 留存计算幂等——按日重算历史矩阵必须得同值；③ 口径变更走"双发布"（新旧口径并行一个季度）+ 变更日志，报表标注口径版本；④ 新增设备与回流活跃分母不能混（行业惯例"新增留存"与"活跃留存"分开两套矩阵）。

```python
# 基线:Python 3.10+;纯标准库实现留存矩阵计算并演示三种口径分歧
# 真实场景:pandas groupby/透视图;口径文档化(分母/第N日定义/行为定义)是关键
from __future__ import annotations
from collections import defaultdict


def matrix_calendar(first_day: dict[str, int], active_days: dict[str, set[int]],
                    horizon: int = 3) -> dict[int, float]:
    """日历口径:第 N 日 = 首日 + N 个自然日(同日界)。"""
    buckets: dict[int, list[str]] = defaultdict(list)
    for u, d0 in first_day.items():
        buckets[d0].append(u)
    ret = {}
    for n in range(1, horizon + 1):
        hit = total = 0
        for users in buckets.values():
            total += len(users)
            hit += sum(1 for u in users if first_day[u] + n in active_days[u])
        ret[n] = hit / total
    return ret


def matrix_rolling(first_ts: dict[str, int], active_hours: dict[str, set[int]],
                   horizon: int = 3) -> dict[int, float]:
    """滚动口径:第 N 日 = (首行为+24N h, +24(N+1) h] 内活跃。"""
    buckets: dict[int, list[str]] = defaultdict(list)
    for u, t0 in first_ts.items():
        buckets[t0 // 24].append(u)                       # 按首日分桶(演示简化)
    ret = {}
    for n in range(1, horizon + 1):
        hit = total = 0
        for users in buckets.values():
            total += len(users)
            for u in users:
                t0 = first_ts[u]
                lo, hi = t0 + 24 * n, t0 + 24 * (n + 1)
                hit += any(lo < h <= hi for h in active_hours[u])
        ret[n] = hit / total
    return ret


def demo() -> None:
    # 口径一:分母 = 首日新增(去重账号)
    first_day = {"u1": 0, "u2": 0, "u3": 0}
    active = {"u1": {0, 1, 2}, "u2": {0}, "u3": {1}}
    m = matrix_calendar(first_day, active)
    print(f"日历口径:第1日留存 {m[1]:.0%}(u1,u3)/第2日 {m[2]:.0%}(u1) ✅")
    assert abs(m[1] - 2 / 3) < 1e-9 and abs(m[2] - 1 / 3) < 1e-9

    # 口径二:滚动 24h 窗口与日历日的分歧案例
    # u4 首行为 D0 日 23:00(t0=23h);次日 04:00(第28小时)活跃
    cal = matrix_calendar({"u4": 0}, {"u4": {0, 1}})       # 日历:次日 04:00 属 day1
    roll = matrix_rolling({"u4": 23}, {"u4": {23, 28}}, horizon=2)  # 滚动:h28 落窗口0
    print(f"同一用户次日 04:00 活跃:日历口径第1日留存={cal[1]:.0%},"
          f"滚动口径第1窗口留存={roll[1]:.0%} ✅")
    assert cal[1] == 1.0 and roll[1] == 0.0
    print("两种口径结论相反 -> 混排曲线趋势不可比,口径必须钉死 ✅")

    # 口径三:时区日界漂移:UTC 日界 vs 本地日界把末尾用户切给不同首日
    print("23:30 新装用户:UTC 日界归 day0,本地日界归 day1"
          " -> 首日集合不同,分母漂移 ✅")
    print("防线:口径文档(分母/第N日/行为/时区) + 口径版本号 + 变更后全量重算双发布")


if __name__ == "__main__":
    demo()
```

**追问一**：为什么周留存/月留存"看起来"比日留存高，可以直接对比吗？
答：窗口越宽"任一天活跃即留存"的命中概率越高，且周/月窗口平滑了周末效应与日级噪声——绝对值天然更高；只有同一口径、同一窗口族内的趋势对比才有效（日矩阵看日趋势、周矩阵看周趋势），跨窗口比绝对值没有意义。

**追问二**：分母用"新增设备"还是"新增账号"，什么场景必须选哪个？
答：营销归因/渠道评估用设备（避免一人多号灌水分母），账号体系产品用账号（跨设备登录体验）；两者混用会让投放侧与产品侧对不上数。多设备一账号的产品要明确"以账号为主、设备作辅"并写进口径，否则换机/重装会同时污染分子分母。

## 背诵要点
- 留存四口径：分母（新增/活跃/设备/账号）、第 N 日定义（日历 vs 滚动 24h）、行为定义、时区日界——分歧不解决数字没有讨论意义。
- 日历与滚动可结论级相反（深夜首行为的次日清晨活跃：日历=留存、滚动=窗口 0）；曲线只可在同口径内比趋势。
- 工程纪律：口径版本号 + 幂等重算 + 口径变更双发布并行一季度，报表标注口径版本。
