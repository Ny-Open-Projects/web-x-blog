### Q7169 · 数据科学笔记本实例的闲置成本账与自动停机设计

难度：P6 ｜ 标签：成本工程、Jupyter、云实例

**问**：团队 20 个数据分析师人手一台 GPU/大内存笔记本实例（SageMaker Notebook / 自建 JupyterHub），月账单 40 万，其中多数实例一天活跃不到 2 小时。闲置成本账怎么算？自动停机的设计要点与阻力是什么？

**答**：**结论**：笔记本实例的成本结构是"**按墙钟时间计费，按活跃时间使用**"——8×24 计费的实例若日均使用 2 小时，闲置率 91.7%，理论节约空间即账单的九成。自动停机（idle timeout）是收益最大的第一刀：`vm_size × 单价 × 24 × 30 × (1 - 活跃率)` 就是月度可省金额。真正的阻力不是技术，是"被停机打断"的体验——所以停机设计必须先解决**状态持久化**（EBS 卷独立计费保留、会话变量丢失的可接受范围）。

**取舍**：三个层级的方案：① idle 自动停机（探测内核无执行 + 无 web 请求 N 小时）——省 60-90%，改动最小；② 按需拉起（JupyterHub spawner on-demand）——省更多，但镜像拉起 1-5 分钟的等待要接受；③ 无状态化到 Job 模式（notebook 只做交互，重活提交到临时任务）——成本最优但工作流改造大。经验路径：先 ① 再 ②，③ 只对重度训练场景做。

**实战**：idle 判定用"内核最后执行时间"而不是"有连接"（挂着浏览器不算活跃）；停机前自动保存 notebook + 快照 EBS；给用户留"锁定实例"通道（长期训练任务），锁定必须带过期时间防止永久占用。

```python
# 笔记本实例闲置成本账与自动停机收益估算
def idle_cost_report(
    instances: list[dict], unit_price_per_hour: dict[str, float],
) -> dict:
    """instances: [{name, vm, active_hours_per_day, locked}]"""
    total, savable = 0.0, 0.0
    rows = []
    for ins in instances:
        price = unit_price_per_hour[ins["vm"]]
        monthly = price * 24 * 30
        active_ratio = min(ins["active_hours_per_day"] / 24, 1.0)
        waste = monthly * (1 - active_ratio)
        total += monthly
        if not ins["locked"]:
            savable += waste
        rows.append((ins["name"], f"{monthly:.0f}",
                     f"{1 - active_ratio:.0%}",
                     f"{waste:.0f}" + ("(锁定)" if ins["locked"] else "")))
    return {"monthly_total": round(total), "monthly_savable": round(savable),
            "rows": rows}

instances = [
    {"name": "a", "vm": "cpu8x",  "active_hours_per_day": 2, "locked": False},
    {"name": "b", "vm": "cpu8x",  "active_hours_per_day": 6, "locked": False},
    {"name": "c", "vm": "gpu1",   "active_hours_per_day": 1, "locked": True},
]
prices = {"cpu8x": 2.0, "gpu1": 10.0}
r = idle_cost_report(instances, prices)
print("月总成本:", r["monthly_total"], "可省:", r["monthly_savable"])
for row in r["rows"]:
    print(row)

# idle 判定：内核最后执行时间 + 无 web 活动的组合条件
def should_stop(last_kernel_exec_h: float, last_web_req_h: float,
               threshold_h: float = 4.0, locked: bool = False,
               lock_expires: float | None = None) -> bool:
    if locked:
        import time
        if lock_expires and lock_expires < time.time():
            return True           # 锁过期自动解除
        return False
    idle = max(last_kernel_exec_h, last_web_req_h)
    return idle >= threshold_h

print("停机判定(空闲5h):", should_stop(5.0, 1.0))
print("停机判定(锁定未过期):", should_stop(9.0, 9.0, locked=True,
                                           lock_expires=9e12))
```

**追问 1**：为什么 idle 判定要用"内核最后执行"而不用连接数？
提示：Jupyter 长连接（浏览器挂着、websocket 保活）不代表工作；内核无 cell 执行 + 无文件写入才是真闲置，用连接数判定会漏掉"开着不干活"的主体浪费。

**追问 2**：停机后"会话变量丢失"如何降到可接受？
提示：约定" notebook 文件即状态"的工作流（重跑成本低、数据不落本地变量），配合 stop 时自动保存 + EBS 持久卷；环境（pip 包）固化在镜像里而不是实例里，这是很多闲置的根因——实例被当成"个人服务器"。

**追问 3**：GPU 实例和 CPU 实例的停机策略要一样吗？
提示：不一样。GPU 单价高 5-10 倍，timeout 应更短（1-2h）且优先强制；CPU 实例保留 4h+ 温和阈值。锁定名单里 GPU 要更严的过期时间。

## 背诵要点
1. 笔记本成本结构：按墙钟计费、按活跃使用；闲置率 = 1 − 活跃小时/24，九成闲置即九成可省。
2. idle 判定用内核最后执行时间（非连接数），停机前自动保存 + EBS 持久化 + 镜像固化环境。
3. 锁定通道必须带过期时间，防止"永久占用"把节省收益吃回去。
