### Q7016 · 桌面/CLI 应用打包分发

> 难度:★★☆ | 标签:打包, PyInstaller, 分发

**问**：把 Python 工具发给没有 Python 环境的用户——PyInstaller/PyOxidizer/cx_Freeze 各自产出什么，「杀毒软件误报」和「文件巨大」这两个高频痛点怎么治？交叉编译做不到怎么办（Mac 上出 Windows 包），CLI 工具的现代分发方式（pipx/uvx/单文件二进制）怎么选？

**答**：① 打包器对比：**PyInstaller**（主流：单目录/单文件模式，分析 import 图打包解释器+依赖；单文件模式启动要解压到临时目录——启动慢、误报多）；**PyOxidizer**（Rust 管理嵌入，真二进制、启动快，但生态复杂）；**cx_Freeze**（老牌，跨平台支持稳）。② 误报治理根因：PyInstaller 的 bootloader 特征被杀软指纹库命中 + 单文件自解压行为像恶意软件——缓解：代码签名证书（macOS notarize / Windows Authenticode）、白名单渠道分发、避免单文件模式用单目录+安装器。③ 体积治理：排除无用依赖（`--exclude-module`）、按需 import（惰性）、用 slim 基础（PyPy 目标反而不行，CPython 最小化）、UPX（压缩但加剧误报，权衡）。④ 分发矩阵：内部 CLI → pipx/uvx（隔离安装，共享 Python，最快）；对外小白用户 → 安装器（安装器包单目录）；需要极致体验 → Rust/Go 重写热点 CLI 是行业现实（uv 本身就是 Rust）。

```python
# demo：打包分析器（import 图裁剪建议 + 体积审计，纯标准库模拟）
import ast, os, pathlib, sys

HEAVY_MODULES = {"pandas": "150MB+", "matplotlib": "80MB+", "scipy": "100MB+",
                 "torch": "2GB+", "tkinter": "5MB", "numpy": "40MB"}
STD_ONLY = {"json", "os", "re", "sys", "time", "argparse"}

def scan_imports(path: str) -> set[str]:
    """AST 扫描顶层 import（不执行代码）。"""
    tree = ast.parse(pathlib.Path(path).read_text())
    mods = set()
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            mods |= {a.name.split(".")[0] for a in node.names}
        elif isinstance(node, ast.ImportFrom) and node.module:
            mods.add(node.module.split(".")[0])
    return mods

def size_audit(entry: str) -> dict:
    """打包体积审计：重依赖建议惰性化或排除。"""
    mods = scan_imports(entry)
    advice = []
    for m in mods:
        if m in HEAVY_MODULES and m not in STD_ONLY:
            advice.append(f"{m}({HEAVY_MODULES[m]}) → 惰性 import 或 --exclude-module")
    return {"imports": sorted(mods), "advice": advice}

def cross_compile_advice(target: str) -> str:
    """交叉编译不可行 → 三选一：CI 矩阵 / 虚拟机 / 原生容器。"""
    return {
        "windows": "GitHub Actions windows-latest 跑 PyInstaller（CI 矩阵是标准解）",
        "linux": "CI ubuntu-latest + auditwheel 修 manylinux tag（libc 兼容）",
        "macos": "构建机出 arm64 + x86_64 双架构 lipo 合并 universal2",
    }[target]

if __name__ == "__main__":
    demo = "/tmp/demo_cli.py"
    pathlib.Path(demo).write_text(
        "import json, os\nimport pandas as pd\nimport argparse\n"
        "def main():\n    df = __import__('pandas').read_csv('x')\n")
    audit = size_audit(demo)
    print("import 图:", audit["imports"])
    for a in audit["advice"]:
        print("  体积建议:", a)
    print("Windows 交叉:", cross_compile_advice("windows"))
    print("macOS 交叉:", cross_compile_advice("macos"))
    # 口径：Mac 上打不出 Windows 包（编译器/ABI 不同），CI 矩阵三平台各出各的；
    # 签名是分发前提（macOS 未 notarize 直接被 Gatekeeper 拦）。
```

**追问**：1) PyInstaller 单文件启动慢的根因？——单文件是自解压归档，启动先解压到 `/tmp/_MEIxxx` 再执行；几十 MB 包解压 1-3s，且临时目录残留问题（旧进程未清理占用）——大型 CLI 用单目录 + 安装器，嵌入式场景用 PyOxidizer。2) `--exclude-module` 排错了会怎样？——运行时 ImportError（打包期无法完全静态发现动态 import：`__import__(name)`、插件系统）——动态 import 的模块要 `--hidden-import` 显式补，这是打包失败的两大互为镜像的坑。3) manylinux tag 什么意思？——manylinux2014/2_28 = 在指定 glibc 基线上构建，用户 pip 装时按其 libc 匹配选择 wheel；本机 Python 太新（如 3.13）没有对应 wheel 就会源码编译（失败率高），分发前用 auditwheel 检查。

## 背诵要点
1. PyInstaller 主流但单文件模式有启动解压 + 杀软误报两大坑；签名（notarize/Authenticode）是分发前提。
2. 体积治理：AST 级 import 审计 → 惰性化重依赖；动态 import 用 --hidden-import 补，排除过狠会运行时炸。
3. 交叉编译不可行：CI 矩阵三平台各打各的（Windows/linux/macos 分链路）；CLI 现代分发 pipx/uvx 优先。

## 复盘追问
1. 打包后在用户机器上 ImportError，本地好的，怎么排查？（提示：环境差异（glibc/Python 版本）、动态 import 未捕获、数据文件未打包（--add-data）——打包器日志 + 复现环境最小化）
2. CLI 升级机制怎么做？（提示：自更新器（下载+校验签名+原子替换）或交给包管理器（pipx upgrade/brew），自更新是安全敏感点必须签名校验）
