### Q7162 · 覆盖率插桩开销容量账：coverage 让 CI 慢了 3 倍值不值

难度：P6-P7 | 标签：容量规划、coverage、CI

**问**：开启 `pytest --cov` 后测试时长从 10 分钟涨到 30 分钟。覆盖率插桩的开销从哪来？这笔容量账怎么算，什么情况下值得开、什么情况下该降采样或旁路？

**答**：结论：开销来自**追踪钩子**：coverage.py 默认 trace 模式在每个 Python 事件（行/调用/返回）挂 C 回调（`sys.settrace` 级别），对 CPU 密集的纯 Python 测试放大 2-5 倍；`sys.monitoring`（Python 3.12+，PEP 669）把事件改为注册制回调，coverage 7.4+ 的 `core=sysmon` 可把开销降到 1.3-2 倍。账的算法：覆盖率收益 = 拦截的缺陷 × 修复成本，插桩成本 = CI 时长增量 × 执行频率 × 机时单价；**值得开**的判据是增量时长可压进阈值（如 <1.5 倍）且覆盖率确实进入了质量门禁决策，否则就是纯税。

取舍与实战：
1. 三个降本开关按序尝试：① `core=sysmon`（3.12+ 首选，代价是部分 C 路径覆盖粒度不同）；② `branch=False`（分支覆盖比行覆盖贵，按需开）；③ 覆盖率旁路化——覆盖率跑批挪到 nightly/PR 合并后，主干 PR 只跑测试不采覆盖率，反馈延迟换主干速度。
2. 范围裁剪：`--cov` 只指向被测包（禁全仓插桩），`omit` 掉测试自身与生成代码；C 扩展代码 trace 不到，覆盖率天然盲区别当质量指标。
3. 与 Q7154（分片均衡）联动：开启覆盖率后各测试耗时结构变化，分片表要按"含插桩耗时"重新校准，否则均衡失效。
4. 数据失真注意：并行/子进程（xdist worker、subprocess）默认不采覆盖，要 `coverage combine` 聚合 worker 数据，漏配会得到虚假低覆盖——比高覆盖更误导决策。

```python
"""插桩开销估算与降本开关决策（标准库演示，可运行）"""
import sys, time

def cov_overhead_plan(
    base_minutes: float,          # 无覆盖率时长
    instrumented_minutes: float,  # 有覆盖率时长
    runs_per_day: int,
    machine_cost_per_h: float,
) -> dict:
    overhead = instrumented_minutes / max(base_minutes, 0.1) - 1
    monthly_cost = (instrumented_minutes - base_minutes) / 60 * runs_per_day * 22 * machine_cost_per_h
    plan = []
    if sys.version_info >= (3, 12):
        plan.append("首选 coverage[sysmon] core=sysmon（PEP 669 注册制回调）")
    if overhead > 1.0:
        plan.append("branch 覆盖按需开；>2 倍时覆盖率挪 nightly 旁路")
    return {"开销倍率": round(overhead + 1, 2),
            "月度增量机时费": round(monthly_cost),
            "行动": plan or ["[OK] 开销可接受，保留主干全量"]}

# 模拟：10 分钟基线 vs 28 分钟插桩
print(cov_overhead_plan(10, 28, runs_per_day=30, machine_cost_per_h=2))
```

**追问 1**：为什么 `sys.monitoring` 比传统 settrace 快一个量级？
**提示**：settrace 是全局单回调（每个事件都进 Python 层分发），PEP 669 按事件类型注册、由解释器在 C 层直接调用且可只对代码对象启用——无事件的代码零开销，热路径回调在 C 里。

**追问 2**：覆盖率旁路到 nightly 后，如何防"PR 覆盖率下降"漏进主干？
**提示**：用 diff-cover 口径——只对 PR 改动的行要求覆盖，nightly 全量数据回流后对近 N 天 PR 做补账门禁；改动行覆盖全量便宜得多，主干速度与质量兼顾。

## 背诵要点
- 插桩开销源：settrace 全局事件回调；3.12+ 用 coverage `core=sysmon`（PEP 669）降到 1.3-2 倍。
- 降本三开关：sysmon → 范围裁剪/branch 按需 → nightly 旁路；账 = 时长增量 × 频率 × 机时单价。
- xdist/subprocess 下要 coverage combine 聚合，否则覆盖率数据虚假；分片表按插桩耗时重校。
