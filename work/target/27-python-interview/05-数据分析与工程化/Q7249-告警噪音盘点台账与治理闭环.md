### Q7249 · 每周 900 条告警没人看：噪音盘点台账与治理闭环

难度：P6 ｜ 标签：告警治理、噪音盘点、处置台账、告警生命周期

基线：Python 3.12；对一周告警流水按来源聚合出噪音榜，模拟治理前后变化并输出台账。

**问**：值班同学平均每周收 900 条告警，其中 70% 没有任何行动，真正致命的告警被淹没。现有的阈值调优、静默（Q7039）、聚合去重（Q1741）都是单点手段，怎么建立**周期性的告警噪音盘点**机制，让告警总量和噪音率持续下降而不是反弹？

**答**：
- **结论**：噪音治理的本质是**告警也要有生命周期管理**：每条告警规则从上线起就该有 owner、预期处置动作与预算（每周最多 N 条）。盘点机制 = 周期性地把告警流水聚合成台账：每条规则的**触发次数、处置率（被人处理的比例）、静默时长、升级次数**，产出"噪音榜"；对处置率持续为零的规则走三个出口——调阈值、降级为日报/看板指标、直接下线。没有闭环的告警就是日志：告警预算制（SRE 的 alert budget）把"每周该响几次"变成可审计的指标。
- **取舍**：① 全量治理不可行，按噪音榜 Top10 逐条攻，收益集中在少数规则；② "处置率"的定义要防刷：以"值班做了与告警对应的动作"为准，可以在工单系统关联；③ 下线规则的风险是漏报——下线前必须给该指标留一个非告警的观测位（看板/日报），观察一个周期；④ 治理成果要防反弹：新增告警规则必须带预算与 owner（上线门禁），台账每周自动刷新，反弹趋势在下次盘点即暴露。
- **实战**：① 台账每周自动生成并贴进值班群，列出 Top 噪音源的处置率与建议动作；② 静默不能当治理手段滥用——静默率本身进台账，静默率高的规则说明阈值或来源有问题；③ 把"告警总量/处置率/静默率"三个数做成值班健康度指标（Q1455 管道健康分思路），纳入复盘会议固定议程。

```python
"""告警噪音台账：按规则聚合处置率/静默率，输出噪音榜与治理动作。"""
Rule = dict


def build_ledger(alerts: list[dict], rules: dict[str, Rule]) -> list[dict]:
    agg: dict[str, dict] = {}
    for a in alerts:
        rid = a["rule"]
        g = agg.setdefault(rid, {"fired": 0, "acted": 0, "silenced": 0,
                                 "escalated": 0})
        g["fired"] += 1
        g["acted"] += 1 if a.get("acted") else 0
        g["silenced"] += 1 if a.get("silenced") else 0
        g["escalated"] += 1 if a.get("escalated") else 0
    rows = []
    for rid, g in agg.items():
        fired = g["fired"]
        rows.append({
            "rule": rid, "owner": rules[rid]["owner"],
            "fired": fired,
            "处置率": g["acted"] / fired,
            "静默率": g["silenced"] / fired,
            "升级数": g["escalated"],
        })
    rows.sort(key=lambda r: -r["fired"])
    return rows


def action(r: dict) -> str:
    if r["处置率"] < 0.05 and r["fired"] > 20:
        return "调阈值或降级为日报(观察1周期后下线)"
    if r["静默率"] > 0.3:
        return "静默滥用嫌疑: 检查阈值与触发条件"
    if r["升级数"] > 0:
        return "保留: 有升级说明有真实价值"
    return "观察"


if __name__ == "__main__":
    rules = {"r1": {"owner": "管道组"}, "r2": {"owner": "DBA"},
             "r3": {"owner": "业务组"}, "r4": {"owner": "风控"}}
    alerts = ([{"rule": "r1", "acted": False} for _ in range(420)]
              + [{"rule": "r2", "acted": False, "silenced": True} for _ in range(180)]
              + [{"rule": "r3", "acted": True, "escalated": True} for _ in range(30)]
              + [{"rule": "r4", "acted": True} for _ in range(120)])

    rows = build_ledger(alerts, rules)
    print(f"{'规则':<6}{'owner':<8}{'触发':>6}{'处置率':>8}{'静默率':>8}  建议")
    for r in rows:
        print(f"{r['rule']:<6}{r['owner']:<8}{r['fired']:>6}{r['处置率']:>7.0%}"
              f"{r['静默率']:>8.0%}  {action(r)}")
    total = sum(r["fired"] for r in rows)
    acted = sum(r["fired"] * r["处置率"] for r in rows)
    print(f"\n周总量 {total:,} | 有效处置 {acted:.0f} 条 | 噪音率 {1 - acted / total:.0%}")
    print("治理后目标: r1 调阈值(420->30), r2 降级日报(180->0) => 周总量 ~270")
    print("结论：告警要有 owner/预算/生命周期；处置率为零的规则迟早要调阈值或下线")
```

**追问一**：怎么判断一条告警该"调阈值"还是该"降级为日报"？

→ 解析：看它的信息价值曲线：如果调低灵敏度后仍然每周大量触发且处置率依旧为零，说明这个指标波动本身不携带决策信息——降级为日报/看板指标，需要时人主动看。判断依据是"是否存在过去一年里该告警触发了值得立刻行动的事件"：有，且阈值只是偏松，就调阈值；没有，就降级。下线是最保守动作，必须留非告警观测位观察一个周期。这个决策链应该固化在盘点模板里，避免每次凭个人偏好拍板。

**追问二**：新增告警规则的"预算制"怎么落地？

→ 解析：规则上线时必须填三项：owner、预期触发频率（如每周 ≤5 条）、预期处置动作（触发后值班做什么）。上线后由台账自动核对实际频率与处置率，连续两周超标即进入盘点清单，owner 要在复盘会上说明调整方案。这与 SRE 的 error budget 同构：告警不是免费的，每条都消耗值班注意力这个稀缺资源。门禁化后，"加个告警"从一个念头变成一个有成本的决策，噪音自然得到源头控制——比事后清理便宜得多。
