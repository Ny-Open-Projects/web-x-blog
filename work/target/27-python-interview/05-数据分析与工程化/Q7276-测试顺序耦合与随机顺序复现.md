### Q7276 · 绿了三天红了今天：测试顺序耦合与随机顺序复现

难度：P6 ｜ 标签：测试顺序耦合、随机顺序、模块级状态、fixture 污染、可复现失败

基线：Python 3.12；用纯标准库模拟测试运行器的顺序执行模型，复现"顺序耦合测试单跑全绿、连跑必红"的形态、随机顺序暴露隐藏依赖、种子固定复现失败序列，全标准库实跑。

**问**：测试套件本地全绿，CI 今天突然红了，重跑又绿；单跑失败用例也绿——顺序耦合长什么样？为什么说"顺序绿"是假绿？随机顺序插件（pytest-randomly 思想）怎么把隐藏依赖逼出来？失败序列怎么固定复现？

**答**：
- **结论**：顺序耦合的本质是**模块级/进程级可变状态在测试间泄露**：环境变量、全局配置单例、类属性、模块级缓存、数据库残余数据、工作目录——前一个测试改了状态，后一个测试恰好依赖（或恰好被污染）。它有两种症状：**依赖型**（测试 B 需要测试 A 产生的状态，单跑 B 失败——绿三天的假绿）与**污染型**（测试 C 留下的脏状态让 D 失败，单跑 D 绿——CI 间歇红）。单跑全绿 + 连跑偶红 + 换机器红绿不同，三个特征齐了就是顺序耦合实锤。治理核心不是"找出是哪个状态"（大海捞针），而是**把顺序从确定变成随机**：随机顺序下耦合测试在 CI 的每次运行随机碰撞，暴露率从"恰好那一个顺序才红"变成"任何依赖都会很快被撞出来"；配套**种子固定**——每次运行的随机种子打进报告，红的时候用同一种子重放，失败序列可复现。根治仍是老三样：状态重建进 fixture（setup/teardown 严格配对）、模块级可变状态改注入（Q487 依赖注入）、外部资源事务回滚隔离（Q931）。
- **取舍**：① 随机化的颗粒度：模块内随机 vs 全局随机——全局随机暴露面大但破坏"同文件相关用例聚一起"的可读性，常见折衷是每个 worker 内随机（Q7003 xdist 同族）+ 每周一次全量随机；② 随机化与 flaky 的区分：顺序耦合的失败**可复现**（同种子同红），真 flaky（并发竞态、外部依赖）换种子也红绿不定（Q7058 的分类学）——先跑同种子重放再归类；③ 修复的优先级：先修"依赖型"（测试间隐式契约，改一次断链全线红）再修"污染型"（teardown 缺失，补 fixture 即可）；④ 别用"固定一个已验证的顺序"当解药——那只是把炸弹埋回土里，新测试照样往耦合上长。
- **实战**：① CI 配置随机顺序 + 种子上报，失败报告第一行就是种子号，本地 `--seed` 重放；② 全局可变状态盘点进 lint：模块级 `dict/list` 可变对象、环境变量写操作、`os.chdir` 触发告警（Q5025 chdir 进程级全局的同族）；③ 单测自检命令："每个测试必须能单独运行"是 PR 门禁之一——一条 `pytest --isolated` 类脚本逐个单跑全套件，一次提交验证一次；④ fixture 的 teardown 断言：资源类 fixture（临时目录、连接、mock 恢复 Q7278 同族）在退出时断言环境已复位，复位失败即测试失败，把污染暴露在源头。

```python
"""Q7276 测试顺序耦合: 固定顺序假绿 vs 随机顺序暴露 + 种子复现。"""
import random

GLOBAL_STATE: dict[str, object] = {}          # 模拟模块级可变配置单例


def reset_state():
    GLOBAL_STATE.clear()


class TestSuite:
    """最小测试运行器: 按给定顺序执行用例, 记录结果与种子."""

    def __init__(self, tests: dict[str, callable]):
        self.tests = tests

    def run(self, order: list[str]) -> list[str]:
        failures = []
        reset_state()
        for name in order:
            try:
                self.tests[name]()
            except AssertionError as e:
                failures.append(f"{name}: {e}")
        return failures


# 三个用例: B 隐式依赖 A 写入的状态(依赖型); C 无污染
def test_a_set_env():
    GLOBAL_STATE["region"] = "cn-east"


def test_b_read_env():
    # 依赖 A 先跑: 单跑 B -> 状态缺失而失败; A+B 顺序连跑 -> 假绿
    if GLOBAL_STATE.get("region") != "cn-east":
        raise AssertionError("region 配置缺失(依赖了测试A的隐式契约)")


def test_c_pure():
    assert 1 + 1 == 2


if __name__ == "__main__":
    suite = TestSuite({"A": test_a_set_env, "B": test_b_read_env, "C": test_c_pure})
    fixed = suite.run(["A", "B", "C"])
    print(f"固定顺序 A,B,C: 失败 {fixed or '无'}  <- 顺序耦合的'假绿'")
    single = suite.run(["B"])
    print(f"单跑 B:        失败 {single}  <- 隐式依赖实锤")

    random.seed(42)                            # 固定种子: 失败序列可复现
    red_orders = 0
    runs = 1000
    for _ in range(runs):
        order = list(suite.tests)
        random.shuffle(order)
        if suite.run(order):
            red_orders += 1
    print(f"随机顺序 {runs} 次(种子42): {red_orders} 次暴露失败 "
          f"({red_orders / runs:.0%} 撞出隐藏依赖)")
    ok = (fixed == [] and single and 0.3 < red_orders / runs < 0.7)
    print(f"校验: 固定序假绿 + 单跑红 + 随机序高概率暴露 -> {'通过' if ok else '异常'}")
    print("结论：顺序耦合=模块级状态在测试间泄露; 固定顺序只是运气;")
    print("      随机顺序+固定种子把'碰巧绿'变成'必然暴露且可复现'")
```

**追问一**：随机顺序跑红了一个组合，但同种子本地重放又是绿的——这时候怎么定位？

→ 解析：同种子不同结果说明还有**种子之外的变量**：① **并行度**：CI 是 xdist 多 worker（Q7003），随机种子决定的顺序只在单 worker 内生效，worker 分片与负载均衡本身就是随机源——本地用 `-p no:xdist` 单进程重放；② **外部状态**：数据库/缓存/对象存储的残余数据、外部 API 的限流窗口、时钟与时区（Q7260 TZ 泄漏）——测试自带的 setup 若没有"以自身为起点重置资源"的语义，重放必受环境历史影响；③ **缓存层**：pytest 缓存（Q7005/Q7073 CI 坏缓存）、`__pycache__`、pip 缓存——本地与 CI 缓存历史不同；④ **文件系统残余**：上一次运行留下的临时文件、glob 匹配到了额外文件（Q7237 同名收集同族）。定位套路：把"随机"剥洋葱——先单进程重放，再固定文件系统快照（容器跑），最后逐项 diff 环境变量与外部资源状态。深层教训：**随机顺序暴露的往往不止测试间耦合，还有测试对环境的隐式依赖——这正是它的价值，也是它 annoying 的原因。**

**追问二**：团队历史上一直按顺序绿着跑，现在引入随机顺序会不会造成"CI 全面变红"瘫痪开发？灰度引入的节奏怎么设计？

→ 解析：会有一个"暴露高峰"，节奏设计就是管理这个高峰：① **影子期**：随机顺序先跑在非阻塞 job（失败不挡合并，只出报告），观察两周的失败清单——通常是十几个耦合点，人工认领修复；影子期的另一个产出是"耦合地图"（哪些测试依赖谁），修复有优先级；② **修复期**：按"依赖型优先"（隐式契约迟早断）与"失败频率"排序修，每修一个从影子豁免清单摘一个；③ **阻塞期**：豁免清零后随机顺序转为合并门禁，种子上报 + 同种子重放标准立起来；④ **防复发机制**：新测试单独运行门禁（每个用例必须能独立跑）、fixture 复位断言、模块级可变状态 lint——让耦合进不来，而不是靠随机顺序一直抓。灰度的反模式警告：直接全量打开随机顺序，CI 红屏 + 团队把随机顺序当背锅侠关掉——顺序耦合不会消失只会回到暗中。核心认知：**随机顺序不是测试工具是暴露工具，它的产出是耦合清单，清单修完它就可以退居二线做哨兵。**
