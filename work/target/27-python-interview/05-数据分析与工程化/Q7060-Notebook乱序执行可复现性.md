### Q7060 · Notebook 单元格乱序执行的可复现性事故

难度：P5 | 标签：Notebook、可复现性、报表工程化、洁净重放

**问**：运营 Notebook 导出的月度报表数字和真实值差了 10%，排查发现是分析师调试时把一个单元格多跑了几遍。为什么 Notebook 的"所见数字"不可信？怎么让 Notebook 报表获得脚本级的可复现性？

**答**：
- **结论**：Notebook 的本质是"共享内核状态的有序单元格"，但保存的 .ipynb 只有代码与输出，没有"执行顺序与内核状态快照"——用户可以乱序执行、重复执行、跳过执行，保存文件里的输出可能来自任意一种执行路径。"多跑一次调参单元格"（`rate = rate * 1.05` 这类自我累乘）就足以让数字漂移 10%。修复思路是消灭"交互态"依赖：报表类 Notebook 用洁净重放（papermill 定参、新内核、按存储顺序从头执行）产出数字，导出前与用户屏幕上的数对账，漂移即阻断；带副作用的实验单元格拆出 Notebook 进脚本。
- **取舍**：完全禁 Notebook 会失去探索效率， Notebook 的正确位置是"探索层"而不是"生产层"：探索随便跑，一旦要进报表/定时任务就必须参数化重放（等价于把 Notebook 当函数：输入参数、确定性输出）。重放成本是多一次计算，换来"屏幕上的数字 = 文件里的数字"的保证。
- **实战**：落地清单：① 报表 Notebook 进调度（papermill 注入参数：日期/渠道），产物落存储而非截图；② 保存执行序号与内核会话 ID，审计乱序；③ 关键报表加"洁净重放 diff"检查，漂移超阈值阻断导出并告警。

```python
"""Notebook 单元格乱序执行的可复现性事故与洁净重放。"""
CELLS = [
    "base_rate = 0.05",          # cell 1：基础费率
    "rate = base_rate",          # cell 2：取当前费率
    "rate = rate * 1.05",        # cell 3：调参单元格（实验用，天然不可重复执行）
]

def exec_cells(order: list[int]) -> float:
    """按给定顺序在共享全局态里执行单元格，返回最终 rate。"""
    state: dict[str, float] = {}
    for idx in order:
        exec(CELLS[idx], state)
    return state["rate"]

# 顺序执行（内核未重启）：结果正确
correct = exec_cells([0, 1, 2])
# 事故形态：人工把 cell 3 重跑了两次（调试时点了几下），内核没重启
drifted = exec_cells([0, 1, 2, 2, 2])
print(f"顺序执行 rate = {correct:.4f}")
print(f"cell3 多跑两次 rate = {drifted:.4f}（+{(drifted / correct - 1):.1%}，报表数字悄悄变了）")

# 洁净重放：新内核按存储顺序从头跑一遍，与"用户看到的数"对账
fresh = exec_cells([0, 1, 2])
print(f"洁净重放 rate = {fresh:.4f} -> "
      f"{'一致' if abs(fresh - drifted) < 1e-12 else '发现漂移： notebook 状态不可信，阻断导出'}")
print("治理：报表 notebook 用 papermill 定参重放并保存执行序号；"
      "带副作用的调参单元格拆出 notebook 进脚本；导出前强制洁净重放对账")
```

**追问链**：
1. 追问一层：为什么"保存执行序号"还不够，必须洁净重放？——执行序号只能审计"怎么跑的"，不能证明"保存的输出与该顺序的结果一致"（用户可以先乱序跑再改代码不重跑）；洁净重放是唯一能产生"独立可复现的数字"的方式，对账的本质是两条独立计算路径互证。
2. 追问二层：为什么"调参单元格"（rate = rate * 1.05）是 Notebook 反模式的核心？——它不是幂等的：执行次数进入结果，状态与执行历史耦合。幂等单元格（从固定输入重算）重跑无害，非幂等单元格重跑即漂移——治理的第一步是消除非幂等单元格或把它移出 Notebook。

**背诵要点**：
1. .ipynb 不保存执行顺序与内核状态：屏幕上的数字可能来自任意执行路径。
2. 报表 Notebook 必须 papermill 定参洁净重放 + 重放 diff 对账，漂移即阻断导出。
3. 非幂等单元格（自我累乘类）是漂移根源：拆出进脚本或改成幂等写法。

**复盘追问**：
1. 为什么这类错误在月报里能存活一个月才被发现？（报表的验收是"看起来合理"，10% 的漂移没有对照物；洁净重放 diff 是唯一自动发现手段，上线该检查后这类事故归零）
2. 团队"先跑 A 再跑 B 再回来改 A"的探索习惯怎么治理？（区分场景：探索态不管、产物态强制重放；用调度产物替代截图传播，让"数字的出处"变成可追溯的运行记录）
