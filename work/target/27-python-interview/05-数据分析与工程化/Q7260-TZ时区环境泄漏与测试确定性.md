### Q7260 · 开发机过 CI 挂的日期测试：TZ/locale 环境泄漏与测试确定性

难度：P6 ｜ 标签：时区、TZ 环境变量、locale、测试确定性、flaky

基线：Python 3.12；用 time.tzset 实测同一日期代码在 UTC 与 CST 下的结果差异，演示环境泄漏型 flaky 与显式修复，全标准库实跑。

**问**：一个"按天聚合"的测试在开发机（东八区）永远通过，在 CI（UTC）永远失败，日志里没有任何报错差异只是数字对不上。代码没改、依赖没变，为什么两地结果不同？哪些代码最容易被环境时区"污染"？修复的正确姿势是改 CI 环境还是改代码？

**答**：
- **结论**：这是**环境泄漏型 flaky**：代码里隐式依赖了进程的环境（`TZ` 环境变量、locale），不同环境跑出不同结果。最易中招的四类代码：① `datetime.now()` / `datetime.date()`——now() 带本地时区，跨日临界点（UTC 已到次日、东八区还是今天）时"今天"不同；② `strftime('%x'/'%c')` 与月名/千分位——locale 决定格式；③ 按自然日分组的聚合（`date()` 截断）——分组边界随时区移动；④ `time.localtime` vs `time.gmtime` 混用。修复的原则是**显式化**：代码用 aware datetime（带 tzinfo）或明确传 UTC，测试用夹具固定环境（`TZ=UTC` + `time.tzset()`），断言不依赖"运行机器在哪"。改 CI 环境去迁就代码是反方向——那只是把泄漏从一个环境搬到另一个，下一个开发机又炸（Q227 flaky 治理的归因：环境差异型要用确定性修复）。
- **取舍**：① 业务时区的选择是产品决策（报表按东八区还是 UTC 出），决策落进配置而不是散在代码里（Q2473 日切的谁的今天）；② 测试固定 TZ=UTC 是"最简一致"，但**临界点行为必须另测**：专门写"UTC 15:30 = 东八区 23:30"这类跨界用例，固定 UTC 反而会漏掉跨界 bug；③ locale 泄漏同理：`%x` 格式化进存储/比较路径必炸（数值解析依赖 locale 更隐蔽），存储与比较永远用 ISO 8601/裸数字（Q2484）；④ `time.tzset()` 只在 Unix 有，Windows CI 的等价方案是只依赖 zoneinfo 显式时区、不用 localtime 系。
- **实战**：① 测试套件入口固定 `TZ=UTC`（conftest 或 CI 容器 env），让"环境"不再是变量；② 代码审查清单：`now()`/`date()`/`localtime`/`%x` 是扫描词，出现即要求说明时区假设；③ 跨日临界用例模板化：`23:30 与 00:30 两地分别是什么日期`；④ 同理治理：`os.environ` 读配置的测试也要夹具化（env 泄漏与 TZ 泄漏同族，Q7262 现场留存里要记录 env）。

```python
"""TZ 环境泄漏实测：同一聚合代码在 UTC 与 CST 下的不同结果。"""
import os
import time
import datetime as dt


def daily_agg(ts_utc: list[float]) -> dict[str, int]:
    """按'本地自然日'分组计数 (隐式依赖 TZ 的危险实现)。"""
    out: dict[str, int] = {}
    for t in ts_utc:
        day = time.strftime("%Y-%m-%d", time.localtime(t))
        out[day] = out.get(day, 0) + 1
    return out


def run_under_tz(tz: str, ts_utc: list[float]) -> dict[str, int]:
    old = os.environ.get("TZ")
    os.environ["TZ"] = tz
    time.tzset()                        # Unix: 让 TZ 生效
    try:
        return daily_agg(ts_utc)
    finally:
        if old is None:
            os.environ.pop("TZ", None)
        else:
            os.environ["TZ"] = old
        time.tzset()


def daily_agg_explicit(ts_utc: list[float], tz) -> dict[str, int]:
    """修复: 显式时区的 aware 截断, 不依赖进程环境。"""
    out: dict[str, int] = {}
    for t in ts_utc:
        day = dt.datetime.fromtimestamp(t, tz).strftime("%Y-%m-%d")
        out[day] = out.get(day, 0) + 1
    return out


if __name__ == "__main__":
    # UTC 16:30 = 东八区次日 00:30 -> 跨日临界点样本
    ts = [dt.datetime(2026, 11, 23, 16, 30, tzinfo=dt.timezone.utc).timestamp(),
          dt.datetime(2026, 11, 23, 8, 0, tzinfo=dt.timezone.utc).timestamp()]

    r_utc = run_under_tz("UTC", ts)
    r_cst = run_under_tz("Asia/Shanghai", ts)
    print("隐式本地日聚合:")
    print(f"  UTC 环境:   {r_utc}")
    print(f"  东八区环境: {r_cst}")
    print(f"  同一数据同一代码, 结果{'一致' if r_utc == r_cst else '不同 -> 环境泄漏型 flaky'}")

    CST = dt.timezone(dt.timedelta(hours=8))
    r_fix_utc = daily_agg_explicit(ts, dt.timezone.utc)
    r_fix_cst = daily_agg_explicit(ts, CST)
    print("\n显式时区修复:")
    print(f"  指定 UTC:   {r_fix_utc}  (任何机器跑都一样)")
    print(f"  指定东八区: {r_fix_cst}  (业务时区是配置, 不是环境)")
    ok = r_utc != r_cst and r_fix_utc == {"2026-11-23": 2} and \
        r_fix_cst == {"2026-11-23": 1, "2026-11-24": 1}
    print(f"校验: 泄漏复现 + 显式修复确定性 -> {'通过' if ok else '异常'}")
    print("\n结论：now()/date()/localtime 隐式吃环境 TZ; 修复=显式 aware 时区,")
    print("      测试入口固定 TZ=UTC, 临界点另设跨界用例")
```

**追问一**：为什么固定 TZ=UTC 之后还要专门测临界点？

→ 解析：固定 TZ=UTC 消除的是"环境不确定性"，换来的是全部用例在单一时区视角下跑——但业务真正出事的地方恰是**两个视角不一致的边界**：UTC 15:30（东八区 23:30）之后写入的数据，日切归属两边不同；DST 切换日（Q7093）的重复/跳过小时也是同类。固定 UTC 后这些边界在普通用例里根本不会出现（UTC 的日期边界就是东八区 8:00，恰好是低峰），跨界 bug 被环境固定"藏"住了。所以测试策略分两层：常规用例在固定环境跑保确定性；专门的边界用例显式构造"同一天两边不同"的样本跑正确性。环境固定解决 flaky，显式边界用例解决正确性——两件事别混。

**追问二**：locale 泄漏与时区泄漏的治理有什么不同？

→ 解析：时区泄漏影响"值的边界"（哪一天、哪一小时），locale 泄漏影响"值的形态"（`%x` 在 en_US 是 11/24/2026、在 zh_CN 是 2026/11/24；千分位逗号会让 `float("1,234")` 炸）。治理差异：时区可以全局固定（TZ=UTC 一把梭），locale 却没法简单固定成"无格式"——正确做法是**让格式与解析根本不经过 locale**：存储/传输/比较一律 ISO 8601 与裸数字，locale 只允许出现在"给用户看的最后一步渲染"。扫描词也不同：时区看 now/localtime，locale 看 `%x/%c`、`str(int)` 的分组参数、以及 C 库 `setlocale` 的调用点。两者共同点是隐式全局状态，共同修法都是显式化：时区显式传 tzinfo，locale 显式选 format 函数。
