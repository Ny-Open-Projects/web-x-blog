### Q7035 · 维度历史怎么存：拉链表（SCD2）与每日全量快照的取舍

> 难度:★★★★ | 标签:数仓, 拉链表, SCD

**问**：用户画像/商品主数据天天变，数仓要支持"查任意时点的状态"。全量快照和拉链表（SCD Type 2）各自怎么工作？迟到数据（回拉）怎么处理才不出双链？什么情况下拉链反而更贵？

**答**：结论：全量快照 = 每日一份完整副本，查询简单（取当日分区）但存储 O(天数 × 全量)；拉链表 = 只存变更链段（start/end 生效区间 + 现行标记），存储 O(基线 + 变更量)，支持任意时点查询。**选型看变更率**：低变更率大表（画像、主数据）拉链省一个量级存储；高变更率表拉链退化成"接近全量复制还搭上链查询复杂度"，快照更简单。

机理与实战：
- **拉链写入纪律**："关旧链 + 开新链"必须同事务原子完成；同值幂等不拉链；迟到回拉按**生效时间**（不是到达时间）切开历史区间——包含生效日的链段截短、新链段止于下一段起点前。
- **双链事故**：回拉乱序/并发写入造成同一 key 区间重叠，时点查询返回多行、报表翻倍。防线：管道后置"区间连续性校验"（同 key 链段排序后 end+1 = next.start），断言不过不许发布。
- **查询写法**：时点查询 `WHERE key=? AND start<=? AND (end>=? OR end IS NULL)`；现行状态 `WHERE is_current`（或 end IS NULL）。is_current 必须由 end IS NULL 派生并在同一事务维护，单独维护必然漂移。
- **快照的不可替代场景**：需要"每日全貌"做对比分析（如每日活跃画像宽表）、变更率太高、或下游只要"当日版"——直接取分区比链查询好教好查。

```python
# 基线:Python 3.10+;纯标准库实现拉链表(SCD2)写入/回拉/时点查询与重叠校验
# 真实场景:数仓维度表;拉链 vs 每日全量快照的存储与查询代价对比
from __future__ import annotations
from dataclasses import dataclass


@dataclass
class ChainRow:
    key: str
    value: str
    start: int                                        # 生效日(含)
    end: int | None                                   # 失效日(含);None=现行


class ChainTable:
    def __init__(self) -> None:
        self.rows: list[ChainRow] = []

    def _open_row(self, key: str) -> ChainRow | None:
        return next((r for r in self.rows if r.key == key and r.end is None), None)

    def upsert(self, key: str, value: str, eff_day: int) -> None:
        """变更:关旧链(同事务)开新链;支持迟到回拉(按生效时间切开区间)。"""
        cur = self._open_row(key)
        if cur and cur.value == value:
            return                                    # 无变化不拉链
        if cur and cur.start <= eff_day:              # 正常追加:生效日不早于现行链起点
            cur.end = eff_day - 1                     # 关旧链
            self.rows.append(ChainRow(key, value, eff_day, None))
            return
        # 迟到回拉:eff_day 落在历史区间内 -> 找包含它的链段并切开
        seg = next((r for r in self.rows if r.key == key and r.start <= eff_day
                    and (r.end is None or eff_day <= r.end)), None)
        if seg and seg.value == value:
            return
        if seg:
            if eff_day > seg.start:
                seg.end = eff_day - 1
            else:
                self.rows.remove(seg)                 # 生效日与链段起点重合:整段替换
        later = sorted((r for r in self.rows if r.key == key and r.start > eff_day),
                       key=lambda r: r.start)
        new_end = later[0].start - 1 if later else None
        assert new_end is None or new_end >= eff_day, "回拉区间冲突"
        self.rows.append(ChainRow(key, value, eff_day, new_end))

    def point_in_time(self, key: str, day: int) -> str | None:
        """某时点状态:start <= day <= end(或现行)。"""
        for r in self.rows:
            if r.key == key and r.start <= day and (r.end is None or day <= r.end):
                return r.value
        return None

    def check_overlap(self) -> list[str]:
        """质量断言:同一 key 的链段不得重叠(双链事故)。"""
        problems = []
        by_key: dict[str, list[ChainRow]] = {}
        for r in self.rows:
            by_key.setdefault(r.key, []).append(r)
        for key, rs in by_key.items():
            rs.sort(key=lambda r: r.start)
            for a, b in zip(rs, rs[1:]):
                if a.end is None or a.end >= b.start:
                    problems.append(f"{key}: [{a.start},{a.end}] 与 "
                                    f"[{b.start},{b.end}] 重叠")
        return problems


def storage_cost(days: int, total_rows: int, changed_per_day: int) -> tuple[int, int]:
    """存储行数账:全量快照(每日全副本) vs 拉链(基线+每日变更)。"""
    return days * total_rows, total_rows + days * changed_per_day


def demo() -> None:
    chain = ChainTable()
    chain.upsert("vip:user_1", "普通会员", eff_day=1)
    chain.upsert("vip:user_1", "白银会员", eff_day=10)
    chain.upsert("vip:user_1", "黄金会员", eff_day=20)
    assert chain.point_in_time("vip:user_1", 5) == "普通会员"
    assert chain.point_in_time("vip:user_1", 15) == "白银会员"
    assert chain.point_in_time("vip:user_1", 25) == "黄金会员"
    print("时点查询:5 日/15 日/25 日分别取到对应版本 ✅")
    assert chain.check_overlap() == []
    print("重叠校验通过(链段连续无双链) ✅")

    # 回拉:迟到数据说 12 日就已变更 -> 切开 [10,19] 区间,后续链段不动
    chain.upsert("vip:user_1", "青铜会员", eff_day=12)
    assert chain.point_in_time("vip:user_1", 15) == "青铜会员"
    assert chain.point_in_time("vip:user_1", 10) == "白银会员"
    assert chain.point_in_time("vip:user_1", 25) == "黄金会员"
    assert chain.check_overlap() == []
    print("迟到回拉 ✅:白银缩到 [10,11]、青铜 [12,19]、黄金 [20,∞] 不动,重叠校验通过")

    # 存储账:100 天 × 1 亿行大表,每天改 10 万行
    snap, chained = storage_cost(100, 100_000_000, 100_000)
    print(f"存储账:全量快照 {snap / 1e8:.0f} 亿行 vs 拉链约 "
          f"{chained / 1e6:.0f} 百万行(相差 {snap // chained} 倍) ✅")
    assert chained < snap / 50


if __name__ == "__main__":
    demo()
```

**追问一**：拉链表的"end 用当日-1"还是"end 用当日"？边界口径错会怎样？
答：两种约定都存在，关键是全仓统一——`end = 新链 start - 1`（闭区间无缝）与 `end = 新链 start`（开区间语义）混用会在衔接日产生双行或空档，时点查询在变更日当天结果随实现而异。口径写进建表文档，校验断言按口径实现。

**追问二**：拉链表怎么与"每日快照"共存？
答：常见架构是"拉链为源、快照为市"——拉链表做存储与变更事实源，按需物化出每日快照分区（当日视图）给分析工具；这样既省存储又保留"取分区即用"的易用性，物化任务复用同一时点查询逻辑，口径天然一致。

## 背诵要点
- 选型看变更率：低变更大表用拉链（存储省 1-2 个量级），高变更/要每日全貌用快照；"拉链为源、快照为市"可兼得。
- 写入三纪律：关旧+开新同事务、同值幂等、迟到回拉按生效时间切开区间（找包含段→截短→新段止于下段起点前）。
- 防双链：链段连续性断言（end+1=next.start）作为发布门禁；is_current 必须由 end IS NULL 同事务派生。

## 复盘追问
- 财务说"上季度某用户 15 号的等级不对"，你在拉链表里怎么查证与修复？（提示：时点查询定位链段 → 用到达时间/生效时间双时间轴判断是回拉还是错数据 → 回拉重算区间并跑重叠校验）
- 拉链表跑了三年后链查询变慢，怎么办？（提示：现行链分区隔离（is_current 独立分区）、历史链按年分区 + start/end 索引、冷历史归档压缩）
