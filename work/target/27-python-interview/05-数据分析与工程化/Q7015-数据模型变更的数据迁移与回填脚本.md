### Q7015 · 特征回填与训练数据版本化

> 难度:★★★ | 标签:ML 工程, 特征管理, 数据版本

**问**：线上加了新特征（用户近 30 天行为数），模型重训练要回填历史 6 个月——为什么直接按今天的口径回填会引入**数据泄漏**？训练数据集要版本化哪些东西（特征值/口径/上游数据快照），特征口径「线上推理 vs 离线回填」不一致的经典事故长什么样？

**答**：① **回填的泄漏陷阱**：新特征是「用户近 30 天行为数」，回填 6 个月前样本时若用**当前时刻**的行为数算，就等于把「未来信息」喂给了历史样本——模型离线指标虚高、上线即衰减。正确口径：回填必须按**每条样本的时间点**取它当时可见的数据（point-in-time join），行为表按样本时间做 ASOF join。② **训练数据版本化**四要素：特征定义（口径代码的 git sha）、上游快照（行为表当日分区指针，不是数据全拷）、特征值物化（parquet + 数据指纹）、标签集——四者绑定成一个 dataset hash，模型卡记录这个 hash，「模型 v12 用 dataset a3f2」可复现。③ **线上/离线口径不一致**（training-serving skew）经典形态：离线用 SQL 算「近 30 天」按自然日截断，线上服务按滚动秒计算——同一用户两边差 3%，模型对特征敏感时直接影响排序。防法：特征逻辑单一实现（feature store 双端共用），或离线回填直接调线上特征服务回放。

```python
# 全部标准库；demo 演示 point-in-time 回填 vs 泄漏回填的差异与 dataset 指纹
import hashlib, json, bisect

BEHAVIORS = [                                  # 用户行为表 (ts, user, event)，按 ts 有序
    (0,   "u1", "view"), (10, "u1", "click"), (40, "u1", "buy"),
    (0,   "u2", "view"), (25, "u2", "click"),
]

def pit_feature(user: str, sample_ts: float, window: float = 30) -> int:
    """Point-in-time：只统计 sample_ts 之前 window 内的行为（当时可见）。"""
    rows = [ts for ts, u, _ in BEHAVIORS if u == user]
    lo = bisect.bisect_left(rows, sample_ts - window)
    hi = bisect.bisect_left(rows, sample_ts)   # 关键：hi 排除未来
    return hi - lo

def leaky_feature(user: str, window: float = 30) -> int:
    """泄漏口径：不管样本时间，用全表统计 —— 未来行为混入历史样本。"""
    return sum(1 for ts, u, _ in BEHAVIORS if u == user)

def dataset_fingerprint(spec: dict) -> str:
    """dataset 指纹 = 口径代码 sha + 上游分区指针 + 参数。"""
    content = json.dumps(spec, sort_keys=True)
    return hashlib.sha256(content.encode()).hexdigest()[:12]

if __name__ == "__main__":
    sample_ts = 12                             # 训练样本时间点：t=12
    pit = pit_feature("u1", sample_ts)         # 只能看到 t<=12 的行为
    leaky = leaky_feature("u1")
    assert pit == 2 and leaky == 3
    print(f"PIT 回填={pit}（正确）vs 泄漏回填={leaky}（把 t=40 的 buy 也算进去了）")
    ds = dataset_fingerprint({
        "feature_code_sha": "a1b2c3",
        "upstream_partitions": ["behaviors/2026-06-01", "behaviors/2026-06-02"],
        "window_days": 30, "labels": "churn_v3",
    })
    print("dataset 指纹:", ds, "→ 模型卡记录，可复现训练")
    # skew 防法：feature store 单一实现（离线回填调线上服务回放），
    # 或离线/在线双实现 + 一致性监控（同输入双算对比，差异>阈值告警）。
```

**追问**：1) point-in-time join 的实现难点？——行为表要按时间分区且样本 join 用 ASOF 语义（取样本时间前最近值），SQL 层各家方言差异大（PG `LATERAL`、Spark `asof join`）；特征量大时离线回填是重计算任务，要分片跑（Q7015 与 A104 租约结合）。2) 为什么上游快照用「分区指针」而不是拷数据？——拷数据成本爆炸且与数仓单源真相冲突；指针指向不可变分区（数据湖的 time-travel 语义），复现时重新读同分区即可。3) skew 监控怎么落地？——采样线上请求特征值与离线同口径重算对比，分布漂移（PSI，Q7009）+ 数值误差双阈值告警。

## 背诵要点
1. 回填铁律：point-in-time join——每条样本只取它当时可见的数据，禁用全表口径（泄漏）。
2. 数据集版本四要素：口径代码 sha + 上游分区指针 + 特征物化指纹 + 标签集 → dataset hash 进模型卡。
3. training-serving skew 防法：特征逻辑单一实现或双实现 + 一致性监控（PSI/误差阈值）。

## 复盘追问
1. 模型上线后效果远低于离线评估，先查什么？（提示：先查 skew（特征口径/分布），再查泄漏导致的虚高（离线指标好到不真实即红旗），最后查服务时序）
2. 特征回填任务跑 8 小时中断怎么办？（提示：按时间分片 + 水位表断点（Q6515 归档流水线同构），失败分片重跑幂等）
