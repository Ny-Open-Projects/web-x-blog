### Q7214 · float16 的精度悬崖：2048 之后还有整数吗

难度：P6 ｜ 标签：numpy、float16、半精度、累加误差

基线：Python 3.12；numpy 1.26/2.x `np.float16`（或用标准库 struct 的 `e` 格式）；纯标准库演示。

**问**：为了省内存把特征矩阵从 float32 降到 float16，离线评估没变化，线上却出现"同一个用户两次打分相差 2 分"、大 ID 特征全部撞在一起。float16 只有 16 位，到底能精确表示多大的整数？为什么累加会越加越偏？

**答**：
- **结论**：IEEE 754 half 的规格是 1 符号 + 5 指数 + 10 尾数，**尾数只有 10 位**，因此：① `[0, 2048]` 内的整数可精确表示，2048 之后步长变成 2，4096 之后变成 4，越大越粗；② 最大有限值 `65504`，再大就溢出成 `inf`；③ 最小正规格数约 `6.1e-5`，更小进入次正规/下溢。两个后果：大整数 ID、金额、计数器在 float16 里会被**舍入到邻近值**（不同 ID 撞成同一个数）；连续累加时每次都要舍入，误差随步数累积，不是简单的"精度低一点"。
- **取舍**：float16 的收益是内存减半、GPU 吞吐翻倍（tensor core），适合**推理/存储**；训练时梯度动态范围大，直接半精度会下溢成 0 或溢出成 inf，需要 **loss scaling + float32 master weights**。数据分析里更要谨慎：pandas/numpy 的聚合默认会把 float16 提升到 float32/64 计算，存进去省的内存可能在计算时又还回去，且中间结果精度不可控。
- **实战**：① ID、金额、时间戳等"必须精确"的列永远不要用 float16；② 需要半精度时先做 `astype(np.float16)` 后的**回读校验**（`(x.astype(np.float16).astype(np.float64) - x).max()`）；③ 聚合前显式升到 float32/64，别让累加在低精度里跑；④ 训练侧用 AMP（autocast + GradScaler），不要手工把整个模型转 half。

```python
"""用标准库 struct 的 'e'（IEEE 754 half）演示 float16 的表示边界。"""
import struct


def f16(x: float) -> float:
    """把 Python float 舍入到最近的 float16 可表示值（溢出按 numpy 语义给 inf）。"""
    try:
        return struct.unpack("e", struct.pack("e", x))[0]
    except (struct.error, OverflowError):
        return float("inf")


if __name__ == "__main__":
    print("2048 附近:", [f16(v) for v in (2047, 2048, 2049, 2050, 2051)])
    print("4096 附近:", [f16(v) for v in (4095, 4096, 4097, 4098, 4099)])

    big_ids = [2049, 2050, 2051]
    print("大 ID 映射:", [(i, f16(i)) for i in big_ids],
          "-> 不同 ID 撞成同一个值")

    print("上限:", f16(65504), "溢出:", f16(65520))
    print("最小正规格:", f16(6.103515625e-05), "更小:", f16(1e-8))

    total = f16(0.0)
    for _ in range(1000):
        total = f16(total + f16(0.1))
    print(f"累加 1000 次 0.1 -> {total}（真值 100.0，误差 {abs(total - 100):.3f}）")
    print("结论：float16 适合存不适合算；ID/金额/累加必须用更高精度")
```

**追问一**：为什么 float16 的累加误差不是线性的，而是可能突然跳变？
→ 解析：误差取决于当前累加值落在哪个 binade（2 的幂区间）。值越大，相邻可表示数的间隔越大（2048 后间隔 2，4096 后 4）。当累加值跨过 2048 这个边界，同样的 `+0.1` 可能直接被舍入掉（加不动），误差从"每次舍一点"变成"完全停止增长"，表现为平台期或跳变。

**追问二**：混合精度训练里，为什么必须保留一份 float32 的权重副本？
→ 解析：float16 的尾数只有 10 位，参数更新的步长（学习率 × 梯度）常常小于当前权重的可表示间隔，直接更新会被舍入成 0，训练停滞。float32 master weights 负责累积微小更新，前向/反向用 float16 提速；再配合 loss scaling 把梯度放大到 half 的可表示范围，避免下溢。
