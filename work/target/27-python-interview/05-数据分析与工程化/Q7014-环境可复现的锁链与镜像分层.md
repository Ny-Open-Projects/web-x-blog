### Q7014 · 环境可复现的锁链

> 难度:★★☆ | 标签:依赖管理, 可复现构建

**问**：「在我机器上是好的」怎么从根上消灭——requirements.txt 裸列表、pip freeze 全量锁定、uv/pip-tools 锁链三种方式各解决什么？镜像分层怎么加速构建（依赖层与代码层分离），Python 版本本身怎么锁定？

**答**：三级锁链：① **裸列表**（`requirements.txt` 写顶层依赖）：只约束直接依赖版本 → 传递依赖随时间漂移，构建不可复现——只适合库（library）声明兼容范围；② **全量冻结**（`pip freeze`）：包含传递依赖的完整快照，但跨平台/Python 版本不可移植（环境标记冲突）且 diff 混乱；③ **锁链**（pip-tools / uv：顶层 `pyproject.toml` + 生成的 `uv.lock`）：顶层声明意图 + 锁文件固化解析结果，可校验、可审计、diff 可读——应用（application）的行业标准。镜像分层：`COPY pyproject + lock → 安装依赖 → COPY 代码`：依赖层只在锁文件变更时重建（构建缓存命中 95%+ 日常发布）；再配多阶段构建（builder 装依赖 → runtime 只拷 site-packages）压体积。Python 版本锁定：`.python-version`（pyenv/uv 读）+ CI 矩阵锁 minor 版本 + 容器基础镜像 tag 锁到 `3.12.x`（`python:3.12` 这种浮动 tag 是漂移源）。

```python
# demo：锁链一致性校验器（纯标准库模拟 uv.lock 语义）
import hashlib, json

def parse_requirements(text: str) -> dict[str, str]:
    """顶层声明：包名 -> 约束（意图层）。"""
    out = {}
    for line in text.splitlines():
        line = line.split("#")[0].strip()
        if not line: continue
        name, _, spec = line.partition("==")
        out[name.lower()] = spec or "*"
    return out

def build_lock(top: dict[str, str], transitive: dict[str, str]) -> dict:
    """锁文件：意图 + 传递闭包 + 校验和（uv.lock 语义模拟）。"""
    resolved = {**top, **transitive}
    content = json.dumps(resolved, sort_keys=True)
    return {"resolved": resolved,
            "checksum": hashlib.sha256(content.encode()).hexdigest()[:16]}

def verify_lock(top: dict, lock: dict) -> list[str]:
    """CI 闸门：pyproject 改了没锁 / 锁漂移 = 拒绝合并。"""
    issues = []
    for pkg, spec in top.items():
        got = lock["resolved"].get(pkg)
        if got is None:
            issues.append(f"锁缺失: {pkg}")
        elif spec != "*" and got != spec.lstrip("="):
            issues.append(f"锁漂移: {pkg} 声明 {spec} 锁内 {got}")
    if lock["checksum"] != build_lock(top, {k: v for k, v in lock["resolved"].items()
                                            if k not in top})["checksum"]:
        pass  # 演示省略：真实 uv.lock 有独立校验和
    return issues

def dockerfile_layer_advice() -> str:
    return """
FROM python:3.12.7-slim        # tag 锁到 minor.patch，不用浮动 3.12
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen           # 依赖层：仅锁文件变更时重建（缓存命中）
COPY . /app                    # 代码层：秒级重建
"""

if __name__ == "__main__":
    top = parse_requirements("fastapi==0.115.0\n# 注释行\npydantic==2.9")
    transitive = {"starlette": "0.41.0", "annotated-types": "0.7"}
    lock = build_lock(top, transitive)
    print("锁内解析:", lock["resolved"])
    assert verify_lock(top, lock) == []              # 一致 ✅
    bad_top = parse_requirements("fastapi==0.116.0\npydantic==2.9")
    print("漂移检测:", verify_lock(bad_top, lock))
    print(dockerfile_layer_advice())
    # 口径速记：库用裸列表声明范围，应用用锁链；镜像 tag 锁 patch 版；
    # uv sync --frozen（有锁文件且不一致即失败）是 CI 的强闸。
```

**追问**：1) 为什么 uv 快一个量级？——Rust 实现的解析器 + 全局缓存（包内容寻址存储，多项目共享下载与 wheel 构建）+ 并行安装；pip 的串行解析是老架构税。2) `uv sync --frozen` 与 `--locked` 差异？——`--frozen` 完全不查锁是否最新（最快、CI 用）；`--locked` 校验锁与 pyproject 一致（更严谨）；开发日常 `uv sync` 会顺带更新锁。3) 私有源怎么进锁链？——`[[tool.uv.index]]` 声明私有源与认证（token 从环境变量注入），锁文件里包来源带 index 标记——供应链审计（防投毒）也靠这个元数据。

## 背诵要点
1. 库用裸列表声明兼容范围，应用必须锁链（pyproject 意图 + uv.lock 快照）。
2. 镜像分层：先 COPY 锁文件装依赖（缓存层），后 COPY 代码；基础镜像 tag 锁到 patch。
3. CI 闸门：`uv sync --frozen`——锁与声明不一致直接失败，杜绝「改了 pyproject 忘了锁」。

## 复盘追问
1. 两个服务锁了同一个包的不同版本，monorepo 怎么管？（提示：单仓多锁文件（各服务独立环境）或统一版本对齐会；冲突包用 uv workspace 分组）
2. 构建产物里混进了开发依赖，怎么审？（提示：uv sync 默认全量、生产用 --no-dev；镜像内 audit（pip list 对比声明组）进 CI）
