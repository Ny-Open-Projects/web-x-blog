### Q7272 · 周末全在告警：监控基线的周期建模与动态阈值

难度：P6 ｜ 标签：监控基线、动态阈值、周期建模、告警噪音、同环比

基线：Python 3.12；实现"同期基线 ± 带宽"的动态阈值模型，对比静态阈值在周期性负载上的误报与故障捕获，全标准库实跑。

**问**：告警群里周末永远在响"流量骤降"——周末流量本来就低，静态阈值不知道。带周期性的业务指标（QPS/订单量/GMV）怎么做基线？动态阈值的带宽怎么定？基线数据自己被污染（故障时段混进基线）怎么办？

**答**：
- **结论**：周期性负载的正确模型是**同期基线**：`基线(时段) = 历史同时段均值 × 星期系数 × 节假日修正`，阈值变成 `基线 × (1 ± 带宽)`——本卡实现"下浮 50% 才告警"：周三故障（流量跌 80%）触发告警，周六自然回落（基线本身就是 0.3 倍）不触发。静态阈值在周期负载上必然出现两难：阈值设高（周末天天误报）设低（工作日故障抓不住）——因为它假设了负载平稳，而业务负载的周期振幅往往超过故障信号幅度。带宽的定法：按历史同时段的**分布离散度**（P5-P95 区间）而非拍脑袋百分比：波动大的时段宽带、平稳时段窄带，让告警灵敏度跟随时段自适应。
- **取舍**：① 基线窗口的长度：太短（一周）周月节奏学不全、太长（三个月）业务形态漂移后基线过时——常见 4-8 周滚动窗口 + 近期权重更高；② 节假日处理：法定节假日、大促日的负载形态完全不同，硬学进基线会把"节后第一个工作日"学成"异常"——节假日表单独建模，基线计算剔除；③ **基线自污染**：故障时段的数据混进历史窗口，会把下次故障的基线抬高（故障后基线里留着跌下来的坑）——基线计算必须剔除"已告警时段"或用中位数/截尾均值抗野点；④ 动态阈值解决"什么是异常"，不解决"异常了做什么"——响应预案仍是运维资产（Q7039 静默与维护窗口治理）。
- **实战**：① 指标分类先行：平稳型（错误率）用静态阈值，周期型（流量/GMV）用同期基线，趋势型（存储增长）用回归预测——一招鲜的告警策略必然一半误报一半漏报；② 告警评估闭环：误报/漏报每周复盘，反哺带宽与模型，Q7249 告警噪音治理的量化抓手；③ 多窗口确认防毛刺：单点越界不告警、连续 3 个周期越界才告警（毛刺与持续异常的区分）；④ 基线服务化：基线计算与告警判定分离部署，基线坏了可以独立降级回静态阈值。

```python
"""Q7272 监控基线动态阈值: 同环比周期建模 vs 静态阈值, 周末降流量不再误报。"""
# 周期建模: 小时基线 * 星期系数; 简化为: 每小时历史均值表
HOUR_BASE = {h: 1000 if 9 <= h <= 21 else 300 for h in range(24)}
WEEK_FACTOR = {"Mon": 1.0, "Tue": 1.0, "Wed": 1.0, "Thu": 1.0, "Fri": 1.0,
               "Sat": 0.3, "Sun": 0.3}
STATIC_THRESHOLD = 500          # 静态告警线


def baseline(day: str, hour: int) -> float:
    return HOUR_BASE[hour] * WEEK_FACTOR[day]


def static_alert(qps: float, hour: int) -> bool:
    return qps < STATIC_THRESHOLD        # 流量骤降告警(静态)


def dynamic_alert(qps: float, day: str, hour: int, band: float = 0.5) -> bool:
    base = baseline(day, hour)
    return qps < base * (1 - band)       # 同期基线下浮 50% 才告警


if __name__ == "__main__":
    # 一周流量: 工作日正常, 周末自然回落, 周三有真实故障(骤降 80%)
    week = [("Mon", 14, 1020), ("Wed", 14, 200), ("Sat", 14, 310), ("Sun", 14, 290)]
    print(f"{'时段':<12}{'实际':>6} {'静态阈值':>8} {'动态阈值':>8}")
    fp, tp = 0, 0
    for day, hour, qps in week:
        sa = static_alert(qps, hour)
        da = dynamic_alert(qps, day, hour)
        if sa and day in ("Sat", "Sun"):
            fp += 1
        if da and day == "Wed":
            tp += 1
        print(f"{day} {hour:02d}:00  {qps:>5}  {'告警' if sa else '-':>5}      "
              f"{'告警' if da else '-'}   (基线 {baseline(day, hour):.0f})")
    ok = fp == 2 and tp == 1 and not dynamic_alert(310, "Sat", 14)
    print(f"校验: 静态误报 {fp} 次, 动态 0 次误报且抓到真故障 -> {'通过' if ok else '异常'}")
    print("结论：带周期的指标用'同期基线±带宽', 静态阈值在周期性负载上必然误报;")
    print("      基线数据要剔除节假日与故障时段, 否则坏样本会污染基线本身")
```

**追问一**：为什么用"P5-P95 区间"定带宽比"固定百分比"更合理？举一个固定带宽会失效的例子。

→ 解析：固定百分比（±50%）假设负载波动均匀，但真实时段的波动幅度差异巨大：午高峰 14:00 的 QPS 可能 ±10% 内稳定，凌晨 03:00 的定时任务窗口 QPS 在 50→5000 间跳变（批处理间歇流量）——凌晨用 ±50% 带宽，批处理启动瞬间"暴涨 90 倍"会告警（误报），批处理结束"跌到 50"也会告警（再误报）。P5-P95 区间直接描述**该时段的历史分布**：凌晨区间天然 [50, 5000]，带宽覆盖真实跳变；午高峰区间窄，±10% 就能抓细微异常。更进一步用分位数还能顺带回答"多异常算异常"：观测值落在 P5 以下是"历史 95% 的同时刻都没这么低"——统计学上有意义的异常定义。成本是多存一份时段分布（几十个百分位数），比"基线 ± 固定比例"多一档精度，告警降噪的投入产出比极高。

**追问二**：基线被污染的完整链条是什么？除了剔除坏时段还有什么结构性防御？

→ 解析：污染链条：故障发生 → 流量跌到基线下方 → 告警触发 → 但故障时段的数据**仍然流进滚动基线窗口** → 下周同时段的基线被拉低 → 故障恢复后正常流量反而"高于新基线"（涨了不告警）或下次故障"跌得不够深"（漏报）——**告警系统用自己响过的时间污染自己的参照系**。防御分三层：① 输入层剔除：基线计算排除"已确认故障时段"（告警事件表 join 进基线作业）与节假日表；② 稳健统计：中位数/截尾均值代替算术平均，单个坏时段的污染权重被压缩；③ 结构性防御——**基线快照版本化**：每周固化基线版本，本周告警判定用上周快照而非滚动实时值，故障对基线的影响延迟一周生效且可回滚；④ 终极防线是人工评审：基线周环比变化超过阈值（如 30%）必须人工确认后才生效——业务形态真的变了（新产品上线）还是污染，机器判不了，人判得了。监控系统的可靠性自身也要被监控——这是元监控的核心一课。
