### Q7098 · 抢占式/竞价实例的计算成本账与重试策略

难度：P6 ｜ 标签：成本工程 / 抢占式实例 / 批处理

**问**：批处理团队想把计算 worker 全换成抢占式实例（Spot/Preemptible，价格约为按需的 30%），结果高峰期任务反复被回收，重跑成本反超省钱幅度。这笔账怎么算？什么负载适合抢占式、什么不适合？

**答**：
- **结论**：抢占式实例的有效成本不是"单价 × 时长"，而是 `单价 × (1 / 完成率)` 再加重跑的固定成本。关键变量是**检查点（checkpoint）粒度**：任务支持从断点续跑时，回收只损失最后一个 checkpoint 之后的部分（重跑成本 ≈ 平均进度 × 固定成本）；不支持续跑时每次回收损失 100%，完成率的下降直接把成本优势吃掉，甚至任务在截止时间前根本跑不完（时效性损失是隐性账里最贵的一项）。分界经验：无状态、可分片、容忍中断的负载（批量数据转换、模型离线推理、渲染）适合抢占式；长事务型、有外部副作用、严格 SLA 的负载（结算任务、上游强依赖的同步任务）用按需或预留。
- **取舍**：混合策略通常最优：关键路径（截止时间硬约束）用按需/预留打底，弹性部分（可延迟的批任务）用抢占式填充，且抢占式 worker 必须带"回收信号处理"（云厂商给 30s-2min 预警窗口，进程要在此窗口内 flush checkpoint 后优雅退出）。重试策略上，抢占式回收不是"异常重试"，指数退避反而有害——应该立即申请新实例续跑，退避只留给真正的故障。
- **实战**：算账步骤：① 实测回收率与回收时长分布（不同可用区/时段差异大）；② 按 `有效成本 = 单价 × 期望尝试次数 + 固定启动成本 × 尝试次数` 建模，尝试次数 = 1/(1-回收率)（checkpoint 有效时更小）；③ 检查点写入频率做成可调参数，用成本模型反推最优粒度（过密拖慢主任务、过疏重跑代价大）；④ 复盘项：记录"截止时间违约率"，成本账必须包含时效维度。

```python
# 抢占式实例有效成本模型（纯标准库）
# 基线：Python 3.9+

def effective_cost(
    ondemand_price: float, spot_ratio: float = 0.3,
    reclaim_rate: float = 0.2, checkpoint_coverage: float = 0.0,
    startup_cost: float = 1.0,
) -> dict:
    """期望有效成本（以按需单价为 1 个货币单位）
    checkpoint_coverage: 每次回收可挽回的进度比例（0-1）
    模型：spot 单价 + 回收率 × 不可挽回比例 × 全额重跑代价"""
    spot_price = ondemand_price * spot_ratio
    redo = spot_price + startup_cost
    p_fail = reclaim_rate * (1 - checkpoint_coverage)
    total = spot_price + p_fail * redo
    e_attempts = 1 / max(1e-9, 1 - p_fail)
    return {"e_attempts": round(e_attempts, 2),
            "effective_cost": round(total, 3),
            "vs_ondemand_pct": round(total / ondemand_price * 100, 1)}


def main() -> None:
    # 无 checkpoint：回收率 20% → 重跑代价全额计入
    no_ckpt = effective_cost(1.0, 0.3, 0.2, 0.0, 1.0)
    print(no_ckpt)
    assert no_ckpt["effective_cost"] > 0.5   # 已接近按需一半，价差被吃掉大半
    # checkpoint 覆盖 90%：回收代价极小 → 成本优势保住
    with_ckpt = effective_cost(1.0, 0.3, 0.2, 0.9, 0.2)
    print(with_ckpt)
    assert with_ckpt["effective_cost"] < 0.35
    print("OK: checkpoint 覆盖率决定抢占式是否真省钱")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么抢占式回收的恢复不该用指数退避？
→ 一句话提示：回收是容量事件不是故障，退避只会把任务往后推、加剧错过截止时间；正确动作是立刻换实例/可用区续跑，指数退避保留给真实错误（如配额拒绝）。

**追问 2**：checkpoint 写入过密会拖慢主任务，怎么找最优频率？
→ 一句话提示：把"checkpoint 开销（吞吐损失）+ 期望重跑成本（回收率 × 平均进度损失）"合成总成本函数对频率求极小；工程上用几组频率实测画出 U 型曲线取谷底。

## 背诵要点
- 有效成本 = 单价 × 期望尝试次数 + 启动成本 × 次数；无 checkpoint 时回收率 20% 就可能吃掉 70% 的价差。
- 混合策略：硬截止路径用按需打底，弹性批任务用抢占式填充；回收预警窗口（30s-2min）内必须 flush checkpoint 优雅退出。
- 回收恢复立即换实例续跑（非异常退避）；成本账必须含时效维度（截止时间违约率）。

## 复盘追问
- 为什么"全部换 Spot 省钱"在高峰期会自我失败？提示：全市场竞价需求随时段波动，高峰回收率飙升且可能申请不到实例；容量账要按时段建模并预留按需兜底，否则截止时间违约的隐性成本最高。
- checkpoint 存到哪也有成本账吗？提示：有——checkpoint 写对象存储有请求与存储费、写本地盘则实例回收即丢失；状态大小决定存储介质选择，大状态还要考虑分片上传的成本与时长。
