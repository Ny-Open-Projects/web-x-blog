### Q7013 · 灰度发布指标护栏

> 难度:★★★ | 标签:发布, 监控, 回滚

**问**：灰度 5% 流量上线新版本——护栏指标选哪些（错误率/延迟分位/业务指标）？「对比基线怎么算公平」（新旧版本流量不同、时间不同）？自动回滚的触发条件、防误滚（抖动）与防漏滚（钝感）怎么平衡？

**答**：① 指标三组：**可用性**（5xx 率、超时率）、**性能**（P99/P95 延迟，不是均值——灰度毛刺藏在分位里）、**业务**（转化率/支付成功率等下游信号，技术指标全绿但业务指标跌 = 逻辑错误型事故）。② 公平基线：同版本同时段对比（新版本灰度流量 vs 旧版本同期流量——消除日间波动）；或金丝雀镜像流量（shadow）；样本量不足时分位数的置信区间要算（5% 灰度下 P99 样本可能只有几十个，别直接比）。③ 触发条件分层：**硬条件**（5xx 率超基线 3σ 或绝对阈值）立即回滚；**软条件**（延迟 +20% 持续 5 分钟）告警人工决策。④ 防抖动：连续窗口判定（连续 3 个 1 分钟窗口超阈值才算，单点毛刺不算）、最小样本量门槛；防钝感：窗口太长会放大事故——**分级扫描间隔**（发布后 10 分钟每分钟扫，稳定后降频）。回滚动作必须预演过（发布演练含回滚演练，A106 联动）。

```python
# 全部标准库；demo 实现护栏判定器（σ 阈值 + 连续窗口 + 最小样本）
import statistics, random, time

class Guardrail:
    def __init__(self, baseline_error_rate: float = 0.005,
                 window_min: int = 3, min_samples: int = 100, sigma: float = 3.0):
        self.base = baseline_error_rate
        self.window, self.min_n, self.sigma = window_min, min_samples, sigma
        self.streak = 0
    def evaluate(self, error_rate: float, samples: int, latency_p99: float,
                 base_p99: float) -> str:
        if samples < self.min_n:
            return "insufficient-samples"          # 防误判：样本不足不判定
        hard = error_rate > self.base + self.sigma * (self.base ** 0.5) or \
               latency_p99 > base_p99 * 2.0
        if hard:
            self.streak += 1
            if self.streak >= self.window:          # 连续窗口才触发（防单点毛刺）
                return "ROLLBACK"
            return f"warning {self.streak}/{self.window}"
        self.streak = 0
        return "healthy"

def canary_report(total: int, errors: int, p99: float) -> tuple[float, int]:
    return errors / total, total

if __name__ == "__main__":
    random.seed(3)
    g = Guardrail()
    timeline = [
        (500, 1, 0.20),   # 5xx 1/500 = 0.2% 健康
        (300, 9, 0.22),   # 3% 错误率 → warning 1/3
        (280, 11, 0.25),  # warning 2/3
        (260, 12, 0.30),  # 连续第 3 窗 → ROLLBACK
    ]
    base_p99 = 0.18
    for total, err, p99 in timeline:
        rate, n = canary_report(total, err, p99)
        verdict = g.evaluate(rate, n, p99, base_p99)
        print(f"err={rate:.1%} p99={p99:.2f}s → {verdict}")
        if verdict == "ROLLBACK":
            print("自动回滚触发（发布流量切回旧版本）✅")
            break
    g2 = Guardrail()
    assert g2.evaluate(0.006, 50, 0.19, base_p99) == "insufficient-samples"
    print("小样本不判定（防误滚）✅")
```

**追问**：1) 为什么业务指标也进护栏？——「技术全绿业务跌」的经典形态：接口 200 正常返回但金额算错（新版本逻辑 bug），只有下游业务指标（GMV/支付成功率）能暴露——护栏必须跨层。2) 分位数在 5% 灰度下怎么算稳？——加大窗口时间、用直方图桶聚合（metric 侧 HDR histogram）而非日志明细；样本不足时对 P99 用 Wilcoxon/bootstrap 置信区间，显著恶化才触发。3) 回滚后怎么避免「立刻再发」？——回滚事件自动创建事故工单 + 发布冻结窗口（比如 24h 内同服务禁止新发布，除非 hotfix 审批），防止边修边炸循环。

## 背诵要点
1. 护栏三组指标：可用性（5xx）、性能（P99 分位不看均值）、业务（下游信号抓逻辑错误）。
2. 公平基线：同版本同时段对比或金丝雀镜像；小样本用置信区间，5% 灰度 P99 别直接比。
3. 触发分层：硬条件（3σ/绝对阈值）+ 连续窗口自动滚，软条件告警人工；扫描间隔分级防钝感。

## 复盘追问
1. 灰度 1% 时护栏几乎测不出问题，怎么补？（提示：请求放大（影子流量/回放录制流量）+ 灰度比例阶梯（1→5→25→100 每阶过闸））
2. 自动回滚把一个「正常重部署」误杀了，怎么复盘改进？（提示：区分部署事件与错误事件（版本标签维度聚合）、基线按版本动态重置）
