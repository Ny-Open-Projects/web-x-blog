### Q7040 · 数据质量规则分层

> 难度:★★☆ | 标签:数据质量, ETL, 门禁

**问**：数据质量问题在下游报表才被发现（老板的周报数字错了）——质量规则应该放在管道哪几个门禁点（摄入/转换/出口各拦什么），规则分层（schema/完整性/准确性/一致性）怎么排优先级，「快速失败 vs 带毒前行」怎么决策（拦下整批还是隔离坏行继续）？

**答**：① 门禁三层：**摄入层**拦结构性问题（schema 不符/编码错误——成本最低，坏了别进来）、**转换层**拦完整性（空值率/值域/去重——转换时上下文最全）、**出口层**拦业务一致性（跨表对账/环比突变——只有算完才知道）。② 优先级排法：按「污染扩散半径」——schema 错会毒化所有下游（最高优先），单表准确性错只毒自己；**越上游的规则越该硬**（fail-fast），出口层规则偏「告警+快照」（数据已到用户门口，拦下整批的代价是 SLA 违约）。③ 快速失败 vs 隔离继续的决策矩阵：**结构性错误 → 快速失败**（整批拒收，上游修了重跑——半批数据进库更难清理）；**行级质量问题 → 隔离继续**（坏行进死信表+计数，好行继续——整批里 0.1% 坏行不值得拦 99.9%）；**一致性突变 → 告警+冻结下游**（不自动修，人工判断是数据错了还是业务真变了）。④ 质量规则本身要可测试（规则误报率监控——规则系统也是系统）。

```python
# 全部标准库；demo 实现「三层门禁 + 死信隔离 + 突变冻结」
import statistics
from collections import deque

class QualityGate:
    def __init__(self, history: int = 10):
        self.dlq: list[dict] = []                       # 死信表
        self.metric_history: deque = deque(maxlen=history)
    def ingest_gate(self, batch: list[dict]) -> tuple[list[dict], list[dict]]:
        """摄入层：schema 快速失败（整批拒收）。"""
        required = {"id", "amount", "ts"}
        if any(not required <= set(r) for r in batch):
            raise ValueError("schema 违规：整批拒收（快速失败）")
        return batch, []
    def transform_gate(self, rows: list[dict]) -> tuple[list[dict], list[dict]]:
        """转换层：行级隔离（坏行进死信，好行继续）。"""
        good, bad = [], []
        for r in rows:
            if r["amount"] < 0 or r["amount"] > 1e7:
                self.dlq.append({"reason": "amount 越值域", "row": r})
                bad.append(r)
            else:
                good.append(r)
        return good, bad
    def consistency_gate(self, today_sum: float) -> str:
        """出口层：环比突变检测（告警+冻结，不自动修）。"""
        self.metric_history.append(today_sum)
        if len(self.metric_history) < 5:
            return "warming-up"
        base = statistics.median(list(self.metric_history)[:-1])
        drift = abs(today_sum - base) / max(base, 1)
        if drift > 0.5:
            return f"ALERT 冻结下游（突变 {drift:.0%}，人工判断数据错 or 业务变）"
        return "pass"

if __name__ == "__main__":
    g = QualityGate()
    good_batch = [{"id": i, "amount": 100.0, "ts": 0} for i in range(5)]
    out, _ = g.ingest_gate(good_batch)
    try:
        g.ingest_gate([{"id": 1, "amount": 5.0}])       # 缺 ts 字段
    except ValueError as e:
        print("摄入层快速失败:", e)
    mixed = good_batch + [{"id": 9, "amount": -5, "ts": 0}]
    good, bad = g.transform_gate(mixed)
    assert len(good) == 5 and len(bad) == 1 and g.dlq[0]["reason"]
    print(f"转换层隔离: 好行 {len(good)} 继续，坏行 {len(bad)} 进死信 ✅")
    for v in (100, 102, 98, 101, 500):                  # 末次暴涨
        verdict = g.consistency_gate(v)
    assert verdict.startswith("ALERT")
    print("出口层突变:", verdict)
    # 决策矩阵：结构性→整批拒收；行级→死信隔离；一致性突变→告警冻结不自动修。
```

**追问**：1) 为什么「转换层坏行隔离」不用整批失败？——0.1% 坏行拦整批 = SLA 违约 + 99.9% 好数据延迟；死信表保留坏行（可修复重放），质量与可用性兼得——粒度决定策略。2) 突变检测为什么「不自动修」？——暴涨可能是真业务（促销）也可能是管道 bug；自动「修」（回滚/丢弃）在真业务场景会毁数据——人判数据源，机器只冻结扩散。3) 质量规则的误报监控怎么做？——规则命中后抽样人工复核（类似告警审计，Q7039），误报率高的规则降级或收紧阈值；规则库也要有 SLO。

## 背诵要点
1. 三门禁：摄入拦结构（快速失败整批拒收）、转换拦完整性（行级死信隔离）、出口拦一致性（告警+冻结）。
2. 决策粒度：结构性错误整批拒、行级问题隔离继续、一致性突变人工判（不自动修）。
3. 越上游越硬、出口层偏告警快照；规则系统自身要监控误报率。

## 复盘追问
1. 死信表堆了 100 万行没人处理，治理机制？（提示：死信也是数据——过期清理 + 修复重放任务 + 死信率进管道健康分（Q7070 积压处置同构））
2. 老板周报错了但所有质量门禁全绿，漏在哪？（提示：跨表一致性规则缺失（口径/汇总逻辑错不是单表质量错）——出口层规则要覆盖「业务口径」维度，不只技术维度）
