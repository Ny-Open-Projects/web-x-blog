### Q7153 · 浮点累加对账误差事故复盘：pandas sum 少了一分钱

难度：P6-P7 | 标签：浮点数、对账、事故复盘

**问**：日终对账任务里 `df["amount"].sum()` 与财务系统 Decimal 合计差了 0.01 元，一个月偶发两三次。复盘：为什么浮点求和会对不上账？工程上从数据类型到求和方式的全链路怎么改？

**答**：结论：IEEE 754 双精度用二进制表示十进制小数，0.1 这类数本身就是近似值；千万级累加的误差累积 + **求和顺序不同结果不同**（并行/分块求和改变了加法顺序），导致 sum 与财务逐笔 Decimal 累加出现分位差。这是金额字段用 float 的必然后果——钱从入库那一刻就该用 Decimal（数据库 DECIMAL）或"分为单位的整数"。

取舍与实战：
1. 类型链路改造：DB DECIMAL → pandas `dtype="float64"` 是第一个断点，正确读法是 `pd.read_csv(..., dtype={"amount": "object"})` 或用 arrow 后端 decimal128（Q7001 arrow 迁移）；Arrow 的 decimal128 端到端无损是根治路线。
2. 临时止血：`df["amount"].sum()` 改 `math.fsum`（精确舍入求和，与顺序无关）或按 Decimal 逐行累加；fsum 消除顺序误差但不消除"0.1 本身存成了近似值"的原始误差——**只能缩小不能根治**。
3. 对账框架兜底：金额比对必须带容差口径（±0.01/万笔）并落差异清单，容差内进人工确认而不是报警失败；出现"偶发几分钱"时先查 dtype 漂移（Q7033）。
4. 分块求和（Q322 chunksize）会加剧顺序问题：分块各自 sum 再总 sum，与单次 sum 结果可能不同——对账口径要钉死"用哪一种"。

```python
"""浮点求和顺序误差与修复方案对照（标准库，可运行）"""
import math
from decimal import Decimal

# 顺序敏感性演示：朴素逐笔累加（对账脚本常见写法），大数吃小数
# 注：CPython 3.12+ 内置 sum() 已用 Neumaier 补偿，但 pandas/numpy 的
# pairwise 求和与自定义累加循环仍可能暴露顺序误差——dtype 才是根源。
def naive_sum(values: list[float]) -> float:
    acc = 0.0
    for v in values:
        acc += v
    return acc

order_a = [1e16, 1.0, 1.0, -1e16]   # 小数逐个撞上大数被吞掉
order_b = [1.0, 1.0, 1e16, -1e16]   # 小数先两两聚成 2.0（1e16 间距是 2，恰好可表示）
a, b = naive_sum(order_a), naive_sum(order_b)
print(f"顺序A = {a}   顺序B = {b}   （同一组数，仅顺序不同）")
assert a == 0.0 and b == 2.0

# 重复小数演示：朴素累加丢精度，fsum 与 Decimal 精确
floats = [0.1] * 10
decs = [Decimal("0.1")] * 10
plain = 0.0
for v in floats:
    plain += v
f_sum = math.fsum(floats)
d_sum = sum(decs, Decimal("0"))
print(f"朴素累加     = {plain!r}")
print(f"math.fsum   = {f_sum!r}")
print(f"Decimal     = {d_sum}")
assert plain != 1.0 and f_sum == 1.0 and d_sum == Decimal("1.0")
print("结论：float 顺序相关且丢精度、fsum 顺序无关等于真值、Decimal 全程无损")
```

**追问 1**：`math.fsum` 为什么能做到与顺序无关？
**提示**：Shewchuk 算法用部分和列表保留全部低位的"丢失精度"，最后一次性舍入；代价是 slower 与 O(n) 额外内存，大表上要分块调用再合并。

**追问 2**：为什么"先乘 100 转整数"也不总是安全？
**提示**：`int(0.29 * 100)` 可能得 28（浮点 0.29 略小于真值）；正确写法 `round(x * 100)` 或直接 `Decimal(str(x)) * 100`——转换入口必须是字符串或 Decimal，不能经过 float 运算。

## 背诵要点
- float 金额求和两个误差源：二进制近似 + 顺序相关；千万级累加会出现分位差。
- 修复链路：金额全程 Decimal/DECIMAL（或分单位整数），过渡用 math.fsum 缩小误差。
- 对账框架带容差口径与差异清单；分块求和顺序也是口径的一部分，必须钉死。
