### Q7154 · CI 测试分片时长均衡容量账：加机器不如拆均匀

难度：P6-P7 | 标签：CI、容量规划、pytest

**问**：测试套件 40 分钟，团队用 4 个 CI 机器分片跑，结果最快分片 8 分钟、最慢 38 分钟——总时长还是 38 分钟。为什么"加分片数"几乎不缩短时长？分片怎么拆才科学？

**答**：结论：CI 并行时长由**最慢分片**决定（木桶效应），盲目加分片只增加排队与资源费用，时长不变。默认的"按文件名字母序/目录均分"与测试耗时毫无相关性——一个目录里塞了全部集成测试就会成为长尾分片。正确做法是**按历史耗时加权均衡**（贪心装箱）：收集每个测试/文件的上次运行时长，把总时长 T 均分成 N 份，按耗时降序往当前最空的分片里放。

取舍与实战：
1. 容量账公式：理论最短时长 = 总耗时 / 分片数，实际 = max(分片耗时) ≥ 理论值；均衡度 = max/avg，>1.3 就该重拆。加分片前先看均衡度，均衡度差时加机器是纯浪费。
2. 数据来源：pytest `--junitxml` 里每条 case 的 time 字段，或 pytest-xdist 之外的 `--duration`；存成 JSON 供下次分片用（数据漂移按周重算）。
3. 分片粒度：模块/文件级够用且实现简单；case 级更均衡但要处理同类 fixture 共享（拆散会重复建环境反而变慢）。
4. 长尾单测处置：单个 >10 分钟的端到端测试无法均衡，要么拆 case、要么挪出主干进 nightly——把它单独当第 N+1 个分片。
5. 与 Q7134（xdist 内存配比）区分：那是单机内进程级并行，这是跨机器分片；两层各自算账，不要混用 xdist worker 数来"解决"分片不均。

```python
"""贪心装箱分片：按历史耗时把测试均衡到 N 台 CI 机器（标准库，可运行）"""

def shard_tests(durations: dict[str, float], n_shards: int) -> list[list[str]]:
    """durations: {测试文件: 上次耗时秒}；贪心：降序放入最空分片"""
    shards: list[list[str]] = [[] for _ in range(n_shards)]
    loads = [0.0] * n_shards
    for name, t in sorted(durations.items(), key=lambda x: -x[1]):
        i = loads.index(min(loads))
        shards[i].append(name)
        loads[i] += t
    return shards

def balance_ratio(loads: list[float]) -> float:
    return max(loads) / (sum(loads) / len(loads))

tests = {"e2e_order": 320, "db_integration": 300, "api": 280, "unit_a": 100,
         "unit_b": 90, "unit_c": 80, "unit_d": 70, "unit_e": 60, "unit_f": 50}
shards = shard_tests(tests, 4)
loads = [sum(tests[t] for t in s) for s in shards]
print("各分片(秒):", loads, "均衡度:", round(balance_ratio(loads), 2))
assert balance_ratio(loads) <= 1.15
# 反例：默认按字母序均分（各拿 2-3 个文件）会产生长尾分片
alpha = [list(tests)[:2], list(tests)[2:5], list(tests)[5:7], list(tests)[7:]]
alpha_loads = [sum(tests[t] for t in s) for s in alpha]
print("字母序均分:", alpha_loads, "均衡度:", round(balance_ratio(alpha_loads), 2))
```

**追问 1**：为什么 case 级分片反而可能更慢？
**提示**：模块级 fixture（建库、起容器）被拆散后每个分片都要重建一遍，重复的环境成本超过均衡收益；分片粒度要沿 fixture 作用域边界切。

**追问 2**：测试耗时的历史数据本身会漂移（新用例、环境变慢），怎么维持？
**提示**：每次 CI 落库最新 case 时长、按滑动窗口（如 7 天）重算分片表；无历史数据的新用例给保守默认值并归入兜底分片。

## 背诵要点
- CI 时长 = max(分片时长)，均衡度 = max/avg > 1.3 先重拆再加机器。
- 分片算法：按 junitxml 历史耗时贪心装箱（降序放最空分片），周级重算。
- 分片粒度沿模块/fixture 作用域切，超长单测单独成片或挪 nightly。
