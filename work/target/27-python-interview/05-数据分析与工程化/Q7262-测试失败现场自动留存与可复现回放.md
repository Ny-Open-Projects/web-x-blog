### Q7262 · 只在 CI 挂的 flaky 用例：失败现场自动留存与可复现回放

难度：P6 ｜ 标签：flaky 测试、失败现场、可复现性、测试基建、环境快照

基线：Python 3.12；实现用例失败时自动写入现场目录（输入参数+日志+环境）与现场回放函数，全标准库实跑。

**问**：有个用例本地永远过、CI 上三天两头挂，挂的时候日志只有一行 AssertionError。复现不了就没法修——只能重跑碰运气。测试失败时能不能自动把"现场"留下来：当时的环境变量、输入参数、内部状态？现场应该包含什么、不包含什么？怎么让现场数据直接变成一个可重放的用例？

**答**：
- **结论**：失败现场是**用例崩溃瞬间的完整输入态快照**，四层内容：① **输入层**：参数化参数、测试输入数据（外发的请求体、文件内容）；② **环境层**：关键环境变量（TZ/配置项）、依赖版本、worker 标识（xdist 的 worker id，Q7257）——环境泄漏型 flaky（Q7260）靠这一层归因；③ **状态层**：被测对象的内部状态、数据库 dump、mock 调用记录；④ **日志层**：用例期间的完整日志。实现机制：测试框架的失败钩子（pytest 的 `pytest_runtest_makereport` 钩子或封装的 runner），失败时把四层内容写入现场目录，路径挂进测试报告。让现场**可重放**的关键设计：现场格式即回放格式——存的是结构化输入（JSON），回放函数读现场直接喂给被测函数，不依赖原始测试代码的构造逻辑。取舍点在**隐私与体积**：现场可能含真实数据，留存前脱敏、采样，目录设上限自动清理（Q2778 慢查询样本留存的同族账）。
- **取舍**：① 全量留存 vs 采样：全量留存的存储会失控，策略是"失败即留、留存上限滚动清理 + 同一用例现场去重（同签名只留最新 N 份）"；② 留存的时机：失败瞬间留，**重试前也要留**（重试插件挂在中间，第一次失败不留的话 flaky 信息就丢了）；③ 状态层最贵（DB dump），分级：核心用例全量、其余只留输入与环境；④ 现场即回放对"时间相关"用例要额外冻结时钟参数——现场里存 now 的值，回放时注入（Q7029 时钟注入的衔接）。
- **实战**：① runner 层统一实现（不让每个用例自己写留存逻辑）；② 现场目录结构标准化：`{test_id}/{timestamp}/{input,env,state,log}`，回放脚本按约定路径找；③ CI 产物：现场目录作为 artifact 上传，与测试报告关联；④ 治理闭环：现场回放确认的 flaky 归因分类（环境泄漏/时序竞态/外部依赖），分类统计驱动修复优先级。

```python
"""失败现场留存与回放: runner 包装 + 结构化现场 + 回放函数。"""
import json
import os
import tempfile


def classify_number(x: float, threshold: float = 10.0) -> str:
    """被测函数 (示例): 带隐藏环境依赖的判定。"""
    mode = os.environ.get("CLASSIFIER_MODE", "strict")
    if mode == "lenient":
        return "high" if x >= threshold * 0.9 else "low"
    return "high" if x > threshold else "low"     # 边界: x == threshold 时 strict 给 low


def capture_failure(out_dir: str, test_id: str, inputs: dict,
                    env_keys: list[str], extra_state: dict) -> str:
    """失败钩子: 四层现场落盘 (输入/环境/状态/日志)。"""
    scene_dir = os.path.join(out_dir, test_id)
    os.makedirs(scene_dir, exist_ok=True)
    scene = {
        "input": inputs,
        "env": {k: os.environ.get(k) for k in env_keys},
        "state": extra_state,
        "log": f"{test_id} AssertionError: classify result mismatch",
    }
    path = os.path.join(scene_dir, "scene.json")
    with open(path, "w", encoding="utf-8") as f:
        json.dump(scene, f, ensure_ascii=False, indent=2)
    return path


def replay(scene_path: str) -> dict:
    """回放: 读现场喂给被测函数 (现场格式=回放格式)。"""
    with open(scene_path, encoding="utf-8") as f:
        scene = json.load(f)
    old = os.environ.get("CLASSIFIER_MODE")
    os.environ["CLASSIFIER_MODE"] = scene["env"]["CLASSIFIER_MODE"] or "strict"
    try:
        result = classify_number(scene["input"]["x"],
                                 scene["input"]["threshold"])
    finally:
        if old is None:
            os.environ.pop("CLASSIFIER_MODE", None)
        else:
            os.environ["CLASSIFIER_MODE"] = old
    return {"replayed": result, "env_at_failure": scene["env"]}


if __name__ == "__main__":
    with tempfile.TemporaryDirectory() as d:
        # CI 现场: 测试契约是 strict 行为 (x==threshold 应判 low),
        # 但 CI 机器环境被配成 lenient -> 实际 high, 用例失败
        os.environ["CLASSIFIER_MODE"] = "lenient"     # CI 环境的隐形配置
        actual, passed, path = None, False, None
        try:
            actual = classify_number(10.0)
            passed = actual == "low"
        finally:
            if not passed:                            # 失败钩子: 留现场
                path = capture_failure(
                    d, "test_classify_boundary",
                    inputs={"x": 10.0, "threshold": 10.0},
                    env_keys=["CLASSIFIER_MODE"],
                    extra_state={"expected": "low", "actual": actual})
            os.environ["CLASSIFIER_MODE"] = "strict"  # 回到干净环境

        with open(path, encoding="utf-8") as f:
            print("现场内容:")
            for line in f.read().splitlines():
                print(f"  {line}")

        rep = replay(path)
        print(f"\n回放: 结果 {rep['replayed']} "
              f"(现场环境 {rep['env_at_failure']}) -> 复现 {rep['replayed'] == actual}")
        ok = rep["replayed"] == "high"
        print(f"校验: 现场可独立复现失败 -> {'通过' if ok else '异常'}")
        print("\n结论：现场四层=输入/环境/状态/日志, 现场格式即回放格式;")
        print("      归因: x=10.0 在 lenient 给 high、strict 给 low -> 环境泄漏型 flaky")
```

**追问一**：现场里的隐私与体积怎么治理？

→ 解析：三个闸门。① **脱敏前置**：现场采集时过一遍脱敏器（字段白名单 + 模式匹配抹手机号/密钥，Q1155 的过滤管线思想），脱敏函数本身要有单测——脱敏失败的现场泄露比 flaky 严重得多；② **体积分级**：输入与环境必存（都是小 JSON），状态层按用例级别开关（DB dump 只有标记为"关键链路"的用例开），目录硬上限（比如每测试 ID 保留最近 3 份 + 总量 100MB）超限滚动删；③ **生命周期**：现场目录进 CI 的清理策略，关联工单的现场保留到问题关闭，未关联的 7 天清——现场是排查工具不是档案库，留着不管终会把 CI 磁盘吃满（Q7046 制品清理的同族账）。

**追问二**：重试插件与现场留存怎么配合才不丢 flaky 证据？

→ 解析：顺序决定成败：**留存必须发生在第一次失败时，重试发生在留存之后**。pytest 的 flaky 重试插件默认行为是"失败→重试→通过则当无事发生"，如果留存钩子挂在"最终失败"上，偶发失败的现场就永远不会留——而偶发失败正是现场最有价值的时刻。正确组装：makereport 钩子在第一次 failed 时立即留现场（带重试轮次标记），重试逻辑独立其后；报告里区分"一次过/重试过/最终失败"三种结果，重试过的用例单独列出（它是 flaky 的信号源）。进一步把"重试通过率"作为测试健康度指标进周报：一个用例重试率持续高于阈值，比它最终失败更值得修——因为它在悄悄腐蚀整个套件的可信度。
