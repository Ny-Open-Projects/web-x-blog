### Q7247 · 合成的测试用户全是 25 岁：测试数据的分布保真度

难度：P6 ｜ 标签：测试数据生成、分布保真、bootstrap、分层抽样、随机种子

基线：Python 3.12；random+statistics 演示均匀随机、有放回重采样（bootstrap）两种生成方式与真实分布的分桶偏差。

**问**：给测试环境造了 10 万"用户"，年龄用 `random.randint(18, 60)` 均匀生成。功能测试没问题，但性能测试时推荐系统缓存命中率虚高、风控规则全不触发、分桶报表跑出来的分布和线上完全不同——用均匀随机数造数据，到底错在哪？怎么造出"分布上像真的"的测试数据？

**答**：
- **结论**：均匀随机破坏的是**分布保真度**：线上用户年龄是偏态的（集中在 25±8）、订单金额是重尾的（少数大额）、活跃度是幂律的（头部 1% 用户贡献 40% 事件）。用均匀分布造数据会改变所有依赖分布形态的环节：分位数、聚簇、缓存的局部性、风控规则的触发率。正确做法是**从真实数据重采样**：有放回抽样（bootstrap）保留边缘分布，分层抽样保留类别配比，字段间相关性（年龄与消费的关系）要么按联合分布采样、要么引入显式相关性模型。测试数据的"真实性"不是逐行像真的，而是**统计特征像真的**。
- **取舍**：① 直接复制真实数据到测试环境最保真但隐私红线（Q341 脱敏后的数据可保留分布，Q7012 的确定性加密可保 join 性）；② bootstrap 采样保边缘分布，但样本间的重复值会让唯一键/去重逻辑失真，需扰动处理；③ 参数化合成（拟合分布再采样）灵活但拟合成本高，适合关键字段；④ 无论哪种，都要**固定种子**（Q332）保证可复现，并给测试数据打标隔离。
- **实战**：① 生成后做分布校验：关键列按分桶对比真实 vs 合成的频率差，超阈值即不合格；② 性能测试重点保"基数与聚簇"（唯一值数量、热点集中度），功能测试重点保"边界与类别配比"；③ 测试数据生成器纳入版本管理，和 schema 一起演进（Q7038 数据契约联动）；④ 涉及 PII 的真实样本必须走脱敏管线，不能直接搬。

```python
"""测试数据分布保真度：均匀随机 vs bootstrap 重采样的分桶偏差。"""
import random
import statistics

# 真实用户年龄分布（线上抽样，右偏：年轻人为主）
REAL = [min(75, max(16, int(random.gauss(27, 8)))) for _ in range(50_000)]


def bucketize(ages: list[int]) -> list[float]:
    """按 16-25 / 26-35 / 36-50 / 51-75 四桶返回占比。"""
    bounds = [25, 35, 50, 75]
    total = len(ages)
    return [sum(1 for a in ages if a <= b) / total for b in bounds]


def gen_uniform(n: int) -> list[int]:
    return [random.randint(16, 75) for _ in range(n)]


def gen_bootstrap(n: int, seed: int) -> list[int]:
    rng = random.Random(seed)
    return [rng.choice(REAL) for _ in range(n)]      # 有放回重采样


if __name__ == "__main__":
    random.seed(42)
    real_b = bucketize(REAL)
    uni_b = bucketize(gen_uniform(50_000))
    boot_b = bucketize(gen_bootstrap(50_000, seed=7))
    labels = ["<=25", "<=35", "<=50", "<=75"]

    print(f"{'分桶':<6}{'真实':>8}{'均匀随机':>10}{'bootstrap':>11}"
          f"{'均匀偏差':>10}{'boot偏差':>10}")
    for i, lab in enumerate(labels):
        print(f"{lab:<6}{real_b[i]:>7.0%}{uni_b[i]:>9.0%}{boot_b[i]:>10.0%}"
              f"{uni_b[i] - real_b[i]:>+10.0%}{boot_b[i] - real_b[i]:>+10.0%}")

    print(f"\n均值: 真实 {statistics.mean(REAL):.1f} | "
          f"均匀 {statistics.mean(gen_uniform(50000)):.1f} | "
          f"boot {statistics.mean(gen_bootstrap(50000, 7)):.1f}")
    print("结论：均匀随机把偏态拉平，依赖分布的环节（分桶/风控/缓存局部性）全失真")
    print("      bootstrap 从真实样本重采样，边缘分布自动保真；固定种子保证可复现")
```

**追问一**：bootstrap 采样保留了什么、丢了什么？

→ 解析：保留了单字段的边缘分布（分桶、分位数、均值）；丢的是**字段间相关性**（年龄与消费金额的联合分布）、**样本间独立性**（重复值导致唯一约束场景失真）和**时序模式**（订单的时间聚集）。如果测试依赖关联结构（推荐系统的协同过滤测试），要在重采样之上补相关性建模：最简单的是"按真实用户整行采样"（整行 copy 保住行内相关），再加行间扰动（改 ID、轻微改数值）。保真度要与测试目标对齐，不是越多越好——目标是性能测试就优先保聚簇与基数，功能测试就优先保边界与异常值。

**追问二**：为什么测试数据也要像生产代码一样版本管理？

→ 解析：测试数据是测试断言的隐含输入：风控规则预期"年龄<18 触发"，生成器改了分布后样例没了未成年人，规则永远不触发，测试"全绿"但其实没测到。版本管理（生成器脚本 + 种子 + 校验报告入库）让"数据变化导致的用例失效"可追溯；再配合生成器与 schema 契约联动（字段新增时生成器必须同步支持），避免测试数据悄悄落后于真实结构。把生成器当产品维护，是数据团队测试基建的分水岭。
