### Q7237 · 两个 test_util.py：第二个文件根本没被收集

难度：P6 ｜ 标签：pytest、import mode、模块名冲突、收集

基线：Python 3.12；用 `importlib` 复现"同名模块只加载一次"的根因，并给出 `importlib` 模式的等价实现。

**问**：项目里 `tests/unit/test_util.py` 和 `tests/integration/test_util.py` 都存在（两个目录都没有 `__init__.py`），本地 `pytest tests/` 显示 collected 120 个用例，CI 上却只 collected 60 个，退出码还是 0。换个目录单独跑又是 60 个。测试没报错、覆盖率却莫名掉了 20%。为什么？

**答**：
- **结论**：pytest 默认的 `prepend` import 模式会把测试文件**按 basename 当模块名**导入（`test_util`），并插入 `sys.modules`。第二次遇到同名文件时，Python 发现 `sys.modules["test_util"]` 已存在，直接复用**第一个**模块对象——第二个文件的代码根本没执行，收集器从旧模块里拿到的还是旧用例。没有报错，因为导入"成功"了；只有加 `__init__.py` 或换 import 模式才会暴露。
- **取舍**：三种修法：① 用 `--import-mode=importlib`（pytest 推荐的新模式），按文件路径生成唯一模块名，彻底消除 basename 冲突；代价是依赖"隐式相对导入"的老测试可能失效，且 `sys.path` 行为变化；② 每个测试目录放 `__init__.py`，把包路径变成模块名的一部分（`tests.unit.test_util`），但混放（一个有、一个没有）会直接报 `import file mismatch`；③ 命名上保证全局唯一（`test_unit_util.py` / `test_integration_util.py`），最土但零配置。
- **实战**：① CI 里断言 `collected == expected`（或对比上次基线），"少收集"比"失败"更危险；② 开 `--strict-markers` 与 `-W error::pytest.PytestCollectionWarning`，让异常收集暴露；③ 用 `pytest --collect-only -q | wc -l` 做基线快照；④ 从 `unittest` 迁移过来的项目优先改 `importlib` 模式，因为 `unittest` 的模块名是按包路径生成的，和 basename 模式天然冲突。

```python
"""同名 test_util.py：sys.modules 缓存让第二个文件永不执行。"""
import importlib
import importlib.util
import sys
import tempfile
from pathlib import Path


def make_module(path: Path, marker: str) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(f"MARK = {marker!r}\nTESTS = [f'{marker}-1', f'{marker}-2']\n")


def load_by_path(path: Path, unique_name: str):
    """pytest --import-mode=importlib 的做法：用唯一模块名按路径加载。"""
    spec = importlib.util.spec_from_file_location(unique_name, path)
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod


if __name__ == "__main__":
    base = Path(tempfile.mkdtemp(prefix="pytest_layout_"))
    unit = base / "tests" / "unit" / "test_util.py"
    integ = base / "tests" / "integration" / "test_util.py"
    make_module(unit, "unit")
    make_module(integ, "integration")

    # 1) prepend 模式：两个目录都进 sys.path，模块名都叫 test_util
    sys.path.insert(0, str(integ.parent))
    sys.path.insert(0, str(unit.parent))
    first = importlib.import_module("test_util")
    sys.path.remove(str(unit.parent))
    second = importlib.import_module("test_util")     # 命中 sys.modules 缓存

    print("第一次导入:", first.MARK, "| 用例:", first.TESTS)
    print("第二次导入:", second.MARK, "| 用例:", second.TESTS)
    print("是同一个模块对象:", first is second)
    print("-> integration 目录的用例从未被收集，总数从 4 变 2\n")

    # 2) importlib 模式：唯一模块名，两个文件都能加载
    m1 = load_by_path(unit, "tests_unit_test_util")
    m2 = load_by_path(integ, "tests_integration_test_util")
    print("importlib 模式:", m1.MARK, m2.MARK)
    print("用例总数:", len(m1.TESTS) + len(m2.TESTS), "-> 全部收集")
    print("是同一个模块对象:", m1 is m2)

    # 3) 清理，别污染当前解释器
    for name in ("test_util",):
        sys.modules.pop(name, None)
    sys.path[:] = [p for p in sys.path if not p.startswith(str(base))]
    print("\n结论：basename 当模块名时，同名文件只有一个会活；collected 数要进 CI 断言")
```

**追问一**：`import file mismatch` 是怎么触发的，为什么它比"少收集"反而好？

→ 解析：当 pytest 发现 `sys.modules` 里已有同名模块、但它的 `__file__` 与当前文件路径不一致时，会直接报 `import file mismatch` 并终止。它只在"同名的旧模块确实来自另一个路径"时出现，而这正是应当失败的情况——**响亮地失败**比"静默只跑一半"好得多。混用 `__init__.py`（一个目录有、一个没有）是最常见的触发方式：有包的那份模块名变成 `tests.unit.test_util`，没有的那份仍是 `test_util`，两条命名空间打架。

**追问二**：改成 `--import-mode=importlib` 后有哪些旧写法会坏？

→ 解析：三类：① 测试文件里 `from .conftest import x` 这类**相对导入**（`importlib` 模式下测试模块不是包的一部分，相对导入失效）；② 依赖 `sys.path[0]` 恰好是测试目录来 `import` 同目录辅助模块的写法；③ 有些插件/钩子按 `module.__name__` 匹配路径。迁移顺序建议：先加 `--import-mode=importlib` 跑一遍全量，看失败集中在哪几类，再逐个改成绝对导入（把项目根加入 `pythonpath`），最后删掉目录里的 `__init__.py`。pytest 8 仍默认 `prepend`，所以这个开关必须显式写进 `pytest.ini`/`pyproject.toml`，否则换台机器行为就变。
