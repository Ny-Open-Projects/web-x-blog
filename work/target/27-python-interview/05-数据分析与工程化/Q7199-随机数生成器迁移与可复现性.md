### Q7199 · 随机数生成器迁移与实验结果可复现性

难度：P6 ｜ 标签：版本迁移、可复现性、numpy、随机种子

基线：Python 3.12；numpy 1.24+ 的 `default_rng`；random 标准库演示概念。

**问**：升级 numpy 后，同事把 `np.random.seed(42)` + `np.random.randn()` 换成了 `np.random.default_rng(42)`，结果"同样的种子"产出的训练数据和以前完全不一样，实验结果对不上。这是 bug 吗？该怎么迁移？

**答**：
- **结论**：不是 bug，是**预期行为**。`np.random.seed` 操作的是全局 `RandomState`（legacy MT19937），`default_rng(42)` 返回的是新的 `Generator`（默认基于 PCG64）。算法不同，即使种子相同也必然产生不同序列——这是两套独立的生成器，不能跨版本/跨 API 比对同一串数。`RandomState` 已被官方置于"遗留维护"状态，新代码应迁到 `Generator`。
- **取舍**：迁移的代价是历史基线、黄金数据、已发表实验结果无法用新生成器逐位复现。对策是：迁移时把"旧序列"归档，新实验用新生成器并重新建立基线；同一版本内用固定 seed 保证可复现；跨实验记录 seed + 生成器类型 + 库版本，缺一不可。
- **实战**：把随机源封装成单一入口（函数/工厂），全局不散落 `np.random.*`；实验元数据记录 `generator=PCG64, seed=42, numpy=1.26`；用独立 `Generator` 实例而不是全局状态，避免不同模块互相干扰序列。

```python
import random


def legacy(seed: int, n: int) -> list[int]:
    """模拟旧 API：全局 RandomState(MT19937) 风格。"""
    r = random.Random(seed)
    return [r.randint(0, 100) for _ in range(n)]


def modern(seed: int, n: int) -> list[int]:
    """模拟新 API：不同算法派生不同内部状态，序列与 legacy 不同但可复现。"""
    r = random.Random(seed + 1_000_003)
    return [r.randrange(101) for _ in range(n)]


if __name__ == "__main__":
    print("legacy(42):", legacy(42, 5))
    print("modern(42):", modern(42, 5))
    print("同种子可复现:", modern(42, 5) == modern(42, 5))
    # 换生成器 = 换序列；迁移实验基线时要重新生成黄金数据。
```

**追问一**：为什么同 seed 换了生成器序列就变了？
→ 解析：seed 只是初始化内部状态的输入，序列由具体算法（MT19937 vs PCG64）决定。算法不同，状态演化规则不同，相同种子得到的序列自然不同。

**追问二**：如何保证一次实验"完全可复现"？
→ 解析：固定三要素——seed、生成器类型/算法、库版本，并确保代码里所有随机源都来自同一个受控实例；还要固定数据顺序、并行度（并发会改变消费随机数的顺序）。
