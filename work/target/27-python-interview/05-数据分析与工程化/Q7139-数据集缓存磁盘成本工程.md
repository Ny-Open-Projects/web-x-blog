### Q7139 · 数据集缓存的磁盘成本工程

难度：P6 ｜ 标签：成本工程 / 容量规划 / 数据工程

**问**：数据科学团队几十个 notebook/任务共用一批数据集缓存（`~/.cache/huggingface`、parquet 快照、下载的 CSV），磁盘每周涨 20GB，最后打满主机磁盘全组停工。数据集缓存的成本账怎么建：缓存目录怎么度量、淘汰策略怎么定、共享缓存和本地缓存的取舍是什么？

**答**：
- **结论**：数据集缓存账三个动作。① **度量**：按目录聚合大小 + 最后访问时间（atime 会被备份/read 破坏，用 mtime + 命中日志更稳），输出"TOP 目录 × 大小 × 最后使用"，工具就是 os.walk + 快照对比（增量 = 本周新增）；② **淘汰**：缓存天花板（磁盘配额，如 200GB）+ LRU 淘汰（按最后使用 + 大小加权：大而少用的先走），被淘汰项保留"重取命令"（数据集 ID + 版本），让"删了可再下"成为安全网；③ **共享化**：本地缓存 × N 人 = N 倍磁盘与 N 倍下载带宽（Q7099 出区流量同理），改为团队级共享缓存（NFS/对象存储 + 本地软链，或集中式数据平台），用一份缓存成本换 N 份归零——共享是数据集缓存最划算的一步，前提是并发读安全（对象存储天然满足）。关键意识：数据集缓存是**可再生的派生数据**，成本工程的核心是让它"可删可再生"，与代码仓库/结果产物区别对待。
- **取舍**：本地缓存快（无网络）但浪费与失控；共享缓存省磁盘与带宽但引入网络延迟与单点。混合策略：热门小数据集本地留、冷门大对象走共享 + 按需拉取。淘汰激进程度与"重新获取成本"挂钩：重新下载要 2 小时的大数据集放宽限，5 分钟的实验数据随删。
- **实战**：① 缓存目录纳入备份排除清单（可再生数据不进备份，省备份成本）；② 下载数据集的工具统一封装（一处写缓存、记日志），禁止各脚本自己 `requests.get` 存散盘；③ 磁盘水位告警分两级：80% 触发 LRU 淘汰预跑、90% 停止新任务写入。

```python
# 数据集缓存账: 目录度量 + 配额 LRU 淘汰 + 重取命令留档
# 基线: Python 3.9+ 标准库
import os
import time
from dataclasses import dataclass


@dataclass
class CacheEntry:
    path: str
    size_gb: float
    last_used: float          # mtime 代替不可靠的 atime
    refill_cost_hours: float = 0.5   # 重新获取耗时


def sweep(entries: list, quota_gb: float) -> tuple[float, list[str]]:
    """配额超限按 (冷且大) 淘汰, refill 贵的放宽。返回(释放量, 被删清单)。"""
    used = sum(e.size_gb for e in entries)
    freed, removed = 0.0, []
    if used <= quota_gb:
        return freed, removed
    # 大且久未用优先; refill 超过 2 小时的强制保护 (放宽限名单)
    order = sorted(entries, key=lambda e: (-e.size_gb, e.last_used))
    for e in order:
        if used <= quota_gb:
            break
        if getattr(e, "refill_cost_hours", 0.5) > 2.0:
            continue                          # 不可再生的先不删
        used -= e.size_gb
        freed += e.size_gb
        removed.append(e.path)
    return freed, removed


def main() -> None:
    now = time.time()
    entries = [
        CacheEntry("hf/imagenet", 120, now - 86400 * 45, 3.0),   # 大而冷但重取贵
        CacheEntry("hf/tokenizer", 2, now - 3600 * 2, 0.1),      # 小而热
        CacheEntry("parquet/tmp_exp", 60, now - 86400 * 30, 0.2),# 大冷易重取
    ]
    freed, removed = sweep(entries, quota_gb=100)
    assert removed == ["parquet/tmp_exp", "hf/tokenizer"]  # 大冷先走, 热的最后
    assert freed == 62.0
    used_after = sum(e.size_gb for e in entries) - freed
    assert used_after == 120.0                  # imagenet 受保护仍超配额
    print(f"释放 {freed}GB, 剩 {used_after}GB (重取>2h 的 imagenet 受保护)")
    print("OK: 配额+LRU(大小加权)+refill 保护; 不可再生项超配额须人工决策")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么用 mtime 而不是 atime 判断"最后使用"？
→ 一句话提示：atime 会被备份扫描、find、甚至读取本身更新（且很多文件系统默认 noatime 根本不记录），mtime 稳定但语义是"最后修改"——更可靠的是缓存工具自己写命中日志。

**追问 2**：共享缓存的并发读为什么在对象存储上天然安全、在 NFS 上要小心？
→ 一句话提示：对象存储无锁读原子且可横向扩展；NFS 读没问题但多任务同时写同一文件会交错损坏，需要"写临时文件+原子改名"（Q7091 同源纪律）。

## 背诵要点
- 数据集缓存是可再生派生数据：度量（目录×大小×最后使用）+ 配额 + LRU（大小加权），被删项留"重取命令"。
- 淘汰保护规则：refill 成本 > 2 小时的强制宽限；本地缓存 × N 人 = N 倍磁盘与带宽，团队共享化是最划算一步。
- 磁盘水位两级告警：80% 预淘汰、90% 停写；缓存目录不进备份清单。

## 复盘追问
- 为什么"禁止散盘下载"要靠工具封装而不是约定？提示：约定无法审计，统一封装后缓存命中日志、去重、配额全在一处，盘点与淘汰才有数据源（Q7041 散盘脚本事故的根因同源）。
- 如何给"重新获取成本"定价？提示：下载时长 × 带宽费 + 上游 API 配额占用 + 下游任务等待的时效成本；用于决定每条缓存的宽限等级。
