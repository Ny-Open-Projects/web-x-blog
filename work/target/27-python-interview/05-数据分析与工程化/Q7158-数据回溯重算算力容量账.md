### Q7158 · 数据回溯重算的算力容量账：修复口径要重跑 180 天怎么办

难度：P6-P7 | 标签：容量规划、数据管道、回溯重算

**问**：指标口径修了 bug，需要重算 180 天历史数据。全量重算要 60 个机时，而日常管道只留了 8 小时夜间窗口。回溯任务的容量账怎么算？和在线管道抢资源还是独立跑？

**答**：结论：回溯重算是一次性**批量作业容量事件**，账分三步：① 需求侧——重算总量 = 回溯窗口 × 日均算力，180 天 × 20 分钟/天 ≈ 60 机时；② 供给侧——可用窗口 = 空闲时段 × 并行度，且必须避开在线管道峰值（错峰或独立资源池）；③ 时间侧——修复有 SLA（下游要数据），60 机时在 8 机并行下 7.5 小时跑完，能否满足 SLA 决定要不要申请临时资源。**能并行就并行、能增量就增量**是两个最大的降本杠杆。

取舍与实战：
1. 增量优先于重跑：bug 影响的是聚合口径时，评估"从原始明细按新口径重聚合"是否比"回放整个管道"便宜——明细重算常比全链路回放便宜一个量级；只重算受影响分区（Q2273 分区级回滚思路），按"口径变更影响面清单"圈定范围。
2. 并行度受数据倾斜与下游写瓶颈约束：按日期分片并行最自然，但要注意每分片写目标表时的锁冲突（改先落临时表再原子交换）；并行度 = min(机时预算/单日耗时, 下游可承受写入并发)。
3. 独立资源池 vs 抢在线资源：共享集群跑回溯要设任务优先级与配额上限，防止夜间管道被挤；SLA 紧急时申请弹性资源（Spot/抢占式实例便宜 60-90%，但要有断点续跑能力——Spot 被回收是常态）。
4. 对账收尾：重算完成后新旧值 diff 报告（Q1068 全量/抽样比对）+ 差异率告警，防止"重算成功但算错了"。

```python
"""回溯重算容量账：机时需求、并行度与弹性资源断点续跑预算（标准库）"""
import math

def backfill_plan(
    days: int, daily_minutes: float,     # 回溯窗口与单日算力
    deadline_hours: float,               # SLA 时限
    idle_machines: int,                  # 空闲时段可用机器
    spot_discount: float = 0.7,          # 弹性资源折扣
) -> dict:
    total_hours = days * daily_minutes / 60
    parallel = max(idle_machines, 1)
    wall = total_hours / parallel
    need_spot = wall > deadline_hours
    spot_machines = math.ceil(total_hours / deadline_hours) if need_spot else 0
    return {
        "总机时": round(total_hours, 1),
        "并行后耗时h": round(wall, 1),
        "超SLA_需弹性": need_spot,
        "弹性机器数": spot_machines,
        "弹性成本系数": round(spot_machines * (1 - spot_discount) + idle_machines, 1),
        "断点续跑": "必配：Spot 被回收后按日期分片幂等续跑",
    }

print(backfill_plan(days=180, daily_minutes=20, deadline_hours=10, idle_machines=8))
```

**追问 1**：为什么回溯分片要"幂等"而不只是"可重试"？
**提示**：Spot 回收可能发生在任意写入中途，重跑同一分片必须覆盖式写（先写临时分区再交换）或按主键 upsert，不能假设"上次跑了一半，这次接着写"；否则产生重复行。

**追问 2**：怎么圈定"口径 bug 真正影响的分区范围"，避免全量重算？
**提示**：从 bug 代码变更时间倒推受影响数据窗口 + 按维度过滤（如 bug 只影响某类事件），先抽样重算几个分区比对新旧值验证影响面假设，再全量执行——影响面评估本身也要算账。

## 背诵要点
- 回溯账三步：总机时 = 窗口 × 日均算力；并行度受下游写瓶颈约束；SLA 决定是否申请弹性资源。
- 增量优先：按影响面圈分区、明细重聚合优于全链路回放，便宜一个量级。
- Spot 实例必配幂等分片（临时分区+原子交换），收尾必配新旧 diff 对账。
