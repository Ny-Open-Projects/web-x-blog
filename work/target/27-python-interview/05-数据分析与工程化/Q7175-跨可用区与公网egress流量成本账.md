### Q7175 · 账单里最容易被忽略的一项：egress 流量的成本工程

难度：P6 ｜ 标签：成本工程、流量计费、架构拓扑
基线：云厂商通用（同 AZ 免费、跨 AZ 约 0.1-0.2 元/GB、公网 egress 约 0.5-0.9 元/GB、跨区更贵）。

**问**：月账单审计发现"网络流量"占 40%，而团队以为云内流量免费。egress 成本由哪几类流量构成？架构上有哪些决策直接决定了这张账？

**答**：**结论**：egress 账的构成按单价排序：公网出口 > 跨 Region > 跨 AZ > 同 AZ（常免费）。常见"隐形大户"四类：① 服务间调用跨了 AZ（部署没做亲和）；② 对象存储的公网直链下载（应走 CDN 或内网）；③ 跨区灾备复制与日志汇聚（常驻后台流量）；④ 微服务链路里"一次请求多次跨 AZ 往返"——每跳都计费。成本工程的核心不是压带宽而是**把流量搬到便宜的网络分区**：服务拓扑与数据 locality 决定了账单下限，代码层面能做的（压缩、缓存、批量）都排在拓扑之后。

**取舍**：压缩与批量都是经典杠杆，但各有对冲：压缩省流量耗 CPU（与 04 类缓存带宽账同理）；批量合并请求省往返但增加延迟与失败半径（一批丢全批）。跨 AZ 亲和的代价是**可用性**——把整条调用链压进同一 AZ，AZ 故障时全链路一起倒；常见解法是读路径同 AZ、写与状态同步跨 AZ，并给跨 AZ 流量设预算告警而非追求归零。

**实战**：egress 账分解与杠杆收益（标准库）：

```python
# egress 流量成本账：分区单价 × 流量来源分解
PRICE = {"公网": 0.8, "跨区": 0.25, "跨AZ": 0.15, "同AZ": 0.0}  # 元/GB 示例
flows = {  # GB/月
    "公网-对象存储直链下载": 40_000,
    "跨AZ-服务间调用": 25_000,
    "跨AZ-跨区日志汇聚": 6_000,
    "同AZ-库读流量": 90_000,
}
total = sum(PRICE[k.split("-")[0]] * v for k, v in flows.items())
print(f"月流量账: {total:,.0f} 元")
for k, v in flows.items():
    zone = k.split("-")[0]
    print(f"  {k}: {v:,} GB -> {PRICE[zone]*v:,.0f} 元/月")

# 杠杆 1：对象存储走 CDN（回源价约为公网价的 1/3，缓存命中后只付回源）
cache_hit = 0.9
cdn_cost = flows["公网-对象存储直链下载"] * (1-cache_hit) * PRICE["公网"] * 0.4
print(f"CDN 化后该项: {cdn_cost:,.0f} 元/月（命中率 {cache_hit*100:.0f}%）")

# 杠杆 2：跨 AZ 调用做同 AZ 亲和，读路径 85% 搬回同 AZ
read_share = 0.85
moved = flows["跨AZ-服务间调用"] * read_share
new_az = flows["跨AZ-服务间调用"] - moved
print(f"亲和后跨AZ剩 {new_az:,.0f} GB -> 省 {PRICE['跨AZ']*moved:,.0f} 元/月")

# 杠杆 3：日志汇聚压缩（zstd 压缩率按 0.35）
compressed = flows["跨AZ-跨区日志汇聚"] * 0.35
print(f"日志压缩后: {compressed:,.0f} GB -> {PRICE['跨AZ']*compressed:,.0f} 元/月")

# 可用性对冲：同 AZ 亲和后 AZ 故障爆炸半径评估
az_isolated_services = 12
print(f"亲和后单 AZ 挂掉的爆炸半径: {az_isolated_services} 个服务同 AZ —— "
      f"需演练 AZ 级故障切换")
```

**追问 1**：为什么说"拓扑决定账单下限，代码优化排在其后"？
提示：跨 AZ/公网差价是数量级的（免费 vs 0.8 元/GB），代码层压缩最多省 50-70% 且耗 CPU；先做分区搬迁再谈压缩，顺序反了白花优化成本。

**追问 2**：跨区灾备复制的流量能省吗？
提示：压缩 + 增量同步（只传变化块）+ 降频（RPO 允许时从实时改小时级）；灾备 RPO 与流量账是一对直接冲突项，账要和业务 SLA 一起评审。

**追问 3**：怎么建立"流量来源可归因"的监控？
提示：按 (源服务, 目标服务, 网络分区) 三元组打流量标签，云厂商的 VPC flow log 聚合；没有归因的成本账只是总数，无法驱动架构决策。

## 背诵要点
1. egress 单价排序：公网 > 跨区 > 跨 AZ > 同 AZ（免费）；四大隐形大户：跨 AZ 调用、公网直链下载、跨区复制、链路多跳往返。
2. 杠杆顺序：拓扑亲和（读同 AZ）> CDN 化对象下载 > 压缩 > 批量合并；压缩省流量耗 CPU，批量省往返增大失败半径。
3. 成本账必须可归因：按源/目标/分区三元组打标，否则只能看总数、无法驱动决策。
