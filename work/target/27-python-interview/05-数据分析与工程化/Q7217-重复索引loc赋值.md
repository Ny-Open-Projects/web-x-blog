### Q7217 · 重复索引下 .loc 赋值：为什么只改了一行

难度：P6 ｜ 标签：pandas、索引、loc、链式赋值

基线：Python 3.12；pandas 2.x（Copy-on-Write 默认前）；纯 Python 模拟 loc 与链式赋值语义。

**问**：清洗脚本里写 `df['status']['u1'] = 'done'`，跑完 `df` 一点没变；改成 `df.loc['u1', 'status'] = 'done'` 后，所有 `u1` 的行都被改了，本来只想改其中一条。索引里确实有重复的 `u1`（一个用户多条订单）。重复索引下 `.loc` 到底返回什么？为什么链式赋值静默失效？

**答**：
- **结论**：索引**不唯一**时，`df.loc['u1']` 不再返回 Series，而是返回一个**包含所有匹配行的 DataFrame**；`df.loc['u1', 'status'] = 'done'` 会对**所有匹配行**赋值（标量广播）。链式 `df['status']['u1'] = ...` 则是先取列（可能返回副本），再在副本上赋值，原 `df` 不受影响——这是典型的 **chained assignment**，pandas 只给 `SettingWithCopyWarning` 甚至静默丢弃。
- **取舍**：要用标签定位唯一一行，必须先保证索引唯一（`df.index.is_unique`），或改用"布尔掩码 + 列"的组合条件；重复索引适合"一个键多行"的语义（如订单明细），但不适合当主键做 `loc` 更新。设置唯一索引（`set_index` 前先去重/加序号）能避免大部分坑，代价是多一次校验/重塑。
- **实战**：① 入口断言 `df.index.is_unique`，不唯一就显式加 `order_id` 组成复合索引；② 更新用 `df.loc[mask, 'col'] = value`，不要链式；③ 需要"只改第一条"时用 `df.loc[df.index == 'u1', 'status'].iloc[0] = ...` 也不可靠，正确是先 `df.index.get_indexer_for(['u1'])[:1]` 取位置，再 `df.iloc[pos, col] = ...`；④ 升级 pandas 3.0 后 CoW 会让链式赋值更明确地失效，别依赖旧行为。

```python
"""模拟重复索引下的 loc 取值/赋值与链式赋值失效。"""


class Frame:
    def __init__(self, rows: list[dict], index: list[str]) -> None:
        self.rows = rows
        self.index = index

    def column(self, col: str) -> list:
        """返回列的新列表：模拟 df['col'] 可能拿到副本。"""
        return [r[col] for r in self.rows]

    def loc_get(self, label: str, col: str):
        hits = [r[col] for r, i in zip(self.rows, self.index) if i == label]
        if len(hits) == 1:
            return hits[0]              # 唯一索引 -> 标量
        return hits                     # 重复索引 -> 一组值（DataFrame 语义）

    def loc_set(self, label: str, col: str, value) -> int:
        n = 0
        for r, i in zip(self.rows, self.index):
            if i == label:
                r[col] = value          # 广播到所有匹配行
                n += 1
        return n


if __name__ == "__main__":
    df = Frame([{"status": "new"}, {"status": "new"}, {"status": "new"}],
               ["u1", "u1", "u2"])

    print("index 是否唯一:", len(set(df.index)) == len(df.index))
    print("loc['u1'] 返回:", df.loc_get("u1", "status"), "(不是标量)")

    col = df.column("status")          # 链式第一步：拿到副本
    col[0] = "done"                    # 改副本
    print("链式赋值后原 df:", df.rows, "-> 没变")

    n = df.loc_set("u1", "status", "done")
    print(f"loc 赋值影响 {n} 行:", df.rows, "-> 两行都被改")

    pos = next(i for i, x in enumerate(df.index) if x == "u1")
    df.rows[pos]["status"] = "only-first"
    print("按位置只改第一行:", df.rows)
```

**追问一**：为什么重复索引做 `reindex` / `join` 会突然行数爆炸？
→ 解析：join/reindex 的语义是"按标签匹配"，左表一个标签对应右表多行时，结果会做**笛卡尔展开**（m 行 × n 行）。索引不唯一时匹配不唯一，行数按乘积增长；如果两侧都重复，可能是平方级放大。合并前必须确认键唯一，或用 `validate='one_to_many'` 显式声明关系。

**追问二**：`SettingWithCopyWarning` 为什么有时报有时不报？
→ 解析：它依赖 pandas 能否判断对象是"视图还是副本"，而这个判断依赖内部块布局与操作链，不是语义保证。同样的链式赋值在不同 dtype/列布局下可能静默成功、也可能改不到原对象。所以不能"看到没警告就放心"，正确做法是永远用单次 `.loc` 完成"选行 + 选列 + 赋值"。
