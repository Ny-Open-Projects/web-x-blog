### Q7292 · 浮点断言分层：isclose 的相对容差与到底该断什么

难度：P6 ｜ 标签：浮点、math.isclose、pytest.approx、容差、Decimal、测试断言

基线：库知识卡，代码用标准库模拟——用 `math.isclose` 与 `Decimal` 对比三种断言口径，不依赖 pytest。

**问**：数据管线的单元测试里写着 `assert sum(amounts) == 1000.0`，本地跑一万次都过，CI 上偶发失败；同事改成 `assert abs(a - b) < 1e-6` 后，金额差 1 分也过了，线上少收钱没被发现。浮点断言到底该怎么写？`math.isclose` 的 `rel_tol`/`abs_tol` 分别管什么？`pytest.approx` 的默认值是什么？哪些东西**根本不该用浮点断言**？

**答**：

- **结论**：断言要分三层，不能一把 `==` 或一把 `1e-6` 走天下。① **精确层**：计数、ID、集合、金额（以"分"为单位的整数或 `Decimal`）——必须精确相等，浮点在这里是错误的数据表示；② **相对容差层**：量级可能很大的浮点（吞吐、金额的浮点近似、模型分数）——用 `rel_tol`，容忍"相对误差"；③ **绝对容差层**：接近 0 的浮点（差值、梯度、概率残差）——必须给 `abs_tol`，因为 `rel_tol` 在 0 附近会把容差压成 0。`math.isclose(a, b, rel_tol=1e-9, abs_tol=0.0)` 的判定是 `|a-b| <= max(rel_tol*max(|a|,|b|), abs_tol)`；默认 `abs_tol=0` 意味着"和 0 比较永远不 close"，而默认 `rel_tol=1e-9` 意味着在 `1e9` 量级上容忍 **1 个单位**——对计数就是灾难。
- **取舍**：容差不是越小越好。太紧 → CI 因累加顺序、BLAS 线程数、平台差异偶发失败（flaky test 比没测试更糟）；太松 → 真实回归被放过（1 分钱的系统性偏差在百万单上就是一万块）。选择依据是**业务精度**：金额的最小单位是分，就用整数分或 `Decimal` 精确断言；比率/分数按业务可接受误差（如 1e-3）设 `rel_tol`，并额外给 `abs_tol=1e-12` 防止近零失效。`pytest.approx` 默认 `rel=1e-6`、`abs=1e-12`，比 `math.isclose` 更适合"相对误差"场景，但同样不能拿来断计数。
- **实战**：一次结算报表的测试用 `assert total == 1000.0`，CI 偶发失败，排查是不同机器的浮点累加顺序不同（并行 reduce），差值 1e-13。改成"金额以分为单位的整数累加"后彻底稳定；另一处模型指标断言用 `abs(a-b) < 1e-6`，结果一次特征 bug 让 AUC 从 0.80 掉到 0.7999995，测试没拦住——因为容差比真实回归还大。最终规范写成三条：金额/计数用精确类型；比率用 `rel_tol=1e-6, abs_tol=1e-12` 并同时断言方向（不能只断"接近"）；任何浮点断言都必须在注释里写清"容差来自哪个业务精度"。

下面把三种容差口径的差异与失效场景跑出来。

```python
# 浮点断言三层: 精确 / rel_tol / abs_tol
import math
from decimal import Decimal

print(f"[1] 0.1+0.2 = {0.1 + 0.2!r}, == 0.3? {0.1 + 0.2 == 0.3}")
assert 0.1 + 0.2 != 0.3
assert math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9)

# rel_tol 在大量级上会吃掉 1 个单位的误差
big = 1e9
print(f"[2] isclose(1e9, 1e9+1) = {math.isclose(big, big + 1)}, "
      f"容忍度 = {1e-9 * (big + 1):.2f}")
assert math.isclose(big, big + 1)
print("    → 实测 对'计数'用默认 rel_tol, 差 1 也会被判相等")

# 近零: rel_tol 失效, 必须给 abs_tol
near = 1e-12
print(f"[3] isclose(1e-12, 2e-12) = {math.isclose(near, 2 * near)} (默认 abs_tol=0)")
assert not math.isclose(near, 2 * near)
assert math.isclose(near, 2 * near, abs_tol=1e-12)
print("    → 实测 近零差值只能靠 abs_tol, rel_tol 在 0 附近没有意义")

# 金额: 浮点累加 vs Decimal
f = 0.0
for _ in range(100):
    f += 0.01
d = Decimal("0")
for _ in range(100):
    d += Decimal("0.01")
print(f"[4] 100 次加 0.01: float={f!r} (==1.0? {f == 1.0}), Decimal={d}")
assert f != 1.0 and d == Decimal("1.00")
assert Decimal("0.1") + Decimal("0.2") == Decimal("0.3")
print("    → 实测 金额用 float 累加, 误差会随笔数累积; Decimal/整数分才是精确层")

# 分层断言器: 计数精确, 金额 Decimal, 比率 rel+abs
def assert_metric(actual, expected, kind, tol=1e-6):
    if kind == "count":
        assert isinstance(actual, int) and actual == expected, f"count {actual} != {expected}"
    elif kind == "money":
        assert isinstance(actual, Decimal) and actual == expected, f"money {actual} != {expected}"
    elif kind == "ratio":
        assert math.isclose(actual, expected, rel_tol=tol, abs_tol=1e-12), \
            f"ratio {actual} != {expected} (rel={tol})"
    else:
        raise ValueError(kind)


assert_metric(1000, 1000, "count")
assert_metric(Decimal("1.00"), Decimal("1.00"), "money")
assert_metric(1 / 3, 0.333333, "ratio", tol=1e-5)

try:
    assert_metric(1_000_000_001, 1_000_000_000, "count")   # 浮点式宽容在这里必须失败
except AssertionError as e:
    print(f"[5] count 层拒绝 1 个单位误差: {e}")
print(f"[6] ratio 层: 1/3 与 0.333333 在 rel=1e-5 下通过 = "
      f"{math.isclose(1/3, 0.333333, rel_tol=1e-5)}")
assert math.isclose(1 / 3, 0.333333, rel_tol=1e-5)
print("    → 实测 该精确的精确、该近似的近似; 容差必须由业务精度反推")
```

**追问一**：`pytest.approx` 和 `math.isclose` 有什么实质区别？该用哪个？—— `pytest.approx` 默认 `rel=1e-6, abs=1e-12`（两个都给），并且支持序列/字典的逐元素比较、`nan_ok` 等便利；`math.isclose` 默认 `abs_tol=0`，语义更"数学"。两者判定公式相同（都是 `|a-b| <= max(rel*max(|a|,|b|), abs)`），差异在默认值与容器支持。实践建议：单值浮点用 `math.isclose` 并显式写两个容差；序列/数组断言用 `pytest.approx` 或 numpy 的 `assert_allclose`（后者对数组更高效）；金额/计数两者都不要用。

**追问二**：为什么"只断言接近"还不够，还要断言方向或范围？—— 因为"接近"是对称的：`abs(actual - 0.80) < 0.01` 同时允许 0.795 和 0.805，而很多回归是**单向**的（召回只能降、金额只能少、延迟只能升）。只断接近会漏掉"方向正确但幅度在容差内"的系统性偏差；更严重的是，容差一旦设得比真实回归大，测试就变成了"永远通过"。补充手段：断言 `actual >= expected - tol`（单侧）、同时断言业务不变量（金额总和守恒、计数非负）、对关键指标用配对样本/置信区间而不是单点阈值。

## 背诵要点

- 判定公式：`|a-b| <= max(rel_tol*max(|a|,|b|), abs_tol)`；`isclose` 默认 `abs_tol=0`（近零永远不 close），`approx` 默认 `rel=1e-6, abs=1e-12`。
- 三层：计数/ID/金额用精确类型（int、Decimal/分）；大量级浮点用 `rel_tol`；近零差值必须给 `abs_tol`。
- 容量与容差由业务精度反推；只断"接近"会漏掉单向偏差，需补单侧断言与不变量断言。
