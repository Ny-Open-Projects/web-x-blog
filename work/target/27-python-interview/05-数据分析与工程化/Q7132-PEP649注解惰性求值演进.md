### Q7132 · PEP 649/749 注解惰性求值（Python 3.14）的演进与迁移点

难度：P7 ｜ 标签：版本演进 / 类型系统 / Python 3.14

**问**：Python 3.14 落地 PEP 649：函数与类的注解从"定义时立即求值"改成"首次访问时惰性求值"。这解决了什么老问题？对 Pydantic/dataclasses 这类"运行时读注解"的框架有什么影响？`from __future__ import annotations` 的字符串注解方案和新方案语义差异在哪？

**答**：
- **结论**：旧语义的三个老问题被解决：① **前向引用**——`def f(x: Node) -> Node` 在 Node 还没定义时报 NameError，要么引号要么 `future` import；惰性求值下定义顺序不再重要。② **import 成本**——注解里引用的类型在定义时全部立即求值，未用到注解的调用方也要付这些 import 与求值成本；惰性化后注解是**未求值的代码对象**（annotate function，PEP 749 的 `__annotations__` 变为按需计算的描述符），3.12 起配合 `type` 别名惰性化（PEP 695）整条链路变轻。③ **运行时定义**——局部类/循环里定义带注解的函数不再因作用域踩坑。对框架的影响：Pydantic v2/dataclasses 在**访问时**拿到的字符串终于能自然解析（PEP 649 提供 `annotationlib` 的 VALUE/FORWARDREF/STRING 三种格式），框架可以"拿到真对象，拿不到就给前向引用占位"而不是全靠字符串拼。与 `future` 方案的本质差异：字符串方案让 `__annotations__` 全是字符串（框架必须自己 eval，有时拿不到上下文就炸），PEP 649 让 `__annotations__` 在访问时**真正求值成对象**——消费方 API 语义不变（拿到对象），只有求值时机变了。迁移点：框架要适配 `annotationlib` 三格式；代码里依赖"import 副作用触发求值"或注解中调用非纯表达式的写法会暴露（行为从定义时移到访问时，异常时机变化）。
- **取舍**：3.14 前的过渡策略：新代码用 `future` annotations（行为最接近 649，字符串代价只有访问时付）还是保持立即求值？库作者倾向 `future`（对用户最宽容），但要记得它把所有注解变字符串——任何 `__annotations__` 直接消费的代码要能处理字符串。真正切换 3.14 后 `future` import 变冗余但无害，可在合适窗口移除。
- **实战**：① 框架侧用 `annotationlib.get_annotations(..., format=...)` 兼容三种取值格式（3.14+），旧版本走 `typing.get_type_hints` 降级；② 审计"注解中非类型表达式"（运行时求值的 hack），它们在新语义下延迟执行；③ CI 增设 3.12/3.14 双矩阵跑一次，重点看异常栈时机变化；④ 库的 requires-python 允许 3.14 时才内联裸注解，否则维持 future 方案。

```python
# 3.12 上模拟新旧语义差异: 立即求值(NameError) vs future 字符串 vs 惰性
# 基线: Python 3.9+ 标准库 (PEP 649 语义以 3.14 为基线, 此处演示差异)


def immediate_semantics() -> None:
    """旧语义: 定义时立即求值 -> 前向引用炸 NameError。"""
    src = """
def make():
    def f(x: Missing) -> int:  # Missing 尚未定义
        return 0
    return f.__annotations__
try:
    make()
    raise AssertionError("应当 NameError")
except NameError:
    pass
"""
    exec(src, {})


def string_semantics() -> None:
    """future/字符串方案: 注解是字符串, 框架要自己 eval。"""
    def f(x: "Missing") -> int:      # 引号: 不求值
        return 0
    ann = f.__annotations__
    assert ann["x"] == "Missing"     # 字符串, 访问时也未解析


def lazy_semantics_demo() -> None:
    """PEP 649 目标语义(3.14): 访问时求值成对象; 这里用受控访问模拟。"""
    class Node: ...
    def f(x: "Node") -> int:         # 消费方按需解析
        return 0
    ann = f.__annotations__
    resolved = eval(ann["x"], {"Node": Node})   # 3.14 由解释器/annotationlib 代劳
    assert resolved is Node


def main() -> None:
    immediate_semantics()
    string_semantics()
    lazy_semantics_demo()
    print("OK: 立即求值炸前向引用 / 字符串方案把负担转给框架 / "
          "PEP649 访问时真求值(annotate function + 三格式)")


if __name__ == "__main__":
    main()
```

**追问 1**：PEP 749 里 `__annotations__` 变成按需计算的描述符，这对"直接读 `__annotations__`"的老代码意味着什么？
→ 一句话提示：读属性的行为不变（仍是 dict 语义），但求值发生在首次访问且可能抛出（注解里名字缺定义时）；依赖"import 时注解已求值、异常已发生"假设的代码要改用 annotationlib 显式指定格式并处理 FORWARDREF。

**追问 2**：为什么框架（Pydantic）偏好 PEP 649 而不是永远用字符串方案？
→ 一句话提示：字符串方案要求框架在任意调用点都能提供正确的全局/局部命名空间来 eval（模块外/局部作用域经常失败），PEP 649 把求值环境绑定回定义处由解释器管理，框架拿到的是已解析对象或可靠的前向引用占位，可靠性数量级提升。

## 背诵要点
- PEP 649（3.14）：注解从定义时立即求值改为首次访问时求值（annotate function），`__annotations__` 变按需描述符（PEP 749），前向引用/def 顺序/import 成本三大老问题解。
- 与 future 字符串方案的本质差异：字符串要框架自己 eval（环境不可靠），649 在定义处作用域内真求值，配 annotationlib 三格式（VALUE/FORWARDREF/STRING）。
- 迁移：框架适配 annotationlib 并保留 typing.get_type_hints 降级；3.14 前用 future 过渡；异常时机从 import 移到访问，CI 双矩阵盯行为变化。

## 复盘追问
- 为什么"注解求值时机改变"会暴露一些从未出错的代码？提示：定义时求值把 import 期错误前置暴露，惰性化后错误延迟到首次访问注解——依赖异常时机（启动期 fail-fast）的部署假设要重新审视。
- 库在 3.12-3.13 的过渡期怎么兼容 3.14 语义？提示：统一走 future/字符串注解 + typing.get_type_hints 消费，避免直接读 `__annotations__` 原始值；允许 3.14 后再切 annotationlib 分支，消费 API 保持单一入口。
