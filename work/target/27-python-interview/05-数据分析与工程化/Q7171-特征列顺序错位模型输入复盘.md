### Q7171 · 特征列顺序错位导致模型输入错乱：复盘

难度：P6 ｜ 标签：事故复盘、特征工程、机器学习

**问**：模型重训上线后，某类预测的准确率突然下降但整体指标正常。排查发现推理侧特征向量与训练时的列顺序不一致。这类"按位置喂特征"的事故如何根除？

**答**：**结论**：根因是**特征传递按位置（ndarray 序）而不是按名字（键绑定）**。训练侧 `model.feature_names_in_` 与推理侧手工拼装的向量顺序，任何一列的插入、删除、重排都会造成静默错位——模型不报错（数值都合法），只是"用年龄列当收入列"，而且往往只影响部分特征、部分群体，整体指标被平均值稀释，是最难发现的 ML 事故之一。

**取舍**：三种绑定方式：① 位置序（ndarray）——最快、最危险，任何 schema 变更即事故；② 名字绑定（DataFrame 传入 + sklearn 校验 `feature_names_in_`）——sklearn 会在列名不匹配时警告/报错，推荐；③ 显式 schema 声明（列名→位置映射单独定义、代码与训练产物共享同一份）——适合特征上百的工业管线。三者可以叠加：schema 单一事实源 + DataFrame 传递 + 训练时锁定 `feature_names_in_` 快照。

**实战**：推理侧守门三件套：① 列名集合断言（`set(actual) == set(expected)`，缺失/多余列 fail-fast）；② 关键特征分布监控（PSI/均值漂移，错位列会立刻显形——Q7009 的 PSI 监控在推理侧复用）；③ 上线灰度与金样本集：固定一批输入/输出对，任何错位都会偏离金样本预测。

```python
from dataclasses import dataclass
import numpy as np

@dataclass(frozen=True)
class FeatureSchema:
    """特征的单一事实源：列名 -> 位置。训练与推理共用同一份。"""
    names: tuple[str, ...]
    def index(self, name: str) -> int:
        return self.names.index(name)
    def validate(self, actual: list[str]) -> None:
        if set(actual) != set(self.names):
            missing = set(self.names) - set(actual)
            extra = set(actual) - set(self.names)
            raise ValueError(f"特征不匹配 缺失={missing} 多余={extra}")
        if len(actual) != len(self.names):
            raise ValueError("列数一致但顺序可能错位——按名字绑定传递")

SCHEMA = FeatureSchema(("age", "income", "tenure"))

def to_vector(row: dict, schema: FeatureSchema) -> np.ndarray:
    """按名字取值组装向量：列顺序怎么变都不会错位。"""
    schema.validate(list(row.keys()))
    return np.array([row[n] for n in schema.names])

# 模拟事故：训练后 schema 加了列 'debt'，推理侧手工拼向量没跟上
train_vec = np.array([35, 50000.0, 4])          # [age, income, tenure]
manual_vec = np.array([35, 50000.0, 4, 0.2])    # 新增 debt 在末尾，旧模型忽略？不——
# 若有人把 debt 插到中间而没改顺序映射，位置绑定就错位了：
misordered = np.array([35, 0.2, 50000.0, 4])    # debt 插在 income 前
print("错位向量的 income 位置读到:", misordered[SCHEMA.index("income")],
      "（实际是 0.2，模型把负债当收入）")

# 名字绑定的正确传递：validate 直接拦截
try:
    to_vector({"age": 35, "tenure": 4, "debt": 0.2}, SCHEMA)  # 缺 income
except ValueError as e:
    print("守门拦截:", e)

# 金样本守门：锁定输入 -> 预测的映射，任何错位都会偏离
golden = [{"age": 35, "income": 50000.0, "tenure": 4}]
golden_out = [np.array([35, 50000.0, 4]).sum()]   # 假模型 = 求和
for row, expect in zip(golden, golden_out):
    got = to_vector(row, SCHEMA).sum()
    assert np.isclose(got, expect), "金样本偏离：特征管线被改坏"
print("金样本校验通过")
```

**追问 1**：为什么"整体指标正常"反而说明问题更严重？
提示：错位往往只影响个别特征、个别客群，聚合指标被稀释；等业务指标（转化率）可见时损失已持续数周——这正是推理侧特征分布监控（单列 PSI）先于聚合指标报警的原因。

**追问 2**：sklearn 的 `feature_names_in_` 校验能替代 schema 管理吗？
提示：它能挡"列名不匹配"，但挡不住"列名对、值语义错"（上游把收入列填了负债值）；schema 管理 + 分布监控 + 金样本是三层防线，前者只是第一层。

**追问 3**：特征上百列时，金样本怎么维护才不会腐烂？
提示：金样本随重训流水线自动再生成（训练最后一步固化），禁止手工编辑；版本化存档，比对失败先怀疑管线而不是模型。

## 背诵要点
1. 按位置喂特征是 ML 事故首因：列增删/重排静默错位，模型不报错只算错。
2. 三层防线：schema 名字绑定（fail-fast）+ 单列分布监控（PSI 显形错位）+ 金样本守门。
3. sklearn 的 feature_names_in_ 只挡列名不匹配，挡不住值语义错；schema 是单一事实源。
