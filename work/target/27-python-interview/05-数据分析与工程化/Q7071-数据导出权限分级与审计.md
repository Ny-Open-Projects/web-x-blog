### Q7071 · 数据导出的权限分级与导出审计

难度：P5 | 标签：数据安全、RBAC、导出审计、脱敏

**问**：一个分析师把 800 万行用户表分 5 次全部导出，一周后出现在竞品手里。导出功能"人人可用、导完不记"缺了哪几层防线？导出审计要记录什么、怎么发现"拖库式导出"？

**答**：
- **结论**：导出是数据出域的最后闸门，需要三层：① 角色分权（RBAC）：行数上限、字段脱敏（手机号/身份证按角色掩码）、表白名单——分析师默认拿不到全量敏感表；② 全量审计：每次导出记录 who/when/table/rows/cols/来源 IP，让"谁拿走了什么"可追溯（事后追责与影响面评估都靠它）；③ 行为异常告警：短窗口高频导出、单次行数贴近上限、敏感表首次访问——拖库式导出的模式特征明显（分批贴上限），频次告警能把"5 次导完 800 万行"拦在第三批。
- **取舍**：脱敏粒度是业务摩擦的来源：全脱敏让分析没法做（看不了分运营商的用户行为），合理折中是"分析域脱敏副本 + 精确查询走审批"——把"需要明文"变成显式申请而不是默认能力。审计全量记录有存储成本，但导出事件量级远低于业务日志，全量是底线，采样省下的钱不值得。
- **实战**：落地清单：① 导出走统一网关（禁止直连 DB 客户端自由查询导出），网关内嵌权限与审计；② 高敏表加导出水印（记录导出者身份到文件元数据）；③ 审计日志的告警规则进 SOC：贴上限分批导出、非工作时段导出、新账号首日大量导出。

```python
"""数据导出的权限分级与导出审计：字段脱敏、频次告警与水印。"""
import time
from dataclasses import dataclass, field

@dataclass
class Role:
    max_rows: int
    masked_cols: frozenset[str]
    allowed_tables: frozenset[str]

ROLES = {
    "analyst": Role(10_000, frozenset({"phone"}), frozenset({"orders", "users"})),
    "admin": Role(1_000_000, frozenset(), frozenset({"orders", "users"})),
}

def mask(value: str) -> str:
    return value[:3] + "****" + value[-2:] if len(value) > 5 else "****"

@dataclass
class AuditLog:
    entries: list[dict] = field(default_factory=list)

    def record(self, user: str, table: str, rows: int, cols: list[str]) -> dict:
        e = {"t": time.time(), "user": user, "table": table,
             "rows": rows, "cols": cols}
        self.entries.append(e)
        return e

    def burst_alert(self, user: str, window_s: float = 600, threshold: int = 4) -> bool:
        now = time.time()
        recent = [e for e in self.entries if e["user"] == user and now - e["t"] < window_s]
        return len(recent) >= threshold

log = AuditLog()

def export(user: str, role_name: str, table: str, cols: list[str], rows: list[dict]):
    role = ROLES[role_name]
    assert table in role.allowed_tables, f"{role_name} 无权导出 {table}"
    assert len(rows) <= role.max_rows, f"超出 {role_name} 上限 {role.max_rows} 行"
    masked_cols = [c for c in cols if c in role.masked_cols]
    out = [{**r, **{c: mask(r[c]) for c in masked_cols if c in r}} for r in rows]
    log.record(user, table, len(rows), cols)
    return out

users = [{"name": "张三", "phone": "13812345678"}] * 3
print("analyst 导出 users:", export("u1", "analyst", "users", ["name", "phone"], users)[0])
print("admin   导出 users:", export("boss", "admin", "users", ["name", "phone"], users)[0])

# 频次异常：同一账号短窗口连续导出 -> 告警（拖库的前兆行为）
for i in range(4):
    export("u1", "analyst", "orders", ["order_id", "phone"],
           [{"order_id": i, "phone": "13800000000"}])
print("10 分钟内第 5 次导出 -> 频次告警触发：", log.burst_alert("u1"))
print("治理：角色分权（行数上限+列脱敏+表白名单）+ 全量导出审计 + 频次异常告警")
```

**追问链**：
1. 追问一层：为什么"分批贴上限"是拖库的特征模式而不是误报噪声？——正常分析一次导几千行足够，连续多次恰好贴着上限（10000/10000/10000…）是"绕过单次上限拿全量"的刻意行为；误报（大促复盘批量导出）有明确的业务背景且列集合分散，两者在审计维度上可区分。
2. 追问二层：为什么导出审计不能只在应用层做？——绕过应用层（直连数据库客户端、BI 工具直连）的导出应用层看不见；数据库侧的审计（连接来源、查询语句、返回行数）与应用层审计互为补充，对账两边的行数差就是"绕道导出"的检测信号。

**背诵要点**：
1. 三层防线：RBAC 分权（行数上限/列脱敏/表白名单）+ 全量审计 + 行为异常告警。
2. 拖库特征：短窗口高频、分批贴上限、敏感表集中；频次告警拦在半路。
3. 导出走统一网关，DB 侧审计与应用层审计对账，补齐绕道出口。

**复盘追问**：
1. 事后追责时，审计日志里最关键的字段是什么？（who + rows + cols + 来源 IP/设备指纹——决定影响面评估与"数据是否可撤销"；没有来源信息的审计无法区分账号被盗与本人操作）
2. 为什么"分析师需要明文"要走审批而不是放开权限？（审批把例外显式化：谁、为什么、多久；放开的权限是静默的常态，出事后无法回答"这 800 万人谁批的"）
