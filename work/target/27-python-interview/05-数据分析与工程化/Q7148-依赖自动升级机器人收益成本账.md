### Q7148 · 依赖自动升级机器人（Dependabot/Renovate）收益成本账

难度：P6-P7 | 标签：成本工程、依赖管理、Renovate

**问**：仓库 200 个直接依赖，安全通告平均每月 5 起。要不要引入 Renovate/Dependabot 自动升级？引入后的收益与隐性成本怎么算？

**答**：结论：升级机器人的收益是**把"被动救火式升级"换成"常态化小步升级"**——安全暴露窗口缩短 + 每次变更 diff 小、易回滚；成本有三笔：① 评审成本：每个 PR 都要人看，低价值 PR 会淹没评审队列；② CI 成本：每个 PR 跑全量测试，矩阵越大越贵（Q7047）；③ 破坏成本：次要版本也可能有行为变化，自动化合入会把破坏分散到每天（Q7102 锁文件漂移同源问题）。策略账的核心是**分层**：安全补丁全自动、锁文件内 patch/minor 自动、major 必须人工+灰度。

实战要点：
1. 按变更半径分组：同生态（pytest 插件组、django 组）合一个 PR，减少评审次数；组内 `allowedVersions` 限制节奏。
2. 合入门槛自动化：PR 必须过"全量测试 + 冒烟"才允许自动合并；flaky 用例（Q7058）必须先治理，否则机器人会把 flaky 放大成"升级破坏"。
3. 关键依赖白名单例外：ORM、HTTP 框架这类"变更半径大"的依赖退出自动升级，走版本演进专项（Q7049、Q7086）。

```python
"""升级机器人分层策略成本账（标准库，可运行）"""
from dataclasses import dataclass


@dataclass
class UpgradePolicy:
    auto_patch: bool = True       # 锁内 patch/minor 自动
    auto_security: bool = True    # 安全通告全自动
    auto_major: bool = False      # major 人工
    review_minutes: float = 10    # 每 PR 评审成本
    ci_minutes: float = 15
    ci_cost_per_min: float = 0.6


def monthly_cost(policy: UpgradePolicy, prs: int) -> float:
    return prs * (policy.review_minutes + policy.ci_minutes
                  * policy.ci_cost_per_min)


pol = UpgradePolicy()
manual_prs, auto_prs = 3, 22            # major 手工 vs 分层后机器人 PR
print("全人工升级月成本:", f"{monthly_cost(pol, manual_prs + 10):,.0f} 元")
print("分层自动月成本:", f"{monthly_cost(pol, auto_prs):,.0f} 元")

# 收益侧：安全暴露窗口（通告到修复的天数）从 30 天压到 3 天
window_manual, window_auto = 30, 3
print("安全暴露窗口缩短:", f"{(window_manual - window_auto) / window_manual:.0%}")


def classify(version_delta: str, security: bool) -> str:
    """PR 分层路由"""
    if security:
        return "auto-merge"       # 过测试即合
    if version_delta.startswith("major"):
        return "human + canary"
    return "auto-merge after full CI"


print([classify(d, s) for d, s in
       [("patch", False), ("minor", False), ("major", False), ("patch", True)]])
```

**追问 1**：为什么"所有 PR 自动合并"在这种账下是错的？
**提示**：major 破坏会分散且难归因，出问题时排查成本远超评审成本；分层是把风险按变更半径定价。

**追问 2**：flaky 用例和升级机器人互相放大的机制是什么？
**提示**：机器人频繁触发 CI，flaky 偶发失败导致自动合并被卡或被误判为升级破坏，要么加人的工作量要么让人关掉绿灯纪律。

## 背诵要点
- 机器人收益=安全暴露窗口缩短+小步 diff；成本=评审+CI+破坏分散，按变更半径分层定价。
- 分层：安全补丁/锁内 minor 自动，major 人工+灰度；大半径依赖（ORM/框架）出白名单。
- 引入前先治理 flaky，否则机器人会放大它。
