### Q7155 · 中间结果缓存指纹与失效成本账：重算一次值多少钱

难度：P6-P7 | 标签：成本工程、缓存、数据管道

**问**：特征/报表管道每天重算 3 小时，但上游表一天只变更 5%。团队想加"中间结果缓存"：输入指纹没变就直接复用昨天的结果。这笔成本账怎么算？指纹怎么设计才不会"该失效不失效、不该失效乱失效"？

**答**：结论：缓存收益 = 跳过的重算时长 × 算力单价（机时费或人力等待成本）；失效成本 = 一次脏数据流入下游的返工代价。指纹设计的核心是**覆盖输入的"内容"而非"形式"**：对每个输入物（表/文件/参数）计算 `hash(数据指纹 + 代码版本 + 处理参数)`，任何一项变化就失效。数据指纹在表级用"分区 max(更新时间) + 行数 + 抽样 checksum"，比 mtime 稳（mtime 会因无关写入误触发，属"不该失效乱失效"）。工程上推荐 hashicorp 风格的 DAG 感知指纹：节点指纹 = hash(自身指纹 + 全部上游指纹)，上游变更自动级联失效。

取舍与实战：
1. 粒度选择：表级指纹粗（10% 变更失效整表重算）、分区级细（只重算变更分区）；粒度越细指纹计算成本越高，按"单分区重算时长 > 指纹计算时长 10 倍"定粒度。
2. 成本账要含指纹本身的成本：大表 checksum 不便宜，抽样校验（如 hash 前 1000 行 + 统计聚合）是折中；指纹计算耗时必须 < 重算时长的 5%，否则缓存净亏。
3. 失效白名单：代码版本参与指纹意味着每次发版全量失效——把"纯重构不改行为"的变更用 pipeline 版本号豁免，发版声明里显式声明行为不变。
4. 与 Q2867（LLM 请求指纹）同构但输入不同：数据管道的输入是"数据集状态"，要防抽样校验的假阴性（变更恰好没落在抽样里），关键表用分区级精确指纹。

```python
"""DAG 节点缓存指纹：上游级联失效 + 抽样数据指纹（标准库，可运行）"""
import hashlib, json

def _h(obj) -> str:
    return hashlib.sha256(json.dumps(obj, sort_keys=True).encode()).hexdigest()[:16]

def dataset_fingerprint(rows: list[dict], sample: int = 3) -> str:
    """表级指纹：行数 + 聚合统计 + 首尾抽样（生产中换成 DB 端实现）"""
    stats = {"n": len(rows),
             "sum_id": sum(r.get("id", 0) for r in rows) if rows else 0}
    sample_rows = (rows[:sample] + rows[-sample:]) if rows else []
    return _h([stats, sample_rows])

def node_fingerprint(code_version: str, params: dict,
                      upstream_fps: list[str], dataset_fp: str) -> str:
    """节点指纹 = 代码版本 + 参数 + 上游指纹级联 + 自身输入数据指纹"""
    return _h([code_version, params, sorted(upstream_fps), dataset_fp])

rows = [{"id": i, "amt": i * 0.5} for i in range(100)]
fp1 = node_fingerprint("v3", {"window": 7}, ["up1_fp"], dataset_fingerprint(rows))
fp2 = node_fingerprint("v3", {"window": 7}, ["up1_fp"], dataset_fingerprint(rows))
fp3 = node_fingerprint("v3", {"window": 30}, ["up1_fp"], dataset_fingerprint(rows))
assert fp1 == fp2 and fp1 != fp3
print("同输入同指纹:", fp1, "| 参数变更→失效:", fp3)
```

**追问 1**：为什么"输入文件的 mtime/文件名时间戳"是不可靠指纹？
**提示**：mtime 会被无关操作触碰（重写相同内容、同步工具），导致"不该失效乱失效"——缓存命中率虚低等于没做；且跨集群复制 mtime 不稳定，指纹必须是内容派生。

**追问 2**：缓存命中但下游代码升级了输出 schema，怎么防旧结构污染？
**提示**：输出 schema 版本也要进指纹（或存缓存时带 schema 版本号），读取端校验不匹配即视为 miss 并重算——指纹要覆盖"输入 + 处理 + 输出契约"三段。

## 背诵要点
- 收益 = 跳过重算 × 单价，失效风险 = 脏数据下游返工；指纹计算耗时须 < 重算时长 5%。
- 指纹三段：内容派生的数据指纹（行数+聚合+抽样，不用 mtime）+ 代码版本 + 上游级联。
- 粒度按分区级细化；纯重构发版用 pipeline 版本号豁免，防全量失效。
