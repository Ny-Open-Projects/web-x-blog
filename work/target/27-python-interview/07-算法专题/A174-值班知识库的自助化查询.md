### A174 · 值班知识库自助化

> 难度:★★☆ | 标签:知识库, RAG, 值班

**问**（笔试·编程+场景题）：值班遇到问题先问老员工（老员工被打断 20 次/天）——知识库自助查询怎么建（问答对来源：从历史工单/聊天记录自动抽取），「先搜再问」的文化怎么建立（问了没搜→回答者把答案贴回知识库），知识库的检索质量（RAG，Q7503）在值班场景的特殊要求（紧急时刻要秒出答案且可定位手册原文），「知识库答案是错的」比没答案更糟怎么防？

**答**：① 问答对来源：历史工单（问题-解决方案对——结构化最好抽）、值班聊天记录（高频问答人工筛选入库）、手册拆条（A142 手册的每条告警处置=一个问答对）——**新问答的入库纪律**：每次「问了没搜」的对话，回答者负责把答案贴回知识库（回答即入库，把知识转移的成本摊到对话里）。② 值班场景 RAG 特殊要求：**快**（秒级返回，值班在事故中）、**可定位**（答案附手册原文链接+操作命令可复制——值班要的是「下一步做什么」，不是综述）、**置信度标注**（低置信答案明确标注并建议升级）——事故中的错误答案会引导错误操作，比没答案糟。③ 防错答案：答案带「验证状态」（validated=老员工确认过/unverified=自动抽取未确认）+ 值班优先用 validated、unverified 需交叉验证 + 定期复核（访问多的 unverified 优先请专家确认）。

```python
# 全部标准库；demo 实现「值班知识库检索（问答对+置信度+可定位）」
import time

KB = [
    {"q": "订单服务 5xx 飙升怎么处理", "a": "1.查 trace 归因 2.切只读降级 3.叫 pay 团队",
     "link": "runbook/orders-5xx", "validated": True, "hits": 30},
    {"q": "Redis 连接池耗尽", "a": "检查 maxclients 与池泄漏，紧急可重启池",
     "link": "runbook/redis-pool", "validated": False, "hits": 5},
]

def search_kb(query: str, threshold: float = 0.4) -> dict | None:
    """值班检索：返回可定位答案（链接+置信度），低置信标注。"""
    best, best_score = None, 0.0
    for item in KB:
        qw = set(query.lower().split())
        kw = set(item["q"].lower().split())
        score = len(qw & kw) / max(len(qw | kw), 1)
        if score > best_score:
            best, best_score = item, score
    if best is None or best_score < threshold:
        return None                                   # 宁可无答案不给错答案
    return {"answer": best["a"], "link": best["link"],          # 可定位手册原文
            "validated": best["validated"], "score": round(best_score, 2),
            "warn": None if best["validated"] else "⚠ 未验证答案，请交叉确认"}

def answer_then_ingest(query: str, answer: str, kb: list):
    """「问了没搜」纪律：回答者把答案贴回知识库（unverified 入库）。"""
    kb.append({"q": query, "a": answer, "link": "chat-verbatim",
               "validated": False, "hits": 0, "ts": time.time()})

if __name__ == "__main__":
    r = search_kb("订单服务 5xx 处理")
    assert r["validated"] and r["link"].startswith("runbook")
    print("值班检索:", r["answer"][:20], "| 手册:", r["link"], "| 已验证 ✅")
    r2 = search_kb("Redis 连接池耗尽了")
    assert r2 and r2["warn"] and "未验证" in r2["warn"]
    print("未验证答案标注:", r2["warn"])
    assert search_kb("完全无关的问题火星天气") is None     # 宁可无答案
    print("低相似拒绝（宁可无答案不给错答案）✅")
    answer_then_ingest("DNS TTL 怎么调", "改 ndots 后轮询生效", KB)
    print("回答即入库（unverified，等专家确认）✅ 知识库条数:", len(KB))
    # 口径：值班 RAG 三要求（快/可定位/置信标注）；错误答案比没答案糟；
    # 回答即入库——知识转移成本摊进对话。
```

**追问**：1) 为什么「回答即入库」的纪律是关键？——知识转移的默认路径（口口相传）不可持续（老员工被打断+答案不沉淀）；「回答必须同步入库」把每次问答变成知识库资产增量——入库成本压到最低（贴原文即可，unverified 状态允许粗粒度入库）2) 值班场景检索「秒级返回」怎么保证？（提示：知识库规模小（千级问答对）直接内存检索即可；若用 RAG 向量库（万级以上）——ANN 索引+预热（Q6020）保证首查也快；事故中不能等冷启动）3) 知识库的「访问统计」驱动什么？（提示：高频 unverified 条目优先请专家验证（投入产出最高）+ 高频问题暴露手册缺口（手册扩条）+ 零访问条目进过期审查（Q168）——访问数据是知识库治理的燃料）

## 背诵要点
1. 问答对三来源：历史工单/值班聊天/手册拆条；「回答即入库」纪律——知识转移摊进对话。
2. 值班 RAG 三要求：秒级返回、答案可定位（手册原文+可复制命令）、置信度标注——错误答案比没答案糟。
3. 检索三防：低相似拒绝、unverified 标注交叉确认、低相似宁可无答案——访问统计驱动验证与治理。

## 复盘追问
1. 知识库检索命中了「错误答案」导致值班操作失误，复盘责任怎么分？（提示：unverified 标注是否清晰、答案是否该验证而未验证（高频未验证=知识库治理失职）+ 错误答案立即下架并登记（同 A170 API 废弃语义）——知识库错误按内容事故同等对待）
2. 「先搜再问」执行两个月，老员工被打断次数没降——为什么？（提示：检索质量（命中不到/答案没用）导致大家放弃搜索——看「问后是否命中」的漏斗数据：搜了没命中→补知识库；没搜就问→流程强化（问问题时机器人先贴检索结果）——漏斗归因再对症下药）
