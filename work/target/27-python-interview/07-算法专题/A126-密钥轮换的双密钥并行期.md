### A126 · 密钥轮换

> 难度:★★☆ | 标签:密钥管理, 轮换, 安全

**问**（笔试·编程+场景题）：签名密钥泄露需要立刻换——「换密钥导致所有已签 token 失效」（用户全下线）怎么避免？双密钥并行期怎么设计（新钥签、双钥验），轮换的完整生命周期（生成→分发→切换→废弃）各步的安全要点，「密钥在配置里明文」这类初始问题怎么根治（KMS/环境注入）？

**答**：① 双钥并行（kid 机制）：签名头带 `kid`（key id），验签按 kid 查当前/上一把密钥——**新钥签、双钥验**：切换瞬间已发的旧钥 token 在自然过期前仍可验证（不强制全下线），新请求全部用新钥签；旧钥在「最长 token 有效期 + 缓冲」后废弃。② 生命周期五步：生成（KMS 内生成，私钥不出 HSM）、分发（验签方只需公钥，可公开——签名/验签分离让分发零风险）、切换（签发方切新钥）、废弃（旧钥标记 revoked，验签拒绝）、审计（每步记录谁在何时操作——密钥操作是最高敏感审计项）。③ 根治明文密钥：**KMS/Secret Manager**（运行时 API 取钥，不落盘）→ 环境注入（容器编排 secret）→ 代码仓库扫描（pre-commit + CI secret scanning 防回潮）——密钥进 git 的代价是「历史里永远存在，轮换所有历史密钥」。

```python
# 全部标准库；demo 实现 kid 双钥轮换（新签旧验 + 过期废弃）
import hmac, hashlib, time, json, base64

def sign(payload: dict, key: bytes, kid: str) -> str:
    body = json.dumps(payload, sort_keys=True).encode()
    sig = hmac.new(key, body, hashlib.sha256).hexdigest()
    token = base64.urlsafe_b64encode(body).decode().rstrip("=")
    return f"{kid}.{token}.{sig}"

def verify(token: str, keyring: dict[str, tuple[bytes, str]]) -> dict | None:
    kid, body_b64, sig = token.split(".")
    state = keyring.get(kid)
    if state is None or state[1] == "revoked":
        return None                                  # 未知/废弃密钥拒绝
    body = base64.urlsafe_b64decode(body_b64 + "==")
    expect = hmac.new(state[0], body, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expect, sig):
        return None
    payload = json.loads(body)
    if payload["exp"] < time.time():
        return None
    return payload

def rotate(keyring: dict[str, tuple[bytes, str]], old_kid: str,
           new_kid: str, new_key: bytes, token_ttl: int) -> dict[str, tuple[bytes, str]]:
    """轮换四步：新钥 active → 旧钥 retiring（可验不可签）→ 过 TTL 废弃。"""
    keyring[new_kid] = (new_key, "active")
    keyring[old_kid] = (keyring[old_kid][0], "retiring")
    # 废弃时机 = 切换时刻 + token_ttl（旧 token 自然过期后再废）
    keyring["_rotate_note"] = (f"old {old_kid} retire after {token_ttl}s", "")  # 审计语义演示
    return keyring

if __name__ == "__main__":
    ring = {"k1": (b"secret-v1", "active")}
    old_token = sign({"uid": "u1", "exp": time.time() + 600}, ring["k1"][0], "k1")
    ring = rotate(ring, "k1", "k2", b"secret-v2", token_ttl=600)
    new_token = sign({"uid": "u2", "exp": time.time() + 600}, ring["k2"][0], "k2")
    # 新请求用新钥签：验签走 k2
    assert verify(new_token, ring)["uid"] == "u2"
    # 旧 token 在 retiring 期仍可验（用户不掉线）✅
    assert verify(old_token, ring)["uid"] == "u1"
    # 废弃后旧 token 全拒（retiring → revoked）
    ring["k1"] = (ring["k1"][0], "revoked")
    assert verify(old_token, ring) is None
    print("双钥轮换：新签旧验 → 废弃拒绝，全程用户无感 ✅")
    # 泄露应急：跳过 retiring 直接 revoked（牺牲在线用户换安全）。
    # 根治口径：KMS 运行时取钥不落盘 + git secret scanning 防回潮。
```

**追问**：1) 泄露时为什么要跳过 retiring 直接 revoked？——retiring 期攻击者手里的旧钥仍可伪造 token（双钥验签让它活着）；泄露场景安全 > 可用性：立刻废弃，在线用户重新登录的代价是可接受的。2) 「验签方只需要公钥」对非对称签名（RS256）意味着什么？——签名服务持私钥（KMS 内），所有验签服务拿公钥（可随意分发）——私钥零分发是攻击面收缩的关键；HS256 对称钥则每验签方都要密钥=分发面大，生产 JWT 首选 RS256。3) 密钥操作的审计为什么是最高敏感级？——审计日志能反推密钥使用模式与轮换时间窗（攻击者精准选择窗口）；密钥审计日志独立存储+告警（谁读钥/轮钥/废钥）。

## 背诵要点
1. kid 双钥轮换：新钥 active 签发、旧钥 retiring 可验（用户无感）、过 TTL 废弃 revoked。
2. 泄露应急跳过 retiring 直接废弃——安全优先于可用性；非对称（RS256）私钥零分发收缩攻击面。
3. 根治明文密钥：KMS 运行时取钥不落盘 + secret scanning 防回潮；密钥操作审计最高敏感级。
