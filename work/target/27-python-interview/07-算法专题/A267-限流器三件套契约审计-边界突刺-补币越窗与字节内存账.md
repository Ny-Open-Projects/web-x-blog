### A267 · 限流器三件套的契约审计

> 难度:★★★★ | 标签:限流, 固定窗口, 滑动日志, 令牌桶, 内存账, 合规审计

**问**（笔试·编程题）：限流器三件套——固定窗口、滑动日志、令牌桶——每本教材都会讲，但面试官要的是**审计级对比**：把限流合同拆成三条款——W「任意 W 秒滑动窗内放行 ≤ L 条（总量契约）」、R「长期平均速率 ≤ r/s（速率契约）」、B「瞬时突发 ≤ b 条（突发契约）」。要求：① 三件套共用一个**可注入的确定性时钟**实现各自的 `allow()`（禁裸 `time.time()`，测试必须可复现）；② 实现**放行审计器**：输入放行时刻序列，输出任意 W 秒滑动窗内的最大放行数——用同一份轨迹（L=10/秒，t=0.99 打 10 条、t=1.01 再打 10 条）跑出三件套的合规矩阵，逐格断言谁违约、违约几条；③ 用第二份轨迹（10 条同一时刻打完）区分「总量合规」与「突发整形」：滑动日志总量零违规为什么仍可能把下游打穿？令牌桶的 capacity 怎么扛住它；④ 字节级内存账：用 `sys.getsizeof` 实测三者满载状态的真实字节数，给出「内存账 × 合规性」的选型结论。请说清与 A101（单机实现四连与 Redis Lua 原子化）、A248（窗口类精确 vs 分桶近似的误差账，不含令牌桶）、A239（分布式令牌桶与时钟漂移）、Q139（四算法概念对比）的分工——本题只回答「**三件套对一份合同的合规矩阵，与各自状态的字节账**」。

**答**：① 分工与动机：A101 回答「怎么实现、分布式怎么原子化」，A248 回答「窗口类内部精确与近似差多少」，Q139 是概念层面的四算法罗列——但没有人回答过面试官真正的那一问：「**这三个器对同一份合同，各自的违约点在哪一格**」。「限流」不是一个指标而是三条款，每个算法都是对三条款的一次不同让步组合，矩阵比文字更能暴露认知盲区。② 审计口径先定死：合同约束的是「放行」，所以审计必须用**放行时刻**而不是请求时刻（被拒请求不占配额，用请求时刻审计会把被限流量错算成违规）；审计函数对放行序列算「任意 W 秒窗内最大放行数」。合规矩阵实测：**固定窗口 W 条款必违**——0.99s 与 1.09s 各放 10 条，审计量出 20 > 10，窗口边界 2 倍突刺，这是结构性缺陷不是参数没调好；**滑动日志 W 条款合规**——同一轨迹第二批次全拒，审计 10 = 10；**令牌桶 W 条款也违**——第一波 10 条清空满桶，0.1 秒惰性补币补出 1 枚又放 1 条，审计 11 > 10。这一格是最大盲区：**令牌桶不是窗口合规限流器**，对外承诺「每秒最多 N 次」的合同不能拿裸令牌桶去顶。但注意违约量级的天壤之别：固定窗口违约上界是 2L（无界于 L），令牌桶违约上界是 `capacity + r·W`（满桶起窗 + 窗内补币全打完），可控且可写进合同附件——**都违约，但一个要改设计，一个只要改承诺口径**。③ 突发条款把剩余分歧切开：10 条同一时刻打完——滑动日志全放（总量契约完美，但 1ms 内 10 个并发照样把下游打穿：它约束的是**记账口径**，不是到达速率）；令牌桶 capacity=4 只放 4 条（capacity 正是 B 条款的承载者，rate 承载 R 条款，两个参数与两条款一一对应）。所以「滑动日志 vs 令牌桶」不是精度之争而是**条款之争**：合同写总量用日志型，合同写速率 + 突发用令牌桶，两个都要就得两级串联取 AND。④ 字节账：满载 1000 条额度的滑动日志，deque 容器加 1000 个 float 对象实测约 3.3 万字节；固定窗口状态是 1 个 int、令牌桶是 2 个 float，都在百字节级——三个数量级的差距决定了多租户网关上滑动日志只能留给「低频高价值」操作（登录、支付、改密），高频接口必须 O(1) 状态。⑤ 选型结论一句话：**先问合同是哪一条款，再问状态内存付不付得起**——W 条款 + 高频 → 分桶近似（A248）；W 条款 + 低频严苛 → 滑动日志；R/B 条款 → 令牌桶；三者皆要 → 串联组合器。

```python
# 全部标准库；限流三件套契约审计：同一轨迹喂三个限流器，输出合规矩阵与字节内存账
import sys
from collections import deque


class Clock:
    """确定性时钟：时间可注入，测试可复现（禁裸 time.time()）。"""

    def __init__(self, t=0.0):
        self.t = t


class FixedWindow:
    """固定窗口：O(1) 状态，窗口边界有结构性 2 倍突刺。"""

    def __init__(self, limit, window, clock):
        self.limit, self.window, self.clock = limit, window, clock
        self._idx = None
        self._cnt = 0

    def allow(self):
        idx = int(self.clock.t // self.window)
        if idx != self._idx:
            self._idx, self._cnt = idx, 0
        if self._cnt >= self.limit:
            return False
        self._cnt += 1
        return True


class SlidingLog:
    """滑动日志：deque 存放行时刻，任意滑动窗总量精确。"""

    def __init__(self, limit, window, clock):
        self.limit, self.window, self.clock = limit, window, clock
        self._hits = deque()

    def allow(self):
        now = self.clock.t
        cutoff = now - self.window
        while self._hits and self._hits[0] <= cutoff:
            self._hits.popleft()
        if len(self._hits) >= self.limit:
            return False
        self._hits.append(now)
        return True


class TokenBucket:
    """令牌桶：惰性补币，capacity=瞬时突发上限，rate=长期均值。"""

    def __init__(self, rate, capacity, clock):
        self.rate, self.capacity, self.clock = rate, capacity, clock
        self._tokens = float(capacity)
        self._last = clock.t

    def allow(self):
        now = self.clock.t
        self._tokens = min(self.capacity,
                           self._tokens + (now - self._last) * self.rate)
        self._last = now
        if self._tokens >= 1.0 - 1e-9:
            self._tokens -= 1.0
            return True
        return False


def max_in_window(times, span):
    """放行审计器：放行时刻序列里，任意长 span 的滑动窗内最多放了几条。"""
    best = 0
    for i in range(len(times)):
        j = i
        while j < len(times) and times[j] - times[i] < span:
            j += 1
        best = max(best, j - i)
    return best


def audit(name, limiter, clock, arrivals, limit, window):
    """喂同一份请求轨迹，返回 (放行时刻序列, 审计最大值)。"""
    allowed = []
    for t in arrivals:
        clock.t = t
        if limiter.allow():
            allowed.append(t)
    worst = max_in_window(allowed, window)
    verdict = "合规" if worst <= limit else "违约(+%d)" % (worst - limit)
    print("%-10s 放行 %2d 条，任意 %gs 窗最多 %2d 条（合同 %d）-> %s"
          % (name, len(allowed), window, worst, limit, verdict))
    return allowed, worst


if __name__ == "__main__":
    LIMIT, WINDOW = 10, 1.0
    trace = [0.99] * 10 + [1.09] * 10        # 边界突刺轨迹：0.99 十条 + 1.09 十条

    # 1) 合规矩阵：同一轨迹，三件套逐格断言
    c1 = Clock()
    _, fw_worst = audit("固定窗口", FixedWindow(LIMIT, WINDOW, c1), c1, trace, LIMIT, WINDOW)
    assert fw_worst == 20, fw_worst          # 边界 2 倍突刺，W 条款违约

    c2 = Clock()
    _, log_worst = audit("滑动日志", SlidingLog(LIMIT, WINDOW, c2), c2, trace, LIMIT, WINDOW)
    assert log_worst == LIMIT, log_worst     # 第二批全拒，W 条款合规

    c3 = Clock()
    _, tb_worst = audit("令牌桶", TokenBucket(10.0, 10.0, c3), c3, trace, LIMIT, WINDOW)
    assert tb_worst == 11, tb_worst          # 补币越窗 11 > 10：W 条款也违，但上界 = cap + r·W
    assert tb_worst < fw_worst               # 同为违约，量级天壤之别：12 vs 20
    print("违约上界: 固定窗口可达 2L=%d；令牌桶上界 cap+r·W=%.0f -> 改承诺口径即可收敛"
          % (2 * LIMIT, 10.0 + 10.0 * WINDOW))

    # 2) 突发条款：10 条同一时刻打完，区分「总量合规」与「突发整形」
    burst = [0.0] * 10
    c4 = Clock()
    b_log, _ = audit("日志·突发", SlidingLog(LIMIT, WINDOW, c4), c4, burst, LIMIT, WINDOW)
    assert len(b_log) == 10                  # 总量合规，但 1ms 内 10 并发照样打穿下游
    c5 = Clock()
    b_tb, _ = audit("令牌桶·突发", TokenBucket(10.0, 4.0, c5), c5, burst, LIMIT, WINDOW)
    assert len(b_tb) == 4                    # capacity=4 是 B 条款的承载者
    print("突发整形: 日志型 10 条同毫秒全放（无速率语义）；令牌桶被 capacity 钳到 4 ✅")

    # 3) 字节级内存账：满载 1000 条额度的真实字节数
    c6 = Clock()
    log1000 = SlidingLog(1000, 60.0, c6)
    for i in range(1000):
        c6.t = i * 0.01
        log1000.allow()
    log_bytes = (sys.getsizeof(log1000._hits)
                 + sum(sys.getsizeof(x) for x in log1000._hits))
    fw = FixedWindow(1000, 60.0, c6)
    tb = TokenBucket(1000.0, 1000.0, c6)
    fw_bytes = sys.getsizeof(fw._cnt)                       # int 状态量级
    tb_bytes = sys.getsizeof(tb._tokens) + sys.getsizeof(tb._last)   # 2 个 float
    print("内存账: 滑动日志满载 %d B；固定窗口 int 状态 %d B；令牌桶 2 个 float %d B"
          % (log_bytes, fw_bytes, tb_bytes))
    assert log_bytes > 10 * tb_bytes         # 差两个数量级以上：多租户高频接口必须 O(1) 状态
    print("选型: W 条款高频->分桶近似(A248) / W 低频严苛->滑动日志 / R+B->令牌桶 / 全要->串联 AND ✅")
```

**追问**：1) 审计器为什么必须用放行时刻、用单调钟？—— 合同约束的对象是「放行」，被拒的请求不占配额、也不构成违约；拿请求时刻审计会把「限流器正常工作」误判成「限流器违约」，这是压测报告里最常见的假违规。时钟侧与 A248 同一条铁律：本地判定用 `time.monotonic`（墙钟会被 NTP 回拨打断，回拨一秒窗口判定整体错乱），分布式统一用服务端时间。2) 令牌桶违反 W 条款的量到底能到多大，能不能让它合规？—— 上界 = `capacity + r·W`（窗口起点桶是满的 + 窗口内补出的币全部打完）。要它严格窗口合规有两条路：a) **capacity → 0 的极限**即漏桶语义（恒速平滑，突发能力归零，B 条款牺牲）；b) 外面再套一层滑动日志管 W、里面令牌桶管 R+B 的**串联组合器**——两级判定取 AND，状态内存相加，合同每多一条款就多一层状态，这是「条款越多、状态越贵」的直接映射。3) 内存账再往多租户推一步会怎样？—— 滑动日志的账是「每租户 × L × 32B」：1 万租户 × 1000 配额就是 300MB+ 常驻，这正是 Q6050 的键基数爆炸在单机内存上的形态；生产上多租户几乎必然降档到 O(1) 状态（固定窗口/令牌桶/分桶近似），把「精确总量」降级成「承诺 L·(1+1/K) 的近似总量」写进合同——**内存付不起的时候，精度是用合同措辞买回来的**。另一个方向是把状态外移到 Redis（A101/A239），但那只是把内存账换成了 RTT 账，每请求一次网络往返在高 QPS 下比 300MB 更贵，两者要放进同一张表里比。

## 背诵要点
1. 合同三条款 W/R/B 与三算法合规矩阵：固定窗口 W 必违（边界 2L）、滑动日志 W 合规但无突发整形、令牌桶 B/R 合规但 W 可违（上界 cap+r·W，远小于固定窗口的无界 2L）。
2. 滑动日志内存 O(L)（实测千条额度 ≈ 3.3 万字节），固定窗口/令牌桶 O(1) 百字节级——多租户高频接口只能 O(1) 状态，精度用合同措辞买。
3. 审计用放行时刻 + monotonic 钟；合同是总量选日志型，是速率+突发选令牌桶，两者都要就两级串联取 AND。
