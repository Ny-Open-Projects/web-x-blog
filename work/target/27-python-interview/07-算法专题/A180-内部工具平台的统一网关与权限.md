### A180 · 内部工具平台

> 难度:★★☆ | 标签:内部平台, 权限, 场景题

**问**（笔试·场景题）：公司有 15 个内部小工具（查订单/改配置/跑脚本/看日志），各自做了登录和权限——为什么「每个工具自己管权限」必然出事故（权限不一致/离职未回收/无审计），统一网关的收敛方案（SSO + 网关代理 + 工具零信任改造），「危险工具」（改生产数据）在统一平台上的额外管控是什么？

**答**：① 自管权限的三宗罪：**不一致**（工具 A 用 LDAP 组、工具 B 用硬编码白名单——权限语义漂移）、**回收漏洞**（离职员工在某工具的白名单里没人记得删——僵尸账号）、**无审计**（谁改了什么数据无从查起——15 个工具 15 种日志格式）。② 统一方案三层：**SSO**（单点登录，权限判定集中一处——RBAC，Q111 复用）；**网关代理**（工具只允许从网关访问（网络层封死直连），网关注入身份头 `X-User`——工具代码里的登录逻辑全删）；**审计统一**（网关层记录 谁在何时访问了哪个工具+参数——一套日志格式）。③ 危险工具额外管控：改生产数据类工具 → 二次确认（输入影响行数预估）+ 四眼原则（另一人审批）+ 全量审计（A112 哈希链）——危险操作的门槛与操作价值成正比。

```python
# 全部标准库；demo 实现「统一网关代理 + 危险工具四眼审批」
import time

SSO_ROLES = {"alice": "admin", "bob": "ops", "carol": "viewer"}
TOOL_ACL = {"config_editor": {"admin"}, "log_viewer": {"admin", "ops", "viewer"},
            "data_mutator": {"admin"}}

class Gateway:
    def __init__(self):
        self.audit: list[dict] = []
        self.pending_approval: dict[str, tuple] = {}
    def access(self, user: str, tool: str, params: dict) -> tuple[int, object]:
        role = SSO_ROLES.get(user)
        if not role:
            return 401, "未认证"
        allowed = TOOL_ACL.get(tool, set())
        if role not in allowed:
            self.audit.append({"ts": time.time(), "user": user, "tool": tool,
                               "verdict": "denied"})
            return 403, "角色无权限"
        if tool == "data_mutator":
            # 危险工具：四眼原则——同人不批自己的申请
            if tool in self.pending_approval:
                approver, req_user, p = self.pending_approval[tool]
                if approver == req_user:
                    return 403, "四眼原则：审批人不能是申请人"
                del self.pending_approval[tool]
                self.audit.append({"ts": time.time(), "user": user, "tool": tool,
                                   "approved_by": approver, "params": params,
                                   "verdict": "executed"})
                return 200, f"executed with {params}"
            self.pending_approval[tool] = (user, user, params)
            return 202, "已提交，等待第二人审批"
        self.audit.append({"ts": time.time(), "user": user, "tool": tool,
                           "verdict": "ok"})
        return 200, f"tool-data({tool})"

if __name__ == "__main__":
    gw = Gateway()
    s, r = gw.access("carol", "log_viewer", {})
    assert s == 200
    s, r = gw.access("bob", "config_editor", {})
    assert s == 403                                       # 角色拦截 ✅
    s, r = gw.access("alice", "data_mutator", {"sql": "UPDATE ..."})
    assert s == 202                                       # 提交待审 ✅
    s, r = gw.access("alice", "data_mutator", {"sql": "UPDATE ..."})
    assert s == 403 and "四眼" in str(r)                  # 同人自批拦截 ✅
    s, r = gw.access("bob", "data_mutator", {"sql": "UPDATE ..."})
    assert s == 200                                       # 第二人审批通过 ✅
    denied = [a for a in gw.audit if a["verdict"] == "denied"]
    assert denied and denied[0]["user"] == "bob"
    print("统一网关：SSO 角色拦截 + 四眼审批 + 全量审计（含 denied）✅")
    print("审计样例:", gw.audit[-1])
    # 口径：权限判定集中一处（SSO+RBAC）、网络层封死直连、审计统一格式；
    # 危险工具四眼原则 + 同人自批拦截。
```

**追问**：1) 为什么「网络层封死直连」比「应用层检查来源」可靠？——应用层检查可以被绕过（直连工具端口、伪造 header）；网络层（防火墙/安全组只放行网关 IP）是物理约束——权限要在「绕不过去」的层强制，Q7516 同构。2) 四眼原则的「同人自批」拦截为什么必须显式做？（提示：审批人列表小时第二人可能就是申请人自己（单人值班）——不拦截等于四眼形同虚设；单人值守期应挂起申请到有人上线，而非降级自批）3) 15 个工具迁到统一网关的迁移顺序？（提示：先迁高危险工具（收益最大：审计+审批）→ 高频工具（统一体验）→ 长尾工具；每迁一个删一份自管权限代码——权限收敛与下线审查（Q137）同构）

## 背诵要点
1. 自管权限三宗罪：语义不一致/回收漏洞（僵尸账号）/无审计——统一 SSO+RBAC 判定集中一处。
2. 统一三层：SSO 单点 + 网关代理（网络层封死直连，身份头注入）+ 审计统一格式（含 denied）。
3. 危险工具：四眼原则 + 同人自批拦截 + 全量审计（哈希链，A112）；危险度与门槛成正比。

## 复盘追问
1. 网关成了单点（网关挂了所有工具不可用），怎么权衡？（提示：内部工具可接受短暂不可用（fail-close 保安全），网关本身高可用部署；绝不「网关挂了放行直连」——可用性让位于安全是内部工具的合理取舍）
2. 离职员工僵尸账号怎么系统性发现？（提示：SSO 账号与 HR 系统对账（离职即禁用）+ 定期审计「90 天未登录但仍有权限」的账号清单——回收自动化比人记可靠）
