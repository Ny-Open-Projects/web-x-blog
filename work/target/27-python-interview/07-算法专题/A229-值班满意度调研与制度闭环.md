### A229 · 值班满意度调研

> 难度:★★☆ | 标签:值班, 调研, 治理

**问**（笔试·场景题）：值班制度的最终检验是「值班者的感受」——满意度调研怎么设计（维度：告警负担/手册质量/工具好用度/升级体验/补偿公平——分维度而非笼统打分），调研的匿名性与「反馈可行动」的平衡（匿名了怎么跟进具体问题），调研结果的「行动转化」（调研完要有改进项落地——Q186 跟进机制），「调研疲劳」（每季度调研没人认真填）怎么防？

**答**：① 调研维度五项（分维度而非总分）：告警负担（次数/夜间分布——Q221 客观数据交叉验证）、手册质量（按手册能独立处置吗——Q142 粒度）、工具好用度（一键处置覆盖率 Q214）、升级体验（升级及时性/专家响应 Q172）、补偿公平（调休落实/负担分摊 Q221）——分维度才能定位「哪里不满」，总分只能知道「不满」。② 匿名与可行动平衡：**匿名 + 分组归因**（匿名填写，但按「服务域/角色」分组统计——不暴露个人但定位「哪个域的痛点」，分组粒度 ≥5 人防去匿名化）；可行动性：维度题的开放反馈按「主题聚类」输出改进项候选（进 Q186 跟进器）。③ 调研疲劳防治：**调研频率季度一次**（不高频）+ **每轮调研必出行动项**（调研→改进→下轮验证「上轮痛点是否缓解」——参与者的反馈被看见才愿意继续填）+ 调研时长 ≤10 分钟（15 题内）。④ 闭环验证：本轮调研的痛点项 → 行动项 → 下轮调研对应维度分数对比——「痛点维度分数变化」是改进有效性的直接验证。

```python
# 全部标准库；demo 实现「满意度调研与行动转化」
import statistics

DIMENSIONS = ["告警负担", "手册质量", "工具好用度", "升级体验", "补偿公平"]

def analyze_survey(responses: list[dict]) -> dict:
    """分组维度统计：按服务域分组，组内人数 ≥5 防去匿名化。"""
    by_group = {}
    for r in responses:
        by_group.setdefault(r["group"], []).append(r)
    out = {}
    for group, rs in by_group.items():
        if len(rs) < 5:
            out[group] = "样本不足（<5），合并到相邻组防去匿名化"
            continue
        out[group] = {dim: round(statistics.mean(r[dim] for r in rs), 1)
                      for dim in DIMENSIONS}
    worst_dim = {}
    for group, dims in out.items():
        if isinstance(dims, dict):
            worst_dim[group] = min(dims, key=dims.get)   # 每组最痛维度
    return {"groups": out, "worst": worst_dim}

def action_conversion(analysis: dict) -> list[dict]:
    """调研 → 行动项（Q186 跟进器输入）。"""
    actions = []
    for group, worst in analysis["worst"].items():
        actions.append({"title": f"{group} 域「{worst}」改进", "source": "survey",
                        "verify": f"下轮调研 {worst} 维度分数"})
    return actions

if __name__ == "__main__":
    responses = [
        {"group": "pay-domain", **{d: v for d, v in zip(DIMENSIONS, [3, 2, 4, 5, 3])}},
        {"group": "pay-domain", **{d: v for d, v in zip(DIMENSIONS, [3, 2, 4, 4, 3])}},
        {"group": "pay-domain", **{d: v for d, v in zip(DIMENSIONS, [2, 3, 4, 5, 4])}},
        {"group": "pay-domain", **{d: v for d, v in zip(DIMENSIONS, [3, 2, 4, 4, 3])}},
        {"group": "pay-domain", **{d: v for d, v in zip(DIMENSIONS, [4, 2, 4, 5, 3])}},
    ]
    a = analyze_survey(responses)
    print("分组分析:", a["groups"])
    print("最痛维度:", a["worst"])
    assert a["worst"]["pay-domain"] == "手册质量"
    acts = action_conversion(a)
    print("行动项:", acts)
    assert acts[0]["verify"].endswith("手册质量 维度分数")   # 闭环验证 ✅
    # 口径：五维度分项调研+分组归因（≥5 人防去匿名化）；每轮调研必出行动项；
    # 下轮同维度分数对比=改进有效性验证。
```

**追问**：1) 为什么调研「分维度」而不是总分？——总分 3.5 无法行动（不知道哪差）；分维度（手册 2 分是痛点）直接定位改进方向——调研的价值在「可行动性」，维度化是可行动的前提（A186 行动项需要明确目标）。2) 「匿名+分组归因」的 ≥5 人下限为什么重要？（提示：分组人数 <5 时，结合其他信息可反推个人（5 人的组里打 1 分的是谁较明显）——去匿名化=下一轮没人说真话——统计的匿名保护要工程化（分组下限）而非口头承诺）3) 调研 → 行动 → 下轮验证的「闭环」如果行动项做了但分数没变？（提示：行动项效果验证失败回炉（A144 同构）+ 检视「痛点根因是否判断对」（手册质量低的根因可能是「系统太复杂」而非「手册写得差」——行动项解决的是表象，根因另寻）——闭环失败也是信息）

## 背诵要点
1. 调研五维度分项：告警负担/手册质量/工具好用度/升级体验/补偿公平——分维度才能定位痛点。
2. 匿名与可行动的平衡：匿名填写 + 分组归因（组内 ≥5 人防去匿名化）+ 主题聚类输出行动项。
3. 闭环三步：调研 → 行动项（Q186）→ 下轮同维度分数对比验证——每轮必出行动项防调研疲劳。

## 复盘追问
1. 满意度调研连续两季「手册质量」最低分，行动项也做了但没改善——深层原因可能是什么？（提示：手册质量问题可能是「系统太复杂导致手册写不清楚」的结构性问题——行动项应升级（系统简化/服务合并）而非继续补手册；同一维度连续两轮垫底=根因在更深层的信号）
2. 值班满意度、值班负担、值班能力三个治理体系（Q221/Q190/Q229）数据互相矛盾（满意度高但负担数据显示超标），信谁？（提示：满意度是主观感知（有滞后与适应偏差），负担数据是客观记录——矛盾本身是信号（「适应了高强度」= 客观超标但主观钝化，是 burnout 前兆）——客观数据优先作为硬约束，主观调研作为趋势预警）
