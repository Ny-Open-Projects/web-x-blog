### A205 · 服务健康度评分

> 难度:★★☆ | 标签:健康分, 可观测性, 治理

**问**（笔试·编程+场景题）：「这个服务健康吗」要回答 6 个维度（错误率/延迟/饱和度/新鲜度/依赖健康/变更风险）——健康分怎么加权合成（维度权重与打分函数），「一票否决」维度（错误率爆表时其他分再高也是不健康），健康分的「降噪」怎么避免分数抖动误导（滑动窗口与滞后），健康分的消费者是谁（值班/容量规划/架构治理各看什么）？

**答**：① 加权合成：每维度归一到 [0,100]（错误率：对 SLO 的燃烧率映射；延迟：P99 与目标的比；饱和度：核心资源峰值占比），加权求和——权重按业务分级（T0 服务错误率权重更高）。② 一票否决：**关键维度超硬线直接判不健康**（错误率 >5% 或可用性 <99%——无论加权分多高），加权分适合「排名」不适合「底线」——底线+加权双层结构。③ 降噪：分数用**滑动窗口**（5 分钟窗口均值而非瞬时值）+ **滞后切换**（健康→不健康需连续 2 个窗口低于阈值，防抖动来回横跳——A110 迟滞同构）。④ 消费者分视角：值班看「当前态+变化趋势」（谁在劣化）、容量规划看「饱和度维度」（扩容信号）、架构治理看「长期低分名单」（欠债服务，Q140 债务台账联动）——一个分数多个消费者，展示要按角色分层。

```python
# 全部标准库；demo 实现「健康分合成 + 一票否决 + 迟滞降噪」
from collections import deque

WEIGHTS = {"error": 0.3, "latency": 0.25, "saturation": 0.2,
           "freshness": 0.15, "dependency": 0.1}
VETO = {"error": 40}                       # 错误维度 <40 直接不健康（一票否决）

class HealthScore:
    def __init__(self, window: int = 5, hysteresis: int = 2):
        self.window = deque(maxlen=window)
        self.hyst, self.bad_streak = hysteresis, 0
        self.state = "healthy"
    def score(self, dims: dict[str, float]) -> int:
        """加权合成（各维度已归一 0-100）。"""
        if dims["error"] < VETO["error"]:
            return min(10, int(dims["error"]))          # 一票否决：底线压分
        return int(sum(dims[k] * WEIGHTS[k] for k in WEIGHTS))
    def update_state(self, dims: dict) -> str:
        s = self.score(dims)
        self.window.append(s)
        avg = sum(self.window) / len(self.window)
        if avg < 60:
            self.bad_streak += 1
            if self.bad_streak >= self.hyst:            # 连续 2 窗口才切不健康
                self.state = "unhealthy"
                self.bad_streak = 0
        else:
            self.bad_streak = 0
            self.state = "healthy"
        return self.state

if __name__ == "__main__":
    h = HealthScore()
    dims = {"error": 95, "latency": 90, "saturation": 60, "freshness": 100, "dependency": 100}
    s = h.score(dims)
    assert h.score({"error": 30, "latency": 95, "saturation": 90,
                    "freshness": 100, "dependency": 100}) <= 10   # 一票否决 ✅
    print("健康分（正常）:", s, "| 一票否决（错误率爆表）:", "<=10")
    # 迟滞降噪：在 60 分界上下抖动的输入不会来回横跳
    flapping = [{"error": 95, "latency": 90, "saturation": 60, "freshness": 100,
                 "dependency": 100} if i % 2 else
                {"error": 55, "latency": 55, "saturation": 55, "freshness": 55,
                 "dependency": 55} for i in range(8)]
    states = [h.update_state(d) for d in flapping]
    print("抖动输入下的状态切换次数:", states.count("unhealthy") - states[:-1].count("unhealthy"),
          "（迟滞抑制横跳）")
    # 消费者口径：值班看趋势、容量看饱和度、治理看低分名单——一个分数多视角展示。
```

**追问**：1) 为什么「底线+加权」双层而非纯加权？——加权合成的悲剧：错误率 20% 但其他维度 100 分，加权分 80「看起来还行」——底线层保证关键维度失守时评分体系不可能说谎；排名用加权、判死用底线——两层各司其职。2) 维度归一的基准怎么定？（提示：各维度以自己的 SLO/目标为 100 分锚（错误率 0 燃烧=100、P99=目标=100），超出目标线性扣——归一基准就是 SLO，健康分天然与 SLO 体系（Q7008）对齐）3) 健康分「低分名单」进架构治理后怎么用？（提示：与债务台账（Q140）/技术栈老化（Q6026）联动——长期低分服务是重构/下线（Q137）的候选清单，评分体系成为治理的输入而非摆设）

## 背诵要点
1. 加权合成五维（错误/延迟/饱和/新鲜/依赖），权重按业务分级；归一锚点=各维度 SLO。
2. 一票否决底线层（错误率爆表直接判死）——排名用加权、判死用底线，双层各司其职。
3. 降噪 = 滑动窗口 + 迟滞切换（连续 2 窗口才换状态，防横跳）；消费者分角色看不同维度。

## 复盘追问
1. 健康分 90 分的服务出了 P0 事故，评分体系哪里失效了？（提示：看「哪个维度没测到」（依赖的依赖？业务逻辑正确性？）——健康分维度要随事故教训进化（每次复盘检视「这个事故健康分能预警吗」）——评分体系自身也要复盘）
2. 所有服务都 85 分以上（分数通胀），健康分还有区分度吗？（提示：通胀=归一基准过松或权重失真——用相对排名（同层服务对比）+ 基准收紧（随 SLO 提高而提高）对抗通胀；分数的价值在区分度不在绝对值）
