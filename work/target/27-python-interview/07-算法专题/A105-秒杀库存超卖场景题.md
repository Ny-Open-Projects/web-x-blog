### A105 · 秒杀库存超卖场景题

> 难度:★★★ | 标签:库存, 超卖, Lua, 场景题

**问**（笔试·场景题）：1000 件库存，10 万人同时抢。设计不超卖的扣减链路：请求进来后每层做什么、扣减动作发生在哪一层、DB 最终一致性怎么保证？写 Redis Lua 扣减 + DB 落单的核心代码。

**答**：三层漏斗，**扣减越靠前越好**：① 挡量层（网关/限流/答题打散），把 10 万削到几千；② **Redis 原子预扣**：库存放 Redis，Lua 脚本「查-扣-记人」单命令原子，扣完即返成功——超卖在这层就被物理杜绝（Redis 单线程串行执行脚本）；③ 异步落库：预扣成功发消息，消费者 DB 建**订单表唯一键(user_id, activity_id) + `UPDATE stock SET n=n-1 WHERE n>0`** 双兜底，Redis 与 DB 间用对账补偿（预扣成功但落库失败 → 回补 Redis 并退款）。任何一环挂掉都不超卖，只可能少卖（可接受）。

```python
# Redis 侧：原子扣减（production 用 redis-py eval；此处演示脚本语义）
SECKILL_LUA = """
local stock = tonumber(redis.call('GET', KEYS[1]) or '0')
local uid = ARGV[1]
if redis.call('SISMEMBER', KEYS[2], uid) == 1 then return -1 end  -- 重复抢
if stock <= 0 then return 0 end                                    -- 售罄
redis.call('DECR', KEYS[1])
redis.call('SADD', KEYS[2], uid)                                   -- 一人一件
redis.call('RPUSH', KEYS[3], uid)                                  -- 成功队列，供落库消费
return 1
"""
# KEYS[1]=stock:act1  KEYS[2]=buyer:act1  KEYS[3]=queue:act1

def consume_to_db(queue_key, stock_key):
    """落库消费者：逐个 uid 建订单；失败回补 Redis（少卖不超卖原则）。"""
    import redis, pymysql, json
    r = redis.Redis()
    conn = pymysql.connect(**json.load(open("db.json")))
    while True:
        _, uid = r.blpop(queue_key, timeout=5)
        try:
            with conn.cursor() as c:
                # 唯一键 + 条件扣减双兜底：WHERE n>0 是最后一道防超卖闸
                n = c.execute(
                    "UPDATE stock SET n=n-1 WHERE act=%s AND n>0", ("act1",))
                if n == 0:
                    raise RuntimeError("db stock empty")
                c.execute(
                    "INSERT INTO orders(user_id, act) VALUES (%s, 'act1')", (uid.decode(),))
            conn.commit()
        except Exception:
            conn.rollback()
            r.incr(stock_key)          # 回补：Redis 多扣的要补回
            r.srem("buyer:act1", uid)  # 允许用户重试

if __name__ == "__main__":
    # 缺库降级：无 redis/pymysql 时重点掌握脚本语义与回补逻辑
    import math
    seq = [1, 1, 0, -1]                       # 模拟脚本对 [买家A, 重复A, 售罄后买家B, ...] 的返回
    assert seq.count(1) == 2 and -1 in seq and 0 in seq
    print("脚本语义: 1=扣成功 -1=重复 0=售罄; 回补=incr+srem")
```

**追问**：1) 为什么不用 DB 行锁直接扛？——`UPDATE ... WHERE n>0` 虽然不超卖，但 10 万并发全压到一行 hot row，InnoDB 行锁排队 TPS 上千就顶死，Redis 预扣把热点移到内存层。2) Redis 扣成功但用户 15 分钟不支付怎么办？——预扣绑定「占位单」，超时未支付走延迟队列回补库存+`SREM`；不要在 Lua 里做过期逻辑。3) 多个 Redis 实例分片库存怎么聚合？——按 uid 哈希分桶到 N 个库存分片，总分库存 = Σ分片，售罄广播给网关层提前拦截。

## 背诵要点
1. 三层漏斗：挡量 → Redis Lua 原子预扣（查-扣-记人单脚本）→ 异步落库，热点不过 DB。
2. 防超卖双兜底：Redis 单线程脚本物理杜绝 + DB `UPDATE ... WHERE n>0` 行级条件兜底。
3. 失败方向单向：落库失败回补 Redis（少卖可接受），绝不做「先落库再扣 Redis」。
