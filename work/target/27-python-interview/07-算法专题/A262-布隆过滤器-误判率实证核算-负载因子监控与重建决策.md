### A262 · 布隆过滤器的误判率实证核算

> 难度:★★★★ | 标签:布隆过滤器, 误判率, 双哈希, 负载因子, 容量重建

**问**（笔试·编程题）：Q977 已经算过「1 亿条、1% 误判要 114MB、k=7」的账，Q976 手写过实现——但面试官会往下追问一层：**这些公式你怎么证明它真的成立**？请实现一个布隆过滤器并完成实证核算，要求：① 位阵列用 `bytearray` 位寻址，k 个位址由**一次哈希派生**（不许对同一元素做 k 次独立哈希，也不许用 Python 内建 `hash()`——它有进程级随机盐）；② **实测误判率**并与理论公式 `(1-e^{-kn/m})^k` 对照，误差要在可解释范围内；③ 提供运行时监控：置位率（负载因子）、理论误判率的实时投影，以及「**此刻必须重建**」的判定——容量是按预估给的，数据超装才是常态，面试官要的是你能在误判飙升**之前**报警；④ 用实测曲线回答「k 是不是越多越好」；⑤ 用同一个过滤器故意 3 倍超装，演示误判率怎么崩、重建后怎么恢复。请说清与 Q976/Q977（公式与手写）、Q1219（布谷鸟：可删除）、Q1954（空值缓存与布隆的纵深分工）、Q1243（缓存穿透场景）的分工——本题只回答「**公式如何被代码实证、容量如何在线决策**」。

**答**：① 分工：Q977 是**纸面算账**（代入公式出内存与 k），Q976 是**结构与手写**，Q1219 回答「要删除怎么办」，Q1954/Q1243 是**业务场景里的位置**（布隆挡穿透、空值缓存兜误判）。本题补的是工程闭环：公式给的是「设计时」的承诺，运行时数据量会漂——**误判率不是常量而是随 count 漂移的函数**，必须有人在运行时盯着它。② 双哈希派生（Kirsch–Mitzenmacher）：`h_i = (h1 + i·h2) mod m`，一次 128 位 blake2b 拆成两个 64 位整数即可生成全部 k 个位址，k 次哈希的 CPU 降到一次；定理保证其误判率不超过独立哈希的 2 倍，实测中与理论曲线几乎重合。注意 `h2 | 1` 奇数化——步长为 0 时 k 个位址全重叠，等于只有 1 个哈希在干活。为什么不用内建 `hash()`：Python 对 str/bytes 默认开 `PYTHONHASHSEED` 随机化，进程重启后位阵列**整体失效**，持久化场景必踩。③ 实测对照的理论式：置位率 ≈ `1-e^{-kn/m}`，误判率 ≈ `(1-e^{-kn/m})^k`。代码里实测 1 万条、目标 1%：**理论投影回到 1% 附近**（这正是 m/k 公式的设计目标），实测与理论差值在千分之一量级；assert 用「实测与理论差值 < 0.01」而不是硬编码区间——因为实测值随哈希细节波动，**要验的是公式吻合度，不是某个具体数字**。④ k 的曲线：固定 m/n=9.59 位/元素，k 从 1 扫到 15，理论误判率在 k=7 处最低（`ln2·m/n`），再往上**每个多余的哈希都在把前面设置的位踩成误判**——k 不是越多越好，它有最优点，这正是「公式不是背出来的，是能被扫出来的」。⑤ 监控与重建决策：`set_bits/m` 是负载因子（免费拿到，add 时增量维护），`projected_fpr()` 用当前 count 算误判率投影。重建判据不用「count > capacity」——那是设计口径；运行时口径是「**投影误判率要跌破业务上限**」，容量超装 3 倍时投影从 0.8% 涨到 43%，实测同步崩到同量级（演示里能直接看到崩的过程），此时唯一补救是换 m 重建重灌（布隆不支持删除，缩不回去；要在线可删就换 Q1219 的布谷鸟）。重建是**有计划的停机窗口**：新尺寸按「当前 count × 增长系数」定，别再按上次的预估定——上次就是这么超装的。

```python
# 全部标准库；布隆过滤器：双哈希位阵 + 误判率实证核算 + 负载因子监控与重建决策
import hashlib
import math


class BloomFilter:
    def __init__(self, capacity, target_fpr=0.01):
        """按目标容量与误判率定尺寸：m = -n·lnP/(ln2)^2，k = (m/n)·ln2。"""
        if capacity <= 0:
            raise ValueError("capacity 必须为正")
        if not 0 < target_fpr < 1:
            raise ValueError("target_fpr 必须在 (0,1) 区间")
        n, p = capacity, target_fpr
        self.m = max(1, int(-n * math.log(p) / (math.log(2) ** 2)))
        self.k = max(1, round(self.m / n * math.log(2)))
        self.bits = bytearray((self.m + 7) // 8)   # 位阵列：bytearray + 位寻址
        self.count = 0                              # 已插入元素数（允许超装，监控就是为此）
        self.set_bits = 0                           # 已置 1 的位数（增量维护）

    def _addrs(self, item):
        """双哈希派生 k 个位址：h_i = (h1 + i·h2) mod m（Kirsch-Mitzenmacher）。"""
        h = hashlib.blake2b(item.encode("utf-8"), digest_size=16).digest()
        h1 = int.from_bytes(h[:8], "big")
        h2 = int.from_bytes(h[8:], "big") | 1       # 奇数化，防步长为 0 全重叠
        return ((h1 + i * h2) % self.m for i in range(self.k))

    def add(self, item):
        for a in self._addrs(item):
            byte, bit = divmod(a, 8)
            mask = 1 << bit
            if not self.bits[byte] & mask:
                self.bits[byte] |= mask
                self.set_bits += 1
        self.count += 1

    def __contains__(self, item):
        return all(self.bits[a // 8] & (1 << a % 8) for a in self._addrs(item))

    def load_factor(self):
        """置位率，运行时应 ≈ 1 - exp(-k·count/m)。"""
        return self.set_bits / self.m

    def projected_fpr(self):
        """误判率随 count 漂移的实时投影：(1 - exp(-k·count/m))^k。"""
        return (1.0 - math.exp(-self.k * self.count / self.m)) ** self.k

    def must_rebuild(self, max_fpr):
        """运行时重建判据：投影误判率越界就重建，不等误判真的飙升。"""
        return self.projected_fpr() > max_fpr


def theoretical_fpr(n, m, k):
    return (1.0 - math.exp(-k * n / m)) ** k


if __name__ == "__main__":
    # 1) 尺寸核算：1 万条、1% 误判 → 约 9.6 万位、k=7、内存约 12KB
    bf = BloomFilter(10000, 0.01)
    assert bf.k == 7, bf.k
    assert abs(theoretical_fpr(10000, bf.m, bf.k) - 0.01) < 0.001
    print("尺寸: n=10000, m=%d 位 (%.1f KB), k=%d；理论误判率 %.4f"
          % (bf.m, len(bf.bits) / 1024, bf.k, theoretical_fpr(10000, bf.m, bf.k)))

    # 2) 实测误判率对照公式：插入 1 万，探测 1 万个绝不在库内的元素
    for i in range(10000):
        bf.add("user:%d" % i)
    fp = sum(1 for i in range(10000) if "ghost:%d" % i in bf)
    measured, theo = fp / 10000, bf.projected_fpr()
    assert abs(measured - theo) < 0.01, (measured, theo)
    print("实证: 实测误判率 %.4f vs 理论 %.4f（吻合）✅" % (measured, theo))

    # 3) k 不是越多越好：固定 m/n，理论误判率先降后升，最优 k=7
    curve = {k: theoretical_fpr(10000, bf.m, k) for k in range(1, 16)}
    best_k = min(curve, key=curve.get)
    assert best_k == 7, best_k
    print("k 曲线: k=3→%.4f, k=7→%.4f(最优), k=15→%.4f——超过 7 误判率回升 ✅"
          % (curve[3], curve[7], curve[15]))

    # 4) 超装 3 倍：误判率崩掉、触发重建判据；按实际 count 重建后恢复
    bf2 = BloomFilter(10000, 0.01)
    for i in range(30000):
        bf2.add("user:%d" % i)
    fp2 = sum(1 for i in range(10000) if "ghost:%d" % i in bf2) / 10000
    assert bf2.must_rebuild(0.05), bf2.projected_fpr()
    print("超装 3 倍: 实测误判率 %.3f、投影 %.3f → must_rebuild(5%%)=True ✅"
          % (fp2, bf2.projected_fpr()))
    bf3 = BloomFilter(bf2.count * 2, 0.01)          # 重建尺寸按当前 count 定，不再按旧预估
    for i in range(30000):
        bf3.add("user:%d" % i)
    fp3 = sum(1 for i in range(10000) if "ghost:%d" % i in bf3) / 10000
    assert fp3 < 0.02 and not bf3.must_rebuild(0.05)
    print("重建恢复: 重建后实测 %.4f、投影 %.4f，回到目标量级 ✅" % (fp3, bf3.projected_fpr()))
```

**追问**：1) 双哈希派生和 k 个独立哈希，实测差多少？—— 各跑一遍对照：独立哈希要 k 次 blake2b，派生只算一次；两者实测误判率都在理论值 ±1 个标准差内（定理保证派生版不超过 2 倍，实测远好于此界）。真正要防的不是派生，是**哈希间相关性**——如果用 `h1+i·h2` 但 m 是偶数且 h2 也是偶数（忘了 `|1`），步长失效位址全同，误判率直接退化到 k=1 的水平。生产上选 m 为奇数或大质数也能再压一点相关性。2) 误判率的「误差方向」能选吗？—— 能，而且这是面试官真正想听的：布隆只会「**把没有说成有**」（假阳性），绝不「把有说成没有」（零假阴性）。所以它适合挡缓存穿透（误判多放几个请求回源，无害；漏放真实 key 打穿 DB，有害）而不适合做「白名单强校验」。这条原则与 A257 追问里 Count-Min sketch 的「只高估不低估」同构：**选结构先选误差方向，再谈误差大小**。3) 分布式下多个节点的布隆怎么保持一致？—— 三条路：a) 每节点全量同构（哈希是纯函数，写路径双写即可，内存换简单）；b) 中心位图（Redis bitmap + 位运算，网络往返成为瓶颈，且位级并发写要原子）；c) 不一致容忍 + 定期重建（布隆天生允许假阳性，跨节点短暂不一致通常可接受）。关键是**重建窗口的全局协调**：重建期间新旧过滤器并存（新写双写、读先查旧再查新），否则重建瞬间的查询会漏判——这和 A126 密钥轮换的双钥并行期是同一个模式。

## 背诵要点
1. m = -n·lnP/(ln2)²，k = (m/n)·ln2；1 亿条 1% 误判 ≈ 114MB、k=7；k 有最优点，多设反而升误判。
2. 双哈希派生 `h_i=(h1+i·h2) mod m`（h2 奇数化）一次哈希出 k 个位址；内建 `hash()` 有随机盐，持久化场景禁用。
3. 误判率是随 count 漂移的函数：监控 `set_bits/m` 与投影 `(1-e^{-kn/m})^k`，投影越界即重建；布隆零假阴性、只假阳性，选型先看误差方向。
