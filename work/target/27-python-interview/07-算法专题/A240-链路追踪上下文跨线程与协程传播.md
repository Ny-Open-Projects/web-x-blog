### A240 · 链路上下文跨线程/协程传播

> 难度:★★☆ | 标签:contextvars, trace_id, asyncio, 并发

**问**（笔试·编程题）：用 `contextvars.ContextVar` 存 trace_id，日志中间件在入口 `set()` 一次——并发请求会不会串（A 请求的日志挂上 B 的 trace_id）？具体要求：① 多个 asyncio 请求交错 `await` 时 trace_id 不串；② 把工作丢进 `threading.Thread` / `ThreadPoolExecutor` 时 trace_id 怎么带过去（裸线程会怎样）；③ 写并发测试证明「不串」（顺序执行测不出来）。与 A160 的跨服务透传划清边界。

**答**：① 与 A160 分工：A160 解决**跨服务** trace_id 经 header 透传与采样联动；A240 解决**进程内**上下文传播——trace_id 存在 ContextVar 里，跨协程/线程时不传播或被串改，日志就张冠李戴。② asyncio：`create_task` / `gather` 在**创建 Task 时复制当前 Context**，每个 Task 持独立副本，Task 内 `set()` 只影响自己——所以交错 `await` 不串（这是 ContextVar 相对 `threading.local` 的核心优势，`local` 在同一线程内多协程会串）。但子 Task 会继承「创建时」的值，故每个请求必须在入口重新 `set()`。③ threading：`threading.Thread` **不自动继承**父线程 Context（新线程拿空 Context），裸线程读到 default（丢失，不是串）——必须 `contextvars.copy_context().run(fn, ...)` 显式带过去；`ThreadPoolExecutor` 同理（submit 时包 `ctx.run`）；`asyncio.to_thread`（3.9+）/ `run_in_executor` 已自动传播，无需手动。④ 不串验证：两请求各设不同 trace_id，故意 `await sleep(0)` 制造交错，断言每条日志的 trace_id 等于本请求 id；线程侧用两个独立 `copy_context` 并发跑，断言各自只看自己的 id——**不串靠并发测试证明**。⑤ 陷阱：线程池里别复用同一个 Context（会串），每请求单独 copy；入口 `set` 后用 `token = var.set()` + `finally: var.reset(token)` 复位，防长连接/复用协程残留上一个请求的 trace_id。

```python
# 全部标准库；demo 实现「ContextVar 跨协程/线程传播 + 不串验证」
import asyncio
import contextvars
import threading
from concurrent.futures import ThreadPoolExecutor

trace_id: contextvars.ContextVar[str] = contextvars.ContextVar("trace_id", default="-")

def current() -> str:
    return trace_id.get()

def capture(sink: list) -> None:
    sink.append(current())

async def async_request(rid: str, sink: list) -> None:
    trace_id.set(rid)                # 本 Task 的上下文副本，set 只影响自己
    await asyncio.sleep(0)           # 让出事件循环，制造交错
    capture(sink)                    # 恢复后仍是自己的 trace_id

async def async_part() -> list:
    sink: list[str] = []
    await asyncio.gather(async_request("T1", sink), async_request("T2", sink))
    return sink

async def to_thread_part() -> str:
    trace_id.set("TO-THREAD")
    return await asyncio.to_thread(current)   # 3.9+ 自动传播 context

if __name__ == "__main__":
    # 1) asyncio：Task 创建时复制 context，交错 await 不串
    async_sink = asyncio.run(async_part())
    assert async_sink == ["T1", "T2"], async_sink
    print("asyncio 交错:", async_sink, "—— 各自 trace_id 不串 ✅")

    # 2) 裸线程：不继承 context → trace 丢失（不是串，是丢）
    bare: list[str] = []
    t = threading.Thread(target=capture, args=(bare,))
    t.start(); t.join()
    assert bare == ["-"], bare
    print("裸线程:", bare, "—— contextvars 不跨线程自动传播")

    # 3) copy_context().run 显式传播：两个请求各自带 context，并发不串
    trace_id.set("TH-A")
    ctx_a = contextvars.copy_context()
    trace_id.set("TH-B")
    ctx_b = contextvars.copy_context()
    sinks: tuple[list, list] = ([], [])
    threads = [threading.Thread(target=ctx.run, args=(capture, sinks[i]))
               for i, ctx in enumerate((ctx_a, ctx_b))]
    for th in threads: th.start()
    for th in threads: th.join()
    assert sinks[0] == ["TH-A"] and sinks[1] == ["TH-B"], sinks
    print("显式传播:", sinks[0], sinks[1], "—— 各自 trace_id 不串 ✅")

    # 4) 线程池：submit 时包一层 ctx.run；to_thread 则自动传播
    trace_id.set("POOL-X")
    pool_ctx = contextvars.copy_context()
    pool_sink: list[str] = []
    with ThreadPoolExecutor(max_workers=2) as ex:
        ex.submit(pool_ctx.run, capture, pool_sink).result()
    assert pool_sink == ["POOL-X"], pool_sink
    print("线程池:", pool_sink, "—— 包 ctx.run 后不丢 ✅")
    assert asyncio.run(to_thread_part()) == "TO-THREAD"
    print("asyncio.to_thread:", "自动传播 ✅")
```

**追问**：1) 为什么 `threading.local` 解决不了这个问题？——`local` 按线程隔离，但 asyncio 所有协程跑在同一线程，多个请求共用一份 `local` 必然串；且 `local` 不会从父线程继承到子线程——`ContextVar` 同时提供「协程级隔离」与「显式跨线程传播（`copy_context`）」，是异步栈的正确原语。2) 入口 `set()` 后为什么要 `reset(token)`？——协程/线程可能被池化复用，上一个请求设的 trace_id 会残留到下一个请求（串），`var.reset(token)` 在 `finally` 里恢复原值才能彻底隔离——`set` 不 `reset` 是 ContextVar 最常见的泄漏源。3) 如果忘了 `copy_context`，把同一个 Context 丢进线程池会怎样？——多个线程在**同一个 Context** 里 `set()` 互相覆盖，trace_id 串；每个请求必须单独 `copy_context()`，Context 不是线程安全的共享容器——「复制而非共享」是跨线程传播的铁律。

## 背诵要点
1. A240 管进程内传播（ContextVar），A160 管跨服务透传——一个在内存、一个在网络 header。
2. asyncio 的 Task 创建时复制 Context，Task 内 set 不串；threading.Thread/ThreadPoolExecutor 不自动继承，必须 `copy_context().run()`；to_thread/run_in_executor 3.9+ 自动传播。
3. 不串靠并发交错测试证明；每请求单独 copy Context，入口 set + finally reset(token) 防残留。

## 复盘追问
1. 日志中间件在异步框架里 set 了 trace_id，但部分日志还是空/串，最可能漏在哪？（提示：日志格式化发生在其它线程/线程池且没包 ctx.run；或某个协程里手动起了裸 threading.Thread——查所有「离开当前 Task」的边界是否都做了传播）
2. 用 ContextVar 存 trace_id 和直接把 trace_id 当参数层层传递，取舍？（提示：显式传参最可靠但侵入深（每个函数都要加参数）；ContextVar 零侵入但传播有边界（线程/回调要显式处理）——框架/中间件用 ContextVar，核心业务函数关键处仍可显式带 id 做双保险）
