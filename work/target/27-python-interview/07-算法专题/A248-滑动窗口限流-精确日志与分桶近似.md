### A248 · 滑窗限流的精确计数与近似计数

> 难度:★★★★ | 标签:限流, 滑动窗口, 近似计数, 误差分析

**问**（笔试·编程题）：同一份「每 N 秒最多 L 次」的配额，实现两套并做取舍分析：**A 精确日志**——窗口内每个请求的时间戳都留，判定零误差；**B 固定桶近似**——把窗口切成 K 个环形计数器，读时按「窗口起点所在桶」的时间占比加权还原。要求：① 时间必须可注入（能确定性测试，别用裸 `time.time()`）；② 线程安全；③ 给出近似计数的**误差上界推导**并用实验验证（均匀流量、集中流量两种分布）；④ 量化内存差异；⑤ 说明 Redis 上两种各自怎么落地、为什么分布式下近似误差会被放大。并回答：Q286 已经用 `deque` 写了滑动窗口、A239 写了令牌桶，本题的增量是什么？什么场景必须用日志型，什么场景分桶就够？

**答**：① 与已有卡的分工：Q286 给的是「日志型滑动窗口」的正确性（`deque` + `popleft` 清理），A239 给的是令牌桶（平滑速率），A101 的「限流四连」把滑动窗口作为四分之一、用一句话交代「精确但内存 O(窗口内请求数)」。本题只做一件事：**同一份配额下精确与近似的定量对比**——误差到底多大、在什么流量分布下退化、内存差几个数量级，以及一个常被忽略的结论：**近似计数在最坏情况下会退化成固定窗口**。② 精确日志：`deque` 存单调时间戳，判定前先 `popleft` 掉窗口外的；每条请求摊销 O(1)，内存 O(L)（L 是配额），CPython 下每个 `float` 对象约 24 字节 + 指针 8 字节，10 万配额的租户就是 ~3MB，多租户直接爆炸。③ 分桶近似：K 个槽，每个槽记录「属于哪个时间桶」和计数；读时把「窗口起点所在的那个桶」按剩余占比折算，其余整桶全额计入。误差来源只有一个假设：**桶内请求均匀到达**。推导：设最老桶剩余占比为 f，桶内实际 c 条，估计值取 c·f；若这 c 条全部集中在桶的末端（离 now 最近，全都还在窗口内），真实值仍是 c，于是估计少算 c(1−f)，最大少算一整桶——**误差上界 = 单桶流量 ≈ L/K，最坏可达 L**（当 f→0 且流量集中在桶末）。这四个字的后果是：近似计数可能放过多达一倍的流量，和固定窗口一样。④ 实测（L=10, N=1s）：固定窗口在 0.99s 与 1.01s 各放 10 条，0.02 秒内 20 条；精确日志同轨迹只放 10 条；分桶 K=10 在均匀流量下最大误差 0.50 条（=L/K），在「10 条全挤在桶末」的集中流量下估计值只有 1.0（真实 10），又放进 10 条，合计 20——**退化成固定窗口**。随机流量下 K=2/4/10/20 的最大误差是 5.58/4.98/3.68/3.08 条，符合「K 越大越准，但收益递减」，且每次读要扫 K 个桶，成本 O(K)。⑤ 内存：日志型峰值 = L 个时间戳；分桶型固定 K 个整数。L=1000 时前者约 32KB/租户，后者不到 1KB，差两个数量级——多租户 SaaS 的限流几乎只能用分桶（或 Redis 计数）。⑥ 分布式落地：精确型用 Redis ZSET（`ZADD` + `ZREMRANGEBYSCORE` + `ZCARD`），三个命令必须在 Lua 里原子执行，否则「先查后写」的竞态会让超卖；内存同样 O(L)，10 万配额的 key 会很重。近似型用「K 个计数器 key + `INCR` + `EXPIRE`」，读时 `MGET` 加权求和，内存 O(K)。分布式下误差被放大有两条路：一是多实例各自读到的桶值有时间差（读写不在同一毫秒），二是客户端时钟与服务端时钟漂移（必须用 Redis `TIME` 而不是应用机时间，Q1521）。⑦ 选型：要「绝对不超卖」——计费、配额、风控、对外 SLA，用日志型或令牌桶；要「挡住大部分突发、成本可控」——内部服务保护、多租户粗粒度配额，用分桶，并把 K 取到误差可接受（K=10 即 ±10%）。⑧ 必须点破的一点：窗口型限流器**防的是总量，不是瞬时速率**。日志型允许 10 条在 1 毫秒内打完，下游照样被打穿；要平滑速率得用令牌桶/漏桶（A239）或并发信号量。三者不是替代关系，是三个不同的问题。⑨ 浮点坑：加权求和是浮点，比较必须留 epsilon（本 demo 的 `- 1e-9`），否则 9.999999999 与 10 的边界会随机放行一条——在限流这种「差一条就是事故」的地方，浮点比较要当成 bug 处理。

```python
# 全部标准库；时间可注入；精确日志 vs 分桶近似，误差用实验验证
import collections
import threading
import time


class Clock:
    def __init__(self, t=0.0):
        self.t = t

    def __call__(self):
        return self.t

    def advance(self, dt):
        self.t += dt


class FixedWindow:
    """最省内存，但窗口交界处可放过 2 倍流量。"""

    def __init__(self, limit, window, clock):
        self.limit, self.window, self.clock = limit, window, clock
        self._idx = None
        self._cnt = 0

    def allow(self):
        idx = int(self.clock() // self.window)
        if idx != self._idx:
            self._idx, self._cnt = idx, 0
        if self._cnt < self.limit:
            self._cnt += 1
            return True
        return False


class LogWindow:
    """精确：存窗口内每个请求的时间戳，O(limit) 内存，零误差。"""

    def __init__(self, limit, window, clock):
        self.limit, self.window, self.clock = limit, window, clock
        self._hits = collections.deque()
        self._lock = threading.Lock()
        self.peak_len = 0

    def allow(self):
        now = self.clock()
        cutoff = now - self.window
        with self._lock:
            while self._hits and self._hits[0] <= cutoff:
                self._hits.popleft()
            if len(self._hits) < self.limit:
                self._hits.append(now)
                self.peak_len = max(self.peak_len, len(self._hits))
                return True
            return False

    def count(self):
        now = self.clock()
        return sum(1 for t in self._hits if t > now - self.window)


class BucketWindow:
    """近似：K 个环形计数器，按「窗口起点所在桶」的时间占比加权还原。"""

    def __init__(self, limit, window, buckets, clock):
        self.limit, self.window, self.clock = limit, window, clock
        self.k = buckets
        self.bs = window / buckets
        self._cnt = [0] * buckets
        self._tag = [None] * buckets        # 槽位当前属于第几个时间桶

    def _slot(self, idx):
        return idx % self.k

    def estimate(self):
        now = self.clock()
        idx = int(now // self.bs)
        elapsed = now - idx * self.bs
        total = 0.0
        for i in range(idx - self.k, idx + 1):
            slot = self._slot(i)
            if self._tag[slot] != i:
                continue
            if i == idx - self.k:           # 窗口起点落在最老那个桶里，按占比折算
                frac = (self.bs - elapsed) / self.bs
                total += self._cnt[slot] * max(0.0, min(1.0, frac))
            else:
                total += self._cnt[slot]
        return total

    def allow(self):
        idx = int(self.clock() // self.bs)
        slot = self._slot(idx)
        if self._tag[slot] != idx:
            self._tag[slot], self._cnt[slot] = idx, 0
        if self.estimate() < self.limit - 1e-9:   # 加权求和是浮点，比较要留 epsilon
            self._cnt[slot] += 1
            return True
        return False


if __name__ == "__main__":
    # 1) 固定窗口的经典缺陷：0.99s 与 1.01s 各放 limit 个
    c = Clock()
    fw = FixedWindow(10, 1.0, c)
    c.t = 0.99
    first = sum(fw.allow() for _ in range(10))
    c.t = 1.01
    second = sum(fw.allow() for _ in range(10))
    assert first == 10 and second == 10
    print("固定窗口: 0.99s 通过 %d，1.01s 又通过 %d -> 0.02s 内 %d 个（2 倍突发）❌"
          % (first, second, first + second))

    # 2) 精确日志：同一轨迹只放 10 个
    c2 = Clock()
    log = LogWindow(10, 1.0, c2)
    c2.t = 0.99
    a = sum(log.allow() for _ in range(10))
    c2.t = 1.01
    b = sum(log.allow() for _ in range(10))
    assert a == 10 and b == 0
    print("精确日志: 同样轨迹通过 %d + %d = 10，零越界 ✅" % (a, b))

    # 3) 均匀流量下，分桶估计误差 <= 1 个桶 = limit/K
    c3 = Clock()
    bw = BucketWindow(10, 1.0, 10, c3)   # K=10，桶宽 0.1s
    real = LogWindow(10, 1.0, c3)
    for i in range(10):                   # 每桶恰好 1 条，均匀铺满 1s
        c3.t = 0.05 + i * 0.1
        assert bw.allow() and real.allow()
    worst = 0.0
    for step in range(100):               # 在下一秒内逐 0.01s 对比估计值与真实值
        c3.t = 1.0 + step * 0.01
        worst = max(worst, abs(bw.estimate() - real.count()))
    assert worst <= 1.0 + 1e-9, worst
    print("分桶 K=10 均匀流量: 最大估计误差 %.2f 条 = limit/K ✅" % worst)

    # 4) 流量集中在桶末：均匀假设被打破，误差逼近整个桶的量
    c4 = Clock()
    bw2 = BucketWindow(10, 1.0, 10, c4)
    c4.t = 0.099                           # 10 条全挤在桶 0 的末尾
    for _ in range(10):
        bw2.allow()
    c4.t = 1.09                            # 窗口 [0.09,1.09] 真实还剩 10 条
    est = bw2.estimate()
    extra = sum(bw2.allow() for _ in range(10))
    assert abs(est - 1.0) < 1e-9, est
    assert extra == 10
    print("分桶 K=10 集中流量: 估计 %.1f（真实 10），又放 %d 条（合计 20）⚠️"
          % (est, extra))

    # 5) 桶越细误差越小，但收益递减（读一次要扫 K 个桶，成本 O(K)）
    import random
    errs = {}
    for k in (2, 4, 10, 20):
        cc = Clock()
        bb = BucketWindow(100, 1.0, k, cc)
        rr = LogWindow(100, 1.0, cc)
        rnd = random.Random(7)
        for t in sorted(rnd.uniform(0.0, 1.0) for _ in range(100)):
            cc.t = t
            bb.allow()
            rr.allow()
        worst2 = 0.0
        for step in range(500):
            cc.t = 1.0 + step * 0.002
            worst2 = max(worst2, abs(bb.estimate() - rr.count()))
        errs[k] = worst2
        print("  K=%2d 桶宽 %.3fs: 随机流量最大估计误差 %.2f 条" % (k, 1.0 / k, worst2))
    assert errs[20] < errs[2]

    # 6) 内存：日志 O(limit)，分桶 O(K)
    c6 = Clock()
    big = LogWindow(1000, 1.0, c6)
    for _ in range(1000):
        big.allow()
    assert big.peak_len == 1000
    print("内存: 日志型峰值 %d 个时间戳；分桶型固定 %d 个 int ✅"
          % (big.peak_len, 10))

    # 7) 并发：8 线程抢同一个精确限流器，放行总数必须恰好等于 limit
    shared = LogWindow(100, 100.0, time.monotonic)
    ok = []
    lock = threading.Lock()

    def worker():
        local = 0
        for _ in range(200):
            if shared.allow():
                local += 1
        with lock:
            ok.append(local)

    ts = [threading.Thread(target=worker) for _ in range(8)]
    for t in ts:
        t.start()
    for t in ts:
        t.join()
    assert sum(ok) == 100, sum(ok)
    print("并发: 8 线程 1600 次抢 100 个额度，放行恰好 %d ✅" % sum(ok))
```

**追问**：1) 分桶近似的误差上界怎么给业务方解释？—— 一句话：**均匀流量下误差约 L/K，最坏是 L**（流量全挤在桶的边界附近时退化成固定窗口）。所以 K 不是「越大越好」，而是「按可容忍的超发比例反推」：能容忍 10% 超发就 K=10，能容忍 5% 就 K=20（读成本翻倍）。给业务方的承诺应写成「窗口内最多 L·(1+1/K) 次」，而不是「绝不超过 L 次」——后者只能靠日志型或令牌桶。2) 为什么分布式下精确日志也必须用 Lua？—— `ZREMRANGEBYSCORE` 清过期、`ZCARD` 判额度、`ZADD` 记账是三条命令，分开执行时两个实例可以同时读到 99 条、同时判定「还能放」、同时写入，配额直接翻倍；限流的本质是「检查与扣减必须原子」，而 Redis 的单命令原子不等于多命令原子，只有脚本/事务能保证。同理，近似型的 `MGET` 加权求和与后续 `INCR` 之间也有同样的窗口，需要 `INCR` 后再判、超了就回退（`DECR`），或者干脆接受这点误差。3) 为什么说日志型也挡不住瞬时突发？—— 它约束的是「窗口内总量」：配额 10/秒时，10 条可以集中在同一毫秒打完，下游那一瞬间的并发是 10；真正要平滑必须引入速率概念（令牌桶按恒定速率发牌，桶容量决定允许的突发量），或者用并发信号量限制在途数。面试里如果只答「滑动窗口解决固定窗口的 2 倍突发」而不区分「总量/速率/并发」，说明只记住了结论。

## 背诵要点
1. 三件套定位：固定窗口 O(1) 内存但边界 2 倍突发；日志型零误差、内存 O(L)；分桶 O(K) 内存、误差上界 = 单桶流量（均匀下 ≈ L/K，最坏退化成固定窗口）。
2. 时间必须注入（可测）；「检查 + 扣减」必须原子（进程内锁，Redis 用 Lua）；浮点加权比较要留 epsilon。
3. 窗口限流管总量，令牌桶管速率，信号量管并发——三个问题，不能互相替代；多租户场景几乎只能用分桶或集中式计数。

## 复盘追问
1. 线上限流器「偶尔多放一条」，怎么定位？（提示：先看边界实现——`<` 还是 `<=`、浮点比较有没有 epsilon、`bisect`/取整的桶边界是否在两端重复计入；再查时钟：用墙钟会被 NTP 回拨打断，`monotonic` 才是本地限流的正确时钟，分布式则统一用服务端时间）
2. 多租户共用一套 Redis 计数，某个租户把 key 打爆了怎么办？（提示：按租户分 key 而不是全局限流才能隔离；再叠一层「租户配额 + 全局兜底」，全局额度小于各租户配额之和，防止所有租户同时打满把 Redis 本身打挂——限流器自身也是被保护对象）
