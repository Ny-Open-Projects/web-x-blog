### A170 · 值班交接四眼复核

> 难度:★★☆ | 标签:值班, 交接, 治理

**问**（笔试·场景题）：交接做了但接班人「不知道自己不知道什么」——交接的四眼复核（书面清单+口头确认双向签名）怎么设计（口头确认什么内容才算确认），交接清单的「三态标注」（每项在途事项的状态：进行中/已升级/已解决）为什么关键，「交接失败」（接班后爆雷发现交接没提）的责任与复盘怎么处理，自动化交接（系统生成待办移交）与人工判断怎么配合？

**答**：① 四眼复核设计：**书面**（交接清单系统化：在途/风险/变更三节，Q142 模板）+ **口头**（逐项过，接班人**复述确认**——不是「明白了吗」而是「我理解的是 X，对吗」——复述暴露理解偏差）；双向签名（交方确认「已完整交代」+ 接方确认「已理解」——双方签字=责任分界线）。② 三态标注关键性：每项在途事项必须标 `进行中（我做了一半，接手要点）/已升级（升级给谁了，等回复）/已解决（留档）`——「进行中未标注」的事项接班后状态断链（做一半的任务没人知道做到哪）——三态是交接清单的最小结构化要求。③ 交接失败复盘：接班后爆雷且交接清单没提 → 双向分析——交方漏报（清单机制缺口：为什么不在清单里——知识在脑子里）+ 接方漏查（该问没问）——行动项双向（不是追人：交方补「隐性知识清单化」机制，接方补「接手首查项」）。④ 自动化+人工：系统自动生成「未闭环事项移交」（工单/告警/变更状态机导出——客观部分机器生成零遗漏），人工部分（风险预判/上下文背景）四眼复核——机器管完整性、人管判断。

```python
# 全部标准库；demo 实现「交接清单三态 + 双向签名」
import time

class Handoff:
    def __init__(self, out_going: str, in_coming: str):
        self.out_going, self.in_coming = out_going, in_coming
        self.items: list[dict] = []
        self.signed = {"out": False, "in": False}
    def add_item(self, name: str, state: str, detail: str):
        assert state in ("进行中", "已升级", "已解决"), "三态标注强制"
        self.items.append({"name": name, "state": state, "detail": detail})
    def verbal_confirm(self, person: str, restatements: dict[str, str]) -> list[str]:
        """口头复述确认：接班人复述理解，偏差即缺口。"""
        assert person == self.in_coming, "复述必须是接班人"
        deviations = []
        for item in self.items:
            said = restatements.get(item["name"], "")
            if item["state"] not in said and item["name"] not in said:
                deviations.append(f"{item['name']}：复述缺失或偏差")
        return deviations
    def sign(self, person: str) -> bool:
        if person == self.out_going:
            self.signed["out"] = True
        if person == self.in_coming:
            self.signed["in"] = True
        return all(self.signed.values())

if __name__ == "__main__":
    h = Handoff("zhang", "li")
    h.add_item("DB 扩容", "进行中", "已提交工单，等 DBA 确认窗口")
    h.add_item("支付超时告警", "已升级", "升级给 pay-team，等回复")
    h.add_item("缓存清理", "已解决", "已完成留档")
    deviations = h.verbal_confirm("li", {"DB 扩容": "我知道 DB 扩容在等 DBA",
                                          "支付超时告警": "哦有个告警",
                                          "缓存清理": "完成了"})
    assert deviations and "支付超时告警" in deviations[1]  # 复述偏差暴露 ✅
    print("复述确认发现理解偏差:", deviations)
    assert not h.sign("zhang") or True
    h.sign("zhang"); h.sign("li")
    assert all(h.signed.values())
    print("双向签名完成（交方已完整交代 + 接方已理解）✅")
    # 口径：三态标注强制；复述确认暴露理解偏差；双向签名=责任分界线；
    # 机器生成完整性 + 人工判断风险，两层配合。
```

**追问**：1) 为什么「复述确认」优于「明白了吗」？——「明白了」是社交应答（无信息量），复述暴露真实理解（偏差当场纠正而非接班后爆雷）——教学与交接的通用技巧：输出才是理解的证明。2) 「双向签名」的责任分界线怎么用在复盘？（提示：签名后爆雷且清单已提 → 接方处置问题（值班能力）；清单没提 → 交方/机制问题（隐性知识清单化缺口）——签名的价值不是追责而是「失败时知道去哪找缺口」）3) 自动化交接生成「未闭环事项」的来源有哪些？（提示：未关闭工单+未关闭告警+进行中变更单+超期行动项（A138）+ 升级中事件——五个状态机的 open 项导出，零遗漏机器保障）

## 背诵要点
1. 交接四眼复核：书面清单（三节模板）+ 口头**复述确认**（不是「明白了吗」）+ 双向签名（责任分界线）。
2. 每项在途事项三态标注强制（进行中/已升级/已解决）——「进行中未标注」= 状态断链。
3. 自动化（五状态机 open 项导出，零遗漏）+ 人工（风险预判与背景）两层配合；交接失败复盘双向归因。

## 复盘追问
1. 交接清单越来越长（50 项），接班人读不完怎么办？（提示：三态过滤（已解决项自动归档不进交接）+ 分级（P0 在途必过、低风险项书面即可）——清单质量治理（Q142 同构），长度失控是清单的债）
2. 两人交接时正好出事故（交接中断），流程怎么处理？（提示：事故优先（接班人立即协助或接手），交接延后补做（书面确认不省——口头可延后）；事故中的「临时接管」责任线在复盘里补记——流程为事故让路但不消失）
