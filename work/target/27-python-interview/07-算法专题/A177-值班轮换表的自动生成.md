### A177 · 值班轮换自动排班

> 难度:★★★ | 标签:排班, 公平性, 约束求解

**问**（笔试·编程+场景题）：8 个人排月度值班表（每日 1 主班+1 副班）——排班约束有哪些（硬约束：不连续两天主班/已申请回避日期；软约束：尽量周末均衡/相邻两次间隔 ≥7 天），贪心排班为什么会陷入死局（前面排完后面无解——回溯），排班表的公平性怎么量化（各人周末班数方差），「临时换班」怎么管理（换班后公平性重新校验）？

**答**：① 约束分级：**硬约束**（不可违反：连续主班禁令/回避日期/人员可用性——违反即重排）、**软约束**（尽量满足：周末均衡/间隔最大化——违反打分扣分，总分最优即可）。② 贪心陷阱：按日期顺序逐日填人，前面的「最优选择」可能让后面某天无解（只剩回避的人）——解法：**回溯搜索**（冲突时回退重排）或约束求解器（小规模贪心+局部修复即可）。③ 公平性量化：**周末班数方差**（各人周末班占比的方差 <阈值）+ 主班总数均衡——公平性是排班质量的核心指标（值班痛苦要分摊）；临时换班后重算公平性（换班是个人协商，公平性是团队纪律——协商后总表仍需校验）。④ 自动化收益：排班从 2 小时手工（还经常不公平）到秒级生成+公平性保证——换班管理同样系统化（换班申请→重算→重新校验→生效）。

```python
# 全部标准库；demo 实现「回溯排班 + 公平性校验」
import statistics
from collections import Counter

DAYS = 14
PEOPLE = [f"p{i}" for i in range(8)]
AVOID = {"p0": {0, 1}}                    # p0 前两天回避
WEEKEND = {5, 6, 12, 13}                  # 周末日索引

def feasible(day, primary, secondary, schedule):
    if primary == secondary: return False
    if primary in AVOID and day in AVOID[primary]: return False
    if secondary in AVOID and day in AVOID[secondary]: return False
    if day > 0:
        prev = schedule[day - 1]
        if prev and primary == prev[0]:   # 不连续两天主班
            return False
    return True

def schedule_month(day=0, schedule=None, used=None):
    schedule = schedule or [None] * DAYS
    used = used or Counter()
    if day == DAYS:
        return schedule
    for p in PEOPLE:
        if used[p] >= 2: continue              # 软约束简化：单人月内 ≤2 次主班
        for q in PEOPLE:
            if p == q: continue
            if feasible(day, p, q, schedule):
                schedule[day] = p
                used[p] += 1
                result = schedule_month(day + 1, schedule, used)
                if result:
                    return result
                used[p] -= 1
                schedule[day] = None
    return None

def fairness(schedule: list) -> dict:
    primary = Counter(s for s in schedule if s)
    weekend = Counter(p for i, p in enumerate(schedule) if i in WEEKEND and p)
    var = statistics.pvariance(list(weekend.values()))
    return {"primary": dict(primary), "weekend_var": round(var, 2)}

if __name__ == "__main__":
    s = schedule_month()
    assert s and all(s)
    f = fairness(s)
    print("排班成功（回溯求解）:", f)
    assert f["weekend_var"] <= 2.0             # 周末班方差有界（公平性）
    print("公平性：周末班方差 ≤2 ✅；临时换班后重跑 fairness 校验即可")
    # 口径：硬约束回溯求解 + 软约束打分；公平性 = 周末班方差量化；
    # 换班协商后总表仍需重新校验（公平性是团队纪律）。
```

**追问**：1) 为什么贪心会陷入死局而回溯能解？——贪心逐日选「当前最优」不考虑全局（前 10 天排满后面 4 天无解）；回溯在死局时回退重选——约束求解的本质是「搜索+剪枝」，天数少时回溯足够，天数大上求解器（OR-Tools）。2) 「临时换班」为什么必须重算公平性？（提示：换班是私人协商（双方自愿），但换班后果由全团队承担（某人周末班翻倍）——公平性校验把「私人协商」约束在「团队纪律」内：校验不过=换班无效或需补偿安排——个人自由与团队公平的边界）3) 排班的「回避日期」怎么收集才不混乱？（提示：回避日期系统化提交（截止时间+工具表单）——截止后变更按换班流程处理（协商+重校验）——避免「排完才说」的返工）

## 背诵要点
1. 约束分级：硬约束（连续主班禁令/回避日期——违反重排）+ 软约束（周末均衡/间隔——打分）。
2. 贪心陷阱 → 回溯搜索（死局回退重排）；规模大上约束求解器；单人月内次数上限做剪枝。
3. 公平性量化 = 周末班方差 + 主班均衡；临时换班后必须重新校验（私人协商受团队纪律约束）。
