### A296 · 归并排序求逆序对：跨区间结算、稳定性与 O(n²) 暴力对拍

> 难度:★★★☆ | 标签:归并排序, 逆序对, 分治, 稳定性, 对拍

**问**（笔试·编程题）：给一个整数数组，统计满足 `i<j` 且 `a[i]>a[j]` 的数对个数，要求 O(n log n)：① 分治为什么能把所有逆序对不重不漏地分成「左半内部、右半内部、跨左右」三类，三类的互斥性与完备性怎么论证；② merge 时遇到 `a[i] > a[j]`，为什么能一次结算 `mid-i+1` 个逆序对，这个结论依赖左半的什么性质，取走 `a[j]` 之后为什么不会重复计数；③ 稳定性：为什么相等时必须取左边（写 `<=`），如果写成 `<` 会多算哪些对，对排序结果的稳定性有什么影响；④ 边界：空数组、单元素、已升序、全相等、严格降序（答案必须是 n(n-1)/2）、含负数与大值域；为什么这个方法完全不需要离散化，和「树状数组 + 离散化」比省掉了什么；⑤ 与 O(n²) 双重循环暴力做 120 组随机对拍，再跑 n=200000 的降序与全相等极值，算清 O(n log n) 时间与 O(n) 峰值空间，并对比冒泡（交换次数恰好等于逆序对数）与树状数组两种方案。

**答**：① 任取一对下标 `i<j`，它们的位置关系只有三种：同在左半 `[lo,mid]`、同在右半 `[mid+1,hi]`、或 i 在左 j 在右——不可能有第四种，所以三类完备；左半与右半不相交、跨类要求一端在左一端在右，所以三类互斥。递归负责前两类，merge 负责第三类，既不漏也不重。② merge 的前提是左右两半**各自已经升序**；当 `a[i] > a[j]`，左半从 i 到 mid 的每个元素都 ≥ `a[i] > a[j]`，且它们的下标都小于 j，所以这 `mid-i+1` 个元素都与 `a[j]` 构成逆序对，可以整段结算，不需要逐个比较。随后把 `a[j]` 取走、j 右移，`a[j]` 不会再参与后续比较，左半那些元素以后只会与更靠右的 j 比较，所以不会重复计数。③ 相等时必须走 `<=` 分支取左边：逆序对定义是**严格大于**，相等不构成逆序；若写成 `<`，会把「左半等于 a[j]」的元素误判成大于，凭空多算 `mid-i+1` 那一整段里的相等元素。同时 `<=` 保证相等时左半先出，归并排序是稳定的（相等元素的相对顺序不变）；写成 `<` 会让右半的相等元素抢先，破坏稳定性。④ 空数组与单元素返回 0；已升序、全相等都返回 0（后者专门验证「相等不算」）；严格降序每一对都是逆序，答案必为 `n(n-1)/2`，这是大 n 下唯一能 O(1) 写出期望值的用例；负数与大值域完全无影响，因为算法只做元素间的大小比较、不拿元素值当数组下标。这正是相对「树状数组 + 离散化」的优势：BIT 方案要先排序去重、把值映射到 `1..k`，多一层 O(n log n) 与实现复杂度，而归并只比较、不索引。⑤ 对拍：120 组随机 n=0..60、值域 -3..3（大量重复，专门压相等分支），与双重循环逐对计数比较；另外 50 组校验分治的副作用——输出必须等于 `sorted(a)`、且入参不能被修改（函数内先拷贝）。极值 n=200000 严格降序得到 19999900000，全相等与升序得到 0，用时约 0.8 秒。复杂度：每层合并 O(n)，共 ⌈log2 n⌉ 层，时间 O(n log n)；空间上任一时刻只有当前合并的临时数组存活，峰值 O(n)，递归栈 O(log n)。对比：冒泡的交换次数确实恰好等于逆序对数（每次相邻交换消掉且只消掉一个逆序），但 O(n²)，20 万直接不可行；树状数组从右往左扫、查「已插入的比当前值小的个数」，也是 O(n log n)，但要离散化、且查询边界（严格小于还是小于等于）容易写错。归并的优点是实现自洽、无需值域假设，缺点是会改写数组（需拷贝）且常数略大。

```python
# 全部标准库；归并排序统计逆序对，与 O(n^2) 暴力对拍，并校验排序稳定性语义
import random
import time


def _sort_count(a, lo, hi):
    if lo >= hi:
        return 0
    mid = (lo + hi) // 2
    cnt = _sort_count(a, lo, mid) + _sort_count(a, mid + 1, hi)

    tmp = []
    i, j = lo, mid + 1
    while i <= mid and j <= hi:
        if a[i] <= a[j]:          # 取等号：相等时先取左侧，保证稳定且不计逆序
            tmp.append(a[i])
            i += 1
        else:
            tmp.append(a[j])
            j += 1
            cnt += mid - i + 1    # a[i..mid] 全部 > a[j]，一次结算整段
    if i <= mid:
        tmp.extend(a[i:mid + 1])
    if j <= hi:
        tmp.extend(a[j:hi + 1])
    a[lo:hi + 1] = tmp
    return cnt


def sort_and_count(a):
    """返回 (升序列表, 逆序对数)，不修改入参。"""
    arr = list(a)
    return arr, _sort_count(arr, 0, len(arr) - 1)


def count_inversions(a):
    return sort_and_count(a)[1]


def brute(a):
    return sum(1 for i in range(len(a)) for j in range(i + 1, len(a)) if a[i] > a[j])


if __name__ == "__main__":
    rng = random.Random(2961)

    # 1) 120 组随机（n=0..60，值域含大量重复）与 O(n^2) 暴力对拍
    for _ in range(120):
        n = rng.randint(0, 60)
        a = [rng.randint(-3, 3) for _ in range(n)]
        assert count_inversions(a) == brute(a), a
    print("逆序对对拍: 120 组随机（含重复值）vs O(n^2) 暴力，全等 ✅")

    # 2) 排序正确性：分治的副作用必须是升序，且不改入参
    for _ in range(50):
        a = [rng.randint(-100, 100) for _ in range(rng.randint(0, 80))]
        snap = list(a)
        s, cnt = sort_and_count(a)
        assert s == sorted(a) and cnt == brute(a) and a == snap
    print("排序正确性: 50 组随机，输出升序、入参未被修改 ✅")

    # 3) 边界：空、单元素、已升序、全相等、严格降序、两元素
    assert count_inversions([]) == 0
    assert count_inversions([9]) == 0
    assert count_inversions([1, 2, 3, 4, 5]) == 0
    assert count_inversions([4, 4, 4, 4]) == 0
    assert count_inversions(list(range(10, 0, -1))) == 45
    assert count_inversions([2, 1]) == 1 and count_inversions([1, 2]) == 0
    assert sort_and_count([3, 1, 3, 2])[0] == [1, 2, 3, 3]
    print("边界: 空/单元素/升序/全相等/降序/两元素 全过 ✅")

    # 4) 稳定性语义：相等元素不计逆序，逆序对只由严格大于产生
    assert count_inversions([1, 1, 1, 0, 0]) == 6      # 3 个 1 各与 2 个 0 配对
    assert count_inversions([0, 0, 1, 0]) == 1         # 只有 1 与后面的 0
    print("稳定性语义: 相等不计数，跨区间贡献 = mid - i + 1 ✅")

    # 5) 极值：n=20 万严格降序，答案必为 n(n-1)/2；全相等必须为 0
    n = 200000
    desc = list(range(n, 0, -1))
    t0 = time.perf_counter()
    got = count_inversions(desc)
    cost = time.perf_counter() - t0
    assert got == n * (n - 1) // 2 == 19999900000
    assert count_inversions([7] * n) == 0
    assert count_inversions(list(range(n))) == 0
    print("极值: n=200000 降序 → %d（公式一致），耗时 %.2fs ✅" % (got, cost))

    print("对拍通过：归并求逆序对 120 组随机 + 50 组排序校验 + 边界 + 20 万极值全绿")
```

**追问**：1) 冒泡的交换次数明明等于逆序对数，为什么不用？—— 因为冒泡每次只消掉相邻的一个逆序，时间 O(n²)，而逆序对数量本身可达 n²/2，20 万就爆了；本题只要求**计数**、不要求列出每一对，所以完全没必要逐对消。这也是「输出规模决定算法下界」的典型例子：如果要输出全部逆序对，答案本身就有 O(n²) 个，谁都做不到更快。2) 树状数组方案怎么做，为什么必须离散化？—— 从右往左扫，每遇到 `a[i]` 就查询「已插入元素中严格小于它的个数」并累加，再把自己插入；BIT 的下标必须是 `1..k` 的整数，值域到 1e9 或含负数时开不下，所以先排序去重、把每个值映射到 rank，重复值共用一个 rank（查询用 `rank-1` 即严格小于）。代价是额外的排序与映射，以及「严格小于/小于等于」这个边界容易写错。3) 逆序对和 LIS 有什么关系？—— 两者都描述排列的有序程度，但不等价：逆序对数衡量「离升序有多远」，LIS 衡量「最长上升链有多长」。由 Dilworth / Erdős–Szekeres，n 个不同元素的序列若 LIS 长度为 a、最长下降子序列长度为 b，则 `n <= a*b`，所以逆序对多（下降结构长）会逼迫 LIS 或 LDS 变长，但仅凭逆序对数推不出 LIS 的具体值。A289 的 patience + 二分求 LIS 与本题的归并计数是两套完全不同的工具，别混用。
