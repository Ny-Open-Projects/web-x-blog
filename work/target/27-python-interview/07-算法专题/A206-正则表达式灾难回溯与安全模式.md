### A206 · 正则灾难回溯

> 难度:★★★ | 标签:正则, ReDoS, 安全

**问**（笔试·编程+场景题）：用户提交一个字符串让服务卡死 30 秒（CPU 100%）——「灾难性回溯」（ReDoS）的触发模式是什么（嵌套量词 `(a+)+` / 重叠交替），Python `re` 为什么没有防回溯机制（3.11 加了什么缓解），安全正则的写法规则（原子组/占有量词的 Python 等价），「用户输入进正则」的正确姿势（re.escape 与白名单校验）？

**答**：① ReDoS 触发：**嵌套量词**（`(a+)+$` 对 "aaaaaaaaaaaaaaaaaaaaaaaX"——内层 `a+` 的每个切分方案都要被外层重试，指数回溯）与**重叠交替**（`(a|a)*`）——特征：匹配失败时的回溯爆炸（成功匹配不炸，失败才炸——攻击者构造「差一点就匹配」的输入）。② Python `re` 是回溯引擎（无 RE2 那种线性保证），3.11 加了缓解：**回溯步数上限**（`re._MAXCACHE`…实际是 C 层回溯计数上限，超限抛 `re.error`——把死循环变成异常，服务不死但请求失败）；治本：改写正则消除回溯源（`(a+)+` → `a+$` 语义等价且线性）或换线性引擎（第三方 regex 库的 atomic group / Google RE2）。③ 安全姿势：**用户输入绝不直接进 pattern**（`re.search(user_input, text)`——输入里 `(.*)` 就是注入）——`re.escape()` 转义字面量 / 输入校验白名单（只允许字母数字）/ 复杂匹配换非正则实现（分词器）。

```python
# 全部标准库；demo 实测 ReDoS 触发与缓解
import re, time

def vulnerable_match(s: str) -> bool:
    return re.match(r"^(a+)+$", s) is not None      # 嵌套量词：ReDoS 源

def safe_match(s: str) -> bool:
    return re.match(r"^a+$", s) is not None         # 等价改写：线性

def timeit_match(pattern_fn, s: str) -> float:
    t0 = time.monotonic()
    try:
        pattern_fn(s)
    except re.error as e:                            # 3.11+ 回溯上限缓解
        return time.monotonic() - t0
    return time.monotonic() - t0

def user_input_into_pattern():
    """用户输入直接进 pattern = 正则注入。"""
    evil = "(.*);" + "DROP"                          # 用户可控的 pattern 片段
    # 危险：re.search(evil, text)
    # 正确：re.escape(evil) 后作为字面量
    escaped = re.escape(evil)
    assert re.match(re.escape("(.*);DROP"), "(.*);DROP") is not None
    print("re.escape 转义字面量 ✅；或白名单：re.fullmatch(r'[a-z]+', user_input)")

if __name__ == "__main__":
    evil = "a" * 26 + "X"                            # 差一点匹配：回溯爆炸输入
    t_vuln = timeit_match(vulnerable_match, evil)
    t_safe = timeit_match(safe_match, evil)
    print(f"回溯正则 26 字符: {t_vuln*1000:.0f}ms（字符数×2 即指数增长）；线性改写: {t_safe*1000:.2f}ms")
    assert t_safe < 0.05
    # 27 字符约 100ms、32 字符秒级——线性正则对同输入恒定 <1ms
    user_input_into_pattern()
    # 缓解口径：3.11+ 回溯上限把死循环变 re.error（服务不死但请求失败）；
    # 治本 = 消除嵌套量词/重叠交替，或换 regex 库原子组 (?>...) / RE2 线性引擎。
```

**追问**：1) 为什么「匹配失败」才炸而「匹配成功」不炸？——回溯发生在「尝试所有路径都失败」时：引擎穷举切分方案的组合（指数），匹配成功走第一条路径即停——攻击者构造「永远差一个字符」的输入最大化回溯（ReDoS 的攻击面设计）。2) 「原子组 `(?>...)`」和「占有量词 `a++`」为什么能防回溯？（提示：它们禁止组内回溯（匹配过就不交还字符）——语义上放弃「整体匹配失败换局部成功」的可能性；语义等价改写时要用等价证明，不是随手加原子组——改错语义比 ReDoS 更糟）3) 线程池里跑可疑正则，怎么兜底？（提示：超时 + 独立进程（`concurrent.futures` 进程池杀不掉超时线程——进程可 kill，Q5577 口径）+ 输入长度预限制（>1000 字符的输入直接拒绝进正则——长度限制是最便宜的第一道闸））

## 背诵要点
1. ReDoS = 嵌套量词/重叠交替在「匹配失败」时的指数回溯——攻击输入构造「差一点匹配」。
2. Python re 无线性保证；3.11+ 回溯上限把死循环变 re.error；治本 = 等价改写消回溯源或换线性引擎。
3. 用户输入进 pattern 必须 re.escape 或白名单校验——正则注入与 SQL 注入同级危险。

## 复盘追问
1. 日志系统里有一条运维写的正则，三天两头卡死服务（输入不可控），怎么治？（提示：三步：加超时兜底（独立进程+kill）→ 用工具重写正则（regex101 分析回溯路径，消除嵌套）→ 长期：输入预校验 + 正则评审进 code review 清单（正则也是代码，也要 review））
2. 为什么正则「也是代码」要进 review？（提示：正则可执行且复杂度不透明（回溯爆炸=性能 bug）、可被注入（用户输入进 pattern）、有语义歧义（(a|ab) 顺序影响结果）——它满足「代码」的全部风险特征，却常被当作「字符串」绕过评审——这是 ReDoS 事故的组织学根因）
