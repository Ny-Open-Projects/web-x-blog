### A220 · 值班周报自动生成

> 难度:★★☆ | 标签:值班, 周报, 可观测性

**问**（笔试·编程+场景题）：值班周报手工写 2 小时还遗漏——周报怎么自动生成（数据来源：告警系统/工单系统/变更系统的聚合），周报的「治理信号」（不只是记录：告警总量趋势/Top 噪声源/变更密度——治理的输入），「写周报」的人力成本怎么压到 15 分钟（自动草稿+人工补充判断），周报的读者分层（团队内部 vs 管理层的内容差异）？

**答**：① 自动草稿来源聚合：告警系统（本周告警数/Top 噪声源/分服分布）、工单（未闭环事项）、变更系统（发布次数/回滚数）、SLA（本月错误预算消耗）——四系统数据聚合出「事实部分」；人工补充「判断部分」（本周的系统性观察：为什么告警涨了/哪个变更风险大）。② 治理信号：周报不是「流水账」而是**治理输入**——Top 噪声源（应发起降噪专项 Q7039）、告警趋势环比（连续 3 周上涨=系统性劣化）、回滚率（发布质量趋势）、错误预算消耗速率（Q179）——每项信号带「建议动作」。③ 15 分钟目标：自动草稿覆盖 80% 事实（数据聚合零人工）+ 人工只写「判断与观察」（3-5 条）——人力压到 15 分钟的关键是**数据管道自动化**（聚合脚本定时跑，草稿自动成文）。④ 读者分层：团队版（细节：每条告警/每个变更——复盘与行动项输入）+ 管理层版（信号与趋势：3 条治理信号+预算状态——管理层不需要流水账，需要「决策需要的信号」）。

```python
# 全部标准库；demo 实现「周报自动草稿生成器」
from collections import Counter

def auto_draft(alerts: list[dict], deploys: list[dict],
               budget_burn: float, open_tickets: int) -> dict:
    """四系统聚合 → 事实部分自动成文。"""
    noisy = Counter(a["name"] for a in alerts).most_common(3)
    rollbacks = sum(1 for d in deploys if d["rollback"])
    signals = []
    if rollbacks >= 3:
        signals.append(f"回滚 {rollbacks} 次 → 发布质量信号，建议复盘")
    if budget_burn > 1:
        signals.append(f"错误预算燃烧率 {budget_burn}× → 冻结评估（Q179）")
    if open_tickets > 20:
        signals.append(f"工单积压 {open_tickets} → 值班疲劳预警（Q142）")
    return {"facts": {"alerts": len(alerts), "top_noise": noisy,
                      "deploys": len(deploys), "rollbacks": rollbacks},
            "governance_signals": signals}

def team_view(draft: dict) -> str:
    return f"告警 {draft['facts']['alerts']} 次，Top 噪声: {draft['facts']['top_noise']}"

def mgmt_view(draft: dict) -> str:
    sig = "; ".join(draft["governance_signals"]) or "无治理信号"
    return f"治理信号: {sig}"

if __name__ == "__main__":
    alerts = ([{"name": "conn_pool_warn"}] * 40 +
              [{"name": "log_disk_80"}] * 20 + [{"name": "other"}] * 5)
    deploys = [{"rollback": False}] * 5 + [{"rollback": True}] * 3
    draft = auto_draft(alerts, deploys, budget_burn=1.2, open_tickets=25)
    print("团队版:", team_view(draft))
    print("管理层版:", mgmt_view(draft))
    assert len(draft["governance_signals"]) == 3      # 三条治理信号自动识别 ✅
    assert draft["facts"]["top_noise"][0][0] == "conn_pool_warn"
    print("自动草稿覆盖 80% 事实 + 人工补判断 = 15 分钟周报 ✅")
    # 口径：四系统聚合出事实、人工写判断；治理信号带建议动作；读者分层两版。
```

**追问**：1) 为什么周报的「治理信号」比「流水账」重要？——流水账是记录（事后翻阅），治理信号是**行动输入**（触发降噪专项/发布复盘/疲劳治理）——没有治理信号的周报是「写了没人看」的成本项；每条信号带建议动作才构成治理闭环。2) 「自动草稿覆盖 80%」的 80% 怎么达成？（提示：数据源自动化程度决定——告警/工单/变更/SLA 四系统都有 API（Q7017 管道同构）——聚合脚本一次性建设后零边际成本；人工部分天然是「判断类」（不可自动化）——自动化覆盖事实、人工专注判断是分工本质）3) 管理层版要不要包含「技术细节」？（提示：管理层需要的是「决策信号」（要不要加人/要不要冻结发布/要不要修系统）——技术细节（哪个服务哪个接口）稀释决策信号——读者分层的内容差异=信息颗粒度差异（Q747 大盘设计同构））

## 背诵要点
1. 周报四源聚合自动成文：告警/工单/变更/SLA——事实部分零人工，人工只写判断与观察（15 分钟目标）。
2. 治理信号四类带建议动作：Top 噪声源（降噪专项）/回滚率（发布质量）/预算燃烧（冻结评估）/工单积压（疲劳预警）。
3. 读者分层：团队版（细节流水）+ 管理层版（决策信号）——信息颗粒度差异。

## 复盘追问
1. 周报自动生成了但「管理层不看」（还是邮件群里问），怎么让周报被消费？（提示：治理信号直接进管理层的现有渠道（周会开场 3 分钟/IM 机器人推送）——周报要到读者手里（推送）而不是「发布等阅读」（Q168 文档同构）——内容分层+渠道对齐双管齐下）
2. 自动周报连续四周「无治理信号」但季度出了大事故——周报的信号体系漏了什么？（提示：周报维度是「周粒度信号」，慢性问题（技术债/知识单点）是「季度粒度」——周报加「季度趋势线」（连续多周的缓慢劣化检测，Q7008 窗口同构）；慢信号要低频报表承载）
