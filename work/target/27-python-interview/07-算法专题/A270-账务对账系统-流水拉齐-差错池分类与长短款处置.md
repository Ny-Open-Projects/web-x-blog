### A270 · 账务对账系统的差错处理闭环

> 难度:★★★★ | 标签:对账, 长短款, 差错池, 资金安全, 幂等

**问**（笔试·场景题）：支付平台每天与微信/支付宝渠道对账。要求设计并实现对账核心：① **流水拉齐**：双方流水按「规范化订单号」拉齐（大小写/空格归一），金额一律用**整数分**——为什么浮点金额是对账天敌；② **差错分类器**：双方金额不一致（金额差错）、我方有对方无（短款方向，疑似掉单）、对方有我方无（长款方向，渠道扣了钱我方没记账）、同侧重复流水、T+1 切割线附近的**在途单**（双方时差造成的假差错）五类——每类给出处置路径；③ **自动补单**：我方单边先查证渠道（query_channel），查到就补单转平，查不到才转人工——为什么查证必须在对账侧而不是信回调；④ **人工差错池**：长款与查证失败的单边进池，带唯一差错号与超期升级（24 小时未核销升级告警）——资金类差错为什么不允许「静默丢弃」。给出可运行实现并逐类断言。请说清与 A105（秒杀对账的分钟级增量口径）、A249（数据库迁移的行数+哈希对账）、A115（Redis 快账与账单慢账对账）的分工——本题只回答「**资金级对账的拉齐、分类与长短款闭环**」。

**答**：① 分工：A105 是秒杀场景的库存对账（Redis+DB 快慢账）、A249 是迁移数据一致性对账、A115 是配额对账——它们对的是「数量」；本题对的是**钱**，资金级对账多出来的东西是：金额分单位、在途窗、长短款的资金方向语义、以及「差错必须可追溯到人」的合规要求。② 拉齐：唯一键 = 规范化订单号（去空格、统一大小写——渠道回来的单号带前后缀脏字符是最常见的假差错源）；金额用 int 分而不是 float 元：`0.1 + 0.2 != 0.3` 在对账场景不是段子是资损——两边各记 0.1 元用浮点算出来可能一边 0.30000000000000004 一边 0.3，逐单比对全炸。所有金额字段从落库那天起就是分。③ 五类差错与处置：**金额差错**（双方都有单但金额不等）→ 以渠道流水为准冲正我方（渠道是资金事实源，我方账只是映射），冲正是新流水不是改老流水（审计链不断）；**我方有对方无**（短款方向）→ 疑似掉单/回调丢失，先自动查证渠道，查到补单、查不到进人工池（也可能是我方多记的单，要冲销）；**对方有我方无**（长款方向）→ 渠道扣了钱我方没记账，是「资金多头」，必须落账或退回，最危险的一类——用户付了钱没拿到东西，客服工单马上就来；**同侧重复**→ 幂等缺口（渠道重发通知我方没去重），先去重再对账，重复流水本身就是要修的 bug；**在途单**→ T+1 切割线附近双方时差造成的假差错（我方 23:59 支付、渠道 00:01 出账），切到「在途池」滚入次日对账，不算差错——没有在途窗的对账系统每天切割线附近都会误报一串。④ 自动补单为什么查证在对账侧：支付回调是**尽力而为**的通道（网络抖动、重试耗尽、消费者宕机都可能丢），拿「没收到回调」推「没支付成功」是错的；渠道的对账单/查证接口才是事实源。查证动作必须幂等（同一差错号多次补单只生效一次），补单产生的流水带来源标记（`auto_repair`），与正常流水区分——否则补单本身又变成对不上的新差错。⑤ 人工差错池：长款与查证失败的单边进池，带唯一差错号、责任人、超期升级（24h 未核销告警升级）——资金差错**不允许静默丢弃**也不允许自动平账（自动平长款等于自动动用户钱包），差错池的消化率与积压时长本身是对账系统的核心 SLO。一句话总结闭环：**先拉齐、再分流（在途/差错）、先机器（查证补单）、后人工（差错池）、全程幂等可追溯**。

```python
# 全部标准库；账务对账：流水拉齐 + 五类差错分类 + 自动补单 + 人工差错池
from collections import namedtuple

Record = namedtuple("Record", "order amount status ts")   # amount 单位=分(int)
InFlight = namedtuple("InFlight", "order ours theirs")

MATCHED, AMOUNT, OURS_ONLY, THEIRS_ONLY, DUP, INFLIGHT = (
    "matched", "amount_diff", "ours_only", "theirs_only", "dup", "inflight")


def norm_order(raw):
    """订单号规范化：渠道回单常见脏字符（空格/大小写/前后缀）先归一再拉齐。"""
    return raw.strip().upper()


def reconcile(ours, theirs, inflight_after):
    """拉齐 + 分类。inflight_after：T+1 切割线时间戳，晚于它的单边进在途池。"""
    our_map, their_map, pool = {}, {}, []
    for r in ours:                       # 同侧重复流水：幂等缺口单列
        key = norm_order(r.order)
        if key in our_map:
            pool.append({"type": DUP, "side": "ours", "key": key})
        else:
            our_map[key] = r
    for r in theirs:
        key = norm_order(r.order)
        if key in their_map:
            pool.append({"type": DUP, "side": "theirs", "key": key})
        else:
            their_map[key] = r

    matched = []
    for key in sorted(set(our_map) | set(their_map)):
        o, t = our_map.get(key), their_map.get(key)
        if o and t:
            if o.amount == t.amount:      # 金额是 int 分：相等才平
                matched.append(key)
            else:
                pool.append({"type": AMOUNT, "key": key,
                             "ours": o.amount, "theirs": t.amount,
                             "action": "以渠道为准冲正（新流水，不改老流水）"})
        elif o:
            if o.ts >= inflight_after:
                pool.append({"type": INFLIGHT, "key": key,
                             "action": "切割线附近，滚入次日对账"})
            else:
                pool.append({"type": OURS_ONLY, "key": key, "rec": o,
                             "action": "短款方向：疑似掉单，先查证渠道"})
        else:
            if t.ts >= inflight_after:
                pool.append({"type": INFLIGHT, "key": key,
                             "action": "切割线附近，滚入次日对账"})
            else:
                pool.append({"type": THEIRS_ONLY, "key": key, "rec": t,
                             "action": "长款方向：资金多头，落账或退回，禁静默"})
    return matched, pool, our_map, their_map


def auto_repair(pool, our_map, channel_lookup, repaired_log):
    """我方单边先查证：查到补单转平（幂等），查不到留人工。"""
    fixed, manual = [], []
    for item in [p for p in pool if p["type"] == OURS_ONLY]:
        key = item["key"]
        if key in repaired_log:           # 补单幂等：同差错号只生效一次
            fixed.append(key)
            continue
        chan = channel_lookup(key)
        if chan is not None and chan.amount == our_map[key].amount:
            repaired_log[key] = chan      # 补单落库（带来源标记 auto_repair）
            fixed.append(key)
            item["action"] = "查证成功，已补单转平"
        else:
            item["action"] = "查证无果，转人工差错池"
            manual.append(key)
    return fixed, manual


class ErrorPool:
    """人工差错池：唯一差错号 + 24h 超期升级，资金差错禁静默丢弃。"""

    def __init__(self, now=0):
        self.seq, self.now = 0, now
        self.items = {}                   # 差错号 -> {key, created, escalated}

    def add(self, keys):
        out = []
        for k in keys:
            self.seq += 1
            eid = "ERR%06d" % self.seq
            self.items[eid] = {"key": k, "created": self.now, "escalated": False}
            out.append(eid)
        return out

    def escalate_overdue(self, after_s=86400):
        out = []
        for eid, it in self.items.items():
            if not it["escalated"] and self.now - it["created"] > after_s:
                it["escalated"] = True
                out.append(eid)
        return out


if __name__ == "__main__":
    CUT = 100000                          # T+1 切割线
    ours = [Record("o1", 1000, "PAID", 80000),
            Record(" O2 ", 500, "PAID", 81000),           # 脏单号，靠归一拉齐
            Record("o3", 800, "PAID", 70000),
            Record("o4", 200, "PAID", 60000),             # 渠道有账我方漏记回调 -> 查证补单
            Record("o9", 300, "PAID", 60000)]             # 我方多记的单 -> 查证无果转人工
    theirs = [Record("O1", 1000, "SUCCESS", 80000),
              Record("o2", 600, "SUCCESS", 81000),        # 金额差错 500 vs 600
              Record("o3", 800, "SUCCESS", 70000),
              Record("o5", 700, "SUCCESS", 50000),        # 长款：渠道扣钱我方无账
              Record("o6", 400, "SUCCESS", 100500),       # 切割线附近 -> 在途
              Record("o1", 1000, "SUCCESS", 80000)]       # 渠道重复通知 -> 同侧重复

    matched, pool, our_map, their_map = reconcile(ours, theirs, CUT)
    types = [p["type"] for p in pool]
    assert set(matched) == {"O1", "O3"}                   # 归一化把 " O2 " 拉齐；o2 进金额差错
    assert types.count(DUP) == 1 and types.count(AMOUNT) == 1
    assert types.count(OURS_ONLY) == 2 and types.count(THEIRS_ONLY) == 1
    assert types.count(INFLIGHT) == 1                     # o6 滚入次日
    print("拉齐分类: 平账 %d 单；差错 %s ✅" % (len(matched), {t: types.count(t) for t in set(types)}))

    # 金额差错：以渠道为准，冲正是新流水不改老流水
    amt = [p for p in pool if p["type"] == AMOUNT][0]
    assert (amt["ours"], amt["theirs"]) == (500, 600)
    print("金额差错: o2 我方 %d 分 vs 渠道 %d 分 -> %s ✅" % (amt["ours"], amt["theirs"], amt["action"]))

    # 自动补单：o4 查证到转平；o9 查证无果转人工；补单幂等（重复触发只生效一次）
    channel = {"O4": Record("o4", 200, "SUCCESS", 60000)}  # 渠道事实源（拉齐键=规范化单号）
    repaired_log, fixed, manual = {}, [], []
    for _ in range(2):                                     # 故意跑两遍验证幂等
        fixed, manual = auto_repair(pool, our_map, channel.get, repaired_log)
    assert fixed == ["O4"] and manual == ["O9"] and len(repaired_log) == 1
    print("自动补单: o4 查证成功补单转平；o9 查证无果转人工；补单幂等 ✅")

    # 人工差错池：长款 + 查证失败的单边，差错号唯一，24h 超期升级
    manual_keys = [p["key"] for p in pool if p["type"] == THEIRS_ONLY] + manual
    pool_obj = ErrorPool(now=0)
    eids = pool_obj.add(manual_keys)
    assert len(eids) == 2 and len(set(eids)) == 2          # o5 长款 + o9
    pool_obj.now = 90000
    assert set(pool_obj.escalate_overdue()) == set(eids)   # 全部超期升级
    print("差错池: %d 条人工差错带唯一差错号，24h 未核销全部升级告警 ✅" % len(eids))
```

**追问**：1) 长短款的定义为什么必须先在纸上写死？—— 不同公司口径相反：有的把「长款」定义为资金多于账面（渠道有我方无），有的按「我方资产多头」定义——面试里直接给结论不给出处会被追问到哑口无言。正确姿势是先声明口径（本题：长款 = 渠道有流水我方无账，资金在渠道侧多头；短款 = 我方有账渠道无流水），再谈处置。共通不变的是处置方向：**资金多头 → 落账或退回（人工），账面空头 → 查证补单（自动）**——方向错了就是自动退用户的钱，资损事故。2) 对账频率怎么定：T+1 全量还是分钟级增量？—— 渠道对账单通常 T+1 出，所以**资金级终局对账只能是 T+1 全量**；分钟级增量对的是「我方内部快慢账」（Redis 预扣 vs DB 落账，A105/A115 口径），作用是**早发现**（掉单 10 分钟内预警，用户感知前补单），但它替代不了 T+1——渠道不出账单，增量对账对不到资金真相。两层共存：增量管时效，全量管终局，全量结果反推增量规则的误报率。3) 查证接口被限流、差错单堆积怎么办？—— 查证是外部依赖，必须自己先做配额与退避（对账 worker 的 QPS 算账与 Q7122 同构），并给差错单定优先级：金额大、时间久的先查；堆积超水位（如 24h 池深超阈值）要升级到人工通道——**对账系统的积压本身就是资金风险敞口**，池深和账龄是要进监控大盘的 SLO，而不是事后报表。
