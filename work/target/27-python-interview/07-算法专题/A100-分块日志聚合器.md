### A100 · 分块日志聚合器

> 难度:★★☆ | 标签:生成器, 内存治理, 场景题

**问**（笔试·编程题）：一个 20GB 的 nginx 日志文件，每行 `ip\tstatus\tbytes\turl`。要求统计每个 ip 的请求次数与总字节数并输出 Top 100，**内存上限 512MB**。写出可运行实现并说明为什么不会超内存。

**答**：三段式流水线，全程不整读：1) `open` 逐行迭代（文件对象本身是惰性迭代器）；2) 若 ip 基数可能爆内存（如数百万独立 ip），先用分桶哈希把行写到 N 个临时文件（同 ip 必落同桶），再逐桶聚合并堆排序；ip 基数 < 100 万时直接单字典聚合即可（百万级 str+int 约 100MB 量级）。3) Top-K 用 `heapq.nsmallest(k, ...)` 配负号或维护小顶堆，避免全量排序。核心考点：**生成器惰性、外排分桶、Top-K 堆**。

```python
import heapq
from collections import defaultdict
from pathlib import Path

def stream_top_ips(path: str, k: int = 100, bucket_dir: str = "/tmp/logbkt",
                    buckets: int = 64) -> list[tuple[str, int, int]]:
    """ip 基数不确定时按哈希分桶，同 ip 必落同桶，逐桶聚合，内存 = 单桶字典。"""
    Path(bucket_dir).mkdir(exist_ok=True)
    handles = [open(f"{bucket_dir}/b{i}", "w") for i in range(buckets)]
    try:
        with open(path, encoding="utf-8", errors="replace") as f:
            for line in f:                      # 逐行惰性，不整读 20GB
                parts = line.rstrip("\n").split("\t")
                if len(parts) != 4:
                    continue                    # 脏行跳过并计数，不能让坏行杀死流水线
                ip, _status, _b, _u = parts
                handles[hash(ip) % buckets].write(line)
    finally:
        for h in handles:
            h.close()

    top = []                                    # 小顶堆：(count, ip, bytes)，只保留 k 条
    for i in range(buckets):
        agg: dict[str, list[int]] = defaultdict(lambda: [0, 0])
        with open(f"{bucket_dir}/b{i}", encoding="utf-8", errors="replace") as f:
            for line in f:
                ip, _s, b, _u = line.rstrip("\n").split("\t")
                agg[ip][0] += 1
                agg[ip][1] += int(b)
        for ip, (cnt, total) in agg.items():
            item = (cnt, ip, total)
            if len(top) < k:
                heapq.heappush(top, item)
            elif item > top[0]:
                heapq.heapreplace(top, item)
    return sorted(top, reverse=True)

if __name__ == "__main__":
    # demo: 造一个临时日志跑通
    demo = "/tmp/demo_access.log"
    with open(demo, "w") as f:
        for i in range(100000):
            f.write(f"10.0.{i % 300}.{i % 97}\t200\t{1024 * (i % 9)}\t/api/x\n")
    for cnt, ip, total in stream_top_ips(demo, k=5)[:5]:
        print(ip, cnt, total)
```

**追问**：1) 如果还要按 url 维度统计呢？——同 ip+url 组合分桶，桶数按组合基数调大；组合基数失控（长尾 url）时先聚合 ip 维度，url 维度单独按前缀分桶二次聚合。2) `hash()` 在这里有什么坑？——CPython 对 str 有随机化盐（PYTHONHASHSEED），进程内一致所以分桶没问题，但**跨进程/跨天复现分桶结果不可靠**，生产应换 `zlib.crc32` 或 md5 截断这种稳定哈希。

## 背诵要点
1. 20GB 单机聚合三板斧：逐行迭代、哈希分桶外排、Top-K 堆——内存由「单桶聚合字典」决定，与文件大小解耦。
2. `hash()` 有 PYTHONHASHSEED 随机化，跨进程不可复现，分桶要用稳定哈希（crc32/md5）。
3. Top-K 用小顶堆 `heapq.heapreplace`，复杂度 O(n log k)，不要全量 sort。
