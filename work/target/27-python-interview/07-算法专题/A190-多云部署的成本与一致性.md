### A190 · 多云部署

> 难度:★★★ | 标签:多云, 成本, 架构

**问**（笔试·场景题）：「防止被单一云厂商锁死」要上多云——多云的真实成本清单（一致性税：K8s 发行版差异/存储 API 差异/监控三套/专有服务不可迁移），「多云」的两种形态（全量双活 vs 主备容灾 vs 服务分层——各服务放不同云）成本差多少，「成本错觉」（云账单看起来省了但工程成本涨了）怎么量化，跨云数据传输费怎么算（出区流量费是最贵的隐形账）？

**答**：① 一致性税清单：**编排层**（K8s 各云发行版差异——要抽象层或选通用形态放弃专有功能）、**存储层**（对象存储 API 各家不同——抽象层或限定通用子集）、**可观测**（监控/日志三套系统——统一采集层自建）、**专有服务**（云厂商的托管数据库/AI 服务不可跨云——用了即锁死）——抽象层的开发与维护成本是持续税。② 三形态成本差：**全量双活**（两倍基础设施 + 一致性税——最贵，适合超大厂）；**主备容灾**（备云只跑最小容量（Q113 冷集群风险）+ 演练成本——中）；**服务分层**（核心服务在主云、边缘服务放第二云——每云只需维护自己那份的一致性，成本最低但「分散锁死」风险）。③ 成本错觉量化：云账单省的钱 vs 工程团队维护多云抽象层的**人力成本**（通常 2-4 名全职工程师）——多云的账要算「总拥有成本」（TCO）：账单 + 抽象层人力 + 演练成本 + 故障代价变化——TCO 视角下多数中小团队的多云是负收益。④ 跨云流量费：出区流量费（egress）≈$0.05-0.12/GB——跨云每 GB 数据都收费，「双活同步数据库」的流量费可能超过机器费——架构设计：跨云只同步必要数据（异步复制/批量），实时大数据流不过云。

```python
# 全部标准库；demo 实现「多云 TCO 计算器」
def tco_calculator(bill_saving: float, eng_headcount: int = 2,
                   avg_salary_year: float = 600000,
                   drill_cost_year: float = 200000,
                   egress_gb_month: float = 5000,
                   egress_price: float = 0.08) -> dict:
    """多云 TCO：账单节省 vs 抽象层人力+演练+跨云流量费。"""
    eng_cost = eng_headcount * avg_salary_year
    egress_cost = egress_gb_month * egress_price * 12
    hidden = eng_cost + drill_cost_year + egress_cost
    return {"bill_saving": bill_saving, "hidden_cost": hidden,
            "net": bill_saving - hidden,
            "verdict": "NEGATIVE-ROI" if hidden > bill_saving else "POSITIVE"}

def egress_budget(sync_tables: list[dict]) -> float:
    """跨云同步流量月费：只同步必要数据（按表评估）。"""
    monthly_gb = sum(t["daily_gb"] * t["sync_days"] * t["copies"] for t in sync_tables)
    return monthly_gb * 0.08

if __name__ == "__main__":
    r = tco_calculator(bill_saving=800000, eng_headcount=2)
    print({k: (f"{v/10000:.0f}万" if isinstance(v, (int, float)) and v > 1000 else v)
           for k, v in r.items()})
    assert r["verdict"] == "NEGATIVE-ROI", "账单省 80 万 < 隐性成本 140 万"
    # 流量费：跨云同步 3 张表，日 50GB
    sync = [{"name": "orders", "daily_gb": 30, "sync_days": 30, "copies": 1},
            {"name": "users", "daily_gb": 20, "sync_days": 30, "copies": 1}]
    cost = egress_budget(sync)
    print(f"跨云同步流量费: {cost/10000:.1f} 万/年（50GB/天 × 0.08$/GB）")
    assert cost > 0
    # 口径：TCO=账单+人力+演练+流量费；跨云只同步必要数据；
    # 服务分层形态成本最低，全量双活是超大厂专属。
```

**追问**：1) 为什么「服务分层」比「主备容灾」成本低还常被忽视？——主备容灾的备云要为「可能的切换」维护全套能力（一致性税全额缴），服务分层每云只维护自己服务的一致性（税按比例缴）——分层还把「多云」从容灾问题变成「部署位置选择」问题，复杂度骤降。2) 「锁死」的真实风险怎么评估？（提示：锁死成本 = 迁移工程（重写专有服务依赖）× 迁移概率（厂商关系/价格策略突变）——评估后常见结论：价格协商能力（用量大厂商让利）比多云架构更便宜地解决了「锁死焦虑」）3) 抽象层的「抽象泄漏」典型案例？（提示：各云消息队列的顺序保证/重复语义不同——抽象层统一 API 但语义统一不了——依赖语义差异的代码在换云时爆雷；抽象层要写「语义差异清单」文档化）

## 背诵要点
1. 一致性税四层：编排/存储/可观测/专有服务——抽象层人力是持续税（TCO 必算项）。
2. 三形态成本：全量双活（最贵）/主备容灾（中）/服务分层（最低）——中小团队多数是负 ROI。
3. 跨云 egress 流量费是隐形大头（$0.05-0.12/GB）——跨云只同步必要数据，实时大流不过云。

## 复盘追问
1. 已经上了多云（全量双活）发现负 ROI，怎么退？（提示：不可逆中找可逆项：先退「全量双活」为「服务分层」（每云保核心），再评估退「主备」为「备份+演练」（数据备份跨云但计算不跨）——渐进降级路径，避免一次性大迁移风险）
2. 厂商承诺「多云管理工具统一一切」，可信吗？（提示：管理工具统一的是控制面（部署/监控），数据面语义（存储 API/网络模型）与专有服务仍锁死——工具降低一致性税但不消除；评估时看「它没统一什么」）
