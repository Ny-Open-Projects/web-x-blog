### A107 · 手写数据库连接池

> 难度:★★★ | 标签:连接池, 并发, 编程题

**问**（笔试·编程题）：不依赖 SQLAlchemy 等库，手写一个线程安全连接池：`acquire(timeout)` / `release()`，支持最小连接数保活、借出超时、坏连接重建、空闲连接淘汰。写出实现并回答：为什么 acquire 里的等待必须用 Condition 而不是 sleep 轮询？

**答**：核心是「**计数上限 + 条件变量**」：池内维护空闲 deque 与借出计数，`acquire` 在池空且达上限时 `Condition.wait(timeout)` 挂起（被 `release` 的 `notify` 唤醒再抢锁），而不是 `sleep` 轮询——sleep 轮询有延迟毛刺且在归还瞬间唤醒不及时，Condition 把「等条件成立」这件事交给内核调度，无忙等。健康检查：借出前 ping 一次，坏则重建；空闲淘汰：后台线程定期关闭超过 max_idle 时间的连接但保留 min_size。所有状态变更必须持同一把锁（连接对象本身非线程安全）。

```python
import threading, time, logging
from collections import deque

class FakeConn:
    """演示用假连接；真实场景换成 DBAPI conn，ping() 失败抛异常。"""
    _id = 0
    def __init__(self):
        FakeConn._id += 1; self.id = FakeConn._id; self.dead = False
    def ping(self):
        if self.dead: raise ConnectionError("stale")
    def close(self): pass

class ConnPool:
    def __init__(self, factory, min_size=2, max_size=10, max_idle=60.0):
        self.factory, self.min_size, self.max_size, self.max_idle = factory, min_size, max_size, max_idle
        self._idle: deque = deque()
        self._out = 0                      # 借出数
        self._cv = threading.Condition()   # 唯一锁：idle/out/state 全在它保护下
        self._stop = False
        for _ in range(min_size):
            self._idle.append((time.monotonic(), factory()))
        self._reaper = threading.Thread(target=self._reap, daemon=True)
        self._reaper.start()

    def acquire(self, timeout: float = 5.0):
        deadline = time.monotonic() + timeout
        with self._cv:
            while True:
                if self._idle:                        # 有空闲：取最老的（LRU 头）
                    ts, conn = self._idle.popleft()
                    self._out += 1
                    try:
                        conn.ping()                   # 借出前健康检查
                    except Exception:
                        logging.warning("conn %s dead, rebuilding", conn.id)
                        conn.close()
                        conn = self.factory()
                    return conn
                if self._idle or self._out + len(self._idle) < self.max_size:
                    pass
                if self._out + len(self._idle) >= self.max_size and not self._idle:
                    remaining = deadline - time.monotonic()
                    if remaining <= 0 or not self._cv.wait(remaining):
                        raise TimeoutError(f"pool exhausted ({self._out} out)")  # wait 返回 False=超时
                    continue                          # 被 notify 唤醒，回循环重抢
                # 未达上限：持锁直接新建（避免并发重复建，锁保护计数）
                conn = self.factory()
                self._out += 1
                return conn

    def release(self, conn, broken=False):
        with self._cv:
            self._out -= 1
            if broken:
                conn.close()
                if len(self._idle) + 1 < self.min_size:
                    self._idle.append((time.monotonic(), self.factory()))  # 保活 min_size
            else:
                self._idle.append((time.monotonic(), conn))
            self._cv.notify()                         # 唤醒一个等连接的线程

    def _reap(self):
        while not self._stop:
            time.sleep(10)
            with self._cv:
                now = time.monotonic()
                while len(self._idle) > self.min_size and self._idle[0][0] < now - self.max_idle:
                    _, conn = self._idle.popleft()
                    conn.close()                      # 淘汰最老空闲，保留 min_size

if __name__ == "__main__":
    pool = ConnPool(FakeConn, min_size=1, max_size=2, max_idle=0.5)
    c1, c2 = pool.acquire(), pool.acquire()
    try:
        pool.acquire(timeout=0.2); assert False
    except TimeoutError:
        pass                                          # 池满借出超时 ✅
    pool.release(c1)
    c3 = pool.acquire()                               # notify 后立刻拿到
    assert c3 is c1
    c1.dead = True                                    # 模拟坏连接
    pool.release(c1)
    c4 = pool.acquire()
    assert c4.id != c1.id                             # 坏连接被重建 ✅
    pool.release(c4); pool.release(c2)
    print("acquire/release/timeout/rebuild/notify 全通过")
```

**追问**：1) 为什么取空闲连接取 deque 头而不是尾？——头是最久未用的（append 从尾进），先复用旧连接让新连接有时间自然进入可淘汰状态，配合 reaper 形成 LRU。2) `release` 一个不属于自己的连接怎么办？——真实池要在借出时给连接打 token/记账，release 校验归属，防止双重归还导致同一连接被两个线程持有（这是经典事故）。3) 借出期间连接被 reaper 淘汰？——reaper 只遍历 `_idle`，借出连接不在队列里，天然安全；这正是「idle/借出两个集合分开」的原因。

## 背诵要点
1. 连接池 = 空闲 deque + 借出计数 + 单把 Condition 锁；等待用 `wait(timeout)` 而非 sleep 轮询。
2. 借出前 ping 健康检查坏则重建；release 必须 notify；reaper 只淘汰空闲、保 min_size。
3. 双重归还是经典事故：借出要记账，归还校验归属。
