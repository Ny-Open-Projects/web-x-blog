### A210 · 配置多环境发布

> 难度:★★☆ | 标签:配置, 多环境, 审批

**问**（笔试·场景题）：配置改错环境（把生产配置当测试改了）——多环境发布怎么防误操作（环境显式选择/环境锁定/发布单关联），配置审批的分级（危险配置双人/普通配置单人/只读配置免审），「只读期」（大促冻结）配置的例外通道（紧急修复还是要改）怎么设计，环境间配置「继承+覆写」的结构怎么防「忘了在预发验证」？

**答**：① 防误操作三闸：**环境显式选择**（发布页强制选环境，默认禁选生产——选生产要额外确认+显示当前生产配置 diff）、**环境锁定**（冻结期生产只读，Q133 联动——例外走紧急通道带审批）、**发布单关联**（配置变更必须有变更单（A143），记录改了什么/为什么/影响面）。② 审批分级：危险配置（限流阈值/路由表/安全参数）双人审批；普通业务参数单人；纯展示类免审——分级表写死在配置元数据（每项配置声明自己的审批等级，不是发布时人判断）。③ 紧急通道：冻结期紧急修复 = L1 通道（A133 语义）——双人审批提速（异步→电话确认）+ 事后补记录——例外通道存在的意义是「冻结不阻塞救火」，但通道要窄（只有白名单的人能用）。④ 继承+覆写：环境配置 = 生产基线 + 环境覆写（diff 视图展示「本环境与生产的差异」）——预发验证的纪律：**覆写项变更必须在预发验证过**（继承项自动跟随生产，无需重复验证）——「忘了验证」的根因是「看不出哪些是我该验证的」，diff 视图消灭这个问题。

```python
# 全部标准库；demo 实现「继承+覆写 diff 视图 + 审批分级」
import time

BASE = {"timeout": 3.0, "rate_limit": 100, "region": "cn-north", "batch_size": 500}
OVERRIDES = {"staging": {"rate_limit": 30}, "dev": {"timeout": 30.0, "region": "local"}}
META = {"timeout": "single", "rate_limit": "double",   # 审批分级
        "region": "double", "batch_size": "single"}
FROZEN = True                                          # 大促只读期

def effective(env: str) -> dict:
    return {**BASE, **OVERRIDES.get(env, {})}

def diff_from_prod(env: str) -> dict:
    eff = effective(env)
    return {k: v for k, v in eff.items() if v != BASE[k]}

def publish(env: str, key: str, value, user: str, emergency: bool = False) -> str:
    if env == "prod" and FROZEN and not emergency:
        return "REJECT: 生产只读期（紧急走 L1 通道 emergency=True）"
    level = META.get(key, "double")
    if level == "double" and not emergency:
        return f"NEED-DUAL-APPROVAL: {key} 为危险配置（{level}），双人审批"
    return f"published {env}.{key}={value} by {user}"

def preflight(env: str) -> dict:
    """预发验证清单：只需验证覆写项（继承项自动跟随生产）。"""
    return {"verify_only_overrides": diff_from_prod(env),
            "inherited_follow_prod": {k: v for k, v in BASE.items()
                                      if k not in OVERRIDES.get(env, {})}}

if __name__ == "__main__":
    print("staging 生效:", effective("staging"))
    print("staging 与生产 diff（该验证的）:", diff_from_prod("staging"))
    assert diff_from_prod("staging") == {"rate_limit": 30}
    print("预发验证清单:", preflight("staging")["verify_only_overrides"])
    print(publish("prod", "rate_limit", 200, "li"))            # 只读期拦截 ✅
    print(publish("prod", "region", "cn-east", "li", emergency=True))  # 危险配置紧急通道需双人
    print(publish("staging", "timeout", 20.0, "li"))           # 单人配置直接发
    # 口径：环境显式选择+只读期+发布单关联；审批分级写进配置元数据；
    # 继承+覆写 diff 视图消灭「忘了验证哪些」。
```

**追问**：1) 为什么审批分级「写死在配置元数据」而不是发布时人判断？——人判断=每次发布都在重新定义风险（且赶工时会放水）；元数据声明让分级成为属性（评审时定级，变更时执行）——把判断前置到冷静时刻。2) 「继承项自动跟随生产」的风险？（提示：生产基线变了，预发继承后行为也变——预发验证过的覆写项没变但整体行为变了——所以继承变更也要触发预发的冒烟验证（继承不等于免测，只是免「重复配置管理」））3) 紧急通道的白名单怎么防滥用？（提示：白名单人少+每次紧急发布事后复盘（为什么走紧急）+ 紧急使用频率进报表（高频紧急=常态化绕过，治理信号））

## 背诵要点
1. 防误操作三闸：环境显式选择（生产加确认+diff）、只读期锁定（Q133 联动）、发布单关联（A143）。
2. 审批分级写死在配置元数据（危险双人/普通单人/展示免审）——判断前置到冷静时刻。
3. 继承+覆写结构：预发只验证覆写项（diff 视图），继承项跟随生产但触发冒烟；紧急通道白名单窄门。

## 复盘追问
1. 配置中心支持了「继承+覆写」，但某覆写项在生产忘了同步改，环境行为分裂——怎么发现？（提示：覆写项定期对账（各环境覆写值 vs 生产基线的偏离度报表）+ 覆写项变更必须写理由（无理由的漂移进待核清单）——覆写是有意差异，漂移是无意差异，台账区分）
2. 「只读期禁改生产配置」导致某团队绕过系统直接改了实例本地文件——治本是？（提示：实例配置必须从中心拉取（禁止本地手改生效——Q130 漂移治理）+ 本地手改进漂移检测自动收敛——绕过通道堵死后紧急通道成为唯一路径，纪律才成立）
