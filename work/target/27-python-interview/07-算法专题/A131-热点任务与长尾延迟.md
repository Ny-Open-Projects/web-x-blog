### A131 · 长尾延迟

> 难度:★★★ | 标签:长尾, P99, 性能

**问**（笔试·编程+场景题）：服务平均延迟 20ms，P99 却 800ms——为什么平均好 P99 差（长尾来源：GC/慢查询/重试放大/队列排队/背景任务），「对冲请求」（hedged request）怎么实现（同样请求发两份取先回），它的成本代价怎么控，「削减 P99」的手段清单按 ROI 排序是什么？

**答**：① 长尾来源分类：**周期性**（GC 暂停、日志轮转、缓存过期重建——定时触发，时间上可预测）、**资源竞争**（慢查询占连接、后台任务抢 CPU——Q122 混部同源）、**放大效应**（扇出请求中「最慢的下游」决定整体——p99 的乘法法则：扇出 N 个依赖整体 P99 ≈ 单依赖 P99 ×（与 N 相关的放大））、**队列排队**（负载超 80% 后延迟指数涨）。② 对冲请求：主请求发出 t 毫秒（如 P95 的 1.5 倍）未返回，向**另一个副本**发同样请求，取先到者——P99 显著下降（尾部慢副本被对冲救回）；代价：额外 QPS = 对冲率 × 流量（典型 +2-5%），必须配**幂等**（A120：非幂等操作对冲=重复执行）与**取消**（先到后取消慢请求）。③ ROI 排序：超时预算与快速失败（成本 0，砍掉无望等待）> 资源隔离（Q122）> 对冲请求（+2-5% 流量）> 全链路重写（最后手段）。

```python
# 全部标准库；demo 实现对冲请求 + 成本统计
import asyncio, random, time

class HedgedClient:
    def __init__(self, hedge_after: float = 0.15, replicas: int = 2):
        self.hedge_after, self.replicas = hedge_after, replicas
        self.stats = {"primary": 0, "hedged": 0, "extra_qps": 0}
    async def call(self, replica_latencies: list[float]) -> float:
        """副本延迟列表（模拟）；对冲：主请求超 hedge_after 后发第二份取先回。"""
        primary = replica_latencies[0]
        self.stats["primary"] += 1
        t0 = time.monotonic()
        main_task = asyncio.create_task(self._slow(primary))
        try:
            return await asyncio.wait_for(main_task, timeout=self.hedge_after)
        except asyncio.TimeoutError:
            self.stats["hedged"] += 1
            self.stats["extra_qps"] += 1
            hedge_task = asyncio.create_task(self._slow(replica_latencies[1] if len(replica_latencies) > 1 else primary))
            done, pending = await asyncio.wait({main_task, hedge_task},
                return_when=asyncio.FIRST_COMPLETED)
            for p in pending:                    # 先到后取消慢请求（防重复副作用需幂等）
                p.cancel()
            return next(iter(done)).result() if done else min(replica_latencies)
    async def _slow(self, latency: float):
        await asyncio.sleep(latency)
        return "ok"

def fanout_amplification(single_p99: float, deps: int = 3) -> float:
    """乘法法则：扇出 N 依赖的整体 P99 ≈ 单依赖 P99 × 放大（近似模拟）。"""
    # 至少一个依赖进入其尾部的概率随 N 上升 → 整体延迟被最慢者主导
    amplification = 1 + 0.3 * (deps - 1)
    return single_p99 * amplification

if __name__ == "__main__":
    random.seed(3)
    client = HedgedClient(hedge_after=0.15)
    results = []
    for _ in range(200):                     # 主副本慢(0.4s) vs 对冲副本快(0.05s)
        lat = random.choice([[0.4, 0.05], [0.05, 0.4]])
        results.append(asyncio.run(client.call(lat)))
    s = client.stats
    p99_before = 0.4                          # 无对冲时尾部 0.4s
    print(f"对冲统计: 主成功 {s['primary']} / 对冲救回 {s['hedged']}，额外 QPS {s['extra_qps']}")
    assert s["hedged"] > 0
    print(f"对冲前尾部 0.4s → 对冲后尾部 ≈ 0.15s（hedge_after 截断）")
    print(f"扇出放大: 单依赖 P99 50ms × 3 依赖 ≈ {fanout_amplification(0.05):.0f}s 量级提示")
    # ROI 口径：超时预算(0 成本) > 资源隔离 > 对冲(+2-5% 流量) > 重写；对冲必须幂等+取消。
```

**追问**：1) 对冲为什么必须配幂等与取消？——非幂等操作对冲=两个副本各执行一次（重复下单）；不取消慢请求=上游连接与下游计算都白耗——两者缺一对冲从优化变事故。2) 「重试」和「对冲」什么时候用哪个？——重试是**失败后**再来（延迟翻倍起），对冲是**等待中**并行再来（延迟几乎不变）；对冲用于读操作/幂等写，重试用于瞬时失败——高 P99 读场景对冲优。3) 削减 P99 先看什么数据？（提示：延迟分布分段归因（trace 分段，Q7519 同构）——先定位是自身计算、下游等待还是排队，再按 ROI 清单动手；盲改代码是最贵的手段）

## 背诵要点
1. 长尾四源：周期性（GC/轮转）、资源竞争、扇出放大（乘法法则）、队列排队（>80% 负载指数涨）。
2. 对冲请求 = hedge_after（P95×1.5）后发第二份取先回 + 取消慢者；必须幂等 + 额外流量 +2-5%。
3. ROI 排序：超时预算（0 成本）> 资源隔离 > 对冲 > 重写；先 trace 归因再动手。

## 复盘追问
1. 对冲让 P99 降了但「额外流量成本」超预算，怎么收敛？（提示：hedge_after 上调（只对冲最尾部）+ 按接口价值分级（核心接口对冲、长尾接口不对冲）+ 对冲率进容量账）
2. 全链路 P99 800ms，trace 显示自己只占 20ms，剩余 780ms 在等下游——你能做什么？（提示：扇出并发化（串行改并行）、下游超时预算+降级（A127）、对冲——自己这 20ms 不是重点，链路编排才是）
