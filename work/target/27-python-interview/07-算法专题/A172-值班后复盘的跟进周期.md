### A172 · 值班改进月度跟进

> 难度:★★☆ | 标签:改进项, 跟进, 治理

**问**（笔试·场景题）：每月值班产生 15 条改进项（告警降噪/手册补齐/自动化脚本），三个月后 80% 没做——改进项跟进怎么设计（月度评审会/owner 承诺/完成度量），「改进项堆积」的根因（与业务优先级竞争不过）怎么破（固定容量配比），「已完成但没用」的改进项（做了降噪告警还是多）怎么判定有效性（效果验证同 A144），改进项的「自动生成」有哪些来源可以自动化？

**答**：① 跟进机制：**月度评审会**（固定 30 分钟：过上月完成情况 + 排本月计划）+ owner 承诺制（每项有 owner+deadline，超期自动升级，A138 体系复用）——改进项与业务迭代用**固定容量配比**（如 20% 工时留给改进——没有固定配比，改进永远输给业务 deadline）。② 有效性判定：完成 ≠ 有效（A144 同构）——每个改进项定义「效果指标」（降噪项：告警数下降 N；手册项：新人按手册独立处置率）——月度评审带效果回看，「做了没用」的改进项检视方案而非追加投入。③ 自动生成来源：值班工单统计（高频告警自动生成降噪项）、手册缺失检测（无 runbook 的告警自动生成补齐项）、重复事故模式（同型 ≥3 次自动升级专项，A144）——能自动生成的不要靠人记。

```python
# 全部标准库；demo 实现「改进项跟进器」
import time

class ImprovTracker:
    def __init__(self, monthly_capacity: float = 32.0):  # 20% 工时配比
        self.items: list[dict] = []
        self.capacity = monthly_capacity
    def add(self, title: str, owner: str, hours: float, effect_metric: str,
            source: str = "manual"):
        self.items.append({"title": title, "owner": owner, "hours": hours,
                           "metric": effect_metric, "source": source,
                           "status": "open", "verified": False})
    def monthly_plan(self) -> tuple[list[dict], float]:
        """月度计划：按来源优先级装填固定容量（自动生成项优先）。"""
        auto = sorted((i for i in self.items if i["source"] == "auto"),
                      key=lambda x: -x["hours"])
        manual = [i for i in self.items if i["source"] == "manual" and i["status"] == "open"]
        plan, used = [], 0.0
        for i in auto + manual:
            if i["status"] != "open" or used + i["hours"] > self.capacity:
                continue
            plan.append(i); used += i["hours"]
            i["status"] = "planned"
        return plan, self.capacity - used
    def verify_effect(self, title: str, metric_achieved: bool) -> str:
        item = next(i for i in self.items if i["title"] == title)
        if not metric_achieved:
            item["status"] = "reopened"                # 做了没用：回炉（A144 同构）
            return "REOPENED: 效果指标未达成，方案回炉"
        item["status"], item["verified"] = "done", True
        return "VERIFIED: 效果指标达成"

if __name__ == "__main__":
    tr = ImprovTracker(monthly_capacity=16)
    tr.add("top5 告警降噪", "zhang", 8, "告警数 -50%", source="auto")   # 自动生成
    tr.add("redis 手册补齐", "li", 4, "新人独立处置率", source="auto")
    tr.add("重构补偿逻辑", "wang", 24, "缺陷率", source="manual")       # 超容量
    plan, remaining = tr.monthly_plan()
    print("月度计划:", [(p['title'], p['hours']) for p in plan], "| 剩余容量:", remaining)
    assert len(plan) == 2 and "重构补偿逻辑" not in [p['title'] for p in plan]
    r = tr.verify_effect("top5 告警降噪", metric_achieved=False)
    assert r.startswith("REOPENED")
    print("效果验证:", r, "（做了没用回炉）✅")
    # 口径：固定容量配比破「改进输给业务」；完成≠有效（效果指标验证）；
    # 自动生成来源：工单统计/手册缺失/重复事故。
```

**追问**：1) 为什么「固定容量配比」能破「改进输给业务」？——不配比时改进项与业务需求在同一池竞争（业务永远更急）——配比是**结构性承诺**（20% 工时天然属于改进，业务排不进来），类似「还债配比」（Q140 技术债同构）——结构优于意志。2) 「做了没用」的改进项回炉后怎么避免反复投入？（提示：回炉时检视方案假设（降噪项没降告警=根因判断错？手段错了？）+ 二次投入需新方案（不是加码原方案）——回炉是重新设计不是重新执行；两次回炉的改进项升级讨论或豁免）3) 哪些改进项「不该自动生成」？（提示：需要业务/架构决策的（不是执行层面的）——自动生成适合「明确的、有标准解的」（降噪/补手册），决策类进人工评审——自动化的边界在「解法已知」）

## 背诵要点
1. 跟进机制：月度评审会 + owner 承诺 + **固定容量配比**（20% 工时）——结构优于意志。
2. 完成 ≠ 有效：每项定义效果指标，月度评审带效果回看，「做了没用」回炉重新设计。
3. 自动生成三来源：工单统计（降噪）/手册缺失检测（补齐）/重复事故模式（专项）——自动生成限「解法已知」项。

## 复盘追问
1. 月度评审会开了两次变成「念清单」，怎么保持评审质量？（提示：评审聚焦「效果验证与方案争议」（自动过掉的 Open 项不发一言）+ 数据前置（效果指标在会前出）——会议时间只花在「需要讨论的」；清单性内容书面流转）
2. 20% 容量配比在业务高压期被挤占（老板要求全投业务），怎么守？（提示：配比协议是事先与老板对齐的（含高压期缩减条款：高压期降到 10%，事后补足）——「绝对不变」不现实，「变化有据可查」是底线——配比写进团队章程并留执行记录）
