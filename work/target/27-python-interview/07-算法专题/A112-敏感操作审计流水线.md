### A112 · 敏感操作审计流水线

> 难度:★★★ | 标签:审计, 哈希链, 合规

**问**（笔试·编程+场景题）：金融系统要求「敏感操作日志 180 天不可篡改」——设计审计流水线：每条审计记录包含什么、哈希链怎么构造（断链怎么检测）、外部锚点（时间戳服务/对象存储 WORM）怎么用、审计系统的自身权限怎么隔离（谁能删审计日志？答案是没人）。

**答**：① 记录六要素：`who/when/what(动作+对象)/result/before→after(数据快照)/trace_id`——审计的价值在「能回答谁在什么时候改了什么、改成什么样」，缺 before/after 的审计等于没做。② **哈希链**：每条记录含 `prev_hash`（上一条哈希），`entry_hash = H(prev_hash + payload)`——改任何一条，其后所有链全断；断链检测 = 顺序重算比对（批量校验任务每日跑）。③ **外部锚点**：每 N 条把链头哈希写进 WORM 对象存储（一次写入永久只读）或 RFC 3161 时间戳服务——内部 DB 被攻破也无法伪造锚点后的历史。④ 权限隔离：审计写入走独立账号（应用只有 INSERT 权限）、无 UPDATE/DELETE；审计查询独立服务；运维删日志 = 物理不可行（WORM）+ 流程拦截（变更审批双签）。⑤ 删除场景例外：合规要求超期销毁（180 天后）用**一次性销毁任务 + 销毁凭证记录**（销毁动作本身也被审计）。

```python
# 全部标准库；demo 实现哈希链 + 断链检测 + 锚点
import hashlib, json, time

class AuditChain:
    def __init__(self):
        self.entries: list[dict] = []
        self.prev = "GENESIS"
    def append(self, who: str, action: str, before=None, after=None) -> dict:
        entry = {"seq": len(self.entries), "ts": time.time(), "who": who,
                 "action": action, "before": before, "after": after,
                 "prev_hash": self.prev}
        entry["hash"] = hashlib.sha256(
            json.dumps(entry, sort_keys=True, ensure_ascii=False).encode()).hexdigest()[:16]
        self.entries.append(entry)
        self.prev = entry["hash"]
        return entry
    def anchor(self) -> str:
        """外部锚点：把当前链头哈希交给 WORM 存储（返回锚点凭证）。"""
        return f"WORM:{self.prev}"
    def verify(self, anchor: str | None = None) -> list[int]:
        """断链检测：重算哈希比对；锚点校验链头未被回退。"""
        broken = []
        expect_prev = "GENESIS"
        for e in self.entries:
            payload = {k: v for k, v in e.items() if k != "hash"}
            h = hashlib.sha256(json.dumps(payload, sort_keys=True,
                             ensure_ascii=False).encode()).hexdigest()[:16]
            if e["prev_hash"] != expect_prev or e["hash"] != h:
                broken.append(e["seq"])
                expect_prev = e["hash"]       # 从断点继续检（报告全部断点）
            else:
                expect_prev = e["hash"]
        if anchor and self.entries and not anchor.endswith(self.entries[-1]["hash"]):
            broken.append(-1)                 # 锚点不匹配 = 链头被回退/截断
        return broken

if __name__ == "__main__":
    ch = AuditChain()
    ch.append("ops1", "update_balance", before=100, after=200)
    ch.append("ops1", "grant_role", after={"user": "bob", "role": "admin"})
    ch.append("ops2", "export_audit", after={"rows": 3})
    assert ch.verify() == []
    print("完整链校验通过；锚点:", ch.anchor())
    tampered = ch.entries[1]["after"]["role"] = "superadmin"   # 模拟篡改
    broken = ch.verify()
    assert 1 in broken and 2 in broken, "篡改后其后的链必须全断"
    print(f"篡改 seq=1 → 断链检测到: {broken}（含后续全部）✅")
    # 口径：审计系统自身权限 = 应用 INSERT-only、无 UPDATE/DELETE、
    # 锚点进 WORM；「销毁凭证」记录销毁动作本身（审计审计者）。
```

**追问**：1) 哈希链和 Merkle 树怎么选？——链 O(n) 顺序校验（全量校验自然）；Merkle 树 O(log n) 单条证明（对第三方证明「某条未被改」不暴露全量）——外部审计对账用 Merkle，内部防篡改用链即可。2) 高并发写入的链怎么保序？——审计入口单点序列化（Kafka 分区单消费者）或网关集中签名；多实例并发会断链——「链的顺序性」要求写入路径收敛，这是哈希链方案的架构约束。3) before/after 快照太大怎么办？——全量快照换字段级 diff（只记变更字段与旧值），超大对象存哈希+引用；审计粒度与存储成本的平衡点在「能否重建当时状态」。

## 背诵要点
1. 审计六要素含 before/after 快照——「能重建当时状态」是审计的价值底线。
2. 哈希链 = H(prev_hash + payload)，改一条断全链；断链检测顺序重算；外部锚点（WORM/时间戳）防内部 DB 被攻破后伪造。
3. 权限隔离：应用 INSERT-only、销毁走一次性任务且销毁动作本身入链。

## 复盘追问
1. 产品的「删除用户数据」合规要求（GDPR）与审计不可篡改冲突吗？（提示：不冲突——审计记录存「数据哈希与操作」，不存个人数据本体；合规删除删业务库，审计链保留操作痕迹但不含敏感内容）
2. 运维说「日志磁盘满了先删点老的」，正确响应？（提示：拒绝 + 归档到 WORM 冷存储 + 容量扩容流程；审计存储是合规承诺，满容量是容量规划失误不是删除理由）
