### A189 · 变更窗口自动化

> 难度:★★☆ | 标签:变更窗口, 冲突检测, 排期

**问**（笔试·编程+场景题）：三个团队都预约了「周五 20:00-22:00」变更同一依赖——变更窗口系统怎么自动检测冲突（同依赖/同时段/影响面重叠三类），预约的「资源模型」（窗口本身是共享资源——容量限制），「冲突时自动改期」的推荐算法（给冲突方推荐次优窗口），预约信息与发布系统/监控的联动（变更期监控自动增强）怎么闭环？

**答**：① 冲突三类检测：**同依赖**（都动 DB/order 服务——变更单的依赖声明 diff）、**同时段**（窗口重叠）、**影响面重叠**（Q123 爆炸半径：两个变更的受影响用户群重叠）——三类命中任一即冲突告警（预约时不阻止但强提示+要求双方确认互不影响）。② 窗口资源模型：每小时窗口容量 = 可并发变更数（同依赖=1，独立=3）——预约即占容量，容量满自动推荐次优窗口（同 A117 排队优先级语义）。③ 自动改期推荐：冲突时按「变更的约束（deadline/依赖可用性）+ 窗口余量」推荐次优窗口（约束满足的简化版）——推荐不强制（团队可坚持原窗口但需双方书面确认互不影响）。④ 监控联动闭环：变更预约自动触发「变更期监控增强」（该服务+下游的指标大盘自动置顶+告警阈值收紧——变更期是高风险期，监控密度应随变更而增）——预约系统成为「变更治理的总枢纽」。

```python
# 全部标准库；demo 实现「变更窗口冲突检测 + 次优推荐」
from collections import defaultdict

class ChangeWindow:
    def __init__(self, hourly_capacity: int = 3):
        self.capacity = hourly_capacity
        self.booked: dict[str, list] = defaultdict(list)   # slot -> [变更]
    def conflicts(self, change: dict, booked_items: list) -> list[str]:
        out = []
        for other in booked_items:
            if set(change["deps"]) & set(other["deps"]):
                out.append(f"同依赖冲突: {other['name']}（{other['team']}）")
            if change["affected_groups"] & other.get("affected_groups", set()):
                out.append(f"影响面重叠: {other['name']}")
        return out
    def book(self, change: dict, slot: str) -> tuple[bool, str]:
        items = self.booked[slot]
        if len(items) >= self.capacity:
            return False, f"窗口容量已满（{self.capacity}），推荐次优窗口"
        conflicts = self.conflicts(change, items)
        if conflicts:
            return False, "冲突: " + "; ".join(conflicts) + " → 仍可预约但需双方书面确认"
        self.booked[slot].append(change)
        return True, f"预约成功（变更期监控自动增强: {change['deps']}）"

def suggest_slots(change: dict, candidate_slots: list[str],
                  booked: dict[str, list], cap: int = 3) -> list[str]:
    """次优窗口推荐：无冲突且有容量的槽位按余量排序。"""
    ok = []
    for slot in candidate_slots:
        if len(booked.get(slot, [])) < cap and not ChangeWindow().conflicts(change, booked.get(slot, [])):
            ok.append((slot, cap - len(booked.get(slot, []))))
    return [s for s, _ in sorted(ok, key=lambda x: -x[1])]

if __name__ == "__main__":
    cw = ChangeWindow(hourly_capacity=2)
    cw.book({"name": "DB 升级", "team": "dba", "deps": ["db"],
             "affected_groups": set()}, "fri-20")
    ok, msg = cw.book({"name": "订单重构", "team": "order", "deps": ["db"],
                       "affected_groups": set()}, "fri-20")
    assert not ok and "同依赖冲突" in msg
    print("冲突检测:", msg)
    ok2, msg2 = cw.book({"name": "前端改版", "team": "fe", "deps": ["cdn"],
                         "affected_groups": set()}, "fri-20")
    assert ok2                                          # 无依赖重叠可并行
    print("无冲突并行:", msg2)
    slots = suggest_slots({"deps": ["db"], "affected_groups": set()},
                          ["fri-20", "fri-21", "sat-20"], cw.booked, cap=2)
    print("次优推荐:", slots)
    assert slots[0] in ("fri-21", "sat-20")
    # 口径：三类冲突检测（同依赖/同时段容量/影响面）；冲突可预约但需双方确认；
    # 预约触发变更期监控增强——预约系统是变更治理枢纽。
```

**追问**：1) 为什么冲突了还「允许预约」而只是强提示？——依赖重叠的变更可能是「配套变更」（DB 升级 + 订单服务适配——本来就要一起做）——系统无法判断「冲突」还是「配套」，把判断交给双方书面确认：配套则协同编排，非配套则改期——自动化检测+人工判断语义，纯自动会挡掉合法配套。2) 「变更期监控自动增强」具体增强什么？（提示：受影响服务+下游的大盘置顶、告警阈值收紧（变更期更敏感）、值班注意力标记（变更清单进交接）——变更期风险高，观测密度应与风险同升）3) 窗口容量的「每小时 3 个」怎么定？（提示：容量=值班/验证资源的并行处理能力（每变更需人盯+验证），不是「服务器能同时改几台」——窗口容量由人的验证带宽决定，Q6063 压测定容的同构思路）

## 背诵要点
1. 冲突三类：同依赖/窗口容量/影响面重叠——检测自动化，判断（冲突 vs 配套）留人工书面确认。
2. 窗口是共享资源：容量由「人的验证带宽」决定，满则推荐次优窗口（余量排序）。
3. 预约闭环：触发变更期监控增强（大盘置顶+阈值收紧）——预约系统是变更治理总枢纽。

## 复盘追问
1. 冲突检测全自动化后，团队「抢窗口」（提前一周占坑）怎么治理？（提示：预约有效期（临近 48h 未确认释放）+ 高峰期配额（每团队每周 N 窗）+ 优先级（紧急变更通道）——窗口资源与 Q117 调度器同构，抢坑治理同理）
2. 变更期监控增强了但事故还是没提前发现（增强的指标不对），怎么改进？（提示：增强指标从「变更内容推导」（改了支付逻辑→支付相关指标增强）而非通用指标全开——变更单的 deps 声明要包含「影响什么业务指标」——预约系统的 deps 字段语义化是联动质量的前提）
