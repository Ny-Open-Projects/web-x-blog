### A128 · 灰度分桶设计

> 难度:★★☆ | 标签:灰度, 分桶, 实验设计

**问**（笔试·编程+场景题）：灰度 10% 上线新版本——「用户这次进实验组下次进对照组」会发生什么问题（体验抖动与数据污染）？分桶键怎么设计（user_id 哈希为什么比会话哈希稳），「队列效应」（同批用户始终是小白鼠）怎么破，多实验并行（分层实验）的正交怎么保证？

**答**：① 用户稳定性：同一用户在实验期内必须**恒定**在实验组——否则体验抖动（今天新版明天旧版）+ 数据污染（组间迁移使效应估计有偏）。分桶键 = `hash(flag_id + user_id) % 100`（Q118 同构：带 flag_id 防小白鼠固定；user_id 比会话哈希稳——会话断了重连就换组）。② 队列效应：单一分桶函数下，永远同一批用户先进 10% 桶——这批人如果本身活跃度/付费意愿异常，实验结论系统性偏差。破法：**分桶键加盐分层**（按实验周期换盐：第二期实验用户重新随机）或**多桶域**（实验平台维护多套独立哈希域，轮换使用）。③ 分层实验正交：多个实验同时跑（推荐算法实验 × 支付按钮实验），若共用一个分桶函数，实验组的组合不是随机分布（相关）——分层架构（Google/Twitter 经典）：每个实验层独立哈希（盐=层名），用户在每层独立随机——**层间正交**（跨层实验因子随机组合），同层互斥（同层只能跑一个实验）。

```python
# 全部标准库；demo 实现「稳定分桶 + 换盐破队列 + 分层正交」
import hashlib, random
from collections import Counter

def bucket(flag_id: str, user_id: str, pct: int, salt: str = "") -> bool:
    """稳定分桶：带 flag_id（防固定小白鼠）与可选盐（破队列效应）。"""
    h = int(hashlib.md5(f"{flag_id}:{salt}:{user_id}".encode()).hexdigest()[:8], 16)
    return h % 100 < pct

def stability_check(pct: int = 30, n: int = 200):
    """同用户 30 次评估必须恒定。"""
    user = "u-stable"
    results = {bucket("dark_mode", user, pct) for _ in range(30)}
    assert len(results) == 1
    return results.pop()

def queue_effect_demo():
    """不换盐：同一批用户始终先进桶；换盐：重洗。"""
    users = [f"u{i}" for i in range(1000)]
    phase1 = [u for u in users if bucket("exp1", u, 10)]
    phase2_same = [u for u in users if bucket("exp1", u, 10)]
    phase2_resalt = [u for u in users if bucket("exp1", u, 10, salt="phase2")]
    overlap = set(phase1) & set(phase2_resalt)
    print(f"不换盐重跑: 小白鼠 100% 相同（{len(phase1)} 人）；换盐后与第一期重叠 {len(overlap)} 人（≈10%）")
    assert set(phase1) == set(phase2_same)
    return overlap

def layered_experiments(user_id: str, layers: dict[str, int]) -> dict:
    """分层实验：每层独立哈希（盐=层名），层间正交。"""
    return {name: bucket(name, user_id, pct, salt=f"layer:{name}")
            for name, pct in layers.items()}

if __name__ == "__main__":
    random.seed(1)
    assert stability_check() is True or stability_check() is False
    print("分桶稳定性（同用户恒定）✅")
    queue_effect_demo()
    # 分层正交验证：推荐层与支付层的分组相关性应接近 0
    n = 4000
    rec = [layered_experiments(f"u{i}", {"rec": 50, "pay": 50}) for i in range(n)]
    both = sum(1 for r in rec if r["rec"] and r["pay"])
    expect = 0.25 * n
    assert abs(both - expect) / expect < 0.1, "层间应正交（组合比例≈25%）"
    print(f"分层正交: rec∩pay 同时命中 {both}/{n}（期望 {expect:.0f}，偏差 <10%）✅")
    # 口径：稳定分桶（flag_id+user_id）+ 换盐破队列 + 层间正交同层互斥。
```

**追问**：1) 为什么「会话哈希」做分桶键会破坏实验？——会话生命周期短（一天多次会话），用户跨会话换组：体验抖动 + 「人均指标」的分母漂移——除非实验就是会话级的（如搜索排序单次会话效果），否则必须用户级分桶。2) 换盐的代价是什么？——实验期内换盐=重新洗组（同 peeking 效应：组间迁移污染已收集数据）；换盐只发生在**实验期之间**（一期结束二期开始），期内绝对不动。3) 分层正交的数量上限？（提示：理论上无限层，实践上层数多时每层的「剩余流量」碎片化（同层多实验占满 100% 后新实验排队）——层容量规划是实验平台的调度问题）

## 背诵要点
1. 灰度分桶键 = hash(flag_id + user_id)：用户稳定（体验不抖动）+ 独立分桶（防固定小白鼠）。
2. 队列效应破法 = 实验期之间换盐重洗；实验期内绝不换盐（组间迁移污染数据）。
3. 分层实验：每层独立哈希（盐=层名）→ 层间正交、同层互斥——多实验并行的行业标准。

## 复盘追问
1. 实验报告显示新版本效果好，但小白鼠用户投诉功能「一会有一会没有」，实验还能信吗？（提示：不能——分桶不稳定使效应估计有偏且体验伤害已发生；先修分桶再重跑实验）
2. 「新用户永远进实验组」的系统性偏差怎么检测？（提示：分组与注册日期的交叉分析（新注册用户实验占比异常）——分桶函数对新 ID 空间偏斜，用分布检验发现）
