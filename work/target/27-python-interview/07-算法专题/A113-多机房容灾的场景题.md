### A113 · 多机房容灾场景题

> 难度:★★★ | 标签:容灾, RTO/RPO, 场景题

**问**（笔试·场景题）：同城双机房 + 异地灾备三地架构——机房 A 整体断电，RTO/RPO 各是多少怎么算（数据同步方式决定 RPO、切换流程决定 RTO）？「脑裂」怎么防（双写风险），切换演练怎么做才敢真切（影子演练 vs 真切换）？

**答**：① **RPO 由数据复制决定**：异步复制（秒级延迟）→ RPO≈复制延迟（可能丢秒级数据）；半同步 → RPO≈0 但写延迟升；同城双机房专线延迟 <2ms 通常可半同步，异地专线 30ms+ 只能异步——标准组合：**同城半同步（RPO=0）+ 异地异步（RPO=分钟级）**。② **RTO 由切换流程决定**：探测（故障确认，30-60s 防误切）→ 决策（自动/人工）→ 数据切换（promote 从库）→ 流量切换（DNS/网关）→ 应用恢复——全链路自动化 RTO 分钟级，人工决策 RTO 十分钟级。③ **脑裂防护**：旧主复活必须被隔离（fencing：旧主只读化、VIP 摘除）——判死依据用**多数派仲裁**（3 机房至少 2 个认为主挂了才切，Quorum 机制），绝不能双机房各 1 票互切。④ **演练分级**：影子演练（把流量复制到灾备机房跑，不动真实数据）每季度；**真切换**（计划内主动切到灾备再切回）每年——没真切过的容灾等于没有容灾（切换脚本从来没在真实负载下跑过）。

```python
# 全部标准库；demo 实现 Quorum 仲裁 + 切换状态机（RTO 计时）
import time

class QuorumArbiter:
    """3 机房多数派仲裁：≥2 票判主死才允许切换（防脑裂）。"""
    def __init__(self, sites: list[str]):
        self.sites = sites
        self.votes: dict[str, bool] = {}
    def vote(self, site: str, master_alive: bool):
        self.votes[site] = master_alive
    def can_failover(self) -> tuple[bool, str]:
        dead_votes = sum(1 for v in self.votes.values() if not v)
        if dead_votes >= (len(self.sites) + 1) // 2:
            return True, f"多数派确认主挂（{dead_votes}/{len(self.sites)} 票）"
        return False, f"未达多数派（{dead_votes}/{len(self.sites)} 票）——拒绝切换防脑裂"

class Failover:
    """切换状态机：detect→decide→data→traffic→recover，各步计时算 RTO。"""
    STEPS = ["detect(30s)", "decide(10s)", "data_promote(60s)", "traffic(30s)", "recover(60s)"]
    def __init__(self):
        self.t0 = None
        self.log = []
    def execute(self):
        self.t0 = time.monotonic()
        for step in self.STEPS:
            time.sleep(0.01)                  # demo 加速
            self.log.append((step, time.monotonic() - self.t0))
        return self.log, self.log[-1][1]

if __name__ == "__main__":
    arb = QuorumArbiter(["A", "B", "C"])
    arb.vote("A", False); arb.vote("B", False); arb.vote("C", True)
    ok, why = arb.can_failover()
    assert ok, why
    print("仲裁:", why)
    arb2 = QuorumArbiter(["A", "B"])          # 双机房互票灾难场景
    arb2.vote("A", False); arb2.vote("B", True)
    ok2, why2 = arb2.can_failover()
    print("双机房分裂场景:", why2, "→ 教训：仲裁必须奇数节点/独立仲裁方")
    assert not ok2
    fo = Failover()
    log, total = fo.execute()
    for step, t in log:
        print(f"  {step} @ {t*1000:.0f}ms")
    print(f"RTO 演练口径: {total*190:.0f}s（真实比例），全程自动化；人工决策 RTO ×3~10")
    # 口径：同城半同步 RPO=0、异地异步 RPO 分钟级；切换脚本必须每年真切验证。
```

**追问**：1) 为什么仲裁节点必须独立于数据机房？——仲裁在机房 A 而主库也在 A：A 半挂（网络抖动但仲裁活着）会出现「A 认为主活着、外部认为死了」的矛盾视图；独立第三方仲裁（云上单独 region 或 witness 节点）消除共谋故障。2) 切换后的「回切」比切换更危险？——回切要反向同步（灾备期间新写的数据回流原主库），数据量与冲突风险更高；标准做法：回切当成一次新的完整切换流程做（含数据校验），不是简单切回。3) 应用侧怎么配合 RPO？——重要写操作带幂等键（客户端重试跨机房都能兜住）、切换窗口读降级（读到旧数据可接受性按业务分级），参考 A102/Q6512。

## 背诵要点
1. RPO 由复制方式定（同城半同步=0、异地异步=分钟级）；RTO 由切换流程定（自动分钟级、人工十分钟级）。
2. 脑裂防护 = Quorum 多数派仲裁（独立第三方仲裁节点）+ 旧主 fencing（只读化/VIP 摘除）。
3. 容灾演练分级：影子演练季度、真切换年度——没真切过的容灾等于没有。

## 复盘追问
1. 灾备机房平时流量为 0，切换后性能崩（冷机问题）怎么防？（提示：灾备常态承载部分真实流量（双活 5-10%），或定期压测灾备容量——冷机切换是 RTO 事故的经典形态）
2. DNS 切换的 TTL 边界怎么处理？（提示：TTL 提前调短（切换前 24h 降到 60s）、客户端缓存无视 TTL 的（HTTP 连接池重连）要应用侧探测兜底）
