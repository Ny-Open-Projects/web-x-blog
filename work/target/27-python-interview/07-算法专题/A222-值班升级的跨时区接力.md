### A222 · 跨时区值班接力

> 难度:★★★ | 标签:follow-the-sun, 跨时区, 值班

**问**（笔试·编程+场景题）：北京团队下班时故障未解决——「follow-the-sun」接力（欧洲团队接手）怎么设计：接力的「交接包」（当前状态/已尝试/怀疑方向/下一步建议四要素），接力后「原团队是否下线」（接力≠甩手——原团队的待命义务），接力失败的兜底（欧洲团队也修不了——亚洲团队重新上线？），接力链的时区拓扑设计（三地怎么轮转不出现「所有时区都在夜间」）。

**答**：① 交接包四要素：**当前状态**（故障现象与最新指标快照）、**已尝试**（动作清单+各自结果——避免接手人重试已失败路径）、**怀疑方向**（根因假设排序——接力者从最高概率假设开始，不从零开始）、**下一步建议**（接手者优先做什么+需要什么权限/资源）——四要素让接力者「从 80% 进度开始」而非从零。② 接力≠甩手：原团队**待命义务**（接力后 2 小时内可被咨询（async 响应即可——新时区是白天，原时区是深夜））——完全下线会让接力者在深夜独自面对「交接包没写到的坑」；待命是接力质量的后盾。③ 兜底：接力者也修不了 → 原团队重新上线（凌晨爬起来）——「接力失败重上线」的触发条件预定义（接力后 30 分钟无进展即回叫原团队）——终极兜底永远是「最有上下文的人」。④ 时区拓扑：三地（北京/欧洲/美西）轮转要保证**任意时刻至少一个「白天的团队」在岗**（24h 覆盖）且**接力的交接窗是双方共同白天**（北京 18:00 = 欧洲 12:00 = 美西 3:00——美西缺席交接）——三地轮转设计：每次接力在「双方共同白天」进行，美西与欧洲的交接用异步（交接包+次日确认）。

```python
# 全部标准库；demo 实现「follow-the-sun 接力链」
import time

def handoff_pack(state: str, tried: list[str], hypotheses: list[str],
                 next_step: str) -> dict:
    """交接包四要素：状态/已尝试/怀疑方向/下一步。"""
    return {"state": state, "tried": tried, "hypotheses": hypotheses,
            "next_step": next_step}

class RelayChain:
    def __init__(self, teams: list[dict]):   # [{"name", "tz", "work_hours"}]
        self.teams = teams
    def best_relay_target(self, now_utc_hour: int) -> dict:
        """接力目标 = 接力时刻处于「白天工作时间」的团队。"""
        for t in self.teams:
            s, e = t["work_hours"]
            if s <= now_utc_hour < e:
                return t
        return {"name": "none", "note": "无团队在白天 → 异步交接包+次日确认"}
    def standby_obligation(self, handoff_time: float) -> str:
        return "原团队待命义务：接力后 2 小时内 async 响应咨询"
    def failover_rule(self, relay_minutes: float = 30) -> str:
        return f"接力后 {relay_minutes} 分钟无进展 → 回叫原团队重新上线"

if __name__ == "__main__":
    pack = handoff_pack(
        state="DB 锁等待持续，错误率 3%",
        tried=["回滚发布无效", "kill 长事务 2 个"],
        hypotheses=["索引失效（概率高）", "外部批量任务（待查）"],
        next_step="检查 pg_stat_activity 的锁链，考虑强杀")
    print("交接包:", pack["hypotheses"])
    teams = [{"name": "beijing", "tz": "UTC+8", "work_hours": (1, 10)},
             {"name": "europe", "tz": "UTC+1", "work_hours": (8, 17)}]
    relay = RelayChain(teams)
    target = relay.best_relay_target(now_utc_hour=11)   # 北京 19:00 / 欧洲 12:00
    print("接力目标:", target["name"], "| 待命:", relay.standby_obligation(0))
    print("兜底:", relay.failover_rule())
    assert target["name"] == "europe"
    # 口径：交接包四要素让接力者从 80% 进度开始；原团队待命 2h；
    # 接力 30min 无进展回叫原团队；接力窗=双方共同白天。
```

**追问**：1) 为什么交接包「怀疑方向」要素关键？——没有怀疑方向，接力者从零排查（重复已失败的路径浪费小时）；按概率排序的假设让接力者从最高概率路径开始——这是「最有价值的信息」，因为它承载了原团队数小时的排查认知。2) 「接力失败回叫原团队」对原团队的疲劳影响？（提示：深夜回叫是真实的疲劳成本——对冲：回叫只在「接力确认失败」时（不是随时可叫）+ 回叫后原团队只做「决策支持」（不重新执行）+ 当周其值班负担减免（Q221 负担口径）——机制保护回叫的可持续性）3) Follow-the-sun 模式的适用门槛？（提示：需要 24h 有团队在岗（多时区团队）+ 交接包纪律成熟（Q184/A215 交接能力）+ 故障可异步接力（不是必须原团队现场操作）——单时区团队先建交接能力再考虑 FTS）

## 背诵要点
1. 交接包四要素：当前状态/已尝试（防重复失败路径）/怀疑方向（概率排序）/下一步建议——接力者从 80% 进度开始。
2. 接力 ≠ 甩手：原团队待命 2 小时（async 响应）；接力 30 分钟无进展回叫原团队（触发条件预定义）。
3. 时区拓扑：任意时刻至少一个白天团队在岗 + 接力窗=双方共同白天；三地轮转美西段用异步交接。

## 复盘追问
1. 交接包写得很好但接手团队「语言不通」（中文交接包给欧洲团队），怎么解决？（提示：交接包模板结构化字段（状态/已尝试/怀疑方向固定字段）+ 关键字段双语（试运行一段时间校准术语表）——结构化降低语言要求（Q215 同构），自由文本部分靠共同语言或翻译）
2. Follow-the-sun 跑了三个月，交接包质量参差（有的详细有的敷衍），怎么治？（提示：交接包质量抽查（接力者对交接包评分：信息完整度）+ 评分低的团队 refresher + 交接包模板强制字段（缺字段无法提交）——质量用接力者反馈闭环（A144 验证同构））
