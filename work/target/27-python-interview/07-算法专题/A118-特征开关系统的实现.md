### A118 · 特征开关系统

> 难度:★★☆ | 标签:feature flag, 评估引擎, 技术债

**问**（笔试·编程+场景题）：实现特征开关评估引擎：布尔开关、百分比灰度（同用户稳定）、白名单、按属性 targeting（ vip_tier>=2 → 开）；评估的短路顺序怎么定，「开关债务」（几百个没人敢删的旧开关）怎么治理——删除一个开关的完整流程是什么？

**答**：① 评估引擎的规则优先级：`白名单 → 属性 targeting → 百分比灰度 → 默认值`（具体规则先于统计规则），单点短路返回——评估要**纯函数化**（同输入同输出、无 IO），配置快照一次拉取（防半改状态）。② 百分比灰度：用户 ID 哈希到 [0,100) 落桶（`hash(flag_id + user_id) % 100 < pct`——**键里带 flag_id**：不同开关的灰度桶分布独立，避免同一批用户总当小白鼠）。③ 开关债务治理：开关生命周期四阶段（实验期 → 全量 → 稳定 → 应删），治理靠**台账自动化**：每个开关带 `created_at/owner/intent（实验目的）/expiry`，过期未清理自动提醒 owner，90 天未动即进「待删清单」；删除流程 = 代码里移除评估调用（确认所有分支行为一致）→ 删配置项 → 删评估代码——**先删代码引用再删配置**（与 Q6017 contract 阶段同构）。

```python
# 全部标准库；demo 实现评估引擎（优先级短路 + 带旗标哈希灰度 + 债务台账）
import hashlib, time

def flag_hash(flag_id: str, user_id: str) -> int:
    """键含 flag_id：不同开关独立分桶，避免小白鼠固定化。"""
    return int(hashlib.md5(f"{flag_id}:{user_id}".encode()).hexdigest()[:8], 16) % 100

class FlagEngine:
    """纯函数评估：白名单 > targeting > 百分比 > 默认。"""
    def __init__(self, config: dict):
        self.config = config                  # 快照：一次拉取，评估无 IO
    def evaluate(self, flag_id: str, user: dict) -> bool:
        cfg = self.config.get(flag_id)
        if not cfg:
            return False                      # 默认拒绝（fail-closed）
        if user["id"] in cfg.get("whitelist", []):
            return True                       # 层1 白名单
        for rule in cfg.get("targeting", []): # 层2 属性条件（白名单表达式风格）
            if all(user.get(k) == v or (isinstance(v, list) and user.get(k) in v)
                   for k, v in rule.items()):
                return True
        pct = cfg.get("percent", 0)           # 层3 百分比灰度
        if flag_hash(flag_id, user["id"]) < pct:
            return True
        return cfg.get("default", False)      # 层4 默认值

class FlagLedger:
    """开关台账：过期自动进待删清单。"""
    def __init__(self, expiry_days: int = 90):
        self.expiry = expiry_days
        self.flags: dict[str, dict] = {}
    def register(self, flag_id: str, owner: str, intent: str):
        self.flags[flag_id] = {"owner": owner, "intent": intent,
                               "created": time.time(), "status": "experiment"}
    def promote(self, flag_id: str, status: str):
        self.flags[flag_id]["status"] = status   # experiment → full → stable
    def debt_list(self) -> list[str]:
        now = time.time()
        return [f for f, m in self.flags.items()
                if m["status"] == "experiment"
                and now - m["created"] > self.expiry * 86400]

if __name__ == "__main__":
    eng = FlagEngine({"dark_mode": {"percent": 30, "default": False,
                      "whitelist": ["u-admin"],
                      "targeting": [{"vip_tier": [2, 3]}]}})
    u_admin = {"id": "u-admin", "vip_tier": 0}
    u_vip = {"id": "u-vip-1", "vip_tier": 3}
    u_normal = {"id": "u-42", "vip_tier": 0}
    assert eng.evaluate("dark_mode", u_admin) is True       # 白名单必开
    assert eng.evaluate("dark_mode", u_vip) is True         # targeting 必开
    r_normal = eng.evaluate("dark_mode", u_normal)          # 30% 桶决定
    # 稳定性：同用户重复评估结果一致（哈希确定性）
    assert all(eng.evaluate("dark_mode", u_normal) == r_normal for _ in range(20))
    print(f"评估链: 白名单✓ targeting✓ 普通用户按桶={r_normal}（稳定可复现）✅")
    led = FlagLedger(expiry_days=90)
    led.register("old_checkout_v2", "zhang", "新版结账页实验")
    led.flags["old_checkout_v2"]["created"] -= 100 * 86400  # 100 天前
    assert "old_checkout_v2" in led.debt_list()
    print("债务台账：100 天未推进的实验开关进入待删清单 ✅")
    # 删除流程：移除代码评估调用 → 删配置 → 删代码（先引用后配置，contract 同构）。
```

**追问**：1) 为什么评估要「纯函数 + 快照」？——半改状态（读配置过程中配置变了）会让同请求两次评估结果不同（日志对不上行为）；快照一次取齐保证评估原子性。2) 百分比灰度键里带 flag_id 的反面代价？——同一批用户在不同开关的分组完全独立，无法做「跨开关的队列效应」分析——某些实验平台故意共享分桶键做 cohort 对齐，取舍要明确。3) targeting 的条件表达式怎么防注入？——结构化条件（字段/操作符/值的 JSON）而非字符串表达式 eval；复杂条件（布尔组合）用受限 AST 求值——字符串 eval 是 RCE 大门。

## 背诵要点
1. 评估链优先级：白名单 → 属性 targeting → 百分比灰度 → 默认值，单点短路；评估纯函数化 + 配置快照。
2. 灰度哈希键含 flag_id（独立分桶防小白鼠固定化）；同用户必须稳定可复现。
3. 开关债务：生命周期台账（owner/intent/expiry）+ 90 天待删清单；删除 = 先删代码引用再删配置。

## 复盘追问
1. 回滚一个 feature flag 和回滚一次部署，为什么前者要快得多？（提示：flag 回滚 = 配置翻转（秒级、无发布风险），是部署回滚的廉价替代——重要变更上线时先包 flag 是行业惯例）
