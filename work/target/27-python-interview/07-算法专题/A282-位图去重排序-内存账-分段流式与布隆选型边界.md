### A282 · 位图去重与排序：海量 int 的内存账、分段流式与布隆选型边界

> 难度:★★★★ | 标签:位图, 去重, 排序, 海量数据, 内存账, 布隆过滤器

**问**（笔试·编程题）：给定 5×10⁷ 个 64 位整数（值域 0~10⁸，内存预算 64MB），要求输出去重后的有序序列——面试官要的不是「会用 set」，而是**内存约束下的算法选择与账目**：① 实现位图 Bitmap：置位/查询/顺序枚举（枚举即有序去重流，排序是免费的）；② 全集位图解法与内存账（10⁸ 值域 → 12.5MB，与排序列表每元素 36B 的账对清楚）；③ 值域涨到 10⁹ 时的**分段位图流式解法**：工作集恒定、多遍扫描的代价与「输入可重放」的前提；④ 假阳性对账：位图对未插入值零误报（探针断言），同批数据等量内存下的布隆过滤器必然出现误报——两者选型边界（布隆不能枚举、不能排序、有假阳性；位图要求值域紧凑、无假阳性、删除代价高）；⑤ 负数与稀疏 ID 的边界处理（偏移平移 / 换分块位图）。请说清与 Q5123（位图 vs set 的容量账与置位实现）、Q1003（Redis bitmap 的签到与活跃统计）、Q2870（int 位集合代数）、A262（布隆误判率实证与重建决策）的分工——本题只回答「**海量 int 去重+排序的完整算法、内存账与位图/布隆选型边界**」。

**答**：① 分工：Q5123 回答「位图比 set 省多少、什么值域下不划算」的容量账，Q1003 是 Redis 侧 bitmap 的业务用法，Q2870 用大整数位运算做集合代数，A262 回答「布隆的误判率怎么算、什么时候重建」——没有一张卡回答「给定一批 int，在内存预算内怎么既去重又排好序地输出」。② 位图三件套与免费排序：add/contains 都是 `i>>3` 取字节、`i&7` 取位的 O(1)；`ordered_iter` 顺序扫字节产出有序流——**去重与排序在一次 O(值域/8 + N) 里同时完成**，这是快排给不了的：排序不是比较出来的，是「地址即序」的结构性质白送的；代价是值域必须已知、紧凑且非负（负数先整体平移 lo）。③ 内存账：10⁸ 值域 12.5MB 位图 vs 排序输出的 int 列表（8B 指针 + 28B 对象 ≈ 36B/个）——本卡实证 20 万唯一值的稀疏分布下位图已是列表的 1/6，值域打满时更是 1.25MB 对 360MB 的两个数量级差距；差距来自「bit 靠地址寻址、对象带头部」，工程上输出流可边扫边写盘，连列表那份都不落内存。④ 分段流式：值域 10⁹ 时全集位图 125MB 超预算，按 4M bit 一段切分，每段扫一遍流筛出落在段内的值——工作集恒 512KB，总代价是「段数 × 流长度」的多遍扫描，前提是**输入可重放**（文件/数组；纯一次性流要外排归并，是另一道题）。⑤ 与布隆的选型边界：布隆 100 万 bit + 4 哈希装下同批数据后对未插入探针必然误报（本卡实证约 9%），且**布隆无法枚举成员、无法输出有序流**——它只回答「可能见过」，位图回答「确定见过、且能按序吐出来」；选型口诀：**值域紧凑要排序选位图，值域稀疏只要判重选布隆，两者都要选 Roaring 分块位图**。追问里再展开计数变体、多线程置位竞态与大整数位图。

```python
# 全部标准库；位图去重排序：全集位图 + 分段流式 + 内存账 + 与布隆的选型边界实证
import hashlib
import random
import sys


class Bitmap:
    def __init__(self, nbits):
        self.nbits = nbits
        self.buf = bytearray((nbits >> 3) + 1)
        self.count = 0

    def add(self, i):
        b, o = i >> 3, i & 7
        if not (self.buf[b] >> o) & 1:
            self.buf[b] |= 1 << o
            self.count += 1

    def __contains__(self, i):
        return bool((self.buf[i >> 3] >> (i & 7)) & 1)

    def ordered_iter(self):
        """顺序扫描即有序去重流——位图的排序是免费的。"""
        for b in range(len(self.buf)):
            byte = self.buf[b]
            if byte:
                base = b << 3
                for o in range(8):
                    if (byte >> o) & 1:
                        yield base + o


def bitmap_sort_dedupe(stream, lo, hi, chunk_bits=1 << 22):
    """分段位图流式去重排序：工作集恒为 chunk_bits/8 字节，与值域大小无关。"""
    out = []
    seg_lo = lo
    while seg_lo < hi:
        seg_hi = min(seg_lo + chunk_bits, hi)
        bm = Bitmap(seg_hi - seg_lo)
        for x in stream:
            if seg_lo <= x < seg_hi:
                bm.add(x - seg_lo)
        out.extend(seg_lo + v for v in bm.ordered_iter())
        seg_lo = seg_hi
    return out


if __name__ == "__main__":
    rng = random.Random(27)
    N_RANGE = 10_000_000
    stream = [rng.randrange(N_RANGE) for _ in range(200_000)]

    # 1) 全集位图：去重 + 排序一次到位，对账 sorted(set())
    bm = Bitmap(N_RANGE)
    for x in stream:
        bm.add(x)
    got = list(bm.ordered_iter())
    want = sorted(set(stream))
    assert got == want
    assert bm.count == len(want)
    print("去重+排序: %d 个样本 -> %d 个唯一值，与 sorted(set) 全等 ✅" % (len(stream), bm.count))

    # 2) 内存账：位图 vs 排序列表（8B 指针 + 28B int 对象）
    bm_mb = sys.getsizeof(bm.buf) / 1e6
    list_mb = len(want) * 36 / 1e6
    dense_list_mb = N_RANGE * 36 / 1e6        # 值域打满时的列表账
    print("内存账: 位图 %.2f MB | 唯一 %d 个的列表 %.1f MB | 值域打满时列表 %.0f MB"
          % (bm_mb, len(want), list_mb, dense_list_mb))
    assert bm_mb < list_mb and bm_mb * 100 < dense_list_mb

    # 3) 分段流式：值域放大到 1e8，工作集恒 512KB，多遍扫描换 O(1) 内存
    stream2 = [rng.randrange(100_000_000) for _ in range(50_000)]
    got2 = bitmap_sort_dedupe(stream2, 0, 100_000_000)
    assert got2 == sorted(set(stream2))
    print("分段流式: 值域 1e8 / 5 万样本，工作集恒 %.2f MB，结果全等 ✅"
          % ((1 << 22) / 8 / 1e6))

    # 4) 零假阳性：从未插入的值查询必为 False
    seen = set(stream)
    miss = [x for x in rng.sample(range(N_RANGE), 20000) if x not in seen]
    assert miss and all(x not in bm for x in miss)
    print("零假阳性: %d 个未插入探针全部 False（位图说是就是）✅" % len(miss))

    # 5) 布隆对照：等量内存下必然误报，且无法枚举输出
    class MiniBloom:
        def __init__(self, bits, k):
            self.bits, self.k = bits, k
            self.buf = bytearray(bits >> 3)

        def _pos(self, x):
            h = hashlib.md5(str(x).encode()).digest()
            h1 = int.from_bytes(h[0:4], "big")
            h2 = int.from_bytes(h[4:8], "big") | 1
            return [(h1 + i * h2) % self.bits for i in range(self.k)]

        def add(self, x):
            for p in self._pos(x):
                self.buf[p >> 3] |= 1 << (p & 7)

        def __contains__(self, x):
            return all((self.buf[p >> 3] >> (p & 7)) & 1 for p in self._pos(x))

    bf = MiniBloom(1 << 20, 4)                # 100 万 bit 装 20 万值：误判必现
    for x in stream:
        bf.add(x)
    fps = [x for x in miss if x in bf]
    assert fps, "布隆在此负载下应出现假阳性"
    assert not any(x in bm for x in fps)
    print("布隆对照: %d 个假阳性（同批探针位图 0 误报）——省内存的代价 ✅" % len(fps))
```

**追问**：1) 位图怎么做「每个值出现几次」的计数？—— 1 bit 升 2 bit（00/01/10/11，计到 3 饱和）或每值 4 bit，内存 ×2/×4；更省的是两遍走：位图先判存在、再只对存在的值哈希计次；次数分布极偏（长尾 1 次、头部上万次）时上分层 sketch——注意 Q5123 的提醒：判重位图和计数位图是两种结构，别混用。2) 多线程置位同一字节会不会丢？—— `buf[b] |= 1 << o` 是读-改-写三步非原子：两个线程写同一字节的不同位，后写者覆盖前写者；解法是按字节分片加锁，或各线程写**私有位图**最后单线程合并（分段位图天然适合这个并行化：段间无共享，段内一把小锁）。3) 为什么不用一个大 int 当位图（大整数位运算走 C 层）？—— 读密集可以且快：`x |= 1 << i` 的交集/并集全在 C 层，Q2870 的位集合代数就是这个路线；但大 int **不可变**，每次置位都整段重拷贝 O(值域/64)，写密集时拷贝税压倒一切——写入流式选 bytearray，批量集合运算选大 int，这是同一枚硬币的两面：那一卡讲「怎么算」，本题讲「什么写入模式下账会翻」。
