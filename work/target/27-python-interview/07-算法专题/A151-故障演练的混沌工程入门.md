### A151 · 混沌工程入门

> 难度:★★★ | 标签:混沌工程, 演练, 可靠性

**问**（笔试·场景题）：「拔网线看看系统挂不挂」是不是混沌工程——它与故障演练的区别（混沌=验证假设：系统**能扛住**X 故障），混沌实验的「稳定态假设」怎么定义（先定义「正常」才能验证「破坏后仍正常」），爆炸半径怎么控制（起步规则：预发→低流量→生产渐进），实验「失败」的两种结果（暴露弱点 vs 触发真事故）怎么区分与处理？

**答**：① 混沌 vs 演练：演练验证「**预案有效**」（拔网线后按手册切换成功）；混沌验证「**假设成立**」（我以为降级开关能扛住依赖全挂——真的扛得住吗）——混沌主动寻找未知的弱点，演练确认已知的预案。② 稳定态假设：实验前先量化「正常」指标（错误率 <0.5%、P99 <200ms、业务下单量在基线带内）——注入故障后**持续观察这些指标**：指标稳定 = 假设成立（系统真能扛）；指标劣化 = 弱点暴露（假设不成立，这是实验的产出不是事故）。③ 爆炸半径渐进：预发全量 → 生产低流量环境（单实例/灰度组）→ 生产小比例（1-5%）→ 生产全量——每级验证过才进下一级；**中止条件**预定义（错误率超 X% 立即停止注入）。④ 「失败」两种结果的区分：**弱点暴露**（注入的故障按设计影响系统，暴露未预期行为——是产出，修复进行动项）vs **实验事故**（注入本身失控，影响超出设计范围——是事故，立即全停+按事故流程处理）；区分标准：影响是否在「注入设计的边界内」。

```python
# 全部标准库；demo 实现「混沌实验控制器」
import time, random

class ChaosExperiment:
    """受控爆炸：稳定态假设 + 渐进半径 + 中止条件。"""
    def __init__(self, name: str, steady_state: dict, abort_error_rate: float = 0.05):
        self.name = name
        self.steady = steady_state            # {"error_rate": 0.005, "p99": 0.2, ...}
        self.abort_th = abort_error_rate
        self.stages = ["staging", "prod-low", "prod-1pct", "prod-full"]
        self.idx = 0
        self.findings: list[str] = []
        self.incident = False
    def _within_steady(self, observed: dict) -> bool:
        return all(observed[k] <= v for k, v in self.steady.items())
    def inject(self, observed: dict, out_of_scope: bool = False) -> str:
        if out_of_scope:                      # 影响超出注入设计边界
            self.incident = True
            return "INCIDENT: 注入失控，全停+按事故流程处理"
        if not self._within_steady(observed):
            self.findings.append(f"stage={self.stages[self.idx]} 弱点暴露: {observed}")
            self.idx = max(0, self.idx - 1)   # 弱点暴露：退一级修复后再试
            return "WEAKNESS: 假设不成立（这是产出，行动项+1）"
        if self.idx < len(self.stages) - 1:
            self.idx += 1
            return f"PASS → 进入 {self.stages[self.idx]}"
        return "HYPOTHESIS-VALID: 全级通过，假设成立"

if __name__ == "__main__":
    random.seed(1)
    exp = ChaosExperiment("依赖全挂降级验证",
                          steady_state={"error_rate": 0.005, "p99": 0.2})
    print(exp.inject({"error_rate": 0.003, "p99": 0.15}))       # staging 过
    print(exp.inject({"error_rate": 0.08, "p99": 0.9}))         # 弱点暴露
    assert len(exp.findings) == 1 and "降级开关没生效" not in exp.findings[0] or True
    exp.observed_fix = True
    print(exp.inject({"error_rate": 0.004, "p99": 0.18}))       # 修复后重试
    print(exp.inject({"error_rate": 0.004, "p99": 0.19}))
    print(exp.inject({"error_rate": 0.004, "p99": 0.2}))
    print(exp.inject({"error_rate": 0.004, "p99": 0.19}, out_of_scope=True))  # 注入失控
    assert exp.incident
    print("混沌两分:", len(exp.findings), "个弱点暴露（产出）vs", "1 次实验事故（流程处理）")
    # 口径：先定义稳定态假设；渐进半径四级；影响超边界=事故，边界内=产出。
```

**追问**：1) 为什么「稳定态假设」必须先于注入定义？——没有量化基线，注入后「变慢了」无法判定是弱点还是波动；基线让实验结论可证伪——混沌工程的科学性全在这步。2) 混沌实验的「中止条件」由谁执行？（提示：自动执行（控制器监控指标即时停止）而非人盯——实验引发的故障以秒级扩散，人工反应来不及；中止自动化是受控爆炸的底线）3) 团队刚开始做混沌，第一个实验选什么？（提示：选「已知预案的验证」（拔一个有降级预案的依赖）——先建立流程信心与工具链，再逐步进入「找未知弱点」的高级阶段；起步就拔核心依赖必翻车）

## 背诵要点
1. 混沌 vs 演练：演练确认已知预案，混沌验证假设（主动找未知弱点）——稳定态假设必须先量化定义。
2. 爆炸半径四级渐进：预发→生产低流量→生产 1-5%→全量，每级过才进下一级，中止条件自动化。
3. 两种「失败」：边界内弱点暴露=产出（行动项），影响超边界=事故（全停+事故流程）。

## 复盘追问
1. 混沌实验暴露了弱点，但修复要两个月——这期间实验结果怎么「持有」？（提示：弱点登记行动项（A138）+ 已知弱点期间禁止进入生产全量级实验 + 短期缓解措施（监控加强/手动预案文档化）——知道弱点存在和裸奔是两回事）
2. 管理层觉得「混沌=自己搞自己」拒绝立项，怎么说服？（提示：用「故障在演练中爆发 vs 在大促爆发」的对比数据（演练中发现的成本≈小时级修复，生产中发现≈资损）+ 从一次低成本的预发实验案例起步展示产出——ROI 叙事而非理念叙事）
