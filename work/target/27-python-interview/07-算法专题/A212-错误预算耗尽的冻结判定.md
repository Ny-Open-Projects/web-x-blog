### A212 · 错误预算耗尽

> 难度:★★☆ | 标签:SLO, 错误预算, 冻结

**问**（笔试·编程+场景题）：SLO 99.9% 服务本月错误预算还剩 2% 但流量高峰没来——「预算耗尽冻结发布」怎么自动化（燃烧率计算/冻结触发/解冻条件），冻结的例外通道（紧急修复/风险消除类变更），「预算提前耗尽」的两种含义（系统真的变差 vs 流量结构变化）怎么区分，预算重新计算的时刻（月初重置）有什么坑？

**答**：① 燃烧率计算：`burn_rate = 实际错误率 / SLO 错误率上限`（SLO 99.9% → 上限 0.1%）——燃烧率 >1 = 预算消耗比时间快；**快速燃烧**（1h 窗 >14.4×）立即告警+考虑冻结，**慢速燃烧**（7d 窗 >1×）月末必耗尽——两窗联动（Q7008）。② 自动化冻结：预算剩余 <10% 且燃烧率 >1 → 自动设置发布冻结（CI 闸拒绝非 L1 发布，Q133 联动）——冻结是「保护剩余预算给故障恢复用的」（预算的另一个用途：故障时的恢复操作也消耗预算——留尾巴）。③ 提前耗尽两含义区分：**系统变差**（错误率本身升了——修错误）vs **流量结构变化**（错误率没变但总流量涨了——错误数增多，SLO 按比例算则预算不变——按错误「比例」定义的 SLO 天然免疫流量变化；按错误「次数」定义的会误伤——SLO 定义要审查）。④ 月初重置的坑：「上月耗尽本月清零」会让慢性问题永远不暴露（每月都在耗尽又每月清零）——滚动窗口（过去 30 天滚动计算）替代自然月重置，慢性劣化才能累积显形。

```python
# 全部标准库；demo 实现「错误预算管理器（滚动窗口）」
import time
from collections import deque

class ErrorBudget:
    """滚动窗口错误预算：燃烧率双窗 + 自动冻结 + 例外通道。"""
    def __init__(self, slo: float = 0.999, window_days: int = 30):
        self.slo_error = 1 - slo                    # 错误率上限 0.1%
        self.events: deque = deque()                # (ts, is_error, is_deploy)
        self.window_days = window_days
        self.frozen = False
    def record(self, is_error: bool, is_deploy: bool = False):
        self.events.append((time.time(), is_error, is_deploy))
    def burn_rate(self, days: float) -> float:
        cutoff = time.time() - days * 86400
        recent = [(e, d) for t, e, d in self.events if t >= cutoff]
        if not recent:
            return 0.0
        err_rate = sum(1 for e, _ in recent if e) / len(recent)
        return err_rate / self.slo_error
    def check_freeze(self) -> str:
        fast = self.burn_rate(1 / 24)               # 1h 窗
        slow = self.burn_rate(7)                    # 7d 窗
        remaining = 1 - min(slow, 10)
        if fast >= 14.4:
            self.frozen = True
            return "FREEZE: 快速燃烧 14.4×+ → 立即冻结发布（L1 例外通道开放）"
        if slow > 1 and remaining < 0.1:
            self.frozen = True
            return "FREEZE: 慢速燃烧且预算剩 <10% → 冻结发布"
        return "open"
    def emergency_allowed(self, change: dict) -> bool:
        """冻结例外：L1 紧急修复（消除错误源的变更反而省预算）。"""
        return change.get("level") == "L1" or change.get("removes_errors", False)

if __name__ == "__main__":
    import random
    random.seed(1)
    eb = ErrorBudget(slo=0.999)
    # 正常流量：错误率 0.05%（预算内一半）
    for _ in range(9000):
        eb.record(is_error=random.random() < 0.0005)
    print("正常:", eb.check_freeze())
    # 突发：错误率 0.5%（5× 燃烧）
    for _ in range(500):
        eb.record(is_error=random.random() < 0.005)
    print("突发后:", eb.check_freeze())
    print("L1 例外:", eb.emergency_allowed({"level": "L1"}), "|",
          eb.emergency_allowed({"level": "L2", "removes_errors": True}))
    # 滚动窗口口径：慢劣化在滚动窗累积显形，自然月重置会掩盖。
```

**追问**：1) 为什么「冻结还要留例外通道」？——预算耗尽时最需要的是「消除错误源的变更」（修 bug/回滚劣化版本）——冻结把这类救火变更也挡了反而加深消耗；例外通道限 L1 + 消除错误类，风险变更仍然冻结。2) SLO 按「比例」还是按「次数」定义的陷阱？（提示：按次数（月错误 <100 次）在流量涨 10 倍时预算被误判耗尽（错误数涨但比例没变——用户体验未变）——SLO 定义以「比例/分位」为正确口径，次数口径要审查）3) 「滚动窗口 vs 自然月重置」的取舍？（提示：滚动窗让慢性劣化累积显形（这是要的）但计算复杂（需存事件明细）；自然月简单但每月清零掩盖慢性问题——生产用滚动窗，月报维度另算「月度汇总」给管理层）

## 背诵要点
1. 燃烧率双窗：1h >14.4× 快速燃烧立即冻结 + 7d >1× 慢速燃烧预算耗尽冻结——两窗联动。
2. 冻结留例外通道：L1 紧急修复 + 消除错误源类变更——冻结不阻塞救火，反而为救火留预算。
3. 滚动窗口替代自然月重置——慢性劣化累积显形；SLO 定义以比例/分位为正确口径。

## 复盘追问
1. 团队抱怨「冻结后产品没法迭代，错误预算被历史故障吃光」，怎么平衡？（提示：预算耗尽的本意是「先恢复可靠性」——冻结期行动项（A138）加速修错误源，错误率回落预算恢复自动解冻；「冻结阻塞迭代」恰是 SLO 要传递的信号——可靠性欠的账要先还）
2. 错误预算被「一次大故障」一次性吃光 vs 被「慢性 0.3% 错误率」吃光，处理有什么不同？（提示：一次性大故障→复盘修根因（行动项）+ 预算自然恢复；慢性错误→没有单一根因（多处小劣化叠加）→需要系统性治理（错误率预算分摊到各子域定位贡献者）——两种耗尽模式对应两种治理路径）
