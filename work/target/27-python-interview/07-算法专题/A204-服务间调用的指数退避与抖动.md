### A204 · 服务间重试纪律

> 难度:★★☆ | 标签:重试, 退避, 可靠性

**问**（笔试·编程+场景题）：服务 A 调 B 调 C，每层都配「重试 3 次」——三层叠加的重试放大（3×3×3=27 倍）怎么算，重试纪律的统一规范（每层重试次数递减/预算递减/只重试幂等操作），「重试预算」与「熔断」（A106/A101）的联动位置（预算在哪层记账），重试的参数（次数/退避/超时）按「下游 SLA」怎么推导？

**答**：① 放大计算：每层重试 3 次 = 失败传播被放大 3^层数——A 调 B（3 次内含 B 调 C 3 次）= C 被 A 的重试放大到最多 9 次调用；规范：**每层重试次数递减**（入口层 3 次 → 中间层 2 次 → 叶子层 1 次——总放大从 27 降到 6）+ 预算递减（每层预算 = 上层剩余 × 50%，Q6019）。② 只重试幂等：非幂等操作（POST 创建）重试 = 重复副作用——必须带幂等键（A102）或转异步补偿（A108）；规范强制「重试的操作默认视为幂等责任在调用方声明」。③ 参数推导：重试超时 ≤ 层预算（Q6019 deadline 传递）；退避基值 = 下游 MTTR 的估计（恢复周期 5s → 退避 1s 起步）；次数 = 层预算 ÷ 单次超时——三参数不是拍的，是从下游 SLA 与预算推导的。

```python
# 全部标准库；demo 实现「层级重试预算联动」
import time

class RetryPolicy:
    def __init__(self, attempts: int, budget_s: float, base_backoff: float = 0.1):
        self.attempts, self.budget, self.base = attempts, budget_s, base_backoff
    def remaining_budget(self, elapsed: float) -> float:
        return max(0, self.budget - elapsed)

def layered_retry_sim(total_budget: float = 5.0):
    """三层重试：预算递减 + 次数递减。"""
    policies = [("A", 3, 2.5), ("B", 2, 1.2), ("C", 1, 0.5)]  # 递减
    worst_case_calls = 1
    for name, attempts, budget in policies:
        worst_case_calls *= attempts
        print(f"  {name}: attempts={attempts} budget={budget}s（累计放大 {worst_case_calls}×）")
    assert worst_case_calls == 6                     # 3×2×1=6（vs 朴素 27）
    return worst_case_calls

def idempotency_check(method: str, has_key: bool) -> str:
    if method in ("GET", "PUT", "DELETE"):
        return "幂等：可重试"
    if has_key:
        return "POST+幂等键：可重试（A102）"
    return "POST 无键：禁止重试（转异步补偿 A108）"

if __name__ == "__main__":
    print("层级重试纪律（预算递减+次数递减）:")
    layered_retry_sim()
    for m, k in [("GET", False), ("POST", True), ("POST", False)]:
        print(f"  {m} (幂等键={k}) → {idempotency_check(m, k)}")
    # 口径：每层次数/预算递减（总放大 27→6）；只重试幂等操作；
    # 参数从下游 SLA 推导（超时≤层预算、退避≈MTTR）。
```

**追问**：1) 为什么「次数递减」而不是「每层 3 次」？——越靠近叶子层，单次调用越便宜且下游恢复概率越高（不需要重试）；越靠近入口，重试的放大效应越强（下游全链被放大）——次数递减把放大预算留给「最有价值的重试」（入口层重试覆盖全链瞬时故障）2) 「重试预算在哪层记账」？（提示：每层独立记账本层消耗（向下游的调用时间），但**入口层持有总预算**（deadline）——中间层向下游分配的预算受入口剩余约束（Q6019 min(配置, 剩余)）——预算是分层记账+入口总控）3) 重试参数「从下游 SLA 推导」的具体公式？（提示：次数 = 层预算 ÷ 单次超时（有余数取整）；退避基值 = 下游 MTTR/重试次数（让重试覆盖一个恢复周期）；超时 = 下游 P99 × 1.2（正常请求不能被误杀）——三参数全部有出处，评审时问得出依据）

## 背诵要点
1. 层级重试纪律：次数递减（3→2→1）+ 预算递减（每层 50%）——总放大从 27 倍压到 6 倍。
2. 只重试幂等操作：POST 无幂等键禁止重试，转异步补偿；重试的幂等责任调用方声明。
3. 三参数推导：次数=层预算÷单次超时、退避≈下游 MTTR、超时=下游 P99×1.2——评审问得出依据。

## 复盘追问
1. 每层都声称「我们只重试幂等操作」，但放大还是发生了——漏了什么？（提示：GET 也是放大（重复查询消耗下游）——「幂等可重试」不等于「该重试」：GET 的重试同样要受预算与次数纪律约束；纪律管的是「放大系数」不是「正确性」）
2. 下游 MTTR 是 5 分钟（恢复慢），但重试预算只有 5 秒——重试根本等不到恢复，参数怎么定？（提示：重试覆盖的是「瞬时故障」（秒级抖动），5 分钟级故障该走熔断+降级（A106）而非重试——重试与熔断的分工：重试管抖动、熔断管持续故障——参数推导前先确认故障类型）
