### A135 · 多集群流量切换

> 难度:★★★ | 标签:流量调度, 双活, 场景题

**问**（笔试·编程+场景题）：双机房 A/B 各扛 50% 流量，B 要紧急下线维护——流量切到 A 的「直接 100%」会发生什么（冷启动毛刺+A113 预热问题），权重切换的步进曲线怎么设计（每次切多少、间隔多久、看什么指标再切），切换期间「会话/长连接」怎么处理，回切怎么比切换更谨慎？

**答**：① 直接 100% 的灾难：B 的流量瞬间全压到 A，A 的连接池/缓存/线程池全冷（Q6020），P99 飙升 → 触发 A 的限流/熔断 → 双机房全挂。**步进曲线**：5% → 25% → 50% → 100%，每步观察 A 的错误率/P99 恢复到基线再进下一步（每步 2-5 分钟），任何一步护栏触发（Q7013）即暂停/回退。② 预热配合：切之前先给 A 预热（探活流量/缓存快照，Q6020 四件套），步进曲线 + 预热双保险。③ 会话/长连接：HTTP 会话 → 粘性会话会随切换断（B 下线）——应用层会话存储共享化（Redis 集中，切换无感）；长连接（WS）→ 切走时服务端发「下线重连」帧，客户端重连到 A（Q6020 排空语义）。④ 回切更谨慎：B 维护完恢复时，它是「冷集群」且 B 上缺失维护期间的数据（若双写未覆盖）——回切 = 一次新的完整切换流程（数据回同步校验 + 更慢的步进 + 只在工作时间做，A113 口径）。

```python
# 全部标准库；demo 实现「步进切换控制器 + 指标护栏」
import time

class TrafficSwitcher:
    def __init__(self, steps: list[int], wait_s: float = 120,
                 err_threshold: float = 0.01, p99_baseline: float = 0.2):
        self.steps, self.wait, self.err_th, self.p99_base = steps, wait_s, err_threshold, p99_baseline
        self.current = 0                      # 当前切到 B 的流量权重 %
        self.log: list[str] = []
    def can_proceed(self, err_rate: float, p99: float) -> tuple[bool, str]:
        if err_rate > self.err_th:
            return False, f"错误率 {err_rate:.1%} 超阈 → 暂停/回退"
        if p99 > self.p99_base * 1.5:
            return False, f"P99 {p99}s 劣化 >50% → 等预热恢复"
        return True, "healthy"
    def execute(self, probe) -> str:
        for step in self.steps:
            target = min(self.current + step, 100)
            self.current = target
            self.log.append(f"→ {target}% (wait {self.wait}s 观察窗)")
            ok, why = probe()
            if not ok:
                self.log.append(f"护栏触发: {why} → 回退到 {max(0, self.current - step)}%")
                self.current = max(0, self.current - step)
                return "paused"
            time.sleep(0.01)                  # demo 加速的观察窗
        return "completed: 100%"

if __name__ == "__main__":
    sw = TrafficSwitcher(steps=[5, 20, 25, 50], wait_s=120)
    healthy = lambda: (0.002, 0.18)           # 模拟健康指标
    result = sw.execute(lambda: (lambda e, p: (True, ""))(*healthy()))
    print(result, sw.log)
    assert sw.current == 100
    # 护栏触发场景：第二步错误率飙升
    sw2 = TrafficSwitcher(steps=[5, 20], wait_s=120)
    bad = lambda: (0.03, 0.9)                 # 3% 错误率
    r2 = sw2.execute(lambda: bad() if sw2.current >= 25 else (True, ""))
    print(r2, sw2.log, "| 当前权重回退至:", sw2.current)
    assert sw2.current == 25                  # 回退到上一步
    print("步进 + 护栏 + 回退 ✅；回切按新切换流程且只在工作时间执行")
    # 口径：切前预热（Q6020）+ 步进观察窗；会话集中存储无感切换；
    # 回切=数据校验+更慢步进+工作时间执行。
```

**追问**：1) 为什么步进是「5/20/25/50」非均匀而不是每步 25%？——第一步最小（5%）验证基础可用（路由/连接），中段大步（20/25/50）在确认健康后加速——非均匀步进把风险预算花在不确定性最高的开头。2) 「会话集中存储」的代价与边界？（提示：Redis 集中会话=每请求一次会话读（可本地缓存+短 TTL）+ 存储成为关键依赖（挂了全员掉线）——会话存储自身要做高可用与降级（匿名降级））3) 双活架构下「定期对切演练」（A113）和这里流量切换什么关系？（提示：对切演练 = 计划内的 100% 切换+回切全流程，验证的是本控制器+预热+回切机制；流量切换是日常调度，演练是真切换——同一个机制两种用途）

## 背诵要点
1. 流量切换 = 步进曲线（非均匀：小步开头验证、大步中段加速）+ 每步观察窗 + 护栏触发回退一步。
2. 切前预热（探活+缓存快照）双保险；会话集中存储无感切换，长连接发下线帧重连。
3. 回切 = 新的完整切换流程：数据回同步校验 + 更慢步进 + 只在工作时间执行。

## 复盘追问
1. 切到 100% 后 A 集群 CPU 80%（仍健康），要不要保持？（提示：健康但无余量——A 已无双活冗余（任何故障无缓冲），目标应是 60-70% 水位；扩容 A 或尽快回切，别停在无冗余态）
2. 切换期间两个机房各扛一半但「写操作」双写怎么保证一致？（提示：双写=最终一致风险，写必须单主（分片按机房路由写、跨机房异步同步）——双活通常是「读双活、写分主」，切流量时写路由也要跟着权重走）
