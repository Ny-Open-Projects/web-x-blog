### A213 · 节假日排班约束

> 难度:★★☆ | 标签:排班, 约束求解, 约束求解

**问**（笔试·编程+场景题）：春节假期 7 天只有 2 人能值班（其余 12 人全部请假）——「可值班池」骤减时排班约束怎么动态调整（平时约束全部失效，最小可行解优先），多人同日请假导致的「约束不可满足」（某天无人可排）怎么检测与处理（提前暴露 vs 当天抓瞎），假期的值班补贴/换休怎么进排班公平性模型（假期班负担系数）？

**答**：① 最小可行解优先：可值班池骤减时，**硬约束降级**——连续主班禁令可放宽（假期 7 天连班在人员不足时是现实）、间隔约束放弃——只保留「绝对硬约束」（人可用性）+ 「最小覆盖」（每天有人）——「平时规则」与「假期规则」分开定义（规则集切换）。② 不可满足检测：排班前先跑「可行性检查」（每天的可值班人数 ≥1，否则提前暴露请人支援/调整请假）——「当天抓瞎」的根因是请假审批不查值班池——请假审批联动排班系统（请假批准前检查该日剩余可值班人数）。③ 负担系数：假期班 1 天 = 平日 3 天负担（排班公平性计算里加权）——假期值班的人下次排班优先豁免（负担分冲抵）——公平性模型要感知「班次的痛苦不等价」。

```python
# 全部标准库；demo 实现「假期排班（最小可行解）+ 可行性预检」
import itertools

HOLIDAY_DAYS = 7
AVAILABLE = ["p3", "p7"]                     # 春节只有 2 人可值班
LEAVE_REQUESTS = {f"p{i}" for i in range(12)}  # 其余全请假

def feasibility_check(days: int, available: list[str], leave: set[str],
                       total_people: int) -> dict:
    """请假审批联动：批准前检查每日剩余可值班人数。"""
    issues = []
    if len(available) < 2:
        issues.append(f"假期可值班仅 {len(available)} 人（<2），需招募支援或驳回部分请假")
    # 请假审批的联动检查：批准这份请假后，某日可值班是否 <1
    for p in leave:
        if p not in AVAILABLE and total_people - len(leave) < 2:
            issues.append(f"批准 {p} 请假将导致部分日期无人可值")
            break
    return {"ok": not issues, "issues": issues}

def holiday_schedule(available: list[str], days: int) -> list[str]:
    """最小可行解：只保留绝对硬约束（每天有人）。"""
    n = len(available)
    return [available[d % n] for d in range(days)]   # 轮流（最公平的最小解）

def burden_model(schedule: list[str], holiday_weight: float = 3.0) -> dict:
    """负担系数：假期班 1 天 = 平日 3 天。"""
    burden = {}
    for p in schedule:
        burden[p] = burden.get(p, 0) + holiday_weight
    return burden

if __name__ == "__main__":
    fc = feasibility_check(HOLIDAY_DAYS, AVAILABLE, LEAVE_REQUESTS, 14)
    assert fc["ok"]
    print("可行性预检通过（假期 2 人轮转）:", fc)
    s = holiday_schedule(AVAILABLE, HOLIDAY_DAYS)
    assert set(s) == set(AVAILABLE)
    print("假期排班（最小可行解，轮流）:", s)
    print("负担模型:", burden_model(s), "（假期班 1 天=平日 3 天，下次排班豁免）✅")
    # 口径：假期规则集与平时分开（最小可行解优先）；请假审批联动值班池检查；
    # 负担系数让公平性感知「班次痛苦不等价」。
```

**追问**：1) 为什么假期约束要「降级」而不是维持平时规则？——规则的服务对象是「可持续的公平」；人员不足时维持公平规则=排不出班（系统失灵），降级规则+负担系数补偿=排得出且事后公平可修——约束的弹性要有边界（绝对硬约束=人可用性永不放弃）。2) 「请假审批联动值班池」的边界怎么定？（提示：审批者看到「批准后该日剩余值班人数」再批——批准导致 <2 人时需同时指定支援方案（加班补贴/外部支援）——审批权与后果可见性绑定，Q6014 同构）3) 负担系数 3× 的依据？（提示：春节班的社交/家庭成本显著高于平日（主观但普遍），3× 是常见行业口径；系数本身可调——重点是「假期班在公平模型里被显式加权」而不是被当作与平日等价的普通班）

## 背诵要点
1. 假期排班规则集切换：硬约束降级到「人可用性+最小覆盖」，平时规则（间隔/连续禁令）暂时失效。
2. 请假审批联动值班池预检（批准后剩余人数 <2 需支援方案）——「当天抓瞎」的根因是审批不查池。
3. 负担系数（假期班 1 天=平日 3 天）进公平性模型——班次的痛苦不等价要显式加权。

## 复盘追问
1. 春节排班表发布后有人临时「到不了」（计划外缺席），当天怎么办？（提示：应急升级链（Q172）——当天 by-design 有最小冗余（2 人），1 人缺席仍有覆盖；单人支撑时降低值守深度（只盯核心告警）并事后补休——应急预案是排班的最后一层）
2. 假期值班「轮流」和「专家优先」（只有专家能处理）冲突时怎么选？（提示：假期值班的主要任务是「响应+升级」不是「独立解决」（升级链保留到专家手机）——轮流可执行响应任务；若假期故障必须专家独立修，则专家值班是硬约束，轮流只适用于响应型班次）
