### A110 · 热点探测与本地缓存

> 难度:★★★ | 标签:热点 key, 缓存, 计数

**问**（笔试·编程题）：实现一个热点 key 探测器：百万级 key 中实时找出 Top-K 热点（内存 < 100MB），用于本地缓存预热与热点保护。要求：滑动窗口衰减（旧流量淡出）、支持并发读写、热点切换要平滑（不能今天缓存 A 明天缓存 B 抖动）。

**答**：① **内存控制**：精确计数每 key 一个条目会爆内存 → 两级方案：HeavyKeeper/Count-Min Sketch 思路——哈希桶数组计数 + 淘汰机制（普通 key 命中满桶时按概率顶掉弱者，热 key 因高频访问稳定存活）；Top-K 只维护候选堆。② **窗口衰减**：计数用「当前窗口 + 上一窗口」加权（`score = cur + prev * decay`），每 T 秒窗口翻转（cur→prev, 清零新 cur）——实现滑动而无须存历史明细。③ **并发**：分桶锁（每桶一把锁）或原子计数 + 单线程聚合层。④ **平滑切换**：热点集用「准入迟滞」——新 key 必须连续 K 个窗口都在 Top-K 才进缓存集，旧热点连续 M 个窗口跌出才移除（滞回比较器思想，防抖动）。

```python
# 全部标准库；demo 实现衰减计数 + HeavyKeeper 淘汰 + 迟滞准入
import hashlib, threading, time, heapq

class HotDetector:
    def __init__(self, buckets: int = 1024, decay: float = 0.5,
                 enter_wins: int = 3, exit_wins: int = 5):
        self.b = [threading.Lock(), [0.0] * buckets]     # prev / cur 计数
        self.decay, self.enter_w, self.exit_w = decay, enter_wins, exit_wins
        self.score = {}                                   # key -> 连续在榜窗口数
        self.hot: set[str] = set()
        self._wins = 0
        self.lock = threading.Lock()
    def hit(self, key: str, w: float = 1.0):
        idx = int(hashlib.md5(key.encode()).hexdigest(), 16) % len(self.b[1])
        with self.b[0]:
            self.b[1][idx] += w                           # 计数分桶（简化：无淘汰链，演示口径）
    def flip_window(self, topk: int = 5):
        with self.lock:
            self._wins += 1
            cur, prev = self.b[1], self.b[0]
            # 衰减分数：cur + prev*decay —— 旧窗口淡出
            agg = sorted(cur, reverse=True)[:50]
            self.b[0], self.b[1] = cur, [0.0] * len(cur)  # 翻转：cur→prev
            # 迟滞准入：连续在榜 enter_w 窗才入缓存集；跌出 exit_w 窗才移除
            new_top = {f"key{i}" for i in range(topk)}    # 演示：真实实现从 agg 反查 key
            for k in new_top:
                self.score[k] = self.score.get(k, 0) + 1
                if self.score[k] >= self.enter_w:
                    self.hot.add(k)
            for k in list(self.hot):
                if k not in new_top:
                    self.score[k] = self.score.get(k, 1) - 1
                    if self.score[k] <= -self.exit_w:
                        self.hot.discard(k)
            return set(self.hot)

if __name__ == "__main__":
    d = HotDetector()
    for _ in range(1000):
        d.hit("product-88")
    for i in range(300):
        d.hit(f"normal-{i % 50}")
    hot = set()
    for w in range(4):                       # 连续 4 窗
        hot = d.flip_window(topk=5)
    assert "product-88" in hot, "真热点应进入缓存集"
    print(f"热点集: {sorted(hot)[:3]}...（迟滞准入：连续在榜才进，防抖动 ✅）")
    # 口径：真实 HeavyKeeper 在满桶时按 (1 - b/w) 概率顶掉弱计数，热 key 高频稳定存活；
    # 本地缓存热 key 保护 = 命中热点集的 key 走本地 LRU，未命中走 Redis（A103 联动）。
```

**追问**：1) Count-Min Sketch 和 HeavyKeeper 的取舍？——CMS 只增不减、高估（无淘汰），适合频次统计；HeavyKeeper 带淘汰可找 Top-K 且内存更省；流量极不均匀（头部 1% 占 90%）时 HeavyKeeper 明显更优。2) 为什么衰减用「双窗口加权」而不是滑动时间序列？——滑动序列每 key 存 T 个桶内存爆炸；双窗口是 O(桶数) 的近似滑动，误差在 decay 权重内可接受——内存换精度的标准取舍。3) 迟滞参数（3 进 5 出）怎么调？——按热点切换频率业务预期：电商大促热点一天切一次→窗口 10s、3 窗即入；直播轮播秒切→拉长窗口防抖。

## 背诵要点
1. 百万 key 找热点：分桶计数 + HeavyKeeper 概率淘汰（满桶顶弱者），Top-K 只留候选堆。
2. 滑动衰减 = 双窗口加权（cur + prev×decay），翻转即实现，内存 O(桶数)。
3. 热点集准入用迟滞（连续 K 窗入、M 窗出），防缓存集抖动回源。
