### A139 · 成本预算与背压联动

> 难度:★★★ | 标签:成本工程, 预算, 场景题

**问**（笔试·场景题）：LLM 应用月度成本预算 10 万元，月中已用 70% 但流量还在涨——「超预算」的三种应对（硬停/降档/加预算申请）怎么自动化，降档的优先序（换便宜模型/砍上下文/降采样），预算告警的提前量怎么算（月中才发现=来不及），「成本 SLO」和「质量 SLO」打架（降档后质量跌）怎么仲裁？

**答**：① 应对自动化三档：**50% 预算 + 40% 时间** → 预警（无动作）；**70% 预算 + 60% 时间** → 自动降档第一步（非核心路径换便宜模型）；**90% 预算 + 75% 时间** → 降档第二步（核心路径也降参+限流非关键功能）；**预算 100%** → 硬停非核心 + 核心限流 + 预算申请审批（加预算是业务决策不是技术决策，人工审批）。关键公式：**消耗速率对比**（今日消耗/日均预算配额），比绝对百分比更早暴露（月初暴涨立刻发现）。② 降档优先序（按质量损失从小到大）：换同能力档便宜模型（Q7516）> 砍上下文（摘要化）> 降采样（非关键用户/功能先降）> 硬限流。③ 仲裁机制：质量 SLO 和成本 SLO 各有「护栏值」，冲突时按**业务分级**裁决——核心付费功能质量优先（成本涨也要保），免费功能成本优先（质量可降）——分级映射表提前与业务对齐，不是工程师拍脑袋。

```python
# 全部标准库；demo 实现「预算消耗速率监控 + 自动降档」
import time

class BudgetGuard:
    """月度预算：消耗速率对比 + 三档自动降档 + 人工审批门槛。"""
    def __init__(self, monthly: float = 100000.0, days: int = 30):
        self.monthly, self.days = monthly, days
        self.used, self.day = 0.0, 1
        self.tier = 0                          # 0 正常 / 1 一级降档 / 2 二级
        self.log: list[str] = []
    def spend(self, amount: float):
        self.used += amount
    def check(self) -> str:
        pct = self.used / self.monthly
        time_pct = self.day / self.days
        pace = pct / max(time_pct, 0.01)       # 消耗速率 / 时间进度
        if pct >= 1.0:
            self.tier = 3
            self.log.append("预算 100%：硬停非核心 + 核心限流 + 人工审批加预算")
            return f"STOP (tier {self.tier})"
        if pct >= 0.9 and time_pct < 0.75:
            self.tier = max(self.tier, 2)
            self.log.append("90% 预算且未到 75% 时间：二级降档（核心降参+限流）")
            return f"tier-{self.tier}"
        if pct >= 0.7 and time_pct < 0.6:
            self.tier = max(self.tier, 1)
            self.log.append("70% 预算且未到 60% 时间：一级降档（非核心换便宜模型）")
            return f"tier-{self.tier}"
        if pace > 1.5 and pct > 0.3:
            self.log.append(f"速率超常（{pace:.1f}×）→ 预警：即使百分比未到也要排查")
            return "pace-warning"
        return f"healthy (tier {self.tier}, pace {pace:.1f}×)"

if __name__ == "__main__":
    g = BudgetGuard(monthly=100000)
    for day in range(1, 19):                   # 前 18 天按日均花
        g.used += 100000 / 30; g.day = day
    r = g.check()
    print("第 18 天:", r)
    assert r.startswith("healthy")
    g.used = 72000; g.day = 18                 # 用量超前（70% 预算 / 60% 时间未到）
    r = g.check()
    assert r == "tier-1", r
    print("自动降档触发:", g.log[-1], "✅")
    g.used = 92000
    r = g.check()
    assert r == "tier-2"
    print("二级降档:", g.log[-1])
    g.used = 100000
    print("硬停:", g.check())
    # 口径：速率对比比绝对百分比更早暴露；降档序按质量损失从小到大；
    # 仲裁按业务分级（付费功能质量优先、免费功能成本优先），映射表提前对齐。
```

**追问**：1) 为什么用「消耗速率」而不是「绝对百分比」做预警？——绝对百分比在流量突增（营销活动）时要到月中才触发（来不及）；速率对比当天就能发现异常——提前量从半月缩到一天。2) 降档后「质量 SLO 跌破」自动升回来吗？（提示：要——降档触发条件解除（预算速率回落）自动升档；质量跌破硬线则立即升档回质量档并告警加预算——双向联动，成本和质量轮流让步而不是单向牺牲）3) 「预算申请审批」给谁批、多久批完？（提示：业务负责人批（预算是业务决策），SLA 4 小时内——审批超时按「维持现状」处理（继续 tier-2 降档），绝不无限期硬停业务）

## 背诵要点
1. 预算四档自动化：50%/40% 预警 → 70%/60% 一级降档 → 90%/75% 二级降档 → 100% 硬停+人工审批；消耗速率比绝对百分比更早暴露。
2. 降档优先序按质量损失从小到大：同档便宜模型 > 砍上下文 > 降采样 > 硬限流。
3. 质量 vs 成本仲裁按业务分级（付费质量优先/免费成本优先），映射表提前对齐；降档触发条件解除自动升档（双向联动）。

## 复盘追问
1. 降档后成本降了 30% 但付费用户投诉质量，CFO 说省得好——怎么仲裁？（提示：用分级映射表说话——付费功能质量是承诺（SLO），违反承诺的省钱是违约；拆分：免费路径保持降档、付费路径升档，成本账分开算）
2. 月底发现预算超了但「没人注意到降档日志」，告警体系漏了什么？（提示：降档事件本身就是告警（进值班通知），且降档对业务可见（degraded 标记，Q7516）——静默降档等于没降档机制的保险绳断了）
