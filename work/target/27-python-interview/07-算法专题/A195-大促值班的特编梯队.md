### A195 · 大促值班特编梯队

> 难度:★★☆ | 标签:大促, 值班, 场景题

**问**（笔试·场景题）：大促期间值班与日常完全不同——特编梯队怎么编（核心链路专家驻场 vs 按需响应），升级快线（大促升级链比日常快在哪：预算/层级/直接到人），值班间隔与轮班节奏（连轴转会出错——疲劳管理），大促值班的「事后恢复」（特编解散后的知识沉淀与疲劳补偿）怎么安排？

**答**：① 特编梯队：**核心链路专家驻场**（支付/库存/下单的 owner 物理在场——升级快线直接到人（跳过值班中转））、**按需响应**（非核心链路专家电话待命——不用都在场）；梯队矩阵 = 链路关键度 × 是否需要实时决策（支付需要实时，文档工具不需要）。② 升级快线：日常升级 15 分钟级（Q172），大促 **5 分钟级**（每分钟都是钱）+ 跳级直达（oncall 直接叫 team lead，跳过专家中转——日常升级链在高压下太慢）；快线的代价：专家全程紧绷——快线限时段（高峰时段启用，平峰回正常链）。③ 疲劳管理：**轮班硬切**（每班 ≤4 小时高峰岗——超过 4 小时判断力显著下降（实证口径））+ 强制休息（换班后 1 小时不上岗）；连轴转的错误率上升是实证的（疲劳驾驶同源）——值班表按「高峰岗轮换矩阵」预排，不靠自觉。④ 事后恢复：特编解散前**知识沉淀会**（大促特有问题/临时预案哪些要常态化）、疲劳补偿（调休排期）、复盘（A138 常规流程 + 大促专项：哪些临时措施该转正式机制）。

```python
# 全部标准库；demo 实现「大促值班排班矩阵 + 快线升级」
import time

CORE_SERVICES = ["payment", "stock", "order"]      # 需专家驻场
PROMO_SHIFT_HOURS = 4                               # 高峰岗每班 ≤4h

class PromoRoster:
    def __init__(self, experts: dict[str, str]):    # service -> expert
        self.experts = experts
        self.shifts: list[dict] = []
    def build_shifts(self, start_hour: int, slots: int):
        """高峰岗轮换矩阵：每班 4h，轮换驻场专家。"""
        for i in range(slots):
            shift = {}
            for svc in CORE_SERVICES:
                expert = self.experts[svc]
                shift[svc] = f"{expert}@shift{i}"    # 轮换占位（真实：按人排）
            self.shifts.append({"slot": i, "hours": (start_hour + i * PROMO_SHIFT_HOURS,
                                                     start_hour + (i + 1) * PROMO_SHIFT_HOURS),
                                "onsite": shift})
        return self.shifts
    def fast_line(self, service: str, minutes_since_start: float) -> str:
        """快线升级：5 分钟级直连 lead（高峰期），平峰回日常链。"""
        in_peak = any(s["hours"][0] % 24 <= time.localtime().tm_hour < s["hours"][1] % 24
                      for s in self.shifts)
        if in_peak:
            return f"快线: 直连 {self.experts[service]} 的 team lead（5min 级）"
        return "平峰: 日常升级链（15min 级，Q172）"

if __name__ == "__main__":
    roster = PromoRoster({"payment": "pay-expert", "stock": "stock-expert",
                          "order": "order-expert"})
    shifts = roster.build_shifts(start_hour=18, slots=3)
    for s in shifts:
        print(f"班次 {s['slot']} ({s['hours'][0]}:00-{s['hours'][1]}:00): {list(s['onsite'])}")
    assert all((s["hours"][1] - s["hours"][0]) <= PROMO_SHIFT_HOURS for s in shifts)
    print("高峰岗每班 ≤4h 硬切 ✅")
    print(roster.fast_line("payment", 10))
    # 事后口径：解散前知识沉淀会 + 疲劳补偿调休 + 常态化评审（临时措施转正评估）。
```

**追问**：1) 为什么高峰岗「每班 ≤4 小时」是硬约束而非建议？——持续高压决策 4 小时后判断力显著下降（疲劳驾驶实证同源）——大促值班的错误操作成本极高（误操作在生产峰值期放大）；硬切防「我还能撑」的自我评估失效。2) 「临时措施转正」怎么评估？（提示：大促期间的临时预案（手动降级脚本/白名单）若证明有效，转正评估 = 正式化（代码化+测试+owner）或明确废弃——临时措施不评估就「顺手留着」是漂移（Q130 同源）——解散前的沉淀会就是评估现场）3) 专家驻场的成本与替代方案？（提示：专家驻场是最贵方案（人力集中）——替代：按需响应（电话 5 分钟到场承诺）+ 核心决策自动化（限流自动触发）——驻场范围随自动化水平降低，大促值班的人海是自动化的映射）

## 背诵要点
1. 特编梯队矩阵：核心链路专家驻场 + 非核心电话待命——按「链路关键度 × 是否实时决策」编排。
2. 升级快线：5 分钟级直连 lead（高峰期启用，平峰回日常链）；跳过中转是速度设计。
3. 高峰岗每班 ≤4 小时硬切 + 换班 1 小时不上岗；解散前知识沉淀会（临时措施转正评估）+ 疲劳补偿。

## 复盘追问
1. 大促值班零事故，团队说「值班的准备是浪费」（下次可以少准备）——怎么回应？（提示：零事故=准备充分的结果而非准备多余的证明——用「演练中发现的 N 个问题已修复」清单说明没有这些准备会发生什么；幸存者偏差的反向表述）
2. 特编梯队里某专家临时有事无法驻场，矩阵怎么调整？（提示：备岗机制（每核心服务 ≥1 备岗专家）+ 备岗激活自动通知（不在场变按需响应+升级快线保留）——单点专家在特编梯队里也是风险，备岗是大促排班的一半工作量）
