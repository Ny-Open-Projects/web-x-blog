### A261 · 日程冲突检测与区间运算

> 难度:★★★★ | 标签:区间合并, 半开区间, 跨天, 时区, 扫描线

**问**（笔试·编程题）：给会议室的日程系统写核心算法，要求：① 区间统一用**半开区间** `[start, end)`，`[10:00,11:00)` 与 `[11:00,12:00)` **不算冲突**（背靠背可以排），但重叠 1 分钟就算；② 支持**跨天**事件（`23:00 → 次日 01:00`），且「按天展示」时不能把同一事件算成两条，也不能在午夜丢掉半小时；③ 输入可能是**带时区**的时间（`2026-11-25T00:30:00+08:00`）或本地裸时间，必须归一后才比较；④ `add` 返回**所有**冲突的既有事件 ID（不是只报第一个），单次查询 `O(log n + k)`；⑤ 还要能算「并集」（占用时间轴）与「补集」（窗口内可预订的空闲时段，可设最短可用时长）；⑥ 批量导入时用**扫描线**一次给出所有冲突对，并说明 1 万个同时段事件会产生多少对、接口该怎么兜。请说清与 A003（基础合并区间，纯数组题）、A189（变更窗口预约：资源容量与自动改期，业务编排层）、Q1666（SQL 版的重叠谓词与 EXCLUDE 约束）的分工。

**答**：① 分工：A003 是「给一堆区间求并集」的裸算法，没有时间语义；A189 是**预约业务**（窗口是共享资源、冲突分三类、还要推荐改期），重心在编排与产品规则；本题是**时间语义与索引结构**：边界开闭、跨天、时区、粒度、批量冲突对、密度上限。三者可以叠加使用——A189 的冲突判定内核就该长成本题的样子。② 为什么必须半开：闭区间 `[10:00,11:00]` 与 `[11:00,12:00]` 共享端点 11:00，判定为冲突，背靠背会议永远排不上；而且闭区间的时长是 `e - s + 1`（按分钟算），每处都要 ±1，是最经典的 off-by-one 温床。半开区间的三条性质恰好是日历需要的：**时长 = e - s**；**相接不重叠**；**任意时刻 t 属于区间 ⟺ s ≤ t < e**，与「时间点是否有长度」的直觉一致。零长度 `[t, t)` 是空集，必须 `ValueError`——它通常意味着上游把「提醒时间」当成了「会议区间」，静默存进去会让所有人查不到冲突。③ 跨天不要「按天拆开存」：拆开再拼会在午夜产生两个半截事件，统计条数时重复、取消时漏删、改期时改一半。正确做法是**存绝对时间轴上的一个区间**（UTC 时间戳或分钟数），只在**展示层**按天切片，且切片只影响显示、不影响存储。切片还有两个坑：跨天事件的**时长**在两天各算一半（求和没问题，但「每天会议数」会 +2）；**全天事件**必须表示成 `[当天 00:00, 次日 00:00)`，而不是「24 小时」的固定长度——夏令时切换那天本地一天是 23 或 25 小时。④ 时区归一：所有入库时间先转 UTC（本题用「UTC 分钟」这个整数轴），带 `+08:00` / `Z` 的字符串用 `fromisoformat` 解析后直接 `timestamp()`；裸时间要显式指定它属于哪个时区（默认 UTC 还是本地，是契约问题，不是实现细节）。只存本地时间字符串的系统，在用户跨时区、或服务器时区被改后会整体错位；只存 UTC 而不存原始时区 ID 的系统，**循环会议**没法正确展开（「每周一 9 点」指的是本地 9 点，DST 之后 UTC 偏移变了）。所以生产上要存两样：**UTC 时间戳 + IANA 时区 ID**。⑤ 索引结构：日程查询的本质是「stabbing query + 区间相交」，标准解法是**区间树**（以 start 建 BST，节点维护子树 max end）。本题用一个更轻的等价物：**按 start 排序的数组 + 前缀最大 end**。查询时 `bisect` 定位第一个 `start ≥ 查询起点` 的位置，向左扫时一旦 `prefix_max_end ≤ 查询起点` 就可以停（左边不可能再有交集），向右扫到 `start ≥ 查询终点` 为止——复杂度 `O(log n + k)`，k 是真实冲突数。插入是 `O(n)`（数组移位），适合「读多写少、单资源几千条」的日程；如果插入也频繁，换成平衡树/跳表，或者干脆用扫描线批量重建。⑥ 批量冲突对：`n` 个区间两两检查是 `O(n²)`，扫描线把小顶堆放进去后是 `O(n log n + k)`，k 是冲突对数。这里必须点破：**k 本身可能是平方级**——1 万个同时段事件产生约 5000 万对，任何接口把它全量返回都会打爆内存和网络。所以 API 必须限制：只返回「前 N 对 + 总数」、或按资源聚合（「该时段有 37 个事件互相冲突」）、或直接拒绝并要求用户先缩小范围。算法正确不等于接口可用。⑦ 空闲时段：`free()` 是 `merge()` 的补集——先合并忙时（相接要合并，因为 10:00-11:00 与 11:00-12:00 连续占用），再把窗口裁开、取间隙，最后按 `min_len` 过滤（15 分钟以下的空隙排不进会议，返回它只会让用户困惑）。注意补集必须**裁剪到窗口内**：不裁的话，窗口前的空闲会被算成从「很久以前」开始，前端渲染直接溢出。⑧ 并发与 TOCTOU：Q1666 已给出 SQL 版的重叠条件与 `EXCLUDE` 约束，本题不重复；但必须点破，本算法是「先查冲突、再插入」，两个请求同时查都发现无冲突，然后都插入——数据库里就出现了重叠。算法层无法解决，必须在存储层用**唯一约束/行锁/串行化隔离**，或把「资源+时间段」做成排他锁。日程系统里这条比算法本身更容易出事故：压测单线程永远是对的，上线第一天就双预订。⑨ 粒度也要在契约里写死：按分钟取整意味着 `10:00:30` 会被截断成 `10:00`，两场看似不冲突的会议实际重叠了 30 秒；要么统一到秒，要么在入口就拒绝非整分钟输入。不要一边截断一边声称精确。

```python
# 全部标准库；绝对时间轴（分钟）+ 半开区间 + 前缀最大 end + 扫描线批量冲突
import heapq
from bisect import bisect_left
from datetime import datetime, timezone

DAY = 1440


def to_min(s, default_tz=timezone.utc):
    """把 '2026-11-24 09:00' / '...T09:00:00+08:00' / '...Z' 统一成 UTC 分钟。

    跨天、跨时区全部靠这一步抹平：之后所有比较都在同一条绝对时间轴上。
    """
    dt = datetime.fromisoformat(s)
    if dt.tzinfo is None:
        dt = dt.replace(tzinfo=default_tz)
    return int(dt.timestamp() // 60)


class Calendar:
    """按资源维护有序区间表；冲突 = 交集长度 > 0，相接不算冲突。"""

    def __init__(self):
        self._items = {}     # res -> [(start, end, eid)] 按 start 升序
        self._starts = {}    # res -> [start]
        self._pmax = {}      # res -> 前缀最大 end，用于「向左扫到不可能再冲突为止」

    def _ensure(self, res):
        if res not in self._items:
            self._items[res] = []
            self._starts[res] = []
            self._pmax[res] = []
        return self._items[res], self._starts[res], self._pmax[res]

    # ---------- 查询：O(log n + k) ----------
    def conflicts(self, res, start, end):
        if end <= start:
            raise ValueError("半开区间必须满足 end > start")
        items, starts, pmax = self._ensure(res)
        p = bisect_left(starts, start)
        out = []
        i = p - 1
        while i >= 0:                       # 向左：end > start 才算重叠
            if pmax[i] <= start:
                break                       # 左侧所有区间都在 start 之前结束
            if items[i][1] > start:
                out.append(items[i][2])
            i -= 1
        j = p
        while j < len(items) and items[j][0] < end:   # 向右：start < end 即重叠
            out.append(items[j][2])
            j += 1
        return out

    def add(self, res, start, end, eid):
        conf = self.conflicts(res, start, end)
        items, starts, pmax = self._ensure(res)
        p = bisect_left(starts, start)
        items.insert(p, (start, end, eid))
        starts.insert(p, start)
        pmax.insert(p, max(end, pmax[p - 1] if p else end))
        for k in range(p + 1, len(pmax)):    # 前缀数组重算（列表插入本身也是 O(n)）
            pmax[k] = max(pmax[k - 1], items[k][1])
        return conf

    # ---------- 并集与补集 ----------
    def merge(self, res):
        """相接的区间合并：用于「占用时间轴」与空闲时段计算，与「是否冲突」是两件事。"""
        out = []
        for s, e, _ in sorted(self._items.get(res, [])):
            if out and s <= out[-1][1]:
                out[-1][1] = max(out[-1][1], e)
            else:
                out.append([s, e])
        return [(s, e) for s, e in out]

    def free(self, res, win_start, win_end, min_len=0):
        if win_end <= win_start:
            raise ValueError("窗口必须 end > start")
        out, cursor = [], win_start
        for s, e in self.merge(res):
            if e <= win_start or s >= win_end:
                continue
            if s > cursor:
                out.append((cursor, min(s, win_end)))
            cursor = max(cursor, e)
            if cursor >= win_end:
                break
        if cursor < win_end:
            out.append((cursor, win_end))
        return [(s, e) for s, e in out if e - s >= min_len]

    def daily_view(self, res, day_start):
        """按天切片只用于展示：跨天事件会在两天各出现一段，统计条数时不能按段计数。"""
        d0, d1 = day_start, day_start + DAY
        return [(max(s, d0), min(e, d1), eid)
                for s, e, eid in self._items.get(res, [])
                if s < d1 and e > d0]


def conflict_pairs(events):
    """批量冲突对：扫描线 + 结束时间小顶堆，返回所有相交对（O(n log n + k)）。"""
    pairs = []
    heap = []
    for s, e, eid in sorted(events):
        while heap and heap[0][0] <= s:      # 已结束的移出，相接不算冲突
            heapq.heappop(heap)
        for _, other in heap:
            pairs.append((other, eid))
        heapq.heappush(heap, (e, eid))
    return pairs


if __name__ == "__main__":
    def at(d, hm):
        return to_min("%s %s" % (d, hm))

    c = Calendar()
    D = "2026-11-24"

    # 1) 首尾相接不算冲突（半开区间的核心语义），重叠 1 分钟就算
    assert c.add("room-1", at(D, "09:00"), at(D, "10:00"), "A") == []
    assert c.add("room-1", at(D, "10:00"), at(D, "11:00"), "B") == []
    assert c.add("room-1", at(D, "09:30"), at(D, "09:45"), "C") == ["A"]
    assert c.add("room-1", at(D, "10:59"), at(D, "12:00"), "D") == ["B"]
    print("边界: [9,10) 与 [10,11) 不冲突；[9:30,9:45) 撞 A；[10:59,12:00) 撞 B ✅")

    # 2) 非法区间必须报错，而不是静默存进去（零长度在业务上通常是上游算错了）
    for bad in ((at(D, "15:00"), at(D, "15:00")), (at(D, "16:00"), at(D, "15:00"))):
        try:
            c.add("room-1", bad[0], bad[1], "X")
            raise AssertionError("应当拒绝非法区间")
        except ValueError:
            pass
    print("非法区间: 零长度与反向区间均被拒绝 ✅")

    # 3) 并集：相接合并；补集：窗口内的空闲时段（可设最短可用时长）
    merged = c.merge("room-1")
    assert merged == [(at(D, "09:00"), at(D, "12:00"))], merged
    free = c.free("room-1", at(D, "08:00"), at(D, "13:00"), min_len=30)
    assert free == [(at(D, "08:00"), at(D, "09:00")),
                    (at(D, "12:00"), at(D, "13:00"))], free
    print("并集/补集: 忙时合并为 09:00-12:00，空闲 = 08-09 与 12-13 ✅")

    # 4) 跨天：23:00 -> 次日 01:00 是一个区间，第二天的 00:30 必须撞上
    c2 = Calendar()
    night = c2.add("room-2", at(D, "23:00"), at("2026-11-25", "01:00"), "N")
    assert night == []
    assert c2.conflicts("room-2", at("2026-11-25", "00:30"),
                        at("2026-11-25", "02:00")) == ["N"]
    assert c2.conflicts("room-2", at("2026-11-25", "01:00"),
                        at("2026-11-25", "02:00")) == []
    print("跨天: 23:00-次日01:00 与 00:30 冲突、与 01:00 不冲突 ✅")

    # 5) 按天切片：跨天事件在两天各出现一段，事件本身仍然只有一个
    d0 = to_min("2026-11-24 00:00")
    slices = c2.daily_view("room-2", d0)
    nxt = c2.daily_view("room-2", d0 + DAY)
    assert slices[0][0] == at(D, "23:00") and nxt[0][1] == at("2026-11-25", "01:00")
    assert len(slices) + len(nxt) == 2 and {x[2] for x in slices + nxt} == {"N"}
    print("切片: 同一跨天事件切成 2 段展示，事件 ID 仍只有一个 ✅")

    # 6) 时区归一：+08:00 与 Z 的同一时刻必须落到同一分钟
    assert to_min("2026-11-25T00:30:00+08:00") == to_min("2026-11-24T16:30:00Z")
    c3 = Calendar()
    c3.add("room-3", to_min("2026-11-25T00:00:00+08:00"),
           to_min("2026-11-25T01:00:00+08:00"), "T1")
    assert c3.conflicts("room-3", to_min("2026-11-24T16:30:00Z"),
                        to_min("2026-11-24T17:30:00Z")) == ["T1"]
    print("时区: 本地 00:00+08:00 存成 16:00Z，用 16:30Z 查询能命中，判定为冲突 ✅")

    # 7) 全天事件：与当天任意时段冲突，但不与次日冲突
    c4 = Calendar()
    c4.add("room-4", at(D, "00:00"), at("2026-11-25", "00:00"), "ALLDAY")
    assert c4.conflicts("room-4", at(D, "23:59"), at("2026-11-25", "00:30")) == ["ALLDAY"]
    assert c4.conflicts("room-4", at("2026-11-25", "00:00"),
                        at("2026-11-25", "01:00")) == []
    print("全天: [00:00, 次日00:00) 覆盖当天任意时刻，且不侵入次日 ✅")

    # 8) 批量冲突对：扫描线一次给出所有相交对（不是只报第一个）
    ev = [(0, 10, "a"), (5, 15, "b"), (10, 20, "c"), (12, 14, "d"), (30, 40, "e")]
    pairs = conflict_pairs(ev)
    assert set(pairs) == {("a", "b"), ("b", "c"), ("b", "d"), ("c", "d")}, pairs
    print("批量: 5 个区间得到 4 对冲突（a-b、b-c、b-d、c-d），相接的 a-c 不算 ✅")

    # 9) 规模：2 万随机区间，冲突对与插入查询都可接受（插入是 O(n) 移位，见追问）
    import random
    import time
    rng = random.Random(0)
    big = []
    for i in range(20000):
        s = rng.randrange(0, 200000)
        e = s + rng.randrange(1, 120)
        big.append((s, e, "e%d" % i))
    t0 = time.perf_counter()
    big_pairs = conflict_pairs(big)
    t1 = time.perf_counter()
    assert len(big_pairs) > 20000
    print("规模: 2 万区间扫描线得 %d 对冲突，耗时 %.0f ms ✅"
          % (len(big_pairs), (t1 - t0) * 1000))
```

**追问**：1) 为什么不用「一天 96 个 15 分钟格子」的位图？—— 位图确实能把冲突检测变成按位与，实现极简，但它的代价是**粒度写死**：会议从 10:07 开始怎么办（要么向上取整产生假冲突，要么向下取整漏判）；跨天事件要跨两张位图；DST 那天本地有 23 或 25 小时，格子数根本不固定；改期一条要清一段位（并发下很难原子）。位图适合「固定时段、固定时长」的排课场景，不适合自由起止的日程。2) 一次导入 10 万个区间、返回所有冲突对会怎样？—— 最坏 50 亿对，内存先炸。接口必须设计成「统计 + 采样」：返回冲突总数、涉及的事件集合大小、前 100 对样例，其余靠用户缩小范围再查。任何「全量返回 O(n²) 结果」的 API 在真实规模下都是拒绝服务漏洞。3) 时区到底怎么存？—— 三条：**UTC 时间戳**存绝对时刻（比较、排序、跨时区查询都靠它）；**原始 IANA 时区 ID**（`Asia/Shanghai`，不是 `+08:00` 偏移，因为偏移会随 DST 变）随事件一起存，用于展示与循环展开；**循环规则**单独存（`FREQ=WEEKLY;BYDAY=MO`），展开时按本地时区计算后再转 UTC——先展开再转、和先转再展开，在 DST 边界上会差一小时，这是日历系统最经典的一类 bug。

## 背诵要点
1. 半开区间 `[s,e)`：时长 = `e-s`、相接不冲突、零长度是空集必须拒绝；闭区间会让「背靠背」排期永远失败。
2. 存绝对时间轴（UTC 时间戳/分钟），只在展示层按天切片；全天事件 = `[当天 0 点, 次日 0 点)`，DST 那天不是 24 小时。
3. 冲突查询 = 按 start 排序 + 前缀最大 end，`O(log n + k)`；批量冲突对用扫描线 `O(n log n + k)`，k 可能是平方级，接口必须限量。

## 复盘追问
1. 单测全绿，上线第一天就出现双预订，为什么？（提示：查-插之间的 TOCTOU 竞态，算法层无解；必须数据库唯一约束/行锁/串行化隔离，或在资源维度加排他锁）
2. 跨时区用户订「下周一 9 点」，DST 切换后提醒偏了一小时，问题在哪？（提示：循环规则被先转 UTC 再展开；应存 IANA 时区 + 循环规则，按本地墙钟展开后再转 UTC）
