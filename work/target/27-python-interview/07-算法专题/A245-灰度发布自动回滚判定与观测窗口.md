### A245 · 灰度自动回滚判定

> 难度:★★★ | 标签:灰度, 自动回滚, 统计判定, 观测窗口

**问**（笔试·场景题）：新版本灰度 5% 流量，要求「指标一变差就自动回滚」——① 指标怎么选（技术护栏、业务指标、依赖指标各看什么，为什么必须和**同期基线桶**比而不是和历史大盘比）；② 观测窗口多长（样本量怎么算，为什么不能「每来一批数据就看一眼、一显著就停」）；③ 自动回滚阈值怎么定（只看 p 值会怎样，为什么还要「业务显著」，多指标同时看会不会误报累积，连续窗口起什么作用）；④ 回滚动作的粒度（暂停推进、摘掉灰度流量、全量回滚，默认选哪个）；⑤ 它与 A146（发布后验证清单）、A208（灰度转全量收尾）、A237（回滚能力演练）边界在哪？

**答**：① 分工：A146 管「发布后该验哪些项、观察窗多长」，A208 管「灰度够干净了、能不能放量到 100%」，A237 管「回滚能力本身能不能用」（周期性演练）；本题是灰度**进行中**的实时决策器：输入双桶指标流，输出 KEEP / HOLD / ROLLBACK 三态。② 指标三层：**技术护栏**（错误率、慢请求占比、饱和度：CPU/连接池/队列积压）、**业务指标**（下单成功率、支付转化率、核心接口成功率）、**依赖指标**（下游错误率、DB 慢查询数、缓存命中率——新版本常常是「把下游打挂」而不是自己报错）。对比对象必须是**同期基线桶**（同版本旧流量或稳定对照组，同一时间段），不能和历史大盘比：大盘有日周期、活动、上游波动，拿昨天同时刻比会把「晚高峰」判成「新版本劣化」。绝对阈值只作兜底（如错误率 ≥5% 无条件回滚）。③ 观察窗与样本：先用公式反推每组最小样本 `n ≈ (z_α+z_β)²·[p0(1-p0)+p1(1-p1)] / MDE²`，其中 MDE 是你「愿意也必须检出」的最小劣化（如错误率 +0.5pp）——1% 基线要检出 +0.5pp，约需每组 1.5 万请求；5% 灰度、1000 QPS 下大约 5 分钟就够，1% 灰度就要 25 分钟。样本不足时输出 HOLD 而不是 KEEP（「没证据」不等于「没问题」）。**禁止无限 peeking**：每多看一次就多一次误报机会，要么预先固定 look 次数并用 α 分摊（如 12 次 look 每次 α/12），要么固定「每 5 分钟一个独立窗口」且要求连续窗口。④ 双门槛：**统计显著**（z ≥ 3.09，单次 α≈0.001）+ **业务显著**（绝对劣化 ≥0.5pp 或相对劣化 ≥20%）。大流量下任何微小差异都会显著——只信 p 值会把 0.01pp 的抖动当事故，频繁误回滚本身就是可用性事故（回滚也要重启、也会抖）。多指标并看必然累积误报（10 个指标各 0.1% 误报 ≈ 1% 整体），所以：指标要精简到 3-5 条核心护栏、每条阈值收紧、再加「连续 2 个窗口」把单点噪声挡掉。⑤ 三态与动作粒度：全部达标且样本充分 → KEEP（允许推进下一档）；有指标 breach 但未连续、或样本不足 → HOLD（加窗复核，不推进也不回滚）；连续 2 窗双显著或触绝对红线 → ROLLBACK。动作默认选**摘掉灰度流量**（只把新版本流量切回旧版，保留现场便于排查、保留对照组），而不是「全量回滚」（影响面更大、还会丢掉对照数据）；「暂停推进」是最轻的止血，适合只超软阈值的情况。回滚后该版本必须冻结、重新走评审（A133），不能改个参数立刻再灰。

```python
# 全部标准库；灰度自动回滚判定：双比例检验 + 双门槛 + 连续窗口 + 三态决策
import math
from dataclasses import dataclass


def z_two_prop(x_ctrl, n_ctrl, x_trt, n_trt):
    """单侧双比例 z 值：z > 0 表示实验组比例更高（更差）。"""
    p_c = x_ctrl / n_ctrl
    p_t = x_trt / n_trt
    pooled = (x_ctrl + x_trt) / (n_ctrl + n_trt)
    se = math.sqrt(pooled * (1 - pooled) * (1 / n_ctrl + 1 / n_trt))
    if se == 0:
        return 0.0
    return (p_t - p_c) / se


def p_value(z):
    """单侧 p 值（正态近似，n 大时够用）。"""
    return 0.5 * math.erfc(z / math.sqrt(2))


def required_samples(p0, mde, z_alpha=3.09, z_power=0.84):
    """按「要检测出的最小劣化 mde」反推每组样本量（α≈0.001，功效 80%）。"""
    p1 = min(p0 + mde, 0.999)
    return math.ceil((z_alpha + z_power) ** 2 *
                     (p0 * (1 - p0) + p1 * (1 - p1)) / (mde ** 2))


@dataclass
class Guardrail:
    """一条护栏指标。min_effect_* 是「业务显著」门槛，z_threshold 是「统计显著」门槛。"""
    name: str
    min_effect_abs: float                 # 绝对劣化下限（如 +0.5pp）
    min_effect_rel: float = 0.2           # 相对劣化下限（如 +20%）
    z_threshold: float = 3.09             # 单次 look 的 α≈0.001
    hard_limit: float = None              # 绝对红线，触发即回滚，不等统计

    def evaluate(self, ctrl, trt):
        n_c, x_c = ctrl
        n_t, x_t = trt
        if n_c == 0 or n_t == 0:
            return {"status": "insufficient", "detail": "无样本"}
        p_c, p_t = x_c / n_c, x_t / n_t
        delta = p_t - p_c
        if self.hard_limit is not None and p_t >= self.hard_limit:
            return {"status": "breach", "immediate": True,
                    "detail": f"{p_t:.2%} 触绝对红线 {self.hard_limit:.2%}"}
        need = required_samples(max(p_c, 1e-4), self.min_effect_abs)
        if n_c < need or n_t < need:
            return {"status": "insufficient",
                    "detail": f"样本 {min(n_c, n_t)} < 所需 {need}"}
        z = z_two_prop(x_c, n_c, x_t, n_t)
        meaningful = delta >= self.min_effect_abs and (
            p_c == 0 or delta / p_c >= self.min_effect_rel)
        if z >= self.z_threshold and meaningful:
            return {"status": "breach", "z": round(z, 2), "p": p_value(z),
                    "detail": f"+{delta:.2%}（相对 +{delta / max(p_c, 1e-9):.0%}）"}
        return {"status": "ok", "z": round(z, 2), "p": p_value(z),
                "detail": f"Δ={delta:+.2%}，未同时满足统计/业务显著"}


class RollbackJudge:
    """三态决策器：连续 N 个窗口双显著才回滚，避免单个窗口的噪声误杀。"""

    def __init__(self, guardrails, need_consecutive=2):
        self.guardrails = guardrails
        self.need = need_consecutive
        self.streak = {g.name: 0 for g in guardrails}

    def observe(self, samples):
        """samples: {指标名: ((n_ctrl, x_ctrl), (n_trt, x_trt))}，传每个窗口的增量。"""
        results = {}
        for g in self.guardrails:
            ctrl, trt = samples[g.name]
            r = g.evaluate(ctrl, trt)
            if r["status"] == "breach":
                self.streak[g.name] += 1
            elif r["status"] == "ok":
                self.streak[g.name] = 0
            results[g.name] = r
        hot = [name for name, s in self.streak.items() if s >= self.need]
        if hot or any(r.get("immediate") for r in results.values()):
            return "ROLLBACK", results
        if any(r["status"] in ("breach", "insufficient") for r in results.values()):
            return "HOLD", results
        return "KEEP", results


if __name__ == "__main__":
    err = Guardrail("error_rate", min_effect_abs=0.005, hard_limit=0.05)
    slow = Guardrail("slow_ratio", min_effect_abs=0.01)
    judge = RollbackJudge([err, slow])

    # 窗口 1：错误率 1.0% vs 1.3%，大样本下统计显著，但只差 0.3pp < 0.5pp
    d, r = judge.observe({
        "error_rate": ((200000, 2000), (200000, 2600)),
        "slow_ratio": ((200000, 10000), (200000, 10200)),
    })
    assert d == "KEEP", (d, r)
    assert r["error_rate"]["z"] > 3.09          # 统计显著
    assert "未同时满足" in r["error_rate"]["detail"]
    print("窗口1: 统计显著但业务不显著（+0.3pp）-> KEEP，不做无效回滚 ✅")

    # 窗口 2/3：错误率涨到 3%，连续两个窗口才回滚
    bad = {"error_rate": ((200000, 2000), (200000, 6000)),
           "slow_ratio": ((200000, 10000), (200000, 10400))}
    d1, _ = judge.observe(bad)
    assert d1 == "HOLD", d1                    # 单窗口先观察
    d2, _ = judge.observe(bad)
    assert d2 == "ROLLBACK", d2                # 连续两窗口 → 自动回滚
    print("窗口2/3: 连续两窗双显著 -> HOLD -> ROLLBACK ✅")

    # 样本不足：500 条里 4%，不下结论
    j2 = RollbackJudge([err, slow])
    d3, r3 = j2.observe({
        "error_rate": ((500, 5), (500, 20)),
        "slow_ratio": ((500, 25), (500, 25)),
    })
    assert d3 == "HOLD" and r3["error_rate"]["status"] == "insufficient"
    print("小样本: 500 条不足以判定 -> HOLD（没证据 ≠ 没问题）✅")

    # 绝对红线：6% 错误率，一个窗口就回滚
    j3 = RollbackJudge([err, slow])
    d4, r4 = j3.observe({
        "error_rate": ((1000, 10), (1000, 60)),
        "slow_ratio": ((1000, 50), (1000, 50)),
    })
    assert d4 == "ROLLBACK" and r4["error_rate"]["immediate"]
    print("硬红线: 6% >= 5% -> 立即 ROLLBACK ✅")

    print("所需样本(1%基线, +0.5pp):", required_samples(0.01, 0.005), "每组")
```

**追问**：1) 为什么不能「一看显著就回滚」？——两类错误：假阳性（噪声导致误杀好版本，回滚本身造成一次可用性抖动，还打击发布节奏）和假阴性（样本不足时真劣化检不出）。固定 look 次数 + 连续窗口 + 双门槛，本质是在控制**整体误回滚率**；工程上还要给回滚加冷却期（同一版本 N 小时内只自动回滚一次），避免抖动—回滚—再灰的死循环。2) 为什么「和历史同期比」不够，一定要同期基线桶？——历史同期只能控制日周期，控制不了当天的大盘波动（上游故障、活动、天气）；双桶同窗口对比把「时间」这个混杂因素消掉了，等价于一次简化 A/B。副作用是基线桶本身也可能被污染（同机房、共享依赖），所以要检查两桶的分层一致性（地域/机型/用户等级），必要时用分层抽样。3) 灰度 1% 时业务指标半天攒不够样本，怎么办？——三条路：放宽 MDE（只承诺检出大幅劣化，小幅劣化靠更长观察或放量后再判）、用代理指标（更敏感的先行指标，如加购率代替支付成功率）、先放量到能测出样本的比例再判（但放量本身扩大风险，需要用技术护栏兜底）。没有普适解，本质是「检测灵敏度 / 风险敞口 / 决策时延」三角取舍。

## 背诵要点
1. 对比必须用同期基线桶（消掉时间混杂），指标分技术护栏/业务/依赖三层，绝对红线只做兜底。
2. 样本量由 MDE 反推（1% 基线检 +0.5pp 约需每组 1.5 万）；样本不足输出 HOLD，禁止无限 peeking。
3. 双门槛（z≥3.09 且绝对/相对劣化达标）+ 连续 2 窗；三态 KEEP/HOLD/ROLLBACK，默认动作是摘灰度流量而非全量回滚。

## 复盘追问

2. 为什么「延迟 P99」不适合直接做双比例检验，而要先转成「慢请求占比」？（提示：分位数不是比例，没有可加的充分统计量；转成「超过阈值的请求占比」就变成二项比例，可以合并、可以做检验，代价是丢掉尾部形状信息）
