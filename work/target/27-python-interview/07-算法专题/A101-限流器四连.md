### A101 · 限流器四连

> 难度:★★★ | 标签:限流, 令牌桶, Redis, 场景题

**问**（笔试·编程+场景题）：现场实现一个限流器，要求：① 单机令牌桶（支持突发）；② 精确滑动窗口日志版；③ 升级到多实例部署用 Redis 怎么改；④ 服务冷启动怎么预热。写核心代码并说明各方案的精度/内存/适用场景。

**答**：① 令牌桶 = 惰性补给：不搞定时器，每次请求按 `(now - last)` 补币再扣，O(1) 且支持突发（桶容量即突发上限）；② 滑动窗口 = `deque` 存时间戳，头部过期即弹出，精确但内存 O(窗口内请求数)，只适合低频关键操作；③ 分布式版用 Redis Lua 把「读桶-补给-扣币-写回」原子化（**不能用 get/set 两步，并发下必超卖**）；④ 预热 = 初始令牌按比例给满或按时间线性抬升，避免冷启动被全量请求压垮。

```python
import time
from collections import deque

class TokenBucket:
    """惰性补给令牌桶：无后台线程，线程安全由调用方锁或换成 per-key 粒度。"""
    def __init__(self, rate: float, capacity: float):
        self.rate = rate                  # 每秒补充令牌数
        self.capacity = capacity          # 桶容量 = 最大突发
        self.tokens = capacity            # 预热默认给满；冷启动保护可改为 capacity * 0.3
        self.last = time.monotonic()

    def allow(self, cost: float = 1.0) -> bool:
        now = time.monotonic()
        self.tokens = min(self.capacity, self.tokens + (now - self.last) * self.rate)
        self.last = now
        if self.tokens >= cost:
            self.tokens -= cost
            return True
        return False

class SlidingWindowLog:
    def __init__(self, limit: int, window: float):
        self.limit, self.window = limit, window
        self.hits: deque[float] = deque()

    def allow(self) -> bool:
        now = time.monotonic()
        while self.hits and self.hits[0] <= now - self.window:
            self.hits.popleft()           # 头部过期弹出，deque O(1)
        if len(self.hits) < self.limit:
            self.hits.append(now)
            return True
        return False

# 分布式版核心：Redis Lua 原子令牌桶（单实例可用 above，多实例必走这里）
REDIS_LUA = """
local key, rate, cap, now, cost = KEYS[1], tonumber(ARGV[1]), tonumber(ARGV[2]),
    tonumber(ARGV[3]), tonumber(ARGV[4])
local b = redis.call('HMGET', key, 'tokens', 'ts')
local tokens = tonumber(b[1]) or cap
local ts = tonumber(b[2]) or now
tokens = math.min(cap, tokens + (now - ts) * rate)
local allow = 0
if tokens >= cost then tokens = tokens - cost; allow = 1 end
redis.call('HSET', key, 'tokens', tokens, 'ts', now)
redis.call('PEXPIRE', key, math.ceil(cap / rate * 2 * 1000))  -- 空闲桶自动回收
return allow
"""

if __name__ == "__main__":
    import threading
    tb = TokenBucket(rate=5, capacity=10)
    ok = [0]
    lock = threading.Lock()
    def worker():
        for _ in range(100):
            if tb.allow():
                with lock: ok[0] += 1
    ts = [threading.Thread(target=worker) for _ in range(8)]
    [t.start() for t in ts]; [t.join() for t in ts]
    # 突发 10 + 持续速率 5/s，短时间大量并发应被拒到只剩桶+速率量级
    assert ok[0] <= 15, ok[0]
    sw = SlidingWindowLog(limit=3, window=1.0)
    results = [sw.allow() for _ in range(6)]
    assert results[:3] == [True, True, True] and results[3] is False
    print("ok:", ok[0], "sw:", results)
```

**追问**：1) 为什么不用 Redis `GET`+`SET` 两步？——两步之间有窗口，10 个实例并发读同一个桶都判定可过，突发上限被放大 N 倍；必须 Lua 单命令原子化。2) 滑动窗口的内存怎么算？——每请求一个时间戳（float≈几十字节），1 万 QPS × 60s 窗口 ≈ 数百 MB，不可行；生产用**滑动窗口计数近似**（两个固定窗口按时间加权）或 Redis ZSET（精确但成本高）。3) 预热还有哪些手法？——按连接数线性抬升 rate、对下游连接池先发探活流量、JIT/缓存先热（GET 预取）。

## 背诵要点
1. 令牌桶不搞定时器：`(now-last)*rate` 惰性补给，桶容量=突发上限。
2. 多实例限流必须 Redis Lua 原子化「读-补-扣-写」，两步 get/set 必超卖。
3. 精确滑动窗口内存 O(窗口内请求数)，高 QPS 换加权近似或 ZSET。
