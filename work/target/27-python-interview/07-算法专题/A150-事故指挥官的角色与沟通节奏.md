### A150 · 事故指挥官

> 难度:★★☆ | 标签:事故响应, 沟通, 场景题

**问**（笔试·场景题）：三级事故拉了 8 个人进会议室——「事故指挥官」（IC）做什么（不是亲自修！），角色分工（IC/ Ops Lead/ comms/ scribe）各管什么，对外的沟通节奏（多久给一次状态更新、更新模板包含什么），「指挥官亲自下场修代码」为什么是反模式？

**答**：① IC 职责：**统筹不执行**——维护时间线、分配任务、做决策（回滚还是前滚）、控制范围（防止 8 个人都去修同一处）、判断升级（要不要拉更多资源/通知管理层）——IC 手里不能有键盘。② 角色四分：**IC**（决策）、**Ops Lead**（实际执行修复的工程师，最多 1-2 人）、**Comms**（对内对外沟通：状态更新/利益方通知——IC 不亲自写全员邮件，写邮件时没人指挥）、**Scribe**（时间线记录：分钟级事件日志——事后复盘的原料，事发时没人记就永远拼不出来）。③ 沟通节奏：**固定间隔**（P0 每 15-30 分钟一条状态更新，哪怕「没有新进展」也要发——沉默的会议室让每个利益方各自猜）、模板四要素（当前状态/已采取措施/下一步/下次更新时间）。④ 「IC 亲自修」反模式：IC 下场修代码 = 无人统筹（其他人在等指令）+ IC 的判断被执行细节占用（大问题看不到）——IC 的价值是全局视角，下场即失职。

```python
# 全部标准库；demo 实现「事故角色分工与沟通节奏器」
import time

class IncidentCommand:
    ROLES = ["IC", "ops", "comms", "scribe"]
    UPDATE_INTERVAL_S = 900                 # P0 每 15 分钟
    TEMPLATE = ["current_state", "actions_taken", "next_step", "next_update_at"]

    def __init__(self, severity: str = "P0"):
        self.severity = severity
        self.assigned: dict[str, str] = {}
        self.timeline: list[tuple[float, str]] = []
        self.last_update = time.monotonic()
        self.next_update_due = self.last_update + self.UPDATE_INTERVAL_S
    def assign(self, person: str, role: str):
        assert role in self.ROLES, f"角色仅限 {self.ROLES}"
        assert person not in self.assigned.values(), f"{person} 已有角色（一人一岗）"
        self.assigned[role] = person
    def guard_ic(self, person: str, wants_to_code: bool) -> str:
        """IC 下场修代码的反模式拦截。"""
        if self.assigned.get("IC") == person and wants_to_code:
            return "REJECT: IC 手里不能有键盘——把修复交给 Ops Lead，回统筹位"
        return "ok"
    def tick(self, event: str):
        self.timeline.append((time.monotonic(), event))
        now = time.monotonic()
        if now >= self.next_update_due:
            self.next_update_due = now + self.UPDATE_INTERVAL_S
            return f"状态更新（模板四要素）: 当前状态/已采取措施/下一步/下次更新 {self.UPDATE_INTERVAL_S//60}min 后"
        return None
    def comms_update(self, state: str, actions: str, nxt: str) -> dict:
        return dict(zip(self.TEMPLATE, [state, actions, nxt,
                                        f"{self.UPDATE_INTERVAL_S // 60}min 后"]))

if __name__ == "__main__":
    inc = IncidentCommand("P0")
    for p, r in [("alice", "IC"), ("bob", "ops"), ("carol", "comms"), ("dave", "scribe")]:
        inc.assign(p, r)
    print("角色分配:", inc.assigned)
    assert inc.guard_ic("alice", wants_to_code=True).startswith("REJECT")
    print("IC 下场拦截:", inc.guard_ic("alice", True))
    inc.tick("DB 连接耗尽")
    time.sleep(0.02)
    upd = inc.comms_update("部分功能受损", "已切换只读降级", "观察错误率决定是否回滚")
    print("对外更新模板:", upd)
    assert len(upd) == 4
    # 口径：IC 统筹不执行（手里不能有键盘）；四角色分工；P0 每 15-30 分钟固定节奏更新。
```

**追问**：1) 为什么「沉默的会议室」有害？——利益方（业务方/客服/管理层）在无更新时会各自行动（客服自己编话术/管理层自己下指令打乱修复优先级）——固定节奏更新哪怕「无进展」也能统一各方认知与动作。2) 小团队（3 个人）发生事故没有 4 个角色怎么办？（提示：角色合并但职责不合并——一人可兼任 IC+comms（修复交另一人）；核心纪律只有两条：**有人统筹、有人记录**——「全员都在修代码」是绝对禁止的最小红线）3) 事故升级（需要拉管理层）的判断标准？（提示：三信号——资损持续扩大、修复超出团队能力（需要跨团队资源）、影响面超预期（波及未预期用户群）；升级是 IC 的决策职责，犹豫要不要升级时通常应该升级）

## 背诵要点
1. IC 统筹不执行：维护时间线/分配任务/决策回滚/控制范围——IC 手里不能有键盘。
2. 四角色分工：IC（决策）/ Ops Lead（执行 1-2 人）/ Comms（沟通）/ Scribe（时间线记录）；小团队合并角色但「有人统筹+有人记录」是底线。
3. P0 每 15-30 分钟固定节奏更新（沉默即失控），模板四要素：状态/措施/下一步/下次更新时间。

## 复盘追问
1. 事故中 IC 判断失误（选了错误的修复方向）怎么办？（提示：Ops/其他角色有权提出异议（心理安全），IC 仍有最终决策权（事故中不能民主投票）；决策失误进复盘（A138）——复盘改的是「决策支持信息」而不是追究 IC 个人）
2. 事故处理完了，Scribe 的时间线记录怎么变成复盘的原料？（提示：时间线 + trace/日志交叉校准（人记的时间有偏差）→ A138 复盘会的分钟级时间线——Scribe 记录的价值在事后拼图，事发时看似多余）
