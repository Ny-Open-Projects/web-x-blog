### A226 · 值班负担长期趋势

> 难度:★★☆ | 标签:趋势分析, 治理, 团队

**问**（笔试·编程+场景题）：单周数据看不出结构性问题——「季度趋势分析」要看什么（告警总量的季度环比/告警类型的结构变化/服务维度的负担迁移），「结构性结论」怎么下（告警涨是因为新服务上线——这是「结构性告警」需要的是排班扩容不是降噪），趋势分析的「降噪与扩容」决策分界（什么信号表示「该加人/加班次」了），季度分析与周报（Q220）、月度评审（Q186）的三层体系怎么分工？

**答**：① 季度分析三视图：**总量趋势**（季度环比告警数——连续两季度上涨 >20% = 结构性增长）、**结构变化**（告警类型分布漂移：新服务告警占比从 5%→30%——负担来源迁移了）、**服务维度迁移**（负担从旧服务迁到新服务——排班/能力矩阵要跟着迁，Q190 覆盖矩阵联动）。② 结构性结论的判据：新服务上线告警涨 = **结构性告警**（解法：新服务 owner 承担其告警（排班扩容/路由调整），不是降噪（告警是真的））；存量服务告警涨 = 噪声劣化（解法：降噪专项）——「结构性问题用结构性手段，噪声问题用降噪手段」——决策分界就是归因。③ 决策分界：告警涨 + 归因新服务 + 服务 owner 无值班意愿 → 「该加人/加班次」信号（值班容量跟不上业务增长）；告警涨 + 归因存量噪声 → 降噪投入。④ 三层体系分工：**周报**（Q220）看周度信号（噪声 TopN/突发）、**月度评审**（Q186）执行改进项（行动项闭环）、**季度分析**看结构性趋势（排班扩容/路由重构/能力矩阵迁移）——颗粒度逐层放大，各自回答不同时间尺度的问题。

```python
# 全部标准库；demo 实现「季度趋势分析」
import statistics
from collections import Counter

def quarter_compare(quarters: list[dict]) -> dict:
    """季度对比：总量环比 + 结构变化 + 服务迁移。"""
    results = []
    for i in range(1, len(quarters)):
        prev, cur = quarters[i-1], quarters[i]
        growth = (cur["total"] - prev["total"]) / max(prev["total"], 1)
        structural = Counter(cur["by_service"]) - Counter(prev["by_service"])
        results.append({"q": i + 1, "growth": round(growth, 2),
                        "new_service_alerts": dict(structural)})
    consecutive_growth = all(r["growth"] > 0.2 for r in results)
    return {"quarters": results, "structural_growth": consecutive_growth}

def decision_boundary(attributions: dict[str, int]) -> dict:
    """决策分界：结构性告警→扩容；噪声→降噪。"""
    structural = {s: n for s, n in attributions.items() if s.startswith("new:")}
    noise = sum(n for s, n in attributions.items() if not s.startswith("new:"))
    return {"structural": structural,
            "action": "排班扩容 + 服务 owner 承担告警" if structural else "降噪专项",
            "noise_total": noise}

if __name__ == "__main__":
    qs = [{"total": 200, "by_service": {"legacy": 190, "new:svc-a": 10}},
          {"total": 260, "by_service": {"legacy": 185, "new:svc-a": 45, "new:svc-b": 30}},
          {"total": 330, "by_service": {"legacy": 180, "new:svc-a": 70, "new:svc-b": 80}}]
    r = quarter_compare(qs)
    print("季度环比:", [x["growth"] for x in r["quarters"]])
    assert r["structural_growth"]                  # 连续两季 >20% 增长
    d = decision_boundary({"new:svc-a": 70, "new:svc-b": 80, "legacy": 180})
    print("决策分界:", d["action"], "| 结构性告警:", d["structural"])
    assert d["action"].startswith("排班扩容")
    # 口径：连续两季 >20% 增长=结构性；新服务告警→扩容，存量噪声→降噪——归因定手段。
```

**追问**：1) 为什么「结构性告警」的解法是扩容而不是降噪？——新服务的告警是「真实信号」（新业务确实在报问题）——降噪它们=掩盖新业务的真问题；正确解法是「告警跟着 owner 走」（新服务 owner 排班/承担——业务扩张要配套值班扩张）——归因决定了手段（Q221 再平衡同构）。2) 「三层体系」会不会变成三套报表的维护负担？（提示：三层共享同一数据源（告警/工单/变更的原始数据），只是聚合粒度不同（周/月/季）——一套数据管道三个视图（Q220 自动草稿同构）——报表不是三套系统，是三个视图）3) 季度分析发现「值班容量跟不上业务增长」，除了加人还有什么解？（提示：值班容量=人 × 自动化水平——自动化处置（Q214 工具箱）让单人处理量提升；告警源头治理（让告警变少）也是扩容的替代——加人是最后手段，先提自动化与降噪）

## 背诵要点
1. 季度三视图：总量环比（连续两季 >20%=结构性增长）/结构变化（告警类型分布漂移）/服务迁移（负担随业务迁移）。
2. 决策分界按归因：新服务结构性告警→排班扩容+owner 承担；存量噪声→降噪专项——归因定手段。
3. 三层体系：周报（周度信号）/月度评审（行动项）/季度分析（结构性趋势）——同一数据源三个聚合视图。

## 复盘追问
1. 季度分析显示「告警总量降了但 P0 事故升了」——总量降是好事吗？（提示：总量降+P0 升 = 噪声治理有效但关键告警被误伤（降噪过头，Q7039 的反向风险）——趋势分析必须分层看（噪声降/P0 稳定才是健康；P0 升是红线）——单一指标的「总量」会误导）
2. 季度分析报告写了但「没人据此做排班调整」——分析到执行的断层怎么接？（提示：季度分析的结论直接生成排班/路由变更的行动项（进 A186 月度评审闭环）——分析的产出物是「可执行变更」不是「PDF 报告」——报告与执行系统的打通是分析价值的最后一公里）
