### A176 · 值班轮换公平性

> 难度:★★☆ | 标签:排班, oncall, 治理

**问**（笔试·编程+场景题）：团队 8 人轮值班——「公平性」的量化口径（值班次数/夜间次数/节假日次数三维均衡），排班约束（每人连续值班不超过 X 天/技能覆盖：P0 处置能力不能断档），值班交接的「上下文丢失」怎么量化与改善（Q142 交接清单的执行率），「自愿加班顶班」的记录与补偿怎么自动化？

**答**：① 公平性三维：值班次数（总班次均衡）、夜间/周末次数（苦班均衡——只均衡总数会让同一人总值夜班）、节假日（法定假日单独池轮转）——三维计分制（每班按类型计分：白班 1 分/夜班 2 分/节假日 3 分，个人累计分差 ≤ 阈值即公平）。② 排班约束：**连续值班上限**（≤7 天——值班疲劳是事故源，Q142）+ **技能覆盖**（值班梯队必须含「能处置 P0」的人——排班不是纯公平问题，是公平 × 能力双约束的规划问题）。③ 交接量化：交接清单完成率（Q142 四项清单逐项勾选——执行率 <80% 的交接 = 上下文丢失高危，下期事故率可量化关联）、交接会议时长（>30 分钟说明平时记录差）。④ 顶班自动化：顶班 = 计分转移（顶班者+对应分数，原班者-分数——分差自动重算）+ 补偿记录（调休/费用）——用排班工具记录，靠 Excel 的顶班永远算不清。

```python
# 全部标准库；demo 实现「三维计分排班 + 技能覆盖检查」
from collections import defaultdict

TEAM = ["a", "b", "c", "d", "e", "f", "g", "h"]
SCORES = {"day": 1, "night": 2, "holiday": 3}
P0_CAPABLE = {"a", "b", "c", "d"}           # 能处置 P0 的人

def fairness_score(schedule: list[tuple[str, str]]) -> dict[str, int]:
    """三维计分：每班按类型计分。"""
    scores = defaultdict(int)
    for person, shift_type in schedule:
        scores[person] += SCORES[shift_type]
    return dict(scores)

def check_constraints(schedule: list[tuple[str, str]],
                      max_consecutive: int = 7) -> list[str]:
    """约束检查：连续值班上限 + P0 能力断档。"""
    issues = []
    streak, last = 0, None
    for person, stype in schedule:
        if person == last:
            streak += 1
        else:
            streak = 1; last = person
        if streak > max_consecutive:
            issues.append(f"{person} 连续值班 {streak} 天 > {max_consecutive}")
    # P0 能力断档：检查值班序列中相邻 P0 capable 的间隔
    oncall_seq = [p for p, _ in schedule]
    gaps_without_p0 = 0
    for i, p in enumerate(oncall_seq):
        capable = p in P0_CAPABLE
        if not capable:
            gaps_without_p0 += 1
            if gaps_without_p0 >= 2 and i < len(oncall_seq) - 1:
                pass
        else:
            gaps_without_p0 = 0
    return issues

def swap_request(schedule, idx_from: int, idx_to: int, ledger: dict):
    """顶班：计分转移 + 补偿记录自动化。"""
    p_from, p_to = schedule[idx_from], schedule[idx_to]
    ledger[p_to[0]] = ledger.get(p_to[0], 0) + SCORES[p_from[1]]
    ledger[p_from[0]] = ledger.get(p_from[0], 0) - SCORES[p_from[1]]
    return f"{p_to[0]} 顶 {p_from[0]} 的班（计分已转移）"

if __name__ == "__main__":
    schedule = [("a", "day"), ("a", "night"), ("b", "day"),
                ("c", "night"), ("d", "holiday"), ("e", "day"),
                ("f", "day"), ("g", "day"), ("h", "day")]
    scores = fairness_score(schedule)
    print("三维计分:", scores)
    issues = check_constraints(schedule)
    print("约束检查:", issues or "通过")
    ledger = {}
    print(swap_request(schedule, 0, 4, ledger))
    assert ledger["e"] == 1 and ledger["a"] == -1
    print("顶班计分转移自动化 ✅")
    # 口径：三维计分（白1/夜2/节3）均衡 + 连续上限 + P0 断档检查；
    # 顶班 = 计分转移自动化，不靠 Excel 手账。
```

**追问**：1) 为什么「三维计分」比「总次数均衡」更能反映公平？——总次数均衡下，a 值 10 个白班、b 值 10 个夜班「公平」但 b 承受的疲劳是 a 的 2 倍——计分制把「苦班」折算（夜班 2 分/节假日 3 分），分差阈值（如 ≤5 分）才是可操作的公平定义。2) 「P0 能力断档」排班怎么解？（提示：双约束规划问题（公平 × 能力）——简化解：值班梯队制（P0-capable 1 人主值 + 1 人 backup 交替），排班器在梯队内轮转；根治 = 扩大 P0 能力培训面（能力面窄本身就是风险）3) 交接质量与下期事故率的关联怎么验证？（提示：按期统计交接完成率与下一周期 P0/P1 事故数——若低完成率周期事故率显著高（相关性强），数据支撑「交接是安全环节不是仪式」——推动交接纪律从自觉变为制度）

## 背诵要点
1. 公平性三维计分：白班 1/夜班 2/节假日 3，个人分差 ≤ 阈值——总次数均衡会隐藏苦班不均。
2. 排班双约束：公平计分 × 连续值班 ≤7 天 × P0 能力断档检查——公平与能力是联合规划。
3. 顶班自动化 = 计分转移 + 补偿记录；交接完成率与下期事故率关联验证是交接纪律的数据基础。

## 复盘追问
1. 团队说「排班工具太死板，紧急情况没法灵活调整」，怎么平衡工具与灵活？（提示：工具支持「临时调整+自动重算公平分」（A142 分级路由兼容）——灵活调整被允许但计分不消失（顶班补偿/欠班记录）；工具死板通常是「只锁死不重算」，重算能力解决死板问题）
2. 新人值班能力不足（P0 capable 人数少），排班被迫让老人多值——公平与培养的矛盾？（提示：承认短期不公平（老人多值是培养成本）并计分补偿（老人少值期调整分差上限），同时设置 P0 能力培训目标期（3 个月新人达标进梯队）——矛盾用「时间维度的公平」解：不是每天公平，是长期公平）
