### A215 · 交接重叠时段

> 难度:★★☆ | 标签:值班, 交接, 排班

**问**（笔试·场景题）：值班 9:00-18:00 与下一班 18:00-2:00 无缝交接——「无缝」的风险（18:00 整点交接时事故正在处理，责任瞬间真空），「重叠时段」（下班前 30 分钟两班同时在岗）怎么设计（重叠期谁主导），重叠期的成本（两班同时占用人力）与收益怎么权衡，跨时区团队的交接（北京-欧洲团队）怎么设计重叠？

**答**：① 无缝交接的风险：18:00 整点交接瞬间——在途事故的责任人换了（新值班还没上下文）、正在执行的命令中断——「交接瞬间」是事故高发点。**重叠 30 分钟**：交班方主导完成在途事务（或移交到可接手状态），接班方旁听熟悉——重叠期主导权在交班方。② 重叠权衡：30 分钟 × 每天两班 = 每天多 1 人时的成本——收益：交接质量（复述确认 Q184）+ 在途事务连续性；对比交接失败的成本（一次事故延误）——收益远大于成本。③ 跨时区重叠：北京 18:00 = 欧洲 12:00——重叠窗口天然存在（北京下午班尾与欧洲上午班头重叠 2-3 小时）——排班时**故意对齐**重叠窗口（交接动作放在重叠窗内），交接文档双语/英语（共同语言）。④ 在途事务移交标准：重叠期内「进行中的事务」要么完成（交方），要么移交到「可接手状态」（断点+上下文文档——Q7017 水位语义同构）——不允许「移一半」（做到一半没有文档的事务是交接最危险的物品）。

```python
# 全部标准库；demo 实现「重叠时段交接调度」
import time

SHIFTS = [("day", 9, 18), ("evening", 15, 24)]   # 重叠 15-18 点

def overlap_window(shifts: list[tuple]) -> tuple[int, int] | None:
    """两班重叠窗口（若有）。"""
    (n1, s1, e1), (n2, s2, e2) = shifts
    lo, hi = max(s1, s2), min(e1, e2)
    return (lo, hi) if lo < hi else None

def handoff_during_overlap(items: list[dict], overlap: tuple[int, int],
                           now_hour: int) -> dict:
    """重叠期内交接：进行中事务「完成或移交可接手状态」。"""
    lo, hi = overlap
    assert lo <= now_hour < hi, "交接必须在重叠窗内执行"
    plan = {}
    for it in items:
        if it["state"] == "进行中":
            if it["can_finish_in_overlap"]:
                it["plan"] = "交方完成"
            else:
                it["plan"] = "移交（附断点+上下文文档）"
                it["watermark"] = True           # Q7017 水位语义
        plan[it["name"]] = it.get("plan", "无需动作")
    return plan

if __name__ == "__main__":
    ov = overlap_window(SHIFTS)
    assert ov == (15, 18)
    print("重叠窗口:", ov, "（交班方主导）")
    items = [
        {"name": "慢查询排查", "state": "进行中", "can_finish_in_overlap": True},
        {"name": "故障恢复中", "state": "进行中", "can_finish_in_overlap": False},
        {"name": "例行巡检", "state": "已解决"},
    ]
    plan = handoff_during_overlap(items, ov, now_hour=16)
    for k, v in plan.items(): print(f"  {k}: {v}")
    assert plan["慢查询排查"] == "交方完成" and plan["故障恢复中"].startswith("移交")
    print("重叠期交接：完成或移交可接手状态，禁止「移一半」✅")
    # 口径：重叠 30min-2h（交方主导）；在途事务完成或移交可接手状态（水位语义）；
    # 跨时区故意对齐重叠窗。
```

**追问**：1) 为什么重叠期「主导权在交班方」？——交班方有完整上下文（知道在途事务的状态与坑），接班方只有书面清单——重叠期由交方主导完成/移交，接班方提问学习；主导权颠倒（接班方立即接手）会让交方的隐性知识无法转移。2) 「移一半的事务」为什么是最危险交接物？——新值班不知道：做到哪一步、踩过什么坑、下一步计划——相当于从半山腰接手登山；水位断点+上下文文档（Q7017）让「移一半」变得可接手——纪律是「移交必须有断点」，不是「不许移交」。3) 跨时区交接的「共同语言」成本？（提示：英语文档质量参差是大团队痛点——关键交接项用结构化模板（字段固定，填空式）替代自由文本降低语言要求；高风险项同步电话会议（语音比文档容错高）——结构化+语音双轨）

## 背诵要点
1. 无缝交接的整点瞬间是事故高发点：重叠 30 分钟-2 小时，重叠期主导权在交班方。
2. 在途事务移交标准：完成或移交「可接手状态」（水位断点+上下文文档）——禁止「移一半」。
3. 跨时区排班故意对齐重叠窗；结构化模板+语音双轨降低语言成本。

## 复盘追问
1. 重叠期制度执行后「重叠期变成聊天时间」（两班都没事干），怎么治理？（提示：重叠期任务清单化（交接复述+在途事务处置+巡检复核——30 分钟的议程排满）+ 重叠期产出抽查——议程化的重叠才不是闲聊）
2. 24×7 三班倒的重叠设计（三班要两两重叠），人力成本怎么算？（提示：三班两两重叠=每天多 2 人时——用「高峰重叠+非高峰快速交接」的混合设计（非高峰只留 15 分钟快速书面交接）——重叠密度按风险分级而非全天等密）
