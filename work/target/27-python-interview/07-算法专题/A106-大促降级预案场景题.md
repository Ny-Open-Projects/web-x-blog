### A106 · 大促降级预案场景题

> 难度:★★★ | 标签:降级, 熔断, 场景题

**问**（笔试·场景题）：大促晚 8 点流量预估 10 倍，你是值班负责人。列出降级预案矩阵：哪些功能该降、用什么开关、手动还是自动、降级后的用户体验；再实现一个带半开探测的自动熔断器代码。

**答**：预案四步：① **列依赖**：把调用链画出来，标出每条依赖挂掉时用户看到什么；② **分级降级开关矩阵**（配置中心热切换）：推荐/评论等非核心 → 直接开关关闭返回静态兜底；搜索 → 降级到缓存快照；下单链路 → 关闭积分扣减等旁路，只保主链；③ **自动熔断**兜手动开关：错误率/慢调用超阈值自动切断，半开试探恢复；④ **演练**：大促前压测 + 主动断依赖演练，验证每个开关真的生效。核心取舍：**降级是产品决策，熔断是技术兜底**，开关清单必须和业务方提前对齐。

```python
import time, threading

class Breaker:
    """三态熔断：closed -> (错误率超阈) open -> (冷却后) half-open -> 探测成功 closed。"""
    def __init__(self, fail_rate=0.5, min_req=20, window=60.0, cool=30.0):
        self.fail_rate, self.min_req, self.window, self.cool = fail_rate, min_req, window, cool
        self.hits: deque = __import__("collections").deque()   # (ts, ok)
        self.state, self.opened_at = "closed", 0.0
        self.lock = threading.Lock()

    def allow(self) -> bool:
        with self.lock:
            now = time.monotonic()
            if self.state == "open":
                if now - self.opened_at >= self.cool:
                    self.state = "half-open"       # 冷却结束，放行少量探测
                else:
                    return False
            if self.state == "half-open":
                return True                         # 探测请求直接放行，由 record 裁决
            while self.hits and self.hits[0][0] < now - self.window:
                self.hits.popleft()
            if len(self.hits) < self.min_req:
                return True                         # 样本不足不熔断，防误切
            fr = sum(1 for _, ok in self.hits if not ok) / len(self.hits)
            if fr >= self.fail_rate:
                self.state, self.opened_at = "open", now
                self.hits.clear()
                return False
            return True

    def record(self, ok: bool):
        with self.lock:
            if self.state == "half-open":
                if ok:
                    self.state = "closed"; self.hits.clear()   # 探测成功恢复
                else:
                    self.state, self.opened_at = "open", time.monotonic()  # 再熔断
                return
            self.hits.append((time.monotonic(), ok))

if __name__ == "__main__":
    br = Breaker(fail_rate=0.5, min_req=4, window=60, cool=0.1)
    for ok in [True, False, False, False]:          # 75% 失败率
        br.allow(); br.record(ok)
    assert not br.allow() and br.state == "open"    # 熔断打开
    time.sleep(0.15)
    assert br.state in ("half-open", "open")
    assert br.allow()                                # 半开放行探测
    br.record(True)
    assert br.state == "closed"                      # 探测成功恢复
    print("closed->open->half-open->closed 全链路 OK")
```

**追问**：1) 熔断和限流的区别？——限流保护**自己**（控制进入量），熔断保护**下游和链路**（不再打已经病了的依赖）；大促两者都要，限流在前。2) 半开态并发探测怎么控制？——探测流量要收敛（如只放 1/N 请求或单探测协程），否则半开瞬间把下游又打挂；生产实现（如 circuitbreaker 库）用原子计数限制半开并发。3) 为什么 `min_req` 样本不足不熔断？——低峰期 3 个请求错 2 个就熔断，会把正常业务打死；阈值要配最小样本量。

## 背诵要点
1. 降级矩阵 = 依赖清单 × 开关层级 × 手动/自动 × 用户兜底体验，提前与业务方对齐并演练。
2. 熔断三态：closed →（错误率超阈+最小样本）→ open →（冷却）→ half-open →（探测成功）closed。
3. 降级是产品决策、熔断是技术兜底：开关管「该不该」，熔断管「来不及」。
