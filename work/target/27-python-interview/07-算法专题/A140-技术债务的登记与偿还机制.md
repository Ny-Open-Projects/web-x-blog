### A140 · 技术债务治理

> 难度:★★☆ | 标签:技术债务, 治理, 场景题

**问**（笔试·场景题）：代码库里 200 处 TODO、50 个「临时方案跑了一年」——技术债务怎么登记（什么算债：只记「有意识的妥协」还是也记「无意识的坏味道」），债务的「利息」怎么量化（每笔债的持续成本），偿还机制怎么设计（专项 sprint vs 随手还），「这债不能还」的豁免机制怎么防滥用？

**答**：① 债的登记口径：**有意识的妥协**（明知不完美但为了交付速度选择绕行——有 owner/有原因/有触发条件）才算债，无意识的坏味道是「bug/重构需求」走另一条线（Q7011 规则治理）——混在一起债务台账就变成垃圾场。② 利息量化：每笔债记「它每周浪费多少」——修复困难度（每次改相关代码多花的时间）× 触碰频率（这块代码多久改一次）；利息高的债优先还（ROI），利息为零的债（死代码旁的 TODO）可以躺到触发条件出现。③ 偿还机制：**随手还**（碰到债务代码的改动，顺带修复 ≤2h 的债——不专项立项）+ **专项 sprint**（高利息债集中偿还，每季度 20% 容量）；「还债」也要走测试与 review（还债的 diff 同样是变更）。④ 豁免防滥用：豁免要「利息也要登记」（豁免≠免费，只是不还本金）+ 年度复审（豁免的理由还在吗）+ 豁免上限（单模块豁免数 >N 强制专项）。

```python
# 全部标准库；demo 实现「债务台账 + 利息排序 + 豁免审计」
import time

class DebtLedger:
    def __init__(self):
        self.debts: list[dict] = []
    def register(self, title: str, owner: str, reason: str, trigger: str,
                 fix_hours: float, touch_per_month: float):
        """登记：有意识的妥协才入账（无意识坏味道走重构需求）。"""
        interest = fix_hours * touch_per_month          # 月利息（小时）
        self.debts.append({"title": title, "owner": owner, "reason": reason,
                           "trigger": trigger, "fix_hours": fix_hours,
                           "touch": touch_per_month, "interest": interest,
                           "waived": False, "created": time.time()})
    def pay_off(self, title: str):
        d = next(d for d in self.debts if d["title"] == title)
        d["waived"] = False; d["paid"] = True
        self.debts.remove(d)
    def repay_plan(self, capacity_hours: float = 40) -> list[str]:
        """偿还计划：利息降序装填容量（ROI 优先）。"""
        live = sorted((d for d in self.debts if not d.get("waived")),
                      key=lambda d: -d["interest"])
        plan, used = [], 0
        for d in live:
            if used + d["fix_hours"] <= capacity_hours:
                plan.append(f"{d['title']}（利息 {d['interest']:.0f}h/月）")
                used += d["fix_hours"]
        return plan
    def waive_audit(self, max_waived_per_owner: int = 3) -> list[str]:
        """豁免审计：豁免也要年审理由 + 单人豁免上限。"""
        from collections import Counter
        waived = [d for d in self.debts if d.get("waived")]
        per_owner = Counter(d["owner"] for d in waived)
        return [f"{o} 豁免 {c} 笔超上限 {max_waived_per_owner}"
                for o, c in per_owner.items() if c > max_waived_per_owner]

if __name__ == "__main__":
    led = DebtLedger()
    led.register("订单服务直连 DB 绕过 API", "li", "大促前赶工", "订单域重构时", fix_hours=16, touch_per_month=4)
    led.register("日志格式两套并存", "wang", "双写过渡期", "采集器统一时", fix_hours=2, touch_per_month=0.5)
    led.register("遗留 SOAP 客户端", "zhao", "对接方不升级", "对方升级时", fix_hours=24, touch_per_month=0.2)
    plan = led.repay_plan(capacity_hours=40)
    print("偿还计划（利息 ROI 优先）:")
    for p in plan: print("  -", p)
    assert plan[0].startswith("订单服务"), "利息 64h/月 最高优先"
    for d in led.debts:
        if d["owner"] == "zhao":
            d["waived"] = True                          # 豁免：对方不升级，无法单方还
    for _ in range(4):                                  # 模拟 zhao 多笔豁免
        led.debts.append({**led.debts[-1], "owner": "zhao", "waived": True})
    print("豁免审计:", led.waive_audit(max_waived_per_owner=3))
    # 口径：债=有意识的妥协（带 owner/原因/触发条件）；利息=修复时长×触碰频率；
    # 随手还(≤2h)+专项 sprint；豁免也要年审理由并设上限防滥用。
```

**追问**：1) 为什么「无意识坏味道」不进债务台账？——台账的价值在「可追责可偿还」（有 owner/触发条件），无意识坏味道没有登记主体，混入后台账失去决策价值；它们走 lint/规则治理（Q7011）自动化消——两条线两套机制。2) 「利息高的债先还」会不会饿死低利息大债？（提示：会——大债（如 SOAP 客户端）利息低但终有一天触发（对方升级）；豁免机制就是给它的：明确「不还的理由与触发条件」，年审时条件变了再还——台账让「不还」成为显式决策而非遗忘）3) 随手还的边界（≤2h）为什么重要？（提示：超 2h 的「顺手修」会让功能迭代延期（还债挤占交付）；纪律是「小债顺手还、大债排期还」——不是「看到就修到天黑」）

## 背诵要点
1. 债 = 有意识的妥协（owner/原因/触发条件三要素），无意识坏味道走规则治理另一条线。
2. 利息 = 修复时长 × 触碰频率，ROI 排序装填偿还容量；豁免 ≠ 免费（豁免也年审理由+上限）。
3. 偿还双轨：随手还（≤2h 顺带）+ 专项 sprint（每季度 20% 容量）；还债 diff 同样走测试 review。

## 复盘追问
1. 老板说「技术债不影响业务先别还」，你怎么说服？（提示：用利息说话——账上债务月利息 X 小时（有台账数据）= 每个迭代实际慢 Y%；再举一次「债务引发的线上事故」案例——数据+故事双管）
2. 债务台账本身没人维护（登记了没人看），怎么让它活着？（提示：台账进迭代流程（排期会看 repay_plan）+ 利息自动计算（从 git 触碰频率统计）+ 债务数与利息进团队健康分——机制要嵌入现有流程而非新开体系）
