### A138 · 事故复盘组织

> 难度:★★☆ | 标签:复盘, blameless, 治理

**问**（笔试·场景题）：三级事故（资损级）跨两个团队——复盘会怎么组织（谁主持/谁参加/什么时间开），blameless（无责复盘）的边界在哪——「无责」是不是「不追责」（人对行为负责、系统对设计负责的区分），复盘产物（时间线/根因/行动项）怎么落地才不是「文档进了坟场」，行动项的闭环机制是什么？

**答**：① 复盘会组织：**48 小时内开**（记忆新鲜、情绪稳定——事故当天下属紧张不宜复盘）、主持人=中立第三方（非当事团队 leader，SRE/架构师）、参加者=当事人+受影响方+相关架构决策者，**不邀请高管旁听**（高管在场，当事人自动进入自保模式，信息不全）。② blameless 边界：复盘的对象是**系统与流程**（为什么允许这个操作发生？为什么没有护栏？），不是**人**（谁按的按钮）——但「无责」≠「不追责」：**故意违规**（明知禁令绕过审批）与**恶意**要追责，**在规则内犯的错**不追人追系统（规则内犯错说明规则有漏洞）——区分标准写进复盘章程，事前公示。③ 产物落地：时间线（分钟级，从 trace/日志重建）、根因（5-Why 到流程层为止）、行动项（每项有 owner/deadline/验证方式）——闭环机制：行动项进事故系统追踪（不是 wiki），超期未完成升级到架构周会，**下个复盘会先过上个复盘会的行动项**（惯例强制）。

```python
# 全部标准库；demo 实现「行动项闭环追踪器」
import time

class ActionTracker:
    """复盘行动项：deadline + 验证方式 + 超期升级。"""
    def __init__(self, escalate_after_days: int = 14):
        self.items: list[dict] = []
        self.escalate = escalate_after_days
    def add(self, title: str, owner: str, deadline_days: int,
            verify: str, from_incident: str):
        self.items.append({"title": title, "owner": owner,
                           "deadline": time.time() + deadline_days * 86400,
                           "verify": verify, "incident": from_incident,
                           "status": "open", "created": time.time()})
    def review(self) -> dict:
        now = time.time()
        overdue = [i for i in self.items
                   if i["status"] == "open" and now > i["deadline"]]
        for i in overdue:
            age = (now - i["created"]) / 86400
            if age > self.escalate:
                i["status"] = "escalated"      # 超期升级到架构周会
        return {"open": sum(1 for i in self.items if i["status"] == "open"),
                "escalated": [i["title"] for i in self.items if i["status"] == "escalated"]}
    def gate_next_review(self, incident_id: str) -> bool:
        """下个复盘会的准入闸：同源未闭环行动项 >0 则先过旧账。"""
        return any(i["incident"] == incident_id and i["status"] == "open"
                   for i in self.items)

if __name__ == "__main__":
    tr = ActionTracker(escalate_after_days=14)
    tr.add("DB 连接池加监控告警", "ops-zhang", 7, "告警配置 PR 合入", "INC-101")
    tr.add("幂等键全链路透传改造", "dev-li", 30, "契约测试覆盖", "INC-101")
    tr.items[0]["deadline"] -= 20 * 86400         # 模拟超期
    review = tr.review()
    assert review["open"] == 2
    assert len(review["escalated"]) == 1 and "监控" in review["escalated"][0]
    print("行动项闭环:", review)
    assert tr.gate_next_review("INC-101") is False  # INC-101 行动项已超期升级
    print("下个复盘会准入闸：INC-101 超期项已升级，需先过旧账 ✅")
    # blameless 边界口径：规则内犯错=修系统不追人；故意违规/恶意=追责，章程事前公示。
```

**追问**：1) 为什么复盘会「不邀请高管旁听」？——高管在场改变信息流动：当事人倾向轻描淡写、争论转向「谁的锅」——需要的完整真相拿不到；高管通过书面复盘报告获取结论（报告同样 blameless 风格）。2) 「规则内犯错不追人」会不会纵容故意犯错？（提示：边界是故意违规追责——纵容论混淆了「无责」与「无后果」；规则内错误对人无责但对系统有行动项，故意违规有后果（绩效/纪律）——两套账分开记）3) 5-Why 到哪层停？（提示：到「流程允许」层停（为什么没护栏→因为流程没要求）就够——再往下问会到「宇宙大爆炸」；追责到流程层的行动项是可执行的，追到个人层的「下次小心」不可执行）

## 背诵要点
1. 复盘会 48h 内开、中立第三方主持、不邀高管旁听——保护信息完整性。
2. blameless 边界：规则内犯错修系统不追人，故意违规/恶意追责——两套账分开，章程事前公示。
3. 行动项闭环：进事故系统（非 wiki）、deadline+owner+验证方式、超期升级架构周会、下个复盘会先过旧账。

## 复盘追问
1. 两个团队复盘时互相甩锅（都是对方的代码问题），主持人怎么破局？（提示：回到时间线事实（trace/日志重建的客观记录）+ 把「谁的代码」转为「为什么测试/护栏没拦住」（系统问题，双方共同行动项）——主持人有权把「人/团队」议题改判为「系统」议题）
2. 行动项全部按时完成，三个月后同型事故又发生——复盘体系哪里失效了？（提示：行动项「完成」≠「有效」——验证方式要包含「防复发验证」（同型故障注入演练），且复盘间要建立模式关联（同型事故 ≥3 次升级为专项治理，参照课程 11 豁免台账模式））
