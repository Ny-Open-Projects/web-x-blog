### A247 · 手写一致性哈希环

> 难度:★★★★ | 标签:一致性哈希, 虚拟节点, 副本放置, 迁移量

**问**（笔试·编程题）：实现一个能上生产的一致性哈希环：① `add(node, weight)` / `remove(node)` / `locate(key)`，定位 O(log V)；② 支持虚拟节点数量配置；③ 支持异构节点权重（16C 与 32C 机器不该分到同样多的 key）；④ 副本放置 `replicas(key, n)` 必须返回 **n 个不同的物理节点**；⑤ 提供迁移账本：任意一次扩容/缩容前后，逐 key 对比归属，输出实际迁移条数与迁移率，并与理论值 1/(N+1) 对照；⑥ 提供倾斜度度量（max/mean、CV）。约束：纯标准库、可复现（同一 key 必须永远落到同一节点）、环上点冲突不能丢点。请说明 Q1341（环与最小迁移）、Q2329（虚拟节点实测）、Q2493（迁移率对比）已经覆盖了什么，本题的增量在哪，以及副本、权重变更、缩容三处的工程坑。

**答**：① 与已有卡的分工：Q1341 证明了「增删节点只搬 1/N」；Q2329 用实验回答「vnode 该取多少」（极差、迁移率随 vnode 数的曲线，结论是 100 左右收益饱和）；Q2493 横向对比取模 / 16384 槽 / 哈希环的迁移率。三张卡停在「分布是否均匀、迁移率是多少」。本题补四件线上真会踩的事——**权重、副本、点冲突、迁移账本**。② 结构与定位：有序点数组 + `bisect`，点存 64 位整数；`locate` 用 `bisect_right` 取严格大于 key 哈希的第一个点，越界则 `% len` 回绕。用 `bisect_left` 也能工作，但「哈希恰好等于某个虚拟点」的归属会不同，全链路（客户端、代理、迁移工具）必须统一，否则同一个 key 在两边算不出同一个主。③ 权重：异构机型按容量分点，`weight=2` 就给双倍虚拟点。代价是**权重调整本身就是一次迁移**——把某节点从 1 调到 2，等于它从所有邻居各抢一段弧，迁移量与「新增一台同容量节点」同量级，所以必须和扩容走同一套灰度、账本、限速流程，不能热改。④ 副本：最容易写错的一步。一台物理机有 160 个虚拟点，环上连续几个点大概率同主，直接取「顺时针下 3 个点」很可能三个都是同一台机器，`RF=3` 退化成 1，宕机直接丢数据。正确做法是顺时针扫描、**跳过已选物理节点**，扫满一圈仍不够就返回实际能给的副本数（节点数 < 副本数时不能假装成功）。⑤ 点冲突：64 位空间里 100 万虚拟点的碰撞期望约 n²/2/2⁶⁴ ≈ 2.7e-8，看起来可以忽略，但工程上真正的问题是**同一条 hash 串的重复**（配置错误把同一节点加了两次、或从备份恢复的节点名重复），一旦发生，`owner[point]` 被覆盖，环少一个点、原来那段弧的 key 无主。所以写入时做确定性线性探测（冲突就 +1 找下一个空位），并且 `remove` 必须用 `add` 时**存下来的点列表**，不能重新计算——重新算出来的值不含探测偏移，删不掉真正的点。⑥ 迁移账本：改环之前先 dry-run，逐 key 比新旧归属，得到「搬多少条、影响哪几个源节点、要多少带宽」。账本的意义在于两个数字不同：**迁移条数**决定带宽和耗时（要限速，打满网卡会拖垮线上），**迁移率**决定缓存失效率（决定回源压力，Q2488 的未命中风暴）。本 demo 3→4 节点实测迁移 25.0%（理论 25.0%），同一批 key 用取模则搬 75.2%。⑦ 倾斜度：用 CV（标准差/均值）比极差稳，极差会被单个异常节点带偏。160 vnode、3 节点实测 max/mean=1.102、CV=0.076；要压到 1.05 以下需要几百 vnode 或换有界负载哈希（超载节点主动把 key 让给后继），后者代价是查找不再是纯 `bisect`。⑧ 两个必须点破的边界：**均匀 ≠ 均衡**——一致性哈希均衡的是 key 条数，不是 QPS，一个 10 万 QPS 的热 key 落哪台哪台死，得靠热 key 拆分；**缩容顺序**——先标记 draining 把写路由摘走，再迁存量、校验、最后 `remove`，直接摘点会把在途写丢在旧节点上。⑨ 与槽位方案的取舍：16384 槽是显式分配表，迁移可枚举、可精确限速、可分批；哈希环是概率均衡，迁移量是期望值。要精细控制节奏用槽，要对节点数无感伸缩用环。

```python
# 全部标准库；环 + 虚拟节点 + 权重 + 副本 + 迁移账本 + 倾斜度度量
import bisect
import hashlib
import statistics

MASK = (1 << 64) - 1


def h64(s):
    return int.from_bytes(hashlib.md5(s.encode()).digest()[:8], "big")


class Ring:
    """一致性哈希环：虚拟节点 + 权重 + 副本 + 迁移账本。"""

    def __init__(self, vnodes=160):
        if vnodes <= 0:
            raise ValueError("vnodes 必须为正")
        self._vnodes = vnodes
        self._points = []
        self._owner = {}
        self._node_points = {}
        self._weight = {}

    def _place(self, node, count):
        pts = []
        for i in range(count):
            p = h64("%s#%d" % (node, i))
            probes = 0
            while p in self._owner:          # 点冲突：线性探测，绝不覆盖别人的点
                p = (p + 1) & MASK
                probes += 1
                if probes > 64:
                    raise RuntimeError("环上点冲突过多，换哈希函数")
            self._owner[p] = node
            bisect.insort(self._points, p)
            pts.append(p)
        return pts

    def add(self, node, weight=1):
        if node in self._node_points:
            return
        count = max(1, int(round(self._vnodes * weight)))
        self._node_points[node] = self._place(node, count)
        self._weight[node] = weight

    def remove(self, node):
        for p in self._node_points.pop(node):    # 用存下来的点，不能重算
            self._owner.pop(p, None)
            i = bisect.bisect_left(self._points, p)
            if i < len(self._points) and self._points[i] == p:
                self._points.pop(i)
        self._weight.pop(node, None)

    def locate(self, key):
        if not self._points:
            return None
        idx = bisect.bisect_right(self._points, h64(key)) % len(self._points)
        return self._owner[self._points[idx]]

    def replicas(self, key, n):
        """顺时针取 n 个不同物理节点；虚拟点再多也只算一个物理节点。"""
        if not self._points:
            return []
        start = bisect.bisect_right(self._points, h64(key)) % len(self._points)
        out, seen = [], set()
        for step in range(len(self._points)):
            node = self._owner[self._points[(start + step) % len(self._points)]]
            if node not in seen:
                seen.add(node)
                out.append(node)
                if len(out) == n:
                    break
        return out

    def distribution(self, keys):
        cnt = {n: 0 for n in self._node_points}
        for k in keys:
            cnt[self.locate(k)] += 1
        return cnt

    def imbalance(self, keys):
        cnt = self.distribution(keys)
        vals = list(cnt.values())
        mean = sum(vals) / len(vals)
        return {"counts": cnt, "max_over_mean": round(max(vals) / mean, 4),
                "cv": round(statistics.pstdev(vals) / mean, 4)}


def migration(src_ring, dst_ring, keys):
    """逐 key 比归属：返回 (迁移条数, 迁移率, 受影响的源节点)。"""
    moved, touched = 0, set()
    for k in keys:
        a, b = src_ring.locate(k), dst_ring.locate(k)
        if a != b:
            moved += 1
            touched.add(a)
    return moved, moved / len(keys), touched


def modulo_ring(nodes):
    class M:
        def locate(self, key):
            return nodes[h64(key) % len(nodes)]
    return M()


if __name__ == "__main__":
    keys = ["user:%d" % i for i in range(20000)]
    ring = Ring(vnodes=160)
    for n in ("s0", "s1", "s2"):
        ring.add(n)

    # 1) key 定位：确定性 + 只落在环上节点
    assert ring.locate("user:42") == ring.locate("user:42")
    st = ring.imbalance(keys)
    assert set(st["counts"]) == {"s0", "s1", "s2"}
    assert st["max_over_mean"] < 1.25, st
    print("3 节点 160 虚拟点: 倾斜 max/mean=%.3f cv=%.3f ✅"
          % (st["max_over_mean"], st["cv"]))

    # 2) 扩容迁移量：一致性哈希 ≈ 1/(N+1)，取模 ≈ 全部
    grown = Ring(vnodes=160)
    for n in ("s0", "s1", "s2", "s3"):
        grown.add(n)
    moved, ratio, touched = migration(ring, grown, keys)
    assert 0.20 <= ratio <= 0.30, ratio
    assert touched <= {"s0", "s1", "s2"} and "s3" not in touched
    mod_old, mod_new = modulo_ring(["s0", "s1", "s2"]), modulo_ring(["s0", "s1", "s2", "s3"])
    mmoved, mratio, _ = migration(mod_old, mod_new, keys)
    assert mratio > 0.70, mratio
    print("扩容 3→4: 哈希环迁移 %d 条 (%.1f%%)，理想 25.0%%；取模迁移 %d 条 (%.1f%%) ✅"
          % (moved, ratio * 100, mmoved, mratio * 100))

    # 3) 缩容：下线节点的 key 全部搬给后继，其余节点内部不动
    shrunk = Ring(vnodes=160)
    for n in ("s0", "s2", "s1"):
        shrunk.add(n)
    shrunk.remove("s1")
    assert "s1" not in shrunk._node_points
    assert all(shrunk.locate(k) in ("s0", "s2") for k in keys[:2000])
    lost = [k for k in keys[:2000] if ring.locate(k) == "s1"]
    assert all(shrunk.locate(k) in ("s0", "s2") for k in lost)
    others_kept = sum(1 for k in keys[:2000]
                      if ring.locate(k) != "s1" and shrunk.locate(k) == ring.locate(k))
    assert others_kept == 2000 - len(lost)
    print("缩容下线 s1: %d 条 key 全部改归 s0/s2，其余 %d 条零迁移 ✅"
          % (len(lost), others_kept))

    # 4) 副本：3 副本必须来自 3 个不同物理节点，且首位与 locate 一致
    rep = ring.replicas("order:8899", 3)
    assert len(rep) == 3 and len(set(rep)) == 3
    assert rep[0] == ring.locate("order:8899")
    assert ring.replicas("order:8899", 5) == rep   # 只有 3 个物理节点，取不到更多
    print("副本放置: %s（首位=locate）✅" % (rep,))

    # 5) 异构权重：weight=2 的节点理论上分到 2 倍虚拟点与 2 倍 key
    weighted = Ring(vnodes=160)
    weighted.add("big", weight=2)
    weighted.add("small", weight=1)
    wc = weighted.distribution(keys)
    ratio_w = wc["big"] / wc["small"]
    assert 1.7 <= ratio_w <= 2.3, ratio_w
    print("权重 2:1 -> key 分布 %d:%d = %.2f 倍 ✅" % (wc["big"], wc["small"], ratio_w))

    # 6) 点冲突探测：人为制造大量同址点也不会丢 owner
    tiny = Ring(vnodes=1)
    for i in range(50):
        tiny.add("n%d" % i)
    assert len(tiny._points) == 50 and len(tiny._owner) == 50
    print("50 个单虚拟点节点零冲突丢点: 环上 %d 点 ✅" % len(tiny._points))
```

**追问**：1) 副本为什么不能直接取「顺时针下 N 个虚拟点」？—— 一台物理机占 160 个虚拟点，环上相邻的几个点大概率同主，取 3 个点很可能三个都是同一台机器；写三份等于写一份，宕机即丢数据。必须按物理节点去重，扫满一圈仍不足就如实返回更少的副本数，让上层决定「降级为 RF=2」还是「拒绝写入」——静默返回重复节点是最危险的实现。2) 把某节点的 weight 从 1 调到 2 会发生什么？—— 它的虚拟点翻倍，等于从所有邻居各抢一段弧，迁移量与新增一台同容量机器同量级；而且方向是「大量 key 涌入该节点」，如果它本来就接近容量上限，这一次调整就可能是压垮它的那根稻草。所以权重变更要按变更管理走：先算账本 → 限速迁移 → 观察命中率与负载 → 再确认。3) 加一个节点，迁移量一定会等于 1/(N+1) 吗？—— 不会，那只是期望值。虚拟点有限（160 个）时，新节点覆盖的弧长有随机偏差；权重更高时按比例放大；如果新节点名恰好与既有虚拟点哈希冲突，探测位移还会让弧段整体偏移一点。所以账本必须实测，公式只用来做上限预估和带宽预留。

## 背诵要点
1. 定位 = 有序点数组 + `bisect_right` + 回绕取模；虚拟点是解决「节点少时分布不均」和「宕机负载压垮邻居」的唯一手段，100-200 个即收益饱和。
2. 三处必踩坑：副本必须按物理节点去重（否则 RF=3 退化 1）；点冲突要确定性探测且删除用存下来的点表；权重调整等价一次扩容，必须走灰度与限速。
3. 迁移账本要看两个数：条数（决定带宽与限速）、比率（决定缓存失效率与回源压力）；倾斜度用 CV 判，max/mean < 1.2 可接受，160 vnode 实测 CV≈0.076。

## 复盘追问
1. 环上加完节点，缓存命中率没降但 DB 负载暴涨，为什么？（提示：迁移的是 key 归属，不是 key 的值——新节点上还没有数据，所有被搬走的 key 第一次读必然穿透回源；迁移必须配「预热/懒加载 + 回源限速」，否则迁移率 25% 就是 25% 的瞬时穿透）
2. 客户端与服务端各算一次环，结果不一致，会出什么事故？（提示：同一个 key 被两边判给不同节点，读走 A 写走 B，表现为「刚写就读不到」的随机丢读；根因通常是 bisect 边界（left/right）、hash 截断位数、节点名字符串格式不统一，所以环的实现要作为协议版本管理，变更时必须双算比对一周）
