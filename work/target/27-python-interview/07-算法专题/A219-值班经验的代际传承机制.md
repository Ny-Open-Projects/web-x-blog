### A219 · 值班经验代际传承

> 难度:★★☆ | 标签:知识传承, 值班, 团队

**问**（笔试·场景题）：老员工离职时说「这个告警看起来吓人但 usually 是误报」——「usually 这种直觉」怎么显性化传承（直觉=统计规律，用数据替代直觉），「隐性经验」的三类（判断类/操作类/联络类）各自的沉淀方式，经验传承的验证（传承后新人能复现老手的判断吗），经验库与值班系统（A166 路由/手册 A142）的集成点在哪？

**答**：① 直觉显性化：「usually 误报」= 统计规律（该告警历史触发 100 次 95 次误报）——显性化 = 把直觉翻译成数据（告警元数据加「历史误报率 95%」字段，值班看到数字而非「听说吓人」）——**数据替代直觉**是传承的核心方法：老员工的每条直觉都能翻译成「历史统计+条件判断」。② 隐性经验三类：**判断类**（这个告警是误报/这个错误率正常——用统计+阈值显性化）、**操作类**（这个服务重启要先停消费者——用 runbook 步骤显性化，A142）、**联络类**（这个 API 的问题找供应商的谁——用专家库/联系人字段显性化，A218）——三类各有显性化工具，混为一谈导致「不知道怎么写下来」。③ 传承验证：老手直觉翻译后，新人用显性化资产**复现老手的判断**（同一批告警，新人按数据判断与老手判断一致率 >90%——不一致=翻译不完整，继续补）——传承不验证 = 资产没有可信度。④ 集成点：判断类 → 告警元数据（A166 路由矩阵输入）、操作类 → runbook（A142 手册）、联络类 → 专家库（A218）——经验传承不是独立系统，是既有值班基础设施的填充。

```python
# 全部标准库；demo 实现「直觉显性化 + 传承验证」
import time

ALERT_HISTORY = [("conn_pool_warn", True)] * 95 + [("conn_pool_warn", False)] * 5
# 100 次触发 95 次误报（is_error=False 为误报）

def alert_stats(name: str, history: list) -> dict:
    total = sum(1 for n, _ in history if n == name)
    real = sum(1 for n, real in history if n == name and real)
    return {"name": name, "total": total, "real_pct": real / max(total, 1)}

def translate_intuition(stats: dict) -> str:
    """直觉 → 数据：「usually 误报」翻译成历史误报率字段。"""
    if stats["real_pct"] < 0.1:
        return f"历史误报率 {stats['real_pct']:.0%} → 元数据标 low-trust，处置=记录后次日复核（非立即）"
    return "真实告警率正常 → 立即处置"

def transfer_verify(veteran_judgments: list[bool], rookie_judgments: list[bool]) -> float:
    """传承验证：新人按显性化资产判断与老手的一致率。"""
    assert len(veteran_judgments) == len(rookie_judgments)
    agree = sum(1 for v, r in zip(veteran_judgments, rookie_judgments) if v == r)
    return agree / len(veteran_judgments)

if __name__ == "__main__":
    stats = alert_stats("conn_pool_warn", ALERT_HISTORY)
    print("告警统计:", stats)
    print("直觉翻译:", translate_intuition(stats))
    assert "95%" in translate_intuition(stats)
    # 传承验证：20 个告警样本，新人按显性化资产判断
    vet = [False] * 19 + [True]
    rook = [False] * 19 + [True]
    agree = transfer_verify(vet, rook)
    assert agree == 1.0
    print(f"传承验证: 新人判断一致率 {agree:.0%} ≥90% ✅")
    # 口径：直觉=统计规律，用数据显性化；三类经验各有工具（元数据/runbook/专家库）；
    # 传承验证=新人复现老手判断一致率 ≥90%。
```

**追问**：1) 为什么「数据替代直觉」是传承的核心方法？——直觉无法被新人学习（直觉在老手脑内是无数次统计的压缩）——显性化为数据后新人可以直接使用统计结论（不需要重新积累 100 次经验）；「直觉」本质是老手替新人跑过的统计——翻译成字段即可无损传承。2) 统计规律「95% 误报」与新告警的关系？（提示：统计是历史分布，新告警仍可能真故障（5% 的真报）——低信任标注 ≠ 不处理（是「降级处置」：记录+次日复核而非立即叫醒，Q7039 降噪语义）；且统计窗口定期刷新（系统变化后误报率可能变））3) 「三类经验」分类错位的后果？（提示：联络类经验写成 runbook 步骤（找谁——写成步骤但人离职就失效）——分类错位=用了错误的显性化工具（联络类要用专家库的动态字段而非静态文档）——分类是传承质量的第一步）

## 背诵要点
1. 直觉显性化 = 翻译成「历史统计+条件判断」（老手的直觉是替新人跑过的统计）——数据替代直觉。
2. 隐性经验三类各有工具：判断类→告警元数据（统计字段）、操作类→runbook、联络类→专家库。
3. 传承验证 = 新人用显性化资产复现老手判断，一致率 ≥90%；低信任标注 ≠ 不处理，是降级处置。

## 复盘追问
1. 老手说「我的直觉没法用数据表达」（不可言传），怎么破？（提示：案例引导——老手对新告警做 10 次判断，回放历史统计对比——直觉的判断结果可记录可对比（「不可言传」通常指原因不可言传，判断本身可记录）——判断可记录→统计可提取→直觉可翻译）
2. 经验传承做了但「传承的是三年前的经验」（系统早已变化），怎么防？（提示：显性化资产与告警/服务绑定（服务变更触发资产复审，Q168 文档时效同构）+ 传承验证用「近期样本」而非历史样本（近期一致的资产才可信）——经验资产与文档一样需要时效治理）
