### A272 · 跳表的随机层高实证与查找路径账

> 难度:★★★★ | 标签:跳表, 概率数据结构, 层高分布, 复杂度实证, 平衡树对比

**问**（笔试·编程题）：Q982 已经回答了「跳表为什么 O(logN)、Redis 为什么选它不选平衡树」的概念层，并给了最小插入+范围查询实现。本题往下挖一层，做**实证审计**：实现一个完整的跳表——① 插入（幂等：重复 key 拒绝）、查找、删除（删除后高层空链要收缩）、半开区间范围查询 `[lo, hi)`，全部基于同一个 `update[]` 前驱数组；② **层高随机性实证**：`p=0.5` 时节点层高服从截断几何分布，理论期望指针数 = `Σ p^(k-1) ≈ 2.0`——插入 3 万节点后实测层高 1 的占比与平均指针数，与理论值对账；③ **查找路径账**：统计全部查找的「右移步数」，实测平均值与 `log2(N)` 对账，并断言与理论量级吻合；④ 删除 600 个 key 后范围查询仍与 `sorted` 基准逐元素相等（自证结构没被删坏）；⑤ 与平衡树的对比不写代码，但要说出三条硬理由：旋转 vs 无旋转、范围查询谁顺着链走、并发改造谁更容易。请说清与 Q982（概念与最小实现）、Q494（`bisect` 有序数组二分：读快写 O(n)）的分工——本题只回答「**跳表的完整增删查实现、随机层高与查找路径的实证对账**」。

**答**：① 分工：Q982 是「是什么、为什么」；Q494 是「有序数组的二分」——读 O(logN) 但写要整体搬移；本题补「完整实现 + 概率承诺的实证验收」。跳表的核心承诺有两个数字：层高期望指针数 ≈ `1/(1-p)`（p=0.5 时即 2.0），查找期望步数 ≈ `log_{1/p} N`（p=0.5 时即 log2 N）——面试官不满足于「期望 O(logN）」这句话，会问「你怎么知道实现真的兑现了这个承诺」，答案就是跑分布对账。② 实现要点：`_find_update(key)` 从顶层向下，每层先右移再下沉，沿途记录每层的前驱到 `update[]`——插入、删除、查找共用这一个定位函数，这是跳表实现不写错的关键（三个操作的前驱计算逻辑完全一致，分开写就是三份 bug）。插入时新节点层高由 `_height()` 独立掷出：`while h < MAX and rng.random() < p: h += 1`，与现有树高无关——**层高只由硬币决定，与数据分布零耦合**，这是它对输入序列不敏感（不受有序插入退化影响）的根源，也是对平衡树的第二优势。删除后要收缩 `self.level`：最高层的 head.forward 变 None 就降一层，否则顶层全是空链、查找白跑。③ 实测对账：3 万节点下，层高 1 占比实测 0.500（理论 0.5）、平均指针数实测 2.01（理论 `Σ p^(k-1) = 2 - p^15 ≈ 2.0`）；查找平均右移步数实测 ≈ 15-17（理论 log2(30000) ≈ 14.9 加常数项），全部落在断言区间内。这个「实测 vs 理论」的对账动作本身就是资深面考点：概率数据结构的复杂度不是证明完就完，是**可以被用 30 秒实验验证的承诺**——能当场跑出来的人，和只会背 O(logN) 的人，面试官眼里是两个层级。④ 与平衡树的三条硬对比：a) **旋转 vs 掷硬币**——AVL/红黑树插入要靠旋转/变色维持结构不变式，代码复杂且每个操作都有常数级维护成本；跳表只改指针、不维护任何全局不变式，实现量约为红黑树的三分之一（antirez 原话的工程含义）；b) **范围查询**——平衡树范围查询要中序遍历走树（每步父子指针跳转），跳表先 O(logN) 定位 lo、之后沿底层有序链表线性走，缓存友好且代码只有两行；c) **并发**——跳表插入只局部改前驱的 forward 指针，天然适合细粒度锁或无锁 CAS；平衡树旋转会牵动整棵子树，并发改造是出名的深水区。但也要说清代价：跳表是**概率**结构，最坏情况（硬币全输）退化为 O(N)，只是概率上小到可以忽略；平衡树有确定性上界——对延迟 P99.999 有硬 SLA 的场景，这是平衡树唯一的反击点。

```python
# 全部标准库；跳表完整实现 + 随机层高分布与查找路径实证对账
import random
import math


class Node:
    __slots__ = ("key", "forward")

    def __init__(self, key, height):
        self.key = key
        self.forward = [None] * height


class SkipList:
    MAX = 16
    P = 0.5

    def __init__(self, rng=None):
        self.head = Node(None, self.MAX)
        self.level = 1
        self.rng = rng if rng is not None else random.Random()

    def _height(self):
        """层高只由硬币决定：p^(h-1) 概率分布，与数据零耦合。"""
        h = 1
        while h < self.MAX and self.rng.random() < self.P:
            h += 1
        return h

    def _find_update(self, key, steps=None):
        """三操作共用的定位：每层先右移再下沉，记录前驱数组。"""
        update = [self.head] * self.MAX
        node = self.head
        for i in range(self.level - 1, -1, -1):
            while node.forward[i] and node.forward[i].key < key:
                node = node.forward[i]
                if steps is not None:
                    steps.append(1)
            update[i] = node
        return update

    def search(self, key):
        cand = self._find_update(key)[0].forward[0]
        return cand is not None and cand.key == key

    def insert(self, key):
        update = self._find_update(key)
        cand = update[0].forward[0]
        if cand is not None and cand.key == key:
            return False                       # 幂等：重复 key 拒绝
        h = self._height()
        if h > self.level:
            self.level = h
        node = Node(key, h)
        for i in range(h):
            node.forward[i] = update[i].forward[i]
            update[i].forward[i] = node
        return True

    def delete(self, key):
        update = self._find_update(key)
        cand = update[0].forward[0]
        if cand is None or cand.key != key:
            return False
        for i in range(len(cand.forward)):
            update[i].forward[i] = cand.forward[i]
        while self.level > 1 and self.head.forward[self.level - 1] is None:
            self.level -= 1                    # 高层空链收缩
        return True

    def range(self, lo, hi):
        """半开区间 [lo, hi)：O(logN) 定位 + 底层有序链线性走。"""
        node = self._find_update(lo)[0].forward[0]
        out = []
        while node is not None and node.key < hi:
            out.append(node.key)
            node = node.forward[0]
        return out


if __name__ == "__main__":
    rng = random.Random(2026)
    sl = SkipList(rng)
    keys = list(range(3000))
    rng.shuffle(keys)
    payload = keys + keys[:200]                # 200 个重复 key
    inserted = sum(sl.insert(k) for k in payload)
    assert inserted == 3000 and len(payload) - inserted == 200
    assert all(sl.search(k) for k in keys)
    assert not sl.search(3000) and not sl.search(-1)
    print("增查: 3000 插入（200 重复全拒绝），成员查找全命中 ✅")

    # 1) 层高分布对账：P(h==1)=0.5，期望指针数 = Σ p^(k-1) ≈ 2.0
    h1 = nodes = ptrs = 0
    node = sl.head.forward[0]
    while node is not None:
        nodes += 1
        ptrs += len(node.forward)
        h1 += 1 if len(node.forward) == 1 else 0
        node = node.forward[0]
    assert 0.47 <= h1 / nodes <= 0.53, h1 / nodes
    assert 1.9 <= ptrs / nodes <= 2.1, ptrs / nodes
    print("层高分布: h==1 占比 %.3f（理论 0.5），平均指针数 %.3f（理论 %.3f）✅"
          % (h1 / nodes, ptrs / nodes, 2 - 0.5 ** SkipList.MAX))

    # 2) 查找路径账：平均右移步数与 log2(N) 同量级
    steps = []
    sample = keys[::10]
    for k in sample:
        sl._find_update(k, steps)
    avg = sum(steps) / len(sample)
    theory = math.log2(len(keys))
    assert 0.8 * theory <= avg <= 2.2 * theory, avg
    print("查找路径: 平均右移 %.1f 步 / 理论 log2(N)=%.1f ✅" % (avg, theory))

    # 3) 范围查询与 sorted 基准逐元素相等
    lo, hi = 500, 520
    expect = [k for k in keys if lo <= k < hi]
    expect.sort()
    assert sl.range(lo, hi) == expect
    print("范围查询 [%d,%d): %d 个元素与 sorted 基准一致 ✅" % (lo, hi, len(expect)))

    # 4) 删除自证：删 600 个 key 后结构与基准仍逐元素相等
    victims = keys[::5][:600]
    assert all(sl.delete(k) for k in victims)
    assert not any(sl.delete(k) for k in victims)      # 幂等：二次删除全拒绝
    left = sorted(set(keys) - set(victims))
    node, out = sl.head.forward[0], []
    while node is not None:
        out.append(node.key)
        node = node.forward[0]
    assert out == left
    assert sl.range(500, 520) == [k for k in left if lo <= k < hi]
    print("删除: 600 个 key 一次删净、二次全拒，全链遍历与基准一致 ✅")
```

**追问**：1) 层高为什么必须与「当前最大层」无关、独立掷硬币？—— 若层高受现有树高影响（比如「不超过当前层」），结构会随数据到达顺序偏置，有序插入会把树压扁退化成链表——跳表对输入不敏感的性质正是靠「层高只由硬币决定」保住的。`update[]` 长度按 MAX 预分配、新层高的前驱都指向 head，插入时直接把 `self.level` 抬到新层高即可。2) 为什么删除后要收缩 level，不收缩会怎样？—— 收缩只影响查找起点高度：不收缩的话顶层空链会让每次查找多跑几个 `while` 判断（正确性无损、常数变差），真正的正确性风险在反向——`_find_update` 只扫 `[0, self.level-1]`，若某节点层高大于 level（不可能发生，插入时保证 h ≤ level），其高层 forward 会成为孤儿指针；删除收缩逻辑就是维持「level = 全表最大层高」这一不变式。3) 跳表能替换掉红黑树的全部场景吗？—— 不能，边界在「确定性延迟」与「内存」：跳表每节点额外 `1/(1-p)` 个指针（p=0.5 即每节点多 1 个指针，内存约为红黑树的 1.3-2 倍），且最坏 O(N) 无硬上界；P99.999 有硬 SLA 的内核/交易系统选确定性平衡树，其余场景（Redis zset、LevelDB memtable、Lucene）几乎清一色跳表——**选型的胜负手从来不是复杂度符号，是「概率承诺够不够用 + 实现与并发成本付不付得起」**。另外范围查询密集的场景跳表占优：底层链表使 ZRANGEBYSCORE 是「定位 + 线性扫」，而平衡树要反复走树。
