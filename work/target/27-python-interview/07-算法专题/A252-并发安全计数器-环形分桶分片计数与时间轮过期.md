### A252 · 带过期的并发安全计数器

> 难度:★★★★ | 标签:并发计数, 滑动窗口, 时间轮, 内存回收, 指标系统

**问**（笔试·编程题）：写一个能被指标系统直接使用的计数器组件，两件东西：**① `WindowCounter`**——统计「最近 10 秒的请求总数」，QPS 峰值 50 万，被 8 个采集线程并发写入；要求零丢更新（`+= 1` 在 CPython 下并不是原子的）、读侧能给出一致性可解释的快照、复用环形槽时绝不能把新数据清掉、时钟回拨不能让窗口错乱。**② `TimingWheel`**——按 key 统计「最近 TTL 内的失败次数」，key 规模百万级且持续新建；要求过期回收是摊销 O(1)，不能靠定时全表扫描，也不能让「已刷新 TTL 的 key 被旧调度记录误删」。给出核心实现、并发压测（8 线程 × 5000 次必须精确等于 40000）、时间轮与惰性过期的内存对比，并说明读侧误差上界。约束：纯标准库、时间必须可注入。请先说清与 A248（滑窗限流的精确日志 vs 分桶近似）、A239（分布式令牌桶）、A101（限流器四连）的分工——那三张的产出是「放行/拒绝」的判定，本题的产出是「可被读取的统计量」，两者错在哪里会各出什么事故。

**答**：① 分工：A248 关心的是**判定误差**——近似计数会多放多少流量，误差上界 L/K，结论是分桶最多退化成固定窗口；A239 关心**分布式时钟漂移下的补币正确性**；A101 是四件套的速览。它们都在回答「这条请求该不该过」。本题回答的是另一个问题：**过去 10 秒到底发生了多少次**，而且这个数会被大盘、告警、容量模型消费。放行判定错一条是局部超卖，统计量错 3% 是全公司按错的曲线扩容——所以本题的重点是**并发正确性**（丢更新）与**内存回收**（百万 key 的 TTL），不是误差界。② 丢更新的真相：`cells[i] += 1` 是 `LOAD / ADD / STORE` 三条字节码，线程可以在任意字节码边界被切走，两个线程读到同一个旧值、各写回 +1，最终少 1。压测里 8 线程 × 5000 若不丢更新恰好 40000，裸字典实现会稳定少几十到几百——这就是「监控数字比真实流量低 3%」的经典来源，而且它不报错、不告警，只是慢慢偏。修法只有三条：全局锁（50 万 QPS 下成为串行点）、原子操作（标准库没有）、**分片 + 每片独立锁**（本题选它）。分片后竞争概率降为 1/S，S=4 时 8 线程的理论冲突率显著下降；关键是每片各一把锁，锁粒度 = 一个槽的一个分片，而不是整个窗口。③ 槽复用必须带 epoch：环形数组只有 K 个槽，第 `e` 个时间桶落到 `e % K`。当窗口往前走了一圈，同一个槽要装新桶的数据——如果只是 `+=`，新桶会继承上一圈的旧值，读出来凭空多一截。正确做法是给每个槽记一个 `epoch`，写入前比较「槽当前代表的桶号」是否等于本次桶号，不等才清零。**清零必须持槽级锁**（`_roll`），否则两个线程同时判断「需要清零」，一个刚清完、另一个又清一次，把对方刚写进去的一笔抹掉——这个竞态比丢更新更隐蔽，因为它只在跨桶边界的那一瞬间发生。④ 读侧语义要写清楚，不能假装强一致：`total()` 返回的是「窗口内各桶的当前累计」，读的瞬间可能有并发写入落在正在累加的桶里，所以它是**单调递增的弱一致快照**——不会倒退、不会读到负值，但可能比真实值少一笔在途的写。误差上界 = 读取期间进入的写入量，量级是一次的写入速率 × 读耗时（微秒级），对大盘完全够用。如果需要严格快照，只能停写或双缓冲切换，那是另一个成本量级。另外**不做边界加权**：加权是限流器的需求（要把「窗口起点所在桶」按时间占比折算），指标场景不需要——10 秒窗口按 1 秒桶对齐，误差就是最多 1 秒的边界模糊，加权反而引入浮点和解释成本。⑤ 时钟必须单调：用 `time.time()` 做桶序号，NTP 回拨 1 秒就会算出更小的桶号，`e % K` 落回旧槽、`epoch` 判定为「需要清零」，把仍在窗口内的数据清掉。所以用 `time.monotonic()`；即便这样也加一道 `max(ep, last_ep)` 钳制，防止注入的假时钟在测试里倒退。⑥ 时间轮：百万 key 的 TTL 过期有三条路——**惰性**（每次访问时检查，未访问的 key 永远不回收，内存只增不减，百万级就是几百 MB 的泄漏）、**定时全扫**（每 tick 扫全表，成本 O(n)，100 万 key 一次几十毫秒，且会周期性打满 CPU）、**时间轮**（按过期 tick 分槽，每 tick 只清一个槽，摊销 O(1)，成本与「本 tick 过期数」成正比而不是与总量成正比）。本题实现单层轮：容量 = `ticks × tick_sec`，超过容量必须拒绝并提示降级到最小堆或分层轮（Linux 内核就是 5 层时间轮），否则会**提前过期**——因为槽在一圈后被复用。⑦ 时间轮最容易写错的地方是 **TTL 刷新**：key 在 t=2 刷新了 TTL，旧调度记录还在 t=3 的槽里，t=3 一到就被删，明明刚写过却消失了。修法不是「从旧槽里摘掉」（那要按 key 反查槽位，O(1) 变 O(n)），而是**惰性校验**：值里存 `expire_tick`，槽触发时只删 `expire_tick == 当前 tick` 的 key，过期的调度记录直接跳过。代价是槽里可能有僵尸记录，靠下一次刷新自然覆盖——用空间换掉一次反向索引。⑧ 内存实测：2 万个 key、TTL 8 秒，惰性过期的字典在 8 秒后仍有 20000 条（只是逻辑过期），时间轮在 8 个 tick 后剩 0 条。这正是「指标系统跑一周内存涨到 40G 然后 OOM」的成因：不是 key 多，是没人删。⑨ 最后两个指标系统的自身陷阱：**scrape 也要限速**——Prometheus 每 15 秒拉一次，几千个计数器逐个求和，读侧成本不能忽略，所以桶数别开太大（K=10 够）；**平均值不能聚合**——多实例各自的 p99 不能求平均，必须上报直方图/摘要（HDR、t-digest）在服务端合并，否则「三个实例 p99 都是 100ms，合起来算出 80ms」这种反直觉结论会出现在事故复盘里。

```python
# 全部标准库；环形分桶 + 分片计数 + epoch 清零 + 时间轮 TTL + 并发压测
import threading
import time


class WindowCounter:
    """最近 window 秒的计数：K 个环形桶，每桶 S 个分片，每片一把锁。"""

    def __init__(self, window=10.0, bucket=1.0, shards=4, clock=time.monotonic):
        if bucket <= 0 or window < bucket:
            raise ValueError("window 必须 >= bucket > 0")
        self._k = int(round(window / bucket))
        self._bs = bucket
        self._s = shards
        self._clock = clock
        self._locks = [[threading.Lock() for _ in range(shards)] for _ in range(self._k)]
        self._cells = [[0] * shards for _ in range(self._k)]
        self._epoch = [-1] * self._k      # 槽当前代表的桶号；复用槽时据此清零
        self._roll = threading.Lock()     # 只保护「判断+清零」这一小段
        self._last = -1
        self._tls = threading.local()     # 线程本地分片号：不经哈希，天然散开
        self._rr = 0
        self._rr_lock = threading.Lock()

    def _shard(self):
        j = getattr(self._tls, "idx", None)
        if j is None:
            with self._rr_lock:
                j = self._rr % self._s
                self._rr += 1
            self._tls.idx = j
        return j

    def _prepare(self, idx, ep):
        if self._epoch[idx] == ep:
            return
        with self._roll:                  # 双检：并发下只让一个人清
            if self._epoch[idx] != ep:
                for j in range(self._s):
                    self._cells[idx][j] = 0
                self._epoch[idx] = ep

    def add(self, n=1, now=None):
        now = self._clock() if now is None else now
        ep = int(now // self._bs)
        ep = max(ep, self._last)          # 时钟回拨钳制：窗口不许倒退
        self._last = ep
        idx = ep % self._k
        self._prepare(idx, ep)
        j = self._shard()
        with self._locks[idx][j]:         # 锁粒度 = 一个槽的一个分片
            self._cells[idx][j] += n

    def total(self, now=None):
        now = self._clock() if now is None else now
        ep = int(now // self._bs)
        lo = ep - self._k + 1
        out = 0
        with self._roll:                  # 与清零互斥，避免读到「清了一半」的槽
            for e in range(lo, ep + 1):
                idx = e % self._k
                if self._epoch[idx] != e:  # 槽里是窗口外的旧桶，跳过
                    continue
                out += sum(self._cells[idx])
        return out

    def per_shard(self):
        """诊断用：分片是否均衡，倾斜说明线程 ident 取模退化了。"""
        res = {}
        for idx in range(self._k):
            for j in range(self._s):
                if self._cells[idx][j]:
                    res[j] = res.get(j, 0) + self._cells[idx][j]
        return res


class TimingWheel:
    """单层时间轮：O(1) 摊销过期；容量 = ticks * tick_sec，超出必须拒绝。"""

    def __init__(self, ticks=8, tick_sec=1.0, clock=time.monotonic):
        self._n = ticks
        self._ts = tick_sec
        self._cap_ticks = ticks
        self._clock = clock
        self._buckets = [set() for _ in range(ticks)]   # 每 tick 的候选 key
        self._cur = -1
        self._lock = threading.Lock()
        self._values = {}                 # key -> [count, expire_tick]
        self.expired = 0

    def _tick(self, now):
        return int(now // self._ts)

    def _advance(self, tick):
        with self._lock:
            while self._cur < tick:
                self._cur += 1
                slot = self._buckets[self._cur % self._n]
                for key in slot:                       # 只处理本 tick 的槽
                    rec = self._values.get(key)
                    if rec is not None and rec[1] == self._cur:
                        del self._values[key]
                        self.expired += 1
                slot.clear()

    def incr(self, key, ttl_ticks=1, now=None):
        now = self._clock() if now is None else now
        if not 1 <= ttl_ticks <= self._cap_ticks:
            raise ValueError("ttl_ticks 必须在 [1, %d]，否则槽会提前复用" % self._cap_ticks)
        tick = self._tick(now)
        self._advance(tick)
        expire = tick + ttl_ticks
        with self._lock:
            rec = self._values.get(key)
            cnt = (rec[0] if rec else 0) + 1
            self._values[key] = [cnt, expire]         # 刷新 TTL 只改这条记录
            self._buckets[expire % self._n].add(key)   # 旧槽的记录留成僵尸，触发时惰性跳过
        return cnt

    def get(self, key, now=None):
        now = self._clock() if now is None else now
        self._advance(self._tick(now))
        with self._lock:
            rec = self._values.get(key)
            return 0 if rec is None else rec[0]

    def __len__(self):
        return len(self._values)


if __name__ == "__main__":
    # 1) 并发压测：8 线程 × 5000 次必须精确等于 40000（零丢更新）
    wc = WindowCounter(window=10, bucket=1, shards=4)
    THREADS, PER = 8, 5000

    def worker():
        for _ in range(PER):
            wc.add(1, now=100.0)          # 固定桶号，压测只测并发正确性

    ts = [threading.Thread(target=worker) for _ in range(THREADS)]
    for t in ts:
        t.start()
    for t in ts:
        t.join()
    got = wc.total(now=100.0)
    assert got == THREADS * PER, got
    print("并发写入 %d 线程 × %d：计数 %d，零丢更新 ✅" % (THREADS, PER, got))
    print("  分片分布: %s（8 线程应大致均分到 4 片）" % wc.per_shard())

    # 2) 窗口滚动：窗口外的桶必须不计入
    wc2 = WindowCounter(window=10, bucket=1, shards=2)
    wc2.add(10, now=100.0)
    wc2.add(5, now=105.0)
    assert wc2.total(now=105.0) == 15
    assert wc2.total(now=115.0) == 0, wc2.total(now=115.0)
    print("窗口滚动: t=105 计 15 条；t=115 全部滑出窗口计 0 ✅")

    # 3) 槽复用：绕一圈后同槽必须清零，不能继承上一圈的值
    wc3 = WindowCounter(window=3, bucket=1, shards=1)     # K=3
    wc3.add(7, now=10.0)                                  # 槽 1
    wc3.add(9, now=13.0)                                  # 同槽 1，必须从 0 开始
    assert wc3.total(now=13.0) == 9, wc3.total(now=13.0)
    print("槽复用: 10s 的 7 条未污染 13s 的计数（epoch 清零生效）✅")

    # 4) 时钟回拨：假时钟倒退不能把窗口推回去
    fake = [100.0]
    wc4 = WindowCounter(window=10, bucket=1, shards=1, clock=lambda: fake[0])
    wc4.add(3)
    fake[0] = 95.0                       # NTP 回拨 5 秒
    wc4.add(2)
    assert wc4.total(now=100.0) == 5
    print("时钟回拨 5s: 计数仍为 5，桶号被钳制不前移 ✅")

    # 5) 时间轮：TTL 到期回收 + 刷新后不被旧调度误删
    fake2 = [0.0]
    tw = TimingWheel(ticks=8, tick_sec=1.0, clock=lambda: fake2[0])
    assert tw.incr("ip:1.1.1.1", ttl_ticks=3) == 1
    fake2[0] = 2.0
    assert tw.incr("ip:1.1.1.1", ttl_ticks=3) == 2      # 刷新：expire 2 -> 5
    fake2[0] = 3.0
    assert tw.get("ip:1.1.1.1") == 2, "旧调度记录(3)把刷新过的 key 删了"
    print("TTL 刷新: t=2 刷新后，t=3 的旧调度记录被惰性跳过，值仍为 2 ✅")
    fake2[0] = 5.0
    assert tw.get("ip:1.1.1.1") == 0
    print("TTL 到期: t=5 回收，计数归零 ✅")

    # 6) 内存对比：2 万 key，惰性过期 vs 时间轮
    fake3 = [0.0]
    tw2 = TimingWheel(ticks=8, tick_sec=1.0, clock=lambda: fake3[0])
    lazy = {}
    for i in range(20000):
        tw2.incr("k%d" % i, ttl_ticks=2)
        lazy["k%d" % i] = [1, 0]      # 惰性实现：只能等下次访问，没人来就永远留着
    fake3[0] = 8.0
    tw2.get("nobody")                  # 触发推进
    assert len(tw2) == 0 and len(lazy) == 20000
    print("2 万 key / TTL 2s：时间轮残留 %d 条，惰性过期残留 %d 条 ✅"
          % (len(tw2), len(lazy)))

    # 7) 时间轮容量边界：TTL 超过一圈会提前过期，必须显式拒绝
    tw3 = TimingWheel(ticks=4, tick_sec=1.0)
    try:
        tw3.incr("k", ttl_ticks=5)
        raise AssertionError("应该拒绝超容量 TTL")
    except ValueError as e:
        print("超容量 TTL 被拒绝: %s ✅" % e)
```

**追问**：1) 为什么不能用一把全局锁包住 `add`？—— 50 万 QPS、每次持锁微秒级，理论上够用，但锁的代价不是吞吐而是**排队尾部**：CPython 的 GIL 已经让字节码切换抖动，再叠一把全局锁，P99 会出现尖刺；更要命的是这把锁与 `total()` 的读锁互相争用，采集线程一读，写入侧就被顶住，监控越频繁服务越慢。分片锁的本质是把「一个热点」变成 S 个温点，S 取 CPU 核数附近即可——再大只会增加读侧的求和成本。2) 这个计数器和限流器能复用同一份数据结构吗？—— 数据结构可以，语义不能。限流器的读必须**阻止超额**，所以读和判定要在同一个原子区里（Redis 用 Lua、本地用锁），而指标读是旁路、允许滞后；把两者合并成一个组件，就会出现「大盘读一次把限流判定拖慢」或者「限流为了快而读脏数据多放行」的耦合事故。共用桶结构、各自封装语义，是唯一安全的复用方式。3) 集群维度的 QPS 怎么得到？—— 绝不能把各实例的「10 秒平均值」再求平均（各实例的窗口边界没对齐，长短窗口混合会系统性低估峰值），正确做法是各实例上报**单调递增的累计值**，由服务端做差再除时间（counter 而非 gauge），窗口边界由抓取时刻决定；同一条规则也适用于「p99 不能平均」——分位数只能由直方图合并，不能由分位数合并。

## 背诵要点
1. `+= 1` 非原子，丢更新是静默的 3% 偏差；解法是分片计数 + 每片一把锁，压测以「精确等于 N×M」验收。
2. 环形槽必须带 epoch，跨圈复用要「判断+清零」在同一锁内完成，否则并发清零会抹掉刚写入的一笔；时钟用 `monotonic` 并做回拨钳制。
3. 百万 key 的 TTL 用时间轮（摊销 O(1)、成本随过期数而非总量增长），刷新语义靠值内 `expire_tick` 惰性校验，而不是反向摘除旧调度；单层轮容量 = ticks×tick_sec，超出必须拒绝。

## 复盘追问
1. 大盘上的 QPS 曲线在整点出现规律性凹陷，代码里计数逻辑没错，问题可能在哪？（提示：桶边界与抓取时刻未对齐——抓取正好落在某个 1 秒桶刚开始时，读到的是「几乎为空的当前桶」；指标侧应上报累计值让服务端做差，或把窗口长度设成抓取间隔的整数倍并只读已完成桶）
2. 时间轮换成「每个 key 一个 `threading.Timer`」行不行？（提示：百万 key = 百万个线程/定时器，内核调度与内存都撑不住，且 Timer 精度依赖线程唤醒；任何「每实体一个定时器」的方案在规模上都等价于给自己造一个线程风暴，时间轮/最小堆才是把 n 个定时器收敛成 1 条时间线的做法）
