### A152 · 自适应限流

> 难度:★★★ | 标签:自适应限流, 负载, BBR 思想

**问**（笔试·编程+场景题）：静态限流阈值（1000 QPS）总在「高峰限流过度、低峰限流不足」间摇摆——自适应限流怎么基于**负载信号**自动调节（CPU/延迟/队列深度哪个信号好），BBR 思想（最大带宽×最小 RTT）在服务限流的映射（「吞吐×延迟」积不变时不过载），信号抖动怎么平滑（EMA），自适应限流的风险（信号反馈回路震荡）怎么阻尼？

**答**：① 信号选型：**CPU**（最易得但离用户远——CPU 高不代表延迟差）、**队列深度**（内部状态准确但要埋点）、**延迟（RTT）**（离用户最近但受下游影响——下游慢会被误判为自己过载）。最佳实践：**主信号延迟 + 辅助信号验证**（延迟涨且 CPU 也涨 = 自己过载；延迟涨 CPU 低 = 下游问题不触发限流）。② BBR 映射：TCP BBR 用「最大带宽 × 最小 RTT」估计管道容量——服务限流同构：持续追踪「最大吞吐（成功 QPS 峰值）」与「最小 RTT」，`max_qps = max_throughput × min_rtt / current_rtt`——RTT 上涨超过 min_rtt 的 β 倍（如 1.5×）判定排队开始，限流到 max_qps。③ 平滑：信号用 **EMA**（指数移动平均）平滑抖动，调节步长限制（每次 ±10%——大幅调节造成振荡）；**阻尼**：升限慢降限快（过载要立即保护，恢复要观察确认——不对称调节，A136 渐进恢复同构）。

```python
# 全部标准库；demo 实现 BBR 思想自适应限流器
import random, time

class AdaptiveLimiter:
    """基于 RTT 的自适应限流（BBR 思想：吞吐 × min_rtt 估计容量）。"""
    def __init__(self, beta: float = 1.5, ema_alpha: float = 0.3,
                 max_step_pct: float = 0.1):
        self.beta = beta                      # RTT 超过 min_rtt × β 判定排队
        self.alpha = ema_alpha                # EMA 平滑系数
        self.max_step = max_step_pct
        self.min_rtt = None                   # 历史最小 RTT（容量信号）
        self.max_throughput = None            # 历史最大成功吞吐
        self.current_limit = 1000             # 当前限流值
        self.ema_rtt = None
    def observe(self, rtt: float, success_qps: float):
        # min_rtt 只降不升（容量估计的下界）
        self.min_rtt = rtt if self.min_rtt is None else min(self.min_rtt, rtt)
        self.max_throughput = (success_qps if self.max_throughput is None
                               else max(self.max_throughput, success_qps))
        # EMA 平滑 RTT
        self.ema_rtt = (rtt if self.ema_rtt is None
                        else self.ema_rtt * (1 - self.alpha) + rtt * self.alpha)
    def adjust(self) -> int:
        if not (self.min_rtt and self.max_throughput and self.ema_rtt):
            return self.current_limit
        capacity = self.max_throughput * self.min_rtt / self.ema_rtt
        if self.ema_rtt > self.min_rtt * self.beta:
            target = capacity                 # 排队中：压到容量估计
        else:
            target = capacity * 1.2           # 健康：允许 20% 余量试探
        # 阻尼：单步 ±10%，升慢降快
        if target > self.current_limit:
            target = self.current_limit * (1 + self.max_step)      # 升 +10%
        else:
            target = self.current_limit * (1 - self.max_step * 3)  # 降 -30%
        self.current_limit = int(max(10, target))
        return self.current_limit

if __name__ == "__main__":
    random.seed(2)
    lim = AdaptiveLimiter()
    for round_ in range(200):
        # 模拟：负载上升 → RTT 变大
        load = min(1.0, round_ / 100)
        rtt = 0.02 + 0.08 * load ** 2         # RTT 随负载非线性涨
        qps = 1000 * (1 - load * 0.3)         # 吞吐随之降
        lim.observe(rtt, qps)
        if round_ % 50 == 0:
            lim.adjust()
    print(f"min_rtt={lim.min_rtt:.3f}s max_throughput≈{lim.max_throughput:.0f}")
    lim.adjust()
    print(f"自适应限流值: {lim.current_limit}（随 RTT 膨胀自动下调）✅")
    assert lim.current_limit < 1000, "负载上升应自动下调限流"
    # 口径：主信号 RTT+辅助验证；min_rtt 只降不升；EMA 平滑+不对称阻尼（升慢降快）。
```

**追问**：1) 为什么 min_rtt「只降不升」？——min_rtt 是「无排队时延」的估计（容量下界）：被污染（升高）后容量估计偏大 → 限流失效；只降不升让估计保守——代价是网络改善后容量估计偏低（可定期重探测，BBR 的 PROBE_RTT 阶段）。2) 「下游慢被误判为自己过载」怎么区分？（提示：多信号验证——自己过载=RTT 涨+CPU 涨+队列深；下游慢=RTT 涨但 CPU 低——辅信号不符则不触发自身限流（转熔断下游，A106）——单信号的限流器必然误伤）3) 反馈回路震荡的根源与阻尼？（提示：限流值降 → 消费端重试/排队 → RTT 信号畸变 → 限流值再降（正反馈雪崩）；阻尼三板斧：EMA 平滑信号、限制调节步长、升慢降快不对称——让回路收敛而非共振）

## 背诵要点
1. 自适应限流信号：主信号 RTT + 辅助信号（CPU/队列）验证——单信号必误伤（下游慢误判）。
2. BBR 映射：max_qps = max_throughput × min_rtt / ema_rtt；min_rtt 只降不升（容量下界保守估计）。
3. 阻尼三件套：EMA 平滑信号、单步 ±10% 限幅、升慢降快不对称——防反馈回路震荡。

## 复盘追问
1. 自适应限流上线后限流值「每天下午准时骤降」，可能什么原因？（提示：下午定时任务/报表查询抬高 RTT——负载信号被「计划内负载」污染；解法：区分信号源（计划内负载走独立资源池，Q122 隔离）或自适应限流排除已知计划窗口）
2. 自适应限流和静态限流（A101 令牌桶）怎么共存？（提示：静态管「合同上限」（对客户承诺的速率），自适应管「自身保护」（动态余量）——取两者较小值生效；自适应波动部分要在监控里可视化，否则运维以为限流失灵）
