### A179 · 关键路径冗余

> 难度:★★★ | 标签:冗余, 表决, 可靠性

**问**（笔试·编程+场景题）：风控决策「不能错」（错单资损百万）——单实例决策不可靠（机器故障/程序 bug），「多副本冗余」怎么设计（N 个独立实例各算，表决器取结果），副本间的「独立性」怎么保证（共享同一个 bug 就白冗余——相同代码/相同数据/相同机器都不算独立），表决规则（多数派/一致才过/加权），冗余的成本与「部分降级」怎么平衡？

**答**：① 副本独立性三隔离：**代码隔离**（不同实现/不同团队维护——同一段代码三个副本 = 三个副本一个 bug）、**数据隔离**（各副本用自己的数据源副本——共享缓存则缓存 bug 传染）、**环境隔离**（不同机器/机房/依赖版本）——独立性是冗余有效性的前提，三隔离缺一 = 假冗余。② 表决规则：**多数派**（3 副本 2 票同 → 采纳，容忍 1 副本错——但「2 票相同」可能都是错的（相关性错误））、**一致才过**（全票一致才采纳，否则转人工——最保守，适合资损级）、**加权表决**（按副本历史准确率加权——需要统计基础）。③ 成本平衡：N 副本 = N 倍计算成本——**分级冗余**：只有高风险决策走多副本表决（大额交易），低风险走单副本+事后对账——冗余是「按风险定价」的资源。

```python
# 全部标准库；demo 实现「表决器（多数派/一致/加权）+ 独立性检查」
from collections import Counter

class Voter:
    def __init__(self, mode: str = "majority", quorum: int = 2):
        self.mode, self.quorum = mode, quorum
    def vote(self, results: list) -> str:
        """results: 各副本决策结果。返回 'adopt'/'manual'/'rejected'。"""
        cnt = Counter(results)
        if self.mode == "majority":
            result, n = cnt.most_common(1)[0]
            return "adopt" if n >= self.quorum else "manual"
        if self.mode == "unanimous":
            return "adopt" if len(cnt) == 1 and None not in results else "manual"
        if self.mode == "weighted":
            return "adopt" if cnt.most_common(1)[0][1] >= 2 else "manual"
        raise ValueError(self.mode)

def independence_audit(replicas: list[dict]) -> list[str]:
    """独立性审计：三隔离逐项检查。"""
    issues = []
    codes = {r["code_version"] for r in replicas}
    datas = {r["data_source"] for r in replicas}
    hosts = {r["host"] for r in replicas}
    if len(codes) < len(replicas):
        issues.append("代码未隔离：相同实现=同一 bug 三副本齐炸")
    if len(datas) < len(replicas):
        issues.append("数据未隔离：共享数据源=数据问题传染")
    if len(hosts) < len(replicas):
        issues.append("环境未隔离：同宿主机=硬件故障齐灭")
    return issues

if __name__ == "__main__":
    v_majority = Voter("majority", quorum=2)
    v_unanimous = Voter("unanimous")
    # 场景 1：2 票 approve 1 票 reject
    r1 = ["approve", "approve", "reject"]
    print("多数派:", v_majority.vote(r1), "| 一致制:", v_unanimous.vote(r1))
    assert v_majority.vote(r1) == "adopt" and v_unanimous.vote(r1) == "manual"
    # 场景 2：相关性错误（三个副本同一个 bug 全部 approve）
    r2 = ["approve", "approve", "approve"]
    print("全票一致:", v_unanimous.vote(r2), "——但独立性审计发现问题才算真冗余")
    replicas = [{"code_version": "v1", "data_source": "cache", "host": "host1"},
                {"code_version": "v1", "data_source": "cache", "host": "host1"},
                {"code_version": "v1", "data_source": "cache", "host": "host1"}]
    issues = independence_audit(replicas)
    print("独立性审计:", issues)                # 三隔离全破 = 假冗余
    assert len(issues) == 3
    # 口径：多数派容忍单错/一致制转人工/资损级用一致制；
    # 独立性三隔离（代码/数据/环境）缺一 = 假冗余。
```

**追问**：1) 为什么「三副本全票一致」也可能不可信？——三副本若共享同一 bug（代码/数据未隔离），一致性只说明「bug 判定一致」；全票一致的置信度取决于独立性审计——审计不过关时全票一致要转人工而不是采纳（假冗余的最优输出就是「人工复核」）。2) 「分级冗余」的分级依据怎么定？（提示：单次错误的期望损失（金额×概率）与冗余成本比较——百万级决策值得 3 副本+一致制，百元级决策单副本+事后对账（A162 对账兜底）；分级表与业务共同维护）3) 表决器自己挂了怎么办？（提示：表决器是新的关键单点——表决器自身高可用（多实例+状态无服务化——表决逻辑无状态可任意横向），且「表决器不可用」的降级 = 全部转人工（fail-safe 到人工，不是 fail-open 自动采纳））

## 背诵要点
1. 副本独立性三隔离：代码（不同实现）/数据（独立源）/环境（异机异机房）——缺一即假冗余。
2. 表决规则分级：多数派（容忍单错）/一致制（资损级，不一致转人工）/加权（按历史准确率）。
3. 冗余按风险定价：高风险决策多副本表决，低风险单副本+事后对账；表决器不可用 fail-safe 转人工。

## 复盘追问
1. 三个副本用了三种实现，但对「同一灰案例」判定不同（2:1），人工复核发现 2 票的是错的——表决器要不要「学习」？（提示：可以按历史准确率加权（加权表决），但要防「过拟合单案例」——统计周期要长（月级）+ 复核案例进训练集有滞后性；更根本的是修那个判错的副本实现，不是调表决权重）
2. 风控决策走多副本表决后延迟从 50ms 涨到 200ms，业务方不满——怎么优化？（提示：并行调用（延迟=最慢副本，A131 对冲同构）+ 超时降级（慢副本超时即用已有票数表决）+ 分级触发（只有大额交易走表决，小额直采）——延迟预算内最大化可靠性）
