### A171 · 升级链与找人

> 难度:★★☆ | 标签:值班, 升级, 治理

**问**（笔试·场景题）：故障 15 分钟，值班的人修不了（不是他领域）——升级链（escalation chain）怎么设计（每级找谁/多久无进展升一级），「知道问题但不在值班表上的人」怎么找到（服务目录的 domain expert 字段），「升级≠甩锅」的沟通语义怎么表达（升级是拉资源不是推责任），升级链失效（该升级的人不升——怕担责）怎么治理？

**答**：① 升级链设计：每类故障预定义升级路径（`告警 → 值班 oncall → 领域专家 → 团队 leader → 架构师/管理层`），**升级触发条件量化**（每级停留 15 分钟无进展自动升一级——人不敢升，系统自动升）；领域专家映射进服务目录（`domain_expert` 字段，Q166 目录驱动——「不在值班表」的专家按目录找到）。② 升级语义：「升级是拉资源不是推责任」——升级话术模板（「我在处理 X，遇到了 Y 需要你帮助，目前进展 Z」——三要素：问题/需要什么/已做什么）；组织上升级无责（A138 blameless 延伸：该升级不升级导致延误才追责，升级本身永远免责）。③ 该升不升的治理：升级链自动化（停留时长超阈值系统自动拉人进会）+ 复盘检视「升级是否及时」（时间线里「开始处理→第一次升级」的间隔是 KPI）——怕担责的文化问题用「升级免责」制度化对冲。

```python
# 全部标准库；demo 实现「自动升级链」
import time

CHAIN = {                          # 故障类型 -> 升级路径（每人停留预算 15min）
    "db": ["oncall", "dba-expert", "db-team-lead", "architect"],
    "payment": ["oncall", "pay-expert", "pay-team-lead", "cto"],
}

class EscalationChain:
    def __init__(self, chain: list[str], step_budget_s: float = 15 * 60):
        self.chain, self.budget = chain, step_budget_s
        self.idx, self.start = 0, time.monotonic()
        self.timeline = [chain[0]]
    def tick(self, resolved: bool, progress: bool = True) -> str:
        if resolved:
            return f"resolved by {self.chain[self.idx]}"
        now = time.monotonic()
        if not progress and now - self.start >= self.budget:
            if self.idx < len(self.chain) - 1:
                self.idx += 1                       # 系统自动升级（人不升系统升）
                self.start = now
                self.timeline.append(self.chain[self.idx])
                return f"auto-escalate → {self.chain[self.idx]}（{self.budget/60:.0f}min 无进展）"
            return "chain-end: 升级链走完 → 重大事故流程（管理层介入）"
        return f"current={self.chain[self.idx]}（进展中，不升级）"
    def escalation_delay_kpi(self, first_escalate_at: float, incident_start: float) -> float:
        """KPI：开始处理→首次升级的间隔。"""
        return first_escalate_at - incident_start

if __name__ == "__main__":
    ec = EscalationChain(CHAIN["db"])
    for i in range(4):
        r = ec.tick(resolved=False, progress=(i == 0))   # 第一级有进展，其后停滞
        print(r)
    assert ec.chain[ec.idx] == "dba-expert" or ec.idx >= 1
    print("升级链时间线:", ec.timeline)
    # 升级话术模板：「处理 X（问题）/遇到 Y（需要）/进展 Z（已做）」——升级=拉资源≠推责任。
    # 口径：每级 15min 无进展系统自动升级；升级免责，该升不升才追责。
```

**追问**：1) 为什么升级触发要「系统自动」而不是「人判断」？——人不敢升（怕显得无能）+ 半夜判断力差（Q142）+ 侥幸心理（再试一下）——自动升级把「要不要拉人」的决策权从怯懦与侥幸手里拿走；人仍可提前手动升级（系统只兜底）。2) 「领域专家不在值班表」的深夜找到人的代价？（提示：专家也是人（不能 7×24 在线）——代价对冲：专家信息透明化（目录可查）+ 深夜联系按「非打扰升级」（短信/异步，非电话轰炸）+ 专家参与值班轮换（专家承担 night pages 的对价是白天补偿）——专家不是无限资源，机制要保护专家）3) 升级到管理层（CTO）的条件怎么写才不会「啥事都叫 CTO」？（提示：量化门槛（资损持续 N 分钟超 X 元/全站不可用/恢复超预算 2 倍）写进事故章程——门槛是决策支持，让 CTO 知道自己什么时候该出现）

## 背诵要点
1. 升级链预定义（按故障类型）+ 每级 15 分钟无进展**系统自动升级**——人不敢升系统升。
2. 领域专家映射进服务目录（domain_expert 字段），「不在值班表」按目录找人；深夜联系非打扰化。
3. 升级免责制度化（该升不升才追责）；话术三要素：问题/需要什么/已做什么——升级=拉资源≠推责任。

## 复盘追问
1. 升级链走完了（到 CTO）问题还没修，接下来是什么？（提示：升级链走完≠结束——重大事故流程（A150 IC 拉全资源+全公司动员+对客沟通），同时记录「链上每级停留时长」作为复盘 KPI（哪级卡最久=哪级能力缺口））
2. 「15 分钟无进展自动升级」会不会在复杂问题上误升（有些问题就是要查 1 小时）？（提示：升级≠换人重修——升级是「拉更多资源与视角」（专家可能一眼看出问题）；「有进展」的定义包含「正在有效推进」（有新线索/假设验证中）——progress 标记由处理人主动更新，诚实汇报即不误升）
