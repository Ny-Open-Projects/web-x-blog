### A236 · 跨时区轮换时区表

> 难度:★★☆ | 标签:跨时区, 排班, 时区

**问**（笔试·场景题）：三地轮换值班（北京/欧洲/美西）——「时区表」怎么管理（DST 切换会让时区偏移变化——夏令时不是恒定偏移），排班表的「时间」统一用什么口径（UTC 是唯一不漂移的锚），「值班窗口的换算」怎么自动（北京晚 6 点=欧洲几点——不能硬编码偏移量），DST 切换日的排班重叠怎么处理（Q7057 夏令时教训的值班版）？

**答**：① UTC 锚定：排班表的**所有时间统一存 UTC**（ISO8601+Z），展示时按各团队本地时区渲染——存本地时间+偏移量会在 DST 切换日错位（偏移量会变），存 UTC 永远无歧义（Q165 全球化口径的排班版）。② 时区表管理：用 **IANA 时区数据库**（zoneinfo）而非固定偏移量——`America/New_York` 自动处理 DST（偏移量从 -5 变 -4 自动跟随），硬编码 "UTC-5" 在 DST 切换日全体错位 1 小时（Q7057 事故的排班版）。③ 换算自动：值班窗口「18:00 UTC-19:00 UTC」存在 UTC，各团队看到本地渲染（北京=次日 2 点，欧洲=19 点，美西=10 点）——**换算永远是「UTC→本地」单向渲染**，不做「本地→本地」双向推算（两级换算必错）。④ DST 切换日：切换日 UTC 与本地的映射不连续（1 小时消失或重复）——排班表在切换日的窗口用 UTC 定义（不变），本地渲染自动跟随（消失的那 1 小时是真实的时间空洞，值班交接避开它）。

```python
# 全部标准库；demo 实现「UTC 锚定排班 + DST 安全渲染」
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

def utc_shift_window(day: str, start_utc_h: int, duration_h: int = 8) -> tuple:
    """值班窗口 UTC 定义（唯一事实源）。"""
    y, m, d = map(int, day.split("-"))
    start = datetime(y, m, d, start_utc_h, tzinfo=timezone.utc)
    return start, start.timestamp() + duration_h * 3600

def render_local(ts_range: tuple, tz_name: str) -> str:
    """UTC → 本地渲染（zoneinfo 自动处理 DST）。"""
    start_ts, end_ts = ts_range
    tz = ZoneInfo(tz_name)
    s = datetime.fromtimestamp(start_ts, tz=tz)
    e = datetime.fromtimestamp(end_ts, tz=tz)
    return f"{tz_name}: {s.strftime('%m-%d %H:%M')} → {e.strftime('%m-%d %H:%M')}"

def dst_safe_check(day: str) -> bool:
    """DST 切换日检查：切换日凌晨的窗口是否跨了「消失/重复的 1 小时」。"""
    tz = ZoneInfo("America/New_York")
    y, m, d = map(int, day.split("-"))
    # 美东 3 月第二个周日 2:00（简化判定）
    start = datetime(y, m, d, 1, tzinfo=timezone.utc)
    local = start.astimezone(tz)
    return local.hour == 1                        # UTC 1:00 = 美东切换边界附近

if __name__ == "__main__":
    win = utc_shift_window("2026-03-08", 18, 8)   # UTC 18:00 起 8 小时
    print(render_local(win, "Asia/Shanghai"))
    print(render_local(win, "Europe/Berlin"))     # DST 切换日：柏林已进入夏令时
    print(render_local(win, "America/New_York"))
    print("DST 安全检查:", dst_safe_check("2026-03-08"), "—— 切换日窗口避开消失的 1 小时 ✅")
    # 口径：排班表全 UTC 存储（唯一不漂移锚）；渲染用 zoneinfo（DST 自动跟随）；
    # 换算单向（UTC→本地）；DST 切换日交接避开时间空洞。
```

**追问**：1) 为什么「存 UTC」而非「存本地时间+时区名」？——存本地时间+时区在 DST 切换日有歧义（2026-03-08 02:30 这个本地时间在美东不存在（跳过了）——无法反推 UTC）；UTC 无歧义，本地永远是渲染结果——存储与渲染分离是时区管理的铁律（Q165 同构）。2) 「zoneinfo 自动处理 DST」有什么坑？（提示：zoneinfo 需要系统 tzdata 数据（容器内常缺——装 tzdata 包）；历史时区数据会更新（某国取消 DST——tzdata 版本要更新）；非整小时偏移的时区（印度 +5:30）某些库处理有坑——「自动处理」不等于「零注意」）3) 跨时区值班的「公平」怎么算时区成本？（提示：深夜班（本地 0-6 点）负担系数 ×2（A201 负担模型扩展时区维度）——三地轮换的深夜班轮流承担——负担模型的时区维度让跨时区公平可量化）

## 背诵要点
1. 排班表全 UTC 存储（ISO8601+Z 唯一不漂移锚），本地渲染用 zoneinfo（DST 自动跟随）。
2. 时区用 IANA 名（America/New_York）而非固定偏移量——DST 自动跟随；容器装 tzdata；tzdata 版本更新。
3. 换算单向（UTC→本地）不做双向推算；DST 切换日交接避开「消失/重复的 1 小时」。

## 复盘追问
1. 排班系统「上周还好，这周全错 1 小时」——最可能的原因？（提示：DST 切换（欧洲/美国 3 月/10 月切换日）——存了固定偏移量（UTC+1）而非 IANA 时区名——修复=迁移到 zoneinfo + 全量校验历史排班）
2. 三地轮换的「深夜班」长期由同一时区承担（北京深夜班最多），公平性模型怎么处理？（提示：负担模型加时区维度（深夜班系数最高，A201 扩展）+ 轮换规则（深夜班轮流承担——每季度换一次「谁的深夜」）——时区公平是跨时区排班的隐藏维度，不加权就是隐性地域歧视）
