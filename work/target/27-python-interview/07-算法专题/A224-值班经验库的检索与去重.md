### A224 · 值班经验库治理

> 难度:★★☆ | 标签:知识库, 检索, 治理

**问**（笔试·编程+场景题）：经验库 500 条目，「搜不到想要的」（检索质量差）和「搜到 5 条重复的」（条目冗余）并存——检索质量怎么提升（关键词 vs 向量混合检索 Q7503），条目去重的「语义重复」判定（同样的处置两种写法），条目的「新鲜度」（老条目与新系统不匹配）怎么标注，知识库治理的「定期体检」包括哪些项？

**答**：① 检索质量：**混合检索**（关键词精确匹配（命令/服务名等实体）+ 向量语义检索（自然语言描述）——RRF 融合（Q7503）——值班场景特殊要求：**实体优先**（搜「Redis」必须命中 Redis 条目——实体错配不可接受）；检索评测集（历史真实问题 → 期望命中的条目）定期回归（命中率 <90% 收紧）。② 语义去重：同样的处置两种写法（「重启服务」vs「服务重启流程」）——去重判定用向量相似度（>0.92 视为重复）+ 人工抽检（自动合并有风险——两篇看似相同可能细节不同：一篇带回滚步骤一篇没有——**合并保留信息超集**）；去重节奏：月度批处理 + 新条目入库时查重（Q7038 契约同构——入库前查重比事后清理便宜）。③ 新鲜度标注：条目带「适用版本/适用环境」字段（老条目自动过期标注，Q168 文档时效同构）——值班检索时「过期条目降权/标注」。④ 定期体检四项：检索命中率回归 + 重复率扫描 + 新鲜度过期扫描 + 访问统计驱动的「孤儿条目」清理。

```python
# 全部标准库；demo 实现「经验库混合检索 + 去重」
import time

def hybrid_search(query: str, kb: list[dict]) -> list[dict]:
    """混合检索：实体精确命中优先 + 字符相似度语义（RRF 简化）。"""
    qw = set(query.lower().split())
    scored = []
    for e in kb:
        kw = set(e["q"].lower().split())
        entity_hit = len(qw & kw) / max(len(qw), 1)      # 实体覆盖
        overlap = len(qw & kw) / max(len(qw | kw), 1)    # Jaccard
        # 实体权重高：值班场景实体错配不可接受
        score = 0.7 * entity_hit + 0.3 * overlap
        scored.append((score, e))
    return [e for s, e in sorted(scored, reverse=True) if s > 0][:3]

def semantic_dedup(kb: list[dict], th: float = 0.92) -> list[tuple]:
    """语义去重：相似条目配对（合并保留信息超集，人工抽检）。"""
    pairs = []
    for i in range(len(kb)):
        for j in range(i + 1, len(kb)):
            qi, qj = set(kb[i]["q"].lower().split()), set(kb[j]["q"].lower().split())
            sim = len(qi & qj) / max(len(qi | qj), 1)
            if sim >= th:
                pairs.append((kb[i]["q"], kb[j]["q"]))
    return pairs

if __name__ == "__main__":
    kb = [
        {"q": "重启 Redis 服务流程", "a": "1...2...3...", "fresh": "3.12"},
        {"q": "Redis 服务重启的操作步骤", "a": "1...2...3...（同上）", "fresh": "3.12"},
        {"q": "MySQL 慢查询治理", "a": "pg_stat_statements...", "fresh": "3.13"},
        {"q": "Redis Cluster 扩容", "a": "reshard...", "fresh": "3.12", "stale": True},
    ]
    hits = hybrid_search("重启 Redis 服务", kb)
    assert hits[0]["q"].startswith("重启 Redis")
    print("混合检索 Top1:", hits[0]["q"])
    dups = semantic_dedup(kb)
    assert len(dups) == 1                              # 前两条语义重复 ✅
    print("语义去重命中:", dups, "→ 合并保留信息超集（人工抽检）")
    stale = [e for e in kb if e.get("stale")]
    print("新鲜度标注:", [e["q"] for e in stale], "→ 检索降权+标注")
    # 口径：混合检索（实体优先）；语义去重月度批+入库前查重；
    # 新鲜度标注降权；体检四项（命中率/重复率/过期/孤儿清理）。
```

**追问**：1) 为什么值班场景「实体优先」于语义？——值班查询常含精确实体（服务名/命令/错误码）——「Redis 连接池」语义检索可能命中「Memcached 连接」（语义相近但完全不同的系统）——实体错配在值班场景会造成错误操作；语义检索用于「无精确实体」的描述性查询——两者融合权重按查询类型分。2) 「合并保留信息超集」具体怎么操作？（提示：两篇相似条目合并 = 内容逐段对比，超集字段保留（有回滚步骤的版本为主 + 另一篇的独有细节并入），合并后标 `merged` 并保留双方历史链接——自动合并的风险（细节差异被丢）靠人工抽检对冲）3) 体检四项的执行频率？（提示：命中率回归每两周（检索质量是生命线）、重复率/新鲜度月度、孤儿清理季度——频率与影响面成正比，全部自动脚本化执行（Q7017 管道同构））

## 背诵要点
1. 混合检索：实体精确命中权重 0.7 + 语义相似 0.3——值班场景实体错配不可接受；评测集定期回归。
2. 语义去重：相似度阈值 0.92 + **合并保留信息超集**（人工抽检对冲）——入库前查重比事后清理便宜。
3. 新鲜度标注（适用版本/环境）检索降权；体检四项：命中率回归/重复率/过期扫描/孤儿清理。

## 复盘追问
1. 经验库「搜到 5 条重复」的根因是「每次问都记一条」——入库前查重为什么没做？（提示：入库通道没有查重闸（回答即入库的纪律缺了闸）——查重闸嵌入入库流程（入库时相似度 >0.9 提示合并而非新建，Q176 回答即入库的补全）——闸要在流程里，不是靠月度清理追）
2. 混合检索的权重 0.7/0.3 怎么调才不是拍脑袋？（提示：评测集驱动调参（历史真实问题的命中回归，网格搜索权重）+ 分查询类型动态权重（含精确实体的查询实体权重升到 0.9）——权重是超参数，评测集是调参依据，不是直觉）
