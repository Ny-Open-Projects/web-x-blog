### A141 · 多环境一致性

> 难度:★★☆ | 标签:环境治理, 等价性, 场景题

**问**（笔试·场景题）：「测试环境好好的，生产炸了」——环境不等价的清单有哪些（数据量级/依赖版本/拓扑/参数/数据形态），「预发环境」要等价到什么程度才值得它的成本，「环境隔离」和「环境等价」的张力怎么解（测试要隔离、等价要同构），环境数量怎么收敛（每个团队一套环境会爆炸）？

**答**：① 不等价清单五维：**数据量级**（测试 1000 行 vs 生产 1 亿——执行计划/缓存行为完全不同，Q6063 压测定容同源）、**依赖版本**（测试用 SQLite 生产用 PG——方言差异；测试用 mock 生产用真服务——A106 降级路径没测过）、**拓扑**（单实例 vs 多实例——并发竞态/会话共享问题只在多实例显形）、**参数**（超时/池大小/feature flags 每环境一套——参数漂移）、**数据形态**（测试数据规整、生产数据有脏行——解析边界只在生产触发）。② 预发等价度：**生产同构**（同版本依赖/同拓扑/同参数）+ **生产缩影数据**（脱敏采样，量级 1-10% 但分布相同——等分布比等体量重要）——100% 等价成本≈第二个生产环境，不值得；等价的关键是「差异可枚举」（每个差异点写进文档并被测试覆盖）。③ 隔离 vs 等价张力：隔离要「我的测试不被你污染」，等价要「环境像生产」——解法：**共享生产同构基础设施 + 逻辑隔离**（独立 schema/命名空间/数据标记，Q6014 多租户同构）——物理隔离只给关键团队。④ 环境收敛：按「用途」合并（dev 共享 + 预发共享 + 生产），每团队一套 dev 环境是成本爆炸源；临时环境用按需创建销毁（preview environment，PR 生命周期）。

```python
# 全部标准库；demo 实现「环境等价性审计」
def audit_envs(envs: dict[str, dict], prod: str = "prod") -> list[str]:
    """五维等价性审计：与生产对比列出差异点。"""
    p = envs[prod]
    issues = []
    for env, cfg in envs.items():
        if env == prod: continue
        dims = [
            ("db", cfg.get("db") != p["db"]),
            ("deps", cfg.get("deps_version") != p["deps_version"]),
            ("topology", cfg.get("instances", 1) < 2),
            ("params", cfg.get("timeout") != p["timeout"]),
            ("data_shape", not cfg.get("prod_like_data", False)),
        ]
        for name, drift in dims:
            if drift:
                issues.append(f"{env}: {name} 维度与生产不等价")
    return issues

def preview_env_ttl(pr_open_days: float) -> str:
    """临时环境随 PR 生命周期销毁。"""
    return f"preview env: PR 存续 {pr_open_days} 天，merge 后自动销毁（成本=PR 数×单价）"

if __name__ == "__main__":
    envs = {
        "prod": {"db": "pg16", "deps_version": "2.9", "instances": 8,
                 "timeout": 3.0, "prod_like_data": True},
        "staging": {"db": "pg16", "deps_version": "2.9", "instances": 2,
                    "timeout": 3.0, "prod_like_data": True},        # 同构+缩影
        "dev": {"db": "sqlite", "deps_version": "2.7", "instances": 1,
                "timeout": 30.0, "prod_like_data": False},
    }
    issues = audit_envs(envs)
    print("等价性审计:")
    for i in issues: print("  -", i)
    assert any("dev: db" in i for i in issues) and any("dev: deps" in i for i in issues)
    assert not any("staging: db" in i for i in issues)     # 预发同构 ✅
    print(preview_env_ttl(3))
    # 口径：预发=生产同构+缩影数据（等分布），dev 允许差异但差异点要可枚举可覆盖。
```

**追问**：1) 为什么「等分布比等体量重要」？——执行计划/缓存/分页行为由数据**分布形态**决定（倾斜值/长尾），1% 体量的等分布数据能复现 90% 的生产行为；等体量但人工造的均匀数据反而掩盖问题——数据采样的关键是保留分布。2) dev 环境用 SQLite 明知的差异怎么「可枚举可覆盖」？（提示：差异清单进文档（SQLite 无 SKIP LOCKED——相关代码在集成测试覆盖）+ dev 只跑单元测试、集成测试必须跑预发——差异被流程隔离而非假装不存在）3) preview environment 的成本失控怎么治？（提示：PR 生命周期强绑定销毁 + 并发上限（同时 ≤N 个）+ 资源配额（单 preview 用最小规格）——成本可见性（每 PR 成本标注）约束滥用）

## 背诵要点
1. 环境不等价五维：数据量级/依赖版本/拓扑/参数/数据形态——每个差异点可枚举并被测试覆盖。
2. 预发 = 生产同构 + 等分布缩影数据（脱敏采样，等分布比等体量重要）；100% 等价不值得。
3. 隔离与等价解法：共享同构设施 + 逻辑隔离（schema/命名空间）；环境按用途收敛，临时环境随 PR 生命周期。

## 复盘追问
1. 「生产炸了」但 staging 完全复现不了，审计全绿——审计漏了什么维度？（提示：审计只覆盖了静态配置维度——动态维度（流量形态/并发时序/第三方行为）无法静态对比，需要流量回放（Q7013 压测同构）或生产影子验证）
2. 团队说「预发数据太老测不出问题」，缩影数据的保鲜怎么解？（提示：每日/每周自动刷新采样管道（脱敏流水线 Q7012 复用）+ 采样后行数与分布校验——新鲜度也是缩影数据的质量维度）
