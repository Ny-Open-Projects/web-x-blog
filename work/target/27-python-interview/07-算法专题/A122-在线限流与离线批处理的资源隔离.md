### A122 · 在线/离线资源隔离

> 难度:★★★ | 标签:资源隔离, 在离混部, 场景题

**问**（笔试·场景题）：离线批处理（每日跑批）和在线 API 服务同集群部署，跑批一开在线 P99 从 50ms 飙到 400ms——吵闹邻居（noisy neighbor）的资源维度有哪些（CPU/内存/IO/网络/缓存），隔离手段分级（物理隔离/容器配额/内核参数/cgroup 压制）各挡什么，「在线优先抢占」怎么实现才不误杀离线任务？

**答**：① 噪声维度五项：**CPU**（批处理吃满核，在线线程被调度延迟）、**内存**（批处理内存膨胀 → 页回收/swap，在线请求缺页变慢）、**磁盘 IO**（批处理顺序写打满盘，在线随机读排队）、**网络**（批处理拉数据打满带宽，在线响应超时）、**LLC 缓存**（批处理的大工作集把在线的热数据挤出三级缓存——CPU 没满但慢，最难查）。② 隔离分级：**物理隔离**（不同集群/机型，最贵最彻底）；**容器配额**（CPU limit/memory limit——注意 CPU limit 引发的 CFS 排队毛刺，Q6025）；**内核参数**（nice/ionice/cgroup cpu.weight——在线设高权重，离线低权重；blkio/io.max 限 IO 带宽）；**混部时间窗**（离线只在深夜在线低峰跑，白天抢占）。③ 抢占实现：在线负载超阈值（如 CPU > 70%）触发离线任务自动降级（暂停/降并发/迁移走）——「软抢占」用信号（SIGSTOP 暂停批任务）比 SIGKILL 安全（任务可恢复，配合检查点 Q7017）；误杀防护 = 离线任务必须有断点（被杀可续）才能参与抢占池。

```python
# 全部标准库；demo 实现「负载感知抢占控制器」
import time, random

class PreemptionController:
    """在线优先：CPU 超阈 → 软抢占离线（SIGSTOP 语义：暂停可恢复）。"""
    def __init__(self, online_cpu_threshold: float = 0.70):
        self.th = online_cpu_threshold
        self.offline_jobs: dict[str, dict] = {}      # job -> {state, checkpoint}
        self.pause_log: list[str] = []
    def register(self, job: str, resumable: bool):
        self.offline_jobs[job] = {"state": "running", "resumable": resumable,
                                  "checkpoint": 0.0}
    def tick(self, online_cpu: float):
        if online_cpu <= self.th:
            # 低峰：恢复暂停的离线任务（FIFO）
            for job, m in self.offline_jobs.items():
                if m["state"] == "paused" and m["resumable"]:
                    m["state"] = "running"
                    self.pause_log.append(f"resume {job} @ checkpoint {m['checkpoint']:.0%}")
                    break
            return "healthy"
        for job, m in self.offline_jobs.items():     # 高负载：暂停（非杀死）
            if m["state"] == "running":
                if not m["resumable"]:
                    self.pause_log.append(f"SKIP {job}（无断点，不可抢占——改调度时间窗）")
                    continue
                m["state"] = "paused"
                self.pause_log.append(f"pause {job}（在线 CPU {online_cpu:.0%} 超阈）")
                return "preempted"
        return "no-offline-to-preempt"

if __name__ == "__main__":
    random.seed(1)
    c = PreemptionController(threshold=0.70)
    c.register("nightly-etl", resumable=True)        # 有断点：可抢占
    c.register("one-shot-report", resumable=False)   # 无断点：不可抢，靠时间窗错峰
    c.tick(0.85)                                     # 在线超阈 → 暂停 etl
    states = {j: m["state"] for j, m in c.offline_jobs.items()}
    assert states["nightly-etl"] == "paused"
    c.tick(0.40)                                     # 低峰 → 恢复
    states = {j: m["state"] for j, m in c.offline_jobs.items()}
    assert states["nightly-etl"] == "running"
    print("抢占控制器:", c.pause_log)
    print("软抢占（暂停+断点恢复）✅ 无断点任务靠时间窗错峰不硬杀 ✅")
    # 噪声五维：CPU/内存/磁盘 IO/网络/LLC 缓存——LLC 污染最难查（CPU 未满仍慢）。
```

**追问**：1) CPU limit 为什么本身会制造毛刺？——CFS 配额按周期扣（如 100ms 窗口），用满即 throttle 到下一周期——在线服务被自己 limit 卡住（Q6025）；混部下离线任务配低权重（cpu.weight）而非硬 limit，让调度器自然偏在线。2) LLC 污染怎么证实与缓解？——`perf` 观察 LLC miss 率在跑批开启后跳升即证实；缓解：缓存亲和（进程绑核）、Intel CAT（Cache Allocation Technology 划分缓存配额）、或干脆物理隔离。3) 「无断点任务不可抢占」的工程含义？——批任务要参与混部必须改造为可断点续跑（Q7017 水位）——这是混部的准入门槛，也倒逼任务质量提升。

## 背诵要点
1. 吵闹邻居五维：CPU/内存/磁盘 IO/网络/LLC 缓存——LLC 污染最难查（CPU 未满仍慢）。
2. 隔离分级：物理 > 容器配额（注意 CFS 毛刺）> 内核参数（cpu.weight/io.max）> 时间窗错峰。
3. 软抢占：SIGSTOP 暂停 + 断点恢复（不 SIGKILL）；无断点任务不可抢占，准入混部必须可续跑。

## 复盘追问
1. 在线 P99 劣化但 CPU/内存/IO 都不高，剩下的嫌疑是什么？（提示：LLC 污染或 NUMA 跨节点访问——perf c2c/miss 率确认；这也是「指标全绿但用户慢」的经典形态）
2. 混部收益（成本省 30%+）与风险怎么定价？（提示：在线服务 SLO 损失成本 vs 机器成本——关键在线服务混部门槛高（强隔离），可混的是低危/可重试负载）
