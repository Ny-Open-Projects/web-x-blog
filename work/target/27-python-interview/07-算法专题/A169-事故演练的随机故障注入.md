### A169 · 混沌工程安全边界

> 难度:★★★ | 标签:混沌工程, 故障注入, 演练

**问**（笔试·场景题）：想在生产环境注入故障（杀掉 10% 的实例/延迟 500ms 的网络）验证系统韧性——「混沌工程」的准入条件（什么系统才能在生产注入），注入的「爆炸半径控制」（最小爆炸/中止条件/自动终止），「演练设计」怎么避免「注入了但什么都没验证到」（假设先行），演练发现的「问题清单」怎么转成行动项（与 A138 复盘闭环）？

**答**：① 准入条件四条：**可观测性完备**（看不到的故障注入=白炸）、**降级路径已实现**（演练验证的是降级，没有降级注入=直接事故）、**值班知情且有权中止**（一键停止演练——爆炸半径的最后一道闸）、**非业务高峰**（且演练影响面 < 真实容灾预算）。② 爆炸半径控制：**最小化**（从 1 个实例/1% 流量开始，验证假设后逐步扩大）、**自动中止**（错误率/P99 超阈即自动终止注入——护栏自动化，不等人工）、**隔离域**（先注入非核心服务/影子环境——核心链路最后碰）。③ 假设先行：演练前写**可证伪假设**（「杀掉缓存实例后，错误率应 <1%（因为本地缓存+单飞保护）」）——注入后验证假设：假设成立=韧性验证通过；假设不成立=发现真实缺陷（这就是演练的价值）——「注入了但没写假设」= 只是把服务搞挂了一遍（无学习价值的表演）。④ 行动项闭环：演练发现的缺陷 → 缺陷清单 → 按 A138 行动项机制（owner/deadline/验证=下次演练复测）——「演练复测」是行动项的天然验证方式（下次演练同场景应通过）。

```python
# 全部标准库；demo 实现「混沌演练控制器：假设先行+爆炸半径+自动中止」
import time

class ChaosExperiment:
    def __init__(self, name: str, hypothesis: str, blast_radius: int,
                 abort_conditions: dict, approved: bool):
        # 假设先行：可证伪假设必填
        assert hypothesis and "应" in hypothesis, "演练必须先写可证伪假设"
        # 爆炸半径：从最小开始（1 实例/1% 流量）
        assert 1 <= blast_radius <= 10, "爆炸半径必须从最小开始"
        # 准入：值班知情 + 降级路径 + 自动中止条件齐备
        assert approved and abort_conditions.get("err_rate") is not None
        self.name, self.hypothesis = name, hypothesis
        self.blast, self.abort = blast_radius, abort_conditions
        self.running, self.log = False, []
        self.findings: list[str] = []
    def start(self):
        self.running = True
        self.log.append(f"注入开始: {self.name} (半径={self.blast})")
    def tick(self, err_rate: float) -> bool:
        """每 tick 检查自动中止条件；返回是否继续。"""
        if not self.running:
            return False
        if err_rate > self.abort["err_rate"]:
            self.running = False
            self.log.append(f"自动中止: 错误率 {err_rate:.1%} 超阈")
            self.findings.append("假设不成立：降级路径未能限制错误率")
            return False
        self.log.append(f"tick: err {err_rate:.1%} within budget, 继续")
        return True
    def conclude(self, hypothesis_holds: bool):
        verdict = "假设成立：韧性验证通过" if hypothesis_holds else \
                  "假设不成立：发现缺陷 → 行动项（下次演练复测）"
        self.log.append(verdict)
        self.findings.append(verdict)
        return verdict

if __name__ == "__main__":
    exp = ChaosExperiment(
        name="杀缓存实例",
        hypothesis="杀掉缓存实例后错误率应 <1%（本地缓存+singleflight 兜底）",
        blast_radius=1,
        abort_conditions={"err_rate": 0.01},
        approved=True)
    exp.start()
    exp.tick(0.004)                            # 注入后错误率 0.4% < 1% 预算
    exp.tick(0.006)
    verdict = exp.conclude(hypothesis_holds=True)
    print(verdict)
    assert "通过" in verdict
    print("\n".join(exp.log))
    # 违规示例：无假设的演练
    try:
        ChaosExperiment("盲注", "", blast_radius=1,
                        abort_conditions={"err_rate": 0.01}, approved=True)
    except AssertionError as e:
        print("准入拦截：", e, "✅（注入了但没验证=表演）")
    # 口径：假设先行（可证伪）+ 最小爆炸半径 + 自动中止 + 行动项闭环（下次复测）。
```

**追问**：1) 为什么「注入了但没写假设」等于表演？——混沌工程的价值是「验证韧性假设」（系统设计者声称的容错能力是否真实）；无假设注入只是「随机搞挂服务」，结果无法指导改进（不知道在验证什么）——「假设→注入→验证→行动项」的闭环才是混沌工程的内核。2) 「核心链路最后碰」的顺序怎么排？（提示：非核心服务 → 核心服务的非关键依赖 → 核心链路（最后，且前序演练已证明相关能力）——排序依据是爆炸半径 × 恢复能力（Q123 影响面 + A106 降级成熟度）；每层通过才进下一层）3) 演练发现的问题「修了但没复测」，怎么保证不再犯？（提示：行动项验证方式绑定「下次演练同场景复测」（A138 闭环）——演练日历排期时优先排「上次发现缺陷的场景」；未复测通过的行动项升级到架构周会）

## 背诵要点
1. 混沌准入四条：可观测性完备/降级路径已实现/值班知情可中止/非高峰且影响面 < 容灾预算。
2. 爆炸半径控制：最小化起步（1 实例/1% 流量）+ 自动中止（错误率超阈即停）+ 非核心先行核心最后。
3. 假设先行：可证伪假设 → 注入验证 → 行动项闭环（下次演练同场景复测）——无假设 = 表演。

## 复盘追问
1. 演练发现「杀缓存实例后错误率 15%」（假设 1%）——团队说「这是演练环境，生产没这个问题」，可信吗？（提示：演练环境≠生产但方向可信（降级路径缺陷是共性的）——验证方式：生产环境用更小半径注入（1 实例）确认，或至少代码审查降级逻辑；「环境差异」是常见借口，要证据不是口头）
2. 混沌演练做了三次，每次都发现新问题——要不要继续做？（提示：要——发现率下降说明韧性提升（收敛信号）；发现率不降 = 修得慢或不彻底（行动项闭环失效）——用「每次演练缺陷数」趋势图量化演练价值，向管理层汇报用数据）
