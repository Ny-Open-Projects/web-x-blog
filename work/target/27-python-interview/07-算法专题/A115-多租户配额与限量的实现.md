### A115 · 多租户配额与限量

> 难度:★★★ | 标签:配额, 多租户, 计费

**问**（笔试·编程+场景题）：SaaS 平台按套餐限租户用量（免费版 1000 次/月 API 调用）——配额记账怎么实现（窗口口径：自然月 vs 滚动 30 天），记账的原子性与漂移（计数和账单不一致）怎么处理，超额时的策略分级（硬拒/软限速/降级），配额系统的性能怎么扛（每请求都查 Redis 的代价）？

**答**：① 窗口口径：自然月（对用户直观、计费对齐）vs 滚动 30 天（防月末突击）；实现用**月桶键**（`quota:{tenant}:{yyyy-mm}`，TTL 到月末+缓冲），滚动窗口用两桶加权（A110 双窗口同构）。② 原子记账：**预扣-结算**模式——请求前 `DECRBY` 预扣（不足即拒），实际用量异步对账修正（上游失败回补）——比「先调用后计数」防超卖（并发下先调后计必然超额）。③ 漂移处理：Redis 计数是**快账**（实时拦截），账单系统是**慢账**（权威）——每日对账任务 diff，差异以账单为准回写 Redis（漂移通常来自重试重复计数/失败未回补）。④ 超额分级：免费版硬拒（429+升级引导）、付费版软限速（降 QPS 而非拒绝）、关键客户宽限期（超额 10% 内放行+告警，商务跟进）。⑤ 性能：每请求 DECRBY 是一次 Redis RTT（~0.5ms）——高 QPS 租户改**批量预扣**（一次扣 100 次配额到本地令牌桶，本地耗尽再续——延迟从每请求一次变每百次一次，代价是崩溃时丢本地余量，少计不多计）。

```python
# 全部标准库；demo 实现「预扣-结算 + 本地批量预扣 + 月桶」
import time, threading

class QuotaLedger:
    def __init__(self, monthly: int = 1000):
        self.monthly = monthly
        self.buckets: dict[str, int] = {}          # 月桶：yyyy-mm -> 剩余额度
        self.pending: dict[str, int] = {}          # 预扣未结算（失败回补）
        self.lock = threading.Lock()
    def _bucket(self) -> str:
        return time.strftime("%Y-%m")
    def reserve(self, tenant: str, n: int = 1) -> bool:
        """预扣：不足即拒（原子）。"""
        with self.lock:
            key = (tenant, self._bucket())
            cur = self.buckets.get(key, self.monthly)
            if cur < n:
                return False                        # 硬拒：超额
            self.buckets[key] = cur - n
            self.pending[key] = self.pending.get(key, 0) + n
            return True
    def settle(self, tenant: str, used: int):
        """结算：实际用量（失败回补差额）。"""
        with self.lock:
            key = (tenant, self._bucket())
            p = self.pending.get(key, 0)
            refund = max(0, p - used)
            self.buckets[key] = self.buckets.get(key, self.monthly) + refund
            self.pending[key] = p - used
            return refund
    def remaining(self, tenant: str) -> int:
        return self.buckets.get((tenant, self._bucket()), self.monthly)

class LocalQuota:
    """批量预扣：本地令牌桶一次领 100，耗尽再向中心续——RTT 降 100×。"""
    def __init__(self, ledger: QuotaLedger, tenant: str, chunk: int = 100):
        self.ledger, self.tenant, self.chunk = ledger, tenant, chunk
        self.local = 0
        self.lock = threading.Lock()
    def allow(self) -> bool:
        with self.lock:
            if self.local <= 0:
                if not self.ledger.reserve(self.tenant, self.chunk):
                    return False                    # 中心配额尽
                self.local = self.chunk
            self.local -= 1
            return True

if __name__ == "__main__":
    led = QuotaLedger(monthly=100)
    assert led.reserve("t1") and led.reserve("t1")
    led.settle("t1", used=1)                          # 第 2 次失败回补 1
    assert led.remaining("t1") == 99
    print("预扣-结算：失败回补后余额 99 ✅")
    led2 = QuotaLedger(monthly=100)
    lq = LocalQuota(led2, "t2", chunk=50)
    ok = sum(1 for _ in range(130) if lq.allow())     # 130 次请求，中心只被扣 3 次（50×3>100）
    assert ok == 100, f"硬上限 100，实际 {ok}"
    print(f"本地批量预扣：130 请求放行 {ok}（硬上限不破），中心记账 RTT 仅 3 次 ✅")
    # 口径：崩溃丢本地余量 = 少计（平台让利可接受）；多计（超额放行）绝不允许。
```

**追问**：1) 为什么「本地丢余量」是可接受方向？——少计让用户占便宜（可忽略），多计让用户超额付费/被误拒（投诉与信任损失）——记账误差方向必须偏向平台让利。2) 跨月桶的请求（月末最后一秒发起、次月结算）怎么算？——按「调用时刻」入月桶（用户视角直觉）；结算跨月的边缘在回补时用同一桶键快照，避免回补给新月。3) 配额系统的可用性怎么定？——配额挂了 fail-open（放行+告警）还是 fail-close（拒绝）？按收入模式：免费层 fail-open（可用性优先）、计费硬上限 fail-close（收入保护）——分级策略写进设计。

## 背诵要点
1. 预扣-结算防超卖：请求前 DECRBY 原子预扣，失败回补；Redis 快账 + 账单慢账每日对账。
2. 本地批量预扣（一次领 100）降 RTT 100×，代价崩溃丢余量——误差方向必须偏向「少计」。
3. 超额分级：免费硬拒 / 付费软限速 / 关键客户宽限期；配额系统故障按收入模式定 fail-open/close。

## 复盘追问
1. 租户被刷（恶意消耗免费配额），配额之外的防线？（提示：IP/设备指纹维度限流（A101）+ 注册风控——配额管用量、风控管身份）
2. 月初计费出账时发现某租户用量是 Redis 计数的 2 倍，最可能的原因？（提示：重试路径重复预扣未回补 / 本地预扣跨实例未合并 / 对账任务停了——先查对账任务健康度）
