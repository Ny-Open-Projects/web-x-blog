### A251 · 任务依赖的拓扑排序与环检测

> 难度:★★★★ | 标签:拓扑排序, Kahn, 环检测, 关键路径

**问**（笔试·编程题）：写一个任务调度器要用的依赖图引擎，输入是 `nodes` 和 `edges`（`u -> v` 表示 u 必须在 v 之前完成），要求：① 输出**可执行批次**——同一批内的任务互不依赖、可以并行，批次之间严格有序；② 检测环并**输出一条具体的环路径**（不是只报「有环」）；③ 输出**关键路径**（最长链）与总工期；④ 结果确定性——同样的图，输入顺序不同也必须输出完全相同的批次；⑤ 5000 节点的深链不能触发递归上限；⑥ 任务失败重跑时，只重算它影响的下游集合。约束：纯标准库。请说明与 Q5145（`graphlib.TopologicalSorter`）、Q1151/Q2291（DAG 执行）、Q2634（graphlib 拓扑排序）的分工，以及「严格按层栅栏执行」在生产上的问题。

**答**：① 与已有卡的分工：Q5145 讲 `graphlib` 的三段式协议（`prepare` / `get_ready` / `done`）与 `CycleError`，Q2634 讲 `TopologicalSorter` 的基本用法，Q1151/Q2291 讲工具 DAG 的就绪驱动执行。它们解决的是「能不能排出一个合法全序」。A188 从发布编排的角度用过拓扑序（顺序 + 兼容窗口 + 人工确认点），但拓扑只是它的一步，没有环路径定位、没有关键路径、没有确定性约束。本题补三个 `graphlib` 与 A188 都不直接给的东西：**分层批次快照**（同一批可并行的集合，这是并发度的直接来源）、**关键路径**（决定「加机器也没用」的短板）、**确定性**（`static_order` 的顺序受插入顺序影响，重放和分布式调度需要可复现）。另外 `CycleError` 只给一条路径且不保证落在剩余子图里，做「配置校验 → 精确告诉用户哪几个任务互相依赖」时，自己走颜色 DFS 更可控。② Kahn 分层：入度表 + 邻接表，每轮把「当前所有入度 0」的节点全部取出作为一个批次，然后统一减后继入度。层宽 = 该层的理论最大并行度。这里有个容易忽略的点：**批次是拓扑语义，不是执行策略**。严格按层栅栏执行（一层全跑完才开下一层）会有长尾等待——一层里 9 个任务 1 分钟、1 个任务 1 小时，整层就要等 1 小时，另外 9 个 worker 空转。生产调度应该用「就绪队列 + 完成即解锁」（`get_ready` 的语义），批次只用来做并发度预估、资源预留和可视化。③ 确定性：同层用 `heapq`/排序固定顺序，同一张图无论节点以什么顺序传入，批次划分与序都一致。代价是字典序贪心可能让层宽略差（把本可与 A 同批的节点排到了下一批），这是「可复现」换「最优并行度」，调度器几乎总是选前者——否则同一个 DAG 两次跑的批次不同，测试、审计、回滚都没法对账。④ 环检测：Kahn 跑完后仍有入度 > 0 的节点，说明这些节点在环上（或环的下游）。要给出具体环，就在**剩余子图**上做颜色标记的 DFS：白=未访问、灰=在栈上、黑=已完成；遇到灰点就是回边，栈里从该灰点到栈顶正好构成一个环。必须**迭代实现**（显式栈 + 迭代器），递归版在 5000 节点深链上直接 `RecursionError`（默认上限 1000）——这是本题最实在的工程约束，别在笔试里写递归然后说「可以调 `setrecursionlimit`」，那是把崩溃推迟到 10 万节点。⑤ 关键路径：`est[v] = max(est[u] + dur[u])`（u 是 v 的前驱），总工期 = `max(est[v] + dur[v])`；它是**下界**也是**可达上界**（只要资源足够），所以「加人不能缩短总工期」当且仅当关键路径不变。实测把 docs 的工期从 2 改成 9，总工期 17 → 19，关键路径从 `test` 链切到 `docs` 链——这就是「优化瓶颈才有用」的量化版本。⑥ 增量重跑：失败节点只需重算它的**下游闭包**（正向 BFS），上游和兄弟分支的结果可以复用。注意方向很容易写反：用反向边 BFS 得到的是祖先（上游），重跑上游纯属浪费，而且会把已成功的产物重算一遍，可能引入新的不确定性。⑦ 工程细节：入度表要校验边引用的节点存在（否则静默丢边，图会「看起来」拓扑成功）；`edges` 里有重复边时入度会多算，导致永远不为 0 的假环——需要去重或明确约定；超大图（百万节点）用 CSR 数组存邻接表而不是 `dict[str, list]`，内存能降一个数量级。

```python
# 全部标准库；Kahn 分层批次 + 迭代 DFS 环路径 + 关键路径 + 增量影响集
import heapq
from collections import defaultdict, deque


def build(nodes, edges):
    adj = defaultdict(list)
    rev = defaultdict(list)
    indeg = {n: 0 for n in nodes}
    for u, v in edges:
        if u not in indeg or v not in indeg:
            raise KeyError("边引用了不存在的任务: %s->%s" % (u, v))
        adj[u].append(v)
        rev[v].append(u)
        indeg[v] += 1
    for n in nodes:
        adj[n].sort()
        rev[n].sort()
    return adj, rev, indeg


def batches(nodes, edges):
    """Kahn 分层：返回 (批次列表, 拓扑序, 剩余节点)。同批内可并行。"""
    adj, _, indeg = build(nodes, edges)
    ready = [n for n in nodes if indeg[n] == 0]
    heapq.heapify(ready)
    out, order = [], []
    while ready:
        batch = []
        while ready:
            batch.append(heapq.heappop(ready))
        out.append(batch)
        for u in batch:
            order.append(u)
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    heapq.heappush(ready, v)
    left = [n for n in nodes if indeg[n] > 0]
    return out, order, left


def cycle_path(nodes, edges):
    """在剩余子图里找一条具体环（迭代 DFS，颜色标记），不存在返回 None。"""
    adj, _, indeg = build(nodes, edges)
    white, gray, black = 0, 1, 2
    color = {n: white for n in nodes}
    for start in sorted(nodes):
        if color[start] != white:
            continue
        color[start] = gray
        stack = [(start, iter(adj[start]))]
        path = [start]
        while stack:
            node, it = stack[-1]
            stepped = False
            for v in it:
                if color[v] == white:
                    color[v] = gray
                    stack.append((v, iter(adj[v])))
                    path.append(v)
                    stepped = True
                    break
                if color[v] == gray:                 # 回边：栈里 v..node 就是环
                    return path[path.index(v):] + [v]
            if not stepped:
                color[node] = black
                stack.pop()
                path.pop()
    return None


def critical_path(nodes, edges, dur):
    """最长链 = 最短完工时间（工期由关键路径决定，加机器也没用）。"""
    adj, rev, _ = build(nodes, edges)
    order, left = batches(nodes, edges)[1], batches(nodes, edges)[2]
    if left:
        raise ValueError("图里有环，先解环: %s" % cycle_path(left, edges))
    est, parent = {}, {}
    for u in order:
        best, bp = 0, None
        for p in rev[u]:
            if est[p] + dur[p] > best:
                best, bp = est[p] + dur[p], p
        est[u] = best
        parent[u] = bp
    end = max(order, key=lambda n: est[n] + dur[n])
    total, cur, chain = est[end] + dur[end], end, []
    while cur is not None:
        chain.append(cur)
        cur = parent[cur]
    chain.reverse()
    return total, chain


def affected(edges, failed):
    """失败重跑：只重算它的所有下游（正向下游 BFS），上游已完成结果可复用。"""
    adj = defaultdict(list)
    for u, v in edges:
        adj[u].append(v)
    seen, q = {failed}, deque([failed])
    while q:
        cur = q.popleft()
        for v in adj[cur]:
            if v not in seen:
                seen.add(v)
                q.append(v)
    return seen


if __name__ == "__main__":
    nodes = ["build", "lint", "test", "e2e", "docs", "pack", "deploy", "notify"]
    edges = [("lint", "build"), ("build", "test"), ("build", "docs"),
             ("test", "e2e"), ("test", "pack"), ("e2e", "deploy"),
             ("pack", "deploy"), ("docs", "pack"), ("deploy", "notify")]
    bs, order, left = batches(nodes, edges)
    assert left == []
    pos = {n: i for i, b in enumerate(bs) for n in b}
    for u, v in edges:
        assert pos[u] < pos[v], (u, v)          # 依赖必须落在更早的批次
    assert bs[0] == ["lint"] and bs[-1] == ["notify"]
    assert sorted(order) == sorted(nodes) and len(order) == len(nodes)
    print("分层批次(%d 批, 最大并行度 %d): %s"
          % (len(bs), max(len(b) for b in bs), " | ".join(",".join(b) for b in bs)))

    # 环：检测 + 给出具体路径，而不是只说「有环」
    bad = ["a", "b", "c", "d"]
    bad_edges = [("a", "b"), ("b", "c"), ("c", "a"), ("d", "a")]
    bs2, order2, left2 = batches(bad, bad_edges)
    assert left2 == ["a", "b", "c"] and "d" not in left2
    cyc = cycle_path(left2, [e for e in bad_edges if e[0] in left2 and e[1] in left2])
    assert cyc == ["a", "b", "c", "a"], cyc
    print("环检测: 剩余 %s，具体环 %s ✅" % (left2, "->".join(cyc)))

    # 确定性：输入顺序打乱，批次结果必须完全一致
    import random
    for seed in range(5):
        rnd = random.Random(seed)
        shuffled = nodes[:]
        rnd.shuffle(shuffled)
        assert batches(shuffled, edges)[0] == bs
    print("确定性: 5 种输入顺序打乱后批次完全一致 ✅")

    # 关键路径：改 docs 的工期，总工期跟着变，说明短板在哪
    dur = {"lint": 1, "build": 3, "test": 5, "e2e": 4, "docs": 2, "pack": 2,
           "deploy": 3, "notify": 1}
    total, chain = critical_path(nodes, edges, dur)
    assert total == 17 and chain == ["lint", "build", "test", "e2e", "deploy", "notify"]
    dur2 = dict(dur, docs=9)
    total2, chain2 = critical_path(nodes, edges, dur2)
    assert total2 == 19 and "docs" in chain2
    print("关键路径: %s = %d；docs 工期加到 9 后变成 %s = %d ✅"
          % ("->".join(chain), total, "->".join(chain2), total2))

    # 深链 5000 节点：递归版必炸 RecursionError，迭代版稳过
    deep_nodes = ["t%d" % i for i in range(5000)]
    deep_edges = [("t%d" % i, "t%d" % (i + 1)) for i in range(4999)]
    bs3, order3, left3 = batches(deep_nodes, deep_edges)
    assert left3 == [] and len(bs3) == 5000
    assert cycle_path(deep_nodes, deep_edges) is None
    print("深链 5000 节点: %d 批、无环判定正常，未触发递归上限 ✅" % len(bs3))

    # 失败重跑：test 挂了只影响 e2e/pack/deploy/notify
    rerun = affected(edges, "test")
    assert rerun == {"test", "e2e", "pack", "deploy", "notify"}, rerun
    assert "build" not in rerun and "docs" not in rerun
    print("失败重跑范围: %s（build/lint/docs 结果可复用）✅" % sorted(rerun))
```

**追问**：1) 为什么有了 Kahn 还要再写一遍 DFS？—— 两者解决不同问题。Kahn 顺带就能判「有没有环」（有剩余节点即有环），但剩下的节点集合包含「环上的」和「被环卡住的下游」，它不告诉你环长什么样；用户看到「有 3 个任务无法调度」根本不知道该改哪条依赖。DFS 的三色标记在遇到回边时能直接给出栈上那一段（本 demo 输出 `a->b->c->a`），这才是可操作的错误信息。反过来说，如果只需要布尔判定，Kahn 一遍就够，不必再跑 DFS。2) 严格按层栅栏执行有什么问题，怎么改？—— 长尾等待。层内最慢的任务决定整层耗时，快任务完成后 worker 空转；层数越多、任务时长方差越大，浪费越严重（本 demo 的 `lint | build | docs,test | ...` 六层里，如果 test 要 1 小时而 docs 只要 1 分钟，第三层的 8 个 worker 有 7 个在等）。改法是「就绪队列 + 完成即解锁」：任何任务完成就把后继入度减一，减到 0 立刻入队执行——这正是 `graphlib` 的 `get_ready`/`done` 语义，也是 Airflow/Celery 等调度器的做法。批次仍然有用，但用途变成「预估最大并发 / 预留资源 / 画甘特图」。3) 关键路径为什么是「加人也没用」的证明？—— 总工期是所有路径长度的最大值，关键路径上的任务首尾相接、没有任何并行空间，加机器只能缩短非关键路径上的任务，而它们本来就有余量（有浮动时间）。要缩短总工期只有三条路：拆细关键路径上的任务（增加可并行粒度）、压缩关键任务的工期（换实现/加资源给它）、或者改变依赖关系（把串行改成部分并行）。这也是为什么性能优化前要先算关键路径——不然优化了半天，优化的全是浮动时间。

## 背诵要点
1. Kahn 分层 = 入度表 + 每轮取全部零入度；同批可并行，但生产执行用「完成即解锁」而非层栅栏（否则长尾等待）；同层排序保证确定性。
2. 环 = Kahn 后剩余节点；要定位具体环用三色迭代 DFS（遇灰点即回边，栈段即环）；深图必须迭代，递归默认 1000 层就炸。
3. 关键路径 `est[v] = max(est[u] + dur[u])`，总工期取最大值；失败重跑只算**下游**闭包，方向写反会白跑上游。

## 复盘追问
1. 调度器里某个任务「永远不开始」，怎么定位？（提示：先看入度——它的入度是否为 0，不为 0 说明某个前驱没被标记完成，常见原因是前驱执行完但回调丢了/进程被杀没写完成位；再查重复边导致的入度虚高，以及 DAG 版本热更新时新旧图的节点 ID 不匹配）
2. 依赖图有 10 万节点、每天变更上百次，每次都全量重排会不会成为瓶颈？（提示：Kahn 是 O(V+E) 的，10 万节点级别也就几十毫秒，真正贵的是「每次变更都重算关键路径 + 重排资源」；做法是增量——只重算被修改节点的下游闭包，上游与无关分支复用上一版结果，和失败重跑是同一套数据结构）
