### A192 · 租户生命周期

> 难度:★★☆ | 标签:多租户, 生命周期, 合规

**问**（笔试·场景题）：SaaS 平台的租户「生命周期」不止开通——欠费冻结（冻结≠删除，数据保留策略）、注销（GDPR 数据删除与备份保留的冲突 Q138）、租户迁移（从共享池迁独立实例，Q6014），每个阶段的资源处置（配额/缓存/队列）怎么联动，「注销后的数据残留」在哪几个地方最容易漏（缓存/备份/日志/搜索索引）？

**答**：① 生命周期四阶段：**active**（正常）→ **suspended**（欠费/违规：只读降级——数据保留 90 天，续费即恢复）、**deleting**（注销：用户申请+冷静期 7 天）、**purged**（彻底删除：业务数据删+备份按合规保留+搜索索引/缓存清理）——每阶段资源处置联动（suspended 时配额清零/队列任务清空/缓存可清；deleting 时逐资源清理并留销毁凭证）。② 残留重灾区五处：**缓存**（Redis 键带 tenant_id——删除主数据不清缓存，恢复幽灵数据 Q6516）、**搜索索引**（ES 索引按租户分——主库删了索引还在，搜索仍能搜到）、**备份**（历史备份含该租户数据——按合规保留 vs 用户删除权冲突，GDPR 口径：备份保留但恢复时排除该租户数据）、**日志**（含租户 PII——保留期内按保留策略，Q6015）、**派生数据**（数据仓库/ML 特征表——下游管道常被漏）。③ 迁移（共享池 → 独立实例）：双写同步 → 校验 → 切流量 → 旧租户数据下线（A113 回切谨慎语义同构）。

```python
# 全部标准库；demo 实现「租户状态机 + 注销清理清单」
from enum import Enum

class St(Enum):
    ACTIVE = "active"; SUSPENDED = "suspended"; DELETING = "deleting"; PURGED = "purged"

LEGAL = {St.ACTIVE: {St.SUSPENDED, St.DELETING},
         St.SUSPENDED: {St.ACTIVE, St.DELETING},     # 冻结可恢复或注销
         St.DELETING: {St.PURGED},                   # 注销冷静期后彻底清除
         St.PURGED: set()}

class Tenant:
    def __init__(self, tid: str):
        self.tid, self.state = tid, St.ACTIVE
    def transition(self, to: St):
        assert to in LEGAL[self.state], f"非法转移 {self.state}→{to}"
        self.state = to

def purge_checklist(tid: str) -> dict[str, bool]:
    """注销清理清单：六处残留逐项核对（漏一处=数据泄漏）。"""
    return {"main_db": True,           # 业务主数据
            "cache_keys": False,       # Redis 缓存键（重灾区①）
            "search_index": False,     # ES 搜索索引（重灾区②）
            "backups_marked": True,    # 备份标记排除恢复（合规保留）
            "logs_pii": True,          # 日志按保留策略（保留期内保留）
            "warehouse_derived": False # 数仓/ML 特征派生表（重灾区③）
            }

def purge_done(checklist: dict[str, bool]) -> bool:
    return all(checklist.values())          # 全部为 True 才可 PURGED

if __name__ == "__main__":
    t = Tenant("t-42")
    t.transition(St.SUSPENDED)               # 欠费冻结：只读降级
    t.transition(St.ACTIVE)                  # 续费恢复
    t.transition(St.DELETING)                # 注销（冷静期 7 天）
    chk = purge_checklist("t-42")
    assert not purge_done(chk)               # 缓存/索引/派生表未清 → 不能 PURGED
    print("注销清理清单:", chk)
    for k in chk: chk[k] = True              # 全部清理完成
    assert purge_done(chk)
    t.transition(St.PURGED)
    print(f"租户 t-42 → PURGED ✅（冷静期后全清单核对通过）")
    # 口径：冻结≠删除（数据保留 90 天可恢复）；注销六处残留（缓存/索引/备份/日志/派生/主库）。
```

**追问**：1) 为什么「冻结」用只读降级而不是直接锁账号？——直接锁登录的用户投诉最烈且「续费挽回」时数据可能已被清（误伤）；只读保留 90 天 = 欠费可挽回、用户可导出自己的数据——冻结期是「挽回窗口」不是惩罚期。2) 「备份含已注销租户数据」与 GDPR 删除权的冲突怎么解？（提示：备份按合规保留（审计需要）但标记「恢复时排除该租户数据」（恢复过滤器）+ 备份到期自然销毁——完全删除备份会让其他租户的容灾能力丧失，过滤恢复是两全解）3) 注销冷静期 7 天内用户反悔了怎么办？（提示：DELETING 状态可恢复到 ACTIVE（数据还在）——冷静期就是反悔窗口；PURGED 后不可逆，所以「彻底删除」必须在冷静期后）

## 背诵要点
1. 四阶段状态机：active → suspended（只读冻结 90 天挽回窗口）→ deleting（冷静期 7 天）→ purged（不可逆）。
2. 注销六处残留：主库/缓存/搜索索引/备份标记/日志 PII/数仓派生表——漏一处即数据泄漏事故。
3. 冻结是挽回窗口非惩罚；备份保留与删除权冲突用「恢复过滤器」两全；PURGED 不可逆。

## 复盘追问
1. 冻结租户 90 天后没续费，自动转 DELETING 前要不要再通知？（提示：要——DELETING 是不可逆前奏（7 天冷静期+彻底删除），90 天到期通知+14 天宽限再转——自动化流程里每一步不可逆动作前都要最后通知）
2. 注销后用户要求「提供我全部数据的副本」（GDPR 数据可携权），但数据已删怎么办？（提示：可携权行使在注销申请时（删除前导出全量数据给用户）——流程设计要前置「删除前导出」步骤，删完再要就是「无法满足的合规请求」，处置记录说明即可）
