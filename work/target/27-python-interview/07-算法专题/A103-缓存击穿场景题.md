### A103 · 缓存击穿场景题

> 难度:★★★ | 标签:缓存, singleflight, 场景题

**问**（笔试·场景题）：热点商品详情缓存失效瞬间，10 万 QPS 同时打穿到 MySQL，DB 瞬间雪崩。现场实现「单飞（singleflight）+ 逻辑过期」双方案，说明各自解决什么、什么场景用哪个，以及两个方案为什么不冲突。

**答**：先分清两个问题：**击穿**=单个热 key 失效瞬间并发回源；**雪崩**=大量 key 同时失效。① singleflight 解决击穿：同进程内对同一 key 的并发回源合并成一次——第一个调用者真回源，其余等待并共享结果（`concurrent.futures.Future` 或 asyncio `Event`）；跨实例再配 Redis `SET NX` 分布式互斥，只放一个实例回源，其余短重试读缓存。② 逻辑过期解决雪崩根因：缓存**永不设物理 TTL**，值里带 `expire_at`；读到「已逻辑过期」时**先返回旧值**（不阻塞），再由拿到互斥锁的那一个请求异步刷新——用户永远不回源等 DB。两者互补：singleflight 管「失效后的回源并发」，逻辑过期把「回源」从同步路径上摘掉。

```python
import asyncio, json, time

class SingleFlightCache:
    def __init__(self):
        self._inflight: dict[str, asyncio.Future] = {}

    async def get(self, key: str, loader, ttl: float):
        if fut := self._inflight.get(key):
            return await fut                      # 同 key 并发：搭车，不回源
        fut = asyncio.get_running_loop().create_future()
        self._inflight[key] = fut
        try:
            value = await loader()                # 只有第一个调用者真正回源
            fut.set_result(value)
            return value
        except BaseException as e:
            fut.set_exception(e)                  # 失败也要广播给等待者
            raise
        finally:
            self._inflight.pop(key, None)

class LogicalTTLCache:
    """物理永不过期；expire_at 只是数据里的一个字段。"""
    def __init__(self):
        self.store: dict[str, tuple[dict, float]] = {}   # key -> (value, expire_at)
        self.flight = SingleFlightCache()

    async def get(self, key: str, loader, ttl: float):
        ent = self.store.get(key)
        if ent is None:
            v = await self.flight.get(f"cold:{key}", loader, ttl)   # 冷启动才真回源
            self.store[key] = (v, time.monotonic() + ttl)
            return v
        value, exp = ent
        if time.monotonic() <= exp:
            return value                          # 未过期：直接返回
        # 已逻辑过期：先返回旧值（不阻塞用户），异步刷新
        if f"refresh:{key}" not in self.flight._inflight:
            async def refresh():
                v = await loader()
                self.store[key] = (v, time.monotonic() + ttl)
            asyncio.create_task(self.flight.get(f"refresh:{key}", refresh, ttl))
        return value

if __name__ == "__main__":
    calls = {"n": 0}
    async def loader():
        calls["n"] += 1
        await asyncio.sleep(0.05)                 # 模拟 DB 查询
        return {"price": 999}

    async def main():
        c = LogicalTTLCache()
        rs = await asyncio.gather(*[c.get("sku:1", loader, 1.0) for _ in range(500)])
        assert all(r == {"price": 999} for r in rs)
        assert calls["n"] == 1, calls            # 500 并发只回源 1 次
        print("回源次数:", calls["n"])
    asyncio.run(main())
```

**追问**：1) 逻辑过期的代价是什么？——**数据永远不是最新的**（读到过期值直到刷新完成），强一致业务不能用；且首次冷启动仍会回源，冷 key 预热要单独做。2) singleflight 等待者超时怎么处理？——`asyncio.wait_for(fut, timeout)` 超时后要么降级读旧值/默认值，要么自己回源（配分布式锁防跨实例放大）；失败广播很重要，否则等待者永远挂起。3) 雪崩还可以怎么防？——TTL 加随机抖动（±10%）、多级缓存（本地 LRU 挡第一波）、DB 侧限流兜底。

## 背诵要点
1. singleflight 管「回源并发合并」（失效后），逻辑过期管「同步路径摘除回源」（永不物理过期）——互补不冲突。
2. 逻辑过期 = 返回旧值 + 异步刷新，代价是读到旧数据；强一致场景禁用。
3. singleflight 失败也要广播异常给等待者，否则挂起；跨实例用 Redis SET NX 只放一个回源。

## 复盘追问
1. 热点 key 是「某主播直播间商品」，刷新周期本来就该秒级，怎么改？（提示：预计算 + 推送失效，而不是被动过期）
2. 缓存服务整体宕机，singleflight 还有效吗？（提示：进程内有效，但要配本地 LRU + DB 限流兜底）
