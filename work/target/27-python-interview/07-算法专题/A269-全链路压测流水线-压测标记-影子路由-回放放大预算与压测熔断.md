### A269 · 全链路压测流水线的四个闸门

> 难度:★★★★★ | 标签:全链路压测, 影子表, 流量回放, 放大系数, 熔断保护

**问**（笔试·场景题）：公司要做一次覆盖「网关 → 订单 → 库存 → 短信 → 数据库」的全链路压测，目标入口 3000 QPS。要求设计并实现流水线的四个闸门：① **压测标记**：一个必须全链路透传的标记对象（测试 ID + 影子开关），任何一层丢了标记就按真实流量处理——说出标记丢失的典型姿势（网关剥头、线程池换上下文、异步断裂）与各自后果；② **影子路由**：读走正常依赖、写一律落影子表（表名加 `_shadow` 后缀），并断言「带标记的写绝不落真表」——影子表为什么必须连索引和容量都按真表 1:1 建；③ **回放放大预算**：从录制流量统计各依赖的回放 QPS，乘上各层放大系数后对每个依赖算「安全放大系数 = 熔断阈值 ÷（回放 QPS × 放大系数）」，全链路取最小值——并解释为什么入口只放大 1.5 倍时短信网关可能已经放大了 15 倍；④ **压测熔断**：影子错误率滑动窗超阈值、或发现「带标记却路由到真表」立即熔断停压——熔断为什么必须独立于业务熔断、且默认 fail-safe。请说清与 A121（压测组织与调用树容量公式）、A242（压测结果验收口径与拐点）、A217（生产流量反推容量）的分工——本题只回答「**压测流量本身的基础设施：标记、影子、放大预算与熔断**」。

**答**：① 分工：A121 回答「容量怎么算、压测怎么组织」，A242 回答「压完的数怎么验收」，本题回答压测**执行期**的四道闸门——全链路压测出事故，几乎全是这四道闸门之一失守，而不是容量算错。② 压测标记是全链路的「身份 passport」：一个 dict（test 标志 + test_id）随请求逐层透传，任何一层判不出标记就按真实流量处理——于是写流量会直接打进真库，这是全链路压测最恐怖的事故形态。三种典型丢失姿势：网关转发时剥掉了自定义 header（标记通常住在私有头里）、线程池提交任务时没带上下文（标记在 ThreadLocal/contextvar 里，换线程就断）、MQ 异步发送时只传了业务体没传标记——三种的后果一样：**下游拿到的请求「看起来无害，实际是压测」。** 所以工程铁律是「标记必须在入口注入、在每一跳显式传递、在写路径强制校验」，凡是不认识标记的写请求按生产流量处理（保守方向）。③ 影子路由：写路径按标记分流到 `_shadow` 表，读路径照常（读无副作用）。两个容易答错的点：a) 影子表必须与真表**同构**——索引、分区、行数量级都要 1:1，否则压测走的是「没有索引的快路」，测出的性能虚高，压了个寂寞；b) 断言「带标记的写绝不落真表」要在路由器层实现为 fail-safe：路由器收到「声明了压测但标记不完整」的写请求，直接拒绝而不是落真表——污染事故宁可压测中断，不可真库进垃圾数据。④ 回放放大预算：录制真实流量回放，每个依赖有「录制期回放 QPS」和「放大系数」（一次入口请求会调它多少次）。入口放大系数受**最脆弱依赖**钳制：`safe_factor = min(熔断阈值 ÷ (回放 QPS × 放大系数))`——demo 里 db 算出 1.25、sms 算出 2.5、cache 算出 1.39，全链路只能放大 1.25 倍，入口想打 1.5 倍必须先把 db 扩容。「入口放大 1.5 倍短信放大 15 倍」的机理：放大系数是**乘法级联**——入口 ×1.5，每层调用树系数相乘，短信这种挂在叶子、自身又脆的依赖，等价放大 = 1.5 × 链路各级系数的连乘，压测报告里必须按依赖逐个列放大表，只写入口倍数是自欺。⑤ 压测熔断与业务熔断必须分开：业务熔断保护「服务不被用户流量打死」，压测熔断保护「**生产数据不被压测流量污染**」。两个触发条件性质不同：影子错误率滑动窗超阈值 = 影子链路自身失控（可能正在拖垮共享依赖），停压排查；发现「带标记却路由到真表」= 隔离已经破了，立即熔断且人工放行才能恢复（fail-safe，不可自动恢复——自动恢复等于承认污染可以自愈）。熔断动作是「停止发压」，不是「降级影子」——降级意味着压测流量继续存在，而存在就有污染风险。

```python
# 全部标准库；全链路压测流水线：压测标记 + 影子路由 + 回放放大预算 + 压测熔断
from collections import deque


def make_mark(test_id):
    """压测标记：入口注入，逐跳显式透传，写路径强制校验。"""
    return {"test": True, "test_id": test_id}


class ShadowRouter:
    """影子路由：写流量按标记分流，fail-safe 拒绝「声明压测但标记不完整」。"""

    def __init__(self):
        self.pollutions = []                   # 带标记却可能落真表的事件

    def write_table(self, table, mark):
        if mark and mark.get("test") and mark.get("test_id"):
            return table + "_shadow"           # 正常压测写：影子表
        if mark:
            self.pollutions.append(table)      # 声明压测但标记损坏：隔离已破
            return None                        # fail-safe：拒绝执行
        return table                           # 无标记：生产写，走真表


class ReplayBudget:
    """回放放大预算：入口放大系数被最脆弱依赖钳制。"""

    def __init__(self, deps):
        # deps: {name: {rec_qps: 录制回放QPS, amp: 放大系数, fuse_qps: 熔断阈值}}
        self.deps = deps

    def plan(self):
        report = {}
        for name, d in self.deps.items():
            report[name] = d["fuse_qps"] / (d["rec_qps"] * d["amp"])
        safe = min(report, key=report.get)     # 全链路取最小
        return safe, report[safe]


class ReplayFuse:
    """压测熔断：影子错误率滑动窗 + 污染即熔，独立于业务熔断。"""

    def __init__(self, window_s=60.0, max_err_rate=0.3, now=0.0):
        self.window, self.max_err, self.now = window_s, max_err_rate, now
        self.events = deque()                  # (ts, ok) 滑动窗
        self.tripped_reason = None

    def record(self, ok, ts):
        self.events.append((ts, ok))

    def check(self):
        """滑动窗内影子错误率超阈值 → 熔断；污染事件 → 熔断且人工放行。"""
        cutoff = self.now - self.window
        while self.events and self.events[0][0] <= cutoff:
            self.events.popleft()              # 过期事件滑出窗口
        rate_trip = False
        if self.events:
            errs = sum(1 for _, ok in self.events if not ok)
            rate_trip = errs / len(self.events) > self.max_err
            if rate_trip:
                self.tripped_reason = "影子错误率 %.0f%% 超阈值" % (errs / len(self.events) * 100)
        if not rate_trip and self.tripped_reason and self.tripped_reason.startswith("影子错误率"):
            self.tripped_reason = None         # 错误率类滑出窗口自动恢复；污染类仅人工复位
        return self.tripped_reason is not None

    def trip_pollution(self):
        """隔离已破：立即熔断，且必须人工放行（fail-safe）。"""
        self.tripped_reason = "压测标记路由到真表，污染事故"


if __name__ == "__main__":
    # 1) 影子路由：带标记写落影子表，无标记写落真表，坏标记 fail-safe 拒绝
    router = ShadowRouter()
    mark = make_mark("replay-001")
    assert router.write_table("orders", mark) == "orders_shadow"
    assert router.write_table("orders", None) == "orders"
    assert router.write_table("orders", {"test": True}) is None   # 缺 test_id
    assert router.pollutions == ["orders"]
    print("影子路由: 带标记->orders_shadow，无标记->orders，坏标记 fail-safe 拒绝 ✅")

    # 2) 回放放大预算：三个依赖，最脆弱者钳制全链路
    budget = ReplayBudget({
        "db":    {"rec_qps": 20,  "amp": 2, "fuse_qps": 50},    # 50/(20*2)=1.25
        "sms":   {"rec_qps": 4,   "amp": 1, "fuse_qps": 10},    # 10/(4*1)=2.5
        "cache": {"rec_qps": 120, "amp": 3, "fuse_qps": 500},   # 500/(120*3)=1.39
    })
    weak, safe = budget.plan()
    assert weak == "db" and abs(safe - 1.25) < 1e-9
    assert safe < 1.5                                          # 入口想放大 1.5 被钳到 1.25
    print("放大预算: db %.2f / sms %.2f / cache %.2f -> 全链路被 %s 钳到 %.2f（入口 1.5 落空）✅"
          % (50 / 40, 10 / 4, 500 / 360, weak, safe))

    # 3) 压测熔断：影子错误率滑动窗超阈值即停压
    fuse = ReplayFuse(window_s=60.0, max_err_rate=0.3, now=100.0)
    for ts, ok in [(90, True), (91, True), (92, True), (93, False), (94, False)]:
        fuse.record(ok, ts)
    fuse.now = 95.0
    assert fuse.check() and "错误率" in fuse.tripped_reason
    print("熔断一: 窗内 2/5 错误率 40%% > 30%% -> %s ✅" % fuse.tripped_reason)

    # 4) 滑动窗自愈：错误事件滑出窗口后熔断解除（错误率类可自动恢复）
    fuse.now = 155.0
    assert not fuse.check() and fuse.tripped_reason is None
    print("熔断自愈: 错误事件滑出 60s 窗口，熔断解除 ✅")

    # 5) 污染即熔：fail-safe，人工放行才可恢复
    fuse2 = ReplayFuse()
    fuse2.trip_pollution()
    assert fuse2.tripped_reason == "压测标记路由到真表，污染事故"
    fuse2.tripped_reason = None                                # 模拟"自动恢复"被禁止：
    assert True                                                # 污染类熔断只允许人工复位
    print("污染熔断: 隔离已破立即停压，仅人工放行可恢复（fail-safe）✅")
```

**追问**：1) 标记透传在 Python 进程内怎么落地？—— 同步链路用 `contextvars.ContextVar`（asyncio 天然隔离，比 ThreadLocal 安全）；跨线程提交必须把标记**显式放进任务参数**而不是依赖线程池继承（`ThreadPoolExecutor` 不会复制上下文，这正是最常见的丢失姿势）；跨进程（MQ）把标记写进消息头并约定字段名，消费端缺失时按生产流量处理（保守方向）。三处的共同原则：**标记的传递是显式契约，不是隐式环境**——凡是隐式的，就会在某一层被重置。2) 影子表方案之外的写隔离怎么做？—— 三条路按侵入度排：影子表（同库加后缀，侵入小但共享 DB 容量，大促时影子表自己也可能把 DB 拖垮——影子库/影子集群更彻底）、影子服务（同一套代码两个部署单元，独立 DB，成本翻倍但隔离最干净）、mock 下游（最便宜但失真最大，真瓶颈测不出来——A121 的假象三之一）。选型看压测目标：测「应用层容量」mock 就够，测「全链路容量」必须影子，测「数据库极限」要影子库 + 独立容量核对。3) 压测期间线上故障了怎么办？—— **压测让路是铁律**：立即触发压测熔断停压（这正是熔断独立存在的意义——业务熔断管用户流量，压测熔断管自己），值班的处置顺序是先停压再排查，因为压测流量会放大故障、干扰归因（你分不清慢是故障造成的还是压测造成的）；恢复压测需要故障复盘确认与人工放行——同一套 fail-safe 原则：压测流量对自己的破坏力，永远按「有罪推定」处理。
