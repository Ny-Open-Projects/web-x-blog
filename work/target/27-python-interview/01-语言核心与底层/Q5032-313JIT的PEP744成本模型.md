### Q5032 · 3.13 实验性 JIT（PEP 744）：成本模型与使用边界

> 难度:★★★★ | 标签:JIT, PEP 744, 版本演进

**问**：3.13 引入的实验性 JIT（PEP 744）是什么原理？"copy-and-patch"和传统 JIT 有什么区别？现在能上生产吗？开了 JIT 就一定快吗？

**答**：PEP 744 给 CPython 加了实验性 JIT：先跑 3.13 的 Tier-1 特化解释器（PEP 659 自适应特化，Q1259），再把"热"的字节码指令翻译成一条条预先编译好的机器码模板（stencils），运行时把特化后的常量"拷贝进模板缝里"（copy-and-patch）拼接成 basicblock 的机器码，跳过解释器循环的 dispatch 开销。它与 PyPy 式 JIT 的关键差异：**不做类型推测、不做跨块的优化（无内联/无逃逸分析）**，只做"特化解释器的机器码化"，所以峰值提升温和（基准 5-15%），内存开销换 JIT 模板（构建产物变大，运行时占比很小）。取舍边界：1) 3.13/3.14 需构建期 `--enable-experimental-jit`，运行期 `PYTHON_JIT=1`，官方明确**未承诺生产支持**，3.14 开始默认关闭但可开；2) 收益集中在纯 Python 热循环（数值/解析/模拟），IO 密集服务几乎无感；3) 与 C 扩展共存没问题（JIT 不介入 C 调用），但与 gdb/perf 的符号对应变复杂，事故排查工具链要先跟上。结论：**观察、基准、别急着上**——这是版本演进题，考的是"知道边界"而不是"背参数"。

```python
# file: code/01_语言核心与底层/q5032_jit_pep744.py
import os
import sys
import time

# 1) 当前解释器是否带 JIT 构建与开关
jit_env = os.environ.get("PYTHON_JIT", "(未设)")
has_jit = getattr(sys.flags, "jit_enabled", None)
print("PYTHON_JIT env:", jit_env, "| sys.flags.jit_enabled:", has_jit)

# 2) 无论 JIT 与否, 纯 Python 热循环是 JIT 的目标负载; 先做一个可复跑基准
def hot_loop(n: int) -> int:
    acc = 0
    for i in range(n):
        acc += i * i % 997
    return acc

def bench(fn, *args, reps: int = 3) -> float:
    best = float("inf")
    for _ in range(reps):
        t0 = time.perf_counter()
        fn(*args)
        best = min(best, time.perf_counter() - t0)
    return best

n = 2_000_000
hot_loop(1000)  # 预热(触发 3.11+ 自适应特化)
t = bench(hot_loop, n)
print(f"纯 Python 热循环 {n} 次: {t*1000:.1f} ms  <- JIT 潜在受益负载")

# 3) 对照组: IO/C 调用为主的负载, JIT 无收益
t_c = bench(lambda: sum(len(bytes(10_000)) for _ in range(200)))
print(f"C 密集(bytes 分配): {t_c*1000:.1f} ms  <- JIT 边际收益趋零")

# 4) 复现实验的方法论: 同机同负载, PYTHON_JIT=0/1 各跑一轮取比值
print("评估姿势: PYTHON_JIT=0 vs =1 各跑同一基准, 关注 p99 与 RSS 变化而非均值")
```

**追问**：1) copy-and-patch 为什么比"解释执行特化指令"更快？——把 3.11+ 已经特化好的指令序列直接变成机器码，省掉每条指令的取指/dispatch/栈管理，模板本身由 clang -O2 生成，缝里只填立即数与跳转偏移。2) 为什么 JIT 不做内联等重量级优化？——CPython 语义太动态（属性、全局随时可变），重量级优化需要假设与守卫（deopt 机制），工程量与正确性风险都大；PEP 744 选择最小可用集合换取可维护性。3) JIT 与 free-threading（3.13 另一实验特性）能同时开吗？——早期构建互斥，3.14+ 路线图上逐步解耦；面试答"当前默认构建二者不可兼得，需关注版本说明"即可。

## 背诵要点
- PEP 744 = Tier-2 JIT，copy-and-patch：模板机器码 + 运行时填常量，无类型推测无跨块优化。
- 构建 `--enable-experimental-jit`，运行 `PYTHON_JIT=1`；3.13/3.14 实验性质，不建议生产。
- 收益集中在纯 Python 热循环（个位数到 15%），IO/C 密集负载基本无感。
