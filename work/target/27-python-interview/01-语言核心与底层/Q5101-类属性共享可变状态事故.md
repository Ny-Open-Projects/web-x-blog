### Q5101 · 类属性共享可变状态事故复盘

> 难度:★★★☆☆ | 标签:类属性, 可变对象, 事故复盘

**问**:多个实例的计数器/列表"串台"了，改一个全变。定位思路与根因是什么？

**答**:结论：根因几乎总是把可变对象放在类属性上。属性查找规则是"实例 dict 没有 → 沿 MRO 找类属性"，读操作拿到的是同一个共享对象；对它做 `append`/`+=`(就地) 这类原地修改不会写回实例 dict，于是所有实例都指向同一份状态。这与可变默认参数（Q004）同源：共享点从"函数定义期"换成了"类定义期"。取舍上，不可变类属性（常量、配置）是合理用法，可变类属性默认就是 bug。实战修复：在 `__init__` 里做实例级初始化；若确需共享计数，用类属性 + 显式 `Counter` 并承认共享语义，或改 `MyClass.count += 1`（会写回类属性并覆盖）。复盘时用 `id(obj.attr)` 对比两个实例即可 30 秒定位。

```python
class Report:
    rows = []          # 事故源：类属性上的可变对象

    def add(self, x):
        self.rows.append(x)      # 读到类属性 list，原地改，全员共享

class ReportFixed:
    def __init__(self):
        self.rows = []           # 实例级初始化，切断共享

a, b = Report(), Report()
a.add("x")
print(b.rows)                    # ['x']  —— b 也"收到"了
print(Report.rows is a.rows)     # True   —— 同一对象

fa, fb = ReportFixed(), ReportFixed()
fa.rows.append("x")
print(fb.rows)                   # []     —— 隔离

# 正确的共享计数写法：改在类上，且接受全局语义
class Bucket:
    total = 0
    @classmethod
    def hit(cls):
        cls.total += 1
```

**追问一层**:`self.rows.append(x)` 为什么不会像 `self.x = 1` 那样写回实例？
**追二层**:如果写 `self.rows = self.rows + [x]` 会发生什么？后续实例各自 append 会一致吗？

**背诵要点**
- 类属性查找先实例后 MRO，读共享、原地改不写回。
- 可变类属性=隐式全局单例；常量/配置放类属性才安全。
- `id(a.attr) == id(b.attr)` 是最快定位手段。

**复盘追问**
- 如果类属性被 `@property` 或 `__getattr__` 包了一层，共享问题会不会被掩盖？提示：考虑描述符劫持读路径。
- 多进程 fork 后这份类属性状态如何演化？提示：结合 COW 与写时分裂。
