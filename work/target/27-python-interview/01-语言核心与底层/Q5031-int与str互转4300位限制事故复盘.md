### Q5031 · int↔str 互转 4300 位限制：一次 CVE 事故复盘

> 难度:★★★★ | 标签:int-str 转换, CVE-2020-10735, 事故复盘, 安全

**问**：Python 3.11 起默认把 int 与 str 之间的转换限制在 4300 位以内，这是为什么？升级后线上"号码转字符串报 ValueError"该怎么处置？这个限制救的是哪类攻击？

**答**：这是 CVE-2020-10735 的修复。`int↔str` 在十进制下是 O(n²) 的经典乘除算法——4300 位的整数转字符串在普通机器上就要秒级 CPU，攻击者用一个巨型整数字面量（JSON/YAML/表单均可注入）就能把单个请求变成几十秒的 CPU 占用，几条请求即可打满 worker。3.11 起 `sys.get_int_max_str_digits()` 默认 4300（可上调但下限 640），超限抛 `ValueError: Exceeds the limit (4300 digits)`。取舍：**这不是精度问题而是 DoS 防线**——hashlib/十六进制、二进制转换不受限（它们是线性时间）。实战处置分三层：1) 确实要处理超大整数（如密码学库、科学计算）→ 对该路径显式 `sys.set_int_max_str_digits(0)` 关闭或调大，绝不能全局无脑关闭；2) 入口校验——JSON 反序列化前限制数字字段长度，比事后异常便宜；3) 监控 ValueError 里的 "Exceeds the limit"，它往往就是有人在探测。3.12+ 该限制已回移到受支持的旧版本（3.7.14+ 等），所以"升上去才有"是误解，安全补丁先于新版本到达。

```python
# file: code/01_语言核心与底层/q5031_int_str_limit.py
import sys

print("当前上限:", sys.get_int_max_str_digits(), "位")

# 1) 4300 位以内正常转换
ok = int("9" * 4000)
print("4000 位转换 OK, 位数:", len(str(ok)))

# 2) 超限触发 ValueError
try:
    int("9" * 5000)
except ValueError as e:
    print("超限:", str(e)[:60], "...")

# 3) 事故处置: 仅对可信路径临时提高(最小权限,不要全局放开)
old = sys.get_int_max_str_digits()
sys.set_int_max_str_digits(20000)
big = int("9" * 5000)
print("调高后 5000 位转换 OK, 位数:", len(str(big)))
sys.set_int_max_str_digits(old)  # 复原

# 4) 十六进制不受限(线性时间), 大整数的合规出口
big_hex = "9" * 5000
h = hex(int.from_bytes(bytes(2500), "big") + int(big_hex, 16))
print("hex 路径 OK, hex 长度:", len(h))

# 5) 二次幂进制(2/4/8/16/32)不受限, 10 进制受限——本质是算法复杂度差异
print("linear-time bases bypass limit; decimal is quadratic -> guarded")
```

**追问**：1) 为什么下限是 640 而不能设 0 关闭全部保护？——640 位约是 int64 的十倍量级，业务几乎用不到更长的十进制串；0 是彻底关闭，只允许在"输入来源完全可信"的独立进程里用。2) 为什么十进制是 O(n²) 而十六进制是线性的？——十进制每步要除以 10^9 这类大基数做经典长除法，n 位要 n 次 O(n) 操作；十六进制每 4 位对应 1 个 nibble，是位操作。3.12 引入了 `_pylong.py` 的 asymptotically faster 算法缓解但仍保留限制。3) JSON 库层面怎么办？——`json.loads` 解析大整数字面量同样触发该限制，网关/入口层先做字段长度校验才是治本。

## 背诵要点
- CVE-2020-10735：十进制 int↔str 是 O(n²)，4300 位即秒级 CPU，默认上限防 DoS。
- `sys.get_int_max_str_digits()/set_int_max_str_digits()`，下限 640、0 为关闭，只对可信路径放开。
- 2/4/8/16/32 进制转换线性时间不受限，是处理超大整数的合规出口。
