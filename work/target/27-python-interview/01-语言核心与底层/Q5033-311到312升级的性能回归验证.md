### Q5033 · 3.11→3.12 升级的性能回归验证方法

> 难度:★★★★ | 标签:版本演进, 性能回归, 升级工程

**问**：解释器小版本升级（3.11→3.12）怎么验证"没有性能回归"？为什么不能只跑一次 benchmark？哪些负载在 3.12 上反而变慢，怎么定位？

**答**：方法论三支柱：**固定变量、多轮采样、分位数对比**。1) 固定变量：同一台机器/容器、关闭 turbo 抖动或至少同步频次、同一依赖版本（wheel 走 cp311/cp312 各自 ABI）、同一数据集；2) 多轮采样：单次测量噪声可达 ±10%，用 timeit 的 repeat 取 min（timeit Q430 的原则），宏观基准取 p50/p99 而不是均值；3) 分层对比：微基准（timeit）→ 组件基准（接口冒烟）→ 生产影子流量。3.12 已知的行为差异要单独验证：PEP 701 f-string 重写让极复杂 f-string 的编译路径变化（运行时影响很小）；`int↔str` 限制改变大整数转换路径（Q5031）；`typing.get_type_hints`/dataclass 重写；以及 immortal objects 让部分引用计数分支消失（多数是正收益）。定位变慢点：先 py-spy/sperf 采样对比热点是否漂移，再看是否踩到新限制/新检查（如更严格的 GC 行为）。取舍：升级收益（3.12 平均 5% 内增、内存治理、新特性）通常大于个别负载回退，但**必须量化而不是相信 changelog**。

```python
# file: code/01_语言核心与底层/q5033_upgrade_regression.py
"""升级回归验证的最小框架: 多轮采样 + 分位数对比 + 热点快照."""
import statistics
import timeit

import timeit

def timeit_repeat(stmt: str, setup: str, number: int = 100_000, repeat: int = 7) -> list[float]:
    """标准库 timeit.repeat: 多轮独立计时, 返回每轮总耗时."""
    return timeit.repeat(stmt, setup=setup, number=number, repeat=repeat)

def quantile(xs: list[float], q: float) -> float:
    xs = sorted(xs)
    return xs[min(len(xs) - 1, int(q * len(xs)))]

CASES = {
    "f-string 简单插值": ("f'{x}'", "x = 42"),
    "dataclass 构造": ("C(i)", "from dataclasses import dataclass\n"
                               "@dataclass\nclass C:\n    v: int\ni = 3"),
}

def run_suite() -> dict[str, list[float]]:
    results = {}
    for name, (stmt, setup) in CASES.items():
        samples = [min(timeit_repeat(stmt, setup, number=100_000, repeat=3))
                   for _ in range(5)]
        results[name] = samples
        print(f"{name}: p50={quantile(samples, .5)*1e6:.2f}us "
              f"p90={quantile(samples, .9)*1e6:.2f}us min={min(samples)*1e6:.2f}us")
    return results

def compare(old: list[float], new: list[float]) -> str:
    """每轮独立采样后按轮配对比较, 输出回归/改善幅度."""
    ratio = quantile(new, .5) / quantile(old, .5)
    if ratio > 1.10:
        return f"回归 {ratio:.2f}x, 先查热点漂移(py-spy)与新限制"
    if ratio < 0.90:
        return f"改善 {1/ratio:.2f}x"
    return f"噪声区间内 ({ratio:.3f}x), 记录基线即可"

if __name__ == "__main__":
    base = run_suite()
    print("生产用法: cp311 跑一份存 JSON, cp312 跑一份, 逐项 compare();")
    print("单次测量不做结论 —— 这里的每项都采了 5 轮取分位。")
```

**追问**：1) 为什么取 min 而不是均值？——微基准的噪声是单向的（系统干扰只会变慢），min 最接近"无干扰真实成本"；但 p99 仍要记录，因为服务关心的是尾部。2) 升级后某接口 p99 变差但 p50 不变，怎么查？——尾部通常来自 GC 时机/内存行为变化或缓存扰动，用 gc.set_debug/tracemalloc 快照对比 + 影子流量复现，而不是重跑压测平均。3) 依赖没有 cp312 wheel 怎么办？——源码编译的扩展可能有 C API 行为差异，先跑该依赖自带基准与冒烟测试，纳入回归门禁；这也是升级清单里"依赖矩阵先行"的原因。

## 背诵要点
- 升级验证 = 固定变量 + 多轮采样 + 分位数（p50/p99），不信单次 benchmark。
- 3.12 关注点：PEP 701 f-string、int↔str 限制（Q5031）、get_type_hints/dataclass 重写、immortal objects。
- 回归定位顺序：热点采样对比 → 新限制/新检查 → GC 与内存行为快照。
