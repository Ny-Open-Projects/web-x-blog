### Q5110 · 特殊方法的类型级查找原理

> 难度:★★★★☆ | 标签:原理深挖, 魔法方法, slot

**问**:为什么 `obj.__len__ = lambda: 0` 之后 `len(obj)` 仍然报错？隐式调用到底绕过了什么？

**答**:结论：隐式调用的特殊方法（`len`/`iter`/`+`/`==`/`with` 等）走的是**类型对象上的 slot**（`tp_len` 等 C 槽），CPython 在类型创建时把 `__len__` 之类从类体拷贝填充进槽，之后 `len(obj)` 直接查槽，不经过实例与常规属性查找（甚至绕过 `__getattribute__`）。所以运行时往实例 dict 塞 `__len__` 无效；往**类**上赋值可以生效，但那是修改类（且对不可变内置类型如 `int` 直接禁止）。原理上这是性能与安全双保险：每对象调用省掉 dict 查找，类型不可变保证 slot 语义稳定。与显式调用 `obj.__len__()` 的区别：显式调用走普通属性协议，会命中实例属性。这就是"魔法方法必须定义在类上"的底层原因。

```python
class Box:
    def __len__(self):
        return 3

b = Box()
print(len(b))                        # 3，经类型槽 tp_len

b.__len__ = lambda: 99               # 塞进实例 dict
print(len(b))                        # 仍是 3！隐式调用不看实例
print(b.__len__())                   # 99 —— 显式调用走普通属性协议

# 类级修改生效（新类型），因为槽在类型创建时可被定制
class Box2(Box):
    __len__ = lambda self: 99
print(len(Box2()))                   # 99

# 内置不可变类型的槽被冻结，运行时改类直接拒绝
try:
    int.__len__ = None
except TypeError as e:
    print("内置类型禁改:", e)

# 特殊方法缺失时槽为空 → TypeError 而不是 AttributeError
class Empty: pass
try:
    len(Empty())
except TypeError as e:
    print("len(Empty):", e)
```

**追问一层**:`obj.__len__()` 显式调用能命中实例属性，那 `iter(obj)` 与 `obj.__iter__()` 在"实例定义了 `__iter__`"时行为一致吗？
**追二层**:CPython 的 slot 机制（`tp_slots` 表）与 3.12 的 `__firstlineno__`/类型定制还有什么关联？为什么 `copy.replace` 也要走协议而不是属性（引 Q5108）？

**背诵要点**
- 隐式特殊方法查类型槽，不查实例 dict、不过 getattribute。
- 实例上赋值魔法方法无效；类级赋值有效；内置类型禁改。
- 显式 `obj.__len__()` 走普通协议，与隐式语义不同。
