### Q5134 · PEP 570 位置参数语法的演进与 API 设计

难度：P6 | 标签：PEP 570、positional-only、API 演进、inspect

**问**：`/` 和 `*` 在函数签名里分别是什么语义？为什么标准库大量函数（如 `len`、`sorted`、`math.pow`）坚持把部分参数声明为仅限位置？这与 Python 3.0 引入的 keyword-only 参数（`*`）如何构成 API 演进的两端？

**答**：

**结论**：`/` 之前的参数只能按位置传递（PEP 570，Python 3.8 正式语法；此前 C 实现函数天生如此），`*` 之后的参数只能按关键字传递（PEP 3102，Python 3.0）。两者把签名切成"位置区 / 可自由区 / 关键字区"三段。仅限位置的价值在于：(1) 参数名成为实现细节，未来重命名不破坏兼容——`len(obj, /)` 所以标准库可以把 `obj` 改名；(2) 避免调用方与实现间无意义的名字耦合；(3) 让 `f(x, /, x)` 同名参数成为可能（如 `pow(base, exp, mod=None, /)` 式链式代理）。仅限关键字的价值相反：把布尔开关参数钉死为关键字，防止 `f(1, True)` 这类不可读调用。

**取舍**：加 `/` 是单向门——已发布的纯位置兼容 API 后续可以收紧成 `/`（不破坏任何人），但反过来从"可关键字"改成"仅位置"是破坏性变更。所以设计原则是：常用且名字可能演进的参数尽早加 `/`；布尔/回调/上下文参数尽早加 `*`。检查工具 `inspect.signature` 与 `typing.ParamSpec` 均可透传这些标记。

**实战**：迁移视角：3.8 之前 C 函数（dict.get、math.sin）就已仅限位置，但纯 Python 代码无法表达，导致"文档里说可以 `dict.get(key=...)` 吗"这类伪问题；PEP 570 让 Python 层与 C 层签名语义对齐，也是 `functools.wraps`/`inspect.Signature` 生态必须处理的新 AST 节点（`posonlyargs`）。

```python
import inspect

def send(payload, /, *, timeout=3.0, retries=2, tag=None):
    """payload 仅限位置：改名不破坏调用方；开关必须写关键字。"""
    return {"payload": payload, "timeout": timeout,
            "retries": retries, "tag": tag}

print(send("hi", timeout=1))          # OK
try:
    send(payload="hi")                # 禁止：payload 在 / 之前
except TypeError as e:
    print("TypeError ->", e)
try:
    send("hi", 1)                     # 禁止：timeout 在 * 之后
except TypeError as e:
    print("TypeError ->", e)

# 签名内省：posonlyargs 是独立的 AST/Signature 段
print(inspect.signature(send))

# 三段式签名：/ 前=位置区，/ 与 * 之间=自由区，* 后=关键字区
def three(a, b, /, c, d, *, e):
    return (a, b, c, d, e)
print(three(1, 2, 3, d=4, e=5))       # c 可位置也可关键字
```

**追问 1**：`def f(x, /, x)`（同名参数跨区）合法吗？
答：合法且有意义——常见于 `f(value, /, **kwargs)` 的代理函数，把位置参数转发为关键字：`def f(obj, /, **kw): return g(obj=obj, **kw)`。编译器只禁止同一区内同名。

**追问 2**：PEP 457 与 PEP 570 的关系？
答：PEP 457 只提出 `*` 的 keyword-only 语法（3.0 落地），PEP 570 补齐对称的 `/` 位置-only 语法（3.8 落地）；更早 PEP 570 前身是讨论多年的"位置参数标记"，C 函数的 `(x, /)` 自 Python 3.x 文档起就用 `/` 表示。

**追问 3**：lambda 和异步函数支持 `/` 吗？
答：支持，语法对所有 def 形态统一（lambda、async def、方法），`Signature` 里以 `POSITIONAL_ONLY` kind 表达；`str.join(self, iterable, /)` 就是方法上的典型应用。

## 背诵要点

- `/` 前仅位置（PEP 570/3.8），`*` 后仅关键字（PEP 3102/3.0），共同构成三段式签名。
- 仅位置参数名是实现细节，可安全重命名；布尔开关钉成关键字防止 `f(1, True)`。
- 收紧（可关键字→仅位置）是破坏性变更，加 `/` 要在首版就定；inspect 用 POSITIONAL_ONLY 内省。
