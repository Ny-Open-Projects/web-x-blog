### Q5197 · 正则 $ 放过末尾换行：白名单校验被换行绕过

难度：P6 ｜ 标签：re、锚点、fullmatch、CRLF 注入、输入校验

**问**：`re.match(r"^[a-z]+$", name)` 校验用户名，`"alice\n"` 却通过了，然后把 `name` 拼进 HTTP 头就变成了响应头注入。`$` 不是"字符串结尾"吗？为什么 `\n` 能被放过？`re.fullmatch` 能不能救？`re.MULTILINE` 下 `^`/`$` 又变成什么语义？

**答**：
结论：在 Python 的 `re` 里，`$` 匹配"字符串结尾**或**结尾换行符之前的位置"（等价于 `(?=\n?\Z)` 的直觉），所以 `"alice\n"` 里 `$` 在 `\n` 之前命中，`re.match` 只要求从开头匹配，剩下的 `\n` 不会被检查。`re.fullmatch` 要求**整个字符串**被模式消费完，因此 `fullmatch(r"[a-z]+$", "alice\n")` 会失败——但它失败是因为多出的 `\n` 没被消费，不是因为 `$` 变严格了。`re.MULTILINE` 下 `^`/`$` 变成"每行开头/结尾"，`\n` 直接成为行分隔符，校验会被切碎成多行分别匹配，风险更大。真正表示"绝对结尾"的是 `\Z`。

取舍：a) 校验整串一律用 `fullmatch`，且模式里不要带 `^`/`$`（带了只会让人误解语义）；b) 需要明确"绝不接受尾随换行"时用 `\Z`，或者先做 `strip` 再校验并断言长度未变；c) 输出到协议头/日志前做字符白名单（拒绝 `\r`、`\n`、`\0`），不要只依赖正则。只做输入正则、不做输出编码，是头部注入的经典组合。

实战：事故形态是"用户昵称允许 `\n`，写进 `X-User` 响应头时把后续头覆盖掉，攻击者构造 `alice\nSet-Cookie: ...` 实现会话固定"。下面演示 `$` 的放过、`fullmatch` 的差异、`\Z` 的严格，以及换行被拼进头部的样子。

```python
import re

name = "alice\n"

print("[1] re.match ^[a-z]+$ :", bool(re.match(r"^[a-z]+$", name)))
print("[2] re.fullmatch 带 $ :", bool(re.fullmatch(r"[a-z]+$", name)))
print("[3] re.fullmatch 不带锚点:", bool(re.fullmatch(r"[a-z]+", name)))
print("[4] \\Z 绝对结尾:", bool(re.fullmatch(r"[a-z]+\Z", name)))
print("[5] 先 strip 再比长度:", len(name.strip()) == len(name))

print("[6] MULTILINE 把输入切成多行:", re.findall(r"^[a-z]+$", "alice\nbob\n", re.M))

header = "X-User: " + name + "Role: admin"
print("[7] 拼进头的实际行:")
for line in header.splitlines():
    print("    " + line)

# 正确姿势：整串校验 + 协议字符拒绝
SAFE = re.compile(r"[a-z0-9_]{1,32}\Z")


def valid(v: str) -> bool:
    return bool(SAFE.fullmatch(v)) and not any(c in v for c in "\r\n\0")


print("[8] 严格校验:", valid("alice"), valid("alice\n"))
```

**追问一**：`\Z` 和 `\z` 有什么区别？—— 3.12 只有 `\Z`（绝对结尾）；`\z` 是 3.14 新增的别名，语义与 `\Z` 相同，目的是和 PCRE/Java 的命名对齐。写 3.12 兼容代码用 `\Z`，不要写 `\z`（会报 `bad escape`）。另外 `$` 在 `re.MULTILINE` 外等价于 `(?=\n?\Z)`，这一点在 `re.fullmatch` 里仍然成立，所以"带 `$` 的 fullmatch"很容易让人误判失败原因。

**追问二**：只做 `strip()` 够不够？—— 不够。`strip()` 会顺手删掉首尾空白，把"` alice `" 变成合法值，语义被悄悄放宽；更危险的是它不处理 `\x0b`、`\x0c`、`\u2028` 这类 `splitlines()` 认作换行的字符。正确做法是"先断言长度与字符集，再做规范化"，并在输出侧统一做协议安全编码（头部值拒绝控制字符），两层都做才稳。

## 背诵要点
- `$` 匹配结尾或结尾换行之前；`\Z` 才是绝对结尾；`fullmatch` 要求整串被消费。
- `re.MULTILINE` 让 `^`/`$` 逐行生效，多行输入会被切碎匹配。
- 校验用 `fullmatch` + 明确字符集，输出侧还要拒绝 `\r\n\0`，不能只靠正则。

## 复盘追问

- 为什么"加个 strip 就好了"是错的？（语义放宽 + Unicode 行分隔符 + 输出侧缺失）
