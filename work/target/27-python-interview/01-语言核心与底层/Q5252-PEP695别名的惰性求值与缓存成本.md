### Q5252 · PEP 695 别名的惰性求值与缓存成本：type 语句在运行时到底做了什么

难度：P6 ｜ 标签：PEP 695、type 语句、TypeAliasType、惰性求值、__value__、泛型别名、import 成本

**问**：把老代码的 `IntList = List[int]` 改成 3.12 的 `type IntList = list[int]` 之后，有个模块的启动报错从"import 时立刻 NameError"变成了"跑到第一个请求才 NameError"；另一个服务把别名塞进 `isinstance()` 直接 TypeError。`type` 语句在运行时到底创建了什么？`__value__` 什么时候求值、求几次？为什么别名不能当类型用？

**答**：

- **结论**：`type X = ...` 不创建类，而是创建一个 `typing.TypeAliasType` 实例，带 `__name__`、`__type_params__` 和惰性属性 `__value__`。定义语句本身只记录"怎么算"，**不求值**：右侧表达式里的名字、下标、甚至不存在的名字都不会在 import 期被碰。第一次访问 `X.__value__` 时才执行右侧表达式，并把结果缓存（同一别名对象后续访问返回同一对象）；求值失败（NameError）不会缓存失败结果，下次访问会再试。泛型特化 `X[int]` 得到的是 `types.GenericAlias`（不是 TypeAliasType），`get_origin(X[int])` 指向别名本身、`get_args` 是 `(int,)`；关键陷阱是别名的 `__value__` **保留未替换的类型参数** `T`，替换要靠使用方自己做（typing 内部有 `_eval_type` 机制，但公开 API 不直接提供）。别名不是类：`isinstance(obj, X)` 或 `isinstance(obj, X[int])` 都报 TypeError，因为 `isinstance` 的第二个参数要求 type/tuple/union；要判断就走 `X.__value__` 或 `get_origin/get_args`（裸别名 `X` 的 `get_origin` 是 None）。

- **取舍**：a) 惰性求值的收益是 import 期零成本与循环引用可表达——`type Tree = list[Tree]` 这种自引用别名，旧写法要靠字符串前向引用，新写法天然成立，代价是**错误延迟**：拼错的名字要等第一次 `__value__` 才炸，启动自检如果只 import 不触碰别名就形同虚设；b) 缓存让重复访问便宜，但**特化对象不缓存**：`Payload[int]` 每次都新建 GenericAlias，热路径反复 `Payload[T]` 会产生稳定的小对象分配，应该在模块级预特化一次（`PayloadInt = Payload[int]`）；c) 别名与"展开后的类型"之间隔着一层替换：自研框架只取 `__value__` 会拿到带 `T` 的模板，必须按 `__type_params__`/`__args__` 建立映射再递归替换，否则 Pydantic 会把 `T` 当未知类型；d) 与 `typing.TypeAlias`（3.10 的标注）不同：后者只是给赋值语句打标记，运行时还是普通对象，没有 `__value__` 这层间接。

- **实战**：事故形态是一个插件系统把 `type Handler = Callable[[Event], Awaitable[None]]` 写进注册表，注册时只存别名对象，运行时用 `isinstance(fn, Handler)` 校验签名——第一个插件加载就 TypeError，而且错误点在注册表深处，日志只显示"arg 2 must be a type"。修复：注册表入口统一 `unwrap(alias)`，对 `TypeAliasType` 取 `__value__`，对泛型别名先 `get_origin` 再判断；同时在模块导入后加一条自检 `assert Alias.__value__`，把惰性求值的错误提前到启动阶段。另一个坑是热重载：别名缓存的是**首次求值时的对象**，reload 模块后旧别名对象仍指向旧类，`is` 判断跨版本失效。

```python
# type 语句: 惰性求值、缓存、泛型特化对象与 isinstance 边界
import types
from typing import TypeAliasType, get_origin, get_args

class Probe:
    hits = 0
    def __class_getitem__(cls, item):
        Probe.hits += 1
        return list[item]

type LazyProbe = Probe[int]          # 定义期不碰右侧
print("→ 定义后 Probe.hits =", Probe.hits)
assert Probe.hits == 0               # 惰性: import 期零求值

v1 = LazyProbe.__value__
v2 = LazyProbe.__value__
print("→ 首次取值后 hits =", Probe.hits, "| 两次取值同一对象:", v1 is v2)
assert Probe.hits == 1               # 只求值一次, 结果缓存
assert v1 is v2 and v1 == list[int]

type Later = NotDefinedYet            # 名字不存在也能定义
try:
    Later.__value__
except NameError as e:
    print("→ 惰性把 NameError 推迟到首次访问:", e)

class NotDefinedYet: pass
print("→ 补齐名字后再访问:", Later.__value__)
assert Later.__value__ is NotDefinedYet

type Payload[T] = dict[str, T]
p1, p2 = Payload[int], Payload[int]
print("→ 特化类型:", type(p1).__name__, "| 是否同一对象:", p1 is p2)
print("→ __value__ 保留类型参数:", p1.__value__, "| args:", get_args(p1))
assert p1 is not p2
assert isinstance(p1, types.GenericAlias) and not isinstance(p1, TypeAliasType)
assert get_origin(p1) is Payload and get_args(p1) == (int,)
assert p1.__value__ == dict[str, Payload.__type_params__[0]]   # T 没有被替换
assert p1.__value__ != dict[str, int]                          # 框架必须自己替换

try:
    isinstance(1, p1)
except TypeError as e:
    print("→ 参数化别名不能当 isinstance 的类型:", e)
try:
    isinstance(1, Payload)
except TypeError as e:
    print("→ 裸别名同样不行:", e)
```

**追问一**：为什么 PEP 695 要把别名做成惰性的？这和 PEP 563/649 的"延迟注解"是同一件事吗？—— 动机有三个：①自引用与互引用（`type Json = dict[str, Json] | list[Json]`）必须在名字还没绑定时就能写；②import 时间：类型表达式可能触发大量 `__class_getitem__`，惰性把成本摊到首次使用；③作用域正确性：`type` 语句的类型参数（`[T]`）有独立的作用域，惰性求值让 `T` 的绑定在需要时才解析。它和注解延迟（PEP 563 的字符串化、PEP 649 的 `__annotate__`）目标相近但不是同一机制：别名是**值对象**的惰性属性，注解是**函数/类元数据**的延迟计算；两者都会把 NameError 从定义点推迟到访问点，所以都需要"启动自检"来兜底。

**追问二**：自研框架（序列化、DI、OpenAPI 生成）拿到一个 `TypeAliasType` 应该怎么处理？为什么直接把别名丢给 `get_type_hints` 不够？—— `get_type_hints` 对已经是对象的注解**不做展开**，返回的仍是别名对象（只有字符串前向引用才会被 eval），所以框架会看到"一个不认识的类型"。正确流程：①`isinstance(tp, TypeAliasType)` → 取 `__value__`；②若拿到的是 `types.GenericAlias` 且 `get_origin(tp)` 是 `TypeAliasType`，则模板是 `origin.__value__`，实参是 `get_args(tp)`，按 `origin.__type_params__` 与实参建立 TypeVar→类型的映射，递归替换模板里的 `T`（标准库没有公开的"替换"API，`typing._eval_type` 是内部实现，不能当稳定接口用）；③展开后可能还是别名（嵌套），循环直到不是 TypeAliasType，并设深度上限防环；④缓存展开结果，避免每次请求都触发惰性求值与替换。结论：别名是"编译期的名字"，运行时框架必须在边界处把它翻译成具体类型，翻译层要幂等、可缓存、能处理循环。

## 背诵要点

- `type X = ...` 创建 `TypeAliasType`，右侧惰性求值、首次 `__value__` 时执行并缓存；定义期不报 NameError，错误推迟到首次访问。
- 泛型特化 `X[int]` 每次新建 `types.GenericAlias`（`is` 为 False），origin 指向别名、args 是实参；`__value__` 保留未替换的 `T`，替换要使用方自己做。
- 别名不是类型：`isinstance(x, X)` 与 `isinstance(x, X[int])` 都 TypeError，裸别名 `get_origin` 为 None；运行时判断要用 `__value__`/`get_origin`，框架入口统一 unwrap。

## 复盘追问

- 为什么把 `IntList = List[int]` 换成 `type IntList = list[int]` 会把 import 期错误变成运行期错误？（惰性求值只记录表达式；启动自检要显式触碰 `__value__`）
- 框架拿到 TypeAliasType 后为什么不能只调用 get_type_hints？（它不展开已是对象的别名；要手动取 `__value__`、处理泛型参数与嵌套，并缓存结果）
