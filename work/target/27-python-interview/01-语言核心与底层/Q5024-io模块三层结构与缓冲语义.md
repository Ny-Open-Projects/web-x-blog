### Q5024 · io 模块三层结构：RawIO、Buffered 与 Text 的缓冲语义

> 难度:★★★★☆ | 标签:io, 缓冲, open

**问**：`open("f", "w")` 返回的对象其实是一个三层包装栈。每一层是谁、各负责什么？为什么文本层 `write("hello")` 后文件可能是空的？"text 模式 + buffering=0" 为什么直接报错？

**答**：从外到内：**TextIOWrapper**（编码/解码、`\n` 与 `os.linesep` 的 newline 转换、通用换行）→ **BufferedWriter/BufferedRandom**（按 `buffering` 大小攒块，默认 8192 字节，减少系统调用）→ **FileIO（RawIOBase）**（裸 fd 的 read/write，一次调用一次 syscall）。`write("hello")` 先过文本层：默认 `write_through=False`，文本层有自己的缓冲（关闭/显式 flush 才下推），再进块缓冲层，两道闸都过才落盘——所以"写了没 flush"文件为空。`buffering=0` 只允许二进制模式（裸 FileIO 无缓冲），文本层必须垫块缓冲，`open(path, "w", buffering=0)` 直接抛 `ValueError: can't have unbuffered text I/O`；`buffering=1` 是行缓冲（仅文本模式）。性能视角：批量小 write 的成本大头是 syscalls，块缓冲摊平它；但多层缓冲意味着**关闭顺序与 flush 时机**才是正确性关键（异常路径用 with 保证）。

```python
# file: code/01_语言核心与底层/q5024_io_layers.py
import io, os, tempfile

path = os.path.join(tempfile.mkdtemp(), "f.txt")

f = open(path, "w+", encoding="utf-8")    # w+: 可读可写,os.pread 才有权限读回
print("Text 层:", type(f).__name__)
print("Buffered 层:", type(f.buffer).__name__)
print("Raw 层:", type(f.buffer.raw).__name__)

f.write("hello")                          # 停在缓冲里,未落盘
print("落盘前读 fd:", os.pread(f.fileno(), 10, 0) or b"<empty>")
f.flush()                                 # 文本层 -> 块层 -> 内核,逐级下刷
print("flush 后读 fd:", os.pread(f.fileno(), 10, 0))
f.close()

try:
    open(path, "w", buffering=0)          # 文本模式禁止无缓冲
except ValueError as e:
    print("buffering=0 + 文本:", e)

raw = io.FileIO(path, "w+")               # 裸 FileIO:write 即 syscall(带读权限供 pread)
raw.write(b"RAW")
print("Raw 直写立即可见:", os.pread(raw.fileno(), 3, 0))
raw.close()

big = os.path.join(os.path.dirname(path), "big.bin")
with open(big, "wb") as g:
    g.write(b"A" * 100)
bf = open(big, "rb")                      # 读侧同样有块缓冲:read(1) 也会预读整块
bf.read(1)
print("read(1) 后块缓冲里预读的剩余字节:", len(bf.peek()), "(远大于 1)")
bf.close()
```

**追问**：1) `write_through=True` 是绕过哪一层？——只绕过 TextIOWrapper 自身的缓冲，把编码结果直接推给块缓冲层；块缓冲仍按 8KB 攒，不是"逐字符落盘"。2) 二进制 `read()` 的大小怎么选？——`read(n)` 在块缓冲层按需补块，网络/管道场景用 `readinto`（Q5530）复用缓冲；文件流 `read(65536)` 级别基本对齐页大小。3) `newline=""` 干什么用？——关闭通用换行翻译，按原始 `\r\n`/`\r`/`\n` 返回，csv 模块官方要求它，否则 Windows 行尾会产生空行。

## 背诵要点
1. 三层栈：TextIOWrapper（编码/换行）→ BufferedWriter（默认 8192）→ FileIO（syscall）。
2. 文本层默认不直写（write_through=False），两道缓冲都要过；flush/close 才落盘。
3. 文本模式禁止 buffering=0；buffering=1 为行缓冲；newline="" 用于 csv 的原始换行。

## 复盘追问
1. 进程崩溃时"写过但没 flush"的数据去哪了？怎么在协议上兜底？（提示：只丢用户态缓冲；重要数据 fsync 或靠重试+幂等，参考 Q380 原子写）
2. 一次写 10MB 与 100 次写 100KB 的耗时差异怎么量化？瓶颈在层还是内核？（提示：strace 数 write 次数；块缓冲下小写也只触发少量 syscall，差异主要来自拷贝与调度）
