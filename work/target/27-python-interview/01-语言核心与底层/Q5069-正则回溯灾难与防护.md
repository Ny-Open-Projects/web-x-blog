### Q5069 · 正则回溯灾难与防护：原子组与超时降级

> 难度:★★★★ | 标签:成本工程, 正则, ReDoS, 防护

**问**：一条用户提交的字符串打了 `re.match(r'^(\w+)+$', s)` 后接口 P99 从 20ms 飙到 30 秒。回溯灾难（ReDoS）的机理是什么？`(\w+)+` 为什么指数级？Python re 有没有超时参数？工程上四层防护怎么配？

**答**：机理：re 是回溯型引擎，`(量词包量词)`（nested quantifier）对失败路径产生**指数级分裂尝试**：`(\w+)+` 匹配 "aaaa...X"（X 不匹配）时，外层每步都重分裂内层 `\w+` 的所有切分方式，n 个字符 2^n 条路径。**成本特征**：输入长度 +1，耗时翻倍——这是容量规划里最危险的"平静曲线"，n=25 时已是分钟级。防护四层：a) **源头**：审计所有含嵌套量词/交替歧义的 pattern（`(.*)*`、`(\d+)*`、`(a|a)*`），能用 possessive/atomic group 的改写——**3.11+ 支持** `(?>...)` 原子组与 `*+` 占有量词，匹配失败不回溯交给外层，语义上等价"贪到底不吐回"；b) **引擎层**：3.11 re **仍无超时参数**（与 .NET 不同），需要超时只能换第三方 `regex` 模块（`regex.match(p, s, timeout=0.5)`，标注基线：regex 2024+）或 C 层 RE2/fkrb；c) **入口层**：限制输入长度（pattern 最坏输入 n 很小就炸，长度上限 1KB 是第一道闸），对用户输入的正则（规则引擎/路由配置）必须白名单校验；d) **隔离层**：把不可信输入的匹配丢进子进程/线程池带超时（signal.alarm 仅 Unix 主线程可用）。实战复盘：上线前用"长度翻倍耗时也翻倍以内"的基准测试过闸——n=20 生成 worst-case 输入，耗时超阈值直接 fail CI。

```python
# file: code/01_语言核心与底层/q5069_redos.py
import re, sys, time

# 1) 复现: 嵌套量词耗时随长度指数增长
pat_evil = r"^(\w+)+$"          # 灾难 pattern(仅演示, 禁止入生产)
for n in (18, 22):              # 别再大, 22 已秒级
    s = "a" * n + "!"
    t0 = time.perf_counter()
    re.match(pat_evil, s)
    dt = (time.perf_counter() - t0) * 1000
    print(f"n={n}: {dt:7.1f} ms  (n+1 耗时约翻倍 -> 指数)")

# 2) 改写1: 去掉嵌套量词, 线性 pattern
pat_ok = r"^\w+$"
print("线性改写匹配:", re.match(pat_ok, "a" * 10_000 + "!") is None)

# 3) 改写2: 3.11+ 原子组 (?>...) 与占有量词 *+  (基线: Python 3.11+)
if sys.version_info >= (3, 11):
    pat_atomic = r"^(?>\w+)$"       # 原子组: 匹配失败不回溯, 直接失败
    pat_pos = r"^\w++$"
    s = "a" * 10_000 + "!"
    t0 = time.perf_counter()
    print("原子组快速失败:", re.match(pat_atomic, s) is None,
          f"{(time.perf_counter()-t0)*1000:.2f} ms")
    t0 = time.perf_counter()
    print("占有量词快速失败:", re.match(pat_pos, s) is None,
          f"{(time.perf_counter()-t0)*1000:.2f} ms")
else:
    print("3.11 以下无原子组: 换 regex 模块或改写 pattern")

# 4) 第三方 regex 的超时闸 (基线: regex 2024+, 缺库降级提示)
try:
    import regex as regex_mod
    s = "a" * 30 + "!"
    print("regex 模块带超时:", regex_mod.match(pat_evil, s, timeout=0.5))
except ImportError:
    print("降级: 未安装 regex 模块 -> 靠输入长度上限+审计 pattern 防护")
except TimeoutError:
    print("regex 超时闸生效")

# 5) 防护基准测试: 长度翻倍耗时不得翻倍(线性闸门)
def cost(pat, n):
    s = "a" * n + "!"
    t0 = time.perf_counter(); re.match(pat, s)
    return time.perf_counter() - t0
c1, c2 = cost(pat_ok, 5000), cost(pat_ok, 10_000)
print(f"线性闸门: n翻倍耗时比={c2/max(c1,1e-9):.2f} (<=2.5 通过, 指数 pattern 远超)")
```

**追问**：1) 为什么 CPython 不给 re 加超时？——re 引擎在 C 层循环，无法从 Python 层打断，加超时要重构引擎为可中断/分片执行，社区选择是保持简单、让用户换 regex/RE2；这也是"安全敏感匹配不上标准 re"的架构理由。2) 原子组和占有量词的语义差别？——都禁止组内回溯，原子组把"组匹配结果整体固化"可包任意子表达式，占有量词只作用于单个量词；改写时要注意它们改变匹配语义——原来靠回溯才能成功的用例会变成失败，需要回归测试。3) 如何系统性审计存量 pattern？——静态扫描嵌套量词/含歧义交替（可用本卡"长度翻倍闸门"自动验证），对规则引擎类"用户可配正则"的服务直接换 RE2（保证线性时间）而非审计。

## 背诵要点
- ReDoS 机理：嵌套量词失败路径指数分裂，n+1 耗时翻倍；3.11 re 无超时参数。
- 四层防护：审计/改写 pattern（3.11+ 原子组 `(?>...)`、占有量词 `*+`）、regex 模块 timeout（缺库降级）、入口限长、子进程隔离。
- CI 加"长度翻倍耗时比 ≤2.5"的线性闸门基准测试；用户可配正则的服务换 RE2 根治。

## 复盘追问
