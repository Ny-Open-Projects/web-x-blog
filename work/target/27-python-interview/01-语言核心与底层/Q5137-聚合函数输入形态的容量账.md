### Q5137 · 聚合函数输入形态的容量账：生成器 vs 列表

难度：P6 | 标签：sum/any/all、生成器表达式、峰值内存、短路求值

**问**：`sum([...])` 换成 `sum(x for x in ...)` 到底省了什么？`any`/`all` 的短路行为在哪种数据规模下才值得专门设计？请给出一套判断"聚合输入该用什么形态"的容量推导。

**答**：

**结论**：三种形态的账各不同：(1) 列表推导 `sum([f(x) for x in data])` 先物化整个列表——峰值多一份 O(n) 内存（大对象时可能是 GB 级），换来的好处是长度已知、可复用、异常发生时中间结果可查；(2) 生成器表达式 `sum(f(x) for x in data)` 逐个产出即时消费，内存 O(1)，但不可重放、异常打断后状态丢失；(3) `any`/`all` 有短路——命中即停，配合生成器可提前终止昂贵计算，这是列表形态做不到的（列表会先全量物化再聚合，短路优势归零）。`max`/`min`/`sorted` 则必须完整遍历，生成器只能省"存储"省不了"计算"。

**取舍**：容量推导公式：若单元素物化大小 s、总量 n，列表形态额外峰值 ≈ n×s + 列表本身 8n 字节指针槽；当 n×s 接近进程内存预算（如 > 数百 MB）或 n 是流式未知量时必须生成器。反过来，元素是int/小对象时列表指针+小对象池开销很低，物化换可重用性反而划算。还有隐形成本：生成器每次 next 都要恢复帧，纯 Python 层的逐元素调度比 C 级列表遍历慢约 20-40%，热循环且内存无压力时列表更快。

**实战**：any/all 与生成器组合是"昂贵的存在性检查"标准解：`any(is_valid(r) for r in scan_table())` 第一个命中就停，不用扫全表；但注意 any 短路后生成器 close，未消费部分的清理逻辑（finally）依然会执行。

```python
import sys, time

data = list(range(2_000_000))

# 1) 峰值内存形态账：列表多一份物化
t = time.perf_counter()
a = sum([x * 2 for x in data])          # 物化 200 万元素列表
t_list = time.perf_counter() - t
t = time.perf_counter()
b = sum(x * 2 for x in data)            # 流式，无物化
t_gen = time.perf_counter() - t
assert a == b
print(f"list 形态 {t_list*1000:6.1f} ms | gen 形态 {t_gen*1000:6.1f} ms")

# 2) 短路收益：第一个命中即停 vs 全量物化后聚合
expensive_calls = 0
def is_target(x):
    global expensive_calls
    expensive_calls += 1
    return x > 10
hit = any(is_target(x) for x in range(1_000_000))
print("any 短路实际调用次数 =", expensive_calls, "命中 =", hit)

# 3) 单元素大小决定物化容量：n*s 推导
elem_cost = sys.getsizeof("x" * 100)     # 100 字节字符串示例
n = 5_000_000
print(f"物化 {n} 个 100B 字符串额外峰值 ≈ {n*elem_cost/1e9:.1f} GB")
```

**追问 1**：`sum` 有 start 参数和 `math.fsum`，聚合浮点时选哪个？
答：`sum` 从 3.12 起对 float 使用 Neumaier 补偿算法，精度大幅提升；更早版本大数吃小数会丢精度，`math.fsum` 是精确补偿和——跨版本基线要写清楚。

**追问 2**：生成器抛异常后能否续跑？
答：不能，异常传播出帧后生成器终止；需要断点续传就自己写显式循环记录游标，或用 `itertools.islice` 分段消费并落 checkpoint。

**追问 3**：`all` 与 `not any` 的短路方向有何不同？
答：`all` 遇到第一个 False 停，`any` 遇到第一个 True 停；校验"全部通过"的场景把最可能失败的检查放前面，短路才真的省时间——这是调用方可控的顺序优化。

## 背诵要点

- 列表形态峰值 ≈ n×s 物化 + 指针槽；生成器 O(1) 内存但不可重放、逐 next 有调度开销。
- any/all 短路只在生成器形态生效，列表物化后短路优势归零；昂贵存在性检查放最可能命中的位置在前。
- 浮点聚合：3.12+ sum 内置 Neumaier 补偿，旧版本用 math.fsum。
