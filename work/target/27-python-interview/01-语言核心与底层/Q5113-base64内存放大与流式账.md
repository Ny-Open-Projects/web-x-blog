### Q5113 · base64 内存放大与流式编解码账

> 难度:★★★☆☆ | 标签:容量规划, base64, 内存账

**问**:把 1GB 的图片转 base64 塞进 JSON 上传，服务却 OOM 了，峰值内存远不止 1GB+1.33GB。这笔内存账该怎么算？大数据量下正确的编解码姿势是什么？

**答**:结论：base64 每 3 字节原文变 4 字节，**膨胀系数 4/3≈1.333**；但峰值内存远不止"输入+输出"两份：`base64.b64encode(bytes)` 是一次性接口，输入前你可能已从文件**完整读入一份**，编码产出**一份 1.33GB 的 bytes**，再拼进 JSON 字符串时 **JSON 序列化还要一份**（str 化后可能又是 UTF-8 bytes 一份）——单条链路峰值轻松到 4-5GB。账目拆解：读入 1GB（①）→ 编码输出 1.33GB（②）→ `json.dumps` 里字符串拼接/复制 ~2GB（③）→ encode 为传输 bytes 再 +2GB（④）。正确姿势：a) **能不用 base64 就不用**：改用 multipart 直传或预签名 URL（见 Q6064），base64 是最后手段；b) 必须用时**分块流式编码**：每次读 3 的倍数块（如 3MB）编码后写入输出缓冲/网络，峰值 O(块)；c) 解码同理 `b64decode` 分块，注意块边界必须是 4 字节倍数（去掉首块外的 padding 才能拼）。

```python
import base64, os, tempfile, time

# 1) 膨胀系数验证
raw = os.urandom(3 * 1_000_000)          # 3MB
enc = base64.b64encode(raw)
print(f"原文 {len(raw)/1e6:.0f}MB -> 编码 {len(enc)/1e6:.1f}MB, 系数 {len(enc)/len(raw):.4f}")

# 2) 内存账：一次性接口的峰值 = 输入 + 输出 同时在内存
#    1GB 文件 ≈ 1GB(读入) + 1.33GB(编码) + json字符串复制，峰值 ≈ 3-4GB
# 3) 流式编码：峰值 O(chunk)
def b64_encode_stream(src, dst, chunk=3 * 1024 * 1024):
    """分块编码大文件到目标文件；chunk 必须是 3 的倍数，保证块边界无 padding"""
    with open(src, "rb") as fin, open(dst, "wb") as fout:
        while True:
            block = fin.read(chunk)          # 峰值只驻留一个块
            if not block:
                break
            fout.write(base64.b64encode(block))
        # 文件长度恰为 3 的倍数时无 padding，可直接拼接；
        # 否则末块补 '='，靠解码端 b64decode 的容错处理

src = tempfile.mktemp(suffix=".bin")
dst = tempfile.mktemp(suffix=".b64")
with open(src, "wb") as f:
    f.write(os.urandom(32 * 1024 * 1024))    # 32MB 样本
t0 = time.perf_counter()
b64_encode_stream(src, dst)
t1 = time.perf_counter()
print(f"流式编码 32MB 耗时 {t1-t0:.3f}s，输出 {os.path.getsize(dst)/1e6:.1f}MB")

# 4) 回读校验（解码同样分块，块长取 4 的倍数）
def b64_decode_stream(src, dst, chunk=4 * 1024 * 1024):
    with open(src, "rb") as fin, open(dst, "wb") as fout:
        while True:
            block = fin.read(chunk)
            if not block:
                break
            fout.write(base64.b64decode(block))
out = tempfile.mktemp()
b64_decode_stream(dst, out)
print("回读一致:", open(src, "rb").read() == open(out, "rb").read())
for p in (src, dst, out):
    os.unlink(p)
```

**追问一层**:为什么流式编码的块长必须是 3 字节的倍数、解码必须是 4 的倍数？padding `=` 只能出现在末尾吗？
**追二层**:JSON 里塞 base64 除了内存还有哪些账（CPU、HTTP 体积、CDN 缓存键）？为什么规范更推荐引用 URL 而非内联（引 Q6064）？

**背诵要点**
- base64 膨胀 4/3≈1.333，链路峰值 = 读入 + 编码输出 + JSON 复制，可到原文 4 倍。
- 流式编码块长取 3 的倍数、解码取 4 的倍数，峰值 O(chunk)。
- 大二进制优先直传/预签名 URL，base64 只做最后手段。

**复盘追问**
- 事故复盘：1GB 图片内联进 JSON OOM，除了改流式还能怎么止血？提示：网关层限制请求体大小 + 强制走预签名直传。
- `b64encode` 传 str 会怎样？提示：TypeError，先明确 bytes/str 边界（Q040）。
