### Q5235 · pow 三参数模幂：为什么不能写 x**y % m

难度：P5 ｜ 标签：pow、模幂、RSA、取模运算、大整数、快速幂、内存爆炸

**问**：`pow(x, y, m)` 三参数形式与 `x**y % m` 结果相同，为什么说后者在生产里是错误写法？模幂的底层做了什么优化？负指数 `pow(x, -1, m)` 是什么语义（3.8+）？RSA 签名验签、Diffie-Hellman 这类场景下两种写法的差距有多大？

**答**：
结论：`pow(x, y, m)` 是**模幂**（modular exponentiation）——底层用平方-乘法（square-and-multiply）算法，每一步乘法后**立即取模**，中间值永远不超过 m²，时间和内存都是 O(log y)；`x**y % m` 则先物化完整的 x^y（位数 = y·log2(x) 位），再对巨数取模——指数稍大就内存爆炸。量化对比：`pow(3, 10**9, 97)` 瞬间完成（中间值 ≤ 97²）；`3 ** 10**9` 是一个约 15.9 亿位（~750MB 起）的整数，直接 OOM——**结果相同、成本天差地别**，这就是"为什么不能写 x**y % m"的全部原因。C 语言家的 `x**y` 大整数乘法用的是 Karatsuba/FFT（Q1292），但再先进的乘法也救不了"先造全量再截断"的思路，模幂赢在**边算边约**。另一层语义：`pow(x, -1, m)`（3.8+）计算**模逆元**（x·y ≡ 1 (mod m) 的 y），x 与 m 不互素时抛 ValueError——RSA 私钥推导、有限域除法都靠它；`pow(0, 0, m)` 语义为 1 % m。签名验签场景（RSA 的 c = m^e mod n，e 常为 65537）必须用三参数 pow，任何 `**` 写法都在为攻击者制造 DoS 面。

取舍：a) 小指数小数值（y < 千级、x^y 仍在内存预算内）：`x**y % m` 可读性更好，性能差异可忽略；b) 密码学/竞赛/大指数：一律 `pow(x, y, m)`，这是唯一正确姿势；c) 需要模逆元：`pow(x, -1, m)` 或 `pow(x, m-2, m)`（m 为素数时费马小定理路线），别手写扩展欧几里得（除非要多样数）；d) 频繁的固定模数运算（如哈希环）：预计算域参数封装成函数，别在热路径重复解释 pow 调用；e) 底层加速注意：CPython 对三参数 pow 仍是大整数乘除法，没有用到 Montgomery 乘法等密码学库优化——真做 TLS 级别吞吐应上 cryptography 库，标准库 pow 是"正确性优先"的通用工具。

实战：事故形态是"自研 RSA 验签 demo 用 `c ** d % n` 校验，d 是 2048 位私钥指数——中间值是 2048 位进制的天文数，单次验签占用数 GB 内存并耗时分钟级，压测直接把服务打挂；改 `pow(c, d, n)` 后单次微秒级，内存恒定"。下面实测两种写法的成本差距与模逆元。

```python
# pow 三参数模幂
import time

print("[1] 结果相同, 成本天差地别")
x, y, m = 3, 10 ** 9, 97
t0 = time.perf_counter()
r1 = pow(x, y, m)                       # 中间值 <= m^2
t1 = time.perf_counter() - t0
print(f"    pow(3, 10**9, 97)      = {r1}  耗时 {t1*1000:.3f} ms (中间值恒 <= 97^2)")
print("    3 ** 10**9 约为 15.9 亿位十进制数 (~500MB+), x**y % m 会直接内存爆炸, 不实跑")

print("[2] 可观测的中间对比: 小一点的指数也拉开数量级")
for e in (10 ** 2, 10 ** 4, 10 ** 6):
    t0 = time.perf_counter()
    a = pow(3, e, 97)
    t1 = time.perf_counter()
    b = (3 ** e) % 97
    t2 = time.perf_counter()
    print(f"    e={e:>8}: 模幂 {t1-t0:9.6f}s | 全量再取模 {t2-t1:9.6f}s (全量位长 ~{e*2} 位)")

print("[3] 负指数 = 模逆元 (3.8+): 求 x*y ≡ 1 (mod m) 的 y")
inv7 = pow(7, -1, 26)
print("    pow(7, -1, 26) =", inv7, "-> 7 *", inv7, "% 26 =", (7 * inv7) % 26, "(== 1)")
try:
    pow(4, -1, 26)                      # gcd(4, 26) = 2 != 1, 不互素
except ValueError as e:
    print("    pow(4, -1, 26) -> ValueError:", e)

print("[4] RSA 风格小例: 公钥 (e, n) 签名, 私钥 d 验签 — 全程 pow 三参数")
p, q = 61, 53
n = p * q
phi = (p - 1) * (q - 1)
e = 17
d = pow(e, -1, phi)                     # 模逆元求私钥
msg, sig = 65, pow(65, d, n)            # 签名 = m^d mod n
ok = pow(sig, e, n) == msg              # 验签 = s^e mod n
print(f"    n={n}, d={d}; 签名 {sig} 验签通过: {ok}")

print("[5] pow(0, 0, m) 语义: 1 % m")
print("    pow(0, 0, 10) =", pow(0, 0, 10))
print("[6] 工程纪律: 大指数模运算一律 pow(x, y, m); 先造全量再截断是 DoS 面")
```

**追问一**：模幂的平方-乘法为什么是 O(log y)？中间值为什么恒不超 m²？—— 平方-乘法把指数按二进制分解：y = Σ 2^k 的展开下，从最低位起每轮先 `result = result * base % m`（位为 1 时）、再 `base = base * base % m`，总共 log₂(y) 轮——每轮一次乘法一次取模，乘法操作数都 ≤ m，故中间值 ≤ m²，位数 ≤ 2·log₂(m)，与 y 无关。这就是"边算边约"的本质：把 x^y 这个天文数字的位长增长，在每一步都压缩回模数的世界里。对比 `x**y`：位长随 y 线性增长，乘法本身还要在巨型位串上做 Karatsuba——双重浪费。学习迁移：模幂是"流式化计算"思想在数论里的原型，与流式摘要（Q5200）"不落全量"同构。

**追问二**：`pow(x, -1, m)` 之前怎么求模逆元？为什么 3.8 才把这个补进来？—— 3.8 前的标准姿势是 `pow(x, m-2, m)`（m 为素数时费马小定理 x^(m-2) ≡ x^-1）或手写扩展欧几里得算法求 Bezout 系数——前者对合数域失效（错误静默），后者代码易错且性能差（纯 Python 循环）。3.8 把它收编为负指数语义，内部直接走扩展欧几里得（x 与 m 不互素时精确报 ValueError，不再静默错值）。设计动机：模逆元是有限域运算的"除法"，RSA/ElGamal/椭圆曲线标量运算都绕不开，收编进内建让纯标准库实现密码学协议（教学、小规模自研）成为可能。注意边界：m ≤ 0 时 ValueError、m=1 时返回 0——协议实现里这些边界要显式断言而不是依赖内建默认。

## 背诵要点
- pow(x, y, m) 模幂：平方-乘法 O(log y)，中间值 ≤ m²；x**y % m 先物化 x^y（位长随 y 线性涨），指数大即 OOM。
- pow(x, -1, m) = 模逆元（3.8+，扩展欧几里得），不互素 ValueError；素数域可 pow(x, m-2, m)。
- RSA 验签/密钥协商必须三参数 pow；** 全量写法是 DoS 面。
