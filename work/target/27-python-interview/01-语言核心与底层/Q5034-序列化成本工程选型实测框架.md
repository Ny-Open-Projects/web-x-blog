### Q5034 · 序列化成本工程：json/pickle/msgpack 的实测选型框架

> 难度:★★★★ | 标签:序列化, 成本工程, 基准, json, pickle

**问**：选序列化协议时"json 慢、pickle 快"对吗？怎么搭一个能说服评审的实测框架？CPU、体积、安全三个维度怎么权衡？

**答**：背诵结论不对，**成本要按负载与协议版本实测**：json 在 3.12+ 的 C 加速器下对小 dict 很快，pickle（协议 5）对 numpy/嵌套对象快但**有安全边界**（unpickle = 任意代码执行，绝不用于跨信任边界）；msgpack/schema 类在体积上赢（二进制 + 无引号开销），orjson（第三方，基线 3.9+）在 CPU 上通常赢标准库 json 2-6 倍。选型框架四个量：**编码 CPU（µs/次）、解码 CPU、输出体积、往返一致性**（自定义类型是否需要 default/钩子，钩子一加成本反转，参考 Q6004 的教训）。取舍口诀：同信任域 + 复杂 Python 对象 → pickle 协议 5；对外 API/跨语言 → JSON（标准库或 orjson）；高吞吐内部总线 → msgpack/protobuf（schema 前置，体积与演进性最好）；任何"不可信来源反序列化"路径 → 只允许 JSON/文本类。实战：把四个量做成参数化基准随 PR 跑，防止"感觉快"进入评审。

```python
# file: code/01_语言核心与底层/q5034_serialization_cost.py
"""序列化选型四量基准: 编码CPU / 解码CPU / 体积 / 往返一致性."""
import json
import pickle
import time

def make_payload(n: int) -> dict:
    return {
        "rows": [{"id": i, "name": f"user-{i}", "tags": ["a", "b"], "score": i * 1.5}
                 for i in range(n)],
    }

def bench(fn, reps: int = 5) -> float:
    best = float("inf")
    for _ in range(reps):
        t0 = time.perf_counter()
        fn()
        best = min(best, time.perf_counter() - t0)
    return best * 1000  # ms

def suite(payload: dict) -> None:
    print(f"payload: {len(payload['rows'])} rows")
    enc = {
        "json(default)": lambda: json.dumps(payload),
        "json(compact)": lambda: json.dumps(payload, separators=(",", ":")),
        "pickle(proto5)": lambda: pickle.dumps(payload, protocol=5),
    }
    # orjson 为可选第三方(基线 Python>=3.9), 缺库自动降级
    try:
        import orjson
        enc["orjson"] = lambda: orjson.dumps(payload)
    except ImportError:
        print("(orjson 未安装, 降级跳过; pip install orjson)")

    results = {}
    for name, fn in enc.items():
        data = fn()
        e = bench(fn)
        d_fn = {"json(default)": lambda d=data: json.loads(d),
                "json(compact)": lambda d=data: json.loads(d),
                "pickle(proto5)": lambda d=data: pickle.loads(d)}.get(name,
                (lambda d=data: orjson.loads(d)) if name == "orjson" else None)
        d = bench(d_fn)
        results[name] = (e, d, len(data))
        print(f"{name:16s} enc={e:7.2f}ms dec={d:7.2f}ms size={len(data)/1024:8.1f}KB")

    print("结论模板: 同负载下对比三列, 再叠加'跨信任边界禁 pickle'的安全约束定选型")

if __name__ == "__main__":
    suite(make_payload(2000))
```

**追问**：1) 为什么 pickle 协议 5 对 numpy 特别快？——out-of-band 缓冲（PEP 574，Q5009）让大 ndarray 不经 pickle 序列化、直接搬内存，省掉拷贝与编解码。2) orjson 什么时候反而比标准库慢？——需要 default 钩子桥接非原生类型时走 Python 回调，或输入是浅层小对象时 C 扩展调用开销占比升高；结论必须带着"你的负载"重测。3) 体积与 CPU 冲突怎么选？——看瓶颈面：内网带宽贵选紧凑协议，CPU 配额贵选最快的解码器；中间态可以上压缩（zstd）但要计入 CPU。

## 背诵要点
- 四量实测：编码 CPU、解码 CPU、体积、往返一致性；钩子（default）会让第三方库成本反转。
- pickle 只用于同信任域；跨信任边界只允许 JSON/文本类，unpickle=任意代码执行。
- orjson（3.9+）典型 2-6 倍于标准库 json，小负载/带钩子时需重测。
