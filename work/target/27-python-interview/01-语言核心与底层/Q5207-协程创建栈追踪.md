### Q5207 · set_coroutine_origin_tracking_depth：协程是谁在哪创建的

难度：P7 ｜ 标签：协程、cr_origin、调试、never awaited、asyncio

**问**：服务日志里频繁出现 `RuntimeWarning: coroutine 'foo' was never awaited`，但调用栈只有 GC 时的告警，看不出协程是在哪创建的；`asyncio` 调试模式有时能给出创建栈，有时给不出。`sys.set_coroutine_origin_tracking_depth` 到底记录什么？为什么默认关闭？它和 `await` 链是一回事吗？

**答**：
结论：`sys.set_coroutine_origin_tracking_depth(n)` 开启后，**新创建**的协程对象会记录最近 n 层创建点的 `(filename, lineno, funcname)`，存在只读属性 `coro.cr_origin` 里；n=0 关闭。它记录的是"协程对象在哪被创建"，不是"协程被谁 await"——后者要看 `cr_await`/任务栈。默认关闭是因为每个协程创建都要抓栈，高频创建场景开销明显。

取舍：a) 只在排障窗口开，复现 "never awaited" 或"协程泄漏"后关闭；b) `asyncio` 调试模式会利用它补创建栈，但只对开启后创建的协程有效；c) `cr_origin` 是元组，可能为空/None，别假设一定有；d) 它不能定位"协程在哪儿被 await 卡住"，那要用 `Task.get_stack()`/`py-spy`；e) 生产常开请用采样/旁路工具，不要全局开深度追踪。

实战：事故形态是"SDK 内部 `async def` 被同步调用后忘记 await，协程对象被丢弃，GC 时才告警；开启 origin tracking 后，`cr_origin` 直接指到 `client.py:88` 的调用点，定位从半天缩短到五分钟"。下面演示开启/关闭后 `cr_origin` 的差异。

```python
import sys


async def inner():
    return 1


async def outer():
    return inner()


sys.set_coroutine_origin_tracking_depth(5)
coro = outer()
print("[1] 追踪开启:", coro.cr_origin is not None)
print("[2] 创建栈深度:", len(coro.cr_origin))
print("[3] 最内层来源:", coro.cr_origin[0][0].rsplit("/", 1)[-1],
      coro.cr_origin[0][1], coro.cr_origin[0][2])
coro.close()

sys.set_coroutine_origin_tracking_depth(0)
coro2 = outer()
print("[4] 关闭后:", coro2.cr_origin)
coro2.close()
print("[5] 只记录创建点，不记录 await 链")
```

**追问一**：为什么 `cr_origin` 有时只有 1 层？—— 深度是"创建协程时的 Python 调用栈层数上限"，如果协程是在模块顶层/单个函数里直接创建，栈本来就只有一层；另外只有开启之后创建的协程才有记录，之前创建的对象不会补。要更深的栈，把 depth 调大并确保创建发生在嵌套调用里。

**追问二**：这和 `asyncio` 的 `PYTHONASYNCIODEBUG=1` 有什么关系？—— asyncio 调试模式在创建 Task 时会利用协程的 `cr_origin` 生成"Task was created here"的日志；如果你的协程是在调试模式开启前创建的，或者 depth=0，日志里就没有创建点。两者是互补的：debug 模式管 Task 生命周期告警，origin tracking 管协程对象本身的来源。

## 背诵要点
- `set_coroutine_origin_tracking_depth(n)` 让新协程记录 `cr_origin` 创建栈，n=0 关闭。
- 只记创建点，不记 await 链；高频创建有开销，排障时临时开。
- "never awaited" 告警配合 `cr_origin` 才能指到调用点。

## 复盘追问
- 只有 GC 时的 never-awaited 告警，怎么找创建点？（开 origin tracking，看 `cr_origin`）
- `cr_origin` 为空/只有一层，可能是什么原因？（开启前创建、depth=0、顶层创建）
