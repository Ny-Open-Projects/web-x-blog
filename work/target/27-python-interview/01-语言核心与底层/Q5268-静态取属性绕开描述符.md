### Q5268 · inspect.getattr_static：绕开描述符与 __getattr__ 的静态取属性

难度：P6 ｜ 标签：inspect、getattr_static、描述符、property、slots、反射

基线：CPython 3.12.2，纯标准库；用带副作用的描述符、property、`__getattr__` 与 `__slots__` 对比普通 `getattr` 和 `getattr_static`。

**问**：管理后台的"模型字段说明"页面要枚举 ORM 模型的所有字段。代码用 `getattr(model, name)` 逐个取值，结果页面上线后，每刷新一次就触发 200 多条懒加载 SQL；另一个模型用了审计描述符，读属性会写一条审计日志，页面刷新把审计表打爆。后来改成 `getattr_static`，SQL 没了，但 `__slots__` 模型的字段值全变成了 `<member 'x' of 'S' objects>`。`getattr_static` 到底绕过了什么？为什么它拿不到 slot 的值？它返回的到底是谁？

**答**：

- **结论**：`inspect.getattr_static(obj, name, default)` 做的是**静态查找**：依次看实例 `__dict__`、类型 MRO 的 `__dict__`，需要时也看元类，但**不调用** `__getattribute__`、`__getattr__`、描述符的 `__get__`、property 的 getter。因此它返回的是"属性在类字典里的原始对象"——类属性返回描述符本身（`property` 对象、自定义描述符对象、`member_descriptor`），实例字典里的属性返回原始值。普通 `getattr` 会按数据描述符 → 实例字典 → 非数据描述符的顺序绑定；`getattr_static` 跳过了绑定这一步。`__slots__` 的值存在 slot 里、不在实例 `__dict__`，类字典里只有 `member_descriptor`，所以静态查找只能返回这个描述符，拿不到值。
- **取舍**：静态查找适合**框架/工具做内省**（生成 schema、找字段、读默认值、调试），因为它无副作用、不会触发 IO；但它也给不了"运行时的值"，需要值时必须 `getattr`。如果既要值又怕副作用，应该显式区分"元数据"和"值"：框架在类定义时收集字段元数据（`__set_name__` 就是干这个的），运行时只对白名单字段取值。另一个坑是继承：`getattr_static` 会沿 MRO 找，但不会合并 `__getattr__` 的动态属性，动态字段永远查不到，必须走普通 `getattr`。
- **实战**：事故页面把"取元数据"和"取值"混在一个循环里。修复：① 字段列表用 `getattr_static(cls, name)` 只判断"是不是描述符/字段对象"，不取值；② 需要展示值的字段，走显式的 `serialize(obj, fields=...)` 白名单，并预加载关联；③ `__slots__` 模型的值用普通 `getattr`（此时已知字段在白名单里，副作用可控）。页面的 SQL 从 200+ 降到 3，审计写入归零。

下面用带打印的 `__get__`、property、`__getattr__` 验证静态查找"不触发任何用户代码"，并验证实例字典、类字典、slots 三种返回形态。

```python
# getattr_static: 不触发 __get__/property/__getattr__, 返回类字典里的原始对象
import inspect


class TrackingDescriptor:
    def __get__(self, obj, owner):
        print("    [副作用] descriptor.__get__ 被调用")
        return "bound-value"


class Model:
    field = TrackingDescriptor()

    def __init__(self):
        self.plain = 42
        self.__dict__["dynamic"] = "from-dict"

    @property
    def computed(self):
        print("    [副作用] property getter 被调用")
        return "computed-value"

    def __getattr__(self, name):
        print("    [副作用] __getattr__ 被调用")
        return f"fallback-{name}"


m = Model()

# 普通 getattr: 会触发描述符/property/__getattr__
print("[1] 普通 getattr:")
assert getattr(m, "field") == "bound-value"
assert getattr(m, "computed") == "computed-value"
assert getattr(m, "missing") == "fallback-missing"

# getattr_static: 全程无副作用
print("[2] getattr_static:")
raw_field = inspect.getattr_static(m, "field")
raw_prop = inspect.getattr_static(m, "computed")
raw_plain = inspect.getattr_static(m, "plain")
raw_dynamic = inspect.getattr_static(m, "dynamic")
print("    field ->", type(raw_field).__name__)
print("    computed ->", type(raw_prop).__name__)
print("    plain/dynamic ->", raw_plain, raw_dynamic)
assert raw_field is Model.__dict__["field"], "返回类字典里的原始描述符"
assert isinstance(raw_prop, property)
assert raw_plain == 42 and raw_dynamic == "from-dict"
assert inspect.getattr_static(m, "missing", "DEFAULT") == "DEFAULT"

# __getattr__ 的动态属性不会被静态查找发现
assert not hasattr(Model, "missing")
print("[3] 动态属性: 静态查找只能拿到 default, 不会触发 __getattr__")

# __slots__: 类字典里是 member_descriptor, 静态查找拿不到值
class SlotModel:
    __slots__ = ("x",)


s = SlotModel()
s.x = 7
static_x = inspect.getattr_static(s, "x")
print("[4] slots 静态查找:", type(static_x).__name__, "| 普通取值:", s.x)
assert type(static_x).__name__ == "member_descriptor"
assert s.x == 7

# 描述符协议本身: 通过类访问才会把 owner 传进去
print("[5] 类访问触发 __get__(None, owner):", Model.field)
assert Model.field == "bound-value"
```

**追问一**：`getattr_static` 和 `vars(obj)` 有什么区别？—— `vars(obj)` 只返回实例 `__dict__`，看不到类属性、描述符、property，也不沿 MRO 找；`getattr_static` 会走完整的静态查找顺序（实例字典 → 类型 MRO → 元类），并且对类属性返回原始描述符。反过来说，`vars(obj)` 更快、更直接，适合"只看实例自身存了什么"；`getattr_static` 适合"模拟一次不会触发副作用的属性查找"。

**追问二**：为什么框架生成 schema 时更推荐 `__set_name__` 而不是 `getattr_static`？—— `__set_name__(owner, name)` 在类创建时由 type 自动调用，描述符可以在这个时刻把自己注册到 owner 的字段表里，**零运行时查找**、零副作用，还能拿到最终类名（处理继承/重命名）。`getattr_static` 是事后扫描，每次都要遍历 MRO，且无法区分"字段"与"普通类属性"。ORM、序列化框架通常在 `__set_name__` 里建注册表，运行时只查表；`getattr_static` 更适合调试器、REPL、通用的对象浏览器。

## 背诵要点

- `getattr_static` 不触发 `__getattribute__`/`__getattr__`/`__get__`/property，返回类字典里的原始对象。
- 类属性返回描述符本身，实例 `__dict__` 属性返回值；`__slots__` 只能拿到 `member_descriptor`，拿不到值。
- 动态属性（`__getattr__`）静态查找永远看不到；框架元数据优先在 `__set_name__` 建表。

## 复盘追问

- 为什么 `getattr_static(instance, "prop")` 返回 `property` 对象而不是值？（静态查找跳过描述符绑定，返回类字典原始对象）
- 用 `getattr_static` 判断"字段是否存在"有什么盲区？（`__getattr__` 提供的动态字段、元类 `__getattr__`、C 扩展的动态属性都看不到）
