### Q5246 · 自定义序列与 abc.Sequence 注册：mixin 免费方法与切片同型

难度：P6 ｜ 标签：collections.abc、Sequence、mixin、__len__、__getitem__、切片同型、虚拟子类、鸭子序列、register

**问**：只实现 `__len__` 和 `__getitem__` 能得到哪些"免费方法"？直接继承 `collections.abc.Sequence` 与 `Sequence.register()` 虚拟注册有什么差异？切片返回为什么必须"同型返回"而不是裸 list？`__iter__` 与 `__getitem__` 迭代（旧式协议，Q542）在性能与语义上怎么选？

**答**：
结论：`collections.abc.Sequence` 是"鸭子序列"的标准化基类：**只需实现 `__getitem__` 与 `__len__` 两个抽象方法**，ABC 的 mixin 实现自动补齐 `__contains__`、`__iter__`、`__reversed__`、`index`、`count`（3.12 起 `Sequence.index/count` 还支持 start/stop 边界）——这套 mixin 的工作方式是"用两个原语推导出全套序列行为"：`__contains__` 退化为线性扫描 `for x in self`、`index` 同理，**没有 O(1) 的成员测试**——自定义序列若底层是哈希结构，应自己覆盖 `__contains__`（Q543 的 in 成本账同族），否则继承 mixin 反而吃性能亏。`isinstance` 语义两条路：①**直接继承**——真子类，`isinstance(obj, Sequence)` 为 True，且 ABC 会检查抽象方法是否齐（缺 `__len__`/`__getitem__` 实例化直接报错）；②**`Sequence.register(MyClass)` 虚拟注册**——isinstance 返回 True 但没有继承任何 mixin（免费方法一个都拿不到），适合"结构上鸭子但无法改继承树"的第三方类。切片同型：`__getitem__` 收到 `slice` 对象时必须返回**同类实例**（`type(self)(data[i])`），返回裸 list 会破坏"切片后仍是窗口/视图"的语义链——调用方 `tw[2:5].sum()` 这类链式调用直接 AttributeError，这是自定义序列最常见的接口违约（slice.indices 折算边界参考 Q1801）。`__iter__` 显式实现 vs 旧式协议：有 `__getitem__` 无 `__iter__` 时 for 循环走旧式协议（从 0 开始递增索引直到 IndexError），**每次迭代要重新走 `__getitem__` 分发**且不支持生成器惰性；显式 `__iter__`（通常 `yield from`）更快、语义更清楚，生产自定义序列一律两个都给。

取舍：a) 继承 Sequence vs 实现完整协议：继承省代码、契约显式（类型检查器认 `isinstance(x, Sequence)`），代价是抽象方法强制 + mixin 性能陷阱；b) 不可变序列：只需 `__len__`/`__getitem__`（MutableSequence 才要 `__setitem__` 等五个），做"只读窗口"类（切片视图、快照）正好够用；c) 切片返回同型但**要防共享底层缓冲**——`type(self)(self._data[i])` 若构造函数只是存引用，切片与原对象共享 list，可变窗口类必须拷贝（`list(...)`）；d) `__length_hint__`（Q544）可选加分：`list(self)` 预分配用；e) 与 typing 的关系：`typing.Sequence` 是 `collections.abc.Sequence` 的别名形态，注解与运行时注册走同一套。

实战：事故形态是"自研 TimeWindow 序列类切片返回裸 list，下游 `[w[0:3].last()]` 炸 AttributeError；排查半天发现是 mixin 假设失效——修复为切片同型返回 + `__contains__` 覆盖为 O(1)（底层本来就带索引 map），成员测试从 O(n) 回到 O(1)，接口测试补齐 '切片保持类型' 用例"。下面实测 mixin 免费方法、虚拟注册差异与切片同型。

```python
# abc.Sequence: mixin 免费方法、虚拟注册与切片同型
from collections.abc import Sequence
import time

class TimeWindow(Sequence):
    """只读时间窗口: 实现两个抽象方法, 免费获得全套序列行为"""

    def __init__(self, stamps: list) -> None:
        self._s = list(stamps)               # 拷贝: 防与原对象共享缓冲
        self._index = {t: i for i, t in enumerate(self._s)}

    def __len__(self) -> int:
        return len(self._s)

    def __getitem__(self, i):
        if isinstance(i, slice):
            return TimeWindow(self._s[i])    # 切片同型返回, 破坏即接口违约
        return self._s[i]                    # 负索引/越界由 list 兜底处理

    def __contains__(self, t) -> bool:       # 覆盖 mixin 的 O(n) 线性扫描
        return t in self._index              # O(1) 哈希查找

tw = TimeWindow([10, 20, 30, 40, 50])

print("[1] isinstance 与抽象方法检查: 继承即真子类")
print("    isinstance(tw, Sequence):", isinstance(tw, Sequence))

print("[2] mixin 免费方法: 不写一行就有")
print("    tw.index(30):", tw.index(30), "| tw.count(20):", tw.count(20))
print("    30 in tw:", 30 in tw, "| list(iter):", list(iter(tw)), "| reversed:", list(reversed(tw)))

print("[3] 切片同型: 切片后仍是 TimeWindow, 链式调用不断")
sub = tw[1:4]
print("    tw[1:4] 类型:", type(sub).__name__, "| 值:", sub._s, "| 二次切片:", sub[1:2]._s)

print("[4] 虚拟注册: isinstance 通过但拿不到 mixin")
class LegacyRows:
    """第三方类, 不能改继承树"""
    def __len__(self):
        return 3
    def __getitem__(self, i):
        return ("r", i) if i < 3 else (_ for _ in ()).throw(IndexError)

Sequence.register(LegacyRows)
lr = LegacyRows()
print("    isinstance(lr, Sequence):", isinstance(lr, Sequence))
print("    lr 有 index 方法吗:", hasattr(lr, "index"), "(虚拟注册不发 mixin)")

print("[5] 覆盖 __contains__ 的性能差: O(n) mixin vs O(1) 哈希")
n = 20000
probe = n - 1
big = TimeWindow(list(range(n)))
t0 = time.perf_counter()
for _ in range(200):
    big.index(probe)                          # mixin 路径: 线性扫描
t1 = time.perf_counter()
mixin_us = (t1 - t0) / 200 * 1e6
t0 = time.perf_counter()
for _ in range(200):
    probe in big                              # 覆盖后的哈希路径
t1 = time.perf_counter()
own_us = (t1 - t0) / 200 * 1e6
print(f"    index/mixin 线性: {mixin_us:8.1f} us | in/覆盖哈希: {own_us:8.1f} us")
print("[rule ] 继承 Sequence 得 mixin; register 只给 isinstance; 切片必须同型; 热路径覆盖 __contains__")
```

**追问一**：`Sequence.register()` 之后 ABC 的 `__subclasshook__` 与"结构化鸭子判定"是什么关系？不注册、不继承的结构正确的类，isinstance 会是 True 吗？—— 机制分三层：①**继承**→真子类，isinstance True；②**register**→虚拟子类，isinstance True 但只是"声明"，不发方法；③**`__subclasshook__` 结构判定**——Sequence 等多数 ABC 定义了 hook：类若有 `__len__` 与 `__getitem__`（可调用、在类上），**不继承也不注册**，isinstance 直接返回 True（这是 `isinstance(x, collections.abc.Iterable)` 对鸭子类生效的同款机制，Q437 的迭代器取舍文里可交叉）。三个推论：虚拟注册与结构判定对 isinstance 等价，但**语义意图不同**——register 是"我宣称兼容"，hook 是"结构巧合"；`issubclass` 与 isinstance 都吃这套；hook 只认**类属性**，实例上动态挂的 `__len__` 不算。工程口径：自己的类继承 ABC 拿 mixin；第三方鸭子类**不注册也能 isinstance**，只有当它结构不齐（比如只有 `__getitem__` 没有 `__len__`）而业务上确实兼容时才 register 显式收编——register 用错方向（把不齐的类硬注册）会把 mixin 假设泄漏给下游调用方。

**追问二**：mixin 的 `index`/`count` 与 `__contains__` 的成本为什么是"结构性 O(n)"？什么时候值得为了性能放弃继承改手写？—— mixin 用"推导"换"省代码"：`__contains__` 的默认实现是 `for x in self: if x is value or x == value: return True`——序列 ABC 没有"成员索引"原语，只能线性；`index` 同理。成本结构：O(n) 比较 + 每次比较走 `__eq__`（自定义类可能更贵）。放弃继承的判据：①**成员测试是热路径**且底层有哈希/有序索引（自定义覆盖 `__contains__` 就够，不必放弃继承——覆盖优先于放弃）；②**频繁随机写**导致每次写都破坏自建索引——直接继承 list 子类或组合 list + 显式 API 比自研窗口类维护成本低；③**大规模切片链**（分页窗口反复切）——切片同型构造函数的拷贝成本 O(n)，可改成"偏移 + 引用"的视图式实现（共享底层数组 + start/stop），代价是可变性与生命周期管理。次序：覆盖方法 > 视图式重构 > 放弃 ABC——ABC 继承的契约价值（isinstance、类型注解、文档自证）通常高于那点方法开销。

## 背诵要点
- collections.abc.Sequence：只需 __len__+__getitem__ 两个抽象方法，mixin 免费给 __contains__/__iter__/__reversed__/index/count——但成员测试是线性 O(n)，底层有索引要覆盖 __contains__。
- isinstance 三路：继承（真子类+mixin）、register（虚拟子类仅声明）、__subclasshook__ 结构判定（len+getitem 即 True，第三方类不注册也算）。
- 切片必须同型返回（type(self)(...)）且防共享底层缓冲；生产类显式 __iter__ 优于旧式 getitem 迭代协议。

## 复盘追问
- 只实现 len/getitem 能白拿哪些方法，哪些是自己覆盖才快的？（contains/iter/reversed/index/count 免费；contains/index 线性，有哈希索引时覆盖）
- 切片返回裸 list 的接口违约在下游怎么炸？（切片后类型降级，链式调用/二次切片语义断裂；同型返回 + 测试用例锁住）
