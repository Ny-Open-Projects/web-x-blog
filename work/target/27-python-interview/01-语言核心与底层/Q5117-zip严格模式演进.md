### Q5117 · zip(strict=True) 的演进与对齐错误拦截

> 难度:★★★★☆ | 标签:版本演进, PEP 618, zip

**问**:两个等长的列表做逐项对齐，历史上 `zip(a, b)` 在长度不一致时会**静默截断**，数据错位没人发现。PEP 618 的 `strict=True` 是怎么解决这个问题的？为什么 3.10 才把它做进内置函数，而不是改默认行为？

**答**:结论：`zip` 一直按"最短者耗尽即停"迭代，多出来的尾巴静默丢弃——这是为流式/无限序列设计的历史语义。PEP 618（Python 3.10）加了 `strict=True`：长度不齐时在**耗尽后检查并抛 ValueError**，把静默截断变成显式错误。**不改默认行为**的原因是兼容性包袱：a) 大量存量代码依赖"截断"语义（如配对遍历到最短处停下），改默认会让无数程序在升级后开始抛错；b) zip 支持无限迭代器，"先看长度"不总是可行的语义（strict 只在正常耗尽后校验，不主动 peek）。3.12 又配套把 `zip(*iters)` 的解包重构（PEP 701 无关，但 3.12 的 `zip` 对多参数 C 层做了批量加速）。对齐场景的正确姿势演进史：3.9- 用 `zip` 后自检长度或 `itertools.zip_longest` 补哨兵，3.10+ 直接 `strict=True`。成本：strict 模式只是在收尾多一次长度比较，可忽略；但它要求两个输入**都耗尽**，若一侧是无限流就会永远挂住——这不是它能解决的场景，属于"对齐"与"配对流"的语义分野。

```python
a, b = [1, 2, 3], [1, 2, 5]

# 3.9 及以前：静默截断（事故高发区）
print(list(zip(a, b)))                  # [(1,1), (2,2)] —— 3 丢了，无告警

# 3.10+：strict 显式报错（PEP 618）
import sys
if sys.version_info >= (3, 10):
    try:
        list(zip(a, b, strict=True))
    except ValueError as e:
        print("strict 拦截:", e)
else:
    # 降级：3.9- 手工对齐校验
    if len(a) != len(b):
        raise ValueError(f"长度不齐 {len(a)}!={len(b)}")

# 不需要严格对齐的流式场景保持原语义（无限流也能配对）
from itertools import count, zip_longest
pairs = zip(count(0), count(100))       # 两个无限流，配对没问题
print([next(pairs) for _ in range(3)])

# 补齐语义：zip_longest + 哨兵（明确"缺口"是合法数据时用）
print(list(zip_longest(a, b, fillvalue=None)))

# 成本：strict 只是收尾多一次比较
import timeit
xs = list(range(100_000))
t1 = timeit.timeit(lambda: zip(xs, xs), number=100)
t2 = timeit.timeit(lambda: zip(xs, xs, strict=True), number=100) if sys.version_info >= (3, 10) else t1
print(f"zip        x100: {t1*1000:.1f}ms")
print(f"zip strict x100: {t2*1000:.1f}ms")
```

**追问一层**:为什么 `strict=True` 不在长度不齐时"立刻"报错，而是等正常迭代结束后才检查？这对"消费一半就 break"的场景意味着什么？
**追二层**:同样的静默截断问题还藏在哪些内置函数里（`slice` 越界、`dict[list]` 取切片、`a[:-1]` 空列表）？为什么 Python 生态整体走"加 strict 开关"而非"改默认"的演进路线（对照 Q5044 utcnow 弃用路线）？

**背诵要点**
- zip 历史语义按最短截断；PEP 618（3.10）`strict=True` 在耗尽后校验并抛 ValueError。
- 不改默认是兼容性与无限流语义所限；strict 只适配"等长对齐"场景。
- 静默截断同类陷阱遍布切片/解包，生态路线是加开关而非改默认。

**复盘追问**
- 数据管道里因 zip 截断导致最后一条记录丢失，怎么建立防线？提示：对齐处强制 strict + CI 里 fuzz 长度不一致样本。
- `zip(a, b, strict=True)` 在 3.9 上的降级实现要注意什么？提示：不能提前 len()（可能是迭代器），要在消费后对账。
