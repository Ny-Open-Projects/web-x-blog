### Q5238 · int() 的两种转换语义：int(str) 严格拒绝 vs int(float) 截断

难度：P5 ｜ 标签：int()、截断、trunc、floor、ceil、字符串解析、静默错值、金额

**问**：`int("3.5")` 报错而 `int(3.5)` 返回 3——同一个 int() 为什么行为不一致？`int()` 对浮点做的是什么截断，与 `math.floor/ceil/trunc` 的区别在哪？`int(-0.5)`、`int(-2.9999)` 各是多少？为什么"金额计算里用 int() 摘要"是事故模式？字符串转整数的严格校验应该怎么做？

**答**：
结论：`int()` 按参数类型走**两套完全不同的转换语义**：①**int(str) 是解析**——只接受"合法整数字面量文本"，`int("3.5")`、`int("3 ")`（内容带小数点）都 ValueError，不接受任何小数部分、不接受千分位逗号，宽容仅限空白与符号——这是"文本→整数"的严格契约；②**int(float) 是数值截断**——向零取整（丢弃小数部分），`int(3.9)`=3、`int(-3.9)`=-3（不是 -4！），且**浮点精度问题会先于截断生效**：`int(2.9999999999999997)`=2（那个值实际比 3 小 1 ULP），`int(0.1+0.2*10)`=1 而不是 2。两套语义的差异就是坑的来源：字符串路径"宁可报错不给错值"，浮点路径"永远给一个值，哪怕不是你要的"——**静默错值比报错危险得多**。与 math 三兄弟的分工：`math.trunc(x)` 与 `int(x)` 等价（都向零）、`math.floor(x)` 向负无穷（`floor(-3.5)`=-4）、`math.ceil(x)` 向正无穷（`ceil(-3.5)`=-3）、`round(x)` 银行家舍入（Q5136）——四个函数四种取整方向，业务语义必须显式选择。

取舍：a) 解析外部文本：`int(s)` + 异常处理是正确姿势，别用 `int(float(s))` 兜底——那会把 "3.7" 静默变 3（对账事故模式）；b) 分摊/分页计算里的"除不尽"：先想清业务要向零、向下还是四舍五入，再选 trunc/floor/round——分页 `ceil(total/n)`、金额分摊 `floor` + 余数分配；c) 浮点→整数前先 `round()` 到预算位数（消除 ULP 级误差）再 trunc，或根本用整数域计算（金额用分）；d) `int(x)` 大数截断仍受浮点表示精度限制（超过 2^53 的整数转 float 再 int 回来会变值）——大整数域别经过 float 中转；e) 严格校验：`s.lstrip("+-").isdigit()` 也不够（Unicode 数字，Q5026），最稳的是 try/int 或 `re.fullmatch(r"-?\d+", s)`（ASCII 语义显式）。

实战：事故形态是"运费计算 `int(weight_kg * 1000 / unit)`，weight 是上游 JSON 浮点，0.3 千克经浮点乘法变 299.99999999999994，int 截断得 299 而不是 300——每单少 1 克计费，月度对账差出数千单；修复为权重以整数克存储、整除用 `//`，浮点入口处 `round(x * 1000)` 显式到预算精度"。下面实测两套语义与四个取整方向。

```python
# int() 的两种转换语义
import math

print("[1] int(str) 是严格解析: 小数点/逗号都拒绝")
for s in ("42", " 42 ", "+42", "3.5", "1,000", "0x1f"):
    try:
        print(f"    int({s!r}) = {int(s)}")
    except ValueError as e:
        print(f"    int({s!r}) -> ValueError: {e}")

print("[2] int(float) 是向零截断: 正负号方向相反于 floor")
for x in (3.9, -3.9, 3.5, -3.5, -0.5):
    print(f"    int({x}) = {int(x)}   floor={math.floor(x)}  ceil={math.ceil(x)}  trunc={math.trunc(x)}  round={round(x)}")

print("[3] 浮点精度先于截断生效: ULP 级误差决定 int 结果")
print("    0.1 + 0.2*10 =", repr(0.1 + 0.2 * 10), "-> int =", int(0.1 + 0.2 * 10), "(期望 2, 得 1)")
v = 2.9999999999999997
print(f"    {v!r} < 3 -> int = {int(v)}  (比 3 小 1 ULP, 截断到 2)")

print("[4] 金额/计量陷阱与整数域修复")
weight_kg = 0.3
grams_float = weight_kg * 1000
print(f"    0.3 * 1000 = {grams_float!r} -> int = {int(grams_float)} (截断丢 1 克)")
print("    整数域: int(round(0.3*1000)) =", int(round(0.3 * 1000)), "| 更好: 上游直接传 300 克")

print("[5] 业务语义显式选: 分页向上取整, 金额分摊向下取整+余数分配")
total, page_size = 103, 20
print(f"    分页数 ceil({total}/{page_size}) =", math.ceil(total / page_size))
amount, parts = 100, 3
base, rem = divmod(amount, parts)
print(f"    分摊 100/3: base={base} rem={rem} -> {[base + (1 if i < rem else 0) for i in range(parts)]} (总和守恒)")

print("[6] 严格校验: try/int 或 ASCII 正则, 而不是 int(float(s)) 兜底")
import re
def parse_int_strict(s: str) -> int:
    if not re.fullmatch(r"-?\d+", s):
        raise ValueError(f"not an ASCII integer: {s!r}")
    return int(s)
print("    parse_int_strict('42') =", parse_int_strict("42"), "| '3.7' ->", end=" ")
try:
    parse_int_strict("3.7")
except ValueError as e:
    print(e)
print("[7] 大整数别经过 float 中转: 超过 2**53 会变值")
big = 2**53 + 1
print("    int(float(2**53+1)) =", int(float(big)), "!= ", big)
```

**追问一**：为什么 `int("3.5")` 报错而 `int(float("3.5"))` 是常见"修复"？这种兜底的真正风险是什么？—— 报错是设计而非缺陷：字符串路径的输入是**自由文本**，"3.5" 到底该 3 还是 4 还是拒绝，只有业务能回答，int() 选择拒绝并把这个决策交还调用方。`int(float(s))` 兜底的真正风险是**替业务做了三个未声明的决定**：①取整方向（向零）；②浮点精度损失（`int(float("299999999999999999"))` 因 float 只有 53 位精度变 300000000000000000）；③校验语义（"1e3"、"nan"、"inf" 也能过 float 这关，`int(float("1e3"))`=1000——业务根本没想到允许科学计数法）。正确分层是：格式校验（正则/isdigit）、业务决策（要不要小数）、显式转换各司其职；兜底只应出现在"已确认文本是小数、且业务明确要截断"的路径上，并配注释说明为什么。

**追问二**：`int(x)` 与 `math.trunc(x)` 完全等价吗？自定义类怎么参与"取整"？—— 数值上等价：`int(x)` 对 float 的行为就是调 `float.__trunc__`，对实现 `__int__` 的对象调 `__int__`（3.8 后 `__trunc__` 优先参与）。区别在**协议与显式性**：math.floor/ceil/trunc 走 `__floor__/__ceil__/__trunc__` 协议，Fraction、Decimal、numpy 标量都实现了各自的取整协议——`int(Decimal("2.5"))`=2 向零、`math.floor(Decimal("2.5"))`=2 一致，但 `round(Decimal("2.5"))`=2（银行家）而 `round(2.5)`=2 但 `round(3.5)`=4——**同一份"取整"意图在不同类型上方向可能不同**。工程纪律：跨类型数值管线（Decimal 金额 ↔ float 统计）里，取整点要集中到一个显式函数（声明方向与精度），禁止散落 int() 调用；这也是"数值边界收口"（Q1563 值域归一化）的一部分。

## 背诵要点
- int(str) 严格解析（小数点报错），int(float) 向零截断（-3.9→-3）；trunc=int、floor 向负无穷、ceil 向正无穷、round 银行家。
- 浮点精度先于截断生效：int(0.1+0.2*10)=1；大整数经 float 中转超 2^53 变值。
- 文本兜底 int(float(s)) 会静默做三个未声明决定（方向/精度/科学计数法）；严格校验用 try/int 或 ASCII 正则。
