### Q5270 · sys.exception：当前正在处理的异常与 except/finally 的作用域

难度：P6 ｜ 标签：sys.exception、异常状态、except、finally、asyncio

基线：CPython 3.12.2，纯标准库；用嵌套 `except`、`finally` 与两个并发协程验证异常状态的保存、恢复与任务隔离。

**问**：统一错误处理函数 `log_current_exception()` 内部用 `sys.exc_info()` 取当前异常，早期在 `except` 块里调用一切正常。后来有人把它移到 `finally` 里做"兜底清理"，日志开始出现大量 `NoneType: None`；另一个服务在 `except` 里 `await` 了一次远程上报，恢复后 `sys.exception()` 拿到的是**另一个任务**的异常，差点把 A 用户的错误写进 B 用户的审计。`sys.exception()` 到底在什么时候有值？嵌套 `except` 退出后会不会恢复外层？`await` 之后还可靠吗？

**答**：

- **结论**：`sys.exception()`（3.11+）返回**当前线程/当前任务正在处理**的异常实例，没有则返回 `None`。它的作用域与 `except` 绑定：进入 `except E as e` 时被设为 `e`；嵌套 `except` 会压栈，内层结束后**恢复外层**；`except` 块结束（正常返回或再次抛出）后清空。`finally` 在异常**向外传播**的过程中执行时，异常仍处于"正在处理"状态，所以 `sys.exception()` 能拿到它；但如果异常已经被某个 `except` 捕获并处理完，再进入后面的 `finally`/普通代码，就拿不到了。它等价于 `sys.exc_info()[1]`，但不构造三元组、语义更明确。
- **取舍**：`except ... as e` 是显式传递，最可靠；`sys.exception()` 适合"深层 helper 不想层层传 `e`"的场景（日志、审计、`__exit__`），但它依赖**隐式线程状态**，调用点必须确认自己仍在异常处理上下文中。`sys.exc_info()` 还会返回 traceback，容易让异常对象/traceback 长时间滞留（循环引用），`sys.exception()` 只给实例，配合 `logging.exception` 更轻。异步场景要特别小心：asyncio 的 Task 在调度时会保存/恢复异常状态，实测同一任务 `await` 后仍能拿到自己的异常；但如果你把逻辑丢到 `run_in_executor` 的另一个线程，或跨任务回调，异常状态不跟随，必须显式传 `e`。
- **实战**：事故一是一段 `try/except/finally`，`except` 里已经 `logger.exception` 处理完，`finally` 又调用 helper，此时异常已被清除，于是打出 `NoneType: None`。修复：helper 增加参数 `exc=None`，在 `except` 里显式传入；`finally` 只做资源清理，不再假设有异常。事故二是 `except` 中 `await` 上报，上报函数内部又触发了别的异常；修复：进入 `except` 后立刻 `exc = sys.exception()` 固定引用，后续所有日志/上报都用 `exc`，不再二次读取全局状态。两处修复后，错误归因错乱归零。

下面验证：无异常时为 `None`、嵌套 `except` 恢复外层、`finally` 传播期可见、处理完后清空、`sys.exc_info()[1]` 同一对象，以及两个并发任务各自保持自己的异常。

```python
# sys.exception: 正在处理的异常, 嵌套恢复, finally 传播期可见, 任务间隔离
import asyncio
import sys

print("[0] 无异常:", sys.exception())
assert sys.exception() is None

seen = {}
try:
    raise KeyError("outer")
except KeyError as outer:
    seen["outer"] = sys.exception()
    seen["outer_ref"] = outer
    try:
        raise ValueError("inner")
    except ValueError as inner:
        seen["inner"] = sys.exception()
    seen["restored"] = sys.exception()
    seen["exc_info_same"] = sys.exc_info()[1]

print("[1] 外层/内层/恢复:", type(seen["outer"]).__name__,
      type(seen["inner"]).__name__, type(seen["restored"]).__name__)
assert seen["outer"] is seen["outer_ref"]
assert isinstance(seen["inner"], ValueError)
assert seen["restored"] is seen["outer_ref"], "内层 except 结束后应恢复外层"
assert seen["exc_info_same"] is seen["outer_ref"]

print("[2] except 结束后:", sys.exception())
assert sys.exception() is None

# finally 在异常传播途中执行, 此时异常仍处于处理中
finally_seen = []
try:
    try:
        raise RuntimeError("propagating")
    finally:
        finally_seen.append(sys.exception())
except RuntimeError as exc:
    seen["finally_exc"] = exc
    print("[3] finally 看到:", type(finally_seen[0]).__name__, "| 捕获:", exc)
assert isinstance(finally_seen[0], RuntimeError)
assert finally_seen[0] is seen["finally_exc"]


async def probe(tag, exc_type):
    try:
        raise exc_type(f"{tag}-error")
    except Exception as exc:
        before = sys.exception() is exc
        await asyncio.sleep(0.01)          # 让另一个任务插入执行
        after = sys.exception() is exc
        return tag, before, after


async def main():
    results = await asyncio.gather(probe("A", ValueError), probe("B", KeyError))
    print("[4] 并发任务异常状态:", results)
    assert all(before and after for _, before, after in results), "任务间异常状态串了"


asyncio.run(main())
print("[5] 结论: 显式 as e 最稳; sys.exception 适合处理上下文内的深层 helper")
```

**追问一**：`sys.exception()` 和 `sys.exc_info()` 该选哪个？—— 只需要异常实例时用 `sys.exception()`：它不创建 `(type, value, traceback)` 三元组，也不会因为元组持有 traceback 而延长对象生命周期；需要类型或 traceback 时用 `sys.exc_info()`（或 `e.__traceback__`）。在日志里不要长期保存 `sys.exc_info()` 的结果，traceback 引用帧、帧引用局部变量，容易把大对象一起留住；如果必须保存，用 `traceback.format_exception` 转成字符串。

**追问二**：在 `except` 里 `raise` 一个新异常，`sys.exception()` 会变成谁？—— 进入新的 `raise` 时，当前异常状态在构造新异常期间仍是旧异常；新异常抛出后，`__context__` 指向旧异常，但在外层 `except` 捕获到新异常之前，`sys.exception()` 的可见值取决于你所在的位置。稳妥的做法是不要在 `raise` 表达式里依赖 `sys.exception()`，而是在 `except ... as e` 里先保存 `e`，再用 `raise New from e` 显式建立链。隐式状态只适合"就地记录"，不适合跨语句推理。

## 背诵要点

- `sys.exception()` 返回当前正在处理的异常，无则 `None`；等价 `sys.exc_info()[1]`，但不构造三元组。
- 嵌套 `except` 结束会恢复外层；`finally` 在异常传播途中能看到异常；`except` 处理完后清空。
- asyncio 同一任务 `await` 后仍保持自己的异常状态；跨线程/跨任务回调不跟随，必须显式传 `e`。

## 复盘追问

- 为什么在 `except` 处理完之后的 `finally` 里调用 `sys.exception()` 会得到 `None`？（异常已被该 `except` 标记为处理完毕，状态清空）
- 把异常对象存进全局列表长期持有，会有什么内存问题？（异常持有 traceback，traceback 持有帧和局部变量，可能拖住整个请求的数据）
