### Q6566 · 备份存储保留策略的成本账

难度：P6 ｜ 标签：备份 / 成本工程 / 存储分层

**问**：数据库 800 GB，每日全量备份 + 全天 binlog 归档，云盘账单里备份存储占第二大头。怎么设计保留策略，既满足合规又不为没人会用的旧备份付钱？

**答**：

**结论**：全量×30 天的裸策略在 800 GB 库上是 ~24 TB 存储起步。正确结构是分层金字塔：高频短档（近 7 天，日全量，热存储，支持快速 PITR）+ 中档（近 8-35 天，每周全量 + 日增量，标准存储）+ 长档（月备 12 份、年备 1-2 份，归档存储/压缩）。分层后同样合规覆盖，存储量降到 ~3-4 TB。第二个杠杆是压缩与去重：备份流 gzip/zstd 压缩率通常 3-5 倍，账要按"压缩后字节数"算。

**取舍**：保留期的唯一约束是合规与恢复场景，不是"越多越安心"：① 恢复场景倒推——误删回滚需要多久前的备份？（大多数事故在 48h 内发现，7 天热备够了）② 合规要求——金融行业数据 5 年，那就放归档层，接受小时级恢复。③ 每月全量链要能独立恢复（不依赖更早的备份），否则"省"出来的增量链断点就是坑。

**实战**：把账做成代码：按保留策略生成备份清单，算每层的存储 GB 与月成本（热/标准/归档单价不同），对比裸策略得出节省；再对"恢复任一天"做可恢复性检查（那天往前找最近全量 + 区间增量是否都在保留期内）。云上还要算跨区复制的流量费：主区备份要不要同步到灾备区？只同步周备可省 80% 流量费。

```python
# 备份保留策略成本账：分层金字塔 vs 裸全量30天
# 仅标准库，Python 3.9+
from __future__ import annotations

HOT, STD, ARCHIVE = 0.023, 0.010, 0.0025  # $/GB/月 量级示例


def monthly_cost(plan: list[tuple[int, float, float]]) -> tuple[float, float]:
    """plan: [(份数, 每份GB, 单价)] -> (存储GB, 月成本$)"""
    gb = sum(n * g for n, g, _ in plan)
    cost = sum(n * g * p for n, g, p in plan)
    return round(gb, 1), round(cost, 2)


def main() -> None:
    db = 800  # GB
    zstd_ratio = 4.0  # 压缩率

    # 裸策略：30 份日全量，热存储，压缩后
    bare_g, bare_c = monthly_cost([(30, db / zstd_ratio, HOT)])
    print(f"裸策略: {bare_g} GB / ${bare_c}/月")

    # 金字塔：7 日全量(热) + 4 周全量(标准) + 12 月备(归档)
    tiered_g, tiered_c = monthly_cost([
        (7, db / zstd_ratio, HOT),
        (4, db / zstd_ratio, STD),
        (12, db / zstd_ratio, ARCHIVE),
    ])
    print(f"金字塔: {tiered_g} GB / ${tiered_c}/月  节省 {1 - tiered_c / bare_c:.0%}")
    assert tiered_c < bare_c * 0.4

    # 可恢复性检查：第 20 天要恢复 → 最近周备(第14天) + 增量？本方案周备间无日增
    # → 演示缺口：第 20 天只能在"第 14 天状态"恢复，8 天 RPO 缺口
    day = 20
    last_weekly = (day // 7) * 7 or 7
    gap = day - last_weekly
    print(f"第{day}天恢复点回退到第{last_weekly}天，RPO 缺口 {gap} 天 → 中档需补日增量")
    assert gap == 6


if __name__ == "__main__":
    main()
```

**追问链**：

- 追问 1：为什么增量链断点比多花钱更危险？——增量恢复依赖链上每一环都完好且未过期；一环被清理或损坏，其后所有恢复点全部作废。所以"全量独立可恢复"是长档的硬要求，增量化只用在热档。
- 追问 1.1：归档存储的取回成本怎么进账？——归档层取回有 per-GB 取回费 + 数小时解冻延迟；账要写"假想一次月备恢复的成本与耗时"，否则真要用时取回费比存一个月还贵。
- 追问 2：跨区同步全量还是只同步关键备份？——账算两边：全量同步的跨区流量费 ≈ 每日备份体积 × 单价 × 30，通常远超备份存储本身；只同步周备+WAL 流，能把灾备区 RPO 保持在分钟级且流量费降一个量级。

**背诵要点**：

1. 分层金字塔（7 日热 / 周备标准 / 月年归档）+ zstd 压缩 3-5 倍，能把 30 天全量裸策略的存储降到 1/6 以下。
2. 增量链只用在热档；长档必须独立可恢复，断链 = 其后恢复点全作废。
3. 账要含归档取回费与跨区流量费；跨区只同步周备 + WAL 可在保分钟级 RPO 下省 80% 流量费。
