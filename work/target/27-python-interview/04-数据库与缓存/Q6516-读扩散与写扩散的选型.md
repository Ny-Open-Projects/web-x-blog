### Q6516 · 读扩散 vs 写扩散

> 难度:★★★ | 标签:Feed 流, 架构, 代价转移

**问**：社交 Feed（关注列表拉时间线）有读扩散（拉的时候聚合）和写扩散（发布时推给所有粉丝收件箱）两种架构——各自的成本曲线是什么？大 V 百万粉丝怎么救（推拉结合），不活跃粉丝的问题怎么处理？

**答**：成本曲线决定选型：① **读扩散**：写一次入库，读时按关注列表聚合 N 个源的时间线（N=关注数，读成本 ∝ 关注数）；写便宜读贵，适合粉丝少、读频率均匀的场景（如 Twitter 早期）。② **写扩散**：发布时写入每个粉丝的收件箱（Redis ZSET/list，写成本 ∝ 粉丝数）；读 O(1) 合并自己收件箱，写贵读便宜——百万粉丝大 V 发一条 = 百万次写，**写放大灾难**。③ **推拉结合（实践主流）**：普通用户发布 → 全推（粉丝量 ≤ 阈值）；大 V 发布 → 只推在线/活跃粉丝，其余**拉**（粉丝读时间线时合并大 V 源在线拉取）；阈值动态调。④ **不活跃粉丝问题**：90 天未登录的粉丝不推（发布时不写他的收件箱），他上线时先拉取回填——「上线回填」是写扩散的标配补救。核心思想：**代价不能消灭只能转移**——读扩散把代价转给读路径（聚合延迟），写扩散转给写路径（发布延迟），推拉结合按流量分布动态转移。

```python
# 全部标准库；demo 实现推拉结合路由与上线回填
import time, collections

class Feed:
    def __init__(self, fanout_threshold: int = 3):
        self.inbox: dict[str, list] = collections.defaultdict(list)   # 写扩散：粉丝收件箱
        self.posts: dict[str, list] = collections.defaultdict(list)   # 原始发布（读扩散源）
        self.followers: dict[str, set] = collections.defaultdict(set)
        self.last_active: dict[str, float] = {}
        self.threshold = fanout_threshold
    def follow(self, fan: str, star: str):
        self.followers[star].add(fan)
    def mark_active(self, user: str):
        self.last_active[user] = time.time()
    def publish(self, author: str, content: str):
        self.posts[author].append(content)
        fans = self.followers[author]
        if len(fans) <= self.threshold:
            targets = [f for f in fans if time.time() - self.last_active.get(f, 0) < 7 * 86400]
            for fan in targets:                       # 小 V：全推（排除不活跃粉丝）
                self.inbox[fan].append(content)
            return f"fanout {len(targets)}"
        online = [f for f in fans if time.time() - self.last_active.get(f, 0) < 7 * 86400]
        for fan in online[:self.threshold]:           # 大 V：只推活跃粉丝
            self.inbox[fan].append(content)
        return f"push {min(len(online), self.threshold)} / rest pull"
    def timeline(self, user: str, followees: list[str]) -> list:
        """读路径：收件箱（已推）+ 在线拉取大 V 源合并。"""
        merged = list(self.inbox[user])
        for author in followees:
            if len(self.followers[author]) > self.threshold:
                merged += self.posts[author][-3:]     # 大 V 走拉（读扩散分支）
        merged.reverse()
        return merged[:20]
    def backfill(self, user: str, followees: list[str]):
        """上线回填：不活跃粉丝上线时从各源拉取重建收件箱。"""
        for a in followees:
            self.inbox[user] += self.posts[a][-5:]

if __name__ == "__main__":
    f = Feed(threshold=3)
    f.mark_active("alice")
    for fan in ("alice", "bob", "carol", "dave"):    # 4 个粉丝 > 阈值 = 大 V
        f.follow(fan, "bigv")
    f.mark_active("bob")                              # bob 在线，dave 90 天未登录
    dave_old = time.time() - 30 * 86400
    f.last_active["dave"] = dave_old
    print("大 V 发布:", f.publish("bigv", "hello"))   # 只推在线活跃粉丝
    tl = f.timeline("bob", ["bigv"])
    assert "hello" in tl
    f.backfill("dave", ["bigv"])                      # dave 上线回填
    assert "hello" in f.timeline("dave", ["bigv"])
    print("推拉结合 + 上线回填全链路 ✅")
```

**追问**：1) 收件箱用 Redis 什么结构、容量怎么控？——ZSET（score=时间戳）取 TopN 截断（用户只看前几百条，更早的走读扩散回溯），`ZREMRANGEBYRANK` 清理超限——收件箱是**有界缓存不是存档**，这是写扩散省内存的关键。2) 推和拉的排序合并怎么做？——各自按时间归并（多路归并），分页游标 = (时间戳, post_id) 复合键；跨「推（收件箱）+拉（源头）」去重用 post_id。3) 为什么不活跃粉丝判定用「上次活跃时间」而不是「最近是否拉取」？——拉取只证明读，活跃时间含互动信号；离线 90 天用户的收件箱写是纯浪费（上线时回填更便宜且能一次补齐）。

## 背诵要点
1. 成本曲线：读扩散写 O(1) 读 ∝ 关注数；写扩散写 ∝ 粉丝数读 O(1)——按流量分布转移代价。
2. 推拉结合：粉丝数 ≤ 阈值全推，大 V 只推活跃粉丝+其余拉；阈值动态。
3. 收件箱 = 有界 ZSET 缓存（TopN+清理）；不活跃粉丝不推，上线回填补齐。
