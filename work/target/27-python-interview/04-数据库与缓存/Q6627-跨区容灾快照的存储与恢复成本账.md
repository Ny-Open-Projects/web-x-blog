### Q6627 · 跨区容灾快照的存储与恢复成本账

难度：P6 ｜ 标签：成本工程 / 容灾 / 快照

**问**：合规要求核心库做跨区容灾，方案是每天做一次全量快照并复制到另一个区。财务一看账单：快照存储每月比数据库实例本身还贵。为什么"每天一份快照"会这么贵？怎么设计保留策略和恢复演练的成本结构？

**答**：
- **结论**：云厂商的快照是**增量链**——每天一份"快照"看起来轻，但计费按"链上仍在引用的所有数据块"算：快照引用的数据块只要被任何一份保留中的快照引用就不删除，保留 30 份快照 × 数据持续增长，存储 ≈ 基线 + 30 天增量总和，随库增长线性上涨；删除单份快照只释放"没有其他快照引用的块"。加上跨区复制流量费（按复制量）与跨区恢复时的取回/出口费，三笔账叠加。降本三板斧：① **降频**——全量快照从每天降到每周，日常靠 WAL/日志归档保 RPO（快照定 RPO 边界，WAL 定 RPO 精度），存储降一个数量级；② **阶梯保留**——7 天日级、5 周周级、12 月月级，总量近似 7+5+12 份而非 30 份；③ **恢复演练单独算账**——每次演练要付跨区取回流量+临时实例费用，按季度排一次并预留预算，不要让人不敢点"恢复"按钮。
- **取舍**：快照复制到冷区（便宜存储区）还是同成本区？冷区单价低但恢复延迟高（取回费+解冻时间），RTO 拉长；合规只要求"异地可恢复"不要求"快速恢复"时选冷区，把热恢复留在同区副本。另一个方向：干脆用流复制跨区备库替代快照链——备库是持续同步，RPO 近零、无复制流量按天计费的问题，但常驻实例费高；"常驻备库 vs 快照链"的成本分界在 RTO/RPO 要求与数据变更率：变更率高时快照链的增量快、备库带宽贵，变更率低时反过来。
- **实战**：① 用"基线 + 保留期内日增量 × 份数"公式估算快照存储，上线前过财务评审；② 保留策略写成 IaC 定时任务（改配置≠改脚本）；③ 每季度演练记录实际恢复时长与费用，把 RTO/RPO 从承诺变成实测值；④ 监控快照链引用块数，异常膨胀（删除未生效）告警。

```python
# 快照链成本账: 存储 = 基线 + 保留份数x日增量; 恢复演练费 = 取回流量+临时实例
# 基线: Python 3.9+ 标准库
from dataclasses import dataclass


@dataclass
class SnapshotPlan:
    baseline_tb: float
    daily_delta_tb: float
    copies: int
    storage_per_tb_month: float   # $/TB/月
    replicate_per_tb: float       # 跨区复制 $/TB (按复制量计费)


def monthly_cost(p: SnapshotPlan) -> float:
    used_tb = p.baseline_tb + p.daily_delta_tb * p.copies
    return used_tb * p.storage_per_tb_month


def replicate_cost(p: SnapshotPlan) -> float:
    # 每日复制增量链(近似日增量), 30 天
    return p.daily_delta_tb * 30 * p.replicate_per_tb


def main() -> None:
    daily = SnapshotPlan(1.0, 0.02, 30, 100.0, 20.0)
    assert abs(monthly_cost(daily) - 160.0) < 1e-9   # 1.0+0.6=1.6TB
    weekly = SnapshotPlan(1.0, 0.02, 4, 100.0, 20.0)
    assert abs(monthly_cost(weekly) - 108.0) < 1e-9  # 1.0+0.08
    assert monthly_cost(weekly) < monthly_cost(daily)
    # 阶梯保留: 7日+5周+12月 近似 24 份且月级多为基础态
    tiered_copies = 7 + 5 + 12
    tiered = SnapshotPlan(1.0, 0.02, tiered_copies, 100.0, 20.0)
    assert monthly_cost(tiered) < monthly_cost(daily)
    print(f"日级30份 ${monthly_cost(daily):.0f}/月 -> 周级4份 "
          f"${monthly_cost(weekly):.0f}/月 + WAL保RPO")
    print(f"OK: 复制费约 ${replicate_cost(daily):.0f}/月按复制量计, "
          f"演练费单独按季度预算")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么删除一份 30 天前的快照不一定会释放存储？
→ 一句话提示：增量链按引用计数，被其他快照共享的块不删；快照账单要按"链总引用块"理解，而不是"每份快照独立大小"。

**追问 2**："快照定 RPO 边界、WAL 定 RPO 精度"是什么意思？
→ 一句话提示：快照链保证"至少能回到某个时点"（最坏 24h 前的完整态），WAL 归档重放把恢复点推进到分钟级；降快照频度必须同步验证 WAL 归档完整性与重放演练，否则 RPO 承诺破产。

## 背诵要点
- 快照存储 = 基线 + 保留份数 × 日增量（引用计数模型），日级 30 份 vs 周级 4 份存储差近 40%。
- 三笔账：链存储 + 跨区复制流量费 + 演练的取回/临时实例费，演练费必须单列预算否则没人敢恢复。
- 快照定 RPO 边界、WAL 定精度：降频前提是 WAL 归档完整且重放演练过；变更率决定"常驻备库 vs 快照链"分界。

## 复盘追问
- 为什么把恢复演练做成"季度例行动作"本身就是成本工程？提示：不演练的容灾是纸面 RTO，一次真实故障的代价远超四年演练费；单列预算消除"不敢点恢复"的组织风险。
- 跨区快照放冷区 vs 同成本区的决策变量是什么？提示：合规对 RTO 的要求——只要"异地可恢复"选冷区省单价，要求小时级恢复则取回延迟不可接受。
