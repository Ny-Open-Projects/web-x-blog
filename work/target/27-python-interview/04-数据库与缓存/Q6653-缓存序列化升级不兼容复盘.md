### Q6653 · 缓存序列化版本升级不兼容复盘

难度：P6-P7 | 标签：Redis、序列化、事故复盘

**问**：把缓存 value 从 pickle+旧 dataclass 换成 msgpack schema 后上线，命中率骤降、DB 回源翻倍、还出现 `UnpicklingError`。错在哪，序列化格式如何安全演进？

**答**：结论：缓存不是"无 schema 存储"——value 里藏着**代码版本耦合**。灰度期内新旧实例共存，旧实例读到新格式（或反之后读旧格式）就反序列化失败；失败常被 except 吞掉当 miss 处理，表现为"命中率下降"而不是报错，掩盖了根因。安全演进三板斧：value 头部带版本字节、写侧只写最新格式+读侧兼容窗口、升级前先做"双格式读"灰度再切换写格式。

实战要点：
1. 头部 1 字节 magic+version，读时按版本分派 decoder；不认识的版本一律回源重建（相当于强制 miss），绝不裸抛。
2. 旧格式下线要有"读不到旧格式"的时间闸门：TTL 一定大于灰度窗口，等旧条目自然过期再删 decoder。
3. pickle 绝不用于跨服务/跨版本缓存（可执行任意代码），用 msgpack/json/protobuf 这类带 schema 的格式。

```python
"""带版本头的缓存 value：读侧兼容窗口（标准库 json 演示，可运行）"""
import json

MAGIC = b"CV1"  # cache value 头

DECODERS: dict[int, callable] = {}


def decoder(version: int):
    def wrap(fn):
        DECODERS[version] = fn
        return fn
    return wrap


@decoder(1)
def _v1(payload: bytes) -> dict:
    return json.loads(payload)  # 旧版：裸 JSON


@decoder(2)
def _v2(payload: bytes) -> dict:
    doc = json.loads(payload)
    return {"name": doc["n"], "price": doc["p"]}  # 新版字段名


def pack(version: int, obj: dict) -> bytes:
    payload = json.dumps(obj, separators=(",", ":")).encode()
    return MAGIC + bytes([version]) + payload


def unpack(raw: bytes) -> dict | None:
    if not raw.startswith(MAGIC):
        return None  # 无头旧数据：视为 miss 回源，不抛异常
    ver = raw[len(MAGIC)]
    fn = DECODERS.get(ver)
    if fn is None:
        return None  # 未登记版本：强制 miss 重建
    try:
        return fn(raw[len(MAGIC) + 1:])
    except Exception:
        return None


cache = {("k1"): pack(1, {"name": "cpu", "price": 100}),
         ("k2"): pack(2, {"n": "gpu", "p": 900})}
for k, raw in cache.items():
    print(k, unpack(raw))
print("unknown ver ->", unpack(MAGIC + b"\x09" + b"{}"))
```

**追问 1**：为什么"吞异常当 miss"比直接报错更危险？
**提示**：它把 bug 转移成容量问题——回源洪峰可能打挂 DB，监控上只看到命中率曲线，没有 traceback。

**追问 2**：如果要回滚这次升级，缓存侧需要什么条件？
**提示**：回滚窗口内写侧仍要能被旧版本读——即新格式必须兼容旧 decoder，或回滚时保留双写。

**追问 3**：msgpack 新增字段旧代码会挂吗？
**提示**：msgpack 按位置/键解码，新增尾字段旧 reader 一般忽略；但**删字段或改字段语义**必挂，所以演进只加不改不删。

## 背诵要点
- 缓存 value 必须带版本头：读侧按版本分派，未知版本强制 miss 回源，绝不裸抛。
- 吞异常当 miss 会把 bug 变成 DB 回源洪峰，命中率下降是它的典型表象。
- 格式演进只加不改不删；TTL 必须大于灰度窗口，旧 decoder 等旧条目过期后再下线。
