### Q6655 · 汇总表预计算与刷新窗口容量账

难度：P6-P7 | 标签：PostgreSQL、容量规划、OLAP

**问**：实时大屏直接聚合 2 亿行明细表，P99 打到 8 秒。打算引入"汇总表预计算"，容量账怎么算——刷新时长、存储增量、陈旧度三者怎么平衡？

**答**：结论：预计算把"读时算力"换成"写时算力+陈旧度"。三笔账：① 刷新账：一次全量重刷时长必须 << 刷新周期（行业经验 <50%），否则任务重叠雪崩；② 存储账：汇总行数 ≈ 维度基数乘积（如 天×渠道×品类 = 365×20×500 ≈ 365 万行/年），可忽略 vs 明细，但多维 cube 会指数爆炸，必须裁剪维度；③ 陈旧度账：业务可接受延迟决定增量（5 分钟增量窗口）还是全量（T+1），数据正确性上增量窗口要处理迟到数据（晚到写入旧窗口）。

实战要点：
1. 优先"时间分片增量"：只重算最近 N 个窗口 + 每天低峰全量对账一次，错峰在凌晨（参见 Q7116）。
2. 刷新写入用 `INSERT ... ON CONFLICT DO UPDATE`（PG）或 `REPLACE INTO`（MySQL）保证幂等，重跑不产生重复行。
3. 用物化视图（PG `REFRESH MATERIALIZED VIEW CONCURRENTLY`）还是自建汇总表？前者省代码但 CONCURRENTLY 需要唯一索引且刷新仍是全量算力；明细过亿时自建增量表更省。

```python
"""汇总表三笔账估算器（标准库，可运行）"""
from dataclasses import dataclass
import math


@dataclass
class RollupPlan:
    days: int = 365
    channels: int = 20
    categories: int = 500
    row_bytes: int = 60          # 每汇总行字节
    refresh_minutes: float = 8   # 一次全量重刷耗时
    cycle_minutes: float = 15    # 刷新周期

    def rows(self) -> int:
        return self.days * self.channels * self.categories

    def storage_gb(self) -> float:
        return self.rows() * self.row_bytes / 1024 ** 3

    def overlap_ratio(self) -> float:
        """刷新时长占周期比例，>0.5 视为高危"""
        return self.refresh_minutes / self.cycle_minutes

    def verdict(self) -> str:
        r = self.overlap_ratio()
        if r > 0.5:
            return f"危险：重刷占周期 {r:.0%}，任务会重叠，改增量"
        return f"OK：重刷占周期 {r:.0%}"


p = RollupPlan()
print("汇总行数:", f"{p.rows():,}")
print("存储:", f"{p.storage_gb():.2f} GB")
print(p.verdict())

# 迟到数据补偿：增量窗口 5 分钟，允许迟到 ≤10 分钟 → 需重算最近 3 个窗口
late_minutes, window = 10, 5
print("增量重算窗口数:", math.ceil(late_minutes / window) + 1)
```

**追问 1**：为什么全量重刷时长不能只"略小于"周期？
**提示**：源表增长会让刷新时长逐年膨胀，80% 水位意味着下个季度就重叠；要留 50% 以下水位与降级空间。

**追问 2**：大屏能不能不用预计算而靠缓存扛？
**提示**：可以组合——汇总表保底 + 缓存挡峰值，但缓存过期回源一次就是一次全量聚合，要预热与单飞（Q1017）。

**追问 3**：增量汇总出现"某渠道当小时数据偏大"怎么定位？
**提示**：先查迟到数据重算窗口是否漏了该小时，再用明细对账 diff 汇总行，通常是窗口边界时区/边界包含问题。

## 背诵要点
- 预计算三笔账：刷新时长 <50% 周期、存储≈维度基数乘积（裁维度防爆炸）、陈旧度决定增全量。
- 增量窗口必须覆盖"迟到数据最大延迟"，用幂等 upsert 保证重跑不重。
- 明细过亿时自建增量汇总表通常优于全量刷物化视图。
