### Q6551 · 云数据库查询成本账：扫描量计费与汇总表改造

难度：P6 | 标签：成本工程、扫描量计费、汇总表、容量规划

**问**：迁到云数据库后账单翻了一倍，DBA 说是"查询变贵了"。云数据库按扫描量计费的机制是什么？为什么一个"每天 288 次的大盘报表"能把账单拉爆？改造的优先级怎么排？

**答**：
- **结论**：云数据库（Aurora、AnalyticDB、BigQuery 思路）按"扫描行数/IO"计费而不是按 QPS——同样的查询在自建机房只耗电，在云上直接烧钱。大盘报表每 5 分钟拉一次明细全表聚合，单次扫描 5000 万行，一个月账单轻松上万倍于"点查+汇总表"方案。改造优先级：先砍"高频 × 全扫"的组合（报表/看板），再处理"低频 × 全扫"（一次性分析任务），点查类基本不用动。
- **取舍**：汇总表要付"新鲜度"代价——预聚合意味着大盘数据延迟一个聚合周期（分钟级）。写成本几乎可忽略（日增 1 万行级别），换来读侧账单下降三个数量级。不要为了省扫描把汇总粒度定太细：聚合周期越短、分桶越多，写入和存储翻着涨，先问业务"大盘数字能接受 1 分钟延迟吗"。
- **实战**：① 上线前守门：报表 SQL 用 EXPLAIN 估算扫描行数，超阈值（如 500 万行）必须改走汇总层或只读副本；② 账单归因：云账单按查询指纹聚类，找出 Top10 扫描大户集中治理；③ 大盘这类"读多写少、聚合口径固定"的场景是汇总表最优解，临时即席分析才交给数据仓库。

```python
"""云数据库查询成本账：扫描量计费模型、汇总表改造与省钱推演。"""
from dataclasses import dataclass

@dataclass
class CloudBill:
    """按扫描量计费的简化账单模型（单位：元 / 百万行扫描）。"""
    price_per_mrow: float = 0.8

    def cost(self, rows_scanned: int) -> float:
        return rows_scanned / 1_000_000 * self.price_per_mrow

ROWS = 50_000_000          # 订单明细表 5000 万行
bill = CloudBill()

# 方案 A：大盘报表直查明细表。按天过滤但没有分区/索引可用，退化为全表扫描
dashboards_per_day = 288   # 每 5 分钟拉一次大盘
scan_a = ROWS * dashboards_per_day
print(f"方案A 单次全扫 {bill.cost(ROWS):.0f} 元，每天 {dashboards_per_day} 次")
print(f"方案A 每月账单 ≈ {bill.cost(scan_a) * 30:,.0f} 元")

# 方案 B：明细点查走索引（每次扫描约 20 行）+ 大盘改读预聚合汇总表（5 万行）
summary_rows = 50_000
point_lookups = 500        # 明细下钻 500 次/天
scan_b = summary_rows * dashboards_per_day + point_lookups * 20
print(f"方案B 每月账单 ≈ {bill.cost(scan_b) * 30:,.2f} 元，"
      f"是方案A的 {(scan_b / scan_a) * 100:.3f}%")

# 汇总表的额外写成本：每分钟增量聚合写入，日增行数与存储可忽略
daily_summary_writes = dashboards_per_day * 50   # 每分钟聚合 50 个分桶
print(f"汇总表日增 {daily_summary_writes / 10_000:.1f} 万行——"
      f"用可忽略的写成本换掉两三个数量级的读账单")
print("守门规则：报表 SQL 上线前估算扫描行数，超过阈值（如 500 万行）必须走汇总层或只读副本")
```

**追问链**：
1. 追问一层：为什么加了 WHERE 条件账单还是没降？——计费看的是实际扫描量不是返回量；过滤条件没有可用的索引/分区时，引擎仍要读完全表再过滤（谓词下推失效），WHERE 只是省了网络传输，不省扫描。
2. 追问二层：只读副本和汇总表怎么选？——副本不减少扫描量，只是把扫描挪到另一台机器并加一份存储费用，适合"查询形态多变、无法预聚合"的场景；汇总表真正消灭扫描，适合"口径固定、高频刷新"的大盘。两者不互斥：大盘走汇总表，下钻明细走副本。

**背诵要点**：
1. 云数据库按扫描量计费：账单爆炸 = 高频 × 全表扫，点查类几乎无感。
2. 改造优先级：先治理"高频全扫"（定时报表），汇总表消灭扫描、副本只转移扫描。
3. 守门：报表上线前 EXPLAIN 估算扫描行数，超阈值强制走汇总层。

**复盘追问**：
1. 月底账单比上月涨 5 倍，第一步查什么？（按查询指纹聚类的账单归因，找 Top 扫描大户，通常是一个新上的定时报表）
2. 为什么"把报表间隔从 5 分钟调到 30 分钟"只能算缓兵之计？（账单线性下降但没改变全扫形态；数据量再涨账单还会回来，根治要消灭扫描本身）
