### Q6637 · 数据库预留实例/包年包月与按量付费的成本分界

难度：P6 ｜ 标签：成本工程 / 容量规划

**问**：数据库实例的计费有按量（小时计费，单价高）和包年包月/预留（折扣 30-60%，但锁定期内不退）。团队同时有稳定基线负载和明显波峰（大促、月末跑批），怎么决定哪些实例转预留、哪些留按量？买多了用不满怎么办？

**答**：
- **结论**：把负载拆成**基线**与**波动**两层：基线层（7×24 恒定在 P20-P30 水位之下的那部分容量）转预留/包年，波动层留按量或弹性伸缩。数学很朴素：设按量单价 P、预留单价 r·P（r≈0.4-0.7），预留保本条件是利用率超过 r——**利用率高于折扣率的实例转预留必然省**；反之留按量。实操口径：对每个实例统计 90 天的"最低小时利用率"，若 `min_util > r`（连最闲的时段都跑在折扣率之上），整台转预留；若只有部分稳定，则买**份额（reserved capacity/资源包）**而非绑实例。风险修正：① 锁定期内业务下线/降配 → 预留变沉没成本，所以只对"确定要活 1 年以上"的核心库转；② 规格变更会使预留失效或需换购，先做规格容量账（Q6546）再买；③ 竞价/抢占实例不适合数据库（中断风险），只适合无状态批任务。
- **取舍**：预留省的钱（30-60%）vs 资金占用与灵活性损失；账要按"承诺折扣率 vs 未来 12 个月负载不确定度"打分——负载预测方差大的团队宁可少买，靠按量+定时启停（Q6615）与 Serverless（Q6570）兜波动。
- **实战**：① 每月跑一次"预留 vs 按量"对账脚本：按实例 ID 拉账单，算 `实际按量成本 × (1-r)` 与已购预留成本比较，偏差 > 10% 触发调整；② 大促波峰实例坚决不预留，用"提前一天升配、活动后降配"的按量策略；③ 多实例同规格时优先买"容量份额"（可漂移给任意实例），比逐实例绑定灵活。

```python
# 预留 vs 按量的保本利用率模型
# 基线: Python 3.9+ 标准库 (r = 预留价/按量价)
from dataclasses import dataclass


@dataclass
class Instance:
    name: str
    ondemand_month: float    # 全按量月成本
    min_util: float          # 90 天最低小时利用率


def decide(inst: Instance, r: float = 0.5) -> str:
    """保本条件: 利用率 > 折扣率 r。min_util 超过 r 说明全时段都该预留。"""
    if inst.min_util > r:
        return f"RESERVE: 省 {1 - r:.0%}"
    if inst.min_util > r * 0.8:
        return "PARTIAL: 买容量份额, 波动留按量"
    return "ONDEMAND: 利用率不足, 预留必亏"


def main() -> None:
    core = Instance("core-order-db", 10_000, min_util=0.62)
    burst = Instance("promo-db", 10_000, min_util=0.12)
    steady_mid = Instance("report-db", 10_000, min_util=0.44)
    assert decide(core, 0.5).startswith("RESERVE")     # 62% > 50%
    assert decide(burst, 0.5).startswith("ONDEMAND")
    assert decide(steady_mid, 0.5).startswith("PARTIAL")
    # 保本等式验证: 预留成本 = ondemand * r, 利用率 u 时
    # 有效成本 = ondemand * r / u, u <= r 时 >= 全按量
    for u, r in ((0.45, 0.5), (0.5, 0.5), (0.8, 0.5)):
        eff = 1 * r / u
        assert (eff >= 1.0) == (u <= r)
    print(f"core: {decide(core)}; burst: {decide(burst)}; "
          f"report: {decide(steady_mid)}")
    print("OK: 保本利用率 = 折扣率 r; 基线转预留, 波动留按量/份额")


if __name__ == "__main__":
    main()
```

**追问 1**：为什么用"最低小时利用率"而不是"平均利用率"做转预留依据？
→ 一句话提示：平均会被波峰拉高，掩盖夜间低谷——预留是全时段锁定的，最低利用率的时段才是决定亏盈的分母；min_util > r 才保证任何时段都不亏。

**追问 2**：容量份额（reserved capacity）和按实例绑定的预留差别是什么？
→ 一句话提示：份额是"买 N 个实例价的额度"，可以漂移套用到任意同规格实例，实例下线额度不浪费；绑定实例则规格变更/下线即失效。

## 背诵要点
- 保本利用率 = 预留折扣率 r（0.4-0.7）：`有效成本 = 按量 × r / 利用率`，利用率低于 r 必亏。
- 决策依据是 90 天**最低**小时利用率（不是平均）；中间地带买容量份额，波动留按量。
- 大促波峰与短生命周期实例坚决不预留；每月跑预留-按量对账，偏差 >10% 调整。

## 复盘追问
- 负载预测方差大的团队为什么宁可少买预留？提示：沉没成本不可退，少买的损失是"差额部分多付 (1-r)"，多买的损失是全额沉没——不对称风险决定保守策略。
- 定时启停（Q6615）与预留怎么组合？提示：稳定常驻层预留 + 波动层按量定时启停，两层账分开算，避免用预留覆盖波动。
