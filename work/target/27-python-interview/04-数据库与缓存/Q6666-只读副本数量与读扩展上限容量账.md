### Q6666 · 只读副本数量与读扩展上限容量账

难度：P6-P7 | 标签：容量规划、主从复制、读写分离

**问**：读 QPS 增长，团队的想法是"读不够就加只读副本"。加副本的容量账怎么算？为什么说副本加到一定数量后是无效扩容？

**答**：结论：加副本解决的是**读 CPU 算力**，但受三重约束封顶：① 主库写入能力——副本的数据流全部来自主库，写 QPS、大事务、DDL 都在主库上；② 复制带宽与单线程回放——一个主库挂太多副本，binlog 下发带宽和每副本的 SQL 回放速度决定延迟，延迟超阈值时该副本必须从读池摘除（Q6646 摘除路由），等于白花钱；③ 连接分发成本——每副本还要复制连接池配置与代理路由。经验上单主库挂 5 个以上副本就该先查"读流量为什么这么大"而不是继续加。

取舍与实战：
1. 容量账的输入：读 QPS × 单查询成本（Q6640 查询单位成本）= 总读 CPU 需求；副本数 = ceil(总需求 / 单副本算力) + 1 台冗余；再校验每副本复制延迟 P99 ≤ 读容忍度（Q2777 按场景标容忍度）。
2. 无效扩容的判定：如果读负载大头是"少数烂 SQL"（全表扫描、无索引 JOIN），副本只是把烂 SQL 复制 N 份执行；先治理慢查询（Q6607 慢查询算力成本）再谈加副本——**治理一条烂 SQL 通常等于白捡一台副本**。
3. 副本拆用途：报表/分析类查询单独挂副本并隔离路由，避免与在线读互相挤压 buffer pool；写为主的业务先扩缓存（Q6663 交叉点账）。
4. 主库才是容量天花板：副本不提供故障转移写能力，主库 CPU/IO 打满时加副本只是延长读的寿命。

```python
"""只读副本数量容量账：算力需求 + 延迟约束双校验（标准库，可运行）"""
import math

def replica_plan(
    read_qps: int, query_cpu_ms: float,   # 单查询平均 CPU 毫秒
    replica_cpu_cap: int,                 # 单副本可承载 CPU 并发折算 QPS 上限
    lag_p99_s: float, lag_budget_s: float,
    slow_sql_share: float,                # 烂 SQL 占读 CPU 比例
) -> dict:
    need_qps = read_qps
    replicas = math.ceil(need_qps / replica_cpu_cap) + 1
    notes = []
    if lag_p99_s > lag_budget_s:
        notes.append(f"[摘除] 延迟 {lag_p99_s}s > 预算 {lag_budget_s}s，"
                     "该副本实际不可用，容量账要按可用数重算")
    if slow_sql_share > 0.3:
        notes.append(f"[无效扩容] 烂 SQL 占读 CPU {slow_sql_share:.0%}，"
                     f"治理后再算：可省 ≈ {replicas * slow_sql_share:.1f} 台副本")
    return {"建议副本数": replicas, "备注": notes or ["[OK] 计划合理"]}

r = replica_plan(read_qps=80_000, query_cpu_ms=3,
                 replica_cpu_cap=25_000, lag_p99_s=1.8,
                 lag_budget_s=1.0, slow_sql_share=0.45)
print(r)
```

**追问 1**：为什么"副本延迟超标摘除"会让加副本的收益打折？
**提示**：容量账里副本数要按"延迟达标可用数"折算；延迟超标的副本承担流量会造成脏读（Q2777），摘除后流量回到其他副本，等效算力没增加。

**追问 2**：半同步复制对这份容量账有什么影响？
**提示**：半同步给写路径加了一份网络确认延迟（写 QPS 上限下降），但降低了主从丢失窗口（Q1415）；它是用写吞吐换 RPO 的参数，入账时要分开列。

## 背诵要点
- 副本数 = ceil(读QPS × 单查询CPU / 副本算力) + 1 冗余，再按复制延迟预算折算可用数。
- 三重封顶：主库写入能力、复制回放延迟、路由成本；5 台以上先查读流量构成。
- 烂 SQL 占读 CPU 30%+ 时，慢查询治理优先于加副本。
