### Q6714 · 不可见索引：下线索引前的灰度开关

难度：P6 ｜ 标签：MySQL 8.0、不可见索引、索引治理、灰度

基线：Python 3.12；MySQL 8.0 invisible index；纯 Python 模拟优化器选择与写放大。

**问**：一张表上有 12 个索引，怀疑其中一个 `idx_city` 早就不用了，但直接 `DROP INDEX` 怕某条低频查询立刻变慢，回滚又要重建（800 万行，几十分钟）。MySQL 8.0 的不可见索引怎么用来安全下线？设成 invisible 后就等于删除吗？

**答**：
- **结论**：`ALTER TABLE t ALTER INDEX idx_city INVISIBLE` 让**优化器看不见**这个索引，但索引仍然存在、仍然随写入维护。这样可以在不改 SQL、不重建索引的前提下观察：如果慢查询/执行计划没有恶化，说明确实没人依赖，再 `DROP`；如果出现回退，`VISIBLE` 一键恢复，秒级回滚。它是"灰度下线"，不是"删除"。
- **取舍**：invisible 期间**写放大还在**（每次 INSERT/UPDATE 仍维护索引），存储也没释放，所以它只解决"读路径是否依赖"的问题，不解决写成本和空间。主键不能设为 invisible；唯一索引设为 invisible 仍会参与唯一性约束（约束不消失）；从库版本低于 8.0 时不识别该属性，DDL 复制可能出问题。
- **实战**：① 先 invisible 观察一个完整业务周期（含月初/月末、定时任务）；② 对比 `performance_schema.table_io_waits_summary_by_index_usage` 的该索引 reads，确认接近 0；③ 观察慢查询新增与 `EXPLAIN` 计划变化；④ 确认无依赖后再 DROP，并在变更单里记录回滚 SQL（重建索引的 DDL）。

```python
def optimizer_choice(indexes: list[dict], query: str) -> str:
    """只考虑 visible 且匹配查询的索引，选估计成本最低者。"""
    candidates = [i for i in indexes if i["visible"] and query in i["covers"]]
    if not candidates:
        return "full_table_scan"
    return min(candidates, key=lambda i: i["cost"])["name"]


def write_cost(indexes: list[dict]) -> int:
    """invisible 索引仍然维护，写成本按全部索引计。"""
    return len(indexes)


if __name__ == "__main__":
    indexes = [
        {"name": "idx_city", "visible": False, "cost": 20, "covers": {"city"}},
        {"name": "idx_status", "visible": True, "cost": 80, "covers": {"status"}},
    ]
    print("查询 city ->", optimizer_choice(indexes, "city"))
    print("写成本(索引数) ->", write_cost(indexes))
    indexes[0]["visible"] = True
    print("回滚 VISIBLE 后 ->", optimizer_choice(indexes, "city"))
    indexes.pop(0)
    print("真正 DROP 后 ->", optimizer_choice(indexes, "city"), "写成本", write_cost(indexes))
```

**追问一**：为什么唯一索引设为 invisible 后，插入重复值仍会报错？
→ 解析：invisible 只影响**优化器的读路径选择**，不改变索引的存在与约束语义。唯一索引的唯一性检查在写入路径执行，与优化器是否可见无关；所以不能用 invisible 来"临时关掉唯一约束"。

**追问二**：`optimizer_switch='use_invisible_indexes=on'` 有什么用？
→ 解析：它让优化器临时把 invisible 索引当可见，用于验证"如果恢复这个索引，计划会不会变好"，或在不改 DDL 的情况下做对比实验。它是会话/全局开关，不是把索引真正变可见，别和 `ALTER INDEX ... VISIBLE` 混淆。
