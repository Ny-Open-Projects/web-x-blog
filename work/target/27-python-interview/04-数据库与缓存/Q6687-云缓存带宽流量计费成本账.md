### Q6687 · 云 Redis 的另一张账单：网络带宽与跨区流量成本

难度：P6 ｜ 标签：成本工程、带宽计费、拓扑优化
基线：云厂商通用计费（公网流量元/GB、跨区/跨可用区流量计费、内网同区免费）。

**问**：Redis 实例包年费用并不高，但月底账单里"网络费用"是实例费的两倍。缓存服务的网络账有哪些构成？哪些架构决策能把它压下来？

**答**：**结论**：缓存是高吞吐低单价的典型——每 GB 数据被反复读，**网络流量成本远超存储成本**。账的四个构成：① 公网/跨区流量单价（最贵，元/GB 级）；② 同可用区内网流量（通常免费）；③ 跨可用区流量（部分厂商计费，主从/哨兵跨 AZ 时持续产生复制流量）；④ 端口费/带宽包月（固定）。压成本的杠杆按收益排序：**搬拓扑**（客户端与 Redis 同 AZ、从库与主库同 AZ）> **压缩 value**（大 value 用压缩序列化，网络侧省 50%+）> **削减冗余读**（客户端缓存/本地 L1 少打 Redis）> **带宽包**（流量包价低于按量）。

**取舍**：压缩与本地缓存都有代价：压缩耗 CPU，且 QPS 很高时压缩的 CPU 成本可能吃掉网络节省；本地 L1 缓存引入一致性问题，失效机制本身又要 Redis 订阅（也产生流量）。同 AZ 拓扑的代价是**可用性**：Redis 与客户端绑在同一 AZ，AZ 故障时一起挂——所以"读路径同 AZ、写路径跨 AZ"的折衷是常见解。

**实战**：带宽账计算与杠杆收益模拟：

```python
# 缓存网络流量成本账：拓扑、压缩、本地缓存三杠杆
QPS, VALUE_KB = 20_000, 4
DAYS = 30
bytes_per_hit = VALUE_KB * 1024
daily_gb = QPS * bytes_per_hit * 86400 / 1e9
print(f"基线：QPS={QPS:,} × {VALUE_KB}KB -> 每日 {daily_gb:,.0f} GB 出流量")

price = {"同AZ内网": 0.0, "跨AZ": 0.15, "公网": 0.8}  # 元/GB 示例
for k, p in price.items():
    print(f"  {k}: {daily_gb*p*DAYS:9,.0f} 元/月")

# 杠杆 1：value 压缩（json -> zstd，按 60% 压缩率算）
compress_ratio = 0.4
save1 = daily_gb * price["跨AZ"] * DAYS * (1 - compress_ratio)
print(f"压缩后跨AZ月费: {daily_gb*compress_ratio*price['跨AZ']*DAYS:,.0f} 元（省 {save1:,.0f}）")

# 杠杆 2：本地 L1 缓存吃掉 80% 的 Redis 读
hit_local = 0.8
save2 = daily_gb * price["跨AZ"] * DAYS * hit_local
print(f"本地缓存省 {save2:,.0f} 元/月，代价：失效订阅流量 + 的一致性复杂度")

# 拓扑账：读路径搬到同 AZ（免费）只留写跨 AZ
write_qps = QPS * 0.05
write_daily_gb = write_qps * bytes_per_hit * 86400 / 1e9
print(f"读同AZ后跨AZ只剩写流量 {write_daily_gb:.1f} GB/日 -> "
      f"{write_daily_gb*price['跨AZ']*DAYS:,.0f} 元/月")

# 压缩的 CPU 代价：zstd 压缩约 100MB/s/核
cpu_cores = daily_gb * 1e9 / 86400 / 100e6
cpu_cost = cpu_cores * 86400 * DAYS * 0.00005 * 730 / 30  # 粗略元/月
print(f"压缩需 ~{cpu_cores:.1f} 核常驻，CPU 成本约 {cpu_cost:,.0f} 元/月 —— 和网络节省对冲")
```

**追问 1**：为什么"客户端缓存（client-side caching）"比本地 L1 更省失效流量？
提示：Redis 6+ 的 client tracking 由服务端主动失效通知，只推失效 key 不推全量，订阅流量远小于自建失效广播；但连接数随客户端实例数增长。

**追问 2**：主从复制流量在账上怎么体现？有什么参数能压它？
提示：全量同步（repl-backlog 不足触发）会产生一次实例级的大流量，监控 `master_repl_offset` 与重连次数；`repl-diskless-sync`、调大 backlog 减少全量重同步。

**追问 3**：带宽包月与按量的分界怎么算？
提示：日流量波动小的稳态负载包月划算，P95 日流量 × 单价对比包月费即可；突发型（营销活动）留按量兜底 + 突发带宽包。

## 背诵要点
1. 缓存成本大头在网络流量而非实例：公网/跨区 元/GB 级、同 AZ 内网常免费——拓扑决定账单下限。
2. 压成本杠杆排序：搬拓扑（读写分 AZ）> 压缩 value > 本地 L1/客户端缓存 > 带宽包。
3. 压缩有 CPU 对冲账：约 100MB/s/核，高 QPS 下先算 CPU 成本再上压缩。
