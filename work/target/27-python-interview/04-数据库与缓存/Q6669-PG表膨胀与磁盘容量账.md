### Q6669 · PostgreSQL 表膨胀与磁盘容量账：dead tuple 不回收的账

难度：P6-P7 | 标签：PostgreSQL、MVCC、容量规划

**问**：PG 的高频更新表磁盘占用一路涨到逻辑数据量的 4 倍，autovacuum 明明在跑。膨胀的容量账怎么算？`VACUUM` 和 `VACUUM FULL`/pg_repack 分别解决什么？

**答**：结论：PG 的 MVCC 更新不覆盖旧行而是**追加新版本（dead tuple）**，普通 autovacuum 只把 dead tuple 标记为可复用空间、**不归还操作系统**——表文件只增不减（HOT 更新与页内复用能省部分）。所以容量账有两个口径：逻辑数据量（行数 × 行宽）与物理占用（含 dead tuple 与空洞），膨胀率 = 物理/逻辑。容量规划按膨胀率上限预留磁盘，更新密集表按 2-3 倍预留是常态。

取舍与实战：
1. 观测先行：`pg_stat_user_tables` 的 `n_dead_tup`、`pgstattuple` 的 `dead_tuple_percent` 是膨胀率事实源；监控按"物理增长速率 > 逻辑增长速率"告警，别只看行数。
2. autovacuum 调参是第一道防线：大表 `autovacuum_vacuum_scale_factor` 默认 0.2 意味着 20% 行变更才触发——大表上等于永不触发，按表覆盖为 0.01-0.05，配 `autovacuum_vacuum_cost_limit` 提速；长事务（Q6575）会卡住 vacuum 的 xmin 冻结，是膨胀失控最常见根因。
3. 归还磁盘要 `VACUUM FULL`（锁全表、需停写窗口）或 pg_repack（在线、需要双倍临时磁盘）。**pg_repack 自身是容量事件**：执行前确认剩余磁盘 > 表大小，否则直接写满盘。
4. 容量账公式：磁盘预算 = 逻辑量 × (1 + 预期膨胀率) + repack 临时空间峰值（≈ 最大单表 × 2）。索引膨胀同理（REINDEX CONCURRENTLY）。

```python
"""表膨胀容量账：膨胀率估算与 repack 磁盘预算（标准库，可运行）"""

def bloat_budget(
    tables: list[tuple[str, int, int]],  # (表名, 逻辑MB, 物理MB)
    expected_bloat: float = 1.0,         # 新表预期膨胀率（增量占比）
) -> dict:
    total_logical = sum(t[1] for t in tables)
    total_physical = sum(t[2] for t in tables)
    worst = max(tables, key=lambda t: t[2] / max(t[1], 1))
    repack_peak = max(t[2] for t in tables) * 2  # pg_repack 临时空间峰值
    return {
        "膨胀率_全库": round(total_physical / max(total_logical, 1), 2),
        "最膨胀表": f"{worst[0]} ({worst[2] / max(worst[1], 1):.1f}x)",
        "repack峰值需求MB": int(repack_peak),
        "磁盘预算MB": int(total_logical * (1 + expected_bloat) + repack_peak),
    }

r = bloat_budget([("orders", 50_000, 180_000), ("events", 20_000, 30_000)])
for k, v in r.items():
    print(f"{k}: {v}")
```

**追问 1**：为什么 autovacuum 跑完 `n_dead_tup` 下降了，磁盘占用却没降？
**提示**：vacuum 只回收页内空间供后续插入复用，不截断文件（除非尾部完全空）；高水位后空闲页散布在文件中部，物理大小不变，只有 FULL/repack 能归还 OS。

**追问 2**：HOT（Heap-Only Tuple）更新为什么能显著抑制膨胀？
**提示**：更新列都不在索引里时，新版本留在同页且索引不用改，dead tuple 在页内被快速复用；fillfactor 与索引设计决定了 HOT 更新比例（pg_stat_user_tables 的 n_hot_upd）。

## 背诵要点
- PG 更新 = 追加 dead tuple；普通 vacuum 复用空间不还磁盘，物理只增不减，磁盘按 2-3 倍逻辑量预留。
- 大表把 per-table `autovacuum_vacuum_scale_factor` 降到 0.01-0.05；长事务卡 xmin 是膨胀失控头号根因。
- 归还磁盘：VACUUM FULL 停写，pg_repack 在线但需峰值 ≈ 最大表 × 2 的临时磁盘——先查余量再执行。
