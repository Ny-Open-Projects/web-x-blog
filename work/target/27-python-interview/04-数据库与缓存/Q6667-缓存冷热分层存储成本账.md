### Q6667 · 缓存冷热分层存储成本账：什么时候该把冷 key 挪出内存

难度：P6-P7 | 标签：成本工程、缓存、分层存储

**问**：Redis 内存账里发现 60% 的 key 一周内访问次数为 0，但 delete 掉又怕哪天被访问。冷热分层的成本账怎么算？分层到 SSD 还是直接降级回源？

**答**：结论：分层的本质是**用便宜的存储承接低频访问的"保险成本"**。账要算三边：内存价（每 GB·月最贵）、SSD/对象存储价（约内存 1/10 - 1/50）、回源价（穿透到数据库的 CPU/IO 折算）。判定式：某类 key 的"访问频率 × 单次回源成本"低于"它迁去便宜层后省下的内存价 + 新层的读写成本"就迁。**多数场景的答案是"直接过期 + 回源重建"而不是建第三层存储**——只有回源本身极贵（重计算/外部 API 计费）时才值得自建 SSD 层。

取舍与实战：
1. 先测访问分布：用 `OBJECT FREQ`（LFU 策略下）或采样统计把 key 分桶：热（日访问 ≥ 10）、温（周访问 ≥ 1）、冷（0）。冷 key 占内存 > 30% 才启动分层项目。
2. 三种承接方案成本从低到高：① 设短 TTL 让其自然过期（省 100% 内存，代价是再来访问时回源一次）；② 序列化迁到对象存储/DB 附表（省内存、取回有几十 ms 延迟）；③ Redis Stack SSD 分层（运维复杂，仅自托管场景）。TTL 方案几乎总是先做。
3. 大 value 优先：冷且大（如 >100KB 的结果缓存）是分层最高 ROI 对象；与 Q6643 大 key 治理、Q1424 maxmemory 瘦身策略衔接——"冷且大优先"同一原则。
4. 命中率口径注意：分层后整体命中率指标会下降，要按"热层命中率"重新设基线，否则误报雪崩。

```python
"""冷 key 分层成本判定：TTL / SSD 层 / 保留内存 三方案比价（标准库，可运行）"""

def tier_decision(
    mem_gb: float,          # 冷 key 占用内存
    mem_price_per_gb: float,   # 内存每 GB·月（元，含实例折算）
    ssd_price_per_gb: float,   # SSD 层每 GB·月
    daily_hits: int,        # 冷 key 总体日访问次数
    rebuild_cost: float,    # 单次回源重建成本（元，含 DB CPU 折算/外部 API 费）
    ssd_read_cost: float,   # SSD 层单次读成本（元）
) -> dict:
    keep_cost = mem_gb * mem_price_per_gb                      # 留内存
    ttl_cost = daily_hits * 30 * rebuild_cost                  # 纯 TTL+回源
    ssd_cost = mem_gb * ssd_price_per_gb + daily_hits * 30 * (rebuild_cost + ssd_read_cost)
    best = min(("TTL+回源", ttl_cost), ("SSD分层", ssd_cost), ("留内存", keep_cost),
               key=lambda x: x[1])
    return {"留内存月成本": round(keep_cost), "TTL月成本": round(ttl_cost),
            "SSD月成本": round(ssd_cost), "建议": best[0]}

# 200GB 冷 key，日访问仅 5000 次，回源一次折算 0.02 元
r = tier_decision(200, 40, 0.8, 5000, 0.02, 0.0001)
for k, v in r.items():
    print(f"{k}: {v}")
```

**追问 1**：为什么"回源重建成本"里要计入雪崩放大风险？
**提示**：TTL 方案在冷 key 被批量重新访问（营销活动重启）时会产生集中回源，单次重建成本要乘并发放大系数，必要时配 singleflight（Q1017）与预热（Q1419）。

**追问 2**：LFU 策略下 `OBJECT FREQ` 读到的频次为什么不能直接当访问分布？
**提示**：它是衰减计数（对数计数器），反映近期相对热度；分布统计要用抽样命令或客户端埋点做绝对口径，二者混用会误判分层名单。

## 背诵要点
- 三边账：内存价 vs 便宜层价 vs 回源价；冷 key 日均访问 × 回源成本 < 内存摊销即迁。
- 方案优先级：短 TTL 自然过期 > 对象存储承接 > SSD 分层；冷且大优先治理。
- 分层后监控口径改为热层命中率，防止误报雪崩。
