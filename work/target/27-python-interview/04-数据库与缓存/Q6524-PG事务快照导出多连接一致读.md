### Q6524 · PG 事务快照导出：多个连接怎么读到同一个一致性视图？

> 难度:★★★★ | 标签:PostgreSQL, MVCC, 一致性

**问**：要做"一次导出：订单表、支付表、库存表三张表按同一时刻口径对账"。三张表很大，单连接串行查要 20 分钟，想并行跑三个连接。但 REPEATABLE READ 只保证"单个事务内"一致，怎么让三个**独立连接**看到同一时刻的数据？

**答**：结论：用 PG 的快照导出机制——主连接 `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ` 开启只读事务后 `pg_export_snapshot()` 拿到快照标识，其他连接在事务开始后 `SET TRANSACTION SNAPSHOT '...'` 导入同一快照，三个连接从此读到同一个 MVCC 版本线，互不看到彼此之后发生的提交。这是 `pg_dump --jobs` 并行导出的底层原理。

取舍与实战：
- 前提：`default_transaction_isolation` 或显式声明必须是 repeatable read / serializable；read committed 下导入快照会被拒绝，因为每个语句都拿新快照，导入没有意义。
- 生命周期：导出快照的主事务必须**保持打开**，直到所有导入连接完成工作——主连接退出则快照失效，其他连接会报 `ERROR: snapshot ... does not exist`。所以主连接的角色是"锚点"，只持有事务不干活。
- 取舍：REPEATABLE READ 并行事务读的是历史版本，长事务会阻碍 vacuum 回收 dead tuple，大表导出期间膨胀监控要盯着；导完立刻提交，别让锚点事务挂到天荒地老。MySQL 没有等价语法（`START TRANSACTION WITH CONSISTENT SNAPSHOT` 只限单连接），跨连接一致读通常靠 `mysqldump --single-transaction` 的 master position 记录。

```python
# 基线:Python 3.9+ / psycopg2 2.8+ / PostgreSQL 9.2+(快照导出) ;缺库降级见末尾
try:
    import psycopg2
    HAS_PG = True
except ImportError:
    HAS_PG = False

def consistent_parallel_read(dsn: str, queries: list[str]) -> list[list[tuple]]:
    """主连接导出快照,N 个并行连接导入同一快照各自查询。"""
    anchor = psycopg2.connect(dsn)
    anchor.autocommit = False
    cur = anchor.cursor()
    cur.execute("SET TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY")
    cur.execute("SELECT pg_export_snapshot()")
    snap_id = cur.fetchone()[0]           # 形如 '00000003-0000001B-1'

    results: list[list[tuple]] = [[] for _ in queries]
    workers = []
    try:
        for i, q in enumerate(queries):
            def work(idx=i, sql=q):
                conn = psycopg2.connect(dsn)
                try:
                    c = conn.cursor()
                    c.execute("SET TRANSACTION ISOLATION LEVEL REPEATABLE READ")
                    c.execute("SET TRANSACTION SNAPSHOT %s", (snap_id,))
                    c.execute(sql)
                    results[idx] = c.fetchall()
                finally:
                    conn.close()          # 只关连接,事务未提交即回滚
            import threading
            t = threading.Thread(target=work)
            t.start()
            workers.append(t)
        for t in workers:
            t.join()
    finally:
        anchor.commit()                   # 快照锚点最后释放
        anchor.close()
    return results

def demo_standard_lib() -> None:
    """缺 psycopg2 时模拟快照语义:同快照读同版本,无快照各读各的。"""
    version_clock = [0]

    class SnapDB:
        """带版本历史的简化 MVCC:写入记版本线,快照读只看 <=snap 的版本。"""
        def __init__(self) -> None:
            self.history: dict[str, list[tuple[int, int]]] = {"pay": []}
        def begin_snapshot(self):
            version_clock[0] += 1
            return version_clock[0]            # 导出当前版本线
        def write(self, key: str, value: int):
            version_clock[0] += 1
            self.history[key].append((version_clock[0], value))
        def read(self, key: str, snap: int):
            visible = [v for ver, v in self.history[key] if ver <= snap]
            return visible[-1]                 # 快照时刻的最新版本

    db = SnapDB()
    db.write("pay", 100)
    snap = db.begin_snapshot()
    db.write("pay", 500)                       # 锚点之后其他事务提交
    assert db.read("pay", snap) == 100, "导入快照的连接读到的仍是导出时刻版本"
    print("模拟通过:快照读者不受后续提交影响 ->", db.read("pay", snap))

if HAS_PG:
    import os
    if os.environ.get("PG_DSN"):
        rs = consistent_parallel_read(os.environ["PG_DSN"],
                                      ["SELECT count(*) FROM orders",
                                       "SELECT count(*) FROM payments"])
        print("两个并行连接读数:", rs)
    else:
        demo_standard_lib()
else:
    demo_standard_lib()
```

**追问一**：导出快照后，锚点事务一直开着 20 分钟，有什么代价？
答：REPEATABLE READ 长事务使 vacuum 无法回收这期间产生的 dead tuple，膨胀集中在被读的大表上；且 `max_connections` 被占一个。对策：导出窗口选低峰、给 pg_stat_activity 加告警监控 `xact_start` 超过 30 分钟的只读事务。

**追问二**：导入快照的连接自己要不要也 READ ONLY？
答：可以写（REPEATABLE READ 可写），但并行的对账导出场景没有理由写；显式 `READ ONLY` 是给执行器优化的提示，也能防止误写破坏一致性口径。

**背诵要点**：
- `pg_export_snapshot()` + `SET TRANSACTION SNAPSHOT`：多个独立连接共享同一 MVCC 版本线。
- 锚点事务保持打开到所有导入方完成，退出即快照失效。
- 需要 REPEATABLE READ 及以上隔离级别；长快照阻碍 vacuum，注意膨胀与连接占用。

**复盘追问**：
- 为什么 READ COMMITTED 下导入快照没有意义？

## 背诵要点
- 跨连接一致读靠快照导出/导入，pg_dump 并行导出即此原理。
- 锚点事务是快照生命周期，先关锚点必报 snapshot does not exist。
- REPEATABLE READ 长事务的代价是 vacuum 膨胀，导出后立即提交。
