### Q6592 · 连接归还时的状态复位：reset_on_return 与会话变量污染

> 难度:★★★★ | 标签:连接池, SQLAlchemy, 会话状态

**问**：某接口改了会话时区/锁了行才 `return`，下游接口复用同一条连接后行为诡异。连接池归还连接时到底做了什么复位？"轻量复位"和"完整回滚"差别在哪、什么时候必须用后者？

**答**：结论：连接池每次归还默认做一次"复位"，SQLAlchemy 的 `create_engine(..., pool_reset_on_return='rollback')` 默认发 `ROLLBACK`——只回滚**未提交事务**，不动已提交的会话级状态（`SET` 过的时区/search_path、advisory lock、临时表、用户变量）。所以"事务干净"≠"连接干净"。凡是接口里执行过会话级 `SET`、`pg_advisory_lock`、`CREATE TEMPORARY TABLE`、`LISTEN` 的，归还时残留都会污染下一个借用者；要么归还前显式还原，要么把这类连接放"专用池/不复用"。

复位等级与选型：
- `rollback`（默认）：开销最小，只管事务边界；适合"业务从不碰会话级状态"的常规服务。
- `commit`：归还即提交——**危险**，会把本该回滚的半截事务悄悄提交，仅限明确"自动提交语义"的队列消费者。
- `none` + 应用自管：性能最好但要求每条路径 `finally` 里自清，事故率高，只给"连接即租约、用完即弃"的专用场景。
- 重型复位：连接级 `DISCARD ALL`（PG）或重连（`pool_recycle` 频繁化）——彻底干净但每次归还多一次往返，常规池承受不起，只在专用池（跑外部脚本、临时查询）用。
- 事故复盘：某报表服务在连接上 `SET timezone='UTC'`，归还后同一连接被订单服务借走，时间字段整体偏移 8 小时。修复：报表侧改 `SET LOCAL`（事务作用域），并把全局"禁止会话级 SET"写进 code review 清单。

```python
# 基线:Python 3.9+ 标准库;模拟池的借还与两级复位差异
class Conn:
    def __init__(self) -> None:
        self.tx_open = False
        self.session_vars: dict[str, str] = {}

    def set_session(self, k: str, v: str) -> None:  # 会话级 SET(危险)
        self.session_vars[k] = v
    def set_local(self, k: str, v: str) -> None:    # 事务级 SET LOCAL(安全)
        if not self.tx_open: raise RuntimeError("SET LOCAL 必须在事务内")
        self._local = {k: v}

class Pool:
    def __init__(self, reset: str = "rollback") -> None:
        self.free: list[Conn] = []
        self.reset = reset

    def release(self, c: Conn) -> None:
        if self.reset == "rollback" and c.tx_open:
            c.tx_open = False                        # 只回滚未提交事务
        self.free.append(c)                          # 会话变量原样残留!

def checkout(pool: Pool) -> Conn:
    return pool.free.pop() if pool.free else Conn()

if __name__ == "__main__":
    p = Pool()
    c1 = checkout(p)
    c1.tx_open = True
    c1.set_session("timezone", "UTC")                # 报表服务设置的残留
    c1.set_local("tz", "UTC") if c1.tx_open else None
    p.release(c1)
    c2 = checkout(p)
    print("事务状态:", c2.tx_open, "| 会话变量残留:", c2.session_vars)
    assert c2.tx_open is False and c2.session_vars.get("timezone") == "UTC"
    print("=> 默认复位只清事务,不清会话级 SET;防御:SET LOCAL 或专用池")
```

**追问**：
- 一层追问：为什么默认是 rollback 而不是 DISCARD ALL？——池的存在意义就是省去连接建立的握手/认证开销，每次归还都全量清场等于把池白搭；默认档位是"概率最高的事故（未提交事务）"与"开销"的折中。
- 二层追问：怎么系统性发现"谁在污染连接"？——PG 侧 `pg_stat_activity` 带 `application_name` + 审计 `SET` 语句（log_statement='mod' 采样），或 SQLAlchemy 事件 `checkout` 时打标签比对期望状态；根治靠规范：会话级语句进白名单评审。
- 三层追问：pool_pre_ping 和 reset 是一回事吗？——不是。pre_ping 是**借出前**探活（防陈旧连接），reset 是**归还时**清场（防状态残留）；一个面向"连接还活着吗"，一个面向"连接还干净吗"，两个都要有但别混谈。
