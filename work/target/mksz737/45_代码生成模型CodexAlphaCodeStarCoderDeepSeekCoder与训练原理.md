# 45. 代码生成模型：Codex / AlphaCode / StarCoder / DeepSeek-Coder 与训练原理

## 纲要

- **商业工具**：Cursor（基于 Codex，月费 $20，无限 GPT-4/3.5）、GitHub Copilot、Codeium（免费+问答+重构）、Codium（问答专注编程）。重度编程选 Cursor/Copilot，学生党可用免费或私有化部署模型。
- **开源代码模型**：StarCoder、DeepSeek-Coder、CodeShell、CodeGeeX、CodeLlama（基于 Llama 训练，原 Llama 仅 5% 代码）、AlphaCode（41B，100% 代码训练）。
- **训练原理**：海量代码数据集（如 The Stack，约 180GB / 200 亿文件）→ Tokenizer 切片 → 初始化模型（常基于 GPT-2 等）→ 训练循环（多 GPU）→ 评估（用新验证集横向比）。
- **关键超参**：temperature（随机性）、top_p（核采样）、max token（单次回复长度）、frequency penalty（降重复）。
- **选型启示**：模型参数越多性能越好（通用结论）；专家调优（数据/参数质量）带来能力跃迁；评估要用模型未见过的验证集才公平。

> 本章按课程口径重构；模型名词已规范化；剥离营销与课程群引流。

## 一、商业代码工具横向

- **Cursor**：基于 Codex，编辑器体验优秀、生态完善（兼容 VSCode 插件市场）；月费 $20 可无限用 GPT-4 与 GPT-3.5（高速 GPT-4 额度用完后转慢速但不影响使用）。重度编程首选。
- **GitHub Copilot**：讲师长期使用两年，内测即上手；惊艳但绘图式交互体验不如 Cursor，最终因依赖绘图编码习惯而转 Cursor。
- **Codeium / Codium**：免费或低门槛；Codium 提供编程问答、一键重构函数，集成度高。

## 二、开源代码大模型

- **代表**：StarCoder、DeepSeek-Coder、CodeShell、CodeGeeX、CodeLlama、AlphaCode。
- **架构分布**：多数代码模型是 Decoder-only（录入知识后依大模型参数生成代码理解）；少数谷歌系（如 T5）为 Encoder-Decoder，翻译语言能力（如 C→C++/Java）更强。
- **数据占比影响表现**：CodeLlama 基于 Llama（原仅约 5% 代码），表现一般；紫色标记（代码数据多）的模型代码能力更强。AlphaCode 为 100% 代码训练、41B 参数（约 410 亿）。
- **爆发时点**：2020 年 GPT-2/3 惊艳后，代码大模型如雨后春笋；规模从 100M 到 10B 再到 100B+ 指数上升。

## 四、代码模型训练原理

- **数据集**：如 Google BigQuery 取 The Stack（约 180GB、200 亿文件）；分析发现 0.1% 独特文件占 15% 体量、1% 占 35%、10% 占 66%——大量代码高度重复（复用库/工具类/类型转换）。
- **Tokenizer + 初始化模型**：把代码切片（token），用已有模型（如 GPT-2）初始化以保留旧知识、在新数据上训练。
- **训练循环（Training Loop）**：多 GPU 反复训练验证，神经网络机制引入随机性（带来「创造力」），故需多轮调参（「炼丹」）。
- **评估**：用「问题+答案」验证集与其他同级模型横向比，看生成代码能否通过测试；**尽量用模型未见过的验证集**，否则易因训练集偏差而失真。

## 五、关键超参与调优

- **temperature**：控制随机性/创造力。
- **top_p（核采样）**：与随机性类似，控制候选词范围。
- **max token**：单次回复最大 token 数。
- **frequency penalty**：越高越降低重复输出词的频次。
- **学习率随模型增大而减小**：专家提供的参数/数据虽小，却能撬动大模型输出方向（如 RLHF 强化学习调优）。

## 六、FAQ

**Q1：Cursor 和 Copilot 怎么选？**
重度编程、要绘图式交互选 Cursor；依赖 VSCode 生态、要集成度选 Copilot；预算有限用 Codeium/Codium 或私有化模型。

**Q2：代码模型为什么大多 Decoder-only？**
录入知识后依大模型参数生成代码理解，训练与推理简单高效；需强翻译能力（跨语言）才用 Encoder-Decoder。

**Q3：训练代码模型为什么要清洗数据？**
原始代码大量重复（复用库/工具类），清洗后灌入模型才能学到有效特征，而非记忆冗余。

**Q4：评估模型为什么要用未见验证集？**
避免训练集偏差导致「自家模型在自己数据上虚高」，横向比较才公平可信。

## 七、面试高频问答

**1. 代码大模型的主流架构与代表有哪些？**
Decoder-only 为主（CodeLlama、StarCoder、DeepSeek-Coder），Encoder-Decoder 少量（T5 系）；代表含 Codex、AlphaCode（41B）、Copilot 背后模型。

**2. 简述代码模型训练流程。**
取海量代码数据集 → Tokenizer 切片 → 基于已有模型初始化 → 多 GPU 训练循环（含随机性）→ 用新验证集横向评估。

**3. temperature / top_p 有什么作用？**
控制生成随机性与候选范围；越高越有创造力但越易偏离，越低越确定越易重复。

**4. 为什么 RLHF/专家调优能小撬大？**
专家提供的高质量参数/数据占比虽小，却可引导大模型输出方向；模型增大后学习率减小，微调影响相对显著。
