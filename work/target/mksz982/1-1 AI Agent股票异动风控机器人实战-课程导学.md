# 1-1 AI Agent 股票异动风控机器人实战 · 课程导学

AI 技术近几年的迭代速度远超预期，正在重构金融、电商、制造等行业的作业方式。开发者和企业也都意识到，单点调用一个大模型并不能解决业务问题，真正能产生价值的是把大模型编排进系统、让智能体（Agent）承担「感知-决策-执行」的闭环。但在实际落地时，绝大多数团队卡在同一个地方：知道 AI 很强，却不知道如何用 Java 工程化地把一个 Agent 跑在生产环境里、把它的能力接到数据库、行情源和消息推送链路上。

正是围绕这一缺口，本课程以 **Spring Boot + Spring AI** 为基座，带你从零做出一个**股票异动风控机器人**：它持续监测股票异动，用规则引擎做风险判定，再通过钉钉 / Telegram 机器人把结论推送给用户，并对外以 MCP 工具的形式开放查询与分析能力。学完之后，你拿到的不是一段演示脚本，而是一套可迁移到任意行业的「代码 + AI + 智能体」落地范式。

## 【学习目标】

读完本节，你应该能够：

1. 说清「代码 + AI + 智能体」三者结合的工业价值，以及它和纯拖拽式工作流平台的本质区别。
2. 在大脑里画出本项目的三层架构（SpringBoot 服务层 / 股票信息数据库 / SpringAI MCP Server），并指出每一层承担的工程职责。
3. 解释本项目「数据采集 → 数据存储 → AI 工具处理」的端到端链路，以及为什么用 MCP 把能力开放出去。
4. 对照自己的技术栈，确认学习前置（Java / Spring / MyBatis / MySQL / Maven）是否就绪，并规划后面十几节要亲手搭的工程模块。

## 【正文】

### 一、为什么是「代码 + AI + 智能体」

很多同学第一次接触智能体，是通过 Coze、Dify 这类「低代码 / 无代码」平台：拖几个节点、连一条工作流就完事。这能快速验证想法，但有两个天花板无法逾越：

- **能力边界受平台约束**：平台给你什么节点，你才能用什么；一旦要对接私有行情接口、私有数据库、内部鉴权，平台往往无能为力。
- **工程可演进性差**：工作流的版本、测试、灰度、监控都依赖平台，出了生产事故很难用代码手段止血。

真正能工业落地的方向，是**把代码、AI、智能体三者放在一起**：用 Java 工程承载确定性逻辑（数据入库、规则判定、消息推送），用大模型承载不确定性的语义理解与编排，用 Agent 把二者串成可自主决策的闭环。举一个硬件侧的例子，假如要做一台能对话的实体机器人，光靠拖拽平台显然不够，回归「代码驱动模型、模型驱动工具、工具反哺代码」这条路才是正解。纯平台的热度会波动，但「代码 + AI」的基建能力只会越来越值钱。

### 二、本项目的两个目标

开发这套课程，目标分两层：

1. **以学习为主**：掌握 Spring AI 的开发模式，理解 Agent 如何在工程里被构建，并学会把某项业务能力封装成工具、再集成进外部 AI 客户端（Cursor、Cherry Studio 等）协同工作。
2. **以变现为辅**：项目本身具备两种商业化路径（课程内逐一拆解）。需要强调的是，这套监测能力在三个月前已经投入生产并产生利润，所以本章所有代码都不是纸面练习，而是经过真实流量验证过的工程。

### 三、项目全景架构

整个系统由三个部分组成，数据从采集侧流入、经 AI 能力侧处理后对外暴露：

```mermaid
flowchart LR
    subgraph APP[SpringBoot 服务层]
        M1[股价异动监测]
        M2[百度实时翻译]
        M3[钉钉机器人]
    end
    subgraph DB[(股票信息数据库)]
        D1[(监测与处理结果)]
    end
    subgraph MCP[SpringAI MCP Server]
        T1[工具模块集]
    end
    APP -->|写入/读取| DB
    APP -->|封装能力| MCP
    MCP -->|向工作流平台/外部AI/企业内部系统开放| EXT[外部调用方]
    APP -->|实时推送| PUSH[钉钉 / Telegram 机器人]
```

由此形成「数据采集与处理 → AI 能力开放与应用」的一体化架构。其中三大主模块是：

- **Spring 模块的股价异动监测**：核心风控逻辑所在，负责周期性扫描行情、触发规则判定；
- **百度实时翻译**：课程抓取的原始资讯大量为英文（如融资、订单、合股类消息），需先翻译为中文再与用户交互；
- **钉钉机器人**：课程默认讲解的推送通道，把风险结论实时发到群。Telegram 与微信机器人作为扩展项一并给出代码，但讲解以钉钉为主。

整个架构打通了「数据采集 → 数据存储 → AI 工具处理」的全流程，具备良好的扩展性与对外接口能力。

### 四、生产实战案例

先看几个真实监测到的数据形态（课程中会以脱敏方式复盘）：

- 某支股票在我们库里持续检测到异常波动，价格从 3 元起步，一周内一路涨到 400 多元。这类非稀释性融资往往支撑上涨趋势，如果是稀释性融资，股价反而可能承压。
- 案例「比一」：上午 9 点半接触到相关信息（传两家公司明年共同投资），当天股价从 6 元涨到 45 元，单日涨幅 40 元。
- 案例「欧尔口」：监测到第一条投资 / 融资报道时，结论直接打印在 IDEA 控制台、未入库，当天股价大涨 100 元；后续新闻跟进，又涨 10 元。

这些原始内容多为英文。课程里结合百度翻译模块做汉化，最终呈现给用户的都是中文。上面的形态是 Telegram 机器人的输出；课程主讲解钉钉机器人的交互方式，但交互载体可自由替换或定制。

> 工程启示：生产系统里「原始数据 → 翻译 → 入库 → 判定 → 推送」每一步都要有幂等和落库设计，不能像「欧尔口」案例那样只打印到控制台，否则后续无法复盘与告警。这也是 982-demo 把行情落库、用 `RiskEvaluationService` 统一编排的原因。

### 五、课程核心：以智能体为中心

本课程的灵魂是围绕**智能体**构建。在完整 AI 闭环里，我们用一个「大脑」承载语义理解与编排，通过 **MCP** 扩展外部工具，从而连通数据库读写、业务逻辑调用；再通过聊天工具里的机器人完成实时消息推送，让智能体能及时响应外部请求。这套「三角联动」机制，是项目能持续生产的关键。

通过课程，你将掌握：架构设计能力、MCP 工具开发、自动化推送、机器人与系统的交互、企业级配置管理与中台化建设能力。

### 六、核心开发流程

完整开发链路如下，每一步都由你亲手构建：

1. **搭建项目架构**：基于 Spring Boot / Spring AI。
2. **股票异动数据采集与入库**：分阶段把实时数据写入数据库。
3. **翻译模块集成**：新抓取的英文数据先翻译为中文，再与用户交互。
4. **机器人集成**：以钉钉为例，实现用户交互与实时消息推送。
5. **开发 MCP 服务与工具**：把服务开放给外部 AI 工具，支持自定义工具、数据库查询、数据分析。

每个环节都是自己一步步搭起来的，没有现成平台替你屏蔽复杂度。

### 七、学完你能获得什么

- **企业级智能体落地方法**：从需求分析、系统设计到开发运行，打造可投入商业应用的 AI 智能体全流程。
- **可持续运行的监测体系**：通过统计分析与异动算法，建立稳定且可扩展的数据处理机制。
- **Spring AI 与 MCP 的结合运用**：让业务能力通过 MCP 工具连接大模型，实现自然语言驱动的业务逻辑。
- **AI 与传统业务的深度融合**：让人工智能真正参与查询、分析、决策、执行，而不是做一个玩具。
- **可复用、可变现的架构模板**：它不止是本课项目，更是一套能迁移到其他行业的通用智能体解决方案。

### 八、前置基础储备

- 具备 **Java** 基础，了解 **Spring**、**MyBatis**、**Spring Boot**；
- 数据库使用 **MySQL**（熟悉 PostgreSQL 等价可替换，框架本身不绑定具体库）；
- 基本命令行操作（不会也只需跟随步骤即可）；
- 项目基于较新版本 **OpenJDK** 与 **Maven** 构建，建议使用新版工具链。

完整可部署的闭环示例见 `982-demo/`：`provider`（行情接入）、`engine`（规则判定）、`service`（`RiskEvaluationService` 编排感知→决策）、`scheduler`（`RiskScanScheduler` 周期扫描）、`controller`（`/api/risk` REST）与 `agent`（`RiskQueryAgent`）共同复刻了本节的「监测→判定→推送」架构，且 `default` profile 离线 OfflineChatModel 即可跑通主流程。

## 【易错点 / 面试题】

1. **面试题：低代码工作流平台和「代码 + AI」工程化方案，生产里怎么选？**
   答：前者适合快速验证、单点场景；后者适合要对接私有数据源、需要版本管理 / 测试 / 监控 / 灰度、且能力要持续演进的生产系统。本课程选择工程化，因为风控机器人要连私有行情、私有库和内部推送链路。

2. **易错点：把监测结论只打印到控制台而不落库。**
   像「欧尔口」案例那样只 `System.out` 打印，无法事后复盘、无法触发规则告警。正确做法是行情进 `QuoteProvider.nextTicks()` 后即落库，再由 `RuleEngine` 统一判定。

3. **面试题：为什么用 MCP 把能力开放出去，而不是直接写 REST？**
   答：MCP 把「工具描述 + 参数 schema」标准化，大模型客户端（Cursor、Cherry Studio）能自动发现并调用，无需为每个前端手写对接代码；同一套 `@Tool` 方法既可挂给 `ChatClient`，也可暴露为 MCP Server 工具。

## 【小结】

本节确立了课程的定位、架构与价值坐标：它不是教你怎么拖一个工作流，而是教你用 Spring Boot + Spring AI 把「代码 + AI + 智能体」真正跑在生产里。下一节起进入环境搭建与工程脚手架，随后你会亲手把五大开发步骤逐个落地，其中 MCP 工具的编写（第 10 节）与 Cherry Studio 接入（第 11 节）会回扣本节提到的「AI 能力开放」设计，而 `982-demo` 则是这套架构的可运行最小闭环，建议在读完第 10 节后对照阅读。
