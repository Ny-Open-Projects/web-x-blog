# 后端校招面试直通车: 基础算法与搜索的本质

## 纲要

- 计算机擅长"规则明确、具象"的问题，人类擅长"抽象、不规则"的创造性问题
- 搜索的本质：利用计算机的高性能，有目的地穷举问题的全部或部分可能，从而找到解
- 求解空间：有限空间 + 明确的有步骤的求解过程 → 正确结果集（空间的子集）
- 搜索在形式上等价于"构造一棵解答树，并寻找符合目标状态的节点"
- 朴素搜索无处不在：两数之和的枚举、解方程的遍历、三数之和的三层遍历、二叉树路径总和的前序遍历
- 搜索的两种细分方法：深度优先搜索（DFS）与广度优先搜索（BFS）

## 计算机适合解决哪类问题

计算机与人类的能力边界不同：

- **人类擅长**：创作型、强调整体意境与意义的工作，例如创作油画、写作小说。这些问题的规则不明确、不具象，难以用确定的步骤描述。
- **计算机擅长**：规则确定、过程明确、结果可验证的问题，例如计算圆周率、求解方程组。这类问题有固定的计算方式或求解流程，因此计算机可以稳定地完成。

本质区别在于"构成"：人脑更适合处理复杂、不规则、抽象的问题；计算机更适合处理规则明确、具象的问题。只要一个问题能被描述成"在一个有限的求解空间里，按确定的步骤找结果"，它就天然适合用计算机求解。

## 搜索的定义与求解空间

对于一个计算机可解的问题，通常存在一个**有限的求解空间**。通过一段明确、有步骤的求解过程，我们可以从该空间中得到一个正确的结果集——这个结果集往往是求解空间的子集。

```mermaid
flowchart LR
    S[有限求解空间] --> P[有步骤的求解过程]
    P --> R[正确结果集 即 空间的子集]
```

所谓**搜索算法**，本质上就是：利用计算机的高性能，有目的地穷举一个问题的部分或全部可能情况，从而求出问题的解。它包含两个要点：

1. 借助计算机的算力去"暴力"枚举；
2. 枚举是有目的的——只保留符合目标状态的情况。

从形式上看，搜索的过程就是**构造一棵"解答树"，并在树上寻找符合目标状态的节点**。只要算力允许，绝大多数计算机问题都可以通过搜索解决，只是效率有高有低。

## 朴素搜索的几个例子

### 两数之和

给定 1 到 23 的数组，求其中两个数之和等于 40 的所有组合。最朴素的办法就是：

- 枚举第一个数所有可能的值；
- 对每个第一个数，再枚举第二个数所有可能的值；
- 把两者相加，若等于 40，就记入结果。

这里的"枚举 + 判断"就是最朴素的搜索。

### 求解方程

求解方程 `5x + 1 = 156`。人类会移项：`x = (156 - 1) / 5 = 31`。计算机则换一种思路：

- 由 `5x` 可知 `x` 是整数，且范围落在 `[-156, 156]` 之间；
- 遍历 `x` 从 `-156` 到 `156`，代入验证等式成立即可。

这就是"穷举所有可能，找到满足等式的解"。

### 三数之和（LeetCode 15）

求数组中三个数之和为 0 的所有三元组。前面介绍过一种朴素解法：三层循环遍历所有组合，把符合要求的先输出，再做去重。这种三层遍历本质上就是**遍历了所有可能结果再过滤**，所以它是一个搜索过程，也是所有同类问题的基础解法。

不过搜索虽能解题，却未必是最优解。三数之和还可以通过"排序 + 双指针"把复杂度从 O(n³) 降到 O(n²)——这正说明搜索是兜底方案，优化往往来自对问题结构的进一步挖掘。

### 二叉树路径总和（LeetCode 113）

给定二叉树根节点与目标整数，找出所有从根到叶子、路径和等于目标的路径。这道题在前面用**前序遍历**已经实现过：遍历过程实际上把所有可能的路径都走了一遍，只是过程中做了剪枝，只把符合条件的路径留下。前序遍历本质上就是在搜索解空间。

## 从搜索到 DFS 与 BFS

上面这几道题虽然都能用"朴素搜索"解决，但搜索往细处分叉，主要有两种方法：**深度优先搜索（DFS）** 与 **广度优先搜索（BFS）**。

- 二叉树的前序遍历走到底再回溯，是 DFS 的典型形态；
- 按层一层一层地访问节点，是 BFS 的典型形态。

后续会分别用这两种方法重新求解路径总和等题目，理解它们各自的适用场景与差异。

## 面试答题要点

- 先点出搜索的本质：利用算力有目的地穷举，从有限求解空间中找到结果集。
- 强调"搜索 = 构造解答树并寻找目标节点"这一形式化理解。
- 用熟悉的问题佐证：两数之和的枚举、方程遍历、三数之和的三层循环、路径总和的前序遍历，本质都是搜索。
- 收尾点出：搜索是兜底解法，DFS 与 BFS 是两种细分路径，为后续章节铺垫。
