# 后端校招面试直通车: TCP 与 UDP 的头部分别长什么样、差异从何而来

## 纲要

- 传输层的定位与端口、套接字的概念
- UDP 首部：源端口、目的端口、长度、校验和
- TCP 首部：序号、确认号、数据偏移、控制位、窗口等字段
- 四个核心字段的语义：序号、确认号、控制位、窗口
- 从"可靠/有连接 vs 不可靠/无连接"推导两者的全部差异
- 典型应用场景与协议对照

## 传输层与端口

传输层在 OSI 模型中是第 4 层，在 TCP/IP 四层模型中是第 3 层。它向上为应用层提供通信服务，提供的是**主机间不同进程之间的通信**，并屏蔽下方网络的核心细节——面向传输层编程时，感觉就像两个主机进程之间有一条端到端的逻辑通信信道。

网络层用 IP 地址定位主机，但一台主机上同时运行着很多进程，数据到达主机后如何交给正确的那个进程？答案就是**端口**：

- 端口是一个 16 比特的数字，占两个字节，取值范围 0 ~ 65535
- 端口用于标识主机上具体的网络进程
- **IP 地址 + 端口**的组合构成一个**套接字（Socket）**，网络编程正是面向 Socket 进行的

理解端口之后，再看 UDP 与 TCP 的首部，就会清楚为什么需要"源端口 + 目的端口"两个字段：传输层是两个主机进程之间的通信，两端都要标识。

## UDP 首部

UDP 首部非常简洁，只有四个字段：

| 字段 | 含义 |
| --- | --- |
| 源端口号 | 标识发送方的进程，用于对方回送数据 |
| 目的端口号 | 标识接收方的进程，用于数据交付 |
| UDP 长度 | 标识 UDP 报文数据的长度 |
| UDP 校验和 | 附加的校验数据，用于判断数据在传输过程中是否发生差错 |

UDP 的设计哲学就藏在这个首部里：**只管把数据发出去，其余一概不管**。

## TCP 首部

```dir
TCP 首部（固定 20 字节 + 可选字段 + 填充）
├── 源端口号 / 目的端口号        （各 16 位）
├── 序号 seq                     （32 位）
├── 确认号 ack                   （32 位）
├── 数据偏移 / 保留字段 / 控制位 （含 URG ACK PSH RST SYN FIN）
├── 窗口                         （16 位）
├── 校验和 / 紧急指针
└── 选项 + 填充                  （可变长度）
```

TCP 首部前 5 行每行 32 比特（4 字节），共 **20 字节的固定部分**；此外还有可选字段与填充字段。因此面试中一个常见陷阱是：

> TCP 首部是固定的 20 字节吗？

答案是**不是**。20 字节只是固定部分的长度，带选项时可以更长。

### 序号

- 占 4 字节，取值范围 0 ~ 2^32-1
- 作用：标识 TCP 数据中的字节序号，**每一个字节都有唯一的序号**——因为 TCP 是面向字节流的协议
- 起始序号在建立 TCP 连接时确定（三次握手中交换的 seq）
- 注意：一个报文的序号表示的是**该报文数据中第一个字节的序号**，而不是给整个报文编号

### 确认号

- 同样占 4 字节
- 含义：期望收到对方下一个报文的第一个数据字节的序号
- 若确认号为 n，则表示**序号 n-1 及之前的所有数据都已正确收到**

序号与确认号是强关联的：一个表达"我发的是哪个字节"，一个表达"我下一个要哪个字节"。

### 控制位

控制位共 6 个特殊标记位，其中三个最常用：

| 标记 | 含义 | 作用 |
| --- | --- | --- |
| URG | 紧急位 | 标识紧急数据 |
| ACK | 确认位 | 该位为 1 时，报文中的确认号生效 |
| PSH | 推送位 | 要求尽快交付给应用层 |
| RST | 复位位 | 连接出现严重差错时重置连接 |
| SYN | 同步位 | 为 1 时表示这是一个连接请求 / 连接接受报文 |
| FIN | 终止位 | 为 1 时表示这是一个释放连接的报文 |

### 窗口

- 占 2 字节，取值范围 0 ~ 65535
- 含义：指明**允许对方发送的数据量大小**
- 存在的理由：发送方与接收方的缓冲空间都是有限的，不可能无限缓存数据，需要窗口来做流量控制

## 差异的根源：可靠有连接 vs 不可靠无连接

| 维度 | UDP | TCP |
| --- | --- | --- |
| 面向连接 | 无连接 | 有连接 |
| 可靠性 | 不可靠 | 可靠 |
| 首部复杂度 | 简单（4 个字段） | 复杂（序号、确认号、控制位、窗口等） |
| 性能负载 | 低 | 高 |
| 速度 | 快 | 相对慢 |
| 实现难度 | 简单 | 复杂 |
| 适用场景 | 简单场景 | 复杂场景 |

**所有的差异都可以从"TCP 提供可靠的、有连接的服务"这一句话推导出来**：

- 有连接意味着通信前必须建连，通信结束后必须释放连接，整个过程复杂
- 可靠意味着要做到**无差错、不丢失、不重复**，还要保证**按序到达**——因为 TCP 面向字节流，数据乱序到应用层是不可用的
- 为了保证这些，TCP 需要序号、确认号、控制位、窗口、重传、流量控制、拥塞控制等一整套机制，首部自然复杂，性能负载自然更高

UDP 恰恰相反：只管发送，既不保证可靠，也不保证连接状态，因此首部极简、开销极低。

一个生活化的类比：

- **TCP 像打电话**：先拨号、对方应答（建立连接），再通话（通信），最后挂断（释放连接）。每一句话都能确认对方听到了
- **UDP 像写信**：信写好寄出去就结束，对方是否收到、何时收到，写信人无从得知

## 典型应用场景

| 协议 | 承载的传输层协议 |
| --- | --- |
| DNS | UDP |
| TFTP（简单文件传送协议） | UDP |
| 流式多媒体通信 | UDP |
| DHCP（IP 地址配置） | UDP |
| 电子邮件协议（SMTP 等） | TCP |
| FTP（文件传送协议） | TCP |
| TELNET（远端终端） | TCP |
| HTTP（浏览网页） | TCP |

这里有个易混淆点：**TFTP 用 UDP，而 FTP 用 TCP**。前者是"简单文件传送"，后者是完整的文件传输协议，可靠性要求不同，选型因此不同。

## 面试答题要点

- 先给结论：TCP 可靠、有连接；UDP 不可靠、无连接
- 再从结论反推差异：首部复杂度、性能负载、速度、实现难度、适用场景
- 讲清首部字段：序号（字节序号，报文中指首字节）、确认号（n 表示 n-1 及之前已收到）、控制位（ACK/SYN/FIN）、窗口（流量控制）
- 纠偏：TCP 首部不是固定 20 字节，20 字节只是固定部分
- 最后举应用场景，顺带说明为何 DNS 用 UDP、HTTP 用 TCP
