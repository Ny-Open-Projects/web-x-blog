# 时序型数据搜索-章节导学

搜索服务四大核心场景的第三站是**时序型数据（典型如日志）的搜索实战与优化**。生产环境中每天产生海量日志，ELK 已基本成为业界默认的日志处理方案。本章以日志为例，讲清数据采集组件家族、常见建模误区、存储降本与生命周期管理。

## 纲要

- 时序数据搜索的场景与痛点：日志集群吞吐高、硬件低、问题多
- ELK = Elasticsearch + Logstash + Kibana，可类比 MVC
- ELKB 的 B = Beats 家族，Filebeat 是轻量日志采集器
- Beats 全家桶：Auditbeat / Functionbeat / Heartbeat / Metricbeat / Packetbeat / Winlogbeat
- 本章路线：建模误区 → 降低存储成本 → ILM 生命周期 → 实现 ES 日志采集搜索

## ELK 与 MVC 模型

ELK 是三个开源软件缩写：Elasticsearch（数据存储/检索）、Logstash（采集过滤转发）、Kibana（可视化）。可把它看作一个 MVC 模型：**Elasticsearch 是 Model 层，Logstash 是 Controller 层，Kibana 是 View 层**。现在广泛使用的是 **ELKB**，其中 B 代表 Beats 家族。

- **Logstash**：具备实时传输能力的数据收集引擎，CS 架构——client 装在需收集日志的主机，server 负责过滤/修改后统一输出到 ES、Kafka 等。
- **Filebeat**：轻量级日志文件采集器，装在目标服务器，配置好日志路径后即可读取并发送给 Logstash 解析，也可直接发往 ES 做集中存储分析。
- 三者的关系：Beats 家族负责「采」，Logstash 负责「收与转」，最终汇入 Elasticsearch。

```mermaid
flowchart LR
    A["日志文件"] --> B["Filebeat (采)"]
    B --> C["Logstash (收/过滤/转发)"]
    C --> D["Elasticsearch (存/检)"]
    D --> E["Kibana (可视化)"]
```

## Beats 家族全景

Beats 不止 Filebeat，还包括：

| 组件 | 用途 |
| --- | --- |
| Filebeat | 日志文件采集（最常用） |
| Auditbeat | 审计 Linux 用户/进程活动，检测关键文件变更 |
| Functionbeat | 收集云服务器事件并发送到 Elasticsearch |
| Heartbeat | 通过 ICMP/TCP/HTTP 检测服务/主机存活 |
| Metricbeat | 收集 OS、软件、服务指标（Docker、Kafka、MySQL、Redis、Nginx、CPU、内存等） |
| Packetbeat | 抓包解码应用层协议（HTTP、MySQL 等），监控流量与 SQL 排名 |
| Winlogbeat | 收集 Windows 事件日志，持久化读取位置以便重启恢复 |

实际生产中这些使用频率不高，但了解「它是什么、能做什么」便于遇到场景时对号入座。

```dir
time-series/
├── 采集层 (Beats)/
│   ├── Filebeat      # 日志
│   ├── Metricbeat    # 指标
│   ├── Winlogbeat    # Windows 事件
│   └── 其他 beats
├── 处理层/
│   └── Logstash      # 过滤/转发
└── 存储与展示/
    ├── Elasticsearch # 存/检
    └── Kibana        # 可视化
```

## 为什么日志场景特殊

生产环境中，很多日志集群的吞吐比大多数业务集群都高，带来的写入负载很大；而出于成本考虑，日志集群的硬件资源往往比同规模业务集群低得多。因此日志集群也是运维中出现问题最多的地方。本章就以日志数据为切入点，详细讨论时序数据场景下的实现细节与优化方案。

## 本章路线

1. 日志索引**数据建模的常见误区**；
2. 如何**降低海量日志的存储成本**；
3. 索引生命周期管理（ILM）的原理与实践；
4. 最终实现 **Elasticsearch 集群日志的收集与搜索**。

## 总结

本章是搜索服务四大核心场景中的「时序型数据搜索」，以日志为典型载体。先建立认知：ELK 可类比 MVC（ES=Model、Logstash=Controller、Kibana=View），而 ELKB 的 B 是 Beats 家族——Filebeat 轻量采日志、Logstash 收转发、其余 Beats 覆盖审计/云事件/心跳/指标/抓包/Windows 事件等细分场景。

日志场景的特殊性在于**高吞吐 + 低硬件 + 问题多**，所以本章不急着写代码，而是先讲清建模误区、存储降本与 ILM 生命周期管理，最后才落地 ES 日志采集与搜索。掌握这套思路，能直接复用到所有时序型数据的搜索与优化中。
