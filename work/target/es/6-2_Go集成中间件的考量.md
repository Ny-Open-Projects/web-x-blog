# Go 项目开发: 封装中间件 SDK 的九个考量

Go 项目里常用的中间件有 Elasticsearch、MySQL、MongoDB、Redis、Kafka、Prometheus，此外还有协程池 —— 它虽算不上中间件，但同样必不可少。如果一味用 `go` 语句开协程，一旦遇到高并发且异步处理慢的场景，就会造成大量协程堆积：每个协程自身要占几 KB 内存，再加上它持有的资源，堆积起来会把系统内存耗尽，最终导致服务宕机。**协程池就是为此而生的。**

集成这些中间件时，SDK 应该考虑哪些事？

## 纲要

- 安全第一：防止删库删表
- 阻止异常操作
- 监控上报
- 多客户端支持
- 与原生操作保持一致
- 参数的优雅处理
- 单元测试与使用样例
- 文档与代码注释
- 合理默认值与参数校验

## 安全第一：防止直接删库删表

删库删表操作一般应通过**运维工单审核后**才能执行，绝不允许通过代码直接删除数据库或数据表。风险来自两方面：

- **误操作** —— 比如执行删除时忘了 `where` 条件、删表时传错了表名。
- **人为破坏** —— 员工带着负面情绪故意破坏数据。

数据是整个系统最宝贵的资源，安全再怎么重视都不过分。具体做法：

- 日志类数据用 **NoSQL 分表存储、定期清理**，只对存核心数据的关系库做严格把控。
- 如果全系统都用 NoSQL，就按隔离原则把核心与非核心数据的库分开。
- 对确需删表的操作，用**白名单**控制 —— 只允许对白名单中的表执行删除。

## 阻止异常操作

很多线上事故源于"合法但危险"的请求，SDK 层可以直接拦掉：

- MySQL 中**不带 where 条件**的查询、更新、删除，或一次更新过多的记录数。
- ES 中 `terms` 查询一次性过滤**上千个值**，或查询嵌套层级过深（几百上千层）。

这些操作都可能拖垮集群，SDK 作为统一入口最有资格做这件事。

## 监控上报

SDK 是应用与中间件之间的**唯一桥梁**，全部流量都经过它。在这里埋监控点，可以汇总统计各中间件的调用信息，**尤其是失败信息** —— 它能帮你提前发现问题。

## 多客户端支持

同一个工程里，可能同时用不同的数据库、不同的 ES 集群、不同的 Redis 集群甚至不同的消息队列（读写分离时就要连不同的库）。而中间件通常只在启动时初始化一次，所以 **SDK 必须支持初始化多个实例**，按名字取用。

## 与原生操作保持一致

对 Redis 这类开发者熟悉的中间件，直接提供与原生基本一致的接口，减少学习成本。对大部分开发人员陌生的中间件，则可以**模仿流行的中间件**来设计 —— 例如给 ES 提供 SQL 支持，学习成本能大幅下降。

## 参数的优雅处理

不同业务对中间件的依赖度不同：搜索业务深度依赖 ES，其他业务用几个基本参数就够了。可以按依赖度分层提供初始化函数：

- `InitClient` —— 只提供基本连接参数，给依赖度不高的普通业务用。
- `InitMultiClient` —— 支持多客户端，一个项目连多个集群。
- `InitExpertClient` —— 开放更多自定义参数，给深度依赖的专家用户。

入参过多时用**函数式选项模式**（Functional Options）处理，比如初始化 MySQL 时把参数选项以函数形式传入。

## 单元测试与使用样例

公共库的单元测试不仅保证质量，**优秀的测试用例本身就是最好的入门文档**，能让使用者快速掌握使用细节。最好再提供已接入的标杆项目实例，让使用者对照真实场景学习最佳实践。

## 文档与代码注释

详细清晰的代码注释基本可以取代文档。开发过程中，直接看公共库源码里的注释了解函数功能与参数含义，比切回去查文档高效得多。**Kafka 与 ES 的官方 SDK 是这方面的典范** —— 每个结构体属性都有详细注释，连官方文档地址都给出来了。

## 合理默认值与参数校验

| 参数 | 合理默认 | 校验 |
| --- | --- | --- |
| ES bulk 刷新间隔 | 1 秒 | 超过 60 秒视为无效 |
| ES bulk 总大小 | 5 MB | **不超过 100 MB**（ES 对 HTTP 请求的默认限制） |
| ES 每批文档数 | 500 ~ 1000 | 超过 1 万视为无效；大文档调小、小文档调大 |
| MySQL 最大连接数 | 1000 | SDK 默认 0（不限制）会导致并发过高时报 too many connections |

其余如**断线重连、熔断、限流、超时控制**，可以借助开源组件实现，不必全部自研。

## 总结

封装中间件 SDK 的检查清单可以浓缩成一句话：**让调用方便捷地用对，让危险的操作被拦住**。具体展开就是 —— 删库走工单、异常操作 SDK 拦截、全流量埋监控、支持多实例、接口贴近原生、参数分层加函数式选项、测试即文档、注释详尽、默认值合理。
