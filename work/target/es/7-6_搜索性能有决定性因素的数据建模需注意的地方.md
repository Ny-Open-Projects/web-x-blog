# 搜索性能有决定性因素的数据建模需注意的地方

数据建模里，分词器的选择与使用对中文搜索的相关性和性能有决定性影响。本节以 IK 分词器为例，讲清索引分词器与查询分词器不一致导致的 `match_phrase` 查不到问题，以及三种应对方案。

## 纲要

- IK 分词器安装与索引配置（ik_max_word / ik_smart）
- 索引用 ik_max_word、查询用 ik_smart 的粗细差异
- `match_phrase` 要求 token 连续相邻，粗细不一致会查不到
- 方案：查询端用同索引分词器 / 设置 slop / 单字分词兜底
- 注意：slop 越大越弱顺序约束且更耗资源，生产不推荐大 slop

## IK 分词器的安装与配置

进入 ES 安装目录执行：`bin/elasticsearch-plugin install <IK 远程地址或 file:// 本地路径>`。创建索引时在 `settings.analysis` 中定义两个 analyzer：

- `ik_index_analyzer`：type 用 `custom`，tokenizer 用 `ik_max_word`，filter 加 `lowercase`；
- `ik_search_analyzer`：tokenizer 用 `ik_smart`。

字段（如 `name`，text 类型）配置 `analyzer=ik_index_analyzer`、`search_analyzer=ik_search_analyzer`。**索引时用 ik_max_word（分词更细），查询时用 ik_smart（分词更粗）**，这是中文搜索的常见搭配。

```mermaid
flowchart LR
    A["写入: ik_max_word"] --> B["倒排索引 token 更细"]
    C["查询: ik_smart"] --> D["查询 token 更粗"]
    B --> E["match_phrase 要求相邻"]
    D --> E
    E --> F["粗细不一致可能查不到"]
```

## 为什么 match_phrase 会查不到

以「欢迎来到慕课网学习」为例：

- 索引分词（ik_max_word）得到：`欢迎`、`迎来`、`来到`、`慕课网`、`学习`（更细，token 多）；
- 查询分词（ik_smart）得到：`欢迎来到`、`慕课网`、`学习`（更粗，token 少）。

`match_phrase` 要求查询词分词后的 token 在倒排索引中**连续且相邻**。索引里 `欢迎` 在 position 0、`来到` 在 position 2，中间隔了 `迎来`（position 1）；而查询端 `欢迎来到` 被当成一个相邻短语，自然匹配不上，导致整句查不出。

## 三种解决方案

1. **查询端用与索引一致的分词器**：在 `match_phrase` 中显式指定 `analyzer=ik_index_analyzer`，让查询也用细粒度分词，即可命中。
2. **设置 slop**：`match_phrase` 支持 `slop` 参数，表示允许 token 之间移动的最大步长。上例中设 `slop=1`，`欢迎` 与 `来到` 移动 1 个 position 即可相邻匹配。`slop` 越大，允许间隔越长，几乎能逼近 `match` 的效果，但会弱化词序约束、降低相关度得分。
3. **单字分词兜底**：第三种方案后续章节详细介绍。

```dir
ik-analyzer/
├── 安装/
│   └── elasticsearch-plugin install
├── 索引配置/
│   ├── ik_index_analyzer   # ik_max_word
│   └── ik_search_analyzer  # ik_smart
└── 查询问题/
    ├── match_phrase 相邻约束
    ├── slop 容忍间隔
    └── 单字分词兜底
```

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| 同分词器查询 | 查询指定 `analyzer=ik_index_analyzer` | 查询变细，召回略增 |
| 设置 slop | `match_phrase` 加 `slop=N` | 计算位置、更耗资源、相关度降 |
| 单字分词 | 单字 token 兜底 | 后续章节 |

## 关于 slop 的提醒

`match_phrase` 带 `slop` 时需要额外计算词项位置，查询效率远低于普通 `match`；且间隔越远相关度越低、得分越低。实际生产环境**不建议把 slop 设得过大**——它会弱化词序约束，也拖慢查询。

## 总结

中文搜索的数据建模里，**索引分词用 ik_max_word、查询分词用 ik_smart** 是标准做法，但两者粒度不同会引发 `match_phrase` 因「要求 token 连续相邻」而查不到整句的问题。根因是细粒度索引（多 token）与粗粒度查询（少 token）在 position 上不连续。

应对有三条路：查询端改用同索引分词器、给 `match_phrase` 设置 `slop` 容忍间隔、或用单字分词兜底。其中 `slop` 虽能放宽匹配，却以更高查询开销和更低相关度为代价，生产上不宜滥用大 slop。理解分词粒度与短语匹配的底层机制，是做好中文搜索建模的前提。
